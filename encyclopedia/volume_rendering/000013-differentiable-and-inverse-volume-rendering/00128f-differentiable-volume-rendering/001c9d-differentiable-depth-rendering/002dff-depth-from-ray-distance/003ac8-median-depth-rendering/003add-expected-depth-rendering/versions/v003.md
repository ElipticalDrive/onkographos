# Expected Depth Rendering

Also called: Expected Depth Calculation

## Overview
Expected Depth Rendering estimates scene depth by computing the weighted average of depth samples along a ray, normalized by the accumulated weight [S1]. This method provides a stable geometric signal for pseudo-normal supervision and ray-tracing initialization, offering superior reconstruction quality and downstream stability compared to inverse-depth variants [S1]. It differs from Median Depth Rendering, which identifies the sample index where cumulative opacity crosses a threshold, by integrating the entire ray's contribution rather than selecting a single median point [S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:**
    *   `z_vals`: Tensor of depth samples (z-coordinates) along each ray. Shape: $(H, W, N)$, where $H, W$ are image dimensions and $N$ is the number of samples per ray [S1][S2, unofficial].
    *   `weights`: Tensor of density weights $w_i$ for each sample. Shape: $(H, W, N)$ [S1][S2, unofficial].
*   **Outputs:**
    *   `depth_map`: Tensor containing the expected depth for each pixel. Shape: $(H, W)$ [S2, unofficial].

**Data Structures**
*   **Weights ($w_i$):** Calculated as $w_i = T_i g_i \alpha_i$, where $T_i$ is transmittance, $g_i$ is Gaussian response (or density weight), and $\alpha_i$ is opacity [S1].
*   **Transmittance ($T_i$):** Cumulative transmittance up to sample $i$, typically $T_i = \exp(-\sum_{j=0}^{i-1} \sigma_j \delta_j)$ or accumulated from previous steps [S1].

**Parameters**
*   `method`: Strategy for computing depth. Set to `'expected'` for weighted mean [S5, unofficial].
*   `depth_threshold`: Used in median variants, but not in expected depth calculation. Default 0.5 [S3, unofficial].

**Steps**
1.  **Compute Weights:** For each sample $i$ along each ray, calculate the weight $w_i$ using $w_i = T_i g_i \alpha_i$ [S1].
2.  **Accumulate Weight:** Compute the total accumulated weight $W$ for each ray: $W = \sum_{i \in N} w_i$, where $N$ is the set of all samples along the ray [S1].
3.  **Compute Expected Depth:** Calculate the expected depth $z_E$ for each pixel using the weighted mean: $z_E = \frac{\sum_{i \in N} w_i z_i}{W}$, where $z_i$ is the depth of sample $i$ [S1].
4.  **Clip Output:** Clip the computed depth to the range $[\min(z_i), \max(z_i)]$ to handle boundary conditions [S2, unofficial].

**Pseudocode**
```python
def expected_depth_rendering(z_vals, weights):
    # z_vals: array of shape (..., N) containing depth samples
    # weights: array of shape (..., N) containing pre-computed weights w_i
    # Returns: array of shape (...) containing expected depth
    eps = 1e-7
    # Step 1: Accumulate total weight W for each ray
    W = sum(weights[..., i] for i in range(weights.shape[-1]))
    # Step 2: Compute weighted sum of depths
    weighted_depth_sum = sum(weights[..., i] * z_vals[..., i] for i in range(weights.shape[-1]))
    # Step 3: Normalize by total weight
    depth_map = weighted_depth_sum / (W + eps)
    # Step 4: Clip to sample boundaries
    min_z = min(z_vals[..., 0], z_vals[..., -1])
    max_z = max(z_vals[..., 0], z_vals[..., -1])
    depth_map = max(min_z, min(max_z, depth_map))
    return depth_map
```

**Edge Cases and Pitfalls**
*   **Zero Weight:** If $W = 0$ (e.g., completely transparent ray), the result is undefined. A small epsilon is added to the denominator for numerical stability [S1].
*   **Precision:** Floating-point precision issues may arise if weights vary significantly in magnitude. Using double precision for accumulation can help [G].
*   **Boundary Conditions:** Ensure $z_i$ values are correctly aligned with $w_i$, and clip the final depth to $[\min(z_i), \max(z_i)]$ to prevent out-of-bounds artifacts [S2, unofficial].

## Subtopics

### Mean Gaussian Depth Rendering
Computes depth as the weighted sum of Gaussian depths $d_k$, where weights are the product of opacity $o_k$, 2D Gaussian contribution $\mathcal{G}_k^{\text{D}}(\mathbf{x})$, and transmittance $T_k$ [S6]. Formula: $d(\mathbf{x}) = \sum_{k=1}^N d_k o_k \mathcal{G}_k^{\text{D}}(\mathbf{x}) T_k$ [S6]. **Pitfall:** Fitting volumetric density does not guarantee consistency with rendered mean depth [S6]. If multiple density peaks exist along a ray but only one surface exists, rendered mean depth diverges from depth derived from raw quads due to oscillating sine/cosine functions in phase encoding, preventing equality in Jensen's inequality [S6]. The gap reduces only when all Gaussians are clustered at the same z-position [S6].

## Operating characteristics
*   **Time Complexity:** $O(N)$ per ray, where $N$ is the number of samples, due to a linear scan to compute weights and sums [S1].
*   **Memory Complexity:** $O(N)$ per ray to store weights and depths [S1].
*   **Performance:** Provides stable geometric signals, making it suitable for pseudo-normal supervision and ray-tracing initialization [S1].
*   **Strengths:** Best overall reconstruction quality among depth variants; stable downstream supervision [S1].
*   **Limitations:** Sensitive to noise in pure gradient-based normals derived from rendered depth; lacks multi-view consistency when applied to 3D Gaussian surfaces without additional constraints [S1].
*   **When to Use:** When stable geometry is needed for supervision or initialization, and multi-view consistency can be handled by other means [S1].
*   **When Not to Use:** When strict surface consistency is required without additional constraints, or when computational resources are extremely limited and simpler approximations suffice [S1, S6].

## Background
Expected Depth Rendering was introduced in the context of differentiable volume rendering and Gaussian Splatting for inverse rendering [S1]. It is used in methods like NeRFactor and GS-IR for depth estimation and normal supervision [S1]. The method was chosen over inverse-depth variants for its stability and reconstruction quality [S1]. It is also referenced in implementations like NeRFies and GaNeRF for depth visualization and evaluation [S2, unofficial][S3, unofficial].
