# Median Depth Rendering

Also called: 50% transmittance depth, Depth Renderer (Median), Median Depth Calculation, Median Depth Visualization, Median termination depth

## Overview
Median Depth Rendering computes the geometric depth of a volume by identifying the sample along a ray where the accumulated transmittance drops to 0.5 [S3]. It solves the bias introduced by residual density in free space that affects Expected Depth Rendering, providing a sharper and less biased geometric representation for ambiguous or sparse scenes [S2, unofficial]. Unlike Expected Depth Rendering, which integrates the entire ray's contribution to find a weighted average, Median Depth Rendering selects a single threshold-crossing point, making it robust to noise in empty regions [S2, unofficial].

## How it works
**Inputs:**
- Ray samples: A set of $N$ points along a ray, defined by their depths $z_i$ and densities $\sigma_i$ for $i = 0, \dots, N-1$ [S3].
- Step sizes: $\Delta z_i = z_{i+1} - z_i$ representing the distance between consecutive samples [G].

**Outputs:**
- Depth value $D$ for the pixel corresponding to the ray [S3].

**Data Structures:**
- `z_vals`: Array of shape $(N,)$ containing depths $z_i$ [S1, unofficial].
- `sigma`: Array of shape $(N,)$ containing densities $\sigma_i$ [S1, unofficial].
- `T`: Array of shape $(N,)$ storing accumulated transmittance values [S3].

**Parameters:**
- `depth_threshold`: The transmittance threshold for median definition. Default is $0.5$ [S2, unofficial].

**Steps:**
1. **Compute Transmittance:** Calculate the accumulated transmittance $T_i$ for each sample. $T_i$ represents the probability that a ray passes through all samples up to $i$ without interacting [S3].
   $$ T_0 = 1.0 $$
   $$ T_{i+1} = T_i \cdot \exp(-\sigma_i \Delta z_i) \quad \text{for } i = 0, \dots, N-2 $$
   [S3]
2. **Find Median Index:** Identify the first sample index $i^*$ such that the accumulated transmittance $T_{i^*}$ is greater than or equal to the threshold [S3].
   $$ i^* = \min \{ i \mid T_i \ge 0.5 \} $$
   [S3]
3. **Assign Depth:** The rendered depth is the depth value of the identified sample [S3].
   $$ D = z_{i^*} $$
   [S3]

**Pseudocode:**
```python
import math

def median_depth_rendering(z_vals: list[float], sigma: list[float], threshold: float = 0.5) -> float:
    """
    Compute median depth rendering for a single ray.
    
    Args:
        z_vals: List of depths along the ray, sorted ascending.
        sigma: List of densities at each depth sample.
        threshold: Transmittance threshold (default 0.5).
        
    Returns:
        The depth value at the median termination point.
    """
    n = len(z_vals)
    if n == 0:
        return 0.0  # [G] Fallback for empty ray
        
    # Step 1: Compute accumulated transmittance T
    T = [0.0] * n
    T[0] = 1.0
    
    for i in range(n - 1):
        delta_z = z_vals[i+1] - z_vals[i]
        T[i+1] = T[i] * math.exp(-sigma[i] * delta_z)
        
    # Step 2: Find the first index where T[i] >= threshold
    median_index = 0
    for i in range(n):
        if T[i] >= threshold:
            median_index = i
            break
            
    # Step 3: Return depth at median_index
    return z_vals[median_index]
```

**Edge Cases and Pitfalls:**
- **Fully Opaque Ray:** If the accumulated transmittance drops below 0.5 immediately, the definition $T_i \ge 0.5$ still finds an index because $T_0=1.0$ always satisfies the condition [S3]. The "first sample" logic ensures that if the object starts at the first sample, that depth is returned [S3].
- **Free Space Bias:** In regions with no geometry (density $\approx 0$), transmittance remains near 1.0 [S2, unofficial]. Expected depth would pull the value towards the far plane, but median depth ignores this residual density, staying anchored to the actual surface where opacity accumulates [S2, unofficial].
- **Discontinuity:** The depth output is discontinuous with respect to small changes in density, as it jumps between sample indices [G]. This can cause artifacts in differentiable rendering if not handled carefully (e.g., via soft approximations) [G].

## Subtopics

### [Expected Depth Rendering](8816-expected-depth-rendering.md)
Expected Depth Rendering estimates scene depth by computing the weighted average of depth samples along a ray, normalized by the accumulated weight. This method provides a stable geometric signal for pseudo-normal supervision and ray-tracing initialization, offering superior reconstruction quality and downstream stability compared to inverse-depth variants. It differs from Median Depth Rendering, which identifies the sample index where cumulative opacity crosses a threshold, by integrating the entire ray's contribution rather than selecting a single median point. Choose Expected Depth Rendering when smooth, differentiable depth fields are required for downstream tasks like normal estimation [G].

## Operating characteristics
- **Time Complexity:** $O(N)$ per ray, where $N$ is the number of samples [G]. Finding the threshold index is a linear scan [G].
- **Memory Complexity:** $O(N)$ to store transmittance values if computed explicitly, or $O(1)$ if computed on the fly with early termination [G].
- **Strengths:** Robust to residual density in empty space; provides sharper depth boundaries than expected depth [S2, unofficial].
- **Limitations:** Discontinuous output can hinder gradient-based optimization in differentiable settings without smoothing [G]. Sensitive to the choice of threshold (though 0.5 is standard) [S1, unofficial].
- **When to use:** When geometric accuracy is prioritized over smoothness, or when residual density in free space biases expected depth significantly [S2, unofficial].

## Background
Median Depth Rendering was introduced in the context of Deformable Neural Radiance Fields (NeRFies) to address the bias in depth visualization caused by residual density in free space [S2, unofficial]. While standard NeRF uses expected termination distance for depth, NeRFies found that median depth provides a less biased geometric representation, particularly for deformable scenes [S2, unofficial]. It is used in NeRFies for depth visualization and potentially for initialization or supervision in deformable reconstruction tasks [S2, unofficial]. The method is also referenced in other implementations like GanERF for depth rendering [S4, unofficial].
