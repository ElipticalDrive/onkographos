# Differentiable Depth Rendering

Also called: Differentiable Depth Rendering via Implicit Function Theorem, IFT-based gradients, Differentiable Depth via Implicit Function Theorem (IFT) Surrogate, IFT Surrogate, IFT-based differentiable rendering, surrogate gradient for depth

## Overview
Differentiable Depth Rendering via the Implicit Function Theorem (IFT) computes exact gradients of rendered depth values with respect to implicit scene parameters (e.g., neural network weights or latent codes) without differentiating through the forward ray-marching or bisection algorithm [S2, unofficial]. It solves the problem of high memory usage and instability associated with backpropagating through iterative solvers by replacing the backward pass with an analytic surrogate derived from the implicit surface equation $f(\mathbf{x}, \boldsymbol{\theta}) = 0$ [S2, unofficial]. Unlike [Differentiable Direct Volume Rendering (DVR)](8871-differentiable-direct-volume-rendering-dvr.md) which integrates emission-absorption, this method targets iso-surface extraction where depth is defined by the zero-crossing of a Signed Distance Function (SDF) [S1][S2, unofficial].

## How it works
The method separates the forward pass (robust, non-differentiable tracing) from the backward pass (analytic gradient computation via IFT) [S2, unofficial].

### Inputs and Outputs
*   **Inputs:**
    *   Ray origins $\mathbf{o} \in \mathbb{R}^3$ and directions $\mathbf{d} \in \mathbb{R}^3$ (normalized) [S2, unofficial].
    *   Implicit function $f(\mathbf{x}; \boldsymbol{\theta})$ returning value and optionally gradient, parameterized by $\boldsymbol{\theta}$ [S2, unofficial].
    *   Forward depth estimate $t_{\text{det}}$ obtained via a robust solver (e.g., bisection or sphere tracing) [S2, unofficial].
    *   Hit mask identifying pixels where the ray intersects the surface (SDF value crosses zero) [S2, unofficial].
*   **Outputs:**
    *   Differentiable depth tensor $\hat{t}$ compatible with autograd frameworks [S2, unofficial].
    *   Gradients $\frac{\partial \hat{t}}{\partial \boldsymbol{\theta}}$ computed during the backward pass [S2, unofficial].

### Data Structures
*   **Hit Mask:** Boolean array identifying pixels where the ray intersects the surface (SDF value crosses zero) [S2, unofficial].
*   **Surface Points:** $\mathbf{p}^* = \mathbf{o} + t_{\text{det}} \mathbf{d}$, the 3D coordinates of the intersection [S2, unofficial].
*   **Tensors:** PyTorch tensors with `requires_grad=True` for $\mathbf{p}^*$ to enable automatic differentiation of $f(\mathbf{p}^*)$ [S2, unofficial].

### Algorithm Steps
1.  **Forward Tracing (Detached):**
    Compute the intersection distance $t_{\text{det}}$ using a standard, non-differentiable algorithm (e.g., bisection or sphere tracing) [S2, unofficial]. This value is detached from the computation graph to prevent backpropagation through the solver [S2, unofficial].
    $$ t_{\text{det}} = \text{Solver}(\mathbf{o}, \mathbf{d}, f) $$

2.  **Surface Point Evaluation:**
    Calculate the 3D position of the surface intersection for hit rays:
    $$ \mathbf{p}^* = \mathbf{o} + t_{\text{det}} \mathbf{d} $$
    Convert $\mathbf{p}^*$ to a tensor requiring gradients [S2, unofficial].

3.  **Implicit Function Evaluation:**
    Evaluate the implicit function at $\mathbf{p}^*$:
    $$ v = f(\mathbf{p}^*; \boldsymbol{\theta}) $$
    Note: Due to the solver, $v$ is approximately zero but may have small residual error [S2, unofficial].

4.  **IFT Gradient Computation:**
    According to the Implicit Function Theorem, for $f(\mathbf{o} + t\mathbf{d}, \boldsymbol{\theta}) = 0$, the derivative of $t$ with respect to parameters $\boldsymbol{\theta}$ is:
    $$ \frac{dt}{d\boldsymbol{\theta}} = -\frac{\frac{\partial f}{\partial \boldsymbol{\theta}}}{\nabla_{\mathbf{x}} f \cdot \mathbf{d}} $$
    In practice, using automatic differentiation on the scalar field value $v$:
    $$ \text{grad}_x = \nabla_{\mathbf{p}^*} v $$
    Compute the directional derivative (denominator):
    $$ \text{dot} = \text{grad}_x \cdot \mathbf{d} $$

5.  **Clamping:**
    To prevent division by zero for grazing rays ($\nabla_{\mathbf{x}} f \perp \mathbf{d}$), clamp the directional derivative:
    $$ \text{dot}_{\text{clamped}} = \begin{cases} \text{grad\_clamp} & \text{if } \text{dot} \ge 0 \text{ and } |\text{dot}| < \text{grad\_clamp} \\ -\text{grad\_clamp} & \text{if } \text{dot} < 0 \text{ and } |\text{dot}| < \text{grad\_clamp} \\ \text{dot} & \text{otherwise} \end{cases} $$
    Typical value for `grad_clamp` is $10^{-6}$ [S2, unofficial].

6.  **Surrogate Depth Construction:**
    Construct the differentiable depth $\hat{t}$ using the surrogate formula [S2, unofficial]. This ensures the forward value matches $t_{\text{det}}$ (approximately) but the gradient follows the IFT rule:
    $$ \hat{t} = t_{\text{det}} - \frac{v}{\text{dot}_{\text{clamped}}} $$
    Here, $t_{\text{det}}$ is detached, so $\frac{\partial \hat{t}}{\partial \boldsymbol{\theta}} = -\frac{\partial}{\partial \boldsymbol{\theta}} \left( \frac{v}{\text{dot}_{\text{clamped}}} \right)$ [S2, unofficial].

### Pseudocode
```python
import torch
import numpy as np

def differentiable_depth_rendering(
    origins: torch.Tensor,       # (N, 3)
    directions: torch.Tensor,    # (N, 3), normalized
    t_detached: torch.Tensor,    # (N,), forward depth from bisection/sphere tracing
    hit_mask: torch.Tensor,      # (N,), boolean mask for rays that hit the surface
    implicit_fn: callable,       # f(x, theta) -> values
    grad_clamp: float = 1e-6
) -> torch.Tensor:
    """
    Computes differentiable depth using IFT surrogate.
    
    Args:
        origins: Ray origins.
        directions: Ray directions.
        t_detached: Non-differentiable depth from forward solver.
        hit_mask: Boolean mask identifying hit pixels.
        implicit_fn: Function evaluating SDF. Must support autograd.
        grad_clamp: Minimum absolute directional derivative.
        
    Returns:
        Differentiable depth tensor.
    """
    # 1. Extract hit indices and corresponding t values
    hit_idx = torch.nonzero(hit_mask, as_tuple=True)[0]
    t_hit = t_detached[hit_idx]
    
    # 2. Compute surface points for hit rays
    p_star = origins[hit_idx] + t_hit[:, None] * directions[hit_idx]
    
    # 3. Convert to torch tensors with requires_grad=True
    p_star = p_star.detach().requires_grad_(True)
    
    # 4. Evaluate implicit function and compute gradient via autograd
    f_vals = implicit_fn(p_star)
    (grad_x,) = torch.autograd.grad(f_vals.sum(), p_star, create_graph=True)
    
    # 5. Compute directional derivative: dot = grad_x . d
    dot = torch.sum(grad_x * directions[hit_idx], dim=1)
    
    # 6. Clamp directional derivative to avoid division by zero
    abs_dot = torch.abs(dot)
    dot_clamped = torch.where(
        abs_dot < grad_clamp,
        torch.where(dot >= 0, grad_clamp, -grad_clamp),
        dot
    )
    
    # 7. Compute IFT surrogate depth
    t_surr = t_detached[hit_idx] - f_vals / dot_clamped
    
    # 8. Scatter t_surr into full depth tensor at hit indices
    t_differentiable = t_detached.clone()
    t_differentiable[hit_idx] = t_surr
    
    return t_differentiable
```

### Parameters
*   `grad_clamp`: Minimum absolute value for the directional derivative $\nabla_{\mathbf{x}} f \cdot \mathbf{d}$. Prevents exploding gradients for grazing rays [S2, unofficial]. Default: $10^{-6}$ [S2, unofficial].
*   `dtype`: Data type for tensors. `float64` is recommended for numerical stability in the division step [S2, unofficial].

### Edge Cases and Pitfalls
*   **Grazing Rays:** When the ray direction is perpendicular to the surface normal, $\nabla_{\mathbf{x}} f \cdot \mathbf{d} \approx 0$ [S2, unofficial]. The clamping mechanism is essential to prevent NaNs or infinite gradients [S2, unofficial].
*   **Non-Zero Residuals:** The forward solver may not find the exact zero-crossing, leaving $f(\mathbf{p}^*) \neq 0$ [S2, unofficial]. The surrogate formula $t_{\text{det}} - f/\text{dot}$ corrects this residual in the gradient computation, effectively linearizing the error [S2, unofficial].
*   **Implementation Gap:** The core IFT logic is often implemented in a separate module (e.g., `isoray/torch/render.py`) and not always shown in the main rendering loop examples, requiring careful integration [S2, unofficial].

## Subtopics

### [Depth from Ray Distance](5665-depth-from-ray-distance.md)
Converts the scalar ray distance $d$ (the Euclidean distance from the camera center to the accumulated volume along a ray) into camera-space depth $z_c$ (the distance along the camera's optical axis) [G]. This conversion is necessary because standard depth maps represent the $z$-coordinate in the camera frame, not the arc length along the ray [G]. It differs from sibling methods like [Median Depth Rendering](8815-median-depth-rendering.md) or [Sigma-Threshold Depth Rendering](5955-sigma-threshold-depth-rendering.md) by providing a continuous, differentiable geometric metric derived directly from the ray integration distance, rather than a discrete sample index or threshold crossing point [G].

### [Approximated Gradient Back-Propagation](5666-approximated-gradient-back-propagation.md)
Computes gradients in differentiable volume rendering by ignoring high-order gradient terms, specifically the dependence of sample point positions on the latent code, to reduce memory usage. It sets itself apart from exact gradient methods by using only the direct gradient of the Signed Distance Function (SDF) network, making it particularly useful for optimizing latent codes in implicit shape representations like DeepSDF.

## Operating characteristics
*   **Accuracy:** Provides exact gradients with respect to $\boldsymbol{\theta}$ assuming the implicit function is differentiable [S2, unofficial]. The surrogate ensures the gradient matches the IFT derivative, correcting for solver residuals [S2, unofficial].
*   **Strengths:** Robust forward tracing (can use any solver); low memory; exact gradients for implicit parameters [S2, unofficial].
*   **Limitations:** Requires the implicit function to be differentiable; sensitive to grazing rays (requires clamping); forward solver must be stable [S2, unofficial].
*   **When to Use:** Optimizing neural implicit representations (SDFs) where memory is a constraint and exact gradients are needed for weights/latent codes [S1][S2, unofficial].
*   **Time Complexity:** Not given in the sources. [G]
*   **Memory Complexity:** Not given in the sources. [G]

## Background
The method originates from the need to optimize neural implicit shapes (e.g., DeepSDF) using differentiable rendering [S1]. The Implicit Function Theorem provides an analytic way to compute $\frac{dt}{d\boldsymbol{\theta}}$ without differentiating the solver [S2, unofficial]. It was implemented in libraries like `isoray` to provide robust, differentiable depth rendering for implicit surfaces [S2, unofficial].
