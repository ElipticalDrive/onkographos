# Dual-Pass Differentiable Volume Rendering with Sparse Gradient Recording

Also called: Concurrent Forward/Backward Pass, Sparse gradRec Gradient Storage

## Overview
This method is a differentiable rendering technique that executes forward and backward passes concurrently to compute radiance and its derivatives simultaneously, utilizing a sparse structure (`gradRec`) to store gradients only along sampled ray paths rather than the entire volume grid [S1]. It sets itself apart from standard Reverse-Mode Automatic Differentiation by reducing memory usage from $O(N^3)$ to $O(RN)$, where $N$ is the voxel grid dimension and $R$ is the number of rays, avoiding the storage of intermediate states for all voxels [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A voxel grid of density $\sigma$ and color $\mathbf{c}$, camera parameters defining rays $\mathbf{r}$, and illumination data (environment maps or point/parallel lights).
*   **Outputs:** Rendered image radiance $L_{out}$ and gradients $\frac{\partial L_{out}}{\partial \sigma}$ for density field updates.

**Data Structures:**
*   `gradRec`: A sparse stack structure. It stores gradients only along active sampled ray paths. It does not store gradients for the full volume grid. The layout is a stack where gradients are pushed during ray marching and popped after the density field update [S1].

**Algorithm Steps:**
1.  **Concurrent Pass Execution:** Execute the forward pass (ray marching to compute radiance) and the backward pass (computing derivatives) concurrently [S1]. This allows the reuse of the Jacobian term $J_{ss}$ during backpropagation [S1].
2.  **Sphere Integration for $J_{ss}$:** Perform integration over the unit sphere to calculate $J_{ss}$ (Algorithm 2 lines 9 and 11) [S1].
    *   For environment map illuminations, use importance sampling [S1].
    *   For point or parallel light illuminations, use direct computation [S1].
    *   *Note:* Straightforward Monte Carlo integration is computationally expensive and is avoided [S1].
3.  **Ray Marching and Gradient Recording:** As rays march through the volume, intersections occur along the ray. At each intersection, push the associated gradients onto the `gradRec` stack (Algorithm 2 lines 14–15) [S1].
4.  **Density Field Update:** After the rendering pass, use the recorded gradients to update the density field [S1].
5.  **Memory Release:** Once the density field update finishes, pop the `gradRec` stack to release memory [S1].

**Pseudocode:**
```python
def dual_pass_render_and_update(voxel_grid, rays, illumination):
    """
    Executes forward and backward passes concurrently, storing gradients
    sparsely along ray paths.
    """
    # Initialize sparse gradient recorder
    # gradRec is a stack structure, not a full grid
    gradRec = Stack() 
    
    # Initialize output radiance
    L_out = 0.0
    
    # Iterate over all rays
    for ray in rays:
        # 1. Concurrent Forward and Backward Pass
        # The algorithm calculates final radiance L_out while simultaneously
        # storing requisite gradients for subsequent density field updates.
        # This dual-pass approach facilitates reuse of J_ss during backpropagation.
        
        # 2. Sphere Integration for J_ss
        # Calculate J_ss using specialized techniques based on illumination type
        # to avoid expensive Monte Carlo integration.
        if illumination.type == ENVIRONMENT_MAP:
            J_ss = importance_sampling_integration(illumination.map)
        elif illumination.type in [POINT_LIGHT, PARALLEL_LIGHT]:
            J_ss = direct_computation_integration(illumination)
        
        # 3. Ray Marching
        # March along the ray
        for sample_point in ray.march():
            # Compute radiance contribution (Forward)
            radiance_contribution = compute_radiance(sample_point, voxel_grid)
            L_out += radiance_contribution
            
            # Compute and store gradients (Backward)
            # Push gradients onto the stack gradRec as intersections occur
            gradient_at_sample = compute_gradient(sample_point, voxel_grid, J_ss)
            gradRec.push(gradient_at_sample)
            
    # 4. Density Field Update
    # Use the recorded gradients to update the density field
    update_density_field(voxel_grid, gradRec)
    
    # 5. Memory Release
    # Pop the gradRec stack to release memory
    gradRec.clear()
    
    return L_out
```

**Parameters and Edge Cases:**
*   **Memory Complexity:** The method reduces memory usage from $O(N^3)$ to $O(RN)$ [S1].
*   **Illumination Handling:** The choice of integration method for $J_{ss}$ is critical. Using standard Monte Carlo for sphere integration is computationally expensive [S1].

## Subtopics

### [Density Reconstruction via Differentiable Rendering](3659-density-reconstruction-via-differentiable-rendering.md)
The process of reconstructing the density field by computing loss against target/primal images, reading density gradients from recorded sampling positions, updating voxel values, and releasing memory.

## Operating characteristics
*   **Memory Complexity:** Reduces memory usage from $O(N^3)$ (where $N$ is the voxel grid dimension) to $O(RN)$ (where $R$ is the number of rays and $N$ is the ray length/samples) [S1]. This is achieved by maintaining gradients only along active ray paths rather than the entire volume grid [S1].
*   **Computational Cost:** The concurrent execution of forward and backward passes facilitates the reuse of the Jacobian term $J_{ss}$ [S1]. Specialized integration techniques (importance sampling for environment maps, direct computation for point/parallel lights) are used to mitigate the high cost of straightforward Monte Carlo integration for sphere integration [S1].
*   **Strengths:** Highly efficient for fluid density optimization due to reduced memory footprint and optimized gradient recording [S1].
*   **Limitations:** Requires careful implementation of the sparse stack structure and specialized integration methods for different illumination types [S1].

## Background
This method originates from research on physics-based differentiable rendering for fluid modeling [S1]. It addresses the high memory consumption of standard reverse-mode automatic differentiation in volume rendering by introducing a sparse gradient recording mechanism and concurrent pass execution [S1].
