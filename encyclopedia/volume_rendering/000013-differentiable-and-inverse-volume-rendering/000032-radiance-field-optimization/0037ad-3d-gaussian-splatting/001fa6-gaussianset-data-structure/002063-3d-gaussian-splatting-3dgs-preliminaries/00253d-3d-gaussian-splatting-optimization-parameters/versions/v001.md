# 3D Gaussian Splatting Optimization Parameters

Also called: 3DGS Training Hyperparameters, Densification and Opacity Reset Settings

## Overview
This method defines the hyperparameters and procedural rules for optimizing a set of 3D Gaussians to reconstruct a scene from images. It solves the problem of initializing and maintaining an appropriate density of Gaussian primitives during training, ensuring the representation is neither too sparse (underfitting) nor too dense (overfitting/noise). It sets apart from static rendering by introducing adaptive density control (clone, split, prune) and periodic opacity resets, which are critical for converging to a high-fidelity radiance field [S1, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
- Initial set of $N$ 3D Gaussians $\mathcal{G} = \{g_i\}_{i=1}^N$.
- Training images with known camera poses.
- Optimization hyperparameters (see below).

**Outputs:**
- Optimized set of Gaussians $\mathcal{G}'$ with updated parameters $(\boldsymbol{\mu}, q, s, \alpha, \mathrm{SH})$.

### Data Structures
Each Gaussian $g_i$ stores:
- $\boldsymbol{\mu}_i \in \mathbb{R}^3$: Center position.
- $q_i \in \mathbb{R}^4$: Orientation (quaternion, normalized).
- $s_i \in \mathbb{R}^3$: Scale (log-space or linear, depending on implementation; typically log-space for stability).
- $\alpha_i \in [0, 1]$: Opacity.
- $\mathrm{SH}_i$: Spherical Harmonics coefficients (typically degree 3, 48 coefficients).

The covariance matrix $\Sigma_i$ is reconstructed from $q_i$ and $s_i$ as:
$$ \Sigma_i = R_i \, \mathrm{diag}(s_i)^2 \, R_i^\top $$
where $R_i$ is the rotation matrix derived from $q_i$ [S1, unofficial].

### Optimization Steps
The training process alternates between rendering, loss computation, and density control.

1. **Initialization**:
   - Place initial Gaussians using Structure-from-Motion (SfM) points.
   - Set initial scales $s_i$ based on the distance to nearest neighbors.
   - Initialize opacities $\alpha_i$ to a small value (e.g., 0.1) or 1.0 depending on the variant. [G] *Note: Original 3DGS initializes opacity to 0.1 to allow gradual growth.*

2. **Rendering**:
   - Project each Gaussian to 2D using EWA splatting. The 2D covariance $\Sigma_{2D}$ is obtained by linearizing the perspective projection at the Gaussian center $\boldsymbol{\mu}_c$ [S1, unofficial].
   - Render image via alpha compositing of 2D Gaussian footprints.

3. **Loss Computation**:
   - Compute photometric loss (e.g., L1 + SSIM) between rendered and ground-truth images.

4. **Gradient Accumulation**:
   - Accumulate gradients for $\boldsymbol{\mu}_i$ and other parameters. Specifically, track the magnitude of the gradient of the loss with respect to the position $\boldsymbol{\mu}_i$, denoted $\|\nabla_{\boldsymbol{\mu}_i} \mathcal{L}\|$.

5. **Adaptive Density Control (Every $K$ iterations)**:
   - **Clone**: For Gaussians with high gradient magnitude $\|\nabla_{\boldsymbol{\mu}_i} \mathcal{L}\| > \tau_{clone}$ and low opacity $\alpha_i < \alpha_{thresh}$, clone the Gaussian. The clone is placed at $\boldsymbol{\mu}_i$ with a small perturbation. [S1, unofficial]
   - **Split**: For Gaussians with high gradient magnitude $\|\nabla_{\boldsymbol{\mu}_i} \mathcal{L}\| > \tau_{split}$ and scale $s_i$ larger than a threshold, split the Gaussian into two. The new scales are reduced (e.g., by a factor of 1.6). [S1, unofficial]
   - **Prune**: Remove Gaussians with opacity $\alpha_i < \alpha_{prune}$ (e.g., 0.005) or scale $s_i$ too small. [S1, unofficial]
   - **Opacity Reset**: Every $K_{reset}$ iterations, reset the opacity of all Gaussians to a small value (e.g., 0.01) and re-normalize or adjust scales to maintain visual consistency. This prevents opacities from saturating and allows further densification. [S1, unofficial]

### Parameters
- **Densification Gradient Threshold ($\tau_{clone}, \tau_{split}$)**: Approximately $2 \times 10^{-4}$ [S1, unofficial].
- **Opacity Reset Interval ($K_{reset}$)**: Every 3000 iterations [S1, unofficial].
- **Pruning Threshold ($\alpha_{prune}$)**: Typically 0.005 [G] *Note: Common value in original implementation.*
- **Clone/Scale Thresholds**: Specific scale thresholds are not explicitly given in the sources; they are typically relative to the initial scale or a global average. "Not given in the sources."

### Pseudocode
```python
def optimize_gaussians(gaussians, images, poses, num_iterations, 
                       grad_threshold_clone=2e-4, 
                       grad_threshold_split=2e-4, 
                       opacity_reset_interval=3000,
                       alpha_prune=0.005):
    for iter in range(num_iterations):
        # 1. Render
        rendered_image = render(gaussians, poses)
        
        # 2. Compute Loss
        loss = compute_loss(rendered_image, images[iter % len(images)])
        
        # 3. Backpropagate
        gradients = compute_gradients(loss, gaussians)
        
        # 4. Update Parameters (SGD/Adam)
        update_parameters(gaussians, gradients)
        
        # 5. Adaptive Density Control
        if iter % 100 == 0:  # Check every 100 iterations
            for g in gaussians:
                grad_mag = norm(gradients[g].mu)
                
                # Clone condition
                if grad_mag > grad_threshold_clone and g.alpha < 0.01:
                    clone_gaussian(g)
                
                # Split condition
                if grad_mag > grad_threshold_split and g.scale > threshold_scale:
                    split_gaussian(g)
                
                # Prune condition
                if g.alpha < alpha_prune:
                    prune_gaussian(g)
        
        # 6. Opacity Reset
        if iter % opacity_reset_interval == 0:
            reset_opacities(gaussians)
```

### Edge Cases and Pitfalls
- **Precision**: Using log-space for scales is recommended to prevent negative scales and improve optimization stability. [G]
- **Boundaries**: Cloning and splitting can lead to explosion in the number of Gaussians if thresholds are too low. Monitor memory usage.
- **Degenerate Input**: If the scene has low texture, gradients may be small, leading to insufficient densification. Consider adjusting thresholds or using additional priors.

## Subtopics

### Mip-Splatting
Fixes scale-aliasing via 3D smoothing + 2D Mip filter. Use when high-frequency details cause aliasing artifacts. [S1, unofficial]

### 2DGS
Replaces 3D ellipsoids with oriented disks for better surface reconstruction. Use when geometry/mesh extraction is the primary goal. [S1, unofficial]

### Scaffold-GS / Octree-GS
Uses voxel anchors + tiny MLP for compression and far-view extrapolation. Use when model size is a constraint. [S1, unofficial]

### Hierarchical 3DGS
Provides Level-of-Detail (LoD) from city-scale to centimeter close-ups. Use for large-scale scenes. [S1, unofficial]

## Operating characteristics
- **Time Complexity**: Rendering is $O(N)$ where $N$ is the number of Gaussians. Densification adds overhead but is sparse.
- **Memory Complexity**: $O(N)$ per Gaussian. Vanilla 3DGS uses 1–3 M Gaussians for room-scale scenes, occupying 200–800 MB on disk [S1, unofficial].
- **Performance**: Real-time rendering is achievable with tile-based rasterization. Optimization speed depends on the number of Gaussians and iterations.
- **Strengths**: High-quality novel view synthesis, real-time rendering, explicit representation.
- **Limitations**: Large model size, potential for popping artifacts due to per-tile center-depth sort (mitigated by StopThePop, GOF, exact pixel sort) [S1, unofficial].
- **When to Use**: Photorealistic novel view synthesis, room-scale scenes with plenty of views. [S1, unofficial]
- **When Not to Use**: When surface mesh quality is critical (use 2DGS), or when model size is extremely constrained (use compression techniques like LightGaussian, SOG, EAGLES, RDO-Gaussian) [S1, unofficial].

## Background
3D Gaussian Splatting (3DGS) was introduced as a replacement for NeRF's MLP+ray-march approach, using explicit anisotropic Gaussians and tile rasterization for real-time rendering [S1, unofficial]. The optimization parameters described here are based on the original 3DGS implementation and its subsequent refinements. The method has become a standard for radiance-field optimization, with numerous variants addressing specific challenges like compression, dynamic scenes, and geometry extraction [S1, unofficial].
