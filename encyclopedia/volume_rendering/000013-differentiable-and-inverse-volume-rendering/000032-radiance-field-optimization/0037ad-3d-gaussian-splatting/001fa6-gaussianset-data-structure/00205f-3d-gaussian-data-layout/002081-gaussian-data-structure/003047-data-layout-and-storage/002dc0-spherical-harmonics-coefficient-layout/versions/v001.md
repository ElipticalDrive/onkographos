# Spherical Harmonics Coefficient Layout

Also called: Per-Dimension SH Storage, SH Buffer Layout

## Overview
This method defines the memory layout for storing spherical harmonics (SH) coefficients for 3D Gaussian splats. It solves the problem of efficiently packing per-splat color data (represented by SH coefficients) into contiguous buffers for GPU transfer and rendering. It sets itself apart from sibling layouts by grouping data by splat first, then by coefficient, then by spatial dimension (RGB), whereas alternative layouts might group by dimension or coefficient globally.

## How it works
**Inputs:** A collection of splats, each having SH coefficients for $L$ degrees.
**Outputs:** A contiguous `FloatBuffer` (or equivalent linear array) of size $N \times D \times 3$, where $N$ is the number of splats, $D$ is the total number of SH coefficients per splat, and 3 represents the RGB color channels.

**Data Structures:**
*   `FloatBuffer`: A 1D array of 32-bit floats.
*   `shDimensions` ($D$): The total number of SH coefficients for a given degree. Calculated as $D = (L+1)^2 - 1$ for real SH, or derived via `Splats.dimensionsForDegree(shDegree)` [S1, unofficial].
*   `N`: Total number of splats.

**Layout Formula:**
The buffer index $idx$ for the component $c \in \{0, 1, 2\}$ (representing x/R, y/G, z/B) of the $d$-th SH coefficient of the $i$-th splat is:
$$ idx = ((i \times D) + d) \times 3 + c $$

**Steps:**
1.  Initialize a `FloatBuffer` of size $N \times D \times 3$.
2.  Iterate over each splat index $i$ from $0$ to $N-1$.
3.  For each splat $i$, iterate over each coefficient index $d$ from $0$ to $D-1$.
4.  For each coefficient $d$, retrieve the three color components (R, G, B) or (X, Y, Z) from the splat's SH representation.
5.  Write the components to the buffer at indices:
    *   $((i \times D) + d) \times 3 + 0$
    *   $((i \times D) + d) \times 3 + 1$
    *   $((i \times D) + d) \times 3 + 2$

**Pseudocode:**
```python
def write_sh_coefficients(splats, sh_degree):
    """
    Writes SH coefficients into a contiguous buffer.
    
    Args:
        splats: List of Splat objects.
        sh_degree: Integer SH degree.
        
    Returns:
        list: Flat list of floats representing the buffer.
    """
    n = len(splats)
    # Calculate total coefficients per splat. 
    # Standard SH degree L has (L+1)^2 coefficients. 
    # Note: Some implementations exclude DC or handle normalization differently.
    # Using the source's helper concept:
    sh_dimensions = (sh_degree + 1) ** 2 
    
    buffer_size = n * sh_dimensions * 3
    buffer = [0.0] * buffer_size
    
    for i in range(n):
        splat = splats[i]
        for d in range(sh_dimensions):
            # Get SH coefficients for this degree and component
            # Assuming getShX, getShY, getShZ return the float values
            # for the d-th coefficient of the splat
            val_x = splat.get_sh_x(d)
            val_y = splat.get_sh_y(d)
            val_z = splat.get_sh_z(d)
            
            base_idx = (i * sh_dimensions + d) * 3
            buffer[base_idx + 0] = val_x
            buffer[base_idx + 1] = val_y
            buffer[base_idx + 2] = val_z
            
    return buffer
```

**Parameters:**
*   `sh_degree`: Integer, typically 3 or 4 for high-quality rendering [S2, unofficial].
*   `shDimensions`: Derived from `sh_degree`.

**Edge Cases:**
*   **Degree 0:** `shDimensions` = 1. Only the DC term is stored.
*   **Precision:** Float32 is standard. Higher precision may be needed for training but increases memory bandwidth.
*   **Boundary:** Ensure `shDimensions` matches the number of coefficients actually stored in the splat object. Mismatches cause buffer overflows or read errors.

## Subtopics

### Spherical Harmonics Texture Management
This variant manages SH data as GPU textures rather than linear buffers. It iterates over `SH_KEYS` (block identifiers). For each key, it calls `ensureShTexture`. If a texture exists and `needsUpdate` is true, it signals the GPU driver to refresh. If no texture exists, it creates a new one from `this.extra[key]` if data is present. This approach groups coefficients by block identifiers (`this.shTextures[key]`) rather than a single flat buffer, facilitating streaming and LOD management [S2, unofficial].

## Operating characteristics
*   **Memory Complexity:** $O(N \times D)$. For degree 3 ($D=16$) and $N=1,000,000$ splats, this is $1,000,000 \times 16 \times 3 \times 4$ bytes $\approx 192$ MB.
*   **Time Complexity:** $O(N \times D)$ to write/read.
*   **Strengths:** Contiguous memory access pattern is cache-friendly for CPU-to-GPU transfers. Simple indexing logic.
*   **Limitations:** Large buffers may exceed single texture size limits on some GPUs, requiring the texture management variant.
*   **When to use:** Standard offline conversion or static scenes where simple buffer uploads suffice.

## Background
This layout is derived from the JSplat library implementation, which provides utilities for writing Gaussian Splat data to buffers [S1, unofficial]. It is commonly used in the preprocessing stage of 3D Gaussian Splatting pipelines before data is uploaded to the GPU for rendering.
