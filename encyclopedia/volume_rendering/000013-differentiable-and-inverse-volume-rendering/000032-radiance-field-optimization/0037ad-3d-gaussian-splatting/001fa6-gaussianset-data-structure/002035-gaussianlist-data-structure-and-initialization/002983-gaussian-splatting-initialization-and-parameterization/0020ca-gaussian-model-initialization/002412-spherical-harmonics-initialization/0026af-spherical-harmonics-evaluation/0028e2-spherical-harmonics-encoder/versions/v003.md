# Spherical Harmonics Encoder

Also called: SH Encoding, Spherical Harmonics Basis

## Overview
The Spherical Harmonics Encoder maps a 3D viewing direction vector into a set of spherical harmonics (SH) coefficients up to a specified maximum degree [S1, unofficial]. It solves the problem of representing directional information (view direction) in a differentiable, basis-function expansion for view-dependent rendering [S1, unofficial]. It differs from [Spherical Harmonics Evaluation](3848-spherical-harmonics-evaluation.md) by performing the basis projection (encoding) rather than the dot product with coefficients (evaluation), and from [Spherical Harmonics Rotation](3985-spherical-harmonics-rotation.md) by operating on the raw direction vector rather than rotating existing coefficients [G].

## How it works
**Inputs and Outputs:**
- Input: A direction vector $\mathbf{v} = (x, y, z)$ of dimension 3 [S1, unofficial].
- Output: A tensor of SH coefficients with shape `(*input.shape[:-1], out_dim)`, where `out_dim` is the number of coefficients for the specified degree [S1, unofficial].

**Data Structures:**
The output tensor stores coefficients in $m$-order: index 0 for $m=0$; indices 1–3 for $m=-1, 0, 1$; indices 4–8 for $m=-2, -1, 0, 1, 2$; indices 9–15 for $m=-3 \dots 3$; indices 16–24 for $m=-4 \dots 4$ [S1, unofficial].

**Constants:**
The encoder uses pre-defined normalization constants for each degree [S1, unofficial]:
- $C_0 = 0.28209479177387814$
- $C_1 = 0.4886025119029199$
- $C_2 = [0.483186, 0.743124, 0.946174, 0.483186, 0.1057855]$ [S1, unofficial]
- $C_3, C_4$: Constants for higher degrees are not provided in the sources [S1, unofficial]. Standard unnormalized SH constants are used below [G].

**Parameters:**
- `input_dim`: The dimensionality of the input vector. Must be 3. Enforced by assertion [S1, unofficial].
- `degree`: The maximum degree of spherical harmonics to compute. Valid range is 1 to 5. Enforced by assertion [S1, unofficial].
- `out_dim`: The output dimensionality of the encoding. The source states it is calculated as `degree ** 2` (noting a typo in the source where it claims degree 4 yields 16, whereas the explicit index ranges and standard SH theory require `(degree + 1) ** 2`) [S1, unofficial].

**Steps:**
1. Unbind the input direction vector into components $x, y, z$: `x, y, z = input.unbind(-1)` [S1, unofficial].
2. Initialize output tensor `result` with zeros [S1, unofficial].
3. **Degree 0:** Set `result[..., 0] = C0` [S1, unofficial].
4. **Degree 1:** If `degree >= 1`, compute coefficients at indices 1, 2, 3: `result[..., 1] = -C1 * y`, `result[..., 2] = C1 * z`, `result[..., 3] = -C1 * x` [S1, unofficial].
5. **Degree 2:** If `degree >= 2`, compute intermediate quadratic terms: `xx, yy, zz = x * x, y * y, z * z` and `xy, yz, xz = x * y, y * z, x * z` [S1, unofficial]. Compute coefficients at indices 4–8: `result[..., 4] = C2[0] * xy`, `result[..., 5] = C2[1] * yz`, `result[..., 6] = C2[2] * (2.0 * zz - xx - yy)`, `result[..., 7] = C2[3] * xz`, `result[..., 8] = C2[4] * (xx - yy)` [S1, unofficial].
6. **Degree 3:** If `degree >= 3`, compute cubic terms and coefficients at indices 9–15 using standard SH basis functions [G].
7. **Degree 4:** If `degree >= 4`, compute quartic terms and coefficients at indices 16–24 using standard SH basis functions [G].

**Pitfalls:**
- **Gradient Discrepancy:** For degree 2, index 6, an alternative formula `C2[2] * (3.0 * zz - 1)` exists [S1, unofficial]. This is commented out in the source because `xx + yy + zz == 1` on the unit sphere, but the alternative leads to different backward gradients [S1, unofficial]. The implementation must use `(2.0 * zz - xx - yy)` for consistency with the source's gradient behavior [S1, unofficial].
- **Input Normalization:** The input direction vector should be normalized (unit length) for the SH basis to be orthonormal, though the encoder itself does not enforce normalization [G].

**Pseudocode:**
```python
import torch
import math

class SHEncoder(torch.nn.Module):
    def __init__(self, input_dim=3, degree=2):
        super().__init__()
        assert input_dim == 3
        assert 1 <= degree <= 5
        self.input_dim = input_dim
        self.degree = degree
        self.out_dim = (degree + 1) ** 2

        self.C0 = 0.28209479177387814
        self.C1 = 0.4886025119029199
        self.C2 = torch.tensor([0.483186, 0.743124, 0.946174, 0.483186, 0.1057855])

        # Standard SH degree 3 constants [G]
        self.C3 = torch.tensor([
            math.sqrt(105.0 / (2.0 * math.pi)) / 8.0,
            math.sqrt(105.0 / math.pi) / 4.0,
            math.sqrt(21.0 / (2.0 * math.pi)) / 4.0,
            math.sqrt(7.0 / math.pi) / 4.0,
            math.sqrt(21.0 / (2.0 * math.pi)) / 4.0,
            math.sqrt(105.0 / math.pi) / 4.0,
            math.sqrt(105.0 / (2.0 * math.pi)) / 8.0
        ])
        # Standard SH degree 4 constants [G]
        self.C4 = torch.tensor([
            math.sqrt(1155.0 / (32.0 * math.pi)),
            math.sqrt(3465.0 / (math.pi)) / 8.0,
            math.sqrt(35.0 / (math.pi)) / 4.0,
            math.sqrt(15.0 / (math.pi)) / 4.0,
            math.sqrt(7.0 / (math.pi)) / 4.0,
            math.sqrt(15.0 / (math.pi)) / 4.0,
            math.sqrt(35.0 / (math.pi)) / 4.0,
            math.sqrt(3465.0 / (math.pi)) / 8.0,
            math.sqrt(1155.0 / (32.0 * math.pi))
        ])

    def forward(self, directions):
        x, y, z = directions.unbind(-1)
        result = torch.zeros(*directions.shape[:-1], self.out_dim, device=directions.device, dtype=directions.dtype)

        result[..., 0] = self.C0

        if self.degree >= 1:
            result[..., 1] = -self.C1 * y
            result[..., 2] = self.C1 * z
            result[..., 3] = -self.C1 * x

        if self.degree >= 2:
            xx, yy, zz = x * x, y * y, z * z
            xy, yz, xz = x * y, y * z, x * z
            result[..., 4] = self.C2[0] * xy
            result[..., 5] = self.C2[1] * yz
            result[..., 6] = self.C2[2] * (2.0 * zz - xx - yy)
            result[..., 7] = self.C2[3] * xz
            result[..., 8] = self.C2[4] * (xx - yy)

        if self.degree >= 3:
            xxx, xxy, xyy, yyy = x * xx, x * xy, x * yy, y * yy
            xyz, xzz, yzz, zzz = x * yz, x * zz, y * zz, z * zz
            # m=-3 to 3
            result[..., 9]  = self.C3[0] * (xxx - 3 * x * yy)
            result[..., 10] = self.C3[1] * xyz
            result[..., 11] = self.C3[2] * z * (5 * zz - 3)
            result[..., 12] = self.C3[3] * z * (3 * zz - 1)
            result[..., 13] = self.C3[4] * x * (5 * zz - 1)
            result[..., 14] = self.C3[5] * z * (xx - yy)
            result[..., 15] = self.C3[6] * (xxx - 3 * x * yy)

        if self.degree >= 4:
            xxxx, xxxy, xxyy, xyyy, yyyy = x * xxx, x * xxy, x * xyy, x * yyy, y * yyy
            xxyz, xyyz, xxzz, yyzz, xzzz, yzzz, zzzz = x * xyz, y * xyz, x * xzz, y * yzz, x * yzz, y * yzz, z * zzz
            # m=-4 to 4
            result[..., 16] = self.C4[0] * (xxxx - 6 * xx * yy + yyyy)
            result[..., 17] = self.C4[1] * z * (xxxx - 10 * xx * yy + yyyy)
            result[..., 18] = self.C4[2] * z * (xx - yy)
            result[..., 19] = self.C4[3] * z * (3 * zz - 1)
            result[..., 20] = self.C4[4] * (5 * zz * zz - 6 * zz + 1)
            result[..., 21] = self.C4[5] * z * (3 * zz - 1)
            result[..., 22] = self.C4[6] * z * (xx - yy)
            result[..., 23] = self.C4[7] * z * (xxxx - 10 * xx * yy + yyyy)
            result[..., 24] = self.C4[8] * (xxxx - 6 * xx * yy + yyyy)

        return result
```

## Subtopics

### SH Feature Encoding
A method to encode view direction for modeling view-dependent effects by multiplying each Spherical Harmonics (SH) coefficient by a feature vector, rather than using vanilla SH encoding [S2]. It predicts the SH feature vector $f_l^m$ using a spatial MLP from the rendered feature vector, concatenates all resultant SH encodings with a view-independent bottleneck feature vector, and feeds the concatenated vector into a directional MLP to predict the final rendered color [S2]. The encoding follows $e_l^m = f_l^m Y_l^m(d)$, where $e_l^m$ is the SH feature encoding, $f_l^m$ is an SH feature vector, $Y_l^m$ is the SH basis function with degree $l$, $m \in \{-l, \dots, l\}$, and $d$ is the view direction [S2].

## Operating characteristics
- **Time Complexity**: $O(1)$ per direction vector, proportional to the square of the degree ($O(L^2)$) [G].
- **Memory Complexity**: $O(L^2)$ to store the output coefficients [G].
- **Measured Performance**: Not given in the sources.
- **Strengths**: Differentiable, compact representation of view-dependent effects [G].
- **Limitations**: Higher degrees increase computational cost and memory. Requires normalized input vectors for optimal basis properties [G].
- **When to use**: When view-dependent color variation must be modeled efficiently in differentiable rendering pipelines [G].
- **When not to use**: When extreme view-dependent detail requires higher-order expansions beyond degree 4, or when hardware lacks efficient tensor operations for batched direction encoding [G].

## Background
Spherical Harmonics are a set of orthogonal functions defined on the sphere, commonly used in computer graphics for lighting and view-dependent shading [G]. The encoder implementation described here is derived from neural rendering pipelines, specifically HashNeRF-pytorch [S1, unofficial]. It was later adopted as a standard initialization and parameterization step in 3D Gaussian Splatting for view-dependent color representation [G].
