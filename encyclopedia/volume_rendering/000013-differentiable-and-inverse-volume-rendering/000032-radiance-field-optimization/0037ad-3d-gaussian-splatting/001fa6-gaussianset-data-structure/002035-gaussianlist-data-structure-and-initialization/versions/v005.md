# GaussianList Data Structure and Initialization

Also called: GaussianList

## Overview
The `GaussianList` is a contiguous, column-major data structure that stores the attributes of a set of 3D Gaussians, enabling batched processing for differentiable volume rendering. It solves the problem of efficiently organizing learnable parameters (position, scale, rotation, opacity, and spherical harmonics coefficients) for GPU or CPU vectorization. It differs from its parent `GaussianSet` by explicitly defining the memory layout and initialization sequence required to compute the 3D covariance matrices from the raw parameters, serving as the foundational state before projection and rendering.

## How it works
### Inputs and Outputs
- **Input**: A vector of Gaussian objects, each containing position (3D), scale (3D), opacity (scalar), rotation (quaternion), and spherical harmonics (SH) coefficients.
- **Output**: A `GaussianList` instance with pre-allocated matrices and computed 3D covariance matrices.

### Data Structures
The `GaussianList` struct stores attributes in column-major matrices to facilitate batch processing. The fields are:

1.  **positions**: `na::Matrix4xX<f32>` (4 rows × N columns). Stores 4D homogeneous coordinates. The first three rows contain the $(x, y, z)$ components, and the fourth row is always $1.0$.
2.  **scales**: `na::Matrix3xX<f32>` (3 rows × N columns). Stores the scale components $(s_x, s_y, s_z)$ for each Gaussian.
3.  **opacities**: `na::DVector<f32>` (1D vector of size N). Stores the opacity scalar for each Gaussian.
4.  **rotations**: `na::Matrix4xX<f32>` (4 rows × N columns). Stores the quaternion components $(q_w, q_x, q_y, q_z)$ for each Gaussian.
5.  **sh**: `Matrix48xX<f32>` (48 rows × N columns). Stores the spherical harmonics coefficients. The layout within each column is interleaved by RGB channel for each degree/order: $C_{0,R}, C_{0,B}, C_{0,G}, C_{1,R}, C_{1,B}, C_{1,G}, \dots$.
6.  **num_gaussians**: `usize`. The total number of Gaussians $N$.
7.  **cov3d**: `na::Matrix3xX<f32>` (3 rows × N columns). Pre-allocated buffer of zeros, filled with the computed 3D covariance matrices.

### Initialization Steps
The initialization process constructs the matrices and computes the covariances as follows:

1.  **Set Count**: Set `num_gaussians` to the length of the input Gaussian vector.
2.  **Construct Positions**: Iterate over the input Gaussians. For each Gaussian $i$, clone its position components $(x_i, y_i, z_i)$ into the first three rows of the $i$-th column of `positions`. Set the fourth row of the $i$-th column to $1.0$.
3.  **Construct Scales**: Iterate over the input Gaussians. Clone the scale components $(s_{x,i}, s_{y,i}, s_{z,i})$ into the corresponding rows of the $i$-th column of `scales`.
4.  **Construct Opacities**: Clone the opacity value $\alpha_i$ into the $i$-th element of the `opacities` vector.
5.  **Construct Rotations**: Iterate over the input Gaussians. Clone the quaternion components $(q_{w,i}, q_{x,i}, q_{y,i}, q_{z,i})$ into the corresponding rows of the $i$-th column of `rotations`.
6.  **Construct SH Coefficients**: Clone the spherical harmonics coefficients into the corresponding rows of the $i$-th column of the `sh` matrix, following the interleaved RGB layout.
7.  **Initialize Cov3d**: Initialize the `cov3d` matrix with zeros of size $3 \times N$.
8.  **Compute Covariances**: Call `compute_cov3d()` to calculate the 3D covariance matrices for all Gaussians.

### Centering Positions
Before or after initialization, positions may be centered to the mean:
1.  Initialize `avg_pos` as a zero vector $(0, 0, 0)$.
2.  Iterate over all Gaussians, adding each position $(x_i, y_i, z_i)$ to `avg_pos`.
3.  Divide `avg_pos` by `num_gaussians` to obtain the mean $(\bar{x}, \bar{y}, \bar{z})$.
4.  Iterate over all Gaussians again, subtracting the mean from each position: $x_i \leftarrow x_i - \bar{x}$, $y_i \leftarrow y_i - \bar{y}$, $z_i \leftarrow z_i - \bar{z}$.

### Computing 3D Covariance Matrices (`compute_cov3d`)
For each Gaussian $i$ from $0$ to `num_gaussians` - 1:
1.  Extract the rotation quaternion from the $i$-th column of `rotations`.
2.  Convert the quaternion to a `UnitQuaternion`, then to a $3 \times 3$ rotation matrix $R_i$.
3.  Create a diagonal scale matrix $S_i$:
    $$
    S_i = \begin{bmatrix}
    s_{x,i}^2 & 0 & 0 \\
    0 & s_{y,i}^2 & 0 \\
    0 & 0 & s_{z,i}^2
    \end{bmatrix}
    $$
4.  Compute the covariance matrix $\Sigma_i$:
    $$
    \Sigma_i = R_i S_i R_i^T
    $$
5.  Copy the resulting $3 \times 3$ matrix $\Sigma_i$ into the `cov3d` buffer at offset $i \times 3$ (column-major).

### Projecting 3D Covariance to 2D Screen Space (`project_cov3d_to_screen`)
Given a Gaussian index $i$, its 3D covariance $\Sigma_i$, and the camera view matrix $V$:
1.  Get the Gaussian position $P_i$ from `positions` and the view matrix $V$.
2.  Convert $P_i$ to a homogeneous vector $p_w = (x, y, z, 1.0)^T$.
3.  Transform to camera space: $p_{cam} = V \cdot p_w$. Let $p_{cam} = (x_c, y_c, z_c, w_c)^T$.
4.  Get the focal lengths $f_x, f_y$ and the tangent of the horizontal and vertical FOV ($\tan(\text{FOV}_x), \tan(\text{FOV}_y)$).
5.  Compute the tangent of the Gaussian center in camera space:
    $$
    t_x = \frac{x_c}{z_c}, \quad t_y = \frac{y_c}{z_c}
    $$
6.  Clamp the tangents to the limits defined by $1.3 \times \tan(\text{FOV}_x)$ and $1.3 \times \tan(\text{FOV}_y)$:
    $$
    t_x = \text{clamp}(t_x, -1.3 \tan(\text{FOV}_x), 1.3 \tan(\text{FOV}_x))
    $$
    $$
    t_y = \text{clamp}(t_y, -1.3 \tan(\text{FOV}_y), 1.3 \tan(\text{FOV}_y))
    $$
    Multiply back by $z_c$ to get the clamped screen-space coordinates relative to the center:
    $$
    t.x = t_x \cdot z_c, \quad t.y = t_y \cdot z_c
    $$
    Let $t.z = z_c$.
7.  Compute the Jacobian $J$ ($3 \times 3$ matrix) using $f_x, f_y, t.x, t.y, t.z$:
    $$
    J = \begin{bmatrix}
    f_x / t.z & 0 & -f_x \cdot t.x / (t.z)^2 \\
    0 & f_y / t.z & -f_y \cdot t.y / (t.z)^2 \\
    0 & 0 & 1
    \end{bmatrix}
    $$
8.  Compute $W$ as the transpose of the top-left $3 \times 3$ submatrix of the view matrix $V$.
9.  Compute the transformation matrix $T$:
    $$
    T = W \cdot J
    $$
10. Compute the projected 2D covariance $\Sigma_{2D}$:
    $$
    \Sigma_{2D} = T^T \cdot \Sigma_i \cdot T
    $$
11. Extract the top-left $2 \times 2$ submatrix of $\Sigma_{2D}$ as the final 2D covariance.
12. Apply a low-pass filter by adding $0.3$ to the diagonal elements:
    $$
    \Sigma_{2D}[0,0] \leftarrow \Sigma_{2D}[0,0] + 0.3
    $$
    $$
    \Sigma_{2D}[1,1] \leftarrow \Sigma_{2D}[1,1] + 0.3
    $$
13. Return $\Sigma_{2D}$.

### Evaluating Color from Spherical Harmonics
1.  Pass the SH coefficients column for index $i$, the SH dimension, and the viewing direction vector $d$ to `eval_spherical_harmonics`.
2.  Return the resulting color vector $C$ and the Gaussian's opacity $\alpha$.

### Pseudocode
```python
def initialize_gaussian_list(input_gaussians):
    """
    input_gaussians: List of Gaussian objects with attributes:
      - position: (x, y, z)
      - scale: (sx, sy, sz)
      - opacity: alpha
      - rotation: (qw, qx, qy, qz)
      - sh: list of coefficients
    """
    N = len(input_gaussians)
    
    # Initialize matrices
    positions = zeros((4, N))
    scales = zeros((3, N))
    opacities = zeros(N)
    rotations = zeros((4, N))
    sh = zeros((48, N))
    cov3d = zeros((3, N))
    
    for i in range(N):
        g = input_gaussians[i]
        
        # Positions: 4D homogeneous
        positions[0, i] = g.position.x
        positions[1, i] = g.position.y
        positions[2, i] = g.position.z
        positions[3, i] = 1.0
        
        # Scales
        scales[0, i] = g.scale.x
        scales[1, i] = g.scale.y
        scales[2, i] = g.scale.z
        
        # Opacities
        opacities[i] = g.opacity
        
        # Rotations: Quaternion
        rotations[0, i] = g.rotation.qw
        rotations[1, i] = g.rotation.qx
        rotations[2, i] = g.rotation.qy
        rotations[3, i] = g.rotation.qz
        
        # SH Coefficients
        sh[:, i] = g.sh
        
    # Compute Covariances
    compute_cov3d(positions, scales, rotations, cov3d, N)
    
    return GaussianList(positions, scales, opacities, rotations, sh, N, cov3d)

def compute_cov3d(positions, scales, rotations, cov3d, N):
    for i in range(N):
        # Extract quaternion
        qw, qx, qy, qz = rotations[0, i], rotations[1, i], rotations[2, i], rotations[3, i]
        
        # Convert quaternion to rotation matrix R
        R = quaternion_to_rotation_matrix(qw, qx, qy, qz)
        
        # Scale matrix S (squared)
        sx2 = scales[0, i] ** 2
        sy2 = scales[1, i] ** 2
        sz2 = scales[2, i] ** 2
        S = diag([sx2, sy2, sz2])
        
        # Covariance = R * S * R^T
        cov = R @ S @ R.T
        
        # Store in cov3d
        cov3d[0, i] = cov[0, 0]
        cov3d[1, i] = cov[0, 1]
        cov3d[2, i] = cov[0, 2]
        cov3d[3, i] = cov[1, 0]
        cov3d[4, i] = cov[1, 1]
        cov3d[5, i] = cov[1, 2]
        cov3d[6, i] = cov[2, 0]
        cov3d[7, i] = cov[2, 1]
        cov3d[8, i] = cov[2, 2]

def project_cov3d_to_screen(cov3d_col, view_matrix, focal_x, focal_y, tan_fovx, tan_fovy):
    """
    cov3d_col: 3x3 covariance matrix for a single Gaussian
    view_matrix: 4x4 view matrix
    """
    # Get position from positions matrix (assumed available in context)
    # p_w = (x, y, z, 1)
    p_w = get_position_homogeneous() 
    
    # Transform to camera space
    p_cam = view_matrix @ p_w
    xc, yc, zc, wc = p_cam[0], p_cam[1], p_cam[2], p_cam[3]
    
    # Compute tangents
    tx = xc / zc
    ty = yc / zc
    
    # Clamp tangents
    limit_x = 1.3 * tan_fovx
    limit_y = 1.3 * tan_fovy
    tx = clamp(tx, -limit_x, limit_x)
    ty = clamp(ty, -limit_y, limit_y)
    
    # Compute Jacobian J
    tz = zc
    J = [
        [focal_x / tz, 0, -focal_x * tx / (tz ** 2)],
        [0, focal_y / tz, -focal_y * ty / (tz ** 2)],
        [0, 0, 1]
    ]
    
    # Compute W (transpose of top-left 3x3 of view matrix)
    W = view_matrix[0:3, 0:3].T
    
    # Compute T = W * J
    T = W @ J
    
    # Compute cov2d = T^T * cov3d * T
    cov2d = T.T @ cov3d_col @ T
    
    # Extract 2x2
    cov2d_2x2 = cov2d[0:2, 0:2]
    
    # Low-pass filter
    cov2d_2x2[0, 0] += 0.3
    cov2d_2x2[1, 1] += 0.3
    
    return cov2d_2x2
```

### Edge Cases and Pitfalls
- **Division by Zero**: In `project_cov3d_to_screen`, if $z_c \le 0$, the Gaussian is behind the camera. The sources do not explicitly state the handling, but standard practice is to discard or clamp $z_c$ to a small positive value [G].
- **Precision**: The low-pass filter adds $0.3$ to the diagonal, ensuring the Gaussian is at least one pixel wide/high, preventing numerical instability from very small covariances [S1, unofficial].
- **FOV Clamping**: The limit $1.3 \times \tan(\text{FOV})$ prevents extreme tangents that could cause artifacts at the screen edges [S1, unofficial].

## Subtopics

### [LinPrim Population Control](2295-linprim-population-control.md)
LinPrim Population Control manages the density of linear primitives (octahedra and tetrahedra) during differentiable volume rendering optimization by pruning, cloning, and splitting primitives to adapt to scene complexity. It differs from standard 3D Gaussian Splatting (3DGS) by redefining primitive size metrics to accommodate non-spherical kernels and adjusting sampling distributions to respect the anisotropic geometry of linear primitives. It builds on [GaussianList Data Structure and Initialization](2214-gaussianlist-data-structure-and-initialization.md) and adapts techniques from [Gaussian Splatting Initialization and Parameterization](2313-gaussian-splatting-initialization-and-parameterization.md).

### [Gaussian Splatting Initialization and Parameterization](2313-gaussian-splatting-initialization-and-parameterization.md)
This method establishes the initial state of the learnable 3D Gaussian parameters (position, scale, rotation, opacity, and color features) required to begin differentiable volume rendering optimization. It solves the problem of providing a valid, non-degenerate starting point for the optimizer, ensuring that initial opacities are in a trainable range and scales are geometrically meaningful relative to the input data density. It sets itself apart from [Spherical Harmonics Initialization](3163-spherical-harmonics-initialization.md) by handling full geometric and attribute seeding rather than just color parameterization, and from [Angle-pose Cuboid Uniform Initialization (ACUI)](4503-angle-pose-cuboid-uniform-initialization-acui.md) by relying on sparse reconstruction data rather than uniform volumetric sampling.

### [Octree-GS / Scaffold-GS](6142-octree-gs-scaffold-gs.md)
Octree-GS and Scaffold-GS are hierarchical level-of-detail (LoD) methods that anchor scene content to a sparse voxel grid or octree structure, using the grid as a scaffold to allocate Gaussians only in occupied regions. This approach naturally adapts to view distance and significantly improves memory efficiency compared to flat Gaussian lists. Unlike sibling methods that rely on population control or simple parameterization, these methods explicitly model spatial hierarchy to enable large size reduction and better generalization to extrapolated views.

### GaussianHair
GaussianHair is a strand-aware hair method using a strand + GS representation [S2, unofficial].

## Operating characteristics
- **Time Complexity**: Initialization is $O(N)$ where $N$ is the number of Gaussians. Covariance computation is $O(N)$ with constant factor for matrix operations. Projection is $O(N)$ per view.
- **Memory Complexity**: $O(N)$ for storing positions, scales, rotations, opacities, SH coefficients, and covariances. The SH matrix dominates memory if high degrees are used.
- **Strengths**: Column-major layout enables efficient batch processing on GPUs. Pre-computed covariances speed up rendering.
- **Limitations**: Flat list structure does not support hierarchical culling or LOD natively, unlike Octree-GS.
- **When to Use**: Standard 3DGS rendering where memory is not the primary constraint and scene complexity is moderate.
- **When Not to Use**: Large-scale outdoor scenes or high-resolution assets where memory efficiency is critical; use Octree-GS instead.

## Background
The `GaussianList` data structure and its initialization procedure originate from the implementation of 3D Gaussian Splatting in the `thomasantony/splat` repository [S1, unofficial]. It provides the foundational state for differentiable volume rendering optimization, enabling the computation of 3D covariance matrices from learnable parameters.
