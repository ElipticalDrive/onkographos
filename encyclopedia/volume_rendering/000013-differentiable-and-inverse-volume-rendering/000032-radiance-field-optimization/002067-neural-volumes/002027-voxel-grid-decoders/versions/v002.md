# Voxel Grid Decoders


## Overview
Voxel Grid Decoders model the volume function $V(\mathbf{x}; \mathbf{z})$ as a discrete 3D grid of voxels, producing an explicit 3D voxel grid as the output tensor of a neural network [S1]. This approach avoids the prohibitive computational requirements of evaluating deep MLPs at every ray-marching step, enabling real-time rendering speeds [S1]. It sets itself apart from implicit MLP decoders by trading memory for speed, storing values in a structured grid rather than computing them on the fly [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A latent code vector $\mathbf{z}$ [S1].
*   **Output:** A volume tensor $\mathbf{Y} \in \mathbb{R}^{C \times D \times D \times D}$ representing the decoded volume [S1].

**Data Structures:**
*   **Tensor $\mathbf{Y}$:** A 4D tensor with dimensions $C \times D \times D \times D$ [S1].
    *   $C$: Channel dimension. In experiments, $C=4$ for RGB$\alpha$ [S1].
    *   $D$: Spatial resolution. In experiments, $D \in \{32, 128\}$ [S1].
*   **Interpolation Function $S(\cdot; \mathbf{Y})$:** Maps continuous 3D coordinates to tensor values by scaling values in $[-1, 1]$ to grid indices $[1, D]$ along each dimension, followed by trilinear interpolation [S1].

**Formulas:**
The volume decoder function is defined as [S1]:
$$
\mathbf{V}(\mathbf{x}; \mathbf{z}) = S\left(\frac{\mathbf{x} - \mathbf{x}_0}{W/2}; \mathbf{g}(\mathbf{z})\right)
$$
Where:
*   $\mathbf{x}$: The 3D query point in world space.
*   $\mathbf{x}_0$: The center of the 3D cube bounding the volume.
*   $W$: The side length of the cube.
*   $\mathbf{g}(\mathbf{z})$: The neural network that maps $\mathbf{z}$ to the tensor $\mathbf{Y}$ of size $4 \times D \times D \times D$ [S1].
*   $S(\cdot; \mathbf{Y})$: The interpolation function defined above [S1].

**Parameters:**
*   **Resolution $D$:** Typically 32 or 128 [S1].
*   **Channels $C$:** Typically 4 (RGB$\alpha$) [S1].
*   **Latent Dimension:** Varies by architecture (e.g., 1024 for convolutional variants, 128 for bottleneck) [S1].

**Architectures for $\mathbf{g}(\mathbf{z})$:**
Three variants are described in the source [S1]:
1.  **Convolutional Decoder (32³):** Apply a fully-connected layer and non-linearity to transform $\mathbf{z}$ into a 1024-dimensional representation [S1]. Reinterpret the resulting vector as a $1 \times 1 \times 1$ cube with 1024 channels [S1]. Apply 5 transposed convolutions to upsample to a final size of $32^3$ [S1].
2.  **Convolutional Decoder (128³):** Same initialization as the 32³ variant [S1]. Apply 7 transposed convolutions to upsample to a final size of $128^3$ [S1].
3.  **Bottleneck Decoder (128³):** Use 3 fully-connected layers with output sizes 128, 4, and $128^3 \times 4$ respectively [S1]. The last layer represents the decoded volume directly [S1].

**Post-processing:**
*   Apply the softplus function to the RGB$\alpha$ values in the output tensor to ensure they are non-negative [S1].

**Pseudocode:**
```python
def decode_voxel_grid(z, variant='conv_32', D=32, C=4):
    # g(z) maps latent z to tensor Y of size C x D x D x D [S1]
    if variant == 'conv_32':
        # 1. Fully-connected layer and non-linearity to 1024-dim [S1]
        h = fc(z, 1024)
        h = relu(h)
        # 2. Reinterpret as 1x1x1 cube with 1024 channels [S1]
        h = reshape(h, (1, 1024, 1, 1, 1))
        # 3. Apply 5 transposed convolutions to reach 32^3 [S1]
        # Note: Exact kernel sizes, strides, and channel progression are not given in the sources.
        for _ in range(5):
            h = transposed_conv(h, out_channels=next_channel(1024, _))
            h = relu(h)
        h = reshape(h, (C, D, D, D))
    elif variant == 'conv_128':
        # Same initialization as 32^3 variant [S1]
        h = fc(z, 1024)
        h = relu(h)
        h = reshape(h, (1, 1024, 1, 1, 1))
        # Apply 7 transposed convolutions to reach 128^3 [S1]
        for _ in range(7):
            h = transposed_conv(h, out_channels=next_channel(1024, _))
            h = relu(h)
        h = reshape(h, (C, D, D, D))
    elif variant == 'bottleneck':
        # 3 fully-connected layers with output sizes 128, 4, and 128^3 x 4 [S1]
        h = fc(z, 128)
        h = fc(h, 4)
        h = fc(h, 128 * 128 * 128 * 4)
        # Last layer represents the decoded volume directly [S1]
        h = reshape(h, (C, D, D, D))
    else:
        raise ValueError("Unknown variant")

    # Post-processing: apply softplus to RGBα values to ensure non-negativity [S1]
    h = softplus(h)
    return h

def sample_volume(tensor_Y, query_points, x0, W):
    # Normalize query points to [-1, 1] range relative to the volume [S1]
    normalized_points = (query_points - x0) / (W / 2.0)
    # Note: The source states evaluation is restricted to the bounding volume.
    # Standard implementations clamp or mask out-of-bounds points [G].
    normalized_points = clamp(normalized_points, -1.0, 1.0)
    # Perform trilinear interpolation using standard grid sampling [G]
    samples = grid_sample(tensor_Y, normalized_points, mode='trilinear')
    return samples
```

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** The decoder function is only evaluated inside the volume it covers by computing intersections with its bounding volume [S1].
*   **Non-negativity:** RGB$\alpha$ values must be non-negative. The softplus function ensures this [S1].
*   **Memory:** High-resolution grids ($128^3$) consume significant memory. The bottleneck decoder runs at 90Hz (matching the faster 32³ convolutional variant) while achieving a higher resolution than the slow 128³ convolutional variant (22Hz) [S1].

## Operating characteristics
*   **Time Complexity:** Depends on the decoder architecture [S1]. Convolutional decoders involve upsampling operations [S1]. Bottleneck decoders involve large fully connected layers [S1].
*   **Memory Complexity:** Proportional to $C \times D^3$ [S1]. For $D=128, C=4$, this is $4 \times 128^3 \times 4$ bytes $\approx 33$ MB per view (assuming float32) [S1].
*   **Measured Performance:**
    *   Convolutional 32³: 90Hz [S1].
    *   Convolutional 128³: 22Hz [S1].
    *   Bottleneck 128³: 90Hz [S1].
*   **Strengths:** Real-time rendering speeds achievable with lower resolutions or bottleneck architectures [S1]. Explicit representation allows for efficient ray marching [S1].
*   **Limitations:** Voxel grids are limited to representing details as small as a single voxel [S1]. They are computationally expensive and wasteful for scenes with large empty spaces compared to sparse representations [S1].
*   **When to Use:** Not given in the sources.
*   **When Not to Use:** Not given in the sources.

## Background
Voxel Grid Decoders were introduced in the "Neural Volumes: Learning Dynamic Renderable Volumes from Images" paper [S1]. They were proposed as an alternative to implicit MLP decoders to address the computational bottleneck of evaluating MLPs at every ray-marching step, which restricts real-time application performance [S1].
