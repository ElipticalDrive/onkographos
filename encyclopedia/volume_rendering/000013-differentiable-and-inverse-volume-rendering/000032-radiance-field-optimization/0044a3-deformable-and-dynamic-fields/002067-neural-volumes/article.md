# Neural Volumes

Also called: Deformable Volumes, Neural Volumes: Learning Dynamic Renderable Volumes from Images, Volumetric Reconstruction with Ray Potentials

## Overview
Neural Volumes (NV) is a method for synthesizing novel views of dynamic scenes by optimizing a deep 3D convolutional network to predict a discretized RGB$\alpha$ voxel grid and a 3D warp field [S1, S2]. It solves the problem of rendering semi-transparent, non-rigidly deforming objects (such as smoke, hair, or human faces) from sparse multi-view video inputs without requiring explicit geometry or texture maps [S2]. Unlike implicit radiance field methods that map coordinates to color via MLPs, NV uses an explicit voxel grid for appearance and a learned warp field to model motion, trading memory for speed and enabling real-time inference after training [S1, S2]. It sets itself apart from static volume decoders by supporting dynamic scenes and from other neural rendering methods by keeping the rendering step (ray marching) parameter-free and interpretable [S2].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A sequence of synchronized, calibrated RGB images from $K$ camera viewpoints (typically $K=3$ orthogonal views) [S2].
*   **Outputs:** A stream of rendered RGB$\alpha$ images for novel viewpoints [S2].

**Data Structures:**
1.  **Latent Code ($z$):** A vector in $\mathbb{R}^{256}$ representing the state of the scene at a given time instant [S2].
2.  **Conditioning Variable ($c$):** An $L$-dimensional vector concatenated with $z$ to allow conditional decoding (e.g., expression, view-dependent appearance) [S2].
3.  **Voxel Grid ($V$):** A discrete 3D grid of resolution $D \times D \times D$ (typically $128^3$) storing RGBA values [S1, S2]. The function is defined as $\mathbf{V} : \mathbb{R}^3 \rightarrow \mathbb{R}^4$, where $\mathbf{V}(\mathbf{x}) = (\mathbf{V}_{\text{rgb}}(\mathbf{x}), \mathbf{V}_{\alpha}(\mathbf{x}))$ [S2].
    *   $\mathbf{V}_{\text{rgb}}(\mathbf{x}) \in \mathbb{R}^3$: Color at $\mathbf{x}$.
    *   $\mathbf{V}_{\alpha}(\mathbf{x}) \in \mathbb{R}$: Differential opacity in $[0, \infty]$, where 0 is fully transparent [S2].
4.  **Warp Grid ($W$):** A discrete 3D grid of resolution $32^3$ storing inverse warp vectors [S1]. The warp field encodes the location within the template voxel grid from which color and opacity are sampled [S2].

**Network Architecture:**
1.  **Encoder:** A CNN with dedicated branches for each of the $K$ input camera views. The outputs are concatenated and encoded down to the parameters of a diagonal 256-dimensional Gaussian ($\mu$ and $\sigma$) [S2].
2.  **Latent Sampling:** An instance $z$ is generated by sampling from the Gaussian using the reparameterization trick: $z = \mu + \sigma \odot \epsilon$, where $\epsilon \sim \mathcal{N}(0, I)$ [S2].
3.  **Decoder:** A deep 3D convolutional network (or linear basis decoder) that takes $[z; c]$ as input and outputs the Voxel Grid $V$ and Warp Grid $W$ [S1][S4, unofficial].
    *   *Convolutional Decoder:* Uses 3D transposed convolutions to upsample from a $1 \times 1 \times 1$ feature cube to the full resolution grid (e.g., $128^3$) [S4, unofficial].
    *   *Activation:* Softplus is used to ensure RGBA values are non-negative [S4, unofficial].

**Rendering (Differentiable Ray Marching):**
For a camera ray $\mathbf{r}$, the system performs front-to-back alpha compositing through the warped voxel grid [S4, unofficial].
1.  Sample points $r_j$ along the ray.
2.  Apply the inverse warp to find the source location in the template grid: $\mathbf{x}_j = W^{-1}(r_j)$ [S4, unofficial].
3.  Sample color and opacity from the template volume: $C_j = \mathbf{V}_{\text{rgb}}(\mathbf{x}_j)$, $\alpha_j = \mathbf{V}_{\alpha}(\mathbf{x}_j)$ [S4, unofficial].
4.  Accumulate color and opacity:
    $$
    I_{\text{rgb}}(p) = \sum_{j} C_j \cdot \alpha_j \cdot \prod_{k<j} (1 - \alpha_k)
    $$
    $$
    I_{\alpha}(p) = 1 - \prod_{j} (1 - \alpha_j)
    $$
    [S4, unofficial]

**Warp Field Mixing (Affine Warp Spatial Mixing):**
To model complex motion, the inverse warp $W^{-1}(x)$ is computed as a weighted average of $N$ affine transformations $A_i^{-1}$ [S4, unofficial]:
$$
W^{-1}(x) = \sum_{i=1}^{N} w_i(A_i^{-1}(x)) \times A_i^{-1}(x)
$$
where $A_i^{-1}(x)$ includes rotation $R_i$, scale $s_i$, and translation $t_i$, and weights $w_i$ are sampled in "warp space" rather than world space [S4, unofficial].

**Training:**
The system is trained end-to-end by minimizing a loss function that includes pixel reconstruction error and regularization terms [S4, unofficial]:
$$
\mathcal{L}(\theta) = \|I_{\text{rgb}} - I^*_{\text{rgb}}\|_2^2 + \beta \cdot D_{KL}(z \| \mathcal{N}(0,1)) + \lambda_{tv} J_{tv}(\mathbf{V}_{\alpha}) + \lambda_B J_B(I_{\alpha})
$$
*   $D_{KL}$: KL-divergence regularization for the latent code [S2].
*   $J_{tv}$: Total variation regularization on log-opacity to encourage sharp boundaries [S4, unofficial].
*   $J_B$: Beta distribution prior on exit opacity to encourage binary transparency (fully transparent or opaque) [S4, unofficial].

import torch
import torch.nn as nn
import torch.nn.functional as F

class NeuralVolumes:
    def __init__(self, voxel_res=128, warp_res=32, latent_dim=256, num_cameras=3):
        self.encoder = Encoder(num_cameras=num_cameras, latent_dim=latent_dim)
        self.decoder = Decoder(voxel_res=voxel_res, warp_res=warp_res, latent_dim=latent_dim)
        self.voxel_res = voxel_res
        self.warp_res = warp_res

    def encode(self, images):
        """
        images: Tensor of shape (B, K, H, W, 3)
        Returns: mu, sigma (Tensors of shape (B, latent_dim))
        """
        # Process each camera view through dedicated CNN branches
        features = [self.encoder.branch(i)(img) for i, img in enumerate(images.unbind(dim=1))]
        # Concatenate features from all K cameras
        combined = torch.cat(features, dim=-1)
        # Encode down to latent space
        mu, log_var = self.encoder.head(combined)
        sigma = torch.exp(0.5 * log_var)
        return mu, sigma

    def sample_latent(self, mu, sigma):
        """Reparameterization trick"""
        eps = torch.randn_like(sigma)
        z = mu + sigma * eps
        return z

    def decode(self, z, c=None):
        """
        z: Tensor of shape (B, latent_dim)
        c: Optional conditioning tensor
        Returns: voxel_grid (RGBA), warp_grid (Inverse Warp)
        """
        if c is not None:
            z = torch.cat([z, c], dim=-1)
        # Decoder outputs explicit voxel grid and warp grid
        voxel_grid = self.decoder(z) # Shape: (B, D, D, D, 4)
        warp_grid = self.decoder_warp(z) # Shape: (B, D_w, D_w, D_w, 3)
        return voxel_grid, warp_grid

    def render(self, voxel_grid, warp_grid, ray_origins, ray_directions, near, far):
        """
        Differentiable ray marching through warped voxel grid.
        voxel_grid: (B, D, D, D, 4)
        warp_grid: (B, D_w, D_w, D_w, 3)
        ray_origins: (B, N_rays, 3)
        ray_directions: (B, N_rays, 3)
        """
        # 1. Sample points along rays
        t_vals = torch.linspace(near, far, 128).to(voxel_grid.device)
        points_3d = ray_origins.unsqueeze(-2) + ray_directions.unsqueeze(-2) * t_vals.unsqueeze(-1)
        
        # 2. Apply inverse warp to find source locations in template grid
        # warp_grid stores W^-1(x). We need to sample W^-1 at points_3d.
        # Note: warp_grid is defined on a coarse grid (32^3), so interpolation is needed.
        warped_points = self.sample_warp(warp_grid, points_3d)
        
        # 3. Sample RGBA from voxel grid at warped locations
        rgba = self.sample_voxel(voxel_grid, warped_points)
        rgb = rgba[..., :3]
        alpha = rgba[..., 3]
        
        # 4. Front-to-back compositing
        # T_i = exp(-sum(sigma_j * delta_j)) approximated by product of (1-alpha)
        # Using discrete alpha blending as per formula in [S4, unofficial]
        weights = alpha * torch.cumprod(torch.ones_like(alpha) - alpha, dim=-2)
        # Handle the first term correctly (cumprod starts with 1, so weights[0] = alpha[0])
        # Correct accumulation:
        transmittance = torch.cumprod(1 - alpha, dim=-2)
        transmittance = torch.cat([torch.ones_like(transmittance[:, :, :1]), transmittance[:, :, :-1]], dim=-2)
        weights = alpha * transmittance
        color = torch.sum(weights.unsqueeze(-1) * rgb, dim=-2)
        opacity = 1 - transmittance[:, :, -1]
        
        return color, opacity

    def train_step(self, images, target_images, ray_params):
        mu, sigma = self.encode(images)
        z = self.sample_latent(mu, sigma)
        voxel_grid, warp_grid = self.decode(z)
        pred_color, pred_alpha = self.render(voxel_grid, warp_grid, **ray_params)

## Subtopics

### [Voxel Grid Decoders](2219-voxel-grid-decoders.md)
Voxel Grid Decoders model the volume function $V(\mathbf{x}; \mathbf{z})$ as a discrete 3D grid of voxels, producing an explicit 3D voxel grid as the output tensor of a neural network. This approach avoids the prohibitive computational requirements of evaluating deep MLPs at every ray-marching step, enabling real-time rendering speeds. It sets itself apart from implicit MLP decoders by trading memory for speed, storing values in a structured grid rather than computing them on the fly.

### [RenderNet Architecture](6691-rendernet-architecture.md)
RenderNet is a deep convolutional network designed for the differentiable rendering of voxelized 3D shapes. It solves the problem of synthesizing novel views by mapping a 3D input volume directly to a 2D image. What sets it apart from its siblings, such as [Voxel Grid Decoders](2219-voxel-grid-decoders.md) and [GRU Volume Fusion](7543-gru-volume-fusion.md), is its explicit architectural separation of 3D feature extraction and 2D image decoding, connected by a projection unit that aggregates features along the viewing ray using an MLP. Unlike methods that extract features in object space independent of camera parameters, RenderNet performs view-space resampling at the beginning of the pipeline, making the features inherently dependent on the camera pose.

### [GRU Volume Fusion](7543-gru-volume-fusion.md)
GRU Volume Fusion incrementally fuses per-frame local radiance fields into a global sparse radiance field using a recurrent neural module. It distinguishes itself from static volume decoders by adaptively updating only voxels covered by incoming local reconstructions, enabling real-time incremental scene reconstruction.

## Operating characteristics
*   **Time Complexity:** Training is computationally expensive, requiring at least 12 hours per scene [S1]. Inference is real-time once the latent codes are generated [S2].
*   **Memory Complexity:** Requires storing an explicit $128^3$ voxel grid and a $32^3$ warp grid [S1]. This limits scalability to fine details at high resolutions compared to implicit methods [S1, S3].
*   **Performance:** Captures reasonably detailed volumetric geometry and appearance but can produce blurry results due to the fixed low resolution of the voxel grid [S3].
*   **Strengths:** Handles semi-transparent materials (smoke, hair) and dynamic scenes; interpretable volume; real-time inference [S2].
*   **Limitations:** Limited by voxel resolution; requires bounded volume with distinct background; training time is long [S1, S2].
*   **When to use:** Novel view synthesis of dynamic, semi-transparent objects within a bounded volume [S1].
*   **When not to use:** Scenes with fine high-frequency details requiring higher resolution than the grid allows, or unbounded scenes [S1, S3].

## Background
Neural Volumes was introduced by Kato et al. in 2019 [S2]. It builds on the concept of ray potentials and volume rendering, extending them to dynamic scenes by introducing a warp field [S2]. It is a baseline method in the field of neural volumetric video representation [S3].
