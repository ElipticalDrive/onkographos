# HexPlane


## Overview
HexPlane is an explicit representation for dynamic 3D scenes that decomposes a 4D spacetime grid into six feature planes spanning each pair of coordinate axes (e.g., XY, ZT) [S1]. It computes features for points in spacetime by projecting the point onto each feature plane, aggregating the six resulting feature vectors, and passing the fused vector to a tiny MLP to predict color [S1]. This method solves the problem of efficient novel view synthesis for dynamic scenes by avoiding the high computational cost of implicit MLP-based representations and the memory inefficiency of dense 4D grids [S1]. It sets itself apart from implicit methods (like T-NeRF) by using an explicit factorized structure, achieving comparable or better synthesis quality with over 100× acceleration [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of posed and timestamped images of a dynamic scene.
*   **Outputs:** A differentiable function that maps a 4D spacetime point $(x, y, z, t)$ and a viewing direction $\mathbf{d}$ to an RGB color $\mathbf{c}$ and an opacity $\alpha$.

**Data Structures:**
The core data structure is the HexPlane, which consists of six learned feature planes. These planes are organized into three pairs, where each pair spans a specific combination of spatial and spatio-temporal axes:
1.  Pair 1: $M^{XY}$ (spatial) and $M^{ZT}$ (spatio-temporal).
2.  Pair 2: $M^{XZ}$ (spatial) and $M^{YT}$ (spatio-temporal).
3.  Pair 3: $M^{YZ}$ (spatial) and $M^{XT}$ (spatio-temporal).

Each plane $M^{AB}$ is a 2D tensor of shape $A \times B$. Additionally, there are three vectors $\mathbf{v}^1, \mathbf{v}^2, \mathbf{v}^3$ of shape $F$ (feature dimension), and a fusion matrix $\mathbf{V}^{RF}$ of shape $R \times F$ (where $R = R_1 + R_2 + R_3$).
*   **Opacity HexPlane:** A separate set of planes (often with lower rank $R$) used specifically to query opacity.
*   **Appearance HexPlane:** A separate set of planes used to query appearance features for points with high opacity.
*   **Emptiness Voxel:** A tiny 3D voxel grid indicating empty regions, computed by taking the maximum opacity across time steps for each spatial location.

**Numbered Steps:**

1.  **Coordinate Normalization:** Map input coordinates $(x, y, z, t)$ to the normalized domain of the grid. For bounded scenes, this is typically Normalized Device Coordinates (NDC) [S1]. For unbounded scenes, re-parameterize $(x, y, z)$ into spherical coordinates $(\theta, \phi, r)$ where $r = 1/\sqrt{x^2+y^2+z^2}$, and use axes $(\theta, \phi, r, t)$ [S1].
2.  **Query Opacity:** To determine if a point is occupied, query the Opacity HexPlane at $(x, y, z, t)$.
    *   Extract feature vectors from the six opacity planes via bilinear interpolation.
    *   Perform element-wise multiplication for paired planes: $\mathbf{p}_1 = \text{interp}(M^{XY}) \odot \text{interp}(M^{ZT})$, $\mathbf{p}_2 = \text{interp}(M^{XZ}) \odot \text{interp}(M^{YT})$, $\mathbf{p}_3 = \text{interp}(M^{YZ}) \odot \text{interp}(M^{XT})$.
    *   Concatenate $\mathbf{p}_1, \mathbf{p}_2, \mathbf{p}_3$ and multiply by the opacity fusion matrix to get a scalar opacity value.
3.  **Skip Empty Regions:** If the opacity is below a threshold (or if the point falls within the "Emptiness Voxel" region), skip rendering for this point [S1].
4.  **Query Appearance Features:** If the point is occupied, query the Appearance HexPlane at $(x, y, z, t)$ using the same interpolation and fusion process as Step 2 to obtain an $F$-dimensional feature vector $\mathbf{f}$ [S1].
5.  **Color Regression:** Pass the feature vector $\mathbf{f}$, the point coordinates $(x, y, z, t)$, and the viewing direction $\mathbf{d}$ into a tiny Multi-Layer Perceptron (MLP) to regress the RGB color $\mathbf{c}$ [S1].
6.  **Volumetric Rendering:** Render the image using standard differentiable volumetric rendering along rays, summing the contributions of sampled points weighted by their opacity and transmittance [S1].
7.  **Optimization:** Update the HexPlane planes and the MLP weights by minimizing the photometric loss between rendered images and ground-truth images, plus regularization terms [S1].

**Formulas:**
The HexPlane representation $\mathbf{D}$ for a 4D feature volume is defined as the sum of three terms:
$$
\mathbf{D} = \sum_{r=1}^{R_1} \mathbf{M}_r^{XY} \circ \mathbf{M}_r^{ZT} \circ \mathbf{v}_r^1 + \sum_{r=1}^{R_2} \mathbf{M}_r^{XZ} \circ \mathbf{M}_r^{YT} \circ \mathbf{v}_r^2 + \sum_{r=1}^{R_3} \mathbf{M}_r^{YZ} \circ \mathbf{M}_r^{XT} \circ \mathbf{v}_r^3
$$
where $\circ$ denotes the outer product, $\mathbf{M}_r^{AB} \in \mathbb{R}^{AB}$ are the learned feature planes, and $\mathbf{v}_r^i \in \mathbb{R}^F$ are the feature vectors [S1].

The query function $D(x, y, z, t)$ mapping a point to an $F$-dimensional feature vector is:
$$
D(x, y, z, t) = (\mathbf{P}_{xy\bullet}^{XYR1} \odot \mathbf{P}_{xt\bullet}^{ZTR1}) \mathbf{V}^{R1F} + (\mathbf{P}_{xz\bullet}^{XZR2} \odot \mathbf{P}_{yt\bullet}^{YTR2}) \mathbf{V}^{R2F} + (\mathbf{P}_{yz\bullet}^{YZR3} \odot \mathbf{P}_{xt\bullet}^{XTR3}) \mathbf{V}^{R3F}
$$
where $\odot$ is element-wise product, $\mathbf{P}$ tensors stack the planes, $\mathbf{V}$ tensors stack the vectors, and subscripts denote bilinear interpolation [S1].

The optimization objective is:
$$
\mathcal{L} = \frac{1}{|\mathcal{R}|} \sum_{\mathbf{r} \in \mathcal{R}} \|C(\mathbf{r}) - \hat{C}(\mathbf{r})\|_2^2 + \lambda_{\text{reg}} \mathcal{L}_{\text{reg}}
$$
where $C(\mathbf{r})$ is the rendered color, $\hat{C}(\mathbf{r})$ is the ground truth, and $\mathcal{L}_{\text{reg}}$ includes Total Variational (TV) loss on planes and depth smooth loss [S1].

**Parameters:**
*   **Spatial Resolution ($N$):** Grid size for X, Y, Z axes. Typical values: 128 to 512 [S1].
*   **Temporal Resolution ($T$):** Grid size for T axis. Typical values: 32 to 300 [S1].
*   **Basis Number ($R$):** Number of low-rank components. Typical values: $R_1, R_2, R_3$ range from 8 to 96. For Plenoptic Video, appearance $R_1=48, R_2=24, R_3=24$; opacity $R_1=24, R_2=12, R_3=12$ [S1].
*   **Feature Size ($F$):** Dimensionality of the feature vector. Typically 3 for RGB, or higher for SH coefficients [S1].
*   **Learning Rate:** 0.02 for feature planes, 0.001 for VRF and MLP [S1].

import numpy as np

def bilinear_interpolate(grid, coords):
    """
    Performs bilinear interpolation on a 2D grid at given continuous coordinates.
    grid: np.array of shape (H, W)
    coords: np.array of shape (2,) with values in [0, 1]
    Returns: np.array of shape (R,) where R is the depth of the grid if it were 3D, 
             or scalar if 2D. Here we assume grid is (H, W, R) for feature planes.
    """
    # Implementation of bilinear interpolation
    # 1. Floor and ceil coordinates
    x0 = np.floor(coords[0]).astype(int)
    y0 = np.floor(coords[1]).astype(int)
    x1 = x0 + 1
    y1 = y0 + 1
    
    # Clamp to grid bounds
    x0 = np.clip(x0, 0, grid.shape[0] - 1)
    y0 = np.clip(y0, 0, grid.shape[1] - 1)
    x1 = np.clip(x1, 0, grid.shape[0] - 1)
    y1 = np.clip(y1, 0, grid.shape[1] - 1)
    
    # Interpolation weights
    dx = coords[0] - x0
    dy = coords[1] - y0
    
    # Get values at corners
    val_00 = grid[x0, y0, :]
    val_10 = grid[x1, y0, :]
    val_01 = grid[x0, y1, :]
    val_11 = grid[x1, y1, :]
    
    # Interpolate
    top = val_00 * (1 - dx) + val_10 * dx
    bottom = val_01 * (1 - dx) + val_11 * dx
    result = top * (1 - dy) + bottom * dy
    
    return result

**Edge Cases and Pitfalls:**
*   **Out-of-Boundary Points:** HexPlane is limited to bounded scenes because grid sampling fails for out-of-boundary points. Using NDC requires bounded x, y values and can lead to artifacts at extreme views [S1]. For unbounded scenes, spherical coordinate re-parameterization is required [S1].
*   **Fast Motion/Sparse Observations:** HexPlane generates degraded results when objects move too fast or there are too few observations to synthesize details, as the basis-sharing mechanism is less effective than deformation fields for extremely sparse observations [S1].
*   **Artifacts:** Explicit representations are prone to artifacts and color jittering, requiring strong regularizations like TV loss [S1].

## Subtopics

### HexPlane-SH
A pure explicit model without MLPs that stores spherical harmonics (SH) as appearance features and directly regresses RGB from it. It is faster than the MLP-based HexPlane but with slightly reduced quality [S1].

### Spherical Coordinate HexPlane
A variant that re-parameterizes coordinates into spherical coordinates $(\theta, \phi, r, t)$ to handle unbounded scenes, avoiding the artifacts associated with NDC at extreme views [S1].

## Operating characteristics
*   **Time Complexity:** Querying a HexPlane requires six bilinear interpolations and one vector-matrix product per term, making it highly efficient compared to MLP evaluations [S1].
*   **Memory Complexity:** Memory usage is reduced from $O(N^3TF)$ to $O(N^2R + NTR + RF)$, where $N$ is spatial resolution, $T$ is temporal resolution, $R$ is the basis number, and $F$ is feature dimension [S1].
*   **Measured Performance:** On the Plenoptic Video dataset, HexPlane achieves 29.470 PSNR in 12 GPU hours (112x speedup over DyNeRF) with 650k iterations. With 100k iterations (HexPlane†), it achieves 29.263 PSNR in 2 GPU hours (672x speedup) [S1]. On D-NeRF dataset, it achieves 31.04 PSNR in 11 minutes [S1].
*   **Model Size:** The entire model occupies approximately 200MB [S1].
*   **Strengths:** Extremely fast training and rendering compared to implicit methods; low memory footprint; no need for deformation fields.
*   **Limitations:** Limited to bounded scenes (unless spherical coordinates are used); sensitive to sparse observations and fast motion; prone to color jittering and artifacts requiring strong regularization [S1].

## Background
HexPlane was introduced by Ang Cao and Justin Johnson from the University of Michigan, Ann Arbor, in 2023 [S1]. It builds on the principles of tensor decomposition (specifically CP decomposition) used in methods like TensoRF [S1]. The method was developed to address the limitations of implicit representations (slow training) and dense 4D grids (high memory usage) in dynamic novel view synthesis [S1]. It is closely related to K*-Planes, which also uses six feature planes [S1].
