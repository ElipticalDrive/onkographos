# GaussianSet Data Structure

Also called: 3D Gaussian Representation, Gaussian Set

## Overview
The `GaussianSet` is a container class representing a collection of 3D Gaussian primitives, storing their parameters (means, orientations, scales, opacities, and spherical harmonics coefficients) and providing methods to compute their world-space covariance matrices [S1, unofficial]. It solves the problem of organizing learnable parameters into a structured format suitable for differentiable volume rendering pipelines [S1, unofficial]. It differs from its parent [3D Gaussian Splatting](1795-3d-gaussian-splatting.md) by focusing on the data container logic rather than the rendering algorithm, and from [GaussianList Data Structure and Initialization](2214-gaussianlist-data-structure-and-initialization.md) by not explicitly managing contiguous memory layout or initialization routines [S1, unofficial].

## How it works
The `GaussianSet` stores raw learnable parameters and computes derived geometric properties on demand. It does not store the covariance matrix directly in its primary storage but computes it from rotation and scale parameters [S1, unofficial].

### Inputs and Outputs
- **Inputs**: Raw learnable parameters for $N$ Gaussians.
- **Outputs**: World-space covariance matrices for each Gaussian.

### Data Structures
The `GaussianSet` class contains the following fields, typically stored as PyTorch tensors or similar GPU-compatible structures [S1, unofficial]:

| Field | Type | Shape | Description |
| :--- | :--- | :--- | :--- |
| `means` | Float32 Tensor | $(N, 3)$ | 3D positions of the Gaussian centers. |
| `quats` | Float32 Tensor | $(N, 4)$ | Unit quaternions representing rotation. |
| `scales` | Float32 Tensor | $(N, 3)$ | Log-space scales (exponentiated at load/render). |
| `opacities` | Float32 Tensor | $(N,)$ | Log-space opacities (sigmoided at load/render). |
| `sh_coefficients` | Float32 Tensor | $(N, S, 3)$ | Spherical Harmonics coefficients for color. |
| `covariances` | Float32 Tensor | $(N, 3, 3)$ | Computed world-space covariance matrices. |

*Note: The `covariances` field is often computed on-the-fly or cached, but the primary stored parameters are `means`, `quats`, `scales`, `opacities`, and `sh_coefficients` [S1, unofficial].*

### Numbered Steps

1. **Load/Initialize Parameters**:
   - Load raw parameters from a checkpoint or file.
   - Normalize quaternions: $q_{norm} = \frac{q}{\|q\|_2}$.
   - Exponentiate scales: $s_{actual} = \exp(s_{raw})$.
   - Sigmoid opacities: $\alpha_{actual} = \sigma(\alpha_{raw})$.
   - Concatenate SH coefficients if stored in separate levels.

2. **Compute Covariance Matrix**:
   - Construct the local diagonal covariance matrix $S$ from the exponentiated scales:
     $$ S = \text{diag}(s_x^2, s_y^2, s_z^2) $$
     where $s_x, s_y, s_z$ are the components of the scale vector [S1, unofficial].
   - Convert the normalized quaternion $q$ to a rotation matrix $R$ [S1, unofficial].
   - Compute the world-space covariance matrix:
     $$ Cov = R S R^T $$
     where $R$ is the rotation matrix derived from the quaternion and $S$ is the diagonal local covariance matrix [S1, unofficial].

### Formulas
- **Covariance in World Coordinates**:
  $$ Cov = R S R^T $$
  where:
  - $R$ is the $3 \times 3$ rotation matrix derived from the quaternion.
  - $S$ is the $3 \times 3$ diagonal matrix of variances in local coordinates.
  - $Cov$ is the $3 \times 3$ symmetric positive-definite covariance matrix in world coordinates [S1, unofficial].

- **Local Covariance Matrix**:
  $$ S = \begin{bmatrix} s_x^2 & 0 & 0 \\ 0 & s_y^2 & 0 \\ 0 & 0 & s_z^2 \end{bmatrix} $$
  where $s_x, s_y, s_z$ are the scale parameters [S1, unofficial].

### Parameters
- **N**: Number of Gaussians. Not given in the sources.
- **S**: Degree of spherical harmonics. Not given in the sources.
- **radius_px**: Base radius in pixels for rendering (used in simplified circle rendering, not core to `GaussianSet` structure). Not given in the sources.

### Edge Cases and Pitfalls
- **Quaternion Normalization**: Quaternions must be normalized to ensure valid rotation matrices. Failure to normalize leads to incorrect covariance shapes [S1, unofficial].
- **Scale Exponentiation**: Scales are stored in log-space to ensure positivity. Exponentiation is required before computing variances [S1, unofficial].
- **Opacity Sigmoid**: Opacities are stored in log-space. Sigmoid is required to map to $[0, 1]$ [S1, unofficial].
- **Covariance Symmetry**: The resulting covariance matrix $Cov$ must be symmetric. Numerical errors in quaternion-to-matrix conversion can break symmetry; symmetrization ($Cov = \frac{1}{2}(Cov + Cov^T)$) may be needed [G].

### Pseudocode

```python
import torch
import torch.nn.functional as F

def quaternion_to_rotation_matrix(quat):
    """Convert a batch of quaternions to rotation matrices."""
    # Normalize quaternions
    quat = F.normalize(quat, p=2, dim=-1)
    w, x, y, z = quat[:, 0], quat[:, 1], quat[:, 2], quat[:, 3]
    
    # Compute rotation matrix components
    R = torch.zeros(quat.shape[0], 3, 3, device=quat.device)
    R[:, 0, 0] = 1 - 2 * (y**2 + z**2)
    R[:, 0, 1] = 2 * (x*y - w*z)
    R[:, 0, 2] = 2 * (x*z + w*y)
    R[:, 1, 0] = 2 * (x*y + w*z)
    R[:, 1, 1] = 1 - 2 * (x**2 + z**2)
    R[:, 1, 2] = 2 * (y*z - w*x)
    R[:, 2, 0] = 2 * (x*z - w*y)
    R[:, 2, 1] = 2 * (y*z + w*x)
    R[:, 2, 2] = 1 - 2 * (x**2 + y**2)
    return R

def compute_covariances(means, quats, scales):
    """Compute world-space covariance matrices from Gaussian parameters."""
    # Normalize quaternions
    quats = F.normalize(quats, p=2, dim=-1)
    
    # Exponentiate scales
    scales = torch.exp(scales)
    
    # Construct local covariance matrix S (diagonal)
    # S = diag(sx^2, sy^2, sz^2)
    S = torch.zeros_like(scales).unsqueeze(-1).expand(-1, -1, 3)
    S[:, 0, 0] = scales[:, 0]**2
    S[:, 1, 1] = scales[:, 1]**2
    S[:, 2, 2] = scales[:, 2]**2
    
    # Convert quaternions to rotation matrices
    R = quaternion_to_rotation_matrix(quats)
    
    # Compute world-space covariance: Cov = R * S * R^T
    # R is (N, 3, 3), S is (N, 3, 3)
    Cov = torch.bmm(torch.bmm(R, S), R.transpose(1, 2))
    
    return Cov

class GaussianSet:
    def __init__(self, means, quats, scales, opacities, sh_coefficients):
        self.means = means
        self.quats = quats
        self.scales = scales
        self.opacities = opacities
        self.sh_coefficients = sh_coefficients
        self.covariances = None

    def compute_covariances(self):
        """Compute and store covariance matrices."""
        self.covariances = compute_covariances(self.means, self.quats, self.scales)
        return self.covariances

    def load_from_checkpoint(self, ckpt):
        """Load parameters from a checkpoint, applying necessary transformations."""
        self.means = ckpt["means"]
        
        # Normalize quaternions
        self.quats = F.normalize(ckpt["quats"], p=2, dim=-1)
        
        # Exponentiate scales
        self.scales = torch.exp(ckpt["scales"])
        
        # Sigmoid opacities
        self.opacities = torch.sigmoid(ckpt["opacities"])
        
        # Concatenate SH coefficients
        self.sh_coefficients = torch.cat([ckpt["sh0"], ckpt["shN"]], dim=-2)
        
        # Compute covariances
        self.compute_covariances()
```

## Subtopics

### [ECoNGS Optimization and Coding](2087-econgs-optimization-and-coding.md)
ECoNGS (Efficient Compressive Neural Gaussian Splats) is a scene representation method that transforms time-consuming volume rendering into an efficient process by optimizing neural editable Gaussians and compressing their attributes via neural entropy coding. It solves the problem of large storage and computational costs in volume visualization by extracting multi-view images and point clouds, grouping geometrically similar scenes for joint learning, and compressing anchor attributes to exploit inter-scene redundancy. Unlike standard 3D Gaussian Splatting which stores all attributes explicitly, ECoNGS uses a two-stage optimization process involving anchor attribute optimization and joint context model training, achieving compression with minimal distortion.

### [GaussianList Data Structure and Initialization](2214-gaussianlist-data-structure-and-initialization.md)
The `GaussianList` is a column-major data structure that stores a batch of 3D Gaussian primitives for efficient differentiable volume rendering. It solves the problem of organizing learnable parameters (means, covariances, opacities, and spherical harmonics) into a format suitable for batched linear algebra operations during optimization. It differs from its parent `GaussianSet` by explicitly managing the contiguous memory layout and providing the initialization routines that convert raw geometric data into valid, differentiable parameters ready for gradient descent.

### [Gaussian Property Loading](2221-gaussian-property-loading.md)
Gaussian Property Loading parses 3D Gaussian parameters (position, scale, rotation, opacity, and spherical harmonics) from a PLY file into a structured data container suitable for differentiable rendering. It solves the problem of converting raw file data into a format suitable for GPU consumption by applying necessary inverse transformations (e.g., exponentiation for scale, sigmoid for opacity) and handling coordinate system inconsistencies. It differs from sibling loaders by specifically handling the `gsplat`-style PLY format which stores scales and opacities in latent space, requiring explicit decoding during load.

### [3D Covariance Computation](2231-3d-covariance-computation.md)
Computes the 3D covariance matrix of a Gaussian from its scale and rotation parameters. It solves the problem of representing the spatial extent and orientation of a 3D Gaussian in world coordinates by transforming local axis-aligned variances into a full symmetric positive-definite matrix. What sets it apart from direct covariance optimization is that it derives the covariance from unconstrained rotation (quaternion) and scale parameters, ensuring the resulting matrix is always valid without requiring projection steps.

### [3D Gaussian Data Layout](2242-3d-gaussian-data-layout.md)
The 3D Gaussian Data Layout defines the memory organization and field definitions for a single 3D Gaussian primitive within differentiable volume rendering pipelines. It serves as the fundamental unit of storage for position, scale, orientation, opacity, and color (spherical harmonics) data, enabling efficient GPU access and optimization. It differs from the higher-level [GaussianSet Data Structure](2074-gaussianset-data-structure.md) by focusing on the raw parameter representation rather than the container logic, and from [Gaussian Data Packing](3257-gaussian-data-packing.md) by retaining floating-point precision for optimization rather than compacting into fixed-size integer buffers for rendering.

### [3D Gaussian Splatting (3DGS) Preliminaries](2257-3d-gaussian-splatting-3dgs-preliminaries.md)
3D Gaussian Splatting (3DGS) is a differentiable, point-based scene representation that replaces the implicit multi-layer perceptron (MLP) and ray-marched volume integration of NeRF with an explicit collection of 3D anisotropic Gaussians. It enables real-time synthesis of high-fidelity novel views via a GPU-friendly tile-based rasterizer that depth-sorts and alpha-composites 2D projections of these Gaussians. Unlike NeRF, which infers density and color at arbitrary points, 3DGS optimizes the parameters of a fixed set of Gaussian primitives (position, covariance, opacity, and spherical harmonic coefficients) to minimize photometric loss, using adaptive density control to adjust the number of primitives during training.

### [N-DGS Bounded Cholesky Parameterization](2811-n-dgs-bounded-cholesky-parameterization.md)
N-DGS (N-Dimensional Gaussian Splatting) is a parameterization method for the joint covariance matrix of 3D Gaussians in differentiable volume rendering. It solves the problem of optimizing the cross-covariance between spatial and query dimensions while maintaining positive-definiteness and numerical stability. Unlike sibling methods that may use direct regression or unbounded factorizations, N-DGS uses a bounded Cholesky factorization where coefficients are scaled by query diagonal scales, ensuring that the resulting cross-covariance and spatial extent remain within controlled bounds. It builds on [GaussianSet Data Structure](2074-gaussianset-data-structure.md) by defining how the covariance matrix components are stored and optimized.

## Operating characteristics
- **Time Complexity**: Computing covariance matrices is $O(N)$ where $N$ is the number of Gaussians, involving matrix multiplications of fixed size ($3 \times 3$).
- **Memory Complexity**: $O(N \cdot (3 + 4 + 3 + 1 + S \cdot 3 + 9))$ for storing means, quats, scales, opacities, SH coefficients, and covariances. Not given in the sources.
- **Measured Performance**: Not given in the sources.
- **Scaling**: Scales linearly with the number of Gaussians.
- **Strengths**: Explicit representation allows for efficient GPU-based rendering. Covariance computation is differentiable and efficient.
- **Limitations**: Requires storing all parameters explicitly, which can be memory-intensive for large scenes. Not given in the sources.
- **When to Use**: When differentiable optimization of Gaussian parameters is required.
- **When Not to Use**: When memory is extremely constrained and compression is needed (use [ECoNGS Optimization and Coding](2087-econgs-optimization-and-coding.md)).

## Background
The `GaussianSet` data structure is part of the 3D Gaussian Splatting (3DGS) pipeline, which was introduced by Kerbl et al. in 2023 [S3, unofficial]. It serves as the core data container for the learnable parameters of the Gaussian primitives. The structure has been adapted in various implementations, such as `gsplat` and `splaty`, to support efficient differentiable rendering [S1, unofficial].
