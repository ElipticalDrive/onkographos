# Visibility-Based Photometric Loss

Also called: Visibility Masking for Photometric Loss

## Overview
Visibility-Based Photometric Loss restricts the photometric error computation to pixels that are geometrically consistent across views, thereby excluding occluded regions and transient objects from the optimization signal. It differs from standard photometric losses by explicitly filtering out pixels where reprojection depth disagrees with rendered depth, preventing the model from fitting to non-static geometry or occlusion boundaries.

## How it works
The method computes a photometric error (typically L1) only on pixels identified as "visible" in both the source and target views. Visibility is determined by comparing the depth of a pixel reprojected from a source view into the target view against the directly rendered depth of that target view.

### Inputs and Outputs
*   **Inputs:**
    *   Source view color image $I_s$ and depth map $D_s$.
    *   Target view color image $I_t$ and rendered depth map $D_t$.
    *   Camera poses for source and target views.
    *   Intrinsic camera parameters.
*   **Outputs:**
    *   Scalar loss value $L_{photo}$.

### Data Structures
*   **Visibility Mask ($M_v$):** A 2D tensor of shape $(H, W)$ with values in $\{0, 1\}$ (or continuous weights in variants). $1$ indicates a visible pixel, $0$ indicates occluded or transient.
*   **Reprojected Depth ($D_{reproj}$):** A 2D tensor of shape $(H, W)$ containing the depth of the source view pixel projected into the target view coordinate system.

### Steps
1.  **Reproject Depth:** For each pixel $(u, v)$ in the target view, project the corresponding 3D point from the source view using the source camera intrinsics, the source-to-target transformation, and the target camera intrinsics. Retrieve the depth value $D_{reproj}(u, v)$ from the source depth map $D_s$ at the projected coordinates.
2.  **Retrieve Rendered Depth:** Obtain the directly rendered depth $D_t(u, v)$ for the target view at pixel $(u, v)$.
3.  **Compute Depth Difference:** Calculate the squared difference $\Delta d^2 = (D_{reproj}(u, v) - D_t(u, v))^2$.
4.  **Determine Visibility:** Mark pixel $(u, v)$ as visible if $\Delta d^2 < \tau$, where $\tau$ is a threshold. The sources specify $\tau = 0.001$ [S1].
5.  **Compute Photometric Loss:** Calculate the L1 loss between the source color $I_s$ (warped to target view) and target color $I_t$ only for pixels where the visibility mask is true.

### Formula
The visibility mask $M_v(u, v)$ is defined as:
$$
M_v(u, v) = \begin{cases} 
1 & \text{if } (D_{reproj}(u, v) - D_t(u, v))^2 < \tau \\
0 & \text{otherwise}
\end{cases}
$$
where $\tau = 0.001$ [S1].

The photometric loss $L_{photo}$ is:
$$
L_{photo} = \frac{1}{\sum M_v} \sum_{u,v} M_v(u, v) \cdot |I_s^{warped}(u, v) - I_t(u, v)|
$$
where $|\cdot|$ denotes the L1 norm [S1].

### Parameters
*   **Threshold ($\tau$):** $0.001$ [S1]. This value determines the tolerance for depth inconsistency.

### Edge Cases and Pitfalls
*   **Precision:** Depth values must be in consistent units. Small numerical errors in reprojection can lead to false occlusions if $\tau$ is too small.
*   **Boundaries:** Pixels near object boundaries may have ambiguous depth due to anti-aliasing or discretization, potentially causing flickering visibility masks.
*   **Degenerate Input:** If depth maps are missing or invalid, reprojection fails. The method assumes valid depth inputs.

### Pseudocode
```python
def visibility_based_photometric_loss(I_s, D_s, I_t, D_t, pose_s, pose_t, intrinsics, tau=0.001):
    """
    Compute photometric loss only on visible pixels.
    
    Args:
        I_s: Source view color image (H, W, 3)
        D_s: Source view depth map (H, W)
        I_t: Target view color image (H, W, 3)
        D_t: Target view rendered depth map (H, W)
        pose_s: Source camera pose (4, 4)
        pose_t: Target camera pose (4, 4)
        intrinsics: Camera intrinsics matrix (3, 3)
        tau: Depth difference threshold (float)
        
    Returns:
        L_photo: Scalar photometric loss
    """
    H, W = I_t.shape[:2]
    
    # Create grid of pixel coordinates
    u, v = torch.meshgrid(torch.arange(W), torch.arange(H), indexing='ij')
    
    # Convert pixel coordinates to homogeneous coordinates in target view
    # Assuming intrinsics are known, we can back-project to 3D in target view
    # However, the standard method reprojects FROM source TO target.
    # Step 1: Get 3D points from Source View
    # Back-project source pixels to 3D using D_s
    x_s = (u - intrinsics[0,2]) / intrinsics[0,0]
    y_s = (v - intrinsics[1,2]) / intrinsics[1,1]
    z_s = D_s
    
    # 3D points in source camera frame
    pts_s_cam = torch.stack([x_s * z_s, y_s * z_s, z_s], dim=-1) # (H, W, 3)
    
    # Transform to world frame
    pts_s_world = transform_points(pts_s_cam, pose_s) # (H, W, 3)
    
    # Transform to target camera frame
    pts_t_cam = transform_points(pts_s_world, inverse(pose_t)) # (H, W, 3)
    
    # Project to target image plane
    u_reproj = (pts_t_cam[..., 0] / pts_t_cam[..., 2]) * intrinsics[0,0] + intrinsics[0,2]
    v_reproj = (pts_t_cam[..., 1] / pts_t_cam[..., 2]) * intrinsics[1,1] + intrinsics[1,2]
    
    # Sample depth from source depth map at reprojected coordinates
    # Note: In practice, bilinear interpolation is used for sampling
    D_reproj = sample_depth(D_s, u_reproj, v_reproj) # (H, W)
    
    # Step 3: Compute depth difference
    delta_d_sq = (D_reproj - D_t) ** 2
    
    # Step 4: Determine visibility
    M_v = (delta_d_sq < tau).float() # (H, W)
    
    # Warp source image to target view
    I_s_warped = warp_image(I_s, u_reproj, v_reproj) # (H, W, 3)
    
    # Step 5: Compute L1 loss on visible pixels
    diff = torch.abs(I_s_warped - I_t) # (H, W, 3)
    loss_per_pixel = torch.mean(diff, dim=-1) # (H, W)
    
    # Masked mean
    visible_sum = torch.sum(M_v)
    if visible_sum > 0:
        L_photo = torch.sum(M_v * loss_per_pixel) / visible_sum
    else:
        L_photo = torch.tensor(0.0)
        
    return L_photo
```

## Subtopics

### Transient Object Handling via Visibility Map
This variant uses a learned 2D visibility map $V_M \in \mathbb{R}^{1 \times H \times W}$ generated by a U-Net model to segment transient objects (e.g., moving people) from static geometry [S2]. Unlike the geometric reprojection method, this approach relies on appearance-based segmentation. The loss between the rendered image $I_r$ and reference image $I_{gt}$ is weighted by $V_M$ via Hadamard product ($\odot$) [S2]. To prevent the network from suppressing all pixels to minimize loss, a regularization loss $L_{vm} = L_2(V_M, 1)$ is applied, encouraging the visibility map to remain close to ones [S2]. This method is chosen when transient objects are prevalent and geometric consistency alone is insufficient to exclude them.

## Operating characteristics
*   **Time Complexity:** $O(HW)$ per view pair for reprojection and masking. The U-Net variant adds inference time for the segmentation network.
*   **Memory Complexity:** $O(HW)$ for storing depth maps and visibility masks.
*   **Strengths:** Effectively removes artifacts from occlusions and transient objects. Improves reconstruction quality in dynamic scenes.
*   **Limitations:** Requires accurate depth maps for the geometric variant. The threshold $\tau$ is sensitive to noise. The U-Net variant requires additional training and memory.
*   **When to use:** Multi-view reconstruction with occlusions or dynamic scenes.
*   **When not to use:** Static scenes with no occlusions where simple photometric loss suffices.

## Background
The geometric visibility-based photometric loss was introduced in the context of differentiable volume rendering and signed distance function (SDF) optimization [S1]. It addresses the issue of photometric errors being computed on occluded pixels, which leads to incorrect gradient updates. The transient object handling variant was proposed for 3D Gaussian Splatting in unconstrained image collections, where moving objects cause artifacts in the reconstructed scene [S2].
