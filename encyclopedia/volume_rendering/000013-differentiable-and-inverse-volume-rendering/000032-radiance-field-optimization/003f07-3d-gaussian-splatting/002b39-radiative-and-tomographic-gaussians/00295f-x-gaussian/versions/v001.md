# X-Gaussian

Also called: Radiative Gaussian Splatting for X-Ray, X-Gaussian NVS

## Overview
X-Gaussian is a radiative Gaussian splatting method designed for efficient X-ray novel view synthesis (NVS) and sparse-view CT reconstruction [S1]. It replaces the standard RGB Gaussian point clouds of 3D Gaussian Splatting (3DGS) with a radiative model that models radiation intensity without view-direction dependence, utilizing Differentiable Radiative Rasterization (DRR) [S1]. Unlike its siblings which may handle volumetric density or multi-view RGB, X-Gaussian is specialized for monochromatic X-ray projections, offering superior convergence speed and inference efficiency compared to NeRF-based alternatives like NAF [S1].

## How it works
**Inputs:** X-ray projection images (sinograms or angular views), X-ray scanner parameters (intrinsic and extrinsic matrices).
**Outputs:** A radiative Gaussian point cloud model (set of 3D Gaussians) and rendered X-ray projections.

**Data Structures:**
The core data structure is a set of $N$ 3D Gaussians. Each Gaussian $i$ is defined by:
1.  **Mean position** $\mu_i \in \mathbb{R}^3$: The center of the Gaussian in 3D space.
2.  **Covariance matrix** $\Sigma_i \in \mathbb{R}^{3 \times 3}$: Controls the shape and orientation. It is typically parameterized by a rotation matrix $R_i \in SO(3)$ and a scaling vector $s_i \in \mathbb{R}^3$, such that $\Sigma_i = R_i S_i S_i^T R_i^T$, where $S_i = \text{diag}(s_i)$ [S1].
3.  **Radiative Intensity** $\alpha_i$ (or opacity/attenuation coefficient): A scalar value representing the X-ray attenuation or intensity contribution of the Gaussian. Unlike RGB 3DGS, there are no spherical harmonics coefficients for color, as X-ray data is monochromatic intensity [S1].

**Initialization (ACUI Strategy):**
1.  Obtain the intrinsic matrix $K$ and extrinsic matrix $[R|t]$ from the X-ray scanner parameters [S1].
2.  Define a cuboid bounding box enclosing the scanned object.
3.  Uniformly sample center points $\mu_i$ for $N$ 3D Gaussians within this cuboid [S1].
4.  Initialize covariances $\Sigma_i$ and intensities $\alpha_i$ (details on initial $\alpha$ values are not specified in the sources, assumed to be small or uniform) [G].

**Radiative Gaussian Point Cloud Model:**
The model excludes the influence of view direction when fitting radiation intensity. The radiance $L$ emitted by a Gaussian is treated as a scalar intensity value rather than a directional function [S1].

**Differentiable Radiative Rasterization (DRR):**
The rendering process projects 3D Gaussians onto the 2D image plane. For a camera with projection matrix $P$, the 3D covariance $\Sigma_i$ is transformed to 2D screen space $\Sigma'_i$ using the Jacobian $J$ of the affine approximation of the projection:
$$ \Sigma'_i = J W \Sigma_i W^T J^T $$
where $W$ is the rotation part of the extrinsic matrix [S1]. The 2D Gaussian is then rendered using alpha compositing. The opacity $\alpha$ of each Gaussian contributes to the final pixel intensity $C$ via:
$$ C = \sum_{i \in \mathcal{O}} T_i \alpha_i $$
where $\mathcal{O}$ is the set of sorted Gaussians, $T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)$ is the accumulated transmittance, and $\alpha_i$ is the opacity derived from the radiative intensity and the Gaussian's spatial extent at the pixel [S1]. The CUDA kernel implements this compositing efficiently [S1].

**Optimization:**
The parameters ($\mu_i, \Sigma_i, \alpha_i$) are optimized by minimizing the difference between rendered projections and ground-truth X-ray projections. The loss function is typically Mean Squared Error (MSE) or L1 loss on pixel intensities [G]. The view-direction dependence is explicitly excluded, simplifying the optimization landscape compared to RGB 3DGS [S1].

    intensities = np.ones(num_gaussians) * 0.01
    
    return {
        'means': torch.tensor(centers, dtype=torch.float32),
        'scales': torch.tensor(scales, dtype=torch.float32),
        'rotations': torch.tensor(rotations, dtype=torch.float32),
        'intensities': torch.tensor(intensities, dtype=torch.float32)
    }

def transform_covariance_to_screen_space(means, scales, rotations, extrinsic_matrix, intrinsic_matrix, image_width, image_height):
    """
    Compute 2D screen-space covariance for each Gaussian.
    """
    # Convert scales and rotations to 3D covariance Sigma
    # Sigma = R * S * S^T * R^T
    S = torch.zeros_like(scales)
    S[:, 0] = scales[:, 0]
    S[:, 1] = scales[:, 1]
    S[:, 2] = scales[:, 2]
    
    # Compute Sigma_3d
    # Using batch matrix multiplication
    Sigma_3d = torch.bmm(torch.bmm(rotations, S * S), torch.transpose(rotations, 1, 2))
    
    # Extrinsics: W is rotation part, t is translation
    W = extrinsic_matrix[:3, :3]
    T = extrinsic_matrix[:3, 3]
    
    # Project centers to camera space
    # p_cam = R * p_world + t
    means_cam = torch.bmm(W.unsqueeze(0), means.unsqueeze(2)).squeeze(2) + T.unsqueeze(0)
    
    # Jacobian J of the projection
    # p_img = K * [x/z, y/z, 1]
    # Jacobian involves derivatives w.r.t x, y, z
    # For a point (X, Y, Z) in camera space:
    # u = fx * X/Z + cx
    # v = fy * Y/Z + cy
    # d(u)/d(X) = fx/Z, d(u)/d(Y) = 0, d(u)/d(Z) = -fx*X/Z^2
    # d(v)/d(X) = 0, d(v)/d(Y) = fy/Z, d(v)/d(Z) = -fy*Y/Z^2
    
    fx = intrinsic_matrix[0, 0]
    fy = intrinsic_matrix[1, 1]
    cx = intrinsic_matrix[0, 2]
    cy = intrinsic_matrix[1, 2]
    
    Z = means_cam[:, 2].unsqueeze(1)
    X = means_cam[:, 0].unsqueeze(1)
    Y = means_cam[:, 1].unsqueeze(1)
    
    # Construct Jacobian J (3x3) for each Gaussian
    J = torch.zeros(means_cam.shape[0], 2, 3)
    J[:, 0, 0] = fx / Z.squeeze()
    J[:, 0, 2] = -fx * X.squeeze() / (Z.squeeze() ** 2)
    J[:, 1, 1] = fy / Z.squeeze()
    J[:, 1, 2] = -fy * Y.squeeze() / (Z.squeeze() ** 2)
    
    # 2D Covariance: Sigma_2d = J * W * Sigma_3d * W^T * J^T
    # Note: W is already applied to Sigma_3d if Sigma_3d is in world space?
    # Usually Sigma_3d is in world space. The transformation to camera space is R * Sigma * R^T.
    # Then projection J applies to camera space coordinates.
    # So: Sigma_cam = W * Sigma_3d * W^T
    # Sigma_2d = J * Sigma_cam * J^T
    
    Sigma_cam = torch.bmm(torch.bmm(W.unsqueeze(0), Sigma_3d), torch.transpose(W, 0, 1).unsqueeze(0))
    Sigma_2d = torch.bmm(torch.bmm(J, Sigma_cam), torch.transpose(J, 1, 2))
    
    return Sigma_2d

**Parameters:**
- Training iterations: Convergence is analyzed at 1000, 5000, 10000, and 20000 iterations [S1].

**Edge Cases and Pitfalls:**
- **Implementation Complexity:** The method requires a custom CUDA kernel for Differentiable Radiative Rasterization, making it harder to debug and less interpretable than PyTorch-based implementations [S1].
- **Redundant Gaussians:** Unlike original 3DGS, X-Gaussian avoids redundant Gaussians, which is crucial for maintaining inference speed [S1].
- **Covariance Adaptation:** The mean covariance of 3D Gaussians decreases as the number of training views increases, indicating a coarse-to-fine adaptation. Insufficient views may result in overly coarse representations [S1].

## Operating characteristics
**Time and Memory Complexity:**
- X-Gaussian achieves 73× faster inference speed compared to SOTA NeRF-based methods [S1].
- Training time is less than 15% of that required by competing methods [S1].
- Inference speed is 192× faster than RGB NeRF-based methods like TensoRF [S1].

**Measured Performance:**
- Outperforms SOTA methods by over 6.5 dB in PSNR on average [S1].
- Yields 12.93 dB higher PSNR than NAF with 192× inference speed and 20× training speed [S1].
- When used to create novel-view projections for CT reconstruction (FDK, SART, ASD-POCS), PSNR improvements are 15.19, 13.01, and 13.53 dB respectively, which are 1.32, 2.41, and 2.65 dB higher than using NAF [S1].

**Strengths and Limitations:**
- **Strengths:** Fast convergence (clear structural details visible within 1 minute), cleaner backgrounds, ability to represent fine-grained structures (e.g., small tumors) as covariance decreases with more views [S1].
- **Limitations:** Higher implementation complexity due to CUDA dependency; requires foundational knowledge in computer graphics and 3D vision [S1].

**When to Use:**
- Use for X-ray novel view synthesis and sparse-view CT reconstruction where speed and accuracy are critical.
- Avoid if Python-only implementation is required or if the scene involves multi-spectral RGB data.

## Background
X-Gaussian was proposed as the first 3D Gaussian Splatting-based framework for X-ray novel view synthesis [S1]. It addresses the limitations of NeRF-based methods (like NAF) which suffer from slow convergence and high computational cost. The method leverages the efficiency of Gaussian splatting while adapting the radiative model to X-ray imaging properties, excluding view-direction dependence to simplify the optimization [S1]. It is used to generate novel-view projections for learning-free CT reconstruction methods such as FDK, SART, and ASD-POCS [S1].
