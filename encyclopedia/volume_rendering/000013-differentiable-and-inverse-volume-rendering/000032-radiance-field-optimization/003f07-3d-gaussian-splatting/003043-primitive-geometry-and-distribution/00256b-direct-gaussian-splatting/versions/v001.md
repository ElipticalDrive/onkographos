# Direct Gaussian Splatting

Also called: dGS, direct conditional parameterization for Gaussian kernel

## Overview
Direct Gaussian Splatting (dGS) is a method for N-dimensional splatting that replaces the covariance-derived conditioning step of standard N-Dimensional Gaussian Splatting (N-DGS) with explicit per-primitive parameters [S1, unofficial]. It solves the problem of expensive per-primitive matrix inversions and regression products required during the forward pass of conditional slicing [S1, unofficial]. By using a Cholesky precision factor for opacity and a factorized query-to-position regression operator, dGS separates position coupling from opacity coupling, removing expensive operations while maintaining view-dependent and dynamic effects [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ 3D Gaussian primitives. Each primitive $i$ is defined by the parent's parameters: mean position $\boldsymbol{\mu}_p \in \mathbb{R}^3$, covariance $\boldsymbol{\Sigma}$ (factored into rotation $\mathbf{R}$ and scale $\mathbf{S}$), base opacity $\alpha \in [0,1]$, and appearance coefficients. Additionally, each primitive carries direct conditioning parameters: a Cholesky precision factor $\mathbf{L}$, a spatial coupling factor $\mathbf{V}_{pq}$, and a per-dimension coupling vector $\boldsymbol{\Lambda}$.
*   **Query:** A conditioning vector $\mathbf{q}$ (e.g., view direction, time).
*   **Outputs:** Conditional mean $\boldsymbol{\mu}_{\text{cond}}$, conditional opacity $\alpha_{\text{cond}}$, and the standard 3D covariance $\boldsymbol{\Sigma}$ (which remains unchanged by the conditioning; only the effective opacity and position shift for rendering are modified).

**Data Structures:**
Each primitive stores:
1.  $\boldsymbol{\mu}_p$: 3D vector.
2.  $\mathbf{R}$: Quaternion (4 floats) or rotation matrix.
3.  $\mathbf{s}$: Scale vector (3 floats).
4.  $\alpha$: Scalar.
5.  $\mathbf{L}$: Cholesky factor of the query precision. For $C$ conditioning dimensions, $\mathbf{L}$ is a $C \times C$ lower triangular matrix ($C^2$ floats, but only $C(C+1)/2$ unique values).
6.  $\mathbf{V}_{pq}$: Spatial coupling factor. Defined as $\bar{s} \boldsymbol{\Theta}_{pq}$ where $\|\boldsymbol{\Theta}_{pq}\|_F = 1$. $\bar{s}$ is the mean scale of the primitive. $\boldsymbol{\Theta}_{pq}$ is a $3 \times C$ matrix.
7.  $\boldsymbol{\Lambda}$: Per-dimension coupling vector of size $C$.

**Numbered Steps:**
1.  **Compute Query Deviation:** Calculate the deviation of the query from the primitive's canonical query mean $\boldsymbol{\mu}_q$.
    $$ \boldsymbol{\delta} = \mathbf{q} - \boldsymbol{\mu}_q $$
2.  **Compute Precision-Transformed Query:** Apply the Cholesky precision factor $\mathbf{L}$ to the deviation.
    $$ \mathbf{z} = \mathbf{L}^T \boldsymbol{\delta} $$
3.  **Compute Conditional Opacity:** Calculate the opacity using the Gaussian kernel decay on $\mathbf{z}$.
    $$ \alpha_{\text{cond}} = \alpha \cdot \exp(-\lambda_0 \|\mathbf{z}\|_2^2) $$
    where $\lambda_0$ is a scaling factor.
4.  **Compute Conditional Position:** Calculate the shift in mean position based on the query deviation, coupling, and spatial factors.
    $$ \boldsymbol{\mu}_{\text{cond}} = \boldsymbol{\mu}_p + \mathbf{V}_{pq} \text{diag}(\boldsymbol{\Lambda}) \mathbf{V}_{qq} \boldsymbol{\delta} $$
    Note: $\mathbf{V}_{qq}$ is the precision factor shared with opacity, derived from $\mathbf{L}$ or defined separately in the factorization. In the direct parameterization, the term $\text{diag}(\boldsymbol{\Lambda}) \mathbf{V}_{qq}$ acts as the query-to-position regression operator. The source defines the position update as:
    $$ \boldsymbol{\mu}_{\text{cond}} = \boldsymbol{\mu}_p + \mathbf{V}_{pq} \text{diag}(\boldsymbol{\Lambda}) \tilde{\mathbf{V}}_{qq} \boldsymbol{\delta} $$
    where $\tilde{\mathbf{V}}_{qq}$ represents the precision-transformed query channels.

**Formulas:**
*   **Opacity:**
    $$ \alpha_{\text{cond}} = \alpha \cdot \exp(-\lambda_0 \|\mathbf{L}^T \boldsymbol{\delta}\|_2^2) $$
    [S1, unofficial]
*   **Position:**
    $$ \boldsymbol{\mu}_{\text{cond}} = \boldsymbol{\mu}_p + \mathbf{V}_{pq} \text{diag}(\boldsymbol{\Lambda}) \mathbf{V}_{qq} \boldsymbol{\delta} $$
    [S1, unofficial]
    The source notes that $\mathbf{V}_{pq} = \bar{s} \boldsymbol{\Theta}_{pq}$ with $\|\boldsymbol{\Theta}_{pq}\|_F = 1$.
*   **Coupling:** $\boldsymbol{\Lambda}$ interpolates between query-independent position ($\boldsymbol{\Lambda} = \mathbf{0}$) and full coupling with opacity precision ($\boldsymbol{\Lambda} = \mathbf{1}$).

**Parameters:**
*   $\lambda_0$: Scaling factor for the opacity kernel. Default value is 0.35. [S1, unofficial]
*   $\mathbf{L}$: Cholesky precision factor for opacity. Learnable per primitive. [S1, unofficial]
*   $\mathbf{V}_{pq}$: Spatial coupling factor for position regression. Learnable per primitive. [S1, unofficial]
*   $\boldsymbol{\Lambda}$: Per-dimension coupling vector. Learnable per primitive. [S1, unofficial]

**Edge Cases and Pitfalls:**
*   **Precision:** The method relies on the Cholesky decomposition $\mathbf{L}^T \mathbf{L}$. Numerical stability depends on the positive definiteness of the underlying precision matrix.
*   **Boundary:** If $\boldsymbol{\Lambda} = \mathbf{0}$, the position does not shift with the query, but opacity still varies. This allows suppression of primitives under unfavorable views without moving their center. [S1, unofficial]
*   **Dimensionality:** The number of conditioning parameters scales with the number of conditioning dimensions $C$. For $C=3$, dGS uses 22 parameters; for $C=4$, it uses 24. [S1, unofficial]

**Pseudocode:**
```python
import numpy as np

def direct_gaussian_splatting_forward(primitive, query):
    """
    Computes conditional opacity and mean for a single primitive.
    
    Args:
        primitive: Dict containing:
            - mu_p: (3,) array, base mean position
            - alpha: float, base opacity
            - L: (C, C) array, Cholesky precision factor (lower triangular)
            - V_pq: (3, C) array, spatial coupling factor
            - Lambda: (C,) array, per-dimension coupling vector
            - V_qq: (C, C) array, precision factor for query (shared with L or derived)
            - mu_q: (C,) array, canonical query mean
            - s_bar: float, mean scale of the primitive
        query: (C,) array, conditioning vector (e.g., view direction, time)
            
    Returns:
        alpha_cond: float, conditional opacity
        mu_cond: (3,) array, conditional mean position
    """
    # 1. Compute query deviation
    delta = query - primitive['mu_q']
    
    # 2. Compute precision-transformed query z = L^T * delta
    # L is lower triangular, so L^T is upper triangular
    z = primitive['L'].T @ delta
    
    # 3. Compute conditional opacity
    # alpha_cond = alpha * exp(-lambda_0 * ||z||^2)
    lambda_0 = 0.35  # Default value
    alpha_cond = primitive['alpha'] * np.exp(-lambda_0 * np.sum(z**2))
    
    # 4. Compute conditional position
    # mu_cond = mu_p + V_pq * diag(Lambda) * V_qq * delta
    # Note: The source defines the position update as:
    # mu_cond = mu_p + V_pq diag(Lambda) V_qq delta
    # where V_qq is the precision-transformed query channels.
    
    # Construct diag(Lambda)
    diag_lambda = np.diag(primitive['Lambda'])
    
    # Compute the shift
    # V_qq is assumed to be available in primitive or derived from L
    # In the direct parameterization, V_qq is part of the factorization.
    # For implementation, V_qq is typically the same precision structure as L
    # or a separate learnable parameter. The source mentions V_qq is shared.
    # Assuming V_qq is provided or derived:
    V_qq = primitive['V_qq'] 
    
    shift = primitive['V_pq'] @ (diag_lambda @ (V_qq @ delta))
    
    mu_cond = primitive['mu_p'] + shift
    
    return alpha_cond, mu_cond
```

## Subtopics

### [FactorSplat](4088-factorsplat.md)
FactorSplat is a per-scene N-dimensional Gaussian splatting (N-DGS) proxy that accepts region-specific intensity-to-RGBA transfer function (TF) curves at inference time [4088-factorsplat.md]. It allows appearance changes without retraining or refitting. It is chosen when dynamic appearance adjustments are needed without modifying the underlying geometry or opacity parameters.

## Operating characteristics
*   **Time Complexity:** dGS removes the need for per-primitive matrix inversions and regression products required by N-DGS [S1, unofficial]. The forward pass involves matrix-vector multiplications ($\mathbf{L}^T \boldsymbol{\delta}$ and $\mathbf{V}_{pq} \text{diag}(\boldsymbol{\Lambda}) \mathbf{V}_{qq} \boldsymbol{\delta}$), which are $O(C^2)$ and $O(3 \cdot C)$ respectively, where $C$ is the number of conditioning dimensions. This is significantly faster than the $O(C^3)$ inversion required by covariance-derived methods.
*   **Memory Complexity:** dGS uses 22 parameters for $C=3$ and 24 for $C=4$ per primitive [S1, unofficial]. This is more than N-DGS (15/16 for $C=3/4$) but less than UBS/dBS (19/27 for $C=3/4$) [S1, unofficial]. The explicit parameters $\mathbf{L}$, $\mathbf{V}_{pq}$, and $\boldsymbol{\Lambda}$ add memory overhead compared to the implicit covariance structure.
*   **Strengths:** Removes expensive operations, separates position from opacity coupling, and allows for efficient rendering of view-dependent and dynamic effects.
*   **Limitations:** Requires learning additional parameters ($\mathbf{L}$, $\mathbf{V}_{pq}$, $\boldsymbol{\Lambda}$) which may increase training complexity. The explicit parameterization may be less robust to ill-conditioned queries if not regularized.
*   **When to use:** When rendering dynamic scenes or view-dependent effects with N-dimensional splatting and performance is critical.
*   **When not to use:** When memory is extremely constrained and the overhead of explicit parameters is prohibitive, or when simple 3D Gaussian Splatting suffices.

## Background
Direct Gaussian Splatting (dGS) was introduced in the paper "Direct Conditional Parameterization for N-Dimensional Splatting" [S1, unofficial]. It is a direct counterpart to N-Dimensional Gaussian Splatting (N-DGS) [Kerbl et al., 2023] extended to N dimensions. The method was developed to address the computational bottlenecks of conditional slicing in N-DGS by replacing covariance-derived readouts with explicit parameters. It is used in contexts requiring efficient rendering of dynamic and view-dependent scenes using Gaussian primitives.
