# 3D Surface Splatting

Also called: 3DSS

## Overview
3D Surface Splatting (3DSS) is a differentiable surface splatting renderer for physically-based inverse rendering that jointly recovers geometry, materials, and illumination from multi-view images by optimizing an unstructured set of oriented surfel primitives [S1, unofficial]. It solves the problem of multi-layer surface separation and visibility discontinuity in surface splatting by formulating surface grouping as an interval-merging algorithm over sorted primitives, replacing binary/ternary depth tests with a smooth, coverage-based compositing model where per-layer opacity arises directly from accumulated Elliptical Weighted Average (EWA) reconstruction weights [S1, unofficial]. It sets itself apart from its parent [2D Gaussian Splatting](6068-2d-gaussian-splatting.md) by using a surface rendering model rather than a volumetric one (surfels carry no learnable opacity), and from [Flattened Gaussian Ellipsoid Rendering](1667-flattened-gaussian-ellipsoid-rendering.md) by explicitly handling multiple surface layers per pixel through depth-interval merging rather than single-layer rasterization.

## How it works
**Inputs and Outputs:**
*   **Input:** An unstructured set of surfel primitives, each defined by center position $\mathbf{c} \in \mathbb{R}^3$, tangent vectors $\mathbf{t}_u, \mathbf{t}_v \in \mathbb{R}^3$, and shading attributes (albedo $\mathbf{a} \in [0, 1]^3$, metallic $m \in [0, 1]$, roughness $r \in [0, 1]$). Co-optimized HDR environment lighting.
*   **Output:** A differentiable 2D image (HDR) and gradients for the surfel parameters.

**Data Structures:**
Each surfel primitive stores:
*   $\mathbf{c} \in \mathbb{R}^3$: Center position.
*   $\mathbf{t}_u, \mathbf{t}_v \in \mathbb{R}^3$: Tangent vectors spanning the local tangent plane. These encode orientation and anisotropic scaling. The surface normal is implicitly $\mathbf{n} = (\mathbf{t}_u \times \mathbf{t}_v) / \|\mathbf{t}_u \times \mathbf{t}_v\|$.
*   $\mathbf{a} \in [0, 1]^3$: Albedo.
*   $m \in [0, 1]$: Metallic.
*   $r \in [0, 1]$: Roughness.
*   Derived view-space properties: Depth $d$, symmetric depth extent $\delta$, and depth interval $[d-\delta, d+\delta]$.

**Parameters:**
*   $\delta_{cut}$: Kernel support cutoff threshold. Typical values are not explicitly given in the sources, but it defines the boundary for discarding surfels. [G: Commonly $\sqrt{6}$ or similar for 3-sigma cutoff in Gaussian kernels, but the source uses $\delta_{cut}$ as a generic parameter for the squared distance threshold $\rho^2 \ge \delta_{cut}^2$.]

**Steps:**

1.  **T-matrix Construction:**
    For each surfel, transform $\mathbf{c}, \mathbf{t}_u, \mathbf{t}_v$ to camera space, yielding $\mathbf{c}', \mathbf{t}'_u, \mathbf{t}'_v$. Construct the $4 \times 4$ transformation matrix $S = [\mathbf{t}'_u \ \mathbf{t}'_v \ \mathbf{0} \ \mathbf{c}']$ mapping local surfel space (unit sphere parameterization) to camera space. Let $P$ be the projection matrix. Compute the T-matrix $T = PS$. This maps points on the unit sphere in local surfel space to clip space [S1, unofficial].

2.  **Bounding Rectangle and Depth Extent:**
    Compute the bounding rectangle of the surfel in screen space using closed-form expressions involving dot products among the rows of $T$. Compute the symmetric depth extent in view space: $\delta = \sqrt{t'_{u,z}^2 + t'_{v,z}^2} \cdot \delta_{cut}$, where $t'_{u,z}$ and $t'_{v,z}$ are the z-components (view-space depth) of the camera-space tangent vectors. The depth interval is $[d-\delta, d+\delta]$ where $d$ is the view-space depth of $\mathbf{c}'$ [S1, unofficial].

3.  **Forward Shading (Pre-shading):**
    Shade each surfel before rasterization. Apply forward microfacet shading under the co-optimized HDR environment lighting using split-sum Image-Based Lighting (IBL). This yields a pre-shaded linear radiance $\mathbf{c}_{pre}$ for each surfel. This step avoids blending directional quantities (like normals) volumetrically [S1, unofficial].

4.  **Tiling and Sorting:**
    Bin surfels into screen-space tiles. Sort the primitives within each tile by their depth interval start $d_{start} = d - \delta$ (closest extent to the camera), not by center depth [S1, unofficial].

5.  **Per-Pixel Rasterization and Surface Layer Grouping:**
    For each pixel in a tile, iterate through the sorted surfels.
    *   **Ray-Surfel Intersection:** Represent the pixel's viewing ray as the intersection of two clip-space planes: $\mathbf{h}_u = (-1, 0, 0, u)^T$ and $\mathbf{h}_v = (0, -1, 0, v)^T$, where $(u,v)$ are the pixel coordinates. Map these planes into the surfel's local coordinate system via $T$ to yield vectors $\mathbf{k}$ and $\mathbf{l}$. Their intersection with the surfel's plane gives local coordinates $(u_{local}, v_{local})$ of the hit point.
    *   **Distance and Discard:** Compute squared distance from surfel center: $\rho^2 = u_{local}^2 + v_{local}^2$. If $\rho^2 \ge \delta_{cut}^2$, discard the surfel for this pixel [S1, unofficial].
    *   **Weight Evaluation:** Compute unnormalized Gaussian reconstruction kernel weight: $w = \exp(-\frac{1}{2} \rho^2)$. Note: The $1/(2\sigma)$ normalization constant is omitted as weights are used for Shepard normalization later [S1, unofficial].
    *   **Interval Merging (Surface Separation):** Maintain a list of active surface layers for the pixel. Each layer tracks a running sum of weights and attributes.
        *   If the current surfel's depth interval $[d-\delta, d+\delta]$ overlaps with the depth interval of the last surfel added to the current active layer, add the surfel to that layer.
        *   If it does not overlap, and since primitives are sorted by $d_{start}$, no future primitive can bridge the gap. Start a new surface layer with the current surfel.
        *   This exact gap detection requires no look-ahead or deferred merging [S1, unofficial].
    *   **Attribute Accumulation:** For each surfel added to a layer, accumulate its pre-shaded radiance $\mathbf{c}_{pre}$ and weight $w$ to the layer's running sums: $W_{layer} \leftarrow W_{layer} + w$ and $\mathbf{C}_{layer} \leftarrow \mathbf{C}_{layer} + w \cdot \mathbf{c}_{pre}$ [S1, unofficial].

6.  **Compositing:**
    After processing all surfels for a pixel, for each active surface layer $k$:
    *   Compute the reconstructed attribute (radiance) for the layer: $\hat{\mathbf{a}}_k = \frac{\sum_{j \in \text{layer } k} w_j \mathbf{c}_{pre, j}}{\sum_{j \in \text{layer } k} w_j}$. This is a Shepard-type normalization [S1, unofficial].
    *   Compute the coverage-based opacity for the layer: $\alpha_k = \frac{\sum_{j \in \text{layer } k} w_j}{\sum_{j \in \text{layer } k} w_j + \epsilon}$ (or similar normalization to [0,1], derived from accumulated weight). The source states opacity arises directly from accumulated EWA weight. [G: Typically, opacity is normalized such that $\alpha_k \in [0,1]$. A common formulation is $\alpha_k = 1 - \exp(-\sum w_j)$ or simply using the normalized weight sum if bounded. The source says "coverage-derived opacity" and "compositing is performed across layers via the over operator". Let $\alpha_k$ be the opacity for layer $k$.]
    *   Composite layers front-to-back using the over operator: $\mathbf{C}_{out} = \sum_{k} \mathbf{C}_k \alpha_k \prod_{j < k} (1 - \alpha_j)$. The final image is the composited HDR image [S1, unofficial].

7.  **Anti-Aliasing:**
    Apply an object-space MIP filter. This exploits the resampling structure of surface splatting. Use a center-precomputed approximation to amortize the Jacobian evaluation, suppressing sampling aliasing [S1, unofficial].

                    w = math.exp(-0.5 * rho_sq)

                    d_start = surfel.d - surfel.delta
                    d_end = surfel.d + surfel.delta

                    added_to_layer = False

                            added_to_layer = True
                            break

                        new_layer = {
                            'W': w,
                            'C': w * surfel.c_pre,
                            'max_d_end': d_end
                        }
                        layers.append(new_layer)
                
                # 4. Compositing
                # Normalize and composite
                alpha_accum = 0.0
                final_color = np.zeros(3)
                
                for layer in layers:
                    # Reconstructed attribute
                    if layer['W'] > 1e-6:
                        a_hat = layer['C'] / layer['W']
                    else:
                        a_hat = np.zeros(3)
                    
                    # Coverage-based opacity
                    # Source says opacity arises from accumulated EWA weight.
                    # Let's assume alpha = 1 - exp(-W) or similar.
                    # For simplicity, let's use a normalized weight if it's bounded, 
                    # but EWA weights are not bounded.
                    # A common approach is alpha = min(1.0, W / W_max) or alpha = 1 - exp(-W).
                    # Let's use alpha = 1 - exp(-W) as a standard coverage model.
                    alpha = 1.0 - math.exp(-layer['W'])
                    
                    # Over operator
                    final_color += a_hat * alpha * (1.0 - alpha_accum)
                    alpha_accum += alpha * (1.0 - alpha_accum)
                
                image[y, x] = final_color
                
    return image

## Subtopics

### [3D Surface Splatting Rasterization](4751-3d-surface-splatting-rasterization.md)
The rasterization core of 3DSS, designed to render an unstructured set of oriented surfel primitives into a 2D image while correctly handling self-occlusion at concavities. It solves the problem where single-layer rasterization approaches fail to distinguish between geometrically distinct surface sheets that project onto the same pixel, resulting in holes or translucent artifacts in high-curvature regions like ears or under chins. It sets itself apart from classical A-buffer approaches by restricting summation to surfels within the same depth-interval layer rather than gathering across all depths, and from single-layer ternary depth tests by detecting gaps in the depth-interval chain to support an arbitrary number of surface layers per pixel.

## Operating characteristics
*   **Time Complexity:** Linear in the number of surfels and pixels, with overhead from sorting and interval merging. The interval merging is efficient as it requires no look-ahead.
*   **Memory Complexity:** Linear in the number of surfels and pixels for storing intermediate layer data.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Not given in the sources.
*   **Strengths:** Handles multiple surface layers per pixel correctly; differentiable visibility; anti-aliased silhouettes; physically-based shading; compatible with mesh reconstruction.
*   **Limitations:** Requires pre-shading; interval merging logic is more complex than simple depth testing.
*   **When to use:** Physically-based inverse rendering where geometry, materials, and illumination need to be recovered jointly, especially for scenes with complex occlusions and multiple surface layers.
*   **When not to use:** When a volumetric representation is preferred or when real-time performance is critical and the overhead of interval merging is prohibitive.

## Background
3D Surface Splatting (3DSS) was introduced by Mae Younes in 2026 [S1, unofficial]. It builds on the foundations of Elliptical Weighted Average (EWA) surface splatting [Zwicker et al. 2001] and addresses the limitations of prior differentiable surface splatting methods like Differentiable Surface Splatting (DSS) [Yifan et al. 2019] by providing a more robust multi-layer surface separation and a surface rendering model compatible with physically-based inverse rendering. It bridges the gap between point-based inverse rendering and mesh-based workflows by producing an optimized surfel representation that is natively compatible with Screened Poisson Surface Reconstruction [Kazhdan and Hoppe 2013].
