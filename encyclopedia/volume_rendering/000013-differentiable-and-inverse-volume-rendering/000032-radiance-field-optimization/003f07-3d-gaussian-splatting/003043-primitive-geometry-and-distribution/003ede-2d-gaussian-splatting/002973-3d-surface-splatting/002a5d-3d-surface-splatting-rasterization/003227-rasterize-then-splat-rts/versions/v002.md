# Rasterize-then-splat (RtS)


## Overview
Rasterize-then-splat (RtS) is a method for differentiable rendering of 3D surfaces that supports both explicit and implicit representations, providing derivatives at occlusion boundaries while remaining fast and simple to implement [S1]. It differs from alternatives like Soft Rasterizer by avoiding costly closest-point queries or mesh processing, and from Nvdiffrast by requiring no specific GPU hardware or custom derivative code, making its differentiable cost independent of mesh size [S1].

## How it works
The method consists of three sequential steps: rasterization of the surface, shading the surface samples, and multi-layer splatting [S1]. All derivatives are produced using automatic differentiation on the forward rendering computation [S1].

**Inputs and Outputs**
*   **Input:** Scene parameters $\theta$ (e.g., camera pose, light parameters, surface definition parameters) [S1].
*   **Output:** Final rendered image $S$ [S1].

**Data Structures**
1.  **Parameter Buffers ($U_k$):** Per-layer screen-space parameter buffers [S1]. For triangle meshes, these consist of per-pixel triangle indices $T_k$ and perspective-correct barycentric coordinates $B_k$ [S1]. These are computed via conventional Z-buffer graphics processing using depth peeling to retrieve multiple intersections per pixel [S1].
2.  **G-buffers ($G_k$):** Interpolated shape attributes (positions, normals) derived from $U_k$ [S1].
3.  **Splat Colors ($C_k$):** Shaded colors computed via a deferred shading function [S1].
4.  **Screen-space Positions ($P_k$):** Projected positions of the splats [S1].

**Steps**
1.  **Sampling (Non-differentiable):** Scene parameters $\theta$ are passed through a sampling function $U$, yielding per-layer screen-space parameter buffers $U_k$ [S1]. This step is non-differentiable and computed only in the forward pass [S1].
2.  **Evaluation (Differentiable):** An evaluation function $G$ uses the non-differentiable parameters $U_k$ to interpolate shape attributes (such as positions and normals) into G-buffers $G_k$ [S1]. Automatic differentiation is applied to $G$ and downstream functions [S1].
3.  **Shading and Projection (Differentiable):** The evaluated attributes are combined to compute splat colors $C_k$ via a deferred shading function $\mathcal{C}$ and corresponding screen-space positions $P_k$ via a projection function $\mathcal{P}$ [S1].
4.  **Splatting (Differentiable):** Function $\mathcal{S}$ splats the shaded colors $C_k$ at the corresponding pixel locations $P_k$ using a 3x3 kernel to produce the final result $S$ [S1].

**Pseudocode**
```python
def rasterize_then_splat(scene_params, camera, surface_def, image_shape):
    # Step 1: Non-differentiable sampling
    # U_k contains per-pixel triangle indices T_k and barycentric coordinates B_k
    # Computed via conventional Z-buffer with depth peeling [S1]
    U_k = depth_peeling_rasterize(surface_def, camera, image_shape)

    # Step 2: Differentiable evaluation
    # G_k contains interpolated positions and normals
    G_k = evaluate_attributes(U_k, surface_def)

    # Step 3: Differentiable shading and projection
    C_k = compute_shading(scene_params, G_k)
    P_k = project_to_screen(G_k, camera)

    # Step 4: Differentiable multi-layer splatting
    # S is the final image, accumulated using a 3x3 kernel
    S = zeros(image_shape)
    for k in range(len(C_k)):
        for y, x in P_k[k]:
            for dy in range(-1, 2):
                for dx in range(-1, 2):
                    ny, nx = y + dy, x + dx
                    if 0 <= ny < image_shape[0] and 0 <= nx < image_shape[1]:
                        weight = 1.0 / 9.0  # 3x3 kernel weight [S1]
                        S[ny, nx] += weight * C_k[k][y, x]
    return S
```

**Edge Cases and Pitfalls**
*   **Occlusion Boundaries:** RtS provides derivatives at occlusion boundaries, a feature not always present in standard rasterization [S1].
*   **Implicit Surfaces:** The method supports isosurfaces extracted from implicit surface definitions (e.g., neural radiance fields), avoiding issues with under- or over-sampling of splats by resampling at each frame [S1].

## Operating characteristics
*   **Time Complexity:** The cost of the differentiable sections is independent of the size of the mesh [S1].
*   **Memory Complexity:** Not given in the sources [S1].
*   **Strengths:** Fast and simple to implement; requires no differentiable meshing or rasterization steps; efficient for large 3D models; applicable to isosurfaces from implicit definitions; no custom derivative code needed [S1].
*   **Limitations:** Relies on non-differentiable rasterization for sampling, but provides derivatives at occlusion boundaries [S1].
*   **When to use:** When rendering large explicit meshes or implicit surfaces (like NeRF isosurfaces) where implementation simplicity and hardware independence are prioritized over specific GPU hardware optimizations [S1].
*   **When not to use:** Not given in the sources.

## Background
RtS was introduced by Zhoutong Zhang in the paper "Differentiable Surface Rendering via Non-Differentiable Sampling" [S1]. It was presented at ICCV 2021 [S1]. The method was demonstrated for implicit-, mesh-, and parametric-surface-based inverse rendering and neural-network training applications, including the first efficient, differentiable rendering of an isosurface extracted from a neural radiance field (NeRF) [S1]. It builds on surface splatting techniques [42] and differentiable visibility methods [34], but distinguishes itself by using a true surface representation and resampling splats per frame [S1].
