# SVGS with Movable Kernels

Also called: Movable Kernels (SVGS Variant), Movable kernels spatially varying function, Ours-MK, SVGS (Movable Kernels), SVGS-MK

## Overview
SVGS with Movable Kernels is a spatially varying function implementation within the SVGS framework that defines $k$ movable exponential kernels located on a Gaussian surfel, weighted by their distance to the intersection point [S1]. It enhances scene representation by allowing sub-kernels to adapt their positions during training, providing higher flexibility and stronger expressiveness than fixed-basis methods [S1]. It sets itself apart from its sibling [Bilinear Interpolation](8729-spatially-varying-gaussian-splatting-svgs.md#bilinear-interpolation) by replacing fixed quadrant weights with learnable, gradient-driven kernel centers, and from [Tiny MLPs](8729-spatially-varying-gaussian-splatting-svgs.md#tiny-mlps) by using a compact parametric form rather than a neural network [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A Gaussian surfel primitive (defined by its mean, covariance, and base opacity/color), camera view, and intersection point $p$ in the local 2D coordinate system $(u, v)$ of the surfel [G].
*   **Output:** The final color $C$ and opacity $\alpha$ for the intersection point, computed by blending the contributions of $k$ movable sub-kernels [S1].

**Data Structures:**
Each Gaussian primitive stores the following learnable parameters in addition to the standard 2DGS attributes [S1]:
*   $k$ kernel centers: $K_i = (K_{ix}, K_{iy})$ for $i = 0, \dots, k-1$. These are 2D coordinates in the local surfel space [S1].
*   $k$ learnable colors: $c_i \in \mathbb{R}^3$ for $i = 0, \dots, k-1$ [S1].
*   $k$ learnable opacities: $\alpha_i \in \mathbb{R}$ for $i = 0, \dots, k-1$ [S1].

**Parameters:**
*   $k$: The number of movable kernels per Gaussian surfel. Default value is $k=4$ [S1].
*   $\lambda_e$: The parameter controlling the changing rate of the kernel function. Default value is $\lambda_e = 0.1$ [S1].

**Algorithm:**
1.  **Initialization:** For each Gaussian primitive, initialize $k$ kernel centers $K_i$, colors $c_i$, and opacities $\alpha_i$ [G].
2.  **Forward Pass (Weight Computation):**
    For a given intersection point $p = (u, v)$ on the surfel:
    a. Compute the Euclidean distance $d_i$ between the intersection point $p$ and each kernel center $K_i$:
       $$ d_i = \| p - K_i \|_2 $$
    b. Compute the weight $w_i$ for each kernel using an exponential decay function:
       $$ w_i = \exp(-\lambda_e \cdot d_i) $$
    c. Normalize the weights to sum to 1:
       $$ \hat{w}_i = \frac{w_i}{\sum_{j=0}^{k-1} w_j} $$
    d. Compute the spatially varying color $C(p)$ and opacity $\alpha(p)$ by blending the learnable attributes using the normalized weights:
       $$ C(p) = \sum_{i=0}^{k-1} \hat{w}_i c_i $$
       $$ \alpha(p) = \sum_{i=0}^{k-1} \hat{w}_i \alpha_i $$
3.  **Backward Pass (Gradient Calculation):**
    a. Compute the gradients of the loss with respect to $C(p)$ and $\alpha(p)$ [G].
    b. Propagate these gradients to the learnable parameters $c_i$, $\alpha_i$, and $K_i$ [G].
    c. Update the kernel centers $K_i$ in the direction of their gradients during optimization [S1].
4.  **Degeneracy Handling:**
    If a kernel center $K_i$ moves outside the Gaussian support during optimization, the primitive effectively degenerates to standard 2DGS behavior for that primitive. No clamping or projection constraints are applied to keep the kernel inside the support [S1].

**Pseudocode:**

```python
import math

def compute_movable_kernel_weights(p_u, p_v, kernel_centers, lambda_e):
    k = len(kernel_centers)
    weights = []
    for i in range(k):
        ku, kv = kernel_centers[i]
        dist_sq = (p_u - ku)**2 + (p_v - kv)**2
        dist = math.sqrt(dist_sq)
        w = math.exp(-lambda_e * dist)
        weights.append(w)
    sum_w = sum(weights)
    if sum_w == 0:
        return [1.0 / k] * k
    normalized_weights = [w / sum_w for w in weights]
    return normalized_weights

def evaluate_spatially_varying_function(p_u, p_v, kernel_centers, colors, opacities, lambda_e):
    k = len(kernel_centers)
    weights = compute_movable_kernel_weights(p_u, p_v, kernel_centers, lambda_e)
    r = 0.0
    g = 0.0
    b = 0.0
    alpha = 0.0
    for i in range(k):
        w = weights[i]
        ri, gi, bi = colors[i]
        ai = opacities[i]
        r += w * ri
        g += w * gi
        b += w * bi
        alpha += w * ai
    return (r, g, b), alpha

def update_kernel_centers(kernel_centers, gradients, learning_rate):
    k = len(kernel_centers)
    updated_centers = []
    for i in range(k):
        ku, kv = kernel_centers[i]
        dku, dkv = gradients[i]
        new_ku = ku - learning_rate * dku
        new_kv = kv - learning_rate * dkv
        updated_centers.append((new_ku, new_kv))
    return updated_centers
```

**Edge Cases and Pitfalls:**
*   **Kernel Degeneracy:** If a kernel center moves outside the Gaussian support, the method degenerates to standard 2DGS behavior for that primitive. The sources state that no special restrictions are imposed to prevent this, as it rarely occurs (probability of remaining inside is >99.5% across datasets) [S1].
*   **Weight Zero Division:** If all exponential weights are effectively zero (e.g., intersection point is very far from all kernels), normalization requires a fallback (e.g., uniform distribution) to avoid division by zero [G].

## Subtopics

### SVGS with Bilinear Interpolation
Uses four fixed kernels located in the four quadrants of the elliptical Gaussian surfel, assigning learnable color and opacity to each quadrant via bilinear interpolation [S1]. Simpler but may cause gradient vanishing [S1]. Choose when computational simplicity is prioritized over maximum expressiveness [G]. [Link](8729-spatially-varying-gaussian-splatting-svgs.md#bilinear-interpolation)

### SVGS with Tiny MLPs
Uses a tiny three-layer neural network on each Gaussian surfel to map local coordinates to color and opacity [S1]. Strongest representation ability but significantly more parameters [S1]. Choose when maximum fidelity is required and parameter budget is less constrained [G]. [Link](8729-spatially-varying-gaussian-splatting-svgs.md#tiny-mlps)

## Operating characteristics
*   **Time Complexity:** Training and rendering are slightly slower than 2DGS due to the per-primitive overhead of evaluating $k$ sub-kernels for weight computation, color blending, and gradient calculation [S1].
*   **Memory Complexity:** Uses approximately 1.4× the parameters of 2DGS [S1].
*   **Measured Performance:** On the Synthetic Blender dataset, training takes 1083.13s vs 635.25s for 2DGS, with rendering at 133.25 FPS vs 210.73 FPS [S1]. Rendering speed still exceeds 30 FPS for real-time use [S1].
*   **Strengths:** Superior novel view synthesis performance on multiple datasets, particularly excelling at representing complex textures on relatively flat geometries [S1]. Maintains superior expressiveness even when 2DGS is forced to use 2× the Gaussians [S1]. Compatible with existing acceleration frameworks without architectural changes [S1].
*   **Limitations:** Slightly slower training and rendering compared to 2DGS [S1].
*   **When to Use:** When high-fidelity reconstruction of complex textures on simple geometry is required, and real-time rendering (>30 FPS) is still desired [G].
*   **When Not to Use:** When maximum training speed is the primary constraint and 2DGS performance is sufficient [G].

## Background
SVGS with Movable Kernels was introduced in the paper "SVGS: Enhancing Gaussian Splatting Using Primitives With Spatially Varying Colors" [S1]. It is part of the SVGS family, which aims to address the non-compactness of vanilla Gaussian Splatting by allowing spatially varying colors and opacity within a single primitive [S1]. The method was evaluated on Synthetic Blender, Mip-NeRF360, Tanks&Temples, and DTU datasets [S1].
