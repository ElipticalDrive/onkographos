# Quantile Rendering

Also called: Q-Render

## Overview
Quantile Rendering (Q-Render) is a sparse, transmittance-guided sampling strategy designed to efficiently render high-dimensional feature maps from 3D Gaussians [S1, unofficial]. It solves the computational bottleneck of dense volume rendering, where accumulating high-dimensional features along every ray scales poorly with feature dimensionality [S1, unofficial]. Unlike conventional volume rendering, which processes all rasterized Gaussians, Q-Render shifts the Riemann partition from the spatial domain to the transmittance domain, sampling only the most representative "quantile Gaussians" that dominate the ray's transmittance profile [S1, unofficial]. This approach reduces complexity from $O(N C)$ to $O(N + K C)$, enabling real-time rendering of high-dimensional data (e.g., 512-D CLIP embeddings) while maintaining segmentation accuracy [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   $\mathcal{G}$: Set of optimized 3D Gaussians, where each $g_i \in \mathcal{G}$ contains parameters $\{\mu_i, s_i, r_i, \alpha_i, \text{sph}_i\}$ [S1, unofficial].
    *   $\mathcal{F}$: Predicted Gaussian features, where each $f_i \in \mathcal{F}$ is a vector in $\mathbb{R}^C$ [S1, unofficial].
    *   $K$: Hyperparameter defining the number of quantile segments (and thus the number of sampled Gaussians) [S1, unofficial].
    *   $I$: Indices of rasterized 3D Gaussians intersecting the target ray, sorted by depth [S1, unofficial].
*   **Output:**
    *   $\tilde{f}_Q \in \mathbb{R}^C$: The rendered feature vector for the ray [S1, unofficial].

**Data Structures:**
The algorithm iterates through the list of rasterized Gaussian indices $I$ using standard accumulators for transmittance and feature vectors [S1, unofficial].

**Mathematical Background:**
Standard volume rendering integrates feature $c(t)$ weighted by density $\sigma(t)$ and transmittance $T(t)$ over spatial distance $t$:
$$ C_{vol} = \int_0^\infty c(t) \sigma(t) T(t) dt $$
where $T(t) = \exp(-\int_0^t \sigma(s) ds)$ [S1, unofficial].
By changing variables to transmittance $u = T(t)$, where $du = -\sigma(t)T(t)dt$, the integral transforms to a Riemann integral over $u \in [0, 1]$:
$$ C_{vol} = \int_0^1 c(u) du $$
Q-Render approximates this integral using a Right Riemann Sum by partitioning the transmittance domain $[0, 1]$ into $K+1$ equal segments defined by boundaries $0 = u_{K+1} < u_K < \dots < u_1 < u_0 = 1$ [S1, unofficial].

**Algorithm Steps:**
1.  **Initialize Accumulators:** Set current transmittance $T \leftarrow 1$, accumulated feature $f_Q \leftarrow \mathbf{0}$, and quantile counter $k \leftarrow 0$ [S1, unofficial].
2.  **Iterate Rasterized Gaussians:** For each Gaussian index $i$ in $I$:
    a. Retrieve Gaussian $g_i$ and feature $f_i$ [S1, unofficial].
    b. Compute test transmittance after passing through $g_i$: $T_{test} \leftarrow T \cdot (1 - \alpha'_i)$, where $\alpha'_i$ is the effective alpha of the Gaussian [S1, unofficial].
    c. **Quantile Boundary Check:** Determine if the transmittance has crossed the next quantile boundary. The boundary for the $(k+1)$-th segment is $1 - \frac{k+1}{K+1}$ [S1, unofficial]. If $T_{test} < 1 - \frac{k+1}{K+1}$:
        i. Increment $k$ to reflect crossing a boundary [S1, unofficial].
        ii. **Sample Quantile Gaussian:** The current Gaussian $g_i$ is selected as the representative for the quantile interval ending at the boundary [S1, unofficial]. Compute its weight $w_Q \leftarrow T \cdot \alpha'_i$ (using the incoming transmittance $T$ for correct alpha-blending) [S1, unofficial].
        iii. **Alpha-Blend:** Update accumulated feature: $f_Q \leftarrow f_Q + w_Q \cdot f_i$ [S1, unofficial].
        iv. **Handle Multiple Crossings:** While $T_{test} < 1 - \frac{k+1}{K+1}$, increment $k$ again to account for cases where a single Gaussian causes the transmittance to drop across multiple quantile boundaries or due to precision issues [S1, unofficial].
    d. **Termination Check:** If $T_{test} < \frac{1}{K+1}$, break the loop, as remaining transmittance is negligible for the quantile approximation [S1, unofficial].
    e. **Update Transmittance:** Set $T \leftarrow T_{test}$ for the next iteration [S1, unofficial].
3.  **Normalize Feature Vector:** Divide the accumulated feature by the remaining transmittance to correct for the unblended portion: $\tilde{f}_Q \leftarrow f_Q / (1 - T)$ [S1, unofficial].

**Pseudocode:**
```python
def QuantileRender(G, F, K, I):
    """
    G: List of Gaussian objects with attribute alpha
    F: List of feature vectors corresponding to G, each of dimension C
    K: Number of quantile segments
    I: List of indices of rasterized Gaussians sorted by depth
    Returns: Rendered feature vector of dimension C
    """
    T = 1.0          # Current transmittance
    f_Q = [0.0] * C  # Accumulated feature vector
    k = 0            # Counter for quantile boundaries crossed
    
    for i in I:
        alpha = G[i].alpha
        f = F[i]
        
        # Transmittance after this Gaussian
        T_test = T * (1.0 - alpha)
        
        # Check if transmittance crossed the next quantile boundary
        boundary = 1.0 - (k + 1) / (K + 1)
        
        if T_test < boundary:
            k += 1
            # Weight uses current incoming transmittance T for correct blending
            w_Q = T * alpha
            for c in range(C):
                f_Q[c] += w_Q * f[c]
            
            # Handle multiple boundary crossings for the same Gaussian
            while T_test < 1.0 - (k + 1) / (K + 1):
                k += 1
        
        # Termination check for negligible remaining transmittance
        if T_test < 1.0 / (K + 1):
            break
            
        # Update transmittance for subsequent Gaussians
        T = T_test
        
    # Normalize to account for residual transmittance
    denom = 1.0 - T
    if denom < 1e-6:
        return f_Q
    f_Q_normalized = [val / denom for val in f_Q]
    return f_Q_normalized
```

**Parameters:**
*   $K$: Number of quantile segments. Typical values are 10, 20, 40 [S1, unofficial]. $K=40$ yields best performance, but convergence is achieved at $K \ge 10$ (~50 mIoU) [S1, unofficial]. Using $K < 10$ causes significant performance drops due to transmittance profile discrepancy [S1, unofficial].
*   $C$: Feature dimension (e.g., 512) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Fixed K Sensitivity:** The optimal $K$ varies with the transmittance distribution of the ray. Using a fixed $K=40$ is a simplification. Inference with $K \neq 40$ (when trained with 40) causes significant performance drops, indicating a need for adaptive $K$ selection [S1, unofficial].
*   **Normalization:** The final normalization step corrects for residual transmittance $T$ remaining after processing all $K$ quantile Gaussians. Without this, the accumulated feature would be biased because the sum of weights would not equal 1 [S1, unofficial].
*   **Precision:** The `while` loop for boundary crossing handles precision issues where multiple boundaries might be crossed by a single Gaussian or due to floating-point errors [S1, unofficial].

## Subtopics

### Learned-K Adaptive Sampling
An adaptive variant of Q-Render that dynamically selects the number of quantiles $K$ per input ray by predicting feature similarity [S1, unofficial].
*   **Definition:** Instead of a fixed $K$, this method predicts the optimal $K$ based on the ray's transmittance profile [S1, unofficial].
*   **Method:** The model is trained with three candidate $K$ values: $\{10, 20, 40\}$ [S1, unofficial]. A similarity-prediction head takes the transmittance profiles $\{T_n\}$ as input and outputs predicted similarity scores for each candidate $K$ [S1, unofficial]. An additional loss computes the difference between predicted similarity scores and actual feature similarity [S1, unofficial]. During inference, the model evaluates these scores and dynamically selects the $K$ that yields the highest predicted similarity [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** Reduces complexity from $O(N C)$ in dense volume rendering to $O(N + K C)$, where $N$ is the number of rasterized Gaussians per pixel and $C$ is the feature dimension [S1, unofficial]. This is significantly faster than top-$K$ sampling, which requires sorting and has complexity $O(N \log K + K C)$ [S1, unofficial].
*   **Memory:** Requires storing the rasterized Gaussian indices and features, similar to standard 3DGS, but reduces the computational load during the accumulation phase [S1, unofficial].

**Measured Performance:**
*   **Speed:** On ScanNet scene0006_00 with 512-D feature maps, Q-Render achieves 28.42 FPS, a ~43.7× speedup over a modified baseline for-loop implementation (0.65 FPS) [S1, unofficial]. It is up to 1.5× faster than standard volume rendering (V-Render) [S1, unofficial].
*   **Accuracy:** On ScanNet, Q-Render with $K=10$ achieved 50.75 mIoU, comparable to V-Render's 49.02 mIoU, and superior to top-$K$ (e.g., 45.70 mIoU at $K=40$) [S1, unofficial]. At $K=40$, mIoU reached 50.85 [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Enables real-time rendering of high-dimensional features (e.g., for open-vocabulary segmentation); avoids sorting overhead of top-$K$; converges quickly with small $K$ [S1, unofficial].
*   **Limitations:** Sensitivity to the fixed $K$ hyperparameter; performance drops if inference $K$ differs from training $K$; theoretical approximation error converges at $O(1/K)$ [S1, unofficial].

## Background
Quantile Rendering was introduced in the paper "Quantile Rendering: Efficiently Embedding High-dimensional Feature on 3D Gaussian Splatting" [S1, unofficial]. It was developed to address the computational cost of rendering high-dimensional features (such as CLIP embeddings) in 3D Gaussian Splatting, which is critical for tasks like open-vocabulary 3D semantic segmentation [S1, unofficial]. The method builds on the continuous volume rendering integral formulation, shifting the sampling domain from spatial distance to transmittance [S1, unofficial]. It is used in architectures like GS-Mink and GS-PTv3 for generalizable 3D neural networks [S1, unofficial].
