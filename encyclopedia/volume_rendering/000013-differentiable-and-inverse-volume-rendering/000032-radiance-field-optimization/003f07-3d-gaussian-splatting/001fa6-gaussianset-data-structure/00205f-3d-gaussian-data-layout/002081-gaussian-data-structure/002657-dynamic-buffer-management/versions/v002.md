# Dynamic Buffer Management

Also called: Capacity Growth

## Overview
Dynamic Buffer Management automatically resizes memory buffers for 3D Gaussian splats when the active count exceeds current capacity, preventing training stalls from insufficient memory [S1, unofficial]. It differs from static allocation by adapting to scene complexity during training [S1, unofficial].

## How it works
The method takes the current number of active Gaussians ($N_{active}$), current buffer capacity ($C_{current}$), stride size ($S$) in floats per Gaussian, element size ($E$) in bytes, and existing buffer data (`old_buffers`) as inputs [S1, unofficial]. The method returns updated buffer pointers, new capacity ($C_{new}$), re-allocated densification flags, and resized scratch buffers as outputs [S1, unofficial]. Buffers are contiguous arrays of floats where each Gaussian occupies $S$ floats [S1, unofficial]. The total memory size is $C \times S \times E$ bytes [S1, unofficial].

1. Check if $N_{active} > C_{current}$ [S1, unofficial].
2. If not, continue training [S1, unofficial].
3. If yes, calculate new capacity $C_{new}$: if $2 \times C_{current} \ge N_{active}$, set $C_{new} = 2 \times C_{current}$; else set $C_{new} = N_{active}$ [S1, unofficial].
4. Allocate new zero-initialized buffers of size $C_{new} \times S \times E$ [S1, unofficial].
5. Copy $N_{active} \times S \times E$ bytes from old buffers to new buffers [S1, unofficial].
6. Update views/pointers to new buffers [S1, unofficial].
7. Re-allocate densification flags as zeros for the new capacity [S1, unofficial].
8. Resize scratch buffers based on $C_{new}$ and feature stride [S1, unofficial].

**Pseudocode:**
```python
def dynamic_buffer_management(active_count, current_capacity, stride, element_size, old_buffers):
    if active_count <= current_capacity:
        return current_capacity, old_buffers, None, None
    if 2 * current_capacity >= active_count:
        new_capacity = 2 * current_capacity
    else:
        new_capacity = active_count
    new_buffers = [0.0] * (new_capacity * stride * element_size)
    copy_size = active_count * stride * element_size
    for i in range(copy_size):
        new_buffers[i] = old_buffers[i]
    buffers = new_buffers
    densification_flags = [0] * new_capacity
    scratch_buffers = [0.0] * (new_capacity * stride)
    return new_capacity, buffers, densification_flags, scratch_buffers
```

**Edge Cases:**
- If $N_{active}$ is significantly larger than $C_{current}$, the capacity is set directly to $N_{active}$ rather than doubling, avoiding excessive over-allocation [S1, unofficial].

## Subtopics

## Operating characteristics
The time complexity is $O(N_{active})$ for copying data during growth [G]. The memory complexity is $O(C_{new})$ for the newly allocated buffer [G]. The method reduces frequent reallocation overhead by doubling capacity when possible [S1, unofficial]. Its strengths are adapting to scene complexity and requiring simple implementation [S1, unofficial]. Its limitations include potential memory waste if capacity grows much larger than needed [G]. It should be used during training when Gaussian count is dynamic [S1, unofficial]. It should not be used in inference where Gaussian count is fixed [G].

## Background
Originated in 3D Gaussian Splatting implementations to handle dynamic Gaussian counts during training [S1, unofficial].
