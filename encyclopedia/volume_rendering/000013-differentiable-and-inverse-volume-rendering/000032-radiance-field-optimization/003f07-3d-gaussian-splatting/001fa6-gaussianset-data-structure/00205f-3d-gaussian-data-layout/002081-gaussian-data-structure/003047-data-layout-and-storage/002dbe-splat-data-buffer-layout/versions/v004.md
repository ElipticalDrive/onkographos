# Splat Data Buffer Layout

Also called: SplatData Layout, Structure-of-Arrays Splat Storage

## Overview
The Splat Data Buffer Layout defines the memory organization for 3D Gaussian splats, storing attributes in separate contiguous linear buffers (Structure-of-Arrays). This layout maximizes cache coherency during batched GPU rendering by ensuring shaders iterate over single attributes without skipping irrelevant data [S1, unofficial]. It serves as the foundational storage scheme for the GaussianSet Data Structure, distinct from sibling methods like [Spherical Harmonics Coefficient Layout](5570-spherical-harmonics-coefficient-layout.md) which details the specific indexing within the SH buffer, or [Covariance Splat Reading](6840-covariance-splat-reading.md) which handles runtime transformation.

## How it works
**Inputs:** A collection of $N$ splats, where each splat $i$ has position $\mathbf{p}_i$, scale $\mathbf{s}_i$, rotation $\mathbf{q}_i$, opacity $\alpha_i$, and spherical harmonic coefficients $\mathbf{c}_{i,d}$.
**Outputs:** A set of contiguous `FloatBuffer` arrays (or equivalent GPU buffers) for each attribute type.

**Data Structures:**
The layout consists of separate buffers, each of size $N \times \text{components}$:
1.  **Positions:** Size $N \times 3$. Stores $(x, y, z)$.
2.  **Scales:** Size $N \times 3$. Stores $(\log(s_x), \log(s_y), \log(s_z))$ in log-space to ensure positivity [S1, unofficial].
3.  **Rotations:** Size $N \times 4$. Stores quaternions in scalar-last order $(x, y, z, w)$ [S1, unofficial].
4.  **Opacities:** Size $N$. Stores scalar opacity values.
5.  **Spherical Harmonics:** Size $N \times D \times 3$. Stores coefficients for $D$ bands per RGB channel.

**Indexing:**
For a buffer of $N$ splats, the $i$-th splat's attribute starts at index $i \times \text{stride}$.
For Spherical Harmonics, the index for the $c$-th channel ($c \in \{0,1,2\}$) of the $d$-th coefficient ($d \in \{0, \dots, D-1\}$) of the $i$-th splat is:
$$ idx = ((i \times D) + d) \times 3 + c $$
[S1, unofficial][5570-spherical-harmonics-coefficient-layout.md].

**Algorithm:**
The data is populated by iterating over the splat collection and writing components to the respective buffers.

```python
def build_splat_buffers(splats):
    """
    Converts a list of Splat objects into Structure-of-Arrays buffers.
    Assumes splats is a list of objects with methods getX(), getY(), etc.
    """
    N = len(splats)
    D = get_sh_degree() # Number of SH coefficients per channel
    num_sh_coeffs = D * 3
    
    # Allocate buffers
    # Positions: N * 3 floats
    positions = [0.0] * (N * 3)
    # Scales: N * 3 floats (log-space)
    scales = [0.0] * (N * 3)
    # Rotations: N * 4 floats (scalar-last quaternion)
    rotations = [0.0] * (N * 4)
    # Opacities: N floats
    opacities = [0.0] * N
    # SH Coefficients: N * D * 3 floats
    sh_coeffs = [0.0] * (N * num_sh_coeffs)
    
    for i, s in enumerate(splats):
        stride_pos = i * 3
        positions[stride_pos + 0] = float(s.getX())
        positions[stride_pos + 1] = float(s.getY())
        positions[stride_pos + 2] = float(s.getZ())
        
        stride_scale = i * 3
        # Store log-scale for optimization stability
        scales[stride_scale + 0] = float(log(s.getScaleX()))
        scales[stride_scale + 1] = float(log(s.getScaleY()))
        scales[stride_scale + 2] = float(log(s.getScaleZ()))
        
        stride_rot = i * 4
        # Scalar-last order: (x, y, z, w)
        rotations[stride_rot + 0] = float(s.getRotationX())
        rotations[stride_rot + 1] = float(s.getRotationY())
        rotations[stride_rot + 2] = float(s.getRotationZ())
        rotations[stride_rot + 3] = float(s.getRotationW())
        
        opacities[i] = float(s.getOpacity())
        
        stride_sh = i * num_sh_coeffs
        for d in range(D):
            for c in range(3):
                # Index formula: ((i * D) + d) * 3 + c
                idx = stride_sh + (d * 3) + c
                sh_coeffs[idx] = float(s.getSHCoefficient(d, c))
                
    return {
        "positions": positions,
        "scales": scales,
        "rotations": rotations,
        "opacities": opacities,
        "sh_coeffs": sh_coeffs
    }
```

**Edge Cases and Pitfalls:**
*   **Precision:** Scales must be stored in log-space during optimization to prevent negative values, but linear scales ($s_{linear} = \exp(s_{log})$) are required for covariance calculation during rendering [S1, unofficial].
*   **Quaternion Order:** The scalar-last convention $(x, y, z, w)$ must be strictly maintained; mixing with scalar-first $(w, x, y, z)$ will cause rotation artifacts [S1, unofficial].
*   **Buffer Size:** The SH buffer size depends on the degree of spherical harmonics. For degree 3, $D=9$ (or similar depending on implementation), resulting in $N \times 27$ floats.

## Subtopics

### [Splat Data Encoding & Disabled Splat Detection](7028-splat-data-encoding-disabled-splat-detection.md)
Defines the binary encoding scheme for 3D Gaussian splats within the `Gaussian-Splat-Lite` renderer and provides logic to detect "disabled" splats during spatial queries and sorting. It solves the problem of efficiently filtering out inactive or merged Gaussians without allocating separate boolean flags. It embeds the status directly into the data payload's bit pattern, allowing the renderer to treat disabled splats as invalid data (NaN) during coordinate extraction. This builds on [Splat Data Buffer Layout](5568-splat-data-buffer-layout.md).

### Unified Parameter Layout and SSD Blocking
A logical layout for all learnable per-Gaussian attributes stored out-of-core on SSD, organized into contiguous spatial blocks to improve I/O efficiency and spatial locality [S2, unofficial].
*   **Definition:** A unified logical layout $\Theta \in \mathbb{R}^{N \times D}$ for all learnable per-Gaussian attributes, with $D=59$ under standard degree-3 SH parameterization [S2, unofficial].
*   **Step:** Morton-sort Gaussians by the codes of their centers before blocking to ensure spatially nearby Gaussians map to nearby indices and blocks [S2, unofficial].
*   **Formula:** $\text{Block}(k) := \Theta[kB : (k+1)B], \quad k \in \{0, \dots, K-1\}$ where $K = \lceil N/B \rceil$ [S2, unofficial].
*   **Parameter:** Block size $B=4096$. With $D=59$ parameters and fp32 (4 bytes), each block is $4096 \times 59 \times 4 = 964,544$ bytes (236 contiguous 4 KB pages, ~944 KiB) [S2, unofficial].
*   **Pitfall:** Gaussian centers move during training, changing block bounds. The owner block is fixed (no migration/duplication). Bounds are conservatively refreshed, allowing neighboring block bounds to overlap, but each Gaussian remains uniquely owned and rasterized exactly once [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Buffer construction is $O(N \times C)$, where $C$ is the number of components per splat (e.g., $3+3+4+1+3D$).
*   **Memory Complexity:** $O(N \times C \times 4)$ bytes for fp32 storage.
*   **Strengths:** High cache coherency for GPU shaders; simple indexing; supports out-of-core extensions via blocking [S2, unofficial].
*   **Limitations:** Requires managing multiple buffers; log-scale conversion adds minor overhead during read/write if not handled in shaders [S1, unofficial].
*   **When to use:** Standard 3D Gaussian Splatting rendering and optimization.
*   **When not to use:** When strict attribute locality per splat is required (use Array-of-Structures instead, though this is rare in GPU rendering).

## Background
The Structure-of-Arrays layout for Gaussian splats was popularized by the JSplat implementation and subsequent differentiable rendering frameworks [S1, unofficial]. It addresses the performance bottlenecks of Array-of-Structures layouts in GPU fragment shaders, where coalesced memory access is critical. The extension to SSD-based out-of-core storage via Morton sorting was introduced in TideGS to handle billion-scale Gaussian scenes [S2, unofficial].
