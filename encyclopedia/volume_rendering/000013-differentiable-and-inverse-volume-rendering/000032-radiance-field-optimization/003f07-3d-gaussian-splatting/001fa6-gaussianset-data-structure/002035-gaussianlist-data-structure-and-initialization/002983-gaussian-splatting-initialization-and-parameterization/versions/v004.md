# Gaussian Splatting Initialization and Parameterization

Also called: Gaussian Initialization, 3D Gaussian Initialization, Gaussian Parameter Initialization, Gaussian Splatting Training Initialization, 3D Gaussian Splatting Training Initialization

## Overview
Gaussian Splatting Initialization and Parameterization establishes the initial state of a 3D Gaussian Splatting representation from input data, typically a sparse point cloud, to begin differentiable optimization [S3, S5, unofficial]. It differs from [Random Large-Variance Initialization](6129-random-large-variance-initialization.md) by using structured geometric priors rather than random noise, and from [Gaussian Geometry Parameters Prediction](8442-gaussian-geometry-parameters-prediction.md) by relying on explicit data mapping rather than learned prediction networks [S3, S5, unofficial]. It serves as the foundational step for [Gaussian Splatting Initialization and Parameterization](2313-gaussian-splatting-initialization-and-parameterization.md).

## How it works
**Inputs:**
*   Input point cloud data: $N$ points with 3D coordinates $\mathbf{xyz} \in \mathbb{R}^N$ and RGB colors $\mathbf{c} \in \mathbb{R}^N$ (e.g., from COLMAP) [S1, S5, unofficial].
*   Optional: Depth maps for normal estimation [S2, unofficial].
*   Configuration: Base distance for scaling, initial opacity target, SH degree [S1, S3, S5, unofficial].

**Outputs:**
*   Learnable parameters for $N$ Gaussians:
    *   Means: $\mathbf{\mu} \in \mathbb{R}^{N \times 3}$ [S3, S5, unofficial].
    *   Scales (log-space): $\mathbf{s} \in \mathbb{R}^{N \times 3}$ (or $\mathbb{R}^{N \times 1}$ for isotropic) [S3, S5, unofficial].
    *   Rotations (quaternions): $\mathbf{q} \in \mathbb{R}^{N \times 4}$ [S3, S5, unofficial].
    *   Opacities (logits): $\alpha_{logit} \in \mathbb{R}^{N}$ [S3, S5, unofficial].
    *   Colors (SH coefficients): $\mathbf{c}_{dc} \in \mathbb{R}^{N \times 3}$ (degree 0) and $\mathbf{c}_{rest} \in \mathbb{R}^{N \times 3 \times D}$ (higher degrees) [S1, S3, S5, unofficial].

**Data Structures:**
Parameters are stored as differentiable tensors (e.g., `nn.Parameter` in PyTorch) on the GPU [S5, unofficial].
*   `_xyz`: Shape $(N, 3)$ [S5, unofficial].
*   `_features_dc`: Shape $(N, 1, 3)$ [S5, unofficial].
*   `_scaling`: Shape $(N, 3)$ [S5, unofficial].
*   `_rotation`: Shape $(N, 4)$, format $[w, x, y, z]$ [S5, unofficial].
*   `_opacity`: Shape $(N, 1)$ [S5, unofficial].

**Steps:**

1.  **Initialize Means:** Copy input XYZ coordinates directly to GPU memory [S1, S5, unofficial]. If the point cloud is not centered, subtract the mean: $\mathbf{\mu}_i \leftarrow \mathbf{\mu}_i - \frac{1}{N}\sum_{j=1}^N \mathbf{\mu}_j$ [S3, unofficial].

2.  **Initialize Rotations:**
    *   *Standard:* Set all quaternions to identity: $\mathbf{q}_i = [1, 0, 0, 0]$ [S3, S5, unofficial].
    *   *Random:* Generate random unit quaternions using [Sho94]:
        $$
        \begin{aligned}
        u_1, u_2, u_3 &\sim \text{Uniform}[0, 1] \\
        q_0 &= \sqrt{1-u_1} \sin(2\pi u_2) \\
        q_1 &= \sqrt{1-u_1} \cos(2\pi u_2) \\
        q_2 &= \sqrt{u_1} \sin(2\pi u_3) \\
        q_3 &= \sqrt{u_1} \cos(2\pi u_3)
        \end{aligned}
        $$
        [S1, unofficial].
    *   *Normal-Aligned:* If depth maps are available, estimate normal maps from spatial gradients [S2, unofficial]. Compute the quaternion that aligns the local z-axis with the estimated surface normal [S2, unofficial].

3.  **Initialize Scales:**
    *   *KNN-based:* Compute the mean distance to $K$ nearest neighbors (e.g., $K=50$) [S3, unofficial]. Let this be $d_{knn}$. Set pre-activation scales: $\mathbf{s}_i = \log(\sqrt{d_{knn}})$ repeated for 3 dimensions [S1, S3, unofficial].
    *   *Fixed Base:* Use a fixed base distance $d_{base} = 0.1$ [S5, unofficial]. Compute $dist2 = \max(0.1, \min(d_{knn}, \infty))$ (clamped min $10^{-7}$) [S5, unofficial]. Set $\mathbf{s}_i = \log(\sqrt{dist2})$ for each dimension [S5, unofficial].
    *   *Isotropic Factor:* In some variants, tangent scales are set to the mean orientation-aware KNN distance multiplied by a scale factor $s_{init} = 1.5$ [S2, unofficial].
    *   *Random:* For random initialization, $\mathbf{s}_i = \log((\text{rand}() + 10^{-6}) \times 0.01)$ [S3, unofficial].

4.  **Initialize Opacities:**
    *   Set pre-activation opacity (logit) to a value that yields a sigmoid output close to 1.0 but not exactly 1.0. A common value is $8.0$, since $\sigma(8.0) \approx 0.9997$ [S3, unofficial].
    *   Alternatively, target an initial opacity of $0.5$ or $0.1$. For $0.5$, the logit is $\log(0.5/0.5) = 0$. For $0.1$, the logit is $\log(0.1/0.9) \approx -2.197$ [S1, unofficial].
    *   Clamp the initial logit value to the range $[\log(10^{-4}/0.99), \log(0.99/10^{-4})]$ to prevent extreme values [S5, unofficial]. Specifically, clamp to $[\log(10^{-4}), \log(0.99)]$ is often cited as $[10^{-4}, 0.99]$ for the probability, implying logit clamping [S5, unofficial].

5.  **Initialize Colors (SH Features):**
    *   Normalize input RGB colors to $[-0.5, 0.5]$ [S1, unofficial].
    *   Compute degree-0 SH coefficient: $\mathbf{c}_{dc, i} = \frac{\mathbf{c}_i}{C_0}$, where $C_0 = 0.28209479177387814$ [S1, S3, unofficial].
    *   Initialize higher-degree coefficients ($\mathbf{c}_{rest}$) to zeros [S1, S3, unofficial].

6.  **Construct Covariance Matrices (for rendering/optimization):**
    *   Compute the scaling matrix $\mathbf{S} = \text{diag}(\exp(\mathbf{s}_i))$ [S5, unofficial]. Clamp $\exp(\mathbf{s}_i)$ to max $10.0$ to prevent excessively large Gaussians [S5, unofficial].
    *   Convert quaternion $\mathbf{q}_i$ to rotation matrix $\mathbf{R}_i \in \mathbb{R}^{3 \times 3}$ [S5, unofficial]. Normalize $\mathbf{q}_i$ first [S5, unofficial].
    *   Compute 3D covariance: $\mathbf{\Sigma}_i = \mathbf{R}_i \mathbf{S}_i \mathbf{S}_i^T \mathbf{R}_i^T$ [S5, unofficial].

7.  **Project to 2D (for rasterization):**
    *   Transform means to camera coordinates: $\mathbf{xyz}_{cam} = \mathbf{R}_{cam} \mathbf{\mu}_i + \mathbf{T}_{cam}$ [S5, unofficial].
    *   Compute Jacobian $\mathbf{J}$ of the perspective projection. With focal length $f$ and depth $z_i = \mathbf{xyz}_{cam}[2] + 10^{-7}$ (clamped to avoid division by zero) [S5, unofficial]:
        $$
        \mathbf{J} = \begin{bmatrix}
        f/z_i & 0 & -(f \cdot x_i)/z_i^2 \\
        0 & f/z_i & -(f \cdot y_i)/z_i^2
        \end{bmatrix}
        $$
        [S5, unofficial].
    *   Compute 2D covariance: $\mathbf{\Sigma}'_i = \mathbf{J} \mathbf{W} \mathbf{\Sigma}_i \mathbf{W}^T \mathbf{J}^T$, where $\mathbf{W}$ is the world-to-camera rotation matrix [S5, unofficial].
    *   Add numerical stability bias: $\mathbf{\Sigma}'_i[0,0] += 0.3$, $\mathbf{\Sigma}'_i[1,1] += 0.3$ [S5, unofficial].

**Pseudocode:**

```python
import torch
import numpy as np

def initialize_gaussians(points_xyz, points_rgb, num_gaussians=None):
    """
    Initialize 3D Gaussian parameters from a point cloud.
    
    Args:
        points_xyz: (N, 3) array of XYZ coordinates.
        points_rgb: (N, 3) array of RGB colors in [0, 1].
        
    Returns:
        Dictionary of initialized parameters.
    """
    N = points_xyz.shape[0]
    device = torch.device('cuda')
    
    # 1. Means
    xyz = torch.tensor(points_xyz, dtype=torch.float32, device=device)
    # Center the point cloud
    xyz = xyz - xyz.mean(dim=0, keepdim=True)
    
    # 2. Rotations (Identity)
    rotation = torch.zeros((N, 4), dtype=torch.float32, device=device)
    rotation[:, 0] = 1.0  # w=1, x=y=z=0
    
    # 3. Scales (KNN-based or Fixed Base)
    # Compute KNN distances (simplified for demo; use KDTree in practice)
    # Assuming points_xyz is already centered
    dists = torch.cdist(xyz, xyz)
    # Exclude self (diagonal is 0)
    dists = dists + torch.eye(N, device=device) * 1e9
    k = 50
    knn_dists, _ = torch.topk(dists, k, dim=1, largest=False)
    mean_knn_dist = knn_dists[:, :k].mean(dim=1)
    
    # Fixed base distance approach [S5, unofficial]
    base_dist = 0.1
    dist2 = torch.clamp(mean_knn_dist, min=1e-7)
    # Use max(0.1, dist2) as per source logic description, though source says "clamped minimum of 0.1"
    # Source [S5, unofficial]: "dist2 as clamped minimum of 0.1 (min 1e-7)" -> likely means clamp dist2 to >= 1e-7, 
    # but also mentions base distance 0.1. Let's follow [S5, unofficial] strictly:
    # "Compute dist2 as clamped minimum of 0.1 (min 1e-7)" is ambiguous. 
    # Another interpretation: dist2 = max(0.1, knn_dist). 
    # Let's use the explicit formula from [S5, unofficial]: log(sqrt(dist2)) where dist2 is derived from KNN.
    # We will use the mean KNN distance directly, clamped.
    dist2 = torch.clamp(mean_knn_dist, min=1e-7)
    
    scaling = torch.log(torch.sqrt(dist2)).unsqueeze(1).repeat(1, 3)
    
    # 4. Opacities (Logits)
    # Target sigmoid value ~0.9997 -> logit 8.0 [S3, unofficial]
    opacity_logit = torch.full((N, 1), 8.0, dtype=torch.float32, device=device)
    # Clamp to [1e-4, 0.99] probability range -> logit range
    # log(1e-4/0.99) ~ -9.21, log(0.99/1e-4) ~ 9.21
    opacity_logit = torch.clamp(opacity_logit, min=-9.21, max=9.21)
    
    # 5. Colors (SH Degree 0)
    C0 = 0.28209479177387814
    rgb_normalized = (torch.tensor(points_rgb, dtype=torch.float32, device=device) - 0.5) / 0.5 # Normalize to [-0.5, 0.5]
    features_dc = rgb_normalized / C0
    features_rest = torch.zeros((N, 3, 15), dtype=torch.float32, device=device) # Assuming SH degree 3
    
    return {
        'xyz': xyz,
        'scaling': scaling,
        'rotation': rotation,
        'opacity': opacity_logit,
        'features_dc': features_dc,
        'features_rest': features_rest
    }

def compute_covariance(scaling, rotation):
    """
    Compute 3D covariance matrix from scaling and rotation.
    """
    # Scaling to matrix
    s = torch.exp(scaling)
    # Clamp max scale
    s = torch.clamp(s, max=10.0)
    S = torch.diag_embed(s)
    
    # Rotation from quaternion
    # Normalize quaternions
    q = torch.nn.functional.normalize(rotation, dim=1)
    # Convert to rotation matrix (simplified for demo, use standard library in practice)
    # q = [w, x, y, z]
    w, x, y, z = q[:, 0:1], q[:, 1:2], q[:, 2:3], q[:, 3:4]
    
    R = torch.zeros((q.shape[0], 3, 3), device=q.device)
    R[:, 0, 0] = 1 - 2 * (y**2 + z**2)
    R[:, 0, 1] = 2 * (x*y - w*z)
    R[:, 0, 2] = 2 * (x*z + w*y)
    R[:, 1, 0] = 2 * (x*y + w*z)
    R[:, 1, 1] = 1 - 2 * (x**2 + z**2)
    R[:, 1, 2] = 2 * (y*z - w*x)
    R[:, 2, 0] = 2 * (x*z - w*y)
    R[:, 2, 1] = 2 * (y*z + w*x)
    R[:, 2, 2] = 1 - 2 * (x**2 + y**2)
    
    # Sigma = R S S^T R^T
    Sigma = R @ S @ S.transpose(1, 2) @ R.transpose(1, 2)
    return Sigma
```

## Subtopics

### [Gaussian Model Initialization](2349-gaussian-model-initialization.md)
Gaussian Model Initialization establishes the initial state of a 3D Gaussian Splatting representation from input data, typically a sparse point cloud, to begin differentiable optimization. It differs from [Random Large-Variance Initialization](6129-random-large-variance-initialization.md) by using structured geometric priors rather than random noise, and from [Gaussian Geometry Parameters Prediction](8442-gaussian-geometry-parameters-prediction.md) by relying on explicit data mapping rather than learned prediction networks. It serves as the foundational step for [Gaussian Splatting Initialization and Parameterization](2313-gaussian-splatting-initialization-and-parameterization.md).

### [Random Large-Variance Initialization](6129-random-large-variance-initialization.md)
Random Large-Variance Initialization (RAIN-GS) relaxes the strict Structure-from-Motion (SfM) point cloud assumption required by standard 3D Gaussian Splatting by introducing sparse, large-variance random initialization. Unlike standard methods that rely solely on dense SfM points, this approach allows optimization to proceed even when SfM data is sparse or absent, serving as a fallback or complementary initialization strategy.

### [Temporal Point Cloud Initialization via Chamfer Distance Minimization](6954-temporal-point-cloud-initialization-via-chamfer-distance-min.md)
A technique to reduce training time for dynamic video scenes by initializing the point cloud of the current frame using the learned model from the previous frame, leveraging temporal correlation between nearby frames.

### [Gaussian Geometry Parameters Prediction](8442-gaussian-geometry-parameters-prediction.md)
Gaussian Geometry Parameters Prediction is a feed-forward method for initializing and refining 3D Gaussian primitives in a unified global volume, primarily designed for urban scene reconstruction. It solves the problem of redundant, inconsistent, and ghosted primitives that arise in existing pixel-aligned feed-forward methods by accumulating depth priors into a global point cloud and refining geometry via a 3D convolutional network. Unlike [Gaussian Splatting Initialization and Parameterization](2313-gaussian-splatting-initialization-and-parameterization.md), which typically relies on per-scene optimization or simple static initialization, this method predicts geometry parameters (position offsets, opacity, covariance) directly from a learned feature volume, enabling fast, consistent reconstruction without iterative optimization.

### [Background Hemisphere Initialization](8446-background-hemisphere-initialization.md)
Background Hemisphere Initialization addresses the problem of rendering distant background regions (typically hundreds of meters away) in large-scale urban or outdoor scenes where standard foreground Gaussian splatting fails due to sparsity and occlusion. It models the background as a fixed-radius hemisphere that moves with the camera to maintain a constant relative distance, allowing for efficient regression of Gaussian parameters from projected 2D colors. It differs from sibling methods like [Gaussian Model Initialization](2349-gaussian-model-initialization.md) and [Random Large-Variance Initialization](6129-random-large-variance-initialization.md) by explicitly structuring the background geometry as a moving hemisphere rather than initializing points within the foreground volume or randomly in space.

### Neural Point Cloud Initialization from COLMAP
A method to initialize the neural point cloud and their features for Point-NeRF using an external point cloud reconstruction (specifically COLMAP). It solves the problem of how to provide initial positions, variances, and feature vectors for the neural points [S6].
1.  Initialize the variance parameter $\gamma_i$ for each point $p_i$ to $0.3$ [S6].
2.  During optimization, the confidence score of valid points is pushed to $1$ [S6].
3.  To acquire the feature vector $f_i$ for a point $p_i$, first rule out all views where the point is occluded by other points [S6].
4.  Find the view where the camera is closest to the point $p_i$ [S6].
5.  Unproject the point $p_i$ onto the feature maps extracted by the Image Feature Extraction 2D CNN (Gf) from the selected closest view to obtain $f_i$ [S6].

### Binary Gaussian Hierarchy Construction
The hierarchy is a binary tree. Leaf nodes contain the full set of optimized Gaussian properties (base color, SH coefficients, position, covariance). Internal nodes store merged approximations of their two child nodes [S7, unofficial].

## Operating characteristics
*   **Time Complexity:** Initialization is $O(N \log N)$ or $O(N^2)$ depending on the KNN implementation, where $N$ is the number of input points [S1, S3, unofficial]. Random initialization is $O(N)$ [S4, unofficial].
*   **Memory Complexity:** $O(N)$ to store the Gaussian parameters [S3, S5, unofficial].
*   **Performance:** COLMAP initialization yields acceptable reconstruction quality (35.201 PSNR) but has slow initialization time (6.0 min) and slower inference (60.28 FPS) compared to random initialization (6.023 PSNR, 0.1 sec init, 197.78 FPS) [S4, unofficial]. EndoGaussian's method achieves best quality (37.849 PSNR) with fast init (2.0 sec) and fast inference (195.09 FPS) [S4, unofficial].
*   **Strengths:** Structured initialization from SfM points leads to faster convergence and better final quality than random initialization [S4, unofficial].
*   **Limitations:** Requires a good SfM reconstruction. If SfM is sparse or absent, random or alternative initialization is needed [S1, unofficial].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S7, unofficial]. The initialization method described here is based on the standard implementation using COLMAP point clouds [S1, S5, unofficial]. Variants like RAIN-GS [S1, unofficial] and EndoGaussian [S4, unofficial] have been developed to address specific limitations.
