# Background Hemisphere Initialization

Also called: Background Hemisphere Initialization and Optimization, Hemisphere Background Model

## Overview
Background Hemisphere Initialization addresses the problem of rendering distant background regions (typically hundreds of meters away) in large-scale urban or outdoor scenes where standard foreground Gaussian splatting fails due to sparsity and occlusion [S1]. It models the background as a fixed-radius hemisphere that moves with the camera to maintain a constant relative distance, allowing for efficient regression of Gaussian parameters from projected 2D colors [S1]. It differs from sibling methods like [Gaussian Model Initialization](2349-gaussian-model-initialization.md) and [Random Large-Variance Initialization](6129-random-large-variance-initialization.md) by explicitly structuring the background geometry as a moving hemisphere rather than initializing points within the foreground volume or randomly in space [S1].

## How it works
**Inputs:**
- Foreground volume midpoint [S1].
- $K$ reference images with known camera poses [S1].
- A lightweight two-layer MLP $\mathcal{M}_{bg}$ [S1].

**Outputs:**
- A set of background Gaussian primitives $G_{bg}$ [S1].
- For each Gaussian: position (on the hemisphere), color $\mathbf{c}_{bg}$, scale $\mathbf{s}_{bg}$, fixed rotation, and fixed opacity [S1].

**Data Structures:**
- **Background Hemisphere:** A geometric surface defined by a center $\mathbf{c}_{center}$ and radius $r_{bg}$, with points sampled uniformly on its surface [S1].
- **Gaussian Primitives:** Each primitive $i$ stores position $\boldsymbol{\mu}_i$, color $\mathbf{c}_{bg}$, scale $\mathbf{s}_{bg}$, rotation, and opacity [S1].

**Parameters:**
- $r_{bg}$: Fixed radius of the background hemisphere. Value: $100$ meters [S1].
- $K$: Number of reference images used for color projection [S1].

**Steps:**
1. **Hemisphere Placement:** Position the center of the background hemisphere at the midpoint of the foreground volume [S1].
2. **Camera Tracking:** Move the hemisphere along with the vehicle/camera motion such that the relative distance between the hemisphere and the target camera remains fixed [S1].
3. **Point Sampling:** Uniformly sample points over the hemisphere surface [S1].
4. **Color Projection:** Project the sampled 3D points onto the $K$ reference images to retrieve their 2D colors $\{\mathbf{c}_k\}_{k=1}^K$ [S1].
5. **Scale Initialization:** Initialize the base Gaussian scales $\mathbf{s}_{bg}^{init}$ using the K-Nearest Neighbors (KNN) algorithm on the projected points [S1].
6. **Parameter Regression:** Input the projected colors $\{\mathbf{c}_k\}_{k=1}^K$ into the network $\mathcal{M}_{bg}$ to predict color $\mathbf{c}_{bg}$ and scale residual $\Delta \mathbf{s}_{bg}$ [S1].
7. **Final Scale Calculation:** Compute the final scale $\mathbf{s}_{bg}$ by adding the initial scale and the predicted residual [S1].
8. **Fixed Attributes:** Explicitly set the rotation to the unit quaternion $[1, 0, 0, 0]$ and opacity to $1$ [S1]. These parameters are fixed and not optimized by the network [S1].

**Formulas:**
The final scale is computed as:
$$
\mathbf{s}_{bg} = \Delta \mathbf{s}_{bg} + \mathbf{s}_{bg}^{init}
$$
where the scale residual is:
$$
\Delta \mathbf{s}_{bg} = \mathcal{M}_{bg}(\{\mathbf{c}_k\}_{k=1}^K)
$$
The color is directly regressed as:
$$
\mathbf{c}_{bg} = \mathcal{M}_{bg}(\{\mathbf{c}_k\}_{k=1}^K)
$$
Note: In the source, $\mathcal{M}_{bg}$ outputs both color and scale from the same input colors [S1].

**Pseudocode:**
```python
import math

def background_hemisphere_initialization(foreground_midpoint, reference_cameras, K, r_bg=100.0):
    """Initialize background Gaussians using the hemisphere model [S1]."""
    hemisphere_center = foreground_midpoint
    hemisphere_radius = r_bg
    N = 1000  # Number of sampled points [G]

    # 1. Sample Points on Hemisphere
    hemisphere_points = []
    for _ in range(N):
        u1 = math.random.uniform(0, 1)
        u2 = math.random.uniform(0, 1)
        theta = math.acos(1 - u1)
        phi = 2 * math.pi * u2
        x = hemisphere_radius * math.sin(theta) * math.cos(phi)
        y = hemisphere_radius * math.sin(theta) * math.sin(phi)
        z = hemisphere_radius * math.cos(theta)
        hemisphere_points.append((x + hemisphere_center[0], y + hemisphere_center[1], z + hemisphere_center[2]))

    # 2. Project to Reference Images to Get Colors
    all_projected_colors = []
    for point in hemisphere_points:
        colors_k = []
        for k in range(K):
            cam = reference_cameras[k]
            # Standard perspective projection to 2D image coordinates [G]
            u, v = project_3d_to_2d(point, cam.K, cam.R, cam.t)
            colors_k.append(cam.image[v, u])
        all_projected_colors.append(colors_k)

    # 3. Initialize Scales using KNN
    s_bg_init = []
    for i, point in enumerate(hemisphere_points):
        dists = []
        for j, p2 in enumerate(hemisphere_points):
            if i != j:
                dists.append(math.sqrt(sum((a-b)**2 for a, b in zip(point, p2))))
        dists.sort()
        # Base scale from local density (KNN) [G]
        s_bg_init.append(dists[0] if dists else 0.1)

    # 4. Regress Parameters using MLP M_bg
    # M_bg is a lightweight two-layer MLP [S1]
    c_bg = []
    delta_s_bg = []
    for colors_k in all_projected_colors:
        # Two-layer MLP forward pass: Linear -> ReLU -> Linear [G]
        h = relu([sum(w * x for w, x in zip(colors_k, W1[i])) + b1[i] for i in range(len(W1))])
        out = [sum(w * x for w, x in zip(h, W2[i])) + b2[i] for i in range(len(W2))]
        c_bg.append(out[:3])
        delta_s_bg.append(out[3:])

    # 5. Compute Final Scale
    s_bg = [init + res for init, res in zip(s_bg_init, delta_s_bg)]

    # 6. Set Fixed Attributes
    rotation = [1.0, 0.0, 0.0, 0.0]
    opacity = 1.0

    # 7. Construct Gaussians
    background_gaussians = []
    for i in range(N):
        background_gaussians.append({
            'position': hemisphere_points[i],
            'color': c_bg[i],
            'scale': s_bg[i],
            'rotation': rotation,
            'opacity': opacity
        })
    return background_gaussians

def project_3d_to_2d(point, K_mat, R, t):
    # Standard perspective projection [G]
    p_cam = [sum(R[i][j] * point[j] for j in range(3)) + t[i] for i in range(3)]
    p_img = [sum(K_mat[i][j] * p_cam[j] for j in range(3)) for i in range(3)]
    return int(p_img[0] / p_img[2]), int(p_img[1] / p_img[2])

def relu(x):
    return [max(0, v) for v in x]
```

**Edge Cases and Pitfalls:**
- **Occlusion:** Projected points may be occluded in reference images, leading to inaccurate color retrieval [S1]. The source mentions using geometric priors (visibility maps based on depth differences) to mitigate this during training, but the initialization step itself relies directly on the projected colors [S1].
- **Fixed Radius:** The radius $r_{bg}$ is fixed at 100 m [S1].
- **Fixed Rotation/Opacity:** Since rotation and opacity are not learned, the model assumes a specific orientation and full opacity for background Gaussians [S1].

## Subtopics

### Generalizable Background Model
This variant uses the same hemisphere structure but emphasizes generalizability across scenes [S1]. It uniformly samples points over a hemisphere with fixed radius $r_{bg}$ that moves with camera motion [S1]. A lightweight two-layer MLP $\mathcal{M}_{bg}$ learns color $\mathbf{c}_{bg}$ and scale $\mathbf{s}_{bg}$ directly from projected colors $\{\mathbf{c}_k\}_{k=1}^K$ [S1]. Rotation and opacity remain fixed parameters [S1]. The formula is $\mathbf{c}_{bg}, \mathbf{s}_{bg} = \mathcal{M}_{bg}(\{\mathbf{c}_k\}_{k=1}^K)$ [S1].

## Operating characteristics
- **Time Complexity:** Depends on the number of sampled points on the hemisphere and the number of reference images $K$ [S1]. The MLP $\mathcal{M}_{bg}$ is lightweight (two-layer) [S1].
- **Memory Complexity:** Proportional to the number of background Gaussians, which is determined by the resolution of the hemisphere sampling [S1].
- **Performance:** Allows efficient 3DGS rasterization for background rendering while keeping desirable background quality [S1].
- **Strengths:** Handles distant backgrounds (hundreds of meters) effectively; moves with the camera to maintain relative distance; simple to implement [S1].
- **Limitations:** Fixed radius may not adapt to varying scene scales; fixed rotation and opacity limit flexibility; relies on accurate color projection from reference images [S1].
- **When to Use:** Large-scale urban or outdoor scenes with distant backgrounds where foreground Gaussians are sparse or occluded [S1].
- **When Not to Use:** Indoor scenes or scenes with close-range backgrounds where the hemisphere model is inappropriate [S1].

## Background
Originated in EVolSplat: Efficient Volume-based Gaussian Splatting for Urban View Synthesis (2025) [S1]. The method was developed to handle the challenge of reconstructing full images via efficient 3DGS rasterization while maintaining desirable background rendering in urban environments [S1]. It builds on the generalizable hemisphere Gaussian model concept to represent backgrounds that lie hundreds of meters away from the vehicle [S1].
