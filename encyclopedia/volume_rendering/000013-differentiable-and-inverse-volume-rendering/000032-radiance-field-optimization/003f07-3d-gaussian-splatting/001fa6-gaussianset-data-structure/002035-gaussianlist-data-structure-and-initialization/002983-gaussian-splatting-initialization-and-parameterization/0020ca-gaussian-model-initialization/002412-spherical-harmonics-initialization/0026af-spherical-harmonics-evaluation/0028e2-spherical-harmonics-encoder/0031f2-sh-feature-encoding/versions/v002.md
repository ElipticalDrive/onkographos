# SH Feature Encoding

Also called: Spherical Harmonics Feature Encoding

## Overview
SH Feature Encoding is a method for modeling view-dependent effects in neural radiance fields by multiplying each Spherical Harmonics (SH) basis coefficient with a learnable feature vector, rather than using the vanilla scalar SH encoding [S1, S2][S3, unofficial]. It solves the problem of representing directional information (view direction) in a differentiable, basis-function expansion for view-dependent rendering by allowing the magnitude and orientation of the SH response to be modulated by spatially varying features [S1, S2][S3, unofficial]. It differs from vanilla SH encoding [Spherical Harmonics Evaluation](4391-spherical-harmonics-evaluation.md) by introducing learnable per-coefficient feature vectors predicted from the scene's spatial features, and differs from the [SPZ Encoder](6850-spz-encoder.md) by relying on the explicit SH basis expansion rather than a direct parameterization [S1, S2][S3, unofficial].

## How it works
**Inputs:**
1. Rendered feature vector $F_{rendered}$: A feature vector output by the Volume Feature Rendering (VFR) or spatial feature representation at the query point [S1, S2][S3, unofficial].
2. View direction $d$: A 3D vector representing the camera-to-point direction [S1, S2][S3, unofficial].
3. SH degree $L$: The maximum degree of spherical harmonics used [S3, unofficial].

**Outputs:**
1. Final rendered color $C$: A 3D RGB vector [S1, S2][S3, unofficial].

**Data Structures:**
* SH Feature Vector ($f_l^m$): A learnable vector associated with each SH coefficient $(l, m)$, predicted by a spatial MLP from the rendered feature vector [S1, S2][S3, unofficial].
* Bottleneck Feature Vector ($F_{bottleneck}$): A view-independent feature vector, also predicted by the spatial MLP [S2][S3, unofficial].
* Encoding Vector ($E$): The concatenation of all SH feature encodings $e_l^m$ [S1, S2][S3, unofficial].

**Numbered Steps:**
1. Spatial MLP Prediction: Feed the rendered feature vector $F_{rendered}$ into a spatial Multi-Layer Perceptron (MLP) [S1, S2][S3, unofficial]. This MLP outputs two vectors: the SH feature vector $F_{SH}$, which is split into individual feature vectors $f_l^m$ for each SH coefficient $(l, m)$ where $l \in \{0, \dots, L\}$ and $m \in \{-l, \dots, l\}$ [S2][S3, unofficial], and the bottleneck feature vector $F_{bottleneck}$, which is view-independent [S2][S3, unofficial].
2. SH Feature Encoding: For each SH coefficient $(l, m)$, compute the SH feature encoding $e_l^m$ by multiplying the learnable feature vector $f_l^m$ by the SH basis function value $Y_l^m(d)$ for the view direction $d$ [S1, S2][S3, unofficial].
3. Concatenation: Concatenate all resultant SH encodings $e_l^m$ to form a comprehensive encoding vector $E$ [S1, S2][S3, unofficial].
4. Final Concatenation: Concatenate the encoding vector $E$ with the bottleneck feature vector $F_{bottleneck}$ [S1, S2][S3, unofficial].
5. Directional MLP: Feed the concatenated vector into a directional MLP to predict the final rendered color $C$ [S1, S2][S3, unofficial].

**Formulas:**
The core SH feature encoding for coefficient $(l, m)$ is defined as [S1, S2][S3, unofficial]:
$$ e_l^m = f_l^m Y_l^m(d) $$
Where:
* $e_l^m$ is the SH feature encoding vector for degree $l$ and order $m$ [S1, S2][S3, unofficial].
* $f_l^m$ is the learnable SH feature vector for degree $l$ and order $m$ [S1, S2][S3, unofficial].
* $Y_l^m(d)$ is the value of the Spherical Harmonics basis function of degree $l$ and order $m$ evaluated at view direction $d$ [S1, S2][S3, unofficial].
* $d$ is the view direction vector [S1, S2][S3, unofficial].
* $l$ is the degree, $m \in \{-l, -(l-1), \dots, 0, \dots, l-1, l\}$ [S1, S2][S3, unofficial].

The final color is predicted by a directional MLP $M_{dir}$ applied to the concatenated features:
$$ C = M_{dir}(\text{Concat}(E, F_{bottleneck})) $$
Where $E = \{e_l^m \mid 0 \le l \le L, -l \le m \le l\}$ [S1, S2][S3, unofficial].

**Parameters:**
* SH Degree ($L$): The maximum degree of spherical harmonics. Typical values are $L=3$ for NeRF synthetic datasets and $L=7$ for Real-world 360 datasets [S3, unofficial].
* Number of SH Features: The dimension of the learnable feature vectors $f_l^m$ is 4 for NeRF synthetic datasets and 8 for Real-world 360 datasets [S3, unofficial].

**Edge Cases and Pitfalls:**
* Precision: The multiplication of $f_l^m$ (learnable vector) and $Y_l^m(d)$ (scalar) scales the vector element-wise [S1, S2][S3, unofficial].
* Degenerate Input: If the rendered feature vector $F_{rendered}$ is zero or undefined, the spatial MLP output may be degenerate [G].

**Pseudocode:**
```python
import torch
import torch.nn as nn
import math

class SHFeatureEncoding(nn.Module):
    def __init__(self, max_degree: int, feature_dim: int):
        super().__init__()
        self.max_degree = max_degree
        self.feature_dim = feature_dim
        # Total coefficients: sum_{l=0}^{L} (2l+1)
        self.num_coeffs = sum(2 * l + 1 for l in range(max_degree + 1))
        # Learnable SH feature vectors f_l^m
        self.sh_features = nn.Parameter(torch.randn(self.num_coeffs, feature_dim))
        # Spatial MLP: maps rendered feature to [SH features, bottleneck]
        # [G] Input/output dimensions are implementation details not specified in sources.
        self.spatial_mlp = nn.Linear(256, self.num_coeffs * feature_dim + 64)
        # Directional MLP: maps concatenated features to RGB
        self.directional_mlp = nn.Linear(self.num_coeffs * feature_dim + 64, 3)

    def forward(self, rendered_feature: torch.Tensor, view_direction: torch.Tensor) -> torch.Tensor:
        # Step 1: Spatial MLP Prediction
        mlp_out = self.spatial_mlp(rendered_feature)
        sh_features_flat = mlp_out[:, :self.num_coeffs * self.feature_dim]
        bottleneck_feature = mlp_out[:, self.num_coeffs * self.feature_dim:]

        # Reshape to (batch, num_coeffs, feature_dim)
        sh_features = sh_features_flat.view(rendered_feature.size(0), self.num_coeffs, self.feature_dim)

        # Step 2: SH Feature Encoding
        # Compute SH basis values Y_l^m(d) for all coefficients
        sh_basis = self._compute_sh_basis(view_direction) # (batch, num_coeffs)
        # e_l^m = f_l^m * Y_l^m(d)
        sh_encodings = sh_features * sh_basis.unsqueeze(-1)

        # Step 3 & 4: Concatenation
        sh_encodings_flat = sh_encodings.view(rendered_feature.size(0), -1)
        combined = torch.cat([sh_encodings_flat, bottleneck_feature], dim=1)

        # Step 5: Directional MLP
        color = self.directional_mlp(combined)
        return color

    def _compute_sh_basis(self, d: torch.Tensor) -> torch.Tensor:
        # [G] Standard SH evaluation up to max_degree
        batch_size = d.size(0)
        sh_vals = torch.zeros(batch_size, self.num_coeffs, device=d.device)
        idx = 0
        for l in range(self.max_degree + 1):
            for m in range(-l, l + 1):
                sh_vals[:, idx] = self._sh_basis_value(d, l, m)
                idx += 1
        return sh_vals

    def _sh_basis_value(self, d: torch.Tensor, l: int, m: int) -> torch.Tensor:
        # [G] Standard spherical harmonic basis function Y_l^m
        x, y, z = d[:, 0], d[:, 1], d[:, 2]
        r = torch.sqrt(x*x + y*y + z*z)
        theta = torch.acos(z / r)
        phi = torch.atan2(y, x)

        if l == 0 and m == 0:
            return torch.full_like(x, 1.0 / math.sqrt(4 * math.pi))
        elif l == 1 and m == -1:
            return torch.full_like(x, math.sqrt(3 / (4 * math.pi)) * (y / r))
        elif l == 1 and m == 0:
            return torch.full_like(x, math.sqrt(3 / (4 * math.pi)) * (z / r))
        elif l == 1 and m == 1:
            return torch.full_like(x, math.sqrt(3 / (4 * math.pi)) * (x / r))
        # Higher degrees follow standard normalization [G]
        return torch.zeros_like(x)
```

## Subtopics

### Vanilla SH Encoding
Uses scalar SH coefficients directly without learnable feature vectors. Simpler but less flexible for view-dependent effects. Choose when computational resources are limited and view-dependent effects are mild [G]. [Spherical Harmonics Evaluation](4391-spherical-harmonics-evaluation.md)

### SPZ Encoder
A different method for encoding view direction. Choose when a direct parameterization is preferred over basis expansion [G]. [SPZ Encoder](6850-spz-encoder.md)

## Operating characteristics
* Time Complexity: Depends on the number of SH coefficients and the dimension of the feature vectors. The multiplication $f_l^m Y_l^m(d)$ is $O(1)$ per coefficient if $f_l^m$ is a vector of fixed size. The MLPs add linear complexity with respect to their input/output dimensions [G].
* Memory Complexity: Proportional to the number of SH coefficients times the feature vector dimension, plus the MLP parameters [G].
* Measured Performance: On NeRF synthetic dataset, VFR with SH feature encoding achieves similar quality to existing methods in significantly less time (0.97 minutes for 6K steps vs hours for NeRF) [S3, unofficial].
* Scaling: Scales with the number of SH coefficients and the feature vector dimension. Higher SH degrees and feature dimensions increase accuracy but also computational cost [G].
* Strengths: Captures complex view-dependent effects by modulating SH coefficients with learnable features. Efficient training compared to some other methods [G].
* Limitations: Requires learnable parameters for each SH coefficient, increasing memory usage. Performance depends on the capacity of the spatial and directional MLPs [G].
* When to use: When modeling strong view-dependent effects (e.g., specular highlights, reflections) in neural radiance fields [G].
* When not to use: When computational resources are extremely limited and view-dependent effects are negligible [G].

## Background
SH Feature Encoding was introduced in the context of Volume Feature Rendering (VFR) for fast neural radiance field reconstruction [S1, S2][S3, unofficial]. It is a variant of the rendering equation encoding proposed in [9] (referenced in the sources) [S1, S2][S3, unofficial]. The method was developed to improve the modeling of view-dependent effects compared to vanilla SH encoding [S1, S2][S3, unofficial]. The implementation details mention using the NerfAcc library and Multiresolution Hash Grid (MHG) for feature representation [S1, S2][S3, unofficial].
