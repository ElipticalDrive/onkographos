# ECoNGS Optimization and Coding

Also called: ECoNGS (Efficient Compressive Neural Gaussian Splats), Efficient Compressive Neural Gaussian Splats

## Overview
ECoNGS (Efficient Compressive Neural Gaussian Splats) is a scene representation method that transforms time-consuming volume rendering into an efficient process by optimizing neural editable Gaussians and compressing their attributes via neural entropy coding [S1, unofficial]. It solves the problem of large storage and computational costs in volume visualization by extracting multi-view images and point clouds, grouping geometrically similar scenes for joint learning, and compressing anchor attributes to exploit inter-scene redundancy [S1, unofficial]. Unlike standard 3D Gaussian Splatting which stores all attributes explicitly, ECoNGS uses a two-stage optimization process involving anchor attribute optimization and joint context model training, achieving compression with minimal distortion [S1, unofficial].

## How it works
ECoNGS operates on a set of basic scenes, each represented by a collection of 3D Gaussian primitives. The method involves data extraction, two-stage optimization, and entropy coding.

### Inputs and Outputs
**Inputs:**
- Multi-view images and corresponding point clouds for each basic scene [S1, unofficial].
- Hyperparameters: $\lambda_s = 0.001$ (scaling regularization weight), $K=10$ (number of neural editable Gaussians per anchor), learning rates ($0.01$ for anchor feature, opacity, scaling, rotation, TF embeddings; $1\times 10^{-4}$ for palette color), training iterations ($10,000$ per stage), and $\lambda_e$ (trade-off hyperparameter for compression losses) [S1, unofficial].

**Outputs:**
- A compressed binary bitstream of anchor attributes encoded via arithmetic coding [S1, unofficial].
- MLP parameters stored as 32-bit floating-point values [S1, unofficial].
- A complete VolVis scene representation formed by compositing trained basic scenes [S1, unofficial].

### Data Structures
The method relies on the **GaussianSet Data Structure** [Parent], which stores means, orientations, scales, opacities, and spherical harmonics coefficients. ECoNGS introduces:
- **Anchor Points:** A subset of Gaussians whose attributes are optimized and compressed.
- **Neural Editable Gaussians:** Derived from anchor points; $K=10$ editable Gaussians are generated per anchor [S1, unofficial].
- **Context Model:** A lightweight MLP used to estimate probabilities for entropy coding [S1, unofficial].
- **Hash Grids:** Used for inter-scene redundancy; $M_+$ and $M_-$ denote the total numbers of $+1$ and $-1$ values in the hash grids [S1, unofficial].

### Formulas
The 3D Gaussian function is defined as [S1, unofficial]:
$$C(\mathbf{x}) = e^{-\frac{1}{2}(\mathbf{x}-\mathbf{x}^s)^\top \mathbf{\Sigma}^{-1}(\mathbf{x}-\mathbf{x}^s)}$$
where $\mathbf{x}$ is an arbitrary 3D position, $\mathbf{x}^s$ is the position attribute of the Gaussian point, and $\mathbf{\Sigma}$ is the covariance matrix. The covariance matrix $\mathbf{\Sigma}$ is parameterized by a scaling factor $s$ and a quaternion rotation vector $q$ to ensure positive semi-definiteness [S1, unofficial].

Rendering uses EWA volume splatting to transform 3D Gaussians $G(\mathbf{x})$ to 2D Gaussians $G'(\mathbf{x}')$ on the image plane. Pixel color $\mathbf{C}(\mathbf{x}')$ is determined by $\alpha$-blending [S1, unofficial]:
$$\mathbf{C}(\mathbf{x}') = \sum_{i \in N} c_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j), \quad \alpha_i = o_i G_i(\mathbf{x}')$$
where $c$ is modeled by spherical harmonics (SH) parameters, $o_i$ is opacity, and $N$ is the number of depth-sorted layered 2D Gaussians [S1, unofficial].

**Loss Functions:**
Stage 1 loss [S1, unofficial]:
$$L_{\text{stage1}} = L_{\text{rec}} + \lambda_s \sum_{j=1}^{N^s} \text{prod}(\mathbf{s}_j)$$
where $L_{\text{rec}}$ is the image reconstruction loss (L1 + SSIM), $N^s$ is the number of predicted editable Gaussians, $\text{prod}(\cdot)$ is the vector product of scaling factors, and $\lambda_s = 0.001$ [S1, unofficial].

Stage 2 loss [S1, unofficial]:
$$L_{\text{stage2}} = L_{\text{stage1}} + \lambda_e \frac{L_{\text{entropy}} + L_{\text{hash}}}{N^a \times d_A}$$
where $N^a$ is the number of anchors, $d_A$ is the sum of all anchor attribute dimensions, and $\lambda_e$ is the trade-off hyperparameter [S1, unofficial]. $L_{\text{entropy}}$ and $L_{\text{hash}}$ encourage distribution of values within anchor attributes and a more concentrated hash grid, reducing bit consumption [S1, unofficial].

### Numbered Steps
1. **Data Extraction:** Extract multi-view images and corresponding point clouds from different basic scenes [S1, unofficial].
2. **Scene Grouping:** Group geometrically similar scenes for joint learning [S1, unofficial].
3. **Stage 1 Optimization:** Optimize only anchor point attributes and lightweight MLPs for 10,000 iterations using $L_{\text{stage1}}$. Turn off uniform noise for the first 3,000 iterations to stabilize optimization [S1, unofficial].
4. **Stage 2 Optimization:** Update all parameters, including the context model, for the remaining 10,000 iterations using $L_{\text{stage2}}$. Enable uniform noise after 3,000 iterations [S1, unofficial].
5. **Encoding:** Encode the context model first. Then, encode anchor attributes into a binary bitstream using an arithmetic encoder based on probabilities estimated by the context model [S1, unofficial].
6. **Storage:** Store MLP parameters as 32-bit floating-point values [S1, unofficial].
7. **Compositing:** Composite all trained basic scenes to form a complete VolVis scene representation [S1, unofficial].

### Pseudocode
```python
def econgs_optimization_and_coding(scenes, hyperparams):
    """
    ECoNGS Optimization and Coding process.
    scenes: List of basic scenes, each containing multi-view images and point clouds.
    hyperparams: dict containing lambda_s, K, learning_rates, iterations_per_stage, lambda_e.
    """
    # Step 1: Extract and Group
    # Extract multi-view images and point clouds (handled by data loader)
    # Group geometrically similar scenes for joint learning
    grouped_scenes = group_similar_scenes(scenes)
    
    # Initialize anchor attributes and lightweight MLPs
    anchors = initialize_anchors(grouped_scenes)
    context_model = initialize_lightweight_mlp()
    
    # Step 2: Stage 1 Optimization
    optimizer_stage1 = Adam(anchors.parameters() + context_model.parameters(), lr=hyperparams['learning_rates']['anchor'])
    
    for iteration in range(hyperparams['iterations_per_stage']):
        # Turn off uniform noise for first 3,000 iterations
        use_noise = iteration > 3000
        
        # Forward pass: Render scenes using current anchors and context model
        rendered_images = render_scenes(anchors, context_model, use_noise)
        
        # Compute L_rec (L1 + SSIM)
        loss_rec = compute_l1_ssim_loss(rendered_images, ground_truth_images)
        
        # Compute scaling regularization term
        scaling_reg = sum(product(s_j) for s_j in anchors.scales)
        
        # Compute L_stage1
        loss_stage1 = loss_rec + hyperparams['lambda_s'] * scaling_reg
        
        # Backward pass
        optimizer_stage1.zero_grad()
        loss_stage1.backward()
        optimizer_stage1.step()
        
        # Decay learning rate for anchor feature, opacity, scaling, rotation, and TF embeddings
        decay_learning_rates(optimizer_stage1)

    # Step 3: Stage 2 Optimization
    optimizer_stage2 = Adam(anchors.parameters() + context_model.parameters(), lr=hyperparams['learning_rates']['anchor'])
    
    for iteration in range(hyperparams['iterations_per_stage']):
        # Forward pass with noise enabled
        rendered_images = render_scenes(anchors, context_model, use_noise=True)
        
        # Compute L_stage1
        loss_rec = compute_l1_ssim_loss(rendered_images, ground_truth_images)
        scaling_reg = sum(product(s_j) for s_j in anchors.scales)
        loss_stage1 = loss_rec + hyperparams['lambda_s'] * scaling_reg
        
        # Compute L_entropy and L_hash
        loss_entropy = compute_entropy_loss(anchors.attributes)
        loss_hash = compute_hash_loss(anchors.hash_grids)
        
        # Compute L_stage2
        loss_stage2 = loss_stage1 + hyperparams['lambda_e'] * (loss_entropy + loss_hash) / (len(anchors) * anchors.attribute_dimension)
        
        # Backward pass
        optimizer_stage2.zero_grad()
        loss_stage2.backward()
        optimizer_stage2.step()
        
        # Decay learning rates
        decay_learning_rates(optimizer_stage2)

    # Step 4: Encoding
    # Encode context model
    context_model_bitstream = encode_context_model(context_model)
    
    # Encode anchor attributes using arithmetic encoder
    anchor_bitstream = encode_anchor_attributes(anchors, context_model)
    
    # Store MLP parameters as 32-bit floats
    mlp_parameters = anchors.mlp_parameters.astype(np.float32)
    
    return context_model_bitstream, anchor_bitstream, mlp_parameters
```

### Edge Cases and Pitfalls
- **Early Optimization Instability:** Uniform noise in quantization can cause instability. This is handled by turning off noise for the first 3,000 iterations [S1, unofficial].
- **Model Capacity Loss:** Too many overlapping primitives can cause model capacity loss. The scaling regularization term $\lambda_s \sum \text{prod}(\mathbf{s}_j)$ encourages primitives to be small [S1, unofficial].
- **Precision:** MLP parameters are stored as 32-bit floats, which may limit precision compared to higher-precision formats, but is sufficient for the method's goals [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Not explicitly given in the sources. The method involves two stages of optimization, each with 10,000 iterations, and entropy coding [S1, unofficial].
- **Memory Complexity:** Not explicitly given in the sources. The method compresses anchor attributes, reducing storage requirements compared to explicit storage of all Gaussian attributes [S1, unofficial].
- **Measured Performance:** Tested on volume datasets such as Argon, Bubble, Combustion, Ionization, and Tangaroa. For example, the Combustion dataset (multivariate) has 41 basic scenes, 1,920 × 2,880 × 480 resolution, and requires 24.3 GB CPU / 12.4 GB GPU memory [S1, unofficial].
- **Strengths:** Efficient rendering via tile-based rasterization, compression of anchor attributes, joint learning of similar scenes [S1, unofficial].
- **Limitations:** Requires multi-view images and point clouds for initialization, may have reconstruction fidelity trade-offs due to compression [S1, unofficial].
- **When to Use:** Suitable for large-scale volume visualization where storage and computational efficiency are critical [S1, unofficial].
- **When Not to Use:** Not suitable for scenes with high geometric complexity that cannot be grouped effectively, or where high-fidelity reconstruction is paramount over compression [S1, unofficial].

## Background
ECoNGS was introduced in the paper "ECoNGS: Efficient Compressive Neural Gaussian Splats for Volume Visualization" [S1, unofficial]. It builds on 3D Gaussian Splatting (3DGS) [Parent] and extends it to volume visualization by incorporating neural entropy coding and joint learning of similar scenes [S1, unofficial]. The method aims to address the limitations of traditional volume rendering, which is computationally intensive, by leveraging the efficiency of Gaussian splatting and the compression capabilities of neural entropy coding [S1, unofficial].
