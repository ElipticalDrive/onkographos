# Splatv Binary File Format Parser

Also called: .splatv format, SplatvLoader

## Overview
The Splatv Binary File Format Parser loads `.splatv` files, a custom binary container format used by `gsplat.js` to store 3D Gaussian Splatting scene data [S1, unofficial]. It parses a structured binary stream combining a magic header, JSON-encoded camera metadata, and binary splat data chunks into a usable scene graph [S1, unofficial]. It is distinct from the Antimatter15 `.splat` parser [Parent](6902-antimatter15-splat-file-parsing.md) because it handles a multi-chunk container with explicit type markers and embedded JSON metadata, rather than a flat, headerless array of records [G].

## How it works
**Inputs and Outputs:**
- Input: An `ArrayBuffer` representing a `.splatv` file [S1, unofficial].
- Output: A `Scene` object containing a `Splat` instance and camera position/rotation derived from the file's metadata [S1, unofficial].

**Data Structures:**
The file begins with a global header: `[Magic: Int32 (0x674b), Size: Int32]` [S1, unofficial]. This is followed by a sequence of chunks, each laid out as `[Chunk Type: String, Size: Int32, Data: Uint8Array]` [S1, unofficial].

**Numbered Steps:**
1. Read the first 8 bytes as an `Int32Array` and verify the magic number is `0x674b`; if invalid, throw an error [S1, unofficial].
2. Read the 'chunks' chunk: decode the data as UTF-8 JSON and parse it into an array of splat chunk objects [S1, unofficial].
3. If the parsed array length exceeds 1, log a warning and proceed only with the first element `splatChunks[0]` [S1, unofficial].
4. Extract the camera position `[x, y, z]` and a 3x3 rotation matrix from the chunk data [S1, unofficial].
5. Convert the 3x3 rotation matrix to a quaternion and set the scene's camera position and rotation [S1, unofficial].
6. If camera data is missing or invalid (e.g., `cameras` array is empty or falsy), skip updating the camera [S1, unofficial].
7. Read the 'splat' chunk and pass its data buffer along with `texwidth` and `texheight` to the deserialization routine [S1, unofficial].
8. Create the `Splatv` object from the deserialized data and add it to the scene [S1, unofficial].

**Pseudocode:**
```python
def parse_splatv(buffer: ArrayBuffer, texwidth: int, texheight: int) -> Scene:
    int_view = Int32Array(buffer)
    if int_view[0] != 0x674b:
        raise ValueError("Invalid splatv file")
    
    offset = 8
    scene = Scene()
    
    while offset < buffer.byteLength:
        # Read null-terminated chunk type string
        type_end = offset
        while type_end < buffer.byteLength and buffer[type_end] != 0:
            type_end += 1
        chunk_type = TextDecoder("utf-8").decode(Uint8Array(buffer, offset, type_end - offset))
        offset = type_end + 1
        
        # Read chunk size and data
        chunk_size = Int32Array(buffer, offset, 1)[0]
        offset += 4
        data = Uint8Array(buffer, offset, chunk_size)
        offset += chunk_size
        
        if chunk_type == "chunks":
            json_str = TextDecoder("utf-8").decode(data)
            splat_chunks = JSON.parse(json_str)
            
            if len(splat_chunks) > 1:
                print("Splatv file contains more than one chunk, only the first one will be loaded")
            
            chunk_data = splat_chunks[0]
            camera_pos = chunk_data.get("camera_position")
            rot_matrix = chunk_data.get("rotation_matrix")
            
            if camera_pos and rot_matrix:
                quaternion = matrix_to_quaternion(rot_matrix)
                scene.camera.position = camera_pos
                scene.camera.rotation = quaternion
        elif chunk_type == "splat":
            # Standard binary unpacking of splat records [G]
            splatv_obj = deserialize_splat_data(data, texwidth, texheight)
            scene.add(splatv_obj)
            
    return scene

def matrix_to_quaternion(matrix):
    m = matrix
    trace = m[0][0] + m[1][1] + m[2][2]
    if trace > 0:
        s = 0.5 / math.sqrt(trace + 1.0)
        w = 0.25 / s
        x = (m[2][1] - m[1][2]) * s
        y = (m[0][2] - m[2][0]) * s
        z = (m[1][0] - m[0][1]) * s
    elif (m[0][0] > m[1][1]) and (m[0][0] > m[2][2]):
        s = 2.0 * math.sqrt(1.0 + m[0][0] - m[1][1] - m[2][2])
        w = (m[2][1] - m[1][2]) / s
        x = 0.25 * s
        y = (m[0][1] + m[1][0]) / s
        z = (m[0][2] + m[2][0]) / s
    elif m[1][1] > m[2][2]:
        s = 2.0 * math.sqrt(1.0 + m[1][1] - m[0][0] - m[2][2])
        w = (m[0][2] - m[2][0]) / s
        x = (m[0][1] + m[1][0]) / s
        y = 0.25 * s
        z = (m[1][2] + m[2][1]) / s
    else:
        s = 2.0 * math.sqrt(1.0 + m[2][2] - m[0][0] - m[1][1])
        w = (m[1][0] - m[0][1]) / s
        x = (m[0][2] + m[2][0]) / s
        y = (m[1][2] + m[2][1]) / s
        z = 0.25 * s
    return Quaternion(w, x, y, z)
```

**Parameters:**
- Magic Number: `0x674b` (Int32) [S1, unofficial].
- Encoding: UTF-8 for strings and JSON [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Multiple Chunks**: If the "chunks" JSON array contains more than one element, only the first is loaded and a warning is issued [S1, unofficial].
- **Missing Camera Data**: If the camera position or rotation matrix is absent or invalid in the JSON, the camera is not updated [S1, unofficial].
- **Precision**: Standard 32-bit floats are assumed for positions and matrix elements unless specified otherwise by the deserialization routine [G].

## Operating characteristics
- **Time Complexity**: Linear $O(N)$ with respect to the file size, as the entire buffer must be read and parsed [G]. JSON parsing is $O(M)$ where $M$ is the metadata chunk size [G].
- **Memory Complexity**: Linear $O(N)$, as the entire buffer is loaded into memory and the deserialization step creates in-memory scene graph structures [G].
- **Strengths**: Structured format allows for embedded camera poses and flexible chunking [S1, unofficial].
- **Limitations**: Requires loading the entire file into memory; JSON parsing adds overhead for metadata [G].
- **When to use**: When using `gsplat.js` and the scene is saved in the `.splatv` format [S1, unofficial].
- **When not to use**: For very large scenes requiring streaming, or if the format is unsupported by the target renderer [G].

## Background
The `.splatv` format is used by the `gsplat.js` library [S1, unofficial]. It was developed to provide a structured binary format for storing 3D Gaussian Splatting data, including camera metadata, which is not present in the flat Antimatter15 `.splat` format [S1, unofficial]. It is primarily used in web-based 3D Gaussian Splatting viewers [S1, unofficial].
