# INRIA V1 PLY Splat Parsing

Also called: INRIA PLY Parser, INRIAV1PlyParser, INRIAV1PlyParser.parseToUncompressedSplat, PLY Format Parsing (INRIA), PLY Reader, ParseFilePLY, SplatCloud parsing

## Overview
A parser for INRIA-generated `.ply` files containing 3D Gaussian splats, handling variable spherical harmonic (SH) degrees by detecting field counts in the header [S1, S3, unofficial]. It extracts flat arrays of positions, scales, rotations, colors, and opacities, applying inverse transformations for scale exponentiation, opacity sigmoid, and coordinate system conversion [S1, S2, unofficial]. It sets itself apart from generic PLY readers by specifically decoding the activation functions (sigmoid for opacity, exponential for scale) and coordinate permutations (Y-up/Z-up conversions) inherent to the INRIA Gaussian Splatting output format [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A binary or ASCII `.ply` file generated by the INRIA 3D Gaussian Splatting code.
- **Output:** An uncompressed splat structure (array of splats) containing normalized positions, scales, quaternions, RGB colors, opacity, and spherical harmonic coefficients.

**Data Structures:**
The output is typically an array of `Splat` structs. The layout of an uncompressed splat in memory (for degree 2 SH) is:
- `OFFSET_X`, `OFFSET_Y`, `OFFSET_Z`: Position (float32)
- `OFFSET_SCALE0`, `OFFSET_SCALE1`, `OFFSET_SCALE2`: Scales (float32)
- `OFFSET_ROT0` to `OFFSET_ROT3`: Quaternion components (float32)
- `OFFSET_FDC0`, `OFFSET_FDC1`, `OFFSET_FDC2`: Zero-order SH coefficients / RGB (uint8 or float32 depending on internal representation, often mapped to 0-255 range for storage)
- `OFFSET_OPACITY`: Opacity (float32 or uint8)
- `OFFSET_FRC0` to `OFFSET_FRC44`: Higher-order SH coefficients (float32)

**Steps:**

1. **Parse Header and Detect SH Degree:**
   - Read the PLY header.
   - Count lines containing `'f_rest_'`.
   - Determine `shFieldsToReadCount`:
     - If count $\ge 45$, set to 45 (Degree 2).
     - Else if count $\ge 24$, set to 24 (Degree 1).
     - Else if count $\ge 9$, set to 9 (Degree 0).
     - Else 0 [S1, unofficial].
   - Construct the field list: Concatenate `BaseFieldNamesToRead` with remaining SH field names `f_rest_1` through `f_rest_N` where $N = \text{shFieldsToReadCount} - 1$ [S1, unofficial].
   - `BaseFieldNamesToRead`: `['scale_0', 'scale_1', 'scale_2', 'rot_0', 'rot_1', 'rot_2', 'rot_3', 'x', 'y', 'z', 'f_dc_0', 'f_dc_1', 'f_dc_2', 'opacity', 'red', 'green', 'blue', 'f_rest_0']` [S1, unofficial].

2. **Extract Vertex Data:**
   - Identify the vertex element.
   - Check for existence of required properties: `PositionExists` (x,y,z), `OrientationExists` (rot_0..3), `ScaleExists` (scale_0..2), `OpacityExists` (opacity), `ZeroOrderHarmonicsExists` (f_dc_0..2) [S2, unofficial].
   - Extract column data for each property into flat float arrays using a PLY reader (e.g., `reader.extract_properties`) [S2, unofficial].

3. **Process Each Splat ($i$ from 0 to numVertices-1):**

   - **Position:**
     - If `PositionExists`:
       - Transform coordinates: $P_{out} = 100.0 \times (P_{in}.x, -P_{in}.z, -P_{in}.y)$ [S2, unofficial].
       - Assign to `newSplat[OFFSET_X]`, `newSplat[OFFSET_Y]`, `newSplat[OFFSET_Z]` [S1, unofficial].

   - **Scale:**
     - If `ScaleExists`:
       - Apply exponential activation and reorder:
         - $S_x = \exp(\text{vertexData["scale\_0"][i]})$
         - $S_y = \exp(\text{vertexData["scale\_2"][i]})$  // Note: scale_2 maps to Y
         - $S_z = \exp(\text{vertexData["scale\_1"][i]})$  // Note: scale_1 maps to Z
       - Scale by 100: $S_{final} = 100.0 \times (S_x, S_y, S_z)$ [S2, unofficial].
       - Assign to `newSplat[OFFSET_SCALE0]`, `newSplat[OFFSET_SCALE1]`, `newSplat[OFFSET_SCALE2]` [S1, unofficial].
       - *Fallback:* If scale fields missing, set all scales to 0.01 [S1, unofficial].

   - **Rotation (Quaternion):**
     - If `OrientationExists`:
       - Construct quaternion from PLY fields. PLY stores as `(rot_0, rot_1, rot_2, rot_3)`.
       - Interpretation: `rot_0` is W, `rot_1` is X, `rot_2` is Y, `rot_3` is Z [S2, unofficial].
       - Normalize: $Q = \text{normalize}(\text{FQuat}(rot_1, rot_2, rot_3, rot_0))$ [S1, S2, unofficial].
       - Apply coordinate transformation to rotation:
         - $Q_{out} = \text{FQuat}(Q.x, -Q.z, -Q.y, Q.w)$ [S2, unofficial].
       - Assign to `newSplat[OFFSET_ROT0]`..`OFFSET_ROT3` [S1, unofficial].

   - **Opacity:**
     - If `OpacityExists`:
       - Apply sigmoid activation: $\alpha = \frac{1}{1 + e^{-\text{vertexData["opacity"][i]}}}$ [S2, unofficial].
       - Clamp to $[0, 1]$ [S2, unofficial].
       - Assign to `newSplat[OFFSET_OPACITY]` [S1, unofficial].
       - *Note:* Some implementations scale this by 255 for storage [S1, unofficial].

   - **Color / Zero-Order SH:**
     - If `ZeroOrderHarmonicsExists`:
       - Extract `f_dc_0`, `f_dc_1`, `f_dc_2` [S2, unofficial].
       - Convert to RGB using SH constant $C_0 = 0.28209479177387814$:
         - $R = (0.5 + C_0 \times f\_dc\_0) \times 255$
         - $G = (0.5 + C_0 \times f\_dc\_1) \times 255$
         - $B = (0.5 + C_0 \times f\_dc\_2) \times 255$ [S1, unofficial].
       - Clamp RGB to $[0, 255]$ [S1, unofficial].
       - Assign to `newSplat[OFFSET_FDC0]`, `OFFSET_FDC1`, `OFFSET_FDC2` [S1, unofficial].
       - *Fallback:* If `f_dc` missing but `red`, `green`, `blue` exist, use those directly scaled by 255 [S1, unofficial].

   - **Higher-Order Spherical Harmonics:**
     - If `shFieldsToReadCount > 9`:
       - For Degree 1 (indices 9-17): Copy `f_rest_0` to `f_rest_8` to `newSplat[OFFSET_FRC[0..8]]` [S1, unofficial].
       - For Degree 2 (indices 18-44): Copy `f_rest_9` to `f_rest_44` to `newSplat[OFFSET_FRC[9..44]]` [S1, unofficial].
       - *Note:* Some parsers (e.g., SceneView) ignore `f_rest_*` entirely and only support SH0 [S3, unofficial].

4. **Write Output:**
   - Write the processed `newSplat` to the output buffer at offset $i \times \text{outBytesPerSplat}$ [S1, unofficial].

**Pseudocode:**

```python
import math

SH_C0 = 0.28209479177387814

def parse_inria_ply(ply_file):
    # 1. Parse Header
    header = parse_ply_header(ply_file)
    vertex_element = find_element(header, "vertex")
    
    # 2. Detect SH Degree
    f_rest_count = count_header_lines(vertex_element.properties, "f_rest_")
    if f_rest_count >= 45:
        sh_degree = 2
        sh_fields_to_read = 45
    elif f_rest_count >= 24:
        sh_degree = 1
        sh_fields_to_read = 24
    elif f_rest_count >= 9:
        sh_degree = 0
        sh_fields_to_read = 9
    else:
        sh_degree = 0
        sh_fields_to_read = 0
        
    # 3. Extract Data
    # Assuming a helper that extracts columns into arrays
    x = extract_column(vertex_element, "x")
    y = extract_column(vertex_element, "y")
    z = extract_column(vertex_element, "z")
    
    scale_0 = extract_column(vertex_element, "scale_0") if has_prop(vertex_element, "scale_0") else None
    scale_1 = extract_column(vertex_element, "scale_1") if has_prop(vertex_element, "scale_1") else None
    scale_2 = extract_column(vertex_element, "scale_2") if has_prop(vertex_element, "scale_2") else None
    
    rot_0 = extract_column(vertex_element, "rot_0") if has_prop(vertex_element, "rot_0") else None
    rot_1 = extract_column(vertex_element, "rot_1") if has_prop(vertex_element, "rot_1") else None
    rot_2 = extract_column(vertex_element, "rot_2") if has_prop(vertex_element, "rot_2") else None
    rot_3 = extract_column(vertex_element, "rot_3") if has_prop(vertex_element, "rot_3") else None
    
    opacity = extract_column(vertex_element, "opacity") if has_prop(vertex_element, "opacity") else None
    
    f_dc_0 = extract_column(vertex_element, "f_dc_0") if has_prop(vertex_element, "f_dc_0") else None
    f_dc_1 = extract_column(vertex_element, "f_dc_1") if has_prop(vertex_element, "f_dc_1") else None
    f_dc_2 = extract_column(vertex_element, "f_dc_2") if has_prop(vertex_element, "f_dc_2") else None
    
    # Extract SH coefficients if needed
    sh_coeffs = {}
    if sh_fields_to_read > 9:
        for i in range(sh_fields_to_read - 9):
            field_name = f"f_rest_{i}"
            if has_prop(vertex_element, field_name):
                sh_coeffs[i] = extract_column(vertex_element, field_name)
            else:
                sh_coeffs[i] = None # Or handle missing

    num_vertices = len(x)
    splats = []

    for i in range(num_vertices):
        splat = {}
        
        # Position: Transform (x, y, z) -> (x, -z, -y) * 100
        splat['x'] = x[i] * 100.0
        splat['y'] = -z[i] * 100.0
        splat['z'] = -y[i] * 100.0
        
        # Scale: Exp and reorder (scale_0->X, scale_2->Y, scale_1->Z) * 100
        if scale_0 is not None:
            sx = math.exp(scale_0[i])
            sy = math.exp(scale_2[i])
            sz = math.exp(scale_1[i])
            splat['scale_x'] = sx * 100.0
            splat['scale_y'] = sy * 100.0
            splat['scale_z'] = sz * 100.0
        else:
            splat['scale_x'] = 0.01
            splat['scale_y'] = 0.01
            splat['scale_z'] = 0.01
            
        # Rotation: Construct Quat (W,X,Y,Z) from (rot_0, rot_1, rot_2, rot_3), normalize, then transform
        if rot_0 is not None:
            # PLY order: rot_0=W, rot_1=X, rot_2=Y, rot_3=Z
            w, x_q, y_q, z_q = rot_0[i], rot_1[i], rot_2[i], rot_3[i]
            norm = math.sqrt(w*w + x_q*x_q + y_q*y_q + z_q*z_q)
            if norm > 0:
                w, x_q, y_q, z_q = w/norm, x_q/norm, y_q/norm, z_q/norm
            
            # Transform: (X, -Z, -Y, W)
            splat['rot_w'] = w
            splat['rot_x'] = x_q
            splat['rot_y'] = -z_q
            splat['rot_z'] = -y_q
        else:
            splat['rot_w'] = 1.0
            splat['rot_x'] = 0.0
            splat['rot_y'] = 0.0
            splat['rot_z'] = 0.0
            
        # Opacity: Sigmoid
        if opacity is not None:
            alpha = 1.0 / (1.0 + math.exp(-opacity[i]))
            splat['opacity'] = alpha # Or alpha * 255 if storing as uint8
        else:
            splat['opacity'] = 0.0
            
        # Color: SH C0 to RGB
        if f_dc_0 is not None:
            r = (0.5 + SH_C0 * f_dc_0[i]) * 255.0
            g = (0.5 + SH_C0 * f_dc_1[i]) * 255.0
            b = (0.5 + SH_C0 * f_dc_2[i]) * 255.0
            splat['r'] = clamp(math.floor(r), 0, 255)
            splat['g'] = clamp(math.floor(g), 0, 255)
            splat['b'] = clamp(math.floor(b), 0, 255)
        else:
            splat['r'] = 0
            splat['g'] = 0
            splat['b'] = 0
            
        # Higher Order SH
        if sh_degree >= 1:
            for k in range(9):
                idx = k
                if sh_coeffs.get(idx) is not None:
                    splat[f'sh_r_{k}'] = sh_coeffs[idx][i]
                else:
                    splat[f'sh_r_{k}'] = 0.0
        if sh_degree >= 2:
            for k in range(9, 45):
                idx = k
                if sh_coeffs.get(idx) is not None:
                    splat[f'sh_r_{k}'] = sh_coeffs[idx][i]
                else:
                    splat[f'sh_r_{k}'] = 0.0
                    
        splats.append(splat)
        
    return splats

def clamp(value, min_val, max_val):
    return max(min_val, min(value, max_val))
```

**Edge Cases and Pitfalls:**
- **Coordinate Systems:** The INRIA format often uses a different axis convention (e.g., Y-up) compared to the target renderer (e.g., Z-up or Unreal's Y-up with specific handedness). The transformation $(x, y, z) \to (x, -z, -y)$ is critical [S2, unofficial].
- **Scale Exponentiation:** Scales are stored as logarithms. Failing to apply $\exp$ results in incorrect sizes [S2, unofficial].
- **Opacity Sigmoid:** Opacity is stored as a logit. Failing to apply the sigmoid results in incorrect transparency [S2, unofficial].
- **Quaternion Order:** PLY quaternions may be stored as $(W, X, Y, Z)$ or $(X, Y, Z, W)$. The code assumes `rot_0` is W [S2, unofficial].
- **Missing Fields:** Some PLY files may lack higher-order SH coefficients. The parser must handle this gracefully, defaulting to 0 or ignoring them [S1, S3, unofficial].

## Subtopics

### [Standard Splat File Parsing](6828-standard-splat-file-parsing.md)
A method to parse the standard `.splat` file format into an uncompressed splat array, handling the specific binary layout of position, scale, color, and rotation data. Choose this when dealing with the compressed `.splat` format rather than the verbose `.ply` format.

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of splats, as each splat's properties are processed in a single pass.
- **Memory Complexity:** $O(N)$ to store the uncompressed splat arrays. The PLY file itself is read into memory or streamed.
- **Performance:** Parsing is generally fast, dominated by I/O and the linear transformation of data. The exponential and sigmoid operations are computationally inexpensive.
- **Strengths:** Handles variable SH degrees automatically; robust to missing fields; applies necessary activation functions.
- **Limitations:** Specific to INRIA's PLY format; may not be compatible with PLY files from other Gaussian Splatting implementations that use different field names or storage orders [S3, unofficial].

## Background
The INRIA V1 PLY format was introduced with the seminal paper "3D Gaussian Splatting for Real-Time Radiance Field Rendering" by Kerbl et al. [S1, unofficial]. It was designed to store the learned 3D Gaussian parameters (position, covariance, color, opacity) in a human-readable and editable format. The format uses specific field names (`scale_0`, `rot_0`, etc.) and stores parameters in a latent space (log-scale, logit-opacity) to facilitate optimization during training. The parser described here is implemented in various projects to load these files for rendering, such as GaussianSplats3D [S1, unofficial], unreal-splat [S2, unofficial], and SceneView [S3, unofficial].
