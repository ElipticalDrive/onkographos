# Texel Size Adaptation and Primitive Management

Also called: Adaptive Texture Allocation, Primitive Management via Quantile Error

## Overview
This method manages the capacity of 3D Gaussian splats by dynamically adjusting the resolution of their associated texture maps (texel size) and the number of active primitives based on rendering error [S1]. It solves the problem of balancing appearance quality against memory and computational cost by ensuring that high-error regions receive more resources (more texels or more primitives) while low-error regions are simplified [S1]. It differs from sibling methods like [Adaptive Density Control](9188-adaptive-density-control.md) by explicitly linking texture resolution to primitive splitting and by using a quantile-based error threshold to drive these decisions, rather than relying solely on gradient magnitudes or opacity thresholds [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Current set of 3D Gaussian primitives $\mathcal{G}$, current iteration number $iter$, texture resolution threshold $\tau_{tr}$, downscale threshold $\tau_{ds}$, texture size per primitive parameter $t_{2pr}$, and texture variance parameter $\lambda_{texture}$ [S1].
*   **Output:** Updated set of primitives $\mathcal{G}'$ (with potentially split primitives) and updated texture maps for each primitive (with potentially upscaled or downscaled resolutions) [S1].

**Data Structures:**
*   **Primitive:** Contains 3D position, covariance, opacity, spherical harmonics coefficients, and a reference to a texture grid [S1].
*   **Texture Grid:** A 2D array of values representing the texture map for a primitive. The dimensions are defined by $t_{2pr}$, the texture size per primitive [S1].
*   **Error Buffer:** Stores the rendering error $E_i$ for each primitive $i$ [S1].

**Parameters:**
*   $\tau_{tr}$: Texture resolution threshold. Controls the aggressiveness of primitive splitting. Starts at 64 and is progressively reduced to 32 within the first 7,000 iterations [S1].
*   $\tau_{ds}$: Downscale threshold. Controls how easily a texture map is downscaled. A higher value makes downscaling easier, leading to simpler appearance and fewer texels [S1].
*   $\lambda_{texture}$: Controls the variance of the texture maps. Higher values lead to smoother results. A low $\lambda_{texture}$ results in fewer texels per primitive [S1].
*   $t_{2pr}$: Texture size per primitive (in texels). Initialized at 500 iterations to the closest power of two such that the smallest axis is 8 texels wide [S1].
*   Quantile: The top 90% of errors are considered for splitting and upscaling [S1].

**Steps:**
1.  **Periodicity Check:** If $iter \pmod{250} \neq 0$, terminate. The routine runs every 250 iterations until 25,000 iterations [S1].
2.  **Error Computation:** For each primitive $i$, compute the rendering error $E_i$ [S1].
3.  **Quantile Determination:** Determine the error threshold $E_{90}$ corresponding to the 90th percentile of all computed errors $E_i$ [S1].
4.  **Primitive Splitting:** For each primitive $i$:
    *   If the current texture resolution is greater than $\tau_{tr}$ AND $E_i \ge E_{90}$, split the primitive along its overflowing axes [S1].
5.  **Texel Upscaling:** For each primitive $i$:
    *   If $t_{2pr} > 1$ AND $E_i \ge E_{90}$, decrease the texel size (upscale the texture resolution) [S1].
6.  **Texel Downscaling:** For each primitive $i$:
    *   Else if the current error metric $E_d < \tau_{ds}$, increase the texel size (downscale the texture resolution) [S1].
    *   Note: The sources use an `else if` structure in the pseudocode, implying downscaling is considered if the upscaling condition is not met, or potentially as a separate branch depending on implementation details not fully specified. The source pseudocode shows: `if ... then ... end if ... then ... end else if ... then ... end`. This suggests downscaling is checked if the upscaling condition ($t_{2pr} > 1$ and high error) is false [S1].

**Pseudocode:**
```python
def texel_size_adaptation_and_primitive_management(primitives, iteration, tau_tr, tau_ds, t2pr, lambda_texture):
    """
    Adapts texture resolution and primitive count based on error quantiles.
    
    Args:
        primitives: List of primitive objects, each with attributes:
            - error: Current rendering error E_i
            - texture_resolution: Current resolution of the texture map
            - t2pr: Current texture size per primitive
            - split(): Method to split the primitive along overflowing axes
            - upscale_texture(): Method to decrease texel size (increase resolution)
            - downscale_texture(): Method to increase texel size (decrease resolution)
        iteration: Current training iteration number
        tau_tr: Texture resolution threshold for splitting
        tau_ds: Downscale threshold for texture reduction
        t2pr: Texture size per primitive parameter
        lambda_texture: Texture variance control parameter
        
    Returns:
        Updated list of primitives
    """
    # Run every 250 iterations until 25,000 iterations
    if iteration % 250 != 0 or iteration > 25000:
        return primitives
    
    # Compute errors for all primitives
    errors = [p.error for p in primitives]
    
    # Determine the 90th percentile error threshold
    # Note: Sorting errors to find the 90th percentile
    sorted_errors = sorted(errors)
    n = len(sorted_errors)
    # Index for 90th percentile (top 10% means index >= 0.9 * n)
    # "Top 90% of errors" usually means the highest 10% of values.
    # If a value is in the top 10%, it is >= the 90th percentile.
    percentile_index = int(0.9 * n)
    if percentile_index >= n:
        percentile_index = n - 1
    error_threshold = sorted_errors[percentile_index]
    
    updated_primitives = []
    
    for p in primitives:
        # Primitive Splitting
        # Condition: texture resolution > tau_tr AND error in top 90%
        if p.texture_resolution > tau_tr and p.error >= error_threshold:
            p.split()
            # Splitting may create new primitives, but the routine iterates over the original set
            # or the updated set. The source says "iterate over all primitives".
            # Assuming the split happens in-place or the primitive is replaced.
            # For simplicity, we assume p is updated.
        
        # Texel Upscaling
        # Condition: t2pr > 1 AND error in top 90%
        if p.t2pr > 1 and p.error >= error_threshold:
            p.upscale_texture()
        # Else if Downscaling
        # Condition: Ed < tau_ds
        # The source pseudocode uses 'else if', implying this is checked if upscaling didn't happen
        # or as a separate condition. The source text says "Else if Ed < tau_ds".
        # We follow the source pseudocode structure.
        elif p.error < tau_ds: # Assuming Ed is p.error or a derived metric
            p.downscale_texture()
            
        updated_primitives.append(p)
        
    return updated_primitives
```

**Edge Cases and Pitfalls:**
*   **Hyperparameter Interdependence:** Changing $\tau_{tr}$ to encourage more primitives can lead to fewer texels per primitive because each primitive represents a more localized, simpler part of the scene [S1].
*   **Initialization:** Texture grids are initialized with 0 on every channel and start optimizing after 500 iterations [S1]. At 500 iterations, $t_{2pr}$ is set to the closest power of two such that the smallest axis is 8 texels wide [S1].
*   **Implementation Detail:** Upscaling and downscaling are implemented using PyTorch's `interpolate` function with a scale factor of 2 [S1].

## Operating characteristics
*   **Time Complexity:** The routine runs every 250 iterations. The complexity per run is $O(N)$ where $N$ is the number of primitives, as it iterates over all primitives to compute errors and apply updates [S1].
*   **Memory Complexity:** Memory usage is determined by the number of primitives and the total number of texels. For example, on the 'drjohnson' scene, the method uses 293K points and 20.8M texels, resulting in 79.7M parameters and 318MB memory [S1]. On the 'bonsai' scene, it uses 291K points and 9.0M texels, resulting in 44.1M parameters and 176MB memory [S1].
*   **Performance:** On the 'drjohnson' scene, the method achieves 77 FPS [S1]. On the 'bonsai' scene, it achieves 35 FPS [S1].
*   **Strengths:** Automatically adjusts the allocation of model capacity between primitives and texels, converging to good results with different ratios of primitive and texel budgets [S1].
*   **Limitations:** The effectiveness depends on the choice of hyperparameters ($\tau_{tr}$, $\tau_{ds}$, $\lambda_{texture}$) [S1].

## Background
This method was introduced by Panagiotis Papantonakis, Georgios Kopanas, Frédo Durand, and George Drettakis in their work on "Content-Aware Texturing for Gaussian Splatting" [S1]. It is part of a broader effort to improve the efficiency and quality of Gaussian Splatting by managing texture resources [S1].
