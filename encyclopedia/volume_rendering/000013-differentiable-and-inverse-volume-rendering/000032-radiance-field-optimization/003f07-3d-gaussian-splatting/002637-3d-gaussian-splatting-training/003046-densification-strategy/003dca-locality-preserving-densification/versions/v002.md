# Locality-preserving Densification

Also called: Z-ordering for Gaussians

## Overview
Locality-preserving densification addresses the memory layout bottleneck in 3D Gaussian Splatting training, where the addition of new Gaussians to the end of parameter buffers causes spatially close primitives to be stored far apart in memory [S1, unofficial]. This spatial fragmentation leads to uncoalesced memory accesses and increased warp divergence during rasterization [S1, unofficial]. By reordering Gaussians based on their 3D spatial proximity using Z-ordering (Morton order), the method ensures that neighboring Gaussians in space are also adjacent in memory, thereby improving cache efficiency and reducing training time for scenes with high Gaussian counts [S1, unofficial]. It is distinct from score-based or group-based densification strategies by focusing exclusively on the memory layout optimization rather than the geometric distribution or selection criteria of the primitives [S1, unofficial].

## How it works
**Inputs:**
*   The current set of $N$ Gaussians $\mathcal{G} = \{\mathcal{G}_1, \dots, \mathcal{G}_N\}$, where each Gaussian $\mathcal{G}_i$ has a 3D mean position $\mathbf{p}_i \in \mathbb{R}^3$.
*   The current training step $t$.
*   Configuration parameters: `zorderInterval` (frequency of application).

**Outputs:**
*   A permuted set of Gaussians $\mathcal{G}'$ such that the memory layout reflects the Z-order of the 3D positions.

**Data Structures:**
*   **Gaussian Buffer:** A contiguous array of structures containing Gaussian parameters (position, covariance, opacity, color, etc.).
*   **Z-order Key:** A 64-bit integer derived from the 3D position of a Gaussian.

**Steps:**
1.  **Check Trigger:** At the beginning of a training iteration, check if densification is active and if the current step $t$ satisfies the condition:
    $$ t \pmod{\text{zorderInterval}} == 0 $$
    If not, skip this step [S1, unofficial]. The standard value for `zorderInterval` is 5000 iterations [S1, unofficial].

2.  **Compute Z-order Keys:** For each Gaussian $\mathcal{G}_i$ with mean position $\mathbf{p}_i = (x_i, y_i, z_i)$:
    *   Normalize or quantize the coordinates to a fixed integer range (e.g., 21 bits per dimension for a 64-bit key, assuming a bounded scene space) [S1, unofficial]. *Note: The exact quantization range is implementation-dependent but must be consistent across all Gaussians.*
    *   Interleave the bits of the three coordinate integers to form a Morton code $Z_i$. For a coordinate $(x, y, z)$ represented as bit strings $x_{20}\dots x_0$, $y_{20}\dots y_0$, $z_{20}\dots z_0$, the Morton code is:
        $$ Z_i = \sum_{k=0}^{20} (x_{i,k} \cdot 2^{3k} + y_{i,k} \cdot 2^{3k+1} + z_{i,k} \cdot 2^{3k+2}) $$
    *   Store the pair $(Z_i, \text{index}_i)$ in a temporary list.

3.  **Sort:** Sort the list of pairs based on the Z-order key $Z_i$ in ascending order. This can be performed using a standard GPU sort algorithm (e.g., radix sort) [S1, unofficial].

4.  **Reorder Buffer:** Use the sorted indices to permute the Gaussian parameters in the main parameter buffer. Let $\pi$ be the permutation array derived from the sorted list. The new buffer at position $j$ contains the parameters of the Gaussian originally at index $\pi[j]$.

5.  **Update Indices:** Ensure that any auxiliary data structures (e.g., tile lists, neighbor caches) that rely on Gaussian indices are updated to reflect the new positions in the buffer.

**Parameters:**
*   `zorderInterval`: The number of training iterations between Z-ordering applications. Default: 5000 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Atomic Contention:** Z-ordering is effective only when used with a per-Gaussian backward pass. If the original backward pass (which uses numerous atomic operations for gradient accumulation) is used, the reordering can heighten atomic contention, negating the benefits [S1, unofficial].
*   **Small Scene Size:** Repeated Z-ordering can slow down training when the number of Gaussians is small. This is attributed to a massive increase in atomic contention in the alpha blending backward pass, potentially due to false sharing [S1, unofficial].
*   **Quantization Bounds:** The scene space must be bounded and consistently quantized to ensure the Z-order keys accurately reflect spatial locality. Unbounded or poorly scaled coordinates will result in incorrect Morton codes.

**Pseudocode:**
```python
def apply_z_ordering(gaussians, step, zorder_interval=5000):
    """
    Reorders Gaussians in the buffer based on 3D spatial proximity using Z-ordering.
    
    Args:
        gaussians: List of Gaussian objects, each with a 'position' (x, y, z) and 'id'.
        step: Current training step.
        zorder_interval: Frequency of Z-ordering application.
        
    Returns:
        permuted_gaussians: List of Gaussian objects reordered by Z-order.
    """
    # Step 1: Check trigger condition
    if step % zorder_interval != 0:
        return gaussians
    
    # Step 2: Compute Z-order keys
    # Note: Quantization range must be defined based on scene bounds.
    # Assuming a normalized range [0, 1] mapped to 21-bit integers.
    bits_per_dim = 21
    scale = (1 << bits_per_dim) - 1
    
    morton_pairs = []
    for g in gaussians:
        x, y, z = g.position
        # Quantize to integer
        ix = int(x * scale)
        iy = int(y * scale)
        iz = int(z * scale)
        
        # Compute Morton code by interleaving bits
        z_code = interleave_bits(ix, iy, iz, bits_per_dim)
        morton_pairs.append((z_code, g))
    
    # Step 3: Sort by Z-order key
    morton_pairs.sort(key=lambda pair: pair[0])
    
    # Step 4: Extract reordered Gaussians
    permuted_gaussians = [pair[1] for pair in morton_pairs]
    
    return permuted_gaussians

def interleave_bits(x, y, z, bits):
    """
    Interleaves the bits of three integers to form a Morton code.
    """
    result = 0
    for i in range(bits):
        # Extract the i-th bit from x, y, z
        bx = (x >> i) & 1
        by = (y >> i) & 1
        bz = (z >> i) & 1
        
        # Place bits at positions 3i, 3i+1, 3i+2
        result |= (bx << (3 * i))
        result |= (by << (3 * i + 1))
        result |= (bz << (3 * i + 2))
        
    return result
```

## Subtopics

### Z-ordering (Morton Order)
A space-filling curve that maps multi-dimensional data to one dimension while preserving locality. It is chosen here because it allows for efficient sorting and cache-friendly memory access patterns for spatially coherent data [S1, unofficial].

### Per-Gaussian Backward Pass
A gradient computation strategy that avoids atomic operations by accumulating gradients per Gaussian. This is a prerequisite for Locality-preserving Densification to be effective, as it prevents the atomic contention that would otherwise negate the memory layout benefits [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The sorting step dominates the cost. For $N$ Gaussians, sorting takes $O(N \log N)$ or $O(N)$ depending on the sort algorithm (e.g., radix sort is linear). The source reports a computational cost of approximately 4 ms per million Gaussians [S1, unofficial].
*   **Memory Complexity:** $O(N)$ to store the Morton codes and the permutation array.
*   **Performance:** Reduces warp divergence and cache misses, leading to faster training times for scenes with many Gaussians [S1, unofficial]. It is particularly effective when the number of Gaussians is large (e.g., >1M), as memory access coalescing becomes a significant bottleneck [S1, unofficial].
*   **Limitations:**
    *   Ineffective or detrimental for small numbers of Gaussians due to false sharing and atomic contention in the backward pass [S1, unofficial].
    *   Requires a per-Gaussian backward pass; incompatible with the original atomic-based backward pass [S1, unofficial].
    *   Diminishing returns with frequent application; optimal interval is empirically determined to be every 5000 iterations [S1, unofficial].
*   **Comparison:** Load-balanced approaches for Gaussian/tile instances can cause uncoalesced memory accesses that become a bigger bottleneck than warp divergence as primitives increase. Z-ordering specifically targets this memory access pattern [S1, unofficial].

## Background
Locality-preserving densification was introduced in the "Faster-GS" framework, which analyzes and improves Gaussian Splatting optimization [S1, unofficial]. The authors observed that memory layout became a throttling factor during densification, where new Gaussians added to the end of buffers caused spatial fragmentation. The method was developed to address this specific performance bottleneck, complementing other optimizations like fused backward and optimizer passes [S1, unofficial]. It is part of a broader effort to reduce training time and VRAM consumption in 3D Gaussian Splatting, achieving up to 5.2× speedup over the original 3DGS implementation on certain datasets [S1, unofficial].
