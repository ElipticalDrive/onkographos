# GRay Optimization Settings

Also called: GRayLQ, GRayHQ

## Overview
GRay Optimization Settings refer to the specific hyperparameter configurations and algorithmic deviations used in the GRay ray-tracing-based 3D Gaussian Splatting framework [S1]. Unlike standard 3DGS, GRay does not use opacity resets and does not prune Gaussians based on size [S1]. These settings define the trade-off between training speed, final frame rate, and reconstruction quality, primarily through adjustments to alpha thresholds, pruning thresholds, and scale decay rates [S1].

## How it works
The GRay optimization process modifies the standard densification and pruning loop by altering the criteria for Gaussian survival and the management of spherical harmonic (SH) coefficients.

**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $\mathcal{G}$, camera poses, and training images.
*   **Output:** Optimized Gaussian parameters (position, scale, rotation, opacity, SH coefficients).

**Key Algorithmic Deviations:**
1.  **No Opacity Resets:** Unlike 3DGS, GRay does not reset opacities to a low value periodically [S1].
2.  **No Size-Based Pruning:** Unlike 3DGS, GRay does not prune Gaussians based on their projected screen size [S1].
3.  **Alpha Thresholding:** Gaussians with opacity $\alpha$ below a minimum threshold $\alpha_{\min}$ are considered for removal or are clamped [S1].
4.  **Pruning Threshold:** A significance threshold $\mu_{\text{prune}}$ is used to remove Gaussians that contribute minimally to the scene [S1].
5.  **Scale Decay:** A decay factor $\eta_{\text{decay}}$ is applied to Gaussian scales to prevent unbounded growth [S1].
6.  **SH Stepping Laziness:** Spherical Harmonic coefficients are updated less frequently than the geometric parameters to save computation [S1].

**Parameters and Typical Values:**
The base GRay configuration and its variants use the following parameters [S1]:

*   $\alpha_{\min}$: Minimum opacity threshold.
*   $\alpha_{\text{expo}}$: Generalized exponent for opacity handling.
*   $\mu_{\text{prune}}$: Pruning threshold for Gaussian significance.
*   $\eta_{\text{decay}}$: Scale decay factor.
*   $\alpha_{\text{lazy}}$: SH stepping laziness threshold.
*   $\tau_{\min}$: Minimum gradient threshold (used in some variants).

**Pseudocode for Optimization Step:**
The following pseudocode illustrates the core optimization step with GRay-specific settings. It assumes a standard SGD or Adam optimizer loop.

```python
def gray_optimization_step(gaussians, cameras, images, step, config):
    """
    Perform one optimization step for GRay.
    
    Args:
        gaussians: List of Gaussian objects with attributes:
            - position (vec3)
            - scale (vec3)
            - rotation (quat)
            - opacity (float)
            - sh_coeffs (array)
        cameras: List of camera objects.
        images: Ground truth images.
        step: Current optimization step number.
        config: Dictionary containing optimization settings.
    
    Returns:
        Updated gaussians.
    """
    # 1. Render and Compute Loss
    # Render images using ray tracing (not splatting)
    rendered_images = []
    for cam, gt_img in zip(cameras, images):
        # Ray trace through gaussians
        rendered = ray_trace_gaussians(gaussians, cam)
        rendered_images.append(rendered)
    
    loss = compute_loss(rendered_images, images)
    
    # 2. Backpropagation
    # Compute gradients for all parameters
    grads = compute_gradients(loss, gaussians, cameras)
    
    # 3. Update Parameters
    for i, g in enumerate(gaussians):
        # Update position, scale, rotation, opacity using optimizer
        g.position -= config.lr_pos * grads['pos'][i]
        g.scale -= config.lr_scale * grads['scale'][i]
        g.rotation -= config.lr_rot * grads['rot'][i]
        g.opacity -= config.lr_opa * grads['opa'][i]
        
        # Apply scale decay if enabled
        if config.enable_scale_decay:
            g.scale *= config.eta_decay
        
        # 4. SH Coefficient Update (Lazy)
        # Only update SH coefficients if opacity is high enough
        if g.opacity > config.alpha_lazy:
            g.sh_coeffs -= config.lr_sh * grads['sh'][i]
    
    # 5. Pruning
    # Remove gaussians with opacity below alpha_min or significance below mu_prune
    # Note: GRay does NOT prune based on size
    active_gaussians = []
    for g in gaussians:
        if g.opacity >= config.alpha_min and g.significance >= config.mu_prune:
            active_gaussians.append(g)
    
    return active_gaussians
```

**Edge Cases and Pitfalls:**
*   **High Alpha Thresholds:** Setting $\alpha_{\min}$ too high (e.g., 0.03) can lead to catastrophic quality deterioration and failure to converge due to rapid Gaussian expansions [S1].
*   **Disabled DHT:** Disabling the Differentiable Hashing Table (DHT) without adjusting other parameters leads to rapid quality loss [S1].
*   **Resolution:** Experiments for GRayLQ and GRayHQ were conducted at half resolution to manage memory requirements [S1].

## Subtopics

### GRayLQ Preset
A low-quality, high-speed configuration designed for rapid training and high frame rates [S1].
*   **Configuration:** $\alpha_{\min}=0.02$, $\alpha_{\text{expo}}=3$, $\mu_{\text{prune}}=5\times10^{-7}$, $\eta_{\text{decay}}=0.9998$, SH stepping laziness at $\alpha_{\text{lazy}}=12$, iterations=7500 [S1].
*   **Performance:** At half resolution, achieves PSNR 26.23, SSIM 0.839, LPIPS 0.191. Init Time 01:58, Opt Time 00:46, FPS 1051. Init #G 3.27M, Final #G 0.48M [S1]. Trains in under a minute and more than doubles 3DGS's frame rate [S1].

### GRayHQ Preset
A high-quality configuration that approaches 3DGS-DI quality while maintaining ray-tracing benefits [S1].
*   **Configuration:** $\alpha_{\min}=0.001$, $\alpha_{\text{expo}}=1$ (matching 3DGS), $\tau_{\min}=0.001$ (matching 3DGRT), initialization binning disabled, pruning threshold $\mu_{\text{prune}}=10^{-9}$, scale decay disabled entirely [S1].
*   **Performance:** At half resolution, achieves PSNR 27.41, SSIM 0.847, LPIPS 0.154. Init Time 01:58, Opt Time 36:11, FPS 55. Init #G 3.97M, Final #G 3.79M [S1]. Improves quality over GRay and approaches 3DGS-DI without reaching it [S1].

## Operating characteristics
*   **Time Complexity:** GRayLQ trains in under a minute, significantly faster than standard 3DGS [S1]. GRayHQ takes longer (36:11 for optimization) but is still competitive [S1].
*   **Memory Complexity:** Experiments were run at half resolution due to high memory requirements [S1]. Final Gaussian counts are significantly lower than initial counts in GRayLQ (0.48M vs 3.27M) [S1].
*   **Performance:** GRayLQ achieves FPS 1051, more than doubling 3DGS's frame rate [S1]. GRayHQ achieves FPS 55 [S1].
*   **Strengths:** High frame rates, reduced initial Gaussian counts, competitive quality metrics (especially LPIPS) [S1].
*   **Limitations:** Quality can deteriorate rapidly if parameters are not tuned correctly (e.g., high $\alpha_{\min}$) [S1]. Half-resolution experiments may not reflect full-resolution performance [S1].

## Background
GRay is a ray-tracing-based 3D Gaussian Splatting method that aims to combine the quality of ray tracing with the speed of splatting [S1]. The optimization settings described here are derived from experiments comparing GRay to 3DGS and 3DGRT [S1]. The method was introduced in the paper "GRay: Ray Tracing 3D Gaussians Near the Speed of Splats" [S1].
