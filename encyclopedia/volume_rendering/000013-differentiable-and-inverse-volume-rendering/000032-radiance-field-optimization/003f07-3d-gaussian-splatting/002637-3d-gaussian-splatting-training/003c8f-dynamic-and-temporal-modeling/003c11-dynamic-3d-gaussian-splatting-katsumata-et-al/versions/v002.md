# Dynamic 3D Gaussian Splatting (Katsumata et al.)
Also called: Dynamic 3DGS, Fourier-based Dynamic 3DGS, Katsumata et al

## Overview
Dynamic 3D Gaussian Splatting [S2] models dynamic scenes by maintaining static Gaussian attributes (opacity, scale, SH coefficients) while explicitly parameterizing the time-dependent evolution of Gaussian positions and orientations [S1, S2]. It distinguishes itself from implicit deformation methods (e.g., D-NeRF) by using continuous parametric functions—Fourier series for position and linear functions for rotation—ensuring temporal continuity and avoiding overfitting associated with large parameter counts [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians defined at a canonical time (typically $t=0$), consisting of static attributes: center $\mathbf{c}_0$, rotation quaternion $\mathbf{q}_0$, scale $\mathbf{s}$, opacity $\alpha$, and spherical harmonic coefficients $\mathbf{c}_{SH}$. A set of input images with corresponding timestamps $t$.
*   **Output:** Rendered images for arbitrary timestamps $t$ and novel views.

**Data Structures:**
Each Gaussian $i$ stores static attributes and dynamic parameters:
1.  **Static Attributes:** $\mathbf{c}_0 \in \mathbb{R}^3$, $\mathbf{q}_0 \in \mathbb{R}^4$ (normalized), $\mathbf{s} \in \mathbb{R}^3$, $\alpha \in \mathbb{R}$, $\mathbf{c}_{SH}$.
2.  **Dynamic Position Parameters:** Fourier series coefficients for $x, y, z$ components. For order $K$, this requires $2K+1$ coefficients per axis (DC + $K$ sine/cosine pairs). Total: $3(2K+1)$ parameters per Gaussian.
3.  **Dynamic Rotation Parameters:** Linear coefficients for quaternion components. Requires 4 coefficients per axis (intercept and slope). Total: 4 parameters per Gaussian.

**Formulas:**
The position $\mathbf{c}(t)$ and rotation $\mathbf{q}(t)$ at time $t$ are computed as:

$$
\mathbf{c}(t) = \mathbf{c}_0 + \sum_{k=0}^{K} \left( \mathbf{a}_k \cos(k \omega t) + \mathbf{b}_k \sin(k \omega t) \right)
$$

$$
\mathbf{q}(t) = \mathbf{q}_0 + \mathbf{m} t
$$

Where:
*   $\mathbf{c}_0$ is the initial center.
*   $\mathbf{a}_k, \mathbf{b}_k \in \mathbb{R}^3$ are the Fourier coefficients for the $k$-th harmonic.
*   $\omega$ is the base frequency (typically normalized to the time range).
*   $\mathbf{q}_0$ is the initial rotation quaternion.
*   $\mathbf{m} \in \mathbb{R}^4$ is the linear slope vector for the quaternion.
*   Note: $\mathbf{q}(t)$ must be normalized to unit length after computation to remain a valid rotation [S2, G].

**Numbered Steps:**
1.  **Initialization:** Initialize Gaussians using standard 3DGS SfM initialization. Set dynamic parameters ($\mathbf{a}_k, \mathbf{b}_k, \mathbf{m}$) to zero or small random values.
2.  **Time Sampling:** For each training iteration, sample a timestamp $t$ from the available frames.
3.  **Deformation:** Compute $\mathbf{c}(t)$ and $\mathbf{q}(t)$ using the formulas above.
4.  **Rendering:** Render the scene using the deformed Gaussians $\mathbf{c}(t), \mathbf{q}(t)$ and static attributes $\mathbf{s}, \alpha, \mathbf{c}_{SH}$ via standard differentiable rasterization.
5.  **Loss Calculation:** Compute image reconstruction loss (e.g., L1 or LPIPS) and bidirectional optical flow loss between predicted and ground truth frames [S2].
6.  **Optimization:** Update all parameters (static and dynamic) using Adam optimizer. The number of dynamic parameters is independent of the number of time steps [S2].

**Pseudocode:**
```python
def compute_dynamic_gaussian(gaussian, t, K, omega):
    """
    Computes the deformed position and rotation for a Gaussian at time t.
    gaussian: dict containing c0, q0, s, alpha, c_SH, and dynamic params
    t: float, current time
    K: int, Fourier series order
    omega: float, base frequency
    """
    # Position: Fourier Series
    # c(t) = c0 + sum(a_k * cos(k*omega*t) + b_k * sin(k*omega*t))
    pos_delta = np.zeros(3)
    for k in range(1, K + 1):
        phase = k * omega * t
        pos_delta += gaussian['a_k'][k-1] * np.cos(phase) + gaussian['b_k'][k-1] * np.sin(phase)
    # DC term is included in a_0 if 0-indexed, or handled separately. 
    # Assuming a_0 is the DC offset in the coefficient list for k=0..K
    if K >= 0:
        pos_delta += gaussian['a_k'][0] # Assuming a_k[0] is DC offset
    c_t = gaussian['c0'] + pos_delta

    # Rotation: Linear Function
    # q(t) = q0 + m * t
    q_t = gaussian['q0'] + gaussian['m'] * t
    
    # Normalize quaternion to ensure valid rotation [G]
    q_t = q_t / np.linalg.norm(q_t)
    
    return c_t, q_t

def render_dynamic_gaussians(gaussians, t, K, omega, camera):
    """
    Renders the scene at time t.
    """
    deformed_gaussians = []
    for g in gaussians:
        c_t, q_t = compute_dynamic_gaussian(g, t, K, omega)
        # Create a new Gaussian object with deformed pos/rot but static s, alpha, c_SH
        new_g = {
            'c': c_t,
            'q': q_t,
            's': g['s'],
            'alpha': g['alpha'],
            'c_SH': g['c_SH']
        }
        deformed_gaussians.append(new_g)
    
    # Standard 3DGS rasterization
    image = rasterize(deformed_gaussians, camera)
    return image
```

**Parameters:**
*   $K$: Fourier order. Not given in the sources.
*   $\omega$: Base frequency. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Quaternion Normalization:** The linear interpolation of quaternions does not preserve unit length. Normalization is required after each time step [G].
*   **Temporal Continuity:** The use of continuous functions ensures smooth motion, preventing flickering artifacts common in discrete frame-based methods [S2].

## Subtopics

### Gaussian-Flow
Combines Fourier approximation (for violent motion) and polynomial fitting (for smooth motion) in a Dual-Domain Deformation Model (DDDM). It also models color changes over time and uses adaptive timestep scaling. [Gaussian-Flow](7582-on-the-fly-dynamic-nerf-training.md)

## Operating characteristics
*   **Time Complexity:** Rendering is $O(N)$ per pixel, same as static 3DGS, as deformation is a simple function evaluation per Gaussian. Training requires optimizing additional parameters but avoids the heavy MLP inference of implicit methods [S2].
*   **Memory Complexity:** Increases by $O(N \cdot K)$ for Fourier coefficients and $O(N)$ for linear rotation parameters. Independent of the number of time steps [S2].
*   **Strengths:** Fast training, robust to overfitting, ensures temporal continuity, handles periodic motion well [S2].
*   **Limitations:** Assumes motion can be approximated by Fourier/linear functions. May struggle with highly non-periodic or complex deformations compared to implicit methods [S2].
*   **When to use:** Scenes with smooth or periodic motion (e.g., human animation, articulated objects) [S2].

## Background
Proposed by Katsumata et al. [S2], this method addresses the limitations of implicit deformation in 3DGS, which can lead to overfitting due to large parameter counts. It draws inspiration from the observation that human and articulated object motion is often periodic, justifying the use of Fourier series for position [S2]. It builds on the shared principles of canonical space deformation [S1, S2].
