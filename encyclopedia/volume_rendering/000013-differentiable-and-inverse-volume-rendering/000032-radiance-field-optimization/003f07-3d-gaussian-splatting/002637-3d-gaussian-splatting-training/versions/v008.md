# 3D Gaussian Splatting Training

Also called: 3DGS Learning, G Splats

## Overview
3D Gaussian Splatting (3DGS) Training is the iterative optimization process that adjusts the geometric and appearance parameters of a set of 3D Gaussian primitives to minimize the difference between rendered images and ground truth views [S2][S6, unofficial]. It solves the problem of reconstructing high-fidelity, real-time renderable scenes from sparse or dense image collections by replacing implicit neural fields with explicit, differentiable volumetric primitives [S5, unofficial]. Unlike NeRF-based methods which require expensive volume integration and neural network inference, 3DGS training optimizes a static set of ellipsoids using differentiable rasterization, achieving comparable image quality with significantly faster convergence and rendering speeds [S2][S5, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:** A set of $N$ input images $\{I_k\}$ with known camera poses (rotation $R_{cw}$, translation $t_{cw}$, intrinsic matrix $K$) and initial 3D point cloud estimates from Structure-from-Motion (SfM) [S2][S6, unofficial].
*   **Outputs:** A set of optimized 3D Gaussians, each defined by mean position $p_w$, rotation quaternion $q$, scale $s$, spherical harmonic coefficients $h$ (for view-dependent color), and opacity $\alpha$ [S2][S6, unofficial].

**Data Structures**
Each Gaussian $i$ stores:
*   $p_{w,i} \in \mathbb{R}^3$: 3D center position.
*   $q_i \in \mathbb{R}^4$: Unit quaternion for rotation.
*   $s_i \in \mathbb{R}^3$: Scale vector (standard deviations).
*   $h_i$: Spherical harmonic coefficients (typically degree 3, 48 coefficients) [S4, S6, unofficial].
*   $\alpha_i \in \mathbb{R}$: Opacity value.

**Initialization**
1.  **Positions ($p_w$):** Initialized from the sparse point cloud generated by SfM tools like COLMAP [S2][S6, unofficial].
2.  **Scales ($s$):** Initialized uniformly between 0 and 1 [S2].
3.  **Rotations ($q$):** Initialized as unit quaternions (identity rotation) [S2].
4.  **Opacities ($\alpha$):** Initialized to a constant value [S6, unofficial].
5.  **Colors ($h$):** Initialized from the average color of the corresponding SfM point or background color [S2][S4, unofficial].

**Training Loop**
The training proceeds in iterations $i$. In each iteration, a training view is sampled, rendered, and gradients are computed.

1.  **Camera Sampling:** Select a camera $V$ and its ground truth image $\hat{I}$ from the training set. Cameras are typically sampled via round-robin with periodic shuffling [S2][S4, unofficial].
2.  **Rendering:**
    *   Project each 3D Gaussian to 2D screen space using the camera matrix. The 3D covariance $\Sigma$ is transformed to 2D $\Sigma'$ via the Jacobian of the affine approximation of the projection [S6, unofficial].
    *   Rasterize the projected Gaussians to generate the rendered image $I$. This involves alpha blending sorted by depth:
        $$ \gamma_j = \sum_{i \in N} \alpha'_{ij} c_i \tau_{ij}, \quad \tau_{ij} = \prod_{k=1}^{i-1} (1 - \alpha'_{kj}) $$
        where $\gamma_j$ is the color of pixel $j$, $c_i$ is the color of Gaussian $i$, $\alpha'_{ij}$ is the effective opacity, and $\tau_{ij}$ is the transmittance [S6, unofficial].
3.  **Loss Computation:** Compute the loss $\mathcal{L}$ between the rendered image $I$ and ground truth $\hat{I}$:
    $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{D-SSIM} $$
    where $\lambda$ is a weight (typically 0.2) [S2][S6, unofficial].
4.  **Backpropagation:** Compute gradients $\nabla \mathcal{L}$ with respect to all Gaussian parameters ($p_w, q, s, h, \alpha$) using the chain rule [S6, unofficial].
5.  **Optimization Step:** Update parameters using the Adam optimizer [S2].
6.  **Adaptive Density Control:** Periodically (e.g., every 100–500 steps), adjust the number of Gaussians based on optimization metrics [S2]:
    *   **Pruning:** Remove Gaussians with opacity $\alpha < \epsilon$ or those that are too large relative to the screen size [S2].
    *   **Densification:** If the positional gradient magnitude $\|\nabla_{p} \mathcal{L}\|$ exceeds a threshold $\tau_p$:
        *   **Split:** If the Gaussian is large ($\|s\| > \tau_s$), split it into two smaller Gaussians to reduce over-reconstruction [S2].
        *   **Clone:** If the Gaussian is small, clone it to increase density in under-reconstructed areas [S2].

**Pseudocode**

```python
def train_3dgs(input_images, camera_poses, initial_points, config):
    # Initialize Gaussians from SfM points
    gaussians = []
    for point in initial_points:
        g = Gaussian(
            p_w=point.position,
            q=identity_quaternion(),
            s=uniform_random(0, 1),
            h=point.color,
            alpha=0.1 # Initial constant opacity
        )
        gaussians.append(g)
    
    optimizer = Adam(gaussians.parameters(), lr=config.initial_lr)
    
    for step in range(config.num_iterations):
        # 1. Sample Camera
        cam_idx = sample_camera(step, len(camera_poses))
        cam = camera_poses[cam_idx]
        gt_image = input_images[cam_idx]
        
        # 2. Render
        # Project Gaussians to 2D, sort by depth, rasterize
        rendered_image = rasterize(gaussians, cam)
        
        # 3. Compute Loss
        loss = compute_loss(rendered_image, gt_image, config.ssim_weight)
        
        # 4. Backpropagate
        loss.backward()
        
        # 5. Update Parameters
        optimizer.step()
        optimizer.zero_grad()
        
        # 6. Adaptive Density Control (every refine_every steps)
        if step % config.refine_every == 0:
            densify_and_prune(gaussians, config)
            
        # 7. Update Learning Rate / SH Degree
        update_schedulers(optimizer, step, config)

def densify_and_prune(gaussians, config):
    # Compute positional gradients
    grads = compute_positional_gradients(gaussians)
    
    new_gaussians = []
    for g in gaussians:
        # Pruning
        if g.alpha < config.opacity_threshold or is_too_large(g, config):
            continue # Remove Gaussian
            
        # Densification
        if grads[g.id] > config.grad_threshold:
            if is_too_large(g, config):
                # Split: Create two smaller Gaussians
                child1, child2 = split_gaussian(g)
                new_gaussians.append(child1)
                new_gaussians.append(child2)
            else:
                # Clone: Create a copy with slight position perturbation
                clone = clone_gaussian(g)
                new_gaussians.append(clone)
                new_gaussians.append(g) # Keep original
        else:
            new_gaussians.append(g)
            
    gaussians = new_gaussians
    return gaussians
```

## Operating characteristics
*   **Time Complexity:** Training typically requires 15,000–30,000 iterations [S2][S4, unofficial]. Convergence is significantly faster than NeRFs, often completing in under an hour on consumer hardware [S5, unofficial].
*   **Memory Complexity:** Memory usage scales linearly with the number of Gaussians. The default maximum is often set to 5,000,000 Gaussians [S3, S4, unofficial].
*   **Performance:** Achieves real-time rendering speeds (100+ FPS) at 1080p resolution on modern GPUs [S5, unofficial]. Training is ~100x faster than NeRFs [S2].
*   **Strengths:** High visual fidelity, real-time rendering, fast training, explicit scene representation.
*   **Limitations:** Can produce "floaters" or artifacts in unobserved regions; requires careful densification tuning to avoid over-reconstruction; memory intensive for large scenes [S1][S5, unofficial].
*   **Hardware:** Primarily GPU-accelerated (CUDA/Metal). CPU execution is possible but ~100x slower [S3, S4, unofficial].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S2]. It builds on the concept of splatting (projecting 3D primitives to 2D) and differentiable rendering. The method initializes Gaussians from SfM point clouds (e.g., COLMAP) and optimizes them using gradient descent [S2][S6, unofficial]. It has become a standard baseline for novel view synthesis due to its speed and quality [S5, unofficial].
