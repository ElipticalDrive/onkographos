# Edge-Aware Disparity Regularization

Also called: Edge-Aware Depth Regularization, Edge-Preserving Depth Regularization

## Overview
Edge-Aware Disparity Regularization is a geometric constraint used during the training of neural radiance fields to enforce local depth smoothness while preserving sharp depth discontinuities that align with object boundaries in the input imagery [S1, unofficial]. It addresses the issue of noisy or inconsistent depth maps generated by NeRF by weighting the disparity gradient penalty with the intensity gradients of the input image, ensuring that depth edges are not smoothed out where color edges exist [S1, unofficial]. This method builds on [Depth Regularization](7616-depth-regularization.md) by introducing image-guided weighting to the smoothness prior.

## How it works
The method computes a differentiable auxiliary loss term $\mathcal{L}_{reg}$ that is added to the total training loss. The core mechanism involves calculating the gradients of the rendered inverse depth map and weighting them by the exponential of the negative gradients of the input color image.

**Inputs and Outputs:**
*   **Input:** Rendered inverse depth map $D_i$ for a specific view $i$, and the corresponding input color image $I_i$.
*   **Output:** Scalar regularization loss $\mathcal{L}_{reg}$.

**Data Structures:**
*   $D_i$: A 2D tensor representing the inverse depth (disparity) for each pixel in the rendered view.
*   $I_i$: A 2D tensor (or 3D with channels) representing the input RGB image.
*   $D^*_i$: A 2D tensor representing the mean-normalized inverse depth.

**Steps:**
1.  **Compute Mean Normalized Inverse Depth:** Calculate the mean of the rendered inverse depth map $\bar{D}_i$ and normalize the map to discourage depth shrinking [S1, unofficial]:
    $$ D^*_i = \frac{D_i}{\bar{D}_i} $$
    where $\bar{D}_i = \frac{1}{N} \sum_{p} D_i(p)$ and $N$ is the number of pixels.
2.  **Compute Image Gradients:** Calculate the horizontal ($\partial_x I_i$) and vertical ($\partial_y I_i$) gradients of the input image. These are typically computed using Sobel filters or finite differences on the grayscale or luminance channel of $I_i$.
3.  **Compute Depth Gradients:** Calculate the horizontal ($\partial_x D^*_i$) and vertical ($\partial_y D^*_i$) gradients of the mean-normalized inverse depth map.
4.  **Compute Edge-Aware Loss:** Combine the depth gradients and image gradients using the following formula [S1, unofficial]:
    $$ \mathcal{L}_{reg} = |\partial_x D^*_i| e^{-|\partial_x I_i|} + |\partial_y D^*_i| e^{-|\partial_y I_i|} $$
    The term $e^{-|\partial I|}$ acts as a weight: where image gradients are high (edges), the penalty on depth gradients is low, allowing depth discontinuities. Where image gradients are low (smooth regions), the penalty is high, enforcing depth smoothness.

**Pseudocode:**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
def edge_aware_disparity_regularization(rendered_depth: Tensor, input_image: Tensor) -> Tensor:
    """
    Computes the edge-aware disparity regularization loss.
    
    Args:
        rendered_depth: 2D Tensor of shape (H, W) representing inverse depth D_i.
        input_image: 2D Tensor of shape (H, W) representing grayscale intensity I_i.
        
    Returns:
        Scalar Tensor representing the regularization loss L_reg.
    """
    # Step 1: Mean-normalized inverse depth
    mean_depth = torch.mean(rendered_depth)
    # Guard against division by zero
    if mean_depth < 1e-8:
        mean_depth = 1e-8
    normalized_depth = rendered_depth / mean_depth
    
    # Step 2: Compute gradients using Sobel operators
    # Sobel kernel for x direction
    sobel_x = torch.tensor([[-1, 0, 1], [-2, 0, 2], [-1, 0, 1]], dtype=torch.float32)
    # Sobel kernel for y direction
    sobel_y = torch.tensor([[-1, -2, -1], [0, 0, 0], [1, 2, 1]], dtype=torch.float32)
    
    # Apply convolution (padding='same' to keep dimensions)
    # Note: In practice, use torch.nn.functional.conv2d with appropriate padding
    depth_grad_x = torch.nn.functional.conv2d(normalized_depth.unsqueeze(0).unsqueeze(0), 
                                              sobel_x.unsqueeze(0).unsqueeze(0), padding=1).squeeze()
    depth_grad_y = torch.nn.functional.conv2d(normalized_depth.unsqueeze(0).unsqueeze(0), 
                                              sobel_y.unsqueeze(0).unsqueeze(0), padding=1).squeeze()
    
    image_grad_x = torch.nn.functional.conv2d(input_image.unsqueeze(0).unsqueeze(0), 
                                              sobel_x.unsqueeze(0).unsqueeze(0), padding=1).squeeze()
    image_grad_y = torch.nn.functional.conv2d(input_image.unsqueeze(0).unsqueeze(0), 
                                              sobel_y.unsqueeze(0).unsqueeze(0), padding=1).squeeze()
    
    # Step 3: Compute absolute gradients
    abs_depth_grad_x = torch.abs(depth_grad_x)
    abs_depth_grad_y = torch.abs(depth_grad_y)
    abs_image_grad_x = torch.abs(image_grad_x)
    abs_image_grad_y = torch.abs(image_grad_y)
    
    # Step 4: Compute edge-aware weights and loss
    # Weight is exp(-|gradient|)
    weight_x = torch.exp(-abs_image_grad_x)
    weight_y = torch.exp(-abs_image_grad_y)
    
    loss_x = abs_depth_grad_x * weight_x
    loss_y = abs_depth_grad_y * weight_y
    
    # Sum over all pixels to get scalar loss
    loss = torch.sum(loss_x + loss_y)
    
    return loss
```

**Parameters:**
*   $\lambda_{reg}$: The scalar weight for the regularization term in the total loss. Not given in the sources.
*   Gradient Kernel: Sobel filters are implied by the gradient notation $\partial_x, \partial_y$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Zero Mean Depth:** If the rendered depth map has a mean of zero, normalization fails. A small epsilon guard is required [G].
*   **Gradient Computation:** The gradients must be computed on the same spatial resolution as the depth map.
*   **Intensity vs. Color:** The formula uses $I_i$, which implies a single-channel intensity representation. If using RGB, the image gradient should be computed on the luminance channel or the magnitude of the RGB gradient vector [G].

## Subtopics

### Geometric Regularization
A regularization method proposed in DGNR to smooth the depth of unobserved viewpoints and alleviate density holes caused by sparsely observed viewpoints [S2]. It is inspired by the piece-wise smoothing characteristics of real-world geometry [S2]. Unlike Edge-Aware Disparity Regularization which uses image gradients for weighting, this method computes a simple squared difference loss between neighboring pixels in patches of size $S_{patch}$ [S2]. It is chosen when dealing with large driving scenes or sparse viewpoints where unobserved regions lead to density holes [S2]. The loss is defined as:
$$ \mathcal{L}_D(\theta, R_r) = \sum_{r \in R_r} \sum_{i,j=1}^{S_{patch}-1} \left[ (\hat{D}_\theta(r_{ij}) - \hat{D}_\theta(r_{i+1,j}))^2 + (\hat{D}_\theta(r_{ij}) - \hat{D}_\theta(r_{i,j+1}))^2 + (\hat{D}_\theta(r_{ij}) - \hat{D}_\theta(r_{i+1,j+1}))^2 \right] $$
where $R_r$ is a set of input rays, $r_{ij}$ denotes a ray passing through pixel $(i,j)$ in a patch, and $\hat{D}_\theta$ is the expected depth [S2]. The total loss combines this with MSE: $\mathcal{L}(\theta, R_r) = \mathcal{L}_{MSE}(\theta, R_r) + \lambda \mathcal{L}_D(\theta, R_r)$ [S2].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels in the rendered view, as it involves computing gradients and element-wise operations [S1, unofficial].
*   **Memory Complexity:** Requires storing the rendered depth map and input image, plus temporary buffers for gradients [S1, unofficial].
*   **Strengths:** Effectively preserves sharp depth boundaries (occlusions) while smoothing noisy depth in textureless or uniform regions [S1, unofficial]. It leverages existing input image data, requiring no additional geometric priors [S1, unofficial].
*   **Limitations:** Relies on the quality of the input image gradients; if the image is noisy, the edge-aware weighting may be unreliable [G]. It does not address unobserved viewpoints as effectively as patch-based smoothing methods like Geometric Regularization [S2].
*   **When to use:** When training NeRFs on scenes with clear object boundaries and where depth consistency is critical for novel view synthesis [S1, unofficial].
*   **When not to use:** When the input images are very noisy or lack distinct edges, or when dealing with sparse viewpoints leading to large unobserved regions where patch-based smoothing is more appropriate [S2].

## Background
The method was introduced in the context of GeCoNeRF (Geometric Consistency NeRF) [S1, unofficial]. It draws inspiration from Godard et al. (2017), who proposed using image gradients to weight depth smoothness losses in monocular depth estimation [S1, unofficial]. The approach was adapted for NeRF training to improve the quality of rendered depth maps, which in turn facilitates optimization and consistency modeling for unobserved views [S1, unofficial].
