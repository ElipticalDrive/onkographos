# Compact 3D Gaussian Representation (C3DGS)

## Overview
Compact 3D Gaussian Representation (C3DGS) is a method that reduces the memory footprint and storage requirements of 3D Gaussian Splatting (3DGS) by eliminating redundant primitives and compressing geometric and color attributes using spatial redundancy [S1]. It sets itself apart from standard 3DGS by replacing per-Gaussian attribute storage with a hash-based neural field for colors and a codebook for geometry, achieving over 25x compression while maintaining or improving reconstruction quality [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $\{G_i\}$ generated by the standard 3DGS densification process (cloning and splitting), where each Gaussian $G_i$ has position $\mathbf{p}_i$, opacity $\alpha_i$, scale $\mathbf{s}_i$, rotation $\mathbf{q}_i$, and spherical harmonic coefficients $\mathbf{c}_i$ [S1].
*   **Output:** A compact scene representation consisting of:
    1.  A reduced set of active Gaussian indices.
    2.  A hash-based grid neural field storing color features.
    3.  A codebook storing geometric primitives (scale/rotation).
    4.  Per-Gaussian indices pointing to the grid and codebook.

**Data Structures:**
1.  **Active Gaussian List:** Stores only the position $\mathbf{p}_i$, opacity $\alpha_i$, and the indices for color and geometry lookup.
2.  **Hash Grid (Instant NGP):** A multi-resolution hash table mapping 3D coordinates to feature vectors. Used to predict view-dependent color [S1].
3.  **Geometry Codebook:** A fixed-size table of learned geometric primitives (scale and rotation vectors). Each Gaussian stores an integer index pointing to a codebook entry [S1].

**Numbered Steps:**

1.  **Volume-Based Masking (Pruning):**
    *   During training, evaluate the contribution of each Gaussian to the rendered image.
    *   Identify "non-essential" Gaussians that have minimal impact on overall performance (e.g., low opacity, high redundancy with neighbors) [S1].
    *   Apply a learnable mask to remove these Gaussians from the active set, reducing the total count $N$ [S1].

2.  **Color Compression via Hash Grid:**
    *   Replace the per-Gaussian spherical harmonic coefficients $\mathbf{c}_i$ with a query to the hash grid [S1].
    *   For a Gaussian at position $\mathbf{p}_i$ and viewing direction $\mathbf{v}$, query the hash grid to retrieve a feature vector.
    *   Decode the feature vector to obtain the color $\mathbf{C}_i(\mathbf{v})$ [S1].
    *   The hash grid uses the Instant NGP structure for compactness and fast processing [S1].

3.  **Geometry Compression via Codebook:**
    *   Cluster the scale $\mathbf{s}_i$ and rotation $\mathbf{q}_i$ attributes of the remaining Gaussians into a small codebook of size $K$ [S1].
    *   For each Gaussian $i$, store only the codebook index $k_i$ such that the geometry is approximated by the codebook entry $E_{geo}[k_i]$ [S1].
    *   The codebook is learned during training to capture shared geometric patterns [S1].

4.  **Rendering:**
    *   For each pixel, rasterize the active Gaussians.
    *   Retrieve color from the hash grid using the Gaussian's position and view direction.
    *   Retrieve geometry (scale/rotation) from the codebook using the stored index.
    *   Perform standard differentiable splatting [S1].

**Formulas:**
*   **Color Retrieval:** $\mathbf{C}_i(\mathbf{v}) = \text{Decode}(\text{HashGrid}(\mathbf{p}_i, \mathbf{v}))$ [S1].
*   **Geometry Retrieval:** $\mathbf{G}_i = E_{geo}[k_i]$, where $k_i = \text{argmin}_{k} \| \mathbf{G}_i^{original} - E_{geo}[k] \|^2$ (learned via codebook training) [S1].

**Parameters:**
*   **Hash Grid Resolution:** Not given in the sources.
*   **Codebook Size ($K$):** Not given in the sources, but described as "quite small" [S1].
*   **Masking Threshold:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Precision:** The hash grid and codebook introduce approximation errors. Quantization and entropy coding are recommended post-processing steps to further reduce size, potentially at the cost of slight quality loss [S1].
*   **Boundaries:** The hash grid must handle out-of-bounds queries gracefully.
*   **Degenerate Input:** If the codebook size is too small, geometric fidelity may suffer. If the mask is too aggressive, scene detail may be lost [S1].

## Operating characteristics
*   **Time Complexity:** Rendering speed is linearly proportional to the number of active Gaussians. C3DGS reduces the number of Gaussians and simplifies attribute lookup, leading to nearly 40% faster rendering on the Deep Blending dataset compared to 3DGS [S1].
*   **Memory Complexity:** Storage is reduced by over 15x generally, and up to 28x on the Deep Blending dataset, with post-processing achieving over 25x compression [S1].
*   **Strengths:** Significant reduction in memory and storage without sacrificing quality; faster rendering; exploits spatial redundancy in color and geometry [S1].
*   **Limitations:** Requires additional learnable components (hash grid, codebook) which may increase training complexity; approximation errors from compression [S1].
*   **When to use:** When memory and storage are critical constraints, and real-time rendering speed is desired.
*   **When not to use:** When maximum geometric fidelity is required without any approximation, or when training resources are extremely limited for the additional learnable structures [S1].

## Background
C3DGS was proposed to address the critical memory and storage issues in 3D Gaussian Splatting, which often require >1GB for large real-world scenes [S1]. It builds on the observation that standard densification produces redundant Gaussians and that spatial redundancy in color and geometry is underutilized [S1]. The method uses Instant NGP for the hash grid [S1].
