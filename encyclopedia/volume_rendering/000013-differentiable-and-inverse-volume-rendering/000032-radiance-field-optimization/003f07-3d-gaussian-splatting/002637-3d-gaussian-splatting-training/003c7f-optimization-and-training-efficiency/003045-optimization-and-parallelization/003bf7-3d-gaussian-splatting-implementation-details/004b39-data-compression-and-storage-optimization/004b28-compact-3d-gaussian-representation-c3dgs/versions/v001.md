# Compact 3D Gaussian Representation (C3DGS)

## Overview
C3DGS is a method that reduces the memory footprint and storage requirements of 3D Gaussian Splatting by eliminating redundant Gaussian primitives and compressing their attributes using spatial redundancy [S1]. It sets itself apart from standard 3DGS by replacing per-Gaussian attribute storage with a shared hash-based grid for view-dependent colors and a discrete codebook for geometric attributes (scale and rotation), achieving over 25x compression while maintaining or improving reconstruction quality [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $\{G_i\}$ generated by the standard 3DGS densification process (cloning and splitting), along with training images and camera poses.
*   **Output:** A compact scene representation consisting of:
    1.  A reduced set of active Gaussian centers $\{c_i\}$ and opacities $\{\alpha_i\}$.
    2.  A hash-based neural grid storing view-dependent color features.
    3.  A codebook storing geometric primitives (scale and rotation vectors).
    4.  For each active Gaussian, an index pointing to the codebook entry and coordinates for grid lookup.

**Data Structures:**
1.  **Active Gaussians:**
    *   `centers`: 3D coordinates $(x, y, z)$.
    *   `opacities`: Scalar $\alpha \in [0, 1]$.
    *   `color_idx`: Integer index into the Codebook.
    *   `grid_coords`: Coordinates used to query the Hash Grid.
2.  **Hash Grid (Instant NGP style):**
    *   A multi-resolution hash table mapping 3D coordinates to feature vectors.
    *   Features are concatenated and passed through a small MLP to predict spherical harmonic coefficients for view-dependent color.
    *   *Note:* The specific hash function and resolution levels follow the Instant NGP implementation [S1].
3.  **Codebook:**
    *   A list of $K$ geometric primitives.
    *   Each primitive stores a scale vector $\mathbf{s} \in \mathbb{R}^3$ and a rotation quaternion $\mathbf{q} \in \mathbb{R}^4$ (or rotation matrix).
    *   Size $K$ is a hyperparameter, typically small relative to the number of Gaussians.

**Numbered Steps:**

1.  **Initialization:** Initialize Gaussians using standard 3DGS densification.
2.  **Volume-Based Masking (Reduction):**
    *   During training, evaluate the contribution of each Gaussian to the rendered image.
    *   Identify "non-essential" Gaussians that have minimal impact on reconstruction quality (e.g., low opacity, redundant coverage).
    *   Apply a learnable mask or threshold to prune these Gaussians. This reduces the total count $N$ significantly [S1].
    *   *Pitfall:* Aggressive pruning too early may degrade fine details. The mask is learned jointly with other parameters [S1].
3.  **Geometric Compression (Codebook):**
    *   Cluster the scale and rotation attributes of the remaining Gaussians.
    *   Train a codebook of size $K$ to represent the dominant geometric patterns.
    *   Replace the explicit $\mathbf{s}_i$ and $\mathbf{q}_i$ for each Gaussian $i$ with a single integer index $k_i$ pointing to the $k_i$-th entry in the codebook.
    *   The codebook entries are optimized during training [S1].
4.  **Color Compression (Hash Grid):**
    *   Replace per-Gaussian spherical harmonic coefficients with a query to the Hash Grid.
    *   For a Gaussian at center $\mathbf{c}_i$, query the grid at $\mathbf{c}_i$ to retrieve a feature vector.
    *   The feature vector is processed (e.g., via a small MLP) to generate view-dependent color coefficients.
    *   This exploits spatial redundancy: neighboring Gaussians query similar grid regions, sharing color information [S1].
5.  **Rendering:**
    *   Standard 3DGS rasterization pipeline.
    *   For each Gaussian, retrieve scale/rotation from the Codebook using $k_i$.
    *   Retrieve color features from the Hash Grid using $\mathbf{c}_i$.
    *   Compute projected covariance and color, then splat to screen [S1].

**Pseudocode:**

        rendered_images.append(img_render)
        
    # 3. Loss Calculation
    loss = compute_loss(rendered_images, images)

    # Gradients flow into:

    loss.backward()

**Parameters:**
*   **Codebook Size ($K$):** Not given in the sources. Must be chosen to balance compression ratio and geometric fidelity.
*   **Hash Grid Resolution:** Not given in the sources. Follows Instant NGP defaults for compactness [S1].
*   **Pruning Threshold:** Not given in the sources. Controls the aggressiveness of Gaussian reduction [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** Quantization of codebook entries and hash grid features may introduce artifacts. Post-processing with entropy coding can mitigate this [S1].
*   **Boundaries:** Hash grid queries at scene boundaries may require padding or specific handling to avoid out-of-bounds access [G].
*   **Degenerate Input:** If pruning removes too many Gaussians, fine details are lost. The method relies on the observation that standard densification produces redundancy [S1].

## Operating characteristics
*   **Time Complexity:** Rendering complexity is linearly proportional to the number of *active* Gaussians, which is significantly reduced compared to standard 3DGS [S1]. Training time is comparable or slightly higher due to grid and codebook optimization, but the reduction in Gaussian count speeds up the forward pass [S1].
*   **Memory Complexity:** Storage is reduced by approximately 15x on average and up to 28x on specific datasets (e.g., Deep Blending) compared to standard 3DGS [S1]. With post-processing (quantization and entropy coding), compression exceeds 25x [S1].
*   **Measured Performance:** On the Deep Blending dataset, C3DGS outperforms 3DGS in PSNR, with over 28x storage efficiency enhancement and nearly 40% faster rendering speed [S1]. Across various datasets, it consistently shows ~15x reduced storage and enhanced rendering speed [S1].
*   **Strengths:** Significant reduction in memory and storage; faster rendering due to fewer primitives; maintains or improves reconstruction quality.
*   **Limitations:** Requires additional components (Hash Grid, Codebook) which add implementation complexity; compression ratio depends on scene redundancy.
*   **When to use:** When storage and memory are critical constraints, or when real-time rendering speed is prioritized without sacrificing quality.
*   **When not to use:** When the scene has very low spatial redundancy (e.g., highly unique geometry per Gaussian), the codebook and grid may not compress effectively.

## Background
C3DGS was proposed to address the critical memory and storage issues in 3D Gaussian Splatting, which often require >1GB for large real-world scenes [S1]. It builds on the observation that standard densification produces redundant Gaussians and that neighboring Gaussians share similar attributes [S1]. The method leverages techniques from neural radiance fields (Instant NGP) for compact grid representation and vector quantization for geometric compression [S1]. It was published in CVPR 2024 [S1].
