# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization strategies, and kernel-level configurations required to train and render 3D Gaussian Splatting (3DGS) efficiently. It addresses the gap between the theoretical formulation of differentiable volume rendering and practical software engineering, focusing on memory management, precision handling, and hyperparameter tuning. It sets itself apart from general training pipeline descriptions by providing concrete values for optimizer settings, loss weighting, and specific code-level modifications (such as SH degree reduction or background color changes) that significantly impact training speed and stability [S1][S5, unofficial][S2].

## How it works
The implementation relies on a differentiable rasterizer that renders images from a set of 3D Gaussians. The core optimization mechanism involves computing the gradient of a loss function $\mathcal{L}$ with respect to the Gaussian parameters (position, covariance, opacity, color, SH coefficients) and any auxiliary parameters [Parent].

### Inputs and Outputs
*   **Inputs:** A set of 3D Gaussians defined by mean position $\mu$, covariance $\Sigma$ (or scale $s$ and rotation $q$), opacity $\alpha$, and spherical harmonic coefficients $c$. Input views consist of camera poses $C_i$ and intrinsics.
*   **Outputs:** Rendered RGB images $\mathbf{I}$ and gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all parameters $\theta$.

### Data Structures
*   **Gaussian Attributes:** Stored in contiguous memory buffers for GPU access.
    *   Position: $\mathbb{R}^3$ (float32 or float16).
    *   Rotation: $\mathbb{R}^4$ (quaternion, normalized).
    *   Scale: $\mathbb{R}^3$ (log-space or linear).
    *   Opacity: $\mathbb{R}^1$ (sigmoid output).
    *   SH Coefficients: $\mathbb{R}^{3 \times (d+1)^2}$ where $d$ is the degree. For $d=3$, this is 48 floats per Gaussian [S9].
*   **Rasterization State:**
    *   Tile-based sorting: Gaussians are sorted by depth within screen-space tiles to enable efficient alpha blending [Parent].
    *   Transmittance buffer: Accumulated $T_i$ per pixel.

### Numbered Steps
1.  **Initialization:** Initialize Gaussians from Structure-from-Motion (SfM) points. Calculate scene extent $e_{\text{scene}}$ to determine initial scale [S3].
2.  **Forward Rasterization:**
    *   Project 3D Gaussians to 2D screen space using the camera projection matrix.
    *   Sort Gaussians by depth within each tile.
    *   For each pixel, iterate through sorted Gaussians. Compute opacity contribution $\alpha_i$ and color $c_i$.
    *   Alpha-blend: $C_{out} = \sum_i \alpha_i T_i c_i$, where $T_i = \prod_{j<i} (1-\alpha_j)$ [Parent].
3.  **Loss Computation:** Compute $\mathcal{L}$ (e.g., L1 + SSIM) between rendered image and ground truth.
4.  **Backward Pass:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ using automatic differentiation or custom CUDA kernels [S1].
5.  **Optimization Step:** Update parameters using Adam optimizer [S2].

### Formulas
*   **Scene Extent (Corrected):** To avoid bias from camera distribution, use the SfM point cloud:
    $$e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$$
    where $\bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i$ is the average camera position [S3].
*   **Total Loss (Dynamic/Deformable):**
    $$\mathcal{L} = \mathcal{L}_{\text{color}} + \lambda_1 \cdot \mathcal{L}_{\text{scales}}$$
    where $\lambda_1 = 0.1$ [S4, unofficial].
*   **Compact View-Dependent Color:**
    $$c_n(d) = f(\text{contract}(p_n), d; \theta)$$
    where $\text{contract}(p_n) = p_n$ if $\|p_n\| \le 1$, else $\frac{p_n}{\|p_n\|}(2 - \|p_n\|)$ [S9].

### Parameters
*   **Optimizer:** Adam with learning rate $1 \times 10^{-3}$ [S2].
*   **SH Degree:** Default is 3, but setting to 0 or 1 can improve speed with minimal quality loss [S2][S5, unofficial].
*   **Background Color:** Default is white (1.0). Optimal range for speed/quality balance is $0.3 \le \text{bg} \le 0.5$ [S5, unofficial].
*   **Volume Dimensions (Example):** Height 12.8m, Width 32m, Length 64m. Voxel size 0.1m, resulting in $128 \times 320 \times 640$ [S2].

### Edge Cases and Pitfalls
*   **Scene Extent Bias:** Default extent calculation based on furthest camera can be too small for large outdoor scenes if cameras are clustered, leading to incorrect splitting/pruning [S3].
*   **SH Coefficients:** In standard 3DGS, SH coefficients with degree > 0 are often unchanged during training, making them superfluous for static scenes [S5, unofficial].
*   **Half-Precision Stability:** Using FP16 requires an automatic scaling factor for loss values to prevent gradient underflow [S1].
*   **Defocus Blur:** Predicting a constant scale offset $\delta s_j$ for all Gaussians degrades to uniform blur; per-Gaussian prediction is required for spatially varying blur [S6].

### Pseudocode
```python
# Simplified training loop step
def training_step(gaussians, camera, gt_image, optimizer):
    # 1. Forward Pass
    # Project Gaussians and rasterize
    rendered_image = rasterize(gaussians, camera)
    
    # 2. Loss Calculation
    # L1 loss + SSIM
    loss = compute_l1_ssim_loss(rendered_image, gt_image)
    
    # 3. Backward Pass
    # Compute gradients
    loss.backward()
    
    # 4. Optimization Step
    optimizer.step()
    optimizer.zero_grad()
    
    # 5. Densification (if applicable)
    # Check gradient thresholds and split/clone Gaussians
    densify(gaussians, camera)
    
    return loss
```

## Subtopics

### [First-order Spherical Harmonics Distillation](9467-first-order-spherical-harmonics-distillation.md)
Reduces parameter count by distilling high-fidelity third-order SH coefficients into a compact first-order representation using knowledge distillation, preserving quality despite reducing coefficients from 16 to 4 per channel.

### [Continuous Attenuation Model for 3D Gaussian Splatting](9624-continuous-attenuation-model-for-3d-gaussian-splatting.md)
Reforms rasterization into a volumetric ray-marching framework by mapping Gaussians to a continuous attenuation field, ensuring unbiased transmittance isosurfaces and preventing surface erosion.

### [Explicit Camera Jacobian Derivation](10077-explicit-camera-jacobian-derivation.md)
Derives analytical Jacobians of SE(3) camera pose with respect to 3D Gaussians for efficient gradient-based camera tracking in SLAM, avoiding automatic differentiation overhead.

### [ASCII-Based Data Compression](11820-ascii-based-data-compression.md)
Compresses floating-point and integer values into ASCII strings to accelerate data transmission during training, achieving ~6% training speed improvement.

### DAVIGS
Mitigates appearance variation-induced floaters by transforming rendered images at the image level using 3D consistent features, decoupling global view-dependent variations from local spatial changes [S1].

### [Sensitivity-Aware Vector Clustering](12167-sensitivity-aware-vector-clustering.md)
Reduces storage by clustering SH coefficients and shape features into compact codebooks using sensitivity-aware vector quantization, prioritizing parameters that affect image quality.

### [Sorting and Rendering Pipeline Optimization](12180-sorting-and-rendering-pipeline-optimization.md)
Aligns software strategies with hardware bottlenecks identified via the Roofline model, applying memory-centric optimizations to sorting and compute-centric optimizations to alpha blending.

### [LangSplat Training Procedure](12438-langsplat-training-procedure.md)
Optimizes 3DGS scenes to incorporate semantic language features (e.g., CLIP) alongside photometric rendering, disabling densification/pruning during language-aware training.

### [Content-Aware Texturing for Gaussian Splatting](12606-content-aware-texturing-for-gaussian-splatting.md)
Augments 2D Gaussians with spatially varying texture maps, using dynamic texel allocation and splitting-based densification to manage geometric and appearance errors.

### [Directed Distance Field (DDF) for Gaussian Splatting](12854-directed-distance-field-ddf-for-gaussian-splatting.md)
A neural field mapping rays to distance and visibility for constant-time ray queries (shadows, AO), eliminating the need for mesh extraction or BVH traversal.

### [Gaussian Representation and Truncation](12855-gaussian-representation-and-truncation.md)
Defines primitives for rasterization and culling, offering alternative radial basis functions (Inverse Multiquadric) and opacity-independent truncation for aggressive culling.

### [Atomized Proliferation](12924-atomized-proliferation.md)
Constrains fine-detail Gaussians into uniformly-sized "Atom Gaussians" and prioritizes their proliferation, stabilizing densification and improving geometric precision.

### [DeSplat](12925-desplat.md)
Decomposes 3DGS into static scene Gaussians and per-view distractor Gaussians to remove transient occluders without external semantic models.

### [Compact 3D Gaussian Representation (C3DGS)](12927-compact-3d-gaussian-representation-c3dgs.md)
Reduces memory by replacing per-Gaussian attribute storage with a shared hash-based grid for colors and a discrete codebook for geometry, achieving >25x compression.

### [360 Gaussian Splatting](12929-360-gaussian-splatting.md)
Modifies the rasterizer for spherical rendering and uses OpenSfM to process equirectangular images from 360-degree cameras, avoiding cropping.

### Corrected Scene-Extent
Calculates scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution, using the formula $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$ [S3].

### Optimization Strategy
Optimizes static Gaussians for the initial 3000 iterations as a warm-up, then jointly optimizes Gaussians and deformation fields, using a loss $\mathcal{L} = \mathcal{L}_{\text{color}} + 0.1 \cdot \mathcal{L}_{\text{scales}}$ [S4, unofficial].

### SH Degree Zero Optimization
Sets SH max degree to 0 to remove superfluous operations, improving training speed by ~16.25% with no explicit quality impact, as higher-degree coefficients remain unchanged [S5, unofficial].

### Background Color Optimization
Changes background from white (1.0) to gray (0.3-0.5) to improve training speed, with bg=0.4 reducing processing time by ~21.85% on the truck dataset [S5, unofficial].

### Selective Defocus Blurring
Predicts per-Gaussian scale offsets $\delta s_j$ to create pixel-wise variable blur kernels, enabling spatially varying blur modeling and deblurring capabilities [S6].

### Triangle Soup (Mesh-based Gaussian Splatting)
Connects Gaussian splats to a mesh structure for real-time editing, automatically recalculating Gaussian parameters when vertices are moved, used in GaMeS [S7].

### SuGaR Mesh Extraction
Extracts surface mesh by regularizing Gaussians to align with the true scene surface and applying Poisson reconstruction on points sampled from the visible level set [S8].

### Compact View-dependent Color
Replaces per-Gaussian SH coefficients with a grid-based neural field using a contraction function and tiny MLP, reducing parameters from 48 to a shared grid [S9].

### AtomGS
Combines Atomized Proliferation with Geometry-Guided Optimization (Edge-Aware Normal Loss) to balance visual and geometric accuracy, refining underlying geometry alignment [S10, unofficial].

## Operating characteristics
*   **Time Complexity:** Rasterization is $O(N \cdot T)$ where $N$ is the number of Gaussians and $T$ is the number of tiles. Optimization is dominated by the backward pass through the rasterizer.
*   **Memory Complexity:** $O(N \cdot D)$ where $D$ is the dimensionality of Gaussian attributes (e.g., 59 parameters per Gaussian for SH degree 3) [S9].
*   **Performance:** Half-precision rasterization reduces register pressure and improves throughput [S1]. SH degree reduction can improve training speed by ~16% [S5, unofficial]. Background color optimization can improve speed by ~21% [S5, unofficial].
*   **Strengths:** Real-time rendering, high fidelity, efficient memory usage with compression techniques.
*   **Limitations:** Sensitive to scene extent calculation, potential for floaters in dynamic scenes, high memory usage for large scenes without compression [S3, S1].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 as a real-time radiance field representation [S1, S8]. It has since evolved with various optimization and implementation details to improve training speed, memory efficiency, and rendering quality [S2][S5, unofficial][S9].
