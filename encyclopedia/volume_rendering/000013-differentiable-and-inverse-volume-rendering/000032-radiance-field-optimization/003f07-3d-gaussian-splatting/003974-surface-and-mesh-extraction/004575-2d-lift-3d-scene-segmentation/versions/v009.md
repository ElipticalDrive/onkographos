# 2D-Lift-3D Scene Segmentation

Also called: 2D-Lift-3D Segmentation for Partial Scene Editing, PSE with 2D-lift-3D segmentation

## Overview
This method segments 3D Gaussian primitives into distinct parts by lifting 2D segmentation masks from a reference view into 3D space using multi-view label voting [S1]. It solves the problem of partial scene editing in volume visualization by allowing independent color, opacity, and lighting adjustments on specific semantic regions of a scene represented by Gaussian splats [S1]. Unlike sibling methods that rely on learnable feature vectors or explicit surface topology, this approach is training-free and relies on external segmentation models and geometric consistency across views [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A trained set of 3D Gaussian primitives $\mathcal{G} = \{g_i\}_{i=1}^N$ (centers $\boldsymbol{\mu}_i$, covariances $\boldsymbol{\Sigma}_i$, opacities $o_i$, spherical harmonics coefficients $\mathbf{c}_i$) [S1, Parent]. A set of training views with known camera poses. A reference view image rendered from the Gaussian scene. User-specified point prompts on the reference view.
*   **Output:** A label assignment $L_i \in \{1, \dots, K\}$ for each Gaussian primitive $g_i$, where $K$ is the number of segmented parts [S1].

**Data Structures:**
*   **Gaussian Set:** Standard 3DGS representation [Parent].
*   **Label Map:** An array of size $N$ storing the integer label for each Gaussian.
*   **Voting Count:** An array of size $N \times K$ (or a hash map) storing the number of views supporting each label for each Gaussian.

**Steps:**
1.  **Render Reference View:** Render an image $I_{ref}$ from an arbitrary view using the current Gaussian primitives [S1].
2.  **Generate 2D Mask:** Use a Segment Anything Model (SAM) with user-specified point prompts on $I_{ref}$ to generate a 2D segmentation mask $M_{ref}$ [S1].
3.  **Generate Multi-View Masks:** For each training view $v_j$ ($j=1 \dots V$):
    a. Render the image $I_{v_j}$ from view $v_j$ [S1].
    b. Use SAM with corresponding point prompts (or propagated prompts) on $I_{v_j}$ to generate 2D masks $M_{v_j}$ [S1]. *Note: The source implies generating masks for "corresponding parts across all training views" [S1].*
4.  **Label Propagation:** Assign distinct integer labels to the segments identified in the 2D masks [S1].
5.  **Multi-View Label Voting:** For each Gaussian primitive $g_i$:
    a. Project the center $\boldsymbol{\mu}_i$ of $g_i$ into the 2D image plane of each training view $v_j$ using the camera projection matrix $\mathbf{P}_j$.
    b. Check if the projected 2D coordinate $(u_{ij}, v_{ij})$ falls within a segment labeled $k$ in mask $M_{v_j}$.
    c. If yes, increment the vote count for label $k$ for Gaussian $g_i$ in view $v_j$.
    d. After checking all views, assign the label $k^*$ with the highest vote count to $g_i$. If no votes are received, the Gaussian remains unsegmented or retains a default label [S1].
6.  **Decomposition:** Group Gaussians by their assigned labels to form distinct parts of the scene [S1].

**Pseudocode:**
```python
def segment_gaussians(gaussians, training_views, reference_view, point_prompts_ref):
    """
    gaussians: List of Gaussian objects with attributes: center (3D), covariance, opacity, SH_coeffs
    training_views: List of camera objects with projection matrices and poses
    reference_view: Camera object for the reference view
    point_prompts_ref: List of 2D points for SAM on reference view
    """
    N = len(gaussians)
    V = len(training_views)
    # Initialize vote counts: votes[i][label] = count
    # Assuming labels are dynamically assigned or pre-defined by SAM output structure
    # For simplicity, we assume SAM returns masks with unique integer labels per mask
    # In practice, label alignment across views is required.
    # Here we assume a global label space or per-view label mapping.
    
    # Step 1 & 2: Get reference mask
    ref_image = render_scene(gaussians, reference_view)
    mask_ref = sam_segment(ref_image, point_prompts_ref)
    
    # Step 3: Get masks for all training views
    # Note: SAM requires prompts. The source says "user-specified point prompts... across all training views".
    # This implies the user provides prompts for each view, or they are propagated.
    # We assume prompts are provided or generated for each view.
    masks_views = []
    for view in training_views:
        img = render_scene(gaussians, view)
        # Prompts for this view would be needed. 
        # The source mentions "corresponding parts", implying semantic consistency.
        # We assume a function get_prompts_for_view(view) exists or prompts are given.
        prompts = get_prompts_for_view(view, point_prompts_ref) # [G] Helper to map prompts
        mask = sam_segment(img, prompts)
        masks_views.append(mask)
        
    # Step 5: Voting
    # We need to align labels across views. SAM might assign different IDs to the same object.
    # The source mentions "multi-view label voting technique [25]".
    # Without explicit label alignment algorithm in [S1], we assume labels are consistent 
    # or a clustering step aligns them. For implementation, we assume labels 1..K are consistent.
    
    votes = {} # key: gaussian_index, value: dict {label: count}
    
    for i, g in enumerate(gaussians):
        votes[i] = {}
        for j, view in enumerate(training_views):
            mask = masks_views[j]
            # Project Gaussian center to 2D
            u, v = project_2d(g.center, view.projection_matrix, view.pose)
            
            # Check if point is inside a valid segment in the mask
            # Mask values are integer labels. 0 might be background.
            label = mask[v, u]
            
            if label > 0: # Assuming 0 is background
                if label not in votes[i]:
                    votes[i][label] = 0
                votes[i][label] += 1
                
    # Assign final label
    final_labels = []
    for i in range(N):
        if votes[i]:
            best_label = max(votes[i], key=votes[i].get)
            final_labels.append(best_label)
        else:
            final_labels.append(0) # Background or unsegmented
            
    return final_labels
```

**Parameters:**
*   **SAM Model:** Segment Anything Model [S1].
*   **Point Prompts:** User-specified 2D coordinates [S1].
*   **Textures Attribute:** Used to uniformly represent non-stylized and stylized scenes, enabling color editing after stylization [S1].

**Edge Cases and Pitfalls:**
*   **Inefficiency:** The method cannot immediately generate a 3D segmentation from 2D masks created with point prompts on a single reference view. It may require multiple rounds of segmentation for certain scenes, which is inefficient [S1].
*   **Label Consistency:** The method relies on consistent labeling across views. If SAM assigns different IDs to the same semantic part in different views, voting will fail without a post-processing alignment step [G].
*   **Occlusion:** Gaussians occluded in most views may receive few votes, leading to ambiguous segmentation [G].

## Operating characteristics
*   **Time Complexity:** Dominated by rendering $V+1$ views and running SAM $V+1$ times. Projection and voting are $O(N \cdot V)$.
*   **Memory Complexity:** $O(N \cdot V)$ for storing votes if not optimized, or $O(N)$ if aggregated. Storage of masks is $O(V \cdot H \cdot W)$.
*   **Strengths:** Training-free; allows flexible partial scene editing (color, opacity, lighting) on specific parts [S1]. Supports post-stylization editing via the textures attribute [S1].
*   **Limitations:** Inefficient for scenes requiring multiple segmentation rounds; dependent on SAM's accuracy and prompt quality; cannot adjust light direction after training in some baselines (though TexGS-VolVis supports it via Blinn-Phong) [S1].
*   **When to use:** When real-time partial editing of a 3DGS scene is required without retraining, and semantic segmentation is available via 2D models.
*   **When not to use:** When high precision surface topology is needed, or when computational resources for multiple SAM inferences are limited.

## Background
The method was introduced in the context of TexGS-VolVis, a 2D Gaussian Splatting-based framework for volume visualization [S1]. It builds on prior work in 2D-lift-3D segmentation [5, 8, 25, 35] and SAGD [25]. It addresses limitations of StyleRF-VolVis, which only supported color editing before stylization and lacked per-part editing [S1].
