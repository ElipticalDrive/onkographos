# Octree refinement

Also called: Spatial subdivision refinement

## Overview
Octree refinement is a spatial subdivision technique used to reorder Gaussian splats for progressive rendering, ensuring that sparsely captured areas of a scene are reconstructed earlier than they would be by global contribution metrics alone [S1]. It differs from simple global sorting by enforcing a minimum representation per spatial region, thereby improving background quality at the cost of slight foreground degradation [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ 3D Gaussians $\{G_i\}$, each with a pre-computed global contribution score $C_i$ derived from rendering error across training views [S1].
*   **Output:** A refined ordering of Gaussians for progressive loading [S1].

**Data Structures:**
*   **Octree:** A hierarchical spatial partitioning structure where each node represents a cubic volume [S1]. The tree uses a fixed maximum depth of 3 [S1].
*   **Leaf Node List:** For each leaf node at depth 3, a list of Gaussians whose centers fall within that node's volume [S1].

**Parameters:**
*   **Octree Depth:** The maximum depth of the octree [S1]. A value of 3 consistently yields good results across scenes [S1]. Low values have little to no impact on quality [S1]. High values (7 or larger) introduce errors such as black blur and cause convergence back to the base global approach [S1].

**Algorithm Steps:**
1.  **Insertion:** Insert all $N$ Gaussians into the octree based on their center positions [S1]. Assign each Gaussian to the leaf node corresponding to its spatial location at depth 3 [S1].
2.  **Selection:** For each leaf node in the octree, identify the subset of Gaussians contained within it [S1]. From this subset, select the top contributing Gaussians with the highest global contribution scores $C_i$ [S1]. Implementation notes suggest using the contribution of the 20 highest contributing Gaussians per pixel as the basis for the initial score, but for the octree step, the selection is strictly per leaf [S1].
3.  **Aggregation:** Collect all selected Gaussians from all leaf nodes [S1]. The resulting set forms the refined ordering [S1].

**Pseudocode:**
```python
def octree_refinement(gaussians, max_depth=3):
    """
    Refine Gaussian ordering using octree spatial subdivision.
    
    Args:
        gaussians: List of Gaussian objects, each having:
            - center: (x, y, z) coordinates
            - contribution: float, global contribution score
        max_depth: int, maximum depth of the octree (default 3)
        
    Returns:
        ordered_gaussians: List of Gaussian objects, sorted by refined priority
    """
    # Compute scene bounding box from input Gaussians
    xs, ys, zs = zip(*[g.center for g in gaussians])
    scene_bounds = ((min(xs), min(ys), min(zs)), (max(xs), max(ys), max(zs)))
    
    # Step 1: Build Octree
    root = OctreeNode(depth=0, bounds=scene_bounds)
    
    for g in gaussians:
        leaf = root.insert(g.center, max_depth)
        leaf.gaussians.append(g)
        
    # Step 2 & 3: Select top contributors per leaf and aggregate
    selected_gaussians = []
    
    for leaf in root.get_leaves():
        if not leaf.gaussians:
            continue
        # Sort Gaussians in this leaf by contribution descending
        leaf.gaussians.sort(key=lambda g: g.contribution, reverse=True)
        # Select top contributing Gaussians per leaf node
        selected_gaussians.extend(leaf.gaussians)
        
    # Return globally sorted by contribution to maintain progressive nature
    selected_gaussians.sort(key=lambda g: g.contribution, reverse=True)
    return selected_gaussians

class OctreeNode:
    def __init__(self, depth, bounds):
        self.depth = depth
        self.bounds = bounds
        self.children = [None] * 8
        self.gaussians = []
        
    def insert(self, center, max_depth):
        if self.depth == max_depth:
            return self
        
        # Determine child octant index based on center relative to bounds midpoint
        mid = tuple((b[0] + b[1]) / 2.0 for b in self.bounds)
        idx = 0
        for i, coord in enumerate(center):
            if coord >= mid[i]:
                idx |= (1 << i)
                
        if self.children[idx] is None:
            child_min = tuple(max(self.bounds[0][i], mid[i]) for i in range(3))
            child_max = tuple(min(self.bounds[1][i], mid[i]) for i in range(3))
            self.children[idx] = OctreeNode(self.depth + 1, (child_min, child_max))
            
        return self.children[idx].insert(center, max_depth)
    
    def get_leaves(self):
        if any(c is not None for c in self.children):
            for c in self.children:
                if c is not None:
                    yield from c.get_leaves()
        else:
            yield self
```

**Edge Cases and Pitfalls:**
*   **High Depth Errors:** Using an octree depth of 7 or larger introduces rendering errors, specifically "black blur," and causes the method to converge back to the base global contribution approach [S1].
*   **Low Depth Impact:** Depth values significantly lower than 3 have little to no impact on quality [S1].
*   **PSNR Loss:** Including the octree refinement results in an average loss in PSNR scores because the foreground (which often contributes more to PSNR) is deprioritized in favor of background coverage [S1]. Perceptually, however, background quality improves [S1].

## Subtopics

### Octree-Based Ordering
An addition to the base contribution metric that uses an octree to force Gaussians to spread out over the scene, ensuring sparsely captured parts are loaded sooner [S1].
*   **Parameter:** Octree depth parameter. A value of 3 consistently yields good results. Values too low or too high result in insufficient attention to the background [S1].
*   **Pitfall:** High depth values (e.g., 7 or larger) introduce errors such as black blur and cause convergence to the base approach. Low depth values have little impact [S1].
*   **Performance:** Including the octree results in an average loss in PSNR scores because the foreground often contributes more to PSNR, but perceptually improves background quality [S1].

## Operating characteristics
*   **Strengths:** Ensures sparsely captured areas are not under-reconstructed; improves perceptual quality of the background; allows for object-level prioritization if manually segmented [S1].
*   **Limitations:** Causes a loss in average PSNR scores; high octree depths introduce rendering artifacts; does not account for viewpoint-specific occlusions (frustum culling is a separate step that occurs after global ordering) [S1].

## Background
Originated in the PRoGS (Progressive Rendering of Gaussian Splats) paper, which introduced spatial subdivision techniques to improve the progressive loading of 3D Gaussian Splatting reconstructions [S1]. The method was developed to address the issue where global contribution metrics unfairly under-reconstruct sparsely captured parts of a scene [S1].
