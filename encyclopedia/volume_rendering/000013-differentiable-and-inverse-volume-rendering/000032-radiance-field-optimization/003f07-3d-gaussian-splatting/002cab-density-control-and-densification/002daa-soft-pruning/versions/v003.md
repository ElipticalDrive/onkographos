# Soft Pruning

Also called: Hessian-aware pruning, L1 loss pruning

## Overview
Soft Pruning is a density control method in 3D Gaussian Splatting that reduces the number of Gaussian primitives during the densification stage by removing those with low contribution to the training loss [S1, S2]. It differs from its sibling [Hard Pruning](5591-hard-pruning.md) by occurring *during* the densification phase (specifically before opacity resets) rather than after, allowing the model to recover performance through subsequent refinement iterations [S1, S2]. This approach maintains a robust Hessian approximation for optimization by eliminating Gaussians that have converged to low L1 loss [S1].

## How it works
Soft Pruning operates by evaluating an "Efficient Pruning Score" based on the L1 photometric loss of each Gaussian. It is applied at specific intervals during training to reduce model size while preserving visual fidelity [S2].

**Inputs and Outputs:**
*   **Input:** The set of 3D Gaussians $\mathcal{G}$, their current L1 loss values $\mathcal{L}_1$, and the current training iteration $t$.
*   **Output:** A reduced set of Gaussians $\mathcal{G}'$ with a specified pruning ratio.

**Data Structures:**
*   Each Gaussian $g_i \in \mathcal{G}$ maintains a scalar L1 loss value $l_i$, which accumulates or tracks the error contribution of that specific primitive during rendering [S1].

**Parameters:**
*   **Pruning Ratio ($\rho$):** The fraction of Gaussians to remove. A value of 80% ($\rho=0.8$) is used in experiments, preserving visual fidelity [S1].
*   **Reset Iterations:** Pruning is triggered immediately before opacity resets at iterations 6000, 9000, and 12000 [S1].

**Steps:**
1.  **Check Trigger Condition:** If the current training iteration $t$ matches a predefined reset iteration (e.g., 6000, 9000, 12000), proceed to pruning. Otherwise, skip [S1].
2.  **Compute Pruning Score:** For each Gaussian $g_i$, retrieve its current L1 loss $l_i$. The pruning score is derived directly from this loss value; lower loss indicates the Gaussian is well-fitted and contributes less to further error reduction [S1, S2].
3.  **Rank Gaussians:** Sort all Gaussians in $\mathcal{G}$ based on their L1 loss $l_i$ in ascending order [S2].
4.  **Select Candidates:** Identify the bottom $\rho \times |\mathcal{G}|$ Gaussians with the lowest L1 loss as candidates for removal [S1].
5.  **Remove Gaussians:** Delete the selected candidates from the scene representation $\mathcal{G}$ [S2].
6.  **Proceed to Opacity Reset:** Immediately after pruning, perform the standard opacity reset for the remaining Gaussians to maintain a robust Hessian approximation for the optimizer [S1].

**Pseudocode:**
```python
def soft_pruning(gaussians, current_iteration, reset_iterations, pruning_ratio):
    """
    Perform Soft Pruning if the current iteration matches a reset point.
    
    Args:
        gaussians: List of Gaussian objects, each having an attribute 'l1_loss'.
        current_iteration: Integer, current training step.
        reset_iterations: List of integers, e.g., [6000, 9000, 12000].
        pruning_ratio: Float, fraction of Gaussians to remove (e.g., 0.8).
        
    Returns:
        Updated list of Gaussians.
    """
    if current_iteration not in reset_iterations:
        return gaussians

    # Step 1: Sort Gaussians by L1 loss (ascending)
    # Gaussians with lower loss are considered less necessary
    sorted_gaussians = sorted(gaussians, key=lambda g: g.l1_loss)
    
    # Step 2: Determine number of Gaussians to prune
    num_to_prune = int(pruning_ratio * len(sorted_gaussians))
    
    # Step 3: Remove the bottom 'num_to_prune' Gaussians
    # These are the ones with the smallest L1 loss
    pruned_gaussians = sorted_gaussians[num_to_prune:]
    
    # Step 4: Return the pruned set. 
    # Note: The caller must subsequently perform opacity resets 
    # on the remaining Gaussians as per the standard 3D-GS pipeline [S1].
    return pruned_gaussians
```

**Edge Cases and Pitfalls:**
*   **Precision:** Ensure L1 loss values are accurately tracked per Gaussian. If loss is not granular enough, pruning may remove critical structures [S1].
*   **Timing:** Pruning must occur *before* opacity resets. Performing it after resets may disrupt the Hessian approximation intended by the reset [S1].
*   **Ratio Selection:** While 80% is effective, higher ratios may degrade visual fidelity. The sources do not specify a maximum safe ratio beyond the experimental 80% [S1].

## Subtopics

### [Hard Pruning](5591-hard-pruning.md)
Hard Pruning is a density control method in 3D Gaussian Splatting that reduces model size by a constant ratio at fixed intervals after the densification stage. It differs from Soft Pruning by occurring post-densification rather than during it, relying on subsequent refinement iterations to recover performance.

## Operating characteristics
*   **Time Complexity:** Sorting Gaussians by loss takes $O(N \log N)$ where $N$ is the number of Gaussians. Pruning itself is $O(N)$. This is performed only at specific iterations (e.g., 3 times in standard setups), so the amortized cost is low [S1, S2].
*   **Memory Complexity:** Reduces memory footprint by approximately 90% when combined with Hard Pruning, as it removes primitives from the scene representation [S2].
*   **Performance:** Increases rendering and training speed due to fewer primitives to rasterize and update [S2].
*   **Strengths:** Maintains visual fidelity even with high pruning ratios (80%) [S1]. Integrates seamlessly into the existing 3D-GS training loop [S2].
*   **Limitations:** Requires tracking per-Gaussian L1 loss, adding minor overhead to the forward pass [S1]. Effectiveness depends on the convergence of L1 loss; if loss does not stabilize, pruning may be premature [S1].
*   **When to use:** When training time and rendering speed are critical, and the scene allows for significant sparsity without quality loss [S2].
*   **When not to use:** If the scene requires very high precision in early training stages where L1 loss has not yet converged [S1].

## Background
Soft Pruning was introduced in the "Speedy-Splat" paper, which proposed fast 3D Gaussian Splatting with sparse pixels and sparse primitives [S1, S2]. The method was developed to address the computational cost of dense Gaussian representations by leveraging the observation that L1 loss converges quickly during training [S2]. It is part of a broader effort to optimize 3D Gaussian Splatting for real-time applications [S1].
