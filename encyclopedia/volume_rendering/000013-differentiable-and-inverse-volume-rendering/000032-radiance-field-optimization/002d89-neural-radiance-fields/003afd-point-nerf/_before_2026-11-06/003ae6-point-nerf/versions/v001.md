# Point-NeRF

Also called: Point-based Neural Radiance Fields

## Overview
Point-NeRF models a radiance field using a neural 3D point cloud, where each point carries a latent feature vector, rather than a dense voxel grid or a single global MLP. It renders efficiently by aggregating these neural point features near scene surfaces within a ray-marching pipeline. It is distinguished from standard NeRF by its explicit geometric initialization via multi-view stereo (MVS) and its significantly faster training convergence, achieving comparable visual quality with approximately 30× faster training time [S1, unofficial].

## How it works
Point-NeRF replaces the implicit coordinate-to-color/density mapping of standard NeRF with a sparse set of learnable 3D points, each associated with a high-dimensional latent code. The rendering process remains volume integration along rays, but the density $\sigma$ and color $\mathbf{c}$ are derived from the features of the nearest points to the ray sample location.

### Inputs and Outputs
*   **Inputs:** A set of calibrated images with known camera poses; optionally, an initial point cloud and feature vectors generated by a pre-trained MVS network (e.g., MVSNet).
*   **Outputs:** Rendered RGB images, depth maps, and the optimized neural point cloud (positions and latent features).

### Data Structures
The core data structure is the **Neural Point Cloud**.
*   **Positions:** A tensor of shape $(N, 3)$ containing the 3D coordinates of $N$ points.
*   **Latent Features:** A tensor of shape $(N, D)$ containing the embedding vector for each point, where $D$ is the `embedding_size`.
*   **Parameters:** The model parameters include the point positions and latent features, optimized via gradient descent.

### Initialization
The method begins by initializing the neural point cloud. This is typically done by direct inference from a pre-trained deep network, such as MVSNet [S1, unofficial].
1.  Depth estimation is performed on input images.
2.  Points are triangulated or back-projected into 3D space.
3.  Feature vectors are extracted for these points.
4.  *Note:* When using MVSNet on datasets with synthetic backgrounds (e.g., NeRF-Synthetic), MVSNet may handle backgrounds poorly. To mitigate this, background color filtering is applied during point fusion to improve fairness [S1, unofficial].

### Optimization
The neural point cloud is finetuned to minimize the difference between rendered and ground-truth images.
1.  **Ray Marching:** For each pixel, a ray is cast. Samples are taken along the ray.
2.  **Feature Aggregation:** For each sample point $\mathbf{x}_i$ on the ray, the $k$ nearest neural points are identified. Their latent features are aggregated (e.g., via weighted average based on distance) to form a feature vector $\mathbf{f}_i$.
3.  **Prediction:** A small MLP (or linear layer) maps $\mathbf{f}_i$ and the viewing direction $\mathbf{d}$ to density $\sigma_i$ and color $\mathbf{c}_i$.
4.  **Rendering:** Color is computed using the standard volume rendering equation:
    $$ C(r) = \sum_{i=1}^{N} T_i \alpha_i \mathbf{c}_i, \quad T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right), \quad \alpha_i = 1 - \exp(-\sigma_i \delta_i) $$
5.  **Loss:** The loss is typically the $L_1$ or $L_2$ difference between rendered and ground-truth colors, possibly combined with regularization terms.
6.  **Update:** Point positions and latent features are updated using an optimizer (e.g., Adam). The implementation separates neural point parameters from other network parameters for separate optimization [S1, unofficial].

### Refinement (Pruning and Growing)
To handle errors and outliers from the initial reconstruction, Point-NeRF employs a pruning and growing mechanism [S1, unofficial].
*   **Pruning:** Points with low contribution to the scene (e.g., low density or high error) are removed.
*   **Growing:** New points are added in regions with high reconstruction error or low point density.
*   This process is controlled by the `alter_step` parameter. If `alter_step` is 0, no alteration occurs [S1, unofficial].

### Parameters
*   `embedding_size`: Dimension of the latent code embedding. Default: -1 (Not given in the sources).
*   `loss_embedding_l2_weight`: Weight for the embedding L2 loss. Default: -1 (Not given in the sources).
*   `loss_kld_weight`: Weight for the VAE KLD loss. Default: -1 (Not given in the sources).
*   `compute_depth`: Boolean flag (0 or 1). If false, depth is only computed when required by losses. Default: 0.
*   `raydist_mode_unit`: Boolean flag (0 or 1). If set, ray distance max is set as one voxel. Default: 0.
*   `save_point_freq`: Frequency of showing training results on console. Default: 100000.
*   `alter_step`: Step interval for alteration (pruning/growing). 0 means no alteration. Default: 0.
*   `prob`: Flag for probabilistic training. Set to 0 for normal training and 1 for probabilistic training. Default: 0.
*   `wcoord_query`: Configuration flag to replace pycuda with pytorch cuda functions when using world coordinates to group neural points. Set to -1 to use pytorch implementation if original setting is 1. Default: -1 (recommended for modern PyTorch).

### Pseudocode
```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class NeuralPoint:
    def __init__(self, positions, features):
        """
        positions: (N, 3) tensor of 3D coordinates
        features: (N, D) tensor of latent embeddings
        """
        self.positions = nn.Parameter(positions.clone().detach())
        self.features = nn.Parameter(features.clone().detach())
        
    def get_k_nearest(self, query_points, k=8):
        """
        Find k nearest neural points for each query point.
        query_points: (M, 3)
        Returns: indices (M, k), distances (M, k)
        """
        # Compute pairwise distances
        # dists: (M, N)
        dists = torch.cdist(query_points, self.positions)
        # Get k nearest
        dists_k, indices_k = torch.topk(dists, k, dim=1, largest=False)
        return indices_k, dists_k

    def aggregate_features(self, query_points, k=8):
        """
        Aggregate features from k nearest points.
        query_points: (M, 3)
        Returns: aggregated features (M, D), weights (M, k)
        """
        indices, dists = self.get_k_nearest(query_points, k)
        # Gather features
        neighbor_features = self.features[indices] # (M, k, D)
        # Compute weights based on distance (inverse distance weighting)
        # Add small epsilon to avoid division by zero
        eps = 1e-6
        weights = 1.0 / (dists + eps) # (M, k)
        weights = weights / weights.sum(dim=1, keepdim=True) # Normalize
        # Weighted sum
        aggregated = torch.sum(neighbor_features * weights.unsqueeze(2), dim=1) # (M, D)
        return aggregated, weights

class PointNeRFModel(nn.Module):
    def __init__(self, positions, features, embedding_size=256, hidden_dim=128):
        super().__init__()
        self.neural_point = NeuralPoint(positions, features)
        # MLP to map aggregated features + direction to sigma and color
        # Input: aggregated_features (D) + viewing_direction (3)
        self.mlp = nn.Sequential(
            nn.Linear(embedding_size + 3, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, 4) # sigma (1) + color (3)
        )
        
    def render(self, rays_o, rays_d, near, far, num_samples):
        """
        rays_o: (H, W, 3) ray origins
        rays_d: (H, W, 3) ray directions (normalized)
        near, far: float, near and far clip distances
        num_samples: int, number of samples per ray
        """
        H, W, _ = rays_o.shape
        # Generate sample points along rays
        t_vals = torch.linspace(0., 1., num_samples)
        z_vals = near * (1. - t_vals) + far * t_vals
        # (H, W, num_samples, 3)
        pts = rays_o.unsqueeze(2) + rays_d.unsqueeze(2) * z_vals.unsqueeze(3)
        
        # Flatten for processing
        pts_flat = pts.reshape(-1, num_samples, 3) # (H*W, num_samples, 3)
        dirs_flat = rays_d.reshape(-1, 1, 3).expand(-1, num_samples, -1) # (H*W, num_samples, 3)
        
        # Aggregate features
        aggregated_features, _ = self.neural_point.aggregate_features(pts_flat) # (H*W, num_samples, D)
        
        # Concatenate with viewing direction
        input_tensor = torch.cat([aggregated_features, dirs_flat], dim=-1) # (H*W, num_samples, D+3)
        
        # Predict sigma and color
        output = self.mlp(input_tensor) # (H*W, num_samples, 4)
        sigma = output[..., 0] # (H*W, num_samples)
        color = torch.sigmoid(output[..., 1:]) # (H*W, num_samples, 3)
        
        # Volume rendering
        # delta_z = z_vals[i+1] - z_vals[i]
        delta_z = z_vals[:, 1:] - z_vals[:, :-1]
        delta_z = torch.cat([delta_z, torch.zeros_like(delta_z[:, :1])], dim=1)
        delta_z = delta_z.reshape(-1, num_samples) # (H*W, num_samples)
        
        alpha = 1.0 - torch.exp(-sigma * delta_z)
        T = torch.cumprod(torch.cat([torch.ones_like(alpha[:, :1]), 1.0 - alpha + 1e-10], dim=1), dim=1)[:, :-1]
        
        weights = T * alpha
        final_color = torch.sum(weights.unsqueeze(2) * color, dim=1)
        
        # Reshape back to (H, W, 3)
        final_color = final_color.reshape(H, W, 3)
        
        return final_color

    def forward(self, rays_o, rays_d, near, far, num_samples):
        return self.render(rays_o, rays_d, near, far, num_samples)
```

### Edge Cases and Pitfalls
*   **MVSNet Background Handling:** When initializing with MVSNet on the NeRF-Synthetic dataset, the alpha channel information from depth estimation can introduce artifacts because MVSNet struggles with background. The authors recommend using background color filtering during point fusion to improve fairness [S1, unofficial].
*   **CUDA Implementation:** The original implementation used `pycuda` for efficient neighbor queries. Users are advised to set `wcoord_query=-1` to use the PyTorch CUDA implementation instead, which is more compatible with modern PyTorch versions [S1, unofficial].
*   **Sparse Initialization:** If the initial point cloud is too sparse, the model may fail to reconstruct fine details. Conversely, too many points increase memory usage and training time.

## Operating characteristics
*   **Training Speed:** Point-NeRF achieves approximately 30× faster training time compared to standard NeRF [S1, unofficial].
*   **Memory Usage:** Memory usage is proportional to the number of points $N$ and the embedding dimension $D$, i.e., $O(N \cdot D)$. This is generally more memory-efficient than dense voxel grids for high-resolution scenes, but depends heavily on the density of the initial point cloud.
*   **Rendering Speed:** Rendering speed depends on the number of nearest neighbor queries per sample. Using efficient data structures (e.g., KD-trees or GPU-based neighbor search) is crucial. The PyTorch CUDA implementation helps accelerate this [S1, unofficial].
*   **Quality:** Visual quality is comparable to or better than standard NeRF, especially when initialized with high-quality MVS data [S1, unofficial].
*   **When to Use:** Suitable for scenes where a good initial 3D reconstruction is available (e.g., from MVS) and fast training is desired.
*   **When Not to Use:** Not suitable for scenes with no initial structure or where MVS fails (e.g., textureless regions, reflective surfaces).

## Background
Point-NeRF was introduced in the paper "Point-NeRF: Point-based Neural Radiance Fields" by Qiangeng Xu et al., presented at CVPR 2022 as an Oral presentation [S1, unofficial]. It builds on the idea of using explicit point representations for radiance fields, combining the efficiency of point-based methods with the flexibility of neural networks. The method was developed to address the slow training speed of standard NeRF while maintaining high visual quality.
