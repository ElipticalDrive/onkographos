# Radiometric Self-Calibration

Also called: Color Calibration, Exposure and Sensor Bias Estimation, Gain and Bias Calibration, Response Curve Optimization

## Overview
Radiometric Self-Calibration optimizes radiometric parameters, specifically exposure and sensor bias, during the reconstruction process to correct for photometric errors and intensity mismatches between training views [S1, S2]. It addresses the limitation that cameras in a multiview system are often geometrically calibrated but not color-calibrated, leading to inconsistent pixel values for the same radiance across different sensors [S2]. Unlike methods that assume fixed camera response, this approach learns per-camera gain and bias parameters to ensure that reconstructed radiance values map consistently to pixel values [S2]. Enabling exposure and sensor bias estimation improves reconstruction quality by approximately 1 dB [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Training images $I_{\text{rgb}}$, camera poses, volume representation (e.g., neural field or voxel grid), and initial geometric calibration.
*   **Outputs:** Optimized volume representation, per-camera gain $g$ and bias $b$ parameters, and optionally a background image $I_{\text{rgb}}^{(\text{bg})}$ and response curve parameters.

**Data Structures:**
*   **Per-camera parameters:** For each camera $c$, store a gain $g_c$ and bias $b_c$ for each color channel (RGB). These are learnable parameters.
*   **Background image (Optional):** A static per-camera background image $I_{\text{rgb}}^{(\text{bg})}$ of the same resolution as the training images.
*   **Response curve (Optional):** Parameters defining the camera response function, if enabled.

**Steps:**
1.  **Initialize Parameters:** Initialize per-camera gain $g$ and bias $b$ to identity values (e.g., $g=1, b=0$) or small random values. If background estimation is enabled, initialize $I_{\text{rgb}}^{(\text{bg})}$ to a neutral color or black.
2.  **Ray Marching:** For each training view, ray march through the volume to compute the accumulated color $I_{\text{rgb}}(\mathbf{p})$ and opacity $I_\alpha(\mathbf{p})$ for each pixel $\mathbf{p}$ [S2].
3.  **Apply Radiometric Correction:** Apply the per-camera gain and bias to the accumulated volume color:
    $$ I_{\text{corrected}}(\mathbf{p}) = g I_{\text{rgb}}(\mathbf{p}) + b $$
    If background estimation is enabled, merge the corrected volume color with the background image using the remaining opacity:
    $$ \widehat{I}_{\text{rgb}}(\mathbf{p}) = (1 - I_\alpha(\mathbf{p})) I_{\text{rgb}}^{(\text{bg})}(\mathbf{p}) + I_{\text{corrected}}(\mathbf{p}) $$
    [S2]
4.  **Compute Loss:** Compare the rendered image $\widehat{I}_{\text{rgb}}$ with the ground truth training image $I_{\text{gt}}$ using a loss function (e.g., L2 or L1).
5.  **Optimize:** Update the volume parameters, per-camera gain $g$, bias $b$, and background image $I_{\text{rgb}}^{(\text{bg})}$ using gradient descent (e.g., Adam) [S2].
6.  **Response Curve Optimization (Optional):** If enabled, optimize the response curve parameters to further improve reconstruction quality [S1].

**Formulas:**
*   **Radiometric Correction:** $I_{\text{corrected}}(\mathbf{p}) = g I_{\text{rgb}}(\mathbf{p}) + b$ [S2]
*   **Background Merging:** $\widehat{I}_{\text{rgb}}(\mathbf{p}) = (1 - I_\alpha(\mathbf{p})) I_{\text{rgb}}^{(\text{bg})}(\mathbf{p}) + (g I_{\text{rgb}}(\mathbf{p}) + b)$ [S2]
    *   $\widehat{I}_{\text{rgb}}(\mathbf{p})$: Final rendered pixel value.
    *   $I_\alpha(\mathbf{p})$: Opacity exiting the volume.
    *   $I_{\text{rgb}}^{(\text{bg})}(\mathbf{p})$: Background pixel value.
    *   $I_{\text{rgb}}(\mathbf{p})$: Volume color.
    *   $g, b$: Per-camera gain and bias.

**Parameters:**
*   **Learning Rate for Background Images:** $10^{-1}$ [S2]
*   **Learning Rate for Gain and Bias:** $10^{-3}$ [S2]
*   **Learning Rate for Network Weights:** $10^{-4}$ [S2]
*   **Batch Size:** 16 [S2]
*   **Pixels Sampled:** 128x128 [S2]

**Edge Cases and Pitfalls:**
*   **Precision:** Ensure that gain and bias parameters do not diverge to extreme values, which could lead to saturation or noise amplification.
*   **Boundaries:** The background image should only capture stationary objects outside the reconstruction volume to avoid artifacts [S2].
*   **Degenerate Input:** If the background is not static, the background estimation may fail, leading to artifacts [S2].

**Pseudocode:**
```python
def radiometric_self_calibration(volume_model, cameras, training_images, num_iterations=500000):
    # Initialize per-camera gain and bias
    gains = {cam: torch.ones(3) for cam in cameras}  # Per-channel gain
    biases = {cam: torch.zeros(3) for cam in cameras}  # Per-channel bias
    
    # Initialize background images (optional)
    backgrounds = {cam: torch.zeros_like(training_images[cam]) for cam in cameras}
    
    optimizer = torch.optim.Adam([
        {'params': volume_model.parameters(), 'lr': 1e-4},
        {'params': list(gains.values()) + list(biases.values()), 'lr': 1e-3},
        {'params': list(backgrounds.values()), 'lr': 1e-1}
    ])
    
    for iteration in range(num_iterations):
        optimizer.zero_grad()
        
        for cam in cameras:
            # Ray march through volume
            I_rgb, I_alpha = ray_march(volume_model, cameras[cam])
            
            # Apply radiometric correction
            I_corrected = gains[cam] * I_rgb + biases[cam]
            
            # Merge with background if enabled
            I_rendered = (1 - I_alpha) * backgrounds[cam] + I_corrected
            
            # Compute loss
            loss = torch.mean((I_rendered - training_images[cam]) ** 2)
            loss.backward()
        
        optimizer.step()
    
    return volume_model, gains, biases, backgrounds
```

## Subtopics

### [Exposure Correction Strategy](8760-exposure-correction-strategy.md)
This strategy corrects inconsistent exposure across training views caused by the auto-exposure behavior of modern cameras in radiance-field optimization. It addresses the limitation of prior methods that only correct exposure at training views by generalizing to images rendered at any novel viewpoint. Unlike approaches that jointly optimize an affine transformation matrix for each training view [6, 17], this method assumes that images taken at nearby locations share similar global lighting conditions and corrects camera exposure at novel views by mimicking the exposure setting of the closest source view.

### Geometric Self-Calibration
Optimization of geometric parameters, such as detector orientation and source position, during the reconstruction process to correct for calibration errors [S1]. It adds Gaussian noise to the position and rotation of each view to simulate bad initial calibration, then enables GSC to recover from this state [S1]. GSC recovers from a 15 dB degradation caused by Gaussian noise in position and rotation, outperforming the baseline [S1].

### Background Image Merging
Estimation of a static per-camera background image $I_{\text{rgb}}^{(\text{bg})}$ to capture stationary objects outside the reconstruction volume, reducing artifacts caused by slight appearance differences from calibration errors or view-dependent effects [S2]. The final image pixel is computed as $\widehat{I}_{\text{rgb}}(\mathbf{p}) = (1 - I_\alpha(\mathbf{p})) I_{\text{rgb}}^{(\text{bg})}(\mathbf{p}) + (g I_{\text{rgb}}(\mathbf{p}) + b)$ [S2]. Per-camera gain $g$ and bias $b$ are learned parameters applied to the volume color before merging with the background [S2]. The learning rate for estimated background images is $10^{-1}$ and for per-camera gain and bias is $10^{-3}$ [S2].

## Operating characteristics
*   **Time Complexity:** Depends on the number of iterations and the complexity of the volume model. Training takes about 10 days on a single NVIDIA Tesla V00 for 500,000 iterations [S2].
*   **Memory Complexity:** Increases with the number of cameras and the resolution of the background images. Randomly sampling 128x128 pixels helps reduce memory usage [S2].
*   **Measured Performance:** Enabling exposure and sensor bias estimation improves reconstruction by approximately 1 dB [S1]. Geometric Self-Calibration recovers from a 15 dB degradation [S1].
*   **Scaling:** The method scales with the number of cameras and the resolution of the images.
*   **Strengths:** Corrects for photometric errors and intensity mismatches, improving reconstruction quality [S1, S2].
*   **Limitations:** Requires additional parameters to be optimized, which can increase training time and complexity [S2].
*   **When to Use:** When cameras are not color-calibrated or when there are significant intensity differences between training views [S2].
*   **When Not to Use:** When the background is not static or when computational resources are limited [S2].

## Background
Radiometric Self-Calibration originated in the context of neural volume rendering and tomography to address the lack of color calibration in multiview systems [S2]. It was introduced in "Neural Volumes: Learning Dynamic Renderable Volumes from Images" [S2] and further developed in "NeAT: Neural Adaptive Tomography" [S1]. The method is used in applications where high-fidelity reconstruction is required, such as medical imaging and 3D scene reconstruction [S1, S2].
