# Quadri-Plane Radiance Fields

Also called: 4-Plane Representation, Quadri-Plane Model

## Overview
Quadri-Plane Radiance Fields represent a 3D scene using four multi-channel 2D feature planes coupled with a decoder MLP, designed to enable computationally efficient volumetric super-resolution by leveraging 2D image super-resolution techniques [S1, unofficial]. It diverges from typical 3D coordinate-based schemes by using explicit feature vectors arranged in planes, setting it apart from sibling architectures like [HexPlane](11358-hexplane.md) which uses six planes, or [STensoRRF](11359-stensorrf.md) which uses tensor decompositions [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:** 3D point coordinates $p \in \mathbb{R}^3$, viewing direction $(\theta_p, \phi_p)$ (azimuth and elevation).
*   **Outputs:** Volume density $\sigma$ and RGB radiance $\{r, g, b\}$.

**Data Structures**
The scene representation $P_s$ consists of four planes:
1.  Three positional planes: $P_{xy}, P_{xz}, P_{yz}$.
2.  One view-direction plane: $P_{dir}$.

Layout details:
*   Positional planes: Dimensions $N \times N \times C$.
*   View-direction plane: Dimensions $N_{dir} \times N_{dir} \times C$.
*   Typical values: $N=200$, $N_{dir}=32$, $C=48$ [S1, unofficial].

**Decoders**
Two fully-connected MLPs are used, both having 128 channels and 4 layers [S1, unofficial]:
*   $D_c$ (Coarse decoder): Computes density $\sigma$.
*   $D_f$ (Fine decoder): Computes radiance $\{r, g, b\}$ (Note: Source text implies $D_f$ is used for radiance in the context of the SR model, but explicitly states radiance uses an MLP with identical characteristics to density MLPs. The standard NeRF scheme uses one MLP for density and one for radiance. The source states: "For computing the corresponding radiance values... we feed the concatenation... into MLPs with identical characteristics." It also mentions "a pair of coarse and fine decoders $D_c$ and $D_f$... shared across all scenes". We assume $D_c$ outputs density and $D_f$ outputs radiance, or a single decoder structure is used for both depending on the specific training phase (LR vs SR). The core method for a single point evaluation uses the described MLPs).

**Numbered Steps**
1.  **Retrieve Positional Features:** For a point $p$, project it onto the three positional planes $P_{xy}, P_{xz}, P_{yz}$. Retrieve feature vectors $v_{p,xy}, v_{p,xz}, v_{p,yz}$ via bilinear interpolation.
2.  **Aggregate Positional Features:** Compute the average of the positional feature vectors to form $v_p$:
    $$ v_p = \frac{1}{3} (v_{p,xy} + v_{p,xz} + v_{p,yz}) $$
3.  **Retrieve View-Direction Feature:** Determine the viewing direction $(\theta_p, \phi_p)$ for the ray passing through $p$. Project this direction onto $P_{dir}$. Retrieve the complementary feature vector $v_{pdir}$ via bilinear interpolation at coordinates $(\theta_p, \phi_p)$ [S1, unofficial].
4.  **Compute Density:** Input $v_p$ into the coarse decoder $D_c$ to yield density $\sigma$ [S1, unofficial].
5.  **Compute Radiance:** Concatenate all four feature vectors ($v_{p,xy}, v_{p,xz}, v_{p,yz}, v_{pdir}$) to form the input vector. Feed this concatenation into the fine decoder $D_f$ (or the radiance MLP) to yield RGB values $\{r, g, b\}$ [S1, unofficial].

**Pseudocode**
```python
import numpy as np

def bilinear_interpolate(plane, u, v):
    """
    Performs bilinear interpolation on a 2D plane at normalized coordinates (u, v).
    plane: numpy array of shape (H, W, C)
    u, v: float in [0, 1]
    Returns: numpy array of shape (C,)
    """
    H, W, C = plane.shape
    # Map [0,1] to pixel coordinates
    u_px = u * (W - 1)
    v_px = v * (H - 1)
    
    u0 = int(np.floor(u_px))
    v0 = int(np.floor(v_px))
    u1 = u0 + 1
    v1 = v0 + 1
    
    # Clamp to boundaries
    u0 = np.clip(u0, 0, W - 2)
    u1 = np.clip(u1, 0, W - 1)
    v0 = np.clip(v0, 0, H - 2)
    v1 = np.clip(v1, 0, H - 1)
    
    # Interpolation weights
    w_u = u_px - u0
    w_v = v_px - v0
    
    # Get corner values
    val_00 = plane[v0, u0, :]
    val_01 = plane[v0, u1, :]
    val_10 = plane[v1, u0, :]
    val_11 = plane[v1, u1, :]
    
    # Bilinear interpolation
    top = val_00 * (1 - w_u) + val_01 * w_u
    bottom = val_10 * (1 - w_u) + val_11 * w_u
    result = top * (1 - w_v) + bottom * w_v
    
    return result

def quadri_plane_render(p, theta, phi, planes, decoders):
    """
    p: numpy array (3,) - 3D point coordinates
    theta: float - azimuth angle
    phi: float - elevation angle
    planes: dict containing 'Pxy', 'Pxz', 'Pyz', 'Pdir'
    decoders: dict containing 'Dc' (density MLP), 'Df' (radiance MLP)
    """
    # 1. Retrieve positional features
    # Projection logic: 
    # Pxy: use x, y coordinates
    # Pxz: use x, z coordinates
    # Pyz: use y, z coordinates
    # Assuming coordinates are normalized or mapped appropriately. 
    # The source implies standard projection. We assume p is normalized to [0,1] or similar for interpolation.
    # If p is in world space, it must be normalized to the plane's domain.
    
    # Example normalization (assuming world space [-1, 1] mapped to [0, 1])
    def normalize(coord):
        return (coord + 1.0) / 2.0

    v_xy = bilinear_interpolate(planes['Pxy'], normalize(p[0]), normalize(p[1]))
    v_xz = bilinear_interpolate(planes['Pxz'], normalize(p[0]), normalize(p[2]))
    v_yz = bilinear_interpolate(planes['Pyz'], normalize(p[1]), normalize(p[2]))
    
    # 2. Aggregate positional features
    v_p = (v_xy + v_xz + v_yz) / 3.0
    
    # 3. Retrieve view-direction feature
    # Pdir uses theta and phi. 
    # Mapping angles to [0, 1] for interpolation.
    # Theta: [0, 2pi], Phi: [0, pi] (or similar spherical mapping)
    # Source does not specify exact angle-to-coordinate mapping, but implies direct projection.
    # Standard spherical to UV: u = theta / 2pi, v = phi / pi
    u_dir = theta / (2 * np.pi)
    v_dir = phi / np.pi
    
    v_pdir = bilinear_interpolate(planes['Pdir'], u_dir, v_dir)
    
    # 4. Compute Density
    sigma = decoders['Dc'](v_p)
    
    # 5. Compute Radiance
    # Concatenate all 4 feature vectors
    v_concat = np.concatenate([v_xy, v_xz, v_yz, v_pdir])
    radiance = decoders['Df'](v_concat)
    
    return sigma, radiance
```

**Parameters**
*   $N$: Positional plane resolution. Typical value $N=200$ for LR training from 100px images [S1, unofficial].
*   $N_{dir}$: View-direction plane resolution. Must be smaller than $N$ ($N_{dir} < N$). Typical value $N_{dir}=32$ [S1, unofficial].
*   $C$: Channel count. Typical value $C=48$ [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Plane Resolution:** If $N$ is too small, high visual frequencies are prohibited. If $N$ is too large, plane regions have insufficient information from LR images, causing artifacts [S1, unofficial].
*   **View-Direction Dependency:** Omitting $P_{dir}$ causes significant performance drops, especially for shiny/reflective objects with non-uniform lighting. PSNR drops from ~29.6 dB to ~23.7 dB in reported experiments [S1, unofficial].
*   **Density Independence:** Volume density $\sigma$ does not vary with viewing direction. Therefore, $P_{dir}$ is not used in the density decoder $D_c$ [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of rays sampled and the MLP depth (4 layers, 128 channels). Bilinear interpolation is $O(1)$.
*   **Memory Complexity:** $4 \times N \times N \times C$ for the planes. With $N=200, C=48$, this is $4 \times 40000 \times 48 \approx 7.68$ million floats (~30 MB for FP32).
*   **Strengths:** Computationally efficient volumetric super-resolution; leverages 2D SR techniques; explicit feature planes allow for easier manipulation than implicit coordinates.
*   **Limitations:** Requires careful tuning of plane resolution $N$ relative to input image resolution; view-direction plane is critical for reflective scenes.
*   **When to use:** When volumetric super-resolution from low-resolution inputs is required, or when 2D SR priors are beneficial.
*   **When not to use:** For scenes with extreme geometric complexity that cannot be captured by 2D plane projections, or if high-frequency details are needed without sufficient LR input information.

## Background
Quadri-Plane Radiance Fields were proposed in "Neural Volume Super-Resolution" [S1, unofficial]. The method builds on the feature plane representation introduced by Chan et al. [9] for human faces, extending it to general scenes by adding a view-direction plane and using coarse/fine decoders [S1, unofficial]. It is designed to integrate with neural volume rendering frameworks [32] (likely referring to the original NeRF paper).
