# HexPlane


## Overview
HexPlane is an explicit representation for dynamic 3D scenes that decomposes a 4D spacetime grid into six feature planes spanning each pair of coordinate axes (e.g., XY, ZT) [S1]. It computes features for points in spacetime by projecting the point onto each feature plane, aggregating the six resulting feature vectors, and passing the fused vector to a tiny MLP to predict color [S1]. It sets itself apart from implicit NeRF variants by avoiding large MLPs and deformation fields, achieving comparable or better synthesis quality for dynamic novel view synthesis with over 100× acceleration [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of posed and timestamped images of a dynamic scene.
*   **Outputs:** A radiance field function $f_\theta(\mathbf{x}, \mathbf{d})$ that outputs volume density (opacity) and color $\mathbf{c}$ for a query point $\mathbf{x}=(x,y,z)$ and time $t$, and view direction $\mathbf{d}$.

**Data Structures:**
The representation consists of two separate HexPlane structures: one for opacity and one for appearance features.
*   **HexPlane Structure:** Comprises three pairs of feature planes. Each pair consists of a spatial plane and a spatio-temporal plane with orthogonal axes.
    *   Pair 1: $M^{XY} \in \mathbb{R}^{X \times Y}$ and $M^{ZT} \in \mathbb{R}^{Z \times T}$
    *   Pair 2: $M^{XZ} \in \mathbb{R}^{X \times Z}$ and $M^{YT} \in \mathbb{R}^{Y \times T}$
    *   Pair 3: $M^{YZ} \in \mathbb{R}^{Y \times Z}$ and $M^{XT} \in \mathbb{R}^{X \times T}$
    *   Note: The source defines the third pair as $M^{YZ}$ and $M^{XT}$ in the formula, but the text lists $M^{YZ}$ and $M^{XT}$ as the third term. The axes covered are XY, XZ, YZ (spatial) and ZT, YT, XT (spatio-temporal).
*   **Rank Vectors:** For each pair $i \in \{1, 2, 3\}$, there is a rank $R_i$. The planes are indexed by $r=1 \dots R_i$.
*   **VRF Matrix:** A matrix $V^{RF} \in \mathbb{R}^{R \times F}$ where $R = R_1 + R_2 + R_3$ and $F$ is the feature size. This matrix is shared across the three terms in the stacked formulation.
*   **Emptiness Voxel:** A tiny 3D voxel grid indicating empty regions, computed by evaluating opacities across time steps and reducing them to a single voxel using maximum opacities [S1].

**Parameters:**
*   $N$: Spatial resolution (e.g., 512).
*   $T$: Temporal resolution (e.g., 32).
*   $F$: Feature size (e.g., 3 for RGB).
*   $R_i$: Basis number for each pair. Typical values: 8, 12, 16, 24, 48, 96.
    *   Plenoptic Video Appearance: $R_1=48, R_2=24, R_3=24$.
    *   Plenoptic Video Opacity: $R_1=24, R_2=12, R_3=12$.
    *   D-NeRF Appearance: $R_1=R_2=R_3=48$.
    *   D-NeRF Opacity: $R_1=R_2=R_3=24$.
*   Coordinate System: Normalized Device Coordinates (NDC) for bounded scenes, or Spherical Coordinates for unbounded scenes [S1].

**Numbered Steps:**

1.  **Query Opacity:** For a query point $(x, y, z, t)$, query the opacity HexPlane to get a scalar opacity value $\sigma$.
    *   If using NDC, coordinates are normalized. If using Spherical, re-parameterize $(x, y, z)$ to $(\theta, \phi, r)$ where $r = 1/\sqrt{x^2+y^2+z^2}$ [S1].
2.  **Query Appearance Features:** If $\sigma$ is high (above a threshold), query the appearance HexPlane to get a feature vector $\mathbf{f} \in \mathbb{R}^F$.
3.  **Color Regression:** Pass $\mathbf{f}$, the point coordinates $(x, y, z, t)$, and view direction $\mathbf{d}$ to a tiny MLP to regress RGB color $\mathbf{c}$ [S1].
4.  **Volume Rendering:** Render images via differentiable volumetric rendering along rays using the predicted color and opacity, following the standard volume rendering integral defined in the parent article [S1].
5.  **Optimization:** Train the HexPlane and the MLP using photometric loss between rendered images and ground-truth images.

**Feature Query Formula:**
The HexPlane representation $D$ for a 4D feature volume is defined as [S1]:
$$
D(x, y, z, t) = (\mathbf{P}_{xy\bullet}^{XYR1} \odot \mathbf{P}_{xt\bullet}^{ZTR1}) \mathbf{V}^{R1F} + (\mathbf{P}_{xz\bullet}^{XZR2} \odot \mathbf{P}_{yt\bullet}^{YTR2}) \mathbf{V}^{R2F} + (\mathbf{P}_{yz\bullet}^{YZR3} \odot \mathbf{P}_{xt\bullet}^{XTR3}) \mathbf{V}^{R3F}
$$
where $\odot$ is elementwise product, $\mathbf{P}$ tensors stack planes, $\mathbf{V}$ tensors stack vectors, and subscripts denote bilinear interpolation.
Alternatively, in stacked form [S1]:
$$
[\mathbf{P}_{xy}^{XYR1} \odot \mathbf{P}_{xt}^{ZTR1}, \mathbf{P}_{xz}^{XZR2} \odot \mathbf{P}_{yt}^{YTR2}, \mathbf{P}_{yz}^{YZR3} \odot \mathbf{P}_{xt}^{XTR3}]^T \mathbf{V}^{RF}
$$
where $[\cdot, \cdot]$ concatenates vectors.

def bilinear_interpolate(grid, u, v):
    """
    Perform bilinear interpolation on a 2D grid at normalized coordinates (u, v).
    grid: np.ndarray of shape (H, W)
    u, v: float in [0, 1]
    Returns: float
    """
    H, W = grid.shape
    # Map [0, 1] to [0, H-1] and [0, W-1]
    u_idx = u * (H - 1)
    v_idx = v * (W - 1)
    
    u0 = int(np.floor(u_idx))
    v0 = int(np.floor(v_idx))
    u1 = min(u0 + 1, H - 1)
    v1 = min(v0 + 1, W - 1)
    
    u_frac = u_idx - u0
    v_frac = v_idx - v0
    
    # Interpolate
    val = (1 - u_frac) * (1 - v_frac) * grid[u0, v0] + \
          (1 - u_frac) * v_frac * grid[u0, v1] + \
          u_frac * (1 - v_frac) * grid[u1, v0] + \
          u_frac * v_frac * grid[u1, v1]
    return val

**Edge Cases and Pitfalls:**
*   **Out-of-Boundary Points:** HexPlane is limited to bounded scenes because grid sampling fails for out-of-boundary points. NDC requires bounded x, y values and faces forwarding assumptions, leading to artifacts and incorrect geometries at extreme views [S1].
*   **Fast Motion/Sparse Observations:** HexPlane generates degraded results when objects move too fast or there are too few observations to synthesize details. The basis-sharing mechanism is less effective than deformation fields for scenes with extremely sparse observations [S1].
*   **Artifacts:** Explicit representations like HexPlane are prone to artifacts and color jittering, requiring strong regularizations [S1].
*   **Overfitting:** An unsuitable large rank $R$ may lead to overfitting, harming synthesis quality on novel views [S1].

## Operating characteristics
*   **Time Complexity:** Querying a HexPlane requires six bilinear interpolations and one vector-matrix product per term [S1]. Training is significantly faster than implicit methods due to the explicit representation.
*   **Memory Complexity:** Memory usage is reduced to $O(N^2 R + N T R + R F)$, where $N$ is spatial resolution, $T$ is time resolution, $R$ is rank, and $F$ is feature dimension [S1]. This is a reduction from the naive $O(N^3 T F)$ [S1].
*   **Measured Performance:**
    *   On Plenoptic Video dataset, HexPlane (650k iterations) achieves 29.470 PSNR, 0.018 D-SSIM, 0.078 LPIPS, 8.16 JOD in 12 GPU hours (112x speedup over DyNeRF) [S1].
    *   On Plenoptic Video dataset, HexPlane† (100k iterations) achieves 29.263 PSNR, 0.020 D-SSIM, 0.097 LPIPS, 8.14 JOD in 2 GPU hours (672x speedup over DyNeRF) [S1].
    *   On D-NeRF dataset, HexPlane achieves 31.04 PSNR, 0.97 SSIM, 0.04 LPIPS in 11 minutes training time [S1].
    *   Model size is 200MB [S1].
*   **Strengths:** High efficiency, explicit representation, no deformation fields needed, robust to different fusion mechanisms and coordinate systems.
*   **Limitations:** Limited to bounded scenes (unless spherical coordinates are used), prone to artifacts, less effective than deformation fields for extremely sparse observations.

## Background
HexPlane was introduced by Ang Cao and Justin Johnson from the University of Michigan, Ann Arbor [S1]. It is based on the idea of factored representations for static scenes, extending them to 4D spacetime for dynamic scenes [S1]. It is most closely related to K*-Planes, which also employs six feature planes for representation [S1].
