# DINER

Also called: DINER (Depth-aware Image-based NEural Radiance fields), Depth-aware Image-based NEural Radiance fields

## Overview
DINER is a method for novel view synthesis that reconstructs a volumetric scene representation (NeRF) from a sparse set of RGB input views by leveraging predicted dense depth maps to guide geometry estimation and sampling efficiency [S1]. Unlike sibling methods that rely on sparse landmarks or implicit correspondence search, which fail under large camera disparities, DINER uses off-the-shelf depth estimators to provide dense geometric priors, enabling high-quality reconstruction from views with significant relative distance [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ source RGB images $\{I^{(i)}\}_{i=1}^N$ with known camera intrinsics $K^{(i)}$ and extrinsics $P^{(i)}$ (comprising rotation $R^{(i)}$ and translation $t^{(i)}$). Typical $N=4$ [S1].
*   **Outputs:** A radiance field function $f_\theta(\mathbf{x}, \mathbf{d})$ that outputs volume density $\sigma$ and color $\mathbf{c}$, enabling the rendering of novel views via volumetric integration [S1].

**Data Structures:**
*   **Feature Maps:** $W^{(i)} \in \mathbb{R}^{H \times W \times C_{feat}}$, where $C_{feat}=512$ [S1].
*   **Depth Maps:** $D^{(i)} \in \mathbb{R}^{H \times W}$, predicted depth for each source view [S1].
*   **Neural Network Parameters:**
    *   Encoder $E$: 2D convolutional network mapping images to feature maps [S1].
    *   MLP Part 1 ($f_1$): Processes per-view features. Input dimension depends on encoded coordinates and features. Output dimension $C_{inter}$ (intermediate features) [S1].
    *   MLP Part 2 ($f_2$): Aggregates and regresses final values. Input dimension $C_{inter}$. Output dimension $C_{out} = C_{color} + 1$ (color + density) [S1].

**Step-by-Step Method:**

1.  **Depth Estimation:**
    For each source view $i$, estimate the depth map $D^{(i)}$ using a state-of-the-art depth estimation network [S1].

2.  **Source Feature Extrapolation (Padding & Encoding):**
    To handle extrapolation beyond source frustums:
    *   Pad each input image $I^{(i)}$ by 64 pixels by repeating border values [S1].
    *   Compute normalized pixel coordinates $\mathbf{uv} \in [-1, +1]^2$ for the padded image [S1].
    *   Apply positional encoding $\gamma_{uv}$ to $\mathbf{uv}$ using 4 exponentially increasing frequencies starting with 0.5. This results in an 18-channel map [S1].
    *   Set the positional encoding to 0 for all pixels belonging to the original (unpadded) image region [S1].
    *   Concatenate the padded image and the positional encoding map.
    *   Extract per-view feature maps $W^{(i)}$ using the encoder $E$:
        $$ W^{(i)} = E(\text{Padded } I^{(i)}, \gamma_{uv}) $$
        [S1]

3.  **Ray Sampling and Projection:**
    For a target ray $\mathbf{r}(t) = \mathbf{o} + t \cdot \mathbf{d}$:
    *   Sample 3D points $\mathbf{x}_j$ along the ray within the near/far planes [S1].
    *   Transform the sample point $\mathbf{x}$ and view direction $\mathbf{d}$ into the coordinate system of each source view $i$:
        $$ \mathbf{x}^{(i)} = P^{(i)} \circ \mathbf{x} $$
        $$ \mathbf{d}^{(i)} = R^{(i)} \circ \mathbf{d} $$
        [S1]
    *   Project $\mathbf{x}^{(i)}$ onto the 2D plane of source view $i$ to obtain pixel coordinates, then interpolate the feature vector $\boldsymbol{\omega}^{(i)}$ from $W^{(i)}$:
        $$ \boldsymbol{\omega}^{(i)} = W^{(i)}[K^{(i)} \circ \mathbf{x}^{(i)}] $$
        [S1]
    *   Compute the depth deviation $\Delta z^{(i)}$ between the sample's z-coordinate in the source camera frame and the predicted depth $D^{(i)}$ at the projected pixel location [S1].

4.  **Depth-Aware Conditioning:**
    *   Compute the positional encoding $\gamma_{\Delta z}$ for the depth deviation $\Delta z^{(i)}$. Use 6 frequency channels with a base frequency of 1 meter, resulting in a 13-dimensional vector [S1].
    *   Concatenate $\gamma_{\Delta z}$ with the feature vector $\boldsymbol{\omega}^{(i)}$ [S1].

5.  **Per-View Feature Processing ($f_1$):**
    *   Process the transformed coordinates, direction, features, and depth conditioning through the first MLP part $f_1$ for each view $i$ independently:
        $$ \mathbf{V}^{(i)} = f_1(\mathbf{x}^{(i)}, \mathbf{d}^{(i)}, \boldsymbol{\omega}^{(i)}, \gamma_{\Delta z}) $$
        [S1]

6.  **Feature Aggregation ($f_2$):**
    *   Average pool the intermediate feature vectors across all $N$ views:
        $$ \bar{\mathbf{V}} = \frac{1}{N} \sum_{i=1}^N \mathbf{V}^{(i)} $$
        [S1]
    *   Regress the final color $\mathbf{c}$ and opacity $\sigma$ using the second MLP part $f_2$:
        $$ (\mathbf{c}, \sigma) = f_2(\bar{\mathbf{V}}) $$
        [S1]

7.  **Depth-Guided Sampling:**
    To improve sampling efficiency, DINER employs a specific sampling strategy [S1]:
    *   Generate 1000 candidate samples per ray based on the predicted depth distribution [S1].
    *   Shortlist 25 samples closest to the estimated surface [S1].
    *   Add 15 samples using Gaussian boosting around the shortlisted points [S1].
    *   Total samples contributing to the final ray color: 40 [S1].
    *   *Note:* Normal maps for backface culling are obtained by calculating central differences on depth maps using $3 \times 3$ convolutional kernels, filtering out foreground-background edges [S1].

8.  **Volumetric Rendering:**
    Compute the final pixel color $\hat{\mathbf{C}}(\mathbf{r})$ using standard volume rendering integration:
    $$ \hat{\mathbf{C}}(\mathbf{r}) = \sum_{j=1}^{M} T_j (1 - \exp(-\sigma_j \delta_j)) \mathbf{c}_j $$
    where $T_j = \exp\left(-\sum_{k=1}^{j-1} \sigma_k \delta_k\right)$, $\delta_j$ is the distance between adjacent samples, and $M=40$ [S1].

import numpy as np

def positional_encoding_depth(z, num_freqs=6, base_freq=1.0):
    """
    Computes positional encoding for depth deviation.
    6 frequency channels, base frequency 1 meter.
    Returns 13-dim vector (sin/cos pairs + original).
    """
    # Standard NeRF PE: sin(2^i * pi * x)
    # 6 freqs -> 12 dims + 1 original = 13 dims
    scales = np.array([2.0**i for i in range(num_freqs)]) * base_freq
    encoded = []
    for scale in scales:
        encoded.append(np.sin(z * scale))
        encoded.append(np.cos(z * scale))
    encoded.append(z) # Original value
    return np.concatenate(encoded)

def positional_encoding_uv(uv, num_freqs=4, start_freq=0.5):
    """
    Computes positional encoding for UV coordinates.
    4 exponentially increasing frequencies starting with 0.5.
    Returns 18-dim vector (sin/cos pairs).
    """
    # 4 freqs -> 8 dims per coordinate -> 16 dims total?
    # Source says 18-channel map. 
    # UV is 2D. 4 freqs * 2 (sin/cos) * 2 (u,v) = 16.
    # Plus original U, V? 16 + 2 = 18.
    encoded = []
    for i in range(num_freqs):
        freq = start_freq * (2.0 ** i)
        encoded.append(np.sin(uv * freq))
        encoded.append(np.cos(uv * freq))
    encoded.append(uv[..., 0]) # u
    encoded.append(uv[..., 1]) # v
    return np.concatenate(encoded, axis=-1)

def volumetric_render(t, colors, sigmas):
    """
    Standard volumetric rendering.
    """
    # Calculate deltas
    deltas = np.diff(t)
    # Handle first sample if needed, usually deltas are between samples
    # Assuming t is sorted
    deltas = np.append(deltas, 0) # Or handle boundary
    
    # Calculate transmittance
    # T_i = exp(-sum_{j=1}^{i-1} sigma_j * delta_j)
    alpha = 1 - np.exp(-sigmas * deltas)
    
    # Transmittance
    # T_1 = 1
    # T_i = T_{i-1} * (1 - alpha_{i-1})
    T = np.ones_like(alpha)
    for i in range(1, len(alpha)):
        T[i] = T[i-1] * (1 - alpha[i-1])
        
    # Color
    C = np.sum(T * alpha * colors, axis=0)
    return C

*   $f_1, f_2$: MLP parts. $f_1$ input dimension is $13 + 512 = 525$ (plus $\mathbf{x}^{(i)}, \mathbf{d}^{(i)}$? Source says "processed... into intermediate feature vectors". The "Depth Awareness" section adds $\Delta z$. It is implied that $\mathbf{x}^{(i)}$ and $\mathbf{d}^{(i)}$ are still inputs. [S1].
*   Loss Weights: $w_l = 1.0$, $w_{vgg} = 0.1$, $w_{ab} = 5.0$ (or $1.0$ for DTU dataset) [S1].
*   Patch Size: $64 \times 64$ pixels for loss evaluation (downsampled to $8 \times 8$ for Lab dataset) [S1].

**Edge Cases and Pitfalls:**
*   **Extrapolation:** Standard image-based NeRFs suffer artifacts when rendering views outside the source frustums. DINER handles this by padding input images and positionally encoding the padded regions [S1].
*   **Large Disparities:** Implicit correspondence search fails when source cameras are far apart. DINER uses dense depth maps instead of sparse landmarks, which are not restricted to specific object categories [S1].
*   **Depth Accuracy:** Synthesis quality improves with depth accuracy up to a standard deviation of 1mm noise. Higher accuracy yields no further improvement [S1].
*   **Backface Culling:** Normal maps are derived from depth maps using $3 \times 3$ central difference kernels. Foreground-background edges are filtered out to prevent incorrect normals [S1].

## Operating characteristics
*   **Time Complexity:** Rendering a $256 \times 256$ image takes approximately two seconds [S1]. This is considered slow compared to real-time methods, though sampling efficiency is improved via depth guidance [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Depth-guided sampling reduces median Chamfer distance by 33% and maximum Chamfer distance by a factor of 4 compared to coarse-to-fine sampling with the same number of points [S1].
*   **Strengths:** Can process input views with high relative distance; does not require per-scene optimization; works on general objects and human heads [S1].
*   **Limitations:** Rendering speed is slow; performance is bound by the accuracy of the depth estimation network [S1].

## Background
DINER was proposed by Malte Prinzler, Justus Thies, and Otmar Hilliges from the Max Planck Institute for Intelligent Systems, ETH Zürich, and the Max Planck ETH Center for Learning Systems [S1]. It was published in CVPR 2023 [S1]. The method builds on the pixelNeRF pipeline [S1]. It addresses the limitations of previous methods that relied on sparse landmarks or implicit correspondence, which deteriorate with large viewpoint changes or specific object classes [S1].
