# DINER

Also called: DINER (Depth-aware Image-based NEural Radiance fields), Depth-aware Image-based NEural Radiance fields

## Overview
DINER is a method for novel view synthesis from sparse input views that predicts depth and feature maps to guide the reconstruction of a volumetric scene representation [S1]. It solves the problem of high relative distance between source cameras, where standard image-based NeRFs fail due to implicit correspondence search limitations and extrapolation artifacts [S1]. Unlike siblings that rely on sparse landmarks or implicit correspondence, DINER leverages dense depth maps for geometry guidance and uses positional encoding with padding to handle feature extrapolation beyond source frustums [S1].

## How it works
**Inputs and Outputs:**
- **Inputs:** $N$ source RGB images $\{I^{(i)}\}_{i=1}^N$ with known camera intrinsics $K^{(i)}$ and extrinsics $P^{(i)}$ (typically $N=4$) [S1].
- **Outputs:** A rendered color $\hat{C}(\mathbf{r})$ for a target ray $\mathbf{r}$ [S1].

**Data Structures:**
- **Feature Maps:** $W^{(i)} \in \mathbb{R}^{H \times W \times C_{feat}}$, where $C_{feat}=512$ [S1].
- **Depth Maps:** $D^{(i)} \in \mathbb{R}^{H \times W}$, estimated from $I^{(i)}$ [S1].
- **Positional Encoding:** 13-dimensional vector for depth deviation (6 frequencies, base 1m) concatenated with 512-dimensional feature vector [S1].

**Steps:**

1.  **Depth Estimation:** Estimate depth maps $D^{(i)}$ for each source view using a state-of-the-art depth estimation network [S1].
2.  **Feature Extraction with Extrapolation:**
    - Pad input images $I^{(i)}$ by 64 pixels by repeating border values [S1].
    - Compute positional encoding for normalized pixel coordinates $\mathbf{uv} \in [-1, +1]$ using 4 exponentially increasing frequencies starting at 0.5, resulting in an 18-channel map set to 0 for unpadded regions [S1].
    - Concatenate the padded image and positional encoding map [S1].
    - Apply 2D-convolutional encoder $E$ to extract feature maps: $W^{(i)} = E(I^{(i)})$ [S1].
3.  **Ray Sampling:** For a target ray $\mathbf{r}(t) = \mathbf{o} + t \cdot \mathbf{d}$, generate 1000 candidate samples [S1].
4.  **Depth-Guided Shortlisting:**
    - Shortlist 25 samples closest to the estimated depth [S1].
    - Add 15 samples via Gaussian boosting around the depth estimate [S1].
    - Total samples contributing to color: 40 [S1].
    - *Note:* Normal maps for backface culling are obtained by central difference on depth maps using $3 \times 3$ kernels, filtering foreground-background edges [S1].
5.  **View Transformation:** For each sample point $\mathbf{x}$ and direction $\mathbf{d}$, transform to source view coordinates:
    $$ \mathbf{x}^{(i)} = P^{(i)} \circ \mathbf{x}, \quad \mathbf{d}^{(i)} = R^{(i)} \circ \mathbf{d} $$
    [S1]
6.  **Feature Interpolation:** Project $\mathbf{x}^{(i)}$ onto feature map $W^{(i)}$ to interpolate feature vector $\boldsymbol{\omega}^{(i)}$:
    $$ \boldsymbol{\omega}^{(i)} = W^{(i)}[K^{(i)} \circ \mathbf{x}^{(i)}] $$
    [S1]
7.  **Depth Deviation:** Compute deviation $\Delta z$ between sample location $z$-coordinate in camera space and estimated depth $D^{(i)}$ [S1].
8.  **Positional Encoding of Depth:** Encode $\Delta z$ using 6 frequency channels with base frequency 1m, resulting in a 13-dimensional vector $\gamma(\Delta z)$ [S1].
9.  **Intermediate Feature Regression ($f_1$):** Process inputs through first MLP part $f_1$ for each view independently:
    $$ \mathbf{V}^{(i)} = f_1(\mathbf{x}^{(i)}, \mathbf{d}^{(i)}, \boldsymbol{\omega}^{(i)}, \gamma(\Delta z)) $$
    [S1]
10. **Feature Aggregation:** Average pool intermediate features across all $N$ views:
    $$ \bar{\mathbf{V}} = \text{mean}_i \mathbf{V}^{(i)} $$
    [S1]
11. **Color and Density Regression ($f_2$):** Process averaged features through second MLP part $f_2$:
    $$ (\mathbf{c}, \sigma) = f_2(\bar{\mathbf{V}}) $$
    [S1]
12. **Volumetric Rendering:** Render final color $\hat{C}(\mathbf{r})$:
    $$ \hat{C}(\mathbf{r}) = \sum_{j=1}^{M} T_j (1 - \exp(-\sigma_j \delta_j)) \mathbf{c}_j $$
    where $M=40$ samples, $\delta_j$ is distance between samples, and $T_j = \exp(-\sum_{k=1}^{j-1} \sigma_k \delta_k)$ [S1].

**Parameters:**
- $N$: Number of source images. Typical value: 4 [S1].
- $f_1, f_2$: MLP parts. $f_1$ input dimension depends on $\mathbf{x}^{(i)}, \mathbf{d}^{(i)}, \boldsymbol{\omega}^{(i)}$ (512), and $\gamma(\Delta z)$ (13) [S1].
- Loss weights: $w_l = 1.0$, $w_{vgg} = 0.1$, $w_{ab} = 5.0$ (or $1.0$ for DTU) [S1].
- Patch size for loss: $64 \times 64$ pixels (downsampled to $8 \times 8$ for Lab) [S1].

**Edge Cases and Pitfalls:**
- **Extrapolation:** Standard image-based NeRFs fail outside source frustums. DINER handles this by padding images by 64 pixels and using positional encoding set to 0 in unpadded regions [S1].
- **Large Disparity:** Implicit correspondence fails with large camera distances. DINER uses dense depth maps instead of sparse landmarks [S1].
- **Depth Accuracy:** Synthesis quality improves with depth accuracy up to a standard deviation of 1mm noise; higher accuracy yields no further improvement [S1].

## Operating characteristics
- **Time Complexity:** Synthesis of a $256 \times 256$ pixel image takes two seconds [S1].
- **Memory Complexity:** Not given in the sources.
- **Performance:** Depth-guided sampling reduces median Chamfer distance by 33% and maximum Chamfer distance by a factor of 4 compared to coarse-to-fine sampling with the same number of points [S1].
- **Strengths:** Handles input views with high relative distance; improves sampling efficiency by focusing samples near the surface; avoids sparse landmark limitations [S1].
- **Limitations:** Rendering speed is slow (2s for 256x256); relies on the accuracy of the depth estimation network [S1].
- **When to use:** When input views have high disparity and dense geometry guidance is beneficial.
- **When not to use:** When real-time rendering is required or depth estimation is unreliable [S1].

## Background
DINER was presented by Malte Prinzler, Justus Thies, and Otmar Hilliges in 2023 [S1]. It builds on the pixelNeRF pipeline and addresses limitations in image-based NeRFs regarding sparse views and large camera disparities [S1]. The method was evaluated on the FaceScape and DTU datasets [S1].
