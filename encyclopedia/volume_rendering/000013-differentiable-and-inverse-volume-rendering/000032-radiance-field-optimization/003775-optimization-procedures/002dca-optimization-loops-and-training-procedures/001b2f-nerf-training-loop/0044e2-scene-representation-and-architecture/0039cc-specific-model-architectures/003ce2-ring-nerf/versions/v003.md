# RING-NeRF

Also called: Distance-Aware Coarse-To-Fine, RING-NeRF pipeline, Residual Implicit Neural Grids

## Overview
RING-NeRF is a neural field architecture that represents 3D scenes using a continuous, unbounded multi-scale grid hierarchy and a position/scale-invariant decoder latent space [S1]. It solves the problem of aliasing artifacts and resolution adaptation when varying observation distances by computing a distance-aware Level of Detail (LOD) for each sample and using a continuous coarse-to-fine optimization strategy [S1]. Unlike sibling methods that require explicit LOD supervision or concatenate positional encodings with grid features, RING-NeRF induces intrinsic LOD through its grid structure and summation-based feature aggregation, allowing for dynamic resolution extension without retraining the decoder [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera poses, image resolutions, and training views. Optional: Depth/SDF supervision for surface reconstruction.
*   **Outputs:** Rendered pixel colors $\hat{C}(\mathbf{r})$ and optimized grid parameters.

**Data Structures:**
*   **Unbounded Hierarchical 3D Grid:** A pyramid of $N$ grids. The resolution of the $i$-th grid is $f^i b$, where $b$ is the base resolution and $f$ is the growth factor.
*   **Grid Layout:** Each grid stores latent feature vectors of size $D_{feat}$. The grids are accessed via linear interpolation.
*   **Decoder:** A small Multi-Layer Perceptron (MLP) and a Random Fourier Feature (RFF) layer.

**Parameters:**
*   $b$: Base grid resolution (e.g., 16).
*   $f$: Growth factor (e.g., 2).
*   $D_{feat}$: Feature size per grid (e.g., 8).
*   $N_{samples}$: Number of samples per ray (e.g., 128).
*   $l_0$: Initial maximal LOD for coarse-to-fine optimization.
*   $n_{ctf}$: Hyperparameter controlling the speed of LOD increase.
*   $c$: Pixel size at distance 1, derived from image resolution and camera FOV.
*   $W_{RFF}$: Linear matrix for RFF mapping (no bias).

**Algorithm Steps:**

1.  **Scene Representation (Recursive Grid Definition):**
    The scene is represented by a mapping function defined recursively. Let $G_i$ be the grid at level $i$ and $\delta_i$ be the latent feature deviation stored in $G_i$. The mapping function $G_L$ for a continuous LOD $L$ is defined as [S1]:
    $$
    G_0 \leftarrow \delta_0
    $$
    $$
    G_N \leftarrow S(G_{N-1}) + \delta_N
    $$
    where $S$ is a subdivision scheme that increases the resolution of $G_{N-1}$ to the resolution of $G_N$ via tri-linear interpolation. For a continuous LOD $L \in [N-1, N]$, the feature is computed as [S1]:
    $$
    G_L \leftarrow S(G_{N-1}) + \alpha \delta_N
    $$
    where $\alpha = L - (N - 1)$.

2.  **Distance-Aware Forward Mapping (LOD Calculation):**
    For a sample at distance $d$ from the camera and location $p$ in contracted space, calculate the LOD $L$ by equating the cone volume in contracted space to the virtual grid cell volume [S1]:
    $$
    L = - \frac {\log \left (d c b \sqrt [3]{\operatorname {det}(J(p))}\right )}{\log (f)}
    $$
    where $J(p)$ is the Jacobian of the contraction function at $p$, $b$ is the base grid resolution, $f$ is the growth factor, and $c$ is the pixel size at distance 1.

3.  **Feature Aggregation:**
    To obtain the latent feature $\mathbf{f}$ for a point at calculated LOD $L$:
    *   Identify all grid levels $i$ such that $i \le L$.
    *   For each level $i$, linearly interpolate the point in the cell of grid $G_i$ to get feature $\mathbf{v}_i$.
    *   Sum the interpolated features: $\mathbf{f} = \sum_{i=0}^{\lfloor L \rfloor} \mathbf{v}_i$.
    *   **Note:** Use summation, not concatenation, to maintain decoder invariance and generalization [S1].

4.  **Normalization and RFF:**
    *   Apply standard, non-learnable normalization (e.g., LayerNorm or InstanceNorm) to $\mathbf{f}$ to improve convergence stability [S1].
    *   Map the normalized feature to a higher dimension using Random Fourier Features: $\mathbf{z} = \sin(W_{RFF} \mathbf{f})$ [S1].

5.  **Decoding Density and Color:**
    *   Pass $\mathbf{z}$ through a linear layer to produce a density/sdf output and a single color feature $\mathbf{c}_{feat}$ [S1].
    *   Encode the viewing direction $\mathbf{d}$ using Spherical Harmonics (SH) encoding [S1].
    *   Concatenate $\mathbf{c}_{feat}$ and the SH-encoded direction.
    *   Feed the concatenated vector into a 3-layer MLP to predict the final radiance $\mathbf{c}$ [S1].
    *   If using SDF-based reconstruction, convert the SDF output to density $\sigma$ using a NEUS-like approach before rendering [S1].

6.  **Volume Rendering:**
    Compute the pixel color $\hat{C}(\mathbf{r})$ using standard volume rendering [S1]:
    $$
    \hat{C}(\mathbf{r}) = \sum_{i=0}^{N-1} T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i
    $$
    $$
    T_i = \exp\left(\sum_{j=0}^{i-1} \sigma_j \delta_j\right)
    $$
    where $\sigma_i$ is density, $\mathbf{c}_i$ is color, and $\delta_i$ is the distance between samples.

7.  **Continuous Coarse-To-Fine Optimization:**
    *   During training, clamp the samples' LOD up to a maximal LOD $l$.
    *   Grids of level $l$ and above are set to zero and not optimized.
    *   Update $l$ continuously using the scheduler [S1]:
        $$
        l = l_0 + n_{ctf}^n
        $$
        where $n$ is the current epoch, $n_{ctf}$ is the speed hyperparameter, and $l_0$ is the initial number of grids.
    *   This ensures all dimensions of the decoder latent space remain supervised, avoiding the need to refine decoder weights when new grids are activated [S1].

8.  **Loss Function:**
    Minimize the Mean Squared Error (MSE) loss [S1]:
    $$
    \mathcal{L} = ||\hat{C}(\mathbf{r}) - C(\mathbf{r})||_2
    $$
    For SDF reconstruction, add an Eikonal loss [S1].

**Pseudocode:**

```python
import math
import torch
import torch.nn as nn
import torch.nn.functional as F

class RINGNeRF:
    def __init__(self, base_res=16, growth_factor=2, num_levels=5, feat_size=8, 
                 rff_dim=256, mlp_hidden=64, l0=0.0, n_ctf=0.1):
        self.base_res = base_res
        self.f = growth_factor
        self.num_levels = num_levels
        self.feat_size = feat_size
        self.l0 = l0
        self.n_ctf = n_ctf
        
        # Initialize hierarchical grids
        # Grid i has resolution (base_res * f^i)
        self.grids = nn.ModuleList([
            nn.Embedding(base_res**3, feat_size) for i in range(num_levels)
        ])
        
        # Initialize embeddings with small random values
        for grid in self.grids:
            nn.init.normal_(grid.weight, std=0.01)
            
        # RFF Layer
        self.rff_weight = nn.Parameter(torch.randn(rff_dim, feat_size))
        
        # Decoder MLP
        # Input: rff_dim + sh_dim (direction)
        # Output: 3 (RGB)
        self.decoder_mlp = nn.Sequential(
            nn.Linear(rff_dim + 27, mlp_hidden), # Assuming SH degree 3 -> 27 coeffs
            nn.ReLU(),
            nn.Linear(mlp_hidden, mlp_hidden),
            nn.ReLU(),
            nn.Linear(mlp_hidden, 3)
        )
        
        # Linear layer for density and color feature from RFF output
        self.head_linear = nn.Linear(rff_dim, 1 + 1) # 1 for density/sdf, 1 for color feature
        
        # Normalization layer
        self.norm = nn.LayerNorm(feat_size)

    def get_lod(self, distance, det_jacobian):
        """
        Calculate LOD L based on distance and contraction Jacobian determinant.
        c: pixel size at distance 1. 
        Note: c is typically derived from camera FOV and image width. 
        For implementation, assume c is passed or computed externally.
        """
        # L = - log(d * c * b * det(J)^(1/3)) / log(f)
        # We assume c is a constant provided during forward pass or setup.
        # Here we return the formula structure.
        pass 

    def get_feature(self, pos, lod, c):
        """
        Get aggregated feature for position pos at continuous LOD.
        pos: (N, 3) coordinates in contracted space.
        lod: (N,) continuous LOD values.
        c: pixel size at distance 1.
        """
        aggregated_feat = torch.zeros_like(pos[:, :1]).expand(-1, self.feat_size)
        
        for i in range(self.num_levels):
            res = self.base_res * (self.f ** i)
            # Check if this level contributes to the current LOD
            # Level i contributes if i <= lod
            # We interpolate at this level's resolution
            # Map pos to grid coordinates [0, res-1]
            grid_coords = pos * (res - 1) # Assuming grid spans [-1, 1] mapped to [0, res-1]
            
            # Trilinear interpolation
            feat_i = self._trilinear_interpolate(self.grids[i], grid_coords, res)
            
            # Add to aggregated feature
            # The recursive definition implies summing deviations.
            # G_L = S(G_{N-1}) + alpha * delta_N
            # In practice, for continuous LOD, we sum the interpolated features 
            # of all levels <= L, weighted appropriately if L is not integer.
            # However, the source says: "interpolate linearly the point in the cell 
            # for each level inferior or equal to N, and sum the results."
            # And for continuous: G_L <- S(G_{N-1}) + alpha * delta_N.
            # This implies we sum the full features of levels < floor(L)
            # and the interpolated feature of level floor(L) weighted by alpha?
            # Actually, the source says: "interpolate ... for each level inferior or equal to N, and sum".
            # Let's implement the summation of interpolated features for all levels i <= L.
            
            # Determine if level i is included
            if i <= lod:
                # If lod is continuous, we might need to weight the last level?
                # The source eq 2: G_L <- S(G_{N-1}) + alpha * delta_N.
                # This suggests a residual structure.
                # Let's stick to the simpler interpretation from text: 
                # "interpolate linearly the point in the cell for each level inferior or equal to N, and sum the results."
                # This implies summing all levels up to the integer part of L? 
                # Or does it mean the continuous interpolation handles the weighting?
                # Given "summation replaces concatenation", we sum the features.
                aggregated_feat += feat_i
        
        # Apply normalization
        aggregated_feat = self.norm(aggregated_feat)
        
        # RFF
        rff_out = torch.sin(torch.matmul(aggregated_feat, self.rff_weight.T))
        
        # Head
        head_out = self.head_linear(rff_out)
        density = head_out[:, 0:1]
        color_feat = head_out[:, 1:2]
        
        return density, color_feat, rff_out

    def _trilinear_interpolate(self, embedding, coords, res):
        # coords: (N, 3) in [0, res-1]
        # embedding: (res^3, feat_size)
        # Standard trilinear interpolation
        x = coords[:, 0]
        y = coords[:, 1]
        z = coords[:, 2]
        
        x0 = torch.floor(x).long()
        y0 = torch.floor(y).long()
        z0 = torch.floor(z).long()
        x1 = x0 + 1
        y1 = y0 + 1
        z1 = z0 + 1
        
        # Wrap coordinates
        x0 = torch.clamp(x0, 0, res - 1)
        y0 = torch.clamp(y0, 0, res - 1)
        z0 = torch.clamp(z0, 0, res - 1)
        x1 = torch.clamp(x1, 0, res - 1)
        y1 = torch.clamp(y1, 0, res - 1)
        z1 = torch.clamp(z1, 0, res - 1)
        
        # Weights
        w_x = x - x0.float()
        w_y = y - y0.float()
        w_z = z - z0.float()
        
        # Gather
        v000 = embedding[z0 * res**2 + y0 * res + x0]
        v100 = embedding[z0 * res**2 + y0 * res + x1]
        v010 = embedding[z0 * res**2 + y1 * res + x0]
        v110 = embedding[z0 * res**2 + y1 * res + x1]
        v001 = embedding[z1 * res**2 + y0 * res + x0]
        v101 = embedding[z1 * res**2 + y0 * res + x1]
        v011 = embedding[z1 * res**2 + y1 * res + x0]
        v111 = embedding[z1 * res**2 + y1 * res + x1]
        
        # Interpolate
        c00 = v000 * (1 - w_x) + v100 * w_x
        c01 = v010 * (1 - w_x) + v110 * w_x
        c10 = v001 * (1 - w_x) + v101 * w_x
        c11 = v011 * (1 - w_x) + v111 * w_x
        
        c0 = c00 * (1 - w_y) + c01 * w_y
        c1 = c10 * (1 - w_y) + c11 * w_y
        
        c = c0 * (1 - w_z) + c1 * w_z
        
        return c

    def forward(self, rays_o, rays_d, lod_values, c, epoch):
        """
        rays_o: (N, 3) ray origins
        rays_d: (N, 3) ray directions
        lod_values: (N,) pre-calculated LODs for each sample
        c: pixel size at distance 1
        epoch: current training epoch
        """
        # Clamp LOD based on coarse-to-fine scheduler
        max_lod = self.l0 + self.n_ctf ** epoch
        lod_values = torch.clamp(lod_values, max=max_lod)
        
        # Get features
        density, color_feat, rff_out = self.get_feature(rays_o, lod_values, c)
        
        # Convert density if SDF
        # sigma = softplus(density) or NEUS conversion
        
        # Encode direction with Spherical Harmonics
        # Assuming SH degree 3 -> 27 coefficients
        sh_dir = self._encode_spherical_harmonics(rays_d, degree=3)
        
        # Concatenate color feature and direction
        # color_feat is (N, 1), sh_dir is (N, 27)
        combined = torch.cat([color_feat, sh_dir], dim=1)
        
        # Predict radiance
        radiance = self.decoder_mlp(combined)
        
        return density, radiance

    def _encode_spherical_harmonics(self, dirs, degree=3):
        # Simplified SH encoding
        # dirs: (N, 3) normalized
        x, y, z = dirs[:, 0], dirs[:, 1], dirs[:, 2]
        # Degree 0
        c0 = torch.ones_like(x)
        # Degree 1
        c1 = -y
        c2 = z
        c3 = -x
        # Degree 2
        c4 = x * y
        c5 = y * z
        c6 = 2 * z**2 - x**2 - y**2
        c7 = x * z
        c8 = x**2 - y**2
        # Degree 3
        c9 = x * (3 * y**2 - x**2)
        c10 = y * (3 * z**2 - y**2)
        c11 = z * (5 * z**2 - 3)
        c12 = x * (5 * z**2 - 1)
        c13 = y * (5 * z**2 - 1)
        c14 = x * y * z
        c15 = x * (x**2 - 3 * y**2)
        c16 = y * (3 * x**2 - y**2)
        
        return torch.stack([c0, c1, c2, c3, c4, c5, c6, c7, c8, 
                            c9, c10, c11, c12, c13, c14, c15, c16], dim=1)
```

## Operating characteristics
*   **Time Complexity:** Training time is comparable to I-NGP but faster than Mip-NeRF 360. On the 360 Dataset Mono-Scale setup, RING-NeRF achieves 28.09 PSNR in 0.45 hours on one Nvidia-A100 GPU [S1].
*   **Memory Complexity:** Memory usage scales with the number of grid levels and feature size. The hierarchical grid structure allows for dynamic resolution extension, optimizing memory by only storing necessary LODs [S1].
*   **Performance:**
    *   360 Dataset (Full Res): PSNR 28.09, SSIM 0.799, LPIPS 0.157 [S1].
    *   360 Dataset (1/2 Res): PSNR 27.18, SSIM 0.804, LPIPS 0.138 [S1].
    *   360 Dataset (1/4 Res): PSNR 25.82, SSIM 0.786, LPIPS 0.142 [S1].
    *   360 Dataset (1/8 Res): PSNR 24.38, SSIM 0.737, LPIPS 0.167 [S1].
    *   With Distance-Aware Coarse-To-Fine: PSNR 28.26, SSIM 0.803, LPIPS 0.155 [S1].
*   **Strengths:**
    *   Intrinsic continuous LOD without explicit supervision [S1].
    *   Robust to varying observation distances and few-view setups [S1].
    *   Dynamic resolution extension (unbounded LOD) [S1].
    *   Fast training times [S1].
*   **Limitations:**
    *   Requires careful tuning of the coarse-to-fine scheduler parameters ($l_0, n_{ctf}$) [S1].
    *   Performance may degrade if concatenation is used instead of summation for feature aggregation [S1].
    *   Does not use appearance embeddings, which may limit performance in scenes with complex lighting variations compared to methods that do [S1].

## Background
RING-NeRF was proposed by D. Petit et al. in the paper "RING-NeRF: Rethinking Inductive Biases for Versatile and Efficient Neural Fields" [S1]. It addresses limitations of standard NeRF architectures, such as aliasing at varying distances and the inability to dynamically increase resolution during training. The method builds on the principles of grid-based NeRFs like I-NGP but introduces specific inductive biases to enhance versatility and efficiency [S1].
