# Quadri-Plane Radiance Fields

Also called: 4-Plane Representation, Quadri-Plane Model

## Overview
Quadri-Plane Radiance Fields represent a 3D scene using four multi-channel 2D feature planes coupled with a decoder MLP, designed to enable computationally efficient volumetric super-resolution by leveraging 2D image super-resolution techniques [S1, unofficial]. Unlike standard NeRF which uses a dense 3D grid or a single MLP for all coordinates, this method decomposes the spatial and angular dependencies into explicit 2D planes, allowing for resolution scaling independent of the 3D volume discretization [S1, unofficial]. It sets itself apart from siblings like [HexPlane](11358-hexplane.md) by using exactly four planes (three spatial, one angular) rather than six spatial planes, and from [MultiPlaneNeRF](8875-multiplanenerf.md) by explicitly separating the view-direction dependency into a dedicated plane rather than relying solely on positional encoding or view-dependent MLPs.

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D position $\mathbf{p} \in \mathbb{R}^3$ and a viewing direction $\mathbf{d} \in \mathbb{R}^3$ (defined by azimuth $\theta$ and elevation $\phi$).
*   **Output:** Volume density $\sigma \in \mathbb{R}$ and RGB radiance $\mathbf{c} \in \mathbb{R}^3$.

**Data Structures:**
The scene representation $P_s$ consists of four 3D tensors (planes):
1.  Three positional planes: $P_{xy}, P_{xz}, P_{yz}$.
2.  One view-direction plane: $P_{dir}$.

Layout details:
*   Each positional plane has dimensions $N \times N \times C$.
*   The view-direction plane has dimensions $N_{dir} \times N_{dir} \times C$.
*   $N$ is the spatial resolution of the positional planes.
*   $N_{dir}$ is the resolution of the view-direction plane.
*   $C$ is the number of channels per plane.
*   Typical values for low-resolution (LR) training from 100px images: $N=200$, $N_{dir}=32$, $C=48$ [S1, unofficial].

**Decoders:**
Two fully-connected MLPs are used, both with 128 channels and 4 layers [S1, unofficial]:
1.  **Coarse Decoder ($D_c$):** Predicts density $\sigma$.
2.  **Fine Decoder ($D_f$):** Predicts density $\sigma$ (used for super-resolution or high-frequency detail).
3.  **Radiance Decoder ($D_r$):** Predicts RGB color. It has identical architecture to $D_c$ and $D_f$ (128 channels, 4 layers) [S1, unofficial].

**Algorithm:**
1.  **Directional Projection:** For a point $\mathbf{p}$, determine its viewing direction $(\theta_p, \phi_p)$ in spherical coordinates (azimuth and elevation).
2.  **Feature Retrieval (Positional):** Project $\mathbf{p}$ onto the three positional planes. Retrieve feature vectors $v_{xy}, v_{xz}, v_{yz}$ via bilinear interpolation at the projected 2D coordinates.
3.  **Feature Retrieval (Angular):** Project $(\theta_p, \phi_p)$ onto $P_{dir}$. Retrieve feature vector $v_{pdir}$ via bilinear interpolation.
4.  **Aggregation:** Compute the aggregated positional feature vector $v_p$ as the average of the positional plane features:
    $$ v_p = \frac{1}{3} (v_{xy} + v_{xz} + v_{yz}) $$
5.  **Density Prediction:**
    *   Input $v_p$ to $D_c$ to get coarse density $\sigma_c$.
    *   Input $v_p$ to $D_f$ to get fine density $\sigma_f$.
    *   (In super-resolution contexts, $\sigma_f$ is used for the final output, or $\sigma_c$ and $\sigma_f$ are combined; the source specifies using $D_c$ and $D_f$ for density [S1, unofficial]).
6.  **Radiance Prediction:**
    *   Concatenate the aggregated positional feature $v_p$ and the directional feature $v_{pdir}$: $v_{concat} = [v_p; v_{pdir}]$.
    *   Input $v_{concat}$ to $D_r$ to predict RGB radiance $\mathbf{c}$.
    *   Note: $v_{pdir}$ is *not* used for density prediction, as volume density is view-independent [S1, unofficial].
7.  **Rendering:** Use the predicted $\sigma$ and $\mathbf{c}$ in the standard volumetric rendering equation [S1, unofficial]:
    $$ C(\mathbf{r}) = \sum_{i=1}^N T_i \alpha_i \mathbf{c}_i, \quad \alpha_i = 1 - \exp(-\sigma_i \delta_i), \quad T_i = \prod_{j=1}^{i-1} (1 - \alpha_j) $$

**Pseudocode:**

```python
import numpy as np

def bilinear_interpolate(plane, u, v):
    """
    Perform bilinear interpolation on a 2D plane (H, W, C) at normalized coordinates (u, v).
    u, v are in [0, 1].
    """
    H, W, C = plane.shape
    # Map to pixel coordinates
    u_px = u * (W - 1)
    v_px = v * (H - 1)
    
    # Floor and ceil
    u0 = np.floor(u_px).astype(int)
    v0 = np.floor(v_px).astype(int)
    u1 = np.minimum(u0 + 1, W - 1)
    v1 = np.minimum(v0 + 1, H - 1)
    
    # Weights
    w_u = u_px - u0
    w_v = v_px - v0
    
    # Interpolate
    # plane[v, u] -> plane[v_px, u_px]
    val00 = plane[v0, u0]
    val01 = plane[v0, u1]
    val10 = plane[v1, u0]
    val11 = plane[v1, u1]
    
    val0 = val00 * (1 - w_u) + val01 * w_u
    val1 = val10 * (1 - w_u) + val11 * w_u
    
    return val0 * (1 - w_v) + val1 * w_v

def quadri_plane_query(positions, directions, planes, N, N_dir, C):
    """
    Query the quadri-plane representation.
    
    Args:
        positions: (N_rays, 3) array of 3D points.
        directions: (N_rays, 3) array of viewing directions.
        planes: Dictionary containing 'P_xy', 'P_xz', 'P_yz' (N, N, C) and 'P_dir' (N_dir, N_dir, C).
        N: Spatial resolution of positional planes.
        N_dir: Resolution of view-direction plane.
        C: Number of channels.
        
    Returns:
        sigma: (N_rays,) density values.
        color: (N_rays, 3) RGB values.
    """
    # 1. Convert directions to spherical coordinates (theta, phi)
    # theta: azimuth, phi: elevation
    # direction = [x, y, z]
    # theta = atan2(y, x)
    # phi = atan2(z, sqrt(x^2 + y^2))
    x, y, z = directions[:, 0], directions[:, 1], directions[:, 2]
    theta = np.arctan2(y, x)
    phi = np.arctan2(z, np.sqrt(x**2 + y**2))
    
    # Normalize theta to [0, 2pi] and phi to [-pi/2, pi/2] if necessary, 
    # then map to [0, 1] for interpolation.
    # Assuming standard mapping: theta in [0, 2pi] -> u_dir, phi in [-pi/2, pi/2] -> v_dir
    u_dir = (theta + np.pi) / (2 * np.pi)
    v_dir = (phi + np.pi / 2) / np.pi
    
    # 2. Retrieve positional features
    # P_xy: project (x, y) -> (u, v) in [0, 1]
    # Assuming the planes are aligned with axes. 
    # For P_xy, coordinates are x, y. Map x, y to [0, 1].
    # Note: The source does not specify the exact coordinate normalization for P_xy, P_xz, P_yz.
    # Standard practice in such plane-based methods is to normalize the 3D bounding box 
    # to [-1, 1] or [0, 1]. We assume [-1, 1] normalized to [0, 1] for interpolation.
    
    def normalize_coord(val, min_val=-1.0, max_val=1.0):
        return (val - min_val) / (max_val - min_val)
        
    # P_xy: use x, y
    u_xy = normalize_coord(positions[:, 0])
    v_xy = normalize_coord(positions[:, 1])
    v_xy = 1 - v_xy # Often y is inverted in image coordinates, but source doesn't specify. 
                    # Assuming standard Cartesian to Image mapping if needed. 
                    # For robustness, we just pass u, v.
    
    # P_xz: use x, z
    u_xz = normalize_coord(positions[:, 0])
    v_xz = normalize_coord(positions[:, 2])
    
    # P_yz: use y, z
    u_yz = normalize_coord(positions[:, 1])
    v_yz = normalize_coord(positions[:, 2])
    
    # Interpolate
    v_xy = bilinear_interpolate(planes['P_xy'], u_xy, v_xy)
    v_xz = bilinear_interpolate(planes['P_xz'], u_xz, v_xz)
    v_yz = bilinear_interpolate(planes['P_yz'], u_yz, v_yz)
    
    # 3. Aggregate positional features
    v_p = (v_xy + v_xz + v_yz) / 3.0
    
    # 4. Retrieve directional features
    v_pdir = bilinear_interpolate(planes['P_dir'], u_dir, v_dir)
    
    # 5. Predict Density
    # D_c and D_f are MLPs. We simulate them here with a placeholder function.
    # In implementation, these are trained weights.
    sigma_c = density_mlp(v_p)
    sigma_f = density_mlp(v_p) # Using same MLP structure for simplicity in this example
    
    # 6. Predict Radiance
    v_concat = np.concatenate([v_p, v_pdir], axis=1)
    color = radiance_mlp(v_concat)
    
    return sigma_f, color

def density_mlp(x):
    """Placeholder for 128-channel, 4-layer MLP."""
    # Implementation depends on specific framework (PyTorch/TF)
    # Here we just return a dummy value for structure demonstration
    return np.sum(x) # [G] Dummy return

def radiance_mlp(x):
    """Placeholder for 128-channel, 4-layer MLP."""
    return np.tanh(x) # [G] Dummy return, typically sigmoid or linear for RGB
```

**Parameters:**
*   $N$: Spatial resolution. Too small prohibits high frequencies; too large causes artifacts due to insufficient information in LR training images. Typical value for LR (100px images): $N=200$ [S1, unofficial].
*   $N_{dir}$: View-direction plane resolution. Set smaller than $N$ ($N_{dir} < N$) because each pixel's information is relevant to only one point on $P_{dir}$ (same viewing direction for all points on a ray), whereas it is relevant to many points on positional planes. Typical value: $N_{dir}=32$ [S1, unofficial].
*   $C$: Channel count. Typical value: $C=48$ [S1, unofficial].
*   Decoder Layers: 4 layers, 128 channels [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **View-Direction Dependency:** Omitting $P_{dir}$ significantly drops performance, especially for shiny/reflective objects with non-uniform lighting. Performance drops from ~29.6 dB to ~23.7 dB in reported experiments [S1, unofficial].
*   **Resolution Mismatch:** Using $N$ too large for the training image resolution leads to artifacts because plane regions have insufficient relevant information [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Querying a point involves 4 bilinear interpolations and two small MLP evaluations (density and radiance). This is generally faster than dense 3D grid lookups or large MLPs for high-resolution NeRFs, especially when combined with super-resolution techniques.
*   **Memory Complexity:** Memory usage is proportional to $4 \times N^2 \times C$. For $N=200, C=48$, this is $4 \times 40000 \times 48 \approx 7.68$ MB, which is very compact compared to dense 3D grids.
*   **Strengths:** Enables efficient volumetric super-resolution by leveraging 2D SR techniques on the planes. Compact memory footprint.
*   **Limitations:** Performance is sensitive to the choice of $N$ relative to training image resolution. Requires careful handling of view-direction encoding.
*   **When to use:** When high-resolution novel view synthesis is required from low-resolution inputs, or when memory efficiency is critical.
*   **When not to use:** For scenes with extreme view-dependent effects that cannot be captured by a single $P_{dir}$ plane, or if the training data is extremely high resolution where $N$ would need to be prohibitively large.

## Background
Quadri-Plane Radiance Fields were introduced in "Neural Volume Super-Resolution" [S1, unofficial]. The method builds on the idea of feature planes for 3D representation, originally proposed for human faces by Chan et al. [9], and extends it to general scenes by adding a view-direction plane and using coarse/fine decoders. It is designed to bridge the gap between 2D image super-resolution and 3D neural rendering.
