# NeRF-In Inpainting Optimization

Also called: Free-Form NeRF Inpainting with RGB-D Priors, NeRF object removal, NeRF-In

## Overview
NeRF-In is a framework for removing unwanted objects from a pre-trained Neural Radiance Field (NeRF) by optimizing the model parameters $\Theta$ using color and depth guidance derived from 2D images, without requiring category-specific training data [S1, unofficial]. Unlike sibling methods that may rely on semantic feature distillation or progressive erasing, NeRF-In explicitly formulates a joint optimization problem combining a color-guiding loss and a depth-guiding loss to ensure both visual plausibility and geometric consistency across novel views [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
1.  A pre-trained NeRF model $F_\Theta$ mapping 3D coordinates $\mathbf{x}$ and viewing directions $\mathbf{d}$ to density $\sigma$ and color $\mathbf{c}$ [S1, unofficial].
2.  A user-chosen camera position $o_u$ and its corresponding rendered view $I_u = F_{\Theta_{image}}(o_u)$ [S1, unofficial].
3.  A user-drawn free-form mask $M_u$ on $I_u$, where $M_u = 1$ for pixels outside the masked region (background/valid) and $M_u = 0$ for pixels inside the masked region (object to remove) [S1, unofficial].

**Outputs:**
1.  Updated NeRF parameters $\tilde{\Theta}$ that remove the unwanted object in the masked region across all rendered views [S1, unofficial].

### Data Structures
The method utilizes standard NeRF data structures for ray sampling and volume rendering, extended with mask and guidance buffers:
*   **Ray Batch $R$**: A set of camera rays $r(t) = o + td$, where $o$ is the camera origin and $d$ is the direction.
*   **Quadrature Points**: For each ray, $N$ points are sampled between near plane $t_n$ and far plane $t_f$.
    *   $t_i$: Position of the $i$-th sample point.
    *   $\delta_i = t_{i+1} - t_i$: Distance between adjacent points.
    *   $c(t_i), \sigma(t_i)$: Color and density predicted by $F_\Theta$ at $t_i$.
*   **Guidance Images**:
    *   $I^G$: Guiding color images for sampled views.
    *   $D^G$: Guiding depth images for sampled views.
    *   $M$: Transferred masks for sampled views.

### Numbered Steps

1.  **Initialize Parameters**: Initialize the NeRF model parameters $\Theta$. In the main method, use a pre-trained model; for baselines, random initialization may be used [S1, unofficial].
2.  **Sample Camera Positions**: Sample $K$ camera positions $O = \{o_s \mid s = 1 \dots K\}$ along a pre-set trajectory (e.g., LLFF test-set trajectory) [S1, unofficial].
3.  **Render Initial Views**: Render RGB images $I_s$ and depth images $D_s$ for each sampled camera position $o_s \in O$ using the current NeRF model $F_\Theta$ [S1, unofficial].
4.  **Transfer Masks**: Transfer the user-drawn mask $M_u$ from the user-chosen view $I_u$ to the sampled views to generate transferred masks $M = \{M_s \mid s = 1 \dots K\}$. This is achieved using a video object segmentation method, specifically STCN [S1, unofficial].
5.  **Generate Guiding Materials**:
    *   **Color Guidance**: For each sampled view $I_s$, generate a guiding color image $I_s^G$ using an image inpainting method $\rho$. The formula is $I_s^G = \rho(I_s, M_s)$, where $\rho$ is a single-image inpainting network (e.g., MST inpainting network) [S1, unofficial].
    *   **Depth Guidance**: For each sampled view, generate a guiding depth image $D_s^G$ using a depth completion method $\tau$. The formula is $D_s^G = \tau(D_s, M_s, I_s^G)$, where $\tau$ is a depth completion method (e.g., Fast Bilateral Solver) [S1, unofficial].
6.  **Define View Sets**: Define the set of all views $O_{all}$ and outside views $O_{out}$. In the main framework, set $O_{all} = \{o_u\}$ (the user-chosen view) and $O_{out} = O$ (all other sampled views) [S1, unofficial].
7.  **Compute Losses**: Compute the total loss $L(\Theta) = L_{color}(\Theta) + L_{depth}(\Theta)$ (see Formulas below) [S1, unofficial].
8.  **Optimize**: Update the NeRF parameters $\Theta$ to obtain $\tilde{\Theta}$ by minimizing the total loss using the Adam optimizer for 50,000 steps [S1, unofficial].

### Formulas

**Volume Rendering**
The expected color $\hat{C}(r)$ of a camera ray $r(t) = o + td$ is computed via the standard volume rendering integral [S1, unofficial]:
$$
\hat{C}(r) = \sum_{i=1}^{N} T(t_i)(1 - \exp(-\sigma(t_i)\delta_i))c(t_i)
$$
where $T(t_i) = \exp(-\sum_{j=1}^{i-1} \sigma(t_j)\delta_j)$ is the accumulated transmittance, $N$ is the number of quadrature points, and $\delta_i = t_{i+1} - t_i$ [S1, unofficial].

**Depth Rendering**
The rendered depth $D_f(o_s)$ for a camera position $o_s$ is computed by accumulating density $\sigma$ from ray batches during volume rendering. Both coarse ($D_c$) and fine ($D_f$) depth images are used in the loss calculation [S1, unofficial].

**Color-Guiding Loss**
The total color-guiding loss $L_{color}(\Theta)$ is the sum of the all-view color loss $L_{all\_color}(\Theta)$ and the outside-view color loss $L_{out\_color}(\Theta)$ [S1, unofficial]:
$$
L_{color}(\Theta) = L_{all\_color}(\Theta) + L_{out\_color}(\Theta)
$$
where:
$$
L_{all\_color}(\Theta) = \sum_{o \in O_{all}} \| F_{\Theta_{image}}(o) - I_o^G \|_2^2
$$
$$
L_{out\_color}(\Theta) = \sum_{o \in O_{out}} \| (F_{\Theta_{image}}(o) - I_o^G) \odot M_o \|_2^2
$$
Here, $F_{\Theta_{image}}(o)$ is the rendered image from camera position $o$, $I_o^G$ is the guiding image, and $M_o$ is the transferred mask [S1, unofficial]. Note: The sources define $L_{out\_color}$ with the mask $M_o$ applied to the difference, effectively weighting the loss by the valid (outside-mask) region, although the text describes it as measuring color difference outside the mask. The formula provided in the source is $\sum_{o \in O_{out}} \| (F_{\Theta_{image}}(o) - I_o^G) M_o \|_2^2$ [S1, unofficial].

**Depth-Guiding Loss**
The depth-guiding loss $L_{depth}(\Theta)$ measures the L2 distance between rendered fine/coarse depth images and guiding depth $D_G(o_s)$ for sampled camera positions $o_s \in O$ [S1, unofficial]:
$$
L_{depth}(\Theta) = \sum_{o_s \in O} \left( \| D_f(o_s) - D_G(o_s) \|_2^2 + \| D_c(o_s) - D_G(o_s) \|_2^2 \right)
$$
where $D_f(o_s)$ and $D_c(o_s)$ are the fine and coarse volume predicted depth images, and $D_G(o_s)$ is the guiding depth image [S1, unofficial].

**Total Optimization Objective**
The updated parameters $\tilde{\Theta}$ are obtained by:
$$
\tilde{\Theta} := \arg \min_{\Theta} \left( L_{color}(\Theta) + L_{depth}(\Theta) \right)
$$
[ S1, unofficial ]

### Parameters
*   **$K$**: The number of sampled camera positions/views used for inpainting guidance [S1, unofficial].
*   **Batch size**: 4,096 [S1, unofficial].
*   **Sample points (Fine model)**: 128 [S1, unofficial].
*   **Sample points (Coarse model)**: 64 [S1, unofficial].
*   **Optimizer**: Adam [S1, unofficial].
*   **Optimization Steps**: 50,000 steps for inpainting (compared to 200,000 for initial training) [S1, unofficial].

### Edge Cases and Pitfalls
*   **Masked MSE Only**: Optimizing only with masked Mean Squared Error (MSE) on the transferred masks without explicit guidance causes the unwanted object to remain in the result [S1, unofficial].
*   **Depth Loss Only**: Using only the depth-guiding loss ($L_{depth}$) introduces color noise outside the masked region and loses color information in flat regions [S1, unofficial].
*   **Multiple Color Guidance**: Using multiple inpainted images as color guidance (beyond the user-chosen view) introduces visual inconsistency between views [S1, unofficial].
*   **Guidance Artifacts**: If the initial guidance materials (generated by $\rho$ and $\tau$) contain appearances or geometries artifacts, the optimized NeRF might output undesired or incorrect results [S1, unofficial].

            loss_depth_fine = torch.mean((depth_fine - guide_depth) ** 2)
            
            total_loss += loss_depth_coarse + loss_depth_fine
            
        # Backpropagate

        optimizer.step()

## Operating characteristics

**Time and Memory Complexity:**
*   The optimization requires 50,000 steps [S1, unofficial].
*   Each step involves rendering rays for $K$ sampled views plus the user-chosen view, using 128 fine and 64 coarse sample points [S1, unofficial].
*   The initial training of the NeRF takes 200,000 steps (approx. 18-20 hours), while the inpainting optimization takes approximately 5 hours [S1, unofficial].
*   Memory usage is dominated by the NeRF model parameters and the batch size of 4,096 rays [S1, unofficial].

**Measured Performance:**
*   Tested on an Intel i7-7800X CPU and GTX-1080 GPU [S1, unofficial].
*   Evaluated on the LLFF dataset and a custom dataset with 24 camera positions per scene [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths**: Does not require category-specific training data or procedures [S1, unofficial]. Jointly optimizes color and depth to maintain geometric consistency and visual plausibility [S1, unofficial].
*   **Limitations**: Performance depends on the quality of the initial guidance materials (inpainting and depth completion). Artifacts in guidance propagate to the NeRF [S1, unofficial]. Using multiple views for color guidance can introduce inconsistencies, so the method restricts color guidance to the user-chosen view [S1, unofficial].

**When to Use:**
*   Use when you need to remove specific objects from a pre-trained NeRF without retraining from scratch or having category-specific data.
*   Use when geometric consistency across views is critical.

**When Not to Use:**
*   Do not use if the initial depth/color guidance is likely to be inaccurate, as this will degrade the NeRF.
*   Do not use if you need to change the semantic content of the scene beyond removal (e.g., replacing an object with a different category), as this method focuses on inpainting/removal.

## Background

**Origin:**
NeRF-In was introduced by Hao-Kang Liu, I-Chao Shen, and Bing-Yu Chen in the paper "NeRF-In: Free-Form NeRF Inpainting with RGB-D Priors" [S1, unofficial].

**History and Development:**
The method addresses the limitation of previous NeRF editing techniques that required category-specific training or segmentation networks [S1, unofficial]. It builds on the standard NeRF rendering equation and incorporates external 2D inpainting and depth completion tools to provide explicit guidance for the 3D optimization [S1, unofficial].

**Usage:**
Implemented in PyTorch and Python 3.9 [S1, unofficial].
