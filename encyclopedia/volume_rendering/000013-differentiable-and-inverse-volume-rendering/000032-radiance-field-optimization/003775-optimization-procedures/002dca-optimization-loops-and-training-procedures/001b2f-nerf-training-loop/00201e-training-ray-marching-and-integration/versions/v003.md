# Training Ray Marching and Integration

Also called: CUDA Ray Marching (Training), NeRF Forward Pass, Standard NeRF forward, Training Ray Marching

## Overview
Training Ray Marching and Integration is the differentiable forward pass that synthesizes RGB images from a Neural Radiance Field (NeRF) during the optimization loop [S1, S2, S4, S8, unofficial]. It solves the problem of mapping discrete, noisy neural network outputs (volume density and color) into a coherent, continuous image by sampling points along camera rays, querying the implicit function, and integrating them via alpha compositing [S2, S4, S8, unofficial]. It sets itself apart from its siblings by combining ray generation, adaptive marching with occupancy grid pruning, neural network evaluation, and alpha compositing into a single differentiable forward pass that supports gradient computation for backpropagation [S1, S7, S8, unofficial].

## How it works
The method takes a bundle of rays defined by camera parameters and integrates the radiance field along them. It supports two main implementation styles: a standard PyTorch-based chunked evaluation [S2, S4, unofficial] and an optimized CUDA kernel-based approach using density bitfields and occupancy grids [S1, S8, unofficial].

### Inputs and Outputs
**Inputs:**
*   `rays_o`: Ray origins, float tensor of shape $[N, 3]$ [S1, S8, unofficial].
*   `rays_d`: Ray directions, float tensor of shape $[N, 3]$ [S1, S8, unofficial].
*   `nears`: Near plane distances, float tensor of shape $[N]$ [S1, S8, unofficial].
*   `fars`: Far plane distances, float tensor of shape $[N]$ [S1, S8, unofficial].
*   `bound`: Bounding box size scalar, defining the spatial bound for ray marching [S1, S8, unofficial].
*   `density_bitfield`: Packed density bitfield, uint8 array of shape $[C \cdot H^3 / 8]$ [S1, S8, unofficial].
*   `cascade`: Cascade parameters for multi-resolution hashing [S8, unofficial].
*   `grid_size`: Grid size for the occupancy grid [S8, unofficial].
*   `perturb`: Boolean flag for adding noise to step sizes [S1, S8, unofficial].
*   `max_steps`: Maximum number of sampled points along each ray, int [S1, S8, unofficial].
*   `mean_count`: Estimated mean steps to accelerate training, int32. If $> 0$, limits output points; if underestimated, rays are randomly dropped [S1, S8, unofficial].
*   `force_all_rays`: Boolean to ignore `mean_count` and calculate all rays [S1, unofficial].
*   `dt_gamma`: Time delta gamma parameter (cone angle), float. Exponentially accelerates ray marching if $> 0$ [S1, S8, unofficial].
*   `chunk_size`: The number of rays to process in a single forward pass to manage memory usage [S2, unofficial].
*   `white_background`: Boolean flag to determine if the background should be white (default False) [S2, unofficial].

**Outputs:**
*   `xyzs`: Generated point coordinates, float tensor of shape $[M, 3]$ [S1, S8, unofficial].
*   `dirs`: View directions, float tensor of shape $[M, 3]$ [S1, S8, unofficial].
*   `deltas`: Step sizes, float tensor of shape $[M, 2]$, where the first element is $\delta_t$ (segment length) and the second is $rays_t$ (ray index) [S1, unofficial].
*   `rays`: Ray metadata, int32 tensor of shape $[N, 3]$, storing `(index, point_offset, point_count)` for each ray [S1, S8, unofficial].
*   `rgb_map`: Rendered RGB image, shape $[width, height, 3]$ [S4, unofficial].
*   `depth_map`: Rendered depth image, shape $[width, height]$ [S4, unofficial].
*   `acc_map`: Accumulated transmittance/opacity map, shape $[width, height]$ [S4, unofficial].

### Data Structures
*   **RayBundle**: Contains ray origins, directions, and metadata.
*   **OccupancyGrid**: A sparse grid used to skip empty space. Initialized with `roi_aabb`, `resolution` (e.g., 128 or 256), and `contraction_type` (e.g., AABB or UN_BOUNDED_SPHERE) [S5, unofficial].
*   **Density Bitfield**: A packed uint8 array representing the density field for fast lookup during ray marching [S1, S8, unofficial].

### Steps

1.  **Ray Generation**: Compute ray origins ($o_{world}$) and directions ($d_{world}$) in world space using camera parameters and the camera-to-world transformation matrix [S7, unofficial]. For a pixel at $(u, v)$ with focal length $f$ and transform $T_{cam2world}$:
    $$
    \begin{aligned}
    \text{direction}_{local} &= \left[ \frac{u - W/2}{f}, -\frac{v - H/2}{f}, -1 \right] \\
    d_{world} &= T_{cam2world}[0:3, 0:3] \cdot \text{direction}_{local} \\
    o_{world} &= T_{cam2world}[0:3, 3]
    \end{aligned}
    $$
    [S4, S7, unofficial].

2.  **Bound Calculation**: Compute near and far clipping planes ($t_{starts}, t_{ends}$) for each ray using the scene axis-aligned bounding box (AABB) and a minimum near distance [S5, S8, unofficial].

3.  **Ray Marching (Sampling)**:
    *   **CUDA Kernel Approach**: Call `raymarching.march_rays_train` with inputs `rays_o`, `rays_d`, `bound`, `density_bitfield`, `cascade`, `grid_size`, `nears`, `fars`, `perturb`, `max_steps`, `dt_gamma`, and `mean_count` [S1, S8, unofficial]. This kernel uses an occupancy grid to prune empty space and adaptive step sizes to concentrate samples in high-density regions [S1, S7, S9, unofficial].
        *   If `perturb` is true, add uniform noise in range $[-0.5, 0.5] \cdot \text{sample\_dist}$ to z-values, where $\text{sample\_dist} = (\text{fars} - \text{nears}) / \text{num\_steps}$ [S8, unofficial].
        *   If `upsampling` is enabled, compute bin weights from initial alphas and sample new z-values using stratified sampling from the probability density function (PDF) derived from weights [S8, unofficial].
        *   Concatenate initial and upsampled z-values, sort them, and reorder corresponding xyzs and density outputs [S8, unofficial].
    *   **PyTorch Approach**: Generate initial uniform z-values along the ray segment between near and far, scaled by the number of steps [S8, unofficial]. If randomization is enabled, add noise to these values [S4, unofficial]. Compute 3D coordinates: $xyzs = rays_o + rays_d \cdot z_{values}$ [S8, unofficial].

4.  **Chunked Network Evaluation**: To avoid out-of-memory errors, split the sampled points into chunks of size `chunk_size` [S2, S4, unofficial].
    *   Query the neural network for density ($\sigma$) and color ($c$) at each sampled point [S2, S8, unofficial].
    *   Concatenate outputs from all chunks along the batch dimension [S2, unofficial].

5.  **Alpha Compositing (Integration)**:
    *   Compute segment lengths (deltas): $\delta_i = z_{i+1} - z_i$. For the last sample, use a large constant ($10^{10}$) to ensure the final segment contributes fully if opaque [S4, S8, unofficial].
    *   Compute opacity ($\alpha$) for each segment:
        $$
        \alpha_i = 1 - \exp(-\sigma_i \cdot \delta_i)
        $$
        [S4, unofficial].
    *   Compute transmittance ($T$):
        $$
        T_i = \prod_{j=0}^{i-1} \exp(-\sigma_j \delta_j)
        $$
        Implemented as cumulative product: $T = \text{cumprod}(\text{cat}([1, \exp(-\sigma \cdot \delta)]), \text{dim}=0)$ [S2, unofficial].
    *   Compute weights ($w_i$):
        $$
        w_i = T_i (1 - \exp(-\sigma_i \delta_i))
        $$
        Implemented as: $w_i = T_i \cdot \alpha_i$ [S2, S4, unofficial]. Add small epsilon ($10^{-10}$) to $1-\alpha$ for numerical stability [S4, unofficial].
    *   Compute final RGB color:
        $$
        C = \sum w_i c_i
        $$
        [S4, unofficial].
    *   Compute final depth:
        $$
        D = \sum w_i d_i
        $$
        [S4, unofficial].
    *   Compute accumulated transmittance/opacity:
        $$
        A = \sum w_i
        $$
        [S4, unofficial].
    *   Add background color contribution: $C_{final} = C + (1 - A) \cdot C_{bg}$ [S5, S8, unofficial].

6.  **Backward Pass**: Compute gradients for ray origins and directions using the adjoint of the ray marching and compositing operations [S1, unofficial].

### Pseudocode

```python
import torch
import torch.nn.functional as F

def cumprod_exclusive(tensor):
    """Mimic tf.math.cumprod(..., exclusive=True)"""
    c = torch.cumprod(tensor, dim=-1)
    c[..., 0] = 1.0
    return c

def render_volume_density(rbg_field, density_field, ray_origins, depth_values):
    """
    Differentiable volume rendering.
    rbg_field: (width, height, num_samples, 3) - RGB colors
    density_field: (width, height, num_samples) - Density sigma
    ray_origins: (width, height, 3)
    depth_values: (num_samples,) or (width, height, num_samples)
    """
    # Compute distances between samples
    one_e_10 = torch.tensor([1e10], dtype=ray_origins.dtype, device=ray_origins.device)
    
    # Handle depth_values shape: if 1D, expand to match ray_origins
    if depth_values.dim() == 1:
        depth_values = depth_values.unsqueeze(0).unsqueeze(0).expand(ray_origins.shape[0], ray_origins.shape[1], -1)
        
    dists = torch.cat((
        depth_values[..., 1:] - depth_values[..., :-1],
        one_e_10.expand(depth_values[..., :1].shape)
    ), dim=-1)
    
    # Compute opacity alpha
    alpha = 1.0 - torch.exp(-density_field * dists)
    
    # Compute weights
    # T_i = product_{j=0}^{i-1} (1 - alpha_j)
    # weights_i = T_i * alpha_i
    weights = alpha * cumprod_exclusive(1.0 - alpha + 1e-10)
    
    # Compute RGB map
    rgb_map = (weights[..., None] * rbg_field).sum(dim=-2)
    
    # Compute Depth map
    depth_map = (weights * depth_values).sum(dim=-1)
    
    # Compute Accumulated Opacity
    acc_map = weights.sum(-1)
    
    return rgb_map, depth_map, acc_map

def training_ray_marching_forward(rays_o, rays_d, nears, fars, bound, density_bitfield, 
                                  cascade, grid_size, perturb, max_steps, mean_count, 
                                  dt_gamma, chunk_size, white_background=False, bg_color=0.0):
    """
    Full training forward pass.
    """
    # 1. Ray Marching (Simulated CUDA call)
    # In practice, this calls a CUDA kernel: raymarching.march_rays_train(...)
    # Returns: xyzs [M, 3], dirs [M, 3], deltas [M, 2], rays [N, 3]
    xyzs, dirs, deltas, rays = raymarching_march_rays_train(
        rays_o, rays_d, bound, density_bitfield, cascade, grid_size,
        nears, fars, perturb=perturb, max_steps=max_steps, 
        mean_count=mean_count, dt_gamma=dt_gamma
    )
    
    # 2. Query Network (Chunked)
    # Split xyzs and dirs into chunks
    num_rays = rays_o.shape[0]
    num_samples = xyzs.shape[0]
    
    # Flatten for network query
    xyzs_flat = xyzs
    dirs_flat = dirs
    
    # Chunked evaluation to save memory
    rbg_field_list = []
    density_field_list = []
    
    for i in range(0, num_samples, chunk_size):
        chunk_xyzs = xyzs_flat[i:i+chunk_size]
        chunk_dirs = dirs_flat[i:i+chunk_size]
        
        # Query neural network: returns sigma and RGB
        # sigma: [chunk_size], rgb: [chunk_size, 3]
        sigma, rgb = query_nerf_network(chunk_xyzs, chunk_dirs)
        
        density_field_list.append(sigma)
        rbg_field_list.append(rgb)
        
    density_field = torch.cat(density_field_list, dim=0)
    rbg_field = torch.cat(rbg_field_list, dim=0)
    
    # Reshape to match ray structure
    # Assuming rays structure maps M samples to N rays
    # This part depends on the specific ray indexing from the CUDA kernel
    # For simplicity, assuming we can reshape based on ray indices
    # In practice, we use scatter or gather based on 'rays' metadata
    
    # 3. Integration
    # Compute deltas for integration
    # deltas from march_rays_train are [M, 2]: [delta_t, ray_t]
    delta_t = deltas[:, 0]
    
    # Compute alpha
    alpha = 1.0 - torch.exp(-density_field * delta_t)
    
    # Compute transmittance
    # T_i = product_{j=0}^{i-1} (1 - alpha_j)
    # We need to group by ray and compute cumprod
    # This is typically done in the CUDA kernel or via scatter operations
    # Here we simulate the result: weights [M]
    weights = compute_ray_weights(alpha, rays)
    
    # Compute RGB and Depth per ray
    # Using scatter_add to accumulate per ray
    rgb_map = torch.zeros(num_rays, 3, device=xyzs.device)
    depth_map = torch.zeros(num_rays, device=xyzs.device)
    acc_map = torch.zeros(num_rays, device=xyzs.device)
    
    # Gather xyzs to get depth values (z-coords along ray)
    # z_vals = rays_o[rays[:, 0], :] + xyzs * dirs[rays[:, 0], :] ... 
    # Simplified: assume we have z_vals for each sample
    z_vals = compute_z_vals(xyzs, rays_o, rays_d, rays)
    
    rgb_map.scatter_add_(0, rays[:, 0].unsqueeze(1).expand(-1, 3), weights[:, None] * rbg_field)
    depth_map.scatter_add_(0, rays[:, 0], weights * z_vals)
    acc_map.scatter_add_(0, rays[:, 0], weights)
    
    # Add background
    if white_background:
        bg_color = torch.tensor([1.0, 1.0, 1.0], device=xyzs.device)
    else:
        bg_color = torch.tensor([bg_color, bg_color, bg_color], device=xyzs.device)
        
    rgb_map = rgb_map + (1.0 - acc_map[:, None]) * bg_color
    
    # Reshape to image dimensions
    # Assuming rays_o shape is [N, 3] where N = width * height
    height = int(torch.sqrt(torch.tensor(N)).item()) # Simplified
    width = N // height
    rgb_image = rgb_map.view(height, width, 3)
    depth_image = depth_map.view(height, width)
    acc_image = acc_map.view(height, width)
    
    return rgb_image, depth_image, acc_image
```

### Parameters and Typical Values
*   `chunk_size`: 1024 * 8 (8192) [S4, unofficial].
*   `near_plane`: 0.2 for MIPNeRF360, 0.0 for NeRF Synthetic [S9, unofficial].
*   `render_step_size`: 1e-3 for MIPNeRF360, 5e-3 for NeRF Synthetic [S9, unofficial].
*   `cone_angle`: 0.004 for MIPNeRF360, 0.0 for NeRF Synthetic [S9, unofficial].
*   `alpha_thre`: 1e-2 for MIPNeRF360, 0.0 for NeRF Synthetic [S9, unofficial].
*   `occupancy_grid_res`: 256 if learned background, 128 otherwise [S5, unofficial].
*   `render_step_size`: 0.01 if learned background, $1.732 \cdot 2 \cdot \text{radius} / \text{num\_samples\_per\_ray}$ otherwise [S5, unofficial].

### Edge Cases and Pitfalls
*   **Precision**: Add epsilon ($10^{-10}$) to $1-\alpha$ in transmittance calculation to prevent numerical instability [S4, unofficial].
*   **Boundaries**: Use a large constant ($10^{10}$) for the last segment's delta to ensure full contribution if the ray is opaque [S4, S8, unofficial].
*   **Memory**: Use chunked evaluation to avoid OOM errors when $N_{samples} \cdot N_{rays}$ exceeds VRAM [S2, S4, unofficial].
*   **Underestimation**: If `mean_count` is underestimated, rays are randomly dropped to maintain performance [S1, S8, unofficial].

## Subtopics

### [NeRF Evaluation and Metric Calculation](3079-nerf-evaluation-and-metric-calculation.md)
NeRF Evaluation and Metric Calculation renders a single image from a given camera pose using trained coarse and fine NeRF models, returning RGB, depth, and disparity maps. It differs from the parent [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md) by operating in inference mode (no gradient computation for backpropagation) and by computing quantitative quality metrics (PSNR, SSIM, LPIPS) against ground truth images. It sets itself apart from sibling [NeRF Rendering (Alpha Compositing)](5124-nerf-rendering-alpha-compositing.md) by handling the full pipeline of ray generation, coordinate transformation (including NDC), batched rendering, and metric aggregation.

### [NeRF Network Query with Hashed Embeddings](3107-nerf-network-query-with-hashed-embeddings.md)
This method performs the neural network evaluation step within the NeRF training loop, mapping 3D spatial coordinates and viewing directions to density and color features using embedding functions and a network function. It replaces expensive high-dimensional coordinate embeddings with a structured lookup process that applies position and direction embeddings before batching the concatenated features through a network function.

### [Chunked Network Evaluation](3177-chunked-network-evaluation.md)
Chunked Network Evaluation is a memory-management technique used during the training and rendering of Neural Radiance Fields (NeRF) to avoid out-of-memory (OOM) errors when evaluating the neural network on large batches of 3D points. It solves the problem where the number of samples per ray ($N_{samples}$) multiplied by the number of rays ($N_{rays}$) exceeds the GPU's VRAM capacity for the network's forward pass. It sets itself apart from standard batched evaluation by explicitly partitioning the point cloud into smaller, manageable subsets (chunks) processed sequentially, rather than attempting to process all points in a single tensor operation.

### [NeRF Rendering (Alpha Compositing)](5124-nerf-rendering-alpha-compositing.md)
NeRF Rendering (Alpha Compositing) is the differentiable integration step that computes the final RGB color and depth for a pixel by synthesizing predictions from a neural radiance field along a camera ray. It solves the problem of mapping discrete, noisy neural network outputs (density and color) into a coherent, continuous image by accounting for occlusion and transparency via alpha compositing. What sets it apart from its siblings is its specific reliance on the stratified sampling intervals and the exponential transmittance decay defined by the original NeRF formulation, distinguishing it from explicit voxel-based integrators like [NeRF-style Volume Rendering Integrator](5964-nerf-style-volume-rendering-integrator.md) or hash-based query methods [NeRF Network Query with Hashed Embeddings](3107-nerf-network-query-with-hashed-embeddings.md).

### [NeRF-style Volume Rendering Integrator](5964-nerf-style-volume-rendering-integrator.md)
A simplified NeRF-style integrator that accumulates emission along a ray through a medium, backed by a dense grid instead of a neural network, with no direction-dependent emission. It differs from standard NeRF implementations by using a dense grid for density/emission storage and explicitly handling primal/dual modes for gradient computation in inverse rendering contexts.

### [Active Learning Strategy for NeRF Distillation](7421-active-learning-strategy-for-nerf-distillation.md)
A strategy to bridge performance gaps between teacher and student NeRF models by actively selecting challenging camera poses, sample rays, and sample points for distillation, rather than using all data uniformly.

## Operating characteristics
*   **Time Complexity**: $O(N_{rays} \cdot N_{samples})$ for standard sampling, reduced by occupancy grid pruning and adaptive step sizes [S1, S7, unofficial].
*   **Memory Complexity**: $O(N_{rays} \cdot N_{samples})$ for storing intermediate tensors, mitigated by chunked evaluation [S2, S4, unofficial].
*   **Performance**: The CUDA kernel-based approach with density bitfields and occupancy grids is significantly faster than pure PyTorch implementations, enabling real-time training [S1, S7, S8, unofficial].
*   **Strengths**: Differentiable, supports gradient-based optimization, efficient with sparse data via pruning [S1, S7, unofficial].
*   **Limitations**: Memory-intensive for high-resolution scenes without chunking, sensitive to hyperparameters like `dt_gamma` and `mean_count` [S1, S8, unofficial].
*   **When to Use**: During the training phase of NeRF models where gradients are needed for backpropagation [S1, S2, S4, unofficial].
*   **When Not to Use**: During inference/evaluation where speed is critical and gradients are not needed; use [NeRF Evaluation and Metric Calculation](3079-nerf-evaluation-and-metric-calculation.md) instead.

## Background
The method originates from the NeRF paper (Mildenhall et al. 2020) [S2, unofficial]. It has been optimized in subsequent works such as instant-NGP (Müller et al. 2022) using hash-based embeddings and CUDA kernels for acceleration [S1, S7, S8, unofficial]. It is widely used in inverse rendering and 3D scene reconstruction from images [S2, S4, unofficial].
