# Tetrahedron Property Querying via Instant-NGP


## Overview
This method queries a differentiable radiance field parameterized by an Instant-NGP data structure to produce density and appearance features for individual tetrahedra in a volumetric mesh. It solves the problem of mapping point-based neural fields to volume-based primitives during optimization, where attaching features directly to vertices fails due to topological changes in the Delaunay tetrahedralization. It differs from standard NeRF point querying by using tetrahedron centers (centroid or circumcenter) and incorporating a radius-based downweighting to handle geometric degeneracy.

## How it works
**Inputs and Outputs**
*   **Input:** A tetrahedron $k$ defined by its vertices, its circumcenter $\mathbb{O}_k$ (or centroid), its circumradius $\mathbb{R}_k$, and a viewing direction $d_k$.
*   **Output:** Density $\sigma_k$, base color $\mathbf{c}_k^0$, and color gradient $\nabla \mathbf{c}_k$.

**Data Structures**
*   **Instant-NGP Field ($G_\theta$):** A multi-resolution hash grid storing features. The specific internal layout is defined by the Instant-NGP implementation [S1, unofficial].
*   **Shallow Neural Network Heads:** Four separate heads ($h_\sigma, h_{sh}, h_\Delta, h_c$) that map the bottleneck feature vector $\mathbf{b}_k$ to output values. These are standard small MLPs.

**Parameters**
*   **Center Strategy:** Either `centroid` or `circumcenter`. The centroid is preferred for numerical stability [S1, unofficial].
*   **Softplus Beta:** $\beta = 10$ for color computation [S1, unofficial].
*   **Downweighting Function ($\phi$):** A function of the radius $\mathbb{R}_k$ used to scale the NGP features. The exact form is not specified in the notes, but it is applied element-wise to the bottleneck features [S1, unofficial].

**Steps**
1.  **Compute Center:** Determine the query point $\mathbb{O}_k$.
    *   If `centroid`: $\mathbb{O}_k$ is the arithmetic mean of the tetrahedron's vertices.
    *   If `circumcenter`: $\mathbb{O}_k$ is the center of the circumscribed sphere. This ensures continuity during edge-flipping in the Delaunay tetrahedralization but suffers from poor numerical conditioning for skinny tetrahedra [S1, unofficial].
2.  **Query NGP:** Retrieve the raw feature vector from the Instant-NGP field at $\mathbb{O}_k$:
    $$ \mathbf{f}_k \leftarrow G_\theta(\mathbb{O}_k) $$
3.  **Downweight Features:** Apply the radius-based downweighting function $\phi(\mathbb{R}_k)$ to the features. The notation $\circ$ denotes element-wise multiplication:
    $$ \mathbf{b}_k \leftarrow \phi(\mathbb{R}_k) \circ \mathbf{f}_k \quad (9) $$
    Here, $\mathbf{b}_k$ is the bottleneck feature vector for tetrahedron $k$.
4.  **Compute Density:** Pass $\mathbf{b}_k$ through the density head $h_\sigma$ and apply an exponential activation:
    $$ \sigma_k \leftarrow \exp(h_\sigma(\mathbf{b}_k)) \quad (10) $$
5.  **Compute Base Color:** Pass $\mathbf{b}_k$ through the spherical harmonic head $h_{sh}$, dot product with spherical harmonics basis functions $Y(d_k)$ evaluated in direction $d_k$, and apply softplus:
    $$ \mathbf{c}_k^0 \leftarrow \text{softplus}_{\beta=10}(h_{sh}(\mathbf{b}_k) \cdot Y(d_k)) \quad (11) $$
6.  **Compute Color Gradient:** Calculate the gradient to prevent negative colors within the tetrahedron.
    *   Compute the raw gradient vector via head $h_\Delta$:
        $$ \mathbf{g}_k \leftarrow h_\Delta(\mathbf{b}_k) $$
    *   Normalize $\mathbf{g}_k$ using a spherical normalization:
        $$ \hat{\mathbf{g}}_k \leftarrow \frac{\mathbf{g}_k}{\sqrt{1 + \|\mathbf{g}_k\|_2^2}} $$
    *   Determine the minimum color value across RGB channels:
        $$ m_k \leftarrow \min_{\mathbf{c}_k} \mathbf{c}_k $$
    *   Scale by the inverse radius and the minimum color:
        $$ \nabla \mathbf{c}_k \leftarrow \frac{m_k}{\mathbb{R}_k} \hat{\mathbf{g}}_k \quad (12) $$
    *   Note: The gradient $\nabla \mathbf{c}_k$ is monochrome (shared across all color channels) to save 30% of memory loads in shaders [S1, unofficial].

**Pseudocode**
```python
def query_tetrahedron_properties(tet, ngp_field, direction_d):
    """
    Query density and appearance for a single tetrahedron.
    
    Args:
        tet: Object containing vertices, circumradius R_k, and method for center.
        ngp_field: Instant-NGP field instance with method query(point).
        direction_d: Viewing direction vector.
        
    Returns:
        sigma: Density.
        c0: Base color (RGB).
        grad_c: Color gradient (RGB, monochrome).
    """
    # Step 1: Compute center O_k
    # Note: The choice between centroid and circumcenter is a hyperparameter.
    # Centroid is preferred for numerical stability.
    if tet.center_method == 'centroid':
        O_k = centroid(tet.vertices)
    elif tet.center_method == 'circumcenter':
        O_k = circumcenter(tet.vertices)
    else:
        raise ValueError("Unknown center method")

    R_k = tet.circumradius

    # Step 2: Query NGP
    f_k = ngp_field.query(O_k)

    # Step 3: Downweight features
    # phi is a function of R_k. Exact implementation of phi is not specified in notes.
    # [G] Assuming phi scales features inversely with radius or similar smoothing.
    # The notes state: b_k <- phi(R_k) o G_theta(O_k)
    b_k = downweight_features(f_k, R_k)

    # Step 4: Compute Density
    # h_sigma is a shallow neural network head
    sigma = exp(h_sigma(b_k))

    # Step 5: Compute Base Color
    # h_sh is a shallow neural network head
    # Y(d_k) are spherical harmonics basis functions evaluated in direction d
    sh_features = h_sh(b_k)
    sh_basis = spherical_harmonics_basis(direction_d)
    color_raw = dot(sh_features, sh_basis)
    c0 = softplus(color_raw, beta=10)

    # Step 6: Compute Color Gradient
    # h_delta is a shallow neural network head
    g_raw = h_delta(b_k)
    
    # Spherical normalization
    norm_factor = sqrt(1.0 + dot(g_raw, g_raw))
    g_normalized = g_raw / norm_factor
    
    # Minimum color across channels (monochrome gradient)
    min_color = min(c0)
    
    # Scale by inverse radius
    grad_c = (min_color / R_k) * g_normalized

    return sigma, c0, grad_c
```

**Edge Cases and Pitfalls**
*   **Skinny Tetrahedra:** The circumcenter can move very quickly for skinny tetrahedra, causing numerical instability. The circumradius $\mathbb{R}_k$ is used to prefilter the NGP to address this [S1, unofficial].
*   **Continuity vs. Stability:** The circumcenter provides continuity during edge-flipping (centers are co-located at the flip moment), but the centroid has better numerical conditioning. The centroid is shown to have better performance in ablation studies [S1, unofficial].
*   **Negative Colors:** The activation in the color gradient formula prevents the color from going negative within the tetrahedron. The maximum negative change is bounded by $-\min \mathbf{c}_k$ [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the Instant-NGP query time, which is generally $O(1)$ with respect to the number of tetrahedra but depends on the hash grid size and resolution.
*   **Memory Complexity:** Requires storing the Instant-NGP hash grids and the parameters for the four shallow neural network heads ($h_\sigma, h_{sh}, h_\Delta, h_c$).
*   **Strengths:** Handles topological changes in the Delaunay tetrahedralization gracefully by querying a continuous field. The monochrome gradient saves 30% of memory loads in shaders [S1, unofficial].
*   **Limitations:** The circumcenter strategy is numerically unstable for skinny tetrahedra. The centroid strategy lacks continuity at edge-flips.
*   **When to use:** When optimizing a radiance field parameterized by a tetrahedral mesh where vertex-attached features are insufficient due to mesh topology changes.

## Background
This method is described in "Radiance Meshes for Volumetric Reconstruction" [S1, unofficial]. It builds on Instant-NGP [46] and mip-NeRF 360 [4]. The approach to querying tetrahedra is similar to Zip-NeRF [5]. The method was developed to address the failure of vertex-attached features during optimization of Delaunay tetrahedralizations.
