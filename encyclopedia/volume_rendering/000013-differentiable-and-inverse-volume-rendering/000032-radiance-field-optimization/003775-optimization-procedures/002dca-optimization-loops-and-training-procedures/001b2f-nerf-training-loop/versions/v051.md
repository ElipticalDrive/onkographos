# NeRF Training Loop

Also called: IPE (Interatomic Positional Encoding), Interatomic Positional Encoding, NeRF Optimization Loop, NeRF Training Procedure, Neural Radiance Field (NeRF) Training

## Overview
The NeRF Training Loop is the iterative optimization procedure that minimizes the photometric reconstruction error between rendered images and ground-truth observations by updating the parameters of a neural radiance field [S5, unofficial][S11, unofficial]. It differs from evaluation by using stochastic ray sampling, adaptive strategies, and chunked processing to manage memory and enable gradient-based learning, whereas evaluation disables these for deterministic results [S2, unofficial][S4, unofficial][S9, unofficial]. It builds on [Optimization Loops and Training Procedures](5622-optimization-loops-and-training-procedures.md) by implementing the specific data loading, batching, and loss computation mechanics required for coordinate-based implicit representations.

## How it works
**Inputs and Outputs:**
*   **Inputs:** A dataset of $N$ training images with known camera poses (intrinsics $K$, extrinsics $C2W$), near/far bounds, and optional metadata (e.g., background color). The model parameters $\theta$ (network weights, embeddings).
*   **Outputs:** Updated model parameters $\theta'$ that minimize the loss $\mathcal{L}$.

**Data Structures:**
*   **Rays Array (`rays_rgb`):** A pre-computed or on-the-fly generated array of shape $[(N-1) \times H \times W, 3, 3]$ storing ray origins, directions, and target RGB colors [S5, unofficial][S14, unofficial].
    *   Axis 0: Flattened pixel index.
    *   Axis 1: Channel type (0: origin, 1: direction, 2: target RGB).
    *   Axis 2: XYZ/RGB components.
    *   Type: `float32` [S5, unofficial][S14, unofficial].
*   **Batch:** A tensor of shape $[3, B, 3]$ containing the current batch of rays, where $B$ is the batch size (number of rays) [S14, unofficial].

**Numbered Steps:**

1.  **Initialization:**
    *   Load training and validation datasets [S9, unofficial][S11, unofficial].
    *   Initialize the NeRF model (MLP) and optimizer (typically Adam) [S5, unofficial][S11, unofficial].
    *   Initialize learning rate scheduler (e.g., Exponential Decay or Cosine Annealing) [S5, unofficial][S11, unofficial].
    *   If using coarse-to-fine training, initialize both coarse and fine networks [S11, unofficial].
    *   [G] Set random seeds for reproducibility.

2.  **Iteration Loop:** For iteration $i$ from 1 to $N_{iters}$:
    *   **Ray Sampling:**
        *   Select a batch of $N_{rand}$ rays from the dataset [S5, unofficial][S14, unofficial].
        *   If pre-computed, slice `rays_rgb[i_batch : i_batch + N_rand]` [S5, unofficial].
        *   If on-the-fly, randomly select pixel coordinates $(x, y)$, construct ray origins/directions using camera intrinsics, and sample target RGB values [S4, unofficial][S14, unofficial].
        *   [G] Apply stratified sampling or jittering if `perturb > 0` to reduce aliasing [S5, unofficial].
        *   [G] If `precrop_iters` is active and $i < precrop_iters$, restrict sampling to a central crop of the image [S2, unofficial].
    *   **Forward Pass (Rendering):**
        *   Sample $N$ points along each ray within $[near, far]$ bounds [S5, unofficial].
        *   Query the neural network for density $\sigma$ and color $\mathbf{c}$ at each point [S5, unofficial].
        *   Compute transmittance $T$ and weights $w$ using the emission-absorption model [S5, unofficial].
        *   Composite the final color $\hat{C}(\mathbf{r})$ [S5, unofficial].
        *   [G] If coarse-to-fine, render coarse predictions first, then sample additional points based on coarse weights for fine rendering [S5, unofficial].
        *   [G] Chunk the ray batch if `use_batching` is True and VRAM is limited, processing `chunk` rays at a time [S5, unofficial][S14, unofficial].
    *   **Loss Computation:**
        *   Compute Mean Squared Error (MSE) between predicted RGB $\hat{C}$ and target RGB $C_{gt}$ [S5, unofficial][S14, unofficial]:
            $$ \mathcal{L}_{rgb} = \frac{1}{B} \sum_{j=1}^{B} \| \hat{C}_j - C_{gt,j} \|^2 $$
        *   [G] If coarse output $\hat{C}_{coarse}$ is available, add coarse loss: $\mathcal{L}_{coarse} = \text{MSE}(\hat{C}_{coarse}, C_{gt})$ [S11, unofficial].
        *   [G] Add regularization terms if defined (e.g., sparsity, Eikonal) [S8][S7, unofficial].
        *   Total Loss: $\mathcal{L} = \mathcal{L}_{rgb} + \lambda_{coarse}\mathcal{L}_{coarse} + \dots$
    *   **Backpropagation and Update:**
        *   Zero gradients: `optimizer.zero_grad()` [S18, unofficial].
        *   Compute gradients: `loss.backward()` [S18, unofficial].
        *   [G] If logging higher-order derivatives (gradient, Laplacian), compute them *before* `backward()` to preserve the autograd graph [S3, unofficial].
        *   Update parameters: `optimizer.step()` [S18, unofficial].
        *   Update learning rate scheduler [S5, unofficial][S11, unofficial].
    *   **Logging and Checkpointing:**
        *   Log loss and PSNR every `i_print` steps [S2, unofficial][S14, unofficial].
        *   Render validation images every `i_img` steps [S2, unofficial].
        *   Save checkpoint every `i_weights` steps [S2, unofficial].

**Parameters with Typical Values:**
*   $N_{rand}$ (Batch Size): 1024 or 2048 rays per iteration [S5, unofficial][S11, unofficial].
*   $N_{iters}$ (Total Steps): 100,000 to 1,000,000 [S11, unofficial][S14, unofficial].
*   Learning Rate ($lr$): $5 \times 10^{-4}$ for Adam [S11, unofficial].
*   Decay: Exponential decay with `decay_steps` = $args.lrate\_decay \times 1000$ and `decay_rate` = 0.1 [S5, unofficial].
*   Positional Encoding Frequency ($L$): 10 for position, 4 for direction [S11, unofficial].
*   Chunk Size: 8192 or 2048 rays to limit VRAM [S5, unofficial][S14, unofficial].

**Edge Cases and Pitfalls:**
*   **VRAM Overflow:** Rendering all rays at once can exceed GPU memory. Mitigated by chunking [S5, unofficial].
*   **Gradient Graph Destruction:** Computing gradients for logging (e.g., Laplacian) after `backward()` fails because the graph is freed. Must be done before [S3, unofficial].
*   **Empty Checkpoints:** Loading a checkpoint with step 0 indicates an empty state; training should abort or reinitialize [S15, unofficial].
*   **Resuming Training:** When resuming, the scheduler's last epoch must be set to `start_epoch - 1` to maintain correct decay [S9, unofficial].
*   **Ray Shuffling:** Ray indices should be shuffled at the start of each epoch or when the batch iterator resets to ensure random sampling order [S11, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.optim as optim

def train_nerf_loop(model, optimizer, scheduler, dataloader, num_iters, 
                    batch_size=1024, render_interval=500, save_interval=10000):
    """
    Main training loop for NeRF.
    
    Args:
        model: Neural Radiance Field model (MLP).
        optimizer: Optimizer (e.g., Adam).
        scheduler: Learning rate scheduler.
        dataloader: Iterator yielding (rays_o, rays_d, target_rgb) batches.
        num_iters: Total number of training iterations.
        batch_size: Number of rays per batch.
        render_interval: Steps between validation renders.
        save_interval: Steps between checkpoint saves.
    """
    model.train()
    mse_loss = nn.MSELoss()
    
    for step in range(1, num_iters + 1):
        # 1. Data Loading / Ray Sampling
        # In a real implementation, dataloader might yield pre-computed rays
        # or generate them on-the-fly from image indices.
        try:
            rays_o, rays_d, target_rgb = next(data_iterator)
        except StopIteration:
            data_iterator = iter(dataloader)
            rays_o, rays_d, target_rgb = next(data_iterator)
            
        # Move to device
        rays_o = rays_o.to(device)
        rays_d = rays_d.to(device)
        target_rgb = target_rgb.to(device)
        
        # 2. Forward Pass
        # Render rays using the model's render function
        # This function handles ray marching, network querying, and compositing
        rendered_rgb, extras = model.render(rays_o, rays_d)
        
        # 3. Loss Computation
        # Primary photometric loss
        loss = mse_loss(rendered_rgb, target_rgb)
        
        # Optional: Coarse-to-fine loss
        if 'rgb_coarse' in extras:
            loss += mse_loss(extras['rgb_coarse'], target_rgb)
            
        # Optional: Regularization (e.g., sparsity, Eikonal)
        # loss += regularization_weight * extras['reg_loss']
        
        # 4. Backpropagation
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 5. Learning Rate Scheduling
        scheduler.step()
        
        # 6. Logging and Checkpointing
        if step % 100 == 0:
            psnr = -10.0 * torch.log10(loss).item()
            print(f"Step {step}: Loss={loss.item():.6f}, PSNR={psnr:.2f}")
            
        if step % render_interval == 0:
            with torch.no_grad():
                # Render validation images
                val_images = render_validation(model, val_data)
                log_images(val_images, step)
                
        if step % save_interval == 0:
            save_checkpoint(model, optimizer, scheduler, step, 'checkpoint.pt')
```

## Subtopics

### [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md)
The differentiable forward pass that synthesizes RGB images from a neural radiance field during optimization. It sets itself apart from evaluation by using stochastic perturbations, adaptive sampling strategies (e.g., occupancy grid pruning), and chunked processing to manage memory, whereas evaluation disables these for deterministic results.

### [Training Configuration](2332-training-configuration.md)
Defines the hyperparameters, optimization routines, and architectural constraints required to stabilize and accelerate the differentiable volume rendering optimization process. It addresses the sensitivity of radiance field training to initialization, sampling density, and activation function choices. Unlike general optimization loops, it specifies implementation-specific details such as learning rate schedules, loss weights, and batch sampling strategies that are critical for convergence in methods like mip-NeRF, Instant-NGP, and NeuralVDB.

### [Neural Volume Scene Setup](4168-neural-volume-scene-setup.md)
Constructs a Mitsuba scene containing a volumetric cube and a custom neural radiance field integrator, initializing the density grid and spherical harmonics coefficients. It differs from generic training setups by directly binding the neural network parameters to the scene graph's heterogeneous volume and integrator components.

### [Camera Pose and Parameter Optimization](7611-camera-pose-and-parameter-optimization.md)
Refers to the family of methods that jointly optimize the parameters of a Neural Radiance Field (NeRF) and the camera poses (extrinsics) and/or intrinsics (e.g., focal length) from a set of input images. It solves the problem of reconstructing 3D scenes when camera parameters are unknown, inaccurate, or when the system requires online pose estimation for navigation. Unlike baseline NeRF, which relies on pre-estimated poses from Structure-from-Motion (SfM) pipelines like COLMAP, these methods treat camera parameters as learnable variables updated via gradient descent alongside the NeRF weights. This family encompasses static scene reconstruction with unknown poses, hybrid 2D/3D registration, and online robot navigation filters.

### [Regularization and Loss Functions](8586-regularization-and-loss-functions.md)
This family encompasses the mathematical terms added to the standard photometric reconstruction loss to constrain the optimization of Neural Radiance Fields (NeRFs), addressing issues such as under-constrained geometry, floaters, and color artifacts in sparse or few-view settings. It distinguishes itself from sibling methods like [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md) by focusing on the objective function's structure rather than the sampling strategy, and from [Training Configuration](2332-training-configuration.md) by defining the specific gradients that drive parameter updates.

### [Progressive Inpainting-and-Erasing](8658-progressive-inpainting-and-erasing.md)
Progressive Inpainting-and-Erasing (PERF) is a training strategy for single-view NeRF that avoids geometry conflicts between visible and invisible regions by computing a mask of conflicted regions and eliminating them from NeRF training. It sets itself apart from standard single-view NeRF methods by integrating a collaborative RGBD inpainting step with a progressive erasing mechanism to handle the ambiguity of unseen geometry, building on the [NeRF Training Loop](970-nerf-training-loop.md) by dynamically expanding the reference view set.

### [KNN-NeRF](8672-knn-nerf.md)
KNN-NeRF is a baseline method for training Neural Radiance Fields (NeRFs) using sparse 3D point clouds as supervision instead of multi-view images. It solves the problem of generating ground-truth color labels for rays that do not pass through existing points by assigning the color of the nearest point in the cloud to the ray. Unlike standard NeRF which relies on pixel colors from images, KNN-NeRF constructs a dense training signal from sparse geometry, though it struggles with sharp object borders due to the low-frequency bias of neural networks and the sparsity of the input.

### [Progressive and Dynamic Scene Growth](8869-progressive-and-dynamic-scene-growth.md)
Addresses the challenge of reconstructing large-scale or complex 3D scenes from limited input data by incrementally expanding the neural representation's capacity or the training dataset. Unlike static NeRF architectures that require pre-defining the entire hierarchy or fixed network size, these methods adaptively grow the model structure or add synthetic reference views during training to resolve occlusions and capture high-frequency details. This family distinguishes itself from sibling methods like [Adaptive Ray Sampling](8870-adaptive-ray-sampling.md) (which focuses on ray selection) and [Sparse NeRF Reconstruction with Geometric and Semantic Initialization](8779-sparse-nerf-reconstruction-with-geometric-and-semantic-initi.md) (which relies on external priors) by actively modifying the model's topology or the set of supervision signals to improve reconstruction quality in complex regions.

### [Adaptive Ray Sampling](8870-adaptive-ray-sampling.md)
Refers to a family of training procedures in neural radiance fields (NeRF) that replace uniform ray sampling with strategies that concentrate computational resources on regions of high geometric or photometric complexity. It solves the inefficiency of uniform sampling, which wastes evaluations on empty space or smooth regions, by dynamically adjusting sample locations or ray selection based on density, error, depth priors, or spatial partitions. This family is distinguished from [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md) by focusing on *where* to sample rather than *how* to integrate, and from [Coarse-to-Fine NeRF](3406-coarse-to-fine-nerf.md) by encompassing broader strategies including error-based mining, depth-guided selection, and superpixel partitioning, not just hierarchical point clustering.

### [Sparse View and Initialization Methods](9394-sparse-view-and-initialization-methods.md)
This family addresses the degradation of NeRF quality—such as blurred geometry, slow convergence, and floaters—when trained on sparse input views (typically 15–20 images or fewer than 50–100 views). It distinguishes itself from standard NeRF training by decoupling the initialization and regularization processes from the default random or empty-space assumptions, instead leveraging external geometric scaffolds, semantic masks, or visibility priors to anchor the optimization.

### [NerfingMVS](9518-nerfingmvs.md)
NerfingMVS is a multi-view depth estimation method that optimizes Neural Radiance Fields (NeRF) directly over implicit volumes, guided by learning-based depth priors derived from sparse Structure-from-Motion and Multi-View Stereo (SfM+MVS) reconstructions. It addresses the shape-radiance ambiguity inherent in NeRF for indoor scenes by eliminating the need for accurate pixel matching across views, instead using external depth estimates to guide the sampling and optimization process. Unlike standard NeRF which samples uniformly or stratified along rays, NerfingMVS incorporates depth priors and their associated confidences into the rendering pipeline to bias sampling towards geometrically plausible regions.

### [NeRV Training](10253-nerv-training.md)
NeRV training optimizes a continuous volumetric representation that decouples scene geometry (shape) from material appearance (reflectance) and lighting interactions (visibility) to enable efficient relighting and view synthesis. It differs from standard NeRF training by introducing a separate "visibility MLP" that predicts ray visibility and termination depth, supervised by consistency terms with the primary shape MLP rather than ground-truth labels, allowing the simulation of direct and one-bounce indirect illumination within the training loop.

### [NeRV Rendering](10264-nerv-rendering.md)
NeRV rendering computes the pixel color for a camera ray by integrating reflected radiance along the ray, where the radiance at each sample point is derived from a physically-based shading model that accounts for direct and indirect illumination. It differs from standard NeRF volume rendering by explicitly modeling surface normals and microfacet BRDF parameters via separate MLPs, and by estimating indirect lighting through secondary visibility queries rather than simple volumetric absorption.

### [Aug-NeRF](10294-aug-nerf.md)
Aug-NeRF is a training framework for Neural Radiance Fields (NeRF) that injects worst-case adversarial perturbations into three distinct levels of the pipeline—input coordinates, intermediate features, and pre-rendering output—to implicitly regularize the model with physical grounds. It addresses the generalization gap in NeRF where interpolation between seen views yields inconsistent and non-smooth geometries. Unlike explicit regularizers like Laplacian or Total Variation which constrain MLP flexibility aggressively, Aug-NeRF uses data-adaptive smoothness priors to enhance generalization to unseen views without sacrificing representation flexibility.

### [Cross-Guided Optimization of Radiance Fields (CROP)](10371-cross-guided-optimization-of-radiance-fields-crop.md)
Cross-Guided Optimization of Radiance Fields (CROP) is a framework that performs multi-view image super-resolution (MVSR) on training-view images during the radiance field optimization process to improve high-resolution novel view synthesis (HRNVS). It fuses single-image super-resolution (SISR) features with voxel-based uncertainty fields to ensure multi-view consistency and high-frequency details. Unlike methods that rely solely on the spectral characteristics of coordinate-based networks for upscaling, CROP explicitly bridges 2D SISR and 5D radiance fields by iteratively refining input images based on rendering errors.

### [Application-Specific Pipelines](11200-application-specific-pipelines.md)
Application-Specific Pipelines are specialized training and optimization procedures designed to address distinct downstream tasks—such as rapid reconstruction, pose estimation, or scene editing—rather than generic radiance field optimization. They diverge from standard NeRF training by integrating external priors (e.g., multi-view stereo data, diffusion models, or dynamics models) and modifying the loss landscape or rendering loop to suit specific constraints like speed, geometric accuracy, or semantic control.

### [Scene Representation and Architecture](11368-scene-representation-and-architecture.md)
This article defines the canonical implicit volumetric representation used in Neural Radiance Fields (NeRF), establishing the standard Multi-Layer Perceptron (MLP) topology, positional encoding schemes, and volume rendering integration that serve as the baseline for optimization. It addresses the problem of how to map 3D spatial coordinates and viewing directions to density and color values to synthesize novel views. It sets itself apart from sibling methods like [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md) by focusing on the neural network's internal structure and feature encoding rather than the sampling strategy, and from [Specific Model Architectures](8585-specific-model-architectures.md) by describing the unmodified baseline rather than variants like VaxNeRF or SimpleNeRF.

### [Acceleration and Sparse Structures](11405-acceleration-and-sparse-structures.md)
Acceleration and Sparse Structures optimize the computational bottleneck of NeRF training and rendering by replacing dense, uniform ray sampling with sparse data structures or constrained sampling volumes. This family solves the problem of excessive MLP invocations and memory bandwidth limitations inherent in standard volumetric rendering. It sets itself apart from sibling methods like [Adaptive Ray Sampling](8870-adaptive-ray-sampling.md) by explicitly discretizing the scene into grids or hulls to enable memory-bound lookups rather than iterative density-based decisions, and from [Scene Representation and Architecture](11368-scene-representation-and-architecture.md) by focusing on inference-time speedups via caching rather than training-time representation efficiency.

### Supersampling Baseline
A baseline method for evaluating NeRF on multiscale data by training on full-resolution images and using brute-force supersampling during evaluation, or training on multiscale data with supersampling during both training and evaluation [S21]. For every pixel, it casts multiple jittered rays sampled uniformly at random through the spatial footprint of the pixel, renders each ray with NeRF, and uses the mean of those rendered values as the predicted color in the loss function [S21]. The full-resolution supersampling baseline relies on 'oracle' scale information that does not exist for most datasets [S21]. Performance-wise, the 16x supersampling baseline performs worse than mip-NeRF and is significantly more expensive during both training and evaluation [S21].

### Two-stage training for proposers
A training schedule split into two equal-duration phases to stabilize learning of a trainable proposer network in NeRF-ID [S22, unofficial]. Phase 1 trains the learnt proposer to mimic the heuristic proposer by minimizing the L2 matching loss between their proposal sets [S22, unofficial]. Phase 2 trains all network components end-to-end, resetting the optimizer state and performing a linear warmup for 1,000 SGD steps to reduce shock from switching regimes [S22, unofficial]. Training from scratch sometimes works but often fails; two-stage training is consistently effective [S22, unofficial].

### Surface-aware density formulation
A method to extract high-quality surfaces from NeRF by modeling geometry as a distance function or occupancy field and converting its output to density using a probability density function [S23]. It incorporates an eikonal term to encourage geometric consistency, enforcing that the gradient norm of the learned SDF is equal to one [S23]. The density distribution is modeled as $\Phi_S(x) = \frac{se^{-sx}}{1+e^{-sx}}$, where $s$ is a scaling parameter and $x$ is the SDF or occupancy value [S23].

### Incremental Registration
A training strategy that registers frames incrementally following temporal order, leveraging the intuition that camera motions in videos are smooth and adjacent poses are close [S24]. At the start of training, it jointly optimizes NeRF parameters $\Theta$ and poses $\{P_1, P_2\}$ from the first two frames $\{I_1, I_2\}$ [S24]. After every $k$ iterations, it adds a new frame $I_i$ and initializes its pose $P_i$ by the previous pose $P_{i-1}$ [S24]. It freezes the learning rate on poses $\{P_i\}$ and NeRF $\Theta$ until all frames are registered, applying a learning rate decay schedule after all $N$ images are added [S24]. Typical values for $k$ are 1k iterations for CO3D/HO3D datasets and 500 iterations for LLFF dataset, with freeze durations of 100k iterations for HO3D/CO3D and 30k for LLFF [S24].

### NeRF-GT Baseline Training Setup
A training setup that trains the NeRF model using HDR views (or consistently exposed LDR views) as input [S25]. During training, it tone-maps the predicted HDR pixel values into LDR pixel values and computes the loss by comparing the tone-mapped predictions to the tone-mapped ground truth LDR views [S25]. Training directly on HDR views can fail to encode all scene areas well due to the high dynamic range, even when using tone-mapped colors for loss calculation [S25].

## Operating characteristics
*   **Time Complexity:** $O(N_{iters} \cdot N_{rand} \cdot N_{samples} \cdot C_{MLP})$, where $N_{iters}$ is total iterations, $N_{rand}$ is batch size, $N_{samples}$ is samples per ray, and $C_{MLP}$ is the cost of a forward pass through the network [S5, unofficial][S14, unofficial].
*   **Memory Complexity:** $O(N_{rand} \cdot N_{samples} \cdot D)$, where $D$ is the dimensionality of intermediate activations (density, color, gradients) [S5, unofficial]. VRAM usage is mitigated by chunking rays [S5, unofficial].
*   **Measured Performance:** Training typically requires 100,000 to 1,000,000 iterations [S11, unofficial][S14, unofficial]. For a 128x128 image, training may take 250 epochs or ~100k steps [S4, unofficial][S11, unofficial].
*   **Scaling:** Performance scales with batch size, but larger batches hinder data loading performance and reduce throughput due to GPU occupancy limits; a trade-off (e.g., $2^{10}$ rays) is often chosen [S15, unofficial].
*   **Strengths:** End-to-end differentiable, handles complex view-dependent effects, produces high-quality novel views.
*   **Limitations:** Slow convergence due to high iteration counts, sensitive to hyperparameters (learning rate, encoding frequency), prone to floaters and under-constrained geometry without regularization [S1][S5, unofficial].
*   **When to Use:** When high-quality novel view synthesis is required and ground-truth geometry is not available.
*   **When Not to Use:** When real-time performance is critical (use [Acceleration and Sparse Structures](11405-acceleration-and-sparse-structures.md)) or when sparse views are available (use [Sparse View and Initialization Methods](9394-sparse-view-and-initialization-methods.md)).

## Background
The NeRF Training Loop was introduced in the seminal paper "NeRF: Representing Scenes as Neural Radiance Fields for View Synthesis" by Mildenhall et al. (2020) [S5, unofficial]. It established the standard paradigm of optimizing a coordinate-based MLP to minimize photometric error between rendered and observed images. Subsequent developments have focused on acceleration (Instant-NGP), multi-scale representations (Mip-NeRF), and robustness to sparse views or unknown poses [S1][S11, unofficial][S21].
