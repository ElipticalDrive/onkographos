# NeRF Training Loop

Also called: IPE (Interatomic Positional Encoding), Interatomic Positional Encoding, NeRF Optimization Loop, NeRF Training Procedure, Neural Radiance Field (NeRF) Training

## Overview
The NeRF Training Loop is the iterative optimization procedure that learns a continuous volumetric scene representation by minimizing the difference between rendered images and ground-truth observations [S5, S6, S14, unofficial]. It solves the inverse rendering problem by updating the parameters of a neural network (typically an MLP) that maps 3D coordinates and view directions to volume density and color [S5, S14, unofficial]. Unlike methods that render full images per step, it typically samples random rays (batches) to enable stochastic gradient descent, significantly reducing memory usage and compute per iteration [S5, S14, unofficial].

## How it works
**Inputs:** A set of $N$ training images with known camera poses (extrinsics $C_i$ and intrinsics $K_i$) and pixel colors.
**Outputs:** A trained neural network $f_\theta$ (and potentially auxiliary structures like occupancy grids) that approximates the radiance field.

**Data Structures:**
1.  **Ray Bundle (`rays_rgb`):** A pre-computed or on-the-fly generated array of shape $[N_{rays}, 3, 3]$ (or $[N_{rays}, 8]$ if including near/far bounds and view directions) [S5, S14, unofficial].
    *   Axis 0: Ray index.
    *   Axis 1: Channel type (0: Ray Origin $\mathbf{o}$, 1: Ray Direction $\mathbf{d}$, 2: Target RGB $\mathbf{c}_{gt}$) [S5, S14, unofficial].
    *   Axis 2: Components (x, y, z).
    *   Type: `float32` [S5, S14, unofficial].
2.  **Model State:** Dictionary containing `model` (network weights), `optimizer` (optimizer state), and optionally `scheduler` state [S11, unofficial].
3.  **Occupancy Grid (Optional):** A sparse grid (e.g., 3D hash table or voxel grid) used to prune empty space during ray marching [S15, unofficial].

**Numbered Steps:**

1.  **Initialization:**
    *   Load training and validation datasets [S8][S11, unofficial].
    *   Initialize the neural network $f_\theta$ (e.g., MLP with positional encoding) [S11, S15, unofficial].
    *   Initialize the optimizer (typically Adam) with learning rate $\eta$ [S5, S11, unofficial].
    *   Initialize the learning rate scheduler (e.g., Exponential Decay or Cosine Annealing) [S5, S11, unofficial].
    *   If using occupancy grids, initialize the grid (e.g., with zeros or pre-computed densities) [S15, unofficial].

2.  **Ray Sampling:**
    *   Randomly select $N_{rand}$ pixels from the training images [S5, S14, unofficial].
    *   For each pixel, compute the ray origin $\mathbf{o}$ and direction $\mathbf{d}$ using camera parameters [S4, S14, unofficial].
    *   Sample $K$ points along the ray between near ($t_{near}$) and far ($t_{far}$) bounds [S5, S13, unofficial].
        *   Uniform sampling: $t_i \sim \text{Uniform}(t_{near}, t_{far})$ [S5, unofficial].
        *   Stratified sampling: Add uniform noise to stratified intervals to reduce variance [S5, unofficial].
        *   Perturbation: Jitter sampling times by $t \in [0, 1]$ to break symmetry [S2, unofficial].
    *   Form the batch tensor `batch_rays` containing $\mathbf{o}, \mathbf{d}$ and `target_s` containing $\mathbf{c}_{gt}$ [S5, S14, unofficial].

3.  **Forward Pass (Rendering):**
    *   Query the network $f_\theta(\mathbf{x}, \mathbf{d})$ for each sample point $\mathbf{x}_i$ on the ray to get raw output $\mathbf{r}_i = (\sigma_i, \mathbf{c}_i)$ [S5, S14, unofficial].
    *   Compute transmittance $T_i$ and weights $w_i$ using the emission-absorption model [S5, S14, unofficial]:
        $$ T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right) $$
        $$ w_i = T_i (1 - \exp(-\sigma_i \delta_i)) $$
        where $\delta_i$ is the distance between adjacent samples [S5, S14, unofficial].
    *   Composite the final color $\hat{\mathbf{C}}$:
        $$ \hat{\mathbf{C}} = \sum_{i=1}^K w_i \mathbf{c}_i $$
    *   If using a coarse-fine scheme, render a coarse image, sample additional points based on coarse weights (importance sampling), and render a fine image [S5, S11, unofficial].

4.  **Loss Computation:**
    *   Compute the Mean Squared Error (MSE) between predicted color $\hat{\mathbf{C}}$ and ground truth $\mathbf{c}_{gt}$ [S5, S14, unofficial]:
        $$ \mathcal{L}_{rgb} = \frac{1}{N_{pixels}} \sum_{p=1}^{N_{pixels}} \|\hat{\mathbf{C}}_p - \mathbf{c}_{gt, p}\|^2 $$
    *   If coarse-fine training is used, add the coarse loss $\mathcal{L}_{coarse}$ to the total loss [S11, unofficial]:
        $$ \mathcal{L} = \mathcal{L}_{fine} + \mathcal{L}_{coarse} $$
    *   Apply additional regularization losses if defined (e.g., sparsity, eikonal, TV) [S7, unofficial][S8].

5.  **Backpropagation and Update:**
    *   Compute gradients $\nabla_\theta \mathcal{L}$ via automatic differentiation [S5, S14, unofficial].
    *   Update network weights $\theta$ using the optimizer step [S5, S14, unofficial].
    *   Update the learning rate according to the scheduler [S5, S11, unofficial].

6.  **Logging and Checkpointing:**
    *   Log loss metrics (PSNR, SSIM) at specified intervals [S11, unofficial].
    *   Render validation images at specified intervals [S11, unofficial].
    *   Save model checkpoints (weights, optimizer state, epoch) at specified intervals [S11, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import DataLoader

def train_nerf_loop(model, train_dataset, val_dataset, config):
    """
    Main training loop for NeRF.
    
    Args:
        model: Neural Radiance Field model (MLP).
        train_dataset: Dataset yielding (rays_o, rays_d, target_rgb, near, far).
        val_dataset: Validation dataset.
        config: Configuration dictionary containing hyperparameters.
    """
    # 1. Initialization
    optimizer = optim.Adam(model.parameters(), lr=config['lr'])
    scheduler = optim.lr_scheduler.ExponentialLR(optimizer, gamma=config['decay_rate'])
    mse_loss = nn.MSELoss()
    
    data_loader = DataLoader(train_dataset, batch_size=config['batch_size'], shuffle=True)
    
    n_iters = config['n_iters']
    log_every = config['log_every']
    save_every = config['save_every']
    
    for step in range(n_iters):
        # 2. Ray Sampling (handled by DataLoader or custom sampler)
        # In a real implementation, rays are sampled from the dataset
        # Here we assume the dataloader yields a batch of rays
        try:
            batch = next(data_loader_iter)
        except StopIteration:
            data_loader_iter = iter(data_loader)
            batch = next(data_loader_iter)
            
        rays_o, rays_d, target_rgb, near, far = batch
        
        # 3. Forward Pass
        optimizer.zero_grad()
        
        # Sample points along rays
        # t_vals = torch.linspace(0., 1., steps=config['num_samples'])
        # t_vals = near + (far - near) * t_vals
        # pts = rays_o[:, None, :] + rays_d[:, None, :] * t_vals[..., None]
        
        # Render
        # raw = model(pts, rays_d) # Returns (sigma, rgb)
        # rgb = render_volume(raw, t_vals, rays_d)
        
        # Placeholder for actual rendering function
        rgb = model.render(rays_o, rays_d, near, far, config['num_samples'])
        
        # 4. Loss Computation
        loss = mse_loss(rgb, target_rgb)
        
        # Optional: Add coarse loss if using coarse-fine scheme
        if 'rgb_coarse' in model.state:
            loss += mse_loss(model.state['rgb_coarse'], target_rgb)
            
        # 5. Backpropagation and Update
        loss.backward()
        optimizer.step()
        scheduler.step()
        
        # 6. Logging and Checkpointing
        if step % log_every == 0:
            psnr = -10.0 * torch.log10(loss)
            print(f"Step {step}: Loss {loss.item():.6f}, PSNR {psnr.item():.2f}")
            
        if step % save_every == 0:
            torch.save({
                'step': step,
                'model_state_dict': model.state_dict(),
                'optimizer_state_dict': optimizer.state_dict(),
            }, f'checkpoint_{step}.pth')

    return model
```

**Parameters:**
*   `lr` (Learning Rate): Default $5 \times 10^{-4}$ [S11, unofficial].
*   `batch_size` ($N_{rand}$): Number of rays per iteration. Typical values: 1024 or 2048 [S5, S11, unofficial].
*   `num_samples` ($K$): Number of points sampled per ray. Typical values: 128 (coarse) and 128 (fine) [S5, S11, unofficial].
*   `n_iters`: Total number of optimization steps. Default: 100,000 [S11, unofficial].
*   `decay_rate`: Factor for exponential learning rate decay. Default: 0.1 [S5, S18, unofficial].
*   `decay_steps`: Steps after which decay begins. Calculated as `args.lrate_decay * 1000` [S5, S18, unofficial].
*   `near` / `far`: Near and far clipping planes. Vary by dataset (e.g., Blender: 2.0, 6.0; LLFF: computed from bounding depths) [S2, S13, unofficial].

**Edge Cases and Pitfalls:**
*   **VRAM Overflow:** Rendering full images exceeds GPU memory. Mitigated by batching rays (`chunk` parameter) [S5, S14, unofficial].
*   **Gradient Freeing:** Higher-order derivatives (e.g., for logging gradients) must be computed before `loss.backward()` [S3, unofficial].
*   **Checkpoint Resumption:** When resuming, the scheduler's last epoch must be set to `start_epoch - 1` to maintain correct decay [S9, unofficial].
*   **Empty Checkpoints:** Loading a checkpoint with step 0 should be treated as an error or re-initialization [S15, unofficial].
*   **Instability in Growing Networks:** Directly growing sub-networks from random initialization causes density collapse. Initialize grown sub-networks' alpha weights to match the parent network [S1].

### Supersampling Baseline
A baseline method for evaluating NeRF on multiscale data by training on full-resolution images and using brute-force supersampling during evaluation, or training on multiscale data with supersampling during both training and evaluation [S21]. For every pixel, multiple jittered rays are cast through the pixel's spatial footprint, rendered, and averaged [S21]. This approach relies on 'oracle' scale information and performs worse than mip-NeRF while being significantly more expensive [S21].

### Two-stage training for proposers
A training schedule split into two equal-duration phases to stabilize learning of a trainable proposer network in NeRF-ID [S22, unofficial]. Phase 1 trains the proposer to mimic a heuristic proposer by minimizing L2 matching loss between proposal sets. Phase 2 trains all components end-to-end, resetting the optimizer and performing a 1,000-step linear warmup [S22, unofficial]. This two-stage approach is consistently effective where training from scratch often fails [S22, unofficial].

### Multi-view SDS
A plug-and-play method that creates multi-view supervision during SDS optimization to address the Janus problem caused by one-by-one view sampling [S23]. Rendered images from 4 sampled views are stitched into a 2x2 image, and gradients are calculated under the condition of the multi-view normal map [S23]. This optimizes 3D assets into differentiable representations like NeRF, 3DGS, and DMTet [S23].

### Guided NeRF Optimization for MVS
A multi-view depth estimation method utilizing conventional reconstruction (sparse SfM+MVS) and learning-based priors over NeRF [S24]. It performs test-time optimization over implicit volumes to eliminate the need for accurate pixel matching, addressing shape-radiance ambiguity in indoor scenes [S24]. It runs COLMAP for sparse depth maps and finetunes a monocular depth network on them [S24].

### Surface-aware density formulation
A method to extract high-quality surfaces from NeRF by modeling geometry as a distance function or occupancy field and converting its output to density using a probability density function [S25]. It incorporates an eikonal term to encourage geometric consistency, enforcing that the gradient norm of the learned SDF is equal to one [S25]. The density distribution is modeled as $\Phi_S(x) = \frac{se^{-sx}}{1+e^{-sx}}$, where $s$ is a scaling parameter and $x$ is the SDF value [S25].

## Operating characteristics
*   **Time Complexity:** $O(N_{iters} \cdot N_{rand} \cdot K \cdot D)$, where $N_{iters}$ is iterations, $N_{rand}$ is batch size, $K$ is samples per ray, and $D$ is network depth/width [S5, S14, unofficial].
*   **Memory Complexity:** $O(N_{rand} \cdot K \cdot D)$ for storing intermediate activations during backpropagation, plus $O(N_{rays})$ for pre-computed ray bundles if batching is used [S5, S14, unofficial].
*   **Performance:** Typical training takes 100,000 iterations (approx. 1-2 hours on a single GPU for synthetic scenes) [S11, unofficial]. PSNR increases from ~10 dB to ~19 dB over 20 epochs for small datasets [S12].
*   **Scaling:** Batch size affects throughput; too small limits GPU occupancy, too large hinders data loading [S15, unofficial]. Occupancy grids can reduce effective $K$ by pruning empty space [S15, unofficial].
*   **Strengths:** High-quality novel view synthesis; handles complex lighting and geometry implicitly.
*   **Limitations:** Slow training and rendering; prone to artifacts (floaters) in unobserved regions; requires careful hyperparameter tuning [S1][S17, unofficial].

## Background
The NeRF Training Loop was introduced by Mildenhall et al. in "NeRF: Representing Scenes as Neural Radiance Fields for View Synthesis" (2020) [S5, S18, unofficial]. It builds upon earlier work on implicit neural representations and differentiable volume rendering. The method has become a standard baseline for inverse rendering and 3D scene reconstruction, inspiring numerous variants and extensions in both academic research and industry applications [S1, S25].
