# Training Ray Batching

Also called: Random Ray Batching, Random Ray Batching for NeRF Training, Random Ray Sampling, batch ray selection, partial ray sampling

## Overview
Training Ray Batching is a data loading strategy for Neural Radiance Fields (NeRF) that selects a random subset of pixel coordinates (and thus rays) from the full image grid per training iteration to reduce GPU memory usage during the backward pass of gradient descent [S1, unofficial]. It differs from single-image sampling by globally shuffling rays from all training images, ensuring the network sees a diverse mix of viewpoints in every batch rather than focusing on one image at a time [S2, unofficial]. This method builds on [Training Loop Setup](1522-training-loop-setup.md) by providing the structured ray tensors that are subsequently shuffled and sampled [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `poses`: Array of camera extrinsic matrices, shape `(num_img, 3, 4)` [S2, unofficial].
    *   `images`: Array of target RGB images, shape `(num_img, H, W, 3)` [S2, unofficial].
    *   `K`: Camera intrinsic matrix, shape `(3, 3)` [S2, unofficial]. Simplified form: `[[f, 0, W/2], [0, f, H/2], [0, 0, 1]]` where `f` is focal length [S2, unofficial].
    *   `i_train`: List of indices for training images [S2, unofficial].
    *   `N_rand`: Number of rays to sample per batch (default 4096, often `32x32x4`) [S2, unofficial].
    *   `use_batching`: Boolean flag. If `True`, sample from all images globally. If `False`, sample from a single random image per iteration [S2, unofficial].
*   **Outputs:**
    *   `batch_rays`: Tensor of shape `(2, N_rand, 3)` containing ray origins and directions [S2, unofficial].
    *   `target_s`: Tensor of shape `(N_rand, 3)` containing target RGB colors [S2, unofficial].

**Data Structures:**
The core data structure is a flat tensor `rays_rgb` of shape `(N_total_rays, 3, 3)` where `N_total_rays = len(i_train) * H * W`. The three channels along the second dimension correspond to:
1.  Ray Origin `(x, y, z)`
2.  Ray Direction `(x, y, z)`
3.  Target RGB `(r, g, b)` [S2, unofficial].

**Steps:**

1.  **Generate Rays:** For each training image `i` in `i_train`, compute ray origins and directions using `get_rays_np(H, W, K, poses[i])`. Stack these into a tensor `rays` of shape `(len(i_train), 2, H, W, 3)` [S2, unofficial].
2.  **Concatenate Targets:** Concatenate `rays` with the corresponding target images `images[i]` along the channel dimension. Result `rays_rgb` has shape `(len(i_train), 3, H, W, 3)` [S2, unofficial].
3.  **Transpose:** Transpose `rays_rgb` to `(len(i_train), H, W, 3, 3)` to group spatial dimensions together [S2, unofficial].
4.  **Reshape:** Flatten the spatial and image dimensions into a single list of rays. Reshape to `(-1, 3, 3)`. The total number of rows is `len(i_train) * H * W` [S2, unofficial].
5.  **Shuffle:** Randomly shuffle the order of rows in `rays_rgb` using a random permutation [S2, unofficial].
6.  **Sample Batch:** In each training iteration, slice the shuffled tensor to get `N_rand` rays. Transpose to separate origins, directions, and targets:
    *   `batch_rays = batch[:2]` -> shape `(2, N_rand, 3)`
    *   `target_s = batch[2]` -> shape `(N_rand, 3)` [S2, unofficial].
7.  **Epoch Management:** Maintain an index `i_batch`. Increment by `N_rand` each step. If `i_batch >= N_total_rays`, reshuffle the entire `rays_rgb` tensor and reset `i_batch` to 0 [S2, unofficial].

**Pseudocode:**

```python
import numpy as np
import torch

def prepare_ray_batch(poses, images, K, i_train, H, W):
    """
    Prepares the global ray batch tensor for random ray batching.
    
    Args:
        poses: (num_img, 3, 4) extrinsic matrices
        images: (num_img, H, W, 3) target RGB images
        K: (3, 3) intrinsic matrix
        i_train: list of training image indices
        H, W: image height and width
        
    Returns:
        rays_rgb: (N_total_rays, 3, 3) tensor, dtype float32
    """
    # Step 1: Generate rays for all training images
    # get_rays_np returns (2, H, W, 3) -> (origins, directions)
    rays_list = []
    for i in i_train:
        p = poses[i]
        rays = get_rays_np(H, W, K, p)
        rays_list.append(rays)
    
    # Stack into (len(i_train), 2, H, W, 3)
    rays = np.stack(rays_list, axis=0)
    
    # Step 2: Concatenate with target images
    # images[i] is (H, W, 3). Need to add dim to match rays shape
    # rays_rgb shape: (len(i_train), 3, H, W, 3)
    # Note: The source code uses images[:,None] assuming images is already filtered or indexed.
    # Here we assume images is (num_img, H, W, 3) and we index it.
    train_images = np.array([images[i] for i in i_train]) # (len(i_train), H, W, 3)
    train_images = train_images[:, np.newaxis, :] # (len(i_train), 1, H, W, 3)
    
    rays_rgb = np.concatenate([rays, train_images], axis=1) # (len(i_train), 3, H, W, 3)
    
    # Step 3: Transpose to (len(i_train), H, W, 3, 3)
    rays_rgb = np.transpose(rays_rgb, [0, 2, 3, 1, 4])
    
    # Step 4: Reshape to flat list (-1, 3, 3)
    rays_rgb = rays_rgb.reshape(-1, 3, 3)
    
    # Step 5: Convert to float32
    rays_rgb = rays_rgb.astype(np.float32)
    
    # Step 6: Shuffle
    np.random.shuffle(rays_rgb)
    
    return rays_rgb

def sample_batch(rays_rgb, N_rand, i_batch):
    """
    Samples a batch of rays from the pre-shuffled tensor.
    
    Args:
        rays_rgb: (N_total_rays, 3, 3) tensor
        N_rand: int, number of rays per batch
        i_batch: int, current batch index
        
    Returns:
        batch_rays: (2, N_rand, 3)
        target_s: (N_rand, 3)
        new_i_batch: int
        reshuffled: bool
    """
    N_total = rays_rgb.shape[0]
    
    # Check if we need to reshuffle
    if i_batch + N_rand > N_total:
        # Reshuffle
        indices = torch.randperm(N_total)
        rays_rgb = rays_rgb[indices]
        i_batch = 0
        reshuffled = True
    else:
        reshuffled = False
        
    # Slice batch
    batch = rays_rgb[i_batch : i_batch + N_rand] # (N_rand, 3, 3)
    
    # Transpose to (3, N_rand, 3) then split
    batch = torch.transpose(batch, 0, 1) # (3, N_rand, 3)
    
    batch_rays = batch[:2] # (2, N_rand, 3)
    target_s = batch[2]    # (N_rand, 3)
    
    new_i_batch = i_batch + N_rand
    
    return batch_rays, target_s, new_i_batch, reshuffled
```

**Parameters:**
*   `N_rand`: Batch size in rays. Default is 4096 (`32x32x4`) [S2, unofficial]. Controls memory footprint and gradient noise [S1, unofficial].
*   `use_batching`: If `True`, enables global random ray batching. If `False`, falls back to single-image sampling [S2, unofficial].
*   `image_size`: Resolution `H x W` of the training images [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Memory:** If `N_rand` is too large, the batch may exceed GPU memory limits during the backward pass [S1, unofficial].
*   **Boundary Conditions:** The batch index `i_batch` must be reset and data reshuffled when it exceeds the total number of rays to ensure every ray is seen exactly once per epoch [S2, unofficial].
*   **Precision:** Data should be cast to `float32` to ensure compatibility with GPU tensors and standard neural network operations [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Preprocessing is $O(N_{img} \cdot H \cdot W)$ to generate and shuffle all rays [S2, unofficial]. Sampling is $O(N_{rand})$ per iteration [S2, unofficial].
*   **Memory Complexity:** Requires storing all training rays in memory: $O(N_{img} \cdot H \cdot W \cdot C)$ where $C=3$ (origin, direction, target) [S2, unofficial]. This is significantly higher than single-image sampling but allows for efficient batched processing.
*   **Performance:** Reduces GPU memory usage compared to rendering full images, enabling larger networks or higher resolutions [S1, unofficial].
*   **Strengths:** Ensures global coverage of viewpoints in every batch, improving convergence stability [S2, unofficial].
*   **Limitations:** High memory overhead for large datasets. Requires pre-computation and shuffling [S2, unofficial].
*   **When to use:** When GPU memory is limited but dataset size is manageable, and global viewpoint mixing is desired [S2, unofficial].
*   **When not to use:** When memory is extremely constrained (use single-image sampling) or when dataset is too large to fit in RAM (use on-the-fly sampling) [S2, unofficial].

## Background
Originated in the NeRF paper (Mildenhall et al., 2020) as a standard training procedure for Neural Radiance Fields [S2, unofficial]. It addresses the memory bottleneck of rendering full-resolution images for every training step [S1, unofficial]. The method is widely used in differentiable volume rendering pipelines for inverse graphics [S2, unofficial].
