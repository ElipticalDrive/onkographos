# Ray Shuffling & Reordering

Also called: shuffleRays, shuffleToNewGroup

## Overview
Ray Shuffling & Reordering permutes ray data across GPU arrays using an index mapping array to improve training order or batch distribution [S1, unofficial]. It differs from its parent [Training Ray Shuffling](5446-training-ray-shuffling.md) by performing the actual data movement on the GPU via a custom kernel, whereas the parent handles initialization and transfer of indices. It addresses the need to reorder rays for better cache locality or load balancing during differentiable volume rendering optimization.

## How it works
**Inputs:**
- Source ray arrays (`src`) containing: `cameraCenterX_Device`, `cameraCenterY_Device`, `cameraCenterZ_Device`, `directionX_Device`, `directionY_Device`, `directionZ_Device`, `near_t_Device`, `far_t_Device`, `gtMask_Device`, and color channels (`gtGray_Device` if grayscale, else `gtRed_Device`, `gtGreen_Device`, `gtBlue_Device`).
- Destination ray arrays (`dest`) with identical layout.
- `shuffledIndexArray`: A device array of integers mapping destination indices to source indices.
- `src.totalRays`: Total number of rays.
- `src.graylized`: Boolean flag indicating grayscale mode.

**Outputs:**
- Destination ray arrays (`dest`) with rays reordered according to `shuffledIndexArray`.

**Data Structures:**
Rays are stored in Structure of Arrays (SoA) format on the GPU. Each attribute is a separate device array of size `totalRays`.

**Steps:**
1. Host function allocates destination memory for ray attributes.
2. Host function calls `ShuffleRank` (implementation not provided in source) to generate `shuffledIndexArray`.
3. Host function copies `shuffledIndexArray` to GPU.
4. Host function launches the `shuffleToNewGroup` kernel with grid/block dimensions sized to `src.totalRays`.
5. Each thread computes its global `destRayIndex`.
6. If `destRayIndex < src.totalRays`, the thread reads the source index from `shuffledIndexArray[destRayIndex]`.
7. The thread copies all ray attributes from the source arrays to the destination arrays using the mapped source index.
8. If `src.graylized` is true, copy `gtGray_Device`; otherwise, copy `gtRed_Device`, `gtGreen_Device`, and `gtBlue_Device`.

**Pseudocode:**
```python
# Note: This is a conceptual Python-like representation of the CUDA kernel logic.
# In practice, this runs on GPU.

def shuffle_to_new_group(src, dest, shuffled_index_array, total_rays, graylized):
    """
    Simulates the logic of the CUDA kernel shuffleToNewGroup.
    src: dict of device arrays (source rays)
    dest: dict of device arrays (destination rays)
    shuffled_index_array: list/array of integers
    total_rays: int
    graylized: bool
    """
    # Grid/block dimensions are sized to total_rays
    # Each thread handles one destRayIndex
    
    for dest_ray_index in range(total_rays):
        if dest_ray_index >= total_rays:
            break
            
        # Read shuffled index
        src_index = shuffled_index_array[dest_ray_index]
        
        # Copy attributes
        dest['cameraCenterX_Device'][dest_ray_index] = src['cameraCenterX_Device'][src_index]
        dest['cameraCenterY_Device'][dest_ray_index] = src['cameraCenterY_Device'][src_index]
        dest['cameraCenterZ_Device'][dest_ray_index] = src['cameraCenterZ_Device'][src_index]
        
        dest['directionX_Device'][dest_ray_index] = src['directionX_Device'][src_index]
        dest['directionY_Device'][dest_ray_index] = src['directionY_Device'][src_index]
        dest['directionZ_Device'][dest_ray_index] = src['directionZ_Device'][src_index]
        
        dest['near_t_Device'][dest_ray_index] = src['near_t_Device'][src_index]
        dest['far_t_Device'][dest_ray_index] = src['far_t_Device'][src_index]
        
        dest['gtMask_Device'][dest_ray_index] = src['gtMask_Device'][src_index]
        
        if graylized:
            dest['gtGray_Device'][dest_ray_index] = src['gtGray_Device'][src_index]
        else:
            dest['gtRed_Device'][dest_ray_index] = src['gtRed_Device'][src_index]
            dest['gtGreen_Device'][dest_ray_index] = src['gtGreen_Device'][src_index]
            dest['gtBlue_Device'][dest_ray_index] = src['gtBlue_Device'][src_index]
```

**Parameters:**
- `shuffledIndexArray`: Host or device array of integers mapping destination indices to source indices.
- `maxIndex`: Total number of rays to shuffle (equivalent to `src.totalRays`).
- `initialized`: Boolean controlling host memory allocation for indices [S1, unofficial].

**Edge Cases and Pitfalls:**
- If `destRayIndex >= src.totalRays`, the thread returns immediately [S1, unofficial].
- Precision issues may arise if `shuffledIndexArray` contains out-of-bounds indices.
- The kernel assumes `src` and `dest` have the same `totalRays` count.

## Subtopics

### ShuffleRank
Generates the permutation indices. Not given in the sources.

### Batch Ray Sampling
Uses shuffled rays for training. Links to [Batch Ray Sampling](5447-batch-ray-sampling.md).

## Operating characteristics
- **Time Complexity**: O(N) where N is the number of rays, as each ray is copied once.
- **Memory Complexity**: O(N) for the destination arrays and the index array.
- **Performance**: Depends on GPU memory bandwidth and the efficiency of the `ShuffleRank` implementation.
- **Strengths**: Improves training order or batch distribution, potentially leading to better convergence.
- **Limitations**: Requires additional memory for destination arrays and index array.
- **When to use**: When ray order affects training stability or performance.
- **When not to use**: When memory is constrained or ray order is not critical.

## Background
Originated in the Clear-plenoxels project by Bryan Norton [S1, unofficial]. It is used in differentiable volume rendering optimization loops to manage ray data efficiently.
