# NeRF Dataset Loading

Also called: Blender Dataset Loader, NeRF Synthetic Dataset Loading, NeRFDatasetLoader

## Overview
This method loads the NeRF-Synthetic (Blender) dataset by parsing JSON metadata for camera poses and images, handling half-resolution resizing, and returning normalized RGBA images and camera parameters [S1, unofficial]. It differs from [LLFF Dataset Loading](2818-llff-dataset-loading.md) by assuming known, precise camera poses provided in JSON rather than estimating them from images, and by using a fixed scene bounding box [S1, unofficial].

## How it works
**Inputs:**
- `dataset_path`: String path to the root directory of the dataset [S2, unofficial].
- `mode`: String indicating 'train', 'test', or 'val' [S2, unofficial].
- `half_res`: Boolean flag to resize images to half resolution. Default: True [S1, unofficial].

**Outputs:**
- `images`: Tensor of shape $[N, H, W, 4]$ containing float32 RGBA values in $[0, 1]$ [S1, unofficial].
- `poses`: Tensor of shape $[N, 4, 4]$ containing camera-to-world matrices [S1, unofficial].
- `focal`: Float scalar representing the focal length [S1, S2, unofficial].
- `near`: Float scalar, fixed at 2.0 [S1, unofficial].
- `far`: Float scalar, fixed at 6.0 [S1, unofficial].

**Data Structures:**
- JSON metadata file: `transforms_{split}.json` (e.g., `transforms_train.json`) [S1, S2, unofficial].
- Image files: PNG format, named sequentially (e.g., `r_0.png`, `r_1.png`) [S2, unofficial].
- Camera parameters in JSON: `camera_angle_x` (field name) [S1, S2, unofficial].
- Transform matrix in JSON: `transform_matrix` (field name), stored as a list of lists [S1, S2, unofficial].

**Steps:**
1. Construct the path to the JSON metadata file based on `mode`: `transforms_{mode}.json` [S2, unofficial].
2. Load the JSON file and parse the `frames` list [S1, S2, unofficial].
3. For each frame in the list:
   a. Extract the image file path from the frame data and append `.png` extension [S2, unofficial].
   b. Load the image using a library such as OpenCV (`cv2.imread`) [S2, unofficial].
   c. Convert the image to RGBA format if not already [G].
   d. Normalize pixel values to $[0, 1]$ by dividing by 255.0 [S1, S2, unofficial].
   e. If `half_res` is True, resize the image to half its original width and height using LANCZOS interpolation [S1, unofficial]; [S2, unofficial] specifies INTER_AREA instead.
   f. Extract the `transform_matrix` from the frame data and convert it to a PyTorch tensor [S2, unofficial].
4. Calculate the focal length using the formula:
   $$ f = \frac{H}{2 \tan(\frac{\theta_x}{2})} $$
   where $H$ is the image height (after resizing if applicable) and $\theta_x$ is `camera_angle_x` loaded from the JSON root [S1, S2, unofficial].
5. If `half_res` is True, halve the calculated focal length [S1, unofficial].
6. Stack all images into a tensor of shape $[N, H, W, 4]$ [S1, S2, unofficial].
7. Stack all pose matrices into a tensor of shape $[N, 4, 4]$ [S1, S2, unofficial].
8. Return the images, poses, focal length, near (2.0), and far (6.0) [S1, unofficial].

**Pseudocode:**
```python
import os
import json
import math
import numpy as np
import torch
import cv2

class NeRFDatasetLoader:
    def __init__(self, dataset_path: str, mode: str, half_res: bool = True):
        self.dataset_path = dataset_path
        self.mode = mode
        self.half_res = half_res
        
        # Determine JSON file name
        if mode == "test":
            json_file = "transforms_test.json"
        elif mode == "train":
            json_file = "transforms_train.json"
        elif mode == "val":
            json_file = "transforms_val.json"
        else:
            raise ValueError(f"Unknown mode: {mode}")
            
        self.json_path = os.path.join(dataset_path, json_file)
        
        # Load JSON metadata
        with open(self.json_path, 'r') as f:
            self.data = json.load(f)
            
        # Extract global parameters
        self.camera_angle_x = self.data['camera_angle_x']
        
    def __len__(self):
        return len(self.data['frames'])
    
    def __getitem__(self, idx):
        frame = self.data['frames'][idx]
        
        # Load image
        img_path = os.path.join(self.dataset_path, frame['file_path'] + '.png')
        img = cv2.imread(img_path)
        
        # Convert to RGBA if necessary (OpenCV loads as BGR)
        if img.shape[2] == 3:
            img = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
            # Add alpha channel if missing
            if img.shape[2] == 3:
                alpha = np.ones((img.shape[0], img.shape[1], 1), dtype=np.float32)
                img = np.concatenate((img, alpha), axis=2)
        
        # Normalize to [0, 1]
        img = img.astype(np.float32) / 255.0
        
        # Handle half resolution
        h, w = img.shape[:2]
        if self.half_res:
            new_h, new_w = h // 2, w // 2
            # Use INTER_AREA for shrinking [S2, unofficial]; LANCZOS is also specified [S1, unofficial]
            img = cv2.resize(img, (new_w, new_h), interpolation=cv2.INTER_AREA)
            h, w = new_h, new_w
        
        # Convert to tensor [H, W, C] to match output spec
        img_tensor = torch.from_numpy(img)
        
        # Load pose
        pose = torch.tensor(frame['transform_matrix'], dtype=torch.float32)
        
        return img_tensor, pose

    def get_full_data(self, device='cpu'):
        """
        Loads all frames and returns stacked tensors.
        """
        images = []
        poses = []
        
        for i in range(len(self)):
            img, pose = self.__getitem__(i)
            images.append(img)
            poses.append(pose)
            
        images = torch.stack(images, dim=0) # [N, H, W, 4]
        poses = torch.stack(poses, dim=0)   # [N, 4, 4]
        
        # Calculate focal length
        # Formula: f = H / (2 * tan(theta_x / 2))
        focal = (images.shape[1] / 2) / math.tan(self.camera_angle_x / 2)
        
        if self.half_res:
            focal /= 2.0
            
        # Move to device
        images = images.to(device)
        poses = poses.to(device)
        
        near = 2.0
        far = 6.0
        
        return images, poses, focal, near, far
```

**Parameters:**
- `half_res`: Boolean. Default True. Reduces memory and compute cost [S1, unofficial].
- `near`: Fixed at 2.0 for Blender data [S1, unofficial].
- `far`: Fixed at 6.0 for Blender data [S1, unofficial].

**Edge Cases and Pitfalls:**
- Precision: Ensure image normalization is done in float32 to avoid precision loss during training [G].
- Boundaries: The fixed near/far values (2.0/6.0) are specific to the NeRF-Synthetic dataset and may not generalize to other scenes [S1, unofficial].
- Degenerate Input: If the JSON file is malformed or missing, the loader will fail. Validation of JSON structure is recommended [G].
- Interpolation: [S1, unofficial] specifies LANCZOS, while [S2, unofficial] specifies INTER_AREA. INTER_AREA is generally preferred for shrinking images in OpenCV [G].

## Subtopics

### LLFF Dataset Loading
- **What it is:** A loader for the LLFF (Local Light Field Fusion) dataset.
- **Difference:** Estimates camera poses from images using COLMAP or similar structure-from-motion pipelines, unlike NeRF Dataset Loading which uses pre-computed poses.
- **When to choose:** Use when camera poses are not known or when working with real-world captured data rather than synthetic Blender scenes.
- **Link:** [LLFF Dataset Loading](2818-llff-dataset-loading.md)

## Operating characteristics
- **Time Complexity:** $O(N \cdot H \cdot W)$ for loading and resizing $N$ images of size $H \times W$ [S1, S2, unofficial].
- **Memory Complexity:** $O(N \cdot H \cdot W \cdot C)$ to store all images in memory, where $C=4$ for RGBA [S1, S2, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Memory usage scales linearly with the number of frames and resolution. Using `half_res=True` reduces memory by 4x [S1, unofficial].
- **Strengths:** Not given in the sources.
- **Limitations:** Fixed near/far bounds may not suit all scenes; requires specific dataset structure [S1, unofficial].
- **When to use:** For training on the NeRF-Synthetic (Blender) dataset [S1, S2, unofficial].
- **When not:** For real-world datasets with unknown poses (use LLFF loader instead) [S1, S2, unofficial].

## Background
The NeRF-Synthetic dataset consists of synthetic scenes rendered with Blender, providing ground-truth camera poses and images [S1, S2, unofficial]. The dataset loader described here is a common implementation pattern found in various NeRF tutorials and repositories [S1, S2, unofficial].
