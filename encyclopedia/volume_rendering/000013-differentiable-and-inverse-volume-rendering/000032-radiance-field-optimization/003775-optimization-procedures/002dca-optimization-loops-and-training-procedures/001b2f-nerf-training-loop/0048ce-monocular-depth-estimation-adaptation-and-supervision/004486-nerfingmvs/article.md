# NerfingMVS

Also called: Guided NeRF Optimization for MVS, Guided Optimization of Neural Radiance Fields for Indoor Multi-View Stereo, NeRF with Depth Priors

## Overview
NerfingMVS is a multi-view depth estimation method that integrates conventional sparse Structure-from-Motion and Multi-View Stereo (SfM+MVS) reconstruction with learning-based monocular depth priors to optimize Neural Radiance Fields (NeRF) [S2]. It addresses the shape-radiance ambiguity inherent in NeRFs for indoor scenes by using depth priors to guide volume sampling, thereby eliminating the need for accurate pixel matching across views during the optimization phase [S2]. Unlike standard NeRF which samples uniformly or stratified along rays, NerfingMVS clamps ray bounds and guides sampling positions using scene-specific depth estimates [S3, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
- A set of multi-view images $I$ for a target scene.
- Camera poses and intrinsics (typically from COLMAP).
- A pre-trained monocular depth estimation (MDE) network $G_\phi$ [S1].

**Outputs:**
- Optimized NeRF model (density and color fields).
- Dense per-view depth maps aligned with the COLMAP coordinate system [S3, unofficial].

### Data Structures
The method relies on the following data structures, adapted from the reference implementation [S3, unofficial]:

1.  **Sparse Point Cloud**: Generated by COLMAP, representing the initial sparse reconstruction.
2.  **Depth Priors ($D^*$)**: A dense depth map for each view, extracted by fine-tuning the MDE network on the sparse point cloud. Shape: $[H, W]$.
3.  **Depth Confidences ($C$)**: A scalar confidence map associated with each pixel in the depth prior, used to weight the supervision or sampling influence. Shape: $[H, W]$.
4.  **Rays Tensor**: Concatenated tensor containing ray origins, directions, near/far bounds, and optionally view directions. Shape: $[N, 3 + 3 + 1 + 1 + 3]$ (depending on flags).
5.  **NeRF Model**: A multi-layer perceptron (MLP) taking 3D position and view direction as input, outputting density ($\sigma$) and RGB color ($c$).

### Steps

1.  **Sparse Reconstruction**: Run COLMAP on the test scene to acquire per-view sparse depth maps by projecting fused 3D point clouds after multi-view stereo [S2]. This provides robust but sparse geometric supervision [S2].

2.  **Depth Prior Adaptation**: Adapt the monocular depth network to the target scene.
    -   Fine-tune the pre-trained MDE network $G_\phi$ using the sparse depth maps from COLMAP as ground truth [S2].
    -   Use a scale-invariant loss to handle the scale ambiguity of the sparse reconstruction [S2]. The loss for a view $i$ is:
        $$ L(D^i_p, D^i_{Sparse}) = \frac{1}{n} \sum_{j=1}^n \left| \log D^i_p(j) - \log D^i_{Sparse}(j) + \alpha(D^i_p, D^i_{Sparse}) \right| $$
        where $D^i_p$ is the predicted dense depth, $D^i_{Sparse}$ is the sparse depth, and $\alpha$ is a correction term to align the mean and variance of the log-depths [S2].
    -   The output is the scene-specific depth prior $D^*$ and associated confidence map $C$ [S3, unofficial].

3.  **Ray Setup**:
    -   For each pixel, compute ray origin $o$ and direction $d$ using camera intrinsics and poses [S3, unofficial].
    -   If NDC (Normalized Device Coordinates) is enabled, convert rays to NDC space [S3, unofficial].
    -   Determine near and far bounds for the ray. In NerfingMVS, these bounds are clamped using the depth priors to restrict sampling to geometrically plausible regions [S1]. Specifically, the near bound is often set to 0 or a small value, and the far bound is determined by the depth prior or a fixed absolute bound (e.g., 0.15 in the reference implementation) [S3, unofficial].

4.  **Guided Volume Sampling and Rendering**:
    -   Divide the ray segment $[near, far]$ into $N$ equal bins [S1].
    -   Sample points along the ray. The sampling is guided by the depth priors, effectively allowing sampling points only at appropriate depths defined by the prior [S1].
    -   Query the NeRF for density $\sigma$ and color $c$ at each sample point.
    -   Compute alpha values $\alpha_i$ using the raw density and distance between samples $d_i$:
        $$ \alpha_i = 1 - \exp(-\sigma_i \cdot d_i) $$
    -   Compute weights $w_i$ for each sample:
        $$ w_i = \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j + \epsilon) $$
        where $\epsilon = 10^{-10}$ for numerical stability [S3, unofficial].
    -   Compute the rendered RGB color $\bar{C}$ and depth $\bar{D}$:
        $$ \bar{C} = \sum_i w_i c_i $$
        $$ \bar{D} = \sum_i w_i y_i $$
        where $y_i$ is the distance of sample $i$ from the camera [S1].
    -   Compute disparity $\bar{D}^{-1}$ and accumulated opacity $\bar{A}$ [S3, unofficial].

5.  **Optimization**:
    -   Optimize the NeRF parameters using the rendered RGB and depth against the ground truth images and potentially the depth priors (if supervised). The reference implementation suggests the primary supervision is RGB, with depth priors guiding the sampling geometry [S2].

### Pseudocode

> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
import torch
import torch.nn.functional as F

def nerfingmvs_render(rays_o, rays_d, depth_priors, depth_confidences, 
                      near_bound, far_bound, N_samples, model, white_bkgd=True):
    """
    Render rays using NerfingMVS guided sampling.
    
    Args:
        rays_o: Ray origins [N, 3]
        rays_d: Ray directions [N, 3]
        depth_priors: Depth prior values [N] (aligned with rays)
        depth_confidences: Confidence values [N]
        near_bound: Float, absolute near bound
        far_bound: Float, absolute far bound
        N_samples: Int, number of samples per ray
        model: NeRF MLP model
        white_bkgd: Bool, composite against white background
    """
    # 1. Determine ray bounds
    # In NerfingMVS, bounds are clamped using depth priors.
    # The reference uses fixed absolute bounds or priors to limit the range.
    # Here we use the provided near/far bounds, potentially influenced by priors.
    # Note: The reference implementation passes depth_priors to batchify_rays,
    # implying they are used to adjust sampling or bounds.
    
    # Create near and far tensors
    near = torch.full((rays_o.shape[0], 1), near_bound, device=rays_o.device)
    far = torch.full((rays_o.shape[0], 1), far_bound, device=rays_o.device)
    
    # 2. Sample points along the ray
    # Divide the ray into N equal bins
    t_vals = torch.linspace(0., 1., N_samples, device=rays_o.device)
    z_vals = near * (1. - t_vals) + far * t_vals
    
    # 3. Query NeRF
    # Points are positions along the ray: o + t * d
    points = rays_o.unsqueeze(1) + z_vals.unsqueeze(2) * rays_d.unsqueeze(1)
    
    # Flatten for model input
    points_flat = points.reshape(-1, 3)
    
    # Query model (simplified, assumes model takes position and view direction)
    # In practice, viewdirs are also passed.
    raw_density, raw_rgb = model(points_flat, rays_d)
    
    # Reshape back
    raw_density = raw_density.reshape(points.shape[0], N_samples, 1)
    raw_rgb = raw_rgb.reshape(points.shape[0], N_samples, 3)
    
    # 4. Compute weights
    dists = z_vals[:, 1:] - z_vals[:, :-1]
    dists = torch.cat([dists, torch.tensor([1e10], device=rays_o.device)], dim=-1)
    dists = dists * torch.norm(rays_d, dim=-1, keepdim=True)
    
    alpha = 1. - torch.exp(-F.relu(raw_density[..., 0]) * dists)
    
    # Cumulative product for transmittance
    ones = torch.ones_like(alpha[..., 0])
    alpha_cumprod = torch.cat([ones, alpha[..., 0]], dim=-1)
    transmittance = torch.cumprod(alpha_cumprod, dim=-1)[..., :-1]
    
    weights = alpha * transmittance
    
    # 5. Compute outputs
    rgb_map = torch.sum(weights.unsqueeze(-1) * raw_rgb, dim=1)
    depth_map = torch.sum(weights * z_vals, dim=1)
    acc_map = torch.sum(weights, dim=1)
    
    if white_bkgd:
        rgb_map = rgb_map + (1. - acc_map.unsqueeze(-1))
        
    return rgb_map, depth_map, acc_map

def nerfingmvs_train_step(args, rays_o, rays_d, gt_rgb, depth_priors, depth_confidences):
    """
    Single training step for NerfingMVS.
    """
    # Render
    rgb, depth, acc = nerfingmvs_render(
        rays_o, rays_d, depth_priors, depth_confidences,
        near_bound=args.near, far_bound=args.far,
        N_samples=args.depth_N_iters, model=args.model
    )
    
    # Loss computation
    # RGB Loss
    rgb_loss = F.mse_loss(rgb, gt_rgb)
    
    # Depth Loss (if supervised by priors or GT)
    # The reference emphasizes using priors for sampling guidance, 
    # but may also use them for loss.
    # Scale-invariant loss if comparing to sparse GT, 
    # or L1/L2 if comparing to dense priors.
    # Here we assume a simple L1 loss against depth priors for demonstration.
    depth_loss = F.l1_loss(depth, depth_priors)
    
    total_loss = rgb_loss + args.depth_lrate * depth_loss
    
    # Backprop
    args.optimizer.zero_grad()
    total_loss.backward()
    args.optimizer.step()
    
    return total_loss.item()
```

### Parameters
-   `depth_N_rand`: Batch size for depth sampling (default 4) [S3, unofficial].
-   `depth_N_iters`: Number of iterations for depth prior training (default 151) [S3, unofficial].
-   `depth_H`, `depth_W`: Height and width of depth image (must be 16x) (default 288, 384) [S3, unofficial].
-   `depth_lrate`: Learning rate for depth network fine-tuning (default 4e-4) [S3, unofficial].
-   `near`: Absolute near bound (default 0.05) [S3, unofficial].
-   `far`: Absolute far bound (default 0.15) [S3, unofficial].
-   `topk`: Top-k for consistency error filtering (default 4) [S3, unofficial].

### Edge Cases and Pitfalls
-   **Numerical Stability**: Add $\epsilon = 10^{-10}$ to $(1-\alpha)$ in the cumulative product for weights to prevent NaNs when $\alpha$ is close to 1 [S3, unofficial].
-   **Division by Zero**: Use $\max(10^{-10}, \dots)$ when computing disparity maps to avoid division by zero [S3, unofficial].
-   **Scale Ambiguity**: The sparse depth maps from COLMAP lack absolute scale. The scale-invariant loss is crucial for adapting the monocular network [S2].
-   **COLMAP Dependency**: Results depend heavily on the quality of COLMAP's sparse reconstruction and poses [S3, unofficial].

## Operating characteristics
-   **Time Complexity**: The method involves an initial COLMAP run, followed by fine-tuning a monocular depth network, and then NeRF optimization. The reference implementation reports approximately 3.5 hours on a single NVIDIA GeForce RTX 2080 GPU for the entire procedure (COLMAP, depth training, NeRF training, filtering, and evaluation) [S3, unofficial].
-   **Memory Complexity**: Depends on the NeRF model size and the number of samples per ray. Chunked rendering is used to avoid OOM errors [S3, unofficial].
-   **Strengths**: Successfully integrates learning-based priors into NeRF, significantly improving geometry in indoor scenes where shape-radiance ambiguity is high [S2]. Eliminates the need for explicit pixel matching across views [S2].
-   **Limitations**: Relies on the quality of COLMAP's sparse reconstruction. May struggle if COLMAP fails to produce a robust initial reconstruction [S3, unofficial].

## Background
NerfingMVS was introduced by Wei et al. in September 2021 at ICCV [S2]. It was designed to address the limitations of standard NeRF in indoor multi-view stereo tasks, where the shape-radiance ambiguity leads to poor geometry reconstruction [S2]. By leveraging conventional SfM+MVS and learning-based monocular depth priors, it provides a robust solution for indoor scene reconstruction [S2]. The code is based on the PyTorch implementation of NeRF [S3, unofficial].
