# NeRF with Unknown Camera Parameters

Also called: Joint optimisation of NeRF and camera parameters, NeRF with unknown cameras, NeRF-- (NeRF without known camera parameters)

## Overview
NeRF with Unknown Camera Parameters (NeRF--) is a method that jointly optimizes the camera parameters (poses and intrinsics) alongside the Neural Radiance Field (NeRF) weights on a sparse set of forward-facing views, eliminating the need for pre-estimated camera poses [S1, unofficial]. It differs from baseline NeRF, which requires ground-truth camera poses as input, by treating camera parameters as trainable variables within the same differentiable pipeline [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ input images $\{I_i\}_{i=1}^N$ with unknown camera parameters.
*   **Outputs:** Optimized NeRF weights $\Theta$ and camera parameters $\{\pi_i\}_{i=1}^N$, where $\pi_i = (\hat{f}, \hat{\phi}_i, \hat{t}_i)$ represents the focal length, rotation, and translation for image $i$.

**Data Structures:**
*   **NeRF Model ($F_\Theta$):** A multi-layer perceptron (MLP) mapping 3D position and viewing direction to color and density. The hidden layer dimension is reduced to 128 for computation efficiency [S1, unofficial].
*   **Camera Parameters ($\pi_i$):**
    *   $\hat{f}$: Scalar focal length.
    *   $\hat{\phi}_i \in \mathbb{R}^3$: Axis-angle rotation vector.
    *   $\hat{t}_i \in \mathbb{R}^3$: Translation vector.
*   **Ray Sampling:** For each training step, $M=1024$ pixels are randomly sampled from each input image [S1, unofficial]. Along each ray, $K=128$ 3D points $\{x_j\}$ are sampled [S1, unofficial].

**Numbered Steps:**
1.  **Initialization:** Initialize NeRF weights $\Theta$ using Kaiming initialization [S1, unofficial]. Initialize all camera parameters: set all cameras at the origin ($\hat{t}_i = \mathbf{0}$), looking in the $-z$ direction (rotation identity or axis-angle zero), and set initial focal length $\hat{f}$ equal to the image width [S1, unofficial].
2.  **Ray Generation:** For a pixel $p=(u,v)$ in image $i$, compute the ray origin $\hat{o}_i$ and direction $\hat{d}_{i,p}$ using current estimates $\hat{\pi}_i = (\hat{f}, \hat{\phi}_i, \hat{t}_i)$:
    $$ \hat{o}_i = \hat{t}_i $$
    $$ \hat{d}_{i,p} = \hat{R}_i \begin{pmatrix} (u - W/2)/\hat{f} \\ -(v - H/2)/\hat{f} \\ -1 \end{pmatrix} $$
    where $W$ and $H$ are image width and height, and $\hat{R}_i$ is the rotation matrix derived from $\hat{\phi}_i$ using Rodrigues' formula [S1, unofficial].
3.  **Sampling and Evaluation:** Sample $K$ points $\{x_j\}$ along the ray. Evaluate radiance colors $\{c_j\}$ and density values $\{\sigma_j\}$ from the NeRF model $F_\Theta$ at these points [S1, unofficial].
4.  **Rendering:** Compute the predicted pixel color $\hat{I}$ by aggregating radiance and densities along the ray using the standard volume rendering integral [S1, unofficial].
5.  **Loss Computation:** Compute the photometric reconstruction loss $\mathcal{L}$ between the rendered colors $\hat{I}$ and ground-truth colors $I$ for the sampled pixels [S1, unofficial].
6.  **Backpropagation:** Compute gradients $\nabla_\Theta \mathcal{L}$ and $\nabla_{\pi_i} \mathcal{L}$ via backpropagation through the differentiable rendering and ray generation operations [S1, unofficial].
7.  **Update:** Update $\Theta$ and $\{\pi_i\}$ using Adam optimizers [S1, unofficial].

def generate_ray(origin, direction, near, far, num_samples):
    """Sample points along a ray.
    origin: (3,) tensor
    direction: (3,) tensor
    near, far: scalars
    num_samples: int
    Returns: (num_samples, 3) tensor of 3D points
    """
    # [G] Linear spacing between near and far is typical.
    t_vals = torch.linspace(near, far, num_samples)
    points = origin.unsqueeze(0) + t_vals.unsqueeze(1) * direction.unsqueeze(0)
    return points

def volume_render(points, sigma, color, near, far):
    """Compute color via volume rendering.
    points: (num_samples, 3)
    sigma: (num_samples,) density
    color: (num_samples, 3) radiance
    Returns: (3,) rendered color
    """
    # [G] Standard alpha compositing formula.
    dists = torch.cat([torch.norm(points[1:] - points[:-1], dim=-1), torch.tensor([far - near]).to(points)])
    alpha = 1.0 - torch.exp(-sigma * dists)
    transmittance = torch.cumprod(torch.cat([torch.ones(1).to(points), 1.0 - alpha + 1e-10]), dim=0)[:-1]
    weights = alpha * transmittance
    color_out = torch.sum(weights.unsqueeze(-1) * color, dim=0)
    return color_out

def train_step(images, gt_colors, nerf_model, camera_params, optimizer_nerf, optimizer_cam, W, H):
    """Single training step."""
    optimizer_nerf.zero_grad()
    optimizer_cam.zero_grad()
    
    # Randomly sample M pixels per image
    M = 1024
    N = len(images)
    total_loss = 0.0
    
    for i in range(N):
        # Sample pixel coordinates
        u = torch.randint(0, W, (M,))
        v = torch.randint(0, H, (M,))
        
        # Get current camera parameters
        f = camera_params['f'][i]
        phi = camera_params['phi'][i]
        t = camera_params['t'][i]
        
        # Compute rotation matrix
        R = rodrigues(phi)
        
        # Generate rays for sampled pixels
        # [G] Ray direction calculation as per formula
        # d = R * [ (u - W/2)/f, -(v - H/2)/f, -1 ]^T
        # o = t
        
        # Sample points along rays
        # [G] Near/far bounds are typically fixed or adaptive. 
        # Assuming fixed near=2, far=6 as per common NeRF practice if not specified.
        near, far = 2.0, 6.0
        num_samples = 128
        
        # Compute ray origins and directions for all M pixels
        # [G] Vectorized implementation preferred.
        origins = t.unsqueeze(0).expand(M, -1)
        dirs = torch.zeros(M, 3)
        for j in range(M):
            u_j, v_j = u[j].item(), v[j].item()
            ray_dir_local = torch.tensor([(u_j - W/2)/f, -(v_j - H/2)/f, -1.0])
            dirs[j] = torch.matmul(R, ray_dir_local)
            
        # Sample points
        points = generate_ray(origins, dirs, near, far, num_samples) # (M, num_samples, 3)
        
        # Evaluate NeRF
        # [G] Flatten points for MLP evaluation
        flat_points = points.view(-1, 3)
        # [G] Directions need to be computed for each point based on view direction
        # [G] Simplified: assume directions are constant along ray for this step
        flat_dirs = dirs.unsqueeze(1).expand(-1, num_samples, -1).view(-1, 3)
        
        sigma, color = nerf_model(flat_points, flat_dirs)
        sigma = sigma.view(M, num_samples)
        color = color.view(M, num_samples, 3)
        
        # Render
        rendered_colors = torch.zeros(M, 3)
        for j in range(M):
            rendered_colors[j] = volume_render(points[j], sigma[j], color[j], near, far)
            
        # Loss
        gt = gt_colors[i] # (H, W, 3)
        loss = torch.mean((rendered_colors - gt[u, v]) ** 2)
        total_loss += loss
        
    total_loss.backward()
    optimizer_nerf.step()
    optimizer_cam.step()
    
    return total_loss.item()

**Parameters:**
*   **Hidden layer dimension:** 128 [S1, unofficial].
*   **Pixels sampled per image ($M$):** 1024 [S1, unofficial].
*   **Points sampled along each ray:** 128 [S1, unofficial].
*   **Initial Focal Length:** Image width [S1, unofficial].
*   **Initial Pose:** Origin, looking at $-z$ direction [S1, unofficial].
*   **Optimizers:** Three separate Adam optimizers for NeRF weights, camera poses ($\phi, t$), and focal lengths ($f$) [S1, unofficial].
*   **Initial Learning Rate:** 0.001 for all optimizers [S1, unofficial].
*   **Learning Rate Decay:**
    *   NeRF: Multiplied by 0.9954 every 10 epochs [S1, unofficial].
    *   Poses and Focal Length: Multiplied by 0.9 every 100 epochs [S1, unofficial].
*   **Training Duration:** 10,000 epochs [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Local Minima:** Joint optimization may trap into local minima for certain scenes (e.g., Orchids, Room), resulting in inaccurate intrinsics and worse Novel View Synthesis (NVS) quality compared to baseline [S1, unofficial].
*   **Intrinsic Accuracy:** The difference between optimized focal lengths and ground truth (e.g., COLMAP) can be noticeable in difficult scenes [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Training is computationally intensive due to the joint optimization of camera parameters. The use of hierarchical sampling is omitted for efficiency, and hidden layers are reduced [S1, unofficial].
*   **Memory Complexity:** Reduced by using 128 hidden dimensions instead of 256 and sampling 1024 pixels per image [S1, unofficial].
*   **Performance:** Achieves comparable NVS quality to baseline NeRF (using COLMAP poses) with $\Delta$SSIM and $\Delta$LPIPS $\approx 0.05$ [S1, unofficial].
*   **Strengths:** Eliminates the need for pre-estimated camera poses (e.g., from COLMAP) [S1, unofficial].
*   **Limitations:** Susceptible to local minima, particularly for scenes with ambiguous geometry or insufficient view coverage [S1, unofficial].

## Background
NeRF-- was introduced by Mildenhall et al. in 2021 [S1, unofficial]. It addresses the limitation of the original NeRF method, which requires accurate camera poses and intrinsics as input. The method was evaluated on the Blender Forward Facing (BLEFF) dataset, a synthetic dataset containing 14 path-traced scenes with rotation and translation perturbations [S1, unofficial].
