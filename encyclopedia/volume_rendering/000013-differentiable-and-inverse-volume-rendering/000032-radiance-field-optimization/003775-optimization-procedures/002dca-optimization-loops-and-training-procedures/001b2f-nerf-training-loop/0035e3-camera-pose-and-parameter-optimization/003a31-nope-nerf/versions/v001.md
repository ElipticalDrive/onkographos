# NoPe-NeRF

Also called: No Pose NeRF

## Overview
NoPe-NeRF is a method for training Neural Radiance Fields (NeRF) without precomputed camera poses, addressing the challenge of optimizing relative poses between consecutive frames using undistorted monocular depth priors [S1, S2]. It distinguishes itself from sibling methods like BARF and iNeRF by explicitly generating a dense point cloud from a monocular depth estimation network and unprojecting undistorted depth maps to constrain pose optimization via point cloud and photometric losses [S1, S2].

## How it works
**Inputs:**
- A sequence of uncalibrated images with unknown camera poses.
- A pre-trained monocular depth estimation network.

**Outputs:**
- Optimized NeRF model parameters (implicit scene representation).
- Optimized camera poses for the input images.

**Data Structures:**
- **Camera Pose:** A $4 \times 4$ transformation matrix $T$ representing the world-to-camera transformation.
- **Monocular Depth Map:** A 2D array $D_{mono}$ of size $H \times W$ containing per-pixel depth estimates.
- **Dense Point Cloud:** A set of 3D points $P = \{p_i\}$ generated by unprojecting the depth map.
- **NeRF Model:** A multi-layer perceptron (MLP) mapping 3D coordinates and viewing directions to color and density.

**Steps:**
1. **Monocular Depth Estimation:** Pass each input image $I$ through the monocular depth estimation network to obtain a raw depth map $D_{raw}$ [S2].
2. **Depth Correction:** Correct the scale and shift of the raw depth map to align with the scene geometry during training. This generates an undistorted depth prior $D_{prior}$ [S1, S2].
3. **Point Cloud Generation:** Unproject the undistorted depth map $D_{prior}$ using the current estimated camera pose to generate a dense 3D point cloud $P$ [S2].
4. **Loss Calculation:** Compute two primary loss terms:
   - **Photometric Loss ($L_{photo}$):** The difference between the rendered image from the NeRF and the input image [S2].
   - **Point Cloud Loss ($L_{pc}$):** A constraint ensuring the NeRF geometry is consistent with the generated point cloud, specifically constraining the relative poses between consecutive frames [S1, S2].
5. **Joint Optimization:** Minimize the total loss $L_{total} = L_{photo} + \lambda L_{pc}$ by updating both the NeRF parameters and the camera poses via gradient descent [S2].

**Formulas:**
- **Total Loss:**
  $$ L_{total} = L_{photo} + \lambda L_{pc} $$
  where $\lambda$ is a weighting factor for the point cloud loss [S2].
- **Photometric Loss:**
  $$ L_{photo} = \| I_{rendered} - I_{input} \| $$
  where $I_{rendered}$ is the image rendered by the NeRF and $I_{input}$ is the ground truth image [S2].
- **Point Cloud Loss:**
  The specific mathematical formulation of $L_{pc}$ is not provided in the sources, but it is described as a function that constrains the relative poses between consecutive frames by comparing the NeRF geometry to the point cloud [S1, S2].

**Parameters:**
- **$\lambda$:** Weight for the point cloud loss. Not given in the sources.
- **Learning Rate:** Not given in the sources.

**Edge Cases and Pitfalls:**
- **Scale Ambiguity:** Monocular depth estimation suffers from scale ambiguity. The method addresses this by correcting scale and shift parameters during training [S1].
- **Depth Errors:** Errors in the monocular depth estimation network can propagate to the point cloud and affect pose estimation. The undistortion and correction steps aim to mitigate this [S2].

**Pseudocode:**
```python
def train_nope_nerf(images, monocular_depth_net, num_iterations):
    # Initialize NeRF model and camera poses
    nerf_model = initialize_nerf()
    camera_poses = initialize_poses(images)
    
    for iteration in range(num_iterations):
        for image in images:
            # Step 1: Get monocular depth
            raw_depth = monocular_depth_net(image)
            
            # Step 2: Correct scale and shift
            # This step is integrated into the training loop to refine depth prior
            prior_depth = correct_depth_scale_shift(raw_depth, camera_poses)
            
            # Step 3: Generate point cloud from undistorted depth
            point_cloud = unproject_depth(prior_depth, camera_poses)
            
            # Step 4: Render image from NeRF
            rendered_image = render_nerf(nerf_model, camera_poses)
            
            # Step 5: Compute losses
            photometric_loss = compute_photometric_loss(rendered_image, image)
            point_cloud_loss = compute_point_cloud_loss(nerf_model, point_cloud, camera_poses)
            
            total_loss = photometric_loss + lambda_weight * point_cloud_loss
            
            # Step 6: Update parameters
            update_nerf_and_poses(nerf_model, camera_poses, total_loss)
            
    return nerf_model, camera_poses
```

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Measured Performance:** Outperforms existing methods in novel view rendering quality and pose estimation accuracy on the Temples and ScanNet datasets [S1]. On the LLFF dataset, PSNR indicators for 3, 6, and 9 input views are 1-2 points higher, and nearly 1 point higher than ViP-NeRF for 3 input views [S1].
- **Scaling:** Not given in the sources.
- **Strengths:** Handles challenging camera trajectories and does not require precomputed poses [S1, S2].
- **Limitations:** Relies on the accuracy of the monocular depth estimation network [S2].
- **When to use:** When camera poses are unknown or unreliable, and monocular depth estimation is available.
- **When not to use:** When high-quality precomputed poses are available, as this adds computational overhead.

## Background
NoPe-NeRF was proposed by Bian et al. in 2023 [S2]. It addresses the limitations of previous methods like BARF and iNeRF, which struggle with challenging camera trajectories or are limited to scenes where objects are in front of the camera [S2]. The method builds on the idea of using monocular depth priors to guide NeRF optimization [S1].
