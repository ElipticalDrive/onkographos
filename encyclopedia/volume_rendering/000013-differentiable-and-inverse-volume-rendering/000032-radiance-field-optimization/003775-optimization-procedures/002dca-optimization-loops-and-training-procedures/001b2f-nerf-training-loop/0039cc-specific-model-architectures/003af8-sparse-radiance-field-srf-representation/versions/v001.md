# Sparse Radiance Field (SRF) Representation


## Overview
A Sparse Radiance Field (SRF) is a voxel-based representation that encodes volumetric density and view-dependent radiance into a sparse 3D grid, serving as a discrete, efficient alternative to the continuous Multi-Layer Perceptron (MLP) used in standard NeRF [S1]. It differs from dense voxel methods by storing only non-empty voxels in a Coordinate (COO) format, significantly reducing memory usage while maintaining the ability to extract explicit 3D meshes via Marching Cubes [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A set of posed images (and optionally depth or normal maps) used to optimize the voxel features.
*   **Output:** A sparse set of tuples $X_{non-empty}$ containing 3D coordinates and associated feature vectors for density and radiance.

**Data Structures**
The SRF is defined as a voxel grid of dimension $1+d$, where $d$ is the dimension of the radiance color features and 1 dimension is for density [S1].
*   **Grid Size:** $H \times H \times H$, where $H$ is the resolution in each dimension [S1].
*   **Feature Vector:** Each voxel stores a feature vector $f \in \mathbb{R}^{d+1}$. The first component is the density $\alpha_{i,j,k} \in \mathbb{R}$, and the remaining $d$ components are the radiance colors $\rho_{i,j,k} \in \mathbb{R}^d$ [S1].
*   **Storage Format:** Coordinate (COO) format [S1]. The SRF is represented as a set of $M$ tuples:
    $$ X_{non-empty} = \{(c_m, f_m)\}_{m=1}^M $$
    where $c_m = (i, j, k)$ are positive integer coordinates ($c \in \mathbb{Z}^+$) and $f_m$ is the feature vector at that location [S1]. The ordering of tuples is arbitrary [S1].

**Parameters**
*   **Resolution ($H$):** The grid size in each dimension. Typical values used in the SPARF dataset are $H \in \{32, 128, 512\}$ [S1].
*   **Radiance Dimension ($d$):**
    *   For view-dependent SRF using 4 spherical harmonics (SH) factors per RGB channel: $d = 3 \times 4 = 12$ [S1].
    *   For fixed RGB colors: $d = 3 \times 1 = 3$ [S1].
    *   Note: Using 4 SH factors reduces optimization space by 40% and time by 10% compared to 9 SH factors, while maintaining similar PSNR [S1]. Using fixed RGB reduces PSNR by ~1 dB but saves 80% space and 20% time [S1].

**Algorithm: Volume Rendering from SRF**
To render an image, rays are cast through the sparse grid. For each ray, the algorithm iterates through the occupied voxels intersected by the ray.

1.  **Ray-Voxel Intersection:** Determine the sequence of occupied voxels $(i, j, k)$ intersected by the ray.
2.  **Feature Retrieval:** For each occupied voxel $m$, retrieve $c_m$ and $f_m = [\alpha_m, \rho_m]$.
3.  **View-Dependent Color:** If $d > 3$, compute the view-dependent color $\mathbf{c}_m$ from $\rho_m$ and the viewing direction $\mathbf{d}$ using spherical harmonics evaluation [S1]. If $d=3$, $\mathbf{c}_m$ is directly $\rho_m$.
4.  **Integration:** Apply the volume rendering equation using the retrieved density $\alpha_m$ (often interpreted as $\sigma \cdot \delta$ or directly as opacity $\alpha$ depending on implementation; standard NeRF integration assumes $\sigma$ and step size $\delta$) [S1].
    $$ C(r) = \sum_{m \in \text{ray}} T_m \alpha_m \mathbf{c}_m, \quad T_m = \exp\left(-\sum_{k < m} \alpha_k\right) $$
    *Note: The source defines $f_m$ as containing density $\alpha_{i,j,k}$. In standard volume rendering, $\alpha$ usually denotes opacity $1-\exp(-\sigma \delta)$. The source implies $\alpha$ is the value stored. If $\alpha$ is density $\sigma$, it must be converted to opacity using the step size $\delta$ between voxel centers. The source does not explicitly define the conversion, but standard practice applies [G].*

**Edge Cases and Pitfalls**
*   **Low-Density Voxels:** Non-empty voxels may have low densities that do not contribute significantly to rendering but contain random color information that can confuse the network during training [S1].
*   **Vanishing Gradients:** High sparsity (~99%) and misalignment between input and output SRF coordinates (caused by sparse convolutional strides and pruning) can lead to vanishing gradients [S1].
*   **Precision:** Small errors in predicting densities or radiance colors can result in large distortions in rendered images [S1].

## Operating characteristics
*   **Memory Complexity:** $O(M)$, where $M$ is the number of non-empty voxels. This is significantly lower than dense $O(H^3)$ grids for sparse scenes [S1].
*   **Time Complexity:** Rendering time depends on the number of occupied voxels along each ray. Training time is reduced by using fewer spherical harmonics components and fewer optimization iterations compared to dense Plenoxels [S1].
*   **Strengths:** Enables direct mesh extraction via Marching Cubes; efficient storage for large-scale datasets (e.g., 1 million SRFs); supports multi-resolution representations [S1].
*   **Limitations:** Sensitive to sparsity-induced gradient issues; requires careful handling of low-density voxels to avoid noise [S1].
*   **When to Use:** Suitable for large-scale 3D object datasets where explicit mesh extraction is desired and memory efficiency is critical [S1].

## Background
The Sparse Radiance Field (SRF) representation was introduced in the context of the SPARF (Sparse Radiance Fields) dataset and SuRFNet architecture [S1]. It builds on the Plenoxels method, which uses spherical harmonics for view-dependent radiance [S1]. The SPARF dataset contains one million SRFs across multiple resolutions (32, 128, 512) extracted from 40,000 shapes from 13 classes, aiming to scale up NeRF-like optimization for large-scale learning [S1].
