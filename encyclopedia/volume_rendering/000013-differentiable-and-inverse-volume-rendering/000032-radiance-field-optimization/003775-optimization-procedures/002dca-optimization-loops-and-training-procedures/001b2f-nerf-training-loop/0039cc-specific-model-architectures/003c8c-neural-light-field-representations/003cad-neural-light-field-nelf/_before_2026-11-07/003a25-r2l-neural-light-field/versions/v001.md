# R2L (Neural Light Field)

Also called: Neural Light Field, R2L network

## Overview
R2L (Radiance-to-Light-field) is a deep neural light field network trained via knowledge distillation from a pre-trained NeRF teacher model to achieve efficient novel view synthesis with significantly reduced computational cost [S1]. It differs from standard NeRF by employing an unprecedentedly deep architecture with extensive internal residual blocks, trading width for depth under the same FLOPs budget to capture fine-grained details [S1]. Unlike depth-dependent efficient methods like DONeRF, R2L does not rely on ground-truth depth, allowing it to handle reflective surfaces (e.g., water, mirrors) more effectively [S1].

## How it works

### Inputs and Outputs
*   **Inputs:**
    *   Pre-trained NeRF teacher model parameters.
    *   Original captured images (training set).
    *   Hyperparameters: Network width $W$, depth $D$, batch size $B$, hard example ratio $r$, pseudo sample size $S$, learning rate schedule.
*   **Outputs:**
    *   R2L network weights.
    *   Rendered images for novel viewpoints.

### Data Structures
The R2L network is a Multi-Layer Perceptron (MLP) with a specific architecture:
*   **Architecture:** $W256D88$ (width 256, depth 88) or $W181D88$ (width 181, depth 88) [S1].
*   **Layers:** The network consists of $D$ linear layers with ReLU activations.
*   **Residual Blocks:** Extensive residual connections are added between internal layers. The input to a residual block is added to its output before passing to the next layer [S1].
*   **Input Encoding:** Unlike NeRF, R2L is a Neural Light Field (NeLF). It takes 5D coordinates $(x, y, \theta, \phi)$ directly as input, where $(x, y)$ is the pixel coordinate and $(\theta, \phi)$ is the viewing direction [S1]. No positional encoding is applied to the input coordinates in the standard R2L formulation described in the source [S1].
*   **Output:** The network outputs the color $C$ and opacity $\sigma$ (or transmittance) for the ray [S1].

import torch
import torch.nn as nn
import torch.optim as optim

class R2LNetwork(nn.Module):
    """
    R2L Neural Light Field Network.
    Architecture: W256D88 or W181D88 with extensive residual blocks.
    """
    def __init__(self, width=256, depth=88):
        super(R2LNetwork, self).__init__()
        self.width = width
        self.depth = depth
        
        # Input: 5D (x, y, theta, phi)
        # Output: 4D (R, G, B, sigma)
        
        # First layer
        self.input_layer = nn.Linear(5, width)
        
        # Hidden layers with residual blocks
        self.hidden_layers = nn.ModuleList()
        for i in range(depth - 1):
            layer = nn.Linear(width, width)
            self.hidden_layers.append(layer)
            
        # Output layer
        self.output_layer = nn.Linear(width, 4)
        
        # Initialize weights (standard initialization not specified, assume standard PyTorch default or Xavier)
        self._init_weights()

    def _init_weights(self):
        for m in self.modules():
            if isinstance(m, nn.Linear):
                nn.init.kaiming_normal_(m.weight, nonlinearity='relu')
                if m.bias is not None:
                    nn.init.constant_(m.bias, 0)

    def forward(self, rays):
        """
        rays: Tensor of shape (N, 5), where N is the number of rays.
              Columns: [x, y, theta, phi]
        Returns: Tensor of shape (N, 4), where columns are [R, G, B, sigma]
        """
        x = self.input_layer(rays)
        x = torch.relu(x)
        
        # Apply residual blocks
        for i in range(self.depth - 1):
            residual = x
            x = self.hidden_layers[i](x)
            x = torch.relu(x)
            # Add residual connection
            x = x + residual
            
        out = self.output_layer(x)
        return out

    # Combine real and pseudo data if using Ours-2 configuration

    for iteration in range(hyperparams['iterations']):

        # Sample from real images

        # Sample from pseudo images
        pseudo_rays_batch, pseudo_colors_batch = sample_pseudo_rays(pseudo_rays, pseudo_colors, batch_size // 2)
        
        # Concatenate
        batch_rays = torch.cat([real_rays, pseudo_rays_batch], dim=0)
        batch_targets = torch.cat([real_colors, pseudo_colors_batch], dim=0)
        
        # 2. Hard Example Training
        # Forward pass to get predictions
        predictions = model(batch_rays)
        
        # Calculate initial loss (e.g., MSE)
        loss = torch.mean((predictions - batch_targets) ** 2)
        
        # Select hard examples based on PSNR (or error)
        # r = 0.2 is default [S1]
        hard_ratio = hyperparams['hard_example_ratio']
        num_hard = int(batch_size * hard_ratio)
        
        if num_hard > 0:
            # Calculate per-ray error
            ray_errors = torch.mean((predictions - batch_targets) ** 2, dim=1)
            
            # Select indices with smallest PSNR (largest error)
            # Note: PSNR is inversely related to MSE. Smallest PSNR = Largest MSE.
            _, hard_indices = torch.topk(ray_errors, k=num_hard, largest=True)
            
            # Re-sample batch to focus on hard examples? 
            # The source says "selecting a fraction r of rays with small PSNR in each batch to focus optimization" [S1].
            # This implies the loss is computed only on these hard examples or the batch is replaced.
            # Standard interpretation: Compute loss only on hard examples.
            hard_rays = batch_rays[hard_indices]
            hard_targets = batch_targets[hard_indices]
            
            # Recompute loss on hard examples
            hard_predictions = model(hard_rays)
            loss = torch.mean((hard_predictions - hard_targets) ** 2)
            
        # 3. Backpropagation
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        scheduler.step()
        
    return model

### Parameters
*   **Network Width ($W$):** 256 or 181 [S1].
*   **Network Depth ($D$):** 88 [S1].
*   **Batch Size:** 98,304 rays per batch [S1].
*   **Hard Example Ratio ($r$):** Fraction of hard examples per batch. Default 0.2. Tested values $\{0, 0.1, 0.2, 0.3\}$ [S1].
*   **Pseudo Sample Size ($S$):** Number of pseudo images used for training. Default 10k. Performance saturates around 5k images [S1].
*   **Iterations:** 1,000k iterations [S1].
*   **Optimizer:** Adam [S1].
*   **Learning Rate:** Initial $5 \times 10^{-4}$, decayed during training, same schedule as teacher NeRF [S1].
*   **Hardware:** 8 NVIDIA V100 GPUs [S1].
*   **Framework:** PyTorch 1.9 [S1].

### Edge Cases and Pitfalls
*   **Overfitting with Small Data:** Using only original captured images (e.g., 0.1k images) causes severe overfitting (test PSNR ~19.81 on Lego scene) [S1]. Regularization techniques like dropout and Batch Normalization do not resolve this [S1]. Abundant pseudo data is critical [S1].
*   **Trainability of Deep Networks:** Without residual blocks, the deep R2L network is barely trainable [S1].
*   **Batch Origin Constraint:** Rays in a batch must be randomly sampled from different images so they do not share the same origin. This is critical for superior performance [S1].
*   **Reflection Surfaces:** Methods relying on ground-truth depth (like DONeRF) fail on reflective surfaces (water, mirrors) because ground-truth depth does not apply to reflections. R2L handles these well as it does not use depth [S1].

## Operating characteristics

### Time and Memory Complexity
*   **FLOPs:** R2L (W181D88) requires ~6.00 M FLOPs, compared to NeRF's 211.42 M FLOPs [S1]. This is a ~35.24× reduction in FLOPs [S1].
*   **Storage:** R2L storage is 23.7 MB, compared to NeRF's 2.4 MB [S1]. Note: KiloNeRF has 38.9 MB, RSEN has 5.4 MB [S1].

### Measured Performance
*   **NeRF Synthetic Dataset:**
    *   Ours-2 (Pseudo+Real): 31.87 PSNR (+1.40 over teacher), 0.9950 SSIM, 0.0340 LPIPS [S1].
    *   Ours-1 (Pseudo only): 30.48 PSNR (+0.01 over teacher), 0.9939 SSIM, 0.0391 LPIPS [S1].
*   **DONeRF Synthetic Dataset:**
    *   Ours-2: 35.45 PSNR (+2.78 over teacher), 0.047 FLIP [S1].
*   **Real-world Dataset (Real ForwardFacing):**
    *   Ours-2: 27.79 PSNR (+0.11 over teacher), 0.9729 SSIM, 0.03 LPIPS [S1].

### Scaling and Speed
*   **Wall-time Speedup:** 28–31× faster than NeRF and 2× faster than DONeRF-16-noGT on GeForce 2080Ti, Tesla V100, and CPU benchmarks [S1].
*   **Scaling:** Performance saturates with pseudo sample size around 5k images [S1]. Hard example ratio $r$ between 0.1 and 0.3 shows no significant difference, but $r=0$ is significantly worse [S1].

### Strengths and Limitations
*   **Strengths:**
    *   Significantly faster rendering than NeRF and other efficient methods [S1].
    *   Better handling of reflective surfaces compared to depth-based methods [S1].
    *   Can outperform teacher NeRF in PSNR when trained with real data [S1].
*   **Limitations:**
    *   Blurry parts in NeRF results may also appear in R2L results, as it learns from NeRF-generated data [S1].
    *   Requires significant pseudo data generation step [S1].
    *   Deep network architecture requires careful training (residuals, hard examples) [S1].

## Background

### Origin
R2L was introduced by H. Wang et al. in the paper "R2L: Distilling Neural Radiance Field to Neural Light Field for Efficient Novel View Synthesis" [S1]. The work was published in 2022 (based on the DOI prefix and context of NeRF literature).

### History and Development
The method builds on the success of NeRF [S1] and the need for efficient novel view synthesis. It addresses the high computational cost of NeRF by distilling its knowledge into a deeper, more efficient Neural Light Field network. The key innovation is the use of extensive residual blocks and hard-example training to make such a deep network trainable and effective [S1].

### Usage
R2L is used for efficient novel view synthesis in computer graphics and vision applications, particularly where real-time or near-real-time rendering is required, and where reflective surfaces are present [S1].
