# On-the-Fly Dynamic NeRF Training

Also called: OD-NeRF

## Overview
On-the-fly dynamic NeRF training is a method for reconstructing dynamic scenes by training the radiance field concurrently with the acquisition of training frames, enabling real-time streaming of the event as it unfolds [S1]. Unlike standard dynamic NeRFs that require full video sequences for offline 4D reconstruction, this approach minimizes optimization iterations per frame to achieve interactive speeds [S1]. It distinguishes itself from siblings like [Neural Transient Field (NeTF)](4692-neural-transient-field-netf.md) and [D-NeRF](8660-d-nerf.md) by treating the radiance field as a hidden state in a Hidden Markov Model, relying on a first-order Markov assumption to avoid storing full history [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A sequence of multi-view forward-facing camera images $C_{0:K}$ arriving sequentially over time steps $t_0, \dots, t_K$. The model maintains the radiance field estimate $F_{k-1}$ from the previous time step.
*   **Outputs:** The updated radiance field function $F_k$ at the current time step $t_k$, capable of rendering novel views for $t_k$ [S1].

**Data Structures:**
The radiance field $F_k$ is typically represented by a neural network (MLP) mapping spatial coordinates $\mathbf{x} \in \mathbb{R}^3$, viewing directions $\mathbf{d} \in \mathbb{R}^3$, and optionally time $t$ to volume density $\sigma \in \mathbb{R}$ and RGB color $\mathbf{c} \in \mathbb{R}^3$ [S1]. The method may also utilize an occupancy grid $G$ for efficient sampling, which is updated via a transition function [S1].

**Algorithm Steps:**
1.  **Initialization:** Initialize the radiance field $F_0$ using the first set of images $C_0$.
2.  **Iterative Training:** For each new time step $k = 1, \dots, K$:
    a. **Markov Assumption:** Assume conditional independence of the current radiance field $F_k$ given the previous field $F_{k-1}$ and current observations $C_k$. This simplifies the posterior estimation to:
       $$ F_k = \arg\max_{F_k} P(F_k | C_k, F_{k-1}) $$
       [S1]
    b. **Loss Minimization:** Optimize $F_k$ by minimizing the rendering loss between the predicted pixel colors $\hat{C}_k(r)$ and the observed images $C_k(r)$ for all rays $r$ in the current view:
       $$ F_k = \arg\min_{F_k} \sum_{r \in R} ||\hat{C}_k(r) - C_k(r)||^2_2 $$
       [S1]
    c. **Volume Rendering:** Compute $\hat{C}_k(r)$ by aggregating colors of $N$ points along ray $r$ with interval $\delta$:
       $$ \hat{C}(r) = \sum_{i=0}^{N-1} T_i (1 - \exp(-\sigma_i \delta_i)) c_i $$
       where the transmittance $T_i$ is:
       $$ T_i = \exp\left(-\sum_{j=0}^{i-1} \sigma_j \delta_j\right) $$
       [S1]
    d. **Transition Update:** Update the internal state (e.g., occupancy grid $G$) from $G_{k-1}$ to $G_k$ using a transition function to maintain sampling efficiency [S1].

**Pseudocode:**
```python
def on_the_fly_training(images_sequence, initial_field):
    """
    images_sequence: List of image sets C_k, where each C_k contains 
                     multi-view images for time step t_k.
    initial_field:   Radiance field F_0.
    """
    F_prev = initial_field
    
    for k, current_images in enumerate(images_sequence):
        if k == 0:
            # Initialize F_0 using C_0
            F_prev = train_field(current_images, F_prev)
            continue
            
        # Step 1: Apply Markov assumption
        # We only condition on C_k and F_{k-1}
        
        # Step 2: Minimize rendering loss
        # F_k = argmin_{F_k} sum_{r in R} || C_hat_k(r) - C_k(r) ||^2_2
        F_curr = train_field(current_images, F_prev)
        
        # Step 3: Update transition state (e.g., occupancy grid)
        # G_curr = transition(G_prev, F_prev, F_curr)
        
        F_prev = F_curr
        
    return F_prev

def train_field(images, field):
    """
    Performs a limited number of optimization steps to update the field.
    """
    # Gradient descent steps to minimize L2 loss between rendered and observed images
    # The number of iterations is minimized for speed [S1]
    for step in range(num_optimization_steps):
        loss = 0
        for ray in sample_rays(images):
            # Volume rendering formula
            sigma, color = field(ray.origin, ray.direction)
            # ... compute transmittance T_i and aggregate color ...
            rendered_color = volume_render(ray, sigma, color)
            target_color = get_pixel_color(ray, images)
            loss += squared_error(rendered_color, target_color)
        
        # Backpropagate and update field parameters
        update_parameters(field, loss)
    return field
```

**Parameters and Edge Cases:**
*   **Camera Setup:** Limited to multi-view forward-facing cameras [S1]. Monocular or 360-degree inward-facing setups are excluded due to hardware complexity or cumbersome operation for prolonged streaming [S1].
*   **Optimization Steps:** The method requires "minimum optimization iterations per frame" to achieve interactive speed [S1]. The exact number is not specified but must be small enough to allow real-time processing [S1].
*   **Scalability:** The Markov assumption is critical; without it, conditioning on all previous images $C_{0:k}$ and fields $F_{0:k-1}$ becomes unscalable as $k$ increases [S1].

## Subtopics

### Hidden Markov Model Formulation
Treats radiance fields as hidden states and images as observations. The emission function is volumetric rendering, and the transition function models motion/deformation between steps [S1].

### Occupancy Grid Transition
A simple transition function is introduced for the occupancy grid $G$ to ensure efficient sampling during the streaming process [S1].

## Operating characteristics
*   **Time Complexity:** Designed for interactive speed. Training is frame-by-frame, requiring minimal optimization iterations per step [S1].
*   **Memory Complexity:** Reduced compared to offline methods as it does not store full 4D space-time or all previous radiance fields explicitly in a joint optimization [S1].
*   **Strengths:** Enables real-time streaming of dynamic scenes; suitable for social media, VR/AR, and gaming [S1].
*   **Limitations:** Restricted to multi-view forward-facing camera setups; accuracy may depend on the quality of the transition function between frames [S1].

## Background
Originated in the paper "OD-NeRF: Efficient Training of On-the-Fly Dynamic Neural Radiance Fields" [S1]. It addresses the limitation of existing dynamic NeRFs that only reconstruct scenes after the event has been fully recorded [S1]. The method builds on [Dynamic and Temporal Modeling](7610-dynamic-and-temporal-modeling.md) principles, specifically the on-the-fly/streaming strategy [S1].
