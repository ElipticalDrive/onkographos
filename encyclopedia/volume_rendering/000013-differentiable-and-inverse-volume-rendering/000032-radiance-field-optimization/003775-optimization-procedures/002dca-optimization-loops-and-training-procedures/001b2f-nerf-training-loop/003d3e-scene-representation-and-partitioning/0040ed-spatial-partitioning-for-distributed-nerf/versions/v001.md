# Spatial Partitioning for Distributed NeRF

Also called: Aspect Ratio Optimization Partitioning, Recursive CDF Partitioning

## Overview
A method to partition 3D space into non-overlapping tiles for distributed NeRF training by recursively splitting space based on a Probability Density Function (PDF) derived from a point cloud or ray samples, optimizing for cubic aspect ratios [S1, unofficial]. Unlike Block-NeRF which partitions based on training cameras, this method partitions space directly, allowing for finer bounding boxes in regions with more content or frequent capture (level-of-detail property) [S1, unofficial].

## How it works
**Inputs:**
*   A 3D scene defined by either a sparse point cloud from Structure from Motion (SfM) or a set of training rays [S1, unofficial].
*   The target number of partitions $N = 2^n$, where $n$ is the number of recursive iterations [S1, unofficial].

**Outputs:**
*   A set of $N$ non-overlapping axis-aligned bounding boxes (tiles) that partition the scene volume [S1, unofficial].

**Data Structures:**
*   **Point Cloud:** A list of 3D points $(x, y, z)$ representing spatial density. If SfM is unavailable, this is generated by discretizing training rays into uniform samples [S1, unofficial].
*   **PDF/CDF Arrays:** For each axis ($x, y, z$), a histogram representing the PDF, and its cumulative sum representing the CDF [S1, unofficial].

**Algorithm:**
1.  **Generate Point Cloud:**
    *   If SfM data exists, use the sparse reconstruction points.
    *   If not (e.g., drone footage of buildings), discretize the training rays into a set of 3D samples to approximate the spatial distribution [S1, unofficial].

2.  **Construct PDF and CDF:**
    *   Compute the Probability Density Function (PDF) for the point cloud distribution along each axis $x, y, z$ [S1, unofficial].
    *   Compute the Cumulative Distribution Function (CDF) for each axis. Let $CDF_x(v)$ be the cumulative count of points with coordinate $\le v$ along the x-axis [S1, unofficial].

3.  **Identify Candidate Split Planes:**
    *   For each axis, identify candidate planes where the CDF equals 0.5 (the median). This plane divides the current partition's points into two equal halves [S1, unofficial].
    *   Let $P_x, P_y, P_z$ be the candidate split planes for the x, y, and z axes respectively [S1, unofficial].

4.  **Select Optimal Split:**
    *   For each candidate plane $P \in \{P_x, P_y, P_z\}$, calculate the aspect ratios of the resulting two sub-partitions.
    *   Define the aspect ratio $AR_i$ for a partition $i$ as the ratio of its longest dimension to its shortest dimension (or similar metric where $AR=1$ is cubic) [S1, unofficial].
    *   Select the plane that yields partitions with aspect ratios closest to 1 (i.e., minimizes the deviation from cubic shape) [S1, unofficial].

5.  **Recursive Partitioning:**
    *   Split the current partition using the selected plane.
    *   Recursively apply steps 2-4 to each new sub-partition.
    *   Repeat for $n$ iterations to achieve $2^n$ partitions [S1, unofficial].

**Parameters:**
*   $n$: Number of recursive iterations. Typical values depend on the number of GPUs. For $G$ GPUs, $n = \log_2 G$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Lack of Point Cloud:** For captures lacking SfM data (e.g., Building capture), the method falls back to discretizing training rays into samples to form the PDF [S1, unofficial].
*   **Imbalanced Workload:** Even with balanced spatial partitioning, workload distribution across GPUs may remain imbalanced due to varying scene complexity within tiles, potentially causing communication bottlenecks [S1, unofficial].

## Subtopics

### NeRF-XL Spatial Partitioning
A strategy to partition 3D space into non-overlapping bounding boxes for multi-GPU assignment, aiming to balance compute by ensuring each region contains a similar amount of spatial content [S1, unofficial]. It generates a point cloud via SfM or ray discretization, constructs a PDF, and recursively partitions space by selecting axes that minimize aspect ratio deviation from cubic shapes [S1, unofficial]. A known pitfall is that imbalanced workload distribution across GPUs remains a bottleneck, which better spatial partitioning algorithms might address [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The partitioning process itself is $O(N \log N)$ or similar, depending on the sorting/histogramming of points, where $N$ is the number of points. This is a preprocessing step.
*   **Memory Complexity:** Requires storing the point cloud and CDF arrays. The number of partitions scales with the number of GPUs.
*   **Performance:** Reduces communication costs by over 2× through partition-based volume rendering (tile-based vs. sample-based synchronization) [S1, unofficial]. However, multi-GPU communication remains the primary bottleneck due to imbalanced workload distribution [S1, unofficial].
*   **Strengths:** Provides a level-of-detail property where regions with more content or frequent capture have finer bounding boxes [S1, unofficial]. Versatile for various captures including drone footage, street captures, and object-centric scenes [S1, unofficial].
*   **Limitations:** Imbalanced GPU workload can negate some benefits. SfM data may not be available for all scenes.

## Background
Originated in the NeRF-XL paper, which revisited existing approaches of decomposing large-scale scenes into independently trained NeRFs [S1, unofficial]. The method was introduced to efficiently harness multi-GPU setups for large-scale NeRF performance, addressing issues that impeded effective utilization of additional computational resources [S1, unofficial]. It contrasts with Mega-NeRF (which uses uniform partitioning) and Block-NeRF (which partitions by cameras) [S1, unofficial].
