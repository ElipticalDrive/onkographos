# Monocular Depth Consistency Loss

Also called: Monocular Depth Loss

## Overview
Monocular Depth Consistency Loss enforces geometric consistency between the estimated depth $\hat{D}(\mathbf{r})$ from a volume rendering model and the predicted monocular depth $\bar{D}(\mathbf{r})$ from a pre-trained depth estimator. It solves the problem of scale and shift ambiguity inherent in monocular depth predictions by applying a per-batch affine alignment. Unlike standard depth losses that assume absolute metric consistency, this method treats monocular depth as a relative cue, making it suitable for scenarios like endoscopic surgery where absolute scale is unknown or unreliable [S1].

## How it works
**Inputs and Outputs**
*   **Inputs**:
    *   $\hat{D}(\mathbf{r})$: Estimated depth values for rays $\mathbf{r}$ sampled from the volume renderer.
    *   $\bar{D}(\mathbf{r})$: Predicted monocular depth values for the same rays, obtained from an external monocular depth network.
    *   $\boldsymbol{\theta}, \boldsymbol{\phi}$: Parameters of the volume rendering model and any associated auxiliary networks.
*   **Output**:
    *   $\mathcal{L}_{Mono}$: The scalar loss value.

**Data Structures**
*   Depth maps are treated as tensors of shape $(H, W)$ or flattened vectors for batch processing.
*   Rays $\mathbf{r}$ are sampled according to a distribution $\bar{D}_i$ associated with the monocular depth prediction $\bar{D}_i$ [S1].

**Parameters**
*   $\eta$: Scale parameter.
*   $\epsilon$: Shift parameter.
*   Typical values: Computed dynamically per batch; no fixed hyperparameters are specified for $\eta$ or $\epsilon$ [S1].

**Steps**
1.  **Sample Rays**: Sample rays $\mathbf{r}$ from the distribution $\bar{D}_i$ corresponding to the current batch's monocular depth map $\bar{D}_i$ [S1].
2.  **Compute Alignment Parameters**: Calculate the scale $\eta$ and shift $\epsilon$ using the closed-form least-squares solution for the current batch. This must be done separately for each batch because predicted depth maps vary in scale and shift across batches [S1].
    *   Calculate $\eta$:
        $$ \eta = \left( \hat{D}(\mathbf{r})^T \hat{D}(\mathbf{r}) \right)^{-1} \hat{D}(\mathbf{r})^T \bar{D}(\mathbf{r}) $$
    *   Calculate $\epsilon$:
        $$ \epsilon = \bar{D}(\mathbf{r}) - \eta \hat{D}(\mathbf{r}) $$
3.  **Compute Loss**: Calculate the mean squared error between the aligned estimated depth and the monocular depth prediction:
    $$ \mathcal{L}_{Mono}(\boldsymbol{\theta}, \boldsymbol{\phi}) = \sum_i \mathbb{E}_{\mathbf{r} \sim \bar{D}_i} \left\| (\eta \hat{D}(\mathbf{r}) + \epsilon) - \bar{D}(\mathbf{r}) \right\|^2 $$
4.  **Optimization**: Replace the standard depth loss $\mathcal{L}_D$ with $\mathcal{L}_{Mono}$ during training for monocular sequences [S1].

**Pseudocode**
```python
def monocular_depth_consistency_loss(estimated_depth, monocular_depth):
    """
    Computes the Monocular Depth Consistency Loss.
    
    Args:
        estimated_depth (Tensor): Shape (N, H, W) or (N, num_samples). 
                                  Depth values estimated by the volume renderer.
        monocular_depth (Tensor): Shape (N, H, W) or (N, num_samples). 
                                  Depth values predicted by a monocular depth network.
                                  
    Returns:
        Tensor: Scalar loss value.
    """
    # Flatten depth maps to vectors for linear algebra operations
    # Shape: (N, num_pixels)
    d_hat = estimated_depth.flatten(start_dim=1)
    d_bar = monocular_depth.flatten(start_dim=1)
    
    # Calculate scale eta and shift epsilon per batch
    # eta = (d_hat^T d_hat)^-1 d_hat^T d_bar
    # This is a standard least-squares solution for y = ax + b where b=0 for eta calculation
    # Note: The formula provided in [S1] calculates eta assuming a zero-intercept fit for the scale,
    # then computes epsilon as the residual mean shift.
    
    # Dot product d_hat^T d_hat: Shape (N, 1)
    dot_hat_hat = torch.sum(d_hat * d_hat, dim=1, keepdim=True)
    
    # Dot product d_hat^T d_bar: Shape (N, 1)
    dot_hat_bar = torch.sum(d_hat * d_bar, dim=1, keepdim=True)
    
    # Avoid division by zero
    dot_hat_hat = torch.clamp(dot_hat_hat, min=1e-8)
    
    # Calculate eta
    eta = dot_hat_bar / dot_hat_hat
    
    # Calculate epsilon: epsilon = d_bar - eta * d_hat
    # This is computed element-wise, but since epsilon is a scalar shift per batch,
    # we typically take the mean of the residuals if the formula implies a global shift.
    # However, the source formula defines epsilon as a vector operation result 
    # or implies it is a constant shift for the batch. 
    # Given "epsilon = D_bar(r) - eta D_hat(r)", this results in a vector.
    # The loss term is || (eta D_hat(r) + epsilon) - D_bar(r) ||^2.
    # If epsilon is a vector, this term becomes 0 by definition if calculated exactly as above.
    # Context implies epsilon is a scalar shift parameter for the batch.
    # Standard interpretation of such alignment:
    # 1. Fit scale eta.
    # 2. Fit shift epsilon as the mean residual.
    
    # Residuals after scaling
    residuals = d_bar - eta * d_hat
    
    # Calculate epsilon as the mean shift for the batch
    epsilon = torch.mean(residuals, dim=1, keepdim=True)
    
    # Aligned estimated depth
    aligned_d_hat = eta * d_hat + epsilon
    
    # Compute MSE loss
    loss = torch.mean((aligned_d_hat - d_bar) ** 2)
    
    return loss
```

**Edge Cases and Pitfalls**
*   **Batch Variance**: $\eta$ and $\epsilon$ must be calculated separately for each batch. Using global or previous batch statistics will fail because monocular depth predictions vary in scale and shift across different batches [S1].
*   **Degenerate Input**: If $\hat{D}(\mathbf{r})$ is zero or near-zero everywhere, the denominator in the $\eta$ calculation becomes zero. A small epsilon (e.g., $10^{-8}$) should be added to the denominator for numerical stability [G].
*   **Monocular Ambiguity**: This loss does not enforce absolute metric scale. It only enforces consistency up to a scale and shift. It is not suitable if absolute metric depth is required without additional constraints [S1].

## Operating characteristics
*   **Time Complexity**: $O(N \cdot P)$ where $N$ is batch size and $P$ is number of pixels/samples. The dominant cost is the dot products and element-wise operations.
*   **Memory Complexity**: $O(N \cdot P)$ to store depth tensors.
*   **Strengths**: Effective for relative depth consistency in domains like endoscopy where absolute scale is unknown. Simple to implement as a differentiable post-processing step.
*   **Limitations**: Does not resolve absolute scale. Performance depends on the quality of the external monocular depth estimator.
*   **When to Use**: Monocular endoscopic sequences or any scenario where stereo/depth sensors are unavailable but a pre-trained monocular depth model is accessible [S1].
*   **When Not to Use**: When absolute metric depth is required, or when stereo/structured light depth is available (use standard depth loss instead) [S1].

## Background
The Monocular Depth Consistency Loss was introduced in the context of efficient deformable tissue reconstruction using orthogonal neural planes. It addresses the challenge of reconstructing 3D structures from monocular video, where depth is inherently ambiguous. The method leverages the relative depth cues provided by monocular depth estimators, which are beneficial even over larger distances, to regularize the volume rendering optimization [S1]. It was specifically applied to the EndoNeRF dataset, which consists of robotic surgery videos captured via stereo cameras from a single viewpoint, simulating monocular input conditions [S1].
