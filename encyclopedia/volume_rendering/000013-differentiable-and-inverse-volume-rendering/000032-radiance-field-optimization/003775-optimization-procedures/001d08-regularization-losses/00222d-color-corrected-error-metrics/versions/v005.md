# Color-Corrected Error Metrics


## Overview
Color-Corrected Error Metrics is an evaluation procedure designed to mitigate the impact of photometric variations—such as autoexposure, white balance shifts, and RGB clipping—in "in the wild" datasets like Tanks and Temples [S1]. It solves the problem of ill-posed view synthesis evaluation where target photometric conditions are unknown or inconsistent [S1]. It differs from standard metrics by introducing a per-image optimization step to align rendered colors with ground truth before error calculation [S1].

## How it works
**Inputs:**
- Rendered image $\hat{I}$ (RGB values).
- Ground truth image $I$ (RGB values).
- Mask $M$ indicating saturated/clipped pixels (ignored during fitting).

**Outputs:**
- Corrected rendered image $\hat{I}'$.
- Error metric value computed between $\hat{I}'$ and $I$.

**Data Structures:**
- Coefficients vector $\mathbf{a}$ containing quadratic polynomial parameters per channel.
- Valid pixel indices excluding saturated regions.

**Steps:**
1. Identify saturated or clipped pixels in the rendered or ground truth image to form a binary mask $M$ [S1].
2. For each color channel $c \in \{R, G, B\}$, construct a quadratic polynomial expansion mapping rendered values to ground truth values: $\hat{I}'_c = a_c \hat{I}_c^2 + b_c \hat{I}_c + c_c$ [S1].
3. Solve a per-image least squares problem to find coefficients $\mathbf{a} = \{a_c, b_c, c_c\}_c$ that minimize the sum of squared errors between the polynomial output and ground truth for all non-saturated pixels: $\min_{\mathbf{a}} \sum_{p \notin M} \| \hat{I}'_p - I_p \|^2$ [S1].
4. Apply the fitted polynomial to the entire rendered image to produce the corrected image $\hat{I}'$ [S1].
5. Compute the desired error metric (e.g., PSNR, SSIM, LPIPS) between $\hat{I}'$ and $I$ [S1].

**Parameters:**
- Polynomial degree: 2 (quadratic) [S1].

**Edge Cases:**
- **Saturated Pixels:** Must be excluded from the least squares fit to prevent the polynomial from being skewed by clipped values [S1].
- **Degenerate Input:** If all pixels are saturated, the least squares problem is undefined and the metric cannot be computed [G].

**Pseudocode:**
```python
import numpy as np

def color_corrected_error(rendered, ground_truth, saturated_mask):
    # rendered: H x W x 3 array
    # ground_truth: H x W x 3 array
    # saturated_mask: H x W boolean array (True if saturated)
    H, W, C = rendered.shape
    valid_pixels = ~saturated_mask

    # Extract valid pixel values
    r_vals = rendered[valid_pixels].reshape(-1, C)
    g_vals = ground_truth[valid_pixels].reshape(-1, C)
    N = r_vals.shape[0]

    # Fit quadratic polynomial per channel: y = a*x^2 + b*x + c
    coefficients = [[], [], []]
    for ch in range(C):
        x = r_vals[:, ch]
        y = g_vals[:, ch]
        # Design matrix X: [x^2, x, 1]
        X = np.column_stack([x**2, x, np.ones(N)])
        # Solve least squares: X @ coeffs = y
        coeffs, _, _, _ = np.linalg.lstsq(X, y, rcond=None)
        coefficients[ch] = coeffs

    # Apply correction to all pixels
    corrected = np.zeros_like(rendered)
    for ch in range(C):
        x = rendered[:, :, ch]
        a, b, c_coef = coefficients[ch]
        corrected[:, :, ch] = a * x**2 + b * x + c_coef

    # Compute error metric (example: MSE then PSNR)
    mse = np.mean((corrected - ground_truth)**2)
    psnr = 10 * np.log10(1.0 / mse) if mse > 0 else float('inf')

    return psnr, corrected
```

## Subtopics

### Bradford Chromatic Adaptation for White Balance
A post-processing white balance technique using Bradford chromatic adaptation to map from a Planck/CIE-daylight illuminant to D65 [S2, unofficial]. It applies the Bradford transform directly to the scene-linear image before tone mapping [S2, unofficial]. It differs from simple gray-world or white-patch algorithms by using a physically-based chromatic adaptation transform [S2, unofficial].

### Phys3DGS Relighting Evaluation
For synthetic data, explicitly computes a 3-channel rescale factor for base color by taking the median value of all pixel-wise ratios between the model's prediction and ground truth [S3, unofficial]. For real captures, omits the rescale procedure and presents only qualitative results as no ground truth on base color is provided [S3, unofficial]. The PBR rendering pipeline operates in linear (HDR) space, and the final result is clipped to [0, 1] and mapped to sRGB just before calculating photometric loss or evaluation [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ per image for the least squares fit, where $N$ is the number of valid pixels [G]. The fit is solved once per image.
- **Memory Complexity:** $O(N)$ to store pixel values during the fit [G].
- **Strengths:** Mitigates the impact of autoexposure and white balance variations in uncontrolled datasets [S1]. Makes models like SVS and GLO quantitatively comparable [S1].
- **Limitations:** Computationally adds overhead to evaluation [G].
- **When to use:** Evaluating view synthesis on "in the wild" datasets like Tanks and Temples where camera settings are not fixed [S1].
- **When not to use:** On controlled datasets with fixed photometry, or when spatially varying color errors are of interest [G].

## Background
Originated in the context of evaluating view synthesis on unbounded datasets where photometric variation makes evaluation ill-posed [S1]. The method was proposed to neutralize these variations during evaluation, allowing for fair comparison between different view synthesis models [S1]. The authors note that this challenge is orthogonal to the unbounded nature of scenes, leading them to construct a dataset with fixed photometry and minimized saturated pixels [S1].
