# Composite Image Loss with Visibility Weighting

Also called: Optimization Loss Function, Visibility-weighted Photometric Loss

## Overview
This method computes the primary photometric reconstruction loss for differentiable volume rendering by combining pixel-wise, structural, and perceptual metrics, weighted by a visibility mask to ignore occluded or background regions. It sets itself apart from standard photometric losses by explicitly incorporating a visibility map $\mathbf{V}_M$ to prevent gradients from propagating through unobserved areas, and by including a perceptual LPIPS term which is less sensitive to high-frequency noise than raw pixel differences [4262-composite-image-loss-with-visibility-weighting.md]. It builds on [Photometric and Image Reconstruction Losses](9789-photometric-and-image-reconstruction-losses.md).

## How it works
**Inputs and Outputs:**
- **Inputs:** Rendered image $\mathbf{I}_r$, ground-truth image $\mathbf{I}_{gt}$, visibility map $\mathbf{V}_M$ (same spatial dimensions as images), and loss weights $\lambda_1, \lambda_{SSIM}, \lambda_{LPIPS}$.
- **Output:** Composite image loss scalar $L_c$.

**Data Structures:**
- $\mathbf{I}_r, \mathbf{I}_{gt}$: 3D tensors of shape $(H, W, C)$, typically float32, normalized to $[0, 1]$ or $[-1, 1]$ depending on the specific LPIPS implementation.
- $\mathbf{V}_M$: 2D or 3D tensor of shape $(H, W)$ or $(H, W, 1)$, values in $[0, 1]$.

**Formulas:**
The composite loss $L_c$ is defined as [S1]:
$$
L_c = \lambda_1 L_1 (\mathbf{V}_M \odot \mathbf{I}_r, \mathbf{V}_M \odot \mathbf{I}_{gt}) + \lambda_{SSIM} L_{SSIM} (\mathbf{V}_M \odot \mathbf{I}_r, \mathbf{V}_M \odot \mathbf{I}_{gt}) + \lambda_{LPIPS} L_{LPIPS} (\mathbf{I}_r, \mathbf{I}_{gt})
$$
where $\odot$ denotes the Hadamard (element-wise) product. The total training loss $L$ further includes regularization terms [S1]:
$$
L = L_c + \lambda_{sc} L_{sc} + \lambda_{vm} L_{vm}
$$
Here, $L_{sc}$ is the sampling coordinate regularization loss and $L_{vm}$ is the visibility map regularization loss.

**Parameters:**
Typical values from the source implementation [S1]:
- $\lambda_1 = 0.8$
- $\lambda_{SSIM} = 0.2$
- $\lambda_{LPIPS} = 0.005$
- $\lambda_{sc} = 0.001$
- $\lambda_{vm} = 0.15$

**Pseudocode:**
```python
def compute_composite_image_loss(I_r, I_gt, V_M, lambda_1=0.8, lambda_ssim=0.2, lambda_lpips=0.005):
    """
    Computes the composite image loss L_c.
    
    Args:
        I_r: Rendered image tensor (H, W, C).
        I_gt: Ground truth image tensor (H, W, C).
        V_M: Visibility map tensor (H, W) or (H, W, 1).
        lambda_1: Weight for L1 loss.
        lambda_ssim: Weight for SSIM loss.
        lambda_lpips: Weight for LPIPS loss.
        
    Returns:
        L_c: Scalar composite loss.
    """
    # Ensure V_M has compatible shape for broadcasting with I_r and I_gt
    # If V_M is (H, W), expand to (H, W, 1)
    if V_M.ndim == 2:
        V_M = V_M.unsqueeze(-1)
        
    # Apply visibility mask via Hadamard product
    masked_I_r = I_r * V_M
    masked_I_gt = I_gt * V_M
    
    # 1. L1 Loss on masked images
    # L1 is the mean absolute error
    l1_loss = torch.mean(torch.abs(masked_I_r - masked_I_gt))
    
    # 2. SSIM Loss on masked images
    # SSIM is typically computed as 1 - SSIM_value to make it a loss
    # Implementation depends on library (e.g., torchmetrics or custom)
    # Assuming a function ssim_loss that returns a scalar between 0 and 1
    ssim_loss = 1.0 - compute_ssim(masked_I_r, masked_I_gt)
    
    # 3. LPIPS Loss on unmasked images
    # LPIPS measures perceptual similarity using deep features
    # Implementation depends on library (e.g., lpips package)
    lpips_loss = compute_lpips(I_r, I_gt)
    
    # Combine losses
    L_c = (lambda_1 * l1_loss) + (lambda_ssim * ssim_loss) + (lambda_lpips * lpips_loss)
    
    return L_c

def compute_total_loss(L_c, L_sc, L_vm, lambda_sc=0.001, lambda_vm=0.15):
    """
    Computes the total loss L including regularization terms.
    
    Args:
        L_c: Composite image loss.
        L_sc: Sampling coordinate regularization loss.
        L_vm: Visibility map regularization loss.
        lambda_sc: Weight for sampling coordinate regularization.
        lambda_vm: Weight for visibility map regularization.
        
    Returns:
        L: Total loss.
    """
    L = L_c + (lambda_sc * L_sc) + (lambda_vm * L_vm)
    return L
```

**Edge Cases and Pitfalls:**
- **Visibility Mask Shape:** The visibility map $\mathbf{V}_M$ must be broadcastable to the image dimensions. If $\mathbf{V}_M$ is 2D, it must be expanded to match the channel dimension of $\mathbf{I}_r$ and $\mathbf{I}_{gt}$ before multiplication [S1].
- **LPIPS Input Range:** LPIPS implementations often expect inputs in specific ranges (e.g., $[-1, 1]$ or $[0, 1]$). Ensure $\mathbf{I}_r$ and $\mathbf{I}_{gt}$ are normalized correctly before passing to the LPIPS function.
- **SSIM on Masked Data:** Applying SSIM to masked images requires care. If $\mathbf{V}_M$ contains zeros, the local variance in those regions becomes zero, which can cause division by zero in SSIM calculations. The SSIM implementation should handle zero-variance regions by ignoring them or setting the local SSIM to 1 (perfect match) for those regions.
- **Gradient Flow:** The visibility mask $\mathbf{V}_M$ is typically treated as a constant during the backward pass for $L_c$ to avoid updating the mask itself through the photometric loss. Updates to $\mathbf{V}_M$ are handled via its own regularization loss $L_{vm}$ [S1].

## Subtopics

### [SRF-Loss](6978-srf-loss.md)
SRF-Loss is the composite objective function used to train SuRFNet for generating high-quality Sparse Radiance Fields (SRFs) from partial or noisy inputs. It addresses the problem of ensuring that generated 3D radiance fields not only match the input density and color statistics but also produce visually accurate renderings from novel views. It sets itself apart from simple pixel-wise reconstruction losses by incorporating a 3D-supervised density/radiance component and an online perceptual loss that explicitly optimizes for rendering quality.

## Operating characteristics
- **Time Complexity:** Dominated by the SSIM and LPIPS computations. LPIPS involves forward passes through a pre-trained VGG network, which is computationally expensive compared to L1. SSIM involves local window statistics.
- **Memory Complexity:** Requires storing intermediate tensors for masked images and gradients. LPIPS requires caching features from the VGG network.
- **Performance:** The use of LPIPS improves perceptual quality but increases training time. The visibility weighting prevents artifacts in unobserved regions.
- **Strengths:** Robust to occlusions, perceptually motivated, combines multiple loss types for balanced optimization.
- **Limitations:** Computationally heavy due to LPIPS and SSIM. Sensitive to the choice of weights.
- **When to Use:** When training differentiable volume rendering models where perceptual quality and handling of occlusions are critical.
- **When Not to Use:** When computational resources are extremely limited and only basic pixel-wise accuracy is required.

## Background
The method originates from the "Gaussian in the Wild" paper, which introduces 3D Gaussian Splatting for unconstrained image collections [S1]. It is used in the optimization phase of training 3D Gaussian Splatting models to ensure high-fidelity reconstruction from sparse or noisy input images. The visibility weighting mechanism is adapted from prior work on differentiable rendering to handle partial observability [S1].
