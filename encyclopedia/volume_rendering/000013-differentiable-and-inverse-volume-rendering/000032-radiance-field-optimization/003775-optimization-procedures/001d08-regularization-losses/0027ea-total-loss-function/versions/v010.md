# Total Loss Function

Also called: Combined Loss, Full Training Objective, Loss function, Total Loss, Training loss

## Overview
The Total Loss Function is the composite objective used to optimize radiance field models by balancing photometric reconstruction accuracy with geometric and structural regularization. It aggregates multiple loss terms—such as pixel-wise color error, latent space priors, and field smoothness constraints—into a single scalar value to guide gradient-based optimization. It differs from sibling methods like [Distortion Loss](2755-distortion-loss.md) or [Total Variation Regularization](860-total-variation-regularization.md) by serving as the overarching container that combines these specific terms with configurable weights, rather than defining a single regularization mechanism in isolation.

## How it works
The total loss is computed as a weighted sum of distinct components, each addressing a specific aspect of the training objective (e.g., color fidelity, geometric consistency, or latent distribution).

**Inputs and Outputs:**
- **Inputs:** Rendered image $\hat{\mathbf{I}}_{\text{rgb}}$, ground truth image $\mathbf{I}_{\text{rgb}}^*$, latent encoding $\mathbf{z}$, volume opacity field $\mathbf{V}_\alpha$, and auxiliary fields (e.g., SDF gradients, discriminator outputs).
- **Outputs:** A scalar loss value $L$ used for backpropagation.

**Data Structures:**
- **Images:** 2D tensors of shape $(H, W, 3)$ or flattened $(P, 3)$ for sampled pixels.
- **Latents:** Vector $\mathbf{z}$ representing the compressed scene representation.
- **Fields:** 3D tensors or implicit function representations for opacity/SDF.

**Formulas:**
The general form of the total loss is:
$$
L = \sum_{k} w_k L_k
$$
where $w_k$ is the weight for loss term $k$, and $L_k$ is the individual loss component.

Specific formulations found in the literature include:

1.  **Variational Autoencoder (VAE) Style Loss [S1]:**
    $$
    \ell(\theta) = \frac{1}{P} \sum_{\mathbf{p}} \left\| \hat{\mathbf{I}}_{\text{rgb}}(\mathbf{p}) - \mathbf{I}_{\text{rgb}}^*(\mathbf{p}) \right\|^2 + \lambda_{\text{KL}} D_{\text{KL}}(\mathbf{z} \parallel \mathcal{N}(0, 1)) + J_{\text{tv}}(\mathbf{V}_\alpha) + J_{\text{B}}(\mathbf{I}_\alpha)
    $$
    where $P$ is the number of sampled pixels, $D_{\text{KL}}$ is the Kullback-Leibler divergence, $J_{\text{tv}}$ is the total variation prior on volume opacity, and $J_{\text{B}}$ is a beta prior on exit opacity.

2.  **SDF/Gaussian Splatting Hybrid Loss [S2, unofficial]:**
    $$
    \mathcal{L} = (\mathcal{L}_{\text{rgb}} + 0.1\mathcal{L}_{\text{eik}}) + (\lambda_1\mathcal{L}_{\text{usdf}} + \lambda_2\mathcal{L}_{\text{bias}} + \lambda_3\mathcal{L}_{\text{pc}})
    $$
    where $\mathcal{L}_{\text{rgb}}$ is the L1 photometric loss, $\mathcal{L}_{\text{eik}}$ is the Eikonal loss, and the latter terms correspond to specific module losses (uncertain SDF, bias, point cloud).

3.  **Proposal Network Loss [S5]:**
    $$
    \mathcal{L}(\mathbf{r}) = \mathcal{L}_{\text{photo}}(\mathbf{r}) + \lambda_{\text{Eik}} \mathcal{L}_{\text{Eik}}(\mathbf{r}) + \mathcal{L}_{\text{prop}}(\mathbf{r})
    $$

**Numbered Steps:**
1.  **Sample Rays/Pixels:** Randomly select $P$ pixels or $N$ rays from the training set. [S1][S2, unofficial]
2.  **Render:** Compute the rendered image $\hat{\mathbf{I}}_{\text{rgb}}$ using the current radiance field parameters.
3.  **Compute Photometric Loss:** Calculate the difference between rendered and ground truth colors.
    -   L2 Loss: $\frac{1}{P} \sum \| \hat{\mathbf{I}} - \mathbf{I}^* \|^2$ [S1]
    -   L1 Loss: $\frac{1}{N} \sum |C_i - \hat{C}_i|$ [S2, unofficial]
4.  **Compute Regularization Losses:**
    -   **KL Divergence:** Compute $D_{\text{KL}}(\mathbf{z} \parallel \mathcal{N}(0, 1))$ for latent codes. [S1]
    -   **Total Variation:** Compute smoothness priors on opacity or bilateral grid parameters. [S1][S6, unofficial]
    -   **Eikonal Loss:** Enforce $\|\nabla f(p)\| = 1$ for SDF fields. [S2, unofficial][S5]
    -   **Auxiliary/Other:** Add specific losses like background entropy, discriminator gradient penalties, or depth consistency. [S4][S7, unofficial]
5.  **Weight and Sum:** Multiply each loss term by its configured weight ($\lambda$) and sum them to get the total loss.
6.  **Backpropagate:** Compute gradients with respect to model parameters $\theta$ and update using an optimizer (e.g., Adam). [S1]

**Parameters with Typical Values:**
-   $\lambda_{\text{KL}}$: 0.001 [S1]
-   $\lambda_{\text{Eik}}$: 0.01 [S5]
-   $\lambda_1, \lambda_2, \lambda_3$: 1, 1, 0.25 [S2, unofficial]
-   Learning Rate: $10^{-4}$ for encoder-decoder weights [S1]
-   Batch Size: 16 rays/pixels [S1]
-   Pixel Sampling: 128x128 pixels randomly sampled from the image [S1]

**Edge Cases and Pitfalls:**
-   **Memory Usage:** Computing gradients for all pixels can be prohibitive. Randomly sampling a subset of pixels (e.g., 128x128) is recommended to reduce memory usage. [S1]
-   **Step Size Normalization:** Step sizes should be computed in normalized voxel space $[-1, 1]^3$ to ensure consistent saturation points at initialization. [S1]
-   **Background Blending:** If the ground truth background is not black, predicted RGB must be blended with the ground truth background color before loss computation to avoid incorrect photometric errors. [S7, unofficial]

**Pseudocode:**
```python
def compute_total_loss(rendered_rgb, gt_rgb, latent_z, opacity_field, config):
    """
    Computes the total loss for radiance field optimization.
    
    Args:
        rendered_rgb: Tensor of shape (H, W, 3) or (P, 3)
        gt_rgb: Tensor of shape (H, W, 3) or (P, 3)
        latent_z: Tensor of latent codes
        opacity_field: Tensor or implicit function for opacity
        config: Object containing loss weights and settings
        
    Returns:
        Scalar loss value
    """
    # 1. Photometric Loss (L1 or L2)
    # Using L1 as per [S2, unofficial], L2 as per [S1]. 
    # Implementation depends on specific variant.
    if config.loss_type == 'l1':
        l_rgb = torch.mean(torch.abs(rendered_rgb - gt_rgb))
    else:
        l_rgb = torch.mean((rendered_rgb - gt_rgb) ** 2)
        
    # 2. KL Divergence (if using VAE-style latent)
    l_kl = 0.0
    if config.use_kl:
        # D_KL(z || N(0,1))
        l_kl = torch.mean(-0.5 * torch.sum(1 + latent_z.var() - latent_z.mean()**2 - latent_z.var(), dim=1))
        
    # 3. Total Variation / Smoothness
    l_tv = 0.0
    if config.use_tv:
        # Compute TV on opacity field or bilateral grid
        l_tv = compute_total_variation(opacity_field)
        
    # 4. Eikonal Loss (if using SDF)
    l_eik = 0.0
    if config.use_eikonal:
        # ||grad(f) - 1||^2
        l_eik = compute_eikonal_loss(opacity_field)
        
    # 5. Other Auxiliary Losses (e.g., Discriminator, Depth)
    l_aux = 0.0
    if config.use_aux:
        l_aux = compute_auxiliary_losses(rendered_rgb, gt_rgb, opacity_field)
        
    # 6. Weighted Sum
    total_loss = (
        l_rgb + 
        config.lambda_kl * l_kl + 
        config.lambda_tv * l_tv + 
        config.lambda_eik * l_eik + 
        l_aux
    )
    
    return total_loss
```

## Subtopics

### [Composite Image Loss with Visibility Weighting](4262-composite-image-loss-with-visibility-weighting.md)
The Composite Image Loss with Visibility Weighting ($L_c$) is a composite objective function used to train radiance field models, specifically SuRFNet, by aligning rendered images with ground-truth references while suppressing errors in occluded or unobserved regions. It sets itself apart from standard photometric losses by explicitly masking the L1 and SSIM terms with a visibility map $V_M$, ensuring that supervision is only applied to pixels corresponding to visible surfaces, while retaining a full-image perceptual loss.

### [Loss Function Configuration](6782-loss-function-configuration.md)
This method defines the specific hyperparameters and weighting strategies used to balance multiple loss components during the optimization of radiance fields. It addresses the problem of stabilizing training by preventing any single loss term (e.g., photometric error vs. regularization) from dominating the gradient updates. It differs from sibling methods by focusing on the static configuration of scalar weights for the total loss function rather than the dynamic computation of loss values or visibility masks.

### [Sparse Depth Consistency Loss](7294-sparse-depth-consistency-loss.md)
The Sparse Depth Consistency Loss enforces geometric consistency between the rendered depth maps of a radiance field and sparse depth estimates provided by a Structure-from-Motion (SfM) pipeline. It serves as a regularization term within the total loss function to mitigate floaters and undesired depth discontinuities common in sparse-input settings. It is distinguished from sibling losses like Composite Image Loss with Visibility Weighting by focusing specifically on depth metric alignment rather than photometric color fidelity or visibility-weighted compositing.

### [Loss Weight Configuration](7883-loss-weight-configuration.md)
Loss weight configuration determines the scalar parameter $\lambda$ that balances the relative contribution of distinct loss terms during radiance-field optimization. It addresses the trade-off between preserving color fidelity and enforcing geometric consistency or adversarial realism. It differs from [Composite Image Loss with Visibility Weighting](4262-composite-image-loss-with-visibility-weighting.md) by weighting loss *terms* rather than pixel *visibility*, and from [Sparse Depth Consistency Loss](7294-sparse-depth-consistency-loss.md) by focusing on the global balance of the total loss function rather than specific depth constraints.

### Empty Space Loss
An AOV loss that encourages the rendering throughput to equal 0.0 in regions where a binary object mask is inactive [S3, unofficial].
1. Retrieve the 'throughput' AOV from the dictionary. If missing, return 0.0.
2. Convert the binary mask to a float tensor.
3. Compute the absolute difference between throughput and 0.0.
4. Multiply the difference by $(1.0 - \text{mask})$.
5. Compute the mean over all pixels/samples.
6. Scale by weight.
Formula: $L = w \cdot \frac{1}{N} \sum_{i=1}^{N} (1 - m_i) \cdot |T_i - 0|$, where $w$ is the weight, $N$ is the number of samples, $m_i \in \{0, 1\}$ is the binary mask value, and $T_i$ is the throughput value [S3, unofficial].
Parameters: `masks` (binary mask array/tensor, values 0 or 1), `weight` (float scalar, default 1.0) [S3, unofficial].

### Opacity Loss
An AOV (Arbitrary Output Variable) loss that encourages the rendering throughput to equal 1.0 in regions where a binary object mask is active [S3, unofficial].
Formula: $L = w \cdot \frac{1}{N} \sum_{i=1}^{N} m_i \cdot |T_i - 1|$, where $w$ is the weight, $N$ is the number of samples, $m_i \in \{0, 1\}$ is the binary mask value, and $T_i$ is the throughput value [S3, unofficial].
Parameters: `masks` (binary mask array/tensor, values 0 or 1), `weight` (float scalar, default 1.0) [S3, unofficial].

### Auxiliary Losses
Includes per-point RGB loss to supervise color emission of each query point directly, and background entropy loss to enforce rendered background probability concentration [S4]. Adding both auxiliary losses yields PSNR 35.54, compared to 35.37 (none) or 35.53 (one loss) [S4].

### HybridNeRF Optimization Loss
The total loss $\mathcal{L}(\mathbf{r})$ is the sum of photometric loss $\mathcal{L}_{\text{photo}}$, Eikonal loss $\mathcal{L}_{\text{Eik}}$ weighted by $\lambda_{\text{Eik}}$, and interlevel proposal loss $\mathcal{L}_{\text{prop}}$ [S5]. Parameter: $\lambda_{\text{Eik}} = 0.01$ [S5].

### Total Variation Loss
A regularization loss that computes the total variation of the bilateral grid parameters to encourage smoothness in the learned color transformations [S6, unofficial].
Steps: Iterate over all bilateral grids; compute TV loss using `total_variation_loss` and multiply by `config.bilgrid_tv_loss_mult`; sum these losses. For a tensor $x$ of shape $(B, C, \dots)$, for each spatial dimension $i$ from 2 to `len(x.shape)`, compute the squared difference between adjacent elements along that dimension. Normalize by the number of elements in the tensor excluding batch and channel dimensions. Sum over all spatial dimensions and divide by batch size [S6, unofficial].
Formula: $L_{TV} = \frac{1}{B} \sum_{i=2}^{D} \frac{\sum_{j} (x_{..., j+1, ...} - x_{..., j, ...})^2}{N_i}$, where $B$ is batch size, $D$ is number of dimensions, and $N_i$ is the number of elements in dimension $i$ excluding batch and channel [S6, unofficial].

### Discriminator Loss with Gradient Penalty
A loss function for training the discriminator, including a gradient penalty term to enforce Lipschitz continuity [S7, unofficial].
Steps:
1. Run discriminator on real patches to get predictions.
2. Run discriminator on detached fake patches to get predictions.
3. Compute gradient penalty using real patches.
4. Sum real and fake losses to get total discriminator loss.
5. Set input tensor to require gradients.
6. Run discriminator on input to get predictions.
7. Compute gradients of the sum of predictions with respect to the input.
Formulas: `loss_d_real = mean(softplus(-pred_real))`, `loss_d_fake = mean(softplus(pred_fake))`, `r1_penalty = mean(sum(gradients^2, dim=[1,2,3]))`, `gradient_penalty = r1_penalty / 2` [S7, unofficial].
Parameter: `gp_loss_mult` (multiplier for gradient penalty) [S7, unofficial].

### Background Blending for Loss Computation
Blends the predicted RGB image with the ground truth background color for accurate loss computation, especially when the background is not black [S7, unofficial].
Step: Call the `blend_background_for_loss_computation` method of the RGB renderer with the predicted RGB, accumulation, and ground truth RGB [S7, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of sampled pixels/rays $P$ or $N$. The dominant cost is the forward rendering pass and the subsequent gradient computation.
- **Memory Complexity:** Proportional to the number of sampled pixels and the depth of the computational graph. Using random sampling (e.g., 128x128) reduces memory usage significantly compared to full-image rendering [S1].
- **Measured Performance:** Training for 500,000 iterations takes approximately 10 days on a single NVIDIA Tesla V100 [S1].
- **Strengths:** Provides a unified framework for incorporating diverse constraints (photometric, geometric, latent). Flexible weighting allows balancing competing objectives.
- **Limitations:** Requires careful tuning of multiple hyperparameters ($\lambda$ weights). Can be sensitive to the choice of loss functions (e.g., L1 vs L2) and sampling strategies.
- **When to Use:** Standard training of radiance fields where both color fidelity and geometric/structural priors are needed.
- **When Not to Use:** When computational resources are extremely limited and only photometric reconstruction is required (though even then, some regularization is often beneficial).

## Background
The concept of a total loss function in radiance field optimization evolved from the need to stabilize training and improve reconstruction quality beyond simple photometric error. Early works like Neural Volumes [S1] introduced composite objectives combining photometric loss with latent space regularization (KL divergence) and spatial priors (Total Variation, Beta priors). Subsequent works like NeuS [S2, unofficial] and HybridNeRF [S5] incorporated geometric constraints such as Eikonal loss and SDF consistency. The modular nature of these losses allows for the integration of new terms (e.g., depth consistency, discriminator losses) as the field advances.
