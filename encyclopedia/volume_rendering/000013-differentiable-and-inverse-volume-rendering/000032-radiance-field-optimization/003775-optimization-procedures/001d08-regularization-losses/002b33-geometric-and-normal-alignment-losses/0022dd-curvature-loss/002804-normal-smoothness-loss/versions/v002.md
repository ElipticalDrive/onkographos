# Normal Smoothness Loss
Also called: Normal Continuity Loss, Normal Smoothness
## Overview
A regularization loss that encourages consecutive surface normals along a viewing ray to be similar, enforcing spatial smoothness in the estimated geometry [S1, unofficial]. It differs from [Surface Curvature Regularization](6510-surface-curvature-regularization.md) by operating on discrete sample points along a ray rather than computing differential geometric invariants from a continuous field [S1, unofficial][S2, unofficial].
## How it works
**Inputs and Outputs:**
- Input: Normal vector at the current sample point $\mathbf{n}_p$, normal vector at the previous sample point along the ray $\mathbf{n}_{prev}$, and a scalar weight $w$ [S1, unofficial].
- Output: Scalar loss value $L$ [S1, unofficial].

**Data Structures:**
- $\mathbf{n}_p$: 3D unit vector representing the surface normal at the current integration sample [S1, unofficial].
- $\mathbf{n}_{prev}$: 3D unit vector representing the surface normal at the immediately preceding integration sample along the same ray [S1, unofficial].

**Steps:**
1. Compute the dot product between the current normal and the previous normal: $d = \mathbf{n}_p \cdot \mathbf{n}_{prev}$ [S1, unofficial].
2. Calculate the raw loss as one minus the dot product: $L_{raw} = 1.0 - d$ [S1, unofficial].
3. Scale the loss by the weight parameter: $L = w \cdot L_{raw}$ [S1, unofficial].

**Formula:**
$$L = w \cdot (1 - \mathbf{n}_p \cdot \mathbf{n}_{prev})$$

Where:
- $L$ is the computed loss [S1, unofficial].
- $w$ is the weight scalar [S1, unofficial].
- $\mathbf{n}_p$ is the normal at the current sample [S1, unofficial].
- $\mathbf{n}_{prev}$ is the normal at the previous sample along the ray [S1, unofficial].

**Parameters:**
- $w$: Float scalar multiplying the loss term. Typical value: 1.0 [S1, unofficial].

**Edge Cases and Pitfalls:**
- Requires tracking adjacent sample normals along a ray [S1, unofficial].
- This state is not natively supported by standard differentiable volume rendering integrators, which typically process samples independently or only accumulate opacity/color [S1, unofficial].
- Implementation requires modifying the integrator loop to store the previous sample's normal, which may not be available in off-the-shelf libraries [S1, unofficial].
- If normals are not normalized, the dot product range varies, affecting the loss magnitude. Normals should be normalized before computation [G].

**Pseudocode:**
```python
import math

def dot(a, b):
    return sum(x * y for x, y in zip(a, b))

def norm(v):
    return math.sqrt(sum(x * x for x in v))

def normal_smoothness_loss(n_p, n_prev, weight=1.0):
    """
    Compute normal smoothness loss between consecutive samples along a ray.
    
    Args:
        n_p: Sequence of 3 floats, normal at current sample.
        n_prev: Sequence of 3 floats, normal at previous sample.
        weight: Float, scalar weight for the loss.
        
    Returns:
        Float, scalar loss.
    """
    # Ensure normals are normalized to prevent scale issues
    n_p = [x / norm(n_p) for x in n_p]
    n_prev = [x / norm(n_prev) for x in n_prev]
    
    # Compute dot product
    d = dot(n_p, n_prev)
    
    # Compute loss: 1 - dot_product
    loss = 1.0 - d
    
    # Scale by weight
    loss = weight * loss
    
    return loss
```
## Subtopics

### Jacobian-based Normal Regularization
A regularization term that uses the Jacobian of the map of normals to regularize scene geometry, derived from differential geometry principles [S2, unofficial]. It computes the Frobenius norm of the Jacobian of the projected normal map $\tilde{n}$, defined as $L_{normals} = \sum \|\tilde{n}(x, y)\|_F^2$ [S2, unofficial]. This approach is significantly slower than depth regularization, processing ~1100 rays/s compared to ~5000 rays/s for depth regularization on NVIDIA V100 hardware [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Not explicitly given for the basic dot-product version [S1, unofficial]. Jacobian-based variants are much slower than depth regularization [S2, unofficial].
- **Memory Complexity:** Requires tracking adjacent sample normals along a ray, which is not natively supported by standard integrators and currently remains a placeholder for future implementation [S1, unofficial].
- **Performance:** Jacobian-based normal regularization processes ~1100 rays/s on NVIDIA V100, compared to ~5000 rays/s for depth regularization [S2, unofficial].
- **Strengths:** Enforces local geometric smoothness by encouraging consecutive normals along a ray to be similar [S1, unofficial].
- **Limitations:** Requires custom integrator modifications to track previous normals, as standard differentiable renderers do not expose this state natively [S1, unofficial]. Jacobian-based variants are computationally expensive [S2, unofficial].
- **When to use:** When surface smoothness is critical and computational budget allows for custom integrator changes or slower Jacobian-based methods [S1, unofficial][S2, unofficial].
- **When not to use:** When using standard off-the-shelf differentiable renderers that do not expose previous sample normals [S1, unofficial].
## Background
The basic form is described in the `tlir` codebase [S1, unofficial]. The Jacobian-based differential geometry formulation is detailed in "Regularization of NeRFs using differential geometry" [S2, unofficial].
