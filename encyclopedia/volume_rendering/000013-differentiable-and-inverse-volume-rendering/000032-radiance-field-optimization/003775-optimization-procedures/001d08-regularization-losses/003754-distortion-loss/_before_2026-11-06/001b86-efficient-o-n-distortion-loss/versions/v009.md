# Efficient O(N) Distortion Loss

Also called: Distortion Regularizer, Linear-time Distortion Loss, MipNeRF360 Distortion Loss, O(N) Distortion Loss

## Overview
The Efficient O(N) Distortion Loss is a regularization term used in differentiable volume rendering to suppress "floaters" (small, disconnected regions of volumetrically dense space) and "background collapse" (distant surfaces incorrectly modeled as semi-transparent clouds close to the camera) [S1]. It minimizes the integral of distances between all pairs of points along the 1D step function parameterized by ray distances and weights [S1]. Unlike NeRF's noise injection regularizer, which partially eliminates these artifacts while reducing reconstruction quality, the distortion loss more effectively prevents these issues without degrading detail [S1]. The "Efficient O(N)" variant specifically addresses the computational bottleneck of the original $O(N^2)$ formulation, enabling its use with high sample counts (e.g., >256 points per ray) typical in point-based or voxel-based queries [S2, unofficial].

## How it works
The method computes a regularization loss based on the normalized ray distances $\mathbf{s}$ and the accumulated weights $\mathbf{w}$ for each ray.

### Inputs and Outputs
*   **Inputs**:
    *   $\mathbf{s}$: Array of normalized ray distances for $N$ samples per ray, shape $(N,)$ or $(B, N)$ for batched rays. Values are non-linearly normalized from near-far clipping distances to $[0, 1]$ [S1][S2, unofficial].
    *   $\mathbf{w}$: Array of weights for $N$ samples per ray, shape $(N,)$ or $(B, N)$. Weights are non-negative and sum to $\le 1$ [S1].
    *   $\lambda_{\text{dist}}$: Scalar hyperparameter balancing the distortion loss against the reconstruction loss [S1][S3, unofficial].
*   **Outputs**:
    *   $\mathcal{L}_{\text{dist}}$: The scalar distortion loss value.
    *   $\nabla_{\mathbf{w}} \mathcal{L}_{\text{dist}}$: The gradient of the loss with respect to the weights, required for backpropagation [S2, unofficial].

### Data Structures
The implementation requires storing prefix and suffix sums to achieve linear time complexity. For a ray with $N$ samples:
*   `prefix_w`: Array of size $N+1$, where `prefix_w[k]` = $\sum_{j=0}^{k-1} w_j$.
*   `prefix_wm`: Array of size $N+1$, where `prefix_wm[k]` = $\sum_{j=0}^{k-1} w_j m_j$.
*   `suffix_w`: Array of size $N+1$, where `suffix_w[k]` = $\sum_{i=k}^{N-1} w_i$.
*   `suffix_wm`: Array of size $N+1$, where `suffix_wm[k]` = $\sum_{i=k}^{N-1} w_i m_i$.

### Steps
1.  **Compute Midpoints**: For each sample $i \in [0, N-1]$, compute the midpoint $m_i$ of the interval $[s_i, s_{i+1}]$:
    $$ m_i = \frac{s_i + s_{i+1}}{2} $$
    Ensure $m_i < m_{i+1}$ [S2, unofficial].

2.  **Compute Prefix and Suffix Sums**:
    *   Compute `prefix_w` and `prefix_wm` by iterating $k$ from $0$ to $N-1$:
        $$ \text{prefix\_w}[k+1] = \text{prefix\_w}[k] + w_k $$
        $$ \text{prefix\_wm}[k+1] = \text{prefix\_wm}[k] + w_k m_k $$
    *   Compute `suffix_w` and `suffix_wm` by iterating $k$ from $N-1$ down to $0$:
        $$ \text{suffix\_w}[k] = \text{suffix\_w}[k+1] + w_k $$
        $$ \text{suffix\_wm}[k] = \text{suffix\_wm}[k+1] + w_k m_k $$
    *   Initialize `prefix_w[0]`, `prefix_wm[0]`, `suffix_w[N]`, `suffix_wm[N]` to 0 [S2, unofficial].

3.  **Compute First Term ($\mathcal{L}_{\text{dist}}^{\text{1st}}$)**:
    The first term of the loss is defined as $\sum_{i=0}^{N-1} \sum_{j=0}^{N-1} w_i w_j |m_i - m_j|$. By eliminating the diagonal ($i=j$) and exploiting symmetry, this is rewritten as:
    $$ \mathcal{L}_{\text{dist}}^{\text{1st}} = 2 \sum_{i=1}^{N-1} w_i m_i \left( \sum_{j=0}^{i-1} w_j \right) - 2 \sum_{i=1}^{N-1} w_i \left( \sum_{j=0}^{i-1} w_j m_j \right) $$
    Using the precomputed prefix sums, this is computed in $O(N)$:
    $$ \mathcal{L}_{\text{dist}}^{\text{1st}} = 2 \sum_{i=1}^{N-1} \left( w_i m_i \cdot \text{prefix\_w}[i] - w_i \cdot \text{prefix\_wm}[i] \right) $$
    [S2, unofficial].

4.  **Compute Second Term ($\mathcal{L}_{\text{dist}}^{\text{2nd}}$)**:
    The second term minimizes the weighted size of each interval:
    $$ \mathcal{L}_{\text{dist}}^{\text{2nd}} = \frac{1}{3} \sum_{i=0}^{N-1} w_i^2 (s_{i+1} - s_i) $$
    [S1][S2, unofficial].

5.  **Combine Loss**:
    $$ \mathcal{L}_{\text{dist}} = \mathcal{L}_{\text{dist}}^{\text{1st}} + \mathcal{L}_{\text{dist}}^{\text{2nd}} $$
    [S1][S2, unofficial].

6.  **Compute Gradients ($\nabla_{\mathbf{w}} \mathcal{L}_{\text{dist}}$)**:
    The gradient with respect to a specific weight $w_k$ is derived from the first term (the second term's gradient is $\frac{2}{3} w_k (s_{k+1} - s_k)$) [S2, unofficial]:
    $$ \frac{\partial}{\partial w_k} \mathcal{L}_{\text{dist}}^{\text{1st}} = 2 m_k \sum_{j=0}^{k-1} w_j - 2 \sum_{j=0}^{k-1} w_j m_j + 2 \sum_{i=k+1}^{N-1} w_i m_i - 2 m_k \sum_{i=k+1}^{N-1} w_i $$
    Using prefix and suffix sums:
    $$ \frac{\partial}{\partial w_k} \mathcal{L}_{\text{dist}}^{\text{1st}} = 2 m_k \cdot \text{prefix\_w}[k] - 2 \cdot \text{prefix\_wm}[k] + 2 \cdot \text{suffix\_wm}[k+1] - 2 m_k \cdot \text{suffix\_w}[k+1] $$
    The total gradient is:
    $$ \frac{\partial \mathcal{L}_{\text{dist}}}{\partial w_k} = \frac{\partial}{\partial w_k} \mathcal{L}_{\text{dist}}^{\text{1st}} + \frac{2}{3} w_k (s_{k+1} - s_k) $$
    [S2, unofficial].

### Pseudocode
```python
def efficient_distortion_loss(s, w, lambda_dist):
    """
    Computes the O(N) distortion loss and its gradient with respect to w.
    
    Args:
        s: Tensor of shape (N,) or (B, N), normalized ray distances.
        w: Tensor of shape (N,) or (B, N), weights.
        lambda_dist: Scalar, weight for the distortion loss.
        
    Returns:
        loss: Scalar tensor, the total distortion loss.
        grad_w: Tensor of shape (N,) or (B, N), gradient of loss w.r.t w.
    """
    # Handle batch dimension if present
    if s.dim() == 1:
        s = s.unsqueeze(0)
        w = w.unsqueeze(0)
        batched = False
    else:
        batched = True
        
    B, N = s.shape
    device = s.device
    
    # 1. Compute midpoints m_i = (s_i + s_{i+1}) / 2
    # s has shape (B, N), so we need s_{i+1}. 
    # We assume s is sorted and represents interval boundaries.
    # m has shape (B, N-1) if we consider intervals, but the loss definition 
    # sums over samples i=0..N-1. The source defines m_i for interval i.
    # In the source, s_i is the distance of the i-th sample. 
    # The interval is [s_i, s_{i+1}]. So we need s up to N.
    # If s has N elements, we have N-1 intervals? 
    # Source [S2, unofficial] says "N sampled points... s_i is non-linearly normalized distance of i-th sample".
    # Eq 1 sums i=0 to N-1. This implies there are N intervals? 
    # Usually NeRF has N samples and N-1 intervals or N intervals with s_{N} = far.
    # Let's assume s has length N+1 or we pad s. 
    # However, standard NeRF outputs N weights for N samples. 
    # The source [S2, unofficial] code comment says "s_i is distance of i-th sample".
    # And "s_{i+1} - s_i is length". This implies s must have N+1 elements 
    # or we treat the last sample's interval differently.
    # Looking at [S1] Eq 15: sum i,j from 0 to N-1. 
    # If there are N samples, there are typically N-1 intervals between them.
    # But the source [S2, unofficial] explicitly writes sum i=0 to N-1 for both terms.
    # This implies s has N+1 elements (boundaries) or the last interval is defined.
    # Let's assume input s has shape (B, N+1) representing boundaries, 
    # and w has shape (B, N) representing weights for intervals?
    # Or s has shape (B, N) and we assume s_{N} is far?
    # Source [S2, unofficial] says "N sampled points... s_i is distance of i-th sample".
    # And "s_{i+1} - s_i". If i goes to N-1, we need s_N.
    # So s must have N+1 elements.
    
    # Check if s has N+1 elements. If not, we might need to pad or assume s is boundaries.
    # For implementation robustness, we assume s has shape (B, N+1) and w has (B, N).
    # If the caller provides N samples and N weights, they likely have N+1 boundaries.
    
    # Let's stick to the variable names in the source:
    # s: distances. w: weights.
    # If the input is N samples, we assume s has N+1 values.
    
    # 1. Midpoints
    # m_i = (s_i + s_{i+1}) / 2 for i in 0..N-1
    m = (s[:, :-1] + s[:, 1:]) / 2.0  # Shape (B, N)
    
    # 2. Prefix and Suffix Sums
    # prefix_w[k] = sum_{j=0}^{k-1} w_j
    # We need prefix sums for indices 0 to N.
    # w has shape (B, N).
    
    # Pad w with 0 at the beginning for prefix sum calculation
    w_padded = torch.cat([torch.zeros(B, 1, device=device), w], dim=1) # (B, N+1)
    prefix_w = torch.cumsum(w_padded[:, :-1], dim=1) # (B, N) -> prefix_w[k] is sum 0..k-1
    # Actually, cumsum gives sum 0..k. 
    # Let's do it manually or carefully.
    # prefix_w[k] = sum_{j=0}^{k-1} w_j.
    # prefix_w[0] = 0.
    # prefix_w[1] = w_0.
    # prefix_w[k] = prefix_w[k-1] + w_{k-1}.
    
    prefix_w = torch.zeros(B, N + 1, device=device)
    prefix_wm = torch.zeros(B, N + 1, device=device)
    
    for k in range(N):
        prefix_w[k+1] = prefix_w[k] + w[:, k]
        prefix_wm[k+1] = prefix_wm[k] + w[:, k] * m[:, k]
        
    # Suffix sums
    # suffix_w[k] = sum_{i=k}^{N-1} w_i
    # suffix_w[N] = 0.
    # suffix_w[k] = suffix_w[k+1] + w_k.
    
    suffix_w = torch.zeros(B, N + 1, device=device)
    suffix_wm = torch.zeros(B, N + 1, device=device)
    
    for k in range(N - 1, -1, -1):
        suffix_w[k] = suffix_w[k+1] + w[:, k]
        suffix_wm[k] = suffix_wm[k+1] + w[:, k] * m[:, k]
        
    # 3. First Term
    # L_dist_1st = 2 * sum_{i=1}^{N-1} ( w_i * m_i * prefix_w[i] - w_i * prefix_wm[i] )
    # Note: Source sums i=1 to N-1.
    # Indices for w, m, prefix are 0-based.
    # i in source formula corresponds to index i in arrays.
    # So we sum i from 1 to N-1.
    
    idx = torch.arange(1, N, device=device).unsqueeze(0) # (1, N-1)
    w_slice = w[:, 1:N] # (B, N-1)
    m_slice = m[:, 1:N] # (B, N-1)
    pw_slice = prefix_w[:, 1:N] # (B, N-1)
    pwm_slice = prefix_wm[:, 1:N] # (B, N-1)
    
    term1_part1 = 2.0 * (w_slice * m_slice * pw_slice)
    term1_part2 = 2.0 * (w_slice * pwm_slice)
    
    L_dist_1st = torch.sum(term1_part1 - term1_part2, dim=1) # (B,)
    
    # 4. Second Term
    # L_dist_2nd = 1/3 * sum_{i=0}^{N-1} w_i^2 * (s_{i+1} - s_i)
    # s has shape (B, N+1). Intervals are s[:, 1:] - s[:, :-1].
    interval_lengths = s[:, 1:] - s[:, :-1] # (B, N)
    L_dist_2nd = (1.0 / 3.0) * torch.sum(w**2 * interval_lengths, dim=1) # (B,)
    
    # 5. Total Loss
    L_dist = L_dist_1st + L_dist_2nd # (B,)
    
    # 6. Gradients
    # dL/dw_k for first term:
    # 2 * m_k * prefix_w[k] - 2 * prefix_wm[k] + 2 * suffix_wm[k+1] - 2 * m_k * suffix_w[k+1]
    
    grad_w_1st = (
        2.0 * m * prefix_w[:, :N] - 
        2.0 * prefix_wm[:, :N] + 
        2.0 * suffix_wm[:, 1:] - 
        2.0 * m * suffix_w[:, 1:]
    )
    
    # dL/dw_k for second term:
    # 2/3 * w_k * (s_{i+1} - s_i)
    grad_w_2nd = (2.0 / 3.0) * w * interval_lengths
    
    grad_w = grad_w_1st + grad_w_2nd
    
    if not batched:
        return L_dist.squeeze(0), grad_w.squeeze(0)
    return L_dist, grad_w
```

### Parameters
*   $\lambda_{\text{dist}}$: Hyperparameter balancing the data term and the regularizer. Typical value: 0.01 [S1].
*   $N$: Number of sampled points per ray. The efficient implementation supports uneven numbers of sampled points across different rays [S2, unofficial].

### Edge Cases and Pitfalls
*   **Normalization**: Using unnormalized ray distances $t$ instead of normalized $s$ significantly upweights distant intervals, causing nearby intervals to be effectively ignored [S1].
*   **Memory**: The naive $O(N^2)$ implementation consumes excessive GPU memory (e.g., >3GB for a batch of 4,096 rays with >256 samples per ray) [S2, unofficial].
*   **Diagonal Term**: The derivation of the $O(N)$ first term explicitly eliminates the diagonal term ($i=j$) where $|m_i - m_i| = 0$, which is crucial for the simplification [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(N)$ per ray, compared to $O(N^2)$ for the naive implementation [S2, unofficial].
*   **Memory Complexity**: $O(N)$ per ray for storing prefix/suffix sums, compared to $O(N^2)$ for storing the full pairwise distance matrix in the naive approach [S2, unofficial].
*   **Performance**: The efficient implementation allows for more than 256 sampled points per ray, which is common in point-based or voxel-based queries, without prohibitive memory costs [S2, unofficial]. It provides a 2–3× speedup when implemented as a CUDA extension [S2, unofficial].
*   **Strengths**: Effectively suppresses floaters and background collapse without reducing reconstruction quality, outperforming noise injection methods [S1]. Enables high-resolution sampling [S2, unofficial].
*   **Limitations**: Requires careful normalization of ray distances [S1]. The gradient computation is more complex than simple MSE [S2, unofficial].

## Background
The distortion loss was proposed in MipNeRF 360 to reduce artifacts such as floaters and background collapse [S1][S3, unofficial]. It was later optimized for linear time complexity by the authors of DirectVoxGO (DVGO) to support higher sample counts in point-based queries [S2, unofficial]. The loss is implemented efficiently in various open-source repositories, such as `torch_efficient_distloss` [S2, unofficial] and `instant-nsr-pl` [S3, unofficial].
