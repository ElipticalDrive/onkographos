# MSE Loss and PSNR Conversion

Also called: img2mse, MSE Loss, Mean Squared Error Loss, MSE (Mean Squared Error), Mean Squared Error (MSE)

## Overview
The Mean Squared Error (MSE) loss computes the average of the squared differences between predicted and target RGB values, serving as the primary photometric reconstruction loss for training neural volume rendering models [S1, unofficial][S2, unofficial][S4, unofficial]. It is often converted to Peak Signal-to-Noise Ratio (PSNR) for logging, providing a logarithmic measure of fidelity where higher values indicate better reconstruction quality [S1, unofficial][S2, unofficial]. Unlike structural metrics such as SSIM, MSE treats all pixel errors equally and is sensitive to large smooth regions but less responsive to high-frequency details [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Predicted RGB tensor $x$ (shape: $[B, H, W, 3]$ or flattened $[N, 3]$) and Target RGB tensor $y$ (same shape and data type, typically normalized to $[0, 1]$).
- **Outputs:** Scalar MSE value and, optionally, the corresponding PSNR value.

**Data Structures:**
- Tensors $x$ and $y$ are dense floating-point arrays. No special bit-packing is required beyond standard IEEE 754 single or double precision.

**Steps:**
1. **Compute Element-wise Difference:** Calculate the difference between predicted and target values: $d = x - y$.
2. **Square the Difference:** Square each element of the difference tensor: $s = d^2$.
3. **Flatten Spatial Dimensions:** Reshape the tensor to shape $[B, -1]$ to flatten height and width dimensions, keeping the batch dimension.
4. **Compute Mean:** Calculate the mean of the squared differences over the flattened spatial dimension (dimension 1) to obtain the MSE.
   $$
   MSE = \frac{1}{N} \sum_{i=1}^{N} (x_i - y_i)^2
   $$
   where $N$ is the total number of pixels (or voxels) in the batch.
5. **Convert to PSNR (Optional):** Calculate PSNR from the MSE.
   $$
   PSNR = -10 \cdot \log_{10}(MSE)
   $$
   Alternatively, using the square root form:
   $$
   PSNR = 20 \cdot \log_{10}\left(\frac{1}{\sqrt{MSE}}\right)
   $$
   If $MSE = 0$, PSNR is defined as $\infty$ [S5, unofficial].

**Pseudocode:**
```python
import math
import torch

def img2mse(x: torch.Tensor, y: torch.Tensor) -> torch.Tensor:
    """
    Compute Mean Squared Error between predicted (x) and target (y) RGB values.
    
    Args:
        x: Predicted RGB tensor of shape (..., 3) or (batch, H, W, 3).
        y: Target RGB tensor of the same shape as x.
        
    Returns:
        Scalar MSE value.
    """
    # 1. Compute element-wise difference
    diff = x - y
    
    # 2. Square the difference
    sq_diff = diff ** 2
    
    # 3. Flatten spatial dimensions and compute mean
    # Reshape to (batch_size, -1) to flatten H, W, C (if C=3, it's included in -1)
    # However, standard MSE usually averages over all elements including channels.
    # The source [S3, unofficial] specifies flattening spatial dimensions and averaging over batch dim 1.
    # Assuming input is (B, H, W, 3), we flatten H, W, 3 into one dimension.
    batch_size = x.shape[0]
    flattened = sq_diff.reshape(batch_size, -1)
    
    # 4. Compute mean along dimension 1 (flattened spatial)
    mse = torch.mean(flattened, dim=1)
    
    # If a single scalar is needed for the whole batch, take mean of the batch means
    # Or sum if treating as total loss. Standard implementation [S1, unofficial] uses reduce_mean over all dims.
    # Let's align with [S1, unofficial] tf.reduce_mean which averages over ALL dimensions.
    mse_scalar = torch.mean(sq_diff)
    
    return mse_scalar

def mse2psnr(mse: torch.Tensor) -> torch.Tensor:
    """
    Convert MSE to PSNR.
    
    Args:
        mse: Mean Squared Error tensor (scalar or array).
        
    Returns:
        PSNR tensor.
    """
    # Handle zero MSE to avoid log(0)
    # If mse is 0, psnr is infinity.
    # In practice, add a small epsilon or handle explicitly.
    # Source [S1, unofficial] uses -10 * log10(mse).
    # Source [S5, unofficial] uses 20 * log10(1/sqrt(mse)) if mse > 0 else inf.
    
    # Using the standard formula derived from [S1, unofficial] and [S5, unofficial]
    # PSNR = -10 * log10(MSE)
    
    # Guard against division by zero / log(0)
    # [G] Standard practice is to clamp MSE to a small positive value or return inf.
    # Here we follow [S5, unofficial] logic: if mse is 0, return inf.
    
    # Note: torch.log10 requires positive input.
    # We can use a small epsilon for numerical stability if not strictly inf.
    # However, to be precise to sources:
    
    if mse == 0:
        return torch.tensor(float('inf'), device=mse.device)
    
    psnr = -10.0 * torch.log10(mse)
    return psnr
```

**Parameters:**
- **Batch Size:** Number of random pixels sampled per iteration [S4, unofficial].
- **Learning Rate:** Adam optimizer learning rate, typically from configuration (e.g., `cfg.training.lr`) [S4, unofficial].

**Edge Cases and Pitfalls:**
- **Zero MSE:** If the predicted image perfectly matches the target, MSE is 0. The logarithm in PSNR calculation is undefined. The implementation must handle this by returning infinity or a large constant [S5, unofficial].
- **Empty Mask:** When using masked MSE (e.g., for volume rendering where only occupied voxels matter), if the boolean mask has no true values, a `RuntimeError` should be raised [S5, unofficial].
- **Precision:** Use floating-point precision (FP32 or FP64) to avoid overflow when squaring differences, especially if inputs are not normalized to $[0, 1]$ [S6, unofficial].

## Subtopics

### [PSNR Metric Calculation](2742-psnr-metric-calculation.md)
Peak Signal-to-Noise Ratio (PSNR) evaluates the quality of reconstructed images in novel view synthesis and volume rendering by comparing rendered output against ground-truth reference images. It quantifies the logarithmic ratio between the maximum possible pixel intensity and the Mean Squared Error (MSE) between the two images, providing a single scalar value where higher indicates better fidelity. Unlike structural metrics such as SSIM, PSNR measures pixel-level photometric error averaged over the entire frame, making it sensitive to large smooth regions but less responsive to small, high-frequency details like specular highlights.

### [SSIM Metric Calculation](3650-ssim-metric-calculation.md)
The Structural Similarity Index (SSIM) measures the perceived distortion between a rendered image and a ground truth image by comparing local patterns of pixel intensities, assuming the human visual system is highly adapted to structured natural scene information. It serves as a standard benchmark for image quality in radiance-field optimization, complementing pixel-wise metrics like MSE and PSNR. Unlike MSE, which treats all errors equally, SSIM accounts for luminance, contrast, and structural correlations, providing a value between -1 and 1 where 1 indicates identical images.

### [Normal-L2 Score Computation](3842-normal-l2-score-computation.md)
The Normal-L2 score evaluates surface geometry by computing the mean squared L2 distance between predicted surface normals and reference normals from a ground-truth mesh. It is computed only on the intersection of predicted and ground-truth masks, distinguishing it from silhouette metrics like iIoU which evaluate mask alignment separately.

### [Minkowski's Metric](4347-minkowski-s-metric.md)
Minkowski's Metric is a full-reference mathematical distance measure that treats images as 2D signals to quantify dissimilarity between a reference image $x$ and a test image $y$. It generalizes the Mean Squared Error (MSE) by allowing the exponent $\gamma$ to vary, thereby controlling the sensitivity to large errors versus small errors. Unlike its sibling [PSNR Metric Calculation](2742-psnr-metric-calculation.md) which is a logarithmic transformation of MSE, or [SSIM Metric Calculation](3650-ssim-metric-calculation.md) which models structural information, Minkowski's Metric operates directly on pixel-wise intensity differences.

### Masked Volume Metrics
A method to exclude empty froxels from evaluation metrics by including only froxels affected by radiance [S7, unofficial]. A froxel is included if any of its RGB channels contain a non-zero value at any point during the test scenario [S7, unofficial]. The Region of Interest (ROI) is computed separately for each tested algorithm; the union of the scenario's ROI and the ground truth's ROI is used to create an effective ROI, ensuring only relevant froxels are included while excluding completely empty regions [S7, unofficial].
$$
ROI_{effective} = ROI_{scenario} \cup ROI_{truth}
$$
Masked MSE is calculated as the mean of squared errors over voxels in the mask:
$$
MSE = \frac{1}{N} \sum_{i \in mask} (v_{ref, i} - v_{comp, i})^2
$$
where $N$ is the number of voxels in the mask [S5, unofficial]. Masked PSNR is calculated as:
$$
PSNR = 20 \cdot \log_{10}\left(\frac{1}{\sqrt{MSE}}\right)
$$
if $MSE > 0$, otherwise $PSNR = \infty$ [S5, unofficial].

### MSE Bias-Variance Decomposition
Treating the TAA algorithm as a biased estimator to analyze correctness using Mean Squared Error (MSE), decomposed into variance and bias squared [S7, unofficial].
$$
MSE[F] = \mathbb{E}[(F - G)^2] = V[F] + \beta[F]^2
$$
where $F$ is the output of the estimator, $G$ is the true value (ground truth), $V[F]$ is the variance of the estimator, and $\beta[F]$ is its bias [S7, unofficial].

### Training Loss Computation with Huber and Masking
In some implementations, Huber loss is used instead of MSE for robustness, combined with masking [S8, unofficial].
1. Render predicted RGB and depth values.
2. Split predicted RGBD tensor into RGB and depth.
3. Blend ground truth RGB with background to match rendering conditions.
4. Compute per-ray Huber loss for RGB with delta=0.1, masked by `ray_is_valid`, and averaged over valid rays:
   $$
   loss_{rgb} = \frac{\sum_{i \in valid} \text{Huber}(pred\_rgbs_i, gt\_rgbs_i, \delta=0.1)}{n_{valid\_rays}}
   $$
5. Aggregate loss components [S8, unofficial].

### Area Loss Scaling
Scaling the loss of each pixel by the area of that pixel's footprint in the original image to ensure low-resolution pixels have comparable influence to high-resolution pixels in multiscale datasets [S9]. For a downsampling factor of $k$, the area scaling factor is $k^2$ [S9].

### IoU Loss
A binary segmentation loss metric that computes the ratio of overlapping voxels above a threshold to the total union of predicted and target voxels [S10, unofficial].
$$
\text{IoU} = \frac{|\{v \mid \hat{v} > \tau\} \cap \{v \mid t_v > 0\}|}{|\{v \mid \hat{v} > \tau\} \cup \{v \mid t_v > 0\}|}
$$
where $\tau$ is the prediction threshold for binarization, default 0.9 [S10, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of pixels or voxels being compared. The operation is element-wise and parallelizable on GPUs.
- **Memory Complexity:** $O(N)$ to store the difference and squared difference tensors during computation, though optimized implementations can compute the sum in-place or in streaming fashion to reduce memory to $O(1)$ auxiliary space.
- **Measured Performance:** MSE is extremely fast to compute and backpropagate, making it suitable for high-frequency updates during training [S4, unofficial]. PSNR calculation is $O(1)$ given the MSE.
- **Strengths:** Simple to implement, differentiable everywhere, and provides a direct measure of pixel-wise accuracy [S2, unofficial].
- **Limitations:** Does not account for structural information or perceptual quality, often leading to blurry results in optimization [S1, unofficial]. Sensitive to outliers.
- **When to Use:** Standard photometric loss for training neural radiance fields when structural fidelity is less critical than pixel-wise accuracy, or as a baseline metric [S4, unofficial].
- **When Not to Use:** When perceptual quality is paramount (use Perceptual Loss [2000-perceptual-loss-training.md]) or when structural similarity is important (use SSIM [3650-ssim-metric-calculation.md]).

## Background
The Mean Squared Error loss is a fundamental metric in signal processing and image reconstruction, widely adopted in neural volume rendering for its simplicity and differentiability [S1, unofficial][S4, unofficial]. It was prominently used in the original NeRF paper and subsequent implementations [S1, unofficial][S2, unofficial]. The conversion to PSNR is a standard practice for reporting results in the field, allowing for comparison across different scenes and resolutions [S1, unofficial][S4, unofficial].
