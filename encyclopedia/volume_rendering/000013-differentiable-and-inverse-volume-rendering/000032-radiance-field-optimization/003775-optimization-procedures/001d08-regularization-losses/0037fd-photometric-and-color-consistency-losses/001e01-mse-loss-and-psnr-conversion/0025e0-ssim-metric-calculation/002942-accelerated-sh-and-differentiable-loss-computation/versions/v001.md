# Accelerated SH and Differentiable Loss Computation

Also called: Batched SH updates, Separable SSIM convolution

## Overview
This method optimizes the training loop of 3D Gaussian Splatting (3DGS) by reducing the computational bottleneck of Adam optimizer updates for Spherical Harmonic (SH) coefficients and accelerating the differentiable SSIM loss calculation. It addresses the disproportionate time spent on SH updates as the number of Gaussians increases and reduces memory traffic in loss computation. It sets itself apart from standard 3DGS implementations by decoupling SH band updates and fusing loss kernel operations.

## How it works
The method consists of two primary optimizations: a batched update schedule for SH coefficients and accelerated differentiable loss computation via separable convolutions and fused kernels.

### Inputs and Outputs
- **Inputs**: Rendered image, ground truth image, Gaussian attributes (position, rotation, scale, opacity, SH coefficients), Adam optimizer state.
- **Outputs**: Updated Gaussian attributes, computed loss value.

### Data Structures
1.  **SH Coefficients**: Stored in separate tensors for the 0th band (base color) and higher bands (1st–5th), rather than a single combined tensor. This avoids the overhead of combining tensors before rasterization [S1].
2.  **Adam State**: Separate optimizer states for base color (0th band), higher SH bands, and opacity.

### Steps

1.  **SH Update Schedule**:
    -   The 0th SH band (base color) is updated every iteration using the Adam optimizer.
    -   All higher SH bands (1st through 5th) are updated using a batched schedule: Adam optimization steps are performed only once every 16 iterations [S1].
    -   The learning rate for the batched SH updates is increased fourfold to $0.001$ [S1].
    -   The opacity learning rate is reduced by half to $0.025$ [S1].

2.  **Differentiable SSIM Loss Computation**:
    -   **Separable Convolution**: The 11×11 Gaussian kernel used for SSIM is separable. The 2D convolution is performed via two consecutive 1D convolutions using optimized CUDA kernels [S1].
    -   **Fused Kernel**: A fused CUDA kernel evaluates the SSIM metric from the convolved results, reducing memory traffic and launch overhead [S1].
    -   **3D Extension (Variant)**: For 3D SSIM loss, a fused CUDA kernel processes the depth dimension using a ring buffer, with each thread operating on a single Z-axis row to avoid excessive shared memory usage [S2, unofficial].

### Pseudocode

```python
def update_gaussians(gaussians, optimizer_state, rendered_image, gt_image, iteration):
    """
    Updates Gaussian attributes using accelerated SH and loss computation.
    """
    # 1. Compute Loss with Accelerated SSIM
    # Perform separable 1D convolutions for SSIM kernel
    local_means_rendered = separable_1d_conv(rendered_image, kernel_size=11)
    local_means_gt = separable_1d_conv(gt_image, kernel_size=11)
    
    # Compute variances and covariance within sliding windows
    local_vars_rendered = compute_local_variance(rendered_image, local_means_rendered)
    local_vars_gt = compute_local_variance(gt_image, local_means_gt)
    local_cov = compute_local_covariance(rendered_image, gt_image, local_means_rendered, local_means_gt)
    
    # Fused kernel for SSIM metric evaluation
    ssim_map = fused_ssim_kernel(local_means_rendered, local_means_gt, 
                                 local_vars_rendered, local_vars_gt, 
                                 local_cov, C1=0.01**2, C2=0.03**2)
    loss_ssim = torch.mean(1 - ssim_map)
    
    # Total loss (assuming MSE component exists)
    loss_mse = torch.mean((rendered_image - gt_image)**2)
    loss = loss_mse + 0.2 * loss_ssim # Weight from standard 3DGS
    
    # 2. Backpropagation
    gradients = torch.autograd.grad(loss, gaussians.attributes, retain_graph=True)
    
    # 3. Optimizer Step
    # Base color (0th SH band) and Opacity: Update every iteration
    optimizer_state['base_color'].step(gradients['base_color'], lr=0.00025) # Standard LR
    optimizer_state['opacity'].step(gradients['opacity'], lr=0.025)        # Reduced LR
    
    # Higher SH bands: Update every 16th iteration
    if iteration % 16 == 0:
        optimizer_state['higher_sh'].step(gradients['higher_sh'], lr=0.001) # Increased LR
    else:
        # No update for higher SH bands in this step
        pass
        
    return loss
```

### Parameters
-   **SH Update Interval**: 16 iterations for bands > 0 [S1].
-   **SH Learning Rate**: 0.001 for batched updates [S1].
-   **Opacity Learning Rate**: 0.025 [S1].
-   **SSIM Kernel Size**: 11×11 Gaussian kernel [S1].

### Edge Cases and Pitfalls
-   **Precision**: Fused kernels may introduce slight numerical differences compared to standard PyTorch operations due to reduced intermediate memory writes [S2, unofficial].
-   **Memory**: The 3D SSIM variant uses a ring buffer to manage shared memory; insufficient buffer size may cause incorrect depth processing [S2, unofficial].
-   **Degenerate Input**: If the number of Gaussians is very low, the overhead of kernel launches may dominate; however, the method is particularly impactful in this regime [S1].

## Subtopics

### Fused Loss Kernels
Replaces standard 2D/3D SSIM and Total Variation (TV) loss calculations with custom fused CUDA kernels. For 2D SSIM, it uses the `fused-ssim` implementation, achieving 5–8x acceleration [S2, unofficial]. For 3D SSIM, it processes the depth dimension with a ring buffer to avoid excessive shared memory, achieving 11x acceleration [S2, unofficial]. It also implements a custom fused kernel for 3D TV loss, achieving 3x acceleration for a $32^3$ volume [S2, unofficial].

## Operating characteristics
-   **Time Complexity**: Reduces the dominant cost of Adam updates for SH coefficients by skipping 15 out of 16 iterations for higher bands. Accelerates SSIM loss computation by 5–8x (2D) and 11x (3D) [S1][S2, unofficial].
-   **Memory Complexity**: Reduces memory traffic by fusing operations and avoiding intermediate tensor allocations for SSIM [S1][S2, unofficial].
-   **Performance**: Significant reduction in training time, especially when the number of optimized Gaussians is low compared to image resolution [S1].
-   **Strengths**: Effective for budget-constrained training scenarios; scalable to large Gaussian counts.
-   **Limitations**: Requires custom CUDA kernels; may introduce minor numerical differences.
-   **When to Use**: When training time is a bottleneck, particularly for high-quality radiance fields with limited resources [S1].
-   **When Not to Use**: When exact numerical reproducibility with standard PyTorch operations is required, or when hardware lacks efficient CUDA support.

## Background
Originated from the "Taming 3DGS" paper [S1] and "FaCT-GS" [S2, unofficial], addressing the computational inefficiencies of the original 3DGS implementation [Kerbl et al. 2023]. The original 3DGS implementation combined SH bands into a single tensor and used standard convolution for SSIM, leading to significant overhead. These optimizations were introduced to make high-quality radiance field reconstruction feasible with limited resources and hardware.
