# Frequency Regularization
Also called: FreGS
## Overview
Frequency regularization is a technique used in 3D Gaussian Splatting (3DGS) training to mitigate the "blurriness" and low-frequency artifacts common in standard photometric optimization. It solves the problem where Gaussians tend to over-smooth scene details by penalizing low-frequency variations in the scene representation, thereby encouraging Gaussians to concentrate in high-frequency detail regions [S1, unofficial]. Unlike depth or normal regularization which constrain geometric consistency, frequency regularization operates in the spectral domain to enhance edge sharpness and texture fidelity.

## How it works
**Inputs and Outputs:**
- **Input:** The rendered image $I_{render}$, the ground truth image $I_{gt}$, and the standard photometric loss $\mathcal{L}_{rgb}$.
- **Output:** An augmented loss function $\mathcal{L}_{total}$ that guides the optimization of Gaussian parameters $\theta = \{\mathbf{x}, \mathbf{s}, \mathbf{r}, \alpha, \mathbf{c}\}$.

**Data Structures:**
- **Frequency Domain Representation:** The rendered image is transformed into the frequency domain. While the specific transform is not detailed in the primary FreGS source [S1, unofficial], related methods like DWTGS use the Discrete Wavelet Transform (DWT) [S2, unofficial].

**Method Steps:**
1. **Render Image:** Generate the rendered image $I_{render}$ using the current set of 3D Gaussians.
2. **Transform to Frequency Domain:** Apply a frequency transform (e.g., Fourier or Wavelet) to $I_{render}$ to obtain frequency coefficients $F(I_{render})$. [G: For implementation, a 2D Fast Fourier Transform (FFT) or Discrete Wavelet Transform (DWT) is standard. DWT is explicitly cited for variants like DWTGS].
3. **Compute Frequency Loss:** Calculate a penalty term based on the low-frequency components. The goal is to suppress energy in low frequencies or encourage high-frequency content. The loss $\mathcal{L}_{freq}$ is typically defined as the difference or norm of low-frequency coefficients between the rendered and ground truth images, or a penalty on the low-frequency energy of the rendered image itself to prevent over-smoothing. [G: A common implementation is to minimize the $L_1$ or $L_2$ distance between the low-pass filtered versions of $I_{render}$ and $I_{gt}$, or to penalize the magnitude of low-frequency coefficients in $I_{render}$ if they deviate from $I_{gt}$].
4. **Augment Loss:** Combine the frequency loss with the standard photometric loss:
   $$ \mathcal{L}_{total} = \mathcal{L}_{rgb} + \lambda_{freq} \mathcal{L}_{freq} $$
   where $\lambda_{freq}$ is a weighting parameter. [G: Typical values for $\lambda_{freq}$ are small, e.g., $0.1$ to $1.0$, to avoid destabilizing the primary photometric gradient].
5. **Backpropagate:** Compute gradients with respect to Gaussian parameters and update them.

**Parameters:**
- $\lambda_{freq}$: Weight for the frequency regularization term. Not given in the sources. [G: Start with $0.1$ and tune based on visual sharpness].

**Edge Cases and Pitfalls:**
- **Precision:** High-frequency components are sensitive to noise. Ensure numerical stability in the frequency transform.
- **Boundaries:** Edge effects in transforms (e.g., FFT) may introduce artifacts. Use appropriate padding or windowing functions. [G: Zero-padding or symmetric padding is common].
- **Degenerate Input:** If the scene is inherently low-frequency (e.g., a plain color wall), frequency regularization may have minimal effect or introduce unnecessary noise.

**Pseudocode:**
```python
def compute_frequency_regularization_loss(rendered_image, gt_image, lambda_freq, transform_type='dwt'):
    """
    Computes the frequency regularization loss.
    
    Args:
        rendered_image: Tensor of shape (H, W, 3), rendered RGB image.
        gt_image: Tensor of shape (H, W, 3), ground truth RGB image.
        lambda_freq: Float, weight for frequency loss.
        transform_type: String, 'dwt' for Discrete Wavelet Transform, 'fft' for Fourier.
        
    Returns:
        Float, the total augmented loss.
    """
    # Standard photometric loss
    l_rgb = torch.mean(torch.abs(rendered_image - gt_image))
    
    # Frequency transform
    if transform_type == 'dwt':
        # Apply DWT to get low-frequency (LL) and high-frequency components
        # Note: PyWavelets (pywt) is a common library, but we write out the logic
        # For simplicity, assume a function that returns low-pass filtered image
        rendered_low_freq = apply_low_pass_filter(rendered_image)
        gt_low_freq = apply_low_pass_filter(gt_image)
    elif transform_type == 'fft':
        # Apply FFT and zero out high frequencies
        rendered_fft = torch.fft.fft2(rendered_image)
        gt_fft = torch.fft.fft2(gt_image)
        # Create a mask to keep only low frequencies (e.g., center 25%)
        mask = create_low_pass_mask(rendered_fft.shape)
        rendered_low_freq = torch.real(torch.fft.ifft2(rendered_fft * mask))
        gt_low_freq = torch.real(torch.fft.ifft2(gt_fft * mask))
    else:
        raise ValueError("Unsupported transform type")
        
    # Compute frequency loss (e.g., L1 distance between low-frequency components)
    l_freq = torch.mean(torch.abs(rendered_low_freq - gt_low_freq))
    
    # Total loss
    total_loss = l_rgb + lambda_freq * l_freq
    
    return total_loss

def apply_low_pass_filter(image):
    """
    Applies a low-pass filter to the image.
    For DWT, this would be the LL subband.
    For simplicity, we use a Gaussian blur as an approximation of low-frequency content.
    """
    # Gaussian blur kernel
    kernel_size = 5
    sigma = 1.0
    kernel = create_gaussian_kernel(kernel_size, sigma)
    # Apply convolution
    filtered_image = torch.nn.functional.conv2d(image.permute(2, 0, 1).unsqueeze(0), kernel, padding=2).squeeze()
    return filtered_image.permute(1, 2, 0)

def create_gaussian_kernel(size, sigma):
    """Creates a 2D Gaussian kernel."""
    coords = torch.arange(size) - size // 2
    x, y = torch.meshgrid(coords, coords, indexing='ij')
    kernel = torch.exp(-(x**2 + y**2) / (2 * sigma**2))
    kernel = kernel / kernel.sum()
    return kernel.unsqueeze(0).unsqueeze(0)

def create_low_pass_mask(shape):
    """Creates a mask to keep low frequencies in the center."""
    h, w = shape
    mask = torch.zeros(h, w)
    center_h, center_w = h // 2, w // 2
    radius = min(h, w) // 4
    y, x = torch.ogrid[:h, :w]
    mask[(y - center_h)**2 + (x - center_w)**2 <= radius**2] = 1.0
    return mask
```

## Subtopics

### DWTGS
DWTGS is a variant that rethinks frequency regularization for sparse-view 3DGS. It applies a Discrete Wavelet Transform (DWT) on the rendered image and penalizes the loss in the wavelet domain to encourage sharper edges [S2, unofficial]. It is chosen when working with sparse input views where standard frequency regularization may not be sufficient to recover high-frequency details.

## Operating characteristics
**Time and Memory Complexity:**
- **Time:** Adding frequency regularization increases training time due to the additional transform and loss computation. The complexity depends on the transform: FFT is $O(N \log N)$, DWT is $O(N)$ for an image of $N$ pixels. [G: In practice, the overhead is small compared to the rasterization step].
- **Memory:** Requires storing intermediate frequency coefficients. For FFT, this is $O(N)$ complex numbers. For DWT, it is $O(N)$ real numbers. [G: Memory overhead is negligible for typical image resolutions].

**Measured Performance:**
- Not given in the sources. [G: DWTGS is reported to improve edge sharpness in sparse-view scenarios].

**Scaling:**
- Scales linearly with image resolution for FFT/DWT.

**Strengths and Limitations:**
- **Strengths:** Reduces blurriness, enhances high-frequency details, improves mesh extraction quality by encouraging sharper boundaries.
- **Limitations:** May introduce noise if not tuned properly; sensitive to the choice of transform and low-frequency cutoff.

**When to Use:**
- Use when the rendered images appear blurry or lack sharp edges.
- Use in sparse-view scenarios where detail recovery is challenging.

**When Not to Use:**
- Avoid if the scene is inherently smooth or low-frequency.
- Avoid if computational resources are extremely limited and the overhead is prohibitive.

## Background
Frequency regularization in the context of 3D Gaussian Splatting was introduced to address the tendency of Gaussians to over-smooth scene details during optimization. It is part of a broader effort to improve the geometric and photometric quality of 3DGS reconstructions. The method is cited in unofficial surveys and cheat sheets summarizing state-of-the-art 3DGS variants [S1, unofficial]. Variants like DWTGS extend this concept to sparse-view settings using wavelet transforms [S2, unofficial].
