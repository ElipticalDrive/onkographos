# RoofGS

Also called: Roofline-Guided End-to-End Acceleration of 3D Gaussian Splatting

## Overview
RoofGS is an end-to-end acceleration method for 3D Gaussian Splatting (3DGS) that optimizes the rendering pipeline by aligning software strategies with hardware bottlenecks identified via the Roofline model [S1, unofficial]. It solves the problem of uncoordinated optimization in 3DGS, where different stages are constrained by different resources (memory bandwidth vs. compute throughput) [S1, unofficial]. It sets itself apart from generic optimization by explicitly using the Roofline model to identify the "knee" point and applying memory-centric optimizations to stages below it and compute-centric optimizations to stages near it [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D Gaussian primitives (position, covariance, opacity, spherical harmonic coefficients), camera parameters, image resolution.
*   **Output:** Rendered image with alpha-composited colors.

**Data Structures:**
*   **Gaussian Attributes:** Compressed low-bit representation of Spherical Harmonic (SH) coefficients. Standard 3rd-degree SH requires 48 coefficients per RGB channel (192 bytes in single precision for $D_{SH}=3$) [S1, unofficial]. RoofGS uses quantization with a single shared scale [S1, unofficial].
*   **Depth Keys:** Compressed radix-sort keys for depth sorting.
*   **Rasterizer State:** Reorganized to support dual-pixel processing.

**Core Optimizations:**
The method implements four core optimizations: front-end fusion, compact attribute storage, compressed radix-sort keys, and a reorganized rasterizer with dual-pixel ILP and fast exponential evaluation [S1, unofficial].

1.  **Memory-Bound Optimization (Front-End):**
    *   **Compact Attribute Storage:** Reduces global memory traffic by quantizing SH coefficients. Instead of streaming full-precision attributes, a single shared scale is used for quantization [S1, unofficial].
    *   **Dynamic Depth-Key Compression:** Compresses the keys used in the radix sort stage to reduce memory bandwidth usage during sorting [S1, unofficial].
    *   **Cross-Stage Kernel Fusion:** Fuses kernels in the front-end to reduce intermediate data movement and global memory traffic [S1, unofficial].

2.  **Compute-Bound Optimization (Rasterization):**
    *   **Dual-Pixel ILP:** Reformulates the per-pixel Gaussian evaluation to increase instruction-level parallelism (ILP) inside the blending loop [S1, unofficial].
    *   **Fast Exponential Evaluation:** Optimizes the computation of the Gaussian opacity contribution [S1, unofficial].

**Formulas:**
For each Gaussian-pixel pair, the baseline rasterizer evaluates the Gaussian power as [S1, unofficial]:
$$p(x, y) = -\frac{1}{2} \left( a(x - w)^2 + b(x - u)(y - v) + c(y - v)^2 \right) \quad (10)$$
where $(x, y)$ is the target pixel coordinate, $(u, v)$ is the projected 2D Gaussian center, and $a, b, c$ are derived from the projected 2D covariance matrix.

The unclamped opacity contribution is then computed as [S1, unofficial]:
$$\tilde{\alpha}(x, y) = o \exp(p(x, y)) \quad (11)$$
where $o$ is the Gaussian opacity.

**Pseudocode:**
```python
def roofgs_render(gaussians, camera, image_width, image_height):
    # 1. Front-End: Memory-Bound Optimizations
    # Compact Attribute Storage: Quantize SH coefficients with shared scale
    compressed_gaussians = quantize_sh_attributes(gaussians, shared_scale=True)
    
    # Dynamic Depth-Key Compression: Compress keys for sorting
    compressed_keys = compress_depth_keys(compressed_gaussians, camera)
    
    # Cross-Stage Kernel Fusion: Fuse front-end kernels
    sorted_gaussians = fused_front_end_sort(compressed_gaussians, compressed_keys, camera)
    
    # 2. Rasterization: Compute-Bound Optimizations
    # Initialize output image
    image = zeros((image_height, image_width, 3))
    alpha_image = zeros((image_height, image_width))
    
    # Process tiles
    for tile in tiles(image_width, image_height):
        # Dual-Pixel ILP: Process multiple pixels in parallel within thread
        for pixel in tile_pixels(tile):
            # Fast Exponential Evaluation: Optimized exp(p(x,y))
            # Reformulated per-pixel Gaussian evaluation for higher ILP
            for gaussian in sorted_gaussians_in_tile(tile):
                # Compute Gaussian power p(x,y) using optimized arithmetic
                p_xy = compute_gaussian_power(pixel, gaussian)
                
                # Compute unclamped opacity with fast exp
                alpha = gaussian.opacity * fast_exp(p_xy)
                
                # Get color from compressed SH attributes
                color = evaluate_sh_color(gaussian, pixel.direction)
                
                # Alpha blending
                image[pixel] = image[pixel] * (1 - alpha) + color * alpha
                alpha_image[pixel] = alpha_image[pixel] * (1 - alpha) + alpha
                
    return image, alpha_image
```

**Parameters:**
*   **SH Degree:** Typically $D_{SH}=3$ (standard for 3DGS) [S1, unofficial].
*   **Quantization Scale:** Single shared scale per Gaussian for SH coefficients [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision Loss:** Quantization of SH coefficients may introduce color inaccuracies if the shared scale is not chosen carefully [S1, unofficial].
*   **Sorting Errors:** Dynamic depth-key compression must preserve relative order to ensure correct alpha blending [S1, unofficial].
*   **ILP Limits:** Dual-pixel processing may saturate register files if not managed properly [S1, unofficial].

## Subtopics

### [Roofline-guided stage-wise optimization](9841-roofline-guided-stage-wise-optimization.md)
Roofline-guided stage-wise optimization is a methodology that uses stage-wise performance characterization to match optimization strategies to the dominant hardware constraints of the baseline pipeline, by reducing intermediate data movement in the front end and reducing arithmetic overhead in rasterization. It solves the problem of uncoordinated software optimization in volume rendering contexts, where different stages of the rendering pipeline are bottlenecked by different hardware resources (memory bandwidth vs. compute throughput). It sets itself apart from generic optimization by explicitly using the Roofline model to identify the "knee" point and applying memory-centric optimizations to stages below it and compute-centric optimizations to stages near it.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Reduced global memory traffic due to compact attribute storage and compressed depth keys [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales with image resolution and number of Gaussians, with optimizations targeting both memory bandwidth and compute throughput [S1, unofficial].
*   **Strengths:** End-to-end acceleration by addressing both memory-bound and compute-bound stages [S1, unofficial].
*   **Limitations:** Requires careful tuning of quantization scales and compression ratios [S1, unofficial].
*   **When to use:** When rendering 3DGS scenes on hardware where both memory bandwidth and compute throughput are significant bottlenecks [S1, unofficial].
*   **When not to use:** If the hardware is not bound by either memory bandwidth or compute throughput (e.g., very small scenes or very low-resolution displays) [S1, unofficial].

## Background
RoofGS was introduced in the paper "RoofGS: Roofline-Guided End-to-End Acceleration of 3D Gaussian Splatting" [S1, unofficial]. It builds on prior roofline analyses [13], [43], [44] which showed that the rasterization stage of 3DGS is compute-bound [S1, unofficial]. The method applies the Roofline model to guide optimization strategies for different stages of the rendering pipeline [S1, unofficial].
