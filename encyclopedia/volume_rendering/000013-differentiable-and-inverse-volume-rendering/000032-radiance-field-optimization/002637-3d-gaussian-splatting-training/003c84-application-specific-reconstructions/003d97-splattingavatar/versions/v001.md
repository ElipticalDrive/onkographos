# SplattingAvatar

Also called: Realistic Real-Time Human Avatars with Mesh-Embedded Gaussian Splatting

## Overview
SplattingAvatar is a real-time human avatar rendering method that embeds 3D Gaussians onto a driving mesh (FLAME) to enable non-ambiguous motion control and high-fidelity rendering of complex geometries like eyes and hair [S2, unofficial]. Unlike [INSTA](52-inst.md), which suffers from noise in complex regions due to nearest-triangle sampling, SplattingAvatar uses trainable embeddings for motion control, avoiding unstable sampling in canonical space [S2, unofficial]. It prioritizes photometric quality and rendering efficiency over accurate geometry and material reconstruction, outperforming mesh-based approaches like [FLARE](52-flare.md) in visual fidelity [S2, unofficial].

## How it works
**Inputs:** Multi-angle video sequences of a subject; pre-fitted parametric head model (FLAME) or neutral head avatar (NHA) mesh [S2, unofficial].
**Outputs:** A set of 3D Gaussians with trainable embeddings, rendered as real-time animatable avatars [S2, unofficial].

**Data Structures:**
1.  **Gaussian Attributes:** Each Gaussian $i$ stores position $\mathbf{p}_i$, covariance $\Sigma_i$, opacity $\alpha_i$, and spherical harmonics coefficients for color [S2, unofficial].
2.  **Embeddings:** Trainable embedding vectors associated with each Gaussian, used to compute pose- and expression-dependent offsets [S2, unofficial].
3.  **Mesh Representation:** The driving mesh (e.g., FLAME) provides the surface topology and UV coordinates [S2, unofficial].

**Numbered Steps:**
1.  **Initialization:** Initialize one Gaussian per mesh triangle in the mesh tangent space [S1, unofficial].
2.  **Embedding-Based Motion Control:** Instead of deforming Gaussians by finding the nearest triangle in posed space (which causes noise), use trainable embeddings to map Gaussians to their deformed positions based on current pose and expression [S2, unofficial].
3.  **Optimization Loop:**
    *   Run for 30,000 iterations [S2, unofficial].
    *   From iteration 600, perform densification and pruning every 100 iterations [S2, unofficial].
    *   Every 3,000 iterations, reset the opacity of all Gaussians to zero to remove redundant Gaussians [S2, unofficial].
    *   Densification, pruning, and opacity reset stop at iteration 15,000 [S2, unofficial].
    *   After densification and pruning, perform the "walking on triangle" step to ensure Gaussians remain on the mesh surface [S2, unofficial].
4.  **Rendering:** Draw one quad primitive for each Gaussian in a Unity implementation, utilizing compute shaders for motion control [S2, unofficial].

**Formulas:**
*   **Loss Function:** The total loss includes an L1 loss term weighted by $\lambda_l = 0.01$ [S2, unofficial]. Other weights mentioned are $\lambda_s = 1.0$, $T_s = 10.0$, and $T_r = 0.008$ [S2, unofficial]. The specific formulation of the full loss is not detailed in the provided notes, but the L1 weight is explicitly given.
*   **Deformation:** The deformation from canonical to posed space is handled via embeddings rather than explicit nearest-neighbor triangle lookup [S2, unofficial].

**Parameters:**
*   $\lambda_l$ (L1 loss weight): 0.01 [S2, unofficial].
*   $\lambda_s$: 1.0 [S2, unofficial].
*   $T_s$: 10.0 [S2, unofficial].
*   $T_r$: 0.008 [S2, unofficial].
*   Total iterations: 30,000 [S2, unofficial].
*   Densify/Prune frequency: Every 100 iterations (starting from iteration 600) [S2, unofficial].
*   Opacity reset frequency: Every 3,000 iterations [S2, unofficial].
*   Stop densify/prune/reset: Iteration 15,000 [S2, unofficial].

**Pitfalls:**
*   **Nearest-Triangle Sampling:** Using nearest-triangle sampling for deformation (as in INSTA) causes unstable sampling in canonical space and strong noise in complex geometries like the eye region [S2, unofficial].
*   **Disabling "Walking on Triangle":** Disabling this mechanism and clipping UV values causes Gaussians to stick and pile up on mesh triangle boundaries, leading to performance drops in PSNR, SSIM, and LPIPS [S2, unofficial].

**Pseudocode:**
```python
# SplattingAvatar Training Loop
# Based on [S2, unofficial]

def train_splatting_avatar(subject_data, mesh, total_iterations=30000):
    # Initialize Gaussians: one per mesh triangle in tangent space [S1, unofficial]
    gaussians = initialize_gaussians_per_triangle(mesh)
    
    # Set parameters [S2, unofficial]
    lambda_l = 0.01
    lambda_s = 1.0
    Ts = 10.0
    Tr = 0.008
    
    for iteration in range(1, total_iterations + 1):
        # Get current pose and expression from subject_data
        pose, expression = get_current_frame(subject_data, iteration)
        
        # Deform Gaussians using embeddings-based motion control [S2, unofficial]
        # This avoids nearest-triangle sampling noise
        deformed_gaussians = apply_embedding_deformation(gaussians, pose, expression)
        
        # Render and compute loss
        rendered_image = render_gaussians(deformed_gaussians)
        target_image = get_target_image(subject_data, iteration)
        loss = compute_loss(rendered_image, target_image, lambda_l, lambda_s, Ts, Tr)
        
        # Backpropagate and update embeddings and Gaussian attributes
        update_parameters(loss)
        
        # Densify, Prune, and Opacity Reset Schedule [S2, unofficial]
        if iteration >= 600 and iteration <= 15000:
            if iteration % 100 == 0:
                # Densify and Prune
                gaussians = densify_and_prune(gaussians, loss_gradients)
                
                # Walking on Triangle Step [S2, unofficial]
                # Ensures Gaussians stay on mesh surface
                gaussians = walking_on_triangle(gaussians, mesh)
        
        if iteration % 3000 == 0 and iteration <= 15000:
            # Reset opacity to remove redundant Gaussians [S2, unofficial]
            for g in gaussians:
                g.opacity = 0.0
                
    return gaussians

def walking_on_triangle(gaussians, mesh):
    # Project Gaussians back to mesh surface to prevent sticking at boundaries [S2, unofficial]
    # Implementation detail: pybind11, ~3.5 ms per frame [S2, unofficial]
    for g in gaussians:
        g.position = project_to_mesh_surface(g.position, mesh)
    return gaussians
```

## Operating characteristics
*   **Performance:** Renders over 300 FPS on an NVIDIA RTX 3090 GPU using a Unity implementation with compute shaders [S2, unofficial].
*   **Runtime Costs:** The "walking on triangle" step takes ~3.5 ms per frame. Densify-clone takes 2.5 ms, and densify-split takes 6 ms [S2, unofficial].
*   **Quality:** On head avatar datasets, achieves PSNR 28.19 (FLAME) and 28.86 (NHA), SSIM 0.931, and LPIPS 0.063/0.060 respectively [S2, unofficial]. Outperforms FLARE in photometric quality and rendering efficiency [S2, unofficial].
*   **Strengths:** High-fidelity rendering of complex details (eyes, hair, glasses); real-time performance; non-ambiguous motion control [S2, unofficial].
*   **Limitations:** Does not focus on accurate geometry and material reconstruction compared to mesh-based methods like FLARE [S2, unofficial].

## Background
SplattingAvatar was introduced as a method for realistic real-time human avatars using mesh-embedded Gaussian Splatting [S2, unofficial]. It addresses the limitations of previous methods like INSTA, which used nearest-triangle sampling that caused noise in complex regions [S2, unofficial]. The method builds on the principles of [Application-Specific Reconstructions](9269-application-specific-reconstructions.md) by embedding Gaussians into a parametric mesh (FLAME) and using trainable embeddings for motion control [S1, unofficial][S2, unofficial].
