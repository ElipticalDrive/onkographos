# Score-based Densification

Also called: Budget-constrained Optimization, Guided Densification

## Overview
Score-based Densification is a constructive densification strategy for 3D Gaussian Splatting that controls model size by adding new Gaussians only to those primitives that maximize a specific quality score, adhering to a pre-defined user budget [S1]. Unlike standard 3D Gaussian Splatting which relies on aggressive pruning and splitting without strict size caps, this method ensures the final model size is predictable and bounded, avoiding the optimization instability caused by large-scale culling [S1]. It is designed for scenarios where hardware memory or storage constraints require a fixed-capacity output [S1].

## How it works
The method operates within the differentiable training loop, replacing the heuristic splitting of [Densification Strategy](6234-densification-strategy.md) with a guided, score-driven insertion process. It does not perform pruning during training; instead, it strictly controls the growth curve to hit an exact target count [S1].

**Inputs and Outputs:**
*   **Inputs:** Current set of Gaussians $\mathcal{G}$, training views, target final Gaussian count $N_{target}$, current iteration $t$, total training iterations $T$.
*   **Outputs:** Updated set of Gaussians $\mathcal{G}'$ with increased count, constrained by $N_{target}$.

**Data Structures:**
*   **Gaussian Buffer:** Stores mean $\mu$, covariance $\Sigma$ (or scale $s$ and rotation $q$), opacity $\alpha$, and spherical harmonics coefficients.
*   **Saliency Map:** Per-pixel gradient magnitude or loss contribution, aggregated from sampled views.
*   **Score Vector:** Per-Gaussian scalar score $S_g$.

**Step-by-Step Method:**

1.  **Sample Views and Compute Saliency:**
    Sample a subset of training views. For each view, render the current scene and compute the per-pixel loss gradient $\nabla_{image} L$. Aggregate these gradients into a per-pixel saliency map $M_{pix}$, representing the reconstruction error density in screen space [S1].

2.  **Compute Per-Gaussian Score ($S_g$):**
    For each Gaussian $G_i$, compute a score $S_g$ using a scoring function $F$ that combines:
    *   **Gradient Norm:** The magnitude of the gradient of the loss with respect to the Gaussian's 2D mean position, $\|\nabla_{\mu_{2D}} L\|$.
    *   **Saliency:** The sum of saliency values $M_{pix}$ over all pixels covered by the Gaussian's projection.
    *   **Primitive Properties:** Factors such as current opacity $\alpha_i$ or screen area, to penalize redundant or overly large primitives [S1].
    
    The score is defined as:
    $$ S_g(G_i) = F(\|\nabla_{\mu_{2D}} L\|, \sum_{p \in \text{proj}(G_i)} M_{pix}(p), \text{properties}(G_i)) $$
    [S1]

3.  **Determine Densification Budget:**
    Calculate the number of new Gaussians to add, $N_{add}$, based on a growth curve that mimics the original 3D Gaussian Splatting behavior but is fitted to reach $N_{target}$ at iteration $T$. The growth curve ensures a smooth, predictable increase in model size [S1].
    $$ N_{add} = \max(0, \min(N_{target} - |\mathcal{G}|, \text{growth\_curve}(t))) $$
    [S1]

4.  **Select Top-Scoring Gaussians:**
    Sort all Gaussians by $S_g$ in descending order. Select the top $K$ Gaussians where $K$ is sufficient to generate $N_{add}$ new primitives (accounting for the split/clone ratio) [S1].

5.  **Constructive Densification:**
    For each selected Gaussian $G_i$:
    *   **Split/Clone:** Generate new Gaussians in the vicinity of $G_i$. The new means are derived from $G_i$'s mean plus/minus a perturbation along the principal axes of its covariance matrix. The new scales are reduced by a factor (e.g., 1.6) [Parent][S1].
    *   **Initialization:** Initialize the opacity of new Gaussians to a low value (e.g., logit -1.386) to prevent them from dominating early [Parent].
    *   **Constraint:** Stop adding Gaussians once the total count reaches $N_{target}$ [S1].

**Pseudocode:**

```python
def score_based_densification(Gaussians, TrainingViews, TargetCount, CurrentIter, TotalIter):
    # 1. Sample views and compute saliency
    SaliencyMap = compute_per_pixel_saliency(TrainingViews, Gaussians)
    
    # 2. Compute scores for all Gaussians
    Scores = []
    for G in Gaussians:
        grad_norm = compute_gradient_norm(G.mu_2D, TrainingViews)
        saliency_sum = sum(SaliencyMap[p] for p in G.projected_pixels)
        score = scoring_function(grad_norm, saliency_sum, G.properties)
        Scores.append((G, score))
    
    # Sort by score descending
    Scores.sort(key=lambda x: x[1], reverse=True)
    
    # 3. Determine how many to add based on growth curve
    CurrentCount = len(Gaussians)
    if CurrentCount >= TargetCount:
        return Gaussians
    
    # Growth curve mimics 3DGS behavior, fitted to TargetCount at TotalIter
    MaxAllowed = growth_curve(CurrentIter, TotalIter, TargetCount)
    AddCount = min(TargetCount - CurrentCount, MaxAllowed - CurrentCount)
    
    if AddCount <= 0:
        return Gaussians
        
    # 4. Select top candidates
    Candidates = Scores[:AddCount * 2] # Heuristic: select more than needed for splitting
    
    NewGaussians = []
    for G, score in Candidates:
        if len(Gaussians) + len(NewGaussians) >= TargetCount:
            break
            
        # 5. Constructive densification (Split)
        # Generate 2 new Gaussians from G
        NewG1, NewG2 = split_gaussian(G, perturbation_axis='principal')
        
        # Initialize opacity low
        NewG1.alpha = logit(-0.25) # Example low opacity
        NewG2.alpha = logit(-0.25)
        
        NewGaussians.append(NewG1)
        NewGaussians.append(NewG2)
        
    # Append new Gaussians
    Gaussians.extend(NewGaussians)
    return Gaussians
```

**Edge Cases and Pitfalls:**
*   **Budget Violation:** If the growth curve is not fitted correctly, the model may exceed $N_{target}$ or fail to reach it. The curve must be monotonic and bounded [S1].
*   **Redundancy:** Without pruning, redundant Gaussians may accumulate if the score function does not adequately penalize low-contribution primitives. The score function must balance gradient magnitude with saliency to avoid splitting in already well-reconstructed regions [S1].
*   **Precision:** Gradient computation must be numerically stable, as the score relies on small differences in gradient norms [S1].

## Subtopics

### Late Densification
A variant where densification is re-enabled late in the training process (e.g., between iterations 20K and 20.5K) for short intervals (e.g., every 100 iterations) to recover loss from pruning of false-positive Gaussians [S2]. This helps refine details after the main budget-constrained growth phase [S2].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot V)$ per step, where $N$ is the number of Gaussians and $V$ is the number of sampled views. Computing saliency and scores requires rendering and backpropagation [S1].
*   **Memory Complexity:** $O(N)$, where $N$ is the current number of Gaussians. No additional large buffers are required beyond standard rendering buffers [S1].
*   **Performance:** Provides predictable training time and memory usage, as the model size is strictly bounded [S1].
*   **Strengths:** Eliminates the need for pruning, reducing optimization instability. Guarantees a fixed model size suitable for deployment [S1].
*   **Limitations:** May require careful tuning of the growth curve and scoring function to avoid suboptimal distributions. Does not remove redundant Gaussians that may form during training, potentially leading to slightly lower quality than a pruned model of the same size [S1].
*   **When to Use:** When hardware memory is limited, or when a fixed-size model is required for downstream tasks [S1].

## Background
Score-based Densification was introduced in "Taming 3DGS: High-Quality Radiance Fields with Limited Resources" [S1]. It addresses the unpredictability of 3D Gaussian Splatting's model size and training duration, which makes it unsuitable for budget-constrained applications [S1]. The method builds on the standard 3D Gaussian Splatting densification pipeline but replaces heuristic splitting with a guided, score-based approach [S1].
