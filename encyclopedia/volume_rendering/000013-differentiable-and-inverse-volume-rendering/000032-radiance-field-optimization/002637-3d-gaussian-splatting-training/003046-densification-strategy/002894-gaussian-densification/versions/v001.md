# Gaussian Densification

Also called: Adaptive Control Point Density, Mesh Densification, Split and Clone

## Overview
Gaussian Densification is a dynamic optimization strategy in 3D Gaussian Splatting that increases the density of Gaussian primitives $\mathcal{G}_i$ in regions of high geometric or photometric complexity during training [S1, unofficial]. It solves the problem of under-reconstruction in complex areas by splitting existing primitives into new ones, thereby refining the representation without manual parameter tuning [S1, unofficial]. It is distinguished from sibling methods like [Optimization and Densification Strategy](4777-optimization-and-densification-strategy.md) by its specific use of SSIM-based error back-projection and tetrahedral variance metrics to select split locations, and from [GroupFlow](6351-groupflow.md) by its discrete, iterative split-and-clone mechanism rather than continuous flow-based adaptation [S1, unofficial][S2, unofficial].

## How it works
**Inputs:**
- Current set of Gaussian primitives $\mathcal{G}_i$ (positions, covariances, opacities, colors).
- Training dataset of cameras $\{\pi_n\}$ and ground truth images.
- Optimization step counter `step`.
- Configuration parameters: `refineEvery`, `warmupLength`, `stopSplitAt`, `densifyGradThresh`, `densifySizeThresh`, `splitScreenSize`, `resetInterval`, `resetLogit`.

**Outputs:**
- Updated set of Gaussian primitives $\mathcal{G}_i'$ with increased count in selected regions.
- Updated GPU buffers for rendering.

**Data Structures:**
The implementation relies on several GPU buffers of size `buf_capacity` (typically 3x the current active Gaussian count to accommodate worst-case splitting) [S2, unofficial]:
- `densify_split_flag`: Boolean flag indicating if a primitive should be split.
- `densify_dup_flag`: Boolean flag indicating if a primitive should be duplicated (kept).
- `densify_split_prefix`: Prefix sum of split flags.
- `densify_dup_prefix`: Prefix sum of dup flags.
- `densify_keep_flag`: Boolean flag for primitives to keep (not split, not removed).
- `densify_keep_prefix`: Prefix sum of keep flags.
- `densify_block_totals`: Array of size `(buf_capacity + 1023) / 1024` for block-level aggregation.
- `densify_compact_scratch`: Scratch space of size `buf_capacity * featuresRest_stride`.
- `densify_random_samples`: Array of size `buf_capacity x 3` storing random perturbations.

**Steps:**

1. **Trigger Check:** Densification is triggered every `refineEvery` steps, after a `warmupLength` period, and before `stopSplitAt` (defined as `maxSteps / 2`) [S2, unofficial]. If `step % resetInterval` is within `numCameras + refineEvery` of the start of the interval, densification is skipped [S2, unofficial].

2. **Metric Computation:** For a sample of $M$ training images:
   - **SSIM Split Score ($\mathcal{S}_k$):** Back-project SSIM error $s$ onto primitives based on their weight $w_k$ and opacity $\alpha_k$. Compute the normalization factor $\nu_k^{\pi_n}$ for each camera $\pi_n$:
     $$ \nu_k^{\pi_n} = \left[ \sum_i \{ \mathbb{1}[w_k \alpha_k > 0] \}_i \right]_{\pi_n} $$
     Compute the score for primitive $k$:
     $$ \mathcal{S}_k = \text{mean} \left( \text{top2} \left[ \frac{1}{\nu_k^{\pi_n}} \sum_i \{ w_k \alpha_k s \}_i \right]_{\pi_n} \right) $$
     Select primitives with $\mathcal{S}_k > 0.5$ [S1, unofficial].
   - **Variance Split Score ($T_k$):** For regions with low density, compute the variance of residuals $\delta = C - C_{gt}$ within each tetrahedron. Compute the expectation $\mathbb{E}[\mathbf{x}]$:
     $$ \mathbb{E}[\mathbf{x}] = \frac{\sum_{\pi_n} [\sum_i \{\alpha_k w_k \mathbf{x}\}]_i}{\sum_{\pi_n} [\sum_i \{\alpha_k w_k\}]_i}_{\pi_n} $$
     Compute variance $\sigma_k^2 = \mathbb{E}[\delta^2] - \mathbb{E}[\delta]^2$. The score $T_k$ is derived from this variance. Select primitives with $T_k > 2.0$ [S1, unofficial].

3. **Selection:** Combine scores to select primitives for splitting. Primitives meeting either threshold are candidates [S1, unofficial].

4. **New Point Generation:** For each selected primitive (tetrahedron):
   - Identify the two cameras with the highest SSIM error scores.
   - Compute mean ray entrance and exit centroids for these cameras:
     $$ \mu_k^{\text{in}} = \frac{\sum_i \{w_k \alpha_k \mathbf{r}(t_k^{\text{in}})\}_i}{\sum_i \{w_k \alpha_k\}_i}, \quad \mu_k^{\text{out}} = \frac{\sum_i \{w_k \alpha_k \mathbf{r}(t_k^{\text{out}})\}_i}{\sum_i \{w_k \alpha_k\}_i} $$
   - Form line segments between $\mu_k^{\text{in}}$ and $\mu_k^{\text{out}}$ for the two top cameras.
   - Find the midpoint of the shortest line between these two segments. This midpoint is the new vertex added to the vertex set $\{v_i\}$ [S1, unofficial].
   - If the intersection lies outside the tetrahedron, fall back to a random point within the tetrahedron [S1, unofficial].

5. **Split and Clone:**
   - Generate random perturbations for split perturbations on CPU using a normal distribution (mean 0, std 1) seeded by the current step, stored in `densify_random_samples` [S2, unofficial].
   - Call `msplat_densify` with parameters: `densifyGradThresh`, `densifySizeThresh`, `splitScreenSize`, `check_screen` (1 if step < `stopScreenSizeAt` else 0), constants 0.1, 0.5, 0.15, `checkHuge` (1 if step > `refineEvery * resetAlphaEvery` else 0), gradient norms, visibility counts, max 2D size, half max screen dimension, and all Gaussian/Adam buffers [S2, unofficial].
   - Update `num_active` to the new count returned by `msplat_densify` and refresh GPU views [S2, unofficial].

6. **Opacity Reset:** Every `resetInterval` steps, specifically when `step % resetInterval == refineEvery`, opacities greater than `resetLogit` (-1.3862943611198906, logit of 0.25) are clamped to this value. Adam state for opacities (group 5) is zeroed [S2, unofficial].

**Pseudocode:**

```python
def gaussian_densification(step, primitives, dataset, config):
    # 1. Trigger Check
    if step < config.warmup_length:
        return primitives
    if step % config.refine_every != 0:
        return primitives
    if step >= config.stop_split_at:
        return primitives
    
    reset_interval = config.reset_alpha_every * config.refine_every
    if (step % reset_interval) < (len(dataset.cameras) + config.refine_every):
        return primitives

    # 2. Metric Computation
    ssim_scores = []
    variance_scores = []
    
    for cam_idx in sample(dataset.cameras, config.sample_size):
        cam = dataset.cameras[cam_idx]
        gt_image = dataset.get_gt(cam)
        rendered_image = render(primitives, cam)
        ssim_error = compute_ssim(rendered_image, gt_image)
        
        # Back-project SSIM error
        for prim in primitives:
            weight = prim.weight(cam)
            alpha = prim.opacity
            if weight * alpha > 0:
                # Accumulate error weighted by contribution
                prim.ssim_accumulator += weight * alpha * ssim_error
                prim.visibility_count += 1
                
    # Normalize and compute SSIM score
    for prim in primitives:
        if prim.visibility_count > 0:
            prim.ssim_score = prim.ssim_accumulator / prim.visibility_count
        else:
            prim.ssim_score = 0
            
    # Compute variance score
    for prim in primitives:
        # Compute expectation of residuals
        residual_mean = compute_residual_expectation(primitives, dataset)
        residual_var = compute_residual_variance(primitives, dataset, residual_mean)
        prim.variance_score = residual_var
        
    # 3. Selection
    split_candidates = []
    for prim in primitives:
        if prim.ssim_score > 0.5 or prim.variance_score > 2.0:
            split_candidates.append(prim)
            
    # 4. New Point Generation
    new_points = []
    for prim in split_candidates:
        # Find top 2 cameras for this primitive
        top_cameras = get_top_cameras_by_error(prim, dataset)
        
        # Compute centroids
        mu_in = compute_centroid(prim, top_cameras[0], 'in')
        mu_out = compute_centroid(prim, top_cameras[0], 'out')
        mu_in_2 = compute_centroid(prim, top_cameras[1], 'in')
        mu_out_2 = compute_centroid(prim, top_cameras[1], 'out')
        
        # Form segments
        seg1 = Segment(mu_in, mu_out)
        seg2 = Segment(mu_in_2, mu_out_2)
        
        # Find approximate intersection
        intersection = find_midpoint_shortest_line(seg1, seg2)
        
        # Check if intersection is inside tetrahedron
        if is_inside_tetrahedron(intersection, prim.tetrahedron):
            new_points.append(intersection)
        else:
            # Fallback to random point
            new_points.append(random_point_in_tetrahedron(prim.tetrahedron))
            
    # 5. Split and Clone
    # Generate random samples
    random_samples = generate_random_samples(len(split_candidates), seed=step)
    
    # Call densification kernel
    new_primitives = msplat_densify(
        primitives,
        split_candidates,
        new_points,
        random_samples,
        config.densify_grad_thresh,
        config.densify_size_thresh,
        config.split_screen_size,
        step < config.stop_screen_size_at,
        step > config.refine_every * config.reset_alpha_every,
        config.constants
    )
    
    # 6. Opacity Reset
    if step % reset_interval == config.refine_every:
        for prim in new_primitives:
            if prim.opacity > config.reset_logit:
                prim.opacity = config.reset_logit
        zero_adam_state_opacities(new_primitives)
        
    return new_primitives
```

## Subtopics

### [Multi-View Density Control Criterion](5663-multi-view-density-control-criterion.md)
A variant that incorporates multi-view consistency checks into the density control, ensuring that densification only occurs where multiple views agree on the presence of detail. It is chosen when multi-view consistency is critical for reducing artifacts in complex scenes.

## Operating characteristics
- **Time Complexity:** Densification is triggered every `refineEvery` steps, making it an intermittent operation. The metric computation is $O(N \cdot M)$ where $N$ is the number of primitives and $M$ is the sample size. The split operation is $O(K)$ where $K$ is the number of split candidates.
- **Memory Complexity:** Requires additional GPU buffers of size `buf_capacity`, typically 3x the current active Gaussian count [S2, unofficial].
- **Performance:** On an M4 Max, training can be completed in ~90s with native Metal acceleration [S2, unofficial].
- **Strengths:** Efficiently refines complex regions without over-smoothing. SSIM-based scoring aligns with perceptual quality.
- **Limitations:** Can lead to over-densification in noisy regions if not properly thresholded. Requires careful tuning of `densifyGradThresh` and `densifySizeThresh`.
- **When to use:** When reconstructing scenes with high-frequency details or thin structures that are under-represented by the initial Gaussian distribution.
- **When not to use:** For simple scenes with low geometric complexity, or when computational resources are severely constrained.

## Background
Gaussian Densification was introduced in the context of 3D Gaussian Splatting to address the limitations of static Gaussian distributions. The method was developed by researchers in the field of differentiable rendering and inverse graphics, with key contributions detailed in "Radiance Meshes for Volumetric Reconstruction" [S1, unofficial]. The implementation details, including GPU acceleration and specific parameter tuning, are further elaborated in the "Msplat" project [S2, unofficial].
