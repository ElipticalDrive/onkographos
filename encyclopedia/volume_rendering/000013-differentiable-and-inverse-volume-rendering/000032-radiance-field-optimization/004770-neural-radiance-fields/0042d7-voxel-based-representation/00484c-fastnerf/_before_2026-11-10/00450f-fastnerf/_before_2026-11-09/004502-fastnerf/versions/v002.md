# FastNeRF

Also called: Factorized Neural Radiance Fields

## Overview
FastNeRF is a neural rendering architecture that accelerates volume rendering by factorizing the standard NeRF function into position-dependent and direction-dependent components, enabling compact caching and avoiding MLP calls at inference time [S1, unofficial]. It solves the computational bottleneck of standard NeRF, which requires hundreds of MLP invocations per pixel, by replacing them with hardware-accelerated cache lookups, achieving interactive rates (200Hz+) on consumer hardware [S1, unofficial]. Unlike standard NeRF, which queries a 5D function, FastNeRF separates this into two lower-dimensional functions, reducing memory complexity from $O(k^3 l^2)$ to $O(k^3(1 + 3D) + l^2 D)$ [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Training Inputs:** Multi-view images, camera extrinsics, intrinsics, and optionally depth/normal maps.
- **Training Outputs:** Weights for two MLPs ($\mathcal{F}_{\text{pos}}$ and $\mathcal{F}_{\text{dir}}$).
- **Inference Inputs:** Camera parameters (ray origins and directions).
- **Inference Outputs:** Rendered pixel colors.

**Data Structures:**
1.  **Position Cache:** A sparse 3D grid of size $k^3$. Stores density $\sigma$ and a deep radiance map $(\mathbf{u}, \mathbf{v}, \mathbf{w})$ for each voxel.
    -   $\sigma$: 16-bit float.
    -   $\mathbf{u}, \mathbf{v}, \mathbf{w}$: $D$-dimensional vectors of 16-bit floats.
    -   Total size per voxel: $1 + 3D$ values.
2.  **Direction Cache:** A sparse 2D grid of size $l^2$ (representing spherical coordinates $\theta, \phi$). Stores direction weights $\boldsymbol{\beta}$.
    -   $\boldsymbol{\beta}$: $D$-dimensional vector of 16-bit floats.
    -   Total size per direction: $D$ values.

**Network Architecture:**
-   $\mathcal{F}_{\text{pos}}(\mathbf{p})$: An 8-layer MLP with 384 hidden units (256 for specific scenes like Ficus). Takes positional encoding of $\mathbf{p} \in \mathbb{R}^3$. Outputs $\sigma$ and $(\mathbf{u}, \mathbf{v}, \mathbf{w})$.
-   $\mathcal{F}_{\text{dir}}(\mathbf{d})$: A 4-layer MLP with 128 hidden units. Takes positional encoding of direction $\mathbf{d} \in \mathbb{R}^3$ (parameterized as a unit vector). Outputs $\boldsymbol{\beta} \in \mathbb{R}^D$.

**Parameters:**
-   $D$: Number of components/factors. Typical values: 8 for NeRF Synthetic 360, 6 for LLFF. 16 provides theoretical improvement but increases sparsity [S1, unofficial].
-   $k$: Grid resolution for position cache (divisions of bounding box longest side). Typical: $256^3$ to $1024^3$.
-   $l$: Grid resolution for direction cache. Typical: $256$ to $1024$ [S1, unofficial].

**Algorithm Steps:**

1.  **Training:** Train $\mathcal{F}_{\text{pos}}$ and $\mathcal{F}_{\text{dir}}$ using the standard NeRF loss function (MSE between rendered and ground truth colors) [S1, unofficial].
2.  **Cache Population:**
    -   Define bounding box $V$ for the scene.
    -   Uniformly sample $k$ values for $x, y, z$ within $V$.
    -   Uniformly sample $l$ values for $\theta \in [0, \pi]$ and $\phi \in [0, 2\pi]$.
    -   Compute $\mathcal{F}_{\text{pos}}$ for all position samples to populate the Position Cache.
    -   Compute $\mathcal{F}_{\text{dir}}$ for all direction samples to populate the Direction Cache [S1, unofficial].
3.  **Mesh Generation (Optional but recommended for speed):**
    -   Extract density volume from Position Cache.
    -   Generate a collision mesh using Marching Cubes on the sign-distance function derived from the density volume [S1, unofficial].
    -   If volume resolution $> 512^3$, downsample by factor of 2 before meshing to reduce complexity [S1, unofficial].
4.  **Rendering (Inference):**
    -   For each pixel, generate a ray.
    -   Use hardware-accelerated ray tracing to intersect the collision mesh. Skip empty space; start integration at the first hit [S1, unofficial].
    -   For each sample point $\mathbf{p}_i$ along the ray:
        -   Lookup $\sigma_i$ and $(\mathbf{u}_i, \mathbf{v}_i, \mathbf{w}_i)$ from Position Cache using **nearest-neighbor** interpolation.
        -   Lookup direction $\mathbf{d}_i$ (converted to $\theta, \phi$).
        -   Lookup $\boldsymbol{\beta}_i$ from Direction Cache using **trilinear** interpolation [S1, unofficial].
        -   Compute color $\mathbf{c}_i = \boldsymbol{\beta}_i^T \cdot (\mathbf{u}_i, \mathbf{v}_i, \mathbf{w}_i)$ [S1, unofficial].
    -   Integrate color and density along the ray using the standard volume rendering equation:
        $$ \mathbf{C} = \sum_{i=1}^N T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i $$
        where $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$ and $\delta_i$ is the distance between samples [S1, unofficial].

## Operating characteristics
-   **Speed:** FastNeRF is approximately 3000x faster than standard NeRF at comparable perceptual quality [S1, unofficial]. It achieves 200Hz rendering on high-end consumer GPUs [S1, unofficial].
-   **Memory:** Memory complexity is $O(k^3(1 + 3D) + l^2 D)$. For $k=l=1024$ and $D=8$, dense cache size is ~54 GB, compared to ~5600 TB for standard NeRF caching [S1, unofficial].
-   **Quality:** Matches or exceeds NeRF quality at high cache resolutions (e.g., $1024^3$). Lower resolutions (e.g., $256^3$) may show "pixelated" appearance or aliasing artifacts due to grid discretization [S1, unofficial].
-   **Training:** Training time is identical to standard NeRF [S1, unofficial].
-   **Limitations:** 
    -   Aliasing artifacts can appear due to caching [S1, unofficial].
    -   Uncached performance is slower than NeRF due to larger MLPs (384 hidden units) [S1, unofficial].
    -   Mesh complexity must be managed for large volumes ($>512^3$) [S1, unofficial].

## Background
FastNeRF was introduced by Garbin et al. in 2021 [S1, unofficial]. It builds on the original NeRF architecture [27] by applying a graphics-inspired factorization similar to spherical harmonics in real-time rendering. The method addresses the high computational cost of NeRF, which is compute-bound due to repeated MLP evaluations. By caching the factorized components, it shifts the bottleneck to memory bandwidth, which is more efficiently handled by modern GPUs. It has been applied to telepresence, dynamic scenes, and single-image reconstruction [S1, unofficial].
