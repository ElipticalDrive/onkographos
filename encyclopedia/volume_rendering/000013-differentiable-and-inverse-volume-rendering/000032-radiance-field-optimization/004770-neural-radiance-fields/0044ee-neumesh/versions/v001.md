# NeuMesh++


## Overview
NeuMesh++ is a mesh-based neural radiance representation that encodes scenes with disentangled geometry, texture, and semantic codes on mesh vertices to enable efficient volumetric editing [S1]. It builds on [Neural Radiance Fields](4972-neural-radiance-fields.md) by replacing the standard volumetric MLP with a mesh-scaffolded architecture that distributes neural features on a mesh surface [S1]. Unlike its predecessor NeuMesh, which relied on an implicit Signed Distance Field (SDF) and a pre-trained teacher model, NeuMesh++ rebuilds the representation directly on the neural radiance field using a novel local space parameterization [S1]. This approach improves spatial distinguishability, avoids sub-optimal convergence, and preserves high-frequency details better than SDF-based methods like NeuS or rasterization-based methods like NeuManifold [S1].

## How it works
### Inputs and Outputs
**Inputs:**
*   A mesh scaffold $\mathcal{M}$ (vertices $\mathcal{V}$, faces $\mathcal{F}$), which can be non-watertight or non-manifold [S1].
*   Camera poses and intrinsics for training views [S1].
*   Ground truth images for optimization [S1].
*   For editing: User interactions (mesh deformation, 2D painting, semantic clicks) [S1].

**Outputs:**
*   Rendered color $\hat{C}(\mathbf{r})$ for a ray $\mathbf{r}$ [S1].
*   Editable scene representation supporting geometry deformation, texture swapping/filling/painting, and semantic-guided editing [S1].

### Data Structures
1.  **Mesh Scaffold $\mathcal{M}$:** Defined by vertices $\mathbf{v}_i \in \mathbb{R}^3$ and connectivity [S1].
2.  **Vertex Codes:** Each vertex $\mathbf{v}_i$ stores three latent codes:
    *   **Geometry Code $\mathbf{g}_i \in \mathbb{R}^{d_g}$:** Encodes local geometry [S1].
    *   **Appearance Code $\mathbf{a}_i \in \mathbb{R}^{d_a}$:** Encodes view-dependent texture [S1].
    *   **Semantic Code $\mathbf{s}_i \in \mathbb{R}^{d_s}$:** Encodes semantic attributes, aggregated from an open-vocabulary segmentation method [S1].
3.  **Modification Color $\mathbf{m}_i \in \mathbb{R}^3$:** A learnable, view-independent color parameter attached to each vertex [S1]. This is decoder-free and used specifically for texture editing fidelity [S1].
4.  **Occupancy Grid:** A 3D grid initialized using the mesh scaffold to bypass unoccupied spaces during sampling [S1]. Updated when the mesh is deformed [S1].
5.  **Lightweight Decoders:** Small Multi-Layer Perceptrons (MLPs) that decode the latent codes into density and color [S1].

### Local Space Parameterization
Naive trilinear interpolation fails to measure spatial variation for 'single layer' codes on mesh vertices, specifically lacking spatial distinguishability for inner/outer queries perpendicular to the surface [S1]. NeuMesh++ introduces a local space parameterization to resolve this [S1].

For a query point $\mathbf{q}$, the method identifies $K$ neighboring mesh vertices $\{\mathbf{v}_k\}_{k=1}^K$ [S1].
1.  **Local Indicator Calculation:** For each neighbor $\mathbf{v}_k$, a local indicator $\lambda_k$ is calculated to signify the relative spatial relationship between $\mathbf{q}$ and $\mathbf{v}_k$ [S1]. This indicator helps determine the direction relative to the surface normal, solving the ambiguity of crossing a mesh face [S1].
2.  **Post-Interpolation Strategy:** The density $\sigma(\mathbf{q})$ and radiance $\mathbf{c}(\mathbf{q})$ are fused from the neighboring vertices based on their latent codes and the local indicators [S1]. This forms a 'local radiance field' around each vertex [S1].

### Rendering Pipeline
The rendering follows the standard emission-absorption model defined in [Neural Radiance Fields](4972-neural-radiance-fields.md), but the density $\sigma$ and color $\mathbf{c}$ are derived from the mesh-based interpolation [S1].

1.  **Sampling:** Rays are sampled. An occupancy grid is used to skip empty space, focusing sampling on grids occupied by the mesh scaffold [S1].
2.  **Query:** For each sample point $\mathbf{q}$ on the ray:
    *   Find $K$ nearest vertices $\{\mathbf{v}_k\}$ on the mesh [S1].
    *   Compute local indicators $\lambda_k$ for each neighbor [S1].
    *   Retrieve latent codes $\mathbf{g}_k, \mathbf{a}_k, \mathbf{s}_k$ and modification colors $\mathbf{m}_k$ for these vertices [S1].
    *   Decode the codes using lightweight MLPs to get intermediate features [S1].
    *   Apply the post-interpolation strategy using $\lambda_k$ to fuse the density $\sigma_i$ and color $\mathbf{c}_i$ contributions from the neighbors [S1].
3.  **Volume Rendering:** Compute the final color $\hat{C}(\mathbf{r})$ using the accumulated density and color along the ray [S1].

### Editing Mechanisms
NeuMesh++ supports three primary editing operations [S1]:

1.  **Geometry Editing:**
    *   Deform the mesh scaffold $\mathcal{M}$ directly [S1].
    *   Update the occupancy grid to reflect the new mesh position (takes ~1 second) [S1].
    *   The radiance field updates automatically because it is bound to the mesh vertices [S1].

2.  **Texture Editing:**
    *   **Swapping/Filling:** Replace the appearance code $\mathbf{a}_i$ or modification color $\mathbf{m}_i$ of specific vertices with those from a reference object. No fine-tuning is required; edited views render immediately [S1].
    *   **Painting:**
        *   User paints on a 2D image.
        *   **Spatial-Aware Optimization:** Probing rays are cast from painted pixels to the mesh surface to identify affected vertices [S1].
        *   Only the **modification colors** $\mathbf{m}_i$ of these selected vertices are fine-tuned to match the painted color [S1].
        *   This avoids overfitting to a single view and keeps other parts unchanged [S1]. Fine-tuning takes ~1 second [S1].

3.  **Semantic-Guided Editing:**
    *   Aggregate semantic information from an open-vocabulary segmentation model onto mesh vertices, storing it in $\mathbf{s}_i$ [S1].
    *   User clicks a region in a 2D view.
    *   **Semantic Propagation:** The click is propagated to a 3D semantic mask by identifying vertices with matching semantic codes [S1].
    *   Editing operations (e.g., texture change) are applied to all vertices in the 3D mask [S1]. Propagation takes ~2 seconds [S1].

### Edge Cases and Pitfalls
*   **Spatial Distinguishability:** Naive trilinear interpolation fails to distinguish inner/outer queries perpendicular to the surface [S1]. NeuMesh++ solves this with local indicators [S1].
*   **Decoder Limitations:** Learned neural decoders narrow the data range of decoded color due to fixed weights and viewing direction conditioning, limiting view-dependent texture modification fidelity [S1]. NeuMesh++ uses decoder-free modification colors to mitigate this [S1].
*   **Overfitting in Painting:** Straightforward fine-tuning with a single image can cause overfitting to a specific view [S1]. NeuMesh++ uses spatial-aware optimization (probing rays) to restrict updates to affected vertices [S1].
*   **Mesh Topology:** The method is agnostic to non-watertight or non-manifold meshes [S1].

## Operating characteristics
*   **Rendering Speed:** ~15 fps on Nvidia GTX 4070 GPU for 800 × 800 images [S1].
*   **Geometry Editing Update Time:** ~1 second to update the occupancy grid according to the deformed mesh [S1].
*   **Texture Painting Fine-tuning Time:** ~1 second [S1].
*   **Semantic-Guided Editing Time:** ~2 seconds for 3D semantic propagation [S1].
*   **Texture Swapping/Filling:** Immediate rendering without extra fine-tuning [S1].
*   **Memory:** Uses compact latent codes and lightweight decoders to minimize time-consuming network queries [S1]. Occupancy grid bypasses unoccupied spaces [S1].
*   **Strengths:** Preserves high-frequency details better than SDF-based methods (NeuS, NeuMesh) and rasterization-based methods (NeuManifold) [S1]. Supports comprehensive editing (geometry, texture, semantics) [S1]. No need for pre-trained teacher model [S1].
*   **Limitations:** Requires a mesh scaffold [S1]. Performance depends on the quality of the mesh and segmentation [S1].

## Background
NeuMesh++ is an extension of NeuMesh [S1]. A preliminary version of NeuMesh was published previously [S1]. NeuMesh++ was introduced to address limitations in NeuMesh, such as the reliance on an implicit SDF field and a pre-trained teacher model [S1]. It rebuilds the representation on the neural radiance field to achieve better rendering quality on geometrically complex objects [S1]. The method was evaluated on the DTU dataset and NeRF 360° Synthetic dataset [S1].
