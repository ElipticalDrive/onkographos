# EgoNeRF

Also called: Balanced Spherical Grid for Egocentric View Synthesis

## Overview
EgoNeRF is an efficient adaptation of NeRF [1185-nerf-neural-radiance-fields.md] designed for large-scale, unbounded scenes captured via casual egocentric video from omnidirectional cameras. It solves the inefficiency and artifact issues of Cartesian grids in wide-field-of-view settings by employing a balanced spherical feature grid that maintains uniform ray hit rates across cells. Unlike [Mip-NeRF](3381-mip-nerf.md) which relies on a proposal MLP for resampling, EgoNeRF shares a single density grid for coarse and fine sampling, enabling faster convergence and superior preservation of fine structures in outdoor environments.

## How it works
EgoNeRF represents the scene using a continuous volumetric field parameterized by a balanced spherical feature grid and a lightweight MLP, optimized via differentiable volume rendering.

### Inputs and Outputs
- **Inputs**: Multi-view equirectangular images from an omnidirectional camera; camera poses estimated via Structure-from-Motion (SfM) [S1].
- **Outputs**: A neural volume representation allowing synthesis of novel views; rendered images with high fidelity to ground truth.

### Data Structures
The core data structure is the **Balanced Spherical Feature Grid**. Unlike Cartesian grids (e.g., [DVGO](1185-nerf-neural-radiance-fields.md) or [TensoRF](1185-nerf-neural-radiance-fields.md)), this grid is defined in spherical coordinates $(r, \theta, \phi)$ to match the geometry of egocentric capture.

1.  **Radial Partition**: Uniformly spaced concentric shells. This ensures consistent resolution scaling with distance, avoiding the "wasted cells" in far regions and low resolution in near regions typical of Cartesian grids [S1].
2.  **Angular Partition**: Uses a **Yin-Yang grid** (a specific arrangement of points on a sphere) combined with a uniform radial partition. This configuration minimizes valence variations at the poles, ensuring uniform ray hit rates for individual cells [S1].
3.  **Feature Storage**: Each grid cell stores feature vectors. These features are combined via vector-matrix factorization to predict volume density ($\sigma$) and view-dependent color ($c$) [S1].
4.  **Density Grid ($G_\sigma$)**: A shared grid used to query volume density for both coarse and fine sampling stages [S1].

### Parameters
- **Hardware**: Experiments conducted on a single RTX-3090 GPU [S1].
- **Ray Batch Size**: Same as baseline methods (DVGO, TensoRF) for fair comparison [S1].
- **Grid Resolution**: Same number of feature grids as DVGO and TensoRF [S1].
- **Training Steps**: High performance achieved at 5,000 steps [S1].

### Algorithm Steps
1.  **Pose Estimation**: Obtain camera poses from input video frames using the OpenMVG SfM library [S1].
2.  **Grid Initialization**: Initialize the balanced spherical feature grid with uniform radial partitions and Yin-Yang angular partitions [S1].
3.  **Ray Sampling**:
    - Cast rays from the camera through each pixel.
    - Sample points along the ray.
    - Query the shared density grid $G_\sigma$ for volume density at these points [S1].
4.  **Resampling**: Employ resampling techniques to refine sample distribution based on density, rather than relying on a separate proposal MLP [S1].
5.  **Feature Aggregation**:
    - Retrieve features from the spherical grid for each sample point.
    - Apply vector-matrix factorization to combine features [S1].
6.  **Rendering**:
    - Compute color and density for each sample.
    - Perform volume rendering (compositing) to produce the final pixel color [S1].
7.  **Optimization**:
    - Minimize the difference between rendered images and ground truth images.
    - Update grid features and MLP parameters via gradient descent [S1].
8.  **Environment Map**: Include an environment map component to handle infinitely far regions, particularly in outdoor scenes [S1].

### Pseudocode
```python
# EgoNeRF Rendering and Optimization Step
# Assumes pre-initialized balanced spherical grid G_spherical and shared density grid G_sigma

def query_spherical_grid(grid, ray_origin, ray_direction, t_min, t_max):
    """
    Queries the balanced spherical feature grid for a ray segment.
    Uses spherical coordinates to map ray points to grid cells.
    """
    samples = []
    # Generate sample points along the ray
    num_samples = 128 # Example value, resampling adjusts this
    t_vals = linear_space(t_min, t_max, num_samples)
    
    for t in t_vals:
        point = ray_origin + ray_direction * t
        # Convert Cartesian (x,y,z) to Spherical (r, theta, phi)
        r = length(point)
        theta = atan2(sqrt(x^2 + y^2), z)
        phi = atan2(y, x)
        
        # Query features from the Yin-Yang balanced grid
        features = grid.sample(r, theta, phi)
        samples.append((point, features, t))
    
    return samples

def render_ray(ray_origin, ray_direction, grid_sigma, grid_spherical, env_map):
    """
    Renders a single ray using shared density grid and spherical features.
    """
    # 1. Coarse Sampling
    coarse_samples = query_spherical_grid(grid_spherical, ray_origin, ray_direction, t_min, t_max)
    
    # 2. Density Query (Shared Grid)
    densities = []
    for point, features, t in coarse_samples:
        sigma = grid_sigma.query(point)
        densities.append(sigma)
    
    # 3. Resampling (Importance Sampling based on densities)
    # EgoNeRF uses resampling techniques rather than a proposal MLP
    fine_samples = resample(coarse_samples, densities)
    
    # 4. Fine Rendering
    alpha_accum = 0.0
    color_accum = vec3(0.0)
    background_color = env_map.query(ray_direction) # Handle infinite distance
    
    for point, features, t in fine_samples:
        sigma = grid_sigma.query(point)
        alpha = 1.0 - exp(-sigma * delta_t) # delta_t is distance between samples
        
        weight = alpha * (1.0 - alpha_accum)
        color_accum += weight * color_from_features(features)
        alpha_accum += weight
        
        if alpha_accum > 0.99:
            break
            
    # Add background for unbounded scenes
    final_color = color_accum + (1.0 - alpha_accum) * background_color
    return final_color

def train_step(images, poses, grid_sigma, grid_spherical, env_map):
    """
    One step of optimization.
    """
    loss = 0.0
    for image, pose in zip(images, poses):
        for u, v in image.pixels:
            ray_origin = pose.camera_center
            ray_direction = pose.get_ray_direction(u, v)
            
            rendered_color = render_ray(ray_origin, ray_direction, grid_sigma, grid_spherical, env_map)
            target_color = image.get_pixel(u, v)
            
            loss += mse(rendered_color, target_color)
            
    gradients = compute_gradients(loss, [grid_sigma, grid_spherical, env_map])
    update_parameters(gradients)
    return loss
```

### Edge Cases and Pitfalls
- **Camera Pose Errors**: Erroneous pose estimates cause rays to hit neighboring cells in the feature grid. This results in **spotty artifacts** in EgoNeRF, whereas MLP-based methods (like standard NeRF) tend to produce **blurry rendering** in the same scenario [S1].
- **Pole Distortion**: Equirectangular images have distortion near poles. Metrics should be weighted-to-spherically uniform (PSNRWS, SSIMWS) to account for this [S1].
- **Missing Components**:
    - Removing the balanced spherical grid components (uniform radial partition, Yin-Yang grid) degrades performance [S1].
    - Removing both radial and angular balanced grids (using uniform spherical grids) causes the biggest drop in performance, except for PSNR in indoor scenes [S1].
    - Not employing resampling techniques and using a double number of ray samples reduces performance [S1].
    - Removing the environment map in outdoor scenes shows blurry artifacts in infinitely far regions and reduces performance [S1].

## Operating characteristics
- **Speed**: EgoNeRF achieves high performance very quickly. It reaches competitive results at 5,000 training steps, taking only **10 minutes** of wall-clock time [S1]. In contrast, [Mip-NeRF](3381-mip-nerf.md) requires approximately **8 hours** to outperform EgoNeRF's 5k-step results [S1].
- **Accuracy**: On the OmniBlender dataset, EgoNeRF (full) achieves:
    - Indoor: PSNR 33.11, LPIPS 0.142, SSIM 0.902 [S1].
    - Outdoor: PSNR 30.56, LPIPS 0.087, SSIM 0.904 [S1].
- **Strengths**:
    - Efficient for large-scale, unbounded scenes captured with omnidirectional cameras [S1].
    - Preserves fine structures (e.g., thin wires, street lamps) better than [Mip-NeRF](3381-mip-nerf.md), which often misses them due to reliance on the proposal MLP's initial guess [S1].
    - Avoids the "wasted cells" and low-resolution center issues of Cartesian grids (TensoRF, DVGO) in large scenes [S1].
- **Limitations**:
    - Sensitive to camera pose errors, leading to spotty artifacts [S1].
    - Performance degrades if the balanced spherical grid structure is simplified to uniform spherical grids [S1].
- **When to Use**: Ideal for egocentric, large-scale scene reconstruction from casual omnidirectional video where fast training and high fidelity to fine details are required.
- **When Not to Use**: If camera poses are highly inaccurate and spotty artifacts are unacceptable, or if the scene is small and bounded where Cartesian grids might suffice.

## Background
EgoNeRF is a variant of NeRF [1185-nerf-neural-radiance-fields.md] introduced to address the limitations of standard NeRF and its variants in large-scale, egocentric settings. While [Mip-NeRF](3381-mip-nerf.md) adapts to unbounded scenes by warping space, EgoNeRF focuses on the geometric suitability of the feature grid for spherical capture. It was developed to enable efficient synthesis of novel views from short videos captured with omnidirectional cameras, leveraging a balanced spherical feature grid to maintain uniform ray hit rates [S1].
