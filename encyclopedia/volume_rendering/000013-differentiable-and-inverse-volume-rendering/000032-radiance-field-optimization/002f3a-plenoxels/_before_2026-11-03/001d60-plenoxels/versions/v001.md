# Plenoxels

Also called: Plenoxels Alpha, Volumetric rendering using ReLU fields

## Overview
Plenoxels is a volumetric rendering technique that replaces the neural network MLPs of Neural Radiance Fields with a static 3D grid storing density scalars and Spherical Harmonic (SH) coefficients for view-dependent color [S2, unofficial]. It solves the inference speed bottleneck of NeRF by enabling fast, non-iterative ray marching on CPU or GPU without neural network evaluation [S2, unofficial]. Unlike its sibling [Explicit Radiance Fields](806-explicit-radiance-fields.md) which may use different basis functions or storage, Plenoxels specifically utilizes 2nd-order SH for color and a single density value per voxel [S2, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
- Sparse 3D grid of cells containing density and SH coefficients.
- Camera parameters: position, direction, up vector, Field of View (FOV), and image resolution ($W \times H$).
- Rendering parameters: number of bins/steps along the ray, grid bounds.

**Outputs:**
- 2D image (color and optionally alpha) for the given camera pose.

### Data Structures

**Grid**
- `minPoint`: `float3` (-1, -1, -1) [S2, unofficial].
- `maxPoint`: `float3` (1, 1, 1) [S2, unofficial].
- `cells`: Flat array of `Cell` structures.
- `total`: Total number of cells, typically $128^3 = 2,097,152$ [S2, unofficial].

**Cell**
- `density`: `float` (scalar) [S2, unofficial].
- `shr`: `float[9]` (SH coefficients for Red channel) [S2, unofficial].
- `shg`: `float[9]` (SH coefficients for Green channel) [S2, unofficial].
- `shb`: `float[9]` (SH coefficients for Blue channel) [S2, unofficial].
- Total size: 28 floats [S2, unofficial].

**Spherical Harmonics (2nd Order)**
- Order $L=1$, size $N=9$ [S2, unofficial].
- Basis functions evaluated at direction normal $\mathbf{n} = (x, y, z)$ [S2, unofficial]:
  - $Y_0 = 0.28209479177387814$
  - $Y_1 = -0.488602511902919978 \cdot x$
  - $Y_2 = -0.488602511902919978 \cdot y$
  - $Y_3 = 0.488602511902919923 \cdot z$
  - $Y_4 = -1.09254843059207896 \cdot z \cdot x$
  - $Y_5 = -1.09254843059207896 \cdot z \cdot y$
  - $Y_6 = 0.94617469575756008 \cdot z^2 - 0.315391565252520045$
  - $Y_7 = 0.546274215296039478 \cdot (x^2 - y^2)$
  - $Y_8 = 1.09254843059207896 \cdot xy$ (Note: Source code computes `2xy` basis scaled, effectively implementing the standard $Y_8$ term via `tmp_c * s1` where `s1=2xy`) [S2, unofficial].

### Algorithm Steps

1. **Camera Ray Generation**:
   For each pixel $(x, y)$ in image of size $W \times H$:
   - Calculate aspect ratio $AR = W/H$.
   - Calculate focal length $f = 2 \tan(\text{FOV}/2)$.
   - Normalize screen coordinates: $u = (x + 0.5)/W$, $v = (y + 0.5)/H$.
   - Compute ray direction in camera space:
     $$ x_{cam} = \text{lerp}(-w/2, w/2, u) $$
     $$ y_{cam} = \text{lerp}(h/2, -h/2, v) $$
     $$ z_{cam} = -1.0 $$
     $$ \mathbf{d}_{cam} = \text{normalize}(x_{cam}, y_{cam}, z_{cam}) $$
   - Transform ray origin and direction using the camera view matrix to world space [S2, unofficial].

2. **Ray-Grid Intersection**:
   Compute entry ($t_{min}$) and exit ($t_{max}$) distances for the ray against the grid AABB defined by `minPoint` and `maxPoint` using the slab method:
   - $\mathbf{r}_{inv} = 1.0 / \mathbf{d}$
   - $t_{min} = \max(\min(\mathbf{r}_{inv} \cdot (\text{minPoint} - \mathbf{p}), \mathbf{r}_{inv} \cdot (\text{maxPoint} - \mathbf{p})))$
   - $t_{max} = \min(\max(\mathbf{r}_{inv} \cdot (\text{minPoint} - \mathbf{p}), \mathbf{r}_{inv} \cdot (\text{maxPoint} - \mathbf{p})))$
   - If $t_{min} > t_{max}$, the ray misses the grid [S2, unofficial].

3. **Ray Marching**:
   Divide the segment $[t_{min}, t_{max}]$ into `bins` (e.g., 100) equal steps of size $\Delta t = (t_{max} - t_{min}) / \text{bins}$ [S2, unofficial].
   For each step $i$ from 0 to `bins`-1:
   - Calculate sample position: $\mathbf{p}_i = \mathbf{p}_{origin} + (t_{min} + i \cdot \Delta t) \cdot \mathbf{d}$.
   - Evaluate cell at $\mathbf{p}_i$ (see **Grid Lookup** and **Trilinear Interpolation**).
   - Let $\sigma$ be density and $\mathbf{c}$ be color from the cell.
   - Accumulate transmittance $T$ and color $\mathbf{C}$:
     $$ T_i = \exp\left(-\sum_{j=0}^{i-1} \sigma_j \Delta t\right) $$
     $$ \mathbf{C} += T_i \cdot (1 - \exp(-\sigma_i \Delta t)) \cdot \mathbf{c}_i $$
   - Note: Some implementations use linear approximation $1 - e^{-\sigma \Delta t} \approx \sigma \Delta t$ for small $\Delta t$ [S2, unofficial].

4. **Grid Lookup & Trilinear Interpolation**:
   Given position $\mathbf{p}$ and ray direction $\mathbf{d}$:
   - Convert $\mathbf{p}$ to integer grid coordinate:
     $$ \text{coord} = \lfloor (\text{grid\_size} - 1) \cdot \frac{\mathbf{p} - \text{minPoint}}{\text{maxPoint} - \text{minPoint}} \rfloor $$
     (Note: Source [S2, unofficial] uses formula $\lfloor (\text{grid}-1) \cdot (\text{pos} + 1.0) / 2 \rfloor$ assuming min/max are -1/1) [S2, unofficial].
   - If `coord` is out of bounds, return black color and zero density [S2, unofficial].
   - Calculate fractional offset:
     $$ \mathbf{s} = \frac{\mathbf{p} - \mathbf{p}_{\text{coord}}}{\mathbf{p}_{\text{coord} + (1,1,1)} - \mathbf{p}_{\text{coord}}} $$
   - Fetch 8 corner cells $C_{ijk}$ where $i,j,k \in \{0,1\}$ using `get(coord + offset, d)` [S2, unofficial].
   - Perform trilinear interpolation on the fetched `float4` (color, density) values [S2, unofficial].

5. **SH Evaluation**:
   For a fetched cell with SH coefficients $\mathbf{S}$ and direction $\mathbf{d}=(x,y,z)$:
   - Evaluate basis functions $\mathbf{Y}(\mathbf{d})$ [S2, unofficial].
   - Color $\mathbf{c} = \mathbf{S} \cdot \mathbf{Y}(\mathbf{d})$ (dot product) [S2, unofficial].

def render_pixel(camera, grid, bins=100):

    # Assuming camera has position, direction, up, fov, and view matrix
    # For a specific pixel (x, y) in WxH image:
    w, h = camera.width, camera.height
    u = (camera.pixel_x + 0.5) / w
    v = (camera.pixel_y + 0.5) / h

    x_cam = -w/2 + u * w
    y_cam = h/2 - v * h
    z_cam = -1.0
    ray_cam = normalize((x_cam, y_cam, z_cam))
    
    # Transform to world space
    ray_dir = camera.view(ray_cam, offset=False)
    ray_orig = camera.view((0,0,0), offset=True) # Origin is camera position
    
    # 2. Ray-Grid Intersection
    # Slab method
    inv_ray = 1.0 / ray_dir
    min_pt = grid.min_point
    max_pt = grid.max_point
    
    t0 = (min_pt - ray_orig) * inv_ray
    t1 = (max_pt - ray_orig) * inv_ray
    tmin = max(min(t0), min(t1)) # Element-wise min/max then reduce
    tmax = min(max(t0), max(t1))
    
    if tmin > tmax:
        return (0.0, 0.0, 0.0)

    dt = (tmax - tmin) / bins
    total_color = (0.0, 0.0, 0.0)

        p = ray_orig + (t + dt/2) * ray_dir # Sample at center of bin

        # Map p to grid coord
        # Formula from [S2, unofficial]: coord = floor((grid-1) * (pos + 1) / 2)

        coord = floor((grid.size - 1) * (p + 1.0) / 2.0)

        # Get 8 corners

        c000 = grid.get(coord)
        c100 = grid.get(coord + (1,0,0))
        c010 = grid.get(coord + (0,1,0))
        c001 = grid.get(coord + (0,0,1))
        c110 = grid.get(coord + (1,1,0))
        c101 = grid.get(coord + (1,0,1))
        c011 = grid.get(coord + (0,1,1))
        c111 = grid.get(coord + (1,1,1))
        
        # Fractional offset
        # p0 is position of coord, p1 is position of coord + (1,1,1)
        # pos_in_grid = coord / (grid.size - 1) * 2 - 1
        # sample = (p - p0) / (p1 - p0)

        # Accumulate
        alpha = 1.0 - math.exp(-sigma * dt)
        total_color += T * alpha * color_rgb
        T *= (1.0 - alpha)
        
        if T < 1e-4:
            break
            
    return total_color

### Parameters
- `bins` (or `constants::bins`): Number of partitions along the ray segment within grid bounds. Default: 100 [S2, unofficial].
- `grid_size`: Dimension of the cubic grid. Default: 128 [S2, unofficial].
- `FOV`: Field of View in radians or degrees [S2, unofficial].

### Edge Cases and Pitfalls
- **Out of Bounds**: If the ray intersection or sample point falls outside the grid bounds $[-1, 1]^3$, return black color and zero density [S2, unofficial].
- **Ray Generation Indexing**: When generating rays for batched images, pixel indices must be clamped to image dimensions $(0 \dots H-1, 0 \dots W-1)$ and converted to appropriate integer types. Note that in tensor access, the y-dimension corresponds to the first index and x to the second [S1, unofficial].
- **Precision**: Using `float` (32-bit) is standard, but precision issues may arise with very small densities or large grids. The source code uses `float` [S2, unofficial].

## Operating characteristics

### Time and Memory Complexity
- **Memory**: $O(N^3)$ where $N$ is the grid dimension. For $N=128$, this is $128^3 \times 28 \times 4 \text{ bytes} \approx 22 \text{ MB}$ [S2, unofficial].
- **Time**: $O(W \cdot H \cdot \text{bins})$ per frame. The evaluation per sample is constant time (SH dot product + trilinear interpolation) [S2, unofficial].

### Measured Performance
- **Hardware**: Intel Core i7-7700HQ, NVIDIA GeForce GTX 1060 [S2, unofficial].
- **Resolution**: 1024x768 [S2, unofficial].
- **CPU Render (1 thread)**: 7.83 seconds [S2, unofficial].
- **CPU Render (OpenMP, 4 threads)**: 1.40 seconds [S2, unofficial].

### Strengths and Limitations
- **Strengths**: Fast inference without neural network overhead; suitable for real-time or near-real-time rendering on CPU; simple data structure [S2, unofficial].
- **Limitations**: View-dependent effects are limited to 2nd-order SH, which may not capture high-frequency specularities or complex lighting as well as higher-order SH or MLPs; static grid resolution limits detail [S2, unofficial].
- **When to use**: When inference speed is critical and high-frequency view-dependent details are not required.
- **When not to use**: When high-fidelity view-dependent effects (e.g., glossy reflections) are needed, or when the scene geometry is too complex for a fixed-resolution grid to capture [S2, unofficial].

## Background
Plenoxels was introduced as an optimization of Neural Radiance Fields (NeRF) to remove the neural network inference step. It uses a sparse 3D grid with Spherical Harmonics to represent color and a scalar field for density. The method was developed to enable faster rendering on consumer devices [S1, S2, unofficial]. The specific implementation details provided here are from unofficial repositories [S1, S2, unofficial].
