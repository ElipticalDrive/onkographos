# LPIPS Evaluation Protocol
Also called: Learned Perceptual Image Patch Similarity

## Overview
LPIPS evaluates perceptual similarity between rendered images and ground truth by measuring distances in a feature space extracted from a pretrained neural network, where lower values indicate higher visual fidelity [S2, unofficial]. It is included in the [Unified Metric Aggregation](3644-unified-metric-aggregation.md) alongside PSNR and SSIM to provide a perceptual quality score that correlates better with human judgment than pixel-wise metrics [S1].

## How it works
**Inputs:** Rendered image tensor and Ground Truth (GT) image tensor.
**Outputs:** A scalar float representing the perceptual distance.

**Data Structures:**
*   Input tensors: Shape $(H, W, C)$ or $(B, H, W, C)$, values in $[0, 1]$.
*   Model: Pretrained VGG-16 feature extractor (specifically layers conv1_2, conv2_2, conv3_3, conv4_3, conv5_3) [S2, unofficial].

**Steps:**
1.  **Scale:** Normalize input tensors from $[0, 1]$ to $[-1, 1]$ using the formula:
    $$ x_{scaled} = 2.0 \cdot x - 1.0 $$
    This aligns the intensity scale with the expectations of the pretrained VGG network [S1][S2, unofficial].
2.  **Batching:** Add a batch dimension if not present:
    $$ x_{batched} = \text{unsqueeze}(x_{scaled}, \text{dim}=0) $$
3.  **Feature Extraction:** Pass both the scaled render and scaled GT through the pretrained VGG network to obtain feature maps $F_{render}$ and $F_{gt}$ [S2, unofficial].
4.  **Distance Calculation:** Compute the normalized $L_2$ distance between the feature maps. For each layer $l$, the distance is:
    $$ d_l = \frac{1}{H_l W_l C_l} \sum_{i,j,k} \frac{(F_{render}^{l,i,j,k} - F_{gt}^{l,i,j,k})^2}{\alpha_l} $$
    where $\alpha_l$ is a learned or fixed normalization constant per layer [S2, unofficial].
5.  **Aggregation:** Sum the distances across all layers and return the mean as the final LPIPS score [S2, unofficial].

**Parameters:**
*   `net`: "vgg" (specifies the VGG-16 backbone) [S2, unofficial].
*   `normalize`: True (implicit in the scaling step) [S1][S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Intensity Scale:** Using the default $[0, 1]$ range without scaling to $[-1, 1]$ yields incorrect results. The evaluation must use the $[-1, 1]$ scale as specified by the protocol [S1].
*   **Network Weights:** The first execution downloads pretrained weights to the `TORCH_HOME` cache directory. This requires an internet connection or pre-cached weights [S2, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn as nn
import lpips # Assuming lpips library is available as per [S2, unofficial]

def compute_lpips(render: torch.Tensor, gt: torch.Tensor) -> float:
    """
    Compute LPIPS between render and gt.
    Inputs: render, gt tensors of shape (H, W, C) or (B, H, W, C), values in [0, 1].
    Returns: float LPIPS score.
    """
    # 1. Scale from [0, 1] to [-1, 1]
    render_scaled = 2.0 * render - 1.0
    gt_scaled = 2.0 * gt - 1.0
    
    # 2. Ensure batch dimension
    if render_scaled.dim() == 3:
        render_scaled = render_scaled.unsqueeze(0)
    if gt_scaled.dim() == 3:
        gt_scaled = gt_scaled.unsqueeze(0)
        
    # 3. Load model (lazy load or pre-load)
    # net = lpips.LPIPS(net='vgg') 
    # Note: First run downloads weights to TORCH_HOME [S2, unofficial]
    
    # 4. Compute distance
    # The lpips library handles feature extraction and normalized L2 distance
    loss_fn = lpips.LPIPS(net='vgg')
    loss_fn.eval() # Set to evaluation mode
    
    # 5. Return mean
    # lpips returns a tensor of shape (B,)
    scores = loss_fn(render_scaled, gt_scaled)
    return scores.mean().item()
```

## Subtopics

### LPIPS Computation
This refers to the specific implementation detail of using the VGG-16 backbone to extract multi-layer features and computing the normalized $L_2$ distance between them [S2, unofficial]. It is chosen for its strong correlation with human perceptual judgments compared to other architectures like AlexNet or ResNet, though VGG is the standard reference in this context [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by the forward pass of the VGG-16 network. For a single image, this is negligible compared to rendering but adds overhead to the evaluation loop.
*   **Memory Complexity:** Requires loading the VGG-16 weights into memory. The feature maps are stored temporarily during the forward pass.
*   **Strengths:** Provides a perceptual metric that correlates well with human opinion scores, addressing the limitations of PSNR/SSIM [S2, unofficial].
*   **Limitations:** Requires a pretrained model and internet access for initial weight download [S2, unofficial]. It is not differentiable with respect to the scene parameters in the same way as the training loss, so it is used only for evaluation [S2, unofficial].
*   **When to use:** When perceptual quality is more important than pixel-wise accuracy, or as a complementary metric to PSNR/SSIM [S1].

## Background
LPIPS was introduced as a learned perceptual image patch similarity metric [S2, unofficial]. It is widely used in the evaluation of generative models and novel view synthesis, including NeRF and 3D Gaussian Splatting variants, to assess visual fidelity [S1][S2, unofficial].
