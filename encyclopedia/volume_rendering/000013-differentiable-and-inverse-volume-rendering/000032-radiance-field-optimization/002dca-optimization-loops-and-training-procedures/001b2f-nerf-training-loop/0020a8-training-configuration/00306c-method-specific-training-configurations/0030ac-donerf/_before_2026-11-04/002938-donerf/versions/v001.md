# DONeRF

Also called: DONeRF Training Setup, Depth Oracle Network Training

## Overview
DONeRF training configuration defines the optimization procedure for the two-stage neural network architecture (depth oracle and shading networks) that enables real-time rendering with very few samples per ray. It solves the problem of high-frequency detail loss and slow convergence in standard NeRF by decoupling depth estimation from color/shading prediction. Unlike standard NeRF which samples uniformly or via hierarchical sampling along the entire ray, DONeRF uses a depth oracle to predict a probability distribution over discretized depth ranges, allowing the shading network to focus computational budget on the surface. It differs from [NeRF Hyperparameters](3065-nerf-hyperparameters.md) by enforcing a strict two-phase training schedule and specific opacity regularization to prevent dark pixel artifacts at low sample counts.

## How it works
The method consists of two distinct training phases: training the Depth Oracle Network and training the Shading Network. The configuration assumes the presence of ground truth depth maps; if unavailable, a dense NeRF is trained first to generate pseudo-ground truth (see [DONeRF Oracle Input Construction](#donerf-oracle-input-construction)).

### Inputs and Outputs
*   **Inputs:** Camera poses, image pixels (RGB), and optionally ground truth depth maps.
*   **Outputs:** RGB color values for novel views.

### Data Structures and Network Layout
Both the Depth Oracle Network and the Shading Network share the same architecture:
*   **Layers:** 8 hidden layers.
*   **Hidden Units:** 256 units per layer.
*   **Activation:** Not specified in sources [G: Standard ReLU is implied for MLPs of this era, but not explicitly stated].

**Depth Oracle Network:**
*   **Input:** 3D positions along the ray (see [DONeRF Oracle Input Construction](#donerf-oracle-input-construction)).
*   **Output:** Probability distribution over discretized depth bins (classification).

**Shading Network:**
*   **Input:** 3D positions warped towards the view cell, features from the depth oracle.
*   **Output:** RGB color and opacity ($\delta$) for each sample.

### Training Schedule
The training is performed in two sequential stages, each lasting 300,000 iterations.

1.  **Phase 1: Depth Oracle Training**
    *   Train the Depth Oracle Network for 300,000 iterations.
    *   Loss: Binary Cross-Entropy (BCE) on the depth classification targets.
    *   *Note:* If ground truth depth is missing, a dense NeRF (12 layers, 512 hidden units, 128 samples/ray) is trained first to extract depth maps, which are then used as ground truth for this phase [S1].

2.  **Phase 2: Shading Network Training**
    *   Freeze the Depth Oracle Network.
    *   Train the Shading Network for 300,000 iterations using the oracle's predictions to guide sampling.
    *   Loss: Weighted sum of MSE and Opacity Loss (see Formulas).

### Optimizer and Hyperparameters
*   **Optimizer:** Adam [KB15].
*   **Learning Rate:** $0.0005$.
*   **Batch Size:** 4096 samples per iteration.
*   **Final Configuration Parameters:**
    *   Neighborhood Filter Size ($K$): 5.
    *   Depth Smoothing Filter Size ($Z$): 5.
    *   Number of Oracle Inputs ($I$): 128.
    *   Samples per Ray ($N$): Variable (DONeRF-2, DONeRF-4, etc.).

### Formulas
**Opacity Loss ($\text{loss}_O$):**
This term prevents "cheating" where the network mixes background color via opacity to satisfy RGB loss, causing dark pixels. It forces accumulated opacity to be at least 1.
$$
\text{loss}_O = \begin{cases} 
0, & \text{if } \sum_{i=1}^X \delta_i \geq 1 \\
\left( \left( \sum_{i=1}^X \delta_i \right) - 1 \right)^2, & \text{otherwise}
\end{cases}
$$
Where:
*   $X$ is the number of samples per ray.
*   $\delta_i$ is the opacity of the $i$-th sample.

**Total Loss:**
$$
\text{loss} = \alpha \cdot \text{loss}_{\text{MSE}} + \beta \cdot \text{loss}_{\text{O}}
$$
Where:
*   $\text{loss}_{\text{MSE}}$ is the Mean Squared Error between predicted and ground truth RGB.
*   $\alpha = 1.0$.
*   $\beta = 10.0$.

### Pseudocode
```python
# Configuration
NUM_ITERATIONS = 300000
LEARNING_RATE = 0.0005
BATCH_SIZE = 4096
ALPHA = 1.0
BETA = 10.0
NUM_HIDDEN_LAYERS = 8
HIDDEN_UNITS = 256
NUM_SAMPLES_RAY = 4  # Example for DONeRF-4

# Phase 1: Train Depth Oracle
oracle_net = MLP(layers=NUM_HIDDEN_LAYERS, units=HIDDEN_UNITS)
optimizer_oracle = Adam(oracle_net.parameters(), lr=LEARNING_RATE)

for iteration in range(NUM_ITERATIONS):
    # Sample rays and get 3D positions (log-transformed, centered in depth bins)
    rays, positions = sample_rays(batch_size=BATCH_SIZE)
    
    # Get oracle predictions (probability distribution over depth bins)
    oracle_preds = oracle_net(positions)
    
    # Calculate BCE loss against ground truth depth bins
    loss_oracle = BCE_Loss(oracle_preds, ground_truth_depth_bins)
    
    optimizer_oracle.zero_grad()
    loss_oracle.backward()
    optimizer_oracle.step()

# Phase 2: Train Shading Network
shading_net = MLP(layers=NUM_HIDDEN_LAYERS, units=HIDDEN_UNITS)
optimizer_shading = Adam(shading_net.parameters(), lr=LEARNING_RATE)

for iteration in range(NUM_ITERATIONS):
    # Sample rays
    rays, positions = sample_rays(batch_size=BATCH_SIZE)
    
    # Get depth distribution from frozen oracle
    depth_dist = oracle_net(positions)
    
    # Warp positions and generate features (Space Warping)
    warped_positions, features = warp_and_generate_features(positions, rays)
    
    # Get shading predictions (RGB and Opacity)
    rgb_pred, opacity_pred = shading_net(warped_positions, features)
    
    # Calculate MSE Loss
    loss_mse = MSE_Loss(rgb_pred, ground_truth_rgb)
    
    # Calculate Opacity Loss
    accumulated_opacity = sum(opacity_pred)
    if accumulated_opacity < 1.0:
        loss_opacity = (accumulated_opacity - 1.0) ** 2
    else:
        loss_opacity = 0.0
    
    # Total Loss
    loss = ALPHA * loss_mse + BETA * loss_opacity
    
    optimizer_shading.zero_grad()
    loss.backward()
    optimizer_shading.step()
```

## Subtopics

### DONeRF Oracle Input Construction
The depth oracle network requires specific input construction to effectively guide the shading network.
*   **Inputs:** 3D positions along the ray are provided as additional inputs to the first network layer.
*   **Positioning:** These positions are placed at the centers of the discretized depth ranges.
*   **Transformation:** A logarithmic transformation is applied to the classification steps (depth ranges) to align with the shading network's logarithmic sampling strategy [S1].
*   **Encoding:** Positional or Fourier encoding is **not** used for depth oracle inputs, as experiments showed it did not improve results [S1].
*   **Parameter ($I$):** The number of 3D input positions provided to the oracle. Tested values are 1 to 128. The final configuration uses $I=128$ [S1].
*   **Impact:** Providing multiple samples along the ray as input adds approximately 1 dB to PSNR. Using a classification network (oracle) instead of predicting a single depth value adds 0.6 dB–1.5 dB to PSNR [S1].

## Operating characteristics
*   **Performance:** On an NVIDIA RTX 3090 at 800x800 resolution with 2 samples per ray, total inference time is 51.3 ms (~20 fps) [S1].
    *   Breakdown: Ray unification/feature gen (0.21 ms), Oracle network (12.64 ms), Space warping/second feature gen (3.46 ms), Shading network (34.9 ms), Final color gen (0.09 ms) [S1].
*   **Scaling:** Shading network cost scales nearly linearly with the number of samples: 34.9 ms (2 samples), 65.4 ms (4 samples), 136.4 ms (8 samples), 270.4 ms (16 samples) [S1].
*   **Quality vs. NeRF:** DONeRF achieves equal or better quality with 2–4 samples per ray compared to NeRF's 256. At 16 samples, DONeRF is up to 7 dB higher PSNR and 15–78x faster than NeRF [S1].
*   **Quality vs. NSVF:** NSVF-medium/large are similar in quality to DONeRF-2/4 but are 43x slower. NSVF requires 2x more memory for competitive quality and 6x longer training [S1].
*   **Quality vs. LLFF:** LLFF uses >1000x more memory and achieves lower quality. LLFF is faster for novel view generation due to simple blending but lacks neural representation capabilities [S1].
*   **Quality vs. NeX:** NeX is 45x faster but requires 25x more memory and is 3 dB lower quality than DONeRF-2. NeX-MLP is better quality but DONeRF is 10x faster and 25x more compact [S1].
*   **Limitations:**
    *   **Reflective/Transparent Surfaces:** Low sample counts and single depth estimates are insufficient for mirrors or refractive water [S1].
    *   **Dark Pixel Artifacts:** Occur at low sample counts if opacity does not accumulate to 1. Remedied by the opacity loss term [S1].
    *   **No-GT Training:** Without ground truth depth, background noise from the initialization NeRF can create high-frequency depth values in empty space, leading to zero-contribution samples [S1].

## Background
DONeRF was introduced in the paper "DONeRF: Towards Real‐Time Rendering of Compact Neural Radiance Fields using Depth Oracle Networks" [S1]. The method addresses the computational bottleneck of standard NeRF by using a depth oracle to concentrate samples on surfaces. It builds on the concept of differentiable volume rendering but introduces a specialized training configuration involving a two-stage network and specific regularization to enable real-time performance on consumer hardware.
