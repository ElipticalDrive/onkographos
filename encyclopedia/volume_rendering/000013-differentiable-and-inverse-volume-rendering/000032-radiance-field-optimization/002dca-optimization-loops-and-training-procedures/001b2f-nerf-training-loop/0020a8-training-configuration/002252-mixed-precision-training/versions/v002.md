# Mixed Precision Training

Also called: AMP Training, FP16 Training, Mixed Precision Training with Fallback

## Overview
Mixed Precision Training accelerates NeRF optimization on CUDA devices by utilizing Automatic Mixed Precision (AMP) to perform computations in lower precision formats while maintaining numerical stability [S1, unofficial]. It differs from standard single-precision training by automating precision casting and loss scaling within the PyTorch training loop [S1, unofficial][S2, unofficial].

## How it works
The method integrates into the standard NeRF training loop by wrapping the forward pass in an automatic precision context manager and applying gradient scaling to prevent underflow in lower-precision gradients [S1, unofficial][S2, unofficial].

**Inputs and Outputs**
*   **Inputs**: Model parameters, optimizer, scheduler, dataset, `use_mixed_precision` flag, and `scaler` instance [S1, unofficial][S2, unofficial].
*   **Outputs**: Updated model parameters, updated optimizer state, updated scaler state, computed loss values, and checkpoint files [S2, unofficial].

**Data Structures**
*   `scaler`: A gradient scaler instance (e.g., `torch.cuda.amp.GradScaler`) that maintains a scale factor for loss values [S1, unofficial].
*   `Loss` and `Epochs`: Empty lists initialized to track loss values and iteration counts for logging [S2, unofficial].

**Parameters**
*   `use_mixed_precision`: Boolean flag to enable/disable AMP [S1, unofficial].
*   `scaler`: Gradient scaler instance initialized with default parameters [S1, unofficial].

**Steps**
1.  **Initialization**: Create a gradient scaler instance and initialize empty lists for `Loss` and `Epochs` [S2, unofficial].
2.  **Iteration Loop**: Iterate `i` from `start_iter` to `num_iters` [S2, unofficial].
3.  **Mode Set**: Set the model to training mode (`model.train()`) [S2, unofficial].
4.  **Data Selection**: Randomly select 4 target images from the dataset using `np.random.choice` on `images.shape[0]` [S2, unofficial].
5.  **Device Transfer**: Extract the target image tensor (`target_img`) and the camera-to-world transformation matrix (`target_tform_cam2world`), moving the transform to the device [S2, unofficial].
6.  **Autocast Context**: Enter the mixed precision context using `torch.cuda.amp.autocast()` (or `torch.amp.autocast('cuda')` for newer PyTorch versions) [S1, unofficial][S2, unofficial].
7.  **Forward Pass**: Call the rendering function with `height`, `width`, `focal_length`, `target_tform_cam2world`, `near_thresh`, `far_thresh`, `depth_samples_per_ray`, and `get_minibatches` to obtain `rgb_predicted` [S2, unofficial].
8.  **Shape Adjustment**: Squeeze the first dimension of `rgb_predicted` to match the target image shape [S2, unofficial].
9.  **Loss Computation**: Compute the mean-squared error (MSE) loss between `rgb_predicted` and `target_img` [S1, unofficial][S2, unofficial].
10. **Gradient Scaling & Backward**: Scale the loss, call `backward()`, step the optimizer, update the scaler, and zero gradients with `set_to_none=True` [S1, unofficial][S2, unofficial].
11. **Scheduler Step**: Step the learning rate scheduler [S2, unofficial].
12. **Checkpointing**: If `i % save_every == 0`, append `loss.item()` to `Loss` and `i+1` to `Epochs`, save a checkpoint to `checkpoint_dir/checkpoint_{i}.pt` containing `model_state_dict`, `optimizer_state_dict`, `loss`, `iteration`, `scaler.state_dict()`, and `scheduler.state_dict()`, and plot figures [S2, unofficial].

**Pseudocode**

```python
import torch
import numpy as np
import os

def train_with_mixed_precision(
    model, 
    optimizer, 
    scheduler, 
    dataset, 
    num_iters, 
    start_iter, 
    save_every, 
    checkpoint_dir,
    device='cuda'
):
    # Initialize scaler for mixed precision
    scaler = torch.cuda.amp.GradScaler()
    
    # Logging structures
    Loss = []
    Epochs = []
    
    # Pre-fetch full data for random selection (example from source)
    images, tforms, _ = dataset.get_full_data(device)
    
    for i in range(start_iter, num_iters):
        model.train()
        
        # Randomly select 4 target images
        indices = np.random.choice(images.shape[0], 4, replace=False)
        target_img = images[indices].to(device)
        target_tform_cam2world = tforms[indices].to(device)
        
        # Mixed precision context
        with torch.cuda.amp.autocast():
            # Forward pass
            rgb_predicted = render_rays(
                model=model,
                target_tform_cam2world=target_tform_cam2world,
                height=target_img.shape[1],
                width=target_img.shape[2],
                focal_length=dataset.focal_length,
                near_thresh=dataset.near_thresh,
                far_thresh=dataset.far_thresh,
                depth_samples_per_ray=dataset.depth_samples_per_ray,
                device=device
            )
            
            # Squeeze dimension if necessary
            if rgb_predicted.dim() > 3:
                rgb_predicted = rgb_predicted.squeeze(0)
                
            # Compute Loss
            loss = torch.mean((rgb_predicted - target_img) ** 2)
            
            # Scale loss and backward
            scaler.scale(loss).backward()
            
            # Optimizer step
            scaler.step(optimizer)
            scaler.update()
            
            # Zero gradients
            optimizer.zero_grad(set_to_none=True)
            
        # Step scheduler
        scheduler.step()
        
        # Checkpointing
        if i % save_every == 0:
            Loss.append(loss.item())
            Epochs.append(i + 1)
            
            checkpoint_path = os.path.join(checkpoint_dir, f"checkpoint_{i}.pt")
            torch.save({
                'model_state_dict': model.state_dict(),
                'optimizer_state_dict': optimizer.state_dict(),
                'loss': loss.item(),
                'iteration': i,
                'scaler_state_dict': scaler.state_dict(),
                'scheduler_state_dict': scheduler.state_dict()
            }, checkpoint_path)
            
            # Plotting (implementation detail)
            plot_figures(Epochs, Loss)
```

**Edge Cases and Pitfalls**
*   **Precision Compatibility**: Older PyTorch versions require `torch.cuda.amp.autocast()` while newer versions use `torch.amp.autocast('cuda')` [S1, unofficial].
*   **Gradient Underflow**: Without the gradient scaler, FP16 gradients may underflow to zero, causing training to stall [G].
*   **Memory Management**: Using `set_to_none=True` in `zero_grad()` helps reduce memory fragmentation during long training runs [S2, unofficial].
*   **Checkpointing**: The scaler state must be saved and restored to ensure consistent training behavior across restarts [S2, unofficial].

## Subtopics

### AMP Training
Also called: Automatic Mixed Precision Training. This is the standard implementation of Mixed Precision Training using PyTorch's AMP API [S1, unofficial]. It automatically casts operations to lower precision formats where beneficial and keeps reductions in FP32 [G]. Choose this when using modern CUDA hardware and PyTorch 1.6+ [G].

### FP16 Training
Also called: Half-Precision Training. This refers to the specific use of FP16 data types within the AMP framework [S2, unofficial]. It is chosen when memory bandwidth is the primary bottleneck and the hardware supports FP16 tensor cores [G]. Note that manual FP16 training requires careful handling of loss scaling and gradient clipping, which AMP automates [S2, unofficial].

### Mixed Precision Training with Fallback
Also called: Robust Mixed Precision. This variant includes logic to detect overflow or instability (e.g., NaN losses) and fallback to FP32 for specific operations or the entire training loop if necessary [G]. It is chosen for older hardware or unstable training configurations where standard AMP might fail [G].
