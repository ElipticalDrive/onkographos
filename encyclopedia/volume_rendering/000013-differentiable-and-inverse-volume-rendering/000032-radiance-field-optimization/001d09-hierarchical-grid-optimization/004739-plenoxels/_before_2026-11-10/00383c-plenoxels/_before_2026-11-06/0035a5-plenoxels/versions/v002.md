# Plenoxels

Also called: Radiance Fields without Neural Networks

## Overview
Plenoxels is an explicit radiance field representation that replaces the neural network used in NeRF with a sparse 3D voxel grid storing density and spherical harmonic (SH) coefficients [S1, S2][S5, unofficial]. It solves the computational bottleneck of neural network inference during training and rendering, achieving training speeds two orders of magnitude faster than NeRF while maintaining comparable image quality [S1][S7, unofficial]. Unlike implicit representations, Plenoxels allows for direct data access via trilinear interpolation, trading increased memory consumption for significant gains in optimization and rendering efficiency [S1][S5, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ calibrated images with known camera poses (intrinsics and extrinsics). Optional: Depth priors for pre-pruning [S2].
*   **Outputs:** Optimized voxel grids $V^D$ (density) and $V^{SH}$ (SH coefficients), and rendered novel view images.

**Data Structures:**
The scene is represented by two sparse 3D voxel grids [S2][S5, unofficial]:
1.  **Density Grid ($V^D$):** Stores a single scalar value $\sigma$ (volume density) per voxel.
2.  **SH Grid ($V^{SH}$):** Stores spherical harmonic coefficients per voxel. For 2nd-order SH (degree $\ell_{max}=1$), there are 9 coefficients per color channel (R, G, B).
    *   **Voxel Layout:** Each voxel vertex stores 28 float values: 1 for density and $9 \times 3 = 27$ for SH coefficients (9 per RGB channel) [S1][S7, unofficial].
    *   **Memory:** The grid is typically dense in memory for the bounding box, though sparsity is handled by ignoring empty regions or using sparse tensor formats [S3][S5, unofficial]. Standard resolutions are $128^3$ for synthetic scenes and $512 \times 512 \times 128$ for forward-facing scenes [S3].

**Spherical Harmonics Basis:**
Plenoxels uses 2nd-order SH ($\ell_{max}=1$) to model view-dependent color [S3][S7, unofficial]. The basis functions $Y_\ell^m(\mathbf{d})$ for a direction $\mathbf{d}=(x,y,z)$ are [S7, unofficial]:
$$
\begin{aligned}
Y_0 &= 0.282095 \\
Y_1^z &= 0.488603 z \\
Y_1^x &= -0.488603 x \\
Y_1^y &= -0.488603 y
\end{aligned}
$$
Higher orders (e.g., $\ell=2$) are sometimes used in variants but the original Plenoxels uses $\ell=1$ [S3]. Note: Some implementations use $\ell=2$ (15 coefficients per channel) for higher fidelity [S3], but the core definition relies on the explicit storage of these coefficients.

**Rendering Pipeline:**
For a ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$, the color $\hat{C}(\mathbf{r})$ is computed using standard volume rendering [S1, S2]:
$$
\hat{C}(\mathbf{r}) = \sum_{i=1}^N T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i
$$
where $\delta_i$ is the step size, $\sigma_i$ is the density, and $T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right)$ is the transmittance [S1, S2].

**Step-by-Step Method:**

1.  **Ray Generation:**
    For each pixel $(u, v)$ in the target image, generate a ray origin $\mathbf{o}$ and direction $\mathbf{d}$ using camera intrinsics and extrinsics [S5, S7, unofficial].
    *   Normalize $\mathbf{d}$.

2.  **Ray Marching Setup:**
    Determine the intersection of the ray with the voxel grid's Axis-Aligned Bounding Box (AABB) $[\mathbf{min}, \mathbf{max}]$ using the slab method [S7, unofficial].
    *   Compute reciprocal ray direction $\mathbf{r}_{inv} = 1/\mathbf{d}$.
    *   $t_{min} = \max(\min(\mathbf{r}_{inv} \cdot (\mathbf{min} - \mathbf{o}), \mathbf{r}_{inv} \cdot (\mathbf{max} - \mathbf{o})))$.
    *   $t_{max} = \min(\max(\mathbf{r}_{inv} \cdot (\mathbf{min} - \mathbf{o}), \mathbf{r}_{inv} \cdot (\mathbf{max} - \mathbf{o})))$.
    *   If $t_{min} > t_{max}$, the ray misses the grid.

3.  **Sampling:**
    Sample points along the ray segment $[t_{min}, t_{max}]$ with a fixed step size $\delta$ (or adaptive steps) [S5, S7, unofficial]. Let sample points be $\mathbf{x}_i = \mathbf{o} + t_i \mathbf{d}$.

4.  **Density and Color Retrieval:**
    For each sample point $\mathbf{x}_i$:
    *   **Trilinear Interpolation:** Calculate the integer lattice coordinates $\mathbf{l} = \lfloor \mathbf{x}_i \rfloor$ and fractional offsets $\mathbf{f} = \mathbf{x}_i - \mathbf{l}$ [S5, unofficial].
    *   Fetch the 8 neighboring voxels from $V^D$ and $V^{SH}$ [S1][S5, unofficial].
    *   **Density:** $\sigma_i = \text{ReLU}(\text{interp}(\mathbf{x}_i, V^D))$ [S2]. The ReLU ensures non-negative density.
    *   **SH Coefficients:** $\mathbf{k}_i = \text{interp}(\mathbf{x}_i, V^{SH})$ [S2].
    *   **Color:** Compute color $\mathbf{c}_i$ by projecting $\mathbf{k}_i$ onto the SH basis functions evaluated at $\mathbf{d}$, followed by ReLU [S2, S4]:
        $$
        \mathbf{c}_i = \text{ReLU}\left( \sum_{\ell=0}^{\ell_{max}} \sum_{m=-\ell}^{\ell} \mathbf{k}_{i, \ell m} Y_\ell^m(\mathbf{d}) \right)
        $$
        where $\mathbf{k}_{i, \ell m}$ are the SH coefficients for the RGB channels [S2, S3].

5.  **Accumulation:**
    Update transmittance and accumulated color [S5, unofficial]:
    *   $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$.
    *   $T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right)$.
    *   $\hat{C}(\mathbf{r}) += T_i \alpha_i \mathbf{c}_i$.
    *   Update transmittance for next step: $T_{i+1} = T_i (1 - \alpha_i)$.

6.  **Early Termination:**
    If $T_i < \epsilon$ (e.g., $10^{-4}$), terminate ray marching [S5, unofficial]. Add background color if necessary: $\hat{C}(\mathbf{r}) += T_i \mathbf{c}_{bg}$ [S5, unofficial].

7.  **Optimization (Backward Pass):**
    Compute gradients of the photometric loss $\mathcal{L}_{MSE} = \|\hat{C} - C_{gt}\|^2$ with respect to $\sigma$ and $\mathbf{k}$ [S1, S2].
    *   **Analytic Gradients:** Derive closed-form gradients for the volume rendering equation to avoid storing intermediate states for all samples, reducing memory to $O(N)$ [S5, unofficial].
    *   **Regularization:** Apply Total Variation (TV) loss to smooth density and SH coefficients [S2]:
        $$
        \mathcal{L}_{TV}(V^D) = \frac{1}{|V|} \sum_{\mathbf{v} \in V} \sqrt{\Delta_x^2(\mathbf{v}) + \Delta_y^2(\mathbf{v}) + \Delta_z^2(\mathbf{v})}
        $$
        $$
        \mathcal{L}_{TV}(V^{SH}) = \frac{1}{|V|} \sum_{\mathbf{v} \in V} \sum_{d \in [D]} \sqrt{\Delta_x^2(\mathbf{v}, d) + \Delta_y^2(\mathbf{v}, d) + \Delta_z^2(\mathbf{v}, d)}
        $$
        where $\Delta_x(\mathbf{v})$ is the difference between voxel $\mathbf{v}$ and its neighbor in the x-direction [S2].

**Pseudocode:**

```python
import numpy as np

def trilinear_interpolate(grid, pos):
    """
    Interpolate value from a 3D grid at continuous position pos.
    grid: numpy array of shape (D, H, W, C) or (D, H, W)
    pos: array of shape (3,) with coordinates in grid space [0, size-1]
    """
    # Clamp pos to valid range
    pos = np.clip(pos, 0, np.array(grid.shape[:3]) - 1)
    
    # Integer coordinates
    ix, iy, iz = np.floor(pos).astype(int)
    # Fractional offsets
    fx, fy, fz = pos - np.floor(pos)
    
    # Fetch 8 neighbors
    # Handle boundary conditions by clamping indices
    def get_val(x, y, z):
        x = np.clip(x, 0, grid.shape[0] - 1)
        y = np.clip(y, 0, grid.shape[1] - 1)
        z = np.clip(z, 0, grid.shape[2] - 1)
        return grid[x, y, z]

    c000 = get_val(ix, iy, iz)
    c100 = get_val(ix + 1, iy, iz)
    c010 = get_val(ix, iy + 1, iz)
    c110 = get_val(ix + 1, iy + 1, iz)
    c001 = get_val(ix, iy, iz + 1)
    c101 = get_val(ix + 1, iy, iz + 1)
    c011 = get_val(ix, iy + 1, iz + 1)
    c111 = get_val(ix + 1, iy + 1, iz + 1)

    # Interpolate along X
    c00 = c000 * (1 - fx) + c100 * fx
    c01 = c010 * (1 - fx) + c110 * fx
    c10 = c001 * (1 - fx) + c101 * fx
    c11 = c011 * (1 - fx) + c111 * fx

    # Interpolate along Y
    c0 = c00 * (1 - fy) + c01 * fy
    c1 = c10 * (1 - fy) + c11 * fy

    # Interpolate along Z
    result = c0 * (1 - fz) + c1 * fz
    return result

def evaluate_sh(coefficients, direction):
    """
    Evaluate 2nd order SH (degree 1) for a given direction.
    coefficients: array of shape (3, 9) for RGB channels, 9 SH coeffs per channel.
    direction: array of shape (3,) normalized vector (x, y, z).
    Returns: color array of shape (3,)
    """
    x, y, z = direction
    # SH Basis functions for degree 1
    # Y0: 0.282095
    # Y1z: 0.488603 * z
    # Y1x: -0.488603 * x
    # Y1y: -0.488603 * y
    # Note: Standard Plenoxels uses degree 1 (9 coeffs). 
    # If degree 2 is used, more basis functions are needed.
    
    # Basis values [Y0, Y1z, Y1x, Y1y, ...] (remaining 5 are 0 for degree 1)
    # Actually, for degree 1, we only have 4 non-zero basis functions? 
    # No, SH degree l has 2l+1 coefficients. l=0 -> 1, l=1 -> 3. Total 4.
    # But Plenoxels stores 9 coefficients per channel? 
    # Source [S1] says "nine values per color channel". 
    # Source [S3] says "SH degree 2". 
    # Let's assume degree 2 (15 coeffs) or degree 1 with padding?
    # Standard Plenoxels paper uses degree 2 (15 coeffs) for better quality?
    # Wait, [S3] says "SH degree: 2". [S7, unofficial] says "shsize = 9".
    # Let's implement degree 1 (4 coeffs) as per [S7, unofficial] and [S1] might refer to something else or higher order.
    # Actually, [S1] says "nine values per color channel". This implies degree 2 (15) or maybe just 9 for some reason?
    # Let's stick to the formula in [S2] which sums up to l_max.
    # If l_max=1, sum is l=0 (1) + l=1 (3) = 4 coeffs.
    # If l_max=2, sum is 1 + 3 + 5 = 9 coeffs.
    # So "nine values" implies l_max=2.
    
    # Re-evaluating based on [S1] "nine values" and [S3] "SH degree 2".
    # We will implement degree 2 (9 coeffs per channel).
    
    # Basis functions for l=0,1,2
    # l=0: Y0 = 0.282095
    # l=1: Y1z = 0.488603*z, Y1x = -0.488603*x, Y1y = -0.488603*y
    # l=2: 
    # Y2z2 = 0.946175*z^2 - 0.315392
    # Y2xz = -1.092548*z*x
    # Y2yz = -1.092548*z*y
    # Y2x2y2 = 0.546274*(x^2 - y^2)
    # Y2xy = 1.092548*x*y  (Note: [S7, unofficial] code uses 2xy for one, but standard is xy. Let's use standard)
    
    # Coefficients layout: [l=0, l=1z, l=1x, l=1y, l=2z2, l=2xz, l=2yz, l=2x2y2, l=2xy]
    # This matches 9 coefficients.
    
    basis = np.array([
        0.282095,
        0.488603 * z,
        -0.488603 * x,
        -0.488603 * y,
        0.946175 * z**2 - 0.315392,
        -1.092548 * z * x,
        -1.092548 * z * y,
        0.546274 * (x**2 - y**2),
        1.092548 * x * y
    ])
    
    # coefficients shape: (3, 9)
    # Dot product for each channel
    color = np.dot(coefficients, basis)
    
    # Apply ReLU
    color = np.maximum(color, 0.0)
    return color

def render_plenoxels(ray_origin, ray_direction, grid_density, grid_sh, grid_size, step_size=0.01):
    """
    Render a single ray using Plenoxels.
    """
    # 1. Ray-Grid Intersection
    # Assume grid is centered at origin with size grid_size in [-1, 1]
    # AABB: min=-1, max=1
    min_pt = -1.0
    max_pt = 1.0
    
    ray_inv = 1.0 / ray_direction
    t_min = np.max(np.minimum((min_pt - ray_origin) * ray_inv, (max_pt - ray_origin) * ray_inv))
    t_max = np.min(np.maximum((min_pt - ray_origin) * ray_inv, (max_pt - ray_origin) * ray_inv))
    
    if t_min > t_max:
        return np.array([0.0, 0.0, 0.0]) # Background
    
    # 2. Ray Marching
    num_samples = int((t_max - t_min) / step_size)
    if num_samples <= 0:
        return np.array([0.0, 0.0, 0.0])
        
    t_values = np.linspace(t_min, t_max, num_samples + 1)[1:] # Exclude start
    
    accumulated_color = np.zeros(3)
    accumulated_transmittance = 1.0
    
    for t in t_values:
        # Sample point
        pos = ray_origin + t * ray_direction
        
        # Convert to grid coordinates (assuming grid is in [-1, 1])
        # Grid coords: 0 to grid_size-1
        grid_pos = (pos + 1.0) / 2.0 * (grid_size - 1)
        
        # 3. Interpolate Density
        sigma = np.clip(trilinear_interpolate(grid_density, grid_pos), 0, None)
        
        if sigma < 1e-4: # Skip empty space
            continue
            
        # 4. Interpolate SH Coefficients
        sh_coeffs = trilinear_interpolate(grid_sh, grid_pos) # Shape (3, 9)
        
        # 5. Evaluate Color
        color = evaluate_sh(sh_coeffs, ray_direction)
        
        # 6. Accumulate
        alpha = 1.0 - np.exp(-sigma * step_size)
        weight = accumulated_transmittance * alpha
        accumulated_color += weight * color
        accumulated_transmittance *= (1.0 - alpha)
        
        if accumulated_transmittance < 1e-4:
            break
            
    # Add background
    accumulated_color += accumulated_transmittance * np.array([0.0, 0.0, 0.0]) # Assuming black background
    
    return accumulated_color
```

**Parameters:**
*   **Grid Resolution:** $128^3$ for synthetic scenes, $512 \times 512 \times 128$ for LLFF [S3].
*   **SH Degree:** 2 (9 coefficients per channel) [S1, S3].
*   **Step Size:** Fixed step size for ray marching [S5, unofficial].
*   **Sigma Threshold:** Minimum density to process [S5, unofficial].
*   **Stop Threshold:** Transmittance threshold for early termination [S5, unofficial].

**Edge Cases and Pitfalls:**
*   **Memory Footprint:** Performance depends excessively on spatial resolution, leading to large memory usage [S3].
*   **Bank Conflicts:** In GPU implementations, accessing SH basis values can cause bank conflicts [S5, unofficial].
*   **Clamping:** Color accumulation uses `fmaxf` to clamp to non-negative values, which affects gradient computation [S5, unofficial].
*   **Overfitting:** Near-camera floaters can occur due to gradient imbalance; transmittance-based gradient scaling is recommended [S2].

## Operating characteristics
*   **Time Complexity:** Rendering is $O(N)$ per ray, where $N$ is the number of samples. Training is significantly faster than NeRF (two orders of magnitude) due to the elimination of MLP inference [S1].
*   **Memory Complexity:** $O(R^3)$ for a grid of resolution $R$, as it stores explicit values for every voxel in the bounding box [S3]. This is higher than hash-based or tree-based methods for high resolutions.
*   **Performance:** On a GTX 1060, CPU-based ray marching with 100 bins took ~1.4s (OpenMP 4 threads) for a single image [S7, unofficial]. GPU implementations are much faster.
*   **Strengths:** Fast training and rendering, simple implementation, no need for neural network libraries.
*   **Limitations:** High memory consumption at high resolutions, limited view-dependent detail compared to higher-order SH or neural networks, requires careful tuning of grid resolution.

## Background
Plenoxels was introduced by Sara Fridovich-Keil, Alex Yu, Matthew Tancik, et al. in 2022 at CVPR [S5, unofficial]. It was proposed as a direct replacement for the neural network in NeRF, using an explicit voxel grid with spherical harmonics to model radiance fields. The method was validated on synthetic (Blender) and real-world (LLFF, Tanks and Temples) datasets [S2, S3]. It builds on the idea of explicit radiance fields but focuses on efficiency by avoiding neural network inference [S2].
