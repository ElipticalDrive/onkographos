# PlenOctree Optimization

Also called: Structure Refinement (Octree Optimization)

## Overview
PlenOctree Optimization is a post-training refinement stage that finetunes a converted PlenOctree on original training images to improve image quality [S1, unofficial]. It addresses residual artifacts and suboptimal density/color allocation by applying Stochastic Gradient Descent (SGD) with the standard NeRF loss, without sparsity regularization, since the octree is already sparse [S1, unofficial]. Unlike its siblings, which focus on configuration or pruning strategies during training, PlenOctree Optimization operates on a fixed tree structure (or applies structural refinement) to allocate resources optimally [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
- **Input:** A converted PlenOctree (density $\sigma$ and SH coefficients $\mathbf{c}$ at leaves) and a set of training images with camera poses [S1, unofficial].
- **Output:** An optimized PlenOctree with refined $\sigma$ and $\mathbf{c}$ values [S1, unofficial].

**Data Structures:**
The PlenOctree is a sparse octree. Each leaf node stores density $\sigma$ (scalar) and Spherical Harmonics (SH) coefficients for RGB channels (vectors) [S1, unofficial]. The tree structure remains fixed during the SGD optimization phase [S1, unofficial]. For structural refinement, the tree supports merging, splitting, and culling leaf nodes [S2].

**Steps:**
1. **Initialize:** Start with the converted PlenOctree. Ensure parameters are in float32 for stability [S1, unofficial]. For structural refinement, initialize with a uniform grid of resolution $4^3 = 64$ [S2].
2. **Convergence & Error:** Wait for training to converge on the current resolution [S2]. Compute per-node error to guide structural refinement [S2].
3. **Structure Refinement (Periodic):** Apply structure refinement every few epochs. Split nodes if the resulting number of leaves does not exceed the budget (e.g., 1024), otherwise merge low-error nodes to allow splitting of high-error leaves [S2].
4. **Loss Calculation:** For each training ray $r$, render the color $\hat{C}(r)$ using the current PlenOctree. Compute the RGB loss:
   $$ L_{RGB} = \sum_{r \in R} ||C(r) - \hat{C}(r)||_2^2 $$
   where $C(r)$ is the ground truth color [S1, unofficial].
5. **Gradient Update:** Use SGD to update the density and SH coefficients of the leaf nodes. Analytic derivatives of the rendering equation with respect to $\sigma$ and $\mathbf{c}$ are implemented in custom CUDA kernels [S1, unofficial].
6. **Iteration & Early Stopping:** Repeat for a fixed number of epochs or until early stopping criteria are met. Monitor PSNR on the validation set to apply early stopping [S1, unofficial].
7. **Storage:** After optimization, convert parameters to float16 to reduce model size [S1, unofficial].

**Parameters:**
- **Learning Rate:**
  - NeRF-synthetic dataset: $1 \times 10^7$ [S1, unofficial].
  - Tanks&Temples dataset: $1.5 \times 10^6$ [S1, unofficial].
- **Epochs:**
  - NeRF-synthetic: Maximum 80 epochs [S1, unofficial].
  - Tanks&Temples: Maximum 40 epochs [S1, unofficial].
- **Validation:** For Tanks&Temples, hold out 10% of the training set as a validation set [S1, unofficial].
- **Early Stopping:** Monitor PSNR on the validation set; stop if no improvement [S1, unofficial].
- **Precision:** Float32 during optimization, Float16 for storage [S1, unofficial].
- **Structural Budget:** Maximum number of leaf nodes is 1024 [S2].

## Subtopics

### [PlenOctree Conversion](1359-plenoctree-conversion.md)
A pipeline to convert a trained NeRF-SH model into a sparse octree representation (PlenOctree) for real-time rendering. The octree stores density and SH coefficients at leaves. It involves rendering alpha maps to identify visible voxels, thresholding, and sampling points within remaining voxels to initialize leaf values.

### [Analytic Derivatives of PlenOctree Rendering](1360-analytic-derivatives-of-plenoctree-rendering.md)
This method provides the closed-form gradients of the NeRF piecewise constant volume rendering equation with respect to the density ($\sigma$) and color ($\mathbf{c}$) parameters. It enables direct optimization of PlenOctree attributes using gradient-based methods (e.g., SGD) to refine image quality.

## Operating characteristics
- **Time Complexity:** Optimization is significantly faster than NeRF training. It operates at about 3 million rays per second, compared to about 9,000 for NeRF training [S1, unofficial].
- **Memory Complexity:** The octree is sparse, reducing memory usage compared to dense grids. Storage is optimized by using float16 after optimization [S1, unofficial].
- **Performance:** Takes around 10 minutes to finish PlenOctree optimization for each scene on a single NVIDIA V100 GPU [S1, unofficial].
- **Strengths:** Accelerates NeRF-based rendering by 5 orders of magnitude without loss in image quality [S1, unofficial]. No sparsity loss is needed as the octree is already sparse [S1, unofficial].
- **Limitations:** Requires a pre-trained NeRF-SH model. The tree structure is fixed during optimization, so it cannot adapt to new geometric complexities that would require structural changes [S1, unofficial].

## Background
PlenOctree Optimization was introduced in the context of PlenOctrees for Real-time Rendering of Neural Radiance Fields (NeRFs) [S1, unofficial]. The method was developed to address the slow training times of original NeRFs by converting them into a sparse, explicit octree representation that can be optimized and rendered much faster [S1, unofficial]. The approach demonstrates state-of-the-art performance for image quality and rendering speed on standard benchmarks [S1, unofficial].
