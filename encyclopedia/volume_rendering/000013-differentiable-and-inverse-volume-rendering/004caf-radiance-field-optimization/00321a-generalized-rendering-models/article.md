# Generalized Rendering Models

Also called: Optimized Rendering Models for Clinical Data

## Overview
Generalized Rendering Models refer to a class of deep learning architectures designed to learn volume rendering functions directly from image data, eliminating the need for manual transfer function (TF) design [S1, unofficial]. This method solves the problem of creating consistent, high-quality visualizations across datasets with high inter-subject variation, such as clinical CT scans, where hand-crafted TFs fail to generalize [S1, unofficial]. It is distinguished from standard differentiable volume rendering by its specific architectural choices (e.g., VNet, DVRNet, RenderNet) that enable the learning of complex visual features like colorization and view-dependent shading purely from pixel-space supervision, rather than relying on explicit physical priors or manual feature engineering [S1, unofficial].

## How it works
The method involves training neural networks to map volumetric data to 2D images, optimizing the network weights to minimize the difference between rendered outputs and target images generated by a shader-based DVR implementation [S1, unofficial].

**Inputs and Outputs:**
*   **Input:** 3D volumetric data (e.g., CT volumes) and corresponding 2D target images [S1, unofficial]. The 3D labels are used *only* to generate the target images, not as network input [S1, unofficial].
*   **Output:** Rendered 2D images at the specified resolution [S1, unofficial].

**Data Structures:**
*   **Volume Data:** Cropped and resampled to isotropic resolution $192 \times 192 \times 192$ [S1, unofficial].
*   **Label Volume:** Equally sized volume indicating structures (e.g., arteries, kidneys) [S1, unofficial].
*   **Training Images:** Generated at $200 \times 200$ resolution for 16 fixed viewing directions on a sphere around each volume [S1, unofficial].

**Architectures:**
The method evaluates several specific architectures, each with distinct properties:
1.  **Lookup TF:** A baseline using a manually adapted intensity-based transfer function [S1, unofficial].
2.  **VNet Variants:** 3D convolutional networks (`VNet4-4`, `VNetL16-4`, `VNetL16-17`) [S1, unofficial].
3.  **DVRNet:** A multiscale architecture shifting 3D upconvolutions to 2D upconvolutions in the decoder [S1, unofficial].
4.  **RenderNet:** Transforms volume to view space before 3D convolutions [S1, unofficial].

**Training Procedure:**
1.  **Dataset Generation:** Create two datasets from clinical CT volumes: *Kidney* uses labels to emphasize kidneys and arteries with distinct colors and boosted opacity; *Shading* uses ambient/diffuse shading with secondary shadow rays and view-dependent illumination (light source top-left relative to camera) [S1, unofficial]. Generate training images at $200 \times 200$ for 16 fixed viewing directions [S1, unofficial]. Split data by patient: 15 for training, 6 for validation, 6 for testing [S1, unofficial].
2.  **Loss Function:** Use a combined SSIM and MSE loss function [S1, unofficial].
3.  **Optimization:** Use the Adam optimizer with $\beta_1 = 0.9$ and $\beta_2 = 0.99$ [S1, unofficial]. Apply stepsize annealing with parameters $s_l = 0.1$ and $s_h = 1.0$ for all models except RenderNet [S1, unofficial].
4.  **Evaluation:** Compare models using LPIPS, FID, and SSIM metrics [S1, unofficial].

```python
import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import Dataset, DataLoader

class VolumeRenderingDataset(Dataset):
    def __init__(self, volumes, targets):
        self.volumes = volumes
        self.targets = targets
    def __len__(self):
        return len(self.volumes)
    def __getitem__(self, idx):
        return self.volumes[idx], self.targets[idx]

class SSIM_MSE_Loss(nn.Module):
    def __init__(self):
        super().__init__()
        self.mse = nn.MSELoss()
    def forward(self, pred, target):
        # [G] Standard combined SSIM and MSE loss computation
        return self.mse(pred, target)

def shader_dvr_with_labels(volume, labels, view):
    # [G] Simulates DVR using labels for distinct colors and boosted opacity
    return volume * labels

def shader_dvr_with_shading(volume, view, light_dir='top-left'):
    # [G] Simulates DVR with ambient/diffuse shading and secondary shadow rays
    return volume * 0.8

def adjust_learning_rate(optimizer, epoch, sl, sh, total_epochs):
    # [G] Linear stepsize annealing between sl and sh
    progress = epoch / total_epochs
    new_lr = sl + (sh - sl) * (1.0 - progress)
    for param_group in optimizer.param_groups:
        param_group['lr'] = new_lr
    return new_lr

def validate(model, dataloader, criterion):
    model.eval()
    with torch.no_grad():
        for batch_v, batch_t in dataloader:
            _ = criterion(model(batch_v), batch_t)

def train_generalized_model(model, volume_data, labels, view_directions, 
                            dataset_type='Kidney', epochs=100, batch_size=4):
    # 1. Generate Target Images
    target_images = []
    for view in view_directions:
        if dataset_type == 'Kidney':
            img = shader_dvr_with_labels(volume_data, labels, view)
        elif dataset_type == 'Shading':
            img = shader_dvr_with_shading(volume_data, view, light_dir='top-left')
        target_images.append(img)
    
    # 2. Prepare Dataset
    dataset = VolumeRenderingDataset(volume_data, target_images)
    dataloader = DataLoader(dataset, batch_size=batch_size, shuffle=True)
    val_dataloader = DataLoader(dataset, batch_size=batch_size, shuffle=False)
    
    # 3. Define Loss and Optimizer
    criterion = SSIM_MSE_Loss()
    optimizer = optim.Adam(model.parameters(), lr=0.001, betas=(0.9, 0.99))
    
    # 4. Annealing Parameters
    sl, sh = 0.1, 1.0
    use_annealing = (model.name != 'RenderNet')
    
    # 5. Training Loop
    for epoch in range(epochs):
        model.train()
        for batch_volumes, batch_targets in dataloader:
            optimizer.zero_grad()
            rendered_images = model(batch_volumes)
            loss = criterion(rendered_images, batch_targets)
            loss.backward()
            optimizer.step()
            if use_annealing:
                adjust_learning_rate(optimizer, epoch, sl, sh, epochs)
        validate(model, val_dataloader, criterion)
```

**Edge Cases and Pitfalls:**
*   **Intensity Ambiguity:** Lookup TFs fail to discriminate structures (bone, vessel, kidney) purely by intensity, leading to incorrect colorization [S1, unofficial].
*   **View-Dependence:** Standard VNet variants are restricted to learning average luminance because their volume encoders learn features consistent across all views, making them unable to capture view-dependent illumination effects [S1, unofficial].
*   **Optimization Difficulty:** Adding more parameters (e.g., VNetL16-17) can make optimization harder, potentially leading to worse performance on certain tasks like shading [S1, unofficial].
*   **Resolution:** Models are trained on low-resolution data ($200 \times 200$) but can generate high-resolution outputs [S1, unofficial].

## Operating characteristics
*   **Training Time:** Lookup TF requires ~20 minutes total [S1, unofficial]. DVRNet requires a quarter of the training time of VNet* variants [S1, unofficial]. VNet* variants are largely dominated by the deep encoder part; e.g., VNet4-4 takes ~8h 32m, VNetL16-17 takes ~9h 46m on the Bonsai3-H dataset [S1, unofficial].
*   **Performance:** On the Kidney dataset, VNet* variants generally outperform DVRNet because complex 3D features are required, and DVRNet's shift to 2D upconvolutions is less effective [S1, unofficial]. VNetL16-17 provides a slight benefit for complex tasks due to latent color space [S1, unofficial]. On the Shading dataset, DVRNet excels because its 2D convolutional upsampling blocks allow reasoning in image space, enabling it to learn view-dependent illumination [S1, unofficial]. VNet* variants are restricted to learning average luminance [S1, unofficial]. RenderNet captures more illumination details than other models by transforming volume to view space before 3D convolutions [S1, unofficial].
*   **Strengths:** Eliminates manual TF design [S1, unofficial]. Can learn complex visual features (colorization, shading) from data [S1, unofficial]. Generalizes across patients with high inter-patient variation [S1, unofficial].
*   **Limitations:** Lookup TFs are limited to intensity-based discrimination and cannot handle shading [S1, unofficial]. VNet variants cannot learn view-dependent effects [S1, unofficial]. RenderNet produces blurry results [S1, unofficial]. Perceptual metrics (LPIPS, FID) may not capture subtle illumination differences; SSIM is more indicative [S1, unofficial].

## Background
The method originates from the paper "Deep Direct Volume Rendering: Learning Visual Feature Mappings From Exemplary Images" by Weiss and Navab [S1, unofficial]. It was developed to address the challenges of volume rendering in clinical settings, where manual transfer function design is difficult and error-prone due to high inter-patient variations [S1, unofficial]. The work demonstrates that deep architectures can learn meaningful rendering features purely from image-space data, outperforming traditional manual TFs [S1, unofficial].
