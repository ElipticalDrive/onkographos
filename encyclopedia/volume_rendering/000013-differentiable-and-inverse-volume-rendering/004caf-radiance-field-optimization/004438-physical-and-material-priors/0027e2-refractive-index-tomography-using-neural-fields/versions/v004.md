# Refractive Index Tomography using Neural Fields

Also called: Neural Field Recovery, Single-View Refractive Index Tomography

## Overview
Refractive Index Tomography using Neural Fields (RNTF) is a method to recover a 3D refractive index field ($\eta$) and a luminance field from single-view refracted image measurements by optimizing neural fields that represent these quantities [S1, unofficial]. It differs from standard differentiable volume rendering by modeling light propagation through a continuous medium with spatially varying refractive index using ray tracing governed by Fermat's principle, rather than assuming straight-line paths or constant index [S1, unofficial]. It builds on [Physical and Material Priors](11198-physical-and-material-priors.md) by explicitly parameterizing the material property (refractive index) as a neural field and integrating the physical equations of motion for light rays.

## How it works
**Inputs and Outputs:**
*   **Inputs:** A single refracted image (or set of measurements), camera parameters (field of view `fov_angle`, resolution `res`), and an optional initial refractive index estimate `n_init` [S1, unofficial].
*   **Outputs:** A trained neural network representing the 3D refractive index field $\eta(\mathbf{x})$ and optionally a luminance/emission field $L(\mathbf{x})$ [S1, unofficial].

**Data Structures:**
*   **Ray Input Array:** Shape `[batch_size, 6 + num_aux]`. The first 3 elements are the ray position $(x, y, z)$, the next 3 are the ray direction $(dx, dy, dz)$, and the remaining elements are auxiliary data [S1, unofficial].
*   **ODE State $y$:** Shape `[batch_size, state_dim]`. `state_dim` is 6 for path-only tracing (position + direction) or 7 for luminance tracing (position + direction + luminance) [S1, unofficial].

**Parameters:**
*   `s_vals`: Array of path length values at which to evaluate the ray-traced path integral. Passed to the ODE solver [S1, unofficial].
*   `lam`: Regularization weight for the boundary term in the loss function [S1, unofficial].
*   `res`: Resolution of the ray grid, determining the number of rays as $res^2$ [S1, unofficial].
*   `fov_angle`: Field of view angle in degrees, used to calculate aperture points and ray directions [S1, unofficial].
*   `n_init`: Initial refractive index at the starting position, used to scale the initial ray direction magnitude [S1, unofficial].
*   `lr_init`, `lr_final`: Initial and final learning rates for the optimizer [S1, unofficial].
*   `num_iters`: Total number of training iterations [S1, unofficial].

**Numbered Steps:**

1.  **Initialize Rays:** Generate ray origins and directions based on camera parameters (`fov_angle`, `res`). Normalize the ray direction and scale its magnitude by the initial refractive index `n_init` at the starting position to ensure correct physical propagation, as the ODE uses `ray_dir / eta` [S1, unofficial].
2.  **Define Neural Fields:** Instantiate two neural networks (e.g., MLPs):
    *   `predict_eta`: Takes 3D position $\mathbf{x}$ as input and outputs the scalar refractive index $\eta(\mathbf{x})$ and its gradient $\nabla \eta(\mathbf{x})$ [S1, unofficial].
    *   `predict_lum`: Takes 3D position $\mathbf{x}$ as input and outputs the luminance/emission $L(\mathbf{x})$ at that point [S1, unofficial].
3.  **Define ODE Function:** Define the derivative function for the ray tracing ODE. The state $y$ contains $[\mathbf{r}, \mathbf{d}, l]$ (position, direction, luminance). The derivatives with respect to path length $s$ are:
    *   $\frac{d\mathbf{r}}{ds} = \frac{\mathbf{d}}{\eta}$
    *   $\frac{d\mathbf{d}}{ds} = \nabla \eta$
    *   $\frac{dl}{ds} = L$ (or $\frac{L}{\eta^2}$ for radiance adjustment depending on the specific variant `renderfn` vs `renderfn_rad`) [S1, unofficial].
4.  **Integrate ODE:** Use an ODE solver (e.g., `jax.experimental.ode.odeint`) to integrate the ODE function over the path length values `s_vals`. The initial state $y_0$ is constructed by concatenating the initialized ray position, direction, and auxiliary data (initial luminance if applicable) [S1, unofficial].
5.  **Extract Results:** Extract the final ray positions (`ray_trace`) and integrated luminance (`ray_lum`) from the integration result. Move the ray trace to the last axis if necessary [S1, unofficial].
6.  **Compute Loss:** Calculate the loss between the rendered luminance/image and the target measurements. Include a regularization term weighted by `lam` for boundary conditions [S1, unofficial].
7.  **Optimize:** Use gradient descent (e.g., Adam) via `jax.value_and_grad` and `apply_gradients` to update the parameters of the neural fields (`predict_eta`, `predict_lum`) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Ray Direction Scaling:** The initial ray direction magnitude must be scaled by the initial refractive index `n_init` to ensure correct physical propagation, as the ODE uses `ray_dir / eta` [S1, unofficial].
*   **Precision:** For simulations like dark matter, tight ODE tolerances (`rtol=1e-10`, `atol=1e-10`) are required to ensure precision [S1, unofficial].
*   **Radiance Adjustment:** The variant `renderfn_rad` adjusts the luminance integrand by dividing by $\eta^2$, whereas `renderfn` does not. This accounts for radiance adjustment according to the index of refraction [S1, unofficial].

## Subtopics

### Inverse Rendering and Optical Properties
Focuses on recovering optical properties like albedo and normals, often assuming straight-line paths or simpler scattering models. RNTF specifically handles refraction in continuous media. [Link](7914-inverse-rendering-and-optical-properties.md)

### Neural Radiative Transfer via Physics-Informed Optimization
Uses physics-informed neural networks (PINNs) to solve the radiative transfer equation, often for participating media. RNTF uses ray tracing ODEs for non-participating or weakly participating media with varying index. [Link](10842-neural-radiative-transfer-via-physics-informed-optimization.md)

### Multi-Sensor and Physical Priors
Incorporates multiple sensor types or strong physical priors to constrain the inverse problem. RNTF primarily uses single-view refracted images. [Link](11031-multi-sensor-and-physical-priors.md)

## Operating characteristics
*   **Time Complexity:** Depends on the number of training iterations, the number of rays ($res^2$), the number of ODE steps (`len(s_vals)`), and the cost of evaluating the neural networks. ODE integration is typically the most expensive part per iteration.
*   **Memory Complexity:** Proportional to the number of rays and the depth of the ODE integration (if storing all steps) or the memory required for the neural network parameters and gradients.
*   **Measured Performance:** Tested on NVIDIA RTX A6000 GPU [S1, unofficial]. Specific performance metrics (FPS, convergence time) are not provided in the sources.
*   **Scaling:** Scales with resolution `res` (number of rays) and the complexity of the neural networks (depth, width).
*   **Strengths:** Can recover continuous 3D refractive index fields from single views; handles smooth variations and complex geometries implicitly via the neural field.
*   **Limitations:** Requires careful tuning of ODE tolerances and regularization; may be slow to converge; single-view setup can lead to ambiguities.
*   **When to use:** Gas flow recovery, smooth refractive field recovery, dark matter halo recovery simulations [S1, unofficial].
*   **When not to use:** When high-speed real-time rendering is required, or when the medium is highly scattering (participating media) where the radiative transfer equation is more appropriate.

## Background
The method is based on the paper "Single-View Refractive Index Tomography using Neural Fields" [S1, unofficial]. It was built and tested on Ubuntu 22.04 and NVIDIA RTX A6000 GPU [S1, unofficial]. The code uses JAX, Flax, and Optax [S1, unofficial]. Applications include gas flow recovery, smooth refractive field recovery, and dark matter halo recovery simulations [S1, unofficial].
