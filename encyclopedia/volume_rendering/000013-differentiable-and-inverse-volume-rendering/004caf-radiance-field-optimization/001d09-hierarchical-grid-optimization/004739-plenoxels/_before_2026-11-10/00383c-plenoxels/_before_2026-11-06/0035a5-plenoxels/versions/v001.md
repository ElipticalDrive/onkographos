# Plenoxels

Also called: Radiance Fields without Neural Networks

## Overview
Plenoxels is an explicit radiance field representation that replaces the neural network used in NeRF with a sparse 3D voxel grid storing density and spherical harmonic (SH) coefficients [S1, S2][S5, unofficial]. It solves the computational bottleneck of neural network inference during training and rendering, enabling training speeds two orders of magnitude faster than NeRF while maintaining comparable image quality [S1][S5, unofficial]. Unlike implicit representations, Plenoxels allows for direct data access and real-time rendering, though it trades off memory efficiency for speed [S1][S5, unofficial].

## How it works
**Inputs:** A set of $N$ calibrated images with known camera poses (intrinsics and extrinsics).
**Outputs:** Two sparse voxel grids: $V^D$ for volume density $\sigma$ and $V^{SH}$ for spherical harmonic coefficients $\mathbf{k}$.

### Data Structures
The scene is represented by two explicit 3D grids (tensors) [S2, S3].
1.  **Density Grid ($V^D$):** Stores a single scalar value $\sigma$ per voxel [S2][S7, unofficial].
2.  **Color Grid ($V^{SH}$):** Stores SH coefficients per voxel [S2][S7, unofficial].
    *   Each voxel stores coefficients for RGB channels.
    *   For degree $\ell_{max}=2$, there are 9 coefficients per channel (R, G, B) [S3][S7, unofficial].
    *   Total values per voxel: $1 (\sigma) + 9 (R) + 9 (G) + 9 (B) = 28$ floats [S1][S7, unofficial].
    *   The grid is typically sparse, meaning only voxels containing geometry are allocated or updated [S2][S5, unofficial].

**Grid Layout:**
*   The grid is defined by a bounding box, typically $[-1, 1]^3$ [S7, unofficial].
*   Resolution varies by dataset: $128^3$ for NeRF-Synthetic/TanksAndTemple, $512 \times 512 \times 128$ for LLFF [S3].
*   Voxels are accessed via trilinear interpolation of the 8 nearest neighbors [S1][S5, unofficial].

### Rendering Pipeline
The rendering follows the standard volume rendering equation [S1][S5, unofficial]:

$$
\hat{C}(\mathbf{r}) = \sum_{i=1}^N T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i
$$

where $\mathbf{r}$ is a ray, $\sigma_i$ is density, $\delta_i$ is step size, and $\mathbf{c}_i$ is color.

**Step 1: Ray Generation**
For each pixel $(x, y)$ in an image of width $W$ and height $H$:
1.  Calculate aspect ratio $AR = W/H$.
2.  Compute focal length $f = 2 \tan(\text{FOV}/2)$ [S7, unofficial].
3.  Normalize pixel coordinates to $[-1, 1]$ range (adjusted for aspect ratio) [S7, unofficial].
4.  Construct ray direction $\mathbf{d}$ in camera space and transform to world space using camera extrinsics [S7, unofficial].

**Step 2: Ray Marching**
1.  Compute intersection of ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ with the grid bounding box to get $t_{min}$ and $t_{max}$ [S7, unofficial].
2.  Sample points along the ray within $[t_{min}, t_{max}]$ with fixed step size $\delta$ [S5, unofficial].
3.  For each sample point $\mathbf{x}_i$:
    *   **Density Sampling:** Trilinearly interpolate $\sigma$ from $V^D$ at $\mathbf{x}_i$. Apply ReLU to ensure non-negativity: $\sigma(\mathbf{x}_i) = \text{ReLU}(\text{interp}(\mathbf{x}_i, V^D))$ [S2].
    *   **Early Termination:** If transmittance $T_i < \text{stop\_thresh}$ (e.g., $10^{-5}$), terminate ray [S5, unofficial].
    *   **Color Sampling:**
        *   Trilinearly interpolate SH coefficients $\mathbf{k}(\mathbf{x}_i)$ from $V^{SH}$ [S2].
        *   Evaluate SH basis functions $Y_{\ell}^m(\mathbf{d})$ for the view direction $\mathbf{d}$ [S7, unofficial].
        *   Compute color: $\mathbf{c}(\mathbf{d}; \mathbf{k}) = \text{ReLU}\left( \sum_{\ell=0}^{\ell_{max}} \sum_{m=-\ell}^{\ell} \mathbf{k}_{\ell}^m Y_{\ell}^m(\mathbf{d}) \right)$ [S2, S3]. Note: Some implementations use a sigmoid activation $S(x) = (1+\exp(-x))^{-1}$ instead of ReLU for color [S3, S4].
        *   Accumulate color and transmittance using the volume rendering equation [S5, unofficial].

**Step 3: Background**
If the ray exits the scene without being fully opaque, add a constant background color weighted by the final transmittance: $\hat{C}_{bg} = T_N \cdot \mathbf{c}_{bg}$ [S5, unofficial].

### Optimization
The grids are optimized using gradient descent (e.g., Adam) to minimize the difference between rendered and ground truth images [S2].

**Loss Function:**
1.  **Photometric Loss:** Mean Squared Error (MSE) between rendered color $\hat{C}(\mathbf{r})$ and ground truth $C(\mathbf{r})$ [S2].
2.  **Total Variation (TV) Regularization:** Applied to both $V^D$ and $V^{SH}$ to smooth the field and prevent overfitting [S2]:
    $$
    \mathcal{L}_{\text{TV}}(V) = \frac{1}{|V|} \sum_{\mathbf{v} \in V} \sqrt{\Delta_x^2(\mathbf{v}) + \Delta_y^2(\mathbf{v}) + \Delta_z^2(\mathbf{v})}
    $$
    where $\Delta_x(\mathbf{v})$ is the difference between voxel $\mathbf{v}$ and its neighbor in the x-direction [S2].

**Gradient Computation:**
Gradients are computed via backpropagation through the differentiable rendering operator [S1][S5, unofficial]. The explicit nature of the grid allows for efficient gradient accumulation directly into the voxel values [S5, unofficial].

### Parameters
*   **Grid Resolution:** $128^3$ or $512 \times 512 \times 128$ [S3].
*   **SH Degree:** 2 (9 coefficients per channel) [S3][S7, unofficial].
*   **Ray Marching Steps:** Fixed number of samples per ray (e.g., 100 bins) [S7, unofficial].
*   **Step Size:** Fixed distance between samples [S5, unofficial].
*   **Stop Threshold:** Transmittance threshold for early termination [S5, unofficial].
*   **Sigma Threshold:** Minimum density to process color [S5, unofficial].

### Edge Cases and Pitfalls
*   **Memory Footprint:** Performance depends heavily on grid resolution; high resolutions lead to large memory usage [S3].
*   **Near-Camera Floaters:** Overfitting near the camera can cause artifacts. Mitigated by transmittance-based gradient scaling [S2].
*   **Overfitting:** High-frequency SH components can lead to inaccurate geometry. Mitigated by curriculum training (starting with lower SH degree) [S2].
*   **Bank Conflicts:** In GPU implementations, accessing SH coefficients can cause shared memory bank conflicts [S5, unofficial].
*   **Clamping:** Color values are clamped to non-negative ranges, which affects gradient flow [S5, unofficial].

## Operating characteristics
*   **Speed:** Training is significantly faster than NeRF (two orders of magnitude) due to the elimination of MLP inference [S1][S5, unofficial]. Rendering can be real-time on consumer hardware [S1].
*   **Memory:** Higher memory consumption than neural network-based methods due to the explicit grid storage [S1][S5, unofficial].
*   **Quality:** Comparable to NeRF on standard datasets, but may struggle with very high-frequency details without high grid resolutions [S2].
*   **Scalability:** Scales with grid resolution; sparse implementations help mitigate memory issues [S2][S5, unofficial].
*   **Use Cases:** Fast training and real-time rendering applications where high accuracy is required but neural network inference is too slow [S1][S5, unofficial].

## Background
Plenoxels was introduced by Fridovich-Keil et al. in 2022 [S5, unofficial]. It was designed to address the computational inefficiency of NeRF by replacing the neural network with an explicit voxel grid representation [S1, S2]. The method leverages spherical harmonics to encode view-dependent appearance, allowing for fast evaluation via trilinear interpolation [S1, S3]. It has since been extended with techniques like depth-guided pruning and curriculum training to improve performance in few-shot settings [S2].
