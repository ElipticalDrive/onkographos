# Joint Finetuning for Vector-Quantized Radiance Fields

Also called: VQ-DVGO, VQ-Plenoxels, VQ-TensoRF finetuning

## Overview
Joint finetuning is a post-compression optimization procedure applied to vector-quantized radiance fields to recover rendering quality lost during voxel pruning and codebook initialization [S1]. It distinguishes itself from standard neural teacher training by operating on a sparse, quantized representation, thereby eliminating hash collisions inherent in dense hash grids and leveraging a larger effective parameter count to exceed the teacher's performance [S1]. This method builds on [Plenoxels Optimization Configuration](929-plenoxels-optimization-configuration.md) by adapting gradient-based optimization specifically for the constraints of vector-quantized structures.

## How it works
The method recovers rendering quality in compressed radiance field representations through a sequence of pruning, initialization, and joint optimization [S1].

### Inputs and Outputs
- **Inputs**: A pre-trained radiance field model (DVGO, Plenoxels, or TensoRF), a set of training images, camera poses, and a target compression ratio (implied by the pruning step).
- **Outputs**: A vector-quantized radiance field model with recovered rendering quality and significantly reduced storage cost (up to 100× lower than uncompressed models) [S1].

### Data Structures
The data structures depend on the specific variant (DVGO, Plenoxels, or TensoRF) being finetuned [S1]:

1.  **DVGO Model**:
    -   **Density Grid**: A 3D grid storing density values.
    -   **Feature Grid**: A 3D grid storing feature vectors.
    -   **Shallow MLP**: A small multi-layer perceptron for color estimation.
2.  **Plenoxels Model**:
    -   **Density Grid**: A 3D grid storing density values.
    -   **Feature Grid**: A 3D grid filled with spherical harmonic (SH) coefficients.
3.  **TensoRF Model**:
    -   **Virtual Grid**: Used for importance scoring of all grid points.
    -   **Tri-planes**: Density and feature tri-planes obtained by projecting and aggregating points from the virtual grid along each axis.

### Steps
1.  **Pruning**: Prune less important voxels from the original model according to the quantile of the cumulative score rate [S1].
2.  **Codebook Initialization**: Use only the pruned voxels for codebook initialization [S1].
3.  **Joint Finetuning**: Begin joint finetuning using method-specific learning rates and exponential decay schedules [S1].

### Parameters and Schedules
The specific parameters for each variant are as follows [S1]:

**DVGO (VQ-DVGO)**
-   **Density Grid Learning Rate**: $8 \times 10^{-2}$
-   **Feature Grid and Shallow MLP Learning Rate**: $1.6 \times 10^{-3}$
-   **Decay Schedule**: Exponential decay, scaling learning rates by $0.3$ every $10,000$ iterations.
-   **Duration**: $10,000$ iterations.
-   **Batch Size**: $8,192$ rays per iteration.

**Plenoxels (VQ-Plenoxels)**
-   **Duration**: $25,600$ iterations (equivalent to two epochs in the original Plenoxels training).
-   **Scheduler Reset**: The learning rate scheduler is reset to the sixth epoch of the original setting [S1].

**TensoRF (VQ-TensoRF)**
-   **Learning Rate**: $5 \times 10^{-3}$ for all density tri-planes, feature tri-planes, and the shallow MLP.
-   **Decay Schedule**: Exponential decay, scaling learning rate by $0.3$ every $30,000$ iterations.
-   **Duration**: $10,000$ iterations.

### Pseudocode
The following pseudocode outlines the general joint finetuning process for a generic vector-quantized radiance field model. Specific parameter values are injected per variant.

```python
def joint_finetune(model, training_data, config):
    """
    Perform joint finetuning on a vector-quantized radiance field.
    
    Args:
        model: The vector-quantized radiance field model (DVGO, Plenoxels, or TensoRF).
        training_data: Dataset containing images and camera poses.
        config: Dictionary containing learning rates, decay factors, and iteration counts.
    """
    # 1. Pruning (Pre-finetuning step)
    # Prune less important voxels based on cumulative score rate quantile
    # This step is performed before finetuning starts
    model.prune_voxels_by_score_quantile()
    
    # 2. Codebook Initialization (Pre-finetuning step)
    # Use only pruned voxels for codebook initialization
    # This step is performed before finetuning starts
    model.initialize_codebook_from_pruned_voxels()
    
    # 3. Joint Finetuning
    num_iterations = config['num_iterations']
    lr_density = config['lr_density']
    lr_feature = config['lr_feature']
    decay_factor = config['decay_factor']
    decay_interval = config['decay_interval']
    
    # Initialize optimizer with specific learning rates for each component
    optimizer = Adam([
        {'params': model.density_grid.parameters(), 'lr': lr_density},
        {'params': model.feature_grid.parameters(), 'lr': lr_feature},
        {'params': model.mlp.parameters(), 'lr': lr_feature}
    ])
    
    # For Plenoxels, reset scheduler to specific epoch
    if config['variant'] == 'plenoxels':
        scheduler = reset_scheduler_to_epoch(optimizer, epoch=6)
    else:
        scheduler = ExponentialLR(optimizer, gamma=decay_factor)
        
    for iteration in range(num_iterations):
        # Sample rays for this iteration
        rays = sample_rays(training_data, batch_size=config['rays_per_iteration'])
        
        # Forward pass to render images
        rendered_images = model.render(rays)
        
        # Compute loss (e.g., MSE between rendered and ground truth images)
        loss = compute_loss(rendered_images, rays.gt_images)
        
        # Backward pass and optimization step
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # Update learning rate schedule
        if config['variant'] == 'plenoxels':
            # Scheduler is managed by reset logic for Plenoxels
            pass
        else:
            # Apply exponential decay every decay_interval iterations
            if (iteration + 1) % decay_interval == 0:
                scheduler.step()
                
    return model
```

### Edge Cases and Pitfalls
-   **Pruning Threshold**: The quantile of the cumulative score rate must be chosen carefully to balance compression ratio and quality recovery. [Not given in the sources.]
-   **Scheduler Reset**: For Plenoxels, resetting the scheduler to the sixth epoch is critical to align the learning rate schedule with the extended iteration count. [S1]
-   **Hash Collisions**: While joint finetuning helps recover quality, the underlying hash grid structure in DVGO may still suffer from hash collisions, which the method aims to mitigate but not entirely eliminate compared to non-hash-based methods. [S1]

A post-baking optimization step that refines only texel colors for 3,000 iterations, freezing geometry and view-dependent color parameters. It distinguishes itself by eliminating hash collisions and leveraging a larger parameter count to exceed teacher performance.

## Operating characteristics
-   **Storage Cost**: Achieves up to 100× lower storage cost compared to uncompressed models while preserving rendering quality [S1].
-   **Performance**: The method effectively preserves rendering quality, including fine details, compared to the model before compression [S1].
-   **Computational Cost**: The finetuning duration varies by variant: 10,000 iterations for DVGO and TensoRF, and 25,600 iterations for Plenoxels [S1].
-   **Scalability**: Not given in the sources.
-   **Strengths**: Significant compression with minimal quality loss; recovers quality lost during quantization.
-   **Limitations**: Still relies on the underlying structure (e.g., hash grids for DVGO) which may have inherent limitations like hash collisions.

## Background
Joint finetuning for vector-quantized radiance fields was introduced in the paper "Compressing Volumetric Radiance Fields to 1 MB" [S1]. The method addresses the challenge of compressing neural radiance fields while maintaining high rendering quality. It builds on previous work in radiance field optimization, such as DVGO, Plenoxels, and TensoRF, adapting them for vector quantization and compression.
