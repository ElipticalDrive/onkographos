# PeRFception-ScanNet Data Generation
## Overview
This method defines the data preparation pipeline for training Plenoxels on the ScanNet dataset, addressing specific challenges such as motion blur from auto-exposure, sparse observation of room geometries, and the resulting "floater" artifacts in empty space [S1]. It builds on [Plenoxels Training Configuration (PeRFception variants)](8192-plenoxels-training-configuration-perfception-variants.md) and differs from standard configurations by initializing the voxel grid with unprojected depth maps rather than a dense grid, and by pre-generating and caching ray batches in CPU memory to optimize bandwidth utilization [S1].

## How it works
**Inputs:** Raw ScanNet video streams and unprojected depth maps provided with ScanNet [S1].
**Outputs:** A compressed dataset of ray batches and initialized voxel grids (occupying ~35GB disk space) [S1].

**Data Structures:**
*   **Ray Batches:** Pre-generated batches of rays, stored in CPU memory [S1].
*   **Voxel Grid:** Initialized using unprojected depth maps [S1].

**Steps:**
1.  **Frame Selection:** For each scene, uniformly sample up to 1,500 image frames [S1]. If a scene has fewer than 1,500 images, use all available frames [S1].
2.  **Blur Filtering:** For scenes with fewer than 1,500 images, filter out blurry frames using a low variance of the Laplacian metric [S1].
3.  **Ray Generation:** Generate batches of rays for the selected frames [S1].
4.  **Memory Caching:** Load the generated ray batches into CPU memory to ensure efficient memory bandwidth utilization during training [S1].
5.  **Voxel Initialization:** Initialize the voxel grid using the unprojected depth maps provided in ScanNet, rather than starting from a dense voxel grid [S1].
6.  **Outlier Filtering:** Apply connected component analysis to the unprojected point clouds derived from the depth maps to filter out disconnected outlier points [S1].

**Parameters:**
*   `max_frames`: 1,500 (uniformly sampled) [S1].
*   `blur_threshold`: Not given in the sources.

**Pitfalls:**
*   **Motion Blur:** ScanNet videos are captured with auto-exposure enabled, leading to motion blur in many frames that results in poor scene geometries if not filtered [S1].
*   **Floaters:** In room-centric datasets like ScanNet, fewer images observe the same part of the space, causing standard Plenoxels reconstruction to create excessive voxels (floaters) in empty space to minimize image reconstruction loss [S1]. The depth-based initialization mitigates this [S1].

## Subtopics

### Partial SRF Optimization
Partial SRFs are generated by optimizing Sparse Radiance Fields (SRFs) on only a small number of images (1 or 3) randomly sampled from all 400 available views for each shape [S2]. These partial SRFs serve as input to the learning pipeline (e.g., SuRFNet) to generate whole SRFs, whereas Whole SRFs are optimized using the entire set of 400 views [S2]. This allows for the creation of multiple partial SRF variants per object, facilitating 3D learning setups that treat radiance fields as 3D data structures [S2].

## Operating characteristics
*   **Storage:** The resulting PeRFception-ScanNet dataset occupies approximately 35GB, compared to the original 966GB required for ScanNet video streams, achieving a 96.4% compression rate [S1].
*   **Performance:** Pre-generating and caching ray batches in CPU memory improves training efficiency by optimizing memory bandwidth utilization [S1].
*   **Quality:** The depth-based initialization and outlier filtering lead to stable and more accurate reconstruction, reducing the generation of floaters in empty space [S1].

## Background
This method is part of the PeRFception project, which focuses on perception using radiance fields [S1]. It adapts the Plenoxels optimization configuration for the ScanNet dataset, which consists of indoor room scans captured with handheld cameras [S1]. The approach addresses the specific challenges of indoor scenes, such as auto-exposure induced blur and sparse viewpoint coverage [S1].
