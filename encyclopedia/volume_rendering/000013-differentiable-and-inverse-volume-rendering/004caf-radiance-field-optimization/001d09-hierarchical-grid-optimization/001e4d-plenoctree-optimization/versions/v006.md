# PlenOctree Optimization

Also called: Structure Refinement (Octree Optimization)

## Overview
PlenOctree Optimization is a post-training fine-tuning process that refines a pre-converted PlenOctree representation on original training images to improve image quality [S1, unofficial]. It solves the residual approximation errors introduced during the initial conversion from a neural network to a sparse octree by applying gradient-based optimization directly to the octree's density and spherical harmonic coefficients [S1, unofficial]. Unlike [Plenoxels Optimization Configuration](929-plenoxels-optimization-configuration.md), which configures fixed-grid parameters, or [Coarse-to-Fine Optimization with Pruning](1153-coarse-to-fine-with-pruning.md), which prunes during training, PlenOctree Optimization operates on a fixed tree structure using analytic derivatives to accelerate convergence by orders of magnitude compared to neural network training [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A PlenOctree structure (fixed topology) containing density $\sigma$ and spherical harmonic (SH) coefficients for color $\mathbf{c}$ at each leaf node, derived from a trained NeRF-SH model [S1, unofficial].
*   **Output:** Optimized density and SH coefficients that minimize the photometric loss on the training set [S1, unofficial].

**Data Structures:**
The PlenOctree is a sparse octree. Each leaf node stores:
1.  Density $\sigma$ (scalar).
2.  Color coefficients: A vector of SH coefficients for each RGB channel. The specific order and degree of SH are determined by the initial NeRF-SH conversion [S1, unofficial].
3.  [G] Standard octree metadata (parent pointer, child pointers, occupancy flags) to support traversal [G].

**Numbered Steps:**
1.  **Initialization:** Load the PlenOctree converted from the NeRF-SH model. Ensure all attributes are stored in `float32` for gradient stability [S1, unofficial].
2.  **Loss Computation:** For each training ray $\mathbf{r}$, render the color $\hat{C}(\mathbf{r})$ using the volume rendering equation. Compute the loss:
    $$
    L_{RGB} = \sum_{\mathbf{r} \in R} ||C(\mathbf{r}) - \hat{C}(\mathbf{r})||_2^2
    $$
    where $C(\mathbf{r})$ is the ground truth color and $\hat{C}(\mathbf{r})$ is the rendered color [S1, unofficial].
3.  **Gradient Calculation:** Compute gradients $\frac{\partial L_{RGB}}{\partial \sigma}$ and $\frac{\partial L_{RGB}}{\partial \mathbf{c}}$ using analytic derivatives of the piecewise constant volume rendering equation [S1, unofficial]. These are implemented in custom CUDA kernels [S1, unofficial].
4.  **Parameter Update:** Apply Stochastic Gradient Descent (SGD) to update $\sigma$ and $\mathbf{c}$ for all leaf nodes [S1, unofficial].
5.  **Iteration:** Repeat steps 2-4 for a fixed number of epochs or until early stopping criteria are met.
6.  **Storage:** After optimization, convert the attributes to `float16` to reduce model size [S1, unofficial].

**Parameters:**
*   **Optimizer:** SGD [S1, unofficial].
*   **Learning Rate (NeRF-synthetic):** $1 \times 10^7$ [S1, unofficial].
*   **Learning Rate (Tanks&Temples):** $1.5 \times 10^6$ [S1, unofficial].
*   **Max Epochs (NeRF-synthetic):** 80 [S1, unofficial].
*   **Max Epochs (Tanks&Temples):** 40 [S1, unofficial].
*   **Validation Set:** For Tanks&Temples, 10% of the training set is held out [S1, unofficial].
*   **Early Stopping:** Monitor PSNR on the validation set; stop if no improvement is observed [S1, unofficial].
*   **Precision:** `float32` during optimization, `float16` for final storage [S1, unofficial].

**Pseudocode:**
```python
def plenoctree_optimization(plenoctree, training_rays, validation_rays, config):
    """
    Optimizes a PlenOctree using SGD and analytic gradients.
    
    Args:
        plenoctree: Sparse octree with density and SH coefficients.
        training_rays: List of rays with ground truth colors.
        validation_rays: List of rays for early stopping.
        config: Dictionary containing learning_rate, max_epochs, etc.
    """
    # Ensure float32 for stability
    plenoctree.set_precision('float32')
    
    best_psnr = -1
    patience_counter = 0
    
    for epoch in range(config['max_epochs']):
        # Shuffle training rays
        random.shuffle(training_rays)
        
        total_loss = 0.0
        num_rays = len(training_rays)
        
        for ray in training_rays:
            # Render ray using current PlenOctree
            rendered_color = render_ray(plenoctree, ray)
            ground_truth_color = ray.color
            
            # Compute L2 loss
            loss = sum((gt - pred)**2 for gt, pred in zip(ground_truth_color, rendered_color))
            total_loss += loss
            
            # Compute analytic gradients w.r.t density and SH coefficients
            # Implemented in custom CUDA kernels [S1, unofficial]
            grad_sigma, grad_color = compute_analytic_gradients(plenoctree, ray, rendered_color, ground_truth_color)
            
            # Update parameters using SGD
            update_plenoctree_parameters(plenoctree, grad_sigma, grad_color, config['learning_rate'])
        
        avg_loss = total_loss / num_rays
        
        # Early stopping check
        if validation_rays:
            val_psnr = compute_psnr(plenoctree, validation_rays)
            if val_psnr > best_psnr:
                best_psnr = val_psnr
                patience_counter = 0
                save_best_model(plenoctree)
            else:
                patience_counter += 1
                # Note: Specific patience value not given in sources [G]
                if patience_counter > 5: 
                    break
        
        # Log progress
        print(f"Epoch {epoch}, Loss: {avg_loss}")

    # Convert to float16 for storage
    plenoctree.set_precision('float16')
    return plenoctree
```

## Subtopics

### [PlenOctree Conversion](1359-plenoctree-conversion.md)
PlenOctree Conversion is a pipeline that transforms a trained NeRF-SH model into a sparse octree representation for real-time volume rendering. It solves the performance bottleneck of conventional NeRFs, which require dense sampling and neural network inference for every ray step dependent on viewing direction. Unlike [Analytic Derivatives of PlenOctree Rendering](1360-analytic-derivatives-of-plenoctree-rendering.md), which focuses on differentiable optimization of the octree structure, this method focuses on the construction and tabulation of the view-dependent volume from a pre-trained network.

### [Analytic Derivatives of PlenOctree Rendering](1360-analytic-derivatives-of-plenoctree-rendering.md)
This method provides the closed-form gradients of the NeRF piecewise constant volume rendering equation with respect to the density ($\boldsymbol{\sigma}$) and color ($\mathbf{c}$) parameters. It enables direct optimization of PlenOctree attributes using gradient-based methods (e.g., SGD) to refine image quality.

### PlenOctree Fine-tuning
PlenOctree Fine-tuning is a variant where the NeRF model is stopped early, converted into a PlenOctree, and then trained significantly faster as it no longer involves neural networks [S1, unofficial]. This approach accelerates NeRF-based rendering by 5 orders of magnitude without loss in image quality [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The optimization is significantly faster than training the original NeRF. PlenOctree optimization operates at about 3 million rays per second, compared to about 9,000 for NeRF training [S1, unofficial].
*   **Memory Complexity:** Memory usage is dominated by the octree structure and the SH coefficients. Since the octree is already sparse, no sparsity loss is applied, and memory is lower than dense grid methods [S1, unofficial].
*   **Measured Performance:** On a single NVIDIA V100 GPU, PlenOctree optimization takes around 10 minutes per scene [S1, unofficial].
*   **Strengths:** Rapid convergence due to the absence of neural network inference; high rendering speeds after optimization; improved image quality over the initial conversion [S1, unofficial].
*   **Limitations:** Requires a pre-trained NeRF-SH model; tree structure is fixed during optimization, so it cannot adapt topology to new errors [S1, unofficial].
*   **When to use:** When real-time rendering is required and a pre-trained NeRF is available, and slight quality improvements over the initial conversion are desired.
*   **When not to use:** If the initial conversion quality is insufficient and topology adaptation is needed (use [Coarse-to-Fine Optimization with Pruning](1153-coarse-to-fine-with-pruning.md) or [Structure Refinement](1414-hierarchical-grid-optimization.md) variants).

## Background
PlenOctree Optimization was introduced in the PlenOctrees paper [S1, unofficial]. It builds on the PlenOctrees representation, which uses spherical harmonics to encode view-dependent appearance in a sparse octree. The optimization step was added to refine the quality of the converted octree, addressing artifacts from the initial grid-based extraction and sampling [S1, unofficial]. It is part of the broader effort to make NeRFs practical for real-time applications by replacing neural network inference with explicit, optimizable structures [S1, unofficial].
