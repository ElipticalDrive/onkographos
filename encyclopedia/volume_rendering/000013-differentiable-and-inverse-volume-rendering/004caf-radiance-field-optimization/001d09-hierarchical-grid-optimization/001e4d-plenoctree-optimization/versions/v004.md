# PlenOctree Optimization

Also called: Structure Refinement (Octree Optimization)

## Overview
PlenOctree Optimization is a post-training fine-tuning process that refines a pre-converted PlenOctree on original training images using the NeRF loss with SGD to improve image quality [S1, unofficial]. It solves the performance bottleneck of conventional NeRFs, which require dense sampling and neural network inference for every ray sample dependent on viewing direction [S1, unofficial]. What sets it apart from its siblings, such as [Plenoxels Optimization Configuration](929-plenoxels-optimization-configuration.md) and [Coarse-to-Fine Optimization with Pruning](1153-coarse-to-fine-optimization-with-pruning.md), is that it operates on a fixed tree structure derived from a pre-trained neural network, focusing on attribute optimization rather than structural growth or neural weight updates [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A PlenOctree converted from a trained NeRF-SH model, containing density $\sigma$ and spherical harmonics (SH) coefficients for color $\mathbf{c}$ at each leaf node. Training images and camera poses.
- **Output:** An optimized PlenOctree with refined $\sigma$ and $\mathbf{c}$ attributes.

**Data Structures:**
- **PlenOctree:** A sparse octree where each leaf node stores:
  - Density $\sigma$ (scalar).
  - Color coefficients: A vector of SH coefficients for each RGB channel. The specific dimension depends on the SH degree used during conversion (typically degree 3 or 4 for real-time rendering) [S1, unofficial].
  - No neural network weights are stored or updated.

**Numbered Steps:**
1. **Initialization:** Load the converted PlenOctree. Ensure attributes are in float32 for stability during optimization [S1, unofficial].
2. **Ray Sampling:** Select random pixels from the training images. Compute ray origins and directions using camera intrinsics ($K$) and extrinsics ($c2w$).
3. **Forward Pass (Volume Rendering):**
   - Sample points along rays within near/far bounds.
   - Interpolate or retrieve $\sigma$ and SH coefficients from the octree leaves.
   - Compute transmittance and accumulated color $\hat{C}(\mathbf{r})$ using the volume rendering integral [S1, unofficial].
   - The rendering equation uses the piecewise constant approximation of density and color within each voxel [S1, unofficial].
4. **Loss Computation:** Calculate the photometric loss:
   $$
   \mathcal{L} = \sum_{\mathbf{r} \in \mathcal{R}} \left\| C(\mathbf{r}) - \hat{C}(\mathbf{r}) \right\|_2^2
   $$
   Note: No sparsity loss is applied since the octree is already sparse [S1, unofficial].
5. **Backpropagation:** Compute gradients of $\mathcal{L}$ with respect to $\sigma$ and SH coefficients. The analytic derivatives of the NeRF piecewise constant volume rendering equation are used [S1, unofficial]. These derivatives are implemented in custom CUDA kernels for efficiency [S1, unofficial].
6. **Weight Update:** Update the leaf node attributes using Stochastic Gradient Descent (SGD).
7. **Scheduling:** Adjust learning rate and epochs based on dataset-specific parameters. Monitor PSNR on a validation set for early stopping [S1, unofficial].

**Parameters:**
- **Learning Rate:**
  - NeRF-synthetic dataset: $1 \times 10^7$ [S1, unofficial].
  - Tanks&Temples dataset: $1.5 \times 10^6$ [S1, unofficial].
- **Epochs:**
  - NeRF-synthetic dataset: Maximum 80 epochs [S1, unofficial].
  - Tanks&Temples dataset: Maximum 40 epochs [S1, unofficial].
- **Validation Set:** For Tanks&Temples, hold out 10% of the training set as validation set [S1, unofficial].
- **Precision:** Float32 for optimization, Float16 for storage [S1, unofficial].

**Pseudocode:**
```python
def plenoptree_optimization(plenoctree, training_data, config):
    """
    Optimizes a PlenOctree using SGD on training images.
    """
    # Initialize optimizer with float32 precision
    optimizer = SGD(params=plenoctree.attributes, lr=config.learning_rate)
    
    # Validation set setup (if applicable)
    if config.has_validation:
        val_data = config.validation_set
    
    for epoch in range(config.max_epochs):
        total_loss = 0
        for ray_batch in training_data:
            # Forward pass: render rays using current PlenOctree
            # Uses analytic derivatives for gradients
            rendered_colors = render_plenoctree(plenoctree, ray_batch.rays)
            
            # Compute MSE loss
            gt_colors = ray_batch.gt_colors
            loss = sum((gt - pred)**2 for gt, pred in zip(gt_colors, rendered_colors))
            
            # Backpropagation
            loss.backward()
            optimizer.step()
            optimizer.zero_grad()
            
            total_loss += loss.item()
        
        # Early stopping check
        if config.has_validation and epoch % config.val_interval == 0:
            val_psnr = evaluate_psnr(plenoctree, val_data)
            if val_psnr < best_psnr - threshold:
                break
            best_psnr = val_psnr
            
    # Convert to float16 for storage
    plenoctree.attributes = plenoctree.attributes.to(torch.float16)
    return plenoctree
```

## Subtopics

### [PlenOctree Conversion](1359-plenoctree-conversion.md)
PlenOctree Conversion is a pipeline that transforms a trained NeRF-SH (Neural Radiance Field with Spherical Harmonics) model into a sparse octree representation called a PlenOctree, enabling real-time volume rendering. It solves the performance bottleneck of conventional NeRFs, which require dense sampling and neural network inference for every ray sample dependent on viewing direction. What sets it apart from its siblings, such as [Analytic Derivatives of PlenOctree Rendering](1360-analytic-derivatives-of-plenoctree-rendering.md), is that it focuses on the *construction* and *tabulation* of the view-dependent volume from a pre-trained neural network, rather than the differentiable optimization of the octree structure itself.

### [Analytic Derivatives of PlenOctree Rendering](1360-analytic-derivatives-of-plenoctree-rendering.md)
This method provides the closed-form gradients of the NeRF piecewise constant volume rendering equation with respect to the density ($\boldsymbol{\sigma}$) and color ($\mathbf{c}$) parameters. It enables direct optimization of PlenOctree attributes using gradient-based methods (e.g., SGD) to refine image quality.

### PlenOctree Fine-tuning
Stop training the NeRF model early, convert it into a PlenOctree, and then train the PlenOctree significantly faster as it no longer involves neural networks [S1, unofficial]. The approach accelerates NeRF-based rendering by 5 orders of magnitude without loss in image quality [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Optimization is significantly faster than NeRF training. It operates at about 3 million rays per second, compared to about 9,000 for NeRF training [S1, unofficial].
- **Memory Complexity:** The octree structure is sparse, reducing memory usage compared to dense grids. Storage precision is reduced to float16 after optimization to further reduce model size [S1, unofficial].
- **Measured Performance:** On a single NVIDIA V100 GPU, PlenOctree optimization takes around 10 minutes per scene [S1, unofficial]. This is a substantial reduction from the ~50 hours required for NeRF training [S1, unofficial].
- **Strengths:** Real-time rendering capability, fast optimization time, high image quality comparable to NeRF [S1, unofficial].
- **Limitations:** Requires a pre-trained NeRF model. The tree structure is fixed during optimization, so it cannot adapt to new geometric details that were not captured in the initial conversion [S1, unofficial].
- **When to use:** When real-time rendering of a NeRF is required and the scene is static.
- **When not to use:** When the scene geometry is unknown or requires structural adaptation during optimization (use [Coarse-to-Fine Optimization with Pruning](1153-coarse-to-fine-optimization-with-pruning.md) instead).

## Background
PlenOctree Optimization was introduced in the paper "PlenOctrees For Real-time Rendering of Neural Radiance Fields (NeRFs)" [S1, unofficial]. It builds on the concept of PlenOctrees, which replace the neural network in NeRF with a sparse octree of spherical harmonics coefficients. The optimization step was added to refine the quality of the converted PlenOctree, addressing potential artifacts from the initial conversion process. The method leverages the sparsity of the octree and the analytical nature of the SH coefficients to enable fast, differentiable rendering and optimization.
