# PlenOctree Conversion

Also called: NeRF-SH to PlenOctree conversion, PlenOctree extraction

## Overview
PlenOctree Conversion is a pipeline that transforms a trained NeRF-SH (Neural Radiance Field with Spherical Harmonics) model into a sparse octree representation called a PlenOctree, enabling real-time volume rendering [S1, unofficial]. It solves the performance bottleneck of conventional NeRFs, which require dense sampling and neural network inference for every ray sample dependent on viewing direction [S1, unofficial]. What sets it apart from its siblings, such as [Analytic Derivatives of PlenOctree Rendering](1360-analytic-derivatives-of-plenoctree-rendering.md), is that it focuses on the *construction* and *tabulation* of the view-dependent volume from a pre-trained neural network, rather than the differentiable optimization of the octree structure itself.

## How it works
**Inputs:** A trained NeRF-SH model (a neural network that outputs density $\sigma$ and Spherical Harmonics (SH) coefficients for a given 3D position $\mathbf{x}$, eliminating the need for view-direction input to the network) [S1, unofficial].
**Outputs:** A sparse octree where each leaf node stores a density value $\sigma$ and a set of SH coefficients representing view-dependent radiance [S1, unofficial].

**Data Structures:**
*   **Octree Node:** Contains a density value $\sigma$ and SH coefficients. The SH coefficients encode the view-dependent appearance.
*   **Voxel Grid:** A uniformly spaced 3D grid used during the initial evaluation phase.

**Parameters:**
*   $\tau_w$: Threshold for voxel weight (maximum ray weight) to determine which voxels are retained. Typical value not explicitly given, but used to eliminate non-visible voxels [S1, unofficial].
*   $\tau_a$: Threshold for density to determine the bounding box of the scene content (used to scale the grid) [S1, unofficial].
*   $N_{samples}$: Number of random points sampled per voxel to reduce aliasing. Value: 256 [S1, unofficial].
*   $\gamma$: Early-stopping transmittance threshold during rendering. Value: 0.01 [S1, unofficial].

**Steps:**
1.  **Evaluation:** Evaluate the NeRF-SH model to obtain density values $\sigma$ on a uniformly spaced 3D grid. The grid is automatically scaled to tightly fit the scene content by pre-evaluating $\sigma$ on a larger grid and finding the bounding box of all points with $\sigma \ge \tau_a$ [S1, unofficial].
2.  **Filtering:** Render alpha maps for all training views using the voxel grid. Track the maximum ray weight $1 - \exp(-\sigma_i \delta_i)$ at each voxel, where $\delta_i$ is the segment length. Eliminate voxels whose weights are lower than the threshold $\tau_w$. This filtering by maximum ray weight is superior to naively thresholding by $\sigma$ at each point because it eliminates non-visible voxels [S1, unofficial].
3.  **Sampling:** For each remaining voxel in the filtered grid, sample $N_{samples} = 256$ random points within the voxel volume. Set the associated leaf of the octree to the mean of these sampled values (density and SH coefficients) to reduce aliasing [S1, unofficial].

**Pseudocode:**
```python
def convert_nerf_to_plenoctree(nerf_sh_model, training_views, tau_w, tau_a):
    # Step 1: Evaluation
    # Determine bounding box based on density threshold tau_a
    # This is done by pre-evaluating sigma on a larger grid
    bounding_box = find_bounding_box(nerf_sh_model, threshold=tau_a)
    
    # Create a uniformly spaced 3D grid within the bounding box
    grid = create_uniform_3d_grid(bounding_box)
    
    # Evaluate NeRF-SH model on grid points to get sigma
    # Note: NeRF-SH outputs SH coefficients, but for grid evaluation,
    # we primarily need sigma for the initial filtering.
    # The grid stores sigma values initially.
    grid_sigma = evaluate_nerf_sigma(nerf_sh_model, grid.points)
    
    # Step 2: Filtering
    # Render alpha maps for all training views to compute voxel weights
    voxel_weights = compute_max_ray_weights(grid, training_views, grid_sigma)
    
    # Retain only voxels with weight >= tau_w
    retained_voxels = [v for v in grid.voxels if voxel_weights[v] >= tau_w]
    
    # Step 3: Sampling
    # Build the octree from retained voxels
    plen_octree = Octree()
    
    for voxel in retained_voxels:
        # Sample 256 random points within the voxel
        samples = sample_random_points_in_voxel(voxel, n=256)
        
        # Evaluate NeRF-SH model at these sample points
        # NeRF-SH returns (sigma, sh_coeffs)
        sample_results = [nerf_sh_model(sample.position) for sample in samples]
        
        # Compute mean of sigma and SH coefficients
        mean_sigma = mean([r.sigma for r in sample_results])
        mean_sh_coeffs = mean([r.sh_coeffs for r in sample_results])
        
        # Add leaf to octree
        plen_octree.add_leaf(voxel.center, mean_sigma, mean_sh_coeffs)
        
    return plen_octree
```

**Edge Cases and Pitfalls:**
*   **Precision:** The conversion process takes about 15 minutes, indicating computational intensity [S1, unofficial].
*   **Boundaries:** The grid scaling must tightly fit the scene to avoid wasting memory on empty space [S1, unofficial].
*   **Degenerate Input:** If $\tau_w$ is set too high, too many voxels may be removed, leading to visual artifacts. If set too low, the octree may not be sparse enough for real-time performance [S1, unofficial].

## Subtopics

### PlenOctree
An octree-based 3D representation (sparse voxel-based octree) that supports view-dependent effects by storing appearance and density values required to model radiance at a point in the volume. It is named after plenoptic functions [S1, unofficial]. Unlike naive NeRF rendering which requires dense sampling and neural network inference for every sample dependent on viewing direction, PlenOctrees pre-tabulate the NeRF into a view-dependent volume, removing the need for neural network queries at test time [S1, unofficial]. Rendering performance is 167.68 FPS on an NVIDIA V100 GPU for 800x800 images, which is over 3000 times faster than conventional NeRFs (approx. 30 seconds per image) [S1, unofficial]. The values in the leaves are calculated by summing the weighted spherical harmonic bases evaluated at the corresponding ray direction $(\theta, \phi)$ [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The conversion process (evaluation, filtering, sampling) takes about 15 minutes [S1, unofficial].
*   **Memory Complexity:** Sparse octree structure reduces memory requirements compared to dense voxel grids [S1, unofficial].
*   **Measured Performance:** 167.68 FPS on an NVIDIA V100 GPU for 800x800 images [S1, unofficial].
*   **Scaling:** Real-time performance is achieved by pre-tabulating the NeRF, allowing interactive rendering in a browser on consumer laptops [S1, unofficial].
*   **Strengths:** Preserves view-dependent effects such as specularities; over 3000 times faster than conventional NeRFs; amenable to modern web technologies [S1, unofficial].
*   **Limitations:** Requires a trained NeRF-SH model; conversion time is non-trivial (15 minutes) [S1, unofficial].
*   **When to use:** When real-time rendering of view-dependent scenes is required without sacrificing quality [S1, unofficial].
*   **When not to use:** When the scene has extreme view-dependent effects that cannot be captured by spherical harmonics, or when the conversion time is prohibitive [S1, unofficial].

## Background
PlenOctrees were introduced by Alex Yu, Ruilong Li, Matthew Tancik, Hao Li, Ren Ng, and Angjoo Kanazawa from UC Berkeley, USC Institute for Creative Technologies, and Pinscreen [S1, unofficial]. The method builds on the concept of plenoptic functions by Adelson and Bergen [S1, unofficial]. It was developed to address the slow rendering speed of NeRFs, which require dense sampling and neural network inference for every sample dependent on viewing direction [S1, unofficial]. The approach factorizes the appearance via closed-form spherical basis functions, specifically spherical harmonics, to enable real-time rendering [S1, unofficial].
