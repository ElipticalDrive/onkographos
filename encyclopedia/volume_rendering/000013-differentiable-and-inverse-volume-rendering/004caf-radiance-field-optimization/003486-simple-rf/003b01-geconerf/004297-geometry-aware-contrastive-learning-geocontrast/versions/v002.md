# Geometry Aware Contrastive Learning (GeoContrast)


## Overview
Geometry Aware Contrastive Learning (GeoContrast) is a contrastive learning method that enforces multi-view consistency by using geometric constraints to define positive and negative samples, distinguishing surface points from non-surface points [S1]. It differs from sibling methods that rely on random pixel sampling by explicitly constructing pairs based on 3D geometric projections [S1].

## How it works
GeoContrast operates on pairs of source views to extract geometrically enhanced features [S1]. It constructs contrastive pairs by projecting 2D pixels into 3D space and re-projecting them into other views, using ground truth depth to identify surface correspondences [S1].

### Inputs and Outputs
*   **Inputs:**
    *   A set of $N_{near}$ source views $\{I_i, K_i, E_i\}_{i=1}^{N_{near}}$, where $I_i$ is the image, $K_i$ is the intrinsic matrix, and $E_i$ is the extrinsic matrix [S1].
    *   Ground truth depth maps $\delta$ for the source views [S1].
    *   A shared CNN feature extractor $M(\cdot)$ that produces feature maps $F_i$ from images $I_i$ [S1].
    *   Hyperparameters: $N_c$ (number of sampled pixels per view), $N_{neg}$ (number of negative samples per pixel), $\tau'$ (temperature, default 10000) [S1].
*   **Outputs:**
    *   A scalar contrastive loss value $L_{contrast}$ used to update the feature extractor weights [S1].

### Data Structures
*   **Pixel Coordinate:** $p = (u, v)^\top$ representing a 2D coordinate in a source view [S1].
*   **Homogeneous Coordinate:** $\tilde{p}$ representing $p$ in homogeneous coordinates [S1].
*   **3D Point:** $p_3$ representing a point in world coordinates [S1].
*   **Feature Vector:** $f_p$ representing the feature vector extracted at pixel $p$ [S1].

### Numbered Steps
1.  **Feature Extraction:** For each source view $i$, extract feature maps $F_i$ using the shared CNN $M(\cdot)$ [S1].
2.  **Pixel Sampling:** For a pair of source views $i$ and $j$, randomly sample a batch of $N_c$ pixels $\{p\}$ from view $i$ [S1].
3.  **Positive Pair Construction:**
    *   For each sampled pixel $p$ in view $i$, retrieve its depth $\delta_p$ from the ground truth depth map [S1].
    *   Compute the 3D point $p_3$ corresponding to $p$ using the camera parameters:
        $$ p_3 = t_i + \delta_p R_i K_i^{-1} \tilde{p} $$
        where $t_i$ and $R_i$ are the translation and rotation components of the extrinsic matrix $E_i$ for view $i$ [S1].
    *   Project $p_3$ into view $j$ to obtain the 2D coordinate $q^+$:
        $$ q^+ = K_j (R_j^{-1} (p_3 - t_j)) $$
        [S1].
    *   **Occlusion Check:** Verify that the region around $q^+$ in view $j$ is unoccluded [S1]. If occluded, discard $(p, q^+)$ as a positive pair [S1]. If unoccluded, $(p, q^+)$ is a positive pair [S1].
4.  **Negative Pair Construction:** For the same pixel $p$ in view $i$, generate $N_{neg}$ negative samples $\{q^-\}_{k=1}^{N_{neg}}$ in view $j$ [S1]. These are obtained by projecting $p$ to view $j$ using different depth hypotheses or by sampling pixels that do not correspond to the surface point $p_3$ [S1]. Each negative pair represents the projection of a non-surface 3D point [S1].
5.  **Weight Calculation:** Calculate the weight $\lambda_{q^-}$ for each negative sample $q^-$ based on its geometric distance to the positive sample $q^+$:
    $$ \lambda_{q^-} = \frac{\exp(\|q^+ - q^-\|^2 / \tau')}{\sum_{r \in R} \exp(\|q^+ - r\|^2 / \tau')} $$
    where $R$ is the set of negative samples in the batch, and $\tau' = 10000$ [S1].
6.  **Loss Computation:** Compute the contrastive loss for pixel $p$ using a weighted InfoNCE formulation:
    $$ L_{contrast}^p = -\log \frac{\exp(-\|q^+ - q^+\|^2 / \tau')}{\exp(-\|q^+ - q^+\|^2 / \tau') + \sum_{k=1}^{N_{neg}} \lambda_{q_k^-} \exp(-\|q^+ - q_k^-\|^2 / \tau')} $$
    [S1]. The final contrastive loss is averaged over all samples $p$ and all source view pairs:
    $$ L_{contrast} = \frac{1}{N_c} \sum_{p} L_{contrast}^p $$
    [S1].

### Pseudocode
```python
import numpy as np
import random

def geometry_aware_contrastive_loss(
    features_i, features_j, 
    depth_i, depth_j,
    K_i, K_j, E_i, E_j,
    N_c, N_neg, tau_prime=10000.0
):
    """
    Computes the GeoContrast loss for a pair of views i and j.
    
    Args:
        features_i: Feature map for view i, shape (H, W, C)
        features_j: Feature map for view j, shape (H, W, C)
        depth_i: Depth map for view i, shape (H, W)
        depth_j: Depth map for view j, shape (H, W)
        K_i, K_j: Intrinsic matrices (3x3)
        E_i, E_j: Extrinsic matrices (4x4)
        N_c: Number of pixels to sample
        N_neg: Number of negative samples per pixel
        tau_prime: Temperature parameter
        
    Returns:
        loss: Scalar contrastive loss
    """
    H, W, C = features_i.shape
    TOLERANCE = 0.05  # [G] Standard depth consistency threshold
    
    sampled_u = [random.randint(0, H - 1) for _ in range(N_c)]
    sampled_v = [random.randint(0, W - 1) for _ in range(N_c)]
    
    total_loss = 0.0
    valid_count = 0
    
    for k in range(N_c):
        u, v = sampled_u[k], sampled_v[k]
        p_hom = np.array([u, v, 1.0])
        delta_p = depth_i[u, v]
        
        R_i = E_i[:3, :3]
        t_i = E_i[:3, 3]
        R_j = E_j[:3, :3]
        t_j = E_j[:3, 3]
        
        cam_coords_i = np.linalg.inv(K_i) @ p_hom
        p3 = t_i + delta_p * (R_i @ cam_coords_i)
        
        cam_coords_j = np.linalg.inv(R_j) @ (p3 - t_j)
        q_plus_hom = K_j @ cam_coords_j
        q_plus = q_plus_hom[:2] / q_plus_hom[2]
        
        if not (0 <= q_plus[0] < W and 0 <= q_plus[1] < H):
            continue
            
        projected_depth_j = cam_coords_j[2]
        gt_depth_q_plus = depth_j[int(round(q_plus[1])), int(round(q_plus[0]))]
        
        if abs(projected_depth_j - gt_depth_q_plus) > TOLERANCE:
            continue
            
        neg_u = [random.randint(0, H - 1) for _ in range(N_neg)]
        neg_v = [random.randint(0, W - 1) for _ in range(N_neg)]
        q_negs = [np.array([neg_u[m], neg_v[m]]) for m in range(N_neg)]
        
        dist_pos_sq = 0.0
        dist_negs_sq = [np.sum((q_plus - q_neg) ** 2) for q_neg in q_negs]
        
        exp_pos = np.exp(-dist_pos_sq / tau_prime)
        exp_negs = [np.exp(-d / tau_prime) for d in dist_negs_sq]
        
        sum_exp_negs = sum(exp_negs)
        if sum_exp_negs == 0:
            continue
            
        lambdas = [e / sum_exp_negs for e in exp_negs]
        weighted_neg_sim = sum(l * e for l, e in zip(lambdas, exp_negs))
        
        loss_p = -np.log(exp_pos / (exp_pos + weighted_neg_sim))
        total_loss += loss_p
        valid_count += 1
        
    if valid_count == 0:
        return 0.0
    return total_loss / valid_count
```

### Parameters
*   $N_c$: Number of sampled pixels. Not given in the sources.
*   $N_{neg}$: Number of negative samples. Not given in the sources.
*   $\tau'$: Temperature hyper-parameter. Default value is 10000 [S1].

### Edge Cases and Pitfalls
*   **Occlusion:** Positive pairs must be discarded if the projected point $q^+$ is occluded in the target view [S1].
*   **Depth Precision:** The 3D reconstruction $p_3$ relies on ground truth depth $\delta_p$ [S1]. Errors in depth lead to incorrect $p_3$ and thus incorrect $q^+$ [G].
*   **Boundary Conditions:** Projected points $q^+$ or $q^-$ may fall outside the image boundaries [G].

## Subtopics

### GeCoNeRF
The parent method that provides the feature extraction backbone and depth prediction module. GeoContrast is a regularization term added to GeCoNeRF's training objective. [GeCoNeRF](8905-geconerf.md)

### ContraNeRF
The broader class of methods using contrastive learning for NeRF generalization. GeoContrast is a specific variant that uses geometry-aware sampling rather than random sampling [S1]. [ContraNeRF](https://doi.org/10.1109/cvpr52729.2023.01584)

## Operating characteristics
*   **Time Complexity:** Depends on the number of sampled pixels $N_c$ and negative samples $N_{neg}$ [S1]. For each pixel, 3D projection and re-projection are performed [S1].
*   **Memory Complexity:** Requires storing feature maps for source views and depth maps [S1].
*   **Strengths:** Enforces geometric consistency, reducing artifacts in novel view synthesis, especially in few-shot settings [S1].
*   **Limitations:** Relies on ground truth depth for training, which may not be available in real-world scenarios without additional depth estimation [S1]. Computationally more expensive than random sampling due to 3D projections [S1].

## Background
GeoContrast was introduced in the paper "ContraNeRF: Generalizable Neural Radiance Fields for Synthetic-to-real Novel View Synthesis via Contrastive Learning" [S1]. It addresses the problem of generalizing NeRF to unseen scenes by leveraging contrastive learning to enforce multi-view consistency [S1]. The method builds on the GeCoNeRF framework, enhancing it with geometry-aware contrastive pairs [S1].
