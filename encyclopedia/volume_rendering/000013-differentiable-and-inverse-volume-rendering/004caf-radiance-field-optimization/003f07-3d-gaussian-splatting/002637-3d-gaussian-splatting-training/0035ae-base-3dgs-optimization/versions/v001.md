# Base 3DGS Optimization

Also called: Base 3DGS Optimization with Normal Attribute

## Overview
Base 3DGS Optimization initializes the geometry attributes of 3D Gaussian primitives to provide a stable foundation for subsequent shading attribute optimization in editable Gaussian splatting [S1]. It differs from standard 3DGS by incorporating an explicit normal attribute $n$ for each Gaussian and optimizing it via a normal consistency loss, while retaining spherical harmonics (SH) for color representation [S1]. This initialization accelerates the convergence of editable Gaussian optimization by ensuring accurate scene geometry representation before decomposing color and lighting [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** Multi-view images, camera poses, initial Gaussian parameters (position $\mu$, rotation $q$, scale $s$, opacity $o$), and a depth map $D$ (or depth estimation) for the target viewpoint.
*   **Outputs:** Optimized Gaussian parameters $\{\mu_i, q_i, s_i, o_i, n_i, c_i\}$, where $n_i$ is the normal attribute and $c_i$ is the SH coefficient set [S1].

**Data Structures**
Each Gaussian $i$ is parameterized as:
$$ \{\mu_i, q_i, s_i, o_i, n_i, c_i\} $$
*   $\mu_i \in \mathbb{R}^3$: Position.
*   $q_i \in \mathbb{R}^4$: Rotation (quaternion).
*   $s_i \in \mathbb{R}^3$: Scale.
*   $o_i \in \mathbb{R}$: Opacity.
*   $n_i \in \mathbb{R}^3$: Normal attribute [S1].
*   $c_i$: Spherical Harmonics coefficients for view-dependent color [S1].

**Numbered Steps**
1.  **Render Depth and Normal Maps:** For a specified viewpoint, render the depth map $D$ and normal map $N$ using the current Gaussian parameters. The rendering follows the volume rendering equation:
    $$ \{D, N\} = \sum_{i \in \mathcal{N}} T_i \alpha_i \{d_i, n_i\} $$
    where $\mathcal{N}$ is the set of sampled Gaussians, $T_i$ is the accumulated transmittance, $\alpha_i$ is the opacity, $d_i$ is the depth of the $i$-th Gaussian, and $n_i$ is the normal of the $i$-th Gaussian [S1].
2.  **Compute Pseudo Normal:** Calculate a pseudo normal $\tilde{N}$ from the rendered depth map $D$ under the local planarity assumption [S1].
3.  **Compute Normal Consistency Loss:** Calculate the loss between the rendered normal map $N$ and the pseudo normal $\tilde{N}$:
    $$ L_n = ||N - \tilde{N}||_2 $$
    [S1].
4.  **Compute Color/Alpha Loss:** Compute the reconstruction loss for the color and alpha channels using a linear combination of L1 loss and SSIM loss [S1].
5.  **Update Parameters:** Minimize the total loss (L1 + SSIM + $L_n$) using the Adam optimizer to update all Gaussian parameters, including the normal attribute $n_i$ [S1].

**Formulas**
*   **Volume Rendering:**
    $$ D = \sum_{i \in \mathcal{N}} T_i \alpha_i d_i, \quad N = \sum_{i \in \mathcal{N}} T_i \alpha_i n_i $$
    where $T_i = \prod_{j < i} (1 - \alpha_j)$ [S1].
*   **Normal Consistency Loss:**
    $$ L_n = ||N - \tilde{N}||_2 $$
    [S1].
*   **Total Loss:**
    $$ L = L_{color/alpha} + L_n $$
    where $L_{color/alpha}$ combines L1 and SSIM losses [S1].

**Parameters**
*   **Loss Coefficients:** The linear combination of L1 and SSIM losses uses coefficients 0.8 and 0.2 respectively [S1].
*   **Normal Loss Scaling:** The normal consistency loss $L_n$ is scaled by 0.01 [S1].
*   **Learning Rate:** The learning rate for the normal attribute $n$ is 0.01 [S1]. Other attributes are trained using the same schedule as original 3DGS [S1].
*   **Optimizer:** Adam [S1].

**Edge Cases and Pitfalls**
*   **Irrelevance to Rendering:** Adjusting the normal attribute $n$ does not affect the rendering results of the base 3DGS model, as color is still represented by SH coefficients [S1]. The optimization of $n$ is solely for initializing geometry to accelerate subsequent editable Gaussian optimization [S1].
*   **Alpha Channel Optimization:** Optimizing the alpha channel enhances reconstruction quality, so it must be included in the loss calculation alongside color [S1].

## Subtopics

### Editable Gaussian Optimization
Editable Gaussian Optimization decomposes color and lighting from the scene using the Blinn-Phong reflection model instead of SH coefficients, enabling scene editing [S1]. It is chosen when scene recoloring or lighting manipulation is required. It builds on Base 3DGS by adding shading attributes: offset color $\Delta c \in \mathbb{R}^3$, ambient/diffuse/specular coefficients $\{k_a, k_d, k_s\}$, and shininess term $\beta$ [S1]. The voxel color $c_v$ is expressed as $c_p + \Delta c$, where $c_p \in \mathbb{R}^3$ is a shared palette color parameter fixed as the mean color of input images during training [S1]. Low-opacity Gaussians are removed periodically to reduce model size, and an L1 regularization term encourages low opacity to neutralize the tendency to use more Gaussians for compact surfaces due to normal-dependent color [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Not given in the sources for Base 3DGS specifically; iVR-GS (which uses this method) reports rendering times ranging from 59 ms to 1651 ms depending on volume size and resolution [S1].
*   **Scaling:** Not given in the sources.
*   **Strengths:** Provides accurate geometry initialization for editable Gaussian optimization; accelerates convergence of shading attribute optimization [S1].
*   **Limitations:** The normal attribute does not influence the base 3DGS rendering output, making it a preparatory step rather than a direct rendering enhancement [S1].
*   **When to use:** When using editable Gaussian optimization that requires accurate initial geometry and normal information [S1].
*   **When not to use:** When only standard view-dependent color rendering is needed without scene editing capabilities [S1].

## Background
Base 3DGS Optimization was introduced in the iVR-GS paper (2025) as a preliminary step for inverse volume rendering with editable 3D Gaussian Splatting [S1]. It adapts the original 3DGS framework by adding a normal attribute and optimizing it via consistency with depth-derived pseudo normals, addressing the need for accurate geometry decomposition in editable scenes [S1].
