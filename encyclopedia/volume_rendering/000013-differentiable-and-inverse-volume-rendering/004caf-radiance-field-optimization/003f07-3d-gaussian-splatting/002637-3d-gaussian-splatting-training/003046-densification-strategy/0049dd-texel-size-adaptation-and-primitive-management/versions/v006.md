# Texel Size Adaptation and Primitive Management

Also called: Adaptive Texture Allocation, Primitive Management via Quantile Error

## Overview
This method adapts the resolution of per-primitive texture maps and manages the population of 3D Gaussian primitives based on quantile error thresholds, running periodically during training to balance model capacity and appearance quality [S1]. It differs from sibling methods like [Score-based Densification](4705-score-based-densification.md) by explicitly coupling the geometric density of primitives with the local texture resolution, allowing the model to automatically adjust the ratio of primitives to texels based on scene complexity [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** The current set of 3D Gaussian primitives $\mathcal{G}$, their associated texture grids, the current optimization iteration $iter$, and hyperparameters $\tau_{tr}$, $\tau_{ds}$, $\lambda_{texture}$, and $t_{2pr}$.
*   **Output:** Modified set $\mathcal{G}$ (with split primitives), updated texture grid resolutions (upscaled or downscaled), and updated parameters.

**Data Structures:**
*   **Primitive:** Contains mean position, covariance, opacity, spherical harmonics coefficients, and a reference to its texture grid.
*   **Texture Grid:** A 2D array of color/feature values. The resolution is defined by $t_{2pr}$, the number of texels along the smallest axis of the primitive's bounding box in texture space.

**Parameters:**
*   $\tau_{tr}$: Texture resolution threshold. Controls splitting aggressiveness. Starts at 64, progressively reduced to 32 within the first 7000 iterations [S1].
*   $\tau_{ds}$: Downscale threshold. Controls downscaling ease. Higher values make downscaling easier, leading to simpler appearances [S1].
*   $\lambda_{texture}$: Variance control for texture maps. Higher values yield smoother results; lower values result in fewer texels per primitive [S1].
*   $t_{2pr}$: Texture size per primitive (in texels). Initialized at iteration 500 to the closest power of two such that the smallest axis is 8 texels wide [S1].
*   Quantile: Top 90% of errors are considered for splitting/upscaling [S1].

**Steps:**
1.  **Initialization:** At iteration 500, initialize texture grids with zero values. Set $t_{2pr}$ for each primitive to the closest power of two such that the smallest axis is 8 texels wide [S1].
2.  **Periodic Execution:** Every 250 iterations, up to iteration 25,000, execute the following routine [S1]:
    1.  Iterate over all primitives $g_k \in \mathcal{G}$.
    2.  Compute the error $E_k$ for the primitive [S1].
    3.  Determine if $E_k$ is in the top 90% of all computed errors [S1].
    4.  **Splitting:** If the current texture resolution exceeds $\tau_{tr}$ AND $E_k$ is in the top 90%:
        *   Split the primitive along overflowing axes [S1].
    5.  **Upscaling:** If $t_{2pr} > 1$ AND $E_k$ is in the top 90%:
        *   Decrease texel size (Upscale) by increasing the resolution of the texture grid [S1].
    6.  **Downscaling:** Else if the downscale metric $E_d < \tau_{ds}$:
        *   Increase texel size (Downscale) by decreasing the resolution of the texture grid [S1].

**Edge Cases and Pitfalls:**
*   **Hyperparameter Interdependence:** Changing $\tau_{tr}$ to encourage more primitives can indirectly lead to fewer texels per primitive, as each primitive represents a more localized, simpler part of the scene [S1].
*   **Memory Management:** Upscaling texture grids increases memory usage. The method relies on periodic execution to prevent out-of-memory errors during early training [S1].
*   **Initialization:** Texture grids must be initialized to zero and optimization must start after 500 iterations to avoid early overfitting and memory issues [S1].

## Operating characteristics
*   **Time Complexity:** The routine runs every 250 iterations. The cost is proportional to the number of primitives $N$ and the cost of error computation and interpolation. Interpolation is typically $O(T)$ where $T$ is the number of texels.
*   **Memory Complexity:** Memory usage scales with the total number of texels. Default configurations use approximately 20-100M texels for scenes with 150-300K points [S1].
*   **Performance:** On the 'drjohnson' scene (DeepBlending dataset), the default configuration uses 293K points, 20.8M texels, 79.7M parameters, achieving 77 FPS and 318MB memory [S1]. On the 'bonsai' scene (Tanks&Temples dataset), it uses 291K points, 9.0M texels, 44.1M parameters, achieving 35 FPS and 176MB memory [S1].
*   **Strengths:** Automatically adjusts the ratio of primitives to texels, robust to different hyperparameter settings, and converges to good results across various scene complexities [S1].
*   **Limitations:** Requires careful tuning of $\tau_{tr}$ and $\tau_{ds}$ to balance detail and performance. The indirect effects of hyperparameters can make prediction of final model size difficult [S1].

## Background
This method was introduced by Panagiotis Papantonakis, Georgios Kopanas, Frédo Durand, and George Drettakis in their work on "Content-Aware Texturing for Gaussian Splatting" [S1]. It addresses the need for efficient representation of high-frequency details in novel view synthesis by decoupling geometric density from texture resolution and allowing both to adapt based on rendering error [S1].
