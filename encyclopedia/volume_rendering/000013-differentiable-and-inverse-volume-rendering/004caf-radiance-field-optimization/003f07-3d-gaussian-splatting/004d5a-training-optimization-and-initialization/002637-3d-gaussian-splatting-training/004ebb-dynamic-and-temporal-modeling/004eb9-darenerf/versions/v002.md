# DaReNeRF

Also called: Direction-aware Representation for Dynamic Scenes

## Overview
DaReNeRF is a method for novel view synthesis of dynamic scenes that addresses the shift variance and direction ambiguity inherent in traditional Discrete Wavelet Transforms (DWT) by employing a direction-aware representation [S1]. It decomposes the 4D spatiotemporal volume into a sum of Hadamard products of learned 2D plane-based representations and vectors, leveraging the Dual-Tree Complex Wavelet Transform (DTCWT) to capture features from six distinct orientations [S1]. Unlike standard plane-based decompositions that suffer from checkerboard artifacts and poor motion modeling, DaReNeRF ensures shift invariance and directional selectivity, significantly reducing memory complexity from $O(N^3 T F)$ to $O(R N^2 T F)$ [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** A set of posed 2D images with associated timestamps $t$.
*   **Outputs:** Rendered RGB images for arbitrary camera poses and time steps.

**Data Structures**
The core data structure is the direction-aware representation of the 4D volume $D$.
*   **Planes:** A set of learned 2D tensors $M_{rAB} \in \mathbb{R}^{A \times B}$, where $(A, B)$ are distinct dimensions from the set $\{X, Y, Z, T\}$.
*   **Vectors:** A set of learned vectors $v_{ri} \in \mathbb{R}^F$ for each component $r$ and term $i \in \{1, 2, 3\}$.
*   **Tensor V:** A 2D tensor formed by stacking all $v_{ri}$ vectors.
*   **MLP:** A compact Multi-Layer Perceptron for color regression.

**Parameters**
*   $N$: Spatial resolution.
*   $T$: Temporal resolution.
*   $F$: Feature size (typically 3 for RGB).
*   $R_1, R_2, R_3$: Number of low-rank components for each of the three decomposition terms.
*   $R$: Total number of low-rank components, $R = R_1 + R_2 + R_3$.
*   Constraint: $R \ll N$ [S1].

**Method Steps**
1.  **Decomposition:** Represent the 4D spatiotemporal volume $D$ as the sum of three terms, each consisting of the Hadamard product of two 2D plane-based representations and a learned vector [S1]:
    $$
    D = \sum_{r=1}^{R_1} M_{rXY} \circ M_{rZT} \circ v_{r1} + \sum_{r=1}^{R_2} M_{rXZ} \circ M_{rYT} \circ v_{r2} + \sum_{r=1}^{R_3} M_{rYZ} \circ M_{rXT} \circ v_{r3}
    $$
    where $\circ$ denotes the Hadamard (element-wise) product [S1].

2.  **Feature Computation:** For a given space-time point, compute density and appearance features by:
    *   Extracting feature vectors from the paired planes (e.g., $M_{XY}$ and $M_{ZT}$).
    *   Multiplying these vectors.
    *   Concatenating the multiplied results from all three terms into a single vector.
    *   Multiplying the concatenated vector by $V$, the 2D tensor stacking all $v_{ri}$ [S1].

3.  **Opacity Query:** Query point opacities directly from the computed density features [S1].

4.  **Color Regression:** Regress RGB color values using a compact MLP. The inputs to the MLP are the appearance features derived in Step 2 and the view direction [S1].

5.  **Rendering:** Synthesize final images via differentiable volumetric rendering along rays, using the queried opacities and regressed colors [S1].

**Pseudocode**
```python
def darenerf_forward(xyz, t, view_dir, planes, vectors, color_mlp):
    """
    xyz: (N, 3) array of spatial coordinates
    t: (N,) array of time coordinates
    view_dir: (N, 3) array of view directions
    planes: Dictionary of 2D tensors M_rAB
    vectors: List of vectors v_ri
    color_mlp: Function for color regression
    """
    # Step 1 & 2: Compute features for each of the 3 terms
    features_list = []
    
    # Term 1: XY and ZT planes
    # Extract features based on coordinates
    feat_xy = planes['XY'][xyz[:, 0], xyz[:, 1]] # Shape: (N, F)
    feat_zt = planes['ZT'][xyz[:, 2], t]        # Shape: (N, F)
    # Hadamard product and vector multiplication
    # v_r1 is vectors[0]
    term1 = (feat_xy * feat_zt) * vectors[0]     # Shape: (N, F)
    features_list.append(term1)
    
    # Term 2: XZ and YT planes
    feat_xz = planes['XZ'][xyz[:, 0], xyz[:, 2]] # Shape: (N, F)
    feat_yt = planes['YT'][xyz[:, 1], t]         # Shape: (N, F)
    # v_r2 is vectors[1]
    term2 = (feat_xz * feat_yt) * vectors[1]     # Shape: (N, F)
    features_list.append(term2)
    
    # Term 3: YZ and XT planes
    feat_yz = planes['YZ'][xyz[:, 1], xyz[:, 2]] # Shape: (N, F)
    feat_xt = planes['XT'][xyz[:, 0], t]         # Shape: (N, F)
    # v_r3 is vectors[2]
    term3 = (feat_yz * feat_xt) * vectors[2]     # Shape: (N, F)
    features_list.append(term3)
    
    # Concatenate results
    concatenated_features = torch.cat(features_list, dim=1) # Shape: (N, 3*F)
    
    # Multiply by V (stacked vectors)
    # V shape: (3*F, F) assuming vectors are stacked appropriately
    # Note: The source describes multiplying by V which stacks all v_ri.
    # Assuming V is constructed from the list of vectors.
    V = torch.stack(vectors, dim=0) # Shape: (3, F) -> needs reshaping to match concatenated dims
    # Correct interpretation: V is a 2D tensor stacking all v_ri. 
    # If concatenated is (N, 3*F), V should be (3*F, F) or similar.
    # Based on "multiplies them by V RF", V is likely (3*F, F).
    # Let's assume V is pre-computed as (3*F, F).
    density_appearance_features = concatenated_features @ V.T # Shape: (N, F)
    
    # Step 3: Query opacities from density features
    # Assuming density features are the first part or derived directly.
    # Source says "point opacities are directly queried from the density features".
    # We assume a simple identity or sigmoid mapping for opacity from the first F/2 or similar.
    # For implementation completeness, we assume density features are used to derive opacity.
    opacity = torch.sigmoid(density_appearance_features[:, :F]) # Placeholder for specific opacity head
    
    # Step 4: Regress color
    color = color_mlp(density_appearance_features, view_dir) # Shape: (N, 3)
    
    return opacity, color
```

## Operating characteristics
*   **Memory Complexity:** Reduced from $O(N^3 T F)$ for direct 4D volume modeling to $O(R N^2 T F)$ using the plane-based decomposition [S1].
*   **Strengths:** Overcomes shift variance and poor direction selectivity of traditional DWT. Captures scene dynamics from six distinct orientations, avoiding checkerboard patterns and ghosting artifacts around moving objects [S1].
*   **Limitations:** Introduces 2D redundancy (with $d=2$ for plane-based decomposition) compared to DWT representation, resulting in lower storage efficiency than ideal wavelet representations, though still better than direct modeling [S1].
*   **When to use:** Suitable for novel view synthesis of dynamic scenes with complex motions where shift invariance and directional features are critical [S1].
*   **When not to use:** When storage efficiency is the primary constraint and motion is minimal or static [S1].

## Background
DaReNeRF was introduced to address the limitations of standard plane-based 4D volume decompositions and traditional Discrete Wavelet Transforms (DWT) in dynamic scene modeling. Traditional 2D DWT suffers from shift variance, where small shifts in input signals disrupt wavelet oscillation patterns, leading to poor results in dynamic regions with motion or camera movement [S1]. Additionally, DWT has poor direction selectivity, producing a checkered pattern that blends representations from $\pm 45^\circ$, causing ghosting artifacts [S1]. Inspired by the Dual-Tree Complex Wavelet Transform (DTCWT), DaReNeRF proposes a direction-aware representation that learns features from six distinct orientations, ensuring shift invariance and better modeling of complex dynamic scenes [S1]. It builds on the baseline plane-based decomposition [7] and integrates with differentiable volumetric rendering [S1].
