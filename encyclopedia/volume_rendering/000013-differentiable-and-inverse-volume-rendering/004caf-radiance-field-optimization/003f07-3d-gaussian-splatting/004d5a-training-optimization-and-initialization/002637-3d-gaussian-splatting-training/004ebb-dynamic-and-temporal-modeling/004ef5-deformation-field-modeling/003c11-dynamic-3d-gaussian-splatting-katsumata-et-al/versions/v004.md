# Dynamic 3D Gaussian Splatting (Katsumata et al.)
Also called: Dynamic 3DGS, Fourier-based Dynamic 3DGS, Katsumata et al

## Overview
Dynamic 3D Gaussian Splatting models dynamic scenes by keeping the intrinsic properties of 3D Gaussians (such as scale and color) unchanged over time, while allowing their positions and orientations to change [S1, S2]. It distinguishes itself from implicit deformation methods by using explicit parametric functions (Fourier series for position, linear functions for rotation), ensuring that the number of optimization parameters remains independent of the number of time steps [S2]. This approach leverages the periodic nature of many motions to ensure temporal continuity and robust novel view synthesis [S2].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A sequence of images of a dynamic scene captured at different timestamps $t$.
*   **Outputs:** A set of 3D Gaussians where position $\mathbf{p}(t)$ and rotation $\mathbf{q}(t)$ are time-dependent, while other attributes (opacity, scale, spherical harmonics coefficients) are static.

**Data Structures:**
Each Gaussian $i$ stores:
1.  **Static Attributes:** Mean scale $\mathbf{s}_i$, opacity $\alpha_i$, spherical harmonics coefficients $\mathbf{c}_i$.
2.  **Time-Dependent Position Parameters:** Fourier series coefficients $\mathbf{A}_i, \mathbf{B}_i$ for each spatial dimension.
3.  **Time-Dependent Rotation Parameters:** Linear function coefficients (slope and intercept) for quaternion components or axis-angle representation.

**Formulas:**
The position $\mathbf{p}_i(t)$ is modeled using a Fourier series [S2]:
$$ \mathbf{p}_i(t) = \mathbf{a}_0 + \sum_{k=1}^{K} \left( \mathbf{a}_k \cos(k \omega t) + \mathbf{b}_k \sin(k \omega t) \right) $$
where $\mathbf{a}_0, \mathbf{a}_k, \mathbf{b}_k$ are learned coefficients, $K$ is the number of harmonics, and $\omega$ is the base frequency.

The rotation $\mathbf{q}_i(t)$ is approximated by a linear function of time [S2]:
$$ \mathbf{q}_i(t) = \mathbf{q}_{start} + t \cdot \mathbf{v}_{rot} $$
(Note: The resulting vector must be normalized to maintain unit quaternion properties).

**Numbered Steps:**
1.  **Initialization:** Initialize 3D Gaussians from static SfM points or random initialization. Assign static attributes ($\mathbf{s}, \alpha, \mathbf{c}$).
2.  **Parameter Assignment:** For each Gaussian, initialize Fourier coefficients for position and linear coefficients for rotation.
3.  **Rendering:** For a given timestamp $t$, compute $\mathbf{p}_i(t)$ and $\mathbf{q}_i(t)$ for all Gaussians. Render the image using standard 3D Gaussian Splatting rasterization with these time-varying transforms.
4.  **Loss Computation:**
    *   Compute image reconstruction loss (e.g., L1 or SSIM) between rendered and ground truth images.
    *   Compute bidirectional optical flow loss between rendered frames and ground truth frames to enforce temporal consistency [S2].
5.  **Optimization:** Optimize the Fourier and linear function parameters along with static attributes. The total number of parameters is fixed regardless of the number of time steps [S2].
6.  **Iteration:** Repeat steps 3-5 until convergence.

**Pseudocode:**
```python
def compute_position(fourier_coeffs, t, base_freq):
    """
    Computes position using Fourier series.
    fourier_coeffs: tuple (a0, a_k, b_k) where a_k, b_k are arrays of shape (K, 3)
    t: scalar time
    base_freq: scalar omega
    """
    a0, a_k, b_k = fourier_coeffs
    pos = a0
    for k in range(1, len(a_k) + 1):
        k_omega_t = k * base_freq * t
        pos += a_k[k-1] * cos(k_omega_t) + b_k[k-1] * sin(k_omega_t)
    return pos

def compute_rotation(linear_coeffs, t):
    """
    Computes rotation using linear approximation.
    linear_coeffs: tuple (q_start, v_rot)
    t: scalar time
    """
    q_start, v_rot = linear_coeffs
    q = q_start + t * v_rot
    return normalize(q)

def dynamic_3dgs_render(gaussians, t, base_freq):
    """
    Renders a frame at time t.
    """
    for g in gaussians:
        g.pos = compute_position(g.fourier_coeffs, t, base_freq)
        g.rot = compute_rotation(g.linear_coeffs, t)
    return standard_3dgs_rasterize(gaussians)

def train_dynamic_3dgs(images, timestamps, base_freq):
    """
    Optimizes dynamic 3DGS parameters.
    """
    for epoch in range(max_epochs):
        for img, t in zip(images, timestamps):
            rendered_img = dynamic_3dgs_render(gaussians, t, base_freq)
            loss = image_loss(rendered_img, img) + optical_flow_loss(rendered_img, img)
            loss.backward()
            optimizer.step()
```

**Edge Cases and Pitfalls:**
*   **Quaternion Normalization:** The linear approximation of rotation may result in non-unit quaternions; normalization is required after computation [S2].
*   **Periodicity Assumption:** Fourier series assumes periodic motion. Non-periodic or transient motions may be poorly modeled [S2].
*   **Temporal Continuity:** The parametric nature ensures continuity, but insufficient Fourier harmonics $K$ may lead to aliasing or smoothing artifacts [S2].

## Subtopics

### Dual-Domain Deformation Model (Gaussian-Flow)
Combines polynomial fitting (for smooth motion) and Fourier approximation (for violent motion) in time and frequency domains. It models position, rotation, and color changes over time and uses adaptive timestep scaling [S2]. [Gaussian-Flow](8797-gaussian-flow.md)

### 4D Gaussian Representation
Uses additional properties to represent 4D rotations and spherindrical harmonics to approximate the spatial-temporal volume directly, rather than deforming 3D Gaussians [S1]. [4D Gaussian Splatting](8798-4d-gaussian-splatting.md)

## Operating characteristics
*   **Time Complexity:** Training time is independent of the number of time steps because the number of parameters is fixed [S2]. Rendering time is similar to static 3DGS per frame, but requires computing time-dependent transforms.
*   **Memory Complexity:** Memory usage is higher than static 3DGS due to the storage of Fourier and linear coefficients for each Gaussian, but significantly lower than implicit deformation methods which require large neural networks [S2].
*   **Strengths:** Fast training due to explicit parameterization; temporal continuity guaranteed by continuous functions; robust to overfitting compared to implicit methods [S2].
*   **Limitations:** Relies on the assumption that motion can be approximated by Fourier series and linear rotation; may struggle with highly complex, non-periodic, or chaotic motions [S2].
*   **When to use:** Suitable for scenes with periodic or smooth motions (e.g., human animation, articulated objects) where temporal consistency is critical [S2].

## Background
Dynamic 3D Gaussian Splatting was proposed by Katsumata et al. [S2]. It was introduced as an explicit deformation method to address the overfitting and high parameter count issues associated with implicit deformation modeling in NeRFs and early 3DGS variants [S2]. The method is inspired by the observation that human and articulated object motions are often periodic, justifying the use of Fourier series for position modeling [S2]. It builds on the foundational 3D Gaussian Splatting method [S1].
