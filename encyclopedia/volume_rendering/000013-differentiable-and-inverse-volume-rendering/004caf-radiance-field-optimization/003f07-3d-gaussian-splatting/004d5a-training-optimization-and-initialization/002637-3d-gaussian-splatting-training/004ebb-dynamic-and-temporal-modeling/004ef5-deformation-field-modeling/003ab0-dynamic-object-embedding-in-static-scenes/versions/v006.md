# Dynamic Object Embedding in Static Scenes

Also called: Lightweight Dynamic NeRF Modeling via Local Deformation Field, Local deformation field model

## Overview
This method integrates dynamic advertising objects into pre-reconstructed static Neural Radiance Field (NeRF) scenes by ensuring perspective consistency through spatial alignment and joint rendering with alpha blending [S1]. It differs from traditional dynamic NeRF approaches, such as DyNeRF, by maintaining a fixed static NeRF model for the background and employing a lightweight local deformation field only for the dynamic regions, significantly reducing parameter count and computational overhead [S1].

## How it works
The method operates in two phases: offline reconstruction/alignment and online rendering.

**Inputs and Outputs:**
*   **Inputs:** A pre-trained static NeRF model $F_{static}$ representing the background; a local deformation field model $\Delta(x, t)$ representing the motion of the dynamic object; camera parameters $(\mathbf{c}, \mathbf{d})$ for the current view; and time $t$.
*   **Outputs:** A rendered 2D image frame with the dynamic object composited into the static scene.

**Data Structures:**
1.  **Static NeRF ($F_{static}$):** A standard NeRF MLP. Parameters are fixed. It takes a 3D coordinate $\mathbf{x}$ and view direction $\mathbf{v}$ and outputs color $\mathbf{c}$ and volume density $\sigma$.
2.  **Deformation Field ($\Delta$):** A 3-layer Multi-Layer Perceptron (MLP).
    *   **Input:** Concatenation of spatial coordinate $\mathbf{x} \in \mathbb{R}^3$ and time $t \in \mathbb{R}$.
    *   **Hidden Layers:** 2 hidden layers, each with 128 units.
    *   **Output Layer:** 1 unit, outputting the displacement vector $\Delta \mathbf{x} \in \mathbb{R}^3$.
    *   **Parameters:** Approximately 5 million parameters [S1].
3.  **Alignment Data:** Four corresponding 3D marking points (e.g., exhibition stand corners) in both the static scene coordinate system and the dynamic object's local coordinate system, used to compute the transformation matrix via RANSAC [S1].

**Numbered Steps:**

1.  **Static Scene Reconstruction:** Generate a static NeRF model for the static parts of the scene (e.g., exhibition stand, background) using sparse input reconstruction. The model parameters are fixed and do not include a time dimension [S1].
2.  **Dynamic Object Modeling:** Train the local deformation field $\Delta(x, t)$ on the dynamic object (e.g., a rotating watch) using sparse video frames (25–30 frames). This field models the motion displacement of the object [S1].
3.  **Spatial Alignment:**
    *   Select four marking points in the static scene and their corresponding points on the dynamic object.
    *   Use the RANSAC algorithm to align the coordinate system of the dynamic object with the static scene.
    *   Goal: Ensure perspective consistency with an alignment error of less than 1 pixel [S1].
4.  **Joint Rendering (Per Frame):**
    *   For a given ray defined by camera origin $\mathbf{c}$ and direction $\mathbf{d}$, sample points $\mathbf{x}$ along the ray.
    *   Determine if $\mathbf{x}$ falls within the bounding volume of the dynamic object.
    *   If inside the dynamic region, calculate the deformed position: $\mathbf{x}' = \mathbf{x} + \Delta(\mathbf{x}, t)$.
    *   Query the static NeRF at the deformed position: $(\mathbf{c}', \sigma') = F_{static}(\mathbf{x}', \mathbf{v})$.
    *   If outside the dynamic region, query the static NeRF at the original position: $(\mathbf{c}', \sigma') = F_{static}(\mathbf{x}, \mathbf{v})$.
    *   Perform volume rendering to accumulate color and density along the ray.
    *   Fuse the dynamic object's contribution with the static scene using alpha blending with a blending factor of 0.95 [S1].

**Formulas:**
The dynamic radiation field is expressed as [S1]:
$$ F(\mathbf{x}, t) = F_{static}(\mathbf{x} + \Delta(\mathbf{x}, t)) $$
Where:
*   $F(\mathbf{x}, t)$ is the radiance field at position $\mathbf{x}$ and time $t$.
*   $F_{static}$ is the static NeRF function.
*   $\Delta(\mathbf{x}, t)$ is the displacement vector output by the deformation field MLP.

**Parameters:**
*   **Deformation Field Architecture:** 3-layer MLP.
*   **Hidden Layer Dimension:** 128 [S1].
*   **Total Parameters:** ~5 million (95% less than DyNeRF's 100M+) [S1].
*   **Alpha Blending Factor:** 0.95 [S1].
*   **Alignment Error Threshold:** < 1 pixel [S1].
*   **Temporal Consistency Loss:** Used to ensure smooth transitions (SSIM $\ge$ 0.92) [S1].

**Edge Cases and Pitfalls:**
*   **Alignment Error:** If the RANSAC alignment error exceeds 1 pixel, perspective consistency is lost, causing visual artifacts at the boundary of the dynamic object [S1].
*   **Sparse Input:** The method relies on sparse input reconstruction (20–30 frames). Insufficient frames may lead to poor deformation field training and temporal discontinuities [S1].
*   **Temporal Consistency:** Without temporal consistency loss, visual discontinuities (color jumps, light/shadow changes) may occur during dynamic processes [S1].

## Operating characteristics
*   **Parameter Efficiency:** The deformation field uses only 5 million parameters, which is 95% less than traditional dynamic NeRF methods like DyNeRF (100M+ parameters) [S1].
*   **Performance:** Suitable for VR devices due to reduced computational load compared to independent models per time step [S1].
*   **Quality:** PSNR increased by $2.3 \pm 0.2$ dB under sparse input conditions (mean $\pm$ std over 10 trials) [S1]. Temporal consistency achieves SSIM $\ge$ 0.92 [S1].
*   **Limitations:** Only models dynamic regions (typically $\le$ 20% of the scene). Static areas are handled by the fixed NeRF, so this method is not suitable for fully dynamic scenes [S1].

## Background
This method was proposed in the context of VR advertising, specifically for integrating dynamic advertising elements (e.g., rotating watches) into static exhibition stand scenes. It addresses the limitations of traditional dynamic NeRF, which requires over 100M parameters and independent models per time step, making it unsuitable for VR devices [S1]. The approach was developed by Y. Tao et al. and published in *Informatica* (2026) [S1].
