# DaReNeRF

Also called: Direction-aware Representation for Dynamic Scenes

## Overview
DaReNeRF is a method for novel view synthesis of dynamic scenes that addresses the shift variance and direction ambiguity inherent in traditional Discrete Wavelet Transforms (DWT) by employing a direction-aware representation [S1]. It decomposes the 4D spatiotemporal volume into a sum of Hadamard products of 2D plane-based representations and learned vectors, utilizing an inverse dual-tree complex wavelet transformation (DTCWT) to recover plane information from six distinct orientations [S1]. Unlike baseline plane-based decompositions that suffer from checkerboard artifacts and poor motion handling, DaReNeRF ensures shift invariance and directional selectivity, reducing memory complexity from $O(N^3 T F)$ to $O(R N^2 T F)$ while maintaining high-fidelity rendering of complex motions [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** A set of posed 2D images with timestamps $t$, representing a dynamic scene.
*   **Outputs:** Rendered images at arbitrary camera poses and time steps.

**Data Structures**
The core data structure is the direction-aware representation of the 4D volume $D$. The volume is decomposed into three terms, each consisting of the Hadamard product of two 2D plane-based representations and a learned vector [S1].

The layout of the parameters is:
*   $M_{rAB} \in \mathbb{R}^{A \times B}$: Learned 2D plane-based representations, where $(A, B) \in \{X, Y, Z, T\}^2$ and $A \neq B$. These are recovered via inverse DTCWT from direction-aware coefficients.
*   $v_{ri} \in \mathbb{R}^F$: Learned vectors along the feature axes.
*   $R_1, R_2, R_3$: The number of low-rank components for each of the three decomposition terms.
*   $R = R_1 + R_2 + R_3$: Total number of low-rank components, where $R \ll N$ ($N$ is spatial resolution).
*   $F$: Feature size, typically 3 for RGB colors.
*   $V \in \mathbb{R}^{R \times F}$: A 2D tensor stacking all $v_{ri}$ vectors.

**Numbered Steps**
1.  **Volume Decomposition:** Represent the 4D spatiotemporal volume $D$ as the sum of three components defined by Equation 1 [S1]:
    $$ D = \sum_{r=1}^{R_1} M_{rXY} \circ M_{rZT} \circ v_{r1} + \sum_{r=1}^{R_2} M_{rXZ} \circ M_{rYT} \circ v_{r2} + \sum_{r=1}^{R_3} M_{rYZ} \circ M_{rXT} \circ v_{r3} $$
    where $\circ$ denotes the Hadamard product (element-wise multiplication) [S1].

2.  **Feature Computation:** For a given space-time point, compute density and appearance features by:
    *   Extracting feature vectors from paired planes (e.g., $M_{XY}$ and $M_{ZT}$).
    *   Multiplying these vectors element-wise.
    *   Concatenating the multiplied results from all three terms into a single vector.
    *   Multiplying the concatenated vector by $V$ [S1].

3.  **Opacity Query:** Query point opacities directly from the computed density features [S1].

4.  **Color Regression:** Regress RGB color values using a compact Multi-Layer Perceptron (MLP). The inputs to the MLP are the appearance features and the view directions [S1].

5.  **Rendering:** Synthesize final images via differentiable volumetric rendering along camera rays [S1].

**Pseudocode**
```python
def darenerf_render(ray_origin, ray_direction, time_t, params):
    """
    Renders a single ray for DaReNeRF.
    
    Args:
        ray_origin: 3D vector, origin of the ray.
        ray_direction: 3D vector, direction of the ray.
        time_t: float, timestamp of the frame.
        params: Dictionary containing learned parameters.
            - M_XY, M_ZT, etc.: 2D plane tensors.
            - V: 2D tensor of shape (R, F).
            - r1, r2, r3: Number of components.
            - color_mlp: Compact MLP for color regression.
            - density_to_opacity: Function mapping density to opacity.
            
    Returns:
        color: 3D vector, RGB color.
        depth: float, accumulated depth.
        alpha: float, accumulated alpha.
    """
    # Sample points along the ray
    # Note: Standard volumetric rendering loop is assumed from parent context
    # This function computes features for a single point (x, y, z, t)
    
    x, y, z = ray_origin + t * ray_direction # t is sample distance
    # Normalize or map coordinates to plane indices if necessary
    # Assuming M planes are indexed by continuous coordinates via interpolation
    
    # 1. Compute density and appearance features
    # Term 1: XY and ZT planes
    # Interpolate M_XY at (x, y) and M_ZT at (z, t)
    feat_xy = interpolate(params.M_XY, x, y)
    feat_zt = interpolate(params.M_ZT, z, time_t)
    term1 = feat_xy * feat_zt # Element-wise product
    
    # Term 2: XZ and YT planes
    feat_xz = interpolate(params.M_XZ, x, z)
    feat_yt = interpolate(params.M_YT, y, time_t)
    term2 = feat_xz * feat_yt
    
    # Term 3: YZ and XT planes
    feat_yz = interpolate(params.M_YZ, y, z)
    feat_xt = interpolate(params.M_XT, x, time_t)
    term3 = feat_yz * feat_xt
    
    # Concatenate terms
    combined_features = concatenate([term1, term2, term3])
    
    # Multiply by V tensor
    # V is shape (R, F). combined_features is shape (R, F) if R is the rank
    # The source says "concatenates the multiplied results... and multiplies by V"
    # Assuming combined_features is already structured to match V's dimensions
    density_appearance_features = matmul(combined_features, params.V)
    
    # Split into density and appearance if necessary, or use directly
    density = density_appearance_features[..., 0] # Example indexing
    appearance = density_appearance_features[..., 1:]
    
    # 2. Query opacity
    opacity = density_to_opacity(density)
    
    # 3. Regress color
    view_dir = ray_direction
    color = params.color_mlp(concatenate([appearance, view_dir]))
    
    return color, opacity
```

**Parameters**
*   $F$: Feature size, typically 3 (RGB) [S1].
*   $R$: Total number of low-rank components ($R = R_1 + R_2 + R_3$), where $R \ll N$ [S1].
*   $N$: Spatial resolution [S1].
*   $T$: Temporal resolution [S1].

**Edge Cases and Pitfalls**
*   **Shift Variance:** Traditional 2D DWT suffers from shift variance, where small shifts in the input signal disrupt wavelet oscillation patterns, causing poor results in dynamic regions with motion or camera movement [S1]. DaReNeRF mitigates this using DTCWT [S1].
*   **Direction Ambiguity:** Traditional 2D DWT has poor direction selectivity, producing a checkered pattern that blends representations from $\pm 45^\circ$, leading to ghosting artifacts around moving objects [S1]. DaReNeRF captures features from six distinct orientations to avoid this [S1].
*   **Storage Redundancy:** The direction-aware representation introduces a 2D redundancy ($d=2$ for plane-based decomposition) compared to DWT, resulting in lower storage efficiency than pure DWT, though still better than direct 4D modeling [S1].

## Operating characteristics
*   **Memory Complexity:** Reduced from $O(N^3 T F)$ for direct 4D volume modeling to $O(R N^2 T F)$ using the plane-based decomposition [S1].
*   **Performance:** Achieves state-of-the-art performance in novel view synthesis for dynamic scenes [S1].
*   **Strengths:** Robust to motion and camera movement due to shift invariance; avoids ghosting artifacts through directional selectivity [S1].
*   **Limitations:** Lower storage efficiency compared to DWT due to 2D redundancy [S1].
*   **When to Use:** Suitable for dynamic scenes with complex motions where traditional DWT-based methods fail due to shift variance and direction ambiguity [S1].

## Background
DaReNeRF was introduced to address the limitations of Discrete Wavelet Transforms (DWT) in modeling dynamic scenes. Traditional 2D DWT-based representations suffer from shift variance and poor direction selectivity, leading to artifacts in dynamic regions [S1]. Inspired by the Dual-Tree Complex Wavelet Transform (DTCWT), DaReNeRF proposes a direction-aware representation that learns features from six distinct orientations, ensuring shift invariance and better directional selectivity [S1]. The method builds on baseline plane-based 4D volume decomposition [S1].
