# DARBF-Splatting

Also called: DARB-Splatting, Decaying Anisotropic Radial Basis Functions Splatting

## Overview
DARBF-Splatting is a method that generalizes 3D Gaussian Splatting by replacing the standard Gaussian kernel with Decaying Anisotropic Radial Basis Functions (DARBFs) [S1]. It solves the limitation of existing splatting methods being restricted to the exponential family, offering improved training convergence and memory efficiency while maintaining comparable visual quality [S1]. Unlike standard 3DGS, which relies on the closed-form integration properties of Gaussians, DARBF-Splatting introduces a correction factor to approximate this efficiency for non-exponential kernels [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D points (means $\boldsymbol{\mu}$) and their associated 3x3 covariance matrices ($\boldsymbol{\Sigma}$), opacity ($\alpha$), and color ($\mathbf{c}$) attributes, typically initialized from Structure-from-Motion (SfM) data [S1].
*   **Output:** A rendered 2D image and optimized 3D primitives [S1].

**Data Structures:**
The primitive representation remains identical to standard 3DGS to ensure compatibility with the differentiable rasterization pipeline:
*   **Mean:** $\boldsymbol{\mu} \in \mathbb{R}^3$
*   **Covariance:** $\boldsymbol{\Sigma} \in \mathbb{R}^{3 \times 3}$ (symmetric positive definite). In implementation, this is often stored as a 6-vector (eigenvalues and rotation) or a 9-vector, but the mathematical definition is a 3x3 matrix [S1].
*   **Opacity:** $\alpha \in [0, 1]$
*   **Color:** $\mathbf{c}$ (e.g., spherical harmonics coefficients or RGB) [S1].

**The DARBF Kernel:**
DARBFs are non-negative, decaying functions of the Mahalanobis distance [S1]. The Mahalanobis distance $d_M$ from a point $\mathbf{x}$ to the center $\boldsymbol{\mu}$ with covariance $\boldsymbol{\Sigma}$ is defined as [S1]:

$$
d_M(\mathbf{x}; \boldsymbol{\mu}, \boldsymbol{\Sigma}) = \sqrt{(\mathbf{x} - \boldsymbol{\mu})^T \boldsymbol{\Sigma}^{-1} (\mathbf{x} - \boldsymbol{\mu})}
$$

The kernel value $K$ is a function $f(d_M^2)$ where $f$ is a decaying function. Examples provided in the source include:
1.  **Half-Cosine:** $K(d_M) = \cos\left(\frac{d_M^2}{\xi}\right)$ for $d_M^2 < \frac{\xi \pi}{2}$, and 0 otherwise, where $\xi > 0$ is a scale parameter [S1].
2.  **Inverse Multiquadric (Inverse MQ):** Mentioned as having a wide-spread area and sharp peak, though the exact formula is not explicitly written in the provided text, it is cited as a valid DARBF [S1].
3.  **Modified Raised Cosine / Modular Sinc:** Mentioned as part of the DARBF class [S1].

**Projection and Correction Factor:**
Standard 3DGS exploits the property that the 2D covariance matrix $\boldsymbol{\Sigma}_{2D}$ can be obtained by simply skipping the third row and column of the 3D covariance matrix $\boldsymbol{\Sigma}_{3D}$ after projection [S1]. This allows for a closed-form integration shortcut during rasterization [S1].

For DARBFs, which do not possess this closure property, the method introduces a correction factor $\psi$ to approximate the Gaussian's integration behavior [S1]. The source evaluates three cases for $\psi$:
1.  No correction factor.
2.  Matrix $\psi$ predicted by an MLP.
3.  Scalar $\psi$ precomputed via closed-form regression [S1].

The source selects the **scalar $\psi$** as it is computationally efficient and produces comparable results to 3DGS (Table 6 in [S1]) [S1]. The rendered opacity contribution of a splat is thus scaled by this factor.

**Algorithm Steps:**
1.  **Initialization:** Initialize 3D primitives with mean $\boldsymbol{\mu}$, covariance $\boldsymbol{\Sigma}$, opacity $\alpha$, and color $\mathbf{c}$ from SfM points [S1].
2.  **Transformation:** Transform 3D primitives to the camera coordinate system [S1].
3.  **Projection:** Project the 3D covariance $\boldsymbol{\Sigma}_{3D}$ to 2D. As per the source, the 2D covariance $\boldsymbol{\Sigma}_{2D}$ is obtained by taking the top-left 2x2 submatrix of the projected 3x3 covariance matrix [S1].
4.  **Splatting:** For each pixel, compute the Mahalanobis distance $d_M$ from the pixel center to the splat center [S1].
5.  **Kernel Evaluation:** Evaluate the DARBF kernel function $K(d_M)$ (e.g., Half-Cosine) [S1].
6.  **Correction:** Apply the scalar correction factor $\psi$ to the kernel value or opacity to approximate closed-form integration [S1].
7.  **Rasterization:** Alpha-blend the corrected splats to produce the final pixel color [S1].
8.  **Optimization:** Backpropagate the pixel error to update $\boldsymbol{\mu}$, $\boldsymbol{\Sigma}$, $\alpha$, and $\mathbf{c}$ [S1].

**Pseudocode:**
```python
import numpy as np

def mahalanobis_distance(x, mu, sigma_inv):
    """
    Calculate Mahalanobis distance squared.
    x: (3,) point in 3D space
    mu: (3,) mean of the primitive
    sigma_inv: (3,3) inverse covariance matrix
    """
    diff = x - mu
    return np.dot(diff, np.dot(sigma_inv, diff))

def half_cosine_kernel(d_m_sq, xi):
    """
    Half-cosine DARBF kernel.
    d_m_sq: Mahalanobis distance squared
    xi: scale parameter
    """
    threshold = (xi * np.pi) / 2
    if d_m_sq < threshold:
        return np.cos(d_m_sq / xi)
    else:
        return 0.0

def render_darbf_splatting(primitives, camera_matrix, image_width, image_height, xi, psi):
    """
    Render a scene using DARBF-Splatting.
    primitives: List of dicts with keys 'mu' (3,), 'sigma' (3,3), 'alpha', 'color'
    camera_matrix: (3,3) projection matrix
    image_width, image_height: int
    xi: float, scale parameter for kernel
    psi: float, scalar correction factor
    """
    image = np.zeros((image_height, image_width, 3))
    
    # Sort primitives by depth for correct alpha blending
    # Note: In practice, this is done via a tile-based rasterizer
    primitives_sorted = sorted(primitives, key=lambda p: np.dot(camera_matrix[2, :], p['mu']))
    
    for prim in primitives_sorted:
        mu_3d = prim['mu']
        sigma_3d = prim['sigma']
        alpha = prim['alpha']
        color = prim['color']
        
        # Project mean to 2D
        mu_3d_hom = np.append(mu_3d, 1.0)
        mu_2d_hom = np.dot(camera_matrix, mu_3d_hom)
        mu_2d = mu_2d_hom[:2] / mu_2d_hom[2]
        
        # Project covariance
        # J is the Jacobian of the projection
        # For simplicity, assuming standard perspective projection logic
        # The source states: 2D covariance is obtained by skipping the third row/col
        # of the 3D covariance matrix AFTER projection transformation.
        # Let W be the view-projection matrix.
        # Sigma_2d = J * Sigma_3d * J^T
        # Then take top-left 2x2.
        
        # Approximate projection of covariance for pseudocode clarity
        # In real implementation, use the full Jacobian J
        J = ... # Jacobian of projection at mu_3d
        sigma_2d_full = np.dot(J, np.dot(sigma_3d, J.T))
        sigma_2d = sigma_2d_full[:2, :2]
        
        # Invert 2D covariance for distance calculation
        try:
            sigma_2d_inv = np.linalg.inv(sigma_2d)
        except np.linalg.LinAlgError:
            continue
            
        # Determine bounding box for splat
        # Use a threshold for d_m_sq, e.g., 4 or 9 depending on kernel support
        # Half-cosine has finite support: d_m^2 < xi*pi/2
        max_d_m_sq = (xi * np.pi) / 2
        # Approximate radius in pixels
        # This is a simplification; real rasterizers use tile-based culling
        radius = np.sqrt(max_d_m_sq) * 2.0 
        
        x_min = max(0, int(mu_2d[0] - radius))
        x_max = min(image_width, int(mu_2d[0] + radius))
        y_min = max(0, int(mu_2d[1] - radius))
        y_max = min(image_height, int(mu_2d[1] + radius))
        
        for y in range(y_min, y_max):
            for x in range(x_min, x_max):
                pixel_center = np.array([x + 0.5, y + 0.5])
                d_m_sq = mahalanobis_distance(pixel_center, mu_2d, sigma_2d_inv)
                
                # Evaluate Kernel
                k_val = half_cosine_kernel(d_m_sq, xi)
                
                # Apply Correction Factor
                # The source implies psi scales the contribution to approximate Gaussian integration
                effective_alpha = alpha * k_val * psi
                
                if effective_alpha > 0:
                    # Alpha blending
                    # Note: Standard 3DGS uses pre-multiplied alpha
                    # This is a simplified blending step
                    image[y, x] += color * effective_alpha * (1 - image[y, x].sum()) # Simplified
                    
    return image
```

**Parameters:**
*   **$\xi$ (xi):** Scale parameter for the Half-Cosine kernel. Typical value: $\beta=2$ for modified half-cosine in simulations [S1].
*   **$\psi$ (psi):** Scalar correction factor. Precomputed via closed-form regression [S1].
*   **Covariance $\boldsymbol{\Sigma}$:** Defines the anisotropic shape and orientation [S1].

**Edge Cases and Pitfalls:**
*   **Unbounded Functions:** Growing functions are omitted due to instability; only decaying functions are used [S1].
*   **Integration Cost:** Using non-Gaussian functions typically incurs costly integration. The correction factor $\psi$ is critical to maintain computational efficiency [S1].
*   **Projection:** The shortcut of skipping the third row/column of the 3D covariance matrix is specific to the Gaussian closure property. For DARBFs, this shortcut is used for the *geometry* (position/scale) but the *kernel value* requires the correction factor $\psi$ [S1].

## Operating characteristics
*   **Training Speed:** Half-cosine kernels achieve 34% faster training convergence compared to standard Gaussian kernels [S1].
*   **Memory Usage:** Half-cosine kernels reduce memory usage by 15% compared to standard Gaussian kernels [S1].
*   **Visual Quality:** Comparable PSNR, SSIM, and LPIPS results to standard 3DGS [S1].
*   **Kernel Spread:** Half-cosines and Inverse MQ functions span a larger region with higher opacity for the same variance, reducing the need for multiple splats to achieve the same accumulated value [S1].
*   **Strengths:** Improved training efficiency and lower memory footprint without sacrificing visual fidelity.
*   **Limitations:** Requires a correction factor $\psi$ to approximate Gaussian integration, which adds a layer of complexity not present in standard 3DGS. The exact optimal value of $\psi$ depends on the kernel choice and scene [S1].

## Background
DARBF-Splatting was introduced by Hashiru Pramuditha, Vinasirajan Viruthshaan, Vishagar Arunan, Saeedha Nazar, Sameera Ramasinghe, Simon Lucey, and Ranga Rodrigo from the University of Moratuwa and University of Adelaide [S1]. The paper was published in 2026 (WACV 2026) [S1]. It addresses the limitation of 3D Gaussian Splatting being restricted to the exponential family of functions, a restriction caused by the computational inefficiency of integrating non-Gaussian functions during the 3D-to-2D projection [S1].
