# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization strategies, and variant configurations required to train and render 3D Gaussian Splatting (3DGS) efficiently. It addresses the gap between the theoretical differentiable rasterization pipeline and practical execution, focusing on memory management, precision handling, and specific algorithmic modifications for stability and performance. It sets itself apart from general training pipelines by providing concrete hyperparameters, data structure layouts, and CUDA-level optimizations [S1, S2].

## How it works

### Inputs and Outputs
*   **Inputs:** Sparse Structure-from-Motion (SfM) point cloud, camera poses, and input images.
*   **Outputs:** Optimized set of 3D Gaussians (position $\mu$, covariance $\Sigma$, opacity $\alpha$, spherical harmonic coefficients $\mathbf{c}$, rotation $q$) and rendered images.

### Data Structures
The core data structure is a list of Gaussian primitives. Each Gaussian $i$ is parameterized by:
*   **Position:** $\mu_i \in \mathbb{R}^3$
*   **Rotation:** $q_i \in \mathbb{R}^4$ (unit quaternion)
*   **Scale:** $s_i \in \mathbb{R}^3$
*   **Opacity:** $\alpha_i \in [0, 1]$
*   **Color:** Spherical Harmonic (SH) coefficients. For degree $L$, this requires $4(L+1)^2$ coefficients per RGB channel. Default 3DGS uses $L=3$, resulting in 48 coefficients per channel [S8].

### Training Configuration and Optimization
The training process minimizes a composite loss $\mathcal{L}$ between rendered images $I^r$ and ground truth $I^{gt}$:
$$ \mathcal{L} = \sum_{k=1}^K (1 - \lambda_1) \| I_k^{gt} - I_k^r(\Theta) \|_{\ell_1} + \lambda_1 L_{D-SSIM}(I_k^{gt}, I_k^r(\Theta)) $$
where $K$ is the number of images and $\lambda_1 \in [0,1]$ [S11].

1.  **Optimizer:** Adam optimizer with learning rate $1 \times 10^{-3}$ [S2].
2.  **Supervision:** Randomly select a single image from a random scene for supervision per iteration [S2].
3.  **Library:** Use `gsplat` for rasterization [S2].

### CUDA Kernel Optimizations
To achieve real-time performance and stability:
1.  **Half-Precision Fetches:** Use half-precision (FP16) memory fetches on feature vectors during rasterization for both forward and backward kernels to reduce register pressure [S1].
2.  **Neural Network Precision:** Use tiny-cuda-nn's JIT-compiled cooperative vector MLPs, trained and evaluated in FP16 [S1].
3.  **Loss Scaling:** Apply an automatic scaling factor to loss values to improve half-precision training stability [S1].

### Scene Extent Calculation
The default 3DGS scene extent $e_{\text{scene}}$ is proportional to the distance of the furthest camera from the average camera position:
$$ e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2 $$
$$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
This can bias optimization if cameras are clustered (e.g., orbiting a small object) [S3].

**Corrected Scene Extent:**
Calculate extent based on the SfM point cloud to avoid camera distribution bias:
$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
where $N_{\text{SfM}}$ is the number of SfM points and $p_i$ is the $i$-th SfM point [S3].

### Pitfalls and Edge Cases
*   **Camera Bias:** If cameras are clustered, default extent calculation leads to incorrect splitting/pruning. Use corrected extent [S3].
*   **SH Degree:** In standard 3DGS, SH coefficients with degree $>0$ often remain unchanged during training, making them superfluous. Setting max SH degree to 0 improves training speed by ~16.25-16.57% without explicit quality loss [S4, unofficial].
*   **Linear Response:** Camera sensors must have a linear response to light. In-camera processed JPEGs or gamma-corrected images cannot be used unless non-linearities are reversed [S11].

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S3]. It sets itself apart from standard 3DGS by decoupling scene volume estimation from camera placement, ensuring appropriate Gaussian sizing for large outdoor scenes captured with clustered cameras [S3].

### SH Degree Zero Optimization
Setting the maximum degree of Spherical Harmonics (SH) coefficients to 0 to remove superfluous operations and improve training speed, as higher-degree SH coefficients for color remain unchanged during training [S4, unofficial]. It distinguishes itself by directly modifying model code to delete operations relative to max degree, yielding a 16.57% improvement in speed with specific code changes, though it increases CPU-GPU process time [S4, unofficial].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It sets itself apart from naive Gaussian blur (which blurs the whole image) or learnable single-kernel approaches by allowing spatially varying blur shapes and magnitudes via a compact MLP predicting $\delta s_j$ for each Gaussian [S5].

### Triangle Soup (Mesh-based Gaussian Splatting)
A representation that connects Gaussian splats to a mesh structure, enabling real-time editing and animation by directly manipulating mesh vertices [S6]. It differs from vanilla GS by automatically recalculating Gaussian parameters (covariance, rotation) when vertices are moved, avoiding holes and blurriness. It is used in the GaMeS model for 3D face reconstruction, using 100 Gaussians per face [S6].

### SuGaR Mesh Extraction
A method to extract a surface mesh from Gaussian Splatting by regularizing Gaussians to align with the true scene surface. It uses Poisson reconstruction on points sampled from the visible level set of the Gaussian splatting density function [S7]. It distinguishes itself by using the discrepancy between regularized Gaussians and the extracted mesh as a cue for "Frosting" layer thickness, handling fuzzy materials better than vanilla 3DGS [S7].

### Compact View-dependent Color
A method to represent view-dependent color using a grid-based neural field instead of storing Spherical Harmonics (SH) coefficients per Gaussian, reducing parameters from 48 to a shared grid [S8]. It sets itself apart by contracting unbounded positions to a bounded range and using a tiny MLP to compute color $c_n(d) = f(\text{contract}(p_n), d; \theta)$, replacing the per-Gaussian SH storage [S8].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising with explicitly differentiable 3DGS [S9]. It sets itself apart from supervised methods by using Noise2Void (N2V), which requires no paired clean data, making it robust to uncertain noise patterns in sparse viewpoint scenarios where only one image per viewpoint exists [S9].

### View-Dependent Opacity Kernel
A transparent Gaussian kernel where opacity is view-dependent, modeled by a half-period cosine function to approximate specular reflectance lobes [S10, unofficial]. It adds 5 learnable parameters ($\alpha, \theta, T, \beta$) to the standard 3DGS configuration. It distinguishes itself by allowing opacity to diminish to zero as angular deviation increases, preventing artifacts outside the lobe's influence [S10, unofficial].

### Backscatter Estimation and Optimization
Adapts 3DGS to underwater environments by learning direct attenuation, infinite backscatter, and backscatter coefficient alongside scene geometry [S11]. It solves color distortion by using an alternating optimization strategy that re-estimates backscatter parameters $B_\infty$ and $B_b$ every 500 steps, ensuring convergence toward medium coefficients [S11].

### Model-based depth estimation for volume parameter update
Uses depth values extracted from the current scene estimate to update medium-parameter estimates ($B_\infty, B_b$) during optimization [S11]. It computes depth $z = \frac{\sum_{i=1}^M d_i \alpha_i T_i}{\sum_{i=1}^M \alpha_i T_i}$ at each pixel during rendering, linking the 3DGS geometry directly to the volumetric underwater model [S11].

## Operating characteristics

*   **Memory:** Standard 3DGS with degree 3 SH requires 48 parameters per channel per Gaussian. Compact methods reduce this significantly [S8].
*   **Speed:** SH Degree Zero Optimization yields ~16.57% training speed improvement [S4, unofficial]. Half-precision rasterization reduces register pressure [S1].
*   **Hardware:** Experiments reported on Tesla V100-SXM2-32GB and NVIDIA A6000/A100 GPUs [S6, S8].
*   **Scalability:** Corrected scene extent improves scalability for large outdoor scenes with clustered cameras [S3].
*   **Limitations:** Triangle Soup artifacts appear with significant changes on meshes with large faces [S6]. Vanilla 3DGS lacks surface alignment regularization [S7].

## Background

3D Gaussian Splatting was introduced by Kerbl et al. (2023) as a real-time radiance field representation [S11]. The implementation details described here stem from subsequent optimizations and adaptations for specific domains (underwater, sparse views, mesh editing) and efficiency improvements (half-precision, SH reduction) [S1-S11].
