# SWAG (Splatting in the Wild images with Appearance-conditioned Gaussians)


## Overview
SWAG is an extension of 3D Gaussian Splatting (3DGS) designed to reconstruct 3D scenes from unstructured, in-the-wild image collections [S1]. It addresses two primary limitations of standard 3DGS in unconstrained scenarios: photometric variations (changes in lighting and appearance across different captures) and the presence of transient occluders (e.g., tourists, clouds) [S1]. Unlike standard 3DGS, which averages appearance and creates floaters or blurry Gaussians to compensate for view-dependent effects, SWAG disentangles static scene geometry from dynamic appearance and transient objects using per-image conditioning [S1]. It sets itself apart from siblings like [3iGS](13977-3igs-factorised-tensorial-illumination-for-3d-gaussian-splat.md) by using a latent image embedding and an MLP to modulate color and opacity, rather than explicit illumination grids [S1].

## How it works
SWAG modifies the standard 3DGS parameter set by introducing appearance-dependent color modulation and adaptive opacity modulation. The method optimizes a Hash Grid encoding, per-image embeddings, and an MLP alongside the standard Gaussian attributes [S1].

### Inputs and Outputs
**Inputs:**
*   A set of unstructured images $I$ with known camera poses.
*   Initial 3D Gaussian parameters derived from Structure-from-Motion (SfM) sparse points: centroid $\mathbf{x}$, scale $\mathbf{S}$, rotation $\mathbf{R}$, base opacity $\alpha$, and base color $\mathbf{c}$ (encoded in spherical harmonic coefficients) [S1].

**Outputs:**
*   Rendered images for novel views.
*   A disentangled scene representation separating static geometry from transient objects [S1].

### Data Structures and Layout
For each Gaussian $i$, the optimized parameters include:
1.  **Standard 3DGS Attributes:** Centroid $\mathbf{x}_i$, scale $\mathbf{S}_i$, rotation $\mathbf{R}_i$, base opacity $\alpha_i$, and base color $\mathbf{c}_i$ [S1].
2.  **Spatial Encoding:** A Hash Grid encoding for the Gaussian center, denoted as $\text{emb}(\mathbf{x}_i)$ [S1].
3.  **Image Embedding:** A per-image latent vector $\mathbf{l}_I$ associated with the training image $I$ [S1].
4.  **MLP:** A multi-layer perceptron $F_\theta$ that maps inputs to appearance and opacity variations [S1].

**Hash Grid Configuration:**
*   Hash table size $T$: $2^{19}$ [S1].
*   Finest resolution $N_{max}$: 2048 [S1].
*   Coarsest resolution $N_{min}$: 16 [S1].
*   Number of levels $L$: 12 [S1].

**MLP Configuration ($F_\theta$):**
*   Number of layers: 8 [S1].
*   Input dimension: 3 (concatenated base color, image embedding, and position encoding) [S1].
*   Hidden layer size: 51 [S1].
*   Output dimension: 64 (outputs image-dependent color $\mathbf{c}_I$ and opacity variation $\Delta \alpha_I$) [S1].

**Image Embedding:**
*   Latent vector dimension: 24 [S1].

### Numbered Steps

1.  **Initialization:** Initialize 3D Gaussians using SfM sparse points. Initialize the Hash Grid, per-image embeddings $\mathbf{l}_I$ for each training image, and the MLP weights $\theta$ [S1].
2.  **Feature Extraction:** For a Gaussian $i$ and a training image $I$:
    *   Compute the position encoding $\text{emb}(\mathbf{x}_i)$ using the Hash Grid [S1].
    *   Retrieve the image embedding $\mathbf{l}_I$ [S1].
3.  **Appearance and Opacity Modulation:**
    *   Concatenate the base color $\mathbf{c}_i$, the image embedding $\mathbf{l}_I$, and the position encoding $\text{emb}(\mathbf{x}_i)$ [S1].
    *   Pass the concatenated vector through the MLP $F_\theta$ to obtain the image-dependent color variation $\mathbf{c}_I$ and the image-dependent opacity variation parameter $\Delta \alpha_I$ [S1].
    *   The final color contribution is derived from $\mathbf{c}_i$ and $\mathbf{c}_I$ [S1].
    *   The final opacity $\alpha_{final}$ is modulated using $\Delta \alpha_I$. Specifically, $\Delta \alpha_I$ serves as the location variable of a concrete distribution (Gumbel-Softmax or similar reparameterization trick) to sample the opacity variation $\widetilde{\Delta \alpha}_I$ [S1].
4.  **Rendering:** Render the scene using standard 3D Gaussian Splatting rasterization, using the modulated color and opacity [S1].
5.  **Loss Computation:** Compute the loss using L1 loss and D-SSIM between the rendered image and the ground truth image [S1].
6.  **Optimization:** Update all parameters ($\mathbf{x}, \mathbf{S}, \mathbf{R}, \alpha, \mathbf{c}$, Hash Grid, $\mathbf{l}_I$, $\theta$) using gradient descent [S1].
7.  **Transient Detection (Post-Training/Inference):**
    *   Identify transient Gaussians by analyzing the variance of the sampled opacity variation $\widetilde{\Delta \alpha}_I$ across different training images [S1].
    *   Gaussians with high variance are classified as transient [S1].
    *   Static Gaussians are those with low variance ($\text{Var}(\widetilde{\Delta \alpha}_I) < \lambda$) [S1].

### Edge Cases and Pitfalls
*   **Transient Detection Holes:** In areas with frequent transient objects (e.g., clouds, tourists), strict transient detection (removing all Gaussians with non-zero variance) can leave holes (black spots) in the static reconstruction [S1].
*   **Adaptive Threshold:** To mitigate holes, an adaptive threshold $\lambda$ can be used ($\text{Var}(\widetilde{\Delta \alpha}_I) < \lambda$) instead of requiring zero variance, but this requires manual tuning of $\lambda$ [S1].
*   **Performance:** Training time almost doubles compared to standard 3DGS, and inference time per frame is 10 times longer [S1].

## Operating characteristics
*   **Time Complexity:** Training time is approximately 2x that of standard 3DGS [S1]. Inference time is 10x slower than 3DGS [S1].
*   **Memory Complexity:** Increased memory usage due to the Hash Grid, per-image embeddings, and MLP parameters [S1].
*   **Strengths:**
    *   Handles unstructured, in-the-wild image collections with photometric variations [S1].
    *   Disentangles static and transient objects, allowing for occluder removal [S1].
    *   Enables controllable appearance via interpolation of image embeddings [S1].
    *   Faster training than previous implicit in-the-wild baselines [S1].
*   **Limitations:**
    *   Slower inference than standard 3DGS [S1].
    *   Requires manual tuning of the transient detection threshold $\lambda$ to avoid holes [S1].
    *   Less than 20% of Gaussians typically capture transient objects, meaning the majority of the scene is static [S1].
*   **When to Use:** Use SWAG when reconstructing scenes from unstructured, internet-sourced photo collections (e.g., Phototourism, NeRF-OSR) where lighting varies and transient objects are present [S1].
*   **When Not to Use:** Avoid if real-time inference speed is critical and the scene is static and well-lit, as standard 3DGS is faster and simpler [S1].

## Background
SWAG was introduced by H. Dahmani et al. in 2024 [S1]. It builds upon 3D Gaussian Splatting to address its poor performance on unstructured in-the-wild data [S1]. The method was evaluated on the Phototourism Dataset (Brandenburg Gate, Sacré Cœur, Trevi Fountain) and the NeRF-OSR Dataset [S1]. It represents a step towards conditioning 3DGS for in-the-wild scene representations, suggesting future research directions such as extension to dynamic scenes [S1].
