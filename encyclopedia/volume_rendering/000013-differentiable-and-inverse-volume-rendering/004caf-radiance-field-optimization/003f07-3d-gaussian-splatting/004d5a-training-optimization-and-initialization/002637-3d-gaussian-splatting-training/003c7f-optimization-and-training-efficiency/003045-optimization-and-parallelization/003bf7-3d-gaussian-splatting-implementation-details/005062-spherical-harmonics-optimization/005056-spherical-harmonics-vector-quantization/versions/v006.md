# Spherical Harmonics Vector Quantization

Also called: SH clustering, SH palette

## Overview
Spherical Harmonics Vector Quantization (SH VQ) is a compression technique for 3D Gaussian Splatting that replaces per-splat SH coefficient vectors with indices pointing to a shared, learned palette of distinct SH vectors [S1, unofficial]. It solves the problem of excessive memory footprint caused by storing high-dimensional SH data for millions of splats, reducing storage from gigabytes to tens of megabytes at the cost of minor lighting artifacts [S1, unofficial]. It differs from degree truncation by retaining full angular resolution per splat (via palette lookup) rather than reducing the SH degree $L$, and from distillation by operating on the coefficient space directly rather than the rendered image space [S1, unofficial].

## How it works
**Inputs:**
- A set of $N$ 3D Gaussians (splats).
- For each splat $i$, the SH coefficients $\mathbf{c}_i \in \mathbb{R}^{3(L+1)^2}$. The first coefficient (degree 0) is treated separately as the base color and is not included in the clustering [S1, unofficial].
- The maximum SH degree $L$ used in the scene.

**Outputs:**
- A palette $\mathcal{P}$ of $K$ distinct SH vectors, where $K$ is the palette size.
- An index map $\mathcal{I}$ of size $N$, where $\mathcal{I}[i]$ is the index into $\mathcal{P}$ for splat $i$.

**Data Structures:**
1.  **Palette ($\mathcal{P}$):** A list of $K$ vectors. Each vector has dimension $D = 3(L+1)^2 - 3$ (excluding the DC term). Stored as FP16 floats.
    -   Size: $K \times D \times 2$ bytes.
2.  **Indices ($\mathcal{I}$):** A list of $N$ integers. Stored as 16-bit unsigned integers (`uint16`), even if $K < 65536$ [S1, unofficial].
    -   Size: $N \times 2$ bytes.

**Parameters:**
-   **Palette Size ($K$):** Typically 4,000 to 16,000 items [S1, unofficial].
-   **SH Degree ($L$):** Commonly $L=3$ (degree 3), resulting in $D = 3(4^2) - 3 = 45$ dimensions per splat for clustering [S1, unofficial].
-   **Precision:** FP16 for palette storage [S1, unofficial].

**Algorithm Steps:**
1.  **Extract Coefficients:** For each splat $i$, extract the SH coefficients for degrees $l=1$ to $L$. Flatten these into a vector $\mathbf{v}_i \in \mathbb{R}^D$.
2.  **Cluster:** Perform vector quantization (clustering) on the set of vectors $\{\mathbf{v}_1, \dots, \mathbf{v}_N\}$ to find $K$ centroid vectors $\{\mathbf{p}_1, \dots, \mathbf{p}_K\}$ that minimize the sum of squared distances:
    $$
    \min_{\mathcal{P}} \sum_{i=1}^{N} \min_{j \in \{1,\dots,K\}} \| \mathbf{v}_i - \mathbf{p}_j \|^2
    $$
    The source uses a custom mini-batch k-means implementation [S1, unofficial].
3.  **Assign Indices:** For each splat $i$, find the index $j$ of the closest palette vector:
    $$
    \mathcal{I}[i] = \arg\min_{j \in \{1,\dots,K\}} \| \mathbf{v}_i - \mathbf{p}_j \|^2
    $$
4.  **Store:** Save $\mathcal{P}$ and $\mathcal{I}$.

**Pseudocode:**
```python
def spherical_harmonics_vector_quantization(splats, K, L=3):
    """
    Compress SH coefficients using vector quantization.
    
    Args:
        splats: List of N splats. Each splat has a 'sh_coeffs' attribute 
                containing a tensor of shape (3, (L+1)^2).
        K: Number of palette entries (e.g., 4000, 16000).
        L: Maximum SH degree (default 3).
        
    Returns:
        palette: Tensor of shape (K, 3*(L+1)^2 - 3), dtype FP16.
        indices: Tensor of shape (N,), dtype uint16.
    """
    N = len(splats)
    # Dimension D excludes the DC term (l=0, m=0) for each channel
    # Total coeffs per channel = (L+1)^2. DC term is 1.
    # D = 3 * ((L+1)^2 - 1)
    D = 3 * ((L + 1)**2 - 1)
    
    # Step 1: Extract and flatten SH coefficients (excluding DC)
    # Shape: (N, D)
    # Note: The source treats the first coefficient as color, so we skip it.
    # Assuming sh_coeffs is (3, (L+1)^2)
    data = []
    for splat in splats:
        # Extract coefficients for l=1..L
        # Flatten R, G, B channels
        coeffs = splat.sh_coeffs # Shape: (3, (L+1)^2)
        # Remove the first element (l=0, m=0) from each channel
        # Reshape to (3, (L+1)^2 - 1) then flatten to (D,)
        reduced = coeffs[:, 1:] 
        flat = reduced.flatten()
        data.append(flat)
    
    X = torch.stack(data) # Shape: (N, D)
    
    # Step 2: Cluster using Mini-Batch K-Means
    # The source uses a custom implementation for speed and quality [S1, unofficial]
    # Standard k-means minimizes intra-cluster variance
    palette, labels = mini_batch_kmeans(X, K, max_iters=100)
    
    # palette shape: (K, D)
    # labels shape: (N,)
    
    # Step 3: Convert palette to FP16
    palette_fp16 = palette.half()
    
    # Step 4: Store indices as uint16
    indices = labels.to(torch.uint16)
    
    return palette_fp16, indices
```

**Edge Cases and Pitfalls:**
-   **Curse of Dimensionality:** Clustering millions of splats in 45 dimensions is computationally expensive and slow [S1, unofficial].
-   **Implementation Choice:** Standard libraries like scikit-learn are too slow; Faiss is faster but adds dependencies. A custom mini-batch k-means implementation was found to be ~3x faster than Faiss and provided better quality for this specific task [S1, unofficial].
-   **Lighting Artifacts:** The method introduces minor lighting artifacts, particularly noticeable in specular highlights, though the "shininess" effect is largely retained [S1, unofficial].

## Operating characteristics
-   **Memory Reduction:** For the 'bike' scene (6.1M splats), SH clustering into 16k items results in ~12MB of index data and ~1.44MB of palette data (FP16), totaling ~13.4MB [S1, unofficial]. This is a significant reduction from the ~1.1GB raw SH data (FP32) or ~350MB (FP16) [S1, unofficial].
-   **Quality:** 
    -   'Low' preset (16k palette): PSNR ~35.17-35.32, Data size ~98-93MB [S1, unofficial].
    -   'Very Low' preset (4k palette): PSNR ~30.19-32.27, Data size ~79-75MB [S1, unofficial].
    -   Compared to previous 'Low' presets without clustering, PSNR improved slightly (34.72 -> 35.17) while data size decreased (119MB -> 98MB) [S1, unofficial].
-   **Performance:** The clustering step is the bottleneck. The custom implementation is preferred for speed [S1, unofficial].
-   **Strengths:** Significant memory savings; retains high-frequency detail better than degree truncation; simple to implement if a fast k-means variant is available.
-   **Limitations:** Introduces quantization artifacts; clustering time scales poorly with $N$ and $D$; requires storing the palette.

## Background
Spherical Harmonics Vector Quantization was introduced by Aras Pranckevičius in a blog post detailing optimizations for 3D Gaussian Splatting in Unity [S1, unofficial]. The author noted that SH coefficients constitute the majority of the data size in raw Gaussian Splatting files. The technique draws inspiration from historical computer graphics palettes (e.g., indexed color) and vector quantization techniques [S1, unofficial]. It was implemented as part of a "Low" and "Very Low" quality preset system to enable running Gaussian Splatting on hardware with limited memory bandwidth and storage [S1, unofficial].
