# CLM
Also called: CPU-GPU Memory Barrier Removal, Smart Caching Policy for Gaussian States

## Overview
CLM is an optimization technique for 3D Gaussian Splatting that removes the GPU memory barrier by moving Gaussian states between CPU and GPU memory during optimization [S1, unofficial]. It employs a smart caching policy to keep the most frequently updated Gaussians on the GPU [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussian parameters $\theta = \{\mathbf{p}_i, \mathbf{\Sigma}_i, \alpha_i, \mathbf{c}_i, \mathbf{S}_i\}$ (position, covariance, opacity, color, spherical harmonics coefficients) distributed across CPU and GPU memory [G].
*   **Output:** Updated Gaussian parameters after an optimization step, with the subset of "hot" Gaussians residing in GPU memory for immediate rasterization [S1, unofficial].

**Data Structures:**
*   **Gaussian State:** A struct containing all attributes of a single Gaussian primitive [G].
*   **Cache Set:** A fixed-size buffer in GPU memory holding the most recently accessed or updated Gaussians [S1, unofficial].
*   **Liveness Counter/Flag:** A mechanism (e.g., a timestamp or usage counter) associated with each Gaussian to determine its "hotness" [G].

**Steps:**
1.  **Initialization:** Load the initial set of Gaussians into CPU RAM [G].
2.  **Selection:** Identify the subset of Gaussians required for the current training view, prioritizing those most frequently updated in previous iterations [S1, unofficial].
3.  **Streaming:** Transfer the selected "hot" Gaussians from CPU RAM to the GPU Cache Set [S1, unofficial].
4.  **Rasterization:** Render the image using the Gaussians currently in the GPU Cache Set via the differentiable rasterizer [G].
5.  **Gradient Computation:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for the rendered image with respect to the active Gaussians [G].
6.  **Update:** Apply the optimizer step (e.g., Adam) to update the parameters of the active Gaussians [G].
7.  **Cache Management:** Update the liveness metrics for the updated Gaussians based on their update frequency [S1, unofficial].
8.  **Repeat:** Return to Step 2 for the next training iteration [G].

**Formulas:**
*   Gradient propagation follows standard alpha blending backpropagation: $\frac{\partial \mathcal{L}}{\partial \theta_i} = \frac{\partial \mathcal{L}}{\partial C} \frac{\partial C}{\partial \alpha_i} \frac{\partial \alpha_i}{\partial \theta_i}$, where $C$ is the pixel color and $\theta_i$ are the parameters of Gaussian $i$ [G].

**Parameters:**
*   Not given in the sources.

**Pitfalls:**
*   **Thrashing:** If the working set of active Gaussians exceeds the GPU cache size, frequent evictions and re-loading can negate performance gains [G].
*   **Boundary Conditions:** Gaussians on the edge of the frustum may flicker in and out of the cache, causing instability in gradients [G].

## Subtopics

### Out-of-Core Training and Rendering
A framework that stores the full scene in CPU RAM and dynamically streams only visible Gaussians to GPU memory, enabling training and rendering of scenes exceeding VRAM on a single consumer GPU [S2, unofficial]. It uses a lightweight caching system to track recently used Gaussians and reduce CPU-GPU data transfer [S2, unofficial]. A key pitfall is that a single distant view may require access to the full scene, causing high transfer overhead [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** $O(K)$ on GPU, where $K$ is the cache size, and $O(N)$ on CPU, where $N$ is the total number of Gaussians [G].
*   **Performance:** Removes the GPU memory barrier by moving Gaussian states between CPU and GPU memory and retaining frequently updated Gaussians on the GPU [S1, unofficial].
*   **Strengths:** Enables training on hardware with limited VRAM without complex spatial partitioning [G].
*   **Limitations:** Performance degrades if the temporal coherence of Gaussian updates is low [G].

## Background
CLM was introduced as part of the broader effort to optimize 3D Gaussian Splatting training efficiency [S1, unofficial]. It addresses the limitations of standard rasterization pipelines where all Gaussians must reside in GPU memory, leading to memory bottlenecks and synchronization barriers [S1, unofficial]. The method builds on the principles of dynamic memory management and caching policies commonly used in computer graphics and database systems [G].
