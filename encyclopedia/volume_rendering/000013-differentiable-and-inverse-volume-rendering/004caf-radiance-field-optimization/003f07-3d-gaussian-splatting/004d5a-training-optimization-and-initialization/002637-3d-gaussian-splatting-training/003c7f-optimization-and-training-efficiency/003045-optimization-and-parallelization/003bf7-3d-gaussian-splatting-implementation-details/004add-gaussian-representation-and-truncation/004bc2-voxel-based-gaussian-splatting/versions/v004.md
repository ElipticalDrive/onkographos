# Voxel-based Gaussian Splatting


## Overview
Voxel-based Gaussian Splatting (VoxGS) is a volume representation designed for efficient Computed Tomography (CT) extraction and differentiable X-ray rendering from sparse projections [S1, unofficial]. It solves the instability and inaccuracy of applying standard 3D Gaussian Splatting (3DGS) to CT data by fixing Gaussian positions to a regular voxel grid and removing view-dependent color coefficients [S1, unofficial]. Unlike standard 3DGS which optimizes primitive positions, VoxGS regresses attributes from transformer tokens in a feed-forward manner, enabling direct volume extraction via simple indexing [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $K$ X-ray projection images, represented as view feature maps $\mathbf{F}_k \in \mathbb{R}^{H \times W \times C}$ for $k=1 \dots K$, and their corresponding projection matrices $\mathbf{P}_k: \mathbb{R}^3 \to \mathbb{R}^2$ [S1, unofficial].
*   **Output:** A set of $N_p$ 3D Gaussians $\mathcal{G} = \{g_i\}_{i=1}^{N_p}$ and a CT density volume $V \in \mathbb{R}^{M \times N \times L}$ [S1, unofficial].

**Data Structures:**
Each Gaussian $g_i$ is defined by the following attributes, stored as floating-point values:
*   **Position $\mu_i$:** Fixed 3D vector $(x, y, z)$ corresponding to the centroid of a voxel in a grid of size $M \times N \times L$. $x \in [1, M], y \in [1, N], z \in [1, L]$ [S1, unofficial].
*   **Opacity $\alpha_i$:** Scalar value representing density [S1, unofficial].
*   **Scale $\mathbf{s}_i$:** 3D vector $(s_x, s_y, s_z)$ [S1, unofficial].
*   **Rotation $\mathbf{r}_i$:** 4D vector representing a quaternion [S1, unofficial].
*   **Note:** No spherical harmonic (SH) coefficients are stored, as X-ray attenuation is isotropic [S1, unofficial].

**Numbered Steps:**
1.  **Grid Initialization:** Define a regular 3D voxel grid with dimensions $M \times N \times L$. Place one isometric 3D Gaussian $g_i$ at the centroid of each voxel. The position $\mu_i$ is fixed and does not change during optimization [S1, unofficial].
2.  **Feature Query:** For each Gaussian $g_i$ with fixed position $\mu_i$, and for each view $k=1 \dots K$:
    *   Project $\mu_i$ to 2D screen coordinates using the view's projection matrix: $P_k(\mu_i)$ [S1, unofficial].
    *   Query the view-specific feature $F_k$ from the view feature map $\mathbf{F}_k$ using bilinear interpolation:
        $$ F_k = \text{Interp}(\mathbf{F}_k, \mathbf{P}_k(\boldsymbol{\mu}_i)) \in \mathbb{R}^C $$
        where $\text{Interp}$ denotes bilinear interpolation [S1, unofficial].
3.  **Feature Aggregation:** Aggregate the $K$ queried view-specific features using MaxPooling to obtain a single view-invariant feature vector $F_i^{\max}$:
    $$ F_i^{\max} = \text{MaxPool}(F_i^1, F_i^2, \dots, F_i^K) \in \mathbb{R}^C $$
    [S1, unofficial].
4.  **Attribute Regression:** Pass $F_i^{\max}$ through a Multi-Layer Perceptron (MLP), denoted as $MLPS$, to predict the Gaussian parameters:
    $$ [\alpha_i, \mathbf{s}_i, \mathbf{r}_i] = MLPS(F_i^{\max}) \in \mathbb{R}^{1+3+4} $$
    The output consists of 1 float for opacity, 3 floats for scale, and 4 floats for rotation [S1, unofficial].
5.  **Volume Extraction:** To extract the CT density volume $V$, directly index the opacity $\alpha_i$ of the Gaussian at the corresponding voxel position:
    $$ V(x, y, z) = \alpha_i \quad \text{where} \quad \boldsymbol{\mu}_i = (x, y, z)^T $$
    This allows for fast extraction without trilinear interpolation [S1, unofficial].
6.  **Differentiable X-ray Rendering:** Render X-ray projections by accumulating the Gaussian contributions along rays. The rendering uses a rasterizer that supports differentiable operations, allowing gradients to flow back to the transformer tokens and MLP parameters [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class VoxGS:
    def __init__(self, grid_dims: tuple, num_views: int, feature_dim: int, mlp_hidden_dims: list):
        """
        Initialize VoxGS representation.
        
        Args:
            grid_dims: Tuple (M, N, L) defining the voxel grid size.
            num_views: Number of X-ray projections K.
            feature_dim: Dimension C of the view feature maps.
            mlp_hidden_dims: List of hidden layer sizes for the attribute prediction MLP.
        """
        self.M, self.N, self.L = grid_dims
        self.K = num_views
        self.C = feature_dim
        
        # Fixed positions for all Gaussians (one per voxel)
        # Shape: (N_p, 3) where N_p = M * N * L
        x = torch.arange(1, M + 1).float()
        y = torch.arange(1, N + 1).float()
        z = torch.arange(1, L + 1).float()
        xx, yy, zz = torch.meshgrid(x, y, z, indexing='ij')
        self.mu = torch.stack([xx.flatten(), yy.flatten(), zz.flatten()], dim=-1) # (N_p, 3)
        self.N_p = self.mu.shape[0]
        
        # MLP to predict attributes from aggregated features
        layers = []
        prev_dim = feature_dim
        for hidden_dim in mlp_hidden_dims:
            layers.append(nn.Linear(prev_dim, hidden_dim))
            layers.append(nn.ReLU())
            prev_dim = hidden_dim
        layers.append(nn.Linear(prev_dim, 1 + 3 + 4)) # alpha, scale, rotation
        self.MLPS = nn.Sequential(*layers)
        
        # Initialize attributes to zeros or small random values
        self.alpha = torch.zeros(self.N_p)
        self.scale = torch.zeros(self.N_p, 3)
        self.rotation = torch.zeros(self.N_p, 4)

    def query_and_aggregate(self, view_features: torch.Tensor, projection_matrices: list) -> torch.Tensor:
        """
        Query view-specific features and aggregate them.
        
        Args:
            view_features: Tensor of shape (K, H, W, C) containing view feature maps.
            projection_matrices: List of K projection matrices P_k.
            
        Returns:
            Aggregated features F_max of shape (N_p, C).
        """
        # view_features: (K, H, W, C)
        # projection_matrices: list of K matrices, each mapping 3D to 2D
        
        all_features = []
        for k in range(self.K):
            P_k = projection_matrices[k]
            # Project all Gaussian centers to 2D for view k
            # mu: (N_p, 3), P_k: (2, 3) or similar affine transform
            # Assuming P_k is a 2x3 matrix for linear projection, or handle affine part
            # For simplicity, assume P_k projects (x,y,z) to (u,v)
            # u = P_k[0,0]*x + P_k[0,1]*y + P_k[0,2]*z + P_k[0,3]
            # v = P_k[1,0]*x + P_k[1,1]*y + P_k[1,2]*z + P_k[1,3]
            
            # Extract 2D coordinates
            # Note: Implementation detail depends on exact P_k format. 
            # Assuming P_k is (2, 4) homogeneous matrix [R|t]
            mu_homogeneous = torch.cat([self.mu, torch.ones(self.N_p, 1)], dim=-1) # (N_p, 4)
            proj_2d = torch.matmul(mu_homogeneous, P_k.T) # (N_p, 2)
            
            # Normalize to [0, 1] for interpolation if needed, or use grid_sample directly
            # grid_sample expects normalized coordinates [-1, 1] or [0, 1]
            # Assuming view_features are in a standard image coordinate system
            
            # Bilinear interpolation
            # grid_sample input: (N, C, H, W), grid: (N, H_out, W_out, 2)
            # We need to sample K points for each of N_p Gaussians
            # Reshape for grid_sample: (N_p * K, C, H, W) is not efficient.
            # Instead, sample for each view separately or batched.
            
            # Let's sample for view k
            # proj_2d: (N_p, 2)
            # Normalize to [-1, 1] assuming image center is 0
            # This step depends on the specific coordinate system of view_features
            # Assuming view_features are H x W, and proj_2d is in pixel coordinates
            # Normalize: grid_x = 2 * (u / W) - 1, grid_y = 2 * (v / H) - 1
            
            H, W = view_features[k].shape[1], view_features[k].shape[2]
            u = proj_2d[:, 0]
            v = proj_2d[:, 1]
            
            # Normalize to [-1, 1]
            grid_x = 2.0 * (u / W) - 1.0
            grid_y = 2.0 * (v / H) - 1.0
            
            # Clamp to avoid out-of-bounds interpolation
            grid_x = torch.clamp(grid_x, -1.0, 1.0)
            grid_y = torch.clamp(grid_y, -1.0, 1.0)
            
            # Create grid for grid_sample: (N_p, 1, 1, 2)
            grid = torch.stack([grid_x, grid_y], dim=-1).unsqueeze(1).unsqueeze(1) # (N_p, 1, 1, 2)
            
            # view_features[k]: (H, W, C) -> (1, C, H, W)
            feat_map = view_features[k].permute(2, 0, 1).unsqueeze(0) # (1, C, H, W)
            
            # Sample features
            # grid_sample: (N, C, H_out, W_out)
            sampled = F.grid_sample(feat_map, grid, mode='bilinear', padding_mode='zeros') # (1, C, 1, 1)
            F_k = sampled.squeeze() # (C,) -> (N_p, C) if we had N_p samples, but here N_p=1 in batch dim?
            # Correction: grid_sample batch dim is N. We have N_p samples.
            # feat_map should be (N_p, C, H, W) if we want to sample all at once? 
            # No, grid_sample samples from the same feature map for all batch items.
            # So feat_map is (1, C, H, W) and grid is (N_p, 1, 1, 2) -> output (N_p, C, 1, 1)
            
            F_k = sampled.squeeze(-1).squeeze(-1) # (N_p, C)
            all_features.append(F_k)
            
        # Stack features: (K, N_p, C) -> (N_p, K, C)
        all_features = torch.stack(all_features, dim=0).permute(1, 0, 2) # (N_p, K, C)
        
        # MaxPool over K views
        F_max = torch.max(all_features, dim=1)[0] # (N_p, C)
        return F_max

    def predict_attributes(self, F_max: torch.Tensor) -> tuple:
        """
        Predict Gaussian attributes from aggregated features.
        
        Args:
            F_max: Aggregated features of shape (N_p, C).
            
        Returns:
            Tuple of (alpha, scale, rotation) tensors.
        """
        # MLP output: (N_p, 1+3+4)
        out = self.MLPS(F_max) # (N_p, 8)
        alpha = out[:, 0] # (N_p,)
        scale = out[:, 1:4] # (N_p, 3)
        rotation = out[:, 4:8] # (N_p, 4)
        return alpha, scale, rotation

    def extract_volume(self, alpha: torch.Tensor) -> torch.Tensor:
        """
        Extract CT density volume from Gaussian opacities.
        
        Args:
            alpha: Opacity values of shape (N_p,).
            
        Returns:
            CT volume V of shape (M, N, L).
        """
        # Reshape alpha to grid dimensions
        V = alpha.reshape(self.M, self.N, self.L)
        return V
```

**Parameters:**
*   **Grid Dimensions ($M, N, L$):** Determined by the desired resolution of the CT volume. Not given in the sources.
*   **Number of Views ($K$):** Number of X-ray projections. Not given in the sources.
*   **Feature Dimension ($C$):** Dimension of the view feature maps. Not given in the sources.
*   **MLP Architecture:** Number of layers and hidden units. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Standard 3DGS Instability:** Directly using standard 3DGS for CT leads to inaccurate volume extraction and unstable optimization in feed-forward frameworks [S1, unofficial]. VoxGS mitigates this by fixing positions [S1, unofficial].
*   **Color Representation:** Standard 3DGS uses spherical harmonics for view-dependent color. VoxGS removes SH coefficients because X-ray attenuation is isotropic and depends only on density [S1, unofficial].
*   **Volume Extraction:** Without fixed positions, extracting a voxel grid from 3DGS requires complex trilinear interpolation. VoxGS allows direct indexing, improving speed and stability [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The attribute prediction is a feed-forward pass through an MLP for each Gaussian, making it $O(N_p)$ where $N_p = M \times N \times L$. Feature querying involves bilinear interpolation for each view, $O(K \cdot N_p)$. This is significantly faster than iterative optimization-based methods [S1, unofficial].
*   **Memory Complexity:** Storage is $O(N_p)$ for Gaussian attributes (opacity, scale, rotation). No SH coefficients are stored, reducing memory compared to standard 3DGS [S1, unofficial].
*   **Performance:** X-GRM using VoxGS reconstructs CT volumes within one second from sparse X-ray inputs, outperforming SOTA methods in both quality and speed [S1, unofficial].
*   **Strengths:** Efficient CT volume extraction via direct indexing; differentiable X-ray rendering for training constraints; stable optimization for feed-forward frameworks [S1, unofficial].
*   **Limitations:** Limited to isotropic density representation (no view-dependent color); requires a pre-trained transformer to generate view features [S1, unofficial].
*   **When to Use:** Sparse-view X-ray to CT reconstruction where fast, differentiable rendering and precise volume extraction are required [S1, unofficial].
*   **When Not to Use:** Applications requiring view-dependent color or non-isotropic scattering [S1, unofficial].

## Background
Voxel-based Gaussian Splatting (VoxGS) was introduced in the paper "X-GRM: Large Gaussian Reconstruction Model for Sparse-view X-rays to Computed Tomography" [S1, unofficial]. It was developed to address the limitations of applying standard 3D Gaussian Splatting to CT reconstruction, specifically the instability of optimizing primitive positions and the complexity of volume extraction. The method leverages the efficient rendering of 3DGS [28] and modifies it for isotropic density representation [S1, unofficial].
