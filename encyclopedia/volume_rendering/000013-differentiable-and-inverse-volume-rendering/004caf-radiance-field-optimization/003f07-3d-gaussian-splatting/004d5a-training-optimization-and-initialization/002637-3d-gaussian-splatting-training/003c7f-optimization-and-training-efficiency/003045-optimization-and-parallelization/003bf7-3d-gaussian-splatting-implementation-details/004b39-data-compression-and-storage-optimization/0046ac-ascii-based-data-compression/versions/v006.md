# ASCII-Based Data Compression

Also called: Anywhere Compression, Base 94 Floating-Point Compression, Base 95 Integer Compression

## Overview
This method reduces the storage and transmission overhead of 3D Gaussian Splatting parameters by encoding numerical values as compact ASCII strings, thereby improving data transmission speed during training [S1, unofficial]. It distinguishes itself from sibling methods like [Sensitivity-Aware Vector Clustering](12167-sensitivity-aware-vector-clustering.md) and [Compact 3D Gaussian Representation (C3DGS)](12927-compact-3d-gaussian-representation-c3dgs.md) by operating on the serialization layer rather than the geometric representation itself, trading minor precision loss for faster I/O [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** High-precision floating-point or integer values representing Gaussian attributes (position, scale, rotation, SH coefficients, color).
*   **Output:** ASCII strings representing the compressed values, and the decoded values for rendering/computation.

**Data Structures:**
The method does not define a new binary data structure but relies on string manipulation. The core mapping is a lookup table between integer ranges and ASCII characters.

**Steps:**

1.  **Integer Compression (Base 95):**
    *   Map integers in the range $[0, 95]$ to ASCII characters with codes 32 to 126 inclusive.
    *   Encoding: $c = \text{chr}(i + 32)$, where $i \in [0, 95]$.
    *   Decoding: $i = \text{ord}(c) - 32$.

2.  **Floating-Point Compression (Base 94):**
    *   Decompose a floating-point number $f$ into an integer part $I$ and a decimal place count $d$.
    *   Map the integer part $I$ (range $[0, 94]$) to ASCII characters 32 to 125.
    *   Use the ASCII character 126 (`~`) as a delimiter to connect the integer part string and the decimal part string.
    *   Encoding: $s = \text{chr}(I + 32) + \text{chr}(126) + \text{str}(d)$.
    *   Decoding: Split string $s$ at the delimiter `~`. Let the first part be $s_I$ and the second part be $s_d$.
        *   $I = \text{ord}(s_I) - 32$
        *   $d = \text{int}(s_d)$
        *   Final value: $f = I \times 10^{-d}$.

3.  **Color Matrix Optimization:**
    *   Quantize color matrix items to one decimal place within the range $[0.0, 2.0]$.
    *   This results in 21 discrete alternative numbers ($0.0, 0.1, \dots, 2.0$).
    *   Apply ASCII compression to these quantized values to significantly reduce data size [S1, unofficial].

**Parameters:**
*   Integer Base: 95.
*   Floating-Point Integer Base: 94.
*   Delimiter: ASCII 126 (`~`).
*   Color Precision: 1 decimal place.

**Edge Cases and Pitfalls:**
*   **Matrix Traversal:** Compressing large color matrices via ASCII string traversal is computationally expensive. Using internal functions like `torch.where` and `torch.index_select` improves speed but may not be fast enough for full replacement of standard loops [S1, unofficial].
*   **Line Breaks:** Using line break characters in ASCII strings adds an extra operator during writing and decoding, increasing overhead [S1, unofficial].
*   **Precision Loss:** The method assumes that compressing color to one decimal place has no explicit impact on final rendering results [S1, unofficial].

    """
    Compress an integer in range [0, 95] to a single ASCII character.
    """
    if not (0 <= value <= 95):
        raise ValueError("Integer out of range [0, 95]")
    return chr(value + 32)

def decompress_integer(char: str) -> int:
    """
    Decompress a single ASCII character back to an integer.
    """
    return ord(char) - 32

    """
    Decompress an ASCII string back to a floating-point number.
    Format: [Char for I][~][String for d]
    """
    delimiter = chr(126)

    Compress a color matrix by quantizing to 1 decimal place [0.0, 2.0]

    """
    # Quantize
    quantized = torch.round(matrix * 10) / 10
    # Clip to [0.0, 2.0]
    quantized = torch.clamp(quantized, 0.0, 2.0)
    
    # Map to 0-20 integer range
    int_values = (quantized * 10).long()

## Operating characteristics
*   **Time Complexity:** The compression/decompression is $O(N)$ where $N$ is the number of parameters. However, matrix traversal for color compression is a bottleneck. Using `torch.where` and `torch.index_select` mitigates this but remains slower than native binary operations [S1, unofficial].
*   **Memory Complexity:** Reduces storage size by encoding multiple values into single ASCII characters. The color matrix reduction is significant due to quantization [S1, unofficial].
*   **Performance:** Gains approximately 6% or less improvement in training speed [S1, unofficial].
*   **Strengths:** Improves data transmission speed; simple implementation using standard ASCII libraries.
*   **Limitations:** Not fast enough for full replacement of matrix operations; precision loss in color quantization; delimiter handling adds overhead [S1, unofficial].
*   **When to use:** When data transmission is the bottleneck in training and minor precision loss is acceptable.
*   **When not to use:** When maximum rendering fidelity is required or when matrix traversal speed is critical.

## Background
This method was introduced in the paper "I3DGS: Improve 3D Gaussian Splatting from Multiple Dimensions" [S1, unofficial]. It is part of a broader effort to optimize 3D Gaussian Splatting training speed through various dimensions including color, learning, structure design, and compression [S1, unofficial].
