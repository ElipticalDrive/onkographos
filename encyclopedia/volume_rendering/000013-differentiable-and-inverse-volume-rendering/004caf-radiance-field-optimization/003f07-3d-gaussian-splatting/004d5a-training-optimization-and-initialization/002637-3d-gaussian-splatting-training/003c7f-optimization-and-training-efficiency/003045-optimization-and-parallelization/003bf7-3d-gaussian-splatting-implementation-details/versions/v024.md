# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific software engineering, hyperparameter configurations, and optimization strategies required to implement the 3D Gaussian Splatting (3DGS) training pipeline. It addresses the practical challenges of differentiable rasterization, including memory management, precision stability, and specific variant implementations for handling blur, color representation, and environmental artifacts. It builds on [Optimization and Parallelization](6233-optimization-and-parallelization.md) by providing the concrete parameters and kernel-level details that enable the shared differentiable rendering principles.

## How it works

### Inputs and Outputs
*   **Inputs:** A set of posed images (typically from Structure-from-Motion), camera intrinsics/extrinsics, and an initial point cloud (e.g., from COLMAP).
*   **Outputs:** A set of 3D Gaussian primitives parameterized by position $\mathbf{p}$, covariance $\Sigma$ (or scale $\mathbf{s}$ and rotation $\mathbf{r}$), opacity $\alpha$, spherical harmonic coefficients $\mathbf{c}$, and potentially auxiliary parameters (e.g., backscatter coefficients, view-dependent opacity lobes).

### Data Structures
The core data structure is a list of Gaussians. Each Gaussian $i$ stores:
*   $\mathbf{p}_i \in \mathbb{R}^3$: Position.
*   $\mathbf{s}_i \in \mathbb{R}^3$: Scale (log-space for optimization).
*   $\mathbf{r}_i \in \mathbb{R}^4$: Rotation (quaternion, normalized).
*   $\alpha_i \in [0, 1]$: Opacity.
*   $\mathbf{c}_{i,0..L} \in \mathbb{R}^{3(L+1)^2}$: SH coefficients for color.
*   [G] Additional attributes for variants (e.g., backscatter parameters $B_d, B_\infty, B_b$).

### Rasterization and Training Loop
The training loop iterates over mini-batches of views. The standard implementation uses the `gsplat` library with custom CUDA kernels based on the 3DGUT formulation [S1].

1.  **Forward Pass (Rasterization):**
    *   Project 3D Gaussians to 2D screen space using the camera projection matrix.
    *   Compute 2D covariance $\Sigma'$ from 3D covariance $\Sigma$ and view Jacobian [S1].
    *   Sort Gaussians by depth for each tile/pixel.
    *   Alpha-blend colors along rays: $C = \sum_i c_i \alpha_i T_i$, where $T_i = \prod_{j<i} (1-\alpha_j)$ [S1].
    *   [G] Use half-precision (FP16) memory fetches for feature vectors during rasterization to reduce register pressure [S1].

2.  **Loss Computation:**
    *   Compute loss $\mathcal{L}$ between rendered image $I^r$ and ground truth $I^{gt}$ using L1 and D-SSIM:
        $$ \mathcal{L} = (1 - \lambda_1) \| I^{gt} - I^r \|_{\ell_1} + \lambda_1 L_{D-SSIM}(I^{gt}, I^r) $$
        where $\lambda_1 \in [0,1]$ [S8].
    *   [G] Apply an automatic scaling factor to loss values to improve half-precision training stability [S1].

3.  **Backward Pass:**
    *   Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all parameters $\theta$ (position, scale, rotation, opacity, SH coefficients) via automatic differentiation through the rasterizer [S1].

4.  **Optimization Step:**
    *   Update parameters using the Adam optimizer.
    *   Typical learning rate: $1 \times 10^{-3}$ [S2].
    *   [G] Randomly select a single image from the scene for supervision per iteration [S2].

### Parameters and Configuration
*   **SH Degree:** Typically 1 for simplicity and speed, though 3 is used for high fidelity [S2][S5].
*   **Optimizer:** Adam [S2].
*   **Library:** `gsplat` for rasterization, `torchsparse` for 3D sparse convolution if used [S2].
*   **Neural Networks:** If using neural fields (e.g., for color), use tiny-cuda-nn's JIT-compiled cooperative vector MLPs in FP16 [S1].

### Edge Cases and Pitfalls
*   **Precision:** Half-precision training requires loss scaling to prevent gradient underflow [S1].
*   **Camera Response:** Underwater or physical optics variants require linear camera response. JPEG or gamma-corrected images must be linearized or excluded [S8].
*   **Scene Extent:** Default scene extent calculation based on camera positions can bias densification if cameras are clustered. Use SfM point cloud-based extent correction [S3].

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S3]. The default 3DGS extent $e_{\text{scene}} = 1.1 \cdot \max_{i} \|\bar{C} - C_i\|_2$ fails when cameras are clustered [S3]. The corrected extent is:
$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
where $\bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i$ is the average camera position, and $p_i$ are SfM points [S3]. This ensures densification parameters are appropriate for the actual scene volume [S3].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S4]. A compact MLP predicts $\delta s_j$ for each Gaussian $j$. The base scale is transformed, and the resulting covariance acts as a blur kernel during rasterization [S4]. If $\delta s_j$ is constant, it degrades to uniform Gaussian blur [S4]. This allows modeling of defocus blur without blurring sharp regions [S4].

### Compact View-dependent Color
Replaces per-Gaussian Spherical Harmonics (SH) coefficients with a grid-based neural field to reduce parameters from 48 (SH degree 3) to a shared grid [S5]. Unbounded positions $p_n$ are contracted to a bounded range using:
$$ \text{contract}(p_n) = \begin{cases} p_n & \text{if } \|p_n\| \le 1 \\ \frac{p_n}{\|p_n\|} (2 - \|p_n\|) & \text{otherwise} \end{cases} $$
View-dependent color is computed as $c_n(d) = f(\text{contract}(p_n), d; \theta)$, where $f$ is a tiny MLP [S5]. 0-degree SH components are used as input features [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3DGS using Noise2Void (N2V) [S6]. Round 1: Train a UNet with N2V, process denoised images through InstantSplat to initialize/train 3DGS, and filter rendered results by viewpoint [S6]. Round 2: Fine-tune the UNet with a composite loss (low-frequency and perceptual consistency) and render again [S6]. Unlike supervised methods, it requires no paired clean data, making it robust to non-Gaussian noise in sparse views [S6].

### View-Dependent Opacity Kernel
Models opacity as view-dependent using a half-period cosine function to approximate specular reflectance lobes [S7, unofficial]. Adds 5 learnable parameters ($T, \beta, \alpha, \theta$) to the standard configuration [S7, unofficial]. The opacity is:
$$ \hat{\alpha}(\theta, \beta, T, \alpha) = \alpha \cdot \frac{\cos(\max(0, \min(\frac{2\theta}{T}, \pi)))+1}{2}\exp(\beta) $$
where $\theta$ is the angle between view direction and lobe orientation, $T$ controls angular span, and $\beta$ modulates sharpness [S7, unofficial]. Transparency diminishes to zero as $\theta$ increases, preventing artifacts outside the lobe [S7, unofficial].

### Backscatter Estimation and Optimization
Adapts 3DGS for underwater scenes by estimating backscatter parameters $B_\infty$ and $B_b$ [S8]. The rendering equation incorporates direct attenuation $B_d$ and backscatter [S8]. Backscatter is estimated by dividing the depth map into 10 clusters and identifying pixels with RGB triplets in the bottom 1st percentile of the ground truth image as overestimates of backscatter [S8]. Nonlinear least squares fitting on $(B_s, z)$ pairs estimates $B_\infty$ and $B_b$ [S8]. Parameters are re-estimated every 500 steps [S8]. Depth $z$ is extracted from the current scene estimate using:
$$ z = \frac{\sum_{i=1}^M d_i \alpha_i T_i}{\sum_{i=1}^M \alpha_i T_i} $$
where $d_i$ is the depth of Gaussian $i$ [S8]. Camera sensors must have a linear response [S8].

### Model-based depth estimation for volume parameter update
Used in conjunction with backscatter estimation, depth values $z$ are extracted from the current scene estimate during optimization to update medium-parameter estimates ($B_\infty, B_b$) [S8]. This leverages the rasterization pipeline to provide dense depth maps without additional neural networks [S8].

## Operating characteristics

### Time and Memory Complexity
*   **Memory:** Dominated by the number of Gaussians. Each Gaussian stores position, scale, rotation, opacity, and SH coefficients. Variants like Compact View-dependent Color reduce memory by sharing neural field parameters [S5]. Data compression methods can reduce storage to <1 GB for large scenes [S12943].
*   **Time:** Rasterization is $O(N \cdot P)$ where $N$ is the number of Gaussians and $P$ is the number of pixels, but optimized via tiling and sorting [S12180]. Training time is dominated by the backward pass through the rasterizer.

### Measured Performance
*   **Hardware:** Typically runs on NVIDIA GPUs (e.g., A100, V100, RTX 4090) [S2][S5].
*   **Resolution:** Supports high-resolution rendering (e.g., 1080p, 4K) with real-time inference speeds (e.g., 100+ fps) [S2][S5].
*   **Scaling:** Scales linearly with the number of Gaussians. Sparse convolution and voxel-based methods can improve efficiency for large scenes [S2][S13071].

### Strengths and Limitations
*   **Strengths:** Real-time rendering, high fidelity, differentiable optimization, flexible representation [S1][S2].
*   **Limitations:** High memory usage for large scenes, sensitivity to initialization, artifacts in sparse views or noisy environments [S6]. Standard 3DGS assumes smooth alpha blending, struggling with sharp discontinuities [S13138].

### When to Use
*   Use for high-quality novel view synthesis from dense image sets.
*   Use variants for specific challenges: Denoise-GS for sparse/noisy views, Backscatter Estimation for underwater scenes, Selective Defocus Blurring for blurred images.

### When Not to Use
*   Avoid for scenes with extreme view-dependent effects not captured by SH or view-dependent opacity (e.g., complex specularities) without augmentation [S7, unofficial].
*   Avoid for scenes with sharp discontinuities without using Discontinuity-aware methods [S13138].

## Background

### Origin
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S26, implied]. It represents scenes as a set of 3D Gaussians optimized via differentiable rasterization.

### History and Development
Since its introduction, numerous variants have been developed to address limitations:
*   **Memory Efficiency:** Compact representations, data compression, and voxel-based methods [S5][S12943][S13071].
*   **Robustness:** Denoising, defocus handling, and underwater adaptation [S4][S6][S8].
*   **Advanced Rendering:** View-dependent opacity, discontinuity handling, and language-aware training [S7, unofficial][S13138][S12438].

### Usage
Widely used in computer vision and graphics for novel view synthesis, 3D reconstruction, and AR/VR applications [S2][S5].
