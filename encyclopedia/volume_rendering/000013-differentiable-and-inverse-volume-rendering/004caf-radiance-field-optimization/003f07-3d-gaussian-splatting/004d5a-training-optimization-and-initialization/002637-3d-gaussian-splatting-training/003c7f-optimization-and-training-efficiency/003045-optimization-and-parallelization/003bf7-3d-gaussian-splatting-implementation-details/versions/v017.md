# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization strategies, and variant algorithms required to train and render 3D Gaussian Splatting (3DGS) scenes efficiently. It addresses the core differentiable rasterization pipeline, including half-precision memory management, loss scaling, and specific hyperparameter configurations for optimizers and spherical harmonics. It also covers minor variants that modify the Gaussian representation, such as view-dependent opacity, mesh-based connections, and compact color fields, to handle specific artifacts like defocus blur, specular reflections, or storage constraints.

## How it works

### Inputs and Outputs
*   **Inputs**: A set of 3D Gaussians parameterized by position $\mathbf{p}$, covariance (scale $\mathbf{s}$ and rotation $\mathbf{q}$), opacity $\alpha$, and spherical harmonic (SH) coefficients $\mathbf{c}$. Camera poses (extrinsics $\mathbf{E}$ and intrinsics $\mathbf{K}$) and ground-truth images.
*   **Outputs**: Rendered images $\mathbf{I}$, gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters, and optionally extracted meshes or depth maps.

### Data Structures
*   **Gaussian Attributes**: Stored in contiguous arrays or structures of arrays (SoA) for cache efficiency during rasterization.
    *   Position: $\mathbf{p} \in \mathbb{R}^3$
    *   Rotation: $\mathbf{q} \in \mathbb{R}^4$ (quaternion)
    *   Scale: $\mathbf{s} \in \mathbb{R}^3$
    *   Opacity: $\alpha \in \mathbb{R}$
    *   SH Coefficients: $\mathbf{c} \in \mathbb{R}^{3 \times (d+1)^2}$, where $d$ is the degree.
*   **Rasterization State**: Per-pixel accumulators for color $\mathbf{C}$ and transmittance $T$.

### Training Configuration and Optimization
The training process uses the Adam optimizer with a learning rate of $1 \times 10^{-3}$ [S2]. The supervision is applied by randomly selecting a single image from a random scene for each iteration [S2].

**Half-Precision Implementation**:
To reduce register pressure and memory bandwidth, the rasterization kernels (both forward and backward) use half-precision (FP16) memory fetches for feature vectors [S1]. The tiny-cuda-nn library is used for JIT-compiled cooperative vector MLPs, trained and evaluated in FP16 [S1]. An automatic scaling factor is applied to loss values to improve training stability in half-precision [S1].

**Spherical Harmonics Degree**:
The standard implementation uses SH degree 1 or higher. However, setting the maximum SH degree to 0 can improve training speed by 16.25–16.57% without explicit impact on final rendering quality, as higher-degree coefficients often remain unchanged during training [S4, unofficial]. This is achieved by deleting superfluous operations related to max degree in the model code [S4, unofficial].

### Scene Extent and Initialization
The scene extent $e_{\text{scene}}$ determines the volume for Gaussian initialization and densification.

**Default Extent**:
The default 3DGS computes extent based on camera positions:
$$ e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2 $$
$$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
where $N_{\text{cam}}$ is the number of camera views and $C_i$ is the position of the $i$-th camera [S3].

**Corrected Scene Extent**:
If cameras are clustered (e.g., orbiting a small object in a large environment), the default extent is biased, leading to incorrect splitting/pruning. A corrected extent uses the Structure-from-Motion (SfM) point cloud:
$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
where $N_{\text{SfM}}$ is the number of SfM points and $p_i$ is the $i$-th SfM point [S3].

### Rasterization and Rendering
The forward pass projects 3D Gaussians to 2D ellipses and alpha-blends them sorted by depth.

**Depth Extraction**:
Depth values $z$ can be extracted from the 3DGS scene for auxiliary tasks (e.g., underwater backscatter estimation) using the weighted average of Gaussian depths:
$$ z = \frac{\sum_{i=1}^M d_i \alpha_i T_i}{\sum_{i=1}^M \alpha_i T_i} $$
where $d_i$ is the depth of Gaussian $i$, $\alpha_i$ is its opacity, and $T_i$ is the transmittance from preceding Gaussians [S11].

### Edge Cases and Pitfalls
*   **Camera Distribution Bias**: Using the default scene extent formula on scenes with clustered cameras leads to underestimation of scene size, causing Gaussians to be pruned incorrectly [S3].
*   **Non-Linear Camera Response**: Underwater backscatter estimation requires linear camera response. In-camera processed JPEGs or gamma-corrected images cannot be used unless non-linearities are reversed [S11].
*   **Constant Blur Prediction**: If the scale offset $\delta s_j$ for defocus blur is predicted as a constant for all Gaussians, the method degrades to a uniform Gaussian blur, failing to model spatially varying blurriness [S5].

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S3]. It sets itself apart from the default 3DGS initialization by using point cloud density rather than camera pose distribution to define the optimization volume [S3].

### SH Degree Zero Optimization
Setting the maximum degree of Spherical Harmonics (SH) coefficients to 0 to remove superfluous operations and improve training speed, as higher-degree SH coefficients for color often remain unchanged during training [S4, unofficial]. It differs from standard training by eliminating the computation of unused high-degree coefficients, yielding a ~16.5% speedup [S4, unofficial].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It sets itself apart from naive Gaussian blur (which blurs the whole image) or learnable single-kernel blur (which models average blurriness) by allowing spatially varying blur shapes and magnitudes via per-Gaussian offsets [S5].

### Triangle Soup (Mesh-based Gaussian Splatting)
A representation that connects Gaussian splats to a mesh structure, enabling real-time editing and animation by directly manipulating mesh vertices [S6]. It distinguishes itself from vanilla GS by automatically recalculating Gaussian parameters (covariance, rotation) when vertices are moved, avoiding holes and blurriness [S6]. Used in the GaMeS model for 3D face reconstruction and object editing [S6].

### SuGaR Mesh Extraction
A method to extract a surface mesh from Gaussian Splatting by regularizing Gaussians to align with the true scene surface. It uses Poisson reconstruction on points sampled from the visible level set of the Gaussian splatting density function [S7]. It sets itself apart from standard 3DGS by enforcing surface alignment regularization and providing a robust mesh extraction pipeline, including automatic tuning of the Poisson octree depth [S7].

### Compact View-dependent Color
Represents view-dependent color using a grid-based neural field instead of storing Spherical Harmonics (SH) coefficients per Gaussian, reducing parameters from 48 to a shared grid [S8]. It differs from standard 3DGS by contracting unbounded positions to a bounded range and using a tiny MLP to predict color from hash grid features and view direction, rather than per-Gaussian SH coefficients [S8].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with differentiable 3DGS [S9]. It sets itself apart from supervised denoising methods by requiring no paired clean data, making it robust to non-Gaussian and time-varying noise in sparse viewpoint scenarios [S9].

### View-Dependent Opacity Kernel
A transparent Gaussian kernel where opacity is view-dependent, modeled by a half-period cosine function to approximate specular reflectance lobes [S10, unofficial]. It adds 5 learnable parameters (base opacity, angular span, sharpness, etc.) to the standard 3DGS configuration, allowing Gaussians to model specular highlights more accurately than constant opacity [S10, unofficial].

### Backscatter Estimation and Optimization
Adapts 3DGS to underwater environments by learning direct attenuation, infinite backscatter, and backscatter coefficients alongside scene geometry [S11]. It solves color distortion and visibility loss in aquatic scenes by using an alternating optimization strategy that refines depth and medium parameters simultaneously, unlike vanilla 3DGS which struggles with underwater color palettes [S11].

### Model-based depth estimation for volume parameter update
Uses depth values extracted from the current 3DGS scene estimate to update medium-parameter estimates (backscatter coefficients) during optimization [S11]. It integrates depth extraction directly into the rendering loop to guide the convergence of physical medium parameters [S11].

### Gaussian Reduction with Learnable Mask
Reduces the number of Gaussians using a learnable mask during optimization, targeting small-sized kernels for removal [S12]. It applies binary masks to opacities and scales, combined with residual vector quantization for geometric attributes and a grid-based neural field for color, reducing model size while maintaining rendering quality [S12].

### 3DGS Visibility Pruning
Applies visibility-based pruning to 3D Gaussian Splatting, using Gaussian centroids as reference points for visibility calculation [S12]. It removes occluded kernels during the densification pipeline by computing a visibility mask based on projected centroids and camera viewpoints, reducing redundant Gaussians [S12].

## Operating characteristics

*   **Time Complexity**: The rasterization is $O(N \cdot P)$ where $N$ is the number of Gaussians and $P$ is the number of pixels, but optimized via spatial hashing and sorting to be effectively linear in practice for typical scenes. Training time is dominated by the backward pass through the rasterizer.
*   **Memory Complexity**: $O(N \cdot D)$ where $D$ is the number of SH coefficients. Standard 3DGS with degree 3 requires 48 floats per Gaussian for color. Compact methods reduce this to a shared grid [S8].
*   **Performance**: Half-precision rasterization reduces register pressure and improves throughput [S1]. SH degree 0 optimization yields ~16.5% faster training [S4, unofficial].
*   **Strengths**: Real-time rendering speeds, high visual fidelity, explicit scene representation.
*   **Limitations**: Large memory footprint for high-resolution scenes with many Gaussians. Sensitive to initialization and scene extent calculation [S3]. Struggles with transparent/specular surfaces without modifications (e.g., view-dependent opacity) [S10, unofficial].

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 as a real-time radiance field representation [S11, S12]. It uses explicit 3D Gaussians as primitives, optimized via differentiable rasterization. The method has since been extended with various training optimizations, such as half-precision kernels [S1], SH degree reduction [S4, unofficial], and scene extent corrections [S3]. Variants address specific challenges like defocus blur [S5], mesh extraction [S7], underwater rendering [S11], and sparse-view denoising [S9].
