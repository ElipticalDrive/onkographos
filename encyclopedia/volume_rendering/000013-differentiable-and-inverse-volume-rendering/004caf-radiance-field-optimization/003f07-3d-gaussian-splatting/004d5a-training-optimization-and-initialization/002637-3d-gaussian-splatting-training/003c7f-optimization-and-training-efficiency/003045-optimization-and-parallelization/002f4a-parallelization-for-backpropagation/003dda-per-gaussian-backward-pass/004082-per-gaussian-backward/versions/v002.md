# Per-Gaussian Backward

Also called: Bucket-based backward, Mallick et al. backward

## Overview
Per-Gaussian Backward is a backward pass optimization for 3D Gaussian Splatting that parallelizes gradient computation over Gaussians rather than pixels to reduce atomic contention [S1, unofficial]. It differs from standard pixel-parallel backpropagation by operating on fixed-size buckets of 32 Gaussians (one GPU warp), allowing threads to collaboratively replay the alpha blending process using warp-level primitives [S1, unofficial]. This approach significantly reduces warp stalls that occur when threads synchronize while loading alpha blending states from global memory [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Forward pass buffers storing intermediate color and transmittance after every 32nd Gaussian, the final number of contributing Gaussians per pixel, Gaussian attributes (position, covariance, opacity, color), and tile definitions [S1, unofficial].
*   **Outputs:** Gradients for Gaussian attributes written to global memory [S1, unofficial].

**Data Structures:**
1.  **Intermediate Buffers:** Allocated during the forward pass to store per-pixel state [S1, unofficial].
    *   `intermediate_color[tile_id][pixel]`: Accumulated color after every 32nd Gaussian.
    *   `intermediate_transmittance[tile_id][pixel]`: Accumulated transmittance after every 32nd Gaussian.
    *   `contributing_count[tile_id][pixel]`: Final number of contributing Gaussians per pixel.
    *   *Size:* Determined by the known lengths of the per-tile Gaussian lists [S1, unofficial].
2.  **Bucket:** A group of 32 Gaussians associated with a single tile [S1, unofficial].
3.  **Shared Memory Buffer:** Used by a warp (32 threads) to store alpha blending states (color/transmittance pairs) for the current bucket's pixels before they are needed [S1, unofficial].

**Numbered Steps:**
1.  **Forward Pass Buffer Population:** During the forward rendering pass, after processing every 32nd Gaussian in a tile's list, write the current accumulated color and transmittance for all pixels in that tile into the intermediate buffers [S1, unofficial]. Also, write the final count of contributing Gaussians per pixel [S1, unofficial].
2.  **Bucket Launch:** For each tile, launch a kernel block where each thread block (warp) handles one bucket of 32 Gaussians [S1, unofficial].
3.  **Thread Assignment:** In a warp of 32 threads, thread $i$ (where $i \in [0, 31]$) is responsible for computing the gradient contribution of the $i$-th Gaussian in the bucket across all pixels in the associated tile [S1, unofficial].
4.  **Shared Memory Pre-loading:** All 32 threads in the warp collaboratively load a batch of alpha blending states into shared memory (one per thread) before they are needed [S1, unofficial]. From that point on, the first thread in each warp reads the next state directly from shared memory instead of global memory [S1, unofficial].
5.  **Gradient Replay:** Starting from the initial color and transmittance values stored in the buffers (or loaded into shared memory), the warp replays the blending process using warp-level primitives to efficiently compute the necessary gradients [S1, unofficial].
6.  **Atomic Accumulation:** Each thread writes the accumulated gradients to global memory using atomics, as Gaussians can be inside multiple buckets across tiles [S1, unofficial].

**Pseudocode:**
```python
# Kernel: PerGaussianBackward
# Input: bucket_gaussians (list of 32 Gaussians), tile_id, intermediate_color, intermediate_transmittance, shared_mem, gradients_global
# Output: gradients_global (updated via atomics)

def PerGaussianBackward(bucket_gaussians, tile_id, intermediate_color, intermediate_transmittance, shared_mem, gradients_global):
    # Each thread i (0..31) handles the i-th Gaussian in the bucket
    thread_id = get_thread_id()  # [G] standard CUDA/OpenCL primitive
    gauss = bucket_gaussians[thread_id]
    pixel_indices = get_pixel_indices_for_gaussian(gauss, tile_id)  # [G] standard rasterization query

    # 1. Collaborative shared memory load
    # All 32 threads load initial blending states for their Gaussian's pixels
    for p in pixel_indices:
        shared_mem[thread_id][p] = (intermediate_color[tile_id][p], intermediate_transmittance[tile_id][p])
    sync_threads()  # [G] warp barrier to ensure all loads complete

    # 2. Gradient replay using warp-level primitives
    color_grad = 0.0
    trans_grad = 0.0
    for p in pixel_indices:
        # Retrieve state from shared memory
        c, t = shared_mem[thread_id][p]
        # Compute gradient contribution for this pixel using chain rule [G]
        # dL/dC = dL/dC_out * dC_out/dC, where dC_out/dC depends on alpha and previous transmittance
        dc = compute_alpha_blending_gradient(gauss, p, c, t)
        color_grad += dc

    # 3. Atomic accumulation to global memory
    # Gaussians may belong to multiple tiles/buckets, requiring atomics [G]
    gradients_global[gauss.id].position += gauss.position_grad
    gradients_global[gauss.id].covariance += gauss.covariance_grad
    gradients_global[gauss.id].opacity += gauss.opacity_grad
    gradients_global[gauss.id].color += color_grad
```

**Parameters:**
*   **Bucket Size:** 32 Gaussians (one warp) [S1, unofficial].
*   **Tile Size:** Typically 16x16 pixels (256 pixels per tile) [G].
*   **Shared Memory Usage:** 32 entries per warp, each entry containing color and transmittance for the relevant pixel range [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Warp Stalls:** If threads are synchronized while the first thread loads alpha blending state from global memory, the entire warp stalls. This is mitigated by collaborative loading into shared memory [S1, unofficial].
*   **Multiple Tile Membership:** A single Gaussian may contribute to multiple tiles. Therefore, gradient accumulation must use atomic operations in global memory [S1, unofficial].
*   **Buffer Size:** The intermediate buffers must be sized according to the maximum number of 32-Gaussian buckets in any tile. This is determined by the per-tile Gaussian list lengths [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of Gaussians, but with a significantly reduced constant factor due to warp-level parallelism and reduced global memory traffic [G].
*   **Memory Complexity:** Additional memory for intermediate buffers: $O(T \cdot B \cdot P)$ where $T$ is the number of tiles, $B$ is the average number of buckets per tile, and $P$ is the number of pixels per tile [G].
*   **Performance:** The shared memory optimization improves kernel runtime by up to 2x compared to the original Mallick et al. implementation [S1, unofficial].
*   **Strengths:** Reduces atomic contention by parallelizing over Gaussians; minimizes global memory latency through shared memory usage; efficient use of warp-level primitives [S1, unofficial].
*   **Limitations:** Requires additional memory for intermediate buffers; complex implementation due to warp-level synchronization and shared memory management; Gaussians spanning multiple tiles still require atomic writes [S1, unofficial].

## Background
Per-Gaussian Backward was proposed by Mallick et al. [56] as a key optimization for 3D Gaussian Splatting training. It was later analyzed and improved by the Faster-GS team, who introduced the shared memory optimization to reduce warp stalls [S1, unofficial]. The method is part of the broader effort to make differentiable volume rendering and radiance field optimization computationally efficient [S1, unofficial].
