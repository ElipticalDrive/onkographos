# Compact 3D Gaussian Representation (C3DGS)
## Overview
Compact 3D Gaussian Representation (C3DGS) is a method for reducing the storage footprint and rendering latency of 3D Gaussian Splatting (3DGS) by exploiting spatial redundancy in Gaussian attributes and pruning redundant primitives. It addresses the high memory cost of standard 3DGS, which stores full per-Gaussian attributes, by replacing per-Gaussian color storage with a hash-based neural field and quantizing geometric attributes (scale and rotation) using a codebook. Unlike its siblings, which rely on vector clustering or ASCII encoding, C3DGS uses continuous grid representations and discrete codebooks to achieve significant compression ratios while maintaining real-time rendering capabilities.
## How it works
**Inputs and Outputs:**
- Input: A set of 3D Gaussians $\{G_i\}$ optimized via standard 3DGS training, where each Gaussian $G_i$ has position $\mathbf{p}_i$, opacity $\alpha_i$, scale $\mathbf{s}_i$, rotation $\mathbf{q}_i$, and spherical harmonic (SH) coefficients $\mathbf{c}_i$.
- Output: A compressed scene representation consisting of a pruned Gaussian set, a hash grid for colors, and a codebook for geometry, enabling reconstruction of the scene with reduced storage and faster rendering.

**Data Structures:**
1.  **Pruned Gaussian Set:** A subset of original Gaussians identified by a learnable mask. Each retained Gaussian stores:
    -   Position $\mathbf{p}_i \in \mathbb{R}^3$
    -   Opacity $\alpha_i \in \mathbb{R}$
    -   Codebook Index $k_i \in \mathbb{Z}$ (for geometry)
    -   (Color is not stored per Gaussian; it is queried from the grid).
2.  **Hash Grid (Instant NGP):** A multi-resolution hash table mapping 3D coordinates to feature vectors. Used to store view-dependent color information.
3.  **Geometry Codebook:** A small lookup table containing representative scale and rotation vectors.

**Steps:**
1.  **Volume-Based Masking (Pruning):**
    -   During training, introduce a learnable mask $m_i \in \{0, 1\}$ for each Gaussian $G_i$.
    -   The mask is optimized to identify and remove non-essential Gaussians that have minimal impact on rendering performance.
    -   This reduces the total number of Gaussians $N$, directly lowering computational complexity which is linear in $N$.
2.  **Color Compression via Hash Grid:**
    -   Replace per-Gaussian SH coefficients $\mathbf{c}_i$ with a query to a hash-based neural field.
    -   For a Gaussian at position $\mathbf{p}_i$ and viewing direction $\mathbf{v}$, the color $\mathbf{C}$ is computed by:
        $$ \mathbf{C} = \text{HashGrid}(\mathbf{p}_i, \mathbf{v}) $$
    -   The hash grid uses the Instant NGP structure [S1] for compactness and fast processing. This exploits spatial redundancy where neighboring Gaussians share similar colors.
3.  **Geometry Compression via Codebook:**
    -   Observe that most Gaussians exhibit similar geometry with limited variation in scale and rotation.
    -   Train a codebook $\mathcal{K} = \{ (\mathbf{s}_k, \mathbf{q}_k) \}_{k=1}^K$ containing $K$ representative geometric patterns.
    -   For each Gaussian $G_i$, find the closest codebook entry $k_i$ such that:
        $$ k_i = \arg \min_{k} \| (\mathbf{s}_i, \mathbf{q}_i) - (\mathbf{s}_k, \mathbf{q}_k) \| $$
    -   Store only the index $k_i$ for each Gaussian. The actual scale and rotation are retrieved from the codebook during rendering.
4.  **Post-Processing (Optional):**
    -   Apply quantization and entropy coding to the codebook indices and hash grid features to achieve further compression.

**Parameters:**
-   **Grid Type:** Hash-based grid (Instant NGP) [S1].
-   **Codebook Size:** Small, to keep spatial and computational overhead low [S1]. Exact size not specified in sources.
-   **Masking Rate:** Determined by optimization; results in ~15x to 28x storage reduction [S1].

**Edge Cases and Pitfalls:**
-   **Sparse Regions:** The hash grid and codebook approach assumes spatial continuity. In very sparse regions, the grid may not provide sufficient detail, and codebook quantization may introduce visible artifacts if the codebook is too small [S1]. (Note: OMG addresses this by retaining per-Gaussian geometry in sparse settings [13978-optimized-minimal-3d-gaussian-splatting-omg.md]).
-   **Masking Convergence:** The learnable mask must be carefully regularized to prevent over-pruning, which would degrade reconstruction quality.
-   **Precision:** Hash grid queries and codebook lookups must maintain sufficient precision to avoid visual degradation.

## Subtopics

### [Optimized Minimal 3D Gaussian Splatting (OMG)](13978-optimized-minimal-3d-gaussian-splatting-omg.md)
OMG extends C3DGS by retaining per-Gaussian parameterization for geometry (scale and rotation) to handle sparsity, while using a small neural field and Sub-Vector Quantization (SVQ) for appearance features. It achieves >300× compression compared to 3DGS, addressing C3DGS's weakness in sparse settings where the grid and codebook may fail to capture local continuity.

## Operating characteristics
- **Storage Reduction:** Achieves approximately 15× reduced storage compared to standard 3DGS across various datasets [S1]. With post-processing (quantization and entropy coding), it achieves over 25× compression [S1]. On the Deep Blending dataset, it achieves over 28× enhancement in storage efficiency [S1].
- **Rendering Speed:** Nearly 40% increase in rendering speed on the Deep Blending dataset compared to 3DGS [S1]. General enhancement in rendering speed is observed across datasets due to the reduced number of Gaussians [S1].
- **Reconstruction Quality:** Outperforms 3DGS in reconstruction quality (PSNR) on the Deep Blending dataset [S1].
- **Complexity:** Computational complexity is linearly proportional to the number of Gaussians. By reducing the number of Gaussians via masking, C3DGS reduces this complexity [S1].
- **Strengths:** Significant storage and speed improvements without sacrificing visual fidelity; exploits spatial redundancy in color and geometry.
- **Limitations:** Performance may degrade in highly sparse regions where the hash grid and codebook cannot adequately represent local variations (addressed by OMG).
## Background
C3DGS was proposed to address the critical memory and storage issues in 3D Gaussian Splatting, which often requires >1GB for large real-world scenes [S1]. It builds on the observation that standard 3DGS densification produces redundant Gaussians and that neighboring Gaussians share similar attributes. The method uses Instant NGP for the hash grid [S1].
