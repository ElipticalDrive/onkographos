# SplatQ

Also called: SplatQ: Post-training Gaussian pruning via QUBO

## Overview
SplatQ is a post-training Gaussian pruning framework that partitions Gaussians by spatial proximity and appearance similarity into size-limited blocks, smooths importance-based block retention quotas to prevent budget concentration, and constructs a quadratic approximation of joint deletion effects to jointly select Gaussians under a fixed budget [S1, unofficial]. It differs from global Top-K methods by solving a combinatorial optimization problem within each block rather than ranking all Gaussians globally by independent scores, and it differs from methods that only consider individual deletion errors by modeling pairwise interactions and joint effects via a quadratic objective [S1, unofficial].

## How it works
**Inputs and outputs:**
*   **Input:** A pretrained 3D Gaussian Splatting model $G$ consisting of $N$ Gaussians, and a target retention count $K$ (where $K < N$).
*   **Output:** A pruned set of $K$ Gaussians with updated attributes.

**Data structures:**
The model is represented as a set of Gaussians $G = \{G_i\}_{i=1}^N$. Each Gaussian $G_i$ is parameterized by:
*   $\mu_i$: Center position.
*   $s_i$: Scale.
*   $r_i$: Rotation quaternion.
*   $c_i$: Zeroth-order (DC) spherical harmonic coefficients.
*   $h_i$: Higher-order spherical harmonic coefficients.
*   $o_i$: Opacity.

The algorithm partitions these $N$ Gaussians into blocks $\{C_b\}$. Each block $C_b$ contains at most $M$ members. For each block, a response matrix $R_b$ is computed.

**Parameters:**
*   $N$: Total number of Gaussians in the pretrained model.
*   $K$: Exact number of Gaussians to retain after pruning.
*   $M$: Maximum size (number of members) of each block $C_b$.
*   $K_b$: Retention quota assigned to block $b$, representing the number of Gaussians to retain within that block.
*   $R_b$: Response matrix for block $b$, used to estimate individual deletion effects and pairwise interactions.

**Steps:**

1.  **Partitioning:** Divide the $N$ Gaussians into several size-limited blocks $\{C_b\}$ of at most $M$ members each, based on spatial proximity and appearance similarity. This is typically achieved using a 3D grid and Morton ordering to efficiently group related Gaussians without quadratic pairwise comparison costs [S1, unofficial].
2.  **Opacity Response Modeling:** For each block $C_b$, compute a response matrix $R_b$ using sampled pixels from multiple views. This matrix estimates individual deletion effects and pairwise interactions by observing changes in rendered pixel colors relative to changes in Gaussian opacity [S1, unofficial].
3.  **Budget Allocation:** Assign a retention quota $K_b$ to every block such that $\sum_b K_b = K$. This is done by deriving an initial quota from importance estimates (derived from $R_b$) and adjusting the distribution to reduce the risk of concentrating the budget in a few blocks, thereby preventing spatial quality imbalance [S1, unofficial].
4.  **Quadratic Selection:** For each block, formulate a Quadratic Unconstrained Binary Optimization (QUBO) objective. The objective incorporates individual responses, pairwise interactions, and quota penalties. Solve the QUBO using Simulated Annealing (SA) or a Coherent Ising Machine (CIM) to determine which $K_b$ block members to retain [S1, unofficial].
5.  **Fine-tuning:** Fine-tune the attributes ($\mu, s, r, c, h, o$) of the retained Gaussians without changing their count to recover rendering quality [S1, unofficial].

**Edge cases and pitfalls:**
*   **Spatial Quality Imbalance:** Global ranking methods can lead to situations where the limited budget concentrates in regions with consistently higher scores, leaving other regions with insufficient representational capacity [S1, unofficial]. SplatQ addresses this via blockwise budget allocation.
*   **Joint Deletion Effects:** Independent scoring fails to capture joint rendering effects because multiple Gaussians may jointly support the same pixel or make overlapping contributions. Degradation from removing multiple Gaussians is not strictly additive [S1, unofficial]. SplatQ addresses this via the quadratic objective.
*   **Scalability:** Formulating the optimization problem over the entire model requires $N$ binary variables and an $N \times N$ matrix, which is impractical for millions of Gaussians. Partitioning into blocks of size $M$ reduces this complexity [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The partitioning step uses a 3D grid and Morton ordering to avoid quadratic pairwise comparisons, making it sub-quadratic or linear with respect to $N$ for grouping. The core computational bottleneck is the QUBO solving for each block. If there are $B$ blocks, and each has size $M$, the complexity is roughly $O(B \cdot T_{QUBO}(M))$, where $T_{QUBO}(M)$ is the time to solve a QUBO of size $M$. Since $M$ is small (size-limited blocks), this is significantly faster than solving a global QUBO of size $N$.
*   **Memory Complexity:** Requires storing the response matrices $R_b$ for each block. Each $R_b$ is of size $M \times M$. Total memory is $O(B \cdot M^2) = O(N \cdot M)$, which is much smaller than the $O(N^2)$ required for a global interaction matrix.
*   **Measured Performance:** The source notes that SplatQ preserves exact global retention count and evaluates quality differences across image patches, showing balanced reconstruction quality over global Top-K pruning [S1, unofficial]. Specific numerical metrics (PSNR, SSIM, LPIPS) are not provided in the abstract/excerpt.
*   **Strengths:** Ensures balanced reconstruction quality across the scene by controlling regional budget allocation. Captures joint deletion effects through pairwise interactions.
*   **Limitations:** Requires solving a combinatorial optimization problem (QUBO) for each block, which may be slower than simple scoring methods. Relies on the quality of the response matrix estimation.
*   **When to use:** When balanced quality across the entire scene is critical, and the scene contains regions with varying levels of detail or importance that might be neglected by global Top-K pruning.
*   **When not to use:** When computational resources for QUBO solving are extremely limited, or when a simple, fast pruning method is sufficient and spatial balance is not a concern.

## Background
SplatQ was proposed by Hongbin Ye, Haixu Liu, Shenwei Kang, Wenxiu Wei, Tinglan Wang, Hongdong Zhu, Fan Tang, Qi Gao, Yin Ma, Kai Wen, Hai Wei, Nuo Qian, Wei-Shi Zheng, Shaobo Chen, Fa-Ting Hong, and Jingke Meng. It was presented as an arXiv preprint (arXiv:2610.13503v1) on October 9, 2026, and was under review as a conference paper at ICLR 2027 [S1, unofficial]. It addresses limitations in existing 3D Gaussian Splatting pruning methods, which primarily rely on global Top-K selection based on independent importance scores, lacking regional budget control and ignoring joint deletion effects [S1, unofficial].
