# Vertex-level Pruning in Mixed-Primitive Gaussian Splatting

Also called: Mixed-Primitive Vertex Pruning

## Overview
Vertex-level pruning is a refinement mechanism for mixed-primitive Gaussian Splatting (MP-GS) that removes redundant vertices from Gaussian triangles and lines during training to reduce storage and simplify the representation [S1, unofficial]. Unlike standard 3D Gaussian Splatting which only performs primitive-level opacity culling, this method dynamically downgrades primitives to lower-dimensional forms (e.g., triangle to line, line to ellipse) based on geometric proximity and collinearity of their constituent vertices [S1, unofficial]. It complements the densification mechanisms of [Atomized Proliferation](12924-atomized-proliferation.md) by ensuring the representation remains compact without sacrificing surface fidelity [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A set of mixed-primitive Gaussians (ellipses, lines, triangles) with vertex positions $\mu_i$, covariances, opacities, and colors.
- **Output:** The same set with redundant vertices removed and primitives converted to simpler forms where appropriate.

**Data Structures:**
The method operates on the vertex coordinates $\mu$ of each primitive.
- **Gaussian Ellipse:** 1 vertex $\mu_1$.
- **Gaussian Line:** 2 vertices $\mu_1, \mu_2$.
- **Gaussian Triangle:** 3 vertices $\mu_1, \mu_2, \mu_3$.

**Parameters:**
- $\omega_{dist}$: Threshold for vertex proximity. Default: $0.5$ [S1, unofficial].
- $\omega_{pear}$: Threshold for collinearity. Default: $0.9$ [S1, unofficial].

**Algorithm:**
Vertex-level pruning is triggered concurrently with primitive-level pruning (opacity-based culling) [S1, unofficial]. The process evaluates each primitive based on its current vertex configuration:

1.  **Gaussian Triangle Pruning:**
    -   **Case A (Collapse to Ellipse):** Calculate the maximum pairwise L2 distance among the three vertices $\mu_1, \mu_2, \mu_3$. If $\max(\|\mu_i - \mu_j\|_2) < \omega_{dist}$, the vertices are considered "close." Prune $\mu_2$ and $\mu_3$, converting the primitive into a Gaussian ellipse centered at $\mu_1$ [S1, unofficial].
    -   **Case B (Collapse to Line):** If the vertices are not close (Case A fails), check for collinearity. Compute the Pearson correlation coefficient $r$ from the coordinates of the three vertices. If $|r| > \omega_{pear}$, the vertices are nearly collinear. Convert the Gaussian triangle into a Gaussian line [S1, unofficial].

2.  **Gaussian Line Pruning:**
    -   **Case C (Collapse to Ellipse):** Calculate the L2 distance between the two vertices $\mu_1$ and $\mu_2$. If $\|\mu_1 - \mu_2\|_2 < \omega_{dist}$, the vertices are considered "close." Prune $\mu_2$, reducing the primitive to a Gaussian ellipse centered at $\mu_1$ [S1, unofficial].

    """
    Prunes vertices from a mixed-primitive Gaussian based on geometry.
    
    Args:
        primitive: Object with type ('ellipse', 'line', 'triangle') 
                   and vertices list [mu1, mu2, mu3] (mu2, mu3 may be None).
        omega_dist: Distance threshold for proximity.
        omega_pear: Correlation threshold for collinearity.
        
    Returns:
        Updated primitive.
    """

            primitive.type = 'ellipse'
            primitive.vertices = [mu1]
            return primitive

        # However, strictly following "Pearson correlation coefficient":
        # We treat the x, y, z coordinates of the 3 points as samples.
        # But Pearson requires at least 2 variables.

        # Without explicit formula, we note the check. 
        # [G] Implementation note: For 3 points, collinearity is often checked via cross product magnitude.

        dist = l2_distance(mu1, mu2)

            primitive.vertices = [mu1]

def is_collinear(p1, p2, p3, threshold):
    """
    Checks if three points are collinear.
    Note: The source specifies Pearson correlation > threshold.
    [G] Since Pearson correlation is not directly defined for 3 3D points in the text,
    we use the standard geometric definition of collinearity (cross product of vectors).
    If the source meant correlation of coordinates, the logic would differ, but 
    geometric collinearity is the standard interpretation for "almost lie on the same line".
    """
    v1 = p2 - p1
    v2 = p3 - p1
    cross = np.cross(v1, v2)
    # Normalize by lengths to get sine of angle
    norm = np.linalg.norm(v1) * np.linalg.norm(v2)
    if norm == 0:
        return True
    sin_theta = np.linalg.norm(cross) / norm
    # If sin_theta is small, points are collinear.
    # Mapping to Pearson-like threshold: 
    # High correlation (close to 1) implies low angle.
    # We check if the deviation from collinearity is below a tolerance derived from threshold.
    # However, to strictly follow "Pearson > 0.9", we might need a specific metric.
    # Given the ambiguity, we return True if the points are geometrically collinear.
    return sin_theta < (1 - threshold) # Approximation

**Edge Cases and Pitfalls:**
-   **Precision:** Distance calculations must use consistent units with $\omega_{dist}$.
-   **Degenerate Input:** If vertices are identical, distance is 0, triggering collapse to ellipse.
-   **Collinearity Metric:** The source specifies Pearson correlation but does not define the vector space for the correlation. In practice, geometric collinearity checks (cross product) are used [G].

## Operating characteristics
-   **Storage Reduction:** The vertex pruning mechanism reduces the average storage size required to store vertex coordinates by 24% compared to the variant without pruning [S1, unofficial].
-   **Performance:** By converting triangles and lines to ellipses, the rendering pipeline processes fewer vertices per primitive, potentially improving rasterization speed [S1, unofficial].
-   **Limitations:** The method relies on heuristic thresholds ($\omega_{dist}, \omega_{pear}$) which may require tuning for different scene scales [S1, unofficial].

## Background
Vertex-level pruning was introduced in the context of Mixed-Primitive Gaussian Splatting (MP-GS) for surface reconstruction [S1, unofficial]. It addresses the inefficiency of retaining high-dimensional primitives (triangles/lines) in regions where lower-dimensional primitives (ellipses) suffice, refining the representation learned during training [S1, unofficial].
