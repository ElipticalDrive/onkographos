# Spherical Harmonics Vector Quantization

Also called: SH clustering, SH palette

## Overview
Spherical Harmonics Vector Quantization (SH VQ) is a compression technique for 3D Gaussian Splatting that replaces per-splat SH coefficients with indices pointing to a shared palette of distinct SH vectors, reducing memory footprint at the cost of minor lighting artifacts [S1, unofficial]. It sets itself apart from quantization methods like Norm11 or Norm565 by leveraging the redundancy in directional lighting across the scene, allowing for significantly higher compression ratios (e.g., 14.9x vs 5.1x for Norm11) while retaining specular "shininess" effects that scalar quantization often blurs [S1, unofficial].

## How it works
**Inputs and Outputs**
- **Input:** A set of $N$ 3D Gaussians, each with a spherical harmonic representation of degree $L=3$ (excluding the 0th order color term).
- **Output:** A palette of $K$ SH vectors and an index map of size $N$.

**Data Structures**
1.  **Palette:** An array of $K$ items. Each item is a vector of 45 floating-point numbers (15 per RGB channel, representing SH coefficients $c_{1,0}$ to $c_{3,3}$ for R, G, and B). Stored as FP16.
    -   Size: $K \times 45 \times 2$ bytes.
2.  **Index Map:** An array of $N$ integers. Each integer maps a splat to an index in the Palette.
    -   Size: $N \times 2$ bytes (16-bit index).

**Parameters**
-   **Palette Size ($K$):** Typically 4,000 to 16,000 distinct SH items [S1, unofficial].
-   **SH Dimensionality:** 45 floats per splat (excluding the 0th-order coefficient, which is stored separately as color) [S1, unofficial].
-   **Index Width:** 16 bits per splat, regardless of whether $K < 65,536$ [S1, unofficial].

**Algorithm Steps**
1.  **Extract SH Data:** Collect the 45-dimensional SH coefficient vectors for all $N$ splats.
2.  **Cluster:** Perform vector quantization (clustering) on the $N$ vectors to find $K$ representative centroids (the palette).
    -   The source uses a custom mini-batch k-means implementation [S1, unofficial].
    -   Standard libraries like scikit-learn are too slow; Faiss is faster but introduces dependencies [S1, unofficial].
3.  **Assign Indices:** For each splat $i$, find the palette index $j$ such that the Euclidean distance between the splat's SH vector $v_i$ and the palette vector $p_j$ is minimized:
    $$ j = \arg \min_{k \in \{0, \dots, K-1\}} \| v_i - p_k \|_2 $$
4.  **Store:** Save the Palette and the resulting Index Map.

**Pseudocode**
```python
import numpy as np

def spherical_harmonics_vector_quantization(sh_data: np.ndarray, k: int) -> tuple:
    """
    Compress SH data using vector quantization.
    
    Args:
        sh_data: (N, 45) array of SH coefficients for N splats.
                 Each row is [R_coeffs, G_coeffs, B_coeffs].
        k: Number of palette entries (e.g., 4000 or 16000).
        
    Returns:
        palette: (K, 45) array of centroid SH vectors.
        indices: (N,) array of 16-bit indices into the palette.
    """
    n = sh_data.shape[0]
    
    # Step 1: Initialize centroids using K-Means++ initialization
    # [G] Standard K-Means++ initialization to pick initial centroids
    centroids = kmeans_plus_plus_init(sh_data, k)
    
    # Step 2: Mini-batch K-Means Clustering
    # [G] Custom mini-batch implementation preferred for speed and no dependencies
    # Iterate until convergence or max iterations
    for iteration in range(100):
        # Sample a mini-batch of data points
        batch_indices = np.random.choice(n, size=256, replace=False)
        batch = sh_data[batch_indices]
        
        # Assign batch points to nearest centroid
        distances = np.linalg.norm(batch[:, np.newaxis, :] - centroids[np.newaxis, :, :], axis=2)
        assignments = np.argmin(distances, axis=1)
        
        # Update centroids based on batch assignments
        for j in range(k):
            members = batch[assignments == j]
            if len(members) > 0:
                centroids[j] = centroids[j] * 0.9 + np.mean(members, axis=0) * 0.1
                # [G] Re-normalization or projection not specified in source, 
                # assuming raw coefficient update as per "mini-batch k-means" description
        
    # Step 3: Final Assignment
    # Calculate distance from all points to all centroids
    # [G] Using efficient matrix operations for final assignment
    distances = np.linalg.norm(sh_data[:, np.newaxis, :] - centroids[np.newaxis, :, :], axis=2)
    indices = np.argmin(distances, axis=1).astype(np.uint16)
    
    return centroids, indices

def kmeans_plus_plus_init(data: np.ndarray, k: int) -> np.ndarray:
    """Initialize centroids using K-Means++."""
    n = data.shape[0]
    centroids = np.empty((k, data.shape[1]))
    
    # Pick first centroid randomly
    idx = np.random.randint(n)
    centroids[0] = data[idx]
    
    for i in range(1, k):
        # Calculate squared distances to nearest existing centroid
        dists = np.min(np.sum((data[:, np.newaxis, :] - centroids[:i, np.newaxis, :, :]) ** 2, axis=2), axis=1)
        # Pick next centroid with probability proportional to distance squared
        probs = dists / np.sum(dists)
        cumprobs = np.cumsum(probs)
        r = np.random.rand()
        idx = np.searchsorted(cumprobs, r)
        centroids[i] = data[idx]
        
    return centroids
```

**Edge Cases and Pitfalls**
-   **Curse of Dimensionality:** Clustering millions of splats in 45 dimensions is computationally expensive and slow [S1, unofficial].
-   **Lighting Artifacts:** The method introduces minor lighting artifacts, particularly in specular highlights, though "shininess" is generally retained [S1, unofficial].
-   **Dependency Management:** External libraries like Faiss provide speed but add dependencies; custom implementations are preferred for standalone distribution [S1, unofficial].

## Operating characteristics
-   **Memory Footprint:**
    -   Palette: $K \times 45 \times 2$ bytes. For $K=16,000$, this is ~1.44 MB [S1, unofficial].
    -   Indices: $N \times 2$ bytes. For $N=6.1$ million splats (e.g., 'bike' scene), this is ~12 MB [S1, unofficial].
    -   Total SH storage: ~13.44 MB for the 'bike' scene with 16k palette [S1, unofficial].
-   **Compression Ratio:**
    -   'Low' preset (16k palette): ~14.9x compression compared to raw uncompressed data [S1, unofficial].
    -   'Very Low' preset (4k palette): ~18.4x compression [S1, unofficial].
-   **Quality (PSNR):**
    -   'Bike' scene, 'Low' (16k): PSNR 35.17, 35.32, 35.00 across different metrics/views [S1, unofficial].
    -   'Bike' scene, 'Very Low' (4k): PSNR 32.27, 30.19, 31.10 [S1, unofficial].
-   **Performance:**
    -   Clustering time: Custom mini-batch k-means is ~3x faster than Faiss and significantly faster than scikit-learn [S1, unofficial].
    -   Rendering: No change to rendering pipeline complexity; requires one texture lookup (palette) per splat instead of 45 floats.
-   **Strengths:**
    -   Drastically reduces memory usage for SH data, which constitutes the majority of Gaussian Splatting memory [S1, unofficial].
    -   Retains specular highlights better than scalar quantization (Norm11/Norm565) [S1, unofficial].
-   **Limitations:**
    -   Introduces visible lighting artifacts if $K$ is too small [S1, unofficial].
    -   Clustering is slow for very large scenes without optimized implementations [S1, unofficial].

## Background
Spherical Harmonics Vector Quantization was introduced by Aras Pranckevičius in a blog post titled "Making Gaussian Splats more smaller" on September 27, 2023 [S1, unofficial]. It was developed as part of a Unity-based Gaussian Splatting implementation to enable real-time rendering of large scenes on consumer hardware by reducing the memory footprint of SH coefficients. The technique draws inspiration from traditional computer graphics palette-based rendering, where colors are stored in a lookup table and pixels store indices [S1, unofficial].
