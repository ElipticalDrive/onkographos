# 3D Gaussian Particle Approximation of VDB Datasets

Also called: Gaussian Particle Approximation, Gaussian Particle Rendering, VDB to Gaussian Conversion

## Overview
This method converts OpenVDB volumetric datasets into a set of non-overlapping 3D Gaussian particles to enable memory-efficient, lossy representation with Level of Detail (LOD) support, rendered via forward ray marching using NVIDIA OptiX [S1, unofficial]. It differs from standard 3D Gaussian Splatting by treating Gaussians as volumetric particles representing local opacity distributions rather than surface splats, and by deriving primitives directly from VDB leaf nodes rather than optimizing from images [S1, unofficial]. Unlike [Inverse Multiquadric Splatting](9910-inverse-multiquadric-splatting.md) which modifies the basis function, this method retains the standard Gaussian density function but constrains the geometry to non-overlapping voxel regions [S1, unofficial].

## How it works

### Inputs and Outputs
*   **Input:** An OpenVDB grid (scalar field or level set).
*   **Output:** A set of 3D Gaussian primitives (position, covariance, opacity) and an OptiX acceleration structure for rendering.
*   **Rendering Output:** A 2D image with color and opacity accumulated via ray marching.

### Data Structures

**Gaussian Model (Device Side)**
A contiguous array structure holding properties for all Gaussians. Each Gaussian $i$ stores:
*   `position` ($\mu_i$): 3D vector (world space).
*   `covariance` ($\Sigma_i$):
    *   For spheres: 1 scalar (radius/scale).
    *   For ellipsoids: 3 scalars (diagonal elements of the covariance matrix, axis-aligned).
*   `opacity` ($\alpha_i$ or $\sigma_i$): Scalar value. For level sets, this may be uniform and not stored per-particle if handled by shader logic [S1, unofficial].

**Acceleration Structures**
*   **GAS (Geometry Acceleration Structure):** Built on the GPU using a CUDA device-side array of Axis-Aligned Bounding Boxes (AABBs). Each AABB encloses a single Gaussian particle, defined by its minimum and maximum coordinates in OpenVDB Index Space.
    *   Build Flags: `OPTIX_BUILD_FLAG_ALLOW_COMPACTION`, `OPTIX_BUILD_INPUT_TYPE_CUSTOM_PRIMITIVES` [S1, unofficial].
*   **IAS (Instance Acceleration Structure):** Stores the GAS instance with the OpenVDB Grid transform. Sets visibility masks for all Gaussians to visible for primary and continuation rays [S1, unofficial].

**HitGroupRecord**
A structure initialized for Gaussian particles rendering specifying the shaders associated with the Gaussian primitive. It contains a pointer to the `GaussianModel` object [S1, unofficial].

### Numbered Steps

#### 1. Data Generation (CPU)
1.  Retrieve all leaf nodes from the OpenVDB Grid Tree using the OpenVDB API [S1, unofficial].
2.  For each leaf node (or cluster based on LOD), derive Gaussian properties:
    *   **Position:** Center in world space, derived from the centroid of the voxel region or its bounding box [S1, unofficial].
    *   **Opacity:** Density value reflecting the average scalar value of the voxel region to preserve local material characteristics [S1, unofficial].
    *   **Covariance:** Diagonal vector of the 3x3 covariance matrix (axis-aligned) or a single scalar for isotropic spheres [S1, unofficial].
3.  Copy all Gaussian properties (opacity, world position, covariance) to contiguous device-side buffers using `cudaMalloc` and `cudaMemcpy` [S1, unofficial].

#### 2. Acceleration Structure Build (GPU)
1.  Build the GAS using the device-side array of AABBs. Each AABB encloses a single Gaussian particle [S1, unofficial].
2.  Create the IAS storing the GAS instance with the OpenVDB Grid transform [S1, unofficial].
3.  Add the `GaussianModel` (containing device pointers to the buffers) to the OptiX Shader Binding Table (SBT) [S1, unofficial].

#### 3. Ray Tracing and Rendering (GPU)
The renderer uses a recursive forward-ray-marching approach with `RAY_TYPE_RADIANCE` [S1, unofficial].

1.  **Ray Generation:** Shoot primary rays from the camera using the `__raygen__` program [S1, unofficial].
2.  **World Intersection:** Intersect the ray with the world AABB. If no intersection, return background color [S1, unofficial].
3.  **Gaussian Iteration:** For each Gaussian in the intersected AABB:
    a.  **Gaussian Intersection:** In the `__intersection__` program, retrieve the Gaussian's AABB. Perform ray-box intersection. If intersected, retrieve center $\mu$ and inverse covariance $\Sigma^{-1}$. Transform the ray into the Gaussian's local space. Solve the quadratic equation to find entry ($t_0$) and exit ($t_1$) distances. Store $t_0, t_1$ in the payload and exit early [S1, unofficial].
    b.  **Ray Marching:** Step along the ray from $t_0$ to $t_1$ using a predefined step size $\Delta t$ (distance between entry and exit points, or a fixed fraction thereof) [S1, unofficial].
    c.  **Density Evaluation:** For each sample point $x_k$:
        *   Compute difference $\delta = x_k - \mu$.
        *   Compute squared Mahalanobis distance $D^2 = \delta^\top \Sigma^{-1} \delta$.
        *   Evaluate density $\rho_k = \exp(-D^2 / 2)$ [S1, unofficial].
    d.  **Absorption Calculation:**
        *   Compute volume factor $V_f = 1 / \det(\Sigma)$.
        *   Compute absorption $A_k = \rho_k \cdot \Delta t \cdot V_f$ [S1, unofficial].
    e.  **Radiance Accumulation:**
        *   Update color: $C \leftarrow C + T_k \cdot c(\sigma_k) \cdot A_k$.
        *   Update transmittance: $T_{k+1} \leftarrow T_k \cdot \exp(-A_k)$.
        *   Where $c(\sigma_k)$ is the scattering color derived from opacity $\sigma_k$ via a transfer function (colormap lookup) [S1, unofficial].
    f.  **Break:** Exit the Gaussian loop after processing the first intersecting Gaussian (non-overlapping constraint) [S1, unofficial].
4.  **Ray Continuation:** Advance ray origin: $o_{new} = o + d \cdot (t_1 - t_0)$ [S1, unofficial].
5.  **Recursion:** Call `optixTrace(payload)` with `RAY_TYPE_RADIANCE`. Increment recursion depth. If depth > max_depth (e.g., 10) or transmittance is negligible, stop [S1, unofficial].
6.  **Final Color:** $C_{final} = C + T_{final} \cdot \text{payload.result}$ [S1, unofficial].

### Pseudocode

```python
# Data Generation (CPU)
def generate_gaussians_from_vdb(vdb_grid):
    gaussians = []
    # Retrieve leaf nodes based on LOD strategy
    leaf_nodes = vdb_grid.get_leaf_nodes()
    
    for node in leaf_nodes:
        if node.is_tiled():
            continue # Skip tiled nodes as they are handled by parent value masks
        
        # Derive properties
        position = node.get_centroid_world_space()
        opacity = node.get_average_scalar_value()
        
        # Covariance: Diagonal vector for axis-aligned ellipsoid or scalar for sphere
        # Using ellipsoid for better fit to voxel distribution
        covariance_diag = node.get_voxel_dimensions_world_space() 
        
        gaussians.append({
            'position': position,
            'opacity': opacity,
            'covariance_diag': covariance_diag
        })
        
    # Transfer to GPU
    device_buffers = cuda_allocate_contiguous_buffers(gaussians)
    return device_buffers

# Ray Tracing (GPU Kernel / OptiX Programs)

def raygen_program():
    ray = create_camera_ray()
    payload = {
        'color': vec3(0.0),
        'transmittance': 1.0,
        'recursion_depth': 0
    }
    result = recursive_ray_march(ray, payload, max_depth=10)
    set_pixel_color(result['color'])

def recursive_ray_march(ray, payload, max_depth):
    if payload['recursion_depth'] >= max_depth:
        return payload['color']
        
    # Intersect with World AABB
    if not intersect_world_aabb(ray):
        return payload['color'] # Return background or accumulated color
        
    # Intersect with Gaussians in the current node
    # Note: In this non-overlapping model, we typically process one Gaussian per ray segment
    # or iterate through the BVH nodes.
    
    hit_found = False
    t0, t1 = 0.0, 0.0
    
    # Find closest Gaussian intersection
    gaussian = find_closest_gaussian_intersection(ray)
    
    if gaussian:
        hit_found = true
        t0, t1 = gaussian.entry_exit_times
        
        # March within the Gaussian
        step_size = (t1 - t0) / num_samples # Or fixed step
        current_t = t0
        
        while current_t < t1:
            sample_point = ray.origin + ray.direction * current_t
            
            # Density Evaluation
            delta = sample_point - gaussian.position
            inv_cov = inverse(gaussian.covariance_matrix)
            d_squared = dot(delta, mul(inv_cov, delta))
            density = exp(-0.5 * d_squared)
            
            # Absorption
            vol_factor = 1.0 / determinant(gaussian.covariance_matrix)
            absorption = density * step_size * vol_factor
            
            # Accumulation
            scattering_color = get_color_from_transfer_function(gaussian.opacity)
            payload['color'] += payload['transmittance'] * scattering_color * absorption
            payload['transmittance'] *= exp(-absorption)
            
            current_t += step_size
            
        # Advance ray
        ray.origin = ray.origin + ray.direction * (t1 - t0)
        payload['recursion_depth'] += 1
        
        # Recursive trace for next segment
        next_payload = recursive_ray_march(ray, payload, max_depth)
        return next_payload
    else:
        return payload['color']

def intersection_program():
    primitive_id = get_primitive_index()
    gaussian = get_gaussian_from_buffer(primitive_id)
    
    # Ray-AABB intersection
    if ray_intersects_aabb(ray, gaussian.aabb):
        # Solve quadratic for ray-ellipsoid intersection
        t0, t1 = solve_ray_ellipsoid_intersection(ray, gaussian.position, gaussian.covariance_matrix)
        set_payload_entry_exit(t0, t1)
        hit()
```

### Parameters
*   **Grid Layout:** The '5-4-3' variant is used (Top-level: $2^5 \times 2^5 \times 2^5$, Intermediate: $2^4 \times 2^4 \times 2^4$, Leaf: $2^3 \times 2^3 \times 2^3$) [S1, unofficial].
*   **LOD Modes:**
    *   **Low:** 1 Gaussian per leaf node [S1, unofficial].
    *   **Medium:** Dense leaves merged into $4 \times 4 \times 4$ groups; sparse into $2 \times 2 \times 2$ [S1, unofficial].
    *   **High:** Sparse leaves = 1 Gaussian per active voxel; dense leaves merged into $2 \times 2 \times 2$ blocks [S1, unofficial].
*   **Ray Type:** `RAY_TYPE_RADIANCE` (forward marching only, no shadows/scattering) [S1, unofficial].

### Edge Cases and Pitfalls
*   **Non-overlapping Constraint:** The implementation assumes non-overlapping Gaussians because OpenVDB leaf nodes are strictly non-overlapping. This limits the model to three overarching refinement levels and introduces lossiness [S1, unofficial].
*   **NanoVDB Incompatibility:** NanoVDB does not support device-side traversal of the Grid Tree or device-side iterators/accessors, creating a bottleneck for random access required in ray-BVH or ray-particle intersections. Therefore, NanoVDB cannot be used for 3D Gaussian generation or rendering in this pipeline; OpenVDB must be used for generation [S1, unofficial].
*   **OptiX Register Constraint:** Propagating state via recursive `optixTrace` calls is limited by OptiX’s 8-payload register constraint, causing sub-optimal accumulation and inconsistent resetting of payload values [S1, unofficial].
*   **Transfer Functions:** Unlike other Gaussian splatting implementations that bake color into Gaussians, this renderer does not, supporting transfer functions similar to traditional volume rendering via colormap lookups [S1, unofficial].

## Operating characteristics

*   **Time Complexity:** Rendering performance is consistently above 150 FPS for tested datasets (bunny_cloud, explosion, fire, utahteapot, venusstatue, dragon) across all LODs, even with millions of Gaussians [S1, unofficial].
*   **Memory Complexity:** Memory footprint scales with the number of Gaussians.
    *   Example (Dragon Dataset):
        *   High LOD: 546 MB, 23.3M Gaussians [S1, unofficial].
        *   Low LOD: 174.4 MB, 7.4M Gaussians [S1, unofficial].
*   **Strengths:**
    *   Real-time performance on modern GPUs via OptiX hardware acceleration [S1, unofficial].
    *   Memory efficiency through sparse VDB representation and LOD [S1, unofficial].
    *   Support for transfer functions (colormap lookups) [S1, unofficial].
*   **Limitations:**
    *   Lossy representation due to non-overlapping constraint and LOD merging [S1, unofficial].
    *   Inability to use NanoVDB for generation due to lack of device-side iterators [S1, unofficial].
    *   Recursive ray tracing limitations due to OptiX register constraints [S1, unofficial].
*   **When to use:** Scientific visualization (SciVis) applications requiring real-time rendering of large volumetric datasets with LOD support.
*   **When not to use:** Photorealistic rendering requiring overlapping Gaussian mixtures or shadow rays, or when NanoVDB is the only available VDB format [S1, unofficial].

## Background

*   **Origin:** This method was presented in a study for Scientific Visualization, exploring the integration of OpenVDB and NVIDIA OptiX to leverage memory compaction and hardware acceleration [S1, unofficial].
*   **History:** It builds on the popularity of 3D Gaussian approximation in stereoscopic image to 3D scene conversion (Gaussian Splatting) [12] and earlier Gaussian mixture models in SciVis [11]. The work specifically addresses the gap in rendering VDB data efficiently using modern ray tracing hardware [S1, unofficial].
*   **Usage:** Used in NVIDIA OptiX-based rendering engines for forward ray marching through Gaussian particles [S1, unofficial].
