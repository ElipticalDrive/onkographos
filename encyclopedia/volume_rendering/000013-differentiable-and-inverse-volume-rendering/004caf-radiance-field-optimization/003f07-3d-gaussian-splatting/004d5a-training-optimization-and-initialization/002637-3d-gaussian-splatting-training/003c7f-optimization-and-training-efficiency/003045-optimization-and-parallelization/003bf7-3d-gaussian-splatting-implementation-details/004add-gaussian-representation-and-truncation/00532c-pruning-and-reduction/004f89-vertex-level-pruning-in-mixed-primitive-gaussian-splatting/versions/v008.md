# Vertex-level Pruning in Mixed-Primitive Gaussian Splatting

Also called: Mixed-Primitive Vertex Pruning

## Overview
Vertex-level pruning is a refinement mechanism for mixed-primitive Gaussian Splatting that removes redundant vertices from Gaussian triangles and lines during training to reduce storage overhead and representation complexity [S1, unofficial]. Unlike standard 3D Gaussian Splatting which only performs primitive-level opacity pruning, this method dynamically downgrades primitives to simpler forms (ellipses or lines) when their vertex configurations become degenerate, complementing the densification operations that maintain surface detail [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** The current set of mixed-primitive splats (Gaussian triangles, Gaussian lines, and Gaussian ellipses) with their vertex positions $\mu_i$, covariances, opacities, and colors.
*   **Output:** A pruned set of primitives where unnecessary vertices have been removed or merged, converting triangles to lines/ellipses or lines to ellipses as appropriate.

**Data Structures:**
Each primitive maintains references to its vertices.
*   **Gaussian Triangle:** Defined by three vertices $\mu_1, \mu_2, \mu_3$.
*   **Gaussian Line:** Defined by two vertices $\mu_1, \mu_2$.
*   **Gaussian Ellipse:** Defined by a single center vertex $\mu_1$ (and associated covariance).

**Parameters:**
*   $\omega_{dist}$: Threshold for vertex proximity. Default: $0.5$ [S1, unofficial].
*   $\omega_{pear}$: Threshold for collinearity. Default: $0.9$ [S1, unofficial].

**Algorithm Steps:**
Vertex-level pruning is triggered simultaneously with primitive-level pruning (e.g., when opacity is low) [S1, unofficial]. The process evaluates the geometric configuration of each primitive:

1.  **Gaussian Triangle to Ellipse:** If the three vertices $\mu_1, \mu_2, \mu_3$ are "close" to each other, prune $\mu_2$ and $\mu_3$. Convert the primitive into a Gaussian ellipse centered at $\mu_1$ [S1, unofficial].
2.  **Gaussian Triangle to Line:** If the vertices are not close but are "nearly collinear," convert the Gaussian triangle into a Gaussian line [S1, unofficial].
3.  **Gaussian Line to Ellipse:** If the two vertices $\mu_1, \mu_2$ of a Gaussian line are "close," prune $\mu_2$. Reduce the primitive to a Gaussian ellipse centered at $\mu_1$ [S1, unofficial].

**Definitions and Formulas:**
*   **Proximity:** A set of vertices is considered "close" if their maximum pairwise L2 distance is below $\omega_{dist}$ [S1, unofficial].
    $$ \max_{i,j} \| \mu_i - \mu_j \|_2 < \omega_{dist} $$
*   **Collinearity:** For a Gaussian triangle with vertices $\mu_1, \mu_2, \mu_3$, they are nearly collinear if the absolute value of the Pearson correlation coefficient computed from the vertices exceeds $\omega_{pear}$ [S1, unofficial].

**Pseudocode:**
```python
def vertex_level_pruning(primitive, omega_dist=0.5, omega_pear=0.9):
    """
    Prunes vertices from a mixed-primitive Gaussian Splatting primitive.
    
    Args:
        primitive: Object with type ('triangle', 'line', 'ellipse') and vertices (list of vectors).
        omega_dist: Distance threshold for proximity.
        omega_pear: Correlation threshold for collinearity.
        
    Returns:
        primitive: The potentially modified primitive.
    """
    if primitive.type == 'triangle':
        mu1, mu2, mu3 = primitive.vertices
        
        # Check if vertices are close
        d12 = l2_distance(mu1, mu2)
        d23 = l2_distance(mu2, mu3)
        d13 = l2_distance(mu1, mu3)
        max_dist = max(d12, d23, d13)
        
        if max_dist < omega_dist:
            # Case 1: All vertices close -> Convert to ellipse at mu1
            primitive.type = 'ellipse'
            primitive.vertices = [mu1]
            # Note: Covariance and other attributes must be preserved/adjusted for the ellipse
            return primitive
            
        # Check if vertices are nearly collinear
        # Pearson correlation is computed from the coordinates of the three vertices
        # Let X be the matrix of vertex coordinates [mu1, mu2, mu3]
        # Compute Pearson correlation coefficient r
        r = pearson_correlation([mu1, mu2, mu3])
        
        if abs(r) > omega_pear:
            # Case 2: Not close, but collinear -> Convert to line
            primitive.type = 'line'
            # Keep mu1 and mu2 as the line endpoints (or re-center if needed)
            # The source specifies converting to a Gaussian line, implying retaining two vertices
            primitive.vertices = [mu1, mu2] 
            return primitive
            
    elif primitive.type == 'line':
        mu1, mu2 = primitive.vertices
        
        # Check if vertices are close
        if l2_distance(mu1, mu2) < omega_dist:
            # Case 3: Line vertices close -> Convert to ellipse at mu1
            primitive.type = 'ellipse'
            primitive.vertices = [mu1]
            return primitive
            
    return primitive

def l2_distance(v1, v2):
    return sqrt(sum((a-b)**2 for a, b in zip(v1, v2)))

def pearson_correlation(vertices):
    """
    Computes the absolute Pearson correlation coefficient for a set of 3D vertices.
    This is a simplified representation of the source's requirement.
    In practice, this likely involves flattening coordinates or computing correlation
    along specific axes/dimensions. The source cites 'Pearson correlation coefficient 
    computed from these vertices'.
    """
    # Standard implementation for a set of points to check linear dependency
    # Often implemented by checking correlation between x, y, z coordinates 
    # or by projecting onto principal components.
    # Given the ambiguity in the source, we assume a standard multivariate correlation metric.
    # A common proxy for collinearity in this context is the correlation of coordinates.
    import numpy as np
    coords = np.array(vertices) # Shape (3, 3)
    # Compute correlation matrix
    corr_matrix = np.corrcoef(coords.T)
    # The source says "absolute value of the Pearson correlation coefficient".
    # This might refer to the maximum off-diagonal element or a specific scalar metric.
    # Without explicit formula, we assume the max absolute correlation between any pair of dimensions.
    return np.max(np.abs(corr_matrix))
```

**Edge Cases and Pitfalls:**
*   **Precision:** The collinearity check relies on Pearson correlation, which can be sensitive to the scale and distribution of vertex coordinates. Ensure coordinates are normalized or consistent in scale before computing [S1, unofficial].
*   **Degenerate Input:** If a triangle collapses to a point, the proximity check handles it. If a line collapses to a point, the proximity check handles it. The algorithm ensures no primitive ends up with fewer than one vertex (ellipse).
*   **Interaction with Densification:** Pruning does not reduce the representation to only ellipses because densification (cloning/splitting) is integrated alongside pruning, allowing triangles and lines to be regenerated where needed [S1, unofficial].

## Operating characteristics
*   **Storage Reduction:** The vertex pruning mechanism reduces the average storage size required to store vertex coordinates by 24% compared to the variant without pruning [S1, unofficial].
*   **Performance:** The pruning step is lightweight, involving distance and correlation calculations per primitive during the training loop. It is triggered alongside primitive-level pruning, adding minimal overhead.
*   **Strengths:** Refines the representation by eliminating unnecessary vertices, leading to "less messy" Gaussian Splatting representations and better surface reconstruction metrics (e.g., lower Chamfer distance) [S1, unofficial].
*   **Limitations:** Relies on heuristic thresholds ($\omega_{dist}, \omega_{pear}$) which may need tuning for different scenes. The collinearity metric (Pearson correlation) is a simplification and may not capture all geometric degeneracies perfectly.

## Background
Vertex-level pruning was introduced in the context of Mixed-Primitive Gaussian Splatting (MP-GS) for surface reconstruction [S1, unofficial]. It addresses the limitation of original Gaussian Splatting, which uses only point-centered primitives and performs only primitive-level pruning. By supporting primitives with varying numbers of vertices (triangles, lines), MP-GS requires a mechanism to handle vertex redundancy during learning [S1, unofficial].
