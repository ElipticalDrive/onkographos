# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization strategies, and variant methodologies required to train and render 3D Gaussian Splatting (3DGS) scenes effectively. It addresses the core differentiable rasterization pipeline, including half-precision memory management, loss scaling, and specific hyperparameter configurations for optimizers and scene extents. It also catalogs specialized variants that modify the Gaussian representation, such as view-dependent opacity, compact color fields, and underwater scattering models, to handle specific visual phenomena and hardware constraints.

## How it works

### Standard Training Configuration
The standard training pipeline relies on the `gsplat` library [S2] and typically employs the Adam optimizer with a learning rate of $1 \times 10^{-3}$ [S2]. The Spherical Harmonics (SH) degree is commonly set to 1 for simplicity and efficiency, though higher degrees are used for fidelity [S2]. During training, the system randomly selects a single image from a random scene as supervision for each iteration [S2]. To ensure stability in half-precision training, an automatic scaling factor is applied to loss values [S1].

### Half-Precision Rasterization
To reduce register pressure and memory bandwidth usage, the forward and backward CUDA kernels utilize half-precision (FP16) memory fetches for feature vectors during rasterization [S1]. The neural network components, such as those used for view-dependent color or auxiliary MLPs, are implemented using tiny-cuda-nn's JIT-compiled cooperative vector MLPs, trained and evaluated in FP16 [S1].

### Scene Extent Calculation
The default 3DGS implementation calculates scene extent $e_{\text{scene}}$ based on camera positions:
$$e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2$$
where $\bar{C}$ is the average camera position [S3]. This can introduce bias if cameras are clustered (e.g., orbiting a small object in a large environment), leading to incorrect Gaussian splitting or pruning [S3]. A corrected scene extent $e'_{\text{scene}}$ can be calculated using the Structure-from-Motion (SfM) point cloud:
$$e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$$
where $N_{\text{SfM}}$ is the number of SfM points and $p_i$ is the $i$-th SfM point [S3].

### Underwater Rendering and Backscatter
For underwater scenes, the rendering equation incorporates direct attenuation ($B_d$), infinite backscatter ($B_\infty$), and backscatter coefficient ($B_b$) [S8]. The color $C^{uw}$ is computed as:
$$C^{uw} = \sum_{i=1}^M c_i \alpha_i T_i e^{-B_d z} + B_\infty (1 - e^{-B_b z})$$
where $T_i = \prod_{j=0}^{i-1} (1 - \alpha_j)$ and $z$ is the depth [S8]. Backscatter parameters are re-estimated every 500 optimization steps using nonlinear least squares fitting on depth clusters [S8]. The camera sensor must have a linear response; gamma-corrected images cannot be used directly [S8]. Depth $z$ is extracted from the 3DGS scene estimate using:
$$z = \frac{\sum_{i=1}^M d_i \alpha_i T_i}{\sum_{i=1}^M \alpha_i T_i}$$
where $d_i$ is the depth of Gaussian $i$ [S8].

### Gaussian Reduction and Pruning
Gaussian reduction can be achieved using a learnable mask $M$ applied to opacities and scales during densification steps [S9]. The masked scale $\hat{s}_n$ and opacity $\hat{o}_n$ are formulated as:
$$M_n = \text{sg}(\mathbb{1}[\sigma(m_n) > \epsilon] - \sigma(m_n)) + \sigma(m_n)$$
$$\hat{s}_n = M_n s_n, \quad \hat{o}_n = M_n o_n$$
where $\epsilon$ is the masking threshold, $\text{sg}(\cdot)$ is the stop-gradient operator, $\mathbb{1}$ is the indicator function, and $\sigma(\cdot)$ is the sigmoid function [S9]. The total loss includes a masking loss $L_m = \frac{1}{N} \sum_{n=1}^N \sigma(m_n)$ with weight $\lambda_m = 5 \times 10^{-4}$ [S9]. Visibility-based pruning uses Gaussian centroids as reference points for 3D visibility masks [S9].

### Compact View-Dependent Color
To reduce parameters from 48 (SH degree 3) to a shared grid, positions $p_n$ are contracted to a bounded range using the mip-NeRF 360 contraction function:
$$\text{contract}(p_n) = \begin{cases} p_n & \text{if } \|p_n\| \le 1 \\ \frac{p_n}{\|p_n\|} (2 - \|p_n\|) & \text{if } \|p_n\| > 1 \end{cases}$$
View-dependent color $c_n(d)$ is then computed via a tiny MLP $f$:
$$c_n(d) = f(\text{contract}(p_n), d; \theta)$$
where $d$ is the view direction and $\theta$ are MLP parameters [S5]. The 0-degree SH components (RGB) are used as input features [S5].

### View-Dependent Opacity Kernel
A transparent Gaussian kernel with view-dependent opacity models specular reflectance lobes:
$$\hat{\alpha}(\theta, \beta, T, \alpha) = \alpha \cdot \frac{\cos(\max(0, \min(\frac{2\theta}{T}, \pi)))+1}{2}\exp(\beta)$$
where $\alpha$ is base opacity, $\theta$ is the angle between view direction and lobe orientation, $T$ controls angular span, and $\beta$ modulates sharpness [S7, unofficial]. This adds 5 learnable parameters per Gaussian [S7, unofficial].

### Selective Defocus Blurring
Selective defocus blurring predicts a per-Gaussian scale offset $\delta s_j$ using a compact MLP. This offset is added to the base scale to transform the covariance, creating pixel-wise variable blur kernels during rasterization [S4]. If $\delta s_j$ is constant, it degrades to uniform Gaussian blur [S4].

### Denoise-GS Pipeline
Denoise-GS uses a two-round process:
1.  Train a UNet using Noise2Void (N2V) for unsupervised denoising.
2.  Process denoised images through InstantSplat to initialize and train 3DGS.
3.  Filter rendered results by viewpoint for stability.
4.  Fine-tune the UNet using a composite loss balancing low-frequency and perceptual detail consistency.
5.  Render again on selected viewpoints [S6].

### Pseudocode: Standard Training Loop with Half-Precision and Loss Scaling

```python
import torch
from gsplat import rasterize_gaussians # Pseudocode for library call
from tiny_cuda_nn import JIT_MLP # Pseudocode for library call

def train_step(gaussians, camera, gt_image, optimizer, config):
    """
    Performs one training step for 3D Gaussian Splatting.
    
    Args:
        gaussians: Object containing positions (xyz), scales (s), rotations (q), 
                   opacities (alpha), and SH coefficients (sh).
        camera: Camera parameters (intrinsics, extrinsics).
        gt_image: Ground truth image tensor.
        optimizer: Adam optimizer instance.
        config: Dictionary of hyperparameters.
    """
    optimizer.zero_grad()
    
    # 1. Forward Pass: Rasterization
    # Use half-precision for feature vectors to reduce register pressure [S1]
    # gsplat handles the differentiable rasterization and alpha blending
    rendered_image, aux_info = rasterize_gaussians(
        gaussians.xyz,
        gaussians.scales,
        gaussians.rotations,
        gaussians.opacities,
        gaussians.sh_coefficients,
        camera.intrinsics,
        camera.extrinsics,
        image_height=config.height,
        image_width=config.width
    )
    
    # 2. Loss Computation
    # Apply automatic scaling factor for half-precision stability [S1]
    loss = compute_loss(rendered_image, gt_image)
    scaled_loss = loss * config.loss_scale_factor
    
    # 3. Backward Pass
    scaled_loss.backward()
    
    # 4. Optimization Step
    optimizer.step()
    
    # 5. Adaptive Density Control (Densification/Pruning)
    # Update scene extent if using corrected method [S3]
    if config.use_corrected_scene_extent:
        update_scene_extent(gaussians, config)
    
    # Apply Gaussian reduction masks if enabled [S9]
    if config.use_gaussian_reduction:
        apply_gaussian_masks(gaussians, config.mask_threshold)
        
    return loss.item()

def compute_loss(rendered, ground_truth):
    """Compute L1 + SSIM loss."""
    l1_loss = torch.abs(rendered - ground_truth).mean()
    ssim_loss = 1.0 - ssim(rendered, ground_truth)
    return l1_loss + config.lambda_ssim * ssim_loss
```

## Operating characteristics

### Time and Memory Complexity
Standard 3DGS training is memory-intensive due to the large number of Gaussians and their attributes (position, scale, rotation, opacity, SH coefficients). The rasterization step is $O(N \cdot P)$ where $N$ is the number of Gaussians and $P$ is the number of pixels, but optimized via tiling and sorting [S2]. Half-precision rasterization reduces register pressure and memory bandwidth usage [S1].

### Measured Performance
On an NVIDIA A100 GPU, standard 3DGS achieves approximately 19 minutes 22 seconds training time and 154 fps rendering on the Mip-NeRF 360 dataset [S5]. Compact methods can reduce training time to 17 minutes 51 seconds and increase fps to 254 [S5]. For urban scenes, methods like EVolSplat achieve 83.81 fps with 10.41 GB memory on Waymo data [S2].

### Strengths and Limitations
Strengths include real-time rendering speeds, high fidelity, and explicit scene representation. Limitations include high memory consumption for large scenes, sensitivity to camera distribution for scene extent, and artifacts in sparse-view or noisy scenarios [S6]. Underwater scenes require specific scattering models [S8].

### When to Use
Use for real-time novel view synthesis, interactive applications, and scenarios requiring explicit geometry. Use variants for specific conditions: underwater (Backscatter), sparse views (Denoise-GS), wild images (SWAG), or semantic queries (LangSplat).

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 as a real-time explicit scene representation method [S1, S2]. It builds on the idea of splatting 3D Gaussians onto a 2D image plane with differentiable rasterization. The method has since been extended to handle various conditions, including underwater environments [S8], discontinuities [S1, S1], and compact representations [S5]. The `gsplat` library [S2] and `tiny-cuda-nn` [S1] are key tools in its implementation.
