# Compact 3D Gaussian Representation (C3DGS)
## Overview
Compact 3D Gaussian Representation (C3DGS) is a method for reducing the memory footprint and storage requirements of 3D Gaussian Splatting (3DGS) by eliminating redundant primitives and compressing attributes via spatial sharing [S1]. It addresses the excessive memory usage of standard 3DGS, which often exceeds 1GB for large scenes, by introducing a volume-based masking strategy to prune non-essential Gaussians and replacing per-Gaussian attribute storage with a hash-based neural field for color and a codebook for geometry [S1]. Unlike its sibling [Sensitivity-Aware Vector Clustering](12167-sensitivity-aware-vector-clustering.md), which clusters based on rendering sensitivity, C3DGS relies on a learnable mask for pruning and explicit structural compression (grid/codebook) for attribute storage [S1].
## How it works
**Inputs:** Standard 3DGS training data (images, camera poses) and initial Gaussian point cloud.
**Outputs:** A compact scene representation consisting of:
1. A set of surviving Gaussian positions and opacities.
2. A hash-based grid neural field for view-dependent color.
3. A codebook for geometric attributes (scale and rotation) and per-Gaussian indices.

**Data Structures:**
1. **Gaussian Primitives:** Each surviving Gaussian $i$ stores:
   - Position $\mathbf{p}_i \in \mathbb{R}^3$ [S1].
   - Opacity $\alpha_i \in \mathbb{R}$ [S1].
   - Codebook Index $c_i \in \mathbb{Z}$ for geometry [S1].
   - Grid Coordinates/Hash Keys for color lookup [S1].
2. **Hash-based Grid (Instant NGP):** A multi-resolution hash table mapping spatial coordinates to feature vectors [S1]. Used to query view-dependent color coefficients (Spherical Harmonics) [S1].
3. **Geometry Codebook:** A fixed-size table of learned geometric patterns (scale and rotation vectors) [S1].

**Steps:**
1. **Volume-based Masking (Pruning):**
   - During training, introduce a learnable mask for each Gaussian.
   - The mask identifies and suppresses non-essential Gaussians that have minimal impact on rendering performance [S1].
   - This reduces the total number of Gaussians, lowering computational complexity which is linearly proportional to the count [S1].
2. **Color Compression via Hash Grid:**
   - Instead of storing per-Gaussian Spherical Harmonics (SH) coefficients, query the hash-based neural field at the Gaussian's position [S1].
   - The grid extracts the color attributes, exploiting spatial redundancy where neighboring Gaussians share similar colors [S1].
   - Instant NGP is used for its compactness and fast processing speed [S1].
3. **Geometry Compression via Codebook:**
   - Observe that most Gaussians exhibit similar geometry with limited variation in scale and rotation [S1].
   - Learn a codebook of geometric patterns shared across the scene [S1].
   - Replace per-Gaussian scale and rotation vectors with a single index pointing to the codebook entry [S1].
   - This significantly reduces spatial overhead as the codebook size is small [S1].
4. **Post-processing (Optional):**
   - Apply quantization and entropy coding to the indices and grid features to further compress storage [S1].

**Pseudocode:**
```python
# Initialization
gaussians = initialize_3dgs_gaussians() # Standard 3dgs init
mask = learnable_mask(gaussians)        # Learnable mask for pruning
hash_grid = HashGrid()                  # Instant NGP style hash grid
codebook = Codebook(size=K)             # Fixed size K for geometry

# Training Loop
for iteration in range(max_iterations):
    # 1. Pruning via Mask
    active_gaussians = []
    for g in gaussians:
        if mask[g.id] > threshold:
            active_gaussians.append(g)
    
    # 2. Render and Compute Loss
    # Color is queried from hash grid, Geometry from codebook
    rendered_image = render(active_gaussians, hash_grid, codebook)
    loss = compute_loss(rendered_image, target_image)
    
    # 3. Backpropagate
    # Update mask, hash_grid features, codebook entries, and positions/opacities
    loss.backward()
    optimizer.step()
    
    # 4. Standard 3DGS Densification (Cloning/Splitting)
    # Note: New Gaussians are added to the active set and assigned
    # initial codebook indices and grid queries
    gaussians = densify(active_gaussians)
```

**Edge Cases and Pitfalls:**
- **Sparse Regions:** The hash grid and codebook assume spatial redundancy. In very sparse regions, this assumption may break, leading to artifacts or poor reconstruction [S1]. (Addressed in [OMG](13978-optimized-minimal-3d-gaussian-splatting-omg.md) by retaining per-Gaussian parameterization for geometry in sparse settings [S1]).
- **Precision:** Quantization and entropy coding may introduce reconstruction errors if not tuned carefully [S1].
- **Boundary Conditions:** The hash grid requires proper handling of out-of-bounds queries [G].

## Subtopics

### [Optimized Minimal 3D Gaussian Splatting (OMG)](13978-optimized-minimal-3d-gaussian-splatting-omg.md)
Retains per-Gaussian parameterization for geometry to handle sparsity, while using a small neural field and Sub-Vector Quantization (SVQ) for appearance features to exploit local continuity. It achieves state-of-the-art storage compression (e.g., >300× relative to 3DGS in the bicycle scene) while maintaining high visual fidelity, building on [Compact 3D Gaussian Representation (C3DGS)](12927-compact-3d-gaussian-representation-c3dgs.md) by addressing the weakness of neural fields in sparse settings where neighboring Gaussians are further apart.

## Operating characteristics
- **Storage Efficiency:** Consistently shows about 15× reduced storage compared to 3DGS across various datasets [S1]. With post-processing (quantization and entropy coding), it achieves over 25× compression [S1]. On the Deep Blending dataset, it achieves over 28× enhancement in storage efficiency [S1].
- **Rendering Speed:** Nearly 40% increase in rendering speed on the Deep Blending dataset [S1]. General enhancement in rendering speed is observed across datasets [S1].
- **Reconstruction Quality:** Outperforms 3DGS in reconstruction quality (PSNR) on the Deep Blending dataset [S1].
- **Complexity:** Computational complexity is linearly proportional to the number of Gaussians, which is reduced by the masking strategy [S1].
- **Strengths:** Significant reduction in memory and storage requirements; fast training and rendering; high-quality reconstruction [S1].
- **Limitations:** Relies on spatial redundancy, which may be less effective in highly sparse or unstructured scenes [S1].

## Background
C3DGS was proposed to address the critical large memory and storage issue in 3DGS, which often requires >1GB for large real-world scenes [S1]. It builds on the observation that standard 3DGS densification produces many redundant and unnecessary Gaussians [S1]. The method leverages spatial redundancy in color and geometry attributes, which has been widely utilized for signal compression [S1]. It uses Instant NGP for the hash-based grid representation due to its compactness and speed [S1].
