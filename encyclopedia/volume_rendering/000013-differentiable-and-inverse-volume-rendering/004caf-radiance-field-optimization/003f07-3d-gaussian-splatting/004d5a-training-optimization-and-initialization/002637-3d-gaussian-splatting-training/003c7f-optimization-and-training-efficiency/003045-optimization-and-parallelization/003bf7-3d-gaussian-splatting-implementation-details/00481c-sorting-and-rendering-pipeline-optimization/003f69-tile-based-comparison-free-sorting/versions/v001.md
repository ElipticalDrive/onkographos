# Tile-Based Comparison-Free Sorting

Also called: Comparison-Free Depth Sorting, Tile-Local Sorting

## Overview
Tile-Based Comparison-Free Sorting restricts depth sorting operations to individual rendering tiles to avoid global synchronization, reduce hardware complexity, and achieve fixed latency per output [S1]. Unlike full-scene sorting which causes excess traffic and latency spikes, this method uses $\langle \text{tile-id}, \text{depth} \rangle$ keys to order Gaussians front-to-back, matching the $\alpha$-blending requirement with deterministic, fixed per-output latency [S1]. It is specifically designed for hardware accelerators where variable latency and high memory overhead of radix sort are prohibitive [S1].

## How it works
**Inputs:** A list of 3D Gaussian points projected onto the screen, partitioned by tile. Each point has a depth value $d$ and a tile identifier $t$.
**Outputs:** A sorted list of Gaussian points per tile, ordered by depth (front-to-back).

**Data Structures:**
*   **Gaussian Point:** Contains depth $d$ (n-bit integer/float) and tile ID $t$.
*   **Element Vector Table (EVT):** A vector of size $N$ (number of points in the tile), initialized to all 1s. Tracks unsorted elements.
*   **Sorting Key:** $\langle t, d \rangle$. Since sorting is tile-local, $t$ is constant for the batch, so sorting effectively reduces to sorting $d$.

**Algorithm Steps:**
1.  **Tile Partitioning:** Assign each Gaussian point to a tile based on its screen-space coordinates.
2.  **Initialization:** For each tile, initialize the EVT with 1s. Set iteration counter $k = 0$.
3.  **Largest Element (LE) Detection:**
    *   Use a parallel comparison-free algorithm to find the largest depth value among points where EVT is 1.
    *   The algorithm processes $n$-bit elements starting from the most significant bit (MSB).
    *   **Sign Bit Skipping:** If near-plane culling ensures $d \ge 0$, the sign bit is always 0 and can be skipped to reduce logic [S1].
    *   **Conflict Resolution:** If multiple points have the same maximum depth, the EVT may return multiple 1s. Resolve this by selecting a single index using:
        $$FO_{NEW} = Fo \& (\sim Fo + 1'b1)$$
        where $Fo$ is the output mask from the comparator stage, and $FO_{NEW}$ isolates the least significant bit (or a deterministic single winner) [S1].
4.  **Update EVT:** Set the bit corresponding to the identified LE in the EVT to 0.
5.  **Iteration:** Repeat steps 3-4 until the EVT contains all 0s. This requires $N$ iterations for $N$ points.
6.  **Output:** The sequence of identified LEs forms the sorted list.

**Pseudocode:**
```python
def tile_based_comparison_free_sort(points_in_tile):
    """
    Sorts points in a single tile using comparison-free logic.
    points_in_tile: List of objects with attribute 'depth' (n-bit).
    Returns: List of points sorted by depth descending.
    """
    N = len(points_in_tile)
    if N == 0:
        return []
    
    # EVT tracks which points are still unsorted. 1 = unsorted, 0 = sorted.
    evt = [1] * N
    sorted_points = []
    
    for _ in range(N):
        # Find the index of the largest depth among unsorted points
        max_idx = find_largest_element(points_in_tile, evt)
        
        # Mark as sorted
        evt[max_idx] = 0
        
        # Append to result
        sorted_points.append(points_in_tile[max_idx])
        
    return sorted_points

def find_largest_element(points, evt):
    """
    Hardware-mapped logic to find the largest depth value.
    Uses parallel bitwise comparison starting from MSB.
    Handles duplicates via conflict resolution.
    """
    # Conceptual implementation of the parallel comparison-free algorithm
    # 1. Filter points where evt[i] == 1
    # 2. Compare bits from MSB to LSB
    # 3. If sign bit is guaranteed 0, skip it
    # 4. Use bitwise AND/OR and adders to resolve ties
    
    # Simplified software equivalent for clarity (not hardware efficient)
    # In hardware, this is done in O(1) cycles per element via parallel logic
    
    candidates = [i for i, e in enumerate(evt) if e == 1]
    if not candidates:
        return -1
        
    # Find max depth
    max_depth = -float('inf')
    for i in candidates:
        if points[i].depth > max_depth:
            max_depth = points[i].depth
            
    # Conflict resolution: if multiple points have max_depth, pick one deterministically
    # The hardware formula FO_NEW = Fo & (~Fo + 1) selects the LSB of the mask
    # Here we simulate picking the first one for simplicity, 
    # but hardware uses bitwise ops to select a unique index from the mask.
    for i in candidates:
        if points[i].depth == max_depth:
            return i
            
    return -1
```

**Parameters:**
*   $N$: Number of Gaussian points in the tile.
*   $n$: Bit-width of the depth value.
*   $k$: Number of parallel clusters in the hardware implementation [S1].

**Edge Cases:**
*   **Duplicate Depths:** Handled by conflict resolution logic to ensure deterministic selection [S1].
*   **Empty Tile:** No sorting required.
*   **Sign Bit:** If near-plane culling is not active, the sign bit must be processed, increasing complexity [S1].

## Subtopics

### Parallel Comparison-Free Sorting
A tile-based, comparison-free sorting algorithm for Gaussian points that uses an Element Vector Table (EVT) to identify the largest element (LE) in $O(N)$ deterministic cycles, avoiding high memory overhead of radix sort [S1]. It uses $k$ parallel clusters processing partitions of $N$ n-bit elements starting from the MSB, filtering smaller values via bitwise AND and multiplexers. Outputs pass to a sequential phase of $k$ cascaded blocks to refine selection. The process repeats $N$ times until EVT is all 0s. Optimizations include sign bit skipping (if $d \ge 0$) and data conflict resolution using $FO_{NEW} = Fo \& (\sim Fo + 1'b1)$ [S1].

## Operating characteristics
*   **Time Complexity:** $O(N)$ deterministic cycles per tile, where $N$ is the number of points in the tile. Each iteration identifies one element [S1].
*   **Memory Complexity:** Low. Avoids histograms, prefix sums, and scatters required by radix sort, reducing gate count and memory overhead [S1].
*   **Performance:** Achieves full-HD rendering at 129 FPS, with 3× higher throughput and 5.98× smaller area compared to prior 3DGS accelerators [S1].
*   **Strengths:** Fixed latency per output, suitable for low-power AR/VR hardware, predictable scheduling, no global synchronization [S1].
*   **Limitations:** Requires tile-local processing; not suitable for global depth sorting without tiling. Performance depends on $N$ per tile.
*   **When to use:** Hardware accelerators for real-time 3DGS rendering where latency predictability and area efficiency are critical.
*   **When not to use:** Software implementations on GPUs where radix sort is highly optimized and memory bandwidth is not the bottleneck.

## Background
Originated from the need to accelerate 3D Gaussian Splatting (3DGS) rendering on hardware. Traditional sorting methods like radix sort incur high memory overhead and variable latency, making them unsuitable for low-power AR/VR hardware [S1]. The method builds on parallel comparison-free algorithms [S1, S21, S22] and adapts them for tile-local depth sorting in 3DGS. It was proposed in a hardware accelerator design achieving 129 FPS at Full HD [S1].
