# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific software engineering choices, hyperparameters, and optimization variants required to implement 3D Gaussian Splatting (3DGS) efficiently. It addresses the gap between the theoretical differentiable rasterization pipeline and a production-ready CUDA implementation, focusing on memory management, precision handling, and specific training configurations. It sets itself apart from general training overviews by providing concrete implementation parameters (e.g., learning rates, volume dimensions, SH degrees) and low-level kernel strategies (e.g., half-precision fetches, JIT-compiled MLPs) necessary for stable and fast convergence [S1, S2].

## How it works
The implementation relies on a differentiable rasterizer that renders images from a set of 3D Gaussians. The core optimization mechanism involves computing the gradient of a loss function $\mathcal{L}$ (e.g., L1, SSIM) with respect to the Gaussian parameters (position, covariance, opacity, color, SH coefficients) and any auxiliary parameters [Parent].

### Inputs and Outputs
*   **Inputs:** A set of $N$ 3D Gaussians, each defined by position $\mathbf{p}$, covariance $\Sigma$ (parameterized by scale $\mathbf{s}$ and rotation $\mathbf{q}$), opacity $\alpha$, and spherical harmonic coefficients $\mathbf{c}$. Camera poses $\mathbf{C}_i$ and intrinsics $\mathbf{K}_i$ for $K$ training views.
*   **Outputs:** Rendered images $\mathbf{I}_{rendered}$ and gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all parameters $\theta$.

### Data Structures
The Gaussian attributes are stored in contiguous memory buffers to optimize CUDA memory coalescing.
*   **Positions:** `float3` array of size $N$.
*   **Rotations:** `float4` quaternion array of size $N$.
*   **Scales:** `float3` array of size $N$.
*   **Opacities:** `float` array of size $N$.
*   **Colors:** `float` array of size $N \times C \times D^2$, where $C$ is channels (3) and $D$ is SH degree + 1. For degree 3, this is $N \times 3 \times 16$.
*   **Sorting Indices:** An integer array used to sort Gaussians by depth per pixel.

### Training Configuration and Parameters
Standard training configurations vary by scene scale and application.

**Optimizer:** Adam optimizer is used with a learning rate of $1 \times 10^{-3}$ [S2].

**Spherical Harmonics (SH) Degree:**
*   Default 3DGS uses degree 3 (16 coefficients per channel) [Parent].
*   **SH Degree Zero Optimization:** Setting the max SH degree to 0 removes superfluous operations. In the original 3DGS code, features represented by SH coefficients with degree > 0 are unchanged during training, making them useless for static scenes. Directly changing the max degree to 0 yields a 16.25% improvement in training speed. With specific code modifications to delete superfluous operations, a 16.57% improvement is achieved, though it increases CPU-GPU process time [S4, unofficial].

**Volume Setup (for Urban/Outdoor Scenes):**
*   **KITTI-360:** Height 12.8m, Width 32m, Length 64m. Voxel size 0.1m, resulting in volume dimension $128 \times 320 \times 640$ [S2].
*   **Waymo Zero-shot:** Volume range $(50m, 20m, 128m)$ [S2].

**Iteration Supervision:**
*   During training, a single image is randomly selected from a random scene as supervision for each iteration [S2].

### CUDA Kernel Implementation Details
To achieve real-time performance, custom CUDA kernels are implemented, often using the `gsplat` library with the 3DGUT formulation [S1].

1.  **Half-Precision Memory Fetches:** To reduce register pressure, half-precision (FP16) memory fetches are used on feature vectors during rasterization for both forward and backward kernels [S1].
2.  **Neural Field Integration:** If using neural fields for color (e.g., Compact View-dependent Color), tiny-cuda-nn's JIT-compiled cooperative vector MLPs are used, trained and evaluated in half precision (FP16) [S1].
3.  **Loss Scaling:** An automatic scaling factor is applied to loss values to improve half-precision training stability [S1].

### Edge Cases and Pitfalls
*   **Half-Precision Instability:** Training in FP16 can lead to overflow or underflow. An automatic scaling factor must be applied to the loss [S1].
*   **SH Degree > 0 Unchanged:** In standard 3DGS implementations, SH coefficients with degree > 0 are often not updated during optimization if the scene is static, leading to wasted computation. Setting degree to 0 and removing related code paths improves speed by ~16.57% [S4, unofficial].
*   **Camera Bias in Scene Extent:** Default scene extent calculation based on camera positions can be biased if cameras are clustered (e.g., orbiting a small object). This leads to incorrect splitting/pruning. Use SfM point cloud for extent calculation instead [S3].

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S3].
*   **Formula:** $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$, where $\bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i$ [S3].
*   **Pitfall:** Default 3DGS scene extent ($e_{\text{scene}}$) is proportional to the distance of the furthest camera from the average camera position, causing bias if cameras are clustered [S3].

### SH Degree Zero Optimization
Setting the maximum degree of Spherical Harmonics (SH) coefficients to 0 to remove superfluous operations and improve training speed, as higher-degree SH coefficients for color remain unchanged during training [S4, unofficial].
*   **Step:** Modify the model code to delete operations relative to the max degree in the model and set the max degree parameter to 0 [S4, unofficial].
*   **Pitfall:** In the original 3D Gaussian Splatting model, features represented by SH coefficients with degree > 0 are unchanged during all training, making them useless [S4, unofficial].
*   **Performance:** Directly changing the max degree to 0 yields a 16.25% improvement. With specific code changes, 16.57% improvement, but increases CPU-GPU process time [S4, unofficial].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5].
*   **Step:** Predict $\delta s_j$ for each Gaussian $j$ using a compact MLP. Add offset to base scale to transform covariance. Project transformed covariance to 2D space. Use as pixel-wise blur kernel during rasterization [S5].
*   **Pitfall:** If $\delta s_j$ is predicted as a constant for all Gaussians, it degrades to a uniform Gaussian blur over the entire image [S5].
*   **Comparison:** A naive Gaussian blur applies a single kernel to the whole image. A learnable Gaussian kernel optimizes a single mean/variance for average blurriness. This method predicts per-Gaussian offsets, enabling spatially varying blur shapes and magnitudes [S5].

### Compact View-dependent Color
A method to represent view-dependent color using a grid-based neural field instead of storing Spherical Harmonics (SH) coefficients per Gaussian, reducing parameters from 48 to a shared grid [S6].
*   **Step:** Contract unbounded positions $p \notin \mathbb{R}^3$ to a bounded range using the contraction function from mip-NeRF 360. Input positions into hash grids, then feed the resulting feature and view direction into the tiny MLP. Use 0-degree components of SH (same channels as RGB, not view-dependent) and convert to RGB colors [S6].
*   **Formula:** Contraction function: $\text{contract}(p_n) = p_n$ if $\|p_n\| \le 1$, else $\frac{p_n}{\|p_n\|} (2 - \|p_n\|)$. View-dependent color $c_n(d)$ is computed as: $c_n(d) = f(\text{contract}(p_n), d; \theta)$, where $f$ is a tiny MLP with parameters $\theta$ [S6].
*   **Comparison:** Original 3DGS uses 48 parameters per Gaussian for SH (max 3 degrees) to model view-dependent color; this method uses a shared grid-based neural field [S6].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising with explicitly differentiable 3DGS to address suboptimal reconstruction performance in sparse view and noisy scenes [S7].
*   **Step:** Round 1: Train a UNet using Noise2Void (N2V) for denoising. Process the denoised images through InstantSplat to initialize, train, and render 3DGS. Group and filter the rendered results by viewpoint to ensure representativeness and stability of the data for the second round. Round 2: Fine-tune the same UNet using a composite loss that balances low-frequency consistency and perceptual detail consistency. Render again on the selected viewpoints to generate new views that achieve denoising effects [S7].
*   **Comparison:** Unlike supervised methods that rely on annotated datasets and struggle with non-Gaussian/time-varying noise, Denoise-GS uses unsupervised N2V, which requires no paired clean data and is robust to uncertain noise patterns in sparse viewpoint scenarios. Unlike N2N which requires paired noisy images, N2V (used in Denoise-GS) requires no paired data, making it suitable for sparse viewpoint scenarios where only one image per viewpoint exists [S7].

### View-Dependent Opacity Kernel
A transparent Gaussian kernel where opacity is view-dependent, modeled by a half-period cosine function to approximate specular reflectance lobes. It adds 5 learnable parameters to the standard 3DGS configuration [S8, unofficial].
*   **Formula:** $\hat{\alpha}(\theta, \beta, T, \alpha) = \alpha \cdot \frac{\cos(\max(0, \min(\frac{2\theta}{T}, \pi)))+1}{2}\exp(\beta)$ where $\alpha$ is the base opacity, $\theta$ is the angle between view direction and lobe central orientation, $T$ controls angular span, and $\beta$ modulates sharpness [S8, unofficial].
*   **Parameter:** $T$: Controls the angular span of the opacity lobe. Initialized as $c\bar{\theta}_i/\pi$ based on viewpoint density. $\beta$: Modulates the sharpness of the opacity lobe. Initialized to zero. $\alpha$: The base opacity attribute of the 3D Gaussian. $\theta$: The angle between the viewing direction and the central orientation of the opacity lobe [S8, unofficial].
*   **Pitfall:** If $\theta$ increases, transparency diminishes to zero, ensuring minimal impact on viewpoints outside the lobe's influence and preventing artifacts [S8, unofficial].

### Backscatter Estimation and Optimization
Adapts 3DGS to underwater environments by learning direct attenuation, infinite backscatter, and backscatter coefficient alongside scene geometry [S9].
*   **Step:** Backscatter estimation algorithm: 1. Divide the depth map (from current scene estimate) into 10 evenly-spaced clusters covering the range from min(z) to max(z). 2. Within each cluster, identify pixels in the ground-truth image whose RGB triplets are below the bottom 1st percentile. 3. These triplets serve as an overestimate of backscatter $B_s$. 4. Use nonlinear least squares fitting on pairs $(B_s, z)$ to estimate parameters $B_\infty$ and $B_b$. Re-estimate backscatter parameters $B_\infty$ and $B_b$ every 500 optimization steps to guide convergence toward the medium coefficients [S9].
*   **Formula:** Original 3DGS loss: $L = \sum_{k=1}^K (1 - \lambda_1) \| I_k^{gt} - I_k^r(\Theta) \|_{\ell_1} + \lambda_1 L_{D-SSIM}(I_k^{gt}, I_k^r(\Theta))$. $K$ is the number of images, $\lambda_1 \in [0,1]$ is user-defined [S9].
*   **Parameter:** Backscatter parameter bounds: $B_\infty \in [0, 1]$, $B_b \in [0, 5]$ [S9].
*   **Pitfall:** Camera sensor must have a linear response to light. In-camera processed .jpg images or gamma-corrected images cannot be used unless non-linearities can be reversed [S9].
*   **Model-based depth estimation for volume parameter update:** During optimization, use Eq. (6) to extract depth values $z$ from the current scene estimate. These depth values are then used to update the medium-parameter estimates ($B_\infty, B_b$). Depth extraction from 3DGS: $z = \frac{\sum_{i=1}^M d_i \alpha_i T_i}{\sum_{i=1}^M \alpha_i T_i}$. Here $d_i$ is the depth of Gaussian $i$. This is computed at each pixel during rendering [S9].

### Gaussian Reduction with Learnable Mask
A method to reduce the number of Gaussians using a learnable mask during optimization, targeting small-sized kernels for removal [S10].
*   **Step:** Apply binary masks M to the opacities and scale attributes of the kernels at every densification step. Use residual vector quantization with L stages of vector quantization for geometric attributes like scale and rotation. Represent view-dependent colors via a grid-based neural field using hash grids for input positions, features, and view direction, fed into an MLP [S10].
*   **Formula:** The end-to-end loss is: $L = L_{ren} + \lambda_m L_m + L_r + L_s$, where $L_{ren}$ is L1+SSIM loss, $L_m$ is masking loss ($1/N \sum \sigma(m_n)$), and $L_r, L_s$ are rotation and scale objective functions [S10].
*   **Parameter:** $\epsilon$: Masking threshold for the sigmoid function in the learnable mask. $\lambda_m$: Weight for the masking loss term, typically $5 \times 10^{-4}$ [S10].

### 3DGS Visibility Pruning
Application of visibility-based pruning to 3D Gaussian Splatting, using Gaussian centroids as reference points for visibility calculation [S10].
*   **Step:** Represent each Gaussian kernel by its centroid position, scaling matrix $S$, and rotation matrix $R$ defining the covariance $\Sigma$. Use the Gaussian centroids as the 3D points $p_i$ in the visibility mask computation algorithm [S10].

## Operating characteristics
*   **Time Complexity:** The rasterization step is $O(N \cdot P)$ where $N$ is the number of Gaussians and $P$ is the number of pixels, but optimized via sorting and culling to be effectively linear in practice for sparse scenes. The backward pass is similarly efficient due to the differentiable nature of the splatting operation.
*   **Memory Complexity:** Memory usage is dominated by the storage of Gaussian attributes. For degree 3 SH, this is $N \times 59$ floats. Optimizations like SH Degree 0 reduce this to $N \times 11$ floats (position, scale, rotation, opacity, base color) [S4, unofficial]. Compact View-dependent Color reduces color parameters from 48 to a shared grid [S6].
*   **Measured Performance:** On an NVIDIA A6000 GPU, standard 3DGS achieves ~154 fps training speed on Mip-NeRF 360. Compact 3DGS achieves ~254 fps with similar PSNR (29.91 vs 29.87) [S6]. SH Degree 0 optimization yields a 16.57% improvement in training speed [S4, unofficial].
*   **Strengths:** Real-time rendering, high fidelity, efficient memory usage with optimizations.
*   **Limitations:** High memory consumption for large scenes without compression. Sensitive to initialization and hyperparameters (e.g., scene extent).
*   **When to use:** Real-time novel view synthesis, interactive applications, large-scale scenes with optimized memory management.
*   **When not to use:** Scenes with extreme view-dependent effects requiring high-degree SH (unless using Compact View-dependent Color), or when computational resources are extremely limited (use SH Degree 0 or lower).

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 as a real-time rendering method for radiance fields [Parent]. It represents scenes as a set of 3D Gaussians, allowing for efficient differentiable rasterization. The method has since been extended with various optimizations for training efficiency, memory compression, and handling specific scene types (e.g., underwater, sparse views, defocus blur) [S1-S10].
