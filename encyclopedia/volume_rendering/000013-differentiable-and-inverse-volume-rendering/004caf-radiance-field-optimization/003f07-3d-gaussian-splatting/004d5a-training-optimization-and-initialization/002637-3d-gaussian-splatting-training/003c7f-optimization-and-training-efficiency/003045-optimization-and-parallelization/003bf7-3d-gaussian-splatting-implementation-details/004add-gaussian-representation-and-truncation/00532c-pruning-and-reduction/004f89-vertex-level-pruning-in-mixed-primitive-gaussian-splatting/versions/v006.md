# Vertex-level Pruning in Mixed-Primitive Gaussian Splatting

Also called: Mixed-Primitive Vertex Pruning

## Overview
Vertex-level pruning is a dynamic optimization mechanism for Mixed-Primitive Gaussian Splatting (MP-GS) that removes redundant vertices from Gaussian triangles and lines during training to refine the scene representation [S1, unofficial]. Unlike standard 3D Gaussian Splatting which only performs primitive-level opacity pruning, this method adapts the geometric complexity of individual splats by converting triangles to lines or ellipses, and lines to ellipses, based on vertex proximity and collinearity [S1, unofficial]. It builds on [Gaussian Representation and Truncation](12855-gaussian-representation-and-truncation.md) by extending truncation logic from the primitive level to the vertex level within mixed-primitive frameworks.

## How it works
**Inputs and Outputs:**
The method operates on the set of active Gaussian primitives during training. It takes as input the current positions of the vertices defining each primitive and outputs a modified set of primitives with reduced vertex counts where appropriate.

**Data Structures:**
Each primitive is defined by a set of vertices $\mu_i$.
- **Gaussian Triangle:** Defined by three vertices $\mu_1, \mu_2, \mu_3$.
- **Gaussian Line:** Defined by two vertices $\mu_1, \mu_2$.
- **Gaussian Ellipse:** Defined by a single center vertex $\mu_1$ (and associated covariance/opacity).

**Parameters:**
- $\omega_{dist}$: Threshold for vertex proximity. Default: $0.5$ [S1, unofficial].
- $\omega_{pear}$: Threshold for collinearity detection. Default: $0.9$ [S1, unofficial].

**Algorithm Steps:**
Vertex-level pruning is triggered whenever primitive-level pruning is performed [S1, unofficial]. The process evaluates the geometry of each primitive:

1.  **Gaussian Triangle Evaluation:**
    -   Calculate the maximum pairwise L2 distance among the three vertices $\mu_1, \mu_2, \mu_3$.
    -   If $\max(\|\mu_i - \mu_j\|_2) < \omega_{dist}$, the vertices are considered "close." Prune $\mu_2$ and $\mu_3$, converting the primitive into a Gaussian ellipse centered at $\mu_1$ [S1, unofficial].
    -   If the vertices are not close, check for collinearity. Compute the Pearson correlation coefficient from the vertex coordinates. If the absolute value of this coefficient exceeds $\omega_{pear}$, the vertices are "nearly collinear." Convert the Gaussian triangle into a Gaussian line [S1, unofficial].

2.  **Gaussian Line Evaluation:**
    -   Calculate the L2 distance between the two vertices $\mu_1$ and $\mu_2$.
    -   If $\|\mu_1 - \mu_2\|_2 < \omega_{dist}$, the vertices are considered "close." Prune $\mu_2$, reducing the primitive to a Gaussian ellipse centered at $\mu_1$ [S1, unofficial].

    """
    Prunes vertices from a mixed-primitive Gaussian splat.
    
    Args:
        primitive: Object containing type ('triangle' or 'line') and vertices (list of 3D vectors).
        omega_dist: Distance threshold for proximity.
        omega_pear: Correlation threshold for collinearity.
        
    Returns:
        Modified primitive object.
    """
    if primitive.type == 'triangle':
        mu1, mu2, mu3 = primitive.vertices
        vertices = [mu1, mu2, mu3]
        
        # Check proximity
        max_dist = 0.0
        for i in range(3):
            for j in range(i + 1, 3):
                dist = l2_distance(vertices[i], vertices[j])
                if dist > max_dist:
                    max_dist = dist
                    
        if max_dist < omega_dist:
            # Convert to ellipse centered at mu1
            primitive.type = 'ellipse'
            primitive.vertices = [mu1]
            return primitive
            
        # Check collinearity if not close
        if is_nearly_collinear(vertices, omega_pear):
            # Convert to line (e.g., using mu1 and mu2)
            primitive.type = 'line'
            primitive.vertices = [mu1, mu2]
            return primitive
            
    elif primitive.type == 'line':
        mu1, mu2 = primitive.vertices
        
        dist = l2_distance(mu1, mu2)
        if dist < omega_dist:
            # Convert to ellipse centered at mu1
            primitive.type = 'ellipse'
            primitive.vertices = [mu1]
            
    return primitive

**Edge Cases and Pitfalls:**
-   **Precision:** The proximity check relies on L2 distance. If vertices are extremely close but not below $\omega_{dist}$, the triangle remains, potentially causing redundancy.
-   **Collinearity Metric:** The use of Pearson correlation for 3D collinearity is non-standard and requires careful implementation to ensure it correctly identifies planar alignment in 3D space [S1, unofficial].
-   **Interaction with Densification:** The method explicitly states that pruning does not reduce the representation to only ellipses because the original densification mechanism (cloning and splitting) is integrated, which can regenerate triangles and lines from ellipses if needed [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
The pruning step adds a constant-time geometric check per primitive during the training loop. It reduces the average storage size for vertex coordinates by 24% compared to the variant without pruning [S1, unofficial].

**Measured Performance:**
-   The mechanism improves surface reconstruction quality. In ablation studies, the framework with vertex pruning outperforms the variant without it [S1, unofficial].
-   Specific quantitative metrics (PSNR, SSIM, LPIPS) for the pruning mechanism alone are not isolated in the provided text, but the overall MP-GS method shows competitive results (e.g., PSNR 0.66 vs 3D-GS 0.13 on a specific metric table, though the table context is unclear) [S1, unofficial].

**Strengths and Limitations:**
-   **Strengths:** Reduces memory footprint and cleans up "messy" representations by eliminating unnecessary geometric complexity [S1, unofficial].
-   **Limitations:** Relies on heuristic thresholds ($\omega_{dist}, \omega_{pear}$) which may need tuning for different scenes. The collinearity check is ambiguous in implementation [S1, unofficial].

**When to Use:**
Use this method when training Mixed-Primitive Gaussian Splatting models where memory efficiency and representation cleanliness are priorities, and the scene contains regions that can be adequately represented by lower-order primitives (lines/ellipses) [S1, unofficial].

## Background
Vertex-level pruning was introduced in the context of Mixed-Primitive Gaussian Splatting (MP-GS) for surface reconstruction [S1, unofficial]. It addresses the limitation of standard 3D Gaussian Splatting, which uses only point-centered primitives, by allowing varying numbers of vertices per primitive (triangles, lines, ellipses) [S1, unofficial]. The method was developed to refine the representation during learning by removing redundant vertices, complementing the existing primitive-level pruning and densification mechanisms [S1, unofficial].
