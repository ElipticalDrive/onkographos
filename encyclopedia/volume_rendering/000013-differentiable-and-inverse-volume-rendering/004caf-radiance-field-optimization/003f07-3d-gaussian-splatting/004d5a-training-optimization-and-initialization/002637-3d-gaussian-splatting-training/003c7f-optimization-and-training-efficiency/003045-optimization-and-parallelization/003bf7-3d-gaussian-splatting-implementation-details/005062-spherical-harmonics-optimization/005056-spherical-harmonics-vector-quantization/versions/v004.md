# Spherical Harmonics Vector Quantization

Also called: SH clustering, SH palette

## Overview
Spherical Harmonics Vector Quantization (SH VQ) is a compression technique for 3D Gaussian Splatting that replaces per-splat SH coefficients with indices pointing to a shared palette of distinct SH vectors, reducing memory footprint at the cost of minor lighting artifacts [S1, unofficial]. It differs from [First-order Spherical Harmonics Distillation](9467-first-order-spherical-harmonics-distillation.md) by retaining higher-order SH information through clustering rather than reducing the degree, and from [Efficient Multi-View Training for 3D Gaussian Splatting](13982-efficient-multi-view-training-for-3d-gaussian-splatting.md) by operating on the final representation rather than the training process.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ Gaussian splats, each with SH coefficients $\mathbf{c}_i \in \mathbb{R}^{45}$ (excluding the 0th-order base color). The coefficients are typically stored as FP32 or FP16.
*   **Output:** A palette $\mathcal{P}$ of $K$ distinct SH vectors, and an index map $\mathbf{I} \in \{0, \dots, K-1\}^N$ assigning each splat to its closest palette entry.

**Data Structures:**
1.  **Palette:** An array of size $K \times 45$. Each entry is a 45-dimensional vector. Stored as FP16 in the reference implementation [S1, unofficial].
2.  **Indices:** An array of size $N$. Each entry is a 16-bit unsigned integer, regardless of whether $K < 65536$ [S1, unofficial].

**Parameters:**
*   $K$: Palette size. Typical values are 4,000 to 16,000 [S1, unofficial].
*   $N$: Number of splats.
*   Dimensionality $D=45$ (15 coefficients per RGB channel) [S1, unofficial].

**Algorithm:**
The method uses a variant of mini-batch k-means clustering [S1, unofficial].

1.  **Extract Coefficients:** Collect all $N$ SH coefficient vectors $\mathbf{c}_i$ from the scene, excluding the 0th-order term [S1, unofficial].
2.  **Initialize Palette:** Select $K$ initial centroids from the dataset (e.g., random sampling) [G].
3.  **Cluster:** Run mini-batch k-means to assign splats to $K$ clusters and update centroids.
    *   *Note:* Standard k-means is too slow for millions of splats in 45 dimensions. A custom mini-batch implementation is recommended over libraries like scikit-learn or Faiss for speed and dependency avoidance [S1, unofficial].
4.  **Assign Indices:** For each splat $i$, find the index $k$ of the palette item $\mathbf{p}_k \in \mathcal{P}$ that minimizes the Euclidean distance:
    $$ k_i = \arg \min_{k \in \{0, \dots, K-1\}} \| \mathbf{c}_i - \mathbf{p}_k \|_2 $$
5.  **Store:** Save $\mathcal{P}$ and $\mathbf{I}$ [S1, unofficial].

**Pseudocode:**
```python
def spherical_harmonics_vector_quantization(coefficients, k):
    """
    coefficients: list of N vectors, each of length 45.
    k: number of palette entries.
    Returns: palette (K x 45), indices (N).
    """
    n = len(coefficients)
    
    # Step 1: Initialize centroids randomly from the dataset
    # [G] Standard k-means++ initialization is preferred for stability, 
    # though the source uses a custom mini-batch variant.
    indices = random.sample(range(n), k)
    centroids = [coefficients[i] for i in indices]
    
    # Step 2: Mini-batch K-Means
    # [G] The source describes a custom implementation. 
    # Below is a standard mini-batch approximation.
    batch_size = 1000
    for iteration in range(100): # [G] Max iterations not specified in source
        # Sample a mini-batch
        batch_indices = random.sample(range(n), batch_size)
        batch_data = [coefficients[i] for i in batch_indices]
        
        # Assign batch data to nearest centroid
        batch_assignments = []
        for point in batch_data:
            dists = [euclidean_distance(point, c) for c in centroids]
            batch_assignments.append(dists.index(min(dists)))
            
        # Update centroids based on batch assignments
        # [G] Standard update rule: new centroid = average of assigned points
        for j in range(k):
            assigned_points = [batch_data[m] for m, a in enumerate(batch_assignments) if a == j]
            if assigned_points:
                centroids[j] = sum(assigned_points) / len(assigned_points)
                
    # Step 3: Final assignment for all splats
    final_indices = []
    for point in coefficients:
        dists = [euclidean_distance(point, c) for c in centroids]
        final_indices.append(dists.index(min(dists)))
        
    return centroids, final_indices

def euclidean_distance(v1, v2):
    return sum((a - b) ** 2 for a, b in zip(v1, v2)) ** 0.5
```

**Edge Cases and Pitfalls:**
*   **Curse of Dimensionality:** Clustering millions of splats in 45 dimensions is computationally expensive and may yield suboptimal results [S1, unofficial].
*   **Precision:** Converting coefficients to FP16 before clustering may affect quality, though the source notes FP16 storage for the palette has "pretty much no quality loss" for the final output [S1, unofficial].
*   **Index Size:** Using 16-bit indices limits the palette to 65,536 items. If $K$ exceeds this, the method requires modification [S1, unofficial].

## Operating characteristics
*   **Memory:**
    *   Palette: $K \times 45 \times 2$ bytes (FP16). For $K=16,000$, this is ~1.44 MB [S1, unofficial].
    *   Indices: $N \times 2$ bytes. For $N=6.1$ million (Bike scene), this is ~12 MB [S1, unofficial].
    *   Total SH storage: ~13.44 MB for the Bike scene with $K=16,000$ [S1, unofficial].
*   **Performance:**
    *   Clustering time: A custom mini-batch k-means implementation is ~3x faster than Faiss and significantly faster than scikit-learn [S1, unofficial].
    *   Rendering: No change in rendering complexity; index lookup is $O(1)$ [G].
*   **Quality:**
    *   $K=16,000$: Retains "shininess" effects. PSNR for Bike scene: ~35.17-35.32 [S1, unofficial].
    *   $K=4,000$: "Somewhat usable." PSNR for Bike scene: ~30.19-32.27 [S1, unofficial].
    *   Artifacts: Minor lighting artifacts are present but considered acceptable [S1, unofficial].
*   **Strengths:** Significant reduction in data size (e.g., from 1.1 GB to ~13 MB for SH data in the Bike scene) [S1, unofficial].
*   **Limitations:** Loss of fine-grained SH detail; clustering is slow for very large $N$ [S1, unofficial].

## Background
The method was proposed by Aras Pranckevičius in a blog post titled "Making Gaussian Splats more smaller" [S1, unofficial]. It was implemented in a Unity-based Gaussian Splatting viewer to enable lower-quality presets ("Low" and "Very Low") with acceptable visual fidelity [S1, unofficial]. The author notes that similar techniques may be used by other implementations like gsplat.tech [S1, unofficial].
