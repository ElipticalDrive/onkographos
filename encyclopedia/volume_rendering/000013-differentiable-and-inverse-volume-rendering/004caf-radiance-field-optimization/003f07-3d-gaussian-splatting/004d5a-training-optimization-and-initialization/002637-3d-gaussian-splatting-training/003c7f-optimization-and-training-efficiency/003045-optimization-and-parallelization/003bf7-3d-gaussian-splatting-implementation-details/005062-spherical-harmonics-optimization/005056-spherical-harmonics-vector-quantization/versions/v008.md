# Spherical Harmonics Vector Quantization

Also called: SH clustering, SH palette

## Overview
Spherical Harmonics Vector Quantization (SH VQ) is a compression technique for 3D Gaussian Splatting that replaces per-splat SH coefficients with indices pointing to a shared palette of distinct SH vectors, reducing memory footprint at the cost of minor lighting artifacts [S1, unofficial]. It sets itself apart from distillation methods by preserving the full dimensionality of the SH basis within the palette entries, rather than reducing the degree or dimensionality of the representation itself [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A set of 3D Gaussian splats, each with a full set of SH coefficients $\mathbf{c}_i$.
- Output: A palette of $K$ SH vectors and an index map assigning each splat to one palette entry.

**Data Structures:**
1.  **Palette:** An array of $K$ SH vectors. Each vector contains 45 floating-point numbers (15 per RGB channel), excluding the DC term (first coefficient) which is treated as view-independent color [S1, unofficial]. Stored as FP16 [S1, unofficial].
2.  **Index Map:** An array of 16-bit integers, one per splat, storing the index into the Palette [S1, unofficial].

**Parameters:**
-   **Palette Size ($K$):** Typically 4,000 to 16,000 items [S1, unofficial].
-   **SH Dimensionality:** 45 floats per splat (excluding DC term) [S1, unofficial].
-   **Index Bit Depth:** 16 bits per splat [S1, unofficial].

**Steps:**
1.  Collect all SH coefficients from the scene, excluding the DC term.
2.  Cluster the collected SH vectors into $K$ distinct items using a mini-batch k-means variant to form the Palette [S1, unofficial].
3.  For each original splat, find the palette item with the smallest Euclidean distance to its SH coefficients [S1, unofficial].
4.  Store the index of the closest palette item for each splat [S1, unofficial].

**Pseudocode:**
```python
import numpy as np

def spherical_harmonics_vector_quantization(sh_data: np.ndarray, k: int) -> tuple:
    """
    sh_data: np.ndarray of shape (N, 45), N splats, 45 SH coefficients (excluding DC)
    k: int, number of palette entries
    Returns: palette (K, 45), indices (N,)
    """
    # Step 1: Initialize centroids randomly from sh_data
    # [G] Standard k-means initialization; source does not specify exact method
    indices = np.random.randint(0, sh_data.shape[0], size=k)
    centroids = sh_data[indices].copy()
    
    # Step 2: Mini-batch K-Means Clustering
    # [G] Source describes a custom implementation ~3x faster than Faiss/scikit-learn
    # Standard mini-batch k-means logic:
    batch_size = 1000 # [G] Typical batch size, not specified in source
    max_iterations = 100 # [G] Convergence criterion, not specified in source
    
    for _ in range(max_iterations):
        # Sample a mini-batch
        batch_indices = np.random.choice(sh_data.shape[0], size=batch_size, replace=False)
        batch = sh_data[batch_indices]
        
        # Assign batch points to nearest centroid
        # Distance calculation: Euclidean distance in 45D space
        # [G] Explicit formula for distance
        distances = np.linalg.norm(batch[:, np.newaxis, :] - centroids[np.newaxis, :, :], axis=2)
        assignments = np.argmin(distances, axis=1)
        
        # Update centroids based on assignments
        for j in range(k):
            mask = assignments == j
            if np.sum(mask) > 0:
                centroids[j] = np.mean(batch[mask], axis=0)
                
    # Step 3: Assign all splats to closest palette item
    # Calculate distance from all splats to all centroids
    # [G] Efficient distance calculation using broadcasting or matrix multiplication
    distances = np.linalg.norm(sh_data[:, np.newaxis, :] - centroids[np.newaxis, :, :], axis=2)
    final_indices = np.argmin(distances, axis=1)
    
    return centroids, final_indices
```

**Edge Cases and Pitfalls:**
-   **Curse of Dimensionality:** Clustering millions of splats into thousands of items in 45 dimensions is slow and computationally expensive [S1, unofficial].
-   **Lighting Artifacts:** The quantization introduces minor lighting artifacts, though they are often acceptable [S1, unofficial].
-   **Implementation Choice:** Standard libraries like scikit-learn are too slow; Faiss is faster but adds dependencies. A custom mini-batch k-means implementation is preferred for speed and dependency management [S1, unofficial].

## Operating characteristics
-   **Memory Footprint:** For a scene with 6.1 million splats (e.g., 'bike' scene), using 16k palette items results in ~1.44MB for the palette (FP16) and ~12MB for the indices (16-bit) [S1, unofficial]. This is a significant reduction from the ~1.1GB required for raw SH coefficients [S1, unofficial].
-   **Performance:** The custom mini-batch k-means implementation is ~3x faster than Faiss and provides better quality for this specific task [S1, unofficial].
-   **Quality:** Retains "shininess" effects. For the 'bike' scene, 'Low' preset (16k items) yields PSNR ~35.17-35.32, while 'Very Low' (4k items) yields PSNR ~30.19-32.27 [S1, unofficial].
-   **Strengths:** Significant data size reduction; preserves view-dependent shading better than lower-dimensional approximations.
-   **Limitations:** Clustering is slow; introduces quantization artifacts; requires 16-bit indices even if fewer palette entries are used.

## Background
This method was introduced by Aras Pranckevičius in a blog post detailing optimizations for 3D Gaussian Splatting in Unity [S1, unofficial]. It draws inspiration from traditional computer graphics palette techniques, where colors are stored in a lookup table and pixels reference indices [S1, unofficial]. The author notes that while the clustering approach might not be theoretically optimal, it provides a practical balance of speed and quality for real-time rendering contexts [S1, unofficial].
