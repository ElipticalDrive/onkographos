# Compact 3D Gaussian Representation (C3DGS)

## Overview
Compact 3D Gaussian Representation (C3DGS) is a method for optimizing 3D Gaussian Splatting (3DGS) by reducing storage requirements and increasing rendering speed through attribute compression and Gaussian pruning [S1]. It addresses the excessive memory consumption of standard 3DGS, which often exceeds 1GB for large scenes, by exploiting spatial redundancy in color and geometry [S1]. Unlike standard 3DGS, which stores unique per-Gaussian attributes, C3DGS replaces per-Gaussian color storage with a hash-based neural grid and replaces per-Gaussian geometric parameters with codebook indices [S1].

## How it works
**Inputs:** A set of 3D Gaussians $\{G_i\}$ generated by the standard 3DGS densification process (cloning and splitting), each with position $\mathbf{p}_i$, scale $\mathbf{s}_i$, rotation $\mathbf{q}_i$, and view-dependent color coefficients $\mathbf{c}_i$ [S1].
**Outputs:** A compressed scene representation consisting of:
1.  A binary mask $M$ indicating active Gaussians.
2.  A hash-based neural grid $\mathcal{G}$ for color prediction.
3.  A geometry codebook $\mathcal{C}_{geo}$ containing learned scale/rotation patterns.
4.  A list of codebook indices $I_i$ for each active Gaussian.

**Data Structures:**
*   **Mask $M$:** A boolean array of size $N$ (total Gaussians), where $M_i=1$ if Gaussian $i$ is essential, $0$ otherwise.
*   **Hash Grid $\mathcal{G}$:** Uses the Instant NGP hash grid structure [S1]. It maps 3D coordinates to feature vectors. The grid size and resolution are hyperparameters; the specific dimensions are not given in the sources.
*   **Geometry Codebook $\mathcal{C}_{geo}$:** A lookup table of size $K$ (codebook size). Each entry contains a quantized scale vector $\mathbf{s}'$ and rotation quaternion $\mathbf{q}'$. The size $K$ is small enough that the overhead is negligible [S1].
*   **Indices $I$:** An integer array of size $N$, storing the index into $\mathcal{C}_{geo}$ for each Gaussian.

**Steps:**

1.  **Volume-Based Masking (Pruning):**
    During training, a learnable mask strategy identifies non-essential Gaussians. The method observes that standard densification produces redundant Gaussians [S1]. A mask variable $m_i$ is learned for each Gaussian. Gaussians with low contribution to the rendering loss are masked out ($m_i=0$), reducing the active set size $N_{active}$ [S1]. This reduces computational complexity, which is linearly proportional to the number of Gaussians [S1].

2.  **Color Compression via Hash Grid:**
    Instead of storing spherical harmonic (SH) coefficients for each Gaussian, the view-dependent color is predicted by querying the hash grid $\mathcal{G}$ at the Gaussian's position $\mathbf{p}_i$ [S1].
    The color $\mathbf{c}_i$ is computed as:
    $$ \mathbf{c}_i = \text{Decode}(\mathcal{G}(\mathbf{p}_i)) $$
    where $\text{Decode}$ is the neural network head associated with the hash grid [S1]. This exploits spatial redundancy, as neighboring Gaussians share similar color attributes [S1].

3.  **Geometry Compression via Codebook:**
    Geometric attributes (scale $\mathbf{s}_i$ and rotation $\mathbf{q}_i$) are quantized using a codebook $\mathcal{C}_{geo}$ [S1].
    For each Gaussian $i$, the original parameters are mapped to the nearest entry in the codebook:
    $$ I_i = \arg \min_{k \in \{1, \dots, K\}} \| (\mathbf{s}_i, \mathbf{q}_i) - \mathcal{C}_{geo}[k] \| $$
    The actual parameters used for rendering are retrieved from the codebook:
    $$ (\mathbf{s}'_i, \mathbf{q}'_i) = \mathcal{C}_{geo}[I_i] $$
    The codebook is learned during training to capture common geometric patterns across the scene [S1].

4.  **Rendering:**
    For each active Gaussian $i$ (where $M_i=1$):
    *   Retrieve color $\mathbf{c}_i$ from $\mathcal{G}(\mathbf{p}_i)$.
    *   Retrieve scale $\mathbf{s}'_i$ and rotation $\mathbf{q}'_i$ from $\mathcal{C}_{geo}[I_i]$.
    *   Compute the covariance matrix $\Sigma_i$ from $\mathbf{s}'_i$ and $\mathbf{q}'_i$.
    *   Rasterize and accumulate color into the image buffer.

**Parameters:**
*   **Grid Type:** Hash-based grid (Instant NGP) [S1].
*   **Codebook Size ($K$):** Not given in the sources, but described as "quite small" [S1].
*   **Masking Threshold:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Precision:** The hash grid and codebook introduce quantization errors. The sources note that post-processing (quantization and entropy coding) can further compress the data, achieving over 25x compression [S1].
*   **Boundaries:** The hash grid requires handling of coordinate hashing collisions and resolution limits. The specific hash function parameters are not given in the sources.
*   **Degenerate Input:** If the scene has high geometric diversity, a small codebook may fail to capture variations. The sources state that "the majority of Gaussians exhibit similar geometry" [S1], implying this method works best when this assumption holds.

## Subtopics

### [Optimized Minimal 3D Gaussian Splatting (OMG)](13978-optimized-minimal-3d-gaussian-splatting-omg.md)
OMG retains per-Gaussian parameterization for geometry to handle sparsity, while using a small neural field and Sub-Vector Quantization (SVQ) for appearance features. It addresses C3DGS's weakness in sparse settings where neighboring Gaussians are far apart.

## Operating characteristics
*   **Storage Efficiency:** Consistently shows about 15x reduced storage compared to 3DGS [S1]. With post-processing (quantization and entropy coding), it achieves over 25x compression [S1]. On the Deep Blending dataset, it achieves over 28x enhancement in storage efficiency [S1].
*   **Rendering Speed:** Nearly 40% increase in rendering speed on the Deep Blending dataset [S1]. General performance shows enhanced rendering speed due to reduced number of Gaussians and simpler attribute retrieval [S1].
*   **Quality:** Outperforms 3DGS in reconstruction quality (PSNR) on the Deep Blending dataset [S1]. Maintains high-quality reconstruction on other datasets [S1].
*   **Complexity:** Spatial complexity is reduced because color is stored in a global grid rather than per-Gaussian [S1]. Computational complexity is linearly proportional to the number of active Gaussians [S1].
*   **Strengths:** Significant reduction in memory and storage; fast training and rendering; high visual fidelity.
*   **Limitations:** Relies on spatial redundancy; may struggle with highly sparse or geometrically diverse scenes where neighbors do not share attributes (addressed by OMG) [S1].

## Background
C3DGS was proposed to address the critical large memory and storage issue in 3DGS, which often requires >1GB for large real-world scenes [S1]. It builds on the observation that standard 3DGS densification produces redundant Gaussians and does not exploit spatial redundancy in attributes [S1]. The method uses a hash-based grid representation (Instant NGP) for color and a codebook for geometry [S1]. It was tested on various real and synthetic scenes, including the Deep Blending dataset [S1].
