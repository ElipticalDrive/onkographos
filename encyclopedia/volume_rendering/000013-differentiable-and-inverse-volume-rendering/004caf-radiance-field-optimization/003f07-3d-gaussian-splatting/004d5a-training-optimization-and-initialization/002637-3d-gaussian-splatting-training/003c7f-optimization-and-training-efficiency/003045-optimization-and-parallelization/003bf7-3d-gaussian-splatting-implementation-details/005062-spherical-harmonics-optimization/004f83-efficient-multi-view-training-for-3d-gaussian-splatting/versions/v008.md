# Efficient Multi-View Training for 3D Gaussian Splatting

Also called: Multi-View Mini-Batch Training for 3DGS, Thread-Efficient Partial Rendering for Multi-View 3DGS

## Overview
This method enables multi-view mini-batch training for 3D Gaussian Splatting (3DGS), addressing the observation that multi-view gradients exhibit lower variance than single-view gradients, leading to more stable optimization [S1, unofficial]. It overcomes the inherent overhead of the tile-based rasterizer, which typically forces single-view training by allocating one thread block per image tile, by introducing a thread-efficient partial rendering scheme that minimizes idle threads [S1, unofficial]. It also resolves the incompatibility of standard Adaptive Density Control (ADC) with multi-view data by proposing a 3D-space compatible densification mechanism [S1, unofficial].

## How it works
**Inputs:** A set of $N$ training images with corresponding camera poses; 3D Gaussian primitives $\{G_i\}$ defined by mean $\mu_i$, covariance $\Sigma_i$ (derived from scale $S_i$ and rotation $R_i$), opacity $o_i$, and spherical harmonic coefficients $\mathbf{c}_i$; learning rate $\eta_t$; number of sampled mini-batches $K$ for variance estimation.

**Outputs:** Updated Gaussian parameters $\{G_i\}$ and optimized scene representation.

**Data Structures:**
*   **Gaussian Primitives:** Stored as a list or flat array. Each primitive $i$ contains:
    *   $\mu_i \in \mathbb{R}^3$: 3D mean position.
    *   $S_i \in \mathbb{R}^3$: Scale vector.
    *   $R_i \in \mathbb{R}^{3 \times 3}$: Rotation matrix (or quaternion).
    *   $o_i \in \mathbb{R}$: Opacity.
    *   $\mathbf{c}_i \in \mathbb{R}^{L^2 \times 3}$: SH coefficients for color (where $L$ is the SH degree).
*   **Tile Grid:** The image is split into tiles. A single thread block is allocated to a single tile.

**Algorithm Steps:**

1.  **Variance Analysis (Optional Validation):**
    To verify the benefit of multi-view training, estimate the variance of mini-batch gradients. Freeze model parameters $w_t$. Randomly sample $K$ mini-batches $B_k$ from the dataset $D$. Compute the mini-batch gradient $\nabla \bar{\phi}_k$ for each. Estimate variance using Monte Carlo sampling:
    $$
    V_{B_k \in S} (\nabla \bar{\phi}_k) = E[\|\nabla \bar{\phi}_k - P(w_t)\|_2^2]
    $$
    where $E[x] = \mu$ is the expectation. Compare this variance against single-view baselines [S1, unofficial].

2.  **Thread-Efficient Partial Rendering:**
    Standard 3DGS rasterizers allocate one block per tile. Rendering multiple images naively causes idle threads because blocks finish at different times. The method implements a partial rendering strategy:
    *   Instead of rendering all pixels of all images in a single iteration (which is expensive), select a subset of pixels or tiles across multiple views.
    *   Ensure that thread blocks are reused efficiently. A thread is freed only when all peer threads in the same block complete their work.
    *   This avoids the "idle thread" overhead seen in naive multi-view implementations where some blocks finish early while others are still processing [S1, unofficial].

3.  **3D-Space Densification (D-SSIM Adaptation):**
    Standard ADC assumes all 2D positional gradients reside in a single image plane. Multi-view training produces gradients in different 2D spaces, making direct arithmetic invalid.
    *   Replace the standard 2D D-SSIM loss with a 3D-space compatible variant.
    *   Compute the loss and gradients in 3D space rather than projecting them to individual 2D image planes for densification decisions. This ensures that densification (splitting/cloning Gaussians) operates on consistent 3D metrics [S1, unofficial].

4.  **Gradient Update:**
    Update weights $w$ (including Gaussian parameters) using the multi-view mini-batch gradient $\nabla \bar{\phi}_k$:
    $$
    w_{t+1} = w_t - \eta_t \nabla \bar{\phi}_k (w_t)
    $$
    where $\nabla \bar{\phi}_k (w_t) = \frac{1}{|B_k|} \sum_{i \in B_k} \nabla \phi_i (w_t)$ [S1, unofficial].

**Parameters:**
*   $\eta_t$: Learning rate. Typical values follow standard 3DGS schedules (e.g., initial $1.6 \times 10^{-4}$ decaying over iterations) [S1, unofficial].
*   $K$: Number of sampled mini-batches for variance estimation. Not given in the sources.
*   Mini-batch size: Defined by the number of pixels/tiles sampled across views. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Idle Threads:** Naive multi-view rendering causes significant overhead due to idle threads in thread blocks. The thread-efficient scheme is required to mitigate this [S1, unofficial].
*   **Gradient Space Mismatch:** Standard ADC fails in multi-view training because it assumes gradients are in a single 2D plane. Using 2D gradients for densification in multi-view leads to suboptimal results [S1, unofficial].
*   **Precision:** The variance estimation relies on Monte Carlo sampling. Ensure sufficient $K$ for stable variance estimates if used for hyperparameter tuning [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The method aims to reduce the overhead of multi-view rendering. While multi-view training inherently processes more data per iteration, the thread-efficient partial rendering minimizes the idle thread penalty, making it computationally feasible compared to naive multi-view approaches [S1, unofficial].
*   **Memory Complexity:** Similar to standard 3DGS, dominated by the storage of Gaussian primitives and intermediate rendering buffers. No significant additional memory overhead is reported beyond the multi-view pixel buffers [S1, unofficial].
*   **Performance:** Multi-view training yields smaller variance in mini-batch gradients compared to single-view training, resulting in more stable optimization [S1, unofficial].
*   **Strengths:** More stable optimization due to lower gradient variance; better utilization of GPU threads compared to naive multi-view rendering.
*   **Limitations:** Requires modification of the standard ADC mechanism to work in 3D space; implementation complexity is higher due to the need for thread-efficient partial rendering [S1, unofficial].
*   **When to use:** When stable optimization is prioritized and computational resources allow for the complexity of thread-efficient rendering and 3D-space densification.
*   **When not to use:** When single-view training is sufficient and simplicity is preferred; or if the hardware does not support the required thread synchronization mechanisms efficiently.

## Background
3D Gaussian Splatting (3DGS) has become a preferred method for inverse rendering due to its speed [S1, unofficial]. Standard 3DGS uses single-view mini-batch training because its rasterization pipeline makes gathering individual pixels from multiple images difficult, requiring rendering every pixel of all images in a single iteration, which incurs considerable overhead [S1, unofficial]. In contrast, NeRF implicitly benefits from multi-view learning [S1, unofficial]. The method was introduced by Minhyuk Choi, Injae Kim, and Hyunwoo J. Kim from Korea University and KAIST in 2025 [S1, unofficial].
