# Spherical Harmonics Vector Quantization

Also called: SH clustering, SH palette

## Overview
Spherical Harmonics Vector Quantization (SH VQ) is a compression technique for 3D Gaussian Splatting that replaces per-splat SH coefficients with indices pointing to a shared palette of distinct SH vectors, reducing memory footprint at the cost of minor lighting artifacts [S1, unofficial]. It differs from distillation methods [First-order Spherical Harmonics Distillation](9467-first-order-spherical-harmonics-distillation.md) by preserving the original SH degree and basis functions, mapping them to a discrete set of representative vectors rather than approximating them with a lower-degree polynomial.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ 3D Gaussians, each with SH coefficients $\mathbf{C} \in \mathbb{R}^{N \times 45}$ (excluding the 0th-order color term). The source uses 15 floats per splat (5 per RGB channel) for degrees up to $d=3$ [S1, unofficial].
*   **Output:** A palette $\mathcal{P} \in \mathbb{R}^{K \times 45}$ of $K$ distinct SH vectors, and an index map $\mathbf{I} \in \mathbb{Z}^{N}$ where $\mathbf{I}_j \in [0, K-1]$ is the index of the closest palette item for Gaussian $j$.

**Data Structures:**
1.  **Palette:** Stored as FP16 (16-bit floating point). Size: $K \times 45 \times 2$ bytes. For $K=16,000$, this is $\approx 1.44$ MB [S1, unofficial].
2.  **Indices:** Stored as 16-bit integers per splat, regardless of $K$ (even if $K < 65,536$). Size: $N \times 2$ bytes. For $N=6.1$ million splats, this is $\approx 12$ MB [S1, unofficial].

**Algorithm Steps:**
1.  **Extract SH Data:** Collect the 45 SH coefficients (excluding the 0th-order term) for all $N$ splats into a matrix $\mathbf{X} \in \mathbb{R}^{N \times 45}$ [S1, unofficial].
2.  **Cluster:** Perform vector quantization on $\mathbf{X}$ using a mini-batch k-means variant to produce $K$ cluster centers (the palette $\mathcal{P}$) [S1, unofficial].
    *   The author notes that standard libraries like scikit-learn are too slow, and while Faiss is faster, a custom implementation was preferred to avoid dependencies [S1, unofficial].
    *   The custom implementation is reported to be $\approx 3\times$ faster than Faiss and provides better quality for this specific task [S1, unofficial].
3.  **Assign Indices:** For each splat $j$, find the palette index $k$ that minimizes the Euclidean distance between the splat's SH vector $\mathbf{x}_j$ and the palette item $\mathbf{p}_k$:
    $$ k_j = \arg \min_{k \in \{0, \dots, K-1\}} \| \mathbf{x}_j - \mathbf{p}_k \|_2 $$
4.  **Store:** Save $\mathcal{P}$ and $\mathbf{I}$ [S1, unofficial].

**Parameters:**
*   **Palette Size ($K$):** Typically 4,000 to 16,000 items [S1, unofficial].
    *   $K=16,000$ ("Low" preset): Retains shininess effects; PSNR $\approx 35.17$ (bike scene) [S1, unofficial].
    *   $K=4,000$ ("Very Low" preset): Usable quality; PSNR $\approx 32.27$ (bike scene) [S1, unofficial].
*   **Precision:** FP16 for palette storage [S1, unofficial].

**Pseudocode:**
```python
import numpy as np

def spherical_harmonics_vector_quantization(sh_data: np.ndarray, k: int) -> tuple:
    """
    Compress SH coefficients using vector quantization.
    
    Args:
        sh_data: Array of shape (N, 45) containing SH coefficients for N splats.
                 Excludes the 0th-order color term.
        k: Number of palette items (e.g., 4000 or 16000).
        
    Returns:
        palette: Array of shape (k, 45) containing the cluster centers.
        indices: Array of shape (N,) containing the index of the closest palette item for each splat.
    """
    # Step 1: Initialize centroids randomly from the data
    # [G] Standard k-means initialization; source does not specify exact initialization strategy.
    rng = np.random.default_rng()
    centroid_indices = rng.choice(sh_data.shape[0], size=k, replace=False)
    centroids = sh_data[centroid_indices].copy()
    
    # Step 2: Mini-batch K-Means Clustering
    # [G] The source describes a custom mini-batch k-means variant. 
    # Below is a standard mini-batch k-means implementation which aligns with the described process.
    n_samples = sh_data.shape[0]
    batch_size = 1024  # [G] Typical batch size; source does not specify.
    n_iterations = 100 # [G] Source does not specify iteration count; sufficient for convergence.
    
    for _ in range(n_iterations):
        # Sample a mini-batch
        batch_indices = rng.choice(n_samples, size=batch_size, replace=False)
        batch = sh_data[batch_indices]
        
        # Assign batch points to nearest centroid
        # Compute distances: (batch_size, k)
        # dist = ||x - c||^2 = ||x||^2 + ||c||^2 - 2 * x.c
        batch_sq = np.sum(batch**2, axis=1, keepdims=True)
        cent_sq = np.sum(centroids**2, axis=1, keepdims=True).T
        cross = batch @ centroids.T
        dists = batch_sq + cent_sq - 2 * cross
        
        # Find closest centroid for each point in batch
        closest_centroids = np.argmin(dists, axis=1)
        
        # Update centroids using the batch statistics
        # [G] Standard mini-batch update: new_centroid = (old * count + sum_batch) / (count + batch_count)
        # For simplicity and alignment with "mini-batch" description, we use a weighted average.
        # However, standard online k-means often just replaces or averages. 
        # Given the source's claim of "better quality" than Faiss, a standard weighted update is assumed.
        for i in range(k):
            mask = closest_centroids == i
            if np.any(mask):
                # Update centroid i with the mean of the batch points assigned to it
                # [G] This is a simplified update. A robust implementation would track counts.
                # Here we assume a simple replacement or averaging for the mini-batch step.
                # To match standard k-means behavior in mini-batch:
                points = batch[mask]
                centroids[i] = np.mean(points, axis=0)
                
    # Step 3: Final Assignment
    # Compute distances for all data points to final centroids
    all_sq = np.sum(sh_data**2, axis=1, keepdims=True)
    cent_sq_final = np.sum(centroids**2, axis=1, keepdims=True).T
    cross_all = sh_data @ centroids.T
    dists_all = all_sq + cent_sq_final - 2 * cross_all
    
    indices = np.argmin(dists_all, axis=1)
    
    return centroids, indices
```

## Operating characteristics
*   **Time Complexity:** Clustering is the bottleneck. The source notes that clustering millions of splats in 45 dimensions is slow due to the curse of dimensionality [S1, unofficial]. A custom mini-batch k-means implementation was $\approx 3\times$ faster than Faiss [S1, unofficial].
*   **Memory Footprint:**
    *   **Palette:** $K \times 45 \times 2$ bytes. For $K=16,000$, $\approx 1.44$ MB [S1, unofficial].
    *   **Indices:** $N \times 2$ bytes. For $N=6.1$ million splats, $\approx 12$ MB [S1, unofficial].
    *   **Total SH Storage:** $\approx 13.44$ MB for the bike scene at $K=16,000$ [S1, unofficial].
*   **Performance:**
    *   **Bike Scene (6.1M splats):**
        *   **Low (16k items):** Data sizes 98MB, 41MB, 93MB; PSNR 35.17, 35.32, 35.00 [S1, unofficial].
        *   **Very Low (4k items):** Data sizes 79MB, 33MB, 75MB; PSNR 32.27, 30.19, 31.10 [S1, unofficial].
*   **Strengths:** Significantly reduces data size (from 1.1GB raw SH to ~13MB for indices+palette) while retaining shininess effects [S1, unofficial].
*   **Limitations:** Introduces minor lighting artifacts [S1, unofficial]. Clustering is computationally expensive [S1, unofficial].

## Background
The method was proposed by Aras Pranckevičius in a blog post discussing optimizations for Gaussian Splatting in Unity [S1, unofficial]. It was implemented in his "Gaussian Splatting for Unity" project to support "Low" and "Very Low" quality presets [S1, unofficial]. The author notes that similar techniques may be used by other implementations, such as gsplat.tech [S1, unofficial].
