# 3D Gaussian Splatting to Point Cloud

Also called: 3DGS-to-PC, Gaussian Splatting to Dense Point Clouds

## Overview
This method converts a trained 3D Gaussian Splatting (3DGS) scene representation into a dense, standard point cloud (PLY format) that visually approximates the original radiance field, enabling compatibility with general 3D software that does not support Gaussian primitives [S1, unofficial]. It differs from standard 3DGS rendering by explicitly sampling discrete points from the continuous Gaussian distributions rather than rasterizing splats, and it optionally reconstructs a mesh via Poisson surface reconstruction [S1, unofficial].

## How it works
The method transforms the parametric Gaussian representation (position, covariance, opacity, spherical harmonics) into a discrete set of 3D points with associated colors and normals.

### Inputs and Outputs
**Inputs:**
- A saved 3DGS scene (typically a `.ply` or `.bin` file containing Gaussian parameters).
- Camera poses and intrinsics (COLMAP `transforms.json` or similar) used for color rendering [S1, unofficial].
- Configuration settings (see `GaussPointCloudSettings` below).

**Outputs:**
- A PLY file containing points, colors, and optionally normals.
- Optionally, a PLY mesh file if `generate_mesh` is enabled.

### Data Structures
The configuration is encapsulated in a `GaussPointCloudSettings` structure. The fields and their default values are:

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `renderer_type` | str | "cuda" | "cuda" or "python" |
| `num_points` | int | 10,000,000 | Total target point count |
| `exact_num_points` | bool | False | Force exact count (slower) |
| `no_prioritise_visible_gaussians` | bool | False | Disable visibility weighting |
| `visibility_threshold` | float | 0.05 | Min contribution to include Gaussian |
| `surface_distance_std` | float | None | Std devs from surface to cull |
| `clean_pointcloud` | bool | False | Remove outliers via Open3D |
| `generate_mesh` | bool | False | Enable Poisson meshing |
| `poisson_depth` | int | 10 | Poisson reconstruction depth |
| `laplacian_iterations` | int | 10 | Mesh smoothing iterations |
| `camera_skip_rate` | int | 0 | Cameras to skip per render |
| `no_render_colours` | bool | False | Skip color rendering |
| `colour_quality` | str | "high" | "tiny", "low", "medium", "high", "ultra", "original" |
| `bounding_box_min` | list | None | Min XYZ bounds |
| `bounding_box_max` | list | None | Max XYZ bounds |
| `no_calculate_normals` | bool | False | Skip normal calculation |
| `mahalanobis_distance_std` | float | 2.0 | Max Mahalanobis distance for sampling |
| `min_opacity` | float | 0.0 | Min opacity threshold |
| `cull_gaussian_sizes` | float | 0.0 | % of largest Gaussians to remove |
| `max_sh_degrees` | int | 3 | Spherical harmonics degree |
| `quiet` | bool | False | Suppress output |
| `device` | str | "cuda" | Compute device |

The output data is structured as `PointCloudData`:
- `points`: `torch.Tensor` of shape `(N, 3)`
- `colors`: `torch.Tensor` of shape `(N, 3)`
- `normals`: `torch.Tensor` of shape `(N, 3)` (if calculated)

### Steps

1. **Pre-filtering Gaussians**
   - Filter Gaussians based on `min_opacity`.
   - If `cull_gaussian_sizes` > 0, remove the top `cull_gaussian_sizes` percentage of Gaussians sorted by size (largest first).
   - If `bounding_box_min` or `bounding_box_max` are set, exclude Gaussians whose centers fall outside these bounds.
   - If `surface_distance_std` is set, cull Gaussians that are more than `surface_distance_std` standard deviations away from the predicted scene surfaces [S1, unofficial].

2. **Visibility Weighting**
   - Calculate the visibility/contribution of each remaining Gaussian.
   - If `no_prioritise_visible_gaussians` is False, assign a sampling weight to each Gaussian proportional to its visibility. Gaussians contributing more to the final image receive more samples.
   - Discard Gaussians with visibility below `visibility_threshold` [S1, unofficial].

3. **Point Sampling**
   - For each selected Gaussian, sample points from a Multivariate Normal distribution defined by the Gaussian's mean (position) and covariance matrix.
   - Reject samples where the Mahalanobis distance from the center exceeds `mahalanobis_distance_std`.
   - Continue sampling until the total number of points approaches `num_points`. If `exact_num_points` is True, adjust sampling to match the count exactly (computationally more expensive) [S1, unofficial].

4. **Color Rendering**
   - If `no_render_colours` is False, render colors for the sampled points.
   - Determine the resolution for rendering based on `colour_quality`:
     - `tiny`: 180px
     - `low`: 360px
     - `medium`: 720px
     - `high`: 1280px
     - `ultra`: 1920px
     - `original`: Native resolution
   - Use the specified `renderer_type` ("cuda" or "python") to project the points onto the camera views and interpolate colors using the Gaussian's spherical harmonics coefficients.
   - If `camera_skip_rate` > 0, skip every N-th camera during rendering to save time [S1, unofficial].

5. **Normal Calculation**
   - If `no_calculate_normals` is False, compute normals for each point. This is typically done by analyzing the local neighborhood or using the Gaussian's orientation parameters [S1, unofficial].

6. **Post-processing (Optional)**
   - If `clean_pointcloud` is True, use Open3D to remove statistical outliers from the point cloud.
   - If `generate_mesh` is True, perform Poisson surface reconstruction on the point cloud using `poisson_depth` and apply `laplacian_iterations` of smoothing [S1, unofficial].

### Parameters and Edge Cases
- **`num_points`**: Default 10,000,000. Higher values increase memory usage and processing time.
- **`exact_num_points`**: If True, the algorithm ensures the output has exactly `num_points`, which may require oversampling and discarding, increasing runtime [S1, unofficial].
- **`mahalanobis_distance_std`**: Default 2.0. Points further than this distance from the Gaussian center are rejected. Lower values result in tighter, more concentrated point clouds [S1, unofficial].
- **`colour_quality`**: Affects rendering resolution. "original" uses the native camera resolution, which is slowest but highest quality [S1, unofficial].
- **Edge Case**: If `no_render_colours` is True, the resulting point cloud will have arbitrary or default colors, as colors are not computed [S1, unofficial].
- **Edge Case**: If `camera_skip_rate` > 0, colors may be inaccurate if cameras are not in a linear trajectory, as fewer views are used for interpolation [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Dominated by the sampling and rendering steps. Rendering colors for millions of points across multiple camera views is the most expensive operation. Using `cuda` renderer is significantly faster than `python` [S1, unofficial].
- **Memory Complexity**: Proportional to `num_points` and the number of Gaussians. Storing points, colors, and normals for 10M points requires significant VRAM/RAM.
- **Scaling**: Performance scales linearly with `num_points` and the number of Gaussians. `exact_num_points` adds overhead.
- **Strengths**: Produces high-quality, dense point clouds that closely mimic the original 3DGS scene. Compatible with standard 3D software.
- **Limitations**: Computationally intensive for large scenes. Colors may be inaccurate if `camera_skip_rate` is high or if `colour_quality` is low. Mesh generation is optional and may not capture fine details [S1, unofficial].

## Background
The method was introduced by Lewis Stuart in 2025 as part of the "3DGS-to-PC" project, addressing the need for compatibility between 3D Gaussian Splatting scenes and general 3D handling software that does not support Gaussian primitives [S1, unofficial]. The work was presented at ICCV 2025 Workshop on 3D-VAST [S1, unofficial].
