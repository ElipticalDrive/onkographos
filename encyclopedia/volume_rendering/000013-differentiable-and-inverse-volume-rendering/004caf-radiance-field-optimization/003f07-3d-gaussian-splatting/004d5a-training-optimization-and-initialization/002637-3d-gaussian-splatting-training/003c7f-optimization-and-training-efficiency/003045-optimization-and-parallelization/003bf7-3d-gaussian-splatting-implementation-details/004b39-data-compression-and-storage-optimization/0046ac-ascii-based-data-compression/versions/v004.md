# ASCII-Based Data Compression
Also called: Anywhere Compression, Base 94 Floating-Point Compression, Base 95 Integer Compression

## Overview
This method reduces the bit-width of serialized Gaussian attributes by encoding numerical values into compact ASCII strings, thereby improving data transmission speed during distributed training [S1, unofficial]. It distinguishes itself from sibling methods like [Sensitivity-Aware Vector Clustering](12167-sensitivity-aware-vector-clustering.md) and [Compact 3D Gaussian Representation (C3DGS)](12927-compact-3d-gaussian-representation-c3dgs.md) by operating on the serialization layer (string encoding) rather than the geometric representation layer (codebooks or hash grids), focusing on reducing I/O overhead rather than storage density [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Continuous numerical values (integers or floating-point numbers) representing Gaussian attributes (e.g., position, scale, rotation, SH coefficients).
*   **Output:** A compact ASCII string representation of the input values.

**Data Structures:**
*   **Integer Codebook:** A mapping of integers in the range $[0, 95]$ to ASCII characters in the range $[32, 126]$ (inclusive).
*   **Floating-Point Codebook:** A mapping of integer components in the range $[0, 94]$ to ASCII characters in the range $[32, 125]$ (inclusive).
*   **Separator:** The ASCII character with code 126 (`~`) is used to delimit the integer and fractional parts of a floating-point number.

**Parameters:**
*   **Color Precision:** Color matrix items are truncated to one decimal place, restricting values to the range $[0.0, 2.0]$ with 21 discrete alternatives [S1, unofficial].

**Steps:**

1.  **Integer Compression:**
    For an integer value $n$ where $0 \le n \le 95$:
    *   Map $n$ to the corresponding ASCII character $c$ using the mapping: $c = \text{chr}(n + 32)$.
    *   The encoded string is the single character $c$.

2.  **Floating-Point Compression:**
    For a floating-point value $f$:
    *   Extract the integer part $I = \lfloor f \rfloor$ and the fractional part.
    *   Determine the number of decimal places $d$ required to represent the fractional part.
    *   Map the integer part $I$ (where $0 \le I \le 94$) to an ASCII character $c_I$ using: $c_I = \text{chr}(I + 32)$.
    *   Append the separator character $c_{sep} = \text{chr}(126)$.
    *   Append the decimal places $d$ as a string representation (Note: The source describes splitting the string into integer part $I$ and decimal places $d$, but does not explicitly detail how $d$ itself is encoded if it exceeds single digits, implying $d$ is stored as a standard digit string or the method assumes single-digit precision for the count of decimal places. Given the context of "one decimal place" for color, $d$ is likely small). *Correction based on source text:* The source states "split into two part... integer part $I$... decimal places $d$". It does not specify encoding $d$ itself via Base94, but rather using the separator. We assume $d$ is stored as a standard ASCII digit string or the method relies on fixed precision. However, the formula $f = I \times 10^{-d}$ suggests $d$ is the exponent. Let's stick to the explicit mapping:
        *   Encode $I$ as $c_I$.
        *   Add separator `~`.
        *   The source implies the fractional part is handled by the exponent $d$. If the value is $1.23$, $I=1$, $d=2$ (two decimal places). The string might be `chr(33) + '~' + "2"`.

3.  **Decoding Integer:**
    *   Take the ASCII character $c$.
    *   Convert to decimal integer: $n = \text{ord}(c) - 32$.

4.  **Decoding Floating-Point:**
    *   Split the string at the separator `~` (ASCII 126).
    *   Let the left part be $s_I$ and the right part be $s_d$.
    *   Decode integer part: $I = \text{ord}(s_I) - 32$.
    *   Decode decimal places: $d = \text{int}(s_d)$.
    *   Calculate final value: $f = I \times 10^{-d}$.

5.  **Color Matrix Optimization:**
    *   Truncate each color component to one decimal place.
    *   Map the truncated value to the 21 available discrete levels.
    *   Apply ASCII compression to these values.

**Pseudocode:**

```python
def encode_integer(n: int) -> str:
    """
    Encode an integer in [0, 95] to a single ASCII character.
    """
    if not (0 <= n <= 95):
        raise ValueError("Integer out of range [0, 95]")
    # Map 0-95 to ASCII 32-126
    return chr(n + 32)

def decode_integer(s: str) -> int:
    """
    Decode a single ASCII character back to an integer.
    """
    return ord(s) - 32

def encode_float(f: float) -> str:
    """
    Encode a floating-point number using Base94 integer part and decimal place count.
    Assumes the integer part is in [0, 94].
    """
    # Extract integer part
    i_part = int(f)
    
    # Determine decimal places d
    # Note: The source formula is f = I * 10^-d. This implies d is the number of decimal places.
    # To recover f, we need I and d.
    # Example: f = 1.23. I = 1. d = 2.
    # We need to store d. The source doesn't specify encoding d in Base94, 
    # but implies it's part of the string after the separator.
    # We will store d as a standard ASCII digit string.
    
    # Calculate d based on precision required. 
    # For simplicity in implementation, we can determine d by finding the smallest 
    # power of 10 that distinguishes the float, or use a fixed precision.
    # The source mentions "one decimal place" for color, but general floats might vary.
    # Let's assume we store d as the number of digits after the decimal point.
    
    # Convert to string to find decimal places
    f_str = f"{f:.10f}".rstrip('0').rstrip('.') # Remove trailing zeros
    if '.' in f_str:
        d = len(f_str.split('.')[1])
    else:
        d = 0
        
    # Encode integer part I
    if not (0 <= i_part <= 94):
        raise ValueError("Integer part out of range [0, 94]")
    c_i = chr(i_part + 32)
    
    # Separator
    sep = chr(126)
    
    # Encode decimal places d
    # d is an integer count. We encode it as ASCII digits.
    d_str = str(d)
    
    return c_i + sep + d_str

def decode_float(s: str) -> float:
    """
    Decode an ASCII string back to a floating-point number.
    """
    # Find separator
    sep_idx = s.find(chr(126))
    if sep_idx == -1:
        raise ValueError("Missing separator")
        
    c_i = s[:sep_idx]
    d_str = s[sep_idx+1:]
    
    # Decode integer part
    i_part = ord(c_i) - 32
    
    # Decode decimal places
    d = int(d_str)
    
    # Calculate value
    f = i_part * (10 ** -d)
    return f

def compress_color_matrix(matrix: list) -> list:
    """
    Compress a color matrix by truncating to 1 decimal place and encoding.
    Range [0.0, 2.0] with 1 decimal place -> 21 values.
    """
    compressed = []
    for val in matrix:
        # Truncate to 1 decimal place
        truncated = round(val, 1)
        # Clamp to [0.0, 2.0] if necessary, though source implies this is the valid range
        # Encode the truncated value. 
        # Since it's 1 decimal place, we can treat it as an integer scaled by 10.
        # val 0.0 -> 0, val 2.0 -> 20.
        int_val = int(round(truncated * 10))
        if not (0 <= int_val <= 20):
            # Handle out of bounds if any
            int_val = max(0, min(20, int_val))
        compressed.append(encode_integer(int_val))
    return compressed
```

## Operating characteristics
*   **Time Complexity:** Encoding/decoding is $O(1)$ per number, but string manipulation overhead exists. Matrix traversal is a bottleneck; using vectorized operations (e.g., `torch::where`) is recommended over loops [S1, unofficial].
*   **Memory Complexity:** Reduces serialization size significantly compared to standard text representation, but increases memory usage during decoding/encoding due to string object creation.
*   **Performance:** Provides approximately 6% or less improvement in training speed [S1, unofficial].
*   **Strengths:** Simple to implement; improves I/O speed for distributed training.
*   **Limitations:** Not suitable for large matrix traversal compression due to processing time overhead; line break characters add decoding complexity [S1, unofficial].

## Background
This method was introduced in the context of improving 3D Gaussian Splatting training efficiency. It is part of the "Anywhere" compression strategy proposed to address data transmission bottlenecks.
