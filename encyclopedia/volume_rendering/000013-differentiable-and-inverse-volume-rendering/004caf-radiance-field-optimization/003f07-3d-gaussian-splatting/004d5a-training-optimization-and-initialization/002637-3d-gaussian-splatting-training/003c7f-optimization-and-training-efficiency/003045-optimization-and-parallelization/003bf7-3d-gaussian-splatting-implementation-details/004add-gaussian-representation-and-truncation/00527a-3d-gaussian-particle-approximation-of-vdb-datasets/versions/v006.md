# 3D Gaussian Particle Approximation of VDB Datasets

Also called: Gaussian Particle Approximation, Gaussian Particle Rendering, VDB to Gaussian Conversion

## Overview
This method converts OpenVDB volumetric datasets into a set of non-overlapping 3D Gaussian particles to enable memory-efficient, lossy representation with Level of Detail (LOD) support [S1, unofficial]. It solves the problem of rendering large sparse volumetric data by mapping voxel regions to Gaussian primitives that can be accelerated via hardware ray tracing (NVIDIA OptiX) [S1, unofficial]. Unlike standard Gaussian Splatting which often uses overlapping primitives for neural radiance fields, this approach strictly partitions the volume into non-overlapping Gaussians derived from OpenVDB leaf nodes, allowing compatibility with traditional transfer functions and SciVis rendering pipelines [S1, unofficial].

## How it works

### Inputs and Outputs
*   **Input:** An OpenVDB grid containing scalar values (volumes) or signed distance fields (level sets).
*   **Output:** A set of 3D Gaussian particles defined by mean ($\mu$), covariance ($\Sigma$), and opacity ($\alpha$), stored in device-side buffers for rendering.
*   **Rendering Output:** A 2D image with accumulated color and opacity based on forward ray marching.

### Data Structures

**Gaussian Model (Device-Side)**
The `GaussianModel` object holds contiguous device-side pointers to arrays for each Gaussian property [S1, unofficial]:
1.  **Opacity:** Scalar array. For volumes, this reflects the average scalar value of the voxel region. For level sets, it is uniform [S1, unofficial].
2.  **World Position:** 3D vector array ($\mu$). Derived from the centroid of the voxel region or its bounding box [S1, unofficial].
3.  **Covariance:** 3D vector array (for ellipsoids) or scalar array (for spheres). Defined as the diagonal vector of the $3 \times 3$ covariance matrix $\Sigma$, representing spatial extent along axes [S1, unofficial].

**Acceleration Structures**
*   **Geometry Acceleration Structure (GAS):** Built on the GPU using a CUDA device-side array of Axis-Aligned Bounding Boxes (AABBs). Each AABB encloses a single Gaussian particle, defined by its minimum and maximum coordinates in OpenVDB Index Space [S1, unofficial].
    *   Build Flags: `OPTIX_BUILD_FLAG_ALLOW_COMPACTION`, `OPTIX_BUILD_INPUT_TYPE_CUSTOM_PRIMITIVES` [S1, unofficial].
*   **Instance Acceleration Structure (IAS):** Stores the GAS instance with the OpenVDB Grid transform. Visibility masks are set for all Gaussians to be visible for primary and continuation rays [S1, unofficial].

**OpenVDB Grid Layout (5-4-3 Variant)**
The method assumes a fixed tree depth with the '5-4-3' layout [S1, unofficial]:
*   **5-level (Root/Top):** $2^5 \times 2^5 \times 2^5 = 32,768$ children.
*   **4-level (Intermediate):** $2^4 \times 2^4 \times 2^4 = 4,096$ children.
*   **3-level (Leaf):** $2^3 \times 2^3 \times 2^3 = 512$ voxels.
*   **Masks:** Each node has a Child Mask (1 bit per child, marks active sub-tree) and a Value Mask (1 bit per child, marks "Tile" regions where all voxels share a single value) [S1, unofficial].

### Parameters
*   **LOD Mode:** Low, Medium, or High.
*   **Ray Type:** `RAY_TYPE_RADIANCE` (forward ray marching only) [S1, unofficial].
*   **Max Recursion Depth:** Typically > 10, limited by OptiX register constraints [S1, unofficial].

### Steps

1.  **Data Generation (CPU):**
    *   Retrieve all leaf nodes from the OpenVDB Grid Tree using the OpenVDB API [S1, unofficial].
    *   Skip leaf nodes marked as "Tiles" in the Value Mask, as their data is stored in the parent node [S1, unofficial].
    *   For each active leaf node (or cluster based on LOD), derive Gaussian properties:
        *   **Position:** Centroid of the voxel region [S1, unofficial].
        *   **Opacity:** Average scalar value of the region [S1, unofficial].
        *   **Covariance:** Diagonal vector of $\Sigma$ (axis-aligned) or scalar for spheres [S1, unofficial].
    *   Copy all Gaussian properties to contiguous device-side buffers using `cudaMalloc` and `cudaMemcpy` [S1, unofficial].

2.  **Acceleration Structure Build (GPU):**
    *   Build the GAS using the array of AABBs derived from Gaussian extents in Index Space [S1, unofficial].
    *   Build the IAS with the OpenVDB Grid transform [S1, unofficial].
    *   Add the `GaussianModel` pointer to the OptiX Shader Binding Table (SBT) [S1, unofficial].

3.  **Ray Tracing and Rendering (GPU):**
    *   Shoot primary rays from the camera (`__raygen__`) [S1, unofficial].
    *   **Intersection (`__intersection__`):**
        *   Retrieve the Gaussian AABB using the primitive index [S1, unofficial].
        *   Perform ray-box intersection with the world AABB [S1, unofficial].
        *   If intersected, retrieve $\mu$ and $\Sigma^{-1}$. Transform the ray into the Gaussian's local space.
        *   Solve the quadratic equation for the ellipsoid/sphere to find entry ($t_0$) and exit ($t_1$) distances [S1, unofficial].
        *   Store $t_0, t_1$ in the payload and exit early [S1, unofficial].
    *   **Ray Marching and Accumulation:**
        *   Step along the ray from $t_0$ to $t_1$ using a predefined step size $\Delta t$ [S1, unofficial].
        *   For each sample point $x_k$:
            *   Compute difference $\delta = x_k - \mu$ [S1, unofficial].
            *   Compute squared Mahalanobis distance $D^2 = \delta^T \Sigma^{-1} \delta$ [S1, unofficial].
            *   Evaluate density $\rho_k = \exp(-D^2 / 2)$ [S1, unofficial].
            *   Compute volume factor $V_f = 1 / \det(\Sigma)$ [S1, unofficial].
            *   Compute absorption $A_k = \rho_k \cdot \Delta t \cdot V_f$ [S1, unofficial].
            *   Update color: $C \leftarrow C + T_k \cdot c(\sigma_k) \cdot A_k$ [S1, unofficial].
            *   Update transmittance: $T_{k+1} = T_k \cdot \exp(-A_k)$ [S1, unofficial].
            *   Where $c(\sigma_k)$ is the scattering color derived from opacity via a transfer function (colormap lookup) [S1, unofficial].
    *   **Ray Continuation:**
        *   Advance ray origin: $o_{new} = o + d \cdot (t_1 - t_0)$ [S1, unofficial].
        *   Recursively trace further Gaussians using `optixTrace` until max depth or transmittance threshold is reached [S1, unofficial].

### Pseudocode

```python
# Gaussian Model Data Structures
class GaussianModel:
    opacity: DeviceArray[float]
    position: DeviceArray[Vec3]
    covariance: DeviceArray[Vec3] # Diagonal elements of Sigma

# Ray Payload
class RayPayload:
    color: Vec3
    transmittance: float
    recursion_depth: int

def compute_gaussian_density(sample_point: Vec3, mu: Vec3, inv_cov: Mat3) -> float:
    delta = sample_point - mu
    D2 = dot(delta, multiply(inv_cov, delta))
    return exp(-0.5 * D2)

def render_ray(ray_origin: Vec3, ray_direction: Vec3, max_depth: int) -> Vec3:
    color = Vec3(0.0)
    transmittance = 1.0
    recursion_depth = 0
    
    # Initial world AABB intersection
    t_min, t_max = intersect_world_aabb(ray_origin, ray_direction)
    if t_max < 0:
        return background_color

    while recursion_depth < max_depth:
        # Find next Gaussian intersection
        hit = False
        t0, t1 = t_min, t_max
        gaussian_idx = -1
        
        # Query GAS for next intersection
        # Returns primitive index and t0, t1 if hit
        if gas_intersect(ray_origin, ray_direction, t_min, t_max, gaussian_idx, t0, t1):
            hit = True
        else:
            break # No more intersections
        
        if not hit:
            break

        # Retrieve Gaussian properties
        mu = gaussian_model.position[gaussian_idx]
        cov_diag = gaussian_model.covariance[gaussian_idx]
        alpha = gaussian_model.opacity[gaussian_idx]
        
        # Construct Sigma and Inverse Sigma
        # Sigma is diagonal matrix with cov_diag elements
        inv_cov = inverse(diag(cov_diag))
        det_sigma = product(cov_diag)
        volume_factor = 1.0 / det_sigma
        
        # Ray Marching within the Gaussian bounds [t0, t1]
        # Step size delta_t is predefined or derived from bounds
        delta_t = (t1 - t0) / num_samples 
        
        current_t = t0
        while current_t < t1:
            sample_point = ray_origin + ray_direction * current_t
            
            # Density Evaluation
            density = compute_gaussian_density(sample_point, mu, inv_cov)
            
            # Absorption Calculation
            absorption = density * delta_t * volume_factor
            
            # Radiance Accumulation
            # c(sigma_k) is obtained via transfer function lookup using alpha/density
            scattering_color = transfer_function_lookup(alpha, density)
            
            color += transmittance * scattering_color * absorption
            transmittance *= exp(-absorption)
            
            current_t += delta_t
            
            if transmittance < epsilon:
                break
        
        # Ray Continuation
        ray_origin = ray_origin + ray_direction * t1
        t_min = t1 # Continue from exit point
        recursion_depth += 1
        
        # Recursive trace for subsequent Gaussians
        # Note: In OptiX, this is often done via optixTrace()
        # Here simulated for clarity of logic
        if recursion_depth < max_depth:
            recursive_result = render_ray(ray_origin, ray_direction, max_depth - recursion_depth)
            color += transmittance * recursive_result
            
    return color
```

### Edge Cases and Pitfalls
*   **Non-overlapping Constraint:** The implementation uses non-overlapping Gaussians because OpenVDB leaf nodes are strictly non-overlapping. This limits the model to three overarching refinement levels and introduces lossiness [S1, unofficial]. Overlapping Gaussians are ignored in the current shader, leading to incorrect transparency if attempted [S1, unofficial].
*   **NanoVDB Incompatibility:** NanoVDB does not support device-side traversal of the Grid Tree or device-side iterators. This prevents random access required for ray-BVH or ray-particle intersections in OptiX. Therefore, NanoVDB cannot be used for generation or rendering in this pipeline; OpenVDB must be used on the CPU for generation [S1, unofficial].
*   **OptiX Register Constraint:** Propagating state via recursive `optixTrace` calls is limited by OptiX’s 8-payload register constraint, causing sub-optimal accumulation and inconsistent resetting of payload values [S1, unofficial].
*   **Transfer Functions:** Unlike other Gaussian splatting implementations that bake color into Gaussians, this renderer supports transfer functions via colormap lookups, requiring separate shaders for photorealistic rendering but allowing unified hybrid rendering for SciVis [S1, unofficial].

## Operating characteristics

*   **Time Complexity:** Rendering performance is consistently above 150 FPS for tested datasets (bunny_cloud, explosion, fire, utahteapot, venusstatue, dragon) across all LODs, even with millions of Gaussians [S1, unofficial]. Performance scales with the number of Gaussians and LOD level.
*   **Memory Complexity:** Memory footprint depends on LOD and dataset sparsity.
    *   Example (Dragon Dataset):
        *   High LOD: 546 MB, 23.3M Gaussians [S1, unofficial].
        *   Low LOD: 174.4 MB, 7.4M Gaussians [S1, unofficial].
    *   Storage per Gaussian: Position (3 floats), Covariance (1 float for spheres, 3 for ellipsoids), Opacity (1 float) [S1, unofficial].
*   **Strengths:**
    *   Real-time performance via hardware-accelerated ray tracing (OptiX) [S1, unofficial].
    *   Memory efficiency through sparse VDB representation and LOD [S1, unofficial].
    *   Support for transfer functions and hybrid volume/surface rendering [S1, unofficial].
*   **Limitations:**
    *   Lossy representation due to non-overlapping constraint and LOD clustering [S1, unofficial].
    *   Inability to use NanoVDB for GPU-side generation [S1, unofficial].
    *   Register constraints in OptiX limit complex recursive state propagation [S1, unofficial].
*   **When to use:** Scientific visualization (SciVis) of large sparse volumetric datasets where real-time performance is critical and lossy approximation is acceptable.
*   **When not to use:** Photorealistic rendering requiring high-fidelity overlapping Gaussian mixtures, or when GPU-side VDB traversal is required without CPU preprocessing.

## Background

*   **Origin:** The method was introduced in a study for Scientific Visualization exploring the integration of OpenVDB and NVIDIA OptiX [S1, unofficial].
*   **History:** It builds on the popularity of 3D Gaussian approximation in stereoscopic image-to-3D scene conversion (Gaussian Splatting) [12] and earlier Gaussian mixture models in SciVis [11]. The work specifically addresses the lack of device-side iterators in NanoVDB by using OpenVDB for CPU-side generation [S1, unofficial].
*   **Usage:** Used in NVIDIA OptiX-based rendering engines for forward ray marching of volumetric and level-set data [S1, unofficial].
