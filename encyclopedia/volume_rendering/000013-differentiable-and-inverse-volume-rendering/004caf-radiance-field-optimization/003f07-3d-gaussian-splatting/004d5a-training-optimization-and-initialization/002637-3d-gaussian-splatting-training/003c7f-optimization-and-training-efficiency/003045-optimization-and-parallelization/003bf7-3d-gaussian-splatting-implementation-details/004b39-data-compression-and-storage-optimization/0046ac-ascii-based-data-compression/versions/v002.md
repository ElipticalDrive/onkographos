# ASCII-Based Data Compression
Also called: Anywhere Compression, Base 94 Floating-Point Compression, Base 95 Integer Compression

## Overview
This method accelerates data transmission during the training of 3D Gaussian Splatting models by compressing numerical attributes into ASCII strings [S1, unofficial]. It addresses the bottleneck of transferring large matrices between CPU and GPU or across distributed nodes by reducing the byte count of floating-point and integer values [S1, unofficial]. Unlike [Sensitivity-Aware Vector Clustering](12167-sensitivity-aware-vector-clustering.md) or [Compact 3D Gaussian Representation (C3DGS)](12927-compact-3d-gaussian-representation-c3dgs.md), which focus on reducing the number of primitives or quantizing coefficients, this method preserves the full precision of the Gaussian parameters (except for a specific color matrix optimization) while optimizing the serialization format for speed [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Numerical data (integers or floating-point numbers) representing 3D Gaussian attributes (position, scale, rotation, SH coefficients) and color matrices.
*   **Output:** ASCII-encoded strings for transmission/storage, and decoded numerical values upon receipt.

**Data Structures:**
The method uses standard ASCII character sets. No complex binary packing is used; the output is a sequence of printable ASCII characters.

**Parameters:**
*   **Integer Base:** 95.
*   **Floating-Point Integer Base:** 94.
*   **Separator Character:** ASCII 126 (`~`).
*   **Color Matrix Precision:** 1 decimal place (range [0.0, 2.0]).

**Steps:**

1.  **Integer Compression (Base 95):**
    *   Map integers in the range $[0, 95]$ to ASCII characters in the range $[32, 126]$.
    *   The mapping is a direct base-95 conversion where each character represents a digit in base 95.
    *   *Note:* The source implies a single character encodes the number if it fits in $[0, 95]$. For larger integers, multi-character encoding is implied by the "base 95" description, though specific multi-digit logic is not detailed [S1, unofficial].

2.  **Floating-Point Compression (Base 94):**
    *   Split the floating-point number $f$ into an integer part $I$ and a fractional part.
    *   Encode the integer part $I$ using Base 94, mapping values $[0, 94]$ to ASCII characters $[32, 125]$.
    *   Use the ASCII character 126 (`~`) as a separator between the integer part string and the fractional part string.
    *   *Note:* The source does not specify how the fractional part is encoded. It only states the separator is used to connect the integer part ASCII string and the fractional part ASCII string [S1, unofficial].

3.  **Decoding Integer:**
    *   Convert the ASCII string directly back to a decimal integer using Base 95 decoding.

4.  **Decoding Floating-Point:**
    *   Split the ASCII string at the separator character `~` (ASCII 126).
    *   Let the left part be the ASCII string for the integer component $I$.
    *   Let the right part be the ASCII string for the decimal places $d$.
    *   Calculate the final value $f$ using the formula:
        $$ f = I \times 10^{-d} $$
    *   *Note:* This formula implies that $d$ is interpreted as the number of decimal places (an integer count), not the fractional value itself. For example, if the fractional part string represents "2", then $d=2$, and the value is $I \times 0.01$ [S1, unofficial].

5.  **Color Matrix Optimization:**
    *   Quantize each item in the output color matrix to one decimal place.
    *   The range is restricted to $[0.0, 2.0]$.
    *   This results in 21 possible values per element ($0.0, 0.1, \dots, 2.0$).
    *   Apply ASCII compression to these quantized values to reduce data size significantly [S1, unofficial].

def decode_integer_base95(s):
    """
    Decodes a Base 95 ASCII string to integer.
    """
    value = 0
    for char in s:
        code = ord(char)
        if code < 32 or code > 126:
            raise ValueError("Invalid character for Base 95")
        digit = code - 32
        value = value * 95 + digit
    return value

    quantized = np.round(color_matrix * 10) / 10

    # Map to integer index 0-20
    indices = (quantized * 10).astype(int)
    # Encode indices using Base 95 (or similar ASCII compression)
    # Since range is 0-20, single character is sufficient.
    compressed = []

**Edge Cases and Pitfalls:**
*   **Matrix Traversal:** Compressing large color matrices via ASCII strings is slow due to traversal overhead. Using `torch::where` and `torch::index_select` helps but is not fast enough for full replacement [S1, unofficial].
*   **Line Breaks:** Using line break characters in ASCII strings adds extra operators during writing and decoding, increasing complexity [S1, unofficial].
*   **Precision Loss:** Quantizing color matrices to one decimal place reduces precision but has no explicit impact on final rendering quality [S1, unofficial].
*   **Ambiguity in Floating-Point Encoding:** The source's description of floating-point encoding and the formula $f = I \times 10^{-d}$ is ambiguous regarding how the fractional part is stored and decoded. Implementers must clarify if $d$ is the count of decimal digits or the fractional value itself.

## Operating characteristics
*   **Time Complexity:** The compression/decompression is linear with respect to the number of elements. However, matrix traversal overhead is significant [S1, unofficial].
*   **Memory Complexity:** Reduces storage size by replacing multi-byte floats with single ASCII characters where possible.
*   **Performance:** Gains approximately 6% or less improvement in training speed [S1, unofficial].
*   **Strengths:** Simple implementation; reduces data transmission size; compatible with standard ASCII streams.
*   **Limitations:** Limited speedup (6%); difficult to compress large color matrices efficiently; ambiguous floating-point decoding logic in source; not suitable for high-precision requirements without the color matrix quantization.

## Background
This method was introduced in the context of improving 3D Gaussian Splatting training speed. It is part of the "Anywhere" compression technique described in the paper "I3DGS: Improve 3D Gaussian Splatting from Multiple Dimensions" [S1, unofficial]. The authors explored various dimensions including color, learning, structure design, and compression to find feasible improvements for training speed.
