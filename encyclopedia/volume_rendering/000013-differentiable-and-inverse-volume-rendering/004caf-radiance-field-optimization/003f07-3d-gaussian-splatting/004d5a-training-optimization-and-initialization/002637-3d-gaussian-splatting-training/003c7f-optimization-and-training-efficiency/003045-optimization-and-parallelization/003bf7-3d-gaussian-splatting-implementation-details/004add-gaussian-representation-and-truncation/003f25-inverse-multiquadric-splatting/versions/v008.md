# Inverse Multiquadric Splatting

Also called: 3DIQS, Inverse Multiquadric

## Overview
Inverse Multiquadric Splatting is a rendering technique that replaces the standard Gaussian kernel with an inverse multiquadric radial basis function to determine the spatial decay of a Gaussian splat. It solves the problem of tailing artifacts and over-smoothing inherent in the exponential Gaussian kernel by providing a slower, algebraic decay rate. It differs from its siblings by modifying the kernel function itself rather than just the truncation thresholds or opacity handling, requiring specific corrections to the covariance matrix scaling and gradient computations.

## How it works
**Inputs and Outputs:**
*   **Input:** 3D Gaussian parameters (mean $\mu$, covariance $\Sigma$), camera projection matrix, pixel screen coordinates $p$.
*   **Output:** Alpha value $\alpha$ for the pixel, and gradients for backpropagation.

**Data Structures:**
The method relies on the standard 3D Gaussian Splatting data structures but modifies the forward and backward passes of the CUDA rasterizer.
*   `cov`: 3D covariance matrix (3x3).
*   `cov2D`: 2D covariance matrix (2x2), derived from projecting `cov` using the camera Jacobian.
*   `conic`: The inverse of `cov2D` ($C = \Sigma'^{-1}$), stored as a symmetric matrix with components $(x, y, z, w)$ corresponding to $C_{11}, C_{12}, C_{22}, \det(\Sigma')^{-1}$ or similar packing depending on implementation. In the source code, `con_o` accesses these components.
*   `d`: Displacement vector from the 2D mean $\mu_{2D}$ to the pixel center $p$.

**Parameters:**
*   `correctionFactor`: A scalar multiplier applied to the covariance matrices to adjust the effective width of the splat. Value: $1.38$ [S1].

**Steps:**

1.  **Covariance Correction:**
    Multiply the 3D covariance matrix $\Sigma$ and the projected 2D covariance matrix $\Sigma'$ by the `correctionFactor`.
    $$ \Sigma \leftarrow \Sigma \times 1.38 $$
    $$ \Sigma' \leftarrow \Sigma' \times 1.38 $$
    [S1]

2.  **Compute Conic Matrix:**
    Compute the inverse of the corrected 2D covariance matrix to obtain the conic matrix $C = (\Sigma')^{-1}$.
    [S1]

3.  **Compute Ellipse Term:**
    Calculate the squared Mahalanobis distance (ellipse term) using the conic matrix and the displacement vector $d = p - \mu_{2D}$.
    $$ \text{ellipse} = d^T C d = C_{11} d_x^2 + C_{22} d_y^2 + 2 C_{12} d_x d_y $$
    [S1]

4.  **Boundary Checks:**
    *   If $\text{ellipse} \le 0$, skip the splat (continue). [S1]
    *   If $\text{ellipse} \ge 9$, skip the splat (continue). This limits the effective 2D ellipse size. [S1]

5.  **Compute Inverse Quadric Weight:**
    Calculate the base weight $G$ using the inverse multiquadric function. Note that the general 3D formula involves a parameter $\xi$, but the implementation simplifies this to a standard inverse quadric form where the denominator term $\frac{1}{\xi}$ is effectively 1 or absorbed.
    $$ G = \frac{1}{\text{ellipse} + 1} $$
    [S1]

6.  **Compute Alpha:**
    Combine the Gaussian opacity $\omega$ (stored in `con_o.w`) with the weight $G$. Apply a hard cap to prevent over-saturation.
    $$ \alpha = \min(0.99, \omega \times G) $$
    [S1]

**Pseudocode:**

```python
def inverse_multiquadric_splatting(cov_3d, cov_2d, conic, opacity, pixel_pos, gaussian_mean_2d):
    """
    Forward pass for Inverse Multiquadric Splatting.
    
    Args:
        cov_3d: 3x3 covariance matrix
        cov_2d: 2x2 covariance matrix
        conic: 2x2 inverse covariance matrix (conic matrix C)
        opacity: scalar opacity w
        pixel_pos: 2D pixel coordinate (x, y)
        gaussian_mean_2d: 2D mean coordinate (mu_x, mu_y)
        
    Returns:
        alpha: final alpha value
    """
    correction_factor = 1.38
    
    # Step 1: Apply correction factor to covariances
    # Note: In practice, this is often done during the projection step or 
    # by scaling the conic matrix inversely. The source code scales cov2D directly.
    cov_2d_corrected = cov_2d * correction_factor
    
    # Recompute conic from corrected cov2D if not precomputed, 
    # or scale the existing conic appropriately. 
    # The source code scales cov2D, implying the conic used for ellipse 
    # calculation should reflect this scaling. 
    # However, the code snippet shows:
    # cov2D *= correctionFactor;
    # float ellipse = con_o.x * d.x * d.x ...
    # This implies the conic matrix 'con_o' used in the ellipse calculation 
    # is derived from the scaled cov2D.
    
    # Let's assume conic is computed from cov_2d_corrected
    # C = inv(cov_2d_corrected)
    # For simplicity, we assume 'conic' passed in is already the inverse of the 
    # corrected covariance, or we scale the existing conic.
    # If conic is inv(cov_2d), then inv(cov_2d * k) = inv(cov_2d) / k.
    # So conic_corrected = conic / correction_factor.
    # BUT the source code says: cov2D *= correctionFactor; 
    # and then uses con_o (which comes from cov2D) to compute ellipse.
    # This suggests the conic matrix used for the ellipse term IS the inverse 
    # of the scaled covariance.
    
    # Displacement vector
    d_x = pixel_pos.x - gaussian_mean_2d.x
    d_y = pixel_pos.y - gaussian_mean_2d.y
    
    # Step 3: Compute ellipse term
    # con_o.x = C_11, con_o.z = C_22, con_o.y = C_12
    ellipse = (conic.x * d_x * d_x + 
               conic.z * d_y * d_y + 
               2.0 * conic.y * d_x * d_y)
    
    # Step 4: Boundary checks
    if ellipse <= 0.0:
        return 0.0
    if ellipse >= 9.0:
        return 0.0
        
    # Step 5: Compute inverse quadric weight
    G = 1.0 / (ellipse + 1.0)
    
    # Step 6: Compute alpha
    alpha = min(0.99, opacity * G)
    
    return alpha

def inverse_multiquadric_backward(conic, opacity, ellipse, d_x, d_y, d_alpha):
    """
    Backward pass for Inverse Multiquadric Splatting.
    
    Args:
        conic: 2x2 inverse covariance matrix (conic matrix C)
        opacity: scalar opacity w
        ellipse: precomputed ellipse value
        d_x: displacement x
        d_y: displacement y
        d_alpha: gradient of loss w.r.t alpha
        
    Returns:
        d_mean: gradient w.r.t 2D mean
        d_conic: gradient w.r.t conic matrix
        d_opacity: gradient w.r.t opacity
    """
    correction_factor = 1.38
    
    # Gradient w.r.t G
    # alpha = min(0.99, w * G)
    # If alpha < 0.99, d_alpha/dG = w, d_alpha/dw = G
    # If alpha == 0.99, gradient is 0 (or handled by min function logic)
    # Assuming active region:
    d_G = opacity * d_alpha
    
    # Gradient of G w.r.t ellipse
    # G = 1 / (ellipse + 1)
    # dG/d_ellipse = -1 / (ellipse + 1)^2
    ellipse_plus_1 = ellipse + 1.0
    dG_d_ellipse = -1.0 / (ellipse_plus_1 * ellipse_plus_1)
    
    d_ellipse = d_G * dG_d_ellipse
    
    # Gradient of ellipse w.r.t conic components
    # ellipse = C_11 * dx^2 + C_22 * dy^2 + 2 * C_12 * dx * dy
    # d_ellipse/d_C_11 = dx^2
    # d_ellipse/d_C_22 = dy^2
    # d_ellipse/d_C_12 = 2 * dx * dy
    
    d_conic_x = d_ellipse * (d_x * d_x)
    d_conic_z = d_ellipse * (d_y * d_y)
    d_conic_y = d_ellipse * (2.0 * d_x * d_y)
    
    # Gradient of ellipse w.r.t mean
    # ellipse = d^T C d
    # d_ellipse/d_d = 2 * C * d
    # d_d/d_mu = -1
    # d_ellipse/d_mu_x = -2 * (C_11 * dx + C_12 * dy)
    # d_ellipse/d_mu_y = -2 * (C_12 * dx + C_22 * dy)
    
    d_mu_x = -2.0 * (conic.x * d_x + conic.y * d_y) * d_ellipse
    d_mu_y = -2.0 * (conic.y * d_x + conic.z * d_y) * d_ellipse
    
    # Gradient w.r.t opacity
    # alpha = w * G
    d_opacity = G * d_alpha
    
    # Note: The source code computes gradients w.r.t conic entries directly 
    # using a specific decomposition. The above is the direct analytical gradient.
    # The source code also includes a correction factor in the backward pass 
    # for the covariance matrix gradients, which affects the conic gradients 
    # if the conic is derived from the covariance.
    # The source code snippet:
    # dL_da = correctionFactor * denom2inv * ...
    # This suggests the gradient flows through the covariance scaling.
    # If we are differentiating w.r.t the original covariance, we must account 
    # for the correction factor.
    
    return d_mu_x, d_mu_y, d_conic_x, d_conic_y, d_conic_z, d_opacity
```

**Backward Pass Details:**
The backward pass computes gradients for the mean, conic matrix, and opacity.
1.  Compute $dL/dG = \omega \cdot dL/d\alpha$ [S1].
2.  Compute $dL/d(\text{ellipse})$ using the derivative of the inverse quadric function:
    $$ \frac{\partial G}{\partial \text{ellipse}} = -\frac{1}{(\text{ellipse} + 1)^2} $$
    $$ dL_{d\text{ellipse}} = dL_{dG} \times \frac{-1}{(\text{ellipse} + 1)^2} $$
    [S1]
3.  Compute gradients w.r.t conic components ($C_{11}, C_{12}, C_{22}$) and mean components using the chain rule through the ellipse term. The source code implements this via atomic additions to gradient buffers.
    $$ \frac{\partial G}{\partial d_x} = \frac{\partial G}{\partial \text{ellipse}} \times \frac{\partial \text{ellipse}}{\partial d_x} = \frac{-2}{(\text{ellipse} + 1)^2} (C_{11} d_x + C_{12} d_y) $$
    [S1]
4.  The `correctionFactor` (1.38) is applied to the gradients of the covariance matrix entries during the backward pass to account for the scaling applied in the forward pass. Specifically, if the covariance is scaled by $k$, the gradient w.r.t the original covariance is scaled by $k$. The source code applies `correctionFactor` to the gradient updates for the conic matrix entries. [S1]

## Operating characteristics
*   **Time Complexity:** Same as standard Gaussian Splatting, $O(N)$ per pixel where $N$ is the number of splats, with a constant factor increase due to the algebraic division and square root operations (if any) compared to the exponential function. The boundary check at 9.0 allows for early culling.
*   **Memory Complexity:** Same as standard Gaussian Splatting.
*   **Performance:** The inverse multiquadric function decays slower than the Gaussian, which can lead to better preservation of fine details and less blurring in the tails of the distribution. However, it may require more careful tuning of the correction factor to avoid over-exposure or artifacts.
*   **Strengths:** Reduces the "halo" or "ghosting" artifacts often seen with Gaussian kernels in transparent or thin structures.
*   **Limitations:** The algebraic decay can result in larger effective support, potentially requiring more careful culling or larger bounding boxes. The correction factor is a hyperparameter that needs to be tuned for different scenes.

## Background
Inverse Multiquadric Splatting was introduced in the paper "DARB-Splatting: Generalizing Splatting with Decaying Anisotropic Radial Basis Functions" [S1]. The paper explores various radial basis functions (RBFs) for Gaussian Splatting, including the inverse multiquadric, to improve the quality of rendered scenes by modifying the kernel shape. The method is part of a broader effort to generalize the Gaussian Splatting framework beyond the standard Gaussian kernel.
