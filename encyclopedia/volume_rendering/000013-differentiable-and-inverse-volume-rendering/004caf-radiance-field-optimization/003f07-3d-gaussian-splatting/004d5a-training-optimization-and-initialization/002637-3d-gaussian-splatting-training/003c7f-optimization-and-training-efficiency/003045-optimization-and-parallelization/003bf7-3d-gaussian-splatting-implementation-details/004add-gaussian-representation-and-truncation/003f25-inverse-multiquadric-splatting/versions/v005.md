# Inverse Multiquadric Splatting

Also called: 3DIQS, Inverse Multiquadric

## Overview
Inverse Multiquadric Splatting is a rendering technique that replaces the standard Gaussian radial basis function with an inverse multiquadric function to modulate the opacity of 3D Gaussians during splatting [S1]. It solves the problem of overly sharp or hard-edged Gaussian contributions by providing a smoother, algebraic decay profile, which can improve visual quality in certain scenes [S1]. It differs from standard Gaussian Splatting by using a rational function instead of an exponential decay, and from Opacity-Independent Gaussian Truncation by modifying the basis function itself rather than just the truncation threshold [S1, 10266-opacity-independent-gaussian-truncation.md].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians defined by mean $\mu$, covariance $\Sigma$, opacity $\omega$ (stored as `con_o.w`), and spherical harmonic coefficients. The rasterizer receives the projected 2D conic matrix $C_{2D}$ (inverse of the projected covariance) and the 2D mean $\mu'$.
*   **Output:** The final alpha value $\alpha$ for each pixel covered by a splat, and gradients $\frac{\partial L}{\partial \mu'}$, $\frac{\partial L}{\partial C_{2D}}$, and $\frac{\partial L}{\partial \omega}$ for backpropagation.

**Data Structures:**
The method operates on the standard 3D Gaussian Splatting representation. The 2D conic matrix $C_{2D}$ is a symmetric $2 \times 2$ matrix stored as three floats $(a, b, c)$ corresponding to:
$$ C_{2D} = \begin{bmatrix} a & b \\ b & c \end{bmatrix} $$
where $a = C_{xx}$, $b = C_{xy}$, $c = C_{yy}$. The 2D mean is $\mu' = (\mu'_x, \mu'_y)$.

**Parameters:**
*   `correctionFactor`: A scalar multiplier applied to the covariance matrices to adjust the spatial extent. Value: $1.38$ [S1].
*   `ellipse_max`: The upper bound for the ellipse term to limit the splat size. Value: $9.0$ [S1].
*   `alpha_max`: The maximum opacity value. Value: $0.99$ [S1].

**Formulas:**
The 3D inverse multiquadric function is defined as [S1]:
$$ f(d_M) = \frac{1}{\frac{1}{\xi} (d_M)^2 + 1}, \quad d_M \geq 0 $$
where $\xi$ is a parameter related to the covariance scaling. In the implementation, this is adapted to the 2D projected space. The 2D splat weight $w$ is calculated as [S1]:
$$ w = \frac{1}{\left[ \frac{1}{\xi} (x - \mu')^T (\Sigma'_{2 \times 2})^{-1} (x - \mu') + 1 \right]} $$
Let $z = x - \mu'$. The term $(x - \mu')^T (\Sigma'_{2 \times 2})^{-1} (x - \mu')$ is computed as the `ellipse` value. The final alpha is [S1]:
$$ \alpha = \min(0.99, w \cdot \omega) $$
where $\omega$ is the original opacity parameter (`con_o.w`).

**Steps:**
1.  **Covariance Scaling:** Multiply the 3D covariance matrix $\Sigma$ and the projected 2D covariance matrix $\Sigma'_{2 \times 2}$ by `correctionFactor` ($1.38$) [S1].
2.  **Ellipse Calculation:** Compute the quadratic form `ellipse` using the 2D conic matrix components $(a, b, c)$ and the pixel offset $(d.x, d.y)$ from the 2D mean [S1]:
    $$ \text{ellipse} = a \cdot d.x^2 + c \cdot d.y^2 + 2 \cdot b \cdot d.x \cdot d.y $$
3.  **Boundary Check:** If `ellipse` $\le 0$ or `ellipse` $\ge 9.0$, skip the splat for this pixel [S1].
4.  **Weight Calculation:** Compute the inverse multiquadric weight $G$ (equivalent to $w$ in the formula above, assuming $\xi=1$ in the specific implementation context or absorbed into the conic matrix) [S1]:
    $$ G = \frac{1}{\text{ellipse} + 1} $$
5.  **Alpha Computation:** Compute the final alpha [S1]:
    $$ \alpha = \min(0.99, \omega \cdot G) $$
6.  **Gradient Computation (Backward Pass):**
    *   Compute gradient w.r.t $G$: $dL_dG = \omega \cdot \frac{\partial L}{\partial \alpha}$ [S1].
    *   Compute gradient w.r.t `ellipse`:
        $$ \frac{\partial L}{\partial \text{ellipse}} = \frac{\partial L}{\partial G} \cdot \frac{-1}{(\text{ellipse} + 1)^2} = dL_dG \cdot \frac{-1}{(\text{ellipse} + 1)^2} $$
        *Note: The source code uses a factor of 2 in the gradient update for mean/covariance due to the chain rule on the quadratic form terms, specifically $d.x \cdot d.x$, $d.y \cdot d.y$, and $d.x \cdot d.y$.*
    *   Update gradients for 2D mean $(\mu'_x, \mu'_y)$ and conic matrix $(a, b, c)$ using atomic adds [S1].

**Pseudocode:**
```python
def inverse_multiquadric_splatting(con_o, d, dL_dalpha, dL_dmean2D, dL_dconic2D, global_id):
    """
    con_o: Object containing opacity w and 2D conic matrix components a, b, c.
    d: Vector (d.x, d.y) representing pixel offset from 2D mean.
    dL_dalpha: Gradient of loss w.r.t. alpha.
    dL_dmean2D: Gradient accumulator for 2D mean.
    dL_dconic2D: Gradient accumulator for 2D conic matrix.
    global_id: Unique identifier for the Gaussian primitive.
    """
    # 1. Covariance Scaling (Applied once per Gaussian, not per pixel)
    # cov *= 1.38f
    # cov2D *= 1.38f
    # Note: The conic matrix (inverse covariance) is also scaled. 
    # If cov' = k * cov, then conic' = (k * cov)^-1 = (1/k) * conic.
    # However, the source code applies correctionFactor to cov and cov2D directly.
    # The gradient updates below assume the conic matrix used in ellipse calculation 
    # is the scaled one. The gradients dL_dconic are updated relative to this scaled conic.
    
    a = con_o.a
    b = con_o.b
    c = con_o.c
    omega = con_o.w
    
    # 2. Ellipse Calculation
    dx = d.x
    dy = d.y
    ellipse = a * dx * dx + c * dy * dy + 2.0 * b * dx * dy
    
    # 3. Boundary Check
    if ellipse <= 0.0 or ellipse >= 9.0:
        return

    # 4. Weight Calculation
    G = 1.0 / (ellipse + 1.0)
    
    # 5. Alpha Computation
    alpha = min(0.99, omega * G)
    
    # 6. Gradient Computation
    # Gradient w.r.t alpha is provided as dL_dalpha
    # Gradient w.r.t G
    dL_dG = omega * dL_dalpha
    
    # Gradient w.r.t ellipse
    # dG/d(ellipse) = -1 / (ellipse + 1)^2
    dL_dellipse = dL_dG * (-1.0 / ((ellipse + 1.0) ** 2))
    
    # Gradients w.r.t conic matrix components (a, b, c)
    # ellipse = a*dx^2 + c*dy^2 + 2*b*dx*dy
    # d(ellipse)/da = dx^2
    # d(ellipse)/dc = dy^2
    # d(ellipse)/db = 2*dx*dy
    
    # Update gradients for conic matrix
    # Using atomicAdd for parallel safety
    dL_da = dL_dellipse * (dx * dx)
    dL_dc = dL_dellipse * (dy * dy)
    dL_db = dL_dellipse * (2.0 * dx * dy)
    
    atomic_add(dL_dconic2D[global_id].a, dL_da)
    atomic_add(dL_dconic2D[global_id].b, dL_db)
    atomic_add(dL_dconic2D[global_id].c, dL_dc)
    
    # Gradients w.r.t 2D mean
    # The source code calculates dG_ddelx and dG_ddely directly.
    # dG/dx = dG/d(ellipse) * d(ellipse)/dx
    # d(ellipse)/dx = 2*a*dx + 2*b*dy
    # d(ellipse)/dy = 2*c*dy + 2*b*dx
    
    # However, the source code uses a specific formulation:
    # dG_ddelx = ellipsepow * (d.x * con_o.x + d.y * con_o.y)
    # where ellipsepow = -2 * dL_dG / (ellipse + 1)^2
    # Let's verify:
    # dL_dG is dL/dG.
    # dG/d(ellipse) = -1/(ellipse+1)^2
    # dL/d(ellipse) = dL/dG * dG/d(ellipse) = dL_dG * (-1/(ellipse+1)^2)
    # The source code defines ellipsepow = - dL_dG * 2 / (ellipse+1)^2
    # So dL_dellipse = ellipsepow / 2
    
    # d(ellipse)/dx = 2*a*dx + 2*b*dy = 2*(a*dx + b*dy)
    # dL/dx = dL/d(ellipse) * d(ellipse)/dx = (ellipsepow/2) * 2*(a*dx + b*dy) = ellipsepow * (a*dx + b*dy)
    
    ellipsepow = -2.0 * dL_dG / ((ellipse + 1.0) ** 2)
    
    dL_dx = ellipsepow * (a * dx + b * dy)
    dL_dy = ellipsepow * (b * dx + c * dy)
    
    # Update gradients for 2D mean
    # Note: The source code uses ddelx_dx and ddely_dy which are derivatives of the pixel coordinates w.r.t the mean.
    # In standard rasterization, x_pixel = x_mean + d.x. So d(x_pixel)/d(x_mean) = 1.
    # Thus ddelx_dx = 1, ddely_dy = 1.
    # The gradients are accumulated into dL_dmean2D.
    
    atomic_add(dL_dmean2D[global_id].x, dL_dx)
    atomic_add(dL_dmean2D[global_id].y, dL_dy)
    
    # Gradient w.r.t opacity
    # dL/d(omega) = G * dL/d(alpha)
    dL_domega = G * dL_dalpha
    atomic_add(dL_dopacity[global_id], dL_domega)
```

**Edge Cases and Pitfalls:**
*   **Boundary Check:** The splat is skipped if `ellipse` $\le 0$ or `ellipse` $\ge 9.0$. This prevents numerical instability and limits the splat size [S1].
*   **Covariance Scaling:** The correction factor $1.38$ must be applied to the covariance matrices before projection or during the forward pass to ensure the correct spatial extent [S1].
*   **Gradient Accuracy:** The gradients for the conic matrix and mean must be computed carefully to match the chain rule through the inverse multiquadric function. The source code provides specific implementations for these gradients [S1].

## Operating characteristics
*   **Time Complexity:** Same as standard Gaussian Splatting, $O(N \cdot M)$ where $N$ is the number of Gaussians and $M$ is the number of pixels covered. The additional arithmetic operations for the inverse multiquadric function are constant time per pixel.
*   **Memory Complexity:** Same as standard Gaussian Splatting. No additional memory is required beyond the standard Gaussian parameters and gradients.
*   **Performance:** The method introduces a small computational overhead due to the division and square root operations (if $\xi$ is not 1) compared to the exponential function in standard Gaussian Splatting. However, the boundary check can cull more splats, potentially improving performance in some cases.
*   **Strengths:** Provides a smoother decay profile, which can reduce artifacts in scenes with high-frequency details or sharp edges.
*   **Limitations:** The choice of the correction factor ($1.38$) and the ellipse limit ($9.0$) are empirical and may need tuning for different scenes. The method may not always outperform standard Gaussian Splatting in terms of PSNR or SSIM.

## Background
Inverse Multiquadric Splatting was introduced in the paper "DARB-Splatting: Generalizing Splatting with Decaying Anisotropic Radial Basis Functions" [S1]. The paper explores various radial basis functions for splatting, including the inverse multiquadric, to generalize the standard Gaussian approach. The method is part of the broader effort to improve the visual quality and flexibility of 3D Gaussian Splatting.
