# TideGS Trajectory Ordering

Also called: Clustered TSP ordering for 3DGS, Trajectory-aware view ordering

## Overview
TideGS Trajectory Ordering is a training strategy for 3D Gaussian Splatting that replaces standard randomized view shuffling with a trajectory-aware ordered sequence of views to improve optimization stability and convergence for large-scale scenes [S1, unofficial]. Unlike standard 3DGS which samples views with random shuffling, TideGS uses a clustered traveling-salesperson (TSP) ordering to preserve trajectory continuity, reducing gradient variation between consecutive steps [S1, unofficial]. It builds on [Base 3DGS Optimization](7549-base-3d-gaussian-splatting-optimization.md) by modifying the view sampling schedule while retaining the standard masked update mechanism.

## How it works
**Inputs and Outputs:**
- **Inputs:** A set of $M$ training views with camera poses; the current state of Gaussian parameters $\theta$; a fixed block size $B$.
- **Outputs:** A permutation $\pi$ of view indices; updated parameters $\theta_{t+1}$ after processing one epoch.

**Data Structures:**
1. **Spatial Blocks:** Gaussians are partitioned into $K$ spatial blocks using Morton-code ordering. Each block contains a fixed number of primitives $B$. The block-index universe is $\mathcal{K} = \{0, \dots, K-1\}$. These blocks serve as the basic unit for SSD–CPU–GPU streaming [S1, unofficial].
2. **View Permutation:** An ordered sequence $\pi = (\pi_1, \dots, \pi_M)$ generated by clustered TSP over camera poses. This is a permutation of view indices, not spatial blocks [S1, unofficial].
3. **Active Set $\mathcal{I}_t$:** At iteration $t$, the set of Gaussian indices and parameter coordinates that are visible and selected for update after coarse-to-fine filtering [S1, unofficial].

**Steps:**
1. **Block Partitioning:** Partition all Gaussian primitives into spatial blocks using Morton-code ordering. Each block $k \in \mathcal{K}$ contains exactly $B$ Gaussians [S1, unofficial].
2. **Trajectory Construction:** Apply a clustered traveling-salesperson (TSP) algorithm to the camera poses of the $M$ training views to generate the permutation $\pi = (\pi_1, \dots, \pi_M)$ [S1, unofficial].
3. **Training Loop:** Iterate through the views in the order defined by $\pi$. For each iteration $t$ from $1$ to $M$:
    a. **Block Selection:** Perform coarse block-wise frustum culling to select the working set of blocks $K_t \subseteq \mathcal{K}$ relevant to the current view $\pi_t$ [S1, unofficial].
    b. **Active Set Determination:** Perform coarse-to-fine filtering to determine the Gaussian-level active set $\mathcal{I}_t$. Only Gaussians in the selected blocks that are visible in view $\pi_t$ are included [S1, unofficial].
    c. **Gradient Computation:** Compute the photometric loss $f_{\pi_t}(\theta)$ and its gradient $\nabla f_{\pi_t}(\theta)$ for the active Gaussians [S1, unofficial].
    d. **Masked Update:** Update the parameters using the masked update rule:
       $$
       \theta_{t+1}^{(j)} = \begin{cases} \theta_t^{(j)} - \eta_t \cdot u_t^{(j)}, & j \in \mathcal{I}_t, \\ \theta_t^{(j)}, & \text{otherwise,} \end{cases}
       $$
       where $u_t^{(j)}$ is the optimizer's update direction (e.g., Adam moments) and $\eta_t$ is the learning rate [S1, unofficial].
    e. **State Preservation:** Parameters not in $\mathcal{I}_t$ are not updated, preserving their state and preventing interference from distant regions [S1, unofficial].

**Formulas:**
- **Objective Function:** The goal is to minimize the average photometric loss over $M$ training views:
  $$
  \min_{\theta} F(\theta) := \frac{1}{M} \sum_{i=1}^M f_i(\theta)
  $$
  where $f_i(\theta)$ is the photometric loss for view $i$ and $\theta \in \mathbb{R}^d$ is the concatenation of all Gaussian parameters [S1, unofficial].
- **Gradient-Variation Surrogate:** To analyze ordering stability, the following surrogate measures the squared norm difference between consecutive per-view gradients along the permutation $\pi$:
  $$
  V_\pi(\{\theta_t\}) := \sum_{t=1}^{M-1} \left\| \nabla f_{\pi_t}(\theta_t) - \nabla f_{\pi_{t+1}}(\theta_t) \right\|^2
  $$
  This term is smaller for $\pi_{TSP}$ than for random permutations, indicating reduced gradient drift [S1, unofficial].

**Parameters:**
- $B$: The fixed number of primitives (Gaussians) contained in each spatial block [S1, unofficial].
- $K$: The total number of spatial blocks [S1, unofficial].
- $M$: The total number of training views [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Stale Optimizer State:** Sequentially correlated samples in non-shuffled training may introduce bias or cause optimizer state (e.g., momentum) to become stale or misaligned [S1, unofficial].
- **Mitigation:** The masked update in TideGS acts as a safeguard against stale optimizer state by updating optimizer state only on active coordinates, preventing distant regions from interfering with each other [S1, unofficial].
- **Visibility Sparsity:** Most parameters are untouched at each step. Inactive parameters are not repeatedly perturbed by unrelated views, and their update history is dominated by iterations where they are visible [S1, unofficial].

## Subtopics

## Operating characteristics
- **Time Complexity:** The TSP ordering is computed once during initialization. The training loop processes each view exactly once per epoch, similar to standard 3DGS, but with the overhead of block-wise frustum culling and Morton-code based spatial partitioning [S1, unofficial].
- **Memory Complexity:** Requires storage for spatial blocks and Morton codes. The out-of-core streaming capability allows handling scenes with over one billion primitives by loading only active blocks into GPU memory [S1, unofficial].
- **Performance:** Improves optimization stability and convergence for large-scale scenes by reducing gradient variation between consecutive steps [S1, unofficial].
- **Strengths:** Reduces gradient drift; mitigates stale optimizer state through masked updates; enables scalable training via out-of-core optimization [S1, unofficial].
- **Limitations:** Requires pre-computation of TSP order; relies on visibility-induced sparsity for effectiveness [S1, unofficial].
- **When to use:** Large-scale scenes where standard random shuffling leads to unstable convergence or slow training [S1, unofficial].
- **When not to use:** Small scenes where random shuffling is sufficient and the overhead of TSP ordering is unjustified [S1, unofficial].

## Background
TideGS was introduced in the paper "TideGS: Scalable Training of Over One Billion 3D Gaussian Splatting Primitives via Out-of-Core Optimization" [S1, unofficial]. It departs from standard randomized view order to address scalability and stability issues in large-scale 3D Gaussian Splatting training. The method leverages empirical properties of visibility-induced sparsity and trajectory continuity to improve optimization [S1, unofficial].
