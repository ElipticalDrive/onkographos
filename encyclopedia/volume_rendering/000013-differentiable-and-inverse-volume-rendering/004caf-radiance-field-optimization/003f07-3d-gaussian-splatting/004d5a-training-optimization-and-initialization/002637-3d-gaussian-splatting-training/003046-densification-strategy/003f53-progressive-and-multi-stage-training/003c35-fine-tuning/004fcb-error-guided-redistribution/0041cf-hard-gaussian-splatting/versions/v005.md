# Hard Gaussian Splatting

Also called: REHGS (Rendering Error guided HGS), Rendering Error guided HGS, Rendering Error guided Hard Gaussian Splatting

## Overview
Hard Gaussian Splatting (HGS) is a training optimization strategy for 3D Gaussian Splatting that addresses rendering artifacts caused by the smoothing effect of average view-space positional gradients [S1]. Unlike standard methods that rely on averaged gradients to grow Gaussians, HGS identifies "hard Gaussians"—primitives with significant individual view-space gradients or noticeable local rendering errors—and grows them to recover missing details and reduce blurring [S1]. It sets itself apart from siblings like [Error-Guided Gaussian Reallocation](13012-error-guided-gaussian-reallocation.md) by focusing on *growth* of defective primitives via multi-view gradient analysis and pixel-level error correlation, rather than reallocation or reset [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of 3D Gaussians $\{G_i\}$, a set of training viewpoints, ground truth images, and hyperparameters $\tau_{grad}, M, k, \lambda, \tau_{large}, \tau_{SSIM}$.
*   **Outputs:** An updated set of 3D Gaussians where "hard Gaussians" have been grown (duplicated and perturbed) according to the HGS criteria.

**Data Structures:**
*   **3D Gaussian $G_i$:** Parameterized by mean vector $\mu_i \in \mathbb{R}^3$, covariance matrix $\Sigma_i \in \mathbb{R}^{3 \times 3}$, color $c_i \in \mathbb{R}^3$, and opacity $\alpha_i \in \mathbb{R}$ [S1].
*   **View-space Positional Gradient $g_{i,j}$:** The gradient of the rendering loss with respect to the position of Gaussian $G_i$ under viewpoint $j$ [S1].
*   **Contribution Set $S_i$:** The set of pixels $u$ where Gaussian $G_i$ has the maximum contribution [S1].

**Rendering Model:**
A 3D Gaussian $G_i$ is splatted to a 2D Gaussian $G_{i,2D}$. The pixel color $c(u)$ is computed via alpha-blending [S1]:
$$ c(u) = \sum_{i=1}^{N} w_i c_i, \quad w_i = \alpha_i G_{i,2D}(u) \prod_{k=1}^{i-1} (1 - \alpha_k G_{k,2D}(u)) $$
where $w_i$ is the blending weight [S1].

**Algorithm Steps:**
The method operates within a growth interval of $M$ iterations. It employs two sub-strategies: Positional Gradient Driven HGS (PGHGS) and Rendering Error Guided HGS (REHGS).

1.  **Compute View-Space Positional Gradients:**
    For each Gaussian $G_i$ and each viewpoint $j$ that observes it during the $M$ iterations, compute the view-space positional gradient $g_{i,j}$ [S1].

2.  **Identify Hard Gaussians via PGHGS (Positional Gradient Driven):**
    *   For each Gaussian $G_i$, collect the $n$ view-space positional gradients $\{g_{i,j}\}$ from the $M$ iterations [S1].
    *   Sort these gradients by magnitude and select the $k$ largest values [S1].
    *   Let $g_{min}^{(k)}$ be the minimum value among these $k$ largest gradients [S1].
    *   If $g_{min}^{(k)} \ge \tau_{grad}$, classify $G_i$ as a hard Gaussian candidate [S1].
    *   *Note:* This strategy uncovers Gaussians with significant gradients in multiple views, which are smoothed out by the standard average criterion $\frac{1}{n}\sum ||g_{i,j}|| \ge \tau_{grad}$ [S1].

3.  **Identify Hard Gaussians via REHGS (Rendering Error Guided):**
    *   **Step 3.1: Identify Potentially Over-Large Gaussians.**
        For each pixel $u$ in the training image, compute its rendered index (the Gaussian with maximum contribution) [S1]:
        $$ idx(u) = \arg \max_i w_i $$
        Construct the contribution set $S_i$ for each Gaussian $G_i$:
        $$ S_i = \{ u \mid idx(u) = i, u \in P \} $$
        where $P$ is the set of all pixels in the image [S1].
        Identify $G_i$ as "potentially over-large" if:
        $$ ||S_i|| > \tau_{large} ||P|| $$
        where $||S_i||$ is the number of pixels in the set, and $\tau_{large}$ is a threshold [S1].
    *   **Step 3.2: Verify with Rendering Error.**
        For each potentially over-large Gaussian $G_i$, project it into the current training viewpoint $j$ to obtain the corresponding pixel $u_{i,j}$ [S1].
        Compute the local Structural Similarity Index Measure (SSIM) between the ground truth image $I_j$ and the rendered image $\hat{I}_j$ at $u_{i,j}$ [S1]:
        $$ SSIM(I_j, \hat{I}_j)(u_{i,j}) $$
        If $SSIM(I_j, \hat{I}_j)(u_{i,j}) < \tau_{SSIM}$, classify $G_i$ as a hard Gaussian candidate [S1].
    *   **Step 3.3: Multi-View Consistency Check.**
        Ensure that the hard Gaussian candidate $G_i$ is identified as such in at least two different views during the $M$ iterations. This avoids unstable growth from single-view determination [S1].

4.  **Grow Hard Gaussians:**
    For each identified hard Gaussian $G_i$:
    *   Duplicate $G_i$ to create new Gaussians.
    *   Perturb the position and scale of the new Gaussians to fill the gaps or resolve artifacts [S1].
    *   Reset the optimizer states (momentum, variance) for the new Gaussians to allow rapid convergence [S1] (Shared Principle).

**Parameters:**
*   $\tau_{grad}$: Gradient threshold for Gaussian growing. Maintained same as in Scaffold-GS [S1].
*   $M$: Growing interval for Gaussian growing. Maintained same as in Scaffold-GS [S1].
*   $k$: Index of the largest positional gradient used in PGHGS. Set to 3 [S1].
*   $\lambda$: Constant controlling the extent of excavation in PGHGS. Set to 1.0 [S1].
*   $\tau_{large}$: Threshold to control the extent of potentially large areas for identifying potentially over-large Gaussians. Set to $2 \times 10^{-4}$ [S1].
*   $\tau_{SSIM}$: Threshold to judge rendering quality for identifying hard Gaussians via SSIM. Set to 0.7 [S1].

**Pseudocode:**

```python
def hard_gaussian_splatting(gaussians, viewpoints, ground_truth_images, params):
    """
    gaussians: List of Gaussian objects with attributes mu, Sigma, c, alpha, grad_history
    viewpoints: List of camera parameters
    ground_truth_images: List of ground truth images corresponding to viewpoints
    params: Dictionary containing tau_grad, M, k, tau_large, tau_ssim
    
    Returns:
    updated_gaussians: List of Gaussians with new ones added for hard Gaussians
    """
    tau_grad = params['tau_grad']
    M = params['M']
    k = params['k']
    tau_large = params['tau_large']
    tau_ssim = params['tau_ssim']
    
    # Track hard Gaussian candidates across views
    hard_gaussian_candidates = {} # Map: gaussian_id -> count of views where it was identified
    
    for view_idx, viewpoint in enumerate(viewpoints):
        # 1. Render current view
        rendered_image, contribution_map = render_view(gaussians, viewpoint)
        
        # 2. PGHGS: Check positional gradients
        for g in gaussians:
            # Get positional gradients for this Gaussian in this view
            # Note: grad_history should store gradients from previous M iterations
            # For simplicity, assume we compute current gradient and append
            current_grad = compute_view_space_positional_gradient(g, viewpoint, rendered_image, ground_truth_images[view_idx])
            g.grad_history.append(current_grad)
            
            # Keep only last M gradients
            if len(g.grad_history) > M:
                g.grad_history.pop(0)
                
            # Check if hard via PGHGS
            if len(g.grad_history) == M:
                # Get k largest gradients
                sorted_grads = sorted([norm(grad) for grad in g.grad_history], reverse=True)
                min_of_k_largest = sorted_grads[k-1] # k is 1-indexed in description, 0-indexed in list
                
                if min_of_k_largest >= tau_grad:
                    if g.id not in hard_gaussian_candidates:
                        hard_gaussian_candidates[g.id] = set()
                    hard_gaussian_candidates[g.id].add(view_idx)

        # 3. REHGS: Check rendering errors
        # Identify potentially over-large Gaussians
        image_pixels = get_pixel_coordinates(rendered_image)
        for g in gaussians:
            # Find pixels where this Gaussian has max contribution
            # contribution_map contains (gaussian_id, weight) for each pixel
            s_i = [u for u in image_pixels if contribution_map[u].gaussian_id == g.id]
            
            if len(s_i) > tau_large * len(image_pixels):
                # Potentially over-large
                # Project Gaussian to image to find representative pixel
                # For simplicity, use the first pixel in S_i or centroid
                if s_i:
                    u_i_j = s_i[0] # Representative pixel
                    # Compute local SSIM
                    local_ssim = compute_local_ssim(ground_truth_images[view_idx], rendered_image, u_i_j)
                    
                    if local_ssim < tau_ssim:
                        if g.id not in hard_gaussian_candidates:
                            hard_gaussian_candidates[g.id] = set()
                        hard_gaussian_candidates[g.id].add(view_idx)

    # 4. Grow Hard Gaussians
    new_gaussians = []
    for g_id, views in hard_gaussian_candidates.items():
        # Ensure seen by at least two views
        if len(views) >= 2:
            original_g = gaussians[g_id]
            # Create new Gaussians (duplicates with perturbation)
            # The exact perturbation logic is implementation-specific, 
            # but typically involves copying and adding noise to position/scale
            new_g1 = copy_gaussian(original_g)
            new_g1.mu = perturb_position(new_g1.mu)
            new_g1.scale = perturb_scale(new_g1.scale)
            reset_optimizer_state(new_g1) # Shared Principle
            
            new_g2 = copy_gaussian(original_g)
            new_g2.mu = perturb_position(new_g2.mu)
            new_g2.scale = perturb_scale(new_g2.scale)
            reset_optimizer_state(new_g2) # Shared Principle
            
            new_gaussians.append(new_g1)
            new_gaussians.append(new_g2)
            
    return gaussians + new_gaussians

def compute_view_space_positional_gradient(gaussian, viewpoint, rendered_image, gt_image):
    # Compute gradient of loss w.r.t. Gaussian position
    # This is typically done via backpropagation through the differentiable rasterizer
    loss = compute_loss(rendered_image, gt_image)
    grad = torch.autograd.grad(loss, gaussian.mu, retain_graph=True)[0]
    return grad

def compute_local_ssim(gt_img, pred_img, pixel_u):
    # Compute SSIM in a local window around pixel u
    # Standard SSIM implementation
    window_size = 11
    window = create_gaussian_window(window_size)
    mu1 = conv2d(gt_img, window)
    mu2 = conv2d(pred_img, window)
    mu1_sq = mu1 ** 2
    mu2_sq = mu2 ** 2
    mu1_mu2 = mu1 * mu2
    sigma1_sq = conv2d(gt_img ** 2, window) - mu1_sq
    sigma2_sq = conv2d(pred_img ** 2, window) - mu2_sq
    sigma12 = conv2d(gt_img * pred_img, window) - mu1_mu2
    
    C1 = 0.01 ** 2
    C2 = 0.03 ** 2
    
    ssim_map = ((2 * mu1_mu2 + C1) * (2 * sigma12 + C2)) / \
               ((mu1_sq + mu2_sq + C1) * (sigma1_sq + sigma2_sq + C2))
               
    # Return local SSIM value at pixel u
    # Note: SSIM map is lower resolution, so we might need to upscale or use a smaller window
    # For this pseudocode, we assume a simplified local calculation
    return ssim_map[pixel_u.y, pixel_u.x]
```

## Subtopics

### [PGHGS](10618-pghgs.md)
PGHGS (Positional Gradient driven Hard Gaussian Splatting) is a densification strategy that identifies "hard Gaussians" by analyzing multi-view positional gradients to alleviate cross-view rendering inconsistencies. Unlike standard methods that rely on averaged gradients which may obscure local errors, PGHGS selects Gaussians based on the magnitude of their largest individual view-space gradients, ensuring that regions with significant reconstruction errors are prioritized for growth.

## Operating characteristics
*   **Time Complexity:** The method adds overhead to the training loop by requiring the computation of per-pixel contribution maps and local SSIM calculations for potentially over-large Gaussians. The SSIM calculation is computationally expensive, but it is only performed for Gaussians exceeding the $\tau_{large}$ threshold, which is sparse [S1].
*   **Memory Complexity:** Requires storing the gradient history for each Gaussian over $M$ iterations and the contribution map for each view during the growth interval [S1].
*   **Measured Performance:** On Tanks&Temples, REHGS with $\tau_{SSIM}=0.7$ yields PSNR 26.36, SSIM 0.880, LPIPS 0.126 [S1]. Lowering $\tau_{SSIM}$ to 0.6 reduces PSNR to 26.34, while raising it to 0.8 increases PSNR to 26.39 [S1].
*   **Strengths:** Effectively resolves blurring and needle-like artifacts by targeting hard Gaussians that standard averaging misses [S1]. It robustly identifies noticeable pixel rendering errors across views [S1].
*   **Limitations:** REHGS tends to find noticeable rendering errors but cannot detect some inconspicuous artifacts, which PGHGS probes better [S1]. Using only the potentially over-large condition results in false positives in low-textured or repetitive texture areas [S1].
*   **When to use:** Use when standard 3DGS exhibits strong spurious artifacts due to smoothed gradients or blurring in complex scenes [S1].
*   **When not to use:** Avoid if computational resources are extremely limited, as SSIM calculation adds overhead. Also, if the scene has very few viewpoints, the multi-view consistency check may fail to identify hard Gaussians [S1].

## Background
Hard Gaussian Splatting (HGS) was proposed to address the limitations of standard 3D Gaussian Splatting (3DGS) in handling challenging areas with strong artifacts [S1]. Standard 3DGS relies on the average magnitude of view-space positional gradients to grow Gaussians, which smooths gradients from different viewpoints and hinders the growth of defective Gaussians [S1]. HGS was introduced to uncover hard Gaussians from multi-view significant positional gradients and rendering errors, thereby improving Novel View Synthesis (NVS) results [S1]. The method builds upon Scaffold-GS, maintaining the same threshold $\tau_{grad}$ and growing interval $M$ [S1].
