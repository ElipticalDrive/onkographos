# PixelGS Densification Criteria

Also called: Pixel-aware and Depth-scaled Gradient Densification

## Overview
PixelGS Densification Criteria modifies the gradient-based densification strategy of 3D Gaussian Splatting to be related to the number of pixels each Gaussian influences [S1]. It scales the positional gradient by the pixel count and applies a depth-dependent scaling factor to encourage densification in background regions while reducing it in foreground regions [S1]. The method achieves state-of-the-art rendering quality at the cost of considerably more Gaussian primitives [S1].

## How it works
**Inputs:**
- Set of 3D Gaussians $\{g_k\}$ [S1].
- For each Gaussian $k$ and view $\nu$:
  - $\text{count}(g_k^\nu)$: The number of pixels influenced by Gaussian $k$ in view $\nu$ [S1].
  - $\text{depth}(g_k^\nu)$: The image depth of the rendered splat for Gaussian $k$ in view $\nu$ [S1].
  - $\left\| \frac{\partial \mathcal{L}(I_\nu, f'_\nu)}{\partial \mu_k^\nu} \right\|_2$: The 2D positional gradient norm of the loss $\mathcal{L}$ with respect to the mean $\mu_k$ of Gaussian $k$ in view $\nu$ [S1].
- Hyperparameters:
  - $\gamma$: Depth scaling hyperparameter (default 0.37) [S1].
  - $e_{\text{scene}}$: The extent of the scene [S1].
  - $N_{\text{views}}$: Total number of training views [S1].

**Outputs:**
- $\tau'_k$: The refined gradient value for Gaussian $k$, used to determine if densification (splitting or cloning) should occur [S1].

**Data Structures:**
- Not given in the sources. Standard per-Gaussian accumulators for the gradient norm and pixel count across views are sufficient [G].

**Steps:**
1. For each Gaussian $k$ and each view $\nu \in \{1, \dots, N_{\text{views}}\}$:
   a. Compute the depth-scaling factor $f_k^\nu$ using the clipped ratio of the splat's image depth to the product of $\gamma$ and $e_{\text{scene}}$ [S1].
   b. Accumulate the weighted gradient contribution by multiplying $f_k^\nu$, $\text{count}(g_k^\nu)$, and the 2D positional gradient norm [S1].
2. Compute the final refined gradient $\tau'_k$ by dividing the sum of weighted contributions by the sum of pixel counts across all views [S1].
3. Compare $\tau'_k$ against a threshold to decide on densification [G].

**Formulas:**

The depth-scaling factor $f_k^\nu$ for Gaussian $k$ in view $\nu$ is defined as [S1]:

$$
f_k^\nu = \text{clip} \left( \frac{\text{depth}(g_k^\nu)}{\gamma \cdot e_{\text{scene}}}, [0, 1] \right)
$$

where:
- $\text{depth}(g_k^\nu)$ is the image depth of the rendered splat [S1].
- $\gamma$ is the hyperparameter (default 0.37) [S1].
- $e_{\text{scene}}$ is the scene extent [S1].
- $\text{clip}(x, [a, b])$ clamps $x$ to the range $[a, b]$ [G].

The refined gradient $\tau'_k$ is calculated as [S1]:

$$
\tau'_k = \frac{\sum_{\nu=1}^{N_{\text{views}}} f_k^\nu \cdot \text{count}(g_k^\nu) \cdot \left\| \frac{\partial \mathcal{L}(I_\nu, f'_\nu)}{\partial \mu_k^\nu} \right\|_2}{\sum_{\nu=1}^{N_{\text{views}}} \text{count}(g_k^\nu)}
$$

where:
- $\text{count}(g_k^\nu)$ is the number of pixels influenced by Gaussian $k$ in view $\nu$ [S1].
- $\left\| \frac{\partial \mathcal{L}(I_\nu, f'_\nu)}{\partial \mu_k^\nu} \right\|_2$ is the 2D positional gradient norm [S1].

**Pseudocode:**

```python
def compute_pixelgs_densification_criteria(gaussians, views, pixel_counts, rendered_depths, grad_norms, gamma=0.37, scene_extent=None):
    """
    Computes the refined gradient tau'_k for each Gaussian k using PixelGS criteria.
    
    Args:
        gaussians: List of Gaussian objects, each having an id 'k'.
        views: List of view objects, each having an id 'nu'.
        pixel_counts: Dict mapping (k, nu) to count(g_k^nu).
        rendered_depths: Dict mapping (k, nu) to depth(g_k^nu).
        grad_norms: Dict mapping (k, nu) to ||dL/dmu_k^nu||_2.
        gamma: Depth scaling hyperparameter.
        scene_extent: The extent of the scene.
        
    Returns:
        dict: Mapping of Gaussian id 'k' to refined gradient tau'_k.
    """
    weighted_gradient_sum = {g.id: 0.0 for g in gaussians}
    pixel_count_sum = {g.id: 0.0 for g in gaussians}

    for g in gaussians:
        k = g.id
        for nu in views:
            nu_id = nu.id
            count = pixel_counts[(k, nu_id)]
            depth = rendered_depths[(k, nu_id)]
            grad_norm = grad_norms[(k, nu_id)]

            if scene_extent is None:
                raise ValueError("scene_extent must be provided to compute depth scaling.")

            depth_scale = depth / (gamma * scene_extent)
            f_k_nu = max(0.0, min(1.0, depth_scale))

            weighted_gradient_sum[k] += f_k_nu * count * grad_norm
            pixel_count_sum[k] += count

    results = {}
    for k in weighted_gradient_sum:
        total_count = pixel_count_sum[k]
        if total_count == 0:
            results[k] = 0.0
        else:
            results[k] = weighted_gradient_sum[k] / total_count
    return results
```

**Edge Cases and Pitfalls:**
- **Zero Visibility:** If a Gaussian is not visible in any view, $\text{count}(g_k^\nu)$ is 0 for all $\nu$ [S1]. The denominator becomes 0 [G]. The implementation must handle this division by zero, typically by assigning a gradient of 0 or skipping densification for that Gaussian [G].
- **Depth Scaling Range:** The depth scaling factor is clamped to $[0, 1]$ [S1]. If $\text{depth}(g_k^\nu)$ is very small (foreground), $f_k^\nu$ approaches 0, suppressing densification [S1]. If it is large (background), $f_k^\nu$ approaches 1, encouraging densification [S1].
- **Hyperparameter Sensitivity:** The value of $\gamma$ (default 0.37) directly controls the depth threshold [S1]. The exact sensitivity is not quantified in the sources [G].

## Operating characteristics
- **Time Complexity:** The computation adds a linear pass over the Gaussians and views to accumulate the weighted gradients and pixel counts [G]. This is negligible compared to the rasterization and gradient computation steps of the main training loop [G].
- **Memory Complexity:** Requires storing two accumulators per Gaussian (weighted gradient sum and pixel count sum) across views [G]. This is minimal additional memory overhead [G].
- **Performance:** PixelGS yields state-of-the-art rendering quality compared to other densification strategies [S1].
- **Trade-offs:** The primary cost is a considerably higher number of Gaussian primitives [S1]. The method encourages densification in background regions, which increases the total primitive count compared to methods that do not use depth scaling [S1].
- **When to use:** Use when rendering quality is the primary metric and increased memory/compute for a larger number of Gaussians is acceptable [S1].
- **When not to use:** Use when memory or rendering speed is constrained, as the increased number of primitives will increase memory usage and potentially slow down rendering [G].

## Background
PixelGS Densification Criteria was proposed by Zhang et al. in the context of PixelGS [S1]. It builds upon the adaptive density control of 3D Gaussian Splatting and incorporates ideas similar to Bulo et al. (2024) regarding pixel-weighted gradients [S1]. The method was introduced to improve rendering quality by better handling the distribution of Gaussians in depth, specifically addressing the tendency of standard 3DGS to under-densify background regions [S1].
