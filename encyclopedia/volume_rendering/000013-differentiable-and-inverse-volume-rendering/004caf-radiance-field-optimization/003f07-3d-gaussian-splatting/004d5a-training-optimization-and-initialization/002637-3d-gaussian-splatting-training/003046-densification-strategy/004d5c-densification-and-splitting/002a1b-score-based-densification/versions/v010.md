# Score-based Densification

Also called: Budget-constrained Optimization, Guided Densification

## Overview
Score-based Densification is a constructive training strategy for 3D Gaussian Splatting that controls model size by adding new primitives only where they improve reconstruction quality, adhering to a strict user-defined budget without requiring pruning or culling [S1]. It differs from standard 3D Gaussian Splatting by replacing fixed-step densification with a guided, score-driven schedule that ensures predictable storage demands and training times [S1].

## How it works
**Inputs:** A set of training views, initial Gaussian primitives, a target model size budget $B$, and a growth curve function $G(t)$.
**Outputs:** A set of Gaussian primitives with size $|G| \le B$.

**Data Structures:**
*   **Gaussian Primitive:** Stores position $\mathbf{p}$, covariance $\mathbf{\Sigma}$ (or rotation $\mathbf{R}$ and scale $\mathbf{s}$), opacity $\alpha$, and spherical harmonic coefficients for color.
*   **Score Buffer:** A scalar value $S_g$ for each Gaussian $g$, initialized to zero.

**Steps:**
1.  **Sample Views:** Select a batch of training images for the current iteration.
2.  **Compute Saliency:** Render the current Gaussians and compute per-pixel saliency maps. Saliency identifies regions where the rendered image differs significantly from the ground truth or where gradients are high [S1].
3.  **Compute Per-Gaussian Score ($S_g$):** For each Gaussian $g$, aggregate metrics across all sampled views where it contributes to the image. The score $S_g$ is computed using a scoring function $F$:
    $$ S_g = F(\nabla L, \text{Saliency}, \text{Properties}) $$
    Where:
    *   $\nabla L$ is the gradient of the loss with respect to the Gaussian's parameters.
    *   $\text{Saliency}$ is the accumulated saliency value projected onto the Gaussian.
    *   $\text{Properties}$ are intrinsic Gaussian attributes (e.g., scale, opacity) [S1].
    *   *Note: The exact mathematical form of $F$ is not specified in the sources, but it combines these three components [S1].*
4.  **Determine Budget:** Calculate the allowed number of Gaussians for the current training step $t$ using the growth curve $G(t)$, which mimics the original 3D Gaussian Splatting behavior but is fitted to reach the exact budget $B$ at the end of training [S1].
5.  **Select Top-Scoring Gaussians:** Identify the Gaussians with the highest $S_g$ values. The number of Gaussians to densify is determined by the difference between the current count and the budget $G(t)$ [S1].
6.  **Densify:** For each selected Gaussian, spawn new Gaussians in its vicinity. The sources do not specify the exact perturbation method (e.g., random noise, cloning with jitter) [G].
7.  **Update:** Continue training with the new set of Gaussians. Repeat until the budget is reached or training completes [S1].

**Parameters:**
*   **Budget ($B$):** The target final number of Gaussians. Typical values depend on the scene resolution and desired quality, but the method allows any user-defined value [S1].
*   **Growth Curve:** A function $G(t)$ that dictates the number of Gaussians at iteration $t$. It is fitted to match the original 3D Gaussian Splatting densification schedule but capped at $B$ [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** The scoring function must be numerically stable to avoid oscillations in densification decisions [S1].
*   **Degenerate Input:** If saliency is zero everywhere (e.g., uniform background), densification may stall. The method assumes non-trivial training data [S1].

## Subtopics

### [Pixel-GS](9189-pixel-gs.md)
Pixel-GS is a variant that scales the densification gradient by the number of pixels a Gaussian influences, prioritizing primitives that cause errors across many pixels. It accounts for projected area and depth, yielding higher quality than standard score-based methods at the cost of a larger primitive count.

### Perceptual-GS
Perceptual-GS replaces the gradient-based score with a scene-adaptive perceptual signal to improve detail in visually salient areas [S2, unofficial]. It computes a local perceptual error map using a lightweight vision-transformer head and densifies only where the Structural Similarity Index Measure (SSIM) falls below a dynamic threshold [S2, unofficial].

### Late Densification
Late Densification is a timing strategy that enables densification in a narrow window between iterations 20,000 and 20,500, occurring every 100 iterations, to help the model recover loss from the pruning of false-positive Gaussians [S3].

## Operating characteristics
*   **Time Complexity:** Training time is reduced compared to standard 3D Gaussian Splatting due to fewer redundant primitives and optimized gradient computation [S1].
*   **Memory Complexity:** Memory usage is strictly bounded by the user-defined budget $B$, preventing unpredictable storage demands [S1].
*   **Performance:** The method achieves high-quality novel-view synthesis with significantly lower storage requirements than unconstrained 3D Gaussian Splatting [S1].
*   **Strengths:** Predictable model size, no need for pruning, controlled optimization trajectory [S1].
*   **Limitations:** Requires careful tuning of the growth curve and scoring function; may not capture fine details as effectively as unconstrained methods if the budget is too low [S1].

## Background
Score-based Densification was introduced to address the challenges of training 3D Gaussian Splatting models on a budget, specifically the unpredictable size and training duration [S1]. It builds on the original 3D Gaussian Splatting densification pipeline but introduces a guided, constructive approach to primitive addition [S1]. The method acknowledges concurrent work on revising densification strategies [S1].
