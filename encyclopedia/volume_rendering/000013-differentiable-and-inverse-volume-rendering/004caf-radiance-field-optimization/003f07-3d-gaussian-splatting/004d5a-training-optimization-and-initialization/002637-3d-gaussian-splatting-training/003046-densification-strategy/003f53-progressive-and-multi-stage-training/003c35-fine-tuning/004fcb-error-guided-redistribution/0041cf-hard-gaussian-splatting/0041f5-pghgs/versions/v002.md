# PGHGS

Also called: Positional Gradient driven HGS, Positional Gradient driven Hard Gaussian Splatting

## Overview
PGHGS (Positional Gradient driven Hard Gaussian Splatting) is a densification strategy that identifies "hard Gaussians" by analyzing multi-view positional gradients to alleviate cross-view rendering inconsistencies [S1]. Unlike standard methods that rely on averaged gradients which may obscure local errors, PGHGS selects Gaussians based on the magnitude of their largest individual view-space gradients, ensuring that regions with significant reconstruction errors are prioritized for growth [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A set of $N$ Gaussians $\{G_i\}$, their current parameters, and the accumulated view-space positional gradients $\{g_{i,j}\}$ for each Gaussian $G_i$ across $M$ training iterations/views [S1].
*   **Output:** A subset of Gaussians identified as "hard Gaussians" to be densified (cloned/split) in the current growth interval [S1].

**Data Structures**
*   **Positional Gradients:** For each Gaussian $G_i$, a list of gradients $g_{i,j}$ corresponding to different viewpoints $j$ [S1]. The gradient $g_{i,j}$ is a vector in view space [G].
*   **Sorted Gradients:** A sorted list $\{g'_{i,1}, \dots, g'_{i,n}\}$ for each Gaussian, ordered by descending norm [S1].

**Method Steps**
1.  **Compute View-Space Positional Gradients:**
    For each Gaussian $G_i$ and each viewpoint $j$, compute the view-space positional gradient $g_{i,j}$ using the rendering error [S1]:
    $$g_{i,j} = \frac{1}{||P||} \sum_{u \in P} e_u \frac{\partial L_j}{\partial \mu_{i,j}}$$
    Where:
    *   $L_j$ is the rendering loss under viewpoint $j$ [S1].
    *   $\mu_{i,j}$ is the pixel-space projection point of Gaussian $G_i$ under viewpoint $j$ [S1].
    *   $P$ is the set of total pixel coordinates [S1].
    *   $e_u$ is the rendering error of pixel $u$ [S1].
    *   $||P||$ is the number of pixels [G].
    *   The sources define this as the gradient of the average rendering error with respect to the view-space projection point [S1].

2.  **Sort Gradients:**
    For each Gaussian $G_i$, sort its $n$ positional gradients across all views in descending order of their norms [S1]:
    $$\{g'_{i,1}, \dots, g'_{i,n}\} = \text{sort}_{\downarrow}(g_{i,1}, \dots, g_{i,n})$$
    Where $g'_{i,k}$ is the $k$-th largest positional gradient for Gaussian $G_i$ [S1].

3.  **Mine Hard Gaussians:**
    A Gaussian $G_i$ is selected as a hard Gaussian if its $k$-th largest positional gradient satisfies the threshold condition [S1]:
    $$||g'_{i,k}|| \ge \lambda \tau_{grad}$$
    Where:
    *   $k$ is the number of significant positional gradients considered in the growth interval [S1].
    *   $\lambda$ is a weight constant controlling the extent of excavation [S1].
    *   $\tau_{grad}$ is the base gradient threshold [G].

**Parameters**
*   **$k$:** The rank of the gradient used for selection. Tested values are 1, 2, 3, 4 [S1]. Lower $k$ relaxes the criterion, producing more growing Gaussians [S1]. Higher $k$ degrades metrics because PGHGS cannot mine hard Gaussians sufficiently when $k$ is too large [S1].
*   **$\lambda$:** Weight for the threshold. Lower $\lambda$ allows mining more hard Gaussians, improving rendering quality but reducing training efficiency [S1]. Higher $\lambda$ degrades PSNR, SSIM, and LPIPS while improving training efficiency [S1].
*   **$\tau_{grad}$:** The gradient threshold. Lowering $\tau_{grad}$ to encourage more growth prioritizes well-reconstructed areas, introducing redundant Gaussians and failing to reduce artifacts [S1].

**Edge Cases and Pitfalls**
*   Lowering $\tau_{grad}$ prioritizes densifying well-reconstructed areas, which introduces redundant Gaussians and fails to reduce artifacts [S1].
*   Reducing $k$ introduces noise that impairs PSNR but improves LPIPS, because LPIPS is evaluated through deep image features which have anti-noise ability [S1].
*   Increasing $k$ degrades almost all rendering metrics [S1].

**Pseudocode**
```python
import math

def select_hard_gaussians(gaussians, gradients, k, lambda_val, tau_grad):
    """
    Select hard Gaussians based on positional gradients.
    
    Args:
        gaussians: List of Gaussian objects with an 'id' attribute.
        gradients: Dict mapping gaussian_id to list of gradient vectors (one per view).
        k: Integer, rank of gradient to check.
        lambda_val: Float, threshold weight.
        tau_grad: Float, base gradient threshold.
        
    Returns:
        List of Gaussian objects identified as hard.
    """
    hard_gaussians = []
    
    for g in gaussians:
        # Get gradients for this Gaussian across all views
        g_grads = gradients[g.id]
        
        # Sort gradients by norm in descending order
        sorted_grads = sorted(g_grads, key=lambda vec: math.sqrt(sum(x**2 for x in vec)), reverse=True)
        
        # Ensure we have at least k gradients; if not, use the largest available
        if len(sorted_grads) >= k:
            kth_largest_grad = sorted_grads[k-1]
        else:
            kth_largest_grad = sorted_grads[-1]
            
        # Check condition: ||g'_i,k|| >= lambda * tau_grad
        if math.sqrt(sum(x**2 for x in kth_largest_grad)) >= lambda_val * tau_grad:
            hard_gaussians.append(g)
            
    return hard_gaussians
```

## Subtopics

### Efficient Hard Gaussian Splatting
An efficient variant of HGS that adaptively controls the number of hard Gaussians to balance rendering quality and efficiency [S1]. It counts the percentage of Gaussians selected by the original growing criterion (Eq. 4) in each growth interval, denoted as $Q$ [S1]. During PGHGS, it chooses the top $Q$ Gaussians as hard ones for growing based on the sorted positional gradients $\{g'_{i,k} | i = 1, \dots, N\}$ [S1].

## Operating characteristics
**Time and Memory Complexity**
*   **Time:** Sorting gradients for each Gaussian adds overhead proportional to $O(N \cdot M \log M)$, where $N$ is the number of Gaussians and $M$ is the number of views/iterations [G]. Lower $\lambda$ increases the number of hard Gaussians, which increases training time due to more splatting and optimization [S1].
*   **Memory:** Requires storing positional gradients for each Gaussian across views [S1].

**Measured Performance**
*   **Tanks&Temples Ablation (k variation):**
    *   $k=1$: PSNR 26.34, SSIM 0.880, LPIPS 0.123 [S1].
    *   $k=2$: PSNR 26.36, SSIM 0.880, LPIPS 0.126 [S1].
    *   $k=3$: PSNR 26.26, SSIM 0.878, LPIPS 0.131 [S1].
    *   $k=4$: PSNR 26.36, SSIM 0.880, LPIPS 0.126 [S1].
*   **Deep Blending Ablation (k variation):**
    *   $k=1$: PSNR 30.31, SSIM 0.906, LPIPS 0.211 [S1].
    *   $k=2$: PSNR 30.39, SSIM 0.908, LPIPS 0.219 [S1].
    *   $k=3$: PSNR 30.40, SSIM 0.908, LPIPS 0.225 [S1].
    *   $k=4$: PSNR 30.19, SSIM 0.908, LPIPS 0.230 [S1].

**Strengths and Limitations**
*   **Strengths:** Reduces cross-view rendering inconsistency by focusing on local errors rather than averages [S1]. Reducing $k$ can improve LPIPS (due to anti-noise ability of deep features) though it may degrade PSNR [S1].
*   **Limitations:** Lowering $\tau_{grad}$ introduces redundant Gaussians in well-reconstructed areas [S1]. Increasing $k$ degrades almost all rendering metrics [S1]. Higher $\lambda$ improves efficiency but degrades quality [S1].

## Background
PGHGS was introduced in "Pushing Rendering Boundaries: Hard Gaussian Splatting" [S1]. It addresses the limitation of standard positional gradients, which average errors over the entire image and fail to reflect local reconstruction errors, preventing Gaussians from growing in regions with larger local errors [S1].
