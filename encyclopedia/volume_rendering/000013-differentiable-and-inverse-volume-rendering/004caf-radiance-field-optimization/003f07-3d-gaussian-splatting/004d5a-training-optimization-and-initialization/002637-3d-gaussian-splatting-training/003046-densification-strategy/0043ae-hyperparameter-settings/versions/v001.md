# Hyperparameter Settings

Also called: Optimizer and Regularization Settings, Optimizer settings, Phys3DGS Hyperparameter Settings, Training Hyperparameters

## Overview
Hyperparameter Settings define the numerical configuration for the differentiable optimization loop in 3D Gaussian Splatting variants, specifically governing the Adam optimizer, learning rates for geometric and photometric parameters, and regularization strengths. This method ensures stable convergence by preventing gradient overflow and material-lighting ambiguities, distinguishing itself from sibling methods by explicitly tuning regularizers for physically-based rendering (PBR) components like roughness and metallic, or by using indirect depth optimization for dynamic scenes.

## How it works
The method configures the training loop inputs (scene data, initial Gaussian set) and outputs (optimized Gaussian attributes: position, scale, rotation, opacity, SH coefficients, and material properties).

### Data Structures and Parameters
The optimizer state maintains per-parameter learning rates and momentum buffers. Key hyperparameters include:
*   **Optimizer:** Adam with $\beta_1=0.9$, $\beta_2=0.999$, $\epsilon=10^{-15}$ [S1][S2, unofficial].
*   **Learning Rates (LR):** Specific values for each Gaussian attribute [S2, unofficial].
*   **Regularization Strengths:** Weights for smoothness and other constraints [S2, unofficial].
*   **Loss Weights:** Balancing terms for multi-task losses (e.g., RGB vs. Depth) [S1].

### Numbered Steps
1.  **Initialization:**
    *   Initialize Gaussian positions, scales, rotations, and opacities (see [Densification Strategy](6234-densification-strategy.md)).
    *   Initialize material properties (e.g., reflectivity $\rho=0.1$) [S1].
    *   Initialize MLP weights (if used for deformation) from $\mathcal{N}(0, 10^{-5})$ [S1].
2.  **Forward Pass:**
    *   Render the scene using the differentiable rasterizer.
    *   Compute loss $\mathcal{L}$ (e.g., RGB loss, C-ToF quad loss, or PBR reconstruction error) [S1][S2, unofficial].
3.  **Regularization Application:**
    *   Apply smoothness penalties to base color, metallic, and roughness with $\lambda_{smooth}$ values [S2, unofficial].
    *   Apply other regularizers ($\lambda_o, \lambda_{sc}, \lambda_{sr}$) with strength 1.0 [S2, unofficial].
4.  **Backward Pass:**
    *   Compute gradients $\nabla \mathcal{L}$ for all learnable parameters.
5.  **Optimizer Step:**
    *   Update parameters using Adam with the specific learning rates defined below.
    *   Decay MLP learning rate exponentially if applicable [S1].

### Formulas and Values
**Learning Rates (Phys3DGS):**
| Parameter | Learning Rate |
| :--- | :--- |
| Position | $1.6 \times 10^{-4}$ |
| Color SH | $2.5 \times 10^{-3}$ |
| Scale | $5 \times 10^{-3}$ |
| Opacity | $5 \times 10^{-2}$ |
| Base Color | $1 \times 10^{-2}$ |
| Metallic | $1 \times 10^{-2}$ |
| Roughness | $1 \times 10^{-2}$ |
| Normal Rotation | $1 \times 10^{-3}$ |
| Direct Light SH (deg=0) | $2.5 \times 10^{-3}$ |
| Direct Light SH (deg>0) | $1 \times 10^{-4}$ |
| Indirect Light SH (deg=0) | $2.5 \times 10^{-4}$ |
| Indirect Light SH (deg>0) | $1 \times 10^{-3}$ |
| Visibility SH | $0.1$ |

**Regularization Strengths (Phys3DGS):**
*   $\lambda_{smooth}$ (Base Color) = 0.06
*   $\lambda_{smooth}$ (Metallic) = 0.02
*   $\lambda_{smooth}$ (Roughness) = 0.02
*   $\lambda_o, \lambda_{sc}, \lambda_{sr} = 1.0$ [S2, unofficial]

**Loss Weights (ToRF):**
*   $\alpha = 5$ (for real-world scenes), $\alpha = 1$ (for synthetic) [S1].
*   $\beta = 0.0008$ [S1].

**MLP Decay (ToRF):**
*   $\gamma_{MLP}$ starts at $0.0008$ and decays to $1.6 \times 10^{-6}$ over 60,000 iterations [S1].

# Learning rates (Phys3DGS example)

LR_SCALE = 5e-3
LR_OPACITY = 5e-2
LR_BASE_COLOR = 1e-2
LR_METALLIC = 1e-2
LR_ROUGHNESS = 1e-2
LR_NORMAL_ROTATION = 1e-3
LR_DIRECT_LIGHT_SH_0 = 2.5e-3
LR_DIRECT_LIGHT_SH_GT0 = 1e-4
LR_INDIRECT_LIGHT_SH_0 = 2.5e-4
LR_INDIRECT_LIGHT_SH_GT0 = 1e-3
LR_VISIBILITY_SH = 0.1

# Regularization weights (Phys3DGS example)
LAMBDA_SMOOTH_COLOR = 0.06
LAMBDA_SMOOTH_METALLIC = 0.02
LAMBDA_SMOOTH_ROUGHNESS = 0.02
LAMBDA_OTHER = 1.0

# ToRF specific
ALPHA_LOSS = 5.0  # 1 for synthetic
BETA_LOSS = 0.0008
MLP_LR_START = 0.0008
MLP_LR_END = 1.6e-6
MLP_DECAY_STEPS = 60000

def compute_mlp_lr(step):
    """Exponential decay for MLP learning rate."""
    if MLP_DECAY_STEPS == 0:
        return MLP_LR_START
    return MLP_LR_START * (MLP_LR_END / MLP_LR_START) ** (step / MLP_DECAY_STEPS)

def update_gaussians(gaussians, gradients, step):
    """
    Update Gaussian parameters using Adam optimizer with specific learning rates.
    """
    for param_name, grad in gradients.items():
        # Select learning rate based on parameter type
        if param_name == "position":
            lr = LR_POSITION
        elif param_name == "color_sh":
            lr = LR_COLOR_SH
        elif param_name == "scale":
            lr = LR_SCALE
        elif param_name == "opacity":
            lr = LR_OPACITY
        elif param_name == "base_color":
            lr = LR_BASE_COLOR
        elif param_name == "metallic":
            lr = LR_METALLIC
        elif param_name == "roughness":
            lr = LR_ROUGHNESS
        elif param_name == "normal_rotation":
            lr = LR_NORMAL_ROTATION
        elif param_name == "direct_light_sh":
            # Simplified: assume deg=0 for this example, or branch logic
            lr = LR_DIRECT_LIGHT_SH_0 
        elif param_name == "indirect_light_sh":
            lr = LR_INDIRECT_LIGHT_SH_0
        elif param_name == "visibility_sh":
            lr = LR_VISIBILITY_SH
        elif param_name == "mlp_weights":
            lr = compute_mlp_lr(step)
        else:
            lr = 0.0 # Not given in the sources.

        # Adam update step [G]
        # m = beta1 * m + (1 - beta1) * grad
        # v = beta2 * v + (1 - beta2) * grad^2
        # m_hat = m / (1 - beta1^t)
        # v_hat = v / (1 - beta2^t)
        # param = param - lr * m_hat / (sqrt(v_hat) + eps)
        pass

def compute_loss(rgb_rendered, rgb_gt, depth_rendered, depth_gt, gaussians):
    """
    Compute loss with regularization.
    """
    # RGB Loss
    l_rgb = mean_squared_error(rgb_rendered, rgb_gt)
    
    # Depth/ToF Loss (ToRF)
    l_depth = mean_squared_error(depth_rendered, depth_gt)
    
    # Combined Loss with weights [S1]
    total_loss = ALPHA_LOSS * l_rgb + BETA_LOSS * l_depth
    
    # Regularization (Phys3DGS) [S2, unofficial]
    l_smooth_color = smoothness_penalty(gaussians.base_color)
    l_smooth_metallic = smoothness_penalty(gaussians.metallic)
    l_smooth_roughness = smoothness_penalty(gaussians.roughness)
    
    total_loss += LAMBDA_SMOOTH_COLOR * l_smooth_color
    total_loss += LAMBDA_SMOOTH_METALLIC * l_smooth_metallic
    total_loss += LAMBDA_SMOOTH_ROUGHNESS * l_smooth_roughness
    total_loss += LAMBDA_OTHER * (other_regularization_terms)
    
    return total_loss

### Edge Cases and Pitfalls
*   **Gradient Overflow:** If a single Gaussian behaves abnormally (e.g., driven to the opposite side of the surface, large scale, or extreme opacity), it interferes with visibility and global illumination [S2, unofficial]. The optimizer may compensate by increasing local illumination intensity or decreasing opacity to extreme values, causing gradient overflow in SH coefficients or opacity [S2, unofficial].
*   **Material-Lighting Ambiguity:** In inverse rendering, base color and lighting are entangled. A rescale factor (median of pixel-wise ratios) is often applied to base color to resolve this, though omitted for real captures without ground truth [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Determined by the rasterization and backward pass of the Gaussian splatting algorithm, plus the overhead of computing additional PBR or depth losses.
*   **Memory Complexity:** Standard 3DGS memory usage plus buffers for additional material properties (roughness, metallic) and potentially MLP weights for deformation [S1].
*   **Strengths:** High-fidelity reconstruction of dynamic scenes (ToRF) or physically accurate materials (Phys3DGS) when hyperparameters are tuned to balance stability and detail.
*   **Limitations:** Sensitive to hyperparameter choices; incorrect regularization strengths can lead to instability or over-smoothing. Requires careful tuning of learning rates for different SH degrees and material properties.

## Background
*   **ToRF (Time of the Flight of the Gaussians):** Introduced in CVPR 2025, this method optimizes depth indirectly using C-ToF data, requiring specific loss weights and MLP decay schedules [S1].
*   **Phys3DGS:** Introduced in arXiv 2024, this method extends 3DGS to inverse rendering with PBR materials, necessitating distinct learning rates for material parameters and smoothness regularizers to prevent instability [S2, S2, unofficial].
