# Texel Size Adaptation and Primitive Management

Also called: Adaptive Texture Allocation, Primitive Management via Quantile Error

## Overview
Texel Size Adaptation and Primitive Management is a content-aware optimization routine for 3D Gaussian Splatting that dynamically allocates texture resolution and primitive counts based on reconstruction error [S1]. It solves the problem of static texture allocation by adapting the number of texels per Gaussian and the total number of Gaussians to local scene complexity, balancing model capacity and appearance quality [S1]. Unlike sibling methods that rely primarily on gradient norms or screen-space size for densification, this method explicitly couples texture map resolution (texel size) with primitive splitting, using quantile error thresholds to drive both upscaling and splitting decisions [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Current set of 3D Gaussians $\mathcal{G}_i$, their associated texture grids, current iteration count `iter`, and hyperparameters $\tau_{tr}$, $\tau_{ds}$, $\lambda_{texture}$, and $t_{2pr}$ [S1].
*   **Outputs:** Updated set of 3D Gaussians (with potential splits/clones), updated texture grid resolutions for each primitive, and updated opacity values [S1].

**Data Structures:**
*   **Primitive List:** A list of Gaussian primitives. Each primitive $i$ maintains:
    *   Mean position $\mu_i$ [Parent].
    *   Covariance matrix $\Sigma_i$ (or rotation/scale) [Parent].
    *   Opacity $\alpha_i$ [Parent].
    *   Texture grid dimensions $W_i \times H_i$ (in texels) [S1].
    *   Texture grid values (RGB or other features) [S1].
*   **Error Buffer:** An array storing the scalar error $E_i$ for each primitive [S1].

**Parameters:**
*   $\tau_{tr}$: Texture resolution threshold. Controls the aggressiveness of primitive splitting. Starts at 64 and is progressively reduced to 32 within the first 7,000 iterations [S1].
*   $\tau_{ds}$: Downscale threshold. Controls the ease of texture downsizing. A higher value makes downscaling easier, leading to simpler appearances [S1].
*   $\lambda_{texture}$: Controls the variance of the texture maps. Higher values lead to smoother results; lower values result in fewer texels per primitive [S1].
*   $t_{2pr}$: Texture size per primitive (in texels). Initialized at iteration 500 to the closest power of two such that the smallest axis is 8 texels wide [S1].
*   Quantile: The top 90% of errors are considered for splitting/upscaling [S1].

**Steps:**
1.  **Initialization (Iteration 500):**
    *   Initialize texture grids for all primitives with zero values [S1].
    *   Set $t_{2pr}$ for each primitive to the closest power of two such that the smallest axis of the projected Gaussian is 8 texels wide [S1].
2.  **Periodic Execution (Iterations 250 to 25,000):**
    *   If `iter` mod 250 == 0:
        a.  **Error Computation:** Compute the error $E_i$ for each primitive $i$. The specific error metric is not detailed in the source, but it is used to rank primitives [S1].
        b.  **Ranking:** Determine the threshold for the top 90% of errors. Let $Q_{90}$ be the error value at the 90th percentile of all $E_i$ [S1].
        c.  **Primitive Management (Splitting):**
            For each primitive $i$:
            If $E_i \ge Q_{90}$ AND current texture resolution > $\tau_{tr}$:
            *   Split the primitive along its overflowing axes (principal axes of covariance) [S1].
            *   The new primitives inherit properties with perturbations, and their opacities are initialized to a low value (e.g., logit -1.386) as per standard 3DGS densification principles [Parent].
        d.  **Texel Size Adaptation (Upscaling):**
            For each primitive $i$:
            If $E_i \ge Q_{90}$ AND $t_{2pr} > 1$:
            *   Decrease texel size (Upscale). This is implemented by doubling the resolution of the texture grid (scale factor of 2) using interpolation [S1].
        e.  **Texel Size Adaptation (Downscaling):**
            For each primitive $i$:
            If $E_i < Q_{90}$ (implied by the `else if` structure in the source, though the source text says "Else if $E_d < \tau_{ds}$", the context implies a condition on error or a derived metric $E_d$; however, Algorithm 1 explicitly states `else if Ed < τds`. Given the lack of definition for $E_d$, we assume it is a local error metric or the same $E_i$ used in a different context. The source text says "If $t_{2pr} > 1$ and $E_i$ in top 90% ... else if $E_d < \tau_{ds}$". This implies if the primitive is NOT in the top 90%, check downscaling. We will assume $E_d$ refers to the error $E_i$ for the purpose of implementation, as no other definition is provided) [S1]:
            *   If $E_i < \tau_{ds}$:
            *   Increase texel size (Downscale). This is implemented by halving the resolution of the texture grid (scale factor of 0.5) using interpolation [S1].

**Edge Cases and Pitfalls:**
*   **Hyperparameter Interdependence:** Changing $\tau_{tr}$ to encourage more primitives can indirectly lead to fewer texels per primitive because each primitive represents a more localized, simpler part of the scene [S1].
*   **Memory Management:** The method requires pre-allocated buffer capacity for primitives (typically 3x initial count) to handle splits without reallocation overhead [Parent].
*   **Initialization:** Texture grids must be initialized to zero and optimization must start after 500 iterations to avoid early overfitting and memory issues [S1].
*   **Precision:** Interpolation during upscaling/downscaling may introduce artifacts if not handled carefully [S1].

## Operating characteristics
*   **Time Complexity:** The routine runs every 250 iterations. Error computation is $O(N)$ where $N$ is the number of primitives. Splitting and texture interpolation are also dependent on $N$ and texture size. The overall impact on training time is minimal as it is not run every step [S1].
*   **Memory Complexity:** Memory usage scales with the number of primitives and the total number of texels. The source reports 293K points and 20.8M texels for the 'drjohnson' scene, resulting in 318MB memory usage [S1].
*   **Performance:** On the 'drjohnson' scene, the method achieves 77 FPS and 318MB memory with 79.7M parameters [S1]. On the 'bonsai' scene, it achieves 35 FPS and 176MB memory with 44.1M parameters [S1].
*   **Strengths:** Automatically adjusts model capacity to scene complexity, reducing overfitting in simple areas and improving detail in complex areas [S1].
*   **Limitations:** Requires careful tuning of hyperparameters ($\tau_{tr}$, $\tau_{ds}$, $\lambda_{texture}$) to balance primitive count and texel density [S1].

## Background
Texel Size Adaptation and Primitive Management was introduced by Panagiotis Papantonakis, Georgios Kopanas, Frédo Durand, and George Drettakis in their work on "Content-Aware Texturing for Gaussian Splatting" [S1]. The method builds on the 3D Gaussian Splatting framework, extending it with dynamic texture allocation. It was developed to address the limitations of static texture resolution in Gaussian Splatting, allowing for more efficient and higher-quality view synthesis [S1].
