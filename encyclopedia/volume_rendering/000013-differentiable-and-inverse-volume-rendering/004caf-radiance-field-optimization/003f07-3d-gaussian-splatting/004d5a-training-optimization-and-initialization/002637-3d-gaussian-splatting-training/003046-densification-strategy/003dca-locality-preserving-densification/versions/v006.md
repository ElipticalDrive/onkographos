# Locality-preserving Densification

Also called: Z-ordering for Gaussians

## Overview
Locality-preserving densification addresses the memory layout bottleneck in 3D Gaussian Splatting training, where adding new primitives at the end of parameter buffers causes spatially close Gaussians to be stored far apart in memory [S1, unofficial]. By reordering Gaussians in parameter buffers based on their 3D spatial proximity using Z-ordering (Morton order), it improves memory access coalescing, reduces warp divergence, and decreases cache misses [S1, unofficial]. It sets itself apart from sibling methods like Score-based Densification by focusing on the *storage layout* of existing primitives rather than the *selection criteria* for creating or removing them.

## How it works
**Inputs:**
- The current set of $N$ Gaussians $\mathcal{G} = \{g_1, \dots, g_N\}$, where each $g_k$ has a mean position $\mu_k \in \mathbb{R}^3$.
- The current parameter buffers storing Gaussian attributes (means, covariances, opacities, spherical harmonics coefficients).

**Outputs:**
- A permutation of the parameter buffers such that Gaussians with spatially close means are stored in contiguous memory locations.

**Data Structures:**
- **Z-order Key:** For a Gaussian mean $\mu_k = (x, y, z)$, the Z-order key $Z_k$ is computed by interleaving the bits of the integer representations of the normalized coordinates.
  - Let $x, y, z$ be mapped to integers in $[0, 2^b - 1]$ (typically $b=10$ or $11$ for sufficient precision).
  - $Z_k = \sum_{i=0}^{b-1} (x_i \cdot 4^i + y_i \cdot 2 \cdot 4^i + z_i \cdot 4^i)$, where $x_i, y_i, z_i$ are the $i$-th bits of $x, y, z$.
- **Sorting Index:** An array of indices $P$ of size $N$, initially $P[i] = i$.

**Parameters:**
- **Frequency:** Z-ordering is applied every 5000 training iterations [S1, unofficial].
- **Precision:** Bit depth for coordinate quantization is not explicitly specified in the source, but standard Morton order implementations use 10-11 bits per dimension for typical scene scales [G].

**Steps:**
1. **Check Frequency:** If the current training iteration $t$ is not a multiple of 5000, skip this procedure [S1, unofficial].
2. **Compute Keys:** For each Gaussian $g_k$ with mean $\mu_k = (x_k, y_k, z_k)$:
   - Normalize coordinates to a fixed bounding box (e.g., $[-1, 1]$ or scene-specific bounds).
   - Quantize to integers $X_k, Y_k, Z_k$.
   - Compute Morton code $M_k = \text{Morton3D}(X_k, Y_k, Z_k)$.
3. **Sort:** Sort the indices $P$ based on the values $M_{P[i]}$ in ascending order.
4. **Reorder Buffers:** Permute all parameter buffers (means, covariances, etc.) according to the sorted index array $P$.
   - For each buffer $B$, create a new buffer $B'$ where $B'[i] = B[P[i]]$.
   - Replace $B$ with $B'$.

**Pseudocode:**
```python
def apply_z_ordering(gaussians, iteration, frequency=5000):
    """
    Reorders Gaussian parameter buffers based on 3D spatial locality using Z-ordering.
    
    Args:
        gaussians: Object containing arrays for means, covariances, opacities, etc.
                   Each array has shape (N, D) where N is number of Gaussians.
        iteration: Current training iteration number.
        frequency: Interval (in iterations) to apply Z-ordering.
        
    Returns:
        None (modifies gaussians in place)
    """
    # Step 1: Check frequency
    if iteration % frequency != 0:
        return

    means = gaussians.means  # Shape (N, 3)
    N = means.shape[0]
    
    # Step 2: Compute Z-order keys
    # Normalize coordinates to [0, 1] range for Morton encoding
    # Assuming means are already in a normalized space or need scaling
    # [G] Typical normalization: (mean - min) / (max - min)
    min_coords = means.min(axis=0)
    max_coords = means.max(axis=0)
    range_coords = max_coords - min_coords
    # Avoid division by zero
    range_coords[range_coords == 0] = 1.0
    
    normalized = (means - min_coords) / range_coords
    
    # Quantize to integers (e.g., 10 bits -> 1024 levels)
    bits = 10
    scale = 2**bits - 1
    int_coords = (normalized * scale).astype(np.int32)
    
    # Clamp to valid range
    int_coords = np.clip(int_coords, 0, 2**bits - 1)
    
    # Compute Morton codes
    # Morton3D interleaves bits of x, y, z
    m_codes = np.zeros(N, dtype=np.int64)
    for i in range(bits):
        m_codes |= (int_coords[:, 0] & (1 << i)) << (2 * i)
        m_codes |= (int_coords[:, 1] & (1 << i)) << (2 * i + 1)
        m_codes |= (int_coords[:, 2] & (1 << i)) << (2 * i + 2)
        
    # Step 3: Sort indices based on Morton codes
    sorted_indices = np.argsort(m_codes)
    
    # Step 4: Reorder all parameter buffers
    for attr_name in gaussians.attribute_names:
        attr = getattr(gaussians, attr_name)
        setattr(gaussians, attr_name, attr[sorted_indices])
```

**Edge Cases and Pitfalls:**
- **Atomic Contention:** Z-ordering is effective only when used with the per-Gaussian backward pass. If the original backward pass (with numerous atomic operations) is used, Z-ordering heightens atomic contention [S1, unofficial].
- **Small Scene Size:** Repeated Z-ordering slows down training when the number of Gaussians is small due to a massive increase in atomic contention in the alpha blending backward pass (false sharing) [S1, unofficial].
- **Precision:** The quality of Z-ordering depends on the normalization and quantization of coordinates. Poor normalization can lead to incorrect spatial locality assumptions [G].

## Operating characteristics
- **Time Complexity:** $O(N \log N)$ for sorting, where $N$ is the number of Gaussians. The Morton code computation is $O(N \cdot b)$ where $b$ is the bit depth.
- **Memory Complexity:** $O(N)$ for storing the sorted indices and temporary Morton codes.
- **Performance:** Computational cost is approximately 4 ms per million Gaussians [S1, unofficial].
- **Scaling:** Reduces warp divergence and cache misses, leading to faster training when scenes contain many Gaussians [S1, unofficial]. However, it can slow down training for small numbers of Gaussians due to false sharing [S1, unofficial].
- **Strengths:** Improves memory access coalescing, reduces cache misses, and accelerates training for large-scale scenes.
- **Limitations:** Ineffective or detrimental for small scenes; requires per-Gaussian backward pass to avoid atomic contention issues.
- **When to Use:** Large scenes with millions of Gaussians where memory bandwidth is a bottleneck.
- **When Not to Use:** Small scenes, or when using the original backward pass with atomic operations.

## Background
Locality-preserving densification was introduced in the "Faster-GS" paper, which analyzes and improves Gaussian Splatting optimization [S1, unofficial]. It addresses the observation that memory layout becomes a throttling factor during densification, as new Gaussians are added at the end of parameter buffers, causing spatially close Gaussians to be far apart in memory [S1, unofficial]. The method leverages Z-ordering (Morton order), a well-known space-filling curve technique, to align Gaussians in memory with their 3D spatial proximity [S1, unofficial].
