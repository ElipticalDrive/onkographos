# Sensitivity Calculation and Pruning

Also called: Gradient-based Sensitivity Pruning

## Overview
This method eliminates 3D Gaussians that have no impact on training images by calculating a sensitivity score based on the gradient of the total image energy with respect to the Gaussian parameters [S1]. It sets itself apart from its parent, [Temporal Sensitivity Pruning](6350-temporal-sensitivity-pruning.md), by focusing on the static contribution to the loss rather than temporal consistency, and from [Statistical Sensitivity-Driven Online Sparsification](14437-statistical-sensitivity-driven-online-sparsification.md) by being a distinct pruning phase rather than an online maintenance mechanism [S1].

## How it works
**Inputs:** A set of $N$ 3D Gaussians $\{G_i\}_{i=1}^N$, where each Gaussian $G_i$ is defined by position $\mathbf{t}_i$, rotation $\mathbf{R}_i$, scaling $\mathbf{s}_i$, and spherical harmonic (SH) coefficients for color. The training dataset consists of views with corresponding target images.
**Outputs:** A pruned set of Gaussians $\{G_i\}_{i \in \text{kept}}$ where Gaussians with zero sensitivity are removed.

**Data Structures:**
Each Gaussian $G_i$ stores:
- $\mathbf{t}_i \in \mathbb{R}^3$: Center position.
- $\mathbf{q}_i \in \mathbb{R}^4$: Unit quaternion representing rotation $\mathbf{R}_i$.
- $\mathbf{s}_i \in \mathbb{R}^3$: Scaling factors (positive).
- $\mathbf{c}_i$: SH coefficients defining directional color.
- $\alpha_i \in \mathbb{R}$: Opacity.

**Sensitivity Calculation:**
The sensitivity $S_i$ of a Gaussian $G_i$ is defined as the gradient of the total image energy (loss) $\mathcal{L}$ with respect to the parameters of $G_i$ [S1]. Specifically, the method evaluates the sensitivity with respect to the color parameters (SH coefficients) [S1].

The covariance matrix $\Sigma_i$ is constructed from the rotation and scaling:
$$ \Sigma_i = \mathbf{R}_i \mathbf{S}_i^2 \mathbf{R}_i^T $$
where $\mathbf{S}_i = \text{diag}([\mathbf{s}_{i,1}^2, \mathbf{s}_{i,2}^2, \mathbf{s}_{i,3}^2]^T)$ [S1].

**Critical Implementation Detail:**
Standard 3D Gaussian Splatting implementations (e.g., Kerbl et al. [13]) clamp negative direction-dependent colors to zero during rendering [S1]. In the backward pass, the partial derivatives for these clamped values are set to zero [S1]. This results in a sensitivity of zero for SH coefficients that may still contribute to the training images if the color were allowed to be negative [S1]. Therefore, when calculating sensitivity, **colors must not be clamped** [S1]. The rendering function used for sensitivity calculation must allow negative color values to ensure non-zero gradients for contributing SH coefficients [S1].

**Pruning Step:**
1. For each Gaussian $G_i$, compute the sensitivity score $S_i$ using the unclamped gradient of the total image energy with respect to its color parameters [S1].
2. Identify Gaussians where $S_i = 0$ (or effectively zero within floating-point precision) [S1].
3. Eliminate these Gaussians from the scene [S1].

**Pseudocode:**
```python
def calculate_sensitivity_and_prune(gaussians, training_views, loss_fn):
    """
    gaussians: List of Gaussian objects with attributes:
               - sh_coeffs: Spherical Harmonic coefficients
               - t: Position
               - q: Rotation quaternion
               - s: Scaling vector
               - alpha: Opacity
    training_views: List of (camera_params, target_image) tuples
    loss_fn: Function computing L2 loss between rendered and target image
    """
    pruned_gaussians = []
    
    for g in gaussians:
        # Calculate sensitivity wrt color parameters
        # Note: Rendering must NOT clamp negative colors to zero
        sensitivity = 0.0
        
        # Accumulate gradient magnitude of loss wrt SH coefficients
        # This requires a backward pass through the differentiable renderer
        # with the specific constraint that color clamping is disabled.
        
        # 1. Render the scene using current Gaussians, allowing negative colors
        # 2. Compute Loss = sum((rendered - target)^2) over all training views
        # 3. Compute gradient d(Loss)/d(g.sh_coeffs)
        
        # Implementation detail [G]: Use automatic differentiation.
        # Ensure the color clamping operation (max(0, color)) is bypassed
        # or replaced with identity during this specific gradient computation.
        
        grad = compute_gradient(loss_fn, g.sh_coeffs, gaussians, training_views, clamp_colors=False)
        
        # Sensitivity is the norm of the gradient
        sensitivity = np.linalg.norm(grad)
        
        # Check for zero sensitivity
        # A notable number of Gaussians (up to 15%) exhibit zero sensitivity [S1]
        if sensitivity > 1e-6: # [G] Small epsilon to handle floating point noise
            pruned_gaussians.append(g)
            
    return pruned_gaussians
```

**Edge Cases and Pitfalls:**
- **Color Clamping:** As noted, failing to disable color clamping during sensitivity calculation leads to false negatives (Gaussians incorrectly identified as having zero sensitivity) [S1].
- **Threshold Selection:** Higher pruning thresholds can remove more Gaussians with minimal PSNR loss, but may remove fine details such as small leaves [S1]. The method described uses a strict zero-sensitivity check, but practical implementations may use a small threshold [S1].

## Subtopics

## Operating characteristics
**Time Complexity:** The method requires a full backward pass through the renderer for each Gaussian (or batched Gaussians) to compute gradients, which is computationally expensive compared to simple opacity-based pruning.
**Memory Complexity:** Requires storing gradients for all parameters during the backward pass.
**Performance:** Can remove up to 15% of Gaussians that have no impact on training images [S1].
**Strengths:** Effectively removes redundant primitives that do not contribute to the reconstruction.
**Limitations:** Higher pruning thresholds risk removing fine details (e.g., small leaves) [S1]. The requirement to disable color clamping adds implementation complexity.

## Background
This method is described in "Compressed 3D Gaussian Splatting for Accelerated Novel View Synthesis" [S1]. It addresses the redundancy in 3D Gaussian Splatting models where a significant portion of Gaussians do not contribute to the final image. The method is part of a broader effort to compress 3D Gaussian Splatting models for faster novel view synthesis.
