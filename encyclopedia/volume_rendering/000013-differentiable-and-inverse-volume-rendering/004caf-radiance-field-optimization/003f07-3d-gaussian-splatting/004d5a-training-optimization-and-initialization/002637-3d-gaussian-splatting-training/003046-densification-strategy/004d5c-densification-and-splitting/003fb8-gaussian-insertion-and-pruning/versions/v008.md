# Gaussian Insertion and Pruning

Also called: Monocular Gaussian Initialization

## Overview
Gaussian Insertion and Pruning is a dynamic management strategy for 3D Gaussian primitives used primarily in monocular and RGB-D SLAM systems [S1, unofficial]. It solves the problem of maintaining a coherent 3D structure in real-time by inserting new Gaussians to capture newly visible scene elements and pruning those that are geometrically unstable or contribute negligibly to the render [S1, unofficial]. Unlike static densification strategies that rely on gradient magnitude thresholds, this method relies on visibility consistency across a sliding window of keyframes and opacity thresholds to manage the primitive set [S1, unofficial].

## How it works
**Inputs:**
*   Current set of 3D Gaussians $\mathcal{G}$.
*   Current camera pose and intrinsics.
*   Rendered depth map $D$ for the current frame.
*   Keyframe window $W_k$ containing recent keyframes.
*   Opacity threshold $\alpha_{\text{prune}} = 0.7$ [S1, unofficial].
*   Keyframe window size $|W_k|$ (e.g., 10 for Replica, 8 for TUM) [S1, unofficial].

**Outputs:**
*   Updated set of 3D Gaussians $\mathcal{G}'$ with new insertions and pruned elements.

**Data Structures:**
*   **Keyframe Window ($W_k$):** A fixed-size buffer storing recent keyframes.
*   **Visibility Counter:** For each newly inserted Gaussian, a counter tracks how many frames in $W_k$ have observed it. A Gaussian is marked as "visible" from a view if it was used in rasterization and the ray's accumulated $\alpha$ has not yet reached 0.5 [S1, unofficial].

**Steps:**

1.  **Initialization of New Gaussians:**
    When a new keyframe is added to $W_k$, new Gaussians are inserted to capture newly visible regions. The mean position $\mu_W$ is initialized based on the rendered depth $D$:
    *   **For pixels $p$ with valid depth $D_p$:** Sample the depth from a normal distribution:
        $$ z \sim \mathcal{N}(D_p, 0.2\sigma_D) $$
        where $\sigma_D$ is the standard deviation of the depth noise/uncertainty [S1, unofficial].
    *   **For pixels without depth estimates (unobserved regions):** Sample from a normal distribution centered at the median depth $\hat{D}$ of the rendered image:
        $$ z \sim \mathcal{N}(\hat{D}, 0.5\sigma_D) $$
        This accounts for incorrect depth estimates by introducing higher variance [S1, unofficial].
    *   The 2D position $(u, v)$ is taken directly from the pixel coordinates. The 3D mean $\mu_W$ is computed by back-projecting $(u, v, z)$ using camera intrinsics [S1, unofficial].

2.  **Visibility-Based Pruning (Geometric Stability):**
    This step ensures that inserted Gaussians are consistent with the scene geometry across multiple views.
    *   **Condition:** Only perform this pruning once the keyframe window $W_k$ is full [S1, unofficial].
    *   **Check:** For each Gaussian inserted within the last 3 keyframes, count the number of other frames in $W_k$ where it was observed (as defined in Visibility Counter).
    *   **Action:** If a Gaussian is unobserved by at least 3 other frames in $W_k$, it is considered geometrically unstable and is pruned [S1, unofficial].

3.  **Opacity-Based Pruning:**
    *   **Action:** Iterate through all Gaussians in $\mathcal{G}$.
    *   **Condition:** If opacity $\alpha_k < 0.7$, remove the Gaussian [S1, unofficial].

**Pseudocode:**

```python
def gaussian_insertion_and_pruning(G, current_frame, W_k, sigma_D):
    """
    G: List of active 3D Gaussians
    current_frame: Current camera frame with rendered depth D
    W_k: List of keyframes in the sliding window
    sigma_D: Standard deviation of depth noise
    """
    
    # Step 1: Insert new Gaussians if a new keyframe is added
    if current_frame.is_new_keyframe:
        D = current_frame.rendered_depth
        median_depth = median(D)
        
        for pixel in current_frame.pixels:
            u, v = pixel.coords
            D_p = D[u, v]
            
            # Initialize mean position based on depth
            if D_p is valid:
                z = sample_normal(D_p, 0.2 * sigma_D)
            else:
                z = sample_normal(median_depth, 0.5 * sigma_D)
            
            # Back-project to 3D
            mu_W = back_project(u, v, z, current_frame.intrinsics)
            
            # Create new Gaussian
            new_g = Gaussian(mean=mu_W, opacity=0.1, scale=initial_scale, rotation=identity)
            new_g.insertion_keyframe_index = len(W_k) - 1
            G.append(new_g)
            
            # Initialize visibility counter
            new_g.visibility_count = 0 # Will be updated during mapping/rasterization

    # Step 2: Visibility-Based Pruning
    # Only perform once the window is full
    if len(W_k) >= W_k.max_size:
        # Identify Gaussians inserted in the last 3 keyframes
        recent_gaussians = [g for g in G 
                            if len(W_k) - g.insertion_keyframe_index <= 3]
        
        for g in recent_gaussians:
            # Count observations in W_k
            # Note: Visibility is determined during rasterization of each keyframe in W_k
            # If g was used and accumulated alpha < 0.5, it is "observed"
            if g.visibility_count < 3:
                G.remove(g)

    # Step 3: Opacity-Based Pruning
    G = [g for g in G if g.opacity >= 0.7]
    
    return G
```

**Parameters:**
*   $\alpha_{\text{prune}} = 0.7$: Opacity threshold for pruning [S1, unofficial].
*   $|W_k|$: Keyframe window size (10 for Replica, 8 for TUM) [S1, unofficial].
*   Depth variance factors: $0.2\sigma_D$ for observed pixels, $0.5\sigma_D$ for unobserved [S1, unofficial].

**Edge Cases:**
*   **Incorrect Depth:** In monocular settings, rendered depth may be incorrect. The high variance initialization ($0.5\sigma_D$) for unobserved regions helps mitigate this, but many inserted Gaussians may be geometrically invalid and will be pruned by the visibility check [S1, unofficial].
*   **Window Not Full:** Visibility-based pruning is skipped until $W_k$ is full, preventing premature removal of valid Gaussians that simply haven't been seen by enough frames yet [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Insertion is $O(N_{\text{new}})$ where $N_{\text{new}}$ is the number of pixels sampled. Pruning is $O(N_{\text{total}})$ as it requires iterating over all Gaussians to check opacity and visibility counts.
*   **Memory Complexity:** Requires storing visibility counts for each Gaussian and maintaining the keyframe window $W_k$.
*   **Strengths:** Effective at removing geometrically unstable Gaussians in SLAM applications, preventing drift and accumulation of noise. Simple to implement.
*   **Limitations:** Relies heavily on the accuracy of rendered depth. In monocular settings, initial insertions may be noisy. The opacity threshold of 0.7 is high compared to standard 3DGS (which often uses lower thresholds like 0.01 or 0.1), leading to more aggressive pruning [S1, unofficial].
*   **When to use:** Monocular or RGB-D SLAM systems where real-time consistency and geometric stability are critical. Not typically used in static scene reconstruction where gradient-based densification is preferred.

## Background
Gaussian Insertion and Pruning was introduced in "Gaussian Splatting SLAM" [S1, unofficial]. It adapts the 3D Gaussian Splatting representation for simultaneous localization and mapping (SLAM). The method addresses the challenge of maintaining a consistent 3D map in real-time by dynamically managing the Gaussian primitives based on visibility and opacity, rather than relying solely on gradient-based densification used in static reconstruction [S1, unofficial].
