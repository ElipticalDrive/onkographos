# VolSplat Architecture and Training Pipeline

Also called: VolSplat

## Overview
VolSplat is a feed-forward deep neural network that directly regresses 3D Gaussian Splatting (3DGS) parameters from sparse multi-view images in a single pass, bypassing the per-scene gradient descent optimization required by standard 3DGS [Parent](9213-mvsplat.md). It distinguishes itself by lifting 2D features into a sparse 3D voxel grid via plane-sweep depth prediction and predicting one Gaussian primitive per occupied voxel, ensuring scene-adaptive primitive allocation while maintaining stable sparse 3D decoding [S1].

## How it works
**Inputs and Outputs:**
- **Inputs:** $N_{in}$ input views (images) of a scene.
- **Outputs:** A set of 3D Gaussian primitives $\mathcal{G}$, each defined by a 38-dimensional parameter vector, representing the radiance field for novel view synthesis.

**Data Structures:**
1.  **Multi-scale Feature Maps:** Extracted from each input view.
2.  **Cost Volume:** Constructed via plane-sweep strategy. Dimensions depend on the reference view resolution and the number of inverse-depth candidates.
3.  **Sparse Voxel Grid:** A 3D data structure where only occupied cells are materialized, implemented using MinkowskiEngine [S1].
4.  **Gaussian Primitive:** One per occupied voxel. The parameter vector $\mathbf{p}$ has dimension 38, comprising:
    -   Opacity ($\alpha$)
    -   Center offset ($\Delta \mathbf{x}$)
    -   Anisotropic scale ($\mathbf{s}$)
    -   Quaternion rotation ($\mathbf{q}$)
    -   Degree-2 spherical-harmonic color coefficients ($\mathbf{c}$) [S1].

**Numbered Steps:**

1.  **Feature Extraction:**
    For each input view $I_i$, extract multi-scale feature maps using a weight-sharing ResNet backbone [S1].

2.  **Cross-View Interaction:**
    Refine the extracted features using a cross-view interaction module implemented with local window attention to enhance multi-view consistency [S1].

3.  **Cost Volume Construction:**
    For a reference view, construct a cost volume using a plane-sweep strategy. The volume contains $D = 128$ inverse-depth candidates per reference view [S1].

4.  **Depth Prediction:**
    Perform local neighbor matching on the cost volume to predict robust depth maps for each reference view [S1].

5.  **Feature Lifting:**
    Lift the 2D features from each input view into 3D space using the predicted depth maps. The lifted 3D representation is built in world coordinates [S1].

6.  **Sparse 3D Refinement:**
    Process the lifted features as a sparse voxel set. Only occupied cells are materialized to avoid computational redundancy of a dense global grid. This is implemented using MinkowskiEngine [S1].

7.  **Gaussian Parameter Prediction:**
    For each occupied voxel in the sparse 3D grid, predict one Gaussian primitive. The network outputs a 38-dimensional parameter vector for each primitive [S1].

**Training Data Sampling:**
-   Each training sample consists of $N_{in} = 6$ input views and $N_{target} = 8$ target views [S1].
-   Two input views are selected as boundary anchors with a randomly sampled frame gap within a predefined range [S1].
-   The remaining input views are sampled between these anchors [S1].
-   The anchor-gap range is progressively expanded during early training iterations [S1].
-   Target novel views are chosen from disjoint camera positions not included in the inputs [S1].

**Parameters:**
-   **Inverse-depth candidates:** 128 per reference view [S1].
-   **Gaussian parameter vector dimension:** 38 [S1].
-   **Input views per training sample:** 6 [S1].
-   **Target views per training sample:** 8 [S1].
-   **Input resolution:** $256 \times 256$ pixels [S1].
-   **Optimizer:** AdamW with decoupled weight decay [S1].
-   **Learning rate:** Two separate groups for the pretrained monocular branch and the remaining trainable parameters [S1].
-   **Stability:** Gradient clipping is enabled during training [S1].

**Edge Cases and Pitfalls:**
-   **Sparse Grid Initialization:** The sparse voxel grid must correctly identify occupied cells to avoid computational redundancy. Incorrect occupancy detection may lead to missing primitives or excessive memory usage [S1].
-   **Depth Prediction Errors:** Robust depth prediction is critical for accurate feature lifting. Errors in depth maps can lead to misaligned 3D features [S1].
-   **Anchor Gap Selection:** The progressive expansion of the anchor-gap range during early training is crucial for stable convergence. Improper scheduling may lead to poor generalization [S1].

## Background
VolSplat was introduced by Choy, JunYoung Gwak, and Silvio Savarese in the paper "VolSplat: Rethinking Feed-Forward 3D Gaussian Splatting with Voxel-Aligned Prediction" [S1]. The method builds on previous work in feed-forward 3DGS, such as MVSplat [Parent](9213-mvsplat.md), and incorporates techniques from 4D spatio-temporal convnets (MinkowskiEngine) for efficient sparse 3D processing [S1]. Training is performed on RealEstate10K and fine-tuned on ScanNet, with zero-shot evaluation on ACID [S1].
