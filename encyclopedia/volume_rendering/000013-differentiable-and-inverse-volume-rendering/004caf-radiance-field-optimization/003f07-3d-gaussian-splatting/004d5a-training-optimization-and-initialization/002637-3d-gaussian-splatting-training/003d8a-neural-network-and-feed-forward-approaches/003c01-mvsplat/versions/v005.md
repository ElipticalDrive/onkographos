# MVSplat

Also called: Feed-forward 3DGS, Single-pass 3DGS

## Overview
MVSplat is a feed-forward deep neural network that directly regresses 3D Gaussian Splatting (3DGS) parameters from sparse multi-view images in a single pass, bypassing the per-scene gradient descent optimization loop required by standard 3DGS [S1][S2, unofficial]. It distinguishes itself from sibling methods like VRP-UDF by combining multi-view feature extraction via transformers and cost volumes with a U-Net decoder to predict Gaussian primitives, enabling rapid inference without iterative scene-specific optimization [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ sparse multi-view images $\{I_1, \dots, I_N\}$ with known camera parameters (intrinsics and extrinsics).
*   **Output:** A set of 3D Gaussian primitives defined by their parameters $\{\mathbf{\mu}_i, \mathbf{R}_i, \mathbf{s}_i, \alpha_i, \mathbf{c}_i\}$, where $\mathbf{\mu}_i$ is the mean, $\mathbf{R}_i$ is the rotation, $\mathbf{s}_i$ is the scale, $\alpha_i$ is the opacity, and $\mathbf{c}_i$ is the color [S1][S2, unofficial].

**Data Structures:**
The method utilizes a U-Net architecture to process aggregated multi-view features. The internal representation involves feature maps derived from the input images and cost volumes representing depth hypotheses. Specific bit-packing or memory layout details for the Gaussian parameters are not given in the sources [S1][S2, unofficial].

**Steps:**
1.  **Multi-view Feature Extraction:** Extract 2D features from the input images using a backbone network, typically involving transformers to generalize features between views [S1].
2.  **Cost Volume Construction:** Compute a cost volume by aggregating features across views. Similarity is computed between reference and target view features at discrete depth levels:
    $$ C(x, y, d) = \text{Similarity}(F_r(x, y), F_t(x', y')) $$
    where $(x', y')$ is the projected pixel in the target view for depth $d$ [S1, Parent].
3.  **U-Net Processing:** Process the cost volumes and extracted features through a U-Net architecture to refine the multi-view information and predict Gaussian properties [S1].
4.  **Parameter Regression:** Decode the U-Net output to directly regress the 3D Gaussian parameters $\{\mathbf{\mu}_i, \mathbf{R}_i, \mathbf{s}_i, \alpha_i, \mathbf{c}_i\}$ [S1][S2, unofficial].
5.  **Differentiable Rendering (Training):** During training, the predicted Gaussians are rasterized using the standard 3DGS rasterizer. The rendered output is compared to ground truth images to compute loss and update network weights [Parent].

**Pseudocode:**
```python
def mvsplat_forward(images, camera_params):
    """
    Forward pass of MVSplat to regress 3DGS parameters.
    
    Args:
        images: List of N input images.
        camera_params: Camera intrinsics and extrinsics for each view.
        
    Returns:
        gaussians: Dictionary containing 3D Gaussian parameters.
    """
    # Step 1: Multi-view feature extraction
    # Uses transformers to extract features from input images
    features = extract_features(images, camera_params)
    
    # Step 2: Cost volume construction
    # Aggregate features across views using depth hypotheses
    cost_volume = build_cost_volume(features)
    
    # Step 3: U-Net processing
    # Refine multi-view information
    refined_features = u_net(cost_volume)
    
    # Step 4: Parameter regression
    # Decode U-Net output to predict Gaussian parameters
    gaussians = decode_gaussians(refined_features)
    
    return gaussians

def mvsplat_loss(gaussians, images, camera_params):
    """
    Compute loss for training MVSplat.
    
    Args:
        gaussians: Predicted 3D Gaussian parameters.
        images: Ground truth images.
        camera_params: Camera intrinsics and extrinsics.
        
    Returns:
        loss: Scalar loss value.
    """
    # Step 5: Differentiable rendering
    # Render images from predicted Gaussians
    rendered_images = rasterize_gaussians(gaussians, camera_params)
    
    # Compute loss between rendered and ground truth images
    loss = compute_loss(rendered_images, images)
    
    return loss
```

**Parameters:**
*   Number of views $N$: Typically sparse (e.g., 2-4 views), though exact typical values are not given in the sources [S1, S3].
*   Depth levels for cost volume: Discrete depth levels are used, but the specific number is not given [S1].

**Edge Cases and Pitfalls:**
*   **Sparse Inputs:** Performance may degrade with very few views or single images, though generalizability-based methods aim to address this [S3].
*   **Camera Parameters:** Known camera parameters are required for standard MVSplat; methods like NoPoSplat address the need for known poses by using canonical coordinate systems [S1].
*   **Precision:** Not given in the sources [S1][S2, unofficial].

## Subtopics

### [VolSplat Architecture and Training Pipeline](13066-volsplat-architecture-and-training-pipeline.md)
VolSplat is a feed-forward deep neural network that directly regresses 3D Gaussian Splatting (3DGS) parameters from sparse multi-view images in a single pass, bypassing the per-scene gradient descent optimization required by standard 3DGS [Parent]. It distinguishes itself by lifting 2D features into a sparse 3D voxel grid via plane-sweep depth prediction and predicting one Gaussian primitive per occupied voxel, ensuring scene-adaptive primitive allocation while maintaining stable sparse 3D decoding.

### Sparse Input Reconstruction via Generalizability
Methods that use learned priors to reconstruct 3D scenes, often allowing reconstruction from a single input image after training on multiple views [S3].
*   **Step:** Synthesize additional views through generative models to augment input data. Use a feed-forward model to directly generate Gaussian properties from input images [S3].
*   **Pitfall:** Synthesizing additional views via generative models is computationally intensive and bounded by the capabilities of the generative model. Pixel-aligned Gaussians are distributed nearly evenly in space, struggling to represent high-frequency details and smoother regions with an appropriate number of Gaussians [S3].
*   **Comparison:** Uses learned priors for fast feed-forward inference, favoring speed and cross-scene generalization, but sometimes at the expense of geometric fidelity compared to regularization-based methods [S3].
*   **Usage:** PixelSplat samples Gaussians from dense probability distributions. Splatter Image uses a 2D image-to-image network to map an input image to a 3D Gaussian per pixel [S3].

## Operating characteristics
*   **Time Complexity:** Single-pass inference, significantly faster than iterative optimization methods like standard 3DGS [S1][S2, unofficial].
*   **Memory Complexity:** Not given in the sources [S1][S2, unofficial].
*   **Measured Performance:** Not given in the sources [S1][S2, unofficial].
*   **Scaling:** Not given in the sources [S1][S2, unofficial].
*   **Strengths:** Fast inference, bypasses per-scene optimization, good cross-scene generalization [S1][S2, unofficial][S3].
*   **Limitations:** May have lower geometric fidelity compared to regularization-based methods [S3]. Struggles with high-frequency details if Gaussians are pixel-aligned [S3].
*   **When to use:** When fast inference is required, or when per-scene optimization is computationally prohibitive [S1][S2, unofficial].
*   **When not to use:** When high geometric fidelity is critical and sufficient compute is available for iterative optimization [S3].

## Background
MVSplat builds upon PixelSplat by combining multi-view feature extraction through transformers and cost volumes, which are then processed by a U-Net [S1]. It is part of a broader trend of feed-forward and initialization strategies that bypass or drastically shorten the per-scene gradient descent loop [S2, unofficial]. The method is cited in surveys on 3D Gaussian Splatting and its applications [S1][S2, unofficial][S3].
