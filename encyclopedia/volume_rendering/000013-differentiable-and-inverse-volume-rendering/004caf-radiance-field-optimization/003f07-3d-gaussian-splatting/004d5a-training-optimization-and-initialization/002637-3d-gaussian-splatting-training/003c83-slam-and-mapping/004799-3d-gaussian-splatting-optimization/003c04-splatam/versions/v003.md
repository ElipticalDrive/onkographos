# SplaTAM

Also called: SplaTAM: RGB-D SLAM and NeRF-to-GS Conversion in a Unified Framework

## Overview
SplaTAM is an RGB-D Simultaneous Localization and Mapping (SLAM) method that represents the scene as a 3D Gaussian Splatting (3DGS) model [S2, unofficial]. It solves the problem of online mapping and tracking by jointly optimizing camera poses and Gaussian parameters using depth and photometric constraints [S2, unofficial]. It is distinguished from sibling methods like Gaussian-SLAM and Gaussian Splatting SLAM by its use of view-independent colors and a specific densification mask strategy to prevent duplicate Gaussian creation [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** RGB-D image pairs $(I_t, D_t)$ from a moving camera.
*   **Outputs:** Camera poses $\mathbf{T}_t$, 3D Gaussian parameters $\mathcal{G}$ (means $\mu$, covariances $\Sigma$, opacities $\alpha$, colors $c$).

**Data Structures:**
*   **Gaussians $\mathcal{G}$:** A set of $N$ Gaussians. Each Gaussian $i$ has:
    *   Mean position $\mu_i \in \mathbb{R}^3$.
    *   Covariance $\Sigma_i \in \mathbb{R}^{3 \times 3}$, parameterized by scale $\mathbf{s}_i \in \mathbb{R}^3$ and rotation $\mathbf{R}_i \in SO(3)$.
    *   Opacity $\alpha_i \in [0, 1]$.
    *   Color $c_i$. SplaTAM uses **view-independent** colors [S1].
*   **Densification Mask:** A binary mask indicating which pixels in the current frame require densification.

**Algorithm Steps:**
1.  **Initialization:** Bootstrap the scene with a lightweight reconstruction model or existing multi-view Gaussian-splat grids [S2, unofficial]. Initialize Gaussians with positions derived from depth data.
2.  **Tracking:** Estimate the current camera pose $\mathbf{T}_t$ by minimizing the difference between rendered and captured depth/photometric data. This involves:
    *   Rendering the current Gaussian map to get predicted depth $D_{pred}$ and color $I_{pred}$.
    *   Computing a loss based on depth and photometric ICP (Iterative Closest Point) [S2, unofficial].
    *   Optimizing $\mathbf{T}_t$ to minimize this loss.
3.  **Mapping (Optimization):** Jointly optimize the Gaussian parameters $\mathcal{G}$ and camera poses $\mathbf{T}_t$ to minimize the reconstruction loss:
    $$ L = L_{photo} + \lambda L_{depth} + L_{reg} $$
    Where $L_{photo} = || I_{pred} - I_{captured} ||_1$ and $L_{depth} = || D_{pred} - D_{captured} ||_1$ [S1][S2, unofficial].
4.  **Densification:** Determine if new Gaussians are needed using a **densification mask** [S1].
    *   The mask is created by comparing the rendered opacity/depth of current Gaussians with the captured depth of the new frame [S1].
    *   If a pixel is not well-covered (high error or low opacity), new Gaussians are spawned in that region [S1].
    *   This strategy avoids duplicate densification in well-reconstructed areas [S1].
5.  **Pruning:** Remove Gaussians with low opacity or those that are not contributing to the reconstruction [S1].

**Pseudocode:**
```python
def splatam_track_and_map(rgb_d_frames):
    # Initialize Gaussians G from depth or bootstrap
    G = initialize_gaussians_from_depth(rgb_d_frames[0])
    
    for t in range(len(rgb_d_frames)):
        I_t, D_t = rgb_d_frames[t]
        
        # 1. Tracking: Optimize camera pose T_t
        # Minimize depth and photometric error between rendered and captured
        T_t = optimize_pose(G, I_t, D_t)
        
        # 2. Mapping: Optimize Gaussian parameters
        # Jointly optimize G and T_t to minimize L_photo + L_depth
        G, T_t = optimize_gaussians(G, T_t, I_t, D_t)
        
        # 3. Densification: Add new Gaussians where needed
        # Create mask based on current Gaussians and captured depth
        densification_mask = create_densification_mask(G, T_t, I_t, D_t)
        
        # Spawn new Gaussians in regions indicated by the mask
        # Use view-independent colors for new Gaussians
        G = densify(G, densification_mask, I_t, D_t)
        
        # 4. Pruning: Remove unreliable Gaussians
        G = prune(G)
        
    return G, T_t
```

**Parameters:**
*   $\lambda$: Weight for depth loss. Not given in the sources.
*   Densification threshold: Not given in the sources.

**Edge Cases:**
*   **Duplicate Densification:** Avoided by using view-independent colors and the densification mask [S1].
*   **Map Drift:** Mitigated by joint optimization of poses and Gaussians [S1].
*   **Gaussian Degeneracy:** Prevented by regularization terms (e.g., scale isotropy) [S1].

## Operating characteristics
*   **Performance:** On the Replica dataset, SplaTAM achieves PSNR 34.11, SSIM 0.97, and LPIPS 0.10 [S1].
*   **Complexity:** Not given in the sources.
*   **Strengths:** Online mapping, real-time capability, high-quality reconstruction [S2, unofficial].
*   **Limitations:** Requires RGB-D input [S2, unofficial].

## Background
SplaTAM was introduced as an RGB-D SLAM method that maps the world as 3DGS [S2, unofficial]. It uses depth and photometric ICP to track and densify online [S2, unofficial]. It is part of the broader trend of using 3DGS for SLAM, following methods like Gaussian-SLAM and Gaussian Splatting SLAM [S2, unofficial].
