# Deferred Back-propagation

Also called: Deferred Gradient Computation, Patch-wise Gradient Accumulation

## Overview
Deferred back-propagation is a memory-efficient technique for optimizing radiance fields using image losses that require full-resolution inputs, such as VGG-based style losses or Gram-matrix losses [S1]. Unlike sparse pixel sampling, which is insufficient for CNN-based losses, this method enables full-resolution optimization by decoupling the loss computation from the differentiable rendering pass [S1]. It sets itself apart by maintaining the GPU memory footprint of a small patch while correctly computing gradients for the entire image [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A radiance field representation (scene parameters $\theta$), a camera viewpoint, a target image (or style image), and a loss function $L$ defined on full-resolution pixel colors.
*   **Outputs:** Accumulated gradients $\frac{\partial L}{\partial \theta}$ for the scene parameters.

**Data Structures:**
*   **Cached Gradient Image:** A 2D tensor of the same resolution as the rendered image, storing $\frac{\partial L}{\partial C_{ij}}$ for each pixel $(i,j)$.
*   **Patch Buffer:** A smaller 2D tensor representing a sub-region of the image, used for re-rendering.

**Steps:**
1.  **Full-Resolution Render (Non-Differentiable):** Render the full-resolution image $C_{full}$ from the current viewpoint using the radiance field, but with auto-differentiation disabled. This step computes the pixel colors but does not store intermediate gradients for the back-propagation graph [S1].
2.  **Loss and Gradient Caching:** Compute the image loss $L$ using $C_{full}$ and the target. Compute the gradient of the loss with respect to the pixel colors, $\frac{\partial L}{\partial C_{full}}$. Cache this gradient tensor in memory [S1].
3.  **Patch Iteration:** Define a set of non-overlapping (or overlapping, depending on implementation) patches that cover the full image resolution. Iterate through each patch $p$:
    a.  **Patch Re-render (Differentiable):** Render only the pixels corresponding to patch $p$ from the radiance field, with auto-differentiation enabled. Let the rendered patch colors be $C_p$.
    b.  **Local Back-propagation:** Retrieve the cached gradients for the pixels in patch $p$, denoted as $\frac{\partial L}{\partial C_p}$. Back-propagate these gradients through the differentiable rendering function for the patch to compute the local gradients for the scene parameters $\theta$ involved in rendering those pixels.
    c.  **Accumulation:** Add the computed local gradients to the global accumulated gradient buffer for $\theta$ [S1].
4.  **Optimization Step:** Use the accumulated gradients to update the scene parameters $\theta$ [S1].

**Pseudocode:**
```python
def deferred_backprop(radiance_field, camera, target_image, loss_fn, patch_size):
    # Step 1: Render full-resolution image without auto-diff
    with torch.no_grad():
        C_full = render_full_resolution(radiance_field, camera)
    
    # Step 2: Compute loss and cache gradients w.r.t. pixel colors
    loss = loss_fn(C_full, target_image)
    # Compute gradient of loss w.r.t. C_full
    grad_C_full = torch.autograd.grad(loss, C_full, retain_graph=True)[0]
    
    # Initialize gradient accumulator for scene parameters
    grad_theta = torch.zeros_like(radiance_field.parameters)
    
    # Step 3: Iterate over patches
    height, width = C_full.shape[1], C_full.shape[2]
    for y in range(0, height, patch_size):
        for x in range(0, width, patch_size):
            # Define patch boundaries
            y_end = min(y + patch_size, height)
            x_end = min(x + patch_size, width)
            
            # Extract cached gradients for this patch
            grad_C_patch = grad_C_full[:, y:y_end, x:x_end]
            
            # Step 3a: Re-render the patch with auto-diff enabled
            # Note: render_patch must only compute gradients for pixels in this patch
            C_patch = render_patch(radiance_field, camera, y, y_end, x, x_end)
            
            # Step 3b: Back-propagate cached gradients to scene parameters
            # We compute the gradient of the loss w.r.t. parameters using the 
            # cached gradient as the upstream gradient
            local_grad_theta = torch.autograd.grad(
                C_patch, 
                radiance_field.parameters, 
                grad_C_patch, 
                retain_graph=True, 
                create_graph=False
            )
            
            # Step 3c: Accumulate gradients
            for i, param in enumerate(radiance_field.parameters):
                grad_theta[i] += local_grad_theta[i]
                
    return grad_theta
```

**Parameters:**
*   **Patch Size:** Determines the trade-off between memory usage and computational overhead. Smaller patches use less memory but increase the number of re-rendering calls. Typical values are not explicitly given in the sources, but must be small enough to fit in GPU memory for differentiable rendering [S1].

**Edge Cases and Pitfalls:**
*   **Memory Overflow:** If the patch size is too large, the differentiable re-rendering step may still exceed GPU memory limits [S1].
*   **Gradient Consistency:** The method assumes that the rendering function is deterministic and that the cached gradients accurately reflect the loss landscape at the time of the initial render. Any changes to the radiance field between the initial render and the patch re-renders (e.g., if the radiance field is updated mid-iteration) would invalidate the cached gradients. The sources imply the radiance field parameters are fixed during the gradient accumulation phase [S1].
*   **Boundary Effects:** If patches overlap, gradients must be accumulated correctly to avoid double-counting. The sources describe a "patch-wise" manner but do not specify overlap handling; standard practice suggests non-overlapping patches or careful weighting for overlaps [S1].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of pixels and $P$ is the number of patches. The method requires one full-resolution render (non-differentiable) and $P$ partial differentiable renders. This is more computationally expensive than sparse sampling but necessary for full-resolution losses.
*   **Memory Complexity:** $O(P_{size} + N)$, where $P_{size}$ is the memory required for a single patch's differentiable render graph and $N$ is the memory for the cached gradient image. This is significantly lower than the $O(N)$ memory required for a full differentiable render [S1].
*   **Strengths:** Enables the use of sophisticated CNN-based losses (VGG, Gram matrix) that require full-resolution images, which sparse sampling cannot support [S1].
*   **Limitations:** Increased computational overhead due to multiple re-rendering passes. Not suitable for per-pixel losses (L1/L2) where sparse sampling is more efficient [S1].
*   **When to Use:** When optimizing radiance fields with style losses or other full-resolution image losses and GPU memory is constrained.
*   **When Not to Use:** For simple per-pixel losses (L1/L2) where sparse sampling is sufficient and more efficient [S1].

## Background
Deferred back-propagation was introduced in the context of "Artistic Radiance Fields" (ARF) by Zhang et al. [S1]. The method was developed to address the memory inefficiency of volumetric radiance field rendering, which typically consumes large amounts of GPU memory due to the composition of many samples per pixel [S1]. Prior methods often resorted to sparse pixel sampling, which was inadequate for style transfer tasks requiring VGG features from full-resolution images [S1]. The technique allows for high-quality 3D stylization by enabling the optimization of radiance fields with full-resolution image losses [S1].
