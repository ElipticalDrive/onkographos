# Deferred Back-propagation

Also called: Deferred Gradient Computation, Patch-wise Gradient Accumulation

## Overview
Deferred back-propagation is a memory-efficient technique for optimizing radiance fields using image losses that require full-resolution inputs, such as VGG-based style losses or Gram-matrix losses [S1]. Unlike sparse pixel sampling, which is insufficient for CNN-based losses, this method enables full-resolution optimization by decoupling the loss computation from the differentiable rendering pass [S1]. It sets itself apart by maintaining the memory footprint of a small patch while correctly computing gradients for the entire image, avoiding the geometric inaccuracies and lack of style details associated with sparse sampling [S1].

## How it works
**Inputs:**
*   A radiance field representation (e.g., 3D Gaussians or volumetric grid).
*   Camera viewpoints for rendering.
*   A loss function $L$ that operates on full-resolution 2D images (e.g., VGG feature loss).
*   Patch size parameters (width $W_p$, height $H_p$) and stride.

**Outputs:**
*   Updated scene parameters (positions, covariances, colors, opacities) via gradient accumulation.

**Data Structures:**
*   **Cached Gradient Buffer:** A 2D array of shape $(H, W, C)$ matching the full-resolution image, storing $\frac{\partial L}{\partial \mathbf{C}(x,y)}$. Data type is typically `float` or `half` depending on precision requirements.
*   **Scene Parameter Gradients:** Accumulated in standard optimizer buffers.

**Steps:**
1.  **Full-Resolution Forward Pass (Non-Differentiable):**
    Render the full-resolution image $\mathbf{C}_{full}$ from the current viewpoint. Auto-differentiation is explicitly disabled for this pass to save memory.
    $$
    \mathbf{C}_{full}(x,y) = \text{Render}_{\text{no\_grad}}(\text{Scene}, \text{Camera})
    $$

2.  **Loss and Gradient Computation:**
    Compute the image loss $L$ using $\mathbf{C}_{full}$ and the target style/content features. Compute the gradient of the loss with respect to the pixel colors:
    $$
    \mathbf{G}_{cached}(x,y) = \frac{\partial L}{\partial \mathbf{C}_{full}(x,y)}
    $$
    Store $\mathbf{G}_{cached}$ in the Cached Gradient Buffer.

3.  **Patch-wise Back-propagation:**
    Iterate over the image in patches. For each patch $p$ defined by spatial bounds $[x_1, x_2] \times [y_1, y_2]$:
    a.  **Patch Forward Pass (Differentiable):**
        Render only the pixels within the patch bounds. Auto-differentiation is enabled.
        $$
        \mathbf{C}_{patch}(x,y) = \text{Render}_{\text{grad}}(\text{Scene}, \text{Camera}, \text{Bounds}_p)
        $$
    b.  **Gradient Accumulation:**
        Extract the cached gradients for the current patch: $\mathbf{G}_{patch} = \mathbf{G}_{cached}[y_1:y_2, x_1:x_2]$.
        Back-propagate these gradients through the differentiable render function to update scene parameters $\theta$:
        $$
        \frac{\partial L}{\partial \theta} \leftarrow \frac{\partial L}{\partial \theta} + \sum_{(x,y) \in \text{Patch}_p} \frac{\partial L}{\partial \mathbf{C}_{patch}(x,y)} \frac{\partial \mathbf{C}_{patch}(x,y)}{\partial \theta}
        $$
        Note: $\frac{\partial L}{\partial \mathbf{C}_{patch}(x,y)}$ is simply $\mathbf{G}_{cached}(x,y)$ from Step 2.

4.  **Optimization Step:**
    Apply the accumulated gradients to the scene parameters using an optimizer (e.g., Adam).

**Pseudocode:**
```python
def deferred_backprop(scene, camera, loss_fn, patch_size=(256, 256)):
    # Step 1: Render full image without gradients
    with torch.no_grad():
        full_image = render(scene, camera)  # Shape: (H, W, C)
    
    # Step 2: Compute loss and cached gradients
    loss, cached_grads = compute_loss_and_grads(loss_fn, full_image)
    
    # Initialize scene gradients (handled by optimizer or manual accumulation)
    # Assuming scene parameters have .grad attributes
    
    # Step 3: Patch-wise back-propagation
    H, W = full_image.shape[:2]
    for y in range(0, H, patch_size[0]):
        for x in range(0, W, patch_size[1]):
            y_end = min(y + patch_size[0], H)
            x_end = min(x + patch_size[1], W)
            
            # Extract cached gradients for this patch
            patch_grads = cached_grads[y:y_end, x:x_end]
            
            # Render patch with gradients enabled
            # The render function must support bounding box culling or masking
            patch_image = render(scene, camera, bounds=(x, y, x_end, y_end))
            
            # Back-propagate cached gradients to scene parameters
            # This computes dL/d_theta for the current patch
            patch_image.backward(patch_grads)
            
    # Step 4: Optimizer step (external)
    optimizer.step()
    optimizer.zero_grad()
```

**Parameters:**
*   **Patch Size:** Determines the trade-off between memory usage and overhead. Typical values are $256 \times 256$ or $512 \times 512$ pixels, fitting within GPU memory limits for differentiable volume rendering [S1].
*   **Stride:** Can be equal to patch size (non-overlapping) or smaller (overlapping) depending on implementation needs. Non-overlapping is standard for this method [S1].

**Edge Cases and Pitfalls:**
*   **Memory Overflow:** If the patch size is too large, the differentiable render pass will OOM. The patch size must be small enough to hold the intermediate activation maps for all samples along rays within the patch [S1].
*   **Boundary Artifacts:** Non-overlapping patches may cause discontinuities if the loss function is sensitive to local pixel correlations (e.g., Gram matrix). However, since the loss is computed on the full image first, the gradients are consistent; the re-rendering is only for the Jacobian, so boundaries are handled correctly by the chain rule [S1].
*   **Precision:** Using `half` precision for cached gradients may introduce noise in style transfer tasks. `float` is preferred for the cached gradient buffer [S1].

## Operating characteristics
*   **Time Complexity:** $O(N_{patches} \cdot T_{render})$, where $N_{patches}$ is the number of patches covering the image and $T_{render}$ is the time to render one patch. This is slower than a single forward pass but necessary for memory constraints.
*   **Memory Complexity:** $O(W \cdot H \cdot C)$ for the cached gradient buffer plus $O(W_p \cdot H_p \cdot C)$ for the differentiable render buffer. This is significantly lower than $O(W \cdot H \cdot C)$ for the differentiable render buffer required by standard full-image back-propagation [S1].
*   **Strengths:** Enables the use of sophisticated CNN-based losses (VGG, Gram) on full-resolution images without OOM errors. Improves stylization quality and content preservation compared to sparse sampling [S1].
*   **Limitations:** Increased training time due to multiple render passes. Not suitable for per-pixel losses (L1/L2) where sparse sampling is more efficient [S1].
*   **When to Use:** When optimizing radiance fields with style losses, perceptual losses, or any loss requiring full-image context.
*   **When Not to Use:** For simple photometric losses (L1/L2) where sparse pixel sampling is sufficient and faster [S1].

## Background
Deferred back-propagation was introduced in the context of "Artistic Radiance Fields" (ARF) by Zhang et al. [S1]. The method addresses the limitation of volumetric radiance field rendering, which is memory-inefficient because pixel color is composited from many samples, making full-resolution rendering impractical for CNN-based losses [S1]. Prior methods often resorted to sparse pixel sampling, which fails for losses like NNFM or Gram matrices that require full-resolution images [S1]. The technique allows for high-quality 3D stylization by enabling the use of full-resolution style images, leading to better visual quality and consistency across viewpoints compared to previous methods [S1].
