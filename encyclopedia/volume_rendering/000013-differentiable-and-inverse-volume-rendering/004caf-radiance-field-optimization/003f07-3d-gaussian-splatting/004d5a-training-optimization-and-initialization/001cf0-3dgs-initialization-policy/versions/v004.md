# 3DGS Initialization Policy

Also called: Initialization Policy, OTS Initialization

## Overview
The 3DGS Initialization Policy defines the deterministic starting configuration for the set of 3D Gaussians in a scene, ensuring that the optimization process begins with a uniform distribution of primitives. It solves the problem of arbitrary initial placement by providing a reproducible baseline for both standard 3D Gaussian Splatting (3DGS) and Order-Independent Transparency (OTS) based methods. It sets apart from heuristic or random initialization strategies by using a fixed power-law scaling for opacity and a uniform random distribution within a bounding volume, which serves as the foundation for subsequent densification and optimization steps [S1].

## How it works
The method initializes a set of $N$ Gaussians within a defined spatial volume. The core of the policy is the uniform assignment of opacity (or OTS weight) derived from the total number of Gaussians, ensuring that the initial integrated opacity of the scene is consistent regardless of $N$.

**Inputs and Outputs:**
*   **Input:** Total number of Gaussians $N$; scene bounding box (typically a unit cube centered at the origin for synthetic scenes).
*   **Output:** A set of $N$ Gaussian primitives, each with position $\mathbf{p}$, covariance $\Sigma$, opacity $\alpha$, and other attributes (color, rotation) initialized to default or random values.

**Data Structures:**
Each Gaussian primitive stores:
*   $\mathbf{p} \in \mathbb{R}^3$: Position (randomly sampled).
*   $\Sigma \in \mathbb{R}^{3 \times 3}$: Covariance matrix (initialized to identity or small random perturbation, though specific covariance initialization is not detailed in the primary source, standard 3DGS practice implies isotropic or small random scales).
*   $\alpha \in [0, 1]$: Opacity (uniformly calculated).
*   Other attributes (SH coefficients, rotation quaternion) are typically initialized to neutral values (e.g., zero rotation, uniform color) or random values depending on the specific implementation, but the policy specifically mandates uniform opacity.

**Steps:**
1.  **Define Bounding Volume:** For standard synthetic scenes (e.g., Nerf-Synthetic), define a unit cube centered at the scene origin. For real-world scenes, this may be adapted to the scene's bounding box [S1].
2.  **Sample Positions:** Generate $N$ random positions $\mathbf{p}_i$ uniformly distributed within the bounding volume for $i = 1 \dots N$.
3.  **Calculate Uniform Opacity:** Compute the initial opacity $\alpha$ for all Gaussians using a power function of $N$. The exponent depends on the rendering formulation:
    *   For standard 3DGS: $\alpha = 2 N^{-0.35}$ [S1].
    *   For OTS-based methods: $\alpha = 2 N^{-0.55}$ [S1].
4.  **Initialize Attributes:** Assign the calculated $\alpha$ to all $N$ Gaussians. Initialize other attributes (rotation, color, scale) to default or random values as per the base 3DGS implementation [S1].

**Formula:**
The opacity $\alpha$ is given by:
$$
\alpha = 2 N^{-\beta}
$$
where:
*   $N$ is the total number of Gaussians.
*   $\beta = 0.35$ for standard 3DGS.
*   $\beta = 0.55$ for OTS-based methods [S1].

**Parameters:**
*   $N$: Total number of Gaussians. Typical values cited are 4k, 12k, 36k, 100k, 500k, 1m, and 5m [S1].
*   Bounding Box: Unit cube (for Nerf-Synthetic) [S1].

**Pseudocode:**
```python
def initialize_gaussians(N, scene_bbox_min, scene_bbox_max):
    """
    Initialize N Gaussians with uniform opacity based on the 3DGS/OTS policy.
    
    Args:
        N (int): Total number of Gaussians.
        scene_bbox_min (np.array): Min coordinates of the bounding box.
        scene_bbox_max (np.array): Max coordinates of the bounding box.
        
    Returns:
        gaussians (dict): Dictionary containing initialized attributes.
    """
    # Step 1: Sample random positions uniformly within the bounding box
    # Positions are sampled from a uniform distribution over the volume
    positions = np.random.uniform(
        low=scene_bbox_min, 
        high=scene_bbox_max, 
        size=(N, 3)
    )
    
    # Step 2: Determine the exponent beta based on the method
    # Note: The caller must specify if this is standard 3DGS or OTS
    # For standard 3DGS: beta = 0.35
    # For OTS: beta = 0.55
    # This function assumes a parameter 'method_type' is passed or determined externally.
    # Here we assume standard 3DGS for the base implementation.
    beta = 0.35 
    
    # Step 3: Calculate uniform opacity
    # Formula: alpha = 2 * N^(-beta)
    opacity = 2.0 * (N ** (-beta))
    
    # Initialize other attributes
    # Rotations: Initialize to identity (no rotation)
    rotations = np.zeros((N, 4))
    rotations[:, 0] = 1.0  # w=1, x=y=z=0 for identity quaternion
    
    # Scales: Initialize to a small random value or identity scale
    # The source does not specify exact scale initialization, so we use a small random perturbation
    scales = np.random.uniform(low=0.01, high=0.1, size=(N, 3))
    
    # Colors: Initialize to a neutral color (e.g., white or black) or random
    # Standard 3DGS often initializes colors randomly or to a base color
    colors = np.ones((N, 3)) # Placeholder for SH coefficients or base color
    
    # Step 4: Construct the Gaussian set
    gaussians = {
        'positions': positions,
        'opacities': np.full(N, opacity),
        'rotations': rotations,
        'scales': scales,
        'colors': colors
    }
    
    return gaussians
```

**Edge Cases and Pitfalls:**
*   **Precision:** For very large $N$ (e.g., 1m, 5m), the opacity $\alpha$ becomes very small. Ensure floating-point precision is sufficient to represent these small values without underflow, although standard float32 is generally sufficient for $N \le 10^7$.
*   **Boundary Conditions:** If the scene bounding box is not axis-aligned or is significantly larger than the unit cube, the random position sampling must be adjusted accordingly. The source specifically mentions the unit cube for Nerf-Synthetic [S1].
*   **Degenerate Input:** $N=0$ is not a valid input. The formula assumes $N \ge 1$.

## Subtopics

### Geometric Correction via Neural Gaussians
A strategy to maximize overlap between cells and emitted neural Gaussians by dynamically aligning cell geometry with Gaussian properties. It involves three steps: (1) Dynamically defining the cell's quaternion as a weighted average of the quaternions associated with its emitted Gaussians; (2) Periodically updating cell centers using the formula $\mathbf{x}_n = \frac{\sum_{k=1}^K \boldsymbol{\mu}_{n,k}}{K}$, where $\mathbf{x}_n$ is the cell center, $K$ is the number of Gaussians in the cell, and $\boldsymbol{\mu}_{n,k}$ is the mean of the k-th Gaussian in cell n; (3) Learning the three-dimensional covariances and positions of first-layer cells in accordance with the updates to the second-layer Gaussians, leveraging the differentiability of cell scales [S2].

### Cell Position Reset
Following adaptive density control, new cells are grown at Gaussians with high view-space positional gradients. To decouple existing cells from newly introduced ones, the offsets of the significant Gaussians are reset to zero after cell growth, i.e., their positions are reinitialized to the centers of the corresponding cells [S2].

## Operating characteristics
*   **Time Complexity:** Initialization is $O(N)$ for sampling positions and computing opacity.
*   **Memory Complexity:** $O(N)$ to store the Gaussian attributes.
*   **Performance:** The policy provides a reproducible baseline. The choice of exponent ($\beta$) affects the initial opacity, which influences the convergence speed and final quality. OTS methods require a higher exponent ($\beta=0.55$) compared to standard 3DGS ($\beta=0.35$) due to different image formation solutions [S1].
*   **Strengths:** Simple, deterministic, and reproducible. Ensures consistent initial conditions across experiments.
*   **Limitations:** Does not account for scene geometry or structure. Relies on subsequent densification to adapt to the scene.
*   **When to use:** Standard initialization for 3DGS and OTS-based methods, particularly for synthetic scenes like Nerf-Synthetic.
*   **When not to use:** If the scene has significant structure that could be exploited for better initial placement (e.g., using point cloud data from SfM).

## Background
The initialization policy was introduced in the context of evaluating whether 3D Gaussian Splatting requires accurate volumetric rendering. It was adopted from the original 3DGS codebase for training on Nerf-Synthetic datasets [S1]. The policy was adapted for OTS-based methods to account for their different image formation solutions, leading to the distinct exponents for opacity calculation [S1].
