# 4D Gaussian Rotation Construction


## Overview
Constructs a 4x4 rotation matrix for 4D Gaussians from two quaternion-like vectors `l` and `r` representing temporal and spatial rotations respectively. It sets itself apart from standard 3D rotation by explicitly modeling the temporal dimension as a rotation component, allowing for rigid body motion in spacetime.

## How it works
**Inputs:**
- `l`: Tensor of shape `(N, 4)` containing temporal rotation quaternions.
- `r`: Tensor of shape `(N, 4)` containing spatial rotation quaternions.

**Outputs:**
- `A`: Tensor of shape `(N, 4, 4)` representing the combined 4D rotation matrix.

**Data Structures:**
- The method operates on batched tensors. `N` is the number of Gaussians.
- Intermediate matrices `M_l` and `M_r` are of shape `(N, 4, 4)`.

**Steps:**
1.  **Normalize:** Compute the L2 norm of `l` and `r` along the last dimension. Divide `l` and `r` by their respective norms to obtain normalized quaternions `q_l` and `q_r`. [S1, unofficial]
2.  **Unpack:** Extract components from `q_l` as `a, b, c, d` and from `q_r` as `p, q, r, s`. Note that `r` here is a scalar component, distinct from the input tensor `r`. [S1, unofficial]
3.  **Construct $M_l$:** Build the temporal rotation matrix $M_l$ using the permutation and sign pattern derived from `q_l`. The raw 16-element vector is `[a, -b, -c, -d, b, a, -d, c, c, d, a, -b, d, -c, b, a]`. This vector is reshaped to `(N, 4, 4)` and then permuted. The specific permutation maps indices to form the standard quaternion-to-matrix conversion for the temporal part. [S1, unofficial]
4.  **Construct $M_r$:** Build the spatial rotation matrix $M_r$ using the pattern from `q_r`. The raw 16-element vector is `[p, q, r, s, -q, p, -s, r, -r, s, p, -q, -s, -r, q, p]`. Reshape to `(N, 4, 4)` and permute similarly to $M_l$. [S1, unofficial]
5.  **Combine:** Compute the final rotation matrix $A$ as the matrix product $M_l @ M_r$. [S1, unofficial]
6.  **Flip Dimensions:** Flip the last two dimensions of $A$ (swap axes 2 and 3) to correct for the specific coordinate system convention used in the rendering pipeline. [S1, unofficial]

**Pseudocode:**
```python
import torch

def build_rotation_4d(l, r):
    """
    Constructs a 4x4 rotation matrix for 4D Gaussians.
    
    Args:
        l: Tensor of shape (N, 4) for temporal rotation.
        r: Tensor of shape (N, 4) for spatial rotation.
        
    Returns:
        A: Tensor of shape (N, 4, 4) representing the 4D rotation.
    """
    # Step 1: Normalize
    l_norm = torch.norm(l, dim=-1, keepdim=True)
    r_norm = torch.norm(r, dim=-1, keepdim=True)
    
    # Handle potential zero norms to avoid division by zero [G]
    l_norm = torch.clamp(l_norm, min=1e-8)
    r_norm = torch.clamp(r_norm, min=1e-8)
    
    q_l = l / l_norm
    q_r = r / r_norm
    
    # Step 2: Unpack components
    a, b, c, d = q_l[..., 0], q_l[..., 1], q_l[..., 2], q_l[..., 3]
    p, q, r_comp, s = q_r[..., 0], q_r[..., 1], q_r[..., 2], q_r[..., 3]
    
    # Step 3: Construct M_l
    # Pattern: [a,-b,-c,-d, b, a,-d, c, c, d, a,-b, d,-c, b, a]
    # Reshape to (N, 4, 4)
    M_l_flat = torch.stack([
        a, -b, -c, -d,
        b,  a, -d,  c,
        c,  d,  a, -b,
        d, -c,  b,  a
    ], dim=-1).view(-1, 4, 4)
    
    # Step 4: Construct M_r
    # Pattern: [p, q, r, s, -q, p, -s, r, -r, s, p, -q, -s, -r, q, p]
    M_r_flat = torch.stack([
        p,  q,  r_comp,  s,
       -q,  p,  -s,     r_comp,
       -r_comp, s,  p,   -q,
       -s, -r_comp, q,   p
    ], dim=-1).view(-1, 4, 4)
    
    # Step 5: Combine
    A = torch.bmm(M_l_flat, M_r_flat)
    
    # Step 6: Flip last two dimensions
    A = A.transpose(1, 2)
    
    return A
```

**Parameters:**
- No explicit hyperparameters. The method is deterministic given inputs `l` and `r`.

**Edge Cases:**
- **Zero Norms:** If `l` or `r` has a zero norm, normalization fails. A small epsilon should be added to the norm denominator to prevent NaNs [G].
- **Degenerate Input:** If the input quaternions are not unit vectors, the resulting matrix will not be a pure rotation (it will include scaling). The normalization step ensures unit length.

## Subtopics

### 4D Scaling and Rotation Construction
Combines 4D scaling and 4D rotation into a single transformation matrix. It initializes a zero matrix `L` of shape `(N, 4, 4)`, sets the diagonal elements to the scaling factors `s[:,0]` to `s[:,3]`, computes the rotation matrix `R` using `build_rotation_4d(l, r)`, and returns `R @ L`. This allows for anisotropic scaling in 4D spacetime alongside rotation. [S1, unofficial]

## Operating characteristics
- **Time Complexity:** $O(N)$ for normalization and unpacking, $O(N)$ for matrix construction, and $O(N \cdot 4^3) = O(N)$ for the matrix multiplication. Overall linear in the number of Gaussians.
- **Memory Complexity:** $O(N \cdot 4^2)$ for storing the output matrix. Intermediate matrices also require $O(N \cdot 4^2)$.
- **Strengths:** Efficiently computes rigid body transformations in 4D spacetime, enabling the rendering of dynamic scenes with moving Gaussians.
- **Limitations:** Assumes rigid rotation. Non-rigid deformations require additional modeling. The method is specific to the 4D Gaussian Splatting framework and may not be directly applicable to other volume rendering techniques without adaptation.

## Background
Originated in the context of 4D Gaussian Splatting, specifically within the 4D-Rotor Gaussian Splatting method which uses Clifford algebra to define 4D primitives. The method was introduced to handle the temporal dimension as a rotation component, allowing for more realistic motion representation in dynamic scene reconstruction. [S1, unofficial]
