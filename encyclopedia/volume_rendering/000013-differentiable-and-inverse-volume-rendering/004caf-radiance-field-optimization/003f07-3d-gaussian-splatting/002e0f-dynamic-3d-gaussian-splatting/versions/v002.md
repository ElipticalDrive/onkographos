# Dynamic 3D Gaussian Splatting

Also called: 3DGS with temporal constraints, Dynamic 3DGS

## Overview
Dynamic 3D Gaussian Splatting enables real-time novel view synthesis of dynamic scenes by maintaining a set of 3D Gaussians whose positions and orientations evolve over time [S1, unofficial]. It solves the problem of temporal inconsistency and flickering inherent in per-frame independent reconstruction by enforcing physical plausibility through local-rigid and As-Rigid-As-Possible (ARAP) constraints [S1, unofficial]. Unlike deformation-field methods that predict offsets from a canonical space, this approach tracks explicit time-varying parameters for each Gaussian particle [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of images $\{I_t\}$ captured at times $t$, along with camera poses $P_t$.
*   **Output:** A set of $N$ dynamic 3D Gaussians, each defined by time-varying parameters $\{\boldsymbol{\mu}_t, q_t, s_t, \mathbf{c}_t, \alpha_t\}$ for $t \in [0, T]$, where $\boldsymbol{\mu}_t$ is position, $q_t$ is rotation quaternion, $s_t$ is scale, $\mathbf{c}_t$ is color, and $\alpha_t$ is opacity.

**Data Structures:**
Each Gaussian $i$ stores:
*   $\boldsymbol{\mu}_{i,t} \in \mathbb{R}^3$: Position at time $t$.
*   $q_{i,t} \in \mathbb{R}^4$: Rotation quaternion at time $t$.
*   $s_{i,t} \in \mathbb{R}^3$: Scale vector.
*   $\mathbf{c}_{i,t} \in \mathbb{R}^3$: Spherical harmonic coefficients (or RGB).
*   $\alpha_{i,t} \in \mathbb{R}$: Opacity.
*   *Note:* The core innovation is the temporal linkage of $\boldsymbol{\mu}$ and $q$.

**Algorithm Steps:**
1.  **Initialization:** Initialize a static 3DGS scene from the first frame or a sparse reconstruction.
2.  **Temporal Tracking:** For each subsequent frame $t$, update $\boldsymbol{\mu}_{i,t}$ and $q_{i,t}$ based on motion.
3.  **Constraint Application:** Apply local-rigid and ARAP constraints to ensure that the deformation of neighboring Gaussians remains physically plausible (rigid body motion or isometry) [S1, unofficial].
4.  **Rendering:** Render the scene at time $t$ using the standard 3DGS rasterizer with the updated parameters.
5.  **Optimization:** Minimize the photometric loss between rendered and ground truth images, plus regularization terms derived from the ARAP constraints.

**Formulas:**
The ARAP constraint minimizes the deviation from rigid transformations. For a Gaussian $i$ and its neighbors $j \in \mathcal{N}_i$, the energy is:
$$ E_{ARAP} = \sum_{i} \sum_{j \in \mathcal{N}_i} w_{ij} \| (\boldsymbol{\mu}_{j,t} - \boldsymbol{\mu}_{i,t}) - R_i (\boldsymbol{\mu}_{j,0} - \boldsymbol{\mu}_{i,0}) \|^2 $$
where $R_i$ is the optimal rotation matrix derived from the initial configuration, and $w_{ij}$ are weights [S1, unofficial].

**Parameters:**
*   ARAP weight: Balances photometric loss against geometric constraints.
*   Neighbor radius: Defines $\mathcal{N}_i$ for local rigidity.

**Edge Cases:**
*   **Degenerate Input:** If motion is too large, local-rigid assumptions may fail, causing tearing.
*   **Precision:** Quaternion normalization must be enforced at each step to prevent drift.

**Pseudocode:**
```python
def update_dynamic_gaussians(gaussians, t, neighbors):
    """
    Update position and rotation of Gaussians using ARAP constraints.
    """
    for g in gaussians:
        # Calculate optimal rigid transformation from initial state
        # to current state based on neighbors
        R_opt = compute_optimal_rotation(g, neighbors[t-1], neighbors[t])
        
        # Apply rotation to relative positions
        for neighbor in neighbors[t]:
            relative_pos = neighbor.pos - g.pos
            rotated_pos = R_opt @ relative_pos
            neighbor.pos = g.pos + rotated_pos
            
        # Update rotation quaternion
        g.rot = R_opt_to_quaternion(R_opt)
        
    return gaussians
```
*Note: The exact implementation of `compute_optimal_rotation` involves SVD on the covariance of relative positions [G].*

## Subtopics

### [GaussianFlow](6149-gaussianflow.md)
GaussianFlow treats each Gaussian as a dynamic particle advected by a 3D velocity field, obtaining the 4D reconstruction by integrating the flow over time. It introduces 2D flow estimation results into the training of dynamic 3D Gaussians to support deformation modeling between neighboring frames. Unlike parent methods that rely on local-rigid or ARAP constraints, GaussianFlow uses an explicit flow field for temporal regularization.

## Operating characteristics
*   **Time Complexity:** $O(N)$ per frame for rendering, where $N$ is the number of Gaussians. Optimization is slower due to constraint calculations.
*   **Memory Complexity:** $O(N \cdot T)$ if storing full trajectories, or $O(N)$ if predicting updates incrementally.
*   **Performance:** Real-time rendering is achievable. Training time is higher than static 3DGS due to temporal constraints.
*   **Strengths:** High temporal consistency, physically plausible motion, real-time rendering.
*   **Limitations:** Struggles with large, non-rigid deformations; sensitive to initialization.
*   **When to use:** Dynamic scenes with moderate motion (e.g., human avatars, moving objects).
*   **When not to use:** Scenes with extreme, non-rigid deformations or occlusions that break local rigidity.

## Background
Dynamic 3D Gaussian Splatting was introduced by Luiten et al. in 3DV'24 [S1, unofficial]. It extends the static 3DGS framework to handle dynamic scenes by incorporating temporal constraints, addressing the flickering and inconsistency issues of per-frame reconstruction methods [S1, unofficial].
