# Contribution-based Pruning

Also called: Opacity and Scale Pruning, Quantile-based Pruning, Gaussian Culling, Point Pruning, Regularization via Pruning

## Overview
Contribution-based Pruning is a regularization strategy to remove redundant 3D Gaussian primitives during training by jointly evaluating their opacity and spatial scale attributes [S2, unofficial]. It identifies Gaussians with low visibility and negligible geometric extent as insignificant and removes them to decrease storage costs and improve rendering efficiency [S2, unofficial]. Unlike pruning based solely on opacity or scale, which leads to substantial performance degradation, this method leverages the complementary nature of both attributes to balance rendering quality and computational overhead [S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Set of Gaussian primitives $\mathcal{G}$, current iteration $t$, pruning threshold $\tau$, pruning interval $I_{prune}$, vote threshold $v$ [S2, unofficial].
- Output: Updated set of Gaussian primitives $\mathcal{G}_{new}$ with redundant Gaussians removed [S2, unofficial].

**Data Structures:**
- $\mathcal{G}$: Set of active Gaussians. Each Gaussian $g$ has attributes: opacity $o_g$, scale vector $\mathbf{s}_g$ (or maximum scale $s_{max}(g)$), position, rotation, spherical harmonics coefficients [G].
- $V_g^{(t)}$: Accumulated vote count for Gaussian $g$ at iteration $t$. Initialized to $V_g^{(0)} = 0$ [S2, unofficial].

**Steps:**
1. **Compute Attributes:** At each iteration $t$, compute the per-primitive opacity $o_g$ and the maximum scale $s_{max}(g)$ across dimensions for all $g \in \mathcal{G}$ [S2, unofficial].
2. **Identify Candidates:** Determine the set of pruning candidates $\mathcal{C}_{\text{prune}}^{(t)}$ by applying a quantile threshold $\tau$ to both opacity and scale distributions [S2, unofficial].
   - Compute the $\tau$-quantile of opacity $Q_\tau(o)$ and maximum scale $Q_\tau(s_{max})$ over the current set $\mathcal{G}$ [S2, unofficial].
   - Define opacity candidates: $\mathcal{C}_{\text{opacity}}^{(t)} = \{g \in \mathcal{G} \mid o_g < Q_\tau(o)\}$ [S2, unofficial].
   - Define scale candidates: $\mathcal{C}_{\text{scale}}^{(t)} = \{g \in \mathcal{G} \mid s_{max}(g) < Q_\tau(s_{max})\}$ [S2, unofficial].
   - The pruning candidate set is the intersection: $\mathcal{C}_{\text{prune}}^{(t)} = \mathcal{C}_{\text{opacity}}^{(t)} \cap \mathcal{C}_{\text{scale}}^{(t)}$ [S2, unofficial].
3. **Accumulate Votes:** Update the vote count for each Gaussian. If $g \in \mathcal{C}_{\text{prune}}^{(t)}$, increment its vote count [S2, unofficial].
   - Formula: $V_g^{(t+1)} = V_g^{(t)} + \mathbf{1}_{\{g \in \mathcal{C}_{\text{prune}}^{(t)}\}}$, where $\mathbf{1}$ is the indicator function [S2, unofficial].
   - Initialize $V_g^{(0)} = 0$ [S2, unofficial].
4. **Prune:** Check if any Gaussian has accumulated enough votes to be permanently removed. This check is typically performed every $I_{prune}$ iterations [S2, unofficial].
   - A Gaussian $g$ is pruned if $V_g^{(t)} > I_{prune} \cdot v$ [S2, unofficial].
   - Update the Gaussian set: $\mathcal{G}_{new} = \mathcal{G} \setminus \{g \in \mathcal{G} \mid V_g^{(t)} > I_{prune} \cdot v\}$ [S2, unofficial].

**Parameters:**
- $\tau$: Pruning threshold (quantile). A larger threshold results in more aggressive pruning. Typical value: 0.2 [S2, unofficial].
- $I_{prune}$: Pruning interval. Value not explicitly given in the main definition section, but used in the threshold calculation. In Distribution-based Pruning variant, set to 1000 [S2, unofficial].
- $v$: Vote threshold. In Distribution-based Pruning variant, set to 0.6 [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Early Training Noise:** Pruning immediately based on single iterations can lead to noisy fluctuations in opacity or scale. The accumulated vote mechanism mitigates this [S2, unofficial].
- **Single Criterion Limitation:** Pruning based solely on opacity or scale leads to substantial performance degradation compared to using both attributes jointly [S2, unofficial].
- **Timing:** Pruning should be applied only during specific phases (e.g., initial 25k iterations) to prevent excessive removal when finer details are critical [S2, unofficial].

**Pseudocode:**
```python
def contribution_based_pruning(G, t, tau, I_prune, v):
    """
    G: List of Gaussian objects, each with attributes .opacity and .max_scale
    t: Current training iteration
    tau: Quantile threshold (e.g., 0.2)
    I_prune: Pruning interval (e.g., 1000)
    v: Vote threshold (e.g., 0.6)
    """
    if not G:
        return G

    # Step 1: Compute attributes (already available in G)
    opacities = [g.opacity for g in G]
    scales = [g.max_scale for g in G]

    # Step 2: Identify candidates using quantile threshold
    q_opacity = quantile(opacities, tau)
    q_scale = quantile(scales, tau)

    C_prune = []
    for g in G:
        if g.opacity < q_opacity and g.max_scale < q_scale:
            C_prune.append(g)

    # Step 3: Accumulate votes
    for g in G:
        if g in C_prune:
            g.vote_count += 1

    # Step 4: Prune if interval reached and threshold exceeded
    if t > 0 and t % I_prune == 0:
        threshold = I_prune * v
        G_new = [g for g in G if g.vote_count <= threshold]
        G = G_new
        
    return G

def quantile(values, tau):
    """Compute the tau-quantile of a list of values [G]."""
    sorted_vals = sorted(values)
    n = len(sorted_vals)
    index = tau * (n - 1)
    lower = int(index)
    upper = lower + 1
    if upper >= n:
        return sorted_vals[-1]
    weight = index - lower
    return sorted_vals[lower] * (1 - weight) + sorted_vals[upper] * weight
```

## Subtopics

### Accumulated Vote Pruning
A pruning strategy that mitigates noisy fluctuations in opacity or scale during early training by accumulating votes for Gaussians selected as pruning candidates, rather than removing them immediately [S2, unofficial]. It identifies pruning candidates $\mathcal{C}_{\text{prune}}^{(t)}$ based on opacity and scale criteria, updates vote counts $V_g^{(t+1)} = V_g^{(t)} + \mathbf{1}_{\{g \in \mathcal{C}_{\text{prune}}^{(t)}\}}$, and permanently prunes Gaussians $g$ where $V_g^{(t)} > I_{prune} \cdot v$ [S2, unofficial]. This ensures that only consistently low-contributing Gaussians are removed [S2, unofficial].

### Distribution-based Pruning
A strategy to remove redundant Gaussian primitives and improve efficiency, specifically applied only during the initial 25k iterations to prevent excessive removal in later stages where finer details are critical [S2, unofficial]. It uses a pruning interval $I_{prune}$ of 1000, a vote threshold $v$ of 0.6, and a redundancy identification threshold $\tau$ of 0.2 [S2, unofficial]. This design allows the model to retain representation capacity while substantially reducing unnecessary primitives in early training [S2, unofficial].

### θ+Opacity Rule Pruning
A pruning rule based on theta and opacity that localizes sacrifice at city scale, serving as a complementary export to the score-based export [S3, unofficial]. It acts as a baseline pruning method compared against the score export [S3, unofficial]. At 10% primitives, the score export dominates LightGaussian (+0.45 dB PSNR), RAP (+0.80 dB), and PUP score (+0.37 dB) [S3, unofficial]. The score export requires one 234s scoring pass with no retraining and extends to extreme budgets: 13.49 dB at 5%, 12.97 dB at 2.5%, 12.53 dB at 1.3% of primitives [S3, unofficial]. The θ+opacity rule is the best LPIPS export at every extreme budget (e.g., 0.547 vs 0.557 for score export at 10%; 0.601 for RAP), consistent with its design of removing perceptually redundant mass [S3, unofficial]. The score export keeps street markings and facades legible at 10% where LightGaussian blurs and RAP collapses [S3, unofficial].

### Iterative Pruning
Removes Gaussian points in multiple sequential iterations to reduce model size while maintaining visual quality [S4]. Iter1 removes 40% of points using a pruning rate of 0.4. Iter2 and Iter3 repeat the same procedure. Iter4 evaluates candidate rates (0.4, 0.3, 0.25, 0.2, 0.1) and selects 0.2 based on the tradeoff between point removal and quality loss [S4]. The pruning rate is the fraction of points removed per iteration, with typical values of 0.4 for Iter1-3 and 0.2 for Iter4 [S4]. It removes 87% of Gaussian points and reduces model size by 82.7% on average across datasets, with an average PSNR drop of 0.23 dB [S4]. Iterative pruning with fine-tuning between steps allows a better quality-size tradeoff compared to single-pass pruning, as it adapts to the remaining point distribution [S4].

## Operating characteristics
**Time and Memory Complexity:**
- The pruning step involves computing quantiles over the set of Gaussians, which is $O(N \log N)$ or $O(N)$ depending on the quantile algorithm, where $N$ is the number of Gaussians [G].
- Memory overhead is minimal, requiring storage for vote counts $V_g$ [S2, unofficial].

**Measured Performance:**
- On the baseline Mobile-GS (0.56M Gaussians, 27.22 PSNR, 109 FPS), applying pruning with threshold 0.2 reduces Gaussians to 0.47M, maintains 27.12 PSNR, and increases FPS to 127 [S2, unofficial].
- Pruning based solely on opacity reduces Gaussians to 0.43M but drops PSNR to 26.84 and increases FPS to 135 [S2, unofficial].
- Pruning based solely on scale reduces Gaussians to 0.45M but drops PSNR to 26.87 and increases FPS to 132 [S2, unofficial].

**Strengths and Limitations:**
- **Strengths:** Jointly considering opacity and scale provides a more balanced pruning decision, discarding a large portion of redundant primitives while maintaining high rendering fidelity [S2, unofficial]. It reduces memory and computational overhead with minimal loss of precision [S2, unofficial]. It can be seamlessly integrated with existing GS pruning methods like MaskGaussian and Mini-Splatting to further reduce Gaussian points [S2, unofficial].
- **Limitations:** Pruning based on a single attribute (opacity or scale) leads to substantial performance degradation [S2, unofficial]. Aggressive pruning (higher $\tau$) can reduce storage but may impact quality if not balanced [S2, unofficial].

**When to Use:**
- Use when computational efficiency and memory reduction are priorities, such as on mobile devices [S2, unofficial].
- Use during training phases where redundant primitives are likely to emerge (e.g., early training) [S2, unofficial].

**When Not to Use:**
- Avoid using solely opacity or scale pruning if high fidelity is required [S2, unofficial].
- Avoid aggressive pruning in later training stages where fine details are critical [S2, unofficial].

## Background
Contribution-based Pruning was introduced in the Mobile-GS paper, which proposes real-time Gaussian Splatting for mobile devices [S2, unofficial]. The method was developed to address the high computational and memory costs of 3D Gaussian Splatting on resource-constrained hardware [S2, unofficial]. It builds on the insight that Gaussians with larger opacity and scale have more important contributions to the final image [S2, unofficial]. The technique is part of a broader effort to optimize 3DGS for mobile deployment, including neural vector quantization and lightweight SH feature compression [S2, unofficial].
