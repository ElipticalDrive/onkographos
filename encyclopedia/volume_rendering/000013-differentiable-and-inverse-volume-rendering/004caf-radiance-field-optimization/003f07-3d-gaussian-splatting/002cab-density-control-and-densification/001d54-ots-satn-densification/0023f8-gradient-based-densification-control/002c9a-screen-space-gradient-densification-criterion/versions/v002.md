# Screen-Space Gradient Densification Criterion

Also called: Screen-Space Gradient Densification

## Overview
This method provides a criterion for 3D primitive densification based on the mean magnitude of the gradient of the photometric loss with respect to the projected 2D screen-space center of the primitive, accumulated over all training views [S1, unofficial]. It differs from alternatives like 2DGS [Huang et al. 2024] by using an analytical T-matrix backward pass to avoid conflating depth and lateral motion, which prevents gradient cancellation and ensures the signal faithfully captures the rendering residual [S1, unofficial].

## How it works
**Inputs:** Photometric loss $\mathcal{L}_j$ for each training view $j$, the $4 \times 4$ projection matrix $T$ for each view, and the specific projection row index $z$ [S1, unofficial].
**Outputs:** Mean gradient score $\bar{g}_i$ for each primitive $i$ [S1, unofficial].
**Data Structures:** $T$ stores projection coefficients where $T_{m,n}$ denotes the $n$-component of the $m$-th row [S1, unofficial]. $\boldsymbol{\mu}_i$ represents the projected 2D screen-space center of primitive $i$ [S1, unofficial]. $\bar{g}_i$ is a scalar score for primitive $i$ [S1, unofficial].

**Steps:**
1. For each primitive $i$ and each view $j$ where the primitive contributes to the rendered image, identify the specific row index $z$ used for projection in the T-matrix backward pass [S1, unofficial].
2. Compute the screen-space center coordinates $(u, v)$ using the T-matrix components: $u = T_{1,z}/T_{4,z}$ and $v = T_{2,z}/T_{4,z}$ [S1, unofficial].
3. Compute the per-pixel contributions to the screen-space positional gradient $(g_x, g_y)$ using the chain rule through the T-matrix gradients: $g_x = \frac{\partial \mathcal{L}}{\partial T_{1,z}} \cdot T_{4,z}$ and $g_y = \frac{\partial \mathcal{L}}{\partial T_{2,z}} \cdot T_{4,z}$ [S1, unofficial].
4. Accumulate the gradient magnitude for primitive $i$ in view $j$ by taking the Euclidean norm of the analytical components: $\left\| \frac{\partial \mathcal{L}_j}{\partial \boldsymbol{\mu}_i} \right\|_2 \approx \sqrt{g_x^2 + g_y^2}$ [S1, unofficial].
5. Calculate the mean gradient score $\bar{g}_i$ for primitive $i$ over all $N$ views where it contributed: $\bar{g}_i = \frac{1}{N} \sum_{j=1}^N \left\| \frac{\partial \mathcal{L}_j}{\partial \boldsymbol{\mu}_i} \right\|_2$ [S1, unofficial].

**Pseudocode:**
```python
import math

def compute_screen_space_gradient_score(primitive_i, views):
    """
    Computes the mean screen-space gradient score for a primitive.
    Args:
        primitive_i: Primitive object with a contributed_to(view) method.
        views: List of view objects, each containing:
            - T: 4x4 projection matrix (list of lists, 0-based indexing)
            - dL_dT: Gradient of loss w.r.t. T matrix (4x4, 0-based indexing)
            - z: Specific row index used for projection
    Returns:
        float: Mean gradient score bar_g_i
    """
    total_norm = 0.0
    count = 0
    for view in views:
        if not primitive_i.contributed_to(view):
            continue
        T = view.T
        dL_dT = view.dL_dT
        z = view.z
        # Compute per-pixel contributions to screen-space positional gradient [S1, unofficial]
        # Source uses 1-based T_{m,n}; mapped to 0-based here (row 1->0, row 2->1, row 4->3)
        gx = dL_dT[0][z] * T[3][z]
        gy = dL_dT[1][z] * T[3][z]
        # Norm of gradient w.r.t. projected 2D screen-space center [S1, unofficial]
        norm = math.sqrt(gx**2 + gy**2)
        total_norm += norm
        count += 1
    return total_norm / count if count > 0 else 0.0
```

**Parameters:**
- Threshold for densification: Not given in the sources.
- Number of views $N$: Depends on the training dataset [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Gradient Cancellation:** The method avoids gradient cancellation identified in other approaches [S1, unofficial].
- **Projection Approximation:** Avoids the discrepancy introduced by projecting 3D center gradients to the image plane, which conflates depth and lateral motion [S1, unofficial].
- **Ambiguous Indexing:** The definition of $z$ and the indexing of $T_{m,n}$ is ambiguous in the source [S1, unofficial]. Implementers must clarify the row/column convention of the T-matrix and the meaning of $z$ [G].

## Subtopics

### Density-Aware Splitting
- **What it is:** A complementary step that determines whether to clone or split a primitive based on its gradient score and size.
- **Difference:** Unlike 3DGS which uses a global scale threshold, this method uses a density-aware criterion suitable for inverse rendering.
- **When to choose:** When refining primitives based on both reconstruction error and local density.
- **Link:** [Density-Aware Splitting](3183-density-aware-splitting.md)

## Operating characteristics
- **Time Complexity:** Linear in the number of views $N$ and primitives [S1, unofficial]. The gradient computation requires a backward pass through the rasterizer and T-matrix for each view [S1, unofficial].
- **Memory Complexity:** Requires storing the gradient of the loss with respect to the T-matrix for each view [S1, unofficial].
- **Strengths:** Provides a principled signal for densification that accurately reflects reconstruction error in screen space [S1, unofficial]. Avoids gradient cancellation and projection artifacts [S1, unofficial].
- **Limitations:** Requires access to the T-matrix gradients, which may not be available in all differentiable renderers [S1, unofficial]. The ambiguity in the definition of $z$ may complicate implementation [G].
- **When to use:** In differentiable volume rendering or inverse rendering settings where accurate densification is critical for high-frequency details [S1, unofficial].

## Background
The method originates from the 3DSS (3D Surface Splatting for Inverse Rendering) paper [S1, unofficial]. It addresses limitations in 3DGS [Kerbl et al. 2023] and 2DGS [Huang et al. 2024] by providing a more accurate gradient-based densification criterion [S1, unofficial]. The approach builds on the analytical backward pass of the T-matrix to compute screen-space gradients directly [S1, unofficial].
