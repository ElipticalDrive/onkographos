# GaussianList Data Structure and Initialization

Also called: GaussianList

## Overview
The `GaussianList` is the primary data structure in 3D Gaussian Splatting (3DGS) that stores the attributes of a set of 3D Gaussian primitives for batch processing during differentiable volume rendering [S1, unofficial]. It solves the problem of efficiently managing and computing the spatial properties (position, scale, rotation, opacity, and color) of $N$ Gaussians in a column-major layout, enabling fast covariance computation and screen-space projection [S1, unofficial]. It differs from hierarchical variants like Octree-GS by using a flat, unstructured list of primitives, which simplifies initialization but lacks the memory efficiency of spatially adaptive structures [S1, S3, unofficial].

## How it works

### Inputs and Outputs
*   **Input**: A vector of $N$ Gaussian objects, each containing position (3D), scale (3D), opacity (scalar), rotation (quaternion), and spherical harmonic (SH) coefficients.
*   **Output**: A `GaussianList` struct containing pre-allocated matrices and vectors for batch operations, including computed 3D covariance matrices.

### Data Structures
The `GaussianList` struct stores attributes in column-major matrices to facilitate batch processing [S1, unofficial]. The fields are:

1.  **`positions`**: `na::Matrix4xX<f32>` (4 rows $\times$ $N$ columns). Stores 4D homogeneous coordinates. The first three rows contain the $(x, y, z)$ position, and the fourth row is always $1.0$ [S1, unofficial].
2.  **`scales`**: `na::Matrix3xX<f32>` (3 rows $\times$ $N$ columns). Stores the scale factors for the $x, y, z$ axes [S1, unofficial].
3.  **`opacities`**: `na::DVector<f32>` (1D vector of size $N$). Stores the opacity scalar for each Gaussian [S1, unofficial].
4.  **`rotations`**: `na::Matrix4xX<f32>` (4 rows $\times$ $N$ columns). Stores the quaternion components $(w, x, y, z)$ for each Gaussian [S1, unofficial].
5.  **`sh`**: `Matrix48xX<f32>` (48 rows $\times$ $N$ columns). Stores spherical harmonic coefficients. The layout within a column is interleaved by RGB channel for each degree/order: $C_{0,R}, C_{0,B}, C_{0,G}, C_{1,R}, C_{1,B}, C_{1,G}, \dots$ [S1, unofficial].
6.  **`num_gaussians`**: `usize`. The total number of Gaussians $N$ [S1, unofficial].
7.  **`cov3d`**: `na::Matrix3xX<f32>` (3 rows $\times$ $N$ columns). Pre-allocated buffer of zeros to store the computed 3D covariance matrices [S1, unofficial].

### Initialization Steps
The initialization process transforms raw Gaussian objects into the `GaussianList` format and computes initial covariances [S1, unofficial]:

1.  **Set Count**: Set `num_gaussians` to the length of the input vector of Gaussian objects.
2.  **Construct Positions**: Iterate over all Gaussians. For each Gaussian $i$, clone its position components $(x_i, y_i, z_i)$ into the first three rows of column $i$ in `positions`. Set the fourth row of column $i$ to $1.0$ to form homogeneous coordinates [S1, unofficial].
3.  **Construct Scales**: Clone the scale components $(s_{x,i}, s_{y,i}, s_{z,i})$ into the rows of column $i$ in `scales` [S1, unofficial].
4.  **Construct Opacities**: Clone the opacity value $\alpha_i$ into the $i$-th element of `opacities` [S1, unofficial].
5.  **Construct Rotations**: Clone the quaternion components $(w_i, x_i, y_i, z_i)$ into the rows of column $i$ in `rotations` [S1, unofficial].
6.  **Construct SH Coefficients**: Clone the spherical harmonic coefficients into the rows of column $i$ in `sh` according to the interleaved RGB layout [S1, unofficial].
7.  **Initialize Covariance Buffer**: Initialize `cov3d` with zeros of size $3 \times N$ [S1, unofficial].
8.  **Compute 3D Covariances**: Call `compute_cov3d()` to calculate the covariance matrices for all Gaussians [S1, unofficial].

### Computing 3D Covariance Matrices
The `compute_cov3d()` function calculates the 3D covariance matrix $\Sigma$ for each Gaussian using its rotation and scale [S1, unofficial]:

1.  Iterate $i$ from $0$ to `num_gaussians` - 1.
2.  Extract the rotation quaternion $q_i$ from the $i$-th column of `rotations`.
3.  Convert $q_i$ to a unit quaternion, then to a $3 \times 3$ rotation matrix $R_i$ [S1, unofficial].
4.  Create a diagonal scale matrix $S_i = \text{diag}(s_{x,i}^2, s_{y,i}^2, s_{z,i}^2)$ using the squared scale components from `scales` [S1, unofficial].
5.  Compute the covariance matrix $\Sigma_i = R_i S_i R_i^T$ [S1, unofficial].
6.  Copy the elements of $\Sigma_i$ into the $i$-th column of `cov3d` [S1, unofficial].

### Projecting 3D Covariance to 2D Screen Space
The `project_cov3d_to_screen()` function projects the 3D covariance matrix to 2D screen space for rasterization [S1, unofficial]:

1.  Get the Gaussian position $p$ and the camera view matrix $V$ [S1, unofficial].
2.  Convert $p$ to a homogeneous vector $p_w = [x, y, z, 1.0]^T$ [S1, unofficial].
3.  Transform to camera space: $p_{cam} = V p_w$ [S1, unofficial].
4.  Get the focal lengths $f_x, f_y$ and the tangent of the horizontal and vertical FOV, $htanfov_{xy}$ [S1, unofficial].
5.  Compute the tangent of the Gaussian center: $t_{xz} = p_{cam}.x / p_{cam}.z$, $t_{yz} = p_{cam}.y / p_{cam}.z$ [S1, unofficial].
6.  Clamp the tangents to limits $L_x = 1.3 \cdot \tan(\text{FOV}_x)$ and $L_y = 1.3 \cdot \tan(\text{FOV}_y)$, then multiply back by $p_{cam}.z$ to get $t.x$ and $t.y$ [S1, unofficial].
7.  Compute the Jacobian $J$ (a $3 \times 3$ matrix) using $f_x, f_y, t.x, t.y, t.z$ [S1, unofficial].
8.  Compute $W$ as the transpose of the top-left $3 \times 3$ submatrix of the view matrix $V$ [S1, unofficial].
9.  Compute $T = W J$ [S1, unofficial].
10. Compute the projected covariance $C = T^T \Sigma_i T$ [S1, unofficial].
11. Extract the top-left $2 \times 2$ submatrix as $C_{2D}$ [S1, unofficial].
12. Apply a low-pass filter by adding $0.3$ to $C_{2D}[0,0]$ and $C_{2D}[1,1]$ to ensure the Gaussian is at least one pixel wide/high [S1, unofficial].
13. Return $C_{2D}$ [S1, unofficial].

### Evaluating Color from Spherical Harmonics
The `eval_spherical_harmonics()` function computes the color of a Gaussian given a viewing direction [S1, unofficial]:

1.  Pass the SH coefficients column for the given index, the SH dimension, and the viewing direction vector $d$ to the SH evaluation routine [S1, unofficial].
2.  Return the resulting color vector $c$ and the Gaussian's opacity $\alpha$ [S1, unofficial].

### Pseudocode

```python
import numpy as np

def initialize_gaussian_list(gaussians: list) -> dict:
    """
    Initialize a GaussianList from a list of Gaussian objects.
    
    Args:
        gaussians: List of objects with attributes:
            - position: (x, y, z)
            - scale: (sx, sy, sz)
            - opacity: float
            - rotation: (w, x, y, z) quaternion
            - sh: list of SH coefficients (interleaved RGB)
            
    Returns:
        A dictionary representing the GaussianList struct.
    """
    N = len(gaussians)
    
    # Initialize matrices with zeros
    positions = np.zeros((4, N))
    scales = np.zeros((3, N))
    opacities = np.zeros(N)
    rotations = np.zeros((4, N))
    sh = np.zeros((48, N))  # Assuming 48 coefficients (degree 2)
    cov3d = np.zeros((3, N))
    
    for i, g in enumerate(gaussians):
        # 1. Positions: 4D homogeneous coordinates
        positions[0, i] = g.position[0]
        positions[1, i] = g.position[1]
        positions[2, i] = g.position[2]
        positions[3, i] = 1.0
        
        # 2. Scales
        scales[0, i] = g.scale[0]
        scales[1, i] = g.scale[1]
        scales[2, i] = g.scale[2]
        
        # 3. Opacities
        opacities[i] = g.opacity
        
        # 4. Rotations: Quaternion components
        rotations[0, i] = g.rotation[0]  # w
        rotations[1, i] = g.rotation[1]  # x
        rotations[2, i] = g.rotation[2]  # y
        rotations[3, i] = g.rotation[3]  # z
        
        # 5. SH Coefficients: Interleaved RGB
        # Assuming sh is a flat list of coefficients in order C0_R, C0_B, C0_G, C1_R, ...
        sh[:, i] = g.sh
        
    # 6. Compute 3D Covariances
    cov3d = compute_cov3d(scales, rotations, N)
    
    return {
        "positions": positions,
        "scales": scales,
        "opacities": opacities,
        "rotations": rotations,
        "sh": sh,
        "num_gaussians": N,
        "cov3d": cov3d
    }

def compute_cov3d(scales: np.ndarray, rotations: np.ndarray, N: int) -> np.ndarray:
    """
    Compute 3D covariance matrices for all Gaussians.
    
    Args:
        scales: (3, N) matrix of scale factors.
        rotations: (4, N) matrix of quaternion components.
        N: Number of Gaussians.
        
    Returns:
        cov3d: (3, N) matrix of covariance matrices (stored column-wise).
    """
    cov3d = np.zeros((3, N))
    
    for i in range(N):
        # Extract quaternion
        q = rotations[:, i]
        # Convert quaternion to rotation matrix R (3x3)
        R = quaternion_to_rotation_matrix(q)
        
        # Create diagonal scale matrix S (3x3) with squared scales
        sx = scales[0, i]
        sy = scales[1, i]
        sz = scales[2, i]
        S = np.diag([sx**2, sy**2, sz**2])
        
        # Compute covariance: Sigma = R * S * R^T
        cov = R @ S @ R.T
        
        # Store in cov3d column i
        cov3d[:, i] = cov.flatten()
        
    return cov3d

def quaternion_to_rotation_matrix(q: np.ndarray) -> np.ndarray:
    """
    Convert a quaternion (w, x, y, z) to a 3x3 rotation matrix.
    
    Args:
        q: (4,) array of quaternion components.
        
    Returns:
        R: (3, 3) rotation matrix.
    """
    w, x, y, z = q
    # Normalize quaternion
    norm = np.sqrt(w**2 + x**2 + y**2 + z**2)
    w, x, y, z = w/norm, x/norm, y/norm, z/norm
    
    R = np.zeros((3, 3))
    R[0, 0] = 1 - 2*(y**2 + z**2)
    R[0, 1] = 2*(x*y - w*z)
    R[0, 2] = 2*(x*z + w*y)
    R[1, 0] = 2*(x*y + w*z)
    R[1, 1] = 1 - 2*(x**2 + z**2)
    R[1, 2] = 2*(y*z - w*x)
    R[2, 0] = 2*(x*z - w*y)
    R[2, 1] = 2*(y*z + w*x)
    R[2, 2] = 1 - 2*(x**2 + y**2)
    
    return R

def project_cov3d_to_screen(cov3d_col: np.ndarray, position: np.ndarray, view_matrix: np.ndarray, focal_x: float, focal_y: float, tan_fovx: float, tan_fovy: float) -> np.ndarray:
    """
    Project a 3D covariance matrix to 2D screen space.
    
    Args:
        cov3d_col: (3, 3) covariance matrix for a single Gaussian.
        position: (3,) position vector.
        view_matrix: (4, 4) view matrix.
        focal_x: Focal length in x.
        focal_y: Focal length in y.
        tan_fovx: Tangent of horizontal FOV.
        tan_fovy: Tangent of vertical FOV.
        
    Returns:
        cov2d: (2, 2) projected covariance matrix.
    """
    # Convert position to homogeneous
    p_w = np.array([position[0], position[1], position[2], 1.0])
    
    # Transform to camera space
    p_cam = view_matrix @ p_w
    
    # Compute tangents
    tz = p_cam[2]
    if tz == 0:
        tz = 1e-6  # Guard against division by zero [G]
    tx = p_cam[0] / tz
    ty = p_cam[1] / tz
    
    # Clamp tangents
    limit_x = 1.3 * tan_fovx
    limit_y = 1.3 * tan_fovy
    tx = np.clip(tx, -limit_x, limit_x)
    ty = np.clip(ty, -limit_y, limit_y)
    
    # Compute Jacobian J (3x3)
    # J = [[fx/z, 0, -fx*x/z^2],
    #      [0, fy/z, -fy*y/z^2],
    #      [0, 0, 0]]
    # Note: The source describes computing J using focal_x, focal_y, t.x, t.y, t.z.
    # Standard derivation: x_screen = fx * X/Z, y_screen = fy * Y/Z
    # d(x_screen)/dX = fx/Z, d(x_screen)/dZ = -fx*X/Z^2
    # d(y_screen)/dY = fy/Z, d(y_screen)/dZ = -fy*Y/Z^2
    J = np.zeros((3, 3))
    J[0, 0] = focal_x / tz
    J[0, 2] = -focal_x * p_cam[0] / (tz**2)
    J[1, 1] = focal_y / tz
    J[1, 2] = -focal_y * p_cam[1] / (tz**2)
    
    # Compute W: transpose of top-left 3x3 of view matrix
    W = view_matrix[:3, :3].T
    
    # Compute T = W * J
    T = W @ J
    
    # Compute cov = T^T * cov3d * T
    cov = T.T @ cov3d_col @ T
    
    # Extract top-left 2x2
    cov2d = cov[:2, :2]
    
    # Apply low-pass filter
    cov2d[0, 0] += 0.3
    cov2d[1, 1] += 0.3
    
    return cov2d
```

## Subtopics

### [LinPrim Population Control](2295-linprim-population-control.md)
LinPrim Population Control manages the density of linear primitives (octahedra and tetrahedra) during differentiable volume rendering optimization by pruning, cloning, and splitting primitives to adapt to scene complexity. It differs from standard 3D Gaussian Splatting by redefining primitive size metrics to accommodate non-spherical kernels and adjusting sampling distributions to respect the anisotropic geometry of linear primitives.

### [Gaussian Splatting Initialization and Parameterization](2313-gaussian-splatting-initialization-and-parameterization.md)
Gaussian Splatting Initialization and Parameterization establishes the initial state of a 3D Gaussian Splatting representation from input data, typically a sparse point cloud, to begin differentiable optimization. It differs from Random Large-Variance Initialization by using structured geometric priors rather than random noise, and from Gaussian Geometry Parameters Prediction by relying on explicit data mapping rather than learned prediction networks. It serves as the foundational step for Gaussian Splatting Initialization and Parameterization.

### [Octree-GS / Scaffold-GS](6142-octree-gs-scaffold-gs.md)
Octree-GS and Scaffold-GS are hierarchical level-of-detail (LoD) methods that anchor scene content to a sparse voxel grid, using the grid as a scaffold to allocate Gaussians only in occupied regions. This approach naturally adapts to view distance and improves memory efficiency compared to flat Gaussian lists. Scaffold-GS specifically uses anchor points to predict "neural" Gaussians on the fly via a small MLP, achieving approximately 5x less memory usage than vanilla 3DGS at the same quality. Octree-GS builds an explicit octree over the scene, associating each node with a merged Gaussian that summarizes the radiance and opacity of its children, enabling massive scene rendering.

### [Random Gaussian Generation](14047-random-gaussian-generation.md)
Random Gaussian Generation is the initialization routine for the `GaussianList` data structure in 3D Gaussian Splatting, creating a set of $N$ isotropic or anisotropic Gaussian primitives with random spatial parameters before scene-specific optimization begins. It differs from sibling methods like LinPrim Population Control, which manages density during training, and Octree-GS, which uses hierarchical spatial structures for initialization; instead, this method provides a uniform, unstructured starting point for radiance-field optimization.

### GaussianHair
GaussianHair is a strand-aware hair method using a strand + GS representation [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: Initialization is $O(N)$ for copying attributes and $O(N)$ for covariance computation, where $N$ is the number of Gaussians. Projection is $O(1)$ per Gaussian but involves matrix multiplications.
*   **Memory Complexity**: $O(N)$ for storing positions, scales, rotations, opacities, SH coefficients, and covariances. The SH matrix dominates memory if high degrees are used (e.g., 48 coefficients per Gaussian).
*   **Strengths**: Simple data layout enables efficient batch processing and GPU acceleration. Flat structure allows easy random access and sorting.
*   **Limitations**: Memory usage scales linearly with $N$, which can be prohibitive for large scenes. Lacks spatial coherence, leading to redundant storage in empty regions.
*   **When to Use**: Suitable for small to medium scenes where simplicity and ease of implementation are prioritized over memory efficiency.
*   **When Not to Use**: For large-scale scenes or mobile applications where memory constraints are critical; hierarchical methods like Octree-GS are preferred.

## Background
The `GaussianList` data structure is a core component of 3D Gaussian Splatting (3DGS), introduced by Kerbl et al. in 2023 [S1, S3, unofficial]. It was designed to provide an efficient way to store and manipulate 3D Gaussian primitives for differentiable rendering. The column-major layout was chosen to optimize for batch processing on GPUs [S1, unofficial]. The structure has since been extended and modified in various variants, such as Octree-GS and Scaffold-GS, to address memory and scalability issues [S1, S3, unofficial].
