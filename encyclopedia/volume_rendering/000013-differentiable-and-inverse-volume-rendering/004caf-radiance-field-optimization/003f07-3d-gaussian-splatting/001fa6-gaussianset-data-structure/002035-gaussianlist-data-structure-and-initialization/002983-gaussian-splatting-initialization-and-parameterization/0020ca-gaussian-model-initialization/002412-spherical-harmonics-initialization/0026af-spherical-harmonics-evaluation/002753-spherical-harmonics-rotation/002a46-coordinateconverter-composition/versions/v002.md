# CoordinateConverter Composition

Also called: SPZ coordinate conversion pipeline

## Overview
The CoordinateConverter Composition is a composite transformation pipeline in the SPZ format that converts Gaussian splatting parameters between coordinate systems by coupling geometric flips with analytic Spherical Harmonics (SH) rotations [S1, unofficial]. It ensures visual consistency across frame changes by baking $\pm\pi/2$ X-axis rotations into callable position, quaternion, and per-band SH transformation functions [S1, unofficial].

## How it works
### Inputs and Outputs
- **Inputs**: `from` (source coordinate system identifier), `to` (target coordinate system identifier), `shDegree` (maximum SH degree, $0 \le \text{shDegree} \le 4$) [S1, unofficial].
- **Output**: A `CoordinateConverter` struct instance containing flip arrays and callable transformation functions [S1, unofficial].

### Data Structures
The `CoordinateConverter` struct layout is as follows [S1, unofficial]:
```cpp
struct CoordinateConverter {
    std::array<float, 3> flipP; // x, y, z flips for positions
    std::array<float, 3> flipQ; // x, y, z flips for quaternions (w never flipped)
    std::array<float, 24> flipSh; // flips for 24 SH coefficients
    std::array<std::function<void(float*)>, SH_MAX_DEGREE> rotFlipShFuncs; // per-band SH transforms
    std::function<void(float*)> rotFlipPFunc; // position flip + rotation
    std::function<void(float*)> rotFlipQFunc; // quaternion flip + rotation
};
```

### Parameters
- `SH_MAX_DEGREE`: A `constexpr int` set to 4, limiting the maximum SH degree handled by `rotFlipShFuncs` [S1, unofficial].

### Numbered Steps
1. Check `needRotation` by comparing `from` and `to` [S1, unofficial]. If identical, return a default converter with identity flips and null functions [S1, unofficial].
2. Determine backward direction via bit 3 of `from` [S1, unofficial].
3. Shift `from` into the same family as `to` by adding or subtracting 8 (`innerFrom = from ± 8`) [S1, unofficial].
4. Recursively call `coordinateConverter(innerFrom, to, shDegree)` to obtain a base converter with aligned family flips [S1, unofficial].
5. Bake the inner flip into `rotFlipPFunc` and `rotFlipQFunc`, composing it with the appropriate $\pm\pi/2$ rotation based on the backward flag [S1, unofficial].
6. Iterate `b` from 0 to `shDegree - 1`, select the SH rotation table (minus for backward, plus for forward), retrieve `rotFn = shTable[b]`, and store it in `result.rotFlipShFuncs[b]` [S1, unofficial].

### Formulas and Transformations
**Position Rotation ($R_x$)**: For a position array $p = [x, y, z]$:
- Backward (rotated $\to$ standard): Apply `flipP`, then $R_x(-\pi/2)$ via `p[1]=z; p[2]=-y;` [S1, unofficial].
- Forward (standard $\to$ rotated): Apply $R_x(+\pi/2)$ via `p[1]=-z; p[2]=y;` then `flipP` [S1, unofficial].

**Quaternion Rotation**: Let $s = \sqrt{2}/2$. The array $p$ holds quaternion components at indices 0–3:
- Backward: Apply `flipQ`, then quaternion rotation: `p[0]=s*(-w+x); p[1]=s*(y+z); p[2]=s*(-y+z); p[3]=s*(w+x);` [S1, unofficial].
- Forward: Apply quaternion rotation: `p[0]=s*(w+x); p[1]=s*(y-z); p[2]=s*(y+z); p[3]=s*(w-x);` then `flipQ` [S1, unofficial].

### Pseudocode
```python
import math
from typing import List, Callable

SH_MAX_DEGREE = 4

class CoordinateConverter:
    def __init__(self, identity=False):
        if identity:
            self.flipP = [1.0, 1.0, 1.0]
            self.flipQ = [1.0, 1.0, 1.0]
            self.flipSh = [1.0] * 24
            self.rotFlipShFuncs = [lambda x: None] * SH_MAX_DEGREE
            self.rotFlipPFunc = lambda x: None
            self.rotFlipQFunc = lambda x: None
        else:
            self.flipP = [0.0, 0.0, 0.0]
            self.flipQ = [0.0, 0.0, 0.0]
            self.flipSh = [0.0] * 24
            self.rotFlipShFuncs = [lambda x: None] * SH_MAX_DEGREE
            self.rotFlipPFunc = None
            self.rotFlipQFunc = None

def coordinate_converter(from_sys: int, to_sys: int, sh_degree: int) -> CoordinateConverter:
    # Step 1: Check rotation need
    if from_sys == to_sys:
        return CoordinateConverter(identity=True)

    # Step 2: Determine direction via bit 3
    is_backward = bool(from_sys & 8)

    # Step 3: Inner family shift
    inner_from = from_sys + 8 if is_backward else from_sys - 8

    # Step 4: Recursive call for base flips
    base = coordinate_converter(inner_from, to_sys, sh_degree)

    result = CoordinateConverter()
    result.flipP = list(base.flipP)
    result.flipQ = list(base.flipQ)
    result.flipSh = list(base.flipSh)

    s = math.sqrt(2) / 2

    # Step 5: Compose rotations into callable functions
    if is_backward:
        # Backward: flipP then R_x(-pi/2)
        def rot_flip_p(p: List[float]) -> None:
            p[0] *= result.flipP[0]
            p[1] *= result.flipP[1]
            p[2] *= result.flipP[2]
            y, z = p[1], p[2]
            p[1] = z
            p[2] = -y

        # Backward: flipQ then quaternion rotation
        def rot_flip_q(q: List[float]) -> None:
            q[0] *= result.flipQ[0]
            q[1] *= result.flipQ[1]
            q[2] *= result.flipQ[2]
            # w is never flipped
            w, x, y, z = q[3], q[0], q[1], q[2]
            q[0] = s * (-w + x)
            q[1] = s * (y + z)
            q[2] = s * (-y + z)
            q[3] = s * (w + x)
    else:
        # Forward: R_x(+pi/2) then flipP
        def rot_flip_p(p: List[float]) -> None:
            y, z = p[1], p[2]
            p[1] = -z
            p[2] = y
            p[0] *= result.flipP[0]
            p[1] *= result.flipP[1]
            p[2] *= result.flipP[2]

        # Forward: quaternion rotation then flipQ
        def rot_flip_q(q: List[float]) -> None:
            w, x, y, z = q[3], q[0], q[1], q[2]
            q[0] = s * (w + x)
            q[1] = s * (y - z)
            q[2] = s * (y + z)
            q[3] = s * (w - x)
            q[0] *= result.flipQ[0]
            q[1] *= result.flipQ[1]
            q[2] *= result.flipQ[2]

    result.rotFlipPFunc = rot_flip_p
    result.rotFlipQFunc = rot_flip_q

    # Step 6: SH Rotation Assignment
    # The source does not provide the contents of sh_minus_table or sh_plus_table [G]
    sh_minus_table = [lambda x: None] * SH_MAX_DEGREE
    sh_plus_table = [lambda x: None] * SH_MAX_DEGREE

    table = sh_minus_table if is_backward else sh_plus_table
    for b in range(sh_degree):
        if b < SH_MAX_DEGREE:
            result.rotFlipShFuncs[b] = table[b]
        else:
            result.rotFlipShFuncs[b] = lambda x: None

    return result
```

### Edge Cases and Pitfalls
- **Precision**: The use of $\sqrt{2}/2$ introduces floating-point approximation [S1, unofficial].
- **Quaternion W Component**: The source explicitly states `w` is never flipped by `flipQ` [S1, unofficial].
- **SH Degree Limit**: `SH_MAX_DEGREE` is 4, so bands $b \ge 4$ are not handled by `rotFlipShFuncs` [S1, unofficial].
- **Bit 3 Ambiguity**: The determination of "backward" relies on bit 3 of `from` [S1, unofficial].

## Subtopics

### CoordinateConverter Composition
- **What it is**: The composite transformation pipeline described above.
- **What sets it apart**: It combines geometric flips with analytic SH rotations in a single callable structure, optimized for the SPZ format's specific coordinate system requirements.
- **When to choose it**: Use when loading or saving SPZ files that require coordinate system conversion, or when integrating Gaussian splatting data from different sources with varying coordinate frames.

## Background
The CoordinateConverter Composition is part of the SPZ (Splatting Point Cloud) format developed by Niantic [S1, unofficial]. It is used to handle the conversion of Gaussian splatting parameters between different coordinate systems, ensuring that the visual appearance remains consistent across different viewing contexts [S1, unofficial]. The method is documented in the Niantic Labs SPZ repository [S1, unofficial].
