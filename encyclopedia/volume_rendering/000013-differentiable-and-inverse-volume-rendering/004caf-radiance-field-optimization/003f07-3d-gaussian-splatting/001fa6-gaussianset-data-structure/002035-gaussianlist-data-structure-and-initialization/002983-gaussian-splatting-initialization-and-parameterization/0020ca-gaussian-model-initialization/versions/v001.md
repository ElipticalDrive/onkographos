# Gaussian Model Initialization


## Overview
Gaussian Model Initialization establishes the initial state of a 3D Gaussian Splatting scene by populating learnable parameters (position, features, scaling, rotation, and opacity) from input data, typically a Structure-from-Motion (SfM) point cloud. It solves the problem of converting discrete, static geometric samples into a continuous, differentiable radiance field representation ready for optimization. It sets itself apart from sibling methods like [Spherical Harmonics Initialization](3163-spherical-harmonics-initialization.md) by handling the full geometric and attribute seeding rather than just color parameterization, and from [Angle-pose Cuboid Uniform Initialization (ACUI)](4503-angle-pose-cuboid-uniform-initialization-acui.md) by relying on sparse reconstruction data rather than uniform volumetric sampling.

## How it works
The standard initialization process, often implemented via `create_from_pcd`, converts a point cloud (xyz, rgb) into a `GaussianModel` instance.

**Inputs and Outputs:**
- Input: A point cloud with $N$ points, where each point has a 3D position $\mathbf{p} \in \mathbb{R}^3$ and an RGB color $\mathbf{c} \in \mathbb{R}^3$.
- Output: A `GaussianModel` object containing tensors for $\mathbf{xyz}$, $\mathbf{features\_dc}$, $\mathbf{scaling}$, $\mathbf{rotation}$, and $\mathbf{opacity}$.

**Data Structures:**
The model stores parameters in PyTorch tensors on the target device (CPU or CUDA).
- `_xyz`: Shape $(N, 3)$, float32.
- `_features_dc`: Shape $(N, 1, 3)$, float32. Stores the zeroth-order spherical harmonic coefficients (DC color).
- `_scaling`: Shape $(N, 3)$, float32. Stores the log-scale of the Gaussian axes.
- `_rotation`: Shape $(N, 4)$, float32. Stores quaternions $(w, x, y, z)$.
- `_opacity`: Shape $(N, 1)$, float32. Stores initial opacity values.

**Numbered Steps:**
1. **Model Instantiation:** Create the `GaussianModel` object and move it to the target device (CPU or GPU) [S1, unofficial].
2. **Point Cloud Population:** Call `create_from_pcd(xyz, rgb)` to populate the model parameters [S1, unofficial].
   - **Position:** Initialize `_xyz` directly from the input point cloud coordinates [S1, unofficial].
   - **Color:** Initialize `_features_dc` with the input RGB colors. The higher-order spherical harmonic coefficients are set to zero [S1, 3163-spherical-harmonics-initialization.md, unofficial].
   - **Opacity:** Initialize `_opacity` to a default value (typically uniform, e.g., 0.1 or derived from density) [G].
   - **Scaling:** Initialize `_scaling` based on the nearest neighbor distance of the point cloud to ensure appropriate initial Gaussian size [S1, unofficial][S2]. Specifically, for each point, compute the distance to its nearest neighbor and use this as the scale factor [S2].
   - **Rotation:** Initialize `_rotation` to identity quaternions $(1, 0, 0, 0)$, implying no initial rotation [S1, unofficial][S2].
3. **Covariance Verification:** Ensure the computed covariance matrix $\Sigma$ is symmetric. The covariance is derived from scaling and rotation as $\Sigma = R S S^T R^T$. A test check verifies `torch.allclose(cov0, cov0.T, atol=1e-6)` [S1, unofficial].

**Parameters:**
- Learning rate for `_xyz`: $1.6 \times 10^{-4}$ [S1, unofficial].
- Learning rate for `_features_dc`: $2.5 \times 10^{-3}$ [S1, unofficial].
- Sampling step: If the point cloud is dense, a sampling step may be applied to reduce $N$ before initialization [S1, unofficial].

**Pseudocode:**
```python
import torch
import numpy as np

def initialize_gaussian_model(xyz: np.ndarray, rgb: np.ndarray, device: str = 'cuda'):
    """
    Initialize a GaussianModel from a point cloud.
    
    Args:
        xyz: numpy array of shape (N, 3) with float32 coordinates.
        rgb: numpy array of shape (N, 3) with float32 RGB values in [0, 1].
        device: 'cpu' or 'cuda'.
        
    Returns:
        model: A GaussianModel instance with initialized parameters.
    """
    # 1. Instantiate model and move to device
    model = GaussianModel()
    model.to(device)
    
    N = xyz.shape[0]
    
    # 2. Populate Position
    # Directly copy xyz to _xyz tensor
    model._xyz = torch.tensor(xyz, dtype=torch.float32, device=device)
    
    # 3. Populate Color (DC Spherical Harmonics)
    # Shape (N, 1, 3) for SH0
    model._features_dc = torch.tensor(rgb, dtype=torch.float32, device=device).unsqueeze(1)
    
    # 4. Populate Opacity
    # Initialize to a small constant value [G]
    model._opacity = torch.ones((N, 1), dtype=torch.float32, device=device) * 0.1
    
    # 5. Populate Scaling
    # Compute nearest neighbor distances to set initial scales [S2]
    # Using a simple brute-force or KD-tree approach for nearest neighbor
    # For implementation simplicity, we assume a helper function nn_distances exists
    # or compute it via broadcasting if N is small.
    # Here we use a placeholder logic for nearest neighbor distance calculation.
    # In practice, use scipy.spatial.cKDTree or similar.
    dists = np.linalg.norm(xyz[:, np.newaxis, :] - xyz[np.newaxis, :, :], axis=2)
    # Exclude self (distance 0)
    np.fill_diagonal(dists, np.inf)
    nn_distances = np.min(dists, axis=1)
    
    # Convert distances to log-scale for _scaling
    # Add a small epsilon to avoid log(0)
    epsilon = 1e-6
    log_scales = np.log(nn_distances + epsilon)
    # Repeat for 3 dimensions (isotropic scaling initially)
    scaling_init = np.tile(log_scales, (3, 1)).T
    
    model._scaling = torch.tensor(scaling_init, dtype=torch.float32, device=device)
    
    # 6. Populate Rotation
    # Initialize to identity quaternion (1, 0, 0, 0)
    model._rotation = torch.zeros((N, 4), dtype=torch.float32, device=device)
    model._rotation[:, 0] = 1.0
    
    # 7. Verify Covariance Symmetry
    # Compute covariance from scaling and rotation
    # R is constructed from quaternions, S is diagonal from exp(scaling)
    # Sigma = R @ S @ S.T @ R.T
    # Check if Sigma is symmetric
    covariances = model.get_covariance() # Assumes model has this method
    if N > 0:
        cov0 = covariances[0]
        if not torch.allclose(cov0, cov0.T, atol=1e-6):
            raise ValueError("Covariance matrix is not symmetric after initialization.")
            
    return model
```

## Subtopics

### [Spherical Harmonics Initialization](3163-spherical-harmonics-initialization.md)
Sets the initial view-dependent color representation by populating only the zeroth-order (DC) spherical harmonic coefficients with the input RGB colors, while leaving higher-order coefficients at zero. It solves the problem of providing a valid, differentiable starting point for view-dependent color optimization without introducing high-frequency artifacts. It sets itself apart from [Angle-pose Cuboid Uniform Initialization (ACUI)](4503-angle-pose-cuboid-uniform-initialization-acui.md) by focusing exclusively on color parameterization rather than geometric pose and scale distribution.

### [Angle-pose Cuboid Uniform Initialization (ACUI)](4503-angle-pose-cuboid-uniform-initialization-acui.md)
An initialization strategy for X-ray Gaussian Splatting that computes camera parameters from scanner specifications and uniformly samples Gaussian centers within a bounding cuboid, replacing Structure-from-Motion (SfM).

#### R2-Gaussian Initialization
Uses the Feldkamp-Davis-Kress (FDK) algorithm to reconstruct a low-quality volume in less than 1 second [S2]. Excludes empty spaces using a density threshold $\tau$ and randomly samples $M$ points as kernel positions [S2]. Sets the scales of Gaussians as the nearest neighbor distances and assumes no rotation [S2]. Queries central densities from the FDK volume and scales them down with $k$ to compensate for overlay between kernels [S2].
- **Parameters:** $M = 50,000$ (number of initial Gaussians), $\tau = 0.05$ (density threshold), $k = 0.15$ (scaling term) [S2].

#### GS-W Sampling Coordinate Initialization
Initializes $K$ learnable sampling coordinates per Gaussian point to enable adaptive feature sampling on $K$ feature maps [S3].
- **Steps:**
  1. Assign each Gaussian point $i$ $K$ sampling coordinates $(sc_1^i, sc_2^i, \dots, sc_K^i) \in \mathbb{R}^{K \times 2}$ [S3].
  2. Randomly generate $K$ matrices $(M^1, M^2, \dots, M^K) \in \mathbb{R}^{K \times 2 \times 3}$ [S3].
  3. Constrain each matrix such that the sum of its rows equals 1 [S3].
  4. Multiply each matrix $M^k$ with the Gaussian point's 3D position $X_i \in \mathbb{R}^3$ to compute the initial sampling coordinates [S3].
- **Formula:** $(sc_1^1, sc_2^2, \dots, sc_K^K)_{init} = (M^1 X_i, M^2 X_i, \dots, M^K X_i)$ [S3].
- **Parameter:** $K = 3$ (number of feature maps) [S3].

#### Persistent Material Descriptors
Attaches samples $(m_{ik}, b_{ik})$ with weights based on initial Gaussian support at sampled voxels, keeping identifiers and weights fixed during optimization [S4, unofficial].
- **Steps:**
  1. Compute weight: $w_{ik} \propto \exp\left(-\frac{1}{2}(\mathbf{x}_{ik} - \boldsymbol{\mu}_i)^\top \Sigma_i^{-1}(\mathbf{x}_{ik} - \boldsymbol{\mu}_i)\right)$, normalized such that $\sum_k w_{ik} = 1$ [S4, unofficial].
  2. Keep identifiers and weights fixed as geometry is optimized [S4, unofficial].
  3. Clone and split children inherit descriptors and factor rows from the nearest pre-existing primitive [S4, unofficial].
  4. Pruning applies one mask to all attributes [S4, unofficial].
- **Pitfall:** Equation 12 makes the descriptor scale-aware: sub-voxel primitives concentrate on their own material, while larger primitives integrate over their footprint [S4, unofficial]. TF changes use persistent material support rather than reassigning regions from optimized centers [S4, unofficial].

## Operating characteristics
- **Time Complexity:** Initialization is $O(N)$ for copying positions and colors, but $O(N^2)$ or $O(N \log N)$ if nearest neighbor distances are computed for scaling [S2]. FDK reconstruction for R2-Gaussian is $O(V)$ where $V$ is volume size, but typically fast (<1s) [S2].
- **Memory Complexity:** $O(N \cdot D)$ where $D$ is the dimensionality of parameters (position, color, scale, rotation, opacity) [S1, unofficial].
- **Strengths:** Provides a geometrically grounded starting point for optimization. Simple and fast for standard SfM data [S1, unofficial].
- **Limitations:** Relies on the quality of the input point cloud. Poor reconstruction leads to poor initialization. Does not handle volumetric data natively without variants like R2-Gaussian [S2].
- **When to use:** Standard 3DGS training on image collections with SfM data [S1, unofficial].
- **When not to use:** Volumetric tomography without modification (use R2-Gaussian) [S2], or unconstrained image collections requiring adaptive feature sampling (use GS-W) [S3].

## Background
Originated with the introduction of 3D Gaussian Splatting [S1, unofficial]. The `create_from_pcd` method is a standard utility in implementations like `mini-splat` to bridge the gap between sparse SfM point clouds and the dense Gaussian representation [S1, unofficial]. Variants like R2-Gaussian extend this to X-ray tomography [S2], while GS-W and FactorSplat introduce specialized initializations for feature maps and material descriptors, respectively [S3][S4, unofficial].
