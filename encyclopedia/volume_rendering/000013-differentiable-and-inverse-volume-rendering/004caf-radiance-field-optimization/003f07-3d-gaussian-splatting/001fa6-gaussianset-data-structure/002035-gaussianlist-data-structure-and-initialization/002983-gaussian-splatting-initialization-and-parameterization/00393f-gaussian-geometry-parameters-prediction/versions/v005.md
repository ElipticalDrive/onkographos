# Gaussian Geometry Parameters Prediction

Also called: EVolSplat, Efficient Volume-based Gaussian Splatting, GRM, Gaussian MLP Heads, Gaussian Representation Model

## Overview
Gaussian Geometry Parameters Prediction is a method for initializing and refining the geometric attributes (position, opacity, covariance) of 3D Gaussian primitives in a feed-forward manner, typically using a global volumetric representation rather than per-pixel local volumes [S2]. It solves the problem of redundant, inconsistent, and ghosting artifacts that arise when accumulating per-pixel aligned Gaussians from multiple views [S2]. Unlike standard initialization which uses static point cloud data, this method predicts geometry parameters by querying a learned 3D feature volume, allowing for global consistency and refinement of noisy depth estimates [S2].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ sparse input images $\{I_n\}_{n=1}^N$, their calibrated intrinsic matrices $\{K_n\}$, extrinsic matrices $\{T_n = R_n | t_n\}$, and optionally monocular depth maps $\{D_n\}$ estimated by an off-the-shelf estimator [S2].
*   **Outputs:** A set of 3D Gaussians $\mathcal{G} = \{(\mu_i, \alpha_i, \Sigma_i, c_i)\}_{i=1}^{N_p}$, where $\mu_i$ is the center, $\alpha_i$ is the opacity, $\Sigma_i$ is the covariance matrix, and $c_i$ is the view-dependent color [S2].

**Data Structures:**
*   **Global Point Cloud ($P$):** A set of 3D points in world coordinates, $P \in \mathbb{R}^{N_p \times 3}$, constructed by unprojecting RGB images using depth maps and camera poses [S2].
*   **Feature Volume ($F$):** A sparse 3D tensor $F \in \mathbb{R}^{H \times W \times D \times C}$ extracted by a sparse 3D CNN (e.g., sparse U-Net) from the point cloud $P$ [S2].
*   **MLP Heads:** Three independent Multi-Layer Perceptrons: $\mathcal{D}_{pos}$ for position offset, $\mathcal{D}_{opa}$ for opacity, and $\mathcal{D}_{cov}$ for covariance [S2].

**Parameters:**
*   $N$: Number of input images [S2].
*   $K$: Number of nearest reference views used for retrieving 2D context for color prediction [S2].
*   $v_{\text{size}}$: Voxel size used to scale the position offset output [S2].
*   $r$: Scaling factor for Gaussian center offset (e.g., $3 \times$ voxel size) [S9].

**Steps:**
1.  **Depth Estimation & Filtering:** Predict metric depth maps $\{D_n\}$ for each input image $I_n$. Apply a depth consistency check and 3D filters to remove floating artifacts [S2].
2.  **Global Point Cloud Construction:** Unproject the RGB images into 3D space using the calibrated matrices and depth maps to construct the global point cloud $P$:
    $$ P = \bigcup_{n=1}^N \pi^{-1}(I_n, D_n, T_n, K_n) $$
    where $\pi^{-1}$ denotes pixel unprojection [S2].
3.  **Deduplication:** Apply a uniform filter to $P$ to delete duplicate primitives while keeping the scene structure, followed by a statistical filter to remove floaters [S2].
4.  **Feature Volume Extraction:** Feed the filtered point cloud $P$ into a sparse 3D CNN to extract the neural feature volume $F$ [S2].
5.  **Geometry Prediction (Iterative Refinement):**
    *   Initialize Gaussian centers $\mu^{init}_i$ using the points in $P$ (i.e., $\mu^{init}_i = p_i \in P$) [S2].
    *   For each Gaussian $i$, maintain a previous position offset $\Delta \mu^{prev}_i$ (initialized to 0 at the start of training or inference) [S2].
    *   Query the feature volume $F$ at the current estimated position $\mu^{init}_i + \Delta \mu^{prev}_i$ using trilinear interpolation to obtain a feature vector $f_i$:
        $$ f_i = F(\mu^{init}_i + \Delta \mu^{prev}_i) $$
    *   Decode opacity $\alpha_i$ and covariance $\Sigma_i$ using the MLP heads:
        $$ \alpha_i = \mathcal{D}_{opa}(f_i), \quad \Sigma_i = \mathcal{D}_{cov}(f_i) $$
    *   Decode the position offset $\Delta \mu_i$:
        $$ \Delta \mu_i = \text{Tanh}(\mathcal{D}_{pos}(f_i)) \cdot v_{\text{size}} $$
    *   Update the Gaussian center:
        $$ \mu_i = \mu^{init}_i + \Delta \mu_i $$
    *   Track $\Delta \mu_i$ as $\Delta \mu^{prev}_i$ for the next iteration [S2].
6.  **Inference Convergence:** During inference, initialize $\Delta \mu^{prev}_i = 0$. Recursively execute the query and update steps (typically twice) to obtain a converged $\Delta \mu_i$, then use the converged point to query $\alpha_i$ and $\Sigma_i$ [S2].
7.  **Color Prediction:** Project the 3D Gaussians to the nearest $K$ reference views to retrieve 2D context (color windows $\{c_k\}$ and visibility maps). Decode the Gaussian color $c_i$ using this 2D context [S2].
8.  **Background Modeling:** Model distant views and the sky with a generalizable hemisphere Gaussian model where geometry is fixed and color is predicted similarly to the foreground [S2].
9.  **Rendering:** Compose foreground and background Gaussians to reconstruct the image using alpha blending:
    $$ c = \sum_{i \in G} c_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    where $G$ is the set of 3D Gaussians [S2].

**Edge Cases and Pitfalls:**
*   **Ghosting Artifacts:** Pixel-aligned methods generate redundant and inconsistent primitives in overlapping regions. Using a global volume and filtering duplicates addresses this [S2].
*   **Noisy Depth:** Monocular depth predictions contain noise and floating artifacts. Statistical filtering is required to remove floaters before feeding into the CNN [S2].
*   **Recursive Dependency:** The position offset $\Delta \mu_i$ depends on the feature queried at the *updated* position. This creates a recursive formulation that stabilizes at a stationary point after sufficient training iterations or inference steps [S2].

## Subtopics

### [Textured-GS](9436-textured-gs.md)
Textured-GS enhances the textural representation of individual 3D Gaussians by modeling spatially defined color and opacity variations across the Gaussian ellipsoidal surface using Spherical Harmonics (SH), without increasing the number of Gaussians or adding extra parameters beyond the existing SH framework. Unlike standard 3D Gaussian Splatting (3DGS) where each Gaussian retains a fixed opacity and shows a single color when viewed from a specific direction, Textured-GS enables color variation across the Gaussian ellipsoidal surface and opacity variations, allowing for deviations from the standard ellipsoidal shape such as 'unidirectional Gaussians' that are opaque on one side and transparent on the other. It differs from Gaussian Geometry Parameters Prediction by using the surface intersection vector for SH evaluation instead of the viewing vector, allowing spatial variation of color/opacity within a single Gaussian.

### [Oriented Gaussian Splatting](9621-oriented-gaussian-splatting.md)
Oriented Gaussian Splatting is a variant of 3D Gaussian Splatting where each primitive is assigned a learnable oriented normal vector $n_i$ to create a reciprocal attenuation model, enabling the derivation of explicit geometric fields (normal and occupancy) via the Objects as Volumes framework. It differs from standard Gaussian Splatting by restoring reciprocity ($\sigma(x, w) = \sigma(x, -w)$), which is broken by standard attenuation, thereby allowing the extraction of watertight meshes and consistent normals.

### [3D Skew-Normal Splatting](10045-3d-skew-normal-splatting.md)
3D Skew-Normal Splatting (SNS) replaces the standard symmetric 3D Gaussian kernel with the Azzalini Skew-Normal distribution to model asymmetric structures, such as sharp boundaries and one-sided surfaces, while preserving analytical tractability under affine transformations. It sets apart from standard Gaussian Splatting and its symmetric variants (e.g., Textured-GS, Oriented Gaussian Splatting) by introducing a learnable skewness parameter that allows continuous interpolation between symmetric Gaussians and half-ellipsoids, enabling a single primitive to represent complex geometries that would otherwise require multiple overlapping kernels.

### [Deformable 3D Gaussian Splatting](10060-deformable-3d-gaussian-splatting.md)
Deformable 3D Gaussian Splatting is a method for dynamic scene reconstruction that learns 3D Gaussians in a canonical (static) space and models spatial-temporal deformation using an implicit deformation field implemented as a Multi-Layer Perceptron (MLP). It differs from static 3D Gaussian Splatting by introducing time-dependent offsets to Gaussian attributes, and from other dynamic variants like Mesh-Embedded Gaussian Splatting by relying on an implicit MLP rather than explicit mesh constraints or voxel grids.

### [Fourier Splatting Primitive](11094-fourier-splatting-primitive.md)
The Fourier Splatting primitive is a planar surfel for radiance field rendering that replaces the fixed Gaussian or elliptical falloff with a boundary defined by a Fourier series, allowing the representation of arbitrary closed shapes. Unlike 3D Gaussian Splatting (3DGS) or 2D Gaussian Splatting (2DGS), which are limited to fixed elliptical/disc shapes, this primitive enables higher fidelity representation of complex geometry and fine-grained details. Its key differentiator is inherent scalability: the level of detail (LoD) is controlled by truncating Fourier coefficients at runtime, allowing a single trained model to be rendered at varying complexities without retraining or post-hoc compression.

### [Conditional Slicing Mechanism](11455-conditional-slicing-mechanism.md)
The Conditional Slicing Mechanism conditions a 7-dimensional Gaussian (defined over spatial, temporal, and angular dimensions) on observed time $t$ and view direction $d$ to yield a conditional 3D Gaussian governing the spatial component. This operation "slices" the full 7D distribution to integrate temporal dynamics and view-dependent effects into the traditional 3D rendering pipeline without introducing additional temporal dependencies in the spherical harmonics. It sets itself apart from static Gaussian Splatting variants by explicitly modeling the joint distribution of space, time, and view, allowing the spatial mean and covariance to shift based on the current rendering context.

### [Structure-Aware 3D Gaussian Splatting (SAGS)](11908-structure-aware-3d-gaussian-splatting-sags.md)
Structure-Aware 3D Gaussian Splatting (SAGS) is a novel-view synthesis method that implicitly encodes scene geometry using a local-global graph representation to facilitate learning complex scenes and enforce meaningful point displacements that preserve structure, thereby reducing floating-point artifacts and storage requirements. Unlike standard 3D Gaussian Splatting which optimizes each Gaussian independently, SAGS leverages inter- and intra-connectivity between 3D point positions via Graph Neural Networks (GNNs) to predict Gaussian attributes, outperforming 3D-GS and Scaffold-GS in capturing high-frequency details while significantly reducing memory footprint.

### [Mesh-embedded representation](12559-mesh-embedded-representation.md)
This family of methods integrates 3D Gaussian Splatting with explicit triangle mesh topology to provide structured, geometry-aware representations. Unlike standard Gaussian Splatting where primitives are independent entities, these methods bind Gaussian parameters to mesh faces or skeletal meshes, enabling direct compatibility with mesh editing, skeletal animation, and blend shapes. They solve the problem of unstructured Gaussian distributions in dynamic or editable scenes by decoupling motion and appearance through mesh-driven initialization and parameterization.

### [Inverse Gaussian Splattling](13193-inverse-gaussian-splattling.md)
Inverse Gaussian Splattling is a method for initializing 3D Gaussian primitives by back-projecting optimized 2D Gaussian kernels from image space into world space. It solves the problem of generating high-quality initial geometric parameters (position, rotation, scale) for new 3D Gaussians from 2D renderings, specifically handling foreground-background ambiguity in boundary regions. It differs from standard initialization by using Weighted Principal Component Analysis (WPCA) on clustered 3D points derived from depth maps, followed by a scaling calibration step to align the projected 3D covariance with the original 2D target.

### GSGEN
GSGEN introduces a 3D SDS loss based on Point-E to mitigate the multi-face or Janus problem in text-to-3D generation [S1]. It adopts Point-E to initialize the point cloud as the initial geometry for optimization and refines the appearance with only the 2D image prior [S1].

### BrightDreamer
BrightDreamer predicts the deviation of a set of fixed anchor points to determine the centers of Gaussians [S1]. The centers of Gaussians are determined from these predicted deviations [S1].

### NeRF-Guided 3D Gaussian Splatting
NeRF-Guided 3D Gaussian Splatting uses a pretrained NeRF as a teacher to guide feature distillation, improving alignment between geometry and semantics [S3, unofficial].

### Gaussian Splatting Attribute Prediction
Gaussian Splatting Attribute Prediction is a voxel transformer that predicts residuals added to initial Gaussian rendering attributes on voxels, rather than generating new attributes directly [S4]. The predicted residual $\Delta \mathbf{G}_j$ is computed as $\Delta \mathbf{G}_j = \text{MLP}_{fine}([\mathbf{O}_j, \mathbf{E}_j])$, where $\mathbf{O}_j$ is the offset and $\mathbf{E}_j$ is the voxel attribute [S4]. The final parameter is $\mathbf{G}'_j = \mathbf{G}_j + \Delta \mathbf{G}_j$ [S4].

### 6D Gaussian Splatting
6D Gaussian Splatting is an extension of 3DGS that models view-dependent effects by adding directional dimensions, representing scene elements as 6D Gaussians (space+direction) [S5]. It parameterizes the full 6D covariance via Cholesky decomposition $\Sigma = LL^\top$ with $L$ lower-triangular and positive diagonal entries to guarantee positive definiteness [S5].

### Anisotropic Covariance
Anisotropic Covariance allows 3D Gaussians to scale anisotropically along the x, y, and z axes and rotate in 3D space, rather than remaining spherical, to better fit scene geometry [S6, unofficial]. Each Gaussian optimizes 3 scale parameters (x, y, z expansion) and 4 rotation parameters (quaternion) [S6, unofficial]. On Average-30K, Full achieves PSNR 26.05, while the Isotropic variant achieves 25.23 [S6, unofficial]. Isotropic forces Gaussians to remain spherical, causing blurry, rounded artifacts (e.g., tree trunks/leaves appear as round dots), whereas Anisotropic allows elongated/rotated shapes matching scene geometry [S6, unofficial].

### Defocus Blur Modeling
Defocus Blur Modeling models optical defocus by adjusting the scale $s$ of 3D Gaussians based on their distance from the camera's focal plane [S7]. During training, larger scale values $\bar{s}_j$ are used to rasterize blurred images, while smaller scale values $s_j$ are used during testing to render sharp details [S7]. Unlike a naive Gaussian kernel that blurs the entire image uniformly, this method selectively enlarges covariances only for Gaussians corresponding to blurred regions [S7].

### AnySplat Pipeline
The AnySplat Pipeline takes uncalibrated images as input to a transformer-based geometry encoder [S8, unofficial]. Three decoder heads ($F_G, F_D, F_C$) predict Gaussian parameters ($\mu, \sigma, r, s, c$), depth map $D$, and camera poses $p$ [S8, unofficial]. Outputs construct pixel-wise 3D Gaussians, which are voxelized into pre-voxel 3D Gaussians using a Differentiable Voxelization module [S8, unofficial]. Multi-view images and depth maps are rendered from voxelized Gaussians and supervised by RGB loss against ground truth and pseudo-geometry priors from pretrained VGGT [S8, unofficial]. Input image tensor shape is $[1, K, 3, 448, 448]$ [S8, unofficial].

### 3D Gaussians Prediction from Voxels
3D Gaussians Prediction from Voxels predicts a set of learnable Gaussian parameters for each voxel $v$, including center offset, opacity, covariance, and spherical harmonic color [S9]. The final 3D Gaussian center $\mu_j$ is computed as $\mu_j = r \cdot (\sigma(\bar{\mu}_j) - 0.5) + \text{Center}_j$, where $\sigma$ is sigmoid, $\bar{\mu}_j$ is the predicted offset, $\text{Center}_j$ is the voxel centroid, and $r$ is a scaling factor (set to 3 times the voxel size) [S9]. The output dimension per Gaussian is 38, comprising offset (3), opacity (1), covariance (6), and spherical harmonic color (28) [S9]. The sigmoid activation restricts the learnable offset to a localized neighborhood; the -0.5 shift facilitates symmetrical, bi-directional movement from the voxel center [S9].

## Operating characteristics
*   **Time Complexity:** Feed-forward inference is significantly faster than per-scene optimization methods. The use of a sparse 3D CNN and iterative refinement (typically 2 steps at inference) keeps computational cost low [S2].
*   **Memory Complexity:** Predicting a global scene representation reduces redundancy compared to per-pixel methods, lowering memory footprint for large scenes like urban environments [S2].
*   **Performance:** EVolSplat achieves real-time rendering speeds suitable for urban view synthesis [S2]. It improves global consistency and reduces ghosting artifacts compared to pixel-aligned methods like MVSplat, Flash3D, and DrivingForward [S2].
*   **Strengths:** Handles foreground and background separately; robust to noisy monocular depth via filtering; global consistency; real-time rendering [S2].
*   **Limitations:** Relies on the quality of off-the-shelf depth estimators; may lose high-frequency appearance details if initial primitives are downsampled too aggressively (addressed by 2D context retrieval) [S2].
*   **When to use:** Urban scene reconstruction, autonomous driving applications, and scenarios requiring fast, feed-forward novel view synthesis from sparse views [S2].
*   **When not to use:** Small-scale scenes with high overlap where per-scene optimization is feasible and higher fidelity is required without speed constraints; scenes with extreme lighting variations not captured by 2D context retrieval [S2].

## Background
Gaussian Geometry Parameters Prediction, specifically in the form of EVolSplat, was introduced by Sheng Miao, Jiaxin Huang, Dongfeng Bai, Xu Yan, Hongyu Zhou, Yue Wang, Bingbing Liu, Andreas Geiger, and Yiyi Liao from Zhejiang University, Huawei Noah’s Ark Lab, and the University of Tübingen [S2]. The paper "EVolSplat: Efficient Volume-based Gaussian Splatting for Urban View Synthesis" was published in CVPR 2025 [S2]. It addresses the limitations of existing feed-forward 3DGS methods that suffer from multi-view inconsistencies and duplicated content by predicting 3D Gaussians across multiple frames within a unified volume using a 3D convolutional network [S2].
