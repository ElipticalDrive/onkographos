# Gaussian Geometry Parameters Prediction

Also called: EVolSplat, Efficient Volume-based Gaussian Splatting, GRM, Gaussian MLP Heads, Gaussian Representation Model

## Overview
Gaussian Geometry Parameters Prediction is a feed-forward method that predicts the geometric attributes (position, opacity, covariance) of 3D Gaussians from a learned volumetric feature representation, rather than optimizing them per-scene or predicting them pixel-by-pixel [S2]. It solves the problem of ghosting artifacts and multi-view inconsistencies inherent in per-pixel aligned Gaussian prediction methods by accumulating depth information into a global 3D volume [S2]. Unlike [Gaussian Splatting Initialization and Parameterization](2313-gaussian-splatting-initialization-and-parameterization.md) which relies on static initialization from point clouds, this method refines geometry through a recursive network prediction loop [S2].

## How it works
**Inputs:** A set of $N$ sparse input images $\{I_n\}_{n=1}^N$ with known camera poses (intrinsic matrices $K_n$, extrinsic matrices $T_n = [R_n | t_n]$) and optional monocular depth estimates $\{D_n\}_{n=1}^N$ [S2].

**Outputs:** A set of 3D Gaussians $\mathcal{G} = \{(\mu_i, \alpha_i, \Sigma_i, c_i)\}_{i=1}^{N_p}$, where $\mu_i$ is the center, $\alpha_i$ is the opacity, $\Sigma_i$ is the covariance matrix, and $c_i$ is the view-dependent color [S2].

**Data Structures:**
1.  **Global Point Cloud ($\mathcal{P}$):** A set of 3D points in world coordinates, $\mathcal{P} \in \mathbb{R}^{N_p \times 3}$, constructed by unprojecting RGB-D data [S2].
2.  **Feature Volume ($\mathcal{F}$):** A sparse 3D tensor $H \times W \times D \times C$ extracted by a sparse 3D CNN, aligned with the world coordinate system [S2].
3.  **MLP Heads:** Three independent Multi-Layer Perceptrons: $\mathcal{D}_{pos}$ (position offset), $\mathcal{D}_{opa}$ (opacity), and $\mathcal{D}_{cov}$ (covariance) [S2].

**Parameters:**
*   $N$: Number of input images.
*   $N_p$: Number of primitives in the global point cloud.
*   $K$: Number of nearest reference views for color retrieval.
*   $v_{\text{size}}$: Voxel size used to scale the position offset output [S2].

**Steps:**

1.  **Global Point Cloud Construction:**
    Unproject the input images $\{I_n\}$ using their depth maps $\{D_n\}$, intrinsics $\{K_n\}$, and extrinsics $\{T_n\}$ to form a raw global point cloud:
    $$ \mathcal{P} = \bigcup_{n=1}^N \pi^{-1}(I_n, D_n, T_n, K_n) $$
    where $\pi^{-1}$ denotes pixel unprojection [S2].
    Apply a uniform filter to $\mathcal{P}$ to remove duplicate primitives while preserving structure. Apply a statistical filter to remove floating artifacts (noise) [S2].

2.  **Feature Volume Extraction:**
    Construct a sparse tensor from the filtered point cloud $\mathcal{P}$. Pass it through a sparse 3D CNN (e.g., sparse U-Net) to extract the neural feature volume $\mathcal{F}$ [S2].

3.  **Initialization:**
    Initialize the Gaussian centers $\mu^{init}_i$ using the points in $\mathcal{P}$:
    $$ \mu^{init}_i = p_i \in \mathcal{P} $$
    Initialize the previous position offset $\Delta \mu^{prev}_i = 0$ [S2].

4.  **Geometry Parameters Prediction (Recursive Update):**
    For each Gaussian $i$, perform the following update rule. During training, this is executed once per iteration. During inference, execute recursively (e.g., twice) to convergence [S2]:
    
    a. Query the feature vector $\mathbf{f}_i$ from $\mathcal{F}$ at the refined position $\mu^{init}_i + \Delta \mu^{prev}_i$ using trilinear interpolation:
    $$ \mathbf{f}_i = \mathcal{F}(\mu^{init}_i + \Delta \mu^{prev}_i) $$
    
    b. Decode opacity and covariance using MLP heads:
    $$ \alpha_i = \mathcal{D}_{opa}(\mathbf{f}_i) $$
    $$ \Sigma_i = \mathcal{D}_{cov}(\mathbf{f}_i) $$
    
    c. Decode position offset $\Delta \mu_i$ using $\mathcal{D}_{pos}$, apply Tanh activation, and scale by voxel size:
    $$ \Delta \mu_i = \text{Tanh}(\mathcal{D}_{pos}(\mathbf{f}_i)) \cdot v_{\text{size}} $$
    
    d. Update the Gaussian center:
    $$ \mu_i = \mu^{init}_i + \Delta \mu_i $$
    
    e. Update the previous offset for the next iteration:
    $$ \Delta \mu^{prev}_i \leftarrow \Delta \mu_i $$

5.  **Color Prediction:**
    Project the 3D Gaussians to the $K$ nearest reference views to retrieve 2D context (color windows $\{c_k\}$ and visibility maps). Decode the Gaussian color $c_i$ using this 2D context [S2].

6.  **Rendering:**
    Render the image by compositing the Gaussians using alpha blending:
    $$ c = \sum_{i \in \mathcal{G}} c_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    where $c$ is the final pixel color, and the product term is the transmittance [S2].

## Subtopics

### [Textured-GS](9436-textured-gs.md)
Textured-GS enhances the textural representation of individual 3D Gaussians by modeling spatially defined color and opacity variations across the Gaussian ellipsoidal surface using Spherical Harmonics (SH). Unlike standard 3DGS where each Gaussian has fixed opacity and single color, Textured-GS allows color/opacity variation across the surface, enabling 'unidirectional Gaussians' that are opaque on one side and transparent on the other. It differs from Gaussian Geometry Parameters Prediction by using the surface intersection vector for SH evaluation instead of the viewing vector.

### [Oriented Gaussian Splatting](9621-oriented-gaussian-splatting.md)
Oriented Gaussian Splatting assigns a learnable oriented normal vector $n_i$ to each primitive to create a reciprocal attenuation model, enabling the derivation of explicit geometric fields (normal and occupancy). It differs from standard Gaussian Splatting by restoring reciprocity ($\sigma(x, w) = \sigma(x, -w)$), which is broken by standard attenuation, thereby allowing the extraction of watertight meshes and consistent normals.

### [3D Skew-Normal Splatting](10045-3d-skew-normal-splatting.md)
3D Skew-Normal Splatting (SNS) replaces the standard symmetric 3D Gaussian kernel with the Azzalini Skew-Normal distribution to model asymmetric structures, such as sharp boundaries and one-sided surfaces. It introduces a learnable skewness parameter that allows continuous interpolation between symmetric Gaussians and half-ellipsoids, enabling a single primitive to represent complex geometries that would otherwise require multiple overlapping kernels.

### [Deformable 3D Gaussian Splatting](10060-deformable-3d-gaussian-splatting.md)
Deformable 3D Gaussian Splatting learns 3D Gaussians in a canonical (static) space and models spatial-temporal deformation using an implicit deformation field implemented as a Multi-Layer Perceptron (MLP). It differs from static 3D Gaussian Splatting by introducing time-dependent offsets to Gaussian attributes, and from other dynamic variants like [Mesh-Embedded Gaussian Splatting](9553-mesh-embedded-gaussian-splatting.md) by relying on an implicit MLP rather than explicit mesh constraints or voxel grids.

### [Fourier Splatting Primitive](11094-fourier-splatting-primitive.md)
The Fourier Splatting primitive is a planar surfel for radiance field rendering that replaces the fixed Gaussian or elliptical falloff with a boundary defined by a Fourier series, allowing the representation of arbitrary closed shapes. Unlike 3D Gaussian Splatting (3DGS) or 2D Gaussian Splatting (2DGS), which are limited to fixed elliptical/disc shapes, this primitive enables higher fidelity representation of complex geometry and fine-grained details. Its key differentiator is inherent scalability: the level of detail (LoD) is controlled by truncating Fourier coefficients at runtime, allowing a single trained model to be rendered at varying complexities without retraining or post-hoc compression.

### [Conditional Slicing Mechanism](11455-conditional-slicing-mechanism.md)
The Conditional Slicing Mechanism conditions a 7-dimensional Gaussian (defined over spatial, temporal, and angular dimensions) on observed time $t$ and view direction $d$ to yield a conditional 3D Gaussian governing the spatial component. This operation "slices" the full 7D distribution to integrate temporal dynamics and view-dependent effects into the traditional 3D rendering pipeline without introducing additional temporal dependencies in the spherical harmonics. It sets itself apart from static Gaussian Splatting variants by explicitly modeling the joint distribution of space, time, and view, allowing the spatial mean and covariance to shift based on the current rendering context.

### [Structure-Aware 3D Gaussian Splatting (SAGS)](11908-structure-aware-3d-gaussian-splatting-sags.md)
Structure-Aware 3D Gaussian Splatting (SAGS) is a novel-view synthesis method that implicitly encodes scene geometry using a local-global graph representation to facilitate learning complex scenes and enforce meaningful point displacements that preserve structure, thereby reducing floating-point artifacts and storage requirements. Unlike standard 3D Gaussian Splatting which optimizes each Gaussian independently, SAGS leverages inter- and intra-connectivity between 3D point positions via Graph Neural Networks (GNNs) to predict Gaussian attributes, outperforming 3D-GS and Scaffold-GS in capturing high-frequency details while significantly reducing memory footprint.

### [Mesh-embedded representation](12559-mesh-embedded-representation.md)
This family of methods integrates 3D Gaussian Splatting with explicit triangle mesh topology to provide structured, geometry-aware representations. Unlike standard Gaussian Splatting where primitives are independent entities, these methods bind Gaussian parameters to mesh faces or skeletal meshes, enabling direct compatibility with mesh editing, skeletal animation, and blend shapes. They solve the problem of unstructured Gaussian distributions in dynamic or editable scenes by decoupling motion and appearance through mesh-driven initialization and parameterization.

### [Inverse Gaussian Splattling](13193-inverse-gaussian-splattling.md)
Inverse Gaussian Splattling is a method for initializing 3D Gaussian primitives by back-projecting optimized 2D Gaussian kernels from image space into world space. It solves the problem of generating high-quality initial geometric parameters (position, rotation, scale) for new 3D Gaussians from 2D renderings, specifically handling foreground-background ambiguity in boundary regions. It differs from standard initialization by using Weighted Principal Component Analysis (WPCA) on clustered 3D points derived from depth maps, followed by a scaling calibration step to align the projected 3D covariance with the original 2D target.

### [Occupancy-Opacity Factorization](13440-occupancy-opacity-factorization.md)
Occupancy-Opacity Factorization decouples a Gaussian primitive's geometric presence from its optical properties by splitting the single standard opacity parameter into two learnable attributes: geometric occupancy ($\sigma$) and optical opacity ($\alpha$). This solves the problem where a single opacity parameter cannot simultaneously model a surface that is geometrically solid (for sharp reflections) yet optically clear (for light transmission). It sets itself apart from siblings like [Textured-GS](9436-textured-gs.md) and [Oriented Gaussian Splatting](9621-oriented-gaussian-splatting.md) by explicitly modeling the probabilistic interaction of rays with the Gaussian substance, enabling deferred shading for high-frequency reflection modeling.

### GSGEN
GSGEN introduces a 3D SDS loss based on Point-E to mitigate the multi-face or Janus problem in text-to-3D generation [S1]. It adopts Point-E to initialize the point cloud as the initial geometry for optimization and refines the appearance with only the 2D image prior [S1].

### BrightDreamer
BrightDreamer predicts the deviation of a set of fixed anchor points to determine the centers of Gaussians [S1]. The centers of Gaussians are determined from these predicted deviations [S1].

### NeRF-Guided 3D Gaussian Splatting
Uses a pretrained NeRF as a teacher to guide feature distillation, improving alignment between geometry and semantics [S3, unofficial].

### Gaussian Splatting Attribute Prediction
A voxel transformer that predicts residuals added to initial Gaussian rendering attributes on voxels, rather than generating new attributes directly [S4]. The residual is calculated as $\Delta \mathbf{G}_j = \text{MLP}_{fine}([\mathbf{O}_j, \mathbf{E}_j])$, where $[\mathbf{O}_j, \mathbf{E}_j]$ denotes the concatenation of offset $\mathbf{O}_j$ and voxel attribute $\mathbf{E}_j$. The final parameter is $\mathbf{G}'_j = \mathbf{G}_j + \Delta \mathbf{G}_j$ [S4].

### 6D Gaussian Splatting
An extension of 3DGS that models view-dependent effects by adding directional dimensions, representing scene elements as 6D Gaussians (space+direction) [S5]. It parameterizes the full 6D covariance via Cholesky decomposition $\Sigma = LL^\top$ with $L$ lower-triangular and positive diagonal entries to guarantee positive definiteness [S5].

### Anisotropic Covariance
Allows 3D Gaussians to scale anisotropically along the x, y, and z axes and rotate in 3D space, rather than remaining spherical, to better fit scene geometry [S6, unofficial]. Each Gaussian optimizes 3 scale parameters (x, y, z expansion) and 4 rotation parameters (quaternion). The Isotropic variant fixes these, removing 7 variables per Gaussian. On Average-30K, Full achieves PSNR 26.05, while Isotropic achieves 25.23 [S6, unofficial]. Isotropic forces Gaussians to remain spherical, causing blurry, rounded artifacts (e.g., tree trunks/leaves appear as round dots), whereas Anisotropic allows elongated/rotated shapes matching scene geometry [S6, unofficial].

### Defocus Blur Modeling
Models optical defocus by adjusting the scale $s$ of 3D Gaussians based on their distance from the camera's focal plane [S7]. During training, larger scale values $\bar{s}_j$ are used to rasterize blurred images. During testing, smaller scale values $s_j$ are used to render sharp details. Unlike a naive Gaussian kernel that blurs the entire image uniformly, this method selectively enlarges covariances only for Gaussians corresponding to blurred regions [S7].

### AnySplat Pipeline
1. Input uncalibrated images to a transformer-based geometry encoder. 2. Three decoder heads ($F_G, F_D, F_C$) predict Gaussian parameters ($\mu, \sigma, r, s, c$), depth map $D$, and camera poses $p$. 3. Outputs construct pixel-wise 3D Gaussians. 4. Gaussians are voxelized into pre-voxel 3D Gaussians using a Differentiable Voxelization module. 5. Multi-view images and depth maps are rendered from voxelized Gaussians. 6. Rendered images are supervised by RGB loss against ground truth. 7. Rendered depth maps, decoded depth $D$, and poses $p$ compute geometry losses. 8. Geometries are supervised by pseudo-geometry priors from pretrained VGGT [S8, unofficial]. Input image tensor shape: $[1, K, 3, 448, 448]$ (batch, views, channels, height, width) [S8, unofficial]. Code: `gaussians, pred_context_pose = model.inference((images+1)*0.5)` [S8, unofficial].

### 3D Gaussians Prediction from Voxels
Predicts a set of learnable Gaussian parameters for each voxel $v$, including center offset, opacity, covariance, and spherical harmonic color [S9]. The final 3D Gaussian center $\mu_j$ is computed by applying a sigmoid activation to the predicted offset $\bar{\mu}_j$, shifting by -0.5, scaling by $r$, and adding the voxel centroid $Center_j$: $\mu_j = r \cdot (\sigma(\bar{\mu}_j) - 0.5) + Center_j$. The output dimension per Gaussian is 38, comprising offset (3), opacity (1), covariance (6), and spherical harmonic color (28). $r$ is the scaling factor for the Gaussian center offset, set to 3 times the voxel size. The sigmoid activation restricts the learnable offset to a localized neighborhood; the -0.5 shift facilitates symmetrical, bi-directional movement from the voxel center [S9].

## Operating characteristics
**Time and Memory Complexity:** The method operates in a feed-forward manner, avoiding per-scene optimization, which significantly reduces training time compared to iterative 3DGS [S2]. By downsampling initial primitives and using a sparse 3D CNN, it reduces computation compared to pixel-aligned methods that process every pixel independently [S2]. Memory usage is determined by the size of the global feature volume $\mathcal{F}$ and the number of primitives $N_p$ in the global point cloud [S2].

**Measured Performance:** EVolSplat achieves real-time rendering speeds for urban scene reconstruction [S2]. It improves global consistency and reduces ghosting artifacts compared to existing feed-forward methods like MVSplat, Flash3D, and DrivingForward, which suffer from multi-view inconsistencies and duplicated content when accumulating local volumes [S2].

**Strengths and Limitations:** The primary strength is the reduction of ghosting artifacts through global volume prediction and the efficiency of feed-forward inference [S2]. A limitation is the reliance on monocular depth estimators, which can introduce noise and floating artifacts, requiring additional filtering steps (uniform and statistical filters) [S2]. It is specifically designed for urban scenes with large camera movements and small parallax, where traditional multi-view stereo might struggle [S2].

## Background
Gaussian Geometry Parameters Prediction, exemplified by EVolSplat, was introduced by Sheng Miao, Jiaxin Huang, Dongfeng Bai, Xu Yan, Hongyu Zhou, Yue Wang, Bingbing Liu, Andreas Geiger, and Yiyi Liao from Zhejiang University, Huawei Noah’s Ark Lab, and the University of Tübingen [S2]. The method was presented at CVPR 2025 (arXiv:2503.20168v1, March 26, 2025) [S2]. It addresses the limitations of previous feed-forward 3DGS methods that predict per-pixel aligned Gaussians using local cost volumes or epipolar transformers, which often lead to inconsistencies in global coordinates [S2].
