# AnySplat Pipeline

Also called: Feed-forward 3D Gaussian Splatting from Unconstrained Views

## Overview
AnySplat is a feed-forward method that predicts a set of 3D Gaussians directly from uncalibrated multi-view images, solving the problem of reconstructing radiance fields without iterative optimization or known camera poses [S1, unofficial]. It differs from sibling methods like [Textured-GS](9436-textured-gs.md) and [Deformable 3D Gaussian Splatting](10060-deformable-3d-gaussian-splatting.md) by using a transformer-based encoder-decoder to predict geometry, appearance, and camera parameters simultaneously, followed by differentiable voxelization to stabilize the representation [S1, unofficial].

## How it works
**Inputs and Outputs:**
The input is a tensor of $K$ uncalibrated images with shape $[1, K, 3, 448, 448]$ (batch, views, channels, height, width) [S1, unofficial]. The output is a set of 3D Gaussians (defined by mean $\mu$, covariance $\sigma$, rotation $r$, scale $s$, and color $c$) and predicted camera poses [S1, unofficial].

**Data Structures:**
The Gaussian parameters are predicted as dense fields or point clouds by the decoder heads. The specific bit-packing or memory layout of the Gaussian attributes is not detailed in the sources [G: Standard 3DGS representation is assumed: $\mu \in \mathbb{R}^3$, $\sigma \in \mathbb{R}^{3 \times 3}$ (or quaternion/scale), $c \in \mathbb{R}^3$].

**Steps:**
1. **Encoding:** Input images are processed by a transformer-based geometry encoder.
2. **Decoding:** Three decoder heads ($F_G, F_D, F_C$) predict:
   - Gaussian parameters: mean $\mu$, covariance $\sigma$, rotation $r$, scale $s$, and color $c$ [S1, unofficial].
   - Depth map $D$ [S1, unofficial].
   - Camera poses $p$ [S1, unofficial].
3. **Gaussian Construction:** Pixel-wise 3D Gaussians are constructed from the predicted parameters [S1, unofficial].
4. **Differentiable Voxelization:** The pixel-wise Gaussians are voxelized into "pre-voxel" 3D Gaussians using a Differentiable Voxelization module [S1, unofficial]. This step aggregates and regularizes the Gaussians.
5. **Rendering:** Multi-view images and depth maps are rendered from the voxelized Gaussians using standard differentiable rasterization [S1, unofficial].
6. **Loss Computation:**
   - **RGB Loss:** Rendered images are compared against ground truth images [S1, unofficial].
   - **Geometry Loss:** Rendered depth maps, decoded depth $D$, and predicted poses $p$ are used to compute geometry losses [S1, unofficial].
   - **Pseudo-Geometry Prior:** Geometries are supervised by pseudo-geometry priors obtained from a pretrained VGGT model [S1, unofficial].

**Pseudocode:**
```python
# Input: images tensor of shape [1, K, 3, 448, 448], values in [-1, 1]
# Normalize to [0, 1]
images_normalized = (images + 1) * 0.5

# Run the AnySplat model inference
# Returns: gaussians (set of 3D Gaussians), pred_context_pose (dict with extrinsic and intrinsic matrices)

# Extract predicted camera poses
pred_all_extrinsic = pred_context_pose['extrinsic']
```

**Parameters:**
- Image resolution: 448x448 [S1, unofficial].
- Number of views $K$: Not specified in the sources [G: Typically 3-5 for feed-forward methods, but not given].
- Training hardware: PyTorch 2.2.0, CUDA 12.1 [S1, unofficial].

**Edge Cases and Pitfalls:**
- The method relies on a pretrained VGGT model for pseudo-geometry priors; performance may degrade if the input scene is out-of-distribution for VGGT [S1, unofficial].
- The differentiable voxelization module is critical for stabilizing the Gaussian set; skipping it may lead to noisy or unstable representations [S1, unofficial].

## Subtopics

### [SubSplat](13524-subsplat.md)
The core component, Sub-pixel Gaussian Reparameterizer (SPGR), which subdivides each grid-anchored primary Gaussian into fine-grained sub-pixel primitives through dedicated geometry and appearance features.

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Measured Performance:** Not given in the sources.
- **Strengths:** Feed-forward inference allows for fast reconstruction from uncalibrated views without iterative optimization [S1, unofficial].
- **Limitations:** Relies on external pretrained models (VGGT) for geometry priors [S1, unofficial].
- **When to use:** When fast reconstruction from uncalibrated multi-view images is required.
- **When not to use:** When iterative optimization is acceptable and higher accuracy is needed, or when camera poses are known and can be used directly.

## Background
AnySplat was introduced by InternRobotics as a feed-forward approach to 3D Gaussian Splatting from unconstrained views [S1, unofficial]. It builds on [Gaussian Geometry Parameters Prediction](8442-gaussian-geometry-parameters-prediction.md) by predicting parameters directly from images. The method uses a transformer architecture and leverages pseudo-geometry priors from VGGT to supervise the geometry [S1, unofficial].
