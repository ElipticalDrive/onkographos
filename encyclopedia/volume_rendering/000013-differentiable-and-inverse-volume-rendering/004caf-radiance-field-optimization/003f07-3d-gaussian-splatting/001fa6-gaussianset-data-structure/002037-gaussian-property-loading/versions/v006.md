# Gaussian Property Loading

Also called: PLY Property Loading with Fallbacks, PLY Gaussian Loading

## Overview
Gaussian Property Loading parses 3D Gaussian Splatting scene data from a Polygon File Format (PLY) file, decoding raw vertex properties into a structured Gaussian representation suitable for rendering [S1, S2, S3, S4, unofficial]. It solves the problem of converting the standardized, often compressed or logarithmically encoded PLY storage format into the explicit mathematical parameters (position, scale, rotation, color, opacity) required by the rasterization pipeline [S1, S2, S3, S4, unofficial]. It differs from its siblings by focusing on the initial ingestion and decoding of the PLY file into the `GaussianData` structure, whereas [Coordinate System Conversion for Gaussian Splats](3935-coordinate-system-conversion-for-gaussian-splats.md) handles spatial alignment and [INRIA V1 PLY Splat Parsing](6822-inria-v1-ply-splat-parsing.md) addresses specific legacy format variations [S1, S2, S3, S4, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A `.ply` file containing vertex elements with properties for position, rotation, scale, opacity, and spherical harmonics (SH) or RGB color [S3, unofficial].
- Output: A dictionary or struct containing decoded Gaussian properties: `xyz` (N,3), `rot` (N,4), `scale` (N,3), `sh` (N, total SH coefficients), `opacity` (N,1), and `dc_colours` (N,3) [S2, S4, unofficial].

**Data Structures:**
The output is typically a dictionary or struct with the following fields [S2, S4, unofficial]:
- `xyz`: Float32 array of shape (N, 3) representing mean positions.
- `rot`: Float32 array of shape (N, 4) representing normalized quaternions (w, x, y, z).
- `scale`: Float32 array of shape (N, 3) representing decoded linear scales.
- `sh`: Float32 array of shape (N, K) where K is the total number of SH coefficients.
- `opacity`: Float32 array of shape (N, 1) representing decoded opacity values.
- `dc_colours`: Float32 array of shape (N, 3) representing the DC term of the SH converted to RGB.

**Numbered Steps:**

1. **Open and Parse Header:** Open the PLY file in binary or ASCII mode [S4, unofficial]. Parse the header to identify the file type and property types [S4, unofficial]. Identify the vertex element and request the following properties:
   - Position: `x`, `y`, `z` [S3, unofficial].
   - Scale: Try `scale_0`, `scale_1`, `scale_2`. If not found, fallback to `scaling_0`, `scaling_1`, `scaling_2` [S3, unofficial].
   - Rotation: Try `rot_0`, `rot_1`, `rot_2`, `rot_3`. If not found, fallback to `rotation_0`, `rotation_1`, `rotation_2`, `rotation_3` [S3, unofficial].
   - Color/SH: Try `f_dc_0`, `f_dc_1`, `f_dc_2` (indicating SH presence) [S3, unofficial]. If not found, fallback to `red`, `green`, `blue` (RGB) [S3, unofficial]. If neither, default to white [S3, unofficial].
   - Opacity: Try `opacity`. If not found, default to full opacity (1.0) [S3, unofficial].
   - Extra SH: Identify extra feature names starting with `f_rest_` [S2, S3, S4, unofficial].

2. **Extract Raw Data:** Read the vertex data [S3, unofficial]. Extract `xyz` coordinates and stack them into shape (N, 3) [S2, unofficial]. Extract scale, rotation, and opacity values [S2, unofficial]. Cast `xyz`, `rot`, `scale`, and `opacity` to float32 [S2, unofficial].

3. **Decode Scale:** The stored scale values are log-scales [S1, S2, unofficial]. Apply the exponential function to decode them:
   $$ \text{scale}_i = \exp(\text{stored\_scale}_i) $$
   for $i \in \{0, 1, 2\}$ [S1, S2, unofficial].

4. **Decode Opacity:** The stored opacity values are pre-activation logits [S1, S2, unofficial]. Apply the sigmoid function to decode them:
   $$ \text{opacity} = \frac{1}{1 + \exp(-\text{stored\_opacity})} $$
   [S1, S2, unofficial].

5. **Decode Rotation:** The stored rotation values are quaternions [S1, S2, unofficial]. Normalize them to ensure they represent valid rotations:
   $$ \text{rot} = \frac{\text{stored\_rot}}{\|\text{stored\_rot}\|} $$
   [S2, unofficial].

6. **Decode Spherical Harmonics (SH):**
   - Identify the maximum SH degree (`max_sh_degree`) [S2, unofficial]. This is determined by the number of `f_rest_` fields, where the count equals $3 \times ((\text{max\_sh\_degree} + 1)^2 - 1)$ [S2, unofficial].
   - Extract `f_dc_0`, `f_dc_1`, `f_dc_2` into the first 3 SH coefficients (DC term) [S1, S2, unofficial].
   - Extract `f_rest_N` coefficients starting at index 3 [S1, S2, unofficial].
   - Reshape `f_rest` to (N, 3, $(max\_sh\_degree + 1)^2 - 1$), then transpose to (N, $(max\_sh\_degree + 1)^2 - 1$, 3) [S2, unofficial].

7. **Compute DC Colours:** Extract the first 3 channels of the SH coefficients (`dc_vals`) [S2, unofficial]. Apply the following formula to convert to RGB:
   $$ \text{dc\_colours} = \max(\text{dc\_vals} \times C_0 + 0.5, 0) $$
   where $C_0$ is the SH constant for degree 0, typically $0.28209479177387814$ [S2, S4, unofficial].

8. **Final Assembly:** Concatenate `features_dc` (reshaped to (-1, 3)) and `features_extra` (reshaped to (N, -1)) along axis -1 to form `sh` of shape (N, total SH coefficients) [S2, unofficial]. Cast to float32 [S2, unofficial].

**Pseudocode:**

```python
import numpy as np

def load_gaussians_from_ply(ply_data):
    """
    Loads Gaussian properties from a parsed PLY file dictionary.
    ply_data: dict mapping property names to numpy arrays of shape (N,) or (N, 3) etc.
    Returns a dictionary with keys: 'xyz', 'rot', 'scale', 'sh', 'opacity', 'dc_colours'.
    """
    # Step 1 & 2: Extract and cast to float32
    xyz = np.stack([ply_data['x'], ply_data['y'], ply_data['z']], axis=-1).astype(np.float32)

    # Scale fallback
    if 'scale_0' in ply_data:
        scale_raw = np.stack([ply_data['scale_0'], ply_data['scale_1'], ply_data['scale_2']], axis=-1)
    else:
        scale_raw = np.stack([ply_data['scaling_0'], ply_data['scaling_1'], ply_data['scaling_2']], axis=-1)
    scale_raw = scale_raw.astype(np.float32)

    # Rotation fallback
    if 'rot_0' in ply_data:
        rot_raw = np.stack([ply_data['rot_0'], ply_data['rot_1'], ply_data['rot_2'], ply_data['rot_3']], axis=-1)
    else:
        rot_raw = np.stack([ply_data['rotation_0'], ply_data['rotation_1'], ply_data['rotation_2'], ply_data['rotation_3']], axis=-1)
    rot_raw = rot_raw.astype(np.float32)

    # Opacity
    if 'opacity' in ply_data:
        opacity_raw = ply_data['opacity'].astype(np.float32).reshape(-1, 1)
    else:
        opacity_raw = np.ones((xyz.shape[0], 1), dtype=np.float32)

    # Color/SH
    has_sh = 'f_dc_0' in ply_data
    has_rgb = 'red' in ply_data

    if has_sh:
        f_dc = np.stack([ply_data['f_dc_0'], ply_data['f_dc_1'], ply_data['f_dc_2']], axis=-1).astype(np.float32)
        f_rest_names = sorted([k for k in ply_data.keys() if k.startswith('f_rest_')], key=lambda x: int(x.split('_')[-1]))
        f_rest = np.stack([ply_data[name] for name in f_rest_names], axis=-1).astype(np.float32)

        # Determine max_sh_degree from extra features count
        num_extra_features = len(f_rest_names)
        max_sh_degree = int(np.sqrt(num_extra_features / 3 + 1) - 1)

        # Reshape and transpose f_rest to (N, (max_sh_degree + 1)^2 - 1, 3)
        f_rest = f_rest.reshape(-1, 3, (max_sh_degree + 1)**2 - 1)
        f_rest = np.transpose(f_rest, (0, 2, 1))

        # Concatenate features_dc and features_extra along last axis to form shs
        sh = np.concatenate([f_dc.reshape(-1, 3), f_rest.reshape(-1, f_rest.shape[1] * 3)], axis=-1)

        # Compute dc_colours
        C0 = 0.28209479177387814
        dc_vals = f_dc
        dc_colours = np.maximum(dc_vals * C0 + 0.5, 0.0)
    elif has_rgb:
        sh = np.zeros((xyz.shape[0], 3), dtype=np.float32)
        dc_colours = np.stack([ply_data['red'], ply_data['green'], ply_data['blue']], axis=-1).astype(np.float32)
    else:
        sh = np.zeros((xyz.shape[0], 3), dtype=np.float32)
        dc_colours = np.ones((xyz.shape[0], 3), dtype=np.float32)

    # Step 3: Decode Scale
    scale = np.exp(scale_raw)

    # Step 4: Decode Opacity
    opacity = 1.0 / (1.0 + np.exp(-opacity_raw))

    # Step 5: Decode Rotation
    rot = rot_raw / np.linalg.norm(rot_raw, axis=1, keepdims=True)

    return {
        'xyz': xyz,
        'rot': rot,
        'scale': scale,
        'sh': sh,
        'opacity': opacity,
        'dc_colours': dc_colours
    }
```

**Parameters:**
- `max_sh_degree`: Maximum spherical harmonic degree, typically set to 3 for high-quality rendering [S2, S4, unofficial].
- `C0`: SH constant for degree 0, value $0.28209479177387814$ [S4, unofficial].

**Edge Cases and Pitfalls:**
- **Coordinate System:** PLY files may use a different coordinate system (e.g., Right-handed Down-Forward) than the rendering engine (e.g., Right-handed Up-Back) [S1, S3, S4, unofficial].
- **Endianness:** Binary PLY files can be little-endian or big-endian. The parser must handle both [S4, unofficial].
- **Missing Properties:** Fallbacks are necessary for scale (`scaling_*`), rotation (`rotation_*`), and color (`red/green/blue`) [S1, S2, S3, S4, unofficial].
- **Precision:** Ensure all values are cast to float32 to maintain consistency with the rendering pipeline [S2, S4, unofficial].

## Subtopics

### [Gaussian Splat PLY Loader](3254-gaussian-splat-ply-loader.md)
The Gaussian Splat PLY Loader parses 3D Gaussian Splatting scene data from a Polygon File Format (PLY) file, decoding raw vertex properties into a structured Gaussian representation suitable for rendering. It solves the problem of converting the standardized, often compressed or logarithmically encoded PLY storage format into the explicit mathematical parameters (position, scale, rotation, color, opacity) required by the rasterization pipeline. It differs from its siblings by focusing on the initial ingestion and decoding of the PLY file into the `GaussianData` structure, whereas [Coordinate System Conversion for Gaussian Splats](3935-coordinate-system-conversion-for-gaussian-splats.md) handles spatial alignment and [INRIA V1 PLY Splat Parsing](6822-inria-v1-ply-splat-parsing.md) addresses specific legacy format variations.

### [Coordinate System Conversion for Gaussian Splats](3935-coordinate-system-conversion-for-gaussian-splats.md)
This method transforms Gaussian splat attributes (position, rotation, spherical harmonics) between different coordinate systems, such as converting from the Right-handed Up-Back (RUB) format used internally to the Right-handed Down-Forward (RDF) format used in PLY files. It sets apart from sibling loaders by handling the specific axis flips and rotations required for quaternion and spherical harmonic consistency, ensuring that the rendered output remains invariant under coordinate system changes.

### [INRIA V1 PLY Splat Parsing](6822-inria-v1-ply-splat-parsing.md)
The INRIA V1 PLY Splat Parsing method decodes the text-based `.ply` files generated by the original INRIA 3D Gaussian Splatting implementation into an uncompressed, contiguous array of Gaussian properties suitable for rendering or further processing. It solves the problem of interpreting variable-length spherical harmonic (SH) fields and applying specific activation functions (sigmoid for opacity, exponential for scale) and coordinate system transformations required by downstream engines. Unlike the standard `.splat` binary format which uses fixed-width records, this method handles the PLY header's variable field counts to dynamically determine the SH degree (0, 1, or 2) and extract the corresponding coefficients.

### [3D Gaussian Splatting Model Preprocessing and Grid Partitioning](6908-3d-gaussian-splatting-model-preprocessing-and-grid-partition.md)
This method preprocesses a raw 3D Gaussian Splatting model stored in PLY format for use in Unreal Engine. It parses the PLY file, converts coordinate systems and property encodings to match the engine's internal representation, and partitions the Gaussians into a spatial grid for efficient culling and rendering. It differs from generic loaders by applying specific axis swaps, exponential scale decoding, and sigmoid opacity activation required by the target engine's shader pipeline.
