# Dynamic Gaussian Splatting Scene Management

Also called: Spirula Scene Management, ROSplat Dynamic Scene API

## Overview
Dynamic Gaussian Splatting Scene Management provides the runtime infrastructure for continuously updating a 3D Gaussian Splatting (3DGS) scene on the GPU without full re-initialization. It solves the problem of real-time scene evolution by managing the lifecycle of splat data structures, handling capacity growth, and batching incoming Gaussian updates from external sources (such as ROS2 sensors or simulation pipelines) into the renderer's state. It differs from static loading methods by supporting incremental `append` operations and dynamic buffer resizing, enabling the scene to grow or refresh while maintaining rendering continuity [S1, unofficial].

## How it works
The method manages a device-resident `DeviceScene` structure that acts as the bridge between host-side data ingestion and the GPU rendering engine. It operates through a sequence of initialization, capacity management, data appending, and rendering steps.

### Inputs and Outputs
*   **Inputs:**
    *   `sh_degree`: Integer in $[0, 4]$ defining spherical harmonic complexity.
    *   `initial_capacity`: Integer $\ge 0$ for initial buffer reservation.
    *   `batch_count`: Number of splats to append.
    *   `means_xyz`: Host array of $N \times 3$ floats.
    *   `quaternions_wxyz`: Host array of $N \times 4$ floats (scalar-last order).
    *   `log_scales_xyz`: Host array of $N \times 3$ floats (log-space scales).
    *   `opacity_logits`: Host array of $N$ floats (logit-space opacity).
    *   `features_dc_rgb`: Host array of $N \times 3$ floats (DC coefficients).
    *   `features_sh_rgb`: Host array of $N \times D \times 3$ floats (SH coefficients), where $D = (\text{sh\_degree} + 1)^2 - 1$.
    *   `width`, `height`: Camera resolution.
    *   `view_matrix_4x4`: $4 \times 4$ row-major float array (world-to-camera).
    *   `intrinsics_fx_fy_cx_cy`: Array of 4 floats.
    *   `modifier`: Positive finite float for global scale adjustment.
*   **Outputs:**
    *   Rendered images (RGBA8, Depth, or Opacity) in host memory.
    *   Updated scene state on the GPU.

### Data Structures
The core state is held in `DeviceScene` on the GPU device:
*   `means`: `float3*` array of size `capacity`.
*   `quats`: `float4*` array of size `capacity`.
*   `scales`: `float3*` array of size `capacity`.
*   `opacities`: `float*` array of size `capacity`.
*   `features_dc`: `float3*` array of size `capacity`.
*   `features_sh`: `float3*` array of size `capacity * num_sh`.
*   `count`: `int64_t` current number of splats.
*   `capacity`: `int64_t` current buffer capacity.
*   `sh_degree`: `int`.
*   `num_sh`: `int`, calculated as $(\text{sh\_degree} + 1)^2 - 1$.

Host-side readback buffers (`HostRender`) store results in pinned memory:
*   `rgb`: `float3*` array of size `rgb_pixels`.
*   `scalar`: `float*` array of size `scalar_pixels`.

### Numbered Steps

1.  **Initialize Renderer:**
    *   Validate `sh_degree` $\in [0, 4]$ and `initial_capacity` $\ge 0$.
    *   Reset the engine and release existing scene data.
    *   Set `scene.sh_degree` and calculate `scene.num_sh = (sh_degree + 1)^2 - 1`.
    *   Reserve memory for `initial_capacity` and bind the scene to the engine.

2.  **Reserve Scene Capacity:**
    *   If the requested capacity exceeds the current `scene.capacity`:
        *   Calculate `next_capacity = max(requested, max(4096, current_capacity * 2))`.
        *   Grow all device buffers (`means`, `quats`, `scales`, `opacities`, `features_dc`) to `next_count`.
        *   If `num_sh > 0`, grow `features_sh` to `next_count * num_sh`.
        *   Update `scene.capacity` and rebind the scene.

3.  **Bind Scene to Engine:**
    *   Set `state.cur_num_splats = scene.count`.
    *   Set `state.max_num_splats = scene.capacity`.
    *   Set `state.num_sh` and `state.sh_degree`.
    *   Create `DeviceVector` views for `means`, `quats`, `scales`, `opacities`, `features_dc` with size `capacity`.
    *   If `num_sh > 0`, create a `DeviceTensor2D` view for `features_sh` with dimensions `(capacity, num_sh, 3)`; otherwise, create an empty tensor.
    *   Set `state.world.initialized = true` if `capacity > 0`.

4.  **Append Splats:**
    *   Validate `batch_count` $\ge 0$ and that all input arrays are non-null.
    *   Calculate `offset = scene.count`.
    *   Check for integer overflow: if `scene.count > numeric_limits<int64_t>::max() - batch_count`, throw `std::overflow_error`.
    *   Reserve space for `offset + batch_count` (triggering growth if necessary).
    *   Copy `means`, `quats`, `scales`, `opacities`, `features_dc` from host to device starting at `offset`.
    *   If `num_sh > 0`, copy `features_sh` from host to device starting at `offset * num_sh`.
    *   Increment `scene.count` and rebind the scene.

5.  **Set Camera:**
    *   Validate `width > 0`, `height > 0`, and that `view_matrix` and `intrinsics` are non-null.
    *   Initialize `dist_coeffs[8]` to zero.
    *   Call `set_camera_params` with `width`, `height`, projection type `"PINHOLE"`, distortion type `"NONE"`, `view_matrix` (1x4x4 float), `intrinsics` (1x4 float), and `dist_coeffs` (1x8 float).
    *   Set `width`, `height`, and `camera_ready = true`.

6.  **Set Scale Modifier:**
    *   Validate `modifier > 0` and is finite.
    *   If `modifier` equals the current `scale_modifier`, return.
    *   Calculate `log_delta = log(requested_modifier / scale_modifier)`.
    *   Calculate `numel = scene.count * 3`.
    *   Allocate a device scratch buffer of size `max_chunk` (typically $1 \ll 20$).
    *   Loop over `numel` in chunks:
        *   Copy `log_delta` to the device chunk.
        *   Call `float_add_into` on the `scales` chunk and the device `delta` chunk.
    *   Free the scratch buffer.
    *   Update `scale_modifier`.

7.  **Render Color:**
    *   Validate output buffer size $\ge$ `pixel_count * 4`.
    *   If `scene.count == 0`, fill output with black (RGB 0,0,0) and alpha 255.
    *   Determine `render_sh_degree = min(requested_sh_degree, scene.sh_degree)` if `requested >= 0`, else `scene.sh_degree`.
    *   Call `forward_3dgs("3dgs", render_sh_degree, true)`.
    *   Get the RGB buffer from `state.fwd.renders`.
    *   Resize `host.rgb` if needed.
    *   Copy RGB from device to host.
    *   Write RGB to the output buffer using `write_gray_or_rgb`.

8.  **Render Depth:**
    *   Validate output.
    *   If `scene.count == 0`, fill with black/alpha 255.
    *   Call `forward_3dgs`.
    *   Get the depth buffer from `state.fwd.renders` (index 1).
    *   Resize `host.scalar`.
    *   Copy depth from device to host.
    *   Call `write_depth(output, pixel_count)`.

9.  **Render Opacity:**
    *   Validate output.
    *   If `scene.count == 0`, fill with black/alpha 255.
    *   Call `forward_3dgs`.
    *   Get the transmittance buffer from `state.fwd.render_Ts`.
    *   Resize `host.scalar`.
    *   Copy transmittance from device to host.
    *   Loop over pixels to write opacity (implementation mirrors color/depth rendering logic).

### Parameters
*   **SH Degree:** Integer, range $[0, 4]$. Determines spherical harmonic complexity. `num_sh` is calculated as $(\text{sh\_degree} + 1)^2 - 1$.
*   **Scale Modifier:** Float, must be positive and finite. Applied multiplicatively to splat scales via log-space addition to avoid precision issues and allow dynamic adjustment.

### Edge Cases and Pitfalls
*   **Empty Scene:** If `scene.count == 0` during rendering, the renderer outputs a black image (RGB 0,0,0) with full alpha (255) instead of crashing or rendering nothing [S1, unofficial].
*   **Buffer Overflow:** The append operation checks for integer overflow when adding `batch_count` to `scene.count`. If `scene.count > numeric_limits<int64_t>::max() - batch_count`, it throws `std::overflow_error` [S1, unofficial].
*   **Precision:** Scales are stored in log-space to ensure positivity and improve optimization stability. Linear scales are recovered via $s_{linear} = \exp(s_{log})$ [S1, unofficial].

## Subtopics

### [Gaussian Splatting Scene Management & ROS2 Bridge](7494-gaussian-splatting-scene-management-ros2-bridge.md)
Manages the dynamic lifecycle of 3D Gaussian splats within a ROS2-enabled rendering pipeline, bridging sensor or simulation data to the GPU renderer. It solves the problem of real-time scene updates by queuing incoming Gaussian batches and efficiently draining them to the renderer state. It differs from static loading by enabling continuous, batched updates via ROS2 communication, allowing the scene to grow or refresh without full re-initialization.

## Operating characteristics
*   **Time Complexity:** Appending splats is $O(N)$ where $N$ is the batch size, plus $O(C)$ for buffer growth if capacity is exceeded, where $C$ is the new capacity. Rendering is $O(P \cdot N)$ where $P$ is the number of pixels and $N$ is the number of splats, typical for rasterization-based splatting.
*   **Memory Complexity:** $O(C \cdot D)$ where $C$ is the capacity and $D$ is the dimensionality of attributes (including SH coefficients).
*   **Scaling:** The doubling strategy for capacity growth ensures amortized $O(1)$ cost for appends, but large jumps can cause temporary memory spikes.
*   **Strengths:** Supports dynamic scene updates without full re-initialization; efficient buffer management; handles empty scenes gracefully.
*   **Limitations:** Requires careful management of buffer growth to avoid fragmentation; log-space storage adds a small computational overhead for scale adjustments.
*   **When to Use:** Real-time applications with evolving scenes, such as SLAM or dynamic object insertion.
*   **When Not to Use:** Static scenes where pre-allocation of exact size is known and fixed.

## Background
The method originates from the ROSplat project, which integrates 3D Gaussian Splatting with ROS2 for robotic applications. It was developed to enable real-time scene updates in dynamic environments, leveraging a Vulkan-based backend for efficient GPU rendering [S1, unofficial].
