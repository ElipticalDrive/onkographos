# Spherical Harmonics Coefficient Layout

Also called: Per-Dimension SH Storage, SH Buffer Layout

## Overview
This method defines the memory layout for storing spherical harmonics (SH) coefficients for 3D Gaussian splats in a Structure-of-Arrays (SoA) format. It solves the problem of efficiently accessing color data during GPU rendering by ensuring that shaders iterate over contiguous memory segments for specific attributes, maximizing cache coherency [5568-splat-data-buffer-layout.md]. Unlike block-compressed or texture-based variants, this layout stores coefficients in a flat, contiguous linear buffer grouped by splat, then coefficient, then channel [S1, unofficial].

## How it works
**Inputs:**
- $N$: Total number of splats.
- $D$: Total number of SH coefficients per channel for the chosen degree (e.g., $D=3$ for degree 1, $D=8$ for degree 2).
- Source data: A collection of splats, each having $D$ coefficients for Red, Green, and Blue channels.

**Outputs:**
- A contiguous linear buffer (e.g., `FloatBuffer`) of size $N \times D \times 3$.

**Data Structures:**
- **SH Buffer:** A 1D array of floats.
- **Indexing Formula:** The index for the $c$-th channel ($c \in \{0, 1, 2\}$ for R, G, B) of the $d$-th coefficient ($d \in \{0, \dots, D-1\}$) of the $i$-th splat ($i \in \{0, \dots, N-1\}$) is:
  $$ idx = ((i \times D) + d) \times 3 + c $$
  This layout groups data by splat, then by coefficient index, then by spatial dimension (RGB) [S1, unofficial].

**Steps:**
1. Initialize a buffer `b` of size $N \times D \times 3$.
2. Iterate over each splat index $i$ from $0$ to $N-1$.
3. For each splat $i$, iterate over each coefficient index $d$ from $0$ to $D-1$.
4. For each coefficient $d$, write the three color components to the buffer:
   - Red ($c=0$): `b[((i * D) + d) * 3 + 0] = s.getShR(d)`
   - Green ($c=1$): `b[((i * D) + d) * 3 + 1] = s.getShG(d)`
   - Blue ($c=2$): `b[((i * D) + d) * 3 + 2] = s.getShB(d)`
5. Return the populated buffer `b`.

**Pseudocode:**
```python
def write_sh_coefficients(splats, sh_dimensions):
    """
    Writes SH coefficients into a flat buffer.
    
    Args:
        splats: List of splat objects, each with get_sh_r(d), get_sh_g(d), get_sh_b(d).
        sh_dimensions: Integer D, total number of SH coefficients per channel.
        
    Returns:
        List of floats representing the flat buffer.
    """
    n = len(splats)
    buffer_size = n * sh_dimensions * 3
    buffer = [0.0] * buffer_size
    
    for i in range(n):
        for d in range(sh_dimensions):
            base_idx = (i * sh_dimensions + d) * 3
            buffer[base_idx + 0] = splats[i].get_sh_r(d)
            buffer[base_idx + 1] = splats[i].get_sh_g(d)
            buffer[base_idx + 2] = splats[i].get_sh_b(d)
            
    return buffer
```

**Parameters:**
- `shDimensions` ($D$): Calculated based on the SH degree. For degree $L$, $D = (L+1)^2$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Coefficients are typically stored as 32-bit floats. Quantization variants exist but require conversion logic [S3, unofficial].
- **Boundary:** The buffer size must be exactly $N \times D \times 3$. Any mismatch causes out-of-bounds access or uninitialized data.

## Subtopics

### Spherical Harmonics Texture Management
Stores SH coefficients in separate GPU textures keyed by block identifiers rather than a single flat buffer. This approach is used in streaming contexts where data is managed via codebooks or LOD blocks. It involves iterating over SH keys, reusing existing textures, or creating new ones if data exists and needs update [S2, unofficial].

### INT8 Spherical Harmonics
Uses 8-bit integer quantization for SH coefficients to reduce memory traffic and bandwidth usage. This variant is often employed in hardware-accelerated rendering pipelines (e.g., using Tensor Cores) to optimize front-end overhead and memory access patterns [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \times D)$ to write/read the buffer, where $N$ is the number of splats and $D$ is the number of coefficients.
- **Memory Complexity:** $O(N \times D \times 3)$ floats. For degree 1 ($D=3$), this is $9N$ floats. For degree 2 ($D=8$), this is $24N$ floats.
- **Performance:** The SoA layout ensures cache coherency during batched rendering, as shaders access contiguous memory for a single attribute [5568-splat-data-buffer-layout.md].
- **Strengths:** Simple indexing, high cache efficiency for standard rendering, easy to integrate with standard GPU buffers.
- **Limitations:** High memory bandwidth usage for high-degree SH. Not suitable for extreme compression without additional quantization steps [S3, unofficial].

## Background
This layout is a standard component of 3D Gaussian Splatting implementations, particularly those following the JSplat architecture [S1, unofficial]. It builds on the general SoA principles of the GaussianSet Data Structure family. The specific indexing formula and buffer management are derived from the JSplat library's implementation details [S1, unofficial].
