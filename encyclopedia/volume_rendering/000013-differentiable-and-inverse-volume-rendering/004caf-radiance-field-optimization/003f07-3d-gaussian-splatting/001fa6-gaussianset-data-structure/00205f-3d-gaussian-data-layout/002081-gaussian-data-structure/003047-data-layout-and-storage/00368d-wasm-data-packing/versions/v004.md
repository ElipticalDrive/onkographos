# WASM Data Packing

Also called: DataWorker Packing, Splat Buffer Allocation

## Overview
WASM Data Packing manages WebAssembly memory allocation and data packing for 3D Gaussian splat attributes (positions, rotations, scales, colors, selection) to prepare them for GPU upload or WASM-side processing [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A `Splat` object containing attribute arrays (positions, rotations, scales, colors, selection) and a `vertexCount` [S1, unofficial].
- **Output:** A contiguous block of memory in the WebAssembly heap (`HEAPF32` and `HEAPU8`) organized in a Structure-of-Arrays (SoA) layout, ready for direct memory access by WASM functions or GPU buffers [S1, unofficial].

**Data Structures:**
The `Splat` class fields include:
- `offset`: number
- `position`: `Float32Array[3]`
- `rotation`: `Float32Array[4]`
- `scale`: `Float32Array[3]`
- `selected`: boolean
- `vertexCount`: number
- `positions`: `Float32Array`
- `rotations`: `Float32Array`
- `scales`: `Float32Array`
- `colors`: `Uint8Array`
- `selection`: `Uint8Array`

**Buffer Layout and Sizes:**
The packed memory is divided into specific regions based on `allocatedVertexCount` (the next power of 2 greater than or equal to `vertexCount`) [S1, unofficial]. Each float occupies 4 bytes.

1.  **positionsPtr**: Size = $3 \times \text{allocatedVertexCount} \times 4$ bytes [S1, unofficial].
2.  **rotationsPtr**: Size = $4 \times \text{allocatedVertexCount} \times 4$ bytes [S1, unofficial].
3.  **scalesPtr**: Size = $3 \times \text{allocatedVertexCount} \times 4$ bytes [S1, unofficial].
4.  **colorsPtr**: Size = $4 \times \text{allocatedVertexCount}$ bytes [S1, unofficial].
5.  **selectionPtr**: Size = $\text{allocatedVertexCount}$ bytes [S1, unofficial].
6.  **dataPtr**: Size = $8 \times \text{allocatedVertexCount} \times 4$ bytes [S1, unofficial].
7.  **worldPositionsPtr**: Size = $3 \times 4 \times 4 = 48$ bytes [S1, unofficial].
8.  **worldRotationsPtr**: Size = $4 \times 4 \times 4 = 64$ bytes [S1, unofficial].
9.  **worldScalesPtr**: Size = $3 \times 4 \times 4 = 48$ bytes [S1, unofficial].

**Numbered Steps:**
1.  **Initialization:** Call `initWasm()`. This loads the WASM module via `createDataModule()` [S1, unofficial]. If the module is not yet loaded, `pack()` waits for loading to finish, initializes WASM, and proceeds [S1, unofficial].
2.  **Capacity Calculation:** Calculate `targetAllocatedVertexCount` as the next power of 2 greater than or equal to `splat.vertexCount`:
    $$ \text{targetAllocatedVertexCount} = 2^{\lceil \log_2(\text{splat.vertexCount}) \rceil} $$
    [S1, unofficial]
3.  **Memory Reallocation:** If `targetAllocatedVertexCount` is larger than the current `allocatedVertexCount`:
    a. Free old WASM buffers using `wasmModule._free()` [S1, unofficial].
    b. Update `allocatedVertexCount` to `targetAllocatedVertexCount` [S1, unofficial].
    c. Allocate new buffers using `wasmModule._malloc()` for each attribute region [S1, unofficial].
4.  **Data Copying:** Copy splat attribute arrays into the newly allocated WASM memory regions:
    a. Use `wasmModule.HEAPF32.set()` for float arrays (positions, rotations, scales) [S1, unofficial].
    b. Use `wasmModule.HEAPU8.set()` for byte arrays (colors, selection) [S1, unofficial].

**Pseudocode:**
```python
def pack(splat):
    # Ensure WASM module is loaded; if not, wait for initialization [S1, unofficial]
    if not wasm_module_loaded:
        # init_wasm() and wait_for_wasm_load() abstract the async module loading step [G]
        initialize_wasm_module()

    # Calculate next power of 2 capacity [S1, unofficial]
    vertex_count = splat.vertex_count
    target_capacity = 1 if vertex_count == 0 else 2 ** math.ceil(math.log2(vertex_count))

    # Check if reallocation is needed [S1, unofficial]
    if target_capacity > allocated_vertex_count:
        # Free old WASM buffers [S1, unofficial]
        if allocated_vertex_count > 0:
            wasm_module._free(positions_ptr)
            wasm_module._free(rotations_ptr)
            wasm_module._free(scales_ptr)
            wasm_module._free(colors_ptr)
            wasm_module._free(selection_ptr)
            wasm_module._free(data_ptr)
            wasm_module._free(world_positions_ptr)
            wasm_module._free(world_rotations_ptr)
            wasm_module._free(world_scales_ptr)

        # Update capacity [S1, unofficial]
        allocated_vertex_count = target_capacity

        # Allocate new buffers [S1, unofficial]
        positions_ptr = wasm_module._malloc(3 * allocated_vertex_count * 4)
        rotations_ptr = wasm_module._malloc(4 * allocated_vertex_count * 4)
        scales_ptr = wasm_module._malloc(3 * allocated_vertex_count * 4)
        colors_ptr = wasm_module._malloc(4 * allocated_vertex_count)
        selection_ptr = wasm_module._malloc(allocated_vertex_count)
        data_ptr = wasm_module._malloc(8 * allocated_vertex_count * 4)
        world_positions_ptr = wasm_module._malloc(48)
        world_rotations_ptr = wasm_module._malloc(64)
        world_scales_ptr = wasm_module._malloc(48)

    # Copy data into WASM heap [S1, unofficial]
    # HEAPF32.set expects offset in 32-bit elements
    wasm_module.HEAPF32.set(splat.positions, positions_ptr // 4)
    wasm_module.HEAPF32.set(splat.rotations, rotations_ptr // 4)
    wasm_module.HEAPF32.set(splat.scales, scales_ptr // 4)
    # HEAPU8.set expects offset in bytes
    wasm_module.HEAPU8.set(splat.colors, colors_ptr)
    wasm_module.HEAPU8.set(splat.selection, selection_ptr)

    # world_* pointers are allocated but population logic is not specified in the source [G]
```

**Parameters:**
- `positionsPtr`: allocated size = $3 \times \text{allocatedVertexCount} \times 4$ bytes [S1, unofficial].
- `rotationsPtr`: allocated size = $4 \times \text{allocatedVertexCount} \times 4$ bytes [S1, unofficial].
- `scalesPtr`: allocated size = $3 \times \text{allocatedVertexCount} \times 4$ bytes [S1, unofficial].
- `colorsPtr`: allocated size = $4 \times \text{allocatedVertexCount}$ bytes [S1, unofficial].
- `selectionPtr`: allocated size = $\text{allocatedVertexCount}$ bytes [S1, unofficial].
- `dataPtr`: allocated size = $8 \times \text{allocatedVertexCount} \times 4$ bytes [S1, unofficial].
- `worldPositionsPtr`: allocated size = 48 bytes [S1, unofficial].
- `worldRotationsPtr`: allocated size = 64 bytes [S1, unofficial].
- `worldScalesPtr`: allocated size = 48 bytes [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Concurrent Calls:** Concurrent calls to `pack()` are serialized via a loading flag and a `while` loop with `setTimeout` to yield to the event loop, preventing race conditions during WASM initialization [S1, unofficial].
- **Memory Efficiency:** Memory is only freed and reallocated when the next power-of-2 capacity exceeds the current `allocatedVertexCount`, preventing frequent reallocations for incremental vertex count changes [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Strengths:** Reduces JavaScript-to-GPU transfer overhead by pre-packaging data in a contiguous WASM heap. Power-of-2 allocation minimizes fragmentation and reallocation frequency. [G]
- **Limitations:** Requires WebAssembly environment. Power-of-2 allocation can lead to memory waste if the vertex count is not a power of 2. [S1, unofficial]
- **When to use:** When rendering 3D Gaussian Splats in a WebAssembly-based environment where data needs to be prepared for GPU upload or WASM-side processing. [S1, unofficial]
- **When not to use:** In pure CPU-based rendering or environments without WebAssembly support. [G]

## Background
WASM Data Packing is part of the `gsplat.js` library, which provides JavaScript/TypeScript bindings for 3D Gaussian Splatting. It was developed to enable efficient rendering of Gaussian Splats in web browsers using WebAssembly [S1, unofficial].
