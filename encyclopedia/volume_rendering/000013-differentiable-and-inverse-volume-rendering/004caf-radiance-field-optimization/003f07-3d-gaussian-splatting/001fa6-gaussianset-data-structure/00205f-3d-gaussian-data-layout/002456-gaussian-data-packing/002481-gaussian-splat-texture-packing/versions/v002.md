# Gaussian Splat Texture Packing

Also called: Texture Packing

## Overview
Gaussian Splat Texture Packing is a method for storing 3D Gaussian Splat attributes in a 2D OpenGL texture to facilitate efficient GPU-side access during rasterization. It solves the problem of transferring large volumes of Gaussian data from CPU memory to the GPU by packing 8 bytes of Gaussian data into pairs of RGBA32UI texels. It is distinguished from [SPZ Packed Format](3926-spz-packed-format.md) by its use of a standard 2D texture array with specific integer packing, and from [PNG-based Gaussian Compression](4834-png-based-gaussian-compression.md) by its uncompressed, direct-memory-mapping approach.

## How it works
**Inputs:** A flat array of Gaussian data (`packedData`) containing 8 bytes per Gaussian, and the total number of Gaussians (`splatCount`).
**Outputs:** An OpenGL 2D texture (`splatTexture`) containing the packed data.

**Data Structures:**
*   `packedData`: `std::vector<uint8_t>` or equivalent buffer. Size is `splatCount * 8` bytes.
*   `splatTexture`: OpenGL texture object.
    *   Format: `GL_RGBA32UI`
    *   Internal Format: `GL_RGBA_INTEGER`
    *   Data Type: `GL_UNSIGNED_INT`
    *   Dimensions: `width = 2048`, `height = ceil(splatCount / 1024)`
    *   Filters: `GL_NEAREST` for minification and magnification.
    *   Wrap Mode: `GL_CLAMP_TO_EDGE` for both S and T axes.

**Layout:**
Each Gaussian occupies 2 horizontal columns in the texture (2 `uvec4` texels).
*   The x-coordinate (column) for Gaussian index `i` is `(i & 0x3FF) << 1`. This places 1024 Gaussians per row.
*   The y-coordinate (row) for Gaussian index `i` is `i >> 10`.

**Steps:**
1.  Calculate texture dimensions:
    $$ \text{textureWidth} = 2048 $$
    $$ \text{textureHeight} = \lceil \frac{\text{splatCount}}{1024} \rceil $$
2.  Create the OpenGL texture with the specified format and dimensions.
3.  For each Gaussian $i$ from $0$ to $\text{splatCount} - 1$:
    a. Compute row and column indices:
       $$ \text{row} = \lfloor i / 1024 \rfloor $$
       $$ \text{col} = (i \pmod{1024}) \times 2 $$
    b. Calculate texture data indices for the two texels:
       $$ \text{idx1} = (\text{row} \times \text{textureWidth} + \text{col}) \times 4 $$
       $$ \text{idx2} = (\text{row} \times \text{textureWidth} + \text{col} + 1) \times 4 $$
    c. Copy the first 4 bytes of the Gaussian data to the first texel:
       $$ \text{textureData}[\text{idx1} \dots \text{idx1}+3] = \text{packedData}[i \times 8 \dots i \times 8 + 3] $$
    d. Copy the next 4 bytes of the Gaussian data to the second texel:
       $$ \text{textureData}[\text{idx2} \dots \text{idx2}+3] = \text{packedData}[i \times 8 + 4 \dots i \times 8 + 7] $$

**Pseudocode:**
```python
def pack_gaussians_to_texture(packed_data: list[int], splat_count: int) -> list[int]:
    """
    Packs Gaussian data into a 2D texture layout.
    
    Args:
        packed_data: Flat list of uint8 values, 8 bytes per Gaussian.
        splat_count: Number of Gaussians.
        
    Returns:
        List of uint32 values representing the texture data (RGBA32UI).
    """
    texture_width = 2048
    texture_height = (splat_count + 1023) // 1024  # ceil(splat_count / 1024)
    
    # Total texels = width * height
    # Each texel is 4 uint32s (RGBA)
    total_texels = texture_width * texture_height
    texture_data = [0] * (total_texels * 4)
    
    for i in range(splat_count):
        # Calculate row and column
        row = i // 1024
        col = (i % 1024) * 2
        
        # Calculate indices in the flat texture_data array
        # Each texel has 4 components (R, G, B, A)
        idx1 = (row * texture_width + col) * 4
        idx2 = (row * texture_width + col + 1) * 4
        
        # Source indices in packed_data (8 bytes per Gaussian)
        src_idx = i * 8
        
        # Copy first 4 bytes to first texel
        texture_data[idx1] = packed_data[src_idx]
        texture_data[idx1 + 1] = packed_data[src_idx + 1]
        texture_data[idx1 + 2] = packed_data[src_idx + 2]
        texture_data[idx1 + 3] = packed_data[src_idx + 3]
        
        # Copy next 4 bytes to second texel
        texture_data[idx2] = packed_data[src_idx + 4]
        texture_data[idx2 + 1] = packed_data[src_idx + 5]
        texture_data[idx2 + 2] = packed_data[src_idx + 6]
        texture_data[idx2 + 3] = packed_data[src_idx + 7]
        
    return texture_data
```

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** If `splatCount` is not a multiple of 1024, the last row of the texture will contain unused texels. These should be initialized to zero or ignored during unpacking [S1, unofficial].
*   **Precision:** The use of `GL_RGBA32UI` ensures no precision loss for integer-packed data. If floating-point data is packed, it must be converted to integers or a different texture format used [S1, unofficial].
*   **Alignment:** The layout assumes 4-byte alignment for `packedData` entries. Ensure the source data is properly aligned [S1, unofficial].

## Subtopics

### [Packed Splat Reading](6819-packed-splat-reading.md)
Decodes a single Gaussian from the packed texture. It is the primary accessor for this layout, distinguishing itself by using a single texture array and specific unpacking for standard spherical harmonics or color data.

## Operating characteristics
*   **Time Complexity:** Packing is $O(N)$ where $N$ is the number of Gaussians, as each Gaussian requires a constant number of memory copies.
*   **Memory Complexity:** The texture size is $O(N)$, specifically $2048 \times \lceil N/1024 \rceil$ texels. Each texel is 16 bytes (4 uint32s), so total memory is $16 \times 2048 \times \lceil N/1024 \rceil$ bytes.
*   **Performance:** This method allows for efficient GPU-side access during rasterization, as the texture can be sampled directly in shaders. It avoids the overhead of complex decompression algorithms used in compressed formats [S1, unofficial].
*   **Strengths:** Simple implementation, fast packing/unpacking, compatible with standard OpenGL texture sampling.
*   **Limitations:** Uncompressed, so it does not reduce memory footprint compared to raw data. The fixed texture width of 2048 may lead to wasted space for small scenes [S1, unofficial].
*   **When to Use:** When GPU-side access to Gaussian data is required and memory bandwidth is not the primary bottleneck.
*   **When Not to Use:** When memory footprint is critical, consider [PNG-based Gaussian Compression](4834-png-based-gaussian-compression.md) or [SPZ Packed Format](3926-spz-packed-format.md) if they offer better compression or compatibility.

## Background
This method is derived from the `gsplat-opengl` project, an unofficial implementation of 3D Gaussian Splatting in OpenGL [S1, unofficial]. It provides a straightforward way to transfer Gaussian data to the GPU for rendering.
