# Gaussian Splat Texture Packing

Also called: Texture Packing

## Overview
Gaussian Splat Texture Packing is a method for storing 3D Gaussian Splat attributes in a 2D OpenGL texture to facilitate efficient GPU-side access during rasterization. It solves the problem of transferring large sets of Gaussian parameters from CPU memory to the GPU by packing 8-byte chunks of Gaussian data into a `GL_RGBA32UI` texture. It differs from sibling methods like [SPZ Packed Format](3926-spz-packed-format.md) by using a specific row-major texture layout with a fixed width of 1024 Gaussians per row, whereas [PNG-based Gaussian Compression](4834-png-based-gaussian-compression.md) uses lossy image compression.

## How it works
**Inputs and Outputs:**
- Input: A contiguous array of packed Gaussian data (`packedData`), where each Gaussian consists of 8 `uint32_t` values (32 bytes total, though only 8 `uint32_t` indices are used for packing logic in the source, implying the data is pre-packed into 32-bit chunks or the source describes a specific 8-uint32 representation). The source code implies `packedData` is a `std::vector<uint32_t>` or similar.
- Output: An OpenGL texture (`splatTexture`) of type `GL_RGBA32UI`.

**Data Structures:**
- **Texture Format:** `GL_RGBA32UI` (internal format), `GL_RGBA_INTEGER` (type), `GL_UNSIGNED_INT` (data type).
- **Texture Dimensions:**
  - Width: 2048 pixels.
  - Height: $\lceil \text{splatCount} / 1024 \rceil$ pixels.
- **Layout Mapping:**
  - Each Gaussian $i$ occupies 2 horizontal columns in the texture (2 `uvec4` elements).
  - The x-coordinate (column index in pixels) for Gaussian $i$ is $(i \pmod{1024}) \times 2$.
  - The y-coordinate (row index in pixels) for Gaussian $i$ is $\lfloor i / 1024 \rfloor$.
  - Each Gaussian's 8 `uint32_t` values are stored as two `uvec4` components.

**Numbered Steps:**
1. Initialize the texture with dimensions `width = 2048` and `height = ceil(splatCount / 1024)`.
2. Set texture filtering to `GL_NEAREST` for both minification and magnification.
3. Set texture wrap mode to `GL_CLAMP_TO_EDGE` for both S and T axes.
4. For each Gaussian index $i$ from $0$ to $\text{splatCount} - 1$:
   a. Calculate the row index: $r = \lfloor i / 1024 \rfloor$.
   b. Calculate the base column index: $c = (i \pmod{1024}) \times 2$.
   c. Calculate the texture data indices for the two `uvec4` components:
      - $idx_1 = (r \times \text{textureWidth} + c) \times 4$
      - $idx_2 = (r \times \text{textureWidth} + c + 1) \times 4$
   d. Copy the first 4 `uint32_t` values from `packedData` starting at offset $i \times 8$ to `textureData` at $idx_1$:
      - `textureData[idx1..idx1+3] = packedData[i*8..i*8+3]`
   e. Copy the next 4 `uint32_t` values from `packedData` starting at offset $i \times 8 + 4$ to `textureData` at $idx_2$:
      - `textureData[idx2..idx2+3] = packedData[i*8+4..i*8+7]`

**Pseudocode:**
```python
def pack_gaussians_to_texture(packed_data: list, splat_count: int) -> list:
    """
    Packs Gaussian data into a 2D texture array represented as a flat list.
    
    Args:
        packed_data: List of uint32_t values representing Gaussian attributes.
                     Each Gaussian is 8 uint32_t values.
        splat_count: Number of Gaussians.
        
    Returns:
        texture_data: List of uint32_t values representing the RGBA32UI texture.
    """
    texture_width = 2048
    texture_height = (splat_count + 1023) // 1024  # ceil(splat_count / 1024)
    texture_size = texture_width * texture_height * 4  # 4 components per pixel
    
    texture_data = [0] * texture_size
    
    for i in range(splat_count):
        row = i // 1024
        col = (i % 1024) * 2
        
        idx1 = (row * texture_width + col) * 4
        idx2 = (row * texture_width + col + 1) * 4
        
        # Copy first 4 uint32_t values
        for k in range(4):
            texture_data[idx1 + k] = packed_data[i * 8 + k]
            
        # Copy next 4 uint32_t values
        for k in range(4):
            texture_data[idx2 + k] = packed_data[i * 8 + 4 + k]
            
    return texture_data
```

**Parameters:**
- `textureWidth`: 2048 (fixed).
- `textureHeight`: $\lceil \text{splatCount} / 1024 \rceil$.
- `minFilter`: `GL_NEAREST`.
- `magFilter`: `GL_NEAREST`.
- `wrapS`: `GL_CLAMP_TO_EDGE`.
- `wrapT`: `GL_CLAMP_TO_EDGE`.

**Edge Cases and Pitfalls:**
- **Precision:** The use of `GL_RGBA32UI` ensures no precision loss for integer attributes. If floating-point attributes are packed, they must be converted to integers or a different texture format used.
- **Boundaries:** The texture height is calculated to fit all Gaussians. Accessing Gaussians beyond `splatCount` should be handled by the reader, as the texture may contain padding.
- **Degenerate Input:** If `splatCount` is 0, the texture height is 0, and no data is copied.

## Operating characteristics
- **Time Complexity:** $O(N)$ for packing, where $N$ is the number of Gaussians.
- **Memory Complexity:** $O(N)$ for the texture storage.
- **Measured Performance:** Not given in the sources.
- **Scaling:** The fixed width of 1024 Gaussians per row limits the texture height. For very large scenes, the texture height increases linearly.
- **Strengths:** Efficient GPU access via texture sampling; simple mapping logic.
- **Limitations:** Fixed width may lead to inefficient memory usage for small numbers of Gaussians; requires OpenGL support for `GL_RGBA32UI`.
- **When to use:** When rendering on OpenGL-based systems and efficient GPU-side access is required.
- **When not:** When using Vulkan or DirectX, or when memory efficiency is critical and a more compact format is needed.
