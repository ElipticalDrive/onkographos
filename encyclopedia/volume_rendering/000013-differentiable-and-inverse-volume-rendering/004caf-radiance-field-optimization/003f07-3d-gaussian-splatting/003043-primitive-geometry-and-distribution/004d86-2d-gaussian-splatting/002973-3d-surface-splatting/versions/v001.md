# 3D Surface Splatting

Also called: 3DSS

## Overview
3D Surface Splatting (3DSS) is a differentiable surface splatting renderer for physically-based inverse rendering that jointly recovers geometry, materials, and illumination from multi-view images by optimizing an unstructured set of oriented surfel primitives [S1, unofficial]. It solves the problem of visibility discontinuity in surface splatting by replacing hard depth tests with a multi-layer interval merging algorithm, allowing arbitrary surface layers per pixel to be composited independently [S1, unofficial]. Unlike its parent [2D Gaussian Splatting](1456-2d-gaussian-splatting.md), which retains a volumetric rendering model with learnable opacity, 3DSS uses a surface rendering model where pixel coverage arises from accumulated EWA reconstruction weights within depth-separated layers, and shading is evaluated at the sample level before blending [S1, unofficial].

## How it works
**Inputs:** An unstructured set of surfel primitives, each defined by center position $\mathbf{c} \in \mathbb{R}^3$, tangent vectors $\mathbf{t}_u, \mathbf{t}_v \in \mathbb{R}^3$, and shading attributes (albedo $\mathbf{a} \in [0, 1]^3$, metallic $m \in [0, 1]$, roughness $r \in [0, 1]$). A camera projection matrix $P$ and an HDR environment map for lighting.
**Outputs:** A composited HDR image and differentiable gradients for optimization.

**Data Structures:**
*   **Surfel:** A struct containing:
    *   `c`: `vec3` center position.
    *   `t_u`, `t_v`: `vec3` tangent vectors (camera-space).
    *   `a`: `vec3` albedo.
    *   `m`: `float` metallic.
    *   `r`: `float` roughness.
    *   `c_pre`: `vec3` pre-shaded linear radiance (computed in preprocessing).
    *   `d`: `float` view-space depth of center.
    *   `delta`: `float` symmetric depth extent.
    *   `T`: `mat4` T-matrix (local to clip space).
    *   `bbox`: `Rect` clip-space bounding rectangle.
    *   `d_start`: `float` depth interval start ($d - \delta$).

**Parameters:**
*   $\delta_{cut}$: Kernel support cutoff radius. Typical value: Not given in the sources.
*   $\delta$: Symmetric depth extent, computed as $\delta = \sqrt{t'_{u,z}^2 + t'_{v,z}^2} \cdot \delta_{cut}$, where $t'_{u,z}$ and $t'_{v,z}$ are the z-components (view-space depth) of the camera-space tangent vectors [S1, unofficial].

**Steps:**

1.  **Preprocessing (T-matrix and Shading):**
    For each surfel:
    a. Transform $\mathbf{c}, \mathbf{t}_u, \mathbf{t}_v$ to camera space to get $\mathbf{c}', \mathbf{t}'_u, \mathbf{t}'_v$.
    b. Construct the transformation matrix $S = [\mathbf{t}'_u, \mathbf{t}'_v, \mathbf{0}, \mathbf{c}']$ (4x4).
    c. Compute $T = P S$, mapping local surfel space to clip space [S1, unofficial].
    d. Compute bounding rectangle of the surfel in clip space using closed-form expressions involving dot products of $T$'s rows [S1, unofficial].
    e. Compute view-space depth $d$ of $\mathbf{c}'$ and symmetric extent $\delta$.
    f. Compute $d_{start} = d - \delta$.
    g. Shade the surfel using forward microfacet shading against the HDR environment map to obtain pre-shaded radiance $\mathbf{c}_{pre}$ [S1, unofficial].

2.  **Tiling and Sorting:**
    a. Bin surfels into screen-space tiles based on their bounding rectangles.
    b. Within each tile, sort surfels by $d_{start}$ in ascending order [S1, unofficial].

3.  **Per-Pixel Rasterization (for each pixel in each tile):**
    a. Initialize an empty list of surface layers. Each layer stores a list of covering surfels.
    b. For each surfel $i$ in the sorted tile:
        i. **Ray-Surfel Intersection:**
           Represent the pixel's viewing ray as the intersection of two clip-space planes: $\mathbf{h}_u = (-1, 0, 0, u)^T$ and $\mathbf{h}_v = (0, -1, 0, v)^T$, where $(u, v)$ are pixel coordinates [S1, unofficial].
           Map these planes into the surfel's local coordinate system via $T$ to yield vectors $\mathbf{k}$ and $\mathbf{l}$.
           Compute the intersection of $\mathbf{k}$ and $\mathbf{l}$ with the surfel's plane to get local coordinates $(u_{loc}, v_{loc})$ [S1, unofficial].
        ii. **Discard Check:**
           Compute squared distance $\rho^2 = u_{loc}^2 + v_{loc}^2$.
           If $\rho^2 \ge \delta_{cut}^2$, discard the surfel for this pixel [S1, unofficial].
        iii. **Weight Computation:**
           Compute unnormalized Gaussian weight $w = \exp(-\frac{1}{2} \rho^2)$ [S1, unofficial].
        iv. **Surface Layer Grouping (Interval Merging):**
           Compute the surfel's depth interval $[d - \delta, d + \delta]$.
           Check if this interval overlaps with the depth interval of the last surfel added to the current active surface layer.
           - If it overlaps, add surfel $i$ to the current surface layer.
           - If it does not overlap, start a new surface layer containing surfel $i$.
           *Note:* Because surfels are sorted by $d_{start}$, if the current surfel's interval does not overlap the running group, no future primitive can bridge the gap [S1, unofficial].
    c. **Attribute Accumulation and Compositing:**
       For each surface layer:
       i. Compute the reconstructed attribute $\hat{\mathbf{a}}$ for the layer by Shepard normalization:
          $$ \hat{\mathbf{a}} = \frac{\sum_{k \in \text{layer}} w_k \mathbf{c}_{pre, k}}{\sum_{k \in \text{layer}} w_k} $$
          where the sum runs over all surfels $k$ in the layer that cover the pixel [S1, unofficial].
       ii. Compute the layer's opacity $\alpha_{layer}$ from the accumulated weight:
           $$ \alpha_{layer} = \frac{\sum_{k \in \text{layer}} w_k}{\sum_{k \in \text{layer}} w_k + \epsilon} $$
           (Note: The source states opacity arises directly from accumulated EWA weight, but does not give the exact normalization formula for opacity vs. attribute. It implies the weight sum drives the coverage. We assume standard alpha compositing uses this weight-derived alpha). [G: Standard alpha compositing requires a normalized alpha. The source says "per-layer opacity arises directly from the accumulated EWA reconstruction weight". We use the sum of weights as the basis for alpha, likely normalized by a maximum or simply used as the alpha value if weights are bounded. Given the omission of the constant in Eq 2, we assume the raw weight sum is used as the alpha contribution, or normalized by the max possible weight. However, Eq 3 normalizes attributes. For compositing, we need $\alpha$. The source says "coverage-based differentiable compositing... per-layer opacity arises directly from the accumulated EWA reconstruction weight".        iii. Composite the layer's color $\hat{\mathbf{a}}$ and opacity $\alpha_{layer}$ into the pixel buffer using the over operator, front-to-back across layers [S1, unofficial].

**Pseudocode:**

```python
import math

def render_3dss(surfels, P, env_map):
    """
    Render a scene using 3D Surface Splatting.
    surfels: List of Surfel objects.
    P: Camera projection matrix (4x4).
    env_map: HDR environment map for lighting.
    """
    # Preprocessing
    for surfel in surfels:
        # Transform to camera space
        c_cam = transform_to_camera(surfel.c)
        tu_cam = transform_vector_to_camera(surfel.t_u)
        tv_cam = transform_vector_to_camera(surfel.t_v)
        
        # T-matrix construction
        # S = [tu_cam, tv_cam, 0, c_cam] as columns
        S = mat4(tu_cam, tv_cam, vec4(0,0,0,1), c_cam)
        surfel.T = P @ S
        
        # Bounding rectangle and depth extent
        surfel.bbox = compute_clip_space_bbox(surfel.T)
        delta_u_z = tu_cam.z
        delta_v_z = tv_cam.z
        # delta = sqrt(tu_z^2 + tv_z^2) * delta_cut
        # delta_cut is a parameter, assumed known
        surfel.delta = math.sqrt(delta_u_z**2 + delta_v_z**2) * delta_cut
        surfel.d = c_cam.z
        surfel.d_start = surfel.d - surfel.delta
        
        # Forward shading
        surfel.c_pre = shade_microfacet(surfel, env_map)

    # Tiling and Sorting
    tiles = bin_into_tiles(surfels)
    for tile in tiles:
        tile.sort(key=lambda s: s.d_start)

    # Rasterization
    image = zeros(image_width, image_height, 3)
    
    for tile in tiles:
        for pixel_u in range(tile.min_u, tile.max_u):
            for pixel_v in range(tile.min_v, tile.max_v):
                layers = [] # List of lists of (weight, color)
                
                for surfel in tile:
                    if not surfel.bbox.contains(pixel_u, pixel_v):
                        continue
                    
                    # Ray-Surfel Intersection
                    # h_u = (-1, 0, 0, u), h_v = (0, -1, 0, v)
                    h_u = vec4(-1, 0, 0, pixel_u)
                    h_v = vec4(0, -1, 0, pixel_v)
                    
                    # Map to local space via T
                    # T maps local to clip. We need clip to local.
                    # T_inv = inverse(T)
                    # k = T_inv * h_u, l = T_inv * h_v
                    T_inv = inverse(surfel.T)
                    k = T_inv @ h_u
                    l = T_inv @ h_v
                    
                    # Intersection with surfel plane (z=0 in local space, w=1)
                    # The surfel is a disc in the plane spanned by t'_u, t'_v at c'
                    # In local space, the plane is z=0.
                    # We need to find the intersection of the ray defined by k and l with z=0.
                    # This is a bit complex. The source says: "intersection with the surfel's plane gives local coordinates (u, v)"
                    # Let's assume the standard T-matrix intersection method.
                    # The ray in local space is defined by the intersection of the two planes.
                    # The hit point in local space (u_loc, v_loc, 0) satisfies:
                    # k.x * u_loc + k.y * v_loc + k.w = 0 ? No, planes are in clip space.
                    # Let's use the standard approach:
                    # The intersection point in clip space is found by solving for the ray.
                    # Then transform to local.
                    # Or, as per source: "Map planes h_u and h_v into the surfel's local coordinate system via T to yield vectors k and l."
                    # This implies k and l are the transformed planes.
                    # The intersection of the two planes in local space is the hit point.
                    # Plane equation: k.x * x + k.y * y + k.z * z + k.w = 0
                    # We want z=0.
                    # k.x * u + k.y * v + k.w = 0
                    # l.x * u + l.y * v + l.w = 0
                    # Solve for u, v.
                    
                    # Solve 2x2 system
                    # k.x * u + k.y * v = -k.w
                    # l.x * u + l.y * v = -l.w
                    det = k.x * l.y - k.y * l.x
                    if abs(det) < 1e-6:
                        continue # Parallel planes, no intersection
                    
                    u_loc = (l.y * (-k.w) - k.y * (-l.w)) / det
                    v_loc = (k.x * (-l.w) - (-k.w) * l.x) / det
                    
                    # Discard check
                    rho2 = u_loc**2 + v_loc**2
                    if rho2 >= delta_cut**2:
                        continue
                    
                    # Weight
                    w = math.exp(-0.5 * rho2)
                    
                    # Surface Layer Grouping
                    # Depth interval [d - delta, d + delta]
                    d_min = surfel.d - surfel.delta
                    d_max = surfel.d + surfel.delta
                    
                    # Find the last layer
                    if layers:
                        last_layer = layers[-1]
                        last_d_max = last_layer['d_max']
                        if d_min <= last_d_max:
                            # Overlap, add to last layer
                            last_layer['weights'].append(w)
                            last_layer['colors'].append(surfel.c_pre)
                            last_layer['d_max'] = max(last_d_max, d_max)
                            continue
                        else:
                            # Gap, start new layer
                            layers.append({
                                'weights': [w],
                                'colors': [surfels.c_pre],
                                'd_max': d_max
                            })
                    else:
                        layers.append({
                            'weights': [w],
                            'colors': [surfels.c_pre],
                            'd_max': d_max
                        })
                
                # Compositing
                alpha_accum = 0.0
                color_accum = vec3(0, 0, 0)
                
                for layer in layers:
                    w_sum = sum(layer['weights'])
                    if w_sum == 0:
                        continue
                    
                    # Attribute accumulation
                    color_sum = sum(w * c for w, c in zip(layer['weights'], layer['colors']))
                    layer_color = color_sum / w_sum
                    
                    # Opacity from weight
                    # Source: "per-layer opacity arises directly from the accumulated EWA reconstruction weight"
                    # We assume alpha = w_sum, possibly normalized.
                    # If weights are not normalized, alpha might exceed 1.
                    # We clamp or normalize. Let's assume the renderer handles it.
                    # For implementation, we use w_sum as alpha.
                    alpha_layer = w_sum 
                    
                    # Porter-Duff Over
                    # C_out = C_layer * alpha_layer + C_accum * (1 - alpha_layer)
                    # But alpha_layer might be > 1.
                    # Standard alpha compositing assumes alpha in [0,1].
                    # If weights are large, we might need to normalize.
                    # The source does not specify normalization for alpha.
                    # We will use alpha_layer = min(w_sum, 1.0) as a safe guard [G]
                    alpha_layer = min(alpha_layer, 1.0)
                    
                    color_accum = layer_color * alpha_layer + color_accum * (1.0 - alpha_layer)
                    alpha_accum += alpha_layer * (1.0 - alpha_accum) # Not used for color, but for transparency
                    
                image[pixel_v, pixel_u] = color_accum

    return image
```

## Subtopics

### [3D Surface Splatting Rasterization](4751-3d-surface-splatting-rasterization.md)
This method is the per-pixel rasterization kernel for 3D Surface Splatting (3DSS), designed to resolve self-occlusion errors at high-curvature concavities by grouping overlapping surfels into distinct surface layers based on depth-interval gaps. Unlike single-layer approaches or classical A-buffers that gather contributions across all depths, it partitions primitives into arbitrary surface groups, allowing multiple surface sheets to be composited independently per pixel.

## Operating characteristics
**Time Complexity:** Linear in the number of surfels and pixels, with overhead from sorting and interval merging. The interval merging is exact and requires no look-ahead, making it efficient [S1, unofficial].
**Memory Complexity:** Linear in the number of surfels. Requires storage for T-matrices, bounding boxes, and pre-shaded colors [S1, unofficial].
**Strengths:** Supports arbitrary number of surface layers per pixel; differentiable visibility; anti-aliased silhouettes; natively compatible with mesh reconstruction (e.g., Screened Poisson Surface Reconstruction) [S1, unofficial].
**Limitations:** Requires forward shading before rasterization, which may be memory-intensive for large environments; interval merging logic is specific to surface splatting and not directly applicable to volumetric methods [S1, unofficial].
**When to use:** Physically-based inverse rendering where geometry, materials, and illumination need to be recovered jointly from multi-view images, especially when multiple surfaces overlap [S1, unofficial].
**When not to use:** When a volumetric representation is preferred, or when real-time rendering with simple opacity is sufficient [S1, unofficial].

## Background
3D Surface Splatting (3DSS) was introduced by Mae Younes in 2026 as the first differentiable surface splatting renderer for physically-based inverse rendering [S1, unofficial]. It builds on the classical EWA surface splatting framework by Zwicker et al. [2001] and addresses the visibility discontinuity problem that has hindered differentiable surface splatting. It differs from prior differentiable surface splatting (DSS) by addressing visibility at the surface layer level rather than the primitive level [S1, unofficial].
