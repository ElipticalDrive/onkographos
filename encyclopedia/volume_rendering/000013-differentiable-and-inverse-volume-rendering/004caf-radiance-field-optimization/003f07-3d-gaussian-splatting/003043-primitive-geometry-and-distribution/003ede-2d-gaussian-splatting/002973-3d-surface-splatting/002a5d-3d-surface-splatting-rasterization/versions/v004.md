# 3D Surface Splatting Rasterization

Also called: 3DSS rasterization, Depth-Interval Grouping, Interval-based surface separation, Multi-layer interval grouping, Per-pixel rasterization with depth-interval grouping

## Overview
This method is the rasterization core of 3D Surface Splatting (3DSS), designed to render an unstructured set of oriented surfel primitives into a 2D image while correctly handling self-occlusion at concavities [S1, unofficial]. It solves the problem where single-layer rasterization approaches fail to distinguish between geometrically distinct surface sheets that project onto the same pixel, resulting in holes or translucent artifacts in high-curvature regions like ears or under chins [S1, unofficial]. It sets itself apart from classical A-buffer approaches by restricting summation to surfels within the same depth-interval layer rather than gathering across all depths, and from single-layer ternary depth tests by detecting gaps in the depth-interval chain to support an arbitrary number of surface layers per pixel [S1, unofficial].

## How it works
The algorithm processes surfels that have already been shaded via split-sum Image-Based Lighting (IBL) against a co-optimized HDR environment, yielding a pre-shaded linear radiance $\mathbf{c}_i$ [S1, unofficial]. The rasterization proceeds in three main phases: tiling and sorting, per-pixel interval grouping, and front-to-back compositing [S1, unofficial].

### Inputs and Outputs
**Inputs:**
- A set of surfels $\mathcal{S}$, each with position $\mathbf{p}_i$, orientation, size, and pre-shaded color $\mathbf{c}_i$ [S1, unofficial].
- Camera parameters (view/projection matrices) to compute screen-space positions and depth intervals [S1, unofficial].
- Kernel cutoff radius $r_{\text{cut}}$ [S1, unofficial].
- Half-thickness parameter $\varepsilon_z^{(i)}$ for each surfel, defining the depth interval extent [S1, unofficial].

**Outputs:**
- A composited HDR image [S1, unofficial].
- Gradients flowing back to surfel parameters and the environment map [S1, unofficial].

### Data Structures
- **Screen-space tiles:** Surfels are binned into tiles based on their screen-space bounding boxes [S1, unofficial].
- **Sorted primitive sequence:** Within each tile, surfels are radix-sorted by their depth-interval start value $z_{\text{start}}^{(i)}$ [S1, unofficial].
- **Per-pixel accumulators:** For each pixel, the algorithm maintains:
  - $\mathbf{C}_g$: Accumulated color for the current surface group $g$ [S1, unofficial].
  - $W_g$: Accumulated weight for the current surface group $g$ [S1, unofficial].
  - $z_{\text{end}}^{\max}$: The farthest depth extent encountered so far in the current group [S1, unofficial].

### Numbered Steps

1.  **Tiling and Sorting:** Bin surfels into screen-space tiles. Radix-sort the surfels within each tile by $z_{\text{start}}^{(i)}$ [S1, unofficial].
2.  **Per-Pixel Initialization:** For each pixel, initialize group accumulators $\mathbf{C}_g \leftarrow \mathbf{0}$, $W_g \leftarrow 0$, and $z_{\text{end}}^{\max} \leftarrow 0$ [S1, unofficial].
3.  **Iterate Surfels:** For each surfel $i$ in the sorted sequence:
    a.  **Intersection:** Compute the ray-surfel intersection to obtain local coordinates $(u, v)$ [S1, unofficial].
    b.  **Weight Evaluation:** Calculate the MIP-filtered squared distance $\rho_{\text{mip}}^2$ using the precomputed inverse covariance $\Sigma_{\text{mip}}^{-1}$ [S1, unofficial].
    c.  **Culling:** If $\rho_{\text{mip}}^2 \geq r_{\text{cut}}^2$, the surfel does not cover this pixel; skip to the next surfel [S1, unofficial].
    d.  **Weight Calculation:** Compute the scalar weight $w = n_f \cdot \exp(-\frac{1}{2} \rho_{\text{mip}}^2)$ [S1, unofficial].
    e.  **Depth Interval:** Define the depth interval $[z_{\text{start}}^{(i)}, z_{\text{end}}^{(i)}]$ where $z_{\text{start}}^{(i)} = z^{(i)} - \varepsilon_z^{(i)}$ and $z_{\text{end}}^{(i)} = z^{(i)} + \varepsilon_z^{(i)}$ [S1, unofficial].
    f.  **Gap Detection:** If $W_g > 0$ AND $z_{\text{start}}^{(i)} > z_{\text{end}}^{\max}$, a gap is detected between the current surfel and the accumulated group [S1, unofficial].
        i.  Finalize the current layer by calling `FLUSHLAYER($\mathbf{C}_g, W_g$)` [S1, unofficial].
        ii. Reset accumulators: $\mathbf{C}_g \leftarrow \mathbf{0}$, $W_g \leftarrow 0$, $z_{\text{end}}^{\max} \leftarrow 0$ [S1, unofficial].
    g.  **Update Extent:** Update the group's farthest extent: $z_{\text{end}}^{\max} \leftarrow \max(z_{\text{end}}^{\max}, z_{\text{end}}^{(i)})$ [S1, unofficial].
    h.  **Accumulate:** Add the surfel's contribution to the current group: $\mathbf{C}_g \leftarrow \mathbf{C}_g + w \cdot \mathbf{c}_i$ and $W_g \leftarrow W_g + w$ [S1, unofficial].
4.  **Finalize Last Layer:** After processing all surfels for a pixel, if $W_g > 0$, call `FLUSHLAYER($\mathbf{C}_g, W_g$)` to finalize the last accumulated group [S1, unofficial].
5.  **Shepard Normalization:** For each finalized surface group, normalize the accumulated color by its weight to obtain the layer color: $\mathbf{C}_{\text{layer}} = \mathbf{C}_g / W_g$ [S1, unofficial].
6.  **Coverage Opacity:** Compute the coverage opacity $\alpha_{\text{layer}}$ for each layer from the accumulated weight $W_g$ using a smooth, monotonically increasing mapping [S1, unofficial]. This replaces threshold-based clamping used in classical A-buffers [S1, unofficial].
7.  **Front-to-Back Compositing:** Composite the resulting layers front-to-back using the computed coverages and opacities to produce the final pixel color [S1, unofficial].
8.  **Post-Processing:** Blend the composited HDR image with the background, then apply tone-mapping and gamma correction [S1, unofficial].

```python
import math

def ray_surfel_hit(ray_o, ray_d, surfel):

    # Standard ray-surfel plane intersection and barycentric check
    # Returns None if outside kernel bounds or behind camera
    return None  # Placeholder for standard intersection math [G]

def compute_rho_mip_sq(u, v, Sigma_mip_inv):
    """Computes MIP-filtered squared distance from precomputed inverse covariance."""
    # Quadratic form: rho^2 = u^2 * Sigma_inv_xx + v^2 * Sigma_inv_yy
    return u * u * Sigma_mip_inv[0][0] + v * v * Sigma_mip_inv[1][1]

def map_weight_to_opacity(W_g):
    """Maps accumulated weight to coverage opacity [G]."""
    # Smooth monotonic mapping assuming partition of unity
    return 1.0 - math.exp(-W_g)

def rasterize_pixel(sorted_surfels, camera_ray_o, camera_ray_d, r_cut_sq, n_f):
    """
    Rasterizes a single pixel using depth-interval grouping.
    
    Args:
        sorted_surfels: List of surfels sorted by z_start.
        camera_ray_o: Ray origin.
        camera_ray_d: Ray direction.
        r_cut_sq: Kernel cutoff radius squared.
        n_f: Front-facing normal factor.
        
    Returns:
        final_color: The composited HDR color for the pixel.
    """
    # Per-pixel accumulators
    C_g = [0.0, 0.0, 0.0]
    W_g = 0.0
    z_end_max = 0.0
    
    # List to store finalized layers (color, opacity)
    layers = []
    
    for surfel in sorted_surfels:
        # 1. Ray-Surfel Intersection
        uv = ray_surfel_hit(camera_ray_o, camera_ray_d, surfel)
        if uv is None:
            continue
            
        u, v = uv
        
        # 2. Evaluate MIP-filtered weight
        rho_mip_sq = compute_rho_mip_sq(u, v, surfel.Sigma_mip_inv)
        
        # 3. Culling
        if rho_mip_sq >= r_cut_sq:
            continue
            
        # 4. Calculate scalar weight
        w = n_f * math.exp(-0.5 * rho_mip_sq)
        
        # 5. Define depth interval
        z_center = surfel.z
        epsilon_z = surfel.epsilon_z
        z_start = z_center - epsilon_z
        z_end = z_center + epsilon_z
        
        # 6. Gap Detection
        if W_g > 0 and z_start > z_end_max:
            # Finalize current group
            if W_g > 0:
                layer_color = [C_g[0] / W_g, C_g[1] / W_g, C_g[2] / W_g]
                layer_opacity = map_weight_to_opacity(W_g)
                layers.append((layer_color, layer_opacity))
            
            # Reset accumulators
            C_g = [0.0, 0.0, 0.0]
            W_g = 0.0
            z_end_max = 0.0
            
        # 7. Update extent
        if z_end > z_end_max:
            z_end_max = z_end
            
        # 8. Accumulate
        C_g[0] += w * surfel.color[0]
        C_g[1] += w * surfel.color[1]
        C_g[2] += w * surfel.color[2]
        W_g += w
        
    # Finalize last group
    if W_g > 0:
        layer_color = [C_g[0] / W_g, C_g[1] / W_g, C_g[2] / W_g]
        layer_opacity = map_weight_to_opacity(W_g)
        layers.append((layer_color, layer_opacity))
        
    # 9. Front-to-Back Compositing
    final_color = [0.0, 0.0, 0.0]
    alpha_acc = 0.0
    
    for layer_color, layer_opacity in layers:
        # Standard front-to-back blending
        contrib_r = layer_color[0] * layer_opacity * (1.0 - alpha_acc)
        contrib_g = layer_color[1] * layer_opacity * (1.0 - alpha_acc)
        contrib_b = layer_color[2] * layer_opacity * (1.0 - alpha_acc)
        
        final_color[0] += contrib_r
        final_color[1] += contrib_g
        final_color[2] += contrib_b
        alpha_acc += layer_opacity * (1.0 - alpha_acc)
        
    return final_color
```

### Parameters
- $\varepsilon_z^{(i)}$: Half-thickness of surfel $i$'s depth interval. This parameter defines the start and end of the depth interval $[z^{(i)} - \varepsilon_z^{(i)}, z^{(i)} + \varepsilon_z^{(i)}]$ used for gap detection [S1, unofficial]. Typical values depend on the surfel size and camera distance, but the source does not specify a fixed value [S1, unofficial].
- $r_{\text{cut}}$: Kernel cutoff radius. Surfels with $\rho_{\text{mip}}^2 \geq r_{\text{cut}}^2$ are skipped [S1, unofficial].
- $n_f$: Front-facing normal factor. Used in the weight calculation $w = n_f \cdot \exp(-\frac{1}{2} \rho_{\text{mip}}^2)$ [S1, unofficial].

### Edge Cases and Pitfalls
- **Self-occlusion at concavities:** Without depth-interval grouping, single-layer approaches produce self-occlusion errors at high-curvature concavities (e.g., inside ears or under chins) where surfels from geometrically distinct surface sheets project onto the same pixel [S1, unofficial]. This manifests as holes or translucent patches revealing the background [S1, unofficial].
- **Silhouette artifacts:** Single-layer approaches can produce a "crusty" shell extending beyond the true silhouette, with aliased contours instead of gradual opacity falloff [S1, unofficial]. The multi-layer approach with smooth coverage falloff anti-aliases silhouettes without post-process edge detection [S1, unofficial].
- **Precision:** The gap detection relies on comparing $z_{\text{start}}^{(i)}$ with $z_{\text{end}}^{\max}$ [S1, unofficial]. Floating-point precision issues could theoretically cause incorrect gap detection if surfels are extremely close in depth, though the source does not specify mitigation strategies [S1, unofficial].

## Subtopics

### [Rasterize-then-splat (RtS)](6690-rasterize-then-splat-rts.md)
Rasterize-then-splat (RtS) is a method for differentiable rendering of 3D surfaces that supports both explicit and implicit representations, providing derivatives at occlusion boundaries while remaining fast and simple to implement. It differs from alternatives like Soft Rasterizer by avoiding costly closest-point queries or mesh processing, and from Nvdiffrast by requiring no specific GPU hardware or custom derivative code, making its differentiable cost independent of mesh size.

## Operating characteristics
- **Time Complexity:** The sorting step is $O(N \log N)$ for $N$ surfels per tile [S1, unofficial]. The per-pixel processing is linear in the number of surfels covering the pixel, with a constant number of operations per surfel (intersection, weight evaluation, accumulation) [S1, unofficial].
- **Memory Complexity:** Requires storage for the sorted surfel list per tile and per-pixel accumulators [S1, unofficial]. The number of layers per pixel is typically small, so memory overhead is low [S1, unofficial].
- **Measured Performance:** The source does not provide specific performance benchmarks (FPS, memory usage) for the rasterization step alone [S1, unofficial]. It notes that the method is "fast and simple to implement" in the context of RtS comparison, but 3DSS itself is a complex optimization framework [S1, unofficial].
- **Strengths:** Correctly handles self-occlusion at concavities without explicit mesh processing [S1, unofficial]. Anti-aliases silhouettes naturally through smooth coverage falloff [S1, unofficial]. Differentiable gradients flow back through all operations [S1, unofficial].
- **Limitations:** Performance depends on the number of surfels per pixel and the number of layers [S1, unofficial]. The source does not specify how many layers are typical or how this scales with scene complexity [S1, unofficial].
- **When to use:** When rendering unstructured surface representations (surfels) where self-occlusion at concavities is a concern, and differentiability is required [S1, unofficial].
- **When not to use:** For simple opaque meshes where a single layer suffices, or when hardware-specific optimizations (like Nvdiffrast) are available and preferred [S1, unofficial].

## Background
3D Surface Splatting (3DSS) was introduced in the paper "3DSS: 3D Surface Splatting for Inverse Rendering" [S1, unofficial]. The method is part of a framework for physically-based inverse rendering that jointly recovers geometry, materials, and illumination from multi-view images [S1, unofficial]. The rasterization algorithm described here is a key component of this framework, enabling the differentiable rendering of surfels [S1, unofficial]. The approach builds on earlier work in splatting and A-buffer techniques but introduces depth-interval grouping to handle multiple surface layers [S1, unofficial].
