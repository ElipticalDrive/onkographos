# 3D Gaussian Splatting (3DGS)
Also called: Gao et al. BRDF Method
## Overview
This method extends standard 3D Gaussian Splatting by embedding physically based rendering (PBR) parameters into each Gaussian primitive, enabling per-point BRDF evaluation rather than simple view-dependent color interpolation [S1, unofficial]. It distinguishes itself from sibling methods like [3DGS-DR](1471-3dgs-dr.md) by explicitly storing incident lighting and roughness/albedo data per Gaussian, allowing for direct lighting reconstruction via environment maps and indirect lighting via spherical harmonics [S1, unofficial].
## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of 3D Gaussians (initialized from standard 3DGS or SfM points), camera poses, and input images.
*   **Outputs:** A rendered image with physically based shading, including specular highlights and albedo-consistent diffuse reflection.

**Data Structures:**
Each Gaussian $i$ in the scene representation stores the following fields beyond standard position, covariance, opacity, and SH coefficients:
1.  **Albedo ($\alpha_i$):** A 3D vector representing the diffuse base color.
2.  **Roughness ($\rho_i$):** A scalar value controlling the specular spread.
3.  **Surface Normal ($\mathbf{n}_i$):** A 3D vector, typically derived from the Gaussian's orientation or optimized directly.
4.  **Incident Lighting:** Represented either as an environment map lookup or spherical harmonic coefficients for indirect illumination.

**Numbered Steps:**
1.  **Initialization:** Initialize Gaussians with standard 3DGS parameters. Assign initial BRDF parameters: uniform albedo, default roughness (e.g., 0.5), and normals estimated from local geometry or random initialization.
2.  **Differentiable Rendering:** For each pixel, project the 3D Gaussians to 2D. Compute the contribution of each Gaussian to the pixel color using the standard alpha-blending equation, but replace the view-dependent SH color with a PBR shading model.
3.  **Shading Model:**
    *   **Direct Lighting:** Sample the environment map at the direction of the light source relative to the surface normal $\mathbf{n}_i$. The direct radiance $L_{dir}$ is computed using a BRDF (e.g., Cook-Torrance) with albedo $\alpha_i$ and roughness $\rho_i$.
    *   **Indirect Lighting:** Compute the ambient/indirect radiance $L_{ind}$ using the Gaussian's spherical harmonic coefficients, which now represent the irradiance at that point rather than view-dependent color.
    *   **Composite Color:** The final color $C$ for a Gaussian is:
        $$ C = \alpha_i \cdot L_{ind} + \int_{\Omega} f_r(\omega_i, \omega_o, \mathbf{n}_i, \rho_i) L_{dir}(\omega_i) (\mathbf{n}_i \cdot \omega_i) d\omega_i $$
        Where $f_r$ is the BRDF, $\omega_i$ is the incident light direction, and $\omega_o$ is the view direction.
4.  **Optimization:** Minimize the photometric loss between the rendered image and the ground truth. Gradients flow through the PBR shading model to update albedo, roughness, normals, and standard Gaussian parameters.
5.  **Secondary Rays (Optional):** To model interreflections, spawn secondary rays (reflections/refractions) upon primary ray interaction with Gaussians, tracing them through the scene [S1, unofficial].

**Parameters:**
*   **Roughness:** Typically optimized in the range $[0.0, 1.0]$.
*   **Environment Map:** High-dynamic-range (HDR) cubemap or spherical harmonics for direct lighting.

**Edge Cases and Pitfalls:**
*   **Normal Ambiguity:** Surface normals derived from Gaussian covariance may be noisy in textureless regions, leading to incorrect specular highlights.
*   **Lighting Estimation:** Accurate direct lighting requires a known environment map. If not provided, indirect lighting via SH may fail to capture sharp specular features.
*   **Optimization Stability:** BRDF parameters can diverge if not regularized. Roughness should be clamped to avoid singularities in the BRDF evaluation.

**Pseudocode:**
```python
def render_3dgs_brdf(gaussians, camera, env_map):
    """
    Render a scene using 3DGS with embedded BRDF parameters.
    """
    # Project Gaussians to screen space
    screen_gaussians = project_to_screen(gaussians, camera)
    
    # Sort by depth for alpha blending
    screen_gaussians.sort_by_depth()
    
    # Initialize output image
    image = zeros_like(camera.resolution)
    
    for gaussian in screen_gaussians:
        # Compute 2D covariance and opacity
        cov2d = compute_2d_covariance(gaussian.cov3d, camera.proj_matrix)
        opacity = gaussian.opacity * compute_gaussian_pdf(gaussian.position_2d, cov2d)
        
        if opacity < epsilon:
            continue
            
        # Retrieve BRDF parameters
        albedo = gaussian.albedo
        roughness = gaussian.roughness
        normal = gaussian.normal
        
        # Compute Direct Lighting
        # Sample environment map based on reflection vector
        reflection_dir = reflect(camera.view_direction, normal)
        direct_radiance = sample_env_map(env_map, reflection_dir)
        
        # Compute BRDF (e.g., Cook-Torrance)
        # Note: Simplified for pseudocode; actual implementation requires microfacet theory
        brdf_value = cook_torrance_brdf(
            view_dir=camera.view_direction,
            light_dir=reflection_dir, # Approximation for environment map sampling
            normal=normal,
            roughness=roughness
        )
        
        # Compute Indirect Lighting from SH coefficients
        # SH coefficients now represent irradiance, not view-dependent color
        indirect_radiance = evaluate_sh(gaussian.sh_coeffs, normal)
        
        # Composite color
        # Diffuse term
        diffuse = albedo * indirect_radiance
        # Specular term
        specular = brdf_value * direct_radiance
        
        gaussian_color = diffuse + specular
        
        # Alpha blend into image
        image = blend_pixel(image, gaussian_color, opacity)
        
    return image
```
## Subtopics

### [3DGS-DR](1471-3dgs-dr.md)
A method that incorporates classical reflection and shading concepts into the 3DGS framework, similar to the BRDF embedding approach but potentially differing in the specific shading model or optimization strategy for normals and lighting [1471-3dgs-dr.md].

### SWAG
A method that extends 3DGS by conditioning Gaussians on learned appearance embeddings and training unsupervised transient Gaussians to ignore occluders, yielding state-of-the-art results on diverse photo scenes by handling transient effects and distractors [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering is comparable to standard 3DGS, but shading evaluation per Gaussian is more expensive due to BRDF and environment map sampling.
*   **Memory Complexity:** Higher than standard 3DGS due to the storage of albedo, roughness, and normal vectors per Gaussian.
*   **Strengths:** Physically plausible rendering, ability to relight scenes, and consistent appearance under varying lighting conditions.
*   **Limitations:** Requires HDR environment maps for direct lighting; optimization is more complex and prone to local minima; normal estimation can be unstable.
*   **When to Use:** When physically based rendering, relighting, or material estimation is required.
*   **When Not to Use:** When only view-dependent appearance is needed, or when computational resources are limited.
## Background
Originated from the work of Gao et al., who embedded BRDF parameters into 3D Gaussians to enable per-point physically based rendering [S1, unofficial]. This approach builds on the foundational 3D Gaussian Splatting method and integrates concepts from classical computer graphics rendering pipelines.
