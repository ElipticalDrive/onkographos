# Volume Encoding Gaussians

Also called: Transfer Function-Agnostic 3D Gaussians for Volume Rendering

## Overview
Volume Encoding Gaussians (VEG) adapts 3D Gaussian Splatting for volume data visualization by removing color and opacity attributes per Gaussian and training only scalar values, enabling interactive transfer function application post-training [S1, unofficial]. This distinguishes it from [Gaussian Splatting Volume Rendering](2063-gaussian-splatting-volume-rendering.md), which typically retains explicit opacity and color attributes for direct rendering [G].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians defined by position $\mathbf{\mu}$, covariance $\mathbf{\Sigma}$ (or rotation $\mathbf{R}$ and scale $\mathbf{s}$), and a learned scalar density value $\sigma$ [S1, unofficial].
*   **Output:** A rendered image where color is determined by applying a user-defined transfer function to the accumulated density [S1, unofficial].

**Data Structures:**
Each Gaussian $i$ stores:
1.  **Position:** $\mathbf{\mu}_i \in \mathbb{R}^3$ [S1, unofficial].
2.  **Covariance:** $\mathbf{\Sigma}_i \in \mathbb{R}^{3 \times 3}$ (parameterized by rotation $\mathbf{R}_i \in SO(3)$ and scale $\mathbf{s}_i \in \mathbb{R}^3$) [S1, unofficial].
3.  **Density:** $\sigma_i \in \mathbb{R}$ (scalar value, no color or opacity) [S1, unofficial].

**Steps:**
1.  **Initialization:** Initialize Gaussians from the input volume data (e.g., via sampling or pruning) with positions and scales, and initialize scalar densities $\sigma_i$ [G].
2.  **Differentiable Rendering:** Project Gaussians to screen space [G].
3.  **Optimization:** Minimize a loss function (e.g., L1 or SSIM) between the rendered image and the ground truth volume visualization generated using a reference transfer function. Only the positions, covariances, and scalar densities $\sigma_i$ are optimized; color and opacity attributes are removed from the optimization variables [S1, unofficial].
4.  **Rendering with Transfer Function:** At inference, apply a desired transfer function $T(\sigma)$ to the accumulated density or per-Gaussian scalar values to compute the final color. This allows interactive adjustment without retraining [S1, unofficial].

**Parameters:**
*   Learning rate for positions, scales, rotations, and densities: Not given in the sources [S1, unofficial].
*   Loss function: Not given in the sources [S1, unofficial].

**Edge Cases:**
*   Not given in the sources [S1, unofficial].

## Subtopics

### GVGEN
GVGEN is a method that works in 3D space based on a 3D Gaussian volume representation [S2]. It is distinct from VEG in that it is framed within a generative context, whereas VEG focuses on adapting existing 3DGS for volume visualization with transfer function agnosticism [S2].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1, unofficial].
*   **Memory Complexity:** Not given in the sources [S1, unofficial].
*   **Strengths:** Enables interactive transfer function application post-training, allowing users to explore different scalar-to-color mappings without retraining [S1, unofficial].
*   **Limitations:** Not given in the sources [S1, unofficial].
*   **When to use:** When interactive exploration of volume data via transfer functions is required, and the underlying geometry/density is static [G].
*   **When not to use:** When specific color/opacity features are critical and cannot be captured by a transfer function on scalar density, or when dynamic appearance changes are needed [G].

## Background
Volume Encoding Gaussians was introduced to adapt 3D Gaussian Splatting for volume data visualization [S1, unofficial]. The method removes color and opacity attributes, training only scalar values to enable transfer function agnosticism [S1, unofficial]. GVGEN is mentioned as another method working in 3D space with a 3D Gaussian volume representation [S2].
