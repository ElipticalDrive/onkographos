# Ray-Patch

Also called: RP-OSRT, RP-SRT, Ray-Patch Decoding, Ray-Patch querying

## Overview
Ray-Patch is a decoding strategy for Light Field Transformers (LFTs) that reduces computational complexity and memory usage by grouping target image pixels into square patches and querying the transformer once per patch instead of per pixel [S1, unofficial]. It maintains global attention capabilities while reducing the number of queries by a factor of $k^2$, where $k$ is the patch side length, enabling real-time rendering of high-resolution images [S1, unofficial].

## How it works
**Inputs:**
- Scene Latent Scene Representation (SLSR) $Z$, a latent feature tensor generated by an encoder from input views.
- Target view image dimensions: height $h$, width $w$, and channels $c$ (typically $c=3$ for RGB).
- Camera parameters for the target view: intrinsic matrix $K_t$ and extrinsic matrix $W T_{C_t} = [R_t | o_t] \in SE(3)$, where $o_t$ is the camera origin.
- Patch size parameter $k$ (integer, typically 2, 4, 8, or 16).
- Decoder channel dimension $f$ (output channels of the attention decoder).

**Outputs:**
- Rendered target image $\hat{I}_t \in \mathbb{R}^{h \times w \times c}$.

**Data Structures:**
- **Patches:** The image is conceptually split into $N_{patches} = \frac{hw}{k^2}$ square patches of size $k \times k$.
- **Queries ($Q_{tp}$):** A set of query vectors, one per patch $p$, encoded with Fourier positional encoding.
- **Feature Vectors ($Z_{tp}$):** The output of the attention decoder for each query, forming an intermediate feature map of shape $\frac{h}{k} \times \frac{w}{k} \times f$.

**Steps:**

1.  **Patch Parametrization:**
    For each patch $p$ in the target image grid:
    a. Identify the center coordinates $(u_{tp}, v_{tp})$ of the patch in pixel space.
    b. Form the homogeneous coordinate vector $x_{tp} = [u_{tp}, v_{tp}, 1]^T$.
    c. Compute the ray direction in the camera reference frame $C_t$ by unprojecting the patch center:
       $$ r^C_{tp} = K_t^{-1} \cdot x_{tp} = \left[ \frac{x_{tp}}{z_{tp}}, \frac{y_{tp}}{z_{tp}}, 1, 1 \right]^T $$
       where $z_{tp}$ is the depth component derived from the unprojection [S1, unofficial].
    d. Transform the ray to the world reference frame $W$:
       $$ r^W_{tp} = R_t \cdot r^C_{tp} $$
       (Note: The origin $o_t$ is used separately in the query encoding).

2.  **Query Generation:**
    Encode the patch parameters using Fourier positional encoding $\gamma(\cdot)$ to generate the query set $\{Q_{tp}\}$:
    $$ \{Q_{tp}\} = \{ \gamma(o_t) \oplus \gamma(r^W_{tp}) \} $$
    where $\oplus$ denotes concatenation [S1, unofficial].

3.  **Attention Decoding:**
    Perform cross-attention between the patch queries $\{Q_{tp}\}$ and the Scene Latent Scene Representation $Z$ using an attention decoder $D_A$:
    $$ \{Z_{tp}\} = D_A(\{Q_{tp}\}, Z) $$
    This computes a feature vector $Z_{tp}$ for each patch. The collection of these vectors forms a feature map $Z_t \in \mathbb{R}^{\frac{h}{k} \times \frac{w}{k} \times f}$ [S1, unofficial].

4.  **Convolutional Decoding:**
    Reshape the feature vectors into the rectangular grid corresponding to the image dimensions. Pass $Z_t$ through a convolutional neural network decoder $D_{CNN}$ (typically based on upsampling blocks with convolutions) to decode the final target image:
    $$ \hat{I}_t = D_{CNN}(Z_t) $$
    The output has $c$ channels (e.g., 3 for RGB) [S1, unofficial].

import torch

def ray_patch_decoding(Z, K_t, R_t, o_t, h, w, k, f, D_A, D_CNN):
    """
    Z: Scene Latent Scene Representation (tensor)
    K_t: Camera intrinsic matrix (3x3)
    R_t: Camera rotation matrix (3x3)
    o_t: Camera origin vector (3,)
    h, w: Target image height and width
    k: Patch side length
    f: Output channels of attention decoder
    D_A: Attention decoder module
    D_CNN: Convolutional decoder module
    """
    # 1. Generate patch centers
    # Create grid of patch centers
    # Number of patches
    n_patches_h = h // k
    n_patches_w = w // k
    
    # Generate coordinates for patch centers
    # Assuming integer division and no overlap/gaps for simplicity
    # In practice, ensure h and w are divisible by k or handle boundaries
    ys = torch.arange(0, h, k) + k // 2
    xs = torch.arange(0, w, k) + k // 2
    
    # Create meshgrid of patch centers
    grid_y, grid_x = torch.meshgrid(ys, xs, indexing='ij')
    
    # Flatten to list of centers
    centers = torch.stack([grid_x.flatten(), grid_y.flatten()], dim=-1).float() # Shape: (N_patches, 2)
    
    # 2. Parametrize rays
    # Add homogeneous coordinate 1
    centers_hom = torch.cat([centers, torch.ones(centers.shape[0], 1)], dim=-1) # Shape: (N_patches, 3)
    
    # Unproject to camera frame
    # r_C = K_inv * x_hom
    K_inv = torch.inverse(K_t)
    rays_cam_hom = torch.matmul(K_inv, centers_hom.t()).t() # Shape: (N_patches, 3)
    
    # Normalize to get direction (assuming perspective projection)
    # r_C = [x/z, y/z, 1]
    z_vals = rays_cam_hom[:, 2:3]
    rays_cam_dir = rays_cam_hom[:, :2] / z_vals
    rays_cam_dir = torch.cat([rays_cam_dir, torch.ones(rays_cam_dir.shape[0], 1)], dim=-1) # Shape: (N_patches, 3)
    
    # Transform to world frame
    # r_W = R * r_C
    rays_world = torch.matmul(R_t, rays_cam_dir.t()).t() # Shape: (N_patches, 3)
    
    # 3. Generate Queries
    # Fourier positional encoding (simplified placeholder for gamma)
    # In practice, gamma maps scalar inputs to a vector of frequencies
    # Here we assume a function that takes a vector and returns a high-dim encoding
    # o_t is the same for all patches
    o_t_enc = fourier_encode(o_t)
    rays_world_enc = fourier_encode(rays_world) # Apply to each ray
    
    # Concatenate origin and ray encodings
    queries = torch.cat([o_t_enc.unsqueeze(0).expand(n_patches_h * n_patches_w, -1), rays_world_enc], dim=-1)
    
    # 4. Attention Decoding
    # D_A takes queries and Z
    # Assuming D_A returns features of shape (N_patches, f)
    features = D_A(queries, Z) # Shape: (N_patches, f)
    
    # Reshape to spatial grid
    features_grid = features.view(n_patches_h, n_patches_w, f)
    
    # 5. Convolutional Decoding
    # Transpose to (N_patches, f, 1, 1) or similar for conv, or use adaptive pooling
    # The paper describes a CNN decoder (upsampling blocks)
    # Assuming D_CNN takes the spatial feature map
    # Reshape to (1, f, h/k, w/k) for standard conv layers
    features_4d = features_grid.permute(2, 0, 1).unsqueeze(0) # Shape: (1, f, h/k, w/k)
    
    # Decode to final image
    # D_CNN upsamples from (h/k, w/k) to (h, w)
    image = D_CNN(features_4d) # Shape: (1, c, h, w)
    
    return image.squeeze(0)

**Parameters:**
- $k$: Side length of the square patch in pixels. Typical values tested are 2, 4, 8, and 16 [S1, unofficial].
- $f$: Number of channels in the output of the attention decoder, determining the channel dimension of the intermediate feature map $Z_t$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Diffuseness:** Larger patch sizes result in more diffuse image outputs. Qualitative results show that RP-SRT with $k=8$ looks more diffuse than with $k=4$ [S1, unofficial].
- **Resolution Scaling:** To maintain fixed rendering speed, the patch size $k$ should increase at the same pace as the number of pixels (resolution) [S1, unofficial].
- **Boundary Conditions:** The method assumes the image dimensions $h$ and $w$ are divisible by $k$ for simple grid splitting. If not, padding or irregular patch handling is required [G].

## Subtopics

### RP-SRT
Ray-Patch applied to the Scene Representation Transformer (SRT). It replaces per-pixel queries with per-patch queries in the SRT decoder. Chosen when using SRT as the base architecture. [Link](1185-nerf-neural-radiance-fields.md)

### RP-OSRT
Ray-Patch applied to the Open-Set Scene Representation Transformer (OSRT). It reduces the querying cost in OSRT by a factor of $k^2$. Chosen when using OSRT for open-set tasks. [Link](6202-neural-reconstruction-in-the-wild.md)

### RP-DeFiNe
Ray-Patch applied to the DeFiNe architecture. It significantly reduces GPU memory usage for attention decoding. Chosen when memory is a bottleneck for high-resolution rendering with DeFiNe. [Link](6800-neural-rendering.md)

## Operating characteristics
- **Time Complexity:** The computational complexity for decoding scales with the number of patches $N_{patches}$ rather than pixels $N_{pixels}$. Since $N_{patches} = N_{pixels} / k^2$, the cost is reduced by a factor of $k^2$. The attention complexity remains $O(n_q^2 d_k)$ where $n_q$ is the number of patches [S1, unofficial].
- **Memory Complexity:** Peak GPU vRAM usage due to attention scales with $n_q \times n_{kv}$. Ray-Patch reduces this by a factor of $k^2$. For example, decoding a 960x1280 image with DeFiNe ($n_{kv}=2048$) requires 75 GB GPU memory with standard attention, but only 0.3 GB with Ray-Patch ($k=16$) [S1, unofficial].
- **Performance:** On MSN-Easy at 120x160 resolution, RP-SRT with $k=8$ achieves 305 fps rendering speed compared to SRT's 30 fps (~10x speedup), with PSNR 32.306 vs 32.842 [S1, unofficial]. Ray-Patch increases rendering speed up to one order of magnitude (10x) compared to previous models like DeFiNe [S1, unofficial].
- **Strengths:** Drastic reduction in querying cost, enabling real-time rendering of high-resolution images. Maintains global attention. Reduces training time by 60-70% [S1, unofficial].
- **Limitations:** Larger patch sizes can lead to diffuse outputs. Accuracy may slightly decrease with very large $k$ compared to per-pixel querying [S1, unofficial].

## Background
Ray-Patch was proposed in the paper "Ray-Patch: An Efficient Decoder for Light Field Transformers" by T. Berriel and J. Civera, published on arXiv in May 2023 [S1, unofficial]. It was developed to address the limitations of neural rendering, specifically the exhaustive querying required to recover each pixel and the high computational cost of Light Field Transformers (LFTs) like SRT, OSRT, and DeFiNe, which scale quartically with image resolution [S1, unofficial]. The method was implemented and evaluated in three different LFT architectures (SRT, OSRT, DeFiNe) and tested on two tasks (novel view synthesis, unsupervised segmentation) and datasets (MSN-Easy, MultiShapeNet-Easy) [S1, unofficial].
