# Lightweight Profiling

Also called: Mesh-assisted NeRF Profiling Model, Polynomial-based Size and Quality Prediction

## Overview
Lightweight Profiling is a white-box model that predicts the representation data size and rendering quality of mesh-assisted Neural Radiance Fields (NeRFs) for specific configurations without training the network [S1]. It solves the problem of high computational cost in configuration search by providing an analytical approximation of performance metrics, avoiding the significant time and resource costs associated with full network training [S1]. It differs from black-box profiling models (e.g., neural networks) by using explicit polynomial functions derived from rendering knowledge, and it differs from its parent [FastNeRF Cache Size Estimation](11428-fastnerf-cache-size-estimation.md) by focusing on mesh-assisted NeRFs (like mobile-NeRF) where geometry and texture knobs are decoupled from the MLP [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Two configuration knobs:
    *   $g$: Number of voxel grids allocated for each axis in the 3D voxel grid representation (geometry knob) [S1].
    *   $p$: One-dimensional size of the texture image allocated for each quad face (texture knob, $p \times p$ pixels) [S1].
*   **Outputs:**
    *   $S$: Total data size (memory load) [S1].
    *   $Q$: Rendering quality metric, specifically SSIM (Structural Similarity Index Measure) [S1].

**Data Structures:**
The model consists of two polynomial functions, $f_s$ and $f_q$, parameterized by a set of coefficients $\theta = \{m, a, b, k, a', b'\}$ [S1]. These coefficients are determined via curve fitting [S1].

**Formulas:**
The size $S$ and quality $Q$ are calculated as follows [S1]:

$$
S = f_s(g, p) = \frac{m}{3}(g + a)^3 \cdot (p + b)^2
$$

$$
Q = f_q(g, p) = k \cdot (g + a')^3 \cdot (p + b')^2
$$

Where:
*   $m, a, b$ are constants for the size model [S1].
*   $k, a', b'$ are constants for the quality model [S1].
*   The exponent 3 on the geometry term $(g+a)$ reflects the 3D nature of the voxel grid [S1].
*   The exponent 2 on the texture term $(p+b)$ reflects the 2D nature of the texture image [S1].
*   The MLP size is excluded from $S$ as it is negligible (a few KB) and has poor compatibility with commercial rendering engines when quantized [S1].

**Parameters and Typical Values:**
*   **Quality Metric $Q$:** SSIM, evaluating luminance, contrast, and structure [S1].
*   **Size Metric $S$:** Total data size in bytes or KB [S1].
*   **Knob $g$:** Integer, number of voxels per axis [S1].
*   **Knob $p$:** Integer, texture resolution per face [S1].
*   **Coefficients:** Not given in the sources. They are determined by curve fitting on sampled data [S1].

**Sampling Strategy for Curve Fitting:**
To minimize the number of sampling points required to fit the coefficients $\theta$, a variable step-size searching strategy is used [S1]:
1.  Select $g$ values using a step size of $2 \cdot g'$, where $g'$ is the value of the previous sample point [S1].
2.  For each selected $g$, select three distinct $p$ values: the maximum, minimum, and midpoint of the valid patch size range [S1].
3.  Pair each $g$ with these three $p$ values to generate sample points [S1].

**Edge Cases and Pitfalls:**
*   **MLP Exclusion:** The model excludes the MLP configuration. This is valid because the MLP size is small (KBs) and quantization is incompatible with commercial engines [S1]. If the MLP size becomes significant for a specific variant, this model will underestimate total size [G].
*   **Mesh-Assisted Only:** The model is designed for mesh-assisted NeRFs (e.g., mobile-NeRF, NeRF2Mesh) where geometry is converted to a voxel grid and textured meshes [S1]. It may not apply to pure voxel-based or pure grid-based NeRFs without texture mapping [S1].
*   **SSIM Limitations:** The quality metric is SSIM, which aligns with human perception but may differ from PSNR [S1]. If PSNR is required, the model must be re-fitted with PSNR targets [G].
*   **Extrapolation:** The polynomial model is fitted within the sampled range. Extrapolating outside the range of $g$ and $p$ used for fitting may lead to inaccurate predictions [G].

## Operating characteristics
*   **Time Complexity:** The prediction itself is $O(1)$ given the coefficients, as it involves simple arithmetic operations [S1]. The cost lies in the initial curve fitting, which requires sampling a small number of configurations (e.g., 45 pairs in validation) [S1].
*   **Memory Complexity:** The model stores a small number of coefficients (6 for size, 3 for quality, total 9) [S1]. Memory usage is negligible compared to the NeRF model itself [S1].
*   **Measured Performance:** Validated on four objects with 45 configuration pairs [S1].
    *   Average error in quality prediction (SSIM): 0.0065, standard deviation 0.0088 [S1].
    *   Average error in size prediction: 3.3410, standard deviation 2.7345 [S1].
*   **Strengths:** Avoids the hours-long training time required for full NeRF optimization (e.g., on RTX 3090 GPUs) [S1]. Provides a white-box, interpretable model [S1].
*   **Limitations:** Limited to mesh-assisted NeRFs. Accuracy depends on the quality of the curve fitting and the representativeness of the sample points [S1]. Does not account for MLP configuration changes [S1].

## Background
*   **Origin:** Proposed in the NeRFlex paper [S1].
*   **Context:** Mobile-NeRF [6] and NeRF2Mesh [7] are examples of mesh-assisted real-time NeRF solutions that convert objects to voxel grid representations [S1]. The baking of data for these representations can take several hours on high-end GPUs [S1].
*   **Development:** The profiling module was designed to predict representation data size and rendering quality without training the network, addressing the high cost of configuration search [S1]. It uses SSIM for quality and total data size for memory load [S1].
*   **Usage:** Used in the NeRFlex framework for resource-aware real-time high-quality rendering on mobile devices [S1].
