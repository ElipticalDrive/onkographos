# Voxel-based Gaussian Splatting


## Overview
Voxel-based Gaussian Splatting (VoxGS) is a volume representation designed for Computed Tomography (CT) reconstruction from sparse X-ray projections, enabling both efficient CT volume extraction and differentiable X-ray rendering [S1, unofficial]. It distinguishes itself from standard 3D Gaussian Splatting [3D Gaussian Splatting](3d-gaussian-splatting.md) by fixing Gaussian positions to a regular voxel grid and removing spherical harmonic color coefficients, thereby solving the instability and inaccurate volume extraction issues associated with applying original 3DGS to CT data [S1, unofficial]. Unlike discrete 3D voxels, VoxGS supports differentiable rendering, allowing X-ray projection constraints to be leveraged during training [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $K$ X-ray projection images, processed into view-specific feature maps $\mathbf{F}_k \in \mathbb{R}^{H \times W \times C}$ by a vision transformer (e.g., ViT) [S1, unofficial].
*   **Output:** A set of $N_p$ 3D Gaussians $\mathcal{G} = \{g_i\}_{i=1}^{N_p}$, where each Gaussian $g_i$ is defined by its fixed position, opacity, scale, and rotation [S1, unofficial].

**Data Structures:**
Each Gaussian $g_i$ stores the following attributes:
*   **Position $\boldsymbol{\mu}_i$:** Fixed at the centroid of a voxel in a regular 3D grid of size $M \times N \times L$. Represented as $(x, y, z)$ where $x \in [1, M], y \in [1, N], z \in [1, L]$ [S1, unofficial].
*   **Opacity $\alpha_i$:** A single scalar float [S1, unofficial].
*   **Scale $\mathbf{s}_i$:** A 3D vector of floats [S1, unofficial].
*   **Rotation $\mathbf{r}_i$:** A 4D vector (quaternion) of floats [S1, unofficial].
*   **Note:** Spherical Harmonic (SH) coefficients for color are explicitly removed [S1, unofficial].

**Numbered Steps:**
1.  **Grid Initialization:** Define a regular 3D voxel grid with dimensions $M \times N \times L$. Place $N_p = M \times N \times L$ isometric 3D Gaussians, fixing the position $\boldsymbol{\mu}_i$ of each Gaussian $g_i$ to the centroid of the corresponding voxel [S1, unofficial].
2.  **Feature Query:** For each Gaussian $g_i$ and each view $k \in \{1, \dots, K\}$:
    *   Project the fixed 3D position $\boldsymbol{\mu}_i$ to 2D using the projection matrix $\mathbf{P}_k$ of the $k$-th view: $\mathbf{P}_k(\boldsymbol{\mu}_i)$ [S1, unofficial].
    *   Query the view-specific feature $\mathbf{F}_k$ at the projected 2D position using bilinear interpolation:
        $$ \tilde{F}_k^i = \text{Interp}(\mathbf{F}_k, \mathbf{P}_k(\boldsymbol{\mu}_i)) \in \mathbb{R}^C $$
        where $\text{Interp}(\cdot)$ denotes bilinear interpolation [S1, unofficial].
3.  **Feature Aggregation:** Aggregate the $K$ queried features for Gaussian $g_i$ using MaxPooling:
    $$ \mathbf{F}_{max}^i = \text{MaxPool}(\tilde{F}_1^i, \tilde{F}_2^i, \dots, \tilde{F}_K^i) \in \mathbb{R}^C $$
    [S1, unofficial].
4.  **Attribute Regression:** Pass the aggregated feature $\mathbf{F}_{max}^i$ through a prediction Multi-Layer Perceptron (MLP), denoted as $MLPS$, to predict the Gaussian parameters:
    $$ [\alpha_i, \mathbf{s}_i, \mathbf{r}_i] = MLPS(\mathbf{F}_{max}^i) \in \mathbb{R}^{1+3+4} $$
    where the output consists of opacity (1 float), scale (3 floats), and rotation (4 floats) [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class VoxGS:
    def __init__(self, grid_dims: tuple, num_views: int, feature_dim: int, mlp_hidden_dims: list):
        """
        Initialize VoxGS representation.
        
        Args:
            grid_dims: Tuple (M, N, L) defining the 3D voxel grid size.
            num_views: Number of X-ray projection views K.
            feature_dim: Dimension C of the input view features.
            mlp_hidden_dims: List of integers for MLP hidden layers.
        """
        self.M, self.N, self.L = grid_dims
        self.K = num_views
        self.C = feature_dim
        self.N_p = M * N * L
        
        # Fixed positions: centroids of the voxel grid
        # x in [1, M], y in [1, N], z in [1, L]
        # Reshape to (N_p, 3)
        x = torch.arange(1, M + 1).float().view(-1, 1)
        y = torch.arange(1, N + 1).float().view(-1, 1)
        z = torch.arange(1, L + 1).float().view(-1, 1)
        
        # Create meshgrid and flatten
        xx, yy, zz = torch.meshgrid(x, y, z, indexing='ij')
        self.mu = torch.stack([xx.flatten(), yy.flatten(), zz.flatten()], dim=1) # (N_p, 3)
        
        # Prediction MLP: Input C -> Output 1+3+4 = 8
        layers = []
        prev_dim = self.C
        for hidden_dim in mlp_hidden_dims:
            layers.append(nn.Linear(prev_dim, hidden_dim))
            layers.append(nn.ReLU())
            prev_dim = hidden_dim
        layers.append(nn.Linear(prev_dim, 8)) # 1 opacity, 3 scale, 4 rotation
        self.MLPS = nn.Sequential(*layers)

    def query_features(self, view_features: torch.Tensor, projection_matrices: list) -> torch.Tensor:
        """
        Query view-specific features for all Gaussians.
        
        Args:
            view_features: Tensor of shape (K, H, W, C) containing feature maps for each view.
            projection_matrices: List of K projection matrices P_k, each mapping 3D to 2D.
                                 Note: In practice, P_k(mu) requires specific camera intrinsics/extrinsics.
                                 Here we assume a helper function `project_3d_to_2d` exists.
        
        Returns:
            Queried features for all Gaussians and views: (N_p, K, C)
        """
        # Placeholder for actual 3D-to-2D projection logic based on P_k
        # P_k: R^3 -> R^2
        # We need to project each mu_i (N_p, 3) using each P_k (K times)
        # Resulting 2D coordinates: (N_p, K, 2)
        
        # Assuming `project_3d_to_2d(mu, P_k)` returns 2D coords
        # This part depends on the specific camera model implementation not detailed in [S1, unofficial]
        # We assume `proj_coords` is (N_p, K, 2)
        proj_coords = self._compute_projections(self.mu, projection_matrices) 
        
        # Bilinear interpolation for each view
        # view_features: (K, C, H, W) for F.grid_sample compatibility
        vf = view_features.permute(0, 3, 1, 2) # (K, C, H, W)
        
        # Normalize coords to [-1, 1] for grid_sample
        # Assuming H, W are known or passed. Let's assume H, W from vf shape.
        H, W = vf.shape[2], vf.shape[3]
        norm_x = 2.0 * proj_coords[:, :, 0] / (W - 1) - 1.0
        norm_y = 2.0 * proj_coords[:, :, 1] / (H - 1) - 1.0
        grid = torch.stack([norm_x, norm_y], dim=-1) # (N_p, K, 1, 2)
        
        # grid_sample expects (N, C, H, W) and grid (N, H_out, W_out, 2)
        # We need to sample K points for each of N_p Gaussians
        # Reshape for grid_sample: (N_p * K, C, 1, 1)
        vf_flat = vf.repeat_interleave(self.N_p, dim=0) # (N_p*K, C, H, W)
        grid_flat = grid.view(self.N_p * self.K, 1, 1, 2) # (N_p*K, 1, 1, 2)
        
        # Sample features
        sampled = F.grid_sample(vf_flat, grid_flat, align_corners=True) # (N_p*K, C, 1, 1)
        sampled = sampled.squeeze(-1).squeeze(-1) # (N_p*K, C)
        
        # Reshape back to (N_p, K, C)
        return sampled.view(self.N_p, self.K, self.C)

        """

        # to project mu (N_p, 3) to 2D for each view.
        # Returns (N_p, K, 2)
        # Since the exact projection function is not provided in [S1, unofficial], 
        # we assume it is handled by the surrounding X-GRM architecture.
        # For the purpose of implementing VoxGS attribute decoding, 
        # we assume `proj_coords` is available.
        raise NotImplementedError("Projection logic depends on camera parameters not detailed in [S1, unofficial].")

    def decode_attributes(self, view_features: torch.Tensor, projection_matrices: list) -> dict:
        """
        Decode Gaussian attributes from view features.
        
        Args:
            view_features: Tensor of shape (K, H, W, C).
            projection_matrices: List of projection matrices.
            
        Returns:
            Dictionary containing alpha, s, r.
        """
        # Step 2: Query features
        queried_features = self.query_features(view_features, projection_matrices) # (N_p, K, C)
        
        # Step 3: MaxPool across views
        # MaxPool over dim=1 (K views)
        F_max = torch.max(queried_features, dim=1).values # (N_p, C)
        
        # Step 4: Regress attributes
        # Output: (N_p, 8) -> [alpha, s_x, s_y, s_z, r_x, r_y, r_z, r_w]
        raw_params = self.MLPS(F_max) # (N_p, 8)
        
        alpha = raw_params[:, 0] # (N_p,)
        s = raw_params[:, 1:4]   # (N_p, 3)
        r = raw_params[:, 4:8]   # (N_p, 4)
        
        return {
            'alpha': alpha,
            's': s,
            'r': r,
            'mu': self.mu
        }

    def extract_volume(self, decoded_attrs: dict) -> torch.Tensor:
        """
        Extract CT density volume V from VoxGS attributes.
        
        Args:
            decoded_attrs: Output of decode_attributes.
            
        Returns:
            CT volume tensor of shape (M, N, L).
        """
        alpha = decoded_attrs['alpha'] # (N_p,)
        # Direct indexing: V(x, y, z) = alpha_i where mu_i = (x, y, z)
        # Reshape alpha to match grid dimensions
        V = alpha.view(self.M, self.N, self.L)
        return V
```

**Edge Cases and Pitfalls:**
*   **Instability with Standard 3DGS:** Directly using original 3DGS for CT leads to inaccurate volume extraction and unstable optimization in feed-forward frameworks [S1, unofficial]. VoxGS mitigates this by fixing positions and removing SH coefficients [S1, unofficial].
*   **Volume Extraction:** The fixed position design allows direct indexing of opacity $\alpha_i$ for volume extraction, avoiding complex trilinear interpolation [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Volume extraction is $O(1)$ per voxel due to direct indexing [S1, unofficial]. Rendering requires differentiable rasterization, which is efficient but depends on the number of Gaussians and views [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of voxels $N_p = M \times N \times L$, storing 8 floats per Gaussian (1 opacity, 3 scale, 4 rotation) [S1, unofficial].
*   **Strengths:** Enables efficient CT volume extraction without interpolation; supports differentiable X-ray rendering for training constraints; stable optimization for feed-forward frameworks [S1, unofficial].
*   **Limitations:** Fixed positions limit flexibility compared to optimized 3DGS; isotropic assumption (no SH) limits view-dependent color rendering [S1, unofficial].
*   **When to Use:** Sparse-view X-ray CT reconstruction where differentiable rendering and fast volume extraction are critical [S1, unofficial].
*   **When Not to Use:** Dense-view synthesis with complex view-dependent lighting where SH coefficients are necessary [S1, unofficial].

## Background
VoxGS was introduced in the X-GRM paper by [S1, unofficial] as a novel volume representation for CT reconstruction from sparse X-ray projections. It was designed to address the limitations of applying standard 3D Gaussian Splatting to CT data, specifically the instability and inaccurate volume extraction issues. The method leverages the efficient rendering of 3DGS [3D Gaussian Splatting](3d-gaussian-splatting.md) while adapting it for the specific requirements of X-ray imaging, such as isotropic density representation and differentiable projection constraints.
