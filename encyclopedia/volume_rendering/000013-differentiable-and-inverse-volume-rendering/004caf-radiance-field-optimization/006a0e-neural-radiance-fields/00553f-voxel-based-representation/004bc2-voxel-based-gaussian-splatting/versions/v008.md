# Voxel-based Gaussian Splatting


## Overview
Voxel-based Gaussian Splatting (VoxGS) is a specialized volume representation designed for efficient Computed Tomography (CT) extraction and differentiable X-ray rendering from sparse projections [S1, unofficial]. It solves the instability and inaccuracy issues inherent in applying standard 3D Gaussian Splatting (3DGS) to volumetric medical imaging by fixing Gaussian positions to a regular grid and removing view-dependent color modeling [S1, unofficial]. Unlike standard 3DGS, which optimizes primitive positions and uses Spherical Harmonics for appearance, VoxGS regresses opacity, scale, and rotation from transformer tokens, enabling direct volume extraction via indexing and stable feed-forward reconstruction [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $K$ X-ray projection images, processed into view-specific feature maps $\mathbf{F}_k \in \mathbb{R}^{H \times W \times C}$ by a Vision Transformer (ViT) encoder and fusion module [S1, unofficial].
*   **Output:** A set of $N_p$ 3D Gaussians $\mathcal{G} = \{g_i\}$ representing the CT volume, and the extracted CT density volume $V \in \mathbb{R}^{M \times N \times L}$ [S1, unofficial].

**Data Structures:**
Each Gaussian $g_i$ is defined by the following attributes. Note that the position is fixed and not stored as a learnable parameter in the same way as standard 3DGS; it is derived from the voxel grid index [S1, unofficial].

*   **Position ($\mu_i$):** Fixed at the centroid of voxel $(x, y, z)$. Not a learnable float vector in the optimization loop, but an integer index mapping to the grid.
*   **Opacity ($\alpha_i$):** `float` (scalar), range $[0, 1]$. Represents the CT density at the voxel center.
*   **Scale ($s_i$):** `float3` vector $(s_x, s_y, s_z)$. Controls the isotropic/anisotropic spread of the Gaussian kernel.
*   **Rotation ($r_i$):** `float4` vector (unit quaternion). Controls the orientation of the Gaussian kernel.
*   **Color/SH:** None. Spherical Harmonics coefficients are removed because X-ray attenuation depends on isotropic density, not view-dependent color [S1, unofficial].

**Numbered Steps:**

1.  **Grid Initialization:** Define a regular 3D voxel grid $V$ with dimensions $M \times N \times L$. The total number of Gaussians is $N_p = M \times N \times L$. For each voxel at integer coordinates $(x, y, z)$ where $x \in [1, M], y \in [1, N], z \in [1, L]$, assign a fixed Gaussian position $\mu_i = (x, y, z)^T$ [S1, unofficial].

2.  **Feature Querying:** For each Gaussian $g_i$ with fixed position $\mu_i$, and for each view $k \in \{1, \dots, K\}$:
    *   Project $\mu_i$ to the 2D image plane of view $k$ using the camera projection matrix $\mathbf{P}_k: \mathbb{R}^3 \to \mathbb{R}^2$ [S1, unofficial].
    *   Query the view-specific feature $F_k$ from the feature map $\mathbf{F}_k$ using bilinear interpolation at the projected position $\mathbf{P}_k(\mu_i)$:
        $$ F_k = \text{Interp}(\mathbf{F}_k, \mathbf{P}_k(\boldsymbol{\mu}_i)) \in \mathbb{R}^C $$
        where $\text{Interp}$ denotes bilinear interpolation [S1, unofficial].

3.  **Feature Aggregation:** Aggregate the $K$ queried features for Gaussian $g_i$ using MaxPooling to obtain a single view-invariant feature vector $F_i^{\max}$:
    $$ F_i^{\max} = \text{MaxPool}(F_i^1, F_i^2, \dots, F_i^K) \in \mathbb{R}^C $$
    where $F_i^k$ is the feature queried from view $k$ for Gaussian $i$ [S1, unofficial].

4.  **Attribute Regression:** Pass the aggregated feature $F_i^{\max}$ through a prediction Multi-Layer Perceptron (MLP), denoted as $\text{MLPS}$, to predict the Gaussian attributes:
    $$ [\alpha_i, \mathbf{s}_i, \mathbf{r}_i] = \text{MLPS}(F_i^{\max}) \in \mathbb{R}^{1+3+4} $$
    The output consists of:
    *   $\alpha_i$: Opacity (1 float).
    *   $\mathbf{s}_i$: Scale vector (3 floats).
    *   $\mathbf{r}_i$: Rotation vector (4 floats, representing a unit quaternion) [S1, unofficial].

5.  **Volume Extraction:** To extract the CT density volume $V$, directly index the opacity of the Gaussian corresponding to each voxel position:
    $$ V(x, y, z) = \alpha_i \quad \text{where} \quad \boldsymbol{\mu}_i = (x, y, z)^T $$
    This allows for fast extraction without trilinear interpolation [S1, unofficial].

6.  **Differentiable X-ray Rendering:** Render X-ray projections by accumulating the Gaussian contributions along rays. The rendering uses a rasterizer (e.g., as implemented in [75] referenced in [S1, unofficial]) to compute differentiable X-ray attenuation, allowing gradients to flow back to the MLP parameters during training [S1, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class VoxGS:
    def __init__(self, grid_dims: tuple, num_views: int, feature_dim: int, mlp_hidden_dims: list):
        """
        Initialize VoxGS representation.
        
        Args:
            grid_dims: Tuple (M, N, L) defining the voxel grid size.
            num_views: Number of X-ray projection views K.
            feature_dim: Dimension C of the view feature maps.
            mlp_hidden_dims: List of hidden dimensions for the attribute prediction MLP.
        """
        self.M, self.N, self.L = grid_dims
        self.K = num_views
        self.C = feature_dim
        self.N_p = M * N * L
        
        # Generate fixed positions for all voxels
        # Shape: (N_p, 3)
        x_coords = torch.arange(1, M + 1).unsqueeze(1).repeat(1, N * L).flatten()
        y_coords = torch.arange(1, N + 1).unsqueeze(0).repeat(M, L).flatten().unsqueeze(1).repeat(1, N).flatten() # Adjusted for correct grid traversal
        z_coords = torch.arange(1, L + 1).unsqueeze(0).repeat(M * N).unsqueeze(1).repeat(1, 1).flatten()
        
        # Correctly generating all combinations of (x, y, z)
        xx, yy, zz = torch.meshgrid(torch.arange(1, M+1), torch.arange(1, N+1), torch.arange(1, L+1), indexing='ij')
        self.mu = torch.stack([xx.flatten(), yy.flatten(), zz.flatten()], dim=1).float() # Shape: (N_p, 3)
        
        # Define the MLP to predict [alpha, scale, rotation]
        # Output dimension: 1 (alpha) + 3 (scale) + 4 (rotation) = 8
        layers = []
        prev_dim = feature_dim
        for hidden_dim in mlp_hidden_dims:
            layers.append(nn.Linear(prev_dim, hidden_dim))
            layers.append(nn.ReLU())
            prev_dim = hidden_dim
        layers.append(nn.Linear(prev_dim, 8))
        self.MLPS = nn.Sequential(*layers)
        
        # Initialize projection matrices P_k for each view (placeholder for actual camera params)
        # In practice, these are known or estimated. Here we assume they are provided or fixed for the example.
        # P_k maps 3D point to 2D image coordinates.
        self.P_k = None # To be set based on camera intrinsics/extrinsics

    def set_projection_matrices(self, P_k_list: list):
        """
        Set the projection matrices for each view.
        
        Args:
            P_k_list: List of K projection matrices, each of shape (2, 3) or (3, 4) depending on homogeneous coords.
                      Assuming 2D projection P: R^3 -> R^2 for simplicity in interpolation.
        """
        self.P_k = torch.stack(P_k_list, dim=0) # Shape: (K, 2, 3) or (K, 3, 4)

    def query_features(self, F_k_list: list, P_k: torch.Tensor) -> torch.Tensor:
        """
        Query view-specific features for all Gaussians using bilinear interpolation.
        
        Args:
            F_k_list: List of K feature maps, each of shape (H, W, C).
            P_k: Projection matrix for the current view, shape (2, 3) or (3, 4).
            
        Returns:
            Features for all Gaussians for this view, shape (N_p, C).
        """
        # Project all mu to 2D for this view
        # mu: (N_p, 3), P_k: (2, 3) -> proj: (N_p, 2)
        # Assuming P_k is (2, 3) for direct linear projection to 2D
        proj_2d = torch.matmul(self.mu, P_k.T) # Shape: (N_p, 2)
        
        # Normalize coordinates to [-1, 1] for F.grid_sample or F.interpolate
        # Assuming image size H, W. Need to map proj_2d to [0, H-1] x [0, W-1] then to [-1, 1]
        # This part depends on the specific coordinate system of F_k.
        # Standard grid_sample expects normalized coordinates in [-1, 1].
        # Let's assume proj_2d is in pixel coordinates [0, W] x [0, H].
        
        H, W = F_k_list[0].shape[0], F_k_list[0].shape[1]
        
        # Normalize to [-1, 1]
        # x in [0, W-1] -> [-1, 1] : 2*x/(W-1) - 1
        # y in [0, H-1] -> [-1, 1] : 2*y/(H-1) - 1
        # Note: grid_sample expects (x, y) order, where x is horizontal (width) and y is vertical (height).
        # proj_2d[:, 0] is likely x (width), proj_2d[:, 1] is likely y (height).
        
        x_norm = 2.0 * proj_2d[:, 0] / (W - 1) - 1.0
        y_norm = 2.0 * proj_2d[:, 1] / (H - 1) - 1.0
        
        # grid_sample expects input of shape (N, C, H, W) and grid of shape (N, H_out, W_out, 2)
        # We want to sample N_p points from 1x1 grid.
        # Reshape for grid_sample
        F_k_4d = F_k_list[0].unsqueeze(0).unsqueeze(0) # (1, 1, H, W)
        grid = torch.stack([x_norm, y_norm], dim=1).unsqueeze(0).unsqueeze(0).unsqueeze(0) # (1, 1, 1, N_p, 2)
        
        # Sample
        # F.grid_sample output: (1, C, 1, N_p)
        sampled = F.grid_sample(F_k_4d, grid, align_corners=False, mode='bilinear') # Shape: (1, C, 1, N_p)
        
        # Reshape to (N_p, C)
        return sampled.squeeze(0).squeeze(0).permute(1, 0) # (N_p, C)

    def forward(self, F_k_list: list) -> dict:
        """
        Forward pass to predict VoxGS attributes.
        
        Args:
            F_k_list: List of K feature maps, each of shape (H, W, C).
            
        Returns:
            Dictionary containing alpha, scale, rotation, and extracted volume.
        """
        # Aggregate features from all views
        all_features = []
        for k in range(self.K):
            # Query features for view k
            # Assuming self.P_k[k] is the projection matrix for view k
            F_k = self.query_features(F_k_list, self.P_k[k])
            all_features.append(F_k)
            
        # Stack features: (K, N_p, C)
        all_features = torch.stack(all_features, dim=0)
        
        # MaxPool over views: (N_p, C)
        F_max = torch.max(all_features, dim=0)[0]
        
        # Predict attributes
        # Output: (N_p, 8) -> [alpha, s_x, s_y, s_z, r_x, r_y, r_z, r_w]
        pred = self.MLPS(F_max)
        
        alpha = pred[:, 0]
        scale = pred[:, 1:4]
        rotation = pred[:, 4:8]
        
        # Extract volume
        # V is a 3D tensor of shape (M, N, L)
        # alpha is (N_p,) where N_p = M*N*L
        # We need to reshape alpha to (M, N, L)
        V = alpha.view(self.M, self.N, self.L)
        
        return {
            'alpha': alpha,
            'scale': scale,
            'rotation': rotation,
            'volume': V
        }
```

**Parameters:**
*   **Grid Dimensions ($M, N, L$):** Determined by the desired resolution of the CT volume. Not given in the sources.
*   **Number of Views ($K$):** Number of X-ray projections. Not given in the sources.
*   **Feature Dimension ($C$):** Dimension of the view feature maps output by the ViT. Not given in the sources.
*   **MLP Architecture:** The number of layers and hidden dimensions for $\text{MLPS}$ is not specified in the sources. [G] A typical choice might be 2-3 hidden layers with 256-512 units.

**Edge Cases and Pitfalls:**
*   **Direct 3DGS Application:** Using standard 3DGS for CT leads to inaccurate volume extraction and unstable optimization in feed-forward frameworks [S1, unofficial]. VoxGS mitigates this by fixing positions and removing SH coefficients [S1, unofficial].
*   **Trilinear Interpolation:** Standard volume extraction from Gaussians requires trilinear interpolation, which is slow. VoxGS avoids this by direct indexing [S1, unofficial].
*   **View-Dependent Color:** X-ray attenuation is isotropic. Including SH coefficients for color is unnecessary and potentially harmful for density estimation [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The dominant cost is the feature querying and aggregation for all $N_p$ Gaussians across $K$ views. Querying involves bilinear interpolation for each Gaussian per view, which is $O(N_p \cdot K)$. The MLP prediction is $O(N_p)$. Volume extraction is $O(1)$ per voxel due to direct indexing.
*   **Memory Complexity:** Storage for $N_p$ Gaussians, each with 8 floats (1 alpha, 3 scale, 4 rotation), is $O(N_p)$. Feature maps storage is $O(K \cdot H \cdot W \cdot C)$.
*   **Measured Performance:** X-GRM with VoxGS reconstructs CT volumes within one second from sparse X-ray inputs, outperforming SOTA methods in both reconstruction quality and inference speed [S1, unofficial].
*   **Strengths:** Fast volume extraction via indexing; stable optimization for feed-forward models; differentiable X-ray rendering for training constraints.
*   **Limitations:** Fixed positions limit flexibility compared to standard 3DGS; requires pre-computed view features from a Transformer; not suitable for general novel view synthesis with arbitrary camera poses without retraining the feature extractor.

## Background
Voxel-based Gaussian Splatting (VoxGS) was introduced in the paper "X-GRM: Large Gaussian Reconstruction Model for Sparse-view X-rays to Computed Tomography" [S1, unofficial]. It was developed to address the limitations of existing 3DGS variants when applied to CT reconstruction, specifically the instability of optimizing Gaussian positions and the inaccuracy of volume extraction. The method leverages the efficient rendering of 3DGS [28] but adapts it for volumetric medical imaging by fixing positions to a voxel grid and removing view-dependent color components.
