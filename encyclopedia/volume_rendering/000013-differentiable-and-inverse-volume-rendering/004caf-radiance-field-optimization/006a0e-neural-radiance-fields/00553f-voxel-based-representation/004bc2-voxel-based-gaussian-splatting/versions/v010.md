# Voxel-based Gaussian Splatting

Also called: VoxGS

## Overview
Voxel-based Gaussian Splatting (VoxGS) is a volume representation that places isometric 3D Gaussians at the fixed centroids of a regular 3D voxel grid to enable efficient Computed Tomography (CT) volume extraction and differentiable X-ray rendering [S1, unofficial]. Unlike standard 3D Gaussian Splatting (3DGS) which optimizes primitive positions and uses spherical harmonics for view-dependent color, VoxGS fixes positions and removes color coefficients, retaining only opacity, scale, and rotation to support isotropic density modeling [S1, unofficial]. This design solves the instability and inaccurate volume extraction issues associated with applying original 3DGS directly to CT data [S1, unofficial].

## How it works
**Inputs:** A set of $K$ X-ray projection images, each associated with a camera projection matrix $\mathbf{P}_k$. The scene is discretized into a 3D voxel grid of dimensions $M \times N \times L$.

**Outputs:** A set of $N_p = M \times N \times L$ 3D Gaussians $\mathcal{G} = \{g_i\}$, where each $g_i$ is defined by its attributes. The system can output a dense CT density volume $V \in \mathbb{R}^{M \times N \times L}$ or differentiable X-ray projections.

**Data Structures:**
Each Gaussian $g_i$ is stored with the following attributes:
*   **Position $\boldsymbol{\mu}_i$:** Fixed 3D vector $(x, y, z)$ corresponding to the integer coordinates of the voxel centroid. $x \in [1, M], y \in [1, N], z \in [1, L]$. This is not a learnable parameter but an index into the grid [S1, unofficial].
*   **Opacity $\alpha_i$:** A single scalar float representing the density/attenuation at that voxel.
*   **Scale $\mathbf{s}_i$:** A 3D vector $(s_x, s_y, s_z)$ controlling the anisotropy of the Gaussian kernel.
*   **Rotation $\mathbf{r}_i$:** A 4D quaternion $(w, x, y, z)$ controlling the orientation of the Gaussian kernel.
*   **Note:** Spherical Harmonic (SH) coefficients for color are explicitly removed, as X-ray attenuation is isotropic [S1, unofficial].

**Numbered Steps:**

1.  **Grid Initialization:** Define a regular 3D voxel grid with dimensions $M \times N \times L$. Assign a fixed position $\boldsymbol{\mu}_i = (x, y, z)^T$ to each Gaussian $g_i$ corresponding to the centroid of voxel $(x, y, z)$ [S1, unofficial].

2.  **Feature Querying:** For each Gaussian $g_i$ at position $\boldsymbol{\mu}_i$, and for each view $k \in \{1, \dots, K\}$:
    *   Project the 3D position $\boldsymbol{\mu}_i$ onto the 2D image plane of view $k$ using the projection matrix $\mathbf{P}_k$: $\mathbf{p}_k = \mathbf{P}_k(\boldsymbol{\mu}_i)$.
    *   Query the view-specific feature vector $\mathbf{F}_k$ from the pre-computed view feature map $\mathbf{F}_k$ (output of a Vision Transformer encoder) using bilinear interpolation at $\mathbf{p}_k$:
        $$
        \mathbf{F}_k = \text{Interp}(\mathbf{F}_k, \mathbf{p}_k) \in \mathbb{R}^C
        $$
        where $C$ is the feature dimension [S1, unofficial].

3.  **Feature Aggregation:** Aggregate the $K$ queried view-specific features $\{\mathbf{F}_1, \dots, \mathbf{F}_K\}$ for Gaussian $g_i$ using MaxPooling to obtain a single fused feature vector $\mathbf{F}_{max}^i$:
    $$
    \mathbf{F}_{max}^i = \text{MaxPool}(\mathbf{F}_1, \dots, \mathbf{F}_K) \in \mathbb{R}^C
    $$
    [S1, unofficial].

4.  **Attribute Regression:** Pass the fused feature $\mathbf{F}_{max}^i$ through a prediction Multi-Layer Perceptron (MLP), denoted as $MLPS$, to predict the Gaussian parameters:
    $$
    [\alpha_i, \mathbf{s}_i, \mathbf{r}_i] = MLPS(\mathbf{F}_{max}^i) \in \mathbb{R}^{1+3+4}
    $$
    where $\alpha_i$ is opacity (1 float), $\mathbf{s}_i$ is scale (3 floats), and $\mathbf{r}_i$ is rotation (4 floats, quaternion) [S1, unofficial].

5.  **Volume Extraction:** To extract the CT density volume $V$, directly index the predicted opacity $\alpha_i$ using the fixed position $\boldsymbol{\mu}_i$:
    $$
    V(x, y, z) = \alpha_i \quad \text{where} \quad \boldsymbol{\mu}_i = (x, y, z)^T
    $$
    This allows for $O(1)$ extraction without trilinear interpolation [S1, unofficial].

6.  **Differentiable X-ray Rendering:** Render X-ray projections by integrating the Gaussian kernels along rays. The opacity $\alpha_i$ and scale $\mathbf{s}_i$ define the attenuation profile. The rasterizer used is typically adapted from 3DGS implementations (e.g., [75] in source) to support differentiable rendering of these isotropic Gaussians [S1, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class VoxGS:
    def __init__(self, grid_dims: tuple, feature_dim: int, mlp_hidden_dims: list):
        """
        Initialize VoxGS representation.
        
        Args:
            grid_dims: Tuple (M, N, L) defining the 3D voxel grid size.
            feature_dim: Dimension C of the input view features from the Transformer.
            mlp_hidden_dims: List of hidden layer sizes for the attribute prediction MLP.
        """
        self.M, self.N, self.L = grid_dims
        self.num_gaussians = self.M * self.N * self.L
        
        # Fixed positions: (N_p, 3)
        # Generate meshgrid and reshape to list of centroids
        x = torch.arange(1, self.M + 1).float()
        y = torch.arange(1, self.N + 1).float()
        z = torch.arange(1, self.L + 1).float()
        xx, yy, zz = torch.meshgrid(x, y, z, indexing='ij')
        self.positions = torch.stack([xx, yy, zz], dim=-1).reshape(-1, 3) # (N_p, 3)
        
        # Learnable MLP to predict [alpha, scale, rotation]
        # Output dim: 1 (alpha) + 3 (scale) + 4 (rotation) = 8
        layers = []
        prev_dim = feature_dim
        for hidden_dim in mlp_hidden_dims:
            layers.append(nn.Linear(prev_dim, hidden_dim))
            layers.append(nn.ReLU())
            prev_dim = hidden_dim
        layers.append(nn.Linear(prev_dim, 8))
        self.mlp = nn.Sequential(*layers)
        
        # Initialize attributes
        self.alpha = torch.ones(self.num_gaussians) # Initial opacity
        self.scale = torch.ones(self.num_gaussians, 3) # Initial scale
        self.rotation = torch.zeros(self.num_gaussians, 4) # Initial rotation (identity quaternion)
        
    def query_and_decode(self, view_features: torch.Tensor, projection_matrices: list):
        """
        Query view features and decode Gaussian attributes.
        
        Args:
            view_features: List of K tensors, each (H, W, C) or (C, H, W).
            projection_matrices: List of K projection matrices P_k (3x3 or 4x4).
            
        Returns:
            alpha: (N_p,)
            scale: (N_p, 3)
            rotation: (N_p, 4)
        """
        K = len(view_features)
        C = view_features[0].shape[-1]
        
        # 1. Query view-specific features for each Gaussian
        # F_k for each view k: (N_p, C)
        queried_features = []
        for k in range(K):
            F_k = view_features[k] # (H, W, C)
            P_k = projection_matrices[k]
            
            # Project positions to 2D
            # Assuming homogeneous coordinates for projection
            pos_homo = torch.cat([self.positions, torch.ones(self.num_gaussians, 1)], dim=-1) # (N_p, 4)
            proj_2d_homo = pos_homo @ P_k.T # (N_p, 3) or (N_p, 4) depending on P_k
            proj_2d = proj_2d_homo[:, :2] / proj_2d_homo[:, 2:3] # (N_p, 2)
            
            # Bilinear interpolation
            # Normalize proj_2d to [-1, 1] range for F.grid_sample or F.interpolate
            # Assuming proj_2d is in pixel coordinates, need to map to [-1, 1]
            H, W = F_k.shape[0], F_k.shape[1]
            norm_x = (proj_2d[:, 0] / (W - 1) * 2 - 1)
            norm_y = (proj_2d[:, 1] / (H - 1) * 2 - 1)
            grid = torch.stack([norm_x, norm_y], dim=-1).unsqueeze(0).unsqueeze(0) # (1, 1, N_p, 2)
            
            # F_k needs to be (1, C, H, W) for grid_sample
            F_k_tensor = F_k.permute(2, 0, 1).unsqueeze(0) # (1, C, H, W)
            
            # Interpolate
            F_k_interp = F.grid_sample(F_k_tensor, grid, mode='bilinear', align_corners=False) # (1, C, 1, N_p)
            F_k_interp = F_k_interp.squeeze(0).squeeze(2).permute(1, 0) # (C, N_p) -> (N_p, C)
            queried_features.append(F_k_interp)
            
        # 2. Aggregate using MaxPooling
        # Stack features: (K, N_p, C)
        stacked_features = torch.stack(queried_features, dim=0)
        # MaxPool over K views: (N_p, C)
        fused_features = torch.max(stacked_features, dim=0).values
        
        # 3. Decode attributes
        # Output: (N_p, 8)
        decoded = self.mlp(fused_features)
        
        alpha = decoded[:, 0]
        scale = decoded[:, 1:4]
        rotation = decoded[:, 4:8]
        
        return alpha, scale, rotation

    def extract_volume(self, alpha: torch.Tensor):
        """
        Extract CT density volume from opacities.
        
        Args:
            alpha: (N_p,) tensor of opacities.
            
        Returns:
            volume: (M, N, L) tensor.
        """
        volume = alpha.reshape(self.M, self.N, self.L)
        return volume
```

**Parameters:**
*   **Grid Dimensions ($M, N, L$):** Determined by the desired resolution of the CT volume. Not given in the sources.
*   **Number of Views ($K$):** Number of X-ray projections. Not given in the sources.
*   **Feature Dimension ($C$):** Dimension of the view features from the Vision Transformer. Not given in the sources.
*   **MLP Architecture:** Number of hidden layers and dimensions. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Position Fixing:** The positions $\boldsymbol{\mu}_i$ are fixed and not optimized. This prevents the instability seen in standard 3DGS when applied to CT [S1, unofficial].
*   **No Color SH:** Spherical Harmonic coefficients are removed. This is appropriate for X-ray/CT where attenuation is isotropic, but makes the representation unsuitable for view-dependent color rendering without modification [S1, unofficial].
*   **Volume Extraction:** Direct indexing relies on the exact mapping between Gaussian index and voxel coordinates. Misalignment in grid generation will cause incorrect volume extraction [S1, unofficial].

## Subtopics

### 3D Gaussian Splatting (3DGS)
The parent method that VoxGS adapts. 3DGS uses learnable positions and SH coefficients for real-time rasterization of point clouds. VoxGS fixes positions and removes SH for CT [S1, unofficial]. [3D Gaussian Splatting](52-3d-gaussian-splatting.md)

### Neural Radiance Fields (NeRF)
The foundational method for differentiable volume rendering. NeRF uses a continuous MLP, whereas VoxGS uses a discrete grid with Gaussian kernels [S1, unofficial]. [Neural Radiance Fields](44-neural-radiance-fields.md)

## Operating characteristics
*   **Time Complexity:** Volume extraction is $O(1)$ per voxel due to direct indexing, significantly faster than trilinear interpolation used in standard 3DGS or NeRF [S1, unofficial]. Rendering complexity depends on the rasterizer implementation but is optimized for real-time performance similar to 3DGS [S1, unofficial].
*   **Memory Complexity:** Stores $N_p = M \times N \times L$ Gaussians, each with 8 floats (1 alpha, 3 scale, 4 rotation). This is comparable to 3DGS but avoids storing SH coefficients [S1, unofficial].
*   **Performance:** X-GRM using VoxGS reconstructs CT volumes within one second from sparse X-ray projections, outperforming SOTA methods in both quality and speed [S1, unofficial].
*   **Strengths:** Precise volume extraction, stable optimization for feed-forward frameworks, differentiable X-ray rendering [S1, unofficial].
*   **Limitations:** Not suitable for view-dependent color rendering due to removal of SH coefficients. Requires a pre-computed feature map from a Vision Transformer [S1, unofficial].

## Background
VoxGS was introduced in the paper "X-GRM: Large Gaussian Reconstruction Model for Sparse-view X-rays to Computed Tomography" [S1, unofficial]. It was developed to address the limitations of applying standard 3DGS to CT data, specifically the inaccurate volume extraction and unstable optimization in feed-forward frameworks. By fixing Gaussian positions to voxel centroids and removing view-dependent color, VoxGS enables efficient and stable CT reconstruction from sparse X-ray projections [S1, unofficial].
