# 3D Gaussian Particle Approximation of VDB Datasets

Also called: Gaussian Particle Approximation, Gaussian Particle Rendering, VDB to Gaussian Conversion

## Overview
This method converts OpenVDB volumetric datasets into a set of non-overlapping 3D Gaussian particles to enable memory-efficient, lossy representation with Level of Detail (LOD) support [S1, unofficial]. It solves the problem of rendering large sparse volumetric data in real-time by replacing dense voxel grids with a sparse set of Gaussian primitives that can be accelerated via hardware ray tracing [S1, unofficial]. Unlike standard Gaussian Splatting which often uses overlapping primitives for dense scene representation, this approach leverages the strictly non-overlapping nature of OpenVDB leaf nodes to create a simplified, axis-aligned particle system [S1, unofficial]. It is distinct from [Opacity-Independent Gaussian Truncation](10266-opacity-independent-gaussian-truncation.md) in that it does not rely on opacity-independent culling thresholds but rather on structural LOD aggregation of the source VDB grid [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** An OpenVDB grid (not NanoVDB) containing scalar field data or level-set data.
*   **Output:** A set of $N$ 3D Gaussian particles, each defined by position, covariance, and opacity, stored in contiguous device-side buffers for rendering via NVIDIA OptiX.

**Data Structures:**
The method uses a `GaussianModel` object on the GPU containing pointers to contiguous arrays for each property [S1, unofficial]:
1.  **Position (`float3`):** World-space centroid derived from the voxel region's bounding box or centroid [S1, unofficial].
2.  **Covariance (`float3` or `float`):**
    *   For ellipsoids: A diagonal vector representing the 3x3 covariance matrix diagonal (axis-aligned) [S1, unofficial].
    *   For spheres: A single scalar value [S1, unofficial].
3.  **Opacity (`float`):** A scalar reflecting the average density/value of the voxel region [S1, unofficial]. For level sets, this may be uniform [S1, unofficial].
4.  **Acceleration Structure:**
    *   **GAS (Geometry Acceleration Structure):** Built on the GPU using a CUDA device-side array of Axis-Aligned Bounding Boxes (AABBs). Each AABB encloses a single Gaussian particle, defined by min/max coordinates in OpenVDB Index Space [S1, unofficial].
    *   **IAS (Instance Acceleration Structure):** Stores the GAS instance with the OpenVDB Grid transform [S1, unofficial].

**Numbered Steps:**

1.  **Data Generation (CPU):**
    *   Retrieve all leaf nodes from the OpenVDB Grid Tree using the OpenVDB API [S1, unofficial].
    *   Verify "Tiled" data storage; exclude leaf nodes that are fully tiled (homogeneous) as their value is stored in the parent node's value mask [S1, unofficial].
    *   Apply LOD rules to derive Gaussian properties for each active leaf node or cluster:
        *   **Low LOD:** Each leaf node becomes a single Gaussian reflecting the distribution of active voxels [S1, unofficial].
        *   **Medium LOD:** Dense leaf nodes merge active voxels into $4 \times 4 \times 4$ groups; sparse leaf nodes merge into $2 \times 2 \times 2$ groups. Remaining voxels become individual Gaussians [S1, unofficial].
        *   **High LOD:** Sparse leaf nodes contribute one Gaussian per active voxel; dense leaf nodes merge into $2 \times 2 \times 2$ blocks [S1, unofficial].
    *   Compute Position (centroid/bounding box center), Opacity (average scalar value), and Covariance (diagonal vector based on spatial extent) [S1, unofficial].

2.  **Buffer Transfer (CPU to GPU):**
    *   Allocate contiguous device-side buffers using `cudaMalloc` for Position, Covariance, and Opacity [S1, unofficial].
    *   Copy data from host to device using `cudaMemcpy` [S1, unofficial].
    *   Store device pointers in a `GaussianModel` object [S1, unofficial].

3.  **Acceleration Structure Build (GPU):**
    *   Build the GAS using `optixAccelBuild` with flags `OPTIX_BUILD_FLAG_ALLOW_COMPACTION` and `OPTIX_BUILD_INPUT_TYPE_CUSTOM_PRIMITIVES` [S1, unofficial].
    *   Input is the array of AABBs enclosing each Gaussian [S1, unofficial].
    *   Build the IAS using the OpenVDB Grid transform [S1, unofficial].
    *   Set visibility masks for all Gaussians to visible for primary and continuation rays [S1, unofficial].

4.  **Rendering Loop (GPU/OptiX):**
    *   **Ray Generation:** Shoot primary rays from the camera using the `__raygen__` program [S1, unofficial].
    *   **Intersection Test (`__intersection__`):**
        *   Use the primitive index to retrieve the Gaussian's AABB [S1, unofficial].
        *   Perform ray-box intersection with the world AABB [S1, unofficial].
        *   If intersected, retrieve the Gaussian's center $\mu$ and inverse covariance $\Sigma^{-1}$ [S1, unofficial].
        *   Transform the ray into the Gaussian's local space using the inverse covariance matrix [S1, unofficial].
        *   Solve the quadratic equation for the ray-ellipsoid/sphere intersection to find entry ($t_0$) and exit ($t_1$) distances [S1, unofficial].
        *   Store $t_0$ and $t_1$ in the payload and exit the intersection shader early [S1, unofficial].
    *   **Ray Marching and Density Evaluation:**
        *   Step along the ray within $[t_0, t_1]$ using a predefined step size $\Delta t$ [S1, unofficial].
        *   For each sample point $x_k$, compute the difference $\delta = x_k - \mu$ [S1, unofficial].
        *   Compute the squared Mahalanobis distance $D^2 = \delta^\top \Sigma^{-1} \delta$ [S1, unofficial].
        *   Evaluate density $\rho_k = \exp(-D^2/2)$ [S1, unofficial].
    *   **Absorption and Transmittance Update:**
        *   Compute `volume_factor` = $1/\det(\Sigma)$ [S1, unofficial].
        *   Calculate absorption $A_k = \rho_k \cdot \Delta t \cdot \text{volume\_factor}$ [S1, unofficial].
        *   Update accumulated color $C$ and transmittance $T$:
            $$ C \leftarrow C + T \cdot c(\sigma_k) \cdot A_k $$
            $$ T \leftarrow T \cdot \exp(-A_k) $$
            where $c(\sigma_k)$ is the scattering color derived from opacity $\sigma_k$ via a transfer function [S1, unofficial].
    *   **Ray Continuation:**
        *   Advance the ray origin: $o_{new} = o + d \cdot (t_1 - t_0)$ [S1, unofficial].
        *   Recursively trace the next Gaussian using `optixTrace` with `RAY_TYPE_RADIANCE` [S1, unofficial].
        *   Terminate if recursion depth exceeds a maximum (e.g., 10) or transmittance is negligible [S1, unofficial].

**Pseudocode:**

```python
# GaussianModel contains device pointers: pos (float3), cov (float3 or float), opacity (float)
# GAS contains AABBs for each Gaussian

def raygen():
    ray = generate_camera_ray()
    payload = {
        'color': (0.0, 0.0, 0.0),
        'transmittance': 1.0,
        'recursion_depth': 0
    }
    result = optixTrace(ray, payload, ray_type=RAY_TYPE_RADIANCE)
    payload['color'] += payload['transmittance'] * result
    return payload['color']

def intersection(primitive_index):
    # Retrieve AABB for the Gaussian at primitive_index
    aabb = get_aabb(primitive_index)
    
    if not ray_box_intersect(ray, aabb):
        return # No intersection
    
    # Retrieve Gaussian properties
    mu = get_position(primitive_index)
    cov = get_covariance(primitive_index)
    inv_cov = inverse(cov)
    
    # Transform ray to local space and solve quadratic for ellipsoid/sphere
    # Returns entry t0 and exit t1
    t0, t1 = solve_ray_gaussian_intersection(ray, mu, inv_cov)
    
    # Store in payload for closest-hit
    payload['t0'] = t0
    payload['t1'] = t1
    payload['primitive_index'] = primitive_index
    return # Exit early

def closesthit():
    t0 = payload['t0']
    t1 = payload['t1']
    idx = payload['primitive_index']
    
    mu = get_position(idx)
    cov = get_covariance(idx)
    opacity_val = get_opacity(idx)
    
    # Determine step size based on distance
    # Note: The source uses a predefined step size or distance between entry/exit
    # For simplicity, we assume a fixed step or adaptive step within t0-t1
    step_size = (t1 - t0) / num_samples # num_samples is a parameter
    
    volume_factor = 1.0 / determinant(cov)
    
    current_t = t0
    while current_t < t1:
        # Sample point in world space
        xk = ray.origin + ray.direction * current_t
        
        # Density evaluation
        delta = xk - mu
        D2 = dot(delta, multiply(inv_cov, delta)) # delta^T Sigma^-1 delta
        rho_k = exp(-0.5 * D2)
        
        # Absorption
        absorption = rho_k * step_size * volume_factor
        
        # Color and Transmittance update
        # c(sigma_k) is obtained via transfer function lookup using opacity_val
        scattering_color = transfer_function(opacity_val)
        
        payload['color'] += payload['transmittance'] * scattering_color * absorption
        payload['transmittance'] *= exp(-absorption)
        
        current_t += step_size
        
    # Advance ray origin for next intersection
    # Note: In the recursive loop, the ray origin is updated after processing this Gaussian
    # This is handled in the recursive call logic below
    pass

def recursive_ray_trace(ray, max_depth):
    payload = {
        'color': (0.0, 0.0, 0.0),
        'transmittance': 1.0,
        'recursion_depth': 0
    }
    
    while payload['recursion_depth'] < max_depth:
        # Intersect with world AABB (GAS)
        if not intersect_world_aabb(ray):
            break
            
        # Find first intersecting Gaussian
        hit_idx = find_first_gaussian_hit(ray)
        
        if hit_idx == -1:
            break
            
        # Perform intersection test to get t0, t1
        # This populates payload with t0, t1, hit_idx
        intersection(hit_idx)
        
        t0 = payload['t0']
        t1 = payload['t1']
        
        # March through the Gaussian
        closesthit()
        
        # Update ray origin for next iteration
        ray.origin = ray.origin + ray.direction * (t1 - t0)
        
        payload['recursion_depth'] += 1
        
    return payload['color']
```

**Parameters:**
*   **Grid Layout:** The '5-4-3' variant is used (Root -> 25x25x25 nodes -> 24x24x24 nodes -> 23x23x23 leaf nodes) [S1, unofficial].
*   **Build Flags:** `OPTIX_BUILD_FLAG_ALLOW_COMPACTION`, `OPTIX_BUILD_INPUT_TYPE_CUSTOM_PRIMITIVES` [S1, unofficial].
*   **Ray Type:** `RAY_TYPE_RADIANCE` (forward ray marching only) [S1, unofficial].
*   **Max Recursion Depth:** Typically limited by OptiX register constraints; sources mention breaking if depth > 10 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Non-overlapping Constraint:** The implementation assumes non-overlapping Gaussians because OpenVDB leaf nodes are strictly non-overlapping [S1, unofficial]. This limits the model to three overarching refinement levels and introduces lossiness [S1, unofficial].
*   **NanoVDB Incompatibility:** NanoVDB cannot be used for generation or rendering in this pipeline because it lacks device-side iterators and Grid Tree traversal support, which are required for random access in ray-particle intersections [S1, unofficial].
*   **OptiX Register Constraint:** Propagating state via recursive `optixTrace` calls is limited by OptiX’s 8-payload register constraint, which can cause sub-optimal accumulation and inconsistent resetting of payload values [S1, unofficial].
*   **Transfer Functions:** Color is not baked into Gaussians; it is applied via transfer functions (colormap lookups) during rendering [S1, unofficial].

## Operating characteristics
*   **Performance:** The renderer consistently provides above 150 FPS for tested datasets (bunny_cloud, explosion, fire, utahteapot, venusstatue, dragon) across all LODs, even with millions of Gaussians [S1, unofficial].
*   **Memory Footprint:**
    *   **Dragon Dataset (High LOD):** 546 MB, 23.3M Gaussians [S1, unofficial].
    *   **Dragon Dataset (Low LOD):** 174.4 MB, 7.4M Gaussians [S1, unofficial].
    *   Memory usage depends on the ratio of spheres (1 float covariance) to ellipsoids (3 floats covariance) and whether opacity is stored per Gaussian or uniform (level sets) [S1, unofficial].
*   **Strengths:** Real-time performance via hardware-accelerated ray tracing (OptiX); memory efficiency through sparse VDB representation and LOD; support for transfer functions [S1, unofficial].
*   **Limitations:** Lossy representation due to non-overlapping constraint; limited to three LOD levels in current implementation; NanoVDB cannot be used; recursive tracing limited by register constraints [S1, unofficial].
*   **When to use:** Scientific visualization (SciVis) of large sparse volumetric datasets where real-time performance is critical and photorealistic overlapping Gaussian blending is not required [S1, unofficial].
*   **When not to use:** Photorealistic rendering requiring overlapping Gaussian mixture models; scenes requiring NanoVDB integration; applications needing fine-grained, non-LOD-based opacity-independent truncation [S1, unofficial].

## Background
This method was introduced in a study for Scientific Visualization (SciVis) that explores the integration of OpenVDB and NVIDIA OptiX [S1, unofficial]. It builds on the popularity of 3D Gaussian approximation in stereoscopic image-to-3D scene conversion (Gaussian Splatting) [S1, unofficial]. The work distinguishes itself from previous Gaussian mixture models in SciVis (e.g., Jang et al.) by leveraging OpenVDB's memory compaction and OptiX's hardware acceleration [S1, unofficial]. It was developed to handle large challenging datasets efficiently, moving away from dense scalar field rendering [S1, unofficial].
