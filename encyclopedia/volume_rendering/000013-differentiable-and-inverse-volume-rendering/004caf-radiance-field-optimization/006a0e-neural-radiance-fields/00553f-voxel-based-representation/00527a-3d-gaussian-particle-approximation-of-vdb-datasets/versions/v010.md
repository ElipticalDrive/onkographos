# 3D Gaussian Particle Approximation of VDB Datasets

Also called: Gaussian Particle Approximation, Gaussian Particle Rendering, VDB to Gaussian Conversion

## Overview
This method converts OpenVDB volumetric datasets into a set of non-overlapping 3D Gaussian particles to enable memory-efficient, lossy representation with Level of Detail (LOD) support, rendered via forward ray marching using NVIDIA OptiX [S1, unofficial]. It differs from standard voxel-based representations by replacing the discrete grid sampling with continuous Gaussian primitives, allowing for hardware-accelerated bounding box intersections and real-time performance with millions of particles, while maintaining compatibility with traditional volume rendering transfer functions [S1, unofficial].

## How it works

### Inputs and Outputs
*   **Input:** An OpenVDB grid containing volumetric or level-set data.
*   **Output:** A rendered image $\hat{C}(\mathbf{r})$ and a GPU-resident data structure of Gaussian particles.

### Data Structures

**Gaussian Model**
A parent class containing device-side pointers to contiguous arrays allocated via `cudaMalloc`. Each array corresponds to a specific Gaussian property:
1.  **Opacity:** Scalar array. For volumes, this stores the density value reflecting the average scalar value of the voxel region. For level sets, opacity is uniform and may not require per-particle storage [S1, unofficial].
2.  **World Position:** 3D vector array. Defined as the center in world space, derived from the centroid of the voxel region or its bounding box [S1, unofficial].
3.  **Covariance:** 3D vector array (for ellipsoids) or scalar array (for spheres). Defined as the diagonal vector of the 3x3 covariance matrix representing spatial extent. Since Gaussians are axis-aligned, off-diagonal elements are zero [S1, unofficial].

**Acceleration Structures**
*   **Geometry Acceleration Structure (GAS):** Built on the CUDA device side using an array of Axis-Aligned Bounding Boxes (AABBs). Each AABB encloses a single Gaussian particle, defined by its minimum and maximum coordinates in OpenVDB Index Space.
    *   Build Flags: `OPTIX_BUILD_FLAG_ALLOW_COMPACTION`, `OPTIX_BUILD_INPUT_TYPE_CUSTOM_PRIMITIVES` [S1, unofficial].
*   **Instance Acceleration Structure (IAS):** Stores the GAS instance with the OpenVDB Grid transform. Visibility masks are set for all Gaussians to be visible for primary and continuation rays [S1, unofficial].

**OptiX Hit Group**
*   **HitGroupRecord:** Initialized for Gaussian particles rendering. Specifies the shaders (`__intersection__`, `__closesthit__`) associated with the Gaussian primitive. Contains a pointer to the `GaussianModel` object [S1, unofficial].

### Algorithm Steps

#### 1. Data Generation (CPU)
1.  Retrieve all leaf nodes from the OpenVDB Grid Tree using the OpenVDB API [S1, unofficial].
2.  For each leaf node (or cluster based on LOD), derive Gaussian properties:
    *   **Position:** Centroid of the voxel region/bounding box.
    *   **Opacity:** Average scalar value of the active voxels in the region.
    *   **Covariance:** Diagonal vector of the covariance matrix.
3.  Apply LOD rules (see Parameters) to determine the number and size of Gaussians.
4.  Copy all Gaussian properties to contiguous device-side buffers using `cudaMalloc` and `cudaMemcpy`. Store device pointers in a `GaussianModel` object [S1, unofficial].

#### 2. Acceleration Structure Build (GPU)
1.  Build the GAS using the device-side array of AABBs derived from Gaussian extents [S1, unofficial].
2.  Create the IAS linking the GAS to the OpenVDB grid transform [S1, unofficial].

#### 3. Ray Tracing Pipeline (GPU)
The renderer uses a recursive forward-ray-marching approach with `RAY_TYPE_RADIANCE` [S1, unofficial].

1.  **Ray Generation:** Shoot primary rays from the camera using the `__raygen__` program [S1, unofficial].
2.  **Intersection Test (`__intersection__`):**
    *   Use the primitive index to retrieve the Gaussian AABB.
    *   Perform ray-box intersection with the world AABB.
    *   If intersected, retrieve the Gaussian's center $\boldsymbol{\mu}$ and inverse covariance $\boldsymbol{\Sigma}^{-1}$.
    *   Transform the ray into the Gaussian's local space.
    *   Solve the quadratic equation to find entry ($t_0$) and exit ($t_1$) distances.
    *   Store $t_0$ and $t_1$ in the payload and exit early [S1, unofficial].
3.  **Ray Marching and Density Evaluation:**
    *   Step along the ray from $t_0$ to $t_1$ using a predefined step size $\Delta t$ (distance between entry and exit points, or a fixed fraction thereof).
    *   For each sample point $\mathbf{x}_k$, compute the difference $\boldsymbol{\delta} = \mathbf{x}_k - \boldsymbol{\mu}$.
    *   Compute the squared Mahalanobis distance:
        $$ D^2 = \boldsymbol{\delta}^\top \boldsymbol{\Sigma}^{-1} \boldsymbol{\delta} $$
    *   Evaluate density:
        $$ \rho_k = \exp\left(-\frac{D^2}{2}\right) $$
4.  **Absorption and Transmittance Update:**
    *   Compute volume factor:
        $$ \text{volume\_factor} = \frac{1}{\det(\boldsymbol{\Sigma})} $$
    *   Calculate absorption:
        $$ A_k = \rho_k \cdot \Delta t \cdot \text{volume\_factor} $$
    *   Update color and transmittance:
        $$ C \leftarrow C + T_k \cdot c(\sigma_k) \cdot A_k $$
        $$ T_k \leftarrow T_k \cdot \exp(-A_k) $$
        Where $c(\sigma_k)$ is the scattering color derived from opacity via a transfer function [S1, unofficial].
5.  **Ray Continuation:**
    *   Advance the ray origin: $\mathbf{o}_{new} = \mathbf{o} + \mathbf{d} \cdot (t_1 - t_0)$.
    *   Recursively trace the next Gaussian using `optixTrace` [S1, unofficial].

### Pseudocode

```python
# Gaussian Model Data Layout
# opacity: float array [N]
# position: float3 array [N]
# covariance_diag: float3 array [N] (or float [N] for spheres)

def recursive_ray_trace(ray_origin, ray_direction, t_min, t_max, max_depth, current_depth):
    """
    Recursively trace rays through Gaussian particles.
    """
    color = vec3(0.0)
    transmittance = 1.0
    
    if current_depth >= max_depth:
        return background_color

    # 1. Intersect with World AABB
    t0, t1 = t_min, t_max
    if not intersect_world_aabb(ray_origin, ray_direction, t0, t1):
        return background_color

    # 2. Iterate through Gaussians in the AABB
    # Note: In OptiX, this is handled by the intersection/closest-hit programs.
    # Here we simulate the logic for a single Gaussian hit.
    
    # Retrieve Gaussian properties using primitive index
    mu = position[primitive_index]
    cov_diag = covariance_diag[primitive_index]
    alpha = opacity[primitive_index]
    
    # Construct diagonal covariance matrix Sigma
    Sigma = diag(cov_diag)
    Sigma_inv = inverse(Sigma)
    
    # Transform ray to local space or solve quadratic for intersection
    # The intersection program provides t0 and t1 relative to the Gaussian
    # For the purpose of density evaluation along the segment [t0, t1]:
    
    # Determine step size. The source uses distance between entry/exit.
    # Let's assume we sample at the midpoint or step through.
    # The source formula uses (t1 - t0) as the delta for absorption calculation
    # directly, implying a single-step integration or pre-calculated delta.
    
    # Calculate volume factor
    det_Sigma = determinant(Sigma)
    volume_factor = 1.0 / det_Sigma
    
    # Sample point x_k. The source implies evaluating density at sample points.
    # For a single step integration over the segment:
    # We need a representative x_k. The source says "Step along the ray... for each sample point".
    # However, the absorption formula uses (t1 - t0) directly.
    # This suggests a simplified integration where density is evaluated at a specific point
    # or averaged. We will evaluate at the midpoint for clarity, or assume the source
    # implies a constant density approximation over the segment for the absorption term.
    
    # Let's evaluate at the midpoint of the segment within the Gaussian
    t_mid = (t0 + t1) / 2.0
    x_k = ray_origin + ray_direction * t_mid
    
    # Density Evaluation
    delta = x_k - mu
    D2 = dot(delta, multiply(Sigma_inv, delta))
    rho_k = exp(-D2 / 2.0)
    
    # Absorption Calculation
    # Note: The source formula Ak = rho_k * Delta_t * volume_factor
    # Delta_t is the step size. If we treat the whole segment as one step:
    Delta_t = t1 - t0
    absorption = rho_k * Delta_t * volume_factor
    
    # Radiance Accumulation
    # c(sigma_k) is scattering color. For SciVis, this comes from a transfer function.
    scattering_color = transfer_function(alpha)
    
    color += transmittance * scattering_color * absorption
    transmittance *= exp(-absorption)
    
    # Ray Continuation
    # Advance ray origin to exit point
    new_origin = ray_origin + ray_direction * t1
    
    # Recursive call for next Gaussian
    # The source uses optixTrace. We simulate the recursion.
    next_color = recursive_ray_trace(new_origin, ray_direction, t_min, t_max, max_depth, current_depth + 1)
    
    # Final color accumulation
    # The source says: Final color += transmittance * payload.result
    # This implies the recursive call returns the color from subsequent Gaussians
    # which is then modulated by the current transmittance.
    final_color = color + transmittance * next_color
    
    return final_color
```

### Parameters
*   **Grid Layout Variant:** The '5-4-3' variant is used. Root node spans dataset. '5-level' nodes are $25 \times 25 \times 25$ (32,768 children). '4-level' nodes are $24 \times 24 \times 24$ (4,096 children). '3-level' leaf nodes contain 512 voxels ($23 \times 23 \times 23$ relative to parent) [S1, unofficial].
*   **LOD Levels:**
    *   **Low:** Each leaf node is a single Gaussian.
    *   **Medium:** Dense leaf nodes merged into $4 \times 4 \times 4$ groups; sparse into $2 \times 2 \times 2$. Remaining voxels are individual Gaussians.
    *   **High:** Sparse leaf nodes contribute one Gaussian per active voxel; dense leaf nodes merged into $2 \times 2 \times 2$ blocks [S1, unofficial].
*   **Ray Type:** `RAY_TYPE_RADIANCE` for purely forward-ray-marching [S1, unofficial].

### Pitfalls
*   **Non-overlapping Constraint:** The implementation uses non-overlapping Gaussians because OpenVDB leaf nodes are strictly non-overlapping. This limits the model to three refinement levels and introduces lossiness [S1, unofficial].
*   **NanoVDB Limitation:** NanoVDB does not support device-side traversal of the Grid Tree or device-side iterators. It cannot be used for 3D Gaussian generation or rendering in this pipeline; OpenVDB must be used for generation [S1, unofficial].
*   **OptiX Register Constraint:** Propagating state via recursive `optixTrace` calls is limited by OptiX’s 8-payload register constraint, causing sub-optimal accumulation and inconsistent resetting of payload values [S1, unofficial].
*   **Transfer Functions:** Unlike other Gaussian splatting implementations that bake color into Gaussians, this renderer does not, supporting transfer functions similar to traditional volume rendering via colormap lookups [S1, unofficial].

## Operating characteristics

*   **Time Complexity:** Real-time performance is achieved. The renderer consistently provides above 150 FPS for tested datasets (bunny_cloud, explosion, fire, utahteapot, venusstatue, dragon) across all LODs, even with millions of Gaussians [S1, unofficial].
*   **Memory Complexity:** Depends on LOD.
    *   **Dragon Dataset (High LOD):** 546MB, 23.3M Gaussians.
    *   **Dragon Dataset (Low LOD):** 174.4MB, 7.4M Gaussians [S1, unofficial].
*   **Strengths:** Memory-efficient, lossy representation with LOD support. Hardware-accelerated ray tracing via OptiX. Supports transfer functions. Unified representation for volumes and level sets.
*   **Limitations:** Lossy due to non-overlapping constraint. Limited to three LOD levels in current implementation. NanoVDB incompatible. Recursive tracing limited by register constraints [S1, unofficial].
*   **When to use:** Scientific visualization (SciVis) requiring real-time rendering of large VDB datasets with LOD.
*   **When not to use:** Photorealistic rendering requiring overlapping Gaussian mixtures or precise alpha blending without lossiness [S1, unofficial].

## Background

*   **Origin:** The method was introduced in a study for Scientific Visualization exploring the integration of OpenVDB and NVIDIA OptiX [S1, unofficial].
*   **History:** It builds on the popularity of 3D Gaussian approximation in stereoscopic image to 3D scene conversion (Gaussian Splatting) and earlier SciVis mixture models [S1, unofficial].
*   **Usage:** Used for rendering volumetric and level-set data from OpenVDB grids in real-time using hardware-accelerated bounding box intersections [S1, unofficial].
