# VoxGRAF

Also called: VoxGRAF: Fast 3D-Aware Image Synthesis with Sparse Voxel Grids

## Overview
VoxGRAF is a 3D-aware Generative Adversarial Network (GAN) that replaces the coordinate-based Multi-Layer Perceptron (MLP) scene representation with a sparse voxel grid generator [S1]. It solves the problem of slow rendering and viewpoint/content entanglement inherent in standard NeRF-like architectures by enabling fast, 3D-consistent image synthesis via a single forward pass [S1]. Unlike sibling methods that rely on neural rendering or reduced sample counts, VoxGRAF leverages sparse voxel grids and trilinear interpolation to maintain high visual fidelity and resolution without sacrificing speed [S1].

## How it works
VoxGRAF generates a 3D scene representation conditioned on a latent code and camera pose, then renders it using differentiable volume rendering. The method disentangles the foreground (3D) from the background (2D) to mitigate memory constraints and improve consistency [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Latent code $\mathbf{z} \in \mathbb{R}^M$, sampled from $\mathcal{N}(0,1)$, representing the specific 3D scene instance [S1].
    *   Camera pose $\boldsymbol{\xi}$ (extrinsics) and intrinsics $\mathbf{K}$ [S1].
*   **Outputs:**
    *   Generated image $\hat{\mathbf{I}}$ [S1].
    *   Foreground color $\mathbf{c}$ and density $\sigma$ on a sparse voxel grid [S1].

### Data Structures
*   **Sparse Voxel Grid:** A 3D grid of resolution $R_G \times R_G \times R_G$ storing color $\mathbf{c} \in \mathbb{R}^{3 \times R_G \times R_G \times R_G}$ and density $\sigma \in \mathbb{R}^{1 \times R_G \times R_G \times R_G}$ [S1]. The grid is sparse to avoid cubic memory growth associated with dense voxels [S1].
*   **Background Generator:** A separate 2D GAN $G_{bg}$ that generates the background image [S1].

### Parameters
*   $R_G$: Resolution of the sparse voxel grid [S1].
*   $N$: Number of sampling points along each camera ray [S1].
*   $M$: Dimensionality of the latent variable $\mathbf{z}$ [S1].
*   $\gamma(\cdot)$: Fixed positional encoding function [S1].

### Numbered Steps

1.  **Foreground Generation:** The foreground generator $G_{f_{\theta_{fg}}}$ takes the latent code $\mathbf{z}$ and camera pose $\boldsymbol{\xi}$ as input. It produces the color values $\mathbf{c}$ and density values $\sigma$ on the sparse voxel grid of resolution $R_G$ [S1].
2.  **Ray Sampling:** For each pixel in the target image, a camera ray $\mathbf{r}$ is defined using the camera intrinsics $\mathbf{K}$ and pose $\boldsymbol{\xi}'$ [S1]. $N$ sampling points are placed along this ray [S1].
3.  **Voxel Querying:** The values at the sampling points are computed by trilinearly interpolating the sparse voxel grid [S1]. This replaces the MLP queries used in standard NeRF [S1].
4.  **Alpha Computation:** For each sample point $i$ along ray $\mathbf{r}$, the alpha value $\alpha^r_i$ is computed from the density $\sigma^r_i$ and the distance $\delta^r_i$ to the next sample point:
    $$
    \alpha^r_i = 1 - \exp(-\sigma^r_i \delta^r_i)
    $$
    where $\delta^r_i = \| \mathbf{x}^r_{i+1} - \mathbf{x}^r_i \|_2$ [S1].
5.  **Volume Rendering (Foreground):** The foreground color $\mathbf{c}^r$ and alpha mask $\mathbf{a}^r$ for the ray are computed using alpha composition:
    $$
    \mathbf{c}^r = \sum_{i=1}^{N} T^r_i \alpha^r_i \mathbf{c}^r_i
    $$
    $$
    \mathbf{a}^r = \sum_{i=1}^{N} T^r_i \alpha^r_i
    $$
    where $T^r_i = \prod_{j=1}^{i-1} (1 - \alpha^r_j)$ is the transmittance [S1].
6.  **Background Generation:** The background generator $G_{bg}$ produces a background image conditioned on the camera pose [S1].
7.  **Composition:** The foreground and background are combined using alpha composition to produce the final image $\hat{\mathbf{I}}$ [S1].
8.  **Discrimination:** The discriminator $D_\phi$ compares the generated image $\hat{\mathbf{I}}$ to the real image $\mathbf{I}_{real}$ [S1].

### Pseudocode

```python
def voxgraf_forward(z, camera_pose, camera_intrinsics, N_samples):
    """
    Generates an image using VoxGRAF.
    
    Args:
        z: Latent code vector of dimension M.
        camera_pose: Camera extrinsic parameters (pose).
        camera_intrinsics: Camera intrinsic matrix K.
        N_samples: Number of sampling points per ray.
        
    Returns:
        Generated image.
    """
    # Step 1: Generate sparse voxel grid for foreground
    # G_fg takes latent code z and camera pose to produce color and density grids
    color_grid, density_grid = G_fg(z, camera_pose)
    
    # Step 2: Define rays based on camera intrinsics and pose
    rays = define_rays(camera_intrinsics, camera_pose)
    
    # Step 3: Sample points along rays
    # For each ray, generate N_samples points
    sample_points = sample_along_rays(rays, N_samples)
    
    # Step 4: Query voxel grid via trilinear interpolation
    # Retrieve color and density at each sample point
    # This replaces MLP queries with fast trilinear interpolation
    colors_at_samples = trilinear_interpolate(color_grid, sample_points)
    densities_at_samples = trilinear_interpolate(density_grid, sample_points)
    
    # Step 5: Compute alpha values
    # Calculate distance between adjacent samples
    deltas = compute_distances(sample_points)
    alphas = 1.0 - torch.exp(-densities_at_samples * deltas)
    
    # Step 6: Volume rendering (Foreground)
    # Compute transmittance T_i = product(1 - alpha_j) for j < i
    transmittances = compute_transmittance(alphas)
    
    # Composite foreground color and alpha
    foreground_color = sum(transmittances * alphas * colors_at_samples)
    foreground_alpha = sum(transmittances * alphas)
    
    # Step 7: Generate background
    background_image = G_bg(camera_pose)
    
    # Step 8: Combine foreground and background
    # Alpha composition of foreground and background
    final_image = alpha_compose(foreground_color, foreground_alpha, background_image)
    
    return final_image
```

### Edge Cases and Pitfalls
*   **Memory Growth:** Dense voxel grids suffer from cubic memory growth, limiting resolution. VoxGRAF uses sparsity to mitigate this [S1].
*   **Entanglement:** Neural rendering often entangles viewpoint and content. VoxGRAF is 3D-consistent by design, avoiding unwanted changes in geometry or appearance when changing camera pose [S1].
*   **Performance:** Rendering an image at 256x256 resolution with 48 sample points per ray requires approximately 3 million MLP queries in standard NeRF. VoxGRAF reduces this to a single forward pass for scene generation, with rendering taking milliseconds thereafter [S1].

## Operating characteristics
*   **Time Complexity:** Inference consists of a single forward pass to generate the 3D scene, which takes up most of the time. Once generated, rendering images takes milliseconds [S1]. This is two orders of magnitude faster than existing approaches that require another forward pass per view [S1].
*   **Memory Complexity:** Uses sparse voxel grids to avoid the cubic memory growth of dense voxels, allowing scaling to higher resolutions [S1].
*   **Strengths:** Fast rendering, 3D consistency, high visual fidelity, no need to reduce sample points for speed [S1].
*   **Limitations:** Requires training a GAN, which can be complex. The background is modeled separately in 2D, which may limit complex background interactions [S1].
*   **When to use:** When fast, 3D-consistent image synthesis is required, and high resolution is needed without the computational cost of per-ray MLP queries [S1].
*   **When not to use:** When explicit control over individual 3D points via coordinate-based queries is required, or when the scene is not amenable to GAN-based generation [S1].

## Background
VoxGRAF was introduced as a 3D-aware GAN that investigates the utility of sparse voxel grid representations for fast and 3D-consistent generative modeling [S1]. It builds on the paradigm of 3D-aware GANs like GRAF but replaces the monolithic MLP with 3D convolutions on sparse voxel grids, combined with progressive growing, free space pruning, and appropriate regularization [S1]. The method was motivated by the need to generate 3D content at high resolution directly, suitable for downstream applications like physics engines, while avoiding the viewpoint/content entanglement of hybrid rendering approaches [S1].
