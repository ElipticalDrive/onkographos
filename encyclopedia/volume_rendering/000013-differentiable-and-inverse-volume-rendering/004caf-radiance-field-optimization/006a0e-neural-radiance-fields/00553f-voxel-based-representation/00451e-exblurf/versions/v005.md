# ExBluRF

Also called: Efficient Radiance Fields for Extreme Motion Blurred Images

## Overview
ExBluRF is a novel view synthesis method designed to reconstruct sharp 3D scenes from extreme motion-blurred images by jointly optimizing voxel-based radiance fields and 6-DOF camera trajectories [S1]. It differs from sibling methods like [FastNeRF](7183-fastnerf.md) or [C-NeRF](7275-c-nerf.md) which focus on static scene acceleration, and from [DeblurNeRF](10878-rendernet.md) which uses 2D pixel-wise blur kernels, by formulating motion blur as a trajectory-based accumulation of rays along a Bézier curve [S1]. This approach allows ExBluRF to handle extreme blur with significantly lower memory and computational costs compared to MLP-based deblurring methods, as its memory complexity remains constant relative to the number of blur samples [S1].

## How it works
**Inputs and Outputs:**
- **Inputs:** A set of extremely motion-blurred images and their initial camera poses [S1].
- **Outputs:** A sharp voxel-based radiance field (density $\sigma$ and color $\mathbf{c}$) and the optimized 6-DOF camera trajectory parameters for each input image [S1].

**Data Structures:**
1.  **Voxel Grid:** Replaces the MLP $f_{NeRF}$ used in standard NeRF. It stores volumetric densities $\sigma$ and colors $\mathbf{c}$ for direct interpolation [S1].
2.  **Bézier Curve Control Points:** The camera trajectory for each view is parameterized by control points $\{\hat{\mathbf{p}}_j\}_{j=0}^M$ in the Lie algebra $\mathfrak{se}(3)$ [S1].

**Parameters:**
-   $N$: Number of sampling points (intermediate sub-frames) along the camera trajectory to approximate the motion blur integral [S1].
-   $P$: Number of sample points on a single ray during volume rendering [S1].
-   $M$: Order of the Bézier curve [S1].
-   $B$: Number of rays processed in a batch [S1].

**Algorithm Steps:**

1.  **Trajectory Reparameterization:**
    For each input image, define the initial pose $P_{\tau_o}$ and final pose $P_{\tau_c}$. Reparameterize the 6-DOF camera motion trajectory using a Bézier curve [S1]. The pose at normalized time $\tau'_i$ is computed as:
    $$
    \mathbf{p}_{\tau_i} = \sum_{j=0}^{M} \binom{M}{j} (1-\tau'_i)^{M-j} (\tau'_i)^j \cdot \hat{\mathbf{p}}_j
    $$
    where $\tau'_i = \frac{\tau_i - \tau_o}{\tau_c - \tau_o}$ and $\hat{\mathbf{p}}_j$ are the learnable control points [S1].

2.  **Ray Generation:**
    For each training iteration and each blurry input image, generate $N$ rays corresponding to the intermediate camera poses along the estimated Bézier trajectory [S1]. For each pixel $x$, compute the ray direction $\mathbf{d}_{\tau_i}$ at each intermediate shutter time $\tau_i$:
    $$
    \mathbf{d}_{\tau_i} = \mathbf{R}_{\tau_i} \cdot \mathbf{K}^{-1} [\mathbf{x}]_+
    $$
    where $[\mathbf{x}]_+$ is the homogeneous coordinate of pixel $x$ [S1]. The ray origin is the camera center corresponding to $P_{\tau_i}$ [S1].

3.  **Volume Rendering:**
    Render the color for each of the $N$ rays using the current voxel-based radiance fields [S1]. For a ray $\mathbf{r}$, compute:
    $$
    \hat{\mathbf{C}}(\mathbf{r}) = \sum_{k=1}^{P} T_k (1 - \exp(-\sigma_k \delta_k)) \mathbf{c}_k
    $$
    where $T_k = \exp\left(-\sum_{j=1}^{k-1} \sigma_j \delta_j\right)$, $\sigma_k$ is density, $\mathbf{c}_k$ is color, and $\delta_k$ is the distance between sample points [S1].

4.  **Blur Accumulation:**
    Compute the blurred RGB color for a pixel $x$ by accumulating the rendered colors of rays at $N$ intermediate shutter times:
    $$
    \hat{\mathbf{C}}_B(\mathbf{x}) \approx \frac{1}{N} \sum_{i=1}^{N} \hat{\mathbf{C}}(\mathbf{r}_{\tau_i}(\mathbf{x}))
    $$
    This approximates the integral of ray colors accumulated while the shutter is open [S1].

5.  **Optimization:**
    Compute the photo-consistency loss between the estimated blurred image $\hat{\mathbf{C}}_B(\mathbf{x})$ and the input blurry image, and backpropagate to optimize both the radiance fields and the camera trajectory parameters [S1].

**Edge Cases and Pitfalls:**
- Pre-trained 2D deblurring networks cannot be directly applied because NeRF requires per-scene optimization without pairs of sharp images [S1].
- Using a 1st order Bézier curve (linear motion in 6-DOF pose space) is difficult to fit the trajectory that generates blur for challenging camera motions, leading to lower performance [S1].
- DeblurNeRF cannot handle a large number of sampling points due to memory and computation costs, leading to significantly degraded performance if limited to 5 samplings [S1].

**Pseudocode:**

```python
import numpy as np
import math

def comb(n, k):
    return math.comb(n, k)

def se3_exp(p):
    """Convert se(3) vector [omega, v] to 4x4 SE(3) matrix [G]."""
    omega = p[:3]
    v = p[3:]
    theta = np.linalg.norm(omega)
    if theta < 1e-8:
        R = np.eye(3)
        K_skew = np.array([[0, -v[2], v[1]], [v[2], 0, -v[0]], [-v[1], v[0], 0]])
        return np.block([[R, v], [np.zeros(3), 1]])
    u = omega / theta
    K_skew = np.array([[0, -u[2], u[1]], [u[2], 0, -u[0]], [-u[1], u[0], 0]])
    R = np.eye(3) + np.sin(theta) * K_skew + (1 - np.cos(theta)) * K_skew @ K_skew
    V = np.eye(3) + (1 - np.cos(theta)) * K_skew + (theta - np.sin(theta)) * K_skew @ K_skew
    t = V @ v
    return np.block([[R, t], [np.zeros(3), 1]])

def bezier_curve(control_points, t):
    M = len(control_points) - 1
    result = np.zeros(6)
    for j in range(M + 1):
        coeff = comb(M, j) * ((1 - t) ** (M - j)) * (t ** j)
        result += coeff * control_points[j]
    return result

def ray_march_voxel(ray_origin, ray_direction, voxel_grid, num_samples, near, far):
    total_transmittance = 1.0
    accumulated_color = np.zeros(3)
    step_size = (far - near) / num_samples
    for k in range(num_samples):
        s_k = near + (k + 0.5) * step_size
        X_k = ray_origin + s_k * ray_direction
        sigma, color = voxel_grid.query(X_k)
        alpha = 1.0 - np.exp(-sigma * step_size)
        weight = total_transmittance * alpha
        accumulated_color += weight * color
        total_transmittance *= (1.0 - alpha)
    return accumulated_color

def exblurf_optimize(blurry_images, initial_poses, voxel_grid, bezier_control_points, K, near, far, N_samples_trajectory, N_samples_ray, max_iterations):
    height, width = blurry_images[0].shape[:2]
    for iteration in range(max_iterations):
        total_loss = 0.0
        for image_idx, blurry_image in enumerate(blurry_images):
            intermediate_poses = []
            for i in range(1, N_samples_trajectory + 1):
                t = (i - 1) / (N_samples_trajectory - 1) if N_samples_trajectory > 1 else 0.0
                p_tau = bezier_curve(bezier_control_points[image_idx], t)
                pose_tau = se3_exp(p_tau)
                intermediate_poses.append(pose_tau)
            rendered_blurred_image = np.zeros_like(blurry_image)
            for y in range(height):
                for x in range(width):
                    pixel_color_accum = np.zeros(3)
                    for pose in intermediate_poses:
                        R = pose[:3, :3]
                        ray_dir = R @ np.linalg.inv(K) @ np.array([x, y, 1])
                        ray_dir = ray_dir / np.linalg.norm(ray_dir)
                        ray_origin = pose[:3, 3]
                        color = ray_march_voxel(ray_origin, ray_dir, voxel_grid, N_samples_ray, near, far)
                        pixel_color_accum += color
                    rendered_blurred_image[y, x] = pixel_color_accum / N_samples_trajectory
            loss = np.mean(np.abs(rendered_blurred_image - blurry_image))
            total_loss += loss
            # [G] Standard AD through voxel grid and Bézier curve updates
```

## Operating characteristics
-   **Time Complexity:** Training time is significantly reduced compared to MLP-based methods. On the 'Camellia' dataset, ExBluRF achieves 10x less training time than DeblurNeRF (4.41 hrs vs 27.48 hrs) [S1].
-   **Memory Complexity:** The memory complexity per ray is $O(1)$ because ray marching evaluates sample points sequentially [S1]. In contrast, DeblurNeRF requires $O(P \cdot L)$ memory per ray due to synchronous feed-forwarding of $P$ points through $L$ MLP layers [S1]. ExBluRF's total memory usage is constant with respect to the number of trajectory samples $N$ [S1].
-   **Performance:** On the 'Camellia' scene, ExBluRF achieves a PSNR of 28.83 with 4.31 GB GPU memory, compared to DeblurNeRF's 27.76 PSNR with 13.89 GB memory [S1]. On the 'Postbox' scene, increasing $N$ from 5 to 31 increases PSNR from 28.62 to 30.23 [S1].
-   **Strengths:** Handles extreme motion blur efficiently; allows large $N$ without memory explosion; jointly optimizes geometry and camera pose [S1].
-   **Limitations:** Requires per-scene optimization; sensitive to the order of the Bézier curve (higher orders may overfit, lower orders may underfit complex motion) [S1]. Pre-trained 2D deblurring networks cannot be directly applied because NeRF requires per-scene optimization without pairs of sharp images [S1].
-   **When to use:** When dealing with extreme motion blur where 2D kernel methods fail or are too memory-intensive, and ground truth sharp images are unavailable for supervised pre-training [S1].

## Background
ExBluRF was introduced by Dongwoo Lee, Sunghyun Cho, Joon-Young Lee, Kyoung Mu Lee, et al. in 2023 [S1]. It addresses the limitations of previous NeRF-based deblurring methods like DeblurNeRF [S1] and BAD-NeRF [S1], which struggled with extreme blur due to high computational costs or inability to model complex 6-DOF trajectories. The method builds on the principles of differentiable volume rendering [44-radiance-field-optimization.md] and voxel-based representations [10852-voxel-based-representation.md]. It was validated on the newly proposed ExBlur dataset, which contains multi-view extremely blurred images with ground truth sharp pairs and trajectories [S1].
