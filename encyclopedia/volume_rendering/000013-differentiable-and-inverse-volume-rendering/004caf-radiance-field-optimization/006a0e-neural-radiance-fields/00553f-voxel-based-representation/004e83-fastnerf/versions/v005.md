# FastNeRF

Also called: Factorized NeRF, Factorized Neural Radiance Fields

## Overview
FastNeRF is a neural rendering method that accelerates inference by factorizing the view-dependent radiance field into position-dependent and direction-dependent components, enabling efficient caching of intermediate network outputs [S4, unofficial]. It solves the problem of high computational cost in standard NeRF by avoiding MLP evaluations at inference time, instead relying on hardware-accelerated ray tracing and grid lookups to achieve interactive frame rates (200Hz) on consumer hardware [S4, unofficial]. It differs from its siblings, such as [C-NeRF](7275-c-nerf.md) and [V4D](8762-v4d-voxel-for-4d-novel-view-synthesis.md), by using a low-rank inner-product factorization to decouple spatial and directional information, whereas other methods may use spherical harmonics or explicit voxel grids for density only [S3].

## How it works
FastNeRF builds on [Voxel-based Representation](10852-voxel-based-representation.md) by replacing the continuous MLP query with cached lookups from sparse 3D grids.

**Inputs and Outputs:**
*   **Input:** Camera parameters (position, orientation, intrinsics), scene bounding box $V$, and trained network weights.
*   **Output:** Rendered image $\hat{C}(\mathbf{r})$ for each pixel ray $\mathbf{r}$.

**Data Structures:**
1.  **Position Cache:** A sparse 3D grid of size $k^3$. Each cell stores the output of $\mathcal{F}_{\text{pos}}$: density $\sigma$ (1 value) and a deep radiance map $(\mathbf{u}, \mathbf{v}, \mathbf{w})$ (3 vectors of dimension $D$). Stored as 16-bit floating point values [S4, unofficial].
2.  **Direction Cache:** A sparse 2D grid of size $l^2$ (representing spherical coordinates $\theta, \phi$). Each cell stores the output of $\mathcal{F}_{\text{dir}}$: a weight vector $\boldsymbol{\beta}$ of dimension $D$. Stored as 16-bit floating point values [S4, unofficial].
3.  **Collision Mesh:** A triangle mesh derived from the density volume $\sigma$ using Marching Cubes, used for ray intersection to skip empty space [S4, unofficial].

**Network Architecture:**
*   $\mathcal{F}_{\text{pos}}$: An 8-layer MLP with 384 hidden units (256 for LLFF scenes) [S4, unofficial]. Input: 3D position $\mathbf{p}$ with positional encoding. Output: $\sigma$ and $(\mathbf{u}, \mathbf{v}, \mathbf{w})$.
*   $\mathcal{F}_{\text{dir}}$: A 4-layer MLP with 128 hidden units [S4, unofficial]. Input: 2D viewing direction $(\theta, \phi)$ or 3D unit vector with positional encoding. Output: $\boldsymbol{\beta}$.

**Parameters:**
*   $D$: Number of components in the deep radiance map. Typical values: 8 for NeRF Synthetic 360, 6 for LLFF [S4, unofficial].
*   $k$: Number of bins for position coordinates $(x, y, z)$. Typical values: 512 to 1024 [S4, unofficial].
*   $l$: Number of bins for direction coordinates $(\theta, \phi)$. Typical values: 256 to 1024 [S4, unofficial].
*   Grid Resolution: Defined by the longest side of the bounding volume $V$. Typical values: $256^3$ to $1024^3$ [S4, unofficial].

**Steps:**

1.  **Cache Population (Preprocessing):**
    *   Define bounding box $V$ for the scene.
    *   Uniformly sample $k$ values for $x, y, z$ within $V$.
    *   Uniformly sample $l$ values for $\theta \in [0, \pi]$ and $\phi \in [0, 2\pi]$.
    *   Compute $\mathcal{F}_{\text{pos}}(\mathbf{p})$ for all $k^3$ positions to populate the Position Cache with $\{\sigma, (\mathbf{u}, \mathbf{v}, \mathbf{w})\}$ [S4, unofficial].
    *   Compute $\mathcal{F}_{\text{dir}}(\mathbf{d})$ for all $l^2$ directions to populate the Direction Cache with $\boldsymbol{\beta}$ [S4, unofficial].
    *   Generate a collision mesh from the density volume $\sigma$ in the Position Cache using Marching Cubes. If volume resolution $> 512^3$, downsample by factor of 2 before meshing [S4, unofficial].

2.  **Ray Casting (Per Pixel):**
    *   Generate ray $\mathbf{r}$ from camera origin through pixel center.
    *   Intersect $\mathbf{r}$ with the collision mesh.
    *   If no hit, discard pixel (background).
    *   If hit, start integration at the intersection point.

3.  **Volume Rendering Integration:**
    *   For each sample point $\mathbf{x}_i$ along the ray within the bounding box:
        a.  **Lookup Position Data:** Query the Position Cache at $\mathbf{x}_i$ using nearest-neighbor interpolation to retrieve $\sigma_i$ and $(\mathbf{u}_i, \mathbf{v}_i, \mathbf{w}_i)$ [S4, unofficial].
        b.  **Lookup Direction Data:** Determine the ray direction $\mathbf{d}$ at $\mathbf{x}_i$. Query the Direction Cache at $(\theta, \phi)$ of $\mathbf{d}$ using trilinear interpolation to retrieve $\boldsymbol{\beta}_i$ [S4, unofficial].
        c.  **Compute Color:** Calculate color $\mathbf{c}_i$ as the inner product:
            $$
            \mathbf{c}_i = \boldsymbol{\beta}_i^T \cdot (\mathbf{u}_i, \mathbf{v}_i, \mathbf{w}_i) = \sum_{j=1}^D \beta_{i,j} (u_{i,j}, v_{i,j}, w_{i,j})
            $$
        d.  **Accumulate:** Update transmittance $T_i$ and accumulated color using the standard volume rendering equation:
            $$
            T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right)
            $$
            $$
            \hat{C}(\mathbf{r}) = \sum_{i=1}^N T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i
            $$
            where $\delta_i$ is the distance between sample points [S4, unofficial].
    *   Terminate integration if transmittance $T_i$ drops below a saturation threshold (early ray termination) [S1].

**Pseudocode:**

```python
import math

def fast_nerf_render(ray_origin, ray_direction, pos_cache, dir_cache, mesh, k, l, D):
    """
    Renders a single pixel using FastNeRF caching.
    
    Args:
        ray_origin: (3,) float array, camera origin.
        ray_direction: (3,) float array, normalized ray direction.
        pos_cache: Sparse 3D grid storing {sigma, u, v, w} for each voxel.
                   Access via nearest neighbor interpolation.
        dir_cache: Sparse 2D grid storing beta for each direction bin.
                   Access via trilinear interpolation on spherical coords.
        mesh: Triangle mesh for empty space skipping.
        k: Number of position bins per dimension.
        l: Number of direction bins per dimension.
        D: Number of factorization components.
        
    Returns:
        color: (3,) float array, RGB color.
    """
    # 1. Skip empty space using hardware-accelerated ray tracing
    hit_point, hit_dist = ray_intersect_mesh(ray_origin, ray_direction, mesh)
    if hit_point is None:
        return [0.0, 0.0, 0.0] # Background

    # 2. Initialize integration
    accumulated_color = [0.0, 0.0, 0.0]
    transmittance = 1.0
    current_pos = hit_point
    sample_step = 0.01 # Fixed step size or adaptive based on grid resolution
    
    # Determine grid bounds for sampling
    # In practice, samples are taken at voxel centers or uniform intervals
    # within the bounding box V.
    
    while transmittance > 1e-4: # Saturation threshold
        # Convert 3D position to cache indices
        # Assuming pos_cache covers bounding box V with k bins per dim
        pos_indices = world_to_cache_index(current_pos, k)
        
        # Lookup position-dependent data (Nearest Neighbor)
        sigma, u, v, w = pos_cache.lookup_nearest(pos_indices)
        
        # If sigma is effectively zero, skip (though mesh should handle empty space)
        if sigma <= 0:
            current_pos += ray_direction * sample_step
            continue
            
        # Convert ray direction to spherical coordinates (theta, phi)
        theta = math.acos(ray_direction[2]) # Assuming z-up or similar convention
        phi = math.atan2(ray_direction[1], ray_direction[0])
        
        # Convert spherical coords to cache indices
        dir_indices = spherical_to_cache_index(theta, phi, l)
        
        # Lookup direction-dependent data (Trilinear)
        beta = dir_cache.lookup_trilinear(dir_indices)
        
        # Compute color via inner product
        # c = beta^T . (u, v, w)
        # u, v, w are D-dimensional vectors
        r = sum(beta[j] * u[j] for j in range(D))
        g = sum(beta[j] * v[j] for j in range(D))
        b = sum(beta[j] * w[j] for j in range(D))
        color = [r, g, b]
        
        # Volume rendering integration
        # T_i = exp(-sum(sigma_j * delta_j))
        # Contribution = T_i * (1 - exp(-sigma_i * delta_i)) * c_i
        delta = sample_step
        alpha = 1.0 - math.exp(-sigma * delta)
        weight = transmittance * alpha
        
        accumulated_color[0] += weight * color[0]
        accumulated_color[1] += weight * color[1]
        accumulated_color[2] += weight * color[2]
        
        transmittance *= (1.0 - alpha)
        
        # Move to next sample
        current_pos += ray_direction * delta
        
        # Check if out of bounds (optional, mesh intersection usually bounds it)
        if not is_inside_bounding_box(current_pos):
            break
            
    return accumulated_color
```

### [FastNeRF Cache Size Estimation](11428-fastnerf-cache-size-estimation.md)
Provides analytical formulas to calculate the memory footprint of the position-dependent and direction-dependent caches. It solves the problem of determining whether a specific configuration fits within available hardware memory, accounting for the factorized representation which results in significantly smaller memory requirements compared to standard NeRF caches.

## Operating characteristics
*   **Time Complexity:** Inference is memory-bound rather than compute-bound due to cache lookups. Rendering speed exceeds 3000x compared to original NeRF [S1][S4, unofficial].
*   **Memory Complexity:** Standard NeRF caching requires $O(k^3 l^2)$ memory. FastNeRF reduces this to $O(k^3(1 + 3D) + l^2 D)$ [S4, unofficial].
*   **Measured Performance:** On a high-end consumer GPU (e.g., Nvidia Tesla V100), FastNeRF renders 300x300 pixel images at 200Hz (200 FPS) [S4, unofficial]. For LLFF scenes at 504x378 resolution, it achieves ~30 FPS in telepresence scenarios, 50x faster than NeRF [S4, unofficial].
*   **Memory Footprint:** For $k=l=1024$ and $D=8$, dense cache size is ~54 GB. Sparse cache size is ~3 GB [S3][S4, unofficial]. Standard NeRF with same resolution would require ~5600 TB [S4, unofficial].
*   **Strengths:** Interactive frame rates on consumer hardware; high visual fidelity comparable to NeRF; compatible with ray-tracing pipelines.
*   **Limitations:** Aliasing artifacts due to grid discretization after training; memory overhead of several GBs per scene makes it prohibitive for embedded systems without further factorization (e.g., SqueezeNeRF) [S3][S4, unofficial]; slower than cached version when not cached due to larger MLPs [S4, unofficial].
*   **When to use:** Scenarios requiring interactive rates on consumer hardware, such as telepresence or mixed reality [S4, unofficial].
*   **When not to use:** Memory-constrained embedded systems (use SqueezeNeRF instead) [S3]; applications requiring minimal memory footprint without sacrificing speed.

## Background
FastNeRF was introduced by Garbin et al. in March 2021 [S1][S4, unofficial]. It was motivated by the need for real-time neural rendering on mobile and mixed reality devices [S4, unofficial]. The method draws inspiration from real-time computer graphics techniques for approximating the rendering equation, specifically using spherical harmonics to factorize view-dependent appearance into a dot product of position-dependent and direction-dependent coefficients [S4, unofficial]. It is a direct extension of the Neural Radiance Fields (NeRF) framework [27], modifying the network architecture to enable caching [S4, unofficial].
