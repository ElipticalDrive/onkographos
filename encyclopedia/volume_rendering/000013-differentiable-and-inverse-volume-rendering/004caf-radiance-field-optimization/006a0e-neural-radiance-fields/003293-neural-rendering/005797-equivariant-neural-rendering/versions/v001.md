# Equivariant Neural Rendering

Also called: Forward renderer, Inverse renderer

## Overview
Equivariant Neural Rendering is a framework for learning neural scene representations directly from images without 3D supervision or absolute pose information [S1, unofficial]. It enforces that the learned implicit representation transforms like a real 3D scene by satisfying the equivariance relation $T_X g(z) = g(T_Z z)$, where transforming the representation and rendering is equivalent to rendering and transforming the image [S1, unofficial]. This allows the model to generalize across camera transformations and infer scenes in real time, unlike methods requiring minutes for inference or pose optimization at test time [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A pair of images $(x_1, x_2)$ of the same scene and their relative 3D rotation transformation $\theta$.
*   **Output:** A rendered image matching the target view, derived from the equivariant scene representation $z$.

**Data Structures:**
*   **Scene Representation ($z$):** A deep voxel grid with layout $\mathbb{R}^{c_s \times d_s \times h_s \times w_s}$. In the reference implementation, dimensions are $64 \times 32 \times 32 \times 32$ (channels, depth, height, width) [S1, unofficial].
*   **Input Images ($x$):** RGB images of size $128 \times 128$ pixels [S1, unofficial].
*   **Transformation ($\theta$):** Parameterized as axis-angle $\theta \hat{n}$ (angle $\theta$, axis $\hat{n}$), implemented as a $3 \times 3$ rotation matrix [S1, unofficial].

**Network Architecture:**
The method consists of two transposed networks:
1.  **Inverse Renderer ($f: X \rightarrow Z$):** Maps images to scene representations. Composed of:
    *   2D Convolutional Network (mapping images to 2D features).
    *   Inverse Projection Layer (mapping 2D features to 3D features).
    *   3D Convolutional Network (mapping 3D features to $z$).
2.  **Forward Renderer ($g: Z \rightarrow X$):** Maps scene representations to images. Composed of:
    *   3D Convolutions.
    *   $1 \times 1$ Projection Convolutions.
    *   2D Convolutions.
    *   Sigmoid activation at the output layer to constrain pixels to $[0, 1]$ [S1, unofficial].

**Implementation Details:**
*   **Layers:** Residual blocks (sequence of $1 \times 1$, $3 \times 3$, $1 \times 1$ convolutions added to identity) for dimension-preserving convolutions; strided convolutions for downsampling [S1, unofficial].
*   **Normalization/Activation:** GroupNorm and LeakyReLU after every layer, except the final scene representation and image output layers [S1, unofficial].
*   **Voxel Rotation:** Implemented by applying the 3D rotation matrix to the coordinates of the features in the voxel grid. Inverse warping with trilinear interpolation is used to reconstruct values at voxel locations where rotated points do not align with the grid [S1, unofficial].

**Training Algorithm:**
The camera is assumed to be on a sphere looking at the origin. The model is trained to minimize the rendering loss, which enforces equivariance.

1.  **Sample Data:** Randomly sample a pair of images $(x_1, x_2)$ from the same scene and their relative rotation $\theta$ [S1, unofficial].
2.  **Encode:** Compute scene representations $z_1 = f(x_1)$ and $z_2 = f(x_2)$ using the inverse renderer [S1, unofficial].
3.  **Rotate Representations:**
    *   Compute $\tilde{z}_1 = R^Z_\theta z_1$ (rotate $z_1$ by $\theta$).
    *   Compute $\tilde{z}_2 = (R^Z_\theta)^{-1} z_2$ (rotate $z_2$ by $-\theta$) [S1, unofficial].
4.  **Render:** Decode the rotated representations using the forward renderer $g$:
    *   Render $\tilde{z}_1$ to predict $x_2$.
    *   Render $\tilde{z}_2$ to predict $x_1$ [S1, unofficial].
5.  **Compute Loss:** Calculate the rendering loss:
    $$ L_{render} = ||x_2 - g(\tilde{z}_1)|| + ||x_1 - g(\tilde{z}_2)|| $$
    where $||\cdot||$ is typically a weighted sum of L1 norm and SSIM [S1, unofficial].
6.  **Optimize:** Update network parameters to minimize $L_{render}$ [S1, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class EquivariantNeuralRendering:
    def __init__(self, inverse_renderer: nn.Module, forward_renderer: nn.Module):
        """
        Initialize the model.
        inverse_renderer: nn.Module mapping (B, C, H, W) -> (B, C_s, D, H_s, W_s)
        forward_renderer: nn.Module mapping (B, C_s, D, H_s, W_s) -> (B, C, H, W)
        """
        self.f = inverse_renderer
        self.g = forward_renderer

    def rotate_voxel_grid(self, z: torch.Tensor, rotation_matrix: torch.Tensor) -> torch.Tensor:
        """
        Rotate a voxel grid z by rotation_matrix using inverse warping.
        z shape: (B, C, D, H, W)
        rotation_matrix shape: (3, 3)
        Returns rotated tensor of same shape.
        """
        B, C, D, H, W = z.shape
        # Create grid of coordinates for the voxel grid
        # Coordinates range from -1 to 1 in each dimension
        grid = torch.stack(torch.meshgrid(
            torch.linspace(-1, 1, W, device=z.device),
            torch.linspace(-1, 1, H, device=z.device),
            torch.linspace(-1, 1, D, device=z.device),
            indexing='ij'
        ), dim=-1) # Shape: (W, H, D, 3)
        
        # Expand grid to batch size
        grid = grid.unsqueeze(0).expand(B, -1, -1, -1, -1) # Shape: (B, W, H, D, 3)
        
        # Apply rotation to coordinates
        # grid is (B, W, H, D, 3), rotation_matrix is (3, 3)
        # We need to rotate the last dimension
        rotated_grid = torch.einsum('...d,ij->...ij', grid, rotation_matrix)
        
        # Reshape for grid_sample (N, C, H, W, D) -> grid_sample expects (N, H, W, D, 3)
        # Note: PyTorch grid_sample works on 2D or 3D. For 3D (volume), use grid_sample with align_corners.
        # The input volume z needs to be permuted to (B, C, D, H, W) which it is.
        # grid_sample expects grid of shape (N, H_out, W_out, D_out, 3)
        # We have rotated_grid of shape (B, W, H, D, 3). 
        # We need to permute to (B, D, H, W, 3) to match the output dimensions of z?
        # Actually, grid_sample samples from the input tensor. 
        # Let's assume standard 3D grid_sample implementation.
        
        # Permute rotated_grid to match the spatial dimensions of z for sampling
        # z is (B, C, D, H, W). We want to sample at locations defined by rotated_grid.
        # rotated_grid coordinates are in the space of z.
        # We need to permute rotated_grid to (B, D, H, W, 3)
        rotated_grid = rotated_grid.permute(0, 3, 2, 1, 4) # (B, D, H, W, 3)
        
        # Perform 3D interpolation
        # z is (B, C, D, H, W). grid_sample expects (B, C, D, H, W) and grid (B, D, H, W, 3)
        z_rotated = F.grid_sample(z, rotated_grid, mode='trilinear', align_corners=True)
        
        return z_rotated

    def forward(self, x1: torch.Tensor, x2: torch.Tensor, rotation_matrix: torch.Tensor) -> torch.Tensor:
        """
        Forward pass for training.
        x1, x2: (B, C, H, W)
        rotation_matrix: (3, 3)
        Returns: Loss scalar.
        """
        # 1. Encode
        z1 = self.f(x1) # (B, C_s, D, H_s, W_s)
        z2 = self.f(x2) # (B, C_s, D, H_s, W_s)
        
        # 2. Rotate Representations
        # Rotate z1 by theta to align with x2's view
        z1_rotated = self.rotate_voxel_grid(z1, rotation_matrix)
        
        # Rotate z2 by -theta (inverse) to align with x1's view
        # Inverse rotation matrix
        rot_inv = rotation_matrix.inverse()
        z2_rotated = self.rotate_voxel_grid(z2, rot_inv)
        
        # 3. Render
        # Render rotated z1 to predict x2
        x2_pred = self.g(z1_rotated)
        
        # Render rotated z2 to predict x1
        x1_pred = self.g(z2_rotated)
        
        # 4. Compute Loss (Weighted sum of L1 and SSIM)
        # Note: SSIM implementation is omitted for brevity, assume ssim_loss function exists
        l1_loss = torch.mean(torch.abs(x2 - x2_pred)) + torch.mean(torch.abs(x1 - x1_pred))
        ssim_loss = ssim_loss_function(x2, x2_pred) + ssim_loss_function(x1, x1_pred)
        
        # Typical weights: alpha for L1, beta for SSIM
        loss = 0.5 * l1_loss + 0.5 * ssim_loss
        
        return loss
```

**Edge Cases and Pitfalls:**
*   **Voxel Alignment:** Rotated points may not align with the voxel grid. Trilinear interpolation is required to reconstruct values, which introduces smoothing artifacts [S1, unofficial].
*   **Pose Ambiguity:** The method assumes the camera is on a sphere looking at the origin. If this assumption is violated, the relative rotation $\theta$ may not correctly map the scene representations [S1, unofficial].
*   **Loss Sensitivity:** The model is not highly sensitive to the choice of regression loss (L1, L2, SSIM), but a weighted sum of L1 and SSIM works well in practice [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Inference (scene reconstruction from a single image) takes approximately 22ms on a Tesla V100 GPU, which is three orders of magnitude faster than optimization-based methods like SRNs (which take ~2 minutes) [S1, unofficial].
*   **Memory Complexity:** The scene representation is a 3D voxel grid of size $64 \times 32 \times 32 \times 32$. The memory footprint depends on the number of channels $c_s$ and the data type (e.g., float32).
*   **Strengths:**
    *   Real-time inference without pose optimization at test time [S1, unofficial].
    *   Does not require 3D ground truth or absolute camera poses during training or inference [S1, unofficial].
    *   Generalizes well to complex lighting and backgrounds (e.g., reflections, clutter) [S1, unofficial].
*   **Limitations:**
    *   Reconstruction accuracy (PSNR) is slightly lower than SRNs on standard benchmarks (e.g., 22.83 dB vs 22.89 dB on ShapeNet Chairs) [S1, unofficial].
    *   Struggles with fine texture and geometry details compared to explicit representations or optimization-based methods [S1, unofficial].
    *   Performance degrades if the camera assumption (sphere, looking at origin) is not met [S1, unofficial].
*   **When to Use:** When real-time scene reconstruction and novel view synthesis are required from single images without prior pose information, and high-fidelity texture is less critical than speed and generalization.
*   **When Not to Use:** When absolute pose estimation is required, or when the highest possible reconstruction accuracy (PSNR) is needed and inference time is not a constraint.

## Background
Equivariant Neural Rendering was proposed by Emilien Dupont, Miguel Angel Bautista, Alex Colburn, Aditya Sankar, Carlos Guestrin, Joshua Susskind, and Qi Shan [S1, unofficial]. The work was published on arXiv in June 2020 (v2 in December 2020) [S1, unofficial]. It builds on the concept of equivariance in neural networks, extending it to 3D scene representations. The method addresses the limitations of previous neural rendering approaches that required 3D supervision or pose information, and those that relied on flow estimation which cannot explicitly enforce 3D rotation equivariance [S1, unofficial]. The authors introduced two new datasets, MugsHQ and extended benchmarks on ShapeNet, to evaluate the model on complex scenes with lighting and backgrounds [S1, unofficial].
