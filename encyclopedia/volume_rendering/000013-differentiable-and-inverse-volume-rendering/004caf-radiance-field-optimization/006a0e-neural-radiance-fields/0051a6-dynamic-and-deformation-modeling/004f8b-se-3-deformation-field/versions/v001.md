# SE(3) Deformation Field

Also called: 6-DOF SE(3) field, Rigid transformation field, Screw axis deformation

## Overview
The SE(3) Deformation Field encodes scene deformation as a rigid transformation (rotation and translation) per point using a screw axis representation [S1, S2]. It replaces per-point translation fields to simplify optimization by requiring a single rotation parameter across space, rather than distinct translation vectors for each point [S1]. This method is primarily used in dynamic scene reconstruction to handle rotational motion more efficiently than pure translation-based deformation fields [S1, S2].

## How it works
**Inputs:**
- Spatial coordinates $\mathbf{x} \in \mathbb{R}^3$ and temporal coordinate $t \in \mathbb{R}$ (or a latent code representing time) [S1].
- A Multi-Layer Perceptron (MLP) trained to predict deformation parameters [S1].

**Outputs:**
- A deformed 3D point $\mathbf{x}' \in \mathbb{R}^3$ [S1].
- The homogeneous transformation matrix $\mathbf{e}^{\hat{S}} \in SE(3)$ [S1].

**Data Structures:**
- **Screw Axis Parameters ($\hat{S}$):** A 6-dimensional vector $\hat{S} = (\mathbf{r}, \mathbf{v}) \in \mathbb{R}^6$, where $\mathbf{r} \in \mathbb{R}^3$ defines the rotation axis and angle, and $\mathbf{v} \in \mathbb{R}^3$ defines the translation component [S1].
- **Skew-Symmetric Matrix ($[\mathbf{x}]_\times$):** A $3 \times 3$ matrix constructed from a vector $\mathbf{x} = [x_1, x_2, x_3]^T$ [S1]:
  $$
  [\mathbf{x}]_\times = \begin{pmatrix} 0 & -x_3 & x_2 \\ x_3 & 0 & -x_1 \\ -x_2 & x_1 & 0 \end{pmatrix}
  $$
  This matrix satisfies $[\mathbf{a}]_\times \mathbf{b} = \mathbf{a} \times \mathbf{b}$ [S1].

**Steps:**
1. **Prediction:** The MLP takes the input $(\mathbf{x}, t)$ and predicts the screw axis parameters $\hat{S} = (\mathbf{r}, \mathbf{v}) \in \mathbb{R}^6$ [S1].
2. **Angle Calculation:** Compute the rotation angle $\theta$ as the magnitude of the rotation vector $\mathbf{r}$:
   $$
   \theta = \|\mathbf{r}\|
   $$
   [S1].
3. **Rotation Matrix Construction:** Compute the rotation matrix $\mathbf{R}$ using Rodrigues' formula [S1]:
   $$
   \mathbf{R} = \mathbf{I} + \frac{\sin \theta}{\theta} [\mathbf{r}]_\times + \frac{1 - \cos \theta}{\theta^2} [\mathbf{r}]_\times^2
   $$
   where $\mathbf{I}$ is the $3 \times 3$ identity matrix [S1].
4. **Translation Matrix Construction:** Compute the matrix $\mathbf{G}$ used to derive the translation from the screw axis vector $\mathbf{v}$ [S1]:
   $$
   \mathbf{G} = \mathbf{I} + \frac{1 - \cos \theta}{\theta^2} [\mathbf{r}]_\times + \frac{\theta - \sin \theta}{\theta^3} [\mathbf{r}]_\times^2
   $$
   [S1].
5. **Translation Vector Calculation:** Compute the translation vector $\mathbf{p}$ [S1]:
   $$
   \mathbf{p} = \mathbf{G}\mathbf{v}
   $$
   [S1].
6. **Homogeneous Transform:** Form the homogeneous transformation matrix $\mathbf{e}^{\hat{S}} \in SE(3)$ [S1]:
   $$
   \mathbf{e}^{\hat{S}} = \begin{pmatrix} \mathbf{R} & \mathbf{p} \\ \mathbf{0} & 1 \end{pmatrix}
   $$
   [S1].
7. **Deformation:** Apply the transformation to the input point $\mathbf{x}$ (treated as a homogeneous vector $[\mathbf{x}, 1]^T$) to obtain the deformed point $\mathbf{x}'$ [S1]:
   $$
   \mathbf{x}' = \mathbf{e}^{\hat{S}} \mathbf{x}
   $$
   [S1].

**Pseudocode:**
```python
import numpy as np

def skew_symmetric(v):
    """
    Constructs the skew-symmetric cross-product matrix for vector v.
    """
    return np.array([
        [0, -v[2], v[1]],
        [v[2], 0, -v[0]],
        [-v[1], v[0], 0]
    ])

def se3_deformation(mlp_predict, x, t):
    """
    Applies the SE(3) deformation field to a point x at time t.
    
    Args:
        mlp_predict: A function that takes (x, t) and returns screw axis params (r, v).
        x: Input 3D point (numpy array of shape (3,)).
        t: Time coordinate (scalar or numpy array).
        
    Returns:
        x_prime: Deformed 3D point.
    """
    # Step 1: Predict screw axis parameters
    # mlp_predict returns r (3,) and v (3,)
    r, v = mlp_predict(x, t)
    
    # Step 2: Compute rotation angle
    theta = np.linalg.norm(r)
    
    # Handle singularity when theta is close to 0
    # [G] Standard limit for Rodrigues' formula as theta -> 0
    if theta < 1e-8:
        R = np.eye(3)
        G = np.eye(3)
    else:
        # Step 3: Construct skew-symmetric matrix [r]_x
        r_cross = skew_symmetric(r)
        
        # Step 4: Compute rotation matrix R using Rodrigues' formula
        # R = I + (sin(theta)/theta) * [r]_x + ((1 - cos(theta))/theta^2) * [r]_x^2
        sin_theta = np.sin(theta)
        cos_theta = np.cos(theta)
        R = np.eye(3) + (sin_theta / theta) * r_cross + ((1 - cos_theta) / (theta**2)) * np.dot(r_cross, r_cross)
        
        # Step 5: Compute matrix G for translation
        # G = I + ((1 - cos(theta))/theta^2) * [r]_x + ((theta - sin(theta))/theta^3) * [r]_x^2
        G = np.eye(3) + ((1 - cos_theta) / (theta**2)) * r_cross + ((theta - sin_theta) / (theta**3)) * np.dot(r_cross, r_cross)
        
    # Step 6: Compute translation vector p = G * v
    p = np.dot(G, v)
    
    # Step 7: Apply transformation x' = R * x + p
    x_prime = np.dot(R, x) + p
    
    return x_prime
```

**Parameters:**
- **Elastic Regularization ($\lambda$):** Used in conjunction with the SE(3) field to improve results for dynamic scenes. A stronger regularization ($\lambda = 0.01$) is recommended for dynamic scenes, while $\lambda = 0.001$ suffices for quasi-static scenes [S1].
- **Coarse-to-Fine Optimization:** Implemented by windowing the frequency bands of the positional encoding [S1].

**Edge Cases and Pitfalls:**
- **Singularity at $\theta = 0$:** When the rotation angle is zero, the division by $\theta$ in Rodrigues' formula and $\mathbf{G}$ calculation becomes undefined. The limit as $\theta \to 0$ is the identity matrix [G].
- **Topological Changes:** The method fails in the presence of topological changes in the scene, as it assumes a rigid transformation structure [S1].
- **Gauge Ambiguity:** Slight misalignments may result from gauge ambiguity, affecting PSNR metrics, though LPIPS may remain robust [S1].

## Subtopics

### Deformation Field Parametrization
- **What it is:** A general category of methods defining how deformation fields are represented (e.g., translation fields, rotation fields, SE(3) fields).
- **Differentiation:** SE(3) specifically uses screw axis theory to combine rotation and translation into a single rigid body motion, whereas other parametrizations might use separate translation vectors or simpler rotation encodings.
- **When to choose:** Choose SE(3) when the scene deformation is predominantly rigid rotation, as it simplifies optimization by requiring a single rotation parameter across space.
- **Link:** [Deformation Field Parametrization](12731-deformation-field-parametrization.md)

### Dynamic Scene Representation
- **What it is:** Methods that represent scenes changing over time, often involving temporal encoding or latent codes.
- **Differentiation:** SE(3) is a specific deformation mechanism applied within a dynamic scene representation to handle rigid body motions.
- **When to choose:** Use SE(3) within a dynamic scene representation when the primary motion is rotational and rigid.
- **Link:** [Dynamic Scene Representation](13340-dynamic-scene-representation.md)

### Deformable Neural Radiance Fields (Nerfies)
- **What it is:** The foundational method that introduced the use of deformation fields for dynamic NeRFs.
- **Differentiation:** SE(3) is a specific refinement or alternative deformation technique inspired by Nerfies, focusing on rigid transformations via screw axes.
- **When to choose:** Use SE(3) if you are building upon Nerfies and need to handle rigid rotations more efficiently than the original translation-based deformation.
- **Link:** [Deformable Neural Radiance Fields (Nerfies)](13428-deformable-neural-radiance-fields-nerfies.md)

### JointRF Representation
- **What it is:** A representation that jointly optimizes radiance fields and deformation fields.
- **Differentiation:** SE(3) can be used as the deformation field component within a JointRF framework.
- **When to choose:** Use SE(3) as the deformation model in JointRF when rigid body motion is dominant.
- **Link:** [JointRF Representation](13660-jointrf-representation.md)

### D-TensoRF
- **What it is:** A tensor-based factorization of NeRFs for dynamic scenes.
- **Differentiation:** SE(3) provides a specific rigid transformation model that can be integrated into the deformation component of D-TensoRF.
- **When to choose:** Use SE(3) in D-TensoRF for efficient handling of rigid rotations.
- **Link:** [D-TensoRF](13781-d-tensorf.md)

## Operating characteristics
- **Time Complexity:** The SE(3) field increases training time by approximately 50% compared to methods without this specific deformation field [S2].
- **Memory Complexity:** Not given in the sources.
- **Rendering Performance:** The additional computational overhead results in about a 20% decrease in FPS during rendering [S2].
- **Strengths:** Simplifies optimization by requiring a single rotation parameter across space, making it easier to optimize than per-point translation fields for rotational motion [S1].
- **Limitations:** Diminishes quality on complex real-world datasets (e.g., NeRF-DS) compared to simpler methods like direct addition [S2]. Fails in the presence of topological changes [S1].
- **When to use:** Use when the scene deformation is primarily rigid rotation and computational resources allow for the increased training time [S1, S2].
- **When not to use:** Avoid for complex real-world scenes with non-rigid deformations or topological changes, or when rendering FPS is critical [S1, S2].

## Background
- **Origin:** The SE(3) deformation field was introduced in the paper "Nerfies: Deformable Neural Radiance Fields" by Park et al. [S1]. It draws inspiration from screw axis theory in rigid body kinematics [S1].
- **History:** The method was proposed to address the inefficiency of translation-based deformation fields in encoding rotational motion. By using a screw axis, it allows a single rotation parameter to encode rotation for all points, simplifying the optimization process [S1].
- **Usage:** It is used in dynamic scene reconstruction, particularly in datasets like D-NeRF, where it offers minor improvements over baseline methods [S1, S2]. It has also been applied to 3D Gaussian Splatting for dynamic scenes [S2].
