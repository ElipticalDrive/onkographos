# Structured Latent Codes Anchored to Mesh

Also called: anchor mesh latent codes, l_geo / l_rgb

## Overview
This method stores geometry ($l_{geo}$) and appearance ($l_{rgb}$) latent codes at anchor nodes (typically mesh vertices) on a deformable mesh, enabling local editing and deformation tracking [S1, unofficial]. It differs from implicit surface methods by using explicit mesh topology to define the spatial relationship of latent codes, resolving ambiguity in surface-normal directions via a signed height indicator [S1, unofficial]. It builds on [Hybrid Surface-Volume and Mesh Representation](13663-hybrid-surface-volume-and-mesh-representation.md).

## How it works
**Inputs:** A canonical mesh (e.g., SMPL rest pose) with vertices serving as anchor nodes; a 3D point $\mathbf{x}$ in canonical space; a target pose $\theta_t$ for deformation.
**Outputs:** Interpolated geometry latent code $l_{geo}$ and appearance latent code $l_{rgb}$ for $\mathbf{x}$; deformed position.

**Data Structures:**
*   **Anchor Nodes:** Vertices of the canonical mesh.
*   **Latent Codes:** Vectors of dimension 32 for both $l_{geo}$ and $l_{rgb}$ stored at each anchor node [S1, unofficial].
*   **Signed Height Indicator:** A scalar value $\tilde{h}$ combining signed distance and UV coordinate to resolve perpendicular ambiguity [S1, unofficial].

**Steps:**
1.  **Identify Nearest Neighbors:** For a query point $\mathbf{x}_t$ in the target pose, find the $K$ nearest vertices $\{v_i\}_{i=1}^K$ on the canonical SMPL mesh [S1, unofficial].
2.  **Compute Weights:** Calculate inverse distance weights $w_i$ for each neighbor:
    $$ w_i = \frac{1}{\|\mathbf{x}_t - v_i\|^2} $$
    Normalize weights:
    $$ \hat{w}_i = \frac{w_i}{\sum_{j=1}^K w_j} $$
    [S1, unofficial]
3.  **Interpolate Latent Codes:** Compute the latent code $l_{geo/rgb}$ for $\mathbf{x}_t$ using the normalized weights:
    $$ l_{geo/rgb} = \sum_{i=1}^K \hat{w}_i l_{geo/rgb}^i $$
    [S1, unofficial]
4.  **Resolve Ambiguity:** Assign a signed height indicator $\tilde{h}$ to $\mathbf{x}_t$. This maps the 3D point to a 2.5D volume by equipping the UV coordinate with a signed distance, ensuring unique latent codes for points along the surface normal [S1, unofficial].
5.  **Deform Geometry (Optional):** To support animation, interpolate the Linear Blend Skinning (LBS) weights $\mathbf{b}$ using the same inverse distance weighting to deform the skinning field in sync with mesh movement [S1, unofficial].

**Parameters:**
*   $K$: Number of nearest neighbors. Not given in the sources.
*   Latent dimension: 32 [S1, unofficial].
*   Learning rate: $5 \times 10^{-4}$ decaying to $5 \times 10^{-6}$ for networks; $10\times$ higher for latent codes [S1, unofficial].

**Edge Cases:**
*   **Perpendicular Ambiguity:** Points along the surface normal direction may have identical nearest neighbors. The signed height indicator $\tilde{h}$ is required to distinguish them [S1, unofficial].
*   **Mesh Topology:** The method assumes the anchor mesh is a valid manifold (e.g., SMPL) to ensure consistent UV projection and neighbor search [S1, unofficial].

## Subtopics

### [Texture Swapping](12720-texture-swapping.md)
Texture swapping transfers appearance latent codes from a source mesh area to a target mesh area within a trained Unified Volumetric Avatar (UVA). It solves the problem of reusing textures between objects with slightly different geometries by performing non-rigid 3D alignment of anchor nodes (mesh vertices). Unlike [Texture Painting](12730-texture-painting.md), which modifies appearance directly on a single model, swapping operates between two distinct trained models or areas, leveraging pre-blended latent codes for better 3D consistency.

### [Texture Painting](12730-texture-painting.md)
Texture painting is a method for locally editing the appearance of a 3D avatar or mesh by fine-tuning specific latent codes to match a 2D input painting. It solves the problem of transferring 2D artistic intent to a 3D neural representation while preserving the geometry and appearance of unedited regions. Unlike global texture replacement, it operates on a sparse set of anchor nodes, allowing for independent, spatial-aware local edits.

### Mesh-Guided Geometry Editing
Editing technique allowing local manipulation of avatar geometry by moving anchor nodes on the mesh, with the density field tracking these movements [S1, unofficial]. Users move anchor nodes in 3D modeling software (e.g., Blender) or using mesh deforming methods (e.g., ARAP) [S1, unofficial]. The movements of corresponding vertices are copied from the canonical mesh to the target mesh to deform the skinning field in sync for animation [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Dependent on $K$-nearest neighbor search per query point. Not given in the sources.
*   **Memory Complexity:** Proportional to the number of mesh vertices times the latent dimension (32) [S1, unofficial].
*   **Performance:** Training takes about 10 hours using two NVIDIA Tesla V100 GPUs for 300K iterations with a batch size of 1024 [S1, unofficial].
*   **Strengths:** Enables local geometry and texture editing; tracks deformation via mesh topology; resolves surface ambiguity [S1, unofficial].
*   **Limitations:** Requires a parametric mesh base (e.g., SMPL); interpolation may blur features if $K$ is large [S1, unofficial].

## Background
Originated in the Unified Volumetric Avatar (UVA) paper [S1, unofficial]. It leverages parametric body models like SMPL to provide a structured basis for latent code storage, allowing for fine-detail local modifications that global parametric shape parameters cannot achieve [S1, unofficial].
