# NeuMesh++

Also called: Hybrid rendering for unbounded scenes, Learning Disentangled Neural Mesh-Based Implicit Field, Learning Disentangled Neural Mesh-Based Implicit Field for Geometry and Texture Editing, NeuMesh++ Neural Mesh-based Radiance Field, NeuMesh++ background blending, Unbounded Scene Rendering with NeuMesh++

## Overview
NeuMesh++ is a mesh-based neural radiance field representation that encodes scene geometry and appearance into disentangled latent codes anchored to the vertices of a mesh scaffold [S2]. It solves the problem of high-frequency detail preservation and efficient, fine-grained editing (geometry deformation, texture swapping, painting) in unbounded scenes, where standard volume rendering requires excessive sampling and traditional mesh representations lack view-dependent appearance [S2]. Unlike its predecessor NeuMesh, which relied on a pre-trained teacher model for stability, NeuMesh++ introduces a novel local space parameterization and a decoder-free modification color to achieve stable training without distillation, while supporting unbounded backgrounds via hybrid blending with an implicit hash grid [S2].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of calibrated images with known camera poses; optionally, foreground masks for scenes with empty backgrounds.
*   **Outputs:** A rendered color image $\hat{C}(\mathbf{r})$ for a given camera ray $\mathbf{r}$; editable mesh geometry and per-vertex latent codes.

**Data Structures:**
1.  **Mesh Scaffold:** A triangle mesh $M$ extracted from an external reconstruction method (e.g., Neuralangelo [S2]) or an SDF field (e.g., NeuS [S1]). The mesh defines the spatial domain.
2.  **Per-Vertex Codes:** For each vertex $v$ on the mesh, the following learnable parameters are stored:
    *   Geometry code $\mathbf{l}_g \in \mathbb{R}^{d_g}$ (dimension not explicitly specified in [S2], but implied by decoder input).
    *   Texture code $\mathbf{l}_t \in \mathbb{R}^{d_t}$ (dimension not explicitly specified in [S2]).
    *   Modification color $\mathbf{c}_m \in \mathbb{R}^3$ (RGB, view-independent).
    *   Semantic code $\mathbf{l}_s \in \mathbb{R}^{d_s}$ (used for semantic-guided editing [S2]).
3.  **Occupancy Grid:** A 3D grid used to guide ray sampling, initialized from the mesh scaffold and updated during geometry editing [S2].

**Numbered Steps:**

1.  **Mesh Acquisition:** Extract a foreground mesh $M$ from a source (e.g., Neuralangelo) using Marching Cubes with a voxel resolution of 256 and spatial range $[-1, 1]$ [S1, S2].
2.  **Ray Casting and Sampling:**
    *   Cast a ray $\mathbf{r}$ from the camera.
    *   Use the occupancy grid to identify occupied regions, bypassing empty space [S2].
    *   Sample $N$ points along the ray within the occupied bounds. The standard configuration uses 64 coarse points and 64 fine points (128 total) [S1, S2].
    *   Pre-compute near-far bounds for each ray by finding the minimum and maximum distances of ray-to-mesh intersections to accelerate sampling [S1].
3.  **Local Space Parameterization (for each query point $\mathbf{x}$ on the ray):**
    *   Find the $K$ nearest vertices $\{v_k\}_{k=1}^K$ from the mesh scaffold within a fixed radius. The standard value is $K=8$ [S1, S2].
    *   For each neighbor $v_k$, calculate:
        *   The Euclidean distance: $d_k = \|\mathbf{v}_k - \mathbf{x}\|$.
        *   The projection distance along the vertex normal $\mathbf{n}_k$: $p_k = (\mathbf{v}_k - \mathbf{x}) \cdot \mathbf{n}_k$ [S2].
        *   The normalized inverse distance: $w_k = \frac{d_k}{\sum_{i=1}^K d_i}$ [S2].
    *   Form the local indicator vector $\mathbf{h}_k = (p_k, w_k)$ [S2].
4.  **Decoding Geometry and Radiance:**
    *   Forward the local geometry code $\mathbf{l}_g^k$, local texture code $\mathbf{l}_t^k$, and local indicator $\mathbf{h}_k$ to the decoders.
    *   **Geometry Decoder ($F_G$):** A Multi-Layer Perceptron (MLP) with 3 hidden layers, 256 hidden size, and SoftPlus activation [S1]. It takes positional encoding of $\mathbf{h}_k$ and $\mathbf{l}_g^k$ as input.
        *   Output: Density $\sigma_k$ [S2].
    *   **Radiance Decoder ($F_R$):** An MLP with 4 hidden layers, 256 hidden size, and ReLU activation [S1]. It takes positional encoding of $\mathbf{h}_k$, $\mathbf{l}_t^k$, viewing direction $\mathbf{d}$, and normal $\mathbf{n}_k$ as input.
        *   Output: Base color contribution $\mathbf{c}_k^{base}$ [S2].
    *   **Final Color:** The color contribution from vertex $k$ is computed as:
        $$ \mathbf{c}_k = \mathbf{c}_k^{base} + \mathbf{c}_m^k $$
        where $\mathbf{c}_m^k$ is the modification color interpolated from the $K$ nearest vertices [S2].
5.  **Volume Rendering:**
    *   Aggregate contributions from all $N$ samples along the ray using standard volume rendering [S2]:
        $$ \hat{C}(\mathbf{r}) = \sum_{i=1}^N T_i \alpha_i \mathbf{c}_i $$
        $$ T_i = \prod_{j=1}^{i-1} (1 - \alpha_j), \quad \alpha_i = 1 - \exp(-\sigma_i \delta_i) $$
        where $\delta_i$ is the distance between adjacent samples [S2].
6.  **Unbounded Background Blending (Optional):**
    *   If the scene is unbounded, render a background color $\hat{C}(\mathbf{r})_{\text{bg}}$ using an implicit hash grid (following the NeuS approach) [S2].
    *   Blend the foreground NeuMesh++ color with the background color weighted by the accumulated transmittance $T$ of the foreground:
        $$ \hat{C}(\mathbf{r})_{\text{comp}} = \hat{C}(\mathbf{r}) \cdot T + \hat{C}(\mathbf{r})_{\text{bg}} \cdot (1 - T) $$
        where $T$ is the accumulated transmittance of NeuMesh++ [S2].

    points = ray_origin + ray_direction * t_values[:, np.newaxis]
    
    accumulated_transmittance = 1.0
    accumulated_color = np.zeros(3)

        k_indices = np.argsort(dists)[:K]
        v_k = mesh.vertices[k_indices]
        n_k = mesh.normals[k_indices]
        
        # 4. Calculate local indicators

        v_to_x = v_k - x # Shape (K, 3)
        
        # Projection distance p_k = (v_k - x) . n_k

        sum_d = np.sum(d_k)
        if sum_d == 0:
            w_k = np.ones(K) / K
        else:
            w_k = d_k / sum_d

        # Note: w_k is scalar per vertex in the formula, but normalized by sum.

        l_t_k = vertex_codes['l_t'][k_indices]
        c_m_k = vertex_codes['c_m'][k_indices]

        # Positional encoding is applied to h_k and codes

        c_k = c_base_k + c_m_k # Shape (K, 3)

        # The paper states: "fuse the densities and radiance ... under the condition of their latent codes and local indicators"
        # Standard approach in such vertex-bounded fields is weighted averaging based on distance or indicator.
        # [S2] defines w_k as normalized inverse distance.

        # For sample i, we have K neighbors. We need to combine them.
        # Let's assume weighted average using w_k (normalized inverse distance)
        # Note: w_k in [S2] is defined as d_k / sum(d_i). This is proportional to distance, not inverse.

        # This is actually proportional to distance. Usually inverse distance weighting uses 1/d.
        # Let's stick to the formula: w_k = d_k / sum(d_i).

        sigma_sample = np.sum(w_k * sigma_k)
        
        # Aggregate color
        c_sample = np.sum(w_k[:, np.newaxis] * c_k, axis=0)
        
        # 7. Volume Rendering Step
        # Calculate opacity alpha
        # delta_i is distance to next sample. For last sample, use a large delta or 0?
        # Standard NeRF: delta_i = t_{i+1} - t_i.
        if i < num_samples - 1:

            delta = t_values[i] - t_values[i-1] # Approximation
            
        alpha = 1.0 - np.exp(-sigma_sample * delta)

        accumulated_color += weight * c_sample
        accumulated_transmittance *= (1.0 - alpha)
        
    # 8. Background Blending
    # Render background
    c_bg = background_model(ray_origin, ray_direction)
    
    # Blend
    final_color = accumulated_color + c_bg * accumulated_transmittance
    
    return final_color

**Parameters:**
*   $K$: Number of nearest vertices. Default: 8 [S1, S2].
*   $K_{tv}$: Number of closest vertices for Total Variation loss. Not given in the sources.
*   Positional Encoding Frequencies: Signed distances (part of $h$) use 8 frequencies; interpolated codes use 2 frequencies; viewing directions use 4 frequencies [S1].
*   Geometry Decoder: 3 hidden layers, 256 hidden size, SoftPlus activation [S1].
*   Radiance Decoder: 4 hidden layers, 256 hidden size, ReLU activation [S1].
*   Loss Weight for Modification Color: 0.01 [S2].
*   Rendering Resolution: 800 × 800 [S2].
*   Training Images: 1600 × 1200 (DTU) [S2].

**Edge Cases and Pitfalls:**
*   **Spatial Distinguishability:** Naive trilinear interpolation of codes on a single-layer mesh fails to distinguish inner/outer queries perpendicular to the surface [S1, S2]. NeuMesh++ solves this with the local indicator $\mathbf{h}_k$ (projection distance $p_k$) [S2].
*   **Training Stability:** Vertex-bounded representations lack the spatial continuity of global MLPs, risking unstable training [S1]. NeuMesh++ avoids the need for a teacher model (used in NeuMesh) by using the local space parameterization and modification color [S2].
*   **Texture Overfitting:** Fine-tuning texture codes with a single image can cause view-dependent artifacts [S1]. NeuMesh++ uses a spatial-aware optimization strategy, selecting only affected modification colors via probing rays, to prevent this [S1, S2].
*   **Non-Watertight Meshes:** The method is agnostic to mesh topology (non-watertight, non-manifold) because it relies on local vertex neighborhoods rather than global surface definitions [S1, S2].

## Operating characteristics
*   **Time Complexity:** Rendering speed is approximately 15 fps on an Nvidia GTX 4070 GPU for 800 × 800 images [S2]. This is attributed to compact latent codes and lightweight decoders [S2].
*   **Memory Complexity:** Memory usage is proportional to the number of mesh vertices ($V$) times the code dimensions ($d_g + d_t + d_s + 3$). The occupancy grid adds a small constant overhead.
*   **Editing Efficiency:**
    *   Geometry editing (mesh deformation + occupancy grid update): ~1 second [S2].
    *   Texture painting (fine-tuning modification colors): ~1 second [S2].
    *   Semantic-guided editing (3D semantic propagation): ~2 seconds [S2].
    *   Texture swapping/filling: Immediate, no fine-tuning required [S2].
*   **Strengths:**
    *   High-fidelity rendering of high-frequency details (e.g., text, fur) compared to SDF-based methods like NeuS [S2].
    *   Efficient, fine-grained editing capabilities (geometry, texture, semantics) [S2].
    *   No need for UV mapping [S1].
    *   Stable training without a pre-trained teacher model [S2].
*   **Limitations:**
    *   Requires an initial mesh scaffold (e.g., from Neuralangelo or NeuS) [S1, S2].
    *   Performance depends on mesh quality and vertex density [S1].
    *   Unbounded scenes require an additional background model (hash grid) [S2].

## Background
NeuMesh++ is an extension of NeuMesh [S1], published in 2022. NeuMesh introduced a mesh-based neural implicit field with disentangled geometry and texture codes but relied on a distillation process from a pre-trained teacher model (NeuS) for stable training [S1]. NeuMesh++, published in 2025, rebuilds the representation on the neural radiance field directly, eliminating the need for distillation [S2]. It introduces a novel local space parameterization (using projection and normalized inverse distance) to improve spatial distinguishability and training stability [S2]. It also adds a decoder-free modification color for better texture editing fidelity and semantic codes for semantic-guided editing [S2]. The method is evaluated on the DTU dataset and NeRF 360° Synthetic dataset [S2].
