# LidaRF Network Architecture

Also called: LidaRF

## Overview
The LidaRF network architecture is a specialized neural network design for LiDAR-based Neural Radiance Fields (NeRF) that jointly learns geometry and 3D point attributes (distance, intensity, ray-drop probability) without explicit 3D reconstruction [S1]. It distinguishes itself from standard NeRF variants by integrating a 3D sparse UNet for LiDAR geometry encoding with a multi-resolution hash grid for density prediction, enabling efficient processing of sparse LiDAR point clouds [S1]. This method builds on [LiDAR-NeRF](11289-lidar-nerf.md) by providing the specific network components required for differentiable LiDAR view synthesis.

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of LiDAR points (3D coordinates).
*   Sampled 3D positions along rays for volume rendering.

**Outputs:**
*   Density values ($\sigma$) for each sampled position.
*   A 15-dimensional density embedding for each sampled position.
*   RGB color values for each sampled position (via the color network, which uses the density embedding).

### Data Structures

**1. Hash Grid (for Proposal Sampler and Density Network)**
*   **Structure:** A multi-resolution hash table mapping 3D coordinates to feature vectors.
*   **Layout:**
    *   **Levels:** $L$ levels of resolution.
    *   **Resolution per Level:** Minimum resolution $N_{min}$, Maximum resolution $N_{max}$.
    *   **Feature Dimension:** $F_{hash}$ dimensions per level.
    *   **Encoding:** Hash encoding maps 3D positions to specific entries in the grid.

**2. Sparse Voxel Grid (for LiDAR Encoding)**
*   **Structure:** A 3D grid of cells.
*   **Size:** $512 \times 512 \times 512$ cells.
*   **Cell Content:** Mean 3D position of LiDAR points falling within the cell. Empty cells are ignored by sparse convolution.

**3. Sparse UNet Features**
*   **Encoder Layers:** Feature dimensions $[32, 64, 96, 128]$.
*   **Decoder Layers:** Feature dimensions $[128, 96, 64, 64]$.
*   **Output:** LiDAR features from the final decoder layer.

**4. MLP Layers**
*   **Proposal Sampler MLP:** 2 layers, 16 hidden features.
*   **Density Network MLP:** 2 layers, 64 hidden features.
*   **Color Network MLP:** 2 layers, 64 hidden features (implied by context of predicting RGB from embedding).

### Numbered Steps

1.  **Scene Bounding Sphere Definition:**
    Define a sphere bounding the scene. The diameter is the maximum distance between any two camera positions in the training log plus 50 meters [S1].

2.  **LiDAR Point Voxelization:**
    *   Input: All LiDAR points.
    *   Process: Voxelize points into a $512 \times 512 \times 512$ grid.
    *   Feature Assignment: For each non-empty cell, compute the mean 3D position of the LiDAR points contained within it. This mean position serves as the initial feature for the cell [S1].

3.  **LiDAR Geometry Encoding (Sparse UNet):**
    *   Input: The voxelized LiDAR features.
    *   Process: Pass features through a 3D sparse UNet.
        *   **Encoder:** Applies sparse convolutions with feature dimensions $[32, 64, 96, 128]$.
        *   **Decoder:** Applies sparse convolutions with feature dimensions $[128, 96, 64, 64]$.
        *   **Skip Connections:** Integrate skip connections and multi-level feature fusion between encoder and decoder stages.
    *   Output: LiDAR features from the final layer of the UNet [S1].

4.  **Proposal Sampling:**
    *   **Structure:** Two consecutive "fused" MLPs.
    *   **Hash Grid Parameters:**
        *   Minimum resolution: 16.
        *   Levels: 5.
        *   Feature dimension per level: 2.
        *   MLP: 2 layers, 16 hidden features.
    *   **Distinction:**
        *   First MLP set: Maximum hash grid resolution 512.
        *   Second MLP set: Maximum hash grid resolution 1024.
    *   **Process:**
        1.  Query hash encoding for 3D positions.
        2.  Pass hash features through the fused MLP to predict density.
        3.  Use the predicted density to sample points (proposal sampling) [S1].

5.  **Density Network Processing:**
    *   **Hash Grid Parameters:**
        *   Minimum resolution: 16.
        *   Maximum resolution: 4096.
        *   Levels: 16.
        *   Feature dimension per level: 2.
    *   **MLP Parameters:** 2 layers, 64 hidden features.
    *   **Process:**
        1.  Compute hash encoding for sampled 3D positions.
        2.  Query hash features from the grid.
        3.  Concatenate hash features with LiDAR features (output from Step 3).
        4.  Pass concatenated features through the Density Network MLP.
    *   **Output:**
        *   Density value ($\sigma$).
        *   15-dimensional density embedding [S1].

6.  **Color Network Processing:**
    *   **Input:** Density embedding (from Step 5) and potentially other attributes (implied by context of RGB prediction).
    *   **MLP Parameters:** 2 layers, 64 hidden features.
    *   **Output:** RGB value for the sampled position [S1].

### Formulas and Parameters

**Hash Encoding:**
Standard multi-resolution hash encoding is used. For a position $\mathbf{x}$, the feature is computed by hashing $\mathbf{x}$ to indices in grids of varying resolutions $N_l$ for $l=1 \dots L$, and interpolating the features at those indices [S1].

**Loss Weights:**
The optimization uses a weighted loss function with the following weights [S1]:
*   $\lambda_1 = 0.0005$
*   $\lambda_2 = 1$
*   $\lambda_3 = 0.005$
*   $\lambda_4 = 1$

**Unnormalized Scale Epsilon Values:**
Used for normalization or scaling in the loss/optimization [S1]:
*   $\epsilon_{0t} = 10\text{m}$
*   $\epsilon_{t} = 100\text{m}$
*   $\epsilon_{0o} = 1\text{m}$
*   $\epsilon_{o} = 0.15\text{m}$
*   $\epsilon_{n} = 0.15\text{m}$
*   $\epsilon_{a} = 1.5\text{m}$

**Scheduling Rates:**
*   $\alpha_t = 1.00004$
*   $\alpha_o = 0.99995$

**Optimization Parameters:**
*   **Algorithm:** RAdam [S1].
*   **Iterations:** 100,000 [S1].
*   **Learning Rate:** Initial 0.01, reduced to 0.0001. Scheduler max limit 50,000 iterations [S1].
*   **Sampling:** 4,096 points per iteration [S1].

### Edge Cases and Pitfalls
*   **Empty Cells:** The sparse UNet relies on sparse convolution, which only processes active (non-zero) elements. Empty cells in the $512 \times 512 \times 512$ grid carry negligible information and are ignored, enhancing efficiency [S1].
*   **Precision:** Hash encoding involves integer hashing and floating-point interpolation. Precision issues may arise if hash collisions are not handled well or if interpolation is inaccurate.
*   **Boundary Conditions:** The scene is bounded by a sphere defined by the camera trajectory plus 50 meters. Points outside this sphere may not be handled correctly if not clamped or ignored [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Memory:** The hash grid memory usage depends on the number of levels and resolutions. The density network uses 16 levels with 2-dim features, and the proposal sampler uses 5 levels with 2-dim features. The sparse UNet memory usage is proportional to the number of active LiDAR points and the grid size ($512^3$ cells, but sparse).
*   **Time:** Sparse convolution is efficient for sparse data. Hash encoding is $O(1)$ per query. The MLPs are small (2 layers, 16-64 hidden units), so they are fast. The overall complexity is dominated by the number of sampled points (4,096 per iteration) and the LiDAR point cloud size [S1].

### Measured Performance
*   **Hardware:** Not specified in the sources.
*   **Resolution:** Not specified.
*   **Scene:** Tested on street scenes (Argoverse dataset mentioned in source [S1]).
*   **Scaling:** The method scales with the number of LiDAR points and sampled points. The sparse UNet handles sparsity well.

### Strengths and Limitations
*   **Strengths:** Efficient processing of sparse LiDAR data using sparse UNet. Joint learning of geometry and attributes. High-resolution results compared to baselines (Chang et al.) [S1].
*   **Limitations:** Relies on accurate LiDAR point cloud registration. Performance may degrade in areas with sparse LiDAR coverage.

### When to Use
*   Use when dealing with LiDAR-based NeRF tasks where efficient processing of sparse point clouds is required.
*   Use when joint learning of geometry and attributes (distance, intensity) is needed.

### When Not to Use
*   Not suitable for purely visual NeRF tasks without LiDAR data.
*   Not suitable for dense point cloud data where sparse convolution benefits are minimal.

## Background

### Origin
The LidaRF network architecture was introduced in the paper "LidaRF: Delving into Lidar for Neural Radiance Field on Street Scenes" [S1].

### History and Development
LidaRF is part of the LiDAR-NeRF framework, which aims to synthesize novel LiDAR views using neural radiance fields. It builds on previous work in NeRF and LiDAR processing, integrating sparse convolution and hash encoding for efficiency and accuracy [S1].

### Where it is Used
Used in autonomous driving and street scene reconstruction, specifically for novel view synthesis of LiDAR data [S1].
