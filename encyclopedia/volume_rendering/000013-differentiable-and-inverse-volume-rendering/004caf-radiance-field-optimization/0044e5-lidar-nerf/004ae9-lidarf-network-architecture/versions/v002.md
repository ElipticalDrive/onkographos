# LidaRF Network Architecture

Also called: LidaRF

## Overview
The LidaRF network architecture is a specialized neural network design for LiDAR-based Neural Radiance Fields (NeRF) that jointly learns geometry and 3D point attributes without explicit 3D reconstruction [S1]. It distinguishes itself from standard NeRF variants by integrating a 3D sparse UNet for LiDAR geometry encoding with a multi-resolution hash grid for density prediction, enabling efficient processing of sparse LiDAR point clouds [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of LiDAR points (3D coordinates) [S1].
*   Sampled 3D positions along rays for volume rendering [S1].

**Outputs:**
*   Density values ($\sigma$) for each sampled position [S1].
*   A 15-dimensional density embedding for each sampled position [S1].
*   RGB color values for each sampled position [S1].

### Data Structures

**1. Hash Grid (for Proposal Sampler and Density Network)**
*   **Structure:** A multi-resolution hash table mapping 3D coordinates to feature vectors [S1].
*   **Layout:**
    *   **Levels:** $L$ levels of resolution [S1].
    *   **Resolution per Level:** Minimum resolution $N_{min}$, Maximum resolution $N_{max}$ [S1].
    *   **Feature Dimension:** $F_{hash}$ dimensions per level [S1].
    *   **Encoding:** Hash encoding maps 3D positions to specific entries in the grid [S1].

**2. Sparse Voxel Grid (for LiDAR Encoding)**
*   **Structure:** A 3D grid of cells [S1].
*   **Size:** $512 \times 512 \times 512$ cells [S1].
*   **Cell Content:** Mean 3D position of LiDAR points falling within the cell [S1]. Empty cells are ignored by sparse convolution [S1].

**3. Sparse UNet Features**
*   **Encoder Layers:** Feature dimensions $[32, 64, 96, 128]$ [S1].
*   **Decoder Layers:** Feature dimensions $[128, 96, 64, 64]$ [S1].
*   **Output:** LiDAR features from the final decoder layer [S1].

**4. MLP Layers**
*   **Proposal Sampler MLP:** 2 layers, 16 hidden features [S1].
*   **Density Network MLP:** 2 layers, 64 hidden features [S1].
*   **Color Network MLP:** 2 layers, 64 hidden features [S1].

### Numbered Steps

1.  **Scene Bounding Sphere Definition:** Define a sphere bounding the scene. The diameter is the maximum distance between any two camera positions in the training log plus 50 meters [S1].
2.  **LiDAR Point Voxelization:** Input all LiDAR points. Voxelize points into a $512 \times 512 \times 512$ grid. For each non-empty cell, compute the mean 3D position of the LiDAR points contained within it. This mean position serves as the initial feature for the cell [S1].
3.  **LiDAR Geometry Encoding (Sparse UNet):** Input the voxelized LiDAR features. Pass features through a 3D sparse UNet. The encoder applies sparse convolutions with feature dimensions $[32, 64, 96, 128]$. The decoder applies sparse convolutions with feature dimensions $[128, 96, 64, 64]$. Integrate skip connections and multi-level feature fusion between encoder and decoder stages. Output LiDAR features from the final layer of the UNet [S1].
4.  **Proposal Sampling:** Structure consists of two consecutive "fused" MLPs. Hash grid parameters: minimum resolution 16, 5 levels, 2 feature dimensions per level. MLP parameters: 2 layers, 16 hidden features. Distinction: first MLP set maximum hash grid resolution 512, second MLP set maximum hash grid resolution 1024. Process: query hash encoding for 3D positions, pass hash features through the fused MLP to predict density, and use the predicted density to sample points [S1].
5.  **Density Network Processing:** Hash grid parameters: minimum resolution 16, maximum resolution 4096, 16 levels, 2 feature dimensions per level. MLP parameters: 2 layers, 64 hidden features. Process: compute hash encoding for sampled 3D positions, query hash features from the grid, concatenate hash features with LiDAR features (output from Step 3), and pass concatenated features through the Density Network MLP. Output: density value ($\sigma$) and 15-dimensional density embedding [S1].
6.  **Color Network Processing:** Input density embedding (from Step 5). MLP parameters: 2 layers, 64 hidden features. Output: RGB value for the sampled position [S1].

### Formulas and Parameters

**Hash Encoding:**
Standard multi-resolution hash encoding is used. For a position $\mathbf{x}$, the feature is computed by hashing $\mathbf{x}$ to indices in grids of varying resolutions $N_l$ for $l=1 \dots L$, and interpolating the features at those indices [S1].

**Loss Weights:**
The optimization uses a weighted loss function with the following weights [S1]:
*   $\lambda_1 = 0.0005$
*   $\lambda_2 = 1$
*   $\lambda_3 = 0.005$
*   $\lambda_4 = 1$

**Unnormalized Scale Epsilon Values:**
Used for normalization or scaling in the loss/optimization [S1]:
*   $\epsilon_{0t} = 10\text{m}$
*   $\epsilon_{t} = 100\text{m}$
*   $\epsilon_{0o} = 1\text{m}$
*   $\epsilon_{o} = 0.15\text{m}$
*   $\epsilon_{n} = 0.15\text{m}$
*   $\epsilon_{a} = 1.5\text{m}$

**Scheduling Rates:**
*   $\alpha_t = 1.00004$
*   $\alpha_o = 0.99995$ [S1].

**Optimization Parameters:**
*   **Algorithm:** RAdam [S1].
*   **Iterations:** 100,000 [S1].
*   **Learning Rate:** Initial 0.01, reduced to 0.0001. Scheduler max limit 50,000 iterations [S1].
*   **Sampling:** 4,096 points per iteration [S1].

### Pseudocode

```python
import torch
import torch.nn as nn

class LidaRFNetwork(nn.Module):
    def __init__(self):
        super(LidaRFNetwork, self).__init__()
        
        # 1. Proposal Sampler
        # Shared: min_res=16, levels=5, feat_dim=2, mlp_layers=2, mlp_hidden=16
        # Distinction: max_res=512 (first), max_res=1024 (second)
        self.proposal_sampler_1 = FusedMLPHash(min_res=16, max_res=512, levels=5, feat_dim=2, mlp_hidden=16)
        self.proposal_sampler_2 = FusedMLPHash(min_res=16, max_res=1024, levels=5, feat_dim=2, mlp_hidden=16)
        
        # 2. LiDAR Encoding (Sparse UNet)
        # Encoder dims: [32, 64, 96, 128], Decoder dims: [128, 96, 64, 64]
        self.lidar_encoder = SparseUNet(in_channels=3, encoder_dims=[32, 64, 96, 128], decoder_dims=[128, 96, 64, 64])
        
        # 3. Density Network
        # Hash grid: min_res=16, max_res=4096, levels=16, feat_dim=2
        # MLP: 2 layers, 64 hidden
        self.density_hash_grid = MultiResolutionHashGrid(min_res=16, max_res=4096, levels=16, feat_dim=2)
        self.density_mlp = nn.Sequential(
            nn.Linear(16 * 2 + 128, 64),
            nn.ReLU(),
            nn.Linear(64, 64),
            nn.ReLU()
        )
        self.density_head = nn.Linear(64, 16) # 1 for density, 15 for embedding
        
        # 4. Color Network
        # MLP: 2 layers, 64 hidden
        self.color_mlp = nn.Sequential(
            nn.Linear(15, 64),
            nn.ReLU(),
            nn.Linear(64, 64),
            nn.ReLU()
        )
        self.color_head = nn.Linear(64, 3) # RGB

    def forward(self, lidar_points, sampled_positions):
        # lidar_points: (N, 3)
        # sampled_positions: (M, 3)
        
        # Step 2: LiDAR Voxelization
        # Voxelize into 512x512x512 grid, compute mean 3D position per cell
        voxel_features, voxel_coords = voxelize_lidar(lidar_points, grid_size=512)
        
        # Step 3: LiDAR Encoding
        # Pass through Sparse UNet
        lidar_features = self.lidar_encoder(voxel_features, voxel_coords)
        # lidar_features shape: (N_active, 128)
        
        # Step 4: Proposal Sampling (Simplified)
        # In practice, proposal samplers generate sampled_positions.
        # Here we assume sampled_positions are provided or generated externally.
        # We proceed to Density Network as per architecture flow.
        
        # Step 5: Density Network
        # Query hash grid for sampled_positions
        hash_features = self.density_hash_grid(sampled_positions) # (M, 32)
        
        # Interpolate/associate LiDAR features to sampled positions
        # Since LiDAR features are sparse, we use nearest-neighbor or trilinear interpolation
        lidar_feats_for_pos = interpolate_lidar_features(sampled_positions, voxel_coords, lidar_features)
        
        concat_features = torch.cat([hash_features, lidar_feats_for_pos], dim=-1)
        density_output = self.density_mlp(concat_features)
        density_values = density_output[:, :1]
        density_embedding = density_output[:, 1:]
        
        # Step 6: Color Network
        color_features = self.color_mlp(density_embedding)
        rgb_values = self.color_head(color_features)
        
        return density_values, rgb_values, density_embedding

def voxelize_lidar(points, grid_size):
    """Voxelize points into a grid and compute mean 3D position per cell."""
    # Normalize points to grid coordinates
    coords = torch.floor(points / grid_size).long()
    # Group by cell and compute mean
    unique_coords, inverse_indices = torch.unique(coords, return_inverse=True, dim=0)
    mean_positions = torch.zeros(unique_coords.shape[0], 3, device=points.device)
    torch.scatter_add(mean_positions, 0, inverse_indices.unsqueeze(1).expand(-1, 3), points)
    counts = torch.bincount(inverse_indices).unsqueeze(1)
    mean_positions /= counts.clamp(min=1)
    return mean_positions, unique_coords

def interpolate_lidar_features(positions, voxel_coords, voxel_features):
    """Interpolate sparse LiDAR features to arbitrary positions."""
    # Simple nearest-neighbor interpolation for demonstration
    dists = torch.cdist(positions, voxel_coords)
    nearest_idx = torch.argmin(dists, dim=1)
    return voxel_features[nearest_idx]

class FusedMLPHash(nn.Module):
    def __init__(self, min_res, max_res, levels, feat_dim, mlp_hidden):
        super(FusedMLPHash, self).__init__()
        self.hash_grid = MultiResolutionHashGrid(min_res, max_res, levels, feat_dim)
        self.mlp = nn.Sequential(
            nn.Linear(levels * feat_dim, mlp_hidden),
            nn.ReLU(),
            nn.Linear(mlp_hidden, mlp_hidden),
            nn.ReLU()
        )
        self.out = nn.Linear(mlp_hidden, 1)

    def forward(self, x):
        h = self.hash_grid(x)
        h = self.mlp(h)
        return self.out(h)

class SparseUNet(nn.Module):
    def __init__(self, in_channels, encoder_dims, decoder_dims):
        super(SparseUNet, self).__init__()
        # Simplified representation of sparse convolution operations
        self.enc1 = nn.Conv3d(in_channels, encoder_dims[0], kernel_size=3, stride=2, padding=1)
        self.enc2 = nn.Conv3d(encoder_dims[0], encoder_dims[1], kernel_size=3, stride=2, padding=1)
        self.enc3 = nn.Conv3d(encoder_dims[1], encoder_dims[2], kernel_size=3, stride=2, padding=1)
        self.enc4 = nn.Conv3d(encoder_dims[2], encoder_dims[3], kernel_size=3, stride=2, padding=1)

        self.dec1 = nn.ConvTranspose3d(encoder_dims[3], decoder_dims[0], kernel_size=3, stride=2, padding=1, output_padding=1)
        self.dec2 = nn.ConvTranspose3d(decoder_dims[0] + encoder_dims[2], decoder_dims[1], kernel_size=3, stride=2, padding=1, output_padding=1)
        self.dec3 = nn.ConvTranspose3d(decoder_dims[1] + encoder_dims[1], decoder_dims[2], kernel_size=3, stride=2, padding=1, output_padding=1)
        self.dec4 = nn.ConvTranspose3d(decoder_dims[2] + encoder_dims[0], decoder_dims[3], kernel_size=3, stride=2, padding=1, output_padding=1)

    def forward(self, features, coords):
        # In a real sparse implementation, operations are applied only to active coords.
        # Here we assume features are already packed and processed sequentially.
        # Encoder
        x = features.view(1, -1, 1, 1, 1) # Placeholder for spatial dims
        x = torch.relu(self.enc1(x))
        x = torch.relu(self.enc2(x))
        x = torch.relu(self.enc3(x))
        x = torch.relu(self.enc4(x))
        # Decoder with skip connections
        x = torch.relu(self.dec1(x))
        x = torch.cat([x, x], dim=1) # Skip connection placeholder
        x = torch.relu(self.dec2(x))
        x = torch.cat([x, x], dim=1)
        x = torch.relu(self.dec3(x))
        x = torch.cat([x, x], dim=1)
        x = torch.relu(self.dec4(x))
        return x.view(-1, x.shape[1])

class MultiResolutionHashGrid(nn.Module):
    def __init__(self, min_res, max_res, levels, feat_dim):
        super(MultiResolutionHashGrid, self).__init__()
        self.levels = levels
        self.feat_dim = feat_dim
        self.grids = nn.ModuleList()
        for i in range(levels):
            res = int(min_res * (max_res / min_res) ** (i / (levels - 1)))
            grid_size = res ** 3
            self.grids.append(nn.Embedding(grid_size, feat_dim))

    def forward(self, x):
        features = []
        for i, grid in enumerate(self.grids):
            res = int(16 * (4096 / 16) ** (i / 15)) # Approximate resolution calculation
            indices = hash_coordinates(x, resolution=res)
            feats = grid(indices)
            features.append(feats)
        return torch.cat(features, dim=-1)

def hash_coordinates(x, resolution):
    """Hash 3D coordinates to grid indices."""
    # Normalize to [0, resolution)
    coords = (x * resolution).long() % resolution
    # Simple 3D hash
    h = (coords[:, 0] * 73856093) ^ (coords[:, 1] * 19349663) ^ (coords[:, 2] * 83492791)
    return h % (resolution ** 3)
```

### Edge Cases and Pitfalls
*   **Empty Cells:** The sparse UNet relies on sparse convolution, which only processes active (non-zero) elements. Empty cells in the $512 \times 512 \times 512$ grid carry negligible information and are ignored, enhancing efficiency [S1].
*   **Precision:** Hash encoding involves integer hashing and floating-point interpolation. Precision issues may arise if hash collisions are not handled well or if interpolation is inaccurate.
*   **Boundary Conditions:** The scene is bounded by a sphere defined by the camera trajectory plus 50 meters. Points outside this sphere may not be handled correctly if not clamped or ignored [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Memory:** The hash grid memory usage depends on the number of levels and resolutions. The density network uses 16 levels with 2-dim features, and the proposal sampler uses 5 levels with 2-dim features. The sparse UNet memory usage is proportional to the number of active LiDAR points and the grid size ($512^3$ cells, but sparse).
*   **Time:** Sparse convolution is efficient for sparse data. Hash encoding is $O(1)$ per query. The MLPs are small (2 layers, 16-64 hidden units), so they are fast. The overall complexity is dominated by the number of sampled points (4,096 per iteration) [S1].

### Measured Performance
*   **Hardware:** Not given in the sources.
*   **Resolution:** Not given in the sources.
*   **Scene:** Tested on street scenes (Argoverse dataset mentioned in source [S1]).
*   **Scaling:** The method scales with the number of LiDAR points and sampled points. The sparse UNet handles sparsity well.

### Strengths and Limitations
*   **Strengths:** Efficient processing of sparse LiDAR data using sparse UNet. Joint learning of geometry and attributes. High-resolution results compared to baselines (Chang et al.) [S1].
*   **Limitations:** Relies on accurate LiDAR point cloud registration. Performance may degrade in areas with sparse LiDAR coverage.

### When to Use
*   Use when dealing with LiDAR-based NeRF tasks where efficient processing of sparse point clouds is required.
*   Use when joint learning of geometry and attributes (distance, intensity) is needed.

### When Not to Use
*   Not suitable for purely visual NeRF tasks without LiDAR data.
*   Not suitable for dense point cloud data where sparse convolution benefits are minimal.

## Background

### Origin
The LidaRF network architecture was introduced in the paper "LidaRF: Delving into Lidar for Neural Radiance Field on Street Scenes" [S1].

### History and Development
LidaRF is part of the LiDAR-NeRF framework, which aims to synthesize novel LiDAR views using neural radiance fields. It builds on previous work in NeRF and LiDAR processing, integrating sparse convolution and hash encoding for efficiency and accuracy [S1].

### Where it is Used
Used in autonomous driving and street scene reconstruction, specifically for novel view synthesis of LiDAR data [S1].
