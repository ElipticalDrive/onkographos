# MixRT

Also called: Mixed Neural Representations For Real-Time NeRF Rendering

## Overview
MixRT is a hybrid neural representation for real-time Neural Radiance Field (NeRF) rendering on edge devices, designed to overcome the speed limitations of pure neural models and the storage overhead of high-fidelity baked meshes [S1]. It solves the problem of achieving photorealistic novel view synthesis at interactive frame rates by decomposing the scene representation into three distinct components: a low-quality triangle mesh for coarse geometry, a view-dependent displacement map for surface calibration, and a compressed NeRF model stored in an Instant-NGP hash table for density and color [S1]. Unlike sibling methods that rely on high-quality meshes or pure voxel grids, MixRT specifically leverages the parallel processing capabilities of rasterizers, texture mapping units, and SIMD units available in standard WebGL hardware to maximize rendering throughput [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera pose (view and projection matrices), scene data consisting of a low-quality triangle mesh, a view-dependent displacement map, and a compressed NeRF hash table.
*   **Outputs:** A rendered 2D image with color and optionally depth.

**Data Structures:**
1.  **Triangle Mesh:** Stores geometric vertex coordinates, texture coordinates, and polygonal face elements. Per-vertex appearance parameters are not stored [S1]. The mesh is post-processed with vertex order optimization to improve cache hit rates for neighboring triangles [S1].
2.  **View-Dependent Displacement Map:** A texture map storing spherical harmonics (SH) coefficients and scale factors. These are accessed via texture coordinates associated with the mesh vertices [S1].
3.  **Compressed NeRF Model:** Implemented as an Instant-NGP format 3D embedding grid stored in a compact 1D hash table [S1]. The hash table configuration is tuned by shrinking the number of levels and enlarging the table size to boost rendering speed [S1].
4.  **MLP Model:** A small Multi-Layer Perceptron with 2 hidden layers, each containing 64 units, used to decode embeddings into density and color [S1].

**Rendering Pipeline:**
The rendering process maps the unbounded scene domain into a finite sphere for the NeRF model using the contraction function from [4], while keeping the mesh and displacement map in their original space [S1]. The pipeline proceeds as follows:

1.  **Ray-Mesh Intersection:** For each pixel, a ray is cast. The rasterizer hardware performs mesh rasterization to determine the intersection point $p$ between the ray and the low-quality mesh [S1].
2.  **Surface Calibration:** Using the texture coordinates at $p$, the texture mapping units access the displacement map to retrieve the SH coefficients and scale. These are used to compute a calibrated point $p_{cali}$, correcting the coarse geometry of the mesh [S1].
3.  **Feature Retrieval:** The calibrated point $p_{cali}$ is processed by SIMD units. The system retrieves embeddings for the eight closest vertices from the 3D grid stored in the hash table. The table index is determined by the coordinates of $p_{cali}$ [S1].
4.  **Interpolation:** Trilinear interpolation is performed on the eight retrieved embeddings to obtain the final feature embedding for the point [S1].
5.  **Color and Density Decoding:** The interpolated embedding is fed into the small MLP (2 layers, 64 hidden units) to predict the volume density and view-dependent color [S1].

**Parameters:**
*   **Mesh Complexity:** Approximately 15 MB storage size [S1].
*   **MLP Architecture:** 2 layers with 64 hidden units each [S1].
*   **Hash Table Configuration:** Number of levels is shrunk; hash table size is enlarged [S1].
*   **Typical Performance:** > 30 FPS at 1280x720 resolution on a MacBook M1 Pro [S1].

**Edge Cases and Pitfalls:**
*   **Storage vs. Speed Trade-off:** Directly combining a low-quality mesh with a standard Instant-NGP hash table retains storage efficiency but fails to achieve real-time rendering speeds [S1]. The hash table structure must be modified (shrinking levels, enlarging size) to meet performance targets [S1].
*   **Geometry Quality:** A low-quality mesh with a hash table color field achieves ~0.3 higher PSNR than a high-quality mesh with 5x more triangles, while consuming only 0.26x the storage size [S1]. However, the mesh must still provide a valid initial intersection for the rasterizer.

## Operating characteristics
*   **Time Complexity:** Rendering speed is dominated by the hash table lookup and MLP inference, optimized via SIMD and texture units. Achieves > 30 FPS at 1280x720 on edge devices (MacBook M1 Pro) [S1].
*   **Memory/Storage Complexity:** Storage size is less than 80% of state-of-the-art methods (e.g., BakedSDF, which uses > 300 MB vs. MixRT's ~15 MB mesh + compressed NeRF) [S1].
*   **Performance:** Achieves 0.2 PSNR higher quality than state-of-the-art methods on indoor scenes of the Unbounded-360 dataset [S1].
*   **Strengths:** High rendering speed on edge devices via WebGL; low storage footprint; leverages standard graphics hardware (Rasterizer, TMU, SIMD).
*   **Limitations:** Relies on WebGL compatibility; quality depends on the accuracy of the displacement map and hash table interpolation; not suitable for scenes requiring high-frequency geometric detail without the displacement map.
*   **When to use:** Real-time NeRF rendering on resource-constrained devices (laptops, mobile) where storage and FPS are critical.
*   **When not to use:** When highest possible geometric fidelity is required without approximation, or on hardware without WebGL/SIMD support.

## Background
MixRT was proposed to address the practical application limitations of NeRF on edge devices, where slow rendering speeds have historically hampered immersive interactions [S1]. The method challenges the convention that high-quality geometry (represented by meshes with substantial triangles) is necessary for photorealistic rendering, observing instead that a low-quality mesh combined with neural color fields can suffice [S1]. It builds on the Instant-NGP representation [24] and the contraction function from [4], adapting them for a rasterization-based pipeline accessible via WebGL APIs [S1]. The work highlights that high-quality novel view synthesis does not necessarily demand extensive triangles if supported by efficient neural color fields and hardware-accelerated texture sampling [S1].
