# Active Set Method for OIT-based 3DGS

Also called: Active Set OIT 3DGS, SparseOIT, SparseOIT Active Set, SparseOIT acceleration

## Overview
The Active Set Method for OIT-based 3DGS (SparseOIT) is an optimization strategy that accelerates the training of Order-Independent Transparency (OIT) based 3D Gaussian Splatting by exploiting the sparsity of variable dependencies among Gaussian splats [S1, unofficial]. Unlike standard 3DGS which relies on depth sorting, which is expensive, SparseOIT removes the sorting step entirely and freezes Gaussians that have converged or contribute negligibly to the gradient, optimizing only a subset of "active" variables [S1, unofficial]. This approach achieves comparable novel-view quality to volumetric rendering methods while significantly outperforming existing OIT-based methods in training speed [S1, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   Training views: A set of images $I$ with corresponding camera poses [S1, unofficial].
*   Initial Gaussian parameters $G = \{\bm{\mu}, \bm{q}, \bm{s}, o, \bm{h}, w\}$, where $\bm{\mu}$ is position, $\bm{q}$ is quaternion, $\bm{s}$ is scale, $o$ is opacity, $\bm{h}$ is spherical harmonics coefficients, and $w$ is weight [S1, unofficial].
*   Pre-rendered images $I^{pre}$ for each training view, initialized to zero or background color [S1, unofficial].

**Outputs:**
*   Optimized Gaussian parameters $G$ [S1, unofficial].
*   Final rendered images [S1, unofficial].

### Data Structures
*   **Active Set ($A$):** A boolean mask or index list identifying which Gaussians are currently being optimized [S1, unofficial].
*   **Non-Active Set ($\bar{A}$):** The complement of $A$, containing Gaussians that are frozen [S1, unofficial].
*   **Pre-rendered Images ($I^{pre}$):** A buffer storing the rendered contribution of the non-active set $\bar{A}$ for each training view [S1, unofficial].
*   **Gradient Thresholds ($\epsilon_v$):** A scalar threshold for each attribute type $v \in \{\bm{\mu}, \bm{q}, \bm{s}, o, \bm{h}, w\}$ used to determine activeness [S1, unofficial].

### Algorithm Steps
1.  **Initialization:** Initialize the active set $A$ to include all Gaussians [S1, unofficial]. Initialize pre-rendered images $I^{pre}$ for all training views [S1, unofficial]. Set iteration counter $k=0$ [G].
2.  **Iteration Loop:** While not converged:
    3.  **Sample View:** Select a training view $i$ and retrieve its ground truth image $I_i$ and pre-rendered image $I_i^{pre}$ [S1, unofficial].
    4.  **Rasterize Active Gaussians:** Render only the Gaussians in the active set $G_A$ using the pre-rendered image $I_i^{pre}$ as the background/base [S1, unofficial]. This yields the output image $I_i^{out}$ [S1, unofficial]. Since OIT does not require sorting, the rendering of $G_A$ is added to $I_i^{pre}$ (which represents $\bar{A}$) to form the final composite [S1, unofficial].
    5.  **Compute Loss:** Calculate the photometric loss $L$ between the ground truth $I_i$ and the rendered output $I_i^{out}$ [S1, unofficial].
    6.  **Update Active Gaussians:** Compute gradients $\nabla L$ and update only the parameters of Gaussians in $G_A$ using an optimizer (e.g., Adam) [S1, unofficial].
    7.  **Active Set Update Check:** If the current iteration $k$ is a multiple of the update interval (or specifically at $K=15,000$ for the first update), perform an active set update:
        8.  **Subsample Views:** Select a subset of $M$ training views (e.g., $M=30$) using farthest point sampling with random initialization to estimate gradients efficiently [S1, unofficial].
        9.  **Estimate Gradients:** For each subsampled view $j$:
            *   Render all Gaussians $G$ (both active and non-active) using their respective pre-rendered images $I_j^{pre}$ to get $I_j^{out}$ [S1, unofficial].
            *   Compute the loss $L_j$ between $I_j^{out}$ and the ground truth $I_j$ [S1, unofficial].
            *   Compute gradients $\nabla L_j$ for all Gaussian attributes [S1, unofficial].
        10. **Update Active Set:** For each Gaussian $i$, determine its activeness indicator $\bm{1}_{\textup{active}}(i)$ based on the estimated gradients from the subsampled views [S1, unofficial]:
            $$
            \bm{1}_{\textup{active}}(i) = \bigvee_{v \in \{\bm{\mu}_i, \bm{q}_i, \bm{s}_i, o_i, \bm{h}_i, w_i\}} (\|\nabla_v\| > \epsilon_v)
            $$
            If $\bm{1}_{\textup{active}}(i)$ is true, Gaussian $i$ is added to $A$; otherwise, it is moved to $\bar{A}$ [S1, unofficial]. (Note: The source formula uses $\forall$ but explicitly clarifies that the Gaussian is active if at least one attribute variable has a non-zero gradient above the threshold.)
        11. **Lazy Pre-rendered Image Update:** When a Gaussian $i$ moves from $A$ to $\bar{A}$ (becomes inactive), its contribution must be added to the pre-rendered images [S1, unofficial]. To avoid poor GPU parallelism from sparse updates, this update is delayed until the specific pre-rendered image $I^{pre}$ is accessed for training [S1, unofficial]. When $I^{pre}$ is accessed, the contributions of newly inactive Gaussians are rendered and accumulated into $I^{pre}$ [S1, unofficial].
    12. Increment $k$.

### Pseudocode
```python
def active_set_oit_3dgs(training_views, initial_gaussians, K_activate=15000, M_subsample=30, epsilon_v=1e-4):
    """
    SparseOIT Active Set Method for OIT-based 3DGS.
    
    Args:
        training_views: List of (image, camera_pose) tuples.
        initial_gaussians: Initial set of Gaussian parameters G.
        K_activate: Iteration count after which active set method is activated.
        M_subsample: Number of views to subsample for active set update.
        epsilon_v: Threshold for gradient norm to determine activeness.
        
    Returns:
        Optimized Gaussian parameters G.
    """
    G = initial_gaussians
    N = len(G)
    active_mask = [True] * N
    pre_rendered = [zeros_like(view.image) for view in training_views]
    prev_active_mask = active_mask.copy()
    pre_rendered_stale = [False] * len(training_views)
    learning_rate = 0.01
    update_interval = 1000  # Not given in the sources.

    while not check_convergence(G):  # [G] Standard check: max gradient norms < threshold
        # 1. Sample view (round-robin for determinism)
        view_id = len(G) % len(training_views)  # Placeholder for actual sampling logic
        view = training_views[view_id]

        # 2. Lazy update of pre-rendered image if stale
        if pre_rendered_stale[view_id]:
            newly_inactive = [i for i in range(N) if not active_mask[i] and prev_active_mask[i]]
            if newly_inactive:
                inactive_contrib = render_oit_additive(G[newly_inactive], zeros_like(view.image))
                pre_rendered[view_id] += inactive_contrib
            pre_rendered_stale[view_id] = False

        # 3. Render active Gaussians + Pre-rendered background
        active_indices = [i for i in range(N) if active_mask[i]]
        rendered = render_oit_additive(G[active_indices], pre_rendered[view_id])

        # 4. Compute loss & gradients
        loss = l2_loss(rendered, view.image)
        grads = compute_gradients(loss, G, view)

        # 5. Update active Gaussians
        for i in active_indices:
            for v in ['mu', 'q', 's', 'o', 'h', 'w']:
                G[i][v] -= learning_rate * grads[i][v]

        # 6. Active Set Update
        if K_activate == 0 or (K_activate > 0 and (len(G) == K_activate or len(G) % update_interval == 0)):
            # Subsample views
            subsampled_ids = farthest_point_sampling(training_views, M_subsample)

            # Estimate gradients on subsampled views
            all_grads = {i: {v: zeros_like(get_attr(G[i], v)) for v in ['mu', 'q', 's', 'o', 'h', 'w']} for i in range(N)}
            for j in subsampled_ids:
                j_view = training_views[j]
                # Render ALL Gaussians for accurate gradient estimation
                full_rendered = render_oit_additive(G, pre_rendered[j])
                full_loss = l2_loss(full_rendered, j_view.image)
                full_grads = compute_gradients(full_loss, G, j_view)
                for i in range(N):
                    for v in ['mu', 'q', 's', 'o', 'h', 'w']:
                        all_grads[i][v] += full_grads[i][v]

            # Update active set based on estimated gradients
            for i in range(N):
                is_active = any(norm(all_grads[i][v]) > epsilon_v for v in ['mu', 'q', 's', 'o', 'h', 'w'])
                active_mask[i] = is_active

            # Mark pre-rendered images as stale for lazy update
            if any(not active_mask[i] and prev_active_mask[i] for i in range(N)):
                pre_rendered_stale = [True] * len(training_views)

            prev_active_mask = active_mask.copy()

        len(G) += 1  # Placeholder for iteration counter
    return G

# Helper definitions
def render_oit_additive(gaussians, background):
    # OIT rendering: additive accumulation without depth sorting
    result = background.copy()
    for g in gaussians:
        result += project_and_accumulate(g)
    return result

def l2_loss(rendered, target):
    return sum((rendered[p] - target[p])**2 for p in range(len(rendered)))

def compute_gradients(loss, G, view):
    # Standard backpropagation through the differentiable OIT rendering operator
    return backprop(loss, G, view)

def farthest_point_sampling(views, k):
    # Select k views maximizing minimum pairwise distance
    if not views: return []
    selected = [views[0]]
    for _ in range(k-1):
        max_min_dist = -1
        best_view = None
        for v in views:
            if v in selected: continue
            min_dist = min(distance(v, s) for s in selected)
            if min_dist > max_min_dist:
                max_min_dist = min_dist
                best_view = v
        selected.append(best_view)
    return selected

def norm(vec): return (sum(x**2 for x in vec))**0.5
def zeros_like(tensor): return [[0.0 for _ in row] for row in tensor]
def get_attr(g, attr): return g[attr]
def check_convergence(G): return False  # [G] Placeholder for standard convergence check (e.g., gradient norms < threshold)
```

### Parameters
*   **$\epsilon_v$**: Threshold for gradient norm to determine activeness. Empirically set to balance efficiency and performance [S1, unofficial].
*   **$K$**: Iteration count after which the active set method is activated. Value: 15,000 iterations [S1, unofficial]. This allows the initial densification phase of 3DGS to complete before sparsity optimization begins [S1, unofficial].
*   **$M$**: Number of subsampled views for active set update. Value: 30 [S1, unofficial]. Selected using farthest point sampling with random initialization [S1, unofficial].

### Edge Cases and Pitfalls
*   **Pre-rendered Image Update Cost:** Directly updating all pre-rendered images after each active set update is prohibitive due to sparsity and poor GPU parallelism [S1, unofficial]. The solution is to delay the update until the pre-rendered image is used for training [S1, unofficial].
*   **Active Set Update Complexity:** Naively updating the active set by re-evaluating gradients of all Gaussians for all views has complexity comparable to a full-variable update, negating acceleration [S1, unofficial]. The solution is to approximate Gaussian gradients via subsampling [S1, unofficial].
*   **Variance:** The method exhibits noticeable variance across different runs due to the stochastic nature of subsampling and farthest point sampling [S1, unofficial]. Reported values are averaged over multiple runs to provide a more reliable evaluation [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The training time is reduced by a factor proportional to the sparsity of the active set [S1, unofficial]. The active set update step has sublinear complexity $O(M \cdot N)$ where $M$ is the number of subsampled views and $N$ is the number of Gaussians, compared to $O(V \cdot N)$ for full updates where $V$ is the total number of views [S1, unofficial].
*   **Memory Complexity:** Memory usage is similar to standard OIT-based 3DGS, requiring storage for pre-rendered images for each training view [S1, unofficial]. However, it avoids the memory overhead of storing depth-sorted lists per pixel [S1, unofficial].
*   **Performance:** SparseOIT significantly outperforms existing OIT-based methods in training speed while achieving comparable novel-view rendering quality to state-of-the-art volumetric rendering methods (like standard 3DGS) [S1, unofficial].
*   **Strengths:** Eliminates the need for depth sorting, which is a bottleneck in OIT methods [S1, unofficial]. Accelerates training by freezing converged Gaussians [S1, unofficial]. Integrates well with GPU acceleration techniques like Taming-3DGS [S1, unofficial].
*   **Limitations:** Introduces variance in results [S1, unofficial]. Requires careful tuning of the activation threshold $\epsilon_v$ and the update interval [S1, unofficial]. The initial 15,000 iterations are identical to standard 3DGS, so acceleration only occurs after this point [S1, unofficial].

## Background
The Active Set Method for OIT-based 3DGS, also known as SparseOIT, was proposed to address the computational inefficiencies of Order-Independent Transparency (OIT) based 3D Gaussian Splatting [S1, unofficial]. Standard 3DGS relies on depth sorting, which is expensive [S1, unofficial]. OIT-based methods remove sorting but suffer from slower convergence and higher computational cost due to the lack of sparsity exploitation [S1, unofficial]. SparseOIT leverages the observation that Gaussian splats have sparse variable dependencies, allowing an active set optimization strategy to accelerate training [S1, unofficial]. The method was introduced in the paper "SparseOIT: Improving Order-Independent Transparency 3DGS via Active Set Method" [S1, unofficial].
