# Neighbor-Replacement Strategy

Also called: Neighbor Replacement

## Overview
The Neighbor-Replacement Strategy is a post-processing step applied within cascaded Bundle Adjustment (BA) modules to correct poorly estimated camera poses [S1]. It identifies inferior views based on rendered image quality and replaces their poses with those of the most similar neighboring cameras [S1]. Unlike standard BA which refines poses iteratively, this strategy explicitly swaps poses to eliminate the detrimental impact of inaccurate initial estimates on scene representation [S1]. It is distinct from sibling methods like [Best Viewpoint Selection via Opacity Entropy](1121-best-viewpoint-selection-via-opacity-entropy.md) by focusing on pose correction via replacement rather than viewpoint selection, and differs from [BARF (Bundle-Adjusting Neural Radiance Fields)](6872-barf-bundle-adjusting-neural-radiance-fields.md) by using a discrete replacement mechanism rather than continuous joint optimization of poses and fields [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of all camera views $Q = \{q_k | k = 1, 2, ..., N\}$, where each $q_k$ includes a camera pose estimate and an associated image. A classification of each view as either "superior" ($Q_s$) or "inferior" ($Q_i$) based on a prior quality criterion [S1].
*   **Output:** An updated set of camera pose estimates $\tilde{Q} = \{\tilde{q}_k | k = 1, 2, ..., N\}$ where inferior poses have been replaced [S1].

**Data Structures:**
*   $Q$: List of $N$ views.
*   $Q_s$: Subset of superior views.
*   $Q_i$: Subset of inferior views.
*   $\tilde{Q}_s, \tilde{Q}_i$: Updated subsets after non-maxima suppression.
*   `replacement_memory`: A set or map tracking poses already used for replacement to prevent redundancy [S1].

**Steps:**

1.  **Identify Inferior Views:**
    Apply the quality criterion from the preceding "Erroneous Pose Detection" step (referenced in [S1] Sec. III-B) to label views in $Q$ as superior ($Q_s$) or inferior ($Q_i$) [S1].

2.  **Non-Maxima Suppression:**
    Inaccurate poses affect neighboring views, causing them to also appear low-quality. To prevent mislabeling accurate neighbors as inferior:
    *   For any cluster of neighboring views labeled as inferior, identify the view with the lowest quality score.
    *   Assume only this lowest-scoring view is truly inaccurate.
    *   Discard the "inferior" label for the other neighboring views, reclassifying them as superior.
    *   Update the sets to $\tilde{Q}_s$ and $\tilde{Q}_i$ [S1].

3.  **Neighbor Search:**
    For each inferior view $q^e_i \in \tilde{Q}_i$:
    *   Search for the nearest neighbor view $q^e_{sim}$ in the full set $Q$ [S1].
    *   **Similarity Metric:** Use the combined criterion from the Erroneous Pose Detection step to measure similarity between $q^e_i$ and candidate views [S1].
    *   **Rotation Matching:** To expand the search space and improve accuracy, perform matching on rotated images with their corresponding camera poses equivalently rotated [S1]. This involves rotating the image and the pose by the same angle to find the best match under rotational ambiguity [S1].

4.  **Pose Replacement:**
    *   Replace the pose of $q^e_i$ with the pose of its nearest neighbor $q^e_{sim}$ [S1].
    *   Form the updated set $\tilde{Q} = \{\tilde{q}_k | k = 1, 2, ..., N\}$ [S1].

5.  **Replacement Memory (Guard):**
    *   Maintain a record of poses used for replacement for each erroneous viewpoint [S1].
    *   If a candidate neighbor pose has already been utilized for a previous replacement, skip it to prevent redundant erroneous replacements and optimization stagnation [S1].

**Pseudocode:**

```python
def neighbor_replacement(all_views, quality_scores, rotation_angles):
    """
    all_views: List of view objects, each with .pose, .image, .id
    quality_scores: Dict mapping view.id -> float (lower is worse)
    rotation_angles: List of angles to test for rotational matching
    
    Returns:
    updated_views: List of view objects with potentially replaced poses
    """
    # Step 1: Initial Classification
    superior_views = []
    inferior_views = []
    for view in all_views:
        if quality_scores[view.id] > threshold: # Threshold defined in prior step
            superior_views.append(view)
        else:
            inferior_views.append(view)
            
    # Step 2: Non-Maxima Suppression
    # Group inferior views by spatial neighborhood (e.g., k-nearest neighbors in pose space)
    # For each group, keep only the one with the absolute lowest score as inferior
    # Re-classify others as superior
    processed_inferior = []
    processed_superior = superior_views.copy()
    
    # Simple implementation of NMS for poses
    # Assume get_neighbors returns indices of k nearest poses in the current inferior set
    remaining_inferior = list(inferior_views)
    while remaining_inferior:
        # Find the view with the minimum score among remaining
        min_view = min(remaining_inferior, key=lambda v: quality_scores[v.id])
        processed_inferior.append(min_view)
        
        # Identify neighbors of min_view in the remaining set
        neighbors = get_neighbors(min_view, remaining_inferior, k=8) # k=8 typical for grid
        
        # Remove neighbors from remaining_inferior and add to processed_superior
        # because they are likely misidentified due to the min_view's error
        for neighbor in neighbors:
            if neighbor in remaining_inferior:
                remaining_inferior.remove(neighbor)
                processed_superior.append(neighbor)
                
    # Step 3 & 4: Replacement with Memory
    replacement_memory = set() # Stores IDs of poses already used as replacements
    updated_views = []
    
    for inferior_view in processed_inferior:
        best_similar_view = None
        best_score = -infinity
        
        # Search for nearest neighbor in ALL views (Q)
        for candidate in all_views:
            # Skip if this candidate's pose was already used
            if candidate.id in replacement_memory:
                continue
                
            # Calculate similarity with rotation matching
            # Simulate rotating candidate image and pose by each angle
            current_score = -infinity
            for angle in rotation_angles:
                # Rotate candidate image and pose
                rotated_img = rotate_image(candidate.image, angle)
                rotated_pose = rotate_pose(candidate.pose, angle)
                
                # Compute similarity between inferior_view and rotated candidate
                # Using the combined criterion from Erroneous Pose Detection
                sim = compute_similarity(inferior_view.image, rotated_img, 
                                         inferior_view.pose, rotated_pose)
                if sim > current_score:
                    current_score = sim
            
            if current_score > best_score:
                best_score = current_score
                best_similar_view = candidate
        
        # Perform replacement
        if best_similar_view is not None:
            # Create a copy of the inferior view with the new pose
            new_view = copy_view(inferior_view)
            new_view.pose = best_similar_view.pose
            updated_views.append(new_view)
            
            # Record the used pose to prevent reuse
            replacement_memory.add(best_similar_view.id)
        else:
            # Fallback: keep original pose if no valid neighbor found
            updated_views.append(inferior_view)
            
    # Add back the superior views (unchanged)
    for view in processed_superior:
        updated_views.append(view)
        
    return updated_views
```

**Parameters:**
*   **Rotation Angles:** Discrete angles tested for rotational matching. Not given in the sources.
*   **Neighbor Count (k):** Number of neighbors considered in non-maxima suppression. Not given in the sources.
*   **Threshold:** Quality score threshold for initial classification. Defined in the "Erroneous Pose Detection" step [S1].

**Edge Cases and Pitfalls:**
*   **Misidentification:** Inaccurate poses can cause neighboring accurate poses to be labeled as inferior. Non-maxima suppression mitigates this [S1].
*   **Redundant Replacement:** Incorrect matching can lead to cycles or redundant swaps. The replacement-memory technique prevents this [S1].
*   **No Ground Truth:** Since ground-truth poses are unknown, identification relies entirely on rendered image quality [S1].

## Operating characteristics
*   **Time Complexity:** Depends on the number of inferior views $N_i$ and the number of candidates $N$. For each inferior view, similarity is computed against all candidates with multiple rotations. Complexity is roughly $O(N_i \cdot N \cdot R)$, where $R$ is the number of rotation angles [S1].
*   **Memory Complexity:** $O(N)$ to store views and $O(N)$ for replacement memory [S1].
*   **Strengths:** Significantly improves pose optimization in the presence of large camera pose noise [S1]. Enhances the initialization for subsequent BA stages in a cascade [S1].
*   **Limitations:** Relies on the accuracy of the initial quality criterion [S1]. May fail if the nearest neighbor is also inaccurate and not caught by memory/guards [S1].
*   **When to Use:** When initial camera poses are noisy or insufficient, and ground-truth poses are unavailable [S1].
*   **When Not to Use:** When poses are already accurate, or when computational cost of repeated similarity checks is prohibitive [S1].

## Background
The Neighbor-Replacement Strategy was introduced in the CBARF (Cascaded Bundle-Adjusting Neural Radiance Fields) model [S1]. It addresses the problem that poor initialization of camera poses significantly impacts BA performance [S1]. The method is part of a cascade of BA modules, where replacement is applied between each pair of modules [S1]. It was developed to handle large camera pose noise in 3D reconstruction and novel view synthesis [S1].
