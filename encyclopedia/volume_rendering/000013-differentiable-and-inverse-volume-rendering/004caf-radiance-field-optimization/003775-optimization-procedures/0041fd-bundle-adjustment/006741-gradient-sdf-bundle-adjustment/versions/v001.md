# Gradient-SDF Bundle Adjustment

Also called: Gradient-SDF pose optimization, Implicit photometric bundle adjustment, Photometric Bundle Adjustment on Gradient-SDF

## Overview
Gradient-SDF Bundle Adjustment is a method for jointly optimizing camera poses and implicit geometry by minimizing a photometric cost function directly on a voxel-based Gradient-SDF representation, avoiding the conversion to explicit point clouds or meshes [S1]. Unlike explicit dense bundle adjustment methods such as [BAD SLAM](8541-bad-slam.md) which rely on surfel clouds, this approach maintains the implicit nature of signed distance fields while storing per-voxel gradients, enabling fully implicit optimization and sharper texture reconstruction [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** A set of $K$ keyframe images, their initial camera poses (from a depth-based tracker), and an initial Gradient-SDF volume. The Gradient-SDF stores a scalar SDF value and a 3D gradient vector per active voxel [S1].
*   **Outputs:** Optimized camera poses and an updated Gradient-SDF volume [S1].

**Data Structures**
The core data structure is a sparse voxel grid (e.g., hash map) where each active voxel $j$ stores:
1.  $d_j$: The signed distance value.
2.  $\mathbf{g}_j$: The gradient vector $\nabla d_j$, which approximates the surface normal direction [S1].
*Note: The sources mention storing weights and distances per voxel in a dense context ($2.68 \times 10^8$ variables) but contrast this with the sparse hash map usage ($2 \times 10^6$ voxels) for the BA experiments [S1]. The BA formulation operates on the implicit representation defined by these voxels.*

**Parameters**
*   **Number of keyframes ($K$):** 30 [S1].
*   **Keyframe ratio:** 10% (e.g., 30 out of 300 frames) [S1].
*   **Regularizer weight ($\lambda$):** $0.01 \, \text{cm}^{-2}$ [S1].
*   **Initial Geometry Source:** Depth-based tracker [S1].

**Algorithm Steps**
1.  **Initialization:** Obtain initial camera poses and a coarse Gradient-SDF volume using a depth-based tracker [S1].
2.  **Cost Formulation:** Define the photometric bundle adjustment cost function $E$ (referred to as Eq. 17 in the source) which measures the photometric consistency between the input images and the rendered gradients/SDF values from the current pose and geometry estimate [S1].
3.  **Optimization Strategy Selection:**
    *   *Full BA:* Optimize both camera poses and SDF voxel values simultaneously.
    *   *Pose-Only BA:* Optimize only camera poses, keeping the SDF geometry fixed. The sources indicate this yields on-par pose errors and visual quality while being faster [S1].
    *   *Decoupled Optimization:* Optimize poses decoupled from the global geometry update, achieving linear complexity in the number of keyframes with nearly identical pose improvement [S1].
4.  **Minimization:** Minimize the cost function $E$ using an iterative solver (e.g., Levenberg-Marquardt or similar gradient-based optimizer implied by the BA context) [S1].
5.  **Iteration:** Repeat minimization until convergence or a fixed iteration count is reached.

**Pseudocode**
```python
def gradient_sdf_bundle_adjustment(keyframes, initial_poses, initial_sdf_volume, num_iterations=10):
    """
    Performs Gradient-SDF Bundle Adjustment.
    
    Args:
        keyframes: List of image frames and their initial poses.
        initial_sdf_volume: Gradient-SDF volume (hash map of voxel -> (d, g)).
        num_iterations: Number of optimization iterations.
        
    Returns:
        optimized_poses: List of optimized camera poses.
        optimized_sdf_volume: Updated Gradient-SDF volume.
    """
    # Initialize poses and SDF volume
    poses = [p.copy() for p in initial_poses]
    sdf_vol = initial_sdf_volume.copy()
    
    # Parameters
    K = len(keyframes)
    lambda_reg = 0.01  # Regularizer weight in cm^-2
    
    for i in range(num_iterations):
        # Compute photometric cost and gradients w.r.t poses and SDF values
        # This corresponds to minimizing Eq. (17) from [S1]
        # The cost function evaluates photometric consistency between 
        # input images and the implicit Gradient-SDF representation.
        
        cost, pose_gradients, sdf_gradients = compute_photometric_cost_and_gradients(
            keyframes, poses, sdf_vol, lambda_reg
        )
        
        # Solve the linear system to update parameters
        # Using a solver like Levenberg-Marquardt or Gauss-Newton
        # The sources note that decoupled optimization yields linear complexity in K [S1]
        
        if use_decoupled_strategy:
            # Optimize poses only, keeping SDF fixed (or updated separately)
            pose_update = solve_linear_system(pose_gradients, cost)
            poses = update_poses(poses, pose_update)
            # SDF update step (if full BA) or skip (if pose-only)
            if not pose_only:
                sdf_update = solve_linear_system(sdf_gradients, cost)
                sdf_vol = update_sdf(sdf_vol, sdf_update)
        else:
            # Full coupled optimization
            combined_gradients = combine_gradients(pose_gradients, sdf_gradients)
            combined_update = solve_linear_system(combined_gradients, cost)
            poses = update_poses(poses, combined_update[:num_pose_params])
            sdf_vol = update_sdf(sdf_vol, combined_update[num_pose_params:])
            
    return poses, sdf_vol

def compute_photometric_cost_and_gradients(keyframes, poses, sdf_vol, lambda_reg):
    """
    Computes the photometric cost (Eq. 17) and its derivatives.
    The cost measures the difference between observed image colors and 
    colors predicted by ray-marching through the Gradient-SDF volume 
    at the current camera poses.
    """
    total_cost = 0.0
    pose_grads = []
    sdf_grads = []
    
    for frame_idx, (image, pose) in enumerate(zip(keyframes, poses)):
        # Ray march through the Gradient-SDF volume using the current pose
        # Sample points along rays, evaluating SDF value d and gradient g
        # Render expected color based on integration of density/alpha derived from d and g
        expected_color = render_gradient_sdf_ray(pose, sdf_vol)
        
        # Photometric error
        error = image - expected_color
        cost = sum(error**2)
        total_cost += cost
        
        # Compute gradients of cost w.r.t pose and SDF voxel values
        # This involves backpropagating through the ray marching and SDF evaluation
        # [G] Specific implementation of ray marching through hash-map SDF is assumed
        # based on standard differentiable rendering techniques for implicit surfaces.
        p_grad = compute_pose_gradient(error, pose, sdf_vol)
        s_grad = compute_sdf_gradient(error, pose, sdf_vol)
        
        pose_grads.append(p_grad)
        sdf_grads.append(s_grad)
        
    # Add regularizer term
    # [G] Regularizer form is not explicitly detailed beyond weight 0.01 cm^-2
    # Assuming a standard Tikhonov or similar regularization on SDF values/gradients
    reg_cost = lambda_reg * sum(sdf_vol.values()) 
    total_cost += reg_cost
    
    return total_cost, pose_grads, sdf_grads
```

**Edge Cases and Pitfalls**
*   **Precision:** The method relies on Taylor interpolation for sparse storage schemes, which is noted as superior to tri-linear interpolation for hash maps [S1].
*   **Memory:** While sparse hash maps reduce memory significantly ($2 \times 10^6$ voxels vs $2.68 \times 10^8$ for dense), the storage of gradients per voxel adds overhead compared to standard SDFs [S1].
*   **Decoupling:** Decoupled optimization is recommended for linear complexity in keyframes, but users must ensure that the decoupling assumption holds for their specific scene dynamics [S1].

## Subtopics

### Levenberg-Marquardt Pose Optimization
Uses LM solver for pose updates; Gradient-SDF BA can utilize this solver for the minimization step [S1, 11301-levenberg-marquardt-pose-optimization.md].

### Joint Optimization of NeRF and Camera Parameters
Gradient-SDF BA is an alternative to NeRF-based joint optimization, offering implicit geometry without neural network inference overhead [S1, 7492-joint-optimization-of-nerf-and-camera-parameters.md].

### BAD SLAM
The primary explicit comparison; Gradient-SDF BA achieves comparable pose error with sharper textures by avoiding surfel conversion [S1, 8541-bad-slam.md].

## Operating characteristics
*   **Time Complexity:** Pose-only decoupled optimization has linear complexity in the number of keyframes $K$ [S1].
*   **Runtime:** BA cost minimization takes 20–30 ms per iteration and pose using a single-threaded CPU implementation [S1]. Total pose estimation takes 30–40 ms per frame, compared to 100–120 ms for the baseline hash map direct SDF tracker [S1].
*   **Memory:** Sparse hash map storage uses approximately $2 \times 10^6$ voxels for typical indoor scenes, significantly less than dense volumes ($2.68 \times 10^8$ variables) [S1].
*   **Performance:** On TUM RGB-D sequences with 30 keyframes, Gradient-SDF pose-only coupled optimization achieves RMSE pose errors of 1.0, 1.0, 1.1, 1.0, and 0.6 cm for sequences fr1/xyz, fr1/teddy, fr2/xyz, fr2/rpy, and fr3/household, respectively [S1]. This is comparable to BAD SLAM (1.8, 3.7, 1.3, 0.9, 1.5 cm) [S1].
*   **Strengths:** Sharper textures than explicit methods; fully implicit optimization; fast runtime potential on GPU; no need for point cloud/mesh conversion [S1].
*   **Limitations:** Memory overhead for storing gradients per voxel; requires good initial geometry from a depth tracker [S1].

## Background
The Gradient-SDF representation was introduced as a semi-implicit surface representation that combines the implicit nature of standard SDF voxels with the surface normal property of surfels by storing gradients per voxel [S1]. It was proposed to enable direct SDF tracking from depth images and photometric bundle adjustment without transforming geometry into explicit forms [S1]. The method was presented in the context of 3D reconstruction, demonstrating superiority over explicit dense bundle adjustment approaches like BAD SLAM in terms of texture sharpness while maintaining comparable pose accuracy [S1].
