# Shonan Averaging for Pose Synchronization

Also called: Global pose configuration, Pose Synchronization (Global Alignment), Pose Synchronization via Shonan Averaging, Shonan averaging, global pose estimation, pose averaging

## Overview
Shonan Averaging for Pose Synchronization is a method for finding a global alignment of camera poses given a set of noisy relative pose measurements from local mini-scenes [S1]. It solves the non-convex optimization problem of registering local coordinate frames into a common global reference frame by iteratively relaxing the problem into higher-dimensional special-orthogonal spaces [S1]. It sets itself apart from its siblings by explicitly handling the non-convexity of the rotation component via Shonan relaxation, whereas [Lie Algebra (Tangent Plane) Pose Optimization](14005-lie-algebra-tangent-plane-pose-optimization.md) relies on local linearization and [Derivative-free Pose Estimation via Feature Matching](11310-derivative-free-pose-estimation-via-feature-matching.md) avoids gradient-based optimization entirely.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ local mini-scenes. For each mini-scene, LU-NeRF provides local camera poses and geometry [S1]. Relative pose observations $P_{ij}$ (rotation $R_{ij}$ and translation $t_{ij}$) between overlapping mini-scenes are derived from these local estimates [S1]. Confidence metrics (PSNR) for these relative poses are also provided [S1].
*   **Output:** A set of global poses $P = \{P_1, \dots, P_N\}$ where $P_i \in SE(3)$, representing the cameras in a common global reference frame [S1].

**Data Structures:**
*   **Relative Pose Graph:** Nodes represent mini-scenes. Edges represent relative pose measurements between overlapping mini-scenes.
*   **Scale Reference:** A Minimum Spanning Tree (MST) constructed over mini-scene centers to propagate scale consistency [S1].

**Steps:**

1.  **Scale Consistency Resolution:**
    The scale of each mini-scene is unique to its local reference frame [S1]. To resolve scale ambiguity:
    *   Construct an MST connecting the centers of all mini-scenes [S1].
    *   Fix the scale of one reference mini-scene [S1].
    *   Propagate the scale to other mini-scenes through the MST edges, ensuring that overlapping edges share a consistent scale [S1].

2.  **Heuristic Selection for Relative Poses:**
    Multiple relative pose measurements may exist for a pair of cameras $(C_i, C_j)$ because they may appear in multiple overlapping mini-scenes [S1]. To select a single measure:
    *   For cameras $C_i$ and $C_j$ with $i < j$, compare the PSNR of the rendering of $C_i$ in the mini-scene centered at $C_i$ versus the rendering of $C_i$ in the mini-scene centered at $C_j$ [S1].
    *   If $PSNR(I_i | C_i) > PSNR(I_i | C_j)$, select the relative pose estimation from the mini-scene centered at $C_i$ [S1].
    *   Apply this same heuristic to select the relative translation measure [S1].

3.  **Shonan Rotation Averaging:**
    Solve for the global rotations $R_i \in SO(3)$ by applying Shonan averaging [S1]. This method solves a convex relaxation of the rotation synchronization problem by iteratively converting the problem to higher-dimensional special-orthogonal spaces $SO(n)$ until convergence [S1].
    *   The input to this step is the set of selected relative rotations and their associated confidence weights [S1].

4.  **Translation Optimization:**
    With the global rotations $R_i$ fixed from Step 3, solve for the global translations $t_i$ [S1].
    *   The problem is formulated as a linear system based on the relative translation observations $t_{ij}$:
        $$ t_j - t_i = R_i t_{ij} $$
        where $t_{ij}$ is the relative translation between camera $i$ and $j$ from LU-NeRF, and $R_i$ is the global rotation of camera $i$ [S1].
    *   This linear system is solved using least-squares optimization [S1].

**Pseudocode:**

```python
def shonan_averaging_pose_synchronization(mini_scenes, relative_poses, confidences):
    """
    mini_scenes: List of mini-scene objects, each containing local poses and PSNR metrics.
    relative_poses: Dict mapping (i, j) to list of relative pose objects (R_ij, t_ij).
    confidences: Dict mapping (i, j) to list of confidence scores (PSNR).
    """
    # Step 1: Resolve Scale Ambiguity
    # Construct MST over mini-scene centers
    mst_edges = construct_mst(mini_scenes)
    
    # Fix reference scale and propagate
    reference_scene = mini_scenes[0]
    reference_scale = reference_scene.scale
    propagate_scale_through_mst(mst_edges, reference_scale)
    
    # Step 2: Select Best Relative Poses
    selected_rotations = {}
    selected_translations = {}
    
    for (i, j), pose_list in relative_poses.items():
        if i > j:
            continue # Handle each pair once
        
        best_pose = None
        best_psnr = -infinity
        
        for pose in pose_list:
            # Heuristic: Compare PSNR of camera i in its own mini-scene vs j's
            # Note: pose comes from a specific mini-scene context
            psnr_i_in_i = get_psnr(mini_scenes[i], mini_scenes[i])
            psnr_i_in_j = get_psnr(mini_scenes[i], mini_scenes[j])
            
            if psnr_i_in_i > psnr_i_in_j:
                current_confidence = psnr_i_in_i
            else:
                current_confidence = psnr_i_in_j
                
            if current_confidence > best_psnr:
                best_psnr = current_confidence
                best_pose = pose
        
        selected_rotations[(i, j)] = best_pose.R
        selected_translations[(i, j)] = best_pose.t

    # Step 3: Shonan Rotation Averaging
    # Input: selected_rotations and their confidences
    # Output: Global rotations R_i for all i
    global_rotations = shonan_rotation_averaging(selected_rotations, confidences)

    # Step 4: Translation Optimization
    # Solve linear system: t_j - t_i = R_i * t_ij
    # Construct matrix A and vector b for least squares
    A = []
    b = []
    
    for (i, j), t_ij in selected_translations.items():
        R_i = global_rotations[i]
        # Equation: t_j - t_i = R_i * t_ij
        # Reshape to linear constraints for t_i and t_j
        # Let t be the flattened vector of all translations
        # Add rows to A and b corresponding to this constraint
        
        # Row for t_i: -I
        # Row for t_j: I
        # RHS: R_i * t_ij
        
        A.append([-eye(3), eye(3)]) # Simplified representation
        b.append(R_i @ t_ij)
        
    # Solve least squares: min ||Ax - b||^2
    global_translations = solve_least_squares(A, b)
    
    # Construct final global poses
    global_poses = []
    for i in range(len(mini_scenes)):
        P_i = SE3(global_rotations[i], global_translations[i])
        global_poses.append(P_i)
        
    return global_poses
```

**Parameters:**
*   **Shonan Relaxation Dimension:** The method iteratively increases the dimension $n$ of the $SO(n)$ space [S1]. The specific stopping criterion or maximum dimension is not given in the sources, but it continues until convergence [S1].
*   **BARF Refinement:** After synchronization, a final global optimization is performed using BARF [30] for 200k iterations with a coarse-to-fine positional encoding strategy [S1].

**Edge Cases and Pitfalls:**
*   **Convergence Failure:** Shonan averaging may fail to converge to a reasonable global pose configuration if depth regularization is not used during the local LU-NeRF optimization, even if the maximum relative rotation error is small [S1].
*   **Scale Ambiguity:** Without the MST-based scale propagation, the global solution remains ambiguous in scale [S1].

## Subtopics

### Pose Synchronization
A robust step that registers local mini-scene poses into a common global reference frame using noisy relative pose measurements from overlapping mini-scenes [S1]. It computes a globally optimal positioning of all cameras from these noisy relative pose measurements [S1]. It is chosen when local estimates (e.g., from LU-NeRF) are inconsistent due to unique local reference frames and estimation errors [S1]. A key pitfall is that relative poses between images in overlapping mini-scenes will not perfectly agree due to these estimation errors and unique local scales [S1].

## Operating characteristics
*   **Time Complexity:** The pose synchronization step runs on CPU and has a negligible running time compared to the neural network training stages (e.g., 3.18 seconds vs. hours for LU-NeRF-1/2 and refinement) [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** On an NVIDIA Tesla P100, the synchronization step takes approximately 3.18 seconds on average [S1].
*   **Strengths:** It handles the general SE(3) pose setting without restrictive assumptions on pose priors, outperforming prior attempts at unposed NeRF [S1]. It is complementary to feature-based SfM pipelines, comparing favorably to COLMAP on low-texture and low-resolution images [S1].
*   **Limitations:** It relies on the quality of local relative pose estimates; if depth regularization is omitted in the local stage, global convergence may fail [S1].
*   **When to use:** When local pose estimates are available but inconsistent across overlapping regions, and a global consistent frame is required for further refinement (e.g., by BARF) [S1].
*   **When not to use:** When high-quality depth regularization is not available for local estimates, as convergence is not guaranteed [S1].

## Background
Shonan Averaging for Pose Synchronization is used in the LU-NeRF pipeline to bridge local mini-scene optimizations into a global scene representation [S1]. The method utilizes the off-the-shelf Shonan averaging technique [20] to solve the non-convex rotation synchronization problem [S1]. The specific application to NeRF pose synchronization was introduced in the LU-NeRF paper [S1].
