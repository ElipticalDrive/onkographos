# Inverse Rendering for Texture/Attribute Refinement

Also called: Photometric Loss Refinement, TexF Refinement via Inverse Rendering, UV Supervised Refinement

## Overview
This method refines the attributes of a surface-aligned texture field (TexF) by propagating image-space supervision through a differentiable rendering process [S1, unofficial]. It minimizes the photometric error between reference images (generated from standard UV mapping) and rendered images (generated by querying the TexF at rasterized surface positions) [S1, unofficial]. This approach reduces transfer and discretization errors during representation construction and refines the compressed neural field [S1, unofficial]. It builds on [Neural Volume Rendering Training (MSE)](3429-neural-volume-rendering-training-mse.md) by applying MSE-based optimization specifically to texture attributes in a 3D sparse voxel grid rather than a dense volume or implicit field.

## How it works
**Inputs and Outputs:**
*   **Input:** A surface-aligned texture field (TexF) defined on a sparse set of active voxels $Q$, where each voxel $q \in Q$ stores texture attributes (e.g., color, albedo). A set of reference images rendered from a 2D UV atlas. Camera parameters for the reference views.
*   **Output:** Refined voxel attributes for the active set $Q$.

**Data Structures:**
*   **Active Set $Q$:** A sparse collection of voxel indices $q \in \mathbb{Z}^3$ such that $0 \le q < K$, where $K$ is the grid resolution. Only voxels intersecting the mesh surface are included. The dense $K^3$ grid is not allocated [S1, unofficial].
*   **Voxel Attributes:** Each $q \in Q$ stores a vector of attributes. The specific dimensionality is not given in the sources [G: typically 3 for RGB color].

**Steps:**
1.  **Rasterization:** For each reference view, rasterize the mesh surface to obtain 2D screen coordinates and corresponding 3D surface positions.
2.  **TexF Query:** For each rasterized surface position, query the TexF. The attributes are obtained by trilinearly interpolating the attributes of the neighboring voxels in the sparse grid [S1, unofficial].
3.  **Rendering:** Construct the rendered image from the queried attributes. The exact shading model is not specified, but it implies a direct color mapping or simple shading consistent with the reference UV rendering [S1, unofficial].
4.  **Loss Computation:** Compute the photometric loss $\mathcal{L}_{photo}$ between the rendered image $I_{TexF}$ and the reference UV image $I_{UV}$:
    $$ \mathcal{L}_{photo} = \| I_{TexF} - I_{UV} \|^2 $$
    where $\| \cdot \|$ denotes the $L_2$ norm (MSE) [S1, unofficial].
5.  **Optimization:** Update the voxel attributes in $Q$ using gradient descent to minimize $\mathcal{L}_{photo}$ [S1, unofficial].

```python
def refine_texf_attributes(texf, mesh, reference_images, cameras, num_iterations, learning_rate):
    """
    Refine TexF attributes using inverse rendering.
    
    Args:
        texf: Sparse texture field object containing active voxel set Q and attributes.
        mesh: Mesh geometry (vertices, faces).
        reference_images: List of reference images (numpy arrays or tensors).
        cameras: List of camera parameters corresponding to reference images.
        num_iterations: Number of optimization steps.
        learning_rate: Step size for gradient descent.
        
    Returns:
        Refined TexF attributes.
    """
    # Initialize optimizer for TexF attributes
    optimizer = torch.optim.Adam(texf.attributes.parameters(), lr=learning_rate)
    
    for iteration in range(num_iterations):
        optimizer.zero_grad()
        total_loss = 0.0
        
        for ref_img, camera in zip(reference_images, cameras):
            # 1. Rasterize mesh to get surface positions for this view
            # Returns: screen_coords, surface_positions (3D points on mesh)
            screen_coords, surface_positions = rasterize_mesh(mesh, camera)
            
            # 2. Query TexF at surface positions using trilinear interpolation
            # Returns: rendered_colors (same shape as ref_img)
            rendered_colors = texf.query_trilinear(surface_positions)
            
            # 3. Construct rendered image from colors
            # (Assumes simple color mapping; shading details not specified)
            rendered_img = reconstruct_image(rendered_colors, screen_coords, ref_img.shape)
            
            # 4. Compute photometric loss (MSE)
            loss = torch.mean((rendered_img - ref_img) ** 2)
            total_loss += loss
            
        # 5. Backpropagate and update
        total_loss.backward()
        optimizer.step()
        
    return texf.attributes
```

## Subtopics

### Repaint123
Repaint123 uses a progressive controllable repainting mechanism to refine generated mesh textures [S2, unofficial]. It incorporates textural information from a reference image via attention feature injection and employs a visibility-aware repainting process to refine overlap regions with varying strengths [S2, unofficial]. The refined images are then used as ground truths to directly optimize the texture through MSE loss, achieving fast optimization [S2, unofficial]. This variant is distinct from the standard TexF refinement as it integrates diffusion-based repainting (SDS loss replacement) and attention mechanisms for texture injection, rather than direct voxel attribute optimization via trilinear queries [S2, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** The method uses a sparse voxel grid, avoiding the allocation of a dense $K^3$ grid. Memory usage is proportional to the number of active voxels intersecting the mesh surface, comparable to 2D texture maps [S1, unofficial].
*   **Time:** Each optimization step requires rasterization, trilinear interpolation, and MSE computation. The complexity per step is linear in the number of pixels and active voxels involved in the query [S1, unofficial].

**Measured Performance:**
*   Not given in the sources [S1, S2, unofficial].

**Scaling:**
*   The sparse support allows high-resolution texture representation with sample counts comparable to 2D texture maps, avoiding the high memory cost of dense volumetric textures [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Reduces transfer and discretization errors; efficient memory usage due to sparsity; direct optimization of 3D attributes [S1, unofficial].
*   **Limitations:** Requires differentiable rendering; sensitive to initial voxelization; boundary conditions for sparse grids are not specified [S1, unofficial].

**When to Use:**
*   Use when refining texture attributes for a surface-aligned sparse voxel grid (TexF) where memory efficiency is critical and high-resolution texture is needed [S1, unofficial].

**When Not to Use:**
*   Do not use if the texture representation is a dense 3D volume or a 2D UV atlas without 3D attributes [S1, unofficial].

## Background
Inverse rendering optimizes geometry or appearance by propagating image-space supervision through a differentiable rendering process [S1, unofficial]. The TexF method applies this to surface-aligned texture fields, organizing texture attributes in a sparse voxel grid derived from the mesh surface [S1, unofficial]. This allows surface positions to directly query the 3D field, providing a common spatial basis for texture representation, compression, and rendering [S1, unofficial]. The method was proposed to overcome limitations of conventional 2D UV atlas compression [S1, unofficial].
