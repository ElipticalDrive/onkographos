# DressiAD Optimization Loop

Also called: Dressi-AD Computational Graph Execution, DressiAD Training Loop, Optimization Loop

## Overview
The DressiAD Optimization Loop is a define-and-run differentiable rendering optimization procedure that constructs a computational graph, marks variables for gradient tracking, and executes forward/backward passes with Stochastic Gradient Descent (SGD) [S1]. It is distinct from eager-mode frameworks (like PyTorch) by explicitly managing graph traversal, packing the computation into Vulkan command buffers, and handling dirty-flag-based graph rebuilding [S1]. It builds on [Framework and Baseline Implementations](16220-framework-and-baseline-implementations.md).

## How it works
**Inputs and Outputs:**
*   **Inputs:** Scene data (vertex positions, UVs, faces, matrices, environment map, albedo, metallic, roughness, normal, background) loaded into CPU memory [S1]. Target images for loss calculation [S1].
*   **Outputs:** Optimized scene parameters (e.g., vertex positions, normal maps) saved as GLTF files [S1].

**Data Structures:**
*   **CpuImage:** A simple buffer of a 2D image used to store scene data [S1]. Non-image data (e.g., vertex positions) are converted into 2D image representation for efficient rendering [S1].
*   **Variable:** A data structure representing inputs and outputs of functions in the computational graph. It has a `type` (VEC3, VEC2, IVEC3, MAT4, FLOAT, VEC4) and `size` [S1]. It includes methods `setRequiresGradRecursively()` and `setDirtyRecursively(bool)` [S1].
*   **Function:** Wraps forward GLSL code and a backward generator [S1].
*   **DressiAD Class:** Contains interfaces for `setLossVar()`, `setOptimizer()`, `sendImg()`, `recvImg()`, and `execStep()` [S1]. It maintains an `InitStatus` enum (`BACKWARD`, `STAGE`, `SUBSTAGE`, `FINISHED`) and counters `m_graph_static_cnt` [S1].

**Parameters:**
*   `lr`: Learning rate for the SGD optimizer. Typical value: 0.01f [S1].
*   `K`: Number of peeling for HardSoftRas. Typical value: 2 [S1].
*   `r`: Radius parameter for HardSoftRas. Typical value: 0.01f [S1].
*   `sigma`: Blending parameter for HardSoftRas. Calculated as `r / 7.f` [S1].
*   `delta`: Silhouette edge width for HardSoftRas. Calculated as `r` [S1].
*   `FAST_REBUILD_COUNT` and `FULL_REBUILD_COUNT`: Thresholds for `m_graph_static_cnt` to trigger graph rebuilds [S1]. Values not given in the sources.

**Steps:**
1.  **Initialization:** Create a renderer instance (e.g., `DressiBasicRenderer`) and load scene data from files into CPU memory [S1].
2.  **Graph Construction:** Build a computational graph by calling `BuildBasicRenderGraph` with scene variables and HardSoftRas parameters (`K, r, sigma, delta`) [S1].
3.  **Loss Calculation:** Compute L1 loss between the target image and the rendered image: $L = \text{Mean}(|I_{target} - I_{rendered}|)$ [S1].
4.  **Target Marking:** Mark vertex positions and normal textures as optimization targets using `requires-gradient` flags via `setRequiresGrad()` [S1].
5.  **Optimizer Setup:** Set the loss variable and an SGD optimizer function to the DressiAD instance [S1]. The SGD update rule is $x_{new} = x_{old} - g \cdot lr$ [S1].
6.  **Optimization Loop:** For each iteration:
    a.  Check if any input variable has changed dirty flags. If so, reset `m_graph_static_cnt` to 0 [S1].
    b.  If `m_graph_static_cnt` equals `FAST_REBUILD_COUNT`, set `m_init_status` to `InitStatus::STAGE` [S1].
    c.  If `m_graph_static_cnt` equals `FULL_REBUILD_COUNT`, set `m_init_status` to `InitStatus::SUBSTAGE` [S1].
    d.  Execute `execStep()` [S1].
7.  **Execution (`execStep`):**
    a.  Send CPU images to GPU if needed (marking variables as dirty) [S1].
    b.  Construct backward pass: Traverse the forward computational graph starting from the loss variable. Initialize gradient of loss to 1.0. For each function, generate backward graph using `Function::buildBwd()`. Sum gradients for variables with multiple creators [S1].
    c.  Pack the graph into Vulkan stages and sub-stages [S1].
    d.  Execute Vulkan commands via `VkQueueSubmit(m_vk_cmd_buf)` [S1].
    e.  Mark all input variables as clean recursively [S1].
    f.  Set `m_init_status` to `FINISHED` [S1].
    g.  Collect input and gradient variables, summing pixel-wise gradients for variables with multiple creators [S1].
8.  **Iteration:** The optimizer function applies the gradient update to the marked variables [S1].
9.  **Finalization:** Save optimized data as a GLTF file [S1].

## Background
The DressiAD Optimization Loop originates from the Dressi renderer, a hardware-agnostic differentiable renderer with reactive shader packing and soft rasterization [S1]. It was proposed in 2022 [S1]. The system is designed to be similar to common AD libraries like PyTorch and TensorFlow but uses a define-and-run approach [S1]. It is used for differentiable rendering optimization of vertex positions and normal maps [S1].
