# Training Loop Setup

Also called: Training Step Execution

## Overview
The Training Loop Setup defines the execution of a single optimization iteration for a radiance field, encompassing data loading, forward rendering, loss computation, and parameter updates [S1, unofficial][S2, unofficial]. It differs from [Training Ray Batching](2252-training-ray-batching.md) by managing the specific tensor layouts and optimizer state interactions for a batch of rays, whereas batching focuses on the selection and shuffling of those rays [S2, unofficial]. It serves as the foundational atomic unit for higher-level procedures like [Training Loop](4290-training-loop.md) and [Training Loop with Adaptive Regularization & LR Decay](2408-training-loop-with-adaptive-regularization-lr-decay.md).

## How it works
**Inputs and Outputs:**
The method takes a batch of rays defined by pixel coordinates and camera parameters, along with the current state of the radiance field representation (e.g., 3D Gaussian splatting attributes or voxel features) and optimizer states. It outputs the updated model parameters and optimizer states after one gradient step.

**Data Structures:**
For the `msplat_train_step` variant, the input tensor layout is dense and explicit [S1, unofficial]:
- `numPoints`: Integer count of points/gaussians.
- `means`: Float32 array of shape `(numPoints, 3)`.
- `scales`: Float32 array of shape `(numPoints, 3)`.
- `glob_scale`: Float32 scalar (default 1.0f).
- `quats`: Float32 array of shape `(numPoints, 4)` (quaternions).
- `viewMat`, `projViewMat`: Float32 matrices for camera projection.
- `fx`, `fy`, `cx`, `cy`: Float32 camera intrinsics.
- `height`, `width`: Integer image dimensions.
- `tileBounds`: Integer array defining tile boundaries for rasterization.
- `near plane`: Float32 (default 0.01f).
- `degree`, `degreesToUse`: Integers for spherical harmonic degrees.
- `cam_pos`: Float32 array `(3,)`.
- `featuresDc`: Float32 array of DC color features.
- `featuresRest`: Float32 array of SH rest coefficients.
- `opacities`: Float32 array of per-point opacities.
- `backgroundColor`: Float32 array `(3,)`.
- `gt`: Float32 array `(batch_size, height, width, 3)` ground truth images.
- `SSIM window`: Float32 array for structural similarity calculation.
- `ssimWeight`: Float32 scalar.
- `lossInvN`: Float32 scalar, normalized as $1.0f / (height \times width \times 3)$ [S1, unofficial].
- `featuresRest stride`: Integer stride for feature memory layout.
- `N_ADAM_GROUPS`: Integer for optimizer partitioning.
- `Adam params`: Float32 arrays for `exp_avg`, `exp_avg_sq`, `scaled lr`, `sqrt(bc2)`.
- `Adam beta1`, `beta2`, `eps`: Float32 scalars.
- `visCounts`, `xysGradNorm`, `max2DSize`, `invMaxDim`: Float32/Integer auxiliary buffers for gradient normalization and visibility tracking. `invMaxDim` is calculated as $1.0f / \max(height, width)$ [S1, unofficial].

**Steps:**
1. **Data Loading:** Load image data and transformation matrices from file paths, moving tensors to the specified device (e.g., GPU) [S2, unofficial].
2. **Grid Initialization:** If using a grid-based representation, generate the initial grid using `generate_grid` with parameters `gridsize`, `points_distance`, `info_size=4`, and the target device [S2, unofficial].
3. **Forward Pass:** Render the batch of rays using the current model parameters (`means`, `scales`, `quats`, `features`, etc.) and camera matrices (`viewMat`, `projViewMat`) to produce predicted pixel colors.
4. **Loss Computation:** Calculate the loss between the rendered output and the ground truth (`gt`). The loss is typically normalized by `lossInvN` [S1, unofficial]. Structural Similarity (SSIM) may be included using `ssimWeight` and the `SSIM window` [S1, unofficial].
5. **Backward Pass:** Compute gradients with respect to the trainable parameters.
6. **Optimizer Update:** Update the model parameters and optimizer states (e.g., Adam moments) using the computed gradients and learning rate [S1, unofficial].

**Pseudocode:**
```python
def msplat_train_step(
    numPoints, means, scales, glob_scale, quats, viewMat, projViewMat,
    fx, fy, cx, cy, height, width, tileBounds, near_plane, degree,
    degreesToUse, cam_pos, featuresDc, featuresRest, opacities,
    backgroundColor, gt, ssim_window, ssimWeight, lossInvN,
    featuresRest_stride, N_ADAM_GROUPS, adam_exp_avg, adam_exp_avg_sq,
    adam_scaled_lr, adam_sqrt_bc2, adam_beta1, adam_beta2, adam_eps,
    visCounts, xysGradNorm, max2DSize, invMaxDim
):
    # 1. Forward Rendering
    # Render rays defined by camera matrices and Gaussian parameters
    # This step involves projecting 3D Gaussians to 2D, sorting, and alpha-compositing
    rendered_image = render_gaussians(
        means=means, scales=scales, glob_scale=glob_scale, quats=quats,
        viewMat=viewMat, projViewMat=projViewMat, fx=fx, fy=fy,
        cx=cx, cy=cy, height=height, width=width, tileBounds=tileBounds,
        near_plane=near_plane, degree=degree, degreesToUse=degreesToUse,
        cam_pos=cam_pos, featuresDc=featuresDc, featuresRest=featuresRest,
        opacities=opacities, backgroundColor=backgroundColor,
        featuresRest_stride=featuresRest_stride
    )

    # 2. Loss Computation
    # MSE Loss normalized by lossInvN
    mse_loss = torch.mean((rendered_image - gt) ** 2) * lossInvN
    
    # SSIM Loss (if applicable)
    # ssim_val = compute_ssim(rendered_image, gt, ssim_window)
    # ssim_loss = 1.0 - ssim_val
    # total_loss = mse_loss + ssimWeight * ssim_loss
    total_loss = mse_loss  # Simplified for core definition

    # 3. Backward Pass
    total_loss.backward()

    # 4. Optimizer Update (Adam)
    # Update moments and parameters
    # This step handles the specific Adam state updates for the msplat structure
    update_adam(
        params=[means, scales, quats, featuresDc, featuresRest, opacities],
        grads=[p.grad for p in [means, scales, quats, featuresDc, featuresRest, opacities]],
        exp_avg=adam_exp_avg,
        exp_avg_sq=adam_exp_avg_sq,
        scaled_lr=adam_scaled_lr,
        sqrt_bc2=adam_sqrt_bc2,
        beta1=adam_beta1,
        beta2=adam_beta2,
        eps=adam_eps,
        visCounts=visCounts,
        xysGradNorm=xysGradNorm,
        max2DSize=max2DSize,
        invMaxDim=invMaxDim,
        N_ADAM_GROUPS=N_ADAM_GROUPS
    )

    return rendered_image, total_loss
```

**Edge Cases and Pitfalls:**
- **Precision:** Use float32 for standard operations; mixed precision may be used in variants like [Mixed Precision Training](2766-mixed-precision-training.md).
- **Boundaries:** Ensure `tileBounds` and `near_plane` are correctly set to avoid rendering artifacts or division by zero in normalization.
- **Degenerate Input:** Handle cases where `numPoints` is zero or camera matrices are invalid.

## Subtopics

### [Training Ray Batching](2252-training-ray-batching.md)
Training Ray Batching is a data loading strategy for Neural Radiance Fields (NeRF) that selects a random subset of pixel coordinates (and their corresponding rays) from the full training image grid per optimization iteration, rather than rendering complete images. It solves the memory bottleneck of full-image rendering by processing only $N_{rand}$ rays at a time, enabling efficient gradient updates and better GPU memory utilization. It differs from [Training Loop for Refractive Index Field](4178-training-loop-for-refractive-index-field.md) and [Training Loop](4290-training-loop.md) by explicitly managing the pre-computation, shuffling, and batch-slicing of ray tensors across multiple training images, whereas those siblings focus on the network forward/backward passes or specific physical models.

### [Training Loop for Refractive Index Field](4178-training-loop-for-refractive-index-field.md)
This method defines the optimization loop for training a Multi-Layer Perceptron (MLP) to represent a 3D refractive index (IOR) field and associated emission field, using differentiable ray tracing. It distinguishes itself by combining Eikonal ray tracing with luminance integration, optimizing the IOR field via boundary regularization and luminance reconstruction loss, specifically implemented in JAX for multi-device sharding. It builds on [Training Loop Setup](1522-training-loop-setup.md) and [Training Ray Batching](2252-training-ray-batching.md).

### [Training Loop](4290-training-loop.md)
The Training Loop is the iterative optimization procedure that updates a radiance field representation (such as a NeRF or 3D Gaussian Splatting model) by minimizing the difference between rendered images and ground-truth observations. It differs from its sibling [Training Ray Batching](2252-training-ray-batching.md) by managing the high-level control flow, data loading, and optimizer state, whereas batching focuses specifically on the memory-efficient assembly of ray samples.

### Training Pipeline Configuration
The main entry point for the training experiment, which loads configuration, sets up global parameters, loads the scene and sensors, renders reference images, and initializes the SDF for optimization [S3, unofficial].
- Load configuration from JSON file `config_file`. Update experiment parameters (name, scene, epochs, lr, sensor counts, batch size) and rendering parameters (integrator, resolution, spp, SDF mode) using command-line args or config defaults [S3, unofficial].
- Load the scene using `mi.load_file` with the specified scene XML and hide environment flag [S3, unofficial].
- Set sensor parameters (radius, height) based on scene name: 'hotdog' (h=0.5), 'lego' (h=0.35), 'chair' (h=0.6, r=1.5), else (h=0.4, r=1.3). Load sensors using `get_h2_sensors` [S3, unofficial].
- Initialize the SDF for optimization as a `SphereSDF` with specified resolution and radius. Enable gradients on the SDF grid tensor [S3, unofficial].
- Check if albedo, roughness, and metallic volumes are present in the scene parameters to determine optimization targets [S3, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of rays in the batch and the number of samples per ray.
- **Memory Complexity:** Proportional to the batch size and the size of the radiance field representation.
- **Performance:** Highly dependent on GPU memory bandwidth and compute capabilities. Variants like [Mixed Precision Training](2766-mixed-precision-training.md) can improve throughput.
- **Strengths:** Modular design allows for easy integration of different loss functions and optimizers.
- **Limitations:** Memory usage can still be high for large scenes or high-resolution images if batching is not efficient.

## Background
The concept of a training loop setup is fundamental to differentiable rendering and neural radiance fields. Early implementations focused on simple gradient descent, while modern approaches incorporate advanced optimizers like Adam [S1, unofficial][S2, unofficial]. The specific `msplat_train_step` implementation is associated with the Msplat project, which aims for fast training on Apple Silicon [S1, unofficial]. The `Plenoxels` project also utilizes similar training loop structures for voxel-based radiance fields [S2, unofficial]. The `relaxed-boundary` project demonstrates a configuration-based approach for SDF optimization [S3, unofficial].
