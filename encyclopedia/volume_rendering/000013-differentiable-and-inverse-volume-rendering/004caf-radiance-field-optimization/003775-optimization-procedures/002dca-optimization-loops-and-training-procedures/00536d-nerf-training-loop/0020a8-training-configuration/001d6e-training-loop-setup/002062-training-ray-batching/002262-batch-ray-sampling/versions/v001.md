# Batch Ray Sampling

Also called: Batch Ray Generation, Random ray sampling, Ray batching, Ray-based training, batch ray selection

## Overview
Batch Ray Sampling generates training batches by selecting random pixels from training images and computing their corresponding ray origins and directions [S1, S2, S5, unofficial]. It differs from image-based training, which renders complete images per step, by using smaller batches of random rays to improve memory utilization and convergence speed [S5, unofficial]. This method is the standard approach in modern NeRF-style methods and differentiable volumetric rendering frameworks [S5, unofficial].

## How it works
The method supports two primary modes: precomputed ray buffers and on-the-fly generation. It also includes mechanisms for geometry filtering and semantic weighting.

### Inputs and Outputs
*   **Inputs:** Training images (RGB), camera parameters (intrinsics $K$, extrinsics $c2w$), batch size $N_{rand}$ (or `batch_size`), and optional flags (`precompute_rays`, `use_batching`, `mask_away_instance`).
*   **Outputs:** A batch of ray origins $r_o$, ray directions $r_d$, view directions $v_d$, and target RGB colors $C_{target}$.

### Data Structures
*   **Ray Buffer:** A tensor of shape $[N, 3]$ or $[N, 7+]$ containing ray origins, directions, and potentially near/far planes and view directions.
*   **Index Generator:** Maintains a permutation of ray indices to ensure uniform sampling over epochs.

### Parameters
*   $N_{rand}$: Number of rays to sample per batch. Typical values: 1024–2048 for small scenes, 4096–8192 for medium scenes, 16384+ for large scenes [S1, S5, unofficial].
*   `precrop_iters`: Number of iterations to restrict sampling to a center crop. Default: 0 [S1, unofficial].
*   `precrop_frac`: Fraction of image width/height for the center crop. Default: 0.5 [S1, unofficial].
*   `precompute_rays`: Boolean flag to use precomputed ray buffers [S6, unofficial].
*   `mask_away_instance`: Boolean for semantic sampling to exclude specific instances [S7, unofficial].
*   `extra_sampling`: Boolean to enable class-weighted sampling [S7, unofficial].
*   `class_ratio`: Dictionary mapping class IDs to sampling ratios [S7, unofficial].

### Steps

1.  **Ray Generation or Retrieval:**
    *   If `precompute_rays` is true: Fetch precomputed rays from the dataset buffer [S6, unofficial].
    *   If `precompute_rays` is false:
        *   Randomly select a training image index $i$ [S1, S6, unofficial].
        *   Compute ray origins $r_o$ and directions $r_d$ for all pixels in image $i$ using camera intrinsics $K$ and extrinsics $c2w$ [S2, unofficial].
        *   If `use_batching` is false, randomly select $N_{rand}$ pixel coordinates $(u, v)$ from the image grid [S1, S3, unofficial].
        *   If `use_batching` is true, slice the precomputed ray buffer for the current batch [S3, unofficial].

2.  **Center Cropping (Optional):**
    *   If current iteration $t < \text{precrop\_iters}$:
        *   Calculate crop dimensions $H_{crop} = \text{precrop\_frac} \times H$ and $W_{crop} = \text{precrop\_frac} \times W$ [S1, unofficial].
        *   Restrict pixel selection to the center region of the image [S1, unofficial].

3.  **Geometry Filtering (Optional):**
    *   For each ray in the batch, test intersection with coarse geometry (e.g., voxel grid or mesh) [S2, unofficial].
    *   Generate a boolean mask $M$ where $M_j = \text{true}$ if ray $j$ hits the geometry [S2, unofficial].
    *   Filter the batch: keep only rays where $M_j$ is true [S2, unofficial].
    *   *Pitfall:* The ratio of kept rays to total rays should be monitored; if too few rays survive, the batch size or geometry approximation may need adjustment [S2, unofficial].

4.  **Semantic Sampling (Optional):**
    *   If `mask_away_instance` is true:
        *   Create a mask excluding pixels belonging to specific instances: $M_{keep} = (\sum \text{instance\_seg} == 0)$ [S7, unofficial].
    *   If `extra_sampling` is true:
        *   For each class $c$ in `class_ratio`:
            *   Calculate extra rays: $N_{extra} = \lfloor \text{class\_ratio}[c] \times N_{rand} \rfloor$ [S7, unofficial].
            *   Identify pixel coordinates belonging to class $c$ using semantic segmentation masks [S7, unofficial].
            *   Sample $N_{extra}$ rays from these coordinates [S7, unofficial].
            *   Update remaining ray count: $N_{rand} \leftarrow N_{rand} - N_{extra}$ [S7, unofficial].
    *   *Pitfall:* If $\sum \text{class\_ratio} > 1$, $N_{rand}$ becomes negative, causing an error [S7, unofficial].

5.  **Subpixel Sampling (Differentiable Rendering):**
    *   For each ray in the batch:
        *   Get integer pixel coordinates $(u, v)$ [S4, unofficial].
        *   Sample a subpixel offset $\delta \in [0, 1)^2$ using a sampler (e.g., stratified or random) [S4, unofficial].
        *   Compute floating-point position: $p = (u + \delta_u, v + \delta_v)$ [S4, unofficial].
        *   Rescale to normalized device coordinates or film coordinates if required by the renderer [S4, unofficial].

6.  **Index Management:**
    *   Maintain a permutation array $P$ of size $N_{total}$ (total number of rays across all images) [S2, unofficial].
    *   Yield a batch of indices from $P$. If the current batch index exceeds $N_{total}$, regenerate $P$ using a random permutation [S2, unofficial].
    *   *Pitfall:* Use `np.random.permutation` instead of `torch.randperm` on CUDA if the latter produces incorrect results on the specific hardware [S2, unofficial].

### Pseudocode

```python
def sample_batch_rays(
    images, 
    poses, 
    K, 
    batch_size, 
    precompute_rays=False, 
    precomputed_rays=None,
    use_batching=False,
    precrop_iters=0,
    precrop_frac=0.5,
    mask_away_instance=False,
    extra_sampling=False,
    class_ratio=None,
    semantic_seg=None,
    instance_seg=None,
    hit_coarse_geo=None
):
    """
    Samples a batch of rays for training.
    
    Args:
        images: List of training images [H, W, 3].
        poses: List of camera-to-world matrices [3, 4].
        K: Camera intrinsics [3, 3].
        batch_size: Number of rays to sample.
        precompute_rays: If True, use precomputed ray buffers.
        precomputed_rays: Tuple of (rays_o, rays_d, viewdirs, rgb) precomputed for all images.
        use_batching: If True, slice from precomputed buffer.
        precrop_iters: Iterations to use center cropping.
        precrop_frac: Fraction of image for center crop.
        mask_away_instance: If True, mask out specific instances.
        extra_sampling: If True, oversample specific semantic classes.
        class_ratio: Dict mapping class ID to sampling ratio.
        semantic_seg: Semantic segmentation masks for images.
        instance_seg: Instance segmentation masks for images.
        hit_coarse_geo: Function to test ray-geometry intersection.
        
    Returns:
        rays_o: Ray origins [batch_size, 3].
        rays_d: Ray directions [batch_size, 3].
        viewdirs: View directions [batch_size, 3].
        targets: Target RGB values [batch_size, 3].
    """
    
    # 1. Get Base Rays
    if precompute_rays:
        # Fetch from precomputed buffer
        # Assuming precomputed_rays is a list of tensors or a single large tensor
        # For simplicity, assume we have a global index generator
        indices = get_next_batch_indices(batch_size)
        rays_o = precomputed_rays[0][indices]
        rays_d = precomputed_rays[1][indices]
        viewdirs = precomputed_rays[2][indices]
        targets = precomputed_rays[3][indices]
    else:
        # On-the-fly generation
        img_idx = random.randint(0, len(images) - 1)
        H, W, _ = images[img_idx].shape
        
        # Center Cropping Logic
        if current_iteration < precrop_iters:
            h_crop = int(H * precrop_frac)
            w_crop = int(W * precrop_frac)
            y_start = (H - h_crop) // 2
            x_start = (W - w_crop) // 2
            y_end = y_start + h_crop
            x_end = x_start + w_crop
            # Restrict pixel selection to this region
        else:
            y_start, y_end = 0, H
            x_start, x_end = 0, W
            
        # Generate all rays for the selected image
        rays_o_all, rays_d_all, viewdirs_all = get_rays_of_a_view(
            H, W, K, poses[img_idx], ndc=False, inverse_y=False, flip_x=False, flip_y=False
        )
        
        # Reshape to list of pixels
        rays_o_all = rays_o_all.reshape(-1, 3)
        rays_d_all = rays_d_all.reshape(-1, 3)
        viewdirs_all = viewdirs_all.reshape(-1, 3)
        targets_all = images[img_idx].reshape(-1, 3)
        
        # Randomly select batch_size pixels
        num_pixels = H * W
        pixel_indices = random.sample(range(num_pixels), batch_size)
        
        rays_o = rays_o_all[pixel_indices]
        rays_d = rays_d_all[pixel_indices]
        viewdirs = viewdirs_all[pixel_indices]
        targets = targets_all[pixel_indices]

    # 2. Geometry Filtering
    if hit_coarse_geo is not None:
        # Test intersection for all rays in batch
        mask = hit_coarse_geo(rays_o, rays_d)
        rays_o = rays_o[mask]
        rays_d = rays_d[mask]
        viewdirs = viewdirs[mask]
        targets = targets[mask]
        
        # If too few rays remain, this is a potential issue
        if len(rays_o) == 0:
            raise ValueError("No rays hit the coarse geometry")

    # 3. Semantic Sampling (if enabled)
    if extra_sampling or mask_away_instance:
        # This logic is complex and depends on specific implementation details
        # of semantic segmentation alignment with rays.
        # Generally:
        # 1. Identify valid pixels based on instance masks.
        # 2. Identify pixels for each class.
        # 3. Sample extra rays for classes based on class_ratio.
        # 4. Replace or augment the initial random batch.
        # For brevity, this step is marked as implementation-specific.
        pass

    # 4. Subpixel Sampling (if differentiable rendering is used)
    # In many NeRF implementations, subpixel sampling is handled during the 
    # ray generation step (get_rays_of_a_view) or during the forward pass 
    # of the renderer. If explicit subpixel offsets are needed:
    # offsets = random.uniform(0, 1, (batch_size, 2))
    # rays_o_final = rays_o + ... # Adjust origin based on offset if necessary
    # rays_d_final = rays_d # Direction remains same, but sampling point changes
    
    return rays_o, rays_d, viewdirs, targets

def get_rays_of_a_view(H, W, K, c2w, ndc, inverse_y, flip_x, flip_y):
    """
    Computes ray origins and directions for all pixels in a view.
    """
    # Standard pinhole camera model
    # i, j are pixel coordinates
    i, j = torch.meshgrid(torch.arange(W), torch.arange(H), indexing='ij')
    
    # Convert to homogeneous coordinates
    dirs = torch.stack([(i - W * 0.5) / K[0, 0], 
                        -(j - H * 0.5) / K[1, 1], 
                        -torch.ones_like(i)], -1) # Note: sign conventions vary
    
    # Transform directions by camera rotation
    dirs = dirs @ c2w[:3, :3].T
    
    # Ray origins are the camera center
    rays_o = torch.broadcast_to(c2w[:3, 3], dirs.shape)
    
    return rays_o, dirs, dirs # viewdirs are same as directions in world space

def get_next_batch_indices(batch_size):
    """
    Manages index permutation to ensure uniform sampling.
    """
    global idx_perm, top, total_rays
    
    if top + batch_size > total_rays:
        idx_perm = np.random.permutation(total_rays)
        top = 0
        
    indices = idx_perm[top : top + batch_size]
    top += batch_size
    return indices
```

## Subtopics

### [Pixel Batching](3134-pixel-batching.md)
A Python-side wrapper that samples `batch_size` random (sensor, pixel) pairs across all sensors, renders those rays to a 1xN box-filter film, and supports a decorrelated PRB (Pixel-Ray-Backpropagation) backward pass without kernel changes [3134-pixel-batching.md]. It extends the basic batch ray sampling by handling multi-sensor setups and specific backward pass requirements for differentiable rendering.

### [Training Ray Shuffling](5446-training-ray-shuffling.md)
Initializes ray data from training cameras and ground truth, shuffles the rays, and transfers shuffled indices to GPU [5446-training-ray-shuffling.md]. This ensures that the training loop does not see correlated rays from adjacent pixels or similar views in consecutive batches, improving gradient stability.

### [Batched Pixel Sampling](5947-batched-pixel-sampling.md)
Samples a batch of pixels and sensors for rendering, generating three separate samplers for pixel selection, primal subpixel sampling, and adjoint subpixel sampling [5947-batched-pixel-sampling.md]. This variant is designed for differentiable rendering frameworks where the adjoint (gradient) pass requires independent subpixel sampling to reduce variance.

### Semantic Ray Sampling
Samples rays based on semantic segmentation masks, allowing for extra sampling of specific classes and masking away instances [S7, unofficial]. It uses parameters like `class_ratio` to oversample rare or important classes and `mask_away_instance` to exclude occluding objects [S7, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N_{rand})$ per iteration for ray generation and filtering. Geometry filtering adds $O(N_{rand})$ with a constant factor depending on the complexity of the coarse geometry test [S2, unofficial].
*   **Memory Complexity:** $O(N_{rand})$ for the batch tensors. Precomputing rays for all images requires $O(N_{total})$ memory, where $N_{total}$ is the total number of pixels across all training images [S6, unofficial].
*   **Performance:** Ray-based sampling is significantly more memory-efficient than image-based training, allowing for larger batch sizes or higher resolution scenes on limited GPU memory [S5, unofficial]. Convergence speed is generally faster due to more frequent updates to diverse parts of the scene [S5, unofficial].
*   **Strengths:** Flexible batch size, efficient memory usage, easy to parallelize, supports various sampling strategies (random, semantic, geometry-filtered) [S5, S7, unofficial].
*   **Limitations:** Can lead to noisy gradients if $N_{rand}$ is too small or if rays are not well-distributed. Geometry filtering can discard a large portion of rays if the coarse geometry is inaccurate [S2, unofficial].
*   **When to use:** Standard for NeRF training. Use when GPU memory is limited or when scene resolution is high. Use semantic sampling when class-specific reconstruction quality is important [S7, unofficial].
*   **When not to use:** When full-image consistency is critical for the loss function (e.g., some specific regularization techniques). When the scene is very small and full-image rendering fits easily in memory.

## Background
Batch Ray Sampling originated with the NeRF (Neural Radiance Fields) paper [S1, S5, unofficial]. It was introduced as a standard training procedure to make training feasible on consumer GPUs by avoiding the memory overhead of rendering full images. Subsequent works like DirectVoxGO [S2, unofficial] and various differentiable rendering frameworks [S4, S5, unofficial] have adopted and extended this method, adding features like geometry filtering, semantic sampling, and differentiable subpixel sampling.
