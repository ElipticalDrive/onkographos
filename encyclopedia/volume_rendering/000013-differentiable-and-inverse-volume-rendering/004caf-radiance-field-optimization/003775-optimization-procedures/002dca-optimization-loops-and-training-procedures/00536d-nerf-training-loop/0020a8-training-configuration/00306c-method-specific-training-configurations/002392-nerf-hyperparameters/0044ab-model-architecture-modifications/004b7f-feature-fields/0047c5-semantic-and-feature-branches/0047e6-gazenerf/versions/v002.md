# GazeNeRF

Also called: GazeNeRF: 3D-Aware Gaze Redirection with Neural Radiance Fields

## Overview
GazeNeRF is a 3D-aware gaze redirection method that reformulates the task as a neural volume rendering problem [S1]. It uses a two-stream MLP architecture to separately predict volumetric features for the face and eye regions, allowing for rigid 3D rotation of the eye features to achieve gaze redirection while preserving identity [S1]. It differs from 2D methods (e.g., STED, FAZE) by explicitly modeling the 3D nature of eyeball rotation and face deformation via separate volumetric streams, whereas 2D methods apply weak rotation priors to mixed 2D latent features [S1]. It differs from EyeNeRF by focusing on gaze redirection accuracy and using disentangled feature streams with explicit 3D rotation, whereas EyeNeRF focuses on high-fidelity rendering and relighting quality [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A reference face image $I_{ref}$, a target gaze label $g$ (2D vector of pitch and yaw angles in radians), and 3DMM latent codes for shape ($z_{sh}$), expression ($z_{ex}$), texture ($z_{te}$), and illumination ($z_{il}$) [S1]. The input image is resized to $512 \times 512$ pixels [S1]. Face parsing masks are used to define the "face-only" region (excluding eyes) and the "eyes" region [S1].
*   **Outputs:** A rendered 2D image $I_{wf}$ of the whole face with redirected gaze, along with intermediate rendered images for the face-only region $I_{fw/o}$ and the eyes region $I_e$ [S1].

**Data Structures:**
*   **Two-stream MLPs:** Two separate Multi-Layer Perceptrons, $h_{\theta_{fw/o}}$ for the face-only region and $h_{\theta_{e}}$ for the eyes region, with learnable parameters $\theta_{fw/o}$ and $\theta_{e}$ respectively [S1].
*   **Volume Feature Maps:** Low-resolution feature maps $F_{fw/o}$ and $F_e$ with dimensions $\mathbb{R}^{64 \times 64 \times 258}$ [S1].
*   **Rotated Eye Feature Map:** $F_e$ is reshaped to $\mathbb{R}^{64 \times 64 \times 86 \times 3}$ to facilitate 3D rotation matrix multiplication [S1].
*   **Merged Feature Map:** $F_{wf} \in \mathbb{R}^{64 \times 64 \times 258}$ [S1].
*   **Latent Codes:** Learnable vectors $z^* = \{z_{sh}, z_{ex}, z_{te}, z_{il}\}$ initialized from 3DMM parameters [S1].

**Numbered Steps:**

1.  **Encode Inputs:** Apply positional encoding $\gamma$ to the 3D position $x$ and view direction $d$. Concatenate $\gamma(x)$ with the latent codes $z_{sh}, z_{ex}, z_{te}, z_{il}$ and the gaze label $g$ [S1].
2.  **Face Stream Processing:** Pass the encoded inputs through the face-only MLP $h_{\theta_{fw/o}}$ to predict volume density $\sigma$ and feature vector $f$ for the face region (excluding eyes) [S1].
    $$ h_{\theta_{fw/o}} : (\gamma(x), z_{sh}, z_{ex}, z_{te}, z_{il}, g) \rightarrow (\sigma, f) $$
3.  **Eye Stream Processing:** Pass the encoded inputs through the eye MLP $h_{\theta_{e}}$ to predict volume density $\sigma$ and feature vector $f$ for the eye region [S1].
    $$ h_{\theta_{e}} : (\gamma(x), z_{sh}, z_{ex}, z_{te}, z_{il}, g) \rightarrow (\sigma, f) $$
4.  **Volume Rendering:** Use volume rendering on the outputs of both MLPs to generate low-resolution volume feature maps $F_{fw/o}$ and $F_e$ with dimensions $\mathbb{R}^{64 \times 64 \times 258}$ [S1].
5.  **3D Rotation:** Reshape the eye feature map $F_e \in \mathbb{R}^{64 \times 64 \times 258}$ to $F_e \in \mathbb{R}^{64 \times 64 \times 86 \times 3}$ [S1]. Calculate a 3D rotation matrix $R$ based on the target gaze direction $g$ [S1]. Apply this rotation matrix to the eye feature map to rigidly rotate the eyeball features:
    $$ F_{e-rot} = R F_e $$
    where $R$ is a 3D rotation matrix computed from gaze label $g$ [S1].
6.  **Feature Composition:** Map the rotated eye feature map $F_{e-rot}$ to the segmented eyes region and the face feature map $F_{fw/o}$ to the segmented face-only region [S1]. Merge the face-only features ($F_{fw/o}$) and rotated eye features ($F_{e-rot}$) using element-wise maximum:
    $$ F_{wf} = \max(F_{fw/o}, F_{e-rot}) $$
    [S1].
7.  **Final Rendering:** Render three images using a neural rendering module with shared weights $\theta_{render}$: face-only image $I_{fw/o}$ from $F_{fw/o}$, eyes image $I_e$ from $F_{e-rot}$, and whole face image $I_{wf}$ from $F_{wf}$ [S1].

**Pseudocode:**

```python
import numpy as np

def gaze_nefer_forward(x, d, z_sh, z_ex, z_te, z_il, g, h_theta_fw_o, h_theta_e, R_matrix, render_module):
    """
    Forward pass of GazeNeRF.
    
    Args:
        x: 3D position coordinates (N, 3)
        d: View direction (N, 3)
        z_sh, z_ex, z_te, z_il: Latent codes for shape, expression, texture, illumination
        g: Gaze label (2,) containing pitch and yaw angles in radians
        h_theta_fw_o: Face-only MLP
        h_theta_e: Eye MLP
        R_matrix: 3D rotation matrix (3, 3) derived from g
        render_module: Neural rendering module with shared weights
        
    Returns:
        I_wf: Rendered whole face image
        I_fw_o: Rendered face-only image
        I_e: Rendered eyes image
    """
    # Step 1: Encode inputs
    # Apply positional encoding gamma to x and d
    gamma_x = positional_encoding(x)
    gamma_d = positional_encoding(d)
    
    # Concatenate gamma(x) with latent codes and gaze label
    # Note: The paper specifies the input to MLPs includes z_sh, z_ex, z_te, z_il, g
    # The exact concatenation order is not specified, but typically latent codes are appended or concatenated
    # Assuming standard concatenation along feature dimension
    input_features = concatenate([gamma_x, z_sh, z_ex, z_te, z_il, g])
    
    # Step 2: Face Stream Processing
    # Pass through face-only MLP
    sigma_fw_o, f_fw_o = h_theta_fw_o(input_features)
    
    # Step 3: Eye Stream Processing
    # Pass through eye MLP
    sigma_e, f_e = h_theta_e(input_features)
    
    # Step 4: Volume Rendering
    # Render low-resolution volume feature maps
    # Dimensions: R^{64x64x258}
    F_fw_o = volume_render(sigma_fw_o, f_fw_o, resolution=(64, 64))
    F_e = volume_render(sigma_e, f_e, resolution=(64, 64))
    
    # Step 5: 3D Rotation
    # Reshape eye feature map to allow 3D rotation
    # F_e is R^{64x64x258}, reshape to R^{64x64x86x3}
    # 258 = 86 * 3
    F_e_reshaped = reshape(F_e, (64, 64, 86, 3))
    
    # Apply rigid rotation: F_{e-rot} = R * F_e
    # R is (3,3), F_e_reshaped is (64, 64, 86, 3)
    # We need to rotate the last dimension (3) for each spatial location and feature channel
    # F_e_reshaped[..., :, :] is (64, 64, 86, 3)
    # We can view this as (64*64*86, 3) and multiply by R.T or R depending on convention
    # The paper says F_{e-rot} = R F_e. Assuming F_e is treated as a vector of 3D features.
    # Let's assume standard matrix multiplication on the last axis.
    # F_e_reshaped shape: (H, W, C, 3)
    # We want to apply R to the 3-dim vector at each (h, w, c)
    # F_e_reshaped[h, w, c, :] is a vector of size 3.
    # R @ F_e_reshaped[h, w, c, :] gives the rotated vector.
    
    # Efficient implementation using einsum or batched matmul
    # Reshape to (H*W*C, 3)
    F_e_flat = reshape(F_e_reshaped, (-1, 3))
    
    # Apply rotation. If R is (3,3) and we want R @ v, we do F_e_flat @ R.T
    # Or if we define R such that it acts on the left, we might need transpose.
    # Standard rotation: v_rot = R @ v.
    # In numpy, if v is (N, 3), v_rot = v @ R.T
    F_e_rot_flat = F_e_flat @ R_matrix.T
    
    # Reshape back to (64, 64, 86, 3)
    F_e_rot = reshape(F_e_rot_flat, (64, 64, 86, 3))
    
    # Reshape back to (64, 64, 258) for merging
    F_e_rot = reshape(F_e_rot, (64, 64, 258))
    
    # Step 6: Feature Composition
    # Merge face-only and rotated eye features using element-wise maximum
    F_wf = maximum(F_fw_o, F_e_rot)
    
    # Step 7: Final Rendering
    # Render images using neural rendering module with shared weights
    I_fw_o = render_module.render(F_fw_o)
    I_e = render_module.render(F_e_rot)
    I_wf = render_module.render(F_wf)
    
    return I_wf, I_fw_o, I_e

def compute_loss(I_wf, I_fw_o, I_e, I_gt, masks_wf, masks_fw_o, masks_e, vgg_net, gaze_estimator, z_sh, z_ex, z_te, z_il, z_sh_0, z_ex_0, z_te_0, z_il_0):
    """
    Compute the total loss for GazeNeRF training.
    """
    # Reconstruction Loss
    # L_R_whole_face
    L_R_wf = mean_absolute_error(masks_wf * I_wf, masks_wf * I_gt)
    
    # L_R_face_only
    L_R_fw_o = mean_absolute_error(masks_fw_o * I_fw_o, masks_fw_o * I_gt)
    
    # L_R_eyes
    L_R_e = mean_absolute_error(masks_e * I_e, masks_e * I_gt)
    
    L_R = L_R_wf + L_R_fw_o + L_R_e
    
    # Perceptual Loss
    # L_P_whole_face
    # Sum over layers i of VGG16
    L_P_wf = 0
    for layer in vgg_net.layers:
        phi_i_wf = layer(I_wf)
        phi_i_gt = layer(I_gt)
        L_P_wf += mean_absolute_error(phi_i_wf, phi_i_gt) / norm(phi_i_gt)
        
    # L_P_face_only
    L_P_fw_o = 0
    for layer in vgg_net.layers:
        phi_i_fw_o = layer(I_fw_o)
        phi_i_gt = layer(I_gt)
        L_P_fw_o += mean_absolute_error(phi_i_fw_o, phi_i_gt) / norm(phi_i_gt)
        
    # L_P_eyes
    L_P_e = 0
    for layer in vgg_net.layers:
        phi_i_e = layer(I_e)
        phi_i_gt = layer(I_gt)
        L_P_e += mean_absolute_error(phi_i_e, phi_i_gt) / norm(phi_i_gt)
        
    L_P = L_P_wf + L_P_fw_o + L_P_e
    
    # Functional Loss
    # L_F_content
    # Angular error between estimated gaze of generated and ground truth
    v_wf = gaze_estimator(I_wf)
    v_gt = gaze_estimator(I_gt)
    E_ang = arccos(dot(v_wf, v_gt) / (norm(v_wf) * norm(v_gt)))
    L_F_content = E_ang
    L_F = L_F_content # Coefficient lambda_F_content is applied during optimization
    
    # Disentanglement Loss
    # L_D
    # Sum over latent codes z* with weights w*
    # w_sh = w_te = w_il = 1e-3, w_ex = 1.0
    L_D = 0
    L_D += 1e-3 * mean_squared_error(z_sh, z_sh_0) / norm(z_sh_0)
    L_D += 1.0 * mean_squared_error(z_ex, z_ex_0) / norm(z_ex_0)
    L_D += 1e-3 * mean_squared_error(z_te, z_te_0) / norm(z_te_0)
    L_D += 1e-3 * mean_squared_error(z_il, z_il_0) / norm(z_il_0)
    
    # Overall Loss
    # lambda_R = lambda_P = lambda_F = lambda_D = 1
    # lambda_F_content starts at 1e-3 and increases by 1e-3 each epoch
    L_Overall = L_R + L_P + L_F + L_D
    
    return L_Overall
```

**Parameters:**
*   **Gaze label $g$:** A 2D vector consisting of pitch and yaw angles of the gaze vector in radians [S1].
*   **Feature map dimensions:** The volume feature maps $F_{fw/o}$ and $F_e$ have dimensions $\mathbb{R}^{64 \times 64 \times 258}$ [S1].
*   **Optimizer:** Adam with learning rate $1 \times 10^{-4}$ [S1].
*   **Loss coefficients:** $\lambda_R = \lambda_P = \lambda_F = \lambda_D = 1$ [S1].
*   **Disentanglement weights:** $w_{sh} = w_{te} = w_{il} = 1 \times 10^{-3}$ and $w_{ex} = 1.0$ [S1].
*   **Functional loss coefficient $\lambda_{F_{content}}$:** Starts at $1 \times 10^{-3}$ and increases by $1 \times 10^{-3}$ after each epoch [S1].
*   **Input resolution:** Face images resized to $512 \times 512$ pixels [S1].

**Edge cases and pitfalls:**
*   **Masking:** The method relies on accurate face parsing masks to separate the eyes and face-only regions. Incorrect masks may lead to improper feature composition [S1].
*   **Rotation Matrix:** The rotation matrix $R$ must be correctly computed from the gaze label $g$ to ensure proper 3D rotation of the eye features [S1].
*   **Latent Code Initialization:** The latent codes $z^*$ are initialized from 3DMM parameters. Poor initialization may affect the disentanglement and identity preservation [S1].

## Operating characteristics
*   **Time and Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Evaluated on the ETH-XGaze dataset. GazeNeRF achieves better results than STED and HeadNeRF for most error metrics, especially gaze and head redirection errors. It achieves similar results as HeadNeRF in terms of image quality error metrics (SSIM, PSNR, LPIPS) [S1].
*   **Scaling:** Not given in the sources.
*   **Strengths:** Explicitly models 3D nature of eyeball rotation and face deformation. Provides fine-grained control over desired gaze angle. Preserves identity better than 2D methods [S1].
*   **Limitations:** Requires face parsing masks and 3DMM parameters for initialization. Relies on a pre-trained gaze estimator for functional loss [S1].
*   **When to use:** When 3D-aware gaze redirection with high accuracy and identity preservation is required.
*   **When not:** When high-fidelity rendering and relighting quality are the primary goals (use EyeNeRF instead) [S1].

## Background
GazeNeRF was proposed in the paper "GazeNeRF: 3D-Aware Gaze Redirection with Neural Radiance Fields" [S1]. It builds on the intuition that the face region and eyeballs are separate 3D structures that move in a coordinated yet independent fashion [S1]. It shares similarities with EyeNeRF but focuses on gaze redirection accuracy rather than high-fidelity rendering and relighting quality [S1]. It differs from 2D methods like STED and FAZE by explicitly modeling the 3D nature of eyeball rotation [S1]. It also differs from HeadNeRF, which uses a single MLP conditioned on gaze labels, by using a two-stream architecture with explicit 3D rotation on separated eye features [S1].
