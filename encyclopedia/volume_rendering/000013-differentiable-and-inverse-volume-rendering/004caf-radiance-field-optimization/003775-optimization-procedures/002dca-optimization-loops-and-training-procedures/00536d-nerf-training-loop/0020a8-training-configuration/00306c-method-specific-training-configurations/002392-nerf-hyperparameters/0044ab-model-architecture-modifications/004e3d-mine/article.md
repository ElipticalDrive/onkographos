# MINE

Also called: Continuous Depth MPI, MINE (Continuous Depth MPI), MINE: Towards Continuous Depth MPI with NeRF for Novel View Synthesis, Multiplane Image with Neural Radiance Fields

## Overview
MINE is a novel view synthesis method that models the frustum of the source camera using a continuous depth Multiplane Image (MPI) representation, conditioned on input images via a fully-convolutional decoder [S1]. Unlike pixelNeRF and GRF, which model the entire 3D space per ray, MINE reconstructs the frustum of the source camera per plane, allowing rendering of any target view via homography warping after a single encoder pass and a fixed number of decoder passes, independent of the number of target views [S1]. This architectural choice makes MINE significantly more efficient than ray-based methods when rendering multiple novel views [S1].

## How it works
**Inputs and Outputs:**
- **Input:** A single source image (or multiple views for GRF, but MINE uses single image conditioning by default) [S1].
- **Output:** A rendered image for a target novel view, generated by warping the reconstructed frustum [S1].

**Data Structures:**
The method uses a standard encoder-decoder architecture.
- **Encoder:** A ResNet50 network [S1]. Feature maps are extracted from five specific layers: `conv1`, `layer1`, `layer2`, `layer3`, and `layer4` [S1].
- **Decoder:** A fully-convolutional depth decoder [S1]. It consists of downsampling and upsampling blocks with skip connections from the encoder [S1]. The final output is a 4-channel tensor representing RGB and volume density $\sigma$ [S1].
- **MPI Representation:** The scene is represented as $N_{\text{planes}}$ planes within the source camera's frustum [S1]. Each plane contains RGB color and opacity/density information [S1].

**Number of Planes ($N_{\text{planes}}$):**
The number of planes is a hyperparameter. The specific value is not given in the sources, but the complexity analysis relies on this count [S1].

**Number of Network Forward Passes ($P$):**
The total number of network forward passes required to render a scene depends on the method:
- For MINE: $P_{\text{MINE}} = 1 + N_{\text{planes}}$ [S1].
- For pixelNeRF: $P_{\text{pixelNeRF}} = 1 + N_{\text{targets}} \times N_{\text{points}} \times H \times W$ [S1].
- For GRF: $P_{\text{GRF}} = N_{\text{views}} + N_{\text{targets}} \times N_{\text{points}} \times H \times W$ [S1].
Where $N_{\text{targets}}$ is the number of novel views, $N_{\text{points}}$ is the number of points per ray, and $H \times W$ is the output resolution [S1].

**Decoder Architecture Details:**
The decoder is based on the depth decoder from [12], with two additional downsampling blocks and two additional upsampling blocks to increase receptive fields [S1]. The output is a 4-channel RGB-$\sigma$ image [S1]. RGB is produced by a Sigmoid layer, and $\sigma$ is produced by taking the absolute value of the last channel [S1].

The layer-by-layer structure is as follows (Table 5 from [S1]):

| Layer | Type | Input Channels | Output Channels | Input Concatenation | Activation |

| upconv4 | Conv + Up | 256 | 128 | - | ELU |

| output4 | Conv | 128 | 4 | iconv4 | Sigmoid (RGB), abs ($\sigma$) |
| upconv3 | Conv + Up | 128 | 64 | - | ELU |

Note: All `upconv` blocks consist of convolution, batch normalization, activation, followed by 2x nearest neighbor upsampling [S1]. All `downconv` blocks consist of max pooling stride 2, convolution, activation [S1]. The "disparity encoding" input has 21 channels [S1].

**Rendering Process:**
1.  **Encoding:** Input a single image into the ResNet50 encoder [S1].
2.  **Feature Extraction:** Extract feature maps from encoder layers `conv1`, `layer1`, `layer2`, `layer3`, `layer4` [S1].
3.  **Frustum Reconstruction:** Pass these features through the decoder to reconstruct the frustum using $N_{\text{planes}}$ decoder inferences [S1]. Each inference produces a plane's RGB and $\sigma$ values [S1].
4.  **Novel View Synthesis:** Render any target view by applying homography warping to the reconstructed frustum [S1].

**Viewing Direction:**
MINE does not take viewing direction as input by default [S1]. Viewing directions can be integrated by concatenating per-ray viewing directions with the output feature maps at the target view (after warping) and using a lightweight fully convolutional network to predict view-dependent radiance [S1]. This adds $N_{\text{views}}$ network inferences [S1].

**Training Strategy:**
- MINE renders the full target image and disparity map during training time [S1].
- This allows for dense supervision signals such as SSIM and edge-aware smoothness loss [S1].
- Multiscale training losses are applied: $L_{L1}$ and $L_{SSIM}$ are applied only on `output1` [S1]. $L_{smooth}$ is applied on all outputs [`output1`, `output2`, `output3`, `output4`] [S1].

**Edge Cases and Pitfalls:**
- **Principle Point Shift:** In datasets like Flowers Light Fields, there is a shift in the principle point between different views due to the Lytro Illum camera [S1]. Since there is no metadata for the shift amount, it is set to a constant value based on grid index [i, j] [S1].
- **Disparity Range:** For Flowers Light Fields, the disparity range is set to [3.0, 0.03] [S1].
- **Grid Distance:** The distance between adjacent grids is set to 0.00128 [S1].
- **Camera Intrinsics:** For Flowers Light Fields, camera intrinsics are set as:
  $$f_x = 0.868056, \quad f_y = 1.250000$$
  $$c_{xij} = 0.5 + 0.002667 * i$$
  $$c_{yij} = 0.5 + 0.002667 * j$$
  where [i, j] is the index in the extracted 8x8 grid and [0, 0] is the top left view [S1].

## Operating characteristics
- **Time Complexity:** The number of network forward passes for MINE is $P_{\text{MINE}} = 1 + N_{\text{planes}}$ [S1]. This is independent of the number of target views ($N_{\text{targets}}$) [S1]. In contrast, pixelNeRF and GRF have complexity proportional to $N_{\text{targets}}$ [S1].
- **Memory Complexity:** Not given in the sources.
- **Measured Performance:** MINE is verified on datasets: KITTI, NYU-V2, RealEstate10k, Flowers Light Fields, and iBims-1 [S1].
- **Scaling:** MINE scales efficiently with the number of target views, as rendering each novel view only requires a homography warping step after the initial frustum reconstruction [S1].
- **Strengths:** Significant efficiency gains over pixelNeRF and GRF, especially for rendering multiple novel views [S1]. Allows for dense supervision signals (SSIM, edge-aware smoothness) during training [S1]. Generalizes well to real-world large-scale datasets [S1].
- **Limitations:** Does not take viewing direction as input by default, requiring additional processing for view-dependent effects [S1].
- **When to Use:** When rendering multiple novel views from a single source image is required, and efficiency is a priority [S1].
- **When Not to Use:** When view-dependent effects are critical and the additional overhead of integrating viewing directions is undesirable [S1].

## Background
MINE was introduced in the paper "MINE: Towards Continuous Depth MPI with NeRF for Novel View Synthesis" [S1]. It was verified on well-known datasets like KITTI, NYU-V2, RealEstate10k, etc., demonstrating its ability to generalize to real-world large-scale datasets [S1]. The method builds on the encoder-decoder structure used in pixelNeRF and GRF but differs in its representation of the scene [S1].
