# PI-NeRF

Also called: Partial-Invertible Neural Radiance Fields

## Overview
PI-NeRF is a framework that integrates NeRF with invertible neural networks (INN) to directly output the 6-DoF pose of a given image without pose initialization or iterative optimization, solving the inverse problem of view synthesis [S1]. It differs from existing NeRF-based pose estimation methods (like iNeRF and pNeRF) by directly outputting the pose without iterative optimization or initial pose, whereas existing methods rely on synthesizing images from a number of poses or iterative optimization, which is time-consuming and sensitive to initial poses [S1].

## How it works
PI-NeRF modifies the standard NeRF architecture to output high-dimensional features instead of RGB colors, then uses an Invertible Neural Network Module (INM) to map these ray features to pixel features. During inference, pixel features extracted from an image are inverted through the INM to recover ray representations, which are then used with a Perspective-n-Point (PnP) algorithm to calculate the camera pose [S1].

### Inputs and Outputs
**Inputs:**
*   A single observed image $I$ with known intrinsic parameters $K$.
*   A pre-trained NeRF-Feat model (MLP mapping 3D points to high-dimensional features).
*   A pre-trained INM (Invertible Neural Network Module).
*   A pre-trained ResUNet encoder.

**Outputs:**
*   The 6-DoF camera pose $(R, t)$, where $R$ is the rotation matrix and $t$ is the translation vector.

### Data Structures
1.  **NeRF-Feat MLP:** Maps a 3D point $x$ and viewing direction $d$ to a high-dimensional feature vector $f_{ray} \in \mathbb{R}^D$.
2.  **INM:** Consists of two invertible neural networks (INNs) that operate in forward and reverse directions.
    *   Forward: $f_{pixel} = \text{INM}_{\text{forward}}(f_{ray}, r_{rep})$
    *   Reverse: $(f_{ray}, r_{rep}) = \text{INM}_{\text{reverse}}(f_{pixel})$
    *   Where $r_{rep}$ is a representation of the ray (e.g., origin and direction).
3.  **ResUNet:** A convolutional neural network that extracts pixel features from an image.

### Steps
1.  **NeRF-Feat Construction:** Modify the standard NeRF MLP to output a high-dimensional feature vector $y_{aux}(x_k)$ at each sampled point $x_k$ along a ray $r$, instead of just density $\sigma(x_k)$ and color $c(x_k, d_k)$. Render this feature along the ray using volume rendering to obtain a ray feature $f_{ray}(r)$ [S1].
    $$
    f_{ray}(r) = \sum_{i=1}^{N} T_i \alpha_i y_{aux}(x_i)
    $$
    where $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$ is the accumulated transmittance [S1, S2, S3].
2.  **Invertible Neural Network Module (INM) Design:** Design an INM consisting of two INNs. The forward path takes the ray feature $f_{ray}$ and a ray representation $r_{rep}$ as input and outputs a pixel feature $f_{pixel}$. The reverse path takes $f_{pixel}$ and recovers $f_{ray}$ and $r_{rep}$ [S1].
3.  **Training with Barlow Twins Loss:**
    *   Use ResUNet to extract pixel features $f_{pixel}^{gt}$ from the observed image.
    *   Feed $f_{pixel}^{gt}$ into the reverse path of INM to recover ray features $f_{ray}^{rec}$ and ray representations $r_{rep}^{rec}$.
    *   Use the forward path of INM with $f_{ray}^{rec}$ and $r_{rep}^{rec}$ to generate reconstructed pixel features $f_{pixel}^{rec}$.
    *   Compute the Barlow Twins (BT) loss between $f_{pixel}^{gt}$ and $f_{pixel}^{rec}$ to train the ResUNet and INM [S1].
4.  **Inference:**
    *   Use ResUNet to extract a feature map from the observed image.
    *   Sample a set of pixel features from the feature map.
    *   Feed these pixel features into the reverse path of INM to obtain ray representations $r_{rep}$ [S1].
    *   Use the Perspective-n-Point (PnP) algorithm with the recovered ray representations and known camera intrinsics $K$ to calculate the camera pose $(R, t)$ [S1].

import numpy as np
import torch
import cv2

class PINeRF:
    def __init__(self, nerf_feat_mlp, inm, resunet, camera_intrinsics):
        """
        Initialize PI-NeRF.
        
        Args:
            nerf_feat_mlp: MLP that maps (x, d) -> (sigma, feature_vector)
            inm: Invertible Neural Network Module with forward and reverse methods
            resunet: ResUNet encoder for extracting pixel features
            camera_intrinsics: 3x3 matrix K
        """
        self.nerf_feat_mlp = nerf_feat_mlp
        self.inm = inm
        self.resunet = resunet
        self.K = camera_intrinsics

    def render_ray_feature(self, ray_origins, ray_directions, num_samples):
        """
        Render high-dimensional feature for a set of rays using NeRF-Feat.
        
        Args:
            ray_origins: (N, 3) array of ray origins
            ray_directions: (N, 3) array of ray directions
            num_samples: Number of samples per ray
            
        Returns:
            ray_features: (N, D) array of rendered ray features
        """
        # Sample points along rays
        t_vals = np.linspace(0.0, 1.0, num_samples)
        z_vals = 0.8 * t_vals + 0.2 * np.ones_like(t_vals) # Near/far bounds assumed fixed or learned
        points = ray_origins[:, None, :] + ray_directions[:, None, :] * z_vals[None, :, None]
        
        # Query NeRF-Feat MLP for density and feature
        # Note: In practice, this involves batching and GPU calls
        # sigma: (N, num_samples)
        # features: (N, num_samples, D)
        sigma, features = self.nerf_feat_mlp(points, ray_directions[:, None, :].repeat(num_samples, axis=1))
        
        # Compute transmittance
        deltas = z_vals[1:] - z_vals[:-1]
        deltas = np.concatenate([deltas, np.array([1e-3])], axis=0) # Last delta
        # Assuming batched computation
        transmittance = np.exp(-np.cumsum(sigma * deltas, axis=1))
        
        # Render feature
        # alpha_i = (1 - exp(-sigma_i * delta_i)) * T_i
        alpha = (1.0 - np.exp(-sigma * deltas)) * transmittance
        ray_features = np.sum(alpha[:, :, None] * features, axis=1)
        
        return ray_features

    def train_step(self, image, gt_pose=None):
        """
        Training step using Barlow Twins loss.
        
        Args:
            image: Input image tensor
            gt_pose: Ground truth pose (optional, not used in loss calculation directly)
            
        Returns:
            loss: Barlow Twins loss
        """
        # Extract pixel features from image using ResUNet
        pixel_features_gt = self.resunet(image)
        
        # Reverse path: Pixel features -> Ray features and Ray representations
        ray_features_rec, ray_reps_rec = self.inm.reverse(pixel_features_gt)
        
        # Forward path: Ray features and Ray representations -> Reconstructed pixel features
        pixel_features_rec = self.inm.forward(ray_features_rec, ray_reps_rec)
        
        # Compute Barlow Twins loss
        loss = barlow_twins_loss(pixel_features_gt, pixel_features_rec)
        
        return loss

    def estimate_pose(self, image):
        """
        Estimate camera pose from a single image.
        
        Args:
            image: Input image
            
        Returns:
            R: Rotation matrix (3x3)
            t: Translation vector (3x1)
        """
        # Extract pixel features from image using ResUNet
        pixel_features = self.resunet(image)
        
        # Sample a set of pixel features (e.g., from corners or grid)
        sampled_pixel_features = sample_features(pixel_features)
        
        # Reverse path: Sampled pixel features -> Ray representations
        ray_features, ray_reps = self.inm.reverse(sampled_pixel_features)
        
        # Use PnP algorithm to estimate pose
        # ray_reps contain 3D points and their corresponding 2D projections
        # Note: ray_reps might need to be converted to 3D points in camera space
        # and 2D points in image space for PnP
        
        # Assuming ray_reps provides 3D points and we have 2D points from the image
        # This step depends on the exact definition of 'ray representation'
        # Typically, ray representation includes origin and direction
        # We need to find 3D points that lie on these rays and project to the sampled 2D points
        
        # For simplicity, assume ray_reps directly provides 3D-2D correspondences
        # or can be easily converted
        object_points, image_points = convert_ray_reps_to_correspondences(ray_reps, self.K)
        
        # Solve PnP
        success, R, t, _ = cv2.solvePnP(object_points, image_points, self.K, None)
        
        if not success:
            raise ValueError("PnP failed to find a solution")
            
        return R, t

def barlow_twins_loss(x, y, lambda_param=5e-3):
    """
    Compute Barlow Twins loss.
    
    Args:
        x: Batch of features (N, D)
        y: Batch of features (N, D)
        lambda_param: Weight for the off-diagonal terms
        
    Returns:
        loss: Scalar loss value
    """
    # Normalize features
    x = x - torch.mean(x, dim=0)
    y = y - torch.mean(y, dim=0)
    
    # Compute covariance matrix
    c = torch.mm(x.T, y)
    c = c / x.size(0)
    
    # Compute standard deviation
    std_x = torch.sqrt(torch.var(x, dim=0) + 1e-5)
    std_y = torch.sqrt(torch.var(y, dim=0) + 1e-5)
    
    # Normalize covariance
    c = c / (std_x[:, None] * std_y[None, :])
    
    # Loss: sum of squared off-diagonal elements + lambda * sum of squared deviations of diagonal from 1
    diagonal = torch.diag(c)
    off_diagonal = c - diagonal.diag()
    loss = torch.sum(off_diagonal ** 2) + lambda_param * torch.sum((diagonal - 1) ** 2)
    
    return loss

### Edge Cases and Pitfalls
*   **PnP Failure:** The PnP algorithm may fail if the recovered ray representations do not provide sufficient or accurate 3D-2D correspondences. This can happen if the INM inversion is inaccurate or if the sampled features are ambiguous [S1].
*   **Initial Pose Sensitivity:** Unlike iterative methods, PI-NeRF does not require an initial pose, but its accuracy depends on the quality of the inverted ray representations [S1].
*   **Precision:** The accuracy of the pose estimation is competitive with iterative methods, but may be lower in complex scenes or with poor feature extraction [S1].

## Operating characteristics
*   **Time Complexity:** PI-NeRF is two orders of magnitude faster than existing NeRF-based methods (e.g., pNeRF takes more than 5 seconds) [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Experiments on synthetic and real-world datasets demonstrate competitive accuracy without initial pose [S1].
*   **Strengths:** Direct pose estimation without iterative optimization or initial pose; fast inference time.
*   **Limitations:** Accuracy may be lower than iterative methods in some cases; requires a pre-trained NeRF-Feat and INM.
*   **When to Use:** Real-time applications requiring fast pose estimation from a single image.
*   **When Not to Use:** When high accuracy is required and computational time is not a constraint; when iterative optimization is preferred for robustness.

## Background
PI-NeRF was proposed by Zhihao Li, Kexue Fu, Haoran Wang, and Manning Wang in 2023 [S1]. It is the first work that uses NeRF for direct pose estimation, integrating NeRF with invertible neural networks (INN) to solve the inverse problem of view synthesis [S1]. The method builds on the idea of using high-dimensional features in NeRF and inverting the rendering process to recover ray information from pixel features [S1].
