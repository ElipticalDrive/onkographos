# Block-NeRF

Also called: Block-based NeRF, Spatially Decomposed NeRF

## Overview
Block-NeRF is a method for city-scale NeRF-based reconstruction from street-level images that handles transient appearance and moving objects by dividing neighborhoods into overlapping blocks [S1]. It scales NeRF to city-scale scenes by spatially decomposing the environment into manageable blocks, training independent NeRFs per block, and compositing them at render time [S2, unofficial]. It sets itself apart from siblings like Zip-NeRF and VaxNeRF by using explicit spatial partitioning with overlapping regions and a visibility MLP to manage occlusion and transient objects, rather than caching or geometric hulls [S1][S2, unofficial].

## How it works
**Inputs:** A large set of street-level images covering a city-scale neighborhood; semantic segmentation masks for transient objects (pedestrians, cars) [S1].
**Outputs:** A set of independent Block-NeRF models, one per spatial block, and a visibility MLP [S1].

**Data Structures:**
1.  **Block-NeRF:** Each block contains a NeRF module. The implementation uses mip-NeRF [48] as the base, utilizing Integrated Positional Encoding (IPE) [S1]. It also incorporates appearance latent code optimization from NeRF-W [88] to handle appearance variations [S1].
2.  **Visibility MLP:** A multi-layer perceptron that predicts the visibility of a block for a given camera viewpoint [S1].
3.  **Octree Cache:** A coarse rendering of densities and colors cached into an octree for each block [S1].

**Steps:**
1.  **Partitioning:** Divide the neighborhood into spatial blocks. Assign an overlap between adjacent blocks to ensure seamless compositing [S1][S2, unofficial].
2.  **Masking:** Use semantic segmentation to mask out transient objects (pedestrians, cars) in the training images [S1].
3.  **Training:** Train a separate NeRF model for each block using only the images with potentially relevant pixels (those not masked and within the block's spatial influence) [S1][S2, unofficial]. The NeRF uses IPE and appearance latent codes [S1].
4.  **Visibility Prediction:** Train a visibility MLP in parallel. Supervise it using the transitivity function (Eq. 3 in [S1]) and the density value generated by the NeRF MLP [S1].
5.  **Rendering:**
    a. Identify visible blocks based on the camera viewpoint.
    b. Discard low-visibility Block-NeRFs using the visibility MLP [S1].
    c. Sample images from the remaining overlapping Block-NeRFs [S1].
    d. Perform appearance code matching optimization to align appearance codes across overlapping blocks [S1].
    e. Composite the outputs of the visible blocks using inverse distance weighting [S1][S2, unofficial].

**Formulas:**
*   **Transitivity Function:** The visibility MLP is supervised using the transitivity function, denoted as Eq. (3) in [S1]. The exact formula is not provided in the sources.
*   **Compositing:** Outputs are composited using inverse distance weighting [S1]. The exact weighting formula is not provided in the sources.

**Parameters:**
*   **Block Overlap:** Not given in the sources.
*   **Visibility Threshold:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Transient Objects:** Handled by semantic segmentation masking [S1].
*   **Appearance Consistency:** Handled by appearance latent code optimization and matching across overlapping blocks [S1].
*   **Occlusion:** Handled by the visibility MLP discarding low-visibility blocks [S1].

## Operating characteristics
*   **Time Complexity:** Training is parallelizable across blocks, reducing total training time compared to a single monolithic NeRF. Rendering requires querying multiple blocks and compositing, which is more complex than a single NeRF but avoids querying empty space.
*   **Memory Complexity:** Scales linearly with the number of blocks. Each block stores its own NeRF weights and octree cache.
*   **Measured Performance:** Demonstrated feasibility on city-scale scenes (SF / Mission Bay) using 2.8 million street-level images [S1][S2, unofficial].
*   **Strengths:** Handles city-scale scenes; manages transient objects and moving vehicles; handles varying appearance.
*   **Limitations:** Requires semantic segmentation for transient objects; complex compositing logic; overlap management.
*   **When to Use:** City-scale reconstruction from street-level imagery with transient objects.
*   **When Not to Use:** Small-scale scenes; scenes without significant transient objects; scenes where semantic segmentation is unavailable.

## Background
Block-NeRF was introduced in February 2022 [S1]. It was developed to address the challenges of city-scale NeRF-based reconstruction from large datasets like 2.8 million street-level images, specifically dealing with transient appearance and moving objects [S1]. It builds on mip-NeRF [48] and NeRF-W [88] [S1].
