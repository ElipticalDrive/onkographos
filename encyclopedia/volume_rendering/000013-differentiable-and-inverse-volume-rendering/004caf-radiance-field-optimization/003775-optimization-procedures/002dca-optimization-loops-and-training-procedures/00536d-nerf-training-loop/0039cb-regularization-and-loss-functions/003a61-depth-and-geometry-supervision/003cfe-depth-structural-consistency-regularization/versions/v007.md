# Depth Structural Consistency Regularization
Also called: RDSC
## Overview
Depth Structural Consistency Regularization (RDSC) is a geometric regularization term applied during Neural Radiance Field (NeRF) training to enforce continuity constraints on rendered depth maps using external depth priors, such as those from DepthAnythingV2 [S1]. It distinguishes itself from sibling methods like [Geometric Baseline Regularization](7475-geometric-baseline-regularization.md) by explicitly modeling local depth variations between neighboring pixels through a k-nearest neighbor (KNN) search, rather than relying solely on global smoothness or pixel-wise alignment [S1]. This approach ensures that the structural consistency of the input depth map is preserved in the NeRF output, even in the presence of minor depth variations [S1].
## How it works
**Inputs and Outputs:**
- Input: Rendered depth map $d^r$ from the NeRF; External depth map $d^{V2}$ (e.g., from DepthAnythingV2); Hyperparameters: $k$ (number of neighbors), $m_{ar'}$ (boundary value for minor variations).
- Output: Scalar regularization loss $\mathcal{L}_{DSC}$.

**Data Structures:**
- Depth maps are treated as 2D grids of floating-point values.
- KNN search operates on the spatial coordinates of pixels in the depth map.

**Steps:**
1. For each pixel $k_1$ in the rendered depth map $d^r$:
2. Identify the corresponding pixel location in the external depth map $d^{V2}$.
3. Find the $k$-nearest neighbors ($KNN$) of the depth value $d^{V2}_{k_2}$ within a small spatial region around the corresponding pixel in $d^{V2}$ [S1].
4. For each neighbor $k_2$ in $KNN$:
   - Compute the absolute difference between the rendered depth $d^r_{k_1}$ and the neighbor's rendered depth $d^r_{k_2}$ [S1].
   - Apply the hinge loss: $\max(|d^r_{k_1} - d^r_{k_2}| - m_{ar'}, 0)$ [S1].
5. Sum the hinge losses over all neighbors $k_2$ and all pixels $k_1$ [S1].

**Formula:**
$$ \mathcal{L}_{DSC} = \sum_{k_1} \sum_{d^{V2}_{k_2} \in KNN(d^{V2}_{k_2})} \max(|d^r_{k_1} - d^r_{k_2}| - m_{ar'}, 0) $$
where:
- $k_1$ indexes pixels in the rendered depth map.
- $KNN(\cdot)$ returns the $k$-nearest neighbors based on depth values within a small region [S1].
- $d^r_{k_1}$ and $d^r_{k_2}$ are depth values at pixels $k_1$ and $k_2$ in the rendered depth map [S1].
- $m_{ar'}$ is a small boundary value accounting for minor depth variations between neighboring pixels [S1].

**Pseudocode:**
```python
def compute_rdsc_loss(rendered_depth, external_depth, k_neighbors, boundary_value):
    """
    Computes the Depth Structural Consistency Regularization loss.
    
    Args:
        rendered_depth (np.ndarray): 2D array of rendered depth values.
        external_depth (np.ndarray): 2D array of external depth values (e.g., from DepthAnythingV2).
        k_neighbors (int): Number of nearest neighbors to consider.
        boundary_value (float): Small boundary value for minor depth variations (m_ar').
        
    Returns:
        float: The RDSC loss value.
    """
    loss = 0.0
    height, width = rendered_depth.shape
    
    # Precompute coordinates for KNN search
    coords = np.array(np.meshgrid(np.arange(height), np.arange(width))).T.reshape(-1, 2)
    
    for i in range(height):
        for j in range(width):
            # Current pixel index
            k1_idx = i * width + j
            
            # Get corresponding external depth value
            d_v2_current = external_depth[i, j]
            
            # Find k-nearest neighbors in external depth map based on spatial proximity
            # Note: The source specifies KNN based on depth values within a small region.
            # Implementation detail: We search for neighbors in the spatial neighborhood
            # and select those with depth values closest to d_v2_current, or simply
            # use spatial neighbors if the region is defined spatially.
            # Given the ambiguity in "based on depth values within a small region",
            # we assume a spatial window search for neighbors, then filter or rank by depth similarity.
            # However, the formula implies comparing rendered depths of neighbors.
            # Let's assume a fixed spatial window (e.g., 3x3) for simplicity as "small region".
            
            neighbors = []
            window_size = 1 # 1 means 3x3 window
            for di in range(-window_size, window_size + 1):
                for dj in range(-window_size, window_size + 1):
                    ni, nj = i + di, j + dj
                    if 0 <= ni < height and 0 <= nj < width:
                        if (ni, nj) != (i, j):
                            neighbors.append((ni, nj))
            
            # If fewer than k_neighbors, use all available
            if len(neighbors) > k_neighbors:
                # Sort neighbors by depth similarity to external depth
                # This aligns with "KNN based on depth values"
                neighbors.sort(key=lambda p: abs(external_depth[p[0], p[1]] - d_v2_current))
                neighbors = neighbors[:k_neighbors]
            
            for ni, nj in neighbors:
                k2_idx = ni * width + nj
                d_r_k1 = rendered_depth[i, j]
                d_r_k2 = rendered_depth[ni, nj]
                
                diff = abs(d_r_k1 - d_r_k2)
                hinge = max(diff - boundary_value, 0)
                loss += hinge
                
    return loss
```

**Parameters:**
- $k$: Number of nearest neighbors. Not given in the sources.
- $m_{ar'}$: Boundary value for minor depth variations. Not given in the sources.

**Edge Cases and Pitfalls:**
- If the external depth map is noisy, the KNN search might select incorrect neighbors, leading to inconsistent regularization [S1].
- The choice of $m_{ar'}$ is critical; too small a value may penalize valid depth discontinuities, while too large a value may fail to enforce continuity [S1].
- Precision issues may arise if depth values vary significantly in scale [G].

## Subtopics

### [Patch-Based Depth Regularization](10369-patch-based-depth-regularization.md)
Patch-Based Depth Regularization is a technique applied during Neural Radiance Field (NeRF) training to enforce geometric consistency by smoothing rendered depth maps while preserving sharp structural edges. It distinguishes itself from sibling methods like RegNeRF’s patch similarity constraints by utilizing bilateral or joint bilateral filters, which explicitly account for spatial proximity and intensity/depth similarity to reduce noise without blurring boundaries.

## Operating characteristics
**Time and Memory Complexity:**
- Time complexity: $O(N \cdot k)$, where $N$ is the number of pixels and $k$ is the number of neighbors. The KNN search adds overhead [S1].
- Memory complexity: $O(N)$ to store the depth maps and intermediate results [G].

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- Scales linearly with the number of pixels and neighbors [G].

**Strengths and Limitations:**
- Strengths: Enforces local structural consistency, leveraging external depth priors for better reconstruction quality [S1].
- Limitations: Dependent on the quality of the external depth map; sensitive to hyperparameters $k$ and $m_{ar'}$ [S1].

**When to Use:**
- Use when external depth maps are available and local structural consistency is critical [S1].
- Not suitable when external depth maps are unavailable or highly inaccurate [G].

## Background
**Origin:**
- Introduced in DASNeRF [S1].

**History and Development:**
- Developed to address the loss of spatial information in sparse-view 3D reconstruction by leveraging latest depth models like DepthAnythingV2 [S1].
