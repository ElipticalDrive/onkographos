# DFF (Decomposing NeRF for Editing Via Feature Field Distillation)

Also called: Feature Field Distillation

## Overview
DFF enables 3D semantic segmentation and editable novel-view synthesis by distilling features from a pre-trained 2D teacher network (such as LSeg or DINO) into a neural radiance field [S1]. Unlike methods that rely on explicit 3D labels or naive reuse of NeRF's internal feature spaces—which are entangled with low-level factors like color and geometry—DFF learns a dedicated feature field that captures semantic similarity, allowing for multi-view consistent decomposition of scenes into semantic regions [S1]. It sets itself apart from sibling methods like [Blended-NeRF](12273-blended-nerf.md) by providing a semantic decomposition mechanism that can be combined with optimization-based editors (e.g., [CLIPNeRF](https://arxiv.org/abs/2204.00000)) to update only desired objects without breaking unintended areas [S1].

## How it works
**Inputs:**
*   A set of posed training images $I$ with corresponding camera poses.
*   A 2D teacher network (LSeg or DINO) to generate target feature maps.
*   For LSeg: Text labels for semantic classes.
*   For DINO: Image patch queries for region selection.

**Outputs:**
*   A radiance field $F_\Theta(\mathbf{x}, \mathbf{v})$ producing density $\sigma$ and color $\mathbf{c}$.
*   A feature field $F_\Phi(\mathbf{x})$ producing semantic features $\mathbf{f}$.
*   A decomposition probability map for editing.

**Data Structures:**
1.  **Radiance Field MLP ($F_\Theta$):**
    *   Input: Positional encoded coordinate $\mathbf{x}$ and viewing direction $\mathbf{v}$.
    *   Architecture: 8 ReLU layers with 256 dimensions.
    *   Output Heads:
        *   Density: Linear layer (1 output).
        *   Color: 3 ReLU layers (256 dims) $\to$ Linear layer (3 outputs, RGB).
        *   Feature (Branch-based): 3 ReLU layers (256 dims) $\to$ Linear layer (feature dim, e.g., 256 or 512).
    *   Positional Encoding (PE): Length 10 for $\mathbf{x}$ and skip connections; Length 4 for $\mathbf{v}$.
2.  **Independent Feature Field MLP ($F_\Phi$) (Optional):**
    *   Used to avoid retraining the radiance field or to enforce smoothness.
    *   Architecture: 4 ReLU layers with 256 dimensions.
    *   Skip connection at the 3rd layer if PE is used.
    *   PE: Optional. If omitted, it acts as a smoothness regularizer.
3.  **Teacher Network Features:**
    *   LSeg: Text-encoded label probabilities.
    *   DINO: Patch-averaged feature vectors.

**Training Procedure:**
The training occurs in two phases. First, a standard NeRF is trained for 200K iterations using only photometric loss $L_p$. Second, the model is finetuned for 5K iterations with the feature branch added, minimizing $L_p + \lambda L_f$.

**Loss Functions:**
1.  **Photometric Loss ($L_p$):** Standard MSE between rendered color $\hat{\mathbf{c}}$ and ground truth $\mathbf{c}_{gt}$.
2.  **Feature Distillation Loss ($L_f$):**
    For LSeg, the target feature for a pixel is the probability distribution over classes. Let $f_{img}(I, r)$ be the resized target feature map for ray $r$ and image $I$. The loss is:
    $$ L_f = \sum_{r} \| \mathbf{f}(\mathbf{x}_r) - f_{img}(I, r) \|^2 $$
    where $\mathbf{f}(\mathbf{x}_r)$ is the feature output from the radiance or feature field MLP at the sampled point $\mathbf{x}_r$ along ray $r$.
    *Note: The sources cite Equation 4 for the combined loss and Equation 22 for LSeg probability calculation, but the explicit formula for $L_f$ is described as minimizing the difference between the network's feature output and the teacher's feature map.*

**Decomposition and Editing:**
*   **LSeg (Text Query):** The probability of a point belonging to a class is computed using the LSeg text encoder. The probability $p$ for a class $c$ at point $\mathbf{x}$ is derived from the feature field output $\mathbf{f}(\mathbf{x})$ and the text embedding $\mathbf{t}_c$:
    $$ p_c(\mathbf{x}) = \text{softmax}(\mathbf{f}(\mathbf{x}) \cdot \mathbf{t}_c) $$
    (Equation 22 in [S1]).
*   **DINO (Image Patch Query):**
    1.  Calculate patch feature $\mathbf{f}_{patch}$ by averaging features of all pixels in the query patch.
    2.  Compute cosine similarity between the point feature $\mathbf{f}(\mathbf{x})$ and $\mathbf{f}_{patch}$.
    3.  Apply thresholding for hard decomposition:
        $$ p = \begin{cases} 1 & \text{if } \text{sim}(\mathbf{f}(\mathbf{x}), \mathbf{f}_{patch}) > \tau \\ 0 & \text{otherwise} \end{cases} $$
    This replaces the softmax with negative queries used in standard LSeg [S1].

import torch
import torch.nn as nn
import torch.nn.functional as F

class DFFRadianceField(nn.Module):
    def __init__(self, feature_dim=256):
        super().__init__()
        # Radiance Field MLP
        self.shared_layers = nn.ModuleList([
            nn.Linear(256, 256), nn.ReLU() for _ in range(8)
        ])
        self.density_layer = nn.Linear(256, 1)
        self.color_layers = nn.ModuleList([
            nn.Linear(256, 256), nn.ReLU(),
            nn.Linear(256, 256), nn.ReLU(),
            nn.Linear(256, 256), nn.ReLU(),
            nn.Linear(256, 3)
        ])
        self.feature_layers = nn.ModuleList([
            nn.Linear(256, 256), nn.ReLU(),
            nn.Linear(256, 256), nn.ReLU(),
            nn.Linear(256, 256), nn.ReLU(),
            nn.Linear(256, feature_dim)
        ])
        
    def forward(self, xyz, dirs):
        # Assume xyz and dirs are already positional encoded and concatenated
        # xyz_enc: [N, 256], dirs_enc: [N, 16] (4*2*2 + 1)
        h = torch.cat([xyz, dirs], dim=-1)
        
        # Shared layers
        for layer in self.shared_layers:
            h = layer(h)
            
        density = self.density_layer(h)
        
        # Color branch
        c = h
        for layer in self.color_layers:
            c = layer(c)
            
        # Feature branch
        f = h
        for layer in self.feature_layers:
            f = layer(f)
            
        return density, c, f

class DFFTrainer:

        self.teacher = teacher_model
        self.teacher_type = teacher_type
        self.radiance_field = DFFRadianceField()
        self.optimizer = torch.optim.Adam(self.radiance_field.parameters(), lr=5e-4)
        self.lambda_f = 1.0 # Typical value; excessive weight (x10) hurts view synthesis
        
    def get_target_features(self, image, rays):
        """
        Get target features from teacher network for a batch of rays.
        Returns resized feature maps matching image resolution.
        """
        # Encode image with teacher
        with torch.no_grad():
            if self.teacher_type == 'LSeg':
                # LSeg returns probability maps or features

                targets = self.teacher.encode(image)
                targets = F.interpolate(targets, size=image.shape[2:], mode='bilinear', align_corners=False)
            elif self.teacher_type == 'DINO':

                targets = F.interpolate(targets, size=image.shape[2:], mode='bilinear', align_corners=False)

    def compute_loss(self, rendered_color, rendered_density, rendered_feature,

        # Photometric Loss
        loss_p = F.mse_loss(rendered_color, gt_color)

        # Assuming target_feature is aligned with the image plane of the ray origin

**Parameters:**
*   **Teacher Networks:** LSeg [44] or DINO [12].
*   **Iterations:** 200K for initial NeRF training; 5K for finetuning with feature branch.
*   **Optimizer:** Adam.
*   **Learning Rate:** Linearly decaying from $5 \times 10^{-4}$ to $8 \times 10^{-5}$ during initial training; fixed at $1 \times 10^{-4}$ during finetuning.
*   **Sampling:** Coarse: 64 points (stratified); Fine: 128 points (importance sampling). Total 192 points.
*   **PE Length:** 10 for coordinates/skip; 4 for viewing direction.
*   **Image Size:** 320x240 (Replica); 1008x756 (others).
*   **Batch Size:** 1024 rays (Replica); 2048 rays (others).
*   **Feature Loss Weight ($\lambda$):** Default 1. Increasing by 10x hurts view synthesis.

**Edge Cases and Pitfalls:**
*   **Feature Loss Convergence:** Feature loss converges faster than photometric loss, justifying the short 5K finetuning period [S1].
*   **Naive NeRF Features:** Using hidden layers of the original NeRF (e.g., 8th layer) for decomposition fails; regions leak to areas with similar color/geometry/position, not semantics [S1].
*   **Excessive Feature Weight:** Increasing $\lambda$ by 10x degrades view synthesis quality without improving segmentation [S1].
*   **Deletion Artifacts:** Deleting foreground objects may leave floating artifacts and blurred volumes in the far distance behind the object [S1].
*   **Sampling Impact:** Fine sampling introduces high-frequency artifacts in segmentation; coarse sampling produces smoother, more natural decompositions [S1].

## Subtopics

### Branch-based DFF
The feature branch shares layers with the radiance field. It does not degrade view synthesis performance compared to NeRF without feature fields and has small computational overhead [S1].

### Independent Feature Field DFF
An independent, lightweight MLP is trained for the feature field. This is useful for introducing DFF into arbitrary 3D scene representations (dynamic NeRFs, meshes) without retraining the radiance field [S1].

### Smooth Volume Decomposition
Achieved by using coarse sampling or training an independent feature field MLP without positional encoding (PE). This minimizes high-frequency floating artifacts [S1].

## Operating characteristics
*   **Time Complexity:** Training requires 200K iterations for the base NeRF and 5K for finetuning. The feature branch adds minimal computational overhead [S1].
*   **Memory Complexity:** Adds parameters for the feature branch (3 layers of 256 dims) or an independent MLP (4 layers). Minimal increase compared to the base NeRF [S1].
*   **Performance:** DFF achieves 3D semantic segmentation performance (mIoU) comparable to or better than supervised sparse 3D convolution models like MinkowskiNet42 [S1].
*   **Strengths:** Multi-view consistent editing; enables zero-shot text-based (LSeg) or patch-based (DINO) decomposition; smooth volume decomposition possible.
*   **Limitations:** Cannot handle lighting decomposition or estimation of unobserved parts as well as surface decomposition; deletion artifacts may persist in occluded regions [S1].
*   **When to Use:** When semantic decomposition is required for editing (deletion, extraction, recoloring) and multi-view consistency is critical.
*   **When Not to Use:** When high-frequency geometric detail in the feature field is required (use fine sampling, but accept artifacts); when lighting decomposition is needed.

## Background
DFF was introduced in the paper "Decomposing NeRF for Editing Via Feature Field Distillation" [S1]. It addresses the challenge that editable NeRFs face in surface decomposition, volume decomposition, and estimating unobserved parts. It builds on the observation that original NeRF features are entangled with low-level factors, necessitating a dedicated feature field distilled from 2D teachers like LSeg and DINO [S1].
