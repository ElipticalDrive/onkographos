# NeRF Editing Procedure

Also called: Inference-Time Interception, Feature-Field Editing, DFF Editing

## Overview
This method modifies the radiance field $F_\Theta(\mathbf{x}, \mathbf{v}) \to (\sigma, \mathbf{c})$ during the rendering pass by intercepting ray samples and applying transformations based on semantic or geometric queries, rather than retraining the network parameters. It solves the problem of achieving multi-view consistent edits (deletion, colorization, translation) without the computational cost of iterative optimization. It sets itself apart from optimization-based siblings like [NeRF-In Inpainting Optimization](12372-nerf-in-inpainting-optimization.md) by performing edits at inference time via an external feature field, and from direct blending methods by using probability-weighted or thresholded selection of points [S1].

## How it works
The core procedure relies on a pre-trained Distilled Feature Field (DFF) or similar external feature encoder to determine the semantic relevance of 3D points. The method operates on a per-ray basis during volume rendering.

**Inputs:**
*   Ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$.
*   NeRF model $F_\Theta$ (outputting $\sigma, \mathbf{c}$).
*   Feature Field model $F_{DFF}$ (outputting semantic probability $p$).
*   Editing parameters: transformation function $g$, colorization function $b$, deletion flag, threshold $\tau$.

**Outputs:**
*   Rendered color $\mathbf{C}(\mathbf{r})$ and alpha $\alpha(\mathbf{r})$.

**Data Structures:**
*   **Ray Samples:** A list of points $x_i$ along the ray.
*   **Feature Query:** For each $x_i$, the DFF returns a probability $p_i \in [0, 1]$ indicating the likelihood that $x_i$ belongs to the target semantic class defined by the query.

**Steps:**

1.  **Sample Points:** Sample points $x_i$ along the ray $\mathbf{r}$ using standard NeRF sampling strategies (e.g., uniform or importance sampling) [S1].
2.  **Feature Query:** For each point $x_i$, query the DFF to obtain the probability $p_i$ that $x_i$ matches the user's semantic query [S1].
3.  **Selection Logic:** Determine if point $x_i$ is "selected" by the query.
    *   *Threshold Mode:* If $p_i > \tau$ (user-defined threshold), the point is selected [S1].
    *   *Probabilistic Mode:* Alternatively, the method can use the mixture of selected and not-selected results in proportion to $p_i$ without a hard threshold [S1].
4.  **Transform Application:**
    *   **Case A: Not Selected.** Calculate density $\sigma(x_i)$ and color $\mathbf{c}(x_i)$ using the vanilla NeRF $F_\Theta(x_i)$ [S1].
    *   **Case B: Selected.** Apply the specific editing transform:
        *   **Deletion:** Set density $\sigma(x_i) = 0$. The color $\mathbf{c}(x_i)$ is irrelevant as the point contributes no opacity [S1].
        *   **Color Editing:** Query the NeRF for $\sigma(x_i)$ and $\mathbf{c}(x_i)$. Transform the color using a colorization function $b$ (e.g., a neural colorization network or simple mapping): $\mathbf{c}'(x_i) = b(\mathbf{c}(x_i))$ [S1].
        *   **Translation/Rescaling:** Compute the inverse transformation $x'_i = g^{-1}(x_i)$.
            *   If $x'_i$ is also selected by the query, use $x'_i$ to query the NeRF for density $\sigma(x'_i)$ and color $\mathbf{c}(x'_i)$ [S1].
            *   If both $x_i$ and $x'_i$ are selected and have non-zero density (e.g., at boundaries of deformed objects), mix the colors $\mathbf{c}(x_i)$ and $\mathbf{c}(x'_i)$ in the ratio of their alphas at the point [S1].
5.  **Volume Rendering:** Perform standard volume rendering using the series of $(\sigma, \mathbf{c})$ tuples generated in Step 4.

**Pseudocode:**

```python
def render_ray_with_editing(ray_o, ray_d, nerf_model, dff_model, 
                            edit_type, transform_func, color_func, threshold):
    """
    Renders a single ray with editing applied via DFF interception.
    
    Args:
        ray_o: Origin of the ray.
        ray_d: Direction of the ray.
        nerf_model: Function returning (sigma, color) given 3D coordinates.
        dff_model: Function returning probability p given 3D coordinates.
        edit_type: String, one of 'deletion', 'color', 'translation'.
        transform_func: Function g_inv(x) for translation/rescaling.
        color_func: Function b(c) for color editing.
        threshold: Float, probability threshold for selection.
        
    Returns:
        color: Rendered RGB color.
        alpha: Rendered alpha.
    """
    # 1. Sample points along the ray (Standard NeRF sampling)
    # Assuming a helper function that returns points and depths
    points, depths = sample_points(ray_o, ray_d)
    
    num_samples = len(points)
    accumulated_alpha = 0.0
    accumulated_color = np.zeros(3)
    
    for i in range(num_samples):
        x = points[i]
        
        # 2. Query DFF for semantic probability
        p = dff_model(x)
        
        # 3. Determine selection
        is_selected = (p > threshold)
        
        # 4. Calculate sigma and color based on selection and edit type
        if not is_selected:
            # Case A: Vanilla NeRF
            sigma, color = nerf_model(x)
        else:
            # Case B: Selected - Apply Transform
            if edit_type == 'deletion':
                # 4-A: Deletion
                sigma = 0.0
                color = np.zeros(3) # Color irrelevant when sigma=0
            elif edit_type == 'color':
                # 4-B: Color Editing
                sigma, raw_color = nerf_model(x)
                color = color_func(raw_color)
            elif edit_type == 'translation':
                # 4'-C: Translation/Rescaling
                x_prime = transform_func(x)
                
                # Check if the transformed point is also selected
                p_prime = dff_model(x_prime)
                is_selected_prime = (p_prime > threshold)
                
                if is_selected_prime:
                    # Query NeRF for the transformed point
                    sigma_prime, color_prime = nerf_model(x_prime)
                    
                    # Query NeRF for the original point to get its sigma
                    sigma_orig, color_orig = nerf_model(x)
                    
                    # Mix colors based on alpha ratio if both have non-zero density
                    # Note: The source specifies mixing colors in ratio of their alphas.
                    # In volume rendering, alpha contribution is sigma * delta_t.
                    # Assuming equal step size or approximating with sigma ratio for simplicity
                    # as per source "ratio of their alphas at the point".
                    if sigma_orig > 0 and sigma_prime > 0:
                        # Simple alpha-weighted mix
                        total_sigma = sigma_orig + sigma_prime
                        w_orig = sigma_orig / total_sigma
                        w_prime = sigma_prime / total_sigma
                        color = w_orig * color_orig + w_prime * color_prime
                        sigma = sigma_orig # Or combined sigma depending on specific blending need
                    else:
                        # Fallback if one is zero
                        sigma = sigma_prime
                        color = color_prime
                else:
                    # Transformed point not selected, use original point's NeRF output
                    sigma, color = nerf_model(x)
            else:
                # Default: Vanilla
                sigma, color = nerf_model(x)
        
        # 5. Volume Rendering Accumulation
        # Standard front-to-back compositing
        alpha_contribution = 1.0 - np.exp(-sigma) # Approximation for discrete steps
        # More precise: alpha = 1 - exp(-sigma * delta_t)
        # Assuming delta_t is handled in sample generation or normalized
        
        weight = accumulated_alpha * alpha_contribution
        accumulated_color += weight * color
        accumulated_alpha += weight * (1.0 - alpha_contribution)
        
    return accumulated_color, accumulated_alpha
```

**Parameters:**
*   $\tau$ (threshold): User-defined probability threshold. Not given in the sources as a fixed value, but described as "user-defined" [S1].
*   $b(\cdot)$: Colorization function. Implementation depends on the specific application (e.g., Instruct-Pix2Pix for stylization) [S2].
*   $g^{-1}(\cdot)$: Inverse geometric transformation. For translation, this is a simple vector addition/subtraction [S1].

**Edge Cases and Pitfalls:**
*   **Boundary Mixing:** When translating objects, boundaries between the original and deformed positions may require careful alpha-weighted color mixing to avoid artifacts [S1].
*   **Threshold Sensitivity:** The choice of $\tau$ affects the smoothness of the edit. A probabilistic mixture (using $p$ directly) can provide smoother transitions than a hard threshold [S1].
*   **Feature Field Accuracy:** The quality of the edit depends heavily on the accuracy of the DFF. If the DFF misclassifies points, the edit will be inconsistent or incomplete [S1].

## Subtopics

### Local Editing via SAM and Depth Propagation
A technique to edit specific objects within a NeRF without altering the background, using 2D segmentation masks propagated across views via depth information. It employs the Segment Anything Model (SAM) to derive masks for all components in each image, allowing users to isolate a target instance with a single point. The identified mask is projected across different views progressively using depth information, continuing as long as the projected mask sufficiently overlaps with the corresponding mask in the current view. This integrated mask permits exclusive modification of the target object, leaving the background intact. This addresses the pitfall where existing methods induce simultaneous changes in both background and foreground [S2].

### ViCA-NeRF Warm-Up
A strategy to efficiently warm up the editing process by blending edits directly before the entire editing process, accelerating editing while preserving consistency. It randomly selects a view to edit and projects the edited view onto all other views. The update for a given view $i$ and edited view $j$ is calculated as:
$$ I_i' = \lambda I_i \odot m_w + (1 - \lambda) I_{i,j} \odot m_w + I_i \odot (1 - m_w) $$
where $m_w$ is the binary mask for the projected area, and $\lambda$ is a hyperparameter controlling the ratio preserved from the original pixel value. This accelerates the editing process while maintaining high consistency in stylization [S2].

### NeRF-RPN Application
A method for scene editing using 3D object detection proposals. It edits the scene by setting the density inside a proposal bounding box to zero when rendering. This effectively removes the detected object from the NeRF representation. It is used in conjunction with NeRF-RPN, a framework for object detection in NeRFs [S3].

## Operating characteristics
*   **Time Complexity:** The primary cost is the additional query to the DFF for every sample point during rendering. This adds a constant overhead per sample compared to vanilla NeRF rendering. Training time is not affected as the NeRF parameters $\Theta$ are not updated during editing [S1].
*   **Memory Complexity:** Requires storing the DFF model weights in addition to the NeRF weights. The DFF is typically a pre-trained feature encoder (e.g., LSeg, DINO) [S1].
*   **Strengths:** Instantaneous editing (no iterative optimization required); multi-view consistency is inherent if the feature field is consistent; supports various edit types (deletion, color, geometry) [S1].
*   **Limitations:** Quality depends on the accuracy of the external feature field; hard to achieve fine-grained control without a good feature field; may struggle with complex semantic boundaries if the DFF is inaccurate [S1].
*   **When to use:** When real-time or near-real-time editing is required, or when the feature field provides strong semantic priors.
*   **When not to use:** When the edit requires significant structural changes that the feature field cannot capture, or when high-fidelity inpainting is needed (use optimization-based methods instead) [S1, S2].

## Background
The NeRF Editing Procedure via Feature Field Distillation was introduced in the paper "Decomposing NeRF for Editing Via Feature Field Distillation" [S1]. It builds on the idea of distilling semantic information from large pre-trained models (like LSeg or DINO) into a feature field that can be queried during rendering. This allows for editing without retraining the NeRF. The method is part of a broader family of inference-time interception techniques for NeRF editing [12491-nerf-editing-procedure.md].
