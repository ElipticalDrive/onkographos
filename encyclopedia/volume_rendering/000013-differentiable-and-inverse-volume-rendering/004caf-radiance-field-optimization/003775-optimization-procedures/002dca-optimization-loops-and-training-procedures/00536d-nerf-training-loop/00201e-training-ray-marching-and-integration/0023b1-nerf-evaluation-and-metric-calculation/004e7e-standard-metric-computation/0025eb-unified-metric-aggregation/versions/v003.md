# Unified Metric Aggregation

Also called: Evaluation Reporting, Global and Per-view Metric Aggregation

## Overview
Unified Metric Aggregation processes the raw per-view evaluation results generated by [NeRF Evaluation and Metric Calculation](3079-nerf-evaluation-and-metric-calculation.md) to produce standardized global performance scores and detailed per-view logs. It aggregates per-view PSNR, SSIM, and LPIPS scores into global averages and per-view dictionaries for evaluation reporting [S1, unofficial]. Unlike [PSNR Evaluation Pipeline](4315-psnr-evaluation-pipeline.md), which may focus on a single metric or specific pipeline stages, this method provides a holistic reporting structure that combines pixel-wise fidelity (PSNR, SSIM) and perceptual quality (LPIPS) into a unified JSON output format.

## How it works
**Inputs and Outputs:**
- **Input:** A list of paired file paths representing rendered images and ground truth (GT) images for a specific test set.
- **Output:** Two JSON files: one containing global average metrics and one containing per-view metrics.

**Data Structures:**
- **Per-view Metric Dictionary:** A mapping from image filename to a dictionary of metric values.
  - Layout: `{"image_name": {"PSNR": float, "SSIM": float, "LPIPS": float}}`
- **Global Metric Dictionary:** A mapping from iteration identifier to average metric values.
  - Layout: `{"ours_{iteration}": {"PSNR": float, "SSIM": float, "LPIPS": float}}`

**Steps:**
1. Initialize empty lists to store per-view metric values for PSNR, SSIM, and LPIPS.
2. Iterate over each pair of rendered and ground truth image paths.
3. Load the RGB images from disk.
4. Normalize pixel values to the range $[0, 1]$.
5. Convert images to CHW (Channel, Height, Width) tensor format.
6. Verify that the rendered and ground truth tensors have identical shapes.
7. Compute PSNR, SSIM, and LPIPS scores for the current pair.
8. Validate that all computed scores are finite numbers.
9. Store the results in the per-view dictionary and append to the global lists.
10. After processing all views, compute the arithmetic mean of each metric list.
11. Write the global metrics and per-view JSON to disk.

```python
def unified_metric_aggregation(

    gt_paths: list,
    iteration_id: str,
    output_dir: Path
) -> None:
    per_view_metrics = {}
    global_psnrs = []
    global_ssims = []
    global_lpips = []

    for render_path, gt_path in zip(render_paths, gt_paths):
        # Load and preprocess
        rendered = load_image(render_path).to(torch.float32)
        ground_truth = load_image(gt_path).to(torch.float32)
        
        # Normalize to [0, 1]
        rendered = rendered / 255.0
        ground_truth = ground_truth / 255.0
        
        # Convert to CHW tensor
        rendered = rendered.permute(2, 0, 1)
        ground_truth = ground_truth.permute(2, 0, 1)
        
        # Shape check
        assert rendered.shape == ground_truth.shape, f"Shape mismatch: {rendered.shape} vs {ground_truth.shape}"
        
        # Compute metrics
        psnr = compute_psnr(rendered, ground_truth)
        ssim = compute_ssim(rendered, ground_truth)
        lpips = compute_lpips(rendered, ground_truth)
        
        # Validate finiteness
        assert torch.isfinite(torch.tensor(psnr)), "PSNR is not finite"
        assert torch.isfinite(torch.tensor(ssim)), "SSIM is not finite"
        assert torch.isfinite(torch.tensor(lpips)), "LPIPS is not finite"
        
        # Store per-view
        image_name = render_path.stem
        per_view_metrics[image_name] = {
            "PSNR": psnr,
            "SSIM": ssim,
            "LPIPS": lpips
        }
        
        # Accumulate for global
        global_psnrs.append(psnr)
        global_ssims.append(ssim)
        global_lpips.append(lpips)

    # Compute global averages
    global_metrics = {
        "PSNR": sum(global_psnrs) / len(global_psnrs) if global_psnrs else 0.0,
        "SSIM": sum(global_ssims) / len(global_ssims) if global_ssims else 0.0,
        "LPIPS": sum(global_lpips) / len(global_lpips) if global_lpips else 0.0
    }

    # Write outputs
    global_json = {f"ours_{iteration_id}": global_metrics}
    per_view_json = {f"ours_{iteration_id}": per_view_metrics}

    (output_dir / "global_metrics.json").write_text(json.dumps(global_json))
    (output_dir / "per_view_metrics.json").write_text(json.dumps(per_view_json))
```

**Parameters:**
- `iteration_id`: String identifier for the current training iteration.
- `output_dir`: Directory path for saving JSON files.

**Edge Cases and Pitfalls:**
- **Shape Mismatch:** If rendered and GT images have different dimensions, the process must abort or raise an error [S1, unofficial].
- **Non-finite Values:** NaN or Inf values in metrics must be detected and handled, typically by excluding the view or logging a warning [S1, unofficial].
- **Normalization:** Incorrect normalization (e.g., not scaling to [0,1]) will lead to incorrect PSNR and SSIM calculations.

## Subtopics

### [LPIPS Evaluation Protocol](4376-lpips-evaluation-protocol.md)
LPIPS evaluates perceptual similarity between rendered images and ground truth by measuring distances in a feature space extracted from a pretrained neural network, where lower values indicate higher visual fidelity. It is included in the [Unified Metric Aggregation](3644-unified-metric-aggregation.md) alongside PSNR and SSIM to provide a perceptual quality score that correlates better with human judgment than pixel-wise metrics.

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of test views $N$, i.e., $O(N)$, assuming constant-time metric computation per view.
- **Memory Complexity:** Linear with respect to $N$ to store per-view results in memory before aggregation.
- **Strengths:** Provides a comprehensive view of model performance by combining multiple metrics; structured output facilitates easy comparison across iterations.
- **Limitations:** Computationally expensive if LPIPS is used for all views; sensitive to input normalization and shape consistency.
- **When to use:** Standard evaluation phase after training or during validation to report final model quality.

## Background
Originating from the evaluation pipelines of modern neural radiance field implementations, this method standardizes the reporting of quantitative metrics. It is commonly found in repositories such as Advanced3DGS [S1, unofficial].
