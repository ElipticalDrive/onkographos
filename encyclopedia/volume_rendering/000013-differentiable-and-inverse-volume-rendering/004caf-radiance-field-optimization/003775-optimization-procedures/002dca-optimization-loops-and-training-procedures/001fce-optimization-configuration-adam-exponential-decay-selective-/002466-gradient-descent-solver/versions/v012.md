# Gradient Descent Solver

Also called: Adam Optimizer, Adam Optimizer Solver, L1/L2 Norm Solver

## Overview
The Gradient Descent Solver is a matrix-free optimization method used to update voxel grid parameters in differentiable volume rendering, supporting both constant update rates and the Adam optimizer [S1, S2, unofficial]. It addresses gradient noise and anisotropy by filtering gradients temporally using exponential moving averages, providing stable behavior for ill-conditioned systems [S1, unofficial][S3]. Unlike direct solvers that form normal equations, it accumulates gradients via atomic additions, supporting both $l_2$-norm (least squares) and $l_1$-norm (least absolute deviations) loss functions [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Current parameter vector $\theta_t$ (e.g., voxel densities or transfer function coefficients), gradient $\nabla_\theta f(\theta_t)$, learning rate $\alpha$, decay rates $\beta_1, \beta_2$.
- Output: Updated parameter vector $\theta_{t+1}$.

**Data Structures:**
- $\theta_t$: Parameter vector of size $N$.
- $m_t$: Exponential moving average of gradients, size $N$, initialized to $0$.
- $v_t$: Exponential moving average of squared gradients, size $N$, initialized to $0$.

**Numbered Steps:**
1. Compute the gradient $\nabla_\theta f(\theta_t)$ of the objective function $f$ with respect to parameters $\theta_t$. In a matrix-free implementation, this is accumulated via atomic additions [S1, unofficial].
2. Update the first moment estimate (mean of gradients):
   $$ m_t = \beta_1 m_{t-1} + (1 - \beta_1) \nabla_\theta f(\theta_t) $$
3. Update the second moment estimate (uncentered variance of gradients):
   $$ v_t = \beta_2 v_{t-1} + (1 - \beta_2) (\nabla_\theta f(\theta_t))^2 $$
   where the square is element-wise [S3].
4. Compute the update step. The sources describe the update as $m_t / v_t$ multiplied by the learning rate $\alpha$ [S3]. Note: Standard Adam includes bias correction terms ($\hat{m}_t = m_t / (1-\beta_1^t)$ and $\hat{v}_t = v_t / (1-\beta_2^t)$), but the source [S3] explicitly omits them for brevity in the described variant. The update is:
   $$ \theta_{t+1} = \theta_t - \alpha \frac{m_t}{v_t} $$
   [G: In standard implementations, a small epsilon $\epsilon$ is added to the denominator to prevent division by zero: $\theta_{t+1} = \theta_t - \alpha \frac{m_t}{v_t + \epsilon}$.]
5. If using $l_1$-norm, the gradient $\nabla_\theta f(\theta_t)$ should be the subgradient of the $l_1$ loss (sign of residuals) [S1, unofficial].

**Parameters:**
- $\alpha$: Learning rate. Typical values are not specified in the sources.
- $\beta_1$: Exponential decay rate for the first moment estimate $m_t$. Typical values are not specified in the sources.
- $\beta_2$: Exponential decay rate for the second moment estimate $v_t$. Typical values are not specified in the sources.

**Edge Cases and Pitfalls:**
- Per-parameter filtering assumes no correlations across parameters [S3]. This can cause high-frequency artifacts if:
  - Gradients are very noisy.
  - The objective function is highly anisotropic.
  - Optimization is terminated early [S3].
- The solver is stable for ill-conditioned systems [S1, unofficial].
- The $l_2$-norm penalizes larger residuals more strongly due to the quadratic term, while the $l_1$-norm tolerates larger outliers [S1, unofficial].

**Pseudocode:**
```python
def gradient_descent_solver_step(theta, gradient, alpha, beta1, beta2, m, v):
    """
    Performs one step of the Gradient Descent Solver with Adam-like updates.
    
    Args:
        theta: Current parameter vector (numpy array).
        gradient: Gradient of the objective function w.r.t. theta (numpy array).
        alpha: Learning rate (float).
        beta1: Exponential decay rate for first moment (float).
        beta2: Exponential decay rate for second moment (float).
        m: Current first moment estimate (numpy array, same shape as theta).
        v: Current second moment estimate (numpy array, same shape as theta).
        
    Returns:
        theta_next: Updated parameter vector.
        m_next: Updated first moment estimate.
        v_next: Updated second moment estimate.
    """
    # Update first moment estimate
    m_next = beta1 * m + (1 - beta1) * gradient
    
    # Update second moment estimate (element-wise square)
    v_next = beta2 * v + (1 - beta2) * (gradient ** 2)
    
    # Compute update step
    # Note: Source [S3] describes update as alpha * (m_t / v_t) without bias correction or epsilon.
    # Standard Adam uses bias correction and epsilon. This implementation follows the source description.
    update = alpha * (m_next / v_next)
    
    # Update parameters
    theta_next = theta - update
    
    return theta_next, m_next, v_next
```

## Subtopics

### [CGLS Solver (Conjugate Gradient Least Squares)](3285-cgls-solver-conjugate-gradient-least-squares.md)
The CGLS solver is a sparse linear least squares method used to solve optimization problems where the normal equations ($A^T A$) are ill-conditioned due to quadratic condition numbers. It provides numerically stable results for large or almost rank-deficient problems, distinguishing itself from direct solvers by avoiding the explicit formation of $A^T A$. While generally slower than computing $A^T A$ and $A^T b$ for moderately sized problems, it is preferred when numerical stability is critical.

### [Partially Learned Gradient Descent](3771-partially-learned-gradient-descent.md)
Partially Learned Gradient Descent (PLGD) is an iterative reconstruction method that unrolls a fixed number of optimization steps into a neural network. It initializes the reconstruction with a filtered backprojection (FBP) estimate and iteratively refines it by passing the current estimate, gradients, and a momentum memory state through a convolutional network to compute the next update. Unlike standard gradient descent which uses a fixed or manually tuned step size, PLGD learns the optimization dynamics (step size and momentum) directly from data, while retaining the explicit physical forward model (e.g., RayTransform) to ensure interpretability and robustness to distribution shifts. It differs from fully learned end-to-end CNNs by preserving the gradient structure of the inverse problem.

### [SGD with Positive t-Distribution](5809-sgd-with-positive-t-distribution.md)
An ablation study variant of differentiable volume rendering optimization that replaces Gaussian noise assumptions with a positive Student's t-distribution to model gradient uncertainty. It serves as a controlled baseline to isolate the impact of heavy-tailed noise modeling from other components like MCMC sampling, ensuring fair comparison with methods using low-pass filtering. It builds on the Gradient Descent Solver [3280-gradient-descent-solver.md] by modifying the noise model [G].

### [Newton's Method](6442-newton-s-method.md)
Newton's Method is a second-order optimization algorithm derived from the second-order Taylor expansion of the objective function. It solves for the root of the gradient (where the derivative is zero) to find local minima or maxima, offering quadratic convergence for well-behaved functions. Unlike [Gradient Descent Solver](3280-gradient-descent-solver.md), which uses only first-order gradient information and a fixed or adaptive step size, Newton's Method incorporates the Hessian matrix to account for local curvature, allowing it to take larger, more informed steps toward the optimum. In the context of inverse volume rendering, it is also applied as a root-finding algorithm to solve for ray intersections with implicit geometry.

### [Inexact Line Search Optimization](7741-inexact-line-search-optimization.md)
Inexact Line Search Optimization is an iterative method that adapts the step size in gradient descent to achieve a reduction in the objective function while ensuring sufficiently fast progress. It solves the problem of slow convergence in standard gradient descent by dynamically selecting a step size that guarantees improvement without requiring the computational expense of finding the exact minimum along the search direction. Unlike exact line search methods, which may suffer from convergence deterioration, this inexact strategy yields reasonable results and descends much faster.

### [Incremental Preconditioned Gradient Method](14178-incremental-preconditioned-gradient-method.md)
The Incremental Preconditioned Gradient Method is an online learning algorithm for reflective tomography that incrementally updates a voxel model $\phi \in \mathbb{R}^N$ to minimize modeling error against a sequence of observed frames. It solves the global least-squares optimization problem by applying preconditioned gradient descent steps to individual data frames one at a time. It distinguishes itself from batch solvers by processing data sequentially (frame-driven) and using a specific preconditioner derived from the projection matrix structure to prioritize high-frequency spatial information (surfaces).

### [Gradient-based Optimization with Surrogate Function](15131-gradient-based-optimization-with-surrogate-function.md)
This method estimates spatially varying extinction coefficients $\beta$ by minimizing a cost function $E(\beta)$ that fits a forward-model rendering to image measurements, using a surrogate function to avoid computing the full Jacobian per gradient step. It sets itself apart from direct Jacobian computation by decoupling the expensive forward-model rendering (FMC) from the gradient descent updates, requiring only one FMC rendering per block of $NGD$ gradient steps rather than $N_{voxels}$.

### [Moment-Damped Levenberg-Marquardt Optimizer](15705-moment-damped-levenberg-marquardt-optimizer.md)
A hybrid optimization strategy for sparse-pixel training that partitions Gaussian parameters into geometry and base appearance blocks, solving them via small Levenberg-Marquardt (LM) systems with Adam-style moment damping, while updating Higher-order Spherical Harmonic (SH) coefficients separately with Adam. It sets itself apart from its parent [Gradient Descent Solver](3280-gradient-descent-solver.md) by introducing Hessian-informed updates for geometry and appearance, and from [CGLS Solver (Conjugate Gradient Least Squares)](3285-cgls-solver-conjugate-gradient-least-squares.md) by using direct Cholesky decomposition on small blocks rather than iterative linear solving.

### PDHG Solver (Primal-Dual Hybrid Gradient)
A solver that keeps the main solver state on the selected NVIDIA GPU during the PDHG loop, including volume, extrapolated volume, previous volume, gradient buffer, TV duals, projection data duals, measured projections, and projection batches [S4, unofficial]. Default resident projector backend is `matched_voxel` [S4, unofficial]. ASTRA is rejected for production resident PDHG because its 3-D CUDA FP/BP pair failed strict matched-adjoint checks [S4, unofficial]. LEAP/PyTorch support is experimental and should only be used when its adjointness guard passes [S4, unofficial]. Current resident multi-GPU support is not a pooled-memory solver; full memory pooling across two GPUs requires volume-sharded resident PDHG implementation [S4, unofficial]. If resident PDHG runs out of VRAM, do not raise GPU PDHG memory safety to force a run; that only weakens the safety check [S4, unofficial].

## Operating characteristics
- **Time and Memory Complexity:** The solver is matrix-free, accumulating gradients via atomic additions [S1, unofficial]. This avoids the explicit formation of large matrices like $A^T A$, making it suitable for large-scale problems where forming such matrices is infeasible [S1, unofficial].
- **Measured Performance:** The solver shows stable behavior for ill-conditioned systems [S1, unofficial]. The choice of loss function ($l_1$ vs. $l_2$) can make a minor difference in final results [S1, unofficial].
- **Scaling:** The matrix-free nature allows it to scale to large voxel grids without the memory overhead of storing the Hessian or normal equations [S1, unofficial].
- **Strengths and Limitations:** It is stable for ill-conditioned systems [S1, unofficial]. However, per-parameter filtering assumes no correlations across parameters, which can lead to high-frequency artifacts if gradients are noisy, the function is highly anisotropic, or optimization is terminated early [S3].
- **When to use it:** Use when dealing with ill-conditioned systems or when memory constraints prevent forming normal equations [S1, unofficial]. Use Adam variant when gradient noise and anisotropy need to be filtered temporally [S3].
- **When not to use it:** Avoid if parameter correlations are critical and can be efficiently exploited (e.g., use Newton's Method or CGLS if applicable) [S3]. Avoid if high-frequency artifacts are unacceptable and the optimization is terminated early [S3].

## Background
The Gradient Descent Solver, specifically the Adam optimizer variant, was introduced by Kingma and Ba in 2015 [S2, S1, unofficial]. It is used in differentiable volume rendering frameworks such as DiffVox [S2, unofficial] and DiffDVR [S1, unofficial] for optimizing voxel grid parameters and transfer functions. The method addresses issues of gradient noise and anisotropy by filtering gradients temporally [S3].
