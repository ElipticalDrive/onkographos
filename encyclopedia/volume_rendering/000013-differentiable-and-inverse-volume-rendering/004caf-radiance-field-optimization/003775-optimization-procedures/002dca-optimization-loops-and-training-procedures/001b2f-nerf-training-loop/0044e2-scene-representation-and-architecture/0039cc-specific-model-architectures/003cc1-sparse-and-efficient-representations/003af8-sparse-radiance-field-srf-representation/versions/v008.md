# Sparse Radiance Field (SRF) Representation


## Overview
A Sparse Radiance Field (SRF) is a voxel-based representation of a 3D scene or object that stores density and view-dependent radiance colors in a sparse grid structure [S1]. It serves as a compact, differentiable alternative to dense neural radiance fields (NeRFs) and dense voxel grids, enabling efficient optimization and rendering by storing data only for occupied regions [S1]. Unlike its siblings, Mega-NeRF Spatial Partitioning and KiloNeRF, which use hierarchical or tree-based structures for scalability, SRF relies on a flat, coordinate-based (COO) sparse array, making mesh extraction straightforward via Marching Cubes [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A set of posed 2D images of a 3D object or scene.
*   **Output:** A Sparse Radiance Field $X_{non-empty}$, defined as a set of tuples containing 3D coordinates and feature vectors.

**Data Structures**
The SRF is defined as a voxel grid of dimension $1+d$, where $d$ is the dimension of the radiance colors and 1 dimension is for density [S1].
*   **Grid Size:** $H \times H \times H$, where $H$ is the resolution in each dimension [S1].
*   **Feature Vector:** At each voxel $(i,j,k)$, the feature vector $f$ contains:
    *   Density $\alpha_{i,j,k} \in \mathbb{R}$
    *   Radiance colors $\rho_{i,j,k} \in \mathbb{R}^d$
*   **Sparse Format:** The grid is stored in Coordinate List (COO) format [S1]. It is a set of $M$ tuples:
    $$X_{non-empty} = \{(c_m, f_m)\}_{m=1}^M$$
    where $c_m = (i, j, k) \in \mathbb{Z}^+$ are positive integer coordinates and $f_m \in \mathbb{R}^{d+1}$ is the feature vector [S1]. The ordering of tuples is arbitrary [S1].

**Parameters**
*   **Resolution ($H$):** The grid size in each dimension. Typical values used in SPARF are $H \in \{32, 128, 512\}$ [S1].
*   **Radiance Dimension ($d$):**
    *   For view-dependent SRF using 4 spherical harmonics (SH) factors per RGB channel: $d = 3 \times 4 = 12$ [S1].
    *   For fixed RGB colors: $d = 3 \times 1 = 3$ [S1].
    *   Note: Using 4 SH factors reduces optimization space by 40% and time by 10% compared to 9 SH factors, while maintaining PSNR [S1]. Using fixed RGB reduces PSNR by ~1 dB but saves 80% space and 20% time [S1].

**Algorithm Steps**
1.  **Initialization:** Initialize an empty list of tuples for $X_{non-empty}$.
2.  **Optimization:** Optimize the SRF parameters (densities and radiance colors) by minimizing the difference between rendered images and input images [S1]. This is typically done using volume rendering equations where rays are cast through the sparse voxel grid [S1].
    *   *Note:* The specific optimization loop details are covered in the parent article [Parent](9326-sparse-and-efficient-representations.md).
3.  **Storage:** After optimization, store only the voxels with non-zero or significant density in the COO format [S1].
4.  **Rendering:** To render a new view, cast rays and sample the COO list. For each ray, identify the occupied voxels $(c_m)$ along the ray path and accumulate color and opacity using standard volume rendering integration [S1].
5.  **Mesh Extraction (Optional):** Since SRFs lie on a 3D voxel space, meshes can be extracted by applying the Marching Cubes algorithm to the density field $\alpha_{i,j,k}$ [S1].

**Pseudocode**
```python
# Data Structure: SparseRadianceField
class SparseRadianceField:
    def __init__(self, resolution_H, radiance_dim_d):
        self.H = resolution_H
        self.d = radiance_dim_d
        # COO format: list of (coordinate, feature_vector)
        # coordinate: tuple of 3 ints (i, j, k)
        # feature_vector: array of size d+1 (density, d radiance values)
        self.tuples = [] 

    def add_voxel(self, coord, density, radiance_colors):
        """
        Adds a voxel to the sparse field.
        coord: (i, j, k)
        density: float
        radiance_colors: array of size d
        """
        feature_vector = [density] + list(radiance_colors)
        self.tuples.append((coord, feature_vector))

    def render_ray(self, ray_origin, ray_direction, num_samples):
        """
        Renders a single ray by sampling the sparse voxel grid.
        Returns accumulated color and opacity.
        """
        # 1. Generate sample points along the ray
        # t values from near to far plane
        t_values = linspace(ray_origin.t_near, ray_origin.t_far, num_samples)
        sample_points = ray_origin + ray_direction * t_values[:, None]
        
        accumulated_color = [0.0, 0.0, 0.0]
        accumulated_opacity = 0.0
        transmittance = 1.0
        
        # 2. For each sample point, check if it exists in the sparse grid
        for point in sample_points:
            # Map continuous point to voxel coordinates
            voxel_coord = map_to_voxel_grid(point, self.H)
            
            # Look up voxel in COO list
            # In practice, this requires a hash map or sorted list for efficiency
            voxel_data = lookup_voxel(self.tuples, voxel_coord)
            
            if voxel_data is not None:
                density = voxel_data[0]
                radiance = voxel_data[1:]
                
                # Volume rendering step
                # alpha = 1 - exp(-density * delta_t)
                # color += transmittance * alpha * radiance
                # transmittance *= 1 - alpha
                
                # [G] Standard volume rendering integration
                delta_t = t_values[1] - t_values[0] # Assuming uniform sampling
                alpha = 1.0 - exp(-density * delta_t)
                
                for c in range(3):
                    accumulated_color[c] += transmittance * alpha * radiance[c]
                
                accumulated_opacity += transmittance * alpha
                transmittance *= (1.0 - alpha)
            else:
                # Empty space, no contribution
                pass
                
        return accumulated_color, accumulated_opacity

# Helper functions (standard graphics operations)
def map_to_voxel_grid(point, H):
    # Normalize point to [0, 1] range relative to bounding box
    # Then scale to [0, H-1]
    normalized = (point - bbox_min) / (bbox_max - bbox_min)
    return tuple(int(p * (H - 1)) for p in normalized)

def lookup_voxel(tuples, coord):
    # Efficient lookup using a hash map or binary search
    # Returns feature vector if found, else None
    for c, f in tuples:
        if c == coord:
            return f
    return None
```

**Edge Cases and Pitfalls**
*   **Low Density Voxels:** Non-empty voxels may have low densities that do not significantly affect volume rendering but contain random colors. These can confuse the network during training [S1].
*   **Vanishing Gradients:** High sparsity (~99%) and misalignment between input and output SRF coordinates (caused by sparse convolutional strides and pruning) can lead to vanishing gradients, harming the learning process [S1].
*   **Small Errors:** Small errors in predicting densities or radiance colors can result in large distortions in rendered images [S1].

## Operating characteristics
*   **Memory Complexity:** Memory usage is proportional to the number of non-empty voxels $M$, not the total grid size $H^3$. This provides significant savings for sparse scenes [S1].
*   **Time Complexity:** Rendering time depends on the number of occupied voxels along the ray. Optimization time is reduced compared to dense NeRFs due to the smaller parameter space [S1].
*   **Performance:** Using 4 SH factors reduces optimization time by 10% compared to 9 SH factors [S1]. Using fixed RGB colors reduces time by 20% but lowers PSNR by ~1 dB [S1].
*   **Strengths:** Straightforward mesh extraction via Marching Cubes; efficient storage for sparse objects; scalable to large datasets (e.g., SPARF with 1 million SRFs) [S1].
*   **Limitations:** Prone to vanishing gradients due to high sparsity; sensitive to small prediction errors; requires careful handling of low-density voxels [S1].
*   **When to Use:** Suitable for 3D object tasks with coarse-to-fine approaches requiring multiple resolutions ($H \in \{32, 128, 512\}$) and when mesh extraction is desired [S1].
*   **When Not to Use:** Not ideal for highly dense, complex scenes where sparsity is low, or when view-dependent effects require high-order spherical harmonics without the associated computational cost [S1].

## Background
The Sparse Radiance Field (SRF) representation was introduced in the context of the SPARF dataset, which contains one million 3D SRFs collected from multiple voxel resolutions (32, 128, 512) [S1]. The work builds upon Plenoxels, adapting its use of spherical harmonics for view-dependent learning into a sparse voxel structure [S1]. The SPARF dataset includes 40,000 shapes from 13 classes, rendered from 400 equidistant views plus additional random views for robustness testing [S1]. The representation was designed to scale up Plenoxels optimization for large-scale learning, reducing iterations while maintaining high PSNR [S1].
