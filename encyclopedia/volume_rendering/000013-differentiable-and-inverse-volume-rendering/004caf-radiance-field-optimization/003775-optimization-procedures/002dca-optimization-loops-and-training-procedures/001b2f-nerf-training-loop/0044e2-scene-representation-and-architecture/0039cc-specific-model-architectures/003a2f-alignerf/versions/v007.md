# AligNeRF

Also called: AligNeRF: High-Fidelity Neural Radiance Fields via Alignment-Aware Training

## Overview
AligNeRF is a training strategy and architectural modification for Neural Radiance Fields (NeRF) designed to improve high-frequency detail recovery and robustness to misalignment caused by moving objects or camera calibration errors in high-resolution settings [S1]. It distinguishes itself from standard NeRF implementations by combining a convolution-augmented architecture with a staged, alignment-aware fine-tuning procedure that utilizes patch-based sampling and optical flow estimation [S1, S2].

## How it works
AligNeRF builds on [Specific Model Architectures](8585-specific-model-architectures.md) by modifying the baseline mip-NeRF 360 [S1]. The method consists of two main components: a convolution-augmented architecture and an alignment-aware training procedure [S1].

### Inputs and Outputs
*   **Inputs:** A set of calibrated images $\{I_i\}$ with known camera poses. The baseline model uses mip-NeRF 360 as the starting point [S1].
*   **Outputs:** Rendered high-resolution images with improved texture detail and reduced blur [S1].

### Data Structures
The method modifies the standard NeRF representation:
1.  **Feature Space Output:** The final layer of the MLP $F_\Theta$ outputs $N$ channels of feature space values instead of 3 RGB channels [S1].
2.  **Convolutional Network:** A 3-layer convolutional network with ReLU activations and $3 \times 3$ kernels is applied after volumetric rendering [S1].
3.  **Padding:** "Reflectance" padding is used for convolution inputs to prevent checkerboard artifacts [S1].

### Numbered Steps

1.  **Pre-training (Normal Stage):**
    Train the baseline NeRF model (mip-NeRF 360) using standard random ray sampling and RGB output [S1].

2.  **Architecture Modification:**
    *   Change the output channels of the MLP's last layer from 3 to $N$ [S1].
    *   Perform numerical integration along the ray in the feature space ($N$ channels) rather than RGB space [S1].
    *   Apply a 3-layer CNN with $3 \times 3$ kernels and ReLU activations to the rendered feature map [S1].
    *   Use reflectance padding for CNN inputs and remove padding values in outputs [S1].
    *   Add a feed-forward perceptron layer at the end of the CNN to convert the feature representation back to RGB space [S1].

3.  **Patch-Based Sampling:**
    Switch from random ray sampling to patch-based sampling. Gather a local image region (patch) during each iteration to utilize 2D local neighborhood information [S1].
    *   Rendered patch size: $32 \times 32$ pixels [S1].
    *   Ground truth patch size ($G$): $48 \times 48$ pixels [S1].

4.  **Alignment-Aware Fine-Tuning:**
    *   Estimate optical flow to handle moving objects or misalignment [S1].
    *   During each iteration, sample a larger ground truth patch $G$ ($48 \times 48$) [S1].
    *   Search over every possible subpatch $G_i$ of $G$ to find the best match with the smaller rendered patch $R$ ($32 \times 32$) [S1].
    *   Compute the loss using a combination of pixel difference and coordinate regularization [S1]:
        $$ L_{PM}(G, R) = \min_{i=1,...,N} (D(G_i, R) + \lambda \cdot D_{coord}(G_i, R)) $$
        where:
        *   $D(G_i, R) = \|G_i - R\|_2$ is the Euclidean distance between the subpatch and rendered patch.
        *   $D_{coord}(G_i, R) = \sqrt{\Delta x^2 + \Delta y^2}$ is the coordinate offset penalty, where $\Delta x$ and $\Delta y$ are the horizontal and vertical offsets between $G_i$ and $R$ [S1].
        *   $\lambda$ is a regularization weight, empirically set to 0.01 [S1].

### Pseudocode

```python
import math

def reflectance_padding(image, kernel_size=3):
    """
    Applies reflectance padding to the image.
    For a kernel of size k, pads by (k-1)/2 on each side.
    """
    pad = (kernel_size - 1) // 2
    # Reflectance padding logic: mirror the edge pixels
    # Top
    top = image[-pad:0:-1]
    # Bottom
    bottom = image[-2:-pad-2:-1]
    # Left
    left = image[:, -pad:0:-1]
    # Right
    right = image[:, -2:-pad-2:-1]
    
    # Construct padded image
    # Note: This is a conceptual implementation. 
    # In practice, this involves stacking arrays.
    padded = []
    # Top row
    padded.append(top)
    # Middle rows with left/right padding
    for row in image:
        padded_row = list(left[0]) + list(row) + list(right[0])
        padded.append(padded_row)
    # Bottom row
    padded.append(bottom)
    
    return padded

def compute_loss(patch_gt, patch_rendered, lambda_reg=0.01):
    """
    Computes the alignment-aware loss.
    patch_gt: Ground truth patch (48x48)
    patch_rendered: Rendered patch (32x32)
    """
    gt_h, gt_w = patch_gt.shape
    rend_h, rend_w = patch_rendered.shape
    
    # Search space for subpatches in GT
    # A 32x32 subpatch can start at x in [0, 48-32] and y in [0, 48-32]
    min_loss = float('inf')
    
    for y in range(gt_h - rend_h + 1):
        for x in range(gt_w - rend_w + 1):
            # Extract subpatch
            subpatch = patch_gt[y:y+rend_h, x:x+rend_w]
            
            # Pixel difference D(Gi, R)
            diff = subpatch - patch_rendered
            d_pixel = math.sqrt(sum(sum(diff**2)))
            
            # Coordinate difference D_coord(Gi, R)
            # Offset is the top-left corner (x, y) relative to some reference
            # The source defines dx/dy as horizontal/vertical offset.
            # Assuming (0,0) is the top-left of the GT patch for simplicity of calculation
            # or relative to the rendered patch's expected position.
            # The source says "offset between Gi and R". 
            # We use the indices x, y as the offset magnitude.
            d_coord = math.sqrt(x**2 + y**2)
            
            current_loss = d_pixel + lambda_reg * d_coord
            
            if current_loss < min_loss:
                min_loss = current_loss
                
    return min_loss

def alignerf_training_step(model, gt_patch_48x48, camera_params):
    """
    One step of the alignment-aware fine-tuning.
    """
    # 1. Render a 32x32 patch using the current model
    # The model outputs feature space, then CNN converts to RGB
    rendered_patch_32x32 = model.render_patch(camera_params, size=(32, 32))
    
    # 2. Compute alignment-aware loss
    loss = compute_loss(gt_patch_48x48, rendered_patch_32x32)
    
    # 3. Backpropagate and update weights
    model.update_weights(loss)
    
    return loss
```

### Parameters
*   **Patch Size (Rendered):** $32 \times 32$ pixels [S1].
*   **Patch Size (Ground Truth):** $48 \times 48$ pixels [S1].
*   **Regularization Weight ($\lambda$):** 0.01 [S1].
*   **CNN Kernels:** $3 \times 3$ [S1].
*   **CNN Layers:** 3 layers with ReLU activations [S1].

### Edge Cases and Pitfalls
*   **Checkerboard Artifacts:** Avoided by using reflectance padding and removing padding values in outputs [S1].
*   **Multiview Inconsistency:** The shallow CNN does not perform upsampling, preventing multiview inconsistency [S1].
*   **Blurry Renderings:** If the rendered patch is very blurry, it may match many subpatches equally well. The coordinate regularization term $D_{coord}$ penalizes this ambiguity [S1].

## Operating characteristics
*   **Performance:** On outdoor datasets, AligNeRF achieves a PSNR more than 3 points higher than standard NeRF and better than the best mip-NeRF result [S2].
*   **Training Time:** Does not significantly increase training time compared to the baseline [S2].
*   **Complexity:** The addition of a shallow CNN and patch-based sampling increases computational overhead per iteration compared to random ray sampling, but the shallow network keeps it lightweight [S1].
*   **Strengths:** Improves high-frequency detail recovery; robust to misalignment from moving objects; easy to plug into existing NeRF-like models [S1, S2].
*   **Limitations:** Requires patch-based sampling which changes the standard random ray sampling paradigm; relies on accurate optical flow estimation for moving objects [S1].

## Background
AligNeRF was introduced by Yifan Jiang, Peter Hedman, Ben Mildenhall, Dejia Xu, Jonathan T. Barron, Zhangyang Wang, and Tianfan Xue from the University of Texas at Austin, Google Research, and The Chinese University of Hong Kong [S1]. It was presented at CVPR 2023 [S1]. The method addresses limitations of training NeRF on high-resolution images, specifically issues with moving objects and camera calibration errors [S2]. It builds upon mip-NeRF 360 as the baseline state-of-the-art method for complex unbounded real-world scenes [S1].
