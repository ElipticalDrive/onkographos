# Fast Per-subject Fine-tuning

Also called: Fast fine-tuning, compensation fine-tuning

## Overview
Fast per-subject fine-tuning is a compensation strategy used in dynamic radiance field optimization to address artifacts and imperfections that arise when rendering unseen persons or subjects [S1]. It operates by first training a generalizable model on a diverse dataset of subjects, then freezing specific components, and finally optimizing only a subset of parameters (deformation field and radiance field) for a new, unseen subject [S1]. This method is distinct from generalizable approaches that attempt to predict all parameters directly, as it relies on iterative optimization for the target subject to recover high-frequency details and correct motion artifacts [S1].

## How it works
**Inputs and Outputs:**
- **Input:** A set of multi-view images of a new, unseen subject (performer) with known camera poses.
- **Output:** Optimized parameters for the deformation field and the generalizable neural radiance field specific to that subject.

**Data Structures:**
The method relies on the architecture defined in [Dynamic and Deformable Fields](11366-dynamic-and-deformable-fields.md), specifically:
- $MLP_B$: Feature blending network (generalizable).
- $MLP_d$: Deformation field network (subject-specific).
- $\Phi$: Generalizable neural radiance field (subject-specific).

**Steps:**
1. **Pre-training (Generalization Phase):** Train the network on a dataset of various subjects/performers. During this phase, all parameters are optimized.
2. **Freezing:** After pre-training, freeze the parameters of the feature blending network $MLP_B$ [S1]. This network is considered generalizable and does not need per-subject adjustment.
3. **Per-subject Optimization (Fine-tuning Phase):** For a new unseen subject:
   - Initialize the deformation field parameters $MLP_d$ and the radiance field parameters $\Phi$ from the pre-trained state.
   - Optimize only $MLP_d$ and $\Phi$ using the images of the new subject [S1].
   - $MLP_B$ remains frozen during this phase.

**Pseudocode:**
```python
# Phase 1: Generalizable Training
# Assume dataset D contains multiple subjects
for subject in D:
    # Optimize all parameters: MLP_B, MLP_d, Phi
    optimize(MLP_B, MLP_d, Phi, subject_images)

# Freeze generalizable components
freeze(MLP_B)

# Phase 2: Fast Per-subject Fine-tuning
def fine_tune_subject(subject_images):
    # Initialize subject-specific components from pre-trained state
    # Note: MLP_d and Phi are initialized with weights from Phase 1
    MLP_d = load_pretrained_deformation()
    Phi = load_pretrained_radiance_field()
    
    # Optimize only subject-specific parameters
    # MLP_B is frozen and not included in the optimizer
    optimizer = Optimizer(params=[MLP_d, Phi])
    
    for iteration in range(max_iterations):
        # Sample rays for the subject
        rays = sample_rays(subject_images)
        
        # Forward pass using frozen MLP_B and trainable MLP_d, Phi
        # 1. Encode position and direction
        pos_enc = positional_encoding(rays.xyz)
        dir_enc = positional_encoding(rays.direction)
        
        # 2. Get deformation field parameters (trainable)
        # MLP_d takes encoded position and possibly time/pose
        deformation_params = MLP_d(pos_enc)
        
        # 3. Get features from radiance field (trainable)
        # Phi takes encoded position, direction, and potentially deformation info
        features = Phi(pos_enc, dir_enc, deformation_params)
        
        # 4. Blend features using frozen MLP_B
        # MLP_B takes features from Phi and possibly other generalizable features
        blended_features = MLP_B(features)
        
        # 5. Render color
        color = render_color(blended_features)
        
        # 6. Compute loss against ground truth images
        loss = compute_loss(color, subject_images)
        
        # 7. Backpropagate and update only MLP_d and Phi
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
    return MLP_d, Phi
```

**Edge Cases and Pitfalls:**
- **Overfitting:** Since only a subset of parameters is optimized, there is a risk of overfitting to the sparse input views of the new subject. The pre-trained initialization helps mitigate this, but regularization may be needed [S1].
- **Initialization Sensitivity:** The quality of the fine-tuning depends heavily on the quality of the pre-trained model. If the pre-trained model does not generalize well, the frozen $MLP_B$ may hinder adaptation [S1].

## Subtopics

## Operating characteristics
- **Time Complexity:** Faster than training a full NeRF from scratch for each subject, as only a subset of parameters ($MLP_d$ and $\Phi$) are optimized. However, it is slower than purely feed-forward generalizable methods that require no optimization [S1].
- **Memory Complexity:** Requires storing the pre-trained model weights. During fine-tuning, memory usage is similar to standard NeRF training but with fewer trainable parameters.
- **Strengths:** Effectively reduces artifacts and imperfections for unseen subjects by allowing the model to adapt to specific high-frequency details and motion patterns [S1].
- **Limitations:** Requires iterative optimization for each new subject, which is computationally more expensive than inference-only methods. Performance depends on the diversity and quality of the pre-training dataset [S1].

## Background
Fast per-subject fine-tuning was introduced in the context of HumanNeRF, an efficient method for generating human radiance fields from sparse inputs [S1]. The method addresses the challenge of transferring motion and appearance to unseen persons, where artifacts often arise due to limited training data and diversity among identities [S1]. It builds on the principle that certain components of the radiance field (like feature blending) can be learned generally, while others (deformation and specific radiance) need per-subject adaptation [S1].
