# NeRF Evaluation and Metric Calculation

Also called: Evaluation and Metric Calculation, NeRF Evaluation, NeRF Validation, Single Image Rendering, Validation Rendering

## Overview
NeRF Evaluation and Metric Calculation is the procedure for quantifying the quality of a trained Neural Radiance Field (NeRF) by rendering images from novel or held-out camera poses and comparing them against ground-truth data [S1, S2, S3, unofficial]. It solves the problem of objective performance assessment by computing photometric and perceptual metrics such as PSNR, SSIM, and LPIPS [S1, S2, unofficial][S3, unofficial]. It differs from training procedures by operating in inference mode with deterministic sampling (no perturbation) and focusing on post-processing aggregation of per-view scores rather than gradient-based optimization [S1, S2, S3, unofficial].

## How it works
**Inputs:**
- `coarse_model`: Trained coarse NeRF MLP [S1, unofficial].
- `fine_model`: Trained fine NeRF MLP [S1, unofficial].
- `pose`: 4x4 camera-to-world matrix (numpy or torch tensor) [S1, S2, unofficial].
- `K`: 3x3 camera intrinsic matrix (numpy or torch tensor) [S1, S2, unofficial].
- `H`, `W`: Image height and width in pixels [S1, S2, S3, unofficial].
- `near`, `far`: Near and far plane distances for ray marching [S1, S2, unofficial].
- `args`: Configuration object containing `chunk` (default 1024), `n_samples_coarse`, `n_samples_fine`, `white_bkgd`, `lindisp`, `netchunk`, `use_ndc` [S1, S3, unofficial].
- `gt_image`: Ground-truth RGB image for the target pose [S2, S3, unofficial].
- `device`: Torch device (CPU/GPU) [S1, unofficial].

**Outputs:**
- `rgb`: Rendered RGB image tensor of shape `[H, W, 3]` [S1, S2, unofficial].
- `depth`: Rendered depth map of shape `[H, W]` [S1, unofficial].
- `disp`: Rendered disparity map of shape `[H, W]` [S1, unofficial].
- `metrics`: Dictionary containing PSNR, SSIM, and optionally MSE [S2, S3, unofficial].

**Data Structures:**
- Rays are represented as two 2D tensors `rays_o` and `rays_d` of shape `[H*W, 3]` containing origins and directions [S1, unofficial].
- Results are stored in a dictionary with keys `rgb`, `depth`, and `disp`. If a fine model is used, keys may include `_fine` suffixes, falling back to `_coarse` if absent [S1, unofficial].

**Steps:**
1. **Initialization:** Set `coarse_model` and `fine_model` to evaluation mode (`model.eval()`) to disable dropout and batch normalization updates [S2, S3, unofficial]. Disable gradient computation using `torch.no_grad()` [S2, unofficial].
2. **Input Conversion:** Convert `pose` and `K` from numpy arrays to `torch.float32` tensors on the specified `device` if they are not already [S1, S2, unofficial].
3. **Ray Generation:** Compute ray origins and directions using the intrinsic matrix and camera pose:
   $$ \text{rays\_o}, \text{rays\_d} = \text{get\_rays}(H, W, K, \text{pose}) $$
   [S1, S3, unofficial]. Reshape these to `[-1, 3]` [S1, unofficial].
4. **NDC Conversion (Optional):** If `args.use_ndc` is true, convert rays to Normalized Device Coordinates:
   $$ \text{rays\_o}, \text{rays\_d} = \text{ndc\_rays}(H, W, \text{focal}, 1.0, \text{rays\_o}, \text{rays\_d}) $$
   [S1, unofficial].
5. **Chunked Rendering:** Process rays in chunks of size `chunk` (default 1024) to manage GPU memory [S1, S2, unofficial]. For each chunk:
   - Call the rendering function (e.g., `batchify_render` or `render_rays`) with `perturb=False` to ensure deterministic results [S1, S2, unofficial].
   - Pass `rays_o`, `rays_d`, `near`, `far`, sample counts (`n_samples_coarse`, `n_samples_fine`), and model parameters [S1, S3, unofficial].
   - Concatenate results from all chunks [S1, S2, unofficial].
6. **Result Reshaping:** Reshape the raw output tensors for `rgb`, `depth`, and `disp` to `[H, W, 3]`, `[H, W]`, and `[H, W]` respectively [S1, unofficial]. Move tensors to CPU and convert to numpy arrays [S1, S2, unofficial].
7. **Metric Calculation:**
   - **MSE:** Calculate Mean Squared Error between predicted RGB and ground truth [S2, S3, unofficial].
   - **PSNR:** Compute Peak Signal-to-Noise Ratio:
     $$ \text{PSNR} = -10 \cdot \log_{10}(\text{MSE}) $$
     [S3, unofficial].
   - **SSIM:** Compute Structural Similarity Index using `compare_ssim` with `full=True` and `multichannel=True` [S3, unofficial].
8. **Aggregation:** Append per-image metrics to lists. Calculate mean PSNR and mean SSIM across all test images [S3, unofficial].
9. **Visualization (Optional):** Create side-by-side images of Ground Truth and Prediction for qualitative assessment [S2, unofficial]. Save predicted RGB as PNG [S3, unofficial].

**Pseudocode:**
```python
import torch
import numpy as np
from skimage.metrics import structural_similarity as compare_ssim

def evaluate_nerf(coarse_model, fine_model, pose, K, H, W, near, far, args, gt_image, device):
    """
    Evaluate a trained NeRF on a single image pose.
    
    Args:
        coarse_model: Trained coarse NeRF model.
        fine_model: Trained fine NeRF model.
        pose: 4x4 camera-to-world matrix.
        K: 3x3 intrinsic matrix.
        H: Image height.
        W: Image width.
        near: Near plane distance.
        far: Far plane distance.
        args: Configuration arguments (chunk, n_samples_coarse, etc.).
        gt_image: Ground truth RGB image (numpy array [H, W, 3]).
        device: Torch device.
        
    Returns:
        rgb: Rendered RGB image (numpy array).
        depth: Rendered depth map (numpy array).
        disp: Rendered disparity map (numpy array).
        metrics: Dict with 'psnr', 'ssim', 'mse'.
    """
    # 1. Set models to eval mode and disable gradients
    coarse_model.eval()
    fine_model.eval()
    with torch.no_grad():
        # 2. Convert inputs to tensors
        if isinstance(pose, np.ndarray):
            pose = torch.from_numpy(pose).float().to(device)
        if isinstance(K, np.ndarray):
            K = torch.from_numpy(K).float().to(device)
            
        # 3. Generate rays
        rays_o, rays_d = get_rays(H, W, K, pose)
        rays_o = rays_o.reshape(-1, 3)
        rays_d = rays_d.reshape(-1, 3)
        
        # 4. NDC conversion if enabled
        if args.use_ndc:
            focal = K[0, 0]
            rays_o, rays_d = ndc_rays(H, W, focal, 1.0, rays_o, rays_d)
            
        # 5. Chunked rendering
        chunk = args.chunk if hasattr(args, 'chunk') else 1024
        all_rgb = []
        all_depth = []
        all_disp = []
        
        for i in range(0, rays_o.shape[0], chunk):
            chunk_o = rays_o[i:i+chunk]
            chunk_d = rays_d[i:i+chunk]
            
            # Call render function with perturb=False
            # This function handles coarse/fine sampling and alpha compositing
            result = batchify_render(
                chunk_o, chunk_d, 
                coarse_model, fine_model,
                near, far,
                args.n_samples_coarse, args.n_samples_fine,
                perturb=False,
                raw_noise_std=0.0,
                white_bkgd=args.white_bkgd,
                lindisp=args.lindisp,
                netchunk=args.netchunk
            )
            
            # Extract results based on keys
            rgb_key = 'rgb_fine' if 'rgb_fine' in result else 'rgb_coarse'
            depth_key = 'depth_fine' if 'depth_fine' in result else 'depth_coarse'
            disp_key = 'disp_fine' if 'disp_fine' in result else 'disp_coarse'
            
            all_rgb.append(result[rgb_key])
            all_depth.append(result[depth_key])
            all_disp.append(result[disp_key])
            
        # 6. Concatenate and reshape
        rgb_tensor = torch.cat(all_rgb, dim=0).reshape(H, W, 3)
        depth_tensor = torch.cat(all_depth, dim=0).reshape(H, W)
        disp_tensor = torch.cat(all_disp, dim=0).reshape(H, W)
        
        # Move to CPU and convert to numpy
        rgb = rgb_tensor.cpu().numpy()
        depth = depth_tensor.cpu().numpy()
        disp = disp_tensor.cpu().numpy()
        
        # 7. Calculate Metrics
        # Ensure gt_image is on device and normalized if necessary
        gt_tensor = torch.from_numpy(gt_image).float().to(device)
        if gt_tensor.dim() == 3:
            gt_tensor = gt_tensor.unsqueeze(0) # Add batch dim if missing
            
        # MSE
        mse_loss = torch.mean((rgb_tensor - gt_tensor) ** 2)
        mse = mse_loss.item()
        
        # PSNR
        psnr = -10.0 * np.log10(mse)
        
        # SSIM
        # SSIM expects values in [0, 1] or [-1, 1] depending on implementation
        # Assuming rgb is in [0, 1]
        ssim_val = compare_ssim(rgb, gt_image, data_range=rgb.max() - rgb.min(), multichannel=True)
        
        metrics = {
            'mse': mse,
            'psnr': psnr,
            'ssim': ssim_val
        }
        
    return rgb, depth, disp, metrics

def get_rays(H, W, K, pose):
    """
    Generate rays from camera intrinsics and pose.
    """
    # Standard ray generation logic
    i, j = torch.meshgrid(torch.linspace(0, W-1, W), torch.linspace(0, H-1, H))
    dirs = torch.stack([(i - K[0, 2]) / K[0, 0], -(j - K[1, 2]) / K[1, 1], -torch.ones_like(i)], dim=-1)
    
    # Rotate ray directions from camera frame to world frame
    # pose is c2w
    dirs = dirs.view(-1, 3)
    rays_d = torch.sum(torch.matmul(dirs.unsqueeze(1), pose[:3, :3].unsqueeze(0)).squeeze(1), dim=-1)
    rays_o = pose[:3, 3].expand_as(rays_d)
    
    return rays_o, rays_d

def ndc_rays(H, W, focal, near, rays_o, rays_d):
    """
    Convert rays to NDC space.
    """
    # Shift ray origins to near plane
    t = -(near + rays_o[..., 2]) / rays_d[..., 2]
    rays_o = rays_o + t.unsqueeze(-1) * rays_d
    
    # Projection
    o0 = rays_o[..., 0]
    o1 = rays_o[..., 1]
    o2 = rays_o[..., 2]
    
    d0 = rays_d[..., 0]
    d1 = rays_d[..., 1]
    d2 = rays_d[..., 2]
    
    rays_o = torch.stack([o0, o1, o2], dim=-1)
    rays_d = torch.stack([d0, d1, d2], dim=-1)
    
    # Normalize
    # ... (Implementation details omitted for brevity, standard NDC conversion)
    return rays_o, rays_d
```

**Parameters:**
- `chunk`: Integer, default 1024. Controls memory usage during ray processing [S1, S2, unofficial].
- `perturb`: Boolean, default `False` for evaluation. Disables random offsetting of sample points to ensure reproducibility [S2, unofficial].
- `white_bkgd`: Boolean. If true, composites against a white background; otherwise, transparent [S1, unofficial].
- `lindisp`: Boolean. If true, samples linearly in disparity space instead of depth [S1, unofficial].
- `netchunk`: Integer. Number of points to process per network forward pass [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Perturbation:** Must be disabled (`perturb=False`) during validation to ensure deterministic and reproducible results [S2, unofficial].
- **Memory:** Large images or high sample counts may exceed GPU memory; chunking is essential [S1, S2, unofficial].
- **NDC:** If using NDC coordinates, rays must be converted before rendering [S1, unofficial].
- **Background:** The `white_bkgd` parameter affects PSNR/SSIM if the ground truth has a specific background; mismatched backgrounds can artificially lower metrics [S1, unofficial].

## Subtopics

### [Masked Evaluation](7531-masked-evaluation.md)
Masked Evaluation restricts NeRF metric calculation (PSNR, SSIM) to pixels visible in at least two training views, preventing metric degradation from predicting unseen geometry or depth of single-view objects. It differs from unmasked evaluation by excluding regions where radiance fields memorize rather than predict scene content, which artificially inflates error metrics. It differs from feature-level occlusion handling by operating directly on rendered depth maps to guide RGBD inpainting or consistency losses.

### [MIMO Objective](10931-mimo-objective.md)
The MIMO objective is the total training loss function for MIMO-NeRF, combining pixel-wise reconstruction errors with a 3D consistency regularization term across multiple reformulated Multi-Input Multi-Output (MIMO) Neural Radiance Fields (NeRFs). It distinguishes itself from standard NeRF training by explicitly enforcing consistency between different "views" of the same scene generated by parallel MLPs with varying sampling densities, thereby enabling faster rendering without sacrificing quality. Unlike sibling methods that focus on evaluation metrics like PSNR or SSIM, this objective drives the optimization loop during training.

### [Text-Image Direction Score](13695-text-image-direction-score.md)
A quantitative metric estimating the similarity between text prompt changes and actual image changes using CLIP embeddings.

### [Standard Metric Computation](13741-standard-metric-computation.md)
Standard Metric Computation quantifies the photorealistic and perceptual quality of rendered NeRF images by comparing them against ground-truth data using PSNR, SSIM, and LPIPS. It differs from sibling methods by focusing on the post-processing stage: aggregating per-view scores into global statistics and structured reports, rather than performing the ray marching or the individual metric calculations themselves. It serves as the final quantitative step in the NeRF evaluation pipeline, ensuring that results from [PSNR Evaluation Pipeline](4315-psnr-evaluation-pipeline.md) and [Masked Evaluation](7531-masked-evaluation.md) are standardized for comparison.

### [Depth Supervision and Pseudo-Depth](13742-depth-supervision-and-pseudo-depth.md)
This family of techniques incorporates geometric constraints into the radiance field optimization loop to improve reconstruction quality, particularly in low-data regimes or when explicit geometry is required for downstream tasks. While standard NeRF optimization relies solely on photometric RGB losses, these methods introduce depth-related penalties or sampling strategies. Depth Supervision explicitly minimizes the difference between rendered depth and ground-truth depth (derived from SfM keypoints or stereo), whereas Pseudo-Depth approximates surface geometry via weighted averaging of sampled points to guide feature distillation or segmentation without requiring explicit depth labels.

#### LiDAR Semantic Filtering for Evaluation
Identifies LiDAR points that fall within the camera's field of view. Selects rays terminating on desired semantic classes (e.g., roads, sidewalks) using segmentation predictions from SegFormer. Feeds the filtered LiDAR rays into the NeRF model to perform depth rendering and predict the corresponding point cloud. Accumulates both the filtered LiDAR ground truth and the NeRF-predicted point clouds for each test frame to evaluate geometry reconstruction quality [S4].

#### Novel View Selection Policy
1. Generates initial synthetic training data $S_{new}$ by rendering RGB-D images with uncertainty estimation from various viewpoints using U-NeRF [S5].
2. Prunes views from $S_{new}$ if: (a) rendered depth < $z_{min}$ (too close); (b) large depth uncertainty (incorrect geometry); (c) large color uncertainty (noisy texture) [S5].
3. Applies pre-trained E-SCRNet (trained on real data $S_{real}$) to the remaining images in $S_{new}$ to get epistemic uncertainty maps and scene coordinate maps [S5].
4. Filters out unreliable pixels in the uncertainty maps using color and depth uncertainties from U-NeRF [S5].
5. Calculates the mean epistemic uncertainty for each image as a novel view score [S5].
6. Selects the top-k images with the highest scores to form the final novel view set $S_{high}$ [S5].

#### Nerfbusters Evaluation Protocol
An evaluation procedure for measuring NeRF quality at novel viewpoints by using two separate camera trajectories: one for training and one for evaluation [S6].
1. Records a video to capture the scene for the training split (10-20 seconds) [S6].
2. Records a second video from a different set of viewpoints for the evaluation split [S6].
3. Extracts images from both videos and computes camera poses for all images [S6].
4. Trains a 'pseudo ground truth' model on a combination of both training and evaluation splits, and saves depth, normal, and visibility maps for evaluation viewpoints [S6].
5. Optimizes a NeRF on the training split and evaluates at novel viewpoints using the captured evaluation images and the pseudo ground truth maps [S6].
**Pitfall:** Standard benchmarks evaluate only on held-out frames from the training sequence (e.g., every 8th frame), which does not reflect quality at extreme novel viewpoints [S6].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of pixels ($H \times W$) and the number of samples per ray ($N$). Chunking introduces overhead but prevents OOM errors [S1, S2, unofficial].
- **Memory Complexity:** Dominated by the storage of intermediate ray results during chunked processing. GPU memory usage scales with `chunk` size and model size [S1, S2, unofficial].
- **Measured Performance:** Depends heavily on hardware (GPU VRAM) and resolution. Typical chunk sizes of 1024 allow rendering 1080p images on consumer GPUs [S1, S2, unofficial].
- **Strengths:** Deterministic results (with `perturb=False`), modular metric calculation (PSNR/SSIM/LPIPS), supports various evaluation protocols (masked, novel view) [S1, S2, S3, unofficial][S6].
- **Limitations:** Standard metrics (PSNR/SSIM) may not correlate perfectly with perceptual quality; unmasked evaluation can be misleading for occluded regions [S1, S2, unofficial][S6].
- **When to Use:** Post-training validation, hyperparameter tuning, and benchmarking against other NeRF variants [S1, S2, S3, unofficial].
- **When Not to Use:** During active training (use training loss instead); for real-time interactive applications (use rasterization-based methods) [S1, S2, unofficial].

## Background
Originated with the introduction of Neural Radiance Fields (NeRF) by Mildenhall et al. in 2020 [S1, unofficial][S6]. The evaluation protocol has evolved from simple held-out frame comparison (e.g., every 8th frame) to more rigorous novel-view benchmarks like Nerfbusters, which use separate training and evaluation captures to assess generalization [S6]. Standard metrics like PSNR and SSIM became the de facto standard for comparing NeRF variants, alongside newer perceptual metrics like LPIPS [S1, S2, unofficial][S3, unofficial].
