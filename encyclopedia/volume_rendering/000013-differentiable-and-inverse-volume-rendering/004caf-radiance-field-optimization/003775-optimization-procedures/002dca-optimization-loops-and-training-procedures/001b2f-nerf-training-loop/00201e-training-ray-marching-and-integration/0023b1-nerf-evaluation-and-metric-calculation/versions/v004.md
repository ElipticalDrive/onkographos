# NeRF Evaluation and Metric Calculation

Also called: Evaluation and Metric Calculation, NeRF Evaluation, NeRF Validation, Single Image Rendering, Validation Rendering

## Overview
NeRF Evaluation and Metric Calculation renders a single image from a given camera pose using trained coarse and fine NeRF models, returning RGB, depth, and disparity maps [S1, S2, unofficial]. It solves the problem of quantifying rendering quality by comparing predicted images against ground truth references to compute validation metrics such as PSNR and SSIM [S2, S3, unofficial]. Unlike [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md), which performs stochastic sampling with perturbation for gradient-based optimization, this method uses deterministic rendering (perturb=False) to ensure reproducible results for performance reporting [S2, unofficial]. It builds on [NeRF Rendering (Alpha Compositing)](5124-nerf-rendering-alpha-compositing.md) by handling the post-processing, metric computation, and aggregation logic [S1, S2, unofficial].

## How it works
**Inputs:**
- `coarse_model`: Trained coarse NeRF model [S1, unofficial].
- `fine_model`: Trained fine NeRF model [S1, unofficial].
- `pose`: 4x4 camera-to-world matrix (numpy or torch tensor) [S1, S2, unofficial].
- `H`, `W`: Image height and width [S1, S3, unofficial].
- `K`: 3x3 camera intrinsic matrix (numpy or torch tensor) [S1, S2, unofficial].
- `near`, `far`: Near and far plane distances [S1, S3, unofficial].
- `args`: Configuration arguments containing `chunk` (default 1024), `n_samples_coarse`, `n_samples_fine`, `white_bkgd`, `lindisp`, `netchunk`, `use_ndc` [S1, S3, unofficial].
- `device`: Torch device [S1, unofficial].
- `gt_image`: Ground truth RGB image for metric calculation [S2, S3, unofficial].

**Outputs:**
- `rgb`: Rendered RGB image [H, W, 3] [S1, S2, unofficial].
- `depth`: Rendered depth map [H, W] [S1, unofficial].
- `disp`: Rendered disparity map [H, W] [S1, unofficial].
- `metrics`: Dictionary containing PSNR, SSIM, and optionally LPIPS [S3, S4, unofficial].

**Data Structures:**
- Rays are stored as tensors of shape `[-1, 3]` for origins (`rays_o`) and directions (`rays_d`) [S1, S3, unofficial].
- Results from `batchify_render` are dictionaries with keys `rgb`, `depth`, `disp` (or `_coarse`/`_fine` variants) [S1, unofficial].

**Steps:**
1. **Setup:** Set `coarse_model` and `fine_model` to evaluation mode (`model.eval()`) [S2, S3, unofficial].
2. **Pose Conversion:** If `pose` is a numpy array, convert it to a `torch.float32` tensor on the specified `device` [S1, S2, unofficial].
3. **Intrinsic Conversion:** If `K` is a numpy array, convert it to a `torch.float32` tensor on the `device` [S1, unofficial].
4. **Ray Generation:** Generate ray origins and directions using `get_rays(H, W, K_tensor, pose)` [S1, S3, unofficial].
5. **NDC Conversion (Optional):** If `args.use_ndc` is true, convert rays to Normalized Device Coordinates using `ndc_rays(H, W, focal, 1.0, rays_o, rays_d)` [S1, unofficial].
6. **Reshape Rays:** Flatten `rays_o` and `rays_d` to shape `[-1, 3]` [S1, S3, unofficial].
7. **Batched Rendering:** Call `batchify_render` with `rays_o`, `rays_d`, `chunk` size, models, bounds, sample counts, `perturb=False`, `raw_noise_std=0.0`, `white_bkgd`, `lindisp`, and `netchunk` [S1, S2, unofficial].
    - *Note:* `perturb=False` is critical to disable stochastic sampling jitter for deterministic evaluation [S2, unofficial].
8. **Result Extraction:**
    - Determine keys for `rgb`, `depth`, `disp` based on the presence of `'_fine'` in the result dictionary, falling back to `'_coarse'` if necessary [S1, unofficial].
    - Reshape `result[key]` to `[H, W, 3]` for RGB, `[H, W]` for depth, and `[H, W]` for disparity [S1, unofficial].
    - Move tensors to CPU and convert to numpy arrays [S1, S2, unofficial].
9. **Metric Calculation:**
    - Calculate Mean Squared Error (MSE) between predicted RGB and `gt_image` [S3, unofficial].
    - Calculate PSNR: $PSNR = -10 \cdot \log_{10}(MSE)$ [S3, unofficial].
    - Calculate SSIM using `compare_ssim` with `full=True` and `multichannel=True` [S3, unofficial].
    - (Optional) Calculate LPIPS using `lpips_module.lpips(render, gt, net_type="vgg").mean()` [S4, unofficial].
10. **Output:** Return `rgb`, `depth`, `disp`, and computed metrics [S1, S3, unofficial].

**Pseudocode:**
```python
import torch
import numpy as np

def evaluate_nerf(coarse_model, fine_model, pose, H, W, K, near, far, args, device, gt_image=None):
    """
    Render a single image and compute evaluation metrics.
    """
    # 1. Setup
    coarse_model.eval()
    fine_model.eval()
    
    # 2. Convert pose and K to tensors if necessary
    if isinstance(pose, np.ndarray):
        pose_tensor = torch.from_numpy(pose).float().to(device)
    else:
        pose_tensor = pose.to(device)
        
    if isinstance(K, np.ndarray):
        K_tensor = torch.from_numpy(K).float().to(device)
    else:
        K_tensor = K.to(device)
        
    # 3. Generate rays
    rays_o, rays_d = get_rays(H, W, K_tensor, pose_tensor)
    
    # 4. NDC conversion if enabled
    if args.use_ndc:
        focal = K_tensor[0, 0].item()
        rays_o, rays_d = ndc_rays(H, W, focal, 1.0, rays_o, rays_d)
        
    # 5. Reshape rays
    rays_o = rays_o.reshape(-1, 3)
    rays_d = rays_d.reshape(-1, 3)
    
    # 6. Batched rendering with perturb=False for deterministic results
    results = batchify_render(
        rays_o=rays_o,
        rays_d=rays_d,
        chunk=args.chunk,
        coarse_model=coarse_model,
        fine_model=fine_model,
        near=near,
        far=far,
        n_samples_coarse=args.n_samples_coarse,
        n_samples_fine=args.n_samples_fine,
        perturb=False,
        raw_noise_std=0.0,
        white_bkgd=args.white_bkgd,
        lindisp=args.lindisp,
        netchunk=args.netchunk
    )
    
    # 7. Extract results
    # Determine keys based on model structure
    if 'rgb_fine' in results:
        rgb_key, depth_key, disp_key = 'rgb_fine', 'depth_fine', 'disp_fine'
    else:
        rgb_key, depth_key, disp_key = 'rgb_coarse', 'depth_coarse', 'disp_coarse'
        
    rgb_tensor = results[rgb_key].reshape(H, W, 3).cpu().numpy()
    depth_tensor = results[depth_key].reshape(H, W).cpu().numpy()
    disp_tensor = results[disp_key].reshape(H, W).cpu().numpy()
    
    metrics = {}
    
    # 8. Compute metrics if ground truth is provided
    if gt_image is not None:
        # Ensure gt_image is on the same device and format for comparison
        gt_tensor = torch.from_numpy(gt_image).float().to(device)
        pred_tensor = torch.from_numpy(rgb_tensor).float().to(device)
        
        # MSE
        mse_loss = torch.mean((pred_tensor - gt_tensor) ** 2)
        
        # PSNR
        psnr = -10.0 * torch.log10(mse_loss)
        metrics['psnr'] = psnr.item()
        
        # SSIM
        # Assuming compare_ssim is available from a library like skimage or custom impl
        # Here we assume a standard implementation
        ssim_val = compare_ssim(rgb_tensor, gt_image, full=True, multichannel=True)
        metrics['ssim'] = ssim_val
        
        # LPIPS (Optional, depends on setup)
        # lpips_val = lpips_module.lpips(pred_tensor, gt_tensor, net_type="vgg").mean()
        # metrics['lpips'] = lpips_val.item()
        
    return rgb_tensor, depth_tensor, disp_tensor, metrics
```

**Parameters:**
- `chunk`: Default 1024 [S2, unofficial].
- `perturb`: False during validation [S2, unofficial].
- `raw_noise_std`: 0.0 during validation [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Perturbation:** Must be disabled (`perturb=False`) to ensure deterministic and reproducible results [S2, unofficial].
- **Data Types:** Ensure numpy arrays are converted to `torch.float32` tensors on the correct device before processing [S1, S2, unofficial].
- **Key Selection:** The result dictionary keys may vary (`_coarse` vs `_fine`); logic must handle fallbacks [S1, unofficial].
- **Background:** `white_bkgd` argument affects how transparent regions are composited; ensure consistency with ground truth background handling [S1, S2, unofficial].

## Subtopics

### [Unified Metric Aggregation](3644-unified-metric-aggregation.md)
Unified Metric Aggregation processes rendered images against ground truth references to compute, aggregate, and persist evaluation metrics for radiance field models. It solves the problem of standardizing performance reporting by converting raw per-pixel errors into standardized perceptual and structural scores (PSNR, SSIM, LPIPS) and organizing them into global averages and per-view dictionaries. Unlike [Metric Computation (PSNR, SSIM, LPIPS)](9928-metric-computation-psnr-ssim-lpips.md), which calculates raw per-pixel or per-tensor values for individual image pairs, this method aggregates those scores into summary statistics and structured output files. It builds on [NeRF Evaluation and Metric Calculation](3079-nerf-evaluation-and-metric-calculation.md) by handling the iteration, normalization, and final aggregation logic.

### [PSNR Evaluation Pipeline](4315-psnr-evaluation-pipeline.md)
The PSNR Evaluation Pipeline computes the Peak Signal-to-Noise Ratio (PSNR) on held-out test or validation splits to quantify the rendering quality of a trained NeRF model. It differs from training metrics by using inference-optimized rendering paths and explicitly handling background compositing to ensure fair comparison against ground truth images.

### [Masked Evaluation](7531-masked-evaluation.md)
Masked Evaluation is a procedure that restricts NeRF metric calculation (PSNR, SSIM) to pixels visible in at least two training views, preventing metric degradation from predicting unseen geometry or depth of single-view objects. It differs from unmasked evaluation by excluding regions where radiance fields memorize rather than predict scene content, which artificially inflates error metrics. It differs from feature-level occlusion handling by operating directly on rendered depth maps to guide RGBD inpainting or consistency losses.

### [MIMO Objective](10931-mimo-objective.md)
The total training objective combining pixel-wise loss and 3D consistency loss across M reformulated MIMO MLPs.

### Official Metrics Evaluation
This variant loads rendered and ground truth images as tensors, handling batched or unbatched formats based on the style [S4, unofficial]. It selects metric functions based on style: `standard_3dgs` uses `loss_utils.ssim` and `batched=True`; `beta_splatting` uses `fused_ssim` and `batched=False` [S4, unofficial]. It computes LPIPS using `lpips_module.lpips(render, gt, net_type="vgg").mean()` and checks that all metric values are finite [S4, unofficial]. Finally, it computes mean metrics across all views and saves them to `results.json` and `per_view.json` [S4, unofficial].

### Depth Supervision for TensoRF
TensoRF augmented with depth supervision derived from COLMAP keypoints to improve low-data performance [S5, unofficial]. It extracts 3D point locations and 2D pixel coordinates of COLMAP keypoints stored in the dataset [S5, unofficial]. It calculates rays $r(t) = o + td$ and depth $D$ from the projection origin using coordinate information and the camera matrix for the ground truth image [S5, unofficial]. It samples the model along these rays to calculate model estimated depths $\hat{D}$ [S5, unofficial]. The depth loss is calculated as $L_{\hat{D}} = \mathbb{E}_{r \in R(P)} ||\hat{D}(r) - D(r)||_2^2$, where $\hat{D}(r)$ is predicted depth and $D(r)$ is ground truth depth [S5, unofficial]. This is combined with the color loss $L_{\hat{C}}$ and a weighting hyperparameter $\lambda_i$ [S5, unofficial]. The dataset used is LLFF, consisting of 20-30 images of household/office environments captured with a smartphone in a grid pattern [S5, unofficial]. MSE loss was implemented as a baseline, despite DS-NeRF paper showing slightly better results with KL loss [S5, unofficial].

### LiDAR Semantic Filtering for Evaluation
This method identifies LiDAR points that fall within the camera's field of view [S6]. It selects rays terminating on desired semantic classes (e.g., roads, sidewalks) using segmentation predictions from SegFormer [S6]. It feeds the filtered LiDAR rays into the NeRF model to perform depth rendering and predict the corresponding point cloud [S6]. It accumulates both the filtered LiDAR ground truth and the NeRF-predicted point clouds for each test frame to evaluate geometry reconstruction quality [S6].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of pixels ($H \times W$) and the number of samples per ray [S1, S3, unofficial]. Chunked evaluation allows processing large images within memory limits [S2, unofficial].
- **Memory Complexity:** Proportional to the number of rays processed per chunk (default 1024) and the network size [S1, S2, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales linearly with image resolution and number of test views [S1, S3, unofficial].
- **Strengths:** Deterministic results due to disabled perturbation; comprehensive metric suite (PSNR, SSIM, LPIPS); supports various evaluation modes (masked, depth-supervised) [S2, S4, S5, unofficial][S6].
- **Limitations:** Computationally expensive for high-resolution images or large datasets; requires ground truth images for standard metrics; depth supervision requires additional COLMAP keypoints [S2, S5, unofficial].
- **When to use:** For validating trained NeRF models against held-out test sets or for comparing different NeRF variants [S2, S3, unofficial].
- **When not to use:** For real-time rendering applications where speed is prioritized over accuracy; for training where stochastic sampling is required [S2, unofficial].

## Background
NeRF Evaluation and Metric Calculation originated with the introduction of Neural Radiance Fields (NeRF) by Mildenhall et al. in 2020 [S1, S3, unofficial]. The method has been widely adopted in subsequent research for benchmarking novel view synthesis quality [S2, S4, S5, unofficial][S6]. It is commonly used in academic benchmarks such as Mip-NeRF 360, Tanks & Temples, and Deep Blending [S4, unofficial]. Variants like depth-supervised NeRF and LiDAR-integrated NeRF have extended the evaluation framework to include geometric accuracy metrics [S5, unofficial][S6].
