# Unified Metric Aggregation

Also called: Evaluation Reporting, Global and Per-view Metric Aggregation

## Overview
Unified Metric Aggregation processes the raw outputs of the [NeRF Evaluation and Metric Calculation](3079-nerf-evaluation-and-metric-calculation.md) pipeline to produce standardized performance statistics. It aggregates per-view metrics—specifically PSNR, SSIM, and LPIPS—into global averages and per-view dictionaries for final evaluation reporting. It distinguishes itself from sibling methods like the [PSNR Evaluation Pipeline](4315-psnr-evaluation-pipeline.md) by handling multi-metric consistency (including perceptual metrics like LPIPS) and enforcing strict data validation (shape matching, finiteness checks) before aggregation.

## How it works
**Inputs:**
- List of paired paths: `(render_path, gt_path)` for each test image.
- Iteration identifier (string, e.g., `"ours_10000"`).
- LPIPS intensity scale parameter (float, typically `[-1, 1]` or `[0, 1]`).

**Outputs:**
- Global metrics dictionary: `{"PSNR": float, "SSIM": float, "LPIPS": float}`.
- Per-view metrics dictionary: `{"image_name": {"PSNR": float, "SSIM": float, "LPIPS": float}}`.
- JSON files written to disk containing the above structures.

**Data Structures:**
- `per_view_metrics`: List of tuples `(image_name, psnr, ssim, lpips)`.
- `global_metrics`: Dictionary with keys `"PSNR"`, `"SSIM"`, `"LPIPS"`.

**Steps:**
1. Initialize `per_view_metrics` as an empty list.
2. Iterate over each pair `(render_path, gt_path)` in the input list.
3. Load `render_img` and `gt_img` from paths.
4. Normalize pixel values to range `[0, 1]`.
5. Convert images to CHW (Channel, Height, Width) tensor format.
6. Validate that `render_img.shape == gt_img.shape`. If not, raise an error or skip [G].
7. Compute PSNR between `render_img` and `gt_img`.
8. Compute SSIM between `render_img` and `gt_img`.
9. Compute LPIPS between `render_img` and `gt_img` using the specified intensity scale.
10. Validate that all computed metrics are finite (not NaN or Inf). If not, log warning or skip [G].
11. Append `(image_name, psnr, ssim, lpips)` to `per_view_metrics`.
12. After the loop, compute the arithmetic mean of all PSNR, SSIM, and LPIPS values in `per_view_metrics`.
13. Store means in `global_metrics`.
14. Write `global_metrics` and `per_view_metrics` to JSON files keyed by the iteration identifier.

**Parameters:**
- `intensity_scale`: Range of input pixel values for LPIPS. Typical value: `[-1, 1]` [S2].

**Edge Cases:**
- Shape mismatch between render and GT images: Must be handled explicitly (skip or error).
- Non-finite metrics (NaN/Inf): Occurs with perfect reconstruction (PSNR=Inf) or numerical instability.
- Empty input list: Results in empty dictionaries.

## Subtopics

### LPIPS Evaluation Protocol
Evaluates perceptual similarity using Learned Perceptual Image Patch Similarity (LPIPS). It differs from PSNR/SSIM by using deep network features. A critical variant detail is the intensity scale normalization: when inputs are in `[-1, 1]`, they must be scaled to `[0, 1]` before LPIPS computation to match the training distribution of the underlying VGG/AlexNet networks [S2]. Failure to apply this scale correction leads to incorrect LPIPS scores [S2].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of test images $N$. Each image requires independent metric computation.
- **Memory Complexity:** $O(N \cdot H \cdot W \cdot C)$ if all images are loaded simultaneously, or $O(H \cdot W \cdot C)$ if processed sequentially.
- **Strengths:** Provides a comprehensive view of quality (pixel-level, structural, perceptual). Standardized JSON output facilitates comparison across experiments.
- **Limitations:** LPIPS computation is computationally expensive compared to PSNR/SSIM. Requires careful handling of input normalization.
- **When to use:** Final evaluation of NeRF variants where perceptual quality is relevant.
- **When not to use:** Real-time feedback during training due to LPIPS cost.

## Background
Originated in the context of NeRF evaluation pipelines, specifically within repositories like Advanced3DGS [S1, unofficial]. It addresses the need for consistent reporting of multiple metrics (PSNR, SSIM, LPIPS) across different NeRF variants. The LPIPS component gained prominence in recent 3DGS evaluations (e.g., EVER, 3DGRT) where perceptual artifacts like "popping" are significant, necessitating correct intensity scaling for fair comparison [S2].
