# Block-NeRF

Also called: Block-based NeRF, Spatially Decomposed NeRF

## Overview
Block-NeRF is a method for city-scale NeRF-based reconstruction from street-level images that handles transient appearance and moving objects by dividing neighborhoods into overlapping blocks [S1]. It scales NeRF to city-scale scenes by spatially decomposing the environment into manageable blocks, training independent NeRFs per block, and compositing them at render time [S2, unofficial]. It sets itself apart from standard NeRF by enabling the processing of millions of images through spatial partitioning and from siblings like Zip-NeRF by using explicit spatial blocks with overlap rather than hierarchical frequency decomposition [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A large dataset of street-level images (e.g., 2.8 million images) with camera poses; semantic segmentation masks for transient objects [S1].
*   **Outputs:** A set of independent Block-NeRF models, one per spatial block, and a composite rendered image for a given viewpoint [S1][S2, unofficial].

**Data Structures:**
*   **Block Grid:** The scene is partitioned into spatial blocks (cells). Each block has an assigned overlap with neighboring blocks [S1].
*   **Block-NeRF Model:** Each block contains a NeRF module. The specific implementation uses mip-NeRF [48] with Integrated Positional Encoding (IPE) and NeRF-W [88] with appearance latent code optimization [S1].
*   **Visibility MLP:** A parallel MLP trained to predict visibility/transmissivity for each block [S1].
*   **Octree Cache:** A coarse rendering of densities and colors cached into an octree for culling [S1].

**Steps:**
1.  **Partitioning:** Divide the neighborhood/scene into spatial blocks with assigned overlaps [S1].
2.  **Masking:** Use semantic segmentation to mask out transient objects (pedestrians, cars) from the training images [S1].
3.  **Training:** Train a separate NeRF model for each block using only images with potentially relevant pixels [S1]. The model incorporates IPE and appearance latent codes [S1].
4.  **Visibility Prediction:** Train a visibility MLP in parallel. Supervise it using the transitivity function (Eq. 3 in source) and the density value generated by the NeRF MLP [S1].
5.  **Culling:** Use the visibility MLP to discard low-visibility Block-NeRFs during rendering [S1].
6.  **Rendering/Compositing:**
    *   Sample images from overlapping Block-NeRFs [S1].
    *   Perform appearance code matching optimization to align appearance codes across blocks [S1].
    *   Composite the outputs using inverse distance weighting [S1].

**Formulas:**
*   **Transitivity Supervision:** The visibility MLP is supervised using the transitivity function defined as Eq. (3) in the source [S1]. The exact formula for Eq. (3) is not provided in the text.
*   **Compositing:** Outputs are composited using inverse distance weighting [S1]. The exact weighting formula is not provided.

**Parameters:**
*   **Overlap:** Blocks are assigned an overlap, but the size is not given in the sources [S1].
*   **Dataset Size:** Demonstrated on 2.8 million street-level images [S1].

**Edge Cases and Pitfalls:**
*   **Transient Objects:** Handled by semantic segmentation masking [S1].
*   **Appearance Consistency:** Handled by appearance code matching optimization across overlapping blocks [S1].
*   **Visibility:** Low-visibility blocks are discarded using the visibility MLP [S1].

## Subtopics

### Mip-NeRF Integration
Uses Integrated Positional Encoding (IPE) for anti-aliased rendering within each block [S1]. Link: [Mip-NeRF](link-to-mip-nerf).

### NeRF-W Integration
Uses appearance latent code optimization to handle varying lighting conditions [S1]. Link: [NeRF-W](link-to-nerf-w).

### Visibility MLP
A parallel network for culling irrelevant blocks based on transitivity and density [S1].

## Operating characteristics
*   **Time Complexity:** Training is parallelized across blocks, reducing per-block training time. Rendering requires querying multiple blocks and compositing, which is faster than querying a single monolithic NeRF for city-scale scenes [S1][S2, unofficial].
*   **Memory Complexity:** Scales linearly with the number of blocks. Each block stores its own NeRF weights, leading to higher total memory usage than a single NeRF, but allows for city-scale scenes [S1][S2, unofficial].
*   **Measured Performance:** Demonstrated on 2.8 million street-level images for city-scale reconstruction (e.g., SF / Mission Bay) [S1][S2, unofficial].
*   **Strengths:** Handles city-scale scenes; manages transient objects; handles varying appearance via latent codes.
*   **Limitations:** Requires semantic segmentation for transient objects; complex compositing logic; higher total memory usage.
*   **When to use:** City-scale or large outdoor scenes with street-level imagery.
*   **When not to use:** Small-scale indoor scenes where a single NeRF is sufficient.

## Background
Block-NeRF was introduced in February 2022 by Tancik et al. [S1][S2, unofficial]. It was developed to address the challenges of city-scale NeRF-based reconstruction from large datasets of street-level images, such as transient appearance and moving objects [S1]. It builds on mip-NeRF [48] and NeRF-W [88] [S1]. Other influential methods for urban 3D reconstruction include S-NeRF [181] (April 2021) and BungeeNeRF [60] (December 2021), which use remote sensing images [S1].
