# Block-NeRF

Also called: Block-based NeRF, Spatially Decomposed NeRF

## Overview
Block-NeRF scales neural radiance fields to city-scale scenes by spatially decomposing the environment into manageable, overlapping blocks, training independent NeRF models for each block, and compositing them at render time [S1][S2, unofficial]. It differs from its siblings [Zip-NeRF Training Procedure](9538-zip-nerf-training-procedure.md) and [VaxNeRF](11379-vaxnerf.md) by relying on explicit spatial partitioning and visibility culling rather than hierarchical frequency encoding or voxel-based caching to handle large-scale transient artifacts and memory constraints [S1][S2, unofficial].

## How it works
**Inputs:** A large set of street-level images covering a city-scale neighborhood; camera poses for each image; semantic segmentation masks for transient objects (pedestrians, cars) [S1].
**Outputs:** A set of independent NeRF models (one per block) and a visibility prediction model; rendered images for a given viewpoint [S1][S2, unofficial].

**Data Structures:**
1.  **Block Grid:** The scene bounding box is partitioned into a grid of spatial blocks. Each block has an assigned overlap region with neighboring blocks [S1][S2, unofficial].
2.  **Per-Block NeRF:** Each block $b$ contains a NeRF model $\mathcal{F}_b$. Based on the source, each $\mathcal{F}_b$ is built upon the mip-NeRF architecture, utilizing Integrated Positional Encoding (IPE) [S1]. It also incorporates appearance latent codes optimized via the NeRF-W approach to handle lighting variations [S1].
3.  **Visibility MLP:** A separate multi-layer perceptron $\mathcal{V}$ predicts the visibility of each block for a given camera ray [S1].
4.  **Coarse Cache (Optional):** Some implementations cache coarse renderings of densities and colors into an octree to accelerate culling [S1].

**Algorithm Steps:**

1.  **Spatial Partitioning:** Divide the neighborhood into blocks with a defined overlap [S1][S2, unofficial].
2.  **Transient Masking:** For each training image, apply semantic segmentation masks to exclude pixels belonging to transient objects (e.g., cars, pedestrians) [S1].
3.  **Per-Block Training:**
    *   Assign each image to the blocks it overlaps.
    *   Train the NeRF model $\mathcal{F}_b$ for each block $b$ using only the images assigned to it and the masked pixels [S1].
    *   Optimize appearance latent codes for each image to handle dynamic lighting [S1].
4.  **Visibility Model Training:**
    *   Train the visibility MLP $\mathcal{V}$ in parallel with the NeRFs [S1].
    *   The loss function supervises $\mathcal{V}$ using a transitivity function (Eq. 3 in [S1]) and the density values generated by the NeRF MLP [S1].
    *   *Note:* The exact formula for Eq. (3) is not provided in the sources [S1].
5.  **Rendering (Compositing):**
    *   For a target camera viewpoint, identify all visible blocks [S2, unofficial].
    *   Use the Visibility MLP $\mathcal{V}$ to discard blocks with low visibility scores [S1].
    *   Sample colors and densities from the remaining Block-NeRFs [S1].
    *   Composite the samples from overlapping blocks using inverse distance weighting [S1].
    *   Apply appearance code matching optimization to align the color spaces of the overlapping blocks before compositing [S1].

```python
def train_block_nerf(images, poses, semantic_masks, block_grid):
    """
    Train independent NeRFs for each block in the grid.
    """
    block_models = {}
    visibility_mlp = init_mlp()
    
    # Initialize visibility MLP and per-block NeRFs
    for block_id in block_grid:
        block_models[block_id] = MipNeRFWithAppearanceCodes()
        
    # Training Loop
    for epoch in range(num_epochs):
        for image, pose, mask in zip(images, poses, semantic_masks):
            # 1. Mask transient objects
            valid_pixels = ~mask
            
            # 2. Determine overlapping blocks for this image
            overlapping_blocks = get_overlapping_blocks(pose, block_grid)
            
            # 3. Update Per-Block NeRFs
            for block_id in overlapping_blocks:
                # Extract pixels relevant to this block's spatial extent
                block_pixels = extract_pixels_for_block(image, valid_pixels, block_id)
                block_models[block_id].update(block_pixels, pose)
                
            # 4. Update Visibility MLP
            # Supervise using transitivity function and NeRF density
            # Note: Eq. (3) from source is not explicitly defined here
            visibility_loss = compute_visibility_loss(visibility_mlp, block_models, poses)
            visibility_mlp.update(visibility_loss)

    return block_models, visibility_mlp

def render_block_nerf(camera_pose, block_models, visibility_mlp, block_grid):
    """
    Composite outputs from visible blocks using inverse distance weighting.
    """
    # 1. Identify candidate blocks
    candidate_blocks = get_overlapping_blocks(camera_pose, block_grid)
    
    # 2. Filter by visibility
    visible_blocks = []
    for block_id in candidate_blocks:
        # Predict visibility of this block for the current ray/view
        vis_score = visibility_mlp.predict(camera_pose, block_id)
        if vis_score > visibility_threshold:
            visible_blocks.append(block_id)
            
    # 3. Composite
    final_color = 0.0
    final_alpha = 0.0
    
    for block_id in visible_blocks:
        # Sample from the specific block's NeRF
        color, alpha = block_models[block_id].render(camera_pose)
        
        # Appearance code matching optimization is applied here to align colors
        # [S1] mentions this step but does not provide the specific alignment formula
        color = apply_appearance_matching(color, block_id)
        
        # Inverse distance weighting for overlapping regions
        weight = compute_inverse_distance_weight(camera_pose, block_id, block_grid)
        
        final_color += color * weight * alpha
        final_alpha += alpha * weight
        
    return final_color / (final_alpha + epsilon)
```

**Parameters:**
*   **Block Overlap:** Not given in the sources.
*   **Visibility Threshold:** Not given in the sources.
*   **IPE:** Integrated Positional Encoding from mip-NeRF [S1].
*   **Appearance Codes:** Optimized per NeRF-W [S1].

**Edge Cases and Pitfalls:**
*   **Transient Objects:** Without semantic masking, moving objects cause ghosting artifacts in the static NeRF representation [S1].
*   **Boundary Artifacts:** Overlapping blocks can cause discontinuities if appearance codes are not matched; inverse distance weighting mitigates this but requires careful tuning [S1].
*   **Visibility Errors:** Incorrect visibility predictions can lead to missing blocks (holes) or double-rendering artifacts [S1].

## Operating characteristics
*   **Time Complexity:** Training is parallelizable across blocks, reducing per-block training time compared to a single global NeRF. Rendering requires querying multiple blocks and compositing, which is more expensive than a single NeRF query but cheaper than evaluating a global model over a vast domain [S1][S2, unofficial].
*   **Memory Complexity:** Scales linearly with the number of blocks. Each block stores its own MLP weights, allowing the system to handle scenes that would exceed GPU memory for a single global model [S1][S2, unofficial].
*   **Measured Performance:** Demonstrated feasibility on city-scale scenes (e.g., SF / Mission Bay) using 2.8 million street-level images [S1][S2, unofficial].
*   **Strengths:** Handles large-scale scenes; mitigates transient artifacts via masking; allows independent optimization of local details [S1][S2, unofficial].
*   **Limitations:** Requires semantic segmentation for best results; boundary artifacts between blocks; visibility prediction adds complexity [S1].
*   **When to use:** City-scale reconstruction from street-level imagery where memory constraints prevent global NeRF training [S1][S2, unofficial].
*   **When not to use:** Small-scale scenes where a single NeRF suffices; scenes with heavy occlusion where visibility prediction is unreliable [S1].

## Background
Block-NeRF was introduced in February 2022 by Tancik et al. [S1][S2, unofficial]. It was developed to address the challenges of city-scale NeRF-based reconstruction from large datasets (e.g., 2.8 million street-level images), specifically handling transient appearance and moving objects [S1]. It builds on mip-NeRF [48] and NeRF-W [88] [S1]. Other influential methods in this domain include S-NeRF (April 2021) and BungeeNeRF (December 2021), which also perform urban 3D reconstruction [S1].
