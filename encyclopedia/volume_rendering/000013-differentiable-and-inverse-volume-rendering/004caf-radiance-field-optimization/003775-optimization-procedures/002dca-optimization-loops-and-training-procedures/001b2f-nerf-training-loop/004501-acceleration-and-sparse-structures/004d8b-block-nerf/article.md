# Block-NeRF

Also called: Block-based NeRF, Spatially Decomposed NeRF

## Overview
Block-NeRF is a method for city-scale NeRF-based reconstruction from street-level images that handles transient appearance and moving objects by dividing neighborhoods into overlapping blocks [S1]. It scales NeRF to city-scale scenes by spatially decomposing the environment into manageable blocks, training independent NeRFs per block, and compositing them at render time [S2, unofficial]. It sets itself apart from standard NeRF by enabling the reconstruction of large outdoor environments (e.g., San Francisco's Mission Bay) that exceed the memory and computational limits of a single global model, while specifically addressing the challenge of transient objects (pedestrians, cars) common in street-level imagery [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A large dataset of street-level images (e.g., 2.8 million images) with known camera poses; semantic segmentation masks for transient objects [S1].
*   **Outputs:** A set of independent NeRF models (one per block) and a visibility prediction model; rendered images composited from visible blocks [S1][S2, unofficial].

**Data Structures:**
*   **Block Partition:** The scene is divided into spatial blocks with assigned overlap [S1].
*   **Per-Block NeRF:** Each block contains a NeRF module. The source specifies these are built on mip-NeRF [48] using Integrated Positional Encoding (IPE) and NeRF-W [88] using appearance latent code optimization [S1].
*   **Visibility MLP:** A parallel MLP trained to predict visibility [S1].
*   **Coarse Rendering Cache:** An octree caching coarse renderings of densities and colors [S1].

**Steps:**
1.  **Partitioning:** Divide the neighborhood into spatial blocks with an assigned overlap [S1].
2.  **Masking:** Use semantic segmentation to mask out transient objects (pedestrians, cars) from the training images [S1].
3.  **Training Per-Block NeRFs:** Train a separate NeRF model for each block. The model uses mip-NeRF's IPE and NeRF-W's appearance latent code optimization [S1].
4.  **Training Visibility MLP:** Train a visibility MLP in parallel. It is supervised using a transitivity function (Eq. 3 in source) and the density value generated by the NeRF MLP [S1].
5.  **Visibility Filtering:** Use the visibility MLP to discard low-visibility Block-NeRFs during rendering [S1].
6.  **Rendering and Compositing:**
    *   Sample images from overlapping Block-NeRFs [S1].
    *   Perform appearance code matching optimization [S1].
    *   Composite the outputs using inverse distance weighting [S1].

**Formulas:**
*   **Transitivity Supervision:** The visibility MLP is supervised using the transitivity function defined as Eq. (3) in the source [S1]. The specific formula for Eq. (3) is not provided in the text.
*   **Compositing:** Outputs are composited using inverse distance weighting [S1]. The specific weighting formula is not provided in the text.

**Parameters:**
*   **Overlap:** Blocks are assigned an overlap, but the size is not specified [S1].
*   **Dataset Size:** The method was demonstrated on 2.8 million street-level images [S1].

**Edge Cases and Pitfalls:**
*   **Transient Objects:** Standard NeRF fails with moving objects; this method requires semantic segmentation to mask them [S1].
*   **Visibility:** Low-visibility blocks must be discarded to avoid artifacts; this requires the parallel visibility MLP [S1].
*   **Appearance Consistency:** Overlapping blocks require appearance code matching optimization to ensure seamless compositing [S1].

## Operating characteristics
*   **Scalability:** Enables city-scale reconstruction (e.g., SF Mission Bay) which is infeasible for standard NeRF [S2, unofficial].
*   **Memory:** Reduces per-model memory footprint by training independent NeRFs per block [S2, unofficial].
*   **Complexity:** Rendering requires compositing multiple blocks, adding overhead compared to a single NeRF [S1].
*   **Strengths:** Handles large outdoor scenes; mitigates transient object artifacts via masking [S1].
*   **Limitations:** Requires semantic segmentation; requires visibility prediction to handle occlusion/visibility between blocks; appearance consistency across block boundaries is non-trivial [S1].

## Background
Block-NeRF was introduced in February 2022 by Tancik et al. [S1][S2, unofficial]. It was designed to address the challenges of city-scale NeRF-based reconstruction from street-level images, specifically handling transient appearance and moving objects [S1]. The method demonstrated feasibility on the SF / Mission Bay dataset [S2, unofficial]. It builds on mip-NeRF [48] and NeRF-W [88] [S1].
