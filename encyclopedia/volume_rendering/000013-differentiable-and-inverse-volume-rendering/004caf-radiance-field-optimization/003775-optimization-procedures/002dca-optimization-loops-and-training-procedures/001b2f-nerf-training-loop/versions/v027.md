# NeRF Training Loop

Also called: IPE (Interatomic Positional Encoding), Interatomic Positional Encoding, NeRF Optimization Loop, NeRF Training Procedure, Neural Radiance Field (NeRF) Training

## Overview
The NeRF Training Loop is the iterative optimization procedure that learns a continuous volumetric scene representation by minimizing the photometric error between rendered images and ground truth observations [S5, S6, unofficial][S8][S14, unofficial]. It solves the inverse rendering problem by updating the parameters of a coordinate-based neural network (MLP) via stochastic gradient descent [S5, S14, unofficial]. It sets itself apart from its siblings by defining the core dynamic sequence of ray sampling, differentiable volume rendering, and weight updates, whereas methods like [Training Configuration](2332-training-configuration.md) define static hyperparameters and [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md) define the forward pass mechanics [S1][S2, S4, unofficial][S8].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ training images with known camera poses (extrinsics $C$ and intrinsics $K$) and pixel colors. A neural network $f_\theta$ parameterizing the radiance field, mapping $(\mathbf{x}, \mathbf{d}) \to (\sigma, \mathbf{c})$.
*   **Outputs:** Optimized network weights $\theta$ and a trained radiance field.

**Data Structures:**
*   **Rays:** A batch of rays is represented as a tensor of shape $[B, 3, 3]$ or $[B, 6]$ (depending on implementation), where $B$ is the batch size ($N_{rand}$). The channels typically correspond to:
    1.  Ray Origin $(x, y, z)$ [S5, S14, unofficial].
    2.  Ray Direction $(x, y, z)$ [S5, S14, unofficial].
    3.  Target RGB Color $(r, g, b)$ [S5, S14, unofficial].
    *   In some implementations, rays are pre-computed into a flat array `rays_rgb` of shape $[(N-1) \cdot H \cdot W, 3, 3]$ containing all possible rays from the training set, shuffled for random access [S5, S14, unofficial].
*   **Checkpoint:** A dictionary containing `model` (state dict), `optimizer` (state dict), and `epoch` or `step` [S10, S11, unofficial].

**Numbered Steps:**

1.  **Initialization:**
    *   Load training and validation datasets [S8][S11, unofficial].
    *   Initialize the neural network $f_\theta$ (e.g., MLP with positional encoding) [S5, S11, unofficial].
    *   Initialize the optimizer (typically Adam) with learning rate $\eta$ [S5, unofficial][S8][S11, unofficial].
    *   Initialize a learning rate scheduler (e.g., Exponential Decay or Cosine Annealing) [S5, unofficial][S8][S11, unofficial].
    *   Pre-compute ray bundles for all training pixels if batching is enabled [S5, S14, unofficial].

2.  **Iteration Loop:** For iteration $i$ from 1 to $N_{iters}$:
    *   **Ray Sampling:**
        *   Select a batch of $N_{rand}$ rays. If using pre-computed rays, slice the `rays_rgb` array [S5, S14, unofficial]. If not, randomly select pixel coordinates from training images and generate rays using camera parameters [S4, S14, unofficial].
        *   If `precrop_iters` is active and $i <$ `precrop_iters`, restrict sampling to a central crop of the image [S2, S14, unofficial].
    *   **Forward Pass (Rendering):**
        *   For each ray in the batch, sample $N$ points along the ray segment $[t_{near}, t_{far}]$ [S5, S13, unofficial].
        *   Query the network $f_\theta$ at each point to obtain density $\sigma$ and color $\mathbf{c}$ [S5, S6, unofficial].
        *   Compute the rendered color $\hat{C}(\mathbf{r})$ using volume rendering equation (alpha compositing) [S5, S6, S14, unofficial].
        *   If a coarse-to-fine strategy is used, render a coarse image, sample additional points based on weights, and render a fine image [S5, S11, unofficial].
    *   **Loss Computation:**
        *   Compute the Mean Squared Error (MSE) between the rendered color $\hat{C}$ and the ground truth color $C_{gt}$ [S5, S6, S14, unofficial]:
            $$ \mathcal{L}_{RGB} = \frac{1}{B} \sum_{j=1}^B \| \hat{C}_j - C_{gt,j} \|^2 $$
        *   If coarse output $\hat{C}_{coarse}$ is available, add its MSE loss to the total loss [S6, S11, S18, unofficial]:
            $$ \mathcal{L}_{total} = \mathcal{L}_{RGB, fine} + \lambda_{coarse} \mathcal{L}_{RGB, coarse} $$
        *   [Optional] Add regularization terms (e.g., sparsity, Eikonal, Total Variation) if defined in configuration [S7, unofficial][S8][S16, unofficial].
    *   **Backpropagation:**
        *   Zero gradients: `optimizer.zero_grad()` [S18, unofficial].
        *   Compute gradients: `loss.backward()` [S18, unofficial].
        *   Update weights: `optimizer.step()` [S18, unofficial].
    *   **Learning Rate Update:**
        *   Update the learning rate according to the scheduler [S5, unofficial][S8][S11, unofficial].
        *   For Exponential Decay: $\eta_{new} = \eta_{old} \cdot \text{decay\_rate}^{(i / \text{decay\_steps})}$ [S5, S18, unofficial].
        *   For Cosine Annealing: $\eta_i = \eta_{min} + \frac{1}{2}(\eta_{max} - \eta_{min})(1 + \cos(\frac{i \cdot T}{T_{max}}))$ [S11, unofficial].
    *   **Logging and Checkpointing:**
        *   Log loss and PSNR every `log_every` steps [S11, unofficial].
        *   Render validation images every `render_every` steps [S11, unofficial].
        *   Save checkpoint every `save_every` steps [S11, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import DataLoader

def train_nerf_loop(model, train_dataset, val_dataset, config):
    """
    Main training loop for NeRF.
    
    Args:
        model: Neural Radiance Field model (MLP).
        train_dataset: Dataset containing images, poses, and intrinsics.
        val_dataset: Validation dataset.
        config: Configuration object with hyperparameters.
    """
    # 1. Initialization
    optimizer = optim.Adam(model.parameters(), lr=config.lr)
    scheduler = optim.lr_scheduler.ExponentialLR(optimizer, gamma=config.lr_decay_gamma)
    # Or CosineAnnealingLR depending on implementation [S11, unofficial]
    
    # Pre-compute rays if batching is used [S5, S14, unofficial]
    if config.use_batching:
        rays_rgb = precompute_rays(train_dataset) # Shape: [N_total_rays, 3, 3]
        rays_rgb = shuffle(rays_rgb)
        num_rays = rays_rgb.shape[0]
    
    n_iters = config.n_iters
    batch_size = config.batch_size # N_rand
    
    for i in range(1, n_iters + 1):
        start_time = time.time()
        
        # 2. Ray Sampling
        if config.use_batching:
            # Slice from pre-computed array [S5, S14, unofficial]
            indices = slice(i * batch_size, (i + 1) * batch_size)
            batch_rays = rays_rgb[indices] # Shape: [batch_size, 3, 3]
            
            # Handle wrap-around and shuffle [S5, S14, unofficial]
            if (i + 1) * batch_size >= num_rays:
                rays_rgb = shuffle(rays_rgb)
                batch_rays = rays_rgb[:batch_size]
        else:
            # Random pixel sampling [S4, S14, unofficial]
            batch_rays, target_colors = sample_random_rays(train_dataset, batch_size, config)
            
        # Split into origins, directions, and targets [S14, unofficial]
        # batch_rays shape: [batch_size, 3, 3] -> [origins, directions, targets]
        origins = batch_rays[:, 0, :]
        directions = batch_rays[:, 1, :]
        targets = batch_rays[:, 2, :]
        
        # 3. Forward Pass
        # Render rays using the model [S5, S6, S14, unofficial]
        # Returns rendered RGB, depth, transmittance, etc.
        outputs = model.render(origins, directions, config.near, config.far, config.n_samples)
        rendered_rgb = outputs['rgb']
        
        # If coarse-to-fine, also get coarse output [S5, S11, unofficial]
        if 'rgb_coarse' in outputs:
            coarse_rgb = outputs['rgb_coarse']
        else:
            coarse_rgb = None
            
        # 4. Loss Computation
        # MSE Loss [S14, S17, unofficial]
        mse_loss = nn.functional.mse_loss(rendered_rgb, targets)
        total_loss = mse_loss
        
        if coarse_rgb is not None:
            coarse_loss = nn.functional.mse_loss(coarse_rgb, targets)
            total_loss = total_loss + coarse_loss # Or weighted sum [S11, unofficial]
            
        # Add regularization if configured [S7, unofficial][S8][S16, unofficial]
        # total_loss += config.reg_weight * regularization_term(model)
        
        # 5. Backpropagation
        optimizer.zero_grad()
        total_loss.backward()
        optimizer.step()
        
        # 6. Learning Rate Update
        scheduler.step()
        
        # 7. Logging
        if i % config.log_interval == 0:
            psnr = compute_psnr(rendered_rgb, targets)
            print(f"Iter {i}: Loss={total_loss.item():.4f}, PSNR={psnr:.2f}")
            
        if i % config.save_interval == 0:
            save_checkpoint(model, optimizer, i, config.checkpoint_path)
            
        if i % config.val_interval == 0:
            validate(model, val_dataset, i)

def precompute_rays(dataset):
    """
    Pre-compute all rays from training images.
    Returns array of shape [N, 3, 3]: [origin, direction, target_rgb]
    """
    all_rays = []
    for img, pose, K in dataset:
        H, W = img.shape[:2]
        # Generate ray origins and directions for all pixels
        rays_o, rays_d = generate_rays(H, W, K, pose)
        # Flatten
        rays_o = rays_o.reshape(-1, 3)
        rays_d = rays_d.reshape(-1, 3)
        targets = img.reshape(-1, 3)
        
        # Stack into [N, 3, 3]
        batch = torch.stack([rays_o, rays_d, targets], dim=1)
        all_rays.append(batch)
        
    return torch.cat(all_rays, dim=0)

def generate_rays(H, W, K, c2w):
    """
    Generate ray origins and directions for a single image.
    """
    # Camera center
    cam_origin = c2w[:3, 3]
    
    # Ray directions
    # u, v are pixel coordinates
    u, v = torch.meshgrid(torch.arange(W), torch.arange(H), indexing='xy')
    u = u.float()
    v = v.float()
    
    # Inverse intrinsics to get direction in camera space
    # x = (u - cx) / fx, y = (v - cy) / fy, z = 1
    fx, fy = K[0, 0], K[1, 1]
    cx, cy = K[0, 2], K[1, 2]
    
    dirs = torch.stack([(u - cx) / fx, (v - cy) / fy, torch.ones_like(u)], dim=-1)
    dirs = dirs / torch.norm(dirs, dim=-1, keepdim=True)
    
    # Transform directions to world space
    # R is the rotation part of c2w
    R = c2w[:3, :3]
    dirs_world = torch.matmul(dirs, R.T)
    
    # Origins are the camera center for all rays
    origins = cam_origin.unsqueeze(0).unsqueeze(0).expand(H, W, 3)
    
    return origins, dirs_world
```

**Parameters:**
*   `lr` (Learning Rate): Default $5 \times 10^{-4}$ [S11, unofficial].
*   `batch_size` ($N_{rand}$): Number of rays per iteration. Typical values: 1024 or 2048 [S5, S11, unofficial].
*   `n_iters`: Total number of optimization steps. Default: 100,000 [S11, unofficial].
*   `n_samples`: Number of points sampled per ray. Default: 128 [S13, S17, unofficial].
*   `near`, `far`: Near and far clipping planes. For Blender dataset: near=2.0, far=6.0 [S2, S13, unofficial]. For LLFF: computed from bounding depths [S2, unofficial].
*   `decay_rate`: Factor for exponential decay. Default: 0.1 [S6, S18, unofficial].
*   `decay_steps`: Steps between decay. Calculated as `args.lrate_decay * 1000` [S5, S18, unofficial].
*   `chunk`: Maximum number of rays processed per forward pass to limit VRAM [S5, unofficial].

**Edge Cases and Pitfalls:**
*   **VRAM Overflow:** Rendering all rays at once can exceed GPU memory. Mitigated by chunking rays or using smaller batch sizes [S5, S15, unofficial].
*   **Instability in Growing Networks:** Directly initializing grown sub-networks randomly can cause density to drop to zero. Initialize new weights to match parent weights [S1].
*   **Gradient Computation Order:** Higher-order derivatives (for logging gradients/laplacians) must be computed *before* `loss.backward()` to avoid freeing the autograd graph [S3, unofficial].
*   **Checkpoint Resumption:** When resuming, the scheduler's last epoch must be set to `start_epoch - 1` to maintain correct scheduling [S9, unofficial].
*   **Empty Checkpoints:** If a checkpoint is loaded but the step is 0, it is considered invalid [S15, unofficial].

### ReconFusion
Uses a Diffusion Prior to constrain unobserved views [S21, unofficial].

### Supersampling Baseline
A baseline method for evaluating NeRF on multiscale data by training on full-resolution images and using brute-force supersampling during evaluation, or training on multiscale data with supersampling during both training and evaluation [S22]. For every pixel, cast multiple jittered rays sampled uniformly at random through the spatial footprint of the pixel. Render each ray with NeRF. Use the mean of those rendered values as the predicted color in the loss function [S22]. Oracle Scale Information: The full-resolution supersampling baseline relies on 'oracle' scale information that does not exist for most datasets [S22]. Performance: The 16x supersampling baseline performs worse than mip-NeRF and is significantly more expensive during both training and evaluation [S22].

### Two-stage training for proposers
A training schedule split into two equal-duration phases to stabilize learning of a trainable proposer network in NeRF-ID [S23, unofficial]. Phase 1: Train the learnt proposer to mimic the heuristic proposer by minimizing the L2 matching loss between their proposal sets [S23, unofficial]. Phase 2: Train all network components end-to-end. At the start of this phase, reset the optimizer state and perform a linear warmup for 1,000 steps to reduce shock from switching regimes [S23, unofficial]. Training from scratch sometimes works but often fails; two-stage training is consistently effective [S23, unofficial].

### Multi-view SDS
A plug-and-play method that creates multi-view supervision during SDS optimization to address the Janus problem caused by one-by-one view sampling [S24]. Rendered images from 4 sampled views are stitched into a large 2x2 image. Gradients are calculated under the condition of the multi-view normal map. The method converts a 3D asset into differentiable representations including NeRF, 3DGS, and DMTet through rendering supervision. The representations are then optimized to improve the quality of the 3D asset [S24].

### Guided NeRF Optimization for MVS
A multi-view depth estimation method that utilizes conventional reconstruction (sparse SfM+MVS) and learning-based priors over Neural Radiance Fields (NeRF). It performs test-time optimization directly over implicit volumes to eliminate the need for accurate pixel matching across views, addressing the shape-radiance ambiguity of NeRF in indoor scenes [S25]. Step 1: Run COLMAP on the test scene to acquire per-view sparse depth maps by projecting fused 3D point clouds after multi-view stereo. Step 2: Adapt a monocular depth network to the target scene by finetuning it on the sparse depth maps from COLMAP using a scale-invariant loss [S25].

### Surface-aware density formulation
A method to extract high-quality surfaces from NeRF by modeling geometry as a distance function or occupancy field and converting its output to density using a probability density function [S26]. Incorporate an eikonal term to encourage geometric consistency, enforcing that the gradient norm of the learned SDF is equal to one [S26]. Density distribution: $\Phi_S(x) = \frac{se^{-sx}}{1+e^{-sx}}$, where s is a scaling parameter and x is the SDF or occupancy value [S26].

## Operating characteristics
*   **Time Complexity:** $O(N_{iters} \cdot N_{rand} \cdot N_{samples} \cdot D)$, where $D$ is the network depth/width [S5, S14, unofficial].
*   **Memory Complexity:** $O(N_{rand} \cdot N_{samples})$ for storing intermediate rendering states per iteration [S5, S14, unofficial]. VRAM usage can be mitigated by chunking rays [S5, unofficial].
*   **Measured Performance:** Training typically requires 100,000 iterations [S11, unofficial]. For a 128x128 image, training may take 250 epochs [S4, unofficial]. With a batch size of 1024, ~7,800 iterations per epoch for 5 epochs results in ~39,000 total iterations [S17, unofficial].
*   **Scaling:** Scales with the number of training images and resolution. Larger scenes require more memory and time [S15, unofficial].
*   **Strengths:** High-quality novel view synthesis; differentiable end-to-end training.
*   **Limitations:** Slow training convergence; high memory usage for large scenes; prone to overfitting without regularization [S1][S17, unofficial].
*   **When to Use:** When high-fidelity novel views are required and computational resources are sufficient.
*   **When Not to Use:** For real-time applications or very large scenes without partitioning [S15, unofficial].

## Background
The NeRF Training Loop was introduced by Mildenhall et al. in "NeRF: Representing Scenes as Neural Radiance Fields for View Synthesis" (2020) [S5, S18, unofficial]. It builds on the concept of coordinate-based neural networks for implicit representations [S3, unofficial][S20]. The method has become a standard baseline for inverse volume rendering and has inspired numerous variants and extensions [S1][S2, S4, unofficial][S8].
