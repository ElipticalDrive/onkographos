# NeRF Training Loop

Also called: IPE (Interatomic Positional Encoding), Interatomic Positional Encoding, NeRF Optimization Loop, NeRF Training Procedure, Neural Radiance Field (NeRF) Training

## Overview
The NeRF Training Loop is the iterative optimization procedure that trains a coordinate-based neural network to represent a 3D scene as a continuous volumetric radiance field [S5, S6, S14, unofficial]. It solves the inverse problem of reconstructing geometry and appearance from a set of unstructured 2D images by minimizing the difference between rendered and ground-truth pixel colors [S5, S14, unofficial]. It sets itself apart from its siblings by defining the core stochastic gradient descent cycle—sampling rays, differentiable volume rendering, and weight updates—that serves as the foundation for all NeRF variants, including those with adaptive sampling [8870-adaptive-ray-sampling.md] or specific architectural extensions [8585-specific-model-architectures.md].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A dataset of $N$ training images with known camera poses (extrinsics) and intrinsics, and a neural network model $f_\theta$ (typically an MLP) parameterized by $\theta$.
*   **Outputs:** Updated network weights $\theta$ that minimize the reconstruction error.

**Data Structures:**
*   **Ray Bundle:** A tensor of shape $[B, 3]$ (or $[B, 5]$ if view directions are included) containing ray origins $\mathbf{o}$ and directions $\mathbf{d}$ for a batch of $B$ rays [S5, S14, unofficial].
*   **Target Colors:** A tensor of shape $[B, 3]$ containing the ground-truth RGB values for the sampled pixel coordinates [S5, S14, unofficial].
*   **Pre-computed Rays (Optional):** An array of shape $[(N-1) \cdot H \cdot W, 3, 3]$ storing flattened pixel indices, ray origins, ray directions, and target RGB values, pre-shuffled to enable efficient random batching [S5, S14, unofficial].

**Numbered Steps:**

1.  **Initialization:** Initialize the neural network weights $\theta$. For standard NeRF, weights are often initialized with small random values or specific schemes (e.g., SIREN initialization) [S3, S15, unofficial]. Initialize the optimizer (typically Adam) with a learning rate $\eta$ [S5, S11, unofficial]. If using a learning rate scheduler, initialize it (e.g., Exponential Decay or Cosine Annealing) [S5, S11, unofficial].
2.  **Ray Sampling:** For each iteration, sample a batch of $B$ rays. This is done by randomly selecting pixel coordinates from the training images and computing the corresponding ray origins and directions using the camera intrinsics and poses [S4, S5, S14, unofficial]. If pre-computed rays are used, slice the shuffled array [S5, S14, unofficial].
3.  **Forward Pass (Rendering):** For each ray in the batch, sample $K$ points along the ray segment between near and far bounds. Query the neural network $f_\theta$ at each point to obtain volume density $\sigma$ and color $\mathbf{c}$ [S5, S6, unofficial]. Compute the rendered color $\hat{C}$ using the differentiable volume rendering equation (alpha compositing) [S1][S5, S6, unofficial].
    *   If a coarse-fine training scheme is used, render a coarse image first, then sample additional points based on coarse weights for a fine render [S5, S11, unofficial].
4.  **Loss Computation:** Compute the loss $\mathcal{L}$ between the rendered colors $\hat{C}$ and the ground-truth target colors $C_{gt}$ [S5, S6, S14, unofficial]. The standard loss is Mean Squared Error (MSE) [S5, unofficial][S12][S14, unofficial]:
    $$
    \mathcal{L}_{MSE} = \frac{1}{B} \sum_{i=1}^B \| \hat{C}_i - C_{gt,i} \|^2
    $$
    Additional loss terms (e.g., coarse loss, regularization) may be added [S6, S11, S18, unofficial].
5.  **Backpropagation:** Compute the gradients of the loss with respect to the network parameters $\theta$ using automatic differentiation [S5, S18, unofficial].
    *   *Pitfall:* If higher-order derivatives (e.g., for logging gradients or Laplacians) are needed, they must be computed *before* calling `loss.backward()`, as the backward pass frees the computational graph [S3, unofficial].
6.  **Optimizer Step:** Update the network weights $\theta$ using the optimizer (e.g., Adam) [S5, S18, unofficial].
7.  **Learning Rate Update:** If a scheduler is used, update the learning rate based on the current step or epoch [S5, unofficial][S8][S11, unofficial].
8.  **Logging and Checkpointing:** Periodically log metrics (loss, PSNR) and save model checkpoints [S8][S11, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.optim as optim

def train_nerf_loop(model, optimizer, scheduler, dataloader, num_epochs, device):
    """
    Standard NeRF training loop.
    
    Args:
        model: Neural Radiance Field model (MLP).
        optimizer: Optimizer (e.g., Adam).
        scheduler: Learning rate scheduler (optional).
        dataloader: Iterator yielding batches of (rays, targets).
        num_epochs: Number of training epochs.
        device: Device to run training on ('cpu' or 'cuda').
    """
    mse_loss = nn.MSELoss()
    
    for epoch in range(num_epochs):
        model.train()
        for rays, targets in dataloader:
            # Move data to device
            rays = rays.to(device)      # Shape: [B, 3] or [B, 5]
            targets = targets.to(device) # Shape: [B, 3]
            
            # Zero gradients
            optimizer.zero_grad()
            
            # Forward pass: Render images from rays
            # model.render_rays returns predicted RGB colors
            # Implementation of render_rays is in [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md)
            predicted_colors = model.render_rays(rays) 
            
            # Compute loss
            loss = mse_loss(predicted_colors, targets)
            
            # Backward pass
            loss.backward()
            
            # Optimizer step
            optimizer.step()
            
            # Update learning rate if scheduler is provided
            if scheduler is not None:
                scheduler.step()
                
        # Optional: Validation and checkpointing logic here
```

**Parameters with Typical Values:**
*   **Learning Rate ($\eta$):** $5 \times 10^{-4}$ [S11, unofficial], $0.01$ [S17, unofficial], or defined in config [S8][S9, unofficial].
*   **Batch Size ($B$):** 1024 [S5, S11, unofficial], 2048 [S5, unofficial], 4096 [S17, unofficial].
*   **Number of Iterations:** 100,000 [S11, unofficial], 1,000,000 [S14, unofficial], or defined by epochs [S4, S17, unofficial].
*   **Positional Encoding Frequencies:** Position: 10 [S11, unofficial], Direction: 4 [S11, unofficial].
*   **Learning Rate Decay:** Exponential decay with rate 0.1 every 100,000 steps [S5, S18, unofficial], or Cosine Annealing [S11, unofficial].

**Edge Cases and Pitfalls:**
*   **VRAM Overflow:** Large batches or high-resolution images can exceed GPU memory. Mitigated by chunking ray batches during the forward pass [S5, S15, unofficial].
*   **Checkpoint Resumption:** When resuming, the optimizer state and scheduler state must be loaded correctly. The scheduler's last epoch should be set to `start_epoch - 1` to ensure correct scheduling [S9, unofficial].
*   **Empty Checkpoints:** Loading a checkpoint with step 0 should be handled as an error or treated as a fresh start [S15, unofficial].
*   **Instability in Growing Networks:** Directly growing a randomly initialized sub-network can cause density to collapse to zero. Weights of grown sub-networks should be initialized to match the parent network [S1].

### Supersampling Baseline
A baseline method for evaluating NeRF on multiscale data by training on full-resolution images and using brute-force supersampling during evaluation, or training on multiscale data with supersampling during both training and evaluation [S21]. For every pixel, multiple jittered rays are cast uniformly at random through the pixel's spatial footprint, rendered, and averaged [S21]. This method relies on 'oracle' scale information not available in most datasets and performs worse than mip-NeRF while being significantly more expensive [S21].

### Two-stage training for proposers
A training schedule split into two equal-duration phases to stabilize learning of a trainable proposer network in NeRF-ID [S22, unofficial]. Phase 1 trains the proposer to mimic a heuristic proposer by minimizing L2 matching loss between proposal sets. Phase 2 trains all components end-to-end, resetting the optimizer and performing a linear warmup for 1,000 steps to reduce shock from switching regimes [S22, unofficial]. This two-stage approach is consistently effective where training from scratch often fails [S22, unofficial].

### Multi-view SDS
A plug-and-play method that creates multi-view supervision during SDS optimization to address the Janus problem caused by one-by-one view sampling [S23]. Rendered images from 4 sampled views are stitched into a large 2x2 image, and gradients are calculated under the condition of the multi-view normal map [S23]. This converts a 3D asset into differentiable representations (NeRF, 3DGS, DMTet) optimized via rendering supervision [S23].

### Guided NeRF Optimization for MVS
A multi-view depth estimation method utilizing conventional reconstruction (sparse SfM+MVS) and learning-based priors over NeRF [S24]. It performs test-time optimization over implicit volumes to eliminate the need for accurate pixel matching across views, addressing shape-radiance ambiguity in indoor scenes [S24]. Step 1 runs COLMAP to acquire sparse depth maps; Step 2 adapts a monocular depth network to the target scene using scale-invariant loss [S24].

### Surface-aware density formulation
A method to extract high-quality surfaces from NeRF by modeling geometry as a distance function or occupancy field and converting its output to density using a probability density function [S25]. It incorporates an eikonal term to encourage geometric consistency, enforcing that the gradient norm of the learned SDF is equal to one [S25]. The density distribution is modeled as $\Phi_S(x) = \frac{se^{-sx}}{1+e^{-sx}}$, where $s$ is a scaling parameter and $x$ is the SDF or occupancy value [S25].

### Dynamically-informed iNeRF Estimator
A state estimation method that uses an iNeRF initialized with a dynamics prior, optimized only via photometric loss, acting as a recursive Bayesian filter with infinite state covariance [S26]. The process loss is set to 0 [S26]. An iNeRF estimator initialized without a dynamics prior will very quickly diverge [S26].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot K \cdot C)$ per iteration, where $N$ is the batch size (number of rays), $K$ is the number of samples per ray, and $C$ is the cost of the neural network forward pass [S5, S14, unofficial].
*   **Memory Complexity:** $O(N \cdot K)$ to store intermediate activations for backpropagation, which can be high for large batches or many samples [S5, unofficial]. Chunking reduces peak memory usage [S5, unofficial].
*   **Measured Performance:** Training on 128x128 images for 250 epochs [S4, unofficial]. On a dataset of 199 images, ~8M rays per epoch, with batch size 1024, resulting in ~7,800 iterations per epoch [S17, unofficial].
*   **Scaling:** Performance is limited by coarse voxel grid resolution and lack of advanced ray sampling in basic implementations, leading to blurry images [S17, unofficial]. Larger batch sizes (e.g., $2^{14}$) can hinder data loading performance, while smaller batches ($2^{10}$) cap iterations per second [S15, unofficial].
*   **Strengths:** Simple to implement, differentiable end-to-end, produces high-quality novel views.
*   **Limitations:** Slow convergence, high memory usage, sensitive to hyperparameters (learning rate, encoding frequencies), prone to overfitting and floaters without regularization.
*   **When to Use:** When high-quality novel view synthesis is required and computational resources are sufficient for iterative optimization.
*   **When Not to Use:** When real-time inference is required without pre-training, or when input views are extremely sparse and unregularized.

## Background
The NeRF Training Loop originates from the seminal paper "NeRF: Representing Scenes as Neural Radiance Fields for View Synthesis" by Mildenhall et al. (2020) [S5, S11, S14, unofficial]. It builds on the concept of coordinate-based neural networks for implicit representations [S3, unofficial]. The method was initially implemented in TensorFlow [S5, unofficial] and later ported to PyTorch [S6, S14, unofficial]. It has become the standard baseline for inverse volume rendering, inspiring numerous variants for adaptive sampling [8870-adaptive-ray-sampling.md], sparse views [9394-sparse-view-and-initialization-methods.md], and different representations [8585-specific-model-architectures.md].
