# NeRF-In Inpainting Optimization

Also called: Free-Form NeRF Inpainting with RGB-D Priors, NeRF object removal, NeRF-In

## Overview
NeRF-In is an optimization-based framework for removing unwanted objects from a pre-trained Neural Radiance Field (NeRF) without requiring category-specific training data or additional 3D supervision [S1, unofficial]. It solves the problem of "free-form" editing by updating the NeRF parameters $\Theta$ to minimize a joint loss function that combines color and depth guidance derived from 2D inpainting and depth completion priors [S1, unofficial]. Unlike inference-time interception methods that modify rendering queries, NeRF-In explicitly optimizes the underlying radiance field to reconstruct the scene geometry and appearance consistent with the removed object [S1, unofficial]. It distinguishes itself from sibling methods by relying on external 2D priors (inpainting/depth) rather than semantic feature fields or diffusion models to guide the 3D optimization [S1, unofficial].

## How it works

### Inputs and Outputs
*   **Inputs:**
    *   Pre-trained NeRF model $F_\Theta$ with parameters $\Theta$.
    *   User-chosen camera position $o_u$ and corresponding rendered image $I_u = F_{\Theta_{image}}(o_u)$.
    *   User-drawn mask $M_u$ on $I_u$, where $M_u = 1$ for pixels outside the masked region (background/valid) and $M_u = 0$ inside the masked region (object to remove) [S1, unofficial].
    *   A pre-set trajectory of camera positions $O = \{o_s \mid s = 1 \dots K\}$ (e.g., LLFF test-set trajectory) [S1, unofficial].
*   **Outputs:**
    *   Updated NeRF parameters $\tilde{\Theta}$ that represent the scene with the unwanted object removed [S1, unofficial].

### Data Structures
*   **NeRF Model $F_\Theta$:** A multi-layer perceptron (MLP) mapping 3D coordinates and viewing directions to density $\sigma$ and color $\mathbf{c}$. The implementation uses a coarse and fine model structure [S1, unofficial].
*   **Masks:** Binary masks $M_s$ for each sampled view $o_s$, generated via video object segmentation. $M_s = 1$ indicates valid/background pixels [S1, unofficial].
*   **Guidance Images:**
    *   Color guidance $I^G = \{I_s^G\}$: Inpainted images for sampled views.
    *   Depth guidance $D^G = \{D_s^G\}$: Completed depth images for sampled views.
    *   User guidance $I_u^G, D_u^G$: Inpainted color and depth for the user-chosen view [S1, unofficial].

### Numbered Steps

1.  **User Input:** The user selects a view $o_u$ from the pre-trained NeRF and draws a mask $M_u$ to specify the region containing the unwanted object. $M_u$ is defined such that $M_u=1$ for pixels outside the masked region [S1, unofficial].
2.  **View Sampling:** Sample $K$ camera positions $O = \{o_s \mid s = 1 \dots K\}$ along a pre-set trajectory. Render initial RGB images $I_s$ and depth images $D_s$ using the pre-trained NeRF $F_\Theta$ [S1, unofficial].
3.  **Mask Transfer:** Transfer the user-drawn mask $M_u$ to the sampled views to generate transferred masks $M = \{M_s \mid s = 1 \dots K\}$. This is achieved using a video object segmentation method (e.g., STCN) [S1, unofficial].
4.  **Guidance Generation:**
    *   Generate color guidance $I_s^G$ for each sampled view using a single-image inpainting method $\rho$: $I_s^G = \rho(I_s, M_s)$ [S1, unofficial].
    *   Generate depth guidance $D_s^G$ for each sampled view using a depth completion method $\tau$: $D_s^G = \tau(D_s, M_s, I_s^G)$ [S1, unofficial].
    *   Generate user-view guidance $I_u^G$ and $D_u^G$ similarly [S1, unofficial].
5.  **Loss Definition:** Define the optimization objective as the sum of color-guiding loss $L_{color}(\Theta)$ and depth-guiding loss $L_{depth}(\Theta)$ [S1, unofficial].
6.  **Optimization:** Optimize the NeRF parameters $\Theta$ to obtain $\tilde{\Theta}$ by minimizing the total loss for a specified number of steps (e.g., 50,000 steps) using the Adam optimizer [S1, unofficial].

### Formulas

**Volume Rendering:**
The expected color $\hat{C}(\mathbf{r})$ of a camera ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ is computed via numerical quadrature [S1, unofficial]:

$$
\hat{C}(\mathbf{r}) = \sum_{i=1}^{N} T(t_i) (1 - \exp(-\sigma(t_i)\delta_i)) c(t_i)
$$

where:
*   $N$ is the number of quadrature points sampled between near plane $t_n$ and far plane $t_f$.
*   $\delta_i = t_{i+1} - t_i$ is the distance between adjacent points.
*   $c(t_i)$ and $\sigma(t_i)$ are the color and density at point $t_i$ produced by $F_\Theta$.
*   $T(t_i) = \exp\left(-\sum_{j=1}^{i-1} \sigma(t_j)\delta_j\right)$ is the accumulated transmittance [S1, unofficial].

**Depth Rendering:**
The rendered depth $D_f(\mathbf{o}_s)$ is computed by accumulating density $\sigma$ from ray batches during volume rendering [S1, unofficial]. Both coarse ($D_c$) and fine ($D_f$) depth images are rendered for each sampled camera position [S1, unofficial].

**Color-Guiding Loss:**
The total color-guiding loss is the sum of an all-view loss and an outside-view loss [S1, unofficial]:

$$
L_{color}(\Theta) = L_{all\_color}(\Theta) + L_{out\_color}(\Theta)
$$

where:
*   $L_{all\_color}(\Theta)$ measures the color difference on the user-chosen view $o_u$ over the entire image:
    $$
    L_{all\_color}(\Theta) = \| F_{\Theta_{image}}(o_u) - I_u^G \|_2^2
    $$
*   $L_{out\_color}(\Theta)$ measures the color difference outside the mask on the sampled views $O$:
    $$
    L_{out\_color}(\Theta) = \sum_{o_s \in O} \| (F_{\Theta_{image}}(o_s) - I_s^G) \odot M_s \|_2^2
    $$
    where $\odot$ denotes element-wise multiplication [S1, unofficial].
*   Note: The framework sets $O_{all} = \{o_u\}$ and $O_{out} = O$ to maintain view consistency and avoid artifacts from multiple inpainted views [S1, unofficial].

**Depth-Guiding Loss:**
The depth-guiding loss measures the L2 distance between rendered fine/coarse depth images and the guiding depth for sampled camera positions [S1, unofficial]:

$$
L_{depth}(\Theta) = \sum_{o_s \in O} \left( \| D_f(o_s) - D_s^G \|_2^2 + \| D_c(o_s) - D_s^G \|_2^2 \right)
$$

where $D_f(o_s)$ and $D_c(o_s)$ are the fine and coarse depth images rendered from $o_s$ [S1, unofficial].

**Total Optimization Objective:**
$$
\tilde{\Theta} := \arg \min_{\Theta} \left( L_{color}(\Theta) + L_{depth}(\Theta) \right)
$$

### Parameters
*   **$K$:** Number of sampled camera positions/views used for inpainting guidance [S1, unofficial].
*   **Batch size:** 4,096 rays per optimization step [S1, unofficial].
*   **Sample points (Fine):** 128 points per ray [S1, unofficial].
*   **Sample points (Coarse):** 64 points per ray [S1, unofficial].
*   **Optimizer:** Adam [S1, unofficial].
*   **Training steps:** 50,000 steps for the inpainting optimization phase [S1, unofficial].
*   **Hardware:** Intel i7-7800X CPU and GTX-1080 GPU [S1, unofficial].

### Edge Cases and Pitfalls
*   **Masked MSE Only:** Optimizing only with masked Mean Squared Error (MSE) on the transferred masks without explicit guidance causes the unwanted object to remain in the result [S1, unofficial].
*   **Depth-Only Loss:** Using only the depth-guiding loss ($L_{depth}$) introduces color noise outside the masked region and loses color information in flat regions [S1, unofficial].
*   **Multiple Guidance Views:** Using multiple inpainted images as color guidance (i.e., including $I_s^G$ for $s \neq u$ in $L_{all\_color}$) introduces visual inconsistency between views [S1, unofficial]. The method restricts $L_{all\_color}$ to the user-chosen view only [S1, unofficial].
*   **Guidance Artifacts:** If the initial guidance materials (from inpainting/depth completion) contain artifacts, the optimized NeRF may output undesired results [S1, unofficial].

## Operating characteristics

*   **Time Complexity:** The optimization requires 50,000 steps. On an Intel i7-7800X CPU and GTX-1080 GPU, this takes approximately five hours per scene [S1, unofficial].
*   **Memory Complexity:** Depends on the NeRF model size and the batch size (4,096 rays). The coarse and fine models require storing parameters for density and color MLPs [S1, unofficial].
*   **Strengths:**
    *   Does not require category-specific training data or additional training procedures [S1, unofficial].
    *   Generates visually plausible inpainted results that maintain consistency across different views [S1, unofficial].
    *   Correctly reconstructs geometry using depth guidance [S1, unofficial].
*   **Limitations:**
    *   Relies on the quality of external 2D priors (inpainting and depth completion) [S1, unofficial].
    *   May struggle with large holes or high variance regions if the 2D priors fail [S1, unofficial].
    *   Baseline methods (per-view color updating or masked MSE retraining) result in incorrect depth maps, visual inconsistencies, or loss of fine structures [S1, unofficial].
*   **When to use:** When removing unwanted objects from a pre-trained NeRF without access to category-specific data or 3D ground truth, and when view consistency is critical.
*   **When not to use:** When high-quality 2D inpainting/depth completion tools are unavailable, or when real-time editing is required (optimization is slow).

## Background

*   **Origin:** NeRF-In was introduced by Hao-Kang Liu, I-Chao Shen, and Bing-Yu Chen in the paper "NeRF-In: Free-Form NeRF Inpainting with RGB-D Priors" [S1, unofficial].
*   **Date:** June 10, 2022 (arXiv:2206.04901v1) [S1, unofficial].
*   **Development:** It addresses the unintuitive nature of editing pre-trained NeRFs, where parameters are not explicitly associated with scene geometry/appearance. It builds on the concept of using 2D priors to guide 3D optimization, distinguishing itself from methods that require learning additional conditional radiance fields or segmentation networks [S1, unofficial].
*   **Usage:** Implemented in PyTorch and Python 3.9. Evaluated on the LLFF dataset and a custom dataset with 24 camera positions per scene [S1, unofficial].
