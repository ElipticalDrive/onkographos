# DONeRF Oracle Input Construction

Also called: Depth oracle inputs, Logarithmic input transformation

## Overview
This method constructs the input vector for the depth oracle network in DONeRF, which predicts sample locations for the subsequent shading network [S1]. It provides spatial context by supplying multiple 3D positions along the ray, enabling the oracle to classify depth ranges rather than predicting a single depth value [S1]. It sets itself apart from standard NeRF training by explicitly feeding discretized 3D positions with a logarithmic transformation aligned to the shading network's sampling strategy, omitting positional encoding [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Ray parameters (origin, direction, near/far bounds) and hyperparameters $I$ (number of input positions) and $N$ (number of classification bins) [S1].
*   **Output:** A vector of $I$ 3D positions passed to the first layer of the depth oracle network [S1].

**Data Structures:**
*   **Positions:** An array of $I$ 3D coordinates, each representing a point along the ray [S1].
*   **Encoding:** No positional or Fourier encoding is applied to these inputs [S1].

**Steps:**
1.  **Logarithmic Transformation:** Apply a logarithmic transformation to the ray's depth interval $[d_{\text{near}}, d_{\text{far}}]$ to align with the shading network's logarithmic sampling strategy [S1].
2.  **Discretize Depth Ranges:** Divide the logarithmic depth interval into $N$ discrete bins (classification steps) [S1].
3.  **Calculate Centers:** For each bin $j \in [0, N-1]$, compute the center depth in linear space, then convert to a 3D position $p_j$ along the ray [S1].
4.  **Construct Input Vector:** Select $I$ positions from the calculated centers (typically $I=N$) and concatenate them into a single vector of shape $(I, 3)$ [S1].

**Parameters:**
*   **$I$ (Number of input positions):** Tested values range from 1 to 128. The final configuration uses $I=128$ [S1].
*   **$N$ (Number of classification bins):** Tested values: 2, 4, 8, 16 [S1].

**Edge Cases and Pitfalls:**
*   **Positional Encoding:** Experiments showed that using positional or Fourier encoding for depth oracle inputs did not improve results and was therefore omitted [S1].
*   **Filter Size:** While not part of the input construction itself, using an excessively large filter size for neighborhood smoothing can reduce quality by placing samples in empty space [S1].

**Pseudocode:**
```python
import math

def construct_oracle_inputs(ray_origin, ray_direction, near, far, num_inputs):
    """
    Constructs the input vector for the DONeRF depth oracle.
    
    Args:
        ray_origin: list of 3 floats, ray origin coordinates.
        ray_direction: list of 3 floats, normalized ray direction.
        near: float, near plane distance.
        far: float, far plane distance.
        num_inputs: int, number of 3D positions to provide (I).
        
    Returns:
        list of lists, shape (num_inputs, 3), the input positions.
    """
    # Step 1: Logarithmic transformation of depth bounds
    log_near = math.log(near)
    log_far = math.log(far)
    
    # Step 2: Discretize depth ranges in log space
    log_step = (log_far - log_near) / num_inputs
    log_boundaries = [log_near + j * log_step for j in range(num_inputs + 1)]
    
    # Step 3: Calculate centers of discretized depth ranges
    log_centers = [(log_boundaries[j] + log_boundaries[j+1]) / 2.0 for j in range(num_inputs)]
    linear_centers = [math.exp(z) for z in log_centers]
    
    # Step 4: Calculate 3D positions along the ray
    positions = []
    for d in linear_centers:
        p = [ray_origin[k] + ray_direction[k] * d for k in range(3)]
        positions.append(p)
        
    return positions
```

## Subtopics

### [DONeRF* (360-degree variant)](8834-donerf-360-degree-variant.md)
A re-implementation of DONeRF adapted for 360-degree scenes, omitting the logarithmic sampling and warping techniques used in the original forward-facing implementation. It differs from standard NeRF by using a discrete classification-based volume representation derived from ground truth depth maps rather than continuous density fields. Choose this variant when rendering 360-degree object captures or arbitrary views outside a view cell.

## Operating characteristics
*   **Performance Gain:** Providing multiple samples along the ray as input adds approximately 1 dB to PSNR [S1].
*   **Comparison:** Using this classification-based oracle input instead of predicting a single depth value adds 0.6 dB–1.5 dB to PSNR [S1].
*   **Cost:** These improvements come at no inference cost for filtering or virtually no inference cost for ray unification and multi-input [S1].
*   **Limitations:** Using an excessively large filter size for neighborhood smoothing can reduce overall quality by placing samples in empty space [S1].

## Background
*   **Origin:** This method is part of the DONeRF architecture, introduced in "DONeRF: Towards Real‐Time Rendering of Compact Neural Radiance Fields using Depth Oracle Networks" [S1].
*   **Development:** It was developed to ease the task of the oracle network by supplying 3D positions along the ray at the centers of discretized depth ranges, aligning them with the shading network's logarithmic sampling [S1].
