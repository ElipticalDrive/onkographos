# Two-Stage Training for Learnable Proposer
## Overview
Two-Stage Training for Learnable Proposer divides network optimization into two distinct stages to resolve the chicken-and-egg problem inherent in learning to sample for radiance fields [S1, unofficial]. Training the proposer requires a good fine network to provide a useful training signal, but the fine network can only improve if sampled at informative locations [S1, unofficial]. This method sets itself apart from joint training approaches by decoupling proposer initialization from radiance field fine-tuning to ensure stable convergence [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of training images with known camera poses [G]. A coarse radiance field network ($N_c$) [S1, unofficial]. A fine radiance field network ($N_f$) [S1, unofficial]. A trainable proposer network ($P$) [S1, unofficial]. A heuristic proposer ($H$) (e.g., uniform or stratified sampling) [S1, unofficial].
*   **Outputs:** Optimized parameters for $N_c$, $N_f$, and $P$ [S1, unofficial]. Rendered images [G].

**Data Structures:**
*   **Proposals:** A set of 1D positions along the ray [G]. Let $N_c$ be the number of coarse samples and $N_f$ be the number of fine samples [G].
*   **Heuristic Proposals:** $Z_H$ generated by $H$ [S1, unofficial].
*   **Learned Proposals:** $Z_P$ generated by $P$ [S1, unofficial].

**Parameters:**
*   **Training Duration:** The number of SGD steps for Stage 1 equals the number of SGD steps for Stage 2 [S1, unofficial]. The total training time is kept constant to allow fair comparison with vanilla NeRF [S1, unofficial].

**Steps:**
1.  **Stage 1: Proposer Mimicry**
    1.  Train $N_c$ and $N_f$ using the heuristic proposer $H$ to generate samples $Z_H$, following vanilla NeRF training procedures [S1, unofficial].
    2.  Simultaneously train the trainable proposer $P$ to predict proposals $Z_P$ that match $Z_H$ [S1, unofficial].
    3.  Match the sets of proposals $Z_P$ and $Z_H$ in a greedy fashion for computational speed [S1, unofficial].
    4.  Minimize the sum of squared L2 distances between the greedily matched proposal pairs [S1, unofficial].
    5.  At the end of Stage 1, $N_c$ and $N_f$ match vanilla NeRF weights, and $P$ mimics $H$ [S1, unofficial].
2.  **Stage 2: End-to-End Optimization**
    1.  Swap the heuristic proposer $H$ with the learned proposer $P$ so the fine network receives samples from $P$ [S1, unofficial].
    2.  Train the entire system ($N_c$, $N_f$, $P$) end-to-end [S1, unofficial].
    3.  Minimize the reconstruction loss of the fine network to improve image quality [S1, unofficial].
    4.  Add the reconstruction loss of the coarse network to prevent divergence [S1, unofficial].
    5.  Optimize the coarse network to minimize its reconstruction loss AND produce features that enable $P$ to provide informative samples to $N_f$ [S1, unofficial].

**Pseudocode:**
```python
def two_stage_training(images, poses, N_c, N_f, num_steps_per_stage):
    # Initialize networks
    N_c = CoarseNetwork()
    N_f = FineNetwork()
    P = ProposerNetwork()
    H = HeuristicProposer() # e.g., uniform sampling

    # Stage 1: Mimic Heuristic Proposer
    for step in range(num_steps_per_stage):
        # 1. Train Coarse and Fine with Heuristic Proposer (Vanilla NeRF style)
        Z_H = heuristic_sample(poses, N_c)
        C_f, T_f = render(N_f, Z_H)
        loss_rec = compute_loss(C_f, images[step])
        
        # 2. Train Proposer to match Heuristic Proposer
        Z_P = propose(P, poses, N_c)
        Z_P_matched, Z_H_matched = greedy_match_1d(Z_P, Z_H)
        loss_prop = sum_squared_l2(Z_P_matched, Z_H_matched)
        
        # Total loss for Stage 1
        loss = loss_rec + loss_prop
        update_parameters([N_c, N_f, P], loss)

    # Stage 2: End-to-End Optimization with Learned Proposer
    for step in range(num_steps_per_stage):
        # 1. Generate samples using Learned Proposer
        Z_P = propose(P, poses, N_c)
        
        # 2. Render with Coarse and Fine networks using Z_P
        C_c, T_c = render(N_c, Z_P)
        C_f, T_f = render(N_f, Z_P)
        
        # 3. Compute reconstruction losses
        loss_fine = compute_loss(C_f, images[step])
        loss_coarse = compute_loss(C_c, images[step])
        
        # Total loss for Stage 2
        loss = loss_fine + loss_coarse
        update_parameters([N_c, N_f, P], loss)

def heuristic_sample(poses, N_c):
    # Standard uniform or stratified sampling along rays
    return sorted(random.uniform(0, 1, N_c))

def propose(P, poses, N_c):
    # Forward pass of trainable proposer to predict N_c positions
    return sorted(P.forward(poses, N_c))

def render(N, samples):
    # Standard volume rendering: query network at samples, accumulate color/alpha
    colors = [N.query(s) for s in samples]
    alphas = [0.5 for _ in samples] # Placeholder for standard alpha
    return accumulate(colors, alphas)

def compute_loss(rendered_color, target_image):
    # Standard L2 or L1 pixel-wise reconstruction loss
    return sum((rendered_color - target_image) ** 2)

def greedy_match_1d(Z_P, Z_H):
    # Sort both sets by position and match i-th to i-th for speed
    return sorted(Z_P), sorted(Z_H)

def sum_squared_l2(A, B):
    return sum((a - b) ** 2 for a, b in zip(A, B))

def update_parameters(networks, loss):
    # Standard gradient descent update
    for net in networks:
        net.zero_grad()
        loss.backward()
        net.step()
```

**Edge Cases and Pitfalls:**
*   **Training from Scratch:** Jointly training $N_c$, $P$, and $N_f$ from scratch can fail to reach good performance or fail badly (e.g., -5 PSNR on Blender: Ship) due to weak supervision (only final ray color) [S1, unofficial].
*   **Divergence:** In Stage 2, omitting the coarse network's reconstruction loss can lead to system divergence [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The total training time is kept constant compared to vanilla NeRF, as the two stages are of equal duration [S1, unofficial].
*   **Memory Complexity:** Requires storing parameters for $N_c$, $N_f$, and $P$ [S1, unofficial]. No additional significant memory overhead compared to standard NeRF, assuming the proposer architecture is lightweight [G].
*   **Strengths:** Solves the chicken-and-egg problem of learning to sample and prevents failure modes associated with joint training from scratch [S1, unofficial].
*   **Limitations:** Requires two distinct training phases and the proposer initially mimics a heuristic method which may not be optimal for the final radiance field [S1, unofficial].
*   **When to Use:** When training a learnable proposer for radiance field optimization, especially if joint training leads to poor convergence [S1, unofficial].

## Background
The method originates from research on learning to sample for view synthesis [S1, unofficial]. The proposer concept draws resemblance to two-stage object detectors such as Faster R-CNN, where a first network produces proposals and a second refines them [S1, unofficial]. Unlike object detection, radiance field training lacks direct supervision via object bounding box annotations, necessitating the two-stage approach [S1, unofficial]. The method also relates to DETR-inspired Transformer proposers [S1, unofficial].
