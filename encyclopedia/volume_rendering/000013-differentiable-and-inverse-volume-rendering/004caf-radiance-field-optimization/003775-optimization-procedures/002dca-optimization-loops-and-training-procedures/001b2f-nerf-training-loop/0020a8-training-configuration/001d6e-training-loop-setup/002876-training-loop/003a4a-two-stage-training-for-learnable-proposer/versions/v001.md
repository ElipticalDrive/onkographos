# Two-Stage Training for Learnable Proposer


## Overview
Two-Stage Training for Learnable Proposer is a training procedure that divides network optimization into two distinct stages to resolve the "chicken-and-egg" problem inherent in learning to sample for radiance fields: training the proposer requires a good fine network to provide a useful training signal, but the fine network can only become good if it is sampled at informative locations [S1, unofficial]. It sets itself apart from joint training approaches by decoupling the initialization of the proposer from the fine-tuning of the radiance field, ensuring stable convergence where end-to-end training might fail [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of training images with known camera poses; a coarse radiance field network ($N_c$); a fine radiance field network ($N_f$); a trainable proposer network ($P$); a heuristic proposer ($H$) (e.g., uniform or stratified sampling).
*   **Outputs:** Optimized parameters for $N_c$, $N_f$, and $P$; rendered images.

**Data Structures:**
*   **Proposals:** A set of 1D positions along the ray. Let $N_c$ be the number of coarse samples and $N_f$ be the number of fine samples.
*   **Heuristic Proposals:** $Z_H = \{z_1, ..., z_{N_c}\}$ generated by $H$.
*   **Learned Proposals:** $Z_P = \{z_1, ..., z_{N_c}\}$ generated by $P$.

**Parameters:**
*   **Training Duration:** The number of SGD steps for Stage 1 equals the number of SGD steps for Stage 2. The total training time is kept constant to allow fair comparison with vanilla NeRF [S1, unofficial].

**Steps:**

1.  **Stage 1: Proposer Mimicry**
    1.  Train $N_c$ and $N_f$ using the heuristic proposer $H$ to generate samples $Z_H$. This stage is identical to vanilla NeRF training.
    2.  Simultaneously train the trainable proposer $P$ to predict proposals $Z_P$ that match $Z_H$.
    3.  Match the sets of proposals $Z_P$ and $Z_H$ in a greedy fashion for computational speed [S1, unofficial].
    4.  Minimize the sum of L2 distances between the matching proposals:
        $$ \mathcal{L}_{prop} = \sum_{i=1}^{N_c} \| z_{P, i} - z_{H, i} \|_2^2 $$
        where $z_{P, i}$ and $z_{H, i}$ are the matched proposals [S1, unofficial].
    5.  At the end of Stage 1, $N_c$ and $N_f$ are identical to those trained in vanilla NeRF, and $P$ has learned to mimic $H$ [S1, unofficial].

2.  **Stage 2: End-to-End Optimization**
    1.  Swap the heuristic proposer $H$ with the learned proposer $P$. The samples seen by the fine network now come from $P$ [S1, unofficial].
    2.  Train the entire system ($N_c, N_f, P$) end-to-end.
    3.  Minimize the reconstruction loss of the fine network ($\mathcal{L}_{fine}$) to improve image quality [S1, unofficial].
    4.  Add the reconstruction loss of the coarse network ($\mathcal{L}_{coarse}$) to prevent divergence [S1, unofficial].
    5.  The coarse network is optimized to minimize its own reconstruction loss AND produce features that enable the proposer to provide informative samples to the fine network [S1, unofficial].

**Pseudocode:**

```python
def two_stage_training(images, poses, N_c, N_f, num_steps_per_stage):
    # Initialize networks
    N_c = CoarseNetwork()
    N_f = FineNetwork()
    P = ProposerNetwork()
    H = HeuristicProposer() # e.g., uniform sampling

    # Stage 1: Mimic Heuristic Proposer
    for step in range(num_steps_per_stage):
        # 1. Train Coarse and Fine with Heuristic Proposer (Vanilla NeRF style)
        # Generate heuristic samples
        Z_H = H.sample(poses, N_c)
        
        # Render coarse and fine colors
        C_c, T_c = N_c.render(Z_H)
        C_f, T_f = N_f.render(Z_H) # Note: N_f usually takes Z_H as input in Stage 1
        
        # Compute reconstruction loss for N_c and N_f
        loss_rec = compute_reconstruction_loss(C_f, images[step])
        
        # 2. Train Proposer to match Heuristic Proposer
        # Generate learned proposals
        Z_P = P.sample(poses, N_c)
        
        # Greedy matching between Z_P and Z_H
        Z_P_matched, Z_H_matched = greedy_match(Z_P, Z_H)
        
        # Compute proposal matching loss
        loss_prop = sum_l2_distance(Z_P_matched, Z_H_matched)
        
        # Total loss for Stage 1
        loss = loss_rec + loss_prop
        
        # Backpropagate and update N_c, N_f, P
        optimizer.step(loss)

    # Stage 2: End-to-End Optimization with Learned Proposer
    for step in range(num_steps_per_stage):
        # 1. Generate samples using Learned Proposer
        Z_P = P.sample(poses, N_c)
        
        # 2. Render with Coarse and Fine networks using Z_P
        C_c, T_c = N_c.render(Z_P)
        C_f, T_f = N_f.render(Z_P)
        
        # 3. Compute reconstruction losses
        loss_fine = compute_reconstruction_loss(C_f, images[step])
        loss_coarse = compute_reconstruction_loss(C_c, images[step])
        
        # Total loss for Stage 2
        # Coarse network is optimized for its own loss AND to help the proposer
        loss = loss_fine + loss_coarse
        
        # Backpropagate and update N_c, N_f, P
        optimizer.step(loss)

def greedy_match(Z_P, Z_H):
    # Simple greedy matching for speed
    # Sort both sets if necessary, or assign based on closest distance
    # This is a placeholder for the specific greedy algorithm used
    # Typically involves sorting by position and matching i-th to i-th
    Z_P_sorted = sort(Z_P)
    Z_H_sorted = sort(Z_H)
    return Z_P_sorted, Z_H_sorted
```

**Edge Cases and Pitfalls:**
*   **Training from Scratch:** Jointly training $N_c$, $P$, and $N_f$ from scratch can fail to reach good performance or fail badly (e.g., -5 PSNR on Blender: Ship) due to weak supervision (only final ray color) [S1, unofficial].
*   **Divergence:** In Stage 2, omitting the coarse network's reconstruction loss can lead to system divergence [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The total training time is kept constant compared to vanilla NeRF, as the two stages are of equal duration [S1, unofficial].
*   **Memory Complexity:** Requires storing parameters for $N_c$, $N_f$, and $P$. No additional significant memory overhead compared to standard NeRF, assuming the proposer architecture is lightweight.
*   **Strengths:** Solves the chicken-and-egg problem of learning to sample; prevents failure modes associated with joint training from scratch [S1, unofficial].
*   **Limitations:** Requires two distinct training phases; the proposer initially mimics a heuristic method which may not be optimal for the final radiance field [S1, unofficial].
*   **When to Use:** When training a learnable proposer for radiance field optimization, especially if joint training leads to poor convergence [S1, unofficial].
*   **When Not to Use:** If computational resources are extremely limited and a heuristic proposer suffices, or if the overhead of two-stage training is prohibitive [S1, unofficial].

## Background
The method was introduced in "NeRF in detail: Learning to sample for view synthesis" [S1, unofficial]. The "proposer" idea draws resemblance to two-stage object detectors such as Faster R-CNN [S1, unofficial], where a first network produces proposals and a second refines them. However, unlike object detection where proposal networks are trained with full supervision using object bounding box annotations, radiance field training lacks such direct supervision, necessitating the two-stage approach [S1, unofficial]. The method also relates to DETR-inspired Transformer proposers [S1, unofficial].
