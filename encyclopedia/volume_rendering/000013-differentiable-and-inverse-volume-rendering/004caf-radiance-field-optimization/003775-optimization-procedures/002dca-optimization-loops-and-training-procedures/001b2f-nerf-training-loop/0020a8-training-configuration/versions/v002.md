# Training Configuration

Also called: Hyperparameter Configuration, Instant-NGP Training Setup, NGP Training Configuration, Optimization Configuration, Optimizer Settings, Training Configuration & Optimization Setup, Training Hyperparameters

## Overview
Training Configuration defines the static and dynamic hyperparameters, optimizer settings, and initialization procedures required to optimize a radiance field model [S1, S2, S3][S4, unofficial]. It establishes baseline settings (MLP depth, width, positional encoding frequencies, and hierarchical sampling counts) against which variants adjust specific architectural or optimization details [S3, S5]. It differs from [Training Loop Setup](1522-training-loop-setup.md) by focusing on numerical values and mathematical schedules rather than procedural orchestration, and from [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md) by defining parameters that control sampling density and loss weighting rather than the integration algorithm itself [G].

## How it works
### Inputs and Outputs
**Inputs:**
- Dataset metadata (image resolution, camera poses, near/far planes) [S4, unofficial].
- Model architecture definition (MLP layers, grid resolutions, embedding sizes) [S2][S4, unofficial].
- Optimization targets (PSNR, SSIM, LPIPS) [S2, S5].

**Outputs:**
- Initialized optimizer state (momentum buffers, learning rates) [S1, S3][S4, unofficial].
- Training schedule parameters (iteration counts, decay schedules) [S3][S4, unofficial].
- Sampling configurations (step sizes, batch sizes, background colors) [S2][S4, unofficial].

### Data Structures
The configuration is typically stored in a namespace or dictionary object containing the following fields:

1.  **Optimizer Parameters:**
    - `lr0`: Initial learning rate for embeddings (e.g., $2 \times 10^{-2}$) [S4, unofficial].
    - `lr1`: Initial learning rate for networks (e.g., $10^{-3}$) [S4, unofficial].
    - `betas`: Tuple $(\beta_1, \beta_2)$, typically $(0.9, 0.99)$ [S1, S3][S4, unofficial] or $(0.9, 0.999)$ [S6, unofficial].
    - `eps`: Epsilon for numerical stability, typically $10^{-15}$ [S3][S4, unofficial] or $10^{-8}$ [S6, unofficial].
    - `weight_decay`: Multiplier, typically $10^{-9}$ [S3].

2.  **Sampling Parameters:**
    - `num_rays`: Number of rays sampled per image per step (e.g., 4096) [S4, unofficial].
    - `batch_size`: Number of points or rays processed per forward/backward pass (e.g., 512 points [S1], 216 [S3], 8192 rays [S2]).
    - `num_steps`: Number of steps sampled per ray (e.g., 512) [S4, unofficial].
    - `max_steps`: Maximum steps for CUDA raymarching (e.g., 1024) [S4, unofficial].
    - `delta`: Sampling step size, often set to half the voxel size $s(\cdot)$, i.e., $\delta(\cdot) = 0.5 s(\cdot)$ [S2].

3.  **Grid/Model Parameters:**
    - `resolution0`: Initial grid resolution (cubed), e.g., 128 [S4, unofficial].
    - `resolution1`: Target grid resolution (cubed), e.g., 300 [S4, unofficial].
    - `bound`: Scene bounding box half-width, e.g., 2 [S4, unofficial].
    - `density_thresh`: Threshold for density grid occupancy, e.g., 10 [S4, unofficial].
    - `dt_gamma`: Adaptive ray marching parameter, e.g., $1/128$ [S4, unofficial].

4.  **Loss Weights:**
    - $w_{\text{photo}}$: Photometric loss weight (e.g., 1) [S2].
    - $w_{\text{pt rgb}}$: Point-wise RGB regularization weight (e.g., $10^{-1}$ coarse, $10^{-2}$ fine) [S2].
    - $w_{\text{bg}}$: Background regularization weight (e.g., $10^{-2}$ coarse, $10^{-3}$ fine) [S2].

### Numbered Steps
1.  **Initialize Model:** Create the neural network (MLP) and voxel grids with specified resolutions and channel counts [S2][S4, unofficial].
2.  **Initialize Optimizer:** Instantiate Adam with specified betas and epsilon. Assign different learning rates to embeddings (`lr0`) and network weights (`lr1`) [S4, unofficial].
3.  **Initialize Scheduler:** Set up a learning rate scheduler (e.g., LambdaLR, Cosine Decay) to decay the learning rate over the total iterations `iters` [S3][S4, unofficial].
4.  **Configure Sampling:** Set the number of rays per step, steps per ray, and sampling step sizes based on voxel dimensions [S2][S4, unofficial].
5.  **Set Loss Weights:** Assign weights to photometric, regularization, and background loss terms based on the training stage (coarse vs. fine) [S2].
6.  **Initialize Trainer:** Combine model, optimizer, criterion, and scheduler into a Trainer object with specified metrics (e.g., PSNRMeter) and evaluation intervals [S4, unofficial].

### Formulas
- **Learning Rate Decay (LambdaLR):**
  $$ \text{lr}(iter) = \text{init\_lr} \times 0.1^{\min(\frac{iter}{\text{iters}}, 1)} $$
  This decays the learning rate to 10% of its initial value at the last iteration [S4, unofficial].

- **Exponential Interpolation for Upsampling:**
  Upsample resolutions are calculated using exponential interpolation between `resolution0` and `resolution1` over the number of upsample steps plus one [S4, unofficial]:
  $$ \text{res}_i = \exp\left( \text{linspace}(\ln(\text{resolution0}), \ln(\text{resolution1}), \text{len}(\text{upsample\_model\_steps}) + 1) \right)_i $$
  for $i > 0$ [S4, unofficial].

- **Randomized Query Shift:**
  During training, query points on a ray are shifted by:
  $$ p \cdot \delta(\cdot) \cdot \frac{d}{\|d\|_2} $$
  where $p \sim U[0, 1]$ and $d$ is the ray viewing direction [S2].

### Parameters with Typical Values
- **Iterations:** 25k [S3], 30k [S4, unofficial], 10k coarse + 20k fine [S2], 20k [S6, unofficial].
- **Batch Size:** 512 points [S1], 216 [S3], 8192 rays [S2], 4096 rays [S4, unofficial].
- **Learning Rates:** $10^{-3}$ for MLP [S2][S4, unofficial], $2 \times 10^{-2}$ for embeddings [S4, unofficial], $0.1$ for voxel grids [S2].
- **Background Color:** Random RGB from $[0, 1]^3$ during training [S5]; fixed $(0.5, 0.5, 0.5)$ at test time for 360/LLFF datasets [S5]; fixed white for Blender [S5].

### Edge Cases and Pitfalls
- **Precision:** Use `eps=10^{-15}` for Adam in some implementations to avoid division by zero in small gradients [S3][S4, unofficial], while others use $10^{-8}$ [S6, unofficial].
- **Boundaries:** The `bound` parameter assumes the scene is in $[-bound, bound]^3$. If `bound > 1`, adaptive ray marching is invoked [S4, unofficial].
- **Degenerate Input:** If `cuda_ray` is false, `num_steps` is used; if true, `max_steps` is used [S4, unofficial].
- **Memory:** Large batch sizes (e.g., 8192 rays) may require significant VRAM; half-precision (`fp16`) is often enabled to mitigate this [S4, unofficial].

### Pseudocode
```python
import torch
import torch.nn as nn
import torch.optim as optim
import numpy as np

class NeRFNetwork(nn.Module):
    def __init__(self, resolution, bound, cuda_ray, density_scale, min_near, density_thresh, bg_radius):
        super().__init__()
        self.resolution = resolution
        self.bound = bound
        self.cuda_ray = cuda_ray
        self.density_scale = density_scale
        self.min_near = min_near
        self.density_thresh = density_thresh
        self.bg_radius = bg_radius
        self.grid = nn.Parameter(torch.zeros(3, resolution[0], resolution[0], resolution[0]))
        self.mlp = nn.Sequential(nn.Linear(3, 128), nn.ReLU(), nn.Linear(128, 4))

    def get_params(self, lr0, lr1):
        return [
            {'params': self.grid.parameters(), 'lr': lr0},
            {'params': self.mlp.parameters(), 'lr': lr1}
        ]

class PSNRMeter:
    def __init__(self):
        self.reset()
    def reset(self):
        self.sum_psnr = 0.0
        self.count = 0
    def update(self, pred, target):
        mse = torch.mean((pred - target) ** 2)
        psnr = 10 * torch.log10(1.0 / mse)
        self.sum_psnr += psnr.item()
        self.count += 1
    def result(self):
        return self.sum_psnr / self.count if self.count > 0 else 0.0

class Trainer:
    def __init__(self, name, opt, model, device, workspace, optimizer, criterion, ema_decay, fp16, lr_scheduler, scheduler_update_every_step, metrics, use_checkpoint, eval_interval):
        self.name = name
        self.opt = opt
        self.model = model
        self.device = device
        self.workspace = workspace
        self.optimizer = optimizer
        self.criterion = criterion
        self.ema_decay = ema_decay
        self.fp16 = fp16
        self.lr_scheduler = lr_scheduler
        self.scheduler_update_every_step = scheduler_update_every_step
        self.metrics = metrics
        self.use_checkpoint = use_checkpoint
        self.eval_interval = eval_interval
        self.upsample_resolutions = []

    def train(self, train_loader, valid_loader, max_epoch):
        for epoch in range(max_epoch):
            self.model.train()
            for batch in train_loader:
                self.optimizer.zero_grad()
                pred = self.model(batch)
                loss = self.criterion(pred, batch.target)
                loss.backward()
                self.optimizer.step()
                if self.scheduler_update_every_step:
                    self.lr_scheduler.step()
            if (epoch + 1) % self.eval_interval == 0:
                self.evaluate(valid_loader)

    def evaluate(self, test_loader):
        self.model.eval()
        for metric in self.metrics:
            metric.reset()
        with torch.no_grad():
            for batch in test_loader:
                pred = self.model(batch)
                for metric in self.metrics:
                    metric.update(pred, batch.target)
        return {m.__class__.__name__: m.result() for m in self.metrics}

    def test(self, test_loader, write_video):
        self.evaluate(test_loader)

def initialize_training_configuration(opt):
    model = NeRFNetwork(
        resolution=[opt.resolution0] * 3,
        bound=opt.bound,
        cuda_ray=opt.cuda_ray,
        density_scale=1,
        min_near=opt.min_near,
        density_thresh=opt.density_thresh,
        bg_radius=opt.bg_radius
    )
    optimizer = torch.optim.Adam(
        model.get_params(opt.lr0, opt.lr1),
        betas=(0.9, 0.99),
        eps=1e-15
    )
    scheduler = optim.lr_scheduler.LambdaLR(
        optimizer,
        lambda iter: 0.1 ** min(iter / opt.iters, 1)
    )
    upsample_resolutions = (
        np.round(
            np.exp(
                np.linspace(
                    np.log(opt.resolution0),
                    np.log(opt.resolution1),
                    len(opt.upsample_model_steps) + 1
                )
            )
        ).astype(np.int32).tolist()[1:]
    )
    trainer = Trainer(
        name='ngp',
        opt=opt,
        model=model,
        device=torch.device('cuda' if torch.cuda.is_available() else 'cpu'),
        workspace=opt.workspace,
        optimizer=optimizer,
        criterion=torch.nn.MSELoss(reduction='none'),
        ema_decay=None,
        fp16=opt.fp16,
        lr_scheduler=scheduler,
        scheduler_update_every_step=True,
        metrics=[PSNRMeter()],
        use_checkpoint=opt.ckpt,
        eval_interval=50
    )
    trainer.upsample_resolutions = upsample_resolutions
    return trainer, optimizer, scheduler
```

## Subtopics

### [Training Loop Setup](1522-training-loop-setup.md)
Defines the procedural orchestration of the training loop, including data loading, forward/backward passes, and checkpoint management. It differs from Training Configuration by handling the execution flow rather than the numerical hyperparameter values.

### [Training Loop with Adaptive Regularization & LR Decay](2408-training-loop-with-adaptive-regularization-lr-decay.md)
Defines the iterative optimization procedure for training neural radiance fields, specifically focusing on the integration of adaptive regularization terms and exponential learning rate decay within the training loop. It solves the problem of stable convergence in high-dimensional implicit surface representations by combining reconstruction loss with structural priors (orthogonality, sparsity, and total variation) while gradually reducing the optimization step size. It builds on [NeRF Training Loop](970-nerf-training-loop.md) by specifying the exact loss composition and parameter update schedule.

### [Learning Rate Scheduling](2701-learning-rate-scheduling.md)
Learning rate scheduling adjusts the optimizer's step size during training to improve convergence stability and final reconstruction quality in radiance-field optimization [G]. It differs from static learning rates by dynamically scaling parameters based on training progress or structural changes, such as densification events. This method builds on [Training Configuration](2332-training-configuration.md) by defining the temporal evolution of the learning rate parameter [G].

### [Mixed Precision Training](2766-mixed-precision-training.md)
Mixed Precision Training accelerates NeRF optimization on CUDA devices by utilizing Automatic Mixed Precision (AMP) to perform computations in lower precision formats while maintaining numerical stability. It differs from standard single-precision training by automating precision casting and loss scaling within the PyTorch training loop.

### [Training Schedule](3154-training-schedule.md)
A training schedule defines the temporal progression of hyperparameters, loss functions, and structural updates during the optimization of differentiable volume rendering models [G]. It solves the problem of unstable convergence and inefficient resource usage by separating the optimization into distinct phases (e.g., warm-up, densification, refinement). Unlike static configurations, it dynamically alters the active loss terms and geometric primitives to handle sparse initialization and high-frequency detail recovery. It differs from [Learning Rate Scheduling](2701-learning-rate-scheduling.md) by controlling structural topology changes and loss activation, rather than just the step size of the optimizer [G].

### [Method-Specific Training Configurations](6267-method-specific-training-configurations.md)
Contains dataset- or architecture-specific hyperparameter overrides that deviate from the vanilla baseline. It solves the problem of poor generalization when applying default settings to specialized scenes or novel network topologies.

### [Regularization and Priors](6281-regularization-and-priors.md)
Defines additional loss terms and structural constraints applied during optimization to enforce physical plausibility or geometric smoothness. It solves the problem of noisy or overfit reconstructions by penalizing high-frequency artifacts and enforcing consistency priors.

### Randomized Background Colors
During training, drawing a random RGB background color from $[0,1]^3$ when compositing pixel color to encourage reconstruction of a fully opaque background, avoiding semi-transparent background artifacts [S5]. Test-time background color is set to $(0.5, 0.5, 0.5)$ [S5]. Used for the 360 dataset and the LLFF dataset; the Blender dataset uses a fixed white background [S5].

### Blender Dataset Simplified Configuration
For Blender dataset: one round of sampling, 128 samples for proposal MLP, 32 samples for NeRF MLP, proposal MLP with 4 layers and 256 hidden units, NeRF MLP with 8 layers and 256 (or 512) hidden units, axis-aligned IPE, MSE loss, no distortion regularizer [S5].

### Adam Optimisation with Adaptive Scaling
Standard PyTorch Adam optimisation with fused Adam on CUDA. Adaptive model capacity is handled via fixed-pool relocation, keeping optimiser tensor shapes constant [S6, unofficial]. Effective rate scaling for $D \le 3$: scaled by $P_D / P^2$, where $P_D = D + D(D+1)/2$ is the number of position and Cholesky parameters per splat (5 for 2D, 9 for 3D). For $D \ge 4$, additional factor $D^{0.8}$ accounts for larger spatial search [S6, unofficial]. Adam parameters: $\beta_1 = 0.9$, $\beta_2 = 0.999$, $\epsilon = 10^{-8}$ [S6, unofficial]. Base learning rate: 0.01. Follows reduce-on-plateau schedule (patience 15 iterations, factor 0.9, threshold $10^{-3}$, floor $10^{-8}$) [S6, unofficial]. Amplitude learning rate multiplier: 3× the dilution-compensated rate [S6, unofficial]. Position learning rate multiplier: 1.5× the dilution-compensated rate [S6, unofficial]. Iteration cap: 20,000 iterations. Early stopping patience: 500 iterations on regularised training loss [S6, unofficial].

### Checkpoint Loading and Resume Training
Load model and optimizer states from a checkpoint file to resume training or evaluation [S7, unofficial]. Steps: Load model state dictionary, Load optimizer state dictionary, Load gradient scaler state if used, Extract start iteration from checkpoint [S7, unofficial].

### LLFF Training Configuration
Distortion regularizer is not disabled. Charbonnier loss is used instead of MSE [S5]. On LLFF dataset with 256 hidden units: mip-NeRF achieves PSNR 26.93, SSIM 0.830, LPIPS 0.177, Time 2.48 hrs, Params 0.61M. Our Model achieves PSNR 26.68, SSIM 0.847, LPIPS 0.150, Time 2.39 hrs, Params 0.84M. On LLFF dataset with 512 hidden units: mip-NeRF achieves PSNR 27.01, SSIM 0.845, LPIPS 0.148, Time 6.15 hrs, Params 2.27M. Our Model achieves PSNR 26.86, SSIM 0.858, LPIPS 0.128, Time 3.84 hrs, Params 3.23M. Our model does not outperform mip-NeRF in PSNR, but yields improved SSIM and LPIPS metrics and a significant speedup when the NeRF MLP is large [S5].

### View Sampler
An abstract base class for sampling context and target views during training or inference, defining the interface for view selection strategies [S8, unofficial]. Parameters: stage (current training stage), is_overfitting (boolean flag), cameras_are_circular (boolean flag), step_tracker (optional tracker) [S8, unofficial]. Layout: Context view indices tensor shape: `Int64[Tensor, " context_view"]`, Target view indices tensor shape: `Int64[Tensor, " target_view"]` [S8, unofficial].

### Training Objective for Fine Representation
Use the same training losses as the coarse stage, but use a smaller weight for the regularization losses as it empirically leads to slightly better quality [S2].

## Operating characteristics
- **Time Complexity:** Training time varies significantly by configuration. Standard NeRF may take hours to days [S5]. Instant-NGP variants can converge in minutes [S2].
- **Memory Complexity:** Depends on grid resolution and batch size. Higher resolutions (e.g., $300^3$) and larger batch sizes (e.g., 8192 rays) increase VRAM usage [S2][S4, unofficial].
- **Measured Performance:** On LLFF dataset with 256 hidden units, Our Model achieves PSNR 26.68, SSIM 0.847, LPIPS 0.150 in 2.39 hours [S5]. On Blender dataset, Our Model achieves PSNR 32.65 for bicycle scene [S3].
- **Scaling:** Exponential interpolation for upsampling resolutions helps manage memory and convergence [S4, unofficial].
- **Strengths:** Flexible configuration allows tuning for specific datasets (Blender vs. LLFF vs. 360) [S5].
- **Limitations:** High VRAM requirements for large batches and resolutions [S2][S4, unofficial].
- **When to Use:** When optimizing a radiance field for novel view synthesis, requiring careful balance between convergence speed and reconstruction quality [G].
- **When Not to Use:** When real-time rendering is the primary goal without pre-training, or when computational resources are severely limited [G].

## Background
Originating from the NeRF paper [19], training configuration has evolved to include specialized optimizers, learning rate schedules, and sampling strategies for various datasets and architectures [S3, S5]. Key developments include Instant-NGP [21, 32], mip-NeRF 360 [3, 20], and Zip-NeRF [3, 20]. It is widely used in computer vision for 3D reconstruction and novel view synthesis [S1, S2].
