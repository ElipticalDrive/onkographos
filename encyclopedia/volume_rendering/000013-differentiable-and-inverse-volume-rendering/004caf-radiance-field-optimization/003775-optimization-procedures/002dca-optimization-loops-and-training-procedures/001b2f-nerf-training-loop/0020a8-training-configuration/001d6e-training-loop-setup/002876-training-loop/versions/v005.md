# Training Loop

Also called: NeRF Training Pipeline, RtStereoHumanModel Training Loop, Training Loop & Data Fetching

## Overview
The Training Loop is the iterative optimization procedure that updates a radiance field's parameters by minimizing the difference between rendered images and ground-truth observations. It solves the problem of converging a continuous or discrete scene representation from sparse 2D inputs. It sets itself apart from its siblings by orchestrating the data fetching, forward rendering, loss computation, and gradient-based parameter updates, often incorporating specific strategies like ray batching [2252-training-ray-batching.md] or diffusion guidance [8117-diffusion-based-guidance-for-radiance-field-optimization.md].

## How it works
The training loop executes a sequence of steps per iteration (or batch), typically involving data loading, forward pass, loss calculation, and backpropagation. The exact implementation varies by dataset and model architecture, but the core logic follows a standard optimization cycle.

### Inputs and Outputs
- **Inputs**: Training dataset (images, camera poses, intrinsics), model parameters (weights of MLPs, Gaussian attributes, or voxel grids), hyperparameters (learning rate, batch size, number of rays).
- **Outputs**: Updated model parameters, training metrics (loss, PSNR, SSIM).

### Data Structures
The specific data structures depend on the implementation. Common elements include:
- **Batch Data**: A dictionary or object containing tensors for images, camera parameters (position, orientation, intrinsics), and optional masks. These are typically moved to the GPU device.
- **Ray Batches**: If ray batching is used, rays are sampled from training images and stacked with their corresponding RGB values. The structure is a flat array of rays with colors [S3, unofficial].
- **Optimizer State**: Maintained by the optimizer (e.g., AdamW), including momentum and variance estimates for each parameter.

### Numbered Steps
1. **Data Fetching**:
   - Fetch a batch of data from the training loader. If using an iterator, handle `StopIteration` by resetting the iterator to `iter(train_loader)` [S2, unofficial].
   - Move all relevant data items (e.g., 'lmain', 'rmain' views) to the CUDA device [S1, unofficial].
   - Depending on the dataset type, load specific attributes:
     - **LLFF**: Load images, poses, bounds, and test indices. Set near/far clipping planes based on bounds (e.g., `near = min(bounds)*0.9`, `far = max(bounds)*1.0`) [S3, unofficial].
     - **Blender**: Load images, poses, and split indices. Set fixed near/far planes (e.g., `near=2.0`, `far=6.0`) [S3, unofficial].
     - **DeepVoxels**: Calculate near/far bounds based on hemisphere radius (e.g., `near = hemi_R - 1.0`, `far = hemi_R + 1.0`) [S3, unofficial].
     - **LINEMOD**: Load intrinsics $K$ and bounds [S3, unofficial].

2. **Forward Pass**:
   - Pass the data through the model with `is_train=True`.
   - If ray batching is enabled, prepare ray batches by stacking rays from training images, concatenating with RGB values, transposing, and reshaping into a flat array of rays with their corresponding colors [S3, unofficial].
   - Render the scene. For Gaussian Splatting, render using parameters like `bg_colour=(0.0, 0.0, 0.0)` and `img_size=(128, 128)` [S2, unofficial]. For NeRF, use `pts2render` with background color from config [S1, unofficial].
   - Get the rendered image, intermediate data, and metrics.

3. **Loss Calculation**:
   - Compute the total loss. A common formulation is:
     $$ \text{Total Loss} = 0.8 \cdot L1 + 0.2 \cdot (1 - \text{SSIM}) + 0.5 \cdot \text{Chamfer Loss} $$
     where $L1$ is the L1 loss between rendered and ground truth images, SSIM is the Structural Similarity Index, and Chamfer Loss is used for point cloud consistency if applicable [S1, unofficial].
   - If Chamfer Loss is enabled and iteration > `iter_from`, extract valid points from left and right xyz using valid masks, sample 10,000 points randomly from each side, and compute the chamfer distance [S1, unofficial].
   - For diffusion-based guidance, compute the score distillation sampling (SDS) loss or similar prior gradients [S8].

4. **Backpropagation**:
   - Scale the loss using `GradScaler` if mixed precision is enabled [S1, unofficial].
   - Perform the backward pass to compute gradients.
   - Unscale the optimizer.
   - Clip gradients to a norm of 1.0 [S1, unofficial].
   - Step the optimizer (e.g., AdamW) [S2, unofficial].
   - Step the learning rate scheduler (e.g., OneCycleLR with `pct_start=0.01`) [S1, unofficial].
   - Update the scaler [S1, unofficial].

5. **Logging and Validation**:
   - Accumulate losses (L1, SSIM, Chamfer, Scale) and print averages every 100 steps [S1, unofficial].
   - Log metrics to a logger [S1, unofficial].
   - If `total_steps % eval_freq == 0`, set the model to eval mode, run evaluation (e.g., `run_eval()`), and set the model back to train mode. Freeze BatchNorm in specific components like raft_stereo if applicable [S1, unofficial].

### Pseudocode
```python
def training_loop(model, train_loader, optimizer, scheduler, scaler, config):
    total_steps = 0
    train_iterator = iter(train_loader)
    
    while total_steps < config.num_steps:
        total_steps += 1
        
        # 1. Data Fetching
        try:
            data = next(train_iterator)
        except StopIteration:
            train_iterator = iter(train_loader)
            data = next(train_iterator)
            
        # Move data to CUDA
        for view in ['lmain', 'rmain']:
            if view in data:
                for item in data[view].keys():
                    data[view][item] = data[view][item].cuda()
        
        # 2. Forward Pass
        # Prepare ray batches if needed (implementation specific)
        # render_kwargs_train.update({'near': near, 'far': far})
        
        with torch.cuda.amp.autocast(enabled=config.mixed_precision):
            rendered_data, _, metrics = model(data, is_train=True)
            
            # Render scene (example for Gaussian Splatting)
            # img_pred = pts2render(rendered_data, bg_color=config.bg_color)
            
            # 3. Loss Calculation
            gt_img = data['lmain']['img'].cuda() # Example ground truth
            rendered_img = rendered_data['novel_view']['img_pred'].cuda()
            
            l1_loss = l1_loss(rendered_img, gt_img)
            ssim_loss = 1 - ssim(rendered_img, gt_img)
            
            total_loss = 0.8 * l1_loss + 0.2 * ssim_loss
            
            # Optional: Chamfer Loss
            if config.if_chamfer and total_steps > config.iter_from:
                # Extract valid points, sample, compute chamfer distance
                chamfer_loss = compute_chamfer_loss(rendered_data)
                total_loss += 0.5 * chamfer_loss
                
        # 4. Backpropagation
        scaler.scale(total_loss).backward()
        scaler.unscale_(optimizer)
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        scaler.step(optimizer)
        scaler.update()
        scheduler.step()
        optimizer.zero_grad()
        
        # 5. Logging
        if total_steps % 100 == 0:
            log_metrics(total_loss, l1_loss, ssim_loss)
            
        # 6. Validation
        if total_steps % config.eval_freq == 0:
            model.eval()
            run_eval(model, val_loader)
            model.train()
            if hasattr(model, 'raft_stereo'):
                model.raft_stereo.freeze_bn()
```

### Parameters
- **lr**: Learning rate for the optimizer (e.g., AdamW) [S1, unofficial].
- **wdecay**: Weight decay for the optimizer [S1, unofficial].
- **N_rand**: Number of random rays to sample per batch [S3, unofficial].
- **use_batching**: Boolean flag to enable ray batching [S3, unofficial].
- **pct_start**: Percentage of total steps for linear warmup in OneCycleLR scheduler, default 0.01 [S1, unofficial].
- **valCamerasCount**: Number of validation cameras, default 100 [S4, unofficial].
- **testCamerasCount**: Number of test cameras, default 200 [S4, unofficial].
- **grayLized**: Flag for grayscale rendering mode, default true [S4, unofficial].

### Edge Cases and Pitfalls
- **Iterator Reset**: Handle `StopIteration` by resetting the iterator to avoid crashes [S2, unofficial].
- **Near/Far Bounds**: Incorrect near/far clipping planes can lead to rendering artifacts or missing geometry. Ensure bounds are calculated correctly for each dataset type [S3, unofficial].
- **Gradient Clipping**: Clip gradients to prevent exploding gradients, especially in deep networks or with large learning rates [S1, unofficial].
- **Mixed Precision**: Use `GradScaler` to prevent underflow in mixed precision training [S1, unofficial].
- **BatchNorm Freezing**: In some architectures (e.g., Raft-Stereo), freeze BatchNorm layers during training to maintain stability [S1, unofficial].
- **Importance Predictor**: If using an importance predictor, apply a stop gradient to its input features to prevent trivial solutions where bad samples are predicted as unimportant [S5, unofficial].

## Subtopics

### [VCCNF Training Loop](4736-vccnf-training-loop.md)
The VCCNF Training Loop is a supervised optimization procedure for a Voxelized Continuous Coordinate Normalizing Flow (VCCNF). It learns to map Gaussian noise to shape latent codes conditioned on voxel data by minimizing the Mean Squared Error (MSE) between predicted and target latent codes.

### [MVDream Multi-View Diffusion Guidance](6345-mvdream-multi-view-diffusion-guidance.md)
MVDream Multi-View Diffusion Guidance provides gradient guidance for 3D optimization by encoding RGB images and camera poses into a multi-view diffusion model, predicting noise, and stepping the DDIM scheduler. It sets itself apart from single-view guidance methods by enforcing multi-view consistency through a multi-view diffusion prior.

### [Diffusion-Based Guidance for Radiance Field Optimization](8117-diffusion-based-guidance-for-radiance-field-optimization.md)
Diffusion-Based Guidance for Radiance Field Optimization, commonly known as Score Distillation Sampling (SDS), computes a gradient signal from a frozen 2D diffusion model (typically Stable Diffusion) to optimize a radiance field or 3D Gaussian representation. It solves the problem of generating 3D geometry from 2D text or image priors by backpropagating the difference between the diffusion model's predicted noise and the actual noise added to a rendered view. It sets itself apart from sibling methods like [MVDream Multi-View Diffusion Guidance](6345-mvdream-multi-view-diffusion-guidance.md) by relying on a single-view diffusion prior with classifier-free guidance rather than multi-view consistency losses, and from [VCCNF Training Loop](4736-vccnf-training-loop.md) by operating in the pixel/latent space of a pre-trained 2D model rather than a learned 3D latent space.

### [Two-Stage Training for Learnable Proposer](8685-two-stage-training-for-learnable-proposer.md)
Two-Stage Training for Learnable Proposer is a training procedure that divides network optimization into two distinct stages to resolve the "chicken-and-egg" problem inherent in learning to sample for radiance fields: training the proposer requires a good fine network to provide a useful training signal, but the fine network can only become good if it is sampled at informative locations. It sets itself apart from joint training approaches by decoupling the initialization of the proposer from the fine-tuning of the radiance field, ensuring stable convergence where end-to-end training might fail.

## Operating characteristics
- **Time Complexity**: Depends on the number of iterations, batch size, and rendering complexity. Ray batching can reduce memory usage but may increase overhead. Diffusion guidance adds significant computational cost due to multiple forward passes through the diffusion model [S8].
- **Memory Complexity**: Proportional to the number of parameters in the model and the batch size. Ray batching helps manage memory by processing fewer rays at a time [S3, unofficial].
- **Measured Performance**: Varies by dataset and hardware. For example, on DTU 3-view, AR-NeRF achieved a PSNR of 20.07 [S6]. Training time can range from hours to days depending on scene size and resolution [S9].
- **Scaling**: Scales with the number of GPUs for data parallelism. Ray batching allows for larger scenes by limiting memory usage per batch.
- **Strengths**: Flexible, supports various loss functions and regularization techniques. Can be combined with diffusion models for text-to-3D generation.
- **Limitations**: Computationally expensive, especially with diffusion guidance. Sensitive to hyperparameters like learning rate and near/far bounds.
- **When to Use**: Suitable for training radiance fields from multi-view images or text prompts. Use when high-quality novel view synthesis is required.
- **When Not to Use**: Not suitable for real-time applications without optimization (e.g., Instant-NGP). Avoid if computational resources are limited and diffusion guidance is used.

## Background
The training loop for NeRF and related radiance field methods originated from the seminal NeRF paper [S3, unofficial]. It has evolved to include various optimizations such as ray batching, adaptive loss weighting, and diffusion-based guidance. The method is widely used in 3D reconstruction, novel view synthesis, and 3D generation from text or images.
