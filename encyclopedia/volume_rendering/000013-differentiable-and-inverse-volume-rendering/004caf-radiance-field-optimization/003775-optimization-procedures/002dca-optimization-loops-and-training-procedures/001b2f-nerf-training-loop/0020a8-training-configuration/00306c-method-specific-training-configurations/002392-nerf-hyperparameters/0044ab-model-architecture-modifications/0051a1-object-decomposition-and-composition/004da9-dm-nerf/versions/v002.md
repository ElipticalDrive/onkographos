# DM-NeRF


## Overview
DM-NeRF is a single-pipeline method that simultaneously reconstructs continuous 3D scene geometry, decomposes all individual objects in 3D space, and supports flexible object shape manipulation (translation, rotation, size adjustment, deformation) from 2D images only [S1, unofficial]. It sets itself apart from standard NeRF variants by introducing an "object field" that predicts a one-hot object code for every 3D point, enabling instance-level decomposition without 3D ground truth labels [S1, unofficial]. Unlike [Unified Decompositional and Compositional NeRF](14413-unified-decompositional-and-compositional-nerf.md), which may handle composition differently, DM-NeRF focuses on decomposing the entire space into object fields and manipulating their geometries via a lightweight inverse query algorithm that explicitly tackles visual occlusions and collisions [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $L$ images for a static scene with known camera poses and intrinsics, denoted as $\{(I_1, \xi_1, K_1) \cdots (I_L, \xi_L, K_L)\}$ [S1, unofficial].
*   **Output:** Novel view rendered images, decomposed 3D object masks, and manipulated scene geometry [S1, unofficial].

**Data Structures and Layout:**
The network architecture consists of an MLP with the following layer dimensions: $128 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 128$ [S1, unofficial].
*   **Positional Encoding:** Inputs are encoded using $\text{PE}(x,y,z)$ for 3D location and $\text{PE}(\theta,\phi)$ for viewing direction [S1, unofficial].
*   **Object Prediction Tensor:** For each view, the network outputs a tensor $I_l \in \mathbb{R}^{U \times V \times (H+1)}$, where $U, V$ are spatial width and height, and $H$ is the predefined number of objects [S1, unofficial]. The first $H$ channels represent object predictions, and the $(H+1)$-th channel represents empty space [S1, unofficial].
*   **Ground Truth Label Tensor:** Paired ground truth labels are $\bar{I}_l \in \mathbb{R}^{U \times V \times T}$, where $T$ is the number of ground truth objects [S1, unofficial].

**Network Outputs:**
For a query point $p=(x,y,z)$ and viewing direction $v=(\theta,\phi)$:
1.  **Volume Density ($\sigma$):** Function of location only.
2.  **Object Code ($o$):** A one-hot vector of length $H+1$, representing the object ID for the point. Function of location only.
3.  **Color ($c$):** RGB vector, function of location and viewing direction [S1, unofficial].

**Training Steps:**
1.  **Positional Encoding:** Compute $\text{PE}(x,y,z)$ and $\text{PE}(\theta,\phi)$ for the query point and direction [S1, unofficial].
2.  **Forward Pass:** Feed encoded inputs into the MLP to predict $\sigma$, $o$, and $c$ [S1, unofficial].
3.  **Volume Rendering:** Render the 2D image color using standard volume rendering integration over the ray, using $\sigma$ and $c$ [S1, unofficial].
4.  **2D Object Matching:**
    *   Reshape the first $H$ channels of the predicted tensor $I_l$ to $M \in \mathbb{R}^{N \times H}$, where $N = U \times V$ [S1, unofficial].
    *   Reshape the ground truth tensor $\bar{I}_l$ to $\bar{M} \in \mathbb{R}^{N \times T}$ [S1, unofficial].
    *   Compute the Soft Intersection-over-Union (sIoU) cost matrix $C^{sIoU}_{h,t}$ between predicted and ground truth masks [S1, unofficial].
    *   Compute the Cross-Entropy Score (CES) [S1, unofficial].
    *   Use the Hungarian algorithm to associate every ground truth 2D object mask with a unique predicted 2D object mask based on sIoU and CES [S1, unofficial].
5.  **Loss Computation:**
    *   Compute color reconstruction loss against ground truth images [S1, unofficial].
    *   Compute object field losses, including $\ell_{3d}^{empty}$ and $\ell_{3d}^{obj}$, to jointly learn correct codes for empty 3D points and object points [S1, unofficial].
6.  **Optimization:** Update network weights using the combined loss [S1, unofficial].

**Object Manipulation:**
1.  **Specify Target:** Select an object ID and transformation parameters (translation, rotation, scale, deformation) [S1, unofficial].
2.  **Inverse Query:** Use a lightweight inverse query algorithm to identify the 3D points belonging to the specified object [S1, unofficial].
3.  **Tackle Visual Occlusions:** Explicitly handle occluded regions and collisions during the editing process to avoid artifacts [S1, unofficial].
4.  **Edit Geometry:** Apply the transformation to the identified object points [S1, unofficial].
5.  **Render:** Render the novel view using the modified geometry and the original radiance field [S1, unofficial].

    Returns: sigma (density), o (object code), c (color)

    c = linear(x_view, network_weights['w_c'], network_weights['b_c']) # 3 dims
    
    return sigma, o, c

def compute_siou_cost(predicted_mask, gt_mask):
    """Compute Soft Intersection-over-Union cost."""
    intersection = np.sum(predicted_mask * gt_mask)
    union = np.sum(predicted_mask) + np.sum(gt_mask) - intersection
    if union == 0:
        return 0
    return 1.0 - (intersection / union) # Cost is 1 - IoU

def match_objects(predicted_tensor, gt_tensor, H, T):
    """
    Match predicted object masks to ground truth using Hungarian algorithm.
    predicted_tensor: (U, V, H+1)
    gt_tensor: (U, V, T)
    """
    U, V, _ = predicted_tensor.shape
    N = U * V
    
    # Reshape to (N, H) and (N, T)
    # Note: predicted_tensor includes empty space at index H, so we take first H
    M_pred = predicted_tensor[:, :, :H].reshape(N, H)
    M_gt = gt_tensor.reshape(N, T)
    
    # Compute cost matrix
    # Cost matrix C[h, t]
    C = np.zeros((H, T))
    for h in range(H):
        for t in range(T):
            # sIoU cost
            cost_siou = compute_siou_cost(M_pred[:, h], M_gt[:, t])
            # CES cost (Cross-Entropy Score) - simplified as difference for demonstration
            # Actual CES definition from Yang et al. 2019 is more complex
            cost_ces = np.mean(np.abs(M_pred[:, h] - M_gt[:, t]))
            C[h, t] = cost_siou + cost_ces
            
    # Hungarian algorithm
    row_ind, col_ind = linear_sum_assignment(C)
    
    return row_ind, col_ind

def train_step(images, poses, intrinsics, gt_masks, network_weights, H, T):
    """
    Single training step.
    images: (L, U, V, 3)
    gt_masks: (L, U, V, T)
    """
    L, U, V, _ = images.shape
    
    total_loss = 0
    
    for l in range(L):

        # Forward pass
        sigma, o, c = forward_pass(rays.xyz, rays.dirs, network_weights)
        
        # Volume rendering to get rendered color
        rendered_color = volume_render(rays, sigma, c)
        
        # Color loss
        color_loss = np.mean((rendered_color - images[l])**2)
        
        # Object field loss
        # 1. Match predicted 2D masks to GT
        pred_tensor = o.reshape(U, V, H+1) # Assuming o is sampled per pixel
        gt_tensor = gt_masks[l]
        
        row_ind, col_ind = match_objects(pred_tensor, gt_tensor, H, T)
        
        # 2. Compute losses for empty and object points
        # l_3d_empty and l_3d_obj are designed to learn correct codes
        # Exact formula not provided, but involves ensuring empty points have high empty code
        # and object points have high object code
        obj_loss = compute_object_loss(o, pred_tensor, gt_tensor, row_ind, col_ind)
        
        total_loss += color_loss + obj_loss
        
    return total_loss

def manipulate_object(scene_rays, object_id, transformation, network_weights):

**Parameters:**
*   $H$: Predefined number of objects. Determines the channel dimension of 2D object prediction tensors. [S1, unofficial]
*   $T$: Number of ground truth objects. Determines the channel dimension of 2D ground truth label tensors. [S1, unofficial]
*   $L$: Number of generated 2D images used for 2D object matching and supervision. [S1, unofficial]
*   $U, V$: Spatial width and height dimensions of the 2D object prediction and ground truth label images. [S1, unofficial]

**Edge Cases and Pitfalls:**
*   **No 3D Ground Truth:** Learning the object code faces the issue of no ground truth 3D object codes available for full supervision [S1, unofficial].
*   **Variable Object Count:** The number of total objects is variable and there is no fixed order for objects [S1, unofficial].
*   **Empty Space:** Non-occupied (empty) 3D space must be taken into account, but there are no labels for supervision as well [S1, unofficial].
*   **Occlusion Artifacts:** Manipulating originally occluded objects or parts may produce artifacts due to inaccuracies in the learned radiance fields [S1, unofficial].
*   **Lighting Discrepancies:** Lighting factors are not decomposed, causing illumination discrepancies on edited objects compared to non-manipulated scenes [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The method uses a lightweight inverse query algorithm for manipulation, avoiding the need to evaluate dense 3D points from implicit fields explicitly, which improves efficiency compared to naive explicit structure extraction [S1, unofficial].
*   **Memory Complexity:** Depends on the MLP size and the number of objects $H$. The object field requires storing a one-hot vector of size $H+1$ for every point.
*   **Measured Performance:** Novel view rendering quality is clearly better than PointNeRF [S1, unofficial]. However, quality decreases after manipulation compared to non-manipulation baselines [S1, unofficial].
*   **Strengths:** Simultaneously reconstructs, decomposes, manipulates, and renders complex 3D scenes in a single pipeline from 2D images [S1, unofficial]. Robust and accurate object decomposition [S1, unofficial].
*   **Limitations:** Manipulation of occluded objects may produce artifacts [S1, unofficial]. Lighting factors are not decomposed [S1, unofficial].
*   **When to Use:** When 3D scene geometry decomposition and manipulation from 2D images is required, and novel view rendering quality is a priority [S1, unofficial].
*   **When Not to Use:** When lighting decomposition is required or when high-fidelity manipulation of heavily occluded objects is critical without potential artifacts [S1, unofficial].

## Background
DM-NeRF was published as a conference paper at ICLR 2023 [S1, unofficial]. It addresses the need for users to virtually manipulate objects in 3D scenes, such as in mixed reality applications, by allowing them to edit real scenes from 2D images [S1, unofficial]. It builds on the success of NeRF by adding an object field component to decompose the entire 3D space into object fields [S1, unofficial].
