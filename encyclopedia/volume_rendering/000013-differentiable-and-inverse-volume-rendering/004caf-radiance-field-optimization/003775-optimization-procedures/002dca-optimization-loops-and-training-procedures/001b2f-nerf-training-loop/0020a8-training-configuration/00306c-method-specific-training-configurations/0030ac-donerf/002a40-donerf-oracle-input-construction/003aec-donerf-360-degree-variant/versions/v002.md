# DONeRF* (360-degree variant)

Also called: DONeRF for 360-degree datasets, DONeRF re-implementation

## Overview
DONeRF* is a re-implementation of the DONeRF method [S1] adapted for 360-degree scenes [S1]. It omits the logarithmic sampling and warping techniques used in the original forward-facing implementation [S1]. It differs from standard NeRF by using a discrete classification-based volume representation derived from ground truth depth maps, rather than continuous density fields [S1].

## How it works
**Inputs and Outputs**
*   **Input:** Training images with corresponding ground truth depth maps [S1].
*   **Output:** A neural network that predicts classification values for ray bins, which are aggregated to render color images [S1].

**Data Structures**
*   **Ray Bins:** The ray is split into $N$ equidistant bins of constant length [S1].
*   **Classification Map:** A discrete map $C_{x,y}(z)$ where $z$ indexes the bin along the ray $(x,y)$ [S1].

**Steps**
1.  **Discretization:** For each pixel $(x,y)$ and its corresponding ray, the ground truth depth $d_s$ is discretized [S1]. The classification value $C_{x,y}(z)$ for bin $z$ (bounded by $d_z$ and $d_{z+1}$) is assigned as [S1]:
    $$
    C_{x,y}(z) = \begin{cases} 
    1 & \text{if } d_z \le d_s < d_{z+1} \\
    0 & \text{otherwise}
    \end{cases}
    $$
    where $d_z$ is the start depth of bin $z$ [S1].

2.  **Blurring:** The classification map is blurred spatially to account for depth uncertainty and occlusion [S1]. For each pixel $(x,y)$ and bin $z$, the blurred value $\tilde{C}_{x,y}(z)$ is computed as the maximum of neighbors within a kernel of size $K$ [S1]:
    $$
    \tilde{C}_{x,y}(z) = \max_{i,j \in \pm \lfloor K/2 \rfloor} \frac{C_{x+i,y+j}(z)}{\sqrt{i^2 + j^2}}
    $$
    where $K$ is the spatial blur kernel size [S1]. The center neighbor $(i=0, j=0)$ is excluded to avoid division by zero [G].

3.  **Filtering:** The blurred map is filtered along the depth dimension to smooth depth transitions [S1]. For each pixel $(x,y)$ and bin $z$, the filtered value $\bar{C}_{x,y}(z)$ is computed as [S1]:
    $$
    \bar{C}_{x,y}(z) = \min \left( \frac{\sum_{i=-\lfloor Z/2 \rfloor}^{\lfloor Z/2 \rfloor} \tilde{C}_{x,y}(z+i) \cdot (\lfloor Z/2 \rfloor + 1 - |i|)}{\lfloor Z/2 \rfloor + 1} \right)
    $$
    where $Z$ is the depth filter kernel size [S1]. The source formula applies a `min` operator to the normalized weighted sum and uses $\lfloor Z/2 \rfloor + 1$ as the denominator [S1].

4.  **Network Input:** The filtered classification values $\bar{C}_{x,y}(z)$ are used as input to the neural network [S1]. The network predicts the color and other properties for each bin [S1].

5.  **Rendering:** The final color is computed by aggregating the network outputs weighted by the classification values, similar to standard volume rendering but using the discrete classification targets [S1].

**Parameters**
*   $N$: Number of bins along the ray. Not given in the sources.
*   $K$: Spatial blur kernel size. Not given in the sources.
*   $Z$: Depth filter kernel size. Not given in the sources.
*   Sampling: Equidistant sampling is used [S1].

**Edge Cases and Pitfalls**
*   **Logarithmic Sampling:** Logarithmic sampling and warping are omitted because they perform poorly on 360-degree scenes [S1].
*   **Single Depth Value:** The method uses a single depth value per ray, which lacks expressivity for volumes with multiple layers (e.g., glass, fog) as it cannot capture multiple peaks in density [S1].

**Pseudocode**
```python
import math

def compute_classification_map(depth_map, n_bins, near, far):
    """Computes the initial classification map C from ground truth depth."""
    H, W = len(depth_map), len(depth_map[0])
    C = [[0.0] * n_bins for _ in range(H * W)]
    bin_length = (far - near) / n_bins
    for y in range(H):
        for x in range(W):
            d_s = depth_map[y][x]
            if near <= d_s < far:
                z = int((d_s - near) / bin_length)
                z = max(0, min(z, n_bins - 1))
                C[y * W + x][z] = 1.0
    return C

def blur_classification_map(C, H, W, n_bins, K):
    """Applies spatial blurring to the classification map."""
    pad = K // 2
    C_blur = [[0.0] * n_bins for _ in range(H * W)]
    for y in range(H):
        for x in range(W):
            for z in range(n_bins):
                max_val = -math.inf
                for i in range(-pad, pad + 1):
                    for j in range(-pad, pad + 1):
                        if i == 0 and j == 0:
                            continue
                        dist = math.sqrt(i * i + j * j)
                        val = C[(y + i) * W + (x + j)][z] / dist
                        if val > max_val:
                            max_val = val
                C_blur[y * W + x][z] = max_val
    return C_blur

def filter_classification_map(C_blur, H, W, n_bins, Z):
    """Applies depth filtering to the blurred classification map."""
    pad = Z // 2
    C_filt = [[0.0] * n_bins for _ in range(H * W)]
    for y in range(H):
        for x in range(W):
            for z in range(n_bins):
                weighted_sum = 0.0
                for i in range(-pad, pad + 1):
                    weight = (pad + 1 - abs(i))
                    weighted_sum += C_blur[y * W + x][z + i] * weight
                denominator = pad + 1
                C_filt[y * W + x][z] = min(weighted_sum / denominator, weighted_sum / denominator)
    return C_filt
```

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** On 360-degree datasets (Lego and Ship), DONeRF* achieves lower PSNR compared to TermiNeRF but is competitive with other methods like NeRF, KiloNeRF, PlenOctrees, and AutoInt [S1].
*   **Strengths:** Provides a discrete, interpretable volume representation based on ground truth depth [S1].
*   **Limitations:** Single depth value per ray lacks expressivity for complex volumes with multiple layers (e.g., glass, fog) [S1]. Logarithmic sampling is omitted, which may limit efficiency in forward-facing scenes but is necessary for 360-degree scenes [S1].

## Background
DONeRF* is a re-implementation of the DONeRF method [S1]. The original DONeRF method was designed for forward-facing scenes [S1]. DONeRF* adapts this method for 360-degree datasets by modifying the sampling strategy [S1]. It is compared against NeRF, KiloNeRF, PlenOctrees, and AutoInt in the context of 360-degree rendering [S1].
