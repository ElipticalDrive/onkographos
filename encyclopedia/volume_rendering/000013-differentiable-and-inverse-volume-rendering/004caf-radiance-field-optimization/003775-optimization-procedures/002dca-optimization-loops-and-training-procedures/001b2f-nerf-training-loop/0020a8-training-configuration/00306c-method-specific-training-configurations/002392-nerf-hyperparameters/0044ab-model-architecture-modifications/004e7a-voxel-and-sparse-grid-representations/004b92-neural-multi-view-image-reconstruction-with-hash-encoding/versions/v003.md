# Neural Multi-View Image Reconstruction with Hash Encoding

Also called: Ours (multi-view)

## Overview
This method performs neural multi-view image reconstruction and novel view synthesis by combining a hash-encoded spatial representation with a Signed Distance Function (SDF) geometry network [S1]. It solves the problem of reconstructing high-frequency geometric details and synthesizing novel views from multi-view images, addressing the noise and lack of geometric detail found in density-based methods like NeRF and the poor performance in textureless areas of methods like NeuS and IDR [S1]. It is distinguished from its siblings by using a hash grid for feature storage and an SDF thresholding strategy for geometry extraction, rather than volume density integration alone [S1].

## How it works
The method consists of a geometry network and a light field (color) network, trained to minimize a composite loss function.

### Inputs and Outputs
*   **Inputs:** Multi-view RGB images with known camera parameters (view direction $\mathbf{v}$); a bounding volume $\Omega$ for the scene.
*   **Outputs:** A reconstructed 3D geometry (mesh) and novel view images.

### Data Structures
1.  **Hash Grid:**
    *   Structure: A set of 16 layers of hash tables [S1].
    *   Layout: Each layer maps spatial coordinates to a feature vector.
    *   Feature Dimension: 2 per grid feature in each layer [S1].
    *   Hashing: Standard multi-resolution hash encoding (as defined in [Parent](13738-voxel-and-sparse-grid-representations.md)).
2.  **Geometry Network:**
    *   Structure: 6-layer MLP [S1].
    *   Activation: Softplus (implied by point cloud architecture similarity, though specific activation for the 6-layer variant is not explicitly named, the point cloud baseline uses softplus [S1]).
    *   Initialization: Modified strategy from [12] (as cited in [S1]).
3.  **Light Field Network:**
    *   Structure: 4 hidden-layer MLP [S1].
    *   Hidden Units: 256 per layer [S1].
    *   Activation: Not explicitly stated, but standard ReLU or similar is assumed for MLPs in this context [G].

### Numbered Steps

1.  **Hash Encoding:**
    For a query 3D point $\mathbf{x}$, compute the hash encoding $\text{enc}(\theta_h, \mathbf{x})$. This involves hashing $\mathbf{x}$ into the 16-layer grid and retrieving the 2-dimensional feature vector from each layer, then concatenating or summing them (standard hash encoding behavior) to form the geometry feature vector $\mathbf{f}_{geo}$ [S1].

2.  **Geometry Network Forward Pass:**
    Input the Fourier positional encoding of $\mathbf{x}$, denoted $\text{enc}_{ff}(\mathbf{x})$, into the first layer of the geometry network. The Fourier position encoding dimension is 6 [S1].
    Pass the data through the 6 layers. At the connected layer (typically the layer before the final output or the layer where features are injected, described as "connected layer of the geometry network" in the source [S1]), concatenate the hash feature vector $\mathbf{f}_{geo}$ with the network's internal representation.
    Output the Signed Distance Function value $S(\mathbf{x})$ and the gradient $\mathbf{n} = \nabla S(\mathbf{x})$ [S1].

3.  **Light Field (Color) Network Forward Pass:**
    Compute the Fourier positional encoding of the view direction $\mathbf{v}$, denoted $\text{enc}_{ff}(\mathbf{v})$, with dimension 6 [S1].
    Concatenate $\text{enc}_{ff}(\mathbf{v})$, the surface normal $\mathbf{n}$, and the geometry feature vector $\mathbf{f}_{geo}$ (output from the connected layer of the geometry network) [S1].
    Pass this concatenated vector through the 4-layer MLP (256 units each) to predict the color $\mathbf{c}$ [S1].

4.  **Hierarchical Sampling:**
    Sample points along the ray using a hierarchical sampling strategy [S1]. This involves drawing samples from a coarse distribution and then refining them based on the SDF values to concentrate samples near the surface [S1].

5.  **Invalid Point Elimination:**
    Calculate the mean of the SDF values of the sampled points on each ray. Use this mean as a threshold to eliminate invalid sampled points (those far from the surface) [S1].

6.  **Volume Rendering:**
    Render the image using the standard differentiable volume rendering equation [S1]:
    $$
    \hat{C}(r) = \sum_{i=1}^{N} w_i \mathbf{c}_i, \quad w_i = T_i \alpha_i, \quad T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)
    $$
    The opacity $\alpha_i$ is derived from the SDF. While the exact mapping from SDF to $\alpha$ is not explicitly formulaic in the notes, it typically follows $\alpha_i = 1 - e^{-\sigma_i \delta_i}$ where $\sigma$ is derived from the SDF gradient or value, consistent with the parent article's principles [S1].

7.  **Loss Calculation:**
    Minimize a composite loss function (Eq. 8 in [S1]) with weights:
    *   $\alpha = 0.1$ (likely image reconstruction loss weight)
    *   $\beta = 0.1$ (likely SDF consistency or regularization weight)
    *   $\gamma = 5 \times 10^{-4}$ (likely Eikonal or other regularization weight) [S1].

8.  **Geometry Extraction:**
    After training, extract the final geometry using the marching cubes algorithm at a resolution of $512^3$ [S1].

def fourier_encoding(x, num_frequencies=6):
    """
    Standard Fourier positional encoding.
    """
    freq_bands = 2.0 ** torch.linspace(0, num_frequencies-1, num_frequencies)
    x = x.unsqueeze(-1) * freq_bands.unsqueeze(0)
    x = torch.cat([torch.sin(x), torch.cos(x)], dim=-1)

### Edge Cases and Pitfalls
*   **Hash Collisions:** With a limited hash table size, collisions can occur. The source uses 16 layers, which helps mitigate this, but implementation must handle hash table resizing or collision resolution [S1].
*   **SDF Thresholding:** Using the mean SDF as a threshold for invalid points can be sensitive to noise. If the scene is not centered or the bounding box is poorly chosen, the mean may not represent the surface accurately [S1].
*   **Initialization:** The method relies on a modified initialization strategy from Ref [12]. Incorrect initialization can lead to poor convergence [S1].
*   **Resolution:** The marching cubes extraction is fixed at $512^3$. Lower resolutions may lose detail, while higher resolutions increase memory and computation time [S1].

## Operating characteristics
*   **Time Complexity:** Training time is 1.8 hours for the tested scenes, significantly faster than IDR (5.2h), NeuS (7.2h), UNISURF (21h), VolSDF (9h), and NeRF (9.1h) [S1].
*   **Memory Complexity:** Memory usage is 5 GB, lower than IDR (6.5 GB), NeuS (7 GB), UNISURF (6 GB), VolSDF (13.8 GB), and NeRF (8 GB) [S1].
*   **Performance:**
    *   Mean Chamfer-L2 Distance: $0.72 \times 10^{-6}$, better than IDR ($0.90 \times 10^{-6}$) and NeuS ($0.77 \times 10^{-6}$) [S1].
    *   Mean PSNR: 30.85 dB, better than IDR (23.20 dB) and NeuS (29.66 dB) [S1].
*   **Scalability:** The method uses 512 rays per iteration, similar to NeuS but fewer than IDR (2048) and others (1024) [S1].
*   **Strengths:** Reconstructs more geometric detail than baselines, especially in textureless areas where NeuS, IDR, VolSDF, and UNISURF perform poorly. Provides better high-frequency detail than NeRF, which suffers from noise due to lack of direct geometric constraints [S1].
*   **Limitations:** Performance depends on the quality of the hash encoding and the SDF thresholding. May struggle with very large scenes if the hash grid resolution is insufficient.

## Background
The method was proposed by Z. Deng, H. Xiao, Y. Lang, et al. in the paper "Multi-scale hash encoding based neural geometry representation" [S1]. It builds upon previous work in neural implicit representations like NeuS and IDR, aiming to improve geometric accuracy and training efficiency using hash encoding [S1]. The approach was evaluated on the DTU dataset and BlendedMVS dataset [S1].
