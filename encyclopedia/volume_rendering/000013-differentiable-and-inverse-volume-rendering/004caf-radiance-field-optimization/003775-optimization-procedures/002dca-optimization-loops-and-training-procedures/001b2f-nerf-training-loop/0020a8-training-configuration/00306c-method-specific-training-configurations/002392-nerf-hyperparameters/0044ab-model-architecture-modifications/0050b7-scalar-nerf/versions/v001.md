# SCALAR-NeRF

Also called: SCAlable LARge-scale Neural Radiance Fields for Scene Reconstruction

## Overview
SCALAR-NeRF is a coarse-to-fine framework for scalable large-scale neural scene reconstruction that decomposes expansive scenes into manageable spatial blocks to enable training on a single GPU [S1, unofficial]. It structures the neural representation as an encoder-decoder architecture where a coarse global model is trained first, followed by local block models that share the global decoder [S1, unofficial]. Unlike Block-NeRF, which suffers from a "foggy" appearance when block centroids are close due to inverse distance weighting (IDW) blending, SCALAR-NeRF fuses local outputs using a reference image rendered from the coarse global model, effectively discarding poorly rendered results [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:** A dataset of images $\{I_i\}$ with associated camera poses $\{P_i\}$ and intrinsics. The scene is assumed to be large-scale and potentially unbounded.
*   **Outputs:** A set of local NeRF models (one per block) and a final fused image for any query ray, synthesized from the local models and the global reference.

**Data Structures**
1.  **Multi-resolution Hash Table Encoder:**
    *   Stores feature vectors $f_l$ at each level $l \in \{1, \dots, L\}$.
    *   Total feature embedding $F \in \mathbb{R}^{L \cdot F}$, where $L$ is the number of levels and $F$ is the feature dimension per level [S1, unofficial].
    *   Hash table size: $2^{19}$ [S1, unofficial].
2.  **Shared Decoder:**
    *   A shallow Multi-Layer Perceptron (MLP) [S1, unofficial].
    *   Inputs: Feature embedding $F$.
    *   Outputs: Volume density $\sigma$ and per-point color $\mathbf{c}$ [S1, unofficial].
3.  **Spatial Blocks:**
    *   Defined by Axis-Aligned Bounding Boxes (AABBs).
    *   Each block has a dedicated local hash table encoder.
    *   Bounding boxes are scaled by a factor $s_{\text{AABB}}$ to create overlap regions [S1, unofficial].

**Numbered Steps**

1.  **Train Coarse Global Model:**
    *   Train a global NeRF model on the entire image dataset using a multi-resolution hash table encoder and a shared decoder [S1, unofficial].
    *   For unbounded scenes, apply space contraction to input coordinates $\mathbf{x}$ [S1, unofficial]:
        $$
        \text{contract}(\mathbf{x}) = \begin{cases} \mathbf{x}, & \|\mathbf{x}\| \le 1, \\ \frac{\mathbf{x}}{2 - \frac{1}{\|\mathbf{x}\|}}, & \|\mathbf{x}\| > 1. \end{cases}
        $$
    *   This model serves as the reference for fusion and provides the shared decoder for local models.

2.  **Partition Images into Blocks:**
    *   Cluster the training images into $K$ blocks using KMeans clustering based on camera positions or image content [S1, unofficial].
    *   Define the spatial extent (AABB) for each block based on the clustered images.

3.  **Scale Bounding Boxes:**
    *   Scale up the AABB of each local block by a factor $s_{\text{AABB}}$ to ensure overlapping regions between adjacent blocks [S1, unofficial].
    *   Optimal value for $s_{\text{AABB}}$ is 1.2 [S1, unofficial]. Values too large (e.g., 1.3) increase hash collision probability and damage quality; values too small (e.g., 1.0) reduce overlap benefits [S1, unofficial].

4.  **Initialize Local Models:**
    *   For each block $k \in \{1, \dots, K\}$:
        *   Initialize a local hash table encoder (random or specific initialization).
        *   Initialize the local decoder by copying the weights from the trained coarse global decoder [S1, unofficial].
        *   **Fix** the shared decoder weights during local training to eliminate saving its computational graph, allowing for larger hash table sizes in the local encoders [S1, unofficial]. (Optional: Fine-tune the decoder later for marginal gains, but fixing it is sufficient for satisfactory results) [S1, unofficial].

5.  **Train Local Models:**
    *   Train each local model using only the images assigned to its block.
    *   The local encoder maps 3D points to features $F$, which are passed through the fixed shared decoder to predict $\sigma$ and $\mathbf{c}$ [S1, unofficial]:
        $$
        \sigma, \mathbf{c} = \text{Decoder}(F)
        $$
    *   Use standard NeRF volume rendering loss (e.g., $\mathcal{L}_{\text{rgb}}$) [S1, unofficial].

6.  **Fuse Local Outputs:**
    *   To render a final image for a query ray:
        *   Render an image from the coarse global model (Reference Image $I_{\text{global}}$).
        *   Render images from each local block model ($I_{\text{local}, k}$).
        *   Fuse these images. SCALAR-NeRF uses the global model's output to discard poorly rendered results from local blocks, avoiding the IDW blending issues of Block-NeRF [S1, unofficial].
        *   *Note:* The specific fusion algorithm (e.g., weighted average, masking) is not explicitly detailed in the provided text beyond "fuse them with a reference image rendered from the coarse model" [S1, unofficial]. However, the ablation study confirms that using the global model for fusion outperforms IDW [S1, unofficial].

**Parameters**
*   **Hash Table Size:** $2^{19}$ [S1, unofficial]. This is smaller than Instant-NGP's $2^{21}$ but achieves better results due to block decomposition.
*   **AABB Scale Factor ($s_{\text{AABB}}$):** 1.2 [S1, unofficial]. Controls overlap. 1.0 is too small, 1.3 is too large (causes hash collisions and quality drop) [S1, unofficial].
*   **Decoder:** Fixed during local training to save memory [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Hash Collisions:** A too-large AABB scale factor increases the probability of hash collisions, degrading reconstruction quality [S1, unofficial].
*   **Foggy Appearance:** Using Inverse Distance Weighting (IDW) for fusion (as in Block-NeRF) performs worse than the global model fusion and is unsuitable when blocks are close [S1, unofficial].
*   **GPU Memory:** Simply increasing hash table size slows training and prevents fitting on a single GPU. Block splitting allows finer details without increasing hash table size [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Training is split into a global phase and $K$ local phases. The global phase is fast due to a smaller hash table ($2^{19}$) and coarse representation. Local phases are independent and parallelizable.
*   **Memory Complexity:** The shared decoder is fixed during local training, eliminating the need to store its computational graph, which allows for larger local hash tables if needed (though $2^{19}$ is used) [S1, unofficial]. The method fits on a single GPU, unlike methods requiring $2^{21}$ hash tables [S1, unofficial].
*   **Measured Performance:** On the Tanks and Temples dataset, SCALAR-NeRF (hash size $2^{19}$) outperforms Block-NeRF and Instant-NGP (hash size $2^{21}$) in PSNR, SSIM, and LPIPS [S1, unofficial].
*   **Strengths:** Scalable to large scenes; avoids "foggy" artifacts of Block-NeRF; fits on single GPU; shared decoder promotes feature space alignment.
*   **Limitations:** Requires KMeans clustering of images; fusion logic relies on global model reference (specific algorithm not detailed); sensitive to AABB scale factor [S1, unofficial].

## Background
SCALAR-NeRF was introduced by Yu Chen and Gim Hee Lee from the National University of Singapore in November 2023 [S1, unofficial]. It addresses the limitations of Block-NeRF, which produces hazy/foggy images when block centroids are close due to its inverse distance weighting blending function [S1, unofficial]. The method builds on the multi-resolution hash table encoder from Instant-NGP and the space contraction method from Mip-NeRF360 [S1, unofficial].
