# Learning Rate Scheduling

Also called: LR Scheduling, LambdaLR Scheduler, Learning Rate Decay, Learning Rate Scheduler

## Overview
Learning rate scheduling adjusts the optimizer's step size during training to improve convergence stability and final reconstruction quality in radiance-field optimization. It differs from static learning rates by dynamically scaling parameters based on training progress or structural changes, such as densification events. This method builds on [Training Configuration](2332-training-configuration.md) by defining the temporal evolution of the learning rate parameter.

## How it works
The method implements time-based exponential decay and event-driven spikes to modulate the learning rates of model parameters (e.g., means, weights, vertex coordinates).

### Inputs and Outputs
- **Inputs**: Current step/iteration $i$, maximum steps $T_{max}$, initial learning rate $lr_{init}$, final learning rate $lr_{final}$, decay gamma $\gamma$, step size $S$, densification iteration $I$, spike duration $L$.
- **Outputs**: Scaled learning rate $lr(i)$ for the current step.

### Data Structures
- **Configuration**: Dictionary or struct containing `lr_init`, `lr_final`, `gamma`, `step_size`, `start_step`, `end_step`, `start_value`, `end_value`.
- **Optimizer State**: The learning rate is typically applied via a scheduler wrapper (e.g., `torch.optim.lr_scheduler.LambdaLR`) that updates the optimizer's parameter groups [S2, unofficial].

### Formulas
1. **Exponential Decay (Normalized Step)**:
   For a normalized step $t = \text{clamp}(i / T_{max}, 0, 1)$, the learning rate for means is:
   $$ lr_{means}(t) = \exp\left( \log(lr_{init}) \cdot (1 - t) + \log(lr_{final}) \cdot t \right) $$
   where $lr_{init}$ is the initial learning rate and $lr_{final}$ is the target final learning rate [S1, unofficial].

2. **Lambda Decay (Step-based)**:
   Using a gamma decay function:
   $$ lr(i) = lr_{init} \cdot \gamma^{(i / S)} $$
   where $\gamma$ is the decay factor and $S$ is the step size [S2, unofficial].

3. **Linear Interpolation**:
   For linear scheduling between start and end values:
   $$ value = start\_value + (end\_value - start\_value) \cdot \max\left(\min\left(1.0, \frac{i - start\_step}{end\_step - start\_step}\right), 0.0\right) $$
   where $start\_step$ and $end\_step$ define the interval, and $start\_value$ and $end\_value$ are the bounds [S3, unofficial].

4. **Learning Rate Spike**:
   After a densification event at iteration $I$, a spike is added to the decaying learning rate $l(i)$ for specific parameters (instant NGP weights, vertex coordinates):
   $$ \text{Spike}(i) = \mathbb{1}\{i - I > 0\} \cdot (l(0) - l(I)) \cdot \exp\left(-\frac{6(i - I)}{L}\right) $$
   The total learning rate becomes $l_{total}(i) = l(i) + \text{Spike}(i)$. This raises the rate back to the initial maximum before decaying over $L$ iterations [S5, unofficial].

### Parameters
- **$lr_{init}$**: Initial learning rate. Typical values depend on the optimizer (e.g., Adam).
- **$lr_{final}$**: Target final learning rate. Often set to $1/10$ or $1/100$ of $lr_{init}$ [S1, unofficial].
- **$\gamma$**: Gamma value for exponential decay. Default often 0.33 or similar [S2, unofficial].
- **$S$**: Step size for decay calculation [S2, unofficial].
- **$L$**: Duration of the learning rate spike in iterations [S5, unofficial].
- **$start\_step, end\_step$**: Boundaries for linear interpolation [S3, unofficial].

### Pseudocode
```python
def compute_lr_exponential_decay(step, max_steps, lr_init, lr_final):
    """
    Computes learning rate using normalized exponential decay.
    """
    # Clamp step to [0, 1]
    t = min(max(step / max_steps, 0.0), 1.0)
    
    # Exponential interpolation in log space
    lr = math.exp(math.log(lr_init) * (1.0 - t) + math.log(lr_final) * t)
    return lr

def compute_lr_lambda_decay(step, lr_init, gamma, step_size):
    """
    Computes learning rate using LambdaLR style decay.
    """
    # Calculate decay factor
    decay_factor = gamma ** (step / step_size)
    return lr_init * decay_factor

def compute_lr_linear(step, start_step, end_step, start_value, end_value):
    """
    Computes learning rate using linear interpolation.
    """
    if end_step == start_step:
        return start_value
    
    # Calculate progress, clamped to [0, 1]
    progress = (step - start_step) / (end_step - start_step)
    progress = min(max(progress, 0.0), 1.0)
    
    return start_value + (end_value - start_value) * progress

def compute_lr_with_spike(step, densification_step, initial_lr, current_decay_lr, spike_duration):
    """
    Adds a learning rate spike after densification.
    """
    if step <= densification_step:
        return current_decay_lr
    
    # Calculate spike magnitude
    # l(0) is initial_lr, l(I) is current_decay_lr at densification step
    spike_magnitude = (initial_lr - current_decay_lr) * math.exp(-6.0 * (step - densification_step) / spike_duration)
    
    return current_decay_lr + spike_magnitude
```

### Edge Cases and Pitfalls
- **Division by Zero**: Ensure `step_size` and `end_step - start_step` are non-zero.
- **Negative Steps**: Clamp `step` to $\ge 0$.
- **Precision**: Use log-space interpolation for exponential decay to avoid numerical instability with very small learning rates [S1, unofficial].
- **Spike Timing**: The spike function is only active for $i > I$. Ensure the indicator function $\mathbb{1}\{i - I > 0\}$ is correctly implemented [S5, unofficial].

## Subtopics

### View-count-based Learning Rate
Adjusts learning rates based on a view-count prior to prioritize under-reconstructed regions. Without this prior, PSNR can degrade by up to -1.22 in the worst case [S4].

### Learning Rate Spike
A technique to increase the learning rate of specific model parameters (instant NGP weights and vertex coordinates) after a densification event to allow rapid accommodation for changes. It adds a spike function with duration $L$ on top of the decay function [S5, unofficial].

## Operating characteristics
- **Time Complexity**: $O(1)$ per step for computing the learning rate.
- **Memory Complexity**: $O(1)$ additional memory for scheduler state.
- **Strengths**: Improves convergence stability; prevents oscillation in later stages; handles structural changes (densification) effectively.
- **Limitations**: Requires careful tuning of decay parameters; spike duration $L$ must be chosen appropriately to avoid instability.
- **When to Use**: Standard for NeRF and Gaussian Splatting training to ensure smooth convergence and high final quality.

## Background
Learning rate scheduling is a standard optimization technique in deep learning. In the context of radiance fields, it was adapted to handle the unique convergence properties of neural implicit representations and 3D Gaussian splatting. The exponential decay and spike mechanisms are specifically tailored to the iterative densification and refinement processes in these methods [S1, S5, unofficial].
