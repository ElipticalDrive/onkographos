# DONeRF

Also called: Depth Oracle Neural Radiance Fields, DONeRF Training Configuration, DONeRF training setup, Depth Oracle Network, DoNeRF

## Overview
DONeRF is a training configuration for neural radiance fields that replaces standard uniform or stratified raymarching with a two-network architecture: a **depth oracle network** and a **shading network** [S3]. It solves the prohibitive computational cost of NeRF by using the oracle to predict a small set of high-importance sample locations, allowing the shading network to render images with only 2–16 samples per ray instead of hundreds [S3]. It sets itself apart from standard NeRF by decoupling geometry estimation from color/density prediction, and from other acceleration methods like NSVF by avoiding explicit voxel structures or large memory caches, relying solely on compact MLPs [S3].

## How it works
DONeRF operates in a two-stage pipeline. First, the depth oracle network predicts sample locations. Second, the shading network renders the image using those locations. The method is not end-to-end trainable; the oracle is trained first, then fixed, and the shading network is trained subsequently [S3].

### Inputs and Outputs
*   **Inputs:** 3D position $\mathbf{x} \in \mathbb{R}^3$ and viewing direction $\mathbf{d} \in S^2$.
*   **Outputs:**
    *   Oracle: Discretized depth classification probabilities (used to select sample indices).
    *   Shading: RGB color $\mathbf{c} \in \mathbb{R}^3$ and volume density $\sigma \in \mathbb{R}^+$.

### Data Structures and Network Layouts
Both networks are Multi-Layer Perceptrons (MLPs) with 8 hidden layers and 256 hidden units per layer, using ReLU activations [S1][S3].

**1. Depth Oracle Network**
*   **Input Processing:** No positional encoding is applied. The input vector is the concatenation of $\mathbf{x}$ and $\mathbf{d}$: $[\mathbf{x}, \mathbf{d}] \in \mathbb{R}^5$.
*   **Architecture:** 8-layer MLP.
*   **Output:** Depth classification logits. The oracle solves a classification task using filtered, discretized target depth values rather than regressing continuous depth directly [S3].

**2. Shading Network**
*   **Input Processing:** Positional encoding is applied to inputs.
    *   $\gamma(\mathbf{x})$: 63-dimensional vector.
    *   $\gamma(\mathbf{d})$: 27-dimensional vector.
*   **Architecture:** 8-layer MLP.
    *   First layer input: $\gamma(\mathbf{x})$.
    *   Last layer input: Feature vector concatenated with $\gamma(\mathbf{d})$.
*   **Output:** $\mathbf{c} \in \mathbb{R}^3$ and $\sigma \in \mathbb{R}^+$.

### Numbered Steps

1.  **Ray Unification (View Cell):**
    Rays are unified within a "view cell," defined as a bounding box with a primary orientation and maximum viewing angle (e.g., 30° pitch, 20° yaw) [S3]. This reduces input ambiguity for the oracle [S3].

2.  **Oracle Inference:**
    The depth oracle network processes the unified ray description to predict sample locations. The oracle outputs a classification over discretized depth bins. The number of selected samples is denoted as $N_s$ (e.g., DONeRF-16 uses $N_s=16$) [S1].

3.  **Logarithmic Transformation and Warping:**
    The sample positions predicted by the oracle are transformed logarithmically. They are then warped towards the view cell center [S3]. This non-linear transformation handles large depth ranges and focuses sampling on foreground details [S3].

4.  **Shading Network Forward Pass:**
    The shading network evaluates the warped sample positions. For each ray, it computes density $\sigma_i$ and color $\mathbf{c}_i$ for $N_s$ samples [S3].

5.  **Volume Rendering:**
    The final color $\hat{C}(\mathbf{r})$ is computed using the standard differentiable volume rendering integral [S6]:
    $$ \hat{C}(\mathbf{r}) = \sum_{i=1}^{N_s} T_i \alpha_i \mathbf{c}_i $$
    where $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$, $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$, and $\delta_i$ is the distance between samples [S6].

6.  **Loss Computation:**
    The total loss is a weighted sum of Mean Squared Error (MSE) on RGB and an Opacity Loss ($\text{loss}_O$) [S3]:
    $$ \text{loss} = \alpha \cdot \text{loss}_{\text{MSE}} + \beta \cdot \text{loss}_{\text{O}} $$
    The opacity loss prevents dark pixel artifacts by forcing accumulated opacity to be at least 1 for opaque surfaces [S3]:
    $$ \text{loss}_O = \begin{cases} 0, & \text{if } \sum_{i=1}^{N_s} \delta_i \geq 1 \\ \left( \left( \sum_{i=1}^{N_s} \delta_i \right) - 1 \right)^2, & \text{otherwise} \end{cases} $$
    Typical weights are $\alpha = 1.0$ and $\beta = 10.0$ [S3].

7.  **Optimization:**
    *   **Stage 1:** Train the depth oracle network for 300,000 iterations using Binary Cross-Entropy (BCE) loss on depth classification.
    *   **Stage 2:** Train the shading network for 300,000 iterations using the fixed oracle predictions, using MSE loss on RGB and the opacity loss [S3].
    *   **Optimizer:** Adam with learning rate $0.0005$ and batch size 4096 samples per iteration [S3].

### Parameters and Typical Values
*   **Network Size:** 8 hidden layers, 256 units per layer for both networks [S3].
*   **Samples per Ray ($N_s$):** 2, 4, 8, or 16. DONeRF-4 is a common configuration [S3].
*   **Training Iterations:** 300,000 for oracle, 300,000 for shading [S3].
*   **Learning Rate:** 0.0005 (Adam) [S3].
*   **Batch Size:** 4096 samples per iteration [S3].
*   **Loss Weights:** $\alpha=1.0$ (MSE), $\beta=10.0$ (Opacity) [S3].
*   **View Cell:** Bounding box with rotation limits (e.g., 30° pitch, 20° yaw) [S3].

### Edge Cases and Pitfalls
*   **Dark Pixel Artifacts:** Low sample counts can cause rays to fail to accumulate to opacity 1, resulting in dark backgrounds. This is mitigated by the opacity loss term [S3].
*   **Non-End-to-End Training:** The architecture is not jointly trainable. It struggles without high-quality depth supervision [S2].
*   **No Ground Truth Depth:** If GT depth is unavailable, a dense NeRF (12 layers, 512 units, 128 samples/ray) must be trained first to extract depth maps for oracle training [S3]. This may introduce background noise if the NeRF outputs high-frequency depth values in empty space [S3].
*   **Reflective/Transparent Surfaces:** Single depth estimates are insufficient for mirrors or refractive surfaces, leading to artifacts [S3].

## Operating characteristics
*   **Time Complexity:** DONeRF requires approximately 4.35 MFLOP per pixel [S3]. Inference costs are reduced by up to 48x compared to NeRF [S3].
*   **Memory Complexity:** Compact. Uses only two MLPs (approx. 4 MB) without additional data structures or caches [S3].
*   **Performance:** Renders at 22 ms per frame (400x400) on a single GPU [S3]. On NVIDIA RTX 3090 at 800x800 with 2 samples/ray, total time is 51.3 ms (~20 fps) [S3].
*   **Quality:** Average PSNR of 31.14 dB, compared to NeRF's 30.52 dB [S3]. At 16 samples, up to 7 dB higher PSNR than NeRF [S3].
*   **Strengths:** Real-time rendering capability, high quality with few samples, compact memory footprint [S3].
*   **Limitations:** Requires ground truth depth (or pre-trained NeRF) for training; struggles with reflective/transparent surfaces; not end-to-end trainable [S2][S3].

## Background
DONeRF was introduced by [S3] to address the prohibitive computational cost of NeRF in real-time applications like games and VR. It builds on the concept of using depth information to guide sampling, replacing NeRF's dense raymarching with a sparse, oracle-guided approach. It is designed to work within the constraints of consumer hardware, leveraging TensorRT and custom CUDA kernels for efficiency [S3].
