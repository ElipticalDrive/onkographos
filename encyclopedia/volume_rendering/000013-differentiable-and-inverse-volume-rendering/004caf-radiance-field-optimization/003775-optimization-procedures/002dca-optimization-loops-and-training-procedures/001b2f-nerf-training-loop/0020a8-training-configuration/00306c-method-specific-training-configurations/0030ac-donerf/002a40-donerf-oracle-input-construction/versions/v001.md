# DONeRF Oracle Input Construction

Also called: Depth oracle inputs, Logarithmic input transformation

## Overview
This method defines the input vector for the depth oracle network in DONeRF, which predicts sample locations for the subsequent shading network. It solves the problem of providing sufficient geometric context to a lightweight MLP to accurately classify depth ranges. It is distinguished from standard single-depth prediction by using a classification head over discretized depth bins and by explicitly injecting 3D spatial coordinates of potential sample points as direct network inputs, rather than relying solely on positional encoding.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $I$ 3D positions $\mathbf{p}_i \in \mathbb{R}^3$ along the ray, and the ray parameters (origin $\mathbf{o}$, direction $\mathbf{d}$).
*   **Output:** The input tensor passed to the first layer of the depth oracle network.

**Data Structures:**
The oracle input consists of the raw 3D coordinates of $I$ points. No positional or Fourier encoding is applied to these inputs [S1].

**Steps:**
1.  **Discretize Depth Range:** Define $N$ discretized depth ranges (bins) along the ray. Let the boundaries of these bins be $z_0, z_1, \dots, z_N$.
2.  **Compute Sample Centers:** For each bin $j \in \{0, \dots, N-1\}$, calculate the center depth $c_j = \frac{z_j + z_{j+1}}{2}$.
3.  **Logarithmic Transformation:** Apply a logarithmic transformation to the center depths to match the shading network's sampling strategy. The transformed depth is $l_j = \log(c_j)$ [S1].
4.  **Compute 3D Positions:** For each transformed depth $l_j$, compute the corresponding 3D position $\mathbf{p}_j$ along the ray:
    $$ \mathbf{p}_j = \mathbf{o} + \exp(l_j) \cdot \mathbf{d} $$
    *Note: The source states positions are placed at the centers of the discretized depth ranges and transformed logarithmically to work in unison with the shading network [S1].*
5.  **Select Input Points:** Select $I$ points from the computed set of positions. The source specifies using $I$ positions provided to the oracle [S1].
6.  **Construct Input Tensor:** Concatenate the $I$ 3D positions into a single input vector/tensor. The order corresponds to the discretized depth ranges [S1].

**Parameters:**
*   $I$: The number of 3D input positions provided to the oracle. Tested values: $1$ to $128$. The final configuration uses $I=128$ [S1].
*   $N$: The number of discretized depth ranges (classification steps). The source varies $N$ in ablation studies but does not specify a fixed default for the input construction itself, other than implying it matches the shading network's sampling [S1].

**Edge Cases and Pitfalls:**
*   **Encoding:** Do not use positional or Fourier encoding for these depth oracle inputs. Experiments showed it did not improve results [S1].
*   **Ray Unification:** If ray unification is employed, the ray origin and direction should be transformed such that the ray starts from a canonical position (e.g., the origin of a circumscribed sphere) before computing $\mathbf{p}_j$ [S1].

## Subtopics

## Operating characteristics
*   **Performance Gain:** Providing multiple samples along the ray as input adds 1 dB to PSNR compared to single-point input [S1].
*   **Comparison:** Using a classification network (oracle) with these inputs adds 0.6 dB–1.5 dB to PSNR compared to predicting a single depth value [S1].
*   **Complexity:** The input construction is computationally negligible. The source states these additions come at "virtually no inference cost" [S1].
*   **Memory:** The input size is $I \times 3$ floats. With $I=128$, this is 384 floats per ray.

## Background
*   **Origin:** This method is part of the DONeRF paper by [S1] (2021).
*   **Development:** The authors conducted an ablation study (Section 5.3) to determine the optimal filter sizes and depth oracle inputs. They found that ray unification, classification, and multi-point input all contributed to quality improvements [S1].
*   **Usage:** Used in the DONeRF architecture for real-time neural rendering [S1].
