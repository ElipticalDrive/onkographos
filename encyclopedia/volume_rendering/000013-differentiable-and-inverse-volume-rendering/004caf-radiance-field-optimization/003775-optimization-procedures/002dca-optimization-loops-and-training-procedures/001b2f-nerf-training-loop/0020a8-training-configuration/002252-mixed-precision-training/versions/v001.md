# Mixed Precision Training

Also called: AMP Training, FP16 Training, Mixed Precision Training with Fallback

## Overview
Mixed Precision Training (MPT) accelerates NeRF optimization on CUDA devices by utilizing Automatic Mixed Precision (AMP) to perform computations in lower precision formats while maintaining numerical stability [S1, unofficial]. It differs from standard single-precision training by reducing memory bandwidth requirements and increasing throughput via tensor cores, without requiring manual precision management for every operation [S1, unofficial].

## How it works
The method integrates into the standard NeRF training loop by wrapping the forward pass in an automatic precision context manager and applying gradient scaling to prevent underflow in lower-precision gradients.

**Inputs and Outputs**
*   **Inputs**: Model parameters, optimizer state, gradient scaler, batch of rays (positions, directions), target images, and transformation matrices.
*   **Outputs**: Updated model parameters, updated optimizer state, updated scaler state, and computed loss value.

**Data Structures**
*   `scaler`: A gradient scaler instance (e.g., `torch.cuda.amp.GradScaler`) that maintains a scale factor for loss values.
*   `autocast_state`: Context manager state handling precision casting (FP32 to FP16/BF16) for supported operations.

**Parameters**
*   `use_mixed_precision`: Boolean flag to enable/disable AMP. Default is typically `True` for modern CUDA hardware [S1, unofficial].
*   `scaler`: Gradient scaler instance. Initialized with default parameters unless specified [S1, unofficial].

**Steps**
1.  **Initialization**: Create a gradient scaler instance. Initialize lists to track loss and iteration epochs for logging [S2, unofficial].
2.  **Iteration Loop**: Iterate from `start_iter` to `num_iters` [S2, unofficial].
3.  **Mode Set**: Set the model to training mode (`model.train()`) [S2, unofficial].
4.  **Data Selection**: Randomly select 4 target images from the dataset using `np.random.choice` on the image count. Extract the target image tensor and the camera-to-world transformation matrix (`target_tform_cam2world`). Move these tensors to the CUDA device [S2, unofficial].
5.  **Autocast Context**: Enter the mixed precision context using `torch.cuda.amp.autocast()` (or `torch.amp.autocast('cuda')` for newer PyTorch versions) [S1, unofficial][S2, unofficial].
6.  **Forward Pass**:
    *   Generate rays from the selected target images.
    *   Query the NeRF model (e.g., `run_one_iter_of_tinynerf` or `InstantNGPNeRF`) with ray origins, directions, and sampling parameters (`near_thresh`, `far_thresh`, `depth_samples_per_ray`) to obtain predicted RGB values (`rgb_predicted`) [S2, unofficial].
    *   Squeeze the first dimension of `rgb_predicted` if necessary to match the target image shape [S2, unofficial].
7.  **Loss Computation**: Compute the Mean Squared Error (MSE) loss between `rgb_predicted` and `target_img` [S1, unofficial][S2, unofficial].
8.  **Gradient Scaling**: Scale the loss value by the scaler's current scale factor [S1, unofficial][S2, unofficial].
9.  **Backward Pass**: Call `loss.backward()` to compute gradients. The scaler automatically handles the upcasting of gradients to FP32 for stability [S1, unofficial][S2, unofficial].
10. **Optimizer Step**: Call `optimizer.step()` to update model parameters [S1, unofficial][S2, unofficial].
11. **Scaler Update**: Call `scaler.step(optimizer)` (if using the scaler's step method) or update the scaler state. If using standard PyTorch AMP, `scaler.step(optimizer)` is called, followed by `scaler.update()` [S1, unofficial][S2, unofficial].
12. **Gradient Zeroing**: Zero the gradients using `optimizer.zero_grad(set_to_none=True)` to free memory [S2, unofficial].
13. **Learning Rate Update**: Step the learning rate scheduler [S2, unofficial].
14. **Checkpointing**: If the current iteration `i` is divisible by `save_every`:
    *   Append `loss.item()` to the `Loss` list and `i+1` to the `Epochs` list [S2, unofficial].
    *   Save a checkpoint to `checkpoint_dir/checkpoint_{i}.pt` containing:
        *   `model_state_dict`
        *   `optimizer_state_dict`
        *   `loss`
        *   `iteration`
        *   `scaler.state_dict()`
        *   `scheduler.state_dict()` [S2, unofficial]
    *   Plot and save loss figures [S2, unofficial].

**Pseudocode**

```python
import torch
import numpy as np
import os

def train_with_mixed_precision(
    model, 
    optimizer, 
    scheduler, 
    dataset, 
    num_iters, 
    start_iter, 
    save_every, 
    checkpoint_dir,
    device='cuda'
):
    # Initialize scaler for mixed precision
    scaler = torch.cuda.amp.GradScaler()
    
    # Logging structures
    Loss = []
    Epochs = []
    
    # Pre-fetch full data for random selection (example from source)
    # In practice, this might be done per batch or via a dataloader
    images, tforms, _ = dataset.get_full_data(device)
    
    for i in range(start_iter, num_iters):
        model.train()
        
        # Randomly select 4 target images
        indices = np.random.choice(images.shape[0], 4, replace=False)
        target_img = images[indices].to(device)
        target_tform_cam2world = tforms[indices].to(device)
        
        # Mixed precision context
        with torch.cuda.amp.autocast():
            # Forward pass
            # Assuming helper functions exist as per source [S2, unofficial]
            # ray_origins, ray_directions, depth_values are derived from 
            # target_tform_cam2world and image dimensions
            rgb_predicted = run_one_iter_of_tinynerf(
                model=model,
                target_tform_cam2world=target_tform_cam2world,
                height=target_img.shape[1],
                width=target_img.shape[2],
                focal_length=dataset.focal_length,
                near_thresh=dataset.near_thresh,
                far_thresh=dataset.far_thresh,
                depth_samples_per_ray=dataset.depth_samples_per_ray,
                device=device
            )
            
            # Squeeze dimension if necessary
            if rgb_predicted.dim() > 3:
                rgb_predicted = rgb_predicted.squeeze(0)
                
            # Compute Loss
            loss = torch.mean((rgb_predicted - target_img) ** 2)
            
            # Scale loss and backward
            scaler.scale(loss).backward()
            
            # Optimizer step
            scaler.step(optimizer)
            scaler.update()
            
            # Zero gradients
            optimizer.zero_grad(set_to_none=True)
            
        # Step scheduler
        scheduler.step()
        
        # Checkpointing
        if i % save_every == 0:
            Loss.append(loss.item())
            Epochs.append(i + 1)
            
            checkpoint_path = os.path.join(checkpoint_dir, f"checkpoint_{i}.pt")
            torch.save({
                'model_state_dict': model.state_dict(),
                'optimizer_state_dict': optimizer.state_dict(),
                'loss': loss.item(),
                'iteration': i,
                'scaler_state_dict': scaler.state_dict(),
                'scheduler_state_dict': scheduler.state_dict()
            }, checkpoint_path)
            
            # Plotting (implementation detail)
            plot_figures(Epochs, Loss)

def plot_figures(Epochs, log_loss):
    import matplotlib.pyplot as plt
    plt.figure(figsize=(10, 4))
    plt.plot(Epochs, log_loss)
    plt.title("Loss")
    plt.savefig("Loss.png")
    plt.close()
```

**Edge Cases and Pitfalls**
*   **Precision Compatibility**: Older PyTorch versions require `torch.cuda.amp.autocast()` while newer versions use `torch.amp.autocast('cuda')`. The implementation must handle this version difference [S1, unofficial].
*   **Gradient Underflow**: Without the gradient scaler, FP16 gradients may underflow to zero, causing training to stall. The scaler prevents this by scaling up the loss before backward pass [S1, unofficial].
*   **Memory Management**: Using `set_to_none=True` in `zero_grad()` helps reduce memory fragmentation during long training runs [S2, unofficial].
*   **Checkpointing**: The scaler state must be saved and restored to ensure consistent training behavior across restarts [S2, unofficial].

## Subtopics

### AMP Training
Also called: Automatic Mixed Precision Training. This is the standard implementation of Mixed Precision Training using PyTorch's AMP API. It automatically casts operations to FP16/BF16 where beneficial and keeps reductions in FP32. Choose this when using modern CUDA hardware (Volta or later) and PyTorch 1.6+. It offers the best balance of speed and ease of implementation [S1, unofficial].

### FP16 Training
Also called: Half-Precision Training. This refers to the specific use of FP16 data types. In the context of NeRF, this is often achieved via AMP rather than manual casting. It is chosen when memory bandwidth is the primary bottleneck and the hardware supports FP16 tensor cores. Note that manual FP16 training requires careful handling of loss scaling and gradient clipping, which AMP automates [S2, unofficial].

### Mixed Precision Training with Fallback
Also called: Robust Mixed Precision. This variant includes logic to detect overflow or instability (e.g., NaN losses) and fallback to FP32 for specific operations or the entire training loop if necessary. It is chosen for older hardware or unstable training configurations where standard AMP might fail. This adds overhead but increases robustness [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: Training time is reduced by approximately 1.5x to 3x compared to FP32 training on supported GPUs (e.g., NVIDIA A100, V100) due to faster tensor core operations [S1, unofficial].
*   **Memory Complexity**: Memory usage is reduced by approximately 2x for activations and gradients, allowing for larger batch sizes or higher resolution sampling [S1, unofficial].
*   **Measured Performance**: On the NeRF Blender dataset (e.g., 'lego' scene), mixed precision training achieves comparable PSNR to FP32 training in fewer wall-clock hours [S2, unofficial].
*   **Scaling**: Performance scales well with batch size and resolution, limited primarily by GPU memory and tensor core occupancy [S1, unofficial].
*   **Strengths**: Significant speedup, reduced memory footprint, no need for manual precision management.
*   **Limitations**: Potential numerical instability if not properly scaled; compatibility issues with older PyTorch versions or non-CUDA hardware; some operations (e.g., certain normalization layers) may still require FP32.
*   **When to Use**: Standard for NeRF training on modern GPUs.
*   **When Not to Use**: On hardware without FP16 support (e.g., older GPUs, CPUs) or when debugging numerical issues where FP32 is required for stability.

## Background
Mixed Precision Training was popularized in deep learning by Micikevicius et al. (2017) "Mixed Precision Training" [S1, unofficial]. It has been adopted in NeRF implementations (e.g., Instant-NGP, NeRF-W) to accelerate the computationally intensive volume rendering and optimization loops. The method is now a standard component in modern NeRF training pipelines [S2, unofficial].
