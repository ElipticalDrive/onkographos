# Training Configuration

Also called: Hyperparameter Configuration, Instant-NGP Training Setup, NGP Training Configuration, Optimization Configuration, Optimizer Settings, Training Configuration & Optimization Setup, Training Hyperparameters, VMesh Training Configuration

## Overview
Training Configuration defines the static hyperparameters, optimizer settings, and structural constraints required to stabilize the optimization of differentiable volume rendering models. It solves the problem of translating theoretical radiance field formulations into convergent training procedures by specifying exact network architectures, sampling strategies, and loss weights. Unlike [Training Loop Setup](1522-training-loop-setup.md), which defines the dynamic runtime sequence of data loading and gradient updates, this method specifies the immutable parameters governing the optimization landscape. It differs from [Regularization and Priors](6281-regularization-and-priors.md) by focusing on the numerical optimization settings (e.g., learning rates, batch sizes) rather than the specific penalty terms added to the loss function.

## How it works
The configuration is applied at initialization and remains static throughout the training loop, except where explicitly modified by a [Training Schedule](3154-training-schedule.md) or [Learning Rate Scheduling](2701-learning-rate-scheduling.md).

### Inputs and Outputs
- **Inputs**: Scene geometry bounds, camera intrinsics/extrinsics, dataset resolution, target metrics (PSNR/SSIM).
- **Outputs**: Initialized optimizer state, model parameters, sampling parameters, loss weights.

### Data Structures and Layouts
The configuration typically consists of the following fields:

1.  **Optimizer Settings**:
    -   `optimizer_type`: String identifier (e.g., "Adam").
    -   `betas`: Tuple $(\beta_1, \beta_2)$.
    -   `eps`: Float, numerical stability constant.
    -   `weight_decay`: Float multiplier.
    -   `lr_embeddings`: Float, learning rate for positional embeddings or voxel grids.
    -   `lr_network`: Float, learning rate for MLP weights.

2.  **Sampling Parameters**:
    -   `batch_size`: Integer, number of rays or points per iteration.
    -   `num_samples_coarse`: Integer, steps in coarse stage.
    -   `num_samples_fine`: Integer, steps in fine stage.
    -   `step_size_ratio`: Float, ratio of voxel size to step size (e.g., 0.5).

3.  **Loss Weights**:
    -   `w_photo`: Float, weight for photometric reconstruction loss.
    -   `w_distortion`: Float, weight for distortion regularizer.
    -   `w_eikonal`: Float, weight for eikonal regularizer.
    -   `w_sparsity`: Float, weight for sparsity regularizer.

4.  **Model Architecture Constraints**:
    -   `hidden_dim`: Integer, MLP hidden layer size.
    -   `num_layers`: Integer, number of MLP layers.
    -   `grid_resolution`: Integer or List, resolution of hash grids or voxel grids.

### Numbered Steps for Initialization

1.  **Initialize Optimizer**:
    Create an Adam optimizer instance. If multiple parameter groups exist (e.g., embeddings vs. network weights), assign different learning rates.
    $$ \text{Adam}(\theta, \text{lr}=\text{lr}_0, \beta_1=0.9, \beta_2=0.99, \epsilon=10^{-15}) $$
    [S7, unofficial]

2.  **Initialize Learning Rate Scheduler**:
    Configure a scheduler to decay the learning rate. Common strategies include exponential decay or linear decay to a target fraction.
    $$ \text{lr}(t) = \text{lr}_{init} \times \gamma^{\lfloor t / \text{decay\_interval} \rfloor} $$
    [S2]

3.  **Set Sampling Step Sizes**:
    Define the step size $\delta$ for ray marching based on the voxel size $s$.
    $$ \delta = 0.5 \times s $$
    [S2]

4.  **Initialize Alpha Values (Voxel Grids)**:
    For voxel-based representations, initialize the opacity/alpha values.
    -   Coarse stage: $\alpha_{init} = 10^{-6}$ [S2]
    -   Fine stage: $\alpha_{init} = 10^{-2}$ [S2]

5.  **Configure Loss Weights**:
    Set the weights for the composite loss function.
    $$ \mathcal{L} = w_{photo}\mathcal{L}_{photo} + w_{distortion}\mathcal{L}_{distortion} + \dots $$
    [S4]

### Pseudocode

```python
def initialize_training_configuration(
    model: NeRFModel,
    dataset: Dataset,
    config: dict
) -> tuple[Optimizer, Scheduler, dict]:
    """
    Initializes the optimizer, scheduler, and loss configuration for NeRF training.
    
    Args:
        model: The neural radiance field model.
        dataset: The training dataset.
        config: Dictionary containing hyperparameters.
        
    Returns:
        optimizer: The configured optimizer.
        scheduler: The learning rate scheduler.
        loss_config: Dictionary of loss weights.
    """
    # 1. Extract parameters from config
    lr_embeddings = config.get('lr_embeddings', 2e-2)
    lr_network = config.get('lr_network', 1e-3)
    betas = config.get('betas', (0.9, 0.99))
    eps = config.get('eps', 1e-15)
    weight_decay = config.get('weight_decay', 1e-9)
    
    # 2. Get parameters for optimizer
    # model.get_params typically separates embedding/grid params from MLP params
    params = model.get_params(lr_embeddings, lr_network)
    
    # 3. Initialize Adam Optimizer
    optimizer = torch.optim.Adam(
        params,
        lr=lr_network, # Base LR, adjusted per group if needed
        betas=betas,
        eps=eps,
        weight_decay=weight_decay
    )
    
    # 4. Initialize Scheduler
    # Example: Linear decay to 10% of initial LR over total iterations
    total_iters = config.get('total_iters', 30000)
    scheduler = torch.optim.lr_scheduler.LambdaLR(
        optimizer,
        lr_lambda=lambda iter: 0.1 ** min(iter / total_iters, 1.0)
    )
    
    # 5. Configure Loss Weights
    loss_config = {
        'w_photo': config.get('w_photo', 1.0),
        'w_distortion': config.get('w_distortion', 0.0), # Often 0 for vanilla NeRF
        'w_eikonal': config.get('w_eikonal', 0.0),
        'w_sparsity': config.get('w_sparsity', 0.0)
    }
    
    return optimizer, scheduler, loss_config
```

### Edge Cases and Pitfalls
-   **Precision**: Use `eps=10^{-15}` for Adam to avoid division by zero in gradient normalization for sparse gradients [S7, unofficial].
-   **Boundary Conditions**: Ensure sampling step sizes are consistent with voxel sizes to avoid aliasing or gaps [S2].
-   **Degenerate Input**: If the scene is unbounded, ensure the `bound` parameter is set correctly to invoke adaptive ray marching [S7, unofficial].

### Randomized Background Colors
-   **Definition**: During training, a random RGB background color is drawn from $[0, 1]^3$ when compositing pixel color. This encourages the model to reconstruct a fully opaque background, avoiding semi-transparent artifacts [S8].
-   **Parameter**: Test-time background color is set to $(0.5, 0.5, 0.5)$ [S8].
-   **Usage**: Used for the 360 dataset and LLFF dataset. The Blender dataset uses a fixed white background [S8].

### Blender Dataset Simplified Configuration
-   **Parameters**: One round of sampling, 128 samples for proposal MLP, 32 samples for NeRF MLP. Proposal MLP: 4 layers, 256 hidden units. NeRF MLP: 8 layers, 256 (or 512) hidden units. Axis-aligned IPE. MSE loss. No distortion regularizer [S8].

### Checkpoint Loading and Resume Training
-   **Definition**: Load model and optimizer states from a checkpoint file to resume training or evaluation [S9, unofficial].
-   **Steps**:
    1.  Load model state dictionary.
    2.  Load optimizer state dictionary.
    3.  Load gradient scaler state if used.
    4.  Extract start iteration from checkpoint [S9, unofficial].

### LLFF Training Configuration
-   **Parameters**: Distortion regularizer is not disabled. Charbonnier loss is used instead of MSE [S8].
-   **Performance**:
    -   256 hidden units: PSNR 26.68, SSIM 0.847, LPIPS 0.150, Time 2.39 hrs, Params 0.84M [S8].
    -   512 hidden units: PSNR 26.86, SSIM 0.858, LPIPS 0.128, Time 3.84 hrs, Params 3.23M [S8].
-   **Comparison**: Does not outperform mip-NeRF in PSNR but yields improved SSIM and LPIPS metrics and significant speedup for large MLPs [S8].

### View Sampler
-   **Definition**: Abstract base class for sampling context and target views during training or inference [S10, unofficial].
-   **Parameters**: `stage` (training/validation), `is_overfitting` (bool), `cameras_are_circular` (bool), `step_tracker` (optional) [S10, unofficial].
-   **Layout**: Context view indices tensor shape: `Int64[Tensor, "context_view"]`. Target view indices tensor shape: `Int64[Tensor, "target_view"]` [S10, unofficial].

### NeuralVDB Hyperparameter Configuration
-   **Steps**: Batch sampling strategy: Either draw $2^{16}$ random samples per epoch, or resample a subset of input voxels at fixed intervals and draw $2^{12}$ batches per epoch. Resampling subset size = resampling intervals (100 or 500) $\times$ batch size. Use resampling when fine details with thin structures are critical [S11, unofficial].
-   **Parameters**:
    -   Subdomain size: Multiple of 512. Too large wastes compute; too small increases dispatch overhead [S11, unofficial].
    -   Network width: Level-1 networks use half the width of level-0 networks. Default: level-0 width 128, depth 3. Use 4 layers for complex volumes [S11, unofficial].
    -   Optimizer: Adam. Default LR: 0.001. Decay: 0.975 every 100 epochs (no resampling) or 0.75 every 1,000 epochs (with resampling). Max epochs: 2,500 for non-resampled [S11, unofficial].
-   **Comparison**: Sparse VDB with active voxel masks yields the best visual quality and low noise reconstruction compared to dense or block grids [S11, unofficial].

## Operating characteristics
-   **Time Complexity**: Depends on the number of iterations and batch size. Typical configurations use 25k–30k iterations [S3, S4].
-   **Memory Complexity**: Proportional to the number of voxels or grid resolution. For example, $M^{(c)} = 100^3$ and $M^{(f)} = 160^3$ voxels [S2].
-   **Performance**: On a single NVIDIA RTX 6000 Ada GPU, 30k iterations take approximately 2–4 hours for LLFF scenes [S4, S8].
-   **Strengths**: Stable convergence with Adam optimizer and appropriate LR scheduling.
-   **Limitations**: High memory usage for large voxel grids or hash tables. Sensitive to hyperparameter choices like learning rate and batch size.

## Background
Training configuration for NeRF and its variants has evolved from the original NeRF paper [S8] which used 500k iterations and a simple MSE loss. Subsequent works like Instant-NGP [S7, unofficial] introduced hash grids and specific learning rate schedules. Mip-NeRF 360 [S3] refined the configuration for unbounded scenes with anti-aliasing. Direct Voxel Grid Optimization [S2] simplified the configuration by optimizing voxel grids directly. NeuralVDB [S11, unofficial] introduced hierarchical sparse volumes with specific subdomain and network width configurations.
