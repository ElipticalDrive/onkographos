# Learning Rate Scheduling

Also called: LR Scheduling, LR decay, LambdaLR Scheduler, Learning Rate Decay, Learning Rate Scheduler

## Overview
Learning rate scheduling adjusts the optimizer's step size during the training of differentiable volume rendering methods to balance convergence speed and final reconstruction quality. It sets itself apart from static learning rate configurations by dynamically modifying parameters based on training progress, batch counts, or structural changes in the scene representation. This article covers the core scheduling mechanisms used in radiance-field optimization, including exponential decay, power-of-2 batch-dependent decay, and adaptive spikes following densification events.

## How it works
The method comprises several distinct scheduling strategies applied to different parameter groups (e.g., means, SH coefficients, NGP weights) depending on the specific rendering formulation (Gaussian Splatting, Neural Radiance Fields, or Mesh-based).

### Inputs and Outputs
*   **Inputs:** Current training step/iteration ($i$ or $t$), maximum steps ($maxSteps$), initial learning rate ($lr_{init}$ or $l(0)$), final learning rate ($lr_{final}$ or $l_{final}$), batch count per epoch ($batchCount$), current epoch ($epoch$), gamma ($\gamma$), step size for decay ($step\_size$), densification iteration ($I$), and spike duration ($L$).
*   **Outputs:** Updated learning rate value for the specific parameter group.

### Data Structures
No specific complex data structures are required beyond standard scalar variables for tracking state (current step, epoch). However, optimizers typically maintain separate learning rate groups for different parameter types (e.g., Adam group 0 for means, group 1 for SH coefficients).

### Scheduling Strategies

#### 1. Exponential Interpolation for Means (NeRF/Gaussian Splatting)
Used for optimizing position means (Adam group 0). The learning rate decays exponentially from an initial value to a final value based on the normalized training progress.

**Formula:**
$$ lr_{means}(t) = \exp( \log(lr_{init}) \cdot (1 - t) + \log(lr_{final}) \cdot t ) $$
where $t = \text{clamp}(step / maxSteps, 0, 1)$ [S1, unofficial].

**Parameters:**
*   $lr_{init}$: Initial learning rate for means.
*   $lr_{final}$: Final learning rate for means.
*   $maxSteps$: Total number of training steps.

#### 2. Power-of-2 Batch-Dependent Decay
Used for general learning rates and SH learning rates in some Plenoxels implementations. The learning rate is divided by a power of 2 after each batch, where the exponent depends on the batch count and current epoch.

**Formula:**
$$ LR_{new} = \frac{LR_{old}}{2^{\frac{1}{batchCount \cdot (epoch + 1)}}} $$
[S2, unofficial].

**Steps:**
1.  After processing each batch, calculate the decay factor: $factor = pow(2, 1. / (batchCount \cdot (epoch + 1.)))$.
2.  Update the learning rate: $config.learningRate = config.learningRate / factor$.
3.  Apply the same update to $config.shLearningRate$ [S2, unofficial].

#### 3. LambdaLR Scheduler (Step Decay)
A generic scheduler often implemented via `torch.optim.lr_scheduler.LambdaLR`. It applies a gamma-based decay every `step_size` epochs.

**Formula:**
$$ lr_{lambda}(epoch) = \gamma^{\frac{epoch}{step\_size}} $$
[S3, unofficial].

**Steps:**
1.  Define the lambda function: `lr_lambda = lambda epoch: gamma ** (epoch / step_size)`.
2.  Create the scheduler: `lr_scheduler = torch.optim.lr_scheduler.LambdaLR(optimizer, lr_lambda, last_epoch=start_epoch - 1)`.
3.  Call `lr_scheduler.step()` after each epoch [S3, unofficial].

**Parameters:**
*   $\gamma$ (`lr_scheduler_gamma`): Decay factor [S3, unofficial].
*   $step\_size$ (`lr_scheduler_step_size`): Number of epochs between decays [S3, unofficial].

#### 4. Linear Warmup/Cosine/Linear Interpolation (General)
Some configurations use linear interpolation between start and end values over a specific step range.

**Formula:**
$$ value = start\_value + (end\_value - start\_value) \cdot \max(\min(1.0, \frac{current\_step - start\_step}{end\_step - start\_step}), 0.0) $$
[S4, unofficial].

**Steps:**
1.  Parse configuration values: $start\_step, start\_value, end\_value, end\_step$.
2.  If the configuration is a list of length 3, prepend 0 to make it length 4 [S4, unofficial].
3.  Calculate the normalized progress within the interval $[start\_step, end\_step]$.
4.  Clamp the progress to $[0, 1]$.
5.  Interpolate the value [S4, unofficial].

#### 5. Learning Rate Spike (Densification-Aware)
Used in mesh-based volumetric reconstruction (Radiance Meshes) to handle rapid changes after densification events (e.g., adding new vertices/triangles). The learning rate is temporarily increased to allow the model to accommodate the new geometry.

**Formula:**
$$ spike(i) = \mathbb{1}\{i - I > 0\} \cdot (l(0) - l(I)) \cdot \exp\left(-\frac{6(i - I)}{L}\right) $$
where $i$ is the current iteration, $I$ is the iteration of densification, $l(0)$ is the initial learning rate, $l(I)$ is the learning rate at iteration $I$, and $L$ is the duration of the spike [S7, unofficial].

**Steps:**
1.  Identify the densification iteration $I$.
2.  Calculate the base decaying learning rate $l(i)$.
3.  Calculate the spike component using the formula above.
4.  Add the spike to the base learning rate: $lr_{total}(i) = l(i) + spike(i)$.
5.  The spike increases the rate back towards $l(0)$ and then decays exponentially over $L$ iterations [S7, unofficial].

**Parameters:**
*   $L$: Duration of the spike in iterations [S7, unofficial].

### Pseudocode

```python
import math

def compute_exponential_lr(step, max_steps, lr_init, lr_final):
    """
    Computes learning rate for means using exponential interpolation.
    """
    t = min(max(step / max_steps, 0.0), 1.0)
    return math.exp(math.log(lr_init) * (1 - t) + math.log(lr_final) * t)

def compute_power_of_2_decay_lr(current_lr, batch_count, epoch):
    """
    Computes new learning rate using power-of-2 batch-dependent decay.
    """
    exponent = 1.0 / (batch_count * (epoch + 1.0))
    decay_factor = math.pow(2, exponent)
    return current_lr / decay_factor

def compute_lambda_lr(epoch, gamma, step_size):
    """
    Computes learning rate using LambdaLR step decay.
    """
    return math.pow(gamma, epoch / step_size)

def compute_linear_interpolation_lr(current_step, start_step, end_step, start_value, end_value):
    """
    Computes learning rate using linear interpolation between steps.
    """
    if end_step == start_step:
        return start_value
    progress = (current_step - start_step) / (end_step - start_step)
    progress = max(0.0, min(1.0, progress))
    return start_value + (end_value - start_value) * progress

def compute_spike_lr(current_iteration, densification_iteration, initial_lr, lr_at_densification, duration):
    """
    Computes learning rate with a spike after densification.
    """
    if current_iteration <= densification_iteration:
        return lr_at_densification # Or base decay function l(i)
    
    # Calculate base decay l(i) - assuming l(i) is provided or computed separately
    # For the spike component:
    diff = initial_lr - lr_at_densification
    spike = diff * math.exp(-6.0 * (current_iteration - densification_iteration) / duration)
    
    # The total LR is base decay + spike. 
    # Note: The source implies adding the spike to the decaying rate.
    # If l(i) is the decaying rate at current_iteration:
    base_lr = lr_at_densification # Placeholder for actual l(i) calculation
    # In practice, l(i) should be the value from the decay schedule at i.
    # Here we assume l(i) is passed or computed. 
    # The formula adds the spike to l(i).
    return base_lr + spike

def update_sh_lr(current_sh_lr, batch_count, epoch):
    """
    Updates SH learning rate using power-of-2 decay.
    """
    return compute_power_of_2_decay_lr(current_sh_lr, batch_count, epoch)
```

### Edge Cases and Pitfalls
*   **Division by Zero:** In `compute_power_of_2_decay_lr`, if `batch_count` is 0 or `epoch` is -1, the exponent calculation may fail. Ensure `batch_count > 0` and `epoch >= 0` [S2, unofficial].
*   **Log of Zero/Negative:** In `compute_exponential_lr`, `lr_init` and `lr_final` must be positive. If they are zero or negative, `log()` will fail [S1, unofficial].
*   **Densification Timing:** The spike function is only active after densification ($i > I$). If densification does not occur, the spike term is zero [S7, unofficial].
*   **View-Count Prior:** In voxel grid optimization, ignoring view-count priors can lead to PSNR degradation up to -1.22. Learning rates should be adjusted based on view-count priors to mitigate this [S6].

## Subtopics

### View-count-based Learning Rate
Adjusts learning rates based on a view-count prior to prevent degradation in reconstruction quality. Without this prior, PSNR can degrade significantly (up to -1.22 in worst-case scenarios). It is chosen when using voxel grid representations where some regions are under-sampled [S6].

### Learning Rate Spike
A technique to increase the learning rate of specific parameters (instant NGP weights and vertex coordinates) after a densification event. It allows rapid accommodation for structural changes by adding an exponential decay spike on top of the base decay function. It is chosen when using mesh-based or densifying representations like Radiance Meshes [S7, unofficial].

## Operating characteristics
*   **Time Complexity:** The scheduling calculations are $O(1)$ per step/epoch, adding negligible overhead to the training loop.
*   **Memory Complexity:** $O(1)$ additional memory for storing state variables (current step, epoch, etc.).
*   **Performance:** Exponential interpolation [S1, unofficial] and LambdaLR [S3, unofficial] are standard and stable. Power-of-2 decay [S2, unofficial] provides a smooth, adaptive decay that depends on training dynamics (batch count). Spikes [S7, unofficial] can improve convergence after structural changes but require careful tuning of duration $L$.
*   **Strengths:** Adapts to different phases of training (exploration vs. exploitation); handles structural changes in the scene representation.
*   **Limitations:** Requires careful tuning of hyperparameters ($\gamma$, $L$, $step\_size$); improper scheduling can lead to divergence or slow convergence.
*   **When to Use:** Use exponential interpolation for standard NeRF/Gaussian Splatting training. Use power-of-2 decay for Plenoxels-like methods. Use spikes for densifying mesh-based methods. Use view-count-based scheduling for voxel grids [S6].

## Background
Learning rate scheduling is a fundamental technique in optimization, widely used in deep learning and differentiable rendering. In the context of volume rendering, it has been adapted to handle the unique challenges of radiance field optimization, such as the need to balance global structure learning with fine detail refinement. The exponential interpolation method [S1, unofficial] and LambdaLR scheduler [S3, unofficial] are common in PyTorch-based implementations. The power-of-2 decay [S2, unofficial] is specific to certain Plenoxels implementations. The learning rate spike [S7, unofficial] is a more recent addition for mesh-based volumetric reconstruction.
