# Linear Learning Rate Schedule

Also called: Linear Interpolation Schedule, LinearSchedule

## Overview
A linear learning rate schedule that transitions from an initial value to a final value over a specified number of steps [S1, unofficial]. It serves as a baseline optimizer configuration for NeRF training, providing a deterministic, continuous decay path [S1, unofficial][S2, unofficial]. Unlike exponential decay which changes rate multiplicatively, this method changes the learning rate additively per step [S1, unofficial][S2, unofficial].

## How it works
**Inputs:**
- `step`: Current optimization step index (integer, $\ge 0$).
- `initial_value` ($lr_{init}$): Starting learning rate [S1, unofficial][S2, unofficial].
- `final_value` ($lr_{final}$): Target learning rate at completion [S1, unofficial][S2, unofficial].
- `num_steps` ($N$): Total number of steps for the transition [S1, unofficial].
- `max_steps`: Total number of optimization steps (often equal to `num_steps`) [S2, unofficial].
- `lr_delay_steps` ($D$): Number of steps to apply a modified initial rate (optional, default 0) [S2, unofficial].
- `lr_delay_mult` ($M$): Multiplier for the initial learning rate during the delay phase (optional, default 1.0) [S2, unofficial].

**Outputs:**
- `current_lr`: The computed learning rate for the current step [S1, unofficial][S2, unofficial].

**Data Structures:**
No persistent data structures are required. The state is purely a function of the current `step` and the hyperparameters.

**Steps:**
1. **Clamp Step:** Ensure `step` does not exceed `num_steps`. If `step >= num_steps`, the schedule is complete and returns `final_value` [S1, unofficial].
2. **Calculate Progress:** Compute the progress ratio $\alpha$:
   $$ \alpha = \min\left(\frac{\text{step}}{\text{num\_steps}}, 1.0\right) $$
3. **Linear Interpolation:** Compute the base learning rate by interpolating between `initial_value` and `final_value`:
   $$ lr_{base} = (1.0 - \alpha) \cdot lr_{init} + \alpha \cdot lr_{final} $$
4. **Delay Handling (Optional):** If `lr_delay_steps` > 0:
   - If `step < lr_delay_steps`:
     $$ lr = lr_{init} \cdot lr_{delay\_mult} $$
   - Else:
     $$ lr = lr_{base} $$
   [S2, unofficial]
5. **Return:** Return `lr` [S1, unofficial][S2, unofficial].

**Pseudocode:**
```python
def linear_schedule(step, initial_value, final_value, num_steps, 
                    lr_delay_steps=0, lr_delay_mult=1.0):
    """
    Compute the learning rate for a given step using a linear schedule.
    
    Args:
        step: Current optimization step (int).
        initial_value: Starting learning rate (float).
        final_value: Final learning rate (float).
        num_steps: Total steps for the transition (int).
        lr_delay_steps: Steps to apply delayed initial rate (int, default 0).
        lr_delay_mult: Multiplier for initial rate during delay (float, default 1.0).
        
    Returns:
        float: The computed learning rate.
    """
    # Step 1: Clamp step to num_steps
    if step >= num_steps:
        return final_value
    
    # Step 2: Calculate progress alpha
    alpha = min(step / num_steps, 1.0)
    
    # Step 3: Linear interpolation
    lr_base = (1.0 - alpha) * initial_value + alpha * final_value
    
    # Step 4: Delay handling
    if lr_delay_steps > 0 and step < lr_delay_steps:
        return initial_value * lr_delay_mult
    
    # Step 5: Return result
    return lr_base
```

**Parameters with Typical Values:**
- `initial_value`: Typically $5 \times 10^{-5}$ to $1 \times 10^{-4}$ for NeRF [S1, unofficial][S2, unofficial].
- `final_value`: Typically $1 \times 10^{-5}$ to $5 \times 10^{-6}$ [S1, unofficial][S2, unofficial].
- `num_steps`: Equal to the total training steps (e.g., 500,000) [S1, unofficial][S2, unofficial].
- `lr_delay_steps`: Often 0 or small values like 1000 [S2, unofficial].
- `lr_delay_mult`: Often 0.1 or 0.01 if delay is used [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Division by Zero:** If `num_steps` is 0, the schedule is undefined. Ensure `num_steps > 0` [G].
- **Step Indexing:** Ensure `step` starts at 0. If 1-indexed, adjust $\alpha$ calculation accordingly [G].
- **Precision:** Use float32 or float64 for `initial_value` and `final_value` to avoid precision loss in interpolation [G].
- **Boundary Conditions:** At `step=0`, `lr` should equal `initial_value` (or `initial_value * lr_delay_mult` if delay is active) [S2, unofficial]. At `step=num_steps`, `lr` should equal `final_value` [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per step. The computation involves basic arithmetic operations [S1, unofficial][S2, unofficial].
- **Memory Complexity:** $O(1)$. No additional memory is required beyond the hyperparameters [S1, unofficial][S2, unofficial].
- **Measured Performance:** Linear schedules are commonly used in NeRF training as a stable baseline [S1, unofficial][S2, unofficial]. They provide a smooth transition from exploration (high LR) to exploitation (low LR) [S1, unofficial].
- **Scaling:** The schedule scales linearly with the number of steps. Increasing `num_steps` slows down the decay rate [S1, unofficial].
- **Strengths:** Simple to implement, predictable, and easy to tune [S1, unofficial][S2, unofficial].
- **Limitations:** May not adapt as well to complex loss landscapes as more sophisticated schedules (e.g., cosine or exponential) [S1, unofficial][S2, unofficial].
- **When to Use:** When a simple, deterministic decay is desired, or as a baseline for comparison [S1, unofficial][S2, unofficial].
- **When Not to Use:** When the training dynamics require more nuanced adaptation, such as in very long training runs or complex scenes [S1, unofficial][S2, unofficial].

## Background
The linear learning rate schedule is a standard technique in optimization, widely used in deep learning including NeRF training [S1, unofficial][S2, unofficial]. It was popularized in the context of NeRF by the Nerfies project [S1, unofficial]. The variant with delay is described in the density_bounded_ray_weights repository [S2, unofficial].
