# S3IM (Stochastic Structural SIMilarity)

Also called: Multiplex Loss, S3IM loss

## Overview
S3IM is a multiplex loss function for neural fields that captures nonlocal structural similarity by processing multiple data points (pixels/rays) as a whole set, rather than individually [S1]. It addresses the limitation of point-wise losses (like MSE) which fail to use collective supervision of distant pixels [S1]. Unlike conventional MSE loss which is computed pixel-wisely, S3IM cannot be expressed as the sum of any other loss computed over individual pixels from the batch [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A minibatch of rays $\mathcal{R}$, ground-truth pixel colors $\mathcal{C}$, rendered pixel colors $\hat{\mathcal{C}}$, model parameters $\Theta$, hyperparameter $\lambda$, number of stochastic estimations $M$, kernel size $K$, and stride size $s$.
*   **Outputs:** The total multiplex loss $L_{\mathrm{M}}(\Theta)$ and its gradient $\nabla L_{\mathrm{M}}(\Theta)$ for parameter update.

**Data Structures:**
*   $\mathcal{R}$: Set of rays.
*   $\mathcal{C}$: Set of ground-truth color vectors $\mathbf{C}(\mathbf{r})$ for $\mathbf{r} \in \mathcal{R}$.
*   $\hat{\mathcal{C}}$: Set of rendered color vectors $\hat{\mathbf{C}}(\mathbf{r})$ for $\mathbf{r} \in \mathcal{R}$.
*   $\mathcal{P}^{(m)}(\cdot)$: Stochastic patch generation function mapping a set of pixels to a 2D patch representation for the $m$-th iteration.

**Numbered Steps:**
1.  Sample a data minibatch of rays $\mathcal{R}$ from the dataset. Obtain ground-truth pixels $\mathcal{C} = \{\mathbf{C}(\mathbf{r}) | \mathbf{r} \in \mathcal{R}\}$ and compute rendered pixels $\hat{\mathcal{C}} = \{\hat{\mathbf{C}}(\mathbf{r}) | \mathbf{r} \in \mathcal{R}\}$ [S1].
2.  Loop $m$ from 1 to $M$ (number of stochastic estimations) [S1]:
    a. Initialize stochastic patch generation function $\mathcal{P}^{(m)}$ [S1].
    b. Transform rendered pixels into rendered stochastic patch $\mathcal{P}^{(m)}(\hat{\mathcal{C}})$ and ground-truth pixels into ground-truth stochastic patch $\mathcal{P}^{(m)}(\mathcal{C})$ [S1].
    c. Compute SSIM between the stochastic patches using kernel size $K$ and stride $s$ [S1].
3.  Average the $M$ computed SSIM values to obtain the final S3IM loss value $L_{\mathrm{S3IM}}$ [S1].
4.  Compute the conventional MSE loss $L_{\mathrm{MSE}}$ over the batch [S1].
5.  Combine losses: $L_{\mathrm{M}}(\Theta) = L_{\mathrm{MSE}} + \lambda L_{\mathrm{S3IM}}$ [S1].
6.  Compute gradient $\nabla L_{\mathrm{M}}(\Theta)$ and update model parameters $\Theta$ [S1].

**Formulas:**
The total multiplex loss is defined as [S1]:
$$
L_{\mathrm{M}} (\Theta ) = \frac {1}{\|\mathcal {R}\|}\sum _{\bm {r}\in \mathcal {R}} l_{\MSE }(\Theta , \bm {r}) + \lambda L_{\SSSIM }(\Theta , \mathcal {R})
$$
where $\lambda$ is a hyperparameter adjusting the importance of S3IM [S1].

The S3IM value is computed as the average of $M$ SSIM estimators over stochastic patches [S1]:
$$
L_{\SSSIM }(\hat {\mathcal {R}},\mathcal {R}) = 1 - \frac {1}{M} \sum _{m=1}^{M} \SSIM (\mathcal{P}^{(m)}(\hat {\mathcal {C}}), \mathcal{P}^{(m)}(\mathcal {C}))
$$
Note: The source defines $L_{\mathrm{S3IM}}$ as $1 - \text{average SSIM}$ in Algorithm 1 line 12 [S1], while the text formula uses $L_{\mathrm{S3IM}}$ directly. The SSIM index range is $[-1, 1]$, so $1 - \text{SSIM}$ maps it to a loss range where lower is better [S1].

SSIM is defined as the product of luminance, contrast, and structure terms [S1]:
$$
\SSIM (a, b) = l(\bm {a}, \bm {b}) c(\bm {a}, \bm {b}) s(\bm {a}, \bm {b})
$$
The luminance, contrast, and structure comparison terms are [S1]:
$$
l(\bm {a}, \bm {b}) = \frac {2\mu _{a}\mu _{b} + C_{1}}{\mu _{a}^{2} + \mu _{b}^{2} + C_{1}}
$$
$$
c(\bm {a}, \bm {b}) = \frac {2\sigma _{a}\sigma _{b} + C_{2}}{\sigma _{a}^{2} + \sigma _{b}^{2} + C_{2}}
$$
$$
s(\bm {a}, \bm {b}) = \frac {\sigma _{ab} + C_{3}}{\sigma _{a}\sigma _{b} + C_{3}}
$$
where $\mu_a, \mu_b$ are means, $\sigma_a, \sigma_b$ are standard deviations, and $\sigma_{ab}$ is covariance of patches $a$ and $b$ [S1].

**Parameters:**
*   Constants for SSIM: $C_1 = (K_1 L)^2$, $C_2 = (K_2 L)^2$, $C_3 = C_2 / 2$ [S1].
*   Typical values: $K_1 = 0.01$, $K_2 = 0.03$, $L = 1$ for RGB images [S1].
*   Batch size $B$: Number of rays/pixels per minibatch. Typical value: 1024 [S1].
*   Kernel size $K$: Size of the local window for SSIM computation. Typical value: $4 \times 4$ [S1].
*   Iterations $M$: Number of times steps 1 and 2 are repeated to average the SSIM estimates. Default value: 10 [S1].
*   Stride size $s$: Set to $K$ to ensure independent samples [S1].

**Pitfalls:**
*   Stochastic sampling breaks positional relationships. The method accounts for this by treating the sampled pixels as a 'stochastic patch' rather than a spatially coherent image patch, and using non-overlapping strides ($s=K$) to ensure independent samples within the batch [S1].

**Pseudocode:**
```python
def compute_s3im_loss(rendered_pixels, ground_truth_pixels, batch_size, kernel_size, num_iterations, lambda_weight):
    """
    Computes the multiplex loss combining MSE and S3IM.
    
    Args:
        rendered_pixels: List of color vectors [r, g, b] for each ray in the batch.
        ground_truth_pixels: List of color vectors [r, g, b] for each ray in the batch.
        batch_size: Number of rays in the batch (len(rendered_pixels)).
        kernel_size: Integer, size of the square kernel (e.g., 4).
        num_iterations: Integer, M, number of stochastic estimations.
        lambda_weight: Float, lambda, weight of S3IM loss.
        
    Returns:
        total_loss: Float, the combined loss value.
    """
    
    # Step 1: Compute MSE Loss
    mse_sum = 0.0
    for r_gt, r_pred in zip(ground_truth_pixels, rendered_pixels):
        # l_MSE is squared error per pixel
        diff = [r_gt[i] - r_pred[i] for i in range(3)]
        mse_sum += sum(d*d for d in diff)
    
    mse_loss = mse_sum / batch_size
    
    # Step 2: Compute S3IM Loss
    ssim_sum = 0.0
    
    for m in range(num_iterations):
        # Initialize stochastic patch generation
        # The source states pixels are randomly formed into a patch.
        # Since the batch is a set of independent rays, we treat the batch itself
        # as the source of pixels for the stochastic patch.
        # We assume the batch size B is sufficient to form a patch of size KxK or larger.
        # If B < K*K, this step is undefined in sources. We assume B >= K*K.
        
        # Transform pixels into stochastic patches
        # The source implies a random selection or reshaping into a 2D structure.
        # Given the stochastic nature and stride=K, we simply compute SSIM
        # on the entire batch treated as a single patch if B == K*K,
        # or average over non-overlapping windows if B > K*K.
        # However, the source says "randomly form a rendered patch... and corresponding ground-truth".
        # And "stride size s=K".
        # Algorithm 1 line 9-10: Compute SSIM(P(m)(C_hat), P(m)(C)) with kernel KxK and stride K.
        
        # Implementation detail:
        # To simulate the stochastic patch, we can randomly shuffle the batch indices
        # and then compute local statistics over windows of size KxK with stride K.
        # If the batch size is not a multiple of K*K, the remaining pixels are ignored
        # or handled as per standard SSIM implementation (usually ignored or padded).
        # The source does not specify padding. We assume B is a multiple of K*K for simplicity
        # or that the SSIM function handles the remainder by ignoring it.
        
        # Let's assume we reshape the batch into a 2D grid of size (B//K) x K? 
        # No, the source says "randomly form". This implies the spatial arrangement is arbitrary.
        # A simple interpretation is: Shuffle the list of pixels, then compute SSIM
        # on the resulting 2D array of shape (sqrt(B), sqrt(B)) if B is a square,
        # or more generally, compute local statistics over windows of size KxK.
        
        # Given the constraint "no placeholders", we must define the patch formation.
        # The most robust interpretation of "randomly form a patch" with stride K is:
        # 1. Shuffle the batch indices.
        # 2. Reshape the shuffled pixels into a 2D image of size H x W such that H*W >= B.
        #    Or, more likely, treat the batch as a set of pixels and compute SSIM
        #    over non-overlapping windows of size KxK drawn from this set.
        #    Since the source emphasizes "nonlocal" and "stochastic", the exact spatial
        #    arrangement doesn't matter as long as the local statistics are computed
        #    over groups of K*K pixels.
        
        # Let's implement a generic SSIM computation over non-overlapping windows.
        # We assume the batch pixels are arranged into a 2D grid for the purpose of
        # computing local statistics. The source says "randomly form", so we shuffle.
        
        indices = list(range(batch_size))
        shuffle(indices) # Random permutation
        
        # We need to compute SSIM. SSIM requires mean, var, cov over a window.
        # We will compute SSIM over non-overlapping windows of size KxK.
        # Total pixels used = (B // (K*K)) * (K*K).
        
        num_windows = batch_size // (kernel_size * kernel_size)
        current_ssim = 0.0
        
        for w in range(num_windows):
            # Extract window pixels
            start_idx = w * kernel_size * kernel_size
            window_indices = indices[start_idx : start_idx + kernel_size * kernel_size]
            
            gt_window = [ground_truth_pixels[i] for i in window_indices]
            pred_window = [rendered_pixels[i] for i in window_indices]
            
            # Compute local statistics for the window
            # Flatten to 1D lists of values for R, G, B channels
            gt_vals = [val for pixel in gt_window for val in pixel]
            pred_vals = [val for pixel in pred_window for val in pixel]
            
            # Compute mean
            mu_gt = sum(gt_vals) / len(gt_vals)
            mu_pred = sum(pred_vals) / len(pred_vals)
            
            # Compute variance and covariance
            # sigma^2 = E[x^2] - (E[x])^2
            # sigma_ab = E[ab] - E[a]E[b]
            
            sum_sq_gt = sum(v*v for v in gt_vals)
            sum_sq_pred = sum(v*v for v in pred_vals)
            sum_prod = sum(g*p for g, p in zip(gt_vals, pred_vals))
            
            n = len(gt_vals)
            
            var_gt = sum_sq_gt / n - mu_gt * mu_gt
            var_pred = sum_sq_pred / n - mu_pred * mu_pred
            cov = sum_prod / n - mu_gt * mu_pred
            
            # Constants
            K1 = 0.01
            K2 = 0.03
            L = 1.0
            C1 = (K1 * L) ** 2
            C2 = (K2 * L) ** 2
            C3 = C2 / 2.0
            
            # Luminance
            l_term = (2 * mu_gt * mu_pred + C1) / (mu_gt**2 + mu_pred**2 + C1)
            
            # Contrast
            # Avoid division by zero if variances are 0
            sigma_gt = math.sqrt(max(var_gt, 0))
            sigma_pred = math.sqrt(max(var_pred, 0))
            
            c_term = (2 * sigma_gt * sigma_pred + C2) / (sigma_gt**2 + sigma_pred**2 + C2)
            
            # Structure
            s_term = (cov + C3) / (sigma_gt * sigma_pred + C3)
            
            ssim_val = l_term * c_term * s_term
            current_ssim += ssim_val
            
        # Average SSIM over windows in this iteration
        if num_windows > 0:
            ssim_sum += current_ssim / num_windows
        else:
            # If batch is too small for even one window, SSIM is 0 or undefined.
            # We add 0 to sum.
            pass
            
    # Average SSIM over M iterations
    if num_iterations > 0:
        avg_ssim = ssim_sum / num_iterations
    else:
        avg_ssim = 0.0
        
    # S3IM Loss is 1 - SSIM (to make it a loss where lower is better)
    s3im_loss = 1.0 - avg_ssim
    
    # Total Multiplex Loss
    total_loss = mse_loss + lambda_weight * s3im_loss
    
    return total_loss
```

### Multiplex Training via S3IM
The broader training framework that incorporates S3IM. It sets apart by processing multiple nonlocal inputs as a whole multiplex input. Choose when structural similarity is more important than pixel-wise accuracy. [10894-multiplex-training-via-s3im.md](10894-multiplex-training-via-s3im.md)

## Operating characteristics
*   **Time Complexity**: The method requires $M$ iterations of SSIM computation per batch. SSIM computation is $O(K^2)$ per window. With batch size $B$ and stride $K$, there are $B/K^2$ windows. Total time per batch is $O(M \cdot B)$.
*   **Memory Complexity**: $O(B)$ to store the batch pixels.
*   **Measured Performance**: The improvements of quality metrics can be particularly significant for difficult tasks. E.g., test MSE loss unexpectedly drops by more than 90% for TensoRF and DVGO over eight novel view synthesis tasks [S1].
*   **Strengths**: Captures nonlocal structural similarity; improves quality metrics significantly; nearly free computational overhead compared to MSE.
*   **Limitations**: Stochastic sampling breaks positional relationships; requires careful handling of batch size and kernel size to ensure independent samples.
*   **When to use**: When structural similarity is critical and point-wise losses are insufficient.
*   **When not**: When computational resources are extremely limited and $M$ iterations are too expensive.

## Background
S3IM was proposed in the paper "S3IM: Stochastic Structural SIMilarity and Its Unreasonable Effectiveness for Neural Fields" [S1]. It is the first nonlocal multiplex training paradigm for NeRF and relevant neural field methods via a novel Stochastic Structural SIMilarity (S3IM) loss [S1].
