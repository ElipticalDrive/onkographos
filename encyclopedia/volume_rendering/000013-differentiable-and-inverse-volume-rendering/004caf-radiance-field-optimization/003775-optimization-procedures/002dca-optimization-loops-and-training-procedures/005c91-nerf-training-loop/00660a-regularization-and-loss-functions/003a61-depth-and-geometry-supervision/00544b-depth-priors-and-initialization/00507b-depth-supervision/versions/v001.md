# Depth Supervision

Also called: Depth Prior Supervision, Monocular Depth Supervision

## Overview
Depth supervision is a training technique that improves reconstructed geometry and reduces floating artifacts by providing depth priors derived from off-the-shelf monocular depth estimation models [S1, unofficial]. It distinguishes itself from sibling methods like [Single-view NeRF Training with Depth Map](8679-single-view-nerf-training-with-depth-map.md) by focusing on refining existing radiance-field optimizations through external geometric priors rather than relying solely on multi-view consistency or specific single-view architectures [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A dataset containing color images and corresponding depth maps; a current geometric representation (e.g., point cloud or Gaussian splats); a boolean flag `use_depth_loss`.
*   **Outputs:** Updated geometric parameters with improved surface accuracy and reduced floaters.

**Data Structures and Layout:**
*   **Depth Map Storage:** Depth priors are stored in a directory structure relative to the dataset root: `<dataset-root>/depths/<FILENAME>.png`, where `<FILENAME>` matches the name of the corresponding dataset image [S1, unofficial].
*   **Optimization Parameters:** The method is controlled via an `OptimizationParams` structure containing the boolean field `use_depth_loss` [S1, unofficial].

**Steps:**
1.  **Enable Supervision:** Set `use_depth_loss = true` in the optimization parameters [S1, unofficial].
2.  **Refit Depth Maps:** Since depth estimates from off-the-shelf models may vary in scale between frames, all depth maps are refitted against the current prior point cloud to ensure a consistent scale [S1, unofficial].
3.  **Discard Invalid Priors:** Depth maps that fail the refitting process against the prior point cloud are discarded and excluded from the supervision loss calculation [S1, unofficial].
4.  **Compute Loss:** During training, the rendered depth is compared against the refitted depth priors to constrain the location of the surface [S1, unofficial].

**Pseudocode:**
```python
def apply_depth_suppression(dataset, gaussians, opt_params):
    if not opt_params.use_depth_loss:
        return

    # Load depth maps from <dataset-root>/depths/<FILENAME>.png
    depth_maps = load_depth_maps(dataset)
    
    # Get current prior point cloud for scale alignment
    prior_cloud = gaussians.get_point_cloud()
    
    valid_depths = []
    for i, depth_map in enumerate(depth_maps):
        # Refit depth map to match the scale of the prior point cloud
        try:
            refitted_depth = refit_depth_to_prior(depth_map, prior_cloud)
            valid_depths.append(refitted_depth)
        except RefitFailure:
            # Discard depth maps that fail refitting
            continue
            
    # Compute depth supervision loss using valid refitted depths
    # Note: Specific loss function formula (e.g., L1, SmoothL1) is not given in sources [G: assume standard L1 or similar differentiable loss]
    depth_loss = compute_depth_loss(rendered_depths, valid_depths)
    
    # Backpropagate depth_loss to update gaussians
    update_gaussians_with_gradient(depth_loss)
```

**Parameters:**
*   `use_depth_loss`: Boolean. Enables depth supervision during training. Default is typically `false` unless explicitly enabled [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Scale Variation:** Off-the-shelf depth estimators often produce depth maps with arbitrary scales. Failure to refit against a common prior (the current point cloud) leads to incorrect geometry [S1, unofficial].
*   **Invalid Priors:** Depth maps that cannot be refitted (e.g., due to severe occlusion or estimation errors) must be discarded to prevent introducing noise [S1, unofficial].

## Subtopics

### Refined Depth for Geometry Supervision
A lightweight depth-regularization objective that refines reconstructed geometry during per-scene training, improving local sharpness and depth consistency without sacrificing efficiency [S2, unofficial]. It is chosen when higher geometric fidelity is needed after initial initialization. It differs from basic depth supervision by deriving refined depths from rendered depths and input images during the per-scene optimization stage, rather than using external priors directly. It advances geometry supervision (i.e., $L_{refD}$) from rendered depths $\{D_i\}$ and associated input images, combining this loss with the original training loss (e.g., SVRaster) to improve geometric accuracy [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Adds overhead for loading depth maps and performing refitting per frame. The refitting step requires alignment with the current point cloud, which scales with the number of Gaussians/points [S1, unofficial].
*   **Memory Complexity:** Requires storing depth maps for all training images. The depth maps are typically stored as PNGs, adding storage overhead proportional to the dataset size [S1, unofficial].
*   **Performance:** Results in better geometry and a reduced number of floaters [S1, unofficial].
*   **Strengths:** Leverages state-of-the-art monocular depth estimators to provide strong geometric priors without requiring multi-view stereo or explicit 3D scans [S1, unofficial].
*   **Limitations:** Dependent on the quality of the off-the-shelf depth estimation model. Fails if depth maps cannot be refitted to the current scale [S1, unofficial].
*   **When to use:** When geometry is poor or floaters are present, and external depth priors are available [S1, unofficial].
*   **When not to use:** When depth maps are unavailable or when the scene has large scale variations that prevent consistent refitting [S1, unofficial].

## Background
Originating from techniques to improve Gaussian Splatting and radiance field reconstruction, depth supervision utilizes off-the-shelf depth estimation models (such as Depth-Anything) to provide geometric priors [S1, unofficial]. It is part of a broader trend of integrating external priors into differentiable rendering pipelines to enhance geometric accuracy [S1, unofficial]. The refined depth variant is associated with advancing structured priors for sparse-voxel surface reconstruction [S2, unofficial].
