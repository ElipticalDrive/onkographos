# Depth-Regularized Fine-Tuning

Also called: Regularized Fine-Tuning

## Overview
Depth-Regularized Fine-Tuning is a per-scene optimization procedure that refines 3D Gaussian Splatting (3DGS) primitives using dense, multi-view consistent ground truth depth maps as geometric priors. It addresses the limitation of feed-forward generalizable 3DGS methods in reconstructing whole indoor scenes by enhancing local sharpness and depth consistency. Unlike vanilla 3DGS which relies solely on photometric and structural similarity losses, this method explicitly minimizes the discrepancy between rendered and ground truth depth, achieving higher reconstruction accuracy with significantly shorter training times [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ input views with corresponding dense, multi-view consistent ground truth depth images $\{D^n\}_{n=1}^N$ and color images. The initial 3DGS primitives (positions, covariances, opacities, colors) are obtained from a feed-forward prediction phase [S1].
*   **Outputs:** Refined 3DGS primitives that preserve geometric accuracy and improve rendering quality [S1].

**Data Structures:**
*   $D^n_r$: Rendered depth map for view $n$, generated by differentiable rendering of the current 3DGS primitives.
*   $D^n$: Ground truth depth map for view $n$.
*   $L_{fcolor}$: Photometric loss (e.g., MSE) between rendered and input color images.
*   $L_{fssim}$: Structural Similarity (SSIM) loss between rendered and input color images.
*   $L_{fdepth}$: Depth regularization loss.

**Parameters:**
*   $\lambda_1$: Weight for SSIM loss in fine-tuning. Typical value: $0.2$ [S1].
*   $\lambda_2$: Weight for depth regularization loss in fine-tuning. Typical value: $0.1$ [S1].

**Steps:**
1.  **Render Depth:** For each view $n \in \{1, \dots, N\}$, render the depth map $D^n_r$ from the current 3DGS primitives using the standard alpha-blending depth equation [S1].
2.  **Compute Depth Loss:** Calculate the L1 norm difference between the rendered depth $D^n_r$ and the ground truth depth $D^n$ for all views:
    $$ L_{fdepth} = \frac{1}{N} \sum_{n=1}^N \| D^n_r - D^n \|_1 $$
    [S1]
3.  **Compute Color Losses:** Calculate the photometric loss $L_{fcolor}$ (typically MSE) and the SSIM loss $L_{fssim}$ between the rendered color images and the input color images [S1].
4.  **Compute Total Loss:** Combine the losses using the weighted formula:
    $$ L_{rft} = (1 - \lambda_1) L_{fcolor} + \lambda_1 L_{fssim} + \lambda_2 L_{fdepth} $$
    [S1]
5.  **Optimize:** Perform gradient descent to update the 3DGS primitives (positions, scales, rotations, opacities, colors) to minimize $L_{rft}$ [S1].

**Pseudocode:**
```python
def depth_regularized_fine_tuning(primitives, views, lambda1=0.2, lambda2=0.1, optimizer=None):
    """
    Refines 3DGS primitives using depth priors.
    
    Args:
        primitives: Current 3D Gaussian primitives (positions, covariances, etc.)
        views: List of view dictionaries containing 'color_image', 'depth_image', 'camera_params'
        lambda1: Weight for SSIM loss
        lambda2: Weight for depth loss
        optimizer: Optimizer for primitive parameters
        
    Returns:
        Refined primitives
    """
    N = len(views)
    
    for iteration in range(num_iterations):
        optimizer.zero_grad()
        
        total_loss = 0.0
        l_color = 0.0
        l_ssim = 0.0
        l_depth = 0.0
        
        for n in range(N):
            view = views[n]
            color_gt = view['color_image']
            depth_gt = view['depth_image']
            camera = view['camera_params']
            
            # Render color and depth from current primitives
            color_rendered, depth_rendered = render_primitives(primitives, camera)
            
            # Compute photometric loss (MSE)
            l_color += mse_loss(color_rendered, color_gt)
            
            # Compute SSIM loss
            l_ssim += ssim_loss(color_rendered, color_gt)
            
            # Compute depth regularization loss (L1)
            l_depth += l1_loss(depth_rendered, depth_gt)
            
        # Average losses over number of views
        l_color /= N
        l_ssim /= N
        l_depth /= N
        
        # Combine losses
        # L_rft = (1 - lambda1) * L_fcolor + lambda1 * L_fssim + lambda2 * L_fdepth
        loss = (1 - lambda1) * l_color + lambda1 * l_ssim + lambda2 * l_depth
        
        # Backpropagate and update
        loss.backward()
        optimizer.step()
        
    return primitives
```

**Edge Cases and Pitfalls:**
*   **Resolution Mismatch:** The method supervises the output on full resolution even if lower resolution maps are used for uninitialization, to encourage high-resolution renderings [S1].
*   **Depth Consistency:** The ground truth depth maps must be dense and multi-view consistent to serve as effective priors without harming rendering quality [S1].

## Subtopics

### Depth-Regularized Per-Scene Fine-Tuning
This variant refers to the specific application of the depth-regularized fine-tuning step after the feed-forward 3DGS prediction phase. It leverages the efficient and geometrically accurate initialization from the feed-forward pipeline to refine the entire scene’s 3DGS primitives. It is chosen when a competitive alternative to vanilla 3DGS is needed, offering significant improvement in reconstruction accuracy within considerably shorter training time [S1].

## Operating characteristics
*   **Time Complexity:** Significantly shorter training time compared to conventional per-scene optimized 3DGS approaches [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Outperforms existing generalizable 3DGS methods (e.g., pixelSplat, MVSplat, PixelGaussian) and provides a competitive alternative to vanilla 3DGS in whole-scene reconstructions, especially for indoor scenes [S1].
*   **Strengths:** Enhances rendering quality while preserving geometric accuracy; removes floaters effectively; reduces redundancy in overlapping regions when combined with fusion mechanisms [S1].
*   **Limitations:** Relies on the availability of dense, multi-view consistent ground truth depth maps [S1].

## Background
Originated in the FreeSplat++ method, which is tailored for generalizable 3D Gaussian Splatting for efficient indoor scene reconstruction. The approach was introduced to address challenges in reconstructing whole indoor scenes where previous fusion modules could not adequately remove floaters or redundancy. It builds on the feed-forward reconstruction of 3DGS primitives and adds a depth-regularized per-scene fine-tuning step to leverage geometric constraints [S1].
