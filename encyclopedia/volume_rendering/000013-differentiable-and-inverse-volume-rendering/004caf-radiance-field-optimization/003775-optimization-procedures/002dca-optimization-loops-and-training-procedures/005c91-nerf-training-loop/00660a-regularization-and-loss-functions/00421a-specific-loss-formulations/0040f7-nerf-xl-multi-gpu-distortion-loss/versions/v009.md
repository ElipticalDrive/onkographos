# NeRF-XL Multi-GPU Distortion Loss

Also called: Distributed Distortion Loss, Multi-GPU Distortion Aggregation

## Overview
This method computes the distortion regularization loss for NeRF-XL in a distributed multi-GPU setting, ensuring that the geometric penalty is calculated globally across all GPUs while maintaining identical outputs to a single-GPU implementation [S1]. It sets itself apart from standard distortion loss by introducing a communication protocol to aggregate auxiliary variables ($A$ and $D$) and transmittance ($T$) from all participating GPUs, allowing the loss to account for the full ray's probability distribution rather than just local segments [S1].

## How it works
The method operates within the NeRF-XL framework where rays are partitioned across $N$ GPUs [S1]. Each GPU $k$ processes a subset of ray segments. The distortion loss is derived from the variance of the depth distribution along the ray [S1]. To compute this globally, each GPU must aggregate statistics from all other GPUs.

**Inputs and Outputs:**
*   **Input:** Local transmittance $T_{k \to k+1}$, local color $\mathbf{C}_{k \to k+1}$ (used for context but not loss calculation directly in this specific algorithm step, though present in data signature), list of GPU indices $I = \{i_1, i_2, \dots, i_N\}$ representing the order of GPUs along the ray, local auxiliary variable $A_{k \to k+1}$, local depth moment $D_{k \to k+1}$, and local loss contribution $L_{k \to k+1}$ [S1].
*   **Output:** Global distortion loss $L_{1 \to N+1}$ [S1].

**Data Structures:**
The algorithm maintains global accumulators for the current GPU $k$:
*   $T_{1 \to i}$: Global transmittance up to segment $i$.
*   $A_{1 \to i}$: Global auxiliary variable (related to the first moment of depth).
*   $D_{1 \to i}$: Global depth moment (related to the second moment of depth).
*   $L_{1 \to N+1}$: Accumulated global distortion loss.

**Definitions:**
*   $T_{i \to j}$: Transmittance from GPU $i$ to GPU $j$.
*   $A_{i \to j}$: Auxiliary variable for segment $i \to j$, defined as $\int_{t_i}^{t_j} t \cdot T(t) \cdot \sigma(t) dt$ (conceptually, representing the weighted depth contribution) [S1].
*   $D_{i \to j}$: Depth moment for segment $i \to j$, defined as $\int_{t_i}^{t_j} t^2 \cdot T(t) \cdot \sigma(t) dt$ [S1].
*   $L_{i \to j}$: Local distortion loss contribution for segment $i \to j$, typically $A_{i \to j}^2 - D_{i \to j}$ or similar variance-based term, though the algorithm treats it as an input [S1].

**Algorithm Steps:**
1.  Initialize global accumulators: $T_{1 \to i} \leftarrow 1$, $A_{1 \to i} \leftarrow 0$, $D_{1 \to i} \leftarrow 0$, and $L_{1 \to N+1} \leftarrow 0$ [S1].
2.  Iterate through the list of GPU indices $I$ from $s = 1$ to $N$:
    a.  Let $i$ be the GPU index $I[s]$ [S1].
    b.  If $i \neq k$ (i.e., the current segment is not from the local GPU):
        i.  Gather $T_{i \to i+1}$ and $\mathbf{C}_{i \to i+1}$ from GPU $i$ with automatic differentiation disabled (to save memory/communication overhead for non-loss data if applicable, though color is gathered here) [S1].
        ii. Gather $A_{i \to k+1}$, $D_{i \to i+1}$, and $L_{i \to i+1}$ from GPU $i$ using a function `gather_loss(i)` [S1]. Note: The source notation $A_{i \to k+1}$ in the gather step seems to imply gathering the local $A$ of GPU $i$, but the update rule uses $A_{i \to i+1}$. Based on Algorithm 2's data signature, the input is $A_{k \to k+1}$, so the gather likely retrieves the local segment statistics $A_{i \to i+1}$ and $D_{i \to i+1}$ and $L_{i \to i+1}$ [S1]. The text says "gather $A_{i \to k+1}$", which is likely a typo for $A_{i \to i+1}$ or implies a cumulative gather, but the update step $A_{1 \to i} += T_{1 \to i} \times A_{i \to i+1}$ confirms we need the local segment's $A$ [S1]. We assume `gather_loss(i)` returns the local segment statistics $A_{i \to i+1}, D_{i \to i+1}, L_{i \to i+1}$ [S1].
    c.  If $i = k$, the local statistics $T_{k \to k+1}, A_{k \to k+1}, D_{k \to k+1}, L_{k \to k+1}$ are already available [S1].
    d.  Compute the cross-term $S_{1 \to i}$:
        $$ S_{1 \to i} = D_{k \to k+1} \times A_{1 \to i} - A_{k \to k+1} \times D_{1 \to i} $$
        *Note: The source uses $D_{k \to k+1}$ and $A_{k \to k+1}$ in the cross-term calculation for every step $i$. This implies that the "local" GPU's segment statistics are used as a reference for the cross-term interaction with the accumulated global prefix sums [S1].*
    e.  Update the global loss:
        $$ L_{1 \to N+1} \leftarrow L_{1 \to N+1} + T_{1 \to i} \times L_{i \to i+1} + T_{1 \to i} \times S_{1 \to i} $$
    f.  Update the global auxiliary variable $A$:
        $$ A_{1 \to i} \leftarrow A_{1 \to i} + T_{1 \to i} \times A_{i \to i+1} $$
    g.  Update the global depth moment $D$:
        $$ D_{1 \to i} \leftarrow D_{1 \to i} + T_{1 \to i} \times D_{i \to i+1} $$
    h.  Update the global transmittance $T$:
        $$ T_{1 \to i} \leftarrow T_{1 \to i} \times T_{i \to i+1} $$

**Pseudocode:**

```python
def compute_distortion_loss_local(k, N, I, T_local, A_local, D_local, L_local):
    """
    Computes the global distortion loss for the k-th GPU.
    
    Args:
        k: Current GPU index.
        N: Total number of GPUs.
        I: List of GPU indices in ray order.
        T_local: Transmittance of the local segment (k -> k+1).
        A_local: Auxiliary variable of the local segment.
        D_local: Depth moment of the local segment.
        L_local: Local loss contribution.
        
    Returns:
        L_global: The aggregated global distortion loss.
    """
    # Initialize global accumulators
    T_global = 1.0
    A_global = 0.0
    D_global = 0.0
    L_global = 0.0
    
    # Local segment stats
    T_i = T_local
    A_i = A_local
    D_i = D_local
    L_i = L_local
    
    # Note: The source algorithm iterates through all GPUs I.
    # For the local GPU k, we use local data. For others, we gather.
    # Since this is a single function representing the logic on GPU k,
    # we simulate the gather for non-local GPUs.
    
    for s in range(N):
        i = I[s]
        
        if i != k:
            # Gather data from remote GPU i
            # In a real implementation, this involves NCCL or similar communication
            # with autograd disabled for T and C, but enabled for loss-related vars?
            # The source says gather T, C with auto-grad disabled, and gather A, D, L using gather_loss.
            # We assume gather_loss returns the local segment stats for GPU i.
            T_i, _ = gather_remote_T_C(i) # C is gathered but not used in loss calc here
            A_i, D_i, L_i = gather_loss(i)
        else:
            # Use local data
            T_i = T_local
            A_i = A_local
            D_i = D_local
            L_i = L_local
            
        # Compute cross-term S
        # Source: S_{1->i} = D_{k->k+1} * A_{1->i} - A_{k->k+1} * D_{1->i}
        # Here, D_{k->k+1} and A_{k->k+1} refer to the LOCAL segment's stats (D_i, A_i)
        # because the loop is running on GPU k, and k is the "local" GPU for this context.
        # The notation in the source "D_{k->k+1}" inside the loop over i implies the local GPU's segment.
        S = D_i * A_global - A_i * D_global
        
        # Update global loss
        L_global += T_global * L_i + T_global * S
        
        # Update global auxiliary A
        A_global += T_global * A_i
        
        # Update global depth moment D
        D_global += T_global * D_i
        
        # Update global transmittance T
        T_global *= T_i
        
    return L_global
```

**Edge Cases and Pitfalls:**
*   **Precision:** Accumulating $A$ and $D$ across many GPUs can lead to precision loss if not handled carefully. Using double precision for accumulators is recommended [G].
*   **Synchronization:** All GPUs must synchronize after the gather steps to ensure consistent ordering and data availability [S1].
*   **Ray Ordering:** The list $I$ must be consistent across all GPUs for the same ray to ensure the prefix sums are computed correctly [S1].

## Operating characteristics
*   **Time Complexity:** $O(N)$ communication steps per ray, where $N$ is the number of GPUs. The computation per step is constant time [S1].
*   **Memory Complexity:** $O(1)$ additional memory per GPU for accumulators, plus communication buffers for gathered data [S1].
*   **Scalability:** The method is designed to scale to large captures (e.g., 25km$^2$ with 64 GPUs) by distributing the rendering and loss computation [S1].
*   **Strengths:** Ensures geometric consistency across GPU boundaries; identical output to single-GPU rendering [S1].
*   **Limitations:** Requires communication overhead for every ray; sensitive to network latency [S1].

## Background
The method was introduced in the NeRF-XL paper, which focuses on scaling NeRFs to large-scale scenes using multiple GPUs [S1]. It addresses the challenge of computing global geometric losses (like distortion) when the ray is split across multiple devices [S1].
