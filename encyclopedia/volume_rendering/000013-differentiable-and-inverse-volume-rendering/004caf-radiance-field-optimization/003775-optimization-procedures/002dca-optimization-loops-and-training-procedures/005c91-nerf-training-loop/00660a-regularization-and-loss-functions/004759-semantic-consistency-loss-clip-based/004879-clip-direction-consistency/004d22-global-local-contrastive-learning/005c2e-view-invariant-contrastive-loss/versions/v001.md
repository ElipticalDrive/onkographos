# View-invariant Contrastive Loss

Also called: Contrastive Learning Framework, Contrastive Loss, Latent Contrastive Loss

## Overview
This method regularizes the latent code of a generative NeRF to ensure it reflects 3D content variations without depending on 2D viewpoints, effectively disentangling 3D edits from camera views [S1]. It prevents optimization instability caused by latent codes that vary violently when input images are similar in appearance but differ in viewpoint [S1]. It builds on [Global-Local Contrastive Learning](13433-global-local-contrastive-learning.md) by specifically targeting the invariance of the latent representation across multi-view renderings.

## How it works
**Inputs:**
- $N$: Number of input views.
- $M$: Number of edited styles/images per view.
- $z_i^j$: Edit code (latent vector) extracted from the $i$-th input view's $j$-th edited image $S_i^j$.
- $\mathcal{N}_{\theta}$: The translated NeRF conditioned on the edit code.
- $\mathcal{E}$: Encoder used to extract edit codes from images.

**Outputs:**
- $\mathcal{L}_{\textrm {contr}}$: The scalar contrastive loss value.

**Data Structures:**
- Edit codes are vectors in $\mathbb{R}^{64}$ (based on the Gaussian distribution dimension specified in the source) [S1].
- Images are 2D tensors.

**Steps:**
1. **Render Multi-View Images:** Given an edit code $z_i^j$ derived from input view $i$ and edited image $S_i^j$, render a set of $N$ multi-view images $\{C_j^l\}_{l=0}^{N-1}$ using the translated NeRF $\mathcal{N}_{\theta}$ conditioned on $z_i^j$. Here, $l$ indexes the different camera viewpoints [S1].
2. **Extract Positive Codes:** Extract edit codes $\{z_j^l\}_{l=0}^{N-1}$ from the rendered images $\{C_j^l\}_{l=0}^{N-1}$ using the encoder $\mathcal{E}$. These represent the same 3D edit observed from different viewpoints [S1].
3. **Extract Negative Codes:** Extract edit codes $\{z_i^k\}_{k=0}^{M-1}$ from the original edited input images $\{S_i^k\}_{k=0}^{M-1}$ for the same view $i$, where $k \neq j$. These represent different edits for the same viewpoint [S1].
4. **Compute Loss:** Calculate the contrastive loss $\mathcal{L}_{\textrm {contr}}$ by minimizing the distance between the original code $z_i^j$ and the rendered codes $\{z_j^l\}$, while maximizing the distance between $z_i^j$ and the alternative edit codes $\{z_i^k\}$ [S1].

**Formula:**
The total contrastive loss is the sum of an attraction term ($\mathcal{L}_{\textrm {contr}}^{\textrm {att}}$) and a repulsion term ($\mathcal{L}_{\textrm {contr}}^{\textrm {rep}}$) [S1]:

$$
\mathcal {L}_{\textrm {contr}} = \mathcal {L}_{\textrm {contr}}^{\textrm {att}} + \mathcal {L}_{\textrm {contr}}^{\textrm {rep}}
$$

$$
\mathcal {L}_{\textrm {contr}}^{\textrm {att}} = \sum _{l=0}^{N-1}||{\mathbf {z}}^j_{i}-{\mathbf {z}}^j_{l}||_2^2
$$

$$
\mathcal {L}_{\textrm {contr}}^{\textrm {rep}} = \sum _{k=0}^{M-1}\max(0,\alpha -||{\mathbf {z}}^j_{i}-{\mathbf {z}}_{i}^k||_2^2)
$$

Where:
- $||\cdot||_2^2$ is the squared Euclidean distance.
- $\alpha$ is the margin hyperparameter [S1].
- $k \neq j$ [S1].

**Parameters:**
- $\alpha$ (Margin): A hyperparameter that encourages the difference in features between distinct edits. Not given in the sources.

**Pseudocode:**
```python
def view_invariant_contrastive_loss(z_i_j, rendered_images, edited_images_same_view, alpha):
    """
    Computes the view-invariant contrastive loss.
    
    Args:
        z_i_j: Tensor of shape (64,), the edit code from the i-th view, j-th edit.
        rendered_images: List of N tensors, each shape (H, W, C), rendered from translated NeRF conditioned on z_i_j.
        edited_images_same_view: List of M tensors, each shape (H, W, C), other edited images for the i-th view.
        alpha: Float, margin for the repulsion term.
        
    Returns:
        loss: Scalar tensor.
    """
    # Step 2: Extract edit codes from rendered images (positives)
    # Note: The encoder E is assumed to be defined elsewhere or part of the model.
    z_j_l_list = [encoder(img) for img in rendered_images]
    
    # Step 3: Extract edit codes from other edited images of the same view (negatives)
    # Exclude the current edit j if it is present in the list, though the source implies k != j
    # assuming edited_images_same_view contains {S_i^k} for k != j.
    z_i_k_list = [encoder(img) for img in edited_images_same_view]
    
    # Step 4a: Attraction term - minimize distance to same-edit, different-view codes
    attraction_loss = 0.0
    for z_j_l in z_j_l_list:
        dist = torch.sum((z_i_j - z_j_l) ** 2)
        attraction_loss += dist
        
    # Step 4b: Repulsion term - maximize distance to different-edit, same-view codes
    repulsion_loss = 0.0
    for z_i_k in z_i_k_list:
        dist = torch.sum((z_i_j - z_i_k) ** 2)
        # hinge loss: max(0, alpha - dist)
        repulsion_loss += torch.clamp(alpha - dist, min=0.0)
        
    return attraction_loss + repulsion_loss
```

**Edge Cases and Pitfalls:**
- **Encoder Consistency:** The encoder $\mathcal{E}$ must be consistent across the original edited images and the rendered images to ensure the latent space comparison is valid [S1].
- **Margin Selection:** If $\alpha$ is too small, the repulsion term may vanish; if too large, it may dominate the attraction term, leading to unstable training [S1].

## Operating characteristics
**Time and Memory Complexity:**
- The complexity depends on the number of views $N$ and edits $M$. The loss calculation involves $N$ forward passes through the encoder for positives and $M$ for negatives, plus $N$ forward passes through the NeRF for rendering.
- Not given in the sources.

**Measured Performance:**
- The method is used in the GenN2N framework for universal NeRF editing tasks including text-driven editing, colorization, super-resolution, and inpainting [S1].
- It ensures multi-view consistency of the edited NeRF [S1].

**Strengths and Limitations:**
- **Strengths:** Disentangles 3D content variations from camera viewpoints, preventing instability when input images are similar in appearance but different in viewpoints [S1]. Enables high-quality, multi-view consistent 3D scene generation from 2D edits [S1].
- **Limitations:** Relies on the quality of the 2D image-to-image translation and the encoder [S1].

**When to use it:**
- Use when training a generative NeRF that needs to support diverse editing tasks while maintaining multi-view consistency [S1].
- Use when the latent code tends to encode viewpoint information rather than just the edit content [S1].

## Background
**Origin:**
- Introduced in "GenN2N: Generative NeRF2NeRF Translation" [S1].
- The paper proposes a 3D VAE-GAN framework that incorporates a differentiable volume renderer to connect 3D content creation with 2D GAN losses [S1].

**History and Development:**
- The method addresses the issue that edit codes obtained from a Latent Distill Module may contain viewpoint-related effects, which causes instability in the translated NeRF [S1].
- It is part of a larger set of four loss functions used to optimize GenN2N, including KL loss, reconstruction loss, and adversarial loss [S1].

**Where it is used:**
- Used in the GenN2N framework for NeRF-to-NeRF translation [S1].
