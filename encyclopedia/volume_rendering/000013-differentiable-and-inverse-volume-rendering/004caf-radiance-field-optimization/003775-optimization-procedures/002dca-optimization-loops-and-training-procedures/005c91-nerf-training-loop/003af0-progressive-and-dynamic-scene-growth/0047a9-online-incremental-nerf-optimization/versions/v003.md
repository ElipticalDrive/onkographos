# Online Incremental NeRF Optimization
Also called: Incremental NeRF Training, Online NeRF

## Overview
Online Incremental NeRF Optimization is a training paradigm where the neural radiance field representation is updated continuously as new camera viewpoints and observations arrive, rather than optimizing on a fixed, pre-collected dataset [S1, unofficial]. It solves the problem of building 3D models in dynamic or large-scale environments where data is acquired sequentially [S1, unofficial]. It differs from offline methods like DVGO by integrating new observations into the training set incrementally, requiring the system to plan next-best views and perceive observations based on the current scene representation [S1, unofficial].

## How it works
The method operates in a closed loop of planning, perception, and optimization.

**Inputs and Outputs:**
*   **Inputs:** Current scene representation (feature grids/MLP), current camera poses, new incoming image observations.
*   **Outputs:** Updated scene representation, next best view plan.

**Data Structures:**
*   **Scene Representation:** Typically a grid-based structure (e.g., hash grid) storing spatial features, and a decoder (MLP) mapping features to color/density [S2, unofficial].
*   **Training Set:** A dynamic buffer of camera poses and corresponding images.

**Steps:**
1.  **Plan:** Based on the current scene representation, the system plans the "next best view" to maximize information gain or reduce uncertainty [S1, unofficial].
2.  **Perceive:** The agent/camera moves to the planned location and captures new observations (images) [S1, unofficial].
3.  **Increment:** The new observations are added to the training set [S1, unofficial].
4.  **Optimize:** The scene representation is optimized using the expanded training set [S1, unofficial].

**Formulas:**
The rendering equation remains standard for volume rendering:
$$ C(r) = \sum_{i=1}^N T_i (1 - \alpha_i) c_i $$
Where $T_i$ is transmittance, $\alpha_i$ is opacity, and $c_i$ is color. The optimization minimizes the difference between rendered and observed colors for the incremental batch.

**Parameters:**
*   **Entropy Threshold:** Used to determine when to stop exploring or when a view is sufficiently informative [S1, unofficial].
*   **Learning Rate:** Standard optimization hyperparameter.

**Edge Cases and Pitfalls:**
*   **Catastrophic Forgetting:** As new views are added, the model may overwrite previously learned information, causing degradation in previously reconstructed regions [S2, unofficial].
*   **Memory Usage:** Large environments result in high memory usage, potentially requiring discarding of older frames [S2, unofficial].

**Pseudocode:**
```python
# Initialize scene representation (grids, MLP)
scene = initialize_scene()
training_data = []

while not termination_condition():
    # 1. Plan next best view based on current representation
    next_pose = plan_next_best_view(scene)
    
    # 2. Perceive new observation
    new_image, new_pose = capture_observation(next_pose)
    
    # 3. Add to training set
    training_data.append((new_image, new_pose))
    
    # 4. Optimize representation on incremental data
    # Note: In practice, this may involve re-optimizing on a subset or using
    # techniques to mitigate forgetting (see Subtopics)
    scene = optimize_scene(scene, training_data)

return scene
```

## Subtopics

### Incremental Reconstruction with Frozen Decoder
A strategy for online incremental reconstruction to address catastrophic forgetting, where the model integrates new viewpoints while preserving previously learned information [S2, unofficial]. It employs pre-trained, scene-agnostic decoders that remain frozen during the feature grids optimization [S2, unofficial]. This design enables new grid cells to represent unseen areas while preserving the integrity of already reconstructed regions [S2, unofficial]. Vanilla NeRF suffers from catastrophic forgetting because every optimization step updates shared MLP weights globally, causing previously reconstructed regions not supervised anymore to degrade [S2, unofficial]. Grid-based representations partially mitigate forgetting due to spatially localized feature storage, but forgetting still occurs due to the decoder and hashgrid dictionary [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the optimization frequency and the size of the incremental batch. Re-optimization on the full set can be costly [S1, unofficial].
*   **Memory Complexity:** Scales with the number of captured images and the size of the scene representation. High memory usage is a concern in large environments [S2, unofficial].
*   **Strengths:** Enables real-time or near-real-time 3D model building in dynamic environments; does not require pre-collected datasets [S1, unofficial].
*   **Limitations:** Susceptible to catastrophic forgetting; requires careful management of training data and optimization strategies [S2, unofficial].
*   **When to use:** Active mapping, robotic navigation, large-scale scene reconstruction where data arrives sequentially [S1, unofficial].
*   **When not to use:** Offline processing of static, pre-collected datasets where global optimization is feasible [S1, unofficial].

## Background
The concept of online incremental NeRF optimization emerged from the need to adapt NeRFs to real-world scenarios involving imperfect data, large-scale scenes, and incremental reconstruction [S2, unofficial]. It contrasts with offline methods like DVGO, which optimize based on a fixed set of collected images [S1, unofficial]. The approach is closely related to active vision and active mapping, where an agent plans views to maximize information gain [S1, unofficial].
