# NeRF Training Loop

Also called: NeRF Optimization Loop, NeRF Training Procedure, Neural Radiance Fields Training, Training Ray Sampling Strategy for Correspondence Disparity, Ray Sampling Strategy for Correspondence Disparity

## Overview
The NeRF Training Loop is the iterative optimization procedure that learns a continuous volumetric scene representation (a neural radiance field) from a set of multi-view images by minimizing the photometric reconstruction error [S5, S10, S15, unofficial]. It solves the inverse problem of recovering implicit geometry and appearance by repeatedly sampling rays, rendering them via differentiable volume integration, and updating network weights via gradient descent [S5, S6, unofficial]. It sets itself apart from its siblings by defining the core stochastic optimization cycle—specifically the random ray sampling and batch processing strategy—that enables efficient training of high-dimensional implicit functions, whereas [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md) focuses on the forward pass mechanics and [Training Configuration](2332-training-configuration.md) defines the hyperparameters governing this cycle [S1][S2, S3, S5, S10, unofficial].

## How it works
The method optimizes a coordinate MLP (or SIREN) to map 3D positions and viewing directions to density and color [S3, S5, unofficial]. The loop operates on batches of rays sampled from training images [S5, S15, unofficial].

**Inputs and Outputs:**
*   **Inputs:** A dataset of $N$ images with known camera poses (extrinsics $C$ and intrinsics $K$) [S5, S10, unofficial]. Each image has height $H$ and width $W$.
*   **Outputs:** Optimized network weights $\Theta$ representing the radiance field [S5, unofficial].

**Data Structures:**
*   **Ray Bundle:** A tensor of shape $[B, 3, 3]$ or $[B, 6]$ (depending on implementation) containing $B$ rays. Each ray consists of origin $\mathbf{o}$, direction $\mathbf{d}$, and target color $\mathbf{c}_{gt}$ [S5, S15, unofficial].
*   **Pre-computed Rays Array:** In batching implementations, a numpy array `rays_rgb` of shape $[(N-1)HW, 3, 3]$ stores all possible rays from training images. Axis 0 is the flattened pixel index. Axis 1 is channel type: 0 for ray origin, 1 for ray direction, 2 for observed RGB. Data type is `float32` [S5, S15, unofficial].

**Numbered Steps:**

1.  **Initialization:** Initialize the neural network weights (e.g., random or specific initialization for SIREN) [S3, S13, unofficial]. Initialize the optimizer (typically Adam) with a learning rate $lr$ [S5, S10, S13, unofficial]. If using a learning rate scheduler (e.g., Exponential Decay or Cosine Annealing), initialize it [S5, S11, unofficial].
2.  **Ray Sampling:** For each iteration $i$:
    *   If using pre-computed batching: Select a batch of $N_{rand}$ rays from the `rays_rgb` array using indices $i_{batch}$ to $i_{batch} + N_{rand}$ [S5, S15, unofficial].
    *   If using on-the-fly sampling: Randomly select pixel coordinates from training images, convert to ray origins and directions using camera parameters, and gather target RGB colors [S4, S15, unofficial].
    *   If using perturbation: Jitter the sample positions along the ray to break symmetry and aid gradient flow [S2, S5, unofficial].
3.  **Forward Pass (Rendering):** Pass the ray origins, directions, and potentially view directions through the neural network to predict density $\sigma$ and color $\mathbf{c}$ at sample points [S5, S6, unofficial]. Compute the rendered color $\hat{\mathbf{C}}(\mathbf{r})$ using the volume rendering equation (see Parent article) [S5, S6, unofficial].
    *   *Note:* If a coarse-to-fine strategy is used, render with a coarse network first, then sample additional points based on coarse weights and render with a fine network [S5, S11, unofficial].
4.  **Loss Computation:** Compute the Mean Squared Error (MSE) between the rendered color $\hat{\mathbf{C}}(\mathbf{r})$ and the ground truth color $\mathbf{C}_{gt}(\mathbf{r})$ [S5, S15, unofficial].
    $$ \mathcal{L}_{MSE} = \frac{1}{B} \sum_{j=1}^{B} \| \hat{\mathbf{C}}(\mathbf{r}_j) - \mathbf{C}_{gt}(\mathbf{r}_j) \|^2 $$
    *   If coarse outputs are available, add the coarse loss: $\mathcal{L} = \mathcal{L}_{fine} + \mathcal{L}_{coarse}$ [S11, S19, unofficial].
    *   If other losses (e.g., regularization, ToF) are defined, add them to the total loss [S20, unofficial].
5.  **Backpropagation and Update:** Compute gradients of the loss with respect to the network weights. Update the weights using the optimizer [S5, S19, unofficial].
    *   *Pitfall:* If logging higher-order derivatives (gradients, Laplacians) for monitoring, these must be computed *before* calling `loss.backward()` to avoid freeing the autograd graph [S3, unofficial].
6.  **Scheduler Step:** Update the learning rate if a scheduler is used [S5, S19, unofficial].
    *   *Exponential Decay Example:* $lr_{new} = lr_{old} \times \text{decay\_rate}^{(\text{step} / \text{decay\_steps})}$ [S5, S19, unofficial].
7.  **Logging and Checkpointing:** Log loss metrics (PSNR, SSIM) and render validation images at specified intervals [S11, S15, unofficial]. Save model checkpoints periodically [S11, unofficial].
8.  **Iteration:** Increment iteration counter. If the batch of pre-computed rays is exhausted, shuffle the `rays_rgb` array and reset the index [S5, S11, unofficial]. Repeat until convergence or max iterations reached.

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.optim as optim
import numpy as np

def train_nerf_loop(model, optimizer, scheduler, train_data, config):
    """
    Standard NeRF training loop.
    
    Args:
        model: Neural Radiance Field MLP.
        optimizer: Optimizer (e.g., Adam).
        scheduler: Learning rate scheduler (e.g., LambdaLR, CosineAnnealing).
        train_data: Object containing training images, poses, and intrinsics.
        config: Configuration dictionary with hyperparameters.
    """
    # 1. Initialization
    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
    model.to(device)
    model.train()
    
    # Pre-compute rays if batching is enabled
    use_batching = config.get("use_batching", True)
    rays_rgb = None
    if use_batching:
        rays_rgb = precompute_rays(train_data) # Shape: [TotalPixels, 3, 3]
        total_rays = rays_rgb.shape[0]
        i_batch = 0
    
    n_iters = config.get("n_iters", 100000)
    batch_size = config.get("batch_size", 1024)
    
    for step in range(n_iters):
        # 2. Ray Sampling
        if use_batching:
            # Slice batch from pre-computed array
            end_idx = i_batch + batch_size
            if end_idx > total_rays:
                # Shuffle and reset if exhausted
                np.random.shuffle(rays_rgb)
                i_batch = 0
                end_idx = i_batch + batch_size
            
            batch_data = rays_rgb[i_batch:end_idx] # Shape: [batch_size, 3, 3]
            i_batch = end_idx
            
            # Split into rays (origin, dir) and targets (rgb)
            # Axis 0: channel type (0: origin, 1: dir, 2: target)
            # Axis 1: batch index
            # Axis 2: components
            batch_rays = batch_data[:, :2, :].transpose(0, 1) # [2, batch_size, 3]
            target_s = batch_data[:, 2, :].transpose(0, 1)   # [3, batch_size] -> [batch_size, 3]
        else:
            # On-the-fly sampling
            batch_rays, target_s = sample_rays_on_the_fly(train_data, batch_size)
            
        batch_rays = batch_rays.to(device)
        target_s = target_s.to(device)
        
        # 3. Forward Pass
        optimizer.zero_grad()
        
        # Render rays
        # model.render_rays expects rays in format [origins, directions, near, far, ...]
        # Adjust format as per specific implementation
        rendered = model.render_rays(batch_rays)
        
        # Extract predicted RGB
        pred_rgb = rendered['rgb'] # Shape: [batch_size, 3]
        
        # 4. Loss Computation
        # MSE Loss
        loss_fn = nn.MSELoss()
        loss = loss_fn(pred_rgb, target_s)
        
        # Add coarse loss if available (coarse-to-fine)
        if 'rgb_coarse' in rendered:
            loss_coarse = loss_fn(rendered['rgb_coarse'], target_s)
            loss = loss + loss_coarse
            
        # 5. Backpropagation
        # Compute gradients
        loss.backward()
        
        # Optional: Log gradients or higher-order derivatives here BEFORE step
        # grad_norm = torch.norm(torch.stack([torch.norm(p.grad) for p in model.parameters()]))
        
        # Update weights
        optimizer.step()
        
        # 6. Scheduler Step
        if scheduler is not None:
            scheduler.step()
            
        # 7. Logging
        if step % config.get("log_interval", 100) == 0:
            psnr = -10.0 * torch.log10(loss).item()
            print(f"Step {step}: Loss={loss.item():.6f}, PSNR={psnr:.2f}")
            
        if step % config.get("save_interval", 5000) == 0:
            save_checkpoint(model, optimizer, step, config.get("checkpoint_dir"))
            
        if step % config.get("render_interval", 5000) == 0:
            render_validation_images(model, train_data.val_data, step)

def precompute_rays(train_data):
    """
    Pre-compute all rays from training images into a single array.
    Returns numpy array of shape [TotalPixels, 3, 3].
    """
    all_rays = []
    for img, pose, K in train_data:
        H, W = img.shape[:2]
        # Generate all pixel coordinates
        y, x = np.meshgrid(np.arange(H), np.arange(W), indexing='ij')
        coords = np.stack([x, y], axis=-1).reshape(-1, 2)
        
        # Convert to rays
        rays_o, rays_d = get_rays_from_pixels(coords, K, pose)
        targets = img.reshape(-1, 3)
        
        # Stack: [origin, direction, target]
        # Shape: [H*W, 3, 3]
        batch_rays = np.stack([rays_o, rays_d, targets], axis=1)
        all_rays.append(batch_rays)
        
    rays_rgb = np.concatenate(all_rays, axis=0).astype(np.float32)
    return rays_rgb
```

**Parameters:**
*   `lr`: Learning rate for Adam optimizer. Typical value: $5 \times 10^{-4}$ [S11, unofficial].
*   `batch_size` ($N_{rand}$): Number of rays sampled per iteration. Typical value: 1024 or 2048 [S5, S11, unofficial].
*   `n_iters`: Total number of optimization steps. Typical value: 100,000 [S11, unofficial].
*   `decay_steps`: Steps after which learning rate decays. Calculated as `args.lrate_decay * 1000` [S5, S19, unofficial].
*   `decay_rate`: Factor by which learning rate is multiplied per decay step. Default: 0.1 [S5, S19, unofficial].
*   `chunk`: Maximum number of rays processed per forward pass to limit VRAM. Passed to render function [S5, unofficial].

**Edge Cases and Pitfalls:**
*   **VRAM Overflow:** Rendering all rays at once can exceed GPU memory. Mitigated by chunking rays during the forward pass [S5, unofficial].
*   **Gradient Graph Freeing:** Higher-order derivative logging (e.g., for SIREN analysis) must occur before `loss.backward()` [S3, unofficial].
*   **Checkpoint Resumption:** When resuming, the scheduler's last epoch must be set to `start_epoch - 1` to ensure correct scheduling [S9, unofficial].
*   **Empty Checkpoints:** If a loaded checkpoint has step 0, it is considered empty and should trigger an error or re-initialization [S16, unofficial].
*   **Instability in Growth:** In dynamic growing NeRFs, directly growing randomly initialized sub-networks causes instability (density drops to 0). Weights should be inherited from the parent network [S1].

### Supersampling Baseline
A baseline method for evaluating NeRF on multiscale data by training on full-resolution images and using brute-force supersampling during evaluation, or training on multiscale data with supersampling during both training and evaluation [S23]. For every pixel, multiple jittered rays are sampled uniformly at random through the spatial footprint of the pixel. The mean of these rendered values is used as the predicted color in the loss function [S23]. This baseline relies on 'oracle' scale information that does not exist for most datasets [S23]. The 16x supersampling baseline performs worse than mip-NeRF and is significantly more expensive during both training and evaluation [S23].

### Two-stage training for proposers
A training schedule split into two equal-duration phases to stabilize learning of a trainable proposer network in NeRF-ID [S24, unofficial]. Phase 1 trains the learnt proposer to mimic the heuristic proposer by minimizing the L2 matching loss between their proposal sets [S24, unofficial]. Phase 2 trains all network components end-to-end, resetting the optimizer state and performing a linear warmup for 1,000 steps to reduce shock from switching regimes [S24, unofficial]. Training from scratch sometimes works but often fails; two-stage training is consistently effective [S24, unofficial].

### JaxNeRF
A re-implementation of the original NeRF in JAX, used as a benchmark comparison for early works seeking to improve on training and rendering speed [S25]. It is slightly faster and more suited for distributed computing than the original TensorFlow implementation of NeRF [S25].

### Gradient Detachment in Training
A training strategy where the object field component is detached from the backbone to prevent gradient backpropagation to the rendering part, ensuring independent optimization [S26, unofficial]. With detach, gradients do not backpropagate to the NeRF backbone; without detach, gradients from the object field component backpropagate, causing mutual influence [S26, unofficial]. With detach achieves better scene rendering and decomposition quality, while without detach causes a significant drop in rendering quality [S26, unofficial]. The hyper-parameter $\Delta d$ for empty 3D point losses is tested at 0.025, 0.05, 0.10 meters, with 0.05 meters being optimal [S26, unofficial].

### Ray Generator Network (RGN)
Used in MEIL-NeRF for incremental learning of NeRF [S27]. During training on task $T$, the RGN $f_T^{RGN}$ learns to map past principal rays from $f_{T-1}^{RGN}$ and current GT principal rays [S27]. During inference, a principal ray is generated using the RGN, and non-principal rays are randomly generated around it using camera intrinsics $K$ [S27]. The generated rays form a cone emitted from the camera center [S27]. The network architecture has 3 hidden layers with 16, 64, and 32 hidden units respectively [S27]. Estimated camera poses accumulate errors over tasks, but the generated approximate rays still effectively direct to the scene of interest near past task cameras, so exact reconstruction of past rays is not required [S27]. Unlike methods that reproduce exact past rays, RGN creates approximate rays directed to the scene of interest, allowing errors under a certain level to reduce the learning burden at a small accuracy cost [S27].

### DFF
A method adopting pre-trained feature extraction networks (LSeg, DINO) as teacher networks for knowledge distillation, resulting in a scene-specific 3D feature field, enabling extraction and deletion of target objects based on image patches or text [S28].

### ISRF
A method that learns additional feature fields to realize self-supervised 3D segmentation [S28].

## Operating characteristics
*   **Time Complexity:** $O(N_{iters} \cdot N_{rand} \cdot N_{samples})$, where $N_{iters}$ is the number of iterations, $N_{rand}$ is the batch size (rays per step), and $N_{samples}$ is the number of samples per ray [S5, S15, unofficial].
*   **Memory Complexity:** $O(N_{rand} \cdot N_{samples})$ for the forward pass, plus $O(N_{params})$ for the model weights and optimizer states [S5, unofficial]. VRAM usage is mitigated by chunking rays [S5, unofficial].
*   **Measured Performance:** In the original NeRF implementation, training on Blender synthetic data (800x800) takes approximately 5 hours on a single GPU for 500,000 iterations [S5, S18, unofficial]. On LLFF with 3 views, increasing the number of target rays from 50 to 200 degrades performance (PSNR 20.33 to 20.15) [S21].
*   **Scaling:** Performance scales with the number of training images and iterations. Larger batch sizes (e.g., $2^{14}$) can hinder data loading performance, while smaller batch sizes (e.g., $2^{10}$) cap iterations per second, reducing throughput [S16, unofficial].
*   **Strengths:** Enables high-quality novel view synthesis from sparse views. Differentiable nature allows for joint optimization of geometry and appearance.
*   **Limitations:** Computationally expensive due to repeated MLP evaluations. Sensitive to hyperparameters (learning rate, batch size). Prone to artifacts (floaters, blurring) in sparse-view settings [S9394-sparse-view-and-initialization-methods.md].
*   **When to use:** When high-fidelity novel view synthesis is required and sufficient computational resources are available.
*   **When not to use:** When real-time rendering is required without acceleration structures, or when training data is extremely sparse and no priors are available.

## Background
The NeRF Training Loop was introduced by Mildenhall et al. in "NeRF: Representing Scenes as Neural Radiance Fields for View Synthesis" (2020) [S5, S10, unofficial]. It builds on the concept of neural implicit representations and differentiable volume rendering [S5, unofficial]. The method was initially implemented in TensorFlow [S5, unofficial] and later ported to PyTorch [S6, unofficial] and JAX [S13, unofficial][S25]. It has become the standard baseline for neural radiance field optimization, with numerous variants and accelerations developed subsequently [S25].
