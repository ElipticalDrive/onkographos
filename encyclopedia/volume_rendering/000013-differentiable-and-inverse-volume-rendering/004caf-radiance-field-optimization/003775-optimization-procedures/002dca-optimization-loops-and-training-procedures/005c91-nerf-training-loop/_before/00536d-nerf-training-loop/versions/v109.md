# NeRF Training Loop

Also called: NeRF Optimization Loop, NeRF Training Procedure, Neural Radiance Fields Training, Training Ray Sampling Strategy for Correspondence Disparity, Ray Sampling Strategy for Correspondence Disparity

## Overview
The NeRF Training Loop is the iterative optimization procedure that trains a coordinate-based neural radiance field to reconstruct a static 3D scene from a set of multi-view 2D images [S5, S6, S15, unofficial]. It solves the inverse problem of learning an implicit volumetric representation by minimizing the photometric difference between rendered images and ground-truth observations [S5, S15, unofficial]. It differs from its siblings by defining the standard stochastic gradient descent cycle of ray sampling, differentiable volume rendering, and weight updates, whereas [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md) details the forward pass mechanics and [Training Configuration](2332-training-configuration.md) defines the static hyperparameters [S1][S3, S6, unofficial].

## How it works
The training loop optimizes the parameters $\Theta$ of a neural network (typically an MLP) that maps 6D coordinates $(\mathbf{x}, \mathbf{d})$ to density $\sigma$ and color $\mathbf{c}$ [S3, S15, unofficial]. The core mechanism relies on the differentiability of the volume rendering equation, allowing gradients to flow from the pixel loss back to the network weights [44-radiance-field-optimization.md].

### Inputs and Outputs
*   **Inputs:** A dataset of $N$ training images with known camera poses (extrinsics $\mathbf{C}$ and intrinsics $\mathbf{K}$) [S5, S11, unofficial]. Each image has resolution $H \times W$.
*   **Outputs:** Optimized network weights $\Theta$ representing the radiance field [S5, unofficial].

### Data Structures
The training data is typically preprocessed into a flat array of rays to enable efficient random sampling [S5, S15, unofficial].
*   **`rays_rgb` Array:** A numpy array of shape $[(N-1) \cdot H \cdot W, 3, 3]$ [S5, S15, unofficial].
    *   Axis 0: Flattened pixel index (from $0$ to $(N-1)HW - 1$).
    *   Axis 1: Channel type. Index 0 is Ray Origin $(\mathbf{o})$, Index 1 is Ray Direction $(\mathbf{d})$, Index 2 is Target RGB Color $(\mathbf{c}_{gt})$ [S5, S15, unofficial].
    *   Axis 2: Components (x, y, z for rays; r, g, b for color).
    *   Data Type: `float32` [S5, S15, unofficial].
*   **Checkpoint Structure:** A dictionary containing:
    *   `'step'`: Integer iteration count [S11, unofficial].
    *   `'coarse'`: State dictionary of the coarse MLP [S11, unofficial].
    *   `'fine'`: State dictionary of the fine MLP (if used) [S11, unofficial].
    *   `'optim'`: State dictionary of the optimizer [S11, unofficial].

### Numbered Steps
1.  **Initialization:** Initialize the neural network weights (e.g., random or SIREN initialization) [S3, S13, unofficial]. Initialize the optimizer (typically Adam) with a learning rate $\eta$ [S5, S11, unofficial]. Initialize a learning rate scheduler (e.g., Exponential Decay or Cosine Annealing) [S5, S11, unofficial]. Precompute the `rays_rgb` array from the training images and camera poses [S5, S15, unofficial].
2.  **Iteration Loop:** For iteration $i$ from $1$ to $N_{iters}$:
    a.  **Ray Sampling:** Select a batch of $N_{rand}$ rays from the `rays_rgb` array [S5, S15, unofficial].
        *   If batching is enabled, slice the precomputed array or randomly sample indices without replacement [S5, S15, unofficial].
        *   If precropping is enabled (for early iterations), restrict sampling to a central crop of the image [S15, unofficial].
        *   Shuffle the ray indices at the start of each epoch or when the batch iterator resets to ensure random sampling order [S11, unofficial].
    b.  **Forward Pass (Rendering):** For each ray in the batch, sample $K$ points along the ray segment $[t_{near}, t_{far}]$ [S5, S11, unofficial].
        *   Query the neural network for density $\sigma_k$ and color $\mathbf{c}_k$ at each point [S5, unofficial].
        *   Compute transmittance $T_k$ and weights $w_k$ using the emission-absorption model [44-radiance-field-optimization.md].
        *   Render the predicted color $\hat{\mathbf{c}}$ for each ray [S5, S11, unofficial].
        *   *Optional:* If a coarse-fine strategy is used, render a coarse image first, sample additional points based on coarse weights, and render a fine image [S5, S11, unofficial].
    c.  **Loss Computation:** Compute the Mean Squared Error (MSE) between the predicted colors $\hat{\mathbf{c}}$ and the ground-truth colors $\mathbf{c}_{gt}$ [S3, S15, unofficial].
        $$ \mathcal{L}_{MSE} = \frac{1}{N_{rand}} \sum_{j=1}^{N_{rand}} \| \hat{\mathbf{c}}_j - \mathbf{c}_{gt,j} \|^2 $$
        [S15, S18, unofficial].
        *   *Optional:* If coarse-fine rendering is used, add the coarse loss $\mathcal{L}_{coarse}$ to the total loss [S11, unofficial].
        *   *Optional:* Add regularization terms (e.g., sparsity, Eikonal, Total Variation) if specified in configuration [S7, unofficial][S8].
    d.  **Backpropagation:** Compute gradients of the total loss with respect to the network parameters $\Theta$ [S5, S19, unofficial].
        *   *Pitfall:* If higher-order derivatives (e.g., gradients for logging) are needed, they must be computed *before* calling `loss.backward()`, as the backward pass frees the autograd graph [S3, unofficial].
    e.  **Optimization Step:** Update the network weights using the optimizer (e.g., Adam step) [S5, S19, unofficial].
    f.  **Learning Rate Update:** Update the learning rate according to the scheduler [S5, S11, unofficial].
        *   Exponential Decay: $\eta_{new} = \eta_{old} \cdot \text{decay\_rate}^{(i / \text{decay\_steps})}$ [S5, S19, unofficial].
        *   Cosine Annealing: $\eta_i = \eta_{min} + \frac{1}{2}(\eta_{max} - \eta_{min})(1 + \cos(\frac{i \cdot \pi}{N_{iters}}))$ [S11, unofficial].
    g.  **Logging and Checkpointing:**
        *   Log loss and PSNR every $I_{print}$ steps [S2, S11, unofficial].
        *   Render validation images every $I_{img}$ steps [S2, S11, unofficial].
        *   Save model checkpoint every $I_{weights}$ steps [S2, S11, unofficial].

### Formulas
*   **MSE Loss:**
    $$ \mathcal{L} = \text{mean}((\hat{\mathbf{c}} - \mathbf{c}_{gt})^2) $$
    [S13, S15, unofficial].
*   **PSNR Calculation:**
    $$ \text{PSNR} = -10 \cdot \log_{10}(\mathcal{L}_{MSE}) $$
    [S15, unofficial].
*   **Learning Rate Decay (Exponential):**
    $$ \eta_i = \eta_0 \cdot \gamma^{(i / D)} $$
    where $\gamma$ is `decay_rate` (default 0.1) and $D$ is `decay_steps` (often $1000 \times \text{args.lrate\_decay}$) [S5, S19, unofficial].

### Parameters
*   **$N_{rand}$ (Batch Size):** Number of rays sampled per iteration. Typical values: 1024 or 2048 [S5, S11, unofficial].
*   **$N_{iters}$ (Iterations):** Total number of optimization steps. Default: 100,000 [S11, unofficial].
*   **Learning Rate ($\eta$):** Default: $5 \times 10^{-4}$ [S11, unofficial] or $1 \times 10^{-3}$ [S13, unofficial].
*   **$K$ (Samples per Ray):** Number of points sampled along each ray. Default: 128 [S18, unofficial].
*   **$t_{near}, t_{far}$:** Near and far clipping planes. For Blender synthetic data: $t_{near}=2.0, t_{far}=6.0$ [S14, unofficial]. For LLFF: computed from bounding depths or NDC $[0, 1]$ [S2, unofficial].
*   **$\gamma$ (Decay Rate):** Factor for LR decay. Default: 0.1 [S6, S19, unofficial].
*   **$D$ (Decay Steps):** Steps over which LR decays. Default: $1000 \times \text{args.lrate\_decay}$ [S5, S19, unofficial].

### Edge Cases and Pitfalls
*   **VRAM Overflow:** Rendering large batches can exceed GPU memory. Mitigated by chunking rays during the forward pass (e.g., `chunk=args.chunk`) [S5, S16, unofficial].
*   **Instability in Growth:** In dynamic growing networks (e.g., Recursive-NeRF), directly initializing new sub-networks randomly causes instability and zero-density regions. Initialize alpha linear weights of grown sub-networks to match the parent [S1].
*   **Checkpoint Resume:** When resuming, the optimizer state and scheduler state must be restored. The scheduler's last epoch must be set to `start_epoch - 1` to ensure correct scheduling [S9, unofficial]. If a checkpoint is loaded but the step is 0, it is considered empty and should trigger an error [S16, unofficial].
*   **Sampling Bias:** If the number of feature-matching correspondences differs significantly from pixel count, training balance is disrupted. Fill regions without correspondences using standard photometric supervision [S21].

### Pseudocode
```python
import torch
import torch.nn as nn
import torch.optim as optim
import numpy as np

def train_nerf(model, rays_rgb, target_colors, num_iters, batch_size, optimizer, scheduler, render_fn):
    """
    Standard NeRF Training Loop.
    
    Args:
        model: Neural Radiance Field MLP.
        rays_rgb: Precomputed array of shape [N_rays, 3, 3] (origins, dirs, targets).
        target_colors: Ground truth colors (extracted from rays_rgb[:, 2, :]).
        num_iters: Total number of training iterations.
        batch_size: Number of rays per batch (N_rand).
        optimizer: PyTorch optimizer (e.g., Adam).
        scheduler: Learning rate scheduler (e.g., ExponentialLR or LambdaLR).
        render_fn: Function that takes rays and model, returns predicted RGB.
    """
    N_rays_total = rays_rgb.shape[0]
    i_batch = 0
    
    for i in range(num_iters):
        # 1. Ray Sampling
        # Slice batch from precomputed rays
        batch_indices = slice(i_batch, i_batch + batch_size)
        batch_rays = rays_rgb[batch_indices] # Shape: [batch_size, 3, 3]
        
        # Extract origins, directions, and targets
        # Axis 0: channel type (0: origin, 1: dir, 2: target)
        # Axis 1: batch index
        # Axis 2: components
        batch_origins = batch_rays[:, 0, :] # [batch_size, 3]
        batch_dirs = batch_rays[:, 1, :]   # [batch_size, 3]
        batch_targets = batch_rays[:, 2, :] # [batch_size, 3]
        
        # Increment batch index and shuffle if exhausted
        i_batch += batch_size
        if i_batch + batch_size > N_rays_total:
            # Shuffle rays to ensure random sampling order across epochs
            indices = np.random.permutation(N_rays_total)
            rays_rgb[:, 0, :] = rays_rgb[indices, 0, :]
            rays_rgb[:, 1, :] = rays_rgb[indices, 1, :]
            rays_rgb[:, 2, :] = rays_rgb[indices, 2, :]
            i_batch = 0
            
        # 2. Forward Pass
        # Stack rays for render function
        rays_batch = torch.stack([batch_origins, batch_dirs], dim=0).to(device) # [2, batch_size, 3]
        targets = batch_targets.to(device) # [batch_size, 3]
        
        # Render
        # render_fn returns predicted RGB [batch_size, 3]
        # If coarse-fine, it may return dict with 'rgb_coarse', 'rgb_fine'
        predictions = render_fn(model, rays_batch)
        
        # 3. Loss Computation
        # Standard MSE loss
        loss = nn.functional.mse_loss(predictions, targets)
        
        # Optional: Add coarse loss if available
        # if 'rgb_coarse' in predictions:
        #     loss += nn.functional.mse_loss(predictions['rgb_coarse'], targets)
        
        # 4. Backpropagation
        optimizer.zero_grad()
        loss.backward()
        
        # 5. Optimization Step
        optimizer.step()
        
        # 6. Learning Rate Update
        scheduler.step()
        
        # 7. Logging (every 100 steps)
        if i % 100 == 0:
            mse_val = loss.item()
            psnr_val = -10.0 * np.log10(mse_val) / np.log10(10.0)
            print(f"Iter {i}: Loss {mse_val:.6f}, PSNR {psnr_val:.2f}")
            
        # 8. Checkpointing (every 5000 steps)
        if i % 5000 == 0:
            save_checkpoint(model, optimizer, i)
```

## Operating characteristics
*   **Time Complexity:** $O(N_{iters} \cdot N_{rand} \cdot K)$, where $N_{iters}$ is iterations, $N_{rand}$ is batch size, and $K$ is samples per ray [S5, S15, unofficial].
*   **Memory Complexity:** $O(N_{rand} \cdot K)$ for storing intermediate rendering states per batch, plus $O(\Theta)$ for network weights [44-radiance-field-optimization.md]. Chunking reduces peak VRAM usage [S5, unofficial].
*   **Measured Performance:** On Blender synthetic data (800x800), training typically runs for 100,000 iterations [S11, unofficial]. On LLFF with 3 views, specific sampling ratios (e.g., 50 target rays) yield PSNR ~20.33 [S21].
*   **Scaling:** Performance scales with batch size, but larger batches hinder data loading performance and GPU occupancy; $2^{10}$ is a common tradeoff [S16, unofficial].
*   **Strengths:** Simple to implement, differentiable end-to-end, produces high-quality novel views for static scenes [S5, S15, unofficial].
*   **Limitations:** Slow convergence due to uniform sampling in empty space, prone to "foggy" densities or floaters in sparse views, requires pre-computed camera poses [S1][S16, unofficial].
*   **When to Use:** Static scenes with dense multi-view coverage and known camera poses [S5, S11, unofficial].
*   **When Not to Use:** Dynamic scenes, sparse views without initialization aids, or scenes requiring real-time rendering without acceleration structures [S1][S16, unofficial].

## Background
The NeRF Training Loop was introduced by Mildenhall et al. in "NeRF: Representing Scenes as Neural Radiance Fields for View Synthesis" (2020) [S5, S11, unofficial]. It builds on the concept of coordinate-based neural networks for implicit scene representation [S3, unofficial]. The method uses stochastic gradient descent with Adam optimizer and positional encoding to map 3D coordinates and viewing directions to volume density and color [S5, S11, unofficial]. It has become the standard baseline for neural rendering research, with numerous variants optimizing specific aspects like sampling, architecture, and regularization [S1, S25].
