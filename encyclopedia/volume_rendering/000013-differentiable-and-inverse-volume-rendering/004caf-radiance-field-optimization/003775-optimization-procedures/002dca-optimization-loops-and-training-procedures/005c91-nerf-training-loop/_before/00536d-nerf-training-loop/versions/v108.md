# NeRF Training Loop

Also called: NeRF Optimization Loop, NeRF Training Procedure, Neural Radiance Fields Training, Training Ray Sampling Strategy for Correspondence Disparity, Ray Sampling Strategy for Correspondence Disparity

## Overview
The NeRF Training Loop is the iterative optimization procedure that trains a coordinate-based neural radiance field to reconstruct a scene from multi-view images [S5, S11, unofficial]. It solves the inverse problem of learning implicit geometry and appearance by minimizing the difference between rendered and observed pixel colors [S15, unofficial]. It differs from its siblings by defining the standard stochastic gradient descent workflow—random ray sampling, differentiable volume rendering, and photometric loss minimization—that serves as the baseline for all specialized NeRF variants [S1][S11, unofficial].

## How it works
The method optimizes a neural network (typically an MLP) that maps 3D spatial coordinates $\mathbf{x}$ and viewing directions $\mathbf{d}$ to density $\sigma$ and color $\mathbf{c}$ [S11, unofficial]. The loop iterates over a dataset of training images, sampling rays, rendering them via volume integration, computing a loss against ground truth, and updating weights [S5, unofficial].

### Inputs and Outputs
*   **Inputs:** A set of $N$ training images with known camera poses (extrinsics $C$ and intrinsics $K$) [S11, unofficial]. Ground truth RGB values $\mathbf{C}_{gt}$ for each pixel [S5, unofficial].
*   **Outputs:** Optimized network weights $\Theta$ representing the radiance field [S5, unofficial].

### Data Structures
*   **Rays Array (`rays_rgb`):** A pre-computed or on-the-fly generated array containing ray origins, directions, and target colors [S5, S15, unofficial].
    *   Layout: Shape $[(N-1) \times H \times W, 3, 3]$ or $[B, 3, 3]$ for batches [S5, S15, unofficial].
    *   Axis 0: Flattened pixel index or batch index.
    *   Axis 1: Channel type (0: Ray Origin, 1: Ray Direction, 2: Target RGB) [S5, S15, unofficial].
    *   Axis 2: XYZ/RGB components (float32) [S5, S15, unofficial].
*   **Checkpoint:** A dictionary storing model state, optimizer state, and step count [S11, unofficial].
    *   Keys: `'step'` (int), `'coarse'` (state_dict), `'fine'` (state_dict), `'optim'` (optimizer state_dict) [S11, unofficial].

### Numbered Steps
1.  **Initialization:** Initialize the neural network weights (e.g., random or specific initialization for SIREN) [S13, S16, unofficial]. Initialize the optimizer (typically Adam) with a learning rate $\eta$ [S5, S11, unofficial]. Initialize a learning rate scheduler (e.g., Exponential Decay or Cosine Annealing) [S5, S11, unofficial].
2.  **Ray Sampling:** For each iteration, sample a batch of $N_{rand}$ random rays from the training images [S5, S15, unofficial].
    *   If using pre-computed rays, slice the `rays_rgb` array [S5, unofficial].
    *   If generating on-the-fly, select random pixel coordinates, convert to ray origins/directions using camera intrinsics, and gather target RGB values [S15, unofficial].
    *   *Edge Case:* If `precrop_iters` is set, sample only from a central crop of the image for the first few iterations to stabilize training [S2, unofficial].
3.  **Forward Pass (Rendering):** Pass the sampled rays through the NeRF model [S6, unofficial].
    *   Sample points along each ray within near/far bounds [S5, unofficial].
    *   Query the network for density $\sigma$ and color $\mathbf{c}$ at these points [S5, unofficial].
    *   Compute transmittance $T_i$ and weights $w_i$ using the emission-absorption model [S5, unofficial].
    *   Composite the final color $\hat{\mathbf{C}}(\mathbf{r})$ [S5, unofficial].
    *   *Memory Management:* If the batch size exceeds VRAM limits, split the ray batch into chunks and process sequentially [S5, unofficial].
4.  **Loss Computation:** Calculate the loss between the rendered color $\hat{\mathbf{C}}(\mathbf{r})$ and the ground truth color $\mathbf{C}_{gt}$ [S15, unofficial].
    *   Standard Loss: Mean Squared Error (MSE) [S15, unofficial].
    *   Formula:
        $$
        \mathcal{L}_{MSE} = \frac{1}{N_{rand}} \sum_{i=1}^{N_{rand}} \| \hat{\mathbf{C}}(\mathbf{r}_i) - \mathbf{C}_{gt}(\mathbf{r}_i) \|^2
        $$
    *   *Coarse/Fine Loss:* If a coarse network is used, compute MSE for both coarse and fine outputs and sum them [S11, unofficial].
    *   *Regularization:* Add terms such as Total Variation (TV) loss or sparsity loss if applicable [S7, unofficial].
5.  **Backpropagation and Update:**
    *   Zero gradients [S19, unofficial].
    *   Compute gradients via automatic differentiation [S19, unofficial].
    *   Step the optimizer [S19, unofficial].
    *   Update the learning rate according to the scheduler [S19, unofficial].
6.  **Logging and Checkpointing:**
    *   Log loss and PSNR metrics at regular intervals [S11, unofficial].
    *   Render validation images at regular intervals [S11, unofficial].
    *   Save checkpoints at regular intervals [S11, unofficial].

### Pseudocode
```python
def train_nerf(model, optimizer, scheduler, train_dataset, config):
    """
    Standard NeRF training loop.
    
    Args:
        model: Neural Radiance Field MLP.
        optimizer: Adam optimizer.
        scheduler: Learning rate scheduler (e.g., ExponentialDecay or CosineAnnealing).
        train_dataset: Dataset containing images, poses, and intrinsics.
        config: Configuration object with hyperparameters.
    """
    # 1. Initialization
    # model is assumed initialized externally
    # optimizer is assumed initialized externally
    # scheduler is assumed initialized externally
    
    n_iters = config.n_iters  # e.g., 100,000
    batch_size = config.batch_size  # e.g., 1024
    log_every = config.log_every  # e.g., 100
    save_every = config.save_every  # e.g., 10000
    
    # Pre-compute rays if necessary (S5, S15)
    # rays_rgb shape: [total_pixels, 3, 3] -> [origin, direction, target_rgb]
    rays_rgb = precompute_rays(train_dataset)
    total_rays = rays_rgb.shape[0]
    i_batch = 0
    
    for step in range(1, n_iters + 1):
        # 2. Ray Sampling
        # Slice batch from pre-computed rays
        batch_start = i_batch
        batch_end = min(i_batch + batch_size, total_rays)
        
        # Extract batch: shape [batch_size, 3, 3]
        batch_rays = rays_rgb[batch_start:batch_end]
        
        # Transpose to [3, batch_size, 3] for splitting (S15)
        batch_rays = batch_rays.transpose(0, 1)
        
        # Split into ray geometry (origin, direction) and targets (rgb)
        # batch_rays[0] = origins, batch_rays[1] = directions, batch_rays[2] = targets
        rays_o = batch_rays[0]
        rays_d = batch_rays[1]
        target_s = batch_rays[2]
        
        # Increment batch index
        i_batch += batch_size
        
        # Shuffle and reset if exhausted (S11)
        if i_batch >= total_rays:
            rays_rgb = rays_rgb[np.random.permutation(total_rays)]
            i_batch = 0
            
        # 3. Forward Pass
        # Zero gradients
        optimizer.zero_grad()
        
        # Render rays
        # model.render_rays returns dict with 'rgb', 'rgb0' (coarse), etc.
        render_output = model.render_rays(rays_o, rays_d, config)
        
        predicted_rgb = render_output['rgb']
        
        # 4. Loss Computation
        # MSE Loss
        loss = torch.mean((predicted_rgb - target_s) ** 2)
        
        # Add coarse loss if available (S11)
        if 'rgb0' in render_output:
            loss_coarse = torch.mean((render_output['rgb0'] - target_s) ** 2)
            loss = loss + loss_coarse
            
        # Add regularization if configured (S7)
        if config.tv_loss_weight > 0 and step > 1000:
            loss = loss + config.tv_loss_weight * compute_tv_loss(model)
            
        # 5. Backpropagation and Update
        loss.backward()
        optimizer.step()
        
        # Update learning rate
        scheduler.step()
        
        # 6. Logging and Checkpointing
        if step % log_every == 0:
            psnr = -10 * torch.log10(loss) / torch.log10(torch.tensor(10.0))
            print(f"Step {step}: Loss {loss.item():.6f}, PSNR {psnr.item():.2f}")
            
        if step % save_every == 0:
            save_checkpoint(model, optimizer, step, config.checkpoint_dir)
```

### Parameters
*   **Learning Rate (`lr`):** Default $5 \times 10^{-4}$ [S11, unofficial] or $1 \times 10^{-3}$ [S13, unofficial].
*   **Batch Size (`N_rand`):** Typically 1024 or 2048 rays per iteration [S5, S11, unofficial].
*   **Iterations (`n_iters`):** Default 100,000 [S11, unofficial].
*   **Decay:** Exponential decay with `decay_rate` = 0.1 and `decay_steps` = `args.lrate_decay` * 1000 [S5, S19, unofficial].
*   **Near/Far Bounds:** Scene-dependent (e.g., near=2, far=6 for Blender) [S2, S14, unofficial].

### Edge Cases and Pitfalls
*   **VRAM Overflow:** Large batches may exceed GPU memory. Mitigated by chunking rays during the forward pass [S5, unofficial].
*   **Gradient Computation Order:** Higher-order derivatives (for logging/visualization) must be computed *before* `loss.backward()` to avoid freeing the autograd graph [S3, unofficial].
*   **Resuming Training:** When loading a checkpoint, the scheduler's last epoch must be set to `start_epoch - 1` to ensure correct scheduling [S9, unofficial].
*   **Empty Checkpoints:** If a checkpoint is loaded but the step count is 0, it is treated as invalid [S16, unofficial].

### Supersampling Baseline
A baseline method for evaluating NeRF on multiscale data by training on full-resolution images and using brute-force supersampling during evaluation, or training on multiscale data with supersampling during both training and evaluation [S23]. For every pixel, multiple jittered rays are sampled uniformly at random through the spatial footprint of the pixel, and the mean of rendered values is used as the predicted color [S23]. This method relies on 'oracle' scale information that does not exist for most datasets and performs worse than mip-NeRF while being significantly more expensive [S23].

### Two-stage training for proposers
A training schedule split into two equal-duration phases to stabilize learning of a trainable proposer network in NeRF-ID [S24, unofficial]. Phase 1 trains the learnt proposer to mimic the heuristic proposer by minimizing the L2 matching loss between their proposal sets. Phase 2 trains all network components end-to-end, resetting the optimizer state and performing a linear warmup for 1,000 steps to reduce shock from switching regimes [S24, unofficial]. This two-stage approach is consistently effective where training from scratch often fails [S24, unofficial].

### JaxNeRF
A re-implementation of the original NeRF in JAX, used as a benchmark comparison for early works seeking to improve on training and rendering speed [S25]. It is slightly faster and more suited for distributed computing than the original TensorFlow implementation [S25].

### Gradient Detachment in Training
A training strategy where the object field component is detached from the backbone to prevent gradient backpropagation to the rendering part, ensuring independent optimization [S26, unofficial]. Without detachment, gradients from the object field backpropagate to the NeRF backbone, causing mutual influence and a significant drop in rendering quality [S26, unofficial]. Detachment achieves better scene rendering and decomposition quality [S26, unofficial].

### Ray Generator Network (RGN)
Used in MEIL-NeRF for incremental learning [S27]. During training on task $T$, the RGN $f_T^{RGN}$ learns to map past principal rays from $f_{T-1}^{RGN}$ and current GT principal rays [S27]. During inference, a principal ray is generated, and non-principal rays are randomly generated around it to form a cone [S27]. The network architecture has 3 hidden layers with 16, 64, and 32 hidden units [S27]. Unlike methods that reproduce exact past rays, RGN creates approximate rays directed to the scene of interest, allowing errors under a certain level to reduce the learning burden [S27].

### DFF
A method adopting pre-trained feature extraction networks (LSeg, DINO) as teacher networks for knowledge distillation, resulting in a scene-specific 3D feature field [S28]. This enables extraction and deletion of target objects based on image patches or text [S28].

### ISRF
A method that learns additional feature fields to realize self-supervised 3D segmentation [S28].

## Operating characteristics
*   **Time Complexity:** $O(N_{iters} \cdot N_{rand} \cdot N_{samples})$, where $N_{iters}$ is the number of iterations, $N_{rand}$ is the batch size (rays per step), and $N_{samples}$ is the number of samples per ray [S5, S11, unofficial].
*   **Memory Complexity:** $O(N_{rand} \cdot N_{samples})$ for storing intermediate rendering states during the forward pass [S5, unofficial]. VRAM usage can be mitigated by chunking rays [S5, unofficial].
*   **Measured Performance:** On a standard dataset (e.g., Blender), training for 100,000 iterations with a batch size of 1024 rays typically takes several hours on a modern GPU [S11, unofficial]. PSNR increases from ~10 dB to ~18-20 dB over 20-100 epochs depending on resolution and complexity [S12][S18, unofficial].
*   **Scaling:** Performance scales with the number of training views and resolution. Larger batch sizes improve throughput but may hinder data loading performance [S16, unofficial].
*   **Strengths:** Simple to implement, differentiable, and produces high-quality novel views from multi-view images [S5, S11, unofficial].
*   **Limitations:** Slow convergence, high memory usage for large scenes, and prone to overfitting or "floaters" in sparse views [S1][S18, unofficial].
*   **When to Use:** Standard multi-view reconstruction with dense input views.
*   **When Not to Use:** Sparse view scenarios (use [Sparse View and Initialization Methods](9394-sparse-view-and-initialization-methods.md)), dynamic scenes (use [Progressive and Dynamic Scene Growth](8869-progressive-and-dynamic-scene-growth.md)), or when real-time rendering is required (use [Acceleration and Sparse Structures](11405-acceleration-and-sparse-structures.md)).

## Background
The NeRF training loop was introduced by Mildenhall et al. in "NeRF: Representing Scenes as Neural Radiance Fields for View Synthesis" (2020) [S5, unofficial]. It builds on the concept of neural implicit representations and differentiable volume rendering [S11, unofficial]. The method uses an MLP to map 3D coordinates and viewing directions to density and color, optimized via stochastic gradient descent with MSE loss [S5, unofficial]. It has become the foundational training procedure for subsequent NeRF variants and 3D deep learning methods [S1][S11, unofficial].
