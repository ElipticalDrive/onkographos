# Text-Image Direction Score

Also called: TIDS

## Overview
The Text-Image Direction Score (TIDS) is a quantitative metric used in text-guided 3D scene editing to estimate the semantic alignment between the direction of a text prompt modification and the resulting direction of change in the rendered image [S1]. Unlike standard pixel-wise metrics such as PSNR or SSIM which measure fidelity to a ground-truth image, TIDS evaluates the *consistency of the edit* by comparing the vector difference in image space against the vector difference in text embedding space [S1]. It is primarily used to validate that a NeRF editing method (e.g., Instruct-NeRF2NeRF, ViCA-NeRF) successfully applies the semantic instruction specified by the user [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ camera views. For each view $i$, the inputs are:
    *   $oI_i$: The rendered image of the *original* (unmodified) NeRF scene.
    *   $eI_i$: The rendered image of the *edited* NeRF scene.
    *   $oT_i$: The text caption/prompt describing the *original* scene.
    *   $eT_i$: The text caption/prompt describing the *edited* scene (the instruction).
*   **Output:** A scalar score $S_i \in [-1, 1]$ for each view, representing the cosine similarity between the image edit direction and text edit direction.

**Data Structures:**
*   Images $oI_i, eI_i$ are normalized to $[0, 1]$ with shape $(C, H, W)$ [S1].
*   Text prompts are strings.
*   Embeddings are fixed-dimensional vectors (e.g., 512 or 768 dimensions depending on the CLIP variant).

**Method Steps:**
1.  **Encode Images:** Pass the original and edited images through the image encoder of a pre-trained CLIP model ($\mathbf{C}_I$) to obtain embeddings:
    $$ \mathbf{v}_{I, orig} = \mathbf{C}_I(oI_i) $$
    $$ \mathbf{v}_{I, edit} = \mathbf{C}_I(eI_i) $$
2.  **Encode Text:** Pass the original and edited text prompts through the text encoder of the same CLIP model ($\mathbf{C}_T$) to obtain embeddings:
    $$ \mathbf{v}_{T, orig} = \mathbf{C}_T(oT_i) $$
    $$ \mathbf{v}_{T, edit} = \mathbf{C}_T(eT_i) $$
3.  **Compute Direction Vectors:** Calculate the difference vectors in both modalities:
    $$ \mathbf{d}_I = \mathbf{v}_{I, edit} - \mathbf{v}_{I, orig} $$
    $$ \mathbf{d}_T = \mathbf{v}_{T, edit} - \mathbf{v}_{T, orig} $$
4.  **Calculate Cosine Similarity:** Compute the cosine similarity between the image direction $\mathbf{d}_I$ and the text direction $\mathbf{d}_T$:
    $$ S_i = \cos(\mathbf{d}_I, \mathbf{d}_T) = \frac{\mathbf{d}_I \cdot \mathbf{d}_T}{\|\mathbf{d}_I\| \|\mathbf{d}_T\|} $$
5.  **Aggregation:** Average $S_i$ across all views $i$ to produce the global TIDS score for the scene [S1].

**Pseudocode:**
```python
import torch
import torch.nn.functional as F
from transformers import CLIPModel, CLIPProcessor

def compute_text_image_direction_score(
    clip_model: CLIPModel,
    clip_processor: CLIPProcessor,
    original_images: torch.Tensor,  # Shape: (N, C, H, W), values in [0, 1]
    edited_images: torch.Tensor,    # Shape: (N, C, H, W), values in [0, 1]
    original_texts: list[str],
    edited_texts: list[str]
) -> float:
    """
    Computes the Text-Image Direction Score (TIDS).
    
    Args:
        clip_model: Pre-trained CLIP model (image and text encoders).
        clip_processor: Processor to normalize images and tokenize text.
        original_images: Tensor of original rendered images.
        edited_images: Tensor of edited rendered images.
        original_texts: List of text prompts for original scenes.
        edited_texts: List of text prompts for edited scenes.
        
    Returns:
        Average cosine similarity score across all views.
    """
    device = clip_model.device
    n_views = original_images.shape[0]
    total_score = 0.0
    
    # Process images: CLIP expects normalized inputs (typically mean/std normalized)
    # The processor handles normalization to [-1, 1] or [0, 1] depending on config, 
    # but standard CLIP image input is normalized.
    orig_img_inputs = clip_processor(images=original_images, return_tensors="pt").to(device)
    edit_img_inputs = clip_processor(images=edited_images, return_tensors="pt").to(device)
    
    # Process text
    orig_text_inputs = clip_processor(text=original_texts, return_tensors="pt", padding=True).to(device)
    edit_text_inputs = clip_processor(text=edited_texts, return_tensors="pt", padding=True).to(device)
    
    # Get embeddings
    with torch.no_grad():
        orig_img_embeds = clip_model.get_image_features(**orig_img_inputs)
        edit_img_embeds = clip_model.get_image_features(**edit_img_inputs)
        
        orig_text_embeds = clip_model.get_text_features(**orig_text_inputs)
        edit_text_embeds = clip_model.get_text_features(**edit_text_inputs)
        
    # Compute direction vectors
    # Note: CLIP embeddings are usually L2-normalized. 
    # The difference vector direction is what matters.
    img_direction = edit_img_embeds - orig_img_embeds
    text_direction = edit_text_embeds - orig_text_embeds
    
    # Compute cosine similarity for each view
    # Normalize direction vectors to handle zero-magnitude cases (no change)
    img_dir_norm = F.normalize(img_direction, p=2, dim=1)
    text_dir_norm = F.normalize(text_direction, p=2, dim=1)
    
    # Cosine similarity is dot product of normalized vectors
    similarities = torch.sum(img_dir_norm * text_dir_norm, dim=1)
    
    # Handle potential NaNs if a view had no change (zero vector)
    # [G] If a view is identical, the direction is undefined. 
    # We exclude these from the average or treat similarity as 0 or 1 depending on convention.
    # Standard practice in [S1] implies averaging valid scores.
    valid_mask = ~torch.isnan(similarities)
    if valid_mask.sum() == 0:
        return 0.0
        
    avg_score = similarities[valid_mask].mean().item()
    
    return avg_score
```

**Parameters:**
*   **CLIP Model:** The specific variant (e.g., ViT-L/14, ViT-B/32) affects embedding dimension and semantic granularity [S1].
*   **Text Prompts:** The accuracy of the score depends heavily on the specificity of $oT_i$ and $eT_i$ [S1].

**Edge Cases:**
*   **No Edit:** If $eI_i = oI_i$ and $eT_i = oT_i$, the direction vectors are zero. The cosine similarity is undefined. The implementation must handle this, typically by excluding the view or assigning a neutral score [G].
*   **Contradictory Edits:** If the text prompt suggests an edit that the model fails to apply, the score will be low or negative, indicating poor alignment [S1].

## Subtopics

### R-Precision
R-Precision measures how well a rendered view of a synthesis object aligns with the text caption used to generate it, functioning as a retrieval-based metric [S2]. Unlike TIDS which compares *changes*, R-Precision evaluates the *generation quality* of a single object-centric scene [S2].
*   **Method:** It computes the precision of rendered views over a group of text captions using a retrieval model [S2]. Specifically, it collects an object-centric captions dataset (e.g., from COCO) and samples captions for training [S2]. The precision of rendered views per synthesis object is computed over a set of captions (e.g., 153 captions) [S2].
*   **Backbones:** It uses both CLIP and BLIP2 as language-image model backbones for the score calculation [S2].
*   **Usage:** It is used in zero-shot object generation and blending contexts (e.g., Blended-NeRF) to ensure the generated object matches its textual description [S2].

## Operating characteristics
*   **Time Complexity:** Dominated by the forward pass of the CLIP encoder for images and text. For $N$ views, it requires $2N$ image encodings and $2N$ text encodings. This is significantly faster than rendering-based metrics but slower than pixel-wise MSE.
*   **Memory Complexity:** Requires storing embeddings for original and edited images/text. Memory usage is proportional to the batch size of views processed simultaneously.
*   **Performance:** In simple settings (e.g., 5 edits on NeRF-Art face scene), TIDS scores for methods like Instruct-NeRF2NeRF are approximately 0.1477, while ViCA-NeRF achieves 0.1545 [S1]. Higher scores indicate better semantic alignment between the text instruction and the visual edit.
*   **Strengths:** Directly measures the success of text-guided editing, which pixel-wise metrics cannot do. It is robust to global lighting changes that might affect PSNR but not semantic content.
*   **Limitations:** Relies on the semantic understanding of the CLIP model; it may not detect geometric inaccuracies or artifacts that do not change the high-level semantic embedding. It is sensitive to the choice of text prompts [S1].

## Background
The Text-Image Direction Score was introduced in the context of evaluating text-guided NeRF editing methods, specifically cited in the evaluation of Instruct-NeRF2NeRF and subsequent works like ViCA-NeRF [S1]. It builds upon the CLIP model [S1, S2], which provides a shared embedding space for images and text, allowing for cross-modal comparison. The metric addresses the limitation of traditional metrics (PSNR, SSIM) in editing scenarios where there is no single "ground truth" edited image, but rather a desired semantic transformation [S1].
