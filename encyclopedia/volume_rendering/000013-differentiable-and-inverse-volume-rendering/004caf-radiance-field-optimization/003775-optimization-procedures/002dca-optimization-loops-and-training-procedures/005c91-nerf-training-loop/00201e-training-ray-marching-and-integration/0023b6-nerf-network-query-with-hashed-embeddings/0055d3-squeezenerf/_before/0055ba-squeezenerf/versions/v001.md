# SqueezeNeRF

Also called: SqueezeNeRF (1K cache)

## Overview
SqueezeNeRF is a memory-efficient neural rendering method that further factorizes the position-dependent Multi-Layer Perceptron (MLP) of FastNeRF into three separate 2D networks operating on coordinate pairs $(x,y)$, $(y,z)$, and $(z,x)$ [S1]. This factorization reduces the cache size complexity from $O(n^3)$ to $O(n^2)$, enabling dense caching with less than 160 MB of memory while maintaining real-time rendering speeds [S1]. It builds on [FastNeRF](15528-fastnerf.md) by addressing its substantial memory overhead, making it suitable for embedded systems where sparse caching strategies used by other fast methods may be ineffective on dense scenes [S1].

## How it works
### Inputs and Outputs
**Inputs:**
- Camera viewing direction $(\theta, \phi)$.
- 3D spatial coordinates $(x, y, z)$ of sample points along a ray.
- Pre-computed caches for the position-dependent networks and view-dependent network.

**Outputs:**
- Final pixel color $(r, g, b)$ and density $\sigma$ via volume rendering integration.

### Data Structures and Cache Layout
The method relies on dense caches storing the outputs of the trained MLPs.

**Position Caches:**
For each of the three position networks $F_{pos}^j$ where $j \in \{(x,y), (y,z), (z,x)\}$, the cache stores outputs for a grid of size $n_p \times n_p$.
- **Default Configuration:**
  - $\sigma^j$ (scalar density component): Stored as 32-bit float.
  - $(u^j, v^j, w^j)$ (radiance map components): Stored as 16-bit floats. Each is a $D$-dimensional vector.
  - Total storage per 3D point combination (conceptually $n_p^3$ combinations, but stored as $3 \times n_p^2$ grids): $3n_p^2(3D + 1)$ values.
- **SqueezeNeRF (alt) Configuration:**
  - $\sigma^j \in \mathbb{R}^{D_\sigma}$, $k^j \in \mathbb{R}^{D_k}$ for $k \in \{u,v,w\}$.
  - Stored as 16-bit floats.
  - Total storage: $3n_p^2(3D_k + D_\sigma)$ values.

**Direction Cache:**
- Stores $\beta \in \mathbb{R}^D$ (deep radiance map weights) for $n_d \times n_d$ combinations of $(\theta, \phi)$.
- Stored as 16-bit floats.
- Total storage: $n_d^2(D)$ values.

**Standard Parameters:**
- $n_p$: Number of bins per position dimension. Values: 512 ('512 cache') or 1024 ('1K cache') [S1].
- $n_d$: Number of bins per direction dimension. Values: 64 (synthetic 360°) or 32 (LLFF) [S1].
- $D$: Dimensionality of radiance map vectors. Typical value: 8 [S1].
- $D_\sigma, D_k$: Used in 'alt' configuration. $D_\sigma=12, D_k=8$ [S1].

### Network Architecture
The method splits the position-dependent network $F_{pos}$ of FastNeRF into three networks:
1.  **Default Architecture:**
    -   $F_{pos}^j: j \rightarrow \{(\sigma_0^j, W_\sigma^j), (w_j^u, u_0^j, w_j^v, v_0^j, w_j^w, w_0^j)\}$ for $j \in \{(x,y), (y,z), (z,x)\}$ [S1].
    -   Each $F_{pos}^j$ is an MLP with 6 layers and 256 hidden units [S1].
    -   $F_{dir}$ (view-dependent) is an MLP with 4 layers and 128 hidden units [S1].
2.  **Alternate Architecture (SqueezeNeRF alt):**
    -   $F_{pos}^j: j \rightarrow \{\sigma^j, u^j, v^j, w^j\}$ [S1].
    -   $\sigma^j \in \mathbb{R}^{D_\sigma}$, $k^j \in \mathbb{R}^{D_k}$ [S1].
    -   Final $\sigma$ and $k$ are computed via linear combinations of concatenated outputs using learnable parameters $W_\sigma, b_\sigma, W_k, b_k$ stored in cache [S1].

### Numbered Steps
1.  **Ray Sampling:** Sample $N=256$ points along each projected ray [S1].
2.  **Cache Lookup:**
    -   For each point $(x,y,z)$, determine the grid indices for $(x,y)$, $(y,z)$, and $(z,x)$.
    -   Fetch $\sigma_0^j, u_0^j, v_0^j, w_0^j, W_\sigma^j, W_k^j$ from the respective position caches using **nearest neighbor interpolation** [S1].
    -   For the viewing direction $(\theta, \phi)$, fetch $\beta$ from the direction cache using **bilinear interpolation** [S1].
3.  **Intermediate Computation (Default):**
    -   Compute weighted components via pointwise multiplication:
        $$ \sigma^j = \sigma_0^j \cdot W_\sigma^j $$
        $$ k^j = W_k^j \cdot k_0^j \quad \forall k \in \{u, v, w\} $$
        where $W_\sigma^j \in \mathbb{R}$ and $W_k^j \in \mathbb{R}^D$ [S1].
4.  **Fusion (Default):**
    -   Combine outputs from the three 2D networks:
        $$ \sigma = \prod_{j \in \{(x,y),(y,z),(z,x)\}} \sigma^j $$
        $$ k = \sum_{j \in \{(x,y),(y,z),(z,x)\}} k^j \quad \forall k \in \{u, v, w\} $$
        Let $k = (u, v, w)$ be the final radiance map vector [S1].
    -   *Note:* In SqueezeNeRF (alt), fusion uses linear combinations: $\sigma = W_\sigma[\text{concat}(\{\sigma^j\})] + b_\sigma$ and $k = W_k[\text{concat}(\{k^j\})] + b_k$ [S1].
5.  **Color Computation:**
    -   Compute color $c = (r, g, b)$ using the inner product of $\beta$ and $k$:
        $$ c = \beta^T \cdot (u, v, w) = \sum_{i=1}^D \beta_i (u_i, v_i, w_i) $$
    -   Compute density $\sigma$ [S1].
6.  **Volume Rendering:**
    -   Compute final pixel color using standard volume rendering integration (Eq. 1 in [S1]) based on the computed $\sigma$ and $c$ at the sampled points [S1].

def bilinear_interpolate(cache, theta, phi, n_d):
    # Normalize theta, phi to [0, 1]
    u = theta / (2 * np.pi)
    v = phi / (2 * np.pi)
    
    # Grid indices
    x1 = int(np.floor(u * (n_d - 1)))
    y1 = int(np.floor(v * (n_d - 1)))
    x2 = min(x1 + 1, n_d - 1)
    y2 = min(y1 + 1, n_d - 1)
    
    # Weights
    wx = u * (n_d - 1) - x1
    wy = v * (n_d - 1) - y1
    
    # Interpolate
    # Cache shape: (n_d, n_d, D)
    val1 = cache[x1, y1]
    val2 = cache[x2, y1]
    val3 = cache[x1, y2]
    val4 = cache[x2, y2]
    
    interp1 = (1 - wx) * val1 + wx * val2
    interp2 = (1 - wx) * val3 + wx * val4
    result = (1 - wy) * interp1 + wy * interp2
    
    return result

### Edge Cases and Pitfalls
-   **Coordinate Pairing:** Splitting coordinates into individual $x, y, z$ dimensions instead of pairs $(x,y), (y,z), (z,x)$ leads to considerably inferior results [S1].
-   **Precision:** Using lower precision for $\sigma$ (e.g., 16-bit) may affect density accuracy, though sources specify 32-bit for $\sigma$ and 16-bit for radiance components [S1].
-   **Interpolation:** Nearest neighbor is used for position caches, which may cause artifacts at low resolutions ($n_p=512$) compared to bilinear [S1].

## Operating characteristics
-   **Time Complexity:** Inference is dominated by cache lookups and simple arithmetic, enabling real-time performance.
-   **Memory Complexity:** Cache size is $O(n_p^2)$, significantly lower than FastNeRF's $O(n_p^3)$ [S1].
-   **Measured Performance:**
    -   **Memory:** 1K cache ($n_p=1024$) uses 155 MB; 512 cache ($n_p=512$) uses 39 MB [S1]. This is >160x more efficient than dense FastNeRF and >65x more efficient than sparse FastNeRF [S1].
    -   **Speed:** Renders at 168 FPS on V100 and 202 FPS on A100 for 512 cache [S1]. 1K cache renders at 5 FPS on synthetic 360° (800x800) due to higher memory bandwidth demands or implementation specifics, but 165 FPS on V100 for 800x800 in Table 1?     -   **Cache Generation:** <9 seconds on V100 [S1].
-   **Strengths:** Extremely low memory footprint, fast cache generation, dense caching avoids geometry-based sparsity issues [S1].
-   **Limitations:** Image quality (PSNR/SSIM) is inferior to NeRF and some baselines due to the simple combination scheme [S1]. 'Alt' configuration improves quality but reduces speed [S1].

## Background
SqueezeNeRF was proposed in 2022 as a further factorization of FastNeRF [S1]. It addresses the memory overhead of FastNeRF, which, while fast, requires large caches (GBs) or sparse structures that may fail on dense scenes [S1]. The method builds on the observation that position-dependent networks can be decomposed into 2D sub-networks [S1].
