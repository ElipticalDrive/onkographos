# Text-Image Direction Score

Also called: TIDS

## Overview
The Text-Image Direction Score (TIDS) is a quantitative metric used in differentiable volume rendering to estimate the semantic alignment between text-driven scene edits and the resulting visual changes in rendered images [S1]. It measures the cosine similarity between the direction of change in the CLIP image embedding space and the direction of change in the CLIP text embedding space [S1]. Unlike standard pixel-wise metrics such as PSNR or SSIM, TIDS evaluates whether the *semantic intent* of a text prompt was correctly translated into the 3D scene's appearance [S1]. It is primarily used in text-guided NeRF editing pipelines to verify that modifications (e.g., "add fireworks") affect the correct regions and semantics without distorting unrelated content [S1].

## How it works
**Inputs:**
1.  Original rendered image $oI_i$ for a specific view $i$.
2.  Edited rendered image $eI_i$ for the same view $i$.
3.  Original text caption $oT_i$ describing the unedited scene.
4.  Edited text caption $eT_i$ describing the desired edited scene.
5.  CLIP image encoder $\mathbf{C}_I$ and CLIP text encoder $\mathbf{C}_T$ [S1].

**Data Structures:**
*   Embeddings are fixed-dimensional vectors (e.g., 512 or 768 dimensions depending on the CLIP variant) [S1].
*   Images are typically resized to the input resolution expected by CLIP (e.g., 224x224) before encoding [S1].

**Steps:**
1.  Encode the original rendered image $oI_i$ using the image encoder to obtain $\mathbf{C}_I(oI_i)$ [S1].
2.  Encode the edited rendered image $eI_i$ using the image encoder to obtain $\mathbf{C}_I(eI_i)$ [S1].
3.  Encode the original text caption $oT_i$ using the text encoder to obtain $\mathbf{C}_T(oT_i)$ [S1].
4.  Encode the edited text caption $eT_i$ using the text encoder to obtain $\mathbf{C}_T(eT_i)$ [S1].
5.  Compute the image direction vector: $\Delta \mathbf{V}_I = \mathbf{C}_I(eI_i) - \mathbf{C}_I(oI_i)$ [S1].
6.  Compute the text direction vector: $\Delta \mathbf{V}_T = \mathbf{C}_T(eT_i) - \mathbf{C}_T(oT_i)$ [S1].
7.  Calculate the cosine similarity between $\Delta \mathbf{V}_I$ and $\Delta \mathbf{V}_T$ [S1].

**Formula:**
$$ \text{TIDS} = \cos(\mathbf{C}_I(eI_i) - \mathbf{C}_I(oI_i), \mathbf{C}_T(eT_i) - \mathbf{C}_T(oT_i)) $$
$$ \text{TIDS} = \frac{(\mathbf{C}_I(eI_i) - \mathbf{C}_I(oI_i)) \cdot (\mathbf{C}_T(eT_i) - \mathbf{C}_T(oT_i))}{\|\mathbf{C}_I(eI_i) - \mathbf{C}_I(oI_i)\| \|\mathbf{C}_T(eT_i) - \mathbf{C}_T(oT_i)\|} $$

**Parameters:**
*   CLIP Model: Standard ViT-L/14 or RN50 variants are typically used [S1].
*   Image Resolution: Must match the CLIP encoder's expected input size [S1].

**Edge Cases and Pitfalls:**
*   **Zero Vector:** If the image or text does not change, the direction vector becomes zero, causing division by zero. A small epsilon or a check for zero magnitude is required [G].
*   **Semantic Drift:** High TIDS indicates semantic alignment but does not guarantee photorealism or geometric consistency [S1].
*   **View Dependence:** TIDS is computed per view $i$. Aggregation across multiple views is not defined in the base formula [S1].

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def compute_text_image_direction_score(clip_image_encoder, clip_text_encoder, 
                                       original_image, edited_image, 
                                       original_text, edited_text):
    """
    Computes the Text-Image Direction Score (TIDS).
    
    Args:
        clip_image_encoder: Function/Model to encode images to embeddings.
        clip_text_encoder: Function/Model to encode text to embeddings.
        original_image: Tensor of shape (H, W, 3) or (3, H, W), original rendered image.
        edited_image: Tensor of shape (H, W, 3) or (3, H, W), edited rendered image.
        original_text: String, caption for the original scene.
        edited_text: String, caption for the edited scene.
        
    Returns:
        float: Cosine similarity between image change direction and text change direction.
    """
    # 1. Encode images
    # Ensure inputs are preprocessed (e.g., resized to 224x224, normalized) as required by CLIP
    emb_o_img = clip_image_encoder(original_image)
    emb_e_img = clip_image_encoder(edited_image)
    
    # 2. Encode text
    emb_o_txt = clip_text_encoder(original_text)
    emb_e_txt = clip_text_encoder(edited_text)
    
    # 3. Compute direction vectors
    # Note: Embeddings are typically normalized in CLIP, but subtraction is done in raw space
    # according to the source formula [S1].
    delta_img = emb_e_img - emb_o_img
    delta_txt = emb_e_txt - emb_o_txt
    
    # 4. Handle zero vectors to avoid division by zero
    norm_img = torch.norm(delta_img)
    norm_txt = torch.norm(delta_txt)
    
    if norm_img < 1e-8 or norm_txt < 1e-8:
        return 0.0 # Or undefined, depending on implementation preference [G]
        
    # 5. Compute cosine similarity
    # Dot product
    dot_product = torch.dot(delta_img, delta_txt)
    
    # Cosine similarity
    score = dot_product / (norm_img * norm_txt)
    
    return score.item()
```

## Subtopics

### R-Precision
R-Precision measures how well a rendered view of a synthesis object aligns with the text caption used to generate it [S2]. It computes the precision of rendered views over a group of text captions using a retrieval model [S2]. The procedure involves collecting an object-centric captions dataset from the COCO dataset and sampling 20 captions for training [S2]. The precision of rendered views per synthesis object is then computed over 153 captions [S2]. The language-image model backbone can be either CLIP or BLIP2 [S2].

## Operating characteristics
*   **Complexity:** $O(1)$ relative to scene size, as it depends only on the number of views evaluated and the fixed cost of the CLIP encoder [S1].
*   **Performance:** In simple settings (5 edits on NeRF-Art face scene), ViCA-NeRF achieved a TIDS of 0.1545 compared to Instruct-NeRF2NeRF's 0.1477 [S1].
*   **Strengths:** Directly correlates with user intent in text-guided editing; robust to photometric variations that do not affect semantics [S1].
*   **Limitations:** Does not measure geometric accuracy or texture fidelity; sensitive to the quality of the text captions [S1].
*   **Usage:** Use for evaluating text-guided NeRF editing methods; not suitable for standard novel view synthesis evaluation [S1].

## Background
The Text-Image Direction Score was introduced in the context of evaluating text-guided NeRF editing methods, specifically following the quantitative evaluation framework established by Instruct-NeRF2NeRF [S1]. It was further utilized in ViCA-NeRF to demonstrate view-consistency-aware 3D editing capabilities [S1]. The metric relies on the CLIP model, which was originally developed for zero-shot image-text retrieval [S1].
