# LPIPS Computation

Also called: Learned Perceptual Image Patch Similarity, LPIPS Loss

## Overview
LPIPS is a full-reference perceptual similarity metric that quantifies the difference between two images by comparing deep feature activations from a pretrained convolutional neural network, rather than comparing raw pixel values [S1][S2, unofficial][S3]. It solves the limitation of pixel-wise metrics like MSE or PSNR, which often correlate poorly with human perception because they penalize phase shifts and ignore contextual, neighboring information [S4][S6, unofficial]. Unlike pointwise metrics, LPIPS captures high-level semantic and textural similarities, making it a superior objective for optimizing perceptual quality in differentiable rendering [S4][S6, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Two images, $x$ (reference) and $y$ (assessed/reconstructed), typically normalized to $[0, 1]$ or $[-1, 1]$.
- **Outputs:** A scalar distance value $LPIPS(x, y) \ge 0$. Lower values indicate higher perceptual similarity.

**Data Structures:**
- **Feature Maps:** For each layer $l$ in the backbone network, the input images are transformed into feature tensors $F^l_x$ and $F^l_y$.
- **Layer Dimensions:** Each feature map at layer $l$ has spatial dimensions $H_l \times W_l$ and channel depth $C_l$.
- **Learned Weights:** A set of scalar weights $w_l$ (or per-channel weights) is pre-computed for each layer to emphasize perceptually significant features.

**Numbered Steps:**
1. **Preprocessing:** Scale input images $x$ and $y$ from $[0, 1]$ to $[-1, 1]$ by computing $x' = 2.0 \cdot x - 1.0$ and $y' = 2.0 \cdot y - 1.0$ [S5, unofficial]. Add a batch dimension if the model expects it (e.g., shape $(1, C, H, W)$) [S5, unofficial].
2. **Feature Extraction:** Pass $x'$ and $y'$ through a pretrained backbone network (commonly VGG16 or AlexNet) [S1][S3][S5, unofficial]. Extract intermediate feature maps $f_l(x')$ and $f_l(y')$ from multiple layers $l \in \{1, \dots, L\}$ [S2, unofficial].
3. **Normalization (Implicit in Standard Implementation):** In the original LPIPS formulation, features are often normalized per channel to have zero mean and unit variance across the training set to ensure scale invariance [G]. *Note: The provided sources do not explicitly detail the normalization step, but it is standard in the reference implementation to prevent channel magnitude dominance.*
4. **Distance Calculation:** For each layer $l$, compute the weighted squared Euclidean distance between the feature maps of $x$ and $y$ [S1][S2, unofficial].
5. **Aggregation:** Sum the weighted distances across all layers to produce the final LPIPS score [S1][S2, unofficial].

**Formulas:**
The LPIPS distance is defined as [S1][S2, unofficial]:

$$
LPIPS(x, y) = \sum_{l} w_l \| f_l(x) - f_l(y) \|_2^2
$$

Where:
- $l$ indexes the layers of the backbone network.
- $w_l$ are the learned weights for layer $l$. In the pixel-wise formulation [S1], this is expanded as:
  $$
  LPIPS(x, y) = \sum_{l} \frac{1}{H_l W_l} \sum_{h,w} \| w_l \odot (x^l_{hw} - y^l_{hw}) \|_2^2
  $$
  where $x^l_{hw}, y^l_{hw}$ are the feature vectors at pixel $(h,w)$ and layer $l$, and $\odot$ denotes element-wise multiplication with the weight vector $w_l$ [S1].
- $H_l, W_l$ are the height and width of the feature map at layer $l$ [S1].
- $\| \cdot \|_2^2$ is the squared $L_2$ norm [S2, unofficial].

**Parameters:**
- **Backbone Architecture:** The original paper used SqueezeNet, VGG, and AlexNet [S1]. VGG16 is the most common choice in modern implementations [S5, unofficial]. AlexNet is also used in specific contexts [S3].
- **Weights ($w_l$):** Pre-computed weights that reflect the perceptual importance of each layer. These are not learned during the rendering optimization but are fixed from the original LPIPS training [S1][S2, unofficial].
- **Normalization:** Not given in the sources. [G] Standard practice involves normalizing features to zero mean and unit variance per channel using statistics from the ImageNet training set.

**Edge Cases and Pitfalls:**
- **Weight Download:** The first run requires downloading pretrained weights (e.g., from the LPIPS repository or Torch Hub) to the cache directory (e.g., `TORCH_HOME`) [S5, unofficial]. If internet access is unavailable, weights must be pre-cached.
- **Input Range:** Inputs must be scaled to $[-1, 1]$ before passing to the network if the backbone expects it (as in many PyTorch pretrained models) [S5, unofficial]. Failure to do so may result in incorrect feature activations.
- **Gradient Flow:** LPIPS is differentiable with respect to the input images, allowing it to be used as a loss function in gradient-based optimization [S6, unofficial]. However, it is computationally expensive compared to pixel-wise losses.

**Pseudocode:**
```python
import torch
import torch.nn as nn

def compute_lpips(reference: torch.Tensor, assessed: torch.Tensor, 
                  backbone: nn.Module, weights: list) -> torch.Tensor:
    """
    Compute LPIPS distance between reference and assessed images.
    
    Args:
        reference: Tensor of shape (B, C, H, W) in range [0, 1].
        assessed: Tensor of shape (B, C, H, W) in range [0, 1].
        backbone: Pretrained VGG/AlexNet model in eval mode.
        weights: List of learned weights for each layer.
        
    Returns:
        Scalar LPIPS distance.
    """
    # Step 1: Preprocessing
    # Scale from [0, 1] to [-1, 1]
    ref_scaled = 2.0 * reference - 1.0
    ass_scaled = 2.0 * assessed - 1.0
    
    # Step 2: Feature Extraction
    # Get feature maps from multiple layers
    # Note: The backbone must be configured to return intermediate features
    ref_features = backbone(ref_scaled)
    ass_features = backbone(ass_scaled)
    
    # Step 3: Distance Calculation
    lpips_score = 0.0
    for l, (ref_feat, ass_feat, w) in enumerate(zip(ref_features, ass_features, weights)):
        # ref_feat, ass_feat: (B, C, H_l, W_l)
        
        # Compute squared L2 distance between feature maps
        # Element-wise difference
        diff = ref_feat - ass_feat
        
        # Square the difference
        sq_diff = diff ** 2
        
        # Apply learned weights (element-wise multiplication)
        # w is typically a 1D tensor of size C or broadcastable
        weighted_sq_diff = w * sq_diff
        
        # Average over spatial dimensions (H_l, W_l) and channels if needed
        # The formula in [S1] averages over H_l * W_l
        # Assuming w is applied per-channel, we sum over channels and average over space
        # Or if w is scalar per layer, we just average over space and channels
        
        # Standard LPIPS implementation averages over spatial dimensions and channels
        # Here we follow the structure: sum over layers, average over spatial dims
        layer_dist = torch.mean(weighted_sq_diff)
        
        lpips_score += layer_dist
        
    return lpips_score
```

## Subtopics

### [Wasserstein Distortion](15233-wasserstein-distortion.md)
Wasserstein Distortion (WD) is a perceptual image-to-image metric that compares spatially local estimates of statistics (mean and standard deviation) in deep feature space, allowing textures with large pointwise differences but similar local statistics to be considered perceptually similar. Unlike pointwise metrics such as [LPIPS Computation](5498-lpips-computation.md) which penalize phase shifts and exact pixel alignment, WD models human peripheral vision by aggregating features over local pooling regions, making it suitable for optimizing perceptual texture quality in differentiable rendering.

## Operating characteristics
- **Time Complexity:** $O(L \cdot H \cdot W \cdot C)$ per image pair, where $L$ is the number of layers, $H, W$ are spatial dimensions, and $C$ is the number of channels. The dominant cost is the forward pass through the backbone network.
- **Memory Complexity:** $O(L \cdot H \cdot W \cdot C)$ to store intermediate feature maps during the forward pass.
- **Measured Performance:** LPIPS is significantly more expensive to compute than PSNR or MSE. It requires a full forward pass through a deep CNN (e.g., VGG16 has ~138M parameters) [S1][S5, unofficial].
- **Strengths:** Strong correlation with human perception [S3]. Better optimization objective than pixel-wise metrics like MSE [S6, unofficial]. Captures structural and textural nuances [S4].
- **Limitations:** Computationally expensive. Requires pretrained weights. Less sensitive to low-frequency errors than PSNR. Not suitable for real-time feedback loops due to latency.
- **When to Use:** When perceptual quality is the primary goal, such as in novel view synthesis, image editing, or texture optimization.
- **When Not to Use:** When computational efficiency is critical, or when pixel-perfect accuracy is required (e.g., medical imaging diagnostics where structural fidelity is paramount).

## Background
LPIPS was introduced by Zhang et al. in 2018 [S1][S3]. It was designed to address the poor correlation between traditional metrics (PSNR, SSIM) and human perceptual judgment. The metric uses features extracted from pretrained networks (AlexNet, VGG, SqueezeNet) to measure similarity [S1]. It has become a standard evaluation metric in neural rendering, particularly for NeRF and Gaussian Splatting, where perceptual quality is often more important than pixel-wise accuracy [S4][S6, unofficial].
