# Warped LPIPS Metric

Also called: E_warp (LPIPS variant), Warped LPIPS Consistency Metric, Warped View Consistency with LPIPS

## Overview
The Warped LPIPS Metric is a no-reference evaluation method used to assess geometric and photometric consistency across viewpoints in novel view synthesis, particularly for stylized or super-resolved NeRFs [S1, S2]. It quantifies consistency by computing the Learned Perceptual Image Patch Similarity (LPIPS) between a target rendered view and a source view warped into the target's coordinate system using estimated depth [S1, S2]. Unlike standard metrics that require ground truth, it measures how well the underlying 3D structure supports consistent appearance from nearby angles [S1]. It distinguishes itself from the base View-Consistency Metric (E_warp) by using LPIPS instead of MSE, making it more sensitive to perceptual artifacts and texture consistency [S1, S2].

## How it works
**Inputs:**
- $I_v$: Rendered image from target viewpoint $v$.
- $I_{v'}$: Rendered image from source viewpoint $v'$ (a nearby viewpoint).
- $D_{v'}$: Predicted depth map corresponding to $I_{v'}$.
- $K_v, K_{v'}$: Intrinsic camera matrices for viewpoints $v$ and $v'$.
- $T_{v \to v'}$: Extrinsic transformation matrix from $v$ to $v'$.
- $M_{v,v'}$: Warping mask indicating valid pixels (occlusion-free regions).

**Outputs:**
- $E_{warp}$: Scalar LPIPS score representing inconsistency. Lower values indicate higher consistency.

**Data Structures:**
- Depth map $D_{v'}$: 2D array of floats, shape $(H, W)$, where each element represents the distance from the camera center to the surface along the ray.
- Warping mask $M_{v,v'}$: 2D binary array, shape $(H, W)$, where 1 indicates a valid pixel and 0 indicates an occluded or invalid region.

**Steps:**

1. **Select Source Viewpoint:**
   Select $v'$ as the 3rd nearest test pose from $v$ [S1]. For short-range consistency, pairs with a gap of 5 indices ($O_i, O_{i+5}$) are used; for long-range, a gap of 15 ($O_i, O_{i+15}$) is used [S2].

2. **Backproject to World Space:**
   For each pixel $(u, v)$ in $I_{v'}$ with depth $d = D_{v'}[u, v]$:
   - Convert pixel coordinates to normalized device coordinates (NDC) or camera coordinates using $K_{v'}$.
   - Unproject to world space coordinates $P_{world}$ using the inverse of the extrinsic matrix $T_{v \to v'}$ and depth $d$.
   - This creates a point cloud in world space [S1].

3. **Reproject to Target View:**
   - Project the world space points $P_{world}$ onto the image plane of viewpoint $v$ using $K_v$ and the extrinsic matrix of $v$.
   - This yields warped coordinates $(u', v')$ in the target image space.

4. **Render Warped Image $W(I_{v'})$:**
   - Use a point cloud rasterizer to render the warped image $W(I_{v'})$ at viewpoint $v$ [S1].
   - The rasterizer samples the color from $I_{v'}$ at the backprojected locations and interpolates to fill the target grid.
   - [G] Handle floating-point inaccuracies by clamping projected coordinates to image bounds and discarding points with negative depth relative to $v$.

5. **Compute Warping Mask $M_{v,v'}$:**
   - Identify pixels in the target view $v$ that correspond to valid, non-occluded regions in $v'$.
   - [G] Common implementation: Cast rays from $v$ through each pixel. If the ray intersects the surface defined by $D_{v'}$ (warped back to $v$'s space) at a distance closer than the depth rendered by $I_v$, mark as occluded (0). Otherwise, mark as valid (1).
   - The mask ensures LPIPS is only computed on geometrically consistent regions [S2].

6. **Compute LPIPS Score:**
   - Calculate the LPIPS score between the masked target image $M_{v,v'} \cdot I_v$ and the warped image $W(I_{v'})$ [S1, S2].
   - Formula:
     $$ E_{warp}(I_v, I_{v'}) = \text{LPIPS}(M_{v,v'} \cdot I_v, W(I_{v'})) $$
   - Only pixels where $M_{v,v'} = 1$ contribute to the LPIPS calculation [S2].

**Pseudocode:**

```python
def compute_warped_lpips(I_v, I_v_prime, D_v_prime, K_v, K_v_prime, T_v_to_v_prime, T_v):
    """
    Compute the Warped LPIPS metric between view v and v'.
    
    Args:
        I_v: Target rendered image (H, W, 3)
        I_v_prime: Source rendered image (H, W, 3)
        D_v_prime: Depth map for source view (H, W)
        K_v, K_v_prime: Camera intrinsics
        T_v_to_v_prime: Extrinsics from v to v'
        T_v: Extrinsics for view v
        
    Returns:
        E_warp: Scalar LPIPS score
    """
    H, W = I_v.shape[:2]
    
    # 1. Backproject source pixels to world space
    # Create grid of pixel coordinates
    u, v = np.meshgrid(np.arange(W), np.arange(H))
    
    # Convert to camera coordinates in v'
    # Assuming pinhole model: x = (u - cx)/fx, y = (v - cy)/fy
    fx, fy = K_v_prime[0, 0], K_v_prime[1, 1]
    cx, cy = K_v_prime[0, 2], K_v_prime[1, 2]
    
    x_cam = (u - cx) / fx
    y_cam = (v - cy) / fy
    
    # Unproject to world space using depth
    # P_world = T_v_to_v_prime^-1 * [x_cam * d, y_cam * d, d, 1]^T
    # Note: T_v_to_v_prime transforms v to v'. We need points in v' space to transform to v.
    # Actually, we have points in v' camera space. We need to transform them to world, then to v.
    # Let's assume T_v_to_v_prime is the transform from v to v'.
    # So inverse transforms v' to v? No, usually T is world-to-camera or camera-to-world.
    # Standard: P_world = T_world_to_cam^-1 * P_cam.
    # If T_v_to_v_prime is v -> v', then P_v_prime = T_v_to_v_prime * P_v.
    # We have P_v_prime (from depth). We want P_v.
    # P_v = T_v_to_v_prime^-1 * P_v_prime.
    
    # Construct homogeneous coordinates in v' camera space
    Z = D_v_prime
    X = x_cam * Z
    Y = y_cam * Z
    
    # Stack to (4, H, W)
    P_v_prime_homo = np.stack([X, Y, Z, np.ones_like(Z)], axis=0)
    
    # Transform to v camera space
    # T_inv is the inverse of T_v_to_v_prime
    T_inv = np.linalg.inv(T_v_to_v_prime)
    
    # Apply transformation
    P_v_homo = T_inv @ P_v_prime_homo # (4, H, W)
    
    X_v = P_v_homo[0] / P_v_homo[2]
    Y_v = P_v_homo[1] / P_v_homo[2]
    Z_v = P_v_homo[2]
    
    # 2. Project to target image coordinates
    fx_v, fy_v = K_v[0, 0], K_v[1, 1]
    cx_v, cy_v = K_v[0, 2], K_v[1, 2]
    
    u_warped = X_v * fx_v + cx_v
    v_warped = Y_v * fy_v + cy_v
    
    # 3. Create Warped Image W(I_v_prime)
    # Use bilinear interpolation to sample I_v_prime at (u_warped, v_warped)
    # Clip coordinates to image bounds
    u_warped_clipped = np.clip(u_warped, 0, W - 1)
    v_warped_clipped = np.clip(v_warped, 0, H - 1)
    
    # Sample colors
    # Note: I_v_prime is (H, W, 3). Need to index carefully.
    # Using scipy.ndimage.map_coordinates or similar for bilinear interpolation
    coords = np.stack([v_warped_clipped, u_warped_clipped], axis=-1)
    W_I_v_prime = map_coordinates(I_v_prime, coords, mode='nearest')
    
    # 4. Compute Warping Mask M_v,v'
    # Mask is 1 if the point is valid (positive depth in v) and not occluded.
    # Occlusion check: Compare depth of warped point Z_v with depth of I_v at (u_warped, v_warped).
    # If Z_v > Depth_I_v, then the warped point is behind the surface, so it's occluded.
    
    # Get depth of I_v (assumed available or estimated)
    # For simplicity, assume we have D_v (depth of target view)
    # If D_v is not available, this step cannot be completed without estimation.
    # The source mentions "predicted depths", implying D_v is also available.
    # Let's assume D_v is passed or estimated similarly.
    
    # Check bounds
    valid_bounds = (u_warped >= 0) & (u_warped < W) & (v_warped >= 0) & (v_warped < H)
    valid_depth = Z_v > 0
    
    # Occlusion check (requires D_v)
    # Interpolate D_v at warped coordinates
    coords_d = np.stack([v_warped_clipped, u_warped_clipped], axis=-1)
    D_v_sampled = map_coordinates(D_v, coords_d, mode='nearest')
    
    # Valid if warped depth is closer than target depth (not occluded)
    # Note: In camera coordinates, smaller Z is closer.
    # So if Z_v < D_v_sampled, it is in front (not occluded).
    # If Z_v > D_v_sampled, it is behind (occluded).
    not_occluded = Z_v < D_v_sampled
    
    M_v_v_prime = (valid_bounds & valid_depth & not_occluded).astype(float)
    
    # 5. Compute LPIPS
    # Apply mask
    I_v_masked = I_v * M_v_v_prime[..., np.newaxis]
    
    # Compute LPIPS between I_v_masked and W_I_v_prime
    # LPIPS function takes two images and returns a scalar
    E_warp = lpips_score(I_v_masked, W_I_v_prime)
    
    return E_warp
```

**Parameters:**
- **View Selection:** $v'$ is the 3rd nearest test pose [S1].
- **Consistency Range:** Short-range uses view pairs with a gap of 5; long-range uses a gap of 15 [S2].
- **LPIPS Model:** Standard LPIPS network (typically VGG or AlexNet based) [S1, S2].

**Edge Cases and Pitfalls:**
- **Occlusions:** The warping mask must correctly identify occluded regions. Incorrect masking leads to high LPIPS scores due to comparing background with foreground [S2].
- **Depth Errors:** Inaccurate depth predictions in $D_{v'}$ cause misalignment in warping, increasing LPIPS even if the view is consistent [S1, S2].
- **Boundary Conditions:** Pixels near image borders may not have valid correspondences, requiring careful handling of the mask [S1].

## Subtopics

### Short-Range Consistency
Measures consistency between very close viewpoints (gap of 5). Sensitive to high-frequency details and local geometry. Use when evaluating fine-grained texture consistency [S2].

### Long-Range Consistency
Measures consistency between viewpoints further apart (gap of 15). Sensitive to global structure and large-scale geometry. Use when evaluating overall 3D coherence [S2].

## Operating characteristics
- **Time Complexity:** Dominated by the backprojection and rasterization steps, which are $O(H \times W)$ per view pair. LPIPS computation is also $O(H \times W)$ but involves neural network inference.
- **Memory Complexity:** $O(H \times W)$ for storing depth maps, warped images, and masks.
- **Measured Performance:** On the LLFF dataset, the metric shows low scores for high-consistency methods. For short-range consistency, scores range from 0.0018 (Trex) to 0.0037 (Orchids) for the best method [S2]. For long-range, scores range from 0.0049 (Fern) to 0.0140 (Trex) [S2].
- **Strengths:** No-reference; perceptually relevant (LPIPS); sensitive to both geometric and photometric inconsistencies [S1, S2].
- **Limitations:** Requires predicted depth maps; sensitive to depth estimation errors; computationally more expensive than MSE-based metrics [S1, S2].
- **When to Use:** Evaluating novel view synthesis methods where ground truth is unavailable, especially for stylized or super-resolved NeRFs [S1, S2].
- **When Not to Use:** When ground truth is available (use PSNR/SSIM); when depth estimation is unreliable [S1, S2].

## Background
The Warped LPIPS Metric was introduced as a no-reference evaluator for assessing view consistency in NeRF-based super-resolution and stylization tasks [S1, S2]. It builds on the concept of warping views using depth to detect inconsistencies, adapting the LPIPS metric for perceptual quality assessment [S1, S2]. It is used in evaluating methods like DiSR-NeRF and Instant Photorealistic Neural Radiance Fields Stylization [S1, S2].
