# NeRFPlayer

Also called: Decomposed Neural Radiance Fields, NeRFPlayer Decomposed Neural Radiance Fields

## Overview
NeRFPlayer is a dynamic scene representation method that decomposes a spatiotemporal volume into stationary, deforming, and new (streaming) areas to enable efficient training and streaming of dynamic neural radiance fields [S1]. It distinguishes itself from sibling methods like MegaNeRF and Spatial Partitioning for Distributed NeRF by explicitly modeling the temporal evolution of scene components through a decomposition field, allowing for high-quality temporal interpolation and low-bitrate streaming without requiring multi-view synchronization or optical flow priors [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A sequence of RGB images of a dynamic scene captured from varying viewpoints (single-camera or multi-camera). No depth, optical flow, or special capturing settings are required [S1].
*   **Outputs:** A decomposed neural radiance field representation consisting of cached features and MLP decoders, capable of rendering novel views and interpolating time [S1].

**Data Structures:**
The representation consists of four main components, implemented as hybrid explicit/implicit structures:
1.  **Decomposition Field ($f$):** Determines the area type (stationary, deforming, new) for any spatial point. It consists of explicitly cached features ($V_f$) and a small MLP decoder ($D_f$) [S1].
2.  **Deformation Field ($d$):** An MLP that maps spatial coordinates to deformation vectors for deforming areas [S1].
3.  **Stationary Field ($s$):** An MLP that outputs static radiance and density for stationary areas [S1].
4.  **Radiance Field ($r$):** An MLP that outputs radiance and density for new/streaming areas. It shares the same structure as the decoder in the chosen backbone (InstantNGP or TensoRF) [S1].

**Parameters:**
*   **Threshold ($\tau$):** Probability threshold for skipping field forwarding. Default: $0.001$ [S1].
*   **Deformation Network:** 4-layer MLP, width 256 [S1].
*   **Stationary Field ($s$):** 2-layer MLP, width 64 [S1].
*   **Radiance Field ($r$):** 4-layer MLP, width 64 [S1].
*   **Backbone (InstantNGP):** 8 levels, 4 feature dimensions per entry [S1].
*   **Backbone (TensoRF):** Follows original TensoRF settings on LLFF datasets [S1].
*   **Streaming Channels ($k$):** Number of new channels needed for rendering a new frame. Default: $1$ [S1].
*   **Loss Balancing ($\lambda$):** Weight for regularization. Default: $0.1$ [S1].
*   **Deformation Penalty ($\alpha$):** Hyper-parameter to penalize deforming areas. Default: $0.01$ [S1].

**Algorithm Steps:**
1.  **Ray Sampling:** For a given camera pose and time $t$, sample points along the ray.
2.  **Decomposition Classification:** Forward sampled points through the decomposition field $f$ to obtain probabilities for each area type: stationary ($P_s$), deforming ($P_d$), and new ($P_n$) [S1].
3.  **Efficiency Skip:** If the maximum probability $P^* < \tau$ (default $0.001$), set the deformation velocity $v^* = 0$ and skip the forwarding process of the deformation field $d$ [S1].
4.  **Field Forwarding:**
    *   If the point is classified as **stationary**, query the stationary field $s$ [S1].
    *   If the point is classified as **deforming**, query the deformation field $d$ to get the deformation vector, then query the stationary field $s$ at the deformed position [S1].
    *   If the point is classified as **new**, query the radiance field $r$ [S1].
5.  **Volume Rendering:** Combine the outputs (density and color) from the active fields using standard volume rendering integration [S1].
6.  **Loss Calculation:** Compute the total loss $\mathcal{L}$ as:
    $$ \mathcal{L} = \mathcal{L}_{rec} + \lambda \mathcal{L}_{reg} $$
    where $\mathcal{L}_{rec}$ is the reconstruction loss (e.g., MSE) and $\mathcal{L}_{reg}$ is a regularization term weighted by $\lambda$ [S1].
7.  **Optimization:** Update network parameters using gradient descent. The deformation penalty $\alpha$ is used within the regularization or classification logic to control the sparsity of deforming areas [S1].

**Pseudocode:**
```python
def nerfplayer_forward(ray_origin, ray_direction, time_t, decomposition_field, deformation_field, stationary_field, radiance_field, tau=0.001, alpha=0.01, lambda_reg=0.1):
    """
    Renders a single ray using the NeRFPlayer decomposition.
    
    Args:
        ray_origin: (3,) array, camera origin.
        ray_direction: (3,) array, normalized ray direction.
        time_t: float, current time step.
        decomposition_field: Object with method get_probabilities(point).
        deformation_field: Object with method forward(point).
        stationary_field: Object with method forward(point).
        radiance_field: Object with method forward(point).
        tau: float, threshold to skip deformation field.
        alpha: float, penalty for deforming areas.
        lambda_reg: float, regularization weight.
        
    Returns:
        color: (3,) array, rendered color.
        loss: float, total loss including regularization.
    """
    # 1. Sample points along the ray
    # [G] Standard NeRF sampling strategy (e.g., uniform + importance sampling)
    points = sample_points(ray_origin, ray_direction, num_samples=256)
    
    # 2. Get probabilities for each area type
    # [S1] Forward sampled points through the decomposition field
    probs = decomposition_field.get_probabilities(points)
    # probs is a tensor of shape (N, 3) for [P_stationary, P_deforming, P_new]
    
    # 3. Initialize outputs
    densities = zeros(N)
    colors = zeros((N, 3))
    reg_loss = 0.0
    
    # 4. Process points based on classification
    for i in range(N):
        p_s, p_d, p_n = probs[i]
        point = points[i]
        
        # Determine dominant type
        max_prob = max(p_s, p_d, p_n)
        
        if max_prob < tau:
            # [S1] Skip deformation field if probability is low
            v = zeros(3)
            # Assume stationary for rendering if not clearly dynamic
            # [G] Fallback to stationary field if no clear classification
            sigma, c = stationary_field.forward(point)
        elif p_d > p_s and p_d > p_n:
            # Deforming area
            # [S1] Query deformation field
            v = deformation_field.forward(point)
            # Deform the point
            point_deformed = point + v
            # Query stationary field at deformed position
            sigma, c = stationary_field.forward(point_deformed)
            # [S1] Apply penalty alpha to deforming areas in regularization
            reg_loss += alpha * norm(v)
        elif p_n > p_s and p_n > p_d:
            # New/Streaming area
            sigma, c = radiance_field.forward(point)
        else:
            # Stationary area
            sigma, c = stationary_field.forward(point)
            
        densities[i] = sigma
        colors[i] = c
        
    # 5. Volume Rendering
    # [G] Standard alpha compositing
    T = 1.0
    final_color = zeros(3)
    for i in range(N):
        alpha_i = 1.0 - exp(-densities[i] * delta_t) # delta_t is step size
        T *= (1.0 - alpha_i)
        final_color += alpha_i * T * colors[i]
        
    # 6. Reconstruction Loss
    # [S1] L_rec is typically MSE against ground truth pixel
    # [G] Assume gt_color is available from input
    rec_loss = mse(final_color, gt_color)
    
    total_loss = rec_loss + lambda_reg * reg_loss
    
    return final_color, total_loss
```

**Edge Cases and Pitfalls:**
*   **High FPS Multi-Camera Datasets:** Deformation is not used by default for efficiency because modeling every dynamic area as new areas leads to good temporal interpolation performance [S1].
*   **Large $\alpha$ (e.g., 1):** Over-suppresses deforming areas, leading to blurry moving objects [S1].
*   **Small $\alpha$ (e.g., 0.005):** Under-suppresses deforming areas, leading to a noisy scene [S1].
*   **Recommended Practice:** Start with a relatively large $\alpha$ to penalize deforming areas, then gradually decrease $\alpha$ to allow areas to deform [S1].

## Subtopics

### Backbone Integration
NeRFPlayer is a general framework that can be built on top of any hybrid representation adopting explicit features. It is primarily implemented with InstantNGP and TensoRF backbones [S1].

### Streaming Optimization
The method supports streaming by tuning the number of new channels $k$ required for rendering a new frame, allowing for bitrate control [S1].

## Operating characteristics
**Time and Memory Complexity:**
*   **Training Time:** On Plenoptic Video dataset, NeRFPlayer (InstantNGP) takes 22.797 GPU hours, compared to 28.448 (Neural Volumes), 29.580 (NeRF-T), and 30.293 (DyNeRF) [S1].
*   **Rendering Time:** On Plenoptic Video dataset, NeRFPlayer (InstantNGP) takes 5.5 s/img, compared to 10.8 s/img (Neural Volumes), 22.1 s/img (NeRF-T), and 30.692 s/img (DyNeRF) [S1].
*   **Bitrate:** For streaming, TensoRF-CP achieves low bitrate, while TensoRF-VM has higher cost but better performance. The first frame requires 96 channels for TensoRF-CP and 4 for TensoRF-VM. Subsequent frames require $k$ new channels [S1].

**Measured Performance:**
*   **PSNR (HyperNeRF-vrig Mean):** NeRFPlayer (InstantNGP) achieves 22.4, compared to 22.4 (HyperNeRF), 22.2 (Nerfies), 26.3 (NSFF), 16.9 (NV), and 20.1 (NeRF) [S1].
*   **SSIM (HyperNeRF-vrig Mean):** NeRFPlayer (InstantNGP) achieves 0.814, compared to 0.814 (HyperNeRF), 0.803 (Nerfies), 0.916 (NSFF), 0.571 (NV), and 0.745 (NeRF) [S1].
*   **Ablation (HyperNeRF-interp):** Full decomposition PSNR is 29.2, w/o deforming is 28.2, w/o new is 28.2 [S1].
*   **Ablation (Immersive Video - Horse):** w/o static PSNR is 27.0, w/ static is 27.4 [S1].
*   **Ablation (Immersive Video - Welder, every 8 frames):** w/o deforming PSNR is 26.1, w/ deforming is 25.2 [S1].

**Strengths and Limitations:**
*   **Strengths:** Significantly reduces training and rendering time compared to prior works (e.g., 12% of DyNeRF's rendering time) [S1]. Achieves higher PSNR than HyperNeRF, generating more accurate images [S1]. Better performance on fast-moving objects compared to DyNeRF (TensoRF-VM variant) [S1].
*   **Limitations:** Slightly lower SSIM than HyperNeRF, resulting in less sharp images [S1]. HyperNeRF suffers from misalignment of moving objects due to incorrect deformation modeling, which NeRFPlayer avoids by decomposing static and dynamic areas [S1].

**When to Use:**
*   Use NeRFPlayer when efficient training and rendering of dynamic scenes are required, especially for streaming applications where bitrate control is important [S1].
*   Choose the InstantNGP backbone for faster rendering and training, or the TensoRF backbone for better performance on fast-moving objects or lower bitrate requirements [S1].

## Background
NeRFPlayer was introduced in the paper "NeRFPlayer: A Streamable Dynamic Scene Representation with Decomposed Neural Radiance Fields" [S1]. It addresses the limitations of existing dynamic NeRF methods that either require multi-view synchronization, optical flow priors, or suffer from high computational costs and flickering backgrounds [S1]. The method builds on the idea of decomposing the scene into stationary, deforming, and new areas to handle dynamic content more effectively [S1].
