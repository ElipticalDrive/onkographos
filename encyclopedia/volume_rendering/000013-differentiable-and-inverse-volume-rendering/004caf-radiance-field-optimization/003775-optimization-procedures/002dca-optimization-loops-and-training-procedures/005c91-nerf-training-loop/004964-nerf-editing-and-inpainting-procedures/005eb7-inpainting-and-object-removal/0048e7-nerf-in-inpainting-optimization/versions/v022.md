# NeRF-In Inpainting Optimization

Also called: Free-Form NeRF Inpainting with RGB-D Priors, NeRF object removal

## Overview
NeRF-In is a framework for removing unwanted objects from a pre-trained Neural Radiance Field (NeRF) by optimizing its parameters $\Theta$ using color and depth guidance derived from 2D images, without requiring category-specific training data [S1, unofficial]. It sets itself apart from sibling methods like [Adaptive View Selection for Inpainting](12405-adaptive-view-selection-for-inpainting.md) by explicitly formulating a joint optimization problem that minimizes both color and depth losses against generated priors, ensuring geometric correctness and view consistency [S1, unofficial]. Unlike [Reference-guided Controllable Inpainting of NeRFs](13952-reference-guided-controllable-inpainting-of-nerfs.md) which may rely on reference images or specific generative models, NeRF-In uses general-purpose inpainting and depth completion tools to create guidance fields [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A pre-trained NeRF model $F_\Theta$; a user-chosen camera position $o_u$; a rendered view $I_u = F_{\Theta_{image}}(o_u)$; a user-drawn binary mask $M_u$ on $I_u$ where $M_u=1$ for pixels outside the masked region (background/valid) and $M_u=0$ inside (object to remove) [S1, unofficial].
*   **Output:** Updated NeRF parameters $\tilde{\Theta}$ [S1, unofficial].

**Data Structures:**
*   **Camera Trajectory:** A set of $K$ camera positions $O = \{o_s \mid s = 1 \dots K\}$ sampled along a pre-set trajectory (e.g., LLFF test-set trajectory) [S1, unofficial].
*   **Masks:** Transferred masks $M = \{M_s \mid s = 1 \dots K\}$, where $M_s$ covers the same object as $M_u$ in view $s$ [S1, unofficial].
*   **Guidance Images:** Guiding color images $I^G = \{I_s^G \mid s = 1 \dots K\}$ and guiding depth images $D^G = \{D_s^G \mid s = 1 \dots K\}$ [S1, unofficial].
*   **Rendered Data:** Coarse depth $D_c(o_s)$ and fine depth $D_f(o_s)$ rendered from $F_\Theta$ [S1, unofficial].

**Numbered Steps:**

1.  **Initialization:** Initialize NeRF parameters $\Theta$ (using a pre-trained model for the main method) [S1, unofficial].
2.  **Sampling:** Sample $K$ camera positions $O$ along a pre-set trajectory [S1, unofficial].
3.  **Rendering:** Render RGB images $I_s$ and depth images $D_s$ using $F_\Theta$ for all $o_s \in O$ [S1, unofficial].
4.  **Mask Transfer:** Transfer the user-drawn mask $M_u$ to the sampled views to generate $M = \{M_s\}$ using a video object segmentation method (e.g., STCN) [S1, unofficial].
5.  **Guidance Generation:**
    *   Generate guiding color images $I_s^G = \rho(I_s, M_s)$ using an image inpainting method $\rho$ (e.g., MST inpainting network) [S1, unofficial].
    *   Generate guiding depth images $D_s^G = \tau(D_s, M_s, I_s^G)$ using a depth completion method $\tau$ (e.g., Fast Bilateral Solver) [S1, unofficial].
6.  **View Set Definition:** Define the set of all views $O_{all}$ and outside views $O_{out}$. In the main framework, set $O_{all} = \{o_u\}$ (the user-chosen view) and $O_{out} = O$ (all other sampled views) [S1, unofficial].
7.  **Optimization:** Optimize $\Theta$ to obtain $\tilde{\Theta}$ by minimizing the total loss $L_{color}(\Theta) + L_{depth}(\Theta)$ using the Adam optimizer for 50,000 steps [S1, unofficial].

**Formulas:**

The expected color $\hat{C}(r)$ of a camera ray $r(t) = o + td$ is computed via volume rendering integral [S1, unofficial]:
$$
\hat{C}(r) = \sum_{i=1}^{N} T(t_i)(1 - \exp(-\sigma(t_i)\delta_i))c(t_i)
$$
where $T(t_i) = \exp(-\sum_{j=1}^{i-1} \sigma(t_j)\delta_j)$, $N$ is the number of quadrature points, $\delta_i = t_{i+1} - t_i$, and $c(t_i), \sigma(t_i)$ are color and density at point $t_i$ produced by $F_\Theta$ [S1, unofficial].

The rendered depth $D_f(o_s)$ is computed by accumulating density $\sigma$ from ray batches during volume rendering [S1, unofficial].

The total color-guiding loss $L_{color}(\Theta)$ is the sum of the all-view color loss $L_{all\_color}(\Theta)$ and the outside-view color loss $L_{out\_color}(\Theta)$ [S1, unofficial]:
$$
L_{color}(\Theta) = L_{all\_color}(\Theta) + L_{out\_color}(\Theta)
$$
where [S1, unofficial]:
$$
L_{all\_color}(\Theta) = \sum_{o \in O_{all}} \| F_{\Theta_{image}}(o) - I_o^G \|_2^2
$$
$$
L_{out\_color}(\Theta) = \sum_{o \in O_{out}} \| (F_{\Theta_{image}}(o) - I_o^G) \odot M_o \|_2^2
$$
Note: The source defines $L_{out\_color}$ with mask $M_o$ but states $O_{out}=O$ and $O_{all}=\{o_u\}$. The mask $M_o$ is applied to the difference [S1, unofficial].

The depth-guiding loss $L_{depth}(\Theta)$ measures the L2 distance between rendered fine/coarse depth images and guiding depth [S1, unofficial]:
$$
L_{depth}(\Theta) = \sum_{o_s \in O} \left( \| D_f(o_s) - D_G(o_s) \|_2^2 + \| D_c(o_s) - D_G(o_s) \|_2^2 \right)
$$
where $D_f(o_s)$ is the fine volume predicted depth, $D_c(o_s)$ is the coarse volume predicted depth, and $D_G(o_s)$ is the guiding depth [S1, unofficial].

**Parameters:**
*   $K$: Number of sampled camera positions/views [S1, unofficial].
*   Batch size: 4,096 [S1, unofficial].
*   Sample points in fine model: 128 [S1, unofficial].
*   Sample points in coarse model: 64 [S1, unofficial].
*   Optimizer: Adam [S1, unofficial].
*   Training steps for inpainting: 50,000 [S1, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn.functional as F

def volume_render_color(ray_origins, ray_directions, sigma, color, near, far, N_samples):
    """
    Computes the expected color for a batch of rays using volume rendering.
    """
    t_vals = torch.linspace(0., 1., N_samples)
    t_vals = near + (far - near) * t_vals
    dz = (far - near) / N_samples
    
    # Alpha calculation
    alpha = 1.0 - torch.exp(-sigma * dz)
    transmittance = torch.cumprod(torch.cat([torch.ones_like(alpha[..., :1]), 1.0 - alpha + 1e-10], dim=-1), dim=-1)[..., :-1]
    
    weights = alpha * transmittance
    color_rendered = torch.sum(weights[..., None] * color, dim=-2)
    return color_rendered

def compute_depth(ray_origins, ray_directions, sigma, near, far, N_samples):
    """
    Computes depth by accumulating density along rays.
    """
    t_vals = torch.linspace(0., 1., N_samples)
    t_vals = near + (far - near) * t_vals
    dz = (far - near) / N_samples
    
    # Weighted average of t_vals using sigma as weight (simplified accumulation)
    # Note: Standard NeRF depth is weighted by alpha. This implementation follows the note "accumulation of sigma".
    # For precise implementation, one typically uses the alpha weights from color rendering.
    # Here we assume a standard depth computation consistent with the volume rendering weights.
    alpha = 1.0 - torch.exp(-sigma * dz)
    transmittance = torch.cumprod(torch.cat([torch.ones_like(alpha[..., :1]), 1.0 - alpha + 1e-10], dim=-1), dim=-1)[..., :-1]
    weights = alpha * transmittance
    depth = torch.sum(weights * t_vals, dim=-1) / (torch.sum(weights, dim=-1) + 1e-10)
    return depth

    # D_G = [depth_complete(D_s, M_s, I_G_s, method='BilateralSolver') for D_s, M_s, I_G_s in zip(D_s_list, M, I_G)]

    O_all = [user_view_idx]

        o_u = user_view_idx
```

**Edge Cases and Pitfalls:**
*   Optimizing only with masked MSE on transferred masks without explicit guidance causes the unwanted object to remain [S1, unofficial].
*   Using only depth-guiding loss introduces color noise outside the masked region and loses color information in flat regions [S1, unofficial].
*   Using multiple inpainted images as color guidance introduces visual inconsistency between views; the framework restricts color guidance to the user-chosen view to maintain consistency [S1, unofficial].
*   Artifacts in initial guidance materials (from $\rho$ or $\tau$) may propagate to the optimized NeRF [S1, unofficial].

## Subtopics

### Removing-NeRF
A method that removes objects by optimizing a NeRF using posed RGB-D images with 2D masks and 2D inpainted frames from LaMa [S2]. It employs confidence-based view selection to automatically exclude inconsistent views during optimization [S2].

## Operating characteristics
*   **Time Complexity:** Optimization takes approximately 5 hours for 50,000 steps on an Intel i7-7800X CPU and GTX-1080 GPU [S1, unofficial].
*   **Memory Complexity:** Depends on the NeRF resolution and batch size (4,096 rays) [S1, unofficial].
*   **Strengths:** No category-specific training data or procedure required; generates visually plausible results with correct geometry and view consistency [S1, unofficial].
*   **Limitations:** Relies on the quality of 2D inpainting and depth completion priors; may struggle if 2D inpainting results are perceptually inconsistent [S1, unofficial][S2].
*   **When to use:** When removing unwanted objects from a pre-trained NeRF without access to category-specific training data or ground-truth masks for the object [S1, unofficial].
*   **When not to use:** When high-quality 2D inpainting is not available or when the object removal requires complex semantic understanding beyond geometric inpainting [S1, unofficial].

## Background
NeRF-In was introduced by Hao-Kang Liu, I-Chao Shen, and Bing-Yu Chen in 2022 [S1, unofficial]. It is the first framework to enable free-form inpainting on NeRFs without category-specific data [S1, unofficial]. It builds on the volume rendering formulation of NeRF [23] and utilizes existing 2D inpainting (MST) and depth completion (Bilateral Solver) methods [S1, unofficial]. It is implemented in PyTorch and Python 3.9 [S1, unofficial].
