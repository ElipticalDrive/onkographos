# NeRF-GT Baseline Training Setup

Also called: NeRF-GT

## Overview
The NeRF-GT baseline establishes a reference training configuration for standard Neural Radiance Fields (NeRF) by utilizing ground-truth (GT) data, typically high-dynamic-range (HDR) renders or consistently exposed low-dynamic-range (LDR) views, to optimize the radiance field [S1]. It differs from its siblings by serving as the upper-bound reference for HDR synthesis methods, where the model is trained directly on HDR inputs rather than recovering HDR from multiple LDR exposures [S1]. Unlike the [NeRF Training Setup](13271-nerf-training-setup.md) which may use generic LDR inputs, NeRF-GT specifically addresses the challenges of high dynamic range by employing tone-mapping for loss computation [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Ground-truth HDR views (rendered via path-tracers like Blender Cycles) or consistently exposed LDR views [S1]. Camera poses and intrinsics are required for ray generation.
*   **Output:** Optimized NeRF network parameters (density $\sigma$ and color $\mathbf{c}$) and the resulting radiance field representation [S1].

**Data Structures:**
*   **Ray Batch:** A batch of 2,048 rays [S2, unofficial].
*   **Sample Points:** For each ray, 64 samples are taken in the coarse phase and 128 samples in the fine phase [S2, unofficial].
*   **Image Resolution:** 800 × 600 pixels [S2, unofficial].

**Training Steps:**
1.  **Ray Sampling:** Generate rays from the camera poses. Sample points along each ray using the coarse (64 samples) and fine (128 samples) strategies [S2, unofficial].
2.  **Volume Rendering:** Compute the predicted HDR color $\hat{\mathbf{C}}_{hdr}$ for each pixel by integrating the density and color predictions along the ray using differentiable volume rendering [S1][S2, unofficial].
3.  **Tone Mapping:** Apply a tone-mapping operator to the predicted HDR pixel values to convert them into LDR values $\hat{\mathbf{C}}_{ldr}$ [S1].
4.  **Ground Truth Preparation:** Apply the same tone-mapping operator to the ground-truth LDR views $\mathbf{C}_{gt\_ldr}$ (or tone-map the HDR ground truth if the input was HDR) to obtain the target LDR values [S1].
5.  **Loss Computation:** Calculate the photometric loss between the tone-mapped predictions and the tone-mapped ground truth [S1].
6.  **Optimization:** Update network parameters using gradient-based optimization (typically Adam) [S2, unofficial].

**Parameters:**
*   **Samples per Ray:** 64 (coarse), 128 (fine) [S2, unofficial].
*   **Batch Size:** 2,048 rays [S2, unofficial].
*   **Resolution:** 800 × 600 pixels [S2, unofficial].
*   **Iterations:** 200,000 solver steps [S2, unofficial].

**Pitfalls:**
*   Training directly on HDR views can fail to encode all scene areas well due to the high dynamic range, even when using tone-mapped colors for loss calculation [S1]. This is because the vast range of intensities can make it difficult for the network to fit all details simultaneously [S1].

## Subtopics

### NeRF Baseline
The NeRF Baseline refers to the standard implementation of the original NeRF method, serving as the primary comparison point for other radiance field optimization techniques. It utilizes the specific sampling and optimization parameters detailed in the original NeRF paper and the Fast Training of Neural Lumigraph Representations study [S2, unofficial]. It is chosen when a standard, non-HDR-specific, or non-generalizable NeRF implementation is required for benchmarking [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The training time is approximately 0.40 seconds per iteration [S2, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Rendering time is approximately 32 seconds per frame [S2, unofficial].
*   **Scaling:** The method scales with the number of samples per ray and the batch size. Larger batch sizes increase iteration time but may improve convergence stability [S2, unofficial].
*   **Strengths:** Provides a high-quality reference for HDR synthesis; straightforward implementation based on established NeRF principles [S1][S2, unofficial].
*   **Limitations:** High rendering latency (32 sec/frame); potential difficulty in encoding high-dynamic-range scenes uniformly [S1][S2, unofficial].
*   **When to use:** When establishing a baseline for HDR NeRF methods or when ground-truth HDR data is available and computational cost is secondary to accuracy [S1][S2, unofficial].
*   **When not:** When real-time rendering is required or when only LDR data with varying exposures is available without HDR ground truth [S1].

## Background
The NeRF-GT baseline originates from the work on HDR-NeRF, which introduced the concept of training NeRF models directly on HDR views to enable novel HDR view synthesis [S1]. The specific training parameters (64/128 samples, 200,000 steps) are derived from the evaluation setup described in the study on Fast Training of Neural Lumigraph Representations, which benchmarked various methods including the original NeRF implementation [S2, unofficial]. The method builds on the foundational NeRF architecture [S2, unofficial].
