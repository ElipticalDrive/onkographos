# Rip-NeRF

Also called: Rip-NeRF25k

## Overview
Rip-NeRF is a radiance field method that renders high-fidelity, anti-aliased images by combining cone casting with an anisotropic 3D Gaussian characterization [S1]. It utilizes Platonic Solid Projection and Ripmap Encoding to enable efficient anisotropic area-sampling of 3D space, distinguishing itself from sibling methods like Zip-NeRF by replacing inefficient multi-sampling with a compact, learnable feature grid structure [S1].

## How it works

### Inputs and Outputs
*   **Inputs:** A set of calibrated multi-view 2D images with known camera poses.
*   **Outputs:** Rendered RGB images for arbitrary viewpoints.
*   **Learnable Parameters:**
    *   Ripmap Encoding base level $R_{0,0}$ with shape $H=512, W=512, C=16$ [S1].
    *   MLP weights $\theta$ for the tiny network $F_\theta$ [S1].
    *   3D Gaussian parameters (mean $\boldsymbol{\mu}$ and covariance $\boldsymbol{\Sigma}$) for the conical frustums [S1].

### Data Structures

**Ripmap Encoding**
The Ripmap Encoding is a hierarchical feature grid. Only the base level $R_{0,0}$ is learnable. Higher levels are derived from the base level using average pooling to ensure consistency and compactness [S1].
*   **Base Level ($R_{0,0}$):** A 3D tensor of shape $(512, 512, 16)$ [S1].
*   **Derived Levels ($R_{i,j}$):** For levels $i, j$ in the $x$ and $y$ directions respectively, the value is computed as:
    $$
    R_{i,j} = \begin{cases} 
    \text{Avg}_{2\times1}(R_{i, j-1}) & \text{if } j \neq 0 \\
    \text{Avg}_{1\times2}(R_{i-1, j}) & \text{if } i \neq 0 \text{ and } j = 0 \\
    R_{0,0} & \text{otherwise}
    \end{cases}
    $$
    where $\text{Avg}_{2\times1}$ averages over two rows and one column, and $\text{Avg}_{1\times2}$ averages over one row and two columns [S1].

**Platonic Solid Projection**
The 3D space is projected onto the faces of a Platonic solid. The default configuration uses an icosahedron, which has 10 unparalleled faces [S1]. Let $\{P_i \mid i = 1, \dots, n\}$ be the set of planes corresponding to these faces, where $n=10$ [S1].

### Numbered Steps

1.  **Cone Casting and Frustum Division:** For each pixel, cast a cone into the scene and divide it into multiple conical frustums [S1].
2.  **3D Gaussian Characterization:** Characterize each conical frustum using an anisotropic 3D Gaussian parameterized by mean $\boldsymbol{\mu}$ and covariance $\boldsymbol{\Sigma}$ [S1].
3.  **Platonic Solid Projection:** Project the 3D Gaussian onto each face $P_i$ of the Platonic solid. This results in a projected 2D Gaussian with mean $\boldsymbol{\mu}_{\text{proj}}$ and covariance $\boldsymbol{\Sigma}_{\text{proj}}$ on plane $P_i$ [S1].
    *   The projection is defined by a projection matrix $M_i \in \mathbb{R}^{3 \times 2}$ mapping the 3D world coordinate system to the 2D coordinate system of plane $P_i$ [S1].
4.  **Ripmap Querying:** For each projected 2D Gaussian on plane $P_i$, query a feature vector $\mathbf{f}_i$ from the Ripmap Encoding of that plane [S1].
    *   The position $(p_x, p_y)$ and level $(l_x, l_y)$ used for interpolation are determined by $\boldsymbol{\mu}_{\text{proj}}$ and $\boldsymbol{\Sigma}_{\text{proj}}$ respectively [S1].
    *   The level calculation involves a hyper-parameter $w=2.0$, which adjusts how much probability mass of the Gaussian footprint is covered [S1].
    *   The feature vector $\mathbf{f}_i$ is obtained via tetra-linear interpolation on the Ripmap Encoding [S1].
5.  **Feature Aggregation:** Concatenate all feature vectors $\{\mathbf{f}_i \mid i = 1, \dots, n\}$ from the $n$ Platonic solid faces to form the final feature vector $\mathbf{f}$ of the 3D Gaussian [S1].
6.  **View Direction Encoding:** Encode the viewing direction $\mathbf{d} \in S^2$ [S1].
7.  **MLP Decoding:** Concatenate the aggregated feature vector $\mathbf{f}$ and the encoded view direction $\mathbf{d}$, then pass them through a tiny MLP $F_\theta$ to estimate the color $\mathbf{c}$ and density $\sigma$ of the conical frustum [S1].
8.  **Volume Rendering:** Render the pixel color using standard volume rendering with the estimated $\mathbf{c}$ and $\sigma$ [S1].
9.  **Optimization:** Optimize the system end-to-end using a photometric loss between rendered and observed images. The loss is scaled by the area of the pixel footprint on the image plane (area loss $L_{\text{area}}$) [S1].

### Parameters
*   **Ripmap Base Level Shape:** $H=512, W=512, C=16$ [S1].
*   **Platonic Solid:** Icosahedron (10 faces) [S1].
*   **Hyper-parameter $w$:** 2.0 (adjusts Gaussian footprint coverage) [S1].
*   **Optimizer:** AdamW [S1].
*   **Iterations:** 120k (standard Rip-NeRF), 25k (Rip-NeRF25k variant) [S1].
*   **Weight Decay:** $1 \times 10^{-5}$ [S1].
*   **Initial Learning Rate:** $2 \times 10^{-3}$, modulated by MultiStepLR [S1].
*   **Ripmap Learning Rate Scale:** 10.0 times the base learning rate [S1].

### Edge Cases and Pitfalls
*   **Empty Space:** Use a binary occupancy grid (e.g., from NerfAcc) to skip samples in empty areas [S1].
*   **Precision:** The Ripmap Encoding uses average pooling to derive higher levels, ensuring consistency but potentially losing high-frequency details if the base level is insufficient [S1].
*   **Boundary Conditions:** The projection of 3D Gaussians onto Platonic solid faces must handle cases where the Gaussian is partially or fully outside the face boundaries [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Training Time:** 2.6 hours on NVIDIA A100-SXM4-80GB GPU for 120k iterations [S1].
*   **Training Time (Variant):** 32 minutes (11.76% of Zip-NeRF's 4.5h) for Rip-NeRF25k [S1].
*   **Model Size:** 160 MB [S1].
*   **GPU Memory:** 20 GB during training [S1].
*   **Rendering Speed:** 3 FPS [S1].

### Measured Performance
*   Evaluated on the multi-scale Blender dataset [S1].
*   Outperforms Zip-NeRF in training time, model size, and rendering speed [S1].
*   Zip-NeRF has slightly better SSIM, but Rip-NeRF has comparable PSNR and LPIPS [S1].
*   Zip-NeRF requires ~80 GB GPU memory, making it unfeasible for consumer GPUs like RTX 4090, whereas Rip-NeRF uses 20 GB [S1].

### Strengths and Limitations
*   **Strengths:** Efficient anisotropic area-sampling, compact representation, fast training and rendering, low memory footprint [S1].
*   **Limitations:** Designed for bounded objects; Zip-NeRF is designed for unbounded scenes and may perform better in that context [S1].

### When to Use
*   Use Rip-NeRF when high-fidelity anti-aliased rendering is required with limited computational resources (memory, time) [S1].
*   Use Rip-NeRF25k when faster reconstruction is prioritized over marginal quality gains [S1].

## Background

### Origin
Rip-NeRF was introduced in the paper "Rip-NeRF: Anti-aliasing Radiance Fields with Ripmap-Encoded Platonic Solids" [S1].

### History and Development
The method builds upon previous work in hybrid representations, such as Mip-NeRF [Barron et al. 2021], Tri-MipRF [Hu et al. 2023], and Zip-NeRF [Barron et al. 2023] [S1]. It addresses the inefficiency of multi-sampling mechanisms in Zip-NeRF by introducing Ripmap Encoding and Platonic Solid Projection for efficient anisotropic area-sampling [S1].

### Usage
Rip-NeRF is used for rendering high-fidelity, anti-aliased images from calibrated multi-view 2D images [S1].
