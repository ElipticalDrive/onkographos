# DP-based Configuration Selector

Also called: Multiple-Choice Knapsack Configuration Selection, Dynamic-programming-based configuration selection, MCK-based configuration selection, NeRFlex configuration selector

## Overview
The DP-based Configuration Selector is a method for selecting optimal neural radiance field (NeRF) configurations for multiple segmented objects under a strict memory constraint $H$ [S1]. It solves the configuration selection problem by formulating it as a Multiple-Choice Knapsack (MCK) problem, which is NP-hard [S1]. Unlike greedy approaches that rely on feasibility conditions often violated in multi-knob NeRF scenarios, this method uses dynamic programming to guarantee an optimal solution within the memory limit [S1]. It is specifically designed for mobile deployment where exceeding memory limits causes rendering failures or severe performance degradation [S1].

## How it works
### Inputs and Outputs
**Inputs:**
*   $I$: The set of segmented objects to be rendered.
*   $C_i$: The configuration space for object $i$, where each configuration $\theta_i$ is a pair $(g_i, p_i)$ representing geometry resolution and texture parameters [S1].
*   $f_{si}(\theta_i)$: A prediction model (profiler) estimating the memory size of object $i$'s NeRF representation given configuration $\theta_i$ [S1].
*   $f_{qi}(\theta_i)$: A prediction model estimating the rendering quality of object $i$ given configuration $\theta_i$ [S1].
*   $H$: The maximum allowed total memory size for all NeRF representations combined [S1].

**Outputs:**
*   `configs`: A list of pairs $(i, \theta_i^*)$ representing the selected optimal configuration for each object $i$ [S1].

### Data Structures
The algorithm maintains three primary data structures [S1]:
1.  `q`: A 1D array of size $H+1$. `q[j]` stores the maximum achievable total quality for a memory capacity of $j$ considering the objects processed so far. Initialized to 0.
2.  `choices`: A 2D array (or dictionary of dictionaries) where `choices[i][j]` stores the configuration $\theta$ selected for object $i$ when the current capacity is $j$. Initialized to null/empty.
3.  `configs`: An empty list to store the final backtracked results.

### Algorithm Steps
The algorithm proceeds in two phases: filling the dynamic programming table and backtracking to find the solution [S1].

1.  **Initialization**: For each object $i \in I$, initialize the minimum configuration $\theta_i^* \leftarrow \min(C_i) = (\min(g_i), \min(p_i))$. Initialize `q`, `choices`, and `configs` as described above [S1].

2.  **DP Table Filling**: Iterate through each object $i$ in the input set $I$. For each object, iterate through the memory capacity $j$ from $H$ down to 0. For each configuration $\theta \in C_i$:
    *   **Threshold Calculation**: Calculate the threshold size $r_i$ required to ensure that at least the minimum configuration for all *other* objects can fit in the remaining memory. This is computed as:
        $$ r_i = H - \sum_{h=1, h \neq i}^{m} \min_{\theta_t \in C_h} f_{sh}(\theta_t) $$
        where $m = |I|$ is the number of objects [S1].
    *   **Feasibility Check**: If the size of the current configuration $f_{si}(\theta)$ is greater than or equal to the threshold $r_i$ (i.e., $f_{si}(\theta) \ge r_i$), skip this configuration. This ensures that selecting $\theta$ leaves enough room for the minimal configurations of all other objects, satisfying the feasibility condition for the MCK problem [S1].
    *   **State Transition**: If the current capacity $j$ is sufficient for the configuration ($j \ge f_{si}(\theta)$), check if selecting this configuration improves the total quality. If:
        $$ q[j] < q[j - f_{si}(\theta)] + f_{qi}(\theta) $$
        then update the quality array and record the choice:
        $$ q[j] \leftarrow q[j - f_{si}(\theta)] + f_{qi}(\theta) $$
        $$ \text{choices}[i][j] \leftarrow \theta $$
        [S1].

3.  **Backtracking**: After processing all objects, iterate from the last object index $m = |I|-1$ down to 0. If `choices[m][H]` is not null, add the pair $(m, \text{choices}[m][H])$ to the `configs` list [S1].

4.  **Return**: Return `configs` [S1].

### Pseudocode
```python
def dp_configuration_selector(objects, config_spaces, size_model, quality_model, H):
    """
    Selects optimal NeRF configurations for multiple objects under memory constraint H.
    
    Args:
        objects: List of object identifiers.
        config_spaces: Dict mapping object_id to list of configuration pairs theta.
        size_model: Function f_si(theta) returning memory size.
        quality_model: Function f_qi(theta) returning rendering quality.
        H: Integer, maximum total memory size.
        
    Returns:
        configs: List of tuples (object_id, theta).
    """
    n = len(objects)
    # q[j] stores max quality for capacity j
    q = [0] * (H + 1)
    # choices[i][j] stores the theta selected for object i at capacity j
    # Using a dict of dicts to handle sparse or large H if necessary, 
    # but array is specified in source.
    choices = {} 
    
    # Pre-calculate minimum sizes for all objects to optimize threshold calculation
    min_sizes = {}
    for i in objects:
        min_theta = min(config_spaces[i], key=lambda t: size_model(i, t))
        min_sizes[i] = size_model(i, min_theta)

    # Phase 1: Fill DP Table
    for i in objects:
        # Calculate the sum of min sizes of all OTHER objects
        # This is the minimum memory required if we pick the smallest config for everyone else
        other_min_size_sum = sum(min_sizes[h] for h in objects if h != i)
        
        # Threshold r_i: The max size object i can take such that 
        # remaining capacity (H - f_si) >= sum of others' min sizes
        # i.e., f_si <= H - sum(others)
        threshold_r_i = H - other_min_size_sum
        
        for j in range(H, -1, -1):
            for theta in config_spaces[i]:
                size = size_model(i, theta)
                
                # Feasibility check: ensure other objects can still fit their min configs
                if size >= threshold_r_i:
                    continue
                
                # State transition
                if j >= size:
                    new_quality = q[j - size] + quality_model(i, theta)
                    if new_quality > q[j]:
                        q[j] = new_quality
                        # Store choice. Note: source uses choices[i][j]
                        # In a flat list of objects, we need an index or map.
                        # Assuming objects are indexed 0..n-1 for the array structure
                        # described in source Algorithm 1.
                        if i not in choices:
                            choices[i] = {}
                        choices[i][j] = theta

    # Phase 2: Backtrack
    configs = []
    # Iterate backwards through objects. 
    # Source Algorithm 1 iterates m from size(I)-1 down to 0.
    # This assumes 'objects' list order matches the DP processing order.
    for idx in range(n - 1, -1, -1):
        i = objects[idx]
        if i in choices and H in choices[i] and choices[i][H] is not None:
            configs.append((i, choices[i][H]))
            
    return configs
```

### Parameters
*   **Memory Constraint ($H$)**: The fixed memory size available on the device. Typical values are 240MB for iPhone 13 and 150MB for Pixel 4 [S1].
*   **Configuration Pair ($\theta_i = (g_i, p_i)$)**: Represents the geometry knob $g_i$ (grid resolution) and texture knob $p_i$ for object $i$'s NeRF [S1]. For baselines like Single NeRF and Block-NeRF, the recommended pair is $(128, 17)$ [S1].
*   **Configuration Space ($C_i$)**: The set of all possible $(g, p)$ pairs evaluated for object $i$ [S1].

### Edge Cases and Pitfalls
*   **Infeasibility**: The problem is NP-hard (MCK). Greedy algorithms often fail because they rely on a feasibility condition ($\sum_{\theta_j \in C_i} f_{si}(\theta_j) + \min_{h \neq i} \min_{\theta_t \in C_h} f_{sh}(\theta_t) \le H$) that is often not met in NeRFlex due to multiple control knobs [S1]. The DP approach handles this by explicitly checking the threshold $r_i$ [S1].
*   **Mobile Device Limits**: On iPhone 13, exceeding 240MB causes the local WebGL rendering engine to fail to load data. On Pixel 4, exceeding 150MB causes average FPS to drop by ~15, leading to stuttering [S1].
*   **Precision**: The source does not specify floating-point precision for the quality/size models. Implementers should ensure consistent units (e.g., bytes for size, SSIM/PSNR for quality) across $f_{si}$ and $f_{qi}$ [S1].

## Operating characteristics
*   **Time Complexity**: $O(nhc)$, where $n$ is the number of objects, $h$ is the memory constraint $H$, and $c$ is the size of the configuration space $C$ for an object. The threshold calculation takes $O(n)$ per object, and the DP process takes $O(hc)$ per object [S1].
*   **Space Complexity**: $O(H)$ for the `q` array and $O(nH)$ for the `choices` array in the worst case, though sparse storage may reduce this [S1].
*   **Strengths**: Guarantees an optimal solution for the MCK problem within the memory constraint, unlike greedy methods which may produce sub-optimal or infeasible solutions [S1].
*   **Limitations**: The pseudo-polynomial time complexity $O(nhc)$ can be prohibitive if $H$ is very large or the configuration space $C$ is dense [S1].
*   **When to Use**: When deploying multi-NeRF systems on mobile devices with strict memory budgets (e.g., <250MB) and multiple objects with varying configuration options [S1].
*   **When Not to Use**: When real-time configuration selection is required and $n$ or $H$ are too large for the $O(nhc)$ complexity, or when a single global NeRF is used instead of segmented objects [S1].

## Background
The DP-based Configuration Selector was introduced in the **NeRFlex** paper, "NeRFlex: Resource-aware Real-time High-quality Rendering of Complex Scenes on Mobile Devices" [S1]. It addresses the challenge of rendering complex scenes on mobile devices where memory is limited. Previous methods for baked NeRFs focused on single-object representation or compression algorithms [S1]. NeRFlex segments high-frequency detail objects and uses profiling models to predict size and quality for different configuration pairs (geometry and texture knobs). The problem is identified as a Multiple-Choice Knapsack (MCK) problem, which is NP-hard [S1]. While common MCK algorithms use greedy search, they require a feasibility condition that is often violated in NeRFlex due to the two control knobs ($g$ and $p$). Therefore, NeRFlex proposes a dynamic programming algorithm to solve the problem in pseudo-polynomial time [S1]. The method was evaluated on iPhone 13 and Pixel 4 devices [S1].
