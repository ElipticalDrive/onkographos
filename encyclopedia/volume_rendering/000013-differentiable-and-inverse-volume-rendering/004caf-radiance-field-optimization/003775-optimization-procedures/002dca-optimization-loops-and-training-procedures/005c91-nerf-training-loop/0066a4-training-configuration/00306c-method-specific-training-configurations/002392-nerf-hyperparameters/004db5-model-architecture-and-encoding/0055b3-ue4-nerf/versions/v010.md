# UE4-NeRF

Also called: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene, UE4-NeRF system

## Overview

UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale 3D scenes by integrating Neural Radiance Fields (NeRF) with the Unreal Engine 4 (UE4) rasterization pipeline [S1]. It addresses the computational limitations of traditional NeRFs and existing real-time variants (like Mobile-NeRF and Mega-NeRF) by partitioning large environments into sub-NeRFs, representing them via optimized textured polygonal meshes initialized from regular octahedra, and leveraging multi-resolution hash encoding for rapid training [S1]. Unlike its siblings which often rely on grid structures or suffer from slow convergence on tilted surfaces, UE4-NeRF supports various scene types (including mountainous terrain) and achieves real-time performance at high resolutions by deploying the neural network as an HLSL fragment shader within the engine [S1, 13622-binary-radiance-fields.md].

## How it works

### Inputs and Outputs
*   **Inputs:** A set of posed images (typically from drone-captured large-scale scenes, e.g., farmland, industrial parks) with GPS metadata; camera parameters.
*   **Outputs:** A textured polygonal mesh hierarchy (LOD levels) per block, ready for import into UE4; real-time rendered video stream at up to 4K resolution.

### Data Structures and Layout

**1. Scene Partitioning**
*   The large-scale scene is divided into multiple blocks (sub-NeRFs).
*   Each training block is slightly larger than the target scene area to create overlapping borders with neighbors for smooth transitions [S1].
*   A coarse model is trained for segmentation to capture terrain outlines; images are filtered using masks to exclude pixels outside the valid area [S1].

**2. Mesh Initialization**
*   A $128 \times 128 \times 128$ grid is initialized [S1].
*   Polygonal meshes are created by selecting the center point of each grid cell along with its six neighboring grids (front, back, left, right, top, bottom) [S1].
*   To handle tilted surfaces and improve convergence stability, the method uses a **regular octahedron** with 20 faces (8 exterior, 12 interior) instead of the mobile-optimized structures used in Mobile-NeRF [S1].
*   Vertex positions of these meshes are continuously optimized during training [S1].

**3. Encoding and Network Architecture**
The method employs Multi-Resolution Hash Encoding (from Instant-NGP) for acceleration [S1]. The neural network consists of an Encoder and a Decoder, implemented as MLPs [S1].

*   **Encoder Network ($E$):**
    *   Input: Hash-encoded positional information $\mathbf{p}_i$.
    *   Architecture: 4-layer MLP.
    *   Dimensions: $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$.
    *   Output: Opacity $\alpha_i$ and an 8-dimensional feature vector $\mathbf{M}_i$.
    *   Formula:
        $$ \mathbf{M}_i, \alpha_i = E(\text{hash}(\mathbf{p}_i); \theta_E) $$
    *   [S1]

*   **Decoder Network ($D$):**
    *   Input: Feature vector $\mathbf{M}_i$ and hash-encoded viewing direction $\mathbf{d}_i$.
    *   Architecture: 3-layer MLP.
    *   Dimensions: $17 \times 16$, $16 \times 16$, $16 \times 3$.
    *   Output: RGB color $\mathbf{c}_i$.
    *   Formula:
        $$ \mathbf{c}_i = D(\mathbf{M}_i, \text{hash}(\mathbf{d}_i); \theta_D) $$
    *   [S1]

**4. Texture Atlas**
*   A texture atlas stores the feature vectors and opacity information for the meshes [S1].
*   During training, the network outputs encode these texture maps [S1].

**5. Rendering Pipeline (UE4 Integration)**
*   The Decoder network is implemented as a High-Level Shading Language (HLSL) fragment shader in UE4 [S1].
*   The shader takes feature vectors (sampled from the texture atlas) as input and outputs colors [S1].
*   **LOD (Level of Detail):** Meshes with varying levels of detail are trained for different observation heights. Coarser meshes are used for higher observation heights to ensure real-time performance [S1].
*   **Coordinate System:** The UE4 coordinate system is used: X-axis points East, Y-axis points South, Z-axis points Up [S1].
*   **Scale:** A 100:1 scale conversion is applied (UE4 units to real-world units) based on GPS data [S1].

### Numbered Steps

1.  **Coordinate Transformation:** Apply UE4 coordinate system (X=East, Y=South, Z=Up) and 100:1 scale conversion to GPS-captured drone imagery [S1].
2.  **Block Partitioning:** Partition the large scene into blocks. Train a coarse segmentation model to define boundaries and filter images using masks [S1].
3.  **Mesh Initialization:** Initialize a $128 \times 128 \times 128$ grid. Create polygonal meshes using grid centers and neighbors, structured as regular octahedra (20 faces) [S1].
4.  **Network Setup:** Construct the Encoder (4-layer MLP, $32 \to 64 \to 64 \to 64 \to 8$) and Decoder (3-layer MLP, $17 \to 16 \to 16 \to 3$) [S1].
5.  **Training:**
    *   Use multi-resolution hash encoding for inputs [S1].
    *   Implement computationally intensive parts in CUDA [S1].
    *   Optimize vertex positions and network parameters simultaneously [S1].
    *   Train for 80,000 epochs per block on a single NVIDIA RTX 3090 GPU [S1].
6.  **Mesh Extraction:** Extract pre-rendered polygonal meshes at different LODs. The meshes are coarse but optimized; textures are encoded in the network outputs and stored in atlases [S1].
7.  **UE4 Deployment:** Import meshes and texture atlases into UE4. Deploy the HLSL fragment shader (Decoder) [S1].
8.  **Rendering:** Render using UE4's rasterization pipeline. The shader computes color from feature vectors [S1].

### Pseudocode

```python
# UE4-NeRF Training and Rendering Logic

def initialize_block(scene_data):
    """
    Partition scene and initialize mesh.
    scene_data: Dict containing images, GPS coordinates, camera poses.
    """
    # 1. Coordinate Transformation
    # UE4: X=East, Y=South, Z=Up. Scale 100:1.
    for img in scene_data.images:
        img.pos = convert_gps_to_ue4(img.gps, scale=100.0)
        img.pose = transform_camera_pose(img.pose)

    # 2. Block Partitioning
    # Create overlapping blocks to ensure smooth transitions
    blocks = partition_scene(scene_data.bounding_box, overlap=0.1)
    
    trained_models = {}
    for block_id, block in blocks.items():
        # Filter images for this block using coarse segmentation mask
        block_images = filter_images(block, scene_data.coarse_mask)
        
        # 3. Mesh Initialization
        # Initialize 128x128x128 grid
        grid = create_grid(128, 128, 128)
        
        # Create octahedron-based meshes from grid centers and neighbors
        # Regular octahedron: 20 faces (8 exterior, 12 interior)
        mesh = create_octahedron_mesh(grid)
        
        # 4. Network Definition
        # Encoder: 4-layer MLP (32->64->64->64->8)
        encoder = MLP(layers=[32, 64, 64, 64, 8])
        # Decoder: 3-layer MLP (17->16->16->3)
        # Note: Input dim 17 comes from 8 feature dims + 9 directional dims (hash encoded)
        decoder = MLP(layers=[17, 16, 16, 3])
        
        # 5. Training Loop
        # Use Multi-Resolution Hash Encoding (Instant-NGP style)
        hash_encoder = MultiResolutionHashEncoder()
        
        for epoch in range(80000):
            for image in block_images:
                # Sample rays through the mesh
                rays = sample_rays_through_mesh(mesh, image.camera)
                
                # Encode positions and directions
                pos_encoded = hash_encoder.encode(rays.positions)
                dir_encoded = hash_encoder.encode(rays.directions)
                
                # Forward pass through Encoder
                # Output: 8-dim feature vector M_i and opacity alpha_i
                features, opacities = encoder(pos_encoded)
                
                # Forward pass through Decoder
                # Concatenate features and direction encoding for decoder input
                # Decoder input size is 17 (8 features + 9 direction components)
                decoder_input = concatenate(features, dir_encoded[:9])
                colors = decoder(decoder_input)
                
                # Compute loss against ground truth image pixels
                loss = compute_rendering_loss(colors, opacities, rays, image.rgb)
                
                # Backpropagate to update encoder, decoder, and mesh vertices
                loss.backward()
                optimizer.step()
                
        # Extract trained model and mesh
        trained_models[block_id] = {
            'mesh': mesh,
            'encoder_weights': encoder.weights,
            'decoder_weights': decoder.weights,
            'hash_table': hash_encoder.table
        }
        
    return trained_models, blocks

def render_block_ue4(block_data, camera_pose):
    """
    Real-time rendering using UE4 HLSL shader.
    """
    # 1. Select LOD based on camera height
    lod_mesh = select_lod(block_data['mesh'], camera_pose.height)
    
    # 2. Update Texture Atlas
    # Encode features and opacities into texture maps
    atlas = encode_network_outputs(block_data['encoder_weights'], lod_mesh.vertices)
    
    # 3. UE4 Rasterization
    # The HLSL shader (Decoder) is called per pixel/fragment
    # Shader code concept:
    #   float4 feature = tex2D(featureAtlas, uv);
    #   float4 dir = hash_encode(camera_direction);
    #   float4 color = decoder(feature, dir);
    #   return color;
    
    rendered_frame = ue4_rasterize(lod_mesh, atlas, camera_pose, shader=block_data['decoder_weights'])
    
    return rendered_frame
```

### Parameters
*   **Grid Size:** $128 \times 128 \times 128$ [S1].
*   **Encoder Layers:** $[32, 64, 64, 64, 8]$ [S1].
*   **Decoder Layers:** $[17, 16, 16, 3]$ [S1].
*   **Training Iterations:** 80,000 epochs per block [S1].
*   **Hardware:** 1 NVIDIA RTX 3090 GPU [S1].
*   **Scale:** 100:1 (UE4 units to real-world units) [S1].
*   **Coordinate System:** X=East, Y=South, Z=Up [S1].

### Edge Cases and Pitfalls
*   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces. UE4-NeRF mitigates this by using regular octahedra (20 faces) instead of simpler structures [S1].
*   **Transparency:** Mobile-NeRF uses opacity binarization, failing on transparent/semi-transparent objects (water, glass). UE4-NeRF stores continuous opacity in texture maps, handling these materials better [S1].
*   **Semi-transparent Overhead:** Vegetation and other semi-transparent objects increase computational overhead, potentially reducing frame rates [S1].
*   **Pre-rendering Gaps:** Pre-rendering meshes cannot capture rays from all viewing angles perfectly, potentially resulting in gaps or holes in the final scene [S1].
*   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, which may cause evaluation metrics (PSNR/SSIM) to underestimate actual reconstruction quality [S1].
*   **Memory Constraints:** Rendering large scenes (square kilometers) incurs significant memory overhead. Increasing accuracy amplifies memory consumption [S1].
*   **Hardware Dependency:** Requires CUDA and NVIDIA GPUs [S1].

## Operating characteristics

**Time and Memory Complexity**
*   **Training Time:** UE4-NeRF trains approximately 1000× faster than Mobile-NeRF [S1].
    *   Per block: ~40 minutes on 1× RTX 3090 (80,000 epochs) [S1].
    *   Full scene ($n$ blocks): $1 \text{ hour} + (40 \text{ minutes} \times n/4)$ on 1× RTX 3090 [S1].
    *   Comparison: Mobile-NeRF takes 48 hours per block on 4× RTX 3090; Mega-NeRF takes 36 hours per block on 1× RTX 3090 [S1].
*   **Memory:** Rendering large scenes incurs significant memory overhead. Memory consumption increases with rendering accuracy [S1].
*   **Implementation:** Computationally intensive parts are implemented in CUDA to utilize GPU parallel computing [S1].

**Measured Performance**
*   **Real-time Rendering:** Achieves real-time performance at 4K resolution with up to 43 FPS on level-1 mesh hierarchy [S1].
*   **Resolution Scaling:** 50 FPS on full scene at 2K resolution; $\ge 70$ FPS on individual blocks at 2K resolution [S1].
*   **Quality:** Outperforms Mobile-NeRF and Mega-NeRF in rendering small objects (e.g., power lines) and dense textures. Avoids the blurriness seen in Mip-NeRF on natural scenes [S1].

**Strengths and Limitations**
*   **Strengths:**
    *   Real-time interactive rendering of large-scale scenes (square kilometers) [S1].
    *   Scene editing capabilities: Traditional 3D models (.obj, .fbx) can be imported; UE4 handles occlusion automatically, skipping neural shader computation for occluded regions, which can slightly improve frame rates [S1].
    *   Handles tilted surfaces and semi-transparent materials better than Mobile-NeRF [S1].
    *   Suitable for various scene types (mountainous terrain, industrial parks) unlike grid-limited Block-NeRF [S1].
*   **Limitations:**
    *   Requires NVIDIA GPUs and CUDA [S1].
    *   Pre-rendering artifacts (holes/gaps) due to limited viewing angle coverage in mesh extraction [S1].
    *   Evaluation metrics may be conservative due to exposure mismatches in UE4 [S1].

## Background

UE4-NeRF was introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" as a system combining NeRF with the Unreal Engine 4 rasterization pipeline [S1]. It was developed to address the limitations of previous NeRF methods in real-time rendering, specifically the high computational cost and inability to handle large-scale outdoor scenes with complex materials and editing requirements [S1]. The method builds upon techniques from Mobile-NeRF (mesh-based representation) and Instant-NGP (hash encoding) but diverges by using regular octahedra and integrating directly with UE4 for real-time interaction [S1]. It has been evaluated on datasets including drone-captured farmland, construction sites, and industrial parks, as well as the Mega-NeRF public dataset [S1].
