# Rip-NeRF

Also called: Rip-NeRF25k

## Overview
Rip-NeRF is a hybrid radiance field method that renders high-fidelity, anti-aliased images by combining cone casting with an explicit representation of anisotropic 3D Gaussians [S1]. It distinguishes itself from sibling methods like Zip-NeRF by using **Ripmap Encoding** and **Platonic Solid Projection** to efficiently featurize these Gaussians, avoiding the computational inefficiency of multi-sampling while maintaining compact storage [S1].

## How it works
Rip-NeRF adopts a hybrid representation, leveraging the efficiency of explicit structures (Gaussians) and the flexibility of implicit features (Ripmaps) [S1]. The method operates on calibrated multi-view images, optimizing the system end-to-end to minimize photometric loss [S1].

### Inputs and Outputs
*   **Inputs:** A set of calibrated multi-view 2D images with known camera intrinsics and extrinsics.
*   **Outputs:** Rendered RGB images and a learned scene representation consisting of Ripmap feature grids and Gaussian parameters.

### Data Structures

**1. Ripmap Encoding**
The Ripmap is a hierarchical feature grid used for area sampling. It consists of a base level and derived lower levels.
*   **Base Level ($R_{0,0}$):** A learnable tensor with shape $H \times W \times C$.
    *   Typical values: $H=512, W=512, C=16$ [S1].
*   **Derived Levels ($R_{i,j}$):** Generated from the base level using average pooling to ensure consistency and compactness. Only $R_{0,0}$ is learnable [S1].
    *   The level at indices $(i, j)$ is computed as:
        $$
        R_{i,j} = \begin{cases} 
        \text{Avg}_{2\times1}(R_{i, j-1}) & \text{if } j \neq 0 \\
        \text{Avg}_{1\times2}(R_{i-1, j}) & \text{if } i \neq 0 \text{ and } j = 0 \\
        R_{0,0} & \text{otherwise}
        \end{cases}
        $$
        where $\text{Avg}_{2\times1}$ averages over the vertical dimension and $\text{Avg}_{1\times2}$ averages over the horizontal dimension [S1].

**2. Anisotropic 3D Gaussian**
Each conical frustum is characterized by a 3D Gaussian defined by its mean $\boldsymbol{\mu}$ and covariance $\boldsymbol{\Sigma}$ [S1].

**3. Platonic Solid Projection**
The 3D Gaussian is projected onto the faces of a Platonic solid to form 2D Gaussians.
*   **Default Configuration:** Icosahedron, which has $n=10$ unparalleled faces [S1].
*   Let $\{P_i \mid i = 1, \dots, n\}$ be the set of planes corresponding to the faces.
*   For each face $P_i$, a projection matrix $M_i \in \mathbb{R}^{3 \times 2}$ maps the 3D world coordinate system to the 2D coordinate system of plane $P_i$ [S1].
*   The projected 2D Gaussian on plane $P_i$ has mean $\boldsymbol{\mu}_{proj}$ and covariance $\boldsymbol{\Sigma}_{proj}$, derived from $\boldsymbol{\mu}$, $\boldsymbol{\Sigma}$, and $M_i$ [S1].

**4. Tiny MLP ($F_\theta$)**
A small Multi-Layer Perceptron takes the aggregated feature vector and encoded view direction to predict density $\sigma$ and color $\mathbf{c}$ [S1].

### Numbered Steps

1.  **Cone Casting and Frustum Division:**
    For each pixel, cast a cone into the scene. Divide this cone into multiple conical frustums along the ray depth [S1]. This avoids discrete point-based sampling of continuous signals [S1].

2.  **Gaussian Characterization:**
    Characterize each conical frustum as an anisotropic 3D Gaussian parameterized by mean $\boldsymbol{\mu}$ and covariance $\boldsymbol{\Sigma}$ [S1].

3.  **Platonic Solid Projection:**
    For each of the $n$ faces $P_i$ of the Platonic solid:
    a. Project the 3D Gaussian onto the plane $P_i$ using the projection matrix $M_i$ to obtain the 2D Gaussian parameters $(\boldsymbol{\mu}_{proj}, \boldsymbol{\Sigma}_{proj})$ [S1].

4.  **Ripmap Querying:**
    For each projected 2D Gaussian on plane $P_i$:
    a. Determine the position $(p_x, p_y)$ and level $(l_x, l_y)$ in the Ripmap based on $\boldsymbol{\mu}_{proj}$ and $\boldsymbol{\Sigma}_{proj}$ [S1].
    b. Query the feature vector $\mathbf{f}_i$ from the Ripmap Encoding using tetra-linear interpolation [S1].
    c. The interpolation uses a hyper-parameter $w$ (default $w=2.0$) to adjust the probability mass coverage of the Gaussian footprint [S1].

5.  **Feature Aggregation:**
    Concatenate all feature vectors $\{\mathbf{f}_i \mid i = 1, \dots, n\}$ from the $n$ Platonic solid faces to form the final feature vector $\mathbf{f}$ [S1].

6.  **Radiance Prediction:**
    Concatenate the aggregated feature vector $\mathbf{f}$ with the encoded view direction $\mathbf{d}$ (processed via the parent's positional encoding) [S1, Parent]. Pass this combined vector through the tiny MLP $F_\theta$ to estimate the density $\sigma$ and color $\mathbf{c}$ for the frustum [S1].

7.  **Volume Rendering:**
    Render the pixel color by performing volume rendering using the estimated $\sigma$ and $\mathbf{c}$ values across the frustums [S1].

8.  **Optimization:**
    Optimize the system end-to-end using a photometric loss between the rendered image and the observed image [S1].
    a. **Area Loss:** Scale the photometric loss for each pixel by the area of its footprint on the image plane ($L_{area}$) [S1].
    b. **Optimizer:** Use AdamW [S1].
    c. **Learning Rate:** Initial learning rate $2 \times 10^{-3}$, modulated by MultiStepLR. The learning rate for the Ripmap encoding is scaled up by $10.0$ times [S1].
    d. **Weight Decay:** $1 \times 10^{-5}$ [S1].

### Pseudocode

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class RipNeRF:
    def __init__(self, num_faces=10, ripmap_H=512, ripmap_W=512, ripmap_C=16, w=2.0):
        """
        Initialize Rip-NeRF.
        
        Args:
            num_faces: Number of faces on the Platonic solid (default 10 for Icosahedron).
            ripmap_H, ripmap_W, ripmap_C: Dimensions of the base Ripmap level R_0,0.
            w: Hyper-parameter for Gaussian footprint coverage adjustment.
        """
        self.num_faces = num_faces
        self.w = w
        
        # Base level is learnable; lower levels are derived via pooling
        self.base_ripmap = nn.Parameter(torch.randn(1, ripmap_C, ripmap_H, ripmap_W) * 0.01)
        
        # Tiny MLP for density and color prediction
        # Input dim: (num_faces * ripmap_C) + encoded_direction_dim
        # Output dim: 4 (density + RGB)
        self.mlp = nn.Sequential(
            nn.Linear((num_faces * ripmap_C) + 256, 128), # 256 is placeholder for encoded dir dim
            nn.ReLU(),
            nn.Linear(128, 64),
            nn.ReLU(),
            nn.Linear(64, 4) # sigma, r, g, b
        )
        
        # Projection matrices for Platonic solid faces (precomputed based on geometry)
        # M_i maps 3D world to 2D plane i
        self.projection_matrices = self._get_icosahedron_projection_matrices()

    def _get_icosahedron_projection_matrices(self):
        # Placeholder for actual geometric derivation of 10 projection matrices
        # Returns list of 10 tensors of shape (3, 2)
        return [torch.eye(2, 3) for _ in range(self.num_faces)]

    def _get_derived_ripmap(self, levels_x, levels_y):
        """
        Retrieve feature from Ripmap at specific level (levels_x, levels_y).
        Levels are derived from base level via average pooling.
        """
        # In practice, this would involve efficient CUDA kernels or pre-computed pooling
        # Here we simulate the logic: R_i,j is derived from R_0,0
        # For implementation, one might store the base and apply pooling on the fly or cache
        current_level = self.base_ripmap
        for _ in range(levels_x):
            current_level = F.avg_pool2d(current_level, kernel_size=(1, 2)) # Avg 1x2
        for _ in range(levels_y):
            current_level = F.avg_pool2d(current_level, kernel_size=(2, 1)) # Avg 2x1
        return current_level

    def query_ripmap(self, mu_proj, sigma_proj, plane_index):
        """
        Query feature vector f_i from Ripmap for a 2D Gaussian on plane i.
        
        Args:
            mu_proj: Mean of projected 2D Gaussian (x, y).
            sigma_proj: Covariance of projected 2D Gaussian (2x2 matrix).
            plane_index: Index of the Platonic solid face.
            
        Returns:
            f_i: Feature vector.
        """
        # Determine position (px, py) and level (lx, ly) from mu_proj and sigma_proj
        # The exact mapping depends on the specific coordinate system normalization
        # Typically, sigma determines the "level" (resolution) needed to cover the footprint
        px, py = mu_proj[0], mu_proj[1]
        
        # Calculate level based on covariance magnitude and w
        # Higher variance -> higher level (lower resolution)
        # Level calculation is specific to the paper's Eq. 2/3 logic
        # Assuming normalized coordinates [-1, 1] or [0, 1]
        var_x = sigma_proj[0, 0]
        var_y = sigma_proj[1, 1]
        
        # Example logic for level determination (simplified)
        # lx, ly are integers representing the mip level
        lx = int(torch.log2(torch.sqrt(var_x) * self.w).clamp(min=0))
        ly = int(torch.log2(torch.sqrt(var_y) * self.w).clamp(min=0))
        
        # Get the feature grid at this level
        feature_grid = self._get_derived_ripmap(lx, ly)
        
        # Tetra-linear interpolation (bilinear in 2D space for a single level)
        # Normalize px, py to [-1, 1] for grid_sample if necessary
        # Assuming px, py are in [0, 1] relative to the plane
        px_norm = 2 * px - 1
        py_norm = 2 * py - 1
        
        # grid_sample expects input of shape (N, C, H, W) and coordinates (N, H_out, W_out, 2)
        # Coordinates should be in [-1, 1]
        coords = torch.tensor([[[px_norm, py_norm]]]).to(feature_grid.device)
        
        # Perform bilinear interpolation
        # feature_grid shape: (1, C, H, W)
        f_i = F.grid_sample(feature_grid, coords, mode='bilinear', padding_mode='zeros')
        
        return f_i.squeeze() # Shape: (C,)

    def forward(self, frustums, view_directions, encoded_view_dirs):
        """
        Forward pass for a batch of frustums.
        
        Args:
            frustums: List of objects containing mu (3,) and sigma (3,3) for each frustum.
            view_directions: Raw view directions (3,) for each pixel/frustum.
            encoded_view_dirs: Sinusoidal positional encoding of view directions.
            
        Returns:
            densities: Tensor of shape (N,)
            colors: Tensor of shape (N, 3)
        """
        densities = []
        colors = []
        
        for frustum, view_dir, enc_view_dir in zip(frustums, view_directions, encoded_view_dirs):
            mu = frustum.mu # (3,)
            sigma = frustum.sigma # (3,3)
            
            features = []
            
            # Project onto each Platonic solid face
            for i in range(self.num_faces):
                M_i = self.projection_matrices[i] # (3, 2)
                
                # Project mean and covariance
                # mu_proj = M_i^T * mu (mapping 3D to 2D plane coords)
                # Sigma_proj = M_i^T * Sigma * M_i
                mu_proj = torch.matmul(M_i.T, mu) # (2,)
                sigma_proj = torch.matmul(torch.matmul(M_i.T, sigma), M_i) # (2,2)
                
                # Query Ripmap
                f_i = self.query_ripmap(mu_proj, sigma_proj, i)
                features.append(f_i)
            
            # Concatenate features from all faces
            f_aggregated = torch.cat(features, dim=0) # Shape: (num_faces * C,)
            
            # Concatenate with encoded view direction
            input_vec = torch.cat([f_aggregated, enc_view_dir], dim=0)
            
            # Predict density and color
            output = self.mlp(input_vec)
            sigma_val = output[0] # Density
            rgb = output[1:]      # Color
            
            densities.append(sigma_val)
            colors.append(rgb)
            
        return torch.stack(densities), torch.stack(colors)

    def compute_loss(self, rendered_images, target_images):
        """
        Compute area-aware photometric loss.
        
        Args:
            rendered_images: Rendered RGB images.
            target_images: Ground truth RGB images.
            
        Returns:
            loss: Scalar loss value.
        """
        # Calculate pixel footprint areas (simplified placeholder)
        # In practice, this requires calculating the cone footprint area on the image plane
        areas = self._compute_pixel_footprint_areas() 
        
        # Photometric loss (e.g., L1 or L2)
        pixel_loss = torch.abs(rendered_images - target_images)
        
        # Scale loss by area
        area_loss = pixel_loss * areas.unsqueeze(-1) # Broadcast to RGB channels
        
        return area_loss.mean()
```

### Parameters and Typical Values
*   **Ripmap Base Level ($R_{0,0}$):** $H=512, W=512, C=16$ [S1].
*   **Platonic Solid:** Icosahedron (10 faces) [S1].
*   **Hyper-parameter $w$:** $2.0$ (adjusts probability mass coverage) [S1].
*   **Optimizer:** AdamW [S1].
*   **Iterations:** $120,000$ (standard Rip-NeRF) or $25,000$ (Rip-NeRF25k variant) [S1].
*   **Weight Decay:** $1 \times 10^{-5}$ [S1].
*   **Initial Learning Rate:** $2 \times 10^{-3}$, modulated by MultiStepLR [S1].
*   **Ripmap Learning Rate:** Scaled up by $10.0$ times relative to the base rate [S1].

### Edge Cases and Pitfalls
*   **Empty Space:** To skip samples in empty areas, a binary occupancy grid (e.g., from NerfAcc) is used [S1].
*   **Precision:** The Ripmap levels are derived via average pooling, ensuring consistency but potentially losing high-frequency detail if the base level is too coarse. The choice of $w=2.0$ is critical for balancing coverage and precision [S1].
*   **Hardware:** The method relies on CUDA kernels for Platonic Solid Projection and Ripmap Encoding, and the `tiny-cuda-nn` library for the MLP [S1].

## Operating characteristics
*   **Training Time:** 2.6 hours on an NVIDIA A100-SXM4-80GB GPU for the standard variant (120k iterations) [S1]. The Rip-NeRF25k variant (25k iterations) takes 32 minutes (11.76% of Zip-NeRF's time) [S1].
*   **Model Size:** 160 MB [S1].
*   **GPU Memory:** 20 GB during training [S1].
*   **Rendering Speed:** 3 FPS [S1].
*   **Scaling:** Rip-NeRF scales better than Zip-NeRF in terms of training time and memory. Zip-NeRF requires ~80 GB GPU memory, which is unfeasible for consumer GPUs like the RTX 4090, whereas Rip-NeRF fits within 20 GB [S1].
*   **Strengths:** High-fidelity anti-aliased rendering, efficient anisotropic area-sampling, compact model size, and fast training compared to Zip-NeRF [S1].
*   **Limitations:** While it outperforms Zip-NeRF in speed and size, Zip-NeRF has slightly better SSIM metrics [S1]. Rip-NeRF is designed for bounded scenes; its performance on unbounded scenes may require further optimization [S1].

## Background
Rip-NeRF was introduced in the paper "Rip-NeRF: Anti-aliasing Radiance Fields with Ripmap-Encoded Platonic Solids" [S1]. It builds upon the hybrid representation concepts from Mip-NeRF [Barron et al. 2021] and Tri-MipRF [Hu et al. 2023], specifically addressing the inefficiency of multi-sampling mechanisms found in methods like Zip-NeRF [Barron et al. 2023] by introducing Ripmap Encoding and Platonic Solid Projection for efficient area sampling [S1].
