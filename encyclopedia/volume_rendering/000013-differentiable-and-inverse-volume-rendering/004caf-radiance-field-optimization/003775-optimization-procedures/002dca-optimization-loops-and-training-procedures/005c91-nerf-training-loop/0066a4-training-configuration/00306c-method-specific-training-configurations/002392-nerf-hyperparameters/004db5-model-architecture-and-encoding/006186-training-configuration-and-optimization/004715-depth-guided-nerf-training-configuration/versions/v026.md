# Depth-Guided NeRF Training Configuration

Also called: Depth-Guided NeRF Training

## Overview
This configuration defines the training protocol for Neural Radiance Fields (NeRF) that incorporate depth supervision to improve geometry reconstruction. It addresses the ambiguity of monocular depth estimation by integrating ground-truth depth priors into the optimization loop. It differs from standard NeRF training by adding specific architectural regularization (dropout) and a weighted depth loss term, distinguishing it from sibling methods like [CLIPNeRF Training Configuration](12073-clipnerf-training-configuration.md) which uses semantic guidance, or [Binary Radiance Fields](13622-binary-radiance-fields.md) which discretizes space.

## How it works
**Inputs:**
*   Camera poses and intrinsics.
*   RGB images.
*   Ground-truth depth maps (optional but required for the depth loss component).
*   Scene-specific depth bounds ($min\_depth$, $max\_depth$).

**Outputs:**
*   Trained NeRF model parameters (MLP weights, encoding tables).
*   Rendered RGB images and predicted depth maps.

**Data Structures:**
*   **NeRF Model:** Builds on the original NeRF architecture [S1].
    *   **Encoding:** Positional encoding of 3D position $\mathbf{x}$ and viewing direction $\mathbf{d}$.
    *   **MLP:** Fully connected layers with ReLU activations.
    *   **Dropout:** Dropout layers with probability $p=0.1$ are inserted after each of the first eight fully connected layers [S1].
*   **Depth Thresholding:** A threshold $\tau$ is computed to evaluate depth uncertainty.
    $$ \tau = (max\_depth - min\_depth) \cdot 0.0001 $$
    Where $max\_depth$ and $min\_depth$ are scene-specific bounds (e.g., 10 and 0.001 for ScanNet) [S1].

**Training Steps:**
1.  **Initialize** the NeRF model with random weights.
2.  **Sample Rays:** For each training iteration, sample rays through the scene.
3.  **Forward Pass:**
    *   Encode sampled points $\mathbf{x}$ and directions $\mathbf{d}$.
    *   Pass through the MLP (with dropout applied to the first 8 layers) to predict density $\sigma$ and color $\mathbf{c}$.
    *   Render RGB color $\hat{C}$ and expected depth $\hat{d}$ using volume rendering equations.
4.  **Compute Loss:**
    *   Calculate RGB reconstruction loss (typically MSE).
    *   Calculate Depth Loss $L_{depth}$ between predicted depth $\hat{d}$ and ground truth $d$. The specific formulation (e.g., Earth Mover’s Distance or L1/L2) depends on the implementation, but the weight $\lambda$ is applied here [S1].
    *   Total Loss: $L = L_{rgb} + \lambda L_{depth} + \gamma L_{uncertainty}$ (if uncertainty modeling is active) [S1].
5.  **Update Parameters:**
    *   Compute gradients.
    *   Update weights using the Adam optimizer.
    *   Apply weight decay.
6.  **Schedule:** Reduce the learning rate after 80% of total steps.
7.  **Repeat** for 500,000 steps.

**Parameters:**
*   **Optimizer:** Adam [S1].
*   **Learning Rate (LR):** $5 \times 10^{-4}$ initially [S1].
*   **LR Schedule:** Reduced to $5 \times 10^{-5}$ after 80% of steps [S1].
*   **Weight Decay:** $1 \times 10^{-6}$ [S1].
*   **Depth Loss Weight ($\lambda$):** $0.007$ for most scenes; $0.02$ for scene 710 [S1].
*   **Uncertainty Weight ($\gamma$):** $1$ [S1].
*   **Depth Scale LR:** $1 \times 10^{-7}$ [S1].
*   **Total Steps:** 500,000 [S1].

**Pseudocode:**
```python
def train_depth_guided_nerf(model, dataloader, config):
    # Initialize optimizer with specific LR for depth scale if applicable
    optimizer = Adam(
        params=model.parameters(),
        lr=config.initial_lr,  # 5e-4
        weight_decay=config.weight_decay  # 1e-6
    )
    
    # Specific LR handling for depth scale parameter if it is a separate learnable parameter
    # Note: The source specifies a distinct LR for 'depth scale', implying it might be 
    # a separate parameter group or handled via a custom scheduler.
    # Assuming standard Adam for main weights and specific handling for scale.
    
    total_steps = config.total_steps  # 500,000
    step_threshold = int(total_steps * 0.8)
    
    for step, batch in enumerate(dataloader):
        images = batch['rgb']
        depth_gt = batch['depth']
        poses = batch['poses']
        
        # Compute scene-specific depth bounds for thresholding
        min_depth = batch['min_depth']
        max_depth = batch['max_depth']
        tau = (max_depth - min_depth) * 0.0001
        
        # Forward pass
        # model returns rendered RGB and predicted depth
        rendered_rgb, predicted_depth = model(poses)
        
        # Compute losses
        # L_rgb is typically MSE between rendered_rgb and images
        loss_rgb = mse_loss(rendered_rgb, images)
        
        # L_depth is weighted by lambda
        # The exact depth loss function (e.g., EMD, L1) is implementation-dependent,
        # but the weight lambda is fixed per source [S1].
        loss_depth = compute_depth_loss(predicted_depth, depth_gt)
        lambda_val = config.lambda_710 if batch['scene_id'] == 710 else config.lambda_default
        weighted_depth_loss = lambda_val * loss_depth
        
        # Uncertainty loss (if applicable)
        # gamma is 1 [S1]
        loss_uncertainty = compute_uncertainty_loss(predicted_depth, depth_gt, tau)
        weighted_uncertainty_loss = config.gamma * loss_uncertainty
        
        total_loss = loss_rgb + weighted_depth_loss + weighted_uncertainty_loss
        
        # Backward pass
        optimizer.zero_grad()
        total_loss.backward()
        optimizer.step()
        
        # Learning rate schedule
        if step == step_threshold:
            for param_group in optimizer.param_groups:
                param_group['lr'] = config.reduced_lr  # 5e-5
                
        if step >= total_steps:
            break
```

## Subtopics

### DS-NeRF Depth Loss Integration
This variant involves integrating the depth loss implementation from the official DS-NeRF codebase into the training pipeline. It requires re-training on specific datasets (LLFF, DTU) using released configuration files, as original publication results for LLFF used different train/test splits and DTU results could not be reproduced due to missing config files [S2].

## Operating characteristics
*   **Time Complexity:** Training requires 500,000 steps [S1]. The addition of depth loss computation adds negligible overhead compared to the forward/backward pass of the NeRF MLP.
*   **Memory Complexity:** Standard NeRF memory usage plus storage for ground-truth depth maps and intermediate depth predictions [S1].
*   **Strengths:** Improves geometric accuracy by leveraging depth priors; dropout prevents overfitting in the early layers [S1].
*   **Limitations:** Requires ground-truth depth maps; sensitive to the choice of $\lambda$ (scene-dependent tuning required for scene 710) [S1].
*   **When to use:** When high-fidelity geometry is required and depth sensors or stereo-derived depth maps are available.
*   **When not to use:** In purely monocular settings without depth priors or when computational resources are extremely limited (due to the long training duration).

## Background
This configuration originates from the work on Depth-Guided NeRF training, specifically utilizing Earth Mover’s Distance for depth supervision [S1]. It builds upon the original NeRF architecture [S1]. The specific hyperparameters (dropout, LR schedule, loss weights) were empirically determined for datasets like ScanNet and DTU [S1]. The integration of DS-NeRF loss highlights the community effort to standardize depth supervision techniques across different NeRF implementations [S2].
