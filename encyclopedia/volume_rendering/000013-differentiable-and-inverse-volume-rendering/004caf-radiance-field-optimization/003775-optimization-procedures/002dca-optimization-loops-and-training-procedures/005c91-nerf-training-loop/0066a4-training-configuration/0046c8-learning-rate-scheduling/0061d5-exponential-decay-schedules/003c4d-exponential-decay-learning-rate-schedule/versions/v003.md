# Exponential Decay Learning Rate Schedule

Also called: Adam with Exponential Decay, Exponential Decay Schedule, Exponential LR Schedule, ExponentialSchedule, Instant NGP LR Schedule, LambdaLR Exponential Decay, Training Optimizer and Schedule

## Overview
An exponentially decaying schedule that transitions a learning rate from an initial value to a final value using a base raised to a normalized step exponent [S1, unofficial]. It differs from [Linear Learning Rate Schedule](11850-linear-learning-rate-schedule.md) by applying multiplicative reductions rather than additive ones, and from [Step Decay Learning Rate Schedule](11852-step-decay-learning-rate-schedule.md) by providing a continuous curve rather than discrete uniform reductions at specific boundaries [S2, unofficial].

## How it works
**Inputs:** Initial learning rate ($lr$), decay factor ($\gamma$), step size ($step\_size$), current epoch or iteration ($epoch$ or $step$).
**Outputs:** Adjusted learning rate ($lr_{current}$).

**Data Structures:**
The implementation typically relies on a scheduler object (e.g., PyTorch's `LambdaLR`) or a manual update function. The state tracks the current epoch/step index.

**Steps:**
1. Initialize the scheduler with the initial learning rate $lr$, the decay function $\lambda(epoch) = \gamma^{(epoch / step\_size)}$, and the starting epoch index (typically $start\_epoch - 1$ to align with zero-based indexing or pre-increment logic) [S2, unofficial].
2. At each optimization step, compute the decay factor using the formula:
   $$ lr(epoch) = lr \times \gamma^{\left(\frac{epoch}{step\_size}\right)} $$
   where:
   - $lr$ is the initial learning rate [S2, unofficial].
   - $\gamma$ is the decay factor (e.g., 0.33) [S3].
   - $epoch$ is the current training step or epoch [S2, unofficial].
   - $step\_size$ is the interval at which the exponent increments (e.g., 10,000 steps) [S3].
3. Apply the computed $lr(epoch)$ to the optimizer's parameter groups [S3].

**Parameters:**
- Typical values for NeRF-style optimization include separate parameter groups: positions ($lr = 10^{-4}$), features ($lr = 5 \times 10^{-3}$), and MLP weights ($lr = 5 \times 10^{-5}$) [S3].
- Decay factor $\gamma = 0.33$ applied every $step\_size = 10,000$ steps after an initial warm-up or fixed iteration count (e.g., after 20,000 iterations) [S3].

**Pitfalls:**
- Redundant execution paths may occur if the condition `step >= self.num_steps` is checked multiple times within the update logic, leading to unnecessary computations or state inconsistencies [S1, unofficial].
- Precision issues may arise if $\gamma^{(epoch / step\_size)}$ underflows for very large epochs or if $\gamma$ is too close to 0.

**Pseudocode:**
```python
def compute_exponential_lr(initial_lr, gamma, step_size, current_step):
    """
    Compute the learning rate using exponential decay.
    
    Args:
        initial_lr (float): The starting learning rate.
        gamma (float): The decay factor (0 < gamma < 1).
        step_size (int): The number of steps between exponent increments.
        current_step (int): The current training step index.
        
    Returns:
        float: The adjusted learning rate.
    """
    # Calculate the exponent based on the step size
    exponent = current_step / step_size
    
    # Compute the decayed learning rate
    lr = initial_lr * (gamma ** exponent)
    
    return lr

# Example usage in a training loop
initial_lr = 1e-3
gamma = 0.33
step_size = 10000
current_step = 25000

lr = compute_exponential_lr(initial_lr, gamma, step_size, current_step)
# Apply lr to optimizer
```

## Subtopics

### [Step Decay Learning Rate Schedule](11852-step-decay-learning-rate-schedule.md)
A step-wise decay schedule that reduces a learning rate by a fixed multiplicative factor at regular intervals until a maximum number of decays is reached. It differs from the parent [Exponential Decay Learning Rate Schedule](9145-exponential-decay-learning-rate-schedule.md) by applying discrete, uniform reductions at specific step boundaries rather than a continuous exponential curve.

## Operating characteristics
- **Time Complexity:** $O(1)$ per step for computing the decay factor, assuming exponentiation is constant time.
- **Memory Complexity:** $O(1)$ additional memory for storing the scheduler state (current step).
- **Performance:** Effective for stabilizing training in later stages of NeRF optimization, particularly when combined with adaptive optimizers like Adam [S3]. The continuous decay helps fine-tune high-frequency details without the abrupt changes associated with step decay.
- **Strengths:** Smooth transition of learning rates; easy to implement; widely supported in deep learning frameworks.
- **Limitations:** Requires careful tuning of $\gamma$ and $step\_size$ to avoid premature convergence or insufficient decay. The continuous nature may not be ideal for tasks requiring sharp phase transitions.
- **When to use:** Suitable for long-running training sessions where gradual refinement is needed, such as in radiance field optimization [S3].
- **When not to use:** Not ideal for tasks requiring sudden changes in learning rate or when the optimal decay rate is unknown and requires frequent adjustment.

## Background
The exponential decay schedule is a classic learning rate scheduling technique used in optimization. In the context of volume rendering and NeRFs, it has been adopted from general deep learning practices and adapted for specific training regimes, such as those described in Instant NGP [S3]. The method is often implemented using framework-specific schedulers like PyTorch's `LambdaLR` [S2, unofficial].
