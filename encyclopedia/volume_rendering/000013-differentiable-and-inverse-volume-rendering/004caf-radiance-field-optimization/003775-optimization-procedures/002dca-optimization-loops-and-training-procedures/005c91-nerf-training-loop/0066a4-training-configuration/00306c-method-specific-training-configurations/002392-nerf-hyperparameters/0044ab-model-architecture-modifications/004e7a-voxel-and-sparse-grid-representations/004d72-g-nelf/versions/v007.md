# G-NeLF

Also called: Grid-based Neural Light Field, Memory- and Data-Efficient Hybrid Neural Light Field

## Overview
G-NeLF is a grid-based Neural Light Field (NeLF) method for novel view synthesis that predicts ray color directly without explicit point-wise volume density modeling [S1, unofficial]. It differs from standard NeRF approaches by replacing the implicit coordinate-to-color/density mapping with an explicit spatial-aware feature sequence derived from a hash-based multi-resolution tri-plane, decoded by an LSTM network [S1, unofficial]. Unlike previous NeLF methods that require training a NeRF model first to synthesize thousands of pseudo-views, G-NeLF trains end-to-end from original views only, achieving performance comparable to grid-based NeRFs with approximately one-tenth the parameters [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $M$ training images with known camera poses; a query ray $r$ defined by origin $\mathbf{o}$ and direction $\mathbf{d}$.
*   **Output:** The predicted color $\hat{C}(r) = (r, g, b)$ for the ray.

**Data Structures:**
1.  **Hash-based Multi-Resolution Tri-Plane:**
    *   Consists of three orthogonal planes: $\pi_{xy}, \pi_{xz}, \pi_{yz}$ [S1, unofficial].
    *   Each plane has $N$ resolution levels.
    *   **Hash Table:** Maps 2D integer coordinates to feature vectors. Size $T$ is $2^{14}$ for small/medium models and $2^{16}$ for large models [S1, unofficial].
    *   **Hash Index Calculation:** For a 2D coordinate $(x, y)$ at resolution level $i$ with grid size $s_i$, the hash index is calculated as:
        $$ \text{Index} = (x_a \oplus y_b) \pmod T $$
        where $\oplus$ is the XOR operation, and constants are $a=1, b=2,654,435,761$ [S1, unofficial].
    *   **Feature Vector Layout:** Each hash entry stores a feature vector. The feature dimension per level is 2 [S1, unofficial].
    *   **Point Feature Vector $F$:** For a 3D point, features are retrieved from all $N$ resolutions for all 3 planes. The total size is $3 \times N \times 2$ [S1, unofficial].

2.  **LSTM Decoder:**
    *   A 2-layer (small/medium) or 3-layer (large) LSTM network [S1, unofficial].
    *   Hidden size: 32 (small), 128 (medium/large) [S1, unofficial].

**Numbered Steps:**

1.  **Ray Emission and Sampling:**
    *   Emit rays based on the camera model for each pixel.
    *   Determine the ray's intersection with the scene bounding box.
    *   Sequentially sample $K$ points $\{\mathbf{x}_1, \dots, \mathbf{x}_K\}$ along the ray within the bounding box.
    *   Parameter $K$: 256 for 360° scenes, 128 for forward-facing scenes (using NDC coordinates) [S1, unofficial].

2.  **Feature Retrieval (Point Feature Acquirement):**
    *   For each sampled point $\mathbf{x}_k$:
        *   Project $\mathbf{x}_k$ onto the three orthogonal planes $\pi \in \{\pi_{xy}, \pi_{xz}, \pi_{yz}\}$ to get 2D coordinates $\mathbf{x}_\pi$ [S1, unofficial].
        *   For each resolution level $i \in \{1, \dots, N\}$ with grid size $s_i$:
            *   Compute integer grid coordinates for the four corners of the cell containing $\mathbf{x}_\pi$:
                $$ \text{idx}_{tl} = \lfloor \mathbf{x}_\pi / s_i \rfloor, \quad \text{idx}_{tr} = \lfloor \mathbf{x}_\pi / s_i \rfloor + [0, 1], \quad \text{idx}_{bl} = \lfloor \mathbf{x}_\pi / s_i \rfloor + [1, 0], \quad \text{idx}_{br} = \lfloor \mathbf{x}_\pi / s_i \rfloor + [1, 1] $$
                *(Note: The source algorithm uses integer division `//` and specific corner indexing)* [S1, unofficial].
            *   Retrieve features from the hash table using the hash index formula for each corner: $f_{tl}, f_{tr}, f_{bl}, f_{br}$ [S1, unofficial].
            *   Perform bilinear interpolation (weighted sum) of these four features based on the fractional distance of $\mathbf{x}_\pi$ within the cell to obtain $f_{\pi, i}$ [S1, unofficial].
        *   Concatenate features from all $N$ resolutions for plane $\pi$: $F_\pi = \text{Concat}(f_{\pi, 1}, \dots, f_{\pi, N})$ [S1, unofficial].
        *   Concatenate features from all three planes to form the point's feature vector: $F_k = \text{Concat}(F_{\pi_{xy}}, F_{\pi_{xz}}, F_{\pi_{yz}})$ [S1, unofficial].
    *   Assemble the feature vectors of all $K$ points into a ray feature sequence $\{F_1, \dots, F_K\}$ [S1, unofficial].

3.  **Direction Encoding:**
    *   Encode the 3D normalized ray direction vector $\mathbf{d}$ using Spherical Harmonics (SH) [S1, unofficial]. Let the encoded direction be $\mathbf{d}_{enc}$ [S1, unofficial].

4.  **LSTM Decoding:**
    *   Initialize LSTM hidden state $H_0$ and cell state $C_0$ to zero [G].
    *   For each point $k = 1$ to $K$:
        *   Concatenate the point's feature vector $F_k$ and the encoded direction $\mathbf{d}_{enc}$: $input_k = \text{Concat}(F_k, \mathbf{d}_{enc})$ [S1, unofficial].
        *   Update LSTM states:
            $$ H_k, C_k = \text{LSTM}(input_k, H_{k-1}, C_{k-1}) $$
        *   where $H_k$ and $C_k$ are the hidden and cell states at step $k$ [S1, unofficial].

5.  **Color Prediction:**
    *   Pass the final hidden state $H_K$ through a 2-layer Multi-Layer Perceptron (MLP) to predict the ray color:
        $$ \hat{C}(r) = \text{MLP}(H_K) $$
    *   Output $\hat{C}(r) = (r, g, b)$ [S1, unofficial].

**Pseudocode:**

```python
import math

def hash_index(x, y, T):
    """
    Calculate hash index for 2D coordinate (x, y) and table size T.
    Constants from source: a=1, b=2654435761
    """
    a = 1
    b = 2654435761
    return ((x * a) ^ (y * b)) % T

def get_point_features(x_3d, tri_plane_hash_tables, resolutions):
    """
    Retrieve feature vector for a 3D point x_3d from the hash-based tri-plane.
    
    Args:
        x_3d: tuple (x, y, z)
        tri_plane_hash_tables: dict mapping plane_name -> list of hash tables (one per resolution)
        resolutions: list of grid sizes s_i for each resolution level
        
    Returns:
        F: concatenated feature vector
    """
    F_planes = []
    
    # Define projections: xy, xz, yz
    planes = [
        ('xy', lambda p: (p[0], p[1])),
        ('xz', lambda p: (p[0], p[2])),
        ('yz', lambda p: (p[1], p[2]))
    ]
    
    for plane_name, project_func in planes:
        F_plane_resolutions = []
        # Get hash tables for this plane
        hash_tables = tri_plane_hash_tables[plane_name]
        
        for i, s_i in enumerate(resolutions):
            # Project 3D point to 2D
            x_2d = project_func(x_3d)
            x_coord, y_coord = x_2d
            
            # Calculate integer grid indices for corners
            # Using floor division for grid cell start
            grid_x = int(math.floor(x_coord / s_i))
            grid_y = int(math.floor(y_coord / s_i))
            
            # Fractional part for interpolation weights
            frac_x = (x_coord / s_i) - grid_x
            frac_y = (y_coord / s_i) - grid_y
            
            # Corner indices
            tl_idx = (grid_x, grid_y)
            tr_idx = (grid_x, grid_y + 1)
            bl_idx = (grid_x + 1, grid_y)
            br_idx = (grid_x + 1, grid_y + 1)
            
            # Retrieve features from hash table
            # Note: Source uses hash table lookup. We assume hash table returns feature vector.
            # If hash collision occurs, source implies dominant weight wins, 
            # but for implementation, we retrieve the stored value.
            f_tl = hash_tables[i][hash_index(tl_idx[0], tl_idx[1], len(hash_tables[i]))]
            f_tr = hash_tables[i][hash_index(tr_idx[0], tr_idx[1], len(hash_tables[i]))]
            f_bl = hash_tables[i][hash_index(bl_idx[0], bl_idx[1], len(hash_tables[i]))]
            f_br = hash_tables[i][hash_index(br_idx[0], br_idx[1], len(hash_tables[i]))]
            
            # Bilinear Interpolation
            # Weighted sum based on distance
            # w_tl = (1-frac_x)*(1-frac_y), etc.
            w_tl = (1 - frac_x) * (1 - frac_y)
            w_tr = (1 - frac_x) * frac_y
            w_bl = frac_x * (1 - frac_y)
            w_br = frac_x * frac_y
            
            f_interp = (w_tl * f_tl + w_tr * f_tr + w_bl * f_bl + w_br * f_br)
            F_plane_resolutions.append(f_interp)
            
        # Concatenate features from all resolutions for this plane
        F_plane = concatenate(F_plane_resolutions)
        F_planes.append(F_plane)
        
    # Concatenate features from all three planes
    F = concatenate(F_planes)
    return F

def spherical_harmonics_encode(direction_vector, degree=3):
    """
    Encode 3D normalized direction vector using Spherical Harmonics.
    Simplified placeholder for standard SH encoding.
    """
    # Standard SH encoding returns a fixed-size vector based on degree
    # For implementation, this is a standard math operation.
    # Returning a dummy vector for structure completeness.
    return [0.0] * 9 # Example size for degree 3

def gnelf_decode(ray_feature_sequence, direction_vector, lstm_model, mlp_model):
    """
    Decode ray color using LSTM and MLP.
    
    Args:
        ray_feature_sequence: list of feature vectors [F_1, ..., F_K]
        direction_vector: 3D normalized direction
        lstm_model: LSTM network
        mlp_model: 2-layer MLP
        
    Returns:
        color: (r, g, b)
    """
    # Encode direction
    d_enc = spherical_harmonics_encode(direction_vector)
    
    # Initialize LSTM states
    H_prev = [0.0] * lstm_model.hidden_size
    C_prev = [0.0] * lstm_model.hidden_size
    
    for F_k in ray_feature_sequence:
        # Concatenate point feature and direction
        input_vec = concatenate(F_k, d_enc)
        
        # LSTM step
        H_curr, C_curr = lstm_model.step(input_vec, H_prev, C_prev)
        
        H_prev = H_curr
        C_prev = C_curr
        
    # Final MLP prediction
    color = mlp_model.forward(H_prev)
    return color
```

**Parameters and Typical Values:**
*   **Hash Table Size ($T$):** $2^{14}$ (small/medium), $2^{16}$ (large) [S1, unofficial].
*   **Resolutions ($N$):** 8 levels (16 to 1024) for small/medium; 16 levels (16 to 2048) for large [S1, unofficial].
*   **Feature Dimension per Level:** 2 [S1, unofficial].
*   **LSTM Hidden Size:** 32 (small), 128 (medium/large) [S1, unofficial].
*   **LSTM Layers:** 2 (small/medium), 3 (large) [S1, unofficial].
*   **Ray Feature Sequence Length ($K$):** 256 (360° scenes), 128 (forward-facing scenes) [S1, unofficial].
*   **Model Size:** 0.95 MB (small), 1.41 MB (medium) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** At the highest resolution, approximately 100,000 3D positions map to a single hash entry [S1, unofficial]. This is not a failure mode but an adaptive mechanism: points far from the surface (low volume rendering weight) do not affect the color features, allowing the hash entry to adaptively capture appearance features of the dominant visible points [S1, unofficial].
*   **Sequential Order:** The method relies on the temporal order of ray propagation (near to far). Using MLP or Transformer (permutation-invariant) directly on the feature sequence loses this sequential information and performs worse [S1, unofficial].
*   **Training Data:** Requires only original views (e.g., 100 or fewer). Does not require synthesizing pseudo-views [S1, unofficial].

## Operating characteristics
*   **Model Size:** Extremely compact. 0.95 MB for small, 1.41 MB for medium [S1, unofficial]. This is approximately one-tenth the size of Instant-NGP (64.1 MB) and TensoRF (71.8 MB) [S1, unofficial].
*   **Performance:** Surpasses R2L by 0.04 dB PSNR on Realistic Synthetic 360° dataset with only 100 views and 0.95 MB size [S1, unofficial]. Surpasses VQRF by 0.79 dB PSNR at comparable model size (1.4 MB) [S1, unofficial]. Achieves comparable PSNR to Instant-NGP and TensoRF [S1, unofficial].
*   **Training Efficiency:** Trains end-to-end from original views only, avoiding the storage overhead (56+ GB) and computation of synthesizing 10K+ pseudo-views required by previous NeLF methods like R2L [S1, unofficial].
*   **Hardware:** Experiments conducted on a single RTX 3090 GPU using float16 [S1, unofficial].
*   **Limitations:** Does not explicitly model volume density, which may limit its applicability in scenarios requiring explicit physical properties (e.g., refraction, complex lighting interactions dependent on density) compared to NeRF [S1, unofficial].

## Background
G-NeLF was introduced in 2024 by authors of the paper "G-NeLF: Memory- and Data-Efficient Hybrid Neural Light Field for Novel View Synthesis" [S1, unofficial]. It addresses the limitations of previous Neural Light Field (NeLF) methods, which suffered from high training difficulty, large storage overhead, and lower rendering quality compared to NeRF [S1, unofficial]. By combining a hash-based multi-resolution tri-plane with an LSTM decoder, G-NeLF leverages spatial-aware feature sequences and the sequential nature of ray propagation to achieve high performance with minimal parameters [S1, unofficial].
