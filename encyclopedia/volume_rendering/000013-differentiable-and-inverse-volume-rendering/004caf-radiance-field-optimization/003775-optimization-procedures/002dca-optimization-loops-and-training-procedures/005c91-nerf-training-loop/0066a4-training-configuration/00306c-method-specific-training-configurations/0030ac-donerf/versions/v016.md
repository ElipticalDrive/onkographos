# DONeRF

Also called: DONeRF (Depth Oracle Neural Radiance Fields), DONeRF Training Configuration, DONeRF training setup, Depth Oracle Network

## Overview
DONeRF is a training configuration and architectural variant of NeRF that replaces the standard uniform raymarching with a two-network pipeline: a **depth oracle network** that predicts sample locations and a **shading network** that renders color and density at those locations [S3]. It solves the prohibitive computational cost of NeRF by reducing the number of samples per ray from hundreds to as few as 2–4, enabling real-time rendering on consumer GPUs [S3]. Unlike standard NeRF or acceleration methods like NSVF that rely on explicit spatial data structures (e.g., voxel octrees), DONeRF remains a compact MLP-based representation without additional memory overhead for acceleration structures [S3].

## How it works
DONeRF operates via a two-stage pipeline involving a depth oracle network and a shading network. The process is divided into five logical stages: ray unification, non-linear depth consideration, oracle classification, space warping, and shading accumulation [S3].

### Inputs and Outputs
*   **Inputs:** Training images (RGBD if available, otherwise RGB), camera poses, intrinsics, and view cell parameters (bounding box and orientation limits) [S3].
*   **Outputs:** Optimized weights for the depth oracle network and the shading network. The inference output is the rendered pixel color $\mathbf{c}$ and accumulated opacity $\alpha$ [S3].

### Data Structures
*   **View Cell:** A bounding box with a primary orientation and maximum viewing angle, defining the region of interest for a set of cameras [S3].
*   **Depth Oracle Network:** An 8-layer MLP with 256 hidden units per layer. Input is the concatenation of 3D position $\mathbf{x} \in \mathbb{R}^3$ and view direction $\mathbf{d} \in S^2$. No positional encoding is applied [S1].
*   **Shading Network:** An 8-layer MLP with 256 hidden units per layer. Input is $\mathbf{x}$ and $\mathbf{d}$. Positional encoding is applied to both [S1].

### Numbered Steps

1.  **Ray Unification:** Rays are transformed into a unified space relative to the view cell's primary orientation. This reduces input ambiguity for the oracle network [S3].
2.  **Oracle Input Construction:** The depth oracle network takes the unified position $\mathbf{x}$ and direction $\mathbf{d}$ as input. It does not use positional encoding [S1].
3.  **Depth Classification:** The oracle network outputs a classification vector representing discretized depth bins along the ray. It learns to classify depth ranges rather than predicting a single continuous depth value [S3].
4.  **Sample Selection:** Based on the oracle's classification, $N_s$ samples are selected along the ray. The number of selected samples $N_s$ is a hyperparameter (e.g., 2, 4, 8, 16) [S3].
5.  **Space Warping:** The selected sample positions are transformed (warped) towards the view cell. This non-linear transformation focuses sampling density on foreground regions and handles large depth ranges [S3].
6.  **Shading Network Forward Pass:** The warped sample positions and original directions are passed to the shading network.
    *   Positional encoding $\gamma(\mathbf{x})$ (63-dim) is applied to positions and fed into the first layer.
    *   Positional encoding $\gamma(\mathbf{d})$ (27-dim) is concatenated to the feature vector before the last layer [S1].
    *   The network outputs RGB color $\mathbf{c} \in \mathbb{R}^3$ and volume density $\sigma \in \mathbb{R}^+$ for each sample [S1].
7.  **Volume Rendering:** The final color is computed using the standard differentiable volume rendering integral over the $N_s$ samples [S3].

### Formulas

**Opacity Loss:**
To prevent dark pixel artifacts caused by low sample counts failing to accumulate to full opacity for opaque surfaces, an opacity loss term is added [S3]:

$$
\text{loss}_O = 
\begin{cases} 
0, & \text{if } \sum_{i=1}^{N_s} \alpha_i \geq 1 \\
\left( \left( \sum_{i=1}^{N_s} \alpha_i \right) - 1 \right)^2, & \text{otherwise}
\end{cases}
$$

where $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$ is the opacity of sample $i$, and $N_s$ is the number of samples per ray [S3].

**Total Loss:**
The total loss is a weighted sum of the Mean Squared Error (MSE) between rendered and ground truth colors, and the opacity loss [S3]:

$$
\text{loss} = \alpha \cdot \text{loss}_{\text{MSE}} + \beta \cdot \text{loss}_O
$$

Typical values are $\alpha = 1.0$ and $\beta = 10.0$ [S3].

**Depth Oracle Loss:**
The depth oracle is trained using Binary Cross Entropy (BCE) loss on the discretized depth classification targets [S3].

### Parameters
*   **Network Architecture:** Both oracle and shading networks have 8 hidden layers with 256 units [S3].
*   **Samples per Ray ($N_s$):** Typically 2, 4, 8, or 16. DONeRF-4 is a common configuration [S3].
*   **Training Iterations:** 300,000 iterations for the oracle network, followed by 300,000 iterations for the shading network [S3].
*   **Optimizer:** Adam, learning rate 0.0005, batch size 4096 samples per iteration [S3].
*   **View Cell:** Defined by a bounding box and rotation limits (e.g., 30° pitch, 20° yaw) [S3].

### Edge Cases and Pitfalls
*   **Dark Pixel Artifacts:** Low sample counts may result in accumulated opacity $< 1$ for opaque surfaces, causing darkening. This is mitigated by the opacity loss term [S3].
*   **Non-End-to-End Training:** The architecture is not jointly trainable in a single pass; the oracle must be trained first to provide stable sample locations for the shading network [S2].
*   **Lack of Ground Truth Depth:** If GT depth is unavailable, a dense NeRF (12 layers, 512 units, 128 samples/ray) must be trained first to extract depth maps, which are then used as supervision for the oracle [S3]. This can introduce noise in background regions [S3].
*   **Reflective/Transparent Surfaces:** Single-depth estimation is insufficient for mirrors or refractive surfaces, leading to artifacts [S3].

## Operating characteristics
*   **Time Complexity:** DONeRF requires approximately 4.35 MFLOP per pixel [S3]. Inference costs are reduced by up to 48x compared to NeRF [S3].
*   **Memory Complexity:** Compact MLP representation. No additional memory for explicit caching or acceleration structures (unlike NSVF) [S3].
*   **Performance:** Renders at 22 ms per frame on a single GPU at 400x400 pixels [S3]. On NVIDIA RTX 3090 at 800x800 with 2 samples/ray, total time is 51.3 ms (~20 fps) [S3].
*   **Quality:** Average PSNR of 31.14 dB compared to NeRF's 30.52 dB [S3]. At 16 samples, up to 7 dB higher PSNR than NeRF [S3].
*   **Strengths:** Real-time performance, compact memory footprint, high quality on large scenes [S3].
*   **Limitations:** Not end-to-end trainable, struggles without high-quality depth supervision, artifacts on reflective/transparent surfaces, dark pixel artifacts at low sample counts [S2][S3].

## Background
DONeRF was introduced by [S3] to address the computational prohibitions of NeRF for real-time rendering. It was developed by researchers at Graz University of Technology and Facebook Reality Labs. The method builds on the concept of using depth information to guide sampling, replacing the coarse/fine network structure of NeRF with a dedicated depth oracle and shading network [S3].
