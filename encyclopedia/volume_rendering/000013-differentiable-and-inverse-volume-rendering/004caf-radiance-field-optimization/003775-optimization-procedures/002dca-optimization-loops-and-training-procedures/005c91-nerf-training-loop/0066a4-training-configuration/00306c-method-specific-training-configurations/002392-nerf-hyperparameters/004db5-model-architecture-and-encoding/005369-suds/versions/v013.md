# SUDS
Also called: SUDS (Scalable Urban Dynamic Scenes), Scalable Urban Dynamic Scenes

## Overview
SUDS is a 4D radiance field representation designed for large-scale dynamic urban scenes that factorizes the scene into three separate hash table data structures to efficiently encode static, dynamic, and far-field radiance fields [S1]. It distinguishes itself from sibling methods by using unlabeled target signals (RGB, sparse LiDAR, 2D descriptors, 2D optical flow) for supervision, enabling free-viewpoint rendering, semantic decomposition, and 3D scene flow at arbitrary poses and time steps without requiring ground truth 3D bounding boxes or panoptic segmentation labels [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ordered RGB images from $N$ videos taken at different days with diverse weather and lighting conditions, associated camera poses, aligned sparse LiDAR depth measurements, 2D self-supervised DINO descriptors, and 2D optical flow predictions [S1].
*   **Outputs:** Per-branch color, density, semantic feature logits, scene flow vectors, and shadow ratios [S1].

**Data Structures:**
The scene is decomposed into three branches, each modeled using a multi-resolution hash table with scene partitioning into $K$ spatial cells [S1].
1.  **Static Branch:** Stores 3D spatial voxels $v_{l,s}$ [S1].
2.  **Dynamic Branch:** Stores 4D spacetime voxels $v_{l,d}$ [S1].
3.  **Far-field Branch:** Stores 3D voxels $v_{l,e}$ indexed by normalized 3D direction vectors, representing an environment map [S1].

Each hash table stores $F$-dimensional feature vectors. The hierarchy has $L$ resolution levels, where resolution doubles between levels [S1].

**Hash Indexing:**
Instead of storing features at voxel corners directly, indices are computed using specific hash functions [S1]:
$$ i_{l,s} = \text{static hash}(\text{space}(v_{l,s})) $$
$$ i_{l,d} = \text{dynamic hash}(\text{space}(v_{l,d}), \text{time}(v_{l,d}), \text{vid}) $$
$$ i_{l,e} = \text{env hash}(\text{dir}(v_{l,e}), \text{vid}) $$
where $\text{vid}$ is the video ID [S1]. Hash collisions are handled via gradient averaging [S1].

**Feature Interpolation:**
Features are linearly interpolated up to the nearest voxel vertices. Quadlinear interpolation is used for the dynamic 4D branch [S1]. Results from all $L$ levels are concatenated into a feature vector $f \in \mathbb{R}^{LF}$ along with auxiliary inputs (viewing direction) [S1].

**Network Outputs:**
The concatenated feature vector is passed into an MLP to obtain per-branch outputs [S1]:
*   **Static Branch:** View-dependent color $c_s(x, d, A_{\text{vid}} F(t)) \in \mathbb{R}^3$ and view-independent density $\sigma_s(x) \in \mathbb{R}$ [S1]. Lighting variations are modeled by conditioning on a latent embedding computed as the product of a video-specific matrix $A_{\text{vid}}$ and a Fourier-encoded time index $F(t)$ [S1].
*   **Dynamic Branch:** Time/video-dependent density $\sigma_d(x, t, \text{vid}) \in \mathbb{R}$, color $c_d(x, t, \text{vid}, d) \in \mathbb{R}^3$, and scalar shadow ratio $\rho_d(x, t, \text{vid}) \in [0, 1]$ [S1]. It also predicts forward and backward 3D scene flow vectors $s_{t0}(x, t, \text{vid}) \in \mathbb{R}^3$ with values in $[-1, 1]$ [S1].
*   **Far-field Branch:** Environment map color $c_e(d, \text{vid}) \in \mathbb{R}^3$ [S1].
*   **Semantic Features:** Each branch has a $C$-dimensional output head to distill DINO features: $\Phi_s(x) \in \mathbb{R}^C$, $\Phi_d(x, t, \text{vid}) \in \mathbb{R}^C$, $\Phi_e(d, \text{vid}) \in \mathbb{R}^C$ [S1].

**Density and Radiance Combination:**
Total density is the sum of static and dynamic densities:
$$ \sigma(x, t, \text{vid}) = \sigma_s(x) + \sigma_d(x, t, \text{vid}) $$
Total radiance combines static and dynamic components, scaled by the shadow ratio:
$$ c(x, t, \text{vid}, d) = \frac{(1 - \rho_d)\sigma_s c_s + \sigma_d c_d}{\sigma} $$
The final color $\hat{C}(r, t, \text{vid})$ for a camera ray $r$ is accumulated along sampled points $r(t)$, forcing intersection with the far-field environment map if no foreground geometry is hit:
$$ \hat{C}(r, t, \text{vid}) = \int_0^{+\infty} T(t)\sigma(r(t), t, \text{vid})c(r(t), t, \text{vid}, d)dt + T(+\infty)c_e(d, \text{vid}) $$
where $T(t) = \exp\left(-\int_0^t \sigma(r(s), t, \text{vid})ds\right)$ [S1].

**Training Configuration:**
*   **Spatial Partitioning:** The scene is split into $K$ spatial cells with centroids $k \in \mathbb{R}^3$. Separate training datasets are generated for each cell by including only datapoints whose camera rays intersect the cell, pruning irrelevant rays using LiDAR depth measurements to ensure visibility [S1].
*   **Hyperparameters:** Training runs for 250,000 iterations with 4098 rays per batch. Adam optimizer is used with an initial learning rate of $5 \times 10^{-3}$ decaying to $5 \times 10^{-4}$ [S1].
*   **Loss Functions:**
    *   **Reconstruction:** L2 photometric loss $L_c(r) = \|C(r) - \hat{C}(r)\|^2$ and L1 feature loss $L_f(r) = \|F(r) - \hat{F}(r)\|_1$ [S1].
    *   **Depth:** L2 loss between measured LiDAR depth $D(r)$ and expected depth $\hat{D}(r)$ [S1].
    *   **Flow:** 3D position $\hat{X}_{t0}(r)$ is predicted using scene flow and rendered to 2D. Loss minimizes distance from observed optical flow $O$ [S1].
    *   **Warping:** Samples are advected using predicted flow to warp density, color, and features. Warped color $\hat{C}^w$ and feature $\hat{F}^w$ are rendered. Loss is downweighted in ambiguous regions using weight $W_{t0}(r)$ derived from dynamic geometry difference [S1].
    *   **Flow Regularization:** Cycle consistency $L_{cyc}(r)$, spatial/temporal smoothness $L_{sm}$, and static scene prior $L_{slo}$ [S1].
    *   **Static-Dynamic Factorization:** Skewed binary entropy loss $L_e(r)$ with $k=1.75$ and penalty on max dynamic ratio $L_d(r)$ [S1].
    *   **Shadow Loss:** Penalizes squared magnitude of shadow ratio $\rho_d$ [S1].

def compute_hash_index(branch_type, space_coords, time=None, vid=None, direction=None):
    """
    Computes hash index for a voxel corner.
    branch_type: 'static', 'dynamic', or 'far_field'
    space_coords: 3D coordinates for static/dynamic
    time: frame index for dynamic
    vid: video ID
    direction: normalized 3D direction for far_field
    """
    if branch_type == 'static':
        return static_hash(space_coords)
    elif branch_type == 'dynamic':
        return dynamic_hash(space_coords, time, vid)
    elif branch_type == 'far_field':
        return env_hash(direction, vid)

def interpolate_features(branch_type, voxel_corners, coords, time=None, vid=None):
    """
    Interpolates features from voxel corners.
    Uses linear interpolation for static/far_field.
    Uses quadlinear interpolation for dynamic.
    """
    if branch_type == 'dynamic':
        return quadlinear_interpolate(voxel_corners, coords, time, vid)
    else:
        return linear_interpolate(voxel_corners, coords)

            dynamic_voxels = find_voxels(x, t, vid, levels=L)
            dynamic_indices = [compute_hash_index('dynamic', v, t, vid) for v in dynamic_voxels]
            dynamic_features = lookup_and_interpolate(dynamic_indices, x, t, vid)
            dynamic_f = concatenate_levels(dynamic_features) + auxiliary_inputs(d, vid, t)
            sigma_d, c_d, rho_d, phi_d, s_flow = dynamic_mlp(dynamic_f)
            
            # Far-field Branch

            far_indices = [compute_hash_index('far_field', v, vid=vid) for v in far_voxels]
            far_features = lookup_and_interpolate(far_indices, d, vid=vid)
            far_f = concatenate_levels(far_features)
            c_e, phi_e = far_mlp(far_f)

            sigma = sigma_s + sigma_d

                c = c_e
            
            # Combine Semantic Features
            phi = (sigma_s * phi_s + sigma_d * phi_d) / sigma if sigma > 0 else phi_e
            
            # Accumulate
            T = exp(-integral_sigma)
            total_radiance += T * sigma * c
            total_transmittance *= T
            total_semantic += T * sigma * phi
            
            if total_transmittance < epsilon:
                break
        
        # Add far-field contribution if ray escapes

        # Update parameters using Adam

## Operating characteristics
*   **Time and Memory Complexity:** SUDS scales to tens of thousands of objects across 1.2 million frames from 1700 videos spanning geospatial footprints of hundreds of kilometers [S1]. It is 10x quicker to train than state-of-the-art methods that rely on ground truth 3D bounding box annotations [S1].
*   **Strengths:** Handles ego-motion and multi-video representations, unlike NSG which cannot handle ego-motion and is constrained by memory requirements for per-object NeRFs (needing over 1TB for a 30-second video) [S1]. Uses unlabeled inputs, avoiding the need for difficult-to-acquire supervised inputs like panoptic segmentation labels or bounding boxes [S1].
*   **Limitations:** Not given in the sources.
*   **When to use:** Large-scale dynamic urban scenes requiring free-viewpoint rendering, semantic decomposition, and 3D scene flow without manual labeling [S1].
*   **When not to use:** Small-scale or static scenes where simpler methods suffice; scenes where ground truth 3D bounding boxes are available and preferred for supervision [S1].

## Background
SUDS was introduced in 2023 by the authors of "SUDS: Scalable Urban Dynamic Scenes" [S1]. It builds on ideas from Instant-NGP [S1] and MegaNeRF [S1], extending them to handle dynamism and scale. It addresses the limitations of prior methods that require supervised inputs like panoptic segmentation labels or bounding boxes, which are difficult to acquire with high accuracy for in-the-wild captures [S1].
