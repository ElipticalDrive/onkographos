# Training Loop Setup

Also called: IDR Baseline, PixelNeRF Training and Rendering Pipeline, Training Loop Configuration & Checkpointing, Training Step Execution

## Overview
The Training Loop Setup establishes the execution environment for differentiable volume rendering optimization, handling initialization, data loading, checkpoint management, and the core iteration logic [S1, S5, unofficial]. It solves the problem of reproducibly managing the state required to train neural radiance fields or implicit surface representations by standardizing how models, optimizers, and datasets are loaded and how gradients are applied [S5, unofficial]. It differs from [Learning Rate Scheduling](2701-learning-rate-scheduling.md) and [Mixed Precision Training](2766-mixed-precision-training.md) by focusing on the structural orchestration of the training state rather than numerical precision or adaptive step sizing [G].

## How it works
The method executes a single training iteration or configures the global training environment. It involves initializing random seeds, loading scene data and camera poses, managing checkpoint resumption, and performing the forward-backward pass sequence [S1, S5, unofficial].

### Inputs and Outputs
**Inputs:**
- Configuration arguments (`args`): dataset type, paths, random seed, learning rate, batch size, GPU IDs, and checkpoint paths [S5, unofficial].
- Scene data: Images, camera poses, bounding boxes, and focal lengths [S2, S5, unofficial].
- Model parameters: Neural network weights (coarse and optional fine networks) [S2, S5, unofficial].
- Optimizer state: Adam moments (exp_avg, exp_avg_sq) if resuming [S1, unofficial].

**Outputs:**
- Updated model weights [S1, unofficial].
- Loss metrics (RGB, SSIM, etc.) for logging [S2, S5, unofficial].
- Checkpoint files saved at specified intervals [S5, unofficial].

### Data Structures
**Ray Data:**
- Generated per view using camera intrinsics and extrinsics [S2, unofficial].
- Shape: `(NV, H, W, 8)` where `NV` is number of views, `H` height, `W` width [S2, unofficial].
- Each ray vector contains 8 dimensions (typically origin xyz, direction xyz, and potentially view index or other metadata) [S2, unofficial].

**Image Data:**
- Input images shape: `(SB, NV, 3, H, W)` where `SB` is batch size [S2, unofficial].
- Source images selected shape: `(SB, NS, 3, H, W)` where `NS` is number of source views [S2, unofficial].
- Pixel values normalized to `[0, 1]` range via `images * 0.5 + 0.5` [S2, unofficial].

**Checkpoint State:**
- Weights stored as `.npy` files [S5, unofficial].
- Filename pattern includes step number: `model_*.npy` [S5, unofficial].
- Step number extracted from filename: `int(ft_weights[-10:-4])` [S5, unofficial].

### Numbered Steps
1. **Environment Initialization:**
   - Set random seeds for reproducibility: `np.random.seed(args.random_seed)` and `tf.compat.v1.set_random_seed` (if using TensorFlow) [S5, unofficial].
   - Create log directory: `os.makedirs(os.path.join(basedir, expname), exist_ok=True)` [S5, unofficial].

2. **Data Loading:**
   - Load images and transformation matrices from disk based on `args.dataset_type` (e.g., llff, blender, deepvoxels) [S5, unofficial].
   - Transform poses and images to the target device (GPU) [S5, unofficial].
   - Normalize image values to `[0, 1]` [S2, unofficial].
   - Generate camera rays for all views using `util.gen_rays(poses, W, H, focal, z_near, z_far)` [S2, unofficial].

3. **Checkpoint Management:**
   - Check for existing checkpoints in the log directory [S5, unofficial].
   - If `args.ft_path` is provided or latest checkpoint exists:
     - Load weights: `model.set_weights(np.load(ft_weights, allow_pickle=True))` [S5, unofficial].
     - Set start step: `start = int(ft_weights[-10:-4]) + 1` [S5, unofficial].
     - If fine network exists, load corresponding fine weights [S5, unofficial].

4. **View Selection (for multi-view methods like PixelNeRF):**
   - Randomly select `curr_nviews` source views from available views: `np.random.choice(NV, curr_nviews, replace=False)` [S2, unofficial].
   - Index into images and poses using `util.batched_index_select_nd` [S2, unofficial].
   - Note: This selection is noted as "somewhat inefficient" in some implementations [S2, unofficial].

5. **Network Encoding (if applicable):**
   - Encode source views into the network: `net.encode(src_images, src_poses, all_focals, c=all_c)` [S2, unofficial].

6. **Forward Pass:**
   - Render the scene by calling the parallel renderer on selected rays: `render_dict = render_par(all_rays, want_weights=True)` [S2, unofficial].
   - Outputs include coarse RGB, fine RGB (if enabled), and weights [S2, unofficial].

7. **Loss Computation:**
   - Calculate RGB loss for coarse output: `loss_coarse = self.rgb_coarse_crit(coarse.rgb, all_rgb_gt)` [S2, unofficial].
   - If fine rendering is used (`len(fine) > 0`), add fine RGB loss weighted by `lambda_fine`: `loss_fine = lambda_fine * self.rgb_fine_crit(fine.rgb, all_rgb_gt)` [S2, unofficial].
   - Total loss: `loss = loss_coarse + loss_fine` [S2, unofficial].
   - Normalize loss by `lossInvN = 1.0 / (height * width * 3)` [S1, unofficial].

8. **Backward Pass and Update:**
   - Compute gradients: `loss.backward()` [G].
   - Step optimizer: `optimizer.step()` [G].
   - Zero gradients: `optimizer.zero_grad()` [G].

9. **Logging and Checkpointing:**
   - Print metrics every `i_print` steps (default 100) [S5, unofficial].
   - Save weights every `i_weights` steps (default 10000) [S5, unofficial].

### Formulas
- **Image Normalization:**
  $$ \text{images}_{[0,1]} = \text{images} \times 0.5 + 0.5 $$
  [S2, unofficial]

- **Loss Normalization Factor:**
  $$ \text{lossInvN} = \frac{1.0}{\text{height} \times \text{width} \times 3} $$
  [S1, unofficial]

- **Scaling Factor for Bounding Box:**
  $$ \text{sc} = \begin{cases} 1. & \text{if } \text{bd\_factor is None} \\ \frac{1}{\min(\text{bds}) \times \text{bd\_factor}} & \text{otherwise} \end{cases} $$
  [S5, unofficial]

- **Total Loss:**
  $$ \mathcal{L} = \mathcal{L}_{\text{coarse}} + \lambda_{\text{fine}} \mathcal{L}_{\text{fine}} $$
  where $\lambda_{\text{fine}}$ is loaded from config, default 1.0 [S2, unofficial].

### Parameters
- `i_print`: Frequency of console printout and metric logging, default 100 [S5, unofficial].
- `i_weights`: Frequency of weight checkpoint saving, default 10000 [S5, unofficial].
- `lambda_coarse`: Weight for coarse RGB loss, loaded from config [S2, unofficial].
- `lambda_fine`: Weight for fine RGB loss, default 1.0 [S2, unofficial].
- `no_bbox_step`: Integer parameter; if `global_step >= no_bbox_step`, bbox sampling is disabled [S2, unofficial].
- `random_seed`: If not None, sets `np.random.seed` and `tf.compat.v1.set_random_seed` [S5, unofficial].

### Edge Cases and Pitfalls
- **Inefficient View Selection:** Randomly selecting source views for each object in the batch loop is noted as inefficient [S2, unofficial].
- **Checkpoint Resumption:** Ensure step number extraction logic matches filename format exactly to avoid incorrect start steps [S5, unofficial].
- **Device Placement:** Ensure all data (images, poses, rays) are moved to the specified GPU device before computation [S5, unofficial].
- **Precision:** Use float32 for poses and images as specified [S5, unofficial].

### Pseudocode
```python
def training_loop_setup(args, model, optimizer, dataset, renderer):
    # 1. Environment Initialization
    if args.random_seed is not None:
        np.random.seed(args.random_seed)
        # tf.compat.v1.set_random_seed(args.random_seed) # If using TF
    os.makedirs(os.path.join(args.basedir, args.expname), exist_ok=True)
    
    # 2. Data Loading
    images, poses, bds, focals = load_data(args.dataset_type, args.datadir)
    images = images.astype(np.float32)
    poses = poses.astype(np.float32)
    
    # Normalize images to [0, 1]
    images_0to1 = images * 0.5 + 0.5
    
    # Move to device
    device = util.get_cuda(args.gpu_id[0])
    images = torch.tensor(images_0to1).to(device)
    poses = torch.tensor(poses).to(device)
    
    # Generate rays
    rays = util.gen_rays(poses, images.shape[-1], images.shape[-2], focals, z_near, z_far)
    # rays shape: (NV, H, W, 8)
    
    # 3. Checkpoint Management
    start_step = 0
    ckpts = sorted([f for f in os.listdir(args.logdir) if f.startswith('model_') and f.endswith('.npy')])
    if ckpts and not args.no_reload:
        ft_weights = ckpts[-1]
        print('Reloading from', ft_weights)
        model.set_weights(np.load(ft_weights, allow_pickle=True))
        start_step = int(ft_weights[-10:-4]) + 1
        if model.has_fine_network():
            # Load fine weights similarly
            pass
    
    # 4. Training Loop
    for step in range(start_step, args.max_steps):
        # 5. View Selection (for multi-view)
        curr_nviews = args.curr_nviews
        NV = images.shape[0]
        source_indices = np.random.choice(NV, curr_nviews, replace=False)
        src_images = util.batched_index_select_nd(images, source_indices)
        src_poses = util.batched_index_select_nd(poses, source_indices)
        
        # 6. Network Encoding (if applicable)
        if model.has_encoder():
            model.encode(src_images, src_poses, focals)
        
        # 7. Forward Pass
        render_dict = renderer.bind_parallel(model, args.gpu_id).eval()(rays, want_weights=True)
        coarse_rgb = render_dict.coarse.rgb
        fine_rgb = render_dict.fine.rgb if render_dict.has_fine else None
        
        # 8. Loss Computation
        loss_coarse = compute_rgb_loss(coarse_rgb, images[source_indices])
        loss = loss_coarse
        if fine_rgb is not None:
            loss_fine = compute_rgb_loss(fine_rgb, images[source_indices])
            loss = loss + args.lambda_fine * loss_fine
        
        # Normalize loss
        loss = loss * (1.0 / (images.shape[-1] * images.shape[-2] * 3))
        
        # 9. Backward Pass and Update
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 10. Logging and Checkpointing
        if step % args.i_print == 0:
            print(f"Step {step}, Loss: {loss.item()}")
        
        if step % args.i_weights == 0:
            np.save(os.path.join(args.logdir, f"model_{step:06d}.npy"), model.get_weights())
```

## Subtopics

### [Training Ray Batching](2252-training-ray-batching.md)
Training Ray Batching is a data loading strategy for Neural Radiance Fields (NeRF) that selects a random subset of pixel coordinates (and their corresponding rays) from the full training image grid per optimization iteration, rather than rendering complete images. It reduces the GPU memory footprint during the backward pass of gradient descent by processing only $N_{rand}$ rays per step, which controls gradient noise and enables efficient training. It differs from [Training Loop for Refractive Index Field](4178-training-loop-for-refractive-index-field.md) and [Training Loop](4290-training-loop.md) by explicitly managing the pre-computation, shuffling, and batch-slicing of ray tensors across multiple training images, whereas those siblings focus on the network forward/backward passes or specific physical models.

### [Training Loop for Refractive Index Field](4178-training-loop-for-refractive-index-field.md)
This method defines the optimization loop for training a Multi-Layer Perceptron (MLP) to represent a 3D refractive index (IOR) field and associated emission field, using differentiable ray tracing. It distinguishes itself by combining Eikonal ray tracing with luminance integration, optimizing the IOR field via boundary regularization and luminance reconstruction loss, specifically implemented in JAX for multi-device sharding. It builds on [Training Loop Setup](1522-training-loop-setup.md) and [Training Ray Batching](2252-training-ray-batching.md) [G].

### [Training Loop](4290-training-loop.md)
The Training Loop is the core optimization procedure for NeRF and related radiance field methods, orchestrating data loading, ray sampling, model forward passes, loss calculation, and parameter updates. It solves the problem of iteratively refining a scene representation to minimize the difference between rendered views and ground truth images. It sets itself apart from its siblings by defining the high-level control flow (epochs, batches, validation, checkpointing) rather than the specific ray batching strategies [Training Ray Batching](2252-training-ray-batching.md) or specialized guidance mechanisms like [Diffusion-Based Guidance for Radiance Field Optimization](8117-diffusion-based-guidance-for-radiance-field-optimization.md).

### [Camera Pose Optimization](15669-camera-pose-optimization.md)
Computes gradients of the reconstruction loss with respect to the rotation and translation components of a camera view matrix.

### Training Pipeline Configuration
The main entry point for the training experiment, which loads configuration, sets up global parameters, loads the scene and sensors, renders reference images, and initializes the SDF for optimization [S6, unofficial]. It loads configuration from a JSON file, updates experiment parameters (name, scene, epochs, lr, sensor counts, batch size) and rendering parameters (integrator, resolution, spp, SDF mode) using command-line args or config defaults [S6, unofficial]. It loads the scene using `mi.load_file` with the specified scene XML and hide environment flag [S6, unofficial]. It sets sensor parameters (radius, height) based on scene name: 'hotdog' (h=0.5), 'lego' (h=0.35), 'chair' (h=0.6, r=1.5), else (h=0.4, r=1.3) [S6, unofficial]. It initializes the SDF for optimization as a `SphereSDF` with specified resolution and radius, enabling gradients on the SDF grid tensor [S6, unofficial]. It checks if albedo, roughness, and metallic volumes are present in the scene parameters to determine optimization targets [S6, unofficial].

## Operating characteristics
- **Time Complexity:** Depends on the number of rays per step and network depth. IDR baseline takes 0.2 sec/iteration [S3, unofficial]. NeRF takes 0.40 sec/iteration [S3, unofficial]. NLR takes 2.21 sec/iteration [S3, unofficial].
- **Memory Complexity:** Proportional to the number of rays processed per step. Ray batching reduces memory footprint by processing only a subset of rays [S1, unofficial].
- **Measured Performance:** Training time varies significantly by method and dataset. IDR: 0.2 sec/iteration, 0.025 sec/frame rendering [S3, unofficial].
- **Scaling:** Scales with number of GPUs via parallel binding [S2, unofficial].
- **Strengths:** Flexible configuration, supports resumption, handles multi-view inputs [S2, S5, unofficial].
- **Limitations:** View selection can be inefficient [S2, unofficial]. Memory intensive for full-image rendering [S1, unofficial].

## Background
The Training Loop Setup is a fundamental component of differentiable volume rendering pipelines, originating from the NeRF paper [S5, unofficial] and adapted in subsequent works like PixelNeRF [S2, unofficial] and IDR [S3, unofficial]. It provides the infrastructure for iterative optimization of neural scene representations.
