# TriDF

Also called: Triplane-Accelerated Density Fields

## Overview
TriDF is a hybrid explicit–implicit 3D representation designed for few-shot novel view synthesis (NVS) in remote sensing, specifically addressing the computational burden and overfitting issues of implicit radiance fields when trained on as few as 3 input views [S1]. It decouples scene representation into explicit triplanes for high-frequency color prediction and implicit density fields for volume density, allowing independent optimization to accelerate convergence and improve geometry reconstruction compared to joint modeling approaches [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** $N_{in}$ input images (typically $N_{in}=3$) with known camera poses, and their corresponding depth maps or sparse point clouds generated via Structure-from-Motion (SfM) and PatchMatch Stereo (PMS) [S1].
*   **Outputs:** A rendered color image $\hat{C}(r)$ for a novel view ray $r$ [S1].

**Data Structures:**
1.  **Triplane ($P$):** A set of three mutually orthogonal feature planes $P = \{P_{XY}, P_{YZ}, P_{ZX}\}$ [S1].
    *   Each plane $P_{ij}$ is a tensor of size $H \times W \times C$ [S1].
    *   $H, W$: Height and width of the planes.
    *   $C$: Channel dimension (feature vector dimension is 64) [S1].
    *   Initialized randomly and optimized directly [S1].
2.  **Density MLP:** A Multi-Layer Perceptron (MLP) implementing the CUTLASS architecture [S1].
    *   Width: 512.
    *   Depth: 8 layers [S1].
3.  **Color MLP:** A compact MLP used to combine features and predict color [S1].
4.  **Reference Features:** Extracted from input images using a pretrained CNN encoder [S1].

**Numbered Steps:**

1.  **Initialization:**
    *   Estimate initial 3D point clouds from training views and poses using COLMAP (SfM + PMS) [S1].
    *   Re-project key points and their associated depth information from the generated point clouds to serve as spatial anchors for depth-guided optimization [S1].
    *   Extract reference features $f_{ref}$ from input images using a pretrained CNN encoder [S1].

2.  **Ray Sampling:**
    *   For a camera ray $r$, sample $N$ points $\mathbf{x}_i$ along the ray segment within the scene bounds [S1].
    *   $\delta_i$ is the distance between adjacent samples [S1].

3.  **Triplane Feature Retrieval (Color Branch):**
    *   For each 3D spatial point $\mathbf{x}$, project it orthogonally onto the three planes $P_{XY}, P_{YZ}, P_{ZX}$ [S1].
    *   Identify the four nearest grid points on each plane.
    *   Apply bilinear interpolation to compute feature vectors $f_{XY}, f_{YZ}, f_{ZX}$ [S1].
    *   Concatenate the feature vectors to form the final triplane feature vector:
        $$ f_{tri} = \text{concat}(f_{XY}, f_{YZ}, f_{ZX}) $$
        [S1]

4.  **Density Field Prediction (Geometry Branch):**
    *   Project reference features $f_{ref}$ to obtain corresponding feature vectors for each sampling point $\mathbf{x}_i$ [S1].
    *   Concatenate the projected reference features with positionally encoded coordinates $\mathbf{x}_i$ (positional encoding frequency = 6) [S1].
    *   Process the concatenated vector through the Density MLP to predict volume density $\sigma_i$ and intermediate features $f_m$ [S1].
        $$ [\sigma_i, f_m] = \text{DensityMLP}(\text{PE}(\mathbf{x}_i), f_{ref}) $$
        [S1]

5.  **Color Prediction:**
    *   Combine triplane features $f_{tri}$ and density features $f_m$ using a compact MLP ($\Phi_{base}$) to generate intermediate features $f_{base}$ [S1]:
        $$ f_{base} = \Phi_{base}(f_{tri}, f_m) $$
        [S1]
    *   Encode the viewing direction $\mathbf{d} \in \mathbb{R}^3$ on the spherical harmonics basis $\text{SH}(\cdot)$ [S1].
    *   Map $f_{base}$ and the encoded viewing direction to determine the point's color $\mathbf{c}_i \in \mathbb{R}^3$ using the Color MLP ($\Phi_{color}$) [S1]:
        $$ \mathbf{c}_i = \Phi_{color}(f_{base}, \text{SH}(\mathbf{d})) $$
        [S1]

6.  **Volume Rendering:**
    *   Compute opacity $\alpha_i$ and transmittance weights $w_i$ for each sample [S1]:
        $$ \alpha_i = 1 - \exp(-\sigma_i \delta_i) $$
        $$ T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right) $$
        $$ w_i = T_i (1 - \exp(-\sigma_i \delta_i)) $$
        [S1]
    *   Aggregate attributes to obtain the final pixel color $\hat{C}(r)$:
        $$ \hat{C}(r) = \sum_{i=1}^{N} w_i \mathbf{c}_i $$
        [S1]

7.  **Optimization:**
    *   Optimize the model using backpropagation [S1].
    *   **Loss Functions:**
        *   Photometric loss between predicted and ground truth colors [S1].
        *   Depth loss derived from the sparse point cloud anchors [S1].
        *   Edge-aware smoothness loss applied to geometric constraints [S1].
    *   **Training Schedule:**
        *   Total iterations: 30,000 [S1].
        *   First 10,000 iterations: Depth-guided optimization [S1].
        *   Next 20,000 iterations: Edge-aware smoothness loss [S1].
    *   **Batching:**
        *   Batch size: 1,024 pixel rays [S1].
        *   Samples per ray: 128 coarse samples [S1].
        *   Empty space skipping: Enabled via Nerfacc [S1].
        *   Edge-aware smoothness: Process 64 key points and randomly render a $16 \times 16$ patch with stride 4 [S1].
    *   **Optimizer:** AdamW with initial learning rate 0.0001 [S1].

## Operating characteristics
*   **Time Complexity:** Training is significantly faster than standard NeRF-based methods. TriDF achieves a 30× speed increase compared to NeRF-based methods [S1].
*   **Memory Complexity:** The triplane representation is compact. The memory usage is lower than dense voxel grids and comparable to or lower than 3DGS methods depending on resolution [S1].
*   **Measured Performance:**
    *   **Training Time:** ~5 minutes for 10k iterations (TriDF-10k) and 14 minutes for full 30k iterations on a single Nvidia GeForce RTX 4090 GPU [S1].
    *   **Rendering Quality:** On the LEVIRNVS dataset, TriDF achieves a 7.4% increase in PSNR and a 3.4% increase in SSIM compared to advanced few-shot methods (e.g., FSGS, CoR-GS) [S1].
*   **Strengths:**
    *   Fast convergence due to direct optimization of explicit triplane features [S1].
    *   Effective few-shot synthesis (as few as 3 views) without requiring extensive pretraining on large multi-view datasets [S1].
    *   Mitigates overfitting in sparse-view scenarios through depth-guided optimization using sparse point clouds [S1].
*   **Limitations:**
    *   Rendering speed lags behind 3DGS-based methods designed for real-time rendering [S1].
    *   Performance drops considerably if input views are extremely sparse without the depth-guided optimization [S1].
    *   Integrating IBR features directly into the triplane branch causes overfitting because frozen encoder features are constant and triplane features maintain a one-to-one correspondence with reference image features [S1].
*   **When to Use:** Remote sensing novel view synthesis with sparse input views (e.g., 3 views) where training speed and high-fidelity reconstruction are prioritized over real-time rendering.
*   **When Not to Use:** Scenarios requiring real-time rendering speeds comparable to 3DGS, or when dense input views are available and pretraining on large datasets is feasible (other methods may be more suitable).

## Background
TriDF was proposed to address the challenges of few-shot novel view synthesis in remote sensing, where input views are sparse and acquisition constraints limit the number of available images [S1]. Traditional NeRF methods suffer from low training efficiency (dozens of hours) and overfitting with sparse inputs [S1]. Existing few-shot methods often rely on extensive pretraining on large multi-view datasets, which is impractical for remote sensing [S1]. TriDF decouples color and volume density to reduce the computational burden on implicit radiance fields, accelerating reconstruction from as few as 3 input views [S1]. The method was validated on the LEVIRNVS dataset [S1].
