# Rip-NeRF

Also called: Rip-NeRF25k

## Overview
Rip-NeRF is a radiance field method that renders high-fidelity, anti-aliased images by combining cone casting with an anisotropic 3D Gaussian characterization [S1]. It differs from sibling methods like Zip-NeRF by using Ripmap-Encoded Platonic Solids to enable efficient anisotropic area-sampling, whereas Zip-NeRF relies on a multi-sampling mechanism that is less efficient [S1]. It builds on [Model Architecture and Encoding](13550-model-architecture-and-encoding.md) by replacing standard positional encoding with a hybrid explicit-implicit representation based on Platonic Solid Projection and Ripmap Encoding.

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of calibrated multi-view 2D images, camera poses, and intrinsics.
*   **Outputs:** Rendered pixel colors $\mathbf{c}$ and volume density $\sigma$ for each pixel, optimized end-to-end.

**Data Structures:**
1.  **Ripmap Encoding ($\mathcal{R}$):** A hierarchical grid of learnable features.
    *   **Base Level ($\mathcal{R}_{0,0}$):** A 3D tensor with shape $H \times W \times C$. Default dimensions: $H=512, W=512, C=16$ [S1].
    *   **Derived Levels:** Higher levels are not learnable but are derived from $\mathcal{R}_{0,0}$ using averaging operations to ensure consistency and compactness [S1].
2.  **Platonic Solid:** A geometric proxy for the 3D space. Default is an icosahedron with 10 unparalleled faces $\{P_i \mid i = 1, \dots, n\}$ [S1].
3.  **Anisotropic 3D Gaussian:** Characterizes each conical frustum. Defined by mean $\boldsymbol{\mu} \in \mathbb{R}^3$ and covariance $\boldsymbol{\Sigma} \in \mathbb{R}^{3 \times 3}$ [S1].
4.  **Tiny MLP ($F_\theta$):** A small neural network that takes aggregated features and outputs $\sigma$ and $\mathbf{c}$ [S1].
5.  **Binary Occupancy Grid:** Used to skip samples in empty space, implemented via the NerfAcc library [S1].

**Numbered Steps:**

1.  **Cone Casting and Frustum Division:**
    For each pixel, cast a cone into the scene. Divide the cone into multiple conical frustums along the viewing ray [S1]. This avoids discrete point-based sampling of continuous signals [S1].

2.  **Gaussian Characterization:**
    Characterize each conical frustum as an anisotropic 3D Gaussian parameterized by mean $\boldsymbol{\mu}$ and covariance $\boldsymbol{\Sigma}$ [S1].

3.  **Platonic Solid Projection:**
    Project the 3D Gaussian onto the faces of the Platonic solid to form 2D Gaussians.
    For each face $P_i$ ($i=1, \dots, n$):
    *   Let $M_i \in \mathbb{R}^{3 \times 2}$ be the projection matrix mapping the 3D world coordinate system to the 2D coordinate system of plane $P_i$ [S1].
    *   Compute the projected mean $\boldsymbol{\mu}_{proj} = M_i^T \boldsymbol{\mu}$ [G] (Note: Source implies mapping via $M_i$, standard projection is $\boldsymbol{\mu}_{proj} = M_i^T \boldsymbol{\mu}$ or similar linear transform; source says "mapping... into... $P_i$").
    *   Compute the projected covariance $\boldsymbol{\Sigma}_{proj} = M_i^T \boldsymbol{\Sigma} M_i$ [G] (Standard covariance transformation under linear map).
    *   The source states $\boldsymbol{\mu}_{proj}$ and $\boldsymbol{\Sigma}_{proj}$ are the mean and covariance of the projected 2D Gaussian on plane $P_i$ [S1].

4.  **Ripmap Encoding Query:**
    Query a feature vector $\mathbf{f}_i$ from the Ripmap Encoding of plane $P_i$ using tetra-linear interpolation [S1].
    *   The position $(p_x, p_y)$ used in interpolation is determined by $\boldsymbol{\mu}_{proj}$ [S1].
    *   The level $(l_x, l_y)$ used in interpolation is determined by $\boldsymbol{\Sigma}_{proj}$ [S1].
    *   The interpolation uses a hyper-parameter $w=2.0$ to adjust how much probability mass of the Gaussian footprint is covered [S1].
    *   The Ripmap levels are derived from the base level $\mathcal{R}_{0,0}$ using the following averaging rules for indices $i, j$ in $x, y$ directions [S1]:
        $$
        \mathcal{R}_{i,j} = \begin{cases} 
        \text{Avg}_{2 \times 1} \mathcal{R}_{i, j-1} & \text{if } j \neq 0 \\
        \text{Avg}_{1 \times 2} \mathcal{R}_{i-1, j} & \text{if } i \neq 0 \text{ \& } j = 0 \\
        \mathcal{R}_{0,0} & \text{otherwise}
        \end{cases}
        $$
        Where $\text{Avg}_{2 \times 1}$ averages two adjacent elements in the $y$-direction (or $x$-direction depending on axis definition, source says "indices of the levels in the x and y directions") and $\text{Avg}_{1 \times 2}$ averages in the other. Specifically, Eq 1 in source: $\mathcal{R}_{i,j} = \text{Avg}_{2 \times 1} \mathcal{R}_{i, j-1}$ if $j \neq 0$, and $\text{Avg}_{1 \times 2} \mathcal{R}_{i-1, j}$ if $i \neq 0, j=0$. This implies hierarchical downsampling [S1].

5.  **Feature Aggregation:**
    Concatenate all feature vectors $\{\mathbf{f}_i \mid i = 1, \dots, n\}$ from the $n$ Platonic solid faces to form the final feature vector $\mathbf{f}$ of the 3D Gaussian [S1].
    Concatenate $\mathbf{f}$ with the encoded view direction $\mathbf{d}$ [S1].

6.  **Density and Color Estimation:**
    Pass the aggregated feature vector (concatenation of $\mathbf{f}$ and $\mathbf{d}$) through the tiny MLP $F_\theta$ to estimate the density $\sigma$ and color $\mathbf{c}$ of the conical frustum [S1].

7.  **Volume Rendering:**
    Render the pixel color by performing volume rendering using the estimated $\sigma$ and $\mathbf{c}$ for all frustums along the ray [S1].

8.  **Optimization:**
    Optimize the system end-to-end using a photometric loss between rendered and observed images [S1].
    *   **Area Loss:** Scale the photometric loss for each pixel by incorporating the area of its footprint on the image plane, denoted as $L_{area}$ [S1]. This makes the loss area-aware [S1].

import torch
import torch.nn as nn
import torch.nn.functional as F

class RipNeRF:
    def __init__(self, h=512, w=512, c=16, num_faces=10, w_param=2.0):
        """
        Initialize Rip-NeRF.
        :param h: Height of base Ripmap level
        :param w: Width of base Ripmap level
        :param c: Channels of base Ripmap level
        :param num_faces: Number of faces in Platonic Solid (default 10 for Icosahedron)
        :param w_param: Hyper-parameter for Gaussian footprint coverage
        """
        self.num_faces = num_faces
        self.w_param = w_param
        
        # Base level Ripmap Encoding is learnable
        self.base_ripmap = nn.Parameter(torch.randn(h, w, c))
        
        # Tiny MLP for density and color
        # Input dim: c * num_faces + direction_encoding_dim
        # Output dim: 4 (sigma + rgb)
        self.mlp = nn.Sequential(
            nn.Linear(c * num_faces + 6, 64), # 6 for directional encoding (2*3)
            nn.ReLU(),
            nn.Linear(64, 4)
        )
        
        # Precompute projection matrices for Platonic Solid faces
        # M_i maps 3D world to 2D plane i
        self.projection_matrices = self.get_icosahedron_projection_matrices()

    def get_icosahedron_projection_matrices(self):
        """
        Returns list of projection matrices M_i for the 10 faces of an icosahedron.
        In a real implementation, this would compute the specific 3x2 matrices
        mapping world coordinates to the local 2D coordinate system of each face.
        Here we return dummy matrices for structure.
        """
        # Placeholder for actual geometric computation
        return [torch.eye(3, 2) for _ in range(self.num_faces)]

    def get_ripmap_level(self, level_x, level_y):
        """
        Retrieves the feature grid for a specific level (level_x, level_y)
        using the hierarchical averaging rule from Eq. 1.
        """
        # Base case
        if level_x == 0 and level_y == 0:
            return self.base_ripmap
        
        # Derived levels
        # Note: Indices might need adjustment based on coordinate system
        if level_y != 0:
            # Avg_2x1: Average along y-dimension (assuming y is vertical in grid)
            # Source: Avg_{2x1} R_{i, j-1}
            prev = self.get_ripmap_level(level_x, level_y - 1)
            # Average adjacent elements in the 'j' (y) direction
            # Assuming prev is (H, W, C), we average along H (if H corresponds to y)
            # The source says "indices of the levels in the x and y directions"
            # Let's assume level_x corresponds to H index and level_y to W index for consistency with typical image coords
            # However, Eq 1 says Avg_{2x1} for j!=0 (y) and Avg_{1x2} for i!=0 (x).
            # Let's assume H is x-axis and W is y-axis for the grid storage? 
            # Standard image: H is rows (y), W is cols (x).
            # Let's stick to source notation: i is x-index, j is y-index.
            # If grid is stored as [H, W, C], then H is y-index, W is x-index?
            # Let's assume grid[i, j] where i is row (y) and j is col (x) is NOT standard.
            # Let's assume grid[h, w, c].
            # If i is x-level and j is y-level.
            # If j != 0 (y-level > 0), we average in y-direction (rows).
            if level_x >= self.base_ripmap.shape[0] or level_y >= self.base_ripmap.shape[1]:
                return self.base_ripmap # Fallback
            
            # Average along the 'j' dimension (columns if j is col index, or rows if j is row index)
            # Source: Avg_{2x1} R_{i, j-1}. This usually means averaging 2 elements in one dim, 1 in other.
            # Let's assume standard PyTorch tensor [H, W, C].
            # If j is W-index (x-direction in image), then Avg_{2x1} averages along H?
            # Let's assume the source implies:
            # i -> H index, j -> W index.
            # If j != 0: Avg along W (dim 1).
            # If i != 0: Avg along H (dim 0).
            
            # Re-reading Eq 1:
            # i, j indices of levels in x and y directions.
            # Avg_{2x1} R_{i, j-1} if j != 0.
            # Avg_{1x2} R_{i-1, j} if i != 0 & j = 0.
            
            # Let's assume grid is [H, W, C].
            # If j is y-level, and we average in y-direction, we average along H.
            # If i is x-level, and we average in x-direction, we average along W.
            
            # Let's try:
            # j != 0: Average along H (dim 0).
            # i != 0: Average along W (dim 1).
            
            # This is ambiguous without the figure. 
            # However, the key is that it's a deterministic average of the previous level.
            # We will implement a generic average pool.
            
            # Let's assume the "level" corresponds to the resolution.
            # Level 0 is HxW. Level 1 is H/2 x W/2.
            # If we are at level (i, j), we derive it from (i, j-1) or (i-1, j).
            
            # Let's implement the average operation.
            # Avg_{2x1} means kernel 2x1. Avg_{1x2} means kernel 1x2.
            
            # If j != 0 (y-level), we use Avg_{2x1}.
            # If i != 0 (x-level), we use Avg_{1x2}.

            # Then Avg_{2x1} (2 rows, 1 col) averages along H.
            # Avg_{1x2} (1 row, 2 cols) averages along W.
            
            # Check source: "i and j are the indices of the levels in the x and y directions"
            # Usually x is horizontal (W), y is vertical (H).
            # So i -> W, j -> H.
            # If j != 0 (H-level > 0), Avg_{2x1} (2 in y, 1 in x) -> Average along H.
            # If i != 0 (W-level > 0), Avg_{1x2} (1 in y, 2 in x) -> Average along W.
            
            # Let's assume grid is [H, W, C].
            # i is W-index, j is H-index.
            
            if level_y != 0: # j != 0

                prev = self.get_ripmap_level(level_x, level_y - 1)

                     return self.base_ripmap

                avg_pool = nn.AvgPool2d(kernel_size=(2, 1), stride=(2, 1))
                # Input to AvgPool2d is (N, C, H, W)
                # prev is (H, W, C) -> (1, C, H, W)
                prev_4d = prev.permute(2, 0, 1).unsqueeze(0)
                pooled = avg_pool(prev_4d)
                return pooled.squeeze(0).permute(1, 2, 0)
            
            else: # j == 0
                if level_x == 0:
                    return self.base_ripmap
                # Avg along W (dim 1)
                # Kernel 1x2
                prev = self.get_ripmap_level(level_x - 1, level_y)
                if level_x >= self.base_ripmap.shape[0] or level_y >= self.base_ripmap.shape[1]:
                     return self.base_ripmap
                avg_pool = nn.AvgPool2d(kernel_size=(1, 2), stride=(1, 2))
                prev_4d = prev.permute(2, 0, 1).unsqueeze(0)
                pooled = avg_pool(prev_4d)
                return pooled.squeeze(0).permute(1, 2, 0)

    def query_ripmap(self, pos, level, base_h, base_w):
        """
        Queries the Ripmap at a specific position and level using tetra-linear interpolation.
        :param pos: (px, py) in [0, 1]
        :param level: (lx, ly) determining the resolution
        """
        # Determine the resolution for this level
        # Assuming level_x corresponds to W reduction, level_y to H reduction
        # lx is x-level, ly is y-level
        lx, ly = level
        h = base_h // (2 ** ly)
        w = base_w // (2 ** lx)
        
        grid = self.get_ripmap_level(lx, ly)
        
        # Map pos [0,1] to grid coordinates
        px = pos[0] * (w - 1)
        py = pos[1] * (h - 1)
        
        # Tetra-linear interpolation (bilinear in 2D)
        # Get 4 corners
        x0 = int(torch.floor(px))
        y0 = int(torch.floor(py))
        x1 = x0 + 1
        y1 = y0 + 1
        
        # Clamp
        x0 = torch.clamp(x0, 0, w - 1)
        y0 = torch.clamp(y0, 0, h - 1)
        x1 = torch.clamp(x1, 0, w - 1)
        y1 = torch.clamp(y1, 0, h - 1)
        
        # Interpolate
        # This is a simplified bilinear interpolation
        # f(x,y) = f(0,0)(1-x)(1-y) + f(1,0)x(1-y) + f(0,1)(1-x)y + f(1,1)xy
        # We need to handle the float positions
        
        # Extract values
        # grid is (H, W, C)
        # We need to interpolate at (py, px)
        
        # Using F.grid_sample for bilinear interpolation
        # Normalize to [-1, 1]
        px_norm = 2 * (px / (w - 1)) - 1
        py_norm = 2 * (py / (h - 1)) - 1
        
        # grid_sample expects (N, C, H, W) and grid (N, H_out, W_out, 2)
        # Grid coordinates are (x, y) -> (col, row)
        grid_coords = torch.stack([px_norm, py_norm], dim=-1).unsqueeze(0).unsqueeze(0) # (1, 1, 1, 2)
        grid_4d = grid.permute(2, 0, 1).unsqueeze(0) # (1, C, H, W)
        
        sampled = F.grid_sample(grid_4d, grid_coords, mode='bilinear', padding_mode='zeros')
        return sampled.squeeze()

    def forward(self, rays_o, rays_d, frustums):
        """
        Forward pass for a batch of rays.
        :param rays_o: Origin of rays (B, 3)
        :param rays_d: Direction of rays (B, 3)
        :param frustums: List of conical frustums for each ray, each characterized by (mu, Sigma)
        """
        rendered_colors = []
        
        for i, ray_frustums in enumerate(frustums):
            pixel_colors = []
            for mu, sigma in ray_frustums:
                # Step 3: Project to Platonic Solid faces
                features = []
                for k in range(self.num_faces):
                    M = self.projection_matrices[k]
                    # Project mean and covariance
                    # mu_proj = M^T mu
                    mu_proj = torch.matmul(M.T, mu)
                    # Sigma_proj = M^T Sigma M
                    sigma_proj = torch.matmul(torch.matmul(M.T, sigma), M)
                    
                    # Step 4: Query Ripmap
                    # Position determined by mu_proj
                    # Level determined by sigma_proj
                    # This requires mapping 2D Gaussian params to (px, py) and (lx, ly)
                    # The source says "position ... determined by mean" and "level ... determined by covariance"
                    # And uses w=2.0 to adjust probability mass coverage.
                    
                    # Simplified mapping:
                    # px, py from mu_proj
                    px, py = mu_proj[0], mu_proj[1]
                    
                    # lx, ly from sigma_proj eigenvalues or trace?
                    # Source says "level ... determined by ... covariance"
                    # And w=2.0 adjusts coverage.
                    # Typically, larger variance -> higher level (coarser resolution).
                    # Let's assume a simple mapping based on variance magnitude.
                    # This is a gap filled by [G].
                    var_x = sigma_proj[0, 0]
                    var_y = sigma_proj[1, 1]
                    
                    # Map variance to level index
                    # Higher variance -> higher level index
                    # w=2.0 might be a scaling factor for the variance before mapping
                    level_x = int(torch.log2(torch.clamp(var_x * self.w_param, min=1.0)))
                    level_y = int(torch.log2(torch.clamp(var_y * self.w_param, min=1.0)))
                    
                    # Clamp levels to base level if too small
                    level_x = max(0, min(level_x, 9)) # Assuming max 10 levels
                    level_y = max(0, min(level_y, 9))
                    
                    # Query feature
                    f_i = self.query_ripmap(torch.tensor([px, py]), (level_x, level_y), 512, 512)
                    features.append(f_i)
                
                # Step 5: Aggregate
                f_concat = torch.cat(features, dim=-1)
                
                # Encode view direction
                # Standard positional encoding for direction d
                # d is (3,)
                # Let's assume a simple linear encoding for brevity, or standard PE
                # Source says "encoded view direction d"
                # We'll use a simple linear projection as a placeholder for PE
                d_enc = torch.cat([torch.sin(2**i * torch.pi * d) for i in range(3)], dim=-1)
                
                # Step 6: MLP
                input_feat = torch.cat([f_concat, d_enc], dim=-1)
                output = self.mlp(input_feat)
                sigma = output[0]
                color = torch.sigmoid(output[1:])
                
                pixel_colors.append(color)
            
            # Step 7: Volume Rendering
            # Standard alpha compositing
            # This is a simplification. Real volume rendering integrates along the ray.
            # Here we assume frustums are sampled points along the ray.
            # We need to sort frustums by depth and apply volume rendering formula.
            # For brevity, we return the last color as a placeholder.
            # In a real implementation, this would be a loop over frustums with opacity calculation.
            if pixel_colors:
                rendered_colors.append(pixel_colors[-1])
            else:
                rendered_colors.append(torch.zeros(3))
                
        return torch.stack(rendered_colors)

## Operating characteristics
*   **Time Complexity:** Training time is 2.6 hours on an NVIDIA A100-SXM4-80GB GPU for 120k iterations [S1]. The variant Rip-NeRF25k trains in 32 minutes (11.76% of Zip-NeRF's 4.5 hours) [S1].
*   **Memory Complexity:** Model size is 160 MB [S1]. GPU memory consumption during training is 20 GB [S1]. This is significantly lower than Zip-NeRF's 80 GB, making it feasible for consumer GPUs like the RTX 4090 [S1].
*   **Rendering Speed:** Approximately 3 FPS in the experimental setting [S1]. This outperforms Zip-NeRF (0.25 FPS) [S1].
*   **Strengths:** High-fidelity anti-aliased rendering; efficient anisotropic area-sampling; compact model size; fast training and rendering compared to Zip-NeRF [S1].
*   **Limitations:** Requires calibrated multi-view images [S1]. Performance on unbounded scenes may be inferior to methods like Zip-NeRF which are designed for them [S1].
*   **When to use:** When high-fidelity anti-aliasing is required, and training time/memory are constraints. Suitable for bounded objects [S1].
*   **When not to use:** For unbounded scenes where Zip-NeRF's generalization is preferred, or if SSIM is the primary metric and Zip-NeRF's slightly better SSIM is critical [S1].

## Background
Rip-NeRF was introduced in 2024 by SRN et al. [S1]. It is part of the evolution of NeRF methods that incorporate hybrid representations (explicit and implicit) to balance efficiency and flexibility [S1]. It builds on concepts from Mip-NeRF (cone casting) and Tri-MipRF (Ripmap-like area sampling) [S1]. The method was evaluated on the multi-scale Blender dataset [S1].
