# LLFF Data Loading and Spiral Path Generation

Also called: Real Scene NeRF Dataset Loading

## Overview
This method prepares LLFF-style datasets for volume rendering by loading camera poses and images, correcting coordinate system conventions, rescaling the scene, and generating a spiral render path for novel view synthesis. It sets itself apart from generic loaders by enforcing specific axis corrections, bounding-box-based rescaling, and the generation of a parametric spiral trajectory for test rendering, as established in the original LLFF paper [S1, unofficial].

## How it works
**Inputs:**
- Raw poses (N x 4 x 4 or N x 3 x 4 matrices), bounds (`bds`), and images.
- Parameters: `recenter` (bool), `bd_factor` (float, default 0.75), `spherify` (bool), `N_views` (int), `path_zflat` (bool), `zdelta` (float), `zrate` (float, default 0.5).
- File paths for `train.txt` and `test.txt` to split data.

**Outputs:**
- Rescaled poses (N x 4 x 4).
- Rescaled bounds (`bds`).
- Spiral render poses (`render_poses`).
- Split images and masks for training and testing.

**Data Structures:**
- Poses: $N \times 4 \times 4$ homogeneous transformation matrices.
- Bounds: $N \times 2$ array where each row is $[min\_depth, max\_depth]$.
- Images: Tensor of shape $(N, H, W, 3)$.

**Steps:**

1. **Load and Correct Poses:**
   Load raw poses and bounds. Correct the rotation matrix ordering by concatenating columns: $poses[:, 1:2, :]$, $-poses[:, 0:1, :]$, and $poses[:, 2:, :]$. Move the last axis to the front (transpose) to match the expected layout [S1, unofficial].

2. **Rescale Scene:**
   Compute scale factor $sc = 1 / (\min(bds) \times bd\_factor)$ if $bd\_factor$ is not None. Rescale all poses and bounds by $sc$ [S1, unofficial].

3. **Recenter (Optional):**
   If `recenter` is True, center the poses around the origin using `recenter_poses(poses)` [S1, unofficial].

4. **Spherify (Optional):**
   If `spherify` is True, call `spherify_poses(poses, bds, N_views)` and update $sc$ accordingly. This adjusts poses to lie on a sphere [S1, unofficial].

5. **Compute Average Pose and Up Vector:**
   If not spherify, compute the average pose $c2w = poses\_avg(poses)$. Compute the up vector:
   $$ up = \text{normalize}\left(\sum_{i=0}^{N-1} poses_i[:, :3, 1]\right) $$
   where $poses_i[:, :3, 1]$ is the y-axis of the $i$-th pose's rotation matrix [S1, unofficial].

6. **Determine Focus Depth and Focal Length:**
   Calculate close and far depths:
   $$ close\_depth = \min(bds) \times 0.9 $$
   $$ inf\_depth = \max(bds) \times 5.0 $$
   Compute mean depth $mean\_dz$:
   $$ mean\_dz = \frac{1}{\frac{1-0.75}{close\_depth} + \frac{0.75}{inf\_depth}} $$
   Set focal length $focal = mean\_dz$ [S1, unofficial].

7. **Adjust Path Parameters:**
   If `path_zflat` is True:
   - Set $zloc = -close\_depth \times 0.1$.
   - Adjust the path center: $c2w\_path[:3, 3] += zloc \times c2w\_path[:3, 2]$.
   - Set radius $rads[2] = 0$.
   - Set $N\_rots = 1$.
   - Set $N\_views = N\_views / 2$.
   Else:
   - Set $N\_rots = 2$ [S1, unofficial].

8. **Generate Spiral Path:**
   Generate render poses using `render_path_spiral(c2w_path, up, rads, focal, zdelta, zrate=0.5, rots=N_rots, N=N_views)`. This creates a spiral trajectory around the scene center [S1, unofficial].

9. **Split Data:**
   Load images and split them into training and test sets based on indices listed in `train.txt` and `test.txt` files in the base directory [S1, unofficial].

**Pseudocode:**

```python
import numpy as np
import torch

def load_llff_data(basedir, factor=8, recenter=True, bd_factor=0.75, spherify=False, path_zflat=True, N_views=120):
    # 1. Load raw data (poses, bds, images)
    # Note: Actual loading logic depends on file structure (poses_bounds.npy, images/)
    poses, bds, imgs = load_raw_llff_data(basedir)
    
    # 2. Correct rotation matrix ordering
    # Concatenate: col 1, -col 0, col 2
    poses_corrected = np.concatenate([poses[:, 1:2, :], -poses[:, 0:1, :], poses[:, 2:, :]], axis=1)
    # Move axis -1 to 0 (transpose last two dims if needed, or reshape)
    poses_corrected = np.moveaxis(poses_corrected, -1, 0)
    poses_corrected = np.transpose(poses_corrected, (0, 2, 1)) # Ensure 4x4 layout
    
    # 3. Rescale
    sc = 1.0 / (np.min(bds) * bd_factor) if bd_factor is not None else 1.0
    poses_corrected *= sc
    bds *= sc
    
    # 4. Recenter
    if recenter:
        poses_corrected = recenter_poses(poses_corrected)
        
    # 5. Spherify
    if spherify:
        poses_corrected, sc = spherify_poses(poses_corrected, bds, N_views)
        
    # 6. Average pose and up vector
    c2w = poses_avg(poses_corrected)
    up = normalize(np.sum(poses_corrected[:, :3, 1], axis=0))
    
    # 7. Focus depth
    close_depth = np.min(bds) * 0.9
    inf_depth = np.max(bds) * 5.0
    mean_dz = 1.0 / (((1 - 0.75) / close_depth) + (0.75 / inf_depth))
    focal = mean_dz
    
    # 8. Path parameters
    zdelta = 0.0 # Default value if not specified
    if path_zflat:
        zloc = -close_depth * 0.1
        c2w_path = c2w.copy()
        c2w_path[:3, 3] += zloc * c2w_path[:3, 2]
        rads = np.array([1.0, 1.0, 0.0]) # rads[2] = 0
        N_rots = 1
        N_views_final = N_views // 2
    else:
        c2w_path = c2w
        rads = np.array([1.0, 1.0, 1.0]) # Placeholder for radius
        N_rots = 2
        N_views_final = N_views
        
    # 9. Generate spiral
    render_poses = render_path_spiral(c2w_path, up, rads, focal, zdelta, zrate=0.5, rots=N_rots, N=N_views_final)
    
    # 10. Split data
    i_train, i_test = load_split_indices(basedir)
    
    return poses_corrected, bds, imgs, render_poses, i_train, i_test

def poses_avg(poses):
    """Compute average pose from a list of poses."""
    center = np.mean(poses[:, :3, 3], axis=0)
    rot = poses[:, :3, :3]
    rot = rot / np.linalg.norm(rot, axis=(1,2), keepdims=True)
    # Simple average of rotation matrices is not ideal, but often used in this context
    # For this implementation, we assume a simple average or identity if not specified
    avg_rot = np.mean(rot, axis=0)
    avg_rot = normalize_rotation(avg_rot) # Ensure valid rotation
    pose_avg = np.eye(4)
    pose_avg[:3, :3] = avg_rot
    pose_avg[:3, 3] = center
    return pose_avg

def normalize(v):
    return v / np.linalg.norm(v)

def normalize_rotation(R):
    # Simple SVD-based re-orthogonalization
    U, S, Vt = np.linalg.svd(R)
    return U @ Vt
```

**Edge Cases and Pitfalls:**
- **Precision:** Rescaling by `bd_factor` can lead to numerical instability if `bds.min()` is very small. [G] Ensure `bd_factor` is not zero.
- **Boundaries:** If `bds` contains zeros or negative values, `close_depth` calculation may fail. [G] Clamp `bds` to positive values before processing.
- **Degenerate Input:** If `N_views` is odd and `path_zflat` is True, integer division `N_views // 2` may lose a view. [G] Handle odd `N_views` explicitly if needed.

### [LLFF Data Loading and Minification](11293-llff-data-loading-and-minification.md)
This method prepares LLFF-style datasets for volume rendering by loading poses and images, downsampling them to a standard resolution, and splitting them into training and test sets. It sets apart from generic loaders by enforcing the specific 1/8th resolution reduction and the "every 8th image" test split convention established in the original LLFF paper. It builds on [LLFF Data Loading and Spiral Path Generation](11275-llff-data-loading-and-spiral-path-generation.md) by providing the raw data tensors required for the optimization loop.

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of images for loading and splitting. Spiral path generation is $O(N_{views})$.
- **Memory Complexity:** Linear with respect to the number of images and resolution.
- **Strengths:** Provides a standardized way to handle LLFF data, ensuring consistent coordinate systems and camera paths for novel view synthesis.
- **Limitations:** Assumes LLFF-style data structure. Spiral path may not be optimal for all scene geometries.
- **When to Use:** When working with LLFF datasets and needing to generate novel views via spiral paths.
- **When Not to Use:** For non-LLFF datasets or when a different camera path (e.g., linear, circular) is required.

## Background
This method is derived from the implementation details of the LLFF (Local Light Field Fusion) dataset and its integration into NeRF training pipelines. It was popularized by the original NeRF paper and subsequent implementations like NerfingMVS [S1, unofficial]. The spiral path generation is a common technique for evaluating novel view synthesis on the LLFF dataset.
