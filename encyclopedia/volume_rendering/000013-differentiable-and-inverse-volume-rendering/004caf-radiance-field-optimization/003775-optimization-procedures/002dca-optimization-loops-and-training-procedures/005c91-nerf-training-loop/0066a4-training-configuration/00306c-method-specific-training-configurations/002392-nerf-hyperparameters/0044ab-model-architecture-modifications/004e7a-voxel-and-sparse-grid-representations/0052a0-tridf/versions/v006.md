# TriDF

Also called: Triplane-Accelerated Density Fields

## Overview
TriDF is a hybrid explicit–implicit 3D representation designed for few-shot novel view synthesis (NVS), particularly in remote sensing scenes with sparse input views (e.g., 3 images) [S1]. It solves the problem of overfitting and slow convergence in standard NeRF-based methods by decoupling color and volume density: high-frequency color information is mapped to explicit triplanes for direct optimization, while low-frequency geometry is modeled by implicit density fields [S1]. Unlike sibling methods that jointly model appearance and geometry or rely on dense pretraining priors, TriDF accelerates reconstruction by 30× compared to NeRF-based methods while improving PSNR by 7.4% and SSIM by 3.4% on the LEVIRNVS dataset [S1].

## How it works
**Inputs:** $V$ input images (typically $V=3$) with known camera poses, and their corresponding depth maps or point clouds generated via Structure-from-Motion (SfM) and PatchMatch Stereo (PMS) [S1].
**Outputs:** A rendered color image $\hat{C}(r)$ for any novel view ray $r$ [S1].

**Data Structures:**
1.  **Triplane ($P$):** A set of three mutually orthogonal feature planes $P = \{P_{XY}, P_{YZ}, P_{ZX}\}$ [S1]. Each plane $P_{ij}$ is a tensor of size $H \times W \times C$ [S1].
    *   $H, W$: Height and width of the feature maps (Not given in the sources).
    *   $C$: Channel dimension (Not given in the sources).
    *   Initialized randomly and optimized directly [S1].
2.  **Density MLP:** A Multi-Layer Perceptron (MLP) with CUTLASS architecture, width 512, depth 8 [S1].
3.  **Color MLP:** A compact MLP (dimensions not specified) [S1].
4.  **Reference Features:** Extracted from input images using a pretrained CNN encoder (e.g., ResNet) [S1]. Feature vector dimension is 64 [S1].

**Numbered Steps:**

1.  **Initialization:** Estimate initial 3D point clouds from training views and poses using COLMAP [S1]. Generate coarse 3D point clouds through SfM and PMS [S1].
2.  **Feature Extraction:** Extract pixel-aligned reference features $f_{ref}$ from input images using a pretrained CNN encoder [S1].
3.  **Triplane Feature Retrieval (Color Branch):**
    *   For a 3D spatial point $\mathbf{x}$, project it orthogonally onto the three planes $P_{XY}, P_{YZ}, P_{ZX}$ [S1].
    *   Identify the four nearest grid points on each plane [S1].
    *   Apply bilinear interpolation to compute feature vectors $f_{XY}, f_{YZ}, f_{ZX}$ [S1].
    *   Concatenate to form the triplane feature vector: $f_{tri} = \text{concat}(f_{XY}, f_{YZ}, f_{ZX})$ [S1].
4.  **Density Field Prediction (Geometry Branch):**
    *   Project reference features $f_{ref}$ to obtain corresponding feature vectors for each sampling point [S1].
    *   Concatenate projected feature vectors with positionally encoded coordinates $\mathbf{x}$ (positional encoding frequency = 6) [S1].
    *   Process the concatenated vector through the Density MLP to predict volume density $\sigma$ and intermediate features $f_m$ [S1].
5.  **Color Prediction:**
    *   Combine triplane features $f_{tri}$ and density features $f_m$ using a compact MLP to generate intermediate features $f_{base}$:
        $$ f_{base} = \Phi_{base}(f_{tri}, f_m) $$
    *   Encode viewing direction $\mathbf{d} \in \mathbb{R}^3$ on the spherical harmonics basis $\text{SH}(\cdot)$ [S1].
    *   Map $f_{base}$ and $\text{SH}(\mathbf{d})$ through the Color MLP to determine the point's color $\mathbf{c} \in \mathbb{R}^3$ [S1].
6.  **Differentiable Volume Rendering:**
    *   Aggregate attributes along ray $r$ using the standard volume rendering equation [S1]:
        $$ \hat{C}(r) = \sum_{i=1}^{N} T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i $$
        $$ T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right) $$
        where $\mathbf{c}_i$ and $\sigma_i$ are color and volume density, $\delta_i$ is the distance between adjacent samples, $N$ is the number of sampling points, and $T_i$ is the accumulated transmittance [S1].
7.  **Optimization:**
    *   Optimize the model using AdamW (initial learning rate 0.0001) [S1].
    *   **Phase 1 (Iterations 1–10,000):** Depth-guided optimization. Re-project key points and depth from the generated point clouds to use as spatial anchors [S1].
    *   **Phase 2 (Iterations 10,001–30,000):** Edge-aware smoothness loss. Process 64 key points and randomly render a $16 \times 16$ patch with stride 4 to compute geometric constraints [S1].
    *   Loss functions include photometric loss (predicted vs. ground truth colors), depth loss, and smoothness loss [S1].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class TriDF:
    def __init__(self, H, W, C, triplane_init_std=0.01):
        """
        Initialize TriDF model.
        H, W, C: Dimensions of the triplane feature maps.
        """
        # Triplane: 3 planes, each H x W x C
        self.P = nn.Parameter(torch.randn(3, C, H, W) * triplane_init_std)
        
        # Density MLP: CUTLASS architecture, width 512, depth 8
        # Input: pos_encoded_coords (dim) + projected_ref_features (64)
        # Output: sigma (1) + f_m (dim)
        self.density_mlp = nn.Sequential(
            nn.Linear(64 + 12, 512), nn.ReLU(), # 12 = 6 * 2 (sin/cos PE)
            nn.Linear(512, 512), nn.ReLU(),
            nn.Linear(512, 512), nn.ReLU(),
            nn.Linear(512, 512), nn.ReLU(),
            nn.Linear(512, 512), nn.ReLU(),
            nn.Linear(512, 512), nn.ReLU(),
            nn.Linear(512, 512), nn.ReLU(),
            nn.Linear(512, 512 + 64) # sigma + f_m
        )
        
        # Color MLP: Compact MLP
        # Input: f_base (dim) + SH(d) (dim)
        # Output: color (3)
        self.color_mlp = nn.Sequential(
            nn.Linear(64 + 15, 64), nn.ReLU(), # SH degree 2 -> 15 coeffs
            nn.Linear(64, 3)
        )
        
        # Pretrained CNN Encoder (frozen)
        self.encoder = get_pretrained_cnn() 
        self.encoder.eval()
        for param in self.encoder.parameters():
            param.requires_grad = False

    def positional_encoding(self, x, freq=6):
        """Standard NeRF positional encoding."""
        # x: (..., 3)
        # Returns: (..., 12)
        x = x.unsqueeze(-1)
        scales = torch.tensor([2**i for i in range(freq)])
        pe = torch.cat([torch.sin(x * scales), torch.cos(x * scales)], dim=-1)
        return pe.view(x.size(0), -1)

    def spherical_harmonics(self, d, degree=2):
        """Simplified SH encoding for degree 2."""
        # d: (..., 3) normalized
        # Returns: (..., 15)
        # Note: Full SH implementation omitted for brevity, assumed available
        return compute_sh(d, degree)

    def get_triplane_features(self, x):
        """
        Retrieve features from triplane for point x.
        x: (N, 3)
        Returns: (N, 3*C)
        """
        # Project x onto XY, YZ, ZX planes
        # x_xy: (N, 2) -> (x, y)
        # x_yz: (N, 2) -> (y, z)
        # x_zx: (N, 2) -> (z, x)
        
        x_xy = x[:, [0, 1]]
        x_yz = x[:, [1, 2]]
        x_zx = x[:, [2, 0]]
        
        # Normalize to [-1, 1] for grid sampling (assuming scene bounds [-1, 1])
        # [G] Assuming scene is normalized to [-1, 1]^3. If not, scaling is required.
        x_xy = x_xy * 0.5 + 0.5
        x_yz = x_yz * 0.5 + 0.5
        x_zx = x_zx * 0.5 + 0.5
        
        # Bilinear interpolation
        # grid_sample expects (N, C, H, W) and grid (N, H_out, W_out, 2)
        # We sample at single points, so H_out=W_out=1
        def sample_plane(plane, coords):
            # coords: (N, 2) in [-1, 1]
            coords = coords.unsqueeze(1).unsqueeze(1) # (N, 1, 1, 2)
            feats = F.grid_sample(plane.unsqueeze(0), coords, align_corners=True)
            return feats.squeeze(-1).squeeze(-1).T # (C, N) -> (N, C)

        f_xy = sample_plane(self.P[0], x_xy)
        f_yz = sample_plane(self.P[1], x_yz)
        f_zx = sample_plane(self.P[2], x_zx)
        
        f_tri = torch.cat([f_xy, f_yz, f_zx], dim=-1) # (N, 3*C)
        return f_tri

    def forward(self, x, d, ref_features):
        """
        Forward pass for a batch of points.
        x: (N, 3) spatial coordinates
        d: (N, 3) viewing directions
        ref_features: (N, 64) projected reference features
        Returns: sigma (N,), color (N, 3)
        """
        # 1. Triplane Features
        f_tri = self.get_triplane_features(x)
        
        # 2. Density Field
        pe_x = self.positional_encoding(x)
        density_input = torch.cat([pe_x, ref_features], dim=-1)
        density_out = self.density_mlp(density_input)
        sigma = density_out[:, :1]
        f_m = density_out[:, 1:]
        
        # 3. Color Prediction
        f_base = self.color_mlp(torch.cat([f_tri, f_m], dim=-1))
        sh_d = self.spherical_harmonics(d)
        color = self.color_mlp(torch.cat([f_base, sh_d], dim=-1))
        
        return sigma, color

    def render(self, rays, ref_features):
        """
        Render a batch of rays.
        rays: (B, N_samples, 3) sampled points along rays
        ref_features: (B, N_samples, 64)
        Returns: color (B, 3)
        """
        sigma, color = self.forward(rays, rays[:, :, 0], ref_features) # d is approx dir of ray start or sample
        
        # Volume Rendering
        # [G] Standard implementation of differentiable volume rendering
        deltas = torch.diff(rays, dim=-2) # (B, N-1, 3)
        deltas = torch.cat([deltas, torch.zeros_like(deltas[:, :1])], dim=1)
        dists = torch.norm(deltas, dim=-1) # (B, N)
        
        alpha = 1.0 - torch.exp(-torch.relu(sigma) * dists)
        T = torch.cumprod(1.0 - alpha + 1e-10, dim=-1)
        weights = alpha * T[:, :-1] # (B, N-1)
        
        # [G] Accumulate color
        # Assuming rays has N samples, weights might be N-1 if deltas is N-1
        # Adjust indices as necessary for exact implementation
        rendered_color = torch.sum(weights.unsqueeze(-1) * color[:, :-1], dim=1)
        return rendered_color
```

**Edge Cases and Pitfalls:**
*   **Overfitting with Sparse Views:** Standard triplane representations rely on dense input views and suffer from redundancy or inaccurate geometry modeling with sparse inputs [S1]. NeRF tends to overfit input views when trained with fewer images, degrading synthesized images [S1].
*   **IBR Integration Pitfall:** Integrating IBR features directly into the triplane branch causes overfitting because frozen encoder features are constant, and triplane features maintain a one-to-one correspondence with reference image features via projection, preventing updates [S1].
*   **Geometry Extrapolation:** Unlike 3DGS methods that require monocular depth priors or complex regularization, TriDF uses sparse point clouds for depth supervision without additional priors, avoiding boundary distortions caused by 3DGS's explicit point cloud representation which fails to extrapolate to empty regions [S1].

## Operating characteristics
*   **Time Complexity:** Training time is ~5 minutes for 10k iterations (TriDF-10k) and 14 minutes for full training on a single consumer GPU (Nvidia GeForce RTX 4090) [S1]. This is 30× faster than NeRF-based methods [S1].
*   **Memory Complexity:** Model size is 25.6 MB for the full TriDF model [S1].
*   **Performance:** On the LEVIRNVS dataset, TriDF achieves a 7.4% increase in PSNR and 3.4% increase in SSIM compared to advanced few-shot methods (e.g., FSGS, CoR-GS) [S1].
*   **Strengths:** Fast convergence due to direct optimization of explicit triplane features; effective few-shot synthesis without large-scale pretraining priors; robust geometry reconstruction via depth-guided optimization [S1].
*   **Limitations:** Rendering speed lags behind 3DGS-based methods designed for real-time rendering [S1]; relies on initial point cloud generation via SfM/PMS [S1].
*   **When to Use:** Remote sensing novel view synthesis with sparse input views (e.g., 3 images) where training speed and high fidelity are required [S1].
*   **When Not to Use:** Dense-view scenarios where triplanes may suffer from redundancy; real-time rendering applications requiring faster inference than NeRF-based methods [S1].

## Background
TriDF was proposed in 2025 by researchers publishing in IEEE Transactions on Geoscience and Remote Sensing [S1]. It addresses the limitations of existing NeRF-based methods in remote sensing, where data acquisition constraints often result in sparse viewpoints (e.g., satellite or aerial imagery) [S1]. Traditional few-shot NVS methods rely on extensive pretraining on large multi-view datasets (e.g., PixelNeRF, IBRNet), which are impractical for remote sensing [S1]. TriDF decouples color and volume density to reduce computational burden, combining explicit triplanes for color and implicit density fields for geometry, guided by sparse point clouds for depth supervision [S1].
