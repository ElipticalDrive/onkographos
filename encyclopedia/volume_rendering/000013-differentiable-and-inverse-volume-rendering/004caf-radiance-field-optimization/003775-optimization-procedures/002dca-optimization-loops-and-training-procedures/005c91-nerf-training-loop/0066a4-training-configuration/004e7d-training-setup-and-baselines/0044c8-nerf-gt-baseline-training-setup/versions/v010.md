# NeRF-GT Baseline Training Setup
Also called: NeRF-GT, HDR-NeRF Baseline, Ground Truth HDR Training

## Overview
NeRF-GT is a training configuration for Neural Radiance Fields (NeRF) that uses High Dynamic Range (HDR) views as ground truth inputs to establish an upper-bound performance reference [S1]. It differs from standard NeRF setups by explicitly handling the high dynamic range of scene illumination, serving as a baseline to evaluate methods that synthesize HDR from Low Dynamic Range (LDR) inputs [S1]. Unlike [NeRF Training Setup](13271-nerf-training-setup.md) which typically assumes LDR consistency, NeRF-GT addresses the difficulty of encoding full scene detail across extreme lighting variations [S1].

## How it works
**Inputs and Outputs:**
- **Input:** HDR views of the scene (rendered from 3D models or captured via exposure bracketing) [S1].
- **Output:** A trained NeRF model capable of rendering HDR views [S1].

**Data Structures:**
- **NeRF Model:** Standard MLP-based radiance field representation [S1].
- **Training Data:** Pairs of predicted HDR pixels and ground truth LDR pixels (after tone-mapping) [S1].

**Steps:**
1. **Training:** Train the NeRF model using HDR views as the target supervision signal [S1].
2. **Tone-Mapping Prediction:** During training, for each rendered pixel, apply a tone-mapping operator to the predicted HDR pixel values to convert them into LDR values [S1].
3. **Loss Computation:** Apply the same tone-mapping operator to the ground truth LDR views. Compute the loss (typically Mean Squared Error) between the tone-mapped predicted LDR values and the tone-mapped ground truth LDR values [S1].

**Pitfalls:**
- Training directly on HDR views can fail to encode all areas of a scene well due to the high dynamic range, even when using tone-mapped colors for loss calculation [S1]. This is because the high dynamic range makes it difficult for the network to balance the representation of both bright and dark regions simultaneously [S1].

**Pseudocode:**
```python
# Pseudocode for NeRF-GT training step
def train_step(neural_field, camera_params, gt_ldr_images, tone_mapper):
    # 1. Render HDR prediction
    # Render the scene using the current neural field and camera parameters
    # This produces raw HDR pixel values
    pred_hdr_images = render(neural_field, camera_params)
    
    # 2. Tone-map predictions to LDR
    # Apply tone-mapping to convert HDR predictions to LDR for comparison
    pred_ldr_images = tone_mapper(pred_hdr_images)
    
    # 3. Tone-map ground truth
    # The ground truth provided is already LDR, but ensure consistent tone-mapping
    # if the GT was stored as HDR or if multiple tone-mapping passes are needed.
    # In the baseline, GT is often assumed to be the target LDR view.
    # If GT is stored as HDR, apply tone_mapper to it.
    # Assuming gt_ldr_images are the target LDR views:
    gt_ldr_images = gt_ldr_images 
    
    # 4. Compute Loss
    # Compare tone-mapped prediction with tone-mapped ground truth
    loss = mean_squared_error(pred_ldr_images, gt_ldr_images)
    
    # 5. Backpropagate
    gradients = compute_gradients(loss, neural_field)
    update_weights(neural_field, gradients)
    
    return loss
```

## Subtopics

### NeRF Baseline
The standard NeRF baseline typically uses LDR views with consistent exposure as input [S1]. It serves as the primary comparison point for NeRF-GT, highlighting the challenges of HDR synthesis. While NeRF-GT uses HDR inputs to set an upper bound, the NeRF Baseline demonstrates the limitations of LDR-only training in high dynamic range scenarios [S1].

## Operating characteristics
- **Time Complexity:** Training time is approximately 0.40 seconds per iteration [S2, unofficial].
- **Memory Complexity:** Not given in the sources.
- **Performance:** Rendering time is approximately 32 seconds per frame [S2, unofficial].
- **Scalability:** The method is computationally intensive due to the need for high sample counts (64 coarse, 128 fine) and large batch sizes (2,048 rays) to handle the dynamic range [S2, unofficial].
- **Strengths:** Provides an upper-bound reference for HDR synthesis methods [S1].
- **Limitations:** Difficult to encode all scene areas well due to high dynamic range [S1].

## Background
The NeRF-GT baseline was introduced in the context of HDR-NeRF, where the authors collected a new dataset of HDR views rendered from 3D models using Blender's Cycles path-tracer [S1]. The setup was designed to evaluate the feasibility of training NeRF directly on HDR data, serving as a ground truth comparison for methods that aim to synthesize HDR from LDR inputs [S1]. The performance metrics (0.40 sec/iteration, 32 sec/frame) were reported in a comparative study of neural rendering methods [S2, unofficial].
