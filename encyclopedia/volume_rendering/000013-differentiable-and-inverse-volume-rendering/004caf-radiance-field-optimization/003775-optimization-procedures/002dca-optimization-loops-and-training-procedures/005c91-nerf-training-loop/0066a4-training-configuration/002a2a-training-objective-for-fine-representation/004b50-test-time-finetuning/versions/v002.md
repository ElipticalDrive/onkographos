# Test-Time Finetuning

Also called: Code Finetuning, Guidance-Finetuning

## Overview
Test-Time Finetuning is a post-sampling optimization step that refines the sampled scene code by minimizing a combined loss of rendering fidelity and a diffusion prior, while keeping the diffusion model and decoder parameters frozen [S1]. It addresses the limitation where reconstruction guidance alone cannot strictly enforce rendering constraints towards faithful reconstruction, distinguishing it from two-stage methods that ignore the prior term during initial training, which results in biased and noisy scene codes [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A sampled scene code $x$ initialized from the sampling process (e.g., DDIM steps) [S1].
*   **Output:** An optimized scene code $x$ that balances rendering accuracy and diffusion prior consistency [S1].

**Data Structures:**
*   **Scene Code ($x$):** The latent representation of the scene being optimized. Its specific layout depends on the underlying radiance field representation (e.g., triplane, voxel grid) but is treated as a differentiable tensor during this phase [S1].
*   **Frozen Parameters:** The diffusion model parameters $\phi$ and decoder parameters $\psi$ are held constant [S1].

**Parameters:**
*   $\lambda_{\text{rend}}$: Weight for the rendering loss.
*   $\lambda'_{\text{diff}}$: Test-time prior weight. This value should be lower than the training weight $\lambda_{\text{diff}}$ because the prior learned from the training dataset is less reliable when transferred to a different testing dataset [S1].
*   **Optimizer:** Adam [S1].

**Formulas:**
The optimization problem is defined as [S1]:
$$
\min_x \lambda_{\text{rend}} \mathcal{L}_{\text{rend}}(x) + \lambda'_{\text{diff}} \mathcal{L}_{\text{diff}}(x)
$$
Where:
*   $\mathcal{L}_{\text{rend}}(x)$ is the rendering loss measuring the difference between rendered images and ground truth.
*   $\mathcal{L}_{\text{diff}}(x)$ is the diffusion prior loss.

**Steps:**
1.  Initialize the scene code $x$ from the sampling process [S1].
2.  Compute the gradient of the rendering loss with respect to $x$: $\nabla_x \lambda_{\text{rend}} \mathcal{L}_{\text{rend}}(x)$ [S1].
3.  Compute the gradient of the diffusion loss with respect to $x$: $\nabla_x \lambda'_{\text{diff}} \mathcal{L}_{\text{diff}}(x)$ [S1].
4.  Sum the gradients to obtain the total gradient $g_x$ [S1].
5.  Update $x$ using the Adam optimizer with the total gradient $g_x$ [S1].
6.  Repeat steps 2-5 until convergence or a fixed number of iterations [S1].

**Pseudocode:**
```python
def test_time_finetuning(scene_code_x, ground_truth_images, diffusion_model, decoder, 
                         lambda_rend, lambda_diff_prime, num_iterations, optimizer_config):
    """
    Finetunes the scene code x by minimizing rendering and diffusion losses.
    Diffusion model and decoder parameters are frozen.
    """
    # Ensure gradients are tracked for x
    scene_code_x.requires_grad = True
    
    # Initialize optimizer for x only
    optimizer = Adam([scene_code_x], **optimizer_config)
    
    for i in range(num_iterations):
        optimizer.zero_grad()
        
        # 1. Compute Rendering Loss
        # Render images from the current scene code x using the frozen decoder
        rendered_images = decoder(scene_code_x)
        loss_rend = compute_rendering_loss(rendered_images, ground_truth_images)
        
        # 2. Compute Diffusion Prior Loss
        # Compute the diffusion loss based on the scene code x
        # This typically involves passing x through the frozen diffusion model
        loss_diff = compute_diffusion_loss(scene_code_x, diffusion_model)
        
        # 3. Combine Losses
        total_loss = lambda_rend * loss_rend + lambda_diff_prime * loss_diff
        
        # 4. Backpropagate
        total_loss.backward()
        
        # 5. Update x
        optimizer.step()
        
    return scene_code_x
```

**Edge Cases and Pitfalls:**
*   **Prior Reliability:** Using the training-time prior weight $\lambda_{\text{diff}}$ at test time can lead to suboptimal results because the prior is less reliable for unseen datasets [S1]. The test-time weight $\lambda'_{\text{diff}}$ must be reduced [S1].
*   **Frozen Parameters:** It is critical that the diffusion model and decoder parameters remain frozen; updating them would constitute training, not finetuning [S1].

## Subtopics

## Operating characteristics
*   **Time Complexity:** Depends on the number of iterations and the cost of rendering and diffusion loss computation per iteration.
*   **Memory Complexity:** Requires memory for the scene code gradients and intermediate activations during the backward pass of both losses.
*   **Strengths:** Enforces faithful reconstruction by combining explicit rendering constraints with implicit diffusion priors [S1].
*   **Limitations:** Requires additional optimization steps after sampling, increasing inference time compared to direct decoding [S1].
*   **When to use:** When high-fidelity reconstruction is required and the initial sampled code is noisy or biased [S1].
*   **When not to use:** When computational resources are limited or real-time inference is required [S1].

## Background
Test-Time Finetuning is introduced in the context of Single-Stage Diffusion NeRF, a unified approach to 3D generation and reconstruction [S1]. It was developed to address issues in previous two-stage methods where the prior term was ignored during the initial training of auto-decoders, leading to biased and noisy scene codes [S1]. The method leverages the training objective to finetune the sampled scene code while keeping model parameters frozen [S1].
