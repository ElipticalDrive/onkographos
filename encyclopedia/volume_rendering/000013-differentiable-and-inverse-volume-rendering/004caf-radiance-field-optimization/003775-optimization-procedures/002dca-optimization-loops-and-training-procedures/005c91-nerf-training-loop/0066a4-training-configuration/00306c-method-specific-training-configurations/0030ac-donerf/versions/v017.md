# DONeRF

Also called: Depth Oracle Neural Radiance Fields, DONeRF Training Configuration, DONeRF training setup, Depth Oracle Network, DoNeRF

## Overview
DONeRF is a training configuration for neural radiance fields that replaces the standard dense raymarching of NeRF with a two-network architecture: a **depth oracle network** to predict sample locations and a **shading network** to predict color and density for those selected samples [S1, S3]. It solves the prohibitive computational cost of NeRF by reducing the number of samples per ray from hundreds to a small constant (e.g., 2–16), enabling real-time rendering on consumer GPUs [S3]. It sets itself apart from standard NeRF by explicitly decoupling geometry estimation (oracle) from appearance rendering (shading), and from other acceleration methods like NSVF by requiring no explicit caching or acceleration structures [S3].

## How it works
DONeRF operates in a two-stage training pipeline. First, the depth oracle network is trained to predict sample locations. Second, the shading network is trained using the samples provided by the oracle. The method relies on "view cells" to unify ray descriptions and uses a classification-based oracle rather than direct depth regression [S3].

### Inputs and Outputs
*   **Inputs:** RGBD images (color and depth) sampled from a view cell. A view cell is a bounding box with a primary orientation and maximum viewing angle, capturing rays that originate within the box and stay within rotation limits [S3].
*   **Outputs:** Rendered RGB images $\hat{C}(\mathbf{r})$ for novel views [S3].

### Data Structures and Network Architectures
Both networks are Multi-Layer Perceptrons (MLPs) with 8 hidden layers and 256 hidden units each [S3].

1.  **Depth Oracle Network:**
    *   **Input:** Concatenated 3D position $\mathbf{x} \in \mathbb{R}^3$ and view direction $\mathbf{d} \in S^2$.
    *   **Encoding:** No positional encoding is applied to inputs [S1].
    *   **Architecture:** 8-layer MLP with ReLU activations, except for the last output layer [S1].
    *   **Output:** Depth value (or classification logits for discretized depth bins) [S1, S3].

2.  **Shading Network:**
    *   **Input:** 3D position $\mathbf{x}$ and view direction $\mathbf{d}$ at the sample locations selected by the oracle.
    *   **Encoding:** Positional encoding [65] is applied to obtain $\gamma(\mathbf{x})$ (63-dimensional) and $\gamma(\mathbf{d})$ (27-dimensional) [S1].
    *   **Architecture:** Same 8-layer MLP structure as the oracle, with modifications:
        *   $\gamma(\mathbf{x})$ is used at the first layer.
        *   $\gamma(\mathbf{d})$ is concatenated to the feature vector before the last layer [S1].
    *   **Output:** RGB color $\mathbf{c} \in \mathbb{R}^3$ and volume density $\sigma \in \mathbb{R}^+$ [S1].

### Numbered Steps

1.  **Ray Unification:** Transform view rays into a unified space defined by the view cell. This reduces input ambiguity and allows the network to generalize across the cell [S3].
2.  **Non-linear Depth Transformation:** Transform depth values into a non-linear space (e.g., logarithmic) to handle large, open scenes and focus sampling on closer regions [S3].
3.  **Oracle Training (Stage 1):**
    *   The oracle network learns a classification task using filtered, discretized target depth values rather than direct depth regression [S3].
    *   Input: $\mathbf{x}$ and $\mathbf{d}$ (unified).
    *   Loss: Binary Cross-Entropy (BCE) loss on the depth classification [S3].
    *   Train for 300,000 iterations [S3].
4.  **Sample Selection:** The oracle predicts $N_s$ sample locations along the ray. These locations are typically warped towards the view cell to direct high-frequency predictions of the shading network to the foreground [S3].
5.  **Shading Training (Stage 2):**
    *   The shading network takes the $N_s$ samples from the oracle.
    *   Volume rendering is performed using these few samples.
    *   Loss: Weighted sum of Mean Squared Error (MSE) for RGB and an Opacity Loss [S3].
    *   Train for 300,000 iterations [S3].

### Formulas

**Volume Rendering:**
The accumulated color is computed using the standard differentiable volume rendering integral [Parent]:
$$ \hat{C}(\mathbf{r}) = \sum_{i=1}^{N_s} T_i \alpha_i \mathbf{c}_i $$
where $N_s$ is the number of samples selected by the oracle (e.g., 4, 8, 16), $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$, $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$, $\sigma_i$ is density, $\mathbf{c}_i$ is color, and $\delta_i$ is the distance between samples [Parent, S3].

**Opacity Loss ($\text{loss}_O$):**
To prevent dark pixel artifacts caused by low sample counts failing to accumulate to full opacity for opaque surfaces, an opacity loss is added [S3]:
$$ \text{loss}_O = \begin{cases} 0, & \text{if } \sum_{i=1}^{N_s} \delta_i \geq 1 \\ \left( \left( \sum_{i=1}^{N_s} \delta_i \right) - 1 \right)^2, & \text{otherwise} \end{cases} $$
where $N_s$ is the number of samples per ray [S3].

**Total Loss:**
$$ \text{loss} = \alpha \cdot \text{loss}_{\text{MSE}} + \beta \cdot \text{loss}_O $$
Typical values: $\alpha = 1.0$, $\beta = 10.0$ [S3].

### Parameters
*   **Network Size:** 8 hidden layers, 256 hidden units per layer for both networks [S3].
*   **Samples per Ray ($N_s$):** Typically 2, 4, 8, or 16. DONeRF-4 is a common configuration [S3].
*   **Optimizer:** Adam [KB15] with learning rate $5 \times 10^{-4}$ and batch size 4096 samples per iteration [S3].
*   **Training Iterations:** 300,000 iterations for the oracle, followed by 300,000 iterations for the shading network [S3].
*   **View Cell Parameters:** K-5, Z-5, I-128 (specific parameters for the view cell definition and input dimensions) [S3].
*   **Resolution:** Images are typically downsampled to 400×400 pixels for training [S1, S3].

### Edge Cases and Pitfalls
*   **Dark Pixel Artifacts:** At low sample counts, rays may not accumulate to opacity 1 for opaque surfaces, causing darkening. This is remedied by the opacity loss term [S3].
*   **Cheating via Opacity:** Shading networks with low sample counts may "cheat" by relying on opacity outputs to mix background color into the accumulation. The opacity loss mitigates this [S3].
*   **Reflective/Transparent Surfaces:** Low sample counts and single depth estimates are insufficient for perfect replication of view-dependent phenomena like mirrors or refractive water [S3].
*   **No Ground Truth Depth:** If ground truth depth is unavailable, a dense NeRF (12 layers, 512 hidden units, 128 samples/ray) is trained first to extract depth maps, which are then used as ground truth for the oracle. This results in a ~1 dB PSNR drop compared to using real depth [S3].
*   **Background Noise:** In no-GT training, NeRF may output high-frequency depth values in the background, creating zero-contribution samples. Background detection during oracle training is suggested as a remedy [S3].
*   **Non-End-to-End:** The architecture is not end-to-end trainable and struggles without high-quality depth supervision [S2].

### Pseudocode

```python
# DONeRF Training Configuration
# Stage 1: Train Depth Oracle Network
def train_depth_oracle(dataset, view_cell, iterations=300000):
    oracle = MLP(layers=8, units=256, activation='ReLU')
    optimizer = Adam(oracle.parameters(), lr=0.0005)
    
    for iteration in range(iterations):
        # Sample batch of rays from view cell
        rays = dataset.sample_batch(batch_size=4096)
        
        # Unify rays and transform depth non-linearly
        unified_rays = unify_rays(rays, view_cell)
        x, d = unified_rays.position, unified_rays.direction
        target_depth = transform_depth_nonlinear(unified_rays.depth)
        
        # Oracle predicts depth classification
        # Input: x, d (no positional encoding)
        oracle_output = oracle(concatenate(x, d))
        
        # Loss: BCE for depth classification
        loss = binary_cross_entropy(oracle_output, target_depth)
        
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
    return oracle

# Stage 2: Train Shading Network
def train_shading_network(dataset, view_cell, oracle, iterations=300000, Ns=4):
    shading_net = MLP(layers=8, units=256, activation='ReLU')
    optimizer = Adam(shading_net.parameters(), lr=0.0005)
    
    for iteration in range(iterations):
        rays = dataset.sample_batch(batch_size=4096)
        unified_rays = unify_rays(rays, view_cell)
        x, d = unified_rays.position, unified_rays.direction
        
        # Oracle selects Ns sample locations
        # Input: x, d (no positional encoding)
        sample_indices = oracle.select_samples(unite(x, d), Ns=Ns)
        
        # Warp samples towards view cell
        warped_samples = warp_samples(sample_indices, view_cell)
        
        # Shading network predicts color and density at warped samples
        # Input: warped_samples, d
        # Encoding: gamma(x) at first layer, gamma(d) concatenated before last layer
        gamma_x = positional_encoding(warped_samples, L=6) # 63-dim
        gamma_d = positional_encoding(d, L=6) # 27-dim
        
        color, density = shading_net(warped_samples, gamma_x, gamma_d)
        
        # Volume rendering with Ns samples
        # Compute transmittance and opacity
        deltas = compute_sample_distances(warped_samples)
        alphas = 1.0 - exp(-density * deltas)
        transmittances = compute_transmittance(alphas, deltas)
        
        rendered_color = sum(transmittances * alphas * color)
        accumulated_opacity = sum(transmittances * alphas)
        
        # Loss: MSE for color + Opacity Loss
        loss_mse = mean_squared_error(rendered_color, rays.color)
        
        # Opacity loss: force accumulated opacity >= 1
        if accumulated_opacity < 1.0:
            loss_opacity = (accumulated_opacity - 1.0)**2
        else:
            loss_opacity = 0.0
            
        loss = 1.0 * loss_mse + 10.0 * loss_opacity
        
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
    return shading_net
```

## Operating characteristics
*   **Time Complexity:** DONeRF requires approximately 4.35 MFLOP per pixel [S3]. Inference costs are reduced by up to 48x compared to NeRF when conditioning on available ground truth depth [S3].
*   **Memory Complexity:** Compact; requires only the storage for two MLPs (approx. 4 MB), with no additional memory for explicit caching or acceleration structures [S3].
*   **Measured Performance:** On an NVIDIA RTX 3090 at 800x800 resolution with 2 samples/ray, DONeRF renders in 51.3 ms (~20 fps) [S3]. At 400x400, it renders at 22 ms per frame [S3].
*   **Scaling:** Shading network cost scales nearly linearly with the number of samples: 34.9 ms (2 samples), 65.4 ms (4 samples), 136.4 ms (8 samples), 270.4 ms (16 samples) [S3].
*   **Strengths:** Real-time rendering capability, high quality (avg PSNR 31.14 dB vs NeRF's 30.52 dB), compact memory footprint, no need for acceleration structures [S3].
*   **Limitations:** Not end-to-end trainable, struggles without high-quality depth supervision, poor performance on reflective/transparent surfaces, dark pixel artifacts at low sample counts without opacity loss [S2, S3].
*   **When to use:** Real-time rendering of synthetic content (games, VR) where ground truth depth is available or can be approximated.
*   **When not to use:** Scenes with significant transparency/reflection, or when end-to-end training is required.

## Background
DONeRF was introduced by [S3] to bring compact neural representations closer to practical real-time rendering applications like games and VR. It addresses the prohibitive computational cost of NeRF, which requires dozens of petaFLOPS. The method was developed at Graz University of Technology and Facebook Reality Labs [S3]. It builds on the concept of depth oracles [S2] and improves upon them by using a classification-based oracle and warping samples to a unified view cell space [S3].
