# LoRA Fine-Tuning of DINO

Also called: LoRA-NeRF, NeRF with LoRA-fine-tuned DINO features

## Overview
This method adapts frozen DINO vision features to the geometric objectives of NeRF by applying Low-Rank Adaptation (LoRA) to the attention layers of the DINO Vision Transformer (ViT) backbone [S1, unofficial]. It solves the misalignment between semantic features and geometric reconstruction by making only low-rank matrices trainable while keeping pre-trained weights frozen [S1, unofficial]. It sets itself apart from [DINO-enhanced NeRF](15497-dino-enhanced-nerf.md) frozen variants by actively tuning the feature extractor for the specific few-shot 3D reconstruction task [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Pre-trained DINOv2-base model weights $W_0$, training images, and camera poses.
*   **Output:** Fine-tuned DINO features $f'(x)$ used as input to the NeRF MLP, concatenated with positional encodings $\gamma(\mathbf{x})$ and view direction encodings $\gamma(\mathbf{d})$ [S1, unofficial].

**Data Structures:**
*   **LoRA Matrices:** Two trainable matrices per attention layer:
    *   $A \in \mathbb{R}^{r \times d}$
    *   $B \in \mathbb{R}^{d \times r}$
    *   Where $d$ is the hidden dimension of the ViT attention layer and $r$ is the LoRA rank [S1, unofficial].
*   **Feature Projection:** DINO features (768-dimensional) are projected to 256 dimensions before fusion with NeRF’s positional encoding [S1, unofficial].

**Numbered Steps:**
1.  **Initialize:** Load the pre-trained DINOv2-base model. Freeze all original weights $W_0$ [S1, unofficial].
2.  **Inject LoRA:** For each attention layer in the ViT, replace the weight matrix $W$ with the sum of the frozen weights and the low-rank adaptation:
    $$W = W_0 + BA$$
    where $W_0$ are the frozen pre-trained weights, and $A$ and $B$ are initialized randomly (standard practice for LoRA, [G]) and trained [S1, unofficial].
3.  **Set Rank:** Configure the LoRA rank $r = 16$ for all experiments [S1, unofficial].
4.  **Feature Extraction:** Compute DINO features for input images. Since LoRA is applied, these features are now "fine-tuned" ($f'(x)$) rather than frozen [S1, unofficial].
5.  **Cache Features:** Compute and cache DINO features once for efficiency during training [S1, unofficial].
6.  **NeRF Input Construction:** For each ray, construct the input vector by concatenating:
    *   Positional encoding of 3D point $\gamma(\mathbf{x})$ (10 frequency bands) [S1, unofficial].
    *   View direction encoding $\gamma(\mathbf{d})$ (4 frequency bands) [S1, unofficial].
    *   Fine-tuned DINO feature $f'(x)$ (projected to 256 dims) [S1, unofficial].
7.  **NeRF Forward Pass:** Feed the concatenated vector into the NeRF MLP (8 layers, skip connection at layer 4, 256 hidden units) to predict RGB color and volume density [S1, unofficial].
8.  **Optimization:** Update only the LoRA matrices $A$ and $B$ (and potentially the projection layer, [G]) using the Adam optimizer with cosine learning rate annealing [S1, unofficial].

**Parameters:**
*   LoRA rank $r$: 16 [S1, unofficial].
*   Feature dimension projection: 768 to 256 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Mixed-precision training is used to accelerate experiments [S1, unofficial].
*   **Hardware:** Experiments reported using Apple Silicon MPS backend [S1, unofficial].
*   **Degenerate Input:** Not specified.

## Subtopics

### LoRA Fine-Tuning
A technique that fine-tunes the diffusion model with minimal computational overhead, making it adaptable to new tasks by modifying a few parameters within the model [S2]. This definition is from a general survey on 3D editing and does not specify the NeRF/DINO context, but describes the general LoRA mechanism [S2].

## Operating characteristics
*   **Time Complexity:** Training takes 2-4 hours per experiment, depending on model complexity [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** On the Lego dataset (5 training views, 200 test views), LoRA-NeRF achieves a PSNR of 12.97, SSIM of 0.45, and LPIPS of 0.54 [S1, unofficial].
*   **Scaling:** Not given in the sources.
*   **Strengths:** Parameter-efficient fine-tuning; preserves prior knowledge from pre-trained weights; adapts features to geometric objectives [S1, unofficial].
*   **Limitations:** All DINO variants (including LoRA) perform worse than the baseline NeRF (PSNR 14.71), with a degradation of approximately 1.7 PSNR points [S1, unofficial].
*   **When to use:** When semantic richness of DINO features is needed but frozen features do not align well with NeRF’s geometric objectives [S1, unofficial].
*   **When not:** When baseline NeRF performance is sufficient or when computational resources for fine-tuning are extremely limited (though LoRA is efficient, it still requires gradient computation) [S1, unofficial].

## Background
The method is described in "Limitations of NERF with pre-trained Vision Features for Few-Shot 3D Reconstruction" [S1, unofficial]. It builds on the observation that frozen DINO features, while semantically rich, may not align well with NeRF’s geometric objectives [S1, unofficial]. LoRA [10] is used for parameter-efficient fine-tuning [S1, unofficial]. The implementation is based on PyTorch and uses the DINOv2-base model [S1, unofficial].
