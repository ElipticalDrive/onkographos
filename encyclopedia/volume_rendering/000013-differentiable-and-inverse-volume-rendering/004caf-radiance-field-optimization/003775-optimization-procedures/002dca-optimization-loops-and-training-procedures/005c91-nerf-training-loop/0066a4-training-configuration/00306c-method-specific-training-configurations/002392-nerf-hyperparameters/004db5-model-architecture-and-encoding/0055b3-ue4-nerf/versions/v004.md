# UE4-NeRF


## Overview
UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale 3D scenes by partitioning the environment into sub-NeRFs represented as textured polygonal meshes and integrating them into the Unreal Engine 4 (UE4) rasterization pipeline [S1]. Unlike standard differentiable volume rendering methods that rely on ray marching through dense grids, UE4-NeRF replaces the volumetric representation with optimized geometric meshes and a neural shader, enabling real-time frame rates (up to 43 FPS at 4K) while maintaining high fidelity [S1]. It distinguishes itself from sibling methods like Mobile-NeRF and Mega-NeRF by using regular octahedra to handle tilted surfaces and storing opacity in texture maps to support semi-transparent objects, thereby overcoming convergence instability and material limitations [S1].

## How it works
UE4-NeRF operates by dividing a large-scale scene into overlapping blocks, training a separate neural model for each block to generate optimized polygonal meshes with embedded feature textures, and rendering these meshes in UE4 using a fragment shader [S1].

### Inputs and Outputs
*   **Inputs:** A set of posed images (typically from drones) with GPS coordinates; camera intrinsics and extrinsics.
*   **Outputs:** Textured polygonal meshes (LOD hierarchy) and a neural shader (HLSL) for real-time rendering in UE4.

### Data Structures
1.  **Scene Partitioning:** The scene is divided into blocks. Each training block is slightly larger than the corresponding physical area to create overlapping borders for smooth transitions [S1].
2.  **Grid Initialization:** A $128 \times 128 \times 128$ grid is initialized for each block [S1].
3.  **Mesh Representation:**
    *   Vertices are selected from the center point of each grid cell and its six neighbors (front, back, left, right, top, bottom) [S1].
    *   Faces are formed using regular octahedra. Each octahedron has 20 faces: 8 exterior and 12 interior [S1].
    *   Vertex positions are optimized during training [S1].
4.  **Texture Atlas:** Stores feature vectors and opacity information for each mesh [S1].
5.  **Neural Shader (HLSL):** A fragment shader implementing the Encoder-Decoder MLP [S1].

### Network Architecture
The method uses an Encoder-Decoder MLP structure [S1]:

*   **Encoder Network ($E$):**
    *   Input: Positional information $\mathbf{p}_i$ encoded via multi-resolution hash encoding (from Instant-NGP) [S1].
    *   Structure: 4-layer MLP with dimensions $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
    *   Output: Opacity $\alpha_i$ and an 8-dimensional feature vector $\mathbf{M}_i$ [S1].
    *   Formula:
        $$ E(\text{hash}(\mathbf{p}_i); \theta_E) \rightarrow \mathbf{M}_i, \alpha_i $$
*   **Decoder Network ($D$):**
    *   Input: Feature vector $\mathbf{M}_i$ and spherical harmonics coefficients $\text{SH}(\mathbf{d}_i)$ of the viewing direction $\mathbf{d}_i$ [S1].
    *   Structure: 3-layer MLP with dimensions $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
    *   Output: Final color $\mathbf{c}_i$ [S1].
    *   Formula:
        $$ D(\mathbf{M}_i, \text{SH}(\mathbf{d}_i); \theta_D) \rightarrow \mathbf{c}_i $$

### Training Procedure
1.  **Coordinate Transformation:** Transform GPS-captured imagery into the UE4 coordinate system. The X-axis points east, Y-axis points south, and Z-axis points up. Apply a 100:1 scale conversion (UE4 units to real-world units) [S1].
2.  **Coarse Model Training:** Train a coarse model for sub-region segmentation to capture overall terrain and building outlines. Filter images associated with sub-regions and use a mask to exclude pixels outside the scene area [S1].
3.  **Block Partitioning:** Partition the large scene into multiple blocks. Ensure overlapping borders between neighboring blocks [S1].
4.  **Mesh Initialization:** Initialize the $128 \times 128 \times 128$ grid. Select center points and six neighbors to create polygonal meshes based on regular octahedra (20 faces) [S1].
5.  **Joint Optimization:**
    *   For each ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ emitted from the camera origin, calculate the intersection with the polygonal meshes [S1].
    *   The intersection point serves as the sampling point [S1].
    *   Optimize the parameters of the Encoder-Decoder network ($\theta_E, \theta_D$) and the vertex positions of the meshes simultaneously [S1].
    *   Use multi-resolution hash encoding for acceleration [S1].
    *   Implement computationally intensive portions using CUDA [S1].
6.  **Convergence:** Train for 80,000 epochs per block to achieve convergence [S1].

### Rendering Procedure
1.  **LOD Selection:** Train meshes with varying levels of detail (LOD) for different observation heights. Coarser meshes are used for higher observation heights to ensure real-time performance [S1].
2.  **Mesh Extraction:** Extract pre-rendered polygonal meshes at different LODs [S1].
3.  **Shader Execution:** In UE4, the rasterization pipeline renders the meshes. The HLSL fragment shader takes the feature vectors from the texture atlas and outputs colors using the Decoder network [S1].
4.  **Occlusion Handling:** When traditional 3D models (e.g., .obj, .fbx) are imported, UE4 handles occlusion automatically, skipping neural shader computation for occluded regions [S1].

### Parameters
*   **Grid Size:** $128 \times 128 \times 128$ [S1].
*   **Octahedron Faces:** 20 total (8 exterior, 12 interior) [S1].
*   **Encoder MLP:** 4 layers, sizes $32 \to 64 \to 64 \to 64 \to 8$ [S1].
*   **Decoder MLP:** 3 layers, sizes $17 \to 16 \to 16 \to 3$ [S1].
*   **Training Hardware:** 1 Nvidia RTX 3090 GPU [S1].
*   **Training Iterations:** 80,000 epochs per block [S1].
*   **Coordinate System:** X=East, Y=South, Z=Up [S1].
*   **World Scale:** 100:1 [S1].

### Edge Cases and Pitfalls
*   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces. UE4-NeRF addresses this by using regular octahedra [S1].
*   **Semi-transparent Objects:** Mobile-NeRF cannot handle transparent/semi-transparent objects (water, glass) due to opacity binarization. UE4-NeRF stores opacity in texture maps to mitigate this [S1].
*   **Performance:** Semi-transparent objects (e.g., vegetation) increase computational overhead, reducing frame rates [S1].
*   **Rendering Gaps:** Pre-rendering cannot capture rays from all viewing angles, potentially resulting in gaps or holes in the final scene [S1].
*   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, causing evaluation metrics (PSNR/SSIM/LPIPS) to underestimate actual reconstruction quality [S1].
*   **Memory:** Rendering large scenes (square kilometers) incurs significant memory overhead, which increases with accuracy [S1].
*   **Hardware Dependency:** Requires CUDA and NVIDIA GPUs [S1].

## Operating characteristics
*   **Training Speed:** 1000× faster than Mobile-NeRF [S1].
    *   Time per block: ~40 minutes on 1×RTX 3090 [S1].
    *   Time for full scene (n blocks): $1 \text{ hour} + (40 \text{ minutes} \times n/4)$ on 1×RTX 3090 [S1].
    *   Comparison: Mobile-NeRF takes 48h/block (4×3090); Mega-NeRF takes 36h/block (1×3090) [S1].
*   **Rendering Performance:**
    *   Real-time rendering at 4K resolution with up to 43 FPS [S1].
    *   50 FPS on full scene at 2K resolution [S1].
    *   ≥70 FPS on individual blocks at 2K resolution [S1].
*   **Memory:** Significant memory overhead for large scenes; increases with accuracy [S1].
*   **Strengths:** Real-time performance, handles tilted surfaces, supports semi-transparent objects, enables scene editing in UE4 [S1].
*   **Limitations:** Requires NVIDIA GPUs/CUDA, potential gaps/holes from pre-rendering, exposure matching issues in UE4, semi-transparent objects reduce FPS [S1].
*   **When to use:** Large-scale outdoor scenes (farmland, construction sites, industrial parks) requiring real-time interactive rendering and scene editing [S1].
*   **When not to use:** Scenes requiring precise exposure matching with original images without post-processing, or on hardware lacking CUDA support [S1].

## Background
UE4-NeRF was introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" [S1]. It was developed to address the limitations of NeRF in real-time rendering of large-scale scenes, specifically targeting applications in virtual reality, computer games, and the Metaverse [S1]. The method combines NeRF with the Unreal Engine 4 rasterization pipeline, leveraging Level of Detail (LOD) techniques and multi-resolution hash encoding to achieve real-time performance [S1]. It is used for drone-captured large-scale scenes and evaluated on the Mega-NeRF public dataset [S1].
