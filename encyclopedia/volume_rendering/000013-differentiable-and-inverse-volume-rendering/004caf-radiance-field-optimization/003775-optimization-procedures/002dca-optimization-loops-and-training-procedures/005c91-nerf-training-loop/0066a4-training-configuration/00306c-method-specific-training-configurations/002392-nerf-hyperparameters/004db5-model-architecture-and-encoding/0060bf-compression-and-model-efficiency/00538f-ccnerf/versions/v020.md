# CCNeRF

Also called: Rank-residual Decomposition NeRF, CCNeRF

## Overview
CCNeRF is a neural field representation that enables efficient compression and composition of 3D scenes by learning a hybrid tensor rank decomposition of the scene without using neural networks for rendering [S1]. Unlike NeRF variants that rely on a shared MLP renderer (e.g., NSVF) or hybrid tensor-MLP approaches (e.g., TensoRF), CCNeRF models the radiance field *only* with tensor rank decomposition, preserving low-rank approximation properties to allow dynamic model size adjustment via rank truncation and arbitrary composition via rank concatenation [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D coordinate $\mathbf{x} = (x, y, z)$ and a viewing direction $\mathbf{d} = (\theta, \phi)$.
*   **Output:** Volume density $\sigma \in \mathbb{R}$ and color $\mathbf{c} \in \mathbb{R}^3$.

**Data Structures:**
The model consists of two main components [S1]:
1.  **Rank Weights Matrix ($W$):** A matrix storing weights for different feature channels. It maps the aggregated rank features to the final output dimensions.
2.  **Decomposed Rank Components:** A set of vectors or matrices representing the scene. These are categorized into:
    *   **Vector-based (CP):** Corresponds to CANDECOMP/PARAFAC decomposition.
    *   **Matrix-based (Triple Plane):** A less compact variant using factor matrices.
    *   The ratio of vector- to matrix-based components is controllable to trade off between model size and performance.

**Numbered Steps:**

1.  **Scene Representation (Training):**
    The 3D scene is modeled as a 4D feature volume. This volume is decomposed using a hybrid Tucker-like decomposition. For a 3D tensor $T \in \mathbb{R}^{H \times W \times D}$, the decomposition is defined as [S1]:
    $$ T_{i,j,k} = \sum_{p=1}^P \sum_{q=1}^Q \sum_{r=1}^R S_{p,q,r} U^x_{i,p} U^y_{j,q} U^z_{k,r} $$
    where $S$ is the core tensor and $U^x, U^y, U^z$ are factor matrices. CCNeRF uses a **rank-residual learning strategy** to encourage lower ranks to preserve more important information, ensuring that truncation retains primary scene details [S1].

2.  **Querying a 3D Coordinate:**
    To evaluate the field at $\mathbf{x}$ and $\mathbf{d}$:
    a. Project the coordinate $\mathbf{x}$ to the decomposed vectors or matrices.
    b. Perform weighted interpolation using the stored rank weights $W$ [S1].
    *Note: The specific projection and interpolation mechanics depend on whether the component is vector-based or matrix-based, but generally involve aggregating the contributions of the rank components.*

3.  **Rendering:**
    The output density $\sigma$ and color $\mathbf{c}$ are integrated along rays using the standard volume rendering equation [S1]:
    $$ \hat{C}(r) = \sum_i T_i \alpha_i c_i, \quad T_i = \prod_{j<i} (1 - \alpha_i), \quad \alpha_i = 1 - \exp(-\sigma_i \delta_i) $$
    where $\delta_i = t_{i+1} - t_i$ is the distance between samples, $t_i$ is the sample position along ray $r$ from origin $o$ with direction $d$, $\sigma_i$ is density, and $c_i$ is color.

4.  **Compression (Rank Truncation):**
    Model size is dynamically adjusted by truncating the rank components. An empirical **sort-and-truncate** strategy is used to achieve near-optimal low-rank approximation at any targeted rank [S1].
    *   **Process:** Ranks are sorted by importance (derived from the rank-residual learning weights), and less important ranks are removed.
    *   **Result:** This allows trade-offs between model size and rendering quality without retraining [S1].
    *   **Pitfall:** Standard truncated Higher-Order SVD (HOSVD) does not hold the optimal property of truncated SVD, but yields a quasi-optimal solution sufficient for practical use [S1].

5.  **Composition:**
    Different models are composed by concatenating their rank components along the rank dimension [S1].
    *   **Transformation:** A transformation matrix is recorded for each object to control its position and orientation in the scene.
    *   **Mechanism:** Since there are no MLP renderers, objects can be composed arbitrarily without compatibility constraints or retraining [S1].
    *   **Optimization:** The growth of storage cost in composed scenes can be mitigated by compressing unimportant objects via rank truncation [S1].

**Parameters:**
*   **Rank ($P, Q, R$):** The number of components kept in the decomposition determines the model size and detail level. Lower ranks preserve primary information due to rank-residual learning [S1].
*   **Vector/Matrix Ratio:** Controls the balance between the CP (vector-based) and Triple Plane (matrix-based) components [S1].

class CCNeRF:
    def __init__(self, rank_weights, rank_components, component_types):
        """
        Initialize CCNeRF model.
        
        Args:
            rank_weights (np.ndarray): Matrix W storing weights for feature channels.
            rank_components (list): List of rank components. 
                                    Each element is either a vector (CP) or matrix (Triple Plane).
            component_types (list): List of strings ('vec' or 'mat') corresponding to rank_components.
        """
        self.W = rank_weights
        self.components = rank_components
        self.types = component_types

    def query(self, x, d):
        """
        Query the radiance field at 3D coordinate x and direction d.
        
        Args:
            x (np.ndarray): 3D coordinate (x, y, z).
            d (np.ndarray): Viewing direction (theta, phi).

            c (np.ndarray): Color (r, g, b).
        """
        # Step 1: Project coordinate to decomposed vectors/matrices
        # This aggregates the contributions of all rank components
        aggregated_features = np.zeros(self.W.shape[0])
        
        for i, comp in enumerate(self.components):
            comp_type = self.types[i]
            if comp_type == 'vec':
                # Vector-based (CP) projection
                # Example: dot product of coordinate embedding and vector component
                # Note: Exact projection depends on specific encoding of x into the vector space
                # Assuming x is mapped to a feature vector phi(x)
                phi_x = self._encode_coordinate(x)

            elif comp_type == 'mat':

                # Example: Interpolation on 2D planes
                # Assuming comp is a set of 2D matrices (Ux, Uy, Uz)
                # Contribution is interpolated based on x's 2D projections
                contribution = self._interpolate_matrix(comp, x)

                raise ValueError("Unknown component type")
            
            # Accumulate contributions (weighted by rank-residual learning implicitly in W)

            aggregated_features += contribution

        c = output[1:4]
        
        return sigma, c

    def compress(self, target_rank):
        """
        Compress the model by truncating ranks.
        
        Args:
            target_rank (int): The desired number of rank components to keep.
        """
        # Sort components by importance (derived from rank-residual weights)
        # [G] Implementation detail: Importance score is typically derived from the 
        # magnitude of the weights in W associated with each rank component.
        importance_scores = self._calculate_importance()
        
        # Sort indices by importance descending
        sorted_indices = np.argsort(importance_scores)[::-1]

        self.components = [self.components[i] for i in keep_indices]

## Operating characteristics
*   **Time Complexity:** Querying is generally faster than MLP-based NeRFs as it avoids forward passes through deep networks, relying instead on linear algebra operations (dot products, interpolation) [S1].
*   **Memory Complexity:** Model size is directly controlled by the rank of the decomposition. Compression reduces memory linearly with the number of truncated ranks [S1].
*   **Measured Performance:** Achieves comparable rendering quality to state-of-the-art methods while enabling extra capabilities of compression and composition [S1].
*   **Strengths:**
    *   No neural networks for rendering, allowing arbitrary composition without retraining [S1].
    *   Dynamic model size adjustment via rank truncation without retraining [S1].
    *   Near-optimal compression via rank-residual learning [S1].
*   **Limitations:**
    *   Standard truncated HOSVD is quasi-optimal, not strictly optimal [S1].
    *   Composition may require careful handling of transformation matrices and rank alignment [S1].
*   **When to use:** When scene manipulation (compression, composition, LOD control) is required without the overhead of MLP rendering [S1].
*   **When not to use:** When maximum possible rendering fidelity is prioritized over manipulability and storage efficiency, or when the scene has very high-frequency details that are poorly captured by low-rank approximations [S1].

## Background
*   **Origin:** Proposed by Jiaxiang Tang, Xiaokang Chen, Jingbo Wang, and Gang Zeng from Peking University and Chinese University of Hong Kong [S1].
*   **Paper:** "Compressible-Composable NeRF via Rank-residual Decomposition" (arXiv:2205.14870v2, Oct 11, 2022) [S1].
*   **History:** Developed to address the difficulty of manipulating implicit NeRF representations compared to explicit meshes, and to overcome the limitations of existing NeRF manipulation methods that were restricted by shared renderer networks or suffered from large model sizes [S1]. It builds on tensor decomposition techniques like Tucker decomposition and CP decomposition, which have been used in various vision tasks [S1]. It specifically contrasts with TensoRF, which uses MLPs that prevent compression/composition [S1].
