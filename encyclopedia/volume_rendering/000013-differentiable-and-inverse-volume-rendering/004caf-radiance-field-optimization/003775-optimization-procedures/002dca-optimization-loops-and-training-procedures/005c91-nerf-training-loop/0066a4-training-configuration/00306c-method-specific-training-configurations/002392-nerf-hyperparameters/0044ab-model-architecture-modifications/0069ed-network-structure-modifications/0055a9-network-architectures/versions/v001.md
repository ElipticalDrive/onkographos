# Network Architectures

Also called: NeRF Network Architectures

## Overview
This article details specific modifications to the standard NeRF network architecture, focusing on layer dimensions, auxiliary heads, and hybrid explicit-implicit structures. It addresses the trade-off between representational capacity and computational efficiency, particularly for mobile or resource-constrained deployment. Unlike the standard two-MLP setup, these architectures often introduce specialized small networks for specific tasks or replace continuous volume representations with discrete texture maps.

## How it works
The standard NeRF architecture consists of two Multi-Layer Perceptrons (MLPs): a coarse network and a fine network . The coarse network takes positional encoded position $\gamma(\mathbf{x})$ and outputs a latent feature vector $\mathbf{h}$ and volume density $\sigma$. The fine network takes $\mathbf{h}$, positional encoded position $\gamma(\mathbf{x})$, and positional encoded view direction $\gamma(\mathbf{d})$ to output color $\mathbf{c}$ .

$$
\gamma(\mathbf{x}, d_1, d_2) = [\mathbf{x}, \sin(2^{d_1}\pi\mathbf{x}), \cos(2^{d_1}\pi\mathbf{x}), \dots, \sin(2^{d_2-1}\pi\mathbf{x}), \cos(2^{d_2-1}\pi\mathbf{x})]
$$

Modifications generally fall into three categories:
1.  **Input Expansion:** Adding new conditioning vectors (e.g., appearance embeddings $\mathbf{z}_i$, fluid volume $v$, or previous stage RGB) to the input concatenation .
2.  **Output Expansion:** Adding auxiliary heads to predict values other than $\sigma$ and $\mathbf{c}$, such as semantic labels $y_{aux}$, object codes $o$, or area encoding probabilities $p$. These are rendered using the same transmittance weights $T_i$ and opacity $\alpha_i$ as color:
    $$
    \hat{Y}(r) = \sum_{i=1}^{N} T_i \alpha_i y_{aux}(x_i)
    $$
    .
3.  **Representation Substitution:** Replacing the continuous MLP function with discrete structures (voxel grids, hash tables) or different implicit surfaces (SDFs) .

### MobileNeRF Architecture
MobileNeRF [S1] modifies the standard architecture to exploit the polygon rasterization pipeline for efficient neural field rendering on mobile devices. It introduces three distinct MLP components: A, F, and H.

**Inputs and Outputs:**
*   **MLP A (Appearance):** Takes positional encoding $\gamma(\mathbf{x})$ and outputs an 8-dimensional feature vector $\mathbf{f}$.
*   **MLP F (Geometry):** Takes $\gamma(\mathbf{x})$ and outputs volume density $\sigma$.
*   **MLP H (Hybrid/Small):** Takes $\mathbf{f}$ and outputs color $\mathbf{c}$.

**Data Structures:**
*   **Feature Storage:** The 8-dimensional features $\mathbf{f}$ from MLP A are stored in two PNG images. Each PNG has 4 channels, totaling 8 channels. The alpha channel is squeezed into the first feature channel: if the first feature channel is non-zero, alpha is 1; otherwise, it is 0 [S1].
*   **Texture Constraints:** Texture sizes are constrained to powers of 2 and at most $4096 \times 4096$ [S1].

**Network Specifications:**
*   **MLPs A and F:** Use the standard NeRF MLP design but with hidden layer sizes increased from 256 to 384 neurons [S1].
*   **MLP H:** A small MLP with two hidden layers, each consisting 16 neurons [S1].

**Pseudocode:**
```python
class MobileNeRF:
    def __init__(self):
        # MLP A: 384 hidden layers
        self.MLP_A = MLP(hidden_size=384, output_size=8)
        # MLP F: 384 hidden layers
        self.MLP_F = MLP(hidden_size=384, output_size=1)
        # MLP H: 16 hidden layers, 2 hidden layers total
        self.MLP_H = MLP(hidden_size=16, num_hidden_layers=2, output_size=3)
        
    def forward(self, x):
        # Encode position
        gamma_x = positional_encoding(x)
        
        # Generate features and density
        features = self.MLP_A(gamma_x) # Shape: [8]
        sigma = self.MLP_F(gamma_x)    # Shape: [1]
        
        # Decode color from features
        color = self.MLP_H(features)   # Shape: [3]
        
        return color, sigma
```

**Edge Cases and Pitfalls:**
*   **Inference:** MLPs A and F are not used during inference in the final deployment phase, allowing more time to be allocated to training these components [S1].
*   **Hardware Constraints:** Mobile devices require texture sizes to be powers of 2 and $\le 4096 \times 4096$, necessitating splitting large feature maps [S1].

## Subtopics

### [MultiPlane NeRF](15533-multiplane-nerf.md)
A NeRF variant that uses a fixed set of n pre-existing 2D images as a non-trainable planar representation, enabling the training of a small implicit decoder without trainable 3D representation schemes.

### [SqueezeNeRF](15536-squeezenerf.md)
SqueezeNeRF is a memory-efficient NeRF inference method that further factorizes the position-dependent MLP of FastNeRF into three separate MLPs to reduce cache size complexity from O(n^3) to O(n^2).

## Operating characteristics
*   **MobileNeRF [S1]:**
    *   **Training Time:** Increased due to larger hidden layers (384 vs 256) in MLPs A and F, but these are not used during inference.
    *   **Inference Efficiency:** High, as it leverages the polygon rasterization pipeline and a small MLP H (16 neurons).
    *   **Memory:** Feature storage is constrained by mobile texture limits ($4096 \times 4096$).
    *   **Use Case:** Mobile neural field rendering.

## Background
MobileNeRF [S1] was introduced to address the computational limitations of standard NeRF on mobile devices. It exploits the polygon rasterization pipeline to offload some of the neural computation, using a hybrid approach of MLPs and texture maps.
