# UE4-NeRF

Also called: UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene

## Overview
UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale 3D scenes by partitioning the environment into sub-NeRFs represented as textured polygonal meshes and integrating them into the Unreal Engine 4 (UE4) rasterization pipeline [S1]. Unlike [Block-NeRF](11916-block-nerf.md) which is limited to grid structures, or [Mobile-NeRF](13622-mobile-nerf.md) which struggles with tilted surfaces and semi-transparent objects, UE4-NeRF uses regular octahedra for mesh initialization and stores opacity in texture maps to handle complex outdoor environments [S1]. It achieves real-time performance (up to 43 FPS at 4K) by leveraging multi-resolution hash encoding for training acceleration and a Level of Detail (LOD) hierarchy for rendering [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of posed images (typically from drone capture) with GPS metadata; camera poses; scene bounding box.
*   **Outputs:** A set of textured polygonal meshes (shading meshes) with associated neural shaders, ready for import into UE4; real-time rendered video frames.

**Data Structures:**
1.  **Scene Partitioning:** The large scene is divided into $N$ blocks. Each block has a training area slightly larger than the physical scene area to create overlapping borders for smooth transitions [S1].
2.  **Mesh Representation:** Each block is represented by a textured polygonal mesh. The mesh is initialized from a grid and optimized. The texture atlas stores two channels: an 8-dimensional feature vector and opacity [S1].
3.  **LOD Hierarchy:** Multiple levels of mesh detail are generated. Coarser meshes (lower vertex count) are used for higher observation heights to maintain frame rate [S1].
4.  **Coordinate System:** UE4 coordinate system: X-axis points East, Y-axis points South, Z-axis points Up. World scale is 100:1 (UE4 units to real-world units) [S1].

**Network Architecture:**
The method uses an Encoder-Decoder MLP structure, implemented as an HLSL fragment shader in UE4 [S1].
*   **Encoder ($E$):** Takes hash-encoded position $\mathbf{p}_i$ and outputs opacity $\alpha_i$ and an 8-dimensional feature vector $\mathbf{M}_i$ [S1].
    *   Architecture: 4-layer MLP.
    *   Dimensions: $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
    *   Input: $\mathbf{p}_i$ encoded via multi-resolution hash encoding (from Instant-NGP) [S1].
*   **Decoder ($D$):** Takes feature vector $\mathbf{M}_i$ and spherical harmonic encoded direction $\mathbf{SH}(\mathbf{d}_i)$ to output color $\mathbf{c}_i$ [S1].
    *   Architecture: 3-layer MLP.
    *   Dimensions: $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
    *   Input: Concatenation of $\mathbf{M}_i$ (8 dims) and $\mathbf{SH}(\mathbf{d}_i)$ (9 dims, assuming degree 2 SH) [S1].

**Numbered Steps:**

1.  **Preprocessing and Partitioning:**
    *   Transform GPS-captured imagery coordinates to the UE4 coordinate system (X=East, Y=South, Z=Up) and apply the 100:1 scale conversion [S1].
    *   Partition the scene into blocks. Train a coarse model to segment sub-regions and capture terrain/building outlines. Filter images and apply masks to exclude pixels outside the scene area [S1].

2.  **Mesh Initialization:**
    *   Initialize a $128 \times 128 \times 128$ grid for each block [S1].
    *   Select the center point of each grid cell and its six neighbors (front, back, left, right, top, bottom) to form polygonal faces [S1].
    *   Construct a regular octahedron with 20 faces (8 exterior, 12 interior) to represent the local geometry, addressing the slow convergence of Mobile-NeRF on tilted surfaces [S1].

3.  **Training (Optimization):**
    *   For each ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$, calculate the intersection with the polygonal mesh to determine sampling points [S1].
    *   Optimize the Encoder-Decoder network parameters ($\theta_E, \theta_D$) and the vertex positions of the meshes simultaneously [S1].
    *   The loss function minimizes the difference between rendered and ground truth colors (typically MSE, though specific loss formulation is not detailed beyond metric evaluation) [S1].
    *   Training is performed using CUDA for GPU parallelization [S1].
    *   Hyperparameters: 80,000 epochs per block on 1× NVIDIA RTX 3090 [S1].

4.  **Mesh Extraction and LOD Generation:**
    *   Extract pre-rendered polygonal meshes at different levels of detail (LOD) [S1].
    *   Coarser meshes are generated for higher observation heights [S1].
    *   The texture atlas is populated with the final optimized feature vectors and opacity values [S1].

5.  **Rendering in UE4:**
    *   Import the textured meshes into UE4 [S1].
    *   Deploy the Encoder-Decoder network as an HLSL fragment shader [S1].
    *   The shader takes the feature vectors (from the texture atlas) and viewing direction as input to output colors [S1].
    *   UE4's rasterization pipeline handles occlusion; if a traditional 3D model (e.g., .obj, .fbx) occludes the NeRF background, the neural shader is skipped for those regions [S1].

    """
    Transform GPS data to UE4 coordinates and partition scene.

def encoder(hash_encoding, theta_E):
    """
    4-layer MLP: 32->64->64->64->8
    Input: Hash-encoded position
    Output: Opacity and 8-dim feature vector
    """
    x = hash_encoding
    x = relu(linear(x, theta_E[0])) # 32->64
    x = relu(linear(x, theta_E[1])) # 64->64
    x = relu(linear(x, theta_E[2])) # 64->64
    x = linear(x, theta_E[3])       # 64->8
    # Split output into opacity and features
    opacity = sigmoid(x[:, :1])
    features = x[:, 1:]
    return opacity, features

def decoder(features, direction, theta_D):
    """
    3-layer MLP: 17->16->16->3
    Input: Concat(Features, SH(Direction))
    Output: Color
    """
    # Encode direction using Spherical Harmonics (degree 2 -> 9 coeffs)
    sh_dir = spherical_harmonics(direction, degree=2)
    input_vec = concat(features, sh_dir) # 8 + 9 = 17
    
    x = relu(linear(input_vec, theta_D[0])) # 17->16
    x = relu(linear(x, theta_D[1]))         # 16->16
    x = linear(x, theta_D[2])               # 16->3
    color = sigmoid(x)
    return color

**Parameters:**
*   **Grid Size:** $128 \times 128 \times 128$ [S1].
*   **Octahedron Faces:** 20 total (8 exterior, 12 interior) [S1].
*   **Encoder Layers:** 4 layers, dimensions $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
*   **Decoder Layers:** 3 layers, dimensions $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
*   **Training Epochs:** 80,000 per block [S1].
*   **Hardware:** 1× NVIDIA RTX 3090 [S1].
*   **Scale:** 100:1 (UE4 units to real-world) [S1].

**Edge Cases and Pitfalls:**
*   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces; UE4-NeRF mitigates this with regular octahedra [S1].
*   **Semi-transparent Objects:** Mobile-NeRF fails on transparent/semi-transparent objects (water, glass) due to opacity binarization. UE4-NeRF stores opacity in texture maps, but semi-transparent objects (e.g., vegetation) still increase computational overhead and reduce frame rates [S1].
*   **Pre-rendering Gaps:** Pre-rendering cannot capture rays from all viewing angles, potentially resulting in gaps or holes in the final scene [S1].
*   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, causing evaluation metrics (PSNR/SSIM) to underestimate actual reconstruction quality [S1].
*   **Memory Overhead:** Rendering large scenes (square kilometers) incurs significant memory overhead, which increases with accuracy [S1].
*   **Hardware Dependency:** Requires CUDA and NVIDIA GPUs [S1].

## Operating characteristics
*   **Training Speed:** 1000× faster than Mobile-NeRF [S1].
    *   Time per block: ~40 minutes on 1× RTX 3090 [S1].
    *   Time for full scene ($n$ blocks): $1 \text{ hour} + (40 \text{ minutes} \times n/4)$ on 1× RTX 3090 [S1].
    *   Comparison: Mobile-NeRF takes 48h/block (4×3090); Mega-NeRF takes 36h/block (1×3090) [S1].
*   **Rendering Performance:**
    *   Real-time at 4K resolution: up to 43 FPS (Level-1 mesh) [S1].
    *   Full scene at 2K resolution: 50 FPS [S1].
    *   Individual blocks at 2K resolution: ≥70 FPS [S1].
    *   Comparison: Mobile-NeRF max 35 FPS at 2K (block only); Mega-NeRF max 60 FPS at 800×800 [S1].
*   **Memory:** Significant memory overhead for large scenes (square kilometers); increases with accuracy [S1].
*   **Strengths:** Real-time large-scale rendering; handles tilted surfaces and semi-transparent objects better than Mobile-NeRF; integrates with UE4 for scene editing; avoids blurriness on natural scenes compared to Mip-NeRF [S1].
*   **Limitations:** Requires NVIDIA GPUs; pre-rendering gaps; exposure matching issues in UE4; semi-transparent objects reduce FPS [S1].
*   **When to use:** Large-scale outdoor scenes (farmland, construction sites, industrial parks) requiring real-time interaction and editing in UE4 [S1].
*   **When not to use:** Small-scale scenes where training overhead is prohibitive; scenes requiring high-fidelity transparent object rendering without performance loss; non-NVIDIA hardware environments [S1].

## Background
*   **Origin:** Introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" [S1].
*   **History:** Developed to address the limitations of NeRF in real-time rendering of large-scale scenes, specifically combining NeRF with the Unreal Engine 4 rasterization pipeline [S1]. It builds on techniques from Mobile-NeRF (mesh representation) and Instant-NGP (hash encoding) [S1].
*   **Usage:** Used for real-time interactive rendering of drone-captured large-scale scenes (Farmland, Construction site, Industrial parks) and evaluated on the Mega-NeRF public dataset [S1].
