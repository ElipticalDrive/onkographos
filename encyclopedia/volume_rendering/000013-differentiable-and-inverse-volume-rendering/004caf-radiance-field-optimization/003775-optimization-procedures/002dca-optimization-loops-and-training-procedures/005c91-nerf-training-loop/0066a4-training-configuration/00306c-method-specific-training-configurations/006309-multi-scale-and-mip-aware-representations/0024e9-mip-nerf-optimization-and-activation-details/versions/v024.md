# Mip-NeRF Optimization and Activation Details

Also called: JaxNeRF Training Procedure, Mip-NeRF Misc. Changes

## Overview
This article details the specific implementation optimizations, activation functions, and learning rate schedules used in the training of Mip-NeRF and JaxNeRF. These changes are designed to improve training stability and robustness without significantly altering the method's accuracy or speed [S1]. Unlike standard NeRF implementations, Mip-NeRF removes the identity encoding from the MLP input and employs shifted softplus and widened sigmoid activations to prevent catastrophic failure modes during optimization [S1]. It builds on [Method-Specific Training Configurations](6267-method-specific-training-configurations.md) by providing the concrete hyperparameters and numerical details required to reproduce the Mip-NeRF results.

## How it works
The training procedure minimizes a photometric loss between rendered pixel colors and ground truth images using the Adam optimizer [S1]. The core loop involves ray sampling, point sampling, feature encoding (Integrated Positional Encoding), network forward pass, volume rendering, and parameter updates [Parent]. The following details specify the deviations from the standard NeRF architecture and optimization loop.

### Inputs and Outputs
*   **Inputs:** Training images (RGB), camera poses, and scene bounds.
*   **Outputs:** Optimized neural network parameters (MLP weights and biases).

### Data Structures
The neural network is a Multi-Layer Perceptron (MLP).
*   **Input Layer:** Receives the Integrated Positional Encoding (IPE) of the position and covariance. It does **not** receive the concatenated original position or view direction [S1].
*   **Hidden Layers:** Standard MLP layers with ReLU activations (implied by standard practice, though not explicitly detailed in the activation section, the density/color heads use specific non-ReLU activations) [S1].
*   **Density Head:** Outputs $\tau$ (pre-activation density).
*   **Color Head:** Outputs $c$ (pre-activation color).
*   **View Direction Injection:** The view direction is processed separately and injected into the last layer of the MLP [S1].

### Numbered Steps

1.  **Input Encoding:**
    *   Compute the Integrated Positional Encoding (IPE) for the position and covariance matrix of the conical frustum [S1].
    *   **Remove Identity Concatenation:** Do not concatenate the original position or view direction to the IPE. The MLP input is the IPE only [S1].

2.  **Density Prediction:**
    *   Pass the IPE through the MLP to get the pre-activation density value $x_\tau$.
    *   Apply the **Shifted Softplus** activation to obtain $\tau$:
        $$ \tau = \log(1 + \exp(x_\tau - 1)) $$
    *   This function is equivalent to initializing the bias of the density output layer to $-1$, resulting in small initial $\tau$ values [S1].

3.  **View Direction Handling:**
    *   Normalize the ray direction $d$.
    *   Apply positional encoding to $d$ with $L=4$ frequencies [S1].
    *   Inject this encoded view direction into the last layer of the MLP. This injection occurs **after** $\tau$ is predicted but **before** the color $c$ is predicted [S1].

4.  **Color Prediction:**
    *   Pass the intermediate features (including injected view direction) through the final layer to get the pre-activation color value $x_c$.
    *   Apply the **Widened Sigmoid** activation to obtain $c$:
        $$ c = \frac{1 + 2\epsilon}{1 + \exp(-x_c)} - \epsilon $$
    *   Where $\epsilon = 0.001$. This allows the output to saturate slightly outside the $[0, 1]$ range to avoid optimization failure when explaining black or white pixels [S1].

5.  **Volume Rendering:**
    *   Compute the accumulated color $\hat{C}(\mathbf{r})$ using the standard volume rendering integral [Parent]:
        $$ \hat{C}(\mathbf{r}) = \sum_{i=1}^{N} T_i \alpha_i \mathbf{c}_i $$
    *   Where $\alpha_i = 1 - \exp(-\tau_i \delta_i)$ and $T_i = \exp(-\sum_{j=1}^{i-1} \tau_j \delta_j)$ [Parent].

6.  **Loss Computation:**
    *   Compute the photometric loss between $\hat{C}(\mathbf{r})$ and the ground truth pixel color.

7.  **Optimization Step:**
    *   Update parameters using the Adam optimizer with the learning rate schedule defined below.

### Learning Rate Schedule
The learning rate $\eta_i$ at iteration $i$ is calculated using a warmup phase followed by logarithmic annealing [S1].

**Parameters:**
*   $n$: Total number of iterations ($1,000,000$) [S1].
*   $n_w$: Warmup iterations ($2,500$) [S1].
*   $\eta_0$: Initial learning rate ($5 \cdot 10^{-4}$) [S1].
*   $\eta_n$: Final learning rate ($5 \cdot 10^{-6}$) [S1].
*   $\lambda_w$: Warmup scale factor, annealed from $0.01$ to $1$ during the warmup period [S1].

**Formula:**
$$ \eta_i = \left( \lambda_w + (1 - \lambda_w) \sin\left(\frac{\pi}{2} \operatorname{clip}\left(\frac{i}{n_w}, 0, 1\right)\right) \right) \times \exp\left( \left(1 - \frac{i}{n}\right) \log(\eta_0) + \frac{i}{n} \log(\eta_n) \right) $$

**Warmup Logic:**
During the first $n_w$ iterations, $\lambda_w$ is smoothly annealed from $0.01$ to $1$. This scales the base learning rate to improve stability for ablations and ensure fair comparison [S1].

### Pseudocode

```python
import math
import jax.numpy as jnp

def shifted_softplus(x):
    """
    Density activation: log(1 + exp(x - 1))
    Prevents catastrophic failure where MLP emits negative values everywhere.
    """
    return jnp.log(1 + jnp.exp(x - 1))

def widened_sigmoid(x, epsilon=0.001):
    """
    Color activation: (1 + 2*eps) / (1 + exp(-x)) - eps
    Saturates slightly outside [0, 1] to avoid optimization failure on black/white pixels.
    """
    return (1 + 2 * epsilon) / (1 + jnp.exp(-x)) - epsilon

def positional_encoding_vector(v, L=4):
    """
    Standard positional encoding for a vector v with L frequencies.
    Returns concatenated [sin(2^0 * pi * v), cos(2^0 * pi * v), ..., sin(2^(L-1) * pi * v), cos(2^(L-1) * pi * v)]
    """
    # Implementation detail: Standard PE function.
    # Assuming v is a vector of shape (D,)
    freq_bands = 2.0 ** jnp.arange(L)
    # This is a conceptual representation; actual implementation uses broadcasting
    # pe = jnp.concatenate([jnp.sin(freq_bands * v * jnp.pi), jnp.cos(freq_bands * v * jnp.pi)], axis=-1)
    # For the purpose of this article, we assume a standard PE function exists.
    pass 

def compute_learning_rate(i, n=1000000, n_w=2500, eta_0=5e-4, eta_n=5e-6):
    """
    Computes the learning rate at iteration i.
    """
    # Calculate lambda_w (warmup scale factor)
    # lambda_w is annealed from 0.01 to 1 during warmup
    # clip(i/n_w, 0, 1) ensures we stay within [0, 1]
    progress = jnp.clip(i / n_w, 0.0, 1.0)
    # The formula uses sin(pi/2 * progress) to go from 0 to 1
    # lambda_w starts at 0.01 when progress=0 and goes to 1 when progress=1
    # Note: The source formula is: lambda_w + (1 - lambda_w) * sin(...)
    # This implies lambda_w is a variable that changes. 
    # Let's interpret the source: "scale factor that is smoothly annealed between lambda_w = 0.01 and 1"
    # The formula provided is: eta_i = (lambda_w + (1 - lambda_w) * sin(...)) * log_annealing
    # This suggests lambda_w in the formula is the *current* value of the warmup factor.
    # Let's define lambda_w_current based on progress.
    # When progress=0, sin(0)=0, term is lambda_w. We want 0.01.
    # When progress=1, sin(pi/2)=1, term is lambda_w + (1-lambda_w) = 1.
    # So lambda_w_current must be 0.01 at start? No, the formula structure is:
    # Base_Scale = lambda_w + (1 - lambda_w) * sin(...)
    # If lambda_w is constant 0.01, Base_Scale goes from 0.01 to 1.
    # The text says "lambda_w is annealed from 0.01 to 1". This is slightly ambiguous.
    # However, the formula explicitly uses lambda_w as a parameter in the expression.
    # Standard interpretation: The term (lambda_w + (1-lambda_w)*sin(...)) IS the warmup multiplier.
    # If lambda_w = 0.01, the multiplier goes from 0.01 to 1.
    # So we treat lambda_w as the constant lower bound 0.01.
    
    lambda_w_lower = 0.01
    warmup_multiplier = lambda_w_lower + (1 - lambda_w_lower) * math.sin(math.pi / 2 * progress)
    
    # Logarithmic annealing
    log_eta = (1 - i / n) * math.log(eta_0) + (i / n) * math.log(eta_n)
    base_lr = math.exp(log_eta)
    
    return warmup_multiplier * base_lr

def mip_nerf_forward_pass(position, covariance, view_direction, mlp_params):
    """
    Single forward pass for a ray sample.
    """
    # 1. Input Encoding
    # IPE is computed from position and covariance (see Mip-NeRF main paper for IPE details)
    # Here we assume `ipe` is the result of the IPE function
    ipe = compute_ipe(position, covariance) 
    
    # 2. Density Prediction
    # Pass IPE through MLP to get pre-activation density x_tau
    x_tau = mlp_forward(ipe, mlp_params)
    tau = shifted_softplus(x_tau)
    
    # 3. View Direction Handling
    # Normalize direction
    d_normalized = view_direction / jnp.linalg.norm(view_direction)
    # PE with L=4
    view_pe = positional_encoding_vector(d_normalized, L=4)
    
    # 4. Color Prediction
    # Inject view_pe into the last layer. 
    # This is typically done by adding or concatenating to the hidden representation 
    # before the final color layer.
    # Assuming `mlp_forward` handles the injection if structured correctly, 
    # or we explicitly modify the last layer input.
    # For clarity, we assume the MLP architecture supports this injection.
    x_c = mlp_forward_with_view(ipe, view_pe, mlp_params)
    c = widened_sigmoid(x_c)
    
    return tau, c
```

### Edge Cases and Pitfalls
*   **Negative Density:** Using standard ReLU for density can lead to catastrophic failure if the MLP outputs negative values everywhere, resulting in zero gradients. The shifted softplus prevents this [S1].
*   **Black/White Pixel Saturation:** Standard sigmoid saturation can cause optimization failure when trying to explain pure black or white pixels. The widened sigmoid mitigates this [S1].
*   **Identity Concatenation:** Including the original position and view direction concatenated with the PE does not improve performance and complicates the IPE formalization. It should be removed [S1].
*   **Correlation Insensitivity:** IPE features are insensitive to off-diagonal elements of the covariance matrix $\Sigma$ (correlation). Experiments show that modeling this correlation does not improve accuracy, so it is omitted [S1].

## Subtopics

### [Mip-NeRF 360 Optimization Setup](3426-mip-nerf-360-optimization-setup.md)
Mip-NeRF 360 Optimization Setup defines the training configuration for unbounded neural radiance fields, specifically addressing the challenge of rendering large-scale, "in-the-wild" scenes with limited video memory. It combines a scene contraction function to warp unbounded space into a finite sphere with a multi-stage proposal sampling strategy and a specific loss formulation to ensure training stability and anti-aliasing. It sets itself apart from standard NeRF implementations by explicitly handling unbounded domains through coordinate warping and using a stop-gradient mechanism to decouple proposal network optimization from the final NeRF network.

### [Scale-Dependent Downweighting for Grid Interpolation](8571-scale-dependent-downweighting-for-grid-interpolation.md)
Scale-Dependent Downweighting is a technique to anti-alias trilinear interpolation in neural radiance fields by downweighting features interpolated from grid cells that are small relative to the sampling Gaussian's spread, preventing aliasing artifacts from high-frequency content. Unlike naive trilinear interpolation which causes aliasing at high frequencies, this method uses the Gaussian CDF to weight samples, similar to Mip-NeRF's IPE features but applied to grid-based representations.

### [S-NeRF Training Configuration](15165-s-nerf-training-configuration.md)
S-NeRF training configuration defines the specific hyperparameters, network architectures, and confidence-based loss weighting used to optimize Neural Radiance Fields for dynamic street scenes using LiDAR and RGB data. It distinguishes itself from standard NeRF variants by employing a dual-phase training loop (foreground vehicles vs. background street views) and integrating geometry/projection confidence maps to mitigate depth outliers from moving objects. This configuration builds on [Mip-NeRF Optimization and Activation Details](3409-mip-nerf-optimization-and-activation-details.md) but adds specific LiDAR-guided confidence mechanisms and distinct MLP topologies for foreground/background separation.

### Alternative Gaussian Positional Encoding
An alternative to Integrated Positional Encoding (IPE) involves concatenating the positional encodings of the mean and the (signed) square root of the elements of the covariance matrix as input to the MLP [S1]. Specifically, positional encoding is applied to the mean $\mu$ with $L=12$, and to $\text{vec}(\text{triu}(\text{sign}(\Sigma) \circ \rho |\Sigma|))$ with $L=2$ [S1]. This approach performs comparably to IPE in terms of accuracy but is sensitive to hyperparameters $L$ and the covariance parameterization design, whereas IPE is hyperparameter-free and more compact [S1]. Additionally, while IPE is insensitive to off-diagonal elements of $\Sigma$, this alternative endows the network with sensitivity to correlation, though experiments show this does not improve accuracy [S1].

### Reflected Cone Derivation
A geometric derivation used in Mip-NeRF to handle reflections by shifting the origin of a reflected ray so that its cone radius matches the incident ray's cone radius at the intersection point, ensuring consistent view-dependent appearance [S2]. The condition for equating radii is $\dot{r}\|\bar{\mathbf{x}} - \mathbf{o}\| = \dot{r}'\|\bar{\mathbf{x}} - \mathbf{o}'\|$, where $\dot{r}$ is the incident ray radius parameter, $\bar{\mathbf{x}}$ is the intersection point, $\mathbf{o}$ is the incident ray origin, $\dot{r}'$ is the reflected ray radius parameter, and $\mathbf{o}'$ is the reflected ray origin [S2]. This equation, along with the constraint that $\mathbf{o}'$ lies on the reflected ray, is solved to determine the correct origin for the reflected ray [S2].

### RawNeRF
RawNeRF is a method for High Dynamic Range (HDR) image view synthesis and denoising that adapts Mip-NeRF to use raw linear images as training data, allowing post-processing after rendering [S3]. Unlike HDR-NeRF which uses LDR images, RawNeRF renders in a linear color space using raw linear images [S3]. It is supervised with variable exposure images, scaling the NeRF models’ “exposure” by the training image’s shutter speed, as well as a per-channel learned scaling factor [S3].

## Operating characteristics
*   **Training Time:** Mip-NeRF is 13x faster to train than a brute-force supersampling baseline (16 rays/pixel) [S1].
*   **Evaluation Speed:** Mip-NeRF is 16x faster to evaluate than the supersampling baseline [S1].
*   **Quality:** Mip-NeRF outperforms brute-force supersampling in quality metrics (PSNR, SSIM, LPIPS) [S1].
*   **Stability:** The shifted softplus and widened sigmoid activations improve training stability, particularly with large learning rates, although the default learning rates used in the paper are conservative [S1].
*   **Memory:** The removal of identity concatenation simplifies the input representation, though the primary memory savings come from the efficient IPE computation compared to supersampling [S1].

## Background
Mip-NeRF was introduced by Barron et al. in 2021 [S1]. The optimization details described here are from the supplementary material of the Mip-NeRF paper, specifically Section E (Miscellaneous Changes) and Section G (Alternative Gaussian Positional Encoding) [S1]. These details were provided to ensure reproducibility and to document changes that improve robustness without significantly affecting the core method's accuracy or speed [S1]. The JaxNeRF codebase implements these procedures [S1]. RawNeRF, a variant using raw images, was created by Mildenhall et al. in November 2021 [S3]. NeRF-Casting, which includes the reflected cone derivation, was published in 2024 [S2].
