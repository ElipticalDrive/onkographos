# UE4-NeRF

Also called: UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene

## Overview
UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale scenes by partitioning environments into sub-NeRFs represented as textured polygonal meshes and integrating them into the Unreal Engine 4 (UE4) rasterization pipeline [S1]. Unlike standard differentiable volume rendering which relies on ray marching, UE4-NeRF converts the learned radiance field into explicit geometry (octahedral meshes) and neural shaders, enabling frame rates up to 43 FPS at 4K resolution [S1]. It distinguishes itself from sibling methods like Mobile-NeRF by using regular octahedra to handle tilted surfaces and from Block-NeRF by supporting non-grid terrains, while achieving significantly faster training times through multi-resolution hash encoding [S1].

## How it works
The method operates in three phases: Block Partitioning, Optimization (Training), and Real-Time Rendering via UE4 integration.

### Inputs and Outputs
*   **Inputs:** A set of posed images (e.g., drone imagery) with GPS coordinates; camera poses; scene bounding box.
*   **Outputs:** A set of textured polygonal meshes (LOD hierarchy) per block, ready for import into UE4; a neural shader (HLSL) for color prediction.

### Data Structures
1.  **Block Partition:**
    *   The scene is divided into $N$ blocks. Each block's training area is slightly larger than the physical scene area to create overlapping borders for smooth transitions [S1].
    *   A coarse model is trained to segment sub-regions and generate masks to exclude pixels outside the scene area [S1].
2.  **Mesh Representation:**
    *   **Grid Initialization:** A $128 \times 128 \times 128$ grid is initialized [S1].
    *   **Octahedron Construction:** For each grid cell, the center point and its six neighbors (front, back, left, right, top, bottom) are used to create polygonal meshes. Specifically, a regular octahedron with 20 faces (8 exterior, 12 interior) is used [S1].
    *   **Vertex Optimization:** Vertex positions are continuously optimized during training [S1].
3.  **Neural Network (Encoder-Decoder):**
    *   **Encoder ($E$):** A 4-layer MLP.
        *   Input: Positional information $\mathbf{p}_i$ encoded via multi-resolution hash encoding (from Instant-NGP) [S1].
        *   Architecture: $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
        *   Output: Opacity $\alpha_i$ and an 8-dimensional feature vector $\mathbf{M}_i$ [S1].
    *   **Decoder ($D$):** A 3-layer MLP.
        *   Input: Feature vector $\mathbf{M}_i$ and spherical harmonics coefficients $\mathbf{SH}(\mathbf{d}_i)$ derived from viewing direction $\mathbf{d}_i$ [S1].
        *   Architecture: $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
        *   Output: Final color $\mathbf{c}_i$ [S1].
    *   **Note:** The input dimension to the decoder is 17, implying the feature vector (8) is concatenated with spherical harmonics coefficients (9, likely degree 2) [S1].
4.  **Texture Atlas:**
    *   Stores feature vectors and opacity information for the meshes [S1].
5.  **Coordinate System:**
    *   UE4 coordinate system: X-axis points East, Y-axis points South, Z-axis points Up [S1].
    *   Scale: 100:1 (UE4 units to real-world units) [S1].

### Numbered Steps

1.  **Preprocessing:**
    *   Transform input images to the UE4 coordinate system and apply the 100:1 scale conversion [S1].
    *   Partition the large-scale scene into multiple blocks with overlapping borders [S1].
    *   Train a coarse segmentation model to filter images and create masks for each block [S1].

2.  **Mesh Initialization:**
    *   For each block, initialize a $128 \times 128 \times 128$ grid [S1].
    *   Select the center point of each grid cell and its six orthogonal neighbors [S1].
    *   Construct regular octahedra (20 faces: 8 exterior, 12 interior) from these points [S1].

3.  **Network Definition:**
    *   Define the Encoder MLP $E(\cdot; \theta_E)$ with layers $[32, 64, 64, 64, 8]$ [S1].
    *   Define the Decoder MLP $D(\cdot; \theta_D)$ with layers $[17, 16, 16, 3]$ [S1].
    *   Implement multi-resolution hash encoding for input positions [S1].

4.  **Training Loop (Per Block):**
    *   Initialize network weights $\theta_E, \theta_D$ and mesh vertex positions [S1].
    *   For each iteration (up to 80,000 epochs):
        *   Sample rays from camera poses to pixels [S1].
        *   Calculate ray-mesh intersections to determine sampling points $\mathbf{p}_i$ and directions $\mathbf{d}_i$ [S1].
        *   Encode position $\mathbf{p}_i$ using hash encoding [S1].
        *   Compute opacity $\alpha_i$ and feature vector $\mathbf{M}_i$ using Encoder:
            $$ [\alpha_i, \mathbf{M}_i] = E(\text{hash}(\mathbf{p}_i); \theta_E) $$
        *   Compute spherical harmonics coefficients $\mathbf{SH}(\mathbf{d}_i)$ for direction $\mathbf{d}_i$ [S1].
        *   Compute color $\mathbf{c}_i$ using Decoder:
            $$ \mathbf{c}_i = D([\mathbf{M}_i; \mathbf{SH}(\mathbf{d}_i)]; \theta_D) $$
        *   Render the image using the mesh intersections and neural outputs (shading) [S1].
        *   Calculate loss against ground truth images (PSNR/SSIM/LPIPS optimization) [S1].
        *   Update $\theta_E, \theta_D$ and optimize vertex positions [S1].
    *   Repeat until convergence (approx. 40 minutes on 1×RTX 3090) [S1].

5.  **LOD Generation:**
    *   Train meshes with varying levels of detail (LOD) for different observation heights [S1].
    *   Coarser meshes are used for higher observation heights to ensure real-time performance [S1].
    *   Extract pre-rendered polygonal meshes at different LODs [S1].

6.  **Rendering in UE4:**
    *   Import the textured polygonal meshes into UE4 [S1].
    *   Implement the Decoder network as an HLSL fragment shader [S1].
    *   The shader takes feature vectors (from texture atlas) as input and outputs colors [S1].
    *   Use UE4's rasterization pipeline to render the scene in real-time [S1].
    *   Apply LOD selection based on camera height/position [S1].

    """

    # Transform coordinates to UE4 system (X=East, Y=South, Z=Up) and scale 100:1
    images_transformed = transform_to_ue4(images, scale=100.0)
    
    # Partition scene and create masks
    coarse_model = train_coarse_segmentation(images_transformed, scene_bounds)
    masks = coarse_model.generate_masks(scene_bounds)
    
    # 2. Mesh Initialization
    # Initialize 128x128x128 grid
    grid = initialize_grid(128, 128, 128)
    
    # Create octahedral meshes from grid centers and neighbors
    # Each cell uses center + 6 neighbors to form octahedra
    meshes = create_octahedral_meshes(grid)
    
    # 3. Network Definition
    # Encoder: 4-layer MLP [32, 64, 64, 64, 8]
    encoder = MLP(layers=[32, 64, 64, 64, 8])
    
    # Decoder: 3-layer MLP [17, 16, 16, 3]
    # Input: 8-dim feature vector + 9-dim SH coefficients = 17
    decoder = MLP(layers=[17, 16, 16, 3])
    
    # Multi-resolution hash encoder (from Instant-NGP)
    hash_encoder = MultiResolutionHashEncoder()
    
    # 4. Optimization Loop
    for epoch in range(80000):
        # Sample random rays from poses
        rays = sample_rays(poses, images_transformed)
        
        # Filter rays using masks to exclude pixels outside scene area
        valid_rays = apply_masks(rays, masks)
        
        # Ray-Mesh Intersection
        # Find intersection points p_i and directions d_i
        intersections = ray_mesh_intersection(valid_rays, meshes)
        
        loss = 0.0
        for ray in intersections:
            p_i = ray.point
            d_i = ray.direction
            
            # Encode position
            p_encoded = hash_encoder.encode(p_i)

            # Note: "outputs opacity and an 8-dimensional feature vector".
            # This implies the encoder might output 9 values, or alpha is computed

    #   - Sample the texture atlas to get the feature vector M_i
    #   - Note: The texture atlas stores features encoded by the network.

### Parameters
*   **Grid Size:** $128 \times 128 \times 128$ [S1].
*   **Octahedron Faces:** 20 total (8 exterior, 12 interior) [S1].
*   **Encoder Layers:** $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ (or 9 to include opacity, see Pitfalls) [S1].
*   **Decoder Layers:** $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
*   **Training Hardware:** 1 Nvidia RTX 3090 GPU [S1].
*   **Training Iterations:** 80,000 epochs per block [S1].
*   **Training Time:** ~40 minutes per block [S1].
*   **Coordinate System:** X=East, Y=South, Z=Up [S1].
*   **Scale:** 100:1 [S1].

### Edge Cases and Pitfalls
*   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces. UE4-NeRF addresses this by using regular octahedra instead of the Mobile-NeRF approach [S1].
*   **Transparency:** Mobile-NeRF cannot handle transparent/semi-transparent objects (water, glass) due to opacity binarization. UE4-NeRF stores opacity in texture maps to mitigate this [S1].
*   **Performance:** Semi-transparent objects (e.g., vegetation) increase computational overhead, reducing frame rates [S1].
*   **Pre-rendering Gaps:** Pre-rendering cannot capture rays from all viewing angles, resulting in gaps or holes in the final rendered scene [S1].
*   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, causing evaluation metrics (PSNR/SSIM/LPIPS) to underestimate actual reconstruction quality [S1].
*   **Memory:** Requires CUDA and NVIDIA GPUs. Rendering large scenes (square kilometers) incurs significant memory overhead, which increases with accuracy [S1].

## Subtopics

### Block Partitioning
Divides large scenes into manageable sub-NeRFs with overlapping borders for smooth transitions. Chosen for scalability. [Link to Block-NeRF](11916-depth-guided-nerf-training-configuration.md) for comparison on partitioning strategies.

### Octahedral Mesh Initialization
Uses regular octahedra to represent grid cells, improving convergence on tilted surfaces compared to Mobile-NeRF's approach. Chosen for stability on complex terrain. [Link to Mobile-NeRF](11916-depth-guided-nerf-training-configuration.md) (Sibling).

### LOD Hierarchy
Trains meshes with varying levels of detail for different observation heights. Chosen to maintain real-time performance (FPS) at different scales. [Link to Mip-NeRF 360 MLP Architecture](14098-mip-nerf-mlp-architecture.md) for comparison on multi-scale handling.

## Operating characteristics
*   **Time Complexity:** Training is significantly faster than predecessors. UE4-NeRF trains a block in 40 minutes on 1×RTX 3090, compared to 48 hours for Mobile-NeRF (4×3090) and 36 hours for Mega-NeRF (1×3090) [S1]. This is ~1000× faster than Mobile-NeRF and ~54× faster than Mega-NeRF per block [S1].
*   **Memory Complexity:** High memory overhead for large scenes (square kilometers). Increasing accuracy amplifies memory consumption [S1].
*   **Rendering Performance:** Real-time rendering at 4K resolution with up to 43 FPS [S1]. 50 FPS on full scene at 2K resolution; ≥70 FPS on individual blocks at 2K resolution [S1].
*   **Strengths:** Real-time interactive rendering of large-scale scenes; handles tilted surfaces and semi-transparent objects better than Mobile-NeRF; supports scene editing in UE4; high fidelity on small objects and dense textures [S1].
*   **Limitations:** Requires NVIDIA GPUs and CUDA; pre-rendering gaps/holes; exposure matching issues in UE4; semi-transparent objects reduce FPS [S1].
*   **When to Use:** Large-scale outdoor scenes (farmland, construction sites, industrial parks) requiring real-time interaction and editing in UE4 [S1].
*   **When Not to Use:** Small-scale scenes where standard NeRF suffices; scenes requiring perfect ray-cast fidelity without pre-rendering artifacts; non-NVIDIA hardware [S1].

## Background
UE4-NeRF was introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" [S1]. It was developed to address the limitations of NeRF in real-time rendering of large-scale scenes, specifically combining NeRF with the Unreal Engine 4 rasterization pipeline. It builds upon concepts from Mobile-NeRF, Block-NeRF, and Instant-NGP [S1]. It is used for drone-captured large-scale scenes and evaluated on the Mega-NeRF public dataset [S1].
