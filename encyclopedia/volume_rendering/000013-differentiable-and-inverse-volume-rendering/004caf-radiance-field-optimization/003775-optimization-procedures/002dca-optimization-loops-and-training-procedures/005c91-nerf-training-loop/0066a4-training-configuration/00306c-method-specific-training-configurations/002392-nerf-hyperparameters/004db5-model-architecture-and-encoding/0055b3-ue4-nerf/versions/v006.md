# UE4-NeRF

Also called: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene

## Overview
UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale 3D scenes by partitioning the environment into sub-NeRFs represented by textured polygonal meshes [S1]. It solves the limitations of standard NeRFs regarding training time and real-time performance on large scales by integrating a neural shader into the Unreal Engine 4 (UE4) rasterization pipeline [S1]. Unlike sibling methods that rely on dense voxel grids or static hash tables for the entire scene, UE4-NeRF uses continuously optimized regular octahedra meshes and Level of Detail (LOD) hierarchies to achieve high frame rates at 4K resolution [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of posed images (typically from drone capture) with GPS metadata; camera poses; scene bounding box.
*   **Outputs:** A set of textured polygonal meshes (octahedra) with associated feature/opacity texture atlases; a compiled HLSL fragment shader for UE4; real-time rendered video frames.

**Data Structures:**
1.  **Scene Partitioning:** The large scene is divided into $N$ blocks. Each block has a training area slightly larger than the scene area to create overlapping borders for smooth transitions [S1].
2.  **Mesh Representation:** Each block is represented by a set of regular octahedra.
    *   **Geometry:** An octahedron has 6 vertices and 8 exterior triangular faces. The method uses 20 faces total (8 exterior, 12 interior) to handle tilted surfaces [S1].
    *   **Vertex Optimization:** Vertex positions are learnable parameters optimized during training [S1].
    *   **LOD Hierarchy:** Multiple levels of mesh detail are trained. Coarser meshes (fewer octahedra or simplified geometry) are used for higher observation heights [S1].
3.  **Texture Atlas:** Stores per-vertex or per-face feature vectors and opacity values. This replaces the dense grid lookup of Instant-NGP for the final rendering stage [S1].
4.  **Neural Shader (HLSL):** An implementation of the Encoder-Decoder MLP in High-Level Shading Language. It takes the feature vector from the texture atlas and the viewing direction as input, and outputs the final color [S1].

**Network Architecture:**
The method employs an Encoder-Decoder MLP structure [S1].
*   **Encoder Network ($E$):**
    *   Input: Positional information $\mathbf{p}_i$ encoded via multi-resolution hash encoding (from Instant-NGP) [S1].
    *   Structure: 4-layer MLP.
    *   Dimensions: $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
    *   Output: Opacity $\alpha_i$ and an 8-dimensional feature vector $\mathbf{M}_i$ [S1].
*   **Decoder Network ($D$):**
    *   Input: Feature vector $\mathbf{M}_i$ and viewing direction $\mathbf{d}_i$ encoded via Spherical Harmonics (SH) [S1].
    *   Structure: 3-layer MLP.
    *   Dimensions: $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
    *   Output: Final color $\mathbf{c}_i$ [S1].

**Numbered Steps:**

1.  **Coordinate Transformation:**
    *   Apply UE4 coordinate system: X-axis points East, Y-axis points South, Z-axis points Up [S1].
    *   Apply scale conversion: 100:1 (UE4 units to real-world units) using GPS data [S1].

2.  **Block Partitioning:**
    *   Divide the large-scale scene into multiple blocks [S1].
    *   Train a coarse segmentation model to capture overall terrain and building outlines [S1].
    *   Filter images for each sub-region and mask out pixels outside the scene area to handle overlapping borders [S1].

3.  **Mesh Initialization:**
    *   Initialize a $128 \times 128 \times 128$ grid for the block [S1].
    *   Select the center point of each grid cell along with its six neighbors (front, back, left, right, top, bottom) [S1].
    *   Construct regular octahedra from these points. Use 20 faces (8 exterior, 12 interior) to ensure stable convergence on tilted surfaces [S1].

4.  **Training Loop (Per Block):**
    *   **Ray Casting:** For each pixel, define ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$, where $\mathbf{d} = (\theta, \phi)$ is the viewing direction [S1].
    *   **Intersection:** Calculate the intersection of the ray with the polygonal meshes to determine sampling points [S1].
    *   **Encoding:** Encode the spatial position $\mathbf{p}_i$ of the intersection point using multi-resolution hash encoding [S1].
    *   **Encoder Forward:** Compute $\mathbf{M}_i, \alpha_i = E(\text{hash}(\mathbf{p}_i); \theta_E)$ [S1].
    *   **Direction Encoding:** Encode viewing direction $\mathbf{d}_i$ using Spherical Harmonics [S1].
    *   **Decoder Forward:** Compute color $\mathbf{c}_i = D(\mathbf{M}_i, \text{SH}(\mathbf{d}_i); \theta_D)$ [S1].
    *   **Loss Calculation:** Compare $\mathbf{c}_i$ with the ground truth pixel color. Use PSNR/SSIM and LPIPS for evaluation [S1].
    *   **Optimization:** Update $\theta_E$, $\theta_D$, and the vertex positions of the octahedra [S1].
    *   **Hardware:** Implement computationally intensive parts (hash encoding, MLP) in CUDA for GPU parallelization [S1].
    *   **Iterations:** Train for 80,000 epochs per block [S1].

5.  **Pre-rendering and LOD Extraction:**
    *   Extract polygonal meshes at different levels of detail (LOD) [S1].
    *   Generate texture atlases storing the optimized feature vectors and opacity [S1].
    *   Compile the Encoder-Decoder network into an HLSL fragment shader [S1].

6.  **Real-Time Rendering (UE4 Integration):**
    *   Import the extracted meshes and texture atlases into UE4 [S1].
    *   Assign the HLSL shader to the mesh materials [S1].
    *   Use LOD hierarchy: select coarser meshes for higher camera heights to maintain performance [S1].
    *   Render using UE4's rasterization pipeline [S1].

**Pseudocode:**

```python
# UE4-NeRF Training and Rendering Logic

class UE4NeRF:
    def __init__(self, scene_bounds, grid_size=128):
        self.scene_bounds = scene_bounds
        self.grid_size = grid_size
        # Encoder: 4-layer MLP (32->64->64->64->8)
        self.encoder_weights = initialize_mlp([32, 64, 64, 64, 8])
        # Decoder: 3-layer MLP (17->16->16->3)
        # Input dim 17 = 8 (features) + 9 (SH coefficients for degree 2)
        self.decoder_weights = initialize_mlp([17, 16, 16, 3])
        
        # Mesh parameters (vertices of octahedra)
        self.mesh_vertices = initialize_octahedra_grid(grid_size, scene_bounds)
        
        # Hash encoding table (from Instant-NGP)
        self.hash_table = initialize_hash_table()

    def coordinate_transform(self, gps_coords):
        """
        Transform GPS coordinates to UE4 space.
        X: East, Y: South, Z: Up. Scale 100:1.
        """
        # Implementation depends on specific GPS projection, 
        # assuming input is already in a local tangent plane or similar.
        ue4_x = gps_coords.x * 100.0
        ue4_y = -gps_coords.y * 100.0  # South is positive Y in UE4 if North is negative? 
                                       # Note: Source says Y points South. Standard UE4 Y is forward.
                                       # Assuming standard mapping where South is +Y.
        ue4_z = gps_coords.z * 100.0
        return Vector3(ue4_x, ue4_y, ue4_z)

    def encode_position(self, position):
        """Multi-resolution hash encoding."""
        return hash_encode(position, self.hash_table)

    def encode_direction(self, direction):
        """Spherical Harmonics encoding."""
        # Degree 2 SH has 9 coefficients
        return spherical_harmonic_basis(direction, degree=2)

    def encoder_forward(self, hash_encoded_pos):
        """
        E(hash(p_i); theta_E) -> M_i, alpha_i
        """
        x = hash_encoded_pos
        for layer in self.encoder_weights[:-1]:
            x = relu(linear(x, layer))
        # Last layer outputs 8 features + 1 opacity
        raw_output = linear(x, self.encoder_weights[-1])
        features = raw_output[:8]
        opacity_raw = raw_output[8]
        opacity = sigmoid(opacity_raw) # Ensure valid opacity
        return features, opacity

    def decoder_forward(self, features, sh_direction):
        """
        D(M_i, SH(d_i); theta_D) -> c_i
        Input concat: features (8) + SH (9) = 17
        """
        x = concat(features, sh_direction)
        for layer in self.decoder_weights[:-1]:
            x = relu(linear(x, layer))
        color = linear(x, self.decoder_weights[-1])
        color = sigmoid(color) # Ensure RGB in [0,1]
        return color

    def train_block(self, images, poses, epochs=80000):
        """
        Train a single block.
        """
        for epoch in range(epochs):
            for image, pose in zip(images, poses):
                # 1. Ray generation
                rays = generate_rays(pose, image.shape)
                
                # 2. Mesh Intersection
                # Find intersection points t for each ray with the octahedra mesh
                intersections = ray_mesh_intersect(rays, self.mesh_vertices)
                
                # 3. Sampling and Network Forward
                loss = 0
                for ray, intersection in zip(rays, intersections):
                    if intersection is None:
                        continue
                    
                    p_i = ray.origin + ray.direction * intersection.t
                    d_i = ray.direction
                    
                    # Encode
                    h_p = self.encode_position(p_i)
                    sh_d = self.encode_direction(d_i)
                    
                    # Encoder
                    M_i, alpha_i = self.encoder_forward(h_p)
                    
                    # Decoder
                    c_i = self.decoder_forward(M_i, sh_d)
                    
                    # Ground truth pixel color
                    c_gt = get_pixel_color(image, ray.pixel_coords)
                    
                    # Loss (e.g., MSE)
                    loss += mse(c_i, c_gt)
                
                # 4. Backpropagation
                # Update encoder weights, decoder weights, and mesh vertices
                gradients = compute_gradients(loss, [self.encoder_weights, self.decoder_weights, self.mesh_vertices])
                update_parameters(gradients)

    def render_realtime(self, camera_pose, resolution):
        """
        Render using UE4 rasterization pipeline.
        """
        # 1. Select LOD based on camera height
        lod_mesh = select_lod_mesh(self.mesh_vertices, camera_pose.height)
        
        # 2. Rasterize mesh to screen space
        screen_coords = rasterize(lod_mesh, camera_pose)
        
        # 3. For each pixel, fetch feature vector from texture atlas
        #    and compute color using HLSL shader logic
        for pixel in screen_coords:
            feature_vector = fetch_texture_atlas(pixel.uv)
            view_direction = compute_view_direction(pixel, camera_pose)
            sh_dir = self.encode_direction(view_direction)
            
            # Execute HLSL equivalent
            color = self.decoder_forward(feature_vector, sh_dir)
            
            set_pixel_color(pixel, color)
        
        return frame_buffer
```

**Parameters:**
*   **Grid Initialization Size:** $128 \times 128 \times 128$ [S1].
*   **Octahedron Faces:** 20 total (8 exterior, 12 interior) [S1].
*   **Encoder MLP Layers:** 4 layers, dimensions $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
*   **Decoder MLP Layers:** 3 layers, dimensions $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
*   **Training Hardware:** 1 Nvidia RTX 3090 GPU [S1].
*   **Training Iterations:** 80,000 epochs per block [S1].
*   **Coordinate System:** X=East, Y=South, Z=Up [S1].
*   **World Scale:** 100:1 [S1].
*   **Hash Encoding:** Multi-resolution hash encoding from Instant-NGP [S1].
*   **Directional Encoding:** Spherical Harmonics (SH) [S1].

**Edge Cases and Pitfalls:**
*   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces. UE4-NeRF mitigates this by using regular octahedra with 20 faces [S1].
*   **Transparency:** Mobile-NeRF cannot handle transparent/semi-transparent objects (water, glass) due to opacity binarization. UE4-NeRF stores opacity in texture maps, allowing semi-transparent rendering, though this increases computational overhead and reduces frame rates [S1].
*   **Pre-rendering Gaps:** Pre-rendering cannot capture rays from all viewing angles, potentially resulting in gaps or holes in the final scene [S1].
*   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, causing evaluation metrics (PSNR/SSIM) to underestimate actual reconstruction quality [S1].
*   **Memory Overhead:** Rendering large scenes (square kilometers) incurs significant memory overhead. Increasing accuracy further amplifies memory consumption [S1].
*   **Hardware Dependency:** Requires CUDA and NVIDIA GPUs [S1].

## Subtopics

### Block-NeRF
Partitions scenes into grid structures. UE4-NeRF is generally suitable for various scene types including mountainous terrain, unlike Block-NeRF which is limited to grid structures [S1].

### Mobile-NeRF
Uses octahedra but suffers from slow convergence on tilted surfaces and cannot handle semi-transparent objects. UE4-NeRF improves convergence and supports transparency via texture atlases [S1].

### Mega-NeRF
Trains hundreds of NeRFs for large scenes. UE4-NeRF trains significantly faster per block (40 mins vs 36 hours) and achieves higher FPS at higher resolutions (4K vs 800x800) [S1].

### Instant-NGP
Provides the multi-resolution hash encoding used in UE4-NeRF for training acceleration [S1].

## Operating characteristics
*   **Training Time:** 40 minutes per block on 1x RTX 3090. Total scene time: 1 hour + (40 minutes $\times$ n/4) for n blocks [S1]. This is ~1000x faster than Mobile-NeRF and ~54x faster per block than Mega-NeRF [S1].
*   **Rendering Performance:** Real-time rendering at 4K resolution with up to 43 FPS on level-1 mesh hierarchy. 50 FPS on full scene at 2K resolution; $\ge$70 FPS on individual blocks at 2K resolution [S1].
*   **Memory:** Significant memory overhead for large scenes (square kilometers). Memory consumption increases with accuracy [S1].
*   **Strengths:** Real-time interactive rendering of large-scale scenes; integration with UE4 allows for scene editing (importing .obj/.fbx); handles semi-transparent objects better than Mobile-NeRF; high fidelity on dense textures and small objects (e.g., power lines) compared to Mip-NeRF [S1].
*   **Limitations:** Requires NVIDIA GPUs and CUDA; pre-rendering artifacts (gaps/holes); exposure matching issues in UE4 affect metric evaluation; semi-transparent objects (vegetation) reduce frame rates due to computational overhead [S1].
*   **When to Use:** Large-scale outdoor scenes (farmland, construction sites, industrial parks) captured by drones where real-time interaction and scene editing are required [S1].
*   **When Not to Use:** Small-scale indoor scenes (overkill); scenes requiring extreme precision in exposure matching without post-processing; hardware-constrained environments without NVIDIA GPUs [S1].

## Background
UE4-NeRF was introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" [S1]. It was developed to address the limitations of NeRF in real-time rendering of large-scale scenes, specifically targeting applications in virtual reality, computer games, and the Metaverse [S1]. The method combines the neural representation of NeRF with the rasterization pipeline of Unreal Engine 4 (UE4) [S1]. It builds on techniques from Mobile-NeRF (octahedra representation), Block-NeRF (scene partitioning), and Instant-NGP (hash encoding) [S1]. The system was evaluated on drone-captured large-scale scenes (Farmland, Construction site, Industrial parks) and the Mega-NeRF public dataset [S1].
