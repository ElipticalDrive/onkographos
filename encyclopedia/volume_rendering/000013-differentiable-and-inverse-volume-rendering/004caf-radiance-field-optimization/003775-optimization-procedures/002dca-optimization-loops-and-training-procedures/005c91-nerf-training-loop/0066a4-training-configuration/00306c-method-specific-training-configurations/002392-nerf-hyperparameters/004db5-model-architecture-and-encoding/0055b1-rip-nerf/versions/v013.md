# Rip-NeRF

Also called: Rip-NeRF25k

## Overview
Rip-NeRF is a radiance field method that renders high-fidelity anti-aliased images by combining cone casting with an anisotropic 3D Gaussian characterization, Platonic Solid Projection, and Ripmap Encoding [S1]. It solves the problem of discrete point-based sampling artifacts in NeRF by using area-sampling strategies to accurately represent the continuous signals in the image plane [S1]. Unlike Zip-NeRF, which uses an effective but inefficient multi-sampling mechanism, Rip-NeRF employs efficient anisotropic area-sampling via Ripmap-Encoded Platonic Solids, resulting in significantly faster training, smaller model size, and higher rendering speed [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of calibrated multi-view 2D images.
*   **Outputs:** Rendered RGB images with density $\sigma$ and color $\mathbf{c}$ estimated per conical frustum.

**Data Structures:**
1.  **Ripmap Encoding:** A hierarchical feature grid.
    *   **Base Level ($R_{0,0}$):** Learnable tensor with shape $H \times W \times C$. Default dimensions: $H=512, W=512, C=16$ [S1].
    *   **Derived Levels:** Generated from the base level using average pooling, not learnable [S1].
2.  **Platonic Solid:** A geometric proxy for the 3D space.
    *   **Default:** Icosahedron with 10 unparalleled faces [S1].
    *   **Faces:** Denoted as $\{P_i \mid i = 1, \dots, n\}$, where $n=10$ for an icosahedron [S1].
3.  **Anisotropic 3D Gaussian:** Characterizes each conical frustum.
    *   **Parameters:** Mean $\boldsymbol{\mu}$ and Covariance $\boldsymbol{\Sigma}$ [S1].
4.  **Tiny MLP ($F_\theta$):** A small neural network that takes aggregated features and view direction to predict $\sigma$ and $\mathbf{c}$ [S1].
5.  **Binary Occupancy Grid:** Used to skip samples in empty areas (implemented via NerfAcc) [S1].

**Numbered Steps:**

1.  **Cone Casting and Frustum Division:**
    For each pixel, cast a cone into the scene and divide it into multiple conical frustums [S1]. This avoids discrete point-based sampling [S1].

2.  **Gaussian Characterization:**
    Characterize each conical frustum as an anisotropic 3D Gaussian parameterized by mean $\boldsymbol{\mu}$ and covariance $\boldsymbol{\Sigma}$ [S1].

3.  **Platonic Solid Projection:**
    Project the 3D Gaussian onto the faces of the Platonic solid to form 2D Gaussians [S1].
    *   For each face $P_i$, compute the projection matrix $M_i \in \mathbb{R}^{3 \times 2}$ mapping the 3D world coordinate system to the 2D coordinate system of plane $P_i$ [S1].
    *   Compute the projected mean $\boldsymbol{\mu}_{proj}$ and covariance $\boldsymbol{\Sigma}_{proj}$ for the 2D Gaussian on plane $P_i$ [S1].

4.  **Ripmap Encoding Query:**
    Query a feature vector $\mathbf{f}_i$ from the Ripmap Encoding of each plane $P_i$ using tetra-linear interpolation [S1].
    *   The interpolation position $(p_x, p_y)$ is determined by the mean $\boldsymbol{\mu}_{proj}$ of the 2D Gaussian [S1].
    *   The interpolation level $(l_x, l_y)$ is determined by the covariance $\boldsymbol{\Sigma}_{proj}$ of the 2D Gaussian [S1].
    *   The levels are derived from the base level $R_{0,0}$ using average pooling operations defined in Equation (1) of the source [S1]:
        $$
        R_{i,j} = \begin{cases} 
        \text{Avg}_{2\times1} R_{i, j-1} & \text{if } j \neq 0 \\
        \text{Avg}_{1\times2} R_{i-1, j} & \text{if } i \neq 0 \text{ \& } j = 0 \\
        R_{0,0} & \text{otherwise}
        \end{cases}
        $$
        where $i$ and $j$ are indices of levels in the $x$ and $y$ directions [S1].
    *   The hyper-parameter $w$ in the level calculation (Eq. 3 in source) is set to 2.0 to adjust the probability mass coverage of the Gaussian footprint [S1].

5.  **Feature Aggregation:**
    Concatenate all feature vectors $\{\mathbf{f}_i \mid i = 1, \dots, n\}$ from the corresponding planes $\{P_i \mid i = 1, \dots, n\}$ to form the final feature vector $\mathbf{f}$ of the 3D Gaussian [S1].

6.  **Density and Color Estimation:**
    Concatenate the aggregated feature vector $\mathbf{f}$ with the encoded view direction $\mathbf{d}$ [S1]. Pass this combined vector through the tiny MLP $F_\theta$ to estimate the density $\sigma$ and color $\mathbf{c}$ of the conical frustum [S1].

7.  **Volume Rendering:**
    Render the pixel color using the estimated color $\mathbf{c}$ and density $\sigma$ via standard volume rendering [S1].

8.  **Optimization:**
    Optimize the system end-to-end using a photometric loss between rendered and observed images [S1].
    *   **Area Loss:** Scale the photometric loss for each pixel by incorporating the area of its footprint on the image plane, denoted as $L_{area}$ [S1]. This follows the approach in Mip-NeRF and Tri-MipRF [S1].

## Subtopics

### Ripmap Encoding
A hierarchical feature grid structure that uses average pooling to derive lower levels from a learnable base level, enabling efficient anisotropic area sampling [S1].

### Platonic Solid Projection
A technique to project 3D Gaussians onto the faces of a Platonic solid (e.g., icosahedron) to form 2D Gaussians, which are then sampled using Ripmap Encoding [S1].

### Area Loss ($L_{area}$)
A loss scaling factor that incorporates the area of the pixel footprint on the image plane to make the photometric loss area-aware, improving anti-aliasing [S1].

## Operating characteristics
*   **Training Time:** 2.6 hours on NVIDIA A100-SXM4-80GB GPU for Rip-NeRF (120k iterations) [S1]. Rip-NeRF25k (25k iterations) takes 32 minutes [S1].
*   **Model Size:** 160 MB for Rip-NeRF [S1].
*   **GPU Memory:** 20 GB during training [S1].
*   **Rendering Speed:** 3 FPS in the experimental setting [S1].
*   **Comparison with Zip-NeRF:**
    *   **Training Time:** Rip-NeRF (2.6h) vs Zip-NeRF (4.5h) [S1].
    *   **Model Size:** Rip-NeRF (160 MB) vs Zip-NeRF (592 MB) [S1].
    *   **Rendering Speed:** Rip-NeRF (3 FPS) vs Zip-NeRF (0.25 FPS) [S1].
    *   **Quality:** Zip-NeRF has slightly better SSIM, but Rip-NeRF outperforms in PSNR and LPIPS [S1].
    *   **Memory:** Zip-NeRF requires ~80 GB GPU memory, while Rip-NeRF requires 20 GB [S1].
*   **Strengths:** High-fidelity anti-aliased rendering, efficient anisotropic area-sampling, compact model size, fast training and rendering [S1].
*   **Limitations:** Designed for bounded scenes (unlike Zip-NeRF which targets unbounded scenes) [S1].

## Background
Rip-NeRF was introduced in the paper "Rip-NeRF: Anti-aliasing Radiance Fields with Ripmap-Encoded Platonic Solids" [S1]. It builds upon previous work in hybrid representations and area-sampling, such as Mip-NeRF, Tri-MipRF, and Zip-NeRF [S1]. The method was developed to address the inefficiency of multi-sampling mechanisms in existing methods like Zip-NeRF, offering a more compact and faster alternative for high-fidelity rendering [S1].
