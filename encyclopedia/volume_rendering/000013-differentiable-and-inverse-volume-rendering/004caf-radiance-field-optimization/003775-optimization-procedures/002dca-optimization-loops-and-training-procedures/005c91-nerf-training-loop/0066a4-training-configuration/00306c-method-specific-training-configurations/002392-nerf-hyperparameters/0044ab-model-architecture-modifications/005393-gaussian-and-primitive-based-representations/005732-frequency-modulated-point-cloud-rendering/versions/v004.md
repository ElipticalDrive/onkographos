# Frequency-Modulated Point Cloud Rendering

Also called: AFNet, Adaptive Frequency Net, Adaptive Frequency Net (AFNet) based rendering, FreqPCR, Frequency-Modulated Radiance Mapping

## Overview
Frequency-Modulated Point Cloud Rendering (also known as AFNet) is a real-time rendering pipeline that represents a scene as a discrete point cloud and reconstructs high-fidelity radiance fields using an Adaptive Frequency Net (AFNet) [S1]. It solves the problem of spectral bias in standard implicit neural representations, where Multi-Layer Perceptrons (MLPs) with ReLU activations fail to reconstruct high-frequency textures, by injecting locally predicted frequency and phase parameters into the activation layers [S1]. Unlike its siblings, it achieves real-time performance (39.27 FPS on NeRF-Synthetic) and supports direct object-level editing and scene composition by operating on explicit point geometry rather than a global implicit field [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ 3D points $\mathcal{P} = \{\mathbf{p}_i\}_{i=1}^N$, where each point $\mathbf{p}_i$ has an initial position, an initial feature vector, and an opacity value. Camera parameters (view and projection matrices) are required for rasterization.
*   **Output:** A rendered RGB image and optionally a depth buffer.

**Data Structures:**
1.  **Point Cloud:** A list of $N$ points. Each point $i$ stores:
    *   $\mathbf{p}_i \in \mathbb{R}^3$: 3D position.
    *   $\mathbf{f}_i \in \mathbb{R}^C$: Feature vector (initially learned or initialized).
    *   $\sigma_i \in [0, 1]$: Opacity.
2.  **AFNet Module:**
    *   **Hypernetwork:** A two-layer MLP that takes a point's spatial coordinate $\mathbf{p}_i$ as input and outputs adaptive frequency $\omega_i \in \mathbb{R}$ and phase $\phi_i \in \mathbb{R}$.
    *   **AF Layer:** An activation function defined by the formula below.

**Numbered Steps:**

1.  **Point Cloud Geometry Optimization (Preprocessing):**
    *   Standard surface point-based methods keep only the closest point per ray, which prevents geometry optimization [S1].
    *   This method uses volume rendering as a preprocessing step to optimize the point cloud geometry [S1].
    *   Multiple points are kept in the pixel buffer. The opacity $\sigma_i$ of each point is learned via differentiable volume rendering [S1].
    *   This step improves PSNR by 2-4dB for poorly reconstructed scenes and avoids artifacts [S1].

2.  **Frequency Estimation via Hypernetwork:**
    *   For each point $i$, the spatial coordinate $\mathbf{p}_i$ is passed through the two-layer MLP hypernetwork [S1].
    *   The hypernetwork outputs the adaptive frequency $\omega^{(i)}$ and phase $\phi^{(i)}$ for each layer of the radiance mapping network [S1].
    *   The hypernetwork learns these parameters without explicit frequency supervision, predicting high frequencies for textured regions and low frequencies for smooth regions [S1].

3.  **Radiance Mapping with Adaptive Frequency Activation:**
    *   The radiance mapping network processes the point features through several layers.
    *   In each layer $l$, the input feature $\mathbf{X}^{(l)} \in \mathbb{R}^{M \times C}$ (where $M$ is the number of points and $C$ is the feature dimension) is processed by the Adaptive Frequency (AF) Layer [S1].
    *   The AF Layer computes the output $\mathbf{Y}^{(l)}$ using the predicted $\omega^{(l)}$ and $\phi^{(l)}$:
        $$ \mathbf{Y}^{(l)} = \mathbf{X}^{(l)} \circ \sin(\omega^{(l)} \circ \mathbf{X}^{(l)} + \phi^{(l)}) $$
        where $\circ$ denotes the Hadamard (element-wise) product [S1].
    *   The dimensions of $\omega^{(l)}$ and $\phi^{(l)}$ are $\mathbb{R}^{M \times 1}$ and are broadcast to $\mathbb{R}^{M \times C}$ during computation [S1].
    *   The final layer outputs the raw RGB values [S1].

4.  **Differentiable Rasterization and Rendering:**
    *   The optimized point cloud is projected to 2D screen space.
    *   Points are sorted by depth.
    *   Alpha compositing is performed to blend the contributions of points along each ray, producing the final image [S1].
    *   Gradients flow back through the compositing and AF layers to update point positions, opacities, features, and hypernetwork parameters [S1].

5.  **Object Editing and Scene Composition (Optional):**
    *   **Editing:** Users edit the point cloud directly. A deformation field between the original and deformed 3D space is obtained by querying the transformations performed on the point cloud [S1].
    *   **Composition:** Multiple scenes are combined at the pixel level using a masking strategy based on the depth buffer to avoid cross-scene training [S1].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class HyperNetwork(nn.Module):
    """
    Two-layer MLP to predict adaptive frequency and phase for each point.
    Input: Point coordinates (N, 3)
    Output: Frequency (N, 1), Phase (N, 1)
    """
    def __init__(self, hidden_dim=64):
        super(HyperNetwork, self).__init__()
        self.fc1 = nn.Linear(3, hidden_dim)
        self.fc2 = nn.Linear(hidden_dim, 2) # Outputs both omega and phi

    def forward(self, points):
        # points: (N, 3)
        h = F.relu(self.fc1(points))
        out = self.fc2(h)
        omega = out[:, 0:1] # (N, 1)
        phi = out[:, 1:2]   # (N, 1)
        return omega, phi

class AdaptiveFrequencyLayer(nn.Module):
    """
    AF Layer: Modulates input features with adaptive frequency and phase.
    Formula: Y = X * sin(omega * X + phi)
    """
    def forward(self, X, omega, phi):
        # X: (N, C)
        # omega: (N, 1)
        # phi: (N, 1)
        # Broadcast omega and phi to (N, C)
        omega_expanded = omega.expand_as(X)
        phi_expanded = phi.expand_as(X)
        
        # Compute sin(omega * X + phi)
        sin_term = torch.sin(omega_expanded * X + phi_expanded)
        
        # Hadamard product
        Y = X * sin_term
        return Y

class RadianceMappingNetwork(nn.Module):
    """
    The main network for radiance mapping from point features.
    """
    def __init__(self, input_dim, hidden_dim, output_dim=3, num_af_layers=4):
        super(RadianceMappingNetwork, self).__init__()
        self.input_dim = input_dim
        self.output_dim = output_dim
        self.num_af_layers = num_af_layers
        
        # Linear layers
        self.layers = nn.ModuleList()
        for i in range(num_af_layers):
            in_ch = input_dim if i == 0 else hidden_dim
            out_ch = hidden_dim
            self.layers.append(nn.Linear(in_ch, out_ch))
        
        # Final linear layer to RGB
        self.final_layer = nn.Linear(hidden_dim, output_dim)
        
        # Hypernetwork for each AF layer
        self.hypernetworks = nn.ModuleList([
            HyperNetwork() for _ in range(num_af_layers)
        ])
        
        # AF Layers
        self.af_layers = nn.ModuleList([
            AdaptiveFrequencyLayer() for _ in range(num_af_layers)
        ])

    def forward(self, points, features):
        """
        points: (N, 3)
        features: (N, input_dim)
        Returns: RGB (N, 3)
        """
        x = features
        for i in range(self.num_af_layers):
            # Get adaptive parameters from hypernetwork
            omega, phi = self.hypernetworks[i](points)
            
            # Linear transformation
            x = self.layers[i](x)
            
            # Apply AF Layer
            x = self.af_layers[i](x, omega, phi)
            
            # ReLU activation after AF layer? 
            # The paper shows ReLU in Fig 3 for some layers, but the core formula is the AF layer.
            # Standard practice in MFN/AFNet often applies ReLU after the modulation or before.
            # Based on Fig 3, ReLU is applied after the AF layer in some stages.
            # We assume ReLU is applied after the AF layer for intermediate layers.
            if i < self.num_af_layers - 1:
                x = F.relu(x)
        
        # Final output
        rgb = self.final_layer(x)
        return rgb
```

**Parameters:**
*   **Hypernetwork:** Two-layer MLP [S1].
*   **AF Layer:** Sinusoidal activation $\sin(\omega X + \phi)$ followed by element-wise multiplication with input $X$ [S1].
*   **Rendering Speed:** 39.27 FPS on NeRF-Synthetic dataset [S1].

**Edge Cases and Pitfalls:**
*   **Spectral Bias:** Standard MLPs with ReLU have strong spectral bias towards low-frequency signals, limiting high-frequency reconstruction [S1]. The AFNet mitigates this by adapting frequencies locally.
*   **Geometry Optimization:** Previous surface point-based works could not optimize point cloud geometry because they kept only the closest point as surface estimation for each ray [S1]. This method avoids that by using volume rendering to keep multiple points and learn opacity [S1].
*   **Cross-Scene Training:** When composing scenes, a masking strategy based on the depth buffer is required to avoid cross-scene training artifacts [S1].

## Subtopics

### Differentiable Primitive Assembly
Uses implicit signed distance functions (SDFs) for quadrics and combines them via soft boolean operations. It does not use point clouds or frequency modulation [13657-differentiable-primitive-assembly.md].

### Viewing Direction Gaussian Splatting
Projects 3D Gaussians to 2D screen space as ellipsoids and rasterizes them. It uses explicit Gaussian parameters rather than implicit radiance mapping with frequency modulation [14273-viewing-direction-gaussian-splatting.md].

### Point-NeRF Representation
Queries local neighborhoods (K-nearest neighbors within radius $R$) to aggregate features via inverse distance weighting. It does not use adaptive frequency modulation via a hypernetwork [15538-point-nerf-representation.md].

## Operating characteristics
*   **Time Complexity:** Real-time rendering speed of 39.27 FPS on NeRF-Synthetic [S1].
*   **Speed Comparison:** 1700x faster than NeRF and 37x faster than CCNeRF [S1].
*   **Quality:** Improves rendering PSNR by 2-4dB for poorly reconstructed scenes compared to methods that do not optimize point cloud geometry [S1].
*   **Strengths:** High-fidelity local detail reconstruction, real-time rendering, user-friendly object-level editing, and scene composition [S1].
*   **Limitations:** Requires a preprocessing step for geometry optimization. Performance depends on the quality of the initial point cloud and the hypernetwork's ability to predict appropriate frequencies [S1].
*   **When to Use:** When real-time rendering and editable point-based representations are required, and high-frequency texture reconstruction is critical [S1].
*   **When Not to Use:** When global implicit representations are preferred, or when editing capabilities are not needed and simpler rasterization suffices.

## Background
*   **Origin:** Proposed by Zhang et al. in "Frequency-Modulated Point Cloud Rendering with Easy Editing" (CVPR 2023) [S1].
*   **History:** The method addresses the limitations of NeRF-based editing, which often requires pre-trained segmentation models, and the spectral bias of standard MLPs in implicit neural representations [S1]. It builds on the idea of using hypernetworks to generate weights for larger networks [S1].
*   **Usage:** Evaluated on NeRF-Synthetic, ScanNet, DTU, and Tanks and Temples datasets [S1].
