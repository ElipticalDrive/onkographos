# Neural Multi-View Image Reconstruction with Hash Encoding

Also called: Ours (multi-view)

## Overview
This method performs neural multi-view image reconstruction and novel view synthesis by combining a hash-encoded geometry representation with a separate light field network [S1]. It solves the problem of reconstructing high-frequency geometric details and textureless areas, which are often noisy or rough in methods like NeRF that lack direct constraints on volume density [S1]. It distinguishes itself from siblings like [Voxel-based Radiance Fields](11470-voxel-based-radiance-fields.md) by using a sparse hash grid instead of a dense voxel grid, and from [NeuS](13480-g-nelf.md) by employing a specific SDF thresholding strategy for invalid point elimination and a deeper geometry network [S1].

## How it works
The method consists of two primary neural networks: a geometry network that outputs Signed Distance Function (SDF) values and features, and a light field network that predicts color. The geometry is represented using a multi-resolution hash encoding.

### Inputs and Outputs
*   **Inputs:** Multi-view images of the scene; camera parameters (view direction $\mathbf{v}$) for each pixel.
*   **Outputs:** Reconstructed 3D geometry (extracted via marching cubes) and novel view images.

### Data Structures
**Hash Encoding Grid:**
*   Structure: A set of hash tables mapping spatial coordinates to feature vectors.
*   Layers: 16 layers [S1].
*   Feature Dimension: 2 per grid feature in each layer [S1].
*   Hashing: Coordinates are hashed to indices in these tables. The features from all 16 layers are concatenated to form the final geometry feature vector for a query point [S1].

**Network Architectures:**
1.  **Geometry Network:**
    *   Type: MLP with 6 layers [S1].
    *   Input: Fourier positional encoding of spatial location $\mathbf{x}$ (dimension 6) [S1].
    *   Internal Connection: The input to the third layer concatenates the hash encoding of spatial location $\text{enc}(\theta_h, \mathbf{x})$ and the output of the second hidden layer [S1].
    *   Output: SDF value $\phi(\mathbf{x})$ and a geometry feature vector.
2.  **Light Field Network:**
    *   Type: MLP with 4 hidden layers [S1].
    *   Hidden Units: 256 units per layer [S1].
    *   Input: Concatenation of:
        *   Fourier positional encoding of view direction $\mathbf{v}$ (dimension 6) [S1].
        *   Gradient $\mathbf{n}$ (normal vector) derived from the geometry network's SDF [S1].
        *   Geometry feature vector output from the connected layer of the geometry network [S1].
    *   Output: Color $\mathbf{c}$.

### Training Procedure
1.  **Sampling:** Use a hierarchical sampling strategy to sample points on rays [S1].
2.  **Invalid Point Elimination:** For each ray, calculate the mean of the SDF values of the sampled points. Use this mean as a threshold to eliminate invalid sampled points (points likely far from the surface or in empty space) [S1].
3.  **Rendering:** Render the image using the standard differentiable volume rendering equation [11470-voxel-based-radiance-fields]:
    $$
    \hat{C}(r) = \sum_{k=1}^{N} w_k \mathbf{c}_k, \quad w_k = T_k \alpha_k, \quad T_k = \prod_{j=1}^{k-1} (1 - \alpha_j)
    $$
    where $\alpha_k = 1 - e^{-\sigma_k \delta_k}$. Note: While the source describes SDF-based reconstruction, the rendering step utilizes volume rendering with opacity $\alpha$ derived from density $\sigma$. The relationship between SDF $\phi$ and density $\sigma$ is implied to be handled via the standard softplus or similar approximation used in SDF-based NeRFs, though the exact formula linking $\phi$ to $\sigma$ is not explicitly detailed in the provided notes beyond the standard volume rendering context [S1, 11470-voxel-based-radiance-fields].
4.  **Loss Function:** The training minimizes a loss function involving weights $\alpha, \beta, \gamma$ set to $0.1, 0.1, 5 \times 10^{-4}$ respectively [S1]. The specific terms (e.g., photometric loss, SDF loss) are not detailed in the provided notes, but the weights suggest a multi-term loss [S1].
5.  **Geometry Extraction:** After training, extract the final geometry using the marching cubes algorithm at a resolution of $512^3$ [S1].

        self.feature_dim = feature_dim
        # Initialize hash tables with learnable features
        # In practice, this involves hashing coordinates to indices
        # and looking up features from a large tensor of shape [num_layers, num_hashes, feature_dim]
        self.grids = nn.ParameterList([
            nn.Parameter(torch.randn(1000000, feature_dim)) for _ in range(num_layers)
        ])
        self.num_hashes = 1000000

    def forward(self, x):
        # x: [N, 3] coordinates
        features = []
        for i in range(self.num_layers):
            # Hash coordinates to indices
            # This is a simplified representation of the hash function
            # Real implementation uses a hash function like xxHash
            indices = self.hash_function(x, i)
            # Gather features
            grid_features = self.grids[i][indices]
            features.append(grid_features)
        # Concatenate features from all layers
        return torch.cat(features, dim=-1)

        self.fc4 = nn.Linear(256, 256)
        self.fc5 = nn.Linear(256, 256)

        # Geometry feature dim = 32

        self.fc1 = nn.Linear(input_dim, 256)
        self.fc2 = nn.Linear(256, 256)
        self.fc3 = nn.Linear(256, 256)
        self.fc4 = nn.Linear(256, 3) # Output color

        h1 = torch.relu(self.fc1(input_vec))
        h2 = torch.relu(self.fc2(h1))
        h3 = torch.relu(self.fc3(h2))
        color = torch.sigmoid(self.fc4(h3))
        return color

class FourierPositionalEncoding(nn.Module):
    def __init__(self, dim):
        super().__init__()
        self.dim = dim
        # Frequencies for positional encoding
        self.frequencies = torch.logspace(0, dim-1, steps=dim)

    def forward(self, x):
        # x: [N, 3]
        # Expand x to [N, 3, 1] and frequencies to [1, 1, dim]
        # Result: [N, 3, dim]

        # Apply sin and cos
        encoded = torch.cat([torch.sin(scaled_x), torch.cos(scaled_x)], dim=-1)
        return encoded.view(x.shape[0], -1)

### Edge Cases and Pitfalls
*   **Invalid Points:** The method explicitly eliminates invalid sampled points using the mean SDF as a threshold. Failure to do so may lead to noise in the reconstructed geometry [S1].
*   **Textureless Areas:** Baseline methods like NeuS, IDR, VolSDF, and UNISURF perform poorly in textureless areas. This method is designed to handle them better, but proper sampling and thresholding are critical [S1].
*   **Memory Usage:** While efficient compared to dense voxels, the hash grid still requires significant memory. The method uses 5 GB for multi-view reconstruction, compared to 6.5 GB for IDR and 7 GB for NeuS [S1].

## Operating characteristics
*   **Time Complexity:** Training time is 1.8 hours for multi-view reconstruction, significantly faster than IDR (5.2 hours), NeuS (7.2 hours), UNISURF (21 hours), VolSDF (9 hours), and NeRF (9.1 hours) [S1].
*   **Memory Complexity:** Memory usage is 5 GB, lower than IDR (6.5 GB), NeuS (7 GB), UNISURF (6 GB), VolSDF (13.8 GB), and NeRF (8 GB) [S1].
*   **Performance:**
    *   **PSNR:** Mean PSNR of 30.85 dB, outperforming IDR (23.20 dB) and NeuS (29.66 dB) [S1].
    *   **Chamfer Distance:** Mean Chamfer-L2 distance of $0.72 \times 10^{-6}$, outperforming IDR ($0.90 \times 10^{-6}$) and NeuS ($0.77 \times 10^{-6}$) [S1].
*   **Rays per Iteration:** 512 rays per iteration [S1].
*   **Strengths:** Reconstructs more geometric detail than baselines, especially in textureless areas and high-frequency details (e.g., bird feathers) [S1].
*   **Limitations:** The source does not explicitly list limitations, but the method relies on the effectiveness of the SDF thresholding and the capacity of the hash grid [S1].
