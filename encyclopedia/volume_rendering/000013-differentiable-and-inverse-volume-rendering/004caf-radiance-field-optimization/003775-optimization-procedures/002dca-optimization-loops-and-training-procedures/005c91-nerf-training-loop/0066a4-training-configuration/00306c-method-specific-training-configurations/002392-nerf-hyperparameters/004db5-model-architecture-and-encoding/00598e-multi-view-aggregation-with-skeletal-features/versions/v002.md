# Multi-view Aggregation with Skeletal Features

Also called: Multi-view aggregation of skeletal and query features

## Overview
This method improves pose refinement and feature representation in articulated neural radiance fields by incorporating multi-view constraints when motion is captured from multiple cameras. It differs from single-view approaches by averaging joint rotation estimates across views without requiring camera calibration, and combines time-augmented skeletal features with pixel-aligned image features via a cross-attention mechanism to produce robust density and color predictions [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $C$ input images $I_{c,t}$ at time $t$; a query 3D point $x \in \mathbb{R}^3$; viewing direction $d \in \mathbb{R}^3$; skeletal pose parameters $\theta_k$; and camera parameters.
*   **Outputs:** Predicted density $\tilde{\tau}_t(x)$ and color $\tilde{r}^g_{bt}(x)$ for the query point.

**Data Structures:**
*   Skeletal features $s^0_{c,t}$: Retrieved via trilinear interpolation in SMPL space using SparseConvNet. Dimension $d$.
*   Pixel-aligned features $p^x_{c,t}$: Retrieved by projecting $x$ onto image $I_{c,t}$. Dimension $d$.
*   Keys and Values: Learned linear projections $k(\cdot)$ and $v(\cdot)$ mapping features to key/value spaces.

**Steps:**

1.  **Pose Initialization (Multi-view Constraint):**
    For each joint $k$, initialize the rotation $\theta_k$ by averaging individual joint rotation estimates from all $V$ views $v \in [1, \dots, V]$. Rotations are relative to the parent and root, allowing averaging without camera calibration. Global position and orientation remain view-specific [S1, unofficial].
    
    The multi-view loss function used for refinement is:
    $$
    L_{MV}(\theta, \phi) = \sum_{v} \sum_{k} \left( d(C_\phi(\theta_k, \omega_{k,0}^{(v)}, \omega_{k,1}^{(v)}), I_k) + \lambda_\theta \|\theta_k - \hat{\theta}_k\|^2 + \lambda_t \|\frac{\partial^2 \theta_k}{\partial t^2}\|^2 \right)
    $$
    where $\theta_k$ is shared across all views, but $\omega_{k,0}^{(v)}$ and $\omega_{k,1}^{(v)}$ (relative camera position and orientation) are estimated independently per view [S1, unofficial].

2.  **Feature Retrieval:**
    *   Retrieve skeletal feature $s^0_{c,t}$ at query location $x$ via trilinear interpolation in SMPL space [S2, unofficial].
    *   Sample pixel-aligned image feature $p^x_{c,t}$ via direct $\mathbb{R}^3 \rightarrow \mathbb{R}^2$ projection of $x$ on image $I_{c,t}$ [S2, unofficial].

3.  **Multi-view Cross-Attention:**
    Construct attention weights $mv\_att^x \in \mathbb{R}^{C \times C}$ using dot product between skeletal keys and pixel-aligned keys, scaled by dimension:
    $$
    mv\_att^x = \psi \left( \frac{1}{\sqrt{d}} k(s^0_{1:C,t}) \cdot k(p^x_{1:C,t})^T \right)
    $$
    where $\psi$ is the softmax operator along the second axis (columns) [S2, unofficial].

4.  **View-wise Representation:**
    Compute view-wise representation $z^x_{1:C,t}$ by combining weighted pixel-aligned values and skeletal values:
    $$
    z^x_{1:C,t} = mv\_att^x \cdot v(p^x_{1:C,t}) + v(s^0_{1:C,t})
    $$
    where $z^x_{c,t} \in \mathbb{R}^d$ [S2, unofficial].

5.  **Meta-time and Meta-view Representation:**
    Compute the final representation $z^x_t$ as the mean across all views:
    $$
    z^x_t = \frac{1}{C} \sum_{c=1}^{C} z^x_{c,t}
    $$
    [S2, unofficial].

6.  **Density and Color Prediction:**
    *   Density $\tilde{\tau}_t(x)$ is computed using an MLP $\text{MLP}_\tau$ with four linear layers applied to $z^x_t$ [S2, unofficial].
    *   Color $\tilde{r}^g_{bt}(x)$ is computed using an MLP $\text{MLP}_{rgb}$ with two linear layers. The input is the mean of pixel-aligned values $v(p^x_{c,t})$ concatenated with the positional encoding $\gamma_d(d)$ of the viewing direction $d$:
        $$
        \tilde{r}^g_{bt}(x) = \text{MLP}_{rgb} \left( \frac{1}{C} \sum_{c=1}^{C} v(p^x_{c,t}) ; \gamma_d(d) \right)
        $$
        where $\gamma_d: \mathbb{R}^3 \rightarrow \mathbb{R}^{6 \times l}$ is a positional encoding with $2 \times l$ basis functions [S2, unofficial].

**Pseudocode:**

```python
def multi_view_aggregation(query_point_x, viewing_direction_d, images, skeletal_features, num_views, feature_dim):
    """
    Computes density and color for a query point using multi-view aggregated features.
    
    Args:
        query_point_x: 3D point (x, y, z)
        viewing_direction_d: 3D viewing direction vector
        images: List of C images I_{c,t}
        skeletal_features: Pre-computed skeletal features in SMPL space
        num_views: Number of views C
        feature_dim: Dimension d of features
        
    Returns:
        density: Scalar density value
        color: RGB color vector
    """
    
    # Step 1: Retrieve features
    skeletal_keys = []
    pixel_keys = []
    pixel_values = []
    skeletal_values = []
    
    for c in range(num_views):
        # Retrieve skeletal feature via trilinear interpolation in SMPL space
        s0_c_t = interpolate_skeletal_feature(skeletal_features, query_point_x)
        
        # Sample pixel-aligned feature via direct projection
        p_x_c_t = project_to_image(images[c], query_point_x)
        
        # Project to keys and values using learned layers
        k_s = linear_projection_keys(s0_c_t)
        k_p = linear_projection_keys(p_x_c_t)
        v_p = linear_projection_values(p_x_c_t)
        v_s = linear_projection_values(s0_c_t)
        
        skeletal_keys.append(k_s)
        pixel_keys.append(k_p)
        pixel_values.append(v_p)
        skeletal_values.append(v_s)
        
    # Stack into matrices: C x d
    S_keys = stack(skeletal_keys) # C x d
    P_keys = stack(pixel_keys)    # C x d
    P_vals = stack(pixel_values)  # C x d
    S_vals = stack(skeletal_values) # C x d
    
    # Step 2: Compute Attention Weights
    # Dot product scaled by 1/sqrt(d)
    dot_products = matmul(S_keys, transpose(P_keys)) / sqrt(feature_dim)
    
    # Softmax along the second axis (columns)
    # mv_att is C x C
    mv_att = softmax(dot_products, axis=1)
    
    # Step 3: Compute View-wise Representation
    # z_{1:C,t} = mv_att * v(P) + v(S)
    # mv_att (C x C) @ P_vals (C x d) -> C x d
    weighted_pixel_vals = matmul(mv_att, P_vals)
    
    # Add skeletal values
    z_viewwise = weighted_pixel_vals + S_vals # C x d
    
    # Step 4: Compute Meta-time and Meta-view Representation
    # Mean across views
    z_meta = mean(z_viewwise, axis=0) # d
    
    # Step 5: Compute Density
    # MLP_tau with 4 linear layers
    density = mlp_density(z_meta)
    
    # Step 6: Compute Color
    # Mean of pixel-aligned values
    mean_pixel_vals = mean(P_vals, axis=0) # d
    
    # Positional encoding of viewing direction
    pos_enc = positional_encoding(viewing_direction_d)
    
    # Concatenate and pass through MLP_rgb (2 linear layers)
    color_input = concatenate(mean_pixel_vals, pos_enc)
    color = mlp_color(color_input)
    
    return density, color
```

**Parameters:**
*   $\lambda_\theta, \lambda_t$: Regularization weights for pose refinement [S1, unofficial].
*   $d$: Feature dimension [S2, unofficial].
*   $l$: Half the number of basis functions in positional encoding [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Camera Calibration:** The method assumes relative camera position and orientation are unknown or uncalibrated, relying on relative rotations for averaging [S1, unofficial].
*   **Projection Errors:** Direct $\mathbb{R}^3 \rightarrow \mathbb{R}^2$ projection may fail if the query point is not visible in a view; handling of occluded views is not explicitly detailed in the provided notes [S2, unofficial].
*   **Sparse Convolution:** Requires efficient implementation of SparseConvNet for trilinear interpolation in SMPL space [S2, unofficial].

## Subtopics

### [SparseConvNet-based Skeletal Feature Sampling](16444-sparseconvnet-based-skeletal-feature-sampling.md)
Samples time-augmented skeletal features at arbitrary 3D query points by diffusing discrete skeletal features into a continuous 3D volume using sparse convolutions. It differs from dense voxelization by processing only occupied voxels, improving efficiency for large 3D spaces. Choose this when memory efficiency for large scenes is critical.

## Operating characteristics
*   **Time Complexity:** Depends on the number of views $C$, the number of joints $L$, and the feature dimension $d$. The cross-attention mechanism involves matrix multiplications of size $C \times C$ and $C \times d$, making it $O(C^2 d + C d^2)$ per query point.
*   **Memory Complexity:** Requires storing features for all views and joints. Sparse convolutions reduce memory usage compared to dense voxelization [S2, unofficial].
*   **Strengths:** Improves pose refinement without camera calibration; effectively combines geometric (skeletal) and appearance (image) features; robust to multi-view inconsistencies via attention [S1, S2, unofficial].
*   **Limitations:** Requires accurate skeletal pose estimation; sensitive to projection errors if views are occluded; computational cost increases with the number of views [S1, S2, unofficial].
*   **When to Use:** Multi-view human performance rendering where camera calibration is unavailable or unreliable.
*   **When Not to Use:** Single-view scenarios; scenes without articulated human subjects.

## Background
Originated in the context of Articulated Neural Radiance Fields (A-NeRF) and Neural Human Performer. A-NeRF introduced multi-view constraints for pose refinement using relative rotations [S1, unofficial]. Neural Human Performer extended this by aggregating skeletal and pixel-aligned features via cross-attention for generalizable radiance fields [S2, unofficial].
