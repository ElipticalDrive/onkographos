# Frequency-Modulated Position Encoding

Also called: FM-NeRF Encoding, Frequency-Modulated Point Cloud Rendering with Easy Editing

## Overview
Frequency-Modulated Position Encoding (FMPE) is a coordinate encoding scheme used in point-based radiance field optimization to map raw 3D spatial coordinates and viewing directions into a high-dimensional feature space [S1]. It addresses the limitation of standard sinusoidal positional encoding by narrowing the encoding interval, thereby providing finer-grained basis function support for frequency modulation [S1]. Unlike standard NeRF which uses integer powers of 2, FMPE uses fractional exponents (specifically powers of $2^{0.5}$) to distribute frequencies more densely across the spectrum, allowing the network to capture high-frequency details more effectively with fewer bands [S1].

## How it works
FMPE transforms input vectors (spatial position $\mathbf{p}$ or view direction $\mathbf{d}$) into a concatenated vector of sine and cosine functions. The transformation is defined by a set of frequency bands determined by the parameter $L$.

### Inputs and Outputs
*   **Input:** A coordinate vector $\mathbf{p} \in \mathbb{R}^3$ (for position) or $\mathbf{d} \in \mathbb{R}^3$ (for view direction).
*   **Output:** A feature vector $\gamma(\mathbf{p}) \in \mathbb{R}^{2 \cdot L \cdot D}$, where $D$ is the dimensionality of the input (3 for 3D coordinates) and $L$ is the number of frequency bands.

### Data Structures and Layout
The encoding does not require persistent data structures; it is a stateless transformation applied per query. However, the resulting feature vector is concatenated with other features (e.g., opacity, normal) before being fed into the decoder network (AFNet MLP).

*   **AFNet MLP Input Dimension:** 120. This dimension is derived from the encoded position and view direction features plus other attributes.
    *   Position encoding: $L_{pos} = 10$ bands. Dimension = $2 \times 10 \times 3 = 60$.
    *   View direction encoding: $L_{view} = 2$ bands. Dimension = $2 \times 2 \times 3 = 12$.
    *   Other features (e.g., opacity $\alpha$, raw color, normals): The remaining dimensions fill the 120 input size. [S1]
*   **AFNet MLP Architecture:** 5 layers.
    *   Input: 120.
    *   Hidden layers: 256, 256, 256, 128.
    *   Output: 11 (3-channel raw image color + 8-channel feature map). [S1]

### Formulas
The frequency-modulated positional encoding $\gamma(\mathbf{p})$ is computed as follows [S1]:

$$
\gamma (\mathbf {p}) = \left( \sin (2^0 \pi \mathbf {p}), \cos (2^0 \pi \mathbf {p}), \sin (2^{0.5} \pi \mathbf {p}), \cos (2^{0.5} \pi \mathbf {p}), \dots, \sin (2^{L-1} \pi \mathbf {p}), \cos (2^{L-1} \pi \mathbf {p}) \right)
$$

Where:
*   $\mathbf{p}$ is the input coordinate or direction vector.
*   $L$ is the number of frequency bands.
*   The exponents of 2 are $0, 0.5, 1.0, \dots, L-1$. Note that the base exponent step is $0.5$, not $1.0$ as in standard NeRF.

### Parameters
*   **$L$ (Frequency Bands):**
    *   For spatial coordinates: $L = 10$ [S1].
    *   For view directions: $L = 2$ [S1].
*   **Learning Rate:**
    *   MLP weights: $5 \times 10^{-4}$ [S1].
    *   Opacity parameters $\alpha$: $0.01$ [S1].
*   **Sparse Loss Weight ($\lambda_{sparse}$):** $5 \times 10^{-4}$ [S1].

### Pseudocode
The following Python-like pseudocode implements the FMPE function. It assumes standard mathematical operations.

```python
import numpy as np

def frequency_modulated_position_encoding(p, L):
    """
    Computes the frequency-modulated positional encoding for input p.
    
    Args:
        p (np.ndarray): Input coordinate vector of shape (D,) or (N, D).
        L (int): Number of frequency bands.
        
    Returns:
        np.ndarray: Encoded feature vector.
    """
    # p shape: (N, D) or (D,)
    # We need to generate frequencies: 2^0, 2^0.5, 2^1.0, ..., 2^(L-1)
    
    # Generate exponents: 0, 0.5, 1.0, ..., L-1
    exponents = np.arange(L) * 0.5
    
    # Calculate frequency multipliers: 2^exponent
    # Shape: (L,)
    freqs = np.power(2.0, exponents)
    
    # Reshape for broadcasting
    # freqs shape: (L, 1)
    # p shape: (N, D)
    
    # Compute 2 * pi * freq * p
    # Result shape: (N, L, D)
    scaled_p = 2.0 * np.pi * freqs * p[:, np.newaxis, :]
    
    # Compute sine and cosine
    # sin_part shape: (N, L, D)
    # cos_part shape: (N, L, D)
    sin_part = np.sin(scaled_p)
    cos_part = np.cos(scaled_p)
    
    # Concatenate along the last dimension
    # Shape: (N, L, 2*D)
    encoded = np.concatenate([sin_part, cos_part], axis=-1)
    
    # Flatten the last two dimensions (L, 2*D) into one dimension
    # Final shape: (N, L * 2 * D)
    N = p.shape[0] if p.ndim > 1 else 1
    encoded_flat = encoded.reshape(N, -1)
    
    return encoded_flat
```

### Edge Cases and Pitfalls
*   **Bleeding Problem:** If the rasterization radius (used to expand points to disks) is too small, points from occluded surfaces and the background can be seen through the front surface [S1].
*   **Edge Expansion:** If the rasterization radius is too large, it leads to inaccurate depth estimation and object edges expand [S1].
*   **Precision:** The use of fractional exponents ($2^{0.5}$) requires careful handling of floating-point precision, though standard IEEE 754 double precision is sufficient for the reported resolutions [S1].

## Operating characteristics
*   **Time Complexity:** The encoding itself is $O(L \cdot D)$ per query, where $L$ is the number of bands and $D$ is the input dimension. The overall training time is significantly faster than standard NeRF. One epoch consumes approximately 12.8 seconds on the NeRF-Synthetic dataset [S1]. Realistic rendering can be achieved in about 10 minutes, with near-convergence in 10 hours [S1].
*   **Memory Complexity:** The memory footprint is determined by the point cloud size and the MLP parameters. The AFNet MLP has 5 layers with hidden dimensions 256, 256, 256, 128, and input/output dimensions 120 and 11, respectively. The exact memory usage depends on the number of points in the cloud.
*   **Measured Performance:** The method achieves higher PSNR/SSIM on NeRF-Synthetic and Tanks and Temples datasets compared to NeRF, CCNeRF, NPBG, NPBG++, and Huang et al. [S1]. Results on ScanNet and DTU are comparable or better [S1].
*   **Strengths:** Faster convergence than standard NeRF; finer frequency support allows for better detail reconstruction; effective editing capabilities via point cloud masking [S1].
*   **Limitations:** Performance is sensitive to the rasterization radius; requires initial point cloud generation (e.g., via MVSNet) [S1].
*   **When to Use:** Suitable for point-based radiance field optimization where fast training and high-frequency detail recovery are prioritized. Ideal for scenes where point cloud initialization is feasible.
*   **When Not to Use:** Not suitable for scenes where point cloud initialization is poor or unavailable, as the method relies on point-based rendering.

## Background
Frequency-Modulated Position Encoding was introduced in the paper "Frequency-Modulated Point Cloud Rendering with Easy Editing" [S1]. The method builds on the position encoding form of NeRF [S1] but modifies the frequency distribution to provide finer-grained basis function support. It is designed for point-based rendering, specifically addressing the challenges of point cloud sparsity and the need for efficient editing. The method has been evaluated on synthetic datasets (NeRF-Synthetic) and real-world datasets (Tanks and Temples, ScanNet, DTU) [S1].
