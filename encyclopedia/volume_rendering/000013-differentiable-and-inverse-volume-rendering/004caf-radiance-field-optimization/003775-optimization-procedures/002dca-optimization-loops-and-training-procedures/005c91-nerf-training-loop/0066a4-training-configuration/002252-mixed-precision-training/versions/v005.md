# Mixed Precision Training

Also called: AMP Training, FP16 Training, Mixed Precision Training with Fallback

## Overview
Mixed Precision Training (MPT) accelerates the optimization of radiance fields by utilizing lower-precision data types (typically FP16) for forward and backward passes while maintaining a master copy of weights in higher precision (FP32) to preserve numerical stability [S1, unofficial][S2, unofficial]. It addresses the computational bottleneck of differentiable volume rendering, which involves expensive Monte Carlo integration and large neural network forward passes, by leveraging Tensor Cores on modern GPUs [S1, unofficial]. Unlike standard FP32 training, MPT reduces memory bandwidth requirements and increases throughput, though it requires careful handling of gradient scaling to prevent underflow in low-precision arithmetic [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A differentiable volume rendering model (e.g., NeRF, 3DGS), a dataset of target images and camera poses, an optimizer, and a loss function (typically MSE).
- **Output:** Optimized model parameters (stored in FP32) and training metrics.

**Data Structures:**
- **Master Weights:** FP32 tensor storing the authoritative model parameters.
- **Working Weights:** FP16 tensor copy used for computation.
- **Gradient Scaler:** State object tracking the loss scale factor and overflow history [S1, unofficial].
- **Optimizer State:** FP32 buffers for momentum/variance (e.g., Adam) [S2, unofficial].

**Numbered Steps:**
1. **Initialization:** Create the model and optimizer. Initialize a `GradScaler` instance [S1, unofficial]. Set model to training mode [S2, unofficial].
2. **Autocast Context:** Wrap the forward pass in `torch.amp.autocast('cuda')` (or `torch.cuda.amp.autocast()` for older PyTorch versions) to automatically cast operations to FP16 where supported [S1, unofficial][S2, unofficial].
3. **Data Loading:** Randomly select a batch of target images and camera transforms. Move data to the GPU device [S2, unofficial].
4. **Forward Pass:** Render predicted RGB images using the model within the autocast context. The model internally uses FP16 for matrix multiplications and volume rendering integrals [S1, unofficial][S2, unofficial].
5. **Loss Computation:** Compute the Mean Squared Error (MSE) between predicted and target images. The loss is computed in FP32 or FP16 depending on the autocast policy, but is typically scaled [S1, unofficial][S2, unofficial].
6. **Loss Scaling:** Multiply the loss by a scale factor $S$ maintained by the scaler. This prevents FP16 underflow during backpropagation [S1, unofficial].
7. **Backward Pass:** Call `loss.backward()` to compute gradients. Gradients are accumulated in FP16 [S1, unofficial][S2, unofficial].
8. **Gradient Unscaling:** The scaler divides the gradients by $S$ to restore their original magnitude [S1, unofficial].
9. **Optimizer Step:** The optimizer updates the **Master Weights** (FP32) using the unscaled gradients. If the optimizer uses adaptive moments (like Adam), these are maintained in FP32 [S2, unofficial].
10. **Scaler Update:** The scaler updates its internal state. If an overflow (NaN/Inf) is detected, the scale factor $S$ is decreased; otherwise, it may be increased [S1, unofficial].
11. **Zero Gradients:** Zero out gradients for the next iteration [S2, unofficial].
12. **Checkpointing:** Periodically save the master weights, optimizer state, scaler state, and iteration count [S2, unofficial].

import torch
import torch.nn as nn
import numpy as np

def train_step(model, optimizer, scaler, batch_data, device):
    """
    Performs one training step using mixed precision.
    
    Args:
        model: Neural network model.
        optimizer: Optimizer instance.
        scaler: Gradient scaler instance.
        batch_data: Tuple of (images, cam2world_transforms).
        device: CUDA device.
    """
    # 1. Move data to device
    target_img, target_tform_cam2world = batch_data
    target_img = target_img.to(device)
    target_tform_cam2world = target_tform_cam2world.to(device)
    
    # 2. Set model to train mode
    model.train()
    
    # 3. Zero gradients
    optimizer.zero_grad(set_to_none=True)
    
    # 4. Forward pass with autocast
    with torch.amp.autocast('cuda'):
        # Render predicted RGB
        # run_one_iter_of_tinynerf is a placeholder for the specific rendering function
        rgb_predicted = run_one_iter_of_tinynerf(
            model, 
            target_tform_cam2world, 
            height=256, # Example height
            width=256,  # Example width
            focal_length=500.0, # Example focal length
            near_thresh=0.01,
            far_thresh=100.0,
            depth_samples_per_ray=128
        )
        
        # Squeeze first dimension if necessary (depends on implementation)
        if rgb_predicted.dim() > 3:
            rgb_predicted = rgb_predicted.squeeze(0)
            
        # 5. Compute Loss
        loss = torch.mean((rgb_predicted - target_img) ** 2)
        
    # 6. Scale Loss
    scaled_loss = scaler.scale(loss)
    
    # 7. Backward Pass
    scaled_loss.backward()
    
    # 8. Optimizer Step and Scaler Update
    # The scaler unscales gradients and checks for overflow
    optimizer.step()
    scaler.update()
    
    return loss.item()

def train_loop(model, optimizer, scaler, dataset, num_iters, save_every, checkpoint_dir):
    """
    Main training loop with mixed precision.
    """
    loss_history = []
    epoch_history = []
    
    for i in range(num_iters):
        # Randomly select 4 target images (as per source [S2, unofficial])
        indices = np.random.choice(dataset.images.shape[0], 4)
        batch_images = dataset.images[indices]
        batch_cam2world = dataset.cam2world[indices]
        
        # Perform training step
        loss = train_step(model, optimizer, scaler, (batch_images, batch_cam2world), 'cuda')
        
        # Step learning rate scheduler (if used)

        # Checkpointing
        if i % save_every == 0:
            loss_history.append(loss)
            epoch_history.append(i + 1)
            
            # Save checkpoint
            checkpoint = {
                'model_state_dict': model.state_dict(),
                'optimizer_state_dict': optimizer.state_dict(),
                'loss': loss,
                'iteration': i,
                'scaler_state_dict': scaler.state_dict(),
                # 'scheduler_state_dict': scheduler.state_dict() # If scheduler exists
            }
            torch.save(checkpoint, f"{checkpoint_dir}/checkpoint_{i}.pt")

**Parameters:**
- `use_mixed_precision`: Boolean flag to enable/disable AMP [S1, unofficial].
- `scaler`: Gradient scaler instance [S1, unofficial].
- `chunksize`: Batch size for chunked forward passes to avoid OOM (e.g., 1024 rays) [S2, unofficial].
- `save_every`: Interval for checkpointing [S2, unofficial].

**Edge Cases and Pitfalls:**
- **NaN/Inf Gradients:** FP16 has a smaller dynamic range than FP32. Gradients can underflow to zero or overflow to NaN. The scaler handles this by detecting NaNs and reducing the scale factor [S1, unofficial].
- **Precision Loss in Accumulation:** Some operations (like reduction in loss or Adam's moment estimates) may require FP32 accumulation. Autocast handles this automatically for standard PyTorch ops [S1, unofficial].
- **Compatibility:** Older PyTorch versions use `torch.cuda.amp` instead of `torch.amp` [S1, unofficial].

## Subtopics

### [Mixed Precision & Gradient Scaling/Clipping](8686-mixed-precision-gradient-scaling-clipping.md)
Integrates Automatic Mixed Precision (AMP) with gradient scaling and clipping to stabilize optimization in differentiable volume rendering. It addresses numerical instability from low-precision arithmetic and high-variance gradients from path-traced Monte Carlo estimates. By scaling the loss before backpropagation and clipping gradients based on their L2 norm, it prevents silent failures from NaN/Inf values and mitigates contamination of optimized textures by improbable light path outliers.

## Operating characteristics
- **Time Complexity:** Training time is reduced by approximately 1.5x to 2x compared to FP32 on GPUs with Tensor Cores (e.g., NVIDIA Volta, Turing, Ampere) [S1, unofficial][S2, unofficial].
- **Memory Complexity:** Memory usage is reduced by ~2x for activations and gradients, allowing for larger batch sizes or higher resolution scenes [S1, unofficial][S2, unofficial].
- **Measured Performance:** On standard NeRF datasets (Blender, LLFF), MPT achieves similar PSNR/SSIM to FP32 but with significantly faster convergence per epoch [S1, unofficial][S2, unofficial].
- **Strengths:** Faster training, lower memory footprint, compatibility with modern GPU hardware.
- **Limitations:** Potential for numerical instability if not properly scaled; requires careful handling of specific operations that do not support FP16 (e.g., certain normalization layers or loss functions) [S1, unofficial].
- **When to Use:** Standard for training large NeRF models on modern GPUs. Not recommended for very small models where overhead outweighs benefits, or on hardware without Tensor Cores [S1, unofficial].

## Background
Mixed Precision Training was popularized in deep learning by Micikevicius et al. (2017) for training large neural networks on GPUs [S1, unofficial]. In the context of NeRF and volume rendering, it has become a standard optimization procedure due to the high computational cost of differentiable rendering [S1, unofficial][S2, unofficial]. It is widely used in modern NeRF implementations (e.g., Instant-NGP, 3DGS) to accelerate training [S1, unofficial][S2, unofficial].
