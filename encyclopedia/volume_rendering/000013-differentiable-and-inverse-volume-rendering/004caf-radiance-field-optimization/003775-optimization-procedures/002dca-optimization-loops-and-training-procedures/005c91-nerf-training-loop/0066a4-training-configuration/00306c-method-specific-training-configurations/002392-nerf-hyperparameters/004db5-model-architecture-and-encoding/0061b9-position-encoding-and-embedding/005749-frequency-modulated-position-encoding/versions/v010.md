# Frequency-Modulated Position Encoding

Also called: FM-NeRF Encoding, Frequency-Modulated Point Cloud Rendering with Easy Editing

## Overview
Frequency-Modulated Position Encoding (FMPE) is a coordinate encoding scheme used in point-based radiance field optimization to map 3D spatial coordinates and viewing directions into a high-dimensional feature space. It solves the problem of representing high-frequency details in sparse point clouds by applying sine and cosine basis functions with exponentially spaced frequencies. Unlike standard NeRF encoding which uses integer powers of 2, FMPE uses fractional powers (specifically $2^{0.5}$ steps) to provide finer-grained basis function support, which is critical for the stability and quality of point-based rendering methods like NPBG and its variants. It is distinct from hash-based or grid-based encodings by relying on explicit trigonometric modulation of raw coordinates.

## How it works

### Inputs and Outputs
*   **Input:** A raw point cloud $\mathcal{P}$ consisting of points $\mathbf{p}_i \in \mathbb{R}^3$ with associated attributes (initially opacity $\alpha$, color $\mathbf{c}$). A viewing direction $\mathbf{d} \in S^2$.
*   **Output:** An encoded feature vector $\mathbf{z} \in \mathbb{R}^D$ for each point and direction, which is fed into a decoding network (typically an MLP or U-Net) to predict final color and opacity.

### Data Structures
The method operates on a point cloud structure. Each point $i$ stores:
*   $\mathbf{p}_i$: 3D position $(x, y, z)$.
*   $\alpha_i$: Opacity scalar.
*   $\mathbf{c}_i$: Color vector $(r, g, b)$.
*   $\mathbf{f}_i$: Feature vector (output of the encoder/decoder, dimension depends on the specific network, e.g., 8-channel feature map in AFNet).

### Preprocessing and Training Loop
The method is embedded within a specific training procedure involving iterative denoising and completion:
1.  **Initialization:** Generate initial point clouds from a Multi-View Stereo (MVS) system (e.g., MVSNet).
2.  **Iterative Refinement:** Perform 4–20 loops of point cloud denoising and completion.
    *   **Denoising:** Train the model for 300 epochs.
    *   **Completion:** If empty buffers are detected during rendering, add points with opacity parameters along the pixel ray. This introduces noise, which is removed in the next denoising stage.
3.  **Pruning:** After training converges, remove points with low opacity.

### Position Encoding Formula
The core encoding function $\gamma(\mathbf{p})$ maps an input coordinate or direction $\mathbf{p}$ to a vector using sine and cosine functions with frequencies defined by powers of 2.

$$ \gamma (\mathbf {p}) = \left( \sin (2^0 \pi \mathbf {p}), \cos (2^0 \pi \mathbf {p}), \sin (2^{0.5} \pi \mathbf {p}), \cos (2^{0.5} \pi \mathbf {p}), \dots, \sin (2^{L-1} \pi \mathbf {p}), \cos (2^{L-1} \pi \mathbf {p}) \right) $$

Where:
*   $\mathbf{p}$ is the input vector (either spatial coordinate $\mathbf{x} \in \mathbb{R}^3$ or view direction $\mathbf{d} \in \mathbb{R}^3$).
*   $L$ is the number of frequency bands.
*   The exponents increase by $0.5$ at each step ($0, 0.5, 1.0, \dots, L-1$). Note: The source notation $2^{L-1}$ implies the last exponent is $L-1$, but the sequence starts at $0$ and increments by $0.5$. For $L=10$, the exponents are $0, 0.5, 1.0, \dots, 4.5$.

### Rasterization
To handle point cloud sparsity, each point is expanded to a disk during rasterization.
*   **Radius Selection:** The radius $r$ is chosen based on two heuristic rules:
    1.  Cover gaps between points to prevent the "bleeding problem" (seeing occluded surfaces/background through front surfaces).
    2.  Keep $r$ as small as possible to avoid inaccurate depth estimation and edge expansion.
*   The radius depends on point cloud density and is adjusted by observing the rendered depth map.

### Network Architecture (AFNet Example)
The encoded features are processed by an MLP (AFNet):
*   **Layers:** 5 layers.
*   **Input Dimension:** 120 (derived from encoding spatial coordinates and view directions).
*   **Hidden Dimensions:** 256, 256, 256, 128.
*   **Output Dimension:** 11 (3-channel raw image color + 8-channel feature map).

### Loss Function
The total loss $\mathcal{L}$ is a combination of RGB reconstruction loss and sparse regularization:

$$ \mathcal{L} = \mathcal{L}_{\text{RGB}} + \lambda_{\text{sparse}} \mathcal{L}_{\text{sparse}} $$

Where:
*   $\mathcal{L}_{\text{RGB}} = ||\hat{C} - C_{gt}||_2^2$
*   $\mathcal{L}_{\text{sparse}} = \frac{1}{N} \sum_{i=1}^N [\log(\alpha_i) + \log(1-\alpha_i)]$
*   $N$ is the number of points.
*   $\lambda_{\text{sparse}} = 5 \times 10^{-4}$.
*   For scenes without background, an additional transparency loss (L2 distance of predicted vs. ground truth transparency) is added.

### Editing and Composition
*   **Masking:** Objects to be edited are stored as masks. Interactive selection (e.g., via PCL library) is used to define these masks.
*   **Shrinking:** For scene composition, masks determined by index buffers are shrunk to avoid edge artifacts caused by point expansion (rasterization radius).

### Edge Cases and Pitfalls
*   **Bleeding Problem:** If the rasterization radius is too small, points from occluded surfaces and the background can be seen through the front surface.
*   **Edge Expansion:** If the rasterization radius is too large, it leads to inaccurate depth estimation and object edges expand.
*   **Completion Noise:** The point completion step introduces noise, which must be handled by the subsequent denoising stage.
*   **Background Masking:** For datasets like ScanNet, background must be masked out using binary segmentation masks (e.g., from IDR).

## Operating characteristics

### Time and Memory Complexity
*   **Training Time:** Approximately 10 minutes for realistic rendering, and about 10 hours to almost converge. One epoch consumes ~12.8 seconds on the NeRF-Synthetic dataset.
*   **Memory:** Depends on the point cloud size and the MLP size (5 layers, 120 input dim). The U-Net for editing also consumes memory.

### Measured Performance
*   Achieves higher PSNR/SSIM on NeRF-Synthetic and Tanks and Temples datasets compared to NeRF, CCNeRF, NPBG, NPBG++, and Huang et al.
*   Comparable or better results on ScanNet and DTU datasets.

### Strengths and Limitations
*   **Strengths:** Fast convergence to realistic rendering; easy editing capabilities via point cloud masking; handles sparse point clouds effectively with frequency modulation.
*   **Limitations:** Requires iterative denoising and completion; sensitive to rasterization radius selection; may suffer from bleeding or edge expansion if radius is not tuned.

### When to Use
*   Use when working with point-based radiance fields (like NPBG) and needing high-frequency detail representation.
*   Use when easy editing and scene composition are required.

### When Not to Use
*   Avoid if computational resources are extremely limited and fast convergence is not a priority (standard NeRF might be more stable).
*   Avoid if the point cloud is extremely dense and uniform, as the specific radius tuning for sparsity compensation may be less critical or harder to optimize.

## Background

### Origin
Frequency-Modulated Position Encoding was introduced in the paper "Frequency-Modulated Point Cloud Rendering with Easy Editing" (CVPR 2023) [S1]. It builds upon the positional encoding scheme used in NeRF [21] but modifies the frequency spacing to fractional powers of 2 to provide finer-grained basis function support.

### History and Development
The method is part of the evolution of point-based neural rendering, specifically improving upon NPBG and NPBG++. It addresses the limitations of integer-based frequency spacing by allowing for more flexible frequency modulation, which helps in capturing fine details in point clouds. The method includes specific training procedures involving iterative denoising and completion to handle the sparsity and noise inherent in MVS-generated point clouds.

### Applications
*   Realistic rendering of synthetic and real-world scenes (NeRF-Synthetic, Tanks and Temples, ScanNet, DTU).
*   Interactive editing and scene composition of 3D assets.
