# Learnable Pose Refinement via Local SE(3) Warp

Also called: Embedding-Based Warp MLP, Local SE(3) Pose Correction

## Overview
This method refines noisy initial camera poses by learning a per-camera correction conditioned on 2D image coordinates, jointly optimizing the neural radiance field and camera extrinsics [S1][S2, unofficial]. It models pose corrections as a continuous function of pixel location to achieve spatially coherent refinement [S1][S2, unofficial]. It sets itself apart from standard coarse-to-fine optimization methods by using a dedicated MLP to predict local SE(3) warps rather than relying solely on frequency-based positional encoding schedules [S1][S2, unofficial].

## How it works

### Inputs and Outputs
**Inputs:** Initial noisy camera poses $P_{w2c} \in SE(3)$ for $N$ cameras [S1], inverse intrinsic matrices $K^{-1}$ [S2, unofficial], image dimensions $(W, H)$ [S1], and per-camera learnable embeddings [S2, unofficial].
**Outputs:** Refined camera poses $P'_{w2c}$ [S2, unofficial] and gradients for pose refinement and network weights [S1].

### Data Structures
**Warp Embedding:** A learnable lookup table storing a vector for each camera [S2, unofficial].
*   `warp_embedding`: `torch.nn.Embedding(num_cameras, embedding_dim)`
*   Layout: A tensor of shape `(num_cameras, embedding_dim)` [S2, unofficial].
*   `embedding_dim`: Integer dimensionality of the pose correction embedding [S2, unofficial].

**Warp MLP:** A neural network mapping 2D coordinates and embeddings to SE(3) Lie algebra vectors [S2, unofficial].
*   `warp_mlp`: A multi-layer perceptron [S2, unofficial].
*   Input dimension: $2 + \text{embedding\_dim}$ (2D coordinates + embedding) [S2, unofficial].
*   Output dimension: 6 (SE(3) Lie algebra vector $\xi \in \mathbb{R}^6$) [S2, unofficial].

### Algorithm Steps
1. **Gather Camera Coordinates:** For a batch of rays, compute the 3D camera coordinates grid using inverse intrinsics and ray indices [S2, unofficial].
2. **Extract 2D Coordinates:** `camera_cords_grid_2D = camera_cords_grid_3D[..., :2]` [S2, unofficial].
3. **Retrieve Embeddings:** For each camera $i$ in the batch, retrieve its specific embedding vector $e_i$ [S2, unofficial].
4. **Compute Local SE(3) Correction:** Concatenate 2D coordinates and embedding, then pass through the warp MLP: `local_se3_refine = self.warp_mlp(opt, torch.cat((camera_cords_grid_2D, embedding), dim=-1))` [S2, unofficial].
5. **Map to SE(3) Matrix:** Convert the Lie algebra vector $\xi$ to an SE(3) matrix $\Delta P$ using the exponential map: `local_pose_refine = camera.lie.se3_to_SE3(local_se3_refine)` [S2, unofficial].
6. **Compose Pose:** Apply the local correction to the base pose: `local_pose = camera.pose.compose([local_pose_refine, pose[:, None, ...]])` [S2, unofficial].
7. **Update Parameters:** Update rotation and translation estimates iteratively [S1]. The update rule is:
   $$ \hat{R}_{w2c} = f(\hat{r}_{w2c} + \Delta r) $$
   $$ \hat{t}_{w2c} = t_{w2c} + \Delta t $$
   where $\hat{r}_{w2c}$ and $t_{w2c}$ are the initial (noisy) camera rotation and translation parameters [S1].

### Rotation Parameterization (6D to Matrix)
The method uses a 6D rotation representation $r = [a_1^T, a_2^T]^T$ where $a_1, a_2 \in \mathbb{R}^3$ [S1]. The rotation matrix $R$ is recovered via a function $f$ using a Gram-Schmidt-like orthogonalization [S1]:
1. $b_1 = N(a_1)$
2. $b_2 = N(a_2 - (b_1 \cdot a_2)b_1)$
3. $b_3 = b_1 \times b_2$
4. $R = [b_1 \mid b_2 \mid b_3]$
Where $N(\cdot)$ denotes the L2 norm [S1].

### Pseudocode
```python
import torch
import torch.nn as nn

class LocalSE3WarpRefinement:
    def __init__(self, num_cameras, embedding_dim, mlp_hidden_dims=[256, 256, 256]):
        self.num_cameras = num_cameras
        self.embedding_dim = embedding_dim
        # warp_embedding: Stores learnable per-camera pose correction vectors [S2, unofficial]
        self.warp_embedding = nn.Embedding(num_cameras, embedding_dim)
        # warp_mlp: Maps concatenated 2D coords and embeddings to 6D SE(3) Lie algebra [S2, unofficial]
        input_dim = 2 + embedding_dim
        layers = []
        for hidden_dim in mlp_hidden_dims:
            layers.append(nn.Linear(input_dim, hidden_dim))
            layers.append(nn.ReLU())
            input_dim = hidden_dim
        layers.append(nn.Linear(input_dim, 6))
        self.warp_mlp = nn.Sequential(*layers)

    def compute_rotation_matrix(self, r):
        """Convert 6D rotation vector r = [a1, a2] to 3x3 rotation matrix R [S1]."""
        a1 = r[..., :3]
        a2 = r[..., 3:6]
        b1 = nn.functional.normalize(a1, dim=-1)
        dot_product = torch.sum(b1 * a2, dim=-1, keepdim=True)
        b2 = nn.functional.normalize(a2 - dot_product * b1, dim=-1)
        b3 = torch.cross(b1, b2, dim=-1)
        return torch.stack([b1, b2, b3], dim=-1)

    def se3_to_matrix(self, xi):
        """Convert SE(3) Lie algebra vector xi (6D) to 4x4 SE(3) matrix [G]."""
        omega = xi[..., :3]
        v = xi[..., 3:6]
        theta = torch.norm(omega, dim=-1, keepdim=True)
        theta = torch.clamp(theta, min=1e-8)
        k = omega / theta
        kx = torch.stack([
            torch.zeros_like(k), -k[..., 2], k[..., 1],
            k[..., 2], torch.zeros_like(k), -k[..., 0],
            -k[..., 1], k[..., 0], torch.zeros_like(k)
        ], dim=-1).reshape(*k.shape[:-1], 3, 3)
        sin_theta = torch.sin(theta).unsqueeze(-1).unsqueeze(-1)
        cos_theta = torch.cos(theta).unsqueeze(-1).unsqueeze(-1)
        I = torch.eye(3).to(xi.device).unsqueeze(0).expand(*xi.shape[:-1], 3, 3)
        R = I + sin_theta * kx + (1 - cos_theta) * torch.matmul(kx, kx)
        P = torch.zeros((*xi.shape[:-1], 4, 4), device=xi.device)
        P[..., :3, :3] = R
        P[..., :3, 3] = v
        P[..., 3, 3] = 1.0
        return P

    def forward(self, base_poses, pixel_coords, camera_indices):
        """Compute refined poses for a batch of rays [S2, unofficial]."""
        # 1. Retrieve per-camera embeddings
        embeddings = self.warp_embedding(camera_indices)
        # 2. Concatenate 2D coords and embeddings
        input_tensor = torch.cat([pixel_coords, embeddings], dim=-1)
        # 3. Pass through Warp MLP to get 6D Lie algebra vector
        local_se3_refine = self.warp_mlp(input_tensor)
        # 4. Convert SE(3) Lie algebra to 4x4 matrix
        local_pose_refine = self.se3_to_matrix(local_se3_refine)
        # 5. Compose local refinement with base pose
        base_pose_for_ray = base_poses[camera_indices]
        refined_poses = torch.bmm(local_pose_refine, base_pose_for_ray)
        return refined_poses

    def update_rotation(self, current_r, delta_r):
        """Update rotation parameters using the 6D representation and Gram-Schmidt [S1]."""
        new_r = current_r + delta_r
        return self.compute_rotation_matrix(new_r)
```

### Parameters and Typical Values
*   **Learning Rates (Adam Optimizer):** Network weights: Initial $5 \times 10^{-4}$, decaying exponentially to $1 \times 10^{-4}$ [S1]. Camera poses: Initial $1 \times 10^{-3}$, decaying to $1 \times 10^{-4}$ [S1]. LLFF specific: Network LR $1 \times 10^{-3}$ to $1 \times 10^{-4}$; Pose LR $3 \times 10^{-3}$ to $1 \times 10^{-5}$ [S1].
*   **Image Resolution:** DTU/Replica: $300 \times 400$ [S1]. LLFF: $378 \times 504$ [S1].
*   **Ray Sampling:** DTU/Replica: 1024 random pixel rays per step [S1]. LLFF: 2048 random pixel rays per step [S1].
*   **Embedding Dimension:** Not explicitly fixed in sources, defined as `embedding_dim` [S2, unofficial].

### Edge Cases and Pitfalls
1.  **Background Artifacts:** In LLFF joint pose-NeRF optimization, applying multi-view correspondence loss and depth consistency loss from the beginning can cause the background to appear in front of the foreground [S1]. The method recommends using only photometric loss for the first 1,000 iterations [S1].
2.  **Rotation Orthogonality:** The 6D rotation representation requires Gram-Schmidt orthogonalization at every update step to ensure the resulting matrix is a valid rotation matrix [S1].
3.  **Hierarchical Sampling:** For LLFF, hierarchical sampling was found unnecessary; a single MLP yields the same results with faster training [S1].

## Subtopics

### Camera Pose Refinement
Refines coarse camera poses by minimizing a point-to-camera ray consistency loss to address inaccuracies from the scene regressor [S3, unofficial]. It fixes the camera pose of the seed image to resolve gauge ambiguity and fixes the scaling factor between the seed image and its most similar adjacent image to resolve scale ambiguity [S3, unofficial]. Using an MLP pose refiner causes divergence because the transformer-based scene regressor limits batch size to 1 on consumer GPUs, preventing multi-view constraint mixing [S3, unofficial].

### Geometric Constraints for Inliers (Re-projection and IoU Losses)
Strategies for inlier poses that introduce additional constraints to enhance geometric consistency, specifically using re-projection loss and Intersection-of-Union (IoU) losses [S4]. It identifies poses as inliers based on a confidence estimation strategy, applies re-projection loss based on the current Signed Distance Function (SDF) and pose estimations, and applies IoU losses to strengthen constraints between matching image pairs [S4].

## Operating characteristics
*   **Time and Memory Complexity:** The addition of multi-view correspondence loss and depth consistency objectives adds a factor of approximately 1.5 to the optimization time, regardless of the number of views [S1]. The PDC-Net used for correspondence runs at 10 fps on $300 \times 400$ images [S1]. Memory complexity depends on the `warp_embedding` and `warp_mlp` sizes.
*   **Strengths and Limitations:** Handles noisy initial poses effectively and reduces training time on LLFF by avoiding hierarchical sampling [S1]. Requires careful tuning of learning rate schedules and may require delayed addition of consistency losses to avoid artifacts [S1].
*   **When to Use:** Sparse-view reconstruction or scenes with noisy initial poses where joint optimization is needed [S1].
*   **When Not to Use:** Not given in the sources.

## Background
The method originates from the SPARF paper, which addresses the challenge of optimizing NeRFs from sparse and noisy camera poses [S1]. The 6D rotation representation is based on work by Zhou et al. [63] in the SPARF paper [S1]. Implementation details regarding the warp MLP and embeddings are documented in unofficial repositories [S2, unofficial].
