# SUDS
Also called: Scalable Urban Dynamic Scenes

## Overview
SUDS is a 4D radiance field representation designed for large-scale dynamic urban scenes that factorizes the scene into three separate multi-resolution hash table structures to efficiently encode static, dynamic, and far-field radiance fields [S1]. It distinguishes itself from sibling methods by using unlabeled target signals (RGB, sparse LiDAR, 2D descriptors, and 2D optical flow) for supervision, enabling free-viewpoint rendering, semantic decomposition, and 3D scene flow estimation without requiring ground truth 3D bounding boxes or panoptic segmentation labels [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ordered RGB images from $N$ videos taken at different days with diverse weather/lighting, associated camera poses, aligned sparse LiDAR depth measurements, 2D self-supervised DINO descriptors, and 2D optical flow predictions [S1].
*   **Outputs:** Per-branch color ($\mathbf{c}$), density ($\sigma$), semantic feature logits ($\Phi$), and scene flow vectors ($\mathbf{s}$) [S1].

**Data Structures:**
The scene is decomposed into $K$ spatial cells with centroids $\mathbf{k} \in \mathbb{R}^3$. Each cell contains three multi-resolution hash table branches: Static, Dynamic, and Far-field [S1].
*   **Hash Tables:** Each branch uses $L$ resolution levels, where resolution doubles between levels [S1].
*   **Feature Vectors:** Each hash table entry stores a feature vector of dimensionality $F$ [S1].
*   **Hash Indexing:** Instead of storing features at voxel corners, indices are computed via hash functions [S1]:
    *   Static: $i_{l,s} = \text{static hash}(\text{space}(\mathbf{v}_{l,s}))$ [S1]
    *   Dynamic: $i_{l,d} = \text{dynamic hash}(\text{space}(\mathbf{v}_{l,d}), \text{time}(\mathbf{v}_{l,d}), \text{vid})$ [S1]
    *   Far-field: $i_{l,e} = \text{env hash}(\text{dir}(\mathbf{v}_{l,e}), \text{vid})$ [S1]
    *   $\text{vid}$ is the video ID, used to index separate interpolating functions per video without linear memory growth [S1].
*   **Collision Handling:** Hash collisions are handled via gradient averaging [S1].

**Numbered Steps:**
1.  **Spatial Partitioning:** Split the scene into $K$ spatial cells. Generate separate training datasets for each cell by including only datapoints whose camera rays intersect the cell. Prune irrelevant rays using LiDAR depth measurements to ensure visibility [S1].
2.  **Voxel Lookup:** For an input coordinate $(\mathbf{x}, \mathbf{d}, t, \text{vid})$ where $\mathbf{x}$ is position, $\mathbf{d}$ is viewing direction, $t$ is frame index, and $\text{vid}$ is video ID, find surrounding voxels at $L$ resolution levels for the static ($\mathbf{v}_{l,s}$), dynamic ($\mathbf{v}_{l,d}$), and far-field ($\mathbf{v}_{l,e}$) branches [S1].
3.  **Hash Indexing:** Compute hash indices for the corners of the surrounding voxels using the specific hash functions defined above [S1].
4.  **Feature Interpolation:**
    *   Look up feature vectors corresponding to the corners.
    *   Linearly interpolate features for the static branch.
    *   Use quadlinear interpolation for the dynamic 4D branch [S1].
    *   Concatenate results from all $L$ levels into a feature vector $\mathbf{f} \in \mathbb{R}^{LF}$ [S1].
5.  **MLP Evaluation:** Concatenate $\mathbf{f}$ with auxiliary inputs (viewing direction $\mathbf{d}$, video-specific lighting embedding $\mathbf{A}_{\text{vid}}\mathbf{F}(t)$ for static branch) and pass into an MLP to obtain per-branch outputs [S1]:
    *   **Static Branch:** View-dependent color $\mathbf{c}_s(\mathbf{x}, \mathbf{d}, \mathbf{A}_{\text{vid}}\mathbf{F}(t)) \in \mathbb{R}^3$ and view-independent density $\sigma_s(\mathbf{x}) \in \mathbb{R}$ [S1]. $\mathbf{F}(t)$ is a Fourier-encoded time index [S1].
    *   **Dynamic Branch:** Time/video-dependent density $\sigma_d(\mathbf{x}, t, \text{vid}) \in \mathbb{R}$, color $\mathbf{c}_d(\mathbf{x}, t, \text{vid}, \mathbf{d}) \in \mathbb{R}^3$, scalar shadow ratio $\rho_d(\mathbf{x}, t, \text{vid}) \in [0, 1]$, and forward/backward 3D scene flow vectors $\mathbf{s}_{t0}(\mathbf{x}, t, \text{vid}) \in [-1, 1]^3$ [S1].
    *   **Far-field Branch:** Environment map color $\mathbf{c}_e(\mathbf{d}, \text{vid}) \in \mathbb{R}^3$ [S1].
    *   **Semantic Features:** Add $C$-dimensional output heads to each branch to distill DINO features: $\Phi_s(\mathbf{x}) \in \mathbb{R}^C$, $\Phi_d(\mathbf{x}, t, \text{vid}) \in \mathbb{R}^C$, $\Phi_e(\mathbf{d}, \text{vid}) \in \mathbb{R}^C$ [S1].
6.  **Density and Radiance Combination:**
    *   Total density: $\sigma(\mathbf{x}, t, \text{vid}) = \sigma_s(\mathbf{x}) + \sigma_d(\mathbf{x}, t, \text{vid})$ [S1].
    *   Total radiance: $\mathbf{c}(\mathbf{x}, t, \text{vid}, \mathbf{d}) = \frac{(1 - \rho_d)\sigma_s \mathbf{c}_s + \sigma_d \mathbf{c}_d}{\sigma}$ [S1].
    *   Semantic features are combined similarly to color [S1].
7.  **Rendering:** Derive color $\hat{\mathbf{C}}$ for a camera ray $\mathbf{r}$ by accumulating transmittance along sampled points $\mathbf{r}(t)$:
    $$ \hat{\mathbf{C}}(\mathbf{r}, t, \text{vid}) = \int_0^{+\infty} T(t)\sigma(\mathbf{r}(t), t, \text{vid})\mathbf{c}(\mathbf{r}(t), t, \text{vid}, \mathbf{d})dt + T(+\infty)\mathbf{c}_e(\mathbf{d}, \text{vid}) $$
    where $T(t) = \exp\left(-\int_0^t \sigma(\mathbf{r}(s), t, \text{vid})ds\right)$ [S1].

**Parameters:**
*   $F$: Dimensionality of feature vectors in hash tables [S1].
*   $L$: Number of resolution levels (resolution doubles between levels) [S1].
*   $N$: Number of input videos [S1].
*   $C$: Dimensionality of DINO feature grid output [S1].
*   $k$: Constant set to 1.75 in skewed binary entropy loss [S1].
*   Training: 250,000 iterations, 4098 rays per batch, Adam optimizer with learning rate decaying from $5 \times 10^{-3}$ to $5 \times 10^{-4}$ [S1].

**Pseudocode:**
```python
def suds_forward(x, d, t, vid, hash_tables, mlp, A_vid, F_t):
    """
    x: position (3,)
    d: viewing direction (3,)
    t: time index
    vid: video ID
    hash_tables: dict with keys 'static', 'dynamic', 'far_field'
                 each containing list of L hash tables
    mlp: neural network taking concatenated features + aux inputs
    A_vid: video-specific matrix for lighting
    F_t: Fourier-encoded time index
    """
    features = []
    
    # Static Branch
    static_features = []
    for l in range(L):
        # Find surrounding voxels v_l,s
        # Compute hash indices i_l,s = static_hash(space(v_l,s))
        # Lookup features at corners
        # Linear interpolation based on relative position
        static_features.append(interpolate_hash_table(hash_tables['static'][l], x))
    f_static = concat(static_features) # R^{LF}
    
    # Dynamic Branch
    dynamic_features = []
    for l in range(L):
        # Find surrounding voxels v_l,d
        # Compute hash indices i_l,d = dynamic_hash(space(v_l,d), time(v_l,d), vid)
        # Lookup features at corners
        # Quadlinear interpolation based on relative position in 4D
        dynamic_features.append(interpolate_hash_table_4d(hash_tables['dynamic'][l], x, t))
    f_dynamic = concat(dynamic_features) # R^{LF}
    
    # Far-field Branch
    far_field_features = []
    for l in range(L):
        # Find surrounding voxels v_l,e based on direction d
        # Compute hash indices i_l,e = env_hash(dir(v_l,e), vid)
        # Lookup and interpolate
        far_field_features.append(interpolate_hash_table(hash_tables['far_field'][l], d))
    f_far_field = concat(far_field_features) # R^{LF}
    
    # MLP Evaluation
    # Static MLP input: f_static + d + A_vid * F_t
    c_s, sigma_s, Phi_s = mlp_static(f_static, d, A_vid * F_t)
    
    # Dynamic MLP input: f_dynamic + d + t + vid (vid handled via hash indexing)
    sigma_d, c_d, rho_d, Phi_d, s_flow = mlp_dynamic(f_dynamic, d, t, vid)
    
    # Far-field MLP input: f_far_field + d + vid
    c_e, Phi_e = mlp_far_field(f_far_field, d, vid)
    
    # Combine
    sigma_total = sigma_s + sigma_d
    c_total = ((1 - rho_d) * sigma_s * c_s + sigma_d * c_d) / sigma_total
    Phi_total = combine_semantics(Phi_s, Phi_d, Phi_e, sigma_s, sigma_d)
    
    return c_total, sigma_total, Phi_total, s_flow, rho_d

def render_ray(r, t, vid, hash_tables, mlp, A_vid, F_t, num_samples):
    """
    r: ray origin and direction
    t: time
    vid: video ID
    """
    # Sample points along ray
    points = sample_along_ray(r, num_samples)
    
    # Get densities and colors
    colors = []
    sigmas = []
    for p in points:
        c, sigma, _, _, _ = suds_forward(p, r.direction, t, vid, hash_tables, mlp, A_vid, F_t)
        colors.append(c)
        sigmas.append(sigma)
        
    # Accumulate transmittance and color
    # T(t) = exp(-int_0^t sigma ds)
    # C = int T(t) sigma(t) c(t) dt + T(+inf) c_env
    # Implementation uses discrete summation
    transmittance = 1.0
    accumulated_color = [0.0, 0.0, 0.0]
    for i, (sigma, c) in enumerate(zip(sigmas, colors)):
        alpha = 1.0 - exp(-sigma * delta_t) # delta_t is sample spacing
        weight = transmittance * alpha
        accumulated_color += weight * c
        transmittance *= (1.0 - alpha)
        
    # Add far-field environment map if ray escapes
    # c_env = mlp_far_field(...)
    accumulated_color += transmittance * c_env
    
    return accumulated_color
```

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** Handled via gradient averaging [S1].
*   **Occlusions:** Pruned using LiDAR depth measurements during spatial partitioning [S1]. Warping losses are downweighted in ambiguous regions using a weight $W_{t0}$ derived from dynamic geometry difference [S1].
*   **Lighting Variations:** Modeled via video-specific matrix $\mathbf{A}_{\text{vid}}$ and Fourier-encoded time index $\mathbf{F}(t)$ in the static branch [S1].

## Operating characteristics
*   **Time Complexity:** Training takes 250,000 iterations. SUDS is 10x quicker to train than state-of-the-art methods relying on ground truth 3D bounding box annotations [S1].
*   **Memory Complexity:** Scales to tens of thousands of objects across 1.2 million frames from 1700 videos spanning hundreds of kilometers [S1]. Uses multi-resolution hash tables to manage memory efficiently, avoiding the linear memory growth of per-object NeRFs (e.g., NSG requires >1TB for 30s video) [S1].
*   **Strengths:** Handles ego-motion and multi-video representations; uses unlabeled inputs for supervision; scales to city-level scenes [S1].
*   **Limitations:** Requires sparse LiDAR and optical flow for optimal performance (though these are "free" supervision sources) [S1].

## Background
SUDS was introduced in 2023 as a response to the limitations of prior dynamic scene representations that required supervised inputs like panoptic segmentation labels or bounding boxes, which are difficult to acquire accurately for in-the-wild captures [S1]. It builds on ideas from Instant-NGP [S1] and MegaNeRF [S1], extending them to handle dynamism and scale. It is used for free-viewpoint synthesis of dynamic urban scenes, unsupervised 3D instance segmentation, and unsupervised 3D cuboid detection [S1].
