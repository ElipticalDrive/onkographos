# Training Configuration

Also called: ExBluRF Training Configuration, Hyperparameter Configuration, Optimization Configuration, Optimizer Settings, Training Details, Training Hyperparameters

## Overview
Training Configuration defines the hyperparameters, optimization schedules, and architectural constraints required to train differentiable radiance field representations from multi-view images. It addresses the problem of stabilizing convergence and achieving high-fidelity reconstruction while managing computational cost and training stability. What sets this configuration apart from generic volume rendering is the tight coupling between the sampling strategy, the network activation functions, and the loss landscape tailored to the specific representation's high-frequency nature or geometric priors [S1][S3, S6]. It serves as the foundational setup for the [NeRF Training Loop](970-nerf-training-loop.md), providing the specific numerical values and procedural rules that govern the optimization process.

## How it works
The training configuration establishes the environment and parameters for the optimization loop. It involves initializing the optimizer, setting learning rate schedules, defining batch sizes, and configuring regularization terms. The specific values vary significantly depending on the underlying representation (e.g., MLP, Voxel Grid, Hash Grid) and the training stage (coarse vs. fine).

### Inputs and Outputs
*   **Inputs:** Scene data (images, camera poses), network architecture definition, hyperparameter settings (learning rates, batch sizes, iterations), and regularization weights.
*   **Outputs:** Optimized network weights (or voxel/hash grid values) and optimizer state.

### Data Structures and Layouts
The configuration is typically stored in a configuration object or command-line arguments. Key fields include:
*   `optimizer`: String identifier (e.g., "Adam", "AdamW", "RMSProp") and hyperparameters (`betas`, `eps`, `weight_decay`).
*   `lr_scheduler`: Type (e.g., "LambdaLR", "CosineAnnealing") and parameters (e.g., `init_lr`, `decay_rate`, `warmup_steps`).
*   `batch_size`: Number of rays or pixels sampled per iteration.
*   `iterations`: Total number of training steps.
*   `sampling_params`: Parameters for ray sampling (e.g., `num_coarse_samples`, `num_fine_samples`, `step_size`).
*   `loss_weights`: Dictionary mapping loss components (e.g., `photo`, `ssim`, `regularization`) to their scalar weights.
*   `resolution`: Grid or voxel resolution (e.g., `128^3`, `300^3`).
*   `bound`: Scene bounding box size (e.g., `[-2, 2]^3`).
*   `fp16`: Boolean flag for mixed precision training.
*   `cuda_ray`: Boolean flag for using CUDA-accelerated ray marching.

### Numbered Steps for Configuration Initialization
1.  **Initialize Random Seed:** Set the random seed for reproducibility [S12, unofficial].
2.  **Define Network Architecture:** Instantiate the radiance field model (e.g., MLP, Voxel Grid, Hash Grid) with specified dimensions and resolutions [S12, unofficial].
3.  **Configure Optimizer:**
    *   Select optimizer (e.g., Adam) [S1, S2, S6, S11].
    *   Set base learning rates. For multi-component models (e.g., voxel grids + MLP), assign different learning rates to different parameter groups [S2][S12, unofficial].
    *   Set optimizer hyperparameters: $\beta_1=0.9$, $\beta_2=0.99$, $\epsilon=10^{-15}$ [S2, S3, S6][S12, unofficial].
    *   Set weight decay if applicable (e.g., $0.1$ for hash grids [S6], $10^{-9}$ for grids [S3], $0.001$ for AdamW [S14]).
4.  **Configure Learning Rate Scheduler:**
    *   Define warm-up phase (e.g., linear increase from $10^{-4}$ to $10^{-2}$ over 100 iterations [S6]; cosine decay from $10^{-8}$ to $1$ over 5k iterations [S3]).
    *   Define decay schedule (e.g., exponential decay to $0.1 \times$ init\_lr at last iteration [S12, unofficial]; logarithmic decay from $10^{-2}$ to $10^{-3}$ [S3]; linear decay from $5 \times 10^{-4}$ to $8 \times 10^{-5}$ [S4]).
5.  **Set Sampling Parameters:**
    *   Define number of samples per ray for coarse and fine stages (e.g., 64 coarse, 128 fine [S4]; 32 and 64 points [S9]).
    *   Define step size relative to voxel size (e.g., $\delta = 0.5 \times s$ [S2][S12, unofficial]).
    *   Define point distribution (e.g., 2:2:1 split of surface, near, and uniform samples [S1]).
6.  **Configure Loss Functions:**
    *   Define loss components (e.g., L2, SSIM, perceptual loss) [S5][S12, unofficial].
    *   Set loss weights (e.g., $L = L2 + 0.2 \times LSSIM$ [S5]; specific weights for photo, pt\_rgb, bg losses [S2]).
7.  **Set Training Duration:** Define total iterations (e.g., 25k [S3, S6], 30k [S5], 100k [S11], 200k [S4, S11]).
8.  **Configure Hardware Flags:** Enable mixed precision (fp16) [S12, unofficial] and CUDA ray marching if supported [S12, unofficial].

### Formulas
*   **Learning Rate Decay (LambdaLR):**
    $$ lr(iter) = lr_{init} \times 0.1^{\min(\frac{iter}{iters}, 1)} $$
    Where $iter$ is the current iteration, $iters$ is the total number of iterations, and $lr_{init}$ is the initial learning rate [S12, unofficial].
*   **Loss Function (General):**
    $$ L = \sum_i w_i L_i $$
    Where $w_i$ are the weights for each loss component $L_i$ (e.g., photometric, SSIM, regularization) [S5][S12, unofficial].
*   **Dynamic Frequency Masking (FreeNeRF):**
    $$ \alpha_i(t, T, L) = \begin{cases} 1 & \text{if } i \le \lfloor \frac{t \cdot L}{T} \rfloor \\ \frac{t \cdot L}{T} - \lfloor \frac{t \cdot L}{T} \rfloor & \text{if } \lfloor \frac{t \cdot L}{T} \rfloor < i \le \lfloor \frac{t \cdot L}{T} \rfloor + 3 \\ 0 & \text{if } i > \lfloor \frac{t \cdot L}{T} \rfloor + 3 \end{cases} $$
    Where $t$ is current iteration, $T$ is total iterations, $L$ is tensor component length, and $\alpha_i$ is the mask value for the $i$-th bit [S13, unofficial].
*   **Point Perturbation:**
    $$ p_{shifted} = p + p_{rand} \cdot \delta(\cdot) \cdot \frac{d}{\|d\|_2} $$
    Where $p$ is the query point, $p_{rand} \sim U[0, 1]$, $\delta(\cdot)$ is the sampling step size, and $d$ is the ray viewing direction [S2].

### Parameters with Typical Values
*   **Optimizer:** Adam [S1, S2, S3, S4, S6, S9, S11][S12, unofficial], AdamW [S14], RMSProp [S11].
*   **Learning Rate:** $10^{-3}$ to $10^{-2}$ for initial stages, decaying to $10^{-4}$ or lower [S1, S2, S3, S4, S6, S9, S11][S12, unofficial].
*   **Batch Size:** 512 points [S1], 216 pixels [S3], 4096 rays [S4, S9][S12, unofficial], 8192 rays [S2, S10], 25k rays [S11], $2^{16}$ pixels [S6].
*   **Iterations:** 10k-20k for coarse stage [S2], 25k [S3, S6], 30k [S5], 100k [S11], 200k [S4, S11].
*   **Voxel Resolution:** $128^3$ initial, $300^3$ target [S12, unofficial]; $190^3$ for dynamic scenes [S8].
*   **Weight Decay:** $0.1$ for hash grids [S6], $10^{-9}$ for grids [S3], $0.001$ for AdamW [S14].

### Edge Cases and Pitfalls
*   **Overfitting:** High-frequency details may lead to artifacts in complex scenes (e.g., 'Drums' scene in Synthesis NeRF) [S13, unofficial].
*   **Memory Limitations:** Large batch sizes or high-resolution grids may exceed GPU memory, requiring mixed precision or smaller batch sizes [S3][S12, unofficial].
*   **Convergence Stability:** Aggressive learning rates or insufficient warm-up can lead to divergence, especially in early training stages [S3, S6].
*   **Noise Sensitivity:** Gaussian noise applied during training should be removed during fine-tuning to avoid blurring [S4].
*   **Boundary Conditions:** Sampling near camera near-plane requires careful handling to avoid numerical instability (e.g., `min_near` parameter) [S12, unofficial].

### Pseudocode
```python
def initialize_training_config(opt):
    """
    Initialize training configuration based on options.
    opt: argparse.Namespace containing hyperparameters.
    """
    # 1. Set random seed
    set_seed(opt.seed)
    
    # 2. Define Model
    model = NeRFNetwork(
        resolution=[opt.resolution0] * 3,
        bound=opt.bound,
        cuda_ray=opt.cuda_ray,
        density_scale=1,
        min_near=opt.min_near,
        density_thresh=opt.density_thresh,
        bg_radius=opt.bg_radius
    )
    
    # 3. Define Optimizer
    # Separate learning rates for embeddings (voxel grids) and networks (MLP)
    params = model.get_params(opt.lr0, opt.lr1)
    optimizer = torch.optim.Adam(
        params, 
        betas=(opt.beta1, opt.beta2), 
        eps=opt.eps, 
        weight_decay=opt.weight_decay
    )
    
    # 4. Define Scheduler
    # Exponential decay to 0.1 * init_lr at last iteration
    scheduler = torch.optim.lr_scheduler.LambdaLR(
        optimizer, 
        lambda iter: opt.lr_decay_rate ** min(iter / opt.iters, 1)
    )
    
    # 5. Define Loss Function
    criterion = torch.nn.MSELoss(reduction='none')
    
    # 6. Initialize Trainer
    trainer = Trainer(
        name='ngp',
        opt=opt,
        model=model,
        device=torch.device('cuda' if torch.cuda.is_available() else 'cpu'),
        workspace=opt.workspace,
        optimizer=optimizer,
        criterion=criterion,
        ema_decay=opt.ema_decay,
        fp16=opt.fp16,
        lr_scheduler=scheduler,
        scheduler_update_every_step=True,
        metrics=[PSNRMeter()],
        use_checkpoint=opt.ckpt,
        eval_interval=opt.eval_interval
    )
    
    # 7. Calculate Upsample Resolutions (if applicable)
    if opt.upsample_model_steps:
        upsample_resolutions = calculate_upsample_resolutions(
            opt.resolution0, 
            opt.resolution1, 
            opt.upsample_model_steps
        )
        trainer.upsample_resolutions = upsample_resolutions
        
    return trainer

def calculate_upsample_resolutions(resolution0, resolution1, steps):
    """
    Calculate exponential interpolation for upsample resolutions.
    """
    import numpy as np
    # Exponential interpolation between resolution0 and resolution1
    log_res0 = np.log(resolution0)
    log_res1 = np.log(resolution1)
    # Generate steps + 1 points, then take the last ones (excluding initial)
    resolutions = np.round(np.exp(np.linspace(log_res0, log_res1, len(steps) + 1))).astype(np.int32)
    return resolutions[1:].tolist()
```

### Dynamic Frequency Masking
A technique to mask tensor components (density or appearance feature) based on training iteration to enhance high-frequency details in later stages and mitigate overfitting [S13, unofficial]. It calculates mask values using integer and fractional parts for smooth transition during training ($t < T$) and returns ones after training ($t \ge T$) [S13, unofficial]. Introduced in FreeNeRF [4] and used in Few TensoRF [S13, unofficial]. Pitfall: May struggle with intricate details and hidden angles in complex scenes like 'Drums' [S13, unofficial].

### NeRF-RPN Training Augmentation and Optimization
Applies random flips along x and y axes (prob 0.5), random z-axis rotations by $\pi/2$ (prob 0.5), and small z-axis rotations by $\alpha \in [-\pi/18, \pi/18]$ (prob 0.5) [S14]. Uses AdamW optimizer with initial learning rate 0.0003 and weight decay 0.001 [S14]. Loss weights $\lambda = 5.0$ for Eq. (3) and $\lambda = 1.0$ for Eq. (6) [S14].

### Batch Size Configuration for Past Rays
Evaluates performance across different ratios of $m_p$ (past task rays) to $m_c$ (current task rays) [S15]. On Tanks and Temples/Barn with $m_c=4096$, $m_p=m_c/2$ yields PSNR 22.14 / MS-SSIM 0.836, chosen as the optimal trade-off between performance and computational efficiency [S15].

## Operating characteristics
*   **Time Complexity:** Training time varies significantly by method and hardware. For example, 25k iterations on a single RTX 3090 may take 1-2 days for generalizable modules [S9], while per-scene optimization with voxel grids can take ~15 minutes [S2]. Dynamic scenes with 200k iterations may take hours to a day on 4x A5000 GPUs [S7].
*   **Memory Complexity:** Depends on grid resolution and batch size. High-resolution grids (e.g., $512^3$) and large batch sizes (e.g., 8192 rays) require significant VRAM, often necessitating mixed precision or gradient checkpointing [S2, S10].
*   **Scaling:** Performance generally improves with more iterations and larger batch sizes, but with diminishing returns and increased computational cost [S8, S15]. Upsampling strategies can improve quality but increase memory usage [S11][S12, unofficial].
*   **Strengths:** Flexible configuration allows tuning for specific datasets and hardware constraints. Mixed precision and CUDA acceleration significantly speed up training [S12, unofficial].
*   **Limitations:** Hyperparameter tuning is non-trivial and sensitive to dataset characteristics. Overfitting can occur with excessive iterations or insufficient regularization [S13, unofficial].
*   **When to Use:** Standard for training any differentiable radiance field. Specific configurations (e.g., warm-start, dynamic masking) are used for specialized tasks like dynamic scenes or few-shot learning.

## Background
The concept of training configuration in neural radiance fields emerged with the original NeRF paper [S19, S10] and has evolved alongside various representations (MLP, Voxel, Hash Grids). Key developments include the introduction of multi-resolution hash encoding [S6], voxel grid optimization [S2], and adaptive sampling strategies [S3][S12, unofficial]. The configuration has become increasingly complex to handle diverse scenarios such as dynamic scenes [S8], blurred images [S11], and few-shot learning [S13, unofficial].
