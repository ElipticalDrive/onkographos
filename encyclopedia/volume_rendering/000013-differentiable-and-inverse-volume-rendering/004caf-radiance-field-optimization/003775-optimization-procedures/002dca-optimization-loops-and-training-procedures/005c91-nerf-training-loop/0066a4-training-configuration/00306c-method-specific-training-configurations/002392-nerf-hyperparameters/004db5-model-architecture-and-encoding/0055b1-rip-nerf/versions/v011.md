# Rip-NeRF

Also called: Rip-NeRF25k

## Overview
Rip-NeRF is a hybrid radiance field method that renders high-fidelity, anti-aliased images by combining cone casting with anisotropic 3D Gaussian characterization and Ripmap Encoding [S1]. It differs from sibling methods like Zip-NeRF by using Platonic Solid Projection to enable efficient anisotropic area-sampling, whereas Zip-NeRF relies on a multi-sampling mechanism that is less efficient [S1].

## How it works
**Inputs:** A set of calibrated multi-view 2D images.
**Outputs:** Rendered RGB images for novel viewpoints.

**Data Structures:**
1.  **Ripmap Encoding:** A hierarchical feature grid.
    *   Base level $R_{0,0}$: Learnable tensor of shape $H \times W \times C$. Default: $H=512, W=512, C=16$ [S1].
    *   Derived levels $R_{i,j}$: Generated from $R_{0,0}$ using average pooling; not learnable [S1].
2.  **Platonic Solid:** A geometric proxy for the 3D Gaussian. Default: Icosahedron with 10 unparalleled faces $\{P_i | i = 1, \dots, n\}$ [S1].
3.  **3D Gaussian:** Characterizes a conical frustum, parameterized by mean $\boldsymbol{\mu}$ and covariance $\boldsymbol{\Sigma}$ [S1].
4.  **Tiny MLP ($F_\theta$):** Takes aggregated features and view direction to output density $\sigma$ and color $\mathbf{c}$ [S1].
5.  **Binary Occupancy Grid:** Used to skip empty space samples (via NerfAcc) [S1].

**Numbered Steps:**

1.  **Cone Casting and Frustum Division:** For each pixel, cast a cone into the scene and divide it into multiple conical frustums [S1].
2.  **Gaussian Characterization:** Characterize each conical frustum as an anisotropic 3D Gaussian with mean $\boldsymbol{\mu}$ and covariance $\boldsymbol{\Sigma}$ [S1].
3.  **Platonic Solid Projection:** Project the 3D Gaussian onto the $n$ faces of the Platonic solid. For each face $P_i$, compute the projected 2D Gaussian parameters $(\boldsymbol{\mu}_{proj}^i, \boldsymbol{\Sigma}_{proj}^i)$ using the projection matrix $M_i \in \mathbb{R}^{3 \times 2}$:
    $$ \boldsymbol{\mu}_{proj}^i = M_i^T \boldsymbol{\mu} $$
    $$ \boldsymbol{\Sigma}_{proj}^i = M_i^T \boldsymbol{\Sigma} M_i $$
    [S1]
4.  **Ripmap Query:** For each face $P_i$, query a feature vector $\mathbf{f}_i$ from the Ripmap Encoding using tetra-linear interpolation. The interpolation position $(p_x, p_y)$ and level $(l_x, l_y)$ are determined by $\boldsymbol{\mu}_{proj}^i$ and $\boldsymbol{\Sigma}_{proj}^i$ respectively [S1].
    *   The level indices are determined by the covariance scale. A hyper-parameter $w=2.0$ adjusts the probability mass coverage [S1].
    *   Tetra-linear interpolation on the Ripmap $R$ at indices $(i, j)$ is defined as:
        $$ R_{i,j} = \begin{cases} \text{Avg}_{2\times1} R_{i, j-1} & \text{if } j \neq 0 \\ \text{Avg}_{1\times2} R_{i-1, j} & \text{if } i \neq 0 \text{ and } j = 0 \\ R_{0,0} & \text{otherwise} \end{cases} $$
        where $i, j$ are level indices in $x$ and $y$ directions [S1].
5.  **Feature Aggregation:** Concatenate all feature vectors $\{\mathbf{f}_i | i = 1, \dots, n\}$ from the Platonic faces and the encoded view direction $\mathbf{d}$ to form the final feature vector $\mathbf{f}$ [S1].
6.  **Density and Color Estimation:** Pass $\mathbf{f}$ through the tiny MLP $F_\theta$ to estimate density $\sigma$ and color $\mathbf{c}$ [S1].
7.  **Volume Rendering:** Render the pixel color using standard volume rendering with the estimated $\sigma$ and $\mathbf{c}$ [S1].
8.  **Optimization:** Optimize the system end-to-end using a photometric loss scaled by the pixel footprint area ($L_{area}$) [S1].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class RipNeRF:
    def __init__(self, ripmap_shape=(512, 512, 16), num_faces=10, w=2.0):
        """
        Initialize Rip-NeRF.
        :param ripmap_shape: (H, W, C) of base level R_0,0
        :param num_faces: Number of faces on the Platonic solid (default 10 for icosahedron)
        :param w: Hyper-parameter for level selection (default 2.0)
        """
        self.num_faces = num_faces
        self.w = w
        
        # Base level Ripmap is learnable
        self.R_0_0 = nn.Parameter(torch.randn(*ripmap_shape))
        
        # Tiny MLP for density and color
        # Input dim: num_faces * C + direction_encoding_dim
        # Output dim: 4 (sigma, r, g, b)
        self.mlp = nn.Sequential(
            nn.Linear(num_faces * ripmap_shape[2] + 16, 64), # 16 for direction encoding [G]
            nn.ReLU(),
            nn.Linear(64, 4)
        )
        
        # Projection matrices for the 10 faces of an icosahedron [G]
        # In practice, these are fixed geometric constants derived from the icosahedron vertices
        self.projection_matrices = self._get_icosahedron_projections()

    def _get_icosahedron_projections(self):
        """
        Returns a list of 10 projection matrices M_i (3x2) for the icosahedron faces.
        This is a placeholder for the specific geometric derivation.
        """
        # [G] Implementation detail: Derive M_i from the normal vectors and basis vectors 
        # of the 10 triangular faces of a unit icosahedron.
        return torch.zeros(10, 3, 2) 

    def get_derived_level(self, i, j):
        """
        Computes derived Ripmap level R_{i,j} from R_0,0 using average pooling.
        Only R_0,0 is learnable.
        """
        if i == 0 and j == 0:
            return self.R_0_0
        
        # Determine the parent level based on the recurrence relation
        # R_{i,j} is derived from R_{i, j-1} (if j!=0) or R_{i-1, j} (if j==0 and i!=0)
        # This implies a hierarchical structure where levels are downsampled.
        # For simplicity, we assume i and j represent downsample factors.
        # If j != 0, we pool along Y from (i, j-1)
        # If j == 0 and i != 0, we pool along X from (i-1, 0)
        
        # Note: The source defines R_{i,j} recursively. To implement this efficiently,
        # one would typically precompute or cache these levels or use a single large grid
        # with appropriate striding. Here we simulate the logic.
        
        # To avoid infinite recursion in this simplified pseudocode, we assume
        # i and j are small integers representing the level index.
        # In a real implementation, this would be a CUDA kernel or efficient pooling chain.
        
        # Base case handled above.
        # Recursive step:
        if j != 0:
            # Pool Y from (i, j-1)
            # We need to get (i, j-1) first.
            prev_level = self.get_derived_level(i, j - 1)
            # Avg pool 2x1 (height 2, width 1)
            # Assuming the tensor is (H, W, C)
            # We need to downsample the H dimension by 2
            if prev_level.shape[0] % 2 != 0:
                prev_level = prev_level[:-1, :, :] # Handle odd dimensions
            return F.avg_pool2d(prev_level.permute(2, 0, 1), kernel_size=(2, 1)).permute(1, 2, 0)
        else:
            # Pool X from (i-1, 0)
            prev_level = self.get_derived_level(i - 1, 0)
            # Avg pool 1x2 (height 1, width 2)
            if prev_level.shape[1] % 2 != 0:
                prev_level = prev_level[:, :-1, :]
            return F.avg_pool2d(prev_level.permute(2, 0, 1), kernel_size=(1, 2)).permute(1, 2, 0)

    def query_ripmap(self, ripmap_tensor, pos, level):
        """
        Tetra-linear interpolation on the Ripmap tensor.
        :param ripmap_tensor: The feature grid (H, W, C)
        :param pos: (px, py) normalized coordinates [0, 1]
        :param level: (lx, ly) integer indices determining the resolution
        """
        # Map normalized pos to grid coordinates
        h, w, c = ripmap_tensor.shape
        px = pos[0] * w
        py = pos[1] * h
        
        # Determine grid resolution based on level
        # Level (lx, ly) implies downsampling by 2^lx and 2^ly
        # Effective resolution
        eff_h = h / (2 ** level[0])
        eff_w = w / (2 ** level[1])
        
        # Map pos to effective grid
        eff_px = px / (2 ** level[0])
        eff_py = py / (2 ** level[1])
        
        # Bilinear interpolation on the effective grid
        # Since the source uses tetra-linear, it likely interpolates in 3D (x, y, level)
        # But here levels are discrete. The source says "tetra-linear interpolation... 
        # position and level used in interpolation are determined by mean and covariance".
        # This implies interpolating between levels as well? 
        # Eq 2 and 3 in source likely define the mapping from Gaussian params to (px, py, lx, ly).
        # For this pseudocode, we assume we have selected the best level or interpolated levels.
        # Given the recursive definition, we query the specific derived level.
        
        # Interpolate at (eff_px, eff_py) on ripmap_tensor
        # Using bilinear interpolation
        x0 = int(torch.floor(eff_px))
        y0 = int(torch.floor(eff_py))
        x1 = x0 + 1
        y1 = y0 + 1
        
        # Clamp coordinates
        x0 = torch.clamp(x0, 0, w - 1)
        y0 = torch.clamp(y0, 0, h - 1)
        x1 = torch.clamp(x1, 0, w - 1)
        y1 = torch.clamp(y1, 0, h - 1)
        
        # Get values
        v00 = ripmap_tensor[y0, x0, :]
        v01 = ripmap_tensor[y0, x1, :]
        v10 = ripmap_tensor[y1, x0, :]
        v11 = ripmap_tensor[y1, x1, :]
        
        # Interpolate
        dx = eff_px - x0
        dy = eff_py - y0
        
        v0 = v00 * (1 - dx) + v01 * dx
        v1 = v10 * (1 - dx) + v11 * dx
        
        feature = v0 * (1 - dy) + v1 * dy
        
        return feature

    def forward(self, gaussian_params, view_direction):
        """
        Forward pass for a single conical frustum.
        :param gaussian_params: Tuple (mu, Sigma) of shape (3,) and (3,3)
        :param view_direction: Encoded view direction vector
        :return: Density sigma, Color c
        """
        mu, Sigma = gaussian_params
        
        features = []
        
        for i in range(self.num_faces):
            M_i = self.projection_matrices[i]
            
            # Project 3D Gaussian to 2D
            mu_proj = M_i.T @ mu
            Sigma_proj = M_i.T @ Sigma @ M_i
            
            # Determine position and level for Ripmap query
            # Position is determined by mu_proj
            pos = mu_proj[:2] # Assuming 2D projection
            
            # Level is determined by Sigma_proj and w
            # The source says w=2.0 adjusts probability mass coverage.
            # Typically, level is derived from the trace or eigenvalues of Sigma_proj.
            # Let's assume a simple heuristic based on covariance scale.
            # [G] Specific formula for level from Sigma_proj is not explicitly given in notes,
            # but "level... determined by the mean and covariance".
            # We assume lx, ly are derived from the diagonal elements of Sigma_proj.
            # A common approach is to scale the covariance by w and take log2.
            scale_x = torch.sqrt(Sigma_proj[0, 0]) * self.w
            scale_y = torch.sqrt(Sigma_proj[1, 1]) * self.w
            
            # Map scale to level index (higher scale -> higher level -> lower resolution)
            # Assuming base level is 0.
            lx = int(torch.clamp(torch.log2(scale_x + 1e-6), 0, 9))
            ly = int(torch.clamp(torch.log2(scale_y + 1e-6), 0, 9))
            
            level = (lx, ly)
            
            # Get derived Ripmap level
            R_ij = self.get_derived_level(lx, ly)
            
            # Query feature
            f_i = self.query_ripmap(R_ij, pos, level)
            features.append(f_i)
            
        # Concatenate features
        f_concat = torch.cat(features, dim=-1)
        
        # Concatenate view direction
        # [G] Assuming view_direction is already encoded to 16 dims
        input_vec = torch.cat([f_concat, view_direction], dim=-1)
        
        # MLP
        output = self.mlp(input_vec)
        sigma_raw = output[0]
        color = output[1:]
        
        # Activate density
        sigma = F.softplus(sigma_raw)
        
        return sigma, color

    def compute_loss(self, rendered_image, target_image):
        """
        Compute area-aware photometric loss.
        """
        # [G] Assuming rendered_image and target_image are tensors of same shape
        # Scale loss by pixel footprint area.
        # The source mentions scaling the loss by the area of the pixel footprint.
        # This is often done by weighting the MSE by the inverse of the area or similar.
        # For simplicity, we use standard MSE as a placeholder for the area-weighted loss.
        loss = F.mse_loss(rendered_image, target_image)
        return loss
```

**Parameters:**
*   **Ripmap Base Shape:** $H=512, W=512, C=16$ [S1].
*   **Platonic Solid:** Icosahedron (10 faces) [S1].
*   **Hyper-parameter $w$:** 2.0 [S1].
*   **Optimizer:** AdamW [S1].
*   **Iterations:** 120k (standard) or 25k (Rip-NeRF25k) [S1].
*   **Weight Decay:** $1 \times 10^{-5}$ [S1].
*   **Initial Learning Rate:** $2 \times 10^{-3}$, modulated by MultiStepLR [S1].
*   **Ripmap Learning Rate:** Scaled up by 10.0 times [S1].

**Edge Cases and Pitfalls:**
*   **Empty Space:** Use a binary occupancy grid (via NerfAcc) to skip samples in empty areas [S1].
*   **Precision:** The recursive derivation of Ripmap levels requires careful handling of tensor shapes and pooling operations to maintain consistency [S1].
*   **Degenerate Input:** If the Gaussian covariance is zero or near-zero, the level selection may fail; a small epsilon should be added [G].

## Operating characteristics
*   **Training Time:** 2.6 hours on NVIDIA A100-SXM4-80GB GPU for 120k iterations [S1]. Rip-NeRF25k takes 32 minutes (11.76% of Zip-NeRF's 4.5h) [S1].
*   **Model Size:** 160 MB [S1].
*   **GPU Memory:** 20 GB during training [S1].
*   **Rendering Speed:** 3 FPS [S1].
*   **Comparison:** Outperforms Zip-NeRF in training time (2.6h vs 4.5h), model size (160MB vs 592MB), and rendering speed (3 FPS vs 0.25 FPS). Zip-NeRF has slightly better SSIM [S1].
*   **Strengths:** High-fidelity anti-aliasing, efficient anisotropic area-sampling, compact representation [S1].
*   **Limitations:** Requires calibrated multi-view images [S1].

## Background
Rip-NeRF was introduced in 2024 by SRN et al. in the paper "Rip-NeRF: Anti-aliasing Radiance Fields with Ripmap-Encoded Platonic Solids" [S1]. It builds on the hybrid representation approach of methods like Mip-NeRF and Tri-MipRF, aiming to improve efficiency and quality over Zip-NeRF [S1].
