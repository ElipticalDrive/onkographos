# Frequency-Modulated Position Encoding

Also called: FM-NeRF Encoding, Frequency-Modulated Point Cloud Rendering with Easy Editing

## Overview
Frequency-Modulated Position Encoding is a positional encoding scheme used in point-based radiance field optimization methods, specifically designed to provide fine-grained basis function support for frequency modulation of spatial coordinates and view directions. It solves the problem of representing high-frequency geometric details in sparse point clouds by narrowing the encoding interval compared to standard NeRF embeddings. It sets itself apart from standard NeRF encoding by using a specific power-of-2 exponent progression ($2^0, 2^{0.5}, \dots, 2^{L-1}$) rather than integer powers, and is distinct from sibling methods like [Mip-NeRF 360 MLP Architecture](14098-mip-nerf-360-mlp-architecture.md) which uses integrated positional encoding for anti-aliasing, or [CCNeRF](15008-ccnerf.md) which relies on different architectural priors.

## How it works
The method encodes 3D spatial coordinates $\mathbf{p}$ and view directions $\mathbf{v}$ into a high-dimensional vector using sine and cosine functions with geometrically spaced frequencies. This encoded vector is then concatenated and fed into a Multi-Layer Perceptron (MLP) to predict color and opacity.

**Inputs and Outputs:**
*   **Input:** A 3D point coordinate $\mathbf{p} \in \mathbb{R}^3$ or a view direction vector $\mathbf{v} \in \mathbb{R}^3$.
*   **Output:** An encoded feature vector $\gamma(\cdot) \in \mathbb{R}^{2 \cdot 3 \cdot L}$, where $L$ is the number of frequency bands.

**Data Structures and Layout:**
The encoding is a fixed-size vector constructed by interleaving sine and cosine terms.
*   **Spatial Encoding:** For spatial coordinates, $L=10$. The input dimension is 3. The output dimension is $2 \times 3 \times 10 = 60$.
*   **View Direction Encoding:** For view directions, $L=2$. The input dimension is 3. The output dimension is $2 \times 3 \times 2 = 12$.
*   **Total Input to MLP:** The spatial and view direction encodings are concatenated. In the specific implementation (AFNet), the total input feature dimension is 120. This implies that other features (such as point indices or raw features) are also concatenated, or the encoding is applied differently. However, based on the formula and standard practices, the position encoding itself contributes 60 (spatial) + 12 (view) = 72 dimensions. The remaining 48 dimensions in the 120-dim input likely come from point-wise features or other context, but the *position encoding* component is strictly defined by the formula below.

**Position Encoding Formula:**
The encoding function $\gamma(\mathbf{p})$ for an input $\mathbf{p}$ is defined as:

$$
\gamma (\mathbf {p}) = \left (\sin \left (2^0 \pi \mathbf {p}\right ), \cos \left (2^0 \pi \mathbf {p}\right ), \sin \left (2^{0.5} \pi \mathbf {p}\right ), \cos \left (2^{0.5} \pi \mathbf {p}\right ), \dots, \sin \left (2^{L-1} \pi \mathbf {p}\right ), \cos \left (2^{L-1} \pi \mathbf {p}\right )\right )
$$

Where:
*   $\mathbf{p}$ is the input coordinate or direction vector.
*   $L$ is the number of frequency bands.
*   The exponents are $0, 0.5, 1.0, \dots, L-1$. Note that the base is 2, and the exponent increases by 0.5 at each step, resulting in frequencies $2^0, 2^{0.5}, 2^1, \dots, 2^{L-1}$.

**Parameters:**
*   $L_{\text{spatial}} = 10$ for spatial coordinates.
*   $L_{\text{view}} = 2$ for view directions.
*   $\lambda_{\text{sparse}} = 5 \times 10^{-4}$ (weight for sparse regularization loss).
*   Learning rate for MLP weights: $5 \times 10^{-4}$.
*   Learning rate for opacity parameters $\alpha$: $0.01$.

**Pseudocode:**
```python
import numpy as np

def frequency_modulated_position_encoding(p, L):
    """
    Computes the frequency-modulated position encoding for input p.
    
    Args:
        p (np.ndarray): Input vector of shape (D,), where D is 3 for coordinates or directions.
        L (int): Number of frequency bands.
        
    Returns:
        np.ndarray: Encoded vector of shape (2 * D * L,).
    """
    # Initialize empty array to hold the result
    # Each dimension of p generates 2 * L values (sin/cos for each frequency)
    encoded = []
    
    # Iterate through frequency bands from 0 to L-1
    for i in range(L):
        # Calculate frequency: 2^(i/2)
        # Note: The formula uses 2^(0.5 * i) effectively if we consider the sequence 0, 0.5, 1.0...
        # The source formula: sin(2^0 pi p), cos(2^0 pi p), sin(2^0.5 pi p), cos(2^0.5 pi p)...
        # So the exponent is i/2.0
        freq = np.power(2, i / 2.0)
        
        # Compute scaled input
        scaled_p = freq * np.pi * p
        
        # Compute sine and cosine
        sin_vals = np.sin(scaled_p)
        cos_vals = np.cos(scaled_p)
        
        # Append to result
        encoded.append(sin_vals)
        encoded.append(cos_vals)
        
    # Concatenate all components
    result = np.concatenate(encoded)
    return result

def get_full_encoding(p, v):
    """
    Computes the full position encoding for a point and view direction.
    
    Args:
        p (np.ndarray): Spatial coordinate, shape (3,).
        v (np.ndarray): View direction, shape (3,).
        
    Returns:
        np.ndarray: Concatenated encoding vector.
    """
    # Spatial encoding with L=10
    enc_p = frequency_modulated_position_encoding(p, L=10)
    
    # View direction encoding with L=2
    enc_v = frequency_modulated_position_encoding(v, L=2)
    
    # Concatenate
    full_enc = np.concatenate([enc_p, enc_v])
    return full_enc
```

**Edge Cases and Pitfalls:**
*   **Precision:** The use of high-frequency terms ($2^{L-1}$) can lead to numerical instability if inputs are not normalized. The method assumes inputs are within a reasonable range (e.g., normalized coordinates).
*   **Bleeding:** If the rasterization radius (used to expand points to disks) is too small, points from occluded surfaces and background can be seen through the front surface. This is not a direct failure of the encoding but a rendering artifact exacerbated by sparse point representations.
*   **Edge Expansion:** If the rasterization radius is too large, it leads to inaccurate depth estimation and object edges expand. The encoding itself does not cause this, but the combination of sparse points and large radii does.

## Subtopics

### AFNet MLP
The specific neural network architecture that consumes this encoding. It is a 5-layer MLP with input dimension 120, hidden dimensions [256, 256, 256, 128], and output dimension 11 (3-channel color + 8-channel feature map). [S1]

### Point Cloud Preprocessing
The method relies on 4-20 loops of point cloud denoising and completion. Each denoising step involves 300 epochs of training. Low-opacity points are removed upon convergence. [S1]

### Rasterization Strategy
Points are expanded to disks to compensate for sparsity. The radius is chosen to cover gaps between points (to prevent bleeding) while being as small as possible (to avoid edge expansion). [S1]

## Operating characteristics
*   **Time Complexity:** One epoch consumes approximately 12.8 seconds on the NeRF-Synthetic dataset. Realistic rendering is achieved in about 10 minutes, but almost complete convergence takes about 10 hours. [S1]
*   **Memory Complexity:** The encoding increases the input dimension to the MLP. With $L=10$ for spatial and $L=2$ for view, the position encoding contributes 72 dimensions. The total input is 120, implying additional features. The MLP size is moderate (5 layers, max 256 hidden units).
*   **Measured Performance:** The method achieves higher PSNR/SSIM on NeRF-Synthetic and Tanks and Temples datasets compared to NeRF, CCNeRF, NPBG, NPBG++, and Huang et al. Results on ScanNet and DTU are comparable or better. [S1]
*   **Strengths:** Fast convergence to realistic rendering (10 mins). Good handling of sparse point clouds via frequency modulation. Easy editing capabilities via point cloud masking. [S1]
*   **Limitations:** Requires initial point clouds (e.g., from MVSNet). Sensitive to rasterization radius selection (though ablation shows effect is not significant). [S1]
*   **When to use:** When working with sparse point clouds and needing fast training times with good detail reconstruction. Suitable for scenes where editing is required. [S1]
*   **When not to use:** When dense volumetric representations are preferred, or when initial point cloud quality is very poor and cannot be improved by denoising/completion loops. [S1]

## Background
The method was introduced in the paper "Frequency-Modulated Point Cloud Rendering with Easy Editing" by [S1]. It builds upon the NeRF positional encoding scheme but modifies the frequency progression to better suit point-based rendering. The work is part of the broader field of differentiable volume rendering and inverse graphics, specifically focusing on point-based radiance fields. It is compared against methods like NPBG, NPBG++, and CCNeRF. [S1]
