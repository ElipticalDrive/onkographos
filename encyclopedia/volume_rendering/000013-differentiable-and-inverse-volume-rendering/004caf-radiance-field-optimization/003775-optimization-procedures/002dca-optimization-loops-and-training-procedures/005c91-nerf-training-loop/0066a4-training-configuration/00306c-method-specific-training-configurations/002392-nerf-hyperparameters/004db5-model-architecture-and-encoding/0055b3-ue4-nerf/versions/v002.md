# UE4-NeRF


## Overview
UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale 3D scenes by integrating Neural Radiance Fields (NeRF) with the Unreal Engine 4 (UE4) rasterization pipeline [S1]. It partitions large environments into sub-NeRFs, representing each partition using textured polygonal meshes initialized from regular octahedra, and employs a Level of Detail (LOD) hierarchy to maintain high frame rates [S1]. Unlike sibling methods such as [Mobile-NeRF](13622-mobile-nerf.md) which rely on binary opacity and grid structures, UE4-NeRF supports semi-transparent materials and arbitrary terrain types by storing opacity in texture maps and optimizing mesh vertices [S1].

## How it works
### Inputs and Outputs
**Inputs:**
*   A set of posed images captured by a drone or camera, including GPS coordinates [S1].
*   Camera intrinsics and extrinsics [S1].
*   Scene bounding box defined in a real-world coordinate system [S1].

**Outputs:**
*   Textured polygonal meshes at multiple Levels of Detail (LOD) [S1].
*   A neural shader (HLSL fragment shader) deployed in UE4 that maps feature vectors to colors [S1].
*   Final real-time rendered video frames [S1].

### Data Structures
**1. Scene Partitioning:**
The scene is divided into overlapping blocks (sub-NeRFs). Each block's training area is slightly larger than the target scene area to ensure smooth transitions at boundaries [S1].

**2. Mesh Representation:**
*   **Geometry:** Regular octahedra with 20 faces (8 exterior, 12 interior) [S1].
*   **Vertices:** Continuously optimized during training [S1].
*   **Texture Atlas:** Stores feature vectors and opacity information for each mesh face [S1].

**3. Neural Network Architectures:**
*   **Encoder Network ($E$):**
    *   Input: Hash-encoded position $\mathbf{p}_i$ [S1].
    *   Structure: 4-layer MLP.
    *   Dimensions: $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
    *   Output: Opacity $\alpha_i$ and an 8-dimensional feature vector $\mathbf{M}_i$ [S1].
*   **Decoder Network ($D$):**
    *   Input: Feature vector $\mathbf{M}_i$ and view direction $\mathbf{d}_i$ [S1].
    *   Structure: 3-layer MLP.
    *   Dimensions: $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
    *   Output: Final color $\mathbf{c}_i$ [S1].

**4. Coordinate System:**
*   X-axis: East.
*   Y-axis: South.
*   Z-axis: Up.
*   Scale: 100:1 (UE4 units to real-world units) [S1].

### Steps

1.  **Coordinate Transformation:**
    Convert GPS-captured drone imagery coordinates to the UE4 coordinate system (X=East, Y=South, Z=Up) and apply the 100:1 scale conversion [S1].

2.  **Block Partitioning:**
    Partition the large-scale scene into multiple blocks. Train a coarse model for sub-region segmentation to capture overall terrain and building outlines. Filter images associated with sub-regions and use a mask to exclude pixels outside the scene area [S1].

3.  **Mesh Initialization:**
    Initialize a $128 \times 128 \times 128$ grid. Select the center point of each grid along with its six neighboring grids (front, back, left, right, top, bottom) to create polygonal meshes. Use regular octahedra with 20 faces (8 exterior, 12 interior) to address slow convergence on tilted surfaces [S1].

4.  **Training Loop (Per Block):**
    For each block, optimize the Encoder-Decoder network parameters and mesh vertex positions for 80,000 epochs [S1].
    
    **Ray Sampling:**
    For a ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$, where $\mathbf{o}$ is the camera origin and $\mathbf{d} = (\theta, \phi)$ is the viewing direction, calculate the intersection with the polygonal meshes. The intersection point serves as the sampling point [S1].

    **Forward Pass:**
    Encode the position $\mathbf{p}_i$ using multi-resolution hash encoding (from Instant-NGP) [S1].
    $$ \mathbf{M}_i, \alpha_i = E(\text{hash}(\mathbf{p}_i); \theta_E) $$
    $$ \mathbf{c}_i = D(\mathbf{M}_i, \text{SH}(\mathbf{d}_i); \theta_D) $$
    Where $\text{SH}(\mathbf{d}_i)$ denotes spherical harmonics encoding of the view direction [S1].

    **Loss Function:**
    Minimize the difference between predicted color $\mathbf{c}_i$ and ground truth color using PSNR/SSIM and LPIPS metrics [S1].

5.  **LOD Generation:**
    Train meshes with varying levels of detail for different observation heights. Coarser meshes are used for higher observation heights to ensure real-time performance [S1].

6.  **Shading Mesh Extraction:**
    Extract coarse polygonal meshes without textures during training. Apply vertex optimization. Encode texture maps in network outputs [S1].

7.  **Rendering Integration:**
    Implement the Decoder network as an HLSL fragment shader in UE4. The shader takes feature vectors (from the texture atlas) as input and outputs colors. Combine pre-rendered polygon meshes with the UE4 rasterization pipeline [S1].

### Parameters
*   **Grid Initialization Size:** $128 \times 128 \times 128$ [S1].
*   **Octahedron Faces:** 20 faces total (8 exterior, 12 interior) [S1].
*   **Encoder MLP:** 4 layers, dimensions $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
*   **Decoder MLP:** 3 layers, dimensions $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
*   **Training Hardware:** 1 Nvidia RTX 3090 GPU [S1].
*   **Training Iterations:** 80,000 epochs per block [S1].
*   **Coordinate System:** X=East, Y=South, Z=Up [S1].
*   **World Scale:** 100:1 [S1].

### Edge Cases and Pitfalls
*   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces; UE4-NeRF addresses this by using regular octahedra [S1].
*   **Semi-transparent Objects:** Mobile-NeRF cannot handle transparent/semi-transparent objects (water, glass) due to opacity binarization. UE4-NeRF stores opacity in texture maps to mitigate this [S1].
*   **Performance Degradation:** Semi-transparent objects (e.g., vegetation) increase computational overhead, reducing frame rates [S1].
*   **Rendering Gaps:** Pre-rendering cannot capture rays from all viewing angles, resulting in gaps or holes in the final rendered scene [S1].
*   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, causing evaluation metrics (PSNR/SSIM/LPIPS) to underestimate actual reconstruction quality [S1].
*   **Memory Overhead:** Requires CUDA and NVIDIA GPUs. Rendering large scenes (square kilometers) incurs significant memory overhead, which increases with accuracy [S1].

## Operating characteristics
*   **Training Speed:** 1000× faster than Mobile-NeRF [S1].
*   **Training Time:** 40 minutes per block on 1×RTX 3090. Full scene training time is $1 \text{ hour} + (40 \text{ minutes} \times n/4)$ for $n$ blocks [S1].
*   **Rendering Performance:** Real-time rendering at 4K resolution with up to 43 FPS. 50 FPS on full scene at 2K resolution; ≥70 FPS on individual blocks at 2K resolution [S1].
*   **Scalability:** Suitable for large-scale scenes (square kilometers) including mountainous terrain, farmland, and construction sites [S1].
*   **Strengths:** Real-time interactive rendering, scene editing capabilities (importing .obj/.fbx), handling of semi-transparent materials, high fidelity on small objects and dense textures [S1].
*   **Limitations:** Requires NVIDIA GPUs/CUDA, memory overhead for large scenes, potential gaps/holes in pre-rendered meshes, exposure matching issues in UE4 [S1].

## Background
UE4-NeRF was introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" as a real-time interactive rendering system combining NeRF with UE4's rasterization pipeline [S1]. It was developed to address the limitations of previous NeRF methods in real-time rendering of large-scale scenes, such as high training costs, inability to handle semi-transparent objects, and lack of scene editing capabilities [S1]. The method builds on [Model Architecture and Encoding](13550-model-architecture-and-encoding.md) by utilizing multi-resolution hash encoding for acceleration [S1]. It is used in Unreal Engine 4 for drone-captured large-scale scenes and evaluated on the Mega-NeRF public dataset [S1].
