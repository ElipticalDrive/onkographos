# SUDS

Also called: SUDS, Scalable Urban Dynamic Scenes

## Overview
SUDS is a 4D radiance field representation designed for large-scale dynamic urban scenes that factorizes the scene into three separate hash table data structures to efficiently encode static, dynamic, and far-field radiance fields [S1]. It enables free-viewpoint rendering, semantic decomposition, and 3D scene flow estimation at arbitrary poses and time steps using multiple video inputs without requiring supervised 3D annotations like bounding boxes or panoptic labels [S1]. Unlike sibling methods that rely on per-object NeRFs or global MLPs, SUDS uses a multi-resolution hash table with scene partitioning to scale to hundreds of kilometers and tens of thousands of objects, handling ego-motion and multi-video lighting variations [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   $N$ ordered RGB images from different videos (varying days, weather, lighting) with associated camera poses [S1].
*   Aligned sparse LiDAR depth measurements [S1].
*   2D self-supervised DINO descriptors (teacher features) [S1].
*   2D optical flow predictions [S1].
*   Query tuple: $(\mathbf{x}, \mathbf{d}, t, \text{vid})$, where $\mathbf{x} \in \mathbb{R}^3$ is position, $\mathbf{d} \in S^2$ is viewing direction, $t$ is frame index, and $\text{vid} \in \{1, \dots, N\}$ is video ID [S1].

**Outputs:**
*   Per-branch color ($\mathbf{c}$), density ($\sigma$), and semantic feature logits ($\Phi$) [S1].
*   Dynamic branch outputs: time/video-dependent density $\sigma_d$, color $\mathbf{c}_d$, shadow ratio $\rho_d \in [0,1]$, and forward/backward 3D scene flow vectors $\mathbf{s}_{t0} \in [-1, 1]^3$ [S1].
*   Final rendered color $\hat{C}(\mathbf{r})$ and feature $\hat{F}(\mathbf{r})$ [S1].

### Data Structures
The scene is decomposed into $K$ spatial cells with centroids $\mathbf{k} \in \mathbb{R}^3$. Each cell maintains three independent multi-resolution hash table branches: Static, Dynamic, and Far-field [S1].

**Hash Table Layout:**
*   **Structure:** Multi-resolution hash tables similar to Instant-NGP [S1].
*   **Levels:** $L$ resolution levels, where resolution doubles between levels [S1].
*   **Feature Dimension:** $F$ (dimensionality of feature vectors in the hash tables) [S1].
*   **Storage:** Hash indices map to $F$-dimensional feature vectors. Hash collisions are handled via gradient averaging [S1].
*   **Voxel Types:**
    *   Static: 3D spatial voxels $v_{l,s}$ [S1].
    *   Dynamic: 4D spacetime voxels $v_{l,d}$ [S1].
    *   Far-field: 3D voxels $v_{l,e}$ indexed by normalized 3D direction vectors [S1].

**Hash Functions:**
Indices are computed for voxel corners using specific hash functions [S1]:
1.  Static: $i_{l,s} = \text{static hash}(\text{space}(v_{l,s}))$
2.  Dynamic: $i_{l,d} = \text{dynamic hash}(\text{space}(v_{l,d}), \text{time}(v_{l,d}), \text{vid})$
3.  Far-field: $i_{l,e} = \text{env hash}(\text{dir}(v_{l,e}), \text{vid})$

The video ID ($\text{vid}$) is included in the dynamic and far-field hash functions to index separate interpolating functions for each video without linear memory growth [S1].

### Numbered Steps

1.  **Spatial Partitioning:** Split the scene into $K$ spatial cells. Generate separate training datasets for each cell by including only datapoints whose camera rays intersect the cell. Prune irrelevant rays using LiDAR depth measurements to ensure visibility [S1].
2.  **Voxel Lookup:** For a query $(\mathbf{x}, \mathbf{d}, t, \text{vid})$, find surrounding voxels at $L$ resolution levels for the static ($v_{l,s}$), dynamic ($v_{l,d}$), and far-field ($v_{l,e}$) branches [S1].
3.  **Hash Indexing:** Compute hash indices for the corners of the surrounding voxels using the hash functions defined above [S1].
4.  **Feature Interpolation:**
    *   Look up feature vectors corresponding to the corners.
    *   Perform linear interpolation for the static branch.
    *   Perform quadlinear interpolation for the dynamic 4D branch [S1].
    *   Concatenate results from all $L$ levels into a feature vector $\mathbf{f} \in \mathbb{R}^{LF}$ [S1].
5.  **MLP Evaluation:** Pass the concatenated feature vector $\mathbf{f}$ and auxiliary inputs into an MLP to obtain per-branch outputs [S1].
    *   **Static Branch:** Outputs view-dependent color $\mathbf{c}_s(\mathbf{x}, \mathbf{d}, \mathbf{A}_{\text{vid}} \mathbf{F}(t)) \in \mathbb{R}^3$ and view-independent density $\sigma_s(\mathbf{x}) \in \mathbb{R}$ [S1].
        *   $\mathbf{F}(t)$ is a Fourier-encoded time index [S1].
        *   $\mathbf{A}_{\text{vid}}$ is a video-specific matrix for lighting variations [S1].
    *   **Dynamic Branch:** Outputs time/video-dependent density $\sigma_d(\mathbf{x}, t, \text{vid}) \in \mathbb{R}$, color $\mathbf{c}_d(\mathbf{x}, t, \text{vid}, \mathbf{d}) \in \mathbb{R}^3$, shadow ratio $\rho_d(\mathbf{x}, t, \text{vid}) \in [0, 1]$, semantic features $\Phi_d(\mathbf{x}, t, \text{vid}) \in \mathbb{R}^C$, and scene flow $\mathbf{s}_{t0}(\mathbf{x}, t, \text{vid}) \in \mathbb{R}^3$ [S1].
    *   **Far-field Branch:** Outputs environment map color $\mathbf{c}_e(\mathbf{d}, \text{vid}) \in \mathbb{R}^3$ and semantic features $\Phi_e(\mathbf{d}, \text{vid}) \in \mathbb{R}^C$ [S1].
    *   **Static Semantic Features:** $\Phi_s(\mathbf{x}) \in \mathbb{R}^C$ [S1].
6.  **Density Combination:** Compute total density as the sum of static and dynamic densities [S1]:
    $$ \sigma(\mathbf{x}, t, \text{vid}) = \sigma_s(\mathbf{x}) + \sigma_d(\mathbf{x}, t, \text{vid}) $$
7.  **Radiance Combination:** Compute total radiance by combining static and dynamic components, scaled by the shadow ratio [S1]:
    $$ \mathbf{c}(\mathbf{x}, t, \text{vid}, \mathbf{d}) = \frac{(1 - \rho_d)\sigma_s \mathbf{c}_s + \sigma_d \mathbf{c}_d}{\sigma} $$
8.  **Feature Combination:** Combine semantic features $\Phi_s, \Phi_d, \Phi_e$ similarly to radiance [S1].
9.  **Rendering:** Render color $\hat{C}(\mathbf{r})$ and features $\hat{F}(\mathbf{r})$ along ray $\mathbf{r}$ using standard volume rendering integration. If the ray does not hit geometry within the foreground, force intersection with the far-field environment map [S1]:
    $$ \hat{C}(\mathbf{r}, t, \text{vid}) = \int_0^{+\infty} T(t) \sigma(\mathbf{r}(t), t, \text{vid}) \mathbf{c}(\mathbf{r}(t), t, \text{vid}, \mathbf{d}) dt + T(+\infty) \mathbf{c}_e(\mathbf{d}, \text{vid}) $$
    where $T(t) = \exp\left(-\int_0^t \sigma(\mathbf{r}(s), t, \text{vid}) ds\right)$ [S1].

### Parameters
*   $F$: Dimensionality of feature vectors in the multi-resolution hash tables [S1].
*   $L$: Number of resolution levels in the hash table hierarchy (resolution doubles between levels) [S1].
*   $N$: Number of input videos [S1].
*   $\text{vid}$: Video ID identifier used as an auxiliary input to the hash function [S1].
*   $\mathbf{A}_{\text{vid}}$: Video-specific matrix used to compute a latent embedding for lighting variations [S1].
*   $\mathbf{F}(t)$: Fourier-encoded time index [S1].
*   $k$: Constant set to 1.75 in the skewed binary entropy loss [S1].
*   $C$: Dimensionality of the feature grid output from the DINO teacher model ($\mathbb{R}^{H \times W \times C}$) [S1].
*   Training Iterations: 250,000 [S1].
*   Rays per Batch: 4,098 [S1].
*   Initial Learning Rate: $5 \times 10^{-3}$ [S1].
*   Final Learning Rate: $5 \times 10^{-4}$ (decayed from initial) [S1].
*   Optimizer: Adam [S1].

### Edge Cases and Pitfalls
*   **Hash Collisions:** Handled via gradient averaging [S1].
*   **Occlusions:** Warping losses are downweighted in ambiguous regions using a weight $W_{t0}(\mathbf{r})$ derived from dynamic geometry difference [S1].
*   **Shadow Over-explanation:** Penalized by the squared magnitude of the shadow ratio $\rho_d$ along each ray to prevent it from explaining dark regions [S1].
*   **Static-Dynamic Factorization:** A skewed binary entropy loss with $k=1.75$ favors static explanations of the scene [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Memory:** Scales linearly with the number of videos due to the video ID in the hash function, but avoids linear growth in memory with the number of videos by indexing separate interpolating functions without storing explicit per-video data structures [S1]. Compared to NSG, which requires over 1TB of memory for a 30-second video, SUDS is significantly more memory efficient [S1].
*   **Training Time:** SUDS is 10x quicker to train than state-of-the-art methods that rely on ground truth 3D bounding box annotations [S1].

### Measured Performance
*   SUDS scales to tens of thousands of objects across 1.2 million frames from 1,700 videos spanning geospatial footprints of hundreds of kilometers [S1].
*   Surpasses state-of-the-art methods on KITTI and Virtual KITTI 2 datasets [S1].

### Strengths and Limitations
*   **Strengths:** Handles ego-motion and multi-video representations; uses unlabeled inputs (RGB, LiDAR, optical flow) for supervision; enables unsupervised 3D instance segmentation and 3D cuboid detection; models shadows explicitly [S1].
*   **Limitations:** Requires aligned sparse LiDAR and optical flow predictions (though these are "free" supervision sources, they require external computation) [S1].

### When to Use
*   Use SUDS for large-scale dynamic urban scene reconstruction where ego-motion is present and labeled 3D data (bounding boxes, panoptic labels) is unavailable or expensive [S1].
*   Use when semantic decomposition and scene flow estimation are required [S1].

### When Not to Use
*   Do not use for small-scale, static scenes where simpler NeRF variants suffice.
*   Do not use if computational resources for generating optical flow and LiDAR alignment are unavailable [S1].

## Background

### Origin
SUDS (Scalable Urban Dynamic Scenes) was introduced in the paper "SUDS: Scalable Urban Dynamic Scenes" [S1]. It was presented at CVPR 2023 [S1].

### History and Development
SUDS builds upon Instant-NGP [S1] for hash table representation and MegaNeRF [S1] for spatial partitioning. It addresses limitations of prior dynamic scene representations like NSG [S1], which cannot handle ego-motion and are constrained by memory requirements for per-object NeRFs. SUDS extends these ideas to city-scale environments, handling multiple videos with diverse lighting and weather conditions [S1].

### Applications
*   Free-viewpoint rendering of dynamic urban scenes [S1].
*   Unsupervised 3D instance segmentation [S1].
*   Unsupervised 3D cuboid detection [S1].
*   3D scene flow estimation [S1].
