# TriDF

Also called: Triplane-Accelerated Density Fields

## Overview
TriDF is a hybrid explicit–implicit 3D representation designed for few-shot novel view synthesis (NVS) in remote sensing, specifically addressing the computational burden and overfitting issues of implicit radiance fields when trained on as few as three input views [S1]. It decouples scene representation by modeling high-frequency color information using an explicit triplane structure and low-frequency geometry using implicit continuous density fields, thereby reducing optimization competition and accelerating convergence [S1]. Unlike sibling methods that jointly model color and density or rely on dense pretraining priors, TriDF leverages sparse depth supervision from Structure-from-Motion (SfM) point clouds to guide geometry reconstruction without requiring extensive external datasets [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** $V$ input images (typically $V=3$) with known camera poses, and their corresponding depth maps or point clouds generated via SfM/PatchMatch Stereo.
*   **Outputs:** A rendered color image $\hat{C}(r)$ for a novel view ray $r$.

**Data Structures:**
1.  **Triplane ($P$):** A set of three mutually orthogonal feature planes $P = \{P_{XY}, P_{YZ}, P_{ZX}\}$. Each plane $P_{ij}$ is a tensor of size $H \times W \times C$ [S1].
    *   $H, W$: Height and width of the feature maps.
    *   $C$: Channel dimension (feature vector dimension is 64) [S1].
    *   Initialized randomly and optimized directly [S1].
2.  **Density MLP:** A Multi-Layer Perceptron (MLP) with CUTLASS architecture, width 512, and depth 8 [S1].
3.  **Color MLP:** A compact MLP used to predict color [S1].
4.  **Reference Features:** Extracted from input images using a pretrained CNN encoder [S1].

**Numbered Steps:**

1.  **Preprocessing (Point Cloud Generation):**
    Generate coarse 3D point clouds from the training views and poses using Structure-from-Motion (SfM) and PatchMatch Stereo (PMS) techniques (e.g., COLMAP) [S1]. Re-project key points and their associated depth information from these point clouds to serve as spatial anchors for depth-guided optimization [S1].

2.  **Triplane Feature Retrieval (Color Branch):**
    For a 3D spatial point $\mathbf{x}$:
    a. Project $\mathbf{x}$ orthogonally onto the three planes $P_{XY}, P_{YZ}, P_{ZX}$ [S1].
    b. Identify the four nearest grid points on each plane.
    c. Apply bilinear interpolation to compute feature vectors $\mathbf{f}_{XY}, \mathbf{f}_{YZ}, \mathbf{f}_{ZX}$ [S1].
    d. Concatenate these vectors to form the triplane feature vector:
       $$ \mathbf{f}_{tri} = \text{concat}(\mathbf{f}_{XY}, \mathbf{f}_{YZ}, \mathbf{f}_{ZX}) $$
       [S1]

3.  **Density Field Prediction (Geometry Branch):**
    a. Extract reference features $\mathbf{f}_{ref}$ from input images using a pretrained CNN encoder [S1].
    b. Project $\mathbf{f}_{ref}$ to obtain corresponding feature vectors for the sampling point [S1].
    c. Concatenate the projected reference features with the spatial coordinates $\mathbf{x}$ encoded via positional encoding (frequency = 6) [S1].
    d. Process the concatenated vector through the Density MLP to predict volume density $\sigma$ and intermediate features $\mathbf{f}_m$ [S1].

4.  **Color Prediction:**
    a. Combine the triplane features $\mathbf{f}_{tri}$ and density features $\mathbf{f}_m$ using a compact MLP ($\Phi_{base}$) to generate intermediate features $\mathbf{f}_{base}$:
       $$ \mathbf{f}_{base} = \Phi_{base}(\mathbf{f}_{tri}, \mathbf{f}_m) $$
       [S1]
    b. Encode the viewing direction $\mathbf{d} \in \mathbb{R}^3$ on the spherical harmonics basis $\text{SH}(\cdot)$ [S1].
    c. Process $\mathbf{f}_{base}$ and $\text{SH}(\mathbf{d})$ through the Color MLP ($\Phi_{color}$) to predict the point's color $\mathbf{c} \in \mathbb{R}^3$:
       $$ \mathbf{c} = \Phi_{color}(\mathbf{f}_{base}, \text{SH}(\mathbf{d})) $$
       [S1]

5.  **Volume Rendering:**
    Render the pixel color $\hat{C}(r)$ along ray $r$ using differentiable volume rendering [S1]:
    $$ \hat{C}(r) = \sum_{i=1}^{N} T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i $$
    $$ T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right) $$
    where $\mathbf{c}_i$ and $\sigma_i$ are the color and volume density at sample $i$, $\delta_i$ is the distance between adjacent samples, $N$ is the number of sampling points, and $T_i$ is the accumulated transmittance [S1].

6.  **Optimization:**
    Optimize the model parameters (Triplane $P$, MLP weights) using backpropagation [S1].
    *   **Loss Functions:** Photometric loss (predicted vs. ground truth colors), depth loss (from point cloud anchors), and edge-aware smoothness loss [S1].
    *   **Edge-Aware Smoothness:** Process 64 key points and randomly render a $16 \times 16$ patch with stride 4 to compute this loss [S1].
    *   **Training Schedule:** 30,000 total iterations. First 10,000 iterations use depth-guided optimization. The subsequent 20,000 iterations use edge-aware smoothness loss [S1].
    *   **Optimizer:** AdamW with initial learning rate 0.0001 [S1].

## Operating characteristics
*   **Time Complexity:** Training is significantly faster than standard NeRF-based methods. TriDF achieves a 30× speed increase compared to NeRF-based methods [S1]. A fully trained model takes 14 minutes, while an early version (TriDF-10k, 10k iterations) takes 5 minutes on a single consumer GPU (Nvidia GeForce RTX 4090) [S1].
*   **Memory Complexity:** The triplane representation is compact. The triplane memory usage is $3 \times H \times W \times C$ bytes. The density MLP is small (width 512, depth 8) [S1]. Total parameters are low compared to dense voxel grids or large MLPs [S1].
*   **Performance:** On the LEVIRNVS dataset, TriDF improves PSNR by 7.4% and SSIM by 3.4% compared to advanced few-shot methods (including 3DGS-based methods like FSGS and CoR-GS) [S1].
*   **Strengths:**
    *   Fast convergence due to explicit optimization of triplane features [S1].
    *   Effective few-shot synthesis (3 views) without extensive pretraining [S1].
    *   Better extrapolation to empty regions compared to explicit 3DGS methods, avoiding boundary distortions [S1].
*   **Limitations:**
    *   Rendering speed lags behind 3DGS-based methods designed for real-time rendering [S1].
    *   Standard triplane representations suffer from redundancy or inaccurate geometry with sparse inputs if not decoupled from density [S1].
    *   Integrating IBR features directly into the triplane branch causes overfitting because frozen encoder features are constant and triplane features maintain a one-to-one correspondence with reference features [S1].

## Background
TriDF was proposed to address the challenges of few-shot novel view synthesis in remote sensing, where input views are sparse and have low overlap [S1]. Traditional NeRF methods require hundreds of views and are computationally intensive, while existing few-shot methods often rely on large-scale pretraining or complex regularization [S1]. The method was validated on the LEVIRNVS dataset, a remote sensing dataset [S1]. The code is publicly available at https://github.com/kanehub/TriDF [S1].
