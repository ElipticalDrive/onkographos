# NeuRay

Also called: Neural Rays

## Overview
NeuRay is an occlusion-aware image-based rendering method that represents a scene by estimating occlusion probabilities (hitting probabilities) from input views to arbitrary 3D points, enabling efficient novel view synthesis [S1]. Unlike standard radiance field methods that treat volume density as a continuous scalar, NeuRay explicitly models visibility to handle feature inconsistency caused by occlusions, particularly in sparse or 360-degree captures [S1]. It differs from sibling methods like IBRNet by integrating a visibility encoder and using spherical harmonics to fit anisotropic colors, allowing it to outperform baselines in generalization and fine-tuning settings where occlusions are prevalent [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** A set of $N$ input images with known camera poses (intrinsics and extrinsics). For rendering a test view, a subset of $N_w$ neighboring input images (working views) is selected.
*   **Outputs:** A synthesized RGB image for the test view, and optionally depth maps.

**Data Structures**
1.  **Cost Volume:** Constructed using $N_s=3$ neighboring source views. Dimensions are $H/4 \times W/4 \times D$, where $D=64$ is the number of disparity planes [S1].
2.  **Visibility Feature:** A feature map of size $H/4 \times W/4 \times 32$ generated by the Initialization Network and refined by the Visibility Encoder [S1].
3.  **Spherical Harmonics Coefficients:** For each sample point, a vector $\boldsymbol{\theta}_i \in \mathbb{R}^{16}$ representing SH coefficients up to degree 3 [S1].
4.  **Hitting Probability:** A scalar $\hat{h}_i$ representing the probability that a point $p_i$ is visible from the test view, derived from a mixture of logistics distributions [S1].

**Network Architecture**
The model consists of shared encoders and task-specific decoders for coarse and fine stages.
1.  **Image Encoder:** A ResNet with 13 residual blocks, outputting a feature map with 32 channels. Convolution layers use ReLU; batch normalization is replaced by instance normalization [S1].
2.  **Initialization Network:**
    *   Inputs: Image feature ($H/4 \times W/4 \times 64$), Depth regression ($H/4 \times W/4 \times 32$), Cost Volume ($H/4 \times W/4 \times 1$).
    *   Structure: Conv3x3(32) $\rightarrow$ ResBlock(32) $\rightarrow$ Conv1x1(32).
    *   Output: Visibility Feature ($H/4 \times W/4 \times 32$) [S1].
3.  **Visibility Encoder:**
    *   Inputs: Visibility Feature ($H/4 \times W/4 \times 32$), Image feature ($H/4 \times W/4 \times 96$).
    *   Structure: Conv3x3(32) $\rightarrow$ ResBlock(32) $\rightarrow$ Conv1x1(32).
    *   Output: Refined Visibility Feature ($H/4 \times W/4 \times 32$) [S1].
4.  **Decoder F (Distribution):** Contains 5 sub-networks, each with 3 fully-connected layers. Predicts $\mu_1, \mu_2, \sigma_1, \sigma_2$ and mixing weight $w_0$ (where $w_1 = 1 - w_0$). Uses ReLU for hidden layers, SoftPlus/Sigmoid for output [S1].
5.  **Aggregation Networks (Coarse/Fine):**
    *   **Network $\mathcal{M}$ (Feature Aggregation):** Inputs are Visibility features ($N \times K \times 32$), View directions ($N \times K \times 3$), Image features ($N \times K \times 3$).
        *   Process: MLP(1,32,32) on visibility, MLP(3,32,32) on directions, MLP(32,32,1) on image features. Element-wise product. MLP(32,32,32). Element-wise plus. MLP(192,64,32). Transformer. MLP(16,1). Output: Aggregated feature [S1].
    *   **Network $\mathcal{A}$ (Alpha):** Inputs are Mean ($N \times 1 \times 32$) and Var ($N \times 1 \times 32$). MLP(35,16,8,1) followed by Softmax. Output: Alpha value $\alpha_i \in [0,1]$ [S1].
    *   **Network $\mathcal{B}$ (Blending):** Inputs are Mean ($N \times 1 \times 32$) and Var ($N \times 1 \times 32$). MLP(64,32,16) followed by sigmoid. Output: Blending weights ($N \times K \times 1$) [S1].

**Numbered Steps**

1.  **Initialization:**
    *   Construct a cost volume using COLMAP patch-match stereo and $N_s=3$ source views [S1].
    *   Pass image features through the Image Encoder, Initialization Network, and Visibility Encoder to obtain the Refined Visibility Feature [S1].

2.  **Ray Sampling:**
    *   For a test ray $r(\lambda) = o + \lambda d$, sample $K_{t,1}$ points for the coarse stage and $K_{t,2}$ points for the fine stage. Default values are $K_{t,1}=64, K_{t,2}=64$ [S1].
    *   Use the coarse model to estimate hitting probabilities $\hat{h}_i$ for all coarse points.
    *   Perform coarse-to-fine sampling: select fine points based on the distribution defined by the coarse hitting probabilities [S1].

3.  **Visibility and Alpha Computation:**
    *   For each sample point $p_i$, compute the hitting probability $\hat{h}_i$ using the mixture of $N_l=2$ logistics distributions parameterized by the Decoder F [S1].
    *   Compute the alpha value $\alpha_i = \mathcal{A}(\mathbf{f}_i)$, where $\mathbf{f}_i$ is the aggregated feature. The network $\mathcal{A}$ assigns large $\alpha_i$ when features from visible input views are consistent [S1].

4.  **Color Computation (Radiance Field Rendering):**
    *   Compute the color $\mathbf{c}_i$ for point $p_i$ using the color blending network $\mathcal{B}$:
        $$ \mathbf{c}_i = \mathcal{B}(\mathbf{f}_i, \{\mathbf{f}_{i,j}; \mathbf{r}_{i,j} - \mathbf{r}; \mathbf{c}_{i,j}; v_{i,j}\}) $$
        where $\mathbf{r}_{i,j}$ is the view direction from the $j$-th input view to $p_i$, $\mathbf{c}_{i,j}$ is the projected color, and $v_{i,j}$ is the visibility [S1].
    *   Render the final pixel color $\hat{c}$ using alpha compositing weighted by hitting probabilities:
        $$ \hat{c} = \sum_i \mathbf{c}_i \hat{h}_i $$
        (Note: The source describes direct rendering as $\hat{c} = \sum_i \hat{c}_i \hat{h}_i$ [S1], but standard volume rendering composites alpha. The text states "compute output color by $\hat{c} = \sum_i \hat{c}_i \hat{h}_i$" in the context of direct rendering, but for the main radiance field, it blends colors. We follow the explicit formula given for direct rendering and the blending description for the main method).

5.  **Spherical Harmonics Fitting (Direct Rendering / Anisotropic Color):**
    *   To represent anisotropic colors, fit a function $R(\mathbf{r}; \boldsymbol{\theta}_i)$ on the sphere for each point $p_i$ using spherical harmonics.
    *   Solve the linear least squares problem for coefficients $\boldsymbol{\theta}_i$:
        $$ \min_{\boldsymbol{\theta}_i} \sum_j \tilde{h}_{i,j}(z_{i,j}, z_{i,j}+l_i) \|R(\mathbf{r}_{i,j}; \boldsymbol{\theta}_i) - \mathbf{c}_{i,j}\|^2 + \boldsymbol{\theta}_i^\intercal \boldsymbol{\Lambda} \boldsymbol{\theta}_i $$
        where $\tilde{h}_{i,j}$ is the hitting probability, $\boldsymbol{\Lambda}$ is a diagonal regularization matrix with elements $(0, 0.001, 0.005, 0.01)$ for degrees 0 to 3, and $R$ is the SH basis function [S1].
    *   The color is then computed as $\mathbf{c}_i = R(\mathbf{r}; \boldsymbol{\theta}_i)$ [S1].

6.  **Training and Loss:**
    *   **Depth Loss:** $\ell_{depth} = \sum \|\mu_1 - z_{in}\|^2$, where $\mu_1$ is the mean of the first logistics distribution and $z_{in}$ is input depth from the cost volume [S1].
    *   **Color Loss:** The difference between predicted and ground truth colors is weighted by hitting probabilities to prevent occluded rays from interfering [S1].
    *   **Visibility Memorization:** During training, predicted hitting probabilities $h_i$ are memorized. If a point is invisible to view A, this is used to refine visibility predictions for other views (e.g., view D) in subsequent steps [S1].

**Edge Cases and Pitfalls**
*   **Invisible Regions:** NeuRay cannot render regions invisible to all working views, even if visible in other input views, because it is image-based [S1].
*   **Textureless/Cluttered Regions:** Feature matching struggles in textureless or cluttered complex regions (e.g., Ficus), leading to view inconsistency and artifacts [S1].
*   **Generalization Speed:** In generalization settings, predicted visibility is often inaccurate, preventing high-quality rendering with very few sample points. Speeding up rendering requires accurate surface location estimation, which is only reliable in finetuned models [S1].
*   **Direct Rendering Artifacts:** Direct rendering produces meaningful results but artifacts occur on edges [S1].

## Operating characteristics
*   **Time Complexity:** Rendering time is significantly reduced compared to NeRF. On the DTU 'birds' dataset, using 4-8 fine sample points speeds up rendering from 30s to ~3s (10x speedup) [S1].
*   **Memory Complexity:** Uses a cost volume of size $H/4 \times W/4 \times 64$ and feature maps of size $H/4 \times W/4 \times 32$. The image encoder is lighter than IBRNet [S1].
*   **Performance:**
    *   **NeRF Synthetic (Lego):** NeuRay-Ft achieves 30.63 PSNR in ~32 minutes, comparable to NeRF's 30.27 PSNR in ~9.5 hours [S1].
    *   **LLFF (Nw=8):** NeuRay 27.06 PSNR vs IBRNet 26.87 PSNR [S1].
    *   **LLFF (Nw=2):** NeuRay 24.86 PSNR vs IBRNet 21.72 PSNR [S1].
    *   **Generalization (Lego, N=100):** NeuRay 28.41 PSNR vs IBRNet 25.64 PSNR [S1].
*   **Strengths:** Occlusion-aware, handles sparse 360-degree captures better than IBRNet, recovers details more clearly than NeRF with fewer training steps, fast finetuning [S1].
*   **Limitations:** Fails on regions invisible to all working views, struggles with textureless regions, generalization mode requires more samples for high quality [S1].
*   **When to Use:** Novel view synthesis with sparse or 360-degree input views, especially where occlusions are present. Suitable for scenarios requiring fast finetuning [S1].
*   **When Not to Use:** Scenes with large invisible regions relative to working views, or highly textureless environments [S1].

## Background
NeuRay was introduced in the paper "Neural Rays for Occlusion-aware Image-based Rendering" [S1]. It addresses the limitations of existing image-based rendering methods like IBRNet, which suffer from feature inconsistency due to occlusions in sparse captures. By explicitly modeling occlusion probabilities, NeuRay refines scene representation and provides better occlusion inference during finetuning [S1]. It is used on datasets such as LLFF, NeRF synthetic (Lego), and DTU [S1].
