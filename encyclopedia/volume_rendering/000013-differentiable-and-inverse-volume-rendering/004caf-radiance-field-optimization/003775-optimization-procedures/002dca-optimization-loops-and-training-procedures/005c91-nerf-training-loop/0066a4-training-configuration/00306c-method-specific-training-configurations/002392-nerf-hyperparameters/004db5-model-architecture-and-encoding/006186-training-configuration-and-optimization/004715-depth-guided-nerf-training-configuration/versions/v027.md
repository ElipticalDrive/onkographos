# Depth-Guided NeRF Training Configuration

Also called: Depth-Guided NeRF Training

## Overview
This configuration defines the hyperparameters, architectural modifications, and optimization settings required to train a Neural Radiance Field (NeRF) model using depth priors. It addresses the problem of improving geometric accuracy and convergence stability in NeRF reconstruction by integrating depth supervision. It differs from standard NeRF training [Model Architecture and Encoding](13550-model-architecture-and-encoding.md) by introducing specific dropout regularization, a depth loss term, and distinct learning rates for depth-related parameters.

## How it works
The method modifies the standard NeRF training loop by adding architectural regularization and a composite loss function that includes depth consistency.

**Inputs and Outputs:**
*   **Inputs:** Camera poses, images, and ground-truth depth maps (where available).
*   **Outputs:** Trained NeRF model parameters (MLP weights, positional encoding tables).

**Data Structures:**
The model architecture builds upon the original NeRF [S1]. The core data structure is the Multi-Layer Perceptron (MLP) that maps positional encodings to density and color.
*   **Architecture Modification:** Dropout layers with probability $p=0.1$ are added after each of the first eight fully connected ReLU-activated layers that encode the positional encoding [S1].
*   **Depth Scale:** A specific parameter for depth scaling is maintained, optimized with a distinct learning rate [S1].

**Loss Function:**
The total loss combines the standard photometric rendering loss with a depth loss term. The depth loss is weighted by $\lambda$. An uncertainty weight $\gamma$ is also applied [S1].
$$ \mathcal{L}_{total} = \mathcal{L}_{rgb} + \lambda \mathcal{L}_{depth} $$
Where $\mathcal{L}_{depth}$ measures the discrepancy between predicted and ground-truth depth. The uncertainty threshold $\tau$ for evaluating depth map validity is computed as:
$$ \tau = (\text{max\_depth} - \text{min\_depth}) \cdot 0.0001 $$
For the ScanNet dataset, $\text{max\_depth} = 10$ and $\text{min\_depth} = 0.001$ [S1].

**Evaluation Metrics:**
Depth accuracy is evaluated using the following metrics over $K$ valid pixels:
$$ \text{RMSE}(d, \hat{d}) = \sqrt{\frac{1}{K} \sum_{k=1}^{K} (d_k - \hat{d}_k)^2} $$
$$ \text{RMSE}_{\log}(d, \hat{d}) = \sqrt{\frac{1}{K} \sum_{k=1}^{K} (\log d_k - \log \hat{d}_k)^2} $$
$$ \text{AbsRel}(d, \hat{d}) = \frac{1}{K} \sum_{k=1}^{K} \frac{|d_k - \hat{d}_k|}{d_k} $$
$$ \text{SqRel}(d, \hat{d}) = \frac{1}{K} \sum_{k=1}^{K} \frac{(d_k - \hat{d}_k)^2}{d_k} $$
[S1]

**Training Steps:**
1.  **Initialize** the NeRF model with positional encoding.
2.  **Apply Dropout:** Insert dropout layers ($p=0.1$) after the first 8 FC layers of the encoding MLP [S1].
3.  **Compute Rendering Loss:** Render images and compute photometric loss against ground truth [S1].
4.  **Compute Depth Loss:** Render depth maps and compute loss against ground truth depth [S1].
5.  **Aggregate Loss:** Combine losses using $\lambda$ and $\gamma$ [S1].
6.  **Update Weights:** Use Adam optimizer to update model weights [S1].
7.  **Update Depth Scale:** Use a separate learning rate for the depth scale parameter [S1].
8.  **Schedule:** Reduce learning rate after 80% of total steps [S1].

**Parameters:**
*   **Optimizer:** Adam [S1].
*   **Initial Learning Rate:** $5 \times 10^{-4}$ [S1].
*   **Learning Rate Schedule:** Reduce to $5 \times 10^{-5}$ after 80% of steps [S1].
*   **Weight Decay:** $1 \times 10^{-6}$ [S1].
*   **Total Training Steps:** 500,000 [S1].
*   **Depth Loss Weight ($\lambda$):** $0.007$ for all scenes except scene 710, where it is $0.02$ [S1].
*   **Uncertainty Weight ($\gamma$):** $1$ [S1].
*   **Depth Scale Learning Rate:** $1 \times 10^{-7}$ [S1].

**Edge Cases and Pitfalls:**
*   **Scene 710:** Requires a higher depth loss weight ($\lambda = 0.02$) compared to other scenes ($\lambda = 0.007$) [S1].
*   **Depth Threshold:** The validity of depth pixels is determined by $\tau$. Incorrect thresholding may lead to noisy gradients from invalid depth data [S1].
*   **Overfitting:** The dropout layers are specifically designed to prevent overfitting in the encoding stage [S1].

## Subtopics

### DS-NeRF Depth Loss Integration
Integrates the depth loss implementation from the official DS-NeRF code base into the training pipeline. This variant requires re-training on LLFF train/test splits using released configuration files, as the original publication results for LLFF used a different split and DTU results could not be reproduced due to missing configuration files in the official code base [S2].

## Operating characteristics
*   **Time Complexity:** Training requires 500,000 steps [S1]. The addition of depth loss computation increases per-step cost slightly compared to RGB-only training.
*   **Memory Complexity:** The dropout layers do not significantly increase memory usage during training but add regularization overhead [S1].
*   **Strengths:** Improves geometric accuracy through depth supervision; dropout prevents overfitting in the encoding MLP [S1].
*   **Limitations:** Requires ground-truth depth maps for supervision; specific hyperparameters (like $\lambda$) may need tuning per scene (e.g., scene 710) [S1].
*   **When to use:** When high-fidelity geometry is required and depth data is available.
*   **When not to use:** When depth data is unavailable or when computational resources are extremely limited due to the extended training steps [S1].

## Background
This configuration originates from the work on Depth-Guided NeRF training via Earth Mover’s Distance [S1]. It builds on the original NeRF architecture [S1] and incorporates techniques from DS-NeRF for depth loss integration [S2]. The method is used in datasets such as ScanNet and LLFF [S1, S2].
