# StyleGAN2 Training Configuration
Also called: StyleGAN2 Training Setup

## Overview
This configuration defines the training recipe for 3D-aware image synthesis models (such as VoxGRAF) that utilize the StyleGAN2 architecture as a backbone for the generator and discriminator. It solves the problem of stable training for high-resolution generative models by combining equalized learning rates, minibatch statistics, and specific regularization techniques. It sets itself apart from standard NeRF training loops by employing a GAN-based adversarial objective rather than pure photometric reconstruction, and differs from the original StyleGAN2 paper by disabling path regularization and style-mixing to reduce computational cost and memory usage [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Real image batches, latent vectors $z$, and conditional inputs (if applicable).
*   **Output:** Generated images, discriminator scores, and updated generator/discriminator weights.

**Data Structures:**
*   **Generator:** Style-based generator with equalized learning rates.
*   **Discriminator:** StyleGAN2 discriminator with a minibatch standard deviation layer at the end and skip connections for progressive growing.
*   **EMA State:** Exponential moving average of generator weights.

**Numbered Steps:**
1.  **Equalized Learning Rates:** Apply equalized learning rates to all trainable parameters in the generator and discriminator. This ensures that layers with fewer parameters do not receive disproportionately large updates [S1].
2.  **Minibatch Standard Deviation:** Append a minibatch standard deviation layer to the end of the discriminator. This layer computes the standard deviation of features across the minibatch dimension and concatenates it as an additional feature channel, helping the discriminator detect mode collapse [S1].
3.  **Exponential Moving Average (EMA):** Maintain an EMA of the generator weights. Update the EMA weights after each optimizer step using a decay rate (typically close to 1, e.g., 0.9999, though the exact rate is not specified in the sources) [S1].
4.  **Mixed Precision:** Perform forward and backward passes for both the generator and discriminator using mixed-precision arithmetic (FP16/FP32) to accelerate training and reduce memory usage [S1].
5.  **Discriminator Update:**
    a. Compute discriminator loss on real images and generated images.
    b. **R1 Regularization:** Compute the R1 gradient penalty on real images. Apply this regularization term once every 4 minibatches. The regularization strength is $\gamma = 1$ [S1].
    c. Update discriminator weights.
6.  **Generator Update:**
    a. Compute generator loss based on discriminator feedback.
    b. Update generator weights.
    c. Update EMA weights.
7.  **Progressive Growing (Conditional Variant):** If using the conditional discriminator variant, implement skip connections. For each layer in the discriminator, add a downsampled version of the input image to the layer's input to facilitate smooth resolution scaling [S1].

**Parameters:**
*   **R1 Regularization Strength ($\gamma$):** 1 [S1].
*   **R1 Frequency:** Once every 4 minibatches [S1].
*   **Truncation ($\psi$):** 0.7 (used during inference/evaluation for qualitative results) [S1].
*   **Learning Rate Decay ($\eta_{fg}$):** 0.4 for AFHQ and FFHQ datasets; 0.1 for Carla dataset [S1].
*   **Background Learning Rate ($\eta_{bg}$):** 0.1 for all datasets [S1].
*   **Feature/Background Consistency Loss ($\lambda_{fcvg}$):** 0.1 for all datasets [S1].

**Edge Cases and Pitfalls:**
*   **Small Datasets:** For small datasets like AFHQ, do not train from scratch. Instead, finetune a generator pretrained on FFHQ. Use initial resolution $R_I = 128$ and generator resolution $R_G = 32$ before pruning the representation [S1].
*   **Computational Cost:** Path regularization and style-mixing are explicitly disabled to reduce memory usage and computational overhead [S1].

    # Apply equalized learning rates internally
    d_real_scores = discriminator(real_images)
    
    # 3. Discriminator Forward Pass (Fake)
    d_fake_scores = discriminator(generated_images.detach())
    
    # 4. Minibatch Std Dev (Discriminator)
    # Added at the end of discriminator architecture
    # d_real_scores = concat(d_real_scores, minibatch_std_dev(real_features))
    
    # 5. Compute Losses
    # Standard GAN losses (e.g., WGAN-GP or Hinge)
    loss_d_real = compute_discriminator_loss(d_real_scores, real_labels)
    loss_d_fake = compute_discriminator_loss(d_fake_scores, fake_labels)
    loss_d = loss_d_real + loss_d_fake
    
    # 6. R1 Regularization (Every 4 minibatches)
    if step_count % 4 == 0:
        # Compute gradient penalty on real images
        # R1 = gamma * ||grad(D(real))||^2
        r1_penalty = compute_r1_penalty(discriminator, real_images, gamma=1.0)
        loss_d += r1_penalty
        
    # 7. Update Discriminator
    optimizer_d.zero_grad()
    loss_d.backward()
    optimizer_d.step()
    
    # 8. Generator Loss
    # Re-run discriminator on generated images (without detach)
    d_fake_scores_gen = discriminator(generated_images)
    loss_g = compute_generator_loss(d_fake_scores_gen)
    
    # 9. Update Generator
    optimizer_g.zero_grad()
    loss_g.backward()
    optimizer_g.step()
    
    # 10. Update EMA
    update_ema(ema_generator, generator, decay=0.9999) # Decay rate not specified in sources [G]
    
    return loss_d, loss_g

## Subtopics

### Conditional Discriminator with Skip Connections for Progressive Growing
A variant of the discriminator used to facilitate progressive growing in 3D-aware synthesis. It differs from the standard discriminator by incorporating skip connections that add a downsampled version of the input image to the input of each layer. This architecture allows the model to smoothly transition between resolutions during training. It is chosen when using conditional inputs and progressive growing strategies to stabilize training at high resolutions [S1].

## Operating characteristics
*   **Time Complexity:** Training is accelerated by mixed-precision arithmetic. R1 regularization is applied sparsely (every 4 minibatches) to reduce the computational cost of gradient computation on real images [S1].
*   **Memory Complexity:** Memory usage is reduced by disabling path regularization and style-mixing, which are present in the original StyleGAN2 implementation [S1].
*   **Performance:** The configuration is designed for efficient rendering using custom CUDA kernels and sparse voxel grids (as seen in VoxGRAF), allowing for equidistant sampling and early ray termination [S1].
*   **Strengths:** Stable training for high-resolution 3D-aware generation; reduced memory footprint compared to full StyleGAN2; effective regularization via R1.
*   **Limitations:** Requires careful handling of small datasets (finetuning required); relies on specific hyperparameters for different datasets (e.g., $\eta_{fg}$ varies) [S1].
*   **When to use:** When training 3D-aware generative models that require high fidelity and stable convergence, particularly when computational resources are constrained.
*   **When not to use:** When style-mixing or path regularization is critical for the specific artistic style or diversity requirements of the output.

## Background
This configuration is derived from the training setup used in VoxGRAF, a method for fast 3D-aware image synthesis with sparse voxel grids. It builds upon the StyleGAN2 architecture [S1]. The approach adapts the proven stability techniques of StyleGAN2 (equalized learning rates, minibatch std dev, EMA) to the context of 3D neural rendering, while optimizing for speed and memory by removing computationally expensive features like path regularization [S1].
