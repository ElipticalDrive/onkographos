# Single-Image Textual Inversion

Also called: auto-prompt generation

## Overview
Single-Image Textual Inversion is a technique to generate a custom prompt for a diffusion model by optimizing an embedding token $\langle e \rangle$ from a single input image prior to 3D reconstruction [S1]. It solves the problem of ill-posed single-view reconstruction by conditioning the diffusion model on a prompt that specifically describes the input object, enabling the generation of plausible novel views [S1]. Unlike generic text-to-image approaches, this method optimizes a learnable token embedding to match the input image, which greatly alleviates artifacts such as "floaters" (disconnected geometry near the camera) that occur without image-specific prompts [S1].

## How it works
**Inputs and Outputs:**
- Input: A single input image $I_0$ corresponding to an unknown camera pose $\pi_0$.
- Output: An optimized embedding vector $e$ (or token $\langle e \rangle$) that serves as a custom prompt for the diffusion model.

**Data Structures:**
- The embedding $e$ is a learnable vector of the same dimension as the text encoder's token embeddings (e.g., 768 for CLIP/ViT-B/16).
- The prompt template is a fixed string: "An image of a $\langle e \rangle$" [S1].

**Initialization:**
The embedding $e$ can be initialized in three ways [S1]:
1. **Random:** Initialize $e$ with random noise.
2. **Manual:** Select a token from the vocabulary that semantically matches the object.
3. **Automated:** Use CLIP to find the most similar noun token in the vocabulary (see "Automated Token Initialization" below).

**Algorithm Steps:**
1. **Prompt Configuration:** Configure the diffusion model's text prompt as "An image of a $\langle e \rangle$" [S1].
2. **Augmentation Setup:** Apply heavy image augmentations to the input image $I_0$ to prevent overfitting to the single view [S1].
3. **Optimization Loop:**
   - For $t = 1$ to $T_{steps}$ (typically 3000):
     a. Apply random augmentations to $I_0$ to produce $I_{aug}$ [S1].
     b. Compute the image embedding $v_{img}$ of $I_{aug}$ using the CLIP image encoder [S1].
     c. Compute the text embedding $v_{text}$ of the prompt "An image of a $\langle e \rangle$" using the CLIP text encoder [S1].
     d. Compute the loss $\mathcal{L}$ as the distance between $v_{img}$ and $v_{text}$ (typically cosine similarity or L2 distance in embedding space) [S1].
     e. Update $e$ using the Adam optimizer [S1].
4. **Result:** The optimized $e$ is used to condition the diffusion model during the subsequent radiance field optimization [S1].

**Parameters:**
- Optimization steps ($T_{steps}$): 3000 [S1].
- Optimizer: Adam [S1].
- Image size: 512px [S1].
- Batch size: 16 [S1].
- Learning rate: $5 \cdot 10^{-4}$ [S1].
- Weight decay: $1 \cdot 10^{-2}$ [S1].

**Edge Cases and Pitfalls:**
- **Floaters:** Without image-specific prompts, disconnected parts of the scene (floaters) appear close to the camera in the majority of reconstructions [S1]. Using image-specific prompts greatly alleviates this issue [S1].
- **Janus Problem:** Reconstructions may have two or more faces because the loss function tries to make the render of every view look like the input image [S1].
- **Overfitting:** Optimizing with a single image leads to severe overfitting if not for the heavy augmentations and the diffusion prior [S1].

## Subtopics

### Automated Token Initialization for Textual Inversion
This variant automates the initialization of the embedding token $\langle e \rangle$ using CLIP and WordNet [S1]. It filters the CLIP text tokenizer tokens to keep only nouns (based on the WordNet database) to reconstruct objects rather than styles [S1]. It generates caption embeddings for each noun token using the template "An image of a $\langle e \rangle$" [S1]. It computes the image embedding for the input image and selects the noun token with the highest similarity between its caption embedding and the input image embedding as the initialization for the textual inversion procedure [S1].

## Operating characteristics
- **Time Complexity:** The optimization runs for 3000 steps [S1]. Each step involves forward passes through the CLIP image and text encoders.
- **Memory Complexity:** Requires memory for the CLIP model and the batch of augmented images (batch size 16) [S1].
- **Performance:** The method uses an image size of 512px and a batch size of 16 [S1].
- **Strengths:** It generates a specific prompt embedding that conditions the diffusion model to "dream up" plausible novel views of the specific input object, solving the ill-posed nature of single-view reconstruction . It greatly reduces floaters compared to generic prompts [S1].
- **Limitations:** It is not necessary in text-to-image-to-3D settings where images sampled from the 2D diffusion model are already well-aligned with their prompts [S1]. It requires careful tuning of augmentations to prevent overfitting [S1].
- **When to use:** When reconstructing a 3D model from a single input image and needing to condition a diffusion prior on the specific object content .
- **When not to use:** When multiple views are available, or when using a text-to-image-to-3D pipeline where the initial image is already generated from a text prompt [S1].

## Background
Single-Image Textual Inversion is a variant of Textual Inversion [10] introduced in the RealFusion paper [S1]. It was developed to address the limitations of DreamFusion, which relies on generic text prompts and suffers from mode collapse when high guidance is applied . The method was proposed by [Authors of RealFusion] in 2023 [S1]. It is used in the RealFusion pipeline to substitute for missing multi-view data [S1].
