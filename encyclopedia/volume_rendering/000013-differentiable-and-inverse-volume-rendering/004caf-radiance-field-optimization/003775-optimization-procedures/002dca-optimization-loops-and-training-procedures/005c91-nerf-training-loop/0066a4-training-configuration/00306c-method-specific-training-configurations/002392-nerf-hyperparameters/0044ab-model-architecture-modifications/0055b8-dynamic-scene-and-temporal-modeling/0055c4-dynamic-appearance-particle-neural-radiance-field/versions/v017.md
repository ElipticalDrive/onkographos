# Dynamic Appearance Particle Neural Radiance Field

Also called: Dynamic Appearance Particle NeRF, Lagrangian dynamic model in NeRF

## Overview
Dynamic Appearance Particle Neural Radiance Field is a method for reconstructing 4D radiance fields from monocular video data by modeling scene dynamics using a particle motion network and appearance particles [S1]. It solves the ambiguity between camera and object motion by superimposing a static grid-based field with a dynamic particle-based field, allowing for efficient linear interpolation querying rather than nearest-neighbor searches [S1]. Unlike ParticleNeRF, which encodes the entire scene with particles and requires multi-view data, this method applies particles only to dynamic elements and supports single-view input [S1].

## How it works
The method constructs a dynamic radiance field $V(\mathbf{x}, t)$ that maps 3D spatial coordinates $\mathbf{x}$ and time $t$ to volume density $\sigma$ and color $\mathbf{c}$. The rendering equation follows the standard volume rendering integral [S1]:

$$ C(\mathbf{r}, t) = \int_{s_n}^{s_f} T(s, t) \sigma(\mathbf{r}(s), t) c(\mathbf{r}(s), \mathbf{d}, t) ds $$

where $\mathbf{r}(s) = \mathbf{o} + s\mathbf{d}$ is a ray from camera center $\mathbf{o}$ with direction $\mathbf{d}$, $s_n$ and $s_f$ are near and far bounds, and $T(s, t) = \exp \left( -\int_{s_n}^{s} \sigma(\mathbf{r}(s'), t) ds' \right)$ is the accumulated transmittance [S1].

### Inputs and Outputs
- **Inputs**: Monocular video data (sequence of images with known camera poses and timestamps).
- **Outputs**: A trained dynamic radiance field model capable of rendering novel views at arbitrary times $t$.

### Data Structures
The field is composed of two components superimposed based on a weight function:

1.  **Static Field ($V_s$)**: A time-independent grid-based model (e.g., hash grid or dense voxel grid) storing features for static scene elements [S1].
2.  **Dynamic Field ($V_{td}$)**: A particle-based representation. The field is formulated as a convolution with a Dirac function to integrate over finite volumes [S1]:
    $$ V_{td}(\mathbf{x}) = (V_{td} * \delta)(\mathbf{x}) = \int V_{td}(\mathbf{x}') \delta(\mathbf{x} - \mathbf{x}') d\nu(\mathbf{x}') $$
    where $\delta(\cdot)$ is the Dirac delta function and $\nu(\cdot)$ is the volume integration variable [S1].
3.  **Particle Motion Network**: A neural network (denoted as $NN_{motion}$ in sources) that predicts the motion/position of particles over time [S1].
4.  **Appearance Network**: A neural network (denoted as $MLP_c$ in sources) that maps particle features to color/radiance [S1].
5.  **Weight Function ($w_t(\mathbf{x})$)**: A binary or soft mask indicating the effectiveness of the dynamic field at location $\mathbf{x}$ and time $t$. It takes value 1 if the dynamic field is effective and 0 otherwise [S1].

### Superposition Formula
The total feature field $V(\mathbf{x}, t)$ is computed as [S1]:

$$ V(\mathbf{x}, t) = (1 - w_t(\mathbf{x})) V_s(\mathbf{x}) + w_t(\mathbf{x}) V_{td}(\mathbf{x}) $$

Notation Convention: Time $t$ is denoted in subscripts on the right-hand side (e.g., $V_{td}$) to clarify that the dynamic component consists of an ensemble of particles, where the time argument is fixed for the instantaneous status construction [S1].

### Kernel Approximation
To enable efficient querying and quantization, the Dirac function $\delta$ is replaced by a kernel $W$ with finite support [S1]:
- $W(\mathbf{x}) = 0$ when $\|\mathbf{x}\|$ exceeds a small radius.
- $\int W(\mathbf{x}) d\nu(\mathbf{x}) = 1$ [S1].

### Algorithm Steps
1.  **Initialize**:
    - Initialize static grid $V_s$ with features from the first frame or a static background model [G].
    - Initialize particle positions $\mathbf{p}_i$ and features $\mathbf{f}_i$ for dynamic elements [G].
    - Initialize Particle Motion Network $NN_{motion}$ and Appearance Network $MLP_c$ [S1].
    - Initialize weight function $w_t(\mathbf{x})$ (e.g., based on motion magnitude or learned mask) [S1].

2.  **For each training step**:
    a. **Sample Rays**: Cast rays $\mathbf{r}$ from camera poses at various times $t$ present in the training data [S1].
    b. **Query Static Field**: For each sample point $\mathbf{x}$ on the ray, retrieve features from $V_s(\mathbf{x})$ using trilinear or hash interpolation [S1].
    c. **Query Dynamic Field**:
        i. Determine particle positions $\mathbf{p}_i(t)$ at time $t$ using $NN_{motion}$ [S1].
        ii. Compute the contribution of particles to $V_{td}(\mathbf{x})$ using the kernel $W$ centered at $\mathbf{p}_i(t)$ [S1].
        iii. Apply appearance network $MLP_c$ to particle features to get color/radiance contributions [S1].
    d. **Superpose**: Combine static and dynamic features using the weight $w_t(\mathbf{x})$ [S1]:
       $$ V(\mathbf{x}, t) = (1 - w_t(\mathbf{x})) V_s(\mathbf{x}) + w_t(\mathbf{x}) V_{td}(\mathbf{x}) $$
    e. **Render**: Compute density $\sigma$ and color $\mathbf{c}$ from $V(\mathbf{x}, t)$ and integrate along the ray to produce pixel color $C(\mathbf{r}, t)$ [S1].
    f. **Loss**: Compare rendered color with ground truth image color and backpropagate [G].
    g. **Update**: Update parameters of $V_s$, $NN_{motion}$, $MLP_c$, and $w_t$ [G].

### Parameters
- **Weight $w_t(\mathbf{x})$**: Takes value 1 if the dynamic field is effective at location $\mathbf{x}$ and time $t$, and 0 otherwise. The support of the dynamic field is implied by the particle representation [S1].
- **Kernel Radius**: The small radius for kernel $W$ where $W(\mathbf{x}) \neq 0$. Not given in the sources.

### Edge Cases and Pitfalls
- **Static vs. Dynamic Boundary**: The weight $w_t(\mathbf{x})$ must accurately distinguish between static and dynamic regions to avoid artifacts at boundaries. If $w_t$ is not well-defined, static and dynamic features may interfere [S1].
- **Particle Density**: If particles are too sparse, the dynamic field may not capture fine details. If too dense, querying becomes expensive [G].
- **Monocular Ambiguity**: With only one camera view per time frame, disambiguating camera motion from object motion is challenging. The particle motion network must be regularized to prevent unrealistic motions [S1].

## Operating characteristics
- **Time Complexity**: Querying the static field is $O(1)$ with hash grids or $O(\log N)$ with octrees. Querying the dynamic field depends on the number of particles $N_p$ and the kernel support. With a finite kernel, only nearby particles contribute, making it $O(k)$ where $k$ is the number of particles in the kernel radius [S1].
- **Memory Complexity**: Proportional to the size of the static grid plus the number of particles and their features [S1].
- **Performance**: Designed for efficiency by using linear interpolation for the grid-based static field and avoiding radius nearest neighbor searching for all points, which was required in ParticleNeRF [S1].
- **Strengths**: Handles monocular video data (single camera view per frame); separates static and dynamic elements; efficient querying via grid interpolation [S1].
- **Limitations**: Requires a particle motion network to be learned; may struggle with highly complex, non-rigid dynamics if particle representation is insufficient [S1].
- **When to use**: When reconstructing dynamic scenes from monocular video is required, and computational efficiency is important [S1].
- **When not to use**: When multi-view data is available and a simpler static NeRF or multi-view dynamic method is sufficient; when the scene is entirely static [S1].

## Background
The method was introduced in "Dynamic Appearance Particle Neural Radiance Field" [S1]. It builds on the concept of Lagrangian dynamic models in NeRF [S1]. It differs from ParticleNeRF [S1], which encodes the entire scene with particles and uses radius nearest neighbor searching, requiring 20 camera views per time frame [S1]. The proposed technique is not tightly coupled to a specific architecture and can be integrated into alternative frameworks such as InstantNGP [S1].
