# Frequency-Modulated Position Encoding

Also called: FM-NeRF Encoding, Frequency-Modulated Point Cloud Rendering with Easy Editing

## Overview
Frequency-Modulated Position Encoding is a coordinate encoding scheme used within a point-based radiance field optimization framework to map 3D spatial coordinates and viewing directions to high-dimensional feature vectors. It solves the problem of representing high-frequency geometric and appearance details in sparse point clouds by applying sine and cosine basis functions with exponentially spaced frequencies. It distinguishes itself from standard NeRF positional encoding by narrowing the encoding interval and using specific frequency bands (powers of 2 and 2^0.5) tailored for point cloud rasterization, enabling fast convergence and easy editing of the rendered scene.

## How it works

### Inputs and Outputs
*   **Inputs:**
    *   Spatial coordinate $\mathbf{p} \in \mathbb{R}^3$ (or $\mathbb{R}^2$ for 2D projections).
    *   Viewing direction $\mathbf{d} \in S^2$.
    *   Number of frequency bands $L$.
*   **Outputs:**
    *   Encoded feature vector $\gamma(\mathbf{p})$ or $\gamma(\mathbf{d})$ with dimension $2L$.

### Data Structures
The encoding does not use a lookup table or hash grid. It computes the features on-the-fly using trigonometric functions. The output is a concatenated vector of sine and cosine values.

### Parameters
*   $L$: Number of frequency bands.
    *   For spatial coordinates: $L = 10$ [S1].
    *   For view directions: $L = 2$ [S1].
*   $\lambda_{\text{sparse}}$: Weight for sparse regularization loss. Set to $5 \times 10^{-4}$ [S1].
*   Learning rate for MLP weights: $5 \times 10^{-4}$ [S1].
*   Learning rate for opacity parameters $\alpha$: $0.01$ [S1] [G].

### Formulas
The frequency-modulated position encoding $\gamma(\mathbf{p})$ is defined as [S1]:

$$
\gamma (\mathbf {p}) = \left (\sin (2^0 \pi \mathbf {p}), \cos (2^0 \pi \mathbf {p}), \sin (2^{0.5} \pi \mathbf {p}), \cos (2^{0.5} \pi \mathbf {p}), \dots, \sin (2^{L-1} \pi \mathbf {p}), \cos (2^{L-1} \pi \mathbf {p})\right )
$$

Where:
*   $\mathbf{p}$ is the input coordinate or direction.
*   $L$ is the number of frequency bands.
*   The frequencies are powers of $2$ for the first few bands and then follow a specific progression. Note that the source explicitly lists $2^0, 2^{0.5}, \dots, 2^{L-1}$. This implies the exponent increases by $0.5$ for each subsequent band pair, or potentially the notation $2^{L-1}$ in the last term refers to the index $k$ in $2^{k/2}$? Let's look closely at the source text: $\sin (2^0 \pi \mathbf {p}), \cos (2^0 \pi \mathbf {p}), \sin (2^{0.5} \pi \mathbf {p}), \cos (2^{0.5} \pi \mathbf {p}), \dots, \sin (2^{L-1} \pi \mathbf {p}), \cos (2^{L-1} \pi \mathbf {p})$. The ellipsis suggests the exponent increments. The first two terms have exponent 0. The next two have exponent 0.5. The last terms have exponent $L-1$. This is an arithmetic progression of exponents with step 0.5. So the $k$-th pair (0-indexed) has frequency $2^{k/2}$.

The training loss function combines RGB reconstruction and sparse regularization [S1]:

$$
\mathcal{L} = \mathcal{L}_{\text{RGB}} + \lambda_{\text{sparse}} \mathcal{L}_{\text{sparse}}
$$

Where:
*   $\mathcal{L}_{\text{RGB}} = ||\hat{C} - C_{gt}||_2^2$ [S1].
*   $\mathcal{L}_{\text{sparse}} = \frac{1}{N} \sum_{i=1}^N [\log(\alpha_i) + \log(1-\alpha_i)]$ [S1].
*   $N$ is the number of points.
*   $\alpha_i$ is the opacity of point $i$.
*   For scenes without background, an additional transparency loss (L2 distance of predicted vs ground truth transparency) is added [S1].

### Pseudocode

```python
import math
import numpy as np

def frequency_modulated_encoding(p, L):
    """
    Computes the frequency-modulated position encoding for input p.
    
    Args:
        p: numpy array of shape (D,) representing the coordinate/direction.
           D is typically 3 for spatial coordinates and 3 for view directions.
        L: int, number of frequency bands.
        
    Returns:
        numpy array of shape (2 * L * D,) containing the encoded features.
    """
    # Initialize output array
    # Each coordinate component gets 2 * L values (sin/cos for each band)
    # Total dimension is 2 * L * p.shape[0]
    encoded = np.zeros(2 * L * p.shape[0])
    
    for i in range(p.shape[0]):
        coord = p[i]
        for k in range(L):
            # The exponent for the k-th band (0-indexed) is k/2
            # Source: 2^0, 2^0.5, ..., 2^(L-1)
            # This implies the exponent is k/2.
            # Let's verify: k=0 -> 2^0. k=1 -> 2^0.5. Last k=L-1 -> 2^(L-1).
            # Yes, exponent = k/2.
            exponent = k / 2.0
            freq = 2.0 ** exponent
            
            # Compute sin and cos
            # Note: The source formula has pi inside the trig function
            sin_val = math.sin(math.pi * freq * coord)
            cos_val = math.cos(math.pi * freq * coord)
            
            # Store in output array
            # Order: sin(2^0), cos(2^0), sin(2^0.5), cos(2^0.5), ...
            # For each coordinate component, we interleave sin/cos of all bands?
            # Or all sins then all coses?
            # Source: (sin(2^0 p), cos(2^0 p), sin(2^0.5 p), cos(2^0.5 p), ...)
            # This suggests the order is: for band 0: sin, cos; for band 1: sin, cos; ...
            # So for a single coordinate, the values are interleaved by band.
            # For multiple coordinates, it's likely concatenated per coordinate or per band.
            # Standard NeRF concatenates per coordinate. Let's assume per coordinate.
            # So for coord i, we have 2*L values.
            
            # Index calculation:
            # For coord i, band k:
            # sin index: i * 2 * L + k * 2
            # cos index: i * 2 * L + k * 2 + 1
            
            encoded[i * 2 * L + k * 2] = sin_val
            encoded[i * 2 * L + k * 2 + 1] = cos_val
            
    return encoded

def compute_sparse_loss(opacities):
    """
    Computes the sparse regularization loss.
    
    Args:
        opacities: numpy array of shape (N,) containing alpha values for N points.
        
    Returns:
        float, the mean sparse loss.
    """
    # L_sparse = 1/N * sum(log(alpha_i) + log(1 - alpha_i))
    # Add small epsilon to avoid log(0)
    epsilon = 1e-7
    alpha = np.clip(opacities, epsilon, 1 - epsilon)
    
    loss_per_point = np.log(alpha) + np.log(1 - alpha)
    return np.mean(loss_per_point)

def compute_rgb_loss(predicted_color, ground_truth_color):
    """
    Computes the L2 reconstruction loss.
    
    Args:
        predicted_color: numpy array of shape (H, W, 3) or (N, 3).
        ground_truth_color: numpy array of same shape.
        
    Returns:
        float, the L2 loss.
    """
    return np.mean((predicted_color - ground_truth_color) ** 2)
```

### Edge Cases and Pitfalls
*   **Bleeding Problem:** If the rasterization radius (used to expand points to disks) is too small, points from occluded surfaces and the background can be seen through the front surface. This is a pitfall of the rendering pipeline, not the encoding itself, but the encoding's ability to represent high frequencies helps mitigate aliasing if the radius is chosen correctly [S1].
*   **Edge Expansion:** If the rasterization radius is too large, it leads to inaccurate depth estimation and object edges expand. The radius should be as small as possible while covering gaps between points [S1].
*   **Low Opacity Points:** Points with low opacity should be removed when training converges to clean up the point cloud [S1].
*   **Point Cloud Sparsity:** The method relies on point cloud completion and denoising loops (4-20 loops) to handle sparsity. The encoding itself does not handle sparsity; the rasterization and preprocessing do [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Encoding:** The encoding is computed on-the-fly. The complexity is $O(L \cdot D)$ per point, where $D$ is the dimension of the input (3 for 3D). This is very fast and memory-efficient compared to hash grids or large lookup tables.
*   **Training Time:** The method requires approximately 10 minutes for realistic rendering and about 10 hours to almost converge. One epoch consumes ~12.8 seconds on the NeRF-Synthetic dataset [S1].
*   **Memory:** The MLP (AFNet) has 5 layers with input dimension 120, hidden dimensions 256, 256, 256, 128, and output dimension 11. This is a relatively small network [S1].

### Measured Performance
*   On NeRF-Synthetic and Tanks and Temples datasets, the method achieves higher PSNR/SSIM compared to NeRF, CCNeRF, NPBG, NPBG++, and Huang et al. [S1].
*   On ScanNet and DTU datasets, it achieves comparable or better results [S1].

### Strengths and Limitations
*   **Strengths:**
    *   Fast convergence (10 minutes for realistic results) [S1].
    *   Easy editing of the scene via point cloud masking [S1].
    *   High quality on synthetic and real-world datasets [S1].
*   **Limitations:**
    *   Relies on initial point clouds from MVSNet or similar methods, which may be noisy or sparse [S1].
    *   Requires careful tuning of rasterization radius to avoid bleeding or edge expansion [S1].
    *   The encoding interval is narrowed compared to standard NeRF, which may limit the range of frequencies it can represent for very large scenes [S1].

### When to Use
*   Use this method when you have a sparse point cloud (e.g., from MVSNet) and want to render high-quality images with fast training times.
*   Use it when editing the scene (e.g., object removal/composition) is a requirement.
*   Do not use it if you have a dense voxel grid or if you need to represent extremely large frequency ranges without normalization.

## Background

### Origin
The method was introduced in the paper "Frequency-Modulated Point Cloud Rendering with Easy Editing" [S1]. It builds on the positional encoding concept from NeRF [S1] but adapts it for point-based rendering.

### History and Development
The method is part of the evolution of point-based neural rendering, following works like NPBG and NPBG++. It addresses the limitations of point-based methods in handling high-frequency details and editing by introducing frequency-modulated encoding and a specific rasterization strategy.
