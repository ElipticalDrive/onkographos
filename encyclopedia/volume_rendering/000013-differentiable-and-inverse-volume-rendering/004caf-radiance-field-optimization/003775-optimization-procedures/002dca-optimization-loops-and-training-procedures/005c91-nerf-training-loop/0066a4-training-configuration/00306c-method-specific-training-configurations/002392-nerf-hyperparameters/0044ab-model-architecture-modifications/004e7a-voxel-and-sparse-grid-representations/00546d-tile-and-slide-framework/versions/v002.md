# Tile and Slide Framework

Also called: Snake-NeRF

## Overview
The Tile and Slide Framework (Snake-NeRF) is an out-of-core method that scales Neural Radiance Fields (NeRFs) to large-scale 3D Earth observation scenes (e.g., 10km x 10km) by dividing the region of interest into non-overlapping 3D tiles, each trained with its own NeRF [S1]. It solves the memory bottleneck of large scenes by operating on a single GPU without loading all images or networks simultaneously, ensuring linear time complexity and fixed memory usage [S1]. Unlike NeRF-XL which dispatches NeRFs to multiple GPUs, this framework guarantees seamless rendering along tile edges using a 2x2 sliding window progression and a segmented ray sampler [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N_{im}$ satellite images covering a Region of Interest (ROI) with area $A_{ROI}$ and spatial resolution $SR$ (pix/m). Rational Polynomial Coefficients (RPCs) for each image to compute ray origins and directions [S1].
*   **Outputs:** A set of non-overlapping NeRF models, one per 3D tile, representing the scene geometry and appearance [S1].

**Data Structures:**
*   **Tiling Grid:** A square grid aligned with East/North (UTM coordinates) partitioning the ROI into non-overlapping 3D tiles [S1].
*   **NeRF Model:** Each tile uses a NeRF architecture similar to NeRF-XL, employing multi-resolution hash tables to encode geometry and a global color network [S1]. The specific internal layout of the hash table or MLP is not detailed in the sources, but it follows the standard NeRF-XL configuration [S1].

**Numbered Steps:**
1.  **Scene Partitioning:** Divide the 3D ROI into a grid of non-overlapping 3D tiles aligned with UTM coordinates [S1].
2.  **Image Cropping:** Crop the input satellite images with overlap to ensure that each tile's NeRF is trained with all necessary pixels corresponding to its spatial domain [S1].
3.  **Sliding Window Progression:** Implement a 2x2 3D tile progression strategy (sliding window) during training. This ensures that every ray is used at least once in a training batch with all necessary NeRFs currently in memory, preventing the isolation of tile boundaries [S1].
4.  **Ray Computation:** Compute ray origins and directions on-the-fly using the RPCs of the cropped images, rather than pre-storing them [S1].
5.  **Segmented Sampling:** Use a segmented sampler that samples per-bounding box (tile) rather than on the entire ray. This guarantees seamless rendering along rays that intersect multiple bounding boxes [S1].
6.  **Training:** Train each NeRF independently on its assigned tile data. The framework prevents catastrophic forgetting by ensuring persistent information storage in trained NeRFs and using the sliding window to maintain context during the training phase [S1].

**Formulas:**
The input size $N$ is defined as:
$$
N = N_{im} \times A_{ROI} \times SR^2
$$
where $N_{im}$ is the number of images, $A_{ROI}$ is the surface area, and $SR$ is the Spatial Resolution in pix/m [S1].

**Parameters:**
*   **Typical Scene Size:** 10km by 10km at 30cm Ground Sample Distance, covered by 20 satellite images [S1].
*   **Scalability Conditions:**
    1.  Time complexity: $O(N)$ [S1].
    2.  Memory complexity: $O(1)$ (fixed memory budget) [S1].
    3.  Quality: The tiled algorithm $A_s$ produces results similar to the reference untiled algorithm $A$ ($A_s(x) \approx A(x)$) [S1].

**Edge Cases and Pitfalls:**
*   **Catastrophic Forgetting:** Training a single NeRF sequentially on subsets of rays $R_i$ causes loss of information on previously seen domains $R_j$ ($j < i$) [S1]. The framework avoids this by using non-overlapping NeRFs and the sliding window mechanism [S1].
*   **Memory Limits:** A typical scene (10km x 10km, 20 images) requires ~200GB for images, ~600GB for the NeRF, and 1.4TB for ray vectors (float32), which exceeds single GPU memory [S1]. The on-the-fly ray computation and out-of-core loading address this [S1].

**Pseudocode:**
```python
# Pseudocode for the Tile and Slide Framework training loop
# Note: Specific NeRF-XL internal details are abstracted as NeRFModel

def train_tile_and_slide(images, rpcs, roi_area, spatial_resolution, tile_size):
    """
    images: List of image data
    rpcs: List of Rational Polynomial Coefficients for each image
    roi_area: Area of the region of interest (A_ROI)
    spatial_resolution: Spatial resolution in pix/m (SR)
    tile_size: Size of each 3D tile
    """
    
    # 1. Partition scene into non-overlapping 3D tiles aligned with UTM
    tiles = create_utm_aligned_grid(roi_area, tile_size)
    
    # 2. Initialize NeRF models for each tile
    # Each tile gets its own NeRF instance
    nerf_models = {tile_id: NeRFModel() for tile_id in tiles}
    
    # 3. Crop images with overlap to ensure coverage for each tile
    # This ensures each NeRF has access to all necessary pixels
    cropped_images = crop_images_with_overlap(images, tiles)
    
    # 4. Define 2x2 sliding window progression
    # This ensures every ray is seen with necessary NeRFs in memory
    window_progression = get_2x2_sliding_window_progression(tiles)
    
    for window in window_progression:
        # Load only the NeRFs in the current 2x2 window into GPU memory
        active_tile_ids = window.tiles
        active_models = [nerf_models[tid] for tid in active_tile_ids]
        
        # Get relevant cropped images for these tiles
        relevant_images = get_images_for_tiles(active_tile_ids, cropped_images)
        
        # Training step for the current window
        for image, rpc in zip(relevant_images, relevant_images.rpcs):
            # Compute ray origins and directions on-the-fly from RPCs
            rays = compute_rays_on_the_fly(image, rpc)
            
            # Segment rays by bounding box (tile)
            # This guarantees seamless rendering across tile edges
            segmented_rays = segment_rays_by_bbox(rays, active_tile_ids)
            
            for tile_id, tile_rays in segmented_rays.items():
                if tile_id in active_tile_ids:
                    model = nerf_models[tile_id]
                    # Render using segmented sampler
                    rendered_colors = model.render_segmented(tile_rays)
                    
                    # Compute loss and update model
                    loss = compute_loss(rendered_colors, image)
                    model.update(loss)
                    
    return nerf_models
```

## Operating characteristics
*   **Time Complexity:** Linear with respect to input size $N$ ($O(N)$) [S1].
*   **Memory Complexity:** Constant with respect to input size ($O(1)$), never exceeding a fixed memory budget [S1].
*   **Hardware:** Designed to operate on a single GPU device [S1].
*   **Performance:** Successfully trained on a benchmark dataset of Very High Spatial Resolution (VHRS) multi-view satellite images [S1].
*   **Strengths:** Eliminates the need to load all images and networks simultaneously; prevents 3D reconstruction errors along tile edges; scalable to large areas (10km x 10km) [S1].
*   **Limitations:** Requires careful tiling strategy and image cropping; relies on NeRF-XL-like architecture for geometry encoding [S1].
*   **When to use:** Large-scale Earth observation scenes (satellite, airborne, UAV) where memory constraints prevent training a single NeRF [S1].
*   **When not to use:** Small scenes where a single NeRF fits in memory; scenes requiring multi-GPU dispatching (use NeRF-XL instead) [S1].

## Background
The Tile and Slide Framework, also known as Snake-NeRF, was introduced to address the memory footprint constraints of state-of-the-art NeRF methods when applied to large scenes [S1]. It builds on the idea of dividing the scene into multiple NeRFs, as seen in Kilo-NeRF [S1], but adapts it for large-scale Earth observation with a single-GPU constraint [S1]. The framework uses multi-resolution hash tables for geometry encoding and a global color network, similar to NeRF-XL [S1].
