# Exponential Learning Rate Decay with Delay

Also called: Exponential Learning Rate Decay

## Overview
Exponential Learning Rate Decay with Delay is a learning rate schedule function used in NeRF optimization that interpolates between an initial and final learning rate using logarithmic linear interpolation, while optionally applying a warm-up phase via reverse cosine decay [S1, S2, unofficial]. It distinguishes itself from standard exponential decay by providing a controlled initial delay period where the learning rate is modulated by a separate cosine schedule, allowing for stable initialization before the main decay trajectory begins [S1, S2, unofficial].

## How it works
The method computes a scalar learning rate value given the current training step and a set of hyperparameters. It combines two components: a base exponential decay curve and an optional delay multiplier.

**Inputs:**
- `step` (int): Current training step index (non-negative).
- `max_steps` (int): Total number of training steps.
- `lr_init` (float): Initial learning rate.
- `lr_final` (float): Final learning rate.
- `lr_delay_steps` (int): Number of steps to apply the delay/warm-up phase.
- `lr_delay_mult` (float): Multiplier scaling the learning rate during the delay phase.

**Outputs:**
- `lr` (float): The computed learning rate for the current step.

**Data Structures:**
No persistent data structures are required; the function is stateless and computes the value from inputs alone.

**Parameters:**
- `lr_delay_steps`: Controls the duration of the warm-up/delay phase. If 0, no delay is applied [S1, S2, unofficial].
- `lr_delay_mult`: Scales the learning rate during the delay. Typical values are small positive floats (e.g., 0.1) to suppress updates initially [S1, S2, unofficial].

**Algorithm Steps:**
1. **Edge Case Handling**: If `step < 0`, return 0.0 [S2, unofficial]. If both `lr_init` and `lr_final` are 0, return 0.0 [S2, unofficial].
2. **Compute Delay Rate**:
   - If `lr_delay_steps > 0`:
     - Calculate the normalized delay progress: $d = \text{clip}(\text{step} / \text{lr\_delay\_steps}, 0, 1)$ [S1, S2, unofficial].
     - Compute the delay rate using reverse cosine decay:
       $$ \text{delay\_rate} = \text{lr\_delay\_mult} + (1 - \text{lr\_delay\_mult}) \cdot \sin\left(0.5 \cdot \pi \cdot d\right) $$
       [S1, S2, unofficial]
   - Else:
     - Set $\text{delay\_rate} = 1.0$ [S2, unofficial].
3. **Compute Base Decay Progress**:
   - Calculate the normalized training progress:
     $$ t = \text{clip}(\text{step} / \text{max\_steps}, 0, 1) $$
     [S1, S2, unofficial]
4. **Compute Log-Linear Interpolation**:
   - Calculate the base learning rate using exponential interpolation between `lr_init` and `lr_final`:
     $$ \text{log\_lerp} = \exp\left( \log(\text{lr\_init}) \cdot (1 - t) + \log(\text{lr\_final}) \cdot t \right) $$
     [S1, S2, unofficial]
5. **Combine**:
   - Return the final learning rate:
     $$ \text{lr} = \text{delay\_rate} \cdot \text{log\_lerp} $$
     [S1, S2, unofficial]

**Pseudocode:**
```python
import numpy as np

def get_expon_lr_func(lr_init, lr_final, lr_delay_steps, lr_delay_mult, max_steps):
    """
    Generates a learning rate schedule that decays exponentially from lr_init to lr_final
    over max_steps, with an optional initial delay phase.
    
    Args:
        lr_init: Initial learning rate.
        lr_final: Final learning rate.
        lr_delay_steps: Number of steps to delay the decay.
        lr_delay_mult: Multiplier for the delay period.
        max_steps: Total number of training steps.
        
    Returns:
        A function that takes a step index and returns the learning rate.
    """
    def schedule(step):
        # Edge case: invalid step or zero learning rates
        if step < 0:
            return 0.0
        if lr_init == 0.0 and lr_final == 0.0:
            return 0.0
            
        # Compute delay rate
        if lr_delay_steps > 0:
            # Clip to ensure valid range for sin argument
            delay_progress = np.clip(step / lr_delay_steps, 0, 1)
            delay_rate = lr_delay_mult + (1 - lr_delay_mult) * np.sin(0.5 * np.pi * delay_progress)
        else:
            delay_rate = 1.0
            
        # Compute base exponential decay progress
        t = np.clip(step / max_steps, 0, 1)
        
        # Log-linear interpolation
        # Using log space to ensure smooth exponential decay
        log_lr_init = np.log(lr_init)
        log_lr_final = np.log(lr_final)
        log_lerp = np.exp(log_lr_init * (1 - t) + log_lr_final * t)
        
        return delay_rate * log_lerp
        
    return schedule
```

**Edge Cases and Pitfalls:**
- **Division by Zero**: If `lr_delay_steps` is 0, the division in step 2 is skipped. If `max_steps` is 0, the division in step 3 would cause an error; however, `max_steps` is typically a large positive integer in training contexts [S1, S2, unofficial].
- **Zero Learning Rates**: If `lr_init` or `lr_final` is 0, `np.log` will return `-inf`. The edge case check handles both being 0, but if only one is 0, the result will be 0 or `-inf` depending on implementation. Standard practice ensures positive learning rates [S2, unofficial].
- **Precision**: Using `np.log` and `np.exp` avoids underflow/overflow issues associated with direct exponential decay for large step counts [S1, S2, unofficial].

## Operating characteristics
- **Time Complexity**: $O(1)$ per step. The computation involves basic arithmetic and trigonometric functions.
- **Memory Complexity**: $O(1)$. No state is stored between steps.
- **Strengths**: Provides a smooth transition from a potentially suppressed initial rate to the main decay curve, which can help stabilize early training [S1, S2, unofficial]. The log-linear interpolation ensures the learning rate decays exponentially in value, which is often more effective than linear decay for neural network optimization [S1, S2, unofficial].
- **Limitations**: Requires careful tuning of `lr_delay_steps` and `lr_delay_mult`. If `lr_delay_steps` is too large relative to `max_steps`, the model may not learn effectively in the early stages [S1, S2, unofficial].
- **When to Use**: Suitable for NeRF training where stable initialization is critical. It is particularly useful when combined with other initialization strategies or when the initial gradients are noisy [S1, S2, unofficial].
