# UE4-NeRF


## Overview
UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale 3D scenes by partitioning the environment into sub-NeRFs represented as textured polygonal meshes [S1]. It integrates these neural representations into the Unreal Engine 4 (UE4) rasterization pipeline, enabling real-time frame rates at high resolutions (up to 4K) while supporting scene editing [S1]. Unlike grid-based large-scale methods like Block-NeRF, UE4-NeRF uses regular octahedra to handle tilted surfaces and stores opacity in texture maps to support semi-transparent objects, addressing the convergence and material limitations of Mobile-NeRF [S1].

## How it works
UE4-NeRF operates in three phases: block partitioning and coarse training, mesh initialization and optimization, and real-time rendering via UE4 integration [S1].

### Inputs and Outputs
**Inputs:**
*   A set of posed images capturing a large-scale scene (e.g., drone imagery).
*   GPS coordinates for each image to establish real-world scale and orientation [S1].
*   Camera intrinsics and extrinsics [S1].

**Outputs:**
*   A set of textured polygonal meshes (one per block) with embedded neural shaders.
*   A Level of Detail (LOD) hierarchy of these meshes for varying observation heights [S1].
*   Real-time rendered RGB images within UE4 [S1].

### Data Structures
**1. Block Partitioning:**
*   The scene is divided into overlapping blocks. Each training area is slightly larger than the corresponding scene area to ensure smooth transitions at borders [S1].
*   A coarse model is trained to segment sub-regions, capturing overall terrain and building outlines. Images are filtered using masks to exclude pixels outside the specific sub-region [S1].

**2. Mesh Representation:**
*   **Grid Initialization:** A $128 \times 128 \times 128$ grid is initialized for each block [S1].
*   **Octahedron Construction:** For each grid cell, the center point and its six neighbors (front, back, left, right, top, bottom) are selected to form polygonal meshes. Specifically, a regular octahedron with 20 faces (8 exterior, 12 interior) is used [S1].
*   **Texture Atlas:** Stores feature vectors and opacity information for each mesh vertex/face [S1].

**3. Neural Network Architecture:**
*   **Encoder Network ($E$):** A 4-layer MLP with dimensions $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$. It takes multi-resolution hash-encoded position $\mathbf{p}_i$ and outputs opacity $\alpha_i$ and an 8-dimensional feature vector $\mathbf{M}_i$ [S1].
*   **Decoder Network ($D$):** A 3-layer MLP with dimensions $17 \times 16$, $16 \times 16$, $16 \times 3$. It takes the feature vector $\mathbf{M}_i$ and the encoded viewing direction $\gamma(\mathbf{d}_i)$ to output the final color $\mathbf{c}_i$ [S1].
*   **Encoding:** Multi-resolution hash encoding (from Instant-NGP) is used for position $\mathbf{p}_i$ [S1]. Direction $\mathbf{d}_i$ is encoded using standard sinusoidal positional encoding (implied by "SH" in formula and standard NeRF practice, though specific dimensions for direction encoding are not explicitly detailed beyond the input size to the decoder: $8 (\text{features}) + 9 (\text{direction}) = 17$ inputs, suggesting 9-dimensional spherical harmonic or similar encoding for direction) [S1].

### Numbered Steps

1.  **Coordinate Transformation:**
    *   Transform GPS-captured drone imagery coordinates to the UE4 coordinate system.
    *   UE4 Coordinate System: X-axis points East, Y-axis points South, Z-axis points Up [S1].
    *   Apply a 100:1 scale conversion (UE4 units to real-world units) [S1].

2.  **Block Partitioning:**
    *   Partition the large scene into multiple blocks.
    *   Train a coarse model to delineate sub-regions.
    *   Filter images and apply masks to exclude pixels outside the block's scene area [S1].

3.  **Mesh Initialization:**
    *   Initialize a $128 \times 128 \times 128$ grid for the block.
    *   Select the center point of each grid cell and its six orthogonal neighbors.
    *   Construct regular octahedra (20 faces: 8 exterior, 12 interior) from these points [S1].

4.  **Network Training:**
    *   Define the ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$, where $\mathbf{o}$ is the camera origin and $\mathbf{d} = (\theta, \phi)$ is the viewing direction [S1].
    *   Calculate the intersection of each ray with the polygonal meshes. The intersection point serves as the sampling point [S1].
    *   Optimize the Encoder-Decoder network parameters and the vertex positions of the meshes simultaneously.
    *   **Encoder:** $\mathbf{M}_i, \alpha_i = E(\text{hash}(\mathbf{p}_i); \theta_E)$ [S1].
    *   **Decoder:** $\mathbf{c}_i = D(\mathbf{M}_i, \text{SH}(\mathbf{d}_i); \theta_D)$ [S1].
    *   Train for 80,000 epochs per block using one Nvidia RTX 3090 GPU [S1].

5.  **LOD Generation:**
    *   Train meshes with varying levels of detail (LOD) for different observation heights.
    *   Coarser meshes are used for higher observation heights to ensure real-time performance [S1].

6.  **Rendering Integration:**
    *   Extract pre-rendered polygonal meshes at different LODs.
    *   Implement the Decoder network as an HLSL fragment shader in UE4. The shader takes feature vectors (from the texture atlas) as input and outputs colors [S1].
    *   Combine the meshes with the UE4 rasterization pipeline for real-time interactive rendering [S1].

### Pseudocode

```python
# UE4-NeRF Training and Rendering Pipeline

def ue4_nerf_pipeline(images, gps_data, intrinsics, extrinsics):
    """
    Main pipeline for UE4-NeRF.
    """
    # 1. Coordinate Transformation
    # Transform GPS to UE4 coordinates: X=East, Y=South, Z=Up
    # Scale: 100:1 (UE4 units per real-world unit)
    ue4_positions = transform_gps_to_ue4(gps_data, scale=100.0, 
                                         x_axis='east', y_axis='south', z_axis='up')
    
    # 2. Block Partitioning
    blocks = partition_scene(ue4_positions, images, overlap=True)
    
    trained_blocks = []
    for block_id, block_data in enumerate(blocks):
        # 2a. Coarse Model for Segmentation
        coarse_model = train_coarse_model(block_data.images, block_data.mask)
        
        # 2b. Mesh Initialization
        # Initialize 128x128x128 grid
        grid = initialize_grid(size=(128, 128, 128))
        
        # Construct octahedra from grid centers and neighbors
        # Each octahedron has 20 faces (8 exterior, 12 interior)
        meshes = construct_octahedra_meshes(grid)
        
        # 2c. Network Definition
        # Encoder: 4-layer MLP (32->64->64->64->8)
        encoder = MLP(layers=[32, 64, 64, 64, 8])
        # Decoder: 3-layer MLP (17->16->16->3)
        # Input: 8 (features) + 9 (direction encoding) = 17
        decoder = MLP(layers=[17, 16, 16, 3])
        
        # Hash Encoder for position (from Instant-NGP)
        hash_encoder = MultiResolutionHashEncoder()
        
        # 2d. Training Loop
        # Optimize network parameters and vertex positions
        for epoch in range(80000):
            for image in block_data.images:
                # Cast rays from camera
                rays = cast_rays(image.camera_origin, image.camera_direction, intrinsics)
                
                # Find intersections with meshes
                intersections = find_ray_mesh_intersections(rays, meshes)
                
                # Sample points at intersections
                sampled_points = intersections.point
                sampled_directions = rays.direction
                
                # Encode position using hash encoding
                encoded_pos = hash_encoder.encode(sampled_points)
                
                # Encode direction (Spherical Harmonics or similar, dim=9)
                encoded_dir = encode_direction(sampled_directions)
                
                # Forward pass through Encoder
                features, opacity = encoder(encoded_pos)
                
                # Concatenate features and direction encoding
                # 8 features + 9 direction = 17
                input_to_decoder = concatenate(features, encoded_dir)
                
                # Forward pass through Decoder
                color = decoder(input_to_decoder)
                
                # Compute loss (e.g., MSE between predicted color and image pixel)
                loss = compute_loss(color, image.pixel_color)
                
                # Backpropagate to update encoder, decoder, and mesh vertices
                update_parameters(encoder, decoder, meshes.vertices, loss)
        
        # 2e. LOD Generation
        # Extract meshes at different levels of detail
        lod_meshes = generate_lod_meshes(meshes, num_levels=3)
        
        # 2f. Export for UE4
        # Convert Decoder to HLSL fragment shader
        shader_code = export_to_hlsld(decoder)
        
        # Create texture atlas for features and opacity
        texture_atlas = create_texture_atlas(meshes.features, meshes.opacity)
        
        trained_blocks.append({
            'id': block_id,
            'lod_meshes': lod_meshes,
            'shader': shader_code,
            'texture_atlas': texture_atlas
        })
        
    return trained_blocks

def render_ue4(trained_blocks, camera_pose, resolution):
    """
    Real-time rendering using UE4 rasterization pipeline.
    """
    # Select appropriate LOD based on camera height
    lod_level = select_lod_level(camera_pose.height, trained_blocks)
    
    # For each block in view
    for block in trained_blocks:
        # Get the mesh for the selected LOD
        mesh = block['lod_meshes'][lod_level]
        
        # Rasterize mesh in UE4
        # The fragment shader uses the texture atlas to look up features
        # and the neural network (HLSL) to compute color
        rendered_image = rasterize_with_neural_shader(
            mesh=mesh,
            shader=block['shader'],
            texture_atlas=block['texture_atlas'],
            camera_pose=camera_pose,
            resolution=resolution
        )
        
    return rendered_image
```

### Parameters
*   **Grid Size:** $128 \times 128 \times 128$ [S1].
*   **Octahedron Faces:** 20 total (8 exterior, 12 interior) [S1].
*   **Encoder MLP:** 4 layers, dimensions $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
*   **Decoder MLP:** 3 layers, dimensions $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
*   **Training Hardware:** 1 Nvidia RTX 3090 GPU [S1].
*   **Training Iterations:** 80,000 epochs per block [S1].
*   **Coordinate System:** X=East, Y=South, Z=Up [S1].
*   **World Scale:** 100:1 [S1].

### Edge Cases and Pitfalls
*   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces. UE4-NeRF addresses this by using regular octahedra instead of the Mobile-NeRF approach [S1].
*   **Semi-transparent Objects:** Mobile-NeRF cannot handle transparent/semi-transparent objects (water, glass, plastic) due to opacity binarization. UE4-NeRF stores opacity in texture maps to mitigate this [S1]. However, semi-transparent objects (e.g., vegetation) increase computational overhead, reducing frame rates [S1].
*   **Pre-rendering Gaps:** Pre-rendering cannot capture rays from all viewing angles, potentially resulting in gaps or holes in the final rendered scene [S1].
*   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, causing evaluation metrics (PSNR/SSIM) to underestimate actual reconstruction quality [S1].
*   **Memory Overhead:** Rendering large scenes (square kilometers) incurs significant memory overhead. Increasing accuracy further amplifies memory consumption [S1].
*   **Hardware Dependency:** Requires CUDA and NVIDIA GPUs [S1].

## Operating characteristics
*   **Training Speed:** 1000× faster than Mobile-NeRF [S1].
*   **Training Time:** 40 minutes per block on 1×RTX 3090. Total training time for a scene with $n$ blocks is $1 \text{ hour} + (40 \text{ minutes} \times n/4)$ on 1×RTX 3090 [S1].
*   **Rendering Performance:**
    *   Real-time rendering at 4K resolution with up to 43 FPS [S1].
    *   50 FPS on full scene at 2K resolution [S1].
    *   ≥70 FPS on individual blocks at 2K resolution [S1].
*   **Scaling:** Uses a Level of Detail (LOD) hierarchy. Coarser meshes are used for higher observation heights to maintain real-time performance [S1].
*   **Strengths:**
    *   Real-time interactive rendering of large-scale scenes [S1].
    *   Handles tilted surfaces better than Mobile-NeRF [S1].
    *   Supports semi-transparent objects via texture-based opacity [S1].
    *   Enables scene editing by integrating with UE4 (occlusion handling, object import) [S1].
    *   Avoids blurriness on natural scenes and renders small objects (e.g., power lines) accurately compared to Mip-NeRF [S1].
*   **Limitations:**
    *   Requires NVIDIA GPUs and CUDA [S1].
    *   High memory consumption for large scenes [S1].
    *   Potential gaps/holes due to pre-rendering limitations [S1].
    *   Semi-transparent objects reduce frame rates [S1].
    *   Evaluation metrics may underestimate quality due to exposure mismatch in UE4 [S1].

## Background
UE4-NeRF was introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" [S1]. It was developed to address the limitations of existing NeRF methods in real-time rendering of large-scale scenes, such as high training costs, slow rendering speeds, and inability to handle complex materials or scene editing [S1]. The method builds on techniques from Mobile-NeRF (mesh-based representation) and Instant-NGP (multi-resolution hash encoding) [S1]. It is used in Unreal Engine 4 for real-time interactive rendering and scene editing, particularly for drone-captured large-scale scenes like farmlands, construction sites, and industrial parks [S1].
