# NLR Baseline

Also called: NLR, Neural Lumigraph Representation

## Overview
NLR [S1, unofficial] is a differentiable volume rendering method that represents a scene using a neural lumigraph, optimizing a set of per-view feature embeddings and a shared neural network to predict radiance and density. It serves as a high-quality, albeit computationally expensive, baseline for novel view synthesis, particularly in the context of meta-learning comparisons [S1, unofficial]. It is distinguished from standard NeRF by its reliance on view-dependent embeddings and its significantly higher per-iteration training cost, which is offset by faster convergence in meta-learning settings [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ training images with known camera poses. Each image $i$ has an associated view embedding $v_i$.
*   **Outputs:** A neural network that, given a 3D point $x$, a view embedding $v$, and a viewing direction $d$, outputs volume density $\sigma$ and color $C$.

**Data Structures:**
*   **View Embeddings:** A learnable vector $v_i \in \mathbb{R}^k$ for each training view $i$.
*   **Neural Network:** A Multi-Layer Perceptron (MLP) taking concatenated inputs of position $x$, view embedding $v$, and direction $d$. The exact architecture is not specified in the baseline notes, but it is referenced as the "NLR implementation" [S1, unofficial].

**Steps:**
1.  **Initialization:** Initialize view embeddings $v_i$ for all training views. Initialize the shared MLP parameters.
2.  **Sampling:** For each training image $i$, sample rays through the scene. For each point $x$ along a ray, retrieve the view embedding $v_i$.
3.  **Network Forward Pass:** Compute density $\sigma(x, v_i, d)$ and color $C(x, v_i, d)$ using the shared MLP.
4.  **Volume Rendering:** Apply standard volume rendering integration to compute the final pixel color $C_{rendered}$ and depth.
5.  **Loss Computation:** Compute the photometric loss (e.g., MSE) between $C_{rendered}$ and the ground truth image pixel.
6.  **Optimization:** Update the view embeddings and MLP parameters using gradient descent to minimize the loss.

**Parameters:**
*   **Meta-learning rate:** $5 \times 10^{-2}$ [S1, unofficial].
*   **Resolution:** 800x600 [S1, unofficial].
*   **Inner loop steps:** Not specified in the baseline notes, but noted to be equal to the number of steps in the compared method [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** The method is noted to have high per-iteration time, suggesting potential numerical stability or memory bandwidth bottlenecks [S1, unofficial].
*   **Boundaries:** The method assumes accurate camera poses and masks, as inaccuracies in COLMAP-produced masks can limit performance [S1, unofficial].

**Pseudocode:**
```python
# NLR Baseline Training Loop
# Inputs: training_images, camera_poses, meta_lr, inner_steps
# Outputs: optimized_view_embeddings, optimized_mlp_params

def nlr_baseline_training(training_images, camera_poses, meta_lr, inner_steps):
    # Initialize view embeddings for each training view
    view_embeddings = initialize_embeddings(len(training_images))
    
    # Initialize shared MLP parameters
    mlp_params = initialize_mlp_params()
    
    for meta_iteration in range(total_meta_iterations):
        # Inner loop: specialize to a specific training scene/view
        current_view_embeddings = view_embeddings.clone()
        current_mlp_params = mlp_params.clone()
        
        for inner_step in range(inner_steps):
            # Sample a batch of rays from the current training views
            rays = sample_rays(training_images, camera_poses)
            
            # For each ray, get the corresponding view embedding
            ray_view_embeddings = get_view_embeddings(rays, current_view_embeddings)
            
            # Forward pass through the shared MLP
            densities, colors = shared_mlp_forward(rays.points, ray_view_embeddings, rays.directions, current_mlp_params)
            
            # Volume rendering
            rendered_colors = volume_render(rays, densities, colors)
            
            # Compute photometric loss
            gt_colors = get_ground_truth_colors(rays, training_images)
            loss = mse_loss(rendered_colors, gt_colors)
            
            # Backward pass and update
            gradients = compute_gradients(loss, current_mlp_params, current_view_embeddings)
            current_mlp_params = update_params(current_mlp_params, gradients.mlp, meta_lr)
            current_view_embeddings = update_params(current_view_embeddings, gradients.views, meta_lr)
        
        # Meta-update: update the shared initialization using Reptile
        # Note: The specific Reptile update rule is not detailed in the baseline notes [S1, unofficial]
        mlp_params = reptile_update(mlp_params, current_mlp_params, meta_lr)
        view_embeddings = reptile_update(view_embeddings, current_view_embeddings, meta_lr)
        
    return view_embeddings, mlp_params
```

## Subtopics

### MetaNLR Baseline
MetaNLR is a variant of NLR that wraps the NLR implementation with an outer loop using the Reptile algorithm to learn the initialization of the shape and color networks [S1, unofficial]. It is designed for few-shot novel view synthesis, specializing to test scenes using the same training and testing views at 800x600 resolution [S1, unofficial]. It is chosen when the goal is to evaluate the effectiveness of meta-learning for rapid adaptation to new scenes compared to standard NLR training [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** NLR has a training time of 2.21 seconds per iteration [S1, unofficial]. This is significantly slower than NeRF (0.40 sec/iteration) and IDR (0.2 sec/iteration) [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Rendering time is 0.025 seconds per frame [S1, unofficial].
*   **Scaling:** MetaNLR++ iterations take 2.19 seconds without shape optimization and 7.69 seconds with shape optimization [S1, unofficial]. The longer iteration times are due to optimizing for multiple entire images instead of randomly selected rays, resulting in larger ray-batch sizes [S1, unofficial].
*   **Strengths:** High quality novel view synthesis results after a short amount of time [S1, unofficial].
*   **Limitations:** High per-iteration training time [S1, unofficial]. Performance can be limited by inaccurate rendering masks in COLMAP-produced data [S1, unofficial].
*   **When to use:** When a high-quality baseline is needed for meta-learning comparisons or when computational resources allow for longer training times [S1, unofficial].
*   **When not to use:** When fast training or real-time rendering is required [S1, unofficial].

## Background
NLR was introduced as a neural lumigraph representation method [S1, unofficial]. It is used as a baseline in the context of fast training of neural lumigraph representations using meta-learning [S1, unofficial]. The method is compared against NeRF, IBRNet, SVS*, and IDR [S1, unofficial].
