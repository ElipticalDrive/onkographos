# Attention-Based Volumetric Rendering

Also called: AB Transformer, ABLE-NeRF, Attention-based Neural Radiance Fields

## Overview
Attention-Based Volumetric Rendering (ABLE-NeRF) replaces the physics-based volumetric rendering equation with a self-attention mechanism to handle view-dependent effects, glossy surfaces, and translucent objects [S1]. Unlike standard NeRF variants that rely on normal prediction or regularization to exclude back-facing points, ABLE-NeRF uses masked attention to implicitly enforce front-to-back accumulation, avoiding the ill-posed nature of predicting normals in an object's interior [S1]. It incorporates Learnable Embeddings (LE) to memorize scene lighting information, similar to light probes in game engines, allowing for accurate relighting and specular effect rendering [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Camera ray $r(t) = o + td$ (origin $o$, direction $d$), camera pose for view token.
*   **Output:** Predicted RGB color $\mathbf{y}$ for the ray.

**Data Structures:**
1.  **Conic Frustum Volumes:** $N$ samples along the ray. Each volume is encoded using Integrated Positional Encoding (IPE) [S1].
2.  **Volume Embeddings ($v_i$):** Latent vector of dimension $D$. Generated by passing each conic volume through a Volume Embedding Block (4 MLP layers) [S1].
3.  **Ray Token ($R$):** Learnable vector of dimension $D$, prepended to the sequence [S1].
4.  **Learnable Embeddings (LE):** $K$ learnable memory tokens of dimension $D$ (e.g., $K=32$) [S1].
5.  **View Token ($V$):** Derived from camera pose, used to query LEs [S1].

**Numbered Steps:**

1.  **Ray Sampling:** Cast a camera ray $r(t) = o + td$ into the scene. Sample $N$ conic frustum volumes along the ray between near and far boundaries. The positions are encoded using Integrated Positional Encoding (IPE) [S1].
2.  **Volume Embedding:** Pass each conic volume $i$ through a Volume Embedding Block consisting of four MLP layers with ReLU activations and hidden dimension $D$. This generates a sequence of volume embeddings $v_1, v_2, \dots, v_N$, where $i$ denotes the position from the camera [S1].
3.  **Sequence Initialization:** Prepend the Ray Token $R$ to the sequence to form the input for the first transformer layer:
    $$ Z_0 = \{R, v_1, v_2, \dots, v_N\} $$
    where $R$ and all $v_i$ have dimension $D$ [S1].
4.  **Attention-Based Rendering Transformer (AB Transformer):** Process the sequence through $L$ transformer encoder layers. For layer $l$ ($1 \le l \le L$):
    *   **Masked Self-Attention for Volumes:** Each volume embedding $v_i^l$ attends only to itself, the Ray Token, and volume embeddings $v_j$ where $j < i$ (in front of it). It excludes volumes behind it ($j > i$). This is implemented by setting the scaled-dot product attention scores to $-\infty$ for illegal connections before the softmax operation [S1].
        $$ v_i^l = \text{Att}(Z^{l-1} \setminus \{v^{l-1}_{i+1}, \dots, v^{l-1}_N\}) $$
    *   **Unmasked Attention for Ray Token:** The Ray Token $R^l$ attends to all elements in the sequence $Z^{l-1}$ (all volumes and previous tokens) [S1].
        $$ R^l = \text{Att}(Z^{l-1}) $$
    *   Note: The set notation $Z^{l-1}$ represents the sequence of tokens at layer $l-1$. The output of the attention mechanism is typically followed by Layer Normalization and a Feed-Forward Network (FFN) as in standard Transformers, though the specific FFN structure is not detailed beyond the hidden unit ratio [S1].
5.  **Color Prediction:** After the final layer $L$, attach a single MLP classification head to the final Ray Token $R_L$ to predict the ray color $\mathbf{y}$ [S1].
    $$ \mathbf{y} = \text{MLP}(R_L) $$
6.  **Learnable Embeddings (LE) Integration (Optional/Extended):** To capture view-dependent effects, $K$ Learnable Embeddings are introduced.
    *   Cross-attention is applied where the LEs attend to the volume embeddings (or the output of the AB Transformer) to memorize scene information [S1].
    *   A directional View Token $V$, comprising the camera pose, queries the LEs to decode view-dependent effects [S1].
    *   *Note:* The core AB Transformer logic (Steps 1-5) defines the replacement of the VR equation. The LE component is an additional module for handling complex lighting/specularities [S1].

**Formulas:**
*   **Input Sequence:**
    $$ Z_0 = \{R, v_1, v_2, \dots, v_N\} \quad [S1] $$
*   **Volume Update (Masked):**
    $$ v_i^l = \text{Att}(Z^{l-1} \setminus \{v^{l-1}_{i+1}, \dots, v^{l-1}_N\}) \quad [S1] $$
*   **Ray Token Update (Unmasked):**
    $$ R^l = \text{Att}(Z^{l-1}) \quad [S1] $$
*   **Output:**
    $$ \mathbf{y} = \text{MLP}(R_L) \quad [S1] $$

**Parameters:**
*   $N$: Number of conic frustum volumes sampled along the ray. Typical value: 96 per network (192 total for coarse+fine) [S1].
*   $L$: Number of transformer layers. Typical value: 2 for coarse network, 6 for fine network [S1].
*   $D$: Latent dimensional size of volume embeddings and ray token. Typical value: 192 [S1].
*   $K$: Number of Learnable Embeddings. Typical value: 32 (standard Blender), 16 (Shiny Blender) [S1].

**Pitfalls:**
*   **Masking:** Without masking, the ray is treated as bi-directional, causing the network difficulty in predicting correct surface appearance [S1].
*   **Normal Prediction:** Unlike Ref-NeRF, this method does not predict normals. Relying on normal prediction for excluding back-facing points is ill-posed for interior points [S1].

import torch.nn as nn
import torch.nn.functional as F

            nn.Linear(D, D)
        )

    def forward(self, x):
        return self.layers(x)

class AttentionBasedVolumetricRendering(nn.Module):
    def __init__(self, N=96, L=6, D=192, num_heads=8):
        super().__init__()
        self.N = N
        self.L = L
        self.D = D
        
        # Ray Token
        self.R = nn.Parameter(torch.randn(1, 1, D))
        
        # Volume Embedding Block
        self.volume_embedder = VolumeEmbeddingBlock(D)
        
        # Transformer Layers
        self.transformer_layers = nn.ModuleList([
            TransformerEncoderLayer(D, num_heads) for _ in range(L)
        ])
        
        # Output MLP
        self.output_mlp = nn.Sequential(
            nn.Linear(D, D),
            nn.ReLU(),
            nn.Linear(D, 3) # RGB
        )

    def create_attention_mask(self, N):
        """
        Create causal mask for volume embeddings.
        v_i can attend to v_j where j <= i.
        Shape: (N, N)
        """
        # Create a mask where 1 means allowed, 0 means blocked
        # We want v_i to attend to 0..i
        # Standard causal mask is upper triangular 0s, lower triangular 1s
        # But here index 0 is closest to camera? 
        # Source says: "v_i can only attend to itself... and other volume embeddings lying in front of it (indices < i)"
        # And "Exclude conic volumes sequenced behind v_i"
        # Assuming sequence is [v_1, ..., v_N] from camera to far.
        # v_1 (closest) attends to v_1.
        # v_2 attends to v_1, v_2.
        # Mask should allow attention to indices <= i.
        
        mask = torch.tril(torch.ones(N, N, dtype=torch.bool))
        return mask

    def forward(self, volume_features):
        """
        volume_features: (B, N, D) - Embedded conic frustums
        """
        B, N, D = volume_features.shape
        
        # Prepend Ray Token
        # R shape: (1, 1, D) -> broadcast to (B, 1, D)
        R_expanded = self.R.expand(B, 1, -1)
        Z = torch.cat([R_expanded, volume_features], dim=1) 
        # Z shape: (B, N+1, D)
        # Index 0 is R, Indices 1..N are v_1..v_N
        
        # Create mask for the N volume embeddings
        # We need to mask attention among the volume embeddings only.
        # The Ray Token (index 0) is unmasked.
        
        for layer in self.transformer_layers:
            # Get attention scores for all tokens
            # Assuming layer handles multi-head attention internally
            # We need to inject the mask
            
            # Extract volume embeddings part for masking logic
            # Z[:, 0, :] is R
            # Z[:, 1:, :] are volumes
            
            # Standard Transformer Layer forward would compute Q, K, V
            # Then apply mask to attention scores
            
            # Since we can't easily modify internal layer without subclassing,
            # we assume a custom TransformerEncoderLayer that accepts a mask
            # for specific token interactions.
            
            # Simplified: Pass Z and a mask that blocks volume-to-volume rear attention
            # Mask shape: (B, num_heads, seq_len, seq_len)
            
            # Construct mask:
            # R (idx 0) can attend to all.
            # v_i (idx i+1) can attend to R (idx 0) and v_j (idx j+1) where j <= i.
            
            seq_len = N + 1
            mask = torch.ones(seq_len, seq_len, dtype=torch.bool)
            
            # Mask for volume-to-volume
            # v_i (row i+1) can attend to v_j (col j+1) if j <= i
            # i ranges 0..N-1 (indices in volume list)
            # Tensor indices in Z are 1..N
            
            for i in range(N):
                row_idx = i + 1
                for j in range(N):
                    col_idx = j + 1
                    if j > i:
                        mask[row_idx, col_idx] = False
            
            # R (row 0) is all True.
            # Columns for R (col 0) are all True (volumes can attend to R? 
            # Source says "v_i can only attend to itself, the ray token...")
            # So yes, volumes attend to R.
            
            # Apply mask in layer
            Z = layer(Z, mask=mask)
            
        # Final Ray Token is at index 0
        R_final = Z[:, 0, :]
        y = self.output_mlp(R_final)
        return y

class TransformerEncoderLayer(nn.Module):
    def __init__(self, D, num_heads):
        super().__init__()
        self.self_attn = nn.MultiheadAttention(D, num_heads, batch_first=True)
        self.norm1 = nn.LayerNorm(D)
        self.norm2 = nn.LayerNorm(D)
        self.ffn = nn.Sequential(
            nn.Linear(D, D * 3), # FF hidden unit ratio 1:3
            nn.ReLU(),
            nn.Linear(D * 3, D)
        )
        
    def forward(self, x, mask=None):
        # Self Attention
        attn_output, _ = self.self_attn(x, x, x, attn_mask=mask)
        x = self.norm1(x + attn_output)
        
        # FFN
        ffn_output = self.ffn(x)
        x = self.norm2(x + ffn_output)
        return x

## Operating characteristics
*   **Time Complexity:** Depends on the number of transformer layers $L$ and samples $N$. The self-attention mechanism is $O(N^2)$ per layer. With $L=6$ and $N=96$, this is computationally heavier than standard NeRF's MLP evaluation per point, but avoids the iterative alpha-compositing loop of VR [S1].
*   **Memory Complexity:** Stores $N$ volume embeddings and $L$ transformer states. The Learnable Embeddings add $K \times D$ memory [S1].
*   **Measured Performance:** On the Blender dataset, ABLE-NeRF achieves SOTA results, surpassing Ref-NeRF in PSNR, SSIM, and LPIPS [S1].
*   **Strengths:** Handles glossy and translucent objects better than standard NeRF and Ref-NeRF. Does not require normal prediction, avoiding ill-posed interior normal estimation [S1].
*   **Limitations:** Requires careful masking to prevent bi-directional ray issues. The attention mechanism may be slower to train than simple MLPs [S1].
*   **When to use:** When rendering scenes with significant specular highlights, glossy surfaces, or translucency where standard NeRF fails [S1].
*   **When not to use:** For simple diffuse scenes where standard NeRF is sufficient and faster [S1].

## Background
Attention-Based Volumetric Rendering, specifically implemented as ABLE-NeRF, was introduced by Zhe Jun Tang, Tat-Jen Cham, and Haiyu Zhao in the paper "ABLE-NeRF: Attention-Based Rendering with Learnable Embeddings for Neural Radiance Field" (arXiv:2303.13817v1, March 2023) [S1]. The method was developed to address the "Achilles' heel" of NeRF: its difficulty in rendering view-dependent effects like glossy and transparent surfaces, which often appear murky [S1]. It draws inspiration from modern game engines' use of light probes for caching indirect lighting [S1].
