# SUDS
Also called: SUDS, Scalable Urban Dynamic Scenes

## Overview
SUDS is a 4D radiance field representation designed for large-scale dynamic urban scenes that factorizes the scene into three separate hash table data structures to efficiently encode static, dynamic, and far-field radiance fields [S1]. It enables free-viewpoint rendering, semantic decomposition, and 3D scene flow estimation at arbitrary poses and time steps using multiple video inputs without requiring supervised 3D annotations like bounding boxes or segmentation masks [S1]. Unlike standard NeRF architectures that use a single MLP, SUDS employs a multi-resolution hash table encoding with a three-branch decomposition to handle scale and dynamism simultaneously [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ordered RGB images from $N$ videos ($vid \in \{1, \dots, N\}$), associated camera poses, aligned sparse LiDAR depth measurements, 2D self-supervised DINO descriptors, and 2D optical flow predictions [S1].
*   **Query:** A 4D coordinate tuple $(\mathbf{x}, \mathbf{d}, t, vid)$, where $\mathbf{x} \in \mathbb{R}^3$ is position, $\mathbf{d} \in \mathbb{R}^3$ is viewing direction, $t$ is frame index, and $vid$ is video ID [S1].
*   **Outputs:** Per-branch color, density, semantic features, and scene flow vectors, blended into final radiance and density for volume rendering [S1].

**Data Structures:**
The scene is decomposed into $K$ spatial cells with centroids $\mathbf{k} \in \mathbb{R}^3$. Each cell contains three independent multi-resolution hash table branches: Static, Dynamic, and Far-field [S1].
*   **Hash Tables:** Each branch uses a hierarchy of $L$ resolution levels, where resolution doubles between levels [S1].
*   **Feature Vectors:** Each hash table entry stores a feature vector of dimensionality $F$ [S1].
*   **Hash Functions:**
    *   Static: $i_{l,s} = \text{static hash}(\text{space}(\mathbf{v}_{l,s}))$ [S1].
    *   Dynamic: $i_{l,d} = \text{dynamic hash}(\text{space}(\mathbf{v}_{l,d}), \text{time}(\mathbf{v}_{l,d}), vid)$ [S1].
    *   Far-field: $i_{l,e} = \text{env hash}(\text{dir}(\mathbf{v}_{l,e}), vid)$ [S1].
    *   Hash collisions are handled via gradient averaging [S1].

**Numbered Steps:**

1.  **Spatial Partitioning:** Split the scene into $K$ spatial cells. Generate training datasets for each cell by including only datapoints whose camera rays intersect the cell. Prune irrelevant rays using LiDAR depth measurements to ensure visibility [S1].
2.  **Voxel Lookup:** For input $(\mathbf{x}, \mathbf{d}, t, vid)$, find surrounding voxels $\mathbf{v}_{l,s}, \mathbf{v}_{l,d}, \mathbf{v}_{l,e}$ at each of the $L$ resolution levels for the static, dynamic, and far-field branches respectively [S1].
3.  **Hash Indexing:** Compute hash indices for the corners of each voxel using the specific hash functions defined above. The dynamic and far-field hashes incorporate $vid$ to index separate interpolating functions per video without linear memory growth [S1].
4.  **Feature Interpolation:**
    *   Look up feature vectors corresponding to the hashed corners.
    *   Perform linear interpolation for the static branch.
    *   Perform quadlinear interpolation for the dynamic 4D branch [S1].
    *   Concatenate results from all $L$ levels into a feature vector $\mathbf{f} \in \mathbb{R}^{LF}$ [S1].
5.  **MLP Evaluation:** Pass $\mathbf{f}$ concatenated with auxiliary inputs (viewing direction $\mathbf{d}$, video-specific lighting embedding) into separate small MLPs for each branch to obtain outputs [S1].
    *   **Static Branch:** Outputs view-dependent color $\mathbf{c}_s(\mathbf{x}, \mathbf{d}, \mathbf{A}_{vid}\mathbf{F}(t)) \in \mathbb{R}^3$ and view-independent density $\sigma_s(\mathbf{x}) \in \mathbb{R}$ [S1]. Lighting is conditioned via $\mathbf{A}_{vid}\mathbf{F}(t)$, where $\mathbf{A}_{vid}$ is a video-specific matrix and $\mathbf{F}(t)$ is a Fourier-encoded time index [S1].
    *   **Dynamic Branch:** Outputs time/video-dependent density $\sigma_d(\mathbf{x}, t, vid) \in \mathbb{R}$, color $\mathbf{c}_d(\mathbf{x}, t, vid, \mathbf{d}) \in \mathbb{R}^3$, scalar shadow ratio $\rho_d(\mathbf{x}, t, vid) \in [0, 1]$, and forward/backward 3D scene flow vectors $\mathbf{s}_{t0}(\mathbf{x}, t, vid) \in \mathbb{R}^3$ with values in $[-1, 1]$ [S1].
    *   **Far-field Branch:** Outputs environment map color $\mathbf{c}_e(\mathbf{d}, vid) \in \mathbb{R}^3$ [S1].
    *   **Semantic Heads:** Each branch outputs $C$-dimensional semantic feature vectors $\Phi_s(\mathbf{x})$, $\Phi_d(\mathbf{x}, t, vid)$, and $\Phi_e(\mathbf{d}, vid)$ to distill DINO features [S1].
6.  **Density Combination:** Compute total density as the sum of static and dynamic densities:
    $$ \sigma(\mathbf{x}, t, vid) = \sigma_s(\mathbf{x}) + \sigma_d(\mathbf{x}, t, vid) $$
    [S1]
7.  **Radiance Combination:** Compute total radiance by blending static and dynamic components, scaled by the shadow ratio:
    $$ \mathbf{c}(\mathbf{x}, t, vid, \mathbf{d}) = \frac{(1 - \rho_d)\sigma_s \mathbf{c}_s + \sigma_d \mathbf{c}_d}{\sigma} $$
    [S1]
8.  **Volume Rendering:** Render color $\hat{C}(\mathbf{r}, t, vid)$ along ray $\mathbf{r}$:
    $$ \hat{C}(\mathbf{r}, t, vid) = \int_0^{+\infty} T(t) \sigma(\mathbf{r}(t), t, vid) \mathbf{c}(\mathbf{r}(t), t, vid, \mathbf{d}) dt + T(+\infty)\mathbf{c}_e(\mathbf{d}, vid) $$
    where $T(t) = \exp\left(-\int_0^t \sigma(\mathbf{r}(s), t, vid) ds\right)$ [S1].
    Semantic features $\hat{F}(\mathbf{r})$ are rendered similarly using the weighted sum of branch features [S1].

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** Handled via gradient averaging [S1].
*   **Visibility:** Pruning rays using LiDAR depth is critical to avoid including occluded data in spatial cells [S1].
*   **Lighting Variations:** Modeled via video-specific matrices $\mathbf{A}_{vid}$ and Fourier-encoded time to handle dramatic changes across videos while maintaining smoothness within a video [S1].
*   **Shadow Over-explanation:** Penalized by squared magnitude of shadow ratio $\rho_d$ to prevent it from explaining dark regions incorrectly [S1].

## Operating characteristics
*   **Scale:** Scales to tens of thousands of objects across 1.2 million frames from 1,700 videos spanning hundreds of kilometers [S1].
*   **Training Speed:** 10x quicker to train than state-of-the-art methods relying on ground truth 3D bounding box annotations [S1].
*   **Memory:** Uses multi-resolution hash tables, avoiding the linear memory growth of per-object NeRFs (e.g., NSG requires >1TB for 30s video) [S1].
*   **Strengths:** Handles ego-motion, multi-video representations, and large-scale urban scenes without supervised 3D labels [S1].
*   **Limitations:** Relies on self-supervised 2D descriptors and optical flow, which may be less robust than explicit 3D supervision in highly ambiguous regions [S1].

## Background
SUDS (Scalable Urban Dynamic Scenes) was introduced to address the limitations of prior dynamic scene representations that required supervised inputs like panoptic segmentation labels or bounding boxes, which are difficult to acquire for in-the-wild captures [S1]. It builds on Instant-NGP's multi-resolution hash tables and extends them to support 4D spacetime and multi-video indexing [S1]. It is used for free-viewpoint synthesis of dynamic urban scenes, unsupervised 3D instance segmentation, and 3D cuboid detection [S1].
