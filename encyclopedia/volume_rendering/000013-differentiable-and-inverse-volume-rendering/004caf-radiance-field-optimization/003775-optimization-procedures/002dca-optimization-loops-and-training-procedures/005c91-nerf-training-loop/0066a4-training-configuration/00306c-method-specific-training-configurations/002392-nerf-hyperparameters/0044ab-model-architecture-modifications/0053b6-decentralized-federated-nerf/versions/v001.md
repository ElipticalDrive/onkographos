# Decentralized Federated NeRF

Also called: DecentNeRF, Decentralized Neural Radiance Fields from Crowdsourced Images

## Overview
Decentralized Federated NeRF (DecentNeRF) is a framework for learning global 3D scene representations from crowd-sourced images by distributing training computation to users and aggregating only global radiance field models to minimize server compute and personal data leakage [S1]. It solves the problem of achieving photorealistic 3D reconstruction of global scene content while preventing the server from reconstructing transient personal content (e.g., users, objects) present in crowdsourced images taken at different times [S1]. Unlike centralized approaches like NeRF-W which require all personal user images to be transferred to a central server, or existing federated learning NeRF techniques which assume static scenes devoid of personal information, DecentNeRF handles personal content and uses secure aggregation [S1]. It differs from siblings like [DoF-NeRF](9432-dof-nerf.md) and [NeRF-VPT](11770-nerf-vpt.md) by explicitly decomposing the scene into global and personal radiance fields per user and employing a learned weighted aggregation protocol with Secure Multi-Party Computation (SMPC) [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $K$ users, each possessing a local dataset of images $\mathcal{I}_k$ with known camera poses (pitch $\theta$, yaw $\phi$) and 3D coordinates. The system assumes known, accurate camera poses derived via Structure from Motion (SfM) [S1].
*   **Outputs:** A globally aggregated global MLP weights $\mathbf{G}$, and locally maintained personal MLP weights $\mathbf{P}_k$ for each user.

**Data Structures:**
Each user $k$ maintains two Multi-Layer Perceptrons (MLPs):
1.  **Global MLP:** Weights $\mathbf{g}_k$. Captures shared global content (static across users).
2.  **Personal MLP:** Weights $\mathbf{p}_k$. Captures user-specific transient content (dynamic across users).

Both MLPs follow the standard NeRF backbone [S6]:
*   **Input:** 5D vector consisting of 3D spatial coordinate $\mathbf{x} = (x, y, z)$ and viewing direction parameters pitch $\theta$ and yaw $\phi$.
*   **Output:** Scalar density $\sigma$ and RGB color vector $\mathbf{c} = (r, g, b)$.

**Parameters:**
*   $\alpha_k$: A per-user weighting factor applied to local weights/gradients during obfuscation and aggregation. It is learned via gradient descent to maximize visual fidelity, implicitly handling user importance (e.g., based on occlusion levels) [S1].
*   $L_k$: The loss function for user $k$, typically comparing predicted color with ground truth RGB [S1].

**Algorithm Steps:**

1.  **Initialization:** Randomly initialize global MLP weights $\mathbf{G}^{(0)}$ and personal MLP weights $\mathbf{P}^{(0)}$ at all $K$ users [S1].
2.  **Local Training (User Side):** For each training round $m$:
    a.  User $k$ trains their local Global MLP ($\mathbf{g}_k$) and Personal MLP ($\mathbf{p}_k$) on their local images $\mathcal{I}_k$.
    b.  The rendered image is an alpha-composite of the output images from both the global and personal MLPs [S1].
    c.  Compute the loss $L_k$ and gradients $\frac{\partial L_k}{\partial \mathbf{g}_k^{(m-1)}}$ for the global MLP [S1].
    d.  Update the per-user weight $\alpha_k$ using the gradient update step derived from the optimization objective (Equation 2 in source) [S1].
3.  **Obfuscation (User Side):**
    a.  **Weight Obfuscation (`send_wts`):** User $k$ obfuscates local global weights $\mathbf{g}_k^{(m)}$ by multiplying with $\alpha_k$ and applying a random mask or encrypting with additively homomorphic encryption [S1].
    b.  **Gradient Obfuscation (`send_grads`):** User $k$ obfuscates the gradients $\frac{\partial L_k}{\partial \mathbf{g}^{(m-1)}}$ similarly to weight obfuscation [S1].
4.  **Secure Aggregation (Server Side):**
    a.  The server receives obfuscated weights and gradients from all users.
    b.  Using a Secure Multi-Party Computation (SMPC) protocol (e.g., SecAgg [4]), the server computes the weighted average of the obfuscated weights $\mathbf{g}^{(m)}$ [S1].
    c.  The server securely aggregates the previous rounds' gradients [S1].
    d.  The server distributes the updated global MLP back to each user [S1].
5.  **Update (User Side):**
    a.  User $k$ receives the aggregated global weights.
    b.  User $k$ updates their local global MLP weights $\mathbf{g}_k$ using the aggregated weights and their local gradients [S1].

**Edge Cases and Pitfalls:**
*   **Initial Rounds:** During initial rounds, users' global MLPs contain personal content. Standard federated averaging would allow the server to reconstruct this personal content. DecentNeRF uses SMPC and learned weighting to minimize this leakage, but some leakage persists initially [S1].
*   **No Overlap:** If two users have no overlapping views (entirely separate scene areas), the server's ability to reconstruct personal content increases considerably [S1].
*   **View Overlap Assumption:** The method assumes sufficient overlap in views such that no single user has views that don't overlap with another user [S1].
*   **Threat Model:** The server is honest-but-curious. Users are untrusted from the server's perspective, but no collusion between users is assumed [S1].

## Operating characteristics
*   **Server Compute:** DecentNeRF requires $\sim 10^4$ times less server computing for a scene than a centralized approach [S1].
*   **FLOPs:** DecentNeRF uses $\sim 0.6$B FLOPs for synthetic data and $\approx 5$B FLOPs for the Phototourism dataset, compared to $\sim 200$T FLOPs for NeRF-W and $\sim 5$B FLOPs for FedNeRF (context-dependent) [S1].
*   **Performance (Phototourism):** On the Phototourism dataset, DecentNeRF achieves PSNR 24.62, SSIM 0.8802, LPIPS 0.2571 [S1].
*   **Personal Content Leakage:** Personal content reconstruction by the server is reduced by 10 dB compared to FedNeRF [S1]. In the first round, server-rendered global image PSNR is 14.2 dB and personal content PSNR is 14.9 dB. In the final round, global image PSNR is 27.2 dB and personal content PSNR is 9.3 dB [S1].
*   **Strengths:** Photorealistic global reconstruction, minimal server compute, privacy-preserving (prevents personal content reconstruction).
*   **Limitations:** Requires known camera poses, assumes sufficient view overlap, initial rounds may leak personal content (mitigated by SMPC).

## Background
DecentNeRF was introduced by Z. Tasneem et al. in the paper "DecentNeRFs: Decentralized Neural Radiance Fields from Crowdsourced Images" [S1]. It is the first work to analyze the decentralization aspects of radiance fields for real-world crowd-sourced images, addressing the limitations of NeRF-W (which requires central server access to personal images) and existing federated learning NeRF techniques (which assume static scenes) [S1]. It builds on the NeRF backbone [S6] and NeRF-W [S20] architectures.
