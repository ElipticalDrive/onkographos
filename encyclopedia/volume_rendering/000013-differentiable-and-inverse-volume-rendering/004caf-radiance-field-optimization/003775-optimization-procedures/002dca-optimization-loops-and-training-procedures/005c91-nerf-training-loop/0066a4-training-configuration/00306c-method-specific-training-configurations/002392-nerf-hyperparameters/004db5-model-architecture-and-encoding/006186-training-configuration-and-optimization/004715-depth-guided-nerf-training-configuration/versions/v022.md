# Depth-Guided NeRF Training Configuration

Also called: Depth-Guided NeRF Training

## Overview
This configuration defines the hyperparameters, architectural modifications, and optimization settings for training a Neural Radiance Field (NeRF) model using depth priors to regularize the learning process [S1]. It builds on [Model Architecture and Encoding](13550-model-architecture-and-encoding.md) by introducing specific dropout layers and a depth-aware loss term. It differs from standard NeRF training by explicitly incorporating depth supervision via an Earth Mover’s Distance (EMD) or similar depth loss, requiring specific weight decay and learning rate schedules to handle the multi-task optimization [S1].

## How it works
**Inputs:**
*   Training images with known camera poses.
*   Ground truth depth maps for the training views (optional but typical for this configuration).
*   Scene-specific depth bounds ($min\_depth$, $max\_depth$).

**Outputs:**
*   Trained NeRF model parameters (MLP weights).

**Data Structures:**
*   **MLP Architecture:** Builds on the standard NeRF MLP. The first eight fully connected layers (after positional encoding) are modified to include dropout.
*   **Optimizer State:** Adam optimizer state variables (first and second moment estimates).

**Parameters:**
*   Dropout probability ($p_{drop}$): 0.1 [S1].
*   Depth loss weight ($\lambda$): 0.007 for most scenes; 0.02 for scene 710 [S1].
*   Uncertainty weight ($\gamma$): 1 [S1].
*   Initial learning rate ($lr$): $5 \times 10^{-4}$ [S1].
*   Reduced learning rate: $5 \times 10^{-5}$ [S1].
*   Weight decay ($wd$): $1 \times 10^{-6}$ [S1].
*   Depth scale learning rate: $1 \times 10^{-7}$ [S1].
*   Total training steps: 500,000 [S1].
*   Threshold for depth uncertainty evaluation ($\tau$): Calculated as $\tau = (max\_depth - min\_depth) \cdot 0.0001$ [S1]. For ScanNet, $max\_depth = 10$ and $min\_depth = 0.001$ [S1].

**Numbered Steps:**
1.  **Initialize Model:** Construct the NeRF MLP as defined in [Model Architecture and Encoding](13550-model-architecture-and-encoding.md).
2.  **Apply Dropout:** Insert dropout layers with probability $p_{drop} = 0.1$ after each of the first eight fully connected ReLU-activated layers that encode the positional encoding [S1].
3.  **Initialize Optimizer:** Configure Adam optimizer with initial learning rate $lr = 5 \times 10^{-4}$ and weight decay $wd = 1 \times 10^{-6}$ [S1].
4.  **Compute Depth Threshold:** For the current scene, determine $min\_depth$ and $max\_depth$. Calculate $\tau = (max\_depth - min\_depth) \cdot 0.0001$ [S1].
5.  **Training Loop (for step $t$ from 1 to 500,000):**
    a. Sample rays and compute volume rendering outputs (density $\sigma$, color $\mathbf{c}$) using the current network state.
    b. Render depth maps from the predicted density distribution.
    c. Compute photometric loss against ground truth images.
    d. Compute depth loss against ground truth depth maps. The depth loss weight is $\lambda = 0.007$ (or 0.02 for scene 710) [S1].
    e. If uncertainty weighting is used, incorporate $\gamma = 1$ into the loss calculation [S1].
    f. Compute total loss: $L_{total} = L_{photo} + \lambda L_{depth} + \gamma L_{uncertainty}$ (if applicable) [S1].
    g. Backpropagate and update weights using Adam.
    h. **Learning Rate Schedule:** If $t > 0.8 \times 500,000$, reduce the learning rate to $5 \times 10^{-5}$ [S1].
    i. **Depth Scale LR:** If optimizing a depth scale parameter, use a separate learning rate of $1 \times 10^{-7}$ [S1].
6.  **Evaluation:** Compute metrics such as RMSE, RMSE log, AbsRel, and SqRel using the threshold $\tau$ to filter invalid depth pixels [S1].

**Pseudocode:**
```python
def train_depth_guided_nerf(training_data, scene_config):
    # 1. Initialize Model with Dropout
    model = NeRFMLP()
    # Add dropout after first 8 FC layers
    for i, layer in enumerate(model.first_eight_fc_layers):
        layer.add_dropout(p=0.1)
    
    # 2. Initialize Optimizer
    optimizer = Adam(
        params=model.parameters(),
        lr=5e-4,
        weight_decay=1e-6
    )
    
    # 3. Scene-specific parameters
    min_depth = scene_config.min_depth  # e.g., 0.001 for ScanNet
    max_depth = scene_config.max_depth  # e.g., 10 for ScanNet
    tau = (max_depth - min_depth) * 0.0001
    lambda_depth = 0.02 if scene_config.scene_id == 710 else 0.007
    gamma_uncertainty = 1
    
    total_steps = 500000
    step_threshold = 0.8 * total_steps
    
    for step in range(1, total_steps + 1):
        # 4. Forward Pass
        rays = sample_rays(training_data)
        sigma, color = model(rays)
        
        # 5. Render Depth and Color
        rendered_color = volume_render_color(sigma, color, rays)
        rendered_depth = volume_render_depth(sigma, rays)
        
        # 6. Compute Losses
        loss_photo = compute_photometric_loss(rendered_color, training_data.gt_images)
        loss_depth = compute_depth_loss(rendered_depth, training_data.gt_depths, tau)
        
        # Note: Specific EMD or L1/L2 formulation for loss_depth depends on implementation,
        # but weight is lambda_depth [S1].
        loss = loss_photo + lambda_depth * loss_depth
        
        # Optional: Add uncertainty loss if implemented
        # loss += gamma_uncertainty * loss_uncertainty
        
        # 7. Backward Pass
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 8. Learning Rate Schedule
        if step > step_threshold:
            for param_group in optimizer.param_groups:
                param_group['lr'] = 5e-5
                
        # 9. Depth Scale LR (if applicable)
        # If a separate depth scale parameter exists, it should be updated with lr=1e-7
        # This requires separate parameter groups in the optimizer
        
    return model
```

**Edge Cases and Pitfalls:**
*   **Scene 710:** Requires a higher depth loss weight ($\lambda = 0.02$) compared to other scenes ($\lambda = 0.007$) [S1].
*   **Depth Threshold:** The threshold $\tau$ is critical for evaluating depth uncertainty and filtering invalid pixels. It is scene-dependent [S1].
*   **Reproducibility:** Some configurations (like those in DS-NeRF) may require specific tricks to prevent overfitting, such as reducing positional encoding frequency, if official config files are missing [S2].

## Subtopics

### DS-NeRF Depth Loss Integration
Integrates the depth loss from the official DS-NeRF code base into the training pipeline [S2]. Due to missing configuration files for DTU in the official release, results were re-trained on LLFF train/test splits using released configuration files, as original LLFF results used a different split [S2].

## Operating characteristics
*   **Time Complexity:** Standard NeRF training complexity, scaled by 500,000 steps [S1].
*   **Memory Complexity:** Standard NeRF memory usage plus storage for depth maps and optimizer states [S1].
*   **Strengths:** Improves geometric accuracy by leveraging depth priors [S1].
*   **Limitations:** Requires ground truth depth maps for training [S1]. Performance may vary if depth thresholds are not tuned correctly [S1].
*   **When to use:** When depth supervision is available and geometric fidelity is prioritized over pure photometric reconstruction [S1].

## Background
Originated from the "Depth-Guided NeRF Training via Earth Mover’s Distance" paper [S1]. The configuration was developed to address the lack of geometric constraints in standard NeRF training by incorporating depth information [S1]. It builds on the original NeRF architecture [S1].
