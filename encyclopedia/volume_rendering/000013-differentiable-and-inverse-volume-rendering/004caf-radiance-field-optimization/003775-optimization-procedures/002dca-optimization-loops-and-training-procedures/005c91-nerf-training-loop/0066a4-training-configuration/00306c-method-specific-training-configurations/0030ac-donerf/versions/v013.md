# DONeRF

Also called: Depth Oracle Neural Radiance Fields, DONeRF Training Configuration, DONeRF training setup, Depth Oracle Network, DoNeRF

## Overview
DONeRF is a compact neural rendering method that replaces the standard NeRF raymarching scheme with a two-network architecture: a **depth oracle network** to predict sample locations and a **shading network** to compute color and density for those samples [S3]. It solves the prohibitive computational cost of dense sampling in NeRF by reducing the number of samples per ray from hundreds to as few as 2–4, enabling real-time rendering on consumer GPUs [S3]. Unlike standard NeRF which uses uniform or importance sampling, DONeRF uses a classification-based oracle to guide sampling, achieving higher quality and up to 48× faster inference than NeRF without requiring explicit acceleration structures or large memory footprints [S3].

## How it works
DONeRF operates in a two-stage pipeline: training the depth oracle to predict sample positions, then training the shading network to render using those positions. The method relies on "view cells" (bounding boxes with orientation limits) to unify ray inputs [S3].

### Inputs and Outputs
*   **Inputs:**
    *   Training images: RGBD pairs (color and depth) sampled from a view cell [S3].
    *   Ray parameters: Origin $\mathbf{x} \in \mathbb{R}^3$ and direction $\mathbf{d} \in S^2$ [S1].
*   **Outputs:**
    *   Rendered RGB color $\mathbf{c} \in \mathbb{R}^3$ and accumulated opacity for each pixel [S3].

### Data Structures
*   **View Cell:** A bounding box defining the spatial extent and viewing angle limits for a subset of the scene. Rays are transformed into this unified space [S3].
*   **Depth Oracle Network:** An 8-layer MLP with 256 hidden units per layer, ReLU activations, and no positional encoding. Input is concatenated $\mathbf{x}$ and $\mathbf{d}$ [S1].
*   **Shading Network:** An 8-layer MLP with 256 hidden units per layer. Input $\mathbf{x}$ and $\mathbf{d}$ are processed with positional encoding (PE). $\gamma(\mathbf{x})$ (63-dim) is used at the first layer; $\gamma(\mathbf{d})$ (27-dim) is concatenated before the last layer [S1].
*   **Sample Indices:** The oracle outputs a set of indices (or probabilities) corresponding to discretized depth bins along the ray [S3].

### Numbered Steps

1.  **View Cell Definition and Ray Unification:**
    *   Define a view cell (bounding box + max viewing angle) [S3].
    *   Transform ray origins and directions into the view cell's local coordinate system to reduce input ambiguity [S3].

2.  **Depth Oracle Training (Stage 1):**
    *   **Task:** The oracle learns a classification task, not direct depth regression. It predicts which discretized depth bins contain surface samples [S3].
    *   **Input Processing:** Concatenate unified position $\mathbf{x}$ and direction $\mathbf{d}$. No positional encoding is applied [S1].
    *   **Forward Pass:** Pass through the 8-layer MLP (256 units, ReLU) to output logits for depth bins [S1].
    *   **Loss:** Binary Cross-Entropy (BCE) loss between predicted bin probabilities and ground truth depth bins [S3].
    *   **Training:** Train for 300,000 iterations using Adam (LR=0.0005, batch size=4096) [S3].

3.  **Shading Network Sampling (Stage 2):**
    *   **Oracle Inference:** For each ray, the trained oracle predicts sample locations. Let $N_s$ be the number of selected samples (e.g., 2, 4, 8, 16) [S3].
    *   **Logarithmic Warping:** Transform the selected sample depths logarithmically and warp them towards the view cell to better capture high-frequency foreground details [S3].
    *   **Sample Generation:** Generate $N_s$ 3D points along the ray based on the oracle's predictions [S3].

4.  **Shading Network Forward Pass:**
    *   **Encoding:** Apply PE to the warped 3D points $\mathbf{x}$ and directions $\mathbf{d}$ to get $\gamma(\mathbf{x})$ and $\gamma(\mathbf{d})$ [S1].
    *   **Network:** Pass encoded features through the shading MLP.
    *   **Output:** Predict RGB color $\mathbf{c}$ and volume density $\sigma$ for each of the $N_s$ samples [S1].

5.  **Volume Rendering:**
    *   Compute accumulated color using standard volume rendering integral with the $N_s$ samples:
        $$ \hat{C}(\mathbf{r}) = \sum_{i=1}^{N_s} T_i \alpha_i \mathbf{c}_i $$
        where $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$ and $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$ [S3].

6.  **Loss Computation:**
    *   **MSE Loss:** Standard Mean Squared Error between rendered color $\hat{C}$ and ground truth RGB [S3].
    *   **Opacity Loss ($\text{loss}_O$):** Prevents "dark pixel" artifacts by forcing accumulated opacity to be at least 1 for opaque surfaces:
        $$ \text{loss}_O = \begin{cases} 0, & \text{if } \sum_{i=1}^{N_s} \delta_i \geq 1 \\ \left( \left( \sum_{i=1}^{N_s} \delta_i \right) - 1 \right)^2, & \text{otherwise} \end{cases} $$
        where $\delta_i$ is the transmittance contribution or distance-weighted opacity term ensuring accumulation [S3].
    *   **Total Loss:**
        $$ \text{loss} = \alpha \cdot \text{loss}_{\text{MSE}} + \beta \cdot \text{loss}_O $$
        with $\alpha = 1.0$ and $\beta = 10.0$ [S3].

7.  **Shading Network Training (Stage 2):**
    *   **Initialization:** Use the frozen depth oracle from Stage 1 to generate samples [S3].
    *   **Optimization:** Train the shading network for 300,000 iterations using Adam (LR=0.0005, batch size=4096) [S3].
    *   **Note:** The architecture is not end-to-end trainable; the oracle must be trained first [S2].

### Pseudocode

```python
def train_donorf(dataset, config):
    # Configuration
    # K=5, Z=5, I=128 for oracle (discretization params)
    # Ns = number of samples per ray (e.g., 4)
    # View cell defined by bounding box and angles
    
    # Stage 1: Train Depth Oracle
    oracle = DepthOracleMLP(layers=8, hidden=256, use_pe=False)
    optimizer_oracle = Adam(oracle.parameters(), lr=0.0005, batch_size=4096)
    
    for iteration in range(300000):
        # 1. Ray Unification
        rays = get_rays_from_view_cell(dataset.poses, dataset.view_cell)
        
        # 2. Discretize Ground Truth Depth
        # Map GT depth to discrete bins based on K, Z, I parameters
        gt_bins = discretize_depth(rays.depth, config.K, config.Z, config.I)
        
        # 3. Oracle Forward Pass
        # Input: x (unified), d (unified). No PE.
        logits = oracle(rays.origin, rays.direction)
        
        # 4. Loss: BCE
        loss = BCE_loss(logits, gt_bins)
        
        # 5. Update
        optimizer_oracle.zero_grad()
        loss.backward()
        optimizer_oracle.step()

    # Stage 2: Train Shading Network
    shading = ShadingMLP(layers=8, hidden=256, use_pe=True)
    optimizer_shading = Adam(shading.parameters(), lr=0.0005, batch_size=4096)
    
    for iteration in range(300000):
        # 1. Ray Unification
        rays = get_rays_from_view_cell(dataset.poses, dataset.view_cell)
        
        # 2. Oracle Inference for Sampling
        # Get sample indices/locations from oracle
        sample_depths = oracle_get_samples(rays.origin, rays.direction, oracle, config.Ns)
        
        # 3. Logarithmic Warping
        # Warp sample depths towards view cell
        warped_samples = warp_samples(sample_depths, dataset.view_cell)
        
        # 4. Shading Network Forward Pass
        # Input: warped_samples, rays.direction
        # PE applied: gamma(x) at first layer, gamma(d) before last
        rgb, sigma = shading(warped_samples, rays.direction)
        
        # 5. Volume Rendering
        # Accumulate color with Ns samples
        rendered_color = volume_render(warped_samples, sigma, rgb)
        
        # 6. Loss Computation
        mse_loss = MSE_loss(rendered_color, dataset.rgb)
        
        # Opacity Loss: Force accumulated opacity >= 1
        accumulated_opacity = compute_accumulated_opacity(sigma, warped_samples)
        opacity_loss = 0.0
        if accumulated_opacity < 1.0:
            opacity_loss = (accumulated_opacity - 1.0)**2
            
        total_loss = 1.0 * mse_loss + 10.0 * opacity_loss
        
        # 7. Update
        optimizer_shading.zero_grad()
        total_loss.backward()
        optimizer_shading.step()
```

### Edge Cases and Pitfalls
*   **Dark Pixel Artifacts:** With low sample counts ($N_s < 8$), rays may fail to accumulate to opacity 1, causing darkening. This is mitigated by the opacity loss term ($\beta=10.0$) [S3].
*   **Non-End-to-End Training:** The method requires sequential training. The oracle must be fully trained before the shading network begins. Joint training is not supported [S2].
*   **Reflective/Transparent Surfaces:** Single depth estimates from the oracle are insufficient for mirrors or refractive surfaces, leading to artifacts. NeRF's dense sampling handles these better [S3].
*   **No Ground Truth Depth:** If GT depth is unavailable, a dense NeRF (12 layers, 512 units, 128 samples) must be trained first to extract depth maps, which are then used to train the oracle. This results in ~1 dB PSNR loss [S3].
*   **Background Noise:** In no-GT training, NeRF may output high-frequency depth in the background, creating zero-contribution samples. Background detection during oracle training is recommended [S3].

## Operating characteristics
*   **Time Complexity:** Inference cost is approximately 4.35 MFLOP per pixel [S3]. Shading network cost scales nearly linearly with sample count $N_s$ (e.g., 34.9 ms for 2 samples, 270.4 ms for 16 samples on RTX 3090 at 800x800) [S3].
*   **Memory Complexity:** Compact. Uses only two MLPs (approx. 4 MB total), similar to NeRF. Does not require explicit caching or acceleration structures like NSVF [S3].
*   **Performance:** Renders at ~20 fps (22 ms/frame) on a single GPU (RTX 3090) at 400x400 resolution with 4 samples/ray [S3].
*   **Quality:** Achieves average PSNR of 31.14 dB, outperforming NeRF's 30.52 dB [S3]. At 16 samples, up to 7 dB higher PSNR than NeRF [S3].
*   **Strengths:** Real-time capability, high quality, compact memory footprint, no need for acceleration structures.
*   **Limitations:** Not end-to-end trainable, struggles with reflective/transparent surfaces, requires GT depth or pre-trained NeRF for initialization, sensitive to view cell definition.
*   **When to Use:** Real-time rendering of synthetic scenes with available depth or where pre-training a NeRF is feasible.
*   **When Not to Use:** Scenes with complex reflections/refractions, or when end-to-end differentiability is required.

## Background
DONeRF was introduced by [S3] (2021) to address the computational bottleneck of NeRF in real-time applications. It was developed by researchers from Graz University of Technology and Facebook Reality Labs. The method builds on the idea of using auxiliary networks to guide sampling, replacing NeRF's dense raymarching with a sparse, oracle-guided approach. It is particularly suited for synthetic content where depth maps are available or can be generated.
