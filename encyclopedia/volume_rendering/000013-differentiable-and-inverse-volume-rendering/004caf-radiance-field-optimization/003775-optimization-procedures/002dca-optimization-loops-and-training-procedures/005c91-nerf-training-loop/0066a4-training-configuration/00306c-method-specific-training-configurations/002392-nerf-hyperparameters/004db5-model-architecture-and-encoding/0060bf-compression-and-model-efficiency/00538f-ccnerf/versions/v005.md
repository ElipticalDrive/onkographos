# CCNeRF
Also called: Compressible-Composable NeRF, Rank-residual Decomposition NeRF

## Overview
CCNeRF is a neural field representation that enables efficient compression and composition of 3D scenes by modeling the radiance field as a hybrid tensor rank decomposition without using neural networks for rendering [S1]. Unlike NeRF variants that rely on a shared MLP renderer (e.g., [NSVF](11916-depth-guided-nerf-training-configuration.md) or [TensoRF](13550-model-architecture-and-encoding.md)), CCNeRF allows arbitrary composition of different models by concatenating rank components and dynamic adjustment of model size via rank truncation, achieving near-optimal low-rank approximation without retraining [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 2D images with known camera poses $(o, d)$ and a target rank configuration (ratio of vector-based to matrix-based components).
*   **Output:** A compressed radiance field representation consisting of rank components (factor matrices/vectors) and a weight matrix, capable of rendering colors $\hat{C}(r)$ for any ray $r$ [S1].

**Data Structures:**
The model structure consists of two main parts [S1]:
1.  **Rank Weights Matrix ($W$):** A matrix storing weights for different feature channels. The size is $R_{vec} \times R_{vec} + R_{mat} \times R_{mat}$, where $R_{vec}$ and $R_{mat}$ are the number of vector-based and matrix-based rank components, respectively.
2.  **Rank Components:** A set of decomposed components.
    *   **Vector-based (CP):** Factor vectors $U^x, U^y, U^z$ for spatial dimensions.
    *   **Matrix-based (Triple Plane):** Factor matrices $\mathcal{U}_{y,z}, \mathcal{U}_{x,z}, \mathcal{U}_{x,y}$ representing planes in 3D space.
    *   The ratio of vector- to matrix-based components is controllable to trade off between model size and performance [S1].

**Formulas:**
The volume rendering equation remains standard [S1]:
$$ \hat{C}(r) = \sum_i T_i \alpha_i c_i $$
where $T_i = \prod_{j<i} (1 - \alpha_i)$, $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$, and $\delta_i = t_{i+1} - t_i$. Here $\sigma_i$ is density, $c_i$ is color, and $t_i$ is the sample position along ray $r$ from origin $o$ with direction $d$ [S1].

The core representation uses a hybrid Tucker-like decomposition. For a 3D tensor $T \in \mathbb{R}^{H \times W \times D}$, the decomposition is defined as [S1]:
$$ T_{i,j,k} = \sum_{p=1}^P \sum_{q=1}^Q \sum_{r=1}^R S_{p,q,r} U^x_{i,p} U^y_{j,q} U^z_{k,r} $$
where $S$ is the core tensor and $U^x, U^y, U^z$ are factor matrices. In CCNeRF, this is extended to a hybrid form combining CP (vector) and Triple Plane (matrix) factors [S1].

**Numbered Steps:**
1.  **Initialization:** Initialize the rank components (vectors or matrices) and the weight matrix $W$. The initial decomposition can be obtained via standard tensor decomposition methods (e.g., HOSVD) [S1].
2.  **Rank-Residual Learning:** Train the model using a rank-residual learning strategy. This strategy encourages lower ranks to preserve more important information of the whole scene, ensuring that truncating higher ranks does not significantly degrade quality [S1].
3.  **Querying a 3D Coordinate:** To query a coordinate $\mathbf{x}$:
    a. Project $\mathbf{x}$ to the decomposed vectors or matrices.
    b. Perform weighted interpolation using the stored rank weights $W$ [S1].
4.  **Rendering:** Sample points along rays, query the field for $\sigma$ and $c$, and apply the volume rendering equation [S1].
5.  **Compression (Rank Truncation):** To compress the model:
    a. Sort the rank components based on their contribution (importance).
    b. Truncate the components with the lowest importance to achieve a targeted rank. This is an empirical sort-and-truncate strategy that yields a quasi-optimal low-rank approximation [S1].
6.  **Composition:** To compose different models:
    a. Concatenate the rank components of different objects along the rank dimension.
    b. Record a transformation matrix for each object to control its position and orientation [S1].

**Parameters:**
*   **Rank ($R$):** The number of components kept in the decomposition. Determines model size and detail level. Lower ranks preserve primary information [S1].
*   **Ratio of Vector/Matrix Components:** Controls the trade-off between model size and performance. Vector-based components are more compact, while matrix-based components capture more local structure [S1].

**Edge Cases and Pitfalls:**
*   **Truncated HOSVD:** Standard truncated Higher-Order SVD (HOSVD) does not hold the optimal property of truncated SVD, but yields a quasi-optimal solution sufficient for practical use [S1].
*   **MLP Dependency:** Unlike TensoRF, CCNeRF avoids MLPs in the rendering path to preserve low-rank approximation properties. Introducing MLPs would prevent compression and composition [S1].

**Pseudocode:**
```python
def query_ccnerf(x, rank_components, weights):
    """
    Query the CCNeRF field at coordinate x.
    
    Args:
        x: 3D coordinate (x, y, z)
        rank_components: List of rank components. 
                         Each component is either a set of vectors (CP) or matrices (Triple Plane).
        weights: Weight matrix W for interpolating rank components.
        
    Returns:
        sigma: Volume density
        c: Color vector (r, g, b)
    """
    # Project x to decomposed vectors/matrices
    # For CP components:
    # v_cp = [U^x[:, i] * x[0] + U^y[:, i] * x[1] + U^z[:, i] * x[2] for i in range(R_vec)]
    
    # For Triple Plane components:
    # v_mat = [U_yz[i, x[1], x[2]] + U_xz[i, x[0], x[2]] + U_xy[i, x[0], x[1]] for i in range(R_mat)]
    
    # Combine projections
    projections = v_cp + v_mat
    
    # Weighted interpolation
    # sigma_raw, c_raw = dot(projections, weights)
    
    # Apply activation functions (e.g., ReLU for sigma, Sigmoid for c)
    sigma = relu(sigma_raw)
    c = sigmoid(c_raw)
    
    return sigma, c

def compress_ccnerf(rank_components, weights, target_rank):
    """
    Compress the CCNeRF model by truncating less important rank components.
    
    Args:
        rank_components: Current rank components.
        weights: Current weight matrix.
        target_rank: Desired number of rank components.
        
    Returns:
        compressed_components: Truncated rank components.
        compressed_weights: Truncated weight matrix.
    """
    # Calculate importance of each rank component
    # importance = norm(weights[:, i]) or similar metric
    
    # Sort components by importance
    sorted_indices = argsort(importance, descending=True)
    
    # Truncate to target rank
    selected_indices = sorted_indices[:target_rank]
    
    compressed_components = [rank_components[i] for i in selected_indices]
    compressed_weights = weights[:, selected_indices]
    
    return compressed_components, compressed_weights

def compose_ccnerf(models, transformations):
    """
    Compose multiple CCNeRF models into a single scene.
    
    Args:
        models: List of CCNeRF models (each with rank_components and weights).
        transformations: List of transformation matrices for each model.
        
    Returns:
        composed_model: A single CCNeRF model representing the composed scene.
    """
    # Concatenate rank components along the rank dimension
    all_components = []
    for model in models:
        all_components.append(model.rank_components)
    
    composed_components = concatenate(all_components, axis=0)
    
    # Concatenate weights
    all_weights = [model.weights for model in models]
    composed_weights = concatenate(all_weights, axis=1) # Assuming weights are per-rank
    
    # Store transformations for each object
    composed_model = {
        'rank_components': composed_components,
        'weights': composed_weights,
        'transformations': transformations
    }
    
    return composed_model
```

## Operating characteristics
*   **Time Complexity:** Querying is linear in the number of rank components. Compression is dominated by the sort-and-truncate step, which is efficient. Composition is linear in the number of models and their ranks.
*   **Memory Complexity:** Memory usage is proportional to the sum of the sizes of the rank components and the weight matrix. Compression reduces this by truncating ranks.
*   **Measured Performance:** CCNeRF achieves comparable rendering quality to state-of-the-art methods while enabling extra capabilities of compression and composition [S1].
*   **Strengths:** No neural networks for rendering, allowing arbitrary composition without retraining. Dynamic adjustment of model size via rank truncation without retraining.
*   **Limitations:** Relies on tensor decomposition, which may not capture complex high-frequency details as well as MLP-based methods if the rank is too low. Standard truncated HOSVD is quasi-optimal, not strictly optimal [S1].
*   **When to use:** When compression and composition of 3D scenes are required, and the scene can be well-approximated by a low-rank tensor.
*   **When not to use:** When high-frequency details are critical and cannot be captured by low-rank approximations, or when the scene is highly dynamic and requires frequent retraining.

## Background
CCNeRF was introduced by Jiaxiang Tang, Xiaokang Chen, Jingbo Wang, and Gang Zeng from Peking University and Chinese University of Hong Kong in 2022 [S1]. It addresses the difficulty of manipulating implicit NeRF representations, which are often restricted by shared renderer networks or suffer from large model sizes [S1]. The method is motivated by the low-rank approximation property of the SVD algorithm and proposes a rank-residual learning strategy to encourage the preservation of primary information in lower ranks [S1].
