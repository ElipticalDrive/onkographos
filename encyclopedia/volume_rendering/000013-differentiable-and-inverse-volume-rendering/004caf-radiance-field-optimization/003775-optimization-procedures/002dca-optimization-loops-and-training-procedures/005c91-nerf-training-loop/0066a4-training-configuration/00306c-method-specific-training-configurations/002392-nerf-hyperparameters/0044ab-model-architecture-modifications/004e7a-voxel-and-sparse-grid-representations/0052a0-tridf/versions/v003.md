# TriDF

Also called: Triplane-Accelerated Density Fields

## Overview
TriDF is a hybrid explicit–implicit 3D representation designed for few-shot novel view synthesis, particularly in remote sensing scenes with sparse input views [S1]. It decouples color and volume density to reduce the computational burden on implicit radiance fields, accelerating reconstruction from as few as 3 input views [S1]. Unlike standard triplane methods that struggle with insufficient supervision or joint models that suffer from capacity competition, TriDF uses explicit triplanes for high-frequency color and implicit density fields for geometry, guided by sparse depth from point clouds [S1].

## How it works
**Inputs:** $V$ input images (typically $V=3$) with known camera poses, and their corresponding depth maps or point clouds generated via Structure-from-Motion (SfM) and PatchMatch Stereo (PMS) [S1].
**Outputs:** A rendered image $\hat{C}(r)$ for any novel view ray $r$ [S1].

**Data Structures:**
1.  **Triplane ($P$):** A set of three orthogonal 2D feature planes $P = \{P_{XY}, P_{YZ}, P_{ZX}\}$ [S1]. Each plane $P_{ij}$ is a tensor of size $H \times W \times C$ [S1].
    *   $H, W$: Height and width of the feature maps (Not given in the sources).
    *   $C$: Channel dimension, set to 64 [S1].
2.  **Density MLP:** A Multi-Layer Perceptron (MLP) for predicting volume density [S1].
    *   Architecture: CUTLASS [S1].
    *   Width: 512 [S1].
    *   Depth: 8 layers [S1].
3.  **Color MLP:** A compact MLP for predicting color [S1].
    *   Inputs: Intermediate features $f_{base}$ and spherical harmonic encoded direction [S1].
4.  **Reference Feature Encoder:** A pretrained CNN used to extract features from input images [S1].

**Numbered Steps:**

1.  **Initialization:**
    *   Estimate initial 3D point clouds from training views and poses using COLMAP [S1].
    *   Initialize triplane features $P$ randomly [S1].
    *   Initialize Density MLP and Color MLP weights [S1].

2.  **Ray Sampling:**
    *   For a batch of rays, sample $N$ points along each ray [S1].
    *   Typical configuration: 1024 pixel rays per batch, 128 coarse samples per ray [S1].
    *   Use Nerfacc for efficient empty space skipping [S1].

3.  **Triplane Feature Extraction (Color Branch):**
    *   For a 3D spatial point $\mathbf{x}$, project it orthogonally onto the three planes $P_{XY}, P_{YZ}, P_{ZX}$ [S1].
    *   Identify the four nearest grid points on each plane [S1].
    *   Apply bilinear interpolation to compute feature vectors $f_{XY}, f_{YZ}, f_{ZX}$ [S1].
    *   Concatenate the feature vectors to form the triplane feature vector:
        $$ f_{tri} = \text{concat}(f_{XY}, f_{YZ}, f_{ZX}) $$
        [S1]

4.  **Density Field Extraction (Geometry Branch):**
    *   Extract reference features $f_{ref}$ from input images using the pretrained CNN encoder [S1].
    *   Project reference features to obtain corresponding feature vectors for each sampling point [S1].
    *   Concatenate the projected reference features with positionally encoded coordinates $\mathbf{x}$ [S1].
        *   Positional encoding frequency: 6 [S1].
    *   Process the concatenated vector through the Density MLP to predict volume density $\sigma$ and intermediate features $f_m$ [S1].
        $$ [\sigma, f_m] = \text{DensityMLP}(\text{Concat}(\mathbf{x}_{pe}, f_{ref})) $$
        [S1]

5.  **Color Prediction:**
    *   Combine triplane features $f_{tri}$ and density features $f_m$ using a compact MLP ($\Phi_{base}$) to generate intermediate features $f_{base}$ [S1]:
        $$ f_{base} = \Phi_{base}(f_{tri}, f_m) $$
        [S1]
    *   Encode the viewing direction $\mathbf{d} \in \mathbb{R}^3$ on the spherical harmonics basis $\text{SH}(\cdot)$ [S1].
    *   Map $f_{base}$ and $\text{SH}(\mathbf{d})$ through the Color MLP ($\Phi_{color}$) to determine the point's color $\mathbf{c} \in \mathbb{R}^3$ [S1]:
        $$ \mathbf{c} = \Phi_{color}(f_{base}, \text{SH}(\mathbf{d})) $$
        [S1]

6.  **Volume Rendering:**
    *   Aggregate attributes of sampling points along the ray using differentiable volume rendering [S1].
    *   The numerical quadrature form is:
        $$ \hat{C}(r) = \sum_{i=1}^{N} T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i $$
        $$ T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right) $$
        [S1]
    *   Where $\mathbf{c}_i$ and $\sigma_i$ are color and volume density, $\delta_i$ is the distance between adjacent samples, $N$ is the number of sampling points, and $T_i$ is the accumulated transmittance [S1].

7.  **Optimization:**
    *   Optimize the model through backpropagation [S1].
    *   **Loss Functions:**
        *   Photometric loss between predicted and ground truth colors [S1].
        *   Depth supervision from generated point clouds (first 10k iterations) [S1].
        *   Edge-aware smoothness loss (last 20k iterations) [S1].
    *   **Optimizer:** AdamW with initial learning rate 0.0001 [S1].
    *   **Training Schedule:**
        *   Total iterations: 30k [S1].
        *   First 10k iterations: Depth guidance optimization [S1].
        *   Next 20k iterations: Edge-aware smoothness loss [S1].
        *   For smoothness loss: Process 64 key points and randomly render a $16 \times 16$ patch with stride 4 [S1].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class TriDF:
    def __init__(self, H, W, C=64, density_width=512, density_depth=8, pe_freq=6):
        """
        Initialize TriDF model.
        :param H: Height of triplane feature maps
        :param W: Width of triplane feature maps
        :param C: Channel dimension of triplane feature maps
        :param density_width: Width of Density MLP
        :param density_depth: Depth of Density MLP
        :param pe_freq: Frequency of positional encoding
        """
        self.H = H
        self.W = W
        self.C = C
        
        # Triplane: 3 planes (XY, YZ, ZX), each H x W x C
        # Initialized randomly [S1]
        self.triplane = nn.Parameter(torch.randn(3, C, H, W))
        
        # Density MLP (CUTLASS architecture) [S1]
        # Input: pos_encoded_coords + ref_features
        # Output: sigma, f_m
        density_input_dim = 3 * (2 * pe_freq + 1) + C # Assuming 3D coord PE and C ref features
        self.density_mlp = self._build_mlp(density_input_dim, density_width, density_depth, out_dim=2*C)
        
        # Color MLP (Compact) [S1]
        # Input: f_base (from base_mlp) + SH_encoded_direction
        # Output: color
        # f_base dim is not explicitly given, but derived from f_tri and f_m
        # f_tri dim = 3*C. f_m dim = C (concatenated with f_tri in base_mlp)
        # Let's assume base_mlp outputs a feature vector of dim C_base
        self.base_mlp = self._build_mlp(4*C, 256, 2, out_dim=128) # f_tri(3C) + f_m(C) -> f_base
        self.color_mlp = self._build_mlp(128 + 12, 256, 2, out_dim=3) # f_base + SH(3 bands -> 12 coeffs) -> color
        
        # Pretrained CNN Encoder for reference features [S1]
        # In practice, this would be a loaded model. Here we simulate feature extraction.
        self.encoder = nn.Conv2d(3, C, kernel_size=1) # Simplified encoder for pseudocode
        
        self.pe_freq = pe_freq

    def _build_mlp(self, in_dim, hidden_dim, num_layers, out_dim):
        layers = []
        for _ in range(num_layers):
            layers.append(nn.Linear(in_dim, hidden_dim))
            layers.append(nn.ReLU())
            in_dim = hidden_dim
        layers.append(nn.Linear(hidden_dim, out_dim))
        return nn.Sequential(*layers)

    def positional_encoding(self, x, freq):
        """
        Standard positional encoding for coordinates.
        x: (..., 3)
        """
        # x is already normalized or scaled appropriately in the pipeline
        # PE(x) = [sin(x), cos(x), sin(2x), cos(2x), ..., sin(freq*x), cos(freq*x)]
        # This is a simplified placeholder for the actual PE function used in NeRF
        # In the source, it's concatenated with features.
        # Assuming x is (N, 3)
        x = x.unsqueeze(-1) # (N, 3, 1)
        scales = torch.tensor([2**i for i in range(freq)], device=x.device)
        pe = torch.cat([torch.sin(x * scales), torch.cos(x * scales)], dim=-1) # (N, 3, 2*freq)
        return pe.view(x.size(0), -1) # (N, 3*2*freq)

    def spherical_harmonics(self, d, degree=3):
        """
        Encode viewing direction d using spherical harmonics.
        d: (..., 3)
        Returns: SH coefficients
        """
        # Simplified SH encoding for degree 3 (12 coefficients)
        # x, y, z are components of d
        x, y, z = d[..., 0], d[..., 1], d[..., 2]
        # Basic SH basis functions for degree 3
        sh = torch.stack([
            0.282095,
            0.488603 * y,
            0.488603 * z,
            0.488603 * x,
            1.092548 * x * y,
            -1.092548 * y * z,
            0.315392 * (3 * z**2 - 1),
            -1.092548 * x * z,
            0.546274 * (x**2 - y**2),
            0.590592 * y * (3 * x**2 - y**2),
            2.890611 * x * y * z,
            0.457046 * y * (5 * z**2 - 1)
        ], dim=-1)
        # Broadcast to match input shape
        return sh.unsqueeze(0).expand(d.size(0), -1)

    def get_triplane_features(self, x):
        """
        Extract triplane features for point x.
        x: (N, 3)
        """
        # Project x onto XY, YZ, ZX planes
        # XY plane: use x, y coordinates
        # YZ plane: use y, z coordinates
        # ZX plane: use z, x coordinates
        
        # Normalize coordinates to [-1, 1] for grid sampling if not already done
        # Assuming x is in world space, needs normalization based on scene bounds
        # For pseudocode, assume x is already normalized to [-1, 1]
        
        xy_coords = torch.stack([x[:, 0], x[:, 1]], dim=-1) # (N, 2)
        yz_coords = torch.stack([x[:, 1], x[:, 2]], dim=-1) # (N, 2)
        zx_coords = torch.stack([x[:, 2], x[:, 0]], dim=-1) # (N, 2)
        
        # Bilinear interpolation on triplane
        # triplane shape: (3, C, H, W)
        # grid_sample expects (N, H_out, W_out, 2)
        
        def sample_plane(plane, coords):
            # coords: (N, 2) in [-1, 1]
            # grid_sample input: (N, 1, 1, 2)
            grid = coords.unsqueeze(1).unsqueeze(1)
            features = F.grid_sample(plane.unsqueeze(0), grid, align_corners=True)
            return features.squeeze(-1).squeeze(-1) # (N, C)
        
        f_xy = sample_plane(self.triplane[0], xy_coords)
        f_yz = sample_plane(self.triplane[1], yz_coords)
        f_zx = sample_plane(self.triplane[2], zx_coords)
        
        # Concatenate
        f_tri = torch.cat([f_xy, f_yz, f_zx], dim=-1) # (N, 3*C)
        return f_tri

    def forward(self, x, d, ref_features):
        """
        Forward pass for a batch of points.
        x: (N, 3) spatial coordinates
        d: (N, 3) viewing directions
        ref_features: (N, C) reference features from encoder
        """
        # 1. Triplane Features
        f_tri = self.get_triplane_features(x)
        
        # 2. Density Features
        # Positional encoding of coordinates
        x_pe = self.positional_encoding(x, self.pe_freq)
        
        # Concatenate PE coords and ref features
        density_input = torch.cat([x_pe, ref_features], dim=-1)
        
        # Density MLP
        density_output = self.density_mlp(density_input)
        sigma = density_output[:, :1] # (N, 1)
        f_m = density_output[:, 1:] # (N, C)
        
        # 3. Color Prediction
        # Base MLP: f_tri + f_m -> f_base
        base_input = torch.cat([f_tri, f_m], dim=-1)
        f_base = self.base_mlp(base_input)
        
        # SH Encoding of direction
        sh_d = self.spherical_harmonics(d)
        
        # Color MLP
        color_input = torch.cat([f_base, sh_d], dim=-1)
        color = self.color_mlp(color_input)
        
        return sigma, color

    def render(self, rays, model, encoder, H, W, C, pe_freq):
        """
        Render a batch of rays.
        rays: (B, N_samples, 3) points along rays
        directions: (B, N_samples, 3) viewing directions
        ref_features: (B, N_samples, C) reference features
        """
        sigma, color = model(rays, directions, ref_features)
        
        # Volume Rendering
        # delta: distance between samples
        # T: accumulated transmittance
        # alpha: opacity
        
        # Compute delta
        deltas = torch.diff(rays, dim=-2, prepend=torch.zeros_like(rays[:, :1, :]))
        deltas = torch.norm(deltas, dim=-1, keepdim=True) # (B, N_samples, 1)
        
        # Alpha
        alpha = 1 - torch.exp(-sigma * deltas)
        
        # Transmittance
        # T_i = exp(-sum_{j=1}^{i-1} sigma_j * delta_j)
        # Cumulative product of (1 - alpha)
        transmittance = torch.cumprod(1 - alpha, dim=-2)
        # Shift for T_i (T_1 = 1)
        transmittance = torch.cat([torch.ones_like(transmittance[:, :1, :]), transmittance[:, :-1, :]], dim=-2)
        
        # Weights
        weights = transmittance * alpha
        
        # Color
        color_rendered = torch.sum(weights * color, dim=-2)
        
        return color_rendered
```

## Operating characteristics
*   **Time Complexity:** Training is significantly faster than standard NeRF-based methods. TriDF achieves a 30× speed increase compared to NeRF-based methods [S1].
*   **Memory Complexity:** The triplane representation is compact. The triplane itself takes $3 \times H \times W \times C$ memory. The Density MLP and Color MLP add parameter memory. Total parameters are lower than joint models [S1].
*   **Measured Performance:** On the LEVIRNVS dataset, TriDF achieves a 7.4% increase in PSNR and 3.4% increase in SSIM compared to advanced few-shot methods [S1].
*   **Training Time:** ~5 minutes on a single consumer GPU (Nvidia GeForce RTX 4090) for 10k iterations (TriDF-10k) [S1]. Fully trained model (30k iterations) takes 14 minutes [S1]. Initialization (stereo-matching + point cloud fusion) takes 18 seconds [S1].
*   **Strengths:** Fast convergence due to explicit triplane optimization; handles sparse views (3 images) effectively; avoids overfitting common in few-shot NeRF; no need for extensive pretraining on large multi-view datasets [S1].
*   **Limitations:** Rendering speed lags behind 3DGS-based methods designed for real-time rendering [S1]; relies on accurate initial point clouds from SfM/PMS; performance drops if input views are extremely sparse or have low overlap [S1].
*   **When to use:** Few-shot novel view synthesis in remote sensing scenes where input views are sparse (e.g., 3 views) and computational efficiency is critical [S1].
*   **When not to use:** Dense view synthesis scenarios where triplanes may suffer from redundancy; real-time rendering applications requiring higher frame rates than 3DGS can provide [S1].

## Background
TriDF was proposed to address the challenges of few-shot novel view synthesis in remote sensing, where input views are sparse and traditional NeRF methods overfit or require excessive training time [S1]. It builds on the triplane representation, which is typically used for dense views, and the implicit density fields of NeRF [S1]. The method decouples color and geometry to reduce optimization burden [S1]. It was validated on the LEVIRNVS dataset [S1]. The code is publicly available at https://github.com/kanehub/TriDF [S1].
