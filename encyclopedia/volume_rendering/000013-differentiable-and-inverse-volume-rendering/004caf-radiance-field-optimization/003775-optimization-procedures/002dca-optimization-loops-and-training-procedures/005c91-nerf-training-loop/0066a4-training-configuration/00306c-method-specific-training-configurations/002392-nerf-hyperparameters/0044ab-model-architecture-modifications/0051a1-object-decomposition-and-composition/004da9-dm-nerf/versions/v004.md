# DM-NeRF


## Overview
DM-NeRF is a pipeline that simultaneously reconstructs continuous 3D scene geometry, decomposes all individual objects in 3D space, and supports flexible object shape manipulation (translation, rotation, size adjustment, deformation) from 2D images only [S1, unofficial]. It sets itself apart from standard NeRF by introducing an explicit **object field** that predicts a one-hot object code for every 3D point, enabling instance-level editing without explicit mesh extraction [S1, unofficial]. It builds on [Object Decomposition and Composition](14518-object-decomposition-and-composition.md) by using a learnable object code conditioned on spatial position rather than fixed segmentation masks.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $L$ images for a static scene with known camera poses and intrinsics, denoted as $\{(I_1, \xi_1, K_1) \dots (I_L, \xi_L, K_L)\}$ [S1, unofficial].
*   **Output:** Volume density $\sigma$, object code $\mathbf{o}$, and color $\mathbf{c}$ for any queried 3D point $\mathbf{p}$ and viewing direction $\mathbf{v}$ [S1, unofficial].

**Data Structures:**
*   **Object Code:** A one-hot vector of dimension $H+1$, where $H$ is the predefined number of objects and the extra dimension represents the background/empty space [S1, unofficial].
*   **Ground Truth Labels:** 2D object masks of dimension $T$, where $T$ is the number of ground truth objects [S1, unofficial].
*   **Prediction Tensors:** 2D object prediction images of size $U \times V \times (H+1)$, where $U, V$ are spatial width and height [S1, unofficial].

**Network Architecture:**
The pipeline consists of three components:
1.  **NeRF Backbone:** Learns volume density and appearance.
2.  **Object Field:** Learns a unique object code for every 3D point.
3.  **Object Manipulator:** Edits the shape of specified objects and handles occlusions [S1, unofficial].

The network takes positional encoding $\text{PE}(x,y,z)$ for location and $\text{PE}(\theta,\phi)$ for viewing direction as input. The architecture is an MLP with the following layer dimensions:
$$ 128 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 128 $$
[S1, unofficial]

**Formulas and Definitions:**
*   **Positional Encoding:** $\text{PE}(\cdot)$ is applied to coordinates $(x,y,z)$ and directions $(\theta,\phi)$ [S1, unofficial].
*   **Outputs:**
    *   Density $\sigma \in \mathbb{R}^1$: Function of location only.
    *   Object Code $\mathbf{o} \in \mathbb{R}^{H+1}$: Function of location only.
    *   Color $\mathbf{c} \in \mathbb{R}^3$: Function of location and viewing direction [S1, unofficial].

**Training Procedure:**
1.  **Forward Pass:** For each ray, sample points. Compute $\text{PE}(\mathbf{p})$ and $\text{PE}(\mathbf{v})$. Feed into MLP to get $\sigma, \mathbf{o}, \mathbf{c}$ [S1, unofficial].
2.  **Rendering:** Render 2D images using standard volume rendering integration of $\sigma$ and $\mathbf{c}$ [S1, unofficial].
3.  **2D Object Matching:**
    *   Generate $L$ images of 2D object predictions $\{I_1 \dots I_L\}$, where $I_l \in \mathbb{R}^{U \times V \times (H+1)}$ [S1, unofficial].
    *   Reshape the first $H$ solid object predictions of $I_l$ to $M \in \mathbb{R}^{N \times H}$, where $N = U \times V$ [S1, unofficial].
    *   Reshape ground truth labels $\bar{I}_l \in \mathbb{R}^{U \times V \times T}$ to $\bar{M} \in \mathbb{R}^{N \times T}$ [S1, unofficial].
    *   Use the Hungarian algorithm to associate every ground truth 2D object mask with a unique predicted 2D object mask based on Soft Intersection-over-Union (sIoU) and Cross-Entropy Score (CES) [S1, unofficial].
    *   sIoU cost between predicted box $h$ and ground truth box $t$:
        $$ C^{sIoU}_{h,t} = \frac{\sum_{n} \dots}{\dots} $$
        *(Note: The exact summation formula is truncated in the source text [S1, unofficial])*
4.  **Loss Functions:**
    *   Standard NeRF rendering loss (color difference) [S1, unofficial].
    *   $\ell_{3d}^{empty}$ and $\ell_{3d}^{obj}$: Jointly learn correct codes for empty 3D points and object points [S1, unofficial]. These are crucial for accurate decomposition [S1, unofficial].

**Object Manipulation:**
1.  **Inverse Query:** Use a lightweight inverse query algorithm to edit the scene geometry. This avoids evaluating dense 3D points from implicit fields explicitly [S1, unofficial].
2.  **Tackle Visual Occlusions:** Explicitly handle occluded regions during manipulation to prevent artifacts [S1, unofficial].
3.  **Apply Transformation:** Translate, rotate, resize, or deform the specified object's coordinates [S1, unofficial].
4.  **Re-render:** Render the novel view with the manipulated object [S1, unofficial].

    return pe

**Edge Cases and Pitfalls:**
*   **No Ground Truth 3D Codes:** Learning the object code faces the issue of no ground truth 3D object codes for full supervision [S1, unofficial].
*   **Variable Number of Objects:** The number of total objects is variable and there is no fixed order for objects [S1, unofficial].
*   **Empty Space:** Non-occupied (empty) 3D space must be taken into account, but there are no labels for supervision [S1, unofficial].
*   **Occlusion Artifacts:** Manipulating originally occluded objects or parts may produce artifacts due to inaccuracies in the learned radiance fields [S1, unofficial].
*   **Lighting Discrepancies:** Lighting factors are not decomposed, causing illumination discrepancies on edited objects compared to non-manipulated scenes [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Novel view rendering quality is clearly better than PointNeRF, though it decreases after manipulation compared to non-manipulation baselines [S1, unofficial].
*   **Strengths:** Simultaneously reconstructs, decomposes, manipulates, and renders complex 3D scenes in a single pipeline from 2D images [S1, unofficial]. Accurately decomposes all 3D objects from 2D views [S1, unofficial].
*   **Limitations:** Manipulation of originally occluded objects may produce artifacts [S1, unofficial]. Lighting factors are not decomposed [S1, unofficial].
*   **When to Use:** When 3D scene geometry decomposition and manipulation from 2D images is required [S1, unofficial].
*   **When Not to Use:** When lighting decomposition is required or when high-fidelity manipulation of heavily occluded objects is critical without artifacts [S1, unofficial].

## Background
DM-NeRF was published as a conference paper at ICLR 2023 [S1, unofficial]. It is among the first methods to simultaneously reconstruct, decompose, manipulate, and render complex 3D scenes in a single pipeline [S1, unofficial]. It builds on the successful NeRF framework but adds an object field component to decompose the entire space into object fields [S1, unofficial].
