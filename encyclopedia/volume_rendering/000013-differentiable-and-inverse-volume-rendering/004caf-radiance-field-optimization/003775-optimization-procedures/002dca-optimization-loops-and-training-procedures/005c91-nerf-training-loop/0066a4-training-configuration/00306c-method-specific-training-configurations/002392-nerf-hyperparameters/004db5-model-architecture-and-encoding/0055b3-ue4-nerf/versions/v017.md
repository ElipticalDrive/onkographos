# UE4-NeRF


## Overview
UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale 3D scenes by partitioning the environment into sub-NeRFs represented by textured polygonal meshes [S1]. It solves the limitations of traditional NeRFs regarding training time and real-time performance on large scales by integrating a learned neural shader into the Unreal Engine 4 (UE4) rasterization pipeline [S1]. Unlike Block-NeRF, which is restricted to grid structures, UE4-NeRF supports arbitrary terrain types (e.g., mountainous) and achieves real-time frame rates (up to 43 FPS at 4K) by using regular octahedra for mesh initialization and multi-resolution hash encoding for acceleration [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of posed images (typically drone-captured) with GPS metadata; camera poses; scene bounding box.
*   **Outputs:** A set of textured polygonal meshes (LOD hierarchy) and a neural shader (HLSL fragment shader) deployed in UE4 for real-time rendering.

**Data Structures:**
1.  **Scene Partitioning:** The large scene is divided into blocks. Each block's training area is slightly larger than the physical scene area to create overlapping borders for smooth transitions [S1].
2.  **Mesh Representation:** Each block is represented by a textured polygonal mesh. The mesh is initialized from a grid and optimized during training. The texture atlas stores an 8-dimensional feature vector and opacity ($\alpha$) for each vertex/face [S1].
3.  **Network Architecture:**
    *   **Encoder ($E$):** A 4-layer MLP. Input: Hash-encoded position $p_i$. Output: Opacity $\alpha_i$ and 8-dimensional feature vector $M_i$ [S1].
    *   **Decoder ($D$):** A 3-layer MLP. Input: Feature vector $M_i$ and spherical harmonics coefficients of viewing direction $d_i$. Output: Color $\mathbf{c}_i$ [S1].
4.  **Coordinate System:** UE4 coordinate system where X points East, Y points South, Z points Up. World scale is 100:1 (UE4 units to real-world units) [S1].

**Numbered Steps:**

1.  **Block Partitioning:**
    *   Train a coarse segmentation model to capture overall terrain and building outlines.
    *   Filter images associated with sub-regions.
    *   Apply a mask to exclude pixels outside the specific scene area of each block [S1].

2.  **Mesh Initialization:**
    *   Initialize a $128 \times 128 \times 128$ grid for the block [S1].
    *   Select the center point of each grid cell along with its six neighboring grids (front, back, left, right, top, bottom) to form the base geometry [S1].
    *   Construct regular octahedra with 20 faces (8 exterior, 12 interior) to represent the local geometry. This replaces the Mobile-NeRF approach to address slow/unstable convergence on tilted surfaces [S1].

3.  **Coordinate Transformation:**
    *   Transform GPS-captured drone imagery coordinates to the UE4 coordinate system.
    *   Apply the 100:1 scale conversion [S1].

4.  **Network Definition:**
    *   Define the Encoder $E$ as a 4-layer MLP with dimensions: $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
    *   Define the Decoder $D$ as a 3-layer MLP with dimensions: $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
    *   The input to the Encoder is the position $p_i$ encoded via multi-resolution hash encoding (from Instant-NGP) [S1].
    *   The input to the Decoder includes the feature vector $M_i$ and the viewing direction $d_i$ encoded via Spherical Harmonics (SH) [S1].

5.  **Training Loop:**
    *   For each ray $r(t) = o + td$ (where $o$ is camera origin, $d$ is viewing direction):
        *   Calculate intersection with the polygonal meshes to determine sampling points [S1].
        *   Compute opacity and feature vector:
            $$ M_i, \alpha_i = E(\text{hash}(p_i); \theta_E) $$
        *   Compute color:
            $$ \mathbf{c}_i = D(M_i, \text{SH}(d_i); \theta_D) $$
    *   Optimize network parameters ($\theta_E, \theta_D$) and vertex positions of the meshes simultaneously [S1].
    *   Use CUDA for computationally intensive portions to leverage GPU parallel computing [S1].
    *   Train for 80,000 epochs per block to achieve convergence [S1].

6.  **LOD Generation:**
    *   Train meshes with varying levels of detail (LOD) for different observation heights.
    *   Coarser meshes are used for higher observation heights to ensure real-time performance [S1].

7.  **Rendering Deployment:**
    *   Extract pre-rendered polygonal meshes at different LODs [S1].
    *   Implement the Decoder network as an HLSL fragment shader in UE4. The shader takes the feature vectors (from the texture atlas) as input and outputs colors [S1].
    *   Combine meshes with the UE4 rasterization pipeline for real-time interactive rendering [S1].

**Pseudocode:**

```python
# UE4-NeRF Training and Rendering Logic

class EncoderMLP:
    """
    4-layer MLP: 32->64, 64->64, 64->64, 64->8
    Input: Hash-encoded position
    Output: Opacity (scalar), Feature Vector (8-dim)
    """
    def __init__(self):
        self.layers = [
            Linear(32, 64), # Assuming hash dimension is 32 based on Instant-NGP standard, 
                            # though source says "32x64" implying input dim 32.
            Linear(64, 64),
            Linear(64, 64),
            Linear(64, 8)
        ]
        # Activation functions not explicitly specified for hidden layers, 
        # standard ReLU is assumed for MLPs unless specified otherwise [G].
        
    def forward(self, hash_encoded_pos):
        x = hash_encoded_pos
        for layer in self.layers[:-1]:
            x = relu(layer(x))
        out = self.layers[-1](x)
        # Split output into opacity and feature vector
        alpha = sigmoid(out[:, 0]) # Opacity usually bounded [0,1] [G]
        feature_vec = out[:, 1:]   # 8-dim feature vector
        return alpha, feature_vec

class DecoderMLP:
    """
    3-layer MLP: 17->16, 16->16, 16->3
    Input: Feature Vector (8-dim) + SH-encoded View Direction (9-dim for 1st order SH)
    Output: Color (3-dim RGB)
    """
    def __init__(self):
        self.layers = [
            Linear(17, 16),
            Linear(16, 16),
            Linear(16, 3)
        ]
        
    def forward(self, feature_vec, view_direction):
        # Concatenate feature vector and SH coefficients
        # SH(1st order) = 3 coefficients per channel (RGB) -> 9 dims? 
        # Source says input dim is 17. Feature vec is 8. 
        # 17 - 8 = 9. So SH encoding is 9-dimensional (1st order spherical harmonics).
        x = concat(feature_vec, sh_encode(view_direction, order=1))
        for layer in self.layers[:-1]:
            x = relu(layer(x))
        color = sigmoid(self.layers[-1](x)) # Color bounded [0,1] [G]
        return color

def train_block(block_data, num_epochs=80000):
    """
    Train a single block of the scene.
    """
    encoder = EncoderMLP()
    decoder = DecoderMLP()
    
    # Initialize mesh from 128x128x128 grid using octahedra
    mesh = initialize_octahedral_mesh(grid_size=128)
    
    optimizer = Adam(params=list(encoder.parameters()) + list(decoder.parameters()) + list(mesh.vertices))
    
    for epoch in range(num_epochs):
        # Sample rays from camera poses
        rays = sample_rays(block_data.cameras, mesh)
        
        total_loss = 0
        for ray in rays:
            # 1. Find intersection with mesh
            t, point = ray_intersect(ray.origin, ray.direction, mesh)
            if t is None: continue
            
            # 2. Encode position
            pos_hash = multi_resolution_hash_encoding(point)
            
            # 3. Encode view direction
            view_sh = spherical_harmonics_encoding(ray.direction, order=1)
            
            # 4. Forward pass
            alpha, feature_vec = encoder(pos_hash)
            color = decoder(feature_vec, view_sh)
            
            # 5. Compute loss against ground truth pixel color
            gt_color = block_data.get_pixel_color(ray)
            loss = mse(color, gt_color)
            total_loss += loss
            
        # Backpropagate and update weights and vertex positions
        optimizer.zero_grad()
        total_loss.backward()
        optimizer.step()
        
    return mesh, encoder, decoder

def render_ue4(meshes_lod, encoder, decoder):
    """
    Deploy to Unreal Engine 4.
    """
    # 1. Extract meshes at different LODs
    # Coarser meshes for higher observation heights
    lod_meshes = generate_lod_hierarchy(meshes_lod)
    
    # 2. Convert Decoder to HLSL Shader
    # The shader takes feature vectors (from texture atlas) and outputs color
    hlsl_shader = convert_mlp_to_hlsl(decoder)
    
    # 3. Integrate with UE4 Rasterization Pipeline
    # UE4 handles occlusion automatically for added 3D models
    scene = UE4Scene()
    for lod in lod_meshes:
        scene.add_mesh(lod, shader=hlsl_shader)
        
    return scene
```

**Parameters:**
*   **Grid Initialization Size:** $128 \times 128 \times 128$ [S1].
*   **Octahedron Faces:** 20 faces total (8 exterior, 12 interior) [S1].
*   **Encoder Dimensions:** $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
*   **Decoder Dimensions:** $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
*   **Training Hardware:** 1 Nvidia RTX 3090 GPU [S1].
*   **Training Iterations:** 80,000 epochs per block [S1].
*   **World Scale:** 100:1 (UE4 units to real-world units) [S1].
*   **Coordinate System:** X: East, Y: South, Z: Up [S1].

**Edge Cases and Pitfalls:**
*   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces. UE4-NeRF addresses this by using regular octahedra [S1].
*   **Transparency:** Mobile-NeRF cannot handle transparent/semi-transparent objects (water, glass) due to opacity binarization. UE4-NeRF stores opacity in texture maps to mitigate this [S1].
*   **Performance:** Semi-transparent objects (e.g., vegetation) increase computational overhead, reducing frame rates [S1].
*   **Pre-rendering Gaps:** Pre-rendering cannot capture rays from all viewing angles, potentially resulting in gaps or holes in the final rendered scene [S1].
*   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, causing evaluation metrics (PSNR/SSIM/LPIPS) to underestimate actual reconstruction quality [S1].
*   **Memory:** Rendering large scenes (square kilometers) incurs significant memory overhead. Increasing accuracy further amplifies memory consumption [S1].
*   **Hardware Dependency:** Requires CUDA and NVIDIA GPUs [S1].

## Operating characteristics
*   **Training Speed:** 1000× faster than Mobile-NeRF [S1].
*   **Training Time:**
    *   Per block: ~40 minutes on 1× RTX 3090 [S1].
    *   Full scene ($n$ blocks): $1 \text{ hour} + (40 \text{ minutes} \times n/4)$ on 1× RTX 3090 [S1].
    *   Comparison: Mobile-NeRF takes 48h/block (4×3090); Mega-NeRF takes 36h/block (1×3090) [S1].
*   **Rendering Performance:**
    *   Real-time rendering at 4K resolution with up to 43 FPS [S1].
    *   50 FPS on full scene at 2K resolution [S1].
    *   $\ge$70 FPS on individual blocks at 2K resolution [S1].
    *   Comparison: Mobile-NeRF max 35 FPS at 2K (block only); Mega-NeRF max 60 FPS at 800×800 (scene) [S1].
*   **Memory:** Significant memory overhead for large scenes (square kilometers). Memory consumption increases with accuracy [S1].
*   **Strengths:** Real-time interactive rendering; handles large-scale scenes; supports scene editing (importing .obj/.fbx); handles tilted surfaces and semi-transparent objects better than Mobile-NeRF; avoids blurriness on natural scenes compared to Mip-NeRF [S1].
*   **Limitations:** Requires NVIDIA GPUs/CUDA; pre-rendering gaps/holes; exposure matching issues in UE4; semi-transparent objects reduce FPS [S1].
*   **When to use:** Real-time interactive rendering of large-scale outdoor scenes (farmland, construction sites, industrial parks) in UE4.
*   **When not to use:** Small-scale scenes where standard NeRF suffices; scenes requiring precise exposure matching without post-processing; non-NVIDIA hardware environments.

## Background
UE4-NeRF was introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" [S1]. It was developed to address the significant limitations of NeRF in real-time rendering and large-scale scene reconstruction, specifically the high training overhead and lack of interactivity. The method builds on [Model Architecture and Encoding](13550-model-architecture-and-encoding.md) by integrating multi-resolution hash encoding (from Instant-NGP) and spherical harmonics for view dependence. It is used in Unreal Engine 4 for drone-captured large-scale scenes and evaluated on the Mega-NeRF public dataset [S1].
