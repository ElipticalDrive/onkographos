# Training Loop

Also called: NeRF Training Pipeline, RtStereoHumanModel Training Loop, Training Loop & Data Fetching

## Overview
The Training Loop is the core optimization procedure for NeRF and related radiance field methods, orchestrating data loading, ray sampling, model forward passes, loss calculation, and parameter updates [S1, unofficial]. It solves the problem of iteratively refining a scene representation to minimize the difference between rendered views and ground truth images. It sets itself apart from its siblings by defining the high-level control flow (epochs, batches, validation, checkpointing) rather than the specific ray batching strategies [Training Ray Batching](2252-training-ray-batching.md) or specialized guidance mechanisms like [Diffusion-Based Guidance for Radiance Field Optimization](8117-diffusion-based-guidance-for-radiance-field-optimization.md).

## How it works
**Inputs and Outputs:**
- **Inputs:** Training dataset (images, poses, intrinsics), model architecture, optimizer configuration, hyperparameters (learning rate, batch size, epochs).
- **Outputs:** Trained model weights, optimizer state, logs, and optionally rendered test images or checkpoints.

**Data Structures:**
- **Batch:** A dictionary containing tensors for images, camera parameters (intrinsics $K$, extrinsics $R, t$), and optional masks. For stereo methods, it includes 'lmain' (left) and 'rmain' (right) views [S2, unofficial].
- **Ray Bundle:** A set of 3D rays defined by origin and direction, sampled from random pixels in the training images [S1, unofficial].
- **Metrics:** Accumulators for L1 loss, SSIM, Chamfer distance, and scale loss [S2, unofficial].

**Numbered Steps:**

1. **Initialization:**
   - Create the NeRF model and optimizer using `create_model(cfg)` or `create_nerf(args)` [S1, unofficial][S4, unofficial].
   - Initialize the learning rate scheduler (e.g., LambdaLR, OneCycleLR) [S1, unofficial][S2, unofficial].
   - Load training and validation datasets using `get_nerf_datasets` or specific loaders (LLFF, Blender, LINEMOD, DeepVoxels) [S1, unofficial][S4, unofficial].
   - Set near and far clipping planes based on dataset type:
     - LLFF: $near = \min(bounds) \times 0.9$, $far = \max(bounds) \times 1.0$ (or 0 and 1 if `no_ndc`) [S1, unofficial][S4, unofficial].
     - Blender: $near = 2.0$, $far = 6.0$ [S1, unofficial][S4, unofficial].
     - DeepVoxels: $near = hemi\_R - 1.0$, $far = hemi\_R + 1.0$ [S1, unofficial][S4, unofficial].

2. **Main Training Loop (Epochs):**
   - Iterate from `start_epoch` to `cfg.training.num_epochs` [S1, unofficial].
   - **Validation:** If `total_steps % eval_freq == 0`, set model to eval mode, run `run_eval()`, then set back to train mode [S1, unofficial]. Freeze BatchNorm in specific components like `raft_stereo` if applicable [S2, unofficial].

3. **Batch Loop:**
   - Iterate over batches in `train_dataloader` [S1, unofficial].
   - **Data Fetching:**
     - Fetch next batch from `train_iterator` [S1, unofficial]. If `StopIteration` occurs, reset iterator to `iter(train_loader)` and fetch again [S3, unofficial].
     - Move all items in 'lmain' and 'rmain' views to CUDA device [S2, unofficial].
     - Extract image, camera, and camera_idx from batch; move to CUDA [S1, unofficial].
   - **Ray Sampling:**
     - Sample random pixels and generate ray bundle [S1, unofficial].
     - Sample ground truth RGB values at the random pixel coordinates [S1, unofficial].
     - If batching is enabled, stack rays from training images, concatenate with RGB values, transpose, and reshape into a flat array of rays with their corresponding colors [S4, unofficial].
   - **Forward Pass:**
     - Pass data through model with `is_train=True` [S2, unofficial].
     - Render scene using the model (e.g., NeRF, Gaussian Splatting) with background color from config [S2, unofficial][S3, unofficial].
     - Get rendered image, metrics, and other outputs [S2, unofficial].
   - **Loss Calculation:**
     - Compute loss. Common total loss formula:
       $$ \text{Total Loss} = 0.8 \times L1 + 0.2 \times (1 - SSIM) + 0.5 \times \text{Chamfer Loss} $$
       [S2, unofficial]
     - If Chamfer loss is enabled (`if_chamfer`) and iteration > `iter_from`:
       - Extract valid points from `l_xyz` and `r_xyz` using `pts_valid` masks [S2, unofficial].
       - Sample 10,000 points randomly from each side [S2, unofficial].
       - Compute chamfer distance between sampled points [S2, unofficial].
       - Accumulate loss and divide by batch size [S2, unofficial].
     - Log metrics (L1, SSIM, Chamfer, Scale) and print averages every 100 steps [S2, unofficial].
   - **Backpropagation:**
     - Scale loss using `GradScaler` if mixed precision is enabled [S2, unofficial].
     - Call `loss.backward()` [S1, unofficial].
     - Unscale optimizer [S2, unofficial].
     - Clip gradients to norm 1.0 [S2, unofficial].
     - Step optimizer [S1, unofficial].
     - Step scheduler [S1, unofficial].
     - Update scaler [S2, unofficial].
     - Zero gradients (`optimizer.zero_grad()`) [S1, unofficial].

4. **End of Epoch:**
   - Step the learning rate scheduler [S1, unofficial].
   - **Checkpointing:** If `epoch % checkpoint_interval == 0` and `checkpoint_path` is set, save model and optimizer state [S1, unofficial].
   - **Rendering:** If `epoch % render_interval == 0` and `epoch > 0`, render test images using surround cameras [S1, unofficial].

**Parameters:**
- `batch_size`: Number of random pixels sampled per training step [S1, unofficial].
- `lr`: Learning rate for Adam/AdamW optimizer [S1, unofficial][S2, unofficial].
- `wdecay`: Weight decay for AdamW optimizer [S2, unofficial].
- `N_rand`: Number of random rays to sample per batch [S4, unofficial].
- `use_batching`: Boolean flag for enabling ray batching [S4, unofficial].
- `lr_scheduler_gamma`: Gamma factor for LambdaLR scheduler [S1, unofficial].
- `lr_scheduler_step_size`: Step size for LambdaLR scheduler exponent [S1, unofficial].
- `pct_start`: Percentage of total steps for linear warmup in OneCycleLR scheduler, default 0.01 [S2, unofficial].
- `checkpoint_interval`: Frequency of saving checkpoints in epochs [S1, unofficial].
- `render_interval`: Frequency of rendering test images in epochs [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Iterator Reset:** Handle `StopIteration` by resetting the iterator to ensure continuous data flow [S3, unofficial].
- **Clipping Planes:** Incorrect near/far bounds can lead to poor rendering or NaN losses, especially for datasets with varying scales (LLFF vs Blender) [S1, unofficial][S4, unofficial].
- **Gradient Clipping:** Essential to prevent exploding gradients, especially with complex loss functions like Chamfer distance [S2, unofficial].
- **Mixed Precision:** Requires `GradScaler` to prevent underflow of small gradients [S2, unofficial].

## Subtopics

### [VCCNF Training Loop](4736-vccnf-training-loop.md)
The VCCNF Training Loop is a supervised optimization procedure for a Voxelized Continuous Coordinate Normalizing Flow (VCCNF). It learns to map Gaussian noise to shape latent codes conditioned on voxel data by minimizing the Mean Squared Error (MSE) between predicted and target latent codes.

### [MVDream Multi-View Diffusion Guidance](6345-mvdream-multi-view-diffusion-guidance.md)
MVDream Multi-View Diffusion Guidance provides gradient guidance for 3D optimization by encoding RGB images and camera poses into a multi-view diffusion model, predicting noise, and stepping the DDIM scheduler. It sets itself apart from single-view guidance methods by enforcing multi-view consistency through a multi-view diffusion prior.

### [Diffusion-Based Guidance for Radiance Field Optimization](8117-diffusion-based-guidance-for-radiance-field-optimization.md)
Diffusion-Based Guidance for Radiance Field Optimization, commonly known as Score Distillation Sampling (SDS), computes a gradient signal from a frozen 2D diffusion model to optimize a 3D radiance field representation. It solves the problem of generating 3D geometry and texture from 2D priors by backpropagating the difference between the diffusion model's predicted noise and the actual noise added to a rendered image's latent representation. Unlike sibling methods that may use explicit 3D supervision or multi-view consistency losses directly, SDS relies entirely on the generative prior of a pre-trained text-to-image diffusion model to guide the optimization loop.

### [Two-Stage Training for Learnable Proposer](8685-two-stage-training-for-learnable-proposer.md)
Two-Stage Training for Learnable Proposer divides network optimization into two distinct stages to resolve the chicken-and-egg problem inherent in learning to sample for radiance fields. Training the proposer requires a good fine network to provide a useful training signal, but the fine network can only improve if sampled at informative locations. This method sets itself apart from joint training approaches by decoupling proposer initialization from radiance field fine-tuning to ensure stable convergence.

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of training steps and batch size. Each step involves a forward pass (ray marching) and a backward pass (gradient computation).
- **Memory Complexity:** Proportional to the model size, batch size, and the number of samples per ray. Large batch sizes or high-resolution images increase memory usage significantly.
- **Measured Performance:** Varies by implementation. For example, IBRNet baseline training takes 0.33 sec/iteration with a rendering time of 33.3 sec/frame [S12, unofficial]. City-on-Web training takes approximately 12 hours for 30,000 iterations [S10].
- **Scaling:** Scales well with distributed training if data loading and gradient aggregation are optimized. Ray batching [Training Ray Batching](2252-training-ray-batching.md) can improve throughput by reducing kernel launch overhead.
- **Strengths:** Flexible, supports various loss functions and datasets. Modular design allows easy integration of new models or guidance methods.
- **Limitations:** Can be slow due to ray marching. Requires careful tuning of hyperparameters (learning rate, clipping, near/far bounds).
- **When to use:** Standard NeRF training, Gaussian Splatting training, and other radiance field optimization tasks.
- **When not to use:** When real-time training is required, or when the scene is extremely large and requires specialized distributed training strategies.

## Background
The NeRF Training Loop originates from the original NeRF paper [S4, unofficial] and has been adapted for various radiance field representations. It is a fundamental component in differentiable rendering pipelines, enabling the optimization of scene representations from 2D images. The loop has evolved to include features like mixed precision training, gradient caching [S9], and adaptive loss weighting [S7].
