# Mip-NeRF 360 MLP Architecture

Also called: Integrated Positional Encoding MLP, PosEnc MLP

## Overview
The Mip-NeRF 360 MLP architecture is a specific configuration of the radiance field neural network that replaces standard positional encoding with **integrated positional encoding** to analytically account for the volume integration of a Gaussian distribution along a ray, thereby reducing aliasing artifacts [S1, unofficial]. It distinguishes itself from the standard NeRF architecture by lifting 3D coordinates and their covariances into a higher-dimensional basis space before encoding, allowing the MLP to approximate the integral of the encoding function over the scene's spatial uncertainty [S1, unofficial].

## How it works
The architecture consists of two MLPs: a density network and a color network, connected by a bottleneck feature vector. The key innovation lies in the input encoding, which integrates positional encoding over a Gaussian distribution defined by the ray's mean position and covariance, rather than encoding a single point.

### Inputs and Outputs
**Inputs:**
*   Ray parameters: Mean position $\mathbf{\mu} \in \mathbb{R}^3$ and covariance matrix $\mathbf{\Sigma} \in \mathbb{R}^{3 \times 3}$ describing the Gaussian distribution of the ray segment [S1, unofficial].
*   Viewing direction $\mathbf{d} \in \mathbb{R}^3$ (or reflection direction $\mathbf{r} \in \mathbb{R}^3$ if reflections are enabled) [S1, unofficial].
*   Optional auxiliary inputs: Normals $\mathbf{n} \in \mathbb{R}^3$, GLO vectors, or roughness [S1, unofficial].

**Outputs:**
*   Raw density $\sigma \in \mathbb{R}$ and bottleneck feature vector $\mathbf{e} \in \mathbb{R}^{D_{bottleneck}}$ from the density network [S1, unofficial].
*   RGB color $\mathbf{c} \in \mathbb{R}^3$ from the color network [S1, unofficial].

### Data Structures and Parameters
The architecture is defined by the following hyperparameters [S1, unofficial]:

*   **Network Depths:** `net_depth` = 8 (density), `net_depth_viewdirs` = 1 (color).
*   **Network Widths:** `net_width` = 256 (density), `net_width_viewdirs` = 128 (color), `bottleneck_width` = 256.
*   **Encoding Degrees:** `min_deg_point` = 0, `max_deg_point` = 12 (3D points), `deg_view` = 4 (directions).
*   **Skip Connections:** `skip_layer` = 4 (density), `skip_layer_dir` = 4 (color).
*   **Activations:** `density_activation` (typically softplus), `rgb_activation` (typically sigmoid or linear_to_srgb).
*   **Biases/Noise:** `density_bias` = -1.0, `density_noise` = 0.0, `rgb_bias` = 0.0, `rgb_padding` = 0.001, `bottleneck_noise` = 0.0.
*   **Basis:** `basis_shape` = 'icosahedron', `basis_subdivisions` = 2.

### Step-by-Step Method

1.  **Basis Precomputation:**
    Generate a basis matrix for integrated positional encoding. This involves creating a tessellated shape (icosahedron or octahedron) with specified subdivisions and computing the basis functions [S1, unofficial]. Store the transpose of this basis matrix as `pos_basis_t` [S1, unofficial].

2.  **Directional Encoding Setup:**
    If `use_directional_enc` is True, generate an Integrated Directional Encoding (IDE) function using `ref_utils.generate_ide_fn(deg_view)` [S1, unofficial]. Otherwise, define a standard positional encoding function for directions with `min_deg=0`, `max_deg=deg_view`, and `append_identity=True` [S1, unofficial].

3.  **Density Network Input Preparation (Integrated Positional Encoding):**
    *   **Linearization:** If a warping function `warp_fn` is provided, linearize the means and covariances using `coord.track_linearize(warp_fn, means, covs)` [S1, unofficial].
    *   **Lifting:** Lift the means $\mathbf{\mu}$ and diagonalize the covariances $\mathbf{\Sigma}$ using the precomputed basis transpose `pos_basis_t`. This transforms the 3D coordinates and their uncertainties into the basis space, resulting in lifted means $\mathbf{\mu}_{lifted}$ and lifted variances $\mathbf{\Sigma}_{lifted}$ [S1, unofficial].
    *   **Encoding:** Compute the integrated positional encoding by evaluating the encoding function at the lifted means and variances. This yields the input vector $\mathbf{x}$ for the density MLP [S1, unofficial].

4.  **Density Network Forward Pass:**
    *   Initialize input $\mathbf{x}$ with the integrated positional encoding.
    *   Iterate $i$ from 0 to `net_depth` - 1:
        *   Apply a dense layer with width `net_width` and activation `net_activation`.
        *   If $i > 0$ and $i \pmod{\text{skip\_layer}} == 0$, concatenate the current output with the original input $\mathbf{x}$ along the last axis (skip connection) [S1, unofficial].
    *   Output raw density $\sigma_{raw}$ using a final dense layer with width 1 [S1, unofficial].
    *   **Density Activation:** Apply the density activation (e.g., softplus) to $\sigma_{raw}$, adding `density_bias` before activation: $\sigma = \text{activation}(\sigma_{raw} + \text{density\_bias})$ [S1, unofficial].
    *   **Noise:** If `density_noise` > 0, add Gaussian noise to $\sigma_{raw}$ before activation [S1, unofficial].

5.  **Normal Computation (Optional):**
    If `disable_density_normals` is False:
    *   Compute the gradient of the raw density with respect to the input coordinates. This is typically done using automatic differentiation (e.g., `jax.value_and_grad`) on the density prediction function [S1, unofficial].
    *   Compute normals as the negative normalized gradient: $\mathbf{n} = -\text{normalize}(\nabla \sigma_{raw})$. Using the raw density gradient is numerically more stable than using the post-activation density [S1, unofficial].

6.  **Color Network Input Preparation:**
    *   **Directional Encoding:** Encode the viewing direction $\mathbf{d}$ (or reflection direction $\mathbf{r}$) using the setup from Step 2. If `use_reflections` is True, ensure view directions are flipped before reflection calculation [S1, unofficial].
    *   **Broadcasting:** Broadcast the directional encoding to match the bottleneck feature dimensions [S1, unofficial].
    *   **Concatenation:** Start with the bottleneck feature vector $\mathbf{e}$ from the density network.
        *   Append the encoded direction.
        *   If `use_n_dot_v` is True, compute $\mathbf{n} \cdot \mathbf{d}$ and append it [S1, unofficial].
        *   If `glo_vec` is provided, broadcast and append it [S1, unofficial].
    *   Concatenate all elements along the last axis to form the input $\mathbf{x}_{color}$ for the color MLP [S1, unofficial].

7.  **Color Network Forward Pass:**
    *   Initialize input $\mathbf{x}_{color}$.
    *   Iterate $i$ from 0 to `net_depth_viewdirs` - 1:
        *   Apply a dense layer with width `net_width_viewdirs` and activation `net_activation`.
        *   If $i > 0$ and $i \pmod{\text{skip\_layer\_dir}} == 0$, concatenate the current output with the original input $\mathbf{x}_{color}$ along the last axis (skip connection) [S1, unofficial].
    *   **RGB Output:** Compute raw RGB values using a final dense layer with width `num_rgb_channels` (typically 3).
    *   **Activation and Padding:** Apply `rgb_activation` to $\text{premultiplier} \times \text{raw\_rgb} + \text{rgb\_bias}$. Finally, apply RGB padding: $\mathbf{c} = \mathbf{c} \times (1 + 2 \times \text{rgb\_padding}) - \text{rgb\_padding}$ [S1, unofficial].

8.  **Specular/Diffuse Split (Optional):**
    If `use_diffuse_color` is True:
    *   Compute diffuse color: $\mathbf{c}_{diffuse} = \text{sigmoid}(\sigma_{raw\_diffuse} - \log(3.0))$ [S1, unofficial].
    *   Compute specular color: If `use_specular_tint` is True, $\mathbf{c}_{specular} = \text{tint} \times \mathbf{c}$; else $\mathbf{c}_{specular} = 0.5 \times \mathbf{c}$ [S1, unofficial].
    *   Combine and tone map: $\mathbf{c}_{final} = \text{clip}(\text{linear\_to\_srgb}(\mathbf{c}_{specular} + \mathbf{c}_{diffuse}), 0.0, 1.0)$ [S1, unofficial].

### Edge Cases and Pitfalls
*   **Reflections Require Normals:** If `use_reflections` is True, normals must be computed (either via `enable_pred_normals` or by not disabling density normals). If normals are not available, a `ValueError` is raised [S1, unofficial].
*   **Reflection Direction Flip:** When computing reflection directions, view directions (which point from camera to point) must be flipped (`-viewdirs`) before reflection because the reflection utility assumes directions point toward the camera [S1, unofficial].
*   **Normal Stability:** Normals are computed from the gradient of the *raw* (pre-activation) density, not the post-activation density, because the activation function (e.g., softplus) can have steep or flat gradients that destabilize normal estimation [S1, unofficial].
*   **Precision:** High-precision (float64) is recommended for color correction and metric computation to avoid quantization errors [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The integrated positional encoding adds computational overhead compared to standard positional encoding due to the lifting and diagonalization steps, but it reduces the need for high-frequency sampling to avoid aliasing. The MLP complexity is $O(D_{in} \cdot W \cdot L)$, where $D_{in}$ is the input dimension (larger due to integrated encoding), $W$ is the width, and $L$ is the depth.
*   **Memory Complexity:** The memory footprint is dominated by the MLP weights and the intermediate activations. The basis matrix is small and precomputed.
*   **Strengths:** Significantly reduces aliasing artifacts in novel views, especially for scenes with high-frequency details or large depth variations. It provides a more robust representation of the radiance field by accounting for the volume integration process.
*   **Limitations:** Slightly higher computational cost per sample due to the integrated encoding. The architecture is more complex to implement than standard NeRF.
*   **When to Use:** Ideal for unbounded scenes (360-degree environments) where aliasing is a major issue. It is the default architecture for the Mip-NeRF 360 dataset and benchmarks.

## Background
The Mip-NeRF 360 MLP architecture was introduced in the "Mip-NeRF 360: Unbounded Anti-Aliased Neural Radiance Fields" paper by T. Müller et al. (2022) [S1, unofficial]. It extends the original Mip-NeRF concept, which used integrated positional encoding for 1D rays, to a full 3D radiance field architecture. The method addresses the aliasing artifacts inherent in standard NeRF when rendering novel views of complex, unbounded scenes. It has become a standard baseline for evaluating neural radiance field methods on the Mip-NeRF 360 dataset.
