# Joint Optimization of Scene and Renderer


## Overview
Joint Optimization of Scene and Renderer is a photometric optimization method that simultaneously refines the geometric and appearance attributes of a scene representation alongside the parameters of a neural renderer [S1]. It solves the problem of reconstructing high-quality novel views from a sparse set of input images by treating per-pixel attributes (color, depth, normal, uncertainty, and latent features) as learnable parameters [S1]. It differs from [Image-based reconstruction optimization](6677-image-based-reconstruction-optimization.md) by explicitly optimizing the scene's underlying point-based representation attributes rather than just camera poses or static geometry, and it differs from [Gradient-Based SE(3) Optimization](7526-gradient-based-se-3-optimization.md) by focusing on per-view attribute refinement rather than global camera pose estimation [S1].

## How it works
**Inputs:** A set of $N$ input images with known camera poses, initial depth maps, and an initial neural renderer (typically a CNN-based decoder) [S1].
**Outputs:** Optimized per-view attributes (color, depth, normal, uncertainty, 6-component latent feature vector) and the neural renderer weights [S1].

**Data Structures:**
*   **Per-View Attributes:** For each input view $i$, a set of tensors corresponding to the image resolution.
    *   `color`: RGB values.
    *   `depth`: Per-pixel depth values.
    *   `normal`: 3D unit normal vectors.
    *   `uncertainty`: Scalar uncertainty values.
    *   `features`: 6-component latent feature vector per pixel.
*   **Neural Renderer:** A CNN decoder that takes the stacked attributes from multiple views and outputs the rendered image [S1].

**Initialization:**
1.  Initialize the 6-component latent feature vector for each pixel to $0.5$ [S1].
2.  Initialize depth maps using generated per-view meshes from Hedman et al. [HPP∗ 18] [S1].
3.  Initialize the neural renderer using the method of Zhang et al. [ZDM19] [S1].
4.  Select 9 views randomly from the best 13 available views for training [S1].

**Optimization Loop:**
The optimization uses a leave-one-out strategy. At each iteration:
1.  **Selection:** Randomly select one view from the 9 selected views to serve as the ground truth view $I_{gt}$ [S1].
2.  **Lifting:** Lift all pixels from the selected input views into 3D space using their depth maps [S1].
3.  **Splatting:** Splat the lifted 3D points (including their attributes) into the 2D coordinate system of the ground truth view [S1].
4.  **Batching:** Stack the attributes from all splatted views into a batch [S1].
5.  **Rendering:** Feed the batched attributes through the neural renderer to produce the predicted image $I$ [S1].
6.  **Feature Scaling:** Feed the latent features through a sigmoid function to scale them to the unit range $[0, 1]$ before they are processed by the next module of the renderer [S1].
7.  **Loss Calculation:** Compute the loss $L$ using the L1 norm between the predicted image $I$ and the ground truth image $I_{gt}$:
    $$ L = \| I - I_{gt} \|_1 $$
8.  **Gradient Update:** Use the ADAM optimizer to update all parameters (renderer weights and per-view attributes) [S1].
9.  **Renormalization:** Renormalize the normal vectors in each iteration to avoid numerical instabilities [S1].

**Pseudocode:**
```python
import math
import random

def sigmoid(x):
    return 1.0 / (1.0 + math.exp(-x))

def normalize(v):
    mag = math.sqrt(sum(c * c for c in v))
    return [c / mag for c in v] if mag > 0 else v

def l1_loss(pred, gt):
    return sum(abs(p - g) for p, g in zip(pred, gt)) / len(pred)

# Initialization
# attributes[i] contains color, depth, normal, uncertainty, features for view i
# renderer is the neural network decoder initialized per Zhang et al. [S1]
# views = list of 9 selected view indices
# camera_poses = known poses for all views
# images = ground truth images for all views

for iteration in range(100000):
    # 1. Select ground truth view
    gt_idx = random.choice(views)
    
    # 2. Lift and Splat
    batch = []
    for v_idx in views:
        if v_idx == gt_idx:
            continue
        # Lift pixels to 3D using depth and camera pose, then splat to gt_idx view
        # Standard perspective projection and accumulation into tgt view grid [G]
        projected = splat_to_view(attributes[v_idx], camera_poses[v_idx], camera_poses[gt_idx])
        batch.append(projected)
    
    # 3. Stack and Render
    # Concatenate lists of attribute tuples into a single batch tensor
    batch_tensor = concatenate(batch)
    
    # 4. Feature Scaling
    # Apply sigmoid to the latent features in the batch
    batch_tensor.features = [sigmoid(f) for f in batch_tensor.features]
    
    # 5. Forward Pass
    predicted_image = renderer.forward(batch_tensor)
    
    # 6. Loss Calculation
    ground_truth_image = images[gt_idx]
    loss = l1_loss(predicted_image, ground_truth_image)
    
    # 7. Backward Pass and Update
    grads = compute_gradients(loss)
    optimizer.step(grads)
    optimizer.zero_grad()
    
    # 8. Renormalization
    # Renormalize normal vectors for all views to prevent numerical instability
    for v_idx in views:
        attributes[v_idx].normal = normalize(attributes[v_idx].normal)

# Parameters
lr_cnn = 0.0001
lr_normal = 0.0001
lr_depth = 0.0001
lr_features = 0.001
lr_uncertainty = 0.01
patch_size = (150, 150)
```

**Parameters:**
*   Learning rates: `lrCNN` = `lrnormal` = `lrdepth` = 0.0001, `lrfeatures` = 0.001, `lrU` = 0.01 [S1].
*   Training iterations: 100,000 [S1].
*   Patch size: 150×150 [S1].

**Edge Cases and Pitfalls:**
*   Numerical instabilities with normal vectors are handled by renormalizing normals in each iteration [S1].

## Subtopics

### Multi-View Harmonization
Multi-View Harmonization is a technique to handle exposure and camera parameter fluctuations between views by optimizing a brightness coefficient per view [S1]. It models the fluctuation as an additional coefficient $\mu_i$ per view, multiplied with the color of the corresponding input image [S1]. It is initialized to $\mu_i = 1.0$ and optimized like any other per-view parameter [S1]. This parameter modifies the input images used for ground truth and re-projections [S1]. To avoid degenerate solutions ($\mu_i=0$), a regularization term $L_\mu$ is added:
$$ L_\mu = \lambda \sum_{i=1}^{N} (\mu_i - 1.0)^2 $$
where $N$ is the number of input views and $\lambda = 0.2$ [S1]. Additionally, a photoconsistency loss $L_{photo}$ is introduced between the optimized image $I_n$ and other reprojected images $R(I_m)$:
$$ L_{photo} = \sum_{m \neq n} (M I_n - R(I_m))^2 $$
where $M$ is a mask of pixels containing content in $R(I_m)$ [S1].

### [Multi-view Style-Transfer](11496-multi-view-style-transfer.md)
Multi-View Style-Transfer (MVST) is a method to jointly optimize input image colors to match a given style while maintaining photo-consistency across multiple views. It leverages the differentiability of point-based reprojection to allow style transfer between input images and a target style image, distinguishing itself from standard style transfer by enforcing multi-view consistency through a photo-consistency loss term. It makes input image colors parameters of the optimization process and adds a multi-view style-transfer loss:
$$ L_{mvst}(I_n, R(I_{m \neq n})) = L_{photo} + \mathcal{L}_{style}(I_n, S) + \mathcal{L}_{cont}(I_n, I_n^*) $$
where $\mathcal{L}_{style}$ is the style loss against a target style image $S$, and $\mathcal{L}_{cont}$ is a content loss.

## Operating characteristics
*   **Time Complexity:** Training for 100,000 iterations takes 12-14 hours on an RTX8000 GPU [S1]. Small scenes (Hugo, Tree) require 20,000 iterations (~3 hours) [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** The method achieves high-quality free-viewpoint rendering after optimization [S1].
*   **Strengths:** Joint optimization allows the scene representation and renderer to adapt to each other, improving rendering quality [S1].
*   **Limitations:** Training time is significant (12-14 hours for full scenes) [S1]. Requires initial depth maps and renderer initialization [S1].
*   **When to use:** When high-quality novel view synthesis is required from a sparse set of input images and computational resources allow for lengthy optimization [S1].
*   **When not to use:** When real-time performance is required during optimization or when initial depth estimates are unavailable [S1].

## Background
The method was introduced by Kopanas et al. in "Point-Based Neural Rendering with Per-View Optimization" [S1]. It builds on previous work in neural rendering and point-based representations [S1]. The neural renderer is initialized using the method of Zhang et al. [ZDM19], and depth initialization uses meshes from Hedman et al. [HPP∗ 18] [S1]. The style transfer component is based on the approach of Mechrez et al. [MTZM18] [S1].
