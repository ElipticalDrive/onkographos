# Metamers Rendered Differentiably (MRD)

## Overview
Metamers Rendered Differentiably (MRD) is a method that uses physically based differentiable rendering to probe vision models' implicit understanding of generative 3D scene properties by searching for 3D scene parameters that are physically different but produce the same model activation (model metamers) [S1, unofficial]. Unlike pixel-based gradient ascent methods that directly adjust image pixels, MRD optimizes physical scene parameters, ensuring reconstructions are grounded in physical descriptions and allowing decomposition of model activations into specific physical causes [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A target scene defined by known parameters $\pi$ (geometry, material, lighting); a frozen neural network $NN(\cdot)$ (e.g., CLIP, ResNet-50, LPIPS); a physically based differentiable rendering function $f(\cdot)$ [S1, unofficial].
*   **Output:** Optimized scene parameters $\pi'$ that constitute a "metamer," i.e., a scene physically distinct from the target but yielding equivalent latent representations in the target network [S1, unofficial].

**Data Structures:**
*   $\pi$: Target scene parameters. Structure depends on the renderer (e.g., mesh vertices, BSDF coefficients, light positions).
*   $\pi'$: Optimized scene parameters. Initialized from a different state (e.g., different shape like a sphere instead of a dragon) [S1, unofficial].
*   $z = NN(f(\pi))$: Latent representation of the target views.
*   $z' = NN(f(\pi'))$: Latent representation of the optimized views.

**Numbered Steps:**
1.  **Sample Camera Positions:** Sample camera positions on the unit sphere to define a set of views for the target scene [S1, unofficial].
2.  **Render Target Views:** Render the set of views for the target scene using the differentiable rendering function $f(\pi)$ with known parameters $\pi$ [S1, unofficial].
3.  **Initialize Optimized Scene:** Initialize a new scene from a different state $\pi'$ (e.g., different geometry) [S1, unofficial].
4.  **Render Optimized Views:** Render the same set of views for the initialized scene using $f(\pi')$ [S1, unofficial].
5.  **Extract Latents:** Pass both rendered image sets through the frozen neural network $NN(\cdot)$ to obtain latent representations $z$ and $z'$ [S1, unofficial].
6.  **Compute Loss:** Compute the optimization objective as the distance (e.g., mean squared error) between the latent representations $z$ and $z'$ [S1, unofficial].
7.  **Backpropagate:** Compute the gradient of the latent loss with respect to the scene parameters $\pi'$ and backpropagate through the differentiable renderer [S1, unofficial].
8.  **Update Parameters:** Update the target scene parameters $\pi'$ using gradient descent while holding other parameters (e.g., lighting) constant [S1, unofficial].

**Formulas:**
The loss is defined as the distance between latent representations:
$$ \mathcal{L}(z, z') $$
The gradient is computed with respect to the optimized scene parameters:
$$ \frac{\partial \mathcal{L}(z, z')}{\partial \pi'} $$
The full optimization loop minimizes $\mathcal{L}$ by updating $\pi'$ [S1, unofficial].

**Parameters:**
*   $\pi$: Target scene parameters (geometry, material, lighting) [S1, unofficial].
*   $\pi'$: Initialized scene parameters to be optimized [S1, unofficial].
*   $NN(\cdot)$: Frozen neural network (e.g., CLIP, ResNet-50, LPIPS) [S1, unofficial].
*   $f(\cdot)$: Physically based differentiable rendering function [S1, unofficial].

**Pitfalls:**
*   Discontinuities arising from changes in lighting or geometric edges can interfere with or bias gradients, making convergence challenging [S1, unofficial].
*   Mitigating these discontinuities and making PBDR computationally tractable are active research areas [S1, unofficial].

**Pseudocode:**
```python
def mrd_optimize(target_scene_params, frozen_network, renderer, num_iterations, learning_rate):
    """
    Optimizes scene parameters to find a metamer for a target scene.
    
    Args:
        target_scene_params: Known parameters pi defining the ground-truth scene.
        frozen_network: NN(·) used to extract latent representations.
        renderer: f(·) physically based differentiable rendering function.
        num_iterations: Number of gradient descent steps.
        learning_rate: Step size for gradient descent.
        
    Returns:
        optimized_params: Optimized parameters pi' forming a metamer.
    """
    # Step 1 & 2: Render target views
    # Sample camera positions on the unit sphere (implementation specific to renderer)
    camera_positions = sample_unit_sphere_views()
    
    # Render target views using known parameters pi
    target_images = renderer.render(target_scene_params, camera_positions)
    
    # Extract target latents
    target_latents = frozen_network(target_images)
    
    # Step 3: Initialize optimized scene from a different state pi'
    # Example: Initialize with a sphere if target is a dragon
    optimized_params = initialize_different_scene(target_scene_params)
    
    for i in range(num_iterations):
        # Step 4: Render optimized views
        optimized_images = renderer.render(optimized_params, camera_positions)
        
        # Step 5: Extract optimized latents
        optimized_latents = frozen_network(optimized_images)
        
        # Step 6: Compute loss (e.g., MSE between latents)
        loss = mean_squared_error(target_latents, optimized_latents)
        
        # Step 7: Compute gradient and backpropagate
        # Gradient is computed w.r.t optimized_params through the renderer and network
        gradients = compute_gradients(loss, optimized_params)
        
        # Step 8: Update parameters
        # Hold other parameters (e.g., lighting) constant if needed
        optimized_params = update_parameters(optimized_params, gradients, learning_rate)
        
    return optimized_params
```

## Operating characteristics
*   **Time Complexity:** Dependent on the number of iterations, number of views, and the cost of differentiable rendering and network inference. PBDR is computationally expensive [S1, unofficial].
*   **Memory Complexity:** Requires storing gradients for all optimized parameters and intermediate rendering buffers [S1, unofficial].
*   **Strengths:** Enables targeted probing of neural network understanding of scene properties by separating physical causes; reconstructions are grounded in physical scene descriptions [S1, unofficial].
*   **Limitations:** Convergence is challenging due to discontinuities in lighting and geometry; computationally intensive [S1, unofficial].
*   **When to use:** When probing vision models for 3D scene understanding, specifically investigating material appearance (BSDF) and shape recovery [S1, unofficial].
*   **When not to use:** When computational resources are limited or when physical grounding of the reconstruction is not required [S1, unofficial].

## Background
*   **Origin:** Introduced by Benjamin Beilharz and Thomas S. A. Wallis from the Perception Lab, Centre for Cognitive Science, Technical University of Darmstadt, and the Center for Mind, Brain and Behavior (CMBB) [S1, unofficial].
*   **History:** Presented as a proof of concept for using physically based differentiable rendering to probe vision models [S1, unofficial].
*   **Usage:** Applied to probe vision models (CLIP, DINO, ResNet-50, ResNet-50-SIN, LPIPS) for 3D scene understanding [S1, unofficial].
