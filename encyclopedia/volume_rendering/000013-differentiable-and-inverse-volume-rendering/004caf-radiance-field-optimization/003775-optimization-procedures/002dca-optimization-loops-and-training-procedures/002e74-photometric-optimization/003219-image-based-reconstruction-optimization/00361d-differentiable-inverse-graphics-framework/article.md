# Differentiable Inverse Graphics Framework

Also called: Analysis-by-synthesis with differentiable rendering, Differentiable Inverse Rendering for Joint Reconstruction, End-to-end differentiable inverse graphics, Inverse parameter optimization pipeline, Joint geometry and reflectance reconstruction

## Overview
The Differentiable Inverse Graphics Framework simultaneously reconstructs 3D geometry, diffuse/specular reflectance, and environment lighting from multi-view photography by minimizing photometric error in a differentiable rendering framework [S1, S2, unofficial]. It solves the inverse problem of inferring latent scene parameters $\theta$ by treating rendering as a differentiable function $R(\theta)$, enabling gradient-based optimization of geometry, materials, and lighting [S2, unofficial]. Unlike sibling methods that may rely on shape priors or specific ray-tracing accelerations, this framework explicitly alternates optimization over distinct parameter sets (geometry, diffuse, specular, lighting) to manage GPU memory and handle the ill-posed nature of joint reconstruction [S1, unofficial]. It builds on [Image-based reconstruction optimization](6677-image-based-reconstruction-optimization.md) by providing a concrete implementation for joint geometry-reflectance-lighting optimization using a physically-based differentiable renderer [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of RGB images $I = \{I_k\}$ from arbitrary viewpoints [S1, unofficial].
*   **Output:** Optimized scene parameters $\theta = \{\theta_g, \theta_d, \theta_s, \theta_l\}$ representing geometry, diffuse reflectance, specular reflectance, and lighting, respectively [S1, unofficial].

**Data Structures:**
The scene is represented by a virtual mesh and lighting parameters:
*   $\theta_g$: Set of 3D positions corresponding to mesh vertices $\{x_0, \dots, x_N\}$ [S1, unofficial].
*   $\theta_d$: Set of diffuse per-vertex color reflectances $\{\theta_d(x_0), \dots, \theta_d(x_N)\}$, where $\theta_d(x) \in \mathbb{R}^3$ [S1, unofficial].
*   $\theta_s$: Set of specular reflectance parameters [S1, unofficial].
*   $\theta_l$: Set of isotropic point sources for environment lighting $\{l_0, l_1, \dots, l_M\}$, where $l_n$ is the intensity of the $n$-th light source [S1, unofficial].
*   $M_k$: Binary mask for the $k$-th view, generated by GrabCut segmentation, to remove background pixel contribution [S1, unofficial].

**Rendering Model:**
The image formation for a pixel $u$ is given by:
$$ I(u) = L(\omega_o; x) \Delta t $$
where $x \in \mathbb{R}^3$ is the 3D coordinate, $\omega_o$ is the outgoing direction, $L$ is the radiance, and $\Delta t$ is the exposure time [S1, unofficial]. The radiance $L_o$ from a non-emitting object follows the rendering equation:
$$ L_o(x, \omega_o) = L_e(x, \omega_o) + \int_{\Omega} f_r(x, \omega_i, \omega_o) L_i(x, \omega_i) (n \cdot \omega_i) d\omega_i $$
where $L_e$ is emitted radiance, $f_r$ is the BRDF, $L_i$ is incoming radiance, $n$ is the surface normal, and $\Omega$ is the hemisphere of incoming directions [S2, unofficial]. The environment lighting is approximated as a set of isotropic point sources, and ray tracing iteratively bounces light up to $T$ times [S1, unofficial].

**Optimization Loop:**
The framework minimizes the photometric error between observed images and rendered images. Due to limited GPU memory, it uses an alternating optimization strategy [S1, unofficial].

1.  **Initialization:** Initialize virtual scene parameters roughly matching the real world using Colmap [S1, unofficial]. Set initial light radiance to 0.5 [S1, unofficial].
2.  **Loss Calculation:** Compute the objective function:
    $$ \mathcal{O} = \sum_{k=1}^K \| M_k I_k - \Phi_k(\theta_g, \theta_d, \theta_s, \theta_l) \|_2^2 $$
    where $\Phi_k$ is the rendering function for view $k$ [S1, unofficial].
3.  **Alternating Update:** Iteratively update one parameter set $\theta \in \{\theta_d, \theta_g, \theta_s, \theta_l\}$ while keeping others unchanged [S1, unofficial].
4.  **Gradient Step:** Use the Adam optimizer to update the selected parameters based on gradients backpropagated through the differentiable renderer (Mitsuba2) [S1, unofficial].
5.  **Repeat:** Continue until convergence or maximum iterations [S1, unofficial].

**Parameters and Typical Values:**
*   $T$: Maximum number of ray bounces. Value: 3 [S1, unofficial].
*   $spp$: Samples per pixel. Value: 1 for iterative optimization, 16 for final output [S1, unofficial].
*   $\alpha$: Surface roughness parameter. Value: 0.1 [S1, unofficial].
*   Optimizer: Adam [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Background Dominance:** Background pixels can dominate the objective value. Solution: Use precomputed binary masks $M_k$ from GrabCut segmentation [S1, unofficial].
*   **GPU Memory:** Physically-based rendering is memory-intensive. Solution: Alternate parameter updates, downsample raw images 8x, and use $spp=1$ during optimization [S1, unofficial].
*   **Visibility Discontinuities:** Silhouette edges cause gradient issues. Handled by MC edge sampling, area-sampling, or thin-band relaxed indicators [S2, unofficial].

## Subtopics

### [Differentiable Re-rendering Module](14687-differentiable-re-rendering-module.md)
The Differentiable Re-rendering Module is a raytracing-based differentiable renderer that uses a Volumetric Spherical Gaussian (VSG) lighting representation and predicted intrinsic properties (albedo, normals, depth) to re-render an input image, enforcing an energy-conserving image formation process. It provides supervision via re-rendering error, ensuring that predicted geometry and reflectance are physically correct by enforcing that the input image should be retrieved if the predictions are re-rendered. It sets itself apart from sibling methods by enabling the estimation of a complete continuous light field function, including HDR and high-frequency spatial and angular details, despite being trained with only LDR images.

### [Physically Based Differentiable Rendering](14937-physically-based-differentiable-rendering.md)
Physically Based Differentiable Rendering (PBDR) is a rendering approach that differentiates through physically based integrators, such as path tracing, to preserve derivatives of light transport operations. It solves the inverse rendering problem by enabling gradient-based optimization to estimate latent 3D scene parameters (geometry, materials, lighting) from observed images. Unlike rasterization-based differentiable renderers, PBDR preserves the physical accuracy of the rendering equation, allowing for the optimization of complex material properties and lighting conditions.

### Neural Programmatic Scene Code Pipeline
A pipeline where an image is encoded into a discrete scene program (geometry, materials, arrangements) via an encoder and LLM/programmatic decoder, which is then rendered by any downstream renderer [S2, unofficial]. Training is performed purely on code or numeric losses, not image losses, allowing the discrete scene program to be optimized [S2, unofficial]. The pipeline flow is: $I \xrightarrow{\Phi} E \xrightarrow{f_\theta} (s_1, ..., s_N) \xrightarrow{h} S$, where $I$ is input image, $E$ is encoded representation, $f_\theta$ generates scene tokens/parameters $s_i$, and $h$ renders scene program $S$ [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Runtime is approximately 140ms per iteration [S1, unofficial]. Total iterations are around 400 per viewpoint [S1, unofficial].
*   **Memory Complexity:** High GPU memory usage due to physically-based rendering. Mitigated by alternating optimization, 8x downsampling, and low spp (1) during training [S1, unofficial].
*   **Performance:** Physics-based MC approaches achieve low reconstruction errors (RE≈0.0087 vs Mitsuba's 0.0102) and normal MAE of 9.81° with sparse Gaussian basis [S2, unofficial]. Point-based splatting and hybrid methods achieve PSNR 38–43 dB and normal MAE ≈4–11° [S2, unofficial].
*   **Strengths:** Enables photo-realistic novel view synthesis, environment light editing, and joint reconstruction of geometry and reflectance in uncontrolled environments [S1, unofficial].
*   **Limitations:** Limited by GPU memory for high-resolution scenes; requires careful handling of visibility discontinuities; alternating optimization may slow convergence compared to joint updates if memory permits [S1, S2, unofficial].
*   **When to Use:** When joint reconstruction of geometry, materials, and lighting from multi-view images is required, and physical accuracy is prioritized over speed [S1, unofficial].
*   **When Not to Use:** When real-time performance is critical, or when scene geometry is extremely high-genus or strongly non-Lambertian without appropriate BRDF modeling [S2, unofficial].

## Background
The Differentiable Inverse Graphics Framework originates from the need to reconstruct 3D geometry and reflectance in uncontrolled environments using conventional hand-held cameras [S1, unofficial]. The method was proposed by Li et al. (2021) and implemented using the Mitsuba2 differentiable renderer [S1, unofficial]. It builds on the principles of analysis-by-synthesis and differentiable rendering, leveraging gradient backpropagation to optimize scene parameters [S2, unofficial]. Initial geometry is typically obtained using Structure-from-Motion (SfM) tools like Colmap [S1, unofficial]. The framework has been extended to include neural surrogates and hybrid methods for improved gradient estimation and scalability [S2, unofficial].
