# Differentiable Inverse Graphics Framework

Also called: Analysis-by-synthesis with differentiable rendering, Differentiable Inverse Rendering for Joint Reconstruction, End-to-end differentiable inverse graphics, Inverse parameter optimization pipeline, Joint geometry and reflectance reconstruction

## Overview
The Differentiable Inverse Graphics Framework simultaneously reconstructs 3D geometry, diffuse/specular reflectance, and environment lighting from multi-view photography by minimizing photometric error in a differentiable rendering pipeline [S1, S2, unofficial]. It solves the inverse problem of inferring latent scene parameters $\theta$ by treating rendering as a differentiable function $R(\theta)$, enabling gradient-based optimization of physical scene properties [S2, unofficial]. Unlike methods that rely on explicit ground-truth lighting or non-differentiable approximators, this framework enforces an energy-conserving image formation process, allowing the estimation of complete continuous HDR light fields from single LDR images while jointly optimizing intrinsic scene properties [S1, unofficial]. It builds on [Image-based reconstruction optimization](6677-image-based-reconstruction-optimization.md) by providing a specific parameterization for geometry, materials, and lighting within a physics-based Monte Carlo path tracer.

## How it works
**Inputs and Outputs**
*   **Input:** A set of RGB images $I = \{I_k\}$ from arbitrary viewpoints $k=1 \dots K$, captured with auto-focus and ordinary ambient/diffuse light [S1, unofficial].
*   **Output:** Optimized scene parameters $\theta = \{\theta_g, \theta_d, \theta_s, \theta_l\}$ representing geometry, diffuse reflectance, specular reflectance, and lighting, enabling novel view synthesis and lighting editing [S1, unofficial].

**Data Structures**
The scene is represented by a parametric vector $\theta$ containing:
1.  **Geometry ($\theta_g$):** Set of 3D positions corresponding to mesh vertices $\{x_0, \dots, x_N\}$ [S1, unofficial].
2.  **Diffuse Reflectance ($\theta_d$):** Set of per-vertex color reflectances $\{\theta_d(x_0), \dots, \theta_d(x_N)\}$, where $\theta_d(x) \in \mathbb{R}^3$ [S1, unofficial].
3.  **Specular Reflectance ($\theta_s$):** Set of specular reflectance parameters [S1, unofficial].
4.  **Lighting ($\theta_l$):** Set of isotropic point sources for environment lighting $\{l_0, l_1, \dots, l_M\}$, where $l_n$ is the intensity of the $n$-th light source [S1, unofficial].

**Parameters**
*   **T:** Maximum number of ray bounces. Value: 3 [S1, unofficial].
*   **spp:** Samples per pixel. Value: 1 for iterative optimization, 16 for final output [S1, unofficial].
*   **$\alpha$:** Surface roughness parameter. Value: 0.1 [S1, unofficial].
*   **$\Delta t$:** Exposure time of the camera [S1, unofficial].
*   **$M_k$:** Binary mask to remove background pixel contribution, generated by GrabCut segmentation [S1, unofficial].
*   **Optimizer:** Adam [S1, unofficial].
*   **Learning Rates:** $\lambda_d = 0.1, \lambda_g = 0.5, \lambda_s = 0.01, \lambda_l = 0.05$ [S1, unofficial].

**Formulas**
The image formation model for a pixel coordinate $u$ is:
$$ I(u) = L(\boldsymbol{\omega}_o; x) \Delta t $$
where $x \in \mathbb{R}^3$ is the 3D coordinate, $\boldsymbol{\omega}_o$ is the outgoing direction, and $L$ is the radiance [S1, unofficial].

The radiance of a non-emitting object is given by the rendering equation:
$$ L_o(\boldsymbol{\omega}_o; x) = \int_{\Omega} f_r(x, \boldsymbol{\omega}_i, \boldsymbol{\omega}_o) L_i(\boldsymbol{\omega}_i; x) (\boldsymbol{\omega}_i \cdot n(x)) \, d\boldsymbol{\omega}_i $$
where $L_o$ is outgoing radiance, $L_i$ is incoming radiance, $f_r$ is the BRDF, $n(x)$ is the surface normal, and $\Omega$ is the hemisphere of incoming directions [S1, S2, unofficial].

The optimization minimizes the objective function:
$$ \mathcal{O} = \sum_{k=1}^K \| M_k I_k - \Phi_k(\theta_g, \theta_d, \theta_s, \theta_l) \|_2^2 $$
where $\Phi_k$ is the physically-based rendering process for view $k$, and $M_k$ masks out background pixels [S1, unofficial].

**Steps**
1.  **Initialization:** Initialize virtual scene parameters roughly matching the real world using Colmap to estimate initial geometry and camera poses [S1, unofficial]. Set initial light source radiance to 0.5 [S1, unofficial].
2.  **Differentiable Rendering:** Render the scene using a physically-based renderer (e.g., Mitsuba2) to produce synthetic images $\hat{I}_k = \Phi_k(\theta)$ [S1, unofficial].
3.  **Loss Computation:** Compute the photometric error between the masked observed images $M_k I_k$ and the rendered images $\hat{I}_k$ using the L2 norm [S1, unofficial].
4.  **Gradient Backpropagation:** Compute gradients of the loss with respect to the scene parameters $\theta$ via automatic differentiation through the differentiable renderer [S1, S2, unofficial].
5.  **Alternate Optimization:** Iteratively update one parameter set $\theta \in \{\theta_d, \theta_g, \theta_s, \theta_l\}$ while keeping others unchanged, using the Adam optimizer [S1, unofficial].
6.  **Iteration:** Repeat steps 2–5 for a maximum of 400 iterations per viewpoint [S1, unofficial].
7.  **Final Output:** Render final images with higher sampling (spp=16) [S1, unofficial].

**Pseudocode**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
import torch
from torch import optim
from mitsuba.core import Vector3f, ScalarVector3f
from mitsuba.render import Scene, Camera, Film
from mitsuba.python.autodiff import DifferentiableScene

def initialize_scene(images, colmap_data):
    """
    Initialize geometry, materials, and lighting from Colmap and image data.
    Returns: theta_g, theta_d, theta_s, theta_l
    """
    # Extract mesh vertices from Colmap
    theta_g = colmap_data.vertices 
    
    # Initialize diffuse colors from image averages or white
    theta_d = torch.ones_like(theta_g) * 0.5
    
    # Initialize specular reflectance (simplified)
    theta_s = torch.zeros_like(theta_g)
    
    # Initialize lighting as isotropic point sources
    theta_l = torch.ones(1) * 0.5
    
    return theta_g, theta_d, theta_s, theta_l

def render_scene(theta_g, theta_d, theta_s, theta_l, camera, scene_params):
    """
    Render the scene using Mitsuba2 differentiable renderer.
    Returns: rendered_image
    """
    # Update scene parameters in Mitsuba
    # Note: This requires binding PyTorch tensors to Mitsuba parameters
    # via the DifferentiableScene interface.
    
    # Set geometry vertices
    scene_params.geometry.set_vertices(theta_g)
    
    # Set material colors
    scene_params.material.set_diffuse_color(theta_d)
    scene_params.material.set_specular_reflectance(theta_s)
    
    # Set lighting intensities
    scene_params.light.set_intensity(theta_l)
    
    # Render
    film = scene_params.film
    film.clear()
    scene_params.camera.render(film)
    
    # Extract image tensor
    rendered_image = film.buffer().numpy()
    
    return rendered_image

def optimize(images, masks, num_iterations=400):
    """
    Main optimization loop.
    """
    # Initialize parameters
    theta_g, theta_d, theta_s, theta_l = initialize_scene(images, colmap_data)
    
    # Create optimizers for each parameter set
    opt_g = optim.Adam([theta_g], lr=0.5)
    opt_d = optim.Adam([theta_d], lr=0.1)
    opt_s = optim.Adam([theta_s], lr=0.01)
    opt_l = optim.Adam([theta_l], lr=0.05)
    
    # Downsample images for optimization
    images_ds = [torch.tensor(img).permute(2, 0, 1) / 255.0 for img in images]
    masks_ds = [torch.tensor(mask).unsqueeze(0) for mask in masks]
    
    for iteration in range(num_iterations):
        # Alternate optimization: update one parameter set at a time
        # Update Geometry
        opt_g.zero_grad()
        rendered_g = render_scene(theta_g, theta_d, theta_s, theta_l, camera, scene_params)
        loss_g = sum(torch.sum((m * (img - rend))**2) for img, m, rend in zip(images_ds, masks_ds, rendered_g))
        loss_g.backward()
        opt_g.step()
        
        # Update Diffuse Reflectance
        opt_d.zero_grad()
        rendered_d = render_scene(theta_g, theta_d, theta_s, theta_l, camera, scene_params)
        loss_d = sum(torch.sum((m * (img - rend))**2) for img, m, rend in zip(images_ds, masks_ds, rendered_d))
        loss_d.backward()
        opt_d.step()
        
        # Update Specular Reflectance
        opt_s.zero_grad()
        rendered_s = render_scene(theta_g, theta_d, theta_s, theta_l, camera, scene_params)
        loss_s = sum(torch.sum((m * (img - rend))**2) for img, m, rend in zip(images_ds, masks_ds, rendered_s))
        loss_s.backward()
        opt_s.step()
        
        # Update Lighting
        opt_l.zero_grad()
        rendered_l = render_scene(theta_g, theta_d, theta_s, theta_l, camera, scene_params)
        loss_l = sum(torch.sum((m * (img - rend))**2) for img, m, rend in zip(images_ds, masks_ds, rendered_l))
        loss_l.backward()
        opt_l.step()
        
    return theta_g, theta_d, theta_s, theta_l
```

**Edge Cases and Pitfalls**
*   **Background Dominance:** Background pixels can dominate the objective value if not masked. Solution: Use precomputed binary masks $M_k$ from GrabCut segmentation [S1, unofficial].
*   **GPU Memory:** Physically-based rendering is GPU memory-intensive. Solution: Alternate between updating each parameter while keeping others unchanged; downsample raw images 8x; use spp=1 during optimization [S1, unofficial].
*   **Visibility Discontinuities:** Silhouette edges cause gradient issues. Handled by MC edge sampling, area-sampling, or thin-band relaxed indicators [S2, unofficial].

## Subtopics

### [Differentiable Re-rendering Module](14687-differentiable-re-rendering-module.md)
The Differentiable Re-rendering Module is a raytracing-based differentiable renderer that enforces an energy-conserving image formation process to supervise the joint training of intrinsic scene properties (albedo, normals, depth) and lighting. It re-renders the input image using predicted intrinsic properties and a Volumetric Spherical Gaussian (VSG) lighting volume, computing a photometric error between the re-rendered output and the original input. Unlike methods that rely on explicit ground-truth lighting, this module enables the estimation of complete continuous HDR light fields from single LDR images by ensuring predictions are physically correct through re-rendering constraints. It builds on the [Differentiable Inverse Graphics Framework](7617-differentiable-inverse-graphics-framework.md) by providing a differentiable path from latent 3D parameters to pixel space.

### Neural Programmatic Scene Code Pipeline
A pipeline where an image is encoded into a discrete scene program (geometry, materials, arrangements) via an encoder and LLM/programmatic decoder, which is then rendered by any downstream renderer [S2, unofficial]. Training is performed purely on code or numeric losses, not image losses, allowing the discrete scene program to be optimized [S2, unofficial]. The pipeline flow is: $I \xrightarrow{\Phi} E \xrightarrow{f_\theta} (s_1, ..., s_N) \xrightarrow{h} S$, where $I$ is input image, $E$ is encoded representation, $f_\theta$ generates scene tokens/parameters $s_i$, and $h$ renders scene program $S$ [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** ~140ms per iteration [S1, unofficial]. Total iterations: 400 per viewpoint [S1, unofficial].
*   **Memory Complexity:** High, due to GPU memory consumption of physically-based rendering. Mitigated by alternating parameter updates and downsampling [S1, unofficial].
*   **Performance:** Physics-based MC approaches achieve low reconstruction errors (RE≈0.0087 vs Mitsuba's 0.0102) and normal MAE of 9.81° with sparse Gaussian basis [S2, unofficial]. Point-based splatting and hybrid methods achieve PSNR 38–43 dB and normal MAE ≈4–11° [S2, unofficial].
*   **Strengths:** Simultaneous reconstruction of geometry, reflectance, and lighting; physically plausible results; enables novel view synthesis and lighting editing [S1, unofficial].
*   **Limitations:** Limited GPU memory; requires multi-view input; sensitive to visibility discontinuities; initialization dependent on Colmap [S1, S2, unofficial].
*   **When to Use:** When high-fidelity, physically-based reconstruction of complex scenes with unknown lighting is required from multi-view photography [S1, unofficial].
*   **When Not to Use:** When real-time performance is critical; when only single-view input is available; when explicit ground-truth lighting is known and fixed [S1, S2, unofficial].

## Background
The Differentiable Inverse Graphics Framework originates from the work of Li et al. (2021), who proposed an efficient method to reconstruct scene geometry and reflectance from multi-view photography using conventional hand-held cameras [S1, unofficial]. The method automatically builds a virtual scene in a differentiable rendering system (Mitsuba2) and optimizes scene parameters by minimizing photometric objectives in an alternating and stochastic fashion [S1, unofficial]. The framework is part of the broader field of differentiable rendering, which enables gradient-based optimization of scene parameters by backpropagating rendering errors [S2, unofficial]. It builds on the principles of analysis-by-synthesis, where a synthetic model is iteratively refined to match observed data [S2, unofficial].
