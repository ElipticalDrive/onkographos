# Monocular Normal Regularization

Also called: Monocular Normal Loss, Omnidata Normal Supervision, Predicted Normal Loss (Monocular), Stable Normal supervision

## Overview
Monocular Normal Regularization is a geometric supervision technique that replaces noisy gradient-based normal estimates with smooth normal cues predicted by pretrained monocular foundation models [S1, S2]. It solves the problem of artifacts in rendered depth and normal maps, particularly in complex scenes, by providing stable geometric priors during radiance-field optimization [S1, S2]. Unlike sibling methods that rely on rendered depth gradients, this approach leverages external monocular networks (e.g., Omnidata, Stable Normal) to guide the optimization of scene geometry [S1, S2].

## How it works
**Inputs and Outputs:**
- **Inputs:** Rendered scene parameters (e.g., Gaussian splats or mesh vertices), camera poses, and intrinsics. Pretrained monocular normal prediction network (e.g., Omnidata [S1] or Stable Normal [S2]).
- **Outputs:** A scalar loss value $\mathcal{L}_{mono}$ used in the total training objective.

**Data Structures:**
- **Predicted Normals ($\boldsymbol{\hat{N}}$):** Per-pixel normal vectors derived from the scene representation.
    - For Gaussian Splatting [S1]: Normals are derived from the scaling and rotation of Gaussians. For a Gaussian $i$ with rotation matrix $R_i \in SO(3)$ and scaling coefficients $s_i \in \mathbb{R}^3$, the normal direction is approximated by the axis with the smallest scale:
      $$ \boldsymbol{\hat{n}}_i = R_i \cdot \text{OneHot}(\arg\min(s_{i,1}, s_{i,2}, s_{i,3})) $$
    - For Mesh-based representations [S2]: Normals are typically vertex or face normals from the explicit mesh.
- **Monocular Normal Cues ($\boldsymbol{N}$):** Per-pixel normal vectors predicted by the monocular network from the input RGB image.

**Numbered Steps:**
1. **Render Scene:** Render the current scene representation to obtain an RGB image and, if necessary, a depth map.
2. **Predict Monocular Normals:** Pass the rendered RGB image (or the original input image if the network is trained on input views) through the pretrained monocular normal network to obtain $\boldsymbol{N}$.
3. **Compute Scene Normals:** Extract per-pixel normals $\boldsymbol{\hat{N}}$ from the scene representation (e.g., via Gaussian scaling axes or mesh normals).
4. **Compute Loss:** Calculate the regularization loss based on the discrepancy between $\boldsymbol{\hat{N}}$ and $\boldsymbol{N}$.

**Formulas:**
Two primary formulations are cited in the sources:

1. **L1 Loss [S1]:**
   $$ \mathcal{L}_{\hat{N}} = \frac{1}{|\hat{N}|} \sum \| \boldsymbol{\hat{N}} - \boldsymbol{N} \|_1 $$
   where $|\hat{N}|$ is the number of pixels in the normal map.

2. **Margin-based Loss [S2]:**
   $$ L_n = \sum \max(\| \boldsymbol{N} - \boldsymbol{\hat{N}} \| - m, 0) $$
   where $m$ is a small margin to handle inherent normal inconsistency across different views produced by monocular foundational models.

**Parameters:**
- **Margin ($m$):** A small scalar value used in the margin-based loss [S2]. Not given in the sources.
- **Weight ($\lambda_n$):** The weight of the monocular normal loss in the total training objective. Not given in the sources.

**Edge Cases and Pitfalls:**
- **Normal Inconsistency:** Monocular models may produce inconsistent normals across different views. The margin $m$ in [S2] helps mitigate this.
- **Depth Noise:** Using gradients of rendered depths for supervision can result in artifacts, especially in complex scenes [S1]. Monocular cues provide smoother estimates.
- **Gaussian Flatness:** In Gaussian Splatting, Gaussians are expected to become flat, disc-like, with one scaling axis much smaller than the other two. This assumption is critical for the normal derivation [S1].

**Pseudocode:**
```python
def monocular_normal_regularization(scene_representation, camera, rgb_image, monocular_network, loss_type='l1', margin=0.0):
    """
    Computes the monocular normal regularization loss.
    
    Args:
        scene_representation: Object containing scene parameters (e.g., Gaussians or mesh).
        camera: Camera parameters (pose, intrinsics).
        rgb_image: Rendered or input RGB image.
        monocular_network: Pretrained monocular normal prediction network.
        loss_type: 'l1' or 'margin'.
        margin: Margin value for margin-based loss.
        
    Returns:
        loss: Scalar loss value.
    """
    # Step 1: Predict monocular normals
    # Note: In [S1], Omnidata is used. In [S2], Stable Normal is used.
    # The input to the network is typically the RGB image.
    N_monocular = monocular_network(rgb_image)
    
    # Step 2: Compute scene normals
    # This depends on the scene representation.
    # For Gaussian Splatting [S1]:
    if scene_representation.type == 'gaussian':
        N_scene = compute_gaussian_normals(scene_representation)
    # For Mesh [S2]:
    elif scene_representation.type == 'mesh':
        N_scene = compute_mesh_normals(scene_representation)
    else:
        raise ValueError("Unsupported scene representation type")
    
    # Step 3: Compute loss
    if loss_type == 'l1':
        # L1 loss [S1]
        # |N| is the number of pixels
        num_pixels = N_scene.shape[0] * N_scene.shape[1]
        loss = torch.mean(torch.abs(N_scene - N_monocular))
    elif loss_type == 'margin':
        # Margin-based loss [S2]
        diff = torch.norm(N_scene - N_monocular, dim=-1)
        loss = torch.mean(torch.clamp(diff - margin, min=0))
    else:
        raise ValueError("Unsupported loss type")
        
    return loss

def compute_gaussian_normals(gaussians):
    """
    Computes normals from Gaussian splats [S1].
    """
    # Get rotation matrices from quaternions
    R = quaternions_to_rotation_matrices(gaussians.quaternions)
    # Get scaling coefficients
    s = gaussians.scales
    
    # Find the index of the smallest scale for each Gaussian
    min_scale_indices = torch.argmin(s, dim=1)
    
    # Create one-hot vectors for the smallest scale axis
    # OneHot(k) is a vector with 1 at index k and 0 elsewhere
    one_hot = torch.zeros_like(s)
    one_hot.scatter_(1, min_scale_indices.unsqueeze(1), 1)
    
    # Compute normals: R * OneHot
    # This assumes R is (N, 3, 3) and one_hot is (N, 3)
    normals = torch.bmm(R, one_hot.unsqueeze(2)).squeeze(2)
    
    # Normalize to ensure unit length
    normals = torch.nn.functional.normalize(normals, dim=1)
    
    return normals
```

## Subtopics

### Omnidata Normal Supervision
Uses Omnidata [S1] for monocular normal prediction. Chosen when smoother normal estimates are needed compared to depth gradients.

### Stable Normal Supervision
Uses Stable Normal [S2] for monocular normal prediction. Chosen when a margin-based loss is preferred to handle view inconsistency.

## Operating characteristics
- **Time Complexity:** Depends on the inference time of the monocular network. Typically adds significant overhead to the training loop as the network must be run for each view.
- **Memory Complexity:** Requires storing the monocular normal maps and scene normals.
- **Strengths:** Provides smooth geometric priors, reducing artifacts in complex scenes [S1]. Improves surface quality in mesh refinement [S2].
- **Limitations:** Relies on the accuracy of the pretrained monocular network. May introduce bias if the monocular predictions are incorrect.
- **When to use:** When rendered depth gradients are noisy or when high-quality geometric priors are needed for surface reconstruction.
- **When not to use:** When computational resources are limited, or when the monocular network is not available.

## Background
Monocular Normal Regularization was introduced to address the limitations of using gradients of rendered depths for normal supervision [S1, S2]. It leverages pretrained monocular foundation models like Omnidata [S1] and Stable Normal [S2] to provide robust geometric cues. This approach has been used in Gaussian Splatting [S1] and joint mesh-Gaussian optimization [S2] for scene reconstruction.
