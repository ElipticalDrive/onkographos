# Normal Ground Truth Alignment Loss

Also called: Normal GT Alignment Loss, Normal GT Loss, Training Loss Functions

## Overview
The Normal Ground Truth Alignment Loss is a regularization term in differentiable inverse rendering that supervises predicted surface normals against available ground truth normals by minimizing their angular deviation [S1][S2, unofficial]. It differs from sibling methods like [Normal Ray Alignment Loss](4202-normal-ray-alignment-loss.md) and [Predicted Normal Loss](7713-predicted-normal-loss.md) by directly comparing network outputs to explicit geometric targets rather than enforcing internal consistency or ray alignment [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   $\mathbf{n}_p$: The predicted normal vector at the current sample point or pixel [S2, unofficial].
    *   $\mathbf{n}_{gt}$: The ground truth normal vector corresponding to the same spatial location [S2, unofficial].
    *   $w$: A scalar weight controlling the influence of this loss term [S2, unofficial].
*   **Outputs:**
    *   $L$: The scalar loss value to be minimized [S2, unofficial].

**Data Structures:**
*   Vectors $\mathbf{n}_p$ and $\mathbf{n}_{gt}$ are typically 3D vectors $(x, y, z)$ [G].
*   In implementations using the angular error formulation, the predicted normal must be explicitly normalized before the dot product [S1].

**Steps:**
1. Retrieve the predicted normal $\mathbf{n}_p$ and ground truth normal $\mathbf{n}_{gt}$ for the current sample or pixel [G].
2. Normalize the predicted normal to unit length: $\hat{\mathbf{n}}_p = \frac{\mathbf{n}_p}{\|\mathbf{n}_p\|}$ [S1].
3. Compute the dot product between the normalized predicted normal and the ground truth normal: $d = \hat{\mathbf{n}}_p \cdot \mathbf{n}_{gt}$ [S1][S2, unofficial].
4. Clamp the dot product $d$ to the range $[-1, 1]$ to handle numerical precision errors that might cause $\arccos$ to fail [G].
5. Calculate the angular error in radians: $\theta = \arccos(d)$ [S1].
6. Compute the loss using the L1 norm over the batch or pixels and apply the scalar weight: $L = w \cdot \|\theta\|_1$ [S1][S2, unofficial].

**Formula:**
The primary formulation uses the L1 angular error between the normalized predicted normal and the ground truth normal [S1]:

$$
L_{normal} = \left\| \cos^{-1} \left( \frac{\mathbf{n}_p}{\|\mathbf{n}_p\|} \cdot \mathbf{n}_{gt} \right) \right\|_1
$$

Where:
*   $\mathbf{n}_p$ is the predicted normal [S1].
*   $\mathbf{n}_{gt}$ is the ground truth normal [S1].
*   $\|\mathbf{n}_p\|$ is the magnitude of the predicted normal [S1].
*   $\|\cdot\|_1$ denotes the L1 norm applied over the batch or pixels [S1].

An alternative weighted formulation uses the dot product directly [S2, unofficial]:

$$
L = w \cdot (1 - \mathbf{n}_p \cdot \mathbf{n}_{gt})
$$

**Parameters:**
*   $w$: Float scalar weight. Typical value is 1.0 [S2, unofficial].
*   $\lambda_N$: Weight for the normal loss term in the total multi-task loss function. Value not given in the sources [G].

**Edge Cases and Pitfalls:**
*   **Normalization:** The predicted normal must be normalized before computing the dot product in the angular error formulation to ensure the input to $\arccos$ is valid [S1].
*   **Numerical Stability:** The dot product result must be clamped to $[-1, 1]$ before passing to $\arccos$ to avoid NaNs due to floating-point inaccuracies [G].
*   **Orientation Consistency:** Ground truth normals must be consistently oriented (e.g., pointing outward from the surface) relative to the camera or world space to avoid minimizing the angle to the opposite direction [G].

**Pseudocode:**
```python
import torch

def normal_ground_truth_alignment_loss(predicted_normals, ground_truth_normals, weight=1.0):
    """
    Computes the Normal Ground Truth Alignment Loss.
    
    Args:
        predicted_normals (torch.Tensor): Tensor of shape (..., 3) containing predicted normal vectors.
        ground_truth_normals (torch.Tensor): Tensor of shape (..., 3) containing ground truth normal vectors.
        weight (float): Scalar weight for the loss term. Default 1.0.
        
    Returns:
        torch.Tensor: Scalar loss value.
    """
    # 1. Normalize predicted normals to unit length
    eps = 1e-8
    predicted_normalized = predicted_normals / (torch.norm(predicted_normals, dim=-1, keepdim=True) + eps)
    
    # 2. Compute dot product between normalized predicted and ground truth normals
    dot_product = torch.sum(predicted_normalized * ground_truth_normals, dim=-1)
    
    # 3. Clamp dot product to [-1, 1] for numerical stability in arccos
    dot_product = torch.clamp(dot_product, -1.0 + eps, 1.0 - eps)
    
    # 4. Compute angular error in radians
    angular_error = torch.acos(dot_product)
    
    # 5. Apply L1 norm over all elements and scale by weight
    loss = weight * torch.sum(angular_error)
    
    return loss
```

## Subtopics

### Normal Ray Alignment Loss
Aligns predicted normals with the viewing ray direction rather than ground truth [G]. Useful when ground truth normals are unavailable [G]. [Link](4202-normal-ray-alignment-loss.md)

### Predicted Normal Loss
Enforces consistency between normals predicted by different network branches or at different scales [G]. Useful for self-supervised scenarios [G]. [Link](7713-predicted-normal-loss.md)

## Background
The Normal Ground Truth Alignment Loss originates from work on indoor inverse rendering, specifically in the context of learning 3D spatially-varying lighting and geometry [S1]. It was introduced as part of a multi-task loss framework that jointly optimizes albedo, normals, depth, and lighting parameters [S1]. The method leverages the differentiability of the rendering equation to backpropagate gradients from the normal loss to the underlying scene representation [G].
