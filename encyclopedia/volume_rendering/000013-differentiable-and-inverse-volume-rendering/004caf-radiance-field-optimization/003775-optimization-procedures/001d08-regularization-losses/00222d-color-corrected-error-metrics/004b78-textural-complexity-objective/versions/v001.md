# Textural Complexity Objective


## Overview
The Textural Complexity Objective ($T$) is a metric used in active view planning for radiance-field optimization to identify camera poses that capture regions with high photometric variation [S1, unofficial]. Unlike geometric metrics that analyze 3D mesh structure, $T$ operates on 2D image projections, leveraging the fact that textural characteristics are readily discernible in 2D even if 3D geometry is ambiguous [S1, unofficial]. It serves as a component of Color-Corrected Error Metrics, helping to mitigate photometric variations such as autoexposure shifts or white balance changes in "in the wild" datasets by prioritizing views with rich texture [S1, unofficial].

## How it works
The method computes a complexity score for an image captured at a specific camera pose. The core idea is that images with higher textural complexity (more unique local patterns) provide more information for reconstruction. The final score is derived from the distribution of Local Binary Patterns (LBP) in the Hue and Saturation channels of the image.

**Inputs:**
- $m_k$: The rendered or captured image at camera pose $c_k$.
- $r_T$: Filter radius for LBP (default: 3) [S1, unofficial].
- $p_T$: Number of circularly symmetric local neighborhood points for LBP (default: 3) [S1, unofficial].
- $d_T$: Discount factor to prevent overfitting to previously seen textures [S1, unofficial].

**Outputs:**
- $f_T$: The normalized textural complexity score for the image.

**Data Structures:**
- Histogram array: A 1D array representing the frequency of LBP codes. The size depends on the number of possible LBP codes for the given $p_T$. For $p_T=3$, there are $2^3=8$ possible codes, so the histogram has 8 bins.

**Steps:**
1. **Channel Selection:** Extract the Hue ($H$) and Saturation ($S$) channels from the image $m_k$. The method ignores the Value/Brightness channel to reduce sensitivity to lighting changes [S1, unofficial].
2. **LBP Computation:** For each channel separately, compute the Local Binary Pattern descriptor.
   - For each pixel, compare its intensity to its $p_T$ neighbors arranged in a circle of radius $r_T$.
   - Generate a binary code based on whether neighbors are greater than or equal to the center pixel.
   - Aggregate these codes into a histogram $Hist(\cdot)$ [S1, unofficial].
3. **Histogram Normalization:** Let $f'_T$ be the histogram of LBP codes. The source defines $f'_T = Hist(LBP(m_k; r_T, p_T))$ [S1, unofficial].
4. **Complexity Calculation:** Compute the complexity score for the channel using the last bin of the histogram.
   - Let $b$ be the index of the last bin in the histogram.
   - Calculate $f_T = 1 - f'_T[b]$ [S1, unofficial].
   - Maximizing this equation selects images with the highest textural complexity. Note: The source implies that a lower frequency in the last bin (or specific bin distribution) correlates with higher complexity, or that this specific formulation is used to maximize the score [S1, unofficial].
5. **Channel Averaging:** Compute the final score by averaging the $f_T$ values obtained from the Hue and Saturation channels [S1, unofficial].
6. **Discounting:** Apply a discount factor $d_T$ to the $T$ values of views that overlap with previously planned trajectories to prevent the planner from overfitting to specific textures already seen [S1, unofficial].

**Pseudocode:**
```python
def compute_textural_complexity(image, r_T=3, p_T=3, d_T=0.0):
    """
    Computes the Textural Complexity Objective for an image.
    
    Args:
        image: RGB image array.
        r_T: LBP filter radius.
        p_T: Number of LBP neighborhood points.
        d_T: Discount factor for previously seen views.
        
    Returns:
        f_T: Normalized textural complexity score.
    """
    # Step 1: Extract Hue and Saturation channels
    # Assuming image is in HSV format or converted to it.
    # If RGB, convert to HSV.
    hsv_image = rgb_to_hsv(image)
    hue_channel = hsv_image[:,:,0]
    sat_channel = hsv_image[:,:,1]
    
    # Step 2 & 3: Compute LBP Histogram for each channel
    # Note: Standard LBP uses a grid. For circular LBP with p_T=3, r_T=3,
    # we sample 3 points on a circle of radius 3.
    # The number of bins is 2^p_T = 8.
    num_bins = 2 ** p_T
    
    hist_hue = compute_lbp_histogram(hue_channel, r_T, p_T, num_bins)
    hist_sat = compute_lbp_histogram(sat_channel, r_T, p_T, num_bins)
    
    # Step 4: Calculate complexity for each channel
    # b is the index of the last bin (num_bins - 1)
    b = num_bins - 1
    
    f_T_hue = 1.0 - hist_hue[b]
    f_T_sat = 1.0 - hist_sat[b]
    
    # Step 5: Average the scores
    f_T_raw = (f_T_hue + f_T_sat) / 2.0
    
    # Step 6: Apply discount factor if needed
    # The source mentions applying d_T towards T values seen during planning.
    # This is typically done at the trajectory planning level, not per-image.
    # Here we return the raw score.
    return f_T_raw

def compute_lbp_histogram(channel, r_T, p_T, num_bins):
    """
    Computes the histogram of Local Binary Patterns for a single channel.
    """
    height, width = channel.shape
    histogram = np.zeros(num_bins)
    
    # Define sampling points for circular LBP
    # Points are at angles 2*pi*i/p_T for i in 0..p_T-1
    # Coordinates: (x, y) = (x_c + r_T * cos(theta), y_c + r_T * sin(theta))
    # Note: Image coordinates usually have y increasing downwards.
    
    for y in range(1, height - 1):
        for x in range(1, width - 1):
            center_val = channel[y, x]
            code = 0
            for i in range(p_T):
                angle = 2 * np.pi * i / p_T
                # Calculate neighbor coordinates
                # Assuming standard image coordinate system
                nx = x + r_T * np.cos(angle)
                ny = y - r_T * np.sin(angle) # Subtract because y is down
                
                # Interpolate neighbor value if not integer
                neighbor_val = interpolate(channel, nx, ny)
                
                if neighbor_val >= center_val:
                    code |= (1 << i)
            
            histogram[code] += 1
            
    # Normalize histogram to sum to 1? The source doesn't explicitly say,
    # but f_T = 1 - f'_T[b] implies f'_T[b] is a probability or normalized count.
    # If not normalized, f_T could be negative or > 1.
    # Assuming normalization for valid probability distribution.
    histogram = histogram / np.sum(histogram)
    
    return histogram

def interpolate(image, x, y):
    """
    Bilinear interpolation for floating point coordinates.
    """
    x0 = int(np.floor(x))
    y0 = int(np.floor(y))
    x1 = x0 + 1
    y1 = y0 + 1
    
    # Handle boundaries
    x0 = max(0, min(x0, image.shape[1]-1))
    y0 = max(0, min(y0, image.shape[0]-1))
    x1 = max(0, min(x1, image.shape[1]-1))
    y1 = max(0, min(y1, image.shape[0]-1))
    
    val00 = image[y0, x0]
    val01 = image[y0, x1]
    val10 = image[y1, x0]
    val11 = image[y1, x1]
    
    dx = x - x0
    dy = y - y0
    
    val = (1-dx)*(1-dy)*val00 + dx*(1-dy)*val01 + (1-dx)*dy*val10 + dx*dy*val11
    return val
```

**Parameters:**
- $r_T = 3$: Filter radius for LBP [S1, unofficial].
- $p_T = 3$: Number of circularly symmetric local neighborhood points [S1, unofficial].

**Pitfalls:**
- **Overfitting:** The planner may overfit to specific textures if it repeatedly selects views of the same complex region. This is mitigated by the discount factor $d_T$ [S1, unofficial].
- **Lighting Sensitivity:** Although Hue and Saturation are used, extreme lighting changes can still affect these channels. The method assumes that textural characteristics are more stable than intensity [S1, unofficial].
- **Bin Indexing:** The formula uses the "last bin's index" $b$. The exact definition of "last bin" depends on the LBP code ordering. Standard LBP codes are ordered numerically. For $p_T=3$, codes are 0-7. $b=7$ [S1, unofficial].

## Subtopics

### Geometric Complexity Objective
A surrogate objective corresponding to the variability of mesh faces' configurations, quantified via mesh normals to identify regions requiring varied views [S1, unofficial]. It is computed using mesh normals $\hat{n}_j$. The objective function $Q$ quantifies the variability of mesh faces' configurations to identify geometrically complex regions (e.g., pillars, domes) that require varied views [S1, unofficial].

**Formula:**
The per-face geometric complexity is defined as:
$$ f'_Q = |LoG(\hat{n}_j; \sigma_Q)|^{\beta_Q} V_{jk} + 1 $$
where $LoG(\cdot)$ is the Laplacian of Gaussian filter, $\sigma_Q$ is the standard deviation of the Gaussian filter, $\beta_Q$ is a scaling factor, $f'_Q$ is the per-face geometric complexity, and $V_{jk}$ is an indicator function corresponding to the visibility of face $j$ from the $k$-th camera-pose [S1, unofficial]. The absolute value is taken because the directionality of normal variations does not matter [S1, unofficial].

The normalized total complexity is:
$$ f_Q = \frac{1}{J} \sum_{j=1}^{J} f'_Q $$
where $J$ is the total number of faces [S1, unofficial]. Maximization of $f_Q$ encourages the selection of camera-poses with higher geometric complexity [S1, unofficial].

**Pitfalls:**
- **Local Maxima:** Over-emphasis on local regions with unusually high geometric complexity can trap the planner in a local maxima. This is handled by applying a scaling discount factor $d_Q$ towards the $Q$ values of overlapping faces seen during trajectory planning [S1, unofficial].

## Operating characteristics
- **Time Complexity:** The computation involves LBP extraction and histogramming, which is $O(N)$ where $N$ is the number of pixels in the image. The Geometric Complexity variant involves mesh processing and LoG filtering, which is more expensive but still linear in the number of faces/pixels.
- **Memory Complexity:** $O(1)$ for the histogram (fixed size for fixed $p_T$) and $O(N)$ for the image data.
- **Strengths:** Effective at identifying regions with rich texture that are crucial for high-fidelity reconstruction. Robust to some lighting variations by using Hue/Saturation.
- **Limitations:** Computationally more expensive than simple photometric error metrics. Relies on accurate camera poses and rendered images. The specific bin index $b$ and normalization method are critical and not fully detailed in the source [S1, unofficial].
- **When to use:** When optimizing for "in the wild" datasets with varying lighting and texture, such as Tanks and Temples.
- **When not to use:** For synthetic datasets with uniform lighting and simple geometry, where geometric complexity might be more relevant.

## Background
The Textural Complexity Objective was introduced in the context of active view planning for NeRF (SO-NeRF) [S1, unofficial]. It is part of a family of surrogate objectives (including Geometric Complexity and Ray Diversity) designed to guide camera trajectory planning for better 3D reconstruction [S1, unofficial]. The method builds on the observation that textural characteristics are discernible in 2D projections, unlike some geometric features [S1, unofficial].
