# Model Regularization

## Overview
Model regularization refers to the application of specific loss terms added to the total optimization objective to constrain the learned radiance field parameters, preventing overfitting and ensuring physical plausibility. Unlike photometric losses that measure pixel-wise error, model regularization enforces structural, geometric, or statistical priors directly on the network outputs or intermediate representations [Parent](1413-regularization-losses.md). It is distinct from sibling methods like Total Variation [860-total-variation-regularization.md] which focus on spatial smoothness, or Distortion Loss [1051-efficient-o-n-distortion-loss.md] which focuses on ray parameterization, by encompassing a broader category of constraints including uncertainty bounding and feature consistency.

## How it works
Model regularization operates by computing auxiliary loss terms $\mathcal{L}_{reg}$ based on the current state of the neural network's outputs (density, color, uncertainty, normals) and integrating them into the total loss function.

**Inputs and Outputs:**
- **Input:** The rendered output dictionary `out` from the radiance field model, containing fields such as color, density, depth, uncertainty, and gradients.
- **Output:** A scalar regularization loss value $\mathcal{L}_{reg}$ and potentially a dictionary of named sub-losses for logging.

**Data Structures:**
- `losses_model_reg`: A dictionary mapping string names (e.g., "zero_reg", "tv") to float tensor values representing individual regularization components.
- `lambda_{name}`: A scalar hyperparameter associated with each regularization term, retrieved from the configuration system.

**Steps:**
1. **Compute Regularization Terms:** Call the model's regularization method, typically `self.model.regularizations(out)`, which processes the output dictionary `out` to compute specific constraints [S1, unofficial].
2. **Aggregate Losses:** Iterate over the resulting dictionary of named loss terms. For each term `name` with value `loss_val`:
   a. Retrieve the corresponding weight $\lambda_{name}$ from the configuration.
   b. Compute the weighted contribution: $\lambda_{name} \times loss\_val$.
   c. Add this contribution to the total loss $\mathcal{L}_{total}$.
3. **Logging:** Record the unweighted and weighted values of each regularization term for monitoring training stability [S1, unofficial].

**Formulas:**
The total loss is augmented as:
$$
\mathcal{L}_{total} = \mathcal{L}_{photo} + \sum_{k} \lambda_k \mathcal{L}_{reg}^{(k)}
$$
Where $\mathcal{L}_{reg}^{(k)}$ represents specific model constraints. A prominent example is the Zero Regularization Loss for uncertainty prediction [S2]:
$$
\mathcal{L}_0 = \sum_{r \in \mathcal{R}} \sum_{i=1}^N \max(\delta_{c_i}, 0)
$$
Here, $\delta_{c_i}$ is the predicted uncertainty at sample point $c_i$ along ray $r$. This term penalizes positive uncertainty values, encouraging them to remain near zero to prevent the uncertainty estimate from "blowing up" during optimization [S2].

**Parameters:**
- $\lambda_k$: Hyperparameters controlling the strength of each regularization term. Typical values vary by term; for instance, in uncertainty regularization, $\alpha_1=1.0$ and $\alpha_2=0.01$ are used for the weighted sum of uncertainty losses [S2].

**Edge Cases and Pitfalls:**
- **Uncertainty Blow-up:** Without regularization like $\mathcal{L}_0$, predicted uncertainty $\delta$ can grow arbitrarily large, destabilizing training [S2].
- **Shallow Network Limitations:** Directly predicting error estimates (like $E(r)$) is difficult for shallow networks; regularization provides necessary inductive bias [S2].
- **Gradient Flow:** Ensure regularization terms are differentiable with respect to the network weights to allow gradient propagation through the rendering operator [Parent](1413-regularization-losses.md).

**Pseudocode:**
```python
def compute_model_regularization(model, out, config):
    """
    Computes model regularization losses and adds them to the total loss.
    
    Args:
        model: The radiance field model instance.
        out: Dictionary containing model outputs (color, density, uncertainty, etc.).
        config: Configuration object containing lambda hyperparameters.
        
    Returns:
        total_reg_loss: Scalar tensor of the total weighted regularization loss.
        reg_dict: Dictionary of named regularization losses for logging.
    """
    # Step 1: Obtain raw regularization losses from the model
    # The model implements specific constraints based on its outputs
    raw_losses = model.regularizations(out)
    
    total_reg_loss = torch.tensor(0.0, requires_grad=True)
    reg_dict = {}
    
    # Step 2: Iterate over each regularization term
    for name, loss_val in raw_losses.items():
        # Retrieve the lambda weight for this specific regularization term
        lambda_key = f"lambda_{name}"
        if lambda_key in config.system.loss:
            lambda_val = config.system.loss[lambda_key]
        else:
            # Default to 0 if not specified, or raise error depending on strictness
            lambda_val = 0.0
            
        # Compute weighted loss
        weighted_loss = lambda_val * loss_val
        
        # Accumulate to total
        total_reg_loss = total_reg_loss + weighted_loss
        
        # Log the values
        reg_dict[name] = weighted_loss
        
    return total_reg_loss, reg_dict
```

## Subtopics

### Zero Regularization Loss
A specific model regularization term used in uncertainty-aware radiance field optimization. It penalizes positive predicted uncertainty values $\delta_{c_i}$ by summing $\max(\delta_{c_i}, 0)$ over all samples on all rays [S2]. This prevents the uncertainty network from predicting arbitrarily large values, which can destabilize training when uncertainty is used to weight photometric errors. It is typically combined with a Log-Sum-Exp (LSE) loss for uncertainty, weighted by $\alpha_1$ and $\alpha_2$ [S2].

## Operating characteristics
- **Time Complexity:** Depends on the number of samples $N$ and rays $|\mathcal{R}|$ used in the batch. Computing $\mathcal{L}_0$ is $O(N \cdot |\mathcal{R}|)$ as it involves a simple element-wise max and sum operation [S2].
- **Memory Complexity:** $O(N \cdot |\mathcal{R}|)$ to store intermediate uncertainty values if not computed on the fly, though typically negligible compared to the main network forward pass.
- **Strengths:** Stabilizes training for uncertainty-aware models; prevents degenerate solutions where uncertainty dominates the loss [S2].
- **Limitations:** Requires careful tuning of $\lambda$ weights; ineffective if the network architecture cannot represent uncertainty meaningfully [S2].
- **When to use:** When using uncertainty prediction heads in NeRF-like models to handle noise or occlusion [S2].
- **When not to use:** In standard deterministic NeRF optimization where uncertainty is not modeled.

## Background
Model regularization in the context of differentiable volume rendering has evolved alongside the complexity of radiance field representations. Early NeRF implementations relied heavily on photometric loss [S1, unofficial]. As models incorporated uncertainty estimation and geometric constraints, specific regularization terms like Zero Regularization Loss were introduced to handle the instability of these additional outputs [S2]. The practice of modularizing regularization into a `regularizations()` method allows for flexible composition of priors, as seen in frameworks like instant-nsr-pl [S1, unofficial].
