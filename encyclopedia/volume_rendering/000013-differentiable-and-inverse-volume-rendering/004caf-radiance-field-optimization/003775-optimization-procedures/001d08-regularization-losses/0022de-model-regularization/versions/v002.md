# Model Regularization

## Overview
Model regularization refers to the application of penalty terms added to the total optimization objective to constrain the learned radiance field parameters, preventing overfitting and enforcing physical or statistical priors [S1, unofficial][S2]. It differs from photometric losses by targeting the internal state of the model (e.g., density, uncertainty, or geometry) rather than the final rendered pixel values [S1, unofficial][S2].
## How it works
### Inputs and outputs
**Inputs:**
*   `out`: Dictionary of model outputs (e.g., density $\sigma$, opacity $\alpha$, color $C$, uncertainty $\delta$) for a batch of rays [S1, unofficial][S2].
*   `config`: Configuration object containing regularization weights $\lambda_k$ [S1, unofficial].
*   `losses_model_reg`: Dictionary mapping regularization loss names to their computed scalar values [S1, unofficial].

**Outputs:**
*   `total_loss`: Scalar value including the weighted sum of regularization losses [S1, unofficial].
*   `losses_dict`: Dictionary of logged loss values for monitoring [S1, unofficial].

### Data structures
*   `losses_model_reg`: `Dict[str, float]`. Keys are loss names (e.g., "uncertainty_reg"), values are computed loss scalars.
*   `config.system.loss`: `Dict[str, float]`. Keys are formatted as `f"lambda_{name}"`, values are scalar weights $\lambda_k$.

### Steps
1.  Compute raw regularization losses by calling the model's regularization method:
    ```python
    losses_model_reg = self.model.regularizations(out)
    ```
    [S1, unofficial]
2.  Initialize the total loss accumulator and a dictionary for logging:
    ```python
    total_loss = 0.0
    losses_dict = {}
    ```
    [G]
3.  Iterate over each name-value pair in `losses_model_reg`:
    ```python
    for name, loss_value in losses_model_reg.items():
        # Retrieve the corresponding lambda weight
        lambda_key = f"lambda_{name}"
        lambda_weight = self.config.system.loss[lambda_key]
        
        # Compute weighted loss
        weighted_loss = loss_value * lambda_weight
        
        # Add to total
        total_loss += weighted_loss
        
        # Log the loss
        losses_dict[name] = weighted_loss
    ```
    [S1, unofficial]
4.  Return `total_loss` and `losses_dict` [S1, unofficial].

### Formulas
The total loss is augmented as:
$$
\mathcal{L}_{total} = \mathcal{L}_{photo} + \sum_k \lambda_k \mathcal{L}_{reg}^{(k)}
$$
[S1, unofficial][S2]

Specific regularization formulas found in sources:
*   **Uncertainty Regularization ($\mathcal{L}_0$):** Encourages predicted uncertainty $\delta_{c_i}$ to be close to zero to prevent it from "blowing up" [S2].
    $$
    \mathcal{L}_0 = \sum_{r \in \mathcal{R}} \sum_{i=1}^N \max(\delta_{c_i}, 0)
    $$
    [S2]
    Where:
    *   $r$: A ray in the set of rays $\mathcal{R}$.
    *   $N$: Number of sample points per ray.
    *   $c_i$: The query coordinate of the $i$-th sample point.
    *   $\delta_{c_i}$: The predicted uncertainty at coordinate $c_i$.

*   **Combined Uncertainty Loss:**
    $$
    \mathcal{L}_{unct} = \alpha_1 \mathcal{L}_{SE} + \alpha_2 \mathcal{L}_0
    $$
    [S2]
    Where $\alpha_1 = 1.0$ and $\alpha_2 = 0.01$ are weights [S2].

### Parameters
*   $\lambda_k$: Scalar weights for each regularization term. Default values are not given in the sources; they are retrieved from `config.system.loss` [S1, unofficial].
*   $\alpha_1, \alpha_2$: Weights for uncertainty loss components. $\alpha_1 = 1.0, \alpha_2 = 0.01$ [S2].

### Edge cases and pitfalls
*   **Uncertainty Blow-up:** Without $\mathcal{L}_0$, uncertainty $\delta_i$ may grow arbitrarily large because predicting error magnitude is difficult for shallow networks [S2].
*   **Weight Sensitivity:** The choice of $\lambda_k$ significantly impacts convergence. Improper weights can dominate the photometric loss or be ignored [S1, unofficial][S2].
*   **Non-differentiability:** The $\max(\delta_{c_i}, 0)$ function is non-differentiable at 0. In practice, this is handled by standard autograd frameworks using the subgradient at 0 (typically 0 or 1) [G].

## Subtopics

### Zero Regularization Loss
A specific regularization term $\mathcal{L}_0$ that penalizes positive uncertainty values to prevent them from growing excessively large during training [S2]. It is used in conjunction with other uncertainty losses (like $\mathcal{L}_{SE}$) to stabilize training of uncertainty-aware NeRFs [S2]. It is chosen when the model predicts uncertainty values that need to be bounded or kept small [S2]. [S2]

## Operating characteristics
*   **Time Complexity:** Depends on the number of regularization terms and the cost of computing each $\mathcal{L}_{reg}^{(k)}$. Typically $O(N)$ per ray for simple terms like $\mathcal{L}_0$ [S2].
*   **Memory Complexity:** Minimal overhead; requires storing loss values and weights [S1, unofficial].
*   **Strengths:** Prevents overfitting, enforces physical priors (e.g., uncertainty bounds), stabilizes training [S1, unofficial][S2].
*   **Limitations:** Requires careful tuning of weights $\lambda_k$ [S1, unofficial]. May slow convergence if weights are too high [G].
*   **When to use:** When the model exhibits overfitting, instability, or violates known physical/statistical priors [S1, unofficial][S2].
*   **When not to use:** When the model is already well-regularized or when computational budget is extremely tight [G].

## Background
Model regularization in differentiable volume rendering has been used to stabilize training and improve generalization. The specific uncertainty regularization $\mathcal{L}_0$ was introduced in Recursive-NeRF to address the difficulty of predicting accurate error estimates with shallow networks [S2]. The general framework of adding weighted regularization losses to the total objective is common in many NeRF variants, including Instant-NSR-PL [S1, unofficial].
