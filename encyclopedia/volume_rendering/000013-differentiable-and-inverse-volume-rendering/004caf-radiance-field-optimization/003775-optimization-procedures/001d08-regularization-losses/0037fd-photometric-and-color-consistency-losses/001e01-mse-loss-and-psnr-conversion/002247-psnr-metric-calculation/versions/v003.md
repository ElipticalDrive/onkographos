# PSNR Metric Calculation

Also called: PSNR Calculation, PSNR Metric, Peak Signal-to-Noise Ratio

## Overview
Peak Signal-to-Noise Ratio (PSNR) is a standard benchmark metric used to evaluate the photometric fidelity of reconstructed or rendered images against ground-truth references in differentiable volume rendering pipelines [S1, S2, S3, unofficial][S4]. It quantifies the error between two images by computing the Mean Squared Error (MSE) and converting it to a logarithmic decibel (dB) scale, where higher values indicate better quality [S2, S3, unofficial][S4]. Unlike structural metrics such as SSIM, PSNR focuses strictly on pixel-wise intensity differences, making it sensitive to large smooth regions but less responsive to small, high-frequency features like specular highlights [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** Two images (or volumes) of identical dimensions: the target/reference image $Y$ and the predicted/reconstructed image $\hat{Y}$.
- **Output:** A single scalar value representing the PSNR in decibels (dB).

**Data Structures:**
- Images are represented as 2D arrays (or 3D arrays for volumetric data) of pixel/voxel values.
- Values are typically normalized to the range $[0, 1]$ for neural network outputs or scaled to $[0, 255]$ for 8-bit integer images.
- The maximum possible pixel value, denoted as $\text{MAX}$, depends on the data type and normalization (e.g., $1.0$ for normalized floats, $255$ for 8-bit integers) [S2, unofficial][S4][S6, unofficial].

**Steps:**
1. **Validation:** Verify that the target image $Y$ and predicted image $\hat{Y}$ have identical spatial dimensions (width $W$ and height $H$). If dimensions mismatch, the metric is undefined or returns an error/maximum value [S5, unofficial].
2. **Compute MSE:** Calculate the Mean Squared Error between $Y$ and $\hat{Y}$.
   - For each pixel $i$ (where $i$ ranges from $0$ to $N-1$ and $N = W \times H$), compute the squared difference across all channels (e.g., R, G, B).
   - Sum these squared differences.
   - Divide by the total number of pixels $N$.
   $$ \text{MSE} = \frac{1}{N} \sum_{i=0}^{N-1} \sum_{c=1}^{C} (Y_{i,c} - \hat{Y}_{i,c})^2 $$
   where $C$ is the number of channels (typically 3 for RGB) [S1, unofficial][S4][S5, unofficial].
3. **Compute PSNR:** Convert the MSE to PSNR using the logarithmic formula.
   $$ \text{PSNR} = 10 \log_{10} \left( \frac{\text{MAX}^2}{\text{MSE}} \right) $$
   Alternatively, this can be expressed as:
   $$ \text{PSNR} = 20 \log_{10}(\text{MAX}) - 10 \log_{10}(\text{MSE}) $$
   [S1, S2, unofficial][S4][S8, unofficial].
4. **Numerical Stability:** Add a small epsilon ($\epsilon$, typically $10^{-10}$) to the MSE before taking the logarithm to prevent division by zero or $\log(0)$ when the prediction is perfect [S3, unofficial].
   $$ \text{PSNR} = 10 \log_{10} \left( \frac{\text{MAX}^2}{\text{MSE} + \epsilon} \right) $$

**Pseudocode:**
```python
import math

def calculate_psnr(target: list, predicted: list, max_val: float = 1.0, eps: float = 1e-10) -> float:
    """
    Calculate Peak Signal-to-Noise Ratio between target and predicted images.
    
    Args:
        target: 2D list or array of pixel values (H x W x C).
        predicted: 2D list or array of pixel values (H x W x C).
        max_val: Maximum possible pixel value (e.g., 1.0 for normalized, 255 for 8-bit).
        eps: Small constant to prevent log(0).
        
    Returns:
        PSNR value in dB.
    """
    # Validate dimensions
    if len(target) != len(predicted) or len(target[0]) != len(predicted[0]):
        raise ValueError("Target and predicted images must have identical dimensions.")
    
    height = len(target)
    width = len(target[0])
    channels = len(target[0][0]) if isinstance(target[0][0], list) else 1
    
    mse_sum = 0.0
    num_pixels = height * width
    
    # Compute sum of squared errors
    for y in range(height):
        for x in range(width):
            for c in range(channels):
                diff = target[y][x][c] - predicted[y][x][c]
                mse_sum += diff * diff
                
    # Compute MSE
    mse = mse_sum / (num_pixels * channels)
    
    # Compute PSNR
    # Avoid division by zero and log(0)
    if mse <= 0:
        return float('inf')
        
    psnr = 10 * math.log10((max_val ** 2) / (mse + eps))
    return psnr
```

**Parameters:**
- **MAX / max_val:** The maximum representable pixel value. Default is often $1.0$ for normalized floating-point images [S2, S8, unofficial].
- **eps:** A small constant (e.g., $10^{-10}$) added to MSE to ensure numerical stability [S3, unofficial].

**Edge Cases and Pitfalls:**
- **Perfect Prediction:** If MSE is exactly 0, PSNR is infinite. In practice, a large finite value or infinity is returned [S2, unofficial].
- **Dimension Mismatch:** If input images have different widths or heights, the metric is invalid. Some implementations return `float.MaxValue` or raise an error [S5, unofficial].
- **Weighting Bias:** PSNR averages over all pixels, heavily weighting large smooth regions. It may not reflect perceptual quality for small, bright features like specular highlights or fine textures [S1, unofficial].
- **Volumetric Data:** When applied to 3D volumes, MSE is averaged over all voxels, including background. This can skew results if the background dominates the volume [S6, unofficial].

## Subtopics

### [3D Evaluation Metrics](2903-3d-evaluation-metrics.md)
3D Evaluation Metrics extend PSNR to volumetric and geometric data. While PSNR focuses on pixel-wise photometric error in rendered images, this approach assesses volumetric reconstruction quality (PSNR on 3D grids) and surface geometry (Chamfer Distance, Normal Consistency). It addresses the limitations of image-space metrics when evaluating the underlying 3D structure.

### [PSNR Difference Metric for Ablation](5656-psnr-difference-metric-for-ablation.md)
This variant isolates the error ratio independent of the bit depth (MAX), as MAX cancels out in the logarithmic difference. It is used to compare the relative performance of models without being affected by the specific pixel value scaling.

### Noise Floor Estimation via MAD
This method estimates the noise floor in volumetric data using Median Absolute Deviation (MAD) estimators to determine the inherent noise level $\sigma$. The noise floor PSNR is then calculated as $10 \log_{10}(1/\sigma^2)$. Estimators include the Laplacian MAD (scaling by $1/(0.6745 \sqrt{2D(2D+1)})$) and Haar finite-difference MAD (scaling by $1/(0.6745 \sqrt{2})$). A pitfall is that MAD may return zero for signal-limited volumes (e.g., Mouse heart nuclei), indicating the model is not noise-limited [S6, unofficial].

### Benchmark Performance Numbers
Standard benchmarks provide reference PSNR values for comparison. On the Mip-NeRF 360 dataset (room scale, average PSNR/LPIPS): Vanilla 3DGS achieves 27.4 / 0.18, Mip-Splatting 27.7 / 0.17, Scaffold-GS 27.9 / 0.18, and 2DGS achieves ~27.0 PSNR with better geometry. GES achieves comparable PSNR with ~30% fewer primitives [S7, unofficial].

### PSNR Loss
PSNR can be used as a regression loss during training. The formula is $\text{PSNR} = 20 \log_{10}(\text{max\_val} / \sqrt{\text{MSE}})$. This is mathematically equivalent to the standard PSNR formula but is sometimes used directly in optimization loops [S8, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- **Time:** $O(N)$, where $N$ is the total number of pixels (or voxels). The calculation involves a single pass to compute squared differences and a constant-time logarithmic operation.
- **Memory:** $O(1)$ auxiliary space if computed incrementally, or $O(N)$ if storing intermediate squared differences.

**Measured Performance:**
- Target PSNR for NeRF paper Blender scenes is 31–33 dB [S2, unofficial].
- On Mip-NeRF 360, state-of-the-art methods achieve PSNR values around 27–28 dB [S7, unofficial].

**Scaling:**
- A 3 dB difference corresponds to a halving of the squared error; a 6 dB difference corresponds to a quartering [S1, unofficial].
- The metric is sensitive to the scale of the input data. Normalization to $[0, 1]$ is common, but $\text{MAX}$ must be adjusted accordingly [S2, S6, unofficial].

**Strengths and Limitations:**
- **Strengths:** Simple to compute, widely understood, and provides a single scalar for easy comparison [S2, unofficial][S4].
- **Limitations:** Does not correlate well with human perception for all types of errors (e.g., structural changes). It is biased towards smooth regions and may penalize high-frequency details less than perceptual metrics like LPIPS or SSIM [S1, S7, unofficial].

**When to Use:**
- Use PSNR for quick, standardized comparison of photometric accuracy in image-space rendering [S2, unofficial].
- Use alongside SSIM or LPIPS for a more comprehensive evaluation [S1, S7, unofficial].

**When Not to Use:**
- Avoid using PSNR as the sole metric for perceptual quality, especially when structural fidelity is important [S1, unofficial].
- Do not use PSNR for volumetric data without considering background voxels, as they can dominate the MSE [S6, unofficial].

## Background
PSNR originated as a standard metric in image and video processing [S4]. It has been widely adopted in novel view synthesis and differentiable volume rendering, particularly in the context of NeRF (Neural Radiance Fields) and 3D Gaussian Splatting, to evaluate the quality of reconstructed images [S1, S2, S3, unofficial]. The metric is defined in numerous computer vision and graphics papers, including those on CT reconstruction and neural rendering [S4][S8, unofficial].
