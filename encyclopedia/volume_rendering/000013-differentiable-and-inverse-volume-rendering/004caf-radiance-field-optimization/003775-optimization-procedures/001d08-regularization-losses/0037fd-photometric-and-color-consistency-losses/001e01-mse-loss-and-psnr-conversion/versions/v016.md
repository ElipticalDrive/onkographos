# MSE Loss and PSNR Conversion

Also called: MSE, MSE Loss, Mean Squared Error, Mean Squared Error Loss

## Overview
MSE Loss and PSNR Conversion computes the Mean Squared Error (MSE) between predicted and target RGB values (or volume voxels) to serve as the primary photometric training loss, and converts this error into Peak Signal-to-Noise Ratio (PSNR) for logging and evaluation [S2, S3, S8, unofficial]. It sets itself apart from siblings like [L1+SSIM Loss](2890-l1-ssim-loss.md) by relying strictly on pixel-wise intensity differences without structural weighting, and from [Visibility-Based Photometric Loss](2917-visibility-based-photometric-loss.md) by typically operating on all pixels unless explicitly masked [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Predicted image/volume $\hat{X}$ (shape $B \times H \times W \times C$ or $B \times D \times H \times W \times C$) and Target image/volume $Y$ (same shape). Optional: Binary mask $M$ (shape $B \times 1 \times 1 \times 1$ or broadcastable) indicating valid regions [S8, unofficial].
- **Outputs:** Scalar loss value $L_{MSE}$ (float) and metric value $PSNR$ (float or $\infty$) [S2, S8, unofficial].

**Data Structures:**
- **Mask Volume:** A boolean tensor where `True` indicates valid voxels/pixels. Generated from a thresholded density or occupancy volume if not provided [S8, unofficial].
- **Mask Threshold:** A scalar parameter `mask_threshold_rel` used to binarize the volume. Default value is `0.01` [S8, unofficial].

**Steps:**
1. **Compute Squared Error:** Calculate the element-wise squared difference between predicted and target values: $E = (\hat{X} - Y)^2$ [S5, unofficial].
2. **Apply Mask (Optional):** If a mask $M$ is provided, retain only elements where $M$ is true. Let $N$ be the count of valid elements (number of pixels or voxels in the mask) [S8, unofficial]. If no mask is used, $N$ is the total number of elements in the batch dimension flattened spatially [S5, unofficial].
3. **Compute MSE:** Average the squared errors over the valid elements:
   $$
   MSE = \frac{1}{N} \sum_{i \in \text{valid}} (\hat{x}_i - y_i)^2
   $$
   where $\hat{x}_i$ and $y_i$ are the predicted and target values at index $i$ [S2, S8, unofficial].
4. **Compute PSNR:** Convert MSE to PSNR. If $MSE > 0$:
   $$
   PSNR = 20 \cdot \log_{10}\left(\frac{1}{\sqrt{MSE}}\right) = -10 \cdot \log_{10}(MSE)
   $$
   If $MSE = 0$, $PSNR = \infty$ [S2, S8, unofficial].

**Pseudocode:**
```python
import math
import torch

def compute_mse_and_psnr(predicted: torch.Tensor, target: torch.Tensor, mask: torch.Tensor = None) -> dict:
    """
    Computes MSE and PSNR between predicted and target tensors.
    
    Args:
        predicted: Tensor of shape (..., C) or (B, H, W, C).
        target: Tensor of same shape as predicted.
        mask: Optional boolean tensor of shape (..., 1) or broadcastable. 
              If None, all elements are used.
              
    Returns:
        Dictionary with 'mse' (float), 'psnr' (float or inf), 'valid_count' (int).
    """
    # 1. Compute element-wise squared difference
    squared_diff = (predicted - target) ** 2
    
    if mask is not None:
        # 2. Apply mask
        # Ensure mask is broadcastable; assume mask is boolean or 0/1
        masked_squared_diff = squared_diff * mask.float()
        valid_count = int(mask.sum().item())
        
        if valid_count == 0:
            raise RuntimeError("Mask has no true values (empty region).")
            
        # 3. Compute MSE over valid elements
        mse = float(masked_squared_diff.sum().item() / valid_count)
    else:
        # No mask: flatten spatial dimensions and average over batch
        # Shape: (batch_size, -1)
        flat = squared_diff.reshape(squared_diff.shape[0], -1)
        valid_count = flat.numel()
        # Mean along dimension 1 (flattened spatial)
        mse = float(torch.mean(flat, dim=1).mean().item())

    # 4. Compute PSNR
    if mse > 0.0:
        psnr = 20.0 * math.log10(1.0 / math.sqrt(mse))
    else:
        psnr = float('inf')

    return {
        'mse': mse,
        'psnr': psnr,
        'valid_count': valid_count
    }
```

**Parameters:**
- `mask_threshold_rel`: Relative threshold applied to the normalized mask volume to create the boolean mask. Default value is `0.01` [S8, unofficial].
- `batch_size`: Number of random pixels sampled per iteration for training [S6, unofficial].
- `lr`: Adam learning rate for the optimizer updating the model parameters [S6, unofficial].

**Edge Cases and Pitfalls:**
- **Empty Mask:** If the boolean mask has no true values, raise a `RuntimeError` [S8, unofficial].
- **Zero MSE:** If `masked_mse` is exactly `0.0`, PSNR remains infinity to avoid division by zero in the `log10` calculation [S8, unofficial].
- **Dimension Mismatch:** Inputs must have the same size; otherwise, throw a `runtime_error` [S9, unofficial].

## Subtopics

### [PSNR Metric Calculation](2742-psnr-metric-calculation.md)
Peak Signal-to-Noise Ratio (PSNR) is a standard benchmark metric used to evaluate the photometric fidelity of reconstructed or rendered images against ground-truth references in differentiable volume rendering pipelines. It quantifies the mean squared error (MSE) between predicted and target pixel values, converting this error into a logarithmic decibel (dB) scale where higher values indicate better quality. Unlike structural metrics such as SSIM, PSNR focuses strictly on pixel-wise intensity differences, making it sensitive to large smooth regions but less responsive to small, high-frequency features like specular highlights.

### [SSIM Metric Calculation](3650-ssim-metric-calculation.md)
SSIM is an image fidelity score used to evaluate the quality of 3D reconstructions and novel 2D views by measuring local structural similarity between a rendered image and a ground truth image. Unlike pixel-wise metrics such as MSE, SSIM captures local patterns of pixel intensities and is correlated with human visual system perception, assuming the human visual system is highly adapted to structured natural scene information. It sets itself apart from its siblings by explicitly modeling luminance, contrast, and structure, whereas PSNR relies solely on global error magnitude and Normal-L2 focuses on geometric normals.

### [Normal-L2 Score Computation](3842-normal-l2-score-computation.md)
The Normal-L2 score evaluates surface geometry by computing the mean squared L2 distance between predicted surface normals and reference normals from a ground-truth mesh. It is computed only on the intersection of predicted and ground-truth masks, distinguishing it from silhouette metrics like iIoU which evaluate mask alignment separately.

### [Minkowski's Metric](4347-minkowski-s-metric.md)
Minkowski's metric is a family of distance measures that treats an image as a 2D signal to calculate the dissimilarity between a reference image and a test image. It generalizes the Mean Squared Error (MSE) by allowing the order parameter $\gamma$ to vary, enabling different sensitivities to pixel-wise errors. Unlike its sibling [PSNR](2742-psnr-metric-calculation.md), which normalizes error by signal power to provide a logarithmic decibel scale, Minkowski's metric provides a raw, unnormalized magnitude of error.

### [Training Loss Computation with Huber and Masking](4765-training-loss-computation-with-huber-and-masking.md)
This method computes the photometric training loss for differentiable volume rendering by combining a Huber loss on RGB values with ray-level validity masking. It addresses the problem of robust optimization in the presence of noisy or saturated pixels, which can destabilize geometry and appearance recovery. It sets itself apart from standard MSE loss [MSE Loss and PSNR Conversion](1651-mse-loss-and-psnr-conversion.md) by using a linear penalty for large errors (reducing outlier sensitivity) and explicitly filtering invalid rays before aggregation.

### [IoU Loss](7110-iou-loss.md)
IoU Loss is a binary segmentation metric used to optimize the occupancy or density fields in differentiable volume rendering by measuring the overlap between predicted and target voxel sets. It differs from pixel-wise photometric losses like [MSE Loss and PSNR Conversion](1651-mse-loss-and-psnr-conversion.md) by operating on binarized volumetric occupancy rather than continuous RGB values, making it robust to intensity ambiguities and suitable for structural consistency.

### [Perceptually-motivated variance metric](9969-perceptually-motivated-variance-metric.md)
The perceptually-motivated variance metric quantifies the error between an 8-bit ambient occlusion (AO) approximation $T$ and a high-fidelity ray-traced reference $R$. It differs from raw pixel Mean Squared Error (MSE) by operating on log-transformed values and spatial gradients, thereby aligning with human visual sensitivity to radiance and its changes. This metric is specifically designed for evaluating AO approximations where reflected ambient radiance is linear in accessibility.

### [Depth Accuracy Metrics](10453-depth-accuracy-metrics.md)
Depth Accuracy Metrics quantify the pixel-wise discrepancy between a predicted depth map $\hat{d}$ and a ground truth depth map $d$. They serve as the primary evaluation standard for depth prior quality in differentiable volume rendering and inverse rendering pipelines. Unlike photometric metrics such as MSE or PSNR which evaluate color fidelity, these metrics assess geometric accuracy. They are distinguished from sibling metrics like SSIM (structural similarity) and Normal-L2 (surface orientation error) by focusing strictly on scalar depth value errors rather than structural coherence or surface normals.

### [Discrete Wavelet Transform Loss](11910-discrete-wavelet-transform-loss.md)
A regularization loss that applies Discrete Wavelet Transform to rendered images to supervise low and mid-frequency structures, prioritizing low frequencies by weighting the LL sub-band higher than others.

### Masked Volume Metrics
A method to exclude empty froxels from evaluation metrics by including only froxels affected by radiance [S10, unofficial]. A froxel is included if any of its RGB channels contain a non-zero value at any point during the test scenario [S10, unofficial]. The Region of Interest (ROI) is computed separately for each tested algorithm; the union of the scenario's ROI and the ground truth's ROI is used to create $ROI_{effective}$, ensuring only relevant froxels are included while excluding completely empty regions [S10, unofficial].

### MSE Bias-Variance Decomposition
Treating the TAA algorithm as a biased estimator to analyze correctness using Mean Squared Error (MSE), decomposed into variance and bias squared [S10, unofficial]. The MSE is defined as $\text{MSE}[F] = \mathbb{E}[(F - G)^2] = V[F] + \beta[F]^2$, where $F$ is the output of the estimator, $G$ is the true value (ground truth), $V[F]$ is the variance of the estimator, and $\beta[F]$ is its bias [S10, unofficial].

### Area Loss Scaling
Scaling the loss of each pixel by the area of that pixel's footprint in the original image to ensure low-resolution pixels have comparable influence to high-resolution pixels in multiscale datasets [S11]. For multiscale datasets, the area scaling factor is calculated based on the downsampling factor (e.g., factor of 2 -> area factor 4, factor of 4 -> area factor 16) and the pixel loss is multiplied by this factor [S11].

### Greedy proposal matching
A fast assignment strategy used during Phase 1 to compute the L2 matching loss between heuristic samples and learnt proposals [S12, unofficial]. For each heuristic sample, the closest proposal from the learnt proposer set is found [S12, unofficial]. Optimal matching (Hungarian algorithm) or strict 1-1 greedy matching significantly slows training [S12, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- **Time:** $O(N)$ where $N$ is the number of pixels or voxels in the batch. The operation is element-wise and reduces to a scalar, making it extremely fast compared to the forward rendering pass [S5, unofficial].
- **Memory:** $O(N)$ to store the squared difference tensor before reduction. If masked, an additional mask tensor of size $O(N)$ is required [S8, unofficial].

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- Scales linearly with resolution and batch size.

**Strengths and Limitations:**
- **Strengths:** Simple to implement, differentiable everywhere, standard baseline for photometric fidelity [S3, unofficial].
- **Limitations:** Sensitive to outliers and noise; does not account for structural similarity or human perception [S1, unofficial].

**When to use it and when not:**
- Use as the primary loss for training when photometric accuracy is the main goal and the data is clean [S3, unofficial].
- Avoid when structural fidelity is more important than pixel-wise accuracy (use SSIM) or when data contains significant noise/outliers (use Huber or Visibility-Based Loss) [S1, unofficial].

## Background
MSE Loss is a fundamental metric in image and volume reconstruction, originating from classical signal processing and optimization theory [S1, unofficial][S4]. It is widely used in differentiable volume rendering pipelines, such as NeRF and its variants, as the primary objective for minimizing the difference between rendered and ground-truth images [S2, S3, S6, unofficial]. The conversion to PSNR provides a standardized logarithmic scale for comparing reconstruction quality across different datasets and resolutions [S2, unofficial][S4].
