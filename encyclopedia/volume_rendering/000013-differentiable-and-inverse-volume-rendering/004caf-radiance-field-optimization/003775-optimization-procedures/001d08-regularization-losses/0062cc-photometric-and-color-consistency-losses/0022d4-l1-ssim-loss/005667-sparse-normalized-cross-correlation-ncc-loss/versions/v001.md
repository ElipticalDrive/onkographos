# Sparse Normalized Cross-Correlation (NCC) Loss
Also called: Tile-wise Structure-Aware Loss
## Overview
A local structure-aware loss that provides sparse yet effective supervision to preserve fine details and stabilize training by measuring sparse Normalized Cross-Correlation (NCC) [S1, unofficial]. It builds on [L1+SSIM Loss](2890-l1-ssim-loss.md) by restricting the structural consistency check to sparsely sampled pixels within tiles, prioritizing challenging regions to avoid redundant gradient computation [S1, unofficial].
## How it works
**Inputs and outputs:**
- Input: Rendered image tiles and ground truth image tiles.
- Input: Per-tile sparsely sampled pixel coordinates, determined by multi-view reconstruction errors [S1, unofficial].
- Output: Scalar loss value per tile or batch.

**Data structures:**
- Not given in the sources.

**Steps:**
1. Perform per-tile sparse pixel sampling driven by multi-view reconstruction errors during training [S1, unofficial]. This prioritizes challenging regions and skips well-reconstructed ones [S1, unofficial].
2. For each tile, identify the set of sparsely sampled pixels [S1, unofficial].
3. Measure the sparse Normalized Cross-Correlation (NCC) between the rendered and ground truth pixel values within each tile using the sparsely sampled pixels [S1, unofficial].
4. Compute the loss based on the NCC measurement to stabilize optimization while preserving fine details [S1, unofficial].

## Operating characteristics
**Time and memory complexity:**
- Time: The method reduces redundant gradient computation by skipping well-reconstructed regions, contributing to up to ~10× training speedup over vanilla 3DGS in the TurboGS framework [S1, unofficial].
- Memory: Not given in the sources.

**Measured performance:**
- TurboGS delivers on par or superior rendering quality within 100 seconds [S1, unofficial].
- Specific metrics for the loss component alone are not isolated in the sources; overall benchmark results include 23.40 dB PSNR and 0.766 SSIM for comparable methods, with TurboGS achieving competitive results [S1, unofficial].

**Scaling:**
- Scales with the number of tiles and the sparsity of the sampling [S1, unofficial].

**Strengths and limitations:**
- Strengths: Stabilizes optimization, preserves fine details, avoids redundant gradient computation [S1, unofficial].
- Limitations: Relies on accurate multi-view error maps for sampling [S1, unofficial].

**When to use it and when not:**
- Use when training speed is critical and fine detail preservation is needed, particularly in the context of 3D Gaussian Splatting optimization [S1, unofficial].
- Not given in the sources for when not to use.
