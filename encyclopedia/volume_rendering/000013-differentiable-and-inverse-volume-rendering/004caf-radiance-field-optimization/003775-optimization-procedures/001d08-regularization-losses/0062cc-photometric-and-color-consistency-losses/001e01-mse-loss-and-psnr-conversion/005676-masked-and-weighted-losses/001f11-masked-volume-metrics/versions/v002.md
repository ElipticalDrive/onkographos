# Masked Volume Metrics

Also called: Effective Region of Interest (ROI) Calculation, Masked MSE and PSNR Computation, Masked Volume MSE/PSNR Computation, ROI Calculation, Region of Interest (ROI) Calculation

## Overview
Masked Volume Metrics is a method for computing evaluation metrics (such as MSE or PSNR) in volumetric rendering by excluding empty froxels from the analysis [S1, unofficial]. It solves the problem of performance and quality analysis being skewed by regions of the volume that contain no radiance and thus provide no meaningful information [S1, unofficial]. It sets itself apart from standard metrics by dynamically defining a Region of Interest (ROI) based on the union of visible radiance in the test scenario and the ground truth, ensuring that only froxels participating in light transport are evaluated [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D froxel grid representing the rendered scenario (test scenario) and a 3D froxel grid representing the ground truth.
*   **Output:** A set of valid froxels ($ROI_{effective}$) used to compute the final metric, and the computed metric value (e.g., MSE) restricted to these froxels.

**Data Structures:**
*   **Froxel Grid:** A 3D array where each element (froxel) contains RGB color values.
*   **ROI Mask:** A binary 3D mask or a set of coordinates indicating which froxels are included in the effective region.

**Steps:**
1.  **Identify Scenario ROI ($ROI_{scenario}$):** Iterate through the froxel grid of the test scenario. A froxel is included in $ROI_{scenario}$ if any of its RGB channels contains a non-zero value at any point during the test scenario [S1, unofficial]. This identifies froxels affected by radiance from light sources or emission [S1, unofficial].
2.  **Identify Truth ROI ($ROI_{truth}$):** Identify froxels that contain non-zero values in the ground truth data [S1, unofficial].
3.  **Compute Effective ROI ($ROI_{effective}$):** Calculate the union of the scenario ROI and the truth ROI [S1, unofficial]:
    $$ROI_{effective} = ROI_{scenario} \cup ROI_{truth}$$
    This ensures that froxels relevant to either the algorithm's output or the ground truth are included, while completely empty regions are excluded [S1, unofficial].
4.  **Compute Metric:** Calculate the base loss metric (e.g., MSE) only over the froxels present in $ROI_{effective}$ [S1, unofficial].

**Pseudocode:**
```python
def compute_masked_volume_metrics(rendered_volume, ground_truth_volume):
    """
    Compute MSE over the effective ROI defined by non-zero radiance in 
    either the rendered scenario or the ground truth.
    
    Args:
        rendered_volume: 3D numpy array (H, W, D, 3) representing the test scenario.
        ground_truth_volume: 3D numpy array (H, W, D, 3) representing ground truth.
        
    Returns:
        mse: float, the Mean Squared Error over the effective ROI.
        roi_mask: 3D boolean array, the mask of valid froxels.
    """
    # Step 1: Identify froxels with non-zero RGB channels in the scenario
    # A froxel is active if any channel is non-zero
    scenario_active = np.any(rendered_volume != 0, axis=-1)
    
    # Step 2: Identify froxels with non-zero values in ground truth
    truth_active = np.any(ground_truth_volume != 0, axis=-1)
    
    # Step 3: Compute Effective ROI as the union
    roi_mask = scenario_active | truth_active
    
    # Step 4: Compute MSE only over valid froxels
    # Extract values where mask is True
    rendered_valid = rendered_volume[roi_mask]
    truth_valid = ground_truth_volume[roi_mask]
    
    # Calculate MSE
    mse = np.mean((rendered_valid - truth_valid) ** 2)
    
    return mse, roi_mask
```

**Parameters:**
*   **Threshold for Non-Zero:** The sources specify "non-zero value" [S1, unofficial]. In practice, a small epsilon might be used to handle floating-point noise, but the source definition is strictly non-zero [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Empty Regions:** If both the scenario and ground truth are empty in a region, those froxels are excluded, preventing them from skewing the metric with zero-error counts that do not reflect visual quality [S1, unofficial].
*   **Algorithm-Specific ROIs:** The ROI is computed separately for each tested algorithm because different methods may produce non-zero contributions in different regions of the froxel grid even in the same test scenario [S1, unofficial].

## Subtopics

### One-Sided RMSE for Feature Evaluation
A numerical metric to evaluate feature difference at a certain scale, computed only for voxels where the approximation $A_f$ is within a given intensity range of interest [S2]. It is used to verify structural simplification of features by comparing the original data set $A$ to its approximation $A_f$ [S2]. The formula is:
$$E = \sqrt{\frac{1}{m} \sum_{i,j,k} (A[i,j,k] - A_f[i,j,k])^2}$$
where the sum is over $m$ voxels where $A_f[i,j,k]$ is within the given intensity range of interest [S2]. This is useful when interested in feature difference at a specific scale rather than global error [S2].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the total number of froxels, as it requires a single pass to identify active froxels and a second pass to compute the metric over the valid subset.
*   **Memory Complexity:** $O(N)$ to store the ROI mask or the set of valid froxel indices.
*   **Strengths:** Excludes completely empty regions that do not contribute meaningful information, providing a more accurate assessment of visual quality and performance for participating media [S1, unofficial].
*   **Limitations:** Requires access to both the rendered scenario and ground truth to compute the union ROI. It may not be suitable for scenarios where empty space is a critical part of the evaluation (e.g., transparency testing).
*   **When to Use:** When evaluating volumetric rendering algorithms where in-scattering and empty regions do not contribute to the visual result, and the goal is to zoom in on froxels participating in light transport [S1, unofficial].

## Background
The method originates from research on temporal anti-aliasing for real-time froxel-based volumetric rendering [S1, unofficial]. It was developed to address the need for accurate performance and quality analysis in production rendering environments, specifically within the Frostbite engine [S1, unofficial]. The approach ensures that evaluation metrics are not skewed by regions unaffected by in-scattering or light transport [S1, unofficial].
