# Masked Volume Metrics

Also called: Effective Region of Interest (ROI) Calculation, Masked MSE and PSNR Computation, Masked Volume MSE/PSNR Computation, ROI Calculation, Region of Interest (ROI) Calculation

## Overview
Masked Volume Metrics is a method for computing evaluation metrics (such as MSE and PSNR) in volumetric rendering by excluding empty or irrelevant froxels from the error calculation. It solves the problem of performance metrics being skewed by large regions of the volume that contain no radiance or meaningful data. It sets itself apart from standard MSE by dynamically defining a Region of Interest (ROI) based on the union of the rendered scenario's active radiance and the ground truth's active data, ensuring only froxels participating in light transport are evaluated [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A volumetric grid of froxels (or voxels). For each froxel, the RGB color values at all time steps (or frames) of the test scenario. The ground truth volumetric data.
- **Output:** A masked metric value (e.g., MSE, PSNR) computed only over the effective ROI.

**Data Structures:**
- **Froxel Grid:** A 3D array representing the volume. Each element contains RGB color values.
- **ROI Mask:** A boolean 3D array of the same dimensions as the froxel grid, where `True` indicates the froxel is included in the effective ROI.

**Steps:**
1. **Identify Scenario ROI ($ROI_{scenario}$):**
   Iterate through all froxels in the grid. A froxel is included in $ROI_{scenario}$ if any of its RGB channels contains a non-zero value at any point during the test scenario. This identifies froxels affected by radiance (from light sources or emission) [S1, unofficial].
   
2. **Identify Ground Truth ROI ($ROI_{truth}$):**
   Identify froxels in the ground truth data that contain non-zero values. This represents the regions where meaningful data exists in the reference [S1, unofficial].

3. **Compute Effective ROI ($ROI_{effective}$):**
   Compute the union of the scenario ROI and the ground truth ROI:
   $$ROI_{effective} = ROI_{scenario} \cup ROI_{truth}$$
   This ensures that froxels relevant to either the rendered output or the ground truth are included, excluding completely empty regions [S1, unofficial].

4. **Compute Metrics:**
   Calculate the desired metric (e.g., MSE) only over froxels where the mask in $ROI_{effective}$ is true.

**Pseudocode:**
```python
def compute_masked_volume_metrics(rendered_volume, ground_truth_volume, time_steps):
    """
    rendered_volume: 3D array (X, Y, Z, 3) or list of 3D arrays for each time step
    ground_truth_volume: 3D array (X, Y, Z, 3)
    time_steps: list of time step indices or frames
    
    Returns:
    masked_mse: float
    roi_mask: 3D boolean array
    """
    # Step 1: Identify Scenario ROI
    # Initialize a boolean mask for the scenario
    scenario_roi_mask = np.zeros_like(ground_truth_volume[..., 0], dtype=bool)
    
    # Iterate through all time steps in the test scenario
    for t in time_steps:
        # Get the rendered volume at time step t
        # Note: rendered_volume might be a list of frames or a 4D array
        frame = rendered_volume[t] if isinstance(rendered_volume, list) else rendered_volume[t]
        
        # Check if any RGB channel has a non-zero value
        # Using a small epsilon for floating point comparisons if necessary
        non_zero = np.any(frame > 1e-6, axis=-1)
        
        # Union with existing scenario ROI
        scenario_roi_mask = np.logical_or(scenario_roi_mask, non_zero)
        
    # Step 2: Identify Ground Truth ROI
    # Froxels with non-zero values in ground truth
    truth_roi_mask = np.any(ground_truth_volume > 1e-6, axis=-1)
    
    # Step 3: Compute Effective ROI
    effective_roi_mask = np.logical_or(scenario_roi_mask, truth_roi_mask)
    
    # Step 4: Compute Metrics (e.g., MSE)
    # Extract values only where effective_roi_mask is True
    rendered_values = rendered_volume[time_steps[-1]] # Use final frame or average? 
    # Note: The source [S1, unofficial] implies the ROI is used for evaluation metrics. 
    # Typically, MSE is computed on a specific frame or averaged. 
    # Assuming we compute MSE on the final rendered frame against ground truth.
    
    # Get the final rendered frame for comparison
    final_rendered = rendered_volume[time_steps[-1]] if isinstance(rendered_volume, list) else rendered_volume[time_steps[-1]]
    
    # Apply mask
    rendered_masked = final_rendered[effective_roi_mask]
    truth_masked = ground_truth_volume[effective_roi_mask]
    
    # Compute MSE
    mse = np.mean((rendered_masked - truth_masked) ** 2)
    
    return mse, effective_roi_mask
```

**Parameters:**
- **Epsilon:** A small threshold (e.g., $10^{-6}$) to determine "non-zero" values, accounting for floating-point precision [G].
- **Time Steps:** The set of frames or time points considered in the test scenario [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point noise might cause froxels to have very small non-zero values. An appropriate epsilon threshold is needed to avoid including truly empty froxels [G].
- **Boundary Conditions:** Froxels on the boundary of the volume might be partially visible. The method assumes froxel-level binary inclusion (non-zero vs zero) [S1, unofficial].
- **Degenerate Input:** If both $ROI_{scenario}$ and $ROI_{truth}$ are empty, the metric is undefined. The implementation should handle this case [G].

## Subtopics

### One-Sided RMSE for Feature Evaluation
A numerical metric to evaluate feature difference at a certain scale, computed only for voxels where the approximation $A_f$ is within a given intensity range of interest. It is used to verify the simplification of features by comparing the original data set $A$ to its approximation $A_f$. The RMSE is computed one-sided, evaluated only for the $m$ voxels where $A_f[i, j, k]$ is within a given intensity range of interest [S2].

Formula:
$$E = \sqrt{\frac{1}{m} \sum_{i,j,k} (A[i,j,k] - A_f[i,j,k])^2}$$
where the sum is over $m$ voxels where $A_f[i, j, k]$ is in the intensity range of interest [S2].

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of froxels in the volume, as it requires a single pass to build the ROI mask and another pass to compute the metric.
- **Memory Complexity:** $O(N)$ for storing the ROI mask.
- **Strengths:** Excludes irrelevant empty regions, providing a more accurate assessment of rendering quality in areas of interest. Reduces the impact of background noise or empty space on metrics [S1, unofficial].
- **Limitations:** Requires access to both the rendered output and the ground truth to define the ROI. The definition of "non-zero" may need tuning based on the specific rendering pipeline and precision [S1, unofficial].
- **When to Use:** When evaluating volumetric rendering algorithms where large portions of the volume are empty or do not participate in light transport. Particularly useful in real-time rendering contexts like those in the Frostbite engine [S1, unofficial].
- **When Not to Use:** When the entire volume is expected to be active, or when background regions are part of the evaluation criteria.

## Background
The method was introduced in the context of temporal anti-aliasing for real-time froxel-based volumetric rendering. It was developed to address the issue of evaluation metrics being skewed by froxels unaffected by in-scattering and light transport. The method is implemented and evaluated within the Frostbite engine [S1, unofficial]. The concept of using an ROI to focus on relevant data is also seen in other contexts, such as tensor approximation for multiscale volume feature representations, where one-sided RMSE is used to evaluate feature simplification [S2].
