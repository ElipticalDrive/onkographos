# PSNR Metric Calculation

Also called: PSNR Calculation, PSNR Metric, Peak Signal-to-Noise Ratio

## Overview
Peak Signal-to-Noise Ratio (PSNR) is a standard benchmark metric used to evaluate the quality of reconstructed images or volumes in novel view synthesis and radiance field optimization [S2, unofficial]. It quantifies the photometric fidelity between a rendered prediction and a ground-truth reference by converting the Mean Squared Error (MSE) into a logarithmic decibel (dB) scale [S3, unofficial]. Unlike structural metrics such as SSIM, PSNR focuses strictly on pixel-wise intensity error, making it a fast, objective measure of reconstruction accuracy, though it is known to correlate imperfectly with human perception [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** Two arrays of identical dimensions representing the target image/volume $y$ and the predicted image/volume $x$. The values are typically normalized to the range $[0, 1]$ or $[0, 255]$.
- **Output:** A single floating-point scalar representing the PSNR in decibels (dB). Higher values indicate better quality.

**Data Structures:**
- The inputs are treated as dense arrays of shape $(H, W, C)$ for images or $(D, H, W, C)$ for volumes, where $C$ is the number of channels (typically 3 for RGB).
- No intermediate data structures are required beyond scalar accumulators for the error sum.

**Parameters:**
- `max_val`: The maximum possible pixel value. Default is $1.0$ if inputs are normalized to $[0, 1]$, or $255$ if inputs are 8-bit integers [S2, unofficial].
- `eps`: A small constant added to the MSE to prevent division by zero or logarithm of zero. Typical value is $10^{-10}$ [S3, unofficial].

**Formulas:**
The core calculation involves two steps: computing the MSE and then converting it to PSNR.

1. **Mean Squared Error (MSE):**
   $$ \text{MSE} = \frac{1}{N} \sum_{i=1}^{N} (x_i - y_i)^2 $$
   where $N$ is the total number of elements (pixels or voxels) across all channels, and $x_i, y_i$ are the predicted and target values respectively [S4].

2. **Peak Signal-to-Noise Ratio (PSNR):**
   $$ \text{PSNR} = 10 \log_{10} \left( \frac{\text{MAX}^2}{\text{MSE} + \epsilon} \right) $$
   Alternatively, using the identity $\log_{10}(A/B) = \log_{10}(A) - \log_{10}(B)$ and $\log_{10}(X^2) = 2\log_{10}(X)$:
   $$ \text{PSNR} = 20 \log_{10}(\text{MAX}) - 10 \log_{10}(\text{MSE} + \epsilon) $$
   where $\text{MAX}$ is the maximum representable pixel value and $\epsilon$ is the epsilon constant [S2, unofficial][S4].

**Pseudocode:**
```python
import math

def calculate_psnr(target: list, predicted: list, max_val: float = 1.0, eps: float = 1e-10) -> float:
    """
    Calculate Peak Signal-to-Noise Ratio between target and predicted arrays.
    
    Args:
        target: List or array of ground truth values.
        predicted: List or array of predicted values.
        max_val: Maximum possible pixel value (default 1.0 for normalized data).
        eps: Small constant to prevent log(0).
        
    Returns:
        PSNR value in dB.
    """
    # Validate dimensions
    if len(target) != len(predicted):
        raise ValueError("Target and predicted arrays must have the same length.")
    
    n_elements = len(target)
    if n_elements == 0:
        return float('inf') # Or handle as error
        
    # Compute Mean Squared Error
    mse_sum = 0.0
    for t, p in zip(target, predicted):
        diff = t - p
        mse_sum += diff * diff
        
    mse = mse_sum / n_elements
    
    # Compute PSNR
    # Using the 10 * log10(MAX^2 / MSE) formulation
    # Note: If max_val is 1.0, MAX^2 is 1.0, so log10(1/MSE) = -log10(MSE)
    # The factor 10 applies to the log10 of the ratio.
    
    # Guard against zero MSE resulting in infinity
    if mse < eps:
        mse = eps
        
    psnr = 10.0 * math.log10((max_val ** 2) / mse)
    
    return psnr
```

**Edge Cases and Pitfalls:**
- **Zero MSE:** If the prediction is identical to the target, MSE is 0, leading to $\log_{10}(0)$ which is undefined (negative infinity). A small epsilon ($10^{-10}$) is added to the denominator to stabilize the calculation [S3, unofficial].
- **Dimension Mismatch:** Inputs must have identical spatial dimensions and channel counts. Mismatched dimensions should raise an error or return a sentinel value (e.g., `float.MaxValue`) [S6, unofficial].
- **Weighting Bias:** PSNR averages error over all pixels. Large smooth regions dominate the score, while small, high-frequency details (like specular highlights or thin structures) have negligible impact on the final value [S1, unofficial].
- **Interpretation:** The scale is logarithmic. A difference of 3 dB corresponds to a halving of the squared error, and 6 dB corresponds to a quartering [S1, unofficial].

## Subtopics

### [3D Evaluation Metrics](2903-3d-evaluation-metrics.md)
3D Evaluation Metrics extend PSNR and SSIM to volumetric data by computing these metrics across axial, coronal, and sagittal slices. Unlike standard 2D PSNR which evaluates pixel-level photometric error in projections, this approach assesses both geometric and photometric fidelity in 3D space. It serves as the foundational evaluation layer for mesh reconstruction and normal consistency checks.

### [Benchmark Performance Numbers](3471-benchmark-performance-numbers.md)
Benchmark Performance Numbers provide standardized baselines for radiance field methods, primarily using the Mip-NeRF 360 dataset metrics (average PSNR and LPIPS). These numbers aggregate results across specific scene sets to compare reconstruction quality against established baselines like 3DGS or Mip-Splatting. They highlight trade-offs between visual fidelity, geometric accuracy, and resource efficiency.

### [PSNR Difference Metric for Ablation](5656-psnr-difference-metric-for-ablation.md)
The PSNR Difference Metric for Ablation quantifies performance degradation by comparing the PSNR of an ablated configuration against the full method. It isolates the error ratio independent of the bit depth (MAX), as MAX cancels out in the logarithmic difference, providing a scale-invariant measure of quality loss.

### Noise Floor Estimation via MAD
This variant estimates the noise floor using Median Absolute Deviation (MAD) to determine the theoretical maximum PSNR (noise floor) for a given volume [S7, unofficial]. It uses estimators such as the Laplacian MAD or Haar finite-difference MAD to compute the noise standard deviation $\sigma$. The noise floor PSNR is then calculated as $10 \log_{10}(1/\sigma^2)$ [S7, unofficial]. A pitfall is that MAD estimators may return zero for signal-limited volumes (e.g., Mouse heart nuclei), indicating the model is not noise-limited [S7, unofficial].

### PSNR Loss
PSNR Loss uses the PSNR formula as a regression metric during training [S8, unofficial]. It is computed as $\text{PSNR} = 20 \log_{10}(\text{max\_val} / \sqrt{\text{MSE}})$ [S8, unofficial]. While typically used as an evaluation metric, it can be adapted as a differentiable loss function, though MSE is more commonly used for optimization due to gradient stability [S8, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- **Time:** $O(N)$, where $N$ is the total number of pixels/voxels. The calculation requires a single pass to compute the squared differences and a constant-time logarithmic conversion.
- **Memory:** $O(1)$ auxiliary space. Only scalar accumulators (sum of squared errors) are needed. The input arrays must be held in memory.

**Measured Performance:**
- On standard NeRF Blender scenes, target PSNR values are typically 31–33 dB [S2, unofficial].
- A 3 dB increase represents a halving of the squared error, making PSNR sensitive to small improvements in high-quality reconstructions [S1, unofficial].

**Strengths and Limitations:**
- **Strengths:** Fast to compute, easy to interpret, and widely used as a standard benchmark for comparing different rendering pipelines [S2, unofficial].
- **Limitations:** It does not account for structural similarity or perceptual quality. It heavily weights large smooth areas and ignores small but visually important details (e.g., grass blades, specular highlights) [S1, unofficial]. It is also sensitive to pixel misalignment.

**When to Use:**
- Use PSNR for quick, objective comparison of photometric accuracy during training logging or when comparing methods on standard benchmarks [S2, unofficial].
- Do not rely on PSNR alone for final quality assessment; combine with SSIM, LPIPS, or human evaluation [S1, unofficial].

## Background
PSNR originated in signal processing and image compression as a measure of reconstruction quality [S4]. In the context of volume rendering and NeRFs, it has become a standard metric for evaluating novel view synthesis quality [S2, unofficial]. The metric is defined in foundational papers such as those evaluating Deep Learning Reconstruction methods [S4] and is widely cited in recent surveys of 3D Gaussian Splatting pipelines [S1, unofficial].
