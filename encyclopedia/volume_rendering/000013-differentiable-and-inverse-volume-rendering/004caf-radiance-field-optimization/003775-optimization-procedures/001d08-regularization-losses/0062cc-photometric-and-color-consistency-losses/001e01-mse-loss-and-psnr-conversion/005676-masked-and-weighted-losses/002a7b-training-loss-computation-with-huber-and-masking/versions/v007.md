# Training Loss Computation with Huber and Masking

Also called: NeRF training loss, RGB and TV loss calculation

## Overview
This method defines the standard photometric loss computation pipeline for differentiable volume rendering, specifically combining Huber loss for RGB error with validity-based masking to exclude invalid rays. It addresses the problem of optimizing neural radiance fields or sparse voxel grids where ground truth images may contain transparent regions, background colors, or invalid sampling intervals. It differs from its parent [Masked and Weighted Losses](15713-masked-and-weighted-losses.md) by specifying the exact Huber loss formulation and the procedural steps for blending ground truth backgrounds and aggregating per-ray losses, while its sibling [Masked Volume Metrics](1927-masked-volume-metrics.md) focuses on evaluation metrics rather than training optimization.

## How it works
**Inputs:**
- `worldspace_rays`: Ray origins and directions for the current batch.
- `appearance_embeddings`: Optional per-ray or per-view appearance codes.
- `bg`: Background color tensor (typically white or black) for blending.
- `gt_rgba_f32`: Ground truth RGBA image array in float32.
- `total_samples`: Number of sampling points per ray.

**Outputs:**
- `loss`: Scalar training loss value.
- `batch_metrics`: Dictionary containing intermediate loss components and validity counts.

**Data Structures:**
- `pred_rgbds`: Tensor of shape `(num_rays, num_samples, 4)`. The last dimension contains `[R, G, B, Depth]`.
- `ray_is_valid`: Boolean tensor of shape `(num_rays,)` indicating whether a ray intersects valid scene geometry or falls within the region of interest.
- `n_valid_rays`: Integer count of rays where `ray_is_valid` is True.

**Parameters:**
- `delta`: Huber loss threshold. Typical value: `0.1` [S1, unofficial].
- `loss_weight`: Scalar multiplier for loss components. Default: `1.0` [S1, unofficial].

**Steps:**
1. **Render:** Call the differentiable renderer with `worldspace_rays`, `appearance_embeddings`, `bg`, and `total_samples` to obtain `pred_rgbds` [S1, unofficial].
2. **Split:** Separate the prediction tensor into RGB and Depth components. Using JAX/NumPy slicing:
   $$ \text{pred\_rgbs}, \text{pred\_depths} = \text{jnp.array\_split}(\text{pred\_rgbds}, [3], \text{axis}=-1) $$
   where `pred_rgbs` has shape `(num_rays, num_samples, 3)` and `pred_depths` has shape `(num_rays, num_samples, 1)` [S1, unofficial].
3. **Blend Ground Truth:** Compute the expected ground truth RGB by blending the RGBA ground truth image with the background color to match the rendering conditions (which typically assume a white or black background for transparent regions):
   $$ \text{gt\_rgbs} = \text{blend\_rgba}(\text{gt\_rgba\_f32}, \text{bg}) $$
   This ensures that pixels with alpha < 1.0 are correctly compared against the rendered output which also blends against `bg` [S1, unofficial].
4. **Compute Per-Ray Huber Loss:** Calculate the Huber loss for each ray. The Huber loss is defined as:
   $$ L_{huber}(p, g) = \begin{cases} \frac{1}{2}(p - g)^2 & \text{if } |p - g| \le \delta \\ \delta(|p - g| - \frac{1}{2}\delta) & \text{otherwise} \end{cases} $$
   The loss is averaged over the samples within each ray, then masked by `ray_is_valid` [S1, unofficial]:
   $$ \text{loss\_rgb} = \frac{\sum_{i} \mathbb{I}(\text{ray\_is\_valid}_i) \cdot \text{mean}_s(L_{huber}(\text{pred\_rgbs}_{i,s}, \text{gt\_rgbs}_{i,s}), \delta=0.1)}{N_{valid}} $$
   where $N_{valid}$ is the count of valid rays [S1, unofficial].
5. **Aggregate:** Sum all loss components (e.g., RGB, depth, regularization) defined in `batch_metrics["loss"]` using tree reduction [S1, unofficial].

**Pseudocode:**
```python
def compute_training_loss(pred_rgbds, gt_rgba_f32, bg, ray_is_valid, batch_metrics):
    # 1. Split RGB and Depth
    pred_rgbs, pred_depths = jnp.array_split(pred_rgbds, [3], axis=-1)
    
    # 2. Blend Ground Truth RGB with background
    # Assuming blend_rgba handles alpha compositing: R_out = R_in * A_in + R_bg * (1 - A_in)
    gt_rgbs = blend_rgba_image_array(imgarr=gt_rgba_f32, bg=bg)
    
    # 3. Compute per-ray Huber loss for RGB
    # jnp.mean computes mean over the last axis (samples)
    # optax.huber_loss computes element-wise Huber loss with delta=0.1
    per_ray_loss = optax.huber_loss(pred_rgbs, gt_rgbs, delta=0.1).mean(axis=-1)
    
    # Mask by validity and sum
    masked_loss = jnp.where(ray_is_valid, per_ray_loss, 0.0)
    n_valid_rays = jnp.sum(ray_is_valid.astype(jnp.float32))
    
    # Avoid division by zero if no valid rays
    loss_rgb = jnp.where(n_valid_rays > 0, 
                         jnp.sum(masked_loss) / n_valid_rays, 
                         0.0)
    
    # 4. Aggregate with other losses in batch_metrics
    # batch_metrics["loss"] is a list of loss tensors to sum
    total_loss = jax.tree_util.tree_reduce(lambda x, y: x + y, batch_metrics["loss"])
    
    # Add RGB loss to the aggregation
    total_loss = total_loss + loss_rgb
    
    return total_loss, {"loss_rgb": loss_rgb, "n_valid_rays": n_valid_rays}
```

**Edge Cases and Pitfalls:**
- **Division by Zero:** If `n_valid_rays` is 0, the loss division must be guarded to prevent NaN gradients [G].
- **Background Mismatch:** If the renderer's background assumption differs from the `bg` used in blending, transparent regions will produce incorrect loss values [S1, unofficial].
- **Depth Loss:** The provided notes focus on RGB loss; depth loss computation (if used) should follow similar masking and aggregation logic [S1, unofficial].

## Subtopics

### [SH Masking](9858-sh-masking.md)
SH Masking (SHM) is a regularization technique for differentiable volume rendering optimization that suppresses the influence of saturated pixels during loss computation. Saturated regions (over- or undersaturation) lack reliable texture cues and act as outliers that bias geometric and photometric recovery. It differs from hard binary masking by using a "leaky" quadratic transition at the saturation boundaries, which allows smoother gradient flow while still reducing bias.

### Convergence Hinge Loss
A hinge loss on the mean mask value to ensure both foreground and background generators are used and cover a minimum fraction of the image [S2]. It prevents the model from collapsing to generating only foreground or only background [S2].

**Formula:**
Foreground convergence loss:
$$ L_{cvg}^{fg} = \lambda_{cvg}^{fg} \max\left(0, \eta_{fg} - \frac{1}{|S|} \sum_{i \in S} \hat{m}_{mask}^{fg}[i]\right) $$
Background convergence loss:
$$ L_{cvg}^{bg} = \lambda_{cvg}^{bg} \max\left(0, \eta_{bg} - \frac{1}{|S|} \sum_{i \in S} (1 - \hat{m}_{mask}^{bg}[i])\right) $$
where $\hat{m}_{mask}$ is the predicted mask value, $|S|$ is the number of pixels, and $\eta$ is the minimum coverage fraction [S2].

**Parameters:**
- Foreground minimum coverage ($\eta_{fg}$): 0.4 for AFHQ and FFHQ; 0.1 for Carla [S2].
- Background minimum coverage ($\eta_{bg}$): 0.1 [S2].
- Convergence loss weight ($\lambda_{cvg}^{fg}$): 0.1 [S2].
- Convergence loss weight ($\lambda_{cvg}^{bg}$): 0.1 [S2].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of valid rays and samples per ray. The Huber loss computation is element-wise and highly parallelizable on GPUs [S1, unofficial].
- **Memory Complexity:** Requires storing intermediate tensors for `pred_rgbs`, `gt_rgbs`, and per-ray losses. Memory usage scales with batch size and resolution [S1, unofficial].
- **Strengths:** Huber loss is more robust to outliers (e.g., noise, saturated pixels) than MSE, leading to more stable training in the presence of imperfect ground truth [S1, unofficial]. Masking ensures that invalid rays (e.g., sky, empty space) do not contribute to the gradient, improving geometric accuracy [S1, unofficial].
- **Limitations:** Requires accurate validity masks; incorrect masking can lead to artifacts. The blending step assumes a known background color, which may not always be available or correct [S1, unofficial].
- **When to Use:** Standard choice for training NeRFs and voxel-based radiance fields when ground truth images have transparent regions or require background blending [S1, unofficial].
- **When Not to Use:** When computational resources are extremely limited and MSE is sufficient, or when no background blending is needed (e.g., opaque scenes with solid backgrounds).

## Background
Originated in the context of training Neural Radiance Fields (NeRF) and sparse voxel grid models like Plenoxels and VoxGRAF. The use of Huber loss for RGB and validity masking is a standard practice in modern differentiable rendering pipelines to handle the complexities of real-world image data, such as transparency and varying background conditions [S1, unofficial][S2]. The convergence hinge loss variant was introduced in VoxGRAF to ensure balanced foreground/background generation in 3D-aware image synthesis [S2].
