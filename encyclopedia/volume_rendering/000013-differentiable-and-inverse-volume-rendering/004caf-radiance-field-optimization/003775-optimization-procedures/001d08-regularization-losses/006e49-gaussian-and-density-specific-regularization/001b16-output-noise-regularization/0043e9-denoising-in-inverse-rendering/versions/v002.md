# Denoising in Inverse Rendering

Also called: Learned Denoising, OptiX denoiser, Primal Denoising

## Overview
This method applies a learned denoiser to Monte Carlo renders in inverse rendering pipelines to reduce variance [S1, S2]. Unlike sibling methods that impose spatial constraints on radiance field parameters, it operates directly on pixel-space images [S1, S2]. However, directly denoising the primal rendered image introduces bias that impedes gradient-based optimization, whereas applying the denoiser to a control variate estimator progressively reduces bias and improves reconstruction quality [S1, S2].

## How it works
**Inputs:**
- The noisy primal rendered image $I_{\text{primal}}$ (RGB) [S1].
- A pre-trained learned denoiser network $D(\cdot)$, such as the OptiX denoiser based on Chaitanya et al. [2017] [S1].

**Outputs:**
- The denoised image $I_{\text{denoised}}$ [S1].

**Data Structures:**
- The denoiser $D$ is a convolutional neural network trained on large datasets of rendered images [S1]. Architecture details are not provided in the sources [S1].

**Steps:**
1. Apply the learned denoiser to the primal image: $I_{\text{denoised}} = D(I_{\text{primal}})$ [S1].
2. Compute gradients for the inverse rendering optimization [S1].

**Edge Cases and Pitfalls:**
- **Bias Introduction:** Directly denoising the primal image adds bias that impedes optimization, potentially turning an unbiased optimization into a non-converging one [S1, S2].
- **Artifacts:** The bias can cause unrealistic artifacts, such as the brightening of the tea in a teapot [S1, S2].
- **Denoiser Choice:** The negative effects are observed with the OptiX denoiser, but similar behavior is expected with other learned denoisers [S1, S2].

**Pseudocode:**
```python
def apply_primal_denoiser(primal_image, denoiser):
    """Applies a learned denoiser to a primal rendered image."""
    # Apply learned denoiser to primal rendered image [S1]
    denoised_image = denoiser(primal_image)
    # Compute gradients for inverse rendering optimization [G]
    return denoised_image
```

## Operating characteristics
Time and memory complexity are not given in the sources. Directly applying the denoiser to the primal image reduces reconstruction quality [S1, S2]. In a challenging indirect illumination scene, L1 error was 1.47e-02 and L2 error was 5.17e-04 for the baseline with denoising [S2]. The method reduces visual noise but introduces bias that impedes optimization [S1, S2]. It is not recommended for direct primal denoising; instead, denoising the control variate estimator is preferred, which progressively reduces bias and yields better results (L1: 1.44e-02, L2: 4.60e-04 in the same scene) [S1, S2].

## Background
The method originates from "Recursive Control Variates for Inverse Rendering" by Nicolet et al. (2023) [S1, S2]. Learned denoisers are common in forward Monte Carlo rendering pipelines to reduce noise in final images, but their application in inverse rendering is counter-intuitive due to the requirement for differentiable gradients [S1, S2]. The study demonstrates that while denoising reduces variance, the introduced bias is detrimental to the optimization process [S1, S2]. The authors propose denoising the control variate estimator instead to mitigate these issues [S1, S2].
