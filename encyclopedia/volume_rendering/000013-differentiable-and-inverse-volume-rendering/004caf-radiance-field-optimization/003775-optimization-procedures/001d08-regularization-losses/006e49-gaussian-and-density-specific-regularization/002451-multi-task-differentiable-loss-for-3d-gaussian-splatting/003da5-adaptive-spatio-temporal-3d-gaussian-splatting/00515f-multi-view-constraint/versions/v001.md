# Multi-View Constraint

Also called: Patch Matching Regularization

## Overview
Multi-View Constraint is a regularization technique that enforces color consistency between reference and neighborhood views using patch matching and homography warping, specifically to improve geometry reconstruction in textureless regions where standard 3D Gaussian Splatting (3DGS) struggles [S1]. It sets itself apart from its sibling [Multi-view Regularization](23237-multi-view-regularization.md) by relying on homography warping for color consistency rather than explicitly computing a forward-backward reprojection cycle error [S1].

## How it works
**Inputs and Outputs**
*   **Inputs**: A set of training images (reference and neighborhood views), camera poses (relative rotation $R$ and translation $t$), intrinsic matrix $K$, and the current state of 3D Gaussians (positions, orientations, opacities, colors).
*   **Outputs**: A scalar loss value $L_{mv}$ added to the total training objective.

**Data Structures**
*   **Rendered Maps**: Depth map $D$ and Normal map $N$ for each view, generated by alpha-blending 3D Gaussians.
*   **Homography Matrix $H$**: A $3 \times 3$ matrix mapping pixels from reference to neighborhood view.
*   **Patch $P_i$**: A set of neighboring pixels around a target pixel $p$.

**Formulas**
1.  **Homography Warping**:
    $$p' = Hp$$
    Where $H$ is defined as:
    $$H = K \left( R - \frac{t n^T}{d} \right) K^{-1}$$
    Here, $R \in \mathbb{R}^{3 \times 3}$ and $t \in \mathbb{R}^{1 \times 3}$ are the relative rotation and translation between the reference and source views, $K \in \mathbb{R}^{3 \times 3}$ is the camera intrinsic matrix, $n \in \mathbb{R}^{1 \times 3}$ is the rendered normal at pixel $p$, and $d$ is the distance from the camera origin to the spatial plane defined by $n$.

2.  **Multi-View Loss**:
    $$L_{mv} = \sum_{p \in P_i} (1 - \text{NCC}(p, p'))$$
    Where $\text{NCC}(p, p')$ is the Normalized Cross Correlation between the patch at $p$ in the reference view and the patch at $p'$ in the neighborhood view.

3.  **Total Loss Integration**:
    $$L = (1 - \lambda)L_1 + \lambda L_{SSIM} + L_{mv}$$
    Where $L_1$ and $L_{SSIM}$ are standard image reconstruction losses from 3DGS [S1].

**Numbered Steps**
1.  **Identify Neighborhood Frames**: For each reference image, identify its neighborhood frames from the subgraphs [S1].
2.  **Render Depth and Normal Maps**: For each image, render depth and normal maps by overlapping the positions and orientations of 3D Gaussians using alpha blending [S1].
3.  **Establish Spatial Plane**: For a pixel $p$ in the reference view, establish a spatial plane defined by the rendered normal $n$ and distance $d$ from the camera origin [S1].
4.  **Compute Homography**: Calculate the homography matrix $H$ using the relative pose $(R, t)$, intrinsics $K$, and the local plane parameters $(d, n)$ [S1].
5.  **Warp Pixel**: Project pixel $p$ to its corresponding pixel $p'$ in the neighborhood view using $p' = Hp$ [S1].
6.  **Construct Patch**: Select neighboring pixels around $p$ to form patch $P_i$ [S1].
7.  **Evaluate Consistency**: Compute the Normalized Cross Correlation (NCC) between the patch at $p$ and the warped patch at $p'$ [S1].
8.  **Accumulate Loss**: Sum $(1 - \text{NCC})$ over all pixels in the patch to form $L_{mv}$ [S1].

**Pseudocode**
```python
def compute_multi_view_constraint(reference_view, neighborhood_view, gaussians, camera_intrinsics, relative_pose):
    """
    Computes the Multi-View Constraint loss between a reference and neighborhood view.
    """
    # 1. Render depth and normal maps for the reference view
    # Alpha blending is handled by the Gaussian rasterizer
    depth_map_ref, normal_map_ref = render_gaussians(gaussians, reference_view.camera)
    
    # 2. Extract relative rotation and translation
    R, t = relative_pose.R, relative_pose.t
    K = camera_intrinsics
    
    loss_mv = 0.0
    
    # 3. Iterate over pixels in the reference view
    # In practice, this is done on a grid or sampled points
    for p in reference_view.pixels:
        # Get normal and depth at pixel p
        n = normal_map_ref[p]
        d = depth_map_ref[p]
        
        # 4. Compute Homography Matrix H
        # H = K * (R - (t * n^T) / d) * K_inv
        # Note: t is row vector (1x3), n is row vector (1x3)
        # t * n^T results in a 3x3 matrix
        t_n_T = np.outer(t, n) # Outer product to get 3x3 matrix
        H = K @ (R - (t_n_T / d)) @ np.linalg.inv(K)
        
        # 5. Warp pixel p to p'
        # Homogeneous coordinates
        p_h = np.array([p.x, p.y, 1.0])
        p_prime_h = H @ p_h
        p_prime_h = p_prime_h / p_prime_h[2] # Normalize
        p_prime = (p_prime_h[0], p_prime_h[1])
        
        # 6. Construct patch Pi around p and warped patch around p'
        # Select neighboring pixels (e.g., 3x3 or 5x5 window)
        patch_p = get_patch(reference_view.image, p, radius=1)
        patch_p_prime = get_patch(neighborhood_view.image, p_prime, radius=1)
        
        # 7. Evaluate NCC
        ncc = normalized_cross_correlation(patch_p, patch_p_prime)
        
        # 8. Accumulate loss
        loss_mv += (1.0 - ncc)
        
    return loss_mv

def normalized_cross_correlation(patch1, patch2):
    """
    Computes NCC between two image patches.
    """
    mean1 = np.mean(patch1)
    mean2 = np.mean(patch2)
    
    diff1 = patch1 - mean1
    diff2 = patch2 - mean2
    
    numerator = np.sum(diff1 * diff2)
    denominator = np.sqrt(np.sum(diff1**2) * np.sum(diff2**2))
    
    if denominator == 0:
        return 0.0
    return numerator / denominator
```

**Parameters**
*   **Patch Radius**: Not given in the sources. The text mentions "several neighboring pixels" [S1].
*   **$\lambda$**: Weight for $L_{SSIM}$ in the total loss. Not given in the sources.

**Edge Cases and Pitfalls**
*   **Depth/Normal Accuracy**: The homography $H$ depends on the rendered depth $d$ and normal $n$. In textureless regions, these may be noisy or incorrect, leading to inaccurate warping [S1].
*   **Occlusions**: Single-pixel-based warping is susceptible to occlusions. The patch-based approach helps mitigate this by averaging over neighbors, but severe occlusions may still cause artifacts [S1].
*   **Lighting Variations**: The method is designed to mitigate lighting variations by using NCC on patches rather than single pixels [S1].

## Subtopics

### [Multi-view Regularization](23237-multi-view-regularization.md)
Penalizes cycle reprojection error to enforce multi-view geometric consistency. Sets itself apart by explicitly computing a forward-backward reprojection cycle error to handle occlusions and unreliable correspondences, rather than relying solely on patch matching and homography warping for color consistency.
