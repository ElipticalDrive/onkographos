# PlaneTV Regularization

Also called: PlaneTV, Total Variation on Planes

## Overview
PlaneTV Regularization computes the total variation (TV) of spatial planes within a feature tensor to encourage smoothness in the learned feature fields [S1, unofficial]. It differs from standard isotropic TV by explicitly separating horizontal and vertical gradient computations across 2D spatial slices, making it suitable for multi-dimensional tensors where specific dimensions represent spatial planes [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 4D tensor $t$ of shape $(B, C, H, W)$, where $B$ is batch size, $C$ is channel count, $H$ is height, and $W$ is width.
- Output: A scalar loss value representing the regularized TV.

**Data Structures:**
- The input tensor $t$ is treated as a collection of spatial planes. For a 3D grid length (standard 2D spatial), spatial grids are indices $[0, 1, 2]$ (Batch, Channel, Height) or similar depending on layout, but the core operation assumes a 4D structure where the last two dimensions are spatial [S1, unofficial]. If the grid length is not 3 (e.g., 4D spatiotemporal), spatial grids are identified as $[0, 1, 3]$ assuming index 3 is time, but the code implementation in [S1, unofficial] processes the last two dimensions as spatial $H$ and $W$ [S1, unofficial].

**Formula:**
The loss is computed as:
$$ L_{PlaneTV} = 2 \times \left( \frac{\sum (t_{i+1} - t_i)^2}{count_h} + \frac{\sum (t_{j+1} - t_j)^2}{count_w} \right) $$

Where:
- $t_{i+1} - t_i$ represents the difference along the height dimension (rows).
- $t_{j+1} - t_j$ represents the difference along the width dimension (columns).
- $count_h = B \times C \times (H-1) \times W$
- $count_w = B \times C \times H \times (W-1)$

**Steps:**
1. Compute the squared differences along the height dimension: $\sum (t_{i+1} - t_i)^2$.
2. Compute the squared differences along the width dimension: $\sum (t_{j+1} - t_j)^2$.
3. Normalize the height sum by $count_h$.
4. Normalize the width sum by $count_w$.
5. Sum the normalized values and multiply by 2.

**Pseudocode:**
```python
def compute_plane_tv(t: Tensor) -> float:
    """
    Computes PlaneTV regularization loss.
    t: Tensor of shape (B, C, H, W)
    """
    B, C, H, W = t.shape
    
    # Compute differences along height (dim 2)
    # t[:, :, 1:, :] - t[:, :, :-1, :]
    diff_h = t[:, :, 1:, :] - t[:, :, :-1, :]
    sum_h = torch.sum(diff_h ** 2)
    count_h = B * C * (H - 1) * W
    
    # Compute differences along width (dim 3)
    # t[:, :, :, 1:] - t[:, :, :, :-1]
    diff_w = t[:, :, :, 1:] - t[:, :, :, :-1]
    sum_w = torch.sum(diff_w ** 2)
    count_w = B * C * H * (W - 1)
    
    # Avoid division by zero if H=1 or W=1
    if count_h == 0:
        term_h = 0.0
    else:
        term_h = sum_h / count_h
        
    if count_w == 0:
        term_w = 0.0
    else:
        term_w = sum_w / count_w
        
    return 2.0 * (term_h + term_w)
```

**Parameters:**
- No explicit hyperparameters are defined in the core formula [S1, unofficial].

**Edge Cases:**
- If $H=1$ or $W=1$, the corresponding count becomes 0, leading to division by zero. The implementation must handle this by setting the term to 0 [G].

## Subtopics

### Triplane TV Regularization
Applies TV regularization specifically to triplane features to smooth them and make their gradients resemble natural images, which are modeled by a hyper-Laplacian with $\alpha \in [0.5, 0.8]$ [S2]. The regularization target $\alpha$ is typically set to 0.5 [S2]. This variant is chosen when training generative models (like autoencoders) on triplanes to prevent high-frequency artifacts [S2].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of elements in the tensor, $O(B \cdot C \cdot H \cdot W)$, as it requires a single pass to compute differences.
- **Memory Complexity:** $O(B \cdot C \cdot H \cdot W)$ to store the intermediate difference tensors if not computed in-place or streamed.
- **Strengths:** Encourages spatial smoothness in feature fields, reducing noise and high-frequency artifacts [S1, unofficial][S2].
- **Limitations:** May oversmooth fine details if the regularization weight is too high. The normalization factors depend on tensor dimensions, requiring careful handling of boundary conditions [S1, unofficial].

## Background
PlaneTV is used in the context of differentiable volume rendering and neural field optimization, specifically in frameworks like 4D Gaussian Splatting (4DGS) for dynamic scene reconstruction [S1, unofficial]. It builds on the concept of Total Variation regularization to enforce priors on learned representations. The Triplane TV variant is associated with Triplane Diffusion models for 3D neural field generation [S2].
