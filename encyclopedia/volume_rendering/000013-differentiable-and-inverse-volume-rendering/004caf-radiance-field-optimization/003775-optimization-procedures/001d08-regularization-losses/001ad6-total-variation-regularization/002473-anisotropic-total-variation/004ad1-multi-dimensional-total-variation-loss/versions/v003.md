# Multi-dimensional Total Variation Loss

Also called: Multi-dimensional TV, TV regularization on tensors

## Overview
Multi-dimensional Total Variation (TV) Loss computes the total variation regularization on multi-dimensional tensors by summing absolute differences along all spatial and channel dimensions [S1, unofficial]. It serves as a smoothness prior for feature fields, encouraging piecewise constant solutions while preserving sharp boundaries. It extends the standard 3D TV prior by generalizing the difference operation to arbitrary tensor shapes, including batch and channel dimensions [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A tensor $\mathbf{x}$ of shape $(B, C, D_1, D_2, \dots, D_k)$, where $B$ is batch size, $C$ is channel size, and $D_i$ are spatial dimensions [S1, unofficial].
- Output: A scalar loss value representing the sum of absolute differences across all specified dimensions.

**Data Structures:**
- The input $\mathbf{x}$ is a dense tensor. No auxiliary structures are required beyond standard tensor indexing.

**Algorithm:**
1. Initialize `tv_loss = 0`.
2. Determine the number of dimensions to iterate over. The iteration typically covers dimensions from index 2 to the last dimension (excluding batch and channel if they are not intended to be regularized, or including all if specified) [S1, unofficial].
3. For each dimension $i$ in the range $[2, \text{len}(\mathbf{x}.shape) - 1]$:
    a. Let $n_{res} = \mathbf{x}.shape[i]$.
    b. Create index sets: $idx_1 = [1, 2, \dots, n_{res}-1]$ and $idx_2 = [0, 1, \dots, n_{res}-2]$.
    c. Select slices: $\mathbf{x}_1 = \mathbf{x}[\dots, idx_1, \dots]$ and $\mathbf{x}_2 = \mathbf{x}[\dots, idx_2, \dots]$ along dimension $i$.
    d. Compute the absolute difference: $\Delta = |\mathbf{x}_1 - \mathbf{x}_2|$.
    e. Add the sum of $\Delta$ to `tv_loss`.
4. Return `tv_loss`.

**Pseudocode:**
```python
def multi_dim_tv_loss(x):
    """
    Computes the multi-dimensional total variation loss.
    x: Tensor of shape (B, C, D1, D2, ...)
    """
    tv = 0.0
    # Iterate over spatial dimensions (assuming dims 0 and 1 are batch/channel)
    # Note: Source [S1, unofficial] iterates from index 2 to len(x.shape)-1
    for i in range(2, len(x.shape)):
        n_res = x.shape[i]
        if n_res < 2:
            continue # Cannot compute difference on dimension of size 1
        
        # Create indices for slicing
        idx1 = list(range(1, n_res))
        idx2 = list(range(0, n_res - 1))
        
        # Select slices along dimension i
        # x.index_select(i, idx1) selects elements at indices idx1 along dim i
        x1 = x.index_select(i, torch.tensor(idx1, device=x.device))
        x2 = x.index_select(i, torch.tensor(idx2, device=x.device))
        
        # Compute absolute difference and sum
        diff = torch.abs(x1 - x2)
        tv += diff.sum()
        
    return tv
```

**Parameters:**
- None explicitly defined in the core algorithm [S1, unofficial].

**Edge Cases and Pitfalls:**
- If any spatial dimension has size 1, the difference along that dimension is undefined or zero. The implementation should skip such dimensions or handle them gracefully [S1, unofficial].
- Precision issues may arise with very large tensors due to accumulation of floating-point errors in the sum.

## Subtopics

### Decomposition Loss (Ld)
A variant used in inverse rendering to regularize material and lighting fields separately [S2]. It computes TV on a mask field $\hat{M}$ and a light field $\hat{E}$ using exponential weighting based on image intensity differences to preserve edges [S2].
- **Formula for Mask:** $TV_{mat} = \frac{1}{|\hat{M}|} \sum_{i,j} \Delta \hat{M}_{ij}$, where $\Delta \hat{M}_{ij} = \exp(-|I_{i,j} - I_{i-1,j}|) (\hat{M}_{i,j} - \hat{M}_{i-1,j})^2 + \exp(-|I_{i,j} - I_{i,j-1}|) (\hat{M}_{i,j} - \hat{M}_{i,j-1})^2$.
- **Formula for Light:** $TV_{light} = \frac{1}{|\hat{E}|} \sum_{i,j} \Delta \hat{E}_{ij}$, where $\Delta \hat{E}_{ij} = (\hat{E}_{i,j} - \hat{E}_{i-1,j})^2 + (\hat{E}_{i,j} - \hat{E}_{i,j-1})^2$.
- **When to choose:** When decomposing a scene into reflectance and illumination components, ensuring smoothness in both while respecting image edges [S2].

### PlaneTV Regularization
A regularizer that computes the total variation of spatial planes to encourage smoothness in feature fields, often used in 4D Gaussian Splatting [S3, unofficial]. It normalizes the squared differences by the count of elements in the height and width directions [S3, unofficial].
- **Formula:** $compute\_plane\_tv(t) = 2 \times \left( \frac{\sum (t_{i+1} - t_i)^2}{count_h} + \frac{\sum (t_{j+1} - t_j)^2}{count_w} \right)$, where $count_h = B \times C \times (H-1) \times W$ and $count_w = B \times C \times H \times (W-1)$.
- **Spatial Grid Identification:** For 3D grids, indices are $[0, 1, 2]$. For 4D grids (e.g., spatiotemporal), spatial grids are typically $[0, 1, 3]$ assuming index 2 is time, or as defined by the specific implementation [S3, unofficial].
- **When to choose:** When optimizing 4D scenes or feature fields where planar smoothness is desired [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \cdot D)$, where $N$ is the total number of elements in the tensor and $D$ is the number of dimensions iterated over. Each dimension requires a single pass over the tensor elements.
- **Memory Complexity:** $O(N)$ for storing the input tensor. The algorithm requires temporary storage for sliced tensors, which is proportional to the tensor size.
- **Strengths:** Simple to implement, differentiable, effective at removing noise and artifacts in optimized fields.
- **Limitations:** Can oversmooth fine details if the regularization weight is too high. The choice of which dimensions to include (batch, channel, spatial) significantly impacts the result [S1, unofficial].
- **When to use:** During the optimization of neural radiance fields or Gaussian splatting parameters to enforce spatial coherence.
- **When not to use:** When preserving high-frequency details is critical and the scene is known to be noisy rather than smooth.

## Background
The concept of Total Variation regularization originates from image processing, where it is used for denoising and segmentation [S1, unofficial]. In the context of volume rendering and neural fields, it has been adapted to regularize 3D and 4D feature grids. The specific multi-dimensional implementation described here is found in recent Gaussian Splatting variants like AnySplat [S1, unofficial] and 4DGS [S3, unofficial], as well as in inverse rendering frameworks like GS-IR [S2].
