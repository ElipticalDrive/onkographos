# Multi-dimensional Total Variation Loss

Also called: Multi-dimensional TV, TV regularization on tensors

## Overview
Multi-dimensional Total Variation (TV) Loss computes the total variation regularization on multi-dimensional tensors by summing absolute differences along all spatial and channel dimensions [S1, unofficial]. It extends the standard 3D spatial TV by treating channel dimensions as additional axes for difference calculation, thereby enforcing smoothness across the entire tensor structure [S1, unofficial]. It differs from [Anisotropic Total Variation](3273-anisotropic-total-variation.md) by including non-spatial dimensions in the gradient computation, and from [Sum of Absolute Differences (SAD)](3279-sum-of-absolute-differences-sad.md) by its specific application to high-dimensional tensor fields in optimization pipelines [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A tensor $\mathbf{x}$ of shape $(B, C, D_1, D_2, \dots, D_k)$, where $B$ is batch size, $C$ is channel size, and $D_i$ are spatial dimensions [S1, unofficial].
*   **Output:** A scalar loss value representing the total variation.

**Data Structures:**
*   $\mathbf{x}$: PyTorch tensor or equivalent numerical array [S1, unofficial].

**Steps:**
1.  Initialize `tv_loss` to 0.
2.  Determine the number of dimensions $N = \text{len}(\mathbf{x}.shape)$.
3.  Iterate over each dimension $i$ from index 1 to $N-1$ (inclusive). Note: Index 0 is typically the batch dimension and is excluded from TV calculation in the source implementation [S1, unofficial].
4.  For each dimension $i$:
    a.  Get the size of dimension $i$: $n_{res} = \mathbf{x}.shape[i]$.
    b.  Create index sets:
        *   $idx_1 = [1, 2, \dots, n_{res}-1]$
        *   $idx_2 = [0, 1, \dots, n_{res}-2]$
    c.  Extract slices along dimension $i$:
        *   $\mathbf{x}_1 = \mathbf{x}[\dots, idx_1, \dots]$
        *   $\mathbf{x}_2 = \mathbf{x}[\dots, idx_2, \dots]$
    d.  Compute the absolute difference: $\Delta = |\mathbf{x}_1 - \mathbf{x}_2|$.
    e.  Sum the absolute differences over all other dimensions to get a scalar contribution for this axis: $term_i = \sum \Delta$.
    f.  Add $term_i$ to `tv_loss`.
5.  Return `tv_loss`.

**Pseudocode:**
```python
def multi_dimensional_tv_loss(x):
    """
    Computes multi-dimensional total variation loss.
    x: Tensor of shape (B, C, D1, ..., Dk)
    """
    tv_loss = 0.0
    num_dims = len(x.shape)
    
    # Loop over dimensions 1 to num_dims-1 (excluding batch dim 0)
    for i in range(1, num_dims):
        n_res = x.shape[i]
        
        # Create indices for slicing
        # idx1: 1 to n_res-1
        # idx2: 0 to n_res-2
        idx1 = list(range(1, n_res))
        idx2 = list(range(0, n_res - 1))
        
        # Select slices along dimension i
        # Using advanced indexing or slicing logic equivalent to index_select
        # x1 shape: same as x except dim i has size n_res-1
        # x2 shape: same as x except dim i has size n_res-1
        
        # Construct slices for all dimensions
        slice1 = [slice(None)] * num_dims
        slice2 = [slice(None)] * num_dims
        
        slice1[i] = idx1
        slice2[i] = idx2
        
        x1 = x[tuple(slice1)]
        x2 = x[tuple(slice2)]
        
        # Compute absolute difference
        diff = torch.abs(x1 - x2)
        
        # Sum over all dimensions except the one we just sliced (which is now size n_res-1)
        # The source implies summing the result to a scalar contribution
        tv_loss += torch.sum(diff)
        
    return tv_loss
```

**Parameters:**
*   None explicitly defined in the source [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Batch Dimension:** The source implementation explicitly skips dimension 0 (batch) [S1, unofficial]. Including it would penalize differences between samples in a batch, which is usually incorrect for regularization.
*   **Small Dimensions:** If any dimension has size 1, the index ranges become empty, resulting in no contribution from that dimension. This is mathematically consistent (no variation possible).
*   **Precision:** Using `float32` may lead to precision issues in very large tensors; `float64` is safer for high-precision requirements [G].

## Subtopics

### Decomposition Loss (Ld)
A variant used in inverse rendering for reflectance decomposition [S2]. It applies a weighted TV loss to material ($\hat{M}$) and lighting ($\hat{E}$) fields. The material loss uses exponential weighting based on intensity gradients to preserve edges: $TV_{mat} = \frac{1}{|\hat{M}|} \sum_{i,j} \Delta \hat{M}_{ij}$, where $\Delta \hat{M}_{ij} = \exp(-|I_{i,j} - I_{i-1,j}|) (\hat{M}_{i,j} - \hat{M}_{i-1,j})^2 + \exp(-|I_{i,j} - I_{i,j-1}|) (\hat{M}_{i,j} - \hat{M}_{i,j-1})^2$ [S2]. The lighting loss is a standard squared difference TV: $TV_{light} = \frac{1}{|\hat{E}|} \sum_{i,j} \Delta \hat{E}_{ij}$, where $\Delta \hat{E}_{ij} = (\hat{E}_{i,j} - \hat{E}_{i-1,j})^2 + (\hat{E}_{i,j} - \hat{E}_{i,j-1})^2$ [S2]. This variant is chosen when edge-aware smoothing is required for material properties [S2].

## Operating characteristics
**Time and Memory Complexity:**
*   Time: $O(N \cdot \prod D_i)$, where $N$ is the number of dimensions processed and $\prod D_i$ is the total number of elements [S1, unofficial].
*   Memory: $O(\prod D_i)$ for storing intermediate difference tensors [S1, unofficial].

**Measured Performance:**
*   Not given in the sources.

**Scaling:**
*   Scales linearly with the number of dimensions and tensor size [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Enforces smoothness across all tensor axes, including channels, which helps in stabilizing optimization for multi-channel fields [S1, unofficial].
*   **Limitations:** May oversmooth sharp features if not weighted appropriately [G].

**When to use it:**
*   Use when optimizing multi-channel tensor fields (e.g., RGB+depth, or material properties) and smoothness is desired across all dimensions [S1, unofficial].

**When not:**
*   Do not use if only spatial smoothness is required (use [Anisotropic Total Variation](3273-anisotropic-total-variation.md)) or if batch-wise consistency is needed [S1, unofficial].

## Background
The multi-dimensional TV loss is implemented in the AnySplat repository [S1, unofficial]. It is a generalization of the standard TV norm to higher-dimensional tensors. The specific implementation details are derived from the AnySplat codebase [S1, unofficial].
