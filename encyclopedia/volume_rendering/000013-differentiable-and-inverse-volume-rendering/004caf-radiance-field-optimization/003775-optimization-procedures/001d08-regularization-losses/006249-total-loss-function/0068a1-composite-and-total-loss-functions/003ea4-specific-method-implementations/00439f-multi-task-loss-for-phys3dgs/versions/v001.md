# Multi-task Loss for Phys3DGS

Also called: Phys3DGS Total Loss

## Overview
The multi-task loss function for Phys3DGS [S1, unofficial] optimizes physically-based 3D Gaussian Splatting (3DGS) parameters for inverse rendering, specifically targeting the recovery of albedo, metalness, roughness, and indirect illumination. It distinguishes itself from standard 3DGS optimization by integrating a deferred rendering pipeline for PBR parameters and enforcing physical plausibility through bilateral smoothness and geometric regularization, whereas siblings like [HybridNeRF Optimization Loss](6045-hybridnerf-optimization-loss.md) focus on hybrid representations and [CF Loss](10573-cf-loss.md) on color field consistency.

## How it works
**Inputs and Outputs:**
*   **Inputs:** Training images, camera poses, an initial mesh (for geometric constraints), and hyperparameters $\lambda_{smooth}, \lambda_{o}, \lambda_{sc}, \lambda_{sr}$.
*   **Outputs:** Optimized Gaussian attributes: position, covariance, opacity, base color (albedo), metalness, roughness, and spherical harmonic (SH) coefficients for indirect illumination.

**Data Structures:**
Gaussians are defined by standard 3DGS attributes plus PBR-specific fields:
*   `base_color`: RGB, clamped to $[0, 1]$.
*   `metalness`: Scalar, clamped to $[0, 1]$.
*   `roughness`: Scalar, scaled and shifted to lie between $0.09$ and $1$ [S1, unofficial].
*   `indirect_illumination`: SH coefficients.

**Total Loss Formula:**
The total loss is a weighted sum of six components [S1, unofficial]:

$$ L_{total} = L_{L1} + L_{PBR} + \lambda_{smooth} L_{smooth} + \lambda_{o} L_{o} + \lambda_{sc} L_{sc} + \lambda_{sr} L_{sr} $$

Where:
*   $L_{L1}$: Volume rendering loss (photometric difference between rendered and ground truth images).
*   $L_{PBR}$: Photometric loss specific to the PBR rendering pipeline.
*   $L_{smooth}$: Bilateral smoothness loss applied to all BRDF parameters (albedo, metalness, roughness).
*   $L_{o}$: Masked opacity regularization.
*   $L_{sc}$: Gaussian scale regularization.
*   $L_{sr}$: Surface regularization loss.
*   $\lambda_{smooth}, \lambda_{o}, \lambda_{sc}, \lambda_{sr}$: Hyperparameters controlling the relative importance of each regularizer [S1, unofficial].

**Optimization Steps:**
1.  **Initialization:** Initialize Gaussians using sparse point clouds (e.g., from SfM) for positions [S2]. Initialize PBR parameters (albedo, metalness, roughness, SH coefficients).
2.  **Clamping and Scaling:**
    *   Clamp `base_color` and `metalness` to $[0, 1]$ [S1, unofficial].
    *   Scale and shift `roughness` to ensure values lie between $0.09$ and $1$ to prevent exceedingly strong specular reflectance [S1, unofficial].
3.  **Rendering:** Render images using a deferred rendering pipeline that separates PBR parameter computation [S1, unofficial].
4.  **Loss Computation:**
    *   Compute $L_{L1}$ and $L_{PBR}$ based on the rendered output.
    *   Compute $L_{smooth}$ using a non-parametric bilateral denoiser approach on BRDF parameters [S1, unofficial].
    *   Compute $L_{sr}$ to enforce Gaussians to stay near their original mesh triangles, preventing large vertex updates during back-propagation [S1, unofficial].
    *   Compute $L_{o}$ and $L_{sc}$ for opacity and scale regularization [S1, unofficial].
5.  **Update:** Minimize $L_{total}$ using gradient descent.

**Pseudocode:**

```python
def compute_phys3dgs_loss(rendered_image, ground_truth_image, gaussians, mesh, lambda_smooth, lambda_o, lambda_sc, lambda_sr):
    # 1. Clamp and Scale PBR parameters
    gaussians.base_color = clamp(gaussians.base_color, 0, 1)
    gaussians.metalness = clamp(gaussians.metalness, 0, 1)
    # Scale and shift roughness to [0.09, 1]
    gaussians.roughness = scale_and_shift(gaussians.roughness, min_val=0.09, max_val=1)

    # 2. Compute Rendering Losses
    # L_L1: Standard L1 loss between rendered and ground truth
    L_L1 = l1_loss(rendered_image, ground_truth_image)
    
    # L_PBR: Photometric loss from PBR pipeline
    L_PBR = compute_pbr_photometric_loss(rendered_image, ground_truth_image)

    # 3. Compute Regularization Losses
    # L_smooth: Bilateral smoothness loss on BRDF parameters
    L_smooth = bilateral_smoothness_loss(gaussians.base_color, gaussians.metalness, gaussians.roughness)
    
    # L_o: Masked opacity regularization
    L_o = compute_masked_opacity_regularization(gaussians.opacity)
    
    # L_sc: Gaussian scale regularization
    L_sc = compute_scale_regularization(gaussians.scale)
    
    # L_sr: Surface regularization (Gaussians stay near mesh triangles)
    L_sr = compute_surface_regularization(gaussians.positions, mesh)

    # 4. Combine Losses
    L_total = (L_L1 + L_PBR + 
               lambda_smooth * L_smooth + 
               lambda_o * L_o + 
               lambda_sc * L_sc + 
               lambda_sr * L_sr)
    
    return L_total
```

**Edge Cases and Pitfalls:**
*   **Degenerate Specular:** Without scaling roughness to $[0.09, 1]$, pixels may exhibit exceedingly strong specular reflectance [S1, unofficial].
*   **Mesh Instability:** Large gradients in HDR space can cause dramatic position shifts in mesh vertices. The surface regularization loss $L_{sr}$ is critical to prevent this by anchoring Gaussians to the original mesh triangles [S1, unofficial].
*   **Low Samples:** Non-parametric bilateral denoising is essential to cope with low samples per point in real-time rendering contexts [S1, unofficial].

## Subtopics

### Physical Losses
A method using explicit Gaussian radiance fields to create physically correct scenes, aiming to generate multi-object compositional scenes [S2]. It introduces "Physical Losses" to maintain correct contact relationships between objects, addressing the limited capability of explicit representations in modeling complex topological structures [S2].

## Operating characteristics
*   **Time Complexity:** Stage 1 (including mesh extraction) takes approximately 40k steps (30k for vanilla 3DGS, 10k for SDF regularization) and finishes within an hour on average [S1, unofficial].
*   **Hardware:** Experiments conducted on a single NVIDIA RTX 4090 GPU [S1, unofficial].
*   **Strengths:** Enables physically-based inverse rendering with relighting capabilities; maintains geometric stability via mesh anchoring [S1, unofficial].
*   **Limitations:** Dependent on the quality of the initial surface mesh; imperfect mesh quality can lead to degenerate cases despite regularization [S1, unofficial].

## Background
Phys3DGS was introduced to address the need for physically-based 3D Gaussian Splatting for inverse rendering [S1, unofficial]. It builds on the 3DGS representation but extends it with PBR parameters and a deferred rendering pipeline. The method was developed to improve upon existing relightable 3DGS methods like Relit3DGS and GIR [S1, unofficial].
