# Loss Function Configuration

Also called: Loss Weighting Scheme, Loss function parameter configuration, Removing Repulsion Loss, Total Training Loss, Training Loss Weights, w/o Lrep

## Overview
Loss Function Configuration defines the composite objective function and its hyperparameters used to optimize radiance fields, balancing pixel-wise fidelity, structural similarity, perceptual quality, and various regularization constraints. It differs from single-metric approaches by combining multiple perceptual and pixel-wise metrics to supervise optimization, addressing the problem of generating high-fidelity, visually consistent rendered images [S1, unofficial][S6]. It excludes explicit physical priors like visibility or normal consistency unless specified by a variant .

## How it works
The configuration specifies the mathematical form of the total loss $\mathcal{L}$ as a weighted sum of component losses, along with the specific values for the weighting hyperparameters. The exact composition varies by method, but generally follows the structure:

$$ \mathcal{L} = \sum_i w_i \mathcal{L}_i $$

where $\mathcal{L}_i$ are individual loss terms (e.g., photometric, perceptual, regularization) and $w_i$ are their corresponding weights.

### Inputs and Outputs
*   **Inputs:** Rendered images $\hat{I}$, ground-truth images $I$, auxiliary data (depth, normals, masks, sky labels), and optimization state (iteration count).
*   **Outputs:** Scalar loss value $\mathcal{L}$ and its gradient with respect to the radiance field parameters.

### Data Structures
The configuration is typically stored as a dictionary or configuration object containing:
*   `loss_weights`: A mapping of loss term names to their scalar weights (e.g., `{"photo": 1.0, "ptc": 0.1}`).
*   `loss_types`: A list or set of active loss terms.
*   `stage`: A string indicating the current training stage (e.g., "coarse", "fine") to allow stage-dependent weights.

### Numbered Steps
1.  **Initialize Weights:** Set the weights $w_i$ for each loss term $\mathcal{L}_i$ based on the current training stage and method-specific defaults.
2.  **Compute Component Losses:** Calculate each individual loss term $\mathcal{L}_i$ using the rendered and ground-truth data.
3.  **Apply Stage-Specific Adjustments:** If the method uses a multi-stage training strategy (e.g., coarse-to-fine), update weights according to the current stage [S2, S6].
4.  **Apply Hybrid Gradient Strategy (if applicable):** If using hybrid gradients, determine whether to use RGBXY or standard derivatives based on the iteration percentage [S5].
5.  **Aggregate Loss:** Compute the total loss $\mathcal{L}$ by summing the weighted component losses.
6.  **Backpropagate:** Compute gradients $\nabla_\theta \mathcal{L}$ with respect to the model parameters $\theta$.

### Formulas
Different methods employ different loss compositions. Key formulas include:

**RT-Splatting (Joint Reflection-Transmission) [S1, unofficial]:**
$$ \mathcal{L} = \mathcal{L}_{\text{img}} + \lambda_{\text{n}}\mathcal{L}_{\text{n}} + \lambda_{\text{mask}}\mathcal{L}_{\text{mask}} $$
where $\mathcal{L}_{\text{img}}$ is the appearance loss, $\mathcal{L}_{\text{n}}$ is the normal consistency loss, and $\mathcal{L}_{\text{mask}}$ is the transparent mask regularization loss.
The appearance loss is defined as:
$$ \mathcal{L}_{\text{img}} = (1 - \lambda)\mathcal{L}_{1} + \lambda \mathcal{L}_{\text{D-SSIM}} + \lambda_{\text{perc}}\mathcal{L}_{\text{perc}} $$
where $\mathcal{L}_{1}$ is the L1 loss, $\mathcal{L}_{\text{D-SSIM}}$ is the D-SSIM loss, and $\mathcal{L}_{\text{perc}}$ is the perceptual loss.

**Neural Deformable Voxel Grid [S2]:**
$$ \mathcal{L} = \mathcal{L}_{\text{photo}} + w_{\text{ptc}} \cdot \mathcal{L}_{\text{ptc}} + w_{\text{bg}} \cdot \mathcal{L}_{\text{bg}} + w_{\text{d\_norm}} \cdot \mathcal{L}_{\text{d\_norm}} + w_{\text{d\_tv}} \cdot \mathcal{L}_{\text{d\_tv}} $$
where $\mathcal{L}_{\text{photo}}$ is the photometric loss, $\mathcal{L}_{\text{ptc}}$ is the photometric consistency loss, $\mathcal{L}_{\text{bg}}$ is the background loss, $\mathcal{L}_{\text{d\_norm}}$ is the deformation norm regularization, and $\mathcal{L}_{\text{d\_tv}}$ is the total variation loss on deformation.

**SplatVoxel [S6]:**
$$ \mathcal{L} = \mathcal{L}_{\text{MSE}}(\hat{I}, I) + \lambda \mathcal{L}_{\text{LPIPS}}(\hat{I}, I) $$
where $\mathcal{L}_{\text{MSE}}$ is the Mean Squared Error and $\mathcal{L}_{\text{LPIPS}}$ is the perceptual LPIPS loss.

**LAENeRF (Color Palette Sparsity) [S8]:**
$$ \mathcal{L}_{\text{sp}} = \frac {\sum _{i=1}^{N_{\hat{P}}} \hat{w}_i}{\sum _{i=1}^{N_{\hat{P}}} \hat{w}_i^2} - 1 $$
where $\hat{w}_i$ is the per-palette weight and $N_{\hat{P}}$ is the number of palettes.

**Editing Conditional Radiance Fields (Shape Part Addition) [S9]:**
$$ \mathcal{L}_{\text{add}} = \mathcal{L}_{\text{rec}} + \lambda_{\text{reg}} \cdot \mathcal{L}_{\text{reg}} $$
where $\mathcal{L}_{\text{rec}}$ is the reconstruction loss and $\mathcal{L}_{\text{reg}}$ is a regularization term penalizing squared differences between original and updated model weights.

**SDFStudio (Sky Loss) [S7, unofficial]:**
For density fields:
$$ \mathcal{L}_{\text{sky}} = \text{BCE}(\text{clip}(\sum_{\text{dim=1}} \text{density\_field\_weights}, 10^{-3}, 1-10^{-3}), \text{sky\_label}) \times 0.01 $$
For occupancy fields:
$$ \mathcal{L}_{\text{osky}} = \text{BCE}(\text{clip}(\sum_{\text{dim=1}} \text{occupancy\_field\_weights}, 10^{-3}, 1-10^{-3}), \text{sky\_label}) \times 0.01 $$

### Parameters with Typical Values
*   **RT-Splatting [S1, unofficial]:**
    *   $\lambda$ (D-SSIM weight): 0.2
    *   $\lambda_{\text{perc}}$ (Perceptual loss weight): 0.01
    *   $\lambda_{\text{n}}$ (Normal consistency loss weight): 0.05
    *   $\lambda_{\text{mask}}$ (Transparent mask regularization weight): 0.01
*   **Neural Deformable Voxel Grid [S2]:**
    *   **Coarse stage:** $w_{\text{ptc}}=0.1$, $w_{\text{bg}}=0.01$, $w_{\text{d\_norm}}=0.1$, $w_{\text{d\_tv}}=1$.
    *   **Fine stage:** $w_{\text{ptc}}=0.01$, $w_{\text{bg}}=0.001$, $w_{\text{d\_norm}}=0.01$, $w_{\text{d\_tv}}=1$.
    *   **Large motion scenes ('Hell Warrior', 'Jumping Jacks', 'T-Rex'):** $w_{\text{d\_norm}}$ is set to 0.01 (coarse) and 0.001 (fine).
*   **SplatVoxel [S6]:**
    *   $\lambda$ (LPIPS weight) for multi-view transformer: 0.5
    *   $\lambda$ (LPIPS weight) for voxel transformer: 4.0
    *   Batch size: 128
    *   Total iterations: 300K
*   **Diffraction-engineered holography [S4]:**
    *   Number of varifocal images: 21 (1 pixel larger than max blur circle diameter of 15 pixels).
    *   $\gamma$: 40 (to avoid simultaneous focusing at two different focal planes).
    *   $\beta$: 20 (to compensate for the imbalance between in-focus (1) and out-of-focus (20) images).
*   **Editing Conditional Radiance Fields [S9]:**
    *   $\lambda_{\text{reg}}$ (Regularization weight): 10
*   **Sphere-Guided Training [S3]:**
    *   Repulsion loss ($\mathcal{L}_{\text{rep}}$): Removed during sphere cloud training.

### Edge Cases and Pitfalls
*   **Repulsion Loss Removal:** Removing the repulsion loss term ($\mathcal{L}_{\text{rep}}$) during sphere cloud training causes spheres to clump together instead of covering the entire object, leading to poor reconstructions [S3].
*   **Hybrid Gradients Alignment:** When initial and target shapes are already aligned very well, the approximated optimal transport method used in RGBXY derivatives may lead to inaccurate matching, making them less effective [S5].
*   **MS-SSIM Defects:** Using MS-SSIM loss instead of MSE loss for defocus-engineered holography optimization resulted in unclear effects and defects in the synthesized images [S4].
*   **Sky Label Computation:** Sky labels must be correctly computed as $1.0 - \text{batch['sky']}$. Incorrect device placement or type conversion can lead to silent failures or NaNs in the sky loss [S7, unofficial].

### Pseudocode
```python
def compute_total_loss(rendered_image, gt_image, auxiliary_data, iteration, total_iterations, config):
    """
    Computes the total loss based on the configured loss function.
    
    Args:
        rendered_image (Tensor): Rendered image I.
        gt_image (Tensor): Ground-truth image I_hat.
        auxiliary_data (dict): Contains depth, normals, masks, sky labels, etc.
        iteration (int): Current optimization iteration.
        total_iterations (int): Total number of optimization iterations.
        config (dict): Configuration object containing loss weights and types.
        
    Returns:
        Tensor: Total loss scalar.
    """
    total_loss = 0.0
    
    # 1. Compute Photometric/Reconstruction Losses
    if 'photo' in config['loss_types']:
        # MSE or L1 loss
        l_photo = mse_loss(rendered_image, gt_image)
        total_loss += config['weights']['photo'] * l_photo
        
    if 'ptc' in config['loss_types']:
        # Photometric consistency loss (e.g., between views)
        l_ptc = compute_photometric_consistency(rendered_image, auxiliary_data['depth'], auxiliary_data['cameras'])
        total_loss += config['weights']['ptc'] * l_ptc
        
    if 'bg' in config['loss_types']:
        # Background loss
        l_bg = compute_background_loss(rendered_image, auxiliary_data['mask'])
        total_loss += config['weights']['bg'] * l_bg

    # 2. Compute Perceptual Losses
    if 'perc' in config['loss_types']:
        # LPIPS or D-SSIM
        l_perc = lpips_loss(rendered_image, gt_image)
        total_loss += config['weights']['perc'] * l_perc
        
    if 'd_ssim' in config['loss_types']:
        l_d_ssim = d_ssim_loss(rendered_image, gt_image)
        total_loss += config['weights']['d_ssim'] * l_d_ssim

    # 3. Compute Regularization Losses
    if 'd_norm' in config['loss_types']:
        # Deformation norm regularization
        l_d_norm = compute_deformation_norm(auxiliary_data['deformation_field'])
        total_loss += config['weights']['d_norm'] * l_d_norm
        
    if 'd_tv' in config['loss_types']:
        # Total variation loss
        l_d_tv = total_variation_loss(auxiliary_data['deformation_field'])
        total_loss += config['weights']['d_tv'] * l_d_tv
        
    if 'n' in config['loss_types']:
        # Normal consistency loss
        l_n = normal_consistency_loss(rendered_image, auxiliary_data['normals'])
        total_loss += config['weights']['n'] * l_n
        
    if 'mask' in config['loss_types']:
        # Transparent mask regularization
        l_mask = transparent_mask_loss(rendered_image, auxiliary_data['mask'])
        total_loss += config['weights']['mask'] * l_mask
        
    if 'sky' in config['loss_types']:
        # Sky loss
        sky_label = 1.0 - auxiliary_data['sky'].float().to(rendered_image.device)
        if config['field_type'] == 'density':
            density_weights = auxiliary_data['density_field_weights']
            sky_loss = bce_loss(
                clip(sum(density_weights, dim=1), 1e-3, 1-1e-3), 
                sky_label
            ) * 0.01
        else: # occupancy
            occupancy_weights = auxiliary_data['occupancy_field_weights']
            sky_loss = bce_loss(
                clip(sum(occupancy_weights, dim=1), 1e-3, 1-1e-3), 
                sky_label
            ) * 0.01
        total_loss += sky_loss
        
    if 'sp' in config['loss_types']:
        # Color palette sparsity loss
        palette_weights = auxiliary_data['palette_weights']
        l_sp = (sum(palette_weights) / sum(palette_weights**2)) - 1
        total_loss += config['weights']['sp'] * l_sp

    # 4. Handle Hybrid Gradients (if applicable)
    # Note: This affects gradient computation, not the loss value itself,
    # but the configuration determines which derivative is used.
    if config.get('use_hybrid_gradients', False):
        if iteration < 0.75 * total_iterations:
            use_rgbxy_derivatives = True
        else:
            use_rgbxy_derivatives = False
        # The actual gradient computation would use the selected derivative type
        # This is handled in the optimizer step, not here.

    # 5. Handle Repulsion Loss (if applicable)
    # In Sphere-Guided Training, L_rep is explicitly removed.
    # If L_rep were included, it would be added here.
    # if 'rep' in config['loss_types']:
    #     l_rep = repulsion_loss(auxiliary_data['sphere_cloud'])
    #     total_loss += config['weights']['rep'] * l_rep

    return total_loss
```

## Subtopics

### [Overall Training Objective](13444-overall-training-objective.md)
The Overall Training Objective defines the composite loss function used to optimize radiance fields, balancing pixel-wise fidelity, structural similarity, perceptual quality, and adversarial constraints. It differs from single-metric approaches by combining multiple perceptual and pixel-wise metrics to supervise optimization, addressing the problem of generating high-fidelity, visually consistent rendered images. It excludes explicit physical priors like visibility or normal consistency unless specified by a variant.

### Hybrid Gradients
A strategy combining RGBXY derivatives and standard derivatives to leverage global matching in early stages and precise local alignment in late stages. Use RGBXY derivatives (Eq. 15) for the first 75% of optimization iterations. Switch to standard derivatives (Eq. 5) for the last 25% of optimization iterations. When initial and target shapes are already aligned very well, the approximated optimal transport method may lead to inaccurate matching, making RGBXY derivatives less effective. [S5]

### Two-Stage Photometric and Perceptual Training Strategy
A two-stage training strategy for the SplatVoxel feed-forward networks using photometric loss. Stage 1: Train the multi-view Transformer backbone for 200K iterations. Stage 2: Jointly fine-tune both the multi-view and voxel Transformers for an additional 100K iterations. Loss function: $\mathcal{L} = \mathcal{L}_{\text{MSE}}(\hat{I}, I) + \lambda \mathcal{L}_{\text{LPIPS}}(\hat{I}, I)$ where $\hat{I}$ is the ground-truth target image, $I$ is the rendered target image, and $\lambda$ is a weighting factor. LPIPS weight for multi-view transformer: $\lambda = 0.5$. LPIPS weight for voxel transformer: $\lambda = 4.0$. Batch size: 128. Total iterations: 300K. Trained on multi-view static scene datasets [87, 35], specifically DL3DV [35] for cross-dataset generalization. [S6]

### Sky Loss
Compute sky label as 1.0 minus batch['sky'] converted to float and moved to device. For density field (use_nerfacto), compute sky_loss as binary cross entropy between sum of density_field_weights over dim=1 (clipped to [1e-3, 1-1e-3]) and sky_label, multiplied by 0.01. For occupancy field, compute osky_loss as binary cross entropy between sum of occupancy_field_weights over dim=1 (clipped to [1e-3, 1-1e-3]) and sky_label, multiplied by 0.01. [S7, unofficial]

### Color Palette Sparsity Loss
A loss metric adopted from PaletteNeRF to measure the sparsity of the learned color palette $\hat{P}$. Formula: $L_{sp} = (\sum \hat{w}_i) / (\sum \hat{w}_i^2) - 1$. Variables: $\hat{w}_i$ is the per-palette weight, $N_{\hat{P}}$ is the number of palettes. [S8]

### Shape Part Addition Loss
Loss function for adding a local part to a shape instance, fitting the network to a composite image of the original and a copied region from another instance. Construct composite image: User selects original view, selects new instance, copies local region by scribbling on new instance view, scribbles paste location on original view. Render color for paste location using shape code from new instance and color code from original instance. Optimize $L_{add}$ over relevant network parameters (Frad, z(c), z(s) as needed for the composite view) using Adam optimizer with learning rate $10^{-2}$. Regularization weight $\lambda_{reg}$: 10 (implied by context of other losses, though not explicitly stated for $L_{add}$, it uses $L_{reg}$). [S9]

## Operating characteristics
*   **Time Complexity:** The computation of the total loss is generally linear with respect to the number of pixels and the number of active loss terms. Multi-stage training (e.g., coarse-to-fine) can reduce the total time required to reach convergence by optimizing simpler representations first [S2].
*   **Memory Complexity:** Memory usage is dominated by the storage of intermediate gradients and the radiance field parameters. The addition of auxiliary losses (e.g., sky loss, palette sparsity) adds minimal overhead [S8][S7, unofficial].
*   **Measured Performance:** In Neural Deformable Voxel Grid, PSNR generally increases slightly after 20k iterations, but requires significantly more iterations to reach maximum. Training is often set to 20k iterations to balance PSNR and time consumption [S2].
*   **Scaling:** The configuration allows for easy scaling by adding new loss terms or adjusting weights. However, adding too many terms without proper weighting can lead to unstable optimization [S1, unofficial][S2].
*   **Strengths:** Combining multiple loss types (photometric, perceptual, regularization) leads to higher fidelity and visually consistent results compared to single-metric approaches . Multi-stage training accelerates convergence [S2].
*   **Limitations:** Improper weight selection can lead to poor reconstructions (e.g., clumping of spheres without repulsion loss) [S3]. Some loss terms (e.g., MS-SSIM) may introduce defects if not carefully tuned [S4]. Hybrid gradients may be less effective when shapes are already well-aligned [S5].
*   **When to Use:** Use when optimizing radiance fields for high-fidelity view synthesis, especially when dealing with complex scenes, dynamic content, or specific artifacts (e.g., floaters, specular reflections).
*   **When Not to Use:** Avoid if computational resources are extremely limited and only a rough approximation is needed. Also avoid if the scene is very simple and a single photometric loss is sufficient.

## Background
Loss function configuration is a fundamental aspect of differentiable volume rendering and neural radiance field optimization. Early methods relied primarily on photometric (L1/L2) losses [S1, unofficial]. As the field evolved, researchers incorporated perceptual losses (LPIPS, D-SSIM) to improve visual quality [S1, unofficial][S6]. Regularization losses (total variation, normal consistency, repulsion) were introduced to enforce geometric priors and prevent artifacts [S1, unofficial][S3, S2]. The concept of multi-stage training and hybrid gradients emerged to address the challenges of optimizing complex, high-dimensional radiance fields efficiently [S2, S5]. The specific configurations detailed in the sources reflect the state-of-the-art practices in various sub-domains, such as reflective object relighting [S1, unofficial], dynamic view synthesis [S2], and feed-forward 3DGS [S6].
