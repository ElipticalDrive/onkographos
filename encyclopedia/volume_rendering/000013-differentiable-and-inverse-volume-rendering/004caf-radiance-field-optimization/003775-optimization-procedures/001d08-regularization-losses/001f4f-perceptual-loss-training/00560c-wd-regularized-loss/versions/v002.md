# WD-Regularized Loss

Also called: WD with original loss regularizer, WD-R, WD-R Objective, WD-Regularized, Wasserstein Distortion (WD) Loss Optimization

## Overview
WD-Regularized Loss (WD-R) is a training objective for 3D Gaussian Splatting that combines the Wasserstein Distance (WD) perceptual loss with a lightly weighted version of the original pixel-level loss [S1]. It solves the problem of visual artifacts that occur in regions with constrained Gaussian splat counts or limited training views, where the pure WD loss may fail to enforce sufficient pixel fidelity [S1]. It balances perceptual fidelity against raw pixel error to maintain compact representations without sacrificing sharpness [S1]. It is compared against sibling methods such as [Stable View Synthesis (SVS) Baseline](2483-stable-view-synthesis-svs-baseline.md) and [High-Frequency Aware Loss](7589-high-frequency-aware-loss.md) [S1].

## How it works
The method augments the standard 3D Gaussian Splatting optimization by introducing a composite loss function [S1]. The core mechanism relies on computing the Wasserstein Distance between VGG feature pyramids of the rendered and ground-truth images, while adding a scaled original loss term to regularize the optimization [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Current 3D Gaussian parameters (means, covariances, opacities, colors, spherical harmonics) [S1].
    *   Camera poses and intrinsics for the current training view [S1].
    *   Ground-truth image for the current view [S1].
    *   Pre-computed ground-truth VGG features and pyramid statistics (if caching is enabled) [S1].
*   **Outputs:**
    *   Rendered image [G].
    *   Scalar loss value $L_{WD-R}$ [S1].
    *   Gradients with respect to Gaussian parameters [G].

### Data Structures
*   **VGG Feature Pyramid:** A stack of feature maps extracted from a pre-trained VGG network [S1]. The implementation uses 96 pyramid levels [S1].
*   **Pyramid Weights:** A scalar weight for each pyramid level $i$, computed as $\text{ReLU}(1 - |\log_2 \sigma - i|)$ [S1].
*   **Cached Statistics:** Ground-truth VGG features and their corresponding pyramid statistics (mean and variance) are cached to avoid recomputation [S1].

### Formulas
The total loss is defined as [S1]:

$$
L_{WD-R} = \gamma (d_{WD} + \beta L_{orig})
$$

Where:
*   $L_{WD-R}$ is the WD-Regularized loss [S1].
*   $\gamma$ is a dataset-specific global scale factor [S1]. It modulates the magnitude of positional gradients to control the number of generated Gaussian splats, ensuring fair comparison with baselines under similar representation budgets [S1].
*   $d_{WD}$ is the Wasserstein Distance distortion metric computed in VGG feature space [S1].
*   $\beta$ is the weighting factor for the original loss [S1]. It is chosen such that $L_{orig}$ acts as a mild pixel fidelity regularizer without overwhelming the WD term [S1].
*   $L_{orig}$ is the original 3DGS pixel-level loss (typically a combination of L1 and SSIM) [S1].

The pure WD loss is defined as [S1]:

$$
L_{WD} = \gamma d_{WD}
$$

The per-level pyramid weight is calculated as [S1]:

$$
w_i = \text{ReLU}(1 - |\log_2 \sigma - i|)
$$

Where:
*   $\sigma = 4$ is a constant [S1].
*   $i$ is the pyramid level index [S1].

### Parameters
*   **$\beta$**: Set to $0.09$ for all scenes [S1]. This value ensures that the gradient from the original loss is moderate; empirical analysis shows the gradient ratio $\frac{\|\nabla d_{WD}\|}{\|\nabla (\beta L_{orig})\|}$ has a mean of $\sim 1.6\times$ across training iterations, confirming WD remains the dominant signal [S1].
*   **$\gamma$**: A dataset-specific global scale [S1]. It is tuned per scene to align Gaussian counts across methods [S1]. Exact values are scene-dependent and not provided as a single constant [S1].
*   **$\sigma$**: Constant set to $4$ [S1].

### Algorithm Steps
1.  **Warm-up Phase:** Optimize the model using the standard 3DGS loss ($L_{orig}$) for 3,000–5,000 iterations [S1].
2.  **Perceptual Phase:** For the remaining iterations (up to 30,000 total), switch to the WD-R objective [S1].
3.  **Feature Extraction:**
    *   Render the current view to obtain the predicted image [G].
    *   Extract VGG features from the predicted image [G].
    *   If caching is enabled, retrieve pre-computed VGG features and pyramid statistics for the ground-truth image [S1].
    *   If caching is not enabled, extract VGG features from the ground-truth image and compute pyramid statistics [S1].
4.  **Pyramid Weighting:** Compute the weight $w_i$ for each pyramid level $i$ using $\sigma = 4$ [S1].
5.  **Pruning:** Identify pyramid levels where $w_i = 0$ [S1]. These levels do not contribute to the loss and can be skipped during computation [S1]. In the standard setup, only 20 of 96 pyramid levels contribute [S1].
6.  **Loss Computation:**
    *   Compute $d_{WD}$ using the weighted VGG feature differences [S1].
    *   Compute $L_{orig}$ (L1 + SSIM) [S1].
    *   Calculate $L_{WD-R} = \gamma (d_{WD} + \beta L_{orig})$ [S1].
7.  **Backpropagation:** Compute gradients with respect to Gaussian parameters and update them [G].

### Pseudocode

```python
import math

def compute_wd_regularized_loss(gaussians, camera, gt_image, cached_gt_features, cached_gt_stats, gamma, beta, sigma=4):
    # 1. Render current view
    pred_image = forward_render(gaussians, camera)

    # 2. Extract VGG features
    pred_features = extract_vgg_features(pred_image)
    if cached_gt_features is not None:
        gt_features = cached_gt_features
        gt_stats = cached_gt_stats
    else:
        gt_features = extract_vgg_features(gt_image)
        gt_stats = compute_pyramid_statistics(gt_features)

    # 3. Compute pyramid weights and identify active levels
    num_levels = 96
    active_levels = []
    weights = {}
    log2_sigma = math.log2(sigma)
    for i in range(num_levels):
        w = max(0.0, 1.0 - abs(log2_sigma - i))
        weights[i] = w
        if w > 0:
            active_levels.append(i)

    # 4. Compute WD distortion (d_WD)
    d_WD = 0.0
    for i in active_levels:
        pred_feat = pred_features[i]
        gt_feat = gt_features[i]
        pred_mean = sum(pred_feat) / len(pred_feat)
        pred_var = sum((x - pred_mean)**2 for x in pred_feat) / len(pred_feat)
        gt_mean = gt_stats['mean'][i]
        gt_var = gt_stats['var'][i]
        level_dist = wasserstein_2_distance(pred_mean, pred_var, gt_mean, gt_var)
        d_WD += weights[i] * level_dist

    # 5. Compute original loss (L_orig)
    L_orig = compute_l1_loss(pred_image, gt_image) + compute_ssim_loss(pred_image, gt_image)

    # 6. Combine losses
    loss = gamma * (d_WD + beta * L_orig)

    # 7. Backpropagation
    grads = compute_gradients(loss, gaussians)
    return loss, grads

def forward_render(gaussians, camera):
    # Standard 3D Gaussian Splatting forward rasterization
    return rasterize_gaussians(gaussians, camera)

def extract_vgg_features(image):
    # Standard VGG-16 feature extraction returning a list of feature maps
    return vgg_forward_pass(image)

def compute_pyramid_statistics(features):
    stats = {'mean': [], 'var': []}
    for feat in features:
        n = len(feat)
        m = sum(feat) / n
        v = sum((x - m)**2 for x in feat) / n
        stats['mean'].append(m)
        stats['var'].append(v)
    return stats

def wasserstein_2_distance(m1, v1, m2, v2):
    # Wasserstein-2 distance between two 1D Gaussian distributions
    return (m1 - m2)**2 + (math.sqrt(v1) - math.sqrt(v2))**2

def compute_l1_loss(pred, gt):
    return sum(abs(p - g) for p, g in zip(pred, gt)) / len(pred)

def compute_ssim_loss(pred, gt):
    # Standard SSIM computation
    return 1.0 - structural_similarity_index(pred, gt)

def compute_gradients(loss, params):
    # Standard automatic differentiation
    return autograd_backward(loss, params)
```

### Edge Cases and Pitfalls
*   **Gradient Dominance:** Although $\beta=0.09$ appears large, the WD gradient consistently exceeds the scaled original loss gradient (mean ratio $\sim 1.6\times$), preventing the original loss from overwhelming the perceptual signal [S1].
*   **Pyramid Pruning:** With $\sigma=4$, most of the 96 pyramid levels have zero weight [S1]. Ignoring these levels is critical for performance but must be handled correctly to ensure bit-exact gradients [S1].
*   **Global Scale Tuning:** $\gamma$ must be tuned per dataset to align Gaussian counts for fair comparison with baselines [S1].
*   **Warm-up Requirement:** Skipping the warm-up phase with the original loss may lead to instability or artifacts, as the perceptual objective requires a stable initial representation [S1].

## Subtopics

### VGG Feature Caching and Pyramid Pruning
This variant refers to the specific optimizations applied to the WD loss computation to reduce overhead [S1]. It involves caching ground-truth VGG features and their pyramid statistics since the ground-truth view is constant across iterations, and pruning zero-weight VGG pyramid levels (only 20 of 96 levels contribute with $\sigma=4$) [S1]. These optimizations reduce the per-iteration time by approximately 48%, lowering the relative training overhead from $\approx 4.5\times$ to $\approx 2.8\times$ over the original 3DGS [S1].

## Operating characteristics
*   **Time Complexity:** The WD loss introduces significant computational overhead due to VGG feature extraction and statistical computation [S1]. At 1063 × 1600 resolution with 4.79M Gaussians, the forward/backward pass takes 273.9 ms/iteration compared to 61.1 ms for L1+SSIM, a 4.5× overhead [S1]. With caching and pruning optimizations, this is reduced to $\approx 2.8\times$ overhead [S1].
*   **Memory Complexity:** Requires storing VGG features for the ground-truth image and potentially cached statistics [S1]. The VGG feature stack consists of 96 levels [S1].
*   **Performance:** WD-R consistently outperforms Original Loss and Perceptual-GS in perceptual metrics while maintaining compact representations (e.g., reducing Gaussian count on BungeNeRF from 6.92M to 4.89M) [S1]. It trades higher training time for improved visual quality and fewer splats, which can partially offset rendering costs [S1].
*   **Strengths:** High perceptual fidelity, compact Gaussian representations, robust against artifacts in sparse-view regions [S1].
*   **Limitations:** High training time overhead (2.8×–4.5× slower than baseline), requires careful tuning of $\gamma$ per dataset [S1].
*   **When to Use:** When perceptual quality and compactness are prioritized over training speed, and when artifacts from pure WD loss are observed in constrained regions [S1].
*   **When Not to Use:** When real-time training speed is critical, or when the scene has abundant training views and no constraint on Gaussian count [S1].

## Background
WD-Regularized Loss was introduced by Özyılkan and Chen et al. in the paper "Drop-In Perceptual Optimization for 3D Gaussian Splatting" [S1]. It builds upon the Wasserstein Distance (WD) perceptual loss for 3D Gaussian Splatting [S1]. The method addresses the limitations of pure WD loss by adding a regularizer to handle regions with constrained splat counts or small numbers of training views [S1]. It is part of the broader effort to improve perceptual quality in differentiable volume rendering and 3D Gaussian Splatting optimization [S1].
