# Perceptual Loss Training

Also called: PIPS Loss, Perceptual Loss for 3DGS, Perceptual loss for dynamic NeRF

## Overview
Perceptual Loss Training is an optimization strategy that incorporates a perceptual loss term to improve the visual fidelity of rendered volume representations, addressing the smoothness and blurriness artifacts inherent in standard pixel-wise losses like L1 or L2 [S1, S2, S3]. It sets itself apart from its siblings by leveraging features from pre-trained convolutional neural networks (typically VGG-19) to enforce high-level structural consistency, whereas methods like [Total Variation Regularization](860-total-variation-regularization.md) focus on spatial smoothness and [Distortion Loss](2755-distortion-loss.md) targets geometric regularization [S1, S3].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Rendered image $\hat{I}$, ground truth image $I_g$, pre-trained feature extractor network $\Phi$ (e.g., VGG-19), and loss weights.
*   **Outputs:** Scalar loss value $\mathcal{L}_{\text{perc}}$ used for backpropagation.

**Data Structures:**
*   **Feature Maps:** Multi-dimensional tensors extracted from intermediate layers of the feature extractor. For VGG-19, these correspond to specific convolutional blocks [S2].

**Method Steps:**
1.  **Feature Extraction:** Pass the rendered image $\hat{I}$ and the ground truth image $I_g$ through the pre-trained network $\Phi$. Extract feature maps from a set of layers $L = \{l_1, l_2, \dots, l_k\}$ [S2].
2.  **Distance Calculation:** Compute the $L_1$ distance between the feature maps of the rendered image and the ground truth image for each layer [S2].
3.  **Weighted Summation:** Sum the distances across all selected layers, weighted by layer-specific coefficients $\lambda_l$ [S2].

**Formulas:**
The perceptual loss is defined as [S2]:
$$
\mathcal{L}_{\text{perc}} = \sum_{l \in L} \lambda_l \| \Phi_l(I_g) - \Phi_l(\hat{I}) \|_1
$$
where:
*   $\Phi_l(\cdot)$ denotes the feature map output from layer $l$ of the network $\Phi$.
*   $\lambda_l$ is the weight for layer $l$.
*   $\| \cdot \|_1$ is the $L_1$ norm.

In the context of Gaussian Splatting (PIPS), the total loss combines perceptual loss with L1 and SSIM losses [S1]:
$$
\mathcal{L} = (1 - \lambda_1 - \lambda_2)\mathcal{L}_1 + \lambda_1\mathcal{L}_{\text{SSIM}} + \lambda_2\mathcal{L}_{\text{PIPS}}
$$
where $\mathcal{L}_1$ is the pixel-wise L1 loss, $\mathcal{L}_{\text{SSIM}}$ is the structural similarity loss, and $\mathcal{L}_{\text{PIPS}}$ is the perceptual loss [S1].

**Parameters:**
*   **VGG-19 Layers:** Commonly used layers include 'input', 'conv1-2', 'conv2-2', 'conv3-2', 'conv4-2', and 'conv5-2' [S2].
*   **Weights ($\lambda_l$):** Values follow Chen et al. [S2]. Specific values for $\lambda_1$ (SSIM weight) and $\lambda_2$ (Perceptual weight) in the combined loss are not explicitly given in the sources [S1].
*   **Optimizer:** Adam optimizer is typically used [S2].
*   **Learning Rate:** Initialized at 0.01, decreased every 7 epochs following the schedule $0.01 \to 0.005 \to 0.001$ [S2].

**Pseudocode:**
```python
def compute_perceptual_loss(rendered_image, ground_truth_image, vgg_model, layer_indices, layer_weights):
    """
    Computes the perceptual loss between rendered and ground truth images.
    
    Args:
        rendered_image (Tensor): Rendered image tensor [B, C, H, W].
        ground_truth_image (Tensor): Ground truth image tensor [B, C, H, W].
        vgg_model (nn.Module): Pre-trained VGG-19 model.
        layer_indices (List[int]): Indices of layers to extract features from.
        layer_weights (List[float]): Weights for each layer's feature distance.
        
    Returns:
        Tensor: Scalar perceptual loss.
    """
    # Extract features for ground truth
    gt_features = []
    for idx in layer_indices:
        # Assuming vgg_model returns a list of features or we iterate through named modules
        # This step depends on the specific VGG implementation's feature extraction interface
        feature = vgg_model.get_feature(ground_truth_image, idx) 
        gt_features.append(feature)

    # Extract features for rendered image
    pred_features = []
    for idx in layer_indices:
        feature = vgg_model.get_feature(rendered_image, idx)
        pred_features.append(feature)

    loss = 0.0
    for i, weight in enumerate(layer_weights):
        # Compute L1 distance between features
        diff = gt_features[i] - pred_features[i]
        layer_loss = torch.mean(torch.abs(diff)) # L1 norm mean
        loss += weight * layer_loss
        
    return loss
```
*[G] The `vgg_model.get_feature` is a placeholder for the specific mechanism to retrieve intermediate layer outputs from a standard PyTorch/TensorFlow VGG implementation, as the exact API is not specified in the sources.*

**Edge Cases and Pitfalls:**
*   **Computational Overhead:** Perceptual loss relies on CNNs, which significantly increases training time. It is recommended to compute the perceptual loss every 20 training iterations to alleviate this overhead without noticeably affecting quality [S1].
*   **Visual Quality Degradation:** Omitting perceptual loss increases the LPIPS (Learned Perceptual Image Patch Similarity) distance, indicating degraded visual quality even if pixel-wise metrics (PSNR/SSIM) remain acceptable [S3].

## Subtopics

### [Stable View Synthesis (SVS) Baseline](2483-stable-view-synthesis-svs-baseline.md)
Stable View Synthesis (SVS) is a view synthesis method that blends training images together to render novel views, relying on proxy geometry from an external system. It is distinguished from its siblings by its explicit dependence on external proxy geometry (typically piecewise planar meshes) and access to all training images, whereas [High-Frequency Aware Loss](7589-high-frequency-aware-loss.md) and [WD-Regularized Loss](15613-wd-regularized-loss.md) operate within different optimization frameworks without this specific blending-and-proxy requirement.

### [High-Frequency Aware Loss](7589-high-frequency-aware-loss.md)
High-Frequency Aware Loss (LHF) is a perceptual regularization term designed to recover high-frequency details in rendered images while avoiding the texture distortion common in deeper perceptual losses. It sets itself apart from standard VGG-based perceptual losses by restricting feature extraction to the first block of the network, before any max-pooling operations, thereby preserving fine-grained spatial information. It builds on [Perceptual Loss Training](2000-perceptual-loss-training.md) by specifically targeting the loss of high-frequency content that occurs when using pixel-wise losses on misaligned data.

### [WD-Regularized Loss](15613-wd-regularized-loss.md)
A training objective that augments the Wasserstein Distance (WD) perceptual loss with a lightly weighted version of the original 3DGS pixel-level loss to avoid artifacts in regions with constrained splat counts or small numbers of training views.

### Anti-Bias Loss
An l1 loss applied to downsampled versions of prediction and ground truth to eliminate color shifts introduced by perceptual loss while remaining robust against minor misalignments [S4]. It is defined as the L1 distance between k-fold downsampled ground truth patch $P$ and predicted patch $\hat{P}$:
$$
\mathcal{L}_{ab} = \| DSk(P) - DSk(\hat{P}) \|_1
$$
where $DSk(\cdot)$ denotes k-fold downsampling [S4]. The full objective function is:
$$
\mathcal{L} = w_{l1} \cdot \mathcal{L}_{l1} + w_{vgg} \cdot \mathcal{L}_{vgg} + w_{ab} \cdot \mathcal{L}_{ab}
$$
where $\mathcal{L}_{l1}$ is the pixel-wise L1 distance and $\mathcal{L}_{vgg}$ is the perceptual loss [S4].

## Operating characteristics
*   **Time Complexity:** High. The inclusion of CNN-based feature extraction increases training time significantly. For example, training on one GeForce 1080 Ti takes an average of 41.5 hours per scene [S2].
*   **Memory Complexity:** Increases due to the storage of intermediate feature maps from the VGG network during the forward pass for gradient computation.
*   **Performance:** Improves perceptual quality (lower LPIPS) and recovers high-frequency details compared to L1/L2/SSIM-only training [S2, S3].
*   **Strengths:** Addresses the "smoothness" problem of pixel-wise losses; robust to minor misalignments when combined with anti-bias terms [S4].
*   **Limitations:** Computationally expensive; can introduce color shifts if not regularized (e.g., by Anti-Bias Loss) [S4].
*   **When to use:** When perceptual quality is prioritized over training speed and pixel-perfect metric alignment [S1, S3].
*   **When not to use:** When real-time training feedback is required or computational resources are severely constrained [S1].

## Background
Perceptual loss was originally introduced for image synthesis tasks [S2]. In the context of volume rendering and radiance fields, it was adopted to mitigate the blurriness associated with standard L1/L2 losses. Key implementations include its use in Neural Point Cloud Rendering [S2], Dynamic NeRFs for human avatars [S3], and Gaussian Splatting variants like PIPS [S1] and DINER [S4].
