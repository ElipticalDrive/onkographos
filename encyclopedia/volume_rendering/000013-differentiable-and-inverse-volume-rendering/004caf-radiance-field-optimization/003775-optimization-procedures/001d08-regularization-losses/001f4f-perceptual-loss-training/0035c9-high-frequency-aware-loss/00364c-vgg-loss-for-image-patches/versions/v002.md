# VGG Loss for Image Patches

Also called: Perceptual Loss (VGG), VGG Loss, VGG feature distance

## Overview
VGG Loss for Image Patches is a perceptual regularization term that encourages generated image patches to match the high-level feature representations of real image patches using a pre-trained VGG network [S1, unofficial]. Unlike traditional pixel-wise losses, it measures perceptual similarity but is highly sensitive to noise in rendered images, which can introduce optimization bias [S2].

## How it works
**Inputs:**
- Real image patches (ground truth).
- Fake image patches (model output).
- A pre-trained VGG network (typically VGG-19) [S2].
- `vgg_loss_mult`: Multiplier for the total loss computation [S1, unofficial].

**Outputs:**
- Scalar VGG loss value.

**Data Structures:**
- Patches are extracted from the model output batch and the target batch [S1, unofficial].
- The implementation slices the patches to include only the first `num_patches` [S1, unofficial].

**Steps:**
1. Extract real and fake image patches from the respective batches [S1, unofficial].
2. Slice the extracted patches to retain only the first `num_patches` [S1, unofficial].
3. Extract high-level features from the truncated VGG network for both patch sets [S2].
4. Compute the Euclidean distance between the feature maps of the real and fake patches [S2].
5. Scale the computed loss by `vgg_loss_mult` for inclusion in the total loss computation [S1, unofficial].

**Formula:**
$$ L_{VGG} = \text{vgg\_loss\_mult} \cdot \| \Phi(P_{real}) - \Phi(P_{fake}) \|_2^2 $$
Where:
- $P_{real}$ and $P_{fake}$ are the sliced real and fake patches [S1, unofficial].
- $\Phi(\cdot)$ represents the feature extraction from the truncated VGG network [S2].
- $\| \cdot \|_2^2$ is the squared Euclidean distance [S2].

**Parameters:**
- `vgg_loss_mult`: Typical value not given in the sources.

**Edge Cases and Pitfalls:**
- **Noise Sensitivity:** High-level feature propagation makes the loss highly sensitive to noise, which can bias optimization towards suboptimal solutions [S2]. This is particularly problematic in inverse rendering where rendered images may contain Monte Carlo noise [S2].
- **Patch Count:** The number of patches must be handled correctly to avoid dimension mismatches [S1, unofficial].

**Pseudocode:**
```python
def compute_vgg_loss_for_patches(real_patches, fake_patches, vgg_model, vgg_loss_mult, num_patches):
    # Slice patches to include only the first num_patches
    real_patches = real_patches[:num_patches]
    fake_patches = fake_patches[:num_patches]
    
    # Extract high-level features using the truncated VGG model
    real_features = vgg_model(real_patches)
    fake_features = vgg_model(fake_patches)
    
    # Compute squared Euclidean distance between features
    diff = real_features - fake_features
    squared_diff = diff * diff
    total_squared_diff = sum(squared_diff.flatten())
    count = len(squared_diff.flatten())
    mean_squared_diff = total_squared_diff / count
    
    # Scale the loss by the multiplier
    total_loss = vgg_loss_mult * mean_squared_diff
    
    return total_loss
```

## Operating characteristics
- **Time Complexity:** Depends on the VGG network inference time for the patch size [G].
- **Memory Complexity:** Requires memory for the VGG network weights and intermediate feature maps for the patches [G].
- **Strengths:** Measures perceptual similarity, which is often more aligned with human vision than pixel-wise losses [S2].
- **Limitations:** Highly sensitive to noise, which can lead to loss-induced bias in optimization [S2]. Not suitable for noisy rendered images without mitigation (e.g., control variates) [S2].
- **When to use:** When perceptual quality is prioritized and the input images are relatively clean or noise has been mitigated [G].
- **When not to use:** When the rendered images contain significant noise, as the loss may bias optimization towards suboptimal solutions [S2].

## Background
The VGG loss was introduced by Johnson et al. [2016] as a differentiable proxy for perceptual similarity [S2]. It uses a truncated VGG-19 network, originally trained on ImageNet by Simonyan and Zisserman [2015], to compute the Euclidean distance between high-level features [S2]. In the context of inverse rendering, it has been used to reconstruct textured scenes, though its sensitivity to noise has been highlighted as a significant challenge [S2].
