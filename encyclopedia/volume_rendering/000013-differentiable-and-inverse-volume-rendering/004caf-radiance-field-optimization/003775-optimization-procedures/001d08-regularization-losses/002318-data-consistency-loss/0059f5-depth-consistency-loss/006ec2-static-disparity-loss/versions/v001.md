# Static Disparity Loss
Also called: Inverse-depth disparity loss, Z-component disparity loss
## Overview
The Static Disparity Loss is a regularization term used in differentiable volume rendering to enforce geometric consistency between corresponding points in static scenes. It constrains the z-component of the camera coordinate for volume-rendered points, prioritizing near-field accuracy by operating in the inverse-depth domain. It complements reprojection losses by providing explicit depth ordering constraints that are robust to scale ambiguities.
## How it works
The method ensures that the rendered depth of corresponding 3D points matches across views or frames, with higher weight given to closer objects.

**Inputs:**
- Two corresponding 3D points, $P_1$ and $P_2$, in camera coordinates. These points are typically obtained by volume rendering from two different camera poses or frames.
- The z-component of these points, $z_1$ and $z_2$.

**Outputs:**
- A scalar loss value $L_{s\_disp}$.

**Data Structures:**
- Points are represented as 3D vectors $(x, y, z)$.
- Depth is stored as a scalar $z$.

**Steps:**
1. **Volume Rendering:** Render the scene from two different viewpoints to obtain the 3D coordinates of corresponding points. Let the z-components in the camera coordinate system be $z_1$ and $z_2$.
2. **Inverse-Depth Conversion:** Convert the depth values to the inverse-depth domain. This step prioritizes near points over far points, as small errors in near depth correspond to larger disparities.
   $$ d_1 = \frac{1}{z_1}, \quad d_2 = \frac{1}{z_2} $$
   [G] Guard against division by zero by clamping $z$ to a minimum positive value (e.g., $10^{-6}$).
3. **Compute Error:** Calculate the absolute difference between the inverse-depth values.
   $$ L_{s\_disp} = |d_1 - d_2| = \left| \frac{1}{z_1} - \frac{1}{z_2} \right| $$

**Parameters:**
- None explicitly defined in the source. The inverse-depth transformation acts as an implicit weighting mechanism.

**Edge Cases and Pitfalls:**
- **Zero Depth:** If $z_1$ or $z_2$ is zero or negative (behind the camera), the inverse depth becomes undefined or infinite. A small epsilon must be added to the denominator.
- **Far Points:** For very large $z$, the inverse depth approaches zero, reducing the gradient magnitude. This is intentional to prioritize near points, but may lead to less accurate depth estimation for distant objects.

**Pseudocode:**
```python
def static_disparity_loss(z1: float, z2: float, epsilon: float = 1e-6) -> float:
    """
    Computes the static disparity loss between two z-depth values.
    
    Args:
        z1: Depth of the first point in camera coordinates.
        z2: Depth of the second point in camera coordinates.
        epsilon: Small value to prevent division by zero.
        
    Returns:
        The disparity loss in the inverse-depth domain.
    """
    # Guard against zero or negative depth
    z1_clamped = max(z1, epsilon)
    z2_clamped = max(z2, epsilon)
    
    # Convert to inverse depth
    inv_z1 = 1.0 / z1_clamped
    inv_z2 = 1.0 / z2_clamped
    
    # Compute absolute difference
    loss = abs(inv_z1 - inv_z2)
    
    return loss
```
## Subtopics

### Dynamic Disparity Loss
The Dynamic Disparity Loss extends the static version to dynamic scenes by incorporating 3D scene flow. It computes the difference in z-components after adding the estimated 3D scene flow to the corresponding points. It is used when motion is present in the scene, unlike the static variant which assumes rigid or static geometry. See [Dynamic Disparity Loss](16535-dynamic-disparity-loss.md).

## Operating characteristics
- **Time Complexity:** $O(1)$ per point pair. The computation involves basic arithmetic operations.
- **Memory Complexity:** $O(1)$ as it only requires storing two depth values.
- **Strengths:** Prioritizes near-field accuracy, which is critical for many applications. It is simple to implement and computationally cheap.
- **Limitations:** It does not handle pure rotating cameras well on its own and may lead to incorrect poses if used without other constraints (like monocular depth loss). It assumes correspondence is known or accurately estimated.
- **When to Use:** Use in static scenes or as part of a larger loss function in dynamic scenes where near-field depth accuracy is prioritized.
- **When Not to Use:** Avoid as the sole depth constraint in scenes with significant rotation or when far-field accuracy is equally important.
## Background
The Static Disparity Loss was introduced in the context of Robust Dynamic Radiance Fields [S1]. It is part of a set of regularization losses designed to improve the robustness of neural radiance fields, particularly in dynamic environments. The loss is computed in the inverse-depth domain to handle the scale ambiguity and prioritize near points. It is often used alongside reprojection loss and monocular depth loss.
