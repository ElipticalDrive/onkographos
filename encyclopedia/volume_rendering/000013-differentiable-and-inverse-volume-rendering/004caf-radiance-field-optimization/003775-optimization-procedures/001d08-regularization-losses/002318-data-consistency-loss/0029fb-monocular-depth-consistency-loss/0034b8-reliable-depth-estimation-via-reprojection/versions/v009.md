# Reliable Depth Estimation via Reprojection

Also called: Reprojection-based Depth Reliability Masking, Intensity-based Depth Consistency Check

## Overview
Reliable Depth Estimation via Reprojection is a data consistency mechanism that identifies trustworthy monocular depth estimates by verifying their geometric consistency across views. It solves the problem of noisy depth supervision in radiance field optimization by distinguishing between reliable and unreliable depth predictions using intensity-based reprojection errors. It sets itself apart from [Monocular Depth Consistency Loss](4668-monocular-depth-consistency-loss.md) by using explicit geometric reprojection checks rather than direct loss minimization, and from [Depth Supervision Loss (Laug)](8111-depth-supervision-loss-laug.md) by providing the reliability masks that enable its robust, gradient-stopped supervision [S1, S2].

## How it works
**Inputs and Outputs:**
- Input: A rendered depth map $D$ (or specific depth values $z_m, z_a$ for main and augmented models), corresponding camera poses, and the nearest training view's image data.
- Output: A binary reliability mask $m$ (or $m_m, m_a$) indicating which pixels have reliable depth estimates.

**Data Structures:**
- Depth maps: 2D arrays of floating-point values representing depth along the viewing ray.
- Image patches: 2D arrays of pixel intensities (RGB or grayscale) from the nearest training view.
- Masks: 2D boolean or binary arrays of the same spatial dimensions as the depth map.

**Steps:**
1. **Reprojection:** For a given pixel $q$ in the current view with predicted depth $z$, unproject $q$ and $z$ to 3D space using the current camera pose. Then, project this 3D point into the nearest training view using that view's camera pose to obtain the reprojected pixel coordinates.
2. **Patch Extraction:** Extract a patch centered at the reprojected coordinates from the nearest training view's image.
3. **Intensity Comparison:** Compute the Mean Squared Error (MSE) of intensities between the reprojected patch and the corresponding patch in the nearest training view. Let $e_m$ be the MSE for the main model's depth $z_m$ and $e_a$ be the MSE for the augmented model's depth $z_a$ (if applicable) [S1].
4. **Thresholding:** Define a threshold $e_\tau$. A depth estimate is considered potentially reliable only if its reprojection MSE is less than $e_\tau$.
5. **Mask Computation:** Compute the reliability mask $m_a$ for the augmented model as:
   $$
   m_a = \begin{cases} 
   1 & \text{if } (e_a \le e_m) \text{ and } (e_a \le e_\tau) \\
   0 & \text{otherwise}
   \end{cases}
   $$
   Compute the reliability mask $m_m$ for the main model similarly, checking if $e_m \le e_a$ and $e_m \le e_\tau$ [S1].
6. **Supervision Application:** Use these masks to select reliable depths for supervision. For example, in the [Depth Supervision Loss (Laug)](8111-depth-supervision-loss-laug.md), the loss is computed as:
   $$
   \mathcal{L}_{aug} = \mathbb{1}\{m_a=1\} \odot \| z_m - \nabla(z_a) \|_2 + \mathbb{1}\{m_m=1\} \odot \| \nabla(z_m) - z_a \|_2
   $$
   where $\odot$ is element-wise product, $\mathbb{1}$ is the indicator function, and $\nabla$ is the stop-gradient operator [S1].

**Parameters:**
- $e_\tau$: Reprojection MSE threshold. Not given in the sources.
- Patch size: Not given in the sources.

**Edge Cases and Pitfalls:**
- Specular regions: Intensities may not match between views, leading to masks being zero. This results in fewer pixels being supervised but avoids supervision with incorrect depth estimates [S1].
- Both models incorrect: If both $e_m$ and $e_a$ exceed $e_\tau$, both masks are zero, and no supervision is applied for those pixels [S1].
- Precision: Reprojection errors depend on accurate camera poses and depth values. Noisy poses can lead to incorrect reprojections and false reliability assessments [S2].

**Pseudocode:**
```python
def compute_reprojection_mask(depth_map, camera_pose, nearest_view_image, nearest_view_pose, threshold_e_tau, patch_size):
    """
    Computes a binary reliability mask based on reprojection intensity consistency.
    
    Args:
        depth_map: 2D array of depth values.
        camera_pose: 4x4 matrix for current view.
        nearest_view_image: 2D array of pixel intensities for nearest training view.
        nearest_view_pose: 4x4 matrix for nearest training view.
        threshold_e_tau: Float, MSE threshold for reliability.
        patch_size: Int, size of the patch to extract.
        
    Returns:
        mask: 2D binary array.
    """
    height, width = depth_map.shape
    mask = np.zeros((height, width), dtype=bool)
    
    # Precompute projection matrices if needed
    # For each pixel, unproject to 3D, reproject to nearest view, compare intensities
    
    for y in range(height):
        for x in range(width):
            z = depth_map[y, x]
            if z <= 0: # Skip invalid depths
                continue
                
            # Unproject pixel (x, y) with depth z to 3D point P
            P = unproject_pixel_to_3d(x, y, z, camera_pose)
            
            # Project P to nearest view
            x_proj, y_proj, z_proj = project_3d_to_pixel(P, nearest_view_pose)
            
            # Check if projected point is within bounds of nearest view image
            if not (0 <= x_proj < width and 0 <= y_proj < height):
                continue
                
            # Extract patch from nearest view image centered at (x_proj, y_proj)
            patch_current = extract_patch(depth_map, x, y, patch_size) # Not used for MSE, only for reference? 
            # Actually, we compare reprojected patch with nearest view patch.
            # The reprojected patch is essentially the patch from the current view's image at (x,y) 
            # but we need to ensure we are comparing the same spatial region.
            # The source says "reprojected patch" vs "corresponding patch in the first image".
            # This implies we take the image patch from the current view at (x,y), 
            # reproject its center, and compare with the patch at the reprojected location in the nearest view.
            
            patch_current_view = extract_patch(nearest_view_image, x, y, patch_size) # Assuming we have the current view's image too
            patch_nearest_view = extract_patch(nearest_view_image, int(x_proj), int(y_proj), patch_size)
            
            # Compute MSE between the two patches
            mse = np.mean((patch_current_view - patch_nearest_view) ** 2)
            
            if mse <= threshold_e_tau:
                mask[y, x] = True
                
    return mask

def unproject_pixel_to_3d(x, y, z, camera_pose):
    """
    Unprojects a 2D pixel coordinate with depth to a 3D point in world space.
    """
    # Inverse projection matrix
    inv_proj = np.linalg.inv(camera_pose[:3, :3])
    # Normalized device coordinates
    ndc_x = (2 * x / width - 1)
    ndc_y = (2 * y / height - 1)
    # Ray direction in camera space
    ray_dir_cam = inv_proj @ np.array([ndc_x, ndc_y, 1])
    ray_dir_cam = ray_dir_cam / np.linalg.norm(ray_dir_cam)
    # 3D point in camera space
    point_cam = ray_dir_cam * z
    # Transform to world space
    point_world = camera_pose[:3, :3] @ point_cam + camera_pose[:3, 3]
    return point_world

def project_3d_to_pixel(point_world, camera_pose):
    """
    Projects a 3D point in world space to 2D pixel coordinates in the camera's view.
    """
    # Transform to camera space
    inv_pose = np.linalg.inv(camera_pose)
    point_cam = inv_pose[:3, :3] @ point_world + inv_pose[:3, 3]
    z_cam = point_cam[2]
    if z_cam <= 0:
        return None, None, None
    # Projection matrix
    proj = camera_pose[:3, :3]
    point_ndc = proj @ point_cam
    ndc_x = point_ndc[0] / point_ndc[2]
    ndc_y = point_ndc[1] / point_ndc[2]
    # Convert to pixel coordinates
    x = (ndc_x + 1) * width / 2
    y = (ndc_y + 1) * height / 2
    return x, y, z_cam

def extract_patch(image, x, y, patch_size):
    """
    Extracts a patch from the image centered at (x, y).
    """
    half_size = patch_size // 2
    x_start = int(x) - half_size
    y_start = int(y) - half_size
    x_end = x_start + patch_size
    y_end = y_start + patch_size
    
    # Handle boundaries by padding or clipping
    # For simplicity, assume valid coordinates or pad with zeros
    patch = np.zeros((patch_size, patch_size))
    valid_x_start = max(0, x_start)
    valid_y_start = max(0, y_start)
    valid_x_end = min(image.shape[1], x_end)
    valid_y_end = min(image.shape[0], y_end)
    
    patch_x_start = valid_x_start - x_start
    patch_y_start = valid_y_start - y_start
    patch_x_end = patch_x_start + (valid_x_end - valid_x_start)
    patch_y_end = patch_y_start + (valid_y_end - valid_y_start)
    
    patch[patch_y_start:patch_y_end, patch_x_start:patch_x_end] = \
        image[valid_y_start:valid_y_end, valid_x_start:valid_x_end]
    return patch
```

## Subtopics

### [Depth Supervision Loss (Laug)](8111-depth-supervision-loss-laug.md)
Depth Supervision Loss (Laug) enforces geometric consistency by minimizing the discrepancy between rendered depth maps and ground-truth depth estimates during radiance field optimization. It distinguishes itself from sibling methods by combining a dynamic adaptive masking strategy to handle unreliable depth regions with a robust, gradient-stopped reliability weighting mechanism that prevents error propagation from noisy depth priors.

### [Depth Consistency Check / Depth Outlier Removal](9363-depth-consistency-check-depth-outlier-removal.md)
This method filters noisy depth data by unprojecting depth maps to 3D space and reprojecting them into nearby views to verify geometric consistency. It solves the problem of incorrect depth supervision caused by moving objects, ill-posed views, and occlusions in street view scenarios. It sets itself apart from [Depth Supervision Loss (Laug)](8111-depth-supervision-loss-laug.md) by using explicit geometric reprojection checks rather than direct loss minimization, and from [Multi-view Consistency Depth Filtering](12319-multi-view-consistency-depth-filtering.md) by focusing on pairwise reprojection error thresholds rather than complex multi-view voting or probabilistic models.

### [Multi-view Consistency Depth Filtering](12319-multi-view-consistency-depth-filtering.md)
Multi-view Consistency Depth Filtering is a mechanism to verify the accuracy and reliability of monocular depth estimates before distilling them into a radiance field. It generates a binary confidence map by measuring the consistency between scaled monocular depth predictions and rendered NeRF depth across multiple viewpoints, filtering out inaccurate rays. It differs from sibling methods by explicitly leveraging the geometric consistency of the learned NeRF itself as a ground-truth proxy to mask noisy monocular depth, rather than relying solely on static thresholds or external consistency checks.

### Sparse SFM Depth Consistency Loss
Enforces consistency between rendered depth and projected sparse 3D points from Structure-from-Motion (SFM) to handle real-world scenes with noisy poses [S2].
- Obtain sparse 2D key points and corresponding 3D point locations from SFM algorithms like COLMAP [S2].
- Given an image and its camera pose, project visible 3D points into camera space [S2].
- Use the z-value of the projected points as the sparse depth $D_{sfm}$ for the corresponding 2D key points [S2].
- Apply an L2 loss between the rendered depth $D$ and the sparse depth $D_{sfm}$ [S2].

## Operating characteristics
- **Time Complexity:** The method involves unprojecting and projecting pixels, which is $O(N)$ where $N$ is the number of pixels. The patch extraction and MSE computation add a constant factor depending on patch size.
- **Memory Complexity:** Requires storing depth maps, image patches, and masks. Memory usage is proportional to the image resolution and patch size.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales linearly with image resolution.
- **Strengths:** Robust to noisy depth priors by filtering out unreliable estimates. Simple to implement.
- **Limitations:** Relies on accurate camera poses. May fail in specular or textureless regions where intensity matching is unreliable.
- **When to use:** When optimizing radiance fields with noisy monocular depth estimates and reliable camera poses are available.
- **When not to use:** When camera poses are highly inaccurate or when scenes have significant specularities or textureless regions.

## Background
Originated in the context of regularizing sparse input radiance fields with simpler solutions [S1] and implicit surface reconstruction with 3D Gaussian Splatting [S2]. It is used in scenarios where monocular depth estimates are used as supervision for neural radiance fields or Gaussian splatting, particularly in real-world datasets like DTU and Tanks & Temples [S2].
