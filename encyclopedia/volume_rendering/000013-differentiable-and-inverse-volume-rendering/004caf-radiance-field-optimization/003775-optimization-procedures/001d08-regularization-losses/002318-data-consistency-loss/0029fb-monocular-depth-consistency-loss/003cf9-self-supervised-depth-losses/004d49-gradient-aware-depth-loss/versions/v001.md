# Gradient-Aware Depth Loss

Also called: Gradient Loss for Depth Smoothing, Gradient-weighted Depth Loss

## Overview
Gradient-Aware Depth Loss is a regularization term used in differentiable volume rendering and Gaussian Splatting to enforce geometric consistency between rendered depth maps and monocular depth estimates. It addresses the problem of noisy or artifact-prone depth predictions by weighting the depth error based on local image texture complexity and aligning the spatial gradients of the predicted depth with those of a reference depth map [S1, S2]. It sets itself apart from standard L1 depth losses by incorporating RGB image gradients to suppress regularization in texture-rich regions and by explicitly penalizing gradient discrepancies rather than just absolute depth errors [S1, S2].

## How it works
The method combines two distinct loss components: a gradient-weighted L1 depth consistency loss and a gradient alignment loss.

**Inputs and Outputs:**
*   **Inputs:**
    *   $\hat{D}$: Rendered depth map (predicted depth).
    *   $D$: Ground truth depth map (if available) or reference depth map (e.g., from MiDaS). Note: [S1] uses $D$ as ground truth, while [S2] uses $D^*$ for the MiDaS estimate and $D$ for the predicted map. We unify notation below: let $\hat{D}$ be the predicted depth and $D_{ref}$ be the reference/ground truth depth.
    *   $I$: The rendered or aligned RGB image corresponding to the view.
    *   $\nabla I$: The gradient of the RGB image.
    *   $N$: The number of rays/pixels in the batch or image.
*   **Outputs:**
    *   $\mathcal{L}_{\text{total}}$: The combined scalar loss value.

**Data Structures:**
*   Depth maps $\hat{D}$ and $D_{ref}$ are 2D arrays of floating-point values, indexed by pixel coordinates $(u, v)$ or ray index $i$.
*   RGB image $I$ is a 2D array of color values.
*   Gradient $\nabla I$ is typically computed as the magnitude of the spatial gradient of $I$, often using Sobel operators or finite differences.

**Steps:**

1.  **Compute RGB Gradient Weight:**
    Calculate the gradient magnitude of the RGB image, $\nabla I$. The weight $g_{\text{rgb}}$ is defined as:
    $$ g_{\text{rgb}} = \exp(-\nabla I) $$
    This weight suppresses the loss in regions with high texture complexity (high gradient), preventing the optimizer from overfitting to noisy texture details [S1].

2.  **Compute Gradient-Weighted Depth Loss ($\mathcal{L}_{\hat{D}}$):**
    Calculate the L1 difference between the predicted depth $\hat{D}$ and the reference depth $D_{ref}$. Apply the logarithmic scaling and the RGB gradient weight:
    $$ \mathcal{L}_{\hat{D}} = g_{\text{rgb}} \frac{1}{|\hat{D}|} \sum_{p \in \hat{D}} \log(1 + |\hat{D}_p - (D_{ref})_p|) $$
    Where $|\hat{D}|$ is the total number of pixels in the depth map [S1]. Note: [S1] uses $\|\cdot\|_1$ inside the log, which for scalar pixel differences is the absolute value.

3.  **Compute Depth Gradient Differences:**
    For adjacent rays or pixels (e.g., horizontal or vertical neighbors), compute the difference in depth values. Let $r_i$ and $r_{i+1}$ be two adjacent rays/pixels. The gradient difference for the predicted depth is:
    $$ \text{diff}(\hat{D}|r_i, r_{i+1}) = \hat{D}(r_i) - \hat{D}(r_{i+1}) $$
    Similarly, for the reference depth $D_{ref}$:
    $$ \text{diff}(D_{ref}|r_i, r_{i+1}) = D_{ref}(r_i) - D_{ref}(r_{i+1}) $$
    [S2] defines this as the difference of depth values between two rays to represent the gradient [S2].

4.  **Compute Gradient Alignment Loss ($\mathcal{L}_{\text{grad}}$):**
    Sum the absolute differences between the predicted depth gradients and the reference depth gradients over all adjacent pairs in the batch:
    $$ \mathcal{L}_{\text{grad}} = \frac{1}{N-1} \sum_{i=1}^{N-1} |\text{diff}(\hat{D}|r_i, r_{i+1}) - \text{diff}(D_{ref}|r_i, r_{i+1})| $$
    Where $N$ is the number of rays/pixels in the batch, and $D_{ref}$ is the MiDaS predicted depth map in [S2] [S2].

5.  **Combine Losses:**
    The total loss is typically a weighted sum of $\mathcal{L}_{\hat{D}}$ and $\mathcal{L}_{\text{grad}}$. The specific weighting coefficients are not provided in the sources [G: Typically, a hyperparameter $\lambda$ is used, e.g., $\mathcal{L}_{\text{total}} = \mathcal{L}_{\hat{D}} + \lambda \mathcal{L}_{\text{grad}}$, but values are not given].

**Pseudocode:**

```python
import numpy as np

def gradient_aware_depth_loss(rendered_depth, ref_depth, rgb_image, 
                              gradient_weight_scale=1.0, gradient_align_weight=1.0):
    """
    Computes the Gradient-Aware Depth Loss.
    
    Args:
        rendered_depth (np.ndarray): 2D array of shape (H, W) with predicted depth values.
        ref_depth (np.ndarray): 2D array of shape (H, W) with reference/ground truth depth.
        rgb_image (np.ndarray): 2D or 3D array of shape (H, W, C) with RGB values.
        gradient_weight_scale (float): Scaling factor for the RGB gradient weight (not specified in sources, assumed 1.0).
        gradient_align_weight (float): Scaling factor for the gradient alignment loss (not specified in sources, assumed 1.0).
        
    Returns:
        float: Total loss value.
    """
    # Step 1: Compute RGB Gradient Magnitude
    # Compute gradients in x and y directions using Sobel operators
    sobel_x = np.array([[-1, 0, 1], [-2, 0, 2], [-1, 0, 1]])
    sobel_y = np.array([[-1, -2, -1], [0, 0, 0], [1, 2, 1]])
    
    # Convert RGB to grayscale for gradient computation if necessary, or compute per channel and sum
    # Using luminance weights for grayscale conversion
    if rgb_image.ndim == 3:
        gray = 0.2989 * rgb_image[:,:,0] + 0.5870 * rgb_image[:,:,1] + 0.1140 * rgb_image[:,:,2]
    else:
        gray = rgb_image
        
    # Pad for convolution
    gray_padded = np.pad(gray, 1, mode='edge')
    
    grad_x = np.convolve(gray_padded.flatten(), sobel_x.flatten(), mode='valid').reshape(gray.shape)
    grad_y = np.convolve(gray_padded.flatten(), sobel_y.flatten(), mode='valid').reshape(gray.shape)
    
    # Gradient magnitude
    grad_mag = np.sqrt(grad_x**2 + grad_y**2)
    
    # Step 2: Compute Gradient-Weighted Depth Loss
    # g_rgb = exp(-grad_mag)
    g_rgb = np.exp(-grad_mag)
    
    # L1 difference
    depth_diff = np.abs(rendered_depth - ref_depth)
    
    # Log(1 + L1)
    log_depth_diff = np.log(1 + depth_diff)
    
    # Weighted sum
    # Note: [S1] defines L_D_hat = g_rgb * (1/|D_hat|) * sum(log(1 + ||D_hat - D||_1))
    # This implies the weight is applied per pixel before averaging
    weighted_loss = g_rgb * log_depth_diff
    l_depth = np.mean(weighted_loss)
    
    # Step 3 & 4: Compute Gradient Alignment Loss
    # Compute depth gradients for predicted and reference depth maps
    # Using simple finite differences for horizontal and vertical neighbors
    depth_grad_x_pred = rendered_depth[:, 1:] - rendered_depth[:, :-1]
    depth_grad_y_pred = rendered_depth[1:, :] - rendered_depth[:-1, :]
    
    depth_grad_x_ref = ref_depth[:, 1:] - ref_depth[:, :-1]
    depth_grad_y_ref = ref_depth[1:, :] - ref_depth[:-1, :]
    
    # Concatenate all gradient differences
    pred_grads = np.concatenate([depth_grad_x_pred.flatten(), depth_grad_y_pred.flatten()])
    ref_grads = np.concatenate([depth_grad_x_ref.flatten(), depth_grad_y_ref.flatten()])
    
    # L1 difference of gradients
    grad_diff = np.abs(pred_grads - ref_grads)
    
    # Average over all gradient pairs
    # [S2] uses 1/(N-1) where N is number of rays. Here we have 2*(H-1)*W + 2*H*(W-1) pairs.
    # We use the number of elements in grad_diff as the denominator.
    n_grads = grad_diff.size
    l_grad = np.mean(grad_diff)
    
    # Step 5: Combine
    # Weights are not specified in sources
    total_loss = l_depth + l_grad
    
    return total_loss
```

**Parameters:**
*   Gradient weight scaling: Not given in the sources.
*   Gradient alignment weight: Not given in the sources.
*   Gradient computation method: Sobel operators are standard for $\nabla I$, but not explicitly specified. Finite differences are used for depth gradients [S2].

**Edge Cases and Pitfalls:**
*   **Precision:** Depth values can vary significantly in scale. Ensure consistent units between $\hat{D}$ and $D_{ref}$ [S1, S2].
*   **Boundaries:** Gradient computation at image boundaries requires padding or exclusion. The pseudocode uses edge padding [G].
*   **Degenerate Input:** If the RGB image is uniform ($\nabla I \approx 0$), $g_{\text{rgb}} \approx 1$, applying full depth loss. If the image is very noisy, $g_{\text{rgb}} \approx 0$, suppressing the loss [S1].

## Operating characteristics
*   **Time Complexity:** $O(HW)$ for computing gradients and losses, where $H$ and $W$ are image dimensions.
*   **Memory Complexity:** $O(HW)$ to store depth maps, RGB image, and gradients.
*   **Performance:** Reduces noise in predicted depth maps and results in smoother depth maps with fewer artifacts in rendered novel view images [S2].
*   **Strengths:** Aligns depth gradients with monocular estimates, improving geometric consistency. Suppresses regularization in textured regions to avoid blurring details [S1, S2].
*   **Limitations:** Relies on the quality of the monocular depth estimate (e.g., MiDaS) [S2]. Requires careful tuning of loss weights if combined with other terms [G].
*   **When to use:** When using self-supervised or semi-supervised depth estimation in volume rendering/Gaussian Splatting, especially when monocular depth priors are available [S1, S2].
*   **When not to use:** When ground truth depth is not available and monocular estimates are unreliable, or when computational resources are extremely limited [G].

## Background
*   **Origin:** The gradient-weighted depth loss component originates from DN-Splatter [S1]. The gradient alignment loss component originates from Dynamic View Synthesis From Small Camera Motion Videos [S2].
*   **History:** DN-Splatter introduced the gradient-aware depth loss to regularize depth in Gaussian Splatting by weighting the L1 loss with RGB image gradients [S1]. The gradient alignment loss was introduced to alleviate noise in dynamic scene depth maps by aligning gradients with MiDaS predictions [S2].
*   **Usage:** Used in Gaussian Splatting and dynamic view synthesis pipelines to improve depth map smoothness and geometric accuracy [S1, S2].
