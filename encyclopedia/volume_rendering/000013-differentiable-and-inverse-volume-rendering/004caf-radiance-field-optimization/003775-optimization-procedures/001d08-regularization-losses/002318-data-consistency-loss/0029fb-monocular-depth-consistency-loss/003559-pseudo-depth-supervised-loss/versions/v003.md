# Pseudo-depth Supervised Loss

Also called: Depth Loss, Pseudo-Depth Supervision, SFM Depth Loss

## Overview
Pseudo-depth Supervised Loss enforces geometric consistency in neural radiance fields by comparing rendered depth against pseudo-depth targets derived from Structure-from-Motion (SfM) data [S1][S3]. Unlike standard photometric losses that only constrain color, this method explicitly constrains the density distribution along rays [S1]. It distinguishes itself from sibling methods like [Reliable Depth Estimation via Reprojection](7293-reliable-depth-estimation-via-reprojection.md) by relying on sparse SfM point clouds rather than dense multi-view stereo consistency, making it suitable for scenarios where dense depth priors are unavailable but camera poses are known [S1][S3].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Rendered RGB color $\tilde{c}(p)$ and depth $\tilde{d}(p)$ for pixel $p$; target color $C(p)$; pseudo-depth $D(p)$; confidence score $U(p)$ for pixel $p$ [S1][S2, unofficial].
*   **Outputs:** Scalar loss value $L$ used for gradient backpropagation [S1][S2, unofficial][S3].

**Data Structures:**
*   **Sparse Point Cloud:** A set of 3D points $\{P_j\}$ with coordinates $(x_j, y_j, z_j)$ generated by SfM solvers (e.g., COLMAP) [S3].
*   **Ray Batch:** A set of rays $R$ (or pixels $p$) sampled for the current training step [S1][S2, unofficial].
*   **Confidence Map:** A per-pixel scalar $U(p) \in [0, 1]$ indicating the reliability of the depth estimate [S2, unofficial].

**Step-by-Step Procedure:**

1.  **Generate Pseudo-Depth (if not provided):**
    *   Estimate camera poses using an SfM solver (e.g., COLMAP) to obtain a sparse point cloud [S3].
    *   Align the camera coordinate system with the point cloud coordinate system [S3].
    *   For a ray $r$ originating at camera center $C$ with direction $\mathbf{v}$, find the intersection with the nearest point $P \in \text{PointCloud}$ along the ray.
    *   Calculate pseudo-depth $D(r) = \| P - C \|_2$ [S3].
    *   *Note:* SfM struggles in texture-less regions, leading to sparse or missing depth data [S1].

2.  **Render Depth and Color:**
    *   For each ray $r$ in the batch, sample points $t_i$ along the ray.
    *   Compute opacity $\alpha_i = 1 - \exp(-\sigma_i \Delta_i)$, where $\sigma_i$ is volume density and $\Delta_i = t_{i+1} - t_i$ [S1].
    *   Render color $\tilde{c}(r) = \sum_i \alpha_i c_i \prod_{j<i} (1-\alpha_j)$ and depth $\tilde{d}(r) = \frac{\sum_i \alpha_i t_i \prod_{j<i} (1-\alpha_j)}{\sum_i \alpha_i \prod_{j<i} (1-\alpha_j)}$ [S1].

3.  **Filter by Confidence:**
    *   Calculate a confidence score $U(p)$ for each pixel $p$ [S2, unofficial].
    *   Define an indicator function $\mathbb{I}(U(p) > \delta)$ which returns 1 if the confidence exceeds threshold $\delta$, and 0 otherwise [S2, unofficial].
    *   Typical threshold $\delta = 0.5$ [S2, unofficial].

4.  **Compute Loss Components:**
    *   **Photometric Loss:** $L_{color} = \sum_{r \in R} \| \tilde{c}(r) - C(r) \|^2$ [S1].
    *   **Depth Loss (Ray-wise, MSE):** $L_{depth} = \sum_{r \in R} \| \hat{D}(r) - D(r) \|^2$ [S1].
    *   **Depth Loss (Pixel-wise, L1 with confidence mask):** $L_{render} = \sum_{p \in I} \left( \lambda_1 \|\tilde{c}(p) - I(p)\|^2 + \lambda_2 \mathbb{I}(U(p) > \delta) |\tilde{d}(p) - D(p)| \right)$ [S2, unofficial].

5.  **Aggregate Total Loss:**
    *   Standard combination [S1][S3]:
        $$ L = \lambda_{color} L_{color} + \lambda_{depth} L_{depth} $$
    *   Multi-level combination (if applicable) [S2, unofficial]:
        $$ L = \sum_{l=1}^{3} L_{render}^l + \lambda_3 L_{mvs} $$

**Parameters:**
*   $\lambda_{color}$: Weight for photometric loss. Typical value: 1.0 [S2, unofficial].
*   $\lambda_{depth}$: Weight for depth loss. Grows linearly from $1e-4$ to $1e-2$ over training steps [S2, unofficial].
*   $\delta$: Confidence threshold. Typical value: 0.5 [S2, unofficial].
*   $\lambda_3$: Weight for multi-view stereo loss. Typical value: 1.0 [S2, unofficial].

**Pseudocode:**

```python
def pseudo_depth_supervised_loss(rendered_color, rendered_depth, 
                                 target_color, pseudo_depth, confidence_map, 
                                 lambda_color=1.0, lambda_depth=0.01, 
                                 delta=0.5):
    """
    Computes the pseudo-depth supervised loss.
    
    Args:
        rendered_color: List of arrays of shape (3,), rendered RGB colors per pixel.
        rendered_depth: List of floats, rendered depths per pixel.
        target_color: List of arrays of shape (3,), ground truth/target colors per pixel.
        pseudo_depth: List of floats, pseudo-depth from SfM per pixel.
        confidence_map: List of floats, confidence scores U(p) per pixel.
        lambda_color: Weight for color loss.
        lambda_depth: Weight for depth loss.
        delta: Confidence threshold.
        
    Returns:
        Scalar loss value.
    """
    # 1. Create mask for reliable pixels
    # Indicator function: 1 if confidence > delta and pseudo_depth > 0, else 0
    reliable_mask = []
    for p in range(len(confidence_map)):
        reliable_mask.append(1.0 if (confidence_map[p] > delta and pseudo_depth[p] > 0) else 0.0)

    # 2. Compute Photometric Loss (MSE)
    color_diff_sq = []
    for i in range(len(rendered_color)):
        diff = [rendered_color[i][k] - target_color[i][k] for k in range(3)]
        color_diff_sq.append(sum(d**2 for d in diff) * reliable_mask[i])
    color_loss = sum(color_diff_sq) / max(len(color_diff_sq), 1)

    # 3. Compute Depth Loss (L2/MSE as per [S1])
    depth_diff_sq = []
    for i in range(len(rendered_depth)):
        diff = rendered_depth[i] - pseudo_depth[i]
        depth_diff_sq.append(diff**2 * reliable_mask[i])
    depth_loss = sum(depth_diff_sq) / max(len(depth_diff_sq), 1)

    # 4. Combine
    total_loss = lambda_color * color_loss + lambda_depth * depth_loss
    return total_loss
```

**Edge Cases and Pitfalls:**
*   **Texture-less Regions:** SfM fails to generate points in uniform areas (walls, ceilings), leading to missing pseudo-depth [S1]. The confidence filter $\delta$ mitigates this by excluding low-confidence predictions [S2, unofficial].
*   **Coordinate Alignment:** Camera and point cloud must be aligned in the same coordinate system before calculating distances [S3].
*   **Moving Objects:** Dynamic objects cause inconsistencies in depth maps; semantic segmentation masks may be required to exclude them [S3].

## Subtopics

### Reliable Depth Estimation via Reprojection
Uses multi-view consistency and reprojection errors to refine depth, avoiding reliance on sparse SfM points [G]. Choose when dense geometric consistency is available and SfM is sparse [G]. [Link](7293-reliable-depth-estimation-via-reprojection.md)

## Operating characteristics
*   **Time Complexity:** Not given in the sources. Online training cost is dominated by the rendering pass [G].
*   **Memory Complexity:** Not given in the sources. Requires storing the sparse point cloud and the confidence map [G].
*   **Strengths:** Effective at removing floating artifacts and improving geometric accuracy in indoor scenes [S1]. Provides explicit geometric supervision where photometric loss is ambiguous [S3].
*   **Limitations:** Relies on the quality of SfM reconstruction; fails in texture-less regions without confidence filtering [S1][S2, unofficial]. Requires accurate camera poses [S3].
*   **When to Use:** Indoor scenes with known camera poses (e.g., from COLMAP) where geometric consistency is critical [S1][S3].
*   **When Not to Use:** Scenes with no distinctive features for SfM, or where camera poses are unknown/unreliable [S1][S3].

## Background
The method originates from the need to improve geometric consistency in Neural Radiance Fields (NeRF), particularly in indoor environments where photometric loss alone leads to floating artifacts [S1]. It leverages Structure-from-Motion (SfM) techniques, specifically COLMAP, which are standard for estimating camera poses and generating sparse point clouds [S3]. The concept of using pseudo-depth from SfM as a supervision signal was introduced to address the lack of ground truth depth in real-world scenarios [S1][S3]. Confidence filtering was later introduced to handle the unreliability of depth predictions in texture-less regions [S2, unofficial].
