# Pseudo-depth Supervised Loss

Also called: Depth Loss, Depth Supervision, Pseudo-Depth Supervision, SFM Depth Loss

## Overview
Pseudo-depth Supervised Loss is a regularization technique that mitigates floating artifacts and enforces geometric consistency in neural radiance fields by comparing rendered depth against pseudo-depth targets derived from Structure-from-Motion (SfM) data [S1, unofficial][S3]. Unlike standard photometric losses that only constrain color, this method explicitly constrains the density distribution along rays [S1, unofficial]. It distinguishes itself from sibling methods like [Reliable Depth Estimation via Reprojection](7293-reliable-depth-estimation-via-reprojection.md) by relying on sparse SfM point clouds rather than dense multi-view stereo consistency, making it suitable for scenarios where dense depth priors are unavailable but camera poses are known [S1, unofficial][S3].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Rendered RGB color $\tilde{c}(p)$ and depth $\tilde{d}(p)$ for pixel $p$; Ground truth or pseudo-depth $D(p)$; Confidence score $U(p)$ for pixel $p$; Camera parameters; Sparse point cloud from SfM.
*   **Outputs:** Scalar loss value $L$ used for gradient backpropagation.

**Data Structures:**
*   **Sparse Point Cloud:** A set of 3D points $\{P_j\}$ with coordinates $(x_j, y_j, z_j)$ and associated color/intensity, generated by SfM solvers (e.g., COLMAP) [S3].
*   **Ray Batch:** A set of rays $R$ (or pixels $p$) sampled for the current training step [S1, S2, unofficial].
*   **Confidence Map:** A per-pixel scalar $U(p) \in [0, 1]$ indicating the reliability of the depth estimate [S2, unofficial].

**Step-by-Step Procedure:**

1.  **Generate Pseudo-Depth (if not provided):**
    *   Estimate camera poses using an SfM solver (e.g., COLMAP) to obtain a sparse point cloud [S3].
    *   Align the camera coordinate system with the point cloud coordinate system [S3].
    *   For a ray $r$ originating at camera center $C$ with direction $\mathbf{v}$, find the intersection with the nearest point $P \in \text{PointCloud}$ along the ray.
    *   Calculate pseudo-depth $D(r) = \| P - C \|_2$ [S3].
    *   *Note:* SfM struggles in texture-less regions, leading to sparse or missing depth data [S1, unofficial].

2.  **Render Depth and Color:**
    *   For each ray $r$ in the batch, sample points $t_i$ along the ray.
    *   Compute opacity $\alpha_i = 1 - \exp(-\sigma_i \Delta_i)$, where $\sigma_i$ is volume density and $\Delta_i = t_{i+1} - t_i$ [S1, unofficial].
    *   Render color $\tilde{c}(r) = \sum_i \alpha_i c_i \prod_{j<i} (1-\alpha_j)$ and depth $\tilde{d}(r) = \frac{\sum_i \alpha_i t_i \prod_{j<i} (1-\alpha_j)}{\sum_i \alpha_i \prod_{j<i} (1-\alpha_j)}$ [S1, S2, unofficial].

3.  **Filter by Confidence:**
    *   Calculate a confidence score $U(p)$ for each pixel $p$ (method of calculation not specified in sources, but assumed available) [S2, unofficial].
    *   Define an indicator function $\mathbb{I}(U(p) > \delta)$ which returns 1 if the confidence exceeds threshold $\delta$, and 0 otherwise [S2, unofficial].
    *   Typical threshold $\delta = 0.5$ [S2, unofficial].

4.  **Compute Loss Components:**
    *   **Photometric Loss:** $L_{color} = \sum_{r \in R} \| \tilde{c}(r) - C(r) \|^2$ [S1, unofficial].
    *   **Depth Loss:**
        *   Using MSE between rendered depth $\hat{D}(r)$ and pseudo-depth $D(r)$ [S1, unofficial]:
            $$ L_{depth} = \sum_{r \in R} \| \hat{D}(r) - D(r) \|^2 $$
        *   Alternatively, combined with confidence filtering (per pixel $p$) [S2, unofficial]:
            $$ L_{render} = \sum_{p \in I} \left( \lambda_1 \| \tilde{c}(p) - I(p) \|^2 + \lambda_2 \mathbb{I}(U(p) > \delta) | \tilde{d}(p) - D(p) | \right) $$
            *Note: Source [S2, unofficial] uses $L_1$ norm for depth in the pixel-wise formula, while [S1, unofficial] uses $L_2$ (MSE) for the ray-wise formula. Both are cited.*

5.  **Aggregate Total Loss:**
    *   Standard combination [S1, unofficial][S3]:
        $$ L = \lambda_{color} L_{color} + \lambda_{depth} L_{depth} $$
    *   Multi-level combination (if applicable) [S2, unofficial]:
        $$ L = \sum_{l=1}^{3} L_{render}^l + \lambda_3 L_{mvs} $$

**Parameters:**
*   $\lambda_{color}$: Weight for photometric loss. Typical value: 1.0 [S2, unofficial].
*   $\lambda_{depth}$: Weight for depth loss. Grows linearly from $1e-4$ to $1e-2$ over training steps [S2, unofficial].
*   $\delta$: Confidence threshold. Typical value: 0.5 [S2, unofficial].
*   $\lambda_3$: Weight for multi-view stereo loss. Typical value: 1.0 [S2, unofficial].

**Pseudocode:**

```python
def pseudo_depth_supervised_loss(rendered_color, rendered_depth, 
                                 pseudo_depth, confidence_map, 
                                 lambda_color=1.0, lambda_depth=0.01, 
                                 delta=0.5):
    """
    Computes the pseudo-depth supervised loss.
    
    Args:
        rendered_color: Tensor of shape (H, W, 3), rendered RGB colors.
        rendered_depth: Tensor of shape (H, W), rendered depths.
        pseudo_depth: Tensor of shape (H, W), pseudo-depth from SfM.
        confidence_map: Tensor of shape (H, W), confidence scores U(p).
        lambda_color: Weight for color loss.
        lambda_depth: Weight for depth loss.
        delta: Confidence threshold.
        
    Returns:
        Scalar loss value.
    """
    # 1. Create mask for reliable pixels
    # Indicator function: 1 if confidence > delta, else 0
    reliable_mask = (confidence_map > delta).float()
    
    # 2. Compute Photometric Loss (MSE)
    # Only compute on pixels where pseudo-depth exists (non-zero/non-NaN)
    # Assuming pseudo_depth has 0 or NaN for invalid pixels
    valid_depth_mask = (pseudo_depth > 0).float()
    
    color_loss = torch.mean((rendered_color - ground_truth_color) ** 2 * valid_depth_mask)
    
    # 3. Compute Depth Loss
    # Use L2 norm as per [S1, unofficial], or L1 as per [S2, unofficial]. We use L2 for consistency with [S1, unofficial]
    # Apply mask to exclude unreliable and invalid depth pixels
    depth_diff = (rendered_depth - pseudo_depth) ** 2
    depth_loss = torch.mean(depth_diff * reliable_mask * valid_depth_mask)
    
    # 4. Combine
    total_loss = lambda_color * color_loss + lambda_depth * depth_loss
    
    return total_loss
```

**Edge Cases and Pitfalls:**
*   **Texture-less Regions:** SfM fails to generate points in uniform areas (walls, ceilings), leading to missing pseudo-depth [S1, unofficial]. The confidence filter $\delta$ mitigates this by excluding low-confidence predictions [S2, unofficial].
*   **Coordinate Alignment:** Incorrect alignment between camera and point cloud coordinates leads to systematic depth errors [S3].
*   **Moving Objects:** Dynamic objects cause inconsistencies in depth maps. Semantic segmentation masks may be required to exclude them [S3].

## Subtopics

### Reliable Depth Estimation via Reprojection
Uses multi-view consistency and reprojection errors to refine depth, avoiding reliance on sparse SfM points. Choose when dense geometric consistency is available and SfM is sparse. [Link](7293-reliable-depth-estimation-via-reprojection.md)

## Operating characteristics
*   **Time Complexity:** Dominated by the rendering pass and the SfM preprocessing (offline). Online training cost is $O(N)$ where $N$ is the number of pixels in the batch, similar to standard NeRF training.
*   **Memory Complexity:** Requires storing the sparse point cloud (small) and the confidence map (same size as image). No significant additional memory overhead compared to standard NeRF.
*   **Strengths:** Effective at removing floating artifacts and improving geometric accuracy in indoor scenes [S1, unofficial]. Provides explicit geometric supervision where photometric loss is ambiguous [S3].
*   **Limitations:** Relies on the quality of SfM reconstruction; fails in texture-less regions without confidence filtering [S1, S2, unofficial]. Requires accurate camera poses [S3].
*   **When to Use:** Indoor scenes with known camera poses (e.g., from COLMAP) where geometric consistency is critical.
*   **When Not to Use:** Scenes with no distinctive features for SfM, or where camera poses are unknown/unreliable.

## Background
The method originates from the need to improve geometric consistency in Neural Radiance Fields (NeRF), particularly in indoor environments where photometric loss alone leads to floating artifacts [S1, unofficial]. It leverages Structure-from-Motion (SfM) techniques, specifically COLMAP, which are standard for estimating camera poses and generating sparse point clouds [S3]. The concept of using pseudo-depth from SfM as a supervision signal was introduced to address the lack of ground truth depth in real-world scenarios [S1, unofficial][S3]. Confidence filtering was later introduced to handle the unreliability of depth predictions in texture-less regions [S2, unofficial].
