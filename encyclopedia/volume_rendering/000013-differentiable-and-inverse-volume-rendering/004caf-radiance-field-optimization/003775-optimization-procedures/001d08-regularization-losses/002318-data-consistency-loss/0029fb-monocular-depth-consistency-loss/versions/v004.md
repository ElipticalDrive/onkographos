# Monocular Depth Consistency Loss

Also called: Monocular Depth Loss

## Overview
Monocular Depth Consistency Loss enforces geometric consistency between the depth rendered from a differentiable volume rendering pipeline and depth predictions from a pre-trained monocular depth estimation network [S1]. It solves the problem of scale and shift ambiguity inherent in monocular depth priors by computing a closed-form least-squares alignment for each training batch [S1]. Unlike sibling methods that may rely on sparse geometric constraints or multi-view consistency, this method specifically addresses the relative nature of monocular depth cues by treating them as relative signals that must be locally aligned to the rendered geometry [S1].

## How it works
**Inputs:**
*   $\hat{D}(\mathbf{r})$: Rendered depth for ray $\mathbf{r}$, derived from the volume rendering optimization parameters $\boldsymbol{\theta}$ and $\boldsymbol{\phi}$ [S1].
*   $\bar{D}(\mathbf{r})$: Predicted monocular depth for the corresponding image pixel, derived from a pre-trained network [S1].
*   $\bar{D}_i$: The set of rays associated with the $i$-th image in the current training batch [S1].

**Outputs:**
*   $\mathcal{L}_{Mono}(\boldsymbol{\theta}, \boldsymbol{\phi})$: The scalar loss value for the batch [S1].

**Data Structures:**
*   Depth maps are treated as dense tensors of floating-point values. No specific bit-packing is mandated; standard float32 or float16 precision is implied by the least-squares operations [S1].

**Steps:**
1.  For the current training batch, collect all rendered depth values $\hat{D}(\mathbf{r})$ and corresponding monocular depth predictions $\bar{D}(\mathbf{r})$ for all rays $\mathbf{r} \in \bar{D}_i$.
2.  Compute the scale parameter $\eta$ and shift parameter $\epsilon$ using the closed-form least-squares solution for the current batch [S1]:
    $$ \eta = \left( \hat{D}(\mathbf{r})^T \hat{D}(\mathbf{r}) \right)^{-1} \hat{D}(\mathbf{r})^T \bar{D}(\mathbf{r}) $$
    $$ \epsilon = \bar{D}(\mathbf{r}) - \eta \hat{D}(\mathbf{r}) $$
    *Note: In implementation, $\hat{D}(\mathbf{r})$ and $\bar{D}(\mathbf{r})$ are vectors containing all depth values in the batch. The term $\hat{D}(\mathbf{r})^T \hat{D}(\mathbf{r})$ is the dot product of the rendered depth vector with itself (a scalar), and $\hat{D}(\mathbf{r})^T \bar{D}(\mathbf{r})$ is the dot product between rendered and predicted depth vectors (a scalar) [S1].*
3.  Compute the aligned rendered depth for each ray: $\hat{D}_{aligned}(\mathbf{r}) = \eta \hat{D}(\mathbf{r}) + \epsilon$ [S1].
4.  Calculate the mean squared error between the aligned rendered depth and the monocular prediction:
    $$ \mathcal{L}_{Mono}(\boldsymbol{\theta}, \boldsymbol{\phi}) = \sum_i \mathbb{E}_{\mathbf{r} \sim \bar{D}_i} \left\| (\eta \hat{D}(\mathbf{r}) + \epsilon) - \bar{D}(\mathbf{r}) \right\|^2 $$
    [S1]

**Parameters:**
*   $\eta$: Scale parameter. Calculated per batch [S1].
*   $\epsilon$: Shift parameter. Calculated per batch [S1].

**Edge Cases and Pitfalls:**
*   **Batch-wise Calculation:** The scale and shift can vary significantly across different batches. Therefore, $\eta$ and $\epsilon$ must be calculated separately for each batch to ensure correct alignment [S1].
*   **Texture-less Regions:** Monocular depth predictions are unreliable in texture-less regions. While the basic formulation does not explicitly filter these, variants (see Subtopics) introduce confidence masks to handle this [S5, unofficial].
*   **Degenerate Input:** If the rendered depth vector $\hat{D}(\mathbf{r})$ is zero or near-zero, the inverse term in the least-squares solution becomes unstable. Standard numerical safeguards (e.g., epsilon addition) should be applied [G].

**Pseudocode:**
```python
def monocular_depth_consistency_loss(rendered_depth, monocular_depth):
    """
    Calculates the Monocular Depth Consistency Loss for a single batch.
    
    Args:
        rendered_depth (Tensor): Shape [N], containing D_hat(r) for N rays.
        monocular_depth (Tensor): Shape [N], containing D_bar(r) for N rays.
        
    Returns:
        Tensor: Scalar loss value.
    """
    # Step 1: Compute scale eta
    # eta = (D_hat^T * D_bar) / (D_hat^T * D_hat)
    # Using dot products for 1D tensors
    dot_dd = torch.dot(rendered_depth, rendered_depth)
    dot_dp = torch.dot(rendered_depth, monocular_depth)
    
    # Guard against division by zero
    if dot_dd < 1e-8:
        eta = 0.0
    else:
        eta = dot_dp / dot_dd
        
    # Step 2: Compute shift epsilon
    # epsilon = mean(D_bar) - eta * mean(D_hat)
    # Note: The source formula epsilon = D_bar - eta * D_hat implies a vector subtraction,
    # but for the least squares solution y = ax + b, b = mean(y) - a * mean(x).
    # The source [S1] writes epsilon = D_bar(r) - eta D_hat(r) inside the context of the solution derivation.
    # Standard OLS shift is calculated on means. However, the source explicitly defines:
    # epsilon = D_bar(r) - eta D_hat(r). This notation is ambiguous for vectors.
    # Given the loss is an expectation over r, and eta/epsilon are scalars per batch,
    # the shift epsilon must be a scalar. The standard closed-form shift is:
    # epsilon = mean(monocular_depth) - eta * mean(rendered_depth)
    # We implement the standard closed-form solution for shift to ensure numerical stability and correctness.
    
    mean_d_hat = torch.mean(rendered_depth)
    mean_d_bar = torch.mean(monocular_depth)
    epsilon = mean_d_bar - eta * mean_d_hat
    
    # Step 3: Align rendered depth
    aligned_depth = eta * rendered_depth + epsilon
    
    # Step 4: Compute MSE loss
    loss = torch.mean((aligned_depth - monocular_depth) ** 2)
    
    return loss
```

## Subtopics

### MonoSDF
Uses monocular depth and normal maps as constraints to address reconstruction issues in weak texture areas [S2, unofficial]. It extends the basic depth consistency by incorporating surface normal information from the monocular predictor to guide the implicit surface reconstruction [S2, unofficial].

### Scale Alignment of Depth Priors
Aligns the scale of a predicted monocular depth map with sparse COLMAP depths to enable supervision during NeRF optimization [S3]. It uses a log-space scale factor $\alpha$ computed by averaging the difference between the log of the predicted depth and the log of the sparse depth over all valid pixels: $\alpha (D^i_p, D^i_{Sparse}) = \frac {1}{n} \sum _j(\log D^i_p(j) - \log D^i_{Sparse}(j))$ [S3].

### Reliable Depth Estimation via Reprojection
Computes the mean squared error (MSE) of intensities between a reprojected patch and the corresponding patch in the nearest training view to determine depth reliability [S4]. It uses masks $m_m$ and $m_a$ to select reliable depths from the main and augmented models based on whether the reprojection MSE is lower than a threshold $e_\tau$ [S4].

### Pseudo-depth Supervised Loss
Supervises the rendered depth against a pseudo-depth target, filtered by a confidence score to ensure reliability in texture-less regions [S5, unofficial]. The loss includes a color reconstruction term and a depth term weighted by an indicator function $\mathbb{I}(U(p) > \delta)$, where $U(p)$ is the confidence score and $\delta$ is a threshold (typically 0.5) [S5, unofficial]. The depth loss weight $\lambda_2$ grows linearly from $1e-4$ to $1e-2$ during training [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** The calculation of $\eta$ and $\epsilon$ involves dot products and mean calculations over the batch size $N$, resulting in $O(N)$ time complexity per batch. The final loss computation is also $O(N)$.
*   **Memory Complexity:** Requires storing the rendered and monocular depth maps for the current batch, $O(N)$ memory.
*   **Strengths:** Simple to implement; effectively handles the scale/shift ambiguity of monocular depth; provides strong geometric regularization for scenes with limited multi-view coverage (e.g., endoscopic sequences) [S1].
*   **Limitations:** Relies on the quality of the pre-trained monocular depth network; performance degrades in texture-less regions without additional confidence filtering [S5, unofficial]; assumes the monocular depth is a valid relative cue for the scene [S1].
*   **When to use:** Suitable for monocular or sparse-view scenarios where multi-view stereo is unreliable or unavailable, such as monocular endoscopic sequences [S1].
*   **When not to use:** Not recommended when high-precision absolute metric depth is required without sparse calibration, or when the monocular predictor is known to be inaccurate for the specific domain [S1][S5, unofficial].

## Background
The Monocular Depth Consistency Loss was introduced in the context of deformable tissue reconstruction using orthogonal neural planes [S1]. It addresses the challenge that depth in monocular sequences should be treated as a relative cue, yet this relative information is beneficial over larger distances [S1]. The method replaces the standard depth loss $L_D$ with $L_{Mono}$ during training for monocular endoscopic sequences [S1].
