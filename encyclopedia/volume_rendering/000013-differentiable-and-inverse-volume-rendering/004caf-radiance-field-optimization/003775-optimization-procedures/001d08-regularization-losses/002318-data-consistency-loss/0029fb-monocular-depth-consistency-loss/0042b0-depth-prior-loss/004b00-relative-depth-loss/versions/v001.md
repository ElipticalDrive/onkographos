# Relative Depth Loss

Also called: Lrel, Single-view relative depth loss

## Overview
Relative Depth Loss is a regularization term that constrains the geometry of a radiance field by aligning rendered depth with monocular or Multi-View Stereo (MVS) depth priors. It differs from absolute depth consistency losses by using a relative formulation ($D_{mvs}/D_r$), which exhibits high sensitivity to errors at closer depths [S1]. It is distinguished from its parent [Depth Prior Loss](10801-depth-prior-loss.md) by its specific mechanism of rejecting erroneous MVS values via thresholding and weighting by rendering certainty [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** MVS depth map $D_{mvs}$, rendered depth map $D_r$, rendering certainty $U$, thresholding hyperparameter $s$.
*   **Output:** Scalar loss value $L_{rel}$.

**Data Structures**
*   $D_{mvs}$: 2D array of depth values from an external MVS estimator or monocular depth network.
*   $D_r$: 2D array of rendered depth values, computed per-pixel.
*   $U$: 2D array of rendering certainty, computed per-pixel.
*   $\omega_i$: Blending weight of the $i$-th Gaussian contributing to a pixel.
*   $t_i$: Depth of the $i$-th Gaussian.
*   $T_i$: Accumulated transmittance up to the $i$-th Gaussian.

**Formulas**
The rendered depth $D_r$ is computed as the median depth, defined as the largest depth value $t_i$ considered visible:
$$ D_r = \max\{t_i \mid T_i > 0.5\} $$
where $T_i$ is the accumulated transmittance [S1].

Rendering certainty $U$ is defined as the sum of blending weights:
$$ U = \sum_i \omega_i $$
where the sum is over all Gaussians contributing to the pixel [S1].

The loss is calculated as:
$$ L_{rel} = 1 - \frac{D_{mvs}}{D_r} \cdot U \cdot I(|D_r - D_{mvs}| < s \cdot D_r) $$
where:
*   $D_{mvs}$ is the MVS depth [S1].
*   $D_r$ is the rendered depth [S1].
*   $s$ is the thresholding tolerance hyperparameter [S1].
*   $I(\cdot)$ is the indicator function, yielding 1 if the condition holds and 0 otherwise [S1].

**Parameters**
*   $s$: Thresholding tolerance. Typically annealed from a less restrictive to a more restrictive value during optimization [S1].

**Pitfalls and Edge Cases**
*   **Mean Depth Artifacts:** Using mean depth ($\sum \omega_i t_i / \sum \omega_i$) leads to inaccurate estimates for semi-transparent or transparent objects and introduces "flying pixel" artifacts near boundaries of opaque objects [S1].
*   **Weight Instability:** Reliance on mean depth calculated using potentially unstable weights $\omega_i$ during optimization can harm reconstruction quality [S1].
*   **Sensitivity:** The relative formulation is highly sensitive to errors at closer depths [S1].

**Pseudocode**
```python
def compute_relative_depth_loss(D_mvs, D_r, U, s):
    """
    Computes the Relative Depth Loss (Lrel).
    
    Args:
        D_mvs: 2D array, MVS depth map.
        D_r: 2D array, rendered median depth map.
        U: 2D array, rendering certainty (sum of blending weights).
        s: float, thresholding tolerance hyperparameter.
        
    Returns:
        float, the scalar loss value.
    """
    # Compute the relative depth ratio
    # Avoid division by zero if D_r is 0
    epsilon = 1e-6
    ratio = D_mvs / (D_r + epsilon)
    
    # Compute the indicator function: 1 if |D_r - D_mvs| < s * D_r, else 0
    # Note: D_r is used in the threshold condition as per the formula
    threshold = s * D_r
    # Handle case where D_r is 0 or negative (should not happen in valid depth)
    valid_depth_mask = D_r > epsilon
    condition = (D_r - D_mvs).abs() < threshold
    
    # Combine masks: valid depth AND condition holds
    indicator = condition.float() * valid_depth_mask.float()
    
    # Compute loss term: 1 - (ratio * U * indicator)
    loss_term = ratio * U * indicator
    
    # Mean loss over all pixels (or sum, depending on implementation convention)
    # The source defines the term; standard practice is to average over valid pixels
    # Here we assume element-wise operation and mean reduction
    loss = 1.0 - loss_term
    
    # Return mean loss
    return loss.mean()

def compute_rendered_depth(Gaussians):
    """
    Computes rendered depth D_r as the median depth.
    
    Args:
        Gaussians: List of Gaussian objects contributing to a pixel, 
                   sorted by depth. Each Gaussian has attributes:
                   - t: depth
                   - T: accumulated transmittance (pre-computed or computed during rasterization)
                   
    Returns:
        float, the median depth D_r.
    """
    # Filter Gaussians where accumulated transmittance T_i > 0.5
    visible_gaussians = [g for g in Gaussians if g.T > 0.5]
    
    if not visible_gaussians:
        # Fallback if no Gaussian is visible (e.g., background)
        # Not specified in source, but typically returns 0 or max depth
        return 0.0
        
    # Return the maximum depth among visible Gaussians
    D_r = max(g.t for g in visible_gaussians)
    return D_r

def compute_rendering_certainty(Gaussians):
    """
    Computes rendering certainty U as the sum of blending weights.
    
    Args:
        Gaussians: List of Gaussian objects contributing to a pixel.
                   Each Gaussian has attribute:
                   - omega: blending weight
                   
    Returns:
        float, the rendering certainty U.
    """
    U = sum(g.omega for g in Gaussians)
    return U
```

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of Gaussians contributing to each pixel for the computation of $D_r$ and $U$. The final loss computation is $O(N)$ where $N$ is the number of pixels.
*   **Memory Complexity:** Requires storage for $D_{mvs}$, $D_r$, and $U$ maps. $O(N)$ for pixel-wise operations.
*   **Strengths:** Mitigates artifacts associated with mean depth (flying pixels, transparency issues) by using median depth. High sensitivity to close-depth errors improves geometric fidelity [S1].
*   **Limitations:** Single-view application may not regularize all scene regions effectively, as gradients primarily affect Gaussians contributing to the median depth in that specific view [S1]. Requires stable MVS priors; erroneous MVS values are rejected via thresholding, but incorrect priors in valid regions may still mislead optimization if not properly thresholded.
*   **When to use:** When high geometric fidelity is required, especially for close-range objects, and MVS priors are available. Suitable for scenes where mean depth fails due to transparency or boundary artifacts.
*   **When not to use:** When MVS priors are unreliable or noisy, as the thresholding may reject valid data or fail to reject erroneous data if $s$ is not tuned correctly. Not suitable for single-view optimization without multiview extension, as it may not regularize all regions [S1].

## Background
Relative Depth Loss was introduced in the context of Multiview Geometric Regularization of Gaussian Splatting for Accurate Radiance Fields [S1]. It addresses limitations of mean depth computation in 3D Gaussian Splatting, such as "flying pixel" artifacts and inaccuracies with transparent objects [S1]. The method builds on the observation that median depth provides a more robust estimate of surface location [S1].
