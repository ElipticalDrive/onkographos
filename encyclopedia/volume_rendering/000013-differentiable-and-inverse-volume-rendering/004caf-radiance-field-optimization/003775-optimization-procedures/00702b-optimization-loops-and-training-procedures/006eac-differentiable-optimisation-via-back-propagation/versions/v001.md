# Differentiable Optimisation via Back-Propagation

Also called: TomOpt optimisation

## Overview
Differentiable Optimisation via Back-Propagation is a method for optimizing scene or system parameters by computing gradients of a task-specific loss function with respect to those parameters using automatic differentiation. It solves the problem of finding optimal configurations (e.g., detector geometry, material properties) where the forward process is differentiable. It is distinguished from standard differentiable rendering by its focus on end-to-end task performance optimization (e.g., fill-level prediction) rather than proxy metrics like image fidelity, leveraging standard deep learning optimizers to update parameters directly [S1].

## How it works
**Inputs:**
- A differentiable forward model (inference and hit-recording steps) parameterized by $\theta$ [S1].
- A task-specific loss function $L$ computed from the model output [S1].
- An optimization algorithm (e.g., SGD, Adam) [S1].

**Outputs:**
- Updated parameters $\theta'$ that minimize $L$ [S1].

**Data Structures:**
- Parameters $\theta$: Tensors managed by the deep learning framework (e.g., PyTorch) [S1].
- Loss $L$: Scalar value derived from the model output [S1].

**Steps:**
1. **Forward Pass:** Compute the model output and the loss $L$ based on the current parameters $\theta$ [S1].
2. **Backward Pass:** Compute the gradients $\frac{\partial L}{\partial \theta}$ by back-propagating the derivative of the loss through the inference and hit-recording steps [S1].
3. **Update:** Update $\theta$ by stepping in the direction of steepest descent of the loss surface using a standard optimizer [S1].

**Pseudocode:**
```python
# Assume model is a PyTorch nn.Module with parameters theta
# Assume loss_fn computes the task-specific loss
# Assume optimizer is an instance of torch.optim.Adam or SGD

for epoch in range(num_epochs):
    # 1. Forward pass
    optimizer.zero_grad() # Clear existing gradients
    output = model(theta) # Inference and hit-recording steps
    loss = loss_fn(output, target) # Compute task-specific loss
    
    # 2. Backward pass
    loss.backward() # Back-propagate derivative of loss through inference and hit-recording steps
    
    # 3. Update parameters
    optimizer.step() # Step in direction of steepest descent
```

**Parameters:**
- Optimizer: Standard optimizers like SGD or Adam [S1].
- Learning rate: Not specified in sources [G].

**Edge Cases:**
- The loss function must be computed under conditions representative of actual operation (e.g., number of muons) to ensure valid gradients [S1].

## Operating characteristics
- **Memory:** Requires storing the computational graph for back-propagation, leading to high memory usage proportional to the number of operations [44-radiance-field-optimization.md].
- **Time:** Gradient computation is $O(1)$ with respect to the number of parameters but depends on the complexity of the forward model [44-radiance-field-optimization.md].
- **Strengths:** Ensures parameter changes directly impact final task performance; no balancing coefficients required between performance and cost in the loss function [S1].
- **Limitations:** High memory consumption due to storing intermediate states [44-radiance-field-optimization.md].

## Background
Originated in the context of particle detector design for muon tomography, specifically in the TomOpt framework [S1]. It leverages automatic differentiation techniques from deep learning [S1].
