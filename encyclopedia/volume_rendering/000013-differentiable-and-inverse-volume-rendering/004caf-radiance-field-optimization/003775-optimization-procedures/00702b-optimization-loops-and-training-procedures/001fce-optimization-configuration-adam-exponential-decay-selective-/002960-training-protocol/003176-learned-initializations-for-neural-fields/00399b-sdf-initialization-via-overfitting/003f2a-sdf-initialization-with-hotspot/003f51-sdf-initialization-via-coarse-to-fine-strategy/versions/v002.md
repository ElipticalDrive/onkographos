# SDF Initialization via Coarse-to-Fine Strategy

Also called: Coarse SDF Initialization, SDF State Initialization Pitfall, Unconverged SDF Initialization

## Overview
This method initializes the Signed Distance Field (SDF) using a coarser, unconverged state rather than a fully converged one to prevent the optimization process from trapping in local minima [S1]. While a fully converged SDF provides a precise geometric prior, it can lead to catastrophic failure in complex scenes by restricting the optimization landscape [S1]. This approach builds on [SDF Initialization with Hotspot](9906-sdf-initialization-with-hotspot.md) by explicitly leveraging the regularization benefits of an incomplete initialization [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A neural field model initialized with SDF values derived from a coarse or partially trained state [S1].
*   **Output:** A refined SDF field that avoids local minima traps associated with over-regularized initial states [S1].

**Data Structures:**
The SDF field is represented as a continuous function $f(\mathbf{x})$ mapping 3D coordinates to signed distances [G]. The "coarse" state implies that the network weights have not been optimized to minimize the SDF loss to convergence, leaving the field less constrained [G].

**Steps:**
1.  **Initialize SDF State:** Instead of training the SDF component until convergence (which yields a "hotspot" or highly refined surface), halt the initial training phase early [S1].
2.  **Begin Optimization Loop:** Start the main differentiable volume rendering optimization loop using this unconverged SDF as the prior [S1].
3.  **Regularization Effect:** The unconverged state acts as a regularizer [S1]. Because the initial surface is not perfectly fitted to the training data, the optimization has more freedom to explore the solution space, avoiding the local minima that a fully converged SDF would enforce [S1].

**Pitfalls:**
*   **Catastrophic Failure:** Using a fully converged SDF initialization can trap the optimizer in a local minimum, leading to significant reconstruction errors (e.g., Mesh ID 252119 in [S1]).
*   **Precision:** Not given in the sources.

**Pseudocode:**
```python
def initialize_sdf_coarse_to_fine(model, training_data, early_stop_threshold):
    """Initializes the SDF model using a coarse, unconverged state."""
    for epoch in range(early_stop_threshold):
        sdf_loss = compute_sdf_loss(model, training_data)
        update_weights(model, sdf_loss)
        if sdf_loss < early_stop_threshold:
            break
    return model

def compute_sdf_loss(model, training_data):
    """Computes the loss for the SDF component."""
    # [G] Standard SDF loss computation (e.g., L1 distance to surface points or Eikonal regularization)
    return model.evaluate_sdf_loss(training_data)

def compute_rendering_loss(model, training_data):
    """Computes the loss for the volume rendering component."""
    # [G] Standard differentiable volume rendering loss (e.g., MSE between rendered and target images)
    return model.evaluate_rendering_loss(training_data)

def update_weights(model, loss):
    """Performs a standard gradient descent step."""
    # [G] Standard gradient descent step
    gradients = compute_gradients(model, loss)
    model.apply_gradients(gradients)

def compute_gradients(model, loss):
    """Computes gradients via backpropagation."""
    # [G] Standard automatic differentiation
    return model.backward(loss)

def main_optimization_loop(model, training_data, total_epochs):
    """Continues optimization from the coarse initialization."""
    for epoch in range(total_epochs):
        rendering_loss = compute_rendering_loss(model, training_data)
        update_weights(model, rendering_loss)
```

## Subtopics

### SDF Progressive Initialization
A training strategy that progressively transitions the scene representation from pure volumetric density to SDF to handle limited image overlap and complex urban scenes, avoiding the need for full scene observability required by bounded sphere initialization [S2]. Unlike StreetSurf, which initializes SDF based on road-surface, this method transitions from density to SDF, making it better suited for driving scenes with linear trajectories and reduced overlap [S2]. Choose this method when working with driving sequences or urban environments where camera trajectories are linear and image overlap is limited [S2]. See [ViiNeS](vii-neus.md) for implementation details [S2].

## Operating characteristics
*   **Strengths:** Prevents catastrophic failure in complex scenes by avoiding local minima traps associated with fully converged SDFs [S1]. Provides better regularization for the optimization loop [S1].
*   **Limitations:** Not given in the sources.
*   **Performance:** Results in significantly improved surface discretization compared to converged initializations in near-sampling and upsampling settings [S1].

## Background
This method addresses the "SDF State Initialization Pitfall" identified in differentiable volume rendering research [S1]. It was highlighted in the context of DCCVT (Differentiable Clipped Centroidal Voronoi Tessellation), where fully converged SDFs were found to cause catastrophic failures in specific mesh reconstructions (e.g., Mesh ID 252119 and 398259) [S1]. The approach contrasts with progressive initialization methods like ViiNeS, which handle limited overlap by transitioning from density to SDF, whereas this method focuses on the state of the SDF itself during the initialization phase of a standard optimization loop [S1, S2].
