# Test-Time Optimization

Also called: TTO for VFMs, Test-Time Optimization (TTO) for VFMs

## Overview
Test-Time Optimization (TTO) is a technique that exploits known camera parameters while keeping the pretrained visual foundation model (VFM) parameters frozen, adapting lightweight Low-Rank Adaptation (LoRA) modules using pose supervision [S1, unofficial]. It addresses misalignment in novel view synthesis by aligning predicted camera parameters with ground truth during inference [S1, unofficial]. Unlike standard inference which uses fixed weights, TTO performs a brief optimization loop on test data to refine the model's internal representation of camera geometry without retraining the backbone [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:** Pretrained VFM backbone (frozen), LoRA modules (trainable), input image(s), initial predicted camera poses ($R_{pi}, t_i, k$), and ground-truth camera poses ($R_{gi}, t_{gi}, k_{gi}$) if available for supervision.
*   **Outputs:** Optimized LoRA parameters, refined camera parameters.

**Data Structures**
The network architecture follows DA3 with $L=40$ attention layers [S1, unofficial].
*   **Layers 1–12:** Single-view attention. No LoRA.
*   **Layers 13–40:** Alternate between single-view and global attention. LoRA is added to the Query (Q), Key (K), and Value (V) projections [S1, unofficial].
*   **LoRA Layout:** Each layer shares a down-projection matrix $A$. Up-projection matrices $B$ are independent per layer [S1, unofficial].

**Steps**
1.  **Initialization:** Insert LoRA modules into the VFM backbone at layers 13–40 [S1, unofficial].
2.  **Pose Alignment (Pre-computation):**
    *   Fix the first ground-truth camera pose to the identity matrix to establish a common coordinate frame [S1, unofficial].
    *   Address scale ambiguity by normalizing translation vectors. Compute the mean scale $s$ for predicted translations $t_i$ and ground-truth translations $t_{gi}$ separately:
        $$ s = \frac{1}{M-1} \sum_{i=1}^M \|t_i\|_2 $$
        where $M$ is the number of views [S1, unofficial].
3.  **Loss Calculation:**
    *   **Rotation Loss ($L_{rot}$):** Constructed from the relative rotation between predicted $R_{pi}$ and ground-truth $R_{gi}$ rotations:
        $$ L_{rot} = \frac{1}{2M} \sum_{i=1}^M (3 - \text{tr}(R_{pi}^\top R_{gi})) $$
        [S1, unofficial]
    *   **Translation Loss ($L_{trans}$):** Calculate the scale-normalized translation loss using SmoothL1 between predicted and ground-truth translations [S1, unofficial].
    *   **Intrinsic Loss ($L_{intrinsics}$):** Supervise camera intrinsics $k = (f_x, f_y, c_x, c_y)$ by directly applying SmoothL1 to predicted and ground-truth values [S1, unofficial].
4.  **Optimization Loop:**
    *   Compute the total TTO loss:
        $$ L_{TTO} = \lambda_{pose} (L_{rot} + w_t L_{trans}) + \lambda_K L_{intrinsics} $$
        [S1, unofficial]
    *   Update LoRA parameters by backpropagation for a fixed number of iterations [S1, unofficial].

**Parameters**
*   $\lambda_{pose}$: Weight for pose loss. Not given in the sources.
*   $w_t$: Weight for translation loss. Not given in the sources.
*   $\lambda_K$: Weight for intrinsic loss. Not given in the sources.
*   Number of iterations: Fixed, but exact value not given in the sources.

**Pseudocode**
```python
def test_time_optimization(vfm_backbone, lora_modules, images, 
                           predicted_poses, ground_truth_poses, 
                           lambda_pose, w_t, lambda_K, num_iterations):
    """
    Performs test-time optimization to align predicted camera poses with ground truth.
    
    Args:
        vfm_backbone: Frozen VFM backbone.
        lora_modules: Trainable LoRA modules inserted in layers 13-40.
        images: Input images.
        predicted_poses: Dictionary containing R_pi, t_i, k for predicted poses.
        ground_truth_poses: Dictionary containing R_gi, t_gi, k_gi for ground truth.
        lambda_pose: Weight for pose loss.
        w_t: Weight for translation loss.
        lambda_K: Weight for intrinsic loss.
        num_iterations: Number of optimization steps.
        
    Returns:
        Optimized LoRA parameters.
    """
    # Step 1: Align coordinate frames
    # Fix first ground-truth pose to identity
    ground_truth_poses.R_gi[0] = IdentityMatrix()
    
    # Step 2: Normalize scales to address ambiguity
    M = len(predicted_poses.t_i)
    
    # Compute mean scale for predicted translations
    sum_pred_norm = sum(norm(t) for t in predicted_poses.t_i)
    scale_pred = sum_pred_norm / (M - 1)
    
    # Compute mean scale for ground-truth translations
    sum_gt_norm = sum(norm(t) for t in ground_truth_poses.t_gi)
    scale_gt = sum_gt_norm / (M - 1)
    
    # Normalize translations
    t_i_normalized = [t / scale_pred for t in predicted_poses.t_i]
    t_gi_normalized = [t / scale_gt for t in ground_truth_poses.t_gi]
    
    optimizer = Adam(lora_modules.parameters())
    
    for step in range(num_iterations):
        optimizer.zero_grad()
        
        # Forward pass through VFM with LoRA
        # Note: The exact forward pass mechanism for camera decoding is not detailed
        # in the sources, but it produces predicted_poses.R_pi, predicted_poses.t_i, predicted_poses.k
        # We assume these are updated or re-evaluated based on current LoRA weights
        predicted_poses = vfm_forward(vfm_backbone, lora_modules, images)
        
        # Calculate Rotation Loss
        # L_rot = 1/(2M) * sum(3 - tr(R_pi^T * R_gi))
        rot_loss = 0.0
        for i in range(M):
            R_pi = predicted_poses.R_pi[i]
            R_gi = ground_truth_poses.R_gi[i]
            # Trace of matrix product
            trace_val = trace(matrix_multiply(transpose(R_pi), R_gi))
            rot_loss += (3.0 - trace_val)
        rot_loss = rot_loss / (2.0 * M)
        
        # Calculate Translation Loss (SmoothL1 on normalized translations)
        trans_loss = 0.0
        for i in range(M):
            t_pred = t_i_normalized[i] # Using normalized predicted
            t_gt = t_gi_normalized[i]  # Using normalized ground truth
            trans_loss += smooth_l1_loss(t_pred, t_gt)
        # Note: Source implies L_trans is the sum or mean; assuming mean for consistency with L_rot
        trans_loss = trans_loss / M
        
        # Calculate Intrinsic Loss (SmoothL1)
        k_pred = predicted_poses.k
        k_gt = ground_truth_poses.k
        intrinsic_loss = smooth_l1_loss(k_pred, k_gt)
        
        # Total TTO Loss
        loss = lambda_pose * (rot_loss + w_t * trans_loss) + lambda_K * intrinsic_loss
        
        # Backpropagation
        loss.backward()
        optimizer.step()
        
    return lora_modules
```

**Edge Cases and Pitfalls**
*   **Scale Ambiguity:** Image-based reconstruction has inherent scale ambiguity. Failure to normalize translations by their mean scale $s$ will result in incorrect loss values [S1, unofficial].
*   **Coordinate Frame:** The first ground-truth pose must be fixed to the identity matrix to align the predicted and ground-truth coordinate systems before computing relative rotation [S1, unofficial].
*   **LoRA Placement:** LoRA is only applied to layers 13–40. Applying it elsewhere or to all layers is not supported by this configuration [S1, unofficial].

## Subtopics

## Operating characteristics
*   **Time Complexity:** Depends on the number of optimization iterations. The sources do not specify the exact number of iterations or the time per iteration, but training the full model requires 80 GPU hours [S1, unofficial]. Test-time optimization is described as "lightweight" and "brief" [S1, unofficial].
*   **Memory Complexity:** Adds the memory overhead of LoRA parameters (75.3M trainable parameters for the full VoxelTTO framework, but TTO only optimizes the LoRA modules) [S1, unofficial].
*   **Strengths:** Improves geometric fidelity and camera-pose estimation for novel view synthesis (NVS) [S1, unofficial]. Compatible with any VGGT-style VFMs [S1, unofficial].
*   **Limitations:** Requires ground-truth camera poses for supervision during the optimization loop [S1, unofficial]. Performance depends on the quality of the initial predicted poses.
*   **When to use:** When known camera parameters are available and alignment between predicted and ground-truth poses is critical for high-quality NVS [S1, unofficial].
*   **When not to use:** When ground-truth poses are unavailable or when computational resources for iterative optimization are limited [S1, unofficial].

## Background
Test-Time Optimization (TTO) was introduced in the VoxelTTO paper [S1, unofficial]. It builds upon the DA3 architecture and VGGT-style visual foundation models [S1, unofficial]. The method was developed to address misalignment issues in novel view synthesis, particularly when injecting camera parameters into the model [S1, unofficial]. It replaces vanilla 3DGS rasterization with stochastic solid volume rendering to improve geometric supervision [S1, unofficial].
