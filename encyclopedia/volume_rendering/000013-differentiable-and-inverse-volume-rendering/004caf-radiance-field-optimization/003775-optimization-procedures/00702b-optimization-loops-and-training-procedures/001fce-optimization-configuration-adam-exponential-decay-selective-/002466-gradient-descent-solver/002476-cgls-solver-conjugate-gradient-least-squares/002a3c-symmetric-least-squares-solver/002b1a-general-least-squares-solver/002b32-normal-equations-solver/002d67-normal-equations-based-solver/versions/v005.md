# Normal Equations-based Solver

Also called: A^T A Solver, Constrained Least Squares, Least Squares via Normal Equations, Quadratic Programming Solver (Box-Constrained)

## Overview
The Normal Equations-based Solver addresses the box-constrained least squares problem $\forall i \in [1,...,n] : 0 \le x_i \le 1$ by formulating it as a quadratic programming (QP) problem [S1, unofficial]. It sets itself apart from its parent [Normal Equations Solver](4954-normal-equations-solver.md) by explicitly handling the box constraints ($0 \le x_i \le 1$) via a QP formulation, whereas the parent solver typically refers to the unconstrained ordinary least squares (OLS) solution [S1, unofficial]. It is noted as the fastest alternative for small systems but suffers from stability issues if the matrix is ill-conditioned [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Matrix $A$ and vector $b$ from the linear system $Ax \approx b$.
- Output: Vector $x$ satisfying $0 \le x_i \le 1$ that minimizes the objective.

**Data Structures:**
- Matrix $Q$: $n \times n$ symmetric positive semi-definite matrix, where $Q = A^T A$.
- Vector $c$: $n$-dimensional vector, where $c = -A^T b$.
- Constraints: Box constraints $l_i = 0, u_i = 1$ for all $i$.

**Steps:**
1. Compute the Hessian matrix $Q = A^T A$.
2. Compute the gradient vector $c = -A^T b$.
3. Formulate the quadratic programming problem:
   $$ \min_x \frac{1}{2} x^T Q x + c^T x $$
   subject to $0 \le x_i \le 1$ for all $i \in [1,...,n]$ [S1, unofficial].
4. Solve the QP problem using the Alternating Direction Method of Multipliers (ADMM) via the OSQP solver library [S1, unofficial].
5. If the solver returns a solution that violates constraints due to numerical precision, apply truncation: $x'_i = \max\{\min\{x_i, 1\}, 0\}$ [S1, unofficial].

**Formulas:**
- Objective: $\min_x \frac{1}{2} x^T Q x + c^T x$ [S1, unofficial].
- Hessian: $H(x) = \frac{\partial^2 E(x)}{\partial x^T \partial x} = 2 A^T A$ [S1, unofficial].
- Condition Number: $\kappa(Q) = \kappa(A)^2$ [S1, unofficial].

**Parameters:**
- Solver: ADMM via OSQP [S1, unofficial].
- Preconditioning: Not specified for this specific QP formulation, though CGLS (a sibling solver) uses Jacobi preconditioning [S1, unofficial].

**Edge Cases and Pitfalls:**
- Ill-conditioning: The condition number of $Q$ is the square of the condition number of $A$. For very large, ill-conditioned systems, evaluating $A^T A$ is problematic [S1, unofficial].
- Convexity: The ordinary least squares problem is convex because the Hessian $2 A^T A$ is positive semi-definite [S1, unofficial].

**Pseudocode:**
```python
def normal_equations_solver(A, b):
    # Step 1: Compute Q = A^T A
    Q = transpose(A) @ A
    
    # Step 2: Compute c = -A^T b
    c = -transpose(A) @ b
    
    # Step 3: Define QP problem
    # min 0.5 * x^T Q x + c^T x
    # s.t. 0 <= x_i <= 1
    
    # Step 4: Solve using ADMM via OSQP
    # Note: OSQP expects Q in sparse format and c as dense vector
    # The solver handles the box constraints internally
    x = osqp_solve(Q_sparse=csc_matrix(Q), c_dense=c, l=zeros(n), u=ones(n))
    
    # Step 5: Enforce constraints via truncation if necessary
    x = clip(x, 0, 1)
    
    return x
```

## Subtopics

### [ADMM Solver](10107-admm-solver.md)
The ADMM Solver is a proximal algorithm used to solve separable minimization problems of the form $\min_x f(x) + g(x)$ or $\min_x f(x) + g(Dx)$, where $f(x)$ is a data fidelity term and $g(x)$ is a prior or regularization term. It sets itself apart from its parent [Normal Equations-based Solver](5483-normal-equations-based-solver.md) by handling composite objectives with non-smooth or complex constraints (like sparsity or total variation) that are difficult to solve directly via normal equations, by splitting the problem into simpler sub-problems.

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Measured Performance:** A GPU implementation of OSQP exists, but for the small size of $A^T A$ resulting from normal equations, no significant speed-up was observed compared to the CPU implementation [S1, unofficial].
- **Strengths:** Fast for small systems; leverages mature QP solvers like OSQP [S1, unofficial].
- **Limitations:** Prone to stability issues if the matrix is ill-conditioned due to the quadratic condition number of $A$ [S1, unofficial].
- **When to use:** Small-sized data where $A^T A$ is well-conditioned and box constraints are required [S1, unofficial].
- **When not:** Large, ill-conditioned systems where $A^T A$ evaluation is numerically unstable [S1, unofficial].

## Background
The method is based on formulating box-constrained least squares as a quadratic programming problem, a technique used in opacity optimization approaches [GRT13, AZD17] [S1, unofficial]. The ADMM algorithm was first introduced by Boyd et al. [BPC∗ 11] for solving convex optimization problems [S1, unofficial]. The OSQP solver library [SBG∗ 20] is used for implementation [S1, unofficial].
