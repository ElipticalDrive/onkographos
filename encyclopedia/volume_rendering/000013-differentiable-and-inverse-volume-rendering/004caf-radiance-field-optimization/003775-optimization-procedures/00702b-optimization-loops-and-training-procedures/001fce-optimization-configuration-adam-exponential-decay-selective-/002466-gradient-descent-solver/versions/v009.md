# Gradient Descent Solver

Also called: Adam Optimizer, Adam Optimizer Solver, L1/L2 Norm Solver

## Overview
The Gradient Descent Solver is a matrix-free optimization method used to update voxel grid parameters in differentiable volume rendering, such as in DiffVox [S2, unofficial]. It supports both constant update rates and the Adam optimizer, providing stable behavior for ill-conditioned systems [S1, unofficial]. It distinguishes itself from second-order methods like [Newton's Method](6442-newton-s-method.md) by avoiding Hessian computation, and from direct least-squares solvers like [CGLS Solver](3285-cgls-solver-conjugate-gradient-least-squares.md) by minimizing the residual via iterative gradient steps rather than solving normal equations directly [S1, unofficial].

## How it works
**Inputs:**
- Parameter vector $\theta$ (e.g., voxel grid values or transfer function coefficients).
- Loss function $L(\theta)$, typically an $L_2$-norm (least squares) or $L_1$-norm (least absolute deviations) [S1, unofficial].
- Learning rate $\alpha$.
- Adam hyperparameters: $\beta_1, \beta_2$ (exponential decay rates for moving averages) [S3].

**Outputs:**
- Updated parameter vector $\theta_{t+1}$.

**Data Structures:**
- $\theta$: Array of parameters.
- $m_t$: Exponential moving average of gradients (first moment).
- $v_t$: Exponential moving average of squared gradients (second moment).
- $t$: Current iteration counter.

**Steps:**
1. **Gradient Accumulation:** Compute the gradient $\nabla_\theta L$ of the loss with respect to the parameters. In a matrix-free implementation, this is often done by accumulating gradients via atomic additions to avoid forming large dense matrices [S1, unofficial].
2. **Update Moments (Adam):**
   - Update the first moment estimate:
     $$ m_t = \beta_1 m_{t-1} + (1 - \beta_1) \nabla_\theta L $$
   - Update the second moment estimate:
     $$ v_t = \beta_2 v_{t-1} + (1 - \beta_2) (\nabla_\theta L)^2 $$
   - Here, $\beta_1$ and $\beta_2$ control the filtering strength (exponential decay rate) for the gradient and squared gradient moving averages, respectively [S3].
3. **Compute Update Step:**
   - Calculate the update direction as the ratio of the moments multiplied by the learning rate:
     $$ \Delta \theta = \alpha \frac{m_t}{v_t} $$
   - Note: Bias correction terms are omitted in the basic description but are standard in Adam implementations [S3].
4. **Parameter Update:**
   - Update the parameters:
     $$ \theta_{t+1} = \theta_t - \Delta \theta $$

**Parameters:**
- $\alpha$: Learning rate. Typical values depend on the problem scale; not specified in sources.
- $\beta_1$: Exponential decay rate for $m_t$. Typical value: 0.9.
- $\beta_2$: Exponential decay rate for $v_t$. Typical value: 0.999.

**Edge Cases and Pitfalls:**
- **Per-parameter filtering assumption:** The Adam update assumes no correlations across parameters, treating each component of $\theta$ independently [S3].
- **High-frequency artifacts:** This assumption can lead to high-frequency artifacts if:
  - Gradients are very noisy.
  - The objective function $f$ is highly anisotropic.
  - Optimization is terminated early [S3].
- **Ill-conditioning:** While stable for ill-conditioned systems, the solver may converge slowly compared to preconditioned methods if the condition number is very high [S1, unofficial].

**Pseudocode:**
```python
def gradient_descent_step(theta, loss_fn, grad_fn, alpha, beta1, beta2, m, v, t):
    """
    Performs one step of the Gradient Descent Solver with Adam optimization.
    
    Args:
        theta: Current parameter vector.
        loss_fn: Function computing the loss L(theta).
        grad_fn: Function computing the gradient dL/dtheta.
        alpha: Learning rate.
        beta1: Exponential decay rate for first moment.
        beta2: Exponential decay rate for second moment.
        m: Current first moment estimate (array).
        v: Current second moment estimate (array).
        t: Current iteration number.
        
    Returns:
        theta_new: Updated parameter vector.
        m_new: Updated first moment estimate.
        v_new: Updated second moment estimate.
    """
    # 1. Compute gradient
    grad = grad_fn(theta)
    
    # 2. Update moments
    m_new = beta1 * m + (1 - beta1) * grad
    v_new = beta2 * v + (1 - beta2) * (grad ** 2)
    
    # 3. Compute update step
    # Note: Bias correction is omitted as per source description [S3]
    update = alpha * (m_new / v_new)
    
    # 4. Update parameters
    theta_new = theta - update
    
    return theta_new, m_new, v_new
```

## Subtopics

### [CGLS Solver (Conjugate Gradient Least Squares)](3285-cgls-solver-conjugate-gradient-least-squares.md)
The CGLS solver is a sparse linear least squares solver designed to avoid the ill-conditioning inherent in normal equations ($A^T A$) for large or rank-deficient problems. It provides numerically stable results where direct methods fail, distinguishing itself from its sibling [Newton's Method](6442-newton-s-method.md) by using iterative conjugate gradients rather than explicit matrix inversion, and from [Gradient Descent Solver](3280-gradient-descent-solver.md) by solving the least-squares formulation directly rather than minimizing the residual via gradient steps.

### [Partially Learned Gradient Descent](3771-partially-learned-gradient-descent.md)
Partially Learned Gradient Descent (PLGD) is an iterative reconstruction method that unrolls a fixed number of optimization steps into a neural network, combining a fixed physics-based gradient step with a learnable neural network update. It initializes the reconstruction with a filtered backprojection (FBP) estimate and iteratively refines it by passing the current estimate, gradients, and a momentum memory state through a convolutional network to compute the next update. Unlike standard gradient descent which uses a fixed or manually tuned step size, PLGD learns the optimization dynamics (step size and momentum) directly from data, while retaining the explicit physical forward model (e.g., RayTransform) to ensure interpretability and robustness to distribution shifts. It differs from fully learned end-to-end CNNs by preserving the gradient structure of the inverse problem.

### [SGD with Positive t-Distribution](5809-sgd-with-positive-t-distribution.md)
An ablation study variant of differentiable volume rendering optimization that replaces Gaussian noise assumptions with a positive Student's t-distribution to model gradient uncertainty. It serves as a controlled baseline to isolate the impact of heavy-tailed noise modeling from other components like MCMC sampling, ensuring fair comparison with methods using low-pass filtering. It builds on the Gradient Descent Solver [3280-gradient-descent-solver.md] by modifying the noise model [G].

### [Newton's Method](6442-newton-s-method.md)
Newton's method is a second-order optimization algorithm that approximates the objective function $f$ using a second-order Taylor expansion to determine an update step that targets the stationary point where the gradient is zero. It sets itself apart from first-order solvers like Gradient Descent by incorporating local curvature information via the Hessian matrix, allowing for faster convergence near optima, though at the cost of significant computational overhead for high-dimensional problems.

### [Inexact Line Search Optimization](7741-inexact-line-search-optimization.md)
Inexact Line Search Optimization is an iterative method that adapts the step size in gradient descent to achieve a reduction in the objective function while ensuring sufficiently fast progress. It solves the problem of slow convergence in standard gradient descent by dynamically selecting a step size that guarantees improvement without requiring the computational expense of finding the exact minimum along the search direction. Unlike exact line search methods, which may suffer from convergence deterioration, this inexact strategy yields reasonable results and descends much faster.

### [Incremental Preconditioned Gradient Method](14178-incremental-preconditioned-gradient-method.md)
The Incremental Preconditioned Gradient Method is an online learning algorithm for reflective tomography that incrementally updates a voxel model $\phi \in \mathbb{R}^N$ to minimize modeling error against a sequence of observed frames. It solves the global least-squares optimization problem by applying preconditioned gradient descent steps to individual data frames one at a time. It distinguishes itself from batch solvers by processing data sequentially (frame-driven) and using a specific preconditioner derived from the projection matrix structure to prioritize high-frequency spatial information (surfaces).

### [Gradient-based Optimization with Surrogate Function](15131-gradient-based-optimization-with-surrogate-function.md)
This method estimates spatially varying extinction coefficients $\beta$ by minimizing a cost function $E(\beta)$ that fits a forward-model rendering to image measurements, using a surrogate function to avoid computing the full Jacobian per gradient step. It sets itself apart from direct Jacobian computation by decoupling the expensive forward-model rendering (FMC) from the gradient descent updates, requiring only one FMC rendering per block of $NGD$ gradient steps rather than $N_{voxels}$.

### PDHG Solver (Primal-Dual Hybrid Gradient)
A solver that keeps the main solver state on the selected NVIDIA GPU during the PDHG loop, including volume, extrapolated volume, previous volume, gradient buffer, TV duals, projection data duals, measured projections, and projection batches [S4, unofficial]. Default resident projector backend is `matched_voxel`. ASTRA is rejected for production resident PDHG because its 3-D CUDA FP/BP pair failed strict matched-adjoint checks. LEAP/PyTorch support is experimental and should only be used when its adjointness guard passes. Current resident multi-GPU support is not a pooled-memory solver; full memory pooling across two GPUs requires volume-sharded resident PDHG implementation. If resident PDHG runs out of VRAM, do not raise GPU PDHG memory safety to force a run; that only weakens the safety check [S4, unofficial].

## Operating characteristics
- **Time Complexity:** Per iteration, the cost is dominated by the gradient computation and the moment updates, which are linear in the number of parameters $N$. The matrix-free implementation avoids $O(N^2)$ matrix operations [S1, unofficial].
- **Memory Complexity:** $O(N)$ for storing parameters, gradients, and moments. The matrix-free approach minimizes additional memory overhead compared to storing the Hessian or normal equations [S1, unofficial].
- **Performance:** Stable for ill-conditioned systems, but generally slower than computing the matrix $A^T A$ and vector $A^T b$ for well-conditioned problems [S1, unofficial].
- **Strengths:** Robust to ill-conditioning, low memory footprint, supports both $L_1$ and $L_2$ norms [S1, unofficial].
- **Limitations:** Per-parameter filtering can cause high-frequency artifacts under noise or anisotropy [S3]. Convergence can be slow without preconditioning.
- **When to use:** Suitable for large-scale differentiable volume rendering where memory is constrained and the problem may be ill-conditioned [S1, unofficial].
- **When not to use:** When high precision is required in the presence of strong parameter correlations or when fast convergence is critical and second-order methods are feasible [S3].

## Background
The Adam optimizer, a variant of the Gradient Descent Solver, was introduced by Kingma and Ba in 2015 [S2, unofficial]. It has been widely adopted in differentiable volume rendering, such as in DiffVox, for optimizing voxel grid parameters [S2, unofficial]. The method addresses gradient noise and anisotropy by filtering gradients temporally using exponential moving averages [S3].
