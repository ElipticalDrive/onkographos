# GPU Volume Reconstruction via Conjugate Gradient

Also called: Implicit Matrix Solution, Ray Marching Back-Projection

## Overview
This method reconstructs spatially varying volume properties (albedo, emission, extinction) by solving the ill-conditioned linear system $Wa = o$ using Conjugate Gradient (CG) minimization on the GPU [S1]. It avoids explicit storage of the large sparse matrix $W$ by implicitly computing matrix-vector products via ray marching [S1].

## How it works
**Inputs:**
- Target images $o$ (observation pixels) [S1].
- Initial volume estimate $a$ (stored in 3D textures) [S1].
- Camera poses and intrinsics [S1].
- Optional: Per-pixel constraint weights, visual hull masks, regularization weights [S1].

**Outputs:**
- Reconstructed volume properties $a$ (albedo, emission, extinction) in 3D textures [S1].

**Data Structures:**
- **Volume Properties ($a$):** Stored in 3D textures representing vectors [S1]. Fields correspond to albedo, emission, and extinction [S1]. Precision can be 16-bit to reduce bandwidth [S1].
- **Target Images ($o$):** 2D textures or buffers [S1].
- **Residual ($c$):** 2D buffer storing $Wa - o$ [S1].
- **Gradient/Direction Vectors:** 3D textures for volume updates [S1].

**Formulas:**
The objective is to minimize the quadratic error function:
$$ E(a) = ||Wa - o||^2 $$
With regularization terms $\Omega(a)$:
$$ E_{reg}(a) = ||Wa - o||^2 + \lambda_L ||La||^2 + \lambda_0 ||a||^2 + \lambda_1 ||a - 1||^2 $$
Where:
- $W$ is the sparse rendering matrix [S1].
- $L$ is the Laplacian operator [S1].
- $\lambda_L, \lambda_0, \lambda_1$ are user-defined weights (typically weak, e.g., $2^{-9}$) [S1].
- Constraint weights $w_p$ are applied per pixel by multiplying the residual vector: minimize $|| (Wa - o) \odot w_p ||^2$ [S1].

**Numbered Steps:**
1. **Initialization:** Initialize $a$ (e.g., zeros or previous estimate) [G]. Compute initial gradient $g_0 = W^T(Wa_0 - o)$ [G]. Set search direction $p_0 = -g_0$ [G].
2. **Iteration Loop:** For $k = 0, 1, \dots$ until convergence:
    a. **Forward Pass ($Wp_k$):** Render the volume with properties $p_k$ to generate an image via ray marching [S1].
    b. **Back-Projection ($W^T(Wp_k)$):** Distribute the rendered image back to the volume voxels via ray marching with accumulation [S1].
    c. **Step Size:** Compute $\alpha_k = \frac{p_k^T p_k}{p_k^T W^T W p_k}$ [G].
    d. **Update Solution:** $a_{k+1} = a_k + \alpha_k p_k$ [G].
    e. **Update Residual:** $g_{k+1} = g_k + \alpha_k W^T W p_k$ [G].
    f. **Convergence Check:** If $||g_{k+1}|| < \epsilon$, stop [G].
    g. **Beta:** Compute $\beta_k = \frac{g_{k+1}^T g_{k+1}}{g_k^T g_k}$ [G].
    h. **Update Direction:** $p_{k+1} = g_{k+1} + \beta_k p_k$ [G].

**Pseudocode:**
The core operations are implemented as shaders [S1]. The unified ray marching loop handles both forward (rendering) and backward (back-projection) passes [S1].

```python
def solve_volume_cg(target_images, initial_volume, max_iter=100, tol=1e-6):
    a = initial_volume.copy()
    # Compute initial gradient: g = W^T(Wa - o)
    Wa = ray_march_forward(a)
    residual_img = Wa - target_images
    g = ray_march_backward(residual_img)
    p = -g.copy()
    p_dot_p = dot_product(p, p)
    
    for k in range(max_iter):
        if p_dot_p < tol:
            break
        # Compute W^T(W*p)
        Wp = ray_march_forward(p)
        WTWp = ray_march_backward(Wp)
        p_dot_WTWp = dot_product(p, WTWp)
        if p_dot_WTWp == 0:
            break
        alpha = p_dot_p / p_dot_WTWp
        a = a + alpha * p
        g = g + alpha * WTWp
        new_p_dot_p = dot_product(g, g)
        if new_p_dot_p < tol:
            break
        beta = new_p_dot_p / p_dot_p
        p = g + beta * p
        p_dot_p = new_p_dot_p
    return a

def ray_march_forward(volume_properties):
    output_image = zeros_like(target_image_shape)
    for pixel in all_pixels:
        ray = get_camera_ray(pixel)
        accumulated_transmittance = 1.0
        accumulated_radiance = 0.0
        t_min, t_max = ray.intersect_volume()
        t = t_min
        while t < t_max:
            position = ray.origin + t * ray.direction
            emission = texture_read_3d(volume_properties.emission, position)
            extinction = texture_read_3d(volume_properties.extinction, position)
            weight = accumulated_transmittance * (1.0 - exp(-extinction))
            accumulated_radiance += weight * emission
            accumulated_transmittance *= exp(-extinction)
            t += ray.step_size
        output_image[pixel] = accumulated_radiance
    return output_image

def ray_march_backward(image_residual):
    volume_gradient = zeros_like(volume_properties)
    # Interleaved 6x6 pattern to avoid synchronization stalls from data scattering [S1]
    # Process pixels in blocks, advancing by 6 each round to minimize conflicts [S1]
    for offset_y in range(6):
        for offset_x in range(6):
            for y in range(offset_y, height, 6):
                for x in range(offset_x, width, 6):
                    pixel = (x, y)
                    ray = get_camera_ray(pixel)
                    residual = image_residual[pixel]
                    accumulated_back_proj = 0.0
                    accumulated_transmittance = 1.0
                    t_min, t_max = ray.intersect_volume()
                    t = t_min
                    while t < t_max:
                        position = ray.origin + t * ray.direction
                        extinction = texture_read_3d(volume_properties.extinction, position)
                        weight = accumulated_transmittance * (1.0 - exp(-extinction))
                        accumulated_back_proj += weight * residual
                        accumulated_transmittance *= exp(-extinction)
                        t += ray.step_size
                    texture_write_add_3d(volume_gradient, position, accumulated_back_proj)
    return volume_gradient

def dot_product(u, v):
    return sum(u[i] * v[i] for i in range(len(u)))
def texture_read_3d(tex, pos):
    return tex.sample(pos)
def texture_write_add_3d(tex, pos, val):
    tex[pos] = tex[pos] + val
def zeros_like(shape):
    return [0.0] * shape
def get_camera_ray(pixel):
    return CameraRay(pixel, intrinsics, extrinsics)
```

**Edge Cases and Pitfalls:**
- **Synchronization Stalls:** Data scattering during back-projection (texture writes) causes stalls because neighboring rays write to the same voxels [S1].
- **Precision:** Use 16-bit textures instead of 32-bit to reduce bandwidth and speed up computation by ~25% [S1].
- **Resolution Mismatch:** Albedo and emission can use lower resolution than extinction to accelerate computation and reduce memory, though this may affect quality [S1].
- **Refractive Rays:** For non-constant refractive indices, use arbitrary integration curves computed via Euler forward scheme [S1].
- **Visual Hulls:** Limit solution domain to voxels with non-zero extinction (for albedo/emission) or user-defined masks (for extinction) to improve quality and performance [S1].

## Operating characteristics
- **Time Complexity:** Depends on the number of CG iterations and the cost of ray marching per iteration [S1].
- **Memory Complexity:** $O(N_v)$ for volume storage, where $N_v$ is the number of voxels [S1].
- **Performance:** 16-bit textures provide ~25% speedup. Interleaved pixel pattern provides ~10% speedup by reducing synchronization stalls [S1].
- **Strengths:** Handles large sparse systems without explicit matrix storage. Flexible regularization. Supports refraction and visual hulls [S1].
- **Limitations:** Ill-conditioned systems may require careful regularization. Synchronization issues in back-projection can limit parallel efficiency [S1].
- **When to Use:** When reconstructing volume properties from multiple views and explicit matrix storage is infeasible [S1].
- **When Not to Use:** When high precision is critical and 16-bit textures are insufficient [S1].

## Background
This method was introduced in "Property and Lighting Manipulations for Static Volume Stylization Using a Painting Metaphor" (2014) [S1]. It builds on the linearity of light transport and the sparsity of the rendering operator [S1]. The use of Conjugate Gradient for volume reconstruction allows for efficient optimization of volume properties without the memory overhead of direct matrix inversion [S1].
