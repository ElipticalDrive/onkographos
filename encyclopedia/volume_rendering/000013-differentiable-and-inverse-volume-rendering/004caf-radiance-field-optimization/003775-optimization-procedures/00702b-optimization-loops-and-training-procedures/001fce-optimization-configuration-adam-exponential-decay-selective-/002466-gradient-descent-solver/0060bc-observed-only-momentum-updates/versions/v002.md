# Observed-Only Momentum Updates

Also called: Observed Variable Updates, Sparse Momentum

## Overview
Observed-Only Momentum Updates is a modification to the Adam optimizer that restricts momentum and moment updates to variables receiving nonzero gradients in the current iteration, preventing noisy momentum from accumulating on unobserved variables [S1]. It differs from standard Adam by filtering updates based on direct observation rather than applying stochastic noise to all parameters [S1].

## How it works
**Inputs and Outputs:**
- Input: Current parameters $\theta$, first moment estimate $m$, second moment estimate $v$, learning rate $\alpha$, decay rates $\beta_1, \beta_2$, stability constant $\epsilon$, iteration count $t$, and gradient $g$ [G].
- Output: Updated parameters $\theta'$, updated moments $m', v'$ [G].

**Data Structures:**
- Parameters $\theta$, moments $m, v$, and gradient $g$: Tensors of identical shape, initialized to zero [G].

**Numbered Steps:**
1. Compute gradient $g$ for the current batch.
2. Identify observed indices $\mathcal{O} = \{ i \mid g_i \neq 0 \}$.
3. For $i \in \mathcal{O}$: update $m_i \leftarrow \beta_1 m_i + (1 - \beta_1) g_i$ and $v_i \leftarrow \beta_2 v_i + (1 - \beta_2) g_i^2$ [G].
4. For $i \in \mathcal{O}$: compute bias-corrected estimates $\hat{m}_i = m_i / (1 - \beta_1^t)$, $\hat{v}_i = v_i / (1 - \beta_2^t)$ [G].
5. For $i \in \mathcal{O}$: update $\theta_i \leftarrow \theta_i - \alpha \hat{m}_i / (\sqrt{\hat{v}_i} + \epsilon)$ [G].
6. For $j \notin \mathcal{O}$: leave $m_j, v_j, \theta_j$ unchanged [S1].

**Formulas:**
- Moment updates (observed $i$): $m_i^{(t)} = \beta_1 m_i^{(t-1)} + (1 - \beta_1) g_i^{(t)}$, $v_i^{(t)} = \beta_2 v_i^{(t-1)} + (1 - \beta_2) (g_i^{(t)})^2$.
- Parameter update (observed $i$): $\theta_i^{(t)} = \theta_i^{(t-1)} - \alpha \frac{\hat{m}_i^{(t)}}{\sqrt{\hat{v}_i^{(t)}} + \epsilon}$.
- Parameters: $\alpha$ (learning rate), $\beta_1, \beta_2$ (exponential decay rates), $\epsilon$ (numerical stability constant), $t$ (iteration count). Typical values are not given in the sources.

**Edge Cases and Pitfalls:**
- **Noisy Momentum Accumulation:** Without this method, Adam maintains moment estimates from previous iterations' stochastic noise, which remains fixed for unobserved variables and impedes convergence [S1].
- **Indirect Gradients:** In differentiable path tracing, gradients for indirectly observed parameters are extremely noisy due to low sampling probability of long light paths; restricting updates to directly observed variables mitigates this [S1].
- **Sparse Updates:** Variables not observed in a batch do not receive updates [S1].

**Pseudocode:**
```python
def observed_only_momentum_update(theta, m, v, g, alpha, beta1, beta2, epsilon, t):
    observed_mask = (g != 0)
    m[observed_mask] = beta1 * m[observed_mask] + (1 - beta1) * g[observed_mask]
    v[observed_mask] = beta2 * v[observed_mask] + (1 - beta2) * (g[observed_mask] ** 2)
    bias_correction1 = 1 - beta1 ** t
    bias_correction2 = 1 - beta2 ** t
    m_hat = m / bias_correction1
    v_hat = v / bias_correction2
    theta[observed_mask] = theta[observed_mask] - alpha * (m_hat[observed_mask] / (sqrt(v_hat[observed_mask]) + epsilon))
    return theta, m, v
```

## Subtopics

### Exponential Momentum Scaling Rule
A momentum scaling rule proposed to maintain high update cosine similarity and similar update magnitude when switching to larger training batch sizes in 3D Gaussian Splatting training [S2]. Compared to leaving momentum coefficients unchanged, the exponential momentum scaling rule keeps update cosine similarity higher across different training batch sizes [S2].

## Operating characteristics
- **Time Complexity:** $O(N)$ per iteration, where $N$ is the number of parameters, due to element-wise operations and masking [G].
- **Memory Complexity:** $O(N)$ for storing parameters and moments, identical to standard Adam [G].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Effectiveness depends on the sparsity of observed gradients [S1].
- **Strengths:** Reduces noise accumulation for unobserved variables, improving convergence in scenes with sparse observations or indirect lighting [S1].
- **Limitations:** May require more iterations to update all variables if observations are sparse [S1].
- **When to use:** Differentiable rendering with path tracing where indirect gradients are noisy and many variables are not directly observed per batch [S1].
- **When not to use:** Dense gradient scenarios where all variables are observed every step, or when masking overhead is prohibitive [G].

## Background
Originated in material and lighting reconstruction for complex indoor scenes using texture-space differentiable rendering [S1]. The method addresses noisy momentum accumulation in the Adam optimizer when applied to differentiable rendering, where not all parameters are observed in every batch due to light transport characteristics [S1].
