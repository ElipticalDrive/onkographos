# Optimization Loops and Training Procedures

Also called: Inverse Rendering Loop

## Overview
This family defines the iterative optimization procedures that embed a differentiable renderer within an optimizer to estimate scene parameters (pose, geometry, materials, illumination) from observed images or measurements [S1, unofficial]. It solves the inverse problem of recovering 3D scene properties by minimizing a photometric or physical loss between rendered outputs and ground-truth targets. It differs from its siblings by providing the general algorithmic skeleton—the evaluation of the forward operator, loss computation, and parameter update cycle—whereas specific articles detail the configuration (e.g., [Optimization Configuration (Adam + Exponential Decay + Selective L2)](2133-optimization-configuration-adam-exponential-decay-selective-.md)), the specific loss functions (e.g., [Photometric Reconstruction Loss](7799-photometric-reconstruction-loss.md)), or specialized strategies like [Staged and Alternating Optimization](12945-staged-and-alternating-optimization.md).

## Shared principles
All methods in this family rely on the differentiability of the forward rendering operator and the propagation of gradients through the integration steps [44-radiance-field-optimization.md]. The core mechanism is the evaluation of the volume rendering equation and the computation of gradients with respect to scene parameters (density, geometry, transfer functions, camera poses) [44-radiance-field-optimization.md].

The standard emission-absorption model computes the color $\hat{C}(\mathbf{r})$ for a ray $\mathbf{r}$ as [44-radiance-field-optimization.md]:

$$
\hat{C}(\mathbf{r}) = \sum_{i=1}^N T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i
$$

where $\sigma_i$ is the density, $\delta_i$ is the step size, $\mathbf{c}_i$ is the color, and $T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right)$ is the transmittance [44-radiance-field-optimization.md].

Differentiation strategies fall into three main categories [44-radiance-field-optimization.md]:
1. **Reverse-Mode Automatic Differentiation (AD):** Standard backpropagation through the computational graph. This requires storing $O(kn)$ intermediate states (where $n$ is pixels and $k$ is samples), leading to high memory usage [44-radiance-field-optimization.md].
2. **Adjoint Method:** Computes gradients by propagating adjoint variables backward through the rendering algorithm, evaluating the chain rule from output to input. This has computational complexity largely constant in the number of parameters, making it preferable for optimizing many parameters like the transfer function [44-radiance-field-optimization.md].
3. **Analytic Inversion / Explicit Gradients:** Uses a-priori knowledge of the DVR operations to invert the order of operations or derive closed-form gradients, reducing memory consumption to $O(n)$ by avoiding the storage of intermediate results [44-radiance-field-optimization.md].

## Subtopics

### [NeRF Training Loop](970-nerf-training-loop.md)
The standard stochastic gradient descent cycle for coordinate-based neural radiance fields, defining ray sampling, differentiable volume rendering, and weight updates.

### [Optimization Configuration (Adam + Exponential Decay + Selective L2)](2133-optimization-configuration-adam-exponential-decay-selective-.md)
Specifies the optimizer settings, learning rate schedule, and selective L2 regularization used to prevent divergence in position encodings and appearance embeddings.

### [Neural Volume Rendering Training (MSE)](3429-neural-volume-rendering-training-mse.md)
Defines the core optimization loop for NeRFs using MSE loss, with explicit strategies like Hierarchical Geometric Guidance (HGG) and Hierarchical Photometric Guidance (HPG) to mitigate depth-supervision bias.

### [Optimization Baselines](6675-optimization-baselines.md)
Black-box optimization strategies (e.g., CMA-ES) that treat the renderer as an opaque function, using population-based search distributions to minimize photometric loss without explicit gradients.

### [DressiAD Optimization Loop](10728-dressiad-optimization-loop.md)
A define-and-run differentiable rendering loop that packs the backward pass into Vulkan command buffers, executing optimization directly on the GPU to avoid CPU-side backpropagation overhead.

### [Phase-Aware Gradient Descent (PAGD)](12876-phase-aware-gradient-descent-pagd.md)
An optimization algorithm for encoding complex wave fields into phase-only holograms, using phase information to reduce ringing artifacts and capture directional light field information.

### [Training & Optimization Protocol](12939-training-optimization-protocol.md)
A protocol for decomposed Gaussian splatting (DeSplat) that separates scene representation into static geometry and dynamic distractor points, using specialized learning rate schedules for geometric vs. appearance parameters.

### [Staged and Alternating Optimization](12945-staged-and-alternating-optimization.md)
Addresses instability in jointly optimizing complex scene parameters by decoupling the problem into sequential phases (e.g., coarse geometry then fine materials) to stabilize gradient descent.

### [Genetic Algorithm Optimization](13247-genetic-algorithm-optimization.md)
A stochastic search method for Direct Volume Rendering Images (DVRIs) that treats opacity seed values as discrete variables, evolving a population to guarantee visibility of specific structures without relying on gradients.

### [Temporal Optimization Heuristics](13688-temporal-optimization-heuristics.md)
Models dynamic content in differentiable bitmap primitive (DiffBMP) rendering by applying warm-starting, removing stuck primitives, and freezing unchanged regions to balance per-frame fidelity and temporal anti-flicker.

### 4DGS Baseline Implementation
A specific training protocol for 4D Gaussian Splatting (4DGS) on multi-view videos. It optimizes the first frame for 3,000 iterations, then optimizes the full multi-view video sequence for 14,000 iterations [S2].

### Geometry Focused Model Optimization
An initial stage in Reflective Gaussian Splatting where the rendering equation is applied directly to each Gaussian primitive to compute outgoing radiance using its material and geometry properties, then alpha-blended during rasterization. This stabilizes gradient transfer to geometry in the initial phase, avoiding convergence challenges caused by pixel-level shading disturbing gradient directions [S3, unofficial].

### Continuous Coarse-To-Fine Optimization
A progressive optimization strategy that avoids shape-radiance ambiguity by restricting the Level of Detail (LOD) to coarse levels initially, then relaxing this regularization to recover scene details. It operates continuously in LOD space rather than discretely [S4, unofficial]. During cone casting, samples' LOD are clamped up to a maximal LOD $L$. Grids of level $L + 1$ and above are set to zero and not optimized. The maximal LOD $L$ is updated per epoch using the linear scheduler: $L = (L_0 + n / n_{ctf}) \in \mathbb{R}^+$, where $n$ is the current epoch, $n_{ctf}$ is a hyperparameter describing the speed of the process, and $L_0$ defines the number of used grids at initialization [S4, unofficial]. Unlike I-NGP-based architectures, this method keeps supervising all decoder latent space dimensions; adding new grid levels only adds degrees of freedom for the mapping function without modifying decoder weights or previously trained grids [S4, unofficial].

### Shape-from-Projections Optimization Pipeline
An iterative optimization pipeline that initializes a mesh, refines it through subdivision and mesh cleaning, runs differentiable rendering optimization, and saves results [S5, unofficial]. Steps include: loading the dataset and computing physical dimensions; initializing the mesh via `save_init_mesh`; if `args.niter0 > 0`, running a coarse refinement loop (create `Model`, estimate/set initial `mu`, run `optimize.run`, extract vertices/faces/labels, update `mus`, save subdivided mesh, clean with `pymeshfix` and `manifold` tool); and running final optimization with `args.niter` iterations [S5, unofficial]. Parameters include `args.niter0` (coarse refinement iterations), `args.niter` (final optimization iterations), `args.nmu0` (initial attenuation values), `args.wlap`, `args.wflat` (regularization weights), and `args.subdiv` (subdivision level) [S5, unofficial]. A pitfall is that mesh cleaning uses external `pymeshfix` and `manifold` executables, where `manifold` requires `outresolution` from the first refinement pass, and `pymeshfix` cleans with `max_iters=10, inner_loops=3` [S5, unofficial].

## Background
The concept of using differentiable renderers within optimizers to solve inverse problems has been a central theme in computer graphics and vision. The loop is conceptually simple: initialize parameters, trace rays, compute loss, backpropagate, and update [S1, unofficial]. However, choosing a faithful model, identifiable parameters, a stable estimator, and a good initialization remains difficult [S1, unofficial]. The field has evolved from basic volume rendering optimization [44-radiance-field-optimization.md] to complex staged optimizations [12945-staged-and-alternating-optimization.md], black-box baselines [6675-optimization-baselines.md], and specialized hardware-aware loops like DressiAD [10728-dressiad-optimization-loop.md].
