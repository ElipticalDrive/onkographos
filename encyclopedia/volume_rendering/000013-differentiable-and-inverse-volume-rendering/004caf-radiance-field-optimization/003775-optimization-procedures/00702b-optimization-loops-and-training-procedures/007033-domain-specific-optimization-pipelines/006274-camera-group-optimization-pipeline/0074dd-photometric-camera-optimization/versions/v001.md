# Photometric Camera Optimization
Also called: Direct photometric objective
## Overview
Photometric Camera Optimization refines camera poses and focal lengths by minimizing a direct photometric objective between rendered and observed RGB images [S1, unofficial]. It distinguishes itself from pose-only methods by jointly optimizing focal parameters and employing robust kernels to regularize updates around initialized values, ensuring stable convergence in differentiable volume rendering [S1, unofficial].
## How it works
**Inputs and Outputs:**
- **Inputs:** Rendered image $\mathbf{C}$, observed RGB image $\mathbf{C}^*$, current camera pose correction $\boldsymbol{\xi}$, current focal length error state $\boldsymbol{\phi}_f$, regularization weights $\lambda_\xi, \lambda_f$, and the color loss function $\mathcal{L}_{\text{rgb}}$ [S1, unofficial].
- **Outputs:** Updated camera parameters (pose and focal length) that minimize $\mathcal{L}_{\text{cam}}$ [S1, unofficial].

**Data Structures:**
- Camera parameters are stored as error states relative to initialized values.
- Focal length $\mathbf{f}$ is parameterized in log-space:
  $$ \log \mathbf{f} = \log \mathbf{f}^{(0)} + \boldsymbol{\phi}_f \quad (21) $$
  where $\mathbf{f}^{(0)}$ is the initial focal length and $\boldsymbol{\phi}_f$ is the learnable error state [S1, unofficial].
- Pose is updated via a correction vector $\boldsymbol{\xi}$ [S1, unofficial].

**Numbered Steps:**
1. Compute the rendered image $\mathbf{C}$ using the current differentiable volume renderer and current camera parameters (pose and focal length) [S1, unofficial].
2. Calculate the color loss $\mathcal{L}_{\text{rgb}}(\mathbf{C}, \mathbf{C}^*)$ between the rendered image and the observed image [S1, unofficial].
3. Compute the total photometric loss:
   $$ \mathcal{L}_{\text{cam}} = \mathcal{L}_{\text{rgb}}(\mathbf{C}, \mathbf{C}^*) + \lambda_\xi \rho_\xi(\boldsymbol{\xi}) + \lambda_f \rho_f(\boldsymbol{\phi}_f) \quad (22) $$
   where $\rho_\xi$ and $\rho_f$ are robust kernels (e.g., Huber or Geman-McClure) that regularize the pose correction $\boldsymbol{\xi}$ and focal update $\boldsymbol{\phi}_f$ around their initialized values [S1, unofficial].
4. Backpropagate the loss $\mathcal{L}_{\text{cam}}$ through the differentiable rendering pipeline to compute gradients with respect to $\boldsymbol{\xi}$ and $\boldsymbol{\phi}_f$ [S1, unofficial].
5. Update $\boldsymbol{\xi}$ and $\boldsymbol{\phi}_f$ using an optimizer (e.g., Adam) [S1, unofficial].
6. Update the camera pose and focal length based on the new error states [S1, unofficial].

**Formulas:**
- **Focal Length Parameterization:**
  $$ \log \mathbf{f} = \log \mathbf{f}^{(0)} + \boldsymbol{\phi}_f \quad (21) $$
  [S1, unofficial]
- **Photometric Loss:**
  $$ \mathcal{L}_{\text{cam}} = \mathcal{L}_{\text{rgb}}(\mathbf{C}, \mathbf{C}^*) + \lambda_\xi \rho_\xi(\boldsymbol{\xi}) + \lambda_f \rho_f(\boldsymbol{\phi}_f) \quad (22) $$
  [S1, unofficial]
- **Ray Direction:** For a pinhole pixel $(u, v)$, the camera-space ray direction is:
  $$ \mathbf{r}^{\text{cam}} \propto \mathbf{K}^{-1} [u, v, 1]^\top $$
  where $\mathbf{K}$ is the camera intrinsic matrix [S1, unofficial].

**Parameters:**
- $\lambda_\xi$: Weight for pose regularization. Value not given in the sources.
- $\lambda_f$: Weight for focal length regularization. Value not given in the sources.
- $\rho_\xi, \rho_f$: Robust kernels. Specific kernel type not given in the sources, but cited as regularizing around initialized values [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Vanishing Gradients:** The vertex-interpolated DC SH component varies continuously within each voxel and across faces shared by voxels, ensuring the photometric gradient does not vanish inside the voxels [S1, unofficial].
- **Large Deviations:** Robust kernels are used to prevent large, unstable updates if the initial camera parameters are far from the ground truth [S1, unofficial].

**Pseudocode:**
```python
def photometric_camera_optimization(rendered_image, observed_image, 
                                    current_pose_correction, current_focal_error,
                                    lambda_pose, lambda_focal, robust_kernel_pose, 
                                    robust_kernel_focal, color_loss_fn, optimizer):
    """
    Optimizes camera pose and focal length using photometric loss.
    
    Args:
        rendered_image: Tensor of shape (H, W, 3), rendered image C.
        observed_image: Tensor of shape (H, W, 3), observed RGB image C*.
        current_pose_correction: Tensor of pose error state xi.
        current_focal_error: Tensor of focal error state phi_f.
        lambda_pose: Scalar weight for pose regularization.
        lambda_focal: Scalar weight for focal regularization.
        robust_kernel_pose: Function rho_xi for pose regularization.
        robust_kernel_focal: Function rho_f for focal regularization.
        color_loss_fn: Function L_rgb for color loss.
        optimizer: Optimizer instance for updating parameters.
        
    Returns:
        Updated pose correction and focal error.
    """
    # Compute color loss
    l_rgb = color_loss_fn(rendered_image, observed_image)
    
    # Compute regularization losses
    l_pose_reg = lambda_pose * robust_kernel_pose(current_pose_correction)
    l_focal_reg = lambda_focal * robust_kernel_focal(current_focal_error)
    
    # Total loss
    l_cam = l_rgb + l_pose_reg + l_focal_reg
    
    # Backpropagate
    l_cam.backward()
    
    # Update parameters
    optimizer.step()
    optimizer.zero_grad()
    
    return current_pose_correction, current_focal_error
```
[G] The pseudocode assumes standard PyTorch-like autograd mechanics. The `robust_kernel` functions are assumed to be differentiable. The `color_loss_fn` is assumed to be defined elsewhere (e.g., L1 or L2 loss). The `optimizer` is assumed to have been initialized with the parameters to be optimized.

## Subtopics

### Alternating Optimization Schedule
This schedule alternates between updating the map parameters and updating the camera parameters [S1, unofficial]. During map updates, camera parameters are held fixed, and the voxel field is trained [S1, unofficial]. Camera optimization runs on the same fixed period as voxel adaptation [S1, unofficial]. At each camera-optimization round, the map is frozen, and cameras sampled within the next voxel-adaptation interval are collected [S1, unofficial]. This look-ahead set is optimized for a small number of steps [S1, unofficial]. Updated camera parameters are rolled back if they do not reduce the color loss $\mathcal{L}_{\text{rgb}}$ [S1, unofficial]. Optimized camera parameters are then reused in subsequent map-training iterations [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Not given in the sources.
- **Strengths:** Ensures gradient continuity via vertex-interpolated DC SH components, preventing vanishing gradients [S1, unofficial]. Robust kernels provide stability against large initial errors [S1, unofficial].
- **Limitations:** Requires differentiable rendering [S1, unofficial]. Alternating schedule adds complexity to the training loop [S1, unofficial].
- **When to use:** When accurate camera poses and focal lengths are needed for geometrically consistent volume rendering [S1, unofficial].
- **When not to use:** When camera parameters are known and fixed, or when computational resources are extremely limited [S1, unofficial].

## Background
Originated in the SpaRV (Sparse Radiance Voxels) framework for scalable geometrically consistent LiDAR-Visual Mapping and Rendering [S1, unofficial]. The method leverages differentiable rendering to optimize camera parameters jointly with the radiance field [S1, unofficial].
