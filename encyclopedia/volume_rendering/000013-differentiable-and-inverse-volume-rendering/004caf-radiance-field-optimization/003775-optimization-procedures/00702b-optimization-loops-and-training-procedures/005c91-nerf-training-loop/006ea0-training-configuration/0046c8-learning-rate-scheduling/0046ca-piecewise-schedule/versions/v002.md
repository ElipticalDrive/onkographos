# Piecewise Schedule
## Overview
A learning rate scheduling method that composes multiple sub-schedules applied sequentially at specified milestone steps [S1, unofficial]. It differs from continuous decay schedules like [Exponential Decay Schedules](18486-exponential-decay-schedules.md) by allowing abrupt behavioral changes at discrete boundaries, and from [Annealing Schedules](11839-annealing-schedules.md) by its explicit modular composition of independent schedule objects rather than a single parametric function [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A global training step index $t$ (integer $\ge 0$).
- Output: A scalar learning rate value $lr$.

**Data Structures:**
The schedule object maintains two primary fields:
1. `schedules`: A list of `Schedule` objects. Each object implements a method `get(step_offset)` that returns a learning rate for a local step offset [S1, unofficial].
2. `milestones`: A 1D array of integers representing cumulative step counts. `milestones[i]` is the global step index where `schedules[i]` begins [S1, unofficial].

**Numbered Steps:**
1. **Initialization:** Construct the `schedules` list and the `milestones` array from configuration [S1, unofficial].
2. **Lookup:** Given a global step $t$:
   a. Find the index $idx$ such that `milestones[idx]` is the insertion point for $t$ using binary search [S1, unofficial].
   b. Determine the base step for the current sub-schedule: if $idx \ge 1$, the base step is `milestones[idx - 1]`; otherwise, it is $0$ [S1, unofficial].
   c. Calculate the local step offset: $t_{\text{local}} = t - \text{base\_step}$ [S1, unofficial].
   d. Retrieve the learning rate from the selected sub-schedule: $lr = \text{schedules}[idx].\text{get}(t_{\text{local}})$ [S1, unofficial].

**Formulas:**
- $t_{\text{local}} = t - \text{base\_step}$, where $t$ is the global step, $\text{base\_step}$ is the cumulative step count where the current sub-schedule begins, and $t_{\text{local}}$ is the offset passed to the sub-schedule [S1, unofficial].

**Parameters:**
- Typical values are not specified in the sources. The learning rate values are defined by the individual sub-schedules [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Milestone Alignment:** The `milestones` array must be strictly increasing and sorted [S1, unofficial].
- **Step Boundaries:** The implementation uses `side='right'` in `searchsorted`, meaning if $t$ equals `milestones[i]`, the returned index is $i+1$, selecting `schedules[i+1]` for that step [S1, unofficial].
- **Precision:** Steps are integers, avoiding floating-point precision issues in step calculation [G].

**Pseudocode:**
```python
import jax.numpy as jnp

class PiecewiseSchedule:
    def __init__(self, schedules, milestones):
        self.schedules = schedules
        self.milestones = jnp.array(milestones)

    def get(self, step):
        idx = jnp.searchsorted(self.milestones, step, side='right')
        schedule = self.schedules[idx]
        base_idx = self.milestones[idx - 1] if idx >= 1 else 0
        return schedule.get(step - base_idx)
```

## Subtopics

### Two-Phase Training Schedule
A specific application of piecewise scheduling for light field compression networks, consisting of a training phase and a quantization phase [S2]. Both phases use a constant learning rate of $0.01$ [S2]. The training phase lasts $12$ epochs, where one epoch is defined as all Sampled Aperture Images (SAIs) being used $500$ times, with $5$ SAIs fed per iteration to calculate averaged loss [S2]. The quantization stage defines one epoch as all SAIs involved $200$ times, followed by fine-tuning all consecutive layers for $1$ epoch after quantizing each layer [S2]. Hardware: Single Nvidia Titan RTX GPU with $24$GB memory; Framework: PyTorch [S2].

## Operating characteristics
- **Time Complexity:** $O(\log N)$ per step lookup, where $N$ is the number of sub-schedules, due to binary search on milestones [S1, unofficial].
- **Memory Complexity:** $O(N)$ to store the milestones array and references to sub-schedules [S1, unofficial].
- **Strengths:** Modular design allows mixing different schedule types [S1, unofficial].
- **Limitations:** Requires careful tuning of milestone boundaries. Discontinuities in learning rate can occur if sub-schedules do not align at boundaries [G].
- **When to use:** When training requires distinct phases with different optimization behaviors [S1, unofficial].

## Background
The piecewise schedule structure is implemented in the Nerfies project, a JAX-based implementation of NeRF [S1, unofficial]. It provides a flexible way to manage learning rates in complex training loops [S1, unofficial]. The two-phase schedule configuration is used in light field compression research [S2].
