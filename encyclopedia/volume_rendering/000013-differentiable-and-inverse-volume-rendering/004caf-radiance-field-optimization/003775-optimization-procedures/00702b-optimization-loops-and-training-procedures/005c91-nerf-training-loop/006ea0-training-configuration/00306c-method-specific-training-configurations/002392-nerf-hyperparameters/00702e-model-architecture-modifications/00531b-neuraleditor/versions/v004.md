# NeuralEditor

Also called: NeuralEditor: Editing Neural Radiance Fields via Manipulating Point Clouds

## Overview
NeuralEditor is a method for editing neural radiance fields (NeRFs) by exploiting an explicit point cloud representation as the underlying structural basis for the implicit field [S1]. Unlike traditional NeRFs that lack native shape-editing capabilities, or mesh-based editing methods that separate mesh optimization from NeRF modeling, NeuralEditor intrinsically integrates point clouds with the NeRF architecture [S1]. This allows users to manipulate scene geometry by moving points in the cloud and re-plotting the resulting radiance field, supporting both zero-shot inference and fast fine-tuning [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of multi-view images of a scene; optionally, a target point cloud or editing instructions for shape deformation/morphing.
*   **Output:** A trained NeuralEditor model capable of rendering novel views and a precise 3D point cloud representing the scene geometry. The model supports editing by outputting rendered images from modified point cloud configurations.

**Data Structures:**
1.  **Point Cloud ($\mathcal{P}$):** A set of 3D points $\mathbf{p}_i \in \mathbb{R}^3$. Each point stores position, color, and normal vector $\mathbf{n}_i$.
2.  **K-D Tree:** A spatial data structure built over $\mathcal{P}$ to facilitate efficient neighbor search and voxel construction.
3.  **Density-Adaptive Voxels:** Volumes defined by the K-D tree structure, where density is adapted based on point distribution.
4.  **NeRF Model ($F_\Theta$):** A neural network that takes spatial coordinates $\mathbf{x}$ and viewing direction $\mathbf{d}$ as input. It outputs volume density $\sigma$ and color $\mathbf{c}$. The color is decomposed into diffuse and specular components using the Phong reflection model.

**Numbered Steps:**

1.  **Point Cloud-Guided NeRF Construction:**
    *   Initialize a point cloud $\mathcal{P}$ from the input images (e.g., via Structure-from-Motion or optimization).
    *   Build a K-D tree over $\mathcal{P}$ to organize spatial data [S1].
    *   Construct density-adaptive voxels using the K-D tree to guide the sampling and integration process [S1].

2.  **Rendering with Deterministic Integration:**
    *   For a camera ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$, sample points along the ray.
    *   Use the K-D tree to efficiently determine which voxels/points are intersected.
    *   Perform deterministic integration over the density-adaptive voxels to compute the final pixel color [S1]. This replaces stochastic sampling with a more stable, point-cloud-driven integration strategy.

3.  **Color Modeling with Phong Reflection:**
    *   The NeRF outputs color $\mathbf{c}$ using a Phong reflection model [S1]:
        $$ \mathbf{c} = \mathbf{c}_{diffuse} + \mathbf{c}_{specular} $$
    *   The specular component is calculated based on the view direction $\mathbf{d}$, light direction $\mathbf{l}$, and surface normal $\mathbf{n}$ (extracted from the point cloud geometry) [S1]. This decomposition enhances color fidelity and geometric detail representation.

4.  **Optimization:**
    *   Optimize the NeRF parameters $\Theta$, point positions, normals, and voxel densities by minimizing the difference between rendered images and ground truth images.
    *   A pruning and growing strategy is applied to the point cloud to maintain optimal density and structure [S1].

5.  **Shape Editing:**
    *   **Zero-Shot Inference:** To edit the shape, map the associated points in $\mathcal{P}$ to new positions $\mathcal{P}'$ (e.g., moving points to deform an object). Re-render the scene using the edited point cloud $\mathcal{P}'$ without retraining the NeRF weights [S1].
    *   **Fine-Tuning:** For higher visual quality and consistency with ambient lighting, perform fast fine-tuning of the NeRF parameters on the edited point cloud configuration [S1].

        :param view_dir: Viewing direction vector.
        :param normal: Surface normal vector.
        :param diffuse_color: Diffuse color component.
        :return: Final color vector.
        """
        # [G] Assume a single directional light source for simplicity
        light_dir = np.array([0.0, 1.0, 0.0])
        light_dir = light_dir / np.linalg.norm(light_dir)
        view_dir = view_dir / np.linalg.norm(view_dir)
        normal = normal / np.linalg.norm(normal)

        # Diffuse term
        diffuse = max(0, np.dot(normal, light_dir))
        diffuse_term = diffuse_color * diffuse

        # Specular term
        reflect_dir = 2 * np.dot(normal, light_dir) * normal - light_dir
        specular = max(0, np.dot(view_dir, reflect_dir)) ** 32 # Shininess = 32
        specular_color = np.array([1.0, 1.0, 1.0]) # White specular highlight
        specular_term = specular_color * specular

        return diffuse_term + specular_term

        """

        # [G] Find nearest point in point cloud to each sample to get normal
        normals = []
        for sample in samples:
            idx = self.kdtree.query_nearest(sample)
            normals.append(self.get_normal(idx))
            
        # 5. Apply Phong model and volume rendering accumulation
        final_color = np.array([0.0, 0.0, 0.0])

            final_color += weight * c_phong

**Edge Cases and Pitfalls:**
*   **Precision:** Traditional NeRFs lack user-adjustable shape editing capabilities, requiring complex space deformation or mesh conversion which may lack precision [S1]. NeuralEditor avoids this by using explicit point clouds.
*   **Boundary Conditions:** The deterministic integration strategy must handle ray-voxel intersections accurately to avoid artifacts [S1].
*   **Degenerate Input:** If the point cloud is sparse or noisy, normal estimation and density-adaptive voxel construction may fail, leading to poor rendering quality [S1].

## Operating characteristics
*   **Time Complexity:** Rendering time depends on the number of samples per ray and the efficiency of the K-D tree traversal. The K-D tree allows for efficient neighbor search and voxel intersection, improving stability and potentially speed compared to uniform sampling [S1].
*   **Memory Complexity:** Requires storing the point cloud, K-D tree, and NeRF parameters. The K-D tree adds overhead but enables density-adaptive structures [S1].
*   **Measured Performance:** NeuralEditor achieves state-of-the-art performance in shape deformation and scene morphing tasks [S1]. It supports zero-shot inference, which is computationally cheaper than retraining, and fast fine-tuning for enhanced quality [S1].
*   **Strengths:** Native shape editing via point manipulation; intrinsic integration of point clouds and NeRF; high-fidelity rendering with Phong shading; supports general scene editing operations difficult for mesh-based methods [S1].
*   **Limitations:** Relies on the quality of the initial point cloud; may require fine-tuning for perfect lighting consistency after editing [S1].
*   **When to Use:** When explicit shape editing of NeRFs is required, especially for general deformation and morphing tasks [S1].
*   **When Not to Use:** When high-quality texture synthesis without geometric editing is the primary goal, or when computational resources for K-D tree construction and maintenance are limited.

## Background
NeuralEditor was proposed by Jun-Kun Chen, Jipeng Lyu, and Yu-Xiong Wang from the University of Illinois at Urbana-Champaign and Peking University [S1]. It was presented at CVPR 2023 [S1]. The method addresses the fundamental challenge of editing the shape of scenes in NeRFs, which traditionally lack such capabilities [S1]. It builds on the insight that NeRF rendering can be interpreted as plotting a 3D point cloud to a 2D image plane [S1].
