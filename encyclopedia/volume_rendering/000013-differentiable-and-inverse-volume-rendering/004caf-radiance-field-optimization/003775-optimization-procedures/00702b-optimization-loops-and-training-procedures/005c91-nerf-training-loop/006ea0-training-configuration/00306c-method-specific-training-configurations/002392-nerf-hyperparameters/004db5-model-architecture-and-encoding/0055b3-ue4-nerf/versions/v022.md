# UE4-NeRF


## Overview
UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale 3D scenes, such as industrial parks and farmlands, by integrating Neural Radiance Fields (NeRF) with the Unreal Engine 4 (UE4) rasterization pipeline [S1]. It partitions large environments into sub-NeRFs, represents each partition using textured polygonal meshes initialized from regular octahedra, and utilizes a Level of Detail (LOD) hierarchy to maintain high frame rates at varying observation heights [S1]. Unlike Block-NeRF, which is limited to grid structures, UE4-NeRF supports diverse terrains including mountainous areas, and unlike Mobile-NeRF, it handles tilted surfaces and semi-transparent objects more effectively through continuous vertex optimization and texture-based opacity storage [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of posed images (e.g., drone-captured) with GPS metadata; camera intrinsics and extrinsics.
*   **Outputs:** Real-time rendered color images at 4K or 2K resolution; textured polygonal meshes for each scene block.

**Data Structures:**
1.  **Scene Partitioning:** The large scene is divided into blocks. Each training block is slightly larger than the corresponding physical area to create overlapping borders with neighbors for smooth transitions [S1].
2.  **Grid Initialization:** A $128 \times 128 \times 128$ 3D grid is initialized for each block [S1].
3.  **Mesh Representation:** Polygonal meshes are created by selecting the center point of each grid cell and its six neighbors (front, back, left, right, top, bottom) [S1]. To handle tilted surfaces, a regular octahedron with 20 faces (8 exterior, 12 interior) is used instead of the Mobile-NeRF approach [S1].
4.  **Texture Atlas:** Stores feature vectors and opacity information for the mesh vertices [S1].
5.  **Neural Network:**
    *   **Encoder:** 4-layer MLP. Dimensions: $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$. Inputs: Hash-encoded position. Outputs: Opacity ($\alpha$) and an 8-dimensional feature vector ($M_i$) [S1].
    *   **Decoder:** 3-layer MLP. Dimensions: $17 \times 16$, $16 \times 16$, $16 \times 3$. Inputs: Feature vector ($M_i$) and view direction encoding. Outputs: Final color ($\mathbf{c}_i$) [S1].
6.  **LOD Hierarchy:** Multiple levels of mesh detail are trained. Coarser meshes are used for higher observation heights to ensure real-time performance [S1].

**Coordinate System and Scaling:**
*   UE4 coordinate system: X-axis points East, Y-axis points South, Z-axis points Up [S1].
*   Scale: 100:1 (UE4 units to real-world units) [S1].

**Algorithm Steps:**

1.  **Preprocessing:**
    *   Transform GPS-captured image coordinates to the UE4 coordinate system and apply the 100:1 scale conversion [S1].
    *   Partition the scene into blocks. Train a coarse model for sub-region segmentation to capture terrain and building outlines. Filter images and apply masks to exclude pixels outside the scene area [S1].

2.  **Mesh Initialization:**
    *   Initialize a $128 \times 128 \times 128$ grid for the block [S1].
    *   Create polygonal meshes using the center point of each grid cell and its 6 neighbors [S1].
    *   Use regular octahedra (20 faces) to represent the geometry, addressing convergence issues on tilted surfaces [S1].

3.  **Training Loop (per block):**
    *   Initialize the Encoder and Decoder networks [S1].
    *   For each training iteration:
        *   Sample rays from camera origins to pixels: $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$, where $\mathbf{d} = (\theta, \phi)$ is the viewing direction [S1].
        *   Calculate ray intersections with the polygonal meshes to determine sampling points [S1].
        *   Encode the position $\mathbf{p}_i$ using multi-resolution hash encoding (from Instant-NGP) [S1].
        *   Compute opacity and feature vector via Encoder:
            $$ M_i, \alpha_i = E(\text{hash}(\mathbf{p}_i); \theta_E) $$
            where $E$ is the 4-layer MLP [S1].
        *   Encode the viewing direction $\mathbf{d}_i$ using spherical harmonics $SH(\mathbf{d}_i)$ [S1].
        *   Compute color via Decoder:
            $$ \mathbf{c}_i = D(M_i, SH(\mathbf{d}_i); \theta_D) $$
            where $D$ is the 3-layer MLP [S1].
        *   Optimize network parameters $\theta_E, \theta_D$ and vertex positions of the meshes using gradient descent [S1].
    *   Repeat for 80,000 epochs per block [S1].

4.  **Pre-rendering and Extraction:**
    *   Extract coarse polygonal meshes without textures during training [S1].
    *   Apply vertex optimization [S1].
    *   Encode texture maps in network outputs [S1].
    *   Extract pre-rendered polygonal meshes at different levels of detail (LOD) for the final rendering module [S1].

5.  **Real-time Rendering (UE4 Integration):**
    *   Implement the Decoder network as a High-Level Shading Language (HLSL) fragment shader in UE4 [S1].
    *   The shader takes feature vectors (from the texture atlas) as input and outputs colors [S1].
    *   Combine the extracted meshes with the UE4 rasterization pipeline [S1].
    *   Select the appropriate LOD mesh based on the camera's observation height [S1].
    *   Handle occlusion: If traditional 3D models (.obj, .fbx) are imported, UE4 automatically handles occlusion, skipping neural shader computation for occluded regions [S1].

**Pseudocode:**

```python
# UE4-NeRF Training and Rendering Logic

def initialize_scene(scene_data):
    """
    Preprocesses large-scale scene data.
    """
    # Coordinate transformation: X=East, Y=South, Z=Up, Scale 100:1
    transformed_images = []
    for img in scene_data.images:
        coords = transform_gps_to_ue4(img.gps_coords, scale=100.0, x_east=True, y_south=True)
        transformed_images.append(coords)
    
    # Partition scene into blocks with overlapping borders
    blocks = partition_scene(transformed_images, overlap=True)
    return blocks

def train_block(block_id, images, coarse_model):
    """
    Trains a single block's NeRF and mesh.
    """
    # Initialize 128x128x128 grid
    grid_size = 128
    grid = initialize_grid(grid_size)
    
    # Create polygonal meshes using center + 6 neighbors
    # Use regular octahedron (20 faces) for better convergence on tilted surfaces
    mesh = create_octahedral_mesh(grid)
    
    # Initialize Neural Networks
    # Encoder: 4-layer MLP (32->64->64->64->8)
    encoder = MLP(layers=[32, 64, 64, 64, 8])
    # Decoder: 3-layer MLP (17->16->16->3)
    # Input to decoder: 8 (features) + 9 (SH of view dir) = 17
    decoder = MLP(layers=[17, 16, 16, 3])
    
    # Multi-resolution hash encoding (Instant-NGP style)
    hash_encoder = MultiResolutionHashEncoder()
    
    # Training loop
    for epoch in range(80000):
        for image in images:
            # Filter images based on coarse model mask
            if not coarse_model.is_inside_mask(image):
                continue
                
            # Sample rays
            rays = sample_rays_from_image(image)
            
            # Intersect rays with mesh to get sampling points
            points = intersect_rays_with_mesh(rays, mesh)
            
            # Encode positions
            pos_features = hash_encoder.encode(points)
            
            # Encode view directions using Spherical Harmonics (SH)
            # Assuming SH degree 3 results in 9 coefficients
            view_dirs = get_view_directions(rays)
            sh_features = spherical_harmonics_encode(view_dirs, degree=3)
            
            # Forward pass Encoder
            # Input: pos_features (size depends on hash resolution, typically concatenated)
            # Note: The source specifies input dim 32 for encoder. 
            # This implies the hash encoding is projected or sampled to 32 dims.
            feature_vectors, opacities = encoder(pos_features)
            
            # Forward pass Decoder
            # Concatenate feature_vector (8) and SH_features (9) -> 17
            decoder_input = concatenate(feature_vectors, sh_features, dim=-1)
            colors = decoder(decoder_input)
            
            # Compute loss (e.g., MSE between rendered colors and image pixels)
            loss = compute_loss(colors, image.pixel_colors)
            
            # Backpropagate to update encoder, decoder, and mesh vertex positions
            update_parameters(encoder, decoder, mesh.vertices, loss)
            
    return mesh, encoder, decoder

def render_block(block_mesh, encoder, decoder, camera_pose, lod_level):
    """
    Renders a block using UE4 rasterization pipeline.
    """
    # Select LOD mesh based on camera height
    mesh = get_lod_mesh(block_mesh, lod_level)
    
    # Extract texture atlas (features and opacity) from trained mesh
    texture_atlas = extract_texture_atlas(mesh, encoder)
    
    # Deploy HLSL fragment shader in UE4
    # Shader input: Feature vectors from texture atlas
    # Shader output: Color
    shader = HLSLFragmentShader(decoder)
    
    # Rasterize mesh
    # UE4 handles occlusion with other 3D objects automatically
    rendered_image = rasterize(mesh, texture_atlas, shader, camera_pose)
    
    return rendered_image

def spherical_harmonics_encode(view_dirs, degree=3):
    """
    Encodes viewing direction into Spherical Harmonics coefficients.
    Degree 3 results in 9 coefficients (3*3 + 1? No, (l+1)^2 for l=0..3 is 1+4+9+16=30? 
    Source says 17 input to decoder: 8 features + 9 SH. 
    This implies degree 2 (1+4+4? No. Degree 2 is (2+1)^2 = 9 coefficients).
    """
    # Degree 2 SH has 9 coefficients
    return compute_sh_coefficients(view_dirs, degree=2)
```

**Parameters:**
*   **Grid Size:** $128 \times 128 \times 128$ [S1].
*   **Octahedron Faces:** 20 total (8 exterior, 12 interior) [S1].
*   **Encoder MLP:** 4 layers, dimensions $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
*   **Decoder MLP:** 3 layers, dimensions $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
*   **Training Hardware:** 1 Nvidia RTX 3090 GPU [S1].
*   **Training Iterations:** 80,000 epochs per block [S1].
*   **Coordinate System:** X=East, Y=South, Z=Up [S1].
*   **World Scale:** 100:1 [S1].

**Edge Cases and Pitfalls:**
*   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces; UE4-NeRF mitigates this with regular octahedra [S1].
*   **Semi-transparent Objects:** Mobile-NeRF fails on transparent/semi-transparent objects (water, glass) due to opacity binarization. UE4-NeRF stores opacity in texture maps, but semi-transparent objects (e.g., vegetation) increase computational overhead, reducing frame rates [S1].
*   **Pre-rendering Gaps:** Pre-rendering cannot capture rays from all viewing angles, potentially resulting in gaps or holes in the final scene [S1].
*   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, causing evaluation metrics (PSNR/SSIM/LPIPS) to underestimate actual reconstruction quality [S1].
*   **Memory Overhead:** Requires CUDA and NVIDIA GPUs. Rendering large scenes (square kilometers) incurs significant memory overhead, which increases with accuracy [S1].

## Operating characteristics
*   **Training Speed:** 1000× faster than Mobile-NeRF [S1].
*   **Training Time:** 40 minutes per block on 1×RTX 3090 [S1]. Total time for $n$ blocks: $1 \text{ hour} + (40 \text{ minutes} \times n/4)$ on 1×RTX 3090 [S1].
*   **Rendering Performance:** Real-time rendering at 4K resolution with up to 43 FPS [S1]. 50 FPS on full scene at 2K resolution; $\ge 70$ FPS on individual blocks at 2K resolution [S1].
*   **Memory:** Significant memory overhead for large scenes (square kilometers); increases with accuracy [S1].
*   **Strengths:** Real-time interactive rendering, handles large-scale diverse terrains (mountains, farmland), supports scene editing with traditional 3D models, handles semi-transparent objects better than Mobile-NeRF, avoids blurriness on natural scenes compared to Mip-NeRF [S1].
*   **Limitations:** Requires NVIDIA GPUs/CUDA, pre-rendering gaps/holes, exposure matching issues in UE4, semi-transparent objects reduce FPS [S1].
*   **When to use:** Large-scale outdoor scenes requiring real-time interaction and editing in UE4.
*   **When not to use:** Small-scale scenes where standard NeRF suffices, scenes requiring perfect ray-traced transparency without LOD artifacts, or environments without NVIDIA hardware.

## Background
UE4-NeRF was introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" [S1]. It addresses the limitations of NeRF in real-time rendering and large-scale scene representation. It builds on techniques from Mobile-NeRF (mesh-based representation), Block-NeRF (scene partitioning), and Instant-NGP (multi-resolution hash encoding) [S1]. It is used in Unreal Engine 4 for drone-captured large-scale scenes (Farmland, Construction site, Industrial parks) and evaluated on the Mega-NeRF public dataset [S1].
