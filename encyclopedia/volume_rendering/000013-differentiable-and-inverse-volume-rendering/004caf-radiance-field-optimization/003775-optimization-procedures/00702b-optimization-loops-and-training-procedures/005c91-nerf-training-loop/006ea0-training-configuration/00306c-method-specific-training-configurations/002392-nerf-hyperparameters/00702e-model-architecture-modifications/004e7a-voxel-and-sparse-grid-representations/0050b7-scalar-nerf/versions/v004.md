# SCALAR-NeRF

Also called: SCAlable LARge-scale Neural Radiance Fields for Scene Reconstruction

## Overview
SCALAR-NeRF is a coarse-to-fine framework for scalable large-scale neural scene reconstruction that structures the neural representation as an encoder-decoder architecture to avoid the 'foggy' issue in Block-NeRF and enable training on a single GPU [S1, unofficial]. It decomposes expansive scenes into manageable blocks, trains a shared decoder from a coarse global model, and fuses local results using the global model to avoid foggy reconstructions [S1, unofficial]. Unlike Block-NeRF, which blends images using an inverse distance weighting function causing foggy appearance when block centroids are close, SCALAR-NeRF fuses local block outputs with a reference image from the coarse global model [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A dataset of images capturing a large-scale scene.
*   **Outputs:** A set of local neural scene models and a coarse global model, fused to produce final rendered images.

**Data Structures:**
The method uses a multi-resolution hash table as the feature encoder, building on the principles of [Voxel and Sparse Grid Representations](13738-voxel-and-sparse-grid-representations.md).
*   **Hash Table:** A lookup table storing feature vectors. The source specifies a size of $2^{19}$ [S1, unofficial].
*   **Feature Embedding ($F$):** Concatenated from the multi-resolution hash table: $F = [f_1, \dots, f_L] \in \mathbb{R}^{L \cdot F}$, where $L$ is the number of levels and $F$ is the feature dimension [S1, unofficial].
*   **Decoder:** A shallow layer MLP that maps features to density and color: $\sigma, c = Decoder(F)$ [S1, unofficial].

**Numbered Steps:**

1.  **Train Coarse Global Model:** Train a global NeRF model on the entire image dataset using a multi-resolution hash table encoder and a shared decoder. This model serves as a reference for fusion and provides the initial decoder weights [S1, unofficial].
2.  **Partition Images:** Partition the training images into smaller blocks using KMeans clustering [S1, unofficial].
3.  **Scale Bounding Boxes:** Enhance overlapping regions across different blocks by scaling up the Axis-Aligned Bounding Box (AABB) of each local block. The scale factor $s_{\text{AABB}}$ controls the overlap. The optimal value found is 1.2 [S1, unofficial].
4.  **Initialize Local Models:** For each block, initialize a local model. The encoder is a multi-resolution hash table specific to that block. The decoder is **shared** from the coarse global model [S1, unofficial].
5.  **Train Local Models:** Train each local model. The shared decoder can be fixed (to eliminate saving its computational graph, enabling larger hash table sizes) or fine-tuned [S1, unofficial].
6.  **Fuse Results:** Synthesize images from each local block and fuse them with a reference image rendered from the coarse global model [S1, unofficial].

**Formulas:**
*   **Space Contraction:** For unbounded scenes, 3D points $\mathbf{x}$ are contracted using the method from Mip-NeRF360 [S1, unofficial]:
    $$
    \text{contract}(\mathbf{x}) = \begin{cases} \mathbf{x}, & \|\mathbf{x}\| \le 1, \\ \frac{\mathbf{x}}{2 - \frac{1}{\|\mathbf{x}\|}}, & \|\mathbf{x}\| > 1. \end{cases}
    $$
*   **Feature Encoding:** $F = \text{Encoder}(\mathbf{x})$, where $F = [f_1, \dots, f_L] \in \mathbb{R}^{L \cdot F}$ [S1, unofficial].
*   **Decoding:** $\sigma, c = \text{Decoder}(F)$ [S1, unofficial].

**Parameters:**
*   **Hash Table Size:** $2^{19}$ [S1, unofficial].
*   **AABB Scale Factor ($s_{\text{AABB}}$):** Controls overlap. Optimal value: 1.2 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** A too-large AABB scale factor damages reconstruction quality and increases the probability of hash collisions [S1, unofficial].
*   **Foggy Artifacts:** Using an inverse distance weighting (IDW) function for fusion performs worse than the global model and is unsuitable when blocks are close to each other [S1, unofficial].
*   **GPU Memory:** Simply increasing the hash table size slows down training and makes it infeasible to fit into a single GPU; splitting scenes into blocks allows finer details without increasing hash table size [S1, unofficial].

## Operating characteristics
*   **Time and Memory Complexity:** The method allows training on a single GPU by splitting the scene into blocks, avoiding the memory constraints of a single large hash table [S1, unofficial]. The hash table size is $2^{19}$, which is smaller than Block-NeRF and Instant-NGP ($2^{21}$), yet it surpasses them in performance [S1, unofficial].
*   **Measured Performance:** Evaluated on the Tanks and Temples dataset, SCALAR-NeRF outperforms Block-NeRF, NeRF, and Instant-NGP in PSNR, SSIM, and LPIPS [S1, unofficial].
*   **Strengths:** Scalability for large-scale scenes, avoidance of foggy artifacts, single-GPU training feasibility [S1, unofficial].
*   **Limitations:** Performance degrades if the AABB scale factor is too large (e.g., 1.3 vs 1.2) due to hash collisions [S1, unofficial]. IDW fusion is inferior to global model fusion [S1, unofficial].
*   **When to Use:** Large-scale scene reconstruction where single-GPU memory is a constraint and foggy artifacts from block blending are a concern.
*   **When Not to Use:** Small-scale scenes where a single global model suffices, or when blocks are very close together and IDW is used (SCALAR-NeRF's global fusion mitigates this, but IDW is not recommended).

## Background
SCALAR-NeRF was introduced by Yu Chen and Gim Hee Lee from the Department of Computer Science, National University of Singapore [S1, unofficial]. It was published on arXiv on November 28, 2023 [S1, unofficial]. The method addresses the limitations of Block-NeRF, which produces foggy images when block centroids are close, and the memory constraints of large hash tables in Instant-NGP [S1, unofficial]. It builds on the multi-resolution hash encoding from Instant-NGP and the space contraction from Mip-NeRF360 [S1, unofficial].
