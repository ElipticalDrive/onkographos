# Memory-Saving Ray Sampling

Also called: Full-Ray Training Optimization

## Overview
Memory-Saving Ray Sampling is a memory optimization technique that enables training neural radiance fields (NeRF) for stylization on all rays simultaneously, avoiding the need to downsample ray counts due to out-of-memory (OOM) constraints [S1]. Unlike sibling methods that may require sparse sampling or precomputed buffers, this approach allows full-resolution ray processing without degradation in stylization quality [S1]. It specifically addresses the trade-off where reducing sampled ray numbers to save memory increases noise and degrades results [S1].

## How it works
**Inputs and Outputs:**
- Input: A batch of rays covering the full image resolution ($W \times H$ rays) [G].
- Output: Rendered image and computed gradients for network optimization [G].

**Data Structures:**
- Exact layouts and sizes are not given in the sources [G]. Standard implementations store ray origins, directions, near/far bounds, and intermediate network activations per ray [G].

**Steps:**
1. Select an image from the training dataset and generate rays for every pixel at full resolution [G].
2. Process all rays simultaneously through the neural network to compute radiance and density [S1].
3. Render the image and compute the training loss [G].
4. Backpropagate gradients to update the model [G].

**Parameters:**
- Ray count: Equal to the total number of pixels in the source image ($W \times H$) [G].
- Typical values: Not specified in the sources [G].

**Edge cases and pitfalls:**
- OOM errors may occur if the system does not have sufficient VRAM to hold all intermediate activations for all rays [S1].
- Reducing ray counts to fit memory leads to increased noise and degraded stylization quality [S1].

**Pseudocode:**
```python
import math

def memory_saving_ray_sampling(ray_origins, ray_directions, near, far, nerf_forward, optimizer, target_image):
    # ray_origins: (N, 3), ray_directions: (N, 3), near/far: (N,)
    # Process all rays simultaneously (full resolution)
    num_rays = len(ray_origins)
    num_samples = 128  # Standard sampling density [G]
    
    # Sample points along all rays
    t_vals = [j / (num_samples - 1) for j in range(num_samples)]
    z_vals = [[near[i] + t * (far[i] - near[i]) for t in t_vals] for i in range(num_rays)]
    points = [[[ray_origins[i][d] + ray_directions[i][d] * z for d in range(3)] for z in z_vals[i]] for i in range(num_rays)]
    
    # Forward pass through network for all points
    densities, colors = nerf_forward(points)
    
    # Alpha compositing for all rays
    rendered_colors = []
    for i in range(num_rays):
        deltas = [z_vals[i][j+1] - z_vals[i][j] for j in range(num_samples - 1)]
        deltas.append(float('inf'))
        
        alpha = [1.0 - math.exp(-densities[i][j] * deltas[j]) for j in range(num_samples)]
        transmittance = 1.0
        final_color = [0.0, 0.0, 0.0]
        
        for j in range(num_samples):
            w = alpha[j] * transmittance
            final_color = [final_color[d] + w * colors[i][j][d] for d in range(3)]
            transmittance *= (1.0 - alpha[j] + 1e-10)
        
        rendered_colors.append(final_color)
    
    # Compute loss and backpropagate
    loss = sum((rendered_colors[i][d] - target_image[i][d])**2 for i in range(num_rays) for d in range(3)) / (3 * num_rays)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    
    return loss
```

## Subtopics

### Feature Vector Sampling for Memory Management
A strategy to prevent OOM errors during training by randomly sampling feature vectors instead of feeding all embeddings [S2]. For 3D embeddings with $F=8$, randomly sample 150K feature vectors $\theta_s$ per iteration [S2]. For 3D embeddings with $F=1, 2, 4$, randomly sample 200K feature vectors $\theta_s$ per iteration [S2]. For 2D embeddings, feed all embeddings together in one iteration without random sampling [S2]. This is used in conjunction with memory-saving techniques to manage VRAM usage [S2].

## Operating characteristics
- **Time Complexity:** Not given in the sources [G].
- **Memory Complexity:** Significantly reduced compared to naive full-batch training by avoiding OOM, but higher than sparse sampling methods [S1, S2].
- **Measured Performance:** In NeRF-Art, this method achieved better stylization quality than AvatarCLIP, which used sparse rays ($112 \times 112$) due to OOM constraints [S1].
- **Strengths:** Avoids noise from sparse sampling; enables full-resolution training [S1].
- **Limitations:** Requires high VRAM; may still require auxiliary strategies like feature vector sampling for very large scenes [S2].
- **When to use:** When VRAM allows full-ray processing and high-quality stylization is critical [S1].
- **When not:** When VRAM is severely limited and sparse sampling is unavoidable [S1].

## Background
Originated in the context of text-driven NeRF stylization, specifically in NeRF-Art [S1]. It was developed to overcome the limitations of methods like AvatarCLIP, which suffered from noise due to sparse ray sampling [S1]. The technique is part of a broader effort to optimize memory usage in NeRF training [S1, S2].
