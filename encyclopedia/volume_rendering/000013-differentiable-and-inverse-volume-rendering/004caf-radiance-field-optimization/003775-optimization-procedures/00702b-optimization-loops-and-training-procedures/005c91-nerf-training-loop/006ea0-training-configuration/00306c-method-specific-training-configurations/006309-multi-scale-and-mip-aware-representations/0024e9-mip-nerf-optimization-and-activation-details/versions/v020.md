# Mip-NeRF Optimization and Activation Details

Also called: JaxNeRF Training Procedure, Mip-NeRF Misc. Changes

## Overview
This method defines the specific implementation details for training Mip-NeRF and JaxNeRF, focusing on activation functions, input encoding strategies, and learning rate scheduling to improve training stability and robustness [S1]. It addresses common failure modes in neural radiance field optimization, such as catastrophic gradient vanishing and saturation issues, without significantly altering the core accuracy or speed of the Mip-NeRF algorithm [S1]. These changes are distinct from the core Mip-NeRF anti-aliasing mechanics (Integrated Positional Encoding) and are considered "miscellaneous" implementation refinements [S1].

## How it works
The method modifies the standard NeRF training loop through four key adjustments: input encoding simplification, density and color activation functions, view direction injection, and a warmup learning rate schedule.

### Inputs and Outputs
*   **Inputs:** Training images, camera intrinsics, camera extrinsics, and dataset metadata (near/far clipping planes).
*   **Outputs:** Optimized MLP weights for density $\tau$ and color $\mathbf{c}$.

### Data Structures
*   **Integrated Positional Encoding (IPE):** The input to the MLP is the IPE vector only. The original NeRF practice of concatenating the IPE with the original position and view direction (identity encoding) is removed [S1].
*   **View Direction:** The ray direction $\mathbf{d}$ is normalized and processed separately.

### Numbered Steps

1.  **Input Encoding:**
    *   Compute the Integrated Positional Encoding (IPE) for the query point and view direction.
    *   Pass the IPE vector directly as the sole input to the MLP. Do not concatenate the raw position or view direction [S1].

2.  **Density Prediction ($\tau$):**
    *   The MLP outputs a scalar value $x$.
    *   Apply the shifted softplus activation to predict density $\tau$:
        $$ \tau = \log(1 + \exp(x - 1)) $$
    *   This function is equivalent to using a softplus with biases initialized to $-1$, ensuring initial $\tau$ values are small [S1].

3.  **View Direction Injection:**
    *   Normalize the ray direction $\mathbf{d}$.
    *   Apply positional encoding to $\mathbf{d}$ with $L=4$ frequencies [S1].
    *   Inject this encoded view direction into the last layer of the MLP.
    *   This injection occurs after $\tau$ is predicted but before the color $\mathbf{c}$ is predicted [S1].

4.  **Color Prediction ($\mathbf{c}$):**
    *   The MLP outputs a scalar value $x$ for each color channel.
    *   Apply the "widened" sigmoid activation to predict color $\mathbf{c}$:
        $$ \mathbf{c} = \frac{1 + 2\epsilon}{1 + \exp(-x)} - \epsilon $$
    *   Use $\epsilon = 0.001$ [S1].

5.  **Learning Rate Schedule:**
    *   Use the Adam optimizer with a batch size of 4096 [S1].
    *   Total iterations $n = 1,000,000$ [S1].
    *   Warmup iterations $n_w = 2500$ [S1].
    *   Base learning rate anneals logarithmically from $\eta_0 = 5 \cdot 10^{-4}$ to $\eta_n = 5 \cdot 10^{-6}$ [S1].
    *   During warmup, scale the learning rate by a factor $\lambda_w$ that anneals from 0.01 to 1.
    *   The learning rate at iteration $i$ is:
        $$ \eta_i = \left( \lambda_w + (1 - \lambda_w) \sin\left(\frac{\pi}{2} \operatorname{clip}\left(\frac{i}{n_w}, 0, 1\right)\right) \right) \times \exp\left( \left(1 - \frac{i}{n}\right) \log(\eta_0) + \frac{i}{n} \log(\eta_n) \right) $$
    *   Here, $\lambda_w$ is a function of $i$ that increases from 0.01 to 1 during the first $n_w$ iterations [S1].

### Edge Cases and Pitfalls
*   **Negative Density:** Using standard ReLU for density can lead to catastrophic failure if the MLP outputs negative values everywhere, resulting in zero gradients. The shifted softplus prevents this [S1].
*   **Saturation on Black/White Pixels:** Standard sigmoid saturation can cause optimization failure when trying to explain pure black or white pixels. The widened sigmoid avoids this by saturating slightly outside [0, 1] [S1].
*   **Identity Concatenation:** Keeping the identity encoding (concatenating raw position/view with PE) makes the formalization of IPE features challenging and does not meaningfully improve performance or speed [S1].

## Subtopics

### Alternative Gaussian Positional Encoding
An alternative to the Integrated Positional Encoding (IPE) is to apply positional encoding to the mean $\mu$ and the (signed) square root of the elements of the covariance matrix $\Sigma$, then concatenate them as input to the MLP [S1]. Specifically, PE is applied to $\mu$ with $L=12$, and to $\text{vec}(\text{triu}(\text{sign}(\Sigma) \circ \sqrt{|\Sigma|}))$ with $L=2$ [S1]. This approach performs comparably to IPE in terms of accuracy (PSNR, SSIM, LPIPS) on multiscale and single-scale Blender datasets [S1]. However, it is sensitive to the hyperparameters $L$ and the design decisions used when parameterizing $\Sigma$, whereas IPE is hyperparameter-free and more compact [S1]. Additionally, while IPE is insensitive to off-diagonal elements of $\Sigma$ (correlation), experiments suggest that modeling this correlation does not improve accuracy, making it an unhelpful cue [S1].

### Reflected Cone Derivation
In the context of Mip-NeRF with reflections, a geometric derivation is used to shift the origin of a reflected ray so that its cone radius matches the incident ray's cone radius at the intersection point [S2]. This ensures consistent view-dependent appearance for reflections [S2]. The condition for equating radii is $\dot{r}\|\bar{\mathbf{x}} - \mathbf{o}\| = \dot{r}'\|\bar{\mathbf{x}} - \mathbf{o}'\|$, where $\dot{r}$ is the incident ray radius parameter, $\bar{\mathbf{x}}$ is the intersection point, $\mathbf{o}$ is the incident ray origin, $\dot{r}'$ is the reflected ray radius parameter, and $\mathbf{o}'$ is the reflected ray origin [S2]. This equation, along with the constraint that $\mathbf{o}'$ lies on the reflected ray, is solved to determine the correct origin shift [S2].

### RawNeRF
RawNeRF adapts Mip-NeRF for High Dynamic Range (HDR) image view synthesis and denoising by using raw linear images as training data [S3]. Unlike HDR-NeRF which uses LDR images, RawNeRF renders in a linear color space, allowing varying exposure and tone-mapping curves to be applied after NeRF rendering [S3]. The method supervises the model with variable exposure images, scaling the NeRF model's "exposure" by the training image's shutter speed, as well as using a per-channel learned scaling factor [S3].

## Operating characteristics
*   **Training Speed:** Mip-NeRF is 13x faster to train than a brute-force supersampling baseline (16 rays/pixel) [S1].
*   **Evaluation Speed:** Mip-NeRF is 16x faster to evaluate than the supersampling baseline [S1].
*   **Quality:** Mip-NeRF outperforms the supersampling baseline in quality metrics (PSNR, SSIM, LPIPS) [S1].
*   **Stability:** The activation functions and learning rate schedule improve training stability, particularly with large learning rates, though the specific ablations show these changes do not significantly alter the final accuracy or speed of the core Mip-NeRF method [S1].
*   **Memory:** The removal of identity encoding and use of IPE makes the feature representation more compact [S1].

## Background
These optimization and activation details were introduced in the Mip-NeRF paper (Barron et al., 2021) as part of the JaxNeRF codebase implementation [S1]. They were designed to address reproducibility and stability issues in training neural radiance fields with the Mip-NeRF architecture [S1]. The method builds on the core Mip-NeRF concept of Integrated Positional Encoding (IPE) to handle multiscale data and reduce aliasing [S1]. RawNeRF, a variant using these principles for HDR synthesis, was introduced by Mildenhall et al. in November 2021 [S3].
