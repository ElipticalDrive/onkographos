# Forward Warping for Novel View Synthesis

Also called: Canonical Field Forward Warping, Forward Flow

## Overview
Forward Warping for Novel View Synthesis is a method for rendering dynamic scenes by modeling a static "canonical" radiance field and differentially warping it to target time steps [S1]. It solves the many-to-one and one-to-many mapping ambiguities inherent in dynamic scene reconstruction by using average splatting for forward warping and an inpaint network to fill occluded regions [S1]. Unlike backward-flow methods such as NDVG, this approach leverages a canonical representation to simplify the deformation field, achieving state-of-the-art performance on public datasets [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of multi-view images $\mathcal{I}$ captured at various time steps $t$.
*   Camera poses $\mathbf{P}_i$ and intrinsic parameters for each image.
*   Time step $t$ for the target novel view.

**Outputs:**
*   Rendered RGB images $\mathbf{C}(\mathbf{r})$ for arbitrary viewpoints and time steps $t$.

### Data Structures
The method relies on several voxel grids and neural networks. All voxel grids are 3D structures indexed by spatial coordinates.

1.  **Canonical Radiance Feature Grid ($VR_f$):** Voxel grid storing radiance features. Feature dimension: 12.
2.  **Canonical Coordinate Grid ($VR_{Can}$):** Voxel grid storing the spatial coordinate of each voxel center.
3.  **Canonical Density Grid ($V_{\sigma}^{Can}$):** Voxel grid storing canonical density values.
4.  **Canonical Color Feature Grid ($V_{cf}^{Can}$):** Voxel grid storing color features. Dimension: 3 (coarse stage) or 12 (fine stage).
5.  **Canonical Deformation Feature Grid ($VD_f^{Can}$):** Voxel grid storing deformation features. Dimension: 0 for D-NeRF dataset, 12 for HyperNeRF dataset.
6.  **Trajectory Grid ($VT_t$):** Voxel grid storing Discrete Cosine Transform (DCT) parameters for each voxel's trajectory.
7.  **Deformation Flow Grid ($V_{flow}$):** Voxel grid storing the deformation flow vector from the canonical position to the position at time $t$.
8.  **Warped Radiance Field ($VR_t$):** The radiance field at time $t$, obtained by warping $VR_f$ using the deformation flow.
9.  **Inpainted Radiance Field ($VR_t^{Inp}$):** The radiance field after applying the inpaint network to $VR_t$.
10. **Upsampled Radiance Field ($VR_t^{Up}$):** The radiance field after upsampling $VR_t^{Inp}$.

### Neural Networks
Four networks define the core logic:

1.  **Canonical Radiance Network ($F_{\theta_1}$):**
    *   **Structure:** 3-layer MLP, width 128, ReLU activation.
    *   **Input:** Radiance feature from $VR_f$ (dim 12) concatenated with embedded position (dim 33).
    *   **Output:** Density (dim 1) and color feature (dim 3 or 12).

2.  **Canonical Deformation Network ($F_{\theta_2}$):**
    *   **Structure:** 4-layer MLP, width 64.
    *   **Input:** Deformation feature from $VD_f^{Can}$ concatenated with embedded position (dim 33).
    *   **Output:** DCT coefficients for trajectory prediction.

3.  **View Dependent Color Network ($F_{\theta_4}$):**
    *   **Structure:** 2-layer MLP, width 64.
    *   **Input:** Embedded view direction (dim 27) concatenated with color feature (dim 12).
    *   **Output:** RGB color (dim 3).

4.  **Inpaint Network ($F_{\theta_3}$):**
    *   **Structure:** UNet with 4 encode layers and 3 decode layers, followed by an upsample layer.
    *   **Encode Layer:** Max pooling + two convolution layers (Instance Norm $\rightarrow$ Conv $\rightarrow$ ReLU).
    *   **Decode Layer:** Up-sample interpolation + two convolution layers (Instance Norm $\rightarrow$ Conv $\rightarrow$ ReLU).
    *   **Input:** Warped radiance field $VR_t$.
    *   **Output:** Inpainted radiance field $VR_t^{Inp}$.

### Numbered Steps

1.  **Canonical Field Initialization:**
    Initialize voxel grids $VR_f$, $VR_{Can}$, $V_{\sigma}^{Can}$, $V_{cf}^{Can}$, $VD_f^{Can}$, and $VT_t$. The canonical time $t_{can}$ is set to the first frame for D-NeRF and the middle frame for HyperNeRF [S1].

2.  **Deformation Flow Calculation:**
    For a target time $t$, sample the deformation feature from $VD_f^{Can}$ and the DCT parameters from $VT_t$ at the canonical position $\mathbf{x}_{can}$. Pass these through $F_{\theta_2}$ to predict the trajectory. Compute the deformation flow $\mathbf{v}(\mathbf{x}_{can}, t)$ representing the displacement from $\mathbf{x}_{can}$ to $\mathbf{x}_t$ [S1].

3.  **Forward Warping (Average Splatting):**
    Warp the canonical radiance features from $VR_f$ to the target time $t$ using the deformation flow. This produces the Warped Radiance Field $VR_t$. The method uses **average splatting** rather than softmax splatting, as predicted weights for softmax splatting showed no improvement and added complexity [S1].
    *   *Note:* Average splatting distributes features from canonical voxels to target voxels based on the flow vector, averaging contributions from multiple canonical voxels mapping to the same target location (handling many-to-one) and filling gaps where no canonical voxel maps (handling one-to-many) [S1].

4.  **Inpainting:**
    Pass $VR_t$ through the Inpaint Network $F_{\theta_3}$ to generate $VR_t^{Inp}$. This step refines the warped field, correcting artifacts caused by occlusions and the averaging process [S1].

5.  **Upsampling (Fine Stage Only):**
    In the fine training stage, upsample $VR_t^{Inp}$ to create $VR_t^{Up}$. This is skipped in the coarse stage [S1].

6.  **Volume Rendering:**
    For a ray $\mathbf{r}$, sample points along the ray in the warped space.
    *   Retrieve density $\sigma$ and color feature $\mathbf{c}_{feat}$ from the appropriate grid ($VR_t^{Inp}$ or $VR_t^{Up}$) using $F_{\theta_1}$ (if not pre-stored) or direct lookup.
    *   Compute final RGB color $\mathbf{c}$ using $F_{\theta_4}$ with the view direction $\mathbf{d}$ and $\mathbf{c}_{feat}$.
    *   Render color $\mathbf{C}(\mathbf{r})$ using standard volume rendering integration [S1].

7.  **Loss Computation:**
    Compute the total loss $\mathcal{L}$ as defined below.

8.  **Optimization:**
    Update all parameters (voxel grids and network weights) using Adam optimizer.

### Formulas

**Point-wise Color Loss ($\mathcal{L}_{ptc}$):**
Supervises the color of sampled points weighted by their accumulation.
$$
\mathcal{L}_{ptc} = \frac{1}{|\mathcal{R}|} \sum_{r \in \mathcal{R}} \mathcal{L}(\mathbf{C}_{\text{Inp}}(\mathbf{r})) + \frac{1}{|\mathcal{R}|} \sum_{r \in \mathcal{R}} \mathcal{L}(\mathbf{C}_{\text{Up}}(\mathbf{r}))
$$
where
$$
\mathcal{L}(\mathbf{C}(\mathbf{r})) = \frac{1}{K} \sum_{k=1}^{K} A_{\text{accum}}(k) \|\mathbf{c}(w_k) - \mathbf{C}_{\text{gt}}(\mathbf{r})\|_2^2
$$
and
$$
A_{\text{accum}}(k) = T(w_k) \, \sigma(w_k) \delta_k
$$
Here, $\mathbf{C}_{\text{Inp}}$ and $\mathbf{C}_{\text{Up}}$ are colors rendered from the inpainted and upsampled fields, respectively. $K$ is the number of samples per ray. $T(w_k)$ is the transmittance, $\sigma(w_k)$ is the density, and $\delta_k$ is the distance between samples [S1].

**Background Entropy Loss ($\mathcal{L}_{bg}$):**
Encourages densities to concentrate on foreground or background (binary distribution).
$$
\mathcal{L}_{bg} = \frac{1}{|\mathcal{R}|} \sum_{r \in \mathcal{R}} \mathcal{L}(\mathbf{A}_{\text{Inp}}(\mathbf{r})) + \frac{1}{|\mathcal{R}|} \sum_{r \in \mathcal{R}} \mathcal{L}(\mathbf{A}_{\text{Up}}(\mathbf{r}))
$$
where
$$
\mathcal{L}(\mathbf{A}(\mathbf{r})) = -\frac{1}{K-1} \sum_{k=1}^{K-1} \left[ A_{\text{accum}}(k)\log(A_{\text{accum}}(k)) + (1-A_{\text{accum}}(k))\log(1-A_{\text{accum}}(k)) \right]
$$
This term is applied to the accumulation values $A_{\text{accum}}(k)$ [S1].

**Total Loss:**
$$
\mathcal{L} = \mathcal{L}_{photo} + w_1\mathcal{L}_{ptc} + w_2\mathcal{L}_{bg} + w_3\mathcal{L}_{flow} + w_4\mathcal{L}_{vdiff} + w_5\mathcal{L}_{tv}(\mathbf{V}_{\sigma}^{\text{Can}}) + w_6\mathcal{L}_{tv}(\mathbf{V}_{\text{flow}}^t) + w_7\mathcal{L}_{tv}(\mathbf{D})
$$
where $\mathcal{L}_{photo}$ is the standard photometric loss, $\mathcal{L}_{flow}$ and $\mathcal{L}_{vdiff}$ are flow and video diffusion losses (if applicable), and $\mathcal{L}_{tv}$ denotes Total Variation loss on the density grid, flow grid, and deformation field $\mathbf{D}$ [S1].

### Parameters and Typical Values

**Coarse Stage:**
*   **Voxel Number:** $6^3$ expected voxels.
*   **Inpaint Scale:** 1.5.
*   **Iterations:** 20,000.
*   **Weights:** $w_1=10^{-1}, w_2=10^{-2}, w_3=10^{-5}, w_4=0, w_5=10^{-6}, w_6=10^{-3}, w_7=10^{-1}$.
*   **Note:** The inpaint network is **not** used during the coarse stage [S1].

**Fine Stage:**
*   **Voxel Number:** $8^3$ for D-NeRF, $7^3$ for HyperNeRF.
*   **Inpaint Scale:** 2.0.
*   **Iterations:** 100,000.
*   **Weights:** $w_1=10^{-2}, w_2=10^{-3}, w_3=10^{-5}, w_4=10^{-5}, w_5=10^{-6}, w_6=10^{-3}, w_7=10^{-1}$.
*   **Progressive Training:** Start with 10 images closest to the canonical time step. Add one image with the closest remaining time step every 60 iterations [S1].

**General:**
*   **Learning Rate:** $10^{-1}$ for voxel grids, $10^{-3}$ for neural networks.
*   **Optimizer:** Adam [S1].

### Edge Cases and Pitfalls
*   **Memory Consumption:** The method is memory-intensive, particularly for real-world scenes, due to the multiple voxel grids and the UNet structure [S1].
*   **Training Speed:** Training is slow, taking approximately one day per scene on an RTX 3090 [S1].
*   **Coarse Stage Necessity:** Removing the coarse stage causes significant performance drops because the voxel grid covers a larger space without the proxy geometry filtering provided by the coarse training [S1].
*   **Inpainting Importance:** Removing the inpaint network significantly reduces performance (e.g., Hell Warrior PSNR drops from 27.71 to 27.15) [S1].
*   **Canonical Time Selection:** Setting the canonical time to the middle frame improves performance for HyperNeRF, as the geometry is closer to other time steps. For D-NeRF, the first frame is used for consistency with other methods [S1].

## Subtopics

### Gear-NeRF
*   **What it is:** A method using gear-like structures to model dynamic scenes.
*   **Difference:** Uses explicit geometric primitives (gears) rather than a canonical radiance field with forward warping.
*   **When to choose:** When the scene has rigid, articulated motion that can be modeled by mechanical structures.
*   **Link:** [Gear-NeRF](13848-gear-nerf.md)

### NeRF with Time Parameter
*   **What it is:** A baseline extension of NeRF that includes time $t$ as an input to the MLP.
*   **Difference:** Directly models time-dependent density and color without a canonical space or warping. Prone to temporal inconsistencies and artifacts.
*   **When to choose:** As a baseline for comparison or for very simple, low-frequency temporal changes.
*   **Link:** [NeRF with Time Parameter](14705-nerf-with-time-parameter.md)

### Dynamic Appearance Particle Neural Radiance Field
*   **What it is:** Combines particle-based appearance modeling with NeRF.
*   **Difference:** Uses particles to capture dynamic appearance variations rather than warping a static field.
*   **When to choose:** For scenes with complex appearance changes (e.g., lighting, texture) that are not purely geometric.
*   **Link:** [Dynamic Appearance Particle Neural Radiance Field](15550-dynamic-appearance-particle-neural-radiance-field.md)

### KFD-NeRF
*   **What it is:** Uses a keyframe-based deformation field.
*   **Difference:** Interpolates deformation fields between keyframes, whereas Forward Warping uses a continuous canonical field warped to any time $t$.
*   **When to choose:** When the scene has distinct key poses and sparse temporal sampling.
*   **Link:** [KFD-NeRF](15551-kfd-nerf.md)

## Operating characteristics

*   **Time Complexity:** Training is slow, approximately one day per scene on an RTX 3090 [S1]. Rendering is also slow, taking 7s per image for D-NeRF and 15s per image for HyperNeRF [S1].
*   **Memory Complexity:** High memory consumption due to multiple voxel grids ($VR_f, V_{\sigma}^{Can}, V_{cf}^{Can}, VD_f^{Can}, VT_t, V_{flow}$) and the UNet inpaint network. Model size is 260M parameters for D-NeRF and 440M for HyperNeRF [S1].
*   **Performance:** Achieves state-of-the-art results on public datasets (D-NeRF, HyperNeRF) and a custom Lego dataset, particularly for canonical frames [S1]. Outperforms backward-flow methods like NDVG [S1].
*   **Strengths:** Handles many-to-one and one-to-many mappings effectively via average splatting and inpainting. Smooth trajectory field allows for better temporal consistency.
*   **Limitations:** High memory usage and slow training/rendering speeds. Performance is sensitive to the choice of canonical time step [S1].

## Background

*   **Origin:** Proposed in the paper "Forward Flow for Novel View Synthesis of Dynamic Scenes" (ICCV 2023) [S1].
*   **History:** The method builds on the concept of canonical representations in dynamic NeRFs, addressing the limitations of direct time-parameterization and backward-flow methods. It introduces average splatting and an inpaint network to handle the ambiguities of forward warping [S1].
*   **Usage:** Used for novel view synthesis of dynamic scenes, including human performance capture and object animation. It has been evaluated on the D-NeRF, HyperNeRF, and a custom Lego Complete Dataset [S1].
