# CLNeRF Architecture with Embeddings

Also called: Appearance and Geometry Embeddings, Compact Continual NeRF

## Overview
CLNeRF is a model architecture modification for NeRF that enables continual learning by incorporating scene changes (appearance and geometry) over time within a single model, preventing model size growth as new scans are added [S1]. It sets itself apart from sibling methods like MIMO-DONeRF and SLS4D by using explicit, trainable per-scan embedding vectors rather than latent space compression or multi-instance networks, allowing for efficient updates and low overhead for generative replay [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A spatial location $\mathbf{x} \in \mathbb{R}^3$, a viewing direction $\mathbf{d} \in \mathbb{R}^3$, and a time step index $t$ identifying the current scan in a continual sequence [S1].
*   **Output:** Color $c$ and volume density (opacity) $\sigma$ [S1].

**Data Structures:**
*   **Feature Vector $\mathbf{f}$:** The encoded representation of spatial location $\mathbf{x}$ [S1].
    *   For NGP backbone: $\mathbf{f}$ is produced by a grid-based hash encoder [S1].
    *   For Vanilla NeRF backbone: $\mathbf{f}$ is produced by an MLP [S1].
*   **Appearance Embedding $e_a$:** A trainable vector encoding appearance changes (e.g., lighting, weather) [S1].
    *   Dimension: 48 [S1].
    *   Layout: A single vector per time step $t$ [S1].
*   **Geometry Embedding $e_g$:** A trainable vector encoding geometry changes (e.g., new objects, construction) [S1].
    *   Dimension: 16 [S1].
    *   Layout: A single vector per time step $t$ [S1].
*   **Decoders:**
    *   $D_c$: Color decoder (MLP) [S1].
    *   $D_\sigma$: Opacity decoder (MLP) [S1].

**Numbered Steps:**
1.  **Encode Spatial Location:** Given a spatial location $\mathbf{x}$, encode it into a feature vector $\mathbf{f}$ [S1]. If using NGP, use the grid-based hash encoder; if using vanilla NeRF, use an MLP [S1].
2.  **Compute Color:** Decode color $c$ using the color decoder $D_c$ [S1]. The inputs are the feature vector $\mathbf{f}$, the viewing direction $\mathbf{d}$, and the trainable appearance embedding $e_a$ corresponding to the current time step $t$ [S1].
    $$c = D_c(\mathbf{f}, \mathbf{d}, e_a)$$
3.  **Compute Opacity:** Decode opacity $\sigma$ using the opacity decoder $D_\sigma$ [S1]. The inputs are the feature vector $\mathbf{f}$ and the trainable geometry embedding $e_g$ corresponding to the current time step $t$ [S1].
    $$\sigma = D_\sigma(\mathbf{f}, e_g)$$
4.  **Embedding Assignment:** For each new time step $t$ (scan) in the continual learning sequence, add one new appearance embedding $e_a$ and one new geometry embedding $e_g$ to the model [S1]. These embeddings are distinct per time step [S1].

**Parameters:**
*   Appearance embedding dimension: 48 [S1].
*   Geometry embedding dimension: 16 [S1].

**Pitfalls:**
*   **Transient Objects:** The architecture does not automatically filter transient objects (e.g., moving pedestrians) within a single scan [S1]. Using a transient MLP with NGP causes the non-transient network to overfit to transient objects and fail to filter them [S1]. Transient objects must be filtered using segmentation masks [S1].
*   **Backbone Choice:** Using vanilla NeRF as the backbone results in worse performance and efficiency compared to NGP for CLNeRF, particularly regarding model updates and generative replay overhead [S1].

**Pseudocode:**
```python
import torch
import torch.nn as nn

class CLNeRF(nn.Module):
    def __init__(self, use_ngp=True, appearance_dim=48, geometry_dim=16):
        super().__init__()
        self.use_ngp = use_ngp
        self.appearance_dim = appearance_dim
        self.geometry_dim = geometry_dim
        
        # Encoders
        if use_ngp:
            # NGP grid-based hash encoder implementation not provided in sources [G]
            self.spatial_encoder = lambda x: x # Placeholder for hash encoding
        else:
            # Vanilla NeRF MLP encoder (exact architecture not specified [G])
            self.spatial_encoder = nn.Sequential(
                nn.Linear(3, 256),
                nn.ReLU(),
                nn.Linear(256, 256),
                nn.ReLU(),
                nn.Linear(256, 256)
            )
            
        # Decoders
        # Color decoder takes f, d, ea
        self.color_decoder = nn.Sequential(
            nn.Linear(256 + 3 + appearance_dim, 256),
            nn.ReLU(),
            nn.Linear(256, 3) # RGB
        )
        
        # Opacity decoder takes f, eg
        self.opacity_decoder = nn.Sequential(
            nn.Linear(256 + geometry_dim, 256),
            nn.ReLU(),
            nn.Linear(256, 1) # Sigma
        )
        
        # Embeddings are stored in lists, one per time step
        self.appearance_embeddings = []
        self.geometry_embeddings = []

    def add_time_step(self):
        """Add new embeddings for a new scan/time step t."""
        ea = nn.Parameter(torch.randn(1, self.appearance_dim))
        eg = nn.Parameter(torch.randn(1, self.geometry_dim))
        self.appearance_embeddings.append(ea)
        self.geometry_embeddings.append(eg)

    def forward(self, x, d, t):
        """
        x: (N, 3) spatial coordinates
        d: (N, 3) viewing directions
        t: int, current time step index
        """
        # 1. Encode spatial location
        f = self.spatial_encoder(x) # (N, 256)
        
        # 2. Get embeddings for time step t
        ea = self.appearance_embeddings[t] # (1, 48)
        eg = self.geometry_embeddings[t]   # (1, 16)
        
        # Expand for batch
        ea = ea.expand(x.size(0), -1)
        eg = eg.expand(x.size(0), -1)
        
        # 3. Compute Color
        # Concatenate f, d, ea
        color_input = torch.cat([f, d, ea], dim=-1)
        c = self.color_decoder(color_input) # (N, 3)
        
        # 4. Compute Opacity
        # Concatenate f, eg
        opacity_input = torch.cat([f, eg], dim=-1)
        sigma = self.opacity_decoder(opacity_input) # (N, 1)
        
        return c, sigma
```

## Operating characteristics
*   **Time and Memory Complexity:** The model size increases linearly with the number of time steps $t$, but the increase is minimal due to the small embedding dimensions (48 and 16) [S1].
*   **Measured Performance:** Using NGP as the backbone provides better performance and efficiency compared to vanilla NeRF for CLNeRF, enabling efficient model updates and low overhead for generative replay [S1].
*   **Strengths:** Compact model size, efficient updates, handles appearance and geometry changes separately [S1].
*   **Limitations:** Requires segmentation masks for transient object filtering; not compatible with transient MLPs for automatic filtering [S1].
*   **When to use:** When continual learning of a scene with appearance and geometry changes is required, and model size must remain compact [S1].
*   **When not to use:** When transient objects within a single scan are present and segmentation masks are unavailable [S1].

## Background
CLNeRF was introduced in the paper "CLNeRF: Continual Learning Meets NeRF" [S1]. It addresses the challenge of continual learning in NeRFs, where the model must adapt to new scans without forgetting previous ones or growing indefinitely in size [S1]. The method builds on the Instant Neural Graphics Primitives (NGP) architecture [S1].
