# Rip-NeRF

Also called: Rip-NeRF25k

## Overview
Rip-NeRF is a radiance field method that renders high-fidelity anti-aliased images by combining cone casting with an anisotropic 3D Gaussian characterization [S1]. It utilizes Platonic Solid Projection and Ripmap Encoding to enable efficient anisotropic area-sampling of 3D space, distinguishing itself from sibling methods like Zip-NeRF by replacing inefficient multi-sampling mechanisms with a compact, learnable feature grid structure [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of calibrated multi-view 2D images with known camera poses.
*   **Outputs:** Rendered pixel colors $\mathbf{c}$ and the optimized scene representation (Ripmap Encodings and Gaussian parameters).

**Data Structures:**
1.  **Ripmap Encoding ($\mathcal{R}$):** A hierarchical grid of learnable features.
    *   **Base Level ($\mathcal{R}_{0,0}$):** The only learnable level. Shape: $H=512, W=512, C=16$ [S1].
    *   **Derived Levels:** All other levels $\mathcal{R}_{i,j}$ are derived from the base level using averaging operations to ensure consistency and compactness [S1].
2.  **Platonic Solid:** A geometric proxy for area sampling. Default is an icosahedron with 10 unparalleled faces $\{P_i | i = 1, \dots, n\}$ [S1].
3.  **Anisotropic 3D Gaussian:** Characterizes each conical frustum, defined by mean $\boldsymbol{\mu}$ and covariance $\boldsymbol{\Sigma}$ [S1].

**Numbered Steps:**

1.  **Cone Casting and Frustum Division:**
    For each pixel, cast a cone into the scene. Divide the cone into multiple conical frustums along the viewing ray [S1].

2.  **Gaussian Characterization:**
    Characterize each conical frustum as an anisotropic 3D Gaussian parameterized by mean $\boldsymbol{\mu}$ and covariance $\boldsymbol{\Sigma}$ [S1].

3.  **Platonic Solid Projection:**
    Project the 3D Gaussian onto the faces of the Platonic solid. For each face $P_i$, compute the projection matrix $M_i \in \mathbb{R}^{3 \times 2}$ mapping the 3D world coordinate system to the 2D coordinate system of plane $P_i$ [S1].
    Calculate the projected mean $\boldsymbol{\mu}^{proj}$ and covariance $\boldsymbol{\Sigma}^{proj}$ for the 2D Gaussian on plane $P_i$ [S1]:
    $$ \boldsymbol{\mu}^{proj} = M_i^T \boldsymbol{\mu} $$
    $$ \boldsymbol{\Sigma}^{proj} = M_i^T \boldsymbol{\Sigma} M_i $$
    [S1]

4.  **Ripmap Encoding Query:**
    For each face $P_i$, query a feature vector $\mathbf{f}_i$ from the Ripmap Encoding using tetra-linear interpolation [S1]. The interpolation position $(p_x, p_y)$ and level $(l_x, l_y)$ are determined by $\boldsymbol{\mu}^{proj}$ and $\boldsymbol{\Sigma}^{proj}$ respectively [S1].
    
    The interpolation uses a hyper-parameter $w=2.0$ to adjust the probability mass coverage of the Gaussian footprint [S1]. The specific interpolation logic (Eq. 2 and Eq. 3 in source) maps the Gaussian's spatial extent to the Ripmap grid coordinates [S1].

5.  **Feature Aggregation:**
    Concatenate all feature vectors $\{\mathbf{f}_i | i = 1, \dots, n\}$ from the $n$ Platonic solid faces to form the final feature vector $\mathbf{f}$ of the 3D Gaussian [S1].

6.  **Neural Mapping:**
    Concatenate the aggregated feature vector $\mathbf{f}$ with the encoded view direction $\mathbf{d}$. Pass this combined vector through a tiny MLP $F_\theta$ to estimate the color $\mathbf{c}$ and density $\sigma$ of the conical frustum [S1].

7.  **Volume Rendering:**
    Render the pixel color by performing volume rendering using the estimated color $\mathbf{c}$ and density $\sigma$ values along the ray [S1].

8.  **Optimization:**
    Optimize the system end-to-end using a photometric loss between rendered and observed images [S1].
    *   **Area Loss:** Scale the photometric loss for each pixel by incorporating the area of its footprint on the image plane, denoted as $L_{area}$ [S1]. This makes the loss area-aware [S1].

**Parameters:**
*   **Ripmap Base Shape:** $H=512, W=512, C=16$ [S1].
*   **Platonic Solid:** Icosahedron (10 faces) [S1].
*   **Hyper-parameter $w$:** 2.0, used to adjust the probability mass of the Gaussian footprint covered during sampling [S1].
*   **Optimizer:** AdamW [S1].
*   **Iterations:** 120k (standard Rip-NeRF) or 25k (Rip-NeRF25k variant) [S1].
*   **Weight Decay:** $1 \times 10^{-5}$ [S1].
*   **Initial Learning Rate:** $2 \times 10^{-3}$, modulated by MultiStepLR [S1].
*   **Ripmap Learning Rate Scale:** Scaled up by 10.0 times relative to the base learning rate [S1].

**Edge Cases and Pitfalls:**
*   **Empty Space:** Use a binary occupancy grid (e.g., via NerfAcc library) to skip samples in empty areas, improving efficiency [S1].
*   **Precision:** The Ripmap Encoding relies on tetra-linear interpolation; ensure coordinate mapping from Gaussian covariance to grid levels is handled with sufficient precision to avoid artifacts in anisotropic sampling [S1].
*   **Hardware:** The method uses `tiny-cuda-nn` for MLPs and custom CUDA kernels for Platonic Solid Projection and Ripmap Encoding [S1].

## Operating characteristics
*   **Training Time:** 2.6 hours on NVIDIA A100-SXM4-80GB GPU for the standard 120k iteration version [S1]. The Rip-NeRF25k variant trains in 32 minutes (11.76% of Zip-NeRF's time) [S1].
*   **Model Size:** 160 MB [S1].
*   **GPU Memory:** 20 GB during training [S1].
*   **Rendering Speed:** 3 FPS in the experimental setting [S1].
*   **Comparison:** Outperforms Zip-NeRF in training time (2.6h vs 4.5h), model size (160MB vs 592MB), and rendering speed (3 FPS vs 0.25 FPS) [S1]. Zip-NeRF has slightly better SSIM but requires significantly more memory (80 GB) and time [S1].
*   **Strengths:** High-fidelity anti-aliasing, efficient anisotropic area-sampling, compact representation, fast training.
*   **Limitations:** Designed for bounded scenes (unlike Zip-NeRF which targets unbounded scenes); performance on unbounded scenes may require adaptation [S1].

## Background
Rip-NeRF was introduced in the paper "Rip-NeRF: Anti-aliasing Radiance Fields with Ripmap-Encoded Platonic Solids" [S1]. It builds upon the hybrid representation approach used in methods like Mip-NeRF and Tri-MipRF, aiming to solve the inefficiency of multi-sampling mechanisms found in competitors like Zip-NeRF by introducing Ripmap Encoding and Platonic Solid Projection [S1].
