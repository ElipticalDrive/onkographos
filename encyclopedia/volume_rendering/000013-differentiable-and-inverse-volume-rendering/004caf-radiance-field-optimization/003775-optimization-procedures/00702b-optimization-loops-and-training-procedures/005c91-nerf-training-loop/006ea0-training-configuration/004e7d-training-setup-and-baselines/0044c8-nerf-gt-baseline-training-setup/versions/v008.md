# NeRF-GT Baseline Training Setup

Also called: NeRF-GT, HDR-NeRF Ground Truth, HDR Baseline

## Overview
NeRF-GT is a reference training configuration for Neural Radiance Fields (NeRF) that uses High Dynamic Range (HDR) rendered views as input to establish an upper-bound performance metric for novel view synthesis [S1]. It differs from standard NeRF baselines, which typically use Low Dynamic Range (LDR) images, by training directly on HDR data while applying tone-mapping to the predicted outputs for loss calculation [S1]. This setup serves as a ground-truth baseline to evaluate the efficiency and quality of methods designed to synthesize HDR views from LDR inputs [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** HDR views of the scene, rendered using a path tracer (e.g., Blender's Cycles) [S1].
*   **Output:** A trained NeRF model capable of synthesizing novel HDR views [S1].

**Data Structures:**
*   **NeRF Model:** Standard MLP-based radiance field representation [S2, unofficial].
*   **Sampling:** Stratified sampling along rays [S2, unofficial].

**Parameters:**
*   **Samples per Ray:** 64 samples in the coarse phase, 128 samples in the fine phase [S2, unofficial].
*   **Batch Size:** 2,048 rays per batch [S2, unofficial].
*   **Resolution:** 800 × 600 pixels [S2, unofficial].
*   **Training Steps:** 200,000 solver steps [S2, unofficial].
*   **Tone Mapping:** Applied to both predicted HDR pixel values and ground truth LDR views before loss computation [S1].

**Steps:**
1.  **Training Input:** Train the NeRF model using HDR views as the target data [S1].
2.  **Prediction:** Render predicted HDR pixel values for the current camera pose [S1].
3.  **Tone Mapping:** Apply tone-mapping to the predicted HDR pixel values to convert them into LDR pixel values [S1].
4.  **Loss Calculation:** Compute the loss by comparing the tone-mapped predicted LDR values to the tone-mapped ground truth LDR views [S1].
5.  **Optimization:** Update model parameters using the computed loss [S1].
6.  **Termination:** Stop training after 200,000 solver steps [S2, unofficial].

**Pitfalls:**
*   Training directly on HDR views can fail to encode all areas of a scene well due to the high dynamic range, even when tone-mapped colors are used for loss calculation [S1].

## Subtopics

### NeRF Baseline
The standard NeRF baseline uses LDR views for training and evaluation, serving as the primary comparison point for HDR methods [S2, unofficial]. It typically employs the same sampling and optimization parameters as the NeRF-GT setup but operates on tone-mapped or standard exposure images without the HDR ground truth [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Training time is approximately 0.40 seconds per iteration [S2, unofficial].
*   **Rendering Time:** Rendering time is approximately 32 seconds per frame [S2, unofficial].
*   **Scaling:** Performance scales with the number of samples per ray and batch size [S2, unofficial].
*   **Strengths:** Provides an upper-bound performance metric for HDR synthesis [S1].
*   **Limitations:** Difficult to ensure all scene areas are encoded well due to high dynamic range [S1].
*   **When to Use:** When establishing a performance baseline for HDR novel view synthesis methods [S1].
*   **When Not to Use:** When HDR data is unavailable or when computational resources are limited [S1].

## Background
The NeRF-GT baseline was introduced in the context of HDR-NeRF, a method for high dynamic range neural radiance fields [S1]. The dataset used for evaluation includes HDR views rendered with Blender's Cycles path-tracer from 3D models provided by Sketchfab [S1]. The training parameters (64/128 samples, 2048 rays/batch, 800x600 resolution, 200,000 steps) are inspired by the provided `config_fern.txt` configuration from the original NeRF authors [S2, unofficial].
