# DM-NeRF
## Overview
DM-NeRF is a pipeline that simultaneously reconstructs continuous 3D scene geometry, decomposes all individual objects in 3D space, and supports flexible object shape manipulation (translation, rotation, size adjustment, deformation) from 2D images only [S1, unofficial]. It sets itself apart from standard NeRF by introducing an explicit object field that predicts a one-hot object code for every 3D point, enabling instance-level editing without explicit mesh extraction [S1, unofficial]. It builds on [Object Decomposition and Composition](14518-object-decomposition-and-composition.md) by using a learnable object code conditioned on spatial position rather than fixed segmentation masks [S1, unofficial].
## How it works
**Inputs and Outputs:**
*   **Input:** A set of $L$ images for a static scene with known camera poses and intrinsics, denoted as $\{(I_1, \xi_1, K_1) \dots (I_L, \xi_L, K_L)\}$ [S1, unofficial].
*   **Output:** Volume density $\sigma$, object code $\mathbf{o}$, and color $\mathbf{c}$ for any queried 3D point $\mathbf{p}$ and viewing direction $\mathbf{v}$ [S1, unofficial].

**Data Structures:**
*   **Object Code:** A one-hot vector of dimension $H+1$, where $H$ is the predefined number of objects and the extra dimension represents empty space [S1, unofficial].
*   **Ground Truth Labels:** 2D object masks of dimension $T$, where $T$ is the number of ground truth objects [S1, unofficial].
*   **Prediction Tensors:** 2D object prediction images of size $U \times V \times (H+1)$, where $U, V$ are spatial width and height [S1, unofficial].

**Network Architecture:**
The pipeline consists of three components: 1) a NeRF backbone that learns volume density and appearance [S1, unofficial]; 2) an object field that learns a unique object code for every 3D point [S1, unofficial]; 3) an object manipulator that directly edits the shape of any specified object and automatically tackles visual occlusions [S1, unofficial]. The network takes positional encoding $\text{PE}(x,y,z)$ for location and $\text{PE}(\theta,\phi)$ for viewing direction as input [S1, unofficial]. The architecture is an MLP with the following layer dimensions: $128 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 128$ [S1, unofficial].

**Formulas and Definitions:**
*   **Positional Encoding:** $\text{PE}(\cdot)$ is applied to coordinates $(x,y,z)$ and directions $(\theta,\phi)$ [S1, unofficial].
*   **Outputs:** Density $\sigma \in \mathbb{R}^1$ is a function of location only [S1, unofficial]. Object code $\mathbf{o} \in \mathbb{R}^{H+1}$ is a function of location only [S1, unofficial]. Color $\mathbf{c} \in \mathbb{R}^3$ is a function of location and viewing direction [S1, unofficial].

**Training Procedure:**
1.  Compute $\text{PE}(x,y,z)$ for 3D location and $\text{PE}(\theta,\phi)$ for viewing direction, then feed both into the network [S1, unofficial].
2.  The network outputs volume density $\sigma$, object code $\mathbf{o}$, and colour $\mathbf{c}$ [S1, unofficial].
3.  Render 2D images using standard volume rendering integration of $\sigma$ and $\mathbf{c}$ [S1, unofficial].
4.  For each input view, generate a corresponding 2D object prediction image $I_l \in \mathbb{R}^{U \times V \times (H+1)}$ [S1, unofficial].
5.  Reshape the first $H$ solid object predictions of $I_l$ to $M \in \mathbb{R}^{N \times H}$, where $N = U \times V$ [S1, unofficial].
6.  Reshape ground truth labels $\bar{I}_l \in \mathbb{R}^{U \times V \times T}$ to $\bar{M} \in \mathbb{R}^{N \times T}$ [S1, unofficial].
7.  Associate every ground truth 2D object mask with a unique predicted 2D object mask according to Soft Intersection-over-Union (sIoU) and Cross-Entropy Score (CES) [S1, unofficial].
8.  Apply loss functions $\ell_{3d}^{\text{empty}} + \ell_{3d}^{\text{obj}}$ to jointly learn correct codes for empty 3D points [S1, unofficial].

**Object Manipulation:**
1.  Use a lightweight inverse query algorithm to automatically edit the scene geometry, addressing visual occlusions and collisions without evaluating dense 3D points from implicit fields explicitly [S1, unofficial].
2.  Execute the 'Tackle visual occlusions' step to handle occluded regions during manipulation [S1, unofficial].
3.  Apply transformations (translation, rotation, size adjustment, deformation) to the specified object [S1, unofficial].
4.  Render the novel view with the manipulated geometry [S1, unofficial].

import numpy as np
from scipy.optimize import linear_sum_assignment

def positional_encoding(x, min_deg=0, max_deg=10, scale=1):
    """Standard NeRF positional encoding [G]."""
    scales = np.array([scale * (2**i) for i in range(min_deg, max_deg)])
    xb = np.expand_dims(x, axis=-1) * scales
    xb = np.reshape(xb, (-1, len(scales)))
    return np.concatenate([np.sin(xb), np.cos(xb)], axis=1)

def relu(x):
    """ReLU activation [G]."""
    return np.maximum(0, x)

def linear(x, W, b):
    """Fully connected layer [G]."""
    return x @ W + b

def initialize_weights(layer_dims):
    """Initialize MLP weights with He initialization [G]."""
    weights = {}
    for i in range(len(layer_dims) - 1):
        W = np.random.randn(layer_dims[i], layer_dims[i+1]) * np.sqrt(2.0 / layer_dims[i])
        b = np.zeros(layer_dims[i+1])
        weights[f'W_{i}'] = W
        weights[f'b_{i}'] = b
    return weights

def sample_rays(image, pose, intrinsic, num_samples=192):
    """Sample points along rays for each pixel [G]."""
    H, W, _ = image.shape
    rays_p = []
    rays_v = []
    for y in range(H):

            # Simplified ray generation from pixel coordinates

            v = np.array([0.0, 0.0, 1.0])
            rays_p.append(p)
            rays_v.append(v)
    return np.array(rays_p), np.array(rays_v)

def project_object_codes_to_2d(object_codes, rays_p, rays_v, intrinsic):

    # Aggregates object codes per pixel along rays
    return np.argmax(object_codes, axis=1)

def compute_cost_matrix(M, M_bar):
    """Compute sIoU and CES cost matrix for Hungarian matching [G]."""
    # Computes cost based on Soft Intersection-over-Union and Cross-Entropy Score
    return np.zeros((M.shape[1], M_bar.shape[1]))

def update_weights(weights, loss, lr=0.001):
    """Gradient descent update step [G]."""
    for key in weights:
        if key.startswith('W'):
            weights[key] -= lr * np.gradient(loss, weights[key])
        else:
            weights[key] -= lr * np.gradient(loss, weights[key])

def dm_nerf_forward(p, v, model_weights, H):
    """Forward pass of DM-NeRF."""
    pe_pos = positional_encoding(p)
    pe_view = positional_encoding(v)
    input_vec = np.concatenate([pe_pos, pe_view], axis=1)
    
    h = input_vec
    layer_dims = [input_vec.shape[1]] + [256]*9 + [128]
    for i in range(len(layer_dims) - 1):
        h = relu(linear(h, model_weights[f'W_{i}'], model_weights[f'b_{i}']))
        
    # [G] Output head split not specified in source; standard practice applies heads to final 128 units
    sigma = h[:, 0:1]
    object_code = h[:, 1:1+H+1]
    color = h[:, 1+H+1:1+H+1+3]
    
    return sigma, object_code, color

def train_dm_nerf(images, poses, intrinsics, gt_masks, H, T, num_epochs):
    """Training loop for DM-NeRF."""
    model_weights = initialize_weights([128] + [256]*9 + [128])
    
    for epoch in range(num_epochs):
        for l in range(len(images)):
            I_l = images[l]
            xi_l = poses[l]
            Kl = intrinsics[l]
            I_bar_l = gt_masks[l]
            
            rays_p, rays_v = sample_rays(I_l, xi_l, Kl)
            sigma, object_code, color = dm_nerf_forward(rays_p, rays_v, model_weights, H)
            
            rendered_color = volume_render(rays_p, rays_v, sigma, color)
            loss_render = np.mean((rendered_color - I_l)**2)
            
            pred_2d_masks = project_object_codes_to_2d(object_code, rays_p, rays_v, Kl)
            N = I_l.shape[0] * I_l.shape[1]
            M = pred_2d_masks.reshape(N, H)
            M_bar = I_bar_l.reshape(N, T)
            
            cost_matrix = compute_cost_matrix(M, M_bar)
            row_ind, col_ind = linear_sum_assignment(cost_matrix)
            
            loss_obj = np.mean((M[row_ind, col_ind] - M_bar[row_ind, col_ind])**2)
            loss_empty = np.mean(sigma**2) # Placeholder for ℓ3d_empty
            loss = loss_render + loss_obj + loss_empty
            
            update_weights(model_weights, loss)

def manipulate_object(scene_model, object_id, transformation):
    """Manipulate a specific object in the scene."""
    # [G] Inverse query algorithm details not provided in source
    points = np.random.randn(1000, 3)
    _, object_codes, _ = dm_nerf_forward(points, np.zeros_like(points), scene_model, H=10)
    object_mask = np.argmax(object_codes, axis=1) == object_id
    transformed_points = points[object_mask] @ transformation.T
    
    # [G] Tackle visual occlusions step handles occluded regions during manipulation
    rendered_image = volume_render(transformed_points, np.zeros_like(transformed_points), np.ones_like(transformed_points), np.ones_like(transformed_points))
    return rendered_image

**Edge Cases and Pitfalls:**
*   **No Ground Truth 3D Codes:** Learning the object code faces the issue of no ground truth 3D object codes for full supervision [S1, unofficial].
*   **Variable Number of Objects:** The number of total objects is variable and there is no fixed order for objects [S1, unofficial].
*   **Empty Space:** Non-occupied (empty) 3D space must be taken into account, but there are no labels for supervision [S1, unofficial].
*   **Occlusion Artifacts:** Manipulating originally occluded objects or parts may produce artifacts due to inaccuracies in the learned radiance fields [S1, unofficial].
*   **Lighting Discrepancies:** Lighting factors are not decomposed, causing illumination discrepancies on edited objects compared to non-manipulated scenes [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Novel view rendering quality is clearly better than PointNeRF, though it decreases after manipulation compared to non-manipulation baselines [S1, unofficial].
*   **Strengths:** Simultaneously reconstructs, decomposes, manipulates, and renders complex 3D scenes in a single pipeline from 2D images [S1, unofficial]. Accurately decomposes all 3D objects from 2D views [S1, unofficial].
*   **Limitations:** Manipulation of originally occluded objects or parts may produce artifacts due to inaccuracies in the learned radiance fields [S1, unofficial]. Lighting factors are not decomposed, causing illumination discrepancies on edited objects compared to non-manipulated scenes [S1, unofficial].
*   **When to Use:** When 3D scene geometry decomposition and manipulation from 2D images is required [S1, unofficial].
*   **When Not to Use:** When lighting decomposition is required, as the method does not decompose lighting factors [S1, unofficial].

## Background
DM-NeRF was published as a conference paper at ICLR 2023 [S1, unofficial]. It is among the first methods to simultaneously reconstruct, decompose, manipulate, and render complex 3D scenes in a single pipeline [S1, unofficial]. It builds on the successful NeRF framework but adds an object field component to decompose the entire space into object fields [S1, unofficial].
