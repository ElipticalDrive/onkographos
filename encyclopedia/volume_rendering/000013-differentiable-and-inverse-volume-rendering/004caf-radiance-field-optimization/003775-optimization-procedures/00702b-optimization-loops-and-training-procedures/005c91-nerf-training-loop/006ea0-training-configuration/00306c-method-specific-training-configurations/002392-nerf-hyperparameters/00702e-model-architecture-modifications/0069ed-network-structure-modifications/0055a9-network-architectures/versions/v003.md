# Network Architectures

Also called: NeRF Network Architectures

## Overview
This article details specific structural modifications to the standard NeRF Multi-Layer Perceptron (MLP) baseline, focusing on capacity adjustments and specialized sub-networks for mobile or efficient rendering pipelines. It addresses the problem of balancing inference speed and memory constraints on edge devices by decoupling training-time heavy networks from the lightweight inference network. It differs from general input/output expansion [14428-sparse-view-and-few-shot-optimization.md] by specifically altering the hidden layer dimensions and introducing a distinct small inference network, and from SDF representations [12495-signed-distance-function-sdf-representations.md] by retaining the density-based volumetric formulation.

## How it works
The architecture modifies the standard two-MLP NeRF structure [Parent](3065-nerf-hyperparameters.md) by introducing three distinct networks: a large network $A$, a large network $F$, and a small network $H$.

**Inputs and Outputs:**
*   **Network A (Appearance/Geometry):** Takes positional encoded position $\gamma(\mathbf{x})$ and outputs a latent feature vector $\mathbf{h}$ and volume density $\sigma$.
*   **Network F (Fine Geometry/Appearance):** Takes $\mathbf{h}$, $\gamma(\mathbf{x})$, and view direction $\gamma(\mathbf{d})$ to output color $\mathbf{c}$.
*   **Network H (Inference):** Takes $\mathbf{h}$ and $\gamma(\mathbf{d})$ to output color $\mathbf{c}$ directly, bypassing the need for $F$ during inference.

**Data Structures:**
*   **Networks A and F:** Multi-Layer Perceptrons (MLPs).
    *   Hidden layer size: 384 neurons per layer [S1].
    *   Standard NeRF uses 256 [S1].
*   **Network H:** Small MLP.
    *   Hidden layers: 2 [S1].
    *   Neurons per layer: 16 [S1].

**Numbered Steps:**
1.  **Training Phase:**
    a. Compute positional encoding $\gamma(\mathbf{x})$ for input position $\mathbf{x}$ [14428-sparse-view-and-few-shot-optimization.md].
    b. Pass $\gamma(\mathbf{x})$ through Network $A$ to obtain latent code $\mathbf{h}$ and density $\sigma$.
    c. Pass $\mathbf{h}$, $\gamma(\mathbf{x})$, and view direction $\gamma(\mathbf{d})$ through Network $F$ to predict color $\mathbf{c}$.
    d. Render the image using standard volume rendering integration with $\sigma$ and $\mathbf{c}$.
    e. Backpropagate errors through $A$ and $F$.
2.  **Inference Phase:**
    a. Compute $\gamma(\mathbf{x})$ and pass through Network $A$ to get $\mathbf{h}$ and $\sigma$.
    b. Pass $\mathbf{h}$ and $\gamma(\mathbf{d})$ through Network $H$ to predict color $\mathbf{c}$.
    c. Render using $\sigma$ and $\mathbf{c}$.
    d. Networks $A$ and $F$ are discarded or unused to save computation time [S1].

**Parameters:**
*   Hidden units in $A$ and $F$: 384 [S1].
*   Hidden layers in $H$: 2 [S1].
*   Hidden units in $H$: 16 [S1].

**Edge Cases and Pitfalls:**
*   **Hardware Constraints:** Texture storage for features must adhere to power-of-2 limits (max $4096 \times 4096$) on mobile hardware [S1].
*   **Alpha Channel Packing:** To save texture memory, the alpha (opacity) channel is squeezed into the first feature channel. Alpha is 1 if the first feature channel is non-zero, and 0 if zero [S1].

## Operating characteristics
*   **Time Complexity:** Training is heavier due to larger hidden layers (384 vs 256) in networks $A$ and $F$, but inference is faster because the heavy network $F$ is replaced by the small network $H$ [S1].
*   **Memory Complexity:** Increased training memory due to larger MLPs. Inference memory is reduced by using the smaller network $H$.
*   **Strengths:** Optimized for mobile architectures where inference speed is critical. Allows trading training time for inference efficiency [S1].
*   **Limitations:** Requires separate training for $A, F$ and $H$. Not suitable for scenarios requiring dynamic view-dependent effects that $F$ might capture better than $H$ during inference.

## Background
This architecture is part of the MobileNeRF method, designed for efficient neural field rendering on mobile devices. It exploits the polygon rasterization pipeline to accelerate rendering. The specific network sizing choices (384 for training networks, 16 for inference) were made to accommodate the computational constraints of mobile hardware while maintaining visual fidelity [S1].
