# Multi-scale Joint Training Parameters

Also called: Multi-scale joint training loss weights

## Overview
Multi-scale joint training parameters are the hyperparameters that balance photometric and auxiliary losses across different training stages or resolutions in neural radiance field optimization [S1]. The method explicitly ties loss weights to a multi-stage progression to stabilize gradient signals during dynamic network growth [S1].

## How it works
The method defines a composite loss function that aggregates errors from multiple network stages or resolution levels [S1]. The primary inputs are the rendered images from each stage $i$ and their corresponding ground truth images [S1]. The outputs are the scalar loss values used to update the network weights [S1].

### Data Structures and Formulas
The total loss $\mathcal{L}$ is computed as a weighted sum over $D$ stages (where $D$ corresponds to the current number of stages or network growth depth) [S1]:

$$
\mathcal{L} = \sum_{i=1}^D \beta_1 \mathcal{L}_{MSE}^i + \beta_2 \mathcal{L}_{unct}^i
$$

Where:
* $D$: The current number of stages in the training hierarchy [S1].
* $\mathcal{L}_{MSE}^i$: The Mean Squared Error (photometric) loss for the output image of stage $i$ [S1].
* $\mathcal{L}_{unct}^i$: The uncertainty loss for the output image of stage $i$ [S1].
* $\beta_1$: The weight for the photometric (MSE) loss component [S1].
* $\beta_2$: The weight for the uncertainty loss component [S1].

### Parameters
* $\beta_1 = 1.0$ [S1].
* $\beta_2 = 0.1$ [S1].
These values are empirically determined to balance the contribution of pixel fidelity against the regularization provided by the uncertainty term [S1].

### Pseudocode
The following Python-like pseudocode illustrates the computation of the joint loss for a given batch of stages [S1].

```python
def compute_multi_scale_joint_loss(rendered_images, ground_truth_images, uncertainty_maps, beta1=1.0, beta2=0.1):
    """
    Computes the multi-scale joint training loss.
    Args:
        rendered_images: List of arrays, shape (N, H, W, 3), for each stage i.
        ground_truth_images: List of arrays, shape (N, H, W, 3), for each stage i.
        uncertainty_maps: List of arrays, shape (N, H, W, 1), for each stage i.
        beta1: Weight for MSE loss (default 1.0).
        beta2: Weight for uncertainty loss (default 0.1).
    Returns:
        total_loss: Scalar value.
    """
    total_loss = 0.0
    for i in range(len(rendered_images)):
        # MSE loss: mean squared difference between rendered and ground truth images
        mse_loss = sum((rendered_images[i] - ground_truth_images[i]) ** 2) / rendered_images[i].size
        # Uncertainty loss formulation not specified in sources [G]
        unct_loss = uncertainty_maps[i].mean()
        # Weighted sum for this stage
        total_loss += beta1 * mse_loss + beta2 * unct_loss
    return total_loss
```

### Edge Cases and Pitfalls
* **Precision:** Not given in the sources [G].
* **Stage Count ($D$):** $D$ changes as the network expands during dynamic growth [S1].
* **Downsampling Scale:** Excessively large downsampling factors lead to blurry ground truth, decreasing fidelity and increasing refinement difficulty [S2].

## Subtopics

### Cross-intrinsic Guidance
A coarse-to-fine training scheme that uses different camera intrinsic parameters to construct an image pyramid, enhancing multi-scale feature learning [S2]. It sets itself apart by modifying the camera projection matrix $K$ at each scale rather than just the image resolution, thereby enforcing multi-view consistency through geometric constraints [S2]. Choose this method when training multi-view Gaussian Splatting or NeRF variants where view-dependent noise is significant and multi-view consistency is critical [S2].

* **Definition:** Constructs a 4-layer image pyramid with downsampling factors $S = \{2^{k-1} \mid k = 4, 3, 2, 1\}$ [S2].
* **Step 1:** For each layer $s \in S$, reconfigure the intrinsic matrix $K$ by dividing the focal length $f$ and principal point coordinates $c_x, c_y$ by $s$:
  $$
  K'_s = \begin{bmatrix} f/s & 0 & c_x/s \\ 0 & f/s & c_y/s \\ 0 & 0 & 1 \end{bmatrix}
  $$
* **Step 2:** Assign matched multi-view settings $M_s = \{M_4, M_3, M_2, M_1\}$ to each layer [S2].
* **Step 3:** Larger downsampling factors (coarser layers) use more views to provide stronger multi-view constraints [S2].
* **Step 4:** Run only a few thousand iterations per stage for the first three coarse stages ($s=8, 4, 2$) [S2].
* **Step 5:** Start fine training ($s=1$) to refine details [S2].
* **Parameters:** $S$ is the set of downsampling factors $\{1, 2, 4, 8\}$ [S2]. The largest factor $s=8$ is empirically sufficient; $s=1$ means no downsampling [S2].
* **Pitfalls:** Excessively large downsampling factors lead to blurry ground truth, decreasing fidelity and increasing refinement difficulty [S2].

## Operating characteristics
* **Time Complexity:** Not given in the sources [G].
* **Memory Complexity:** Not given in the sources [G].
* **Strengths:** Stabilizes gradient-based optimization in multi-view settings by reinforcing scene features and minimizing view-dependent noise [S2].
* **Limitations:** Coarse stages cannot capture sufficient details, requiring a subsequent fine-tuning phase [S2].
* **When to use:** When training multi-view Gaussian Splatting or NeRF variants where view-dependent noise is significant and multi-view consistency is critical [S2].

## Background
The concept of multi-scale joint training parameters originates from Recursive-NeRF, which introduced an efficient and dynamically growing NeRF architecture [S1]. The specific weights $\beta_1=1.0$ and $\beta_2=0.1$ were proposed to balance MSE and uncertainty losses in this dynamic growth framework [S1]. The related Cross-intrinsic Guidance variant was introduced in MVGS (Multi-view-regulated Gaussian Splatting) to address multi-view consistency issues by leveraging camera intrinsic parameter variations [S2].
