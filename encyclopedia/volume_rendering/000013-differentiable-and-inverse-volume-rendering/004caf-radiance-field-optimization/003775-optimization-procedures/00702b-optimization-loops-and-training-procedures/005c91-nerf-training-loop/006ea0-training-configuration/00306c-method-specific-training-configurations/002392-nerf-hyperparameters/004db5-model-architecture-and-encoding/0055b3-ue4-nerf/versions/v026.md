# UE4-NeRF


## Overview
UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale 3D scenes by integrating Neural Radiance Fields (NeRF) with the Unreal Engine 4 (UE4) rasterization pipeline [S1]. It partitions large environments into sub-NeRFs, representing each block using textured polygonal meshes initialized from regular octahedra, and utilizes a Level of Detail (LOD) hierarchy to maintain high frame rates at varying observation heights [S1]. Unlike Block-NeRF, which is limited to grid structures, UE4-NeRF supports diverse terrains including mountainous areas, and unlike Mobile-NeRF, it handles tilted surfaces and semi-transparent objects more effectively [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** A set of posed camera images (typically drone-captured) with GPS metadata; camera intrinsics and extrinsics; a large-scale scene bounding box [S1].
*   **Outputs:** A set of textured polygonal meshes (shading meshes) for each scene block at multiple Levels of Detail (LOD); a neural shader (HLSL fragment shader) deployed in UE4; real-time rendered RGB images [S1].

**Data Structures**
1.  **Scene Partitioning:** The large scene is divided into overlapping blocks [S1]. Each training area is slightly larger than the corresponding scene area to ensure smooth transitions at boundaries [S1].
2.  **Mesh Representation:** Each block is represented by a textured polygonal mesh [S1]. The mesh is initialized from a grid and optimized during training [S1]. The texture atlas stores feature vectors and opacity information [S1].
3.  **Coordinate System:** X-axis points east, Y-axis points south, Z-axis points up [S1]. The world scale is 100:1 (UE4 units to real-world units) [S1].
4.  **Network Architecture:** The Encoder is a 4-layer MLP with dimensions $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1]. It takes multi-resolution hash-encoded position features and outputs an opacity scalar $\alpha$ and an 8-dimensional feature vector $\mathbf{m}$ [S1]. The Decoder is a 3-layer MLP with dimensions $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1]. It takes the feature vector $\mathbf{m}$ and spherical harmonics coefficients of the view direction to predict the final RGB color $\mathbf{c}$ [S1].

**Method Steps**

1.  **Preprocessing and Coordinate Transformation:** Convert GPS-captured drone imagery coordinates to the UE4 coordinate system (X=East, Y=South, Z=Up) and apply the 100:1 scale conversion [S1].
2.  **Block Partitioning:** Partition the large-scale scene into multiple blocks (sub-NeRFs) [S1]. Train a coarse model for sub-region segmentation to capture overall terrain and building outlines [S1]. Filter images associated with each sub-region and apply a mask to exclude pixels outside the specific scene area [S1].
3.  **Mesh Initialization:** Initialize a $128 \times 128 \times 128$ grid for each block [S1]. Select the center point of each grid cell along with its six neighboring grids (front, back, left, right, top, bottom) to form the initial polygonal mesh structure [S1]. Use regular octahedra with 20 faces (8 exterior, 12 interior) instead of the Mobile-NeRF approach to address slow/unstable convergence on tilted surfaces [S1].
4.  **Training (Optimization):** For each block, optimize the Encoder-Decoder network parameters and the vertex positions of the meshes simultaneously [S1]. Use multi-resolution hash encoding (from Instant-NGP) for the position input $p_i$ to accelerate training [S1]. Represent the viewing direction $d$ using spherical harmonics $SH(d)$ [S1]. Compute opacity and feature vector via $\mathbf{m}_i, \alpha_i = E(\text{hash}(p_i); \theta_E)$ [S1]. Compute color via $\mathbf{c}_i = D(\mathbf{m}_i, SH(d_i); \theta_D)$ [S1]. Minimize the difference between rendered colors and ground truth images using PSNR/SSIM and LPIPS metrics [S1]. Implement computationally intensive portions using CUDA on NVIDIA GPUs (e.g., RTX 3090) [S1]. Train for 80,000 epochs per block to achieve convergence [S1].
5.  **Shading Mesh Extraction:** Extract coarse polygonal meshes without textures during training [S1]. Apply vertex optimization results [S1]. Encode texture maps (feature vectors and opacity) into the network outputs [S1].
6.  **Level of Detail (LOD) Generation:** Train meshes with varying levels of detail for different observation heights [S1]. Coarser meshes are used for higher observation heights to ensure real-time performance [S1]. Extract pre-rendered polygonal meshes at different LODs for the final rendering module [S1].
7.  **Rendering in UE4:** Deploy the Encoder-Decoder network as an HLSL fragment shader in UE4 [S1]. The shader takes feature vectors (from the texture atlas) as input and outputs colors [S1]. Combine the extracted LOD meshes with the UE4 rasterization pipeline [S1]. UE4 handles occlusion automatically; if traditional 3D models (e.g., .obj, .fbx) are imported, the neural shader computation is skipped for occluded regions [S1].

**Parameters**

*   **Coordinate System:** X=East, Y=South, Z=Up [S1].

**Edge Cases and Pitfalls**
*   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces; UE4-NeRF addresses this by using regular octahedra [S1].
*   **Semi-transparent Objects:** Mobile-NeRF cannot handle transparent/semi-transparent objects (water, glass, plastic) due to opacity binarization [S1]. UE4-NeRF stores opacity in texture maps to mitigate this, though semi-transparent objects (e.g., vegetation) increase computational overhead and reduce frame rates [S1].
*   **Pre-rendering Gaps:** Pre-rendering cannot capture rays from all viewing angles, potentially resulting in gaps or holes in the final rendered scene [S1].
*   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, causing evaluation metrics (PSNR/SSIM/LPIPS) to underestimate actual reconstruction quality [S1].
*   **Memory Overhead:** Rendering large scenes (square kilometers) incurs significant memory overhead, especially when using CUDA and NVIDIA GPUs [S1]. Increasing accuracy further amplifies memory consumption [S1].

## Operating characteristics
*   **Training Speed:** 1000× faster than Mobile-NeRF [S1]. Training time per block is 40 minutes on 1×RTX 3090 [S1]. Training time for a full scene of $n$ blocks is 1 hour + (40 minutes × $n$/4) on 1×RTX 3090 [S1].
*   **Rendering Performance:** Real-time rendering at 4K resolution achieves up to 43 FPS [S1]. Full scene rendering at 2K resolution achieves 50 FPS [S1]. Individual block rendering at 2K resolution achieves ≥70 FPS [S1].
*   **Memory:** Significant memory overhead for large scenes (square kilometers) [S1]. Requires NVIDIA GPUs and CUDA [S1].
*   **Strengths:** Real-time interactive rendering of large-scale scenes [S1]. Handles tilted surfaces and semi-transparent objects better than Mobile-NeRF [S1]. Supports scene editing with traditional 3D models [S1]. Suitable for diverse terrains (mountainous, farmland) unlike Block-NeRF [S1].
*   **Limitations:** Pre-rendering gaps/holes [S1]. Exposure matching issues in UE4 [S1]. High memory consumption [S1]. Semi-transparent objects reduce frame rates [S1]. Requires NVIDIA GPUs [S1].
*   **When to Use:** Real-time interactive rendering of large-scale outdoor scenes (e.g., digital twins, VR, games) where high fidelity and editability are required [S1].
*   **When Not to Use:** Scenes requiring perfect ray-casting from all angles without pre-rendering artifacts; environments with extremely high densities of semi-transparent objects where frame rate is critical; hardware without NVIDIA GPUs/CUDA support [S1].

## Background
UE4-NeRF was introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" [S1]. It was developed to address the limitations of existing NeRF methods in real-time rendering of large-scale scenes, such as high training costs, slow rendering speeds, and lack of editability [S1]. The method combines NeRF with the Unreal Engine 4 (UE4) rasterization pipeline, leveraging LOD techniques and multi-resolution hash encoding to achieve real-time performance [S1]. It is used in UE4 for real-time interactive rendering and scene editing/manipulation, particularly for drone-captured large-scale scenes like farmlands, construction sites, and industrial parks, and has been evaluated on the Mega-NeRF public dataset [S1].
