# SUDS
Also called: SUDS, Scalable Urban Dynamic Scenes

## Overview
SUDS is a 4D radiance field representation designed for large-scale dynamic urban scenes that factorizes the scene into three separate hash table data structures to efficiently encode static, dynamic, and far-field radiance fields [S1]. It distinguishes itself from sibling methods like [Neural Scene Graphs](17706-neural-scene-graphs.md) and [UrbanIR](16200-urbanir.md) by eliminating the need for supervised 3D bounding boxes or panoptic labels, instead relying on unlabeled RGB, sparse LiDAR, and optical flow to learn scene flow and semantic decomposition [S1]. Unlike [Mip-NeRF 360 MLP Architecture](14098-mip-nerf-360-mlp-architecture.md) which focuses on static environments, SUDS explicitly models temporal dynamics and ego-motion across multiple video inputs [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** $N$ ordered RGB images from different videos (varying days/weather), associated camera poses, aligned sparse LiDAR depth, 2D self-supervised DINO descriptors, and 2D optical flow predictions [S1].
*   **Outputs:** Per-branch color, density, semantic features, scene flow vectors, and shadow ratios for any position $x$, direction $d$, time $t$, and video ID $vid$ [S1].

**Data Structures:**
The scene is decomposed into $K$ spatial cells with centroids $k \in \mathbb{R}^3$. Each cell contains three multi-resolution hash table branches:
1.  **Static Branch:** 3D spatial voxels $v_{l,s}$.
2.  **Dynamic Branch:** 4D spacetime voxels $v_{l,d}$.
3.  **Far-field Branch:** 3D direction voxels $v_{l,e}$ (normalized direction vectors) [S1].

Each table has $L$ resolution levels, doubling resolution between levels. Features are $F$-dimensional vectors [S1].

**Hash Indexing:**
Instead of storing features at voxel corners, indices are computed via hash functions [S1]:
$$ i_{l,s} = \text{static hash}(\text{space}(v_{l,s})) $$
$$ i_{l,d} = \text{dynamic hash}(\text{space}(v_{l,d}), \text{time}(v_{l,d}), vid) $$
$$ i_{l,e} = \text{env hash}(\text{dir}(v_{l,e}), vid) $$
The video ID $vid$ is included in the dynamic and far-field hashes to index separate interpolating functions per video without linear memory growth [S1]. Hash collisions are handled via gradient averaging [S1].

**Feature Interpolation:**
Features are linearly interpolated to the nearest voxel vertices. Quadlinear interpolation is used for the 4D dynamic branch. Results from all $L$ levels are concatenated into a feature vector $f \in \mathbb{R}^{LF}$ [S1].

**MLP Evaluation:**
The concatenated feature vector $f$ and auxiliary inputs (viewing direction $d$, video-specific lighting embedding $A_{vid}F(t)$) are passed to an MLP [S1].
*   **Static Output:** View-dependent color $c_s(x, d, A_{vid}F(t)) \in \mathbb{R}^3$ and view-independent density $\sigma_s(x) \in \mathbb{R}$ [S1].
*   **Dynamic Output:** Time/video-dependent density $\sigma_d(x, t, vid) \in \mathbb{R}$, color $c_d(x, t, vid, d) \in \mathbb{R}^3$, shadow ratio $\rho_d(x, t, vid) \in [0, 1]$, and 3D scene flow $s_{t0}(x, t, vid) \in \mathbb{R}^3$ (values in $[-1, 1]$) [S1].
*   **Far-field Output:** Environment map color $c_e(d, vid) \in \mathbb{R}^3$ [S1].
*   **Semantic Output:** $C$-dimensional feature logits $\Phi_s, \Phi_d, \Phi_e$ for each branch [S1].

**Density and Radiance Combination:**
Total density is the sum of static and dynamic components:
$$ \sigma(x, t, vid) = \sigma_s(x) + \sigma_d(x, t, vid) $$
Total radiance combines static and dynamic components, scaled by the shadow ratio:
$$ c(x, t, vid, d) = \frac{(1 - \rho_d)\sigma_s c_s + \sigma_d c_d}{\sigma} $$
Rendering along a ray $r(t)$ accumulates transmittance $T(t) = \exp(-\int_0^t \sigma(r(s), t, vid) ds)$:
$$ \hat{C}(r, t, vid) = \int_0^{+\infty} T(t)\sigma(r(t), t, vid)c(r(t), t, vid, d)dt + T(+\infty)c_e(d, vid) $$
Semantic features $\Phi$ are combined and rendered similarly [S1].

**Training Loop:**
1.  **Spatial Partitioning:** Split scene into $K$ cells. Generate training datasets for each cell by including only camera rays intersecting the cell and pruning rays using LiDAR depth to ensure visibility [S1].
2.  **Sampling:** Sample 4098 rays per batch using a proposal sampling strategy similar to Mip-NeRF 360 [S1].
3.  **Forward Pass:** Compute hash indices, interpolate features, evaluate MLPs, and render color, features, and depth for all branches [S1].
4.  **Loss Calculation:** Compute reconstruction, flow, warping, regularization, and factorization losses (see below) [S1].
5.  **Optimization:** Update parameters using Adam optimizer [S1].

**Loss Functions:**
*   **Reconstruction:** L2 photometric loss $L_c(r) = ||C(r) - \hat{C}(r)||^2$ and L1 feature loss $L_f(r) = ||F(r) - \hat{F}(r)||_1$ [S1].
*   **Depth:** L2 loss between rendered depth $\hat{D}(r)$ and LiDAR $D(r)$: $L_d(r) = ||D(r) - \hat{D}(r)||^2$ [S1].
*   **Flow:** Predict 3D position $\hat{X}_{t0}(r)$ using scene flow, render to 2D, and minimize distance from observed optical flow $O$: $L_o(r) = \sum_{t0} ||X(o) - \hat{X}_{t0}(r)||_1$ [S1].
*   **Warping:** Advect samples using flow to get warped density/color/features. Render warped color $\hat{C}^w$ and feature $\hat{F}^w$. Minimize $L_c^w$ and $L_f^w$ downweighted by ambiguity weight $W_{t0}(r)$ [S1].
*   **Flow Regularization:** Cycle consistency $L_{cyc}(r) = \sum_{t0} \sum_x w_{t0}(x,t) ||s_{t0}(x,t) + s_t(x+s_{t0}, t-t0)||_1$, spatial/temporal smoothness $L_{sm}$, and static scene prior $L_{slo} = \sum_{t0} \sum_x ||s_{t0}(x,t)||_1$ [S1].
*   **Static-Dynamic Factorization:** Skewed binary entropy loss $L_e(r) = \int_0^{+\infty} H(\frac{\sigma_d}{\sigma_s + \sigma_d}) dt$ with $k=1.75$ (where $H(x) = -(x \log x + (1-x) \log (1-x))$) and max dynamic ratio penalty $L_d(r) = \max(\frac{\sigma_d}{\sigma_s + \sigma_d})$ along each ray [S1].
*   **Shadow Loss:** Penalize squared shadow ratio $L_\rho(r) = \int_0^{+\infty} \rho_d(r(t))^2 dt$ [S1].

**Parameters:**
*   $F$: Feature vector dimensionality [S1].
*   $L$: Number of resolution levels [S1].
*   $N$: Number of input videos [S1].
*   $C$: DINO feature dimensionality [S1].
*   $k$: Constant 1.75 for entropy loss [S1].
*   Training: 250,000 iterations, 4098 rays/batch, Adam LR $5 \times 10^{-3}$ decaying to $5 \times 10^{-4}$ [S1].

## Operating characteristics
*   **Scale:** Scales to tens of thousands of objects across 1.2 million frames from 1700 videos spanning hundreds of kilometers [S1].
*   **Performance:** 10x quicker to train than methods requiring ground truth 3D bounding box annotations [S1].
*   **Memory:** Uses multi-resolution hash tables to avoid linear memory growth with the number of videos, unlike object-centric methods like [Neural Scene Graphs](17706-neural-scene-graphs.md) which require over 1TB for short videos [S1].
*   **Strengths:** Handles ego-motion, multi-video representations, and large-scale urban scenes without manual labeling [S1].
*   **Limitations:** Relies on the quality of self-supervised descriptors (DINO) and optical flow; performance depends on the accuracy of sparse LiDAR alignment [S1].

## Background
SUDS was introduced in 2023 by researchers aiming to build the largest dynamic NeRF to date, addressing the limitations of prior methods that required supervised inputs like panoptic segmentation labels or bounding boxes [S1]. It builds on [Instant-NGP](14098-mip-nerf-360-mlp-architecture.md) by using multi-resolution hash tables and extends [MegaNeRF](14098-mip-nerf-360-mlp-architecture.md) by adding dynamic and semantic branches [S1]. It is used for free-viewpoint rendering, unsupervised 3D instance segmentation, and 3D cuboid detection in urban environments [S1].
