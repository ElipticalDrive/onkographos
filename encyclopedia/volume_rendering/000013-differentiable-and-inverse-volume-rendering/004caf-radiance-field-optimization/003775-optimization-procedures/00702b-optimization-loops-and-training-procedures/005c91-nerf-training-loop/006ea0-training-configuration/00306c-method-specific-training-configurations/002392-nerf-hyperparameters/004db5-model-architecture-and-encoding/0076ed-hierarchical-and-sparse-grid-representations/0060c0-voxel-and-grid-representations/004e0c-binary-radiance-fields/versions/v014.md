# Binary Radiance Fields

Also called: BRF

## Overview
Binary Radiance Fields (BiRF) is a storage-efficient radiance field representation that constrains feature grid parameters to binary values (+1 or -1) to achieve compact storage without post-processing compression [S1]. It differs from real-valued hash-based methods (like Instant-NGP) by using 1-bit storage for features and from post-training compression methods (like PlenOctrees) by performing binarization during the optimization loop [S1]. It builds on [Model Architecture and Encoding](13550-model-architecture-and-encoding.md) by replacing real-valued feature grids with a 2D-3D hybrid binary structure.

## How it works
**Inputs and Outputs:**
*   **Input:** 3D spatial coordinate $\mathbf{x} \in \mathbb{R}^3$, viewing direction $\mathbf{d} \in S^2$.
*   **Output:** Volume density $\sigma \in \mathbb{R}_{\ge 0}$, RGB color $\mathbf{c} \in [0, 1]^3$.

**Data Structures:**
The representation consists of four multi-resolution feature grids implemented using hash encoding [S1]:
1.  One 3D voxel grid $\Phi_{\theta_{xyz}}$.
2.  Three 2D plane grids $\Phi_{\theta_{xy}}$, $\Phi_{\theta_{xz}}$, $\Phi_{\theta_{yz}}$.

All grid parameters are binary, stored as 1-bit values representing +1 or -1 [S1]. The grids are organized into levels (resolutions).
*   **3D Grid Levels ($L$):** Resolutions range from 16 to 1024. Each level holds up to $T_{3D}$ feature vectors.
*   **2D Grid Levels ($M$):** Resolutions range from 64 to 512. Each level holds up to $T_{2D}$ feature vectors.
*   **Feature Dimension ($F$):** The dimension of the feature vector per level. Model variants scale with $F \in \{2, 4, 8\}$ [S1].

**Parameters:**
*   $\lambda_{\text{sparsity}}$: Weight for sparsity loss. Default: $2.0 \times 10^{-5}$ [S1].
*   $T_{3D}$: Max feature vectors per 3D level. Small model (Ours-S): $\log_2(T_{3D}) = 17$. Base model (Ours-B): $\log_2(T_{3D}) = 19$ [S1].
*   $T_{2D}$: Max feature vectors per 2D level. Small model (Ours-S): $\log_2(T_{2D}) = 15$. Base model (Ours-B): $\log_2(T_{2D}) = 17$ [S1].
*   MLPs: Shallow networks with 128-channel hidden layers and ReLU activation. Density MLP has 1 hidden layer; Color MLP has 2 hidden layers [S1].

**Algorithm Steps:**

1.  **Binarization:** During training, real-valued grid parameters $\theta$ are transformed to binary $\theta'$ using the sign function:
    $$
    \theta' = \text{sign}(\theta) = \begin{cases} +1 & \text{if } \theta \ge 0 \\ -1 & \text{otherwise} \end{cases}
    $$
    Gradients are propagated using the Straight-Through Estimator (STE). The gradient is passed if $|\theta| \le 1$, otherwise it is zeroed to prevent scale divergence [S1].

2.  **Feature Encoding:**
    *   **3D Features ($f_{xyz}$):** For input $\mathbf{x}$, compute features by tri-linearly interpolating the binary parameters of the 3D grid across $L$ levels and concatenating them:
        $$
        f_{xyz} = \left\{ \text{interp}(\mathbf{x}, \text{sign}(\Phi^l_{\theta_{xyz}})) \right\}_{l=1}^L
        $$
    *   **2D Features ($f_{xy}, f_{xz}, f_{yz}$):** Project $\mathbf{x}=(x,y,z)$ to 2D coordinates: $\mathbf{x}_{xy}=(x,y)$, $\mathbf{x}_{xz}=(x,z)$, $\mathbf{x}_{yz}=(y,z)$. For each axis, bi-linearly interpolate binary parameters across $M$ levels and concatenate:
        $$
        f_{xy} = \left\{ \text{interp}(\mathbf{x}_{xy}, \text{sign}(\Phi^m_{\theta_{xy}})) \right\}_{m=1}^M
        $$
        Repeat for $f_{xz}$ and $f_{yz}$ [S1].

3.  **Feature Concatenation:** Combine all encoded features:
    $$
    f = \{ f_{xyz}, f_{xy}, f_{xz}, f_{yz} \}
    $$

4.  **Positional Encoding:** Apply sinusoidal positional encoding $\gamma(\mathbf{x})$ to the input coordinate $\mathbf{x}$ [S1].

5.  **Density Prediction:** Feed $\gamma(\mathbf{x})$ and $f$ into the density MLP:
    $$
    (\sigma, e) = \text{MLP}_{\text{density}}(\gamma(\mathbf{x}), f)
    $$
    where $e$ is the embedded feature and $\sigma$ is the raw density [S1].

6.  **Color Prediction:** Feed $e$ and directional encoding $\mathbf{d}$ (using spherical harmonics) into the color MLP:
    $$
    \mathbf{c} = \text{MLP}_{\text{color}}(e, \mathbf{d})
    $$

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** 3D grids suffer from hash collisions at higher resolutions. The 2D grids supplement the 3D grid to alleviate this impact and reinforce features with fewer parameters [S1].
*   **Gradient Vanishing:** The derivative of the sign function is zero almost everywhere. The Straight-Through Estimator (STE) is required to pass gradients through the threshold function during training [S1].
*   **Scale Divergence:** Large values of $\theta$ can cause divergence. The STE implementation stops propagating gradients when $|\theta| > 1$, constraining the value to $\{-1, 1\}$ [S1].

## Operating characteristics
*   **Storage:** Extremely compact. The Ours-S2 variant requires < 0.5 MB for Synthetic-NeRF scenes [S1]. This outperforms TensoRF-CP (3.7 MB) and Instant-NGP (24.5 MB) on the mic scene [S1].
*   **Performance:** Achieves PSNR of 32.03 dB on Synthetic-NeRF, 34.48 dB on Synthetic-NSVF, and 28.20 dB on Tanks and Temples [S1].
*   **Training Time:** Approximately 6, 9, and 14 minutes for Ours-B2 to Ours-B8 models on Synthetic-NeRF scenes (20K iterations on NVIDIA RTX A6000) [S1].
*   **Strengths:** Storage efficiency without post-processing; comparable or better reconstruction quality than larger baselines; fast training.
*   **Limitations:** Binary constraints may limit representational capacity compared to full-precision models; hash collisions in 3D grid require careful resolution management [S1].
*   **When to use:** When storage is a critical bottleneck and high-fidelity real-valued models are too large.
*   **When not to use:** When maximum possible reconstruction quality is required regardless of storage size.

## Background
Binary Radiance Fields were proposed by Seungjoo Shin and Jaesik Park from POSTECH and Seoul National University, published in arXiv:2306.07581v2 on December 4, 2023 [S1]. The method addresses the storage bottleneck of neural radiance fields by introducing binary feature encoding. It builds on the multi-resolution hash encoding architecture of Instant-NGP [S1].
