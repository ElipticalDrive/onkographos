# Binary Radiance Fields

Also called: BRF

## Overview
Binary Radiance Fields (BiRF) is a storage-efficient radiance field representation that constrains feature grid parameters to binary values (+1 or -1) to achieve compact storage without post-training compression [S1]. Unlike post-processing compression methods such as PlenOctrees or Re:NeRF, which require additional optimization steps and are bounded by pre-trained model performance, BiRF performs binarization during training using a straight-through estimator, allowing for end-to-end optimization with significantly reduced memory footprint [S1]. It builds on [Model Architecture and Encoding](13550-model-architecture-and-encoding.md) by replacing real-valued hash grid parameters with binary ones, utilizing a 2D-3D hybrid multi-resolution architecture to mitigate hash collisions inherent in high-resolution 3D grids [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D coordinate $\mathbf{x} = (x, y, z)$ and a viewing direction $\mathbf{d} = (\theta, \phi)$.
*   **Output:** Volume density $\sigma$ and color $\mathbf{c} = (r, g, b)$.

**Data Structures:**
The radiance field consists of a multi-resolution 2D-3D hybrid feature grid implemented using hash encoding [S1].
1.  **3D Voxel Grid ($\Phi_{\theta_{xyz}}$):** Contains $L$ resolution levels. Resolutions range from 16 to 1024. Each level holds up to $T_{3D}$ feature vectors.
2.  **2D Plane Grids ($\Phi_{\theta_{xy}}, \Phi_{\theta_{xz}}, \Phi_{\theta_{yz}}$):** Three orthogonal grids. Each contains $M$ resolution levels. Resolutions range from 64 to 512. Each level holds up to $T_{2D}$ feature vectors.
3.  **Parameter Storage:** All grid parameters are binary, stored as 1-bit values (+1 or -1) [S1].
4.  **MLPs:**
    *   Density MLP: 1 hidden layer, 128 channels, ReLU activation.
    *   Color MLP: 2 hidden layers, 128 channels, ReLU activation.
    *   Directional Encoding: Spherical Harmonics basis functions [S1].

**Parameters:**
*   $L$: Number of 3D grid levels.
*   $M$: Number of 2D grid levels.
*   $T_{3D}$: Max feature vectors per 3D level.
*   $T_{2D}$: Max feature vectors per 2D level.
*   $F$: Feature dimension per level. Variants use $F \in \{2, 4, 8\}$ [S1].
*   $\lambda_{\text{sparsity}}$: Sparsity loss weight. Value: $2.0 \times 10^{-5}$ [S1].
*   Model Variants:
    *   Small (Ours-S): $\log_2(T_{3D}) = 17$, $\log_2(T_{2D}) = 15$ [S1].
    *   Base (Ours-B): $\log_2(T_{3D}) = 19$, $\log_2(T_{2D}) = 17$ [S1].

**Algorithm Steps:**

1.  **Binarization (Training):**
    During training, real-valued grid parameters $\theta$ are constrained to binary values $\theta'$ using the sign function [S1]:
    $$
    \theta' = \text{sign}(\theta) = \begin{cases} +1 & \text{if } \theta \ge 0 \\ -1 & \text{otherwise} \end{cases}
    $$
    Gradients are propagated using the Straight-Through Estimator (STE) [S1]:
    $$
    \frac{\partial L}{\partial \theta} = \begin{cases} \frac{\partial L}{\partial \theta'} & \text{if } |\theta| \le 1 \\ 0 & \text{otherwise} \end{cases}
    $$
    This prevents scale divergence by stopping gradient propagation when $|\theta| > 1$ [S1].

2.  **Feature Extraction (3D):**
    For input coordinate $\mathbf{x}$, compute features from the 3D grid by tri-linearly interpolating the binary parameters across $L$ resolution levels and concatenating them [S1]:
    $$
    \mathbf{f}_{xyz} = \left\{ \text{interp}(\mathbf{x}, \text{sign}(\Phi^l_{\theta_{xyz}})) \right\}_{l=1}^L
    $$
    where $\text{interp}$ denotes tri-linear interpolation [S1].

3.  **Feature Extraction (2D):**
    Project $\mathbf{x}$ onto the three orthogonal planes: $\mathbf{x}_{xy} = (x, y)$, $\mathbf{x}_{xz} = (x, z)$, $\mathbf{x}_{yz} = (y, z)$ [S1]. For each plane, bi-linearly interpolate binary parameters across $M$ resolution levels and concatenate [S1]:
    $$
    \mathbf{f}_{xy} = \left\{ \text{interp}(\mathbf{x}_{xy}, \text{sign}(\Phi^m_{\theta_{xy}})) \right\}_{m=1}^M
    $$
    Repeat for $\mathbf{f}_{xz}$ and $\mathbf{f}_{yz}$ [S1].

4.  **Feature Concatenation:**
    Combine all encoded features [S1]:
    $$
    \mathbf{f} = \{ \mathbf{f}_{xyz}, \mathbf{f}_{xy}, \mathbf{f}_{xz}, \mathbf{f}_{yz} \}
    $$

5.  **Positional Encoding:**
    Apply sinusoidal positional encoding $\gamma(\mathbf{x})$ to the input 3D coordinate [S1].

6.  **Density Prediction:**
    Feed $\gamma(\mathbf{x})$ and $\mathbf{f}$ into the density MLP to obtain density $\sigma$ and embedding feature $\mathbf{e}$ [S1]:
    $$
    (\sigma, \mathbf{e}) = \text{MLP}_{\text{density}}(\gamma(\mathbf{x}), \mathbf{f})
    $$

7.  **Color Prediction:**
    Feed $\mathbf{e}$ and directional encoding $\mathbf{d}$ (using spherical harmonics) into the color MLP to obtain color $\mathbf{c}$ [S1]:
    $$
    \mathbf{c} = \text{MLP}_{\text{color}}(\mathbf{e}, \mathbf{d})
    $$

**Loss Function:**
The total loss combines reconstruction loss and sparsity regularization [S1]:
$$
L = L_{\text{recon}} + \lambda_{\text{sparsity}} L_{\text{sparsity}}
$$
Where $L_{\text{recon}}$ is the mean squared error between rendered and ground truth colors [S1]. The sparsity loss uses Cauchy loss to encourage sparse density, accelerating rendering by allowing empty space skipping via an occupancy grid [S1]:
$$
L_{\text{sparsity}} = \sum_{i,k} \log(1 + 2\sigma(\mathbf{r}_i(t_k))^2)
$$
where $\mathbf{r}_i$ are sampled rays and $t_k$ are sample points [S1].

## Operating characteristics
*   **Storage Efficiency:** The model achieves significant storage reduction. The small model variant (Ours-S2) requires less than 0.5 MB of storage space [S1]. This outperforms baselines like TensoRF-CP (3.7 MB) and Instant-NGP (24.5 MB) on the mic scene while maintaining comparable or better PSNR [S1]. The total storage capacity of the MLPs varies from 0.06 to 0.11 MB depending on the feature dimension [S1].
*   **Performance:** On Synthetic-NeRF scenes, BiRF achieves a PSNR of 32.03 dB; on Synthetic-NSVF, 34.48 dB; and on Tanks and Temples, 28.20 dB [S1].
*   **Training Time:** Training takes approximately 6, 9, and 14 minutes for Ours-B2 to Ours-B8 models on Synthetic-NeRF scenes, respectively, on a single NVIDIA RTX A6000 GPU [S1].
*   **Strengths:**
    *   Extremely compact storage due to 1-bit binary parameters [S1].
    *   No post-processing compression required; binarization is integrated into training [S1].
    *   2D-3D hybrid design mitigates hash collisions common in high-resolution 3D grids [S1].
*   **Limitations:**
    *   Hash collisions in the 3D grid at higher resolutions can limit performance, necessitating the 2D supplement [S1].
    *   The derivative of the sign function is zero almost everywhere, requiring the Straight-Through Estimator (STE) for gradient flow, which can introduce quantization noise [S1].
    *   Large values of real-valued parameters $\theta$ can cause divergence if not constrained by STE [S1].
*   **When to use:** Suitable for applications requiring high storage efficiency and fast rendering with minimal memory footprint, such as mobile AR/VR or web-based 3D viewing, where post-processing compression is undesirable [S1].
*   **When not to use:** When maximum possible reconstruction fidelity is required regardless of storage size, as the binary constraint may limit the representational capacity compared to full-precision real-valued grids [S1].

## Background
Binary Radiance Fields were proposed by Seungjoo Shin and Jaesik Park from POSTECH and Seoul National University, respectively [S1]. The work was published on arXiv in June 2023 (v2 in December 2023) [S1]. The method builds upon the Instant-NGP architecture  and utilizes the occupancy grid implementation from NerfAcc . It addresses the storage bottleneck of neural radiance fields by introducing binary feature encoding, contrasting with prior efficient methods like TensoRF and Instant-NGP which rely on real-valued parameters or tensor decomposition [S1]. The approach is implemented based on Instant-NGP and trained on NVIDIA RTX A6000 hardware [S1].
