# NeRF Training Setup

Also called: Control-NeRF Training Setup

## Overview
This article defines the training configuration for the Control-NeRF method, which optimizes a radiance field conditioned on disentangled 3D feature volumes rather than raw 3D coordinates. It solves the problem of enabling explicit scene manipulation by replacing the standard positional encoding of 3D positions with sampled feature vectors. It differs from the standard NeRF baseline [11349-nerf-gt-baseline-training-setup.md] by using a 64-dimensional feature vector as the primary spatial input and omitting positional encoding on that vector, while retaining positional encoding for the viewing direction.

## How it works

### Inputs and Outputs
*   **Input:** A batch of rays $\mathbf{r}$ sampled from multi-view images. Each ray is defined by an origin and a direction vector $\mathbf{d} \in \mathbb{R}^3$.
*   **Output:** Predicted color $\mathbf{c}$ and volume density $\sigma$ for sampled points along the ray, used to render images via volume rendering.
*   **Supervision:** Pixel-wise color loss against ground truth images from the LLFF dataset.

### Data Structures
*   **Feature Volume ($V_s$):** A 3D grid storing 64-dimensional feature vectors for scene $s$.
*   **Sampled Feature Vector ($\mathbf{v}_s$):** A 64-dimensional vector obtained by trilinearly sampling $V_s$ at a point $\mathbf{p} \in \mathbb{R}^3$.
*   **Direction Encoding:** A high-dimensional vector derived from the ray direction $\mathbf{d}$.

### Numbered Steps

1.  **Ray Sampling:** Sample 1024 rays per batch from the LLFF multi-view image datasets. The images are scaled to a resolution of $504 \times 378$ [S1].
2.  **Direction Encoding:** For each ray with direction $\mathbf{d}$, compute the positional encoding $\gamma(\mathbf{d})$.
    *   Let $\mathbf{p}$ be each dimension of $\mathbf{d}$.
    *   Apply the encoding function with depth $L=4$:
        $$ \gamma(\mathbf{p}) = [\sin(2^0\pi\mathbf{p}), \cos(2^0\pi\mathbf{p}), \dots, \sin(2^{L-1}\pi\mathbf{p}), \cos(2^{L-1}\pi\mathbf{p})] $$
    *   Concatenate the encoded dimensions for all 3 dimensions of $\mathbf{d}$ to form the full direction input [S1].
3.  **Coarse Network Optimization ($\hat{C}_c$):**
    *   Sample 64 points from evenly spaced bins along the ray length [S1].
    *   For each point $\mathbf{p}$, retrieve the feature vector $\mathbf{v}_s = S(V_s, \mathbf{p})$ via trilinear sampling [S1].
    *   Input $(\mathbf{v}_s, \gamma(\mathbf{d}))$ into the coarse network $F_{\Theta_c}$ to predict density $\sigma$ and color $\mathbf{c}$.
    *   Note: No positional encoding is applied to $\mathbf{v}_s$ [S1].
4.  **Fine Network Sampling:**
    *   Use the opacity results (density $\sigma$) from the coarse network to determine the probability of ray termination at each sampled point [S1].
    *   Sample 64 additional points for the fine network $\hat{C}_f$ from these more relevant portions of the scene volume, following the hierarchical sampling strategy of [23] [S1].
5.  **Fine Network Optimization ($\hat{C}_f$):**
    *   For each of the 64 fine points $\mathbf{p}$, retrieve $\mathbf{v}_s = S(V_s, \mathbf{p})$ [S1].
    *   Input $(\mathbf{v}_s, \gamma(\mathbf{d}))$ into the fine network $F_{\Theta_f}$ to predict density and color [S1].
6.  **Volume Rendering:**
    *   Compute the final color $C(\mathbf{r})$ for the ray using the discretized approximation of the volume rendering integral [S1]:
        $$ C(\mathbf{r}) = \sum_{i=1}^{N} T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i $$
        where $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$ is the accumulated transmittance, $\sigma_i$ is the density, $\mathbf{c}_i$ is the color, and $\delta_i$ is the distance between samples [S1, G].
7.  **Loss Calculation:** Compute the loss between the rendered image and the ground truth image. The baseline includes multiscale loss and Total Variation (TV) regularization on the feature volume, as ablation studies show their removal degrades performance significantly (e.g., Avg. PSNR drops from 26.131 to 20.745 without them) [S1].

### Formulas
*   **Direction Positional Encoding:**
    $$ \gamma(\mathbf{p}) = [\sin(2^0\pi\mathbf{p}), \cos(2^0\pi\mathbf{p}), \dots, \sin(2^{L-1}\pi\mathbf{p}), \cos(2^{L-1}\pi\mathbf{p})] $$
    where $\mathbf{p}$ is a dimension of the direction vector $\mathbf{d}$ and $L=4$ [S1].
*   **Feature Sampling:**
    $$ \mathbf{v}_s = S(V_s, \mathbf{p}) $$
    where $S$ is trilinear sampling from volume $V_s$ at point $\mathbf{p}$ [S1].

### Parameters
*   **Positional Encoding Depth ($L$):** 4, applied to each dimension of the direction vector $\mathbf{d}$ [S1].
*   **Feature Vector Dimension:** 64 [S1].
*   **Batch Size:** 1024 rays [S1].
*   **Image Resolution:** $504 \times 378$ [S1].
*   **Coarse Samples:** 64 points per ray [S1].
*   **Fine Samples:** 64 points per ray [S1].
*   **Total Direction Input Size:** $3 \times 2 \times 4 = 24$ parameters (derived from $L=4$ and 3 dimensions) [S1, G].

### Edge Cases and Pitfalls
*   **Feature Volume Initialization:** The feature volume $V_s$ must be initialized appropriately (e.g., zeros or small random values) before training begins. [G]
*   **Trilinear Sampling:** Ensure that the feature volume is padded or handled correctly at boundaries to avoid out-of-bounds access during trilinear sampling. [G]
*   **Density Bias:** The density values sampled from the network are used to determine ray termination probabilities. Ensure that the network output is appropriately scaled or biased to avoid early ray termination or excessive computation. [G]

## Operating characteristics

### Time and Memory Complexity
*   **Memory:** Dominated by the storage of the 64-dimensional feature volume $V_s$. The size depends on the scene resolution and the 64-channel depth. The networks themselves are relatively small compared to the volume storage.
*   **Time:** Two-stage sampling (coarse + fine) doubles the number of network evaluations per ray compared to a single-stage approach, but allows for more efficient sampling by focusing on relevant volumes. The directional encoding is computed once per ray.

### Measured Performance
*   **Dataset:** LLFF multi-view image datasets [S1].
*   **Metrics:**
    *   **PSNR:** Average 26.131 (Fern: 25.752, T-Rex: 26.510) [S1].
    *   **SSIM:** Average 0.864 (Fern: 0.820, T-Rex: 0.907) [S1].
    *   **LPIPS:** Average 0.195 (Fern: 0.236, T-Rex: 0.153) [S1].
*   **Ablation Impact:** Removing multiscale loss and TV regularization causes a significant drop in performance (Avg. PSNR: 20.745, Avg. SSIM: 0.698, Avg. LPIPS: 0.345) [S1].

### Strengths and Limitations
*   **Strengths:** Enables explicit scene manipulation via feature volume editing. Uses a compact 64-dimensional feature vector instead of high-dimensional positional encodings for position, potentially reducing network complexity for the spatial input.
*   **Limitations:** Requires storing and sampling from a 3D feature volume, which may have higher memory overhead than implicit coordinate-based representations for very large scenes. Performance is sensitive to the inclusion of multiscale loss and TV regularization.

### When to Use
*   Use this setup when the goal is to train a NeRF-based model that supports explicit 3D feature manipulation and editing, rather than just novel view synthesis.
*   Use when working with LLFF-style datasets or similar multi-view setups.

### When Not to Use
*   Do not use if the primary goal is maximum rendering quality without the need for feature manipulation, as standard NeRF with positional encoding on positions may offer a different trade-off.
*   Do not use if memory constraints are extremely tight and the feature volume size becomes prohibitive.

## Background

### Origin
Control-NeRF was introduced in the paper "Control-NeRF: Editable Feature Volumes for Scene Rendering and Manipulation" [S1]. The method builds upon the original NeRF architecture [23] and the Visual Object Networks (VON) [S1] by integrating disentangled 3D feature volumes into the radiance field optimization process.

### History and Development
The method adapts the VON approach, which uses feature volumes for image generation, to the context of neural radiance fields. It replaces the standard positional encoding of 3D positions with sampled feature vectors, allowing for direct manipulation of the scene's appearance and geometry through the feature volume. The training setup follows the hierarchical sampling strategy of the original NeRF [23] but modifies the network input to accommodate the feature vectors.

### Where it is Used
Control-NeRF is used in applications requiring editable 3D scenes, such as 3D content creation, scene editing, and potentially in virtual/augmented reality where dynamic scene manipulation is needed.
