# PL-NeRF

Also called: Power Line NeRF

## Overview
PL-NeRF is a specialized Neural Radiance Field (NeRF) architecture designed for the 3D reconstruction of thin, low-texture structures, specifically power transmission lines (PTLs), in unbounded scenes [S1]. It addresses the discontinuity, jagged edges, and slow rendering speeds inherent in standard NeRF when applied to such structures by combining spatial compression via the $L_\infty$ norm, Hash Encoding (HE) for positions, and Integrated Positional Encoding (IPE) for directions [S1]. Unlike standard NeRF which uses Normalized Device Coordinates (NDC) for unbounded space, PL-NeRF compresses the scene into a fixed cube, aligning better with hash-based spatial indexing [S1].

## How it works
PL-NeRF builds on the standard NeRF architecture [Parent](11313-model-architecture-modifications.md) by modifying the position encoding, spatial compression, and sampling strategies to handle the specific geometric and textural properties of power lines [S1].

### Inputs and Outputs
*   **Inputs:** Progressive motion sequence images of PTLs captured by a Flying–walking Power Line Inspection Robot (FPLIR) [S1]. Camera intrinsics and extrinsics for each image [S1].
*   **Outputs:** Rendered RGB images, volume density ($\sigma$), view-dependent color ($\mathbf{c}$), and surface normals [S1].

### Data Structures

**1. Hash Table (for Hash Encoding)**
*   **Layout:** A sparse hash table mapping quantized 3D coordinates to feature vectors.
*   **Fields:**
    *   `index`: Integer hash index derived from the coordinate.
    *   `features`: Vector of learned features associated with the voxel/vertex.
*   **Initialization:** The scene space is normalized using the $L_\infty$ norm. Coordinates are quantized to determine small vertices. The hash function maps these vertices to table indices [S1].

**2. Appearance Embedding**
*   **Layout:** A learnable vector per input image.
*   **Purpose:** Embeds appearance information (accounting for exposure differences) into the radiance field on an image-by-image basis [S1].

**3. Multivariate Gaussian Representation (for IPE)**
*   **Layout:** Parameters defining a Gaussian distribution over the truncated frustum.
*   **Fields:** Mean and covariance derived from the integration of positional encoding over the viewing cone [S1].

### Numbered Steps

1.  **Spatial Compression:**
    Compress the unbounded scene into a fixed bounded volume using the $L_\infty$ norm. This maps the infinite space to a cube shape, defined as:
    $$ \mathbf{x}' = \frac{\mathbf{x}}{\max(|\mathbf{x}|_\infty, 1)} $$
    This replaces the NDC method used in standard NeRF, which relies on ill-defined near/far bounds for unbounded PTL scenes [S1].

2.  **Ray Bundle Generation:**
    For each pixel in the input image, emit a cone beam from the camera center. Divide this cone into frustums perpendicular to the ray axis [S1].

3.  **Position Encoding (Hash Encoding - HE):**
    *   Quantify the compressed 3D position $\mathbf{x}'$ into small vertices.
    *   Construct a hash function to map these vertices to indices in the Hash Table.
    *   Retrieve feature values from the Hash Table.
    *   Perform cubic interpolation using the retrieved values to generate the position feature vector $\mathbf{h}_{pos}$ [S1].

4.  **Direction Encoding (Integrated Positional Encoding - IPE):**
    *   Identify the truncated frustum region corresponding to the viewing cone.
    *   Integrate the standard positional encoding (PE) over this region.
    *   Approximate this integration using a multivariate Gaussian approach. Compute the Gaussian representation of the truncated frustum to obtain a multivariate Gaussian representation of the encoding [S1].
    *   Truncate the frustum’s encoding to calculate the expected encoding, resulting in the direction feature vector $\mathbf{h}_{dir}$ [S1]. This reduces sample size and generates anti-aliasing features [S1].

5.  **Network Forward Pass:**
    *   **Position MLP ($\Phi_{pos}$):** Input $\mathbf{h}_{pos}$ into an 8-layer MLP with 256 hidden units per layer. Output a feature vector $\mathbf{h}$ [S1].
    *   **Color MLP ($\Phi_{color}$):** Input $\mathbf{h}$, $\mathbf{h}_{dir}$, and the image-specific appearance embedding into a 4-layer MLP with 256 hidden units per layer. Output volume density $\sigma$ and view-dependent color $\mathbf{c}$ [S1].

6.  **Sampling (Proposal Network):**
    *   Employ a proposal network sampler to merge sampling positions into the area where the first surface intersects. This focuses samples on regions contributing most to the final rendering [S1].

7.  **Volume Rendering:**
    *   Render the image using standard volume rendering equations.
    *   Incorporate techniques from Ref-NeRF to calculate and predict surface normals during the rendering process [S1].

def l_infinity_norm_compression(x):

    Compress unbounded space into a cube using L-infinity norm.

    Position MLP: 8 layers, 256 hidden units.
    h_pos: feature vector from Hash Encoding
    """
    h = h_pos

    """

    sigma = np.exp(h[0]) # Density is typically positive

    # Compress points
    points_compressed = l_infinity_norm_compression(points)
    
    # 2. Encoding
    h_pos = hash_encode(points_compressed, hash_table)
    h_dir = integrated_positional_encoding(ray_direction[np.newaxis, :])
    
    # 3. Network Forward
    h = position_mlp(h_pos, mlp_weights['pos'])
    sigma, color = color_mlp(h, h_dir, appearance_embed, mlp_weights['color'])
    
    # 4. Volume Rendering (Standard Alpha Compositing)
    # Note: Proposal network sampling is used to refine points, but standard integration is shown here
    dt = t_vals[1] - t_vals[0]
    alpha = 1.0 - np.exp(-sigma * dt)
    T = np.cumprod(np.exp(-np.concatenate([[0], sigma[:-1] * dt])))
    weights_render = alpha * T
    rendered_color = np.sum(weights_render[:, np.newaxis] * color, axis=0)
    
    return rendered_color

### Parameters
*   **Position MLP:** 8 layers, 256 hidden units per layer [S1].
*   **Color MLP:** 4 layers, 256 hidden units per layer [S1].
*   **Spatial Compression Shape:** Cube, achieved via $L_\infty$ norm [S1].
*   **Reconstruction Metrics:** PSNR = 29, SSIM = 0.871, LPIPS = 0.087 [S1].

### Edge Cases and Pitfalls
*   **Unbounded Space Boundaries:** Standard NDC is ill-defined for unbounded PTL scenes. PL-NeRF mitigates this by using $L_\infty$ compression into a cube, which aligns better with hash encoding than the sphere compression used in Mip-NeRF 360 [S1].
*   **Thin Structures:** Power lines are thin and low-texture, causing discontinuity and jagged edges in standard NeRF. The combination of IPE and HE reduces sample size and generates anti-aliasing features to address ghosting [S1].
*   **Exposure Differences:** Training cameras may have varying exposure. PL-NeRF uses image-by-image appearance embedding to account for this [S1].

## Subtopics

### Hash Encoding (HE)
A spatial indexing method used in PL-NeRF to encode position information. It maps quantized 3D coordinates to a hash table for fast lookup and interpolation. It is chosen for its efficiency in handling the compressed spatial domain [S1].

### Integrated Positional Encoding (IPE)
A directional encoding method that integrates positional encoding over a truncated frustum (viewing cone) using a multivariate Gaussian approximation. It reduces aliasing and ghosting for thin structures [S1].

### $L_\infty$ Spatial Compression
A technique to compress unbounded scenes into a fixed cube. It is preferred over $L_2$ (sphere) compression in PL-NeRF to better align with the rectangular nature of hash grids and the long, narrow structure of power lines [S1].

## Operating characteristics
*   **Time and Memory Complexity:** Not explicitly given in the sources. However, the use of Hash Encoding (inspired by Instant-NGP) suggests lower memory usage and faster training compared to dense grid methods, while IPE reduces the number of samples needed along the beam [S1].
*   **Measured Performance:** On PTL datasets, PL-NeRF achieved PSNR = 29, SSIM = 0.871, and LPIPS = 0.087 [S1].
*   **Scaling:** The method is designed for large-scale scenes like PTLs. The spatial compression allows handling unbounded environments [S1].
*   **Strengths:** High reconstruction fidelity for thin, low-texture structures; handles unbounded scenes effectively; reduces ghosting and discontinuity [S1].
*   **Limitations:** Prioritizes reconstruction quality over rendering smoothness and real-time capabilities compared to methods like Volinga [S1].
*   **When to use:** 3D reconstruction of power transmission lines or similar thin, unbounded structures using progressive motion sequence images [S1].
*   **When not to use:** When real-time rendering speed is the primary constraint over reconstruction quality [S1].

## Background
PL-NeRF was proposed to address the difficulties in 3D reconstruction of power transmission lines (PTLs) due to their thin structure and low texture, which cause feature matching difficulties and discontinuities in standard NeRF [S1]. It was inspired by Mip-NeRF 360 for space compression and Ref-NeRF for normal prediction [S1]. The method was applied to data captured by a Flying–walking Power Line Inspection Robot (FPLIR) [S1].
