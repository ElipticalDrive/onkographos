# MLP Network Architecture
Also called: Radiance Field MLP, NeRF MLP, Implicit Field Network

## Overview
The MLP Network Architecture family defines the fully-connected neural networks used to map encoded spatial coordinates and view directions to volume density and view-dependent radiance. It solves the problem of representing continuous 3D scenes as differentiable functions that can be optimized via gradient descent. What sets this family apart from sibling methods like [Octree-based Implicit Surface Representation](22788-octree-based-implicit-surface-representation-with-sh-and-sdf.md) or [Hierarchical and Sparse Grid Representations](23610-hierarchical-and-sparse-grid-representations.md) is the exclusive reliance on dense, multi-layer perceptrons for the final prediction head, often preceded by explicit positional encoding, rather than sparse voxel grids or hash tables for the primary feature storage.

## Shared principles
The core mechanism involves transforming low-dimensional input coordinates into a high-dimensional feature space using sinusoidal positional encoding, which is then processed by a fully-connected MLP to predict radiance field properties.

**Positional Encoding**
The input coordinates $\mathbf{x} \in \mathbb{R}^3$ (position) and $\mathbf{d} \in \mathbb{R}^3$ (view direction) are mapped to higher dimensions using a hierarchical positional encoding function $\gamma(\cdot)$ [S1]. For a scalar input $p$, the encoding is defined as:
$$ \gamma(p) = (\sin(2^0 \pi p), \cos(2^0 \pi p), \dots, \sin(2^{L-1} \pi p), \cos(2^{L-1} \pi p)) $$
where $L$ is the number of frequency bands . This function is applied independently to each of the three components of the position vector and the direction vector [S1].

**Network Architecture**
The radiance field is represented by an MLP that takes the encoded position and direction as input. The architecture typically consists of two branches:
1.  **Density Branch:** Processes the encoded position features to predict volume density $\sigma$.
2.  **Color Branch:** Processes the encoded direction features concatenated with intermediate features from the density branch to predict RGB color $\mathbf{c}$ [S1].

**Ray Sampling**
Rendering requires sampling points along camera rays. A ray is parameterized as $r(\lambda) = o_{world} + \lambda d_{world}$, where $o_{world}$ is the world-space origin and $d_{world}$ is the world-space direction [S1]. The direction is computed from camera intrinsics and extrinsics: $d_{cam} = (\frac{i - c_x}{f_x}, \frac{j - c_y}{f_y}, 1)$, $d_{world} = R d_{cam}$, and $o_{world} = t$ [S1]. Position samples $x$ are generated along the ray within a defined near/far range [S1].

## Subtopics

### [Mip-NeRF 360 MLP Architecture](14098-mip-nerf-360-mlp-architecture.md)
The Mip-NeRF 360 MLP architecture is a multi-layer perceptron designed to predict volume density and view-dependent radiance from integrated positional encodings of 3D points and view directions. It extends the standard NeRF MLP by incorporating Integrated Directional Encoding (IDE) and supporting advanced features such as specular tinting, roughness prediction, and normal-based reflection directions. Unlike the original Mip-NeRF architecture which uses a simpler positional encoding, this variant explicitly handles the integration of positional encodings over conical frustums to reduce aliasing in wide-baseline scenes. See [Mip-NeRF 360 MLP Architecture](14098-mip-nerf-360-mlp-architecture.md).

### [Lightning-NeRF Model Configuration](18065-lightning-nerf-model-configuration.md)
The Lightning-NeRF model configuration defines the hyperparameters for a neural radiance field architecture optimized for efficient training and rendering, particularly in autonomous driving and large-scale real-world scenes. It distinguishes itself from standard NeRF implementations by integrating a hash-encoded density grid for fast lookup and specific initialization strategies using point clouds, alongside configurable view-independent and view-dependent MLP branches. Unlike Mip-NeRF variants which focus on anti-aliasing via cone tracing, Lightning-NeRF prioritizes training speed and memory efficiency through sparse grid structures and optimized ray marching parameters. See [Lightning-NeRF Model Configuration](18065-lightning-nerf-model-configuration.md).

### [Mip-NeRF Network Architecture](18138-mip-nerf-network-architecture.md)
This architecture is a compact, fully-connected multilayer perceptron (MLP) designed for neural radiance fields, specifically optimized for efficiency compared to the original NeRF [16] baseline. It solves the problem of high computational cost in radiance field representation by reducing the network size while maintaining structural similarity to standard implementations. It is distinguished from its sibling, the [Mip-NeRF 360 MLP Architecture](14098-mip-nerf-360-mlp-architecture.md), by its specific configuration of hidden layer dimensions and its origin in the RGB-D depth-assisted variant. See [Mip-NeRF Network Architecture](18138-mip-nerf-network-architecture.md).

### Intrinsic Neural Fields Network Architecture
- **Definition:** A neural network architecture for learning functions on a 2-manifold, using an eigenfunction embedding for intrinsic coordinates and sine/cosine positional encoding for view directions [S1].
- **Parameters:** Uses $\gamma_{Intr}$ for intrinsic coordinates $p$ and $\gamma_{FF}$ (sine/cosine positional encoding from NeRF [29]) for the unit ray direction $d$ [S1].
- **Layout:** Input consists of point $p$ on the 2-manifold and unit ray direction $d$. The embeddings $\gamma_{Intr}(p)$ and $\gamma_{FF}(d)$ are concatenated [S1].
- **Usage:** This first architecture is used in all experiments except those in Section 5.4 of the source [S1]. A second architecture (described in Fig. 9 of the source) is used in Section 5.4 experiments [S1].

### Nerflets Model Architecture
- **Steps:** Coarse-to-fine sampling is performed as in NeRF, but both coarse and fine samples are drawn from a single MLP rather than two distinct networks [S2].
- **Layout:** Each nerflet uses an MLP with 4 hidden layers and 32 hidden dimensions per layer. The shortcut connection from the original NeRF architecture is removed [S2]. The background neural field uses NeRF++ style encoding, with its MLP $f_{far}$ having 6 hidden layers and 128 hidden dimensions [S2].

### NeRF Network Architecture
- **Definition:** A fully-connected ResNet architecture used to predict volume density and color from spatial coordinates and encoded features [S3].
- **Steps:** Aggregate features across source views after block 3 using an average-pooling operation to enable arbitrary number of views as input [S3].
- **Parameters:** Architecture consists of 5 ResNet blocks with width 512 [S3].
- **Layout:** Each linear layer in the ResNet blocks is followed by a ReLU activation [S3].

### H-NeRF Architecture
- **Definition:** The specific network architecture and training hyperparameters used for all H-NeRF experiments, consisting of two MLPs for the radiance field and deformation field [S4, unofficial].
- **Parameters:** Number of coarse-level ray samples is 256; fine-level ray samples is 256. Positional encoding dimension for $F_\omega$ is 8; for $\Delta H_\omega$ is 1 [S4, unofficial].
- **Layout:** Module $F_\omega$ (radiance field) has 8 MLP layers, 256 dimensions per layer, skip connection to the middle layer, and Swish activation. Module $\Delta H_\omega$ (deformation field) has 6 MLP layers, 128 dimensions per layer, skip connection to the middle layer, and Swish activation [S4, unofficial].

### HelixSurf Network Architecture
- **Definition:** HelixSurf uses two MLPs to encode the implicit signed distance field (SDF-MLP) and implicit radiance field (RF-MLP), respectively [S5].
- **Formula:** Positional encoding $\gamma(x)$ applied to input spatial position $x$: $\gamma(x) = (\sin(2^0 \pi x), \cos(2^0 \pi x), \dots, \sin(2^{L-1} \pi x), \cos(2^{L-1} \pi x))$. Frequencies $L$ is set to 6 [S5].
- **Parameters:** SDF-MLP uses Softplus activation function defined as $\text{Softplus}(x) = \beta_1 \times \log(1 + \exp(\beta \times x))$, where $\beta = 100$ [S5]. Spherical encoding $Sh(\cdot)$ applied to input view direction $v$. Degrees of spherical encoding are set to 4 [S5].
- **Layout:** Input: position $x$ (3D vector), view direction $v$. Output: SDF and color $c$. Surface normal $n = \nabla f(x)$ [S5].

### MLP Architecture for Context & Quantization
- **Definition:** Neural network architecture for quantization and context modeling in HAC++, combining specific MLPs and varying input channels [S6].
- **Layout:** MLP$_q$ and MLP$_c$ combined into a single 3-layer MLP with ReLU activation. MLP$_a$ consists of multiple MLPs with varying input channels to accommodate different number of input chunks across different intra steps. Synthetic-NeRF uses a lightweight version of MLP$_a$ [S6].

## Background
The MLP-based radiance field representation was introduced by Mildenhall et al. in the original NeRF paper (2020) [S1]. It established the standard paradigm of using a fully-connected network to map 3D coordinates and view directions to density and color, leveraging positional encoding to overcome the network's bias toward low-frequency functions. This approach has become the foundational architecture for most subsequent differentiable volume rendering methods, including variants like Mip-NeRF, Instant-NGP (which hybridizes MLPs with hash grids), and numerous specialized extensions for dynamic scenes, large-scale environments, and specific domains like autonomous driving or human avatars.
