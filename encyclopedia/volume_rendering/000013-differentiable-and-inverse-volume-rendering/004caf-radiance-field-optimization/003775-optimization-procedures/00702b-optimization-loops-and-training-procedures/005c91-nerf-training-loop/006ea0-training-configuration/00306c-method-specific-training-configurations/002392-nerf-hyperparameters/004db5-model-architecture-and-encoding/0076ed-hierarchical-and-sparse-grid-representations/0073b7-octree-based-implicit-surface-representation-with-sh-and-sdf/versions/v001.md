# Octree-based Implicit Surface Representation with SH and SDF Optimization

Also called: Octree-NeRF, Octree-SDF

## Overview
This method accelerates neural implicit surface rendering by storing SDF values and Spherical Harmonic (SH) coefficients at the leaf nodes of an adaptive octree, replacing expensive trilinear interpolation with constant leaf-node lookups [S1]. It distinguishes itself from standard grid-based NeRFs by using SDF-based subdivision to adaptively refine geometry and SH to model view-dependent appearance, achieving real-time rendering speeds (often >30x faster than trilinear interpolation) while maintaining competitive quality through a fine-tuning phase [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of multi-view images with known camera poses.
*   Initial octree structure (typically starting from a coarse root or a pre-trained network like VolSDF).
*   Camera intrinsics and extrinsics for ray generation.

**Outputs:**
*   An optimized octree where each leaf node stores:
    *   SDF value $S$.
    *   SH coefficients $\mathbf{c}$ (representing view-dependent color).
*   A rendered image for a given camera pose.

### Data Structures
The scene is represented by an octree.
*   **Node:** Each node has 8 children (or is a leaf).
*   **Leaf Node Storage:**
    *   `sdf`: Scalar float representing the Signed Distance Function value at the node's center or representative point.
    *   `sh_coeffs`: Array of floats storing Spherical Harmonic coefficients. The source uses degree 2 SH, which requires $3 \times (2+1)^2 = 27$ coefficients per color channel (RGB), or 81 floats total if stored per channel, or 27 vectors if stored as RGB vectors. The source specifies "SH coefficients" and "degree 2" [S1].
    *   *Note:* The source does not explicitly define the exact memory layout (e.g., AoS vs SoA) or bit-packing, but implies a dense storage of these values at leaf nodes [S1].

### Algorithm Steps

1.  **Initialization (Optional Network-Based):**
    *   If integrating with a network-based method like VolSDF, input grid point coordinates into the network to obtain initial SDF values and SH coefficients [S1].
    *   Subdivide leaf nodes according to SDF values (e.g., split if $|S| < \epsilon$) until a target maximum subdivision level is reached [S1].

2.  **Octree Subdivision:**
    *   For each leaf node, evaluate the SDF $S(\mathbf{p})$ at its center $\mathbf{p}$.
    *   If the node is not at the maximum depth and meets subdivision criteria (e.g., small SDF magnitude indicating proximity to the surface), split it into 8 children [S1].
    *   Initialize children's properties (SDF and SH) based on the parent or by querying the initial network [S1].

3.  **Rendering (Forward Pass):**
    *   For each pixel, cast a ray $r(\lambda) = o + \lambda d$.
    *   Traverse the octree to find intersection points with the implicit surface defined by $S(\mathbf{x}) = 0$.
    *   **Sampling:** Sample points along the ray.
    *   **Property Retrieval:**
        *   **Trilinear Mode:** Interpolate SDF and SH coefficients from the 8 surrounding grid points (if using grid-based storage) or use trilinear interpolation on the octree grid points [S1].
        *   **Constant Leaf Mode (Fast):** Identify the leaf node containing the sample point. Retrieve the constant SDF value $S$ and SH coefficients $\mathbf{c}$ stored at that leaf node [S1].
    *   **Color Computation:**
        *   Compute the normal $\mathbf{n} = \nabla S(\mathbf{p}) / \|\nabla S(\mathbf{p})\|$ [S1].
        *   Evaluate the SH function using the view direction $\mathbf{d}$ and the retrieved SH coefficients $\mathbf{c}$ to get the color $\hat{\mathbf{C}}$ [S1].
    *   **Volume Rendering:** Composite the color and opacity along the ray using standard volume rendering integration [S1].

4.  **Loss Calculation:**
    The total loss $\mathcal{L}$ is a weighted sum of three terms:
    $$ \mathcal{L} = \mathcal{L}_{\text{col}} + \lambda_1 \mathcal{L}_{\text{TV}} + \lambda_2 \mathcal{L}_{\text{smooth}} $$

    *   **Color Loss ($\mathcal{L}_{\text{col}}$):** Mean Squared Error between rendered color $\hat{\mathbf{C}}_n$ and ground truth color $\mathbf{C}_n$ [S1].
        $$ \mathcal{L}_{\text{col}} = \frac{1}{N} \sum_{n=1}^N \|\mathbf{C}_n - \hat{\mathbf{C}}_n\|_2^2 $$
        where $N$ is the number of pixels [S1].

    *   **Total Variation Loss ($\mathcal{L}_{\text{TV}}$):** Regularizes the SH coefficients (and potentially SDF) to ensure spatial smoothness and preserve geometric continuity, especially at low resolutions [S1].
        $$ \mathcal{L}_{\text{TV}} = \frac{1}{|\mathcal{V}|} \sum_{\mathbf{p} \in \mathcal{V}} \sqrt{(D_{\mathbf{p}}^x)^2 + (D_{\mathbf{p}}^y)^2 + (D_{\mathbf{p}}^z)^2} $$
        *Note:* The source text contains a typo $(D_{\mathbf{p}}^x)^2$ repeated in the second term, but context implies derivatives in $x, y, z$ directions [S1].
        *   $\mathcal{V}$ is the set of grid points/leaf nodes.
        *   To speed up training, only 1% of points from $\mathcal{V}$ are randomly selected for this calculation [S1].

    *   **SDF Smoothness Loss ($\mathcal{L}_{\text{smooth}}$):** Encourages the gradient of the SDF to be smooth, regularizing the surface normal field [S1].
        $$ \mathcal{L}_{\text{smooth}} = \frac{1}{|\mathcal{V}_{smooth}|} \sum_{\mathbf{p} \in \mathcal{V}_{smooth}} \|\mathcal{G}(\nabla S(\mathbf{p})) - \nabla S(\mathbf{p})\|_2^2 $$
        *   $\nabla S(\mathbf{p})$ is the gradient of the SDF at point $\mathbf{p}$.
        *   $\mathcal{G}$ is a Gaussian filter applied to the gradient [S1].
        *   $\mathcal{V}_{smooth}$ is the set of points where $-0.1 \le S(\mathbf{p}) \le 0.1$ when subdivision level $l \le 8$. When $l > 8$, 10% of points are selected randomly to speed up training [S1].

5.  **Optimization (Fine-Tuning):**
    *   After the octree reaches the target resolution (subdivision stops), perform fine-tuning of the leaf node properties (SDF and SH) using the loss function above [S1].
    *   This step mitigates quality loss from using constant leaf values instead of interpolated values, making rendering quality comparable to trilinear interpolation [S1].
    *   The SH TV term ($\mathcal{L}_{\text{TV}}$) is turned off when subdivision level $l > 8$ to prevent excessive smoothness and ensure detail recovery [S1].

### Parameters
*   **SH Degree:** 2 [S1].
*   **$\lambda_1$ (TV Weight):** Default $10^{-5}$. Increased to $(10^{-5}, 10^{-3}]$ for bright scenes (metallic/transparent materials or intense light) [S1].
*   **$\lambda_2$ (Smooth Weight):** $2 \times 10^{-4}$ [S1].
*   **Subdivision Level Threshold:** SH TV term is turned off when subdivision level $l > 8$ [S1].
*   **Sampling for TV Loss:** 1% of points [S1].
*   **Sampling for Smooth Loss:** Points where $-0.1 \le S(\mathbf{p}) \le 0.1$ if $l \le 8$; 10% of points if $l > 8$ [S1].

### Edge Cases and Pitfalls
*   **Small $\lambda_1$:** Results in coarse shapes with holes at low octree resolution, which are difficult to patch as resolution increases [S1].
*   **Lighting Sensitivity:** Methods like Voxurf and BakedSDF are sensitive to lighting, exhibiting holes in areas with high specular highlights or intense lighting. This method consistently produces satisfactory geometry but may not recover specular highlights perfectly [S1].
*   **Quality vs. Speed Trade-off:** Using constant leaf node values increases speed by over 30 times compared to trilinear interpolation but decreases quality. Fine-tuning is required to mitigate this [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Rendering Speed:** Using leaf node values with fine-tuning achieves a speed increase of over 30 times compared to trilinear interpolation on grid points [S1].
*   **Training Time:**
    *   Level $l=9$: 75k iterations in 40 minutes on NVIDIA Tesla V100 [S1].
    *   Level $l=10$: 100k iterations in 60 minutes on NVIDIA Tesla V100 [S1].

### Measured Performance
*   **NeRF-Synthetic (Chair, $l=9$, Constant):** 288.62 FPS (vs. Trilinear $l=9$: 18.51 FPS) [S1].
*   **NeRF-Synthetic (Mic, $l=9$, Constant):** 692.03 FPS (vs. Trilinear $l=9$: 18.35 FPS) [S1].
*   **NeRF-Synthetic (Chair, $l=10$, Trilinear):** PSNR 34.62, CD 1.39 [S1].
*   **DTU (ID 24, $l=10$, Constant):** 146.27 FPS (vs. Trilinear $l=10$: 5.59 FPS) [S1].

### Strengths and Limitations
*   **Strengths:** Real-time rendering capabilities (surpassing 3DGS in some cases), robust geometry reconstruction even in intense lighting conditions where other methods fail, efficient memory usage via adaptive octree.
*   **Limitations:** May not recover high-frequency specular highlights as well as some other methods (e.g., Voxurf, BakedSDF, 3DGS) in terms of PSNR, though geometry remains intact. Requires fine-tuning to match the quality of trilinear interpolation.

### When to Use
*   When real-time rendering is required.
*   When robust geometry reconstruction is prioritized over perfect specular highlight recovery.
*   When scene complexity varies significantly, requiring adaptive resolution.

### When Not to Use
*   When maximum possible PSNR is required and real-time performance is not a constraint (standard NeRF or Plenoxels might be better).
*   When exact specular highlight reproduction is critical and the scene is not extremely bright.

## Background
This method was introduced in the paper "Real-time volume rendering with octree-based implicit surface representation" [S1]. It builds upon VolSDF [S1] by integrating an octree structure and Spherical Harmonics for view-dependent appearance. The approach addresses the computational bottleneck of neural implicit surface rendering by replacing expensive interpolation with constant leaf-node lookups, enhanced by a fine-tuning phase. It is implemented as a specialized PyTorch CUDA extension library [S1].
