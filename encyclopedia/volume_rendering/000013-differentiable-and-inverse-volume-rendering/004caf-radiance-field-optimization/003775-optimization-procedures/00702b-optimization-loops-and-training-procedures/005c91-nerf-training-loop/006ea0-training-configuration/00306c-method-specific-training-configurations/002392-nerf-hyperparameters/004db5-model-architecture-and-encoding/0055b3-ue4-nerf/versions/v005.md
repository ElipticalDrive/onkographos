# UE4-NeRF

Also called: UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene

## Overview
UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale 3D scenes by partitioning the environment into sub-NeRFs represented by textured polygonal meshes [S1]. Unlike standard differentiable volume rendering which renders rays directly, UE4-NeRF extracts a mesh representation from the neural field and integrates it into the Unreal Engine 4 (UE4) rasterization pipeline [S1]. It sets itself apart from sibling methods like [Mobile-NeRF](13622-mobile-nerf.md) and [Mega-NeRF](14098-mega-nerf.md) by utilizing regular octahedra for mesh initialization to handle tilted surfaces and multi-resolution hash encoding for training acceleration, achieving real-time frame rates at 4K resolution [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of posed images (typically from drones) with GPS coordinates; camera poses; scene bounding box.
*   **Outputs:** A set of textured polygonal meshes (LOD hierarchy) and a neural shader (HLSL fragment shader) deployed in UE4, producing real-time rendered images [S1].

**Data Structures:**
1.  **Scene Partitioning:** The large scene is divided into blocks (sub-NeRFs). Each block's training area is slightly larger than the physical scene area to create overlapping borders for smooth transitions [S1].
2.  **Grid Initialization:** A $128 \times 128 \times 128$ grid is initialized for each block [S1].
3.  **Mesh Representation:** Polygonal meshes are created by selecting the center point of each grid cell and its six neighbors (front, back, left, right, top, bottom) [S1]. To handle tilted surfaces, a regular octahedron with 20 faces (8 exterior, 12 interior) is used instead of the standard cube-based approach [S1].
4.  **Texture Atlas:** Stores feature vectors and opacity information for the mesh vertices [S1].
5.  **Neural Shader:** An HLSL fragment shader implementing the MLP decoder [S1].

**Network Architecture:**
The method uses an Encoder-Decoder network structure [S1].
*   **Encoder ($E$):** A 4-layer MLP with dimensions $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$. It takes positional information encoded by multi-resolution hash encoding and outputs opacity ($\alpha_i$) and an 8-dimensional feature vector ($M_i$) [S1].
*   **Decoder ($D$):** A 3-layer MLP with dimensions $17 \times 16$, $16 \times 16$, $16 \times 3$. It takes the feature vector $M_i$ and spherical harmonics coefficients of the viewing direction $SH(\mathbf{d}_i)$ to output the final color $\mathbf{c}_i$ [S1].

**Numbered Steps:**

1.  **Coordinate Transformation:** Transform GPS-captured drone imagery coordinates to the UE4 coordinate system. In this system, the X-axis points east, the Y-axis points south, and the Z-axis points up. Apply a 100:1 scale conversion (UE4 units to real-world units) [S1].
2.  **Block Partitioning:** Partition the large-scale scene into multiple blocks. Train a coarse model for sub-region segmentation to capture overall terrain and building outlines. Filter images associated with sub-regions and use a mask to exclude pixels outside the scene area [S1].
3.  **Mesh Initialization:** Initialize a $128 \times 128 \times 128$ grid. For each grid cell, select the center point and its six neighboring grids to form the base geometry. Construct regular octahedra (20 faces) at these locations to serve as the initial polygonal meshes [S1].
4.  **Training Loop:**
    *   For each ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ emitted from the camera origin $\mathbf{o}$ with direction $\mathbf{d} = (\theta, \phi)$, calculate the intersection with the polygonal meshes [S1].
    *   The intersection point serves as the sampling point.
    *   Encode the spatial position $\mathbf{p}_i$ using multi-resolution hash encoding (from Instant-NGP) [S1].
    *   Compute the feature vector and opacity using the Encoder:
        $$ M_i, \alpha_i = E(\text{hash}(\mathbf{p}_i); \theta_E) $$
    *   Compute the color using the Decoder, incorporating Spherical Harmonics (SH) for the viewing direction $\mathbf{d}_i$:
        $$ \mathbf{c}_i = D(M_i, SH(\mathbf{d}_i); \theta_D) $$
    *   Optimize the parameters of the Encoder-Decoder network ($\theta_E, \theta_D$) and the vertex positions of the meshes continuously during training [S1].
    *   Train for 80,000 epochs per block to achieve convergence [S1].
5.  **LOD Generation:** Train meshes with varying levels of detail (LOD) for different observation heights. Coarser meshes are used for higher observation heights to ensure real-time performance [S1].
6.  **Extraction and Deployment:** Extract pre-rendered polygonal meshes at different LODs. Deploy the neural shader (HLSL fragment shader) in UE4. The shader takes the feature vectors from the texture atlas as input and outputs colors [S1].
7.  **Rendering:** Combine the extracted meshes with the UE4 rasterization pipeline. UE4 handles occlusion between added traditional 3D models (e.g., .obj, .fbx) and the NeRF-rendered background, skipping neural shader computation for occluded regions [S1].

**Pseudocode:**

```python
# UE4-NeRF Implementation Steps

def ue4_nerf_pipeline(images, poses, gps_coords):
    """
    Main pipeline for UE4-NeRF.
    """
    # Step 1: Coordinate Transformation
    # Transform GPS coords to UE4 system: X=East, Y=South, Z=Up
    # Scale: 100:1
    ue4_coords = transform_gps_to_ue4(gps_coords, scale=100.0)
    
    # Step 2: Block Partitioning
    # Partition scene into blocks with overlapping borders
    blocks = partition_scene(ue4_coords, overlap=True)
    
    # Coarse model for segmentation
    coarse_model = train_coarse_segmentation(blocks)
    
    processed_blocks = []
    
    for block in blocks:
        # Filter images for this block using mask from coarse model
        block_images = filter_images(images, poses, block.mask)
        
        # Step 3: Mesh Initialization
        # Initialize 128x128x128 grid
        grid = initialize_grid(size=128)
        
        # Create polygonal meshes using regular octahedra (20 faces)
        # Center point + 6 neighbors
        meshes = initialize_octahedra_meshes(grid)
        
        # Step 4: Training
        # Initialize networks
        encoder = EncoderMLP(layers=[32, 64, 64, 64, 8])
        decoder = DecoderMLP(layers=[17, 16, 16, 16, 3])
        
        # Multi-resolution hash encoding (Instant-NGP style)
        hash_encoder = MultiResolutionHashEncoder()
        
        # Training loop
        for epoch in range(80000):
            loss = 0.0
            for image, pose in zip(block_images, block.poses):
                # Generate rays
                rays = generate_rays(pose, image.resolution)
                
                # Intersect rays with meshes to get sampling points
                sampling_points = intersect_rays_with_meshes(rays, meshes)
                
                # Encode positions
                hashed_features = hash_encoder.encode(sampling_points.positions)
                
                # Encode network
                # E(hash(pi); theta_E) -> Mi, alpha_i
                features, opacities = encoder(hashed_features)
                
                # Decode color
                # D(Mi, SH(di); theta_D) -> ci
                # SH encoding for viewing direction
                sh_coeffs = encode_spherical_harmonics(rays.directions)
                colors = decoder(concat([features, sh_coeffs]))
                
                # Compute loss against ground truth image pixels
                pixel_loss = compute_rendering_loss(colors, opacities, rays, image)
                loss += pixel_loss
            
            # Backpropagate to update encoder, decoder, and mesh vertex positions
            update_parameters(encoder, decoder, meshes, loss)
            
        # Step 5: LOD Generation
        # Train/extract meshes for different LODs
        lod_meshes = generate_lod_hierarchy(meshes)
        
        # Step 6: Extract Texture Atlas
        # Store features and opacity in texture maps
        texture_atlas = extract_texture_atlas(encoder, meshes)
        
        processed_blocks.append({
            'meshes': lod_meshes,
            'texture_atlas': texture_atlas,
            'shader': compile_hlsl_shader(decoder)
        })
        
    return processed_blocks

def render_ue4(block_data, camera_pose):
    """
    Real-time rendering using UE4 rasterization pipeline.
    """
    # Select appropriate LOD based on camera height
    lod_mesh = select_lod(block_data['meshes'], camera_pose.height)
    
    # Bind texture atlas and neural shader
    bind_texture(block_data['texture_atlas'])
    bind_shader(block_data['shader'])
    
    # Rasterize meshes in UE4
    # UE4 handles occlusion culling automatically
    image = rasterize(lod_mesh, camera_pose)
    
    return image
```

**Parameters:**
*   **Grid Size:** $128 \times 128 \times 128$ [S1].
*   **Octahedron Faces:** 20 total (8 exterior, 12 interior) [S1].
*   **Encoder MLP:** 4 layers, dimensions $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
*   **Decoder MLP:** 3 layers, dimensions $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
*   **Training Hardware:** 1 Nvidia RTX 3090 GPU [S1].
*   **Training Iterations:** 80,000 epochs per block [S1].
*   **Coordinate System:** X=East, Y=South, Z=Up [S1].
*   **World Scale:** 100:1 [S1].

**Edge Cases and Pitfalls:**
*   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces; UE4-NeRF addresses this by using regular octahedra [S1].
*   **Transparency:** Mobile-NeRF cannot handle transparent/semi-transparent objects due to opacity binarization; UE4-NeRF stores opacity in texture maps to mitigate this [S1].
*   **Performance:** Semi-transparent objects (e.g., vegetation) increase computational overhead, reducing frame rates [S1].
*   **Pre-rendering Gaps:** Pre-rendering cannot capture rays from all viewing angles, resulting in gaps or holes in the final rendered scene [S1].
*   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, causing evaluation metrics (PSNR/SSIM) to underestimate actual reconstruction quality [S1].
*   **Memory:** Requires CUDA and NVIDIA GPUs; rendering large scenes (square kilometers) incurs significant memory overhead, which increases with accuracy [S1].

## Operating characteristics
*   **Time Complexity:** Training is significantly faster than predecessors. 1000× faster than Mobile-NeRF [S1]. Training time is ~40 minutes per block on 1×RTX 3090 [S1]. Full scene training time is $1 \text{ hour} + (40 \text{ minutes} \times n/4)$ for $n$ blocks [S1].
*   **Memory Complexity:** High memory overhead for large scenes (square kilometers). Increasing accuracy amplifies memory consumption [S1].
*   **Performance:** Real-time rendering at 4K resolution with up to 43 FPS on level-1 mesh hierarchy [S1]. 50 FPS on full scene at 2K resolution; $\ge 70$ FPS on individual blocks at 2K resolution [S1].
*   **Strengths:** Real-time interactive rendering of large-scale scenes; handles tilted surfaces and semi-transparent objects better than Mobile-NeRF; integrates with UE4 for scene editing; avoids blurriness on natural scenes compared to Mip-NeRF [S1].
*   **Limitations:** Requires NVIDIA GPUs and CUDA; pre-rendering gaps/holes; exposure matching issues in UE4; semi-transparent objects reduce FPS [S1].
*   **When to Use:** Real-time visualization of large-scale outdoor scenes (farmland, construction sites, industrial parks) where interactivity and high resolution are required.
*   **When Not to Use:** Scenes requiring precise ray-caching from all angles (due to pre-rendering gaps); environments without NVIDIA hardware; scenes where exposure consistency is critical for metric evaluation.

## Background
UE4-NeRF was introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" [S1]. It was developed to address the limitations of NeRF in real-time rendering of large-scale scenes, specifically targeting applications in virtual reality, computer games, and the Metaverse [S1]. It builds on techniques from Mobile-NeRF (mesh representation) and Instant-NGP (hash encoding) [S1]. It is used in Unreal Engine 4 for drone-captured large-scale scenes and evaluated on the Mega-NeRF public dataset [S1].
