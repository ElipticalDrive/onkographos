# Cosine Learning Rate Schedule

Also called: CosineEasingSchedule

## Overview
It is a learning rate schedule that transitions from an initial value to a final value using a cosine function to ease the change [S1, S2, unofficial]. It differs from the parent [Linear Learning Rate Schedule](11850-linear-learning-rate-schedule.md) by providing a non-linear, smooth decay curve rather than a linear interpolation, which stabilizes optimization in radiance-field training by reducing the learning rate more gradually in the later stages [S1, unofficial].

## How it works
**Inputs and Outputs:**
- `step`: Current training step (integer).
- `warm_up_steps`: Number of steps for the linear warm-up phase (integer) [S1, unofficial].
- `max_decay_steps`: Total number of steps for the entire schedule (integer) [S1, unofficial].
- `lr_start`: Starting learning rate at step 0 (float) [S1, unofficial].
- `lr_max`: Maximum learning rate reached after warm-up and start of cosine decay (float) [S1, unofficial].
- `lr_min`: Minimum learning rate reached at the end of the cosine decay (float) [S1, unofficial].
- Output: The computed learning rate for the current step (float).

**Data Structures:**
No complex data structures are required; the calculation is stateless and depends only on the current step and configuration parameters [G].

**Steps:**
1. If `step` is less than `warm_up_steps`, compute the linear warm-up value [S1, unofficial].
2. If `step` is greater than or equal to `warm_up_steps`, compute the normalized progress `t` for the cosine decay phase, clamped to $[0.0, 1.0]$ [S1, unofficial].
3. Apply the cosine decay formula using `t`, `lr_max`, and `lr_min` [S1, unofficial].
4. Return the computed learning rate [S2, unofficial].

**Formula:**
Warm-up phase ($n < \text{warm\_up\_steps}$):
$$lr = \frac{lr_{max} - lr_{start}}{warm\_up\_steps} \cdot n + lr_{start}$$
Cosine decay phase ($n \ge \text{warm\_up\_steps}$):
Let $t = \min\left(\frac{n - warm\_up\_steps}{max\_decay\_steps - warm\_up\_steps}, 1.0\right)$ [S1, unofficial]. Then:
$$lr = lr_{min} + 0.5 \cdot (lr_{max} - lr_{min}) \cdot (1 + \cos(t \cdot \pi))$$
A simplified variant transitions directly between an initial value $v_{init}$ and final value $v_{final}$ over `num_steps` [S2, unofficial]:
$$v = v_{init} + (v_{final} - v_{init}) \cdot 0.5 \cdot (1 + \cos(\pi x + \pi))$$
where $x = \min(\max(step/num\_steps, 0), 1)$ [S2, unofficial].

**Parameters:**
- `lr_start`: Starting learning rate at step 0 [S1, unofficial].
- `lr_max`: Maximum learning rate reached after warm-up [S1, unofficial].
- `lr_min`: Minimum learning rate reached at the end of the cosine decay [S1, unofficial].
- `warm_up_steps`: Number of steps for the linear warm-up phase [S1, unofficial].
- `max_decay_steps`: Total number of steps for the entire schedule (warm-up + decay) [S1, unofficial].
- `base_lr`: Must be set to 1.0 [S1, unofficial].

**Edge Cases and Pitfalls:**
- If `step` is negative, the clamping ensures $x=0$, returning `initial_value` [G].
- If `step` exceeds `num_steps`, the clamping ensures $x=1$, returning `final_value` [G].
- Precision issues with floating-point arithmetic in the cosine calculation are generally negligible for standard training scales [G].

**Pseudocode:**
```python
import math

def cosine_learning_rate(step, warm_up_steps, max_decay_steps, lr_start, lr_max, lr_min):
    if step < warm_up_steps:
        return lr_start + (lr_max - lr_start) * (step / warm_up_steps)
    else:
        t = min((step - warm_up_steps) / (max_decay_steps - warm_up_steps), 1.0)
        return lr_min + 0.5 * (lr_max - lr_min) * (1 + math.cos(t * math.pi))
```

## Subtopics

### [Delayed Cosine Schedule](11854-delayed-cosine-schedule.md)
A schedule wrapper that delays the start of a base learning rate schedule using a sinusoidal rate multiplier. It sets apart from standard cosine schedules by introducing a warm-up phase where the learning rate is suppressed, easing into the base schedule's trajectory. This prevents early instability in radiance-field optimization by avoiding large gradient updates during the initial training steps.

## Operating characteristics
- **Time Complexity:** $O(1)$ per step, as it involves basic arithmetic and a single trigonometric function evaluation [G].
- **Memory Complexity:** $O(1)$, requiring no additional storage beyond the current step and configuration values [G].
- **Strengths:** Provides a smooth, non-linear decay that can help the optimizer settle into minima more effectively than linear schedules [G].
- **Limitations:** May converge slower than aggressive schedules if the initial learning rate is not well-tuned. The smooth decay might not be optimal for all types of loss landscapes in radiance-field optimization [G].
- **When to use:** Suitable for stable training scenarios where a gradual reduction in learning rate is beneficial [G].
- **When not to use:** If rapid convergence is required in the early stages, a linear or step schedule might be more appropriate [G].
- **Measured Performance:** Not given in the sources [G].

## Background
The cosine learning rate schedule is implemented in the Nerfies project, a JAX-based framework for neural radiance fields [S2, unofficial]. It is part of the training configuration for optimizing radiance fields, providing a smooth transition in learning rates during the training loop [S1, unofficial]. It is also utilized in differentiable optimization pipelines for task-specific loss minimization, such as the 1-cycle learning rate annealing in TomOpt for muon tomography detector design [S3].
