# PI-NeRF

Also called: Partial-Invertible Neural Radiance Fields

## Overview
PI-NeRF is a framework that integrates NeRF with invertible neural networks (INN) to directly output the 6-DoF camera pose from a single image without requiring pose initialization or iterative optimization [S1]. It solves the inverse problem of view synthesis by "inverting" the NeRF rendering process, allowing for direct pose estimation from a given image [S1]. Unlike sibling methods such as [NeRF2Points](12125-nerf2points.md) or [GazeNeRF](12127-gazenerf.md) which may rely on iterative optimization or specific geometric priors, PI-NeRF achieves this by mapping pixel features to ray representations via an Invertible Neural Network Module (INM), enabling the use of standard PnP algorithms for pose calculation [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A single RGB image $I$ captured by a camera with known intrinsic parameters $K$.
*   **Output:** The 6-DoF camera pose, consisting of rotation $R \in SO(3)$ and translation $t \in \mathbb{R}^3$.

**Data Structures:**
1.  **NeRF-Feat:** A modified NeRF MLP that maps a 3D point $x$ and viewing direction $d$ to a high-dimensional feature vector $f \in \mathbb{R}^D$ instead of RGB color. The standard NeRF density $\sigma$ is also retained.
2.  **Invertible Neural Network Module (INM):** Consists of two invertible neural networks (INNs) operating in forward and reverse directions.
    *   Forward Path: Maps Ray Feature + Ray Representation $\rightarrow$ Pixel Feature.
    *   Reverse Path: Maps Pixel Feature $\rightarrow$ Ray Feature + Ray Representation.
3.  **ResUNet:** A U-Net based encoder used to extract pixel features from the input image.

**Numbered Steps:**

1.  **NeRF-Feat Construction:**
    Modify the standard NeRF architecture. For a 3D point $x$ and direction $d$, the network outputs a feature vector $f(x, d)$ and density $\sigma(x)$. The volume rendering equation is applied to aggregate these features along a ray $r$:
    $$
    F(r) = \sum_{i=1}^{N} T_i \alpha_i f(x_i, d_i)
    $$
    where $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$ is the accumulated transmittance, $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$ is the opacity weight, and $f(x_i, d_i)$ is the high-dimensional feature at sample point $x_i$ [S1]. This results in a ray feature $F(r)$ for each ray.

2.  **Invertible Neural Network Module (INM) Design:**
    Design an INM that establishes a bijective mapping between the ray feature space and the pixel feature space.
    *   **Forward Path:** Takes the ray feature $F(r)$ and a ray representation $r_{rep}$ (encoding the ray's geometric properties) as input, and outputs a pixel feature $f_{pix}$.
    *   **Reverse Path:** Takes the pixel feature $f_{pix}$ as input and recovers the corresponding ray feature $F(r)$ and ray representation $r_{rep}$ [S1].

3.  **Training Phase:**
    *   **Feature Extraction:** Use a ResUNet encoder to extract a pixel feature map from the observed image $I$. Let $f_{img}(u, v)$ be the feature at pixel $(u, v)$ [S1].
    *   **Forward Rendering:** For training images with known poses, render ray features $F(r)$ using the NeRF-Feat model.
    *   **INM Forward Pass:** Pass $F(r)$ and $r_{rep}$ through the forward path of the INM to generate predicted pixel features $\hat{f}_{pix}$.
    *   **Loss Computation:** Compute the Barlow Twins (BT) loss between the predicted pixel features $\hat{f}_{pix}$ and the features $f_{img}$ extracted by the ResUNet from the input image. This loss encourages the ResUNet to generate features that, when passed through the reverse INM, correctly recover the ray representations [S1].
    *   **Optimization:** Optimize the parameters of the NeRF-Feat, INM, and ResUNet jointly to minimize the BT loss.

4.  **Inference Phase (Pose Estimation):**
    *   **Feature Extraction:** Given a query image $I_{query}$ with unknown pose, use the trained ResUNet to extract the pixel feature map $f_{query}(u, v)$ [S1].
    *   **Reverse INM:** Sample features from $f_{query}$ and feed them into the reverse path of the trained INM. The INM outputs the corresponding ray representations $r_{rep}$ and ray features $F(r)$ [S1].
    *   **Pose Calculation:** Use the recovered ray representations (which encode the ray directions and origins relative to the scene) and the known camera intrinsics $K$ to solve for the camera pose. Specifically, use a Perspective-n-Point (PnP) algorithm to calculate the 6-DoF pose $(R, t)$ [S1].

**Parameters:**
*   **Feature Dimension $D$:** Not given in the sources.
*   **Barlow Twins Loss:** Used as the primary training objective for the feature alignment [S1].
*   **PnP Solver:** Standard PnP algorithm (e.g., EPnP) used in the final step [S1].

**Edge Cases and Pitfalls:**
*   **Invertibility Constraint:** The INM must strictly maintain invertibility. If the network fails to converge to a bijective mapping, the reverse path will not accurately recover ray representations, leading to incorrect pose estimation [S1].
*   **Ray Representation Ambiguity:** The "ray representation" $r_{rep}$ must uniquely identify the ray geometry. If the INM cannot distinguish between rays with similar features but different geometries, the PnP step will fail [S1].
*   **Intrinsic Calibration:** The method assumes known camera intrinsics $K$ for the PnP step. Incorrect intrinsics will lead to systematic pose errors [S1].

## Operating characteristics
*   **Speed:** PI-NeRF is two orders of magnitude faster than existing NeRF-based pose estimation methods (e.g., pNeRF takes >5 seconds) [S1]. It does not require iterative optimization or image synthesis from multiple poses [S1].
*   **Accuracy:** Maintains competitive accuracy compared to iterative methods and significantly outperforms NeRF-free absolute pose regression methods [S1].
*   **Initialization:** Does not require an initial pose estimate, unlike methods such as iNeRF which are sensitive to initialization and prone to local optima [S1].
*   **Memory:** Requires storing the NeRF-Feat model, INM, and ResUNet. The memory footprint is comparable to standard NeRF plus the additional INM and ResUNet components.
*   **Scalability:** Performance is independent of the number of training views, as it relies on a single query image for inference.

## Background
*   **Origin:** Proposed by Zhihao Li, Kexue Fu, Haoran Wang, and Manning Wang in the paper "PI-NeRF: A Partial-Invertible Neural Radiance Fields for Pose Estimation" presented at MM '23 (October 29-November 3, 2023, Ottawa, ON, Canada) [S1].
*   **Motivation:** Existing NeRF-based pose estimation methods (like iNeRF and pNeRF) rely on synthesizing images from a number of poses or iterative optimization, which is time-consuming and sensitive to initial poses. PI-NeRF addresses this by "inverting" NeRF to directly estimate pose from a given image [S1].
*   **Applications:** Camera pose estimation is a basis for robot manipulation, simultaneous localization and mapping (SLAM), and augmented reality [S1].
