# Panoptic Radiance Field

Also called: Panoptic Lifting

## Overview
Panoptic Lifting learns a panoptic 3D volumetric representation from posed RGB images and machine-generated 2D panoptic segmentation masks, lifting noisy 2D labels into a consistent 3D representation of color, density, semantics, and instances [S1]. It differs from sibling methods like [Panoptic NeRF](11916-panoptic-nerf.md) and [DM-NeRF](11916-dm-nerf.md) by requiring no manual ground truth (such as coarse meshes or per-image 2D panoptic segmentations), relying instead on pre-trained 2D segmentation networks to generate supervision [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   Posed RGB images $\{I\}$ of a scene.
*   Machine-generated 2D panoptic segmentation masks for each input image, produced by a pre-trained network (e.g., Mask2Former [S1]).
*   Camera poses for each image.

**Outputs:**
*   A panoptic radiance field $\Phi(\mathbf{x}, \mathbf{d})$ that, for any 3D point $\mathbf{x} \in \mathbb{R}^3$ and viewing direction $\mathbf{d} \in S^2$, outputs:
    *   Density $\sigma \in \mathbb{R}_{\ge 0}$.
    *   Semantic class distribution $\kappa$ over classes $K$.
    *   Distribution $\pi$ over surrogate identifiers $J$.
    *   RGB color $\mathbf{c} \in \mathbb{R}^3$.
*   Rendered novel view images, depth maps, and 3D-consistent panoptic segmentation masks.

### Data Structures and Layout
The representation $\Phi$ comprises four components [S1]:
1.  **Color and Density:** Leverages the TensoRF [4] representation, using shared low-rank tensors (lines and planes) to encode $\sigma$ and $\mathbf{c}$.
2.  **Semantic Field:** A small Multi-Layer Perceptron (MLP), denoted $f_{sem}$, taking encoded position features to output the semantic distribution $\kappa$.
3.  **Instance Field:** A separate small MLP, denoted $f_{inst}$, taking encoded position features to output the distribution $\pi$ over surrogate identifiers.
4.  **Surrogate Identifiers:** A fixed set $J$ of class-agnostic, 3D-consistent identifiers. The set of all possible 3D instances is $H^{3D} := K^T \times J$, where $K^T$ is the set of "thing" classes [S1].

**Ray Abstraction:**
Rays $r$ are parameterized as $r = \mathbf{p}_0 + t\mathbf{d}_r$, where $\mathbf{p}_0$ is the origin, $\mathbf{d}_r$ is the unit direction, and $t$ is a scalar [S1]. Training rays associated with image $I$ have ground-truth labels: RGB color $\hat{\mathbf{c}}_r \in \mathbb{R}^3$, semantic class $\hat{k}_r \in K$, and 2D instance ID $\hat{h}_r \in H^I$ (defined only if $\hat{k}_r \in K^T$) [S1].

### Training Procedure

#### 1. Confidence Estimation via Test-Time Augmentation (TTA)
To handle noise in machine-generated labels, confidence estimates are derived using TTA [S1].
1.  Apply augmentations (horizontal flip, scale, brightness, contrast) to input images.
2.  Run the pre-trained 2D panoptic segmentation model on augmented images.
3.  Fuse resulting segmentations via segment clustering.
4.  For each pixel (ray $r$), obtain a semantic class distribution $\hat{\kappa}_r$ over $K$ and a confidence estimate $w_r$ [S1].

#### 2. Linear Assignment for Instance Mapping
2D instance IDs are inconsistent across views. A linear assignment problem solves this by mapping 2D instance IDs to 3D surrogate identifiers [S1].
1.  For a batch of rays $R$, identify the subset $H^R \subseteq H^I$ of 2D instances present.
2.  Compute a cost matrix based on the model's current 3D instance predictions and the machine-generated 2D masks.
3.  Solve the linear assignment to find an injective mapping $\Pi^*_R: H^R \to J$ [S1].
4.  Each ray $r$ is assigned a surrogate identifier $j = \Pi^*_R(\hat{h}_r)$ [S1].

#### 3. Loss Functions
The total loss is a weighted sum of instance, consistency, semantic, and photometric losses [S1]:
$$ L_{tot}(R) := \lambda_{ins} L_{ins}(R_I) + \lambda_{con} L_{con}(R_I) + \lambda_{RGB} L_{RGB}(R_S) + \lambda_{sem} L_{sem}(R_S) $$
where $R_S$ are rays randomly sampled across the scene and $R_I$ are rays sampled from a single image [S1].

**Semantic Loss ($L_{sem}$):**
Cross-entropy between the rendered semantic distribution $\kappa_r$ and the TTA-derived distribution $\hat{\kappa}_r$, weighted by confidence $w_r$ [S1]:
$$ L_{sem}(R) := -\frac{1}{|R|} \sum_{r \in R} w_r \sum_{k \in K} \hat{\kappa}_r(k) \log \kappa_r(k) $$
*Note:* The semantic field outputs bounded probability distributions directly, not logits, to prevent unbounded signals in low-density areas [S1].

**Instance Loss ($L_{ins}$):**
Minimizes the log-loss of the co-occurrence of the mapped surrogate identifier and the rendered instance distribution [S1].

**Segment Consistency Loss ($L_{con}$):**
Guides semantic supervision to avoid optima that fragment objects in the presence of label inconsistencies [S1].

**Photometric Loss ($L_{RGB}$):**
Standard L2 loss between rendered color $\mathbf{c}_r$ and ground truth $\hat{\mathbf{c}}_r$ [S1].

#### 4. Gradient Blocking
To prevent noisy segmentation labels from corrupting geometry (e.g., creating "cloudy" geometry to satisfy conflicting labels), gradients from the semantic and instance branches are stopped before reaching the density network [S1].

#### 5. Rendering Novel Views
For a novel view ray $r$:
1.  Render the semantic distribution $\kappa_r$ and instance distribution $\pi_r$ using the volumetric rendering equation.
2.  Determine the semantic class: $k^*_r := \arg \max_{k \in K} \kappa_r(k)$.
3.  If $k^*_r \in K^T$, determine the surrogate ID: $j^*_r := \arg \max_{j \in J} \pi_r(j)$.
4.  The 3D instance ID is the pair $(k^*_r, j^*_r) \in H^{3D}$ [S1].

### Parameters
*   **$K$**: Set of semantic classes, partitioned into thing classes $K^T$ and stuff classes $K^S$ [S1].
*   **$J$**: Set of surrogate identifiers. Fixed number held by the instance field MLP [S1].
*   **$H^{3D}$**: Set of all possible 3D instances, $H^{3D} := K^T \times J$ [S1].
*   **Loss Weights**: $\lambda_{con} = 1.35$, $\lambda_{ins} = 1$, $\lambda_{sem} = 1$, $\lambda_{RGB} = 1$ [S1].
*   **Optimizer**: Adam [S1].
*   **Learning Rates**: $5 \times 10^{-4}$ for MLPs, $1 \times 10^{-2}$ for TensoRF lines and planes [S1].
*   **Training Duration**: 450k iterations (~10 hours) on 1 NVIDIA A6000 [S1].
*   **2D Segmenter**: Mask2Former with Swin-L backbone [S1].

### Edge Cases and Pitfalls
*   **Logits vs. Probabilities:** Rendering class logits instead of probabilities can introduce semantic inconsistencies across viewpoints because unbounded logits can generate significant signals in low-density areas, violating geometric constraints. This is resolved by rendering bounded probability distributions [S1].
*   **Geometry Corruption:** Supervision from noisy 2D labels can influence geometry, causing "cloudy" geometry to satisfy conflicting labels. This is avoided by stopping gradients from segmentation branches back to densities [S1].
*   **Class Limitations:** The method is limited to classes supported by the pre-trained 2D segmentation model (e.g., COCO classes) [S1].
*   **Offline Nature:** The method runs offline due to lengthy pre-processing for pose estimation, 2D segmentation inference, and neural field optimization [S1].

## Operating characteristics

*   **Time Complexity:** Training is intensive, requiring 450k iterations (~10 hours) on a single NVIDIA A6000 [S1]. Inference (rendering) is comparable to other NeRF-based methods.
*   **Memory Complexity:** Depends on the TensoRF configuration and the size of the MLPs. TensoRF is generally more memory-efficient than dense MLPs for high-resolution scenes.
*   **Performance:** Improves scene-level Panoptic Quality (PQ) by 8.4% on Hypersim, 13.8% on Replica, and 10.6% on ScanNet over state-of-the-art methods [S1]. Maintains comparable PSNR for novel view synthesis [S1].
*   **Strengths:** Robust to noise in machine-generated labels; requires no manual ground truth; enables scene editing (deletion, duplication, manipulation) [S1].
*   **Limitations:** Limited to classes in the pre-trained 2D segmenter; offline processing; sensitive to pose estimation errors [S1].
*   **When to Use:** When only machine-generated 2D labels are available and high-quality 3D panoptic segmentation is required.
*   **When Not to Use:** When real-time training is required or when classes outside the pre-trained 2D model's vocabulary are needed [S1].

## Background

*   **Origin:** Panoptic Lifting was introduced in the paper "Panoptic Lifting for 3D Scene Understanding with Neural Fields" [S1].
*   **History:** It builds on the NeRF framework [Parent] and TensoRF [4], extending them to handle panoptic segmentation. It addresses the limitations of previous methods like Panoptic NeRF [11] and DM-NeRF [42], which required manual ground truth [S1].
*   **Usage:** Evaluated on Hypersim, Replica, and ScanNet datasets [S1].
