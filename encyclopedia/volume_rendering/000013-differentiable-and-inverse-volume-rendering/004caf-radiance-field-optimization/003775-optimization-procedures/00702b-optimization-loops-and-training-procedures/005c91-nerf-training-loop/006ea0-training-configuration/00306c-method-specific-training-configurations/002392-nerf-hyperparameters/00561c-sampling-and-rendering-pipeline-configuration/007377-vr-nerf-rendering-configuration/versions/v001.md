# VR NeRF Rendering Configuration

Also called: Meta Quest Pro NeRF Config

## Overview
This configuration defines the hyperparameters and rendering pipeline settings for training and rendering room-scale Neural Radiance Fields (NeRF) specifically for native execution on the Meta Quest Pro headset [S1]. It addresses the constraints of high-resolution (dual 2K×2K), high-frame-rate (72 FPS), and low-latency VR rendering by optimizing the hash grid structure, MLP architecture, and sampling strategy [S1]. It distinguishes itself from standard NeRF configurations by targeting specific hardware capabilities (Nvidia Tensor Cores) and utilizing a 20-GPU workstation setup for training, while maintaining a compact model size suitable for real-time inference on standalone VR hardware [S1].

## How it works
The method configures a differentiable volume rendering pipeline using Instant Neural Graphics Primitives (iNGP) style hash grids [S1]. The rendering process discretizes rays into samples and evaluates a multi-layer perceptron (MLP) to predict density and color.

**Inputs and Outputs**
- **Input**: Camera pose $(\mathbf{c}, \mathbf{R}, \mathbf{t})$, image resolution (target 2K×2K per eye), and training images (1K or 2K resolution).
- **Output**: Rendered color image $\mathbf{C}$ and optionally depth or segmentation masks.

**Data Structures**
1.  **Hash Grid**:
    -   Levels ($L$): 16 [S1].
    -   Base resolution ($N_{base}$): 128 [S1].
    -   Scaling factor ($s$): 1.4 [S1].
    -   Feature dimension: Two features per level (implied by iNGP standard, though not explicitly stated as a single number, the text says "two features" [S1]).
    -   Total entries: $\sum_{l=0}^{L-1} 2^l \cdot N_{base}^3$ (standard iNGP hashing).
2.  **MLP**:
    -   **Density MLP**: 1 hidden layer, 64 neurons [S1].
    -   **Color MLP**: 2 hidden layers, 64 neurons [S1].
    -   Inputs: Hash grid features concatenated with view direction (for color).
    -   Activation: Exponential color activation for HDR modeling (linear RGB space) [S1].
3.  **Optimizer State**:
    -   Adam optimizer parameters: $\beta_1 = 0.9$, $\beta_2 = 0.99$, $\epsilon = 10^{-15}$ [S1].

**Parameters**
-   **Samples per ray ($N_{samples}$)**: 1024 [S1].
-   **Sampling distribution**: Exponential distances [S1].
-   **Batch size**: 12,800 rays [S1].
    -   Composition: 256 random rays sampled from 50 random images per batch [S1].
-   **Learning Rates**:
    -   Hash grids: 0.01 [S1].
    -   Remaining modules (MLPs): 0.005 [S1].
-   **Training Iterations**:
    -   Ablation experiments: 110,000 iterations [S1].
    -   Demo videos: >200,000 iterations [S1].
-   **Dataset Resolution**:
    -   Ablation: 1K resolution [S1].
    -   Demo: 2K resolution [S1].
-   **Scene Type**: Far-field contraction used for unbounded scenes [S1].

**Numbered Steps**
1.  **Initialize Hash Grids**: Create 16 levels of hash grids with base resolution 128 and scaling factor 1.4 [S1].
2.  **Initialize MLPs**: Construct a 1-hidden-layer density MLP (64 neurons) and a 2-hidden-layer color MLP (64 neurons) [S1].
3.  **Sample Rays**: For each training batch, select 50 random images and sample 256 random rays per image, totaling 12,800 rays [S1].
4.  **Discretize Rays**: For each ray, sample 1024 points using exponential distance distribution [S1].
5.  **Query Hash Grids**: Map the 3D coordinates of the samples to hash grid indices and retrieve features [S1].
6.  **Evaluate MLPs**:
    -   Pass hash features through the density MLP to obtain volume density $\sigma$ [S1].
    -   Concatenate hash features and view direction, then pass through the color MLP to obtain color $\mathbf{c}$ [S1].
7.  **Volume Rendering**: Apply standard volume rendering integral using the sampled densities and colors to compute the final pixel color [S1].
8.  **Optimize**: Update parameters using Adam optimizer with specified learning rates and hyperparameters [S1].
9.  **Pruning (Optional)**: Use a coarse occupancy grid of $128^3$ resolution, annealing $\alpha$ linearly from 0 to 0.2, and upsample at predefined milestones to prune empty space [S1].

**Pseudocode**
```python
# Configuration Constants
L = 16                  # Hash grid levels
N_base = 128            # Base resolution
s = 1.4                 # Scaling factor
N_samples = 1024        # Samples per ray
Batch_size = 12800      # Total rays per batch
Rays_per_img = 256      # Rays per image in batch
Num_imgs = 50           # Images per batch
LR_hash = 0.01          # Learning rate for hash grids
LR_mlp = 0.005          # Learning rate for MLPs
Beta1 = 0.9
Beta2 = 0.99
Epsilon = 1e-15

# Data Structures
hash_grids = InitializeHashGrids(L, N_base, s)
density_mlp = InitializeMLP(layers=[64], activation='relu') # 1 hidden layer
color_mlp = InitializeMLP(layers=[64, 64], activation='relu') # 2 hidden layers
optimizer = Adam(params=[hash_grids, density_mlp, color_mlp], 
                 lr=[LR_hash, LR_mlp, LR_mlp], 
                 betas=(Beta1, Beta2), eps=Epsilon)

def render_ray(ray_origin, ray_direction, samples=N_samples):
    # Sample points along ray using exponential distribution
    t_vals = SampleExponential(t_near, t_far, samples)
    points = ray_origin + ray_direction * t_vals
    
    # Query hash grid
    features = QueryHashGrids(hash_grids, points)
    
    # Evaluate Density MLP
    sigma = density_mlp(features)
    
    # Evaluate Color MLP (concatenate features and view direction)
    view_dirs = Normalize(ray_direction)
    color_input = Concatenate(features, view_dirs)
    color = color_mlp(color_input)
    
    # Volume Rendering (Standard Alpha Compositing)
    weights = ComputeWeights(sigma, t_vals)
    final_color = Sum(weights * color)
    return final_color

def train_step(images, poses):
    # Select random subset of images and rays
    selected_imgs = RandomSample(images, Num_imgs)
    selected_poses = RandomSample(poses, Num_imgs)
    
    total_loss = 0
    for img, pose in zip(selected_imgs, selected_poses):
        # Sample rays from image
        rays = SampleRaysFromImage(img, pose, Rays_per_img)
        
        # Render each ray
        rendered_colors = [render_ray(r.origin, r.direction) for r in rays]
        
        # Compute loss against ground truth
        loss = ComputeLoss(rendered_colors, img.pixels)
        total_loss += loss
    
    # Backpropagate and update
    optimizer.zero_grad()
    total_loss.backward()
    optimizer.step()
    return total_loss
```

**Edge Cases and Pitfalls**
-   **Precision**: The use of exponential color activation requires handling HDR values correctly to prevent clipping or underflow [S1].
-   **Memory**: The 20-GPU training setup suggests high memory requirements for hash grids and gradients; inference on Quest Pro requires careful memory management [S1].
-   **Pruning**: The occupancy grid upsampling milestones must be carefully chosen to avoid pruning valid geometry prematurely [S1].

## Subtopics

### [VR-NeRF](22718-vr-nerf.md)
VR-NeRF is a holistic pipeline for the capture, reconstruction, and rendering of high-fidelity walkable spaces in virtual reality, designed to achieve higher resolution, frame rate, and visual fidelity than standard NeRF. It distinguishes itself by targeting native rendering on headsets like the Meta Quest Pro with strict latency and resolution constraints, utilizing specific training configurations and pruning strategies to maintain smoothness via Asynchronous Spacewarp (ASW).

## Operating characteristics
-   **Time Complexity**: Inference is optimized for real-time VR (72 FPS) using a custom multi-GPU CUDA renderer with in-register MLP evaluation [S1]. Training is computationally intensive, requiring a 20-GPU workstation [S1].
-   **Memory Complexity**: Hash grid size is determined by $L=16$, $N_{base}=128$, and scaling factor 1.4 [S1]. MLP size is small (64 neurons) [S1].
-   **Measured Performance**: Target is dual 2K×2K eyebuffers at 72 FPS on Meta Quest Pro [S1].
-   **Strengths**: High fidelity for room-scale scenes, optimized for VR hardware, efficient MLP evaluation [S1].
-   **Limitations**: Requires significant training resources (20 GPUs), complex setup [S1].
-   **When to use**: When deploying NeRFs on standalone VR headsets like Meta Quest Pro for high-quality, real-time experiences [S1].
-   **When not to use**: For non-VR applications or when training resources are limited [S1].

## Background
VR-NeRF was introduced in the paper "VR-NeRF: High-Fidelity Virtualized Walkable Spaces" [S1]. It was developed to address the limitations of standard NeRF in VR, specifically regarding resolution, frame rate, and latency. The work leverages iNGP techniques and custom hardware optimizations to enable native rendering on the Meta Quest Pro [S1].
