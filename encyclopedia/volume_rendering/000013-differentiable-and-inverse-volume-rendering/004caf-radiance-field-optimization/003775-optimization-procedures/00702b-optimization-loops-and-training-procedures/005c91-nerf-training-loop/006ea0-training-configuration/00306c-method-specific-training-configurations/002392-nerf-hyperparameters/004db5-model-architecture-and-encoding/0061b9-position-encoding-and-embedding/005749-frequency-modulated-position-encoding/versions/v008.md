# Frequency-Modulated Position Encoding

Also called: FM-NeRF Encoding, Frequency-Modulated Point Cloud Rendering with Easy Editing

## Overview
Frequency-Modulated Position Encoding is a coordinate encoding scheme used within point-based radiance field optimization to map 3D spatial coordinates and viewing directions to high-dimensional feature vectors. It solves the problem of representing high-frequency geometric and appearance details in sparse point clouds by applying sinusoidal basis functions with exponentially increasing frequencies. It sets itself apart from standard NeRF positional encoding by narrowing the encoding interval and using specific frequency bands for spatial versus directional inputs, and differs from hash-based encodings by relying on explicit sinusoidal modulation rather than learned lookup tables.

## How it works

### Inputs and Outputs
*   **Inputs:**
    *   Spatial coordinate $\mathbf{p} \in \mathbb{R}^3$ (or $\mathbb{R}^2$ for 2D projections).
    *   Viewing direction $\mathbf{d} \in S^2$ (normalized 3D vector).
    *   Number of frequency bands $L$.
*   **Outputs:**
    *   Encoded feature vector $\gamma(\mathbf{p})$ or $\gamma(\mathbf{d})$ of dimension $2 \times L \times \text{dim}(\mathbf{p})$.

### Data Structures
The encoding is a static mathematical transformation; no persistent data structure is required beyond the input vector and the integer parameter $L$.

### Parameters
*   $L_{\text{space}}$: Number of frequency bands for spatial coordinates. Default: 10 [S1].
*   $L_{\text{view}}$: Number of frequency bands for viewing directions. Default: 2 [S1].
*   $\lambda_{\text{sparse}}$: Weight for sparse regularization loss. Default: $5 \times 10^{-4}$ [S1].

### Formulas
The frequency-modulated positional encoding $\gamma(\mathbf{p})$ for an input $\mathbf{p}$ is defined as:

$$
\gamma (\mathbf {p}) = \left (\sin \left (2^0 \pi \mathbf {p}\right ), \cos \left (2^0 \pi \mathbf {p}\right ), \sin \left (2^{0.5} \pi \mathbf {p}\right ), \cos \left (2^{0.5} \pi \mathbf {p}\right ), \dots , \sin \left (2^{L-1} \pi \mathbf {p}\right ), \cos \left (2^{L-1} \pi \mathbf {p}\right )\right )
$$

Where:
*   $\mathbf{p}$ is the input coordinate or direction vector.
*   $L$ is the number of frequency bands.
*   The exponent of 2 increases by 0.5 for each subsequent pair of sine/cosine terms (i.e., $2^0, 2^{0.5}, 2^1, \dots, 2^{L-1}$). Note: The source notation $2^{L-1}$ in the final term implies the exponent sequence is $0, 0.5, 1.0, \dots$. Specifically, the $k$-th pair (0-indexed) uses frequency $2^{k/2}$.

### Pseudocode

```python
import numpy as np

def frequency_modulated_encoding(p, L):
    """
    Computes the frequency-modulated positional encoding for input p.
    
    Args:
        p: numpy array of shape (D,) representing the input coordinate/direction.
        L: int, number of frequency bands.
        
    Returns:
        numpy array of shape (2 * L * D,) representing the encoded features.
    """
    # Initialize output array
    # Each band produces 2 (sin/cos) * D features
    encoded_features = []
    
    for k in range(L):
        # Frequency exponent: 0, 0.5, 1.0, ..., L-1
        # The source formula shows exponents 0, 0.5, ..., L-1. 
        # If L=10, exponents are 0, 0.5, ..., 9.0.
        exponent = k / 2.0
        
        # Calculate frequency multiplier
        freq = np.power(2, exponent) * np.pi
        
        # Apply sine and cosine
        sin_val = np.sin(freq * p)
        cos_val = np.cos(freq * p)
        
        # Append to list
        encoded_features.append(sin_val)
        encoded_features.append(cos_val)
        
    # Concatenate all features
    return np.concatenate(encoded_features)

def compute_loss(predicted_color, gt_color, opacities, lambda_sparse):
    """
    Computes the total training loss.
    
    Args:
        predicted_color: numpy array of predicted RGB values.
        gt_color: numpy array of ground truth RGB values.
        opacities: numpy array of point opacities alpha_i.
        lambda_sparse: float, weight for sparse loss.
        
    Returns:
        float, total loss value.
    """
    # L_RGB: L2 distance between predicted and ground truth color
    l_rgb = np.sum((predicted_color - gt_color) ** 2)
    
    # L_sparse: Sparse regularization
    # Sum over N points: log(alpha_i) + log(1 - alpha_i)
    # Note: This term encourages opacities to be either 0 or 1.
    # We must handle numerical stability for log(0).
    # [G] Add small epsilon to avoid log(0)
    eps = 1e-7
    alpha = np.clip(opacities, eps, 1 - eps)
    l_sparse = np.mean(np.log(alpha) + np.log(1 - alpha))
    
    total_loss = l_rgb + lambda_sparse * l_sparse
    return total_loss
```

### Steps
1.  **Preprocessing:** Perform 4-20 loops of point cloud denoising and completion. For each denoising step, train for 300 epochs. Remove low-opacity points when training converges [S1].
2.  **Encoding:** For each point in the cloud, compute the spatial encoding $\gamma(\mathbf{p})$ using $L=10$ bands. For the viewing direction $\mathbf{d}$, compute $\gamma(\mathbf{d})$ using $L=2$ bands [S1].

4.  **Decoding:** Pass the concatenated features through the AFNet MLP (5 layers: 120 -> 256 -> 256 -> 256 -> 128 -> 11) to predict raw image (3 channels) and feature map (8 channels) [S1].
5.  **Rasterization:** Expand each point to a disk. Select radius to cover gaps between points (prevent bleeding) while keeping it small (prevent edge expansion) [S1].
6.  **Loss Calculation:** Minimize $\mathcal{L} = \mathcal{L}_{RGB} + \lambda_{sparse} \mathcal{L}_{sparse}$. For scenes without background, add transparency loss (L2 distance of predicted vs ground truth transparency) [S1].
7.  **Optimization:** Update MLP weights and opacity parameters $\alpha$ with learning rates $5 \times 10^{-4}$ and $0.01$ respectively [S1].

### Edge Cases and Pitfalls
*   **Bleeding Problem:** If the rasterization radius is too small, points from occluded surfaces and the background can be seen through the front surface [S1].
*   **Edge Expansion:** If the rasterization radius is too large, it leads to inaccurate depth estimation and object edges expand [S1].
*   **Numerical Stability:** The sparse loss involves $\log(\alpha_i)$ and $\log(1-\alpha_i)$. Opacities must be clamped away from 0 and 1 to prevent NaN gradients [G].

## Operating characteristics

*   **Time Complexity:** One epoch consumes approximately 12.8 seconds on the NeRF-Synthetic dataset [S1]. Realistic rendering is achieved in 10 minutes, but almost convergence takes about 10 hours [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Achieves higher PSNR/SSIM on NeRF-Synthetic and Tanks and Temples datasets compared to NeRF, CCNeRF, NPBG, NPBG++, and Huang et al. Comparable or better results on ScanNet and DTU datasets [S1].
*   **Strengths:** Fast convergence to realistic rendering; effective handling of sparse point clouds via frequency modulation; easy editing capabilities via point cloud masking [S1].
*   **Limitations:** Sensitive to rasterization radius selection (bleeding vs. edge expansion); requires initial point cloud from MVSNet or similar; performance depends on point cloud quality [S1].
*   **When to use:** When working with sparse point clouds and requiring fast training times with good visual quality, especially for editing tasks.
*   **When not to use:** When dense volumetric representation is required, or when high-frequency details cannot be captured by the limited frequency bands (L=10 for space, L=2 for view).

## Background

Frequency-Modulated Position Encoding was introduced in the paper "Frequency-Modulated Point Cloud Rendering with Easy Editing" [S1]. It builds on the positional encoding form of NeRF [21] but narrows the encoding interval to provide more fine-grained basis function support for frequency modulation. The method is designed for point-based rendering, addressing the sparsity of point clouds by expanding points to disks during rasterization. It has been evaluated on datasets including NeRF-Synthetic, Tanks and Temples, ScanNet, and DTU [S1].
