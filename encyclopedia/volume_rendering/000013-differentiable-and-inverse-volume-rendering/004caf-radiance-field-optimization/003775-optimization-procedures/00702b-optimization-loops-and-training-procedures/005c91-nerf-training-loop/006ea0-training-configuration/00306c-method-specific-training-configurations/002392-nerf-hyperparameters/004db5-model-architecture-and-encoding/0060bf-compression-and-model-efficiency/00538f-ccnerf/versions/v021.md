# CCNeRF

Also called: Compressible-Composable NeRF, Rank-residual Decomposition NeRF

## Overview
CCNeRF is a neural field representation that enables efficient compression and composition of 3D scenes by learning a hybrid tensor rank decomposition of the scene without using neural networks for rendering [S1]. Unlike NeRF variants that rely on a shared MLP renderer (e.g., NSVF) or TensoRF which uses MLPs that prevent direct compression/composition, CCNeRF models the field *only* with tensor rank decomposition, allowing arbitrary composition without retraining and dynamic model size adjustment via rank truncation [S1].

## How it works
CCNeRF represents a 3D scene as a 4D feature volume described by rank components and a weight matrix. The method allows for dynamic adjustment of model size via rank truncation and composition via rank concatenation [S1].

### Inputs and Outputs
*   **Input:** 3D coordinates $\mathbf{x} \in \mathbb{R}^3$ and viewing directions $\mathbf{d} \in S^2$.
*   **Output:** Volume density $\sigma \in \mathbb{R}$ and color $\mathbf{c} \in \mathbb{R}^3$.

### Data Structures
The model structure consists of two main parts [S1]:
1.  **Rank Weights Matrix ($W$):** A matrix storing weights for different feature channels. The dimensions are $R_{vec} \times R_{vec} + R_{mat} \times R_{mat}$, where $R_{vec}$ and $R_{mat}$ are the number of vector-based and matrix-based components, respectively.
2.  **Decomposed Rank Components:** A set of components that are either vector-based (CP decomposition) or matrix-based (triple plane variant). The ratio of vector- to matrix-based components is controllable [S1].

For a 3D tensor $T \in \mathbb{R}^{H \times W \times D}$, the Tucker decomposition is defined as [S1]:
$$ T_{i,j,k} = \sum_{p=1}^P \sum_{q=1}^Q \sum_{r=1}^R S_{p,q,r} U^x_{i,p} U^y_{j,q} U^z_{k,r} $$
where $S$ is the core tensor and $U^x, U^y, U^z$ are factor matrices. CCNeRF uses a hybrid of CP and a triple plane variant [S1].

### Numbered Steps

1.  **Training (Rank-Residual Learning):**
    The model is trained to learn the rank components and weights. A rank-residual learning strategy is employed to encourage the preservation of primary information in lower ranks [S1]. This ensures that lower ranks contain the most important scene information, facilitating effective compression.

2.  **Querying a 3D Coordinate:**
    To query a point $\mathbf{x}$:
    a. Project the coordinate to the decomposed vectors or matrices.
    b. Perform weighted interpolation using the stored rank weights from matrix $W$ [S1].

3.  **Volume Rendering:**
    Compute the pixel color $\hat{C}(r)$ for a ray $r$ using the standard volume rendering equation [S1]:
    $$ \hat{C}(r) = \sum_i T_i \alpha_i c_i $$
    where:
    *   $T_i = \prod_{j<i} (1 - \alpha_j)$ is the accumulated transmittance.
    *   $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$ is the opacity of the $i$-th sample.
    *   $\delta_i = t_{i+1} - t_i$ is the distance between samples.
    *   $\sigma_i$ is the density and $c_i$ is the color at sample position $t_i$ along ray $r$ from origin $o$ with direction $d$ [S1].

4.  **Compression (Rank Truncation):**
    Model size is dynamically adjusted by rank truncation. An empirical sort-and-truncate strategy is used to achieve near-optimal low-rank approximation at any targeted rank. This allows trade-off between model size and rendering quality without retraining [S1]. The number of components kept in the decomposition determines the model size and detail level. Lower ranks preserve primary information due to rank-residual learning [S1].

5.  **Composition:**
    Different models are composed by concatenating their rank components along the rank dimension. A transformation matrix is recorded for each object to control its position and orientation. Since there are no MLP renderers, this composition is arbitrary and requires no retraining or compatibility constraints [S1].

def compress_ccnerf(rank_components, weights, target_rank):
    """
    Compress the model by truncating ranks.
    
    Args:
        rank_components: List of rank components.
        weights: numpy array of weights.
        target_rank: int, the desired number of components to keep.
        
    Returns:
        compressed_components: List of truncated rank components.
        compressed_weights: numpy array of truncated weights.
    """
    # Empirical sort-and-truncate strategy
    # Sort weights by magnitude
    sorted_indices = np.argsort(np.abs(weights))[::-1]
    
    # Keep top target_rank components
    keep_indices = sorted_indices[:target_rank]
    
    # Sort the components and weights accordingly
    # Note: rank_components and weights must be aligned
    compressed_weights = weights[keep_indices]
    compressed_components = [rank_components[i] for i in keep_indices]
    
    return compressed_components, compressed_weights

    """
    Compose two CCNeRF models by concatenating rank components.

        model_b: dict with 'rank_components' and 'weights' and 'transform_matrix'
        
    Returns:
        composed_model: dict with concatenated components and combined transform matrices.
    """
    # Concatenate rank components along the rank dimension

    return {
        'rank_components': combined_components,

### Parameters
*   **Rank Truncation:** The number of components kept in the decomposition determines the model size and detail level. Lower ranks preserve primary information due to rank-residual learning [S1].
*   **Vector-to-Matrix Ratio:** The ratio of vector- to matrix-based components is controllable to trade off between model size and performance [S1].

### Edge Cases and Pitfalls
*   **Truncated HOSVD:** Standard truncated Higher-Order SVD (HOSVD) does not hold the optimal property of truncated SVD, but yields a quasi-optimal solution sufficient for practical use [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Model size is dynamically adjustable via rank truncation. The storage cost growth can be mitigated by compressing unimportant objects in the composed scene [S1].
*   **Measured Performance:** The method achieves comparable rendering quality to state-of-the-art methods while enabling extra capability of compression and composition [S1].
*   **Scaling:** Not given in the sources.
*   **Strengths:** No neural networks for rendering, allowing arbitrary composition without retraining or compatibility constraints. Dynamic adjustment of model size via rank truncation without retraining.
*   **Limitations:** Standard truncated HOSVD is only quasi-optimal.
*   **When to use:** When compression and composition of 3D scenes are required without the overhead of neural network rendering.
*   **When not:** When high-fidelity view-dependent effects requiring complex MLP decoders are necessary (though CCNeRF claims comparable quality, it lacks the MLP capacity of standard NeRF).

## Background
CCNeRF was introduced by Jiaxiang Tang, Xiaokang Chen, Jingbo Wang, and Gang Zeng from Peking University and Chinese University of Hong Kong in 2022 [S1]. It addresses the difficulty in manipulating implicit NeRF representations, such as compression and composition, which are typically restricted by shared renderer networks or suffer from large model sizes [S1]. The method is motivated by the low-rank approximation property of the SVD algorithm [S1].
