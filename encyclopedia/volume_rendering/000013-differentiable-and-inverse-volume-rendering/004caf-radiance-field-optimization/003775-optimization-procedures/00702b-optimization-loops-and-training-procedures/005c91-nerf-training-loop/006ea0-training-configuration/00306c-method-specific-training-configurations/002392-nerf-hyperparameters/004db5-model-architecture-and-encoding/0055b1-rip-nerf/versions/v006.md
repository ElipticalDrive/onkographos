# Rip-NeRF

Also called: Rip-NeRF25k

## Overview
Rip-NeRF is a radiance field method that renders high-fidelity, anti-aliased images by combining cone casting with an explicit hybrid representation of anisotropic 3D Gaussians [S1]. It differs from standard NeRF by replacing point-based sampling with area-sampling, where conical frustums are characterized by Gaussians and featurized via Platonic Solid Projection and Ripmap Encoding [S1]. This approach enables efficient anisotropic area-sampling of 3D space, offering faster training and smaller model sizes compared to multi-sampling alternatives like Zip-NeRF, while maintaining competitive anti-aliasing quality [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of calibrated multi-view 2D images with known camera poses.
*   **Outputs:** Rendered RGB images and depth maps for arbitrary viewpoints.

**Data Structures:**
1.  **Ripmap Encoding ($R$):** A hierarchical grid of learnable features.
    *   **Base Level ($R_{0,0}$):** A 3D tensor of shape $H \times W \times C$. Default dimensions: $H=512, W=512, C=16$ [S1].
    *   **Derived Levels:** Higher levels are not stored explicitly but are derived from the base level using averaging operations to ensure consistency and compactness [S1].
2.  **Platonic Solid Projection:** The 3D space is projected onto the faces of a Platonic solid. Default is an icosahedron with $n=10$ unparalleled faces [S1].
3.  **Anisotropic 3D Gaussian:** Each conical frustum is characterized by a mean $\boldsymbol{\mu} \in \mathbb{R}^3$ and a covariance matrix $\boldsymbol{\Sigma} \in \mathbb{R}^{3 \times 3}$ [S1].
4.  **Tiny MLP ($F_\theta$):** A small multi-layer perceptron that takes aggregated feature vectors and view directions to predict density and color [S1].

**Numbered Steps:**

1.  **Cone Casting and Frustum Division:**
    For each pixel, cast a cone into the scene and divide it into multiple conical frustums along the ray [S1]. This avoids discrete point-based sampling of continuous signals [S1].

2.  **Gaussian Characterization:**
    Characterize each conical frustum as an anisotropic 3D Gaussian parameterized by mean $\boldsymbol{\mu}$ and covariance $\boldsymbol{\Sigma}$ [S1].

3.  **Platonic Solid Projection:**
    Project the 3D Gaussian onto the $n$ faces of the Platonic solid. For each face $P_i$ (where $i = 1, \dots, n$):
    *   Apply a projection matrix $M_i \in \mathbb{R}^{3 \times 2}$ to map the 3D world coordinates to the 2D coordinate system of plane $P_i$ [S1].
    *   Compute the projected mean $\boldsymbol{\mu}_{proj}$ and covariance $\boldsymbol{\Sigma}_{proj}$ of the 2D Gaussian on plane $P_i$ [S1].

4.  **Ripmap Encoding Query:**
    For each projected 2D Gaussian on plane $P_i$, query a feature vector $\mathbf{f}_i$ from the Ripmap Encoding using tetra-linear interpolation [S1].
    *   The position $(p_x, p_y)$ for interpolation is determined by $\boldsymbol{\mu}_{proj}$ [S1].
    *   The level $(l_x, l_y)$ for interpolation is determined by $\boldsymbol{\Sigma}_{proj}$ [S1].
    *   The interpolation uses a hyper-parameter $w$ to adjust the probability mass coverage. Default $w = 2.0$ [S1].
    *   *Note on Ripmap Derivation:* Higher levels $R_{i,j}$ are derived from the base level $R_{0,0}$ as follows [S1]:
        $$
        R_{i,j} = \begin{cases} 
        \text{Avg}_{2 \times 1} R_{i, j-1} & \text{if } j \neq 0 \\
        \text{Avg}_{1 \times 2} R_{i-1, j} & \text{if } i \neq 0 \text{ and } j = 0 \\
        R_{0,0} & \text{otherwise}
        \end{cases}
        $$
        where $i$ and $j$ are indices of levels in the $x$ and $y$ directions, respectively. Only $R_{0,0}$ is learnable [S1].

5.  **Feature Aggregation:**
    Concatenate all feature vectors $\{\mathbf{f}_i \mid i = 1, \dots, n\}$ obtained from the $n$ Platonic solid faces to form the final feature vector $\mathbf{f}$ for the 3D Gaussian [S1].

6.  **Density and Color Prediction:**
    Concatenate the aggregated feature vector $\mathbf{f}$ with the encoded viewing direction $\mathbf{d}$ [S1]. Pass this combined vector through the tiny MLP $F_\theta$ to estimate the density $\sigma$ and color $\mathbf{c}$ of the conical frustum [S1].

7.  **Volume Rendering:**
    Render the pixel color by performing volume rendering using the estimated color $\mathbf{c}$ and density $\sigma$ values from the sampled frustums [S1].

8.  **Optimization:**
    Optimize the system end-to-end using a photometric loss between rendered and observed images [S1].
    *   **Area Loss:** Scale the photometric loss for each pixel by the area of its footprint on the image plane, denoted as $L_{area}$ [S1]. This makes the loss area-aware [S1].

import torch
import torch.nn as nn
import torch.nn.functional as F

class RipNeRF:
    def __init__(self, num_faces=10, base_h=512, base_w=512, base_c=16, w=2.0):
        """
        Initialize Rip-NeRF.
        :param num_faces: Number of faces on the Platonic solid (default 10 for icosahedron).
        :param base_h, base_w, base_c: Dimensions of the base Ripmap level R_0,0.
        :param w: Hyper-parameter for Gaussian footprint coverage.
        """
        self.num_faces = num_faces
        self.w = w
        # Base level is learnable; higher levels are derived
        self.base_ripmap = nn.Parameter(torch.randn(base_h, base_w, base_c))
        
        # Tiny MLP for density and color prediction
        # Input dim: base_c * num_faces + directional_encoding_dim
        # Output dim: 4 (density + 3 RGB)
        self.mlp = nn.Sequential(
            nn.Linear(base_c * num_faces + 27, 64), # 27 is standard SH degree 2 dim or similar
            nn.ReLU(),
            nn.Linear(64, 32),
            nn.ReLU(),
            nn.Linear(32, 4) # sigma, r, g, b
        )
        
        # Projection matrices for Platonic solid faces (precomputed)
        self.projection_matrices = self._get_platonic_projections(num_faces)

    def _get_platonic_projections(self, num_faces):
        """
        Returns a list of projection matrices M_i for each face.
        In practice, these are fixed geometric transformations.
        """
        # Placeholder for actual geometric projection matrix generation
        # Each M_i is 3x2 mapping 3D world to 2D plane coordinates
        return [torch.eye(2, 3) for _ in range(num_faces)] # Simplified for structure

    def derive_ripmap_level(self, i, j):
        """
        Derive Ripmap level R_{i,j} from base level using averaging.
        """
        if i == 0 and j == 0:
            return self.base_ripmap
        
        # Get parent levels
        if j != 0:
            parent = self.derive_ripmap_level(i, j - 1)
            # Avg_2x1: Average along x-axis (dim 0)
            # Assuming parent is H x W x C
            # To average 2x1, we reshape and average
            h, w, c = parent.shape
            # Reshape to (h/2, 2, w, c) -> average dim 1 -> (h/2, w, c)
            # Note: This requires h to be even. 
            # The source implies a hierarchical structure where levels are coarser.
            # Standard mipmapping logic:
            if h % 2 == 0:
                parent_reshaped = parent.reshape(h//2, 2, w, c)
                return parent_reshaped.mean(dim=1)
            else:
                # Fallback or error if dimensions don't align, 
                # but source implies consistent derivation.
                return parent # [G] Fallback for odd dimensions not specified in source
        
        if i != 0 and j == 0:
            parent = self.derive_ripmap_level(i - 1, j)
            # Avg_1x2: Average along y-axis (dim 1)
            h, w, c = parent.shape
            if w % 2 == 0:
                parent_reshaped = parent.reshape(h, w//2, 2, c)
                return parent_reshaped.mean(dim=2)
            else:
                return parent

    def query_ripmap(self, x, y, level_x, level_y):
        """
        Query feature vector from Ripmap using tetra-linear interpolation.
        :param x, y: Normalized 2D coordinates on the plane.
        :param level_x, level_y: Integer indices for the level in x and y directions.
        """
        # Determine the grid size for the requested level
        # Level 0 is base_h x base_w
        # Level i is roughly base_h / 2^i x base_w / 2^i
        # However, source says levels are derived. We can just access the derived tensor.
        
        # Get the specific level tensor
        # Note: In implementation, one might precompute or cache derived levels
        # or compute on the fly. For simplicity, we assume a helper to get level tensor.
        # Since derive_ripmap_level is recursive, we might want to memoize or flatten.
        # For this pseudocode, we assume we can get the tensor for level (level_x, level_y).
        
        # Let's assume a helper `get_level_tensor(level_x, level_y)` exists
        # which calls derive_ripmap_level and returns the tensor.
        level_tensor = self.get_level_tensor(level_x, level_y)
        
        h, w, c = level_tensor.shape
        
        # Map x, y to grid coordinates
        # x, y are typically in [0, 1] or [-1, 1]. Source doesn't specify range.
        # Assuming normalized [0, 1] mapped to [0, w-1], [0, h-1]
        grid_x = x * (w - 1)
        grid_y = y * (h - 1)
        
        # Tetra-linear interpolation (bilinear in 2D grid)
        # Get floor and ceil coordinates
        x0 = torch.floor(grid_x).long()
        y0 = torch.floor(grid_y).long()
        x1 = x0 + 1
        y1 = y0 + 1
        
        # Clamp to boundaries
        x0 = torch.clamp(x0, 0, w - 1)
        x1 = torch.clamp(x1, 0, w - 1)
        y0 = torch.clamp(y0, 0, h - 1)
        y1 = torch.clamp(y1, 0, h - 1)
        
        # Interpolation weights
        wx = grid_x - x0.float()
        wy = grid_y - y0.float()
        
        # Get values
        v00 = level_tensor[y0, x0, :] # h, w, c -> y, x, c
        v10 = level_tensor[y0, x1, :]
        v01 = level_tensor[y1, x0, :]
        v11 = level_tensor[y1, x1, :]
        
        # Bilinear interpolation
        v0 = v00 * (1 - wx) + v10 * wx
        v1 = v01 * (1 - wx) + v11 * wx
        v = v0 * (1 - wy) + v1 * wy
        
        return v

        """

        all_directions = []
        
        for sample in samples:
            mu_3d = sample.mu
            sigma_3d = sample.sigma
            
            features_per_face = []
            
            # 3. Platonic Solid Projection

                M_i = self.projection_matrices[i]
                
                # Project mean and covariance
                # mu_proj = M_i^T * mu_3d ? Or M_i * mu_3d?
                # Source: M_i in R^{3x2} maps 3D to 2D.
                # Usually projection is P * X. If M is 3x2, it might be a basis.
                # Let's assume standard projection: mu_2d = M_i^T * mu_3d (if M is 3x2 basis)
                # Or mu_2d = M_i * mu_3d (if M is 2x3). Source says M_i in R^{3x2}.
                # If M is 3x2, it likely maps 2D plane coords to 3D world.
                # Inverse mapping: 2D = (M^T M)^-1 M^T * 3D.
                # For simplicity, we assume a function `project_2d` handles this.
                mu_2d, sigma_2d = project_2d_gaussian(mu_3d, sigma_3d, M_i)
                
                # 4. Query Ripmap
                # Position determined by mu_2d
                px, py = mu_2d[0], mu_2d[1]
                # Level determined by Sigma_2d and w
                # Source: level (lx, ly) determined by covariance.
                # Typically, larger variance -> higher level (coarser).
                # Formula not explicitly given for lx, ly from Sigma, but w=2.0 adjusts mass.
                # [G] Assume a heuristic: level = floor(log2(variance * w))
                lx = int(torch.floor(torch.log2(torch.sqrt(sigma_2d[0,0]) * self.w)))
                ly = int(torch.floor(torch.log2(torch.sqrt(sigma_2d[1,1]) * self.w)))
                
                f_i = self.query_ripmap(px, py, lx, ly)
                features_per_face.append(f_i)
            
            # 5. Aggregate

            # 6. Predict

            d_encoded = encode_direction(sample.direction) # e.g., SH or PE
            input_vec = torch.cat([f_final, d_encoded], dim=-1)
            
            output = self.mlp(input_vec)
            sigma = torch.relu(output[0]) # Density
            color = torch.sigmoid(output[1:]) # Color [0,1]
            
            all_features.append((sigma, color))
            
        # 7. Volume Rendering

        return colors, depths

**Parameters:**
*   **Ripmap Base Size:** $H=512, W=512, C=16$ [S1].
*   **Platonic Solid:** Icosahedron (10 faces) [S1].
*   **Hyper-parameter $w$:** 2.0, adjusting Gaussian footprint probability mass coverage [S1].
*   **Optimizer:** AdamW [S1].
*   **Iterations:** 120,000 for Rip-NeRF; 25,000 for Rip-NeRF25k [S1].
*   **Weight Decay:** $1 \times 10^{-5}$ [S1].
*   **Initial Learning Rate:** $2 \times 10^{-3}$, modulated by MultiStepLR [S1].
*   **Ripmap Learning Rate:** Scaled up by 10.0 times relative to the base learning rate [S1].

**Edge Cases and Pitfalls:**
*   **Empty Space:** Use a binary occupancy grid (e.g., from NerfAcc) to skip samples in empty areas, improving efficiency [S1].
*   **Precision:** The derivation of higher-level Ripmap grids from the base level ensures consistency but requires careful handling of grid dimensions (even/odd) during averaging [S1].
*   **Boundary Conditions:** Interpolation coordinates must be clamped to the valid range of the Ripmap grid [G].

## Operating characteristics
*   **Training Time:** 2.6 hours on an NVIDIA A100-SXM4-80GB GPU for the standard Rip-NeRF (120k iterations) [S1]. The Rip-NeRF25k variant (25k iterations) trains in 32 minutes, which is 11.76% of Zip-NeRF's 4.5 hours [S1].
*   **Model Size:** 160 MB [S1]. This is significantly smaller than Zip-NeRF's 592 MB [S1].
*   **GPU Memory:** 20 GB during training [S1]. This is feasible for consumer GPUs like the RTX 4090, whereas Zip-NeRF requires ~80 GB [S1].
*   **Rendering Speed:** Approximately 3 FPS in the experimental setting [S1]. This outperforms Zip-NeRF's 0.25 FPS [S1].
*   **Strengths:** High-fidelity anti-aliasing, efficient anisotropic area-sampling, compact model size, and fast training/rendering compared to multi-sampling methods [S1].
*   **Limitations:** Requires calibrated multi-view images [S1]. SSIM is slightly lower than Zip-NeRF, though PSNR and LPIPS are better [S1].
*   **When to Use:** When high-quality anti-aliased rendering is needed with limited GPU memory and faster training times are preferred over maximum SSIM [S1].
*   **When Not to Use:** If unbounded scenes are the primary requirement (Zip-NeRF is designed for this) or if maximum SSIM is the sole metric [S1].

## Background
Rip-NeRF was introduced in the paper "Rip-NeRF: Anti-aliasing Radiance Fields with Ripmap-Encoded Platonic Solids" [S1]. It builds upon the hybrid representation approach, combining the efficiency of explicit representations (like 3D Gaussians) with the flexibility of implicit representations (like MLPs) [S1]. The method addresses the limitations of discrete point-based sampling in NeRF by using cone casting and area-sampling, inspired by Mip-NeRF and Tri-MipRF [S1]. It specifically improves upon Zip-NeRF's multi-sampling mechanism by using Ripmap-Encoded Platonic Solids for more efficient anisotropic area-sampling [S1].
