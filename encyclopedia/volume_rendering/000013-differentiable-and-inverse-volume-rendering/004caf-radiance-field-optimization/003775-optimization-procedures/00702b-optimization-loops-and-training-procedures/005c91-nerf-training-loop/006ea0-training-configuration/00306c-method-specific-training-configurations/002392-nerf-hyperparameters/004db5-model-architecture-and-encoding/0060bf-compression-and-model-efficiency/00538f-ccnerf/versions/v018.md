# CCNeRF
Also called: Rank-residual Decomposition NeRF

## Overview
CCNeRF is a neural field representation that enables efficient compression and composition of 3D scenes by learning a hybrid tensor rank decomposition of the scene volume, eliminating the need for neural networks during the rendering process [S1]. Unlike NeRF variants that rely on a shared MLP renderer (e.g., NSVF) or hybrid structures that prevent direct tensor manipulation (e.g., TensoRF), CCNeRF models the radiance field *only* with tensor rank decomposition, allowing arbitrary composition of objects via rank concatenation and dynamic resolution adjustment via rank truncation without retraining [S1].

## How it works
CCNeRF represents a 3D scene as a 4D feature volume described by rank components and a weight matrix. The method replaces the standard MLP-based query with a direct algebraic evaluation of decomposed tensors.

### Inputs and Outputs
*   **Input:** A 3D coordinate $\mathbf{x} = (x, y, z)$ and a viewing direction $\mathbf{d} = (\theta, \phi)$.
*   **Output:** Volume density $\sigma$ and color $\mathbf{c} = (r, g, b)$.

### Data Structures
The model consists of two primary components [S1]:
1.  **Rank Weights Matrix ($W$):** A matrix storing weights for different feature channels. It maps the aggregated rank features to the final output dimensions.
2.  **Decomposed Rank Components:** A set of vectors or matrices representing the spatial and directional features. These are categorized into:
    *   **Vector-based (CP):** Corresponding to CANDECOMP/PARAFAC decomposition.
    *   **Matrix-based (Triple Plane):** A less compact variant using plane factors.
    *   The ratio of vector- to matrix-based components is a controllable hyperparameter to trade off between model size and performance.

### Formulas
The volume rendering equation remains standard [S1]:
$$ \hat{C}(r) = \sum_i T_i \alpha_i c_i $$
where $T_i = \prod_{j<i} (1 - \alpha_i)$, $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$, and $\delta_i = t_{i+1} - t_i$. Here $\sigma_i$ is density, $c_i$ is color, and $t_i$ is the sample position along ray $r$ from origin $o$ with direction $d$.

The core representation uses a hybrid Tucker-like decomposition. For a 3D tensor $T \in \mathbb{R}^{H \times W \times D}$, the decomposition is defined as [S1]:
$$ T_{i,j,k} = \sum_{p=1}^P \sum_{q=1}^Q \sum_{r=1}^R S_{p,q,r} U^x_{i,p} U^y_{j,q} U^z_{k,r} $$
where $S$ is the core tensor and $U^x, U^y, U^z$ are factor matrices. In CCNeRF, this is extended to a hybrid structure where some factors are vectors (CP) and others are matrices (Triple Plane).

### Parameters
*   **Rank ($R$):** The number of components kept in the decomposition. This determines the model size and detail level. Lower ranks preserve primary information due to rank-residual learning [S1].
*   **Hybrid Ratio:** The proportion of vector-based vs. matrix-based components [S1].

### Numbered Steps

1.  **Initialization (Training Phase):**
    *   Initialize the rank components (vectors/matrices) and the weight matrix $W$.
    *   Apply **Rank-Residual Learning**: During optimization, the model is trained such that lower ranks capture the most significant information. This is achieved by encouraging the preservation of primary information in lower ranks, often via specific loss weighting or initialization strategies that prioritize low-frequency or high-magnitude components [S1].
    *   *Note:* The sources do not provide the exact loss function or optimization algorithm (e.g., Adam, SGD) details, only the structural constraint of rank-residual learning [S1].

2.  **Querying a 3D Coordinate (Inference/Rendering):**
    *   **Project:** For a given 3D coordinate $\mathbf{x}$, project it onto the stored decomposed vectors or matrices. For vector-based components, this is a dot product; for matrix-based components, this involves linear interpolation or projection onto the planes [S1].
    *   **Aggregate:** Combine the projected features from all rank components.
    *   **Interpolate:** Perform weighted interpolation using the stored rank weights matrix $W$. The aggregated features are multiplied by $W$ to produce the final density $\sigma$ and color $\mathbf{c}$ [S1].
    *   *Pseudocode for Query:*
        ```python
        def query_ccnerf(x, rank_components, weights):
            # rank_components is a list of tensors (vectors or matrices)
            # weights is the rank weights matrix W
            
            features = []
            for comp in rank_components:
                # Project x onto the component
                # If comp is a vector (CP): dot product
                # If comp is a matrix (Triple Plane): interpolate/project
                projected = project_coordinate(x, comp)
                features.append(projected)
            
            # Aggregate features (e.g., concatenate or sum)
            aggregated = aggregate(features)
            
            # Weighted interpolation using W
            # W maps aggregated features to (sigma, color)
            output = aggregated @ weights
            
            sigma = output[..., 0] # Assuming first channel is sigma
            color = output[..., 1:] # Remaining channels are color
            
            return sigma, color
        ```

3.  **Compression (Rank Truncation):**
    *   To compress the model, perform an empirical **sort-and-truncate** strategy on the rank components.
    *   Sort the rank components based on their importance (e.g., magnitude of weights or energy).
    *   Truncate the components to a target rank $R' < R$.
    *   This achieves near-optimal low-rank approximation at any targeted rank, allowing dynamic trade-off between model size and rendering quality without retraining [S1].
    *   *Pitfall:* Standard truncated HOSVD does not hold the optimal property of truncated SVD, but yields a quasi-optimal solution sufficient for practical use [S1].

4.  **Composition (Rank Concatenation):**
    *   To compose different models (objects) into one scene, concatenate their rank components along the rank dimension.
    *   Record a transformation matrix for each object to control its position and orientation.
    *   The growth of storage cost is mitigated by compressing unimportant objects in the composed scene via rank truncation [S1].
    *   *Pseudocode for Composition:*
        ```python
        def compose_models(model_a, model_b, transform_a, transform_b):
            # Concatenate rank components along the rank dimension
            # Note: The weight matrix W must also be adjusted or expanded
            # to handle the increased number of rank components.
            
            # Assuming rank_components are lists of tensors
            new_rank_components = model_a.rank_components + model_b.rank_components
            
            # Adjust weights to account for new rank dimension
            # This may require expanding W or using a new W for the composed scene
            # The sources state concatenation along rank dimension, implying
            # the feature space grows.
            new_weights = expand_weights(model_a.weights, model_b.weights)
            
            # Store transformation matrices
            transformations = {
                'a': transform_a,
                'b': transform_b
            }
            
            return {
                'rank_components': new_rank_components,
                'weights': new_weights,
                'transformations': transformations
            }
        ```

### Edge Cases and Pitfalls
*   **Precision:** The quasi-optimal nature of truncated HOSVD means that aggressive truncation may lead to noticeable quality loss, though it is generally sufficient for practical use [S1].
*   **Boundaries:** The method relies on the low-rank approximation property. If the scene data is not inherently low-rank, compression will result in significant artifacts.
*   **Degenerate Input:** The sources do not specify handling for degenerate inputs (e.g., empty scenes), but the tensor decomposition framework implies that zero-rank components would result in null outputs [S1].

## Operating characteristics
*   **Time Complexity:** Rendering is faster than MLP-based NeRFs as it involves only tensor operations (dot products, interpolation) and matrix multiplications, avoiding forward passes through deep networks [S1].
*   **Memory Complexity:** Memory usage is determined by the rank $R$ and the hybrid structure. Compression reduces memory linearly with the rank [S1].
*   **Measured Performance:** The method achieves comparable rendering quality to state-of-the-art methods while enabling extra capabilities of compression and composition [S1].
*   **Strengths:** No neural networks for rendering; arbitrary composition without retraining; dynamic LOD control via rank truncation.
*   **Limitations:** Requires careful initialization and training to ensure low-rank structure is learned; truncated HOSVD is only quasi-optimal.
*   **When to use:** When scene manipulation (compression, composition) is required, and computational efficiency during rendering is a priority.
*   **When not to use:** When the scene does not exhibit low-rank properties, or when maximum possible rendering quality is required without any compression artifacts.

## Background
CCNeRF was introduced by Jiaxiang Tang, Xiaokang Chen, Jingbo Wang, and Gang Zeng from Peking University and the Chinese University of Hong Kong [S1]. The paper, titled "Compressible-Composable NeRF via Rank-residual Decomposition," was published on arXiv in October 2022 [S1]. It addresses the limitations of NeRF's implicit representation, which makes manipulation difficult compared to explicit meshes. Previous attempts at NeRF manipulation were restricted by shared renderer networks or large model sizes. CCNeRF builds on the low-rank approximation property of SVD and tensor decomposition techniques like Tucker decomposition [S1]. It contrasts with TensoRF, which uses MLPs that prevent compression/composition, by modeling the field *only* with tensor rank decomposition [S1].
