# Exponential Decay Learning Rate Schedule

Also called: Adam with Exponential Decay, Exponential Decay Schedule, Exponential LR Schedule, ExponentialSchedule, Instant NGP LR Schedule, LambdaLR Exponential Decay, Training Optimizer and Schedule

## Overview
An exponentially decaying schedule transitions from an initial value to a final value using a base raised to a normalized step exponent [S1, unofficial]. It produces a continuous curve without discrete jumps, ensuring the learning rate asymptotically approaches zero rather than reaching it abruptly [G]. It is commonly implemented via framework schedulers like PyTorch's `LambdaLR` [S2, unofficial] or applied manually in custom training loops [S3].

## How it works
**Inputs:** Initial learning rate ($lr_{initial}$), decay factor ($\gamma$), normalization interval ($T$), current step index ($t$) [S2, unofficial].
**Outputs:** Adjusted learning rate ($lr_t$) [S2, unofficial].

**Data Structures:**
The scheduler maintains a state variable for the current step or epoch index [S2, unofficial]. Framework implementations (e.g., `LambdaLR`) wrap the optimizer and apply a lambda function at each optimization step [S2, unofficial].

**Steps:**
1. Initialize the optimizer with parameter groups and their respective initial learning rates [S3].
2. Initialize the scheduler state with the starting step index, typically $t = start\_epoch - 1$ to align with zero-based indexing conventions in frameworks like PyTorch's `LambdaLR` [S2, unofficial].
3. At each optimization step, compute the decay factor using the formula:
   $$ lr_t = lr_{initial} \times \gamma^{\frac{t}{T}} $$
   where:
   - $lr_{initial}$ is the base learning rate for a parameter group [S2, unofficial].
   - $\gamma$ is the decay factor ($0 < \gamma < 1$) [S3].
   - $t$ is the current training step or epoch [S2, unofficial].
   - $T$ is the normalization interval or step size [S2, unofficial].
4. Apply the computed $lr_t$ to the optimizer's parameter groups [S3].
5. Increment the scheduler state index for the next step [G].

**Parameters:**
- Typical values for NeRF-style optimization use separate parameter groups: positions ($lr_{initial} = 10^{-4}$), features ($lr_{initial} = 5 \times 10^{-3}$), and MLP weights ($lr_{initial} = 5 \times 10^{-5}$) [S3].
- Decay factor $\gamma = 0.33$ applied every $T = 10,000$ steps, often starting after a fixed iteration count (e.g., $t \ge 20,000$) [S3].

**Pitfalls:**
- Precision underflow may occur if $\gamma^{(t/T)}$ becomes too small for very large $t$ or if $\gamma$ is excessively close to $0$ [G].

**Pseudocode:**
```python
def compute_exponential_lr(initial_lr, gamma, T, current_step, start_step=0):
    """
    Compute the learning rate using exponential decay.
    
    Args:
        initial_lr (float): The starting learning rate for a parameter group.
        gamma (float): The decay factor (0 < gamma < 1).
        T (float): The normalization interval.
        current_step (int): The current training step index t.
        start_step (int): Optional offset to delay decay start (default 0).
        
    Returns:
        float: The adjusted learning rate.
    """
    # Apply optional start step offset to align with implementations that delay decay
    t = max(0, current_step - start_step)
    
    # Compute the decayed learning rate
    lr = initial_lr * (gamma ** (t / T))
    
    return lr
```

## Subtopics

### [Step Decay Learning Rate Schedule](11852-step-decay-learning-rate-schedule.md)
A step-wise decay schedule that reduces a learning rate by a fixed multiplicative factor at regular intervals until a maximum number of decays is reached. It differs from the parent [Exponential Decay Schedules](18486-exponential-decay-schedules.md) by applying discrete, uniform reductions at specific step boundaries rather than a continuous exponential curve.

### Logarithmic Decay Learning Rate Schedule
Scales the learning rate for each Gaussian level using a logarithmic decay function dependent on the current frame/iteration ID to stabilize optimization across pyramid levels [S4, unofficial]. At each optimization step, the level iteration counter increments and the decay factor is computed as $factor = 1.0 / (1.0 + \log(frameid + 1))$, where $frameid$ is the current 0-based optimization iteration index and $\log$ is the natural logarithm [S4, unofficial]. The factor is applied to the model's learning rate via an update function [S4, unofficial].

### Exponential Decay Scheduler for Training Hyperparameters
Adjusts training hyperparameters (radii backward scaler and projection lambda) based on the current iteration count using exponential decay with lower limits [S5, unofficial]. The radii backward scaler follows $radii\_backward\_scaler = \max(init\_dss\_backward\_radii \times \gamma\_dss\_backward\_radii^{(it // steps\_dss\_backward\_radii)}, limit\_dss\_backward\_radii)$, and the projection lambda follows $\lambda\_dr\_proj = \min(\lambda\_dr\_proj \times \gamma\_proj^{(it // steps\_proj)}, limit\_proj)$, where $it$ is the current iteration [S5, unofficial]. Default parameters include $init\_dss\_backward\_radii=0$, $steps\_dss\_backward\_radii=-1$ (no update), $\gamma\_dss\_backward\_radii=0.99$, $limit\_dss\_backward\_radii=1.5$, $steps\_proj=-1$, $\gamma\_proj=5$, and $limit\_proj=1.0$ [S5, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per step for computing the decay factor, assuming exponentiation is constant time [G].
- **Memory Complexity:** $O(1)$ additional memory for storing the scheduler state (current step) [G].
- **Strengths:** Provides a smooth, continuous transition of learning rates that avoids the abrupt changes associated with step decay [G].
- **Limitations:** Requires careful tuning of $\gamma$ and $T$ to balance convergence speed and stability [G].

## Background
The method is widely used in differentiable volume rendering and NeRF optimization to gradually refine high-frequency details during training [S3]. It has been adopted in frameworks like Instant NGP, which applies a factor of $0.33$ every $10,000$ steps after $20,000$ iterations [S3]. Framework-specific implementations, such as PyTorch's `LambdaLR`, are commonly used to wrap optimizers and apply the schedule automatically [S2, unofficial].
