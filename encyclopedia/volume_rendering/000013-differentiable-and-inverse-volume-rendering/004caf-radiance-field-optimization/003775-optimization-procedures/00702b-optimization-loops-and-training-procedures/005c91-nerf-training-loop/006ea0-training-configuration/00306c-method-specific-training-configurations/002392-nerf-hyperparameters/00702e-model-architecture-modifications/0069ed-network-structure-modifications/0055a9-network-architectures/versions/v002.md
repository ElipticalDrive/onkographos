# Network Architectures
Also called: NeRF Network Architectures

## Overview
This article details specific modifications to the standard NeRF network architecture, focusing on parameter scaling, auxiliary heads, and input/output expansions. It serves as a catalog of structural variations used to improve training efficiency, enable auxiliary tasks, or reduce memory footprint. It builds on [Model Architecture Modifications](11313-model-architecture-modifications.md) by providing concrete implementation details for specific architectural choices found in the literature.

## How it works
The standard NeRF architecture consists of two Multi-Layer Perceptrons (MLPs): a coarse network and a fine network . The coarse network takes positional encoded position $\gamma(\mathbf{x})$ and outputs a latent feature vector $\mathbf{h}$ and volume density $\sigma$. The fine network takes $\mathbf{h}$, positional encoded position $\gamma(\mathbf{x})$, and positional encoded view direction $\gamma(\mathbf{d})$ to output color $\mathbf{c}$ .

$$
\gamma(\mathbf{x}, d_1, d_2) = [\mathbf{x}, \sin(2^{d_1}\pi\mathbf{x}), \cos(2^{d_1}\pi\mathbf{x}), \dots, \sin(2^{d_2-1}\pi\mathbf{x}), \cos(2^{d_2-1}\pi\mathbf{x})]
$$

Modifications generally fall into three categories:
1.  **Input Expansion:** Adding new conditioning vectors (e.g., appearance embeddings $\mathbf{z}_i$, fluid volume $v$, or previous stage RGB) to the input concatenation .
2.  **Output Expansion:** Adding auxiliary heads to predict values other than $\sigma$ and $\mathbf{c}$, such as semantic labels $y_{aux}$, object codes $o$, or area encoding probabilities $p$. These are rendered using the same transmittance weights $T_i$ and opacity $\alpha_i$ as color:
    $$
    \hat{Y}(r) = \sum_{i=1}^{N} T_i \alpha_i y_{aux}(x_i)
    $$
    .
3.  **Representation Substitution:** Replacing the continuous MLP function with discrete structures (voxel grids, hash tables) or different implicit surfaces (SDFs) .

### Specific Architectural Configurations
While the general principles above define the categories, specific implementations vary in layer depth and width to balance performance and resource constraints.

**Scaled MLPs for Auxiliary Networks**
In architectures that introduce auxiliary networks (such as those for texture or feature storage) which are not used during inference, the network capacity can be increased to improve training accuracy without affecting rendering latency [S1].
*   **Networks A and F:** These networks adopt the standard NeRF MLP design but with increased hidden layer sizes. The hidden layer size is increased from the standard 256 units to 384 units [S1]. This increase is permissible because these networks are excluded from the inference pipeline, allowing for more computationally expensive training steps [S1].
*   **Network H:** A smaller auxiliary network, used for specific feature extraction tasks, mirrors the architecture of the small MLP used in SNeRG. It consists of two hidden layers, each containing 16 neurons [S1].

**Data Packing in Auxiliary Networks**
When auxiliary networks output feature vectors for storage in texture maps (e.g., for mobile rendering pipelines), the output dimensionality must be mapped to standard image formats [S1].
*   **Feature Storage:** If the auxiliary network outputs an 8-dimensional feature vector, this is stored in two PNG images. Each PNG image has 4 channels (RGBA), providing a total of 8 channels to store the 8-dimensional features [S1].
*   **Alpha Channel Squeezing:** To avoid allocating a separate image for binary alpha (opacity) data, the alpha channel is "squeezed" into the first feature channel of the texture [S1]. The decoding logic interprets the first feature channel $f_1$ such that if $f_1 \neq 0$, the alpha is 1; if $f_1 = 0$, the alpha is 0 [S1].

**Hardware Constraints**
Implementation of these architectures must respect hardware limits, particularly on mobile devices. Texture sizes must be powers of 2 and typically capped at $4096 \times 4096$ pixels [S1].

## Subtopics

### [MultiPlane NeRF](15533-multiplane-nerf.md)
MultiPlane NeRF is a radiance field representation that replaces trainable 3D latent structures (such as voxels or feature grids) with a fixed set of $n$ pre-existing 2D images. It solves the problem of parameter efficiency in neural rendering by enabling a small implicit decoder to reconstruct 3D scenes without optimizing a volumetric representation. Unlike [TriPlane](15530-triplane.md) which uses trainable feature planes, MultiPlane NeRF uses non-trainable RGB images, resulting in an explicit representation with fewer parameters.

### [SqueezeNeRF](15536-squeezenerf.md)
SqueezeNeRF is a memory-efficient neural rendering method that further factorizes the position-dependent Multi-Layer Perceptron (MLP) of FastNeRF into three separate 2D networks operating on coordinate pairs $(x,y)$, $(y,z)$, and $(z,x)$. This factorization reduces the cache size complexity from $O(n^3)$ to $O(n^2)$, enabling dense caching with less than 160 MB of memory while maintaining real-time rendering speeds. It builds on [FastNeRF](15528-fastnerf.md) by addressing its substantial memory overhead, making it suitable for embedded systems where sparse caching strategies used by other fast methods may be ineffective on dense scenes.
