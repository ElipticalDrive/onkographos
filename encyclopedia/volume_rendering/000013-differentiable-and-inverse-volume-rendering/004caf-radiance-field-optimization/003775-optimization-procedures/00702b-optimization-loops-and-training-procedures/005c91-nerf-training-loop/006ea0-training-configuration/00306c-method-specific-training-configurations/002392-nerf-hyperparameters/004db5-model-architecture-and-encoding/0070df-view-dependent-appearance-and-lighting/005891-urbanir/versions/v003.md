# UrbanIR

Also called: Urban Scene Inverse Rendering

## Overview
UrbanIR is a method for inverse rendering of large-scale urban scenes from a single monocular video under single illumination, inferring shape, albedo, visibility, and sun/sky illumination to enable relighting and night simulation [S1]. It differs from standard NeRFs by learning intrinsic attributes (albedo, normal) independent of lighting, solving the problem where standard NeRFs bake shading and shadows into observed color, making them non-relightable [S1]. Unlike methods requiring multiple lighting sources (NeRF-OSR) or LiDAR/multi-camera setups (FEGR, LightSim), UrbanIR uses only single illumination RGB video [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A multi-frame video of a scene under single illumination with known camera motion. Defined as $\{I_i, E_i, K_i\}$, where $I_i \in \mathbb{R}^{H \times W \times 3}$ is the RGB image, $E_i \in SE(3)$ is the camera pose, and $K_i$ is the camera intrinsic matrix [S1].
*   **Output:** A neural scene model capable of rendering novel viewpoints under novel lighting conditions, including albedo, normal, semantic, and density fields, along with inferred sun and sky illumination parameters [S1].

**Data Structures:**
The scene representation is built on Instant-NGP, a spatial hash-based voxel NeRF representation [S1].
*   **Feature Hash Table:** A dense feature hash table representing the scene [S1].
*   **MLP Headers:** Individual MLP headers are used to decode each attribute (albedo $\mathbf{a}$, normal $\mathbf{n}$, semantics $\mathbf{s}$, density $\sigma$) given a queried feature at point $\mathbf{x}$ [S1].
*   **Scene Function:** $F_\theta(\mathbf{x}) = (\mathbf{a}, \mathbf{n}, \mathbf{s}, \sigma)$, where $\mathbf{x} \in \mathbb{R}^3$ is the position [S1].
*   **Lighting Model $\mathbf{L}$:**
    *   Sun: 5-DoF representation encoding sun color $\mathbf{L}_{\text{sun}}$ and azimuth $\psi_{\text{sun}}$, zenith $\phi_{\text{sun}}$ [S1].
    *   Ambient: 3-DoF Lambert model $\mathbf{L}_{\text{amb}}$ [S1].
    *   Sky: Sky dome model inferring sky texture from viewing direction [S1].

**Numbered Steps:**
1.  **Sampling:** For each camera ray $\mathbf{r}$, sample multiple points along the ray.
2.  **Feature Query:** Query the feature hash table at each sampled point $\mathbf{x}_i$ to get features.
3.  **Attribute Decoding:** Pass features through individual MLP headers to predict intrinsic attributes $\mathbf{a}_i, \mathbf{n}_i, \mathbf{s}_i$ and density $\sigma_i$ [S1].
4.  **Intrinsic Volume Rendering:** Accumulate intrinsic attributes along the ray using alpha-composition weights $w_i$ [S1]:
    $$ \mathbf{A}(\mathbf{r}) = \sum_{i=1}^{N} w_i \mathbf{a}_i, \quad \mathbf{N}(\mathbf{r}) = \sum_{i=1}^{N} w_i \mathbf{n}_i, \quad \mathbf{S}(\mathbf{r}) = \sum_{i=1}^{N} w_i \mathbf{s}_i $$
    where $w_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j) (1 - \exp(-\sigma_i \delta_i))$ and $\delta_i = t_i - t_{i-1}$ [S1].
5.  **Visibility Estimation:**
    *   Compute an estimate $\hat{\mathbf{x}}(\mathbf{r})$ of the 3D point being shaded by volume rendering depth (substituting $\hat{t} = \sum w_i t_i$ into the depth equation) [S1].
    *   Estimate visibility $V(\hat{\mathbf{x}}, \text{sun})$ by computing the transmittance along the ray segment between $\hat{\mathbf{x}}$ and the light source using volume rendering [S1].
6.  **Shading:** Compute final RGB color $\mathbf{C}$ using the shading function:
    $$ \mathbf{C} = \texttt{Shade}(\texttt{Intrinsic}(F_\theta, \mathbf{r}), \texttt{Shadow}(F_\theta, \mathbf{r}, \mathbf{L}), \mathbf{L}) $$
    where $\texttt{Intrinsic}$ provides $\mathbf{A}, \mathbf{N}, \mathbf{S}$ and $\texttt{Shadow}$ provides visibility $V$ [S1].
7.  **Optimization:** Jointly optimize scene parameters $\theta$ and lighting parameters $\mathbf{L}$ using a loss function combining rendering loss and other constraints (e.g., $\mathcal{L}_{\text{render}} + \lambda_1 \mathcal{L}_{\dots}$) [S1].

**Pseudocode:**
```python
def urbanir_render(ray_origin, ray_direction, scene_hash_table, lighting_params):
    """
    Renders a single ray using UrbanIR's inverse rendering pipeline.
    """
    # 1. Sample points along the ray
    t_vals = sample_points(ray_origin, ray_direction)
    points = ray_origin + ray_direction * t_vals
    
    # 2. Query features and decode attributes
    features = query_hash_table(scene_hash_table, points)
    albedos, normals, semantics, densities = decode_attributes(features)
    
    # 3. Compute alpha-composition weights
    deltas = t_vals[1:] - t_vals[:-1]
    # Add a small epsilon to avoid log(0) if densities are 0
    transmittances = exp(-cumsum(densities[:-1] * deltas))
    alpha_weights = transmittances * (1 - exp(-densities * deltas))
    
    # 4. Volume render intrinsics
    albedo_map = sum(alpha_weights * albedos)
    normal_map = sum(alpha_weights * normals)
    semantic_map = sum(alpha_weights * semantics)
    
    # 5. Estimate shaded point depth
    # Note: Standard NeRF depth is sum(w_i * t_i). UrbanIR uses this to find the surface point.
    estimated_depth = sum(alpha_weights * t_vals)
    shaded_point = ray_origin + ray_direction * estimated_depth
    
    # 6. Estimate shadow visibility
    # Compute transmittance from shaded_point to sun direction
    sun_visibility = compute_sun_transmittance(shaded_point, lighting_params.sun_direction, scene_hash_table)
    
    # 7. Apply shading
    # Shade function combines intrinsic color, visibility, and lighting model
    final_color = shade(
        intrinsic_color=albedo_map,
        visibility=sun_visibility,
        lighting=lighting_params
    )
    
    return final_color, albedo_map, normal_map, semantic_map

def compute_sun_transmittance(point, sun_direction, scene_hash_table):
    """
    Computes visibility of the sun from a point by ray marching towards the sun.
    """
    # Sample points from 'point' towards 'sun_direction'
    # Use a large distance or until hitting a high-density surface
    sun_ray_points = sample_points_towards(point, sun_direction, max_dist=1000.0)
    
    # Query densities along sun ray
    sun_densities = query_densities(scene_hash_table, sun_ray_points)
    
    # Compute transmittance (1 - accumulated opacity)
    # This represents the probability that the sun is visible
    transmittance = exp(-sum(sun_densities * deltas_along_sun_ray))
    return transmittance
```

**Parameters:**
*   **Lighting Model:** Sun (5-DoF: color, azimuth, zenith), Ambient (3-DoF), Sky (view-dependent texture) [S1].
*   **Loss Weights:** $\lambda_1$ for additional constraints (specific values not given in sources) [S1].

**Edge Cases and Pitfalls:**
*   **Standard NeRF Limitations:** Standard NeRFs bake shading, shadow, and specularity into observed color, making them non-relightable. UrbanIR solves this by learning intrinsic attributes [S1].
*   **Visibility Modeling:** Modeling visibility with a per-scene optimized MLP head is impractical because the sun position changes during relighting, but training data only has one sun position. UrbanIR avoids this by computing visibility via transmittance to the light source [S1].
*   **Large-Scale Scenes:** Standard NeRFs may struggle with expansive outdoor scenes due to memory and consistency issues. UrbanIR uses Instant-NGP's spatial hash-based voxel representation for compactness and consistency [S1].

## Operating characteristics
*   **Time and Memory Complexity:** Built on Instant-NGP, which offers low memory consumption and high efficiency in training and rendering [S1]. Specific complexity metrics are not given.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Designed for large-scale, unbounded urban scenes [S1].
*   **Strengths:** Works with single monocular video; enables relighting and night simulation; handles large-scale scenes efficiently [S1].
*   **Limitations:** Assumes single illumination during training; relies on known camera motion [S1].
*   **When to Use:** When relighting and intrinsic property estimation (albedo, normal) are needed for large outdoor scenes from a single video [S1].
*   **When Not to Use:** When multiple lighting sources are present during training, or when LiDAR/multi-camera data is available and preferred (e.g., FEGR) [S1].

## Background
UrbanIR was introduced by Chih-Hao Lin, Bohan Liu, Yi-Ting Chen, Kuan-Sheng Chen, David Forsyth, Jia-Bin Huang, Anand Bhattad, and Shenlong Wang from the University of Illinois Urbana-Champaign and University of Maryland, College Park [S1]. It was published in 3DV 2025 (arXiv:2306.09349v4, 14 Jan 2025) [S1]. The method addresses the limitations of object-centric relightable NeRF methods and indoor-focused approaches by enabling inverse rendering for large-scale urban scenes from a single video [S1]. It builds on Instant-NGP for efficient scene representation [S1].
