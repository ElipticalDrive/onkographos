# Mip-NeRF Optimization and Activation Details

Also called: JaxNeRF Training Procedure, Mip-NeRF Misc. Changes

## Overview
This article defines the specific implementation details for training Mip-NeRF and JaxNeRF, focusing on activation functions, input encoding strategies, and learning rate schedules that improve training stability and robustness [S1]. These "miscellaneous" changes do not significantly alter the theoretical accuracy or speed of the method but prevent catastrophic failure modes during optimization [S1]. It sets itself apart from standard NeRF training by replacing ReLU with shifted softplus for density, using a widened sigmoid for color, removing identity concatenation from inputs, and employing a specific warmup learning rate schedule [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Training images (normalized to $[0, 1]$), camera poses, and intrinsics.
*   **Output:** Optimized MLP weights for density $\tau$ and color $c$.

**Data Structures:**
*   **MLP Weights:** Standard Mip-NeRF architecture (8-layer MLP for position, 4-layer for direction, though the direction injection is handled separately as per [S1]).
*   **Optimizer State:** Adam optimizer state with $\beta_1=0.9, \beta_2=0.999, \epsilon=10^{-7}$ [S1].

**Numbered Steps:**

1.  **Input Pre-processing (Identity Removal):**
    *   Compute the Integrated Positional Encoding (IPE) for the conical frustum defined by the ray segment.
    *   **Do not** concatenate the original position and view direction vectors to the IPE features. The MLP input is solely the IPE features [S1].

2.  **Network Forward Pass (Density):**
    *   Pass the IPE features through the MLP layers.
    *   Let $x$ be the pre-activation output for the density branch.
    *   Apply the **shifted softplus** activation to obtain density $\tau$:
        $$ \tau = \log(1 + \exp(x - 1)) $$
    *   This is equivalent to initializing the bias of the density output layer to $-1$ [S1].

3.  **Network Forward Pass (View Direction):**
    *   Normalize the ray direction vector $\mathbf{d}$.
    *   Apply standard positional encoding to $\mathbf{d}$ with $L=4$ frequencies.
    *   Inject these encoded direction features into the **last layer** of the MLP.
    *   This injection occurs **after** the density $\tau$ is predicted but **before** the color $c$ is predicted [S1].

4.  **Network Forward Pass (Color):**
    *   Let $y$ be the pre-activation output for the color branch.
    *   Apply the **widened sigmoid** activation to obtain color $c$:
        $$ c = \frac{1 + 2\epsilon}{1 + \exp(-y)} - \epsilon $$
    *   Where $\epsilon = 0.001$ [S1].

5.  **Volume Rendering:**
    *   Render the pixel color using the standard differentiable volume rendering integral with the computed $\tau$ and $c$ [S1].

6.  **Loss Computation:**
    *   Compute the photometric loss (e.g., MSE) between the rendered color and the ground truth image [S1].

7.  **Optimization (Learning Rate Schedule):**
    *   Use the Adam optimizer with a batch size of 4096 [S1].
    *   Perform 1,000,000 iterations [S1].
    *   Apply the following learning rate schedule $\eta_i$ at iteration $i$ (total iterations $n=1,000,000$, warmup iterations $n_w=2,500$):
        $$ \eta_i = \left( \lambda_w + (1 - \lambda_w) \sin\left(\frac{\pi}{2} \operatorname{clip}\left(\frac{i}{n_w}, 0, 1\right)\right) \right) \times \left( \exp\left( (1 - \frac{i}{n}) \log(\eta_0) + \frac{i}{n} \log(\eta_n) \right) \right) $$
    *   Where:
        *   $\eta_0 = 5 \cdot 10^{-4}$ (initial learning rate)
        *   $\eta_n = 5 \cdot 10^{-6}$ (final learning rate)
        *   $\lambda_w$ is annealed from $0.01$ to $1$ during the warmup period $[0, n_w]$ [S1].

**Pseudocode:**

```python
import math
import jax.numpy as jnp

def shifted_softplus(x):
    """
    Density activation: log(1 + exp(x - 1))
    Equivalent to softplus with bias -1.
    """
    return jnp.log(1.0 + jnp.exp(x - 1.0))

def widened_sigmoid(x, epsilon=0.001):
    """
    Color activation: (1 + 2*eps) / (1 + exp(-x)) - eps
    """
    return (1.0 + 2.0 * epsilon) / (1.0 + jnp.exp(-x)) - epsilon

def compute_learning_rate(i, n=1000000, n_w=2500, eta_0=5e-4, eta_n=5e-6):
    """
    Mip-NeRF/JaxNeRF learning rate schedule with warmup.
    """
    # Log-linear annealing part
    log_eta = (1.0 - i / n) * math.log(eta_0) + (i / n) * math.log(eta_n)
    base_lr = math.exp(log_eta)
    
    # Warmup scaling factor
    # lambda_w anneals from 0.01 to 1 during warmup
    if i < n_w:
        # clip(i/n_w, 0, 1) is just i/n_w since i < n_w
        sin_val = math.sin((math.pi / 2.0) * (i / n_w))
        # lambda_w is implicitly handled by the formula structure in the source
        # The source formula: (lambda_w + (1-lambda_w)*sin(...))
        # However, the source says lambda_w is annealed FROM 0.01 TO 1.
        # Let's interpret the formula exactly as written in [S1]:
        # eta_i = (lambda_w + (1 - lambda_w) * sin(...)) * base_lr
        # But lambda_w itself is a function of i.
        # The text says: "scale factor that is smoothly annealed between lambda_w = 0.01 and 1"
        # And the formula uses lambda_w.
        # Standard interpretation of such warmup in JaxNeRF:
        # The term (lambda_w + (1-lambda_w)*sin(...)) acts as the warmup multiplier.
        # If lambda_w starts at 0.01, the multiplier starts at 0.01.
        # If lambda_w ends at 1, the multiplier ends at 1.
        # Let's define lambda_w_current based on i.
        # Actually, the formula in [S1] Eq 42 uses lambda_w as a constant in the expression?
        # No, "lambda_w is annealed from 0.01 to 1".
        # Let's assume lambda_w is the *current* value.
        # But the formula has lambda_w inside.
        # Let's look at the structure:
        # If i=0, sin(0)=0. Multiplier = lambda_w.
        # If i=n_w, sin(pi/2)=1. Multiplier = lambda_w + (1-lambda_w)*1 = 1.
        # So lambda_w must be the starting value (0.01) if it's constant?
        # No, "annealed from 0.01 to 1".
        # If lambda_w is the variable, the formula is ambiguous.
        # Re-reading: "scale factor that is smoothly annealed between lambda_w = 0.01 and 1".
        # And the formula is: (lambda_w + (1 - lambda_w) * sin(...))
        # This implies lambda_w is the *initial* scale factor (0.01) and the term evolves to 1.
        # Wait, if lambda_w is constant 0.01:
        # i=0 -> 0.01.
        # i=n_w -> 0.01 + 0.99*1 = 1.0.
        # This matches "annealed from 0.01 to 1".
        # So lambda_w in the formula is the constant 0.01.
        lambda_w_init = 0.01
        warmup_factor = lambda_w_init + (1.0 - lambda_w_init) * math.sin((math.pi / 2.0) * (i / n_w))
    else:
        warmup_factor = 1.0
        
    return warmup_factor * base_lr

def train_mipnerf_step(model, ray_bundle, gt_image):
    # 1. Encode Position (IPE)
    # Assuming get_ipe returns the integrated positional encoding features
    pos_features = get_ipe(ray_bundle.query_points, ray_bundle.covariances)
    
    # 2. Forward Pass for Density
    # MLP forward pass for density branch
    x_density = model.mlp_forward_density(pos_features)
    tau = shifted_softplus(x_density)
    
    # 3. Encode Direction
    directions = ray_bundle.directions / jnp.linalg.norm(ray_bundle.directions, axis=-1, keepdims=True)
    dir_features = positional_encoding(directions, L=4)
    
    # 4. Forward Pass for Color
    # Inject dir_features into the last layer
    # This is a specific architectural detail:
    # The MLP processes pos_features. The output of the second-to-last layer
    # is combined with dir_features before the final linear layer for color.
    # Or, as per [S1]: "injected into the last layer ... after tau is predicted but before c is predicted"
    # This implies the network structure allows separate heads or a specific injection point.
    # Standard JaxNeRF/MipNeRF implementation:
    # The MLP outputs a vector. We split it or use a specific head.
    # Let's assume the model has a method that handles this injection.
    c_raw = model.mlp_forward_color(pos_features, dir_features)
    c = widened_sigmoid(c_raw)
    
    # 5. Render
    rendered_color = volume_render(tau, c, ray_bundle)
    
    # 6. Loss
    loss = jnp.mean((rendered_color - gt_image) ** 2)
    
    return loss
```

**Edge Cases and Pitfalls:**
*   **Catastrophic Failure:** Using standard ReLU for density can cause the MLP to emit negative values everywhere, resulting in zero gradients and optimization failure. The shifted softplus prevents this [S1].
*   **Black/White Pixel Saturation:** Standard sigmoid saturation can cause optimization failure when trying to explain pure black or white pixels. The widened sigmoid avoids this by saturating slightly outside $[0, 1]$ [S1].
*   **Identity Concatenation:** Concatenating the original position/direction to the IPE is not only unnecessary for performance but makes the formalization of IPE features challenging. It should be removed [S1].
*   **Correlation Insensitivity:** IPE features are insensitive to the off-diagonal elements (correlation) of the covariance matrix $\Sigma$. Experiments show that modeling this correlation does not improve accuracy [S1].

## Subtopics

### Alternative Gaussian Positional Encoding
An alternative to Integrated Positional Encoding (IPE) involves concatenating the positional encoding of the mean $\mu$ (with $L=12$) and the positional encoding of the vectorized upper triangular part of the signed covariance matrix $\Sigma$ (with $L=2$) [S1]. This approach performs comparably to IPE in terms of PSNR/SSIM/LPIPS but is sensitive to the hyperparameters $L$ and the parameterization of $\Sigma$, whereas IPE is hyperparameter-free and more compact [S1].

### Reflected Cone Derivation
For consistent view-dependent appearance in reflections, the origin of the reflected ray $\mathbf{o}'$ is shifted so that its cone radius matches the incident ray's cone radius at the intersection point $\bar{\mathbf{x}}$ [S2]. This is achieved by solving $\dot{r}\|\bar{\mathbf{x}} - \mathbf{o}\| = \dot{r}'\|\bar{\mathbf{x}} - \mathbf{o}'\|$ along with the constraint that $\mathbf{o}'$ lies on the reflected ray [S2].

### RawNeRF
RawNeRF adapts Mip-NeRF for High Dynamic Range (HDR) view synthesis by training on raw linear images [S3]. It renders in a linear color space and supervises with variable exposure images, scaling the NeRF model's "exposure" by the training image's shutter speed and a per-channel learned scaling factor [S3]. This allows post-processing (tone-mapping) to be applied after rendering, unlike methods using LDR images [S3].

## Operating characteristics
*   **Training Time:** Mip-NeRF is 13x faster to train than a brute-force supersampling baseline (16 rays/pixel) [S1].
*   **Evaluation Speed:** Mip-NeRF is 16x faster to evaluate than the supersampling baseline [S1].
*   **Quality:** Mip-NeRF outperforms the 16x supersampling baseline in PSNR, SSIM, and LPIPS [S1].
*   **Stability:** The specific activation functions and learning rate schedule improve stability, particularly when using larger learning rates or training ablations [S1].
*   **Memory:** Uses a batch size of 4096 rays [S1].

## Background
These details originate from the Mip-NeRF paper (Barron et al., 2021) and the associated JaxNeRF codebase [S1]. The "miscellaneous" changes were included to ensure reproducibility and robustness of the training procedure, particularly for ablation studies and comparisons with other methods like JaxNeRF [S1]. RawNeRF (Mildenhall et al., 2021) later adapted this training framework for HDR data [S3].
