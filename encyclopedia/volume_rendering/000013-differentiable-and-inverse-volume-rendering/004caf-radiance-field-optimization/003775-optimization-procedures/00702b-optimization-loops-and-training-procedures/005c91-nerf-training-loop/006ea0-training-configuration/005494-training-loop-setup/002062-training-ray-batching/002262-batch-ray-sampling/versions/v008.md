# Batch Ray Sampling

Also called: batch ray selection, Batch Ray Generation, Training Ray Sampling, Training Data Batching, NeRF Training Loop and Ray Batching

## Overview
Batch Ray Sampling generates batches of rays for training by sampling pixels from training images and computing ray origins and directions [S1, S3, S4, S7, unofficial]. It solves the memory bottleneck of rendering full images per optimization step by processing only a subset of rays, enabling efficient gradient updates and better memory utilization [S4, S5, unofficial]. Unlike image-based training which iterates over complete images, this method samples random rays across the entire image pool (or within a single image), which is the standard approach in modern NeRF methods and differentiable volumetric rendering frameworks [S5, unofficial][S10].

## How it works
**Inputs:** Training images (RGB), camera poses (extrinsics), camera intrinsics (focal length, principal point), batch size ($N_{rand}$ or `batch_size`), and optional configuration flags (`use_batching`, `precompute_rays`, `precrop_iters`, `precrop_frac`).
**Outputs:** A batch tensor containing ray origins, ray directions, and target RGB colors.

**Data Structures:**
The core data structure is a ray batch tensor. In the standard implementation [S4, unofficial], this is a 3D array with shape `[N, 3, 3]` where:
- Axis 0 ($N$) is the ray index (total rays across all images).
- Axis 1 represents the component type: 0 for ray origin, 1 for ray direction, 2 for target RGB color.
- Axis 2 contains the 3D coordinates (X, Y, Z) for origins/directions or RGB channel values (R, G, B) for colors.

**Steps:**
1. **Preprocessing (Optional):** If `precompute_rays` is true, generate rays for all training images, concatenate with target colors, transpose to `[N, H, W, 2+1, 3]`, reshape to `[num_rays, 3, 3]`, and shuffle the array [S1, S4, unofficial]. If false, rays are generated on-the-fly [S6, unofficial].
2. **Batch Selection:**
    - **All-Images Mode:** Randomly sample `batch_size` indices from all available rays across all images [S9, unofficial]. Select corresponding pixels and rays [S1, S9, unofficial].
    - **Single-Image Mode:** Randomly select one image index, then randomly sample `batch_size` indices from that specific image's rays [S9, unofficial].
    - **Non-Batching Mode:** Select a random image, get its rays, select random coordinates, and extract ray origins and directions [S1, S2, unofficial].
3. **Ray Generation:** For selected pixels, compute ray origins and directions using camera poses and intrinsics [S1, S4, S7, unofficial].
    - Calculate near and far clipping planes. A common heuristic sets `hemi_R` as the mean norm of camera pose translation vectors, then `near = hemi_R - 1.` and `far = hemi_R + 1.` [S4, unofficial].
    - Construct the ray batch tensor by stacking origins, directions, and target colors [S4, unofficial].
4. **Center Cropping (Optional):** During early training (iteration $i < \text{precrop\_iters}$), restrict pixel selection to a center crop of size $2 \cdot dH \times 2 \cdot dW$, where $dH, dW$ are derived from `precrop_frac` (typically 0.5) [S1, S4, unofficial].
5. **Subpixel Sampling (Advanced/Renderer-Specific):** In differentiable rendering contexts (e.g., Mitsuba), extend the wavefront to `batch_size * spp`. Gather sensor and pixel information, compute subpixel offsets using a sampler, and rescale to $[0, 1]^2$ [S3, unofficial].
6. **Batch Extraction:** Slice the precomputed or generated rays for the current iteration. Transpose to `[2+1, B, 3]` (where axes are ray origin/direction and target color) [S4, unofficial]. Split into `batch_rays` (origins/directions) and `target_s` (colors) [S4, unofficial]. Increment batch index and reshuffle if the end of the array is reached [S4, unofficial].

**Pseudocode:**
```python
def generate_batch_rays(images, poses, intrinsics, batch_size, use_batching=True, 
                        precompute_rays=False, precrop_iters=0, precrop_frac=0.5, 
                        current_iter=0):
    """
    Generates a batch of rays for training.
    
    Args:
        images: Tensor of shape [num_images, H, W, 3]
        poses: Tensor of shape [num_images, 3, 4] (camera-to-world)
        intrinsics: Tuple (focal_length, principal_point_x, principal_point_y)
        batch_size: Number of rays to sample
        use_batching: If True, use precomputed ray buffers
        precompute_rays: If True, rays are precomputed and shuffled
        precrop_iters: Number of iterations to use center cropping
        precrop_frac: Fraction of image for center crop
        current_iter: Current training iteration
        
    Returns:
        batch_rays: Tensor of shape [batch_size, 6] (origins and directions)
        target_colors: Tensor of shape [batch_size, 3]
    """
    if use_batching and precompute_rays:
        # Fetch precomputed rays_rgb tensor of shape [total_rays, 3, 3]
        # Axis 0: ray index, Axis 1: type (0:origin, 1:dir, 2:rgb), Axis 2: coords/channels
        rays_rgb = get_precomputed_rays() 
        
        # Determine batch start index
        global i_batch
        if i_batch is None: i_batch = 0
        
        # Slice batch
        batch_tensor = rays_rgb[i_batch : i_batch + batch_size]
        i_batch += batch_size
        
        # Reshuffle if end of array reached
        if i_batch >= rays_rgb.shape[0]:
            shuffle(rays_rgb)
            i_batch = 0
            
        # Transpose to [3, batch_size, 3] -> [batch_size, 3, 3] -> split
        # batch_tensor shape: [batch_size, 3, 3]
        origins = batch_tensor[:, 0, :] # [batch_size, 3]
        directions = batch_tensor[:, 1, :] # [batch_size, 3]
        targets = batch_tensor[:, 2, :] # [batch_size, 3]
        
        return origins, directions, targets

    else:
        # On-the-fly generation
        # 1. Select image
        img_idx = random.randint(0, len(images) - 1)
        img = images[img_idx]
        pose = poses[img_idx]
        H, W, _ = img.shape
        
        # 2. Determine pixel coordinates
        if current_iter < precrop_iters:
            # Center crop
            dH = int(H * (1 - precrop_frac) / 2)
            dW = int(W * (1 - precrop_frac) / 2)
            y_coords = torch.arange(dH, H - dH)
            x_coords = torch.arange(dW, W - dW)
        else:
            y_coords = torch.arange(H)
            x_coords = torch.arange(W)
            
        # Create meshgrid and flatten
        ys, xs = torch.meshgrid(y_coords, x_coords, indexing='ij')
        coords = torch.stack([xs, ys], dim=-1).reshape(-1, 2)
        
        # 3. Sample random pixels
        num_pixels = coords.shape[0]
        pixel_indices = torch.randint(0, num_pixels, (batch_size,))
        selected_coords = coords[pixel_indices]
        
        # 4. Generate rays
        origins, directions = compute_rays_from_coords(selected_coords, pose, intrinsics)
        
        # 5. Get target colors
        # Map 2D coords to 1D index for tensor gathering
        h, w = selected_coords[:, 0], selected_coords[:, 1]
        target_colors = img[h, w]
        
        return origins, directions, target_colors

def compute_rays_from_coords(coords, pose, intrinsics):
    """
    Computes ray origins and directions from pixel coordinates.
    coords: [N, 2] (x, y)
    pose: [3, 4] camera-to-world
    intrinsics: (f, cx, cy)
    """
    f, cx, cy = intrinsics
    x, y = coords[:, 0], coords[:, 1]
    
    # Normalized device coordinates or pixel space conversion
    # Assuming pinhole model: x_ndc = (x - cx) / f, y_ndc = (y - cy) / f
    # Direction in camera space
    dirs_cam = torch.stack([x - cx, y - cy, torch.ones_like(x)], dim=-1)
    dirs_cam = dirs_cam / torch.norm(dirs_cam, dim=-1, keepdim=True)
    
    # Origin in camera space is (0,0,0)
    origins_cam = torch.zeros_like(dirs_cam)
    
    # Transform to world space
    # R is pose[:, :3, :3], t is pose[:, :3, 3]
    R = pose[:, :3, :3]
    t = pose[:, :3, 3]
    
    origins_world = origins_cam @ R.T + t
    directions_world = dirs_cam @ R.T
    
    return origins_world, directions_world
```

**Parameters:**
- `N_rand` / `batch_size`: Number of rays per batch. Typical values: 1024–2048 for small/low-res scenes, 4096–8192 for medium scenes (default), 16384+ for large/high-res scenes [S5, unofficial][S8].
- `precrop_iters`: Iterations to use center cropping. Default: 0 [S1, unofficial].
- `precrop_frac`: Fraction of image for center crop. Default: 0.5 [S1, unofficial].
- `precompute_rays`: Boolean to cache rays in memory. Default: False [S6, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Ray origins and directions must be normalized or consistently scaled to avoid numerical instability in volume rendering integration [S4, unofficial].
- **Boundaries:** Ensure pixel coordinates are within image bounds, especially when using center cropping [S1, unofficial].
- **Degenerate Input:** If `batch_size` exceeds the total number of pixels in the selected image(s), sampling must handle repetition or error gracefully [S9, unofficial].

## Subtopics

### [Pixel Batching](3134-pixel-batching.md)
Pixel Batching is a ray-centric batched rendering operation that computes gradients of rendered images with respect to scene parameters using automatic differentiation (AD) in backward mode, supporting multiple sensors and pixels in a single batch. It serves as a Python-side wrapper that samples `batch_size` random (sensor, pixel) pairs across all sensors, renders those rays to a 1xN box-filter film, and supports a decorrelated PRB backward pass without requiring kernel changes. Unlike the sensor-centric `mi.render` or sibling methods like [Batch Ray Sampling](2767-batch-ray-sampling.md) which prepare rays, this method encapsulates the full forward and backward rendering pipeline for a specific batch of pixels, enabling efficient training loops for inverse volume rendering.

### [Semantic Ray Sampling](3896-semantic-ray-sampling.md)
Semantic Ray Sampling is a strategy for distinguishing individual elements (deformable and non-deformable) within a scene by tagging 3D points with semantic labels based on 2D semantic masks and distance to 3D skeletons. It addresses occlusion and dynamic supervision challenges inherent in reconstructing interacting entities. Unlike standard uniform or depth-based sampling, this method allows for extra sampling of specific semantic classes and masking away of specific instances.

### [Training Ray Shuffling](5446-training-ray-shuffling.md)
Training Ray Shuffling generates random batch indices for training and transfers shuffled indices to the GPU. It differs from its parent [Batch Ray Sampling](2767-batch-ray-sampling.md) by explicitly managing the permutation state and handling the CPU-to-GPU transfer [G].

### [Training Ray Masking and Caching](6776-training-ray-masking-and-caching.md)
Training Ray Masking and Caching filters the set of candidate training rays to retain only those that intersect the coarse geometry of the scene, storing the valid rays and their associated RGB values in contiguous buffers for efficient training. It differs from sibling methods like [Pixel Batching](3134-pixel-sampling.md) by explicitly discarding rays that miss the geometry (background or empty space) before the training loop begins, thereby reducing the number of rays processed per iteration.

### [Memory-Saving Ray Sampling](13419-memory-saving-ray-sampling.md)
Memory-Saving Ray Sampling is a technique that enables training neural radiance fields (NeRF) on all rays simultaneously, avoiding the need to downsample ray counts due to out-of-memory (OOM) constraints. Unlike sibling methods that may require sparse sampling or precomputed buffers, this approach allows full-resolution ray processing without degradation in stylization quality. It specifically addresses the trade-off where reducing sampled ray numbers to save memory increases noise and degrades results.

### [Texture-Space Sampling](16007-texture-space-sampling.md)
Texture-space sampling is a method for forming training batches in differentiable inverse volume rendering and radiance-field optimization by sampling unknowns (texture variables) uniformly directly in texture space, rather than sampling a random subset of views. This approach reduces gradient noise by ensuring that batches of observations are directly relevant to the selected unknowns, providing even coverage within an iteration compared to standard image-based sampling. It sets itself apart from [Batch Ray Sampling](2767-batch-ray-sampling.md) by prioritizing the uniformity of the latent representation (texture) over the uniformity of the input data (images), and from [Texture-Space Differentiable Rendering](5555-texture-space-differentiable-rendering.md) by focusing on the batch formation strategy rather than the gradient computation mechanics alone.

### Batched Pixel Sampling
Batched Pixel Sampling samples a batch of pixels and sensors for rendering, generating three separate samplers for pixel selection, primal subpixel sampling, and adjoint subpixel sampling [S3, unofficial]. It determines the number of sensors, creates samplers with sizes `batch_size`, `batch_size * spp`, and `batch_size * spp_grad`, seeds them, selects sensors and pixels, and returns the indices and samplers [S3, unofficial].

### Batch Preparation
Batch Preparation prepares the film and sampler for batched rendering, ensuring correct dimensions, pixel format, and wavefront size limits [S3, unofficial]. It asserts wavefront size divisibility, maps pixel formats to channel counts, creates/validates the film (defaulting to a 1xN box-filter), creates/validates the sampler, sets sample counts, checks wavefront size limits (e.g., 0xffffffff for LLVM), seeds the sampler, and returns the film, sampler, and spp [S3, unofficial].

### Training Ray Sub-sampling
Training Ray Sub-sampling is a dataset transform that sub-samples a fixed number of rays from a multiview batch for training or rendering [S11, unofficial]. It generates random ray indices using `torch.randint`, sub-samples rays and ray values (channels) using these indices, and returns contiguous tensors [S11, unofficial].

### Sequential Test Data Sampling
Sequential Test Data Sampling samples the next test example (image or render path frame) sequentially [S9, unofficial]. It increments an internal iterator index modulo the number of examples, and returns rays from a render path or pixels/rays from the current image index depending on the mode [S9, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Memory: $O(N_{rays} \cdot C)$, where $N_{rays}$ is the batch size and $C$ is the number of channels/coordinates per ray (typically 6 for origin/direction + 3 for color). This is significantly lower than $O(H \cdot W \cdot C)$ required for full image rendering [S5, unofficial].
- Time: Proportional to the number of rays processed per iteration. Since only a subset is rendered, convergence per iteration is faster in terms of wall-clock time, but more iterations may be needed for full convergence compared to full-image updates [S5, unofficial].

**Measured Performance:**
- Typical batch sizes range from 1024 to 16384 rays depending on scene complexity and GPU memory [S5, unofficial][S8].
- Using `Nerfacc` for empty space skipping can further reduce computation time by skipping rays that do not intersect geometry [S8].

**Strengths and Limitations:**
- **Strengths:** Enables training on large scenes with limited GPU memory; allows for efficient use of high-resolution training images by sampling only necessary pixels; supports center cropping to focus on main subjects [S1, S5, unofficial].
- **Limitations:** Random sampling may lead to uneven coverage of the scene if not shuffled properly; may miss rare but important features if not weighted; requires careful tuning of batch size to balance memory and gradient noise [S1, S5, unofficial].

**When to Use:**
- Use when GPU memory is insufficient for full-image rendering.
- Use when training on high-resolution images where full rendering is prohibitively slow.
- Use when employing techniques like center cropping or semantic masking.

**When Not to Use:**
- Use full-image rendering when memory allows and uniform coverage is critical without shuffling overhead.
- Avoid if the scene is very small and full-image rendering is faster due to lower overhead.

## Background
Batch Ray Sampling originated with the NeRF (Neural Radiance Fields) paper by Mildenhall et al. (2020) [S4, unofficial]. It was introduced to address the computational and memory constraints of rendering high-resolution images for every optimization step. The method samples random rays from training images, renders them through a neural network, and optimizes the network weights by minimizing the Mean Squared Error (MSE) between predicted and ground truth colors [S4, unofficial]. This approach has become standard in modern NeRF-style methods and differentiable volumetric rendering frameworks [S5, unofficial]. Variants and optimizations, such as precomputing rays, center cropping, and semantic sampling, have been developed to improve efficiency and quality [S1, S2, S3, S9, S11, unofficial].
