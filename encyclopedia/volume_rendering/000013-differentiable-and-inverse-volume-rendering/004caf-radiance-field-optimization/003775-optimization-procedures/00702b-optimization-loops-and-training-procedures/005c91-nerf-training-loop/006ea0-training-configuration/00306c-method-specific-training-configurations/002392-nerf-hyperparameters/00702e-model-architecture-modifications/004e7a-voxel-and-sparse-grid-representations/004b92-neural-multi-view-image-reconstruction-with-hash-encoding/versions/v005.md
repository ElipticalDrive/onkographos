# Neural Multi-View Image Reconstruction with Hash Encoding

Also called: Ours (multi-view)

## Overview
This method performs neural multi-view image reconstruction and novel view synthesis by combining hash-encoded spatial features with a Signed Distance Function (SDF) representation [S1]. It solves the problem of reconstructing high-frequency geometric details and synthesizing novel views from multi-view images more efficiently than previous neural implicit methods [S1]. It distinguishes itself from voxel-based siblings like [Voxel-based Radiance Fields](11470-voxel-based-radiance-fields.md) by using a sparse hash table for feature retrieval rather than dense trilinear interpolation, and from [NeRF](11470-voxel-based-radiance-fields.md) by providing direct geometric constraints via SDF thresholding, which reduces noise and improves high-frequency detail [S1].

## How it works
The method consists of two main networks: a geometry network that predicts the SDF and a light field network that predicts color. The geometry network uses a hash encoding to map 3D coordinates to feature vectors, which are processed by a Multi-Layer Perceptron (MLP). The light field network takes these features, along with view direction and surface normal information, to predict RGB color. Rendering is performed using differentiable volume rendering with hierarchical sampling and SDF-based invalid point elimination.

### Inputs and Outputs
*   **Inputs:** Multi-view images of the scene; camera parameters (intrinsics and extrinsics) for training and novel view synthesis.
*   **Outputs:** Reconstructed 3D geometry (extracted as a mesh via Marching Cubes) and synthesized novel view images.

### Data Structures

**1. Hash Encoding Table**
The spatial feature representation is stored in a hash table.
*   **Structure:** A list of $L$ layers. Each layer $l$ contains a hash table mapping hashed coordinates to feature vectors.
*   **Dimensions:**
    *   Number of layers ($L$): 16 [S1].
    *   Feature dimension per grid feature: 2 [S1].
    *   Total feature vector size per coordinate: $L \times 2 = 32$ [S1].
*   **Hashing:** Coordinates are hashed to indices in the table. The specific hash function and table size are not explicitly defined in the source, but the structure implies a standard learnable hash encoding where features are stored at the hashed indices [S1].

**2. Fourier Position Encoding**
*   **Structure:** A deterministic positional encoding applied to input coordinates.
*   **Dimensions:** Frequency domain dimension is 6 [S1]. This typically implies sine and cosine functions for frequencies $2^0, 2^1, \dots, 2^5$, resulting in a 12-dimensional vector (6 frequencies $\times$ 2 trig functions) [S1].

**3. Geometry Network**
*   **Structure:** An MLP with 6 layers [S1].
*   **Activation:** Softplus activation functions are used [S1].
*   **Initialization:** Modified initialization strategy from [12] (referenced in [S1]), applied to the geometry network [S1].

**4. Light Field Network**
*   **Structure:** An MLP with 4 hidden layers [S1].
*   **Units:** Each hidden layer contains 256 units [S1].
*   **Activation:** Not explicitly stated, but standard ReLU or similar is implied by the context of MLPs in this domain; however, the source does not specify. [G: Assume ReLU if not specified, but strictly following sources, it is "Not given in the sources."]

### Numbered Steps

1.  **Hash Encoding:** For a 3D point $\mathbf{x}$, compute its hash encoding $\text{enc}(\theta_h, \mathbf{x})$ using 16 layers with 2 features per layer [S1].
2.  **Fourier Encoding:** Compute the Fourier positional encoding $\text{enc}_{ff}(\mathbf{x})$ with dimension 6 for the input spatial location [S1].
3.  **Geometry Network Forward Pass:**
    *   Input the Fourier-encoded spatial location $\text{enc}_{ff}(\mathbf{x})$ to the first layer of the geometry network [S1].
    *   Process through the MLP layers.
    *   At the connected layer (specifically, the input to the third layer concatenates the hash encoding and the output of the second hidden layer), concatenate the hash encoding $\text{enc}(\theta_h, \mathbf{x})$ with the output of the previous layer [S1].
    *   Output the geometry feature vector and the SDF value $S(\mathbf{x})$ [S1].
4.  **Surface Normal Calculation:** Compute the surface normal $\mathbf{n}$ as the gradient of the SDF: $\mathbf{n} = \nabla S(\mathbf{x})$ [S1].
5.  **Light Field Network Forward Pass:**
    *   Compute Fourier positional encoding for the view direction $\mathbf{v}$ with dimension 6 [S1].
    *   Concatenate the Fourier-encoded view direction $\text{enc}_{ff}(\mathbf{v})$, the surface normal $\mathbf{n}$, and the geometry feature vector from Step 3 [S1].
    *   Pass this concatenated vector through the 4-layer light field MLP (256 units per layer) to predict the color $\mathbf{c}$ [S1].
6.  **Hierarchical Sampling:** Sample points along the ray using a hierarchical sampling strategy [S1]. This involves sampling from a coarse distribution and then refining the samples based on the SDF values [S1].
7.  **Invalid Point Elimination:** Calculate the mean of the SDF values of the sampled points on each ray. Use this mean as a threshold to eliminate invalid sampled points (points likely inside or far from the surface) [S1].
8.  **Volume Rendering:** Render the image using the standard differentiable volume rendering equation:
    $$
    \hat{C}(r) = \sum_{k=1}^{N} w_k \mathbf{c}_k, \quad w_k = T_k \alpha_k, \quad T_k = \prod_{j=1}^{k-1} (1 - \alpha_j)
    $$
    where opacity $\alpha_k = 1 - e^{-\sigma_k \delta_k}$ [S1]. The density $\sigma$ is derived from the SDF [S1].
9.  **Loss Calculation:** Minimize the reconstruction loss, which includes weights $\alpha=0.1$, $\beta=0.1$, and $\gamma=5 \times 10^{-4}$ in Eq. (8) of the source [S1]. The specific form of Eq. (8) is not provided in the text, but it typically involves photometric loss and SDF regularization [S1].
10. **Geometry Extraction:** Extract the final geometry using the Marching Cubes algorithm at a resolution of $512^3$ [S1].

            nn.Linear(256 + 32, 256), # 32 = 16 layers * 2 features
            nn.Softplus(beta=100),
            nn.Linear(256, 256),
            nn.Softplus(beta=100),
            nn.Linear(256, 256),
            nn.Softplus(beta=100),
            nn.Linear(256, 1) # Output SDF
        )

    def forward(self, x):

        # Fourier encoding
        fourier_enc = fourier_position_encoding(x, self.fourier_dim)
        # Hash encoding
        hash_feat = self.hash_enc(x)
        
        # First two layers use only Fourier encoding
        h = self.mlp[0](fourier_enc)
        h = self.mlp[1](h)

        for i in range(2, len(self.mlp)):

        sdf = h.squeeze(-1)

class LightFieldNetwork(nn.Module):

            layers.append(nn.Linear(in_dim, hidden_units))

        fourier_view = fourier_position_encoding(view_dir, 6)
        input_vec = torch.cat([fourier_view, normal, geo_feat], dim=-1)
        color = self.output_layer(self.mlp(input_vec))

def fourier_position_encoding(x, dim):
    # x: (N, 3)
    # Returns (N, dim * 2) using sin/cos for frequencies 2^0 to 2^(dim-1)
    # [G] Standard implementation
    freq_bands = 2.0 ** torch.linspace(0, dim-1, dim).to(x.device)
    x_expanded = x.unsqueeze(-1) * freq_bands.unsqueeze(0)
    encoded = torch.cat([torch.sin(x_expanded), torch.cos(x_expanded)], dim=-1)
    return encoded

    t_vals = torch.linspace(0, 1, num_samples)

    # Get SDF
    sdf = geometry_net(points)

    # [G] Simplified logic based on description

    # Eliminate points where SDF is significantly positive (outside)
    # [G] Exact thresholding logic not specified, using mean as threshold

    # Compute density from SDF
    # [G] Standard conversion: sigma = max(0, -SDF / delta) or similar
    # Not explicitly defined in [S1], assuming standard SDF-to-density
    delta = 0.01
    sigma = torch.relu(-sdf / delta)
    
    # Volume rendering
    # [G] Standard differentiable volume rendering
    alpha = 1.0 - torch.exp(-sigma * delta)
    T = torch.cumprod(1.0 - alpha, dim=1)
    weights = alpha * T
    
    # Get color
    # Compute normals
    grad = torch.autograd.grad(sdf.sum(), points, create_graph=True)[0]
    normal = torch.nn.functional.normalize(grad, dim=-1)
    
    # Get geometry features for valid points
    geo_feat = hash_enc(points)
    
    # Predict color
    color = light_field_net(ray_direction, normal, geo_feat)
    
    # Composite
    final_color = torch.sum(weights.unsqueeze(-1) * color, dim=1)
    return final_color

### Edge Cases and Pitfalls
*   **Textureless Areas:** Baseline methods like NeuS, IDR, VolSDF, and UNISURF perform poorly in textureless areas [S1]. This method mitigates this by using SDF constraints [S1].
*   **Noise in NeRF:** NeRF reconstructs rough geometry with obvious noise due to lack of direct constraints on volume density [S1]. This method avoids this by using SDF thresholding [S1].
*   **Invalid Points:** The method explicitly eliminates invalid sampled points using the mean of the SDF as a threshold [S1]. Failure to do so may lead to incorrect rendering in empty space.

## Operating characteristics
*   **Time Complexity:** Training time is 1.8 hours for multi-view reconstruction on the DTU dataset [S1]. This is significantly faster than IDR (5.2 hours), NeuS (7.2 hours), UNISURF (21 hours), VolSDF (9 hours), and NeRF (9.1 hours) [S1].
*   **Memory Complexity:** Memory usage is 5 GB [S1]. This is lower than IDR (6.5 GB), NeuS (7 GB), UNISURF (6 GB), VolSDF (13.8 GB), and NeRF (8 GB) [S1].
*   **Rays per Iteration:** 512 rays per iteration [S1]. This is lower than IDR (2048), UNISURF (1024), VolSDF (1024), and NeRF (1024), but equal to NeuS (512) [S1].
*   **Performance:**
    *   **PSNR:** Mean PSNR of 30.85 dB [S1]. This is higher than IDR (23.20 dB), NeuS (29.66 dB), UNISURF (28.53 dB), VolSDF (27.11 dB), and NeRF (29.80 dB) [S1].
    *   **Chamfer Distance:** Mean Chamfer-L2 distance of $0.72 \times 10^{-6}$ [S1]. This is lower (better) than IDR ($0.90 \times 10^{-6}$) and NeuS ($0.77 \times 10^{-6}$) [S1].
*   **Strengths:** Reconstructs more geometric detail than baselines, especially in textureless areas and high-frequency details (e.g., bird feathers) [S1]. Faster training and lower memory usage compared to most baselines [S1].
*   **Limitations:** Not explicitly stated in the sources, but the method relies on the quality of the hash encoding and the SDF representation, which may be sensitive to initialization and hyperparameters [S1].

## Background
The method was proposed by Z. Deng, H. Xiao, Y. Lang, et al. in the paper "Multi-scale hash encoding based neural geometry representation" [S1]. It was developed to address the limitations of existing neural implicit methods in reconstructing high-frequency geometric details and efficiently synthesizing novel views from multi-view images [S1]. The method builds on the concept of hash encoding, which was previously used in [SIREN] and other contexts, and applies it to neural geometry representation with SDF thresholding [S1]. It is used for multi-view image reconstruction and novel view synthesis tasks, evaluated on the DTU and BlendedMVS datasets [S1].
