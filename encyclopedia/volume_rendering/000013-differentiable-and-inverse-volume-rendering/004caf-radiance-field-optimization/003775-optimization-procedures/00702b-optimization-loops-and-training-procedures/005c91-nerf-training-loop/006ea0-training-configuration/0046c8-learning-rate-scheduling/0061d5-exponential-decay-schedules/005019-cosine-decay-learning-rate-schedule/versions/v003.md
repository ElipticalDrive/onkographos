# Cosine Decay Learning Rate Schedule

Also called: Cosine Annealing, Cosine Decay, Eikonal loss weighting, Training schedule and loss weighting

## Overview
The Cosine Decay Learning Rate Schedule gradually reduces the learning rate from a peak value to a minimum value following a cosine curve, often preceded by a linear warmup phase [S2, unofficial][S3]. It is used in differentiable volume rendering and radiance field optimization to stabilize training convergence [S1, S3]. It sets itself apart from [Exponential Decay Learning Rate Schedule](9145-exponential-decay-learning-rate-schedule.md) by providing a smoother decay profile that avoids the sharp initial drop of exponential schedules, and from [Linear Learning Rate Schedule](11850-linear-learning-rate-schedule.md) by offering a non-linear transition [G].

## How it works
**Inputs and Outputs:**
- **Inputs:** $t$ (current iteration, integer, $t \ge 0$), $t_{warmup}$ (warmup iterations, integer), $t_{total}$ (total iterations, integer), $\eta_{max}$ (peak learning rate, float), $\eta_{min}$ (minimum learning rate, float). [S2, unofficial] extends these to support repeated cycles using lists: `warm_up_steps`, `cycle_lengths`, `f_max`, `f_min`, `f_start`, and cumulative cycle boundaries `cum_cycles`.
- **Outputs:** $\eta_t$ (learning rate for iteration $t$, float).

**Data Structures:**
Lists of cycle parameters (`warm_up_steps`, `cycle_lengths`, `f_max`, `f_min`, `f_start`) and cumulative cycle boundaries `cum_cycles` for multi-cycle training configurations [S2, unofficial].

**Parameters:**
- Typical values from [S3]: $t_{warmup} = 5,000$, $\eta_{max} = 10^{-3}$, $\eta_{min} = 5 \times 10^{-5}$.
- Typical values from [S1]: $\eta_{max} = 2 \times 10^{-4}$ for non-backbone layers, $\eta_{max} = 2 \times 10^{-6}$ for pre-trained backbones.
- $t_{total}$ varies by dataset and model size (e.g., 150,000 iterations for RealEstate10K [S1]).

**Steps:**
1. Determine the current cycle index `cycle` by finding the smallest `cl` in `cum_cycles` such that $t \le cl$ [S2, unofficial].
2. Normalize the step within the cycle: $n = t - cum\_cycles[cycle]$ [S2, unofficial].
3. If $n < warm\_up\_steps[cycle]$, compute the learning rate using the linear warmup formula [S2, unofficial].
4. Otherwise, compute the learning rate using the cosine decay formula [S2, unofficial].

**Formulas:**
For the warmup phase within a cycle:
$$ f = \frac{f_{max} - f_{start}}{warm\_up\_steps} \cdot n + f_{start} $$
For the cosine decay phase within a cycle, let $t_{norm} = \min\left(\frac{n - warm\_up\_steps}{cycle\_length - warm\_up\_steps}, 1.0\right)$ [S2, unofficial]. Then:
$$ f = f_{min} + 0.5 \cdot (f_{max} - f_{min}) \cdot (1 + \cos(t_{norm} \cdot \pi)) $$
[S2, unofficial]

**Edge Cases and Pitfalls:**
- **Division by Zero:** If $t_{total} = t_{warmup}$, the denominator in the cosine phase is zero. This degenerate case where warmup consumes the entire training budget should default to $\eta_{max}$ or be explicitly guarded [G].
- **Precision:** Ensure floating-point precision is maintained for small learning rates near $\eta_{min}$ to prevent gradient stagnation [G].
- **Boundary Conditions:** At $t = t_{warmup}$, both formulas yield $\eta_{max}$, ensuring continuity. At $t = t_{total}$, the normalized progress reaches $1.0$, yielding $\eta_{min}$ [G].

**Pseudocode:**
```python
import math

def compute_cosine_decay_lr(t, warm_up_steps, cycle_lengths, f_max, f_min, f_start, cum_cycles):
    """
    Compute learning rate using cosine decay with linear warmup, supporting repeated cycles.
    
    Args:
        t: Current iteration.
        warm_up_steps: List of warm-up steps for each cycle.
        cycle_lengths: List of total lengths for each cycle.
        f_max: List of maximum values for each cycle.
        f_min: List of minimum values for each cycle.
        f_start: List of starting values for each cycle.
        cum_cycles: List of cumulative cycle boundaries.
        
    Returns:
        Learning rate for iteration t.
    """
    # Determine current cycle index
    cycle = 0
    for i, cl in enumerate(cum_cycles):
        if t <= cl:
            cycle = i
            break
    else:
        cycle = len(cum_cycles) - 1

    # Normalize step within cycle
    n = t - cum_cycles[cycle] if cycle > 0 else t

    # Cycle-specific parameters
    w_steps = warm_up_steps[cycle]
    c_length = cycle_lengths[cycle]
    f_max_val = f_max[cycle]
    f_min_val = f_min[cycle]
    f_start_val = f_start[cycle]

    if n < w_steps:
        # Linear warmup phase
        return (f_max_val - f_start_val) / w_steps * n + f_start_val
    else:
        # Cosine decay phase
        denom = c_length - w_steps
        if denom == 0:
            return f_max_val
        t_norm = min((n - w_steps) / denom, 1.0)
        t_norm = max(0.0, t_norm)
        return f_min_val + 0.5 * (f_max_val - f_min_val) * (1.0 + math.cos(t_norm * math.pi))
```

## Operating characteristics
- **Time Complexity:** $O(1)$ per iteration for learning rate computation [G].
- **Memory Complexity:** $O(1)$ auxiliary memory per iteration, excluding parameter lists [G].
- **Performance:** Provides stable convergence in neural implicit representations [G]. [S3] reports successful reconstruction of thin structures with an Eikonal loss weight of 0.01, noting that lower weights lead to thinner structures, indicating interaction between the LR schedule and regularization strength [S3]. [S1] reports training times of 1 day (small model) and 2 days (large model) on 4× GH200 GPUs for 150K iterations at 256×256 resolution [S1].
- **Strengths:** Smooth transition prevents oscillations in late training; warmup stabilizes early training [G].
- **Limitations:** Requires setting $t_{total}$ in advance; less flexible than adaptive schedulers if validation metrics are used to adjust [G].
- **When to use:** Standard choice for NeRF and radiance field optimization when a fixed training budget is known [G].
- **When not to use:** When training duration is uncertain or dynamic adjustment based on loss landscape is required [G].

## Background
The cosine decay schedule is a widely used technique in deep learning, originating from general optimization practices [G]. In volume rendering and neural implicit representations, it has been adopted in methods like ShadowNeuS [S3] and DepthSplat [S1] to optimize neural networks for 3D reconstruction. The specific combination with linear warmup and coarse-to-fine rendering strategies has become a standard configuration for stabilizing training in differentiable rendering pipelines [S3].
