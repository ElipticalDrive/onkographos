# Adam Optimizer with Torch Compatibility and Tile-Level Sparsity

Also called: Adam with zero-gradient replay, adamUpdateTorchCUDA

## Overview
A CUDA implementation of the Adam optimizer that maintains strict behavioral compatibility with PyTorch's Adam while optimizing for tile-level sparsity [S1, unofficial]. It solves the problem of inconsistent state updates in sparse rendering pipelines where some tiles receive zero gradients, by replaying optimization steps for skipped tiles to ensure exponential moving averages decay correctly [S1, unofficial]. It sets itself apart from standard Adam implementations by explicitly handling the temporal gap between optimization steps for untiled regions, ensuring that the state evolution matches what would occur if every parameter were updated at every step, even with zero gradients [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `param`: Current parameter value (float/tensor) [S1, unofficial].
    *   `grad`: Current gradient for the parameter (float/tensor) [S1, unofficial].
    *   `exp_avg`: First moment estimate (float/tensor) [S1, unofficial].
    *   `exp_avg_sq`: Second moment estimate (float/tensor) [S1, unofficial].
    *   `global_step`: Current global optimization step index (integer) [S1, unofficial].
    *   `lr_history`: Array of learning rates indexed by step (array/tensor) [S1, unofficial].
    *   `b1`: First moment decay rate (float) [S1, unofficial].
    *   `b2`: Second moment decay rate (float) [S1, unofficial].
    *   `eps`: Epsilon for numerical stability (float) [S1, unofficial].
    *   `tiles_touched`: Boolean array indicating which tiles were rendered in the current step (array) [S1, unofficial].
    *   `last_seen_step`: Integer array tracking the last optimization step performed for each tile (array) [S1, unofficial].
    *   `N`: Total number of tiles (integer) [S1, unofficial].
    *   `M`: Number of parameters per tile (integer) [S1, unofficial].
*   **Outputs:**
    *   Updated `param`, `exp_avg`, `exp_avg_sq` in global memory [S1, unofficial].
    *   Updated `last_seen_step` for the tile if this thread is the leader [S1, unofficial].

**Data Structures:**
*   `tiles_touched`: A boolean array of size $N$, where $N$ is the number of tiles. `tiles_touched[i]` is true if tile $i$ contributed to the loss in the current step [S1, unofficial].
*   `last_seen_step`: An integer array of size $N$. `last_seen_step[i]` stores the global step index of the last time tile $i$ was updated [S1, unofficial].
*   `lr_history`: An array of learning rates indexed by step, used to support dynamic learning rate schedules while maintaining Torch compatibility [S1, unofficial].

**Algorithm Steps:**
1.  **Thread Indexing:** Initialize thread index $p\_idx$ and global parameter index $g\_idx = p\_idx / M$ [S1, unofficial].
2.  **Sparsity Check:** If $g\_idx \ge N$ or `tiles_touched[g_idx]` is false, return immediately [S1, unofficial].
3.  **State Loading:** Load parameter state into registers: `param`, `exp_avg`, `exp_avg_sq`, and `param_grad`. Retrieve the `last_seen_step` for the tile $g\_idx$ [S1, unofficial].
4.  **Zero-Gradient Replay:** If there is a gap between the previous update and the current step (i.e., $prev\_seen\_step + 1 \le global\_step - 1$), replay the Adam updates for all intermediate steps using zero gradients. This involves decaying the exponential moving averages and applying the Adam update with the learning rate history [S1, unofficial].
    *   For each step $s$ from $prev\_seen\_step + 1$ to $global\_step - 1$:
        *   Compute bias correction factors: $bias\_correction1 = 1 - b1^s$, $bias\_correction2 = 1 - b2^s$ [S1, unofficial].
        *   Compute step size: $step\_size = lr\_history[s - 1] / bias\_correction1$ [S1, unofficial].
        *   Compute denominator: $denom = \sqrt{exp\_avg\_sq} / \sqrt{bias\_correction2} + \epsilon$ [S1, unofficial].
        *   Compute update delta: $delta = -step\_size \cdot exp\_avg / denom$ [S1, unofficial].
        *   Update parameter and moving averages: $param = param + delta$, $exp\_avg = b1 \cdot exp\_avg$, $exp\_avg\_sq = b2 \cdot exp\_avg\_sq$ [S1, unofficial].
5.  **Current Step Update:** Update the exponential moving averages with the current gradient: $exp\_avg = b1 \cdot exp\_avg + (1 - b1) \cdot grad$, $exp\_avg\_sq = b2 \cdot exp\_avg\_sq + (1 - b2) \cdot grad^2$ [S1, unofficial].
6.  **Delta Computation:** Compute the Adam update delta for the current global step using the updated moving averages and the learning rate from $lr\_history[global\_step - 1]$, then add it to the parameter value [S1, unofficial].
7.  **State Writeback:** Write the updated parameter and moving averages back to global memory. If the thread index is a multiple of $M$ (indicating the first thread of a tile group), update $last\_seen\_step[g\_idx] = global\_step$ [S1, unofficial].

**Pseudocode:**
```python
def adam_update_torch_cuda(
    param: float,
    grad: float,
    exp_avg: float,
    exp_avg_sq: float,
    global_step: int,
    lr_history: list[float],
    b1: float,
    b2: float,
    eps: float,
    tiles_touched: list[bool],
    last_seen_step: list[int],
    g_idx: int,
    p_idx: int,
    M: int,
    N: int
) -> tuple[float, float, float, list[int]]:
    """
    Performs one Adam update step with zero-gradient replay and tile-level sparsity.
    
    Args:
        param: Current parameter value.
        grad: Current gradient.
        exp_avg: First moment estimate.
        exp_avg_sq: Second moment estimate.
        global_step: Current global step index (1-based).
        lr_history: List of learning rates, indexed by step-1.
        b1: First moment decay rate.
        b2: Second moment decay rate.
        eps: Epsilon for numerical stability.
        tiles_touched: Boolean array of touched tiles.
        last_seen_step: Array of last seen steps per tile.
        g_idx: Global tile index.
        p_idx: Global parameter index.
        M: Parameters per tile.
        N: Total number of tiles.
        
    Returns:
        Updated (param, exp_avg, exp_avg_sq, last_seen_step).
    """
    # Step 1 & 2: Sparsity Check
    if g_idx >= N or not tiles_touched[g_idx]:
        return param, exp_avg, exp_avg_sq, last_seen_step

    # Step 3: Load State
    prev_seen_step = last_seen_step[g_idx]

    # Step 4: Zero-Gradient Replay
    for s in range(prev_seen_step + 1, global_step):
        bias_correction1 = 1.0 - b1 ** s
        bias_correction2 = 1.0 - b2 ** s
        
        step_size = lr_history[s - 1] / bias_correction1
        denom = (exp_avg_sq ** 0.5) / (bias_correction2 ** 0.5) + eps
        delta = -step_size * exp_avg / denom
        
        param = param + delta
        exp_avg = b1 * exp_avg
        exp_avg_sq = b2 * exp_avg_sq

    # Step 5: Current Step Update
    exp_avg = b1 * exp_avg + (1.0 - b1) * grad
    exp_avg_sq = b2 * exp_avg_sq + (1.0 - b2) * grad ** 2
    
    # Step 6: Delta Computation
    bias_correction1 = 1.0 - b1 ** global_step
    bias_correction2 = 1.0 - b2 ** global_step
    
    step_size = lr_history[global_step - 1] / bias_correction1
    denom = (exp_avg_sq ** 0.5) / (bias_correction2 ** 0.5) + eps
    delta = -step_size * exp_avg / denom
    
    param = param + delta

    # Step 7: Leader Update
    if p_idx % M == 0:
        last_seen_step[g_idx] = global_step

    return param, exp_avg, exp_avg_sq, last_seen_step
```

**Parameters:**
*   `b1`: First moment decay rate, typically 0.9 [S1, unofficial].
*   `b2`: Second moment decay rate, typically 0.999 [S1, unofficial].
*   `eps`: Epsilon for numerical stability, typically 1e-8 [S1, unofficial].
*   `lr_history`: Array of learning rates indexed by step, used to support dynamic learning rate schedules while maintaining Torch compatibility [S1, unofficial].
*   `tiles_touched`: Boolean array indicating which tiles were rendered in the current step, used to skip updates for untouched tiles [S1, unofficial].
*   `last_seen_step`: Integer array tracking the last optimization step performed for each tile, used to determine if zero-gradient replay is needed [S1, unofficial].

**Pitfalls:**
*   If a tile was not touched in previous steps, the moving averages must be decayed for each skipped step to maintain consistency with PyTorch's Adam behavior, which assumes updates occur at every step even if gradients are zero [S1, unofficial].
*   The kernel launches with grid size $(N \cdot M + 255) / 256$ blocks and 256 threads per block, requiring careful indexing to avoid out-of-bounds memory access [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales with the number of tiles and parameters due to the tile-level sparsity optimization, as untouched tiles are skipped entirely [S1, unofficial].
*   **Strengths:** Maintains strict compatibility with PyTorch's Adam, ensuring consistent behavior across different frameworks [S1, unofficial]. Efficiently handles sparse gradients by skipping updates for untouched tiles while correctly maintaining state for those tiles [S1, unofficial].
*   **Limitations:** The replay loop can be computationally expensive if large gaps occur between updates for a tile [S1, unofficial].
*   **When to use:** Use when training differentiable volume rendering pipelines with tile-based rasterization where sparsity is high, and strict compatibility with PyTorch's Adam is required [S1, unofficial].
*   **When not to use:** Avoid if the overhead of zero-gradient replay becomes significant due to extreme sparsity or if framework compatibility is not a concern [S1, unofficial].

## Background
This method is a CUDA implementation of the Adam optimizer designed for differentiable volume rendering pipelines that uses tile-level sparsity [S1, unofficial]. It was introduced to address state consistency issues in sparse rendering by replaying optimization steps for parameters that received zero gradients [S1, unofficial].
