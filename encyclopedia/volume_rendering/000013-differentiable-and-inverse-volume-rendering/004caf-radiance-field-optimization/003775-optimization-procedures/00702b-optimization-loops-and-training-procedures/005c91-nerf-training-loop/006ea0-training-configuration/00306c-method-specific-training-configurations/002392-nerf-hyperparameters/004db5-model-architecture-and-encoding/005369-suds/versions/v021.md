# SUDS

Also called: Scalable Urban Dynamic Scenes

## Overview
SUDS is a 4D radiance field representation designed for large-scale dynamic urban scenes that factorizes the scene into three separate hash table data structures to efficiently encode static, dynamic, and far-field radiance fields [S1]. It solves the problem of scaling neural reconstruction to city-level footprints with significant dynamism and multi-video inputs without requiring expensive 3D supervision like bounding boxes or panoptic labels [S1]. Unlike sibling methods that rely on per-object models or supervised annotations, SUDS uses unlabeled RGB, sparse LiDAR, and optical flow to learn scene flow and semantic decomposition, enabling free-viewpoint rendering and 3D scene flow estimation at arbitrary poses and time steps [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ordered RGB images from $N$ videos taken at different days with diverse weather/lighting, associated camera poses, aligned sparse LiDAR depth measurements, 2D self-supervised DINO descriptors, and 2D optical flow predictions [S1].
*   **Outputs:** View-dependent color $\mathbf{c}$, volume density $\sigma$, semantic features $\Phi$, and 3D scene flow vectors $\mathbf{s}$ for any position $\mathbf{x}$, viewing direction $\mathbf{d}$, time $t$, and video ID $vid$ [S1].

**Data Structures:**
The scene is decomposed into $K$ spatial cells, each trained independently [S1]. Within each cell, the representation consists of three branches, each implemented using a multi-resolution hash table hierarchy [S1].
1.  **Static Branch:** Stores features for stationary topography. Uses 3D spatial voxels $\mathbf{v}_{l,s}$ [S1].
2.  **Dynamic Branch:** Stores features for transient and dynamic objects. Uses 4D spacetime voxels $\mathbf{v}_{l,d}$ [S1].
3.  **Far-field Branch:** Stores features for sky and far-field objects. Uses 3D voxels $\mathbf{v}_{l,e}$ indexed by normalized direction vectors [S1].

Each branch uses $L$ resolution levels, where resolution doubles between levels [S1]. Features are stored in hash tables of dimension $F$ [S1]. Hash indices are computed as follows:
$$ i_{l,s} = \text{static hash}(\text{space}(\mathbf{v}_{l,s})) $$
$$ i_{l,d} = \text{dynamic hash}(\text{space}(\mathbf{v}_{l,d}), \text{time}(\mathbf{v}_{l,d}), vid) $$
$$ i_{l,e} = \text{env hash}(\text{dir}(\mathbf{v}_{l,e}), vid) $$
Hash collisions are handled via gradient averaging [S1]. The video ID $vid$ is included in the hash index to index separate interpolating functions per video without linear memory growth, but is not used for interpolation [S1].

**Numbered Steps:**
1.  **Spatial Partitioning:** Split the scene into $K$ spatial cells with centroids $\mathbf{k} \in \mathbb{R}^3$ [S1]. Generate separate training datasets for each cell by including only datapoints whose camera rays intersect the cell [S1]. Prune irrelevant rays using LiDAR depth measurements to ensure visibility [S1].
2.  **Voxel Lookup:** For an input coordinate $(\mathbf{x}, \mathbf{d}, t, vid)$, find surrounding voxels at $L$ resolution levels for the static ($\mathbf{v}_{l,s}$), dynamic ($\mathbf{v}_{l,d}$), and far-field ($\mathbf{v}_{l,e}$) branches [S1].
3.  **Hash Indexing:** Compute hash indices for the corners of the surrounding voxels using the specific hash functions defined above [S1].
4.  **Feature Interpolation:** Look up feature vectors corresponding to the corners. Linearly interpolate features for the static branch. Use quadlinear interpolation for the dynamic 4D branch [S1]. Concatenate results from all $L$ levels into a feature vector $\mathbf{f} \in \mathbb{R}^{LF}$ [S1].
5.  **Auxiliary Input Processing:** Compute a latent embedding for lighting variations in the static branch as $\mathbf{A}_{vid} \mathbf{F}(t)$, where $\mathbf{A}_{vid}$ is a video-specific matrix and $\mathbf{F}(t)$ is a Fourier-encoded time index [S1]. Concatenate $\mathbf{f}$, viewing direction $\mathbf{d}$, and auxiliary inputs (e.g., $\mathbf{A}_{vid} \mathbf{F}(t)$ for static branch) [S1].
6.  **MLP Evaluation:** Pass the concatenated vector into a small MLP for each branch to obtain outputs [S1]:
    *   Static: Color $\mathbf{c}_s(\mathbf{x}, \mathbf{d}, \mathbf{A}_{vid} \mathbf{F}(t)) \in \mathbb{R}^3$ and density $\sigma_s(\mathbf{x}) \in \mathbb{R}$ [S1].
    *   Dynamic: Density $\sigma_d(\mathbf{x}, t, vid) \in \mathbb{R}$, color $\mathbf{c}_d(\mathbf{x}, t, vid, \mathbf{d}) \in \mathbb{R}^3$, shadow ratio $\rho_d(\mathbf{x}, t, vid) \in [0, 1]$, and scene flow $\mathbf{s}_{t0}(\mathbf{x}, t, vid) \in [-1, 1]^3$ [S1].
    *   Far-field: Color $\mathbf{c}_e(\mathbf{d}, vid) \in \mathbb{R}^3$ [S1].
    *   Semantic Heads: Each branch outputs $C$-dimensional feature logits $\Phi_s, \Phi_d, \Phi_e$ [S1].
7.  **Density and Radiance Combination:** Compute total density and radiance [S1]:
    $$ \sigma(\mathbf{x}, t, vid) = \sigma_s(\mathbf{x}) + \sigma_d(\mathbf{x}, t, vid) $$
    $$ \mathbf{c}(\mathbf{x}, t, vid, \mathbf{d}) = \frac{(1 - \rho_d)\sigma_s \mathbf{c}_s + \sigma_d \mathbf{c}_d}{\sigma} $$
    [S1]
8.  **Rendering:** Accumulate transmittance $T(t)$ and radiance along sampled points $\mathbf{r}(t)$ on a camera ray [S1]:
    $$ \hat{\mathbf{C}}(\mathbf{r}, t, vid) = \int_0^{+\infty} T(t) \sigma(\mathbf{r}(t), t, vid) \mathbf{c}(\mathbf{r}(t), t, vid, \mathbf{d}) dt + T(+\infty) \mathbf{c}_e(\mathbf{d}, vid) $$
    where $T(t) = \exp\left(-\int_0^t \sigma(\mathbf{r}(s), t, vid) ds\right)$ [S1].
9.  **Loss Calculation:** Minimize a weighted sum of reconstruction, warping, flow, and regularization losses (see Operating characteristics) [S1].

**Parameters:**
*   $F$: Dimensionality of feature vectors in hash tables [S1].
*   $L$: Number of resolution levels (resolution doubles between levels) [S1].
*   $N$: Number of input videos [S1].
*   $vid$: Video ID identifier [S1].
*   $\mathbf{A}_{vid}$: Video-specific matrix for lighting conditioning [S1].
*   $\mathbf{F}(t)$: Fourier-encoded time index [S1].
*   $k$: Constant set to 1.75 in the skewed binary entropy loss [S1].
*   $C$: Dimensionality of DINO feature grid output [S1].
*   Training iterations: 250,000 [S1].
*   Rays per batch: 4,098 [S1].
*   Initial learning rate: $5 \times 10^{-3}$ [S1].
*   Final learning rate: $5 \times 10^{-4}$ (decayed from initial) [S1].

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** Handled via gradient averaging [S1].
*   **Occlusions:** Warping losses are downweighted in ambiguous regions using a weight $W_{t0}(\mathbf{r})$ derived from dynamic geometry difference [S1].
*   **Shadow Over-explanation:** Penalized by the squared magnitude of the shadow ratio $\rho_d$ to prevent it from explaining dark regions [S1].
*   **Visibility:** Pruning rays using LiDAR depth is critical to avoid including data points that are occluded by intervening buildings [S1].

## Operating characteristics
**Time and Memory Complexity:**
SUDS scales to tens of thousands of objects across 1.2 million frames from 1,700 videos spanning geospatial footprints of hundreds of kilometers [S1]. It is 10x quicker to train than state-of-the-art methods that rely on ground truth 3D bounding box annotations [S1]. The multi-resolution hash table structure allows for efficient memory usage compared to dense voxel grids or large MLPs, scaling without linear memory growth with the number of videos due to the video-ID-based hashing [S1].

**Strengths and Limitations:**
*   **Strengths:** Handles ego-motion and multi-video representations; does not require supervised inputs like panoptic segmentation labels or bounding boxes; enables unsupervised 3D instance segmentation and 3D cuboid detection; models shadows explicitly [S1].
*   **Limitations:** Requires aligned sparse LiDAR and optical flow for supervision (though these are "free" sources, they are not RGB alone); relies on spatial partitioning which may introduce seams if not handled carefully (though not explicitly detailed in the notes, the partitioning is a key architectural choice) [S1].

**When to Use:**
Use SUDS for large-scale, dynamic urban scene reconstruction where multi-video inputs are available, and where unsupervised semantic decomposition and scene flow are desired. It is suitable when computational resources for training per-object NeRFs are insufficient or when 3D bounding box annotations are unavailable [S1].

## Background
SUDS was introduced in the paper "SUDS: Scalable Urban Dynamic Scenes" [S1]. It addresses the limitations of prior dynamic scene representations that require supervised inputs like 3D bounding boxes and panoptic labels, which are difficult to acquire for in-the-wild captures [S1]. It builds on ideas from Instant-NGP for hash table encoding and MegaNeRF for spatial partitioning [S1]. Unlike NSG, which cannot handle ego-motion and requires over 1TB of memory for a 30-second video, SUDS handles ego-motion and scales to city-level footprints [S1].
