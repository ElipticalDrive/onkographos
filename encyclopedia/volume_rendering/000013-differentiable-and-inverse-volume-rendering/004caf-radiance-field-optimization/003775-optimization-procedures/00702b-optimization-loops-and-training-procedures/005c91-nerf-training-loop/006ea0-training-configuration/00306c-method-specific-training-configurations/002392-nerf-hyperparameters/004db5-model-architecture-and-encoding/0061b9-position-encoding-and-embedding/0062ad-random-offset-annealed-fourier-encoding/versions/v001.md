# Random Offset Annealed Fourier Encoding

Also called: ROAFE

## Overview
Random Offset Annealed Fourier Encoding (ROAFE) is a positional encoding scheme for 3D coordinates that combines Fourier basis functions with random Gaussian offsets and an annealing schedule to improve the optimization landscape for neural radiance fields. It addresses the axis-alignment artifacts and striping issues inherent in standard NeRF encoding by breaking symmetry through random shifts, while using a truncated Hann window to gradually introduce high-frequency details. It is primarily used in the SAMURAI framework.

## How it works
**Inputs and Outputs:**
- Input: A 3D coordinate vector $x \in \mathbb{R}^3$.
- Output: An encoded vector $\gamma(x) \in \mathbb{R}^{3+6L}$, where $L$ is the number of frequency bands.

**Data Structures:**
- $R \in \mathbb{R}^{L \times 3}$: Matrix of random Gaussian offsets, sampled from $\mathcal{N}(0, 0.1)$.
- $\alpha \in [0, L]$: Annealing parameter, typically annealed from 0 to $L$ over a fixed number of training steps (e.g., 50,000 steps).
- $L$: Number of frequency bands. Default value is 10.

**Formulas:**
The encoding is defined as:
$$ \gamma(x) = (x, \Gamma_1(x; \alpha), \dots, \Gamma_{L-1}(x; \alpha)) $$
Note: The source notation uses indices $1$ to $L-1$ for the frequency components, implying $L$ total bands including the input or a specific indexing convention. However, the text states "10 Random Offset Annealed Fourier Frequencies" and the formula sums up to $L$ components if we consider the range. The source formula (1) lists $\Gamma_1 \dots \Gamma_{L-1}$. Let us strictly follow the source's indexing:
$$ \gamma(x) = (x, \Gamma_1, \dots, \Gamma_{L-1}) $$
Each frequency component $\Gamma_k$ for $k \in \{1, \dots, L-1\}$ is computed as:
$$ \Gamma_k(x; \alpha) = w_k(\alpha) \left[ \sin(2^k x + 2^k R_k), \cos(2^k x + 2^k R_k) \right] $$
where $R_k$ is the $k$-th row of the offset matrix $R$ (a vector in $\mathbb{R}^3$). The annealing weight $w_k(\alpha)$ is a truncated Hann window:
$$ w_k(\alpha) = \frac{1 - \cos(\pi \cdot \text{clamp}(\alpha - k, 0, 1))}{2} $$
Here, $\text{clamp}(v, 0, 1)$ restricts $v$ to the range $[0, 1]$.

**Parameters:**
- $L = 10$: Number of frequency bands.
- $R \sim \mathcal{N}(0, 0.1)$: Random offsets.
- $\alpha$: Annealing parameter, annealed over 50,000 steps.
- Direction encoding: 4 non-annealed and non-offset Fourier frequencies are used for the view direction $d$.

**Pseudocode:**
```python
import numpy as np

def random_offset_annealed_fourier_encoding(x, L=10, alpha=0.0, R=None):
    """
    Computes the Random Offset Annealed Fourier Encoding for a batch of 3D coordinates.
    
    Args:
        x: numpy array of shape (N, 3), batch of 3D coordinates.
        L: int, number of frequency bands.
        alpha: float, annealing parameter in [0, L].
        R: numpy array of shape (L, 3), random offsets. If None, sampled from N(0, 0.1).
        
    Returns:
        numpy array of shape (N, 3 + 6*(L-1)), the encoded vector.
    """
    if R is None:
        R = np.random.normal(0, 0.1, size=(L, 3))
    
    # Initialize output array
    # The input x is concatenated at the beginning.
    # There are L-1 frequency bands in the source formula (1).
    # Each band produces 2 * 3 = 6 values (sin and cos for x, y, z).
    # However, the formula (5) shows sin(2^k x + 2^k R_k). 
    # x is a vector, R_k is a vector. The addition is element-wise.
    # sin(2^k x + 2^k R_k) results in a vector of size 3.
    # So each k contributes 6 values.
    
    num_bands = L - 1
    output_dim = 3 + 6 * num_bands
    encoded = np.zeros((x.shape[0], output_dim))
    
    # Concatenate original coordinates
    encoded[:, :3] = x
    
    for k in range(1, L):
        # Calculate annealing weight w_k(alpha)
        # clamp(alpha - k, 0, 1)
        val = alpha - k
        clamped_val = np.clip(val, 0, 1)
        w_k = (1 - np.cos(np.pi * clamped_val)) / 2
        
        # Frequency scaling factor 2^k
        freq_scale = 2 ** k
        
        # Random offset for this band
        R_k = R[k-1, :] # R is 0-indexed in code, but formula uses 1-based k? 
                        # Source says R in R^{Lx3} and R_k. 
                        # If k goes 1..L-1, we need L-1 rows. 
                        # Let's assume R has L rows and we use indices 0..L-2 or similar.
                        # The source says "R in R^{Lx3}" and "R_k". 
                        # If k=1..L-1, we need L-1 vectors. 
                        # Let's assume R is indexed 0..L-1 and we use R[k-1] for k=1..L-1.
        
        # Compute argument: 2^k * x + 2^k * R_k
        # x shape: (N, 3), R_k shape: (3,)
        arg = freq_scale * x + freq_scale * R_k
        
        # Compute sin and cos
        sin_vals = np.sin(arg)
        cos_vals = np.cos(arg)
        
        # Apply weight
        # w_k is a scalar, broadcast to (N, 3)
        sin_weighted = w_k * sin_vals
        cos_weighted = w_k * cos_vals
        
        # Concatenate to output
        # Indices in output: 3 + (k-1)*6 to 3 + (k-1)*6 + 5
        start_idx = 3 + (k - 1) * 6
        encoded[:, start_idx : start_idx + 3] = sin_weighted
        encoded[:, start_idx + 3 : start_idx + 6] = cos_weighted
        
    return encoded
```

**Edge Cases and Pitfalls:**
- **Precision:** The exponential scaling $2^k$ can lead to large values for high $k$, potentially causing numerical instability in sine/cosine calculations if $x$ is not normalized.
- **Boundary Conditions:** The `clamp` function in the weight calculation ensures $w_k$ is 0 when $\alpha < k$ and 1 when $\alpha > k+1$, providing a smooth transition.
- **Degenerate Input:** If $x$ is not normalized, the high-frequency components may oscillate rapidly, leading to optimization difficulties.

## Operating characteristics
- **Time Complexity:** $O(L \cdot N)$, where $N$ is the batch size and $L$ is the number of frequency bands. The computation involves simple trigonometric functions and linear scaling.
- **Memory Complexity:** $O(L \cdot D)$, where $D$ is the dimensionality of the coordinate (3). The random offsets $R$ are stored once.
- **Measured Performance:** In SAMURAI, using 10 ROAFE bands annealed over 50,000 steps improved reconstruction quality compared to standard NeRF encoding, particularly in reducing striping artifacts.
- **Strengths:** Breaks axis-alignment, reduces striping artifacts, and provides a smooth optimization landscape via annealing.
- **Limitations:** Requires careful tuning of the annealing schedule and random offset variance. Not given in the sources: specific hardware performance metrics.
- **When to Use:** When standard NeRF encoding suffers from axis-aligned artifacts or slow convergence due to high-frequency details.
- **When Not to Use:** When computational resources are extremely limited and $L$ needs to be very small, or when the scene does not exhibit high-frequency details.

## Background
ROAFE was introduced in the SAMURAI paper (2022) [S1]. It builds on the Fourier encoding from NeRF [7], the annealing technique from BARF [5] and Nerfies [8], and the benefits of random frequencies from Tancik et al. [11]. The method was designed to improve the optimization landscape for neural radiance fields by combining these techniques.
