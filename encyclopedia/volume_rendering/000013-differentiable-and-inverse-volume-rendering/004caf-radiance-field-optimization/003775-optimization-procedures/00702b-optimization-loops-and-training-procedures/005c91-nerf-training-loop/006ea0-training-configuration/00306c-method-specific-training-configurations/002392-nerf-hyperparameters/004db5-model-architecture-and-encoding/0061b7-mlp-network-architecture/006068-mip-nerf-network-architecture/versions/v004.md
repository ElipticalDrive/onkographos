# Mip-NeRF Network Architecture

Also called: Mip-NeRF RGB-D Network Architecture

## Overview
This architecture is a compact, fully-connected multilayer perceptron (MLP) designed for neural radiance fields, specifically optimized for efficiency compared to the original NeRF [16] baseline [S1]. It solves the problem of high computational cost in radiance field representation by reducing the network size while maintaining structural similarity to standard implementations [S1]. It is distinguished from its sibling, the [Mip-NeRF 360 MLP Architecture](14098-mip-nerf-360-mlp-architecture.md), by its specific configuration of hidden layer dimensions and its origin in the RGB-D depth-assisted variant [S1].

## How it works
The method maps 3D spatial coordinates and viewing directions to volume density and RGB color using a hierarchical sinusoidal positional encoding followed by a shallow MLP [S1].

**Inputs and Outputs:**
*   **Input:** 3D position vector $\mathbf{x} \in \mathbb{R}^3$ and viewing direction vector $\mathbf{d} \in \mathbb{R}^3$.
*   **Output:** Volume density scalar $\sigma$ and RGB color vector $\mathbf{c} \in [0, 1]^3$.

**Data Structures:**
The network consists of fully-connected (FC) layers. The internal state is a feature vector.
*   **Positional Encoding:** The input $\mathbf{x}$ and $\mathbf{d}$ are expanded using a hierarchical sinusoidal positional encoding function $\gamma(\cdot)$ [S1]. The specific dimensionality of the encoded vectors is not explicitly defined in the source text beyond the layer sizes, but standard NeRF implementations use $\gamma(\mathbf{x}) \in \mathbb{R}^{2L+1}$ and $\gamma(\mathbf{d}) \in \mathbb{R}^{2L'+1}$ where $L, L'$ are the number of frequency bands [S1]. The source diagram indicates an input size of 96 for the position encoding path and 27 for the direction encoding path [S1].

**Parameters:**
*   **Hidden Layers:** 4 layers, each with 256 channels [S1].
*   **Output Layer:** 1 layer with 128 channels [S1].
*   **Activations:** ReLU for hidden layers; Sigmoid for the final RGB output [S1].
*   **Density Output:** The source diagram shows a direct path for $\sigma$ from the encoded position $\gamma(\mathbf{x})$ with a dimension of 96, implying a separate or parallel output head for density, or that the first 96 units of the first hidden layer are dedicated to density [S1]. The text states the network outputs RGB, and the diagram shows $\sigma$ branching off early [S1].

**Algorithm Steps:**
1.  **Encode Position:** Compute $\mathbf{e}_x = \gamma(\mathbf{x})$.
2.  **Encode Direction:** Compute $\mathbf{e}_d = \gamma(\mathbf{d})$.
3.  **Density Branch:** Pass $\mathbf{e}_x$ through a transformation to produce $\sigma$. The source diagram [S1] shows $\gamma(\mathbf{x})$ (size 96) mapping directly to $\sigma$ via a block labeled "96", suggesting a linear projection or identity mapping for density, or that the density is derived from the initial feature representation before the main MLP depth. Given the text says "The MLP uses 4 hidden layers... for RGB", and the diagram shows $\sigma$ branching from the input encoding, we assume $\sigma$ is computed from $\mathbf{e}_x$ or the first layer. However, standard NeRF computes $\sigma$ from the last hidden layer of the position branch. The diagram [S1] is ambiguous: it shows $\gamma(\mathbf{x})$ -> 96 -> $\sigma$ AND $\gamma(\mathbf{x})$ -> 96 -> 256 -> 256 -> 256 -> 256. This implies $\sigma$ might be a direct output of the position encoding or a separate small head. To be implementable based strictly on the text "The MLP uses 4 hidden layers... for RGB", we follow the RGB path for the main MLP and note the density path as shown in the diagram [S1].
4.  **Position MLP:** Pass $\mathbf{e}_x$ through 4 fully-connected layers with 256 units and ReLU activation.
    *   $h_1 = \text{ReLU}(\text{FC}_1(\mathbf{e}_x))$
    *   $h_2 = \text{ReLU}(\text{FC}_2(h_1))$
    *   $h_3 = \text{ReLU}(\text{FC}_3(h_2))$
    *   $h_4 = \text{ReLU}(\text{FC}_4(h_3))$
5.  **Concatenate Direction:** Concatenate the encoded direction $\mathbf{e}_d$ to the feature vector $h_4$.
    *   $h_{cat} = \text{concat}(h_4, \mathbf{e}_d)$
6.  **Color MLP:** Pass $h_{cat}$ through a final fully-connected layer with 128 units.
    *   $h_{out} = \text{FC}_{out}(h_{cat})$
7.  **Output Color:** Apply Sigmoid activation to produce RGB.
    *   $\mathbf{c} = \text{Sigmoid}(h_{out})$

**Edge Cases and Pitfalls:**
*   **Input Dimension Mismatch:** The source diagram [S1] specifies an input size of 96 for position encoding, which does not match the standard NeRF positional encoding output for common frequency counts (e.g., L=10 yields 63). Implementers must verify the exact number of frequency bands $L$ used to achieve 96 dimensions or pad/truncate the encoding [S1].
*   **Density Output:** The source diagram [S1] shows $\sigma$ branching from the position encoding, but the text focuses on the RGB MLP. The exact computation for $\sigma$ is not detailed in the text [S1].
*   **Final Layer Projection:** The text states the final layer has 128 channels and produces RGB via Sigmoid. Since RGB is 3-dimensional, a projection from 128 to 3 is implied but not explicitly described in the text [S1].
