# NeRF with Time Parameter

Also called: NeRF + time, NeRF with Time Parameter Baseline, Time-NeRF

## Overview
This method adapts the standard Neural Radiance Field (NeRF) architecture [Parent](3065-nerf-hyperparameters.md) to handle dynamic scenes by introducing a temporal coordinate $t$ as an additional input to the neural network [S1]. It solves the problem of static scene representation in video sequences by allowing the density and color fields to vary over time [S1]. Unlike sibling methods that use explicit deformation fields or particle systems, this approach relies solely on input expansion, treating time as a direct coordinate alongside spatial position and view direction [S1]. While it improves reconstruction quality over vanilla NeRF for dynamic content, it is limited by its inability to explicitly model scene dynamics, often resulting in blurry predictions and ghosting artifacts [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A 4D query tuple $(\mathbf{x}, \mathbf{d}, t)$, where $\mathbf{x} \in \mathbb{R}^3$ is the spatial position, $\mathbf{d} \in \mathbb{R}^3$ is the view direction, and $t \in \mathbb{R}$ is the time coordinate [S1].
*   **Outputs:** Volume density $\sigma$ and view-dependent color $\mathbf{c}$ [S1].

**Data Structures:**
The method uses the standard Multi-Layer Perceptron (MLP) architecture defined in the parent article [Parent](3065-nerf-hyperparameters.md). The primary modification is the input layer size. If the spatial and directional positional encodings result in a vector of dimension $D_{spatial}$, the time encoding adds $D_{time}$ dimensions. The total input dimension to the first layer is $D_{total} = D_{spatial} + D_{time}$ [S1].

**Positional Encoding:**
The time parameter $t$ is processed using the same positional encoding function $\gamma$ as the spatial coordinates [S1].
1.  Compute spatial positional encoding: $\gamma_{\mathbf{x}}(\mathbf{x})$ [S1].
2.  Compute time positional encoding: $\gamma_{t}(t)$ [S1].
3.  Concatenate the encodings: $\mathbf{z} = [\gamma_{\mathbf{x}}(\mathbf{x}), \gamma_{t}(t)]$ [S1].
4.  The view direction $\mathbf{d}$ is typically encoded separately and concatenated later in the network (as per standard NeRF [Parent](3065-nerf-hyperparameters.md)), but the time component is fused with the spatial component at the input [S1].

**Rendering Equation:**
The volume rendering equation is adapted to include time $t$ [Parent](15546-dynamic-scene-and-temporal-modeling.md):
$$
C(\mathbf{r}, t) = \int_{s_n}^{s_f} T(s, t) \sigma(\mathbf{r}(s), t) \mathbf{c}(\mathbf{r}(s), \mathbf{d}, t) ds
$$
where $\mathbf{r}(s) = \mathbf{o} + s\mathbf{d}$ is the ray equation, and $\sigma$ and $\mathbf{c}$ are now functions of space, view direction, and time [Parent](15546-dynamic-scene-and-temporal-modeling.md).

**Training Procedure:**
1.  **Data Preparation:** Collect image sequences with known camera poses and timestamps $t$ [S1].
2.  **Model Initialization:** Initialize the NeRF MLP [S1].
3.  **Forward Pass:** For each pixel, sample points along the ray. For each point $\mathbf{x}$, retrieve its timestamp $t$ from the corresponding frame [S1].
4.  **Encoding:** Apply positional encoding to $\mathbf{x}$ and $t$, and concatenate them [S1].
5.  **Network Evaluation:** Pass the concatenated vector through the MLP to predict $\sigma$ and $\mathbf{c}$ [S1].
6.  **Rendering:** Compute the pixel color $C(\mathbf{r}, t)$ using the time-aware volume rendering integral [Parent](15546-dynamic-scene-and-temporal-modeling.md).
7.  **Loss Calculation:** Compare rendered colors against ground truth images for the corresponding time $t$ [S1].
8.  **Optimization:** Update network weights using gradient descent [S1].

**Parameters:**
*   **Training Configuration:** The method is trained using the configuration reported for NeRF's real forward-facing experiments [S1]. Specific hyperparameters (learning rate, number of samples per ray, etc.) are not detailed in the sources beyond this reference [S1].

**Edge Cases and Pitfalls:**
*   **Blurriness:** The method suffers from blurry predictions because it lacks an explicit mechanism to reason about scene dynamics [S1].
*   **Ghosting:** Even with the time parameter, small changes in camera pose can lead to slightly different viewing directions for spatial points across frames, causing severe ghosting artifacts [S1].
*   **Detail Loss:** It fails to capture fine details in complex dynamic scenes compared to methods that explicitly model motion [S1].

## Subtopics

### Temporal Compression of NeRF Models
A compression strategy for sequences of NeRF models that exploits temporal redundancy by treating the first model as a key-frame and compressing only the deltas between successive models [S2].
*   **Definition:** It reduces storage requirements by leveraging the similarity between neighboring NeRF models in a video sequence [S2].
*   **Steps:**
    1.  Initialize the NeRF for the first frame from scratch [S2].
    2.  For subsequent frames, initialize the new NeRF based on the previous frame's trained NeRF weights to encourage temporal redundancy and save training time [S2].
    3.  Calculate the delta between the current frame's NeRF weights and the previous frame's NeRF weights [S2].
    4.  Apply exponent-based quantization and Huffman coding to the deltas [S2].
    5.  To restore a model, accumulate the decoded deltas to the reference model (the previous frame's model) [S2].
*   **When to choose:** Use when storage or transmission bandwidth is constrained and the scene exhibits high temporal coherence [S2].

## Operating characteristics
*   **Time Complexity:** Training time is comparable to standard NeRF per frame, but initialization from previous frames can reduce convergence time for subsequent frames [S2]. Rendering time is identical to standard NeRF, scaled by the number of samples [S1].
*   **Memory Complexity:** Memory usage is proportional to the size of the MLP. Compression variants reduce storage size by storing only deltas [S2].
*   **Measured Performance:** On KITTI dataset scenes, "NeRF + time" achieves a PSNR of 24.18, SSIM of 0.677, and LPIPS of 0.425, which is an improvement over vanilla NeRF (PSNR 23.34, SSIM 0.662, LPIPS 0.415) but significantly worse than methods explicitly modeling dynamics like Neural Scene Graphs (PSNR 26.66, SSIM 0.806, LPIPS 0.186) [S1].
*   **Strengths:** Simple to implement; requires no modification to the core NeRF architecture other than input concatenation [S1].
*   **Limitations:** Cannot explicitly model motion; results in blurry images and ghosting artifacts in dynamic scenes [S1].
*   **When to use:** As a baseline for dynamic scene reconstruction; when computational resources for complex deformation models are unavailable [S1].
*   **When not:** When high-fidelity detail and sharp boundaries are required in dynamic scenes [S1].

## Background
The method was introduced as a baseline modification to demonstrate the limitations of simple input expansion for dynamic scenes [S1]. It was proposed in the paper "Neural Scene Graphs for Dynamic Scenes" by Yuang Shi et al. [S1]. The authors noted that while adding a time parameter improves quality over vanilla NeRF, it is insufficient for complex dynamics [S1]. The concept of temporal compression for NeRF models was later explored in "Volumetric Video Compression Through Neural-based Representation" [S2].
