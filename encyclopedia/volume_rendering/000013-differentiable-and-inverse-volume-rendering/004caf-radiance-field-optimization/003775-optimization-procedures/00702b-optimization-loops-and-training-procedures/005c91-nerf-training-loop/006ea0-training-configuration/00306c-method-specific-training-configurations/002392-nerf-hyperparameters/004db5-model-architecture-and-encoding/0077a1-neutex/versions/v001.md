# NeuTex

Also called: Neural Texture Mapping

## Overview
NeuTex is a neural scene representation that explicitly disentangles scene geometry from appearance by representing geometry as a continuous 3D volume and appearance as a continuous 2D texture map in an automatically discovered UV space [S1]. Unlike standard NeRF, which uses a single MLP to bake both density and radiance into a 3D volume, NeuTex uses three separate MLPs for geometry, texture mapping, and texture, enabling disentangled modeling and texture editing [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Multi-view images of a scene, camera poses, and optionally a coarse point cloud for initialization.
*   **Outputs:** A rendered image for a given camera pose, and a 2D neural texture map representing the scene's appearance.

**Data Structures:**
The method relies on four Multi-Layer Perceptrons (MLPs):
1.  **Geometry Network ($F_\sigma$):** Maps 3D position $\mathbf{x}$ to volume density $\sigma$.
2.  **Texture Mapping Network ($F_{\mathbf{uv}}$):** Maps 3D position $\mathbf{x}$ to 2D UV coordinates $\mathbf{u}$.
3.  **Texture Network ($F_{\text{tex}}$):** Maps 2D UV coordinates $\mathbf{u}$ and view direction $\mathbf{d}$ to radiance $\mathbf{c}$.
4.  **Inverse Texture Mapping Network ($F_{\mathbf{uv}}^{-1}$):** Maps 2D UV coordinates $\mathbf{u}$ back to 3D position $\mathbf{x}$.

**Positional Encoding:**
Following the parent article [Model Architecture and Encoding](13550-model-architecture-and-encoding.md), inputs to the geometry and texture networks use hierarchical sinusoidal positional encoding [S1]. However, the texture mapping networks ($F_{\mathbf{uv}}$ and $F_{\mathbf{uv}}^{-1}$) do **not** use positional encoding, as the mapping is expected to be smooth and uniform [S1].

**Numbered Steps:**

1.  **Initialization:**
    *   Normalize the scene space to a unit box.
    *   Initialize the inverse mapping network $F_{\mathbf{uv}}^{-1}$ using a coarse point cloud (e.g., from COLMAP) by minimizing a Chamfer loss [S1].
    *   Initialize other networks randomly or with standard NeRF weights [G].

2.  **Ray Sampling:**
    *   For each pixel in a batch, generate a ray $r(\lambda) = o + \lambda d$.
    *   Sample $N=256$ shading points along the ray within the unit box using stratified sampling [S1].

3.  **Forward Pass (Rendering):**
    *   For each shading point $\mathbf{x}_i$ on the ray:
        *   Compute density: $\sigma_i = F_\sigma(\mathbf{x}_i)$.
        *   Compute UV coordinate: $\mathbf{u}_i = F_{\mathbf{uv}}(\mathbf{x}_i)$.
        *   Compute radiance: $\mathbf{c}_i = F_{\text{tex}}(\mathbf{u}_i, \mathbf{d})$.
    *   Compute transmittance $T_i$ and contribution weights $w_i$:
        $$ T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right) $$
        $$ w_i = T_i (1 - \exp(-\sigma_i \delta_i)) $$
    *   Render pixel color:
        $$ \mathbf{I} = \sum_i w_i \mathbf{c}_i $$

4.  **Cycle Consistency Check:**
    *   For shading points with high contribution weights (near the surface), map their UV coordinates back to 3D space:
        $$ \mathbf{x}'_i = F_{\mathbf{uv}}^{-1}(\mathbf{u}_i) = F_{\mathbf{uv}}^{-1}(F_{\mathbf{uv}}(\mathbf{x}_i)) $$

5.  **Loss Calculation:**
    *   **Rendering Loss:** $L_{\text{render}} = \|\mathbf{I}_{\text{gt}} - \mathbf{I}\|_2^2$ [S1].
    *   **Cycle Loss:** Weighted by radiance contribution to focus on surface points:
        $$ L_{\text{cycle}} = \sum_i w_i \| \mathbf{x}'_i - \mathbf{x}_i \|_2^2 $$
    *   **Mask Loss:** Supervises foreground/background using the transmittance of the last point $T_N$:
        $$ L_{\text{mask}} = \| M_{\text{gt}} - (1 - T_N) \|_2^2 $$
    *   **Total Loss:**
        $$ L = L_{\text{render}} + a_1 L_{\text{cycle}} + a_2 L_{\text{mask}} $$
        Where $a_1 = 1$ and $a_2 = 1$ (or $0$ if view coverage is dense) [S1].

6.  **Optimization:**
    *   **Phase 1:** Train with Chamfer loss (on $F_{\mathbf{uv}}^{-1}$) and Rendering loss for 50,000 iterations [S1].
    *   **Phase 2:** Remove Chamfer loss. Train with full loss ($L_{\text{render}} + L_{\text{cycle}} + L_{\text{mask}}$) for ~500,000 iterations [S1].
    *   **Phase 3:** Fine-tune $F_{\text{tex}}$ while freezing $F_\sigma$, $F_{\mathbf{uv}}$, and $F_{\mathbf{uv}}^{-1}$ to improve texture details [S1].

```python
import torch.nn as nn
import torch.nn.functional as F

class NeuTex:

        self.F_sigma = GeometryMLP()
        self.F_uv = TextureMappingMLP()
        self.F_tex = TextureMLP()
        self.F_uv_inv = InverseTextureMappingMLP()

        self.a1 = 1.0
        self.a2 = 1.0 # Set to 0 if view coverage is dense
        self.num_samples = 256
        self.batch_size = 600 # Pixels per batch
        
    def positional_encoding(self, x, L=10):

    def forward(self, rays_o, rays_d, gt_images, gt_masks=None):
        """
        rays_o: [B, 3] ray origins
        rays_d: [B, 3] ray directions
        gt_images: [B, H, W, 3] ground truth images
        gt_masks: [B, H, W] ground truth masks (optional)
        """
        B, H, W = gt_images.shape[:3]
        # Flatten rays to batch of pixels
        rays_o = rays_o.unsqueeze(1).expand(-1, H, W, -1).reshape(-1, 3)
        rays_d = rays_d.unsqueeze(1).expand(-1, H, W, -1).reshape(-1, 3)
        
        # Stratified sampling along rays within unit box
        # Returns points [B*H*W, N, 3]
        points = stratified_sample(rays_o, rays_d, self.num_samples)
        
        # 1. Geometry
        # Apply positional encoding to 3D points
        points_pe = self.positional_encoding(points)
        sigma = self.F_sigma(points_pe) # [B*H*W, N, 1]
        
        # 2. Texture Mapping
        # No positional encoding for UV mapping
        uv = self.F_uv(points) # [B*H*W, N, 2]
        
        # 3. Texture
        # View direction is constant per ray, broadcast to points
        rays_d_expanded = rays_d.unsqueeze(1).expand(-1, self.num_samples, -1)
        # Apply positional encoding to view direction
        rays_d_pe = self.positional_encoding(rays_d_expanded, L=4)
        
        # Concatenate UV and view direction features? 
        # Note: F_tex takes (u, d). The source says F_tex(u, d). 
        # Usually d is also encoded.
        c = self.F_tex(uv, rays_d_pe) # [B*H*W, N, 3]
        
        # 4. Rendering
        # Compute transmittance and weights
        # delta is distance between samples. Assume uniform or compute from points.
        # For simplicity, assume uniform delta or compute from points.
        # Let's assume points are sorted and we can compute deltas.
        # [G] Standard NeRF ray marching logic.
        deltas = compute_deltas(points) # [B*H*W, N]
        alpha = 1.0 - torch.exp(-sigma * deltas) # [B*H*W, N]
        T = torch.cumprod(1.0 - alpha + 1e-10, dim=1) # [B*H*W, N]
        T = torch.cat([torch.ones_like(T[:, :1]), T[:, :-1]], dim=1) # Shift for T_i
        weights = T * alpha # [B*H*W, N]
        
        rendered_color = torch.sum(weights.unsqueeze(-1) * c, dim=1) # [B*H*W, 3]
        
        # Reshape to image
        rendered_image = rendered_color.reshape(B, H, W, 3)
        
        # 5. Cycle Loss
        # Map UV back to 3D
        points_inv = self.F_uv_inv(uv) # [B*H*W, N, 3]
        
        # Weighted cycle loss
        # Only consider points with significant contribution
        cycle_loss = torch.mean(weights * torch.sum((points_inv - points)**2, dim=-1))
        
        # 6. Mask Loss
        mask_loss = 0.0
        if gt_masks is not None:
            # Transmittance of the last point indicates background
            T_last = T[:, -1] # [B*H*W]
            # (1 - T_N) is the foreground mask
            foreground_pred = 1.0 - T_last
            foreground_pred = foreground_pred.reshape(B, H, W)
            mask_loss = torch.mean((gt_masks - foreground_pred)**2)
            
        # 7. Rendering Loss
        render_loss = torch.mean((gt_images - rendered_image)**2)
        
        total_loss = render_loss + self.a1 * cycle_loss + self.a2 * mask_loss
        
        return rendered_image, total_loss, cycle_loss, mask_loss

    def train_step(self, rays_o, rays_d, gt_images, gt_masks):
        self.optimizer.zero_grad()
        rendered_image, total_loss, cycle_loss, mask_loss = self.forward(rays_o, rays_d, gt_images, gt_masks)
        total_loss.backward()
        self.optimizer.step()
        return total_loss.item()
```

**Parameters:**
*   $a_1$ (Cycle loss weight): 1 [S1].
*   $a_2$ (Mask loss weight): 1 for most scenes, 0 for scenes with good view coverage [S1].
*   Number of shading points per ray: 256 [S1].
*   Batch size: 600-800 pixels [S1].
*   Training iterations: 50,000 (Chamfer + Render) + 500,000 (Full loss) + Fine-tuning [S1].

**Edge Cases and Pitfalls:**
*   **Degenerate Mapping:** Naively adding a texture mapping network and supervising only with rendering loss leads to a degenerate texture mapping that does not unwrap the surface [S1].
*   **Empty Space Cycle Loss:** Enforcing cycle mapping in empty space is meaningless; it must be weighted by radiance contribution [S1].
*   **Mask Loss Necessity:** Mask loss is necessary when viewpoints do not cover the object entirely to prevent the network from faking shading effects via volume density [S1].

## Operating characteristics
*   **Time Complexity:** Training is computationally intensive, taking 2-3 days on a single RTX 2080Ti GPU for convergence [S1].
*   **Memory Complexity:** Depends on batch size (600-800 pixels) and number of samples (256). Four MLPs must be stored in memory.
*   **Performance:** On DTU scenes, NeuTex achieves a PSNR of 28.23 and SSIM of 0.894, which is lower than NeRF (30.73 PSNR, 0.938 SSIM) but enables texture editing [S1].
*   **Strengths:** Disentangled geometry and appearance; enables 2D texture editing; discovers more uniform surface parameterization than AtlasNet [S1].
*   **Limitations:** Lower rendering quality (PSNR/SSIM) compared to standard NeRF; requires careful initialization of the inverse mapping network [S1].

## Background
NeuTex was introduced by Xiang et al. in 2021 [S1]. It builds on the NeRF framework [S1] to address the limitation of "black-box" volumetric representations that cannot be edited. The method was developed while F. Xiang was an intern at Adobe Research [S1].
