# Panoptic Radiance Field

Also called: Panoptic Lifting

## Overview
Panoptic Lifting learns a panoptic 3D volumetric representation from posed RGB images and machine-generated 2D panoptic segmentation masks, lifting noisy 2D labels into a consistent 3D representation comprising color, density, semantics, and instances [S1]. It differs from siblings like [Panoptic NeRF](13622-panoptic-nerf.md) and [DM-NeRF](13622-dm-nerf.md) by requiring only machine-generated 2D labels rather than manual ground truth or coarse meshes, and employs specific robustness mechanisms (bounded fields, gradient blocking) to handle label noise [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   Posed RGB images $\{I\}$ of a scene.
*   Machine-generated 2D panoptic segmentation masks for each image, inferred from a pre-trained network (e.g., Mask2Former) [S1].
*   Rays $r$ parameterized as $r = p_0 + t d_r$, where $p_0$ is the ray origin, $d_r$ is the unit direction, and $t$ is a scalar [S1].
*   For training rays belonging to image $I$: associated RGB color $\hat{c}_r \in \mathbb{R}^3$, semantic class $\hat{k}_r \in K$, and 2D instance ID $\hat{h}_r \in H_I$ (defined only if $\hat{k}_r \in K_T$, where $K_T$ is the set of "thing" classes) [S1].

**Outputs:**
*   A panoptic radiance field $\Phi(x, d)$ that assigns to each 3D point $x \in \mathbb{R}^3$ and viewing direction $d \in S^2$:
    *   Density $\sigma \in \mathbb{R}_{\ge 0}$.
    *   Semantic class distribution $\kappa$ over classes $K$.
    *   Distribution $\pi$ over surrogate identifiers $J$.
    *   RGB color $c \in \mathbb{R}^3$ [S1].
*   Rendered color, depth, semantic class distribution, and 3D-consistent instance identifiers for novel views [S1].

### Data Structures
The neural field representation comprises four components [S1]:
1.  **Color and Density:** Leverage TensoRF [4] representation (tensor decomposition of lines and planes).
2.  **Semantic Field:** A small Multi-Layer Perceptron (MLP) outputting a probability distribution over $K$ classes.
3.  **Instance Field:** A separate small MLP outputting a distribution over a fixed number of class-agnostic surrogate identifiers $J$ [S1].
4.  **Surrogate Identifiers:** A fixed set $J$ of identifiers held by the instance field MLP [S1].

The set of all possible 3D instances is defined as $H_{3D} := K_T \times J$ [S1].

### Training Procedure

#### 1. Confidence Estimation via Test-Time Augmentation
To handle noisy 2D labels, test-time augmentations (horizontal flip, scale, brightness, contrast) are applied to input images. The resulting segmentations are fused by segment clustering to obtain a semantic class distribution $\hat{\kappa}_r$ and a confidence estimate $w_r$ for each pixel (ray $r$) [S1].

#### 2. Linear Assignment for Instance Mapping
To account for inconsistencies of 2D instance identifiers across views, a linear assignment problem is solved. The cost is based on the model’s current predictions and the machine-generated segmentation masks. This maps each 2D instance $\hat{h}_r$ to a 3D surrogate identifier via an injective mapping $\Pi^*_R$ [S1].

#### 3. Loss Functions
The total training loss is defined over a batch of rays $R = R_S \cup R_I$, where $R_S$ are rays randomly sampled across the scene and $R_I$ are rays sampled from a single image [S1]:

$$ L_{tot}(R) := \lambda_{ins} L_{ins}(R_I) + \lambda_{con} L_{con}(R_I) + \lambda_{RGB} L_{RGB}(R_S) + \lambda_{sem} L_{sem}(R_S) $$

Typical loss weights are $\lambda_{con} = 1.35$, $\lambda_{ins} = 1$, $\lambda_{sem} = 1$, $\lambda_{RGB} = 1$ [S1].

*   **Photometric Loss ($L_{RGB}$):** Standard L2 loss between rendered color $c_r$ and ground truth $\hat{c}_r$ [S1].
*   **Semantic Loss ($L_{sem}$):** Cross-entropy between the rendered semantic distribution $\kappa_r$ and the augmented label distribution $\hat{\kappa}_r$, weighted by confidence $w_r$ [S1]:
    $$ L_{sem}(R) := -\frac{1}{|R|} \sum_{r \in R} w_r \sum_{k \in K} \hat{\kappa}_r(k) \log \kappa_r(k) $$
*   **Instance Loss ($L_{ins}$):** Minimizes the log-loss of the co-occurrence of the mapped 2D instance and the rendered surrogate identifier distribution $\pi_r$ [S1].
*   **Segment Consistency Loss ($L_{con}$):** Guides semantic supervision to avoid optima that fragment objects in the presence of label inconsistencies [S1].

#### 4. Rendering Equation
For a vector field $f$ along ray $r$ given density field $\sigma$, the rendered value is [S1]:

$$ R[f | r, \sigma] := \int_0^\infty \alpha_t(r) \sigma(r_t) f(r_t, d_{r_t}) dt $$

where $\alpha_t(r) := \exp \left(-\int_0^t \sigma(r_s) ds\right)$ is the transmittance probability at $t$ [S1].

#### 5. Novel View Inference
For a pixel from a novel view corresponding to ray $r$:
1.  Compute rendered semantic class distribution $\kappa_r$.
2.  Obtain semantic class $k^*_r := \arg \max_{k \in K} \kappa_r(k)$.
3.  If $k^*_r$ is a thing class, compute most probable surrogate identifier $j^*_r := \arg \max_{j \in J} \pi_r(j)$.
4.  Form unique 3D instance identifier $(k^*_r, j^*_r) \in H_{3D}$ [S1].

### Pseudocode

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class PanopticRadianceField:
    """
    Implements Panoptic Lifting.
    Assumes TensoRF backbone for density/color is initialized.
    """
    def __init__(self, num_surrogates, num_classes, learning_rate_mlp=5e-4, learning_rate_tenor=1e-2):
        self.num_surrogates = num_surrogates
        self.num_classes = num_classes
        self.K_T = set(range(0, 91)) # Example: COCO thing classes, adjust as needed
        self.K_S = set(range(91, 133)) # Example: COCO stuff classes
        
        # TensoRF components for density and color (simplified placeholder for TensoRF structure)
        self.tenor_density = TensoRFBackbone() 
        self.tenor_color = TensoRFBackbone()
        
        # Small MLPs for semantic and instance fields
        self.semantic_mlp = nn.Sequential(
            nn.Linear(256, 128), # Input size depends on TensoRF feature dim
            nn.ReLU(),
            nn.Linear(128, num_classes)
        )
        self.instance_mlp = nn.Sequential(
            nn.Linear(256, 128),
            nn.ReLU(),
            nn.Linear(128, num_surrogates)
        )
        
        # Optimizer setup
        # TensoRF params use higher LR, MLPs use lower LR
        optimizer_params = list(self.tenor_density.parameters()) + list(self.tenor_color.parameters())
        mlp_params = list(self.semantic_mlp.parameters()) + list(self.instance_mlp.parameters())
        
        self.optimizer = torch.optim.Adam([
            {'params': optimizer_params, 'lr': learning_rate_tenor},
            {'params': mlp_params, 'lr': learning_rate_mlp}
        ])
        
        # Loss weights
        self.lambda_ins = 1.0
        self.lambda_con = 1.35
        self.lambda_rgb = 1.0
        self.lambda_sem = 1.0

    def forward(self, x, d):
        """
        Query the radiance field at point x with direction d.
        Returns: sigma, c, kappa (semantic probs), pi (instance probs)
        """
        # Get features from TensoRF backbone
        # Note: TensoRF implementation details are abstracted here as per standard usage
        # In practice, this involves querying 1D lines and 2D planes
        features = self.tenor_density.get_features(x) 
        
        # Density
        sigma = self.tenor_density.get_density(x)
        sigma = torch.clamp(sigma, min=0) # Ensure non-negative density
        
        # Color
        c = self.tenor_color.get_color(x, d)
        
        # Semantic and Instance fields use the bottleneck features
        # Assuming features are passed to the small MLPs
        # Note: The source mentions "small MLPs", implying they take the same or similar features
        # as the color/density networks or a shared feature vector.
        
        # Semantic output (logits)
        sem_logits = self.semantic_mlp(features)
        # Bounded probability distribution: use sigmoid for multi-label or softmax for single-label?
        # Source says "bounded probability distribution" and "cross entropy", implying softmax over classes.
        # However, standard semantic segmentation often uses softmax. 
        # Source explicitly contrasts with "rendering class logits... converting via softmax".
        # It says "resolve this by instead rendering the bounded probability distribution".
        # This implies the MLP output IS the probability distribution, or uses a bounded activation.
        # Given "cross entropy of kappa_r relative to kappa_hat", and kappa_hat is a distribution,
        # we assume the MLP outputs logits and we apply Softmax, BUT the source warns against unbounded logits.
        # The resolution "bounded probability distribution" likely means using a specific activation 
        # or clamping, or simply that the output is treated as probabilities directly if the network is small.
        # Standard interpretation of "bounded segmentation fields" in this context (Panoptic Lifting paper):
        # They likely use a Softmax but the "bounded" refers to the fact that they are probabilities 
        # integrated over density, OR they clamp the logits. 
        # Re-reading: "Standard implementations... render class logits... converting... via softmax. 
        # This approach can potentially introduce semantic inconsistencies... We resolve this by instead 
        # rendering the bounded probability distribution."
        # This suggests the MLP outputs probabilities directly (e.g., via Softmax inside the head) 
        # rather than raw logits that are then softmaxed. Or it means the rendering equation integrates 
        # the probabilities weighted by density, which is standard. 
        # The key is "bounded". Logits are unbounded. Probabilities are bounded [0,1].
        # So, we apply Softmax to the logits to get kappa.
        kappa = F.softmax(sem_logits, dim=-1)
        
        # Instance output
        inst_logits = self.instance_mlp(features)
        pi = F.softmax(inst_logits, dim=-1)
        
        return sigma, c, kappa, pi

    def render_ray(self, ray_origins, ray_directions, sigma, kappa, pi, t_near, t_far, num_samples):
        """
        Volumetric rendering along rays.
        """
        # Sample points along the ray
        t_vals = torch.linspace(t_near, t_far, num_samples)
        points = ray_origins.unsqueeze(1) + t_vals.unsqueeze(0) * ray_directions.unsqueeze(1)
        
        # Get sigma, kappa, pi at these points (forward pass)
        # Note: In practice, this is done via a single forward pass or pre-computed grid
        # Here we assume sigma, kappa, pi are already computed for the points
        # or we query them. For the formula, we assume we have the values.
        
        # Transmittance
        # alpha_t(r) = exp(-int_0^t sigma(r_s) ds)
        # Discrete approximation:
        deltas = t_vals[1:] - t_vals[:-1]
        # Add epsilon to avoid division by zero in exp
        deltas = torch.cat([deltas, torch.ones_like(deltas[:1]) * 1e-10])
        
        # Density at sample points
        # sigma is shape (num_rays, num_samples)
        sigma_deltas = sigma * deltas
        
        # Transmittance T_t = exp(-sum_{i<t} sigma_i * delta_i)
        # Cumulative sum from the back
        exp_neg_sigma_delta = torch.exp(-sigma_deltas)
        alpha = 1.0 - exp_neg_sigma_delta
        T = torch.cumprod(exp_neg_sigma_delta, dim=1)
        T = torch.cat([torch.ones_like(T[:, :1]), T[:, :-1]], dim=1)
        
        # Rendered Color
        # R[c] = sum alpha_t * sigma_t * c_t
        # Note: The formula in source is R[f] = int alpha_t sigma_t f dt.
        # In discrete form: sum (T_t * alpha_t * c_t) ? 
        # Standard NeRF: C(r) = sum T_t * (1 - exp(-sigma_t * delta_t)) * c_t
        # Which is sum T_t * alpha_t * c_t if alpha_t is defined as 1 - exp(-sigma delta).
        # Source formula: alpha_t(r) = exp(-int sigma). This is transmittance T(t).
        # The integrand is alpha_t * sigma * f.
        # So rendered value = sum T_t * sigma_t * delta_t * f_t.
        
        weights = T * (1.0 - exp_neg_sigma_delta) # T_t * alpha_t
        weights_sum = torch.sum(weights, dim=1, keepdim=True)
        weights = weights / (weights_sum + 1e-10) # Normalize if needed, but standard NeRF doesn't normalize weights for color
        
        # Render Color
        # c is shape (num_rays, num_samples, 3)
        rendered_color = torch.sum(weights.unsqueeze(-1) * c, dim=1)
        
        # Render Semantic Distribution
        # kappa is shape (num_rays, num_samples, num_classes)
        rendered_kappa = torch.sum(weights.unsqueeze(-1) * kappa, dim=1)
        
        # Render Instance Distribution
        # pi is shape (num_rays, num_samples, num_surrogates)
        rendered_pi = torch.sum(weights.unsqueeze(-1) * pi, dim=1)
        
        return rendered_color, rendered_kappa, rendered_pi

    def compute_loss(self, rendered_color, rendered_kappa, rendered_pi, 
                     gt_color, gt_kappa_dist, gt_confidence, gt_instance_ids, 
                     current_instance_predictions, ray_indices):
        """
        Computes the total loss.
        """
        # 1. Photometric Loss (L_RGB)
        # Sampled from R_S (randomly across scene)
        # Assuming the inputs passed here are from R_S for RGB
        loss_rgb = F.mse_loss(rendered_color, gt_color)
        
        # 2. Semantic Loss (L_sem)
        # Sampled from R_S
        # Cross entropy between rendered distribution and augmented label distribution
        # weighted by confidence
        # gt_kappa_dist is the distribution kappa_hat_r
        # gt_confidence is w_r
        # rendered_kappa is kappa_r
        log_probs = torch.log(rendered_kappa + 1e-10)
        # Weighted cross entropy
        loss_sem = -torch.mean(gt_confidence * torch.sum(gt_kappa_dist * log_probs, dim=-1))
        
        # 3. Instance Loss (L_ins) and Consistency Loss (L_con)
        # Sampled from R_I (single image)
        # Requires linear assignment to map 2D instance IDs to 3D surrogates
        # This mapping is done externally or as part of the training step
        # Let's assume mapped_ids are provided
        # loss_ins minimizes log-loss of co-occurrence
        # loss_con guides semantic supervision
        
        # Placeholder for Instance Loss logic based on linear assignment
        # L_ins = - sum log(pi_r[j_mapped])
        # L_con = consistency term
        
        # For the purpose of this pseudocode, we assume these losses are computed
        # based on the mapped surrogate identifiers.
        loss_ins = 0.0 # Placeholder: Implement log-loss against mapped surrogates
        loss_con = 0.0 # Placeholder: Implement segment consistency loss
        
        total_loss = (self.lambda_ins * loss_ins + 
                      self.lambda_con * loss_con + 
                      self.lambda_rgb * loss_rgb + 
                      self.lambda_sem * loss_sem)
        
        return total_loss

    def train_step(self, rays_R_S, rays_R_I, gt_data_R_S, gt_data_R_I):
        """
        One training step.
        """
        self.optimizer.zero_grad()
        
        # Forward pass for R_S (RGB, Semantic)
        # rays_R_S contains origins, directions, and associated gt_color, gt_kappa, gt_conf
        sigma_S, c_S, kappa_S, pi_S = self.forward(rays_R_S.origins, rays_R_S.directions)
        rendered_color_S, rendered_kappa_S, _ = self.render_ray(...) # Simplified
        
        # Forward pass for R_I (Instance)
        sigma_I, c_I, kappa_I, pi_I = self.forward(rays_R_I.origins, rays_R_I.directions)
        rendered_pi_I = ... # Render instance distribution
        
        # Compute Losses
        # Note: Gradient blocking from segmentation branches to geometry
        # This is implemented by detaching sigma or the features used for sigma 
        # from the semantic/instance branches, or by stopping gradients in the loss computation.
        # Source: "stop gradients from the segmentation branches back to the densities"
        # Implementation: Ensure the semantic/instance MLPs do not receive gradients 
        # that flow back to the TensoRF density parameters.
        
        loss = self.compute_loss(rendered_color_S, rendered_kappa_S, rendered_pi_I, ...)
        
        loss.backward()
        self.optimizer.step()
        
        return loss.item()
```

### Parameters
*   **K**: Set of semantic classes, partitioned into thing classes $K_T$ and stuff classes $K_S$ [S1].
*   **J**: Set of surrogate identifiers. Fixed number held by the instance field MLP [S1].
*   **Optimizer**: Adam [S1].
*   **Learning Rates**: $5 \times 10^{-4}$ for MLPs, $1 \times 10^{-2}$ for TensoRF lines and planes [S1].
*   **Loss Weights**: $\lambda_{con} = 1.35$, $\lambda_{ins} = 1$, $\lambda_{sem} = 1$, $\lambda_{RGB} = 1$ [S1].
*   **Hardware**: 1 NVIDIA A6000 [S1].
*   **Duration**: 450k iterations (~10 hours) [S1].

### Edge Cases and Pitfalls
*   **Semantic Inconsistencies from Unbounded Logits:** Rendering class logits instead of probabilities can introduce semantic inconsistencies across viewpoints because unbounded logits can generate significant signals in low-density areas, violating geometric constraints. This is resolved by rendering bounded probability distributions (e.g., using Softmax directly in the output head) [S1].
*   **Cloudy Geometry from Noisy Labels:** Supervision from noisy 2D labels can influence geometry, causing the model to create "cloudy" geometry to satisfy conflicting labels. This is avoided by stopping gradients from the semantic and instance branches back to the density network [S1].
*   **Label Noise:** Machine-generated labels are noisy and inconsistent across views. The method uses test-time augmentations and linear assignment to mitigate this [S1].
*   **Class Limitations:** The method is limited to classes supported by the pre-trained 2D panoptic segmentation model (e.g., Mask2Former) [S1].
*   **Offline Processing:** The method runs offline due to lengthy pre-processing for pose estimation, 2D segmentation inference, and neural field optimization [S1].

## Operating characteristics

**Time and Memory Complexity:**
*   Training requires 450k iterations (~10 hours) on a single NVIDIA A6000 [S1].
*   Memory usage depends on the TensoRF resolution and the number of surrogate identifiers. Not given in the sources.

**Measured Performance:**
*   Improves scene-level Panoptic Quality (PQ) by 8.4% on Hypersim, 13.8% on Replica, and 10.6% on ScanNet over state-of-the-art methods [S1].
*   Maintains comparable PSNR for novel view synthesis compared to baselines [S1].
*   Outperforms Mask2Former, SemanticNeRF, DM-NeRF, and PNF on mIoU and PQ_scene across Hypersim, Replica, and ScanNet datasets [S1].

**Strengths and Limitations:**
*   **Strengths:** Robust to inherent noise in machine-generated labels; enables in-the-wild scene processing without manual ground truth; supports scene editing (deletion, duplication, manipulation) [S1].
*   **Limitations:** Limited to classes in the pre-trained 2D segmenter; offline processing; relies on accurate pose estimation [S1].

**When to Use:**
*   Use when only machine-generated 2D panoptic labels are available and manual annotation is not feasible.
*   Use when 3D-consistent panoptic segmentation and novel view synthesis are required.
*   Use for scene editing tasks involving instance manipulation [S1].

**When Not to Use:**
*   Use when real-time inference is required (method is offline) [S1].
*   Use when classes outside the pre-trained 2D model's vocabulary are needed [S1].

## Background

**Origin:**
Panoptic Lifting was introduced in the paper "Panoptic Lifting for 3D Scene Understanding with Neural Fields" (CVPR 2023) [S1].

**History and Development:**
The method builds upon NeRF and TensoRF architectures. It addresses the limitations of previous panoptic NeRF methods (like Panoptic NeRF and DM-NeRF) which required manual ground truth (coarse meshes or per-image 2D panoptic segmentations) [S1]. Panoptic Lifting was developed to enable robust panoptic 3D scene understanding from in-the-wild scenes using only machine-generated labels [S1].

**Usage:**
Evaluated on Hypersim, Replica, and ScanNet datasets. Uses Mask2Former with Swin-L backbone as the pre-trained 2D panoptic segmenter [S1].
