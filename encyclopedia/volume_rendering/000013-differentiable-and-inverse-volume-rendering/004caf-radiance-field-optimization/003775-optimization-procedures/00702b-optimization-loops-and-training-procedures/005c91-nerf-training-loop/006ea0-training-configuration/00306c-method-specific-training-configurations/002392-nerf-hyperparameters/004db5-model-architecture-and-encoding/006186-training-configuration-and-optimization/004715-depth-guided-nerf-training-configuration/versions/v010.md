# Depth-Guided NeRF Training Configuration

Also called: Depth-Guided NeRF Training

## Overview
This configuration defines the training protocol for Neural Radiance Fields (NeRF) that incorporate depth supervision to improve geometry reconstruction and training stability. It modifies the standard NeRF architecture by adding regularization and integrates a depth loss term into the optimization objective. It is distinguished from sibling methods by its specific use of Earth Mover’s Distance (EMD) for depth evaluation and a fixed dropout regularization scheme on the positional encoding layers, rather than architectural changes to the density/color networks themselves or alternative loss formulations like binary cross-entropy.

## How it works
The method builds on the standard NeRF [Parent](13550-model-architecture-and-encoding.md) framework, mapping 3D coordinates and viewing directions to density and color. The training process is modified to include depth priors.

**Inputs:**
*   Camera poses and intrinsics.
*   RGB images.
*   Ground truth depth maps (optional but required for the depth loss).
*   Scene-specific depth bounds ($min\_depth$, $max\_depth$).

**Outputs:**
*   Trained NeRF model parameters (MLP weights).
*   Rendered RGB images and depth maps.

**Data Structures:**
*   **NeRF Model:** Two Multi-Layer Perceptrons (MLPs) as defined in [Parent](13550-model-architecture-and-encoding.md).
    *   **Architecture Modification:** Dropout layers with probability $p=0.1$ are inserted after each of the first eight fully connected ReLU-activated layers in the positional encoding network.
*   **Optimizer State:** Adam optimizer state variables (first and second moment estimates).

**Parameters:**
*   Depth loss weight: $\lambda = 0.007$ for most scenes; $\lambda = 0.02$ for scene 710 [S1].
*   Uncertainty weight: $\gamma = 1$ [S1].
*   Optimizer: Adam [S1].
*   Initial learning rate: $5 \times 10^{-4}$ [S1].
*   Learning rate schedule: Reduce to $5 \times 10^{-5}$ after 80% of total steps [S1].
*   Weight decay: $1 \times 10^{-6}$ [S1].
*   Total training steps: 500,000 [S1].
*   Depth scale learning rate: $1 \times 10^{-7}$ [S1].
*   Depth threshold $\tau$: Computed per scene as $\tau = (max\_depth - min\_depth) \cdot 0.0001$ [S1]. For ScanNet, $max\_depth = 10$ and $min\_depth = 0.001$ [S1].

**Algorithm:**

1.  **Initialization:** Initialize NeRF MLPs. Initialize Adam optimizer with learning rate $5 \times 10^{-4}$ and weight decay $1 \times 10^{-6}$. Initialize depth scale parameter with learning rate $1 \times 10^{-7}$ [S1].
2.  **Sampling:** For each training step, sample a batch of rays. For each ray, sample points along the ray segment defined by near and far planes.
3.  **Forward Pass:**
    *   Encode spatial coordinates $\mathbf{x}$ and viewing directions $\mathbf{d}$ using positional encoding.
    *   Pass encoded features through the modified MLPs (with dropout $p=0.1$ on the first 8 FC layers of the encoding network) to predict volume density $\sigma$ and color $\mathbf{c}$ [S1].
    *   Compute the rendered color $\hat{C}$ using standard volume rendering integration [Parent](13550-model-architecture-and-encoding.md).
    *   Compute the rendered depth $\hat{D}$ using the sampled depths and weights [S1].
4.  **Loss Calculation:**
    *   Compute RGB loss (e.g., MSE) between rendered color $\hat{C}$ and ground truth color $C$.
    *   Compute Depth Loss. The specific formulation (e.g., Earth Mover’s Distance) is implied by the source title [S1], but the evaluation metrics provided are RMSE, Log-RMSE, AbsRel, and SqRel [S1]. The training loss typically involves a weighted sum of RGB and depth errors.
    *   Total Loss $L = L_{rgb} + \lambda L_{depth}$ [S1].
5.  **Optimization:**
    *   Compute gradients of $L$ with respect to MLP weights and depth scale.
    *   Update parameters using Adam optimizer [S1].
    *   Apply learning rate decay: if current step $> 0.8 \times 500,000$, set learning rate to $5 \times 10^{-5}$ [S1].
6.  **Iteration:** Repeat steps 2-5 for 500,000 steps [S1].

**Edge Cases and Pitfalls:**
*   **Scene 710:** Requires a higher depth loss weight ($\lambda = 0.02$) compared to other scenes ($\lambda = 0.007$) [S1].
*   **Depth Threshold:** The threshold $\tau$ for evaluating depth uncertainty is scene-dependent and calculated based on the depth range [S1].
*   **Overfitting:** The dropout regularization is critical to prevent overfitting, especially given the limited data in some scenarios [S1].

## Subtopics

### DS-NeRF Depth Loss Integration
This variant involves integrating the depth loss implementation from the official DS-NeRF codebase into the training pipeline. It requires re-training on specific datasets (LLFF, DTU) using released configuration files, as original publication results may use different train/test splits or unreleased architectural tricks (e.g., reduced positional encoding frequency) to prevent overfitting [S2].

## Operating characteristics
*   **Time Complexity:** Training takes 500,000 steps [S1]. The exact time per step depends on hardware and scene complexity, but the addition of depth loss computation adds minimal overhead compared to RGB loss.
*   **Memory Complexity:** Standard NeRF memory usage plus storage for ground truth depth maps if used during training [S1].
*   **Strengths:** Improves geometric accuracy and training stability through depth supervision. The dropout regularization helps prevent overfitting [S1].
*   **Limitations:** Requires ground truth depth maps for training. Performance may vary across scenes, necessitating scene-specific hyperparameter tuning (e.g., scene 710) [S1]. Reproducing results from other works (like DS-NeRF) may be difficult due to missing configuration files or undocumented architectural modifications [S2].

## Background
This configuration was introduced in the context of Depth-Guided NeRF training using Earth Mover’s Distance [S1]. It builds upon the original NeRF architecture [Parent](13550-model-architecture-and-encoding.md) and incorporates insights from DS-NeRF regarding depth loss integration [S2]. The method is particularly relevant for applications where accurate 3D geometry is crucial, such as in ScanNet and DTU datasets [S1, S2].
