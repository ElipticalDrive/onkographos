# CCNeRF
Also called: Rank-residual Decomposition NeRF

## Overview
CCNeRF is a neural field representation that enables efficient compression and arbitrary composition of 3D scenes without using neural networks for rendering [S1]. It models a 3D scene as a 4D feature volume described by rank components and a weight matrix, allowing dynamic adjustment of model size via rank truncation and composition via rank concatenation [S1]. Unlike NeRF variants that use a shared MLP renderer (e.g., NSVF) or TensoRF which uses MLPs that prevent compression/composition, CCNeRF uses no neural networks for rendering, allowing arbitrary composition without retraining or compatibility constraints [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 2D images with known camera poses used to train the scene representation.
*   **Output:** A compressed, composable 3D scene representation consisting of decomposed rank components and a weight matrix, capable of rendering novel views via volume rendering.

**Data Structures:**
The model structure consists of two main parts [S1]:
1.  **Rank Weights Matrix ($W$):** A matrix storing rank weights for different feature channels. The dimensions are $R_{vec} \times R_{vec} + R_{mat} \times r$, where $R_{vec}$ and $R_{mat}$ are the number of vector-based and matrix-based components, respectively, and $r$ is the feature dimension (typically 3 for RGB) [S1].
2.  **Decomposed Rank Components:** A set of components that are either vector-based (CP decomposition) or matrix-based (triple plane variant) [S1]. The ratio of vector- to matrix-based components is controllable to trade off between model size and performance [S1].
    *   **Vector-based (CP):** Factor matrices $U^x, U^y, U^z$ for spatial dimensions $x, y, z$.
    *   **Matrix-based (Triple Plane):** Factor matrices $\mathcal{U}_{y,z}, \mathcal{U}_{x,z}, \mathcal{U}_{x,y}$ representing planes in the 3D space [S1].

**Numbered Steps:**

1.  **Scene Representation (Rank-Residual Learning):**
    The 3D scene is modeled as a 4D feature volume. To encourage the preservation of primary information in lower ranks, a rank-residual learning strategy is employed [S1]. This allows the model to achieve near-optimal low-rank approximation at any targeted rank without extra optimization [S1].

2.  **Querying a 3D Coordinate:**
    To render a point, the coordinate $\mathbf{x} = (x, y, z)$ is queried as follows [S1]:
    a.  **Projection:** Project the coordinate to the decomposed vectors or matrices. For vector-based components, this involves interpolating along the 1D vectors $U^x, U^y, U^z$. For matrix-based components, this involves interpolating on the 2D planes $\mathcal{U}_{y,z}, \mathcal{U}_{x,z}, \mathcal{U}_{x,y}$ [S1].
    b.  **Weighted Interpolation:** Perform weighted interpolation using the stored rank weights matrix $W$ [S1]. The output is a feature vector (density $\sigma$ and color $\mathbf{c}$) for that point.

3.  **Volume Rendering:**
    The final pixel color $\hat{C}(r)$ for a ray $r$ is computed using the standard volume rendering equation [S1]:
    $$ \hat{C}(r) = \sum_i T_i \alpha_i c_i $$
    where:
    *   $T_i = \prod_{j<i} (1 - \alpha_i)$ is the accumulated transmittance.
    *   $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$ is the opacity of the $i$-th sample.
    *   $\delta_i = t_{i+1} - t_i$ is the distance between samples.
    *   $\sigma_i$ is the density and $c_i$ is the color at sample position $t_i$ along ray $r$ from origin $o$ with direction $d$ [S1].

4.  **Compression (Rank Truncation):**
    Model size is dynamically adjusted by rank truncation [S1]. An empirical sort-and-truncate strategy is used to achieve near-optimal low-rank approximation at any targeted rank [S1]. This allows a trade-off between model size and rendering quality without retraining [S1]. Lower ranks preserve primary information due to the rank-residual learning strategy [S1]. Note that standard truncated HOSVD does not hold the optimal property of truncated SVD, but yields a quasi-optimal solution sufficient for practical use [S1].

5.  **Composition:**
    Different models are composed by concatenating their rank components along the rank dimension [S1]. A transformation matrix is recorded for each object to control its position and orientation in the scene [S1]. Since there are no MLP renderers, this composition is arbitrary and does not require retraining or compatibility constraints [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Determined by the rank of the decomposition. Lower ranks result in smaller model size [S1].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Not given in the sources.
*   **Strengths:**
    *   Enables efficient compression and arbitrary composition of 3D scenes [S1].
    *   No neural networks for rendering, allowing arbitrary composition without retraining or compatibility constraints [S1].
    *   Dynamic adjustment of model size via rank truncation without retraining [S1].
*   **Limitations:**
    *   Standard truncated HOSVD is only quasi-optimal [S1].
*   **When to use it:** When compression and composition of NeRF models are required without the overhead of neural network rendering [S1].
*   **When not:** When the highest possible rendering quality is required and compression is not a priority, or when the quasi-optimal nature of HOSVD is insufficient [S1].

## Background
*   **Origin:** CCNeRF was introduced by Jiaxiang Tang, Xiaokang Chen, Jingbo Wang, and Gang Zeng from Peking University and Chinese University of Hong Kong [S1].
*   **Paper:** "Compressible-Composable NeRF via Rank-residual Decomposition" [S1].
*   **Date:** arXiv:2205.14870v2, 11 Oct 2022 [S1].
*   **History and Development:** The method was motivated by the low-rank approximation property of the SVD algorithm [S1]. It addresses the difficulty in manipulating implicit NeRF representations, which are often restricted by shared renderer networks or suffer from large model sizes [S1]. It builds on tensor decomposition techniques like Tucker decomposition and CP decomposition [S1].
*   **Usage:** Used for photo-realistic rendering and manipulation of 3D scenes, specifically for compression and composition tasks [S1].
