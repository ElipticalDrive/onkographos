# LoRA Fine-Tuning of DINO

Also called: LoRA-NeRF, NeRF with LoRA-fine-tuned DINO features

## Overview
This method adapts frozen DINO vision features to the geometric objectives of NeRF by applying Low-Rank Adaptation (LoRA) to the attention layers of the DINO Vision Transformer (ViT) backbone [S1, unofficial]. It solves the misalignment between semantic features and geometric reconstruction by making only low-rank matrices trainable while keeping pre-trained weights frozen [S1, unofficial]. It sets itself apart from frozen DINO variants by allowing feature adaptation to specific few-shot 3D reconstruction requirements [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Pre-trained DINOv2-base model weights ($W_0$), training images, and camera poses.
*   **Output:** Updated low-rank adaptation matrices ($A, B$) and the frozen weights ($W_0$) which together form the adapted weight matrix $W$. The output features $f'(x)$ are used by the NeRF MLP [S1, unofficial].

**Data Structures:**
*   **LoRA Matrices:**
    *   $A \in \mathbb{R}^{r \times d}$: Trainable down-projection matrix.
    *   $B \in \mathbb{R}^{d \times r}$: Trainable up-projection matrix.
    *   $r$: LoRA rank (default 16) [S1, unofficial].
    *   $d$: Dimension of the attention layer weights [S1, unofficial].
*   **Frozen Weights:** $W_0$ remains static during training [S1, unofficial].

**Steps:**
1.  **Initialize:** Load pre-trained DINOv2-base weights $W_0$. Freeze all parameters in the ViT backbone [S1, unofficial].
2.  **Inject LoRA:** For each attention layer in the ViT, replace the weight matrix $W$ with $W = W_0 + BA$ [S1, unofficial].
3.  **Train:** Optimize only $A$ and $B$ using the Adam optimizer. Keep $W_0$ frozen [S1, unofficial].
4.  **Feature Extraction:** Compute DINO features $f'(x)$ using the adapted model. Project raw 768-dimensional features to 256 dimensions [S1, unofficial].
5.  **NeRF Integration:** Concatenate projected features with positional encodings $\gamma(\mathbf{x})$ and view direction encodings $\gamma(\mathbf{d})$ as input to the NeRF MLP [S1, unofficial].

**Formula:**
$$W = W_0 + BA$$
Where $W_0$ are frozen pre-trained weights, $A \in \mathbb{R}^{r \times d}$ and $B \in \mathbb{R}^{d \times r}$ are trainable low-rank adaptation matrices [S1, unofficial].

**Parameters:**
*   LoRA rank $r = 16$ [S1, unofficial].
*   Optimizer: Adam, learning rate $2 \times 10^{-4}$ [S1, unofficial].
*   Schedule: Cosine learning rate annealing [S1, unofficial].
*   Epochs: 200 [S1, unofficial].
*   Regularization: Dropout rate 0.1 in NeRF MLP [S1, unofficial].
*   Gradient Clipping: Max norm 1.0 [S1, unofficial].
*   Early Stopping: Validation PSNR, patience 20 epochs [S1, unofficial].
*   Precision: Mixed-precision training [S1, unofficial].

**Edge Cases and Pitfalls:**
*   LoRA is applied selectively to attention layers only [S1, unofficial].
*   DINO features are computed once and cached for efficiency [S1, unofficial].
*   Performance may be lower than baseline NeRF in some metrics (e.g., PSNR 12.97 vs 14.71 on Lego dataset with 5 views) [S1, unofficial].

**Pseudocode:**
```python
# Initialize LoRA parameters
r = 16
d = attention_layer_dim # e.g., 768 for DINOv2-base
A = torch.randn(r, d) * init_scale
B = torch.zeros(d, r) # Initialize B to zero for stable start

# Forward pass with LoRA
def forward_with_lora(x, W0, A, B):
    # W0 is frozen, A and B are trainable
    # W = W0 + B @ A
    # Note: In practice, this is often implemented as a residual update
    # to avoid materializing the full W matrix
    return W0 @ x + B @ (A @ x)

# Training loop
for epoch in range(200):
    # 1. Extract features using adapted DINO
    # DINO backbone weights W0 are frozen
    # Only A and B are updated via optimizer
    features = dino_model(input_images, A=A, B=B)
    
    # 2. Project features
    projected_features = projection_layer(features) # 768 -> 256
    
    # 3. NeRF forward pass
    # Concatenate with positional encodings
    nerf_input = concat(pos_enc, view_enc, projected_features)
    color, density = nerf_mlp(nerf_input)
    
    # 4. Compute loss and backpropagate
    loss = compute_loss(color, density, ground_truth)
    loss.backward()
    
    # 5. Update only A and B
    optimizer.step()
    optimizer.zero_grad()
```

## Subtopics

### LoRA Fine-Tuning
A technique that fine-tunes the diffusion model with minimal computational overhead, making it adaptable to new tasks by modifying a few parameters within the model [S2].

## Operating characteristics
*   **Time Complexity:** Training takes 2-4 hours per experiment, depending on model complexity [S1, unofficial].
*   **Memory Complexity:** Mixed-precision training is used to accelerate experiments [S1, unofficial].
*   **Performance:** On the Lego dataset with 5 training views, LoRA-NeRF achieves PSNR 12.97, SSIM 0.45, LPIPS 0.54 [S1, unofficial]. This is lower than Baseline NeRF (PSNR 14.71) but comparable to Frozen DINO-NeRF (PSNR 12.99) [S1, unofficial].
*   **Strengths:** Parameter-efficient, preserves prior knowledge, adapts features to geometric objectives [S1, unofficial].
*   **Limitations:** May not outperform baseline NeRF in standard metrics; performance depends on rank $r$ and layer selection [S1, unofficial].
*   **When to use:** Few-shot 3D reconstruction where semantic alignment is crucial but geometric alignment of frozen features is insufficient [S1, unofficial].
*   **When not to use:** When baseline NeRF performance is sufficient or computational resources are extremely limited [S1, unofficial].

## Background
Originated from the paper "Limitations of NERF with pre-trained Vision Features for Few-Shot 3D Reconstruction" [S1, unofficial]. It builds on the DINO-enhanced NeRF framework [S1, unofficial]. LoRA itself is a well-known technique for efficient fine-tuning of large models [S2].
