# MINE

Also called: Continuous Depth MPI, MINE (Continuous Depth MPI), MINE: Towards Continuous Depth MPI with NeRF for Novel View Synthesis, Multiplane Image with Neural Radiance Fields

## Overview
MINE is a method for novel view synthesis that models the frustum of the source camera using continuous depth Multiplane Images (MPI), conditioned on input images via a fully-convolutional decoder [S1]. It differs from pixelNeRF and GRF, which model the entire 3D space per ray, by reconstructing the source camera's frustum per plane, allowing rendering of any target view via homography warping after a single encoder pass and a fixed number of decoder passes, independent of the number of target views [S1].

## How it works
**Inputs:** A single input image (or multiple views for GRF comparison, but MINE uses single image conditioning) and camera intrinsics.
**Outputs:** Rendered novel view images and disparity maps.

**Data Structures:**
1.  **Encoder Features:** A list of feature maps extracted from a ResNet50 encoder at layers `[conv1, layer1, layer2, layer3, layer4]` [S1].
2.  **MPI Representation:** A set of $N_{\text{planes}}$ planes. Each plane is represented as a 4-channel image (RGB-σ) output by the decoder [S1].
    *   Channels 0-2: RGB color values, normalized via Sigmoid.
    *   Channel 3: Density ($\sigma$), computed as the absolute value of the last channel [S1].
3.  **Decoder Output:** A 4-channel tensor per plane inference [S1].

**Parameters:**
*   $N_{\text{planes}}$: The number of planes in the MPI representation. Typical values depend on the dataset depth range [S1].
*   $H \times W$: Output image resolution [S1].
*   $N_{\text{points}}$: Number of points along each ray (used for comparison with NeRF-like methods) [S1].
*   Disparity Range: Specific to datasets, e.g., $[3.0, 0.03]$ for Flowers Light Fields [S1].

**Steps:**
1.  **Encoding:** Input the source image into a ResNet50 encoder. Extract feature maps from layers `conv1`, `layer1`, `layer2`, `layer3`, and `layer4` [S1].
2.  **Frustum Reconstruction (Decoding):** Perform $N_{\text{planes}}$ forward passes of the fully-convolutional depth decoder. Each pass reconstructs one plane of the MPI frustum [S1].
    *   The decoder takes encoder features and disparity encoding as input [S1].
    *   The decoder architecture consists of downsampling and upsampling blocks with skip connections from the encoder [S1].
3.  **Rendering Novel Views:** For each target view, apply homography warping to the reconstructed frustum (the set of $N_{\text{planes}}$ planes) to render the image [S1].
    *   If view-dependent effects are required, concatenate per-ray viewing directions with the warped feature maps and pass through a lightweight fully-convolutional network [S1].

**Formulas:**
The number of network forward passes $P$ for MINE is:
$$P_{\text{MINE}} = 1 + N_{\text{planes}}$$
where the '1' is the encoder pass and $N_{\text{planes}}$ are the decoder passes [S1].

For comparison, the forward passes for pixelNeRF and GRF are:
$$P_{\text{pixelNeRF}} = 1 + N_{\text{targets}} \times N_{\text{points}} \times H \times W$$
$$P_{\text{GRF}} = N_{\text{views}} + N_{\text{targets}} \times N_{\text{points}} \times H \times W$$
where $N_{\text{targets}}$ is the number of novel views, $N_{\text{points}}$ is points per ray, and $H \times W$ is output resolution [S1].

**Decoder Architecture Details:**
The decoder is based on the depth decoder from [12], with two additional downsampling blocks and two upsampling blocks [S1]. The layers are defined as follows (Table 5 in [S1]):

| Layer | Type | Input Channels | Output Channels | Input Concatenation | Activation |
| :--- | :--- | :--- | :--- | :--- | :--- |
| downconv1 | Conv | 2048 | 512 | - | ELU |
| downconv2 | Conv | 512 | 256 | - | ELU |
| upconv1_extra | Conv + Up | 256 | 256 | - | ELU |
| upconv2_extra | Conv + Up | 256 | 2048 | - | ELU |
| upconv5 | Conv + Up | 2048 + 21 | 256 | cat(upconv2_extra, disparity_encoding) | ELU |
| iconv5 | Conv | 256 + 1024 + 21 | 256 | cat(upconv5, encoder_layer3, disparity_encoding) | ELU |
| upconv4 | Conv + Up | 256 | 128 | - | ELU |
| iconv4 | Conv | 128 + 512 + 21 | 128 | cat(upconv4, encoder_layer2, disparity_encoding) | ELU |
| output4 | Conv | 128 | 4 | iconv4 | Sigmoid (RGB), abs (σ) |
| upconv3 | Conv + Up | 128 | 64 | - | ELU |
| iconv3 | Conv | 64 + 256 + 21 | 64 | cat(upconv3, encoder_layer1, disparity_encoding) | ELU |
| output3 | Conv | 64 | 4 | iconv3 | Sigmoid (RGB), abs (σ) |
| upconv2 | Conv + Up | 64 | 32 | - | ELU |
| iconv2 | Conv | 32 + 64 + 21 | 32 | cat(upconv2, encoder_conv1, disparity_encoding) | ELU |
| output2 | Conv | 32 | 4 | iconv2 | Sigmoid (RGB), abs (σ) |
| upconv1 | Conv + Up | 32 | 16 | - | ELU |
| iconv1 | Conv | 16 | 16 | - | ELU |
| output1 | Conv | 16 | 4 | iconv1 | Sigmoid (RGB), abs (σ) |

*   `upconv` blocks: Convolution, Batch Normalization, Activation, followed by 2x nearest neighbor upsampling [S1].
*   `downconv` blocks: Max pooling (stride 2), Convolution, Activation [S1].
*   `disparity_encoding`: Input to specific layers (channels 21) [S1].

**Edge Cases and Pitfalls:**
*   **Principal Point Shift:** In datasets like Flowers Light Fields, the principal point shifts between views due to the Lytro Illum camera. If metadata is unavailable, a constant shift based on grid index $[i, j]$ must be applied: $c_{xij} = 0.5 + 0.002667 \times i$ and $c_{yij} = 0.5 + 0.002667 \times j$ [S1].
*   **Viewing Direction:** MINE does not take viewing direction as input by default. To support view-dependent effects, viewing directions must be concatenated with output feature maps after warping and processed by a lightweight fully-convolutional network [S1].
*   **Loss Application:** Multiscale training losses ($L_{L1}$ and $L_{SSIM}$) are applied only to `output1`, while edge-aware smoothness loss ($L_{smooth}$) is applied to all outputs (`output1` through `output4`) [S1].

## Operating characteristics
**Time and Memory Complexity:**
The complexity of MINE is independent of the number of target views ($N_{\text{targets}}$) [S1]. The number of forward passes is $P_{\text{MINE}} = 1 + N_{\text{planes}}$ [S1]. In contrast, pixelNeRF and GRF scale with $N_{\text{targets}}$ [S1].

**Measured Performance:**
MINE is significantly more efficient than pixelNeRF and GRF because it reconstructs the source camera's frustum per plane rather than the entire 3D space per ray [S1]. This allows for dense supervision signals (SSIM, edge-aware smoothness) during training, which is infeasible for NeRF-like methods due to their inefficiency [S1].

**Strengths and Limitations:**
*   **Strengths:** High efficiency for novel view synthesis, especially when rendering many target views. Generalizes well to large-scale real-world datasets (KITTI, NYU-V2, RealEstate10k, Flowers Light Fields, iBims-1) [S1].
*   **Limitations:** Does not natively support view-dependent effects without modification. Requires careful handling of camera intrinsics shifts in light field data [S1].

**When to Use:**
Use MINE when efficient novel view synthesis is required, particularly when the number of target views is large or when dense supervision during training is beneficial for generalization [S1].

**When Not to Use:**
Avoid if view-dependent effects are critical and a lightweight additional network is not feasible, or if the scene requires modeling of the entire 3D space explicitly rather than just the frustum [S1].

## Background
MINE (Multiplane Image with Neural Radiance Fields) was introduced in the paper "MINE: Towards Continuous Depth MPI with NeRF for Novel View Synthesis" [S1]. It was verified on datasets including KITTI, NYU-V2, RealEstate10k, Flowers Light Fields, and iBims-1 [S1]. The method builds on the concept of Multiplane Images (MPI) and integrates it with neural network-based conditioning, differing from prior works like pixelNeRF and GRF by modeling the frustum rather than the entire 3D space [S1].
