# Multiplicative Interaction Module

Also called: MI-NeRF conditional input module, conditional input module, multiplicative module M

## Overview
The Multiplicative Interaction Module (MIM) is a neural component that generates conditional inputs for a NeRF by computing multiplicative interactions between expression, identity, and optional latent codes to improve facial disentanglement and rendering quality [S1, unofficial]. It sets itself apart from sibling methods like [MIMO-DONeRF](16217-mimo-donerf.md) or [Point-NeRF Adaptation for Object Manipulation](16395-point-nerf-adaptation-for-object-manipulation.md) by explicitly modeling higher-order (second and third) multiplicative dependencies between semantic codes rather than relying on linear concatenation or simple additive fusion [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Expression vector $e \in \mathbb{R}^d$
- Identity vector $i \in \mathbb{R}^d$
- Optional latent code $l \in \mathbb{R}^d$ (time-varying, per-frame)
- Output vector $y \in \mathbb{R}^o$

**Data Structures:**
- Tensor $\mathcal{W} \in \mathbb{R}^{o \times d \times d}$: Learnable third-order tensor for pure multiplicative interaction.
- Matrices $W_2, W_3 \in \mathbb{R}^{o \times d}$: Learnable linear weights for identity and expression respectively.
- Factor matrices $A, B \in \mathbb{R}^{d \times k}$: Learnable parameters for CP decomposition of $\mathcal{W}$ along the expression and identity modes.
- Matrix $C \in \mathbb{R}^{o \times k}$: Learnable output projection matrix from the CP decomposition.
- Matrices $U_1, U_2, U_3 \in \mathbb{R}^{k \times d}$: Learnable projection matrices used in the full third-order variant with latent codes.

**Parameters:**
- $d$: Dimension of input vectors. Set to 79 in the final model [S1, unofficial].
- $k$: Rank of the CP decomposition. Set to $k=d$ in the final model [S1, unofficial].
- $o$: Output dimension. Set to $o=d$ in the final model; tested at $o=256$ in ablation [S1, unofficial].

**Formulas:**
The basic module computes interactions between expression $e$ and identity $i$. The full multiplicative interaction is defined as:
$$ M^\dagger(e, i) = \mathcal{W} \times_2 e \times_3 i $$
where $\times_m$ denotes the mode-$m$ vector product [S1, unofficial].

To augment this with linear interactions, the formula becomes:
$$ M^\dagger(e, i) = \mathcal{W} \times_2 e \times_3 i + W_2 e + W_3 i $$
where $W_2, W_3 \in \mathbb{R}^{o \times d}$ [S1, unofficial].

Using CP decomposition [S1, unofficial], the tensor term $\mathcal{W} \times_2 e \times_3 i$ can be rewritten using factor matrices $A, B \in \mathbb{R}^{d \times k}$ and $C \in \mathbb{R}^{o \times k}$:
$$ \mathcal{W} \times_2 e \times_3 i = C (A \odot B)^T (e \odot i) $$
where $\odot$ denotes the Khatri-Rao product. Applying the mixed product property, this simplifies to a Hadamard product $*$:
$$ M^\dagger(e, i) = C \left[ (A^T e) * (B^T i) \right] + W_2 e + W_3 i $$
If we set $o=k=d$ and $A^T = U_1, B^T = U_2$, this matches the standard implementation form [S1, unofficial].

For the variant including latent codes $l$, the module captures third-order interactions:
$$ M(e, i, l) = C \left[ (U_1 e) * (U_2 i) * (U_3 l) + (U_1 e) * (U_2 i) + (U_1 e) * (U_3 l) + (U_2 i) * (U_3 l) + (U_1 e) + (U_2 i) + (U_3 l) \right] $$
where $U_1, U_2, U_3 \in \mathbb{R}^{k \times d}$ and $C \in \mathbb{R}^{o \times k}$ [S1, unofficial].

**Pseudocode:**
```python
def multiplicative_interaction_module(e, i, l=None, d=79, k=79, o=79):
    """
    Computes the multiplicative interaction module output.
    
    Args:
        e: Expression vector, shape (d,)
        i: Identity vector, shape (d,)
        l: Optional latent code vector, shape (d,)
        d: Input dimension (default 79)
        k: CP decomposition rank (default d)
        o: Output dimension (default d)
        
    Returns:
        y: Output vector, shape (o,)
    """
    # Initialize learnable parameters
    # In a real implementation, these would be loaded from a trained model
    # W_tensor: shape (o, d, d)
    # W2: shape (o, d)
    # W3: shape (o, d)
    # A: shape (d, k)
    # B: shape (d, k)
    # C: shape (o, k)
    # U1, U2, U3: shape (k, d) if l is used
    
    # Base multiplicative term using CP decomposition
    # Term 1: (A^T e) * (B^T i)
    # A^T e: shape (k,)
    # B^T i: shape (k,)
    # Hadamard product: shape (k,)
    term_base = (A.T @ e) * (B.T @ i)
    
    # Project to output space
    # C @ term_base: shape (o,)
    y = C @ term_base
    
    # Add linear terms
    # W2 @ e: shape (o,)
    # W3 @ i: shape (o,)
    y = y + (W2 @ e) + (W3 @ i)
    
    # If latent code l is provided, use the full third-order variant
    if l is not None:
        # Recompute using the full formula with U matrices
        # u1_e = U1 @ e, shape (k,)
        # u2_i = U2 @ i, shape (k,)
        # u3_l = U3 @ l, shape (k,)
        
        u1_e = U1 @ e
        u2_i = U2 @ i
        u3_l = U3 @ l
        
        # Third-order interaction
        term_3 = u1_e * u2_i * u3_l
        
        # Second-order interactions
        term_2_1 = u1_e * u2_i
        term_2_2 = u1_e * u3_l
        term_2_3 = u2_i * u3_l
        
        # First-order interactions
        term_1_1 = u1_e
        term_1_2 = u2_i
        term_1_3 = u3_l
        
        # Sum all terms
        combined = term_3 + term_2_1 + term_2_2 + term_2_3 + term_1_1 + term_1_2 + term_1_3
        
        # Project to output space
        y = C @ combined
        
    return y
```

**Edge Cases and Pitfalls:**
- Reducing dimension $d$ below 79 loses necessary information for capturing 3DMM principal components, as learned matrices $W_1, W_2, W_3$ have full rank with all singular values $> 10^{-3}$ [S1, unofficial].
- Including latent codes $l$ in the multiplicative module decreases performance (PSNR 29.01 vs 29.73) because $l$ captures time-varying per-frame variations that do not meaningfully interact with time-invariant identity or expression codes [S1, unofficial].
- Using simple learnable concatenation $M(e, i) = [W_2 e; W_3 i]$ decreases performance (PSNR 28.99) due to the lack of multiplicative interactions [S1, unofficial].
- Increasing output dimension to $o=256$ yields similar performance (PSNR 29.76) but with more parameters, offering no significant benefit [S1, unofficial].

## Operating characteristics
- **Time Complexity:** The CP-decomposed implementation is efficient, scaling linearly with $d$ and $k$ for the multiplicative term, plus linear terms for the linear weights. The full third-order variant with latent codes increases complexity due to additional Hadamard products and projections.
- **Memory Complexity:** Depends on the size of learnable parameters: $\mathcal{W}$ ($o \cdot d^2$), $W_2, W_3$ ($2 \cdot o \cdot d$), or the CP factors $A, B, C$ ($2 \cdot d \cdot k + o \cdot k$). The CP decomposition significantly reduces memory compared to the full tensor $\mathcal{W}$ when $k < d$.
- **Strengths:** Explicitly models multiplicative dependencies between semantic codes, leading to better facial disentanglement and rendering quality compared to linear concatenation [S1, unofficial].
- **Limitations:** Does not benefit from including time-varying latent codes in the multiplicative interaction, as these do not interact meaningfully with static identity/expression codes [S1, unofficial]. Requires careful selection of dimension $d$ to preserve 3DMM information [S1, unofficial].
- **When to use:** When facial disentanglement between identity, expression, and other semantic codes is critical for high-quality rendering.
- **When not to use:** When computational resources are extremely limited and the performance gain from multiplicative interactions is not justified, or when time-varying latent codes are the primary source of variation (as they do not benefit from multiplicative interaction with static codes) [S1, unofficial].

## Background
The Multiplicative Interaction Module was introduced in the MI-NeRF paper [S1, unofficial]. It leverages CP decomposition, a core tool for low-rank tensor factorization introduced by Kolda & Bader (2009) [S1, unofficial]. The module is designed to improve the conditional input generation for NeRFs in the context of facial reconstruction, specifically addressing the need to disentangle identity and expression information.
