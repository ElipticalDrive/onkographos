# View Direction Removal

Also called: View-independent color prediction, Removing view direction condition

## Overview
View Direction Removal is a training configuration strategy that excludes the viewing direction $\mathbf{d}$ from the input signature used to predict color $\mathbf{c}$, while retaining it for density $\sigma$ prediction or discarding it entirely depending on the specific implementation variant. This method addresses the problem of spurious correlations and dataset bias that arise when a model uses view direction as a shortcut to explain appearance variations, particularly in scenarios with limited input views [S1, unofficial]. It sets itself apart from standard NeRF and its siblings like [See-NeRF](18115-see-nerf.md) by explicitly decoupling geometric density from view-dependent appearance, prioritizing synthesis consistency over the modeling of complex specular or anisotropic effects.

## How it works
**Inputs and Outputs:**
*   **Input:** 3D position $\mathbf{x}$, viewing direction $\mathbf{d}$ (optional, depending on density branch), and positional encodings $\Gamma(\mathbf{x})$.
*   **Output:** Density $\sigma$ and color $\mathbf{c}$.

**Data Structures:**
The Multi-Layer Perceptron (MLP) architecture is modified from the standard joint encoding.
1.  **Position Encoding:** $\Gamma(\mathbf{x})$ is computed using positional encoding.
2.  **Direction Encoding:** $\Gamma(\mathbf{d})$ is computed.
3.  **Network Split:**
    *   **Density Branch:** Takes $\Gamma(\mathbf{x})$ (and optionally $\Gamma(\mathbf{d})$ if view-dependent density is desired, though standard removal often implies view-independent geometry) to output $\sigma$.
    *   **Color Branch:** Takes $\Gamma(\mathbf{x})$ **only**. It does **not** concatenate $\Gamma(\mathbf{d})$. It outputs $\mathbf{c}$.

**Steps:**
1.  Encode the 3D position $\mathbf{x}$ into $\Gamma(\mathbf{x})$.
2.  Encode the viewing direction $\mathbf{d}$ into $\Gamma(\mathbf{d})$.
3.  Pass $\Gamma(\mathbf{x})$ through the density sub-network to predict $\sigma(\mathbf{x})$.
4.  Pass $\Gamma(\mathbf{x})$ through the color sub-network to predict $\mathbf{c}(\mathbf{x})$. Note that $\mathbf{d}$ is **not** provided to this branch.
5.  Render the volume using the standard volume rendering integral:
    $$ C(\mathbf{r}) = \sum_{i=1}^{N} T_i \alpha_i \mathbf{c}_i $$
    where $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$ and $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$.

**Parameters:**
*   **View Direction in Color MLP:** Disabled (False).
*   **View Direction in Density MLP:** Typically Disabled (False) for pure view-independent geometry, but may be enabled if view-dependent density is required [G].

**Edge Cases and Pitfalls:**
*   **Spurious Correlations:** Including $\mathbf{d}$ in color prediction allows the model to memorize background or lighting artifacts specific to the training set rather than learning the intrinsic material properties [S1, unofficial].
*   **Single-View Targets:** The bias is most severe when training on single-view or very few views, as the model lacks the angular diversity to disentangle geometry from appearance [S1, unofficial].
*   **Loss of Specular Detail:** This method cannot model view-dependent effects like specular highlights or reflections. It is unsuitable for shiny or metallic materials [S1, unofficial].

**Pseudocode:**
```python
def forward(self, x, d):
    # x: (N, 3), d: (N, 3)
    
    # 1. Encode position
    x_enc = positional_encoding(x)
    
    # 2. Encode direction (computed but not used for color)
    d_enc = positional_encoding(d)
    
    # 3. Predict Density (View-Independent)
    # Concatenate only position encoding
    density_input = x_enc
    sigma = self.density_mlp(density_input)
    
    # 4. Predict Color (View-Independent)
    # CRITICAL: Do NOT concatenate d_enc here
    color_input = x_enc
    c = self.color_mlp(color_input)
    
    return sigma, c
```

## Subtopics
*   **See-NeRF [See-NeRF](18115-see-nerf.md):** Uses a different approach to handle view-dependence by incorporating a latent code or specific attention mechanisms, rather than simple removal. Choose when view-dependent effects are critical.
*   **REF2-NeRF [REF2-NeRF](18124-ref2-nerf.md):** Focuses on reflection modeling. Choose when specular reflections are the primary target.
*   **Lighting and Intrinsic Decomposition [Lighting and Intrinsic Decomposition](18220-lighting-and-intrinsic-decomposition.md):** Explicitly separates albedo, normal, and lighting. Choose when physical interpretability is required.

## Operating characteristics
*   **Time Complexity:** Slightly lower than standard NeRF due to reduced input dimensionality to the color MLP.
*   **Memory Complexity:** Reduced model size for the color branch.
*   **Strengths:** Improves synthesis consistency; prevents overfitting to dataset-specific lighting or backgrounds; robust for diffuse materials.
*   **Limitations:** Cannot render specular highlights, anisotropic reflections, or any view-dependent appearance.
*   **When to use:** Diffuse objects, single-view or few-view reconstruction, scenarios where background consistency is more important than material realism.
*   **When not to use:** Shiny/metallic objects, scenes with strong directional lighting effects, multi-view datasets where view-dependence is a key feature.

## Background
Originating from StyleNeRF, this method was proposed to address the limitations of standard NeRF's default view-dependent color prediction. The original NeRF [S1, unofficial] suggested using view direction to model view-dependent effects, a design adopted by many follow-up works. However, StyleNeRF demonstrated that this freedom leads to the capture of spurious correlations and dataset bias, particularly when training data is limited (e.g., single-view targets). By removing the view direction from color prediction, the method improves the consistency of synthesized images [S1, unofficial].
