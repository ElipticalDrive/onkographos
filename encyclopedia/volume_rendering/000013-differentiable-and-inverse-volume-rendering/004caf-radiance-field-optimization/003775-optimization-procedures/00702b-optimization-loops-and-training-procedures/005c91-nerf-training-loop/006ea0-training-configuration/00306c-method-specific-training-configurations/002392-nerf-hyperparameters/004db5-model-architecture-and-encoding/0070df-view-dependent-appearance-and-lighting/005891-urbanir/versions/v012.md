# UrbanIR

Also called: Urban Scene Inverse Rendering

## Overview
UrbanIR is a method for the inverse rendering of large-scale, unbounded urban scenes from a single monocular video under single illumination [S1]. It infers shape, albedo, surface normals, semantics, and sun/sky illumination to enable realistic relighting and night simulation [S1]. Unlike standard NeRFs that bake lighting into color, or methods requiring LiDAR/multiple cameras (e.g., FEGR, LightSim) or multiple light sources (e.g., NeRF-OSR), UrbanIR uses only RGB video and known camera poses [S1]. It distinguishes itself by using a spatial hash-based voxel representation (Instant-NGP) for scalability and a visibility estimation technique that avoids per-scene optimized MLP heads for shadows, allowing the sun position to change during relighting [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A multi-frame video of a scene under single illumination with known camera motion. Defined as a set $\{I_i, E_i, K_i\}$, where $I_i \in \mathbb{R}^{H \times W \times 3}$ is the RGB image, $E_i \in SE(3)$ is the camera pose, and $K_i$ is the camera intrinsic matrix [S1].
*   **Output:** A relightable neural scene model encoding albedo $\mathbf{a}$, normal $\mathbf{n}$, semantics $\mathbf{s}$, density $\sigma$, and a lighting model $\mathcal{L}$ (sun, ambient, sky) [S1].

**Data Structures:**
The scene representation is built on Instant-NGP [S1].
1.  **Dense Feature Hash Table:** A spatial hash-based voxel structure representing the scene. It provides compactness and consistency for expansive outdoor scenes [S1].
2.  **MLP Headers:** Individual Multi-Layer Perceptrons are used to decode each attribute (albedo, normal, semantics, density) given a queried feature vector at point $\mathbf{x}$ [S1].
3.  **Lighting Model $\mathcal{L}$:**
    *   Sun: 5-DoF representation encoding sun color $\mathbf{L}_{\text{sun}}$ and azimuth $\psi_{\text{sun}}$, zenith $\phi_{\text{sun}}$ [S1].
    *   Ambient: 3-DoF Lambertian ambient light $\mathbf{L}_{\text{amb}}$ [S1].
    *   Sky: A sky dome model inferring sky texture from viewing direction [S1].

**Numbered Steps:**

1.  **Scene Representation Query:** For a query point $\mathbf{x} \in \mathbb{R}^3$, the hash table is queried to retrieve a feature vector. This feature is passed through individual MLP headers to predict intrinsic attributes: diffuse albedo $\mathbf{a}$, surface normal $\mathbf{n}$, semantic vector $\mathbf{s}$, and density $\sigma$ [S1].
    $$ F_\theta(\mathbf{x}) = (\mathbf{a}, \mathbf{n}, \mathbf{s}, \sigma) $$
    where $\theta$ are the learnable scene parameters [S1].

2.  **Volume Rendering of Intrinsics:** For a camera ray $\mathbf{r}$, $N$ points are sampled along the ray. The intrinsic attributes are accumulated using alpha-composition weights $w_i$ [S1]:
    $$ w_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right) (1 - \exp(-\sigma_i \delta_i)) $$
    where $\delta_i = t_i - t_{i-1}$ is the step size [S1]. The final rendered intrinsic values are:
    $$ \mathbf{A}(\mathbf{r}) = \sum_{i=1}^{N} w_i \mathbf{a}_i, \quad \mathbf{N}(\mathbf{r}) = \sum_{i=1}^{N} w_i \mathbf{n}_i, \quad \mathbf{S}(\mathbf{r}) = \sum_{i=1}^{N} w_i \mathbf{s}_i $$
    [S1].

3.  **Visibility Estimation:** To model shadows without per-scene optimized MLPs (which cannot handle changing sun positions during relighting), UrbanIR estimates visibility $V(\mathbf{x}, \text{sun})$ [S1].
    *   First, compute the 3D point $\mathbf{x}(\mathbf{r})$ being shaded by volume rendering depth: $\hat{t} = \sum_{i=1}^N w_i t_i$ [S1].
    *   Then, estimate the transmittance along the ray segment between $\mathbf{x}(\mathbf{r})$ and the light source (sun) using volume rendering to determine if the point is visible to the sun [S1].

4.  **Shading:** The final color $\mathbf{C}$ is computed by combining the rendered intrinsics with the lighting model $\mathcal{L}$ and the shadow visibility estimate [S1]:
    $$ \mathbf{C} = \texttt{Shade}(\texttt{Intrinsics}(F_\theta, \mathbf{r}), \texttt{Shadow}(F_\theta, \mathbf{r}, \mathcal{L}), \mathcal{L}) $$
    [S1]. The shading function combines albedo, normals, sun/ambient/sky illumination, and shadow visibility [S1].

5.  **Optimization:** The scene parameters $\theta$ and lighting parameters $\mathcal{L}$ are jointly optimized to minimize the difference between rendered images and input observations, often using additional priors (e.g., gray-world, smoothness) to constrain the ill-posed decomposition [S1, Parent].

def urbanir_render(ray_origin, ray_direction, scene_hash_table, lighting_model, num_samples):
    """
    Renders a single ray using UrbanIR's inverse rendering pipeline.
    """
    # 1. Sample points along the ray
    t_values = linear_space(ray_origin, ray_direction, num_samples)
    points = ray_origin + ray_direction * t_values
    
    # 2. Query scene for intrinsic attributes
    # Returns albedo, normal, semantics, density for each point
    albedos, normals, semantics, densities = query_scene_hash(points, scene_hash_table)
    
    # 3. Compute alpha-composition weights
    # w_i = exp(-sum_{j=1}^{i-1} sigma_j * delta_j) * (1 - exp(-sigma_i * delta_i))
    deltas = t_values[1:] - t_values[:-1]
    deltas = np.concatenate([[0], deltas]) # Handle first delta if needed, usually delta_1 is t_1 - t_0
    
    # Compute transmittance T_i = exp(-sum_{j=1}^{i-1} sigma_j * delta_j)
    # Using cumulative sum of density * delta
    density_delta = densities * deltas
    cumulative_density = np.cumsum(density_delta)
    transmittance = np.exp(-np.concatenate([[0], cumulative_density[:-1]]))
    
    # Alpha for each step
    alpha = 1.0 - np.exp(-density_delta)
    
    # Weights
    weights = transmittance * alpha
    
    # 4. Volume render intrinsics
    albedo_rendered = np.sum(weights[:, np.newaxis] * albedos, axis=0)
    normal_rendered = np.sum(weights[:, np.newaxis] * normals, axis=0)
    semantics_rendered = np.sum(weights[:, np.newaxis] * semantics, axis=0)
    
    # 5. Estimate Visibility (Shadow)
    # Compute depth point x(r)
    depth_t = np.sum(weights * t_values)
    shaded_point = ray_origin + ray_direction * depth_t
    
    # Estimate visibility of shaded_point to sun
    # Trace ray from shaded_point to sun direction
    sun_visibility = estimate_sun_visibility(shaded_point, lighting_model.sun_direction, scene_hash_table)
    
    # 6. Shade
    color = shade(intrinsics=(albedo_rendered, normal_rendered, semantics_rendered),
                  lighting=lighting_model,
                  visibility=sun_visibility)
                  
    return color

**Edge Cases and Pitfalls:**
*   **Shadow Modeling:** Using a per-scene optimized MLP head for visibility is impractical because the sun position changes during relighting, but training data only has one sun position [S1]. UrbanIR avoids this by estimating visibility via transmittance to the sun [S1].
*   **Large-Scale Scenes:** Standard NeRFs are not suitable for large-scale urban scenes due to memory and consistency issues; Instant-NGP is required [S1].
*   **Ill-posed Decomposition:** Inverse rendering is ill-posed; additional priors (e.g., gray-world, smoothness) are needed to constrain the solution [S1, Parent].

## Operating characteristics
*   **Time and Memory Complexity:** Uses Instant-NGP, which offers low memory consumption and high efficiency in training and rendering compared to standard MLP-based NeRFs [S1].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Designed for large-scale, unbounded urban scenes [S1].
*   **Strengths:** Works with single monocular video; no LiDAR or multiple cameras required; enables relighting and night simulation [S1].
*   **Limitations:** Assumes single illumination during training; visibility estimation relies on the assumption that shadows are primarily due to a single directional sunlight [S1].

## Background
UrbanIR was introduced by Chih-Hao Lin, Bohan Liu, Yi-Ting Chen, Kuan-Sheng Chen, David Forsyth, Jia-Bin Huang, Anand Bhattad, and Shenlong Wang from the University of Illinois Urbana-Champaign and University of Maryland, College Park [S1]. It was published in 3DV 2025 (arXiv:2306.09349v4, Jan 2025) [S1]. It addresses the limitation of existing relightable NeRF methods that focus on small bounded indoor environments or require multiple lighting sources/LiDAR [S1].
