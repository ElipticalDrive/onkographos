# MoCo-NeRF

Also called: Motion-Oriented Compositional Neural Radiance Fields

## Overview
MoCo-NeRF is a framework for free-viewpoint rendering of monocular human videos that models non-rigid body motions as radiance residual fields rather than spatial offsets, using rigid skeletal transformations as a prior [S1]. It decomposes the radiance field into a rigid branch learning a canonical T-pose representation and a non-rigid branch optimizing pose-driven radiance residuals, allowing direct color supervision for both components [S1]. Unlike offset-based strategies that suffer from high computational complexity and misaligned learning objectives, MoCo-NeRF reduces the prediction range to the radiance space and establishes direct supervision from ground-truth pixel colors [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Monocular video frames, camera poses, and skeletal joint positions $J$ for each frame.
*   **Outputs:** Rendered RGB images for arbitrary viewpoints and poses.

**Data Structures:**
*   **Multiresolution Hash Encoding (MHE) $\psi_{hash}$:** A single hash grid shared by both branches in the single-subject setting. For multi-subject settings, a global MHE $\psi_{hash}^G$ and $N_s$ local MHEs $\{\psi_{hash}^i\}$ are used [S1].
*   **Rigid MLP Decoder $M_{rigid}$:** Takes sliced features and outputs density $\sigma$ and color $\mathbf{c}$ [S1].
*   **Non-Rigid MLP Decoder $M_{nr}$:** Takes partially frozen features and pose-embedded implicit features to output residuals $\Delta \mathbf{c}$ and $\Delta \sigma$ [S1].
*   **Learnable Base Code $S$:** A tensor of shape $\mathbb{R}^{64}$, randomly initialized and optimized per subject [S1].
*   **Projection Matrices:** $W_p, W_Q, W_K, W_V$ for generating pose-embedded implicit features [S1].

**Numbered Steps:**

1.  **Canonical Transformation:**
    For an observation point $\mathbf{x}$ and skeletal pose defined by rotations $R_k$ and translations $\mathbf{t}_k$ for $K$ joints, compute the canonical point $\mathbf{x}_c$ using inverse linear blend skinning [S1]:
    $$ \mathbf{x}_c = \sum_{k=1}^K w^o_k (R_k \mathbf{x} + \mathbf{t}_k) $$
    where the observation skinning weights $w^o_k$ are derived from canonical weights $w^c_k$ [S1]:
    $$ w^o_k = \frac{w^c_k(R_k \mathbf{x} + \mathbf{t}_k)}{\sum_{j=1}^K w^c_j(R_j \mathbf{x} + \mathbf{t}_j)} $$
    The canonical weights $w^c_k$ are optimized via an explicit volume decoder [S1].

2.  **Feature Querying (Single-Subject):**
    Query multiresolution volumetric features $\mathbf{f}_{\mathbf{x}_c}$ from the MHE $\psi_{hash}$ [S1]:
    $$ \mathbf{f}_{\mathbf{x}_c} = \psi_{hash}(\mathbf{x}_c) $$

3.  **Rigid Branch Prediction:**
    Slice the first half ($H$ dimensions) of $\mathbf{f}_{\mathbf{x}_c}$ at each resolution level to compute $\mathbf{f}^{:H}_{\mathbf{x}_c}$ [S1]. Predict rigid color $\mathbf{c}$ and density $\sigma$ using $M_{rigid}$ [S1]:
    $$ \mathbf{c}, \sigma = M_{rigid}(\mathbf{f}^{:H}_{\mathbf{x}_c}) $$

4.  **Non-Rigid Branch Feature Preparation:**
    Use the full feature $\mathbf{f}_{\mathbf{x}_c}$ but freeze the first half representing canonical radiance. Denote the remaining optimized half as $\mathbf{f}^*_{\mathbf{x}_c}$ [S1].

5.  **Pose-Embedded Implicit Feature Generation:**
    *   Initialize learnable base code $S \in \mathbb{R}^{64}$ [S1].
    *   Apply sinusoidal positional encoding $\gamma$ to the 23 joint positions $J = \{j_i\}_{i=1}^{23}$ with $L=10$ frequency bands [S1]:
        $$ \gamma(j_i) = [j_i, \sin(2^0 \pi j_i), \cos(2^0 \pi j_i), \dots, \sin(2^{L-1} \pi j_i), \cos(2^{L-1} \pi j_i)] $$
        This results in $\gamma(J) \in \mathbb{R}^{23 \times 63}$ [S1].
    *   Project encoded joints to raw pose-embedded code $\mathbf{P}_{raw}$ using projection matrix $W_p$ [S1]:
        $$ \mathbf{P}_{raw} = W_p \cdot \gamma(J) $$
    *   Generate query $\mathbf{P}_q$ from $S$, and key $\mathbf{P}_k$, value $\mathbf{P}_v$ from $\mathbf{P}_{raw}$ via linear projections [S1]:
        $$ \mathbf{P}_q = W_Q \cdot S, \quad \mathbf{P}_k = W_K \cdot \mathbf{P}_{raw}, \quad \mathbf{P}_v = W_V \cdot \mathbf{P}_{raw} $$
    *   Compute final implicit feature $\mathbf{P}_{nr}$ using cross-attention [S1]:
        $$ \mathbf{P}_{nr} = \text{softmax}(\mathbf{P}_q \cdot \mathbf{P}_k^\top) \cdot \mathbf{P}_v $$

6.  **Non-Rigid Branch Prediction:**
    Predict color and density residuals $\Delta \mathbf{c}, \Delta \sigma$ using $M_{nr}$ conditioned on $\mathbf{f}^*_{\mathbf{x}_c}$ and $\mathbf{P}_{nr}$ [S1]:
    $$ \Delta \mathbf{c}, \Delta \sigma = M_{nr}(\mathbf{f}^*_{\mathbf{x}_c}; \mathbf{P}_{nr}) $$
    The feature $\mathbf{P}_{nr}$ is concatenated to the first intermediate output of $M_{nr}$ [S1].

7.  **Compositional Rendering:**
    For each ray $\mathbf{r}$, query $M$ samples. Compute final RGB $\mathbf{C}_{final}$ using stratified sampling and volume rendering with compositional density $(\sigma + \Delta \sigma)$ and color $(\mathbf{c} + \Delta \mathbf{c})$ [S1]:
    $$ \mathbf{C}_{final}(\mathbf{r}) = \sum_{m=1}^M T_m (1 - \exp(-(\sigma_m + \Delta \sigma_m)\delta_m)) (\mathbf{c}_m + \Delta \mathbf{c}_m) $$
    where transmittance $T_m = \exp(-\sum_{n=1}^{m-1} \sigma_n \delta_n)$ and $\delta_m$ is the adjacent distance from the $m$-th to the $(m+1)$-th sample [S1].

8.  **Multi-Subject Extension (Optional):**
    For subject $i$, query global features from global MHE $\psi_{hash}^G$ and slice local features from local MHE $\psi_{hash}^i$. Concatenate global features, sliced local features, and subject ID code $S_i$ to predict $\mathbf{c}, \sigma$ [S1]:
    $$ \mathbf{c}, \sigma = M_{rigid}(\psi_{hash}^G(\mathbf{x}_c) \oplus (\psi_{hash}^i(\mathbf{x}_c))^{:H} \oplus S_i) $$

import torch
import torch.nn as nn
import torch.nn.functional as F

class MoCoNeRF:
    def __init__(self, num_joints=23, num_freq_bands=10, base_code_dim=64,

        Initialize MoCo-NeRF components.
        """
        self.num_joints = num_joints
        self.num_freq_bands = num_freq_bands
        self.base_code_dim = base_code_dim
        self.feature_dim = feature_dim
        self.is_multi_subject = is_multi_subject
        self.num_subjects = num_subjects

        self.mhe = HashGridEncoder(
            num_levels=num_levels,

            hash_table_size=hash_table_size,
            is_multi_subject=is_multi_subject,
            num_subjects=num_subjects
        )
        
        # Rigid Branch MLP
        self.m_rigid = nn.Sequential(
            nn.Linear(feature_dim, feature_dim),
            nn.ReLU(),
            nn.Linear(feature_dim, feature_dim),
            nn.ReLU(),
            nn.Linear(feature_dim, 4) # 3 for color, 1 for density
        )

        # Input: feature_dim (from MHE) + pose_embed_dim
        # Pose embed dim comes from cross-attention output
        self.m_nr = nn.Sequential(
            nn.Linear(feature_dim + base_code_dim, feature_dim),
            nn.ReLU(),
            nn.Linear(feature_dim, feature_dim),
            nn.ReLU(),
            nn.Linear(feature_dim, 4) # 3 for color residual, 1 for density residual
        )

        self.base_code = nn.Parameter(torch.randn(1, 1, base_code_dim)) # S

        self.w_q = nn.Linear(base_code_dim, base_code_dim) # W_Q
        self.w_k = nn.Linear(base_code_dim, base_code_dim) # W_K
        self.w_v = nn.Linear(base_code_dim, base_code_dim) # W_V

        """
        Apply sinusoidal positional encoding to joint positions.
        joints: Tensor of shape [batch_size, num_joints, 3]
        Returns: Tensor of shape [batch_size, num_joints, 1 + 2 * num_freq_bands]
        """
        batch_size, num_joints, _ = joints.shape
        # Concatenate original coordinates
        encoded = joints # [B, J, 3]
        
        # Generate frequency bands
        # L=10 bands as per source
        freq_bands = torch.arange(self.num_freq_bands, device=joints.device).float()
        # 2^i * pi * p
        angles = 2**freq_bands * torch.pi * joints.unsqueeze(-1) # [B, J, 3, L]
        
        sin_angles = torch.sin(angles)
        cos_angles = torch.cos(angles)
        
        # Reshape to [B, J, 3 * 2 * L] then concatenate? 
        # Source says: gamma(ji) = [ji, sin(...), cos(...)]
        # ji is 3D. sin/cos are 3D * L.
        # Total dim = 3 + 3 * 2 * L = 3 + 6L. 
        # Source says gamma(J) in R^{23x63}. 23 joints. 63 dim.
        # 3 + 6*10 = 63. Correct.
        
        sin_part = sin_angles.reshape(batch_size, num_joints, -1) # [B, J, 3L]
        cos_part = cos_angles.reshape(batch_size, num_joints, -1) # [B, J, 3L]
        
        encoded = torch.cat([joints, sin_part, cos_part], dim=-1) # [B, J, 63]
        return encoded

    def generate_pose_embed(self, joints):
        """
        Generate pose-embedded implicit feature P_nr using cross-attention.
        joints: Tensor of shape [batch_size, num_joints, 3]
        Returns: Tensor of shape [batch_size, 1, base_code_dim]
        """
        # 1. Encode joints
        gamma_j = self.sinusoidal_encoding(joints) # [B, J, 63]
        
        # 2. Project to raw pose-embedded code
        p_raw = self.w_p(gamma_j) # [B, J, base_code_dim]
        
        # 3. Linear projections
        # S is [1, 1, base_code_dim], broadcasted to batch
        p_q = self.w_q(self.base_code) # [1, 1, base_code_dim] -> [B, 1, base_code_dim]
        p_k = self.w_k(p_raw) # [B, J, base_code_dim]
        p_v = self.w_v(p_raw) # [B, J, base_code_dim]
        
        # 4. Cross-attention
        # P_q: [B, 1, D], P_k: [B, J, D]
        # Attention scores: [B, 1, J]
        attn_scores = torch.matmul(p_q, p_k.transpose(-2, -1)) # [B, 1, J]

        p_nr = torch.matmul(attn_weights, p_v) # [B, 1, base_code_dim]
        
        return p_nr

        # x_trans: [B, K, 3]
        x_trans = torch.bmm(R, x.unsqueeze(-1)).squeeze(-1) + t # [B, K, 3]
        
        # Numerator: w_c_k * x_trans_k
        # w_c: [B, K], x_trans: [B, K, 3] -> [B, K, 3]
        num = w_c.unsqueeze(-1) * x_trans # [B, K, 3]
        
        # Denominator: sum(w_c_j * x_trans_j) over K
        # This is a weighted sum of points, resulting in a single point per batch
        # Actually, the formula is w_o_k = w_c_k(x_trans_k) / sum(w_c_j(x_trans_j))
        # The denominator is a scalar per batch item? No, w_c_j(x_trans_j) is a vector.
        # Wait, the formula in source: w_o_k = w_c_k(R_k x + t_k) / sum_j w_c_j(R_j x + t_j)
        # This implies the denominator is the sum of the weighted transformed points.
        # So x_c = sum_k w_o_k (R_k x + t_k)
        # Let's compute denominator vector D = sum_j w_c_j (R_j x + t_j)
        D = torch.sum(num, dim=1) # [B, 3]
        
        # w_o_k = num_k / D
        # To avoid division by zero, add epsilon
        w_o = num / (D.unsqueeze(1) + 1e-8) # [B, K, 3]
        
        # x_c = sum_k w_o_k (R_k x + t_k)
        # w_o is already the weight for the term (R_k x + t_k)
        # So x_c = sum_k w_o_k
        x_c = torch.sum(w_o, dim=1) # [B, 3]
        
        # 2. Feature Query
        # Query MHE
        # If multi-subject, use global and local MHEs
        if self.is_multi_subject and subject_id is not None:
            # subject_id is an index or embedding
            # Global features

            # Local features

            # Slice local features
            f_local_sliced = f_local[:, :self.feature_dim//2] # Assuming half is H
            # Concatenate
            f_xc = torch.cat([f_global, f_local_sliced, subject_id], dim=-1)
        else:
            f_xc = self.mhe.query(x_c) # [B, feature_dim]
            if not self.is_multi_subject:
                # Slice for rigid branch
                f_xc_sliced = f_xc[:, :self.feature_dim//2]
                # Freeze first half for non-rigid
                f_xc_frozen = f_xc[:, :self.feature_dim//2]
                f_xc_opt = f_xc[:, self.feature_dim//2:]
        
        # 3. Rigid Branch
        # c, sigma = M_rigid(f_xc_sliced)
        rigid_out = self.m_rigid(f_xc_sliced) # [B, 4]
        c = rigid_out[:, :3]
        sigma = rigid_out[:, 3:]
        
        # 4. Non-Rigid Branch
        # Generate pose embed
        p_nr = self.generate_pose_embed(joints) # [B, 1, base_code_dim]
        
        # Prepare input for M_nr
        # Concatenate f_xc_opt and p_nr

**Parameters:**
*   $K$: Total number of joints in the skeletal model (typically 23 for human models) [S1].
*   $L$: Number of frequency bands in sinusoidal positional encoding, typically $L=10$ [S1].
*   $\lambda$: Hyperparameter for balancing rigid and final loss terms, typically $\lambda=0.2$ [S1].
*   $N_p$: Number of patches sampled per iteration [S1].
*   $M$: Number of samples per ray [S1].
*   $H$: Half the dimension of the feature vector at each resolution level [S1].

**Edge Cases and Pitfalls:**
*   **Spatial Offset Misalignment:** Traditional methods model non-rigid motions as spatial offsets, which span an unbounded range and are unique for every 3D point, leading to high computational complexity and misaligned learning objectives with RGB supervision [S1]. MoCo-NeRF avoids this by modeling residuals in radiance space [S1].
*   **Precision:** The freezing of the first half of the feature vector for the non-rigid branch requires careful initialization to ensure the frozen part does not interfere with the residual learning [S1].

## Operating characteristics
*   **Time Complexity:** Training time for 6 subjects on the ZJU-MoCap dataset is 2 hours on one RTX 3090 GPU [S1]. This is significantly more efficient than offset-based strategies which suffer from high learning complexity [S1].
*   **Memory Complexity:** Uses a single MHE for single-subject, or a global MHE plus $N_s$ local MHEs for multi-subject. The hash encoding is memory-efficient compared to dense voxel grids.
*   **Strengths:** Direct color supervision for both rigid and non-rigid components; efficient modeling of non-rigid motions without spatial offsets; scalable to multi-subject training [S1].
*   **Limitations:** Requires accurate skeletal joint positions as input [S1]. Performance depends on the quality of the canonical T-pose representation [S1].
*   **When to use:** Free-viewpoint rendering of dynamic human subjects from monocular videos, especially when non-rigid motions (e.g., cloth dynamics) are significant [S1].
*   **When not to use:** Static scenes (use standard NeRF) or scenes where skeletal information is unavailable [S1].

## Background
MoCo-NeRF was proposed by J. Kim et al. in 2024 [S1]. It addresses the challenges of novel view synthesis of monocular human videos, which involve complex articulated body motions and non-rigid motions like cloth dynamics [S1]. Previous methods modeled non-rigid motions as spatial offsets, which were computationally expensive and difficult to supervise directly [S1]. MoCo-NeRF introduces a motion-oriented compositional approach, decomposing the radiance field into rigid and non-rigid branches [S1]. It has been evaluated on the ZJU-MoCap and MonoCap datasets, demonstrating state-of-the-art performance in both single- and multi-subject settings [S1].
