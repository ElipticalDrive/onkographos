# Depth-Guided NeRF Training Configuration

Also called: Depth-Guided NeRF, DäRF Configuration

## Overview
This configuration defines the training protocol for Neural Radiance Fields (NeRF) that incorporate depth priors to improve reconstruction quality, particularly in sparse-view or noisy-pose scenarios. It distinguishes itself from standard NeRF training by integrating a depth loss term and modifying the network architecture to handle depth uncertainty, building on [Training Configuration and Optimization](18409-training-configuration-and-optimization.md).

## How it works
The method extends the original NeRF architecture by adding regularization and a depth-aware loss function.

**Inputs:**
*   Camera poses and intrinsics.
*   RGB images.
*   Depth maps (ground truth or estimated).
*   Scene bounds (min/max depth).

**Outputs:**
*   Trained NeRF model parameters.
*   Rendered RGB images and depth maps.

**Data Structures:**
*   **NeRF Network:** A multi-layer perceptron (MLP) taking positional encoding of 3D coordinates and view direction.
*   **Depth Scale:** A learnable scalar parameter for depth normalization.

**Parameters:**
*   Dropout probability: $p=0.1$ [S1].
*   Depth loss weight: $\lambda = 0.007$ (default), $\lambda = 0.02$ for scene 710 [S1].
*   Uncertainty weight: $\gamma = 1$ [S1].
*   Adam learning rate: $lr = 5 \times 10^{-4}$ [S1].
*   Depth scale learning rate: $lr_{scale} = 1 \times 10^{-7}$ [S1].
*   Weight decay: $1 \times 10^{-6}$ [S1].
*   Total steps: $500,000$ [S1].
*   LR decay step: $80\%$ of total steps [S1].

**Algorithm:**

1.  **Architecture Modification:** Initialize the NeRF network. After each of the first eight fully connected ReLU-activated layers that encode the positional encoding, insert a dropout layer with probability $p=0.1$ [S1].
2.  **Depth Thresholding:** Define a threshold $\tau$ to evaluate depth map uncertainty. Calculate $\tau$ as:
    $$ \tau = (\text{max\_depth} - \text{min\_depth}) \cdot 0.0001 $$
    For ScanNet, $\text{max\_depth} = 10$ and $\text{min\_depth} = 0.001$ [S1].
3.  **Optimization Loop:** For each training step $t$ from $1$ to $500,000$:
    a. Sample rays and render RGB and depth values.
    b. Compute photometric loss (e.g., MSE) between rendered RGB and ground truth RGB.
    c. Compute depth loss using the predicted depth $\hat{d}$ and ground truth depth $d$. The specific depth loss formulation is not detailed in the provided notes, but it is weighted by $\lambda$ [S1].
    d. Compute uncertainty-weighted loss weighted by $\gamma$ [S1].
    e. Combine losses: $L_{total} = L_{rgb} + \lambda L_{depth} + \gamma L_{uncertainty}$ [S1].
    f. Update network weights using Adam optimizer with $lr = 5 \times 10^{-4}$ and weight decay $1 \times 10^{-6}$ [S1].
    g. Update the depth scale parameter using Adam with $lr = 1 \times 10^{-7}$ [S1].
    h. If $t > 0.8 \times 500,000$, reduce the main learning rate to $5 \times 10^{-5}$ [S1].

**Edge Cases:**
*   Scene 710 requires a higher depth loss weight ($\lambda=0.02$) [S1].
*   Depth evaluation metrics (RMSE, AbsRel, etc.) are computed only on pixels with valid ground truth depth [S1].

## Subtopics

### DS-NeRF Depth Loss Integration
Integrates the depth loss implementation from the official DS-NeRF codebase into the training pipeline. Due to missing configuration files for DTU in the official release, results were reproduced on LLFF using released configuration files and specific train/test splits, as original publication results used different splits [S2].

## Operating characteristics
*   **Complexity:** Standard NeRF complexity, augmented by depth loss computation.
*   **Performance:** Improves depth accuracy and reconstruction quality in sparse-view settings [S1].
*   **Limitations:** Requires depth priors (ground truth or estimated). Performance may degrade if depth priors are noisy or inaccurate without proper uncertainty weighting [S1].
*   **Hardware:** Not specified in sources.

## Background
Originated from the DäRF (Depth-guided NeRF) method, which incorporates depth priors into NeRF training to address challenges in sparse-view reconstruction. The configuration details were provided in the supplementary material of the DäRF paper [S1].
