# SUDS

Also called: Scalable Urban Dynamic Scenes

## Overview
SUDS is a 4D radiance field representation designed for large-scale dynamic urban scenes that factorizes the scene into three separate hash table data structures to efficiently encode static, dynamic, and far-field radiance fields [S1]. It solves the problem of scaling neural reconstruction to city-level footprints with tens of thousands of objects and ego-motion by using unlabeled target signals (RGB, sparse LiDAR, 2D descriptors, 2D optical flow) for supervision, avoiding the need for 3D bounding boxes or panoptic labels [S1]. Unlike sibling methods that rely on per-object NeRFs or supervised annotations, SUDS uses a multi-branch hash encoding to disentangle static background, dynamic objects, and lighting variations across multiple videos [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ordered RGB images from $N$ videos taken at different days with diverse weather/lighting, associated camera poses, aligned sparse LiDAR depth measurements, 2D self-supervised DINO descriptors, and 2D optical flow predictions [S1].
*   **Outputs:** View-dependent color $\mathbf{c}$, volume density $\sigma$, semantic features $\Phi$, and 3D scene flow vectors $\mathbf{s}$ for arbitrary poses and time steps [S1].

**Data Structures:**
The scene is decomposed into $K$ spatial cells, each trained independently with its own static, dynamic, and far-field branches [S1]. Each branch uses a multi-resolution hash table [S1].
*   **Hash Tables:** For each resolution level $l \in \{1, \dots, L\}$, features are stored in hash tables indexed by hash functions [S1].
    *   **Static Branch:** 3D spatial voxels $\mathbf{v}_{l,s}$. Hash index: $i_{l,s} = \text{static hash}(\text{space}(\mathbf{v}_{l,s}))$ [S1].
    *   **Dynamic Branch:** 4D spacetime voxels $\mathbf{v}_{l,d}$. Hash index: $i_{l,d} = \text{dynamic hash}(\text{space}(\mathbf{v}_{l,d}), \text{time}(\mathbf{v}_{l,d}), \text{vid})$ [S1].
    *   **Far-field Branch:** 3D direction voxels $\mathbf{v}_{l,e}$. Hash index: $i_{l,e} = \text{env hash}(\text{dir}(\mathbf{v}_{l,e}), \text{vid})$ [S1].
*   **Feature Vector:** Features from all $L$ levels are concatenated into a vector $\mathbf{f} \in \mathbb{R}^{LF}$, where $F$ is the feature dimensionality [S1].
*   **Hash Collisions:** Handled via gradient averaging [S1].

**Parameters:**
*   $L$: Number of resolution levels in the hash table hierarchy, where resolution doubles between levels [S1].
*   $F$: Dimensionality of feature vectors in the hash tables [S1].
*   $N$: Number of input videos [S1].
*   $\text{vid}$: Video ID identifier used as an auxiliary input to the hash function [S1].
*   $A_{\text{vid}}$: Video-specific matrix for lighting variation embedding [S1].
*   $C$: Dimensionality of the DINO feature grid output ($\mathbb{R}^{H \times W \times C}$) [S1].
*   $k$: Constant set to 1.75 in the skewed binary entropy loss [S1].
*   Training: 250,000 iterations, 4098 rays per batch, Adam optimizer with learning rate decaying from $5 \times 10^{-3}$ to $5 \times 10^{-4}$ [S1].

**Steps:**

1.  **Spatial Partitioning:** Split the scene into $K$ spatial cells with centroids $\mathbf{k} \in \mathbb{R}^3$. Generate separate training datasets for each cell by including only datapoints whose camera rays intersect the cell. Prune irrelevant rays using LiDAR depth measurements to ensure visibility [S1].
2.  **Voxel Lookup:** For an input coordinate $(\mathbf{x}, \mathbf{d}, t, \text{vid})$ where $\mathbf{x}$ is position, $\mathbf{d}$ is viewing direction, $t$ is frame index, and $\text{vid}$ is video ID, find surrounding voxels at $L$ resolution levels for the static ($\mathbf{v}_{l,s}$), dynamic ($\mathbf{v}_{l,d}$), and far-field ($\mathbf{v}_{l,e}$) branches [S1].
3.  **Hash Indexing:** Compute hash indices for voxel corners using the specific hash functions defined above. The $\text{vid}$ is included in the dynamic and far-field hashes to index separate interpolating functions for each video without linear memory growth [S1].
4.  **Feature Interpolation:**
    *   Look up feature vectors corresponding to the corners.
    *   Linearly interpolate features for the static branch.
    *   Use quadlinear interpolation for the dynamic 4D branch [S1].
    *   Concatenate results from all $L$ levels into $\mathbf{f} \in \mathbb{R}^{LF}$ [S1].
5.  **MLP Evaluation:** Pass $\mathbf{f}$ concatenated with auxiliary inputs (viewing direction $\mathbf{d}$, lighting embedding) into separate MLPs for each branch [S1].
    *   **Static Branch Output:** View-dependent color $\mathbf{c}_s(\mathbf{x}, \mathbf{d}, A_{\text{vid}}\mathbf{F}(t)) \in \mathbb{R}^3$ and view-independent density $\sigma_s(\mathbf{x}) \in \mathbb{R}$. Lighting conditioning uses a Fourier-encoded time index $\mathbf{F}(t)$ and video-specific matrix $A_{\text{vid}}$ [S1].
    *   **Dynamic Branch Output:** Time/video-dependent density $\sigma_d(\mathbf{x}, t, \text{vid}) \in \mathbb{R}$, color $\mathbf{c}_d(\mathbf{x}, t, \text{vid}, \mathbf{d}) \in \mathbb{R}^3$, scalar shadow ratio $\rho_d(\mathbf{x}, t, \text{vid}) \in [0, 1]$, and semantic features $\Phi_d(\mathbf{x}, t, \text{vid}) \in \mathbb{R}^C$. Also predicts forward/backward 3D scene flow $\mathbf{s}_{t0}(\mathbf{x}, t, \text{vid}) \in \mathbb{R}^3$ with values in $[-1, 1]$ [S1].
    *   **Far-field Branch Output:** Environment map color $\mathbf{c}_e(\mathbf{d}, \text{vid}) \in \mathbb{R}^3$ and semantic features $\Phi_e(\mathbf{d}, \text{vid}) \in \mathbb{R}^C$ [S1].
6.  **Density Combination:** Compute total density as the sum of static and dynamic densities:
    $$ \sigma(\mathbf{x}, t, \text{vid}) = \sigma_s(\mathbf{x}) + \sigma_d(\mathbf{x}, t, \text{vid}) $$
    [S1]
7.  **Radiance Combination:** Compute total radiance by combining static and dynamic components, scaled by the shadow ratio:
    $$ \mathbf{c}(\mathbf{x}, t, \text{vid}, \mathbf{d}) = \frac{(1 - \rho_d)\sigma_s \mathbf{c}_s + \sigma_d \mathbf{c}_d}{\sigma} $$
    [S1]
8.  **Rendering:** Render color $\hat{\mathbf{C}}$ for a camera ray $\mathbf{r}$ by accumulating transmittance along sampled points $\mathbf{r}(t)$:
    $$ \hat{\mathbf{C}}(\mathbf{r}, t, \text{vid}) = \int_0^{+\infty} T(t)\sigma(\mathbf{r}(t), t, \text{vid})\mathbf{c}(\mathbf{r}(t), t, \text{vid}, \mathbf{d}) dt + T(+\infty)\mathbf{c}_e(\mathbf{d}, \text{vid}) $$
    where $T(t) = \exp\left(-\int_0^t \sigma(\mathbf{r}(s), t, \text{vid}) ds\right)$ [S1].
9.  **Loss Calculation:** Minimize the following losses [S1]:
    *   **Reconstruction:** L2 photometric loss $\mathcal{L}_c(\mathbf{r}) = \|\mathbf{C}(\mathbf{r}) - \hat{\mathbf{C}}(\mathbf{r})\|^2$ and L1 feature loss $\mathcal{L}_f(\mathbf{r}) = \|\mathbf{F}(\mathbf{r}) - \hat{\mathbf{F}}(\mathbf{r})\|_1$ [S1].
    *   **Depth:** L2 loss between observed LiDAR depth $\mathbf{D}(\mathbf{r})$ and rendered depth $\hat{\mathbf{D}}(\mathbf{r}) = \int_0^{+\infty} T(s)\sigma(\mathbf{r}(s)) ds$ [S1].
    *   **Flow:** Predict 3D position $\hat{\mathbf{X}}_{t0}(\mathbf{r}) = \int_0^{+\infty} T(t)\sigma(\mathbf{r}(t))(\mathbf{r}(t) + \mathbf{s}_{t0}(\mathbf{r}(t))) dt$. Render to 2D using neighboring camera matrix. Minimize distance from observed optical flow $\mathbf{O}$ via $\mathcal{L}_o(\mathbf{r}) = \sum_{t0} \|\mathbf{X}(\mathbf{o}) - \hat{\mathbf{X}}_{t0}(\mathbf{r})\|_1$ [S1].
    *   **3D Warping:** Advect samples using predicted flow $\mathbf{s}_{t0}$ to get warped density $\sigma^w$, color $\mathbf{c}^w$, features $\Phi^w$. Render warped color $\hat{\mathbf{C}}^w$ and feature $\hat{\mathbf{F}}^w$. Downweight loss in ambiguous regions using weight $W_{t0}(\mathbf{r})$ derived from dynamic geometry difference. Minimize $\mathcal{L}_c^w$ and $\mathcal{L}_f^w$ [S1].
    *   **Flow Regularization:** Cycle consistency $\mathcal{L}_{cyc}(\mathbf{r}) = \sum_{t0} \sum_{\mathbf{x}} w_{t0}(\mathbf{x}, t) \|\mathbf{s}_{t0}(\mathbf{x}, t) + \mathbf{s}_t(\mathbf{x}+\mathbf{s}_{t0}, t-t0)\|_1$. Spatial/temporal smoothness $\mathcal{L}_{sm}$ and static scene prior $\mathcal{L}_{slo} = \sum_{t0} \sum_{\mathbf{x}} \|\mathbf{s}_{t0}(\mathbf{x}, t)\|_1$ [S1].
    *   **Static-Dynamic Factorization:** Skewed binary entropy loss $\mathcal{L}_e(\mathbf{r}) = \int_0^{+\infty} H\left(\frac{\sigma_d(\mathbf{r}(t))}{\sigma_s(\mathbf{r}(t)) + \sigma_d(\mathbf{r}(t))}\right) dt$ with $k=1.75$, where $H(x) = -(x \log x + (1-x) \log (1-x))$. Penalize max dynamic ratio $\mathcal{L}_d(\mathbf{r}) = \max\left(\frac{\sigma_d}{\sigma_s + \sigma_d}\right)$ along each ray [S1].
    *   **Shadow Loss:** Penalize squared magnitude of shadow ratio $\mathcal{L}_\rho(\mathbf{r}) = \int_0^{+\infty} \rho_d(\mathbf{r}(t))^2 dt$ [S1].

## Operating characteristics
*   **Time Complexity:** Training takes 250,000 iterations with 4098 rays per batch [S1]. It is 10x quicker to train than state-of-the-art methods that rely on ground truth 3D bounding box annotations [S1].
*   **Memory Complexity:** Scales to tens of thousands of objects across 1.2 million frames from 1700 videos spanning geospatial footprints of hundreds of kilometers [S1]. Uses multi-resolution hash tables to manage memory efficiently, avoiding the linear memory growth of per-object NeRFs (e.g., NSG requires over 1TB for a 30-second video) [S1].
*   **Strengths:** Handles ego-motion and multi-video representations; uses unlabeled inputs (RGB, LiDAR, optical flow) for supervision; enables free-viewpoint rendering, semantic decomposition, and 3D scene flow [S1].
*   **Limitations:** Requires aligned sparse LiDAR depth and 2D optical flow predictions as "free" supervision sources; relies on self-supervised DINO descriptors for semantic features [S1].

## Background
SUDS (Scalable Urban Dynamic Scenes) was introduced in 2023 by the authors of the paper "SUDS: Scalable Urban Dynamic Scenes" [S1]. It addresses the limitations of prior dynamic scene representations that require supervised inputs like panoptic segmentation labels or bounding boxes, which are difficult to acquire for in-the-wild captures [S1]. It builds on ideas from Instant-NGP for hash table encoding and MegaNeRF for spatial partitioning [S1].
