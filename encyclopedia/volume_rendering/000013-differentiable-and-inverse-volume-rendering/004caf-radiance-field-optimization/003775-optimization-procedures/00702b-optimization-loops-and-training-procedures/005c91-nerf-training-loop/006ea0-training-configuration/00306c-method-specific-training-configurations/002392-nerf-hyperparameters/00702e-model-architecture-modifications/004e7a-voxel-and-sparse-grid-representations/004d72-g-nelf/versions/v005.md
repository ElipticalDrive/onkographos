# G-NeLF

Also called: Grid-based Neural Light Field, Memory- and Data-Efficient Hybrid Neural Light Field

## Overview
G-NeLF is a grid-based Neural Light Field (NeLF) method for novel view synthesis that predicts ray color directly without point-wise volume density modeling [S1, unofficial]. It represents a ray as a sequence of spatial-aware features extracted from a hash-based multi-resolution tri-plane, which are decoded by an LSTM network to predict color [S1, unofficial]. Unlike standard NeRF methods that model density and color per point, G-NeLF bypasses explicit physical modeling to achieve high performance with significantly fewer parameters (e.g., 0.95 MB) and less training data (≤100 views) [S1, unofficial]. It sets itself apart from sibling NeLF methods like R2L by using a spatial-aware feature sequence instead of direct coordinate concatenation, and from grid-based NeRFs like Instant-NGP by using a ray-wise representation that requires roughly one-tenth the parameters [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Camera pose (origin $\mathbf{o}$, direction $\mathbf{d}$), bounding box of the scene, and the learned model parameters (hash tables, LSTM weights).
*   **Output:** Predicted ray color $(r, g, b)$.

**Data Structures:**
1.  **Hash Table:** A lookup table mapping integer coordinate pairs to feature vectors.
    *   **Size ($T$):** $2^{14}$ for small/medium models, $2^{16}$ for large models [S1, unofficial].
    *   **Content:** Learnable feature vectors.
2.  **Tri-Plane:** Three orthogonal feature planes ($\pi_{xy}, \pi_{xz}, \pi_{yz}$) [S1, unofficial].
    *   Each plane has $N$ resolutions.
    *   **Resolutions:** 8 levels from 16 to 1024 (small/medium); 16 levels from 16 to 2048 (large) [S1, unofficial].
    *   **Feature Dimension:** 2 per level [S1, unofficial].
3.  **LSTM Decoder:** A recurrent neural network with 2 layers (small/medium) or 3 layers (large) [S1, unofficial].
    *   **Hidden Size:** 32 (small), 128 (medium), 128 (large) [S1, unofficial].

**Algorithm Steps:**

1.  **Ray Emission:** For each pixel in the target image, emit a ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ based on the camera model [S1, unofficial].
2.  **Sampling:** Sequentially sample $K$ points along the ray within the scene's bounding box.
    *   **Sequence Length ($K$):** 256 for 360° scenes, 128 for forward-facing scenes [S1, unofficial].
    *   Let the sampled points be $\{\mathbf{x}_1, \dots, \mathbf{x}_K\}$ ordered from near to far [S1, unofficial].
3.  **Feature Extraction (Point Feature Acquirement):** For each sampled point $\mathbf{x}_i$:
    a.  **Projection:** Project $\mathbf{x}_i$ onto the three orthogonal planes $\pi \in \{\pi_{xy}, \pi_{xz}, \pi_{yz}\}$ to obtain 2D coordinates $\mathbf{x}_\pi$ [S1, unofficial].
    b.  **Hash Lookup:** For each resolution level $j \in \{1, \dots, N\}$ with grid size $s_j$:
        i.  Compute integer grid indices for the four corners of the cell containing $\mathbf{x}_\pi$:
            $$
            \begin{aligned}
            \text{idx}_{tl} &= (\lfloor x_\pi[0]/s_j \rfloor, \lfloor x_\pi[1]/s_j \rfloor) \\
            \text{idx}_{tr} &= (\lfloor x_\pi[0]/s_j \rfloor, \lfloor x_\pi[1]/s_j \rfloor + 1) \\
            \text{idx}_{bl} &= (\lfloor x_\pi[0]/s_j \rfloor + 1, \lfloor x_\pi[1]/s_j \rfloor) \\
            \text{idx}_{br} &= (\lfloor x_\pi[0]/s_j \rfloor + 1, \lfloor x_\pi[1]/s_j \rfloor + 1)
            \end{aligned}
            $$
        ii. Calculate hash indices for these corners using the hash function:
            $$ \text{Index} = (x_a \oplus y_b) \pmod T $$
            where $x_a, y_b$ are the integer coordinates, $\oplus$ is XOR, and $T$ is the hash table size [S1, unofficial].
        iii. Retrieve feature vectors $\mathbf{f}_{tl}, \mathbf{f}_{tr}, \mathbf{f}_{bl}, \mathbf{f}_{br}$ from the hash table using the calculated indices [S1, unofficial].
        iv. Perform trilinear interpolation (weighted sum) of these four features based on the fractional distance of $\mathbf{x}_\pi$ within the cell to obtain the feature vector $\mathbf{f}_{\pi,j}$ for this resolution [S1, unofficial].
    c.  **Concatenation:** Concatenate the feature vectors from all $N$ resolutions for plane $\pi$ to form $\mathbf{F}_\pi$ [S1, unofficial].
    d.  **Point Feature Vector:** Concatenate the features from all three planes:
        $$ \mathbf{F}_i = \text{Concat}([\mathbf{F}_{\pi_{xy}}, \mathbf{F}_{\pi_{xz}}, \mathbf{F}_{\pi_{yz}}]) $$
        The dimension of $\mathbf{F}_i$ is $3 \times N \times 2$ [S1, unofficial].
4.  **Direction Encoding:** Encode the ray's 3D normalized direction vector $\mathbf{d}$ using Spherical Harmonics (SH) [S1, unofficial]. Let the encoded direction be $\mathbf{d}_{enc}$ [S1, unofficial].
5.  **LSTM Decoding:** Process the feature sequence $\{\mathbf{F}_1, \dots, \mathbf{F}_K\}$ sequentially using a 2-layer (or 3-layer for large) LSTM [S1, unofficial].
    a.  Initialize hidden state $\mathbf{H}_0$ and cell state $\mathbf{C}_0$ to zero [G].
    b.  For $i = 1$ to $K$:
        $$ \mathbf{H}_i, \mathbf{C}_i = \text{LSTM}(\text{Concat}(\mathbf{F}_i, \mathbf{d}_{enc}), \mathbf{H}_{i-1}, \mathbf{C}_{i-1}) $$
        where $\text{Concat}(\cdot)$ combines the point feature and encoded direction [S1, unofficial].
6.  **Color Prediction:** Pass the final hidden state $\mathbf{H}_K$ through a 2-layer MLP to predict the ray color:
    $$ (r, g, b) = \text{MLP}(\mathbf{H}_K) $$
    [S1, unofficial].

**Pseudocode:**

```python
import math

def get_hash_index(x, y, table_size):
    """Calculate hash index using XOR and modulo."""
    return (x ^ y) % table_size

def trilinear_interpolate(f_tl, f_tr, f_bl, f_br, frac_x, frac_y):
    """
    Perform trilinear interpolation (bilinear in 2D plane) for features.
    frac_x, frac_y are fractional parts of the coordinate within the cell [0, 1).
    """
    # Interpolate along x
    f_top = f_tl * (1 - frac_x) + f_tr * frac_x
    f_bottom = f_bl * (1 - frac_x) + f_br * frac_x
    # Interpolate along y
    return f_top * (1 - frac_y) + f_bottom * frac_y

def get_point_feature(x_3d, tri_plane_params, hash_tables):
    """
    Extract feature vector for a 3D point from the hash-based tri-plane.
    x_3d: (3,) array, 3D coordinate.
    tri_plane_params: dict containing 'N' (num resolutions), 's' (list of grid sizes).
    hash_tables: dict mapping plane_name -> list of hash tables (one per resolution).
    """
    N = tri_plane_params['N']
    s = tri_plane_params['s']
    planes = ['xy', 'xz', 'yz']
    
    point_features = []
    
    for plane in planes:
        plane_features = []
        # Project 3D point to 2D plane
        if plane == 'xy':
            x_2d = [x_3d[0], x_3d[1]]
        elif plane == 'xz':
            x_2d = [x_3d[0], x_3d[2]]
        elif plane == 'yz':
            x_2d = [x_3d[1], x_3d[2]]
            
        for j in range(N):
            grid_size = s[j]
            # Integer indices
            ix = int(math.floor(x_2d[0] / grid_size))
            iy = int(math.floor(x_2d[1] / grid_size))
            
            # Fractional parts
            fx = (x_2d[0] / grid_size) - ix
            fy = (x_2d[1] / grid_size) - iy
            
            # Corner indices
            corners = [
                (ix, iy),
                (ix, iy + 1),
                (ix + 1, iy),
                (ix + 1, iy + 1)
            ]
            
            # Retrieve features from hash table
            # Note: In implementation, hash_tables[plane][j] is the table for resolution j
            table = hash_tables[plane][j]
            features = []
            for cx, cy in corners:
                idx = get_hash_index(cx, cy, table['size'])
                # Retrieve feature vector at index idx
                f = table['data'][idx]
                features.append(f)
                
            f_tl, f_tr, f_bl, f_br = features
            f_interp = trilinear_interpolate(f_tl, f_tr, f_bl, f_br, fx, fy)
            plane_features.append(f_interp)
            
        # Concatenate features from all resolutions for this plane
        plane_feat_concat = concatenate_along_last_dim(plane_features)
        point_features.append(plane_feat_concat)
        
    # Concatenate features from all three planes
    final_feature = concatenate_along_last_dim(point_features)
    return final_feature

def g_nelf_render(ray_origin, ray_direction, model_params):
    """
    Render a single ray using G-NeLF.
    """
    # 1. Sample points along the ray
    # K points, ordered from near to far
    K = model_params['K']
    t_vals = linspace(model_params['t_near'], model_params['t_far'], K)
    points = [ray_origin + t * ray_direction for t in t_vals]
    
    # 2. Extract feature sequence
    feature_sequence = []
    for p in points:
        F_i = get_point_feature(p, model_params['tri_plane'], model_params['hash_tables'])
        feature_sequence.append(F_i)
        
    # 3. Encode direction

    # 4. LSTM Decoding
    # Initialize states
    H_prev = zeros(model_params['lstm_hidden_size'])
    C_prev = zeros(model_params['lstm_hidden_size'])

        # Concatenate feature and direction
        input_vec = concatenate([F_i, d_enc])
        # LSTM step
        H_curr, C_curr = lstm_step(input_vec, H_prev, C_prev, model_params['lstm_weights'])
```

**Parameters and Typical Values:**
*   **Hash Table Size ($T$):** $2^{14}$ (small/medium), $2^{16}$ (large) [S1, unofficial].
*   **Resolutions ($N$):** 8 (small/medium), 16 (large) [S1, unofficial].
*   **Grid Sizes:** 16 to 1024 (small/medium), 16 to 2048 (large) [S1, unofficial].
*   **Feature Dimension per Level:** 2 [S1, unofficial].
*   **LSTM Hidden Size:** 32 (small), 128 (medium), 128 (large) [S1, unofficial].
*   **LSTM Layers:** 2 (small/medium), 3 (large) [S1, unofficial].
*   **Sequence Length ($K$):** 256 (360°), 128 (forward-facing) [S1, unofficial].
*   **Model Size:** 0.95 MB (small), 1.41 MB (medium) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** At the highest resolution, approximately 100,000 spatial positions map to a single hash entry [S1, unofficial]. This is not a critical error because points far from the visible surface have low weight in the rendering process (though G-NeLF doesn't use density, the spatial distribution of features still benefits from this adaptive concentration) and do not significantly affect the final color prediction, allowing high-resolution features to adaptively capture appearance details [S1, unofficial].
*   **Sequential Order:** The method relies on the temporal order of the ray feature sequence. Using permutation-invariant architectures like Transformers or simple MLPs on concatenated features degrades performance because they ignore the near-to-far propagation order [S1, unofficial].
*   **Training Data:** Requires only original training views (≤100). It does not require synthesizing pseudo-views, which simplifies training compared to earlier NeLF methods [S1, unofficial].

## Operating characteristics
*   **Model Size:** Extremely compact. 0.95 MB for the small model, 1.41 MB for the medium model [S1, unofficial]. This is approximately one-tenth the size of Instant-NGP (64.1 MB) and TensoRF (71.8 MB) [S1, unofficial].
*   **Performance:** On the Realistic Synthetic 360° dataset at 400x400 resolution, G-NeLF surpasses R2L by 0.04 dB PSNR with only 100 views and 0.95 MB model size [S1, unofficial]. It surpasses VQRF by 0.79 dB PSNR at a comparable model size (1.4 MB) [S1, unofficial]. It achieves rendering quality comparable to standard NeRF methods [S1, unofficial].
*   **Training Data:** Requires 100 or fewer original views. No pseudo-views are synthesized [S1, unofficial].
*   **Hardware:** Experiments conducted on a single RTX 3090 GPU using float16 precision [S1, unofficial].
*   **Strengths:** High data efficiency (works with few views), extremely small model size, comparable quality to much larger grid-based NeRFs.
*   **Limitations:** Does not model explicit volume density, which may limit its applicability in tasks requiring physical properties (e.g., relighting, shadow casting) compared to NeRF-based methods. Performance is tied to the specific ray-wise representation and may not generalize to all types of scenes as robustly as density-based methods without careful tuning.

## Background
G-NeLF was introduced in the paper "G-NeLF: Memory- and Data-Efficient Hybrid Neural Light Field for Novel View Synthesis" [S1, unofficial]. It addresses the limitations of previous Neural Light Field (NeLF) methods, which often required training a NeRF first and synthesizing thousands of views to train the NeLF, leading to high storage and computational costs [S1, unofficial]. G-NeLF proposes a hybrid approach combining grid-based spatial awareness with a recurrent neural network to directly predict ray colors, enabling high-quality novel view synthesis with minimal resources.
