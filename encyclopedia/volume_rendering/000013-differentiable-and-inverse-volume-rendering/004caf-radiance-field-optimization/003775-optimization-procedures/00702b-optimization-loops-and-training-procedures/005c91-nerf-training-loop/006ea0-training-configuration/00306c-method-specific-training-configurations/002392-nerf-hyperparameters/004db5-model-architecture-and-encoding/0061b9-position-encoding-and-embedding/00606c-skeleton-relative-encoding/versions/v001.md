# Skeleton-Relative Encoding

Also called: A-NeRF Skeleton-Relative Encoding, Relative Encoding, Skeleton-Relative Input Encoding

## Overview
Skeleton-Relative Encoding transforms query locations and view directions into local bone-relative coordinate systems before processing them through a neural radiance field, explicitly incorporating domain knowledge of human body part linkage [S1, unofficial]. It differs from standard NeRF by reparameterizing the input space to respect articulated motion, allowing the model to learn pose-dependent deformations and appearance without relying on explicit parametric surface models like SMPL [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   World query position $q \in \mathbb{R}^3$.
*   Incoming ray direction $d \in \mathbb{R}^3$.
*   Skeleton pose parameters $\theta_k$ for frame $k$, defining the transformation $T(\theta_k, m)$ from local bone $m$ coordinates to world coordinates.
*   Bone index $m \in \{1, \dots, 24\}$.

**Outputs:**
*   Combined encoding vector $e_k \in \mathbb{R}^D$, which serves as the input to the NeRF network $F_\phi$ to predict color and opacity.

### Data Structures
*   **Skeleton Pose:** Represented by a set of 24 bones. The transformation $T(\theta_k, m)$ maps a point from the local coordinate system of bone $m$ to the world coordinate system at frame $k$. The inverse transformation $T^{-1}(\theta_k, m)$ maps world coordinates to local bone coordinates.
*   **Bone-Relative Position:** $\tilde{q}_{k,m} \in \mathbb{R}^3$.
*   **Relative Distance:** $\tilde{v}_{k,m} \in \mathbb{R}$.
*   **Relative Direction:** $\tilde{r}_{k,m} \in \mathbb{R}^3$.
*   **Relative Ray Direction:** $\tilde{d}_{k,m} \in \mathbb{R}^3$.
*   **Cutoff Value:** $h(\tilde{v}_{k,m}) \in \mathbb{R}$.

### Steps

1.  **Compute Bone-relative Position:** For each bone $m$, transform the world query position $q$ into the local coordinate system of bone $m$ using the inverse pose transformation [S1, unofficial]:
    $$ \tilde{q}_{k,m} = T^{-1}(\theta_k, m)q $$
    This is computed for all $m \in \{1, \dots, 24\}$ [S1, unofficial].

2.  **Compute Relative Distance:** Calculate the L2 norm of the bone-relative position to obtain the radial distance from the bone origin [S1, unofficial]:
    $$ \tilde{v}_{k,m} = \|\tilde{q}_{k,m}\|_2 $$

3.  **Compute Relative Direction:** Normalize the bone-relative position to obtain the direction vector from the bone origin to the query point [S1, unofficial]:
    $$ \tilde{r}_{k,m} = \frac{\tilde{q}_{k,m}}{\|\tilde{q}_{k,m}\|_2} $$
    *Note:* This direction encoding is passed directly into the final encoding without subsequent positional encoding [S1, unofficial].

4.  **Compute Relative Ray Direction:** Rotate the incoming world ray direction $d$ by the rotational part of the inverse bone-to-world transformation to obtain the ray direction relative to the bone [S1, unofficial]:
    $$ \tilde{d}_{k,m} = [T^{-1}(\theta_k, m)]_{3\times3} d $$
    where $[T^{-1}(\theta_k, m)]_{3\times3}$ is the $3\times3$ rotational component of the inverse transformation matrix.

5.  **Apply Cutoff Function:** To reduce the influence of irrelevant (distant) bones, apply a cutoff function $h$ to the distance and ray direction encodings [S1, unofficial]:
    $$ h(\tilde{v}_{k,m}) = 1 - S(\tau(\tilde{v}_{k,m} - t)) $$
    where $S$ is the sigmoid function, $t$ is the cutoff point, and $\tau$ is the sharpness parameter.

6.  **Construct Final Encoding:** Combine the components into the final input vector $e_k$ for the NeRF network [S1, unofficial]:
    $$ e_k = [h(\tilde{v}_k)\Gamma(\tilde{v}_k), \tilde{r}_k, h(\tilde{v}_k)\Gamma(\tilde{d}_k)] $$
    Here, $\Gamma$ denotes the positional encoding (PE) function applied to the relative distance $\tilde{v}_k$ and relative ray direction $\tilde{d}_k$. The relative direction $\tilde{r}_k$ is concatenated directly. The subscript $k$ indicates that these vectors are computed for all 24 bones, resulting in concatenated vectors for the entire skeleton.

### Pseudocode

```python
import numpy as np

def skeleton_relative_encoding(q, d, pose_transforms, t, tau, gamma_func):
    """
    Computes the skeleton-relative encoding for a query point and ray direction.
    
    Args:
        q: World query position, shape (3,)
        d: Incoming ray direction, shape (3,)
        pose_transforms: List of 24 inverse bone-to-world transformation matrices T_inv,
                         each shape (4, 4). T_inv[m] corresponds to bone m.
        t: Cutoff point for the sigmoid function.
        tau: Sharpness parameter for the sigmoid function.
        gamma_func: Positional encoding function, takes a scalar or vector and returns encoded vector.
    
    Returns:
        e_k: Combined encoding vector, shape (D,)
    """
    num_bones = 24
    encoded_distances = []
    encoded_ray_dirs = []
    relative_directions = []
    cutoffs = []
    
    for m in range(num_bones):
        # Step 1: Bone-relative Position
        # Transform world query q to local bone coordinates
        q_homogeneous = np.append(q, 1.0)
        q_local_homogeneous = pose_transforms[m] @ q_homogeneous
        q_local = q_local_homogeneous[:3]
        
        # Step 2: Relative Distance
        v_m = np.linalg.norm(q_local)
        
        # Step 3: Relative Direction
        # Handle degenerate case where q_local is near zero
        if v_m < 1e-8:
            r_m = np.zeros(3)
        else:
            r_m = q_local / v_m
            
        # Step 4: Relative Ray Direction
        # Extract rotational part (3x3) of the inverse transformation
        R_inv = pose_transforms[m][:3, :3]
        d_local = R_inv @ d
        
        # Step 5: Cutoff Function
        # h(v) = 1 - sigmoid(tau * (v - t))
        sigmoid_val = 1.0 / (1.0 + np.exp(-tau * (v_m - t)))
        h_m = 1.0 - sigmoid_val
        
        # Step 6: Construct Components
        # Apply positional encoding to distance and ray direction, scaled by cutoff
        # gamma_func should handle scalar input for distance and vector for ray direction
        enc_v = gamma_func(v_m) * h_m
        enc_d = gamma_func(d_local) * h_m
        
        encoded_distances.append(enc_v)
        encoded_ray_dirs.append(enc_d)
        relative_directions.append(r_m)
        cutoffs.append(h_m)
        
    # Concatenate all bone encodings
    # Note: The paper specifies e_k = [h(v_k)Gamma(v_k), r_k, h(v_k)Gamma(d_k)]
    # This implies concatenating the encoded vectors for all bones.
    final_encoding = np.concatenate([
        np.concatenate(encoded_distances),
        np.concatenate(relative_directions),
        np.concatenate(encoded_ray_dirs)
    ])
    
    return final_encoding
```

### Parameters
*   **Number of bones:** 24 [S1, unofficial].
*   **Cutoff point ($t$):** Not given in the sources.
*   **Sharpness ($\tau$):** Not given in the sources.
*   **Positional Encoding ($\Gamma$):** Standard NeRF positional encoding [S1, unofficial].

### Edge Cases and Pitfalls
*   **Dimensionality:** Bone-relative position encoding (concatenating $\tilde{q}_{k,m}$ for all bones) increases dimensionality by an order of magnitude compared to relative distance encoding. The relative distance encoding is preferred for lower dimensionality and better reconstruction accuracy [S1, unofficial].
*   **Direction Encoding:** Relative direction encoding ($\tilde{r}_{k,m}$) does not benefit from subsequent positional encoding and is passed directly into the final encoding vector $e_k$ [S1, unofficial].
*   **Degenerate Input:** If the query point $q$ coincides with the bone origin, the relative direction vector is undefined. A guard such as returning a zero vector or a default direction should be implemented [G].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of bones ($O(N_{bones})$) for the encoding computation, as each bone's transformation and encoding must be computed independently.
*   **Memory Complexity:** Proportional to the number of bones and the dimensionality of the positional encoding. Using relative distance instead of bone-relative position reduces memory usage [S1, unofficial].
*   **Strengths:** Incorporates domain knowledge of articulated motion, improves reconstruction accuracy for human bodies, and allows for pose-dependent deformation [S1, unofficial].
*   **Limitations:** Requires a skeleton pose estimator for initialization and runtime [S1, unofficial]. Ambiguities can arise when a query point is at equal distance to multiple bones, though relative distance encoding mitigates this compared to bone-relative position [S1, unofficial].

## Background
Skeleton-Relative Encoding was introduced in A-NeRF (Articulated Neural Radiance Fields) by [S1, unofficial]. It was designed to learn human shape, appearance, and pose from monocular video without relying on explicit parametric surface models like SMPL, instead using the skeleton as a guide for reparameterizing the NeRF input space.
