# Voxel-based Radiance Fields

Also called: Voxel NeRF, Voxel Radiance Fields

## Overview
Voxel-based Radiance Fields replace the multi-layer perceptron (MLP) of standard NeRF with explicit voxel grids to store volume density and spherical harmonic (SH) coefficients, enabling real-time volume rendering by eliminating heavy feed-forward neural computations [S1]. Unlike hash-based or dense MLP approaches, this method limits learnable parameters strictly to grid values, allowing for memory-efficient training via coarse-to-fine sparse voxel reconstruction and pruning [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D spatial position $\mathbf{X}_k$ and viewing direction $\mathbf{d}$ for a sample point $k$ on a ray.
*   **Output:** Volume density $\sigma_k$ and view-dependent color $\mathbf{c}_k$.

**Data Structures:**
Two separate voxel grids are maintained:
1.  **Density Grid ($G_\sigma$):** Maps $\mathbb{R}^3 \rightarrow \mathbb{R}$. Stores scalar volume density values.
2.  **SH Coefficient Grid ($G_{sh}$):** Maps $\mathbb{R}^3 \rightarrow \mathbb{R}^{9 \times 3}$. Stores degree-2 spherical harmonic coefficients for RGB color. Each spatial location stores a vector of 9 coefficients per color channel (total 27 values per voxel).

**Interpolation:**
For any query point $\mathbf{X}_k$, features are retrieved via trilinear interpolation from the nearest 8 neighboring voxels in both $G_\sigma$ and $G_{sh}$ [S1].

**Formulas:**
The volume density is computed as:
$$ \sigma_k = \mathcal{G}_\sigma(\mathbf{X}_k) $$
where $\mathcal{G}_\sigma$ denotes trilinear interpolation from $G_\sigma$ [S1].

The color is computed as:
$$ \mathbf{c}_k = S(\mathbf{d})^\intercal \cdot \mathcal{G}_{sh}(\mathbf{X}_k) $$
where:
*   $S(\mathbf{d}): \mathbb{R}^3 \rightarrow \mathbb{R}^9$ is the spherical harmonic function mapping the viewing direction $\mathbf{d}$ to a 9-dimensional basis vector [S1].
*   $\mathcal{G}_{sh}(\mathbf{X}_k)$ is the trilinearly interpolated vector of SH coefficients from $G_{sh}$ at $\mathbf{X}_k$ [S1].
*   The dot product combines the direction basis with the spatial features to produce the RGB color vector $\mathbf{c}_k$ [S1].

**Pseudocode:**
```python
def compute_voxel_radiance_field(X_k, d, G_sigma, G_sh):
    """
    Compute density and color for a sample point using voxel grids.
    
    Args:
        X_k: 3D spatial position (float32[3])
        d: Viewing direction (float32[3])
        G_sigma: Density grid (3D tensor)
        G_sh: SH coefficient grid (3D tensor, last dim 27)
        
    Returns:
        sigma_k: Volume density (float32)
        c_k: Color RGB (float32[3])
    """
    # 1. Trilinear interpolation for density
    # G_sigma is assumed to be a 3D array indexed by [x, y, z]
    # Trilinear interpolation from nearest 8 voxels
    sigma_k = trilinear_interpolate(G_sigma, X_k)
    
    # 2. Trilinear interpolation for SH coefficients
    # G_sh stores 27 values (9 SH coeffs * 3 RGB channels) per voxel
    sh_coeffs = trilinear_interpolate(G_sh, X_k) # Returns float32[27]
    
    # 3. Compute SH basis vector for direction d
    # Degree 2 SH basis has 9 components
    sh_basis = compute_sh_basis(d) # Returns float32[9]
    
    # 4. Compute color
    # Reshape sh_coeffs to [3, 9] or [9, 3] depending on storage layout.
    # Standard layout implies sh_coeffs[i] corresponds to channel i // 9?
    # Or sh_coeffs is [9, 3] where row is SH order, col is RGB.
    # Based on formula c_k = S(d)^T . G_sh(X_k), G_sh(X_k) must be [9, 3] or [3, 9] transposed.
    # Assuming G_sh stores [9, 3] (9 SH coeffs, 3 RGB channels):
    # sh_coeffs shape: [9, 3]
    
    # Dot product: [1, 9] @ [9, 3] -> [1, 3]
    c_k = sh_basis @ sh_coeffs.T # If sh_coeffs is [9, 3], this is wrong.
    # Correct: c_k = S(d)^T . V, where V is [9, 3]. Result is [3].
    # c_k[j] = sum_i S(d)[i] * V[i, j]
    
    c_k = np.dot(sh_basis, sh_coeffs) # If sh_coeffs is [9, 3], dot([9], [9,3]) -> [3]
    
    return sigma_k, c_k

def trilinear_interpolate(grid, point):
    """
    Perform trilinear interpolation from a 3D grid at a continuous point.
    """
    # Get fractional coordinates
    x, y, z = point
    # Get integer base coordinates
    ix, iy, iz = floor(x), floor(y), floor(z)
    # Get fractional offsets
    fx, fy, fz = x - ix, y - iy, z - iz
    
    # Retrieve 8 corner values
    # Handle boundary conditions (clamp or wrap) [G]
    v000 = grid[ix, iy, iz]
    v100 = grid[ix+1, iy, iz]
    v010 = grid[ix, iy+1, iz]
    v110 = grid[ix+1, iy+1, iz]
    v001 = grid[ix, iy, iz+1]
    v101 = grid[ix+1, iy, iz+1]
    v011 = grid[ix, iy+1, iz+1]
    v111 = grid[ix+1, iy+1, iz+1]
    
    # Interpolate along x
    v00 = lerp(v000, v100, fx)
    v01 = lerp(v010, v110, fx)
    v10 = lerp(v001, v101, fx)
    v11 = lerp(v011, v111, fx)
    
    # Interpolate along y
    v0 = lerp(v00, v01, fy)
    v1 = lerp(v10, v11, fy)
    
    # Interpolate along z
    return lerp(v0, v1, fz)

def lerp(a, b, t):
    return a + t * (b - a)

def compute_sh_basis(d):
    """
    Compute degree 2 spherical harmonic basis vector for direction d.
    Returns float32[9].
    """
    # Standard degree 2 SH basis functions evaluated at d
    # x, y, z are components of normalized direction d
    x, y, z = d
    # Basis functions (unnormalized constants omitted or included in grid weights)
    # Typically: [1, x, y, z, x^2, xy, xz, y^2, yz] or similar ordering
    # Exact ordering must match training. Standard order [S1] implies 9 coeffs.
    # Common order: Y0, Y1, Y2, Y3, Y4, Y5, Y6, Y7, Y8
    # Y0 ~ 1
    # Y1 ~ x, Y2 ~ y, Y3 ~ z
    # Y4 ~ x^2, Y5 ~ xy, Y6 ~ xz, Y7 ~ y^2, Y8 ~ yz (simplified)
    # Note: Precise normalization factors are usually absorbed into the grid weights [G]
    return np.array([1.0, x, y, z, x*x, x*y, x*z, y*y, y*z])
```

**Edge Cases and Pitfalls:**
*   **Boundary Handling:** Trilinear interpolation requires handling coordinates outside the grid bounds. Clamping or wrapping must be defined [G].
*   **SH Basis Ordering:** The ordering of the 9 SH coefficients in $G_{sh}$ must match the implementation of `compute_sh_basis` exactly [S1].
*   **Memory:** While more efficient than MLPs, dense voxel grids still consume significant memory for high-resolution scenes. Sparse reconstruction and pruning are required for scalability [S1].

## Operating characteristics
*   **Time Complexity:** Rendering is significantly faster than MLP-based NeRF because it replaces expensive fully-connected layer computations with simple memory lookups and trilinear interpolation [S1]. This enables real-time volume rendering.
*   **Memory Complexity:** Memory usage is proportional to the number of voxels. It is more memory-efficient than dense MLPs for comparable resolution but less efficient than sparse hash grids for highly sparse scenes [S1].
*   **Strengths:** Real-time rendering capability; memory-efficient parameterization; compatible with differentiable volume rendering [S1].
*   **Limitations:** Resolution is limited by voxel grid size; aliasing artifacts may occur at high frequencies if grid resolution is insufficient; requires coarse-to-fine strategies and pruning for large scenes [S1].
*   **When to Use:** Applications requiring real-time rendering and moderate resolution, such as blurred view reconstruction or interactive applications [S1].
*   **When Not to Use:** Scenes requiring extremely high frequency details without massive grid sizes, or highly sparse environments where hash-based or octree methods are superior.

## Background
Voxel-based Radiance Fields were introduced as a memory-efficient alternative to MLP-based NeRF, replacing the neural network with voxel grids for density and spherical harmonic coefficients [S1]. This approach was notably applied in ExBluRF for efficient radiance field optimization in the presence of extreme motion blur [S1]. The method leverages differentiable volume rendering while eliminating feed-forward operations to achieve real-time performance [S1].
