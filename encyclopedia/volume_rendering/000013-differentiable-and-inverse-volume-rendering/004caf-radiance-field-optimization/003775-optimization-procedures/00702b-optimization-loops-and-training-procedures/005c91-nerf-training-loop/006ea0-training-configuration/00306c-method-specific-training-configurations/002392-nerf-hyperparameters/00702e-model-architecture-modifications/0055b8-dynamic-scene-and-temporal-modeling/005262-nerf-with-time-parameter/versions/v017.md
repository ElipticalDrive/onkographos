# NeRF with Time Parameter

Also called: NeRF + time, NeRF with Time Parameter Baseline, Time-NeRF

## Overview
NeRF with Time Parameter is a baseline method for adapting static Neural Radiance Fields (NeRF) to dynamic scenes by explicitly conditioning the radiance field on a temporal coordinate [S1]. It solves the problem of representing time-varying geometry and appearance by extending the input domain of the implicit function from $(\mathbf{x}, \mathbf{d})$ to $(\mathbf{x}, \mathbf{d}, t)$ [S1]. Unlike deformation-based approaches that warp points to a canonical space, this method treats time as a direct conditioning signal [S1]. It sets itself apart from siblings like [Gear-NeRF](13848-gear-nerf.md) or [ST-NeRF](18515-st-nerf.md) by its simplicity: it modifies only the input encoding and MLP conditioning, without introducing explicit deformation fields, particle systems, or complex temporal attention mechanisms [S1].

## How it works
The method modifies the standard NeRF architecture to accept a time parameter $t$. The core task is to learn a continuous volumetric scene representation $F_\Theta: (\mathbf{x}, \mathbf{d}, t) \rightarrow (\sigma, \mathbf{c})$, where $\mathbf{x} \in \mathbb{R}^3$ is the spatial position, $\mathbf{d} \in \mathbb{R}^3$ is the viewing direction, $t \in \mathbb{R}$ is the time parameter, $\sigma$ is the volume density, and $\mathbf{c} \in \mathbb{R}^3$ is the view-dependent color [G].

**Inputs and Outputs:**
*   **Input:** A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$, sampled at $N$ points $\mathbf{x}_i$ along the ray, and a specific time instance $t$.
*   **Output:** Volume density $\sigma_i$ and color $\mathbf{c}_i$ for each sample point.

**Data Structures:**
The model consists of a Multi-Layer Perceptron (MLP) with weights $\Theta$. The input layer receives a concatenated vector of positional encodings.
*   **Positional Encoding $\gamma(\cdot)$:** Standard NeRF positional encoding is used for spatial coordinates $\mathbf{x}$ and viewing direction $\mathbf{d}$ [S1].
*   **Time Encoding:** The scalar time parameter $t$ is also positionally encoded using $\gamma(t)$ [S1].

**Steps:**
1.  **Encode Inputs:** Compute the positional encoding for the spatial coordinates $\gamma(\mathbf{x})$ and the time parameter $\gamma(t)$ [S1].
2.  **Concatenate:** Concatenate the spatial encoding and time encoding to form the combined spatial-temporal input vector: $\mathbf{v} = [\gamma(\mathbf{x}), \gamma(t)]$ [S1]. Note: The viewing direction $\mathbf{d}$ is typically encoded separately and concatenated later in the standard NeRF architecture (e.g., after the first hidden layer for the color branch), but the time parameter is specifically fused with the spatial features [S1].
3.  **Forward Pass:** Pass the concatenated vector $\mathbf{v}$ through the density MLP to obtain $\sigma$ and intermediate features [S1].
4.  **Color Prediction:** Combine the intermediate features with the encoded viewing direction $\gamma(\mathbf{d})$ and pass them through the color MLP to obtain $\mathbf{c}$ [S1].
5.  **Volume Rendering:** Integrate $\sigma_i$ and $\mathbf{c}_i$ along the ray using standard volume rendering equations to compute the final pixel color [G].

**Pseudocode:**
```python
import torch
import torch.nn as nn

class NeRFTime(nn.Module):
    def __init__(self, D=8, W=256, skips=[4], input_ch=3, input_ch_dir=3, input_ch_time=1):
        super().__init__()
        # Standard NeRF architecture components
        self.D = D
        self.W = W
        self.input_ch = input_ch
        self.input_ch_dir = input_ch_dir
        self.input_ch_time = input_ch_time
        
        # Density network
        self.pts_linears = nn.ModuleList([nn.Linear(input_ch + input_ch_time, W)] + 
                                         [nn.Linear(W, W) for _ in range(D - 1)])
        self.output_linear = nn.Linear(W, 1) # Output sigma
        
        # Color network
        self.dir_linears = nn.ModuleList([nn.Linear(W + input_ch_dir, W // 2)])
        self.output_linear_color = nn.Linear(W // 2, 3) # Output color
        
        # Skips are applied to the input of the D-th layer
        self.skips = skips

    def forward(self, x, d, t):
        """
        x: [N, 3] spatial coordinates
        d: [N, 3] viewing directions
        t: [N, 1] time parameters
        """
        # 1. Encode time and concatenate with spatial coordinates
        # Assuming gamma is a function that returns positional encodings
        # In a real implementation, gamma would be applied before this module or as a layer
        x_enc = gamma(x) # [N, L_x]
        t_enc = gamma(t) # [N, L_t]
        
        # Concatenate spatial and time encodings
        x_t_enc = torch.cat([x_enc, t_enc], dim=-1) # [N, L_x + L_t]
        
        # 2. Density Network
        h = x_t_enc
        for i, linear in enumerate(self.pts_linears):
            h = linear(h)
            h = torch.relu(h)
            if i in self.skips:
                h = torch.cat([x_t_enc, h], dim=-1)
        
        sigma = self.output_linear(h) # [N, 1]
        sigma = torch.relu(sigma) # Ensure non-negative density
        
        # 3. Color Network
        # Concatenate features from density network with direction encoding
        d_enc = gamma(d) # [N, L_d]
        h_dir = torch.cat([h, d_enc], dim=-1)
        
        for linear in self.dir_linears:
            h_dir = linear(h_dir)
            h_dir = torch.relu(h_dir)
            
        color = self.output_linear_color(h_dir) # [N, 3]
        color = torch.sigmoid(color) # Ensure color in [0, 1]
        
        return sigma, color
```

**Parameters:**
*   **Training Configuration:** The method is trained using the configuration reported for NeRF's real forward-facing experiments [S1]. This typically includes learning rates, batch sizes, and number of iterations as defined in the original NeRF paper [S1].
*   **Time Normalization:** The time parameter $t$ should be normalized to a consistent range (e.g., $[0, 1]$) across the sequence to ensure stable training [G].

**Edge Cases and Pitfalls:**
*   **Blurriness:** The method suffers from blurry predictions and lacks detail compared to more complex dynamic methods [S1].
*   **Ghosting:** Even with the time parameter, small changes in camera pose can lead to slightly different viewing directions for spatial points across frames, causing severe ghosting artifacts if the scene dynamics are not perfectly captured by the time conditioning alone [S1].
*   **Lack of Dynamics Reasoning:** The method fails to reason about scene dynamics explicitly; it relies on the MLP to interpolate between states, which can lead to uncertain predictions in regions of high motion [S1].

## Subtopics

### Temporal Compression of NeRF Models
A compression strategy for sequences of NeRF models that exploits temporal redundancy by treating the first model as a key-frame and compressing only the deltas between successive models [S2].
*   **Definition:** This approach leverages the observation that neighboring NeRF models share considerable similarities [S2]. It treats the first model as a reference "I-frame" and stores only the weight differences (deltas) for subsequent frames [S2].
*   **Steps:**
    1.  Initialize the NeRF for the first frame from scratch [S2].
    2.  For subsequent frames, initialize the new NeRF based on the previous frame's trained NeRF to encourage temporal redundancy and save training time [S2].
    3.  Calculate the delta between the current frame's NeRF weights and the previous frame's NeRF weights [S2].
    4.  Apply exponent-based quantization and Huffman coding to the deltas [S2].
    5.  To restore a model, accumulate the decoded deltas to the reference model (the previous frame's model) [S2].
*   **When to choose:** Use this when storage or transmission bandwidth is constrained and the scene dynamics are smooth enough that weight deltas are small and compressible [S2].

## Operating characteristics
*   **Time Complexity:** Training time is comparable to standard NeRF, as the computational graph is similar, with the addition of time encoding [S1]. However, it may require more iterations to converge to a satisfactory dynamic representation due to the increased complexity of the input space [S1].
*   **Memory Complexity:** Memory usage is similar to standard NeRF, as the model size is determined by the MLP dimensions, which are not significantly increased by the addition of the time parameter [S1].
*   **Performance:** On dynamic scenes (e.g., KITTI), NeRF + time achieves higher PSNR and SSIM than vanilla NeRF but significantly lower performance than methods designed for dynamics (e.g., Neural Scene Graphs) [S1]. It suffers from blurry predictions and fails to capture fine details [S1].
*   **Strengths:** Simple to implement; requires minimal changes to the standard NeRF codebase [S1].
*   **Limitations:** Poor handling of complex dynamics; prone to ghosting and blurring; does not explicitly model motion [S1].
*   **When to use:** As a baseline for comparison; for scenes with very slow or minimal dynamics where simplicity is preferred over accuracy [S1].
*   **When not to use:** For scenes with significant motion, complex interactions, or high-frequency details [S1].

## Background
The method was introduced as a baseline to assess the capabilities of existing implicit methods for dynamic scenes [S1]. It was proposed in the context of comparing against more advanced dynamic scene representations, such as Neural Scene Graphs [S1]. The approach builds on the original NeRF paper [S1], extending its input domain to include time [S1].
