# Conditional and Latent Representations

Also called: Conditional Radiance Fields, Latent NeRFs

## Overview
Conditional and Latent Representations extend the standard NeRF architecture [Parent](11313-model-architecture-modifications.md) to model entire object categories (e.g., chairs, cars) rather than single static scenes, using instance-specific latent vectors for shape and appearance [S1, S2]. This approach enables a single unified network to represent multiple distinct 3D instances, allowing for efficient multi-instance training, text- or image-driven manipulation, and editing without per-sample optimization during inference [S1, S2].

## Shared principles
The family replaces the single-scene assumption with a conditional mapping that takes spatial position $\mathbf{x}$, viewing direction $\mathbf{d}$, and instance-specific latent codes as inputs. The core mechanism involves disentangling shape and appearance into separate latent vectors, typically denoted as $\mathbf{z}^{(s)}$ (shape) and $\mathbf{z}^{(c)}$ or $\mathbf{z}_a$ (appearance/color) [S1, S2].

The network function $F$ maps these inputs to scalar density $\sigma$ and radiance color $\mathbf{c}$ [S1]:
$$
(\mathbf{c}, \sigma) = F(\mathbf{x}, \mathbf{d}, \mathbf{z}^{(s)}, \mathbf{z}^{(c)})
$$
Key structural constraints include:
1.  **Density Independence:** The density output $\sigma$ is generally independent of the viewing direction $\mathbf{d}$, depending only on position and shape code [S1].
2.  **Radiance Dependence:** The radiance output $\mathbf{c}$ depends on position, viewing direction, and appearance code [S1].
3.  **Latent Optimization:** The latent codes $\mathbf{z}^{(s)}$ and $\mathbf{z}^{(c)}$ are learnable parameters optimized alongside network weights during training for each instance in the dataset [S1].
4.  **Rendering:** Rendering follows standard volume rendering with alpha compositing [S1, S2]:
    $$
    \hat{C}(r, \mathbf{z}^{(s)}, \mathbf{z}^{(c)}) = \sum_{i=1}^{N_c} c_i \alpha_i \exp \left( -\sum_{j=1}^{i-1} \sigma_j \delta_j \right)
    $$
    where $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$ and $\delta_i = t_{i+1} - t_i$ [S1].

## Subtopics

### [Conditional Radiance Field Training](15963-conditional-radiance-field-training.md)
Trains a conditional radiance field on a dataset of $K$ instances by learning instance-specific latent codes $\mathbf{z}_k^{(s)}$ and $\mathbf{z}_k^{(c)}$. It uses two 4-layer MLPs (256 channels) with skip connections and stratified/hierarchical sampling. It is chosen when the goal is to model a dataset of varying instances with a single network architecture, achieving accuracy comparable to per-instance NeRFs.

### [Conditional Radiance Field with Shared Branch](15964-conditional-radiance-field-with-shared-branch.md)
Disentangles shape and color using a modular architecture with a shared shape branch ($F_{\text{share}}$), instance-specific shape branch ($F_{\text{inst}}$), and fusion network ($F_{\text{fuse}}$). It improves view synthesis quality (PSNR 35.79 vs 33.91 on PhotoShapes) and facilitates scaling to larger datasets compared to standard conditional fields. Choose this when higher fidelity and better disentanglement are required for multi-instance training.

### [Conditional NeRF Implementation Details](16755-conditional-nerf-implementation-details.md)
A generative model mapping 5D coordinates and latent vectors to density/radiance, featuring a deformation network to disentangle shape from appearance and feed-forward mappers for text/image-driven manipulation. It differs by enabling text- and image-driven manipulation without per-sample optimization during inference. Choose this for interactive editing and generation tasks.

### Conditional Radiance Field
#### definition
- A neural network representation that extends NeRF to model an entire object class (e.g., chairs) rather than a single scene, using latent vectors for shape and appearance to allow editing [S1].
- The network $F$ takes a 3D location $\mathbf{x}$, viewing direction $\mathbf{d}$, and instance-specific latent vectors $\mathbf{z}^{(s)}$ and $\mathbf{z}^{(c)}$ to output radiance $\mathbf{c}$ and density $\sigma$ [S1].
- The density output $\sigma$ is independent of the viewing direction [S1].
- The radiance output $\mathbf{c}$ depends on both position and viewing direction [S1].

#### step
- Sample $N_c$ 3D points $\{t_i\}$ along a cast ray $r$ from pixel location, ordered near to far [S1].
- Compute radiance $c_i$ and density $\sigma_i$ at each sampled point $t_i$ using network $F$ [S1].

#### formula
- Alpha compositing value: $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$, where $\delta_i = t_{i+1} - t_i$ is the distance between adjacent samples [S1].

#### parameter
- $\mathbf{x}$: 3D location vector $(x, y, z)$ [S1].
- $\mathbf{d}$: viewing direction vector $(\phi, \theta)$ [S1].
- $\mathbf{z}^{(c)}$: latent color (appearance) vector [S1].

#### layout
- Network $F$ is parametrized as a multi-layer perceptron (MLP) [S1].

### Continuous Manipulation via Latent Space Scaling
#### definition
- A technique to achieve gradual editing of shape and appearance by scaling the editing direction vectors in the latent space using a scalar factor [S2].

#### formula
- $\mathbf{z}_s = s \times \Delta \mathbf{z}_s + \mathbf{z}_{s0}$, $\mathbf{z}_a = s \times \Delta \mathbf{z}_a + \mathbf{z}_{a0}$, where $s$ is a scalar, $\mathbf{z}_s$ and $\mathbf{z}_a$ are the updated shape and appearance codes, $\mathbf{z}_{s0}$ and $\mathbf{z}_{a0}$ are the original codes, and $\Delta \mathbf{z}_s$ and $\Delta \mathbf{z}_a$ are the manipulation directions provided by the code mappers [S2].

#### parameter
- Scalar $s$: Controls the intensity of the edit. Typical range: 0 to 1.6 with step 0.2. Effect: Manipulation strength increases as $s$ increases [S2].

#### usage
- Used for continuous editing of both shape and appearance given a single text prompt or exemplar, allowing users to adjust the degree of change [S2].

### CLIP-Driven Manipulation
#### step
- 1. Extract CLIP feature embedding from input text prompt or exemplar image. 2. Feed embedding into two separate feed-forward code mappers (shape mapper and appearance mapper). 3. Mappers output local displacements in the latent space to update $\mathbf{z}_s$ and $\mathbf{z}_a$. 4. Render image with updated codes. 5. Train mappers using a CLIP-based matching loss to enforce CLIP space consistency between input constraint and output renderings [S2].

#### comparison
- Differs from optimization-based editing (e.g., EditNeRF) by using learned feed-forward networks mapping user edits to latent codes, enabling fast inference for interactive editing instead of slow iterative optimization per sample [S2].

## Background
The concept of conditional radiance fields was introduced by Chan et al. in "Editing Conditional Radiance Fields" (ICCV 2021) [S1]. This work extended the original NeRF representation [45] to model entire shape classes (e.g., chairs) by learning instance-specific latent vectors for shape and appearance. The primary motivation was to enable editing over a class of objects rather than a single scene, allowing the disentanglement of shape and appearance for modification during editing [S1].

Later, "CLIP-NeRF: Text-and-Image Driven Manipulation of Neural Radiance Fields" (CVPR 2022) [S2] built upon this foundation by integrating the CLIP model [34]. This approach introduced code mappers that map CLIP features to the latent space, enabling text- and image-driven manipulation. It addressed the slowness of iterative optimization methods (like EditNeRF) by using feed-forward networks for fast inference, supporting global deformation and intuitive editing via text prompts or exemplar images [S2].
