# Multi-input MLP (mi-MLP)
Also called: mi-MLP, per-layer inputs incorporation

## Overview
The multi-input MLP (mi-MLP) is a network structure modification for Neural Radiance Fields that incorporates the raw input embeddings (3D location and viewing direction) into every layer of the MLP, rather than only at the input stage. It solves the overfitting problem in few-shot view synthesis by creating shorter paths between inputs and outputs, allowing the model to synthesize high-quality details with fewer parameters while maintaining the capacity of the original architecture. Unlike vanilla NeRF, which relies on deep implicit mappings, mi-MLP ensures each layer is explicitly aware of the input embeddings, alleviating overfitting without harming detailed synthesis [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 5D coordinate vector $\mathbf{x}$, composed of the 3D spatial position $\mathbf{p} \in \mathbb{R}^3$ and the 2D viewing direction $\mathbf{d} \in \mathbb{R}^2$ (normalized).
*   **Output:** Volume density $\sigma$ and RGB color $\mathbf{c}$.

**Data Structures:**
*   **Positional Encoding $\gamma_L(\mathbf{x})$:** A vector in $\mathbb{R}^{2L}$ generated by applying sinusoidal positional encoding to $\mathbf{x}$.
*   **Layer Weights:** For layer $i$, weights are split into $\mathbf{w}_i^{j0} \in \mathbb{R}^{1 \times d_1}$ (connecting to input embeddings) and $\mathbf{w}_i^{j1} \in \mathbb{R}^{1 \times d_2}$ (connecting to previous layer features).
*   **Layer Biases:** $\mathbf{b}_i \in \mathbb{R}^{d_2 \times 1}$.

**Parameters:**
*   **$L$:** Hyperparameter controlling the number of frequency bands in positional encoding. Default values vary by implementation, but $L$ determines the dimension $d_1 = 2L$ of the input embedding $\gamma_L(\mathbf{x})$.
*   **Activation Function $\epsilon$:** Default is ReLU [S1].
*   **Weight Initialization:** Default PyTorch initialization is used, which satisfies the condition $\|\mathbf{w}_i^{j1}\|_1 \in (0, 1]$ [S1].

**Step-by-Step Method:**

1.  **Encode Inputs:** Compute the positional encoding of the 5D input $\mathbf{x}$:
    $$ \gamma_L(\mathbf{x}) = (\sin(2^0 \mathbf{x}), \cos(2^0 \mathbf{x}), \dots, \sin(2^{L-1} \mathbf{x}), \cos(2^{L-1} \mathbf{x})) $$
    where $\mathbf{x}$ is concatenated or treated as a single 5D vector for the encoding function [S1].

2.  **Initialize First Layer:** Compute the output of the first layer $f_1$ using only the encoded inputs:
    $$ f_1 = \phi_1(\gamma_L(\mathbf{x})) $$
    where $\phi_1$ is the first layer function [S1].

3.  **Iterate Through Hidden Layers:** For each subsequent layer $i$ (where $i > 1$), compute the output feature $f_i$ by combining the previous layer's output $f_{i-1}$ and the encoded inputs $\gamma_L(\mathbf{x})$:
    $$ f_i = \phi_i(f_{i-1}, \gamma_L(\mathbf{x})) $$
    This explicit concatenation or addition ensures the input information is available at every depth [S1].

4.  **Compute Layer Element:** For the $j$-th element of the output feature vector $f_i$, the computation is:
    $$ \phi_i^j(\gamma_L(\mathbf{x})) = \epsilon\left( \mathbf{w}_i^{j0}[\gamma_L(\mathbf{x})] + \mathbf{w}_i^{j1}[f_{i-1}] + \mathbf{b}_i \right) $$
    where:
    *   $\epsilon$ is the activation function (ReLU).
    *   $\mathbf{w}_i^{j0}$ connects the input embedding to the $j$-th neuron.
    *   $\mathbf{w}_i^{j1}$ connects the previous layer's output to the $j$-th neuron.
    *   $\mathbf{b}_i$ is the bias vector [S1].

5.  **Output Prediction:** The final layer outputs the volume density $\sigma$ and color $\mathbf{c}$. Note that mi-MLP often models these separately using distinct MLPs or heads to handle the different frequency characteristics of geometry and appearance [S1].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import math

class PositionalEncoding(nn.Module):
    def __init__(self, L):
        super().__init__()
        self.L = L

    def forward(self, x):
        # x shape: (..., 5) -> (batch, 5)
        # Frequencies: 2^0 to 2^(L-1)
        freq_bands = 2.0 ** torch.arange(self.L, device=x.device).float()
        # Expand x to (..., 5, L) and freq_bands to (L,)
        # sin(2^k * x) and cos(2^k * x)
        x_expanded = x.unsqueeze(-1) * freq_bands.unsqueeze(0) # (..., 5, L)
        sin_vals = torch.sin(x_expanded)
        cos_vals = torch.cos(x_expanded)
        # Concatenate along the last dimension: (..., 5, 2, L) -> (..., 10*L)
        out = torch.cat([sin_vals, cos_vals], dim=-1).flatten(start_dim=-2)
        return out

class MiMLPLayer(nn.Module):
    def __init__(self, input_dim, output_dim):
        super().__init__()
        self.linear = nn.Linear(input_dim + input_dim, output_dim) # Input + Prev Output
        # Note: The paper describes separate weights w0 and w1. 
        # In standard linear layer: W * [x, h_prev] + b = W0*x + W1*h_prev + b
        # We initialize weights to satisfy ||w1||_1 in (0, 1] if required, 
        # though PyTorch default is stated to work.
        
    def forward(self, x_enc, h_prev):
        # x_enc: encoded inputs (gamma_L(x))
        # h_prev: output of previous layer
        combined = torch.cat([x_enc, h_prev], dim=-1)
        return self.linear(combined)

class MiMLP(nn.Module):
    def __init__(self, L, hidden_dim, num_layers):
        super().__init__()
        self.pos_enc = PositionalEncoding(L)
        self.input_dim = 5 * 2 * L # 5D input * 2 (sin/cos) * L bands
        
        layers = []
        # First layer takes only encoded input
        layers.append(nn.Linear(self.input_dim, hidden_dim))
        
        # Subsequent layers take encoded input + previous output
        for _ in range(num_layers - 1):
            layers.append(MiMLPLayer(self.input_dim, hidden_dim))
            
        self.layers = nn.ModuleList(layers)
        self.relu = nn.ReLU()
        
        # Separate heads for density and color as per the paper's extension
        self.density_head = nn.Linear(hidden_dim, 1)
        self.color_head = nn.Linear(hidden_dim, 3)

    def forward(self, x):
        # x: (..., 5)
        x_enc = self.pos_enc(x)
        
        h = self.layers[0](x_enc)
        h = self.relu(h)
        
        for i in range(1, len(self.layers)):
            # Each layer gets x_enc and previous hidden state
            h = self.layers[i](x_enc, h)
            h = self.relu(h)
            
        sigma = self.density_head(h)
        color = self.color_head(h)
        
        return sigma, color
```

**Edge Cases and Pitfalls:**
*   **Gradient Amplitude:** During early training, mi-MLP ensures deeper layers receive large gradients while shallower layers receive extremely small ones, unlike vanilla MLP where gradients are similar across layers. This behavior is critical for convergence [S1].
*   **Weight Initialization:** The condition $\|\mathbf{w}_i^{j1}\|_1 \in (0, 1]$ is theoretically required for the gradient ratio property. Default PyTorch initialization satisfies this, but custom initialization must respect this bound [S1].
*   **Separate Modeling:** While mi-MLP defines the layer structure, the paper recommends modeling density and color separately to reduce artifacts, as geometry is smoother than appearance. Using a single shared head may leave residual artifacts [S1].

## Operating characteristics
*   **Time Complexity:** Similar to vanilla NeRF per forward pass, but potentially faster convergence in few-shot settings due to alleviated overfitting.
*   **Memory Complexity:** Slightly higher memory usage per layer due to the concatenation of input embeddings $\gamma_L(\mathbf{x})$ at every layer, increasing the input dimension to each linear layer from $d_{prev}$ to $d_{prev} + d_{input}$ [S1].
*   **Performance:** Boosts PSNR significantly in few-shot view synthesis (e.g., from 14.73 to 24.23 on specific benchmarks) compared to baseline NeRF [S1].
*   **Strengths:** Prevents overfitting in data-scarce scenarios; maintains high-frequency detail synthesis; plug-and-play with existing NeRF pipelines [S1].
*   **Limitations:** Requires careful handling of input encoding dimensions; may introduce artifacts if density and color are not modeled separately [S1].

## Background
The mi-MLP was introduced in the paper "Is Vanilla MLP in Neural Radiance Field Enough for Few-Shot View Synthesis?" (CVPR 2024) [S1]. It addresses the observation that trivially reducing parameters alleviates overfitting but loses detail. By incorporating inputs into each layer, it provides an orthogonal solution to the overfitting problem in few-shot view synthesis, revealing that shorter paths between inputs and outputs allow for effective synthesis with fewer parameters while keeping model capacity unchanged [S1].
