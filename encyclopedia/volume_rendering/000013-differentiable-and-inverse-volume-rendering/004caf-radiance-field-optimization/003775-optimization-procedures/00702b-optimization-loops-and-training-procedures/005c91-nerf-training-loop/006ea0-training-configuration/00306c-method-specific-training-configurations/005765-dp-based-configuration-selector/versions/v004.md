# DP-based Configuration Selector

Also called: Multiple-Choice Knapsack Configuration Selection, Dynamic-programming-based configuration selection, MCK-based configuration selection, NeRFlex configuration selector

## Overview
The DP-based Configuration Selector optimizes neural radiance field (NeRF) configurations for multiple segmented objects under a strict global memory constraint $H$ [S1]. It formulates the selection task as a Multiple-Choice Knapsack (MCK) problem, which is NP-hard [S1]. Unlike greedy approaches that require a feasibility condition frequently violated by multi-knob NeRF configurations, this method uses dynamic programming to guarantee an optimal quality allocation within the memory limit [S1]. It is specifically designed for mobile deployment where exceeding memory limits triggers rendering failures or severe performance degradation [S1].

## How it works
**Inputs and Outputs**
*   **Input:**
    *   $I$: The set of segmented objects, with cardinality $n = |I|$ [S1].
    *   $C_i$: The discrete configuration space for object $i$ [S1].
    *   $f_{si}(\theta)$: A profiling function estimating the memory size of object $i$'s NeRF representation given configuration $\theta$ [S1].
    *   $f_{qi}(\theta)$: A profiling function estimating the rendering quality of object $i$'s NeRF representation given configuration $\theta$ [S1].
    *   $H$: The maximum allowed total memory size for the multi-modal NeRF representation [S1].
*   **Output:**
    *   `configs`: A list of pairs $(i, \theta_i^*)$ representing the selected optimal configuration for each object $i$ [S1].

**Data Structures**
The algorithm utilizes three primary data structures [S1]:
1.  `q`: A 1D array of size $H+1$. `q[j]` stores the maximum achievable total quality for the processed objects using capacity $j$ [S1].
2.  `choices`: A 2D array of dimensions $n \times (H+1)$. `choices[i][j]` stores the configuration pair $\theta$ selected for object $i$ at capacity $j$ [S1].
3.  `configs`: An empty list to store the final selected configuration pairs during backtracking [S1].

**Parameters**
*   **Configuration Pair $\theta_i = (g_i, p_i)$**: Represents the geometry resolution knob $g_i$ and texture parameter knob $p_i$ for object $i$ [S1].
*   **Memory Constraint $H$**: Fixed memory size available on the target device [S1]. Typical values are 240MB for iPhone 13 and 150MB for Pixel 4 [S1].
*   **Baseline Configuration**: For single NeRF or Block-NeRF baselines, the recommended pair is $(128, 17)$ [S1].

**Algorithm Steps**
The algorithm proceeds in two phases: DP table filling and backtracking [S1].

1.  **Initialization**:
    *   For each object $i \in I$, initialize the minimum configuration $\theta_i^* \leftarrow \min(C_i) = (\min(g_i), \min(p_i))$ [S1].
    *   Initialize `q` as an array of zeros of length $H+1$ [S1].
    *   Initialize `choices` as a 2D array of nulls with dimensions $n \times (H+1)$ [S1].
    *   Initialize `configs` as an empty list [S1].

2.  **DP Table Filling**:
    Iterate through each object $i$ from $0$ to $n-1$ [S1]. For each object, iterate through the capacity $j$ from $H$ down to $0$ [S1].
    
    For each configuration $\theta \in C_i$:
    *   **Calculate Threshold**: Compute the minimum memory required by all other objects $h \neq i$ using their minimum configurations:
        $$ r_i = H - \sum_{h=1, h \neq i}^{n} \min_{\theta_t \in C_h} f_{sh}(\theta_t) $$
        [S1]
    *   **Feasibility Check**: If the size of the current configuration $f_{si}(\theta) \ge r_i$, skip this configuration [S1]. This ensures that selecting $\theta$ leaves enough room for the minimal configurations of all other objects, satisfying the feasibility condition [S1].
    *   **State Transition**: If the current capacity $j$ is sufficient for the configuration ($j \ge f_{si}(\theta)$):
        *   Calculate the potential new quality: $Q_{new} = q[j - f_{si}(\theta)] + f_{qi}(\theta)$ [S1].
        *   If $q[j] < Q_{new}$:
            *   Update `q[j]` $\leftarrow Q_{new}$ [S1].
            *   Record the choice: `choices[i][j]` $\leftarrow \theta$ [S1].

3.  **Backtracking**:
    *   Iterate from the last object index $m = n-1$ down to $0$ [S1].
    *   If `choices[m][H]` is not null:
        *   Add the pair $(m, \text{choices}[m][H])$ to `configs` [S1].
    *   Return `configs` [S1].

**Pseudocode**
```python
def dp_configuration_selector(objects, config_spaces, size_func, quality_func, H):
    """
    Selects optimal NeRF configurations for a set of objects under memory constraint H.
    
    Args:
        objects: List of object identifiers I.
        config_spaces: List of configuration spaces C_i corresponding to each object.
        size_func: Function f_si(theta) returning memory size for object i and config theta.
        quality_func: Function f_qi(theta) returning quality for object i and config theta.
        H: Maximum allowed memory size.
        
    Returns:
        configs: List of tuples (object_index, selected_config_pair).
    """
    n = len(objects)
    # Data structures
    q = [0.0] * (H + 1)
    choices = [[None] * (H + 1) for _ in range(n)]
    
    # Precompute minimum configurations and sizes for threshold calculation
    min_configs = {}
    min_sizes = {}
    for i in range(n):
        C_i = config_spaces[i]
        min_configs[i] = min(C_i, key=lambda theta: size_func(i, theta))
        min_sizes[i] = size_func(i, min_configs[i])
        
    # DP Table Filling
    for i in range(n):
        C_i = config_spaces[i]
        
        # Calculate the minimum memory required by all OTHER objects
        min_other_size = sum(min_sizes[h] for h in range(n) if h != i)
        r_i = H - min_other_size
        
        # Iterate capacity downwards to satisfy MCK constraints
        for j in range(H, -1, -1):
            for theta in C_i:
                size = size_func(i, theta)
                
                # Feasibility check: ensure remaining capacity can fit min configs of others
                if size >= r_i:
                    continue
                
                # State transition
                if j >= size:
                    new_quality = q[j - size] + quality_func(i, theta)
                    if new_quality > q[j]:
                        q[j] = new_quality
                        choices[i][j] = theta
                        
    # Backtracking
    configs = []
    for m in range(n - 1, -1, -1):
        selected_theta = choices[m][H]
        if selected_theta is not None:
            configs.append((m, selected_theta))
            
    return configs
```

**Edge Cases and Pitfalls**
*   **Infeasibility of Greedy Conditions**: The feasibility condition $f_{si}(\theta) + \min_{h \neq i} \min_{\theta_t \in C_h} f_{sh}(\theta_t) \le H$ is often not met in NeRFlex due to the presence of two control knobs ($g$ and $p$) [S1]. Greedy algorithms fail here, necessitating DP [S1].
*   **Memory Limits**: On iPhone 13, exceeding 240MB causes the local WebGL rendering engine to fail to load data [S1]. On Pixel 4, exceeding 150MB causes average FPS to drop by ~15, leading to stuttering [S1].
*   **Profiling Accuracy**: The size function $f_{si}$ and quality function $f_{qi}$ are derived from profiling models [S1]. Inaccuracies in these models can lead to suboptimal selections or constraint violations if the estimated size is significantly lower than the actual runtime size [S1].

## Operating characteristics
*   **Time Complexity**: $O(nhc)$, where $n$ is the number of objects, $h$ is the memory constraint $H$, and $c$ is the size of the configuration space $C$ for an object [S1]. The threshold calculation takes $O(n)$ per object, and the DP process takes $O(hc)$ per object [S1].
*   **Memory Complexity**: $O(nh)$ for the `choices` table and $O(h)$ for the `q` array [S1].
*   **Strengths**: Guarantees an optimal solution to the MCK problem within the memory constraint, unlike greedy approaches which may fail or produce sub-optimal results when feasibility conditions are not met [S1].
*   **Limitations**: The problem is NP-hard [S1]. The pseudo-polynomial time complexity $O(nhc)$ can be prohibitive if $H$ or $c$ is very large [S1]. It requires accurate profiling models for size and quality [S1].
*   **When to Use**: When deploying multi-NeRF systems on resource-constrained devices (e.g., mobile phones) where strict memory limits must be respected and optimal quality is desired [S1].
*   **When Not to Use**: When real-time configuration selection is required and $n$ or $H$ are too large for the $O(nhc)$ complexity, or when profiling models are unavailable or inaccurate [S1].

## Background
The DP-based Configuration Selector was introduced in the **NeRFlex** paper [S1]. NeRFlex is a resource-aware real-time high-quality rendering system for complex scenes on mobile devices [S1]. The method addresses the challenge of managing memory for multiple segmented NeRF objects on devices with limited RAM, such as the iPhone 13 and Pixel 4 [S1]. The problem is formulated as a Multiple-Choice Knapsack (MCK) problem, which is known to be NP-hard [S1]. Previous approaches for single-object NeRFs or those relying on greedy search were insufficient due to the multi-knob nature of the configuration space and the strict feasibility requirements of greedy algorithms [S1].
