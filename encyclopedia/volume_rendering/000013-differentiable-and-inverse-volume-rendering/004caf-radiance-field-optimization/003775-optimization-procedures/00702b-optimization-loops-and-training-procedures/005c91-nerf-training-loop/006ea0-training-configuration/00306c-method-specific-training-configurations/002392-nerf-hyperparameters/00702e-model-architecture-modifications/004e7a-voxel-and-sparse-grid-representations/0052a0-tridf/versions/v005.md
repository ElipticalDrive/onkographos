# TriDF

Also called: Triplane-Accelerated Density Fields

## Overview
TriDF is a hybrid explicit–implicit 3D representation designed for few-shot novel view synthesis, particularly in remote sensing scenes where input views are sparse (e.g., 3 images) and have low overlap [S1]. It decouples color and volume density to reduce the computational burden on implicit radiance fields and accelerate reconstruction [S1]. Unlike standard triplane methods that struggle with fine-grained geometry under insufficient supervision, or joint models where color and density compete for network capacity, TriDF uses explicit triplanes for high-frequency color prediction and implicit density fields for geometry, guided by sparse depth from point clouds [S1].

## How it works
**Inputs:** $V$ input images (typically $V=3$) with known camera poses, and their associated depth maps or point clouds generated via Structure-from-Motion (SfM) and PatchMatch Stereo (PMS) [S1].
**Outputs:** A rendered image $\hat{C}(r)$ for a novel view ray $r$ [S1].

**Data Structures:**
1.  **Triplane ($P$):** A set of three mutually orthogonal feature planes $P = \{P_{XY}, P_{YZ}, P_{ZX}\}$ [S1]. Each plane $P_{ij}$ is a tensor of size $H \times W \times C$ [S1].
    *   $H, W$: Height and width of the feature maps.
    *   $C$: Channel dimension (feature vector dimension is 64) [S1].
    *   Initialized randomly and optimized directly [S1].
2.  **Density MLP:** A Multi-Layer Perceptron (MLP) implementing the CUTLASS architecture [S1].
    *   Width: 512.
    *   Depth: 8 layers [S1].
3.  **Color MLP:** A compact MLP for color prediction [S1].
4.  **Base MLP ($\Phi_{base}$):** A compact MLP combining triplane and density features [S1].

**Parameters:**
*   Positional encoding frequency for coordinates: 6 [S1].
*   Batch size: 1024 pixel rays [S1].
*   Samples per ray: 128 coarse samples [S1].
*   Total iterations: 30,000 (10k with depth guidance, 20k with edge-aware smoothness loss) [S1].
*   Optimizer: AdamW, initial learning rate 0.0001 [S1].

**Algorithm:**

1.  **Initialization:**
    *   Estimate initial 3D point clouds from training views and poses using COLMAP [S1].
    *   Re-project key points and their associated depth information from the generated point clouds to use as spatial anchors [S1].
    *   Initialize triplane tensors $P_{XY}, P_{YZ}, P_{ZX}$ randomly [S1].

2.  **Feature Extraction (IBR):**
    *   Extract pixel-aligned features $f_{ref}$ from input images using a pretrained CNN encoder [S1].
    *   Project these reference features to obtain corresponding feature vectors for each sampling point along the ray [S1].

3.  **Density Field Prediction:**
    *   For a 3D spatial point $\mathbf{x}$, apply positional encoding (frequency 6) to $\mathbf{x}$ [S1].
    *   Concatenate the positionally encoded coordinates with the projected reference features $f_{ref}$ [S1].
    *   Process the concatenated vector through the Density MLP to predict volume density $\sigma$ and intermediate features $f_m$ [S1].
    *   Note: The Density MLP outputs both $\sigma$ and $f_m$ [S1].

4.  **Triplane Feature Retrieval:**
    *   Decompose the scene space into three orthogonal parameterized planes $P = \{P_{XY}, P_{YZ}, P_{ZX}\}$ [S1].
    *   For a 3D spatial point $\mathbf{x}$, project it orthogonally onto the three planes [S1].
    *   Identify the four nearest grid points on each plane and apply bilinear interpolation to compute feature vectors $f_{XY}, f_{YZ}, f_{ZX}$ [S1].
    *   Concatenate the feature vectors from the three planes to form the final triplane feature vector:
        $$ f_{tri} = \text{concat}(f_{XY}, f_{YZ}, f_{ZX}) $$
        [S1]

5.  **Color Prediction:**
    *   Combine triplane features $f_{tri}$ and density features $f_m$ using the Base MLP ($\Phi_{base}$) to generate intermediate features $f_{base}$:
        $$ f_{base} = \Phi_{base}(f_{tri}, f_m) $$
        [S1]
    *   Encode the viewing direction $\mathbf{d} \in \mathbb{R}^3$ on the spherical harmonics basis $\text{SH}(\cdot)$ [S1].
    *   Map $f_{base}$ and the encoded viewing direction to determine the point's color $\mathbf{c} \in \mathbb{R}^3$ using the Color MLP ($\Phi_{color}$):
        $$ \mathbf{c} = \Phi_{color}(f_{base}, \text{SH}(\mathbf{d})) $$
        [S1]

6.  **Volume Rendering:**
    *   Aggregate attributes along the ray using differentiable volume rendering [S1].
    *   The pixel color $\hat{C}(r)$ is computed as:
        $$ \hat{C}(r) = \sum_{i=1}^{N} T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i $$
        where $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$, $\mathbf{c}_i$ and $\sigma_i$ are color and volume density, $\delta_i$ is the distance between adjacent samples, and $N$ is the number of sampling points [S1].

7.  **Optimization:**
    *   Optimize the model through backpropagation [S1].
    *   **Loss Functions:**
        *   Photometric loss between predicted and ground truth colors [S1].
        *   Depth supervision from the generated point clouds (first 10k iterations) [S1].
        *   Edge-aware smoothness loss (last 20k iterations) [S1].
            *   For edge-aware smoothness loss: process 64 key points and randomly render a $16 \times 16$ patch with stride 4 [S1].
    *   Use Nerfacc for efficient empty space skipping [S1].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class TriDF:
    def __init__(self, H, W, C, num_samples=128):
        """
        Initialize TriDF model.
        :param H: Height of triplane feature maps
        :param W: Width of triplane feature maps
        :param C: Channel dimension of triplane feature maps
        :param num_samples: Number of coarse samples per ray
        """
        self.H = H
        self.W = W
        self.C = C
        self.num_samples = num_samples
        
        # Triplane parameters: 3 planes (XY, YZ, ZX), each H x W x C
        self.triplane = nn.Parameter(torch.randn(3, C, H, W))
        
        # Density MLP (CUTLASS architecture: width 512, depth 8)
        # Input: pos_encoded_coord (dim=7) + ref_features (dim=64) -> 71
        # Output: sigma (1) + f_m (dim=64) -> 65
        self.density_mlp = nn.Sequential(
            nn.Linear(71, 512), nn.ReLU(),
            nn.Linear(512, 512), nn.ReLU(),
            nn.Linear(512, 512), nn.ReLU(),
            nn.Linear(512, 512), nn.ReLU(),
            nn.Linear(512, 512), nn.ReLU(),
            nn.Linear(512, 512), nn.ReLU(),
            nn.Linear(512, 512), nn.ReLU(),
            nn.Linear(512, 65) # 1 for sigma, 64 for f_m
        )
        
        # Base MLP: combines f_tri (192) and f_m (64) -> f_base (64)
        self.base_mlp = nn.Sequential(
            nn.Linear(192 + 64, 512), nn.ReLU(),
            nn.Linear(512, 64)
        )
        
        # Color MLP: combines f_base (64) and SH(d) (dim=27 for SH order 2) -> color (3)
        # Note: SH dimension depends on order. Standard NeRF uses order 4 (81 dims) or order 2 (27 dims).
        # The source mentions "SH(·)" but doesn't specify order. We assume a standard SH encoding function.
        self.color_mlp = nn.Sequential(
            nn.Linear(64 + 27, 512), nn.ReLU(),
            nn.Linear(512, 512), nn.ReLU(),
            nn.Linear(512, 3)
        )
        
        # Pretrained CNN encoder for reference features (frozen)
        self.encoder = get_pretrained_cnn_encoder() 
        self.encoder.eval()
        for param in self.encoder.parameters():
            param.requires_grad = False

    def positional_encoding(self, x, freq=6):
        """
        Apply positional encoding to coordinates.
        :param x: Coordinates (N, 3)
        :param freq: Frequency of sine/cosine waves
        :return: Encoded coordinates (N, 3 * 2 * freq + 3)
        """
        # Standard NeRF positional encoding
        x = x.unsqueeze(-1)
        scales = torch.tensor([2**i for i in range(freq)])
        shaped_x = x * (2 * torch.pi * scales).reshape(1, 1, -1, 1)
        pe = torch.cat((torch.sin(shaped_x), torch.cos(shaped_x)), -1)
        pe = pe.reshape(x.shape[0], -1)
        return torch.cat([x.reshape(x.shape[0], -1), pe], dim=-1)

    def get_triplane_features(self, x, triplane):
        """
        Retrieve features from triplane for points x.
        :param x: Points (N, 3)
        :param triplane: Triplane parameters (3, C, H, W)
        :return: Concatenated features (N, 3*C)
        """
        features = []
        # Project onto XY, YZ, ZX planes
        # XY plane: use x, y coordinates
        xy_coords = x[:, :2] # (N, 2)
        # Normalize to [-1, 1] for grid_sample if necessary, assuming triplane is in this range
        # grid_sample expects normalized coordinates in [-1, 1]
        xy_norm = xy_coords * 2 - 1 
        xy_norm = xy_norm.unsqueeze(1).unsqueeze(1) # (N, 1, 1, 2)
        
        # Sample from P_XY
        f_xy = F.grid_sample(triplane[0].unsqueeze(0), xy_norm, align_corners=True).squeeze() # (C, N)
        f_xy = f_xy.permute(1, 0) # (N, C)
        
        # YZ plane: use y, z coordinates
        yz_coords = x[:, 1:] # (N, 2)
        yz_norm = yz_coords * 2 - 1
        yz_norm = yz_norm.unsqueeze(1).unsqueeze(1)
        f_yz = F.grid_sample(triplane[1].unsqueeze(0), yz_norm, align_corners=True).squeeze()
        f_yz = f_yz.permute(1, 0)
        
        # ZX plane: use z, x coordinates
        zx_coords = torch.cat([x[:, 2:], x[:, :1]], dim=1) # (N, 2)
        zx_norm = zx_coords * 2 - 1
        zx_norm = zx_norm.unsqueeze(1).unsqueeze(1)
        f_zx = F.grid_sample(triplane[2].unsqueeze(0), zx_norm, align_corners=True).squeeze()
        f_zx = f_zx.permute(1, 0)
        
        f_tri = torch.cat([f_xy, f_yz, f_zx], dim=1) # (N, 3*C)
        return f_tri

    def forward(self, rays_o, rays_d, ref_images, ref_poses, point_cloud_depths):
        """
        Forward pass for a batch of rays.
        :param rays_o: Ray origins (B, 3)
        :param rays_d: Ray directions (B, 3)
        :param ref_images: Reference images (V, 3, H_img, W_img)
        :param ref_poses: Reference camera poses (V, 4, 4)
        :param point_cloud_depths: Depth maps from point clouds for supervision
        :return: Rendered colors, densities, and auxiliary losses
        """
        # 1. Extract reference features
        with torch.no_grad():
            ref_features = self.encoder(ref_images) # (V, C_enc, H_ref, W_ref)
        
        # 2. Sample points along rays
        # Assume t_near, t_far are determined by Nerfacc or bounding box
        t_vals = torch.linspace(0, 1, self.num_samples) # Placeholder for actual sampling strategy
        # In practice, Nerfacc handles empty space skipping. Here we assume uniform sampling for simplicity.
        # t_vals = nerfacc.sample_stratified(t_near, t_far, self.num_samples)
        t_vals = t_vals.to(rays_o.device)
        t_vals = torch.stack([t_vals] * rays_o.shape[0], dim=0)
        z_vals = t_vals # Placeholder
        
        # 3. Compute 3D points
        pts = rays_o.unsqueeze(1) + rays_d.unsqueeze(1) * z_vals.unsqueeze(2) # (B, N, 3)
        pts_flat = pts.reshape(-1, 3) # (B*N, 3)
        
        # 4. Get Triplane Features
        f_tri = self.get_triplane_features(pts_flat, self.triplane) # (B*N, 3*C)
        
        # 5. Get Reference Features for Density
        # Project reference features to sampling points
        # This requires projecting ref_images to the 3D points and aggregating
        # Simplified: Assume we have pre-computed f_ref for each point
        # f_ref = project_ref_features(pts_flat, ref_features, ref_poses)
        # For the sake of the pseudocode, we assume f_ref is available
        f_ref = torch.randn(pts_flat.shape[0], 64).to(pts_flat.device) # Placeholder for IBR feature aggregation
        
        # 6. Density Field Prediction
        pos_enc = self.positional_encoding(pts_flat, freq=6) # (B*N, 7)
        density_input = torch.cat([pos_enc, f_ref], dim=1) # (B*N, 71)
        density_output = self.density_mlp(density_input) # (B*N, 65)
        sigma = density_output[:, 0] # (B*N,)
        f_m = density_output[:, 1:] # (B*N, 64)
        
        # 7. Color Prediction
        f_base = self.base_mlp(torch.cat([f_tri, f_m], dim=1)) # (B*N, 64)
        
        # Spherical Harmonics encoding of viewing direction
        # d_flat = rays_d.unsqueeze(1).expand(-1, self.num_samples, -1).reshape(-1, 3)
        # d_flat = d_flat / d_flat.norm(dim=1, keepdim=True)
        # sh_d = spherical_harmonics_encoding(d_flat, order=2) # (B*N, 27)
        sh_d = torch.randn(pts_flat.shape[0], 27).to(pts_flat.device) # Placeholder
        
        color = self.color_mlp(torch.cat([f_base, sh_d], dim=1)) # (B*N, 3)
        color = color.reshape(rays_o.shape[0], self.num_samples, 3)
        sigma = sigma.reshape(rays_o.shape[0], self.num_samples)
        
        # 8. Volume Rendering
        # Compute deltas
        deltas = z_vals[:, 1:] - z_vals[:, :-1] # (B, N-1)
        # Add epsilon for numerical stability
        deltas = torch.cat([deltas, torch.ones_like(deltas[:, :1]) * 1e-10], dim=-1)
        
        # Alpha
        alpha = 1 - torch.exp(-sigma * deltas) # (B, N)
        
        # Transmittance
        T = torch.cumprod(1 - alpha + 1e-10, dim=1) # (B, N)
        T = torch.cat([torch.ones_like(T[:, :1]), T[:, :-1]], dim=-1) # (B, N)
        
        # Weights
        weights = alpha * T # (B, N)
        
        # Color
        C = torch.sum(weights.unsqueeze(-1) * color, dim=1) # (B, 3)
        
        return C, sigma, alpha, weights
```

## Operating characteristics
*   **Time Complexity:** Training is significantly faster than standard NeRF-based methods. TriDF achieves a 30× speed increase compared to NeRF-based methods [S1].
*   **Memory Complexity:** The triplane representation is compact. The triplane itself consumes 25.6 MB (for $H, W, C$ values implied by the source, though exact $H,W$ are not given, the memory is stated) [S1]. The density MLP consumes 6.4 MB [S1]. Total parameters are manageable on a single consumer GPU [S1].
*   **Measured Performance:** On the LEVIRNVS dataset, TriDF achieves a 7.4% increase in PSNR and a 3.4% increase in SSIM compared to advanced few-shot methods [S1].
*   **Training Time:** ~5 minutes for 10k iterations (TriDF-10k) and 14 minutes for 30k iterations on a single Nvidia GeForce RTX 4090 GPU [S1]. Initialization (stereo-matching + point cloud fusion) takes 18 seconds [S1].
*   **Strengths:** Fast convergence due to direct optimization of explicit triplane features; effective few-shot rendering from as few as 3 views; avoids overfitting common in standard NeRF with sparse views; no need for extensive pretraining on large multi-view datasets [S1].
*   **Limitations:** Rendering speed lags behind 3DGS-based methods designed for real-time rendering [S1]; relies on the quality of initial point clouds from SfM/PMS; standard triplane representations suffer from redundancy or inaccurate geometry modeling with sparse inputs if not decoupled [S1].
*   **When to use:** Remote sensing novel view synthesis with sparse input views (e.g., 3 images) where fast reconstruction is required [S1].
*   **When not to use:** When real-time rendering speed is the primary constraint (use 3DGS); when dense input views are available and pretraining is feasible (use PixelNeRF/IBRNet); when high-frequency geometry is critical and point cloud initialization is unreliable [S1].

## Background
TriDF was proposed in a paper published in 2025 [S1]. It addresses the challenges of few-shot novel view synthesis in remote sensing, where data acquisition constraints limit the number of input views to as few as 3 [S1]. Traditional NeRF methods require hundreds of images and are computationally intensive, taking dozens of hours to reconstruct a single scene [S1]. Existing few-shot methods often rely on pretraining on large datasets (e.g., PixelNeRF, IBRNet) or complex regularization (e.g., 3DGS methods), which are impractical for remote sensing due to the lack of comprehensive 3D datasets and the specific characteristics of aerial imagery [S1]. TriDF introduces a hybrid explicit–implicit representation that decouples color and volume density, using triplanes for color and implicit fields for density, guided by sparse depth from point clouds [S1].
