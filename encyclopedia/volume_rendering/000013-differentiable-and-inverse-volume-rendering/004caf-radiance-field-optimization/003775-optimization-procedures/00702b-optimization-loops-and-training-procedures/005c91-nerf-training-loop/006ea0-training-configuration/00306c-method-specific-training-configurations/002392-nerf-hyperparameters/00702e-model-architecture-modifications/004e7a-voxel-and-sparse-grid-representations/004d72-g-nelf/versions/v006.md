# G-NeLF

Also called: Grid-based Neural Light Field, Memory- and Data-Efficient Hybrid Neural Light Field

## Overview
G-NeLF is a grid-based Neural Light Field (NeLF) method for novel view synthesis that predicts ray color directly without point-wise volume density modeling [S1, unofficial]. It represents a ray as a sequence of spatial-aware features extracted from a hash-based multi-resolution tri-plane, decoded by an LSTM network to predict color [S1, unofficial]. Unlike standard NeRF methods that model density and color per point, G-NeLF bypasses explicit volume rendering equations, relying instead on the sequential inference capability of recurrent networks to simulate ray propagation [S1, unofficial]. It distinguishes itself from siblings like [R2L](11470-voxel-based-radiance-fields.md) by using a feature sequence rather than direct coordinate concatenation, and from [Instant-NGP](13013-neural-multi-view-image-reconstruction-with-hash-encoding.md) by achieving comparable quality with approximately one-tenth the parameters [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Camera parameters (origin $\mathbf{o}$, direction $\mathbf{d}$), scene training images.
*   **Output:** Predicted ray color $(r, g, b)$.

**Data Structures:**
1.  **Hash Table:** Maps integer coordinate pairs to feature vectors.
    *   Size $T$: $2^{14}$ for small/medium models, $2^{16}$ for large models [S1, unofficial].
    *   Layout: A flat array or hash map where each entry stores a feature vector of dimension $D_{feat}$ (typically 2) [S1, unofficial].
2.  **Tri-Plane:** Three orthogonal 2D planes $\pi_{xy}, \pi_{xz}, \pi_{yz}$ [S1, unofficial].
    *   Each plane has $N$ resolution levels.
    *   Small/Medium: $N=8$ levels, resolutions from 16 to 1024 [S1, unofficial].
    *   Large: $N=16$ levels, resolutions from 16 to 2048 [S1, unofficial].
3.  **Point Feature Vector $F$:**
    *   Constructed by concatenating features from 3 planes, each with $N$ resolutions, each resolution having 2 dimensions.
    *   Total size: $3 \times N \times 2$ [S1, unofficial].

**Algorithm Steps:**

1.  **Ray Emission:** For each pixel in the target image, emit a ray $r = (\mathbf{o}, \mathbf{d})$ based on the camera model [S1, unofficial].
2.  **Bounding Box Check:** Determine if the ray intersects the scene's bounding box. If not, return background color [S1, unofficial].
3.  **Sampling:** Sequentially sample $K$ points $\{\mathbf{x}_1, \dots, \mathbf{x}_K\}$ along the ray within the bounding box.
    *   $K=256$ for $360^\circ$ scenes [S1, unofficial].
    *   $K=128$ for forward-facing scenes (using NDC coordinates) [S1, unofficial].
4.  **Feature Extraction (for each point $\mathbf{x}_k$):**
    *   Project $\mathbf{x}_k$ onto the three orthogonal planes to get 2D coordinates $\mathbf{x}_{\pi} = (x_\pi, y_\pi)$ for $\pi \in \{\pi_{xy}, \pi_{xz}, \pi_{yz}\}$ [S1, unofficial].
    *   For each resolution level $i \in \{1, \dots, N\}$ with grid size $s_i$:
        *   Compute integer grid indices for the four corners of the cell containing $\mathbf{x}_{\pi}$:
            $$
            \begin{aligned}
            idx_{tl} &= (x_\pi // s_i, y_\pi // s_i) \\
            idx_{tr} &= (x_\pi // s_i, y_\pi // s_i + 1) \\
            idx_{bl} &= (x_\pi // s_i + 1, y_\pi // s_i) \\
            idx_{br} &= (x_\pi // s_i + 1, y_\pi // s_i + 1)
            \end{aligned}
            $$
        *   Compute hash indices for these corners using the hash function:
            $$
            \text{Index} = (x_a \oplus y_b) \pmod T
            $$
            where $x_a, y_b$ are the integer coordinates, $\oplus$ is XOR, and $T$ is the hash table size [S1, unofficial].
        *   Retrieve feature vectors $v_{tl}, v_{tr}, v_{bl}, v_{br}$ from the hash table at the computed indices [S1, unofficial].
        *   Perform bilinear interpolation (weighted sum) of these four vectors based on the fractional distance of $\mathbf{x}_{\pi}$ within the cell to obtain the feature vector $f_{\pi, i}$ for this resolution [S1, unofficial].
    *   Concatenate $f_{\pi, i}$ for all $i=1 \dots N$ to form the plane feature vector $F_\pi$ [S1, unofficial].
    *   Concatenate $F_{\pi_{xy}}, F_{\pi_{xz}}, F_{\pi_{yz}}$ to form the point feature vector $F_k$ [S1, unofficial].
5.  **Sequence Assembly:** Assemble the feature vectors of all $K$ points into a ray feature sequence $\{F_1, \dots, F_K\}$ [S1, unofficial].
6.  **Direction Encoding:** Encode the normalized ray direction $\mathbf{d}$ using Spherical Harmonics (SH) to obtain vector $\mathbf{d}_{enc}$ [S1, unofficial].
7.  **LSTM Decoding:** Process the sequence sequentially using a 2-layer LSTM network [S1, unofficial].
    *   Initialize hidden state $H_0$ and cell state $C_0$ to zero vectors of size $H_{dim}$ (32 for small, 128 for medium/large) [S1, unofficial].
    *   For $k = 1$ to $K$:
        $$
        H_k, C_k = \text{LSTM}(\text{Concat}(F_k, \mathbf{d}_{enc}), H_{k-1}, C_{k-1})
        $$
        where $\text{Concat}(\cdot)$ combines the point feature and direction encoding [S1, unofficial].
8.  **Color Prediction:** Pass the final hidden state $H_K$ through a 2-layer Multi-Layer Perceptron (MLP) to predict the ray color:
    $$
    (r, g, b) = \text{MLP}(H_K)
    $$
    [S1, unofficial].

**Pseudocode:**

```python
import math

def hash_index(x, y, table_size):
    """Compute hash index for 2D coordinate."""
    return (x ^ y) % table_size

def get_point_features(x, tri_planes, resolutions, hash_tables):
    """
    Extract feature vector for a 3D point x from hash-based tri-plane.
    
    Args:
        x: 3D coordinate (x, y, z)
        tri_planes: List of plane names ['xy', 'xz', 'yz']
        resolutions: List of grid sizes [s_1, s_2, ..., s_N]
        hash_tables: Dict mapping plane_name -> List of hash tables [hash_1, ..., hash_N]
        
    Returns:
        F: Concatenated feature vector
    """
    F_all = []
    
    for plane in tri_planes:
        F_plane = []
        
        # Project 3D point to 2D based on plane
        if plane == 'xy':
            x_2d, y_2d = x[0], x[1]
        elif plane == 'xz':
            x_2d, y_2d = x[0], x[2]
        elif plane == 'yz':
            x_2d, y_2d = x[1], x[2]
            
        for i, s in enumerate(resolutions):
            # Get hash table for this resolution and plane
            ht = hash_tables[plane][i]
            
            # Compute integer grid coordinates
            ix = int(x_2d // s)
            iy = int(y_2d // s)
            
            # Fractional part for interpolation
            fx = x_2d - ix * s
            fy = y_2d - iy * s
            
            # Normalize fractions to [0, 1] relative to grid size
            # Note: Standard bilinear interpolation weights
            w_tl = (1 - fx/s) * (1 - fy/s)
            w_tr = (fx/s) * (1 - fy/s)
            w_bl = (1 - fx/s) * (fy/s)
            w_br = (fx/s) * (fy/s)
            
            # Compute hash indices for 4 corners
            idx_tl = hash_index(ix, iy, len(ht))
            idx_tr = hash_index(ix, iy + 1, len(ht))
            idx_bl = hash_index(ix + 1, iy, len(ht))
            idx_br = hash_index(ix + 1, iy + 1, len(ht))
            
            # Retrieve features (assuming feature dim is 2)
            v_tl = ht[idx_tl]
            v_tr = ht[idx_tr]
            v_bl = ht[idx_bl]
            v_br = ht[idx_br]
            
            # Bilinear interpolation
            v_interp = (w_tl * v_tl + 
                        w_tr * v_tr + 
                        w_bl * v_bl + 
                        w_br * v_br)
            
            F_plane.append(v_interp)
            
        # Concatenate features from all resolutions for this plane
        F_plane_concat = concat(F_plane)
        F_all.append(F_plane_concat)
        
    # Concatenate features from all 3 planes
    F_final = concat(F_all)
    return F_final

def spherical_harmonic_encode(direction, degree=4):
    """
    Encode 3D direction vector using Spherical Harmonics.
    Simplified implementation for demonstration.
    """
    # Normalize direction
    d = direction / math.linalg.norm(direction)
    x, y, z = d
    
    # Standard SH basis functions up to degree 4 (9 coefficients for m=0, plus others)
    # This is a placeholder for the actual SH math defined in Ref-NeRF/Instant-NGP
    # Real implementation requires specific SH basis evaluation
    return [0.282095, 0.488603 * y, 0.488603 * z, 0.488603 * x, 
            1.092548 * x * y, 1.092548 * y * z, 0.315392 * (3 * z**2 - 1), 
            1.092548 * x * z, 0.546274 * (x**2 - y**2)]

def gnelf_render(ray_origin, ray_direction, tri_planes, resolutions, hash_tables, lstm, mlp):
    """
    Render a single ray using G-NeLF.
    """
    # 1. Sample points along ray
    # Assume bounding box intersection logic is handled externally
    # Sample K points uniformly or using stratified sampling
    K = 256 # For 360 degree scenes
    points = []
    for k in range(K):
        t = (k + 0.5) / K # Uniform sampling within [0, 1] normalized range
        # In practice, t maps to actual distance in bounding box
        point = ray_origin + ray_direction * t
        points.append(point)
        
    # 2. Extract features for each point
    features = []
    for point in points:
        F_k = get_point_features(point, tri_planes, resolutions, hash_tables)
        features.append(F_k)
        
    # 3. Encode direction
    d_enc = spherical_harmonic_encode(ray_direction)
    
    # 4. LSTM Decoding
    # Initialize hidden and cell states
    H_prev = [0.0] * lstm.hidden_size
    C_prev = [0.0] * lstm.hidden_size
    
    for F_k in features:
        # Concatenate point feature and direction encoding
        input_vec = concat(F_k, d_enc)
        
        # LSTM step
        H_curr, C_curr = lstm_step(input_vec, H_prev, C_prev)
        
        H_prev = H_curr
        C_prev = C_curr
        
    # 5. Color Prediction
    color = mlp(H_prev)
    return color
```

**Parameters:**
*   **Hash Table Size ($T$):** $2^{14}$ (small/medium), $2^{16}$ (large) [S1, unofficial].
*   **Resolutions:** 8 levels (16 to 1024) for small/medium; 16 levels (16 to 2048) for large [S1, unofficial].
*   **Feature Dimension per Level:** 2 [S1, unofficial].
*   **LSTM Hidden Size:** 32 (small), 128 (medium/large) [S1, unofficial].
*   **Sequence Length ($K$):** 256 (360° scenes), 128 (forward-facing) [S1, unofficial].
*   **Model Size:** 0.95 MB (small), 1.41 MB (medium) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** At the highest resolution, approximately 100,000 3D positions map to a single hash entry [S1, unofficial]. This is not detrimental because points far from the visible surface have low weight in volume rendering (if it were used) or low influence on the final color in NeLF, allowing the hash entry to adaptively capture the appearance of the dominant visible points [S1, unofficial].
*   **Network Choice:** Using an MLP directly on concatenated features ignores temporal order, while Transformers are permutation-invariant and lose sequential ray propagation information [S1, unofficial]. LSTM is chosen to preserve this order [S1, unofficial].
*   **Training Data:** Requires only original training views (e.g., 100 views), no pseudo-views synthesized [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by the hash lookups and bilinear interpolation for $K$ points, followed by the LSTM sequence processing. Hash lookups are $O(1)$ on average. LSTM is $O(K \cdot H_{dim})$.
*   **Memory Complexity:** Determined by the hash table size $T$ and feature dimension. Small model: $2^{14} \times 2 \times 4$ bytes $\approx 128$ KB for features, plus overhead. Total model size is 0.95 MB [S1, unofficial].
*   **Performance:** On Realistic Synthetic 360° dataset at 400x400, G-NeLF surpasses R2L by 0.04 dB PSNR [S1, unofficial]. At 1.4 MB model size, it surpasses VQRF by 0.79 dB PSNR [S1, unofficial]. It achieves comparable PSNR to Instant-NGP and TensoRF but with ~1/10th the parameters (1.41 MB vs 64.1 MB/71.8 MB) [S1, unofficial].
*   **Strengths:** Extremely compact model size, low training data requirement (no pseudo-views), efficient use of spatial-aware features.
*   **Limitations:** Does not model volume density explicitly, which may limit its applicability to tasks requiring physical properties (e.g., relighting, segmentation) compared to NeRF-based methods. Performance relies heavily on the quality of the hash grid and LSTM capacity.

## Background
G-NeLF was introduced in 2024 as a memory- and data-efficient hybrid neural light field method [S1, unofficial]. It addresses the training difficulties and high resource consumption of previous NeLF methods like R2L, which required synthesizing over 10,000 pseudo-views from a pre-trained NeRF [S1, unofficial]. By leveraging a hash-based multi-resolution tri-plane and an LSTM decoder, G-NeLF demonstrates that NeLF can achieve performance comparable to state-of-the-art grid-based NeRFs (like Instant-NGP) with significantly fewer parameters and less data [S1, unofficial].
