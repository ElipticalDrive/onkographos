# MINE

Also called: Continuous Depth MPI, MINE (Continuous Depth MPI), MINE: Towards Continuous Depth MPI with NeRF for Novel View Synthesis, Multi-Plane Image NeRF, Multiplane Image with Neural Radiance Fields

## Overview
MINE is a hybrid method that combines Multi-Plane Images (MPI) with Neural Radiance Fields (NeRF) to reconstruct dense 3D representations from single color images for novel view synthesis [S1, unofficial][S2]. Unlike pixelNeRF and GRF, which model the entire 3D space per ray, MINE models the frustum of the source camera using continuous depth MPIs [S2]. This architectural difference allows MINE to be significantly more efficient, as its complexity is independent of the number of target views, whereas pixelNeRF and GRF scale with the number of novel views [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A single source image $I_{src}$ and camera intrinsics.
*   **Output:** A rendered image $I_{target}$ for a target viewpoint, generated via homography warping of the reconstructed frustum.

**Data Structures:**
The method uses a continuous depth MPI representation. The scene is represented as a set of $N_{\text{planes}}$ planes. Each plane contains:
*   **RGB:** View-independent color (3 channels).
*   **$\sigma$:** Opacity/density (1 channel).
*   **Disparity:** Continuous depth information associated with the plane.

The network outputs a 4-channel RGB-$\sigma$ image for each plane.

**Network Architecture:**
1.  **Encoder:** A standard ResNet50 [S2]. Feature maps are extracted from layers: `conv1`, `layer1`, `layer2`, `layer3`, and `layer4` [S2].
2.  **Decoder:** A fully convolutional depth decoder [S2]. It consists of downsampling and upsampling blocks with skip connections from the encoder [S2].
    *   The decoder is based on the architecture in [12], augmented with two additional downsampling blocks and two upsampling blocks to increase receptive fields [S2].
    *   The final output is a 4-channel tensor. The first 3 channels are passed through a Sigmoid activation to produce RGB. The 4th channel is passed through an absolute value function to produce $\sigma$ [S2].

**Decoder Layer Layout:**
The decoder processes features through the following sequence [S2]:

| Layer | Input Channels | Output Channels | Input Composition | Activation |
| :--- | :--- | :--- | :--- | :--- |
| `downconv1` | 2048 | 512 | Encoder output | ELU |
| `downconv2` | 512 | 256 | `downconv1` output | ELU |
| `upconv1_extra` | 256 | 256 | `downconv2` output | ELU |
| `upconv2_extra` | 256 | 2048 | `upconv1_extra` output | ELU |
| `upconv5` | 2048 + 21 | 256 | `cat(upconv2_extra, disparity_encoding)` | ELU |
| `iconv5` | 256 + 1024 + 21 | 256 | `cat(upconv5, encoder_layer3, disparity_encoding)` | ELU |
| `output4` | 256 | 4 | `iconv5` | Sigmoid (RGB), Abs ($\sigma$) |
| `upconv4` | 256 | 128 | `output4` features | ELU |
| `iconv4` | 128 + 512 + 21 | 128 | `cat(upconv4, encoder_layer2, disparity_encoding)` | ELU |
| `output3` | 128 | 4 | `iconv4` | Sigmoid (RGB), Abs ($\sigma$) |
| `upconv3` | 128 | 64 | `output3` features | ELU |
| `iconv3` | 64 + 256 + 21 | 64 | `cat(upconv3, encoder_layer1, disparity_encoding)` | ELU |
| `output2` | 64 | 4 | `iconv3` | Sigmoid (RGB), Abs ($\sigma$) |
| `upconv2` | 64 | 32 | `output2` features | ELU |
| `iconv2` | 32 + 64 + 21 | 32 | `cat(upconv2, encoder_conv1, disparity_encoding)` | ELU |
| `output1` | 32 | 4 | `iconv2` | Sigmoid (RGB), Abs ($\sigma$) |
| `upconv1` | 32 | 16 | `output1` features | ELU |
| `iconv1` | 16 | 16 | `upconv1` output | ELU |

*Note: `upconv` blocks consist of convolution, batch normalization, activation, followed by 2x nearest neighbor upsampling. `downconv` blocks consist of max pooling (stride 2), convolution, activation [S2].*

**Number of Planes ($N_{\text{planes}}$):**
The number of planes is a hyperparameter. The specific value is not given in the sources, but it determines the depth resolution of the MPI [S2].

**Rendering Process:**
1.  **Encoder Pass:** The source image is passed through the ResNet50 encoder once [S2].
2.  **Decoder Passes:** The encoder features are passed through the decoder $N_{\text{planes}}$ times to reconstruct the frustum. Each pass produces one plane of the MPI (RGB and $\sigma$) [S2].
3.  **Homography Warping:** To render a target view, the reconstructed frustum (the set of $N_{\text{planes}}$ planes) is warped using homography transformations corresponding to the target camera pose [S2].
4.  **Compositing:** The warped planes are composited using standard alpha compositing (volume rendering equation) to produce the final image [S2].

**View-Dependent Color:**
By default, MINE does not take viewing direction as input [S2]. To support view-dependent effects, per-ray viewing directions can be concatenated with the output feature maps at the target view (after warping), and a lightweight fully convolutional network can predict the view-dependent radiance [S2].

**Training Strategy:**
*   **Loss Functions:** MINE uses multiscale training losses [S2].
    *   $L_{L1}$ and $L_{SSIM}$ are applied only to `output1` [S2].
    *   $L_{smooth}$ (edge-aware smoothness loss) is applied to all outputs (`output1`, `output2`, `output3`, `output4`) [S2].
*   **Dense Supervision:** Because MINE renders the full target image and disparity map during training, it can utilize dense supervision signals like SSIM and edge-aware smoothness, which are infeasible for NeRF-like methods due to their inefficiency [S2].

        Render a target view by warping the MPI planes.
        
        Args:
            mpi_planes (list): List of (RGB, sigma) tuples for each plane.
            target_homography (torch.Tensor): Homography matrix for the target view.
            
        Returns:
            torch.Tensor: Rendered image.
        """
        # Warp each plane using the homography
        warped_planes = []
        for rgb, sigma in mpi_planes:
            # Warp RGB and Sigma separately
            warped_rgb = F.affine_grid(target_homography, rgb.shape) # Simplified
            warped_rgb = F.grid_sample(rgb, warped_rgb)
            warped_sigma = F.affine_grid(target_homography, sigma.shape)
            warped_sigma = F.grid_sample(sigma, warped_sigma)
            warped_planes.append((warped_rgb, warped_sigma))
        
        # Composite the warped planes
        # Standard alpha compositing
        final_rgb = torch.zeros_like(warped_planes[0][0])
        accumulated_sigma = torch.zeros_like(warped_planes[0][1])
        
        for rgb, sigma in reversed(warped_planes):
            # Alpha compositing
            # C = C_prev * (1 - alpha) + C_new * alpha
            # alpha = sigma * (1 - accumulated_sigma)
            alpha = sigma * (1 - accumulated_sigma)
            final_rgb = final_rgb * (1 - alpha) + rgb * alpha
            accumulated_sigma = accumulated_sigma + alpha * (1 - accumulated_sigma)
            
        return final_rgb

    def forward(self, image, target_homography):
        """
        Full forward pass.
        
        Args:
            image (torch.Tensor): Source image.
            target_homography (torch.Tensor): Homography for target view.
            
        Returns:
            torch.Tensor: Rendered target image.
        """
        features = self.encode(image)
        # Disparity encoding is assumed to be generated or passed
        disparity_encoding = self.generate_disparity_encoding()
        
        mpi_planes = self.decode(features, disparity_encoding)
        rendered_image = self.render(mpi_planes, target_homography)
        
        return rendered_image

**Parameters:**
*   **$N_{\text{planes}}$:** The number of planes in the MPI representation. Not given in the sources.
*   **Disparity Range:** For Flowers Light Fields, the disparity range is set to $[3.0, 0.03]$ [S2].
*   **Grid Distance:** For Flowers Light Fields, the distance between adjacent grids is set to $0.00128$ [S2].
*   **Camera Intrinsics (Flowers Light Fields):**
    *   $f_x = 0.868056$
    *   $f_y = 1.250000$
    *   $c_{xij} = 0.5 + 0.002667 \times i$
    *   $c_{yij} = 0.5 + 0.002667 \times j$
    *   where $[i, j]$ is the index in the extracted $8 \times 8$ grid and $[0, 0]$ is the top-left view [S2].

**Edge Cases and Pitfalls:**
*   **Principle Point Shift:** The Flowers Light Fields dataset, captured with a Lytro Illum camera, has a shift in the principle point between different views. Since there is no metadata for the shift amount, it is set to a constant value based on the grid index $[i, j]$ [S2].
*   **View-Dependent Color:** MINE does not take viewing direction as input by default. If view-dependent effects are required, a lightweight fully convolutional network must be added after warping, which adds $N_{\text{views}}$ network inferences [S2].

## Operating characteristics
*   **Time Complexity:** The number of network forward passes $P$ for MINE is $P_{\text{MINE}} = 1 + N_{\text{planes}}$ [S2]. This is independent of the number of target views $N_{\text{targets}}$ [S2].
*   **Memory Complexity:** Not given in the sources.
*   **Comparison:**
    *   **pixelNeRF:** $P_{\text{pixelNerF}} = 1 + N_{\text{targets}} \times N_{\text{points}} \times H \times W$ [S2].
    *   **GRF:** $P_{\text{GRF}} = N_{\text{views}} + N_{\text{targets}} \times N_{\text{points}} \times H \times W$ [S2].
    *   MINE is significantly more efficient than pixelNeRF and GRF because its complexity does not scale with $N_{\text{targets}}$ [S2].
*   **Strengths:**
    *   Efficient novel view synthesis from a single image [S2].
    *   Allows for dense supervision signals (SSIM, edge-aware smoothness) during training [S2].
    *   Generalizes well to large-scale real-world datasets (KITTI, NYU-V2, RealEstate10k, Flowers Light Fields, iBims-1) [S2].
*   **Limitations:**
    *   Does not natively support view-dependent color without additional network layers [S2].
    *   Requires careful handling of camera intrinsics for datasets with principle point shifts (e.g., Flowers Light Fields) [S2].

## Background
MINE was proposed by Liu et al. in 2021 [S2]. It is a hybrid between Multi-Plane Images (MPI) and NeRF [S1, unofficial]. The method was verified on datasets including KITTI, NYU-V2, RealEstate10k, Flowers Light Fields, and iBims-1 [S2]. It addresses the inefficiency of NeRF-like methods in novel view synthesis by reconstructing the camera frustum per plane rather than the entire 3D space per ray [S2].
