# G-NeLF

Also called: Grid-based Neural Light Field, Memory- and Data-Efficient Hybrid Neural Light Field

## Overview
G-NeLF is a grid-based Neural Light Field (NeLF) method for novel view synthesis that predicts ray color directly without point-wise volume density modeling [S1, unofficial]. It represents a ray as a sequence of spatial-aware features extracted from a hash-based multi-resolution tri-plane, which is decoded by an LSTM network to predict color [S1, unofficial]. Unlike standard NeRF methods that model density and color per point, G-NeLF bypasses explicit volumetric integration, allowing it to achieve performance comparable to state-of-the-art grid-based NeRFs (e.g., Instant-NGP, TensoRF) with approximately one-tenth the parameters [S1, unofficial]. It is specifically designed to overcome the training difficulties of previous NeLF methods that required synthesizing thousands of pseudo-views, enabling training with 100 or fewer original views [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $V$ training images with known camera poses; a query ray $r$ defined by origin $\mathbf{o}$ and direction $\mathbf{d}$.
*   **Output:** Predicted pixel color $\hat{\mathbf{c}} = (r, g, b)$ for the ray.

**Data Structures:**
1.  **Hash-Based Multi-Resolution Tri-Plane:**
    *   Consists of three orthogonal feature planes: $\pi_{xy}, \pi_{xz}, \pi_{yz}$ [S1, unofficial].
    *   Each plane contains $N$ resolution levels [S1, unofficial].
    *   Each resolution level $i$ has a grid size $s_i$ and an associated hash table $hash_{\pi, i}$ [S1, unofficial].
    *   **Hash Table Layout:** Maps integer coordinate pairs to feature vectors. Size $T$ (typically $2^{14}$ or $2^{16}$) [S1, unofficial].
    *   **Hash Index Calculation:** For a projected 2D coordinate $(x, y)$ at resolution $i$, the index is calculated as:
        $$ \text{Index} = (x \oplus y) \mod T $$
        where $\oplus$ is the bitwise XOR operation [S1, unofficial]. Note: The source text specifies coefficients $a=1, b=2,654,435,761$ for the hash function in some contexts, but the algorithm description uses simple XOR [S1, unofficial]. The algorithm description (Algorithm 1) uses simple integer division and XOR logic implicitly via the modulo operation on the divided coordinates. We follow Algorithm 1 for implementation clarity.
    *   **Feature Vector per Vertex:** Each entry in the hash table stores a feature vector of dimension 2 [S1, unofficial].

2.  **Point Feature Vector ($\mathbf{F}$):**
    *   For a 3D point $\mathbf{x}$, the feature vector is the concatenation of features retrieved from all resolutions of all three planes [S1, unofficial].
    *   Total dimension: $3 \times N \times 2$ [S1, unofficial].

3.  **Ray Feature Sequence:**
    *   A sequence of $K$ point feature vectors $\{\mathbf{F}_1, \dots, \mathbf{F}_K\}$ corresponding to $K$ sampled points along the ray [S1, unofficial].

**Parameters:**
*   **Hash Table Size ($T$):** $2^{14}$ for small/medium models; $2^{16}$ for large models [S1, unofficial].
*   **Grid Resolutions ($N$):** 8 levels (from 16 to 1024) for small/medium; 16 levels (from 16 to 2048) for large [S1, unofficial].
*   **Feature Dimension per Level:** 2 [S1, unofficial].
*   **LSTM Hidden Size:** 32 (small), 128 (medium), or 128 (large) [S1, unofficial].
*   **Ray Feature Sequence Length ($K$):** 256 for 360° scenes; 128 for forward-facing scenes [S1, unofficial].
*   **Model Size:** ~0.95 MB (small) to 1.41 MB (medium) [S1, unofficial].

**Algorithm Steps:**

1.  **Ray Sampling:**
    *   Emit rays from the camera center through each pixel.
    *   Determine the intersection of the ray with the scene bounding box.
    *   Sample $K$ points $\{\mathbf{x}_1, \dots, \mathbf{x}_K\}$ sequentially along the ray segment within the bounding box [S1, unofficial].

2.  **Point Feature Acquisition:**
    *   For each sampled point $\mathbf{x}_k$:
        *   Project $\mathbf{x}_k$ onto the three orthogonal planes $\pi_{xy}, \pi_{xz}, \pi_{yz}$ to obtain 2D coordinates $\mathbf{x}_{\pi}$ [S1, unofficial].
        *   For each plane $\pi$ and each resolution level $i \in \{1, \dots, N\}$:
            *   Calculate grid coordinates: $u = \lfloor x_{\pi,0} / s_i \rfloor$, $v = \lfloor x_{\pi,1} / s_i \rfloor$ [S1, unofficial].
            *   Retrieve features from the four corner vertices of the grid cell using the hash table $hash_{\pi, i}$:
                *   $\mathbf{f}_{tl} = hash_{\pi, i}([u, v])$
                *   $\mathbf{f}_{tr} = hash_{\pi, i}([u, v+1])$
                *   $\mathbf{f}_{bl} = hash_{\pi, i}([u+1, v])$
                *   $\mathbf{f}_{br} = hash_{\pi, i}([u+1, v+1])$
            *   Compute the weighted sum of these four features based on the fractional distance of $\mathbf{x}_{\pi}$ from the grid corners (trilinear interpolation) [S1, unofficial]. Let this result be $\mathbf{f}_{\pi, i}$ [S1, unofficial].
        *   Concatenate $\mathbf{f}_{\pi, i}$ for all $i$ to form the plane feature vector $\mathbf{F}_{\pi}$ [S1, unofficial].
        *   Concatenate $\mathbf{F}_{xy}, \mathbf{F}_{xz}, \mathbf{F}_{yz}$ to form the point feature vector $\mathbf{F}_k$ [S1, unofficial].
    *   Assemble $\{\mathbf{F}_1, \dots, \mathbf{F}_K\}$ into the ray feature sequence [S1, unofficial].

3.  **Direction Encoding:**
    *   Encode the ray's normalized direction vector $\mathbf{d}$ using Spherical Harmonics (SH) [S1, unofficial]. Let the encoded direction be $\mathbf{d}_{enc}$ [S1, unofficial].

4.  **LSTM Decoding:**
    *   Initialize LSTM hidden state $\mathbf{H}_0 = \mathbf{0}$ and cell state $\mathbf{C}_0 = \mathbf{0}$ [S1, unofficial].
    *   For $k = 1$ to $K$:
        *   Concatenate the current point feature $\mathbf{F}_k$ and the encoded direction $\mathbf{d}_{enc}$: $\mathbf{input}_k = \text{Concat}(\mathbf{F}_k, \mathbf{d}_{enc})$ [S1, unofficial].
        *   Update LSTM state:
            $$ \mathbf{H}_k, \mathbf{C}_k = \text{LSTM}(\mathbf{input}_k, \mathbf{H}_{k-1}, \mathbf{C}_{k-1}) $$
        *   [S1, unofficial]
    *   [S1, unofficial]

5.  **Color Prediction:**
    *   Pass the final hidden state $\mathbf{H}_K$ through a 2-layer Multi-Layer Perceptron (MLP) to predict the color:
        $$ \hat{\mathbf{c}} = \text{MLP}(\mathbf{H}_K) $$
    *   [S1, unofficial]

**Pseudocode:**

import numpy as np

def get_hash_index(coord_x, coord_y, table_size):
    """
    Calculate hash index for a 2D grid coordinate.
    Uses XOR operation as per Algorithm 1 description.
    """
    return (coord_x ^ coord_y) % table_size

def trilinear_interpolate(features_4_corners, fractional_coords):
    """
    Perform trilinear interpolation on 4 corner features.
    fractional_coords: [fx, fy] in [0, 1]
    features_4_corners: [f_tl, f_tr, f_bl, f_br]
    """
    fx, fy = fractional_coords
    # Weights for the four corners
    w_tl = (1 - fx) * (1 - fy)
    w_tr = fx * (1 - fy)
    w_bl = (1 - fx) * fy
    w_br = fx * fy
    
    # Weighted sum
    # Assuming features are numpy arrays of shape (dim,)
    f_tl, f_tr, f_bl, f_br = features_4_corners
    return w_tl * f_tl + w_tr * f_tr + w_bl * f_bl + w_br * f_br

def get_point_feature(x, tri_plane_hash_tables, grid_sizes, num_resolutions, feature_dim_per_level):
    """
    Retrieve feature vector for a 3D point x from the hash-based tri-plane.
    
    Args:
        x: 3D coordinate (np.array [3])
        tri_plane_hash_tables: dict {'xy': [hash_table_1, ...], 'xz': [...], 'yz': [...]}
        grid_sizes: list of grid sizes for each resolution [s_1, ..., s_N]
        num_resolutions: N
        feature_dim_per_level: 2
        
    Returns:
        F: Point feature vector (np.array)
    """
    F = []
    
    # Process each plane
    for plane_name in ['xy', 'xz', 'yz']:
        F_plane = []
        hash_tables = tri_plane_hash_tables[plane_name]
        
        # Project 3D point to 2D plane
        if plane_name == 'xy':
            x_proj = x[:2]
        elif plane_name == 'xz':
            x_proj = [x[0], x[2]]
        elif plane_name == 'yz':
            x_proj = x[1:]
            
        # Process each resolution
        for i in range(num_resolutions):
            s_i = grid_sizes[i]
            hash_table = hash_tables[i]
            
            # Calculate integer grid coordinates
            u = int(np.floor(x_proj[0] / s_i))
            v = int(np.floor(x_proj[1] / s_i))
            
            # Calculate fractional coordinates for interpolation
            fx = (x_proj[0] / s_i) - u
            fy = (x_proj[1] / s_i) - v
            
            # Retrieve features from 4 corners
            # Note: Hash table lookup returns feature vector
            f_tl = hash_table[get_hash_index(u, v, len(hash_table))]
            f_tr = hash_table[get_hash_index(u, v + 1, len(hash_table))]
            f_bl = hash_table[get_hash_index(u + 1, v, len(hash_table))]
            f_br = hash_table[get_hash_index(u + 1, v + 1, len(hash_table))]
            
            # Interpolate
            f_interp = trilinear_interpolate([f_tl, f_tr, f_bl, f_br], [fx, fy])
            F_plane.append(f_interp)
            
        # Concatenate features from all resolutions for this plane
        F_plane_concat = np.concatenate(F_plane)
        F.append(F_plane_concat)
        
    # Concatenate features from all three planes
    F_final = np.concatenate(F)
    return F_final

def g_nelf_decode(ray_origin, ray_direction, tri_plane_hash_tables, grid_sizes, 
                  num_resolutions, feature_dim_per_level, lstm_model, mlp_model,

        ray_direction: 3D vector (normalized)
        ... (other params as above)

        mlp_model: 2-layer MLP network
        num_samples: K
        sh_degree: Degree for Spherical Harmonics

        color: Predicted RGB color

    # Assuming a bounding box intersection is handled externally or simplified here

    t_vals = np.linspace(t_min, t_max, num_samples)
    points = ray_origin + ray_direction * t_vals[:, np.newaxis]
    
    # 2. Get feature sequence
    feature_sequence = []
    for p in points:
        F_k = get_point_feature(p, tri_plane_hash_tables, grid_sizes, 
                                num_resolutions, feature_dim_per_level)
        feature_sequence.append(F_k)

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** At the highest resolution, approximately 100,000 3D positions map to a single hash entry [S1, unofficial]. This is not a bug but a feature: positions far from the visible surface have low volume rendering weight and do not significantly influence the color. Thus, the features at high resolutions adaptively concentrate on capturing appearance features of the visible surface [S1, unofficial].
*   **Sequential Order:** The method relies on the temporal order of ray propagation (near to far). Using permutation-invariant models like Transformers or simple MLPs on the feature sequence leads to inferior performance because they lose this sequential information [S1, unofficial].
*   **Training Data:** G-NeLF is designed to work with very few views (≤100). It does not require synthesizing pseudo-views, which is a common requirement for other NeLF methods [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The feature acquisition step is $O(K \cdot N \cdot P)$ where $K$ is the number of samples per ray, $N$ is the number of resolutions, and $P$ is the number of planes (3). The LSTM decoding is $O(K \cdot H)$ where $H$ is the hidden size. Overall, it is efficient due to the small model size and lightweight decoder.
*   **Memory Complexity:** The model size is extremely small, approximately 0.95 MB to 1.41 MB [S1, unofficial]. This is roughly one-tenth the size of Instant-NGP (64.1 MB) and TensoRF (71.8 MB) [S1, unofficial].
*   **Performance:** On the Realistic Synthetic 360° dataset at 400x400 resolution, G-NeLF surpasses R2L by 0.04 dB PSNR using only 100 views and 0.95 MB model size [S1, unofficial]. It surpasses VQRF by 0.79 dB PSNR at a comparable model size (1.4 MB) [S1, unofficial]. It achieves comparable rendering quality to standard NeRF methods like Instant-NGP and TensoRF [S1, unofficial].
*   **Strengths:** Extremely compact model size; does not require pseudo-view synthesis; leverages sequential information for better inference; handles high-resolution hash collisions effectively by focusing on visible surfaces.
*   **Limitations:** Does not model volume density explicitly, which may limit its applicability to tasks requiring physical properties (e.g., relighting, shadow casting) compared to NeRF [S1, unofficial]. Performance may degrade on scenes with very complex geometry that cannot be well-approximated by the tri-plane projection [G].

## Background
G-NeLF was introduced in the paper "G-NeLF: Memory- and Data-Efficient Hybrid Neural Light Field for Novel View Synthesis" [S1, unofficial]. It addresses the limitations of previous Neural Light Field (NeLF) methods, which often required training a NeRF model first and then synthesizing over 10,000 views to train the NeLF, leading to high storage and computational overhead [S1, unofficial]. G-NeLF proposes a hybrid approach combining grid-based spatial awareness with a recurrent neural network (LSTM) to decode ray colors directly from a feature sequence, enabling high-quality novel view synthesis with minimal data and storage requirements [S1, unofficial].
