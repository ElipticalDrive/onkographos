# UE4-NeRF

Also called: UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene

## Overview
UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale 3D scenes by partitioning the environment into sub-NeRFs represented as textured polygonal meshes and integrating them into the Unreal Engine 4 (UE4) rasterization pipeline [S1]. Unlike standard differentiable volume rendering methods that rely on ray marching, UE4-NeRF extracts explicit geometric meshes optimized via neural networks, enabling real-time frame rates (up to 43 FPS at 4K) and scene editing capabilities [S1]. It distinguishes itself from sibling methods like [Mobile-NeRF](13622-mobile-nerf.md) and [Mega-NeRF](14098-mega-nerf.md) by using regular octahedra for mesh initialization to handle tilted surfaces and multi-resolution hash encoding for training acceleration, while avoiding the opacity binarization limitations of Mobile-NeRF [S1].

## How it works
**Inputs:** A set of posed images with GPS metadata (resolution ~6000×4000) and camera poses; a large-scale scene (e.g., farmland, industrial parks) spanning several square kilometers.
**Outputs:** A set of textured polygonal meshes (shading meshes) for each block, optimized vertex positions, and a neural shader (HLSL fragment shader) deployed in UE4.

**Data Structures:**
1.  **Block Partition:** The scene is divided into overlapping blocks. Each training area is slightly larger than the corresponding scene area to ensure smooth transitions at boundaries [S1].
2.  **Grid Initialization:** A $128 \times 128 \times 128$ grid is initialized for each block [S1].
3.  **Mesh Geometry:** Polygonal meshes are constructed from the grid. For each grid center point, the center and its six neighbors (front, back, left, right, top, bottom) are selected to form faces. Specifically, a regular octahedron with 20 faces (8 exterior, 12 interior) is used per grid cell to address convergence issues on tilted surfaces [S1].
4.  **Texture Atlas:** Stores feature vectors and opacity information for the mesh vertices/faces [S1].
5.  **Network Parameters:**
    *   **Encoder MLP ($E$):** 4 layers. Dimensions: $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$. Input: Hash-encoded position $p_i$. Output: Opacity $\alpha_i$ and 8-dimensional feature vector $M_i$ [S1].
    *   **Decoder MLP ($D$):** 3 layers. Dimensions: $17 \times 16$, $16 \times 16$, $16 \times 3$. Input: Feature vector $M_i$ and spherical harmonic encoded direction $SH(d_i)$. Output: Color $c_i$ [S1].
6.  **Level of Detail (LOD) Hierarchy:** Meshes are trained at varying levels of detail. Coarser meshes are used for higher observation heights to maintain real-time performance [S1].

**Algorithm Steps:**

1.  **Coordinate Transformation:** Convert GPS-captured drone imagery coordinates to the UE4 coordinate system.
    *   X-axis: East.
    *   Y-axis: South.
    *   Z-axis: Up.
    *   Scale: 100:1 (UE4 units to real-world units) [S1].

2.  **Block Partitioning:**
    *   Partition the large scene into multiple blocks.
    *   Train a coarse model for sub-region segmentation to capture overall terrain and building outlines.
    *   Filter images associated with sub-regions and apply a mask to exclude pixels outside the scene area [S1].

3.  **Mesh Initialization:**
    *   Initialize a $128 \times 128 \times 128$ grid for the block.
    *   Select the center point of each grid and its six neighbors to create polygonal meshes.
    *   Construct regular octahedra (20 faces) for each cell [S1].

4.  **Neural Network Definition:**
    *   Define the Encoder $E$ and Decoder $D$ as defined in the data structures.
    *   Implement the computationally intensive portions (hash encoding, MLP inference) using CUDA for GPU parallel computing [S1].
    *   Use multi-resolution hash encoding (from Instant-NGP) for position $p_i$ [S1].
    *   Encode viewing direction $d_i$ using Spherical Harmonics $SH(d_i)$ [S1].

5.  **Training Optimization:**
    *   For each ray $r(t) = o + td$ from the camera origin, calculate the intersection with the polygonal meshes.
    *   The intersection point serves as the sampling point.
    *   Continuously optimize the vertex positions of the meshes during training.
    *   Optimize the parameters of the Encoder-Decoder network ($\theta_E, \theta_D$).
    *   Train for 80,000 epochs per block to achieve convergence [S1].

6.  **Pre-rendering and Extraction:**
    *   Extract pre-rendered polygonal meshes at different levels of detail (LOD).
    *   Encode texture maps (feature vectors and opacity) in the network outputs [S1].

7.  **Rendering in UE4:**
    *   Implement the Decoder MLP as an HLSL fragment shader in UE4.
    *   The shader takes feature vectors (from the texture atlas) as input and outputs colors.
    *   Combine the extracted meshes with the UE4 rasterization pipeline.
    *   Apply LOD selection based on observation height: use coarser meshes for higher viewpoints [S1].

**Parameters:**
*   Grid size: $128 \times 128 \times 128$ [S1].
*   Octahedron faces: 20 (8 exterior, 12 interior) [S1].
*   Encoder MLP: 4 layers, dims $32 \times 64, 64 \times 64, 64 \times 64, 64 \times 8$ [S1].
*   Decoder MLP: 3 layers, dims $17 \times 16, 16 \times 16, 16 \times 3$ [S1].
*   Training hardware: 1 Nvidia RTX 3090 GPU [S1].
*   Training iterations: 80,000 epochs per block [S1].
*   Training time: ~40 minutes per block on 1×RTX 3090 [S1].
*   Coordinate system: X=East, Y=South, Z=Up [S1].
*   World scale: 100:1 [S1].

**Edge Cases and Pitfalls:**
*   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces. UE4-NeRF addresses this by using regular octahedra [S1].
*   **Transparency:** Mobile-NeRF cannot handle transparent/semi-transparent objects (water, glass) due to opacity binarization. UE4-NeRF stores opacity in texture maps to mitigate this [S1].
*   **Performance:** Semi-transparent objects (e.g., vegetation) increase computational overhead, reducing frame rates [S1].
*   **Pre-rendering Gaps:** Pre-rendering cannot capture rays from all viewing angles, potentially resulting in gaps or holes in the final scene [S1].
*   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, causing evaluation metrics (PSNR/SSIM) to underestimate actual reconstruction quality [S1].
*   **Memory:** Rendering large scenes (square kilometers) incurs significant memory overhead. Increasing accuracy amplifies memory consumption [S1].
*   **Hardware Dependency:** Requires CUDA and NVIDIA GPUs [S1].

## Operating characteristics
*   **Training Speed:** 1000× faster than Mobile-NeRF [S1].
    *   Per block: 40 minutes on 1×RTX 3090 (vs. 48h on 4×3090 for Mobile-NeRF, 36h on 1×3090 for Mega-NeRF) [S1].
    *   Full scene (n blocks): 1 hour + (40 minutes × n/4) on 1×RTX 3090 [S1].
*   **Rendering Performance:**
    *   Real-time rendering at 4K resolution with up to 43 FPS (Level-1 mesh hierarchy) [S1].
    *   50 FPS on full scene at 2K resolution; ≥70 FPS on individual blocks at 2K resolution [S1].
*   **Memory:** Significant memory overhead for large scenes (square kilometers). Memory consumption increases with accuracy [S1].
*   **Strengths:**
    *   Real-time interactive rendering of large-scale scenes.
    *   Handles tilted surfaces and semi-transparent objects better than Mobile-NeRF.
    *   Scene editing capabilities via UE4 integration (occlusion handling, object addition) [S1].
    *   High fidelity for small objects (power lines) and dense textures compared to Mip-NeRF [S1].
*   **Limitations:**
    *   Requires NVIDIA GPUs and CUDA [S1].
    *   Pre-rendering artifacts (gaps/holes) due to limited viewing angles [S1].
    *   Evaluation metrics may underestimate quality due to exposure mismatch in UE4 [S1].
    *   Semi-transparent objects reduce frame rates [S1].
*   **When to use:** Real-time visualization of large-scale outdoor scenes (farmland, construction sites) where interactive frame rates and scene editing are required.
*   **When not to use:** Small-scale indoor scenes, scenes requiring perfect geometric fidelity without pre-rendering artifacts, or environments without NVIDIA hardware.

## Background
UE4-NeRF was introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" [S1]. It was developed to address the limitations of existing NeRF methods in real-time rendering and large-scale scene handling. Previous methods like Mobile-NeRF and Mega-NeRF were either too slow, limited to grid structures, or produced blurry results. UE4-NeRF combines NeRF with the Unreal Engine 4 rasterization pipeline, leveraging LOD techniques and multi-resolution hash encoding to achieve real-time performance. It is used for drone-captured large-scale scenes and evaluated on the Mega-NeRF public dataset [S1].
