# View Sampler

Also called: View Selection Policy, View Selection Strategy, ViewSampler Abstract Base Class, ViewSampler Abstract Interface

## Overview
The View Sampler is an abstract base class that defines the interface for sampling context and target views during training or inference [S1, S2, S3, unofficial]. It determines which input images (context) and which novel views (target) are used in each optimization step, enabling strategies that range from random sampling to geometry-aware selection [S1, S2, S3, unofficial].

## How it works
### Inputs and Outputs
*   **Inputs to `__init__`**:
    *   `cfg`: Configuration object [S3, unofficial].
    *   `stage`: Current training stage (e.g., training, validation) [S1, S3, unofficial].
    *   `is_overfitting`: Boolean flag indicating if the model is overfitting to a single scene [S1, S2, S3, unofficial].
    *   `cameras_are_circular`: Boolean flag indicating if the camera setup is circular [S1, S2, S3, unofficial].
    *   `step_tracker`: Optional tracker for the global training step [S1, S2, S3, unofficial].
*   **Inputs to `sample`**:
    *   `scene`: The scene object containing camera data [S3, unofficial].
    *   `extrinsics`: Float tensor of shape `[view, 4, 4]` containing camera extrinsic matrices [S2, S3, unofficial].
    *   `intrinsics`: Float tensor of shape `[view, 3, 3]` containing camera intrinsic matrices [S2, S3, unofficial].
    *   `device`: The device (CPU/GPU) for the output tensors [S3, unofficial].
*   **Outputs of `sample`**: A tuple containing:
    1.  `context_view`: Int64 tensor of shape `[context_view]` containing indices of context camera views [S2, S3, unofficial].
    2.  `target_view`: Int64 tensor of shape `[target_view]` containing indices of target camera views [S2, S3, unofficial].
    3.  `overlap`: Float tensor of shape `[overlap]` representing the overlap metric between context and target views [S2, S3, unofficial].

### Data Structures and Properties
The abstract class maintains the following instance variables [S3, unofficial]:
*   `cfg`: The configuration.
*   `stage`: The current stage.
*   `is_overfitting`: The overfitting flag.
*   `cameras_are_circular`: The circular camera flag.
*   `step_tracker`: The step tracker.

It exposes the following abstract properties and methods [S3, unofficial]:
*   `num_target_views`: Returns the integer count of target views.
*   `num_context_views`: Returns the integer count of context views.
*   `global_step`: Returns the current global step. If `step_tracker` is `None`, it returns 0; otherwise, it returns `step_tracker.get_step()` [S3, unofficial].

### Interface Specification
The abstract class defines the contract for view selection strategies [S3, unofficial]. Implementations must follow these steps:
1.  Initialize instance variables (`cfg`, `stage`, `is_overfitting`, `cameras_are_circular`, `step_tracker`) in the constructor [S3, unofficial].
2.  Implement abstract properties `num_target_views` and `num_context_views` to return the required integer counts [S3, unofficial].
3.  Implement `global_step` to return 0 if `step_tracker` is `None`, otherwise call `step_tracker.get_step()` [S3, unofficial].
4.  Implement `sample(scene, extrinsics, intrinsics, device)` to return a tuple of `(context_view, target_view, overlap)` tensors on the specified device [S2, S3, unofficial].

### Pseudocode
```python
from abc import ABC, abstractmethod
from typing import Tuple, Optional
import torch
from torch import Tensor

class ViewSampler(ABC):
    def __init__(
        self,
        cfg,
        stage,
        is_overfitting: bool,
        cameras_are_circular: bool,
        step_tracker: Optional['StepTracker'] = None
    ):
        self.cfg = cfg
        self.stage = stage
        self.is_overfitting = is_overfitting
        self.cameras_are_circular = cameras_are_circular
        self.step_tracker = step_tracker

    @property
    def global_step(self) -> int:
        if self.step_tracker is None:
            return 0
        return self.step_tracker.get_step()

    @property
    @abstractmethod
    def num_target_views(self) -> int:
        """Returns the number of target views."""
        pass

    @property
    @abstractmethod
    def num_context_views(self) -> int:
        """Returns the number of context views."""
        pass

    @abstractmethod
    def sample(
        self,
        scene,
        extrinsics: Tensor,  # Shape: [view, 4, 4]
        intrinsics: Tensor,  # Shape: [view, 3, 3]
        device: torch.device
    ) -> Tuple[Tensor, Tensor, Tensor]:
        """
        Samples context and target views.
        
        Args:
            scene: The scene object.
            extrinsics: Camera extrinsics.
            intrinsics: Camera intrinsics.
            device: Target device for tensors.
            
        Returns:
            context_view: Int64 tensor [context_view]
            target_view: Int64 tensor [target_view]
            overlap: Float tensor [overlap]
        """
        pass
```

### Edge Cases and Pitfalls
*   **Step Tracker Null**: If `step_tracker` is not provided, `global_step` defaults to 0 to prevent null pointer exceptions [S3, unofficial].

## Subtopics

### [Diverse View Selection via Overlap and Distance](10788-diverse-view-selection-via-overlap-and-distance.md)
This method selects a diverse subset of $N_v$ camera views from a 3D scene by iteratively sampling candidates and accepting them only if they satisfy thresholds for spatial overlap and geometric distance relative to already selected views. It is chosen when view diversity is critical to prevent the model from overfitting to similar viewpoints.

### Viewpoint Sampling with Blend Iteration
This variant selects training cameras from a standard viewpoint stack or an origin viewpoint stack based on the current training iteration [S5, unofficial]. It enables a transition from standard to origin viewpoints after a specified blend threshold (`opt.blend_until_iter`) [S5, unofficial]. It is chosen when a curriculum learning approach is desired, starting with standard training views and gradually shifting to origin views [S5, unofficial].

### [Sparse View Sampling Strategy](15397-sparse-view-sampling-strategy.md)
This strategy constructs a training pair by selecting a random target (query) view and sampling a small, fixed number of nearby but spatially sparse source views to optimize radiance fields or semantic fields efficiently. It differs from dense sampling by reducing computational load per iteration while maintaining geometric consistency through proximity, and from diverse selection strategies by prioritizing local sparsity over global coverage.

### Geometry-Aware View Sampling
GVS selects views based on error and pose/direction distance [S6, unofficial]. It is part of a pipeline that includes error-guided sparse pixel sampling [S6, unofficial]. Replacing GVS with random view sampling (RVS) leads to consistent drops in PSNR and perceptual metrics [S6, unofficial]. It is chosen when high-fidelity reconstruction is prioritized over training speed, as it focuses sampling on geometrically complex or high-error regions [S6, unofficial].

## Operating characteristics
*   **Time Complexity**: Not given in the sources [S4, unofficial].
*   **Memory Complexity**: Not given in the sources [S4, unofficial].
*   **Measured Performance**: Geometry-Aware View Sampling improves PSNR and perceptual metrics compared to random view sampling [S6, unofficial]. Sparse View Sampling reduces computational load per iteration while maintaining geometric consistency through proximity [S1, unofficial]. Progressive Global View Sampling dynamically adjusts the probability density of camera angles to prioritize frontal views early and back views later [S1, unofficial].
*   **Scaling**: Not given in the sources [S4, unofficial].
*   **Strengths**: Flexible interface allows for various sampling strategies [S1, S2, S3, unofficial]. Geometry-aware sampling focuses on geometrically complex or high-error regions [S6, unofficial]. Blend iteration supports transitioning between viewpoint stacks [S5, unofficial].
*   **Limitations**: Geometry-aware sampling is computationally more intensive [S6, unofficial]. Requires careful tuning of blend thresholds and overlap metrics [S5, unofficial].

## Background
Defined in `pixelsplat`, `NoPoSplat`, and `AnySplat` as an abstract base class for view selection strategies [S1, S2, S3, unofficial]. Used within training loops to dynamically select context and target views for radiance field optimization [S1, S2, S3, unofficial].
