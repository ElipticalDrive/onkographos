# NeRF-Casting

Also called: NeRF-Casting: Improved View-Dependent Appearance with Consistent Reflections

## Overview
NeRF-Casting synthesizes photorealistic specular appearance and reflections in real-world scenes by integrating ray tracing into the Neural Radiance Field rendering pipeline [S1]. It solves the problem of view-dependent appearance modeling by replacing expensive neural network queries for outgoing radiance with reflection rays cast into the NeRF geometry, which naturally synthesizes consistent reflections of nearby and distant content [S1]. Unlike Ref-NeRF, which requires a large MLP to encode the entire environment at every point, or inverse rendering methods that perform expensive Monte Carlo integration over the hemisphere, NeRF-Casting renders accurate reflections with low computational overhead by sampling features from traced reflection rays and decoding them with a small MLP [S1].

## How it works
NeRF-Casting improves upon the standard NeRF architecture [Parent](11313-model-architecture-modifications.md) by decoupling geometry representation from view-dependent specular appearance [S1]. Instead of predicting color directly from position and view direction via a large MLP, it predicts a feature vector and decodes it into color using a small MLP, where the feature vector is obtained by casting reflection rays into the scene [S1].

### Inputs and Outputs
*   **Inputs**: Camera ray origin $\mathbf{o}$, camera ray direction $\mathbf{d}$, a NeRF geometry representation, and a small color decoder MLP [S1].
*   **Outputs**: Volume-rendered color $\bar{\mathbf{c}}$ for the pixel [S1].

### Data Structures
The method modifies the standard NeRF query logic:
1.  **NeRF Representation**: A function $F_\Theta$ that maps a 3D position to volume density $\tau$ [S1]. This representation is queried along both camera and reflection rays [S1].
2.  **Color Decoder**: A small Multi-Layer Perceptron (MLP), denoted as $D$, that maps a feature vector $\mathbf{f} \in \mathbb{R}^k$ to RGB color $\mathbf{c} \in \mathbb{R}^3$ [S1]. The decoder is significantly smaller than the standard NeRF shading MLP [S1].

### Spatial Contraction
To allocate higher representational capacity to points near the cameras, NeRF-Casting employs a spatial contraction function $C: \mathbb{R}^3 \rightarrow \mathbb{R}^3$ that maps all points in $\mathbb{R}^3$ to a sphere of radius 2 [S1].

$$
C(\mathbf{x}) = 
\begin{cases} 
\mathbf{x} & \text{if } \|\mathbf{x}\| \le 1 \\
\frac{1}{2 - \|\mathbf{x}\|} \frac{\mathbf{x}}{\|\mathbf{x}\|} & \text{if } \|\mathbf{x}\| > 1 
\end{cases}
$$

The contracted coordinate $C(\mathbf{x})$ is used as the input to all NeRF density queries [S1].

### Rendering Algorithm
The rendering process for a single camera ray proceeds as follows:

1.  **Sample Points**: Sample $N$ points $t^{(i)}$ along the camera ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ for $i = 1, \dots, N$ [S1].
2.  **Query Density**: For each sample point $\mathbf{x}^{(i)} = \mathbf{o} + t^{(i)}\mathbf{d}$, query the NeRF to obtain the volume density $\tau^{(i)} = F_\Theta(C(\mathbf{x}^{(i)}))$ [S1].
3.  **Cast Reflection Rays**: For each sample point $\mathbf{x}^{(i)}$ with non-negligible density, cast a reflection ray [S1]. The reflection direction $\mathbf{d}_{\text{refl}}^{(i)}$ is computed from the surface normal $\mathbf{n}^{(i)}$ at $\mathbf{x}^{(i)}$ using $\mathbf{d}_{\text{refl}}^{(i)} = \mathbf{d} - 2(\mathbf{d} \cdot \mathbf{n}^{(i)})\mathbf{n}^{(i)}$ [G]. The source does not specify the exact normal estimation method [S1].
4.  **Trace Reflection**: Trace the reflection ray $\mathbf{r}_{\text{refl}}(t) = \mathbf{x}^{(i)} + t\mathbf{d}_{\text{refl}}^{(i)}$ through the NeRF geometry [S1]. Sample points along this reflection ray and use the standard volume rendering equation to compute a feature vector $\mathbf{f}^{(i)}$ representing the anti-aliased content of the reflected scene [S1].
5.  **Decode Color**: Pass the feature vector $\mathbf{f}^{(i)}$ through the small Color Decoder MLP $D$ to obtain the color $\mathbf{c}^{(i)} = D(\mathbf{f}^{(i)})$ [S1].
6.  **Volume Render**: Combine the colors $\mathbf{c}^{(i)}$ and densities $\tau^{(i)}$ using the standard volume rendering equation to produce the final pixel color $\bar{\mathbf{c}}$ [S1].

The weight $w^{(i)}$ for the $i$-th sample is calculated as:
$$ w^{(i)} = \left( 1 - \exp\left(-\tau^{(i)} \left( t^{(i+1)} - t^{(i)} \right) \right) \right) \exp\left( -\sum_{j < i} \tau^{(j)} \left( t^{(j+1)} - t^{(j)} \right) \right) $$

The final color is:
$$ \bar{\mathbf{c}} = \sum_i w^{(i)} \mathbf{c}^{(i)} $$

def spatial_contraction(x):
    """Maps points in R^3 to a sphere of radius 2 [S1]."""
    norm = np.linalg.norm(x)
    if norm <= 1.0:
        return x
    return (1.0 / (2.0 - norm)) * (x / norm)

def volume_render_ray(origin, direction, num_samples=64):

    t_vals = np.linspace(0.0, 10.0, num_samples)  # [G] Ray segment bounds depend on scene
    points = origin[:, np.newaxis] + direction[:, np.newaxis] * t_vals[np.newaxis, :]
    contracted = np.array([spatial_contraction(p) for p in points.T])
    
    densities = np.zeros(num_samples)
    features = np.zeros((num_samples, 32))
    for i in range(num_samples):
        densities[i], features[i] = query_nerf(contracted[i])
        
    delta = np.diff(np.concatenate(([0.0], t_vals)))
    alpha = 1.0 - np.exp(-densities * delta)
    T = np.cumprod(1.0 - alpha + 1e-10)
    T = np.concatenate(([1.0], T[:-1]))
    weights = alpha * T
    
    rendered_feature = np.sum(weights[:, np.newaxis] * features, axis=0)
    return rendered_feature, weights

def estimate_normal(x):
    """Estimates surface normal via numerical density gradient [G]."""
    eps = 1e-4
    x_c = spatial_contraction(x)
    grad = np.zeros(3)
    for axis in range(3):
        x_p = x.copy(); x_p[axis] += eps
        x_m = x.copy(); x_m[axis] -= eps
        grad[axis] = (query_nerf(spatial_contraction(x_p))[0] - query_nerf(spatial_contraction(x_m))[0]) / (2 * eps)
    return grad / np.linalg.norm(grad)

def color_decoder(feature):

    return feature / (np.linalg.norm(feature) + 1e-8)

def render_camera_ray(origin, direction, num_samples=64):
    """Renders a single camera ray using NeRF-Casting [S1]."""
    t_vals = np.linspace(0.0, 10.0, num_samples)
    points = origin[:, np.newaxis] + direction[:, np.newaxis] * t_vals[np.newaxis, :]
    contracted = np.array([spatial_contraction(p) for p in points.T])
    
    densities = np.zeros(num_samples)
    for i in range(num_samples):
        densities[i], _ = query_nerf(contracted[i])
        
    delta = np.diff(np.concatenate(([0.0], t_vals)))
    alpha = 1.0 - np.exp(-densities * delta)
    T = np.cumprod(1.0 - alpha + 1e-10)
    T = np.concatenate(([1.0], T[:-1]))
    weights = alpha * T
    
    final_color = np.zeros(3)
    for i in range(num_samples):
        if weights[i] > 1e-5:
            x = points[:, i]
            normal = estimate_normal(x)
            d_refl = direction - 2 * np.dot(direction, normal) * normal
            feature, _ = volume_render_ray(x, d_refl, num_samples=64)

            final_color += weights[i] * color
    return final_color

### Parameters
*   **Spatial Contraction**: The sphere radius is fixed at 2 [S1].
*   **Reflection Ray Sampling**: The number of samples along the reflection ray is not specified in the source, but the method implies it is sufficient to capture anti-aliased features [S1].
*   **Color Decoder Size**: Described as "small" and "inexpensive" compared to the standard NeRF MLP [S1]. Exact dimensions are not given [S1].

### Edge Cases and Pitfalls
*   **Normal Estimation**: The source does not specify how surface normals are estimated for reflection ray casting; using density gradients can be noisy in sparse regions [G].
*   **Reflection Ray Tracing**: Tracing reflection rays increases computational cost per sample compared to standard NeRF, but remains significantly cheaper than inverse rendering methods that require hundreds to thousands of samples per point [S1].
*   **Feature Dimensionality**: The dimensionality of the feature vector $\mathbf{f}$ is not specified [S1].

## Operating characteristics
*   **Time Complexity**: Higher than standard NeRF due to additional reflection ray tracing, but significantly lower than inverse rendering methods that perform Monte Carlo integration over the hemisphere [S1].
*   **Memory Complexity**: Similar to standard NeRF, as it does not require storing large environment maps or complex light transport data structures [S1].
*   **Strengths**: Synthesizes photorealistic specular appearance and reflections in real-world scenes; produces consistent reflections of nearby and distant content; requires comparable optimization time to state-of-the-art view synthesis models [S1].
*   **Limitations**: Requires ray tracing integration; performance depends on the accuracy of normal estimation for reflection directions [S1].
*   **When to use**: When view synthesis of scenes containing shiny objects is required and photorealistic specular appearance is needed [S1].

## Background
NeRF-Casting was introduced by the authors of the paper "NeRF-Casting: Improved View-Dependent Appearance with Consistent Reflections" [S1]. It addresses the limitations of prior NeRF methods that rely on large neural networks to model outgoing radiance, which severely limits optimization and rendering speed [S1]. It is distinct from Ref-NeRF and other inverse rendering approaches by using ray tracing to naturally synthesize reflections without requiring the MLP to represent the full environment at every point [S1].
