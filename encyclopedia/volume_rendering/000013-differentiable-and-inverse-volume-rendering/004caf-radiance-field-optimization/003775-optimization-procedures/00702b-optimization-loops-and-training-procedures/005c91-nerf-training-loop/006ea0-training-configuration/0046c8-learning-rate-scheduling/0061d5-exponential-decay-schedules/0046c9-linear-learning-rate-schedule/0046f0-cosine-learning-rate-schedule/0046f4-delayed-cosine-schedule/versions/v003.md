# Delayed Cosine Schedule

Also called: DelayedSchedule

## Overview
A schedule wrapper that delays the start of a base learning rate schedule using a sinusoidal rate multiplier [S1, unofficial]. It multiplies the output of a base schedule by a delay rate that transitions from a minimum value to 1.0 over a specified number of steps [S1, unofficial].

## How it works
The method computes a delay multiplier that transitions from a minimum value to 1.0 over a specified number of steps, then multiplies this by the output of a base schedule [S1, unofficial].

**Inputs:**
- `step`: Current optimization step (integer) [S1, unofficial].
- `base_schedule`: The underlying Schedule object or callable that returns a base learning rate for a given step [S1, unofficial].
- `delay_steps`: Number of steps over which the delay rate transitions [S1, unofficial].
- `delay_mult`: Minimum multiplier applied during the delay period [S1, unofficial].

**Outputs:**
- `learning_rate`: The final scaled learning rate value [S1, unofficial].

**Steps:**
1. Calculate the normalized step progress for the delay phase: $t = \text{clip}(\frac{\text{step}}{\text{delay\_steps}}, 0, 1)$ [S1, unofficial].
2. Compute the delay multiplier using a sinusoidal interpolation: $\text{delay\_rate} = \text{delay\_mult} + (1 - \text{delay\_mult}) \times \sin(0.5 \times \pi \times t)$ [S1, unofficial].
3. Retrieve the base learning rate from the underlying schedule: $\text{base\_lr} = \text{base\_schedule}(\text{step})$ [S1, unofficial].
4. Return the product: $\text{learning\_rate} = \text{delay\_rate} \times \text{base\_lr}$ [S1, unofficial].

**Pseudocode:**
```python
import math

def delayed_cosine_schedule(step, base_schedule, delay_steps, delay_mult):
    """
    Computes the learning rate using a delayed cosine schedule.
    
    Args:
        step (int): Current optimization step.
        base_schedule (callable): Function that returns the base learning rate for a given step.
        delay_steps (int): Number of steps for the delay transition.
        delay_mult (float): Minimum multiplier during the delay phase.
        
    Returns:
        float: The scaled learning rate.
    """
    # Guard against division by zero if delay_steps is 0 [G]
    if delay_steps <= 0:
        return base_schedule(step)
    
    # Step 1: Clip normalized step to [0, 1]
    t = step / delay_steps
    t = max(0.0, min(1.0, t))
    
    # Step 2: Compute delay_rate using sinusoidal interpolation
    # Formula: delay_mult + (1 - delay_mult) * sin(0.5 * pi * t)
    delay_rate = delay_mult + (1.0 - delay_mult) * math.sin(0.5 * math.pi * t)
    
    # Step 3: Get base learning rate
    base_lr = base_schedule(step)
    
    # Step 4: Return scaled learning rate
    return delay_rate * base_lr
```

**Edge Cases and Pitfalls:**
- **Division by Zero:** If `delay_steps` is 0, the calculation must be guarded to avoid division by zero [G].
- **Negative Steps:** The `clip` operation handles negative steps by clamping $t$ to 0 [S1, unofficial].
- **Precision:** The sine function operates in the $[0, \pi/2]$ range, which is numerically stable [G].

## Subtopics

### [Learning Rate Schedule with Delay](15469-learning-rate-schedule-with-delay.md)
A variant that applies a delay multiplier to a base log-linear interpolation schedule rather than a cosine curve. It combines a 'reverse cosine decay' delay factor with a standard log-linear interpolation between initial and final learning rates. It sets itself apart from its parent [Delayed Cosine Schedule](11854-delayed-cosine-schedule.md) by explicitly defining the delay mechanism as a multiplicative factor applied to a base log-linear schedule, rather than just delaying the start of a base schedule.
