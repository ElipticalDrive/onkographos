# SUDS
Also called: SUDS, Scalable Urban Dynamic Scenes

## Overview
SUDS is a 4D radiance field representation designed for large-scale dynamic urban scenes that factorizes the scene into three separate multi-resolution hash table structures to efficiently encode static, dynamic, and far-field radiance fields [S1]. It solves the problem of scaling neural reconstruction to city-level environments with significant dynamism and multi-video inputs by using unlabeled target signals (RGB, sparse LiDAR, 2D descriptors, and 2D optical flow) for supervision, eliminating the need for expensive 3D bounding box or panoptic segmentation annotations [S1]. Unlike sibling methods that rely on per-object NeRFs or supervised labels, SUDS handles ego-motion and multi-video representations by decomposing the world into stationary topography, transient/dynamic objects, and an environment map, enabling free-viewpoint rendering, semantic decomposition, and 3D scene flow estimation at arbitrary poses and time steps [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ordered RGB images from $N$ videos taken at different days with diverse weather/lighting, associated camera poses, aligned sparse LiDAR depth measurements, 2D self-supervised DINO descriptors, and 2D optical flow predictions [S1].
*   **Outputs:** Rendered RGB color $\hat{C}$, rendered semantic features $\hat{F}$, predicted density $\sigma$, predicted 3D scene flow vectors $s_{t0}$, and shadow ratio $\rho_d$ [S1].

**Data Structures:**
The representation is partitioned into $K$ spatial cells, each trained independently. Each cell contains three branches: Static, Dynamic, and Far-field. Each branch uses a multi-resolution hash table hierarchy.
*   **Hash Tables:** For each branch $b \in \{s, d, e\}$ (static, dynamic, environment) and resolution level $l \in \{0, \dots, L-1\}$, features are stored in a hash table.
*   **Feature Vector:** Each hash entry stores a feature vector $f \in \mathbb{R}^F$.
*   **Hash Indexing:** Instead of storing features at voxel corners, indices are computed via hash functions:
    *   Static: $i_{l,s} = \text{static\_hash}(\text{space}(v_{l,s}))$
    *   Dynamic: $i_{l,d} = \text{dynamic\_hash}(\text{space}(v_{l,d}), \text{time}(v_{l,d}), \text{vid})$
    *   Environment: $i_{l,e} = \text{env\_hash}(\text{dir}(v_{l,e}), \text{vid})$
    *   Where $v_{l,s}$ are 3D spatial voxels, $v_{l,d}$ are 4D spacetime voxels, and $v_{l,e}$ are 3D direction voxels [S1].
*   **Hash Collisions:** Handled via gradient averaging [S1].

**Numbered Steps:**

1.  **Spatial Partitioning:** Split the scene into $K$ spatial cells with centroids $k \in \mathbb{R}^3$. Generate training datasets for each cell by including only datapoints whose camera rays intersect the cell. Prune irrelevant rays using LiDAR depth measurements to ensure visibility [S1].
2.  **Voxel Lookup:** For an input coordinate $(x, d, t, \text{vid})$ where $x \in \mathbb{R}^3$ is position, $d \in \mathbb{R}^3$ is viewing direction, $t$ is frame index, and $\text{vid} \in \{1, \dots, N\}$ is video ID, find surrounding voxels at $L$ resolution levels for the static ($v_{l,s}$), dynamic ($v_{l,d}$), and far-field ($v_{l,e}$) branches. Resolution doubles between levels [S1].
3.  **Hash Indexing:** Compute hash indices for the corners of the surrounding voxels using the specific hash functions defined above. The video ID is used as an auxiliary input to index separate interpolating functions for each video without linear memory growth [S1].
4.  **Feature Interpolation:**
    *   Look up feature vectors corresponding to the corners.
    *   Perform linear interpolation for the static branch.
    *   Perform quadlinear interpolation for the dynamic 4D branch.
    *   Concatenate the interpolated features from all $L$ levels into a feature vector $f \in \mathbb{R}^{LF}$ [S1].
5.  **MLP Evaluation (Per Branch):** Pass the concatenated feature vector $f$ and auxiliary inputs into branch-specific MLPs to obtain outputs:
    *   **Static Branch:** View-dependent color $c_s(x, d, A_{\text{vid}} F(t)) \in \mathbb{R}^3$ and view-independent density $\sigma_s(x) \in \mathbb{R}$. Lighting variations are modeled by conditioning on a latent embedding $A_{\text{vid}} F(t)$, where $A_{\text{vid}}$ is a video-specific matrix and $F(t)$ is a Fourier-encoded time index [S1].
    *   **Dynamic Branch:** Time/video-dependent density $\sigma_d(x, t, \text{vid}) \in \mathbb{R}$, color $c_d(x, t, \text{vid}, d) \in \mathbb{R}^3$, scalar shadow ratio $\rho_d(x, t, \text{vid}) \in [0, 1]$, and 3D scene flow vectors $s_{t0}(x, t, \text{vid}) \in \mathbb{R}^3$ (forward and backward, values in $[-1, 1]$) [S1].
    *   **Far-field Branch:** Environment map color $c_e(d, \text{vid}) \in \mathbb{R}^3$ [S1].
    *   **Semantic Heads:** Each branch outputs $C$-dimensional semantic features $\Phi_s(x)$, $\Phi_d(x, t, \text{vid})$, and $\Phi_e(d, \text{vid})$ to distill DINO features [S1].
6.  **Density and Radiance Combination:**
    *   Compute total density: $\sigma(x, t, \text{vid}) = \sigma_s(x) + \sigma_d(x, t, \text{vid})$ [S1].
    *   Compute total radiance:
        $$ c(x, t, \text{vid}, d) = \frac{(1 - \rho_d)\sigma_s c_s(x, d, A_{\text{vid}} F(t)) + \sigma_d c_d(x, t, \text{vid}, d)}{\sigma} $$
        The shadow ratio $\rho_d$ scales down the static color to model shadows [S1].
7.  **Rendering:** For a camera ray $r$ with direction $d$ at frame $t$ and video $\text{vid}$, accumulate transmittance $T(t)$ and radiance along sampled points $r(t)$:
    $$ \hat{C}(r, t, \text{vid}) = \int_0^{+\infty} T(t) \sigma(r(t), t, \text{vid}) c(r(t), t, \text{vid}, d) dt + T(+\infty) c_e(d, \text{vid}) $$
    where $T(t) = \exp\left(-\int_0^t \sigma(r(s), t, \text{vid}) ds\right)$. If the ray does not hit geometry within the foreground, it intersects the far-field environment map [S1].
8.  **Loss Calculation:** Minimize the total loss $\mathcal{L}$, which is a weighted sum of reconstruction, warping, flow, regularization, and factorization losses (see formulas below) [S1].

**Formulas:**

*   **Reconstruction Losses:**
    *   Photometric (L2): $\mathcal{L}_c(r) = \| C(r) - \hat{C}(r) \|^2$ [S1].
    *   Feature (L1): $\mathcal{L}_f(r) = \| F(r) - \hat{F}(r) \|_1$ [S1].
    *   Depth (L2): $\mathcal{L}_d(r) = \| D(r) - \hat{D}(r) \|^2$, where $\hat{D}(r) = \int_0^{+\infty} T(s) \sigma(r(s)) ds$ [S1].

*   **Flow Losses:**
    *   Predict 3D position $\hat{X}_{t0}(r) = \int_0^{+\infty} T(t) \sigma(r(t)) (r(t) + s_{t0}(r(t))) dt$. Render to 2D using neighboring camera matrix. Minimize distance from observed optical flow $O$: $\mathcal{L}_o(r) = \sum_{t0} \| X(o) - \hat{X}_{t0}(r) \|_1$ [S1].
    *   Cycle Consistency: $\mathcal{L}_{cyc}(r) = \sum_{t0} \sum_x w_{t0}(x,t) \| s_{t0}(x,t) + s_t(x+s_{t0}, t-t0) \|_1$ [S1].
    *   Spatial/Temporal Smoothness: $\mathcal{L}_{sm}$ [S1].
    *   Static Scene Prior: $\mathcal{L}_{slo} = \sum_{t0} \sum_x \| s_{t0}(x,t) \|_1$ [S1].

*   **Warping Losses:**
    *   Advect samples using predicted flow $s_{t0}$ to get warped density $\sigma^w$, color $c^w$, features $\Phi^w$. Render warped color $\hat{C}^w$ and feature $\hat{F}^w$.
    *   Downweight loss in ambiguous regions using weight $W_{t0}(r)$ derived from dynamic geometry difference.
    *   $\mathcal{L}_c^w(r) = \sum_{t0 \in [-1,1]} (1 - W_{t0})(r) \| C(r) - \hat{C}_{t0}^w(r) \|^2$ [S1].
    *   $\mathcal{L}_f^w(r) = \sum_{t0 \in [-1,1]} (1 - W_{t0})(r) \| F(r) - \hat{F}_{t0}^w(r) \|_1$ [S1].

*   **Static-Dynamic Factorization Losses:**
    *   Skewed Binary Entropy: $\mathcal{L}_e(r) = \int_0^{+\infty} H\left(\frac{\sigma_d(r(t))}{\sigma_s(r(t)) + \sigma_d(r(t))}\right) dt$ with $k=1.75$, where $H(x) = -(x \log x + (1-x) \log (1-x))$ [S1].
    *   Max Dynamic Ratio: $\mathcal{L}_d(r) = \max_{r(t)} \frac{\sigma_d(r(t))}{\sigma_s(r(t)) + \sigma_d(r(t))}$ [S1].
    *   Shadow Loss: $\mathcal{L}_\rho(r) = \int_0^{+\infty} \rho_d(r(t))^2 dt$ [S1].

**Parameters:**
*   $F$: Dimensionality of feature vectors in hash tables.
*   $L$: Number of resolution levels in hash table hierarchy (resolution doubles between levels).
*   $N$: Number of input videos.
*   $C$: Dimensionality of DINO feature grid output ($\mathbb{R}^{H \times W \times C}$).
*   $k$: Constant set to 1.75 in skewed binary entropy loss [S1].
*   Training: 250,000 iterations, 4098 rays per batch, Adam optimizer, initial learning rate $5 \times 10^{-3}$ decaying to $5 \times 10^{-4}$ [S1].

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** Handled via gradient averaging, which may introduce noise if collisions are frequent [S1].
*   **Ambiguous Regions:** Warping losses must be downweighted in regions with occlusions or ambiguous dynamic geometry to prevent incorrect flow supervision [S1].
*   **Shadow Over-explanation:** The shadow loss penalizes the squared magnitude of the shadow ratio to prevent the model from using shadows to explain dark regions incorrectly [S1].
*   **Memory Growth:** Video ID is used in hashing but not interpolation to avoid linear memory growth with the number of videos [S1].

## Operating characteristics
*   **Time Complexity:** Training is 10x quicker than state-of-the-art methods relying on ground truth 3D bounding box annotations [S1].
*   **Memory Complexity:** Scales to tens of thousands of objects across 1.2 million frames from 1700 videos spanning hundreds of kilometers. Memory usage is managed via spatial partitioning into $K$ cells and multi-resolution hash tables, avoiding the per-object memory constraints of methods like NSG (which required >1TB for 30s video) [S1].
*   **Scaling:** Scales to city-level environments ($>100 \text{ km}^2$) through spatial partitioning and hash table representations [S1].
*   **Strengths:** Handles ego-motion, multi-video representations, and large-scale dynamism without supervised 3D labels. Enables unsupervised 3D instance segmentation and scene flow [S1].
*   **Limitations:** Relies on the quality of self-supervised 2D descriptors and optical flow. Performance depends on the accuracy of sparse LiDAR depth for visibility pruning [S1].

## Background
SUDS was introduced in the paper "SUDS: Scalable Urban Dynamic Scenes" [S1]. It addresses the limitations of prior dynamic scene representations that required supervised inputs like panoptic segmentation labels or bounding boxes, which are difficult to acquire for in-the-wild captures. It builds on ideas from Instant-NGP [S1] for hash table encoding and MegaNeRF [S1] for spatial partitioning. It is used for free-viewpoint synthesis of dynamic urban scenes, unsupervised 3D instance segmentation, and 3D cuboid detection [S1].
