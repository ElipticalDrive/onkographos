# Viewing Direction Gaussian Splatting


## Overview
Viewing Direction Gaussian Splatting (VDGS) is a hybrid neural rendering method that combines the explicit geometric representation of 3D Gaussian Splatting (GS) with the view-dependent appearance modeling of Neural Radiance Fields (NeRF) [S1]. It solves the limitation of classical GS, where color and opacity are static per primitive, by using a neural network to modulate opacity (and optionally color) based on the viewing direction, thereby accurately rendering specular reflections, transparency, and shadows without significantly increasing training time [S1]. Unlike classical GS, VDGS achieves NeRF-quality view-dependent effects while retaining the fast differentiable rasterization pipeline of Gaussian primitives [S1].

## How it works
**Inputs:** A set of camera poses and corresponding 2D images; initial 3D points from Structure from Motion (SfM) or random initialization.
**Outputs:** A scene representation consisting of a set of 3D Gaussians $\mathcal{G}$ and a neural network $F_{VDGS}$; rendered images for arbitrary viewpoints.

**Data Structures:**
1.  **Gaussian Primitives ($\mathcal{G}$):** A set of $N$ 3D Gaussians. Each Gaussian $i$ is defined by:
    *   Mean position $\mathbf{m}_i \in \mathbb{R}^3$.
    *   Covariance matrix $\mathbf{\Sigma}_i \in \mathbb{R}^{3 \times 3}$ (symmetric positive definite).
    *   Base opacity $\sigma_i \in \mathbb{R}$ (scalar, non-view-dependent).
    *   Color $\mathbf{c}_i \in \mathbb{R}^3$ (RGB).
2.  **Neural Network ($F_{VDGS}$):** A Multi-Layer Perceptron (MLP) with parameters $\Theta$.
    *   Input: Hash-encoded Gaussian mean $\mathbf{m}_i$ and viewing direction $\mathbf{d}$.
    *   Output: Density update $\Delta \sigma_i(\mathbf{d}) \in \mathbb{R}$.
    *   Implementation: 2-layer MLP with LeakyReLU activation [S1].
    *   Encoding: 3D structured hash grid with 12 levels of 3D embedding (resolutions 16 to 512), hash table size $2^{14}$ (16384), feature dimension 2 [S1].

**Numbered Steps:**

1.  **Initialization:** Initialize the Gaussian set $\mathcal{G}$ using SfM points (e.g., from COLMAP) or random points. Set initial means $\mathbf{m}_i$, covariances $\mathbf{\Sigma}_i$, base opacities $\sigma_i$, and colors $\mathbf{c}_i$ [S1].
2.  **Hash Encoding:** For each Gaussian $i$, encode its mean position $\mathbf{m}_i$ using the 3D hash grid to produce a feature vector $\mathbf{h}_i$ [S1].
3.  **Density Update Calculation:** For a given viewing direction $\mathbf{d}$, compute the density update $\Delta \sigma_i(\mathbf{d})$ by passing the hash-encoded mean $\mathbf{h}_i$ and direction $\mathbf{d}$ through the MLP $F_{VDGS}$:
    $$ \Delta \sigma_i(\mathbf{d}) = F_{VDGS}(\mathbf{m}_i, \mathbf{d}; \Theta) $$
    [S1]
4.  **Effective Opacity Calculation:** For each sample $i$ along a ray, calculate the effective opacity $\alpha_i$ using the base opacity $\sigma_i$, the distance between adjacent samples $\delta_i$, and the density update $\Delta \sigma_i(\mathbf{d})$:
    $$ \alpha_i = 1 - \exp\left( \sigma_i \cdot \Delta \sigma_i(\mathbf{d}) \cdot \delta_i \right) $$
    [S1]
    *Note: The source defines $\Delta \sigma_i(\mathbf{d})$ as the output of the network. The term $\sigma_i \cdot \Delta \sigma_i(\mathbf{d})$ acts as the effective volume density for the sample.*
5.  **Rendering (Alpha Compositing):** Compute the pixel color $C(\mathbf{p})$ by blending $N$ ordered overlapping Gaussian samples along the ray:
    $$ C(\mathbf{p}) = \sum_{i \in \mathcal{N}} \mathbf{c}_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    where $\mathcal{N}$ is the set of indices of Gaussians intersecting the pixel, ordered by depth [S1].
6.  **Optimization:** Jointly optimize all parameters: Gaussian means $\mathbf{m}_i$, covariances $\mathbf{\Sigma}_i$, base opacities $\sigma_i$, colors $\mathbf{c}_i$, and MLP weights $\Theta$ using gradient descent via differentiable Gaussian rasterization [S1].
7.  **Pruning and Densification:**
    *   **Pruning:** Every 100 iterations, eliminate Gaussians with opacity below a specific threshold [S1].
    *   **Densification:** Generate new Gaussians in unoccupied areas of 3D space to fill vacant regions [S1].

**Edge Cases and Pitfalls:**
*   **Joint Color and Opacity Update:** Updating both color and opacity via the neural network simultaneously yields slightly worse results than updating only one. This is attributed to the dependency of opacity on color, making joint training ineffective [S1].
*   **Opacity vs. Color Update:** Changing only opacity (Opacity Multiply) provides the most consistently high-quality results on real-world scenes. Changing only color (Color Multiply) performs best on the NeRF Synthetic dataset [S1].
*   **Precision:** The use of hash encoding provides fast queries and superior results compared to frequency encoding for Gaussian means [S1].

## Subtopics

### Differentiable Primitive Assembly
Uses differentiable set operations on primitive distances for occupancy. VDGS differs by using rasterization-based alpha compositing of Gaussians rather than set operations [13657-differentiable-primitive-assembly.md].

### Point-NeRF Representation
Uses point clouds with neural features. VDGS differs by using 3D Gaussians (with covariance) for shape and a NeRF-based MLP for view-dependent updates, whereas Point-NeRF typically uses points with local MLPs [15538-point-nerf-representation.md].

### Frequency-Modulated Point Cloud Rendering
Uses frequency modulation on point clouds. VDGS differs by using Gaussian splatting with hash-encoded NeRF updates for view-dependent appearance [15903-frequency-modulated-point-cloud-rendering.md].

## Operating characteristics
**Time and Memory Complexity:**
*   Training time is comparable to classical Gaussian Splatting (GS), significantly faster than NeRF. For VDGS-30K on RTX 3090: Mip-NeRF360 46m11s, Tanks&Temples 29m45s, Deep Blending 41m29s [S1].
*   Inference FPS is high: Mip-NeRF360 41.35, Tanks&Temples 38.53, Deep Blending 44.72 on RTX 3090 [S1].
*   Memory usage is dominated by the Gaussian primitives and the hash grid. The hash grid size is fixed at $2^{14}$ entries with 2 features per level [S1].

**Measured Performance:**
*   **Mip-NeRF360:** SSIM 0.813, PSNR 27.64, LPIPS 0.220 [S1].
*   **Tanks and Temples:** SSIM 0.851, PSNR 24.02, LPIPS 0.176 [S1].
*   **Deep Blending:** SSIM 0.906, PSNR 29.54, LPIPS 0.243 [S1].
*   **Shiny Blender:** Avg PSNR 30.62 [S1].

**Strengths and Limitations:**
*   **Strengths:** Accurately models light reflection, transparency, and shadows; removes view-dependent artifacts; fast training and inference comparable to GS; better background regulation [S1].
*   **Limitations:** Requires careful tuning of opacity vs. color updates; joint updates are ineffective; performance on synthetic datasets may favor color-only updates [S1].

**When to Use:**
*   Use VDGS when view-dependent effects (specularities, transparency) are critical and classical GS fails to capture them, but NeRF is too slow.
*   Use Opacity Multiply for real-world scenes.
*   Use Color Multiply for synthetic NeRF datasets.

## Background
VDGS was proposed by researchers from the Faculty of Mathematics and Computer Science, Jagiellonian University, and the Department of Engineering, University of Cambridge [S1]. The method was presented in the paper "Gaussian Splatting with NeRF-based Color and Opacity" (arXiv:2312.13729) in 2023 [S1]. It addresses the limitations of both NeRF (slow, hard to locate geometry) and GS (hard to condition, static appearance) by creating a hybrid model [S1]. The implementation is available on GitHub: https://github.com/gmum/ViewingDirectionGaussianSplatting [S1].
