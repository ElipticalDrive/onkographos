# Training and Supervision

Also called: Hybrid Lighting Supervision, Sky Modeling and Object Insertion Losses

## Overview
This article details the supervision strategy for optimizing a hybrid lighting representation that combines a volumetric lighting field with a parametric sky model for street scenes. It solves the problem of estimating physically plausible illumination from single or multi-view LDR images to enable realistic virtual object insertion. It is distinguished from sibling methods by its explicit separation of sky and volumetric lighting components, supervised via a pre-trained sky modeling network and adversarial feedback from object insertion realism rather than pure photometric consistency alone.

## How it works

### Inputs and Outputs
*   **Inputs:**
    *   LDR input images: Perspective crops $I_{crop}$ from panoramas or single images.
    *   Ground truth data: Captured images $I_{gt}$, depth maps $D_{gt}$, sky masks $M_{sky}$, sun direction $f_{dir}$ (for panoramas), and camera poses/intrinsics.
    *   3D Assets: High-quality 3D models (e.g., cars) for insertion.
*   **Outputs:**
    *   Predicted lighting parameters: Sky peak intensity $\hat{f}_{intensity}$, sky direction $\hat{f}_{dir}$, sky latent code $\hat{f}_{latent}$, and a lighting volume representation.
    *   Reconstructed HDR sky $\hat{I}_{pano}$.
    *   Edited image $\hat{I}_{edit}$ containing inserted objects.

### Data Structures
*   **Sky Mask ($M_{sky}$):** Binary mask indicating sky regions in panoramic images.
*   **Pseudo Labels:** HDR estimates ($\tilde{f}_{intensity}, \tilde{f}_{latent}$) generated by a fixed pre-trained sky modeling network from LDR inputs.

### Loss Functions
The total loss is a weighted sum of the following components. All vector norms are Euclidean ($L_2$) unless specified.

1.  **Log-Encoded L2 Loss:** Used for intensity and HDR reconstruction to handle high dynamic range.
    $$ \text{LogEncodedL2}(\hat{x}, x) = \| \log(1 + \hat{x}) - \log(1 + x) \|_2^2 $$
    where $\hat{x}$ is the prediction and $x$ is the target [S1].

2.  **Sky Modeling Supervision (Pre-training):**
    *   Applied to an encoder-decoder network trained on LDR-HDR pairs $(I_{LDR}, I_{HDR})$.
    *   $I_{LDR}$ is derived from $I_{HDR}$ via gamma correction and intensity clipping.
    *   **Peak Direction Loss ($L_{dir}$):** $L_1$ angular error between predicted and ground-truth sun direction.
    *   **Peak Intensity Loss ($L_{intensity}$):** Log-encoded L2 error between predicted and ground-truth peak intensity.
    *   **HDR Reconstruction Loss ($L_{hdr}$):** Log-encoded L2 error between reconstructed and ground-truth HDR panorama.

3.  **Hybrid Lighting Prediction Losses:**
    *   **HDR Sky Branch:**
        *   Input: Perspective crop $I_{crop}$.
        *   Targets: Pseudo labels $\tilde{f}_{intensity}, \tilde{f}_{latent}$ from the pre-trained sky network; ground-truth sun direction $f_{dir}$; LDR panorama $I_{pano}$ within sky mask $M_{sky}$.
        *   $L_{intensity}$: Log-encoded L2 between $\hat{f}_{intensity}$ and $\tilde{f}_{intensity}$.
        *   $L_{latent}$: $L_1$ loss between $\hat{f}_{latent}$ and $\tilde{f}_{latent}$.
        *   $L_{dir}$: $L_1$ angular loss between $\hat{f}_{dir}$ and $f_{dir}$.
        *   $L_{sky\_recon}$: $L_1$ reconstruction loss between $\hat{I}_{pano} \odot M_{sky}$ and $I_{pano} \odot M_{sky}$.
    *   **Lighting Volume Branch:**
        *   Render radiance along camera rays using the predicted lighting volume and sky dome.
        *   $L_{vol}$: $L_2$ loss between rendered radiance and captured ground-truth image $I_{gt}$.
        *   $L_{depth}$: Consistency loss between rendered alpha-channel depth map and ground-truth depth $D_{gt}$.
    *   **Sky Separation Loss:**
        *   Prevents the lighting volume from occluding the sky.
        *   $L_{sep}$: Binary cross-entropy loss supervising sky transmittance $\tau_K$ (from Eq. 1 in source) against sky mask $M_{sky}$.

4.  **Adversarial Supervision (Object Insertion):**
    *   Insert a 3D asset into the scene using estimated lighting.
    *   Check collision/occlusion using depth maps.
    *   $L_{adv}$: Adversarial loss $-D(\hat{I}_{edit})$, where $D$ is a discriminator judging the realism of the edited image $\hat{I}_{edit}$ against real car images.

### Pseudocode

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

def log_encoded_l2(pred, target):
    """
    Computes LogEncodedL2 loss: || log(1 + pred) - log(1 + target) ||_2^2
    """
    return torch.sum(torch.pow(torch.log1p(pred) - torch.log1p(target), 2))

def angular_loss(pred_dir, target_dir):
    """
    Computes L1 angular error between two direction vectors.
    Assumes normalized vectors.
    """
    # Cosine similarity
    cos_sim = torch.sum(pred_dir * target_dir, dim=-1)
    # Clip to avoid numerical instability in acos
    cos_sim = torch.clamp(cos_sim, -1.0, 1.0)
    angle = torch.acos(cos_sim)
    return torch.mean(angle)

class TrainingLoop:
    def __init__(self, sky_model, lighting_net, discriminator, optimizer):
        self.sky_model = sky_model  # Pre-trained, fixed
        self.lighting_net = lighting_net
        self.discriminator = discriminator
        self.optimizer = optimizer

    def step(self, batch):
        """
        Performs one training step.
        batch contains:
        - I_crop: LDR perspective crop
        - I_pano: LDR panorama (for sky branch supervision)
        - M_sky: Sky mask
        - f_dir: Ground truth sun direction
        - I_gt: Ground truth captured image
        - D_gt: Ground truth depth
        - camera_pose, intrinsics
        """
        self.optimizer.zero_grad()

        # 1. Predict Lighting Parameters
        # lighting_net outputs: f_hat_intensity, f_hat_dir, f_hat_latent, lighting_volume, I_hat_pano
        f_hat_intensity, f_hat_dir, f_hat_latent, lighting_volume, I_hat_pano = self.lighting_net(I_crop)

        # 2. Sky Modeling Supervision (Pseudo Labels)
        # Use pre-trained sky model to get targets from LDR panorama
        with torch.no_grad():
            # Sky model takes LDR panorama, outputs HDR pseudo labels
            f_tilde_intensity, f_tilde_latent = self.sky_model(I_pano)

        # 3. Compute Sky Branch Losses
        loss_intensity = log_encoded_l2(f_hat_intensity, f_tilde_intensity)
        loss_latent = F.l1_loss(f_hat_latent, f_tilde_latent)
        loss_dir = angular_loss(f_hat_dir, f_dir)
        
        # L1 reconstruction within sky mask
        sky_masked_pred = I_hat_pano * M_sky
        sky_masked_gt = I_pano * M_sky
        loss_sky_recon = F.l1_loss(sky_masked_pred, sky_masked_gt)

        # 4. Compute Lighting Volume Branch Losses
        # Render radiance along camera rays
        rendered_radiance = render_radiance(lighting_volume, I_hat_pano, camera_pose, intrinsics)
        loss_vol = F.mse_loss(rendered_radiance, I_gt)
        
        # Render depth from alpha channel
        rendered_depth = render_depth_from_alpha(rendered_radiance) # Implementation detail [G]
        loss_depth = F.mse_loss(rendered_depth, D_gt)

        # 5. Sky Separation Loss
        # Supervise sky transmittance tau_K with binary cross entropy against M_sky
        # tau_K is derived from lighting_volume and sky model (Eq 1 in source)
        tau_K = compute_sky_transmittance(lighting_volume)
        loss_sep = F.binary_cross_entropy(tau_K, M_sky.float())

        # 6. Adversarial Loss (Object Insertion)
        # Insert 3D asset using estimated lighting
        # Assume object_insertion_module handles placement, collision, and rendering
        I_hat_edit = object_insertion_module(
            scene_lighting=(lighting_volume, I_hat_pano),
            camera_pose=camera_pose,
            depth_map=rendered_depth,
            asset_path="car_model.obj"
        )
        
        # Discriminator output
        D_output = self.discriminator(I_hat_edit)
        loss_adv = -torch.mean(D_output)

        # 7. Total Loss
        # Weights are hyperparameters not specified in source [G]
        total_loss = (
            loss_intensity + 
            loss_latent + 
            loss_dir + 
            loss_sky_recon + 
            loss_vol + 
            loss_depth + 
            loss_sep + 
            loss_adv
        )

        total_loss.backward()
        self.optimizer.step()

        return {
            "loss_intensity": loss_intensity.item(),
            "loss_latent": loss_latent.item(),
            "loss_dir": loss_dir.item(),
            "loss_sky_recon": loss_sky_recon.item(),
            "loss_vol": loss_vol.item(),
            "loss_depth": loss_depth.item(),
            "loss_sep": loss_sep.item(),
            "loss_adv": loss_adv.item(),
            "total_loss": total_loss.item()
        }
```

### Edge Cases and Pitfalls
*   **Degenerate Sky Occlusion:** Without the sky separation loss, the lighting volume may completely occlude the sky, leading to incorrect illumination. The binary cross-entropy loss on transmittance $\tau_K$ prevents this [S1].
*   **Unrealistic Object Insertion:** If adversarial supervision is omitted, the lighting may be photometrically consistent but produce incorrect shadows or specular highlights on inserted objects. The discriminator $D$ detects these errors [S1].
*   **Precision:** Log-encoded L2 is used to handle the wide dynamic range of HDR data, preventing saturation issues in standard L2 losses [S1].

## Operating characteristics
*   **Time Complexity:** Training involves rendering radiance fields and depth maps for every batch, which is computationally expensive. The adversarial step adds the cost of a discriminator forward pass.
*   **Memory Complexity:** Requires storing the lighting volume representation and sky model parameters. Pseudo-label generation for sky supervision requires storing the pre-trained sky model in memory (though fixed).
*   **Strengths:** Enables realistic virtual object insertion by ensuring lighting consistency with both the environment and inserted objects. Handles HDR estimation from LDR inputs effectively.
*   **Limitations:** Relies on the quality of the pre-trained sky modeling network for pseudo-labels. Requires 3D assets and depth maps for adversarial training.
*   **When to use:** When the goal is not just scene reconstruction but also editing (e.g., inserting virtual objects) with physically plausible lighting.
*   **When not to use:** For simple view synthesis where editing is not required, or when HDR ground truth is available and no sky/volume separation is needed.

## Background
The method originates from "Neural Light Field Estimation for Street Scenes with Differentiable Virtual Object Insertion" [S1]. It addresses the limitation of previous radiance field methods that struggled with realistic object insertion due to inaccurate lighting estimation. The approach combines a parametric sky model with a neural volumetric light field, supervised by a combination of photometric, geometric, and adversarial losses. It utilizes datasets like nuScenes and HoliCity, which provide LDR street-level imagery, and lifts them to HDR pseudo-labels using a pre-trained sky network.
