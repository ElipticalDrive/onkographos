# Switch-NeRF

Also called: HMoHE, Heterogeneous Mixture of Hash Experts

## Overview
Switch-NeRF++ is a large-scale Neural Radiance Field method that uses a trainable decomposition and heterogeneous representation to scale NeRF to large scenes, extending Switch-NeRF with hash-based networks and heterogeneous experts [S1]. It employs a Heterogeneous Mixture of Hash Experts (HMoHE) framework where both the gating network and the experts are hash-based, allowing the network to select a suitable resolution range for each scene part [S1]. Unlike Switch-NeRF which uses homogeneous experts and an MLP-based gating network, Switch-NeRF++ uses heterogeneous hash experts and a hash-based gating network to learn heterogeneous decomposition and representation efficiently [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** 3D point coordinates $\mathbf{x} \in \mathbb{R}^3$, view direction $\mathbf{d} \in \mathbb{R}^3$, and an appearance embedding $\mathbf{a}$.
*   **Outputs:** Volume density $\sigma$ and RGB color $\mathbf{c}$ for the point $\mathbf{x}$.

**Data Structures:**
*   **Hash Experts:** There are $N$ hash experts. Each expert $i$ consists of a multi-resolution hash encoding grid with a distinct resolution range. The minimum resolutions of the experts exponentially increase from 16 to 512, and maximum resolutions from 2048 to 16384 [S1].
*   **Gating Network:** A hash-based gating network $G$ that maps point features into gate values $G(\mathbf{x})$ [S1].
*   **Prediction Heads:** Small MLPs for density and color prediction.

**Numbered Steps:**
1.  **Gating Network Evaluation:** For a 3D point $\mathbf{x}$, the hash-based gating network computes gate values. This involves looking up feature encoding $\mathbf{f}_g$ in the hash encoding by computing a hash value of $\mathbf{x}$, and using a small MLP to predict gating values [S1].
2.  **Gate Normalization:** Compute gate values $G = \text{Softmax}(\mathbf{f}_g)$ [S1].
3.  **Expert Selection:** Select the top-1 hash expert $i$ using $i = \arg \max(G)$ [S1].
4.  **Expert Feature Encoding:** Compute the feature encoding $\mathbf{E}_i(\mathbf{x})$ using the selected hash expert $i$ [S1].
5.  **Gate Application:** Multiply the gate value by the expert output to ensure differentiability: $\hat{\mathbf{E}}_i(\mathbf{x}) = G_i \cdot \mathbf{E}_i(\mathbf{x})$ [S1].
6.  **Direction Encoding:** Compute spherical harmonics of direction $\mathbf{d}$: $\text{SH}_d = \text{SphericalHarmonics}(\mathbf{d})$ [S1].
7.  **Feature Concatenation:** Concatenate features: $\mathbf{f}_{\text{final}} = [\hat{\mathbf{E}}_i(\mathbf{x}), \text{SH}_d, \mathbf{a}]$, where $\mathbf{a}$ is the appearance embedding [S1].
8.  **Density Prediction:** Predict density $\sigma = \text{MLP}_{\text{density}}(\hat{\mathbf{E}}_i(\mathbf{x}))$ [S1].
9.  **Color Prediction:** Predict color $\mathbf{c} = \text{MLP}_{\text{color}}(\hat{\mathbf{E}}_i(\mathbf{x}))$ [S1].
10. **Rendering:** Render the pixel color using volume rendering along the ray [S1].
11. **Loss Calculation:** Compute the rendering loss and the gate balance loss [S1].

**Formulas:**
*   **Transmittance:** $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$ [S1].
*   **Rendered Color:** $\hat{C}(\mathbf{r}) = \sum_{i=1}^{N} T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i$ [S1].
*   **Rendering Loss:** $L_r = \sum_{\mathbf{r} \in \mathcal{R}} ||\hat{C}(\mathbf{r}) - C(\mathbf{r})||^2$ [S1].
*   **Gate Balance Loss:** $L_b = \sum_n f_i g_i$ [S1].
*   **Overall Loss:** $L_o = L_r + \lambda L_b$ [S1].

**Parameters:**
*   Number of hash experts $N = 8$ [S1].
*   Learning rate: $5 \times 10^{-4}$, exponentially decreasing [S1].
*   Balance loss weight $\lambda$: $5 \times 10^{-4}$ [S1].

**Pitfalls:**
*   The discrete selection operation of experts is not differentiable, and gradients cannot be back-propagated through it into the gating network [S1]. This is addressed by multiplying gate values to the expert outputs [S1].
*   Using more gating networks increases memory and computation cost significantly [S1].

**Pseudocode:**
```python
def switch_nerf_forward(x, d, a, gating_hash, experts, density_head, color_head):
    """
    x: 3D point coordinates (N, 3)
    d: View direction (N, 3)
    a: Appearance embedding (N, D_a)
    gating_hash: Hash grid for gating network
    experts: List of N hash grids for experts
    density_head: MLP for density prediction
    color_head: MLP for color prediction
    """
    # 1. Gating Network Evaluation
    # Lookup feature encoding fg in gating_hash using hash of x
    fg = lookup_hash(gating_hash, x)
    # Predict gating values using small MLP
    gate_values = small_mlp(fg)
    
    # 2. Gate Normalization
    G = softmax(gate_values)
    
    # 3. Expert Selection (Top-1)
    # Note: In practice, this is integrated into CUDA implementation
    # For pseudocode, we assume a differentiable approximation or straight-through estimator
    # is used for training, but the selection logic is:
    i = argmax(G, dim=1)
    
    # 4. Expert Feature Encoding
    # Lookup feature encoding Ei(x) in the selected expert's hash grid
    # This requires gathering features from different hash grids based on i
    Ei_x = gather_expert_features(experts, x, i)
    
    # 5. Gate Application
    # Multiply gate value by expert output
    Gi = gather_gate_values(G, i)
    E_hat_i_x = Gi * Ei_x
    
    # 6. Direction Encoding
    SH_d = spherical_harmonics(d)
    
    # 7. Feature Concatenation
    f_final = concatenate([E_hat_i_x, SH_d, a], dim=-1)
    
    # 8. Density Prediction
    sigma = density_head(E_hat_i_x)
    
    # 9. Color Prediction
    c = color_head(E_hat_i_x)
    
    return sigma, c

def render_ray(ray_origin, ray_direction, near, far, num_samples, switch_nerf_forward):
    """
    ray_origin: Origin of the ray (3,)
    ray_direction: Direction of the ray (3,)
    near: Near plane distance
    far: Far plane distance
    num_samples: Number of samples along the ray
    switch_nerf_forward: The Switch-NeRF++ forward function
    """
    # Generate samples along the ray
    t = linspace(near, far, num_samples)
    points = ray_origin + t[:, None] * ray_direction
    
    # Get density and color for each sample
    sigma_list = []
    c_list = []
    for point in points:
        # Assume d and a are constant for the ray or computed per point
        # For simplicity, we assume d and a are passed or computed
        sigma, c = switch_nerf_forward(point, ray_direction, appearance_embedding)
        sigma_list.append(sigma)
        c_list.append(c)
    
    sigma = stack(sigma_list)
    c = stack(c_list)
    
    # Volume Rendering
    # Compute delta distances
    delta = diff(t, prepend=near)
    
    # Compute transmittance
    # T_i = exp(-sum_{j=1}^{i-1} sigma_j * delta_j)
    # Using cumulative sum
    alpha = 1 - exp(-sigma * delta)
    T = exp(-cumsum(sigma * delta))
    T = concatenate([ones_like(T[:1]), T[:-1]]) # T_1 = 1
    
    # Rendered color
    C = sum(T * alpha * c, axis=0)
    
    return C
```

## Subtopics

### Switch-NeRF
Uses an MLP-based gating network and homogeneous experts. It was the first large-scale NeRF framework to automatically learn scene decomposition in an end-to-end manner without heuristic supervision. [Switch-NeRF](14964-suds.md)

### Switch-NeRF++ (Homo.)
Uses a hash-based gating network but homogeneous experts with default Instant-NGP settings for all experts. It is less effective than the heterogeneous version on complex scenes. [Switch-NeRF++ (Homo.)](14964-suds.md)

### Switch-NeRF++ (Heter.)
Uses a hash-based gating network and heterogeneous hash experts with varying resolution ranges. It achieves state-of-the-art results on large-scale scenes. [Switch-NeRF++ (Heter.)](14964-suds.md)

## Operating characteristics
*   **Time Complexity:** Switch-NeRF++ achieves an 8x acceleration in training and a 16x acceleration in rendering compared to Switch-NeRF [S1]. It achieves state-of-the-art results with 5.5h training (50k steps), which is 8x faster than Switch-NeRF (44h) and 5x faster than Mega-NeRF (30h) [S1].
*   **Memory Complexity:** Hash dispatching uses less GPU memory in training compared to MoE dispatching [S1].
*   **Measured Performance:** On the UrbanBIS scene (6.5km2, 13k images), Switch-NeRF++ achieved a PSNR of 20.76, compared to 19.58 for INGP [S1].
*   **Strengths:** Highly scalable to large-scale scenes, end-to-end trainable, efficient hash-based gating and dispatching, heterogeneous representation for diverse scene parts [S1].
*   **Limitations:** Requires careful tuning of expert resolution ranges for optimal performance [S1].
*   **When to use:** Large-scale scene modeling where scalability and efficiency are critical [S1].
*   **When not to use:** Small-scale scenes where simpler methods like Instant-NGP might be sufficient [S1].

## Background
Switch-NeRF++ was introduced in a paper published in IEEE Transactions on Pattern Analysis and Machine Intelligence in 2025 [S1]. It extends the previous Switch-NeRF method [S1]. The method is evaluated on Mega-NeRF, UrbanBIS, Block-NeRF, and MatrixCity datasets [S1].
