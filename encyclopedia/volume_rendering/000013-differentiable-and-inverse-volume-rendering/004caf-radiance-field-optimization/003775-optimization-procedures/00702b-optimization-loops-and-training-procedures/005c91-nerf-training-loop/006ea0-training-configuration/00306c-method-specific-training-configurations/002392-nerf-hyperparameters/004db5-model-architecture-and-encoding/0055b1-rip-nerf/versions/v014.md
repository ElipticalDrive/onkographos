# Rip-NeRF

Also called: Rip-NeRF25k

## Overview
Rip-NeRF is a radiance field method that renders high-fidelity, anti-aliased images by combining cone casting with an anisotropic 3D Gaussian representation encoded via Platonic Solid Projection and Ripmap Encoding [S1]. It differs from sibling methods like Zip-NeRF by replacing inefficient multi-sampling mechanisms with compact, learnable Ripmap features on Platonic solid faces, enabling efficient anisotropic area-sampling [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of calibrated multi-view 2D images.
*   **Outputs:** Rendered RGB images and a trained model (Ripmap Encodings, Gaussian parameters, MLP weights).

**Data Structures:**
1.  **Ripmap Encoding ($R$):** A hierarchical feature grid.
    *   **Base Level ($R_{0,0}$):** Learnable tensor of shape $H \times W \times C$. Default: $H=512, W=512, C=16$ [S1].
    *   **Derived Levels:** Generated from $R_{0,0}$ using averaging operations to ensure consistency and compactness [S1].
2.  **Platonic Solid:** A geometric proxy for the 3D space. Default: Icosahedron with 10 unparalleled faces $\{P_i | i = 1, \dots, n\}$ [S1].
3.  **3D Gaussian:** Characterizes a conical frustum, parameterized by mean $\boldsymbol{\mu} \in \mathbb{R}^3$ and covariance $\boldsymbol{\Sigma} \in \mathbb{R}^{3 \times 3}$ [S1].
4.  **Tiny MLP ($F_\theta$):** A small neural network taking aggregated features and view direction to output density $\sigma$ and color $\mathbf{c}$ [S1].

**Numbered Steps:**

1.  **Cone Casting and Frustum Division:**
    For each pixel, cast a cone into the scene and divide it into multiple conical frustums [S1].

2.  **Gaussian Characterization:**
    Characterize each conical frustum as an anisotropic 3D Gaussian with mean $\boldsymbol{\mu}$ and covariance $\boldsymbol{\Sigma}$ [S1].

3.  **Platonic Solid Projection:**
    Project the 3D Gaussian onto the faces of the Platonic solid. For each face $P_i$:
    *   Compute the projection matrix $M_i \in \mathbb{R}^{3 \times 2}$ mapping the 3D world coordinate system to the 2D coordinate system of plane $P_i$ [S1].
    *   Compute the projected mean $\boldsymbol{\mu}_{proj}$ and covariance $\boldsymbol{\Sigma}_{proj}$ of the 2D Gaussian on plane $P_i$ [S1].

4.  **Ripmap Encoding Query:**
    For each face $P_i$, query a feature vector $\mathbf{f}_i$ from the Ripmap Encoding of that plane using tetra-linear interpolation [S1].
    *   The interpolation position $(p_x, p_y)$ is determined by $\boldsymbol{\mu}_{proj}$ [S1].
    *   The interpolation level $(l_x, l_y)$ is determined by $\boldsymbol{\Sigma}_{proj}$ [S1].
    *   The hyper-parameter $w$ in the level calculation is set to 2.0 to adjust the probability mass coverage of the Gaussian footprint [S1].

5.  **Feature Aggregation:**
    Concatenate all feature vectors $\{\mathbf{f}_i | i = 1, \dots, n\}$ from the Platonic solid faces to form the final feature vector $\mathbf{f}$ of the 3D Gaussian [S1].

6.  **Color and Density Estimation:**
    Concatenate the aggregated feature vector $\mathbf{f}$ with the encoded view direction $\mathbf{d}$ and pass them through the tiny MLP $F_\theta$ to estimate the density $\sigma$ and color $\mathbf{c}$ for the frustum [S1].

7.  **Volume Rendering:**
    Render the pixel color using standard volume rendering with the estimated $\sigma$ and $\mathbf{c}$ [S1].

8.  **Optimization:**
    Optimize the system end-to-end using a photometric loss between rendered and observed images. The loss is scaled by the area of the pixel footprint on the image plane (area loss $L_{area}$) [S1].

**Parameters:**
*   **Ripmap Base Level ($R_{0,0}$):** Shape $512 \times 512 \times 16$ [S1].
*   **Platonic Solid:** Icosahedron (10 faces) [S1].
*   **Hyper-parameter $w$:** 2.0 (controls probability mass coverage) [S1].
*   **Optimizer:** AdamW [S1].
*   **Iterations:** 120k (standard) or 25k (Rip-NeRF25k variant) [S1].
*   **Weight Decay:** $1 \times 10^{-5}$ [S1].
*   **Initial Learning Rate:** $2 \times 10^{-3}$, modulated by MultiStepLR [S1].
*   **Ripmap Learning Rate Scale:** 10.0 times the base learning rate [S1].
*   **Libraries:** `tiny-cuda-nn` for MLP, CUDA kernels for Projection/Encoding, `NerfAcc` for occupancy grid [S1].

**Edge Cases and Pitfalls:**
*   **Empty Space:** Use binary occupancy grid (from NerfAcc) to skip samples in empty areas [S1].
*   **Precision:** Tetra-linear interpolation requires careful handling of boundary conditions in the Ripmap grid [S1].
*   **Degenerate Input:** Calibrated multi-view images are required; uncalibrated inputs are not supported [S1].

## Operating characteristics
*   **Training Time:** 2.6 hours on NVIDIA A100-SXM4-80GB GPU for 120k iterations [S1]. Rip-NeRF25k (25k iterations) takes 32 minutes [S1].
*   **Model Size:** 160 MB [S1].
*   **GPU Memory:** 20 GB during training [S1].
*   **Rendering Speed:** 3 FPS [S1].
*   **Scaling:** Rip-NeRF25k achieves comparable results to Zip-NeRF with only 11.76% of the training time [S1].
*   **Strengths:** High-fidelity anti-aliasing, efficient anisotropic area-sampling, compact model size, fast training compared to Zip-NeRF [S1].
*   **Limitations:** Requires calibrated multi-view images; slightly lower SSIM than Zip-NeRF [S1].
*   **When to Use:** When high-fidelity anti-aliased rendering is needed with limited training time and GPU memory compared to Zip-NeRF [S1].
*   **When Not to Use:** When unbounded scenes are required (Zip-NeRF is designed for this) or when maximum SSIM is prioritized over speed/size [S1].

## Background
Rip-NeRF was introduced in 2024 by authors including SRN, building on previous work in Mip-NeRF, Tri-MipRF, and Zip-NeRF [S1]. It addresses the inefficiency of multi-sampling mechanisms in methods like Zip-NeRF by introducing Ripmap-Encoded Platonic Solids for efficient anisotropic area-sampling [S1].
