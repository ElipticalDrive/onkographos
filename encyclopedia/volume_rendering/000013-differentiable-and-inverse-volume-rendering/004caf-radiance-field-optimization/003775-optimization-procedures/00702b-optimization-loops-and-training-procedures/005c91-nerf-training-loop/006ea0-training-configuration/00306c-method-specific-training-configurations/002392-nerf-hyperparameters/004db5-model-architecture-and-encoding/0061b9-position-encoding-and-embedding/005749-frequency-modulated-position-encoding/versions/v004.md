# Frequency-Modulated Position Encoding

Also called: FM-NeRF Encoding, Frequency-Modulated Point Cloud Rendering with Easy Editing

## Overview
Frequency-Modulated Position Encoding is a coordinate encoding scheme used in point-based radiance field optimization to map 3D spatial coordinates and viewing directions to feature vectors. It solves the problem of representing high-frequency geometric and appearance details in sparse point clouds by narrowing the encoding interval compared to standard NeRF, providing finer basis function support for frequency modulation [S1]. It sets itself apart from standard positional encoding by using a geometric progression of frequencies with a base of $2^{0.5}$ rather than $2$, and from sibling methods like [Mip-NeRF 360 MLP Architecture](14098-mip-nerf-360-mlp-architecture.md) by being specifically tailored for point cloud rasterization rather than continuous volume rendering [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D point coordinate $\mathbf{p} \in \mathbb{R}^3$ or a viewing direction $\mathbf{d} \in S^2$.
*   **Output:** A feature vector $\gamma(\mathbf{p})$ or $\gamma(\mathbf{d})$ of dimension $2 \times L$, where $L$ is the number of frequency bands.

**Data Structures:**
The encoding is a static function; no persistent data structures are required beyond the input vector and the scalar parameter $L$. The output is a concatenated array of sine and cosine values.

**Parameters:**
*   $L$: Number of frequency bands.
    *   For spatial coordinates: $L = 10$ [S1].
    *   For view directions: $L = 2$ [S1].
*   $\lambda_{\text{sparse}}$: Sparse regularization weight. Set to $5 \times 10^{-4}$ [S1].

**Formulas:**
The frequency-modulated position encoding $\gamma(\mathbf{p})$ is defined as [S1]:

$$
\gamma (\mathbf {p}) = \left (\sin \left (2^0 \pi \mathbf {p}\right ), \cos \left (2^0 \pi \mathbf {p}\right ), \sin \left (2^{0.5} \pi \mathbf {p}\right ), \cos \left (2^{0.5} \pi \mathbf {p}\right ), \dots , \sin \left (2^{L-1} \pi \mathbf {p}\right ), \cos \left (2^{L-1} \pi \mathbf {p}\right )\right )
$$

Where:
*   $\mathbf{p}$ is the input coordinate or direction.
*   The exponent of the base 2 increases by $0.5$ for each subsequent band (i.e., frequencies are $2^0, 2^{0.5}, 2^1, \dots, 2^{L-1}$).
*   This contrasts with standard NeRF which uses integer exponents $2^0, 2^1, \dots, 2^{L-1}$ [S1].

**Numbered Steps:**
1.  **Preprocessing (Optional but typical in this context):** Perform 4-20 loops of point cloud denoising and completion. For each denoising step, train for 300 epochs. Remove low-opacity points when training converges [S1].
2.  **Encoding:** For each point $\mathbf{p}$ and direction $\mathbf{d}$, compute $\gamma(\mathbf{p})$ and $\gamma(\mathbf{d})$ using the formula above with respective $L$ values (10 for $\mathbf{p}$, 2 for $\mathbf{d}$) [S1].
3.  **Network Input:** Concatenate $\gamma(\mathbf{p})$ and $\gamma(\mathbf{d})$ (and any other features) to form the input vector for the MLP (e.g., AFNet) [S1].
4.  **Rasterization:** Expand each point to a disk. Select radius to cover gaps between points (prevent bleeding) while keeping it small (avoid edge expansion) [S1].
5.  **Loss Calculation:** Compute $\mathcal{L}_{\text{RGB}}$ and $\mathcal{L}_{\text{sparse}}$. For scenes without background, add transparency loss [S1].

**Pseudocode:**

```python
import math
import numpy as np

def frequency_modulated_encoding(p, L):
    """
    Computes the frequency-modulated position encoding for input p.
    
    Args:
        p (np.ndarray): Input coordinate or direction vector of shape (3,) or (2,).
        L (int): Number of frequency bands.
        
    Returns:
        np.ndarray: Encoded vector of shape (2 * L * len(p)).
    """
    # Initialize output array
    # The formula applies sin/cos to each component of p scaled by 2^(k/2)
    # We iterate k from 0 to L-1
    encoded_parts = []
    
    for k in range(L):
        # Calculate frequency multiplier: 2^(k/2)
        freq = math.pow(2, k / 2.0)
        
        # Scale input by pi and frequency
        scaled_p = p * freq * math.pi
        
        # Compute sine and cosine for each component
        # If p is (3,), this produces 3 sin and 3 cos values
        sin_vals = np.sin(scaled_p)
        cos_vals = np.cos(scaled_p)
        
        # Append to list
        encoded_parts.append(sin_vals)
        encoded_parts.append(cos_vals)
        
    # Concatenate all parts
    # Result shape: (2 * L * input_dim)
    return np.concatenate(encoded_parts)

def compute_loss(predicted_color, gt_color, alphas, lambda_sparse):
    """
    Computes the total loss including RGB and sparse regularization.
    
    Args:
        predicted_color (np.ndarray): Predicted color C_hat.
        gt_color (np.ndarray): Ground truth color C_gt.
        alphas (np.ndarray): Opacity values alpha_i for N points.
        lambda_sparse (float): Weight for sparse loss.
        
    Returns:
        float: Total loss value.
    """
    # L_RGB = ||C_hat - C_gt||_2^2
    l_rgb = np.mean(np.square(predicted_color - gt_color))
    
    # L_sparse = (1/N) * sum(log(alpha_i) + log(1 - alpha_i))
    # Note: Ensure alphas are within (0, 1) to avoid log(0)
    # [G] Add small epsilon to prevent numerical instability in log
    epsilon = 1e-7
    safe_alphas = np.clip(alphas, epsilon, 1 - epsilon)
    
    sparse_term = np.log(safe_alphas) + np.log(1 - safe_alphas)
    l_sparse = np.mean(sparse_term)
    
    total_loss = l_rgb + lambda_sparse * l_sparse
    return total_loss
```

**Edge Cases and Pitfalls:**
*   **Bleeding:** If the rasterization radius is too small, points from occluded surfaces and background can be seen through the front surface [S1].
*   **Edge Expansion:** If the rasterization radius is too large, it leads to inaccurate depth estimation and object edges expand [S1].
*   **Precision:** The use of $2^{0.5}$ exponents requires careful handling of floating-point precision for high $L$ values, though $L=10$ is standard [S1].

## Operating characteristics
*   **Time Complexity:** One epoch consumes approximately 12.8 seconds on NeRF-Synthetic [S1]. Realistic rendering is achieved in 10 minutes, but almost convergence takes about 10 hours [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Achieves higher PSNR/SSIM on NeRF-Synthetic and Tanks and Temples datasets compared to NeRF, CCNeRF, NPBG, NPBG++, and Huang et al. Comparable or better results on ScanNet and DTU [S1].
*   **Strengths:** Fast convergence for realistic rendering; effective for point cloud rendering with editing capabilities [S1].
*   **Limitations:** Requires initial point clouds (e.g., from MVSNet); sensitive to rasterization radius selection (though ablation shows effect is not significant) [S1].
*   **When to use:** When working with point-based radiance fields and requiring easy editing capabilities, especially on synthetic and real-world datasets like NeRF-Synthetic, Tanks and Temples, ScanNet, and DTU [S1].
*   **When not to use:** When continuous volume rendering is preferred over point-based rendering, or when computational resources are extremely limited and sub-10-minute convergence is not required [S1].

## Background
The method was introduced in the paper "Frequency-Modulated Point Cloud Rendering with Easy Editing" [S1]. It builds on the position encoding form of NeRF [S1] but narrows the encoding interval to provide more fine-grained basis function support for frequency modulation. It is used in the context of point-based rendering (PBR) and inverse graphics, specifically for tasks involving point cloud denoising, completion, and editing [S1].
