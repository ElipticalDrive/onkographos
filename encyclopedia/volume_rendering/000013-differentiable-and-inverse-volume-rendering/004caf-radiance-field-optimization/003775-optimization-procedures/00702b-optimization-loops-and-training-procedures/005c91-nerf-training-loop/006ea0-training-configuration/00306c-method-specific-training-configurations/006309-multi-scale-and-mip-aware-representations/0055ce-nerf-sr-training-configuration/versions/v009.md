# NeRF-SR Training Configuration

## Overview
NeRF-SR is a training configuration designed to synthesize high-resolution (HR) novel views from low-resolution (LR) inputs by exploiting 3D consistency through a supersampling strategy [S1]. It differs from standard NeRF training by optimizing the neural radiance field directly at higher resolutions during the training loop, rather than upsampling the final rendered image [S1]. This approach addresses the limitation where standard NeRF trained on LR data produces blurry HR outputs, while post-processing upsampling methods (like bicubic) fail to recover high-frequency details [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ LR images $\{I_n\}$ with known camera poses and intrinsics.
*   **Output:** A trained neural radiance field (MLP) capable of rendering HR images, and optionally, a refinement network for real-world scenes.

**Data Structures:**
*   **Neural Radiance Field (MLP):** Takes 3D position $\mathbf{x}$ and viewing direction $\mathbf{d}$ as input. Outputs volume density $\sigma$ and view-dependent color $\mathbf{c}$. The architecture mirrors the standard NeRF "coarse" and "fine" MLPs [S1].
*   **Reference Patches (for Refinement):** A set of $K$ reference image patches $\{P^{REF}_k\}_{k=1}^K$ extracted from a reference image $I_{REF}$ [S1].

**Numbered Steps:**
1.  **Hierarchical Sampling:** For each ray $\mathbf{r}$, sample $N_c = 64$ points using the coarse MLP to estimate density. Then, sample $N_f = 64$ points using importance sampling based on the coarse density estimates to focus on high-density regions [S1].
2.  **Differentiable Volume Rendering:** Compute the rendered color $\hat{C}(\mathbf{r})$ using the standard volume rendering integral:
    $$ \hat{C}(\mathbf{r}) = \sum_{i=1}^{N_f} T_i \alpha_i \mathbf{c}_i $$
    where $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$, $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$, and $\delta_i$ is the distance between samples [Parent][S1].
3.  **Loss Calculation:** Minimize the photometric loss between the rendered HR image and the ground truth HR image (if available for supervision) or use the LR image with a supersampling constraint. The primary loss is Mean Squared Error (MSE) or Charbonnier loss [Parent][S1].
4.  **Optimization:** Update the MLP weights using the Adam optimizer [S1].
5.  **Inference (Optional Refinement):** For real-world datasets (e.g., LLFF), divide the input image into non-overlapping patches. For each patch, extract $K$ reference patches from $I_{REF}$ using depth and camera parameters to boost texture details [S1]. Stitch the refined patches together [S1].

**Formulas:**
*   **Patch Extraction for Refinement:** To obtain a reference patch $P^{REF}_{i,j}$ for a pixel location $(i,j)$ on the input patch $P$:
    $$ P^{REF}_{i,j} = K_{REF} T (K_n^{-1} d_{i,j} P_{i,j}) $$
    where $d_{i,j}$ is the estimated depth, $T$ is the transformation between camera extrinsic matrices from $I_n$ to $I_{REF}$, and $K_{REF}$ and $K_n$ are the camera intrinsic matrices [S1]. Points falling outside $I_{REF}$ are discarded [S1].

**Parameters:**
*   **Optimizer:** Adam with $\beta_1 = 0.9$, $\beta_2 = 0.999$ [S1].
*   **Batch Size:** 2048 rays per batch [S1].
*   **Learning Rate:** Exponentially decayed from $5 \cdot 10^{-4}$ to $5 \cdot 10^{-6}$ [S1].
*   **Samples:** 64 coarse samples, 64 fine samples [S1].
*   **Epochs:** 20 epochs for Blender dataset, 30 epochs for LLFF dataset [S1].
*   **Refinement Parameters:** $K=8$ reference patches, patch dimensions $64 \times 64$ [S1].

**Edge Cases and Pitfalls:**
*   **Arbitrary Scale:** NeRF-SR does not support arbitrary-scale super-resolution; it is trained for specific scale factors (e.g., $\times 2, \times 4$) [S1].
*   **Real-world Complexity:** Supersampling alone is insufficient for complex real-world scenes (LLFF); a refinement network is required to recover high-frequency details [S1].
*   **Inference Time:** Refinement adds negligible time (~1.3s) compared to volumetric rendering (~48s for 1008x756 on 1080Ti) [S1].

## Subtopics

### Refinement Network (Ours-Refine)
A post-processing step that boosts NeRF-SR outputs with texture details and edge sharpness, specifically for real-world LLFF datasets where supersampling alone is insufficient [S1]. It uses a fixed number of $K=8$ reference patches of size $64 \times 64$ [S1]. During inference, input images are divided into non-overlapping patches, refined using the reference patches, and stitched together [S1]. It is necessary for scale $\times 4$ where supersampling derives fewer details, but provides only subtle LPIPS improvements for scale $\times 2$ where PSNR is already decent [S1].

## Operating characteristics
*   **Time Complexity:** Training time is comparable to training a standard HR NeRF [S1]. Inference time for volumetric rendering is dominant (~48s for 1008x756 on 1080Ti); refinement adds ~1.3s [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** On LLFF dataset (scale $\times 4$), Ours-Refine achieves PSNR 25.59, SSIM 0.759, LPIPS 0.165 [S1]. On LLFF dataset (scale $\times 2$), Ours-Refine achieves PSNR 27.34, SSIM 0.842, LPIPS 0.103 [S1].
*   **Strengths:** Recovers high-frequency details better than bicubic upsampling or standard NeRF [S1].
*   **Limitations:** Lacks arbitrary-scale support; requires specific training for each scale factor [S1].

## Background
NeRF-SR was introduced by Wang et al. in the paper "NeRF-SR: High-Quality Neural Radiance Fields using Supersampling" [S1]. It is the first pipeline to achieve high-resolution novel view synthesis from mostly low-resolution inputs without external data, by exploiting 3D consistency through supersampling [S1].
