# UE4-NeRF

Also called: UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene

## Overview
UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale 3D scenes by partitioning the environment into sub-NeRFs represented as textured polygonal meshes and integrating them into the Unreal Engine 4 (UE4) rasterization pipeline [S1]. Unlike standard differentiable volume rendering methods that rely on ray-marching through voxel grids, UE4-NeRF converts the learned radiance field into a mesh-based representation optimized for GPU rasterization, enabling real-time frame rates at 4K resolution [S1]. It distinguishes itself from sibling methods like [Mobile-NeRF](13622-mobile-nerf.md) and [Mega-NeRF](14098-mega-nerf.md) by utilizing regular octahedra for mesh initialization to handle tilted surfaces and employing multi-resolution hash encoding for accelerated training, while avoiding the opacity binarization limitations of Mobile-NeRF [S1].

## How it works
UE4-NeRF operates in three main phases: block partitioning and coarse segmentation, mesh-based training with vertex optimization, and LOD-based extraction for rasterization in UE4. The method maps 3D points and viewing directions to color and opacity using an Encoder-Decoder network, but instead of volumetric sampling, it uses the network outputs to texture polygonal meshes.

### Inputs and Outputs
*   **Inputs:** A set of posed images (e.g., from drone capture) with GPS metadata; camera poses; scene bounding box.
*   **Outputs:** Textured polygonal meshes at multiple Levels of Detail (LOD); a neural shader (HLSL fragment shader) deployed in UE4; final real-time rendered frames.

### Data Structures and Layouts

**1. Scene Partitioning**
The large scene is divided into $N$ blocks. Each block's training area is slightly larger than the target scene area to create overlapping borders for smooth transitions [S1].

**2. Mesh Initialization**
*   **Grid:** A $128 \times 128 \times 128$ grid is initialized for each block [S1].
*   **Vertices:** For each grid cell, the center point and its six neighbors (front, back, left, right, top, bottom) are selected to form polygonal faces [S1].
*   **Topology:** Regular octahedra are used, consisting of 20 faces total (8 exterior, 12 interior) [S1]. This topology replaces the Mobile-NeRF approach to ensure stable convergence on tilted surfaces [S1].
*   **Vertex Optimization:** Vertex positions are continuously optimized during training [S1].

**3. Neural Network Architecture**
The method uses an Encoder-Decoder MLP structure, implemented as a CUDA kernel during training and an HLSL shader during rendering [S1].

*   **Encoder Network ($E$):**
    *   **Input:** Positional information $\mathbf{p}_i$ encoded via multi-resolution hash encoding (from Instant-NGP) [S1].
    *   **Architecture:** 4-layer MLP.
    *   **Dimensions:** $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
    *   **Output:** Opacity $\alpha_i$ and an 8-dimensional feature vector $\mathbf{M}_i$ [S1].
    *   **Formula:**
        $$ \mathbf{M}_i, \alpha_i = E(\text{hash}(\mathbf{p}_i); \theta_E) $$

*   **Decoder Network ($D$):**
    *   **Input:** Feature vector $\mathbf{M}_i$ and spherical harmonic coefficients $\text{SH}(\mathbf{d}_i)$ derived from viewing direction $\mathbf{d}_i$ [S1].
    *   **Architecture:** 3-layer MLP.
    *   **Dimensions:** $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1]. (Note: The input dimension 17 combines the 8 feature dimensions with 9 spherical harmonic coefficients for the zeroth and first orders, or similar basis, though the source specifies 17 explicitly) [S1].
    *   **Output:** Final RGB color $\mathbf{c}_i$ [S1].
    *   **Formula:**
        $$ \mathbf{c}_i = D(\mathbf{M}_i, \text{SH}(\mathbf{d}_i); \theta_D) $$

**4. Texture Atlas**
*   Stores feature vectors and opacity information for the mesh vertices/faces [S1].
*   Unlike Mobile-NeRF, which binarizes opacity, UE4-NeRF stores continuous opacity values to handle semi-transparent objects (water, glass, vegetation) [S1].

**5. Level of Detail (LOD) Hierarchy**
*   Multiple mesh resolutions are trained for different observation heights [S1].
*   Coarser meshes are used for higher observation heights to maintain real-time performance [S1].
*   Pre-rendered meshes are extracted for the final rendering module [S1].

### Numbered Steps

1.  **Coordinate Transformation:** Transform GPS-captured drone imagery coordinates to the UE4 coordinate system (X: East, Y: South, Z: Up) with a 100:1 scale conversion (UE4 units to real-world units) [S1].
2.  **Block Partitioning:** Partition the large-scale scene into multiple blocks. Train a coarse model for sub-region segmentation to capture overall terrain and building outlines. Filter images associated with sub-regions and use a mask to exclude pixels outside the scene area [S1].
3.  **Mesh Initialization:** Initialize a $128 \times 128 \times 128$ grid. Select center points and six neighbors to create polygonal meshes based on regular octahedra (20 faces) [S1].
4.  **Training Loop:**
    a. For each ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$, calculate intersection with the polygonal meshes to determine sampling points [S1].
    b. Encode position $\mathbf{p}_i$ using multi-resolution hash encoding [S1].
    c. Pass encoded position through Encoder MLP to get feature vector $\mathbf{M}_i$ and opacity $\alpha_i$ [S1].
    d. Encode viewing direction $\mathbf{d}_i$ using spherical harmonics [S1].
    e. Pass $\mathbf{M}_i$ and $\text{SH}(\mathbf{d}_i)$ through Decoder MLP to get color $\mathbf{c}_i$ [S1].
    f. Compute loss (PSNR/SSIM/LPIPS) against ground truth images [S1].
    g. Update network parameters $\theta_E, \theta_D$ and optimize vertex positions [S1].
    h. Repeat for 80,000 epochs per block [S1].
5.  **Mesh Extraction:** Extract pre-rendered polygonal meshes at different levels of detail. The meshes are extracted without textures during training, but the network outputs encode the texture maps [S1].
6.  **Rendering in UE4:**
    a. Import the extracted meshes into UE4 [S1].
    b. Deploy the neural shader (HLSL fragment shader) which takes feature vectors as input and outputs colors [S1].
    c. Use the LOD hierarchy to select the appropriate mesh resolution based on camera height [S1].
    d. Render using UE4's rasterization pipeline [S1].
7.  **Scene Editing (Optional):** Import traditional 3D models (.obj, .fbx). UE4 handles occlusion automatically, skipping neural shader computation for occluded regions [S1].

### Pseudocode

```python
# UE4-NeRF Training and Rendering Logic
# Note: This pseudocode abstracts the CUDA/HLSL implementation details 
# into standard Python-like logic for clarity.

def ue4_nerf_pipeline(images, poses, scene_bounds):
    """
    Main pipeline for UE4-NeRF.
    """
    # 1. Coordinate Transformation
    # Transform GPS coordinates to UE4 system: X=East, Y=South, Z=Up, Scale=100:1
    transformed_images = transform_coordinates(images, scale_factor=100.0, 
                                             x_axis='east', y_axis='south', z_axis='up')
    
    # 2. Block Partitioning
    blocks = partition_scene(scene_bounds, overlap=True)
    trained_blocks = []
    
    for block in blocks:
        # Filter images for this block and mask out-of-bounds pixels
        block_images = filter_images(transformed_images, block.mask)
        
        # 3. Mesh Initialization
        # Initialize 128x128x128 grid
        grid = initialize_grid(size=128)
        # Create octahedron meshes (20 faces: 8 exterior, 12 interior)
        # Vertices are optimized during training
        mesh = create_octahedron_mesh(grid)
        
        # 4. Network Initialization
        # Encoder: 4-layer MLP (32->64->64->64->8)
        encoder = MLP(layers=[32, 64, 64, 64, 8])
        # Decoder: 3-layer MLP (17->16->16->3)
        # Input dim 17 = 8 features + 9 SH coefficients
        decoder = MLP(layers=[17, 16, 16, 3])
        
        # 5. Training
        # Train for 80,000 epochs on 1x RTX 3090
        for epoch in range(80000):
            for image, pose in zip(block_images, poses):
                # Ray generation
                rays = generate_rays(pose, image.resolution)
                
                # Intersection with mesh to get sampling points
                # This replaces volumetric sampling
                intersections = ray_mesh_intersection(rays, mesh.vertices, mesh.faces)
                
                # Forward Pass
                colors = []
                for point, ray in zip(intersections.points, rays):
                    # Encode position with multi-resolution hash
                    hash_features = hash_encoding(point.position)
                    
                    # Encoder: Position -> Feature Vector + Opacity
                    feature_vec, opacity = encoder(hash_features)
                    
                    # Encode viewing direction with Spherical Harmonics
                    # Assuming 3rd order SH (9 coefficients) + 8 features = 17 input
                    sh_coeffs = spherical_harmonics(ray.direction, order=3)
                    input_vec = concatenate(feature_vec, sh_coeffs)
                    
                    # Decoder: Feature + Direction -> Color
                    color = decoder(input_vec)
                    colors.append(color)
                
                # Loss Calculation
                loss = compute_loss(colors, image.rgb)
                
                # Backpropagation
                # Update encoder/decoder weights AND mesh vertex positions
                update_parameters(encoder, decoder, mesh.vertices, loss)
        
        # 6. LOD Extraction
        # Extract meshes at varying levels of detail
        lod_meshes = extract_lod_meshes(mesh, encoder, decoder)
        trained_blocks.append(lod_meshes)
        
    return trained_blocks

def render_ue4(lod_meshes, camera_pose, camera_height):
    """
    Real-time rendering in Unreal Engine 4.
    """
    # Select LOD based on camera height
    # Higher height -> Coarser mesh
    mesh = select_lod(lod_meshes, camera_height)
    
    # Deploy neural shader (HLSL fragment shader)
    # The shader takes feature vectors from the mesh texture atlas
    # and outputs colors
    frame = rasterize_with_neural_shader(mesh, camera_pose)
    
    return frame
```

### Parameters and Typical Values
*   **Grid Size:** $128 \times 128 \times 128$ [S1].
*   **Octahedron Faces:** 20 total (8 exterior, 12 interior) [S1].
*   **Encoder MLP:** 4 layers, dimensions $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
*   **Decoder MLP:** 3 layers, dimensions $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
*   **Training Hardware:** 1 Nvidia RTX 3090 GPU [S1].
*   **Training Iterations:** 80,000 epochs per block [S1].
*   **Training Time:** ~40 minutes per block on 1x RTX 3090 [S1].
*   **Coordinate System:** X: East, Y: South, Z: Up [S1].
*   **World Scale:** 100:1 (UE4 units to real-world units) [S1].
*   **Evaluation Metrics:** PSNR, SSIM, LPIPS [S1].

### Edge Cases and Pitfalls
*   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces. UE4-NeRF mitigates this by using regular octahedra instead of the Mobile-NeRF mesh structure [S1].
*   **Transparency:** Mobile-NeRF cannot handle transparent/semi-transparent objects (water, glass, plastic) due to opacity binarization. UE4-NeRF stores opacity in texture maps, allowing it to handle these materials, though semi-transparent objects (e.g., vegetation) increase computational overhead and reduce frame rates [S1].
*   **Pre-rendering Gaps:** Pre-rendering cannot capture rays from all viewing angles, potentially resulting in gaps or holes in the final rendered scene [S1].
*   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, causing evaluation metrics (PSNR/SSIM) to underestimate actual reconstruction quality [S1].
*   **Memory Overhead:** Rendering large scenes (square kilometers) incurs significant memory overhead. Increasing accuracy further amplifies memory consumption [S1].
*   **Hardware Dependency:** Requires CUDA and NVIDIA GPUs [S1].

## Subtopics

### Block Partitioning
Divides large scenes into manageable sub-NeRFs with overlapping borders for smooth transitions. Chosen for scalability in large-scale environments. See [Block-NeRF](13622-block-nerf.md) for related grid-based partitioning.

### Octahedron Mesh Initialization
Uses regular octahedra (20 faces) to represent scene geometry, optimizing vertex positions during training. Chosen to handle tilted surfaces better than Mobile-NeRF's approach.

### LOD (Level of Detail) Hierarchy
Trains meshes with varying levels of detail for different observation heights. Chosen to ensure real-time performance across different viewing distances.

## Operating characteristics
*   **Training Speed:** 1000× faster than Mobile-NeRF [S1].
    *   Per block: 40 minutes on 1× RTX 3090 [S1].
    *   Full scene: 1 hour + (40 minutes × $n$/4) on 1× RTX 3090, where $n$ is the number of blocks [S1].
    *   Comparison: Mobile-NeRF takes 48h/block on 4×3090; Mega-NeRF takes 36h/block on 1×3090 [S1].
*   **Rendering Performance:**
    *   Real-time rendering at 4K resolution with up to 43 FPS on level-1 mesh hierarchy [S1].
    *   50 FPS on full scene at 2K resolution [S1].
    *   ≥70 FPS on individual blocks at 2K resolution [S1].
*   **Memory:** Significant memory overhead for large scenes (square kilometers). Memory consumption increases with accuracy [S1].
*   **Strengths:** Real-time interactive rendering of large-scale scenes; handles semi-transparent objects; supports scene editing with traditional 3D models; high fidelity on small objects and dense textures compared to Mip-NeRF and Mega-NeRF [S1].
*   **Limitations:** Requires NVIDIA GPUs/CUDA; pre-rendering can cause gaps/holes; exposure matching issues in UE4 affect metric evaluation; semi-transparent objects reduce frame rates [S1].
*   **When to Use:** Large-scale outdoor scenes (farmland, construction sites, industrial parks) requiring real-time interaction and high resolution.
*   **When Not to Use:** Small-scale scenes where standard NeRF is sufficient; scenes requiring precise metric evaluation without exposure correction; environments without NVIDIA hardware.

## Background
UE4-NeRF was introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" [S1]. It addresses the limitations of NeRF in real-time rendering and large-scale scene handling. It builds on [Mobile-NeRF](13622-mobile-nerf.md) by replacing its mesh structure with octahedra and using multi-resolution hash encoding from [Instant-NGP](13622-mobile-nerf.md) for acceleration. It differs from [Block-NeRF](13622-block-nerf.md) by not being limited to grid structures and supporting various scene types like mountainous terrain. It is used in Unreal Engine 4 for drone-captured large-scale scenes and evaluated on the Mega-NeRF public dataset [S1].
