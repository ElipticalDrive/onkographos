# Dynamic Appearance Particle Neural Radiance Field

Also called: Dynamic Appearance Particle NeRF, Lagrangian dynamic model in NeRF

## Overview
Dynamic Appearance Particle Neural Radiance Field is a method for modeling dynamic scenes from monocular video data by superimposing a static grid-based radiance field with a particle-based dynamic field [S1]. It solves the problem of capturing continuous scene dynamics without requiring prior geometric knowledge or multi-view stereo setups, distinguishing itself from ParticleNeRF by applying particles only to dynamic elements and using efficient linear interpolation instead of radius nearest neighbor searching [S1].

## How it works
The method models the scene as a dynamic radiance field $V(x, t)$ that outputs volume density $\sigma$ and emitted radiance $\mathbf{c}$ for a given 3D position $x$, viewing direction $d$, and time $t$ [S1].

**Inputs and Outputs**
*   **Inputs:** Monocular video data (one camera view per time frame), camera poses, and intrinsics.
*   **Outputs:** Rendered pixel color $C(r, t)$ for a ray $r$ at time $t$.

**Data Structures**
1.  **Static Field ($V_s$):** A time-independent grid-based model (e.g., hash grid or dense voxel grid) storing features for static scene components [S1].
2.  **Dynamic Field ($V_{td}$):** A particle-based representation where each particle carries appearance features and motion parameters [S1].
3.  **Weight Field ($w_t$):** A binary or soft mask indicating the effectiveness of the dynamic field at position $x$ and time $t$ [S1].

**Formulas**
The total feature field is a superposition of static and dynamic components [S1]:
$$ V(x, t) = (1 - w_t(x))V_s(x) + w_t(x)V_{td}(x) $$
where $w_t(x) = 1$ if the dynamic field is effective at $(x, t)$, and $0$ otherwise [S1]. The support of $V_{td}$ is defined by the particle positions.

The dynamic field $V_{td}$ is formulated as a convolution with a Dirac delta function to integrate over finite volumes [S1]:
$$ V_{td}(x) = (V_{td} * \delta)(x) = \int V_{td}(x')\delta(x - x')d\nu(x') $$
where $\delta(\cdot)$ is the Dirac function ($\delta(r)=0$ for $r \neq 0$, $\int \delta(r)d\nu = 1$) and $\nu$ is the volume integration variable [S1].

For implementation, the Dirac function is replaced by a kernel $W$ with finite support to quantize the field [S1]:
$$ W(x) = 0 \text{ when } \|x\| \text{ exceeds a small radius}, \quad \int W(x)d\nu(x) = 1 $$
This kernel approximation allows for efficient querying via linear interpolation [S1].

**Rendering**
Pixel color is computed by standard volume rendering integration along the ray [S1]:
$$ C(r, t) = \int_{s_n}^{s_f} T(s)\sigma(r(s), t)\mathbf{c}(r(s), d, t) ds $$
where $r(s) = o + sd$ is the ray equation, $s_n, s_f$ are near/far bounds, and $T(s) = \exp\left(-\int_{s_n}^s \sigma(r(s'), t) ds'\right)$ is the accumulated transmittance [S1].

**Pseudocode**
The following pseudocode outlines the training and inference logic. Note that specific MLP architectures for $V_s$ and particle motion are assumed to be standard NeRF MLPs or grid decoders, while the particle motion network updates particle states.

```python
import numpy as np

class DynamicAppearanceParticleNeRF:
    def __init__(self, static_grid, particles, kernel_radius):
        """
        Initialize the model.
        :param static_grid: Grid-based structure for V_s(x)
        :param particles: List of particle objects, each with position, velocity, and appearance features
        :param kernel_radius: Radius for the finite support kernel W
        """
        self.static_grid = static_grid
        self.particles = particles
        self.kernel_radius = kernel_radius
        # w_t(x) is implicitly defined by particle proximity in this implementation
        # In practice, this might be a separate network or computed on-the-fly

    def query_dynamic_field(self, x, t):
        """
        Query the dynamic field V_td(x) at position x and time t.
        Uses kernel-weighted interpolation of particle features.
        """
        dynamic_value = 0.0
        total_weight = 0.0
        
        for particle in self.particles:
            # Predict particle position at time t based on motion model
            # This requires a motion network or physics simulation step
            particle_pos_t = particle.predict_position(t)
            
            dist = np.linalg.norm(x - particle_pos_t)
            
            if dist <= self.kernel_radius:
                # Compute kernel weight W(dist)
                # W(x) = 0 when ||x|| > radius, integral = 1
                # Example: Truncated Gaussian or Epanechnikov kernel
                w = self.compute_kernel_weight(dist, self.kernel_radius)
                
                # Interpolate particle features
                # Features might be stored in a small MLP or directly
                feat = particle.get_features()
                
                dynamic_value += w * feat
                total_weight += w
        
        if total_weight > 0:
            return dynamic_value / total_weight
        else:
            return 0.0 # No dynamic influence

    def compute_weight_mask(self, x, t):
        """
        Compute w_t(x). Returns 1 if dynamic field is effective, 0 otherwise.
        """
        # Check if any particle influences x
        for particle in self.particles:
            particle_pos_t = particle.predict_position(t)
            dist = np.linalg.norm(x - particle_pos_t)
            if dist <= self.kernel_radius:
                return 1.0
        return 0.0

    def render(self, ray_o, ray_d, t, num_samples):
        """
        Render a single pixel for a ray at time t.
        """
        # Sample points along the ray
        s = np.linspace(ray_o.near, ray_o.far, num_samples)
        points = ray_o + ray_d * s[:, np.newaxis]
        
        sigma_accum = 0.0
        color_accum = np.zeros(3)
        
        for i, x in enumerate(points):
            # Query static field
            v_s = self.static_grid.query(x)
            sigma_s, c_s = self.decode_static(v_s)
            
            # Query dynamic field
            w_t = self.compute_weight_mask(x, t)
            if w_t > 0:
                v_td = self.query_dynamic_field(x, t)
                sigma_td, c_td = self.decode_dynamic(v_td)
            else:
                sigma_td, c_td = 0.0, np.zeros(3)
            
            # Superposition
            sigma = (1 - w_t) * sigma_s + w_t * sigma_td
            color = (1 - w_t) * c_s + w_t * c_td
            
            # Volume rendering accumulation
            alpha = 1.0 - np.exp(-sigma * (s[i+1] - s[i])) # Approximation for segment length
            transmittance = np.exp(-sigma_accum)
            
            color_accum += transmittance * alpha * color
            sigma_accum += sigma * (s[i+1] - s[i])
            
        return color_accum

    def train_step(self, batch):
        """
        One training step.
        """
        # 1. Update particle positions/velocities using motion network
        for particle in self.particles:
            particle.update_motion(batch.time)
            
        # 2. Render images for all time steps in batch
        rendered_images = []
        for t in batch.times:
            for ray in batch.rays:
                rendered_images.append(self.render(ray.o, ray.d, t, ray.samples))
                
        # 3. Compute loss against ground truth
        loss = self.compute_loss(rendered_images, batch.gt_images)
        
        # 4. Backpropagate to update static grid, dynamic decoder, and motion network
        loss.backward()
        self.optimizer.step()
```

**Edge Cases and Pitfalls**
*   **Particle Density:** If particles are too sparse, the dynamic field may have holes. If too dense, querying becomes slow [S1].
*   **Kernel Support:** The choice of kernel radius affects the smoothness of the dynamic field. A radius that is too small leads to aliasing; too large causes blurring [S1].
*   **Monocular Ambiguity:** Without multi-view constraints, disambiguating dynamic vs. static components can be challenging, relying heavily on the temporal consistency enforced by the particle motion network [S1].

## Operating characteristics
*   **Time Complexity:** Querying the static field is $O(1)$ with hash grids or $O(\log N)$ with trees. Querying the dynamic field is $O(K)$ where $K$ is the number of particles within the kernel radius. Rendering is $O(R \cdot S \cdot K)$ where $R$ is rays and $S$ is samples per ray.
*   **Memory Complexity:** $O(G)$ for the static grid and $O(P \cdot F)$ for $P$ particles with feature dimension $F$ [S1].
*   **Performance:** Designed for efficiency compared to full particle-based NeRFs by using grid-based interpolation for static parts and limiting particles to dynamic elements [S1].
*   **Strengths:** Handles monocular video; no prior geometry needed; efficient querying via linear interpolation [S1].
*   **Limitations:** Relies on the accuracy of the particle motion model; may struggle with highly complex, non-rigid deformations not captured by the motion network [S1].
*   **When to use:** Monocular dynamic scene reconstruction where multi-view data is unavailable [S1].
*   **When not to use:** Scenes with extensive static background and sparse dynamic objects might be better served by simpler background subtraction or static NeRFs [S1].

## Background
The method was proposed in "Dynamic Appearance Particle Neural Radiance Field" [S1]. It builds upon the concept of Lagrangian dynamic models, integrating particle-based representations into the NeRF framework. It addresses limitations of ParticleNeRF, which requires multi-view data and encodes the entire scene with particles [S1]. The approach is not tightly coupled to a specific architecture and can be integrated into frameworks like InstantNGP [S1].
