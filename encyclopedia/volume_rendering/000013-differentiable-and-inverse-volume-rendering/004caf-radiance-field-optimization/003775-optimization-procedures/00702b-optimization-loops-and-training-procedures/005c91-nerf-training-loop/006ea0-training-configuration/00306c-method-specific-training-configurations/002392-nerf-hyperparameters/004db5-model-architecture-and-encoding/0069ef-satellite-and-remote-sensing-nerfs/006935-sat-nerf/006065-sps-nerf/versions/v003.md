# SpS-NeRF

Also called: SparseSat-NeRF

## Overview
SpS-NeRF is a NeRF variant adapted for sparse single-date satellite images that employs dense depth supervision guided by a cross-correlation similarity metric from traditional semi-global MVS (SGM) matching [S1]. It extends Sat-NeRF to handle novel view generation and 3D geometry reconstruction from sparse satellite views by jointly optimizing RGB and depth losses, using uncertainty metrics from SGM correlation maps to robustify the supervision [S1]. Unlike learning-based depth completion methods used in indoor scenes, SpS-NeRF leverages traditional SGM, which is sufficient for satellite scenarios and avoids the need for ground truth depth maps for training [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ sparse satellite images with known camera poses (RPC functions as per Sat-NeRF), and corresponding dense depth maps computed via Semi-Global Matching (SGM) on downsampled images (factor 4) [S1]. The input depth maps are incomplete (due to occlusions) and imprecise (4x larger Ground Sample Distance) [S1].
*   **Outputs:** A neural radiance field model capable of rendering novel views and a refined Digital Surface Model (DSM) [S1].

**Data Structures:**
*   **Neural Network:** A fully-connected (non-convolutional) deep network $F_\Theta$ defining the continuous volumetric representation, identical to Sat-NeRF but omitting modules for transient objects and solar correction modeling, as the method targets synchronous acquisitions [S1].
*   **SGM Correlation Maps:** Used to derive an uncertainty metric $corr(r)$ for each ray $r$ [S1].

**Numbered Steps:**

1.  **Ray Sampling:** For each pixel in the target view, cast a ray $r$ through the scene. Use guided ray sampling borrowed from Roessle et al. (2022) [S1]. The sampling is influenced by the uncertainty metric $corr(r)$ [S1].
2.  **Query Points:** Sample $N$ query points $x_i$ along the ray $r$ through the 3D field [S1].
3.  **Network Forward Pass:** Query the network $F_\Theta$ at each $x_i$ to obtain density $\sigma_i$ and color $c_i$ [S1].
4.  **Volume Rendering (RGB):** Compute the accumulated color $C(r)$ for the ray using standard volume rendering integration [S1]:
    $$
    C(r) = \sum_{i=1}^{N} T_i \alpha_i c_i
    $$
    where:
    *   $\alpha_i = 1 - e^{-\sigma_i \delta_i}$ is the opacity of the current query point $x_i$,
    *   $\delta_i = t_{i+1} - t_i$ is the distance between adjacent query points,
    *   $T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)$ is the probability that the ray reaches $x_i$ without being blocked [S1].
5.  **Uncertainty Metric Calculation:** Compute the uncertainty metric $corr(r)$ based on the SGM cross-correlation maps [S1]. This metric is applied three times during optimization:
    *   (i) As a weight applied to the final depth loss [S1].
    *   (ii) As a threshold to determine whether the depth loss should be activated [S1].
    *   (iii) In guided ray sampling [S1].
    *   *Note:* The exact formula for $corr(r)$ is referenced as Equation (5) in the source but is not explicitly provided in the text snippets. The source states that for the ablation variant "SpS-NeRF \Corr", $corr(r)=1$ for every pixel [S1].
6.  **Depth Supervision:** Compute a depth loss similar to DDPNeRF [S1]. The loss encourages the network to estimate the depth within a margin $m$ of the input depth, weighted by $corr(r)$ [S1]. The exact loss formulation is referenced as Equation (6) in the source but is not explicitly provided in the text snippets.
7.  **Joint Optimization:** Optimize the network parameters $\Theta$ by minimizing a combined loss of RGB rendering error and the weighted depth loss [S1].

**Pseudocode:**

```python
# SpS-NeRF Training Step
# Inputs:
#   images: List of satellite images with poses
#   depths: List of dense depth maps from SGM (downsampled by factor 4)
#   corr_maps: List of SGM cross-correlation maps for uncertainty
#   model: Neural radiance field F_Theta (Sat-NeRF architecture without transient/solar modules)
#   optimizer: Optimization algorithm
#   m: Margin for depth loss (from DDPNeRF formulation)

def train_step(images, depths, corr_maps, model, optimizer):
    total_loss = 0
    
    for img, depth_map, corr_map in zip(images, depths, corr_maps):
        # 1. Cast rays for the current image
        rays = cast_rays(img.pose)
        
        # 2. Sample points along rays
        # Uses guided ray sampling influenced by uncertainty (Eq 5/6 context)

        # 3. Query network for sigma and color
        sigma, color = model.query(points)
        
        # 4. Render RGB using volume rendering
        # C(r) = sum(T_i * alpha_i * c_i)
        rendered_color = volume_render(points, sigma, color)
        
        # 5. Compute RGB Loss
        rgb_loss = mse_loss(rendered_color, img.pixel_values)
        
        # 6. Compute Depth Loss with Uncertainty
        # Note: Exact formulas for Eq 5 (corr) and Eq 6 (depth loss) are not provided in text.
        # Implementation relies on the described logic:
        # - corr(r) acts as weight and threshold.
        # - Loss encourages depth within margin m of input depth.
        
        # Extract rendered depth from the volume rendering process
        rendered_depth = compute_rendered_depth(points, sigma, color)
        
        # Calculate uncertainty weight from correlation map
        # corr(r) is derived from corr_map at the ray's pixel location
        uncertainty_weight = get_uncertainty_weight(corr_map, rays)
        
        # Apply thresholding: activate loss only if uncertainty is below threshold
        # (Specific threshold logic from Eq 5 is not detailed in text)
        active_mask = uncertainty_weight < threshold # [G] Placeholder for specific threshold logic
        
        # Calculate depth error within margin m
        depth_error = abs(rendered_depth - depth_map)
        
        # Weighted depth loss
        # Loss is active only where active_mask is true
        depth_loss = sum(active_mask * uncertainty_weight * depth_error) / sum(active_mask)
        
        # 7. Combine losses
        # Jointly optimize RGB and depth losses
        loss = rgb_loss + lambda_depth * depth_loss
        
        total_loss += loss
```

**Parameters:**
*   **SGM Downsampling Factor:** 4 [S1].
*   **Margin $m$:** Used in depth loss formulation (value not specified in sources) [S1].
*   **Loss Weighting:** The balance between RGB and depth loss is implicit in the joint optimization; specific weights are not detailed in the provided text [S1].

**Edge Cases and Pitfalls:**
*   **Flat Surfaces:** SpS-NeRF lacks regularization on flat surfaces, leading to local irregularities, a common problem in NeRFs [S1]. Adding semantic information might be a possible solution [S1].
*   **GT Bias:** In the Djibouti dataset, the Ground Truth DSM was generated with the same SGM as the best performing SGM baseline ($SGM_{scl1}$), potentially biasing the comparison [S1].
*   **SGM Outliers:** SGM is susceptible to outliers, so the GT DSM is likely corrupted with some erroneous depth estimations [S1].
*   **Sparse Depths:** Without dense depths, sparse depths are not enough to complete missing information with 2 or 3 input images [S1].

## Subtopics

### Sat-NeRF
The parent method, an end-to-end model for learning multi-view satellite photogrammetry using native satellite camera models (RPC functions) [20274-sat-nerf.md].

### DDPNeRF
A method that learns a depth completion network from sparse depth maps, using explicit depth loss [S1]. SpS-NeRF borrows the depth supervision concept but replaces the learning-based prediction with SGM.

### Roessle et al. (2022)
The source of the guided ray sampling strategy used in SpS-NeRF [S1].

## Operating characteristics
*   **Time and Memory Complexity:** Not given in the sources.
*   **Measured Performance:**
    *   **DFC2019 (2 views):** PSNR 20.2, SSIM 0.87, MAEin 3.02, MAEout 7.77 [S1].
    *   **DFC2019 (3 views):** PSNR 19.06, SSIM 0.86, MAEin 4.63, MAEout 2.05 [S1].
    *   **Djibouti (2 views):** PSNR 32.85, SSIM 0.92, MAEin 1.57, MAEout 1.15 [S1].
    *   **Djibouti (3 views):** PSNR 36.26, SSIM 0.95, MAEin 1.35, MAEout 0.81 [S1].
*   **Comparison with Baselines:**
    *   Outperforms NeRF and Sat-NeRF in all scenarios [S1].
    *   Better than $SGM_{scl1}$ (full-resolution SGM) in occluded and poorly textured areas (MAEout) [S1].
    *   Worse than $SGM_{scl1}$ in altitude extraction on valid pixels (MAEin) due to lack of regularization [S1].
    *   Better than $SGM_{scl1}$ close to building outlines and free of outliers [S1].
*   **Ablation Results (DFC2019 2 views):**
    *   Dense Sat-NeRF (vanilla Sat-NeRF with dense depths): PSNR 19.39, SSIM 0.86, MAEin 3.58, MAEout 7.91 [S1].
    *   SpS-NeRF \Corr (deactivated uncertainty metric): PSNR 19.67, SSIM 0.86, MAEin 3.21, MAEout 8.03 [S1].
    *   Full SpS-NeRF: PSNR 20.2, SSIM 0.87, MAEin 3.02, MAEout 7.77 [S1].
*   **Strengths:** Robust to shadows and transient objects (inherited from Sat-NeRF context, though transient modeling is omitted in SpS-NeRF for synchronous data), handles sparse views effectively, improves upon traditional SGM in occluded areas.
*   **Limitations:** Lacks regularization on flat surfaces, sensitive to SGM outliers in GT, requires SGM pre-processing.
*   **When to use:** Sparse single-date satellite imagery where traditional MVS fails in occluded/poorly textured areas and learning-based depth prediction is not desired or feasible.
*   **When not to use:** Dense view scenarios, indoor scenes (where learning-based methods like NerfingMVS/DDPNeRF are better), or when high precision on flat surfaces is critical without semantic regularization.

## Background
SpS-NeRF was presented in 2023 by Zhang et al. in the ISPRS Annals of the Photogrammetry, Remote Sensing and Spatial Information Sciences [S1]. It is an extension of Sat-NeRF (Marí et al., 2022) and incorporates concepts from DDPNeRF (Roessle et al., 2022) [S1]. The method was developed to address the challenge of generating convincing scene geometries from sparse satellite views, which is rare in earth observation compared to the many views required by standard NeRF variants [S1]. The research was funded by CNES (Centre national d’études spatiales) and the Djibouti dataset was obtained through the CNES ISIS framework [S1]. Numerical computations were performed on the SCAPAD cluster processing facility at the Institute de Physique du Globe de Paris [S1].
