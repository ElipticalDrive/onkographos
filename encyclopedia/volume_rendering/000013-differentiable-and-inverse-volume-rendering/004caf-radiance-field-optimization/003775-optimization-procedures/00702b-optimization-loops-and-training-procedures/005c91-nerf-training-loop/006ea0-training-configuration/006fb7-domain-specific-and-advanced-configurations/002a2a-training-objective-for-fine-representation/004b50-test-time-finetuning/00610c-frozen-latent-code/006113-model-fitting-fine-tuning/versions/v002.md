# Model Fitting (Fine-tuning)
Also called: Test-Time Finetuning with Optimized Latent Code

## Overview
Model fitting adapts the weights of a pretrained volumetric prior to generate novel views of a target identity at high resolutions from sparse input views [S1]. It solves the problem of geometric distortion and high-frequency overfitting that occurs when training a NeRF model on sparse views by initializing with a pretrained prior and optimizing both model parameters and a per-identity latent code [S1]. Unlike its sibling [Frozen Latent Code](18270-frozen-latent-code.md), which keeps the latent code fixed, this method jointly optimizes the latent code $w_{\text{target}}$ and the model weights $\theta_{\text{target}}$ [S1].

## How it works
**Inputs:**
- Pretrained volumetric prior model weights [S1].
- Target identity latent code $w_{\text{target}}$ obtained through inversion [S1].
- Sparse input views (as few as two) of the target identity [S1].
- Camera poses aligned to a canonical pose via Procrustes analysis on five 3D keypoints (outer eye corners, nose, mouth, chin) [S1].

**Outputs:**
- Finetuned model weights $\theta_{\text{target}}$ and optimized latent code $w_{\text{target}}$ that generate high-resolution novel views with intricate details like individual hair strands [S1].

**Data Structures:**
- The model architecture is identical to the prior model, except for an additional linear layer that maps features from the trunk to 3D normal vectors [S1].
- The rendering volume is bounded by a rectangular box because the model generates faces aligned to a canonical pose [S1]. Density outside this box is set to zero for final rendering [S1].

**Steps:**
1. Initialize the model weights with the pretrained prior model weights [S1].
2. Use the latent code $w_{\text{target}}$ obtained through inversion as the initial latent code [S1].
3. Create training batches by sampling 8,912 rays via random pixel sampling from all available views [S1].
4. Optimize the parameters $\theta_{\text{target}}$ and $w_{\text{target}}$ using the objective function $\mathcal{L}_{\text{fit}}$ until convergence [S1].
5. During rendering, clamp density to zero outside the canonical bounding box [S1].

**Objective Function:**
The optimization minimizes the following loss:
$$
\argmin _{\mathbf {\theta }_{\text {target}}, \mathbf {w}_{\text {target}}} \mathcal {L}_\text {fit} = \mathcal {L}_\text {recon} + \lambda _\text {prop} \mathcal {L}_\text {prop} + \lambda _\text {normal} \mathcal {L}_\text {normal} + \lambda _{v} \mathcal {L}_{v}
$$
where:
- $\mathcal {L}_\text {recon}$ is the reconstruction loss [S1].
- $\mathcal {L}_\text {prop}$ is the propagation loss with hyperparameter $\lambda _\text {prop}$ (identical to Eq. 3 in [S1]) [S1].
- $\mathcal {L}_\text {normal}$ is the normal consistency loss from RefNeRF [59] [S1].
- $\mathcal {L}_{v} = \|\theta_v\|_2^2$, where $\theta_v$ correspond to weights of the connections between the encoded view direction and the output [S1].

**Parameters:**
- $\lambda_{normal} = 0.001$ [S1].
- $\lambda_{v} = 0.0001$ [S1].
- Optimizer: Adam with $\beta_1 = 0.9, \beta_2 = 0.999$ [S1].
- Learning rate schedule: Starts at 0.001 and exponentially decays to 0.00002 [S1].
- Batch size: 8,912 rays per batch [S1].
- Optimization steps depend on target resolution: 25,000 steps for 256×256, 50,000 steps for 512×512, 100,000 steps for 1024×1024, 200,000 steps for 2048×2048, and 300,000 steps for 4096×4096 [S1].
- Hardware: Always optimized on 4 TPUs [S1].

**Pitfalls:**
- Naïve optimization without constraints leads to overfitting to the view direction [S1].
- Regularizing only the view branch weights causes fuzzy surface structures [S1].
- This fuzziness is mitigated by the normal consistency loss $\mathcal {L}_\text {normal}$ [S1].

## Subtopics

### Model Finetuning
A training procedure that adapts a pre-trained volumetric prior to a target subject by optimizing both model parameters and a per-identity latent code, with an added linear layer for 3D normal prediction [S1]. It creates training batches by sampling 8,912 rays via random pixel sampling from all available views [S1]. It optimizes using Adam with a learning rate that starts at 0.001 and exponentially decays to 0.00002 [S1]. The number of optimization steps is set based on target resolution: 25,000 for 256×256, 50,000 for 512×512, 100,000 for 1024×1024, 200,000 for 2048×2048, and 300,000 for 4096×4096 [S1]. It is always optimized on 4 TPUs [S1].

## Operating characteristics
- **Time Complexity:** The model finetuning takes 4 hours for 25,000 steps and linearly increases for more training steps [S1].
- **Memory Complexity:** Not given in the sources.
- **Measured Performance:** On the authors' dataset, this method achieves PSNR 25.69, SSIM 0.8039, and LPIPS 0.1905, outperforming FreeNeRF [68], EG3D-based prior [9], Learnit [57], RegNeRF [36], and KeypointNeRF [32] [S1].
- **Strengths:** Correctly initializing the weights of the model avoids floater artifacts and leads to high-quality novel view synthesis with intricate details like individual hair strands from as few as two views [S1].
- **Limitations:** Training a NeRF model on sparse views leads to major artifacts because of distorted geometry and overfitting to high frequencies if not properly constrained [S1].
- **When to use:** When adapting a prior model for generating novel views of a target identity at high resolutions from sparse views [S1].
- **When not to use:** When the target identity requires a fixed latent code and only model weights should be adapted (use [Frozen Latent Code](18270-frozen-latent-code.md) instead) [S1].

## Background
Originated in "A Data-driven Volumetric Prior for Few-shot Ultra High-resolution Face Synthesis" [S1]. The method addresses the limitations of training NeRF models on sparse views, which typically result in distorted geometry and overfitting to high frequencies [S1]. It builds on the concept of using a pretrained prior model trained on low resolution to reconstruct a large set of identities from many views, and then fine-tuning it for a single target identity [S1]. The approach relies on camera alignment to a canonical pose using Procrustes analysis on 3D keypoints [S1].
