# DM-NeRF


## Overview
DM-NeRF is a single-pipeline method that simultaneously reconstructs continuous 3D scene geometry, decomposes all individual objects in 3D space, and supports flexible object shape manipulation (translation, rotation, size adjustment, deformation) from 2D images only [S1, unofficial]. It sets itself apart from standard NeRF variants by introducing an explicit "object field" that predicts a one-hot object code for every 3D point, enabling instance-level decomposition without 3D ground truth labels [S1, unofficial]. Unlike [Fig-NeRF](12006-fig-nerf.md) which focuses on figure-ground separation or [Unified Decompositional and Compositional NeRF](14413-unified-decompositional-and-compositional-nerf.md) which handles both decomposition and composition, DM-NeRF specifically targets the simultaneous reconstruction, decomposition, and *manipulation* of objects, including handling visual occlusions during editing [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A set of $L$ images for a static scene with known camera poses and intrinsics, denoted as $\{(I_1, \xi_1, K_1) \cdots (I_L, \xi_L, K_L)\}$ [S1, unofficial].
*   **Output:** A continuous 3D representation comprising volume density $\sigma$, color $c$, and an object code $o$ for any query point $p=(x,y,z)$ and viewing direction $v=(\theta, \phi)$ [S1, unofficial].

**Data Structures**
The network is an MLP with the following layer dimensions:
$128 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 256 \rightarrow 128$ [S1, unofficial].

The output tensor for a query point contains:
1.  Volume density $\sigma \in \mathbb{R}^1$ (function of location only).
2.  Object code $o \in \mathbb{R}^{H+1}$ (function of location only). This is a one-hot vector where $H$ is the predefined number of objects and the extra channel represents empty space [S1, unofficial].
3.  Color $c \in \mathbb{R}^3$ (function of location and viewing direction) [S1, unofficial].

**Parameters**
*   $H$: Predefined number of objects, determining the channel dimension of 2D object prediction tensors [S1, unofficial].
*   $T$: Number of ground truth objects, determining the channel dimension of 2D ground truth label tensors [S1, unofficial].
*   $L$: Number of generated 2D images used for supervision [S1, unofficial].
*   $U, V$: Spatial width and height dimensions of the 2D object prediction and ground truth label images [S1, unofficial].

**Algorithm**
The pipeline consists of three major components: a NeRF backbone, an object field, and an object manipulator [S1, unofficial].

1.  **Positional Encoding:** Compute positional encoding $PE(x,y,z)$ for the 3D location and $PE(\theta, \phi)$ for the viewing direction [S1, unofficial].
2.  **Forward Pass:** Feed the encoded location and direction into the MLP. The network outputs volume density $\sigma$, object code $o$, and color $c$ [S1, unofficial].
3.  **Loss Computation:** Optimize the network using multiple loss functions supervised by color images with 2D object masks [S1, unofficial]. Specifically, apply loss functions $\ell_{3d}^{empty} + \ell_{3d}^{obj}$ to jointly learn correct codes for empty 3D points [S1, unofficial].
4.  **2D Object Matching:** For each image pair (prediction $I_l$ and ground truth $\bar{I}_l$):
    *   Reshape the first $H$ solid object predictions of $I_l$ to $M \in \mathbb{R}^{N \times H}$, where $N = U \times V$ [S1, unofficial].
    *   Reshape $\bar{I}_l$ to $\bar{M} \in \mathbb{R}^{N \times T}$ [S1, unofficial].
    *   Associate every ground truth 2D object mask with a unique predicted 2D object mask using the Hungarian algorithm based on Soft Intersection-over-Union (sIoU) and Cross-Entropy Score (CES) [S1, unofficial].
5.  **Object Manipulation:** When editing a specified object:
    *   Apply the desired transformation (translation, rotation, size, deformation) to the object's geometry [S1, unofficial].
    *   Execute the 'Tackle visual occlusions' step to handle occluded regions automatically using a lightweight inverse query algorithm, avoiding the need to evaluate dense 3D points from implicit fields explicitly [S1, unofficial].

            # Compute cost matrix using sIoU and CES
            # C_sIoU[h, t] = sum(M[h] * M_bar[t]) / sum(M[h] + M_bar[t] - M[h] * M_bar[t])

            loss_color = mse(rendered_color, I_l)

            # Backpropagate
            network.backward(total_loss)

**Edge Cases and Pitfalls**
*   **No 3D Ground Truth:** Learning the object code faces the issue that no ground truth 3D object codes are available for full supervision [S1, unofficial].
*   **Variable Object Count:** The number of total objects is variable and there is no fixed order for objects [S1, unofficial].
*   **Empty Space:** Non-occupied (empty) 3D space must be taken into account, but there are no labels for supervision as well [S1, unofficial].
*   **Occlusion Artifacts:** Manipulating originally occluded objects or parts may produce artifacts due to inaccuracies in the learned radiance fields [S1, unofficial].
*   **Lighting Discrepancies:** Lighting factors are not decomposed, causing illumination discrepancies on edited objects compared to non-manipulated scenes [S1, unofficial].

## Operating characteristics
*   **Time and Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Novel view rendering quality is clearly better than PointNeRF, though it decreases after manipulation compared to non-manipulation baselines [S1, unofficial].
*   **Scaling:** Not given in the sources.
*   **Strengths:** Simultaneously reconstructs, decomposes, manipulates, and renders complex 3D scenes in a single pipeline from 2D views. The object decomposition is nearly perfect even after deformation manipulation [S1, unofficial].
*   **Limitations:** Manipulation of originally occluded objects may produce artifacts. Lighting factors are not decomposed [S1, unofficial].
*   **When to use:** When the goal is to decompose and manipulate 3D objects from 2D images without 3D ground truth.
*   **When not to use:** When high-fidelity lighting decomposition is required or when manipulating heavily occluded objects where artifacts are unacceptable.

## Background
DM-NeRF was published as a conference paper at ICLR 2023 [S1, unofficial]. It is among the first methods to simultaneously reconstruct, decompose, manipulate, and render complex 3D scenes in a single pipeline from 2D images [S1, unofficial]. The method builds on the successful NeRF architecture but adds an object field component to decompose the entire 3D space into object fields [S1, unofficial].
