# Dynamic Appearance Particle Neural Radiance Field
Also called: Dynamic Appearance Particle NeRF, Lagrangian dynamic model in NeRF

## Overview
Dynamic Appearance Particle NeRF is a method for modeling dynamic scenes from monocular video data by decomposing the radiance field into a static component and a dynamic component represented by moving particles [S1]. It solves the problem of reconstructing time-varying scenes without requiring multi-view stereo data or prior geometric knowledge of dynamic objects [S1]. Unlike ParticleNeRF, which encodes the entire scene with particles and requires multiple views per frame, this method applies appearance particles only to dynamic elements and uses a grid-based field for efficient querying, enabling the use of single-camera video streams [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Monocular video data (a sequence of images with known camera poses and timestamps $t$).
*   **Outputs:** A dynamic radiance field model capable of rendering novel views at arbitrary times $t$.

**Data Structures:**
The model consists of two primary components combined via superposition:
1.  **Static Field ($V_s$):** A time-independent grid-based model (e.g., a canonical feature field) storing static scene information [S1].
2.  **Dynamic Field ($V_{td}$):** A particle-based representation where particles move over time. Each particle carries appearance features. The field is quantized using a kernel $W$ with finite support [S1].

**Notation:**
*   $t$: Time index.
*   $\mathbf{x}$: 3D spatial position.
*   $\mathbf{d}$: View direction.
*   $V_s(\mathbf{x})$: Static field value at $\mathbf{x}$.
*   $V_{td}(\mathbf{x})$: Dynamic field value at $\mathbf{x}$.
*   $w_t(\mathbf{x})$: Weight function indicating if the dynamic field is effective at $(\mathbf{x}, t)$.
*   $W(\mathbf{x})$: Finite support kernel replacing the Dirac delta function.

**Method Steps:**

1.  **Field Decomposition:**
    The total feature field $V(\mathbf{x}, t)$ is computed as a weighted superposition of the static and dynamic fields [S1]:
    $$
    V(\mathbf{x}, t) = (1 - w_t(\mathbf{x}))V_s(\mathbf{x}) + w_t(\mathbf{x})V_{td}(\mathbf{x})
    $$
    Here, $w_t(\mathbf{x})$ takes the value 1 if the dynamic field is effective at location $\mathbf{x}$ and time $t$, and 0 otherwise [S1]. The support of the dynamic field is implied by the particle representation [S1].

2.  **Dynamic Field Formulation:**
    The dynamic field $V_{td}$ is formulated as a convolution with a Dirac function to integrate over finite volumes [S1]:
    $$
    V_{td}(\mathbf{x}) = (V_{td} * \delta)(\mathbf{x}) = \int V_{td}(\mathbf{x}')\delta(\mathbf{x} - \mathbf{x}')d\nu(\mathbf{x}')
    $$
    where $\delta(\cdot)$ is the Dirac function and $\nu(\cdot)$ is the volume integration variable [S1].

3.  **Kernel Quantization:**
    To enable efficient computation, the Dirac function $\delta$ is replaced with a kernel $W$ with finite support [S1]:
    $$
    W(\mathbf{x}) = 0 \quad \text{when } \|\mathbf{x}\| \text{ exceeds a small radius}
    $$
    $$
    \int W(\mathbf{x})d\nu(\mathbf{x}) = 1
    $$
    This leads to a quantization of the field, allowing particles to be queried efficiently [S1].

4.  **Rendering:**
    For a given ray $\mathbf{r}(s) = \mathbf{o} + s\mathbf{d}$ from camera center $\mathbf{o}$ at time $t$, the pixel color $C(\mathbf{r}, t)$ is computed by integrating along the ray from near bound $s_n$ to far bound $s_f$ [S1]:
    $$
    C(\mathbf{r}, t) = \int_{s_n}^{s_f} T(s, t) \sigma(\mathbf{r}(s), t) \mathbf{c}(\mathbf{r}(s), \mathbf{d}, t) ds
    $$
    where $T(s, t) = \exp\left(-\int_{s_n}^{s} \sigma(\mathbf{r}(s'), t) ds'\right)$ is the accumulated transmittance [S1]. The density $\sigma$ and color $\mathbf{c}$ are derived from the decomposed field $V(\mathbf{x}, t)$ [S1].

5.  **Particle Motion:**
    A particle motion network models the continuous dynamics of the particles across all time frames [S1]. The time $t$ is denoted in subscripts on the right-hand side of the superposition equation (e.g., $V_{td}$) to clarify that the dynamic component consists of an ensemble of particles, where the time argument is fixed for the instantaneous status construction [S1].

**Pseudocode:**

```python
def render_dynamic_nerf(ray_o, ray_d, time_t, static_grid, particles, kernel_width):
    """
    Renders a pixel for a dynamic scene using the superposition of static and dynamic fields.
    
    Args:
        ray_o: Origin of the ray (3D vector).
        ray_d: Direction of the ray (3D vector).
        time_t: Current time step.
        static_grid: Grid-based static field V_s(x).
        particles: List of particles, each with position p(t), velocity v(t), and appearance features.
        kernel_width: Radius of the finite support kernel W.
        
    Returns:
        color: Rendered pixel color.
    """
    # 1. Sample points along the ray
    # In practice, this involves sampling N points along the ray segment [s_n, s_f]
    # For this high-level description, we assume a function sample_ray exists
    points, depths = sample_ray(ray_o, ray_d, num_samples=128)
    
    density_sum = 0.0
    accumulated_color = 0.0
    transmittance = 1.0
    
    for i, point in enumerate(points):
        x = point
        s = depths[i]
        
        # 2. Query Static Field
        # V_s(x) is time-independent
        static_feat = query_static_grid(static_grid, x)
        
        # 3. Query Dynamic Field
        # V_td(x) is computed by aggregating contributions from nearby particles
        # using the finite support kernel W
        dynamic_feat = 0.0
        dynamic_weight_sum = 0.0
        
        for particle in particles:
            # Get particle position at current time t
            p_t = particle.position_at_time(time_t)
            
            # Compute distance
            dist = norm(x - p_t)
            
            # Check if within kernel support
            if dist <= kernel_width:
                # Compute kernel weight W(dist)
                # W(x) = 0 when ||x|| exceeds radius, integral is 1
                w_kernel = compute_kernel_weight(dist, kernel_width)
                
                # Aggregate particle features
                dynamic_feat += w_kernel * particle.features
                dynamic_weight_sum += w_kernel
        
        # Normalize dynamic features if needed, or use raw aggregation
        # The paper implies V_td is the convolution result
        dynamic_feat = dynamic_feat / dynamic_weight_sum if dynamic_weight_sum > 0 else 0.0
        
        # 4. Determine Weight w_t(x)
        # w_t(x) is 1 if dynamic field is effective, 0 otherwise
        # Effectiveness is implied by particle representation (i.e., if particles are nearby)
        # If dynamic_weight_sum > 0, the dynamic field is effective
        if dynamic_weight_sum > 0:
            w_t = 1.0
        else:
            w_t = 0.0
            
        # 5. Superposition
        # V(x, t) = (1 - w_t(x)) * V_s(x) + w_t(x) * V_td(x)
        combined_feat = (1 - w_t) * static_feat + w_t * dynamic_feat
        
        # 6. Decode to Density and Color
        # This step depends on the specific MLP architecture used to decode features
        # sigma and c are derived from combined_feat
        sigma, c = decode_features(combined_feat)
        
        # 7. Volume Rendering Accumulation
        # alpha = 1 - exp(-sigma * delta_s)
        # T(s) = product of (1 - alpha) for previous samples
        # contribution = T(s) * alpha * c
        delta_s = depths[i] - (depths[i-1] if i > 0 else 0)
        alpha = 1.0 - exp(-sigma * delta_s)
        
        accumulated_color += transmittance * alpha * c
        transmittance *= (1.0 - alpha)
        
        # Early termination if transmittance is very low
        if transmittance < 1e-5:
            break
            
    return accumulated_color
```

**Parameters:**
*   **Kernel Width:** The radius of the finite support kernel $W$. Not given in the sources.
*   **Weight $w_t(\mathbf{x})$:** Binary weight (0 or 1) determining the contribution of the dynamic field. It is 1 if the dynamic field is effective at $(\mathbf{x}, t)$ and 0 otherwise [S1].

**Edge Cases and Pitfalls:**
*   **Particle Density:** If no particles are near a query point, the dynamic field contribution is zero, and the static field is used. This requires careful initialization of particles to cover dynamic regions [S1].
*   **Temporal Consistency:** The particle motion network must ensure smooth transitions between time frames to avoid flickering [S1].
*   **Monocular Ambiguity:** Since the method uses monocular video, depth and motion estimation may be ambiguous for static background elements that move similarly to dynamic foreground elements. The superposition weight $w_t(\mathbf{x})$ helps disambiguate by assigning regions to either static or dynamic fields [S1].

## Operating characteristics
*   **Time Complexity:** Rendering time depends on the number of particles and the kernel support radius. Querying the dynamic field requires checking particles within the kernel radius, which can be optimized with spatial hashing or grids. The static field query is $O(1)$ with trilinear interpolation.
*   **Memory Complexity:** Memory is dominated by the static grid and the particle data structures. The number of particles scales with the complexity of the dynamic scene.
*   **Strengths:**
    *   Handles monocular video data, requiring only one camera view per time frame [S1].
    *   Does not require prior geometric knowledge of dynamic objects [S1].
    *   Efficient querying via grid-based static field and kernel-based dynamic field [S1].
    *   Not tightly coupled to a specific architecture; can be integrated into frameworks like InstantNGP [S1].
*   **Limitations:**
    *   Performance may degrade in scenes with high dynamic complexity requiring many particles.
    *   Relies on the accuracy of the particle motion network for temporal consistency.
*   **When to Use:** Suitable for dynamic scene reconstruction from monocular video where multi-view data is unavailable or impractical to collect.
*   **When Not to Use:** Not suitable for scenes requiring high-fidelity static background reconstruction with complex dynamic foregrounds if the particle representation cannot adequately capture the dynamics. Also not ideal if multi-view data is available, as other methods might offer better accuracy.

## Background
Dynamic Appearance Particle NeRF was proposed to address the limitations of existing dynamic NeRF methods that either require multi-view data or prior geometric knowledge. It builds on the Lagrangian dynamic model, representing scene dynamics through moving particles. The method was developed to handle monocular video data, making it more accessible for real-world applications where multi-camera setups are not feasible [S1]. It differs from ParticleNeRF, which encodes the entire scene with particles and requires 20 camera views per time frame, by applying appearance particles only to dynamic elements and using a grid-based field for efficient querying [S1].
