# SUDS
Also called: Scalable Urban Dynamic Scenes

## Overview
SUDS is a 4D radiance field representation designed for large-scale dynamic urban scenes that factorizes the scene into three separate multi-resolution hash table structures to efficiently encode static, dynamic, and far-field components [S1]. Unlike prior methods that require supervised inputs like 3D bounding boxes or panoptic labels, SUDS uses unlabeled target signals (RGB, sparse LiDAR, 2D descriptors, and 2D optical flow) for supervision, enabling free-viewpoint rendering, semantic decomposition, and 3D scene flow estimation at arbitrary poses and time steps [S1]. It scales to tens of thousands of objects across 1.2 million frames from 1700 videos, spanning geospatial footprints of hundreds of kilometers, while being 10x quicker to train than state-of-the-art methods relying on ground truth 3D annotations [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ordered RGB images from $N$ videos taken at different days with diverse weather/lighting, associated camera poses, aligned sparse LiDAR depth measurements, 2D self-supervised DINO descriptors, and 2D optical flow predictions [S1].
*   **Outputs:** Per-branch color, density, semantic feature logits, scene flow vectors, and shadow ratio [S1].

**Data Structures:**
The scene is decomposed into $K$ spatial cells with centroids $\mathbf{k} \in \mathbb{R}^3$. Each cell contains three multi-resolution hash table branches: Static, Dynamic, and Far-field [S1].
*   **Hash Tables:** Each branch uses $L$ resolution levels, where resolution doubles between levels [S1].
*   **Feature Vector:** Each hash table entry stores a feature vector $\mathbf{f} \in \mathbb{R}^F$ [S1].
*   **Hash Indexing:** Features are not stored at voxel corners directly; instead, hash indices are computed for corners using specific hash functions [S1]. Hash collisions are handled via gradient averaging [S1].
    *   Static branch index: $i_{l,s} = \text{static hash}(\text{space}(\mathbf{v}_{l,s}))$ [S1].
    *   Dynamic branch index: $i_{l,d} = \text{dynamic hash}(\text{space}(\mathbf{v}_{l,d}), \text{time}(\mathbf{v}_{l,d}), \text{vid})$ [S1].
    *   Far-field branch index: $i_{l,e} = \text{env hash}(\text{dir}(\mathbf{v}_{l,e}), \text{vid})$ [S1].
    *   Here, $\mathbf{v}_{l,s}, \mathbf{v}_{l,d}, \mathbf{v}_{l,e}$ are voxels at level $l$ for static, dynamic, and far-field branches respectively [S1]. The `vid` (video ID) is used as an auxiliary input to the hash function to index separate interpolating functions for each video without linear memory growth [S1].

**Numbered Steps:**
1.  **Spatial Partitioning:** Split the scene into $K$ spatial cells. Generate separate training datasets for each cell by including only datapoints whose camera rays intersect the cell. Prune irrelevant rays using LiDAR depth measurements to ensure visibility [S1].
2.  **Voxel Lookup:** For an input coordinate $(\mathbf{x}, \mathbf{d}, t, \text{vid})$ where $\mathbf{x} \in \mathbb{R}^3$ is position, $\mathbf{d} \in \mathbb{R}^3$ is viewing direction, $t$ is frame index, and $\text{vid}$ is video ID, find surrounding voxels at $L$ resolution levels for both static and dynamic branches (and far-field if applicable) [S1].
3.  **Hash Indexing:** Compute hash indices for the corners of the surrounding voxels using the functions defined in Data Structures [S1].
4.  **Feature Interpolation:** Look up feature vectors corresponding to the corners. Linearly interpolate features up to the nearest voxel vertices. Use quadlinear interpolation for the dynamic 4D branch. Concatenate results from all $L$ levels into a feature vector $\mathbf{f} \in \mathbb{R}^{LF}$ [S1].
5.  **Auxiliary Input Construction:**
    *   For the static branch, compute a latent embedding for lighting variations as $\mathbf{A}_{\text{vid}} \mathbf{F}(t)$, where $\mathbf{A}_{\text{vid}}$ is a video-specific matrix and $\mathbf{F}(t)$ is a Fourier-encoded time index [S1].
    *   Concatenate the interpolated feature vector $\mathbf{f}$ with auxiliary inputs (viewing direction $\mathbf{d}$ and lighting embedding for static branch) [S1].
6.  **MLP Evaluation:** Pass the concatenated vector into a small MLP to obtain per-branch outputs [S1]:
    *   **Static:** View-dependent color $\mathbf{c}_s(\mathbf{x}, \mathbf{d}, \mathbf{A}_{\text{vid}}\mathbf{F}(t)) \in \mathbb{R}^3$ and view-independent density $\sigma_s(\mathbf{x}) \in \mathbb{R}$ [S1].
    *   **Dynamic:** Time/video-dependent density $\sigma_d(\mathbf{x}, t, \text{vid}) \in \mathbb{R}$, color $\mathbf{c}_d(\mathbf{x}, t, \text{vid}, \mathbf{d}) \in \mathbb{R}^3$, scalar shadow ratio $\rho_d(\mathbf{x}, t, \text{vid}) \in [0, 1]$, and forward/backward 3D scene flow vectors $\mathbf{s}_{t0}(\mathbf{x}, t, \text{vid}) \in \mathbb{R}^3$ with values in $[-1, 1]$ [S1].
    *   **Far-field:** Environment map color $\mathbf{c}_e(\mathbf{d}, \text{vid}) \in \mathbb{R}^3$ [S1].
    *   **Semantic:** Add $C$-dimensional output heads to each branch to distill DINO features: $\Phi_s(\mathbf{x}) \in \mathbb{R}^C$, $\Phi_d(\mathbf{x}, t, \text{vid}) \in \mathbb{R}^C$, $\Phi_e(\mathbf{d}, \text{vid}) \in \mathbb{R}^C$ [S1].
7.  **Density Combination:** Compute total density $\sigma(\mathbf{x}, t, \text{vid}) = \sigma_s(\mathbf{x}) + \sigma_d(\mathbf{x}, t, \text{vid})$ [S1].
8.  **Radiance Combination:** Compute total radiance $\mathbf{c}(\mathbf{x}, t, \text{vid}, \mathbf{d})$ by combining static and dynamic components, scaled by shadow ratio:
    $$ \mathbf{c}(\mathbf{x}, t, \text{vid}, \mathbf{d}) = \frac{(1 - \rho_d)\sigma_s \mathbf{c}_s + \sigma_d \mathbf{c}_d}{\sigma} $$
    [S1].
9.  **Rendering:** Derive color $\hat{\mathbf{C}}$ for a camera ray $\mathbf{r}$ with direction $\mathbf{d}$ at frame $t$ and video $\text{vid}$ by accumulating transmittance along sampled points $\mathbf{r}(t)$ along the ray, forcing the ray to intersect the far-field environment map if it does not hit geometry within the foreground:
    $$ \hat{\mathbf{C}}(\mathbf{r}, t, \text{vid}) = \int_0^{+\infty} T(t)\sigma(\mathbf{r}(t), t, \text{vid})\mathbf{c}(\mathbf{r}(t), t, \text{vid}, \mathbf{d}) dt + T(+\infty)\mathbf{c}_e(\mathbf{d}, \text{vid}) $$
    where $T(t) = \exp\left(-\int_0^t \sigma(\mathbf{r}(s), t, \text{vid}) ds\right)$ [S1].
10. **Loss Calculation:** Compute losses as detailed below.

**Pseudocode:**
```python
def suds_forward(x, d, t, vid, hash_tables, mlp, A_vid, F_t):
    """
    x: Position (3,)
    d: Viewing direction (3,)
    t: Time index
    vid: Video ID
    hash_tables: Dict containing 'static', 'dynamic', 'far_field' multi-resolution hash tables
    mlp: Neural network for decoding features
    A_vid: Video-specific matrix for lighting
    F_t: Fourier-encoded time index
    """
    # 1. Voxel Lookup and Hash Indexing
    static_features = []
    dynamic_features = []
    far_field_features = []
    
    for level in hash_tables.levels:
        # Static branch: 3D spatial voxels
        v_l_s = get_surrounding_voxels(x, level)
        indices_s = [static_hash(space(v)) for v in v_l_s]
        feats_s = [hash_tables['static'].lookup(idx) for idx in indices_s]
        static_features.append(interpolate_linear(feats_s, x))
        
        # Dynamic branch: 4D spacetime voxels
        v_l_d = get_surrounding_voxels_4d(x, t, vid, level)
        indices_d = [dynamic_hash(space(v), time(v), vid) for v in v_l_d]
        feats_d = [hash_tables['dynamic'].lookup(idx) for idx in indices_d]
        dynamic_features.append(interpolate_quadlinear(feats_d, x, t))
        
        # Far-field branch: 3D direction voxels
        v_l_e = get_surrounding_voxels_dir(d, level)
        indices_e = [env_hash(dir(v), vid) for v in v_l_e]
        feats_e = [hash_tables['far_field'].lookup(idx) for idx in indices_e]
        far_field_features.append(interpolate_linear(feats_e, d))

    # 2. Concatenate Features
    f_static = concat(static_features) # R^{LF}
    f_dynamic = concat(dynamic_features) # R^{LF}
    f_far_field = concat(far_field_features) # R^{LF}

    # 3. MLP Evaluation
    # Static: View-dependent color, view-independent density, semantic features
    input_static = concat(f_static, d, A_vid * F_t)
    out_static = mlp(input_static)
    c_s = out_static['color']
    sigma_s = out_static['density']
    Phi_s = out_static['semantic']

    # Dynamic: Density, color, shadow ratio, scene flow, semantic features
    input_dynamic = concat(f_dynamic, d)
    out_dynamic = mlp(input_dynamic)
    sigma_d = out_dynamic['density']
    c_d = out_dynamic['color']
    rho_d = out_dynamic['shadow_ratio']
    s_flow = out_dynamic['scene_flow']
    Phi_d = out_dynamic['semantic']

    # Far-field: Environment map color, semantic features
    input_far = concat(f_far_field, d)
    out_far = mlp(input_far)
    c_e = out_far['color']
    Phi_e = out_far['semantic']

    # 4. Combine Densities and Radiance
    sigma_total = sigma_s + sigma_d
    c_total = ((1 - rho_d) * sigma_s * c_s + sigma_d * c_d) / sigma_total
    Phi_total = ((1 - rho_d) * sigma_s * Phi_s + sigma_d * Phi_d) / sigma_total # Assuming similar blending for semantics

    return {
        'color': c_total,
        'density': sigma_total,
        'semantic': Phi_total,
        'shadow_ratio': rho_d,
        'scene_flow': s_flow,
        'far_field_color': c_e
    }

def render_ray(r, t, vid, hash_tables, mlp, A_vid, F_t):
    """
    r: Ray origin and direction
    """
    samples = sample_along_ray(r)
    colors = []
    transmittances = []
    T = 1.0
    
    for sample in samples:
        x, dist = sample
        d = r.direction
        out = suds_forward(x, d, t, vid, hash_tables, mlp, A_vid, F_t)
        
        sigma = out['density']
        c = out['color']
        
        alpha = 1.0 - exp(-sigma * dist)
        weight = T * alpha
        colors.append(weight * c)
        transmittances.append(weight)
        T *= (1.0 - alpha)
        
        # If T is very small, break early
        if T < 1e-4:
            break
            
    # Add far-field contribution if ray didn't hit geometry
    if T > 1e-4:
        far_c = suds_forward(r.origin, r.direction, t, vid, hash_tables, mlp, A_vid, F_t)['far_field_color']
        colors.append(T * far_c)
        
    return sum(colors)
```

**Parameters:**
*   $F$: Dimensionality of feature vectors in the multi-resolution hash tables [S1].
*   $L$: Number of resolution levels in the hash table hierarchy, where resolution doubles between levels [S1].
*   $N$: Number of input videos [S1].
*   $\text{vid}$: Video ID identifier used as an auxiliary input to the hash function [S1].
*   $\mathbf{A}_{\text{vid}}$: Video-specific matrix used to compute a latent embedding for lighting variations [S1].
*   $\mathbf{F}(t)$: Fourier-encoded time index [S1].
*   $k$: Constant set to 1.75 in the skewed binary entropy loss [S1].
*   $C$: Dimensionality of the feature grid output from the DINO teacher model ($\mathbb{R}^{H \times W \times C}$) [S1].
*   250,000: Total number of training iterations [S1].
*   4098: Number of rays per batch during training [S1].
*   $5 \times 10^{-3}$: Initial learning rate for the Adam optimizer [S1].
*   $5 \times 10^{-4}$: Final learning rate for the Adam optimizer (decayed from initial) [S1].

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** Handled via gradient averaging [S1].
*   **Occlusions:** Warping losses are downweighted in ambiguous regions that may contain occlusions, using a weight $W_{t0}(\mathbf{r})$ derived from dynamic geometry difference [S1].
*   **Shadow Over-explanation:** The shadow ratio loss penalizes the squared magnitude of the shadow ratio to prevent it from over-explaining dark regions [S1].
*   **Static-Dynamic Factorization:** A skewed binary entropy loss favors static explanations of the scene, penalizing high dynamic ratios [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources, but noted to scale without linear memory growth with the number of videos due to hash indexing [S1].
*   **Measured Performance:** SUDS scales to tens of thousands of objects across 1.2 million frames from 1700 videos spanning geospatial footprints of hundreds of kilometers [S1]. It is 10x quicker to train than state-of-the-art methods that rely on ground truth 3D bounding box annotations [S1].
*   **Scaling:** Scales to city-scale environments (over 100 km²) by decomposing the scene into individually trained spatial cells [S1].
*   **Strengths:** Handles ego-motion and multi-video representations; uses unlabeled inputs (RGB, LiDAR, optical flow) to learn scene flow and semantic predictions; disentangles dynamic objects from static background and models shadow effects [S1].
*   **Limitations:** Requires aligned sparse LiDAR depth and 2D optical flow predictions as "free" supervision sources [S1].
*   **When to use:** Large-scale dynamic urban scene reconstruction, free-viewpoint synthesis, unsupervised 3D instance segmentation, and 3D cuboid detection [S1].
*   **When not to use:** Small-scale or static scenes where simpler methods suffice; scenes where labeled 3D bounding boxes are available and scale is not a concern (other methods may be faster to train if labels are cheap) [S1].

## Background
SUDS (Scalable Urban Dynamic Scenes) was introduced in 2023 [S1]. It builds on the idea of using multi-resolution hash tables for efficient neural rendering, inspired by Instant-NGP [S1]. It addresses the limitations of prior dynamic scene representations that require supervised inputs like panoptic segmentation labels or bounding boxes, which are difficult to acquire with high accuracy for in-the-wild captures [S1]. It also overcomes the memory constraints of object-centric approaches like NSG, which cannot handle ego-motion and require over 1TB of memory to represent a 30-second video [S1]. SUDS is used for free-viewpoint rendering, semantic decomposition, and 3D scene flow estimation in large-scale urban environments [S1].
