# Panoptic Neural Fields (PNF) Model Architecture

Also called: Panoptic Neural Fields, Panoptic Neural Fields (PNF) Rendering & Compositing

## Overview
Panoptic Neural Fields (PNF) decomposes a scene into a set of distinct Multi-Layer Perceptrons (MLPs), where each MLP represents either a specific object instance ("thing") or the background ("stuff") [S1]. This architecture learns a 4D panoptic radiance field from images alone, allowing the query of color, density, instance ID, and semantic category for any 3D point over time [S1]. Unlike monolithic radiance field models, PNF explicitly separates dynamic objects from the static background, enabling superior performance in dynamic scenes by modeling instance-specific geometry and appearance [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   3D position coordinates $\mathbf{x} \in \mathbb{R}^3$. For "stuff" (background), these are world coordinates. For "things" (objects), these are object-local coordinates.
*   3D view direction $\mathbf{d} \in \mathbb{R}^3$.
*   Time $t$ (implicit in the 4D representation, handled via object pose optimization).

**Outputs:**
*   Volume density $\sigma$.
*   RGB color $\mathbf{c}$.
*   Semantic class probability distribution.
*   Instance ID.

### Data Structures and Layout
The scene is represented by a collection of MLPs.
1.  **Stuff MLP:** Represents the static background.
    *   Architecture: 8 hidden layers, width 256.
    *   Input: Encoded world position + Encoded view direction.
2.  **Thing MLPs:** One MLP per detected object instance.
    *   Architecture: 4 hidden layers, width 128.
    *   Input: Encoded object-local position + Encoded view direction.

### Positional Encoding
Following the shared principles of the parent article, inputs are encoded using hierarchical sinusoidal positional encoding $\gamma(\cdot)$ [S1].

For a scalar input $p$:
$$ \gamma(p) = (\sin(2^0 \pi p), \cos(2^0 \pi p), \dots, \sin(2^{L-1} \pi p), \cos(2^{L-1} \pi p)) $$

**Parameters:**
*   **Stuff Position:** $L=10$ frequencies.
*   **Thing Position:** $L=6$ frequencies (applied to object-local coordinates).
*   **View Direction:** $L=2$ frequencies. These frequencies are gradually activated over the course of optimization [S1].

### Network Architecture and Output Heads
The MLPs predict outputs based on the encoded inputs. The architecture assumes that structure and semantics vary only with position, while appearance (color) varies with view direction [S1].

1.  **Density ($\sigma$) and Semantic ($\mathbf{s}$) Heads:**
    *   These heads depend **only** on the encoded position features.
    *   Semantic output is a probability distribution over classes.
2.  **Color ($\mathbf{c}$) Head:**
    *   This head takes the intermediate features from the position processing and concatenates them with the encoded view direction features.
    *   Output: RGB color values.

### Ray Sampling and Rendering
PNF does not use hierarchical sampling (coarse/fine networks) to conserve memory [S1]. Instead, it uses a single set of MLPs per instance/stuff.

**Sampling:**
*   Stratified sampling is used along rays.
*   Number of samples per ray: 1024 (as used in KITTI experiments) [S1].

**Compositing:**
For a ray $r$, the final color $C(r)$, density, semantic, and instance ID are computed by volume rendering (Eq. 2 in [S1], standard NeRF compositing):
$$ C(r) = \sum_{i=1}^N T_i \alpha_i \mathbf{c}_i $$
where $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$, $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$, and $\delta_i$ is the distance between samples.

**Panoptic Output:**
*   **Semantic Segmentation:** Rendered by compositing semantic probabilities along the ray.
*   **Instance Segmentation:** Rendered by compositing instance IDs weighted by opacity.
*   **Depth Estimation:** Obtained by over-compositing point depths along rays with opacity values [S1].

### Training Configuration
**Loss Function:**
The total loss combines color and semantic losses:
$$ \mathcal{L} = \mathcal{L}_{color} + \lambda \mathcal{L}_{semantic} $$
*   $\mathcal{L}_{color}$: Mean Squared Error (MSE) between rendered and ground truth RGB.
*   $\mathcal{L}_{semantic}$: Softmax cross-entropy between rendered semantic probabilities and ground truth labels.
*   $\lambda$: A scaling factor applied to the semantic loss to prevent it from dominating the training process, as MSE and Cross-Entropy have different scales [S1].

**Optimization:**
*   **Optimizer:** Adam [S1].
*   **Pose Optimization:** The rotation component $R \in \mathbb{R}^{3 \times 3}$ of object tracks is optimized. To ensure valid rotation matrices, SVD orthogonalization is applied [S1].
*   **Meta-Learning:** Category-specific learned initializations are derived using a simplified Federated Averaging (FedAvg) algorithm, equivalent to REPTILE meta-learning [S1]. This allows the model to generalize across object categories.

import numpy as np

def positional_encoding(p, L):
    """
    Hierarchical sinusoidal positional encoding.
    p: scalar or array of shape (D,)
    L: number of frequency bands
    Returns: array of shape (D * 2 * L,)
    """
    # Apply to each component independently
    encoded_components = []
    for dim in range(p.shape[0]):
        freqs = np.linspace(0, L-1, L)
        # 2^i * pi * p
        angles = np.outer(2**freqs * np.pi, p[dim])
        # sin and cos
        s = np.sin(angles)
        c = np.cos(angles)
        encoded_components.append(np.concatenate([s, c]))
    return np.concatenate(encoded_components)

        # Process color: concatenate position features (from last hidden layer) and view direction
        # Note: The paper states color is conditioned on view directions.
        # Typically, the position features passed to color head are the output of the last hidden layer

        color_input = np.concatenate([x, view_enc])
        color = sigmoid(color_input @ self.w_color)
        
        return sigma, semantic_probs, color

class ThingMLP:
    def __init__(self, object_id):
        # 4 hidden layers, width 128
        self.weights = initialize_weights(4, 128)
        self.biases = initialize_biases(4, 128)
        self.w_density = initialize_weights(128, 1)
        self.w_semantic = initialize_weights(128, num_classes)
        self.w_color = initialize_weights(128 + 4, 3)
        self.object_id = object_id

    def forward(self, pos_local, view_dir):
        # Encode inputs
        # L=6 for position (object local), L=2 for view direction
        pos_enc = positional_encoding(pos_local, L=6)
        view_enc = positional_encoding(view_dir, L=2)
        view_enc = apply_view_activation_schedule(view_enc, step)

        x = pos_enc
        for i in range(4):
            x = relu(x @ self.weights[i] + self.biases[i])
        
        sigma = sigmoid(x @ self.w_density)
        semantic_logits = x @ self.w_semantic
        semantic_probs = softmax(semantic_logits)
        
        color_input = np.concatenate([x, view_enc])
        color = sigmoid(color_input @ self.w_color)
        
        return sigma, semantic_probs, color, self.object_id

def render_ray(ray_origin, ray_direction, stuff_mlp, thing_mpls, near, far, num_samples=1024):
    """
    Renders a single ray by compositing contributions from stuff and all things.
    """
    # Sample points along ray
    t_vals = stratified_sample(near, far, num_samples)
    points = ray_origin + t_vals[:, None] * ray_direction
    
    # Initialize compositing variables
    accumulated_color = np.zeros(3)
    accumulated_alpha = 0.0
    accumulated_depth = 0.0
    accumulated_semantic = np.zeros(num_classes)
    accumulated_instance_id = -1
    
    # We need to determine which MLP contributes at each sample point.
    # This requires checking if a point is inside a thing's bounding box.
    # For simplicity, we assume a mask or distance field is available to select the MLP.
    # In PNF, this is handled by the object detection/tracking pipeline providing bounding boxes.
    
    for i, t in enumerate(t_vals):
        point = points[i]
        view_dir = ray_direction
        
        # Determine which MLP to query
        # 1. Check if point is inside any Thing's bounding box
        active_thing = None
        for thing in thing_mpls:
            if is_inside_bbox(point, thing.bbox):
                active_thing = thing
                break
        
        if active_thing:
            # Transform point to object local coordinates
            pos_local = transform_to_local(point, active_thing.pose)
            sigma, semantic_probs, color, instance_id = active_thing.mlp.forward(pos_local, view_dir)
        else:
            # Query Stuff MLP
            sigma, semantic_probs, color = stuff_mlp.forward(point, view_dir)
            instance_id = -1 # Background instance ID
        
        # Standard Volume Rendering Step
        delta = t_vals[i] - (t_vals[i-1] if i > 0 else near)
        alpha = 1.0 - np.exp(-sigma * delta)
        T = np.exp(-np.sum(sigma * delta)) # Cumulative transmittance up to this point
        
        weight = alpha * T
        accumulated_color += weight * color
        accumulated_alpha += weight
        accumulated_depth += weight * t_vals[i]
        accumulated_semantic += weight * semantic_probs
        
        # Instance ID is usually the last opaque object or weighted average
        if alpha > 0.5:
            accumulated_instance_id = instance_id
            
    return accumulated_color, accumulated_semantic, accumulated_instance_id, accumulated_depth

def train_step(stuff_mlp, thing_mpls, rays, gt_colors, gt_semantics, optimizer):
    """
    Single training step.
    """
    losses = []
    for ray, gt_c, gt_s in zip(rays, gt_colors, gt_semantics):
        pred_c, pred_s, _, _ = render_ray(*ray, stuff_mlp, thing_mpls)
        
        # Color Loss (MSE)
        l_color = np.mean((pred_c - gt_c)**2)
        
        # Semantic Loss (Cross-Entropy)
        l_semantic = cross_entropy(pred_s, gt_s)
        
        # Total Loss
        l_total = l_color + lambda_sem * l_semantic
        
        # Backpropagate and update
        optimizer.step(l_total)
        losses.append(l_total)
        
    return np.mean(losses)

### Edge Cases and Pitfalls
*   **Missing/Duplicate Detections:** The framework optimizes bounding box poses from noisy 3D object detection. It does not handle missing detections, duplicate detections, or incorrect class predictions from the detector [S1].
*   **Deformable Objects:** PNF is restricted to scenes with rigid moving objects. It does not handle deformable objects [S1].
*   **Complex Light Transport:** The model does not incorporate complex light transport effects such as shadowing under object motion [S1].
*   **Compute Intensity:** The method is compute-intensive and currently suited only for offline applications [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Memory:** PNF uses one MLP per object instance plus one for the background. This is more memory-intensive than grid-based methods but less than maintaining full hierarchical sampling networks for every object. The use of stratified sampling instead of hierarchical sampling reduces memory overhead compared to standard NeRF [S1].
*   **Time:** Rendering requires querying multiple MLPs per ray (one for the background, potentially one for each object intersecting the ray). Training involves optimizing both network weights and object poses (SVD orthogonalization) [S1].

### Measured Performance
*   Evaluated on KITTI and KITTI-360 datasets [S1].
*   Achieves state-of-the-art 74.28 mIoU for novel view semantic segmentation on KITTI [S1].
*   Outperforms SemanticNeRF by +9.2 mIoU on dynamic scenes [S1].
*   Outperforms NSG (Neural Scene Graphs) despite 10x fewer FLOPs in instance MLPs, due to category-specific priors from meta-learning [S1].

### Strengths and Limitations
*   **Strengths:** Explicitly models dynamic objects; provides panoptic segmentation (semantic + instance); enables scene editing (removing/adding objects); robust to dynamic scenes.
*   **Limitations:** Requires 3D object detection/tracking as input; cannot handle deformable objects; computationally expensive; limited to offline applications; sensitive to detection errors [S1].

### When to Use
*   Use PNF when the scene contains multiple dynamic rigid objects and panoptic segmentation is required.
*   Use when scene editing (object removal/addition) is a goal.
*   Do not use for real-time applications or scenes with significant deformation or complex lighting effects [S1].

## Background

### Origin
Panoptic Neural Fields (PNF) was introduced in the paper "Panoptic Neural Fields: A Semantic Object-Aware Neural Scene Representation" [S1].

### History and Development
PNF extends the NeRF framework by incorporating semantic and instance information. It builds upon the idea of decomposing scenes into object-aware components. The method utilizes meta-learning (via FedAvg/REPTILE) to learn category-specific initializations, allowing the model to generalize across different object categories [S1]. It addresses the limitations of previous methods like SemanticNeRF, which could not model dynamic objects effectively [S1].

### Usage
PNF has been evaluated on the KITTI and KITTI-360 datasets for tasks including novel view synthesis, panoptic segmentation, depth estimation, and scene editing [S1].
