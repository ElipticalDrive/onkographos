# MI-NeRF

Also called: Multi-Identity NeRF, Single Unified Face NeRF

## Overview
MI-NeRF is a method for learning a single unified dynamic neural radiance field (NeRF) that models complex non-rigid facial motion for multiple identities using only monocular videos of arbitrary length [S1, S1, unofficial]. It solves the problem of expensive per-identity optimization in dynamic face reconstruction by training a single implicit representation $F_\Theta$ conditioned on identity, expression, latent codes, position, and view direction [S1, unofficial]. Unlike previous generic NeRF models that require static settings and multiple input views during training, MI-NeRF works for monocular videos captured in the wild, reducing total training time by up to 90% compared to standard single-identity NeRFs [S1, S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:** Monocular RGB video frames for multiple identities; 3D Morphable Model (3DMM) parameters (head pose $P$, expression $e$) extracted per frame; randomly initialized identity codes $i$ and latent codes $l$.
*   **Outputs:** Rendered RGB video frames for novel viewpoints and expressions; personalized identity-specific models via fine-tuning.

**Data Structures**
*   **Identity Code ($i$):** Vector of size 79, randomly initialized per video, learned during training. Captures time-invariant identity information [S1, S1, unofficial].
*   **Latent Code ($l$):** Vector of size 32, randomly initialized per frame per video, learned during training. Captures time-varying information (illumination, appearance variations) [S1, S1, unofficial].
*   **Expression Parameters ($e$):** Vector of size 79, extracted via 3DMM fitting [S1, S1, unofficial].
*   **Head Pose ($P$):** $4 \times 4$ matrix, decomposed into rotation $R \in \mathbb{R}^{3 \times 3}$ and translation $t \in \mathbb{R}^{3 \times 1}$ [S1, S1, unofficial].
*   **Network Parameters ($\Theta$):** Weights of an 8-layer MLP with hidden size 256 and ReLU activations [S1, S1, unofficial].

**Method Steps**
1.  **Preprocessing:** For each video frame, segment the head from the background [S1, S1, unofficial]. Fit a 3DMM to extract head pose $P$ and expression parameters $e$ using an optimization-based method minimizing photo-consistency and landmark terms [S1, S1, unofficial]. Use learned axes from Guo et al. (2018b) based on the Basel Face Model and FaceWarehouse [S1, S1, unofficial].
2.  **Initialization:** Randomly initialize one identity code $i \in \mathbb{R}^{79}$ per video and one latent code $l \in \mathbb{R}^{32}$ per frame per video [S1, S1, unofficial].
3.  **Canonical Transformation:** Transform sampled 3D points $x$ to the canonical space using the head pose $P = [R; t]$ before shooting rays [S1, S1, unofficial].
4.  **Feature Interaction:** Compute the interaction between expression $e$ and identity $i$ using the Hadamard product (element-wise multiplication): $M(e, i) = e \odot i$ [S1, S1, unofficial]. Note: The source mentions $M(e,i)$ can be replaced by $H(e,i)$, but defines $M$ as the Hadamard product in the text [S1, S1, unofficial].
5.  **NeRF Query:** For each ray, sample 3D points $x$ and view directions $v$. Encode $x$ and $v$ using positional encoding. Concatenate the encoded features with the interaction term $M(e, i)$ and the latent code $l$. Pass through the MLP $F_\Theta$ to predict density $\sigma$ and color $\mathbf{c}$ [S1, S1, unofficial]:
    $$ F_\Theta : (M(\mathbf{e}, \mathbf{i}), \mathbf{l}, \mathbf{x}, \mathbf{v}) \rightarrow (\mathbf{c}, \sigma) $$
6.  **Volumetric Rendering:** Render the final color $C(\mathbf{r}; \Theta)$ for each ray $\mathbf{r}$ using volume rendering [S1, S1, unofficial]:
    $$ C(\mathbf{r}; \Theta) = \int_{t_n}^{t_f} \sigma(\mathbf{r}(t)) \mathbf{c}(\mathbf{r}(t), \mathbf{v}) T(t) dt $$
    where $T(t) = \exp(-\int_{t_n}^t \sigma(\mathbf{r}(s)) ds)$, and $t_n, t_f$ are near and far bounds [S1, S1, unofficial].
7.  **Optimization:** Optimize the network parameters $\Theta$, identity codes $i$, and latent codes $l$ simultaneously using hierarchical sampling (coarse and fine models) [S1, S1, unofficial]. Minimize the loss function:
    $$ \mathcal{L} = \mathcal{L}_c + \lambda_l \mathcal{L}_l + \lambda_i \mathcal{L}_i $$
    where $\mathcal{L}_c = \sum_r \| \hat{C}(\mathbf{r}; \Theta) - C(\mathbf{r}) \|_2^2$ is the photo-consistency loss, $\mathcal{L}_l = \|\mathbf{l}\|_2^2$, $\mathcal{L}_i = \|\mathbf{i}\|_2^2$, $\lambda_l = 0.01$, and $\lambda_i = 10^{-4}$ [S1, S1, unofficial].

**Pseudocode**
```python
import torch
import torch.nn as nn
import torch.optim as optim

class MINeRF:
    def __init__(self, num_identities, num_frames_per_video, hidden_size=256, num_layers=8):
        self.num_identities = num_identities
        self.num_frames_per_video = num_frames_per_video
        
        # Identity codes: one per identity, size 79
        self.identity_codes = nn.Embedding(num_identities, 79)
        nn.init.normal_(self.identity_codes.weight.data)
        
        # Latent codes: one per frame per video, size 32
        # Total frames = num_identities * num_frames_per_video
        self.latent_codes = nn.Embedding(num_identities * num_frames_per_video, 32)
        nn.init.normal_(self.latent_codes.weight.data)
        
        # MLP Architecture
        layers = []
        input_dim = 79 + 32 + 3 * 20 + 3 * 8 # Interaction(79) + Latent(32) + PosEnc(60) + DirEnc(24)
        # Note: PosEnc for x is 10 freqs -> 60 dims, DirEnc for v is 4 freqs -> 24 dims
        # The interaction term M(e,i) is size 79.
        # The source says input is (M(e,i), l, x, v). 
        # Standard NeRF positional encoding: 2*L freqs per dim.
        # x: 3 dims * 10 freqs * 2 = 60. v: 3 dims * 4 freqs * 2 = 24.
        # Total input dim = 79 + 32 + 60 + 24 = 195.
        
        for _ in range(num_layers):
            layers.append(nn.Linear(input_dim, hidden_size))
            layers.append(nn.ReLU())
            input_dim = hidden_size
        
        # Branches
        self.color_branch = nn.Linear(hidden_size, 3) # RGB
        self.density_branch = nn.Linear(hidden_size, 1) # Sigma
        
        self.mlp = nn.Sequential(*layers)
        
        # Optimizer
        self.optimizer = optim.Adam(
            list(self.mlp.parameters()) + 
            list(self.identity_codes.parameters()) + 
            list(self.latent_codes.parameters()),
            lr=5e-4
        )
        self.scheduler = optim.lr_scheduler.ExponentialLR(self.optimizer, gamma=0.99) # Approximation of exponential decay
        
        # Hyperparameters
        self.lambda_l = 0.01
        self.lambda_i = 1e-4
        self.pos_freqs_x = 10
        self.pos_freqs_v = 4

    def positional_encoding(self, x, freqs):
        """Standard positional encoding as defined in parent article."""
        # x shape: (..., 3)
        # Output shape: (..., 3 * freqs * 2)
        pe = []
        for i in range(freqs):
            scale = 2**i * torch.pi
            pe.append(torch.sin(scale * x))
            pe.append(torch.cos(scale * x))
        return torch.cat(pe, dim=-1)

    def forward(self, identity_idx, frame_idx, x, v, e):
        """
        identity_idx: long tensor of shape (batch_size,)
        frame_idx: long tensor of shape (batch_size,)
        x: tensor of shape (batch_size, num_samples, 3)
        v: tensor of shape (batch_size, num_samples, 3)
        e: tensor of shape (batch_size, num_samples, 79)
        """
        # Get codes
        i = self.identity_codes(identity_idx).unsqueeze(1) # (batch, 1, 79)
        l = self.latent_codes(frame_idx).unsqueeze(1)     # (batch, 1, 32)
        
        # Hadamard product for interaction M(e, i)
        # e is (batch, num_samples, 79), i is (batch, 1, 79) -> broadcast
        M_ei = e * i
        
        # Positional Encodings
        pe_x = self.positional_encoding(x, self.pos_freqs_x) # (batch, num_samples, 60)
        pe_v = self.positional_encoding(v, self.pos_freqs_v) # (batch, num_samples, 24)
        
        # Concatenate features
        # Shape: (batch, num_samples, 79 + 32 + 60 + 24)
        features = torch.cat([M_ei, l.expand_as(M_ei), pe_x, pe_v], dim=-1)
        
        # MLP
        h = self.mlp(features) # (batch, num_samples, 256)
        
        # Branches
        sigma = self.density_branch(h).squeeze(-1) # (batch, num_samples)
        color = torch.sigmoid(self.color_branch(h)) # (batch, num_samples, 3)
        
        return color, sigma

    def render_ray(self, ray_o, ray_d, t_n, t_f, num_samples, identity_idx, frame_idx, e):
        """
        ray_o: (batch, 3)
        ray_d: (batch, 3)
        t_n, t_f: scalars
        """
        # Sample points along ray
        t_vals = torch.linspace(t_n, t_f, num_samples).to(ray_o.device)
        t_vals = t_vals.unsqueeze(0).expand(ray_o.shape[0], -1)
        x = ray_o.unsqueeze(1) + ray_d.unsqueeze(1) * t_vals.unsqueeze(2) # (batch, num_samples, 3)
        v = ray_d.unsqueeze(1).expand(-1, num_samples, -1) # (batch, num_samples, 3)
        
        # Forward pass
        color, sigma = self.forward(identity_idx, frame_idx, x, v, e)
        
        # Volumetric Rendering
        # Compute deltas
        deltas = t_vals[:, 1:] - t_vals[:, :-1]
        delta_inf = torch.tensor(1e10).to(ray_o.device)
        deltas = torch.cat([deltas, delta_inf.unsqueeze(0).expand_as(deltas)], dim=1)
        
        # Alpha
        alpha = 1 - torch.exp(-sigma * deltas)
        
        # Transmittance
        T = torch.cumprod(1 - alpha + 1e-10, dim=1)
        T = torch.cat([torch.ones_like(T[:, :1]), T[:, :-1]], dim=1)
        
        # Weight
        weights = alpha * T
        
        # Composite color
        C = torch.sum(weights.unsqueeze(2) * color, dim=1)
        
        return C

    def train_step(self, batch):
        """
        batch: dict with 'video_idx', 'frame_idx', 'gt_color', 'pose', 'expr'
        """
        self.optimizer.zero_grad()
        
        # Extract inputs
        video_idx = batch['video_idx']
        frame_idx = batch['frame_idx']
        gt_color = batch['gt_color']
        pose = batch['pose'] # P
        expr = batch['expr'] # e
        
        # Transform points to canonical space? 
        # The source says: "Use the extracted head pose P... to transform sampled 3D points to the canonical space before shooting rays"
        # This implies the ray marching happens in canonical space, or the points x are transformed.
        # Standard NeRF samples in world space. Here, we likely sample in world space, transform to canonical, then query.
        # Or sample in canonical space? The source says "march camera rays through the scene and sample 3D points... transform... to canonical".
        # Let's assume we sample in world space, then transform x to x_canonical.
        
        # Ray generation (simplified, assuming intrinsics/extrinsics are handled elsewhere)
        # For this pseudocode, we assume x and v are provided in world space for the current frame
        # and we need to transform x to canonical space for the network query.
        # However, the network input is (M(e,i), l, x, v). 
        # The source formula 3 uses x and v. 
        # Section 3.1 says: "P... is used to transform the sampled 3D points to the canonical space before shooting the rays"
        # This phrasing is slightly ambiguous. Usually, you shoot rays in world space, get points, then transform points to canonical for the MLP.
        # Let's assume x_world is sampled, then x_canonical = R^T * (x_world - t).
        
        # For the sake of the pseudocode, we will assume the caller provides x_canonical and v_canonical?
        # No, v is view direction. In canonical space, the view direction also changes.
        # Let's stick to the high-level logic provided in the notes.
        
        # 1. Sample points x_world along rays.
        # 2. Transform x_world to x_canonical using P.
        # 3. Transform v_world to v_canonical using R.
        # 4. Query MLP with x_canonical, v_canonical, e, i, l.
        
        # Since ray marching details are standard NeRF, we focus on the conditioning.
        
        # Placeholder for ray marching logic which is standard
        x_world, v_world = sample_rays(batch['rays'], t_n, t_f)
        
        # Transform to canonical
        R = pose['R']
        t = pose['t']
        # x_canonical = R^T * (x_world - t)
        x_canonical = torch.matmul(R.transpose(-2, -1), (x_world - t).unsqueeze(-1)).squeeze(-1)
        # v_canonical = R^T * v_world
        v_canonical = torch.matmul(R.transpose(-2, -1), v_world.unsqueeze(-1)).squeeze(-1)
        
        # Identity and Frame indices
        identity_idx = video_idx
        frame_idx = video_idx * self.num_frames_per_video + batch['local_frame_idx']
        
        # Forward
        color, sigma = self.forward(identity_idx, frame_idx, x_canonical, v_canonical, expr)
        
        # Render
        C_pred = self.render_ray(batch['ray_o'], batch['ray_d'], t_n, t_f, num_samples, identity_idx, frame_idx, expr)
        
        # Loss
        L_c = torch.mean((C_pred - gt_color) ** 2)
        L_l = torch.mean(self.latent_codes.weight ** 2)
        L_i = torch.mean(self.identity_codes.weight ** 2)
        
        loss = L_c + self.lambda_l * L_l + self.lambda_i * L_i
        
        loss.backward()
        self.optimizer.step()
        self.scheduler.step()
        
        return loss.item()
```

**Parameters**
*   **Expression parameter dimension:** 79 [S1, S1, unofficial].
*   **Identity code dimension:** 79 [S1, S1, unofficial].
*   **Latent code dimension:** 32 [S1, S1, unofficial].
*   **MLP architecture:** 8 linear layers, hidden size 256, ReLU activations [S1, S1, unofficial].
*   **Positional encoding frequencies:** 10 for position $x$, 4 for view direction $v$ [S1, S1, unofficial].
*   **Optimizer:** Adam, learning rate $5 \times 10^{-4}$ decaying exponentially to $5 \times 10^{-5}$ [S1, S1, unofficial].
*   **Regularization weights:** $\lambda_l = 0.01$, $\lambda_i = 10^{-4}$ [S1, S1, unofficial].

**Edge Cases and Pitfalls**
*   **Short Videos:** The method works for very short video clips (only a few seconds), but personalization may require a short video of the target identity to capture details like wrinkles [S1, S1, unofficial].
*   **Monocular Input:** Unlike multi-view methods, MI-NeRF relies on monocular videos, which may lead to ambiguities in depth without strong priors from the 3DMM fitting [S1, S1, unofficial].
*   **Identity Disentanglement:** The Hadamard product is used to approximate non-linear interactions. The source notes that higher-degree interactions might be beneficial in other cases, but Hadamard was chosen for simplicity and effectiveness [S1, S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Training time is reduced by up to 90% compared to training multiple standard single-identity NeRFs, leading to a sublinear cost curve with respect to the number of identities [S1, S1, unofficial].
*   **Memory Complexity:** Requires storing one identity code (79 dims) per identity and one latent code (32 dims) per frame per video, plus the MLP weights. This is significantly less than storing separate NeRFs for each identity.
*   **Strengths:** Works with monocular videos of arbitrary length captured in the wild; robust to synthesizing novel expressions for any input identity; allows personalization with few iterations [S1, S1, unofficial].
*   **Limitations:** Requires 3DMM fitting for each frame to extract pose and expression; relies on the quality of the 3DMM fit (Basel Face Model/FaceWarehouse axes); may struggle with extreme occlusions or non-facial regions if not segmented properly [S1, S1, unofficial].
*   **When to use:** When training a unified model for multiple identities from monocular videos is required, and computational efficiency is a priority.
*   **When not to use:** When multi-view stereo data is available and higher geometric accuracy is needed without reliance on 3DMM priors; when real-time rendering is required without pre-computation (standard NeRF is not real-time).

## Background
MI-NeRF was introduced by Chatziagapi et al. in 2024 [S1, unofficial]. It addresses the challenge of capturing 4D dynamics and appearance of non-rigid human face motion, which has applications in AR/VR, video games, and virtual communication [S1, unofficial]. Previous approaches relied on 3DMMs or GANs, or required per-identity optimization for NeRFs [S1, unofficial]. MI-NeRF is the first method to learn a single unified face NeRF from monocular videos of multiple identities, leveraging a multiplicative module to disentangle identity and non-identity specific information [S1, S1, unofficial].
