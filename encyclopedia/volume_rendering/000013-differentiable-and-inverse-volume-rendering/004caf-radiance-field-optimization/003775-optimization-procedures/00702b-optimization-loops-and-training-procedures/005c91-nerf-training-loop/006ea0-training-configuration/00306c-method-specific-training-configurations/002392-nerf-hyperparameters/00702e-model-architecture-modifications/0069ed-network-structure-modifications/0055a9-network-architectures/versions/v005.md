# Network Architectures

Also called: NeRF Network Architectures

## Overview
Network architectures in differentiable volume rendering modify the standard NeRF baseline [Parent](3065-nerf-hyperparameters.md) to address specific limitations such as inference speed, scene complexity, or semantic understanding. While the standard architecture uses two MLPs (coarse and fine) with positional encoding, modifications generally fall into three categories: input expansion (adding conditioning vectors), output expansion (adding auxiliary heads for semantic/object codes), and representation substitution (replacing MLPs with discrete structures or SDFs) [14428-sparse-view-and-few-shot-optimization.md]. These architectures aim to improve rendering fidelity, enable novel tasks like object manipulation, or reduce computational costs on constrained hardware.

## How it works
The standard NeRF architecture [Parent](3065-nerf-hyperparameters.md) serves as the baseline. It consists of two Multi-Layer Perceptrons (MLPs): a coarse network and a fine network. The coarse network takes positional encoded position $\gamma(\mathbf{x})$ and outputs a latent feature vector $\mathbf{h}$ and volume density $\sigma$. The fine network takes $\mathbf{h}$, positional encoded position $\gamma(\mathbf{x})$, and positional encoded view direction $\gamma(\mathbf{d})$ to output color $\mathbf{c}$ [14428-sparse-view-and-few-shot-optimization.md].

$$
\gamma(\mathbf{x}, d_1, d_2) = [\mathbf{x}, \sin(2^{d_1}\pi\mathbf{x}), \cos(2^{d_1}\pi\mathbf{x}), \dots, \sin(2^{d_2-1}\pi\mathbf{x}), \cos(2^{d_2-1}\pi\mathbf{x})]
$$

Modifications generally fall into three categories [14428-sparse-view-and-few-shot-optimization.md]:
1.  **Input Expansion:** Adding new conditioning vectors (e.g., appearance embeddings $\mathbf{z}_i$, fluid volume $v$, or previous stage RGB) to the input concatenation [14428-sparse-view-and-few-shot-optimization.md].
2.  **Output Expansion:** Adding auxiliary heads to predict values other than $\sigma$ and $\mathbf{c}$, such as semantic labels $y_{aux}$, object codes $o$, or area encoding probabilities $p$. These are rendered using the same transmittance weights $T_i$ and opacity $\alpha_i$ as color:
    $$
    \hat{Y}(r) = \sum_{i=1}^{N} T_i \alpha_i y_{aux}(x_i)
    $$
3.  **Representation Substitution:** Replacing the continuous MLP function with discrete structures (voxel grids, hash tables) or different implicit surfaces (SDFs).

### MIMO-DONeRF
MIMO-DONeRF applies the Multi-Input Multi-Output (MIMO) neural rendering concept to the DONeRF architecture [S1]. It modifies the shading network to accept multiple spatial inputs and view directions simultaneously, producing multiple color and density outputs per forward pass [S1]. This approach improves inference speed compared to increasing the number of samples in standard DONeRF, while maintaining or improving image quality by allowing the network to accumulate neighbor information through grouped samples [S1]. It differs from standard DONeRF by processing $N_p$ samples in parallel rather than sequentially, and from MIMO-NeRF by being specifically adapted to the two-network structure (depth oracle and shading) of DONeRF [S1]. The MLPs A and F use the MLP designed in NeRF, with hidden layer sizes increased from 256 to 384 [S1]. MLPs A and F are not used during inference, allowing more time on training [S1]. The small MLP H is the same as the small MLP used in SNeRG, with two hidden layers, each consisting 16 neurons [S1].

### Point-NeRF Adaptation for Object Manipulation
This variant adapts Point-NeRF for scene-level geometry decomposition and manipulation [S2, unofficial]. During training, it uses ground truth dense point clouds (400 million points per scene) instead of MVSNet generated ones to generate the neural point cloud [S2, unofficial]. During inference, it feeds the spatial locations of all neural points into DM-NeRF to infer corresponding object codes [S2, unofficial]. After determining points to edit, it transforms corresponding neural points to desired locations based on predefined manipulation information [S2, unofficial]. The new neural point cloud is then used to render an image with object manipulation from a given view using point-based volume rendering in Point-NeRF [S2, unofficial].
