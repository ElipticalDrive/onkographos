# Fig-NeRF
Also called: FigNeRF
## Overview
Fig-NeRF is a scene composition model designed for object interpolation and amodal segmentation by decomposing a scene into separate foreground and background representations [S1]. It distinguishes itself from standard NeRF by modeling an object category as a template shape that undergoes latent-conditioned deformation, allowing for intuitive shape variation explanation and retrieval from real object scans [S2, unofficial].
## How it works
### Inputs and Outputs
**Inputs:**
*   A set of input images containing an object and its background.
*   Camera poses corresponding to the input images.
*   A latent code $z$ representing the object category and specific instance variations.

**Outputs:**
*   A rendered image of the scene.
*   A segmentation mask separating the foreground object from the background.

### Data Structures
The method utilizes two distinct Neural Radiance Field (NeRF) models:
1.  **Foreground Model:** A deformable NeRF (based on the Nerfies architecture) [S1]. It stores a template shape and deformation fields.
2.  **Background Model:** An appearance NeRF conditioned on latent codes [S1].

### Steps
1.  **Latent Encoding:** Encode the object category and instance-specific variations into a latent code $z$ [S2, unofficial].
2.  **Template and Deformation:** Define a template shape for the object category. Apply a deformation field to this template, where the deformation is conditioned on the same latent code $z$ [S2, unofficial]. This allows the network to explain shape variations as intuitive deformations of the template [S2, unofficial].
3.  **Background Modeling:** Train a separate, learnable background model to represent the scene's background [S2, unofficial]. This model is conditioned on latent codes to capture appearance variations [S1].
4.  **Rendering:** Render the foreground and background separately using volume rendering. The foreground is rendered using the deformed template shape, and the background is rendered using the appearance NeRF [S1][S2, unofficial].
5.  **Segmentation:** Use the learnable background model to segment the object from the background [S2, unofficial]. This implies a compositional model where the final image is a combination of the foreground and background renders, potentially with an alpha mask derived from the segmentation process.
6.  **Loss Calculation:** Compute two separate photometric losses: one for the foreground and one for the background [S1].
7.  **Optimization:** Optimize the parameters of both the foreground and background models, as well as the latent code $z$, to minimize the combined photometric losses [S1][S2, unofficial].

### Formulas
*   **Deformation:** $x' = T(x, z)$, where $T$ is the deformation function conditioned on latent code $z$, and $x$ is a point on the template shape [S2, unofficial].
*   **Photometric Loss:** $L = L_{fg} + L_{bg}$, where $L_{fg}$ is the photometric loss for the foreground and $L_{bg}$ is the photometric loss for the background [S1].

### Edge Cases and Pitfalls
*   **Ambiguous Segmentation:** If the background model is not sufficiently expressive, it may fail to accurately segment the object, leading to artifacts in the foreground render [S2, unofficial].
*   **Deformation Artifacts:** The deformation field must be smooth and physically plausible to avoid unrealistic shape variations [S2, unofficial].
*   **Latent Code Interpretability:** The latent code $z$ must effectively capture both category-level and instance-level variations for meaningful interpolation [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Achieves good results for amodal segmentation and object interpolation on datasets such as ShapeNet, Gelato, and Objectron [S1].
*   **Strengths:** Enables object interpolation and amodal segmentation; models shape variations as intuitive deformations [S1][S2, unofficial].
*   **Limitations:** Requires separate models for foreground and background, increasing complexity [S1].
*   **When to Use:** When object interpolation and amodal segmentation are required, and the object category has significant shape variations [S1][S2, unofficial].
*   **When Not to Use:** When a simple, single-model NeRF is sufficient for the scene [S1].

## Background
Fig-NeRF was introduced in April 2021 [S1]. It builds on the concept of scene composition and focuses on object interpolation and amodal segmentation [S1]. The method models an object category as a template shape conditioned on a latent code, which undergoes a deformation also conditioned on the same latent variable [S2, unofficial]. This approach enables the network to explain certain shape variations as more intuitive deformations [S2, unofficial]. Fig-NeRF focuses on retrieving an object category from real object scans and proposes using a learnable background model to segment the object from its background [S2, unofficial].
