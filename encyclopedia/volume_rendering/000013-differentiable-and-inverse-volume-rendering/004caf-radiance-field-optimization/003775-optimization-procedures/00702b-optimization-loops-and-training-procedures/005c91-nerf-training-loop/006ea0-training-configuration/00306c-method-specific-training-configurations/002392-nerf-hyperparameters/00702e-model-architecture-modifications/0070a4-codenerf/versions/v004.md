# CodeNeRF

Also called: Disentangled Neural Radiance Fields for Object Categories

## Overview
CodeNeRF is an implicit 3D neural representation that learns the variation of object shapes and textures across a semantic category, enabling the synthesis of novel views of unseen objects from a single unposed input image [S2]. Unlike standard NeRF which is scene-specific, CodeNeRF disentangles shape and texture by learning separate latent embeddings, allowing for joint optimization of camera viewpoint, shape code, and texture code at test time [S2]. It differs from sibling methods like DoF-NeRF by explicitly decoupling shape and texture into independent embedding spaces, whereas alternatives like M1 (direction input to shape network) or M2 (single embedding) fail to maintain disentanglement, leading to incorrect textures or unwanted shape changes during editing [S2].

## How it works
CodeNeRF employs an auto-decoder architecture with decoupled shape and texture embedding spaces. The model consists of two MLPs: a shape network $F^s_{\Theta_s}$ and a texture network $F^t_{\Theta_t}$, which together form the radiance field $F_\Theta$ [S2].

### Inputs and Outputs
*   **Inputs:**
    *   3D spatial position $\mathbf{x} \in \mathbb{R}^3$ [G].
    *   Viewing direction $\mathbf{d} \in \mathbb{R}^3$ [G].
    *   Shape latent code $\mathbf{z_s} \in \mathbb{R}^{D_s}$ [S2].
    *   Texture latent code $\mathbf{z_t} \in \mathbb{R}^{D_t}$ [S2].
    *   Camera parameters (azimuth $\phi$, elevation $\theta$, distance $\rho$) during inference optimization [S2].
*   **Outputs:**
    *   Volume density $\sigma \in \mathbb{R}$ [G].
    *   View-dependent color $\mathbf{c} \in \mathbb{R}^3$ [S2].

### Data Structures
*   **Network Parameters $\Theta$:** Weights for $F^s_{\Theta_s}$ and $F^t_{\Theta_t}$ [S2].
*   **Latent Embeddings:**
    *   $\mathbf{z_s}$: Shape code.
    *   $\mathbf{z_t}$: Texture code.
    *   During training, a set of embeddings $\{\mathbf{z_s}_j, \mathbf{z_t}_j\}_{j=1}^M$ is maintained for $M$ objects [S2].
*   **Camera Pose:** Represented by spherical coordinates $(\phi, \theta, \rho)$ or equivalent rotation/translation matrices for ray generation [S2].

### Positional Encoding
Positional encoding $\gamma(\cdot)$ is applied to coordinates and directions to capture high-frequency details [S2]:
*   For 3D point coordinates $\mathbf{x}$: 10 frequencies are used [S2].
*   For viewing directions $\mathbf{d}$: 4 frequencies are used [S2].

### Network Architecture
The architecture uses two decoupled networks to enforce disentanglement [S2]:

1.  **Shape Network ($F^s_{\Theta_s}$):**
    Takes the positional encoding of the 3D point $\gamma_{\mathbf{x}}(\mathbf{x})$ and the shape code $\mathbf{z_s}$ as input. It outputs the volume density $\sigma$ and an intermediate feature vector $\mathbf{v} \in \mathbb{R}^{256}$ [S2].
    $$ F^s_{\Theta_s}: (\gamma_{\mathbf{x}}(\mathbf{x}), \mathbf{z_s}) \rightarrow (\sigma, \mathbf{v}) $$

2.  **Texture Network ($F^t_{\Theta_t}$):**
    Takes the intermediate feature vector $\mathbf{v}$, the positional encoding of the viewing direction $\gamma_{\mathbf{d}}(\mathbf{d})$, and the texture code $\mathbf{z_t}$ as input. It outputs the RGB color $\mathbf{c}$ [S2].
    $$ F^t_{\Theta_t}: (\mathbf{v}, \gamma_{\mathbf{d}}(\mathbf{d}), \mathbf{z_t}) \rightarrow (\mathbf{c}) $$

The combined radiance field is $F_\Theta = F^t_{\Theta_t} \circ F^s_{\Theta_s}$ [S2].

### Volume Rendering
Color is aggregated along camera rays $\mathbf{r}(t) = \mathbf{c} + t\mathbf{d}$ using standard volume rendering equations with $N$ uniform samples from near to far bounds [S2]. The estimated pixel color $\hat{C}(\mathbf{r})$ is:

$$ \hat{C}(\mathbf{r}) = \sum_{i=1}^{N} T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i $$

Where:
*   $\delta_i = t_{i+1} - t_i$ is the distance between adjacent samples [S2].
*   $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$ is the accumulated transmittance [S2].
*   $\sigma_i$ and $\mathbf{c}_i$ are the density and color at sample $i$ [S2].

### Training Procedure
During training, the model learns from a set of $N$ images depicting $M$ objects with known poses [S2].

1.  **Ray Sampling:** For each image, sample a batch of 4094 rays using intrinsic and extrinsic camera parameters [S2].
2.  **Point Sampling:** Sample 64 points along each ray [S2].
3.  **Forward Pass:** Feed points, directions, and current latent codes $\{\mathbf{z_s}_j, \mathbf{z_t}_j\}$ into $F_\Theta$ to obtain $\sigma$ and $\mathbf{c}$ [S2].
4.  **Rendering:** Compute rendered colors $\hat{C}(\mathbf{r})$ using volume rendering [S2].
5.  **Loss Calculation:** Minimize the total loss $\mathcal{L}$ [S2]:

    $$ \mathcal{L}(\Theta, \{\mathbf{z_s}^i, \mathbf{z_t}^i\}^M) = \sum_{\mathbf{r} \in \mathcal{R}} ||\hat{C}(\mathbf{r}) - C(\mathbf{r})||_2^2 + \frac{1}{\nu^2} \sum_{i=1}^M (||\mathbf{z_s}^i||_2^2 + ||\mathbf{z_t}^i||_2^2) $$

    Where:
    *   The first term is the photometric L2 loss [S2].
    *   The second term is an L2 regularization loss on the latent vectors with weight $1/\nu^2$ [S2].
    *   $\mathcal{R}$ is the set of sampled rays [S2].

6.  **Optimization:** Update network parameters $\Theta$ and latent embeddings $\{\mathbf{z_s}_j, \mathbf{z_t}_j\}_{j=1}^M$ jointly using AdamW [S2].

### Inference Optimization
Given a single unposed reference image of an unseen object, CodeNeRF reconstructs the object and estimates its viewpoint [S2].

1.  **Initialization:**
    *   Network weights $\Theta$ are fixed (pre-trained) [S2].
    *   Latent vectors $\mathbf{z_s}, \mathbf{z_t}$ are initialized with the mean vector of the trained embeddings [S2].
    *   Camera parameters $(\phi, \theta, \rho)$ are initialized with large errors (average 80 degrees rotation error from ground truth) [S2].
2.  **Joint Optimization:** Minimize the photometric loss and regularization term with respect to $\mathbf{z_s}, \mathbf{z_t}$ and camera parameters $(\phi, \theta, \rho)$ [S2]:

    $$ \min_{\mathbf{z_s}, \mathbf{z_t}, \phi, \theta, \rho} \mathcal{L}(\mathbf{z_s}, \mathbf{z_t}, \phi, \theta, \rho) + \frac{1}{\nu^2} (||\mathbf{z_s}||_2^2 + ||\mathbf{z_t}||_2^2) $$

3.  **Iteration:** Run optimization for 299 iterations [S2].

### Parameters
*   **Positional Encoding Frequencies:** 10 for $\mathbf{x}$, 4 for $\mathbf{d}$ [S2].
*   **Optimizer:** AdamW [S2].
*   **Learning Rates (Training):**
    *   Network parameters $\Theta$: $1 \times 10^{-4}$ [S2].
    *   Latent vectors $\mathbf{z_s}, \mathbf{z_t}$: $1 \times 10^{-3}$ [S2].
*   **Learning Rates (Inference):**
    *   Latent vectors $\mathbf{z_s}, \mathbf{z_t}$: $1 \times 10^{-2}$ [S2].
    *   Camera azimuth $\phi$: $1 \times 10^{-2}$ [S2].
    *   Camera elevation $\theta$: $1 \times 10^{-1}$ [S2].
    *   Camera distance $\rho$: $1 \times 10^{-1}$ [S2].
*   **Regularization Weight:** $1/\nu^2$. Value of $\nu$ not explicitly given in the sources.
*   **Samples per Ray:** 64 [S2].
*   **Rays per Image (Training):** 4094 [S2].
*   **Inference Iterations:** 299 [S2].

### Edge Cases and Pitfalls
*   **Camera Initialization:** Initial camera pose estimates can have rotation errors above 30 degrees (average 80 degrees from ground truth). The optimization must be robust to this; it converged in 85% of cases in experiments [S2].
*   **Disentanglement Failure:** If the architecture is modified to input viewing direction into the shape network (M1) or use a single embedding for shape and texture (M2), disentanglement fails. M1 synthesizes incorrect textures, and M2 causes unwanted shape changes during texture editing [S2].
*   **No 3D Supervision:** The model is trained end-to-end from images only, without 3D ground truth supervision, relying on multi-view photometric consistency [S2].

## Operating characteristics
*   **Time Complexity:** Training involves optimizing network weights and latent codes for all objects in the category. Inference requires iterative optimization (299 iterations) per unseen object to find latent codes and camera pose [S2].
*   **Memory Complexity:** Requires storing latent embeddings for each object in the training set ($M$ objects) [S2].
*   **Performance:** On the ShapeNet-SRN benchmark, CodeNeRF achieves competitive PSNR and SSIM scores for novel view synthesis and few-shot reconstruction compared to methods like SRN, PixelNeRF, and GRF [S2].
*   **Strengths:**
    *   Disentangles shape and texture, allowing independent editing [S2].
    *   Does not require known camera pose at inference time [S2].
    *   Generalizes well to unseen objects from a single image [S2].
*   **Limitations:**
    *   Requires training on a category of objects first [S2].
    *   Convergence is not guaranteed (85% success rate in pose estimation) [S2].

## Background
CodeNeRF was introduced at ICCV 2021 [S2]. It builds on the original NeRF and takes inspiration from SRN and DeepSDF. It addresses the limitation of NeRF being scene-specific by learning a category-level representation. It is used for single-view reconstruction, novel view synthesis, and shape/texture editing on datasets like ShapeNet-SRN (cars and chairs) [S2].
