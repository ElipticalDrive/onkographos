# Tile and Slide Framework

Also called: Snake-NeRF

## Overview
The Tile and Slide Framework (Snake-NeRF) is an out-of-core method that scales Neural Radiance Fields (NeRFs) to large-scale Earth observation scenes (e.g., 10km x 10km) by partitioning the region of interest into non-overlapping 3D tiles, each trained with its own independent NeRF [S1]. It operates on a single GPU without loading all images or networks simultaneously, solving the memory bottleneck that prevents standard NeRFs from handling terabytes of satellite imagery [S1]. Unlike NeRF-XL, which dispatches NeRFs to multiple GPUs, this framework ensures scalability by strictly adhering to a fixed memory budget and linear time complexity through a sliding window training strategy [S1].

## How it works
The method addresses the "Catastrophic Forgetting" problem, where training a single NeRF sequentially on spatial subsets of rays causes the model to lose information about previously seen domains [S1]. To prevent this, the scene is divided into non-overlapping NeRFs, ensuring that once a tile is trained, its learned information remains persistent [S1].

### Inputs and Outputs
*   **Inputs:** A set of $N_{im}$ satellite images covering a Region of Interest (ROI) with surface area $A_{ROI}$ and spatial resolution $SR$ (pix/m). Each image provides Rational Polynomial Coefficients (RPCs) for ray origin and direction computation [S1].
*   **Outputs:** A set of non-overlapping NeRF models, one per 3D tile, capable of rendering the scene seamlessly [S1].

### Data Structures
The scene is partitioned using a **Tiling Strategy**:
*   **Layout:** A square grid aligned with East/North directions (UTM coordinates) [S1].
*   **Geometry:** The tiles are 3D bounding boxes. For satellite imagery, the Z-variation is extremely low ($\approx 200$m) compared to the X/Y dimensions ($\approx 10$km) [S1].
*   **Model Architecture:** Each tile uses a NeRF implementation compatible with multi-resolution hash tables for geometry encoding and a global color network, as used in NeRF-XL [S1].

### Numbered Steps

1.  **Scene Partitioning:** Divide the 3D ROI into non-overlapping 3D tiles based on the UTM-aligned square grid. Each tile corresponds to a distinct NeRF model [S1].
2.  **Image Cropping:** Crop the input satellite images with overlap to ensure that every NeRF receives all necessary pixels for its specific spatial domain [S1].
3.  **Ray Computation:** Compute ray origins and directions on-the-fly using the RPCs of the cropped images. This avoids storing the full ray dataset in memory [S1].
4.  **Segmented Sampling:** Use a segmented sampler that samples per-bounding box rather than along the entire ray. This guarantees seamless rendering for rays intersecting multiple bounding boxes [S1].
5.  **Sliding Window Training:** Employ a $2 \times 2$ 3D tile progression strategy (sliding window). This ensures that each ray is used at least once in a training batch with all necessary NeRFs currently loaded in memory [S1].
6.  **Optimization:** Train each NeRF independently on its assigned tiles. Because the tiles are non-overlapping and the sliding window manages memory, no catastrophic forgetting occurs [S1].

### Formulas
The total input size $N$ (number of pixels) is defined as:
$$ N = N_{im} \times A_{ROI} \times SR^2 $$
Where:
*   $N_{im}$: Number of images [S1].
*   $A_{ROI}$: Surface area of the region of interest [S1].
*   $SR$: Spatial Resolution in pixels per meter (pix/m) [S1].

### Parameters
*   **Typical Scene Size:** 10km by 10km [S1].
*   **Ground Sample Distance (GSD):** 30cm [S1].
*   **Number of Images:** 20 satellite images [S1].
*   **Scalability Conditions:**
    1.  Time complexity: $O(N)$ [S1].
    2.  Memory complexity: $O(1)$ (fixed memory budget) [S1].
    3.  Quality preservation: $A_s(x) \approx A(x)$, where $A_s$ is the tiled algorithm and $A$ is the reference untiled algorithm [S1].

### Pseudocode
```python
# Snake-NeRF Training Loop
# Assumes:
# - scene_roi: 3D bounding box of the entire area
# - images: List of image data with RPCs
# - tile_size: Dimensions of a single 3D tile
# - gpu_memory_budget: Maximum memory available on single GPU

def train_snake_nerf(scene_roi, images, tile_size, gpu_memory_budget):
    # 1. Partition scene into non-overlapping tiles
    tiles = partition_scene_into_tiles(scene_roi, tile_size)
    
    # 2. Initialize a dictionary to store trained NeRFs
    trained_nerfs = {}

    # 3. Define the 2x2 sliding window progression
    # The window moves across the tile grid. 
    # At each step, we load the NeRFs corresponding to the 2x2 window.
    window_progression = get_2x2_window_progression(tiles)

    for window in window_progression:
        # 'window' is a list of 4 tile IDs currently in the sliding window
        
        # Load the 4 NeRFs for the current window into GPU memory
        current_nerfs = load_nerfs_into_gpu(window, trained_nerfs, gpu_memory_budget)
        
        # For each NeRF in the window, train on its specific tile domain
        for tile_id, nerf in current_nerfs.items():
            # Crop images relevant to this tile
            cropped_images = crop_images_with_overlap(images, tile_id)
            
            # Train the NeRF on the cropped images
            # Ray coordinates are computed on-the-fly from RPCs
            train_nerf(nerf, cropped_images, compute_rays_on_the_fly)
            
            # Mark this NeRF as trained so it persists if evicted later
            trained_nerfs[tile_id] = nerf

    return trained_nerfs

def compute_rays_on_the_fly(image, rpcs):
    # Compute ray origins and directions using Rational Polynomial Coefficients
    # Returns ray origins and directions without storing them in a large array
    origins = []
    directions = []
    for pixel in image:
        origin, direction = rpcs_to_ray(rpcs, pixel)
        origins.append(origin)
        directions.append(direction)
    return origins, directions
```

### Edge Cases and Pitfalls
*   **Catastrophic Forgetting:** Training a single NeRF sequentially on subsets of rays $R_i$ causes loss of information on previously seen domains $R_j$ ($j < i$) [S1]. This is avoided by using non-overlapping NeRFs [S1].
*   **Memory Overflow:** A typical scene (10km x 10km, 30cm GSD, 20 images) requires 200GB for images, ~600GB for the NeRF, and 1.4TB for ray vectors (float32), totaling ~2.2TB, which exceeds single GPU memory [S1]. The on-the-fly ray computation and tiling solve this [S1].
*   **Edge Artifacts:** Rays intersecting multiple bounding boxes can cause seams. The segmented sampler (per-bounding box sampling) prevents this [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to input size $N$, i.e., $O(N)$ [S1].
*   **Memory Complexity:** Constant with respect to input size, i.e., $O(1)$, bounded by the fixed GPU memory budget [S1].
*   **Hardware:** Designed for a single GPU device [S1].
*   **Scalability:** Successfully scales to 10km x 10km scenes with 20 satellite images [S1].
*   **Strengths:** Eliminates the need to load all images and networks simultaneously; prevents catastrophic forgetting; maintains quality comparable to a single large NeRF [S1].
*   **Limitations:** Requires careful tiling and cropping; relies on specific scene characteristics (e.g., low Z-variation for satellite imagery) [S1].
*   **When to use:** Large-scale Earth observation (satellite, airborne, UAV) where memory constraints prevent training a single global NeRF [S1].
*   **When not to use:** Small scenes where a single NeRF fits in memory; scenes with high Z-variation where the 2D-aligned tiling strategy may be less efficient [S1].

## Background
The Tile and Slide Framework, also known as Snake-NeRF, was introduced to address the limitations of existing NeRF methods in handling large-scale 3D mapping of the Earth [S1]. Previous work on large-scale NeRFs, such as Kilo-NeRF and NeRF-XL, either required pre-trained models or distributed training across multiple GPUs [S1]. Snake-NeRF distinguishes itself by operating on a single GPU and using an out-of-core approach [S1]. It builds on the principles of spatial discretization and feature storage shared by voxel-based representations [Parent](13738-voxel-and-sparse-grid-representations.md). The method was developed in the context of remote sensing and Earth observation, aiming to enable high-resolution 3D reconstruction of vast areas using multi-view satellite imagery [S1].
