# UE4-NeRF


## Overview
UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale 3D scenes by partitioning environments into sub-NeRFs represented as textured polygonal meshes [S1]. It integrates these neural models into the Unreal Engine 4 (UE4) rasterization pipeline, enabling real-time performance at 4K resolution (up to 43 FPS) while supporting scene editing with traditional 3D assets [S1]. Unlike standard NeRFs that rely on volumetric ray-marching, UE4-NeRF uses a mesh-based representation optimized for GPU parallelism, addressing the slow convergence and transparency handling limitations of prior mobile-focused methods like Mobile-NeRF [S1].

## How it works
UE4-NeRF operates by dividing a large-scale scene into overlapping blocks, training a separate neural model for each block to generate a textured polygonal mesh, and rendering these meshes in real-time within UE4 [S1].

### Inputs and Outputs
**Inputs:**
- A set of posed images captured by a drone or camera, typically with GPS metadata [S1].
- Camera poses $(o, d)$, where $o$ is the origin and $d = (\theta, \phi)$ is the viewing direction [S1].
- Scene bounding box defined by the partitioning strategy [S1].

**Outputs:**
- Textured polygonal meshes for each block, containing feature vectors and opacity information in texture atlases [S1].
- Real-time rendered color images $\mathbf{c}$ for given camera viewpoints [S1].

### Data Structures and Layouts
The method relies on specific network architectures and mesh structures:

1.  **Encoder Network ($E$):** A 4-layer Multi-Layer Perceptron (MLP) [S1].
    -   Input: Hash-encoded position $p_i$ [S1].
    -   Layers: $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
    -   Output: Opacity $\alpha_i$ and an 8-dimensional feature vector $M_i$ [S1].

2.  **Decoder Network ($D$):** A 3-layer MLP implemented as an HLSL fragment shader in UE4 [S1].
    -   Input: Feature vector $M_i$ and directional encoding $SH(d_i)$ [S1].
    -   Layers: $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
    -   Output: Final color $\mathbf{c}_i$ [S1].

3.  **Mesh Structure:**
    -   Initialized from a $128 \times 128 \times 128$ grid [S1].
    -   Vertices are selected from the center point of each grid cell and its six neighbors (front, back, left, right, top, bottom) [S1].
    -   Faces are formed as regular octahedra, consisting of 20 faces total (8 exterior, 12 interior) [S1].
    -   Texture atlas stores the feature vectors $M_i$ and opacity $\alpha_i$ [S1].

4.  **Encoding:**
    -   Multi-resolution hash encoding from Instant-NGP is used for input position $p_i$ [S1].
    -   Spherical Harmonics (SH) are used for viewing direction $d_i$ [S1].

### Numbered Steps

1.  **Coordinate Transformation:**
    -   Apply UE4 coordinate system: X-axis points East, Y-axis points South, Z-axis points Up [S1].
    -   Apply scale conversion: 100:1 (UE4 units to real-world units) [S1].

2.  **Block Partitioning:**
    -   Partition the large-scale scene into multiple blocks (sub-NeRFs) [S1].
    -   Ensure each training area is slightly larger than the corresponding scene area to create overlapping borders with neighboring blocks for smooth transitions [S1].
    -   Train a coarse model for sub-region segmentation to capture overall terrain and building outlines [S1].
    -   Filter images associated with sub-regions and use a mask to exclude pixels outside the scene area [S1].

3.  **Mesh Initialization:**
    -   Initialize a $128 \times 128 \times 128$ grid for each block [S1].
    -   Select center points of each grid and their six neighbors to create polygonal meshes [S1].
    -   Use regular octahedra (20 faces: 8 exterior, 12 interior) to address slow/unstable convergence on tilted surfaces [S1].

4.  **Training (Optimization):**
    -   For each ray $r(t) = o + td$ emitted from the camera origin, calculate its intersection with the polygonal meshes [S1].
    -   The intersection point serves as the sampling point [S1].
    -   Optimize vertex positions continuously during training [S1].
    -   Optimize Encoder ($E$) and Decoder ($D$) parameters [S1].
    -   The Encoder predicts opacity $\alpha_i$ and feature vector $M_i$:
        $$ E(\text{hash}(p_i); \theta_E) \rightarrow M_i, \alpha_i $$
    -   The Decoder predicts color $\mathbf{c}_i$:
        $$ D(M_i, SH(d_i); \theta_D) \rightarrow \mathbf{c}_i $$
    -   Train for 80,000 epochs per block to achieve convergence [S1].
    -   Implement computationally intensive portions using CUDA to utilize GPU parallel computing [S1].

5.  **LOD (Level of Detail) Generation:**
    -   Train meshes with varying levels of detail for different observation heights [S1].
    -   Coarser meshes are used for higher observation heights to ensure real-time performance [S1].
    -   Extract pre-rendered polygonal meshes at different levels of detail for the final rendering module [S1].

6.  **Rendering:**
    -   Combine extracted meshes with the UE4 rasterization pipeline [S1].
    -   Deploy the neural shader (Decoder MLP) in HLSL within UE4 [S1].
    -   The shader takes feature vectors from the texture atlas as input and outputs colors [S1].
    -   For scene editing, import traditional 3D models (.obj, .fbx); UE4 handles occlusion, skipping neural shader computation for occluded regions [S1].

### Pseudocode

```python
# UE4-NeRF Implementation Logic

def ue4_nerf_pipeline(images, poses, scene_bounds):
    """
    Main pipeline for UE4-NeRF.
    """
    # 1. Coordinate Transformation
    # UE4: X=East, Y=South, Z=Up. Scale 100:1.
    transformed_images, transformed_poses = apply_coordinate_transform(images, poses, scale=100)

    # 2. Block Partitioning
    blocks = partition_scene(scene_bounds, overlap=True)
    
    trained_blocks = []
    for block_id, block in enumerate(blocks):
        # Filter images for this block
        block_images = filter_images(transformed_images, block.mask)
        block_poses = filter_poses(transformed_poses, block.mask)
        
        # 3. Mesh Initialization
        # Initialize 128x128x128 grid
        grid = initialize_grid(size=128)
        # Create octahedra meshes from grid centers and neighbors
        mesh = create_octahedra_mesh(grid)
        
        # 4. Training
        # Encoder: 4-layer MLP (32->64->64->64->8)
        # Decoder: 3-layer MLP (17->16->16->3)
        # Hash Encoding for position, SH for direction
        encoder = EncoderMLP(layers=[32, 64, 64, 64, 8])
        decoder = DecoderMLP(layers=[17, 16, 16, 3])
        
        # CUDA-accelerated training loop
        for epoch in range(80000):
            for image, pose in zip(block_images, block_poses):
                # Ray generation
                rays = generate_rays(pose, image.resolution)
                
                # Ray-Mesh Intersection
                intersections = ray_mesh_intersection(rays, mesh)
                
                # Forward Pass
                # Hash encode position
                hash_pos = hash_encode(intersections.position)
                # Encode direction with SH
                sh_dir = spherical_harmonics_encode(intersections.direction)
                
                # Encoder: Output feature vector M and opacity alpha
                M, alpha = encoder(hash_pos)
                
                # Decoder: Output color c
                # Note: Input to decoder is M concatenated with SH components
                # The source specifies input dim 17, M is 8, SH is likely 9 (L=2)
                color = decoder(concatenate(M, sh_dir))
                
                # Loss Calculation (e.g., MSE against image pixel)
                loss = compute_loss(color, image.pixel)
                
                # Backpropagation
                update_parameters(encoder, decoder, loss)
                
                # Vertex Optimization
                optimize_mesh_vertices(mesh, loss)
        
        # 5. LOD Extraction
        lod_meshes = extract_lod_meshes(mesh, encoder, decoder)
        trained_blocks.append((block_id, lod_meshes))
        
    return trained_blocks

def render_in_ue4(trained_blocks, camera_pose):
    """
    Real-time rendering in Unreal Engine 4.
    """
    # Select appropriate LOD based on camera height
    mesh = select_lod(trained_blocks, camera_pose.height)
    
    # Rasterization pipeline
    # The neural shader (Decoder) is executed as an HLSL fragment shader
    # Input: Feature vectors from texture atlas
    # Output: Color
    rendered_image = rasterize(mesh, camera_pose, neural_shader=decoder)
    
    return rendered_image
```

### Parameters and Typical Values
-   **Grid Initialization Size:** $128 \times 128 \times 128$ [S1].
-   **Octahedron Faces:** 20 faces total (8 exterior, 12 interior) [S1].
-   **Encoder MLP Dimensions:** $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
-   **Decoder MLP Dimensions:** $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
-   **Training Hardware:** 1 Nvidia RTX 3090 GPU [S1].
-   **Training Iterations:** 80,000 epochs per block [S1].
-   **Training Time:** ~40 minutes per block on 1×RTX 3090 [S1].
-   **Coordinate System:** X=East, Y=South, Z=Up [S1].
-   **World Scale:** 100:1 [S1].
-   **Evaluation Metrics:** PSNR, SSIM, LPIPS [S1].

### Edge Cases and Pitfalls
-   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces; UE4-NeRF mitigates this by using regular octahedra [S1].
-   **Transparency:** Mobile-NeRF cannot handle transparent/semi-transparent objects (water, glass, plastic) due to opacity binarization; UE4-NeRF stores opacity in texture maps to mitigate this [S1].
-   **Performance:** Semi-transparent objects (e.g., vegetation) increase computational overhead, reducing frame rates [S1].
-   **Pre-rendering Gaps:** Pre-rendering cannot capture rays from all viewing angles, resulting in gaps or holes in the final rendered scene [S1].
-   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, causing evaluation metrics (PSNR/SSIM) to underestimate actual reconstruction quality [S1].
-   **Memory:** Requires CUDA and NVIDIA GPUs; rendering large scenes (square kilometers) incurs significant memory overhead, which increases with accuracy [S1].

## Subtopics

### Block-NeRF
A method that partitions large scenes into grid-structured sub-NeRFs. UE4-NeRF is generally suitable for various scene types (e.g., mountainous terrain) unlike Block-NeRF which is limited to grid structures. [Block-NeRF](11916-block-nerf.md)

### Mobile-NeRF
A method for real-time NeRF on mobile devices using binary opacity. UE4-NeRF improves upon Mobile-NeRF by handling tilted surfaces with octahedra and supporting semi-transparency via texture maps, while being significantly faster to train. [Mobile-NeRF](11916-mobile-nerf.md)

### Mega-NeRF
A method for large-scale NeRF using multiple models. UE4-NeRF trains ~54× faster per block than Mega-NeRF and achieves higher FPS at higher resolutions without significant blur. [Mega-NeRF](11916-mega-nerf.md)

### Instant-NGP
A method using multi-resolution hash encoding for training acceleration. UE4-NeRF employs this encoding to accelerate training. [Instant-NGP](11916-instant-ngp.md)

## Operating characteristics
-   **Training Speed:** 1000× faster than Mobile-NeRF [S1].
-   **Training Time:** 40 minutes per block on 1×RTX 3090; 1 hour + (40 minutes × n/4) for a full scene with n blocks [S1].
-   **Rendering Performance:** Real-time rendering at 4K resolution with up to 43 FPS [S1]. 50 FPS on full scene at 2K resolution; ≥70 FPS on individual blocks at 2K resolution [S1].
-   **Memory:** Significant memory overhead for large scenes (square kilometers); increases with accuracy [S1].
-   **Hardware Requirements:** Requires CUDA and NVIDIA GPUs [S1].
-   **Strengths:** Real-time interactive rendering of large-scale scenes; supports scene editing with traditional 3D models; handles semi-transparent objects; high fidelity on small objects and dense textures [S1].
-   **Limitations:** Pre-rendering gaps/holes; exposure matching issues in UE4; reduced frame rates with semi-transparent objects; dependency on NVIDIA GPUs [S1].
-   **When to Use:** Real-time interactive rendering of large-scale outdoor scenes (farmland, construction sites, industrial parks) where high fidelity and editability are required [S1].
-   **When Not to Use:** Scenes requiring precise exposure matching with original images without post-processing; environments with extreme semi-transparency where frame rate is critical; non-NVIDIA hardware environments [S1].

## Background
UE4-NeRF was introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" [S1]. It was developed to address the limitations of NeRF in real-time interactive rendering of large-scale scenes, such as those captured by drones [S1]. The method combines NeRF with the Unreal Engine 4 (UE4) rasterization pipeline, leveraging Level of Detail (LOD) techniques and multi-resolution hash encoding [S1]. It is used for real-time interactive rendering and scene editing/manipulation in UE4, evaluated on drone-captured large-scale scenes and the Mega-NeRF public dataset [S1].
