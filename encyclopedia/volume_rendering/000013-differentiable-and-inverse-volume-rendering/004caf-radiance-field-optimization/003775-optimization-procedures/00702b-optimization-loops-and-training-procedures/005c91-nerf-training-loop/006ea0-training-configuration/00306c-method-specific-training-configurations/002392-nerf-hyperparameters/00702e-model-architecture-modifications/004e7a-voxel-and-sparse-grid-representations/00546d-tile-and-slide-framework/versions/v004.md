# Tile and Slide Framework

Also called: Snake-NeRF

## Overview
The Tile and Slide Framework (Snake-NeRF) is an out-of-core method that scales Neural Radiance Fields (NeRFs) to large-scale Earth observation scenes (e.g., 10km × 10km) by partitioning the region of interest into non-overlapping 3D tiles, each trained with its own independent NeRF [S1]. It solves the memory bottleneck of large-scene training by ensuring that only a fixed subset of images and networks resides in GPU memory at any time, operating on a single device without loading the entire dataset [S1]. Unlike multi-GPU dispatch methods such as NeRF-XL, this framework guarantees seamless rendering across tile boundaries through a specific 2×2 sliding window progression and a segmented ray sampler, preventing the 3D reconstruction errors that typically arise at domain edges [S1].

## How it works
The method replaces the single global NeRF with a set of local NeRFs, each responsible for a specific spatial tile. The training process is designed to satisfy three scalability conditions: linear time complexity with respect to input pixels, constant memory usage relative to the scene size, and rendering quality equivalent to a reference untiled algorithm [S1].

### Inputs and Outputs
*   **Inputs:** A set of $N_{im}$ satellite images covering a Region of Interest (ROI) with surface area $A_{ROI}$ and spatial resolution $SR$ (pixels/meter). The total input size is defined as $N = N_{im} \times A_{ROI} \times SR^2$ [S1]. Each image is associated with Rational Polynomial Coefficients (RPCs) for geometric projection [S1].
*   **Outputs:** A collection of trained NeRF models, one per tile, which can be rendered independently or stitched together for global synthesis [S1].

### Data Structures
The scene is partitioned into a square grid aligned with East/North directions (UTM coordinates) [S1].
*   **Tiles:** Non-overlapping 3D bounding boxes. The Z-dimension variation is small (e.g., ≈200m) compared to X/Y (e.g., ≈10km) [S1].
*   **NeRFs:** Each tile contains a separate NeRF instance. The implementation uses multi-resolution hash tables to encode geometry combined with a global color network, following the architecture of NeRF-XL [S1].
*   **Image Cropping:** Input images are cropped with overlap to ensure that every NeRF receives all necessary pixel data for its domain [S1].

### Numbered Steps
1.  **Scene Partitioning:** Divide the ROI into a grid of non-overlapping tiles aligned with UTM coordinates [S1].
2.  **Image Cropping:** For each tile, crop the input images to include the field of view relevant to that tile, including an overlap margin to cover boundary rays [S1].
3.  **Sliding Window Progression:** Implement a 2×2 3D tile progression strategy (sliding window) [S1]. This ensures that during training, any given ray is processed in a batch where all necessary NeRFs (those intersecting the ray's path) are loaded into memory [S1].
4.  **Ray Computation:** Compute ray origins and directions on-the-fly using the RPCs of the current images, rather than pre-storing them [S1].
5.  **Segmented Sampling:** Use a segmented sampler that samples per-bounding box rather than along the entire ray length [S1]. This guarantees that rays intersecting multiple bounding boxes are sampled correctly within each tile's domain, ensuring seamless rendering [S1].
6.  **Training:** Train each NeRF independently using the cropped images and segmented samples. Because tiles are non-overlapping and trained sequentially or in parallel with isolated memory, catastrophic forgetting is avoided [S1].

### Formulas
The total input size $N$ is calculated as:
$$
N = N_{im} \times A_{ROI} \times SR^2
$$
where:
*   $N_{im}$ is the number of images.
*   $A_{ROI}$ is the surface area of the region of interest.
*   $SR$ is the spatial resolution in pixels per meter [S1].

The scalability conditions are:
1.  Time complexity: $O(N)$ [S1].
2.  Memory complexity: $O(1)$ (fixed memory budget) [S1].
3.  Quality equivalence: $A_s(x) \approx A(x)$, where $A_s$ is the tiled algorithm and $A$ is the reference algorithm [S1].

### Parameters
*   **Typical Scene Size:** 10km × 10km area [S1].
*   **Resolution:** 30cm Ground Sample Distance (GSD) [S1].
*   **Image Count:** 20 satellite images [S1].
*   **Architecture:** Multi-resolution hash tables for geometry + global color network [S1].

### Edge Cases and Pitfalls
*   **Catastrophic Forgetting:** Training a single NeRF sequentially on subsets of rays $R_i$ causes the loss of information on previously seen domains $R_j$ ($j < i$) [S1]. This is mitigated by using non-overlapping NeRFs, ensuring learned information is persistent [S1].
*   **Boundary Artifacts:** Rays intersecting multiple tiles can cause discontinuities if sampled globally. The segmented sampler resolves this by restricting sampling to the bounding box of the active NeRF [S1].
*   **Memory Limits:** Pre-computing ray origins/directions for a 10km × 10km scene at 30cm GSD with 20 images requires ~1.4TB of float32 storage, which exceeds single-GPU capacity [S1]. On-the-fly computation is required [S1].

### Pseudocode
```python
# Snake-NeRF Training Loop
# Assumes:
# - scene_roi: 3D bounding box of the entire area
# - images: List of image data and their RPCs
# - tile_size: Dimensions of a single tile in world coordinates
# - num_tiles_x, num_tiles_y: Grid dimensions

def train_snake_nerf(scene_roi, images, tile_size, num_tiles_x, num_tiles_y):
    # 1. Partition scene into non-overlapping tiles
    tiles = generate_tile_grid(scene_roi, tile_size, num_tiles_x, num_tiles_y)
    
    # 2. Pre-crop images for each tile to ensure coverage
    # This creates a mapping: tile_id -> list of (cropped_image, rpcs)
    tile_image_data = {}
    for tile in tiles:
        tile_image_data[tile.id] = crop_images_for_tile(images, tile.bbox)

    # 3. Initialize NeRFs for each tile
    # Architecture: Multi-resolution hash tables + global color network
    nerfs = {tile.id: init_nerf() for tile in tiles}

    # 4. Sliding Window Training
    # Iterate through 2x2 windows of tiles
    for y in range(0, num_tiles_y - 1):
        for x in range(0, num_tiles_x - 1):
            # Define the 2x2 window of tiles
            window_tiles = [
                tiles[y * num_tiles_x + x],
                tiles[y * num_tiles_x + x + 1],
                tiles[(y + 1) * num_tiles_x + x],
                tiles[(y + 1) * num_tiles_x + x + 1]
            ]
            
            # Load only the NeRFs in the current window into GPU memory
            active_nerfs = {t.id: nerfs[t.id] for t in window_tiles}
            
            # Get images relevant to this window
            window_images = merge_image_data([tile_image_data[t.id] for t in window_tiles])
            
            # Train the active NeRFs
            for tile in window_tiles:
                train_tile_nerf(
                    nerf=active_nerfs[tile.id],
                    images=window_images,
                    tile_bbox=tile.bbox,
                    rpcs=window_images.rpcs
                )

def train_tile_nerf(nerf, images, tile_bbox, rpcs):
    # Sample rays using segmented sampler
    # For each ray, compute origin/direction on-the-fly from RPCs
    # Sample only within the tile's bounding box
    rays = generate_segmented_rays(images, tile_bbox, rpcs)
    
    # Render and compute loss
    for ray in rays:
        # Segmented sampling: restrict sample points to tile_bbox
        samples = sample_along_ray(ray, tile_bbox)
        
        # Query features from the NeRF (hash table lookup)
        densities, colors = nerf.query(samples)
        
        # Volume rendering
        color = volume_render(densities, colors)
        
        # Compute loss against ground truth pixel
        loss = compute_loss(color, ray.gt_color)
        
        # Backpropagate
        nerf.update(loss)

def generate_segmented_rays(images, tile_bbox, rpcs):
    rays = []
    for img, img_rpcs in zip(images, rpcs):
        # Compute ray origins and directions on-the-fly
        ray_origins, ray_directions = compute_rays_from_rpcs(img, img_rpcs)
        
        # Filter rays that intersect the tile bounding box
        intersecting_rays = filter_rays_intersecting_bbox(ray_origins, ray_directions, tile_bbox)
        
        for origin, direction in intersecting_rays:
            rays.append({
                'origin': origin,
                'direction': direction,
                'gt_color': get_pixel_color(img, origin, direction)
            })
    return rays
```

## Subtopics

### Voxel-based Radiance Fields
Uses dense or sparse voxel grids for feature storage. Choose when high-frequency geometric detail is needed and memory allows for dense storage, or when using sparse structures like Octree-NeRF. Link: [Voxel-based Radiance Fields](11470-voxel-based-radiance-fields.md).

### Neural Multi-View Image Reconstruction with Hash Encoding
Uses multi-resolution hash tables for compact feature storage. Choose when memory is constrained but high resolution is required, as in Snake-NeRF's architecture. Link: [Neural Multi-View Image Reconstruction with Hash Encoding](13013-neural-multi-view-image-reconstruction-with-hash-encoding.md).

### G-NeLF
Incorporates geometric priors or constraints. Choose when explicit geometric guidance improves reconstruction quality in complex scenes. Link: [G-NeLF](13480-g-nelf.md).

### SCALAR-NeRF
Uses scalar fields for density representation. Choose when a simpler, scalar-based density model is sufficient for the scene complexity. Link: [SCALAR-NeRF](14267-scalar-nerf.md).

### TriDF
Uses triplane representations. Choose for planar or limited-depth scenes where 2D plane projections are more efficient than 3D volumes. Link: [TriDF](14761-tridf.md).

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of input pixels $N$, i.e., $O(N)$ [S1].
*   **Memory Complexity:** Constant with respect to scene size, i.e., $O(1)$, as it only loads a 2×2 window of tiles and their associated images into GPU memory [S1].
*   **Measured Performance:** Tested on a 10km × 10km scene at 30cm GSD with 20 satellite images [S1].
*   **Hardware:** Operates on a single GPU [S1].
*   **Strengths:** Eliminates the need to load all images and networks simultaneously; prevents catastrophic forgetting by using non-overlapping NeRFs; ensures seamless rendering via segmented sampling and sliding window progression [S1].
*   **Limitations:** Requires careful tiling and cropping; performance depends on the efficiency of the underlying NeRF architecture (e.g., hash tables) [S1].
*   **When to Use:** Large-scale Earth observation scenes (satellite, airborne, UAV) where memory constraints prevent training a single global NeRF [S1].
*   **When Not to Use:** Small-scale scenes where a single NeRF fits in memory; scenes with significant Z-variation where the 2D-aligned tiling strategy is less effective [S1].

## Background
The Tile and Slide Framework, also known as Snake-NeRF, was introduced to address the memory footprint limitations of state-of-the-art NeRF methods when applied to large-scale 3D Earth observation [S1]. Previous works on large-scale NeRFs often required multiple GPUs or modified the rendering equation [S1]. This framework was developed to enable out-of-core training on a single GPU by dividing the scene into non-overlapping NeRFs and using a sliding window mechanism to manage memory [S1]. It builds on the use of multi-resolution hash tables for geometry encoding, as seen in NeRF-XL, but adapts it for single-GPU scalability [S1].
