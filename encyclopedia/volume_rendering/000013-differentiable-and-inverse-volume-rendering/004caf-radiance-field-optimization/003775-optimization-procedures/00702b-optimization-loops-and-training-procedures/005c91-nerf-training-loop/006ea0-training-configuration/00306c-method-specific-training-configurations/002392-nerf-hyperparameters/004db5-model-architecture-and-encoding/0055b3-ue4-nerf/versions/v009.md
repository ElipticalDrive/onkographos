# UE4-NeRF


## Overview
UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale 3D scenes by partitioning the environment into sub-NeRFs represented as textured polygonal meshes [S1]. It addresses the computational overhead and lack of real-time capability in standard NeRFs and their mobile variants by integrating a learned neural shader into the Unreal Engine 4 (UE4) rasterization pipeline [S1]. Unlike Block-NeRF, which is limited to grid structures, UE4-NeRF supports diverse terrains (e.g., mountainous, farmland) and handles semi-transparent objects by storing opacity in texture maps rather than binarizing it [S1]. It achieves real-time performance (up to 43 FPS at 4K) by using multi-resolution hash encoding for training acceleration and a Level of Detail (LOD) hierarchy for rendering [S1].

## How it works
**Inputs:**
*   A set of posed images with GPS metadata for a large-scale scene.
*   Camera poses $(\mathbf{o}, \mathbf{d})$ where $\mathbf{o}$ is the origin and $\mathbf{d}$ is the viewing direction.

**Outputs:**
*   A real-time rendered image stream in UE4.
*   Textured polygonal meshes for each scene block.

**Data Structures:**
1.  **Scene Partitioning:** The large scene is divided into $N$ blocks. Each block's training area is slightly larger than the physical scene area to create overlapping borders for smooth transitions [S1].
2.  **Mesh Representation:** Each block is represented by a textured polygonal mesh. The mesh is initialized from a grid and optimized during training. The texture atlas stores an 8-dimensional feature vector and opacity $\alpha$ for each vertex/face [S1].
3.  **LOD Hierarchy:** Multiple levels of mesh detail are generated. Coarser meshes are used for higher observation heights to maintain frame rates [S1].
4.  **Neural Shader:** An HLSL fragment shader implementing the MLP decoder, taking feature vectors as input and outputting RGB color [S1].

**Network Architecture:**
The method uses an Encoder-Decoder network.
*   **Encoder ($E$):** Takes the multi-resolution hash encoded position $\mathbf{p}_i$ and outputs opacity $\alpha_i$ and an 8-dimensional feature vector $\mathbf{M}_i$ [S1].
    *   Structure: 4-layer MLP.
    *   Dimensions: $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
*   **Decoder ($D$):** Takes the feature vector $\mathbf{M}_i$ and the spherical harmonic encoded viewing direction $\text{SH}(\mathbf{d}_i)$ to predict the color $\mathbf{c}_i$ [S1].
    *   Structure: 3-layer MLP.
    *   Dimensions: $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
    *   Note: The input dimension to the decoder is 17, composed of the 8 feature dimensions and 9 spherical harmonic coefficients for the viewing direction [S1].

**Coordinate System and Scale:**
*   UE4 Coordinate System: X-axis points East, Y-axis points South, Z-axis points Up [S1].
*   World Scale: 100:1 (UE4 units to real-world units) [S1].

**Numbered Steps:**

1.  **Block Partitioning:**
    *   Partition the large-scale scene into multiple blocks.
    *   Train a coarse segmentation model to capture overall terrain and building outlines.
    *   Filter images associated with each sub-region and apply a mask to exclude pixels outside the scene area [S1].

2.  **Mesh Initialization:**
    *   Initialize a $128 \times 128 \times 128$ grid for each block [S1].
    *   Select the center point of each grid cell along with its six neighboring grids (front, back, left, right, top, bottom) to form polygonal meshes [S1].
    *   Replace the standard Mobile-NeRF approach with a regular octahedron having 20 faces (8 exterior, 12 interior) to handle tilted surfaces and improve convergence stability [S1].

3.  **Training (Optimization):**
    *   For each ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$, calculate intersections with the polygonal meshes to determine sampling points [S1].
    *   Continuously optimize vertex positions of the meshes during training [S1].
    *   Optimize the parameters of the Encoder-Decoder network ($\theta_E, \theta_D$) using the following forward pass for each sample point $i$:
        $$ \mathbf{M}_i, \alpha_i = E(\text{Hash}(\mathbf{p}_i); \theta_E) $$
        $$ \mathbf{c}_i = D(\mathbf{M}_i, \text{SH}(\mathbf{d}_i); \theta_D) $$
    *   Use multi-resolution hash encoding (from Instant-NGP) for position $\mathbf{p}_i$ to accelerate training [S1].
    *   Implement computationally intensive parts (hash encoding, MLP inference) in CUDA [S1].
    *   Train for 80,000 epochs per block to achieve convergence [S1].

4.  **Shading Mesh Extraction:**
    *   Extract coarse polygonal meshes without textures.
    *   Apply the learned vertex optimizations.
    *   Encode the final texture maps (feature vectors and opacity) into the network outputs [S1].

5.  **Real-Time Rendering in UE4:**
    *   Import the extracted meshes into UE4.
    *   Deploy the neural shader (HLSL fragment shader) which implements the Decoder network.
    *   The shader takes the feature vectors stored in the texture atlas as input and outputs the final color [S1].
    *   Apply LOD: Use coarser meshes for higher observation heights [S1].
    *   Handle occlusion: UE4 rasterization pipeline automatically handles occlusion between imported 3D models (.obj, .fbx) and the NeRF background, skipping neural shader computation for occluded regions [S1].

**Pseudocode:**

```python
# UE4-NeRF Implementation Logic

class UE4NeRF:
    def __init__(self, scene_bounds, grid_size=128):
        self.scene_bounds = scene_bounds
        self.grid_size = grid_size
        # Encoder: 4-layer MLP (32->64->64->64->8)
        self.encoder = MLP(layers=[32, 64, 64, 64, 8])
        # Decoder: 3-layer MLP (17->16->16->3)
        # Input: 8 feature dims + 9 SH coeffs for viewing direction
        self.decoder = MLP(layers=[17, 16, 16, 3])
        # Multi-resolution hash encoding (from Instant-NGP)
        self.hash_encoder = MultiResolutionHashEncoding()
        # Mesh structure: Regular octahedron with 20 faces
        self.mesh = RegularOctahedronMesh(num_faces=20)
        # Texture atlas storing features and opacity
        self.texture_atlas = TextureAtlas()
        
    def train_block(self, images, poses, epochs=80000):
        """
        Train a single block of the scene.
        """
        # 1. Initialize Mesh from Grid
        # Select center and 6 neighbors for each grid cell
        self.mesh.initialize_from_grid(self.grid_size)
        
        # 2. Optimization Loop
        for epoch in range(epochs):
            for image, pose in zip(images, poses):
                # 3. Ray Casting
                rays = generate_rays(pose, image.shape)
                
                # 4. Intersection with Mesh
                # Calculate intersection points p_i and directions d_i
                intersections = self.mesh.intersect(rays)
                
                # 5. Forward Pass (CUDA optimized)
                losses = []
                for p_i, d_i in intersections:
                    # Encode position
                    hash_features = self.hash_encoder.encode(p_i)
                    
                    # Encoder: Output feature vector M_i and opacity alpha_i
                    # Input to encoder is hash_features (dimension 32)
                    M_i, alpha_i = self.encoder(hash_features)
                    
                    # Encode viewing direction using Spherical Harmonics (SH)
                    # SH coefficients for degree 2 (9 coeffs)
                    sh_coeffs = spherical_harmonics(d_i, degree=2)
                    
                    # Concatenate features: 8 (from M_i) + 9 (SH) = 17
                    decoder_input = concatenate([M_i, sh_coeffs])
                    
                    # Decoder: Output color c_i
                    c_i = self.decoder(decoder_input)
                    
                    # Compute loss against ground truth pixel color
                    loss = compute_loss(c_i, image.pixel_color)
                    losses.append(loss)
                
                # Backpropagation
                update_parameters(self.encoder, self.decoder, losses)
                
                # 6. Vertex Optimization
                # Update mesh vertex positions to minimize ray intersection error
                self.mesh.optimize_vertices(intersections)
                
        # 7. Extract Texture Atlas
        # Store final M_i and alpha_i in texture atlas
        self.texture_atlas = self.mesh.extract_texture_atlas()
        
    def render(self, camera_pose, resolution):
        """
        Render a frame using UE4 rasterization pipeline.
        """
        # 1. Select LOD Mesh
        # Choose mesh level based on camera height
        lod_mesh = self.get_lod_mesh(camera_pose.height)
        
        # 2. Rasterization
        # UE4 rasterizes the polygonal mesh
        # For each pixel, the neural shader is invoked
        frame = ue4_rasterize(lod_mesh, camera_pose)
        
        # 3. Neural Shader Execution (HLSL)
        # The shader reads feature vectors from texture_atlas
        # and computes color using the Decoder network
        # This happens per-pixel/fragment in the GPU pipeline
        rendered_frame = self.neural_shader(frame, self.texture_atlas)
        
        return rendered_frame

    def add_object(self, obj_mesh):
        """
        Import traditional 3D model and handle occlusion.
        """
        # UE4 handles occlusion automatically
        # NeRF shader is skipped for occluded regions
        self.scene_objects.append(obj_mesh)
```

**Parameters:**
*   **Grid Initialization Size:** $128 \times 128 \times 128$ [S1].
*   **Octahedron Faces:** 20 total (8 exterior, 12 interior) [S1].
*   **Encoder Layers:** $32 \times 64, 64 \times 64, 64 \times 64, 64 \times 8$ [S1].
*   **Decoder Layers:** $17 \times 16, 16 \times 16, 16 \times 3$ [S1].
*   **Training Hardware:** 1 Nvidia RTX 3090 GPU [S1].
*   **Training Iterations:** 80,000 epochs per block [S1].
*   **World Scale:** 100:1 [S1].
*   **Coordinate System:** X=East, Y=South, Z=Up [S1].

**Edge Cases and Pitfalls:**
*   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces. UE4-NeRF mitigates this by using regular octahedra [S1].
*   **Transparency:** Mobile-NeRF cannot handle transparent/semi-transparent objects (water, glass) due to opacity binarization. UE4-NeRF stores opacity in texture maps, allowing it to handle these materials, though semi-transparent objects (e.g., vegetation) increase computational overhead and reduce frame rates [S1].
*   **Pre-rendering Gaps:** Pre-rendering cannot capture rays from all viewing angles, potentially resulting in gaps or holes in the final scene [S1].
*   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, causing evaluation metrics (PSNR/SSIM) to underestimate actual reconstruction quality [S1].
*   **Memory Overhead:** Rendering large scenes (square kilometers) incurs significant memory overhead, which increases with accuracy [S1].
*   **Hardware Dependency:** Requires CUDA and NVIDIA GPUs [S1].

## Operating characteristics
*   **Training Speed:** 1000× faster than Mobile-NeRF [S1].
    *   Time per block: ~40 minutes on 1×RTX 3090 [S1].
    *   Time for full scene ($n$ blocks): $1 \text{ hour} + (40 \text{ minutes} \times n/4)$ on 1×RTX 3090 [S1].
    *   Comparison: Mobile-NeRF takes 48h/block (4×3090); Mega-NeRF takes 36h/block (1×3090) [S1].
*   **Rendering Performance:**
    *   Real-time rendering at 4K resolution with up to 43 FPS [S1].
    *   50 FPS on full scene at 2K resolution [S1].
    *   $\ge$70 FPS on individual blocks at 2K resolution [S1].
*   **Memory:** Significant memory overhead for large scenes (square kilometers) [S1].
*   **Strengths:**
    *   Real-time interactive rendering of large-scale scenes [S1].
    *   Handles diverse terrains (mountainous, farmland) unlike grid-limited Block-NeRF [S1].
    *   Supports scene editing (importing .obj/.fbx) with automatic occlusion handling [S1].
    *   Handles semi-transparent objects better than Mobile-NeRF [S1].
    *   Accurate rendering of small objects (power lines) and dense textures compared to Mip-NeRF [S1].
*   **Limitations:**
    *   Requires NVIDIA GPUs and CUDA [S1].
    *   Semi-transparent objects (vegetation) reduce frame rates due to computational overhead [S1].
    *   Pre-rendering artifacts (gaps/holes) due to limited viewing angles [S1].
    *   Evaluation metrics may underestimate quality due to exposure matching issues in UE4 [S1].

## Background
UE4-NeRF was introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" [S1]. It was developed to address the limitations of NeRF in real-time rendering of large-scale scenes, specifically targeting applications in virtual reality, computer games, and the Metaverse [S1]. The method builds upon Mobile-NeRF and Block-NeRF but introduces regular octahedra for mesh representation and integrates with the Unreal Engine 4 rasterization pipeline [S1]. It is used for drone-captured large-scale scenes such as farmland, construction sites, and industrial parks, and has been evaluated on the Mega-NeRF public dataset [S1].
