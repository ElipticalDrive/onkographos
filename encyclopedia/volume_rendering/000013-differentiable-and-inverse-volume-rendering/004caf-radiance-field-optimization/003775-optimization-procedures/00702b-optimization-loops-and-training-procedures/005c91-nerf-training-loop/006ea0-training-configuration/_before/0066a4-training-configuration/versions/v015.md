# Training Configuration

Also called: Hyperparameter Configuration, Implementation Parameters, Optimization Configuration, Optimization Setup, Optimizer Settings, Training Details, Training Hyperparameters, Training Settings

## Overview
Training Configuration specifies the hyperparameters, optimization strategies, and architectural settings required to train neural radiance fields or implicit surface representations [S1, S5]. It solves the problem of reproducibly managing the training state by standardizing how models, optimizers, and datasets are initialized and how gradients are applied [S1, S5]. It differs from [Learning Rate Scheduling](2701-learning-rate-scheduling.md) and [Mixed Precision Training](2766-mixed-precision-training.md) by focusing on the structural orchestration of the training state rather than numerical precision or adaptive step sizing [G].

## How it works
The training configuration establishes the execution environment for the optimization loop. It specifies the optimizer type, learning rates, batch sizes, sampling strategies, and loss function weights.

### Inputs and Outputs
*   **Inputs:** Scene data (images, poses), network architecture definition, hyperparameter dictionary (learning rates, batch sizes, iteration counts), and device specification (GPU/CPU) [G].
*   **Outputs:** Trained model weights (MLP parameters, voxel grid values, latent codes) and optionally checkpoints for resume training [S1, S5].

### Data Structures
The configuration is typically stored in a dictionary or object containing:
*   `optimizer`: String identifier (e.g., "Adam", "AdamW", "RMSProp") and parameters (betas, eps, weight decay) [S6, S16].
*   `lr`: Initial learning rate, potentially split by parameter group (e.g., embeddings vs. networks) [S16].
*   `batch_size`: Number of rays or pixels per iteration [S1, S6, S7].
*   `iterations`: Total number of training steps [S3][S16].
*   `loss_weights`: Dictionary mapping loss terms (e.g., L2, SSIM, regularization) to scalar multipliers [S5, S13, S24].
*   `sampling`: Parameters for ray marching (e.g., number of coarse/fine samples, step sizes) [S2, S4].

### Numbered Steps
1.  **Initialization:** Initialize the model parameters (MLP weights, voxel grids, latent codes) using specific schemes (e.g., Gaussian noise for density, specific initialization for alpha values) [S2, S14, S4].
2.  **Optimizer Setup:** Instantiate the optimizer with specified hyperparameters (e.g., Adam with $\beta_1=0.9, \beta_2=0.99, \epsilon=10^{-15}$) [S6][S16].
3.  **Data Loading:** Load training images and camera poses. Create a data loader that samples pixels or rays [S6, S7].
4.  **Iteration Loop:**
    a. Sample a batch of rays/pixels from the training set [S6, S7].
    b. Perform forward pass to render predicted colors [G].
    c. Compute loss (e.g., $L = L_2 + 0.2 \cdot L_{SSIM}$) [S5].
    d. Backpropagate gradients.
    e. Update model parameters using the optimizer [S1, S6].
    f. Apply learning rate schedule if configured [S6][S16].
    g. Apply regularization or pruning if scheduled (e.g., every 300 iterations) [S5, S14].
5.  **Checkpointing:** Save model state periodically for resume training or evaluation [S1, S5].

### Formulas
*   **Loss Function:** $L = L_2 + 0.2 \cdot L_{SSIM}$, where $L_2$ is the L2-loss and $L_{SSIM}$ is the perceptual loss [S5].
*   **Dynamic Frequency Masking (FreeNeRF):** $\alpha_i(t, T, L)$ denotes the $i$-th bit value of the mask $\alpha(t, T, L)$:
    $$
    \alpha_i(t, T, L) = 
    \begin{cases} 
    1 & \text{if } i \le \lfloor \frac{t \cdot L}{T} \rfloor \\
    \frac{t \cdot L}{T} - \lfloor \frac{t \cdot L}{T} \rfloor & \text{if } \lfloor \frac{t \cdot L}{T} \rfloor < i \le \lfloor \frac{t \cdot L}{T} \rfloor + 3 \\
    0 & \text{if } i > \lfloor \frac{t \cdot L}{T} \rfloor + 6
    \end{cases}
    $$
    where $t$ is current iteration, $T$ is total iterations, and $L$ is the tensor component length [S18].
*   **Sampling Step Size:** Points sampling step sizes are set to half of the voxel sizes: $\delta^{(c)} = 0.5 \cdot s^{(c)}$ and $\delta^{(f)} = 0.5 \cdot s^{(f)}$ [S3].

### Parameters with Typical Values
*   **Optimizer:** Adam is most common. Betas: $(0.9, 0.99)$ or $(0.9, 0.999)$ [S6, S7, S14]. Epsilon: $10^{-15}$ [S6][S16].
*   **Learning Rate:** Varies by method. Common values: $10^{-3}$ [S1][S16], $5 \times 10^{-4}$ [S7, S15][S22], $0.1$ for voxel grids [S2].
*   **Batch Size:** Ranges from 1 ray [S10] to 256 rays [S13] to 25,000 rays [S16] or 256 pixels [S6].
*   **Iterations:** 20,000 [S3, S11], 25,000 [S6], 30,000 default [S16], 200,000 [S7, S15].
*   **Weight Decay:** $0.1$ for hash grid values [S6], $2 \times 10^{-5}$ [S14], $10^{-9}$ [S3].

### Edge Cases and Pitfalls
*   **Inaccurate Optical Flow:** Can cause errors in later training phases; handled by disabling multi-sampling and using vanilla sampling with fewer but accurate data points [S7].
*   **Overfitting:** Mitigated by dynamic frequency masking or regularization [S18].
*   **Narrow-Baseline Poses:** COLMAP may struggle; treat camera pose parameters (focal length, parallax offset) as trainable variables [S23, unofficial].
*   **Non-determinism:** GPU hashgrid optimization is nondeterministic; fixing seed does not guarantee bitwise-identical trajectories [G].

### Pseudocode
```python
def train_nerf(model, train_loader, optimizer, scheduler, num_iterations, device):
    model.train()
    for step in range(num_iterations):
        rays, gt_colors = next(train_loader)
        rays = rays.to(device)
        gt_colors = gt_colors.to(device)
        
        pred_colors = model.render(rays)
        
        # Compute L2 loss
        loss = sum((pred_colors[i] - gt_colors[i]) ** 2 for i in range(len(pred_colors))) / len(pred_colors)
        
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        if scheduler is not None:
            scheduler.step()
            
        if step % 1000 == 0:
            # Save model state dict and optimizer state to disk
            pass 
```

### Dynamic Frequency Masking
A technique to mask tensor components (density or appearance feature) based on training iteration to enhance high-frequency details in later stages and mitigate overfitting [S18]. It calculates mask values using integer and fractional parts for smooth transition during training ($t < T$) and returns ones after training ($t \ge T$) [S18]. Introduced in FreeNeRF and used in Few TensoRF [S18]. Pitfall: May struggle with intricate details and hidden angles in complex scenes like 'Drums' [S18].

### NeRF-RPN Training Augmentation and Optimization
Configures training for object detection in NeRFs. Involves random flipping (x, y axes, prob 0.5), random rotation (z-axis, $\pi/2$, prob 0.5), and slight rotation ($\alpha \in [-\pi/18, \pi/18]$, prob 0.5) [S19, unofficial]. Uses AdamW optimizer with LR 0.0003 and weight decay 0.001 [S19, unofficial]. Loss weights: $\lambda = 5.0$ for Eq. (3) and $\lambda = 1.0$ for Eq. (6) [S19, unofficial].

### Batch Size Configuration for Past Rays
Balances performance and efficiency by adjusting the ratio of past task rays ($m_p$) to current task rays ($m_c$) [S20]. $m_p = m_c/2$ is chosen as optimal trade-off (e.g., PSNR 22.14 / MS-SSIM 0.836 on Tanks and Temples/Barn with $m_c=4096$) [S20].

### Particle Removal and Re-sampling
Alternately removes and re-samples particles to manage count and convergence [S21]. Re-sampled count gradually decreases to zero as model converges (e.g., after 10K steps on D-NeRF) [S21].

### Trainable Camera Parameters
Initializes NeRF for structured light fields where camera pose parameters (focal length $f$, parallax offset $\Delta$) are trainable to handle narrow-baseline cases where COLMAP struggles [S23, unofficial].

### Group Shift
A self-supervised regularization technique that shifts the grouping of samples along the ray to assess each point in multiple ways using different groups, imposing consistency on the results [S24]. Shifts the head index $k$ of the first group by $s$ towards the camera, where $s$ is randomly sampled from $\{1, \dots, N_p-1\}$ during training [S24].

### Self-Calibrating NeRF
A method that jointly optimizes the NeRF MLP and input camera poses, bypassing the need for structure-from-motion preprocessing for forward facing scenes [S25, unofficial].

### HDR NeRF Training
A variant of NeRF trained with 32-bit HDR images to produce 3-channel radiance in linear color space, reconciling the color space difference between NeRF (sRGB) and path tracing (linear) [S26]. Achieves higher lighting realism compared to 8-bit LDR NeRF [S26].

## Operating characteristics
*   **Time Complexity:** Training time varies significantly by method and hardware. Typical ranges: 15 minutes [S2], 20 hours [S10], 1-2 days [S12], few hours to one day [S8].
*   **Memory Complexity:** Depends on batch size and model size. GPU memory usage can be ~10.5 GB [S10]. Mixed precision training reduces memory bandwidth requirements [G].
*   **Scaling:** Performance generally increases with more training iterations and larger batch sizes, but with diminishing returns and higher computational cost [S11, S20].
*   **Strengths:** Flexible configuration allows optimization for various scenes and constraints (e.g., sparse views, dynamic scenes) [G].
*   **Limitations:** Hyperparameter tuning is often empirical and method-specific [S1, S14]. Some methods are sensitive to initialization and learning rate schedules [S2, S7].
*   **When to Use:** Standard NeRF optimization requires generic hierarchical sampling with Adam [Parent]. Specific variants (e.g., Mip-NeRF, DONeRF) require tailored configurations [G].

## Background
Originating from early neural radiance field formulations [S1], training configuration has evolved to address challenges in convergence speed, memory efficiency, and generalization. Early methods used simple Adam optimization with fixed learning rates [S1]. Subsequent works introduced adaptive scaling, mixed precision, and dynamic sampling strategies [S2][S18]. The field continues to develop specialized configurations for specific applications like object detection [S19, unofficial], dynamic scenes [S21], and X-ray tomography [S22].
