# SUDS

Also called: SUDS (Scalable Urban Dynamic Scenes), Scalable Urban Dynamic Scenes

## Overview
SUDS is a 4D radiance field representation designed for large-scale dynamic urban scenes, enabling free-viewpoint rendering, semantic decomposition, and 3D scene flow estimation across thousands of videos and millions of frames [S1]. It distinguishes itself from sibling methods by factorizing the scene into three separate multi-resolution hash table branches (static, dynamic, and far-field) and utilizing unlabeled auxiliary signals (sparse LiDAR, 2D optical flow, and DINO descriptors) for supervision, thereby avoiding the need for expensive 3D bounding box or panoptic segmentation annotations [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ordered RGB images from $N$ videos ($vid \in \{1, \dots, N\}$), associated camera poses, aligned sparse LiDAR depth measurements, 2D self-supervised DINO descriptors, and 2D optical flow predictions [S1].
*   **Outputs:** For a query position $\mathbf{x} \in \mathbb{R}^3$, viewing direction $\mathbf{d} \in S^2$, time $t$, and video ID $vid$, the method outputs density $\sigma$, color $\mathbf{c}$, semantic features $\mathbf{\Phi}$, and scene flow $\mathbf{s}$ [S1].

**Data Structures:**
The scene is partitioned into $K$ spatial cells. Each cell contains three multi-resolution hash table branches: Static, Dynamic, and Far-field [S1].
1.  **Static Branch:** Stores 3D spatial voxels $\mathbf{v}_{l,s}$ at $L$ resolution levels. Features are indexed by spatial position [S1].
2.  **Dynamic Branch:** Stores 4D spacetime voxels $\mathbf{v}_{l,d}$ at $L$ resolution levels. Features are indexed by spatial position, time $t$, and video ID $vid$ [S1].
3.  **Far-field Branch:** Stores 3D voxels $\mathbf{v}_{l,e}$ indexed by normalized viewing direction $\mathbf{d}$ and video ID $vid$, modeling the environment map [S1].

Each voxel corner in the hash tables holds a feature vector $\mathbf{f} \in \mathbb{R}^F$, where $F$ is the feature dimension [S1]. Hash collisions are handled via gradient averaging [S1].

**Hash Indexing:**
Indices for voxel corners are computed using specific hash functions [S1]:
$$ i_{l,s} = \text{static\_hash}(\text{space}(\mathbf{v}_{l,s})) $$
$$ i_{l,d} = \text{dynamic\_hash}(\text{space}(\mathbf{v}_{l,d}), \text{time}(\mathbf{v}_{l,d}), vid) $$
$$ i_{l,e} = \text{env\_hash}(\text{dir}(\mathbf{v}_{l,e}), vid) $$
The video ID $vid$ is included in the hash to index separate interpolating functions per video without linear memory growth, but is not used for interpolation [S1].

**Feature Interpolation:**
For a query point, features are looked up at $L$ resolution levels. Linear interpolation is used for the static and far-field branches. Quadlinear interpolation is used for the dynamic 4D branch [S1]. The results from all $L$ levels are concatenated into a feature vector $\mathbf{f} \in \mathbb{R}^{LF}$ [S1].

**Network Backbone and Outputs:**
The concatenated feature vector $\mathbf{f}$ and auxiliary inputs are passed to an MLP.
*   **Static Branch:** Outputs view-dependent color $\mathbf{c}_s(\mathbf{x}, \mathbf{d}, \mathbf{A}_{vid}\mathbf{F}(t)) \in \mathbb{R}^3$ and view-independent density $\sigma_s(\mathbf{x}) \in \mathbb{R}$ [S1]. Lighting variations are modeled via a latent embedding $\mathbf{A}_{vid}\mathbf{F}(t)$, where $\mathbf{A}_{vid}$ is a video-specific matrix and $\mathbf{F}(t)$ is a Fourier-encoded time index [S1].
*   **Dynamic Branch:** Outputs time/video-dependent density $\sigma_d(\mathbf{x}, t, vid) \in \mathbb{R}$, color $\mathbf{c}_d(\mathbf{x}, t, vid, \mathbf{d}) \in \mathbb{R}^3$, and a scalar shadow ratio $\rho_d(\mathbf{x}, t, vid) \in [0, 1]$ [S1]. It also predicts forward and backward 3D scene flow vectors $\mathbf{s}_{t0}(\mathbf{x}, t, vid) \in \mathbb{R}^3$ with values in $[-1, 1]$ [S1].
*   **Far-field Branch:** Outputs environment map color $\mathbf{c}_e(\mathbf{d}, vid) \in \mathbb{R}^3$ [S1].
*   **Semantic Features:** Each branch has a $C$-dimensional output head distilling DINO features: $\mathbf{\Phi}_s(\mathbf{x}) \in \mathbb{R}^C$, $\mathbf{\Phi}_d(\mathbf{x}, t, vid) \in \mathbb{R}^C$, $\mathbf{\Phi}_e(\mathbf{d}, vid) \in \mathbb{R}^C$ [S1].

**Density and Radiance Combination:**
Total density is the sum of static and dynamic components:
$$ \sigma(\mathbf{x}, t, vid) = \sigma_s(\mathbf{x}) + \sigma_d(\mathbf{x}, t, vid) $$
Total radiance combines static and dynamic colors, scaled by the shadow ratio $\rho_d$:
$$ \mathbf{c}(\mathbf{x}, t, vid, \mathbf{d}) = \frac{(1 - \rho_d)\sigma_s \mathbf{c}_s + \sigma_d \mathbf{c}_d}{\sigma} $$
Semantic features are combined similarly [S1].

**Rendering:**
Color $\hat{\mathbf{C}}$ for a ray $\mathbf{r}$ is accumulated using standard volume rendering, forcing intersection with the far-field environment map if no foreground geometry is hit:
$$ \hat{\mathbf{C}}(\mathbf{r}, t, vid) = \int_0^{+\infty} T(t)\sigma(\mathbf{r}(t), t, vid)\mathbf{c}(\mathbf{r}(t), t, vid, \mathbf{d}) dt + T(+\infty)\mathbf{c}_e(\mathbf{d}, vid) $$
where $T(t) = \exp\left(-\int_0^t \sigma(\mathbf{r}(s), t, vid) ds\right)$ [S1].

**Training Configuration:**
*   **Spatial Partitioning:** The scene is split into $K$ cells. Training datasets for each cell include only rays intersecting the cell, pruned by LiDAR depth to ensure visibility [S1].
*   **Hyperparameters:** 250,000 training iterations, 4098 rays per batch, Adam optimizer with learning rate decaying from $5 \times 10^{-3}$ to $5 \times 10^{-4}$ [S1].
*   **Loss Functions:**
    1.  **Reconstruction:** L2 photometric loss $\mathcal{L}_c(\mathbf{r}) = \|\mathbf{C}(\mathbf{r}) - \hat{\mathbf{C}}(\mathbf{r})\|^2$ and L1 feature loss $\mathcal{L}_f(\mathbf{r}) = \|\mathbf{F}(\mathbf{r}) - \hat{\mathbf{F}}(\mathbf{r})\|_1$ [S1].
    2.  **Depth:** L2 loss between rendered depth $\hat{D}(\mathbf{r})$ and LiDAR depth $D(\mathbf{r})$ [S1].
    3.  **Flow:** 3D position $\hat{\mathbf{X}}_{t0}$ is rendered using scene flow, and L1 loss is minimized against observed 2D optical flow $\mathbf{O}$ [S1].
    4.  **Warping:** Samples are advected using predicted flow to warp density, color, and features. Warped color $\hat{\mathbf{C}}^w$ and feature $\hat{\mathbf{F}}^w$ are rendered. Loss is downweighted in ambiguous regions using weight $W_{t0}(\mathbf{r})$ derived from dynamic geometry difference [S1].
    5.  **Flow Regularization:** Cycle consistency $\mathcal{L}_{cyc}$, spatial/temporal smoothness $\mathcal{L}_{sm}$, and static scene prior $\mathcal{L}_{slo}$ (encouraging zero flow in static regions) [S1].
    6.  **Static-Dynamic Factorization:** Skewed binary entropy loss $\mathcal{L}_e(\mathbf{r}) = \int_0^{+\infty} H\left(\frac{\sigma_d}{\sigma_s + \sigma_d}\right) dt$ with $k=1.75$, and penalty on max dynamic ratio $\mathcal{L}_d(\mathbf{r}) = \max\left(\frac{\sigma_d}{\sigma_s + \sigma_d}\right)$ [S1].
    7.  **Shadow Loss:** Squared magnitude of shadow ratio $\mathcal{L}_\rho(\mathbf{r}) = \int_0^{+\infty} \rho_d(\mathbf{r}(t))^2 dt$ [S1].

## Operating characteristics
*   **Complexity:** Memory usage scales with the number of hash table entries, which is controlled by the hash table size parameter (not explicitly given, but implied to be manageable for city-scale scenes). Training time is 10x quicker than methods requiring 3D bounding box annotations [S1].
*   **Performance:** Scales to tens of thousands of objects across 1.2 million frames from 1700 videos spanning hundreds of kilometers [S1].
*   **Strengths:** Handles ego-motion and multi-video representations; does not require labeled 3D data (bounding boxes/segmentation); explicitly models shadows and scene flow [S1].
*   **Limitations:** Requires sparse LiDAR and optical flow for optimal supervision (though these are "free" from standard sensor rigs); relies on self-supervised DINO features which may have limited semantic granularity compared to labeled data [S1].

## Background
SUDS was introduced in the paper "SUDS: Scalable Urban Dynamic Scenes" [S1]. It addresses the limitations of prior dynamic scene representations that required supervised inputs like panoptic segmentation labels or bounding boxes, which are difficult to acquire for in-the-wild captures [S1]. It builds on the multi-resolution hash table concept from Instant-NGP [S1] and extends it to 4D with separate branches for static, dynamic, and far-field components. It is used for large-scale dynamic NeRF reconstruction, novel-view synthesis, 3D scene flow estimation, and unsupervised instance segmentation [S1].
