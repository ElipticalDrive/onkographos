# SUDS

Also called: SUDS (Scalable Urban Dynamic Scenes), Scalable Urban Dynamic Scenes

## Overview
SUDS is a 4D radiance field representation designed for large-scale dynamic urban scenes that factorizes the scene into three separate multi-resolution hash table structures: static, dynamic, and far-field [S1]. It solves the problem of scaling neural reconstruction to city-level footprints with tens of thousands of objects and ego-motion by using unlabeled target signals (RGB, sparse LiDAR, 2D descriptors, and 2D optical flow) for supervision, eliminating the need for ground truth 3D bounding boxes or panoptic labels [S1]. Unlike sibling methods that rely on per-object NeRFs or supervised annotations, SUDS handles multi-video representations and dynamic objects within a unified global coordinate system [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ordered RGB images from $N$ videos taken at different days with diverse weather/lighting, associated camera poses, aligned sparse LiDAR depth measurements, 2D self-supervised DINO descriptors, and 2D optical flow predictions [S1].
*   **Outputs:** Rendered color $\hat{C}(r)$, rendered features $\hat{F}(r)$, density $\sigma$, scene flow $s_{t_0}$, and semantic logits $\Phi$ for any position $\mathbf{x}$, direction $\mathbf{d}$, time $t$, and video ID $vid$ [S1].

**Data Structures:**
The scene is decomposed into $K$ spatial cells with centroids $\mathbf{k} \in \mathbb{R}^3$. Each cell contains three branches, each implemented as a multi-resolution hash table [S1].
1.  **Static Branch:** Stores 3D spatial voxels $v_{l,s}$ at $L$ resolution levels. Features are indexed by spatial position [S1].
2.  **Dynamic Branch:** Stores 4D spacetime voxels $v_{l,d}$ at $L$ resolution levels. Features are indexed by spatial position, time, and video ID [S1].
3.  **Far-field Branch:** Stores 3D voxels $v_{l,e}$ indexed by normalized 3D direction vectors $\mathbf{d}$ and video ID [S1].

Each hash table stores $F$-dimensional feature vectors. The hash functions map voxel corners to indices in a global hash table of fixed size [S1]. Hash collisions are handled via gradient averaging [S1].

**Parameters:**
*   $F$: Dimensionality of feature vectors in hash tables [S1].
*   $L$: Number of resolution levels, where resolution doubles between levels [S1].
*   $N$: Number of input videos [S1].
*   $C$: Dimensionality of DINO feature grid ($\mathbb{R}^{H \times W \times C}$) [S1].
*   $k$: Constant set to 1.75 in the skewed binary entropy loss [S1].
*   Training: 250,000 iterations, 4098 rays per batch, Adam optimizer with learning rate decaying from $5 \times 10^{-3}$ to $5 \times 10^{-4}$ [S1].

**Algorithm Steps:**

1.  **Spatial Partitioning:** Split the scene into $K$ spatial cells. For each cell, generate a training dataset including only datapoints whose camera rays intersect the cell. Prune irrelevant rays using LiDAR depth measurements to ensure visibility [S1].
2.  **Voxel Lookup:** For an input coordinate $(\mathbf{x}, \mathbf{d}, t, vid)$, find surrounding voxels at $L$ resolution levels for the static ($v_{l,s}$), dynamic ($v_{l,d}$), and far-field ($v_{l,e}$) branches [S1].
3.  **Hash Indexing:** Compute hash indices for voxel corners:
    *   Static: $i_{l,s} = \text{static hash}(\text{space}(v_{l,s}))$ [S1].
    *   Dynamic: $i_{l,d} = \text{dynamic hash}(\text{space}(v_{l,d}), \text{time}(v_{l,d}), vid)$ [S1].
    *   Far-field: $i_{l,e} = \text{env hash}(\text{dir}(v_{l,e}), vid)$ [S1].
4.  **Feature Interpolation:**
    *   Look up feature vectors corresponding to the corners.
    *   Linearly interpolate features for the static branch.
    *   Use quadlinear interpolation for the dynamic 4D branch [S1].
    *   Handle hash collisions via gradient averaging [S1].
    *   Concatenate results from all $L$ levels into a feature vector $\mathbf{f} \in \mathbb{R}^{LF}$ for each branch [S1].
5.  **MLP Evaluation:** Pass the concatenated feature vector $\mathbf{f}$ and auxiliary inputs (viewing direction $\mathbf{d}$, time encoding) into a small MLP to obtain per-branch outputs [S1].
    *   **Static Output:** View-dependent color $\mathbf{c}_s(\mathbf{x}, \mathbf{d}, \mathbf{A}_{vid} \mathbf{F}(t)) \in \mathbb{R}^3$ and view-independent density $\sigma_s(\mathbf{x}) \in \mathbb{R}$. The lighting is conditioned on a latent embedding $\mathbf{A}_{vid} \mathbf{F}(t)$, where $\mathbf{A}_{vid}$ is a video-specific matrix and $\mathbf{F}(t)$ is a Fourier-encoded time index [S1].
    *   **Dynamic Output:** Time/video-dependent density $\sigma_d(\mathbf{x}, t, vid) \in \mathbb{R}$, color $\mathbf{c}_d(\mathbf{x}, t, vid, \mathbf{d}) \in \mathbb{R}^3$, scalar shadow ratio $\rho_d(\mathbf{x}, t, vid) \in [0, 1]$, and forward/backward 3D scene flow vectors $\mathbf{s}_{t_0}(\mathbf{x}, t, vid) \in \mathbb{R}^3$ with values in $[-1, 1]$ [S1].
    *   **Far-field Output:** Environment map color $\mathbf{c}_e(\mathbf{d}, vid) \in \mathbb{R}^3$ [S1].
    *   **Semantic Output:** $C$-dimensional feature logits $\Phi_s(\mathbf{x})$, $\Phi_d(\mathbf{x}, t, vid)$, and $\Phi_e(\mathbf{d}, vid)$ for each branch [S1].
6.  **Density and Radiance Combination:**
    *   Total density: $\sigma(\mathbf{x}, t, vid) = \sigma_s(\mathbf{x}) + \sigma_d(\mathbf{x}, t, vid)$ [S1].
    *   Total radiance:
        $$ \mathbf{c}(\mathbf{x}, t, vid, \mathbf{d}) = \frac{(1 - \rho_d)\sigma_s \mathbf{c}_s + \sigma_d \mathbf{c}_d}{\sigma} $$
        [S1].
    *   Total semantic feature $\Phi$ is computed similarly by blending branch features [S1].
7.  **Rendering:** For a camera ray $r$ with direction $\mathbf{d}$ at frame $t$ and video $vid$, accumulate transmittance along sampled points $r(t)$:
    $$ \hat{C}(r, t, vid) = \int_0^{+\infty} T(t)\sigma(r(t), t, vid)\mathbf{c}(r(t), t, vid, \mathbf{d}) dt + T(+\infty)\mathbf{c}_e(\mathbf{d}, vid) $$
    where $T(t) = \exp\left(-\int_0^t \sigma(r(s), t, vid) ds\right)$ [S1].
8.  **Loss Calculation:** Minimize the total loss $\mathcal{L}$ (Eq. 16 in [S1]):
    *   **Reconstruction:** L2 photometric loss $\mathcal{L}_c(r) = \|\mathbf{C}(r) - \hat{\mathbf{C}}(r)\|^2$ and L1 feature loss $\mathcal{L}_f(r) = \|\mathbf{F}(r) - \hat{\mathbf{F}}(r)\|_1$ [S1].
    *   **Depth:** L2 loss between rendered depth $\hat{D}(r)$ and LiDAR depth $D(r)$ [S1].
    *   **Flow:** L1 loss between rendered 2D optical flow and observed optical flow $\mathbf{O}$ [S1].
    *   **Warping:** Advect samples using predicted flow to warp density, color, and features. Render warped color $\hat{\mathbf{C}}^w$ and feature $\hat{\mathbf{F}}^w$. Minimize L2/L1 losses between warped outputs and ground truth, downweighted by ambiguity weight $W_{t_0}(r)$ [S1].
    *   **Flow Regularization:** Cycle consistency loss $\mathcal{L}_{cyc}$, spatial/temporal smoothness $\mathcal{L}_{sm}$, and static scene prior $\mathcal{L}_{slo}$ (encouraging zero flow in static regions) [S1].
    *   **Static-Dynamic Factorization:** Skewed binary entropy loss $\mathcal{L}_e(r) = \int_0^{+\infty} H\left(\frac{\sigma_d(r(t))}{\sigma_s(r(t)) + \sigma_d(r(t))}\right) dt$ with $k=1.75$, and penalty on max dynamic ratio $\mathcal{L}_d(r)$ [S1].
    *   **Shadow Loss:** Penalize squared magnitude of shadow ratio $\mathcal{L}_\rho$ [S1].

## Operating characteristics
*   **Time and Memory Complexity:** SUDS scales to tens of thousands of objects across 1.2 million frames from 1700 videos spanning hundreds of kilometers [S1]. It is 10x quicker to train than state-of-the-art methods relying on ground truth 3D bounding box annotations [S1]. Memory usage is controlled by multi-resolution hash tables, avoiding the linear memory growth of per-object NeRFs (e.g., NSG requires >1TB for 30s video) [S1].
*   **Strengths:** Handles ego-motion and multi-video representations; uses unlabeled inputs (RGB, LiDAR, flow) for supervision; enables semantic decomposition and 3D scene flow; scales to city-level footprints [S1].
*   **Limitations:** Requires aligned sparse LiDAR and optical flow for optimal performance (though these are "free" supervision sources); relies on spatial partitioning which may introduce seams if not handled carefully [S1].
*   **When to use:** Large-scale dynamic urban scene reconstruction with ego-motion and multiple video sources where labeled 3D data is unavailable [S1].
*   **When not to use:** Small-scale static scenes or scenes without dynamic elements where simpler NeRF variants suffice [S1].

## Background
SUDS (Scalable Urban Dynamic Scenes) was introduced in 2023 by the authors of the paper "SUDS: Scalable Urban Dynamic Scenes" [S1]. It builds on Instant-NGP's multi-resolution hash tables and addresses the limitations of prior dynamic scene representations like NSG, which cannot handle ego-motion and suffer from high memory requirements [S1]. SUDS is used for free-viewpoint rendering, semantic decomposition, and 3D scene flow estimation in large-scale urban environments [S1].
