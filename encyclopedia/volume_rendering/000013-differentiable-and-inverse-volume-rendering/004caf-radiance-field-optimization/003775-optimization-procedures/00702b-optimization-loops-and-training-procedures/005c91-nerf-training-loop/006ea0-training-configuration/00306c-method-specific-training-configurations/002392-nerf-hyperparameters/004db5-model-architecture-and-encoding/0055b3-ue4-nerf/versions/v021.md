# UE4-NeRF


## Overview
UE4-NeRF is a neural rendering system designed for the real-time interactive rendering of large-scale 3D scenes by partitioning the environment into sub-NeRFs represented as textured polygonal meshes [S1]. It integrates these neural models into the Unreal Engine 4 (UE4) rasterization pipeline, enabling real-time frame rates at high resolutions (up to 4K) while supporting scene editing [S1]. Unlike Block-NeRF, which is limited to grid structures, UE4-NeRF handles diverse terrains (e.g., mountainous areas) using regular octahedra, and unlike Mobile-NeRF, it supports semi-transparent objects and converges stably on tilted surfaces [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of posed images (typically from drones) with GPS metadata; camera poses; scene bounding box.
*   **Outputs:** A UE4 scene containing LOD polygonal meshes with texture atlases storing feature vectors and opacity, and an HLSL fragment shader for color prediction.

**Data Structures:**
1.  **Scene Partitioning:** The large scene is divided into blocks. Each block's training area slightly exceeds the scene area to create overlapping borders for smooth transitions [S1].
2.  **Mesh Geometry:**
    *   Initialized from a $128 \times 128 \times 128$ grid [S1].
    *   Vertices are selected from the center point of each grid cell and its six neighbors (front, back, left, right, top, bottom) [S1].
    *   Faces are formed into regular octahedra. Each octahedron has 20 faces: 8 exterior and 12 interior [S1].
    *   Vertex positions are optimized during training [S1].
3.  **Texture Atlas:** Stores per-vertex feature vectors and opacity values [S1].
4.  **Network Architecture:**
    *   **Encoder:** 4-layer MLP. Dimensions: $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$. Input: Hash-encoded position $p_i$. Output: Opacity $\alpha_i$ and 8-dimensional feature vector $M_i$ [S1].
    *   **Decoder:** 3-layer MLP. Dimensions: $17 \times 16$, $16 \times 16$, $16 \times 3$. Input: Feature vector $M_i$ and view direction encoding $SH(d_i)$. Output: Color $c_i$ [S1].
    *   **Encoding:** Multi-resolution hash encoding (from Instant-NGP) [S1].

**Numbered Steps:**

1.  **Coordinate Transformation:** Convert GPS-captured imagery coordinates to the UE4 coordinate system. The X-axis points East, Y-axis points South, Z-axis points Up. Apply a 100:1 scale conversion (UE4 units to real-world units) [S1].
2.  **Block Partitioning:** Partition the scene into blocks. Train a coarse segmentation model to capture terrain/building outlines. Filter images for each sub-region and mask out pixels outside the scene area [S1].
3.  **Mesh Initialization:** For each block, initialize a $128 \times 128 \times 128$ grid. Construct polygonal meshes using grid centers and neighbors, forming regular octahedra (20 faces each) [S1].
4.  **Network Training:**
    *   Define the Encoder $E$ and Decoder $D$ networks [S1].
    *   For a ray $r(t) = o + td$ (where $d=(\theta, \phi)$ is the viewing direction), calculate intersections with the polygonal meshes to obtain sampling points [S1].
    *   Encode position $p_i$ using multi-resolution hash encoding.
    *   Compute opacity and features: $M_i, \alpha_i = E(\text{hash}(p_i); \theta_E)$ [S1].
    *   Encode view direction $d_i$ using spherical harmonics $SH$.
    *   Compute color: $c_i = D(M_i, SH(d_i); \theta_D)$ [S1].
    *   Optimize vertex positions, encoder parameters $\theta_E$, and decoder parameters $\theta_D$ simultaneously [S1].
    *   Train for 80,000 epochs per block [S1].
5.  **LOD Generation:** Train meshes with varying levels of detail (LOD) for different observation heights. Coarser meshes are used for higher observation heights to ensure real-time performance [S1].
6.  **Shader Implementation:** Implement the Decoder network as an HLSL fragment shader in UE4. The shader takes feature vectors (from the texture atlas) as input and outputs colors [S1].
7.  **Rendering:** Extract pre-rendered polygonal meshes at different LODs. Combine with the UE4 rasterization pipeline. UE4 handles occlusion between added 3D objects and the NeRF background, skipping neural shader computation for occluded regions [S1].

def initialize_mesh(grid_size=128):

    Uses regular octahedra with 20 faces (8 exterior, 12 interior).
    """
    mesh_vertices = []
    # Iterate through 128x128x128 grid

def encode_position(position, hash_table):
    """
    Multi-resolution hash encoding (Instant-NGP style).
    """
    # Hash the position coordinates into a feature vector
    return hash_table.query(position)

def encoder_network(hash_features):
    """
    4-layer MLP: 32->64->64->64->8.
    Input: Hash features.
    Output: Opacity (scalar) and Feature Vector (8-dim).
    """
    x = hash_features
    x = relu(linear(x, 32, 64))
    x = relu(linear(x, 64, 64))
    x = relu(linear(x, 64, 64))
    output = linear(x, 64, 8)
    opacity = sigmoid(output[0]) # Assuming opacity is derived or separate head
    features = output[1:]
    return opacity, features

def decoder_network(features, view_direction):
    """
    3-layer MLP: 17->16->16->3.
    Input: Features (8-dim) + Spherical Harmonics of View Dir (9-dim).
    Output: Color (3-dim).
    """
    sh_coeffs = spherical_harmonics(view_direction, degree=3) # 9 coefficients
    input_vec = concat(features, sh_coeffs) # 8 + 9 = 17 dims
    
    x = relu(linear(input_vec, 17, 16))
    x = relu(linear(x, 16, 16))
    color = sigmoid(linear(x, 16, 3))
    return color

    encoder = EncoderMLP()

**Parameters:**
*   **Grid Size:** $128 \times 128 \times 128$ [S1].
*   **Octahedron Faces:** 20 total (8 exterior, 12 interior) [S1].
*   **Encoder Layers:** 4 layers, dimensions $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S1].
*   **Decoder Layers:** 3 layers, dimensions $17 \times 16$, $16 \times 16$, $16 \times 3$ [S1].
*   **Training Epochs:** 80,000 per block [S1].
*   **Hardware:** 1 Nvidia RTX 3090 GPU [S1].
*   **Coordinate System:** X=East, Y=South, Z=Up [S1].
*   **Scale:** 100:1 [S1].

**Edge Cases and Pitfalls:**
*   **Tilted Surfaces:** Mobile-NeRF suffers from slow/unstable convergence on tilted surfaces. UE4-NeRF addresses this by using regular octahedra [S1].
*   **Transparency:** Mobile-NeRF cannot handle transparent/semi-transparent objects (water, glass) due to opacity binarization. UE4-NeRF stores opacity in texture maps to mitigate this [S1].
*   **Performance:** Semi-transparent objects (e.g., vegetation) increase computational overhead, reducing frame rates [S1].
*   **Pre-rendering Gaps:** Pre-rendering cannot capture rays from all viewing angles, potentially resulting in gaps or holes in the final scene [S1].
*   **Exposure Matching:** Consistent exposure matching with original images is difficult in UE4, causing evaluation metrics (PSNR/SSIM) to underestimate actual reconstruction quality [S1].
*   **Memory:** Requires CUDA and NVIDIA GPUs. Rendering large scenes (square kilometers) incurs significant memory overhead; increasing accuracy amplifies this [S1].

## Operating characteristics
*   **Training Speed:** 1000× faster than Mobile-NeRF [S1].
*   **Training Time:** ~40 minutes per block on 1×RTX 3090. Total scene time: 1 hour + (40 minutes × $n/4$) for $n$ blocks [S1].
*   **Rendering Performance:** Real-time at 4K resolution with up to 43 FPS (Level-1 mesh) [S1]. 50 FPS on full scene at 2K; ≥70 FPS on individual blocks at 2K [S1].
*   **Memory:** Significant memory overhead for large scenes (square kilometers). Increases with accuracy [S1].
*   **Strengths:** Real-time large-scale rendering, handles tilted surfaces, supports semi-transparency, enables scene editing in UE4 [S1].
*   **Limitations:** Requires NVIDIA GPUs/CUDA, pre-rendering gaps, exposure matching issues in UE4, performance drop with semi-transparent objects [S1].
*   **Comparison:**
    *   vs. Mobile-NeRF: Faster training (40 mins vs 48h/block), handles tilted surfaces, supports transparency, higher FPS (43 FPS 4K vs 35 FPS 2K) [S1].
    *   vs. Mega-NeRF: Faster training (40 mins vs 36h/block), higher resolution support (4K vs 800x800), less blur [S1].
    *   vs. Mip-NeRF: Avoids blurriness on natural scenes, renders small objects (power lines) accurately [S1].

## Background
UE4-NeRF was introduced in the paper "UE4-NeRF: Neural Radiance Field for Real-Time Rendering of Large-Scale Scene" [S1]. It addresses the limitations of NeRF in real-time interactive rendering for large-scale scenes, such as those captured by drones (farmland, construction sites, industrial parks) [S1]. It builds on techniques from Mobile-NeRF (mesh representation) and Instant-NGP (hash encoding) [S1]. It is used within Unreal Engine 4 for real-time interactive rendering and scene editing [S1].
