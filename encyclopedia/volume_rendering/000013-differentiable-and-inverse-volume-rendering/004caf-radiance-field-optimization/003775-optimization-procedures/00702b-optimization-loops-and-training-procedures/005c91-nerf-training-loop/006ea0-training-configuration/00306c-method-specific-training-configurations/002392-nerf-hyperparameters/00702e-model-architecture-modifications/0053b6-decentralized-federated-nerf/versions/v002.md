# Decentralized Federated NeRF

Also called: DecentNeRF, Decentralized Neural Radiance Fields from Crowdsourced Images

## Overview
DecentNeRF is a decentralized framework for learning global 3D scene representations from crowd-sourced images by distributing training computation to users and aggregating only global radiance field models to minimize server compute and personal data leakage [S1]. The core problem solved is achieving photorealistic 3D reconstruction of global scene content while preventing the server from reconstructing transient personal content (e.g., users, objects) present in crowdsourced images taken at different times [S1]. It sets itself apart from centralized approaches like NeRF-W by eliminating the need to transfer raw personal images to the server, and from standard federated NeRFs like FedNeRF by explicitly separating personal and global content via dual MLPs and employing secure multi-party computation (SMPC) to prevent server-side reconstruction of personal data [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $K$ users, each possessing a local dataset of images $\mathcal{I}_k$ with known camera poses. The images contain both static global scene content and transient personal content.
*   **Outputs:** A global NeRF model (aggregated at the server) capable of rendering the global scene, and local personal NeRF models (kept on user devices) capable of rendering user-specific content.

**Data Structures:**
Each user $k$ maintains two Multi-Layer Perceptrons (MLPs):
1.  **Global MLP:** Weights $\mathbf{g}_k$. Captures static, shared scene content.
2.  **Personal MLP:** Weights $\mathbf{p}_k$. Captures transient, user-specific content.
*   **NeRF Backbone:** Both MLPs take a 5D input vector: 3D spatial coordinate $\mathbf{x} = (x, y, z)$ and viewing direction parameters pitch $\theta$ and yaw $\phi$. They output a scalar density $\sigma$ and an RGB color vector $\mathbf{c} = (r, g, b)$ [S1].
*   **Rendering:** Images are synthesized via volume rendering. The final rendered image is an alpha-composite of the output images from both the global and personal MLPs [S1].
*   **Federation Scope:** Only the global MLP weights $\mathbf{g}_k$ are federated to the server. Personal MLP weights $\mathbf{p}_k$ remain local to the user device [S1].

**Parameters:**
*   $\alpha_k$: A per-user weighting factor applied to local weights/gradients during obfuscation and aggregation. It is learned via gradient descent to maximize visual fidelity, implicitly handling user importance (e.g., based on occlusion levels) rather than using uniform averaging [S1].
*   Typical values: Not given in the sources.

**Assumptions:**
1.  **Transient Personal Content:** Personal content is transient across users (not all clients have taken images at the same instant) [S1].
2.  **Sufficient View Overlap:** No single user has views that don’t overlap with another user. If two users have no overlapping views, the server’s ability to reconstruct personal content increases considerably [S1].
3.  **Known Camera Poses:** Accurate camera poses are provided (derived via SfM in centralized settings, but assumed known here) [S1].

**Threat Model:**
The server and other users are untrusted from the user's perspective. The server is honest-but-curious (follows protocols but attempts to reconstruct raw data). No collusion between users is assumed [S1].

**Algorithm Steps:**
1.  **Initialization:** Randomly initialize global MLP weights $\mathbf{G}^{(0)}$ and personal MLP weights $\mathbf{P}^{(0)}$ at all $K$ users [S1].
2.  **Local Training (User Side):** For each training round $m$:
    *   Each user $k$ trains their local Global MLP and Personal MLP on their local images $\mathcal{I}_k$.
    *   The loss is computed by comparing the rendered image (alpha-composite of global and personal outputs) with the ground truth RGB [S1].
    *   Calculate the loss gradients for the global MLP weights from the previous round: $\frac{\partial L_k}{\partial \mathbf{g}^{(m-1)}}$ [S1].
    *   Calculate the gradient update for the weighting factor $\alpha_k$ based on the current loss [S1].
3.  **Obfuscation (User Side):**
    *   **Weight Obfuscation (`send_wts`):** Each user obfuscates their local global weights $\mathbf{g}_k^{(m)}$ by multiplying with $\alpha_k$ and applying a random mask or encrypting with additively homomorphic encryption. This prevents the server from recovering original values while enabling accurate weighted averaging [S1].
    *   **Gradient Obfuscation (`send_grads`):** Each user communicates local gradients by performing randomized obfuscation similar to the weight obfuscation process [S1].
4.  **Secure Aggregation (Server Side):**
    *   The server securely aggregates the obfuscated weights and previous rounds' gradients from all users using a Secure Multi-Party Computation (SMPC) protocol (e.g., SecAgg) [S1].
    *   The server computes the weighted average of the global MLPs [S1].
5.  **Distribution (Server Side):**
    *   The server sends the updated aggregated global MLP and the aggregated gradients back to each user [S1].
6.  **Update (User Side):**
    *   Each user calculates the update step for $\alpha_k$ and updates their local global MLP weights using the received aggregated information [S1].

**Edge Cases and Pitfalls:**
*   **Initial Rounds:** During initial rounds of federation, users’ global MLPs contain personal content. Standard federated learning uniformly averages user weights, which does not maximize visual fidelity and leads to undesired reconstruction of personal content by the server [S1]. DecentNeRF mitigates this via learned weighted averaging and SMPC [S1].
*   **No View Overlap:** If two users have no overlapping views (entirely separate scene areas), the server's ability to reconstruct personal content increases considerably [S1].
*   **Precision:** The use of additively homomorphic encryption and random masking requires careful handling of numerical precision to ensure the weighted average remains accurate [S1].

## Operating characteristics
*   **Server Compute:** DecentNeRF requires $\sim 10^4$ times less server computing for a scene than a centralized approach [S1].
*   **FLOPs:** DecentNeRF uses $\sim 0.6$B FLOPs for the aggregation/optimization process, compared to $\sim 200$T FLOPs for FedNeRF and $\sim 5$B FLOPs for NeRF-W (Note: The source labels these as comparative metrics, with DecentNeRF's 0.6B likely referring to the server-side aggregation cost or a specific efficient setup, while NeRF-W's 5B refers to its total server cost) [S1].
*   **Performance:** On the Phototourism dataset, DecentNeRF achieves PSNR 24.62, SSIM 0.8802, LPIPS 0.2571 with $\approx 5$B server FLOPs [S1].
*   **Personal Content Leakage:** In the first federation round, server-rendered global image PSNR is 14.2 dB and server-rendered personal content PSNR is 14.9 dB. In the final federation round, server-rendered global image PSNR is 27.2 dB and server-rendered personal content PSNR is 9.3 dB [S1]. Personal content reconstruction by the server is reduced by 10 dB compared to FedNeRF [S1].
*   **Strengths:** Photorealistic global reconstruction, minimal server compute, strong privacy protection against honest-but-curious servers.
*   **Limitations:** Requires known camera poses, assumes sufficient view overlap, and relies on the assumption that personal content is transient.

## Background
DecentNeRF was introduced by Z. Tasneem et al. in the paper "DecentNeRFs: Decentralized Neural Radiance Fields from Crowdsourced Images" [S1]. It addresses the limitations of NeRF-W, which requires all personal user images to be transferred to a central server, leading to personal content access and high compute [S1]. It also improves upon existing federated learning NeRF techniques (like FedNeRF) which assume static scenes devoid of personal information and allow server access to personal info without secure aggregation [S1]. The method is used for decentralized NeRF training on crowdsourced datasets including the Novel Blender Dataset and Phototourism Dataset (Brandenburg Gate, Trevi Fountain, Sacre Couer) [S1].
