# NeRF-based Trajectory Optimization

Also called: Differential Flatness-based Trajectory Optimization with NeRF, NeRF-based collision penalty optimization, Proposed trajectory optimizer

## Overview
NeRF-based Trajectory Optimization is a planning method for differentially flat systems that optimizes a dense set of flat output waypoints directly using first-order gradient descent [S1]. It solves collision-free path planning in complex environments by using Neural Radiance Field (NeRF) density as an implicit obstacle representation, replacing closed-form polytopes [S1]. Unlike traditional pipelines that use quadratic programs with static, hand-designed waypoints, this method optimizes waypoint locations to minimize a combined objective of collision probability and control effort [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A pre-trained NeRF model $\rho(x)$ representing environment density; current robot pose; goal pose; robot body geometry $B$ [S1].
*   **Outputs:** A sequence of optimized flat output waypoints $\{\sigma_1, \dots, \sigma_h\}$ defining the trajectory [S1].

**Data Structures:**
*   **Waypoints:** A sequence of flat output vectors. For quadrotors, each waypoint $\sigma_i$ contains position $(x, y, z)$ and yaw angle $\psi$ [S1].
*   **Robot Body Model:** A finite collection of points $B$ representing the robot's physical extent [S1].

**Algorithm Steps:**

1.  **Initialization:** Generate a preliminary set of waypoints between the current pose and the goal pose using a heuristic such as a straight line or A* search on a coarse grid [S1]. Let this initial sequence be $\{\sigma_1^{(0)}, \dots, \sigma_h^{(0)}\}$ [S1].
2.  **Define Cost Function:** The optimization minimizes a combined loss function $\mathcal{L}$ consisting of a collision probability term $\mathcal{L}_{coll}$ and a control effort term $\mathcal{L}_{ctrl}$ [S1]:
    $$ \mathcal{L} = \mathcal{L}_{coll} + \lambda \mathcal{L}_{ctrl} $$
    where $\lambda$ is a weighting parameter balancing collision avoidance and smoothness [G].
3.  **Compute Collision Probability:** For each trajectory segment, the collision probability is approximated by summing the NeRF density values at the locations of the robot body points $B$ [S1]. Let $b_t$ be the position of a point $b \in B$ at time $t$ [S1]. The collision cost is bounded by Boole's inequality as:
    $$ \mathcal{L}_{coll} = \sum_{t} \sum_{b \in B} \rho(b_t) s(b_t) $$
    where $\rho(b_t)$ is the NeRF density at $b_t$, and $s(b_t)$ is the distance traveled by the body-fixed point $b$ in timestep $t$ [S1].
4.  **Compute Control Effort:** Control inputs $u$ and states are derived from the surrounding waypoints using the robot's dynamics [S1]. The control effort $\mathcal{L}_{ctrl}$ minimizes an objective functional such as snap or jerk over the trajectory [S1].
5.  **Optimization:** Perform gradient descent on the waypoint parameters $\{\sigma_1, \dots, \sigma_h\}$ to minimize $\mathcal{L}$ [S1]. The gradients $\nabla_{\sigma_i} \mathcal{L}$ are computed using automatic differentiation through the NeRF density queries and the trajectory dynamics [S1]. The Adam optimizer is used due to the non-convex nature of the problem [S1].
6.  **Online Replanning (Optional):** If the robot's state estimate deviates significantly from the planned path, repeat the optimization using the latest state estimate as the new starting point, running for 250 iterations with a 0.1s time step [S1].

**Pseudocode:**

```python
def nerf_trajectory_optimization(nerf_density_fn, current_pose, goal_pose, body_points, num_waypoints, num_iterations, lr):
    """
    Optimizes a trajectory using NeRF-based collision probability.
    
    Args:
        nerf_density_fn: Function rho(x) returning density at point x.
        current_pose: Initial robot position (3D vector).
        goal_pose: Target robot position (3D vector).
        body_points: List of 3D vectors B representing the robot body.
        num_waypoints: Number of intermediate waypoints h.
        num_iterations: Number of gradient descent steps.
        lr: Learning rate for Adam optimizer.
        
    Returns:
        optimized_waypoints: List of 3D position vectors.
    """
    # Step 1: Initialize waypoints via linear interpolation
    waypoints = [current_pose + (goal_pose - current_pose) * (i / (num_waypoints - 1)) for i in range(num_waypoints)]
    
    # Initialize Adam optimizer state
    m = [0.0] * num_waypoints
    v = [0.0] * num_waypoints
    beta1, beta2, eps = 0.9, 0.999, 1e-8
    
    for step in range(num_iterations):
        # Step 2 & 3: Compute collision cost
        coll_cost = 0.0
        for i in range(num_waypoints - 1):
            seg_start = waypoints[i]
            seg_end = waypoints[i+1]
            seg_len = norm(seg_end - seg_start)
            for b in body_points:
                b_pos = seg_start + b
                density = nerf_density_fn(b_pos)
                coll_cost += density * seg_len
                
        # Step 4: Compute control effort (snap approximation)
        ctrl_cost = 0.0
        for i in range(2, num_waypoints - 2):
            snap = waypoints[i-2] - 4*waypoints[i-1] + 6*waypoints[i] - 4*waypoints[i+1] + waypoints[i+2]
            ctrl_cost += norm(snap)**2
            
        # Total loss
        loss = coll_cost + 0.1 * ctrl_cost
        
        # Step 5: Compute gradients and update via Adam
        for i in range(num_waypoints):
            # Compute gradient via finite differences for self-containment
            # In production, automatic differentiation is used [S1]
            eps_grad = 1e-4
            waypoints[i] += eps_grad
            loss_plus = coll_cost + 0.1 * ctrl_cost
            waypoints[i] -= eps_grad
            grad = (loss_plus - loss) / eps_grad
            
            m[i] = beta1 * m[i] + (1 - beta1) * grad
            v[i] = beta2 * v[i] + (1 - beta2) * grad**2
            m_hat = m[i] / (1 - beta1**(step + 1))
            v_hat = v[i] / (1 - beta2**(step + 1))
            waypoints[i] -= lr * m_hat / (sqrt(v_hat) + eps)
            
    return waypoints
```

**Parameters:**
*   **Optimizer:** Adam [S1].
*   **Iterations (Initial):** 2500 [S1].
*   **Iterations (Replanning):** 250 [S1].
*   **Time Step (Replanning):** 0.1s [S1].
*   **Flat Outputs:** Position and yaw angle for quadrotors [S1].

**Edge Cases and Pitfalls:**
*   **Non-Convexity:** The optimization landscape is non-convex, requiring robust first-order methods like Adam [S1].
*   **NeRF Density Proxy:** NeRF density correlates with ground-truth mesh intersections, validating its use as a collision proxy [S1].

## Subtopics

### [Online Replanning](10684-online-replanning.md)
Online Replanning is a pipeline component that re-plans collision-free trajectories when state estimates deviate significantly from the planned path. It solves the problem of catastrophic collisions caused by external disturbances or state estimation errors during execution. Unlike open-loop execution, which follows a pre-computed plan regardless of deviations, online replanning uses feedback to generate new collision-free paths to the goal, ensuring robustness in dynamic or uncertain environments.

## Operating characteristics
*   **Time Complexity:** Dependent on the number of waypoints, robot body points, and optimization iterations [S1]. Initial planning takes approximately 20 seconds for 2500 iterations on an AMD Ryzen 9 5900X CPU and Nvidia RTX 3090 GPU [S1]. Online replanning updates take approximately 2 seconds for 250 iterations [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** In the Stonehenge environment, the optimizer converges to a trajectory with zero intersections with ground-truth meshes by iteration 49 [S1]. The NeRF collision loss correlates with the intersecting volume of ground-truth meshes [S1].
*   **Strengths:** Handles complex, implicit obstacle representations without explicit meshing; optimizes waypoint locations for smoother trajectories compared to minimum-snap planners with fixed waypoints; compatible with differential flatness-based feedback controllers [S1].
*   **Limitations:** Computationally expensive compared to traditional QP-based methods; performance depends on the quality of the NeRF representation [S1].
*   **When to Use:** Suitable for robots with differentially flat dynamics (e.g., quadrotors) navigating complex environments where explicit obstacle mapping is difficult or unavailable, and sufficient computational resources are available for gradient-based optimization [S1].

## Background
The method was proposed in "Vision-Only Robot Navigation in a Neural Radiance World" [S1]. It builds on the concept of differential flatness, commonly used in trajectory planning for quadrotors [S1]. Traditional methods use quadratic programs with closed-form obstacle descriptions (polytopes) and hand-designed waypoints [S1]. This approach leverages the differentiable nature of NeRFs to enable gradient-based optimization of trajectories directly in the neural representation space [S1].
