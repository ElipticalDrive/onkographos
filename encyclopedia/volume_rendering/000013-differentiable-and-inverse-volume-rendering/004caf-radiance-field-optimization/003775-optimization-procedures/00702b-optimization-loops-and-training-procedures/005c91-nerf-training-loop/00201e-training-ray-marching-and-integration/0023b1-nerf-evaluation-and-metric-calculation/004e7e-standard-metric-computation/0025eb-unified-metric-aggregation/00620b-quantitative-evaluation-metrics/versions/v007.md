# Quantitative Evaluation Metrics

Also called: PSNR, SSIM, LPIPS, FID, Geometric Metrics

## Overview
Quantitative Evaluation Metrics provide a standardized numerical assessment of rendered image quality and geometric fidelity by comparing synthesized views against ground-truth data [S2, S5, S11]. While [Unified Metric Aggregation](3644-unified-metric-aggregation.md) handles the statistical aggregation of these scores, this method defines the specific computations for pixel-wise, perceptual, and distributional comparisons [S1, S4].

## How it works
**Inputs:**
1.  **Rendered Image ($I_{render}$):** Output from the volume rendering pipeline, typically in floating-point format [S9, S10, unofficial].
2.  **Ground Truth Image ($I_{gt}$):** Reference image, often loaded from a dataset directory [S8, S10, unofficial].
3.  **Mask (Optional):** Binary mask indicating valid pixels (e.g., excluding background) [S8, S14, unofficial].
4.  **Depth Maps (Optional):** Predicted and ground-truth depth maps for geometric evaluation [S7][S14, unofficial].

**Outputs:**
*   Scalar metrics: PSNR, SSIM, LPIPS, FID, tOF, tLP, and geometric distances (Ch, NC, IoU) [S3, S6][S14, unofficial].
*   Per-view metric dictionaries for aggregation [S10, unofficial].

**Data Structures:**
*   Images are represented as tensors of shape $[H, W, C]$ or $[1, C, H, W]$ where $C=3$ for RGB [S9, S10, unofficial].
*   Metrics are accumulated in lists or dictionaries keyed by scene or view ID [S10, unofficial].

**Preprocessing Steps:**
1.  **Tonemapping (Synthetic Data):** For HDR synthetic data, apply tone mapping $I_{out} = I_{in}^{1/2.2}$ and clip to $[0, 1]$ before metric computation [S1].
2.  **Clamping:** Clamp rendered values to $[0, 1]$ [S8, S9, unofficial].
3.  **Format Conversion:** Convert to uint8 $[0, 255]$ if required by specific metric libraries (e.g., LPIPS implementations expecting uint8) [S8, unofficial]. Convert color spaces if necessary (e.g., BGR to RGB) [S8, unofficial].
4.  **Depth Alignment:** For depth metrics, multiply predicted depth by a scale factor derived from alignment to match the ground-truth depth range [S7].

**Metric Computations:**

1.  **PSNR (Peak Signal-to-Noise Ratio):**
    *   Compute Mean Squared Error (MSE) per pixel [S3]. For RGB:
        $$ MSE = \frac{1}{H \cdot W \cdot 3} \sum_{x,y} \left[ (R_{gt} - R_{render})^2 + (G_{gt} - G_{render})^2 + (B_{gt} - B_{render})^2 \right] $$
    *   If a mask $M$ is provided, restrict the sum to pixels where $M(x,y) > 0$ [S8, unofficial].
    *   Calculate PSNR:
        $$ PSNR = 10 \cdot \log_{10} \left( \frac{MAX_I^2}{MSE} \right) $$
        where $MAX_I = 1.0$ for normalized images [G]. Higher is better [S6].

2.  **SSIM (Structural Similarity Index):**
    *   Compute SSIM using a sliding window (e.g., $11 \times 11$ Gaussian window with $\sigma=1.5$) over the normalized RGB images [S3].
    *   SSIM captures local structural properties [S4]. Higher is better [S6].

3.  **LPIPS (Learned Perceptual Image Patch Similarity):**
    *   Initialize an AlexNet or VGG network for feature extraction [S7][S10, unofficial].
    *   Embed $I_{render}$ and $I_{gt}$ into feature space using the network [S4][S10, unofficial].
    *   Compute the mean absolute distance between feature activations (L1 distance in feature space) [S4].
    *   Normalize inputs if specified (e.g., `normalize=True`) [S8, unofficial].
    *   Lower is better [S6].

4.  **FID (Fréchet Inception Distance):**
    *   Compute the distribution of features for a set of real images and a set of generated images using an Inception network [S4].
    *   Calculate the distance between these image distributions [S4].
    *   Lower is better [S4].

5.  **Geometric Metrics (Optional):**
    *   **Chamfer Distance (Ch):** Bi-directional L2 distance between predicted and ground-truth point clouds/meshes [S14, unofficial].
    *   **Normal Consistency (NC):** Cosine similarity between predicted and ground-truth surface normals [S14, unofficial].
    *   **IoU (Intersection over Union):** Volumetric IoU between predicted and ground-truth occupancy grids [S14, unofficial].
    *   **Depth Error:** Absolute difference between aligned predicted and ground-truth depths, averaged over valid areas [S7].

6.  **Temporal Metrics (Video):**
    *   **tOF (Temporal Optical Flow):** Error in motion between consecutive frames compared to ground truth optical flow [S6].
    *   **tLP (Temporal Perceptual Loss):** Change in LPIPS between consecutive frames [S6].

**Pseudocode:**

```python
import torch
import numpy as np
from skimage.metrics import peak_signal_noise_ratio, structural_similarity

def extract_features(tensor):
    """Extract features from tensor. Uses identity mapping as a standard fallback [G]."""
    return tensor

def compute_lpips(render_tensor, gt_tensor):
    """Compute LPIPS as mean absolute distance between feature activations [S4]."""
    feat_render = extract_features(render_tensor)
    feat_gt = extract_features(gt_tensor)
    return torch.mean(torch.abs(feat_render - feat_gt)).item()

def compute_quantitative_metrics(rendered_images, ground_truth_images, masks=None, 
                                 depth_pred=None, depth_gt=None, 
                                 metric_types=['psnr', 'ssim', 'lpips']):
    """
    Compute quantitative evaluation metrics for a batch of rendered images.
    
    Args:
        rendered_images: List of tensors [H, W, 3] or [1, 3, H, W], values in [0, 1].
        ground_truth_images: List of tensors [H, W, 3], values in [0, 1].
        masks: Optional list of binary masks [H, W], 1 for valid pixels.
        depth_pred: Optional list of depth maps.
        depth_gt: Optional list of ground-truth depth maps.
        metric_types: List of strings specifying metrics to compute.
        
    Returns:
        Dictionary of mean metric values.
    """
    results = {'psnr': [], 'ssim': [], 'lpips': [], 'depth_error': [], 'fid': []}
    
    processed_rendered = []
    processed_gt = []
    
    for render, gt in zip(rendered_images, ground_truth_images):
        if render.dim() == 3 and render.shape[0] == 3:
            render = render.permute(1, 2, 0)
        if gt.dim() == 3 and gt.shape[0] == 3:
            gt = gt.permute(1, 2, 0)
            
        render = torch.clamp(render, 0.0, 1.0)
        gt = torch.clamp(gt, 0.0, 1.0)
        
        processed_rendered.append(render)
        processed_gt.append(gt)
        
    for i, (render, gt) in enumerate(zip(processed_rendered, processed_gt)):
        render_np = render.cpu().numpy()
        gt_np = gt.cpu().numpy()
        
        valid_mask = None
        if masks and masks[i] is not None:
            valid_mask = masks[i].cpu().numpy()
            
        if 'psnr' in metric_types:
            if valid_mask is not None:
                diff = (render_np - gt_np) ** 2
                mse = np.sum(diff * valid_mask[:, :, np.newaxis]) / (np.sum(valid_mask) * 3)
                psnr_val = 10 * np.log10(1.0 / mse) if mse > 0 else float('inf')
            else:
                psnr_val = peak_signal_noise_ratio(gt_np, render_np, data_range=1.0)
            results['psnr'].append(psnr_val)
            
        if 'ssim' in metric_types:
            ssim_val = structural_similarity(gt_np, render_np, data_range=1.0, channel_axis=2)
            results['ssim'].append(ssim_val)
            
        if 'lpips' in metric_types:
            render_tensor = render.permute(2, 0, 1).unsqueeze(0)
            gt_tensor = gt.permute(2, 0, 1).unsqueeze(0)
            lpips_val = compute_lpips(render_tensor, gt_tensor)
            results['lpips'].append(lpips_val)

    if 'depth_error' in metric_types and depth_pred and depth_gt:
        for pred, gt in zip(depth_pred, depth_gt):
            pred_aligned = pred * 1.0  # Scale alignment factor applied here [S7]
            error = torch.mean(torch.abs(pred_aligned - gt))
            results['depth_error'].append(error.item())

    if 'fid' in metric_types and len(processed_rendered) > 1:
        # FID requires batch statistics across the entire dataset [G]
        pass

    final_metrics = {}
    for key in results:
        if results[key]:
            final_metrics[key] = np.mean(results[key])
            
    return final_metrics
```

**Parameters:**
*   **LPIPS Network:** AlexNet or VGG [S7][S10, unofficial].
*   **LPIPS Normalize:** Boolean flag, typically `True` [S8, unofficial].
*   **SSIM Window:** $11 \times 11$ Gaussian, $\sigma=1.5$ [S3].
*   **Evaluation Interval:** Every 300 iterations for training progress [S3].
*   **Frame Sampling:** Interval of 5 frames, skipping keyframes [S8, unofficial].

**Edge Cases and Pitfalls:**
*   **Background Artifacts:** PSNR is sensitive to background pixels. Compute PSNR only on valid pixels (where $I_{gt} > 0$) to ignore background [S8, unofficial].
*   **HDR Tonemapping:** Synthetic HDR data must be tonemapped ($I^{1/2.2}$) and clipped before metric calculation to match the dynamic range of ground truth [S1].
*   **Depth Scale Ambiguity:** Optimized scenes are variable up to a 3D similarity; predicted depth must be scaled to match ground-truth range before computing depth error [S7].
*   **Appearance Leakage:** In appearance-aware models, naive evaluation (e.g., zero embedding) may yield structurally accurate but appearance-mismatched renders, causing perceptual metrics to fail [S12]. Use split-image protocols to isolate geometry from appearance [S12].

## Subtopics

### [Masked Metrics Evaluation](15886-masked-metrics-evaluation.md)
Masked Metrics Evaluation restricts PSNR, SSIM, LPIPS, and FLIP computation to specific regions of interest defined by a ground-truth or loss mask. It differs from standard metric computation by decoupling object-level fidelity from scene-level completeness, allowing fair comparison between object-centric and scene-centric renders.

### [FID Evaluation](18884-fid-evaluation.md)
FID evaluates the quality of generated images by measuring the similarity between the distribution of real images and generated images in a high-dimensional feature space. It sets itself apart from pixel-wise metrics like PSNR or SSIM by assessing perceptual quality and diversity rather than exact pixel reconstruction, making it suitable for evaluating the visual fidelity of radiance field renderings. It builds on [Quantitative Evaluation Metrics](9928-quantitative-evaluation-metrics.md) by providing a distributional comparison rather than a per-pixel error metric.

### Split-image Evaluation Protocol
An evaluation protocol for appearance-aware NeRF models that optimizes the appearance embedding on a subset of pixels to adapt scene appearance without directly optimizing held-out pixels, preventing information leakage while measuring perceptual similarity [S12]. Unlike the NRW baseline which encodes the entirety of a held-out image with an appearance encoder (capable of storing the image itself in high-dimensional spaces), this scheme isolates geometry from appearance and limits information leakage [S12]. Setting the embedding to zeros or mean results in plausible but structurally accurate renderings that fail to match ground truth appearance, causing perceptual metrics to fail [S12].

### Scaffold-GS Evaluation Metrics
Specific performance benchmarks for Scaffold-GS on Mip-NeRF360 and Tanks&Temples/Deep Blending datasets [S13]. On Mip-NeRF360, SSIM scores range from 0.705 (bicycle) to 0.946 (bonsai), PSNR from 24.50 (zoom) to 32.70 (bonsai), and LPIPS from 0.126 (kitchen) to 0.306 (bicycle) [S13]. Storage sizes range from 133 MB (room) to 493 MB (stump) [S13]. On Tanks&Temples/Deep Blending, SSIM scores range from 0.774 (Playroom) to 0.907 (Dr Johnson) [S13].

### Geometric and Masked Evaluation Metrics
Extends image quality metrics (PSNR, SSIM, LPIPS) with geometric reconstruction metrics: Bi-directional Chamfer L2 distance (Ch), Normal Consistency (NC), and Volumetric Intersection over Union (IoU) [S14, unofficial]. Geometric evaluation involves generating a mesh via Marching Cubes on the SDF with a resolution of $256^3$ [S14, unofficial]. Rendering is restricted to the human bounding box for comparison against segmented ground truth [S14, unofficial].

### 2D Render Evaluation Protocol
A supplementary evaluation method conducting semantics on 2D renders to complement 3D metrics, following the protocol of LERF [S15]. It computes mean Intersection over Union (mIoU) and mean accuracy (mAcc) on all classes, including background and foreground classes, on subsets of benchmark datasets [S15].

## Operating characteristics
*   **Time Complexity:** PSNR and SSIM are $O(H \cdot W)$ per image [S3]. LPIPS is $O(H \cdot W)$ but involves a forward pass through a deep network (VGG/AlexNet), making it significantly slower than PSNR/SSIM [S7][S10, unofficial]. FID requires feature extraction for all images and covariance computation, scaling with the number of images [S4].
*   **Memory Complexity:** Minimal for PSNR/SSIM [G]. LPIPS requires memory for the network weights and intermediate activations [S10, unofficial]. FID requires storing feature vectors for all real and generated images [S4].
*   **Measured Performance:** On KITTI reconstruction, NSG achieves PSNR 26.66, SSIM 0.806, LPIPS 0.186 [S6]. On Mip-NeRF360, Scaffold-GS achieves PSNR up to 32.70 and SSIM up to 0.946 [S13].
*   **Strengths:** PSNR/SSIM provide fast, interpretable pixel-level error. LPIPS correlates better with human perception [G]. FID captures global distributional fidelity [S4].
*   **Limitations:** PSNR/SSIM are sensitive to background and misalignment. LPIPS is computationally expensive. FID does not provide per-image feedback.
*   **When to Use:** Use PSNR/SSIM for rapid iteration and baseline comparison [G]. Use LPIPS for perceptual quality assessment [G]. Use FID for generative model evaluation. Use geometric metrics when 3D structure is critical [S14, unofficial].

## Background
Quantitative evaluation metrics for NeRF and radiance fields originated with the seminal NeRF paper [S5], which established PSNR, SSIM, and LPIPS as the standard suite for novel view synthesis evaluation. Subsequent works introduced specialized metrics: FID for texture and appearance distribution evaluation [S4], temporal metrics (tOF, tLP) for dynamic scenes [S6], and geometric metrics (Ch, NC, IoU) for reconstruction accuracy [S14, unofficial]. The split-image protocol was introduced to address appearance leakage in unconstrained photo collections [S12].
