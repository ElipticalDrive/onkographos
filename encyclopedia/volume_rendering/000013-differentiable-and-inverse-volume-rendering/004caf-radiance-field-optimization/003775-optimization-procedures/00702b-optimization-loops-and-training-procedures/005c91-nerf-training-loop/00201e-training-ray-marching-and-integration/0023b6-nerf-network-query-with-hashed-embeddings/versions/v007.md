# NeRF Network Query with Hashed Embeddings

Also called: HashNeRF query, Instant-NGP NeRF, NeRF with Hash Encoding, NeRF with Multiresolution Hash Encoding, Neural Radiance and Density Fields (NeRF) with Multiresolution Hash Encoding

## Overview
This method queries a neural radiance field by mapping 3D spatial coordinates and 2D view directions into a high-dimensional feature space using a multiresolution hash encoding, then passing these features through concatenated Multi-Layer Perceptrons (MLPs) to predict volume density and view-dependent color [S2]. It sets itself apart from standard NeRF by replacing positional encoding with a learnable, sparse hash grid that allows for significantly faster training and rendering on modern GPUs, while avoiding the memory overhead of dense voxel grids [S2].

## How it works
**Inputs and Outputs:**
*   **Inputs:** 3D spatial coordinates $\mathbf{x} \in \mathbb{R}^3$, view direction $\mathbf{d} \in \mathbb{R}^3$ (unit vector).
*   **Outputs:** Volume density $\sigma$ (scalar) and RGB color $\mathbf{c} \in \mathbb{R}^3$.

**Data Structures:**
*   **Hash Grid:** A set of $L$ resolution levels. Each level $l$ has a hash table of size $T_l$ and a feature dimension $F$. The hash table maps hashed coordinates to feature vectors of size $F$.
*   **MLPs:** Two networks:
    1.  **Density MLP:** 1 hidden layer, 64 neurons.
    2.  **Color MLP:** 2 hidden layers, 64 neurons.

**Parameters:**
*   **Hash Table Sizes:** $T_l$ scales with resolution (e.g., $2^{18}$ to $2^{24}$) [S2].
*   **Feature Dimension ($F$):** Typically 2 per resolution level [S2].
*   **Batch Size (`netchunk`):** Default 65536 (1024*64) to avoid Out-Of-Memory errors [S1, unofficial].
*   **Spherical Harmonics Degree:** 4 (first 16 coefficients) [S2].
*   **Activation:** Sigmoid for sRGB data; Exponential for HDR data [S2].

**Steps:**
1.  **Reshape Inputs:** Flatten the input batch of positions $\mathbf{x}$ to shape $(-1, 3)$ [S1, unofficial].
2.  **Position Embedding:** Apply the multiresolution hash encoding function `embed_fn` to $\mathbf{x}$. This involves:
    *   For each resolution level $l$, hashing the coordinates of $\mathbf{x}$ into the hash table for level $l$.
    *   Retrieving the $F$-dimensional feature vector for each level.
    *   Concatenating the feature vectors from all $L$ levels along the last dimension to form the encoded position $\mathbf{y}$ [S2].
    *   Generating a validity mask `keep_mask` to identify points within the bounding box [S1, unofficial].
3.  **Direction Embedding (if applicable):** If view directions $\mathbf{d}$ are provided:
    *   Expand $\mathbf{d}$ to match the batch size of $\mathbf{x}$ [S1, unofficial].
    *   Reshape $\mathbf{d}$ to $(-1, 3)$ [S1, unofficial].
    *   Project $\mathbf{d}$ onto the first 16 coefficients of the spherical harmonics basis (degree 4) to create a 16-dimensional direction feature [S2].
4.  **Concatenate Features:** Concatenate the encoded position $\mathbf{y}$ and the direction feature along the last dimension to form the input for the Color MLP [S1, unofficial][S2].
5.  **Density Prediction:** Pass $\mathbf{y}$ through the Density MLP. The output is a vector of 16 values. The first value is treated as the log-space density $\log(\sigma)$ [S2].
6.  **Color Prediction:** Pass the concatenation of the Density MLP output and the direction feature through the Color MLP. The output is an RGB triplet [S2].
7.  **Apply Activation:** Apply Sigmoid or Exponential activation to the RGB output based on the data type (sRGB or HDR) [S2].
8.  **Handle Invalid Points:** Set $\sigma = 0$ and $\mathbf{c} = 0$ for points where `keep_mask` is False [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn as nn
import math

class HashGrid:
    """Simplified hash grid for demonstration."""
    def __init__(self, num_levels, level_dim, resolution):
        self.num_levels = num_levels
        self.level_dim = level_dim
        self.resolution = resolution
        # In practice, this is a large hash table mapping coordinates to features
        self.grids = [nn.Embedding(resolution, level_dim) for _ in range(num_levels)]

    def forward(self, x):
        # x shape: (N, 3)
        # Hashing logic omitted for brevity; assumes x is hashed to indices
        # and features are retrieved and concatenated
        features = []
        for i in range(self.num_levels):
            # Placeholder for actual hashing and indexing
            indices = self.hash_function(x, self.resolution[i]) 
            features.append(self.grids[i](indices))
        return torch.cat(features, dim=-1)

class NeRFQuery(nn.Module):
    def __init__(self, hash_grid, density_mlp, color_mlp, use_hdr=False):
        super().__init__()
        self.hash_grid = hash_grid
        self.density_mlp = density_mlp
        self.color_mlp = color_mlp
        self.use_hdr = use_hdr
        self.sh_degree = 4
        self.sh_coeffs = 2 * self.sh_degree * (self.sh_degree + 1) # 16

    def spherical_harmonics(self, d):
        """Project direction d onto first 16 SH coefficients."""
        # Simplified projection; in practice, uses precomputed SH basis
        # d shape: (N, 3)
        # Output shape: (N, 16)
        return torch.zeros(d.shape[0], self.sh_coeffs, device=d.device) # Placeholder

    def forward(self, x, d=None):
        # x shape: (N, 3)
        # d shape: (N, 3) or None
        
        # 1. Position Embedding
        y = self.hash_grid(x) # Concatenated features from all resolutions
        
        # 2. Direction Embedding
        if d is not None:
            d_sh = self.spherical_harmonics(d)
            # Concatenate position features and direction features
            input_color = torch.cat([y, d_sh], dim=-1)
        else:
            input_color = y
            
        # 3. Density MLP
        density_out = self.density_mlp(y) # (N, 16)
        log_sigma = density_out[:, 0]     # First value is log density
        sigma = torch.exp(log_sigma)      # Convert to density
        
        # 4. Color MLP
        color_out = self.color_mlp(input_color) # (N, 3)
        
        # 5. Activation
        if self.use_hdr:
            color = torch.exp(color_out)
        else:
            color = torch.sigmoid(color_out)
            
        return sigma, color
```

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** Different coordinates may hash to the same index, causing "grainy" microstructure artifacts. The MLP cannot fully compensate for this [S2].
*   **Dimensionality Reduction:** Concatenating features is preferred over reducing them (e.g., summing) because reduction may result in a feature dimension too small to encode useful information [S2].
*   **Invalid Points:** Points outside the bounding box must be masked out to prevent invalid density/color predictions [S1, unofficial].

## Subtopics

### [HybridNeRF Model Architecture](4842-hybridnerf-model-architecture.md)
HybridNeRF combines dense multi-resolution 3D feature grids with multi-resolution triplanes to accelerate training and rendering. It sets itself apart from pure grid-based methods like Instant-NGP by incorporating triplanes for anisotropic feature resolution, and from pure MLP methods by avoiding the computational cost of deep networks for every sample point.

### [MVS Network Query](7517-mvs-network-query.md)
MVS Network Query prepares inputs for a neural network by embedding points and view directions, then applies the network in batches to generate features for multi-view stereo (MVS) rendering. It differs from standard NeRF network queries by explicitly handling multi-view geometric consistency through the generation of angle and point features derived from camera poses and depth candidates, rather than relying solely on spatial coordinates and view directions for a single viewpoint.

### SqueezeNeRF
SqueezeNeRF is a memory-efficient neural rendering method that factorizes the position-dependent MLP of FastNeRF into three separate 2D networks operating on coordinate pairs $(x,y)$, $(y,z)$, and $(z,x)$ to reduce cache size complexity from $O(n^3)$ to $O(n^2)$ [S1, unofficial]. It builds on NeRF Network Query with Hashed Embeddings by replacing the dense 3D position cache with a set of 2D position caches and a 2D direction cache, enabling real-time inference with significantly lower memory overhead than FastNeRF or NeRF-SH while maintaining high rendering speeds [S1, unofficial].

### VoxNeRF
VoxNeRF integrates explicit scene geometry priors (mesh, point cloud, or depth map) with implicit radiance field representation to improve sampling efficiency and reconstruction accuracy [S1, unofficial]. It addresses the ill-posed nature of recovering 3D geometry from 2D images by using a Sparse Voxel Octree (SVO) to model geometric uncertainty, which guides a hybrid sampling strategy [S1, unofficial]. Unlike standard NeRF methods that sample uniformly or via stratified noise, VoxNeRF concentrates samples near the estimated surface while maintaining coverage of free space, reducing computational waste in empty regions [S1, unofficial].

### [Deformation Field Integration for Telepresence](10866-deformation-field-integration-for-telepresence.md)
This method extends the FastNeRF architecture to support dynamic, expression-driven head avatars for telepresence by integrating a learnable deformation field network ($F_{deform}$) and a non-trainable skeletal deformation field ($F_{bone}$) into the ray marching process. It solves the problem of rendering animatable 3D heads from static multi-view images by warping sample positions based on an expression vector before querying the radiance field. It is distinguished from static NeRF variants by its explicit handling of temporal expression parameters and from other dynamic NeRF methods by its specific integration with the FastNeRF caching infrastructure and grid-based pruning.

### [HDR-HexPlane](13548-hdr-hexplane.md)
HDR-HexPlane is an end-to-end neural radiance field framework for dynamic scenes that learns 3D scene representations from dynamic 2D images captured with various exposures, allowing for novel view synthesis with adjustable exposure levels. It explicitly separates the modeling of dynamic scene geometry/radiance from the learning of scene illumination (exposure), addressing color inconsistency caused by objects moving between dark and bright regions. Unlike static HDR-NeRF methods, HDR-HexPlane handles dynamic scenes by incorporating temporal information (timestamp $t$) into the HexPlane representation.

### [Multi-scale PointNeRF++ Feature Aggregation](13651-multi-scale-pointnerf-feature-aggregation.md)
Multi-scale PointNeRF++ is a method for obtaining radiance ($\rho_q$) and density ($\sigma_q$) for a query point $q$ by operating on a sparse, hierarchical point cloud representation at multiple granularity levels. It solves the problem of rendering in empty regions without relying on failure-prone region-growing heuristics. Unlike its sibling PointNeRF, this method naturally fills empty regions by averaging feature embeddings over valid scale levels where neighbors exist. It builds on NeRF Network Query with Hashed Embeddings by replacing hash grids with a multi-scale point cloud hierarchy.

### FourieRF
A few-shot NeRF estimation method that parameterizes grid-based NeRF features using a Fourier Transform prior to control frequency bands, avoiding high-frequency artifacts and overfitting in sparse data scenarios.

### [Hash-grid anti-aliasing and regularization](15594-hash-grid-anti-aliasing-and-regularization.md)
This family encompasses techniques that modify the hash-grid encoding mechanism in neural radiance fields to mitigate artifacts such as high-frequency aliasing and sparse-view floaters. It differs from standard hash-grid encoding by introducing either capacity constraints (smaller hash tables) to enforce feature sharing and geometric consistency, or statistical down-weighting factors to suppress high-frequency noise during rendering.

### [NeRF-W](15666-nerf-w.md)
A method for robust neural radiance fields in unconstrained photo collections, addressing transient objects (moving/occluding) and uncertainty in camera poses.

### Stratified PDF Sampling for NeRF
A method to resample points along a ray based on the importance (weight) of previous samples, improving detail in high-density regions [S3, unofficial]. It normalizes bin weights by adding epsilon (1e-5) and dividing by sum to create a PDF, computes the CDF by cumsumming the PDF and padding with zeros at the start, generates uniform random values $u$ in $[0, 1]$ (or deterministic midpoints if `det=True`), finds indices in the CDF where $u$ falls using `searchsorted`, identifies lower and upper bin indices for interpolation, and interpolates the final sample position within the bin using linear interpolation based on $u$'s position in the CDF interval [S3, unofficial].

### MikeLee Method
A sparse neural rendering method that explicitly conditions the color prediction network on local features extracted from a pretrained network to improve color and feature consistency [S4]. It extracts local features $F_{gt}(r)$ from a pretrained VGG network's Relu1-1 layer for each ray $r$, concatenates bottleneck feature $b_i$, prior feature $f_i$, and view direction $d$, and predicts color $c_i = M_c(b_i, f_i, d)$ [S4]. The loss function is $L = L_c + \lambda L_f$, where $L_f = || F(r) - F^{gt}(r) ||_2$ [S4]. It uses the Relu1-1 layer because it is the same size as the input image, avoiding interpolation artifacts from deeper layers [S4]. Training is done at low resolution for 44K iterations, with frequency regulation ending at 40K iterations, and a batch size of 1024 due to memory limitations [S4].

### Appearance Matching
A post-training optimization step to ensure consistent appearance across adjacent Block-NeRFs by matching an appearance latent code from a target Block-NeRF to its neighbors [S5]. It selects a 3D matching location between pairs of adjacent Block-NeRFs where visibility prediction is high for both blocks, freezes the Block-NeRF network weights, and optimizes only the appearance code of the adjacent Block-NeRF to match the target appearance [S5]. Without this, randomly initialized appearance codes lead to different appearances in different blocks, causing inconsistencies during compositing [S5].

## Operating characteristics
*   **Time Complexity:** Training time is significantly reduced compared to standard NeRF. For example, 5 seconds to accumulate 128 samples at 1080p on a single RTX 3090 GPU for a modular synthesizer scene [S2].
*   **Memory Complexity:** The hash grid is sparse, but the total memory usage depends on the number of hash tables and their sizes. The MLPs are small (64 neurons), keeping memory overhead low [S2].
*   **Performance:** Rendering performance can reach 10 frames per second on an RTX 3090 GPU for a large natural 360 scene [S2].
*   **Strengths:** Fast training and rendering, ability to handle large scenes, support for HDR data.
*   **Limitations:** Hash collisions can cause artifacts, which the MLP can only partially mitigate [S2]. Replacing the MLP with a direct linear lookup significantly compromises quality, failing to capture specular effects and resolve hash collisions, despite being cheaper [S2].

## Background
The method was introduced by Müller et al. in "Instant Neural Graphics Primitives with a Multiresolution Hash Encoding" [S2]. It builds on the original NeRF architecture by Mildenhall et al. [2020] [S2]. The key innovation is the use of a multiresolution hash encoding to map 3D coordinates to a high-dimensional feature space, enabling efficient training and rendering of neural radiance fields.
