# PSNR Evaluation Pipeline

Also called: NeRF validation loop, PSNR calculation, Quantitative Evaluation, Test Set PSNR, Validation and PSNR Evaluation Pipeline

## Overview
The PSNR Evaluation Pipeline computes the Peak Signal-to-Noise Ratio (PSNR) on held-out test or validation splits to quantitatively assess the rendering quality of a trained Neural Radiance Field (NeRF) [S1, unofficial]. It differs from training loops by disabling gradient computation, replacing active raymarching with inference-optimized variants, and aggregating pixel-wise Mean Squared Error (MSE) into a global mean score [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A trained NeRF model (coarse and/or fine), dataset metadata (camera poses, intrinsics, resolution), and a dataset split identifier ("test" or "val") [S1, unofficial].
*   **Outputs:** A scalar mean PSNR value, per-view PSNR scores, and optionally side-by-side visual comparisons of ground truth and rendered images [S1, unofficial][S2, unofficial].

**Data Structures:**
*   **State:** An evaluation state object containing inference-specific raymarching and rendering functions, distinct from the training state [S2, unofficial].
*   **Images:** Ground truth (GT) and rendered images are stored as arrays with shape `(Height, Width, Channels)` or `(Channel, Height, Width)`, normalized to $[0, 1]$ [S1, unofficial][S2, unofficial].

**Steps:**
1.  **Load Data:** Load the scene metadata and images for the specified split. Images are typically loaded at half resolution for faster evaluation [S1, unofficial].
    *   `data = load_blender_data(scene, split="test", half_res=True)`
2.  **Initialize Evaluation State:** Replace the training raymarching and rendering functions with their inference counterparts to disable gradients and optimize for speed [S2, unofficial].
    *   `state_eval = state.replace(raymarch=args.raymarch_eval, render=args.render_eval)`
3.  **Prepare Ground Truth:** Composite ground truth RGBA images with a white background to ensure consistent comparison against rendered RGB images [S1, unofficial].
    *   `test_imgs = composite_white(test_imgs)`
4.  **Iterate and Render:** For each view in the validation/test set:
    *   Extract camera transforms [S2, unofficial].
    *   Render the image using chunked ray marching to manage memory [S1, unofficial].
    *   `bg, rgb, depth, _ = render_image_inference(key, val_transform, state_eval)`
5.  **Blend and Align:** Blend the ground truth RGBA image with the rendered background to handle transparency and ensure pixel alignment [S2, unofficial].
    *   `gt_rgbs_f32 = blend_rgba_image_array(gt_rgba_u8 / 255.0, rendered_bg)`
6.  **Compute Metrics:**
    *   Calculate MSE between the aligned ground truth RGB and rendered RGB [S1, unofficial][S2, unofficial].
        $$ \text{MSE} = \frac{1}{N} \sum_{i=1}^{N} (P_i - G_i)^2 $$
        Where $P_i$ is the predicted pixel value and $G_i$ is the ground truth pixel value.
    *   Compute PSNR from MSE [S1, unofficial].
        $$ \text{PSNR} = 10 \cdot \log_{10}\left(\frac{1}{\text{MSE}}\right) $$
        *Note: If MSE is 0, PSNR is infinite. In practice, a small epsilon or clamping is applied to avoid NaN/Inf [S1, unofficial].*
7.  **Aggregate:** Accumulate PSNR scores across all views. Compute the mean and standard deviation [S1, unofficial].
    *   `mean_psnr = sum(psnr_scores) / len(psnr_scores)`
8.  **Visualize (Optional):** Create side-by-side comparisons of GT, rendered RGB, and depth maps for qualitative inspection [S2, unofficial].

**Parameters:**
*   `split`: Dataset split to evaluate ("test" or "val") [S1, unofficial].
*   `half_res`: Boolean flag to load images at half resolution for faster evaluation [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Zero MSE:** If a rendered image perfectly matches the ground truth, MSE is 0, leading to infinite PSNR. Implementation must handle this by capping PSNR or adding a small epsilon to MSE [S1, unofficial].
*   **Resolution Mismatch:** Ensure GT and rendered images have identical dimensions before computing MSE [S1, unofficial].
*   **Background Handling:** GT images may have alpha channels; rendered images are typically RGB. Blending GT with a white background is required for fair comparison [S1, unofficial][S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and views. Chunked rendering helps manage memory but adds overhead. Half-resolution evaluation reduces time by ~4x compared to full resolution [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of pixels per view and the number of views. Chunking limits peak memory usage during rendering [S1, unofficial].
*   **Strengths:** Standard, interpretable metric for image quality. Fast to compute once rendering is done.
*   **Limitations:** PSNR correlates poorly with perceptual quality compared to SSIM or LPIPS. It is sensitive to pixel misalignment and does not account for structural similarity [S1, unofficial].
*   **When to Use:** Standard benchmarking for NeRF variants. Not sufficient alone for perceptual quality assessment.

## Background
The PSNR evaluation pipeline is a standard component in NeRF research, originating from the original NeRF paper [S1, unofficial]. It is widely used in the NeRF-Synthetic (Blender) dataset benchmarks to compare different NeRF architectures and training strategies [S1, unofficial]. The use of half-resolution evaluation is a common optimization in implementations like the one described in [S1, unofficial].
