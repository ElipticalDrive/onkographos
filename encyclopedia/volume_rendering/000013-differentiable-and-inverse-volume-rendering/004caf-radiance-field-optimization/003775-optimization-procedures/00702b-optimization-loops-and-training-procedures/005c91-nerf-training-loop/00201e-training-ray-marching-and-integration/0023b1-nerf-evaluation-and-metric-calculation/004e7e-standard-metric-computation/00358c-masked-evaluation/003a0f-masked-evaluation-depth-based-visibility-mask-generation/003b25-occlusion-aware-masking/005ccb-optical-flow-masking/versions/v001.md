# Optical Flow Masking

Also called: Flow-based Occlusion Masking, Optical Flow Validity Masking

## Overview
Optical Flow Masking distinguishes between valid and invalid optical flow areas to handle occlusion and lighting errors during NeRF optimization [S1]. It sets aside regions where geometric inconsistencies or artifacts would corrupt feature-level regularization, building on [Occlusion-Aware Masking](8889-occlusion-aware-masking.md) by using pixel-space flow consistency rather than just depth-based visibility [S1].

## How it works
**Inputs:** Two adjacent RGB images (source $I_a$, target $I_b$), forward optical flow field $f_{a \to b}$, backward optical flow field $f_{b \to a}$, image dimensions $H \times W$, and a threshold $\theta$.
**Outputs:** A binary validity mask $M_{a \to b}$ of size $H \times W$.

**Data Structures:**
- $f_{a \to b}(r, c)$: 2D vector $(u, v)$ representing flow at pixel $(r, c)$.
- $M_{a \to b}$: Binary matrix, $M_{a \to b}(r, c) \in \{0, 1\}$.

**Steps:**
1. Compute forward corresponding point coordinates $F_{a \to b}(r, c)$ for all $r \in [0, H], c \in [0, W]$:
   $$F_{a \to b}(r, c) = (r, c) + f_{a \to b}(r, c)$$
   Similarly for backward flow $F_{b \to a}(r, c) = (r, c) + f_{b \to a}(r, c)$ [S1].
2. Calculate the absolute difference $d$ between the target ground-truth image $True_{rgb}$ and the source image warped by the flow:
   $$d = |Flow_{rgb} - True_{rgb}|$$
   Where $Flow_{rgb}$ is the pixel value at $F_{a \to b}(r, c)$ sampled from $I_a$, and $True_{rgb}$ is the pixel value at $(r, c)$ in $I_b$ [S1].
3. Set the mask value $M_{a \to b}(r, c)$:
   $$M_{a \to b}(r, c) = \begin{cases} 1 & \text{if } d \le \theta \text{ and } F_{a \to b}(r, c) \in [W, H] \\ 0 & \text{otherwise} \end{cases}$$
   The condition $F_{a \to b}(r, c) \in [W, H]$ checks if the corresponding point lies within the image bounds [S1].

**Parameters:**
- $\theta$: Threshold between optical flow prediction and ground truth. Not given in the sources.

**Edge Cases:**
- If $F_{a \to b}(r, c)$ falls outside image bounds, the mask is 0 [S1].
- Lighting changes or occlusions cause large $d$, resulting in mask 0 [S1].

```python
def compute_optical_flow_mask(I_a, I_b, f_a_to_b, H, W, theta):
    """
    I_a: Source image (H, W, 3)
    I_b: Target image (H, W, 3)
    f_a_to_b: Forward flow field (H, W, 2)
    H, W: Image height and width
    theta: Consistency threshold
    """
    mask = np.zeros((H, W), dtype=np.float32)
    
    # Get coordinates
    rows, cols = np.meshgrid(np.arange(H), np.arange(W), indexing='ij')
    
    # Compute corresponding points
    # f_a_to_b contains (dx, dy)
    fx = cols + f_a_to_b[:, :, 0]
    fy = rows + f_a_to_b[:, :, 1]
    
    # Check bounds
    valid_bounds = (fx >= 0) & (fx < W) & (fy >= 0) & (fy < H)
    
    # Sample warped source image
    # Clamp coordinates for sampling to avoid index errors, though valid_bounds handles logic
    fx_clamped = np.clip(fx, 0, W - 1).astype(np.int32)
    fy_clamped = np.clip(fy, 0, H - 1).astype(np.int32)
    
    # Get RGB values from source image at corresponding points
    # Note: I_a shape is (H, W, 3)
    flow_rgb = I_a[fy_clamped, fx_clamped]
    
    # Calculate absolute difference
    d = np.abs(flow_rgb.astype(np.float32) - I_b.astype(np.float32))
    
    # Sum differences across channels (or use mean, source says "absolute difference")
    # Source implies scalar d, likely sum or max of channel diffs
    d_scalar = np.sum(d, axis=2)
    
    # Apply threshold and bounds
    valid_flow = d_scalar <= theta
    
    mask = (valid_bounds & valid_flow).astype(np.float32)
    
    return mask
```

## Operating characteristics
Time and memory complexity: Not given in the sources.
Measured performance: Not given in the sources.
Scaling: Not given in the sources.
Strengths and limitations: Handles occlusion and lighting errors effectively [S1]. Limitations include sensitivity to lighting changes and occlusions which generate invalid flow areas [S1].
When to use it: When using optical flow to guide view synthesis or feature regularization in NeRF, specifically to ignore invalid flow regions [S1].
When not: When high-quality depth and pose information is available for rigid flow subtraction (use Per-Frame Soft Dynamism Masks instead) [S2, unofficial].

## Background
Origin: Introduced in "Bidirectional Optical Flow NeRF: High Accuracy and High Quality under Fewer Views" [S1].
History and development: Used to preprocess optical flow graphs before NeRF optimization to ensure correct and photorealistic novel views under fewer input views [S1].
Where it is used: In NeRF training loops that incorporate bidirectional optical flow constraints [S1].
