# Deformable 3DGS

Also called: 4D Gaussian Splatting, Dynamic 3DGS

## Overview
Deformable 3DGS extends static 3D Gaussian Splatting to dynamic scenes by modeling time-varying geometry and appearance [S1, S2, unofficial]. It solves the problem of rendering moving objects (e.g., people, fluids) by decomposing the representation into a static canonical space and a time-dependent deformation field [S2, unofficial]. Unlike static 3DGS, it predicts deltas to canonical parameters based on a time parameter $t$, enabling real-time rendering of dynamic content [S1, S2, unofficial].

## How it works
**Inputs:** A set of canonical 3D Gaussians $\mathcal{G}_{canon}$, multi-view video sequences of a dynamic scene, and camera poses for each frame.
**Outputs:** A rendered image sequence and optimized canonical parameters and deformation network weights.

**Data Structures:**
1.  **Canonical Gaussian $i$**: Stores static base parameters $(\boldsymbol{\mu}_i, \mathbf{q}_i, \mathbf{s}_i, \alpha_i, \mathbf{c}_{SH,i})$ [S1, unofficial].
2.  **Deformation Network $f_\theta$**: An MLP (or HexPlane decomposition) that takes canonical features and time $t$ as input [S1, S2, unofficial].
3.  **Time Parameter $t$**: Normalized timestamp in $[0, 1]$ [S1, unofficial].

**Method Steps:**
1.  **Initialization**: Initialize canonical Gaussians $\mathcal{G}_{canon}$ from static reconstruction or SfM points [S1, unofficial].
2.  **Deformation Prediction**: For each Gaussian $i$ and time $t$, compute deformation deltas using the network:
    $$ \Delta\boldsymbol{\mu}_i = f_\theta(\boldsymbol{\mu}_i, t) $$
    $$ \Delta\mathbf{q}_i = f_\theta(\mathbf{q}_i, t) $$
    $$ \Delta\mathbf{s}_i = f_\theta(\mathbf{s}_i, t) $$
    *Note: Specific input features to $f_\theta$ vary by variant (e.g., per-Gaussian features, HexPlane coordinates) [S1, S2, unofficial].*
3.  **Time-Varying Parameter Update**: Compute the instantaneous parameters for rasterization [S1, unofficial]:
    $$ \boldsymbol{\mu}_i(t) = \boldsymbol{\mu}_i + \Delta\boldsymbol{\mu}_i $$
    $$ \mathbf{q}_i(t) = \text{Normalize}(\mathbf{q}_i \otimes \Delta\mathbf{q}_i) $$
    $$ \mathbf{s}_i(t) = \mathbf{s}_i + \Delta\mathbf{s}_i $$
    where $\otimes$ is quaternion multiplication and normalization prevents drift [G].
4.  **Rendering**: Rasterize the set $\mathcal{G}(t)$ using standard differentiable rasterization with the camera pose and time $t$ [S1, unofficial].
5.  **Optimization**: Minimize photometric loss $\mathcal{L} = \mathcal{L}_{rec} + \lambda \mathcal{L}_{reg}$ via SGD, updating canonical parameters, features, and network weights [S1, unofficial].

**Parameters:**
*   $\lambda$: Regularization weight. Value not given in the sources.
*   Network Architecture: MLP or HexPlane. HexPlane is a compact decomposition used in 4DGS [S2, unofficial].

**Edge Cases:**
*   **Quaternion Drift**: Without normalization, $\mathbf{q}_i(t)$ drifts from unit length, causing artifacts [G].
*   **Temporal Consistency**: Discrete per-frame deformation can lead to jitter; smooth deformation fields (e.g., splines) mitigate this [S3, unofficial].

## Subtopics

### SplineGS
SplineGS replaces discrete per-frame deformation with a smooth spline modeling the trajectory of each primitive's center and rotation as a function of time [S3, unofficial]. It ensures physically plausible, smooth motion with fewer parameters [S3, unofficial]. The position is computed as:
$$ \mu_i(t) = \sum_{k=0}^K \mathbf{B}_k(t) \mathbf{p}_{i,k} $$
where $\mathbf{B}_k$ are B-spline basis functions and $\mathbf{p}_{i,k}$ are control points [S3, unofficial].

### VolSegGS
VolSegGS segments and tracks structures across timesteps in dynamic volumetric scenes using deformable 3D Gaussians, avoiding grid-based memory constraints [S2, unofficial]. It employs a two-level segmentation strategy guided by an affinity field network, allowing it to split segments beneath thin, semi-transparent layers and resolve inner color variations [S1, unofficial]. Unlike 4DGS, which relies on expensive k-NN regularization, VolSegGS uses a hybrid deformation network for spatial smoothness, balancing real-time performance and segmentation accuracy [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: Real-time rendering is maintained if the deformation network is lightweight (e.g., HexPlane) [S2, unofficial]. MLP-based deformation adds inference overhead per Gaussian [S1, unofficial].
*   **Memory Complexity**: Higher than static 3DGS due to stored deformation network weights and potentially additional features [S2, unofficial].
*   **Strengths**: Real-time rendering of dynamic scenes; compact representation compared to voxel-based methods [S1, S2, unofficial].
*   **Limitations**: Requires multi-view video for training; deformation artifacts may occur with complex non-rigid motion if the network capacity is insufficient [S1, unofficial].
*   **When to use**: Dynamic scenes with people, fluids, or articulated objects [S1, unofficial].
*   **When not to use**: Static scenes (use standard 3DGS) or scenes requiring explicit mesh extraction (use SuGaR) [S1, unofficial].

## Background
Deformable 3DGS was introduced by Yang et al. in CVPR'24 [S2, unofficial]. It builds on the success of 3D Gaussian Splatting by adding temporal modeling capabilities [S2, unofficial]. The method is part of the broader family of 4D Gaussian Splatting techniques, which include variants like 4DGS (Wu et al., CVPR'24) using HexPlane decoders [S2, unofficial].
