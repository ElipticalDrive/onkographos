# Deformable 3DGS

Also called: 4D Gaussian Splatting, Dynamic 3DGS

## Overview
Deformable 3DGS extends static 3D Gaussian Splatting to dynamic scenes by modeling time-varying geometry and appearance. It solves the problem of reconstructing and rendering moving objects (e.g., people, fluids) from multi-view video by predicting deformation deltas for canonical Gaussians based on a time parameter $t$ [S1, S2, unofficial]. It distinguishes itself from sibling methods like Sparse-Controlled 3D Gaussian Splatting by using a dense deformation network (MLP or HexPlane) rather than sparse control points, offering a trade-off between flexibility and computational overhead [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Multi-view video frames at various timestamps $t$; camera poses; initial canonical Gaussian set $\mathcal{G}_{canon}$ (position $\boldsymbol{\mu}$, rotation $\mathbf{q}$, scale $\mathbf{s}$, opacity $\alpha$, SH coefficients $\mathbf{c}_{SH}$).
*   **Outputs:** Time-varying Gaussian set $\mathcal{G}(t)$ for any $t \in [0, 1]$; rendered images.

**Data Structures:**
The canonical Gaussian $i$ stores static base parameters. The deformation is handled by a network $f_\theta$ (MLP or HexPlane) that takes the canonical features and time $t$ as input to output deltas.
*   **Canonical Gaussian $i$:**
    *   $\boldsymbol{\mu}_i \in \mathbb{R}^3$: Position.
    *   $\mathbf{q}_i \in \mathbb{R}^4$: Rotation quaternion.
    *   $\mathbf{s}_i \in \mathbb{R}^3$: Scale.
    *   $\alpha_i \in \mathbb{R}$: Opacity.
    *   $\mathbf{c}_{SH,i}$: Spherical Harmonic coefficients.
    *   *Optional:* Per-Gaussian feature vector $\mathbf{f}_i$ used as input to the deformation network [S2, unofficial].

**Deformation Network:**
The core mechanism predicts deltas $(\Delta\boldsymbol{\mu}_i, \Delta\mathbf{q}_i, \Delta\mathbf{s}_i)$ using a function $f_\theta$. Common implementations include:
1.  **MLP:** $f_\theta(\mathbf{f}_i, t) \to (\Delta\boldsymbol{\mu}_i, \Delta\mathbf{q}_i, \Delta\mathbf{s}_i)$ [S1, unofficial].
2.  **HexPlane Decomposition:** A compact 4D encoder that decomposes spacetime into 2D planes to predict deltas efficiently [S2, unofficial].
3.  **Polynomial Bases:** Using basis functions to model trajectories [S1, unofficial].

**Numbered Steps:**
1.  **Initialization:** Initialize canonical Gaussians $\mathcal{G}_{canon}$ from static reconstruction or SfM points. Initialize deformation network parameters $\theta$.
2.  **Time Sampling:** For a training batch, sample a time $t$ uniformly from $[0, 1]$ (or normalized timestamp).
3.  **Delta Prediction:** For each Gaussian $i$, compute deltas:
    $$ \Delta\boldsymbol{\mu}_i = f_\theta^{\mu}(\mathbf{f}_i, t) $$
    $$ \Delta\mathbf{q}_i = f_\theta^{q}(\mathbf{f}_i, t) $$
    $$ \Delta\mathbf{s}_i = f_\theta^{s}(\mathbf{f}_i, t) $$
    [S1, S2, unofficial].
4.  **Parameter Update:** Compute time-varying parameters:
    $$ \boldsymbol{\mu}_i(t) = \boldsymbol{\mu}_i + \Delta\boldsymbol{\mu}_i $$
    $$ \mathbf{q}_i(t) = \text{Normalize}(\mathbf{q}_i \otimes \Delta\mathbf{q}_i) $$
    $$ \mathbf{s}_i(t) = \mathbf{s}_i + \Delta\mathbf{s}_i $$
    [Parent, S1, unofficial]. Note: $\otimes$ is quaternion multiplication; normalization prevents drift [G].
5.  **Rendering:** Rasterize $\mathcal{G}(t)$ using standard differentiable Gaussian splatting rasterizer with camera pose and time $t$ [S1, unofficial].
6.  **Optimization:** Minimize photometric loss $\mathcal{L} = \mathcal{L}_{rec} + \lambda \mathcal{L}_{reg}$ between rendered and ground truth images. Update $\mathcal{G}_{canon}$, $\mathbf{f}_i$, and $\theta$ via SGD [S2, unofficial].

**Parameters:**
*   $t$: Normalized time, typically $[0, 1]$.
*   $\lambda$: Regularization weight (e.g., for smoothness or magnitude of deltas). Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Quaternion Drift:** Without normalization, $\mathbf{q}_i(t)$ drifts from unit length, causing scaling artifacts [G].
*   **Temporal Consistency:** Discrete MLP outputs may cause jitter; HexPlane or spline-based methods (see Subtopics) mitigate this [S3, unofficial].
*   **Degenerate Input:** Static regions may overfit to noise if deformation network is too expressive; regularization is critical [S2, unofficial].

## Subtopics

### SplineGS
SplineGS replaces the discrete per-frame deformation prediction with a smooth spline model for each primitive's trajectory [S3, unofficial]. It ensures physically plausible, smooth motion with fewer parameters by modeling position and rotation as functions of time using B-spline basis functions [S3, unofficial].
**Formula:**
$$ \boldsymbol{\mu}_i(t) = \sum_{k=0}^K \mathbf{B}_k(t) \mathbf{p}_{i,k} $$
where $\mathbf{B}_k$ are B-spline basis functions and $\mathbf{p}_{i,k}$ are control points [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering is $O(N)$ per pixel, same as static 3DGS, but requires evaluating the deformation network $f_\theta$ for each Gaussian per frame [S1, unofficial].
*   **Memory Complexity:** $O(N \cdot D)$ where $D$ is the size of the deformation network parameters plus per-Gaussian features [S2, unofficial]. HexPlane variants reduce $D$ significantly compared to dense MLPs [S2, unofficial].
*   **Performance:** Real-time rendering is achievable with efficient implementations (e.g., HexPlane) [S2, unofficial].
*   **Strengths:** Handles complex, non-rigid deformations; real-time rendering possible.
*   **Limitations:** Requires careful regularization to avoid temporal flickering; higher memory than static GS if dense features are used [S2, unofficial].
*   **When to use:** Dynamic scenes with significant non-rigid motion (people, fluids) [S1, unofficial].
*   **When not to use:** Static scenes (use standard 3DGS); scenes with very sparse temporal sampling where smoothness priors are hard to learn.

## Background
Deformable 3DGS was introduced by Yang et al. in CVPR'24 [S2, unofficial]. It builds on the success of 3D Gaussian Splatting by extending it to 4D (spacetime) to handle dynamic content. The method has been widely adopted for dynamic scene reconstruction and novel view synthesis from video [S1, unofficial].
