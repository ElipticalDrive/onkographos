# PSNR and Time Metrics Calculation


## Overview
This method computes quantitative evaluation metrics for volume rendering, specifically Peak Signal-to-Noise Ratio (PSNR) for image quality and rendering time for computational performance. It parses training and rendering logs to identify the specific frames and views to evaluate, calculates per-pixel error against ground truth images, and aggregates these into mean scores. It is distinct from general metric computation by explicitly linking evaluation to specific training epochs and rendering configurations logged during the NeRF training loop.

## How it works
**Inputs:**
- `train_log_file`: Path to the training log file containing timestamps and frame indices.
- `render_log_file`: Path to the rendering log file containing experiment IDs and view indices.
- `images_base_dir`: Root directory containing the rendered and ground truth images.
- `view_start_idx`: Starting index of the views to evaluate.
- `num_of_views`: Number of views to evaluate.
- `frame_start`: Starting frame index for evaluation.
- `frame_end`: Ending frame index for evaluation.
- `test_set_views`: List of view indices included in the test set.

**Outputs:**
- A CSV file containing per-view average PSNR and total rendering time statistics.

**Data Structures:**
- `datas`: A dictionary or list of records storing metrics. Each record contains:
  - `view_id`: Integer identifier of the camera view.
  - `avg_psnr`: Float, average PSNR across all evaluated frames for this view.
  - `render_time`: Float, total time to render the sequence of frames for this view (if measured).

**Steps:**
1. **Parse Configuration:**
   - Read `train_log_file` to extract `train_exp_id`, `images_base_dir`, `view_start_idx`, and `num_of_views`.
   - Read `render_log_file` to extract `render_exp_id`, `frame_start`, `frame_end`, and `test_set_views`.
   - [G] Ensure `images_base_dir` exists and contains the expected image format (e.g., `.jpg`).

2. **Initialize Metrics Storage:**
   - Create an empty dictionary `view_psnrs` mapping `view_id` to a list of PSNR values.
   - Initialize `total_render_time` to 0.0.

3. **Iterate Over Frames and Views:**
   - For each `frame_idx` in range `frame_start` to `frame_end` (inclusive):
     - For each `view_id` in `test_set_views`:
       - Construct `orig_path`: Path to the rendered image. Format: `{images_base_dir}/{render_exp_id}/{view_id}/{frame_idx:04d}.jpg` (format may vary by implementation).
       - Construct `target_path`: Path to the ground truth image. Format: `{images_base_dir}/{train_exp_id}/{view_id}/{frame_idx:04d}.jpg`.
       - Read `orig_img` and `target_img` using `cv2.imread`.
       - [G] Handle cases where images are not found or cannot be read (e.g., skip or log error).
       - Calculate `psnr` using `cv2.PSNR(orig_img, target_img)`.
       - Append `psnr` to `view_psnrs[view_id]`.

4. **Calculate Rendering Time (Optional/Contextual):**
   - If rendering time is to be measured, parse `train_log_file` for timestamps associated with the rendering of specific frames or views.
   - Use regex patterns to extract start and end times:
     - `pattern_start_training = re.compile(r'\[(.*?)\] - Start training frame(\d+)')`
     - `pattern_end_training = re.compile(r'\[(.*?)\] - End training frame(\d+)')`
   - [G] Note: The provided source [S1, unofficial] uses these patterns for *training* frames, but the method description implies evaluating rendered frames. If measuring rendering time specifically, ensure the log contains corresponding "Render" events or use wall-clock time during the evaluation loop. If not available, report "Not given in the sources." for precise per-frame rendering time extraction from logs in this specific script context.

5. **Aggregate Results:**
   - For each `view_id` in `view_psnrs`:
     - Calculate `avg_psnr` = sum(`view_psnrs[view_id]`) / len(`view_psnrs[view_id]`).
     - Store `view_id` and `avg_psnr` in `datas`.

6. **Save Results:**
   - Write `datas` to a CSV file with columns: `view_id`, `avg_psnr`.

**Formulas:**
- PSNR: $$ \text{PSNR} = 10 \cdot \log_{10} \left( \frac{\text{MAX}_I^2}{\text{MSE}} \right) $$
  Where $\text{MAX}_I$ is the maximum possible pixel value (e.g., 255 for 8-bit images) and $\text{MSE}$ is the Mean Squared Error between the rendered and ground truth images.
- Average PSNR per View: $$ \text{AvgPSNR}_v = \frac{1}{N} \sum_{i=1}^{N} \text{PSNR}_{v,i} $$
  Where $N$ is the number of frames evaluated for view $v$.

**Parameters:**
- `cv2.PSNR`: Uses default parameters for 8-bit images.
- Image format: Typically `.jpg` or `.png`.

**Edge Cases and Pitfalls:**
- **Missing Images:** If a rendered or ground truth image is missing, `cv2.imread` returns `None`. The implementation must handle this to avoid crashes.
- **Dimension Mismatch:** Ensure rendered and ground truth images have identical dimensions.
- **Log Parsing Errors:** Regex patterns for log parsing may fail if log format changes. [S1, unofficial] provides specific patterns for "Start training frame" and "End training frame".

**Pseudocode:**
```python
import cv2
import re
import csv
import os

def calculate_psnr_time_metrics(train_log_file, render_log_file, images_base_dir, view_start_idx, num_of_views, frame_start, frame_end, test_set_views):
    # Parse render_log_file for frame_start, frame_end, test_set_views
    # Note: Actual parsing logic depends on log format. Assuming these are extracted as inputs.
    
    view_psnrs = {view_id: [] for view_id in test_set_views}
    
    for frame_idx in range(frame_start, frame_end + 1):
        for view_id in test_set_views:
            # Construct paths - format may vary
            orig_path = os.path.join(images_base_dir, f"{frame_idx:04d}_{view_id}.jpg")
            target_path = os.path.join(images_base_dir, f"gt_{frame_idx:04d}_{view_id}.jpg")
            
            if not os.path.exists(orig_path) or not os.path.exists(target_path):
                continue
                
            orig_img = cv2.imread(orig_path)
            target_img = cv2.imread(target_path)
            
            if orig_img is None or target_img is None:
                continue
                
            # Calculate PSNR
            psnr = cv2.PSNR(orig_img, target_img)
            view_psnrs[view_id].append(psnr)
            
    # Aggregate results
    datas = []
    for view_id, psnr_list in view_psnrs.items():
        if len(psnr_list) > 0:
            avg_psnr = sum(psnr_list) / len(psnr_list)
            datas.append({'view_id': view_id, 'avg_psnr': avg_psnr})
            
    # Save to CSV
    with open('metrics.csv', 'w', newline='') as csvfile:
        fieldnames = ['view_id', 'avg_psnr']
        writer = csv.DictWriter(csvfile, fieldnames=fieldnames)
        writer.writeheader()
        for row in datas:
            writer.writerow(row)
            
    return datas
```

## Subtopics

### Performance Measurement
Measures the computational cost of rendering, typically in seconds per image. [S2] reports that rendering a single 800x800 image takes 25.59 seconds for Vanilla NeRF and 32.35 seconds for PL-NeRF on the Lego scene. Total rendering time varies with sample counts: (64+64) samples take 19.20 seconds, (64+128) take 25.85 seconds, and (128+64) take 32.35 seconds for PL-NeRF. [S2]

### Comparison
Compares the efficiency and quality trade-offs between different NeRF variants. [S2] PL-NeRF converges to a higher training PSNR than Vanilla NeRF under different numbers of samples, despite requiring more FLOPS and being slightly slower due to importance sampling computations. [S2]

## Operating characteristics
- **Time Complexity:** The PSNR calculation is $O(P)$ per image pair, where $P$ is the number of pixels. The total time is proportional to the number of frames and views evaluated.
- **Memory Complexity:** $O(V \cdot F)$ to store PSNR values, where $V$ is the number of views and $F$ is the number of frames. Images are loaded and discarded, so peak memory is $O(P)$.
- **Measured Performance:** On an Nvidia V100 GPU, training times were 17.78 hours for Vanilla NeRF and 21.43 hours for PL-NeRF. [S2] Rendering times for 800x800 images range from 19.20 to 32.35 seconds depending on the method and sample count. [S2]
- **Strengths:** Provides a standard, quantitative measure of rendering quality (PSNR) and computational cost.
- **Limitations:** PSNR is not always correlated with perceptual quality. Rendering time measurements are hardware-dependent. [S2]
- **When to Use:** Standard evaluation of NeRF training progress and final model quality.
- **When Not to Use:** When perceptual metrics (e.g., LPIPS) are more relevant, or when real-time performance is the primary concern.

## Background
