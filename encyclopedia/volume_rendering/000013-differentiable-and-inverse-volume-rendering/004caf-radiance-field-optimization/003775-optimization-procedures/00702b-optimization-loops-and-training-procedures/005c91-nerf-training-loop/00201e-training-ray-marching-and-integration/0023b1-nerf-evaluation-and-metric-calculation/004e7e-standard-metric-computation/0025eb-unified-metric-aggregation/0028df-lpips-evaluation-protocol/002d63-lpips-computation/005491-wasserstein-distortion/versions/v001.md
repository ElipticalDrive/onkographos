# Wasserstein Distortion

Also called: Feature-space agnostic distortion metric

## Overview
Wasserstein Distortion (WD) is a perceptual image-to-image metric that compares spatially local estimates of statistics (mean and standard deviation) in deep feature space, allowing textures with large pointwise differences but similar local statistics to be considered perceptually similar [S1][S2, unofficial]. Unlike pointwise metrics such as [LPIPS Computation](5498-lpips-computation.md) which penalize phase shifts and exact pixel alignment, WD models human peripheral vision by aggregating features over local pooling regions, making it suitable for optimizing perceptual texture quality in differentiable rendering [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Two images $I_1$ (ground truth) and $I_2$ (reconstructed/estimated).
- **Outputs:** A scalar distortion value $D_{WD}$.

**Data Structures:**
- Feature maps $F_1, F_2$: Multi-scale representations extracted from a pre-trained VGG network [S2, unofficial]. Each feature map is a 3D tensor of shape $(C, H, W)$ where $C$ is channels, $H$ height, $W$ width [S2, unofficial].
- Pooling Kernel: A spatial window of size $K \times K$ centered at each pixel, where $K = 2\sigma$ [S2, unofficial].

**Parameters:**
- $\sigma$: Hyperparameter defining the kernel size as $2\sigma$. Controls the trade-off between point-wise fidelity ($\sigma \to 0$) and texture re-sampling/peripheral vision mimicry (larger $\sigma$) [S2, unofficial].
- Typical Value: $\sigma = 4$ (constant) [S1].
- Spatially Varying $\sigma(x,y)$: Optional, allowing greater flexibility by allocating more weight to salient regions [S2, unofficial].

**Steps:**
1. **Feature Extraction:** Extract multi-scale feature representations $F_1$ and $F_2$ from the pre-trained VGG network for images $I_1$ and $I_2$ respectively [S2, unofficial].
2. **Local Statistics Computation:** For each feature map and each spatial location $(x, y)$:
   - Apply a pooling kernel of size $2\sigma$ centered at $(x, y)$ to the feature map [S2, unofficial].
   - Compute the local mean $\mu$ and local standard deviation $\nu$ of the features within this kernel [S1].
   - Let $\mu, \nu$ be the statistics for $I_1$ and $\hat{\mu}, \hat{\nu}$ be the statistics for $I_2$ [S1].
3. **Local Distortion Calculation:** Compute the local Wasserstein distortion $d_{\textrm{WD}}$ at $(x, y)$ using the Root Mean Square Error (RMSE) between the local statistics [S1]:
   $$
   d_{\textrm{WD}}(x, y) = \sqrt {(\mu - \hat {\mu })^2 + (\nu - \hat {\nu })^2}
   $$
   This is equivalent to computing the squared 2-Wasserstein divergence $W_2^2$ between two 1D Gaussian distributions defined by $(\mu, \nu)$ and $(\hat{\mu}, \hat{\nu})$ [S2, unofficial].
4. **Aggregation:** Spatially average and sum the local $d_{\textrm{WD}}$ values across all spatial locations and all feature maps to produce the final metric [S2, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def wasserstein_distortion(image_gt, image_pred, sigma=4, vgg_features_gt=None, vgg_features_pred=None):
    """
    Computes Wasserstein Distortion between ground truth and predicted images.
    
    Args:
        image_gt: Tensor of shape (B, C, H, W), ground truth images.
        image_pred: Tensor of shape (B, C, H, W), predicted images.
        sigma: Hyperparameter for kernel size (kernel size = 2 * sigma).
        vgg_features_gt: List of VGG feature maps for GT. If None, extracted internally.
        vgg_features_pred: List of VGG feature maps for Pred. If None, extracted internally.
        
    Returns:
        Scalar tensor representing the WD score.
    """
    # Step 1: Feature Extraction
    # Note: In a full implementation, a VGG backbone is used.
    # Here we assume vgg_features_gt and vgg_features_pred are lists of tensors [F1, F2, ...]
    # each of shape (B, C, H, W).
    if vgg_features_gt is None or vgg_features_pred is None:
        raise NotImplementedError("VGG feature extraction logic omitted for brevity; "
                                  "use a standard VGG-16/19 feature extractor.")
    
    features_gt = vgg_features_gt
    features_pred = vgg_features_pred
    
    total_distortion = 0.0
    num_spatial_pixels = 0
    
    kernel_size = 2 * sigma
    
    # Step 2 & 3: Local Statistics and Distortion per Feature Map
    for F_gt, F_pred in zip(features_gt, features_pred):
        # F_gt, F_pred shape: (B, C, H, W)
        
        # Compute local mean and std for GT
        # Use adaptive_avg_pool2d or manual padding/convolution for mean
        # Mean: average over kernel
        mean_gt = F.avg_pool2d(F_gt, kernel_size=kernel_size, stride=1, padding=kernel_size//2)
        mean_pred = F.avg_pool2d(F_pred, kernel_size=kernel_size, stride=1, padding=kernel_size//2)
        
        # Std: sqrt(E[X^2] - (E[X])^2)
        sq_gt = F.avg_pool2d(F_gt ** 2, kernel_size=kernel_size, stride=1, padding=kernel_size//2)
        sq_pred = F.avg_pool2d(F_pred ** 2, kernel_size=kernel_size, stride=1, padding=kernel_size//2)
        
        std_gt = torch.sqrt(sq_gt - mean_gt ** 2 + 1e-8) # Guard against negative due to precision
        std_pred = torch.sqrt(sq_pred - mean_pred ** 2 + 1e-8)
        
        # Step 3: Local Distortion (RMSE between mean and std)
        # d_WD = sqrt( (mu - mu_hat)^2 + (nu - nu_hat)^2 )
        diff_mean = mean_gt - mean_pred
        diff_std = std_gt - std_pred
        
        local_distortion = torch.sqrt(diff_mean ** 2 + diff_std ** 2 + 1e-8)
        
        # Step 4: Aggregation
        # Sum over spatial dimensions and batch, then average over feature maps?
        # Sources say "spatially averaged and summed across feature maps".
        # Usually, this implies summing the spatial averages or averaging the spatial sums.
        # We sum over spatial dimensions (H, W) and channels (C) are already reduced by pooling.
        # We sum over batch dimension B.
        
        # Sum over spatial locations
        spatial_sum = local_distortion.sum(dim=[2, 3]) # Shape (B,)
        
        # Sum over feature maps (accumulated in total_distortion)
        # Note: The source says "summed across feature maps". 
        # We accumulate the sum of spatial distortions for this map.
        total_distortion += spatial_sum.sum()
        
        # Count pixels for normalization if "averaged" implies per-pixel normalization
        # "Spatially averaged and summed" is slightly ambiguous. 
        # LPIPS typically averages over spatial dims then sums over maps.
        # WD [S2, unofficial] says "spatially averaged and summed across feature maps".
        # Let's assume we average over spatial pixels for each map, then sum maps.
        
    # Re-evaluating aggregation based on "spatially averaged and summed":
    # Reset and do it properly:
    total_distortion = 0.0
    num_maps = len(features_gt)
    
    for F_gt, F_pred in zip(features_gt, features_pred):
        mean_gt = F.avg_pool2d(F_gt, kernel_size=kernel_size, stride=1, padding=kernel_size//2)
        mean_pred = F.avg_pool2d(F_pred, kernel_size=kernel_size, stride=1, padding=kernel_size//2)
        
        sq_gt = F.avg_pool2d(F_gt ** 2, kernel_size=kernel_size, stride=1, padding=kernel_size//2)
        sq_pred = F.avg_pool2d(F_pred ** 2, kernel_size=kernel_size, stride=1, padding=kernel_size//2)
        
        std_gt = torch.sqrt(sq_gt - mean_gt ** 2 + 1e-8)
        std_pred = torch.sqrt(sq_pred - mean_pred ** 2 + 1e-8)
        
        local_distortion = torch.sqrt((mean_gt - mean_pred) ** 2 + (std_gt - std_pred) ** 2 + 1e-8)
        
        # Spatially average
        spatial_avg = local_distortion.mean(dim=[2, 3]) # Shape (B,)
        
        # Sum across feature maps (accumulate)
        total_distortion += spatial_avg.sum()
        
    # Normalize by number of maps? Source says "summed across feature maps".
    # It does not explicitly say "averaged across feature maps".
    # However, to keep scale consistent, often divided by num_maps.
    # Given "summed", we leave it as sum.
    
    return total_distortion / num_maps # Averaging over maps is standard for multi-scale metrics like LPIPS/WD to balance scales.
```

**Edge Cases and Pitfalls:**
- **Precision:** When computing standard deviation, ensure numerical stability by adding a small epsilon ($10^{-8}$) before taking the square root to handle cases where variance is slightly negative due to floating-point errors [G].
- **Boundary Conditions:** The pooling kernel requires padding. Use 'same' padding or explicit reflection/replication padding to handle image boundaries correctly [G].
- **Texture Perception:** Pointwise metrics fail to account for phase shifts (e.g., 180-degree phase shift in textures). WD addresses this by aggregating over local regions, but if $\sigma$ is too small, it reverts to pointwise behavior and loses this benefit [S1].
- **Global vs Local:** WD is not the Wasserstein Distance (Earth Mover’s Distance) which measures global distribution divergence. WD is strictly an image-to-image local statistic metric [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Dominated by VGG feature extraction ($O(N)$ where $N$ is pixels) and pooling operations ($O(N \cdot \sigma^2)$). Overall linear with respect to image resolution and number of feature maps.
- **Memory Complexity:** Requires storing multi-scale VGG feature maps for both images. Memory usage scales with image resolution and number of VGG layers [S2, unofficial].
- **Strengths:** Better matches human perceptual judgments than LPIPS or DISTS by accounting for texture realism and peripheral vision [S2, unofficial]. Permissive to texture resampling in less salient regions [S1].
- **Limitations:** Computationally heavier than pointwise metrics due to pooling and multi-scale feature extraction. Requires a pre-trained VGG network [S2, unofficial].
- **When to Use:** When perceptual quality (texture realism) is more important than exact pixel-wise reconstruction fidelity, such as in differentiable rendering optimization [S1][S2, unofficial].
- **When Not to Use:** When exact signal reconstruction is required, or when computational resources are severely limited [S2, unofficial].

## Background
Wasserstein Distortion was introduced as a feature-space agnostic distortion metric to address the limitations of pointwise metrics like LPIPS in capturing human texture perception [S1]. It is motivated by models of the human visual system suggesting that peripheral vision encodes images using summary statistics over local pooling regions rather than precise pointwise values [S1]. The metric was notably used in the context of overfitted image codecs to showcase its effectiveness in perceptual optimization [S2, unofficial]. It distinguishes itself from the global Wasserstein Distance (Earth Mover’s Distance) by focusing on local statistics matching [S2, unofficial].
