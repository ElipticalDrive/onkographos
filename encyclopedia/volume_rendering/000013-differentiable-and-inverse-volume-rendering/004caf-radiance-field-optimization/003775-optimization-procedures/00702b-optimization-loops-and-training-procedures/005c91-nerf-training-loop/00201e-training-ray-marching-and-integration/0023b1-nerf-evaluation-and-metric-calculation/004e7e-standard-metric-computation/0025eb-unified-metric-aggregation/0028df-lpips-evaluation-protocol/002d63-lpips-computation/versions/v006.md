# LPIPS Computation

Also called: Learned Perceptual Image Patch Similarity, LPIPS Loss

## Overview
LPIPS is a full-reference perceptual quality assessment metric that estimates the similarity between two images by comparing deep features extracted from pretrained convolutional neural networks [S1][S2, unofficial][S3, S4]. It solves the limitation of pixel-wise metrics (such as MSE or PSNR) by capturing high-level semantic and structural nuances that align better with human perception [S3, S4][S6, unofficial]. Unlike its siblings, it operates on feature activations rather than raw pixel values, making it sensitive to texture and edge preservation [S6, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Two images (or image patches), $x$ (reference) and $y$ (assessed/reconstructed). Typically normalized to $[0, 1]$ or $[-1, 1]$.
- **Outputs:** A scalar distance value $LPIPS(x, y) \ge 0$. Lower values indicate higher perceptual similarity.

**Data Structures:**
- **Feature Maps:** For each layer $l$ in the backbone network, the output is a tensor of shape $(C_l, H_l, W_l)$, where $C_l$ is the number of channels, and $H_l, W_l$ are the spatial dimensions.
- **Learned Weights:** A set of scalar weights $w_l$ for each layer $l$, learned via a perceptual loss optimization on human judgments [S1][S2, unofficial].

**Steps:**
1. **Preprocessing:** Scale input images from $[0, 1]$ to $[-1, 1]$ using the transformation $x' = 2x - 1$ and $y' = 2y - 1$ [S5, unofficial]. Add a batch dimension if necessary (e.g., shape $(1, C, H, W)$) [S5, unofficial].
2. **Feature Extraction:** Pass both images through a pretrained backbone network (e.g., VGG, AlexNet, or SqueezeNet) [S1, S3][S5, unofficial]. Extract intermediate feature maps $f_l(x)$ and $f_l(y)$ for a set of layers $l \in \{0, \dots, L\}$ [S2, unofficial].
3. **Normalization:** Normalize the feature maps per channel. The original LPIPS paper normalizes features by dividing by the square root of the number of elements in the feature map, effectively computing a normalized Euclidean distance [S1][S2, unofficial]. *Note: The specific normalization step is implicit in the "learned weights" formulation in [S2, unofficial] but explicit in the weighted MSE formulation in [S1]. The standard implementation [S5, unofficial] uses the `lpips` library which handles this internally.*
4. **Distance Calculation:** Compute the weighted squared Euclidean distance between the feature maps of $x$ and $y$ across all layers [S1][S2, unofficial].

**Formula:**
The LPIPS distance is defined as [S1][S2, unofficial]:

$$
LPIPS(x, y) = \sum_{l} w_l \| f_l(x) - f_l(y) \|_2^2
$$

Where:
- $l$ indexes the layers of the backbone network.
- $w_l$ are the learned weights for layer $l$ [S2, unofficial].
- $f_l(x)$ and $f_l(y)$ are the feature activations of images $x$ and $y$ at layer $l$ [S2, unofficial].
- $\| \cdot \|_2^2$ denotes the squared $L_2$ norm (sum of squared differences) over the spatial dimensions and channels of the feature map [S1][S2, unofficial].

An equivalent formulation provided in [S1] expands the norm:

$$
LPIPS(x, y) = \sum_{l} \frac{1}{H_l W_l} \sum_{h,w} ||w_l \odot (x^l_{hw} - y^l_{hw})||_2^2
$$

Where:
- $x^l_{hw}, y^l_{hw}$ are the feature vectors at pixel $(h, w)$ and layer $l$ [S1].
- $H_l, W_l$ are the height and width of the feature map at layer $l$ [S1].
- $\odot$ denotes element-wise multiplication with the learned weights $w_l$ [S1].

**Parameters:**
- **Backbone Architecture:** The original paper used SqueezeNet, VGG, and AlexNet [S1]. VGG is commonly used in modern implementations [S5, unofficial]. AlexNet is also cited for specific applications [S3].
- **Weights ($w_l$):** Learned per layer to minimize correlation with human perceptual judgments [S2, unofficial]. Not given in the sources for specific values, but they are part of the pretrained model weights.

**Pitfalls:**
- **Weight Download:** The first run requires downloading pretrained weights to the `TORCH_HOME` cache, requiring internet access or pre-cached weights [S5, unofficial].
- **Normalization:** Incorrect input scaling (e.g., not converting to $[-1, 1]$ if the model expects it) can lead to incorrect feature activations [S5, unofficial].
- **Perceptual vs. Pixel:** LPIPS does not measure pixel-perfect accuracy. It may assign high similarity to images that are perceptually similar but pixel-different [S6, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn as nn
import lpips # External library for pretrained weights and model definition

def compute_lpips(image_x: torch.Tensor, image_y: torch.Tensor, net_type: str = 'vgg') -> float:
    """
    Compute LPIPS between two images.
    
    Args:
        image_x: Reference image tensor of shape (C, H, W) or (B, C, H, W), values in [0, 1].
        image_y: Assessed image tensor of same shape, values in [0, 1].
        net_type: Backbone architecture ('vgg', 'alex', 'squeeze').
        
    Returns:
        LPIPS distance scalar.
    """
    # 1. Load model
    loss_fn = lpips.LPIPS(net=net_type)
    
    # 2. Set to evaluation mode
    loss_fn.eval()
    
    # 3. Ensure batch dimension
    if image_x.dim() == 3:
        image_x = image_x.unsqueeze(0)
        image_y = image_y.unsqueeze(0)
        
    # 4. Scale from [0, 1] to [-1, 1]
    # Note: Some implementations handle this internally, but explicit scaling is safer
    # based on [S5, unofficial] which shows `* 2.0 - 1.0`.
    # However, the standard lpips library often expects [-1, 1] input directly.
    # We follow [S5, unofficial] explicitly.
    image_x_scaled = image_x * 2.0 - 1.0
    image_y_scaled = image_y * 2.0 - 1.0
    
    # 5. Compute distance
    # The lpips library returns a tensor of shape (B,)
    distance = loss_fn(image_x_scaled, image_y_scaled)
    
    # 6. Return mean as float
    return distance.mean().item()
```

## Subtopics

### [Wasserstein Distortion](15233-wasserstein-distortion.md)
An image-to-image metric that focuses on local statistics matching rather than global divergence, used as the primary training objective for perceptual quality.

## Operating characteristics
- **Time Complexity:** Dominated by the forward pass of the backbone network (e.g., VGG-16). For a single image pair, it is comparable to a single forward pass of the backbone.
- **Memory Complexity:** Requires storing intermediate feature maps for all layers during the forward pass. For VGG-16, this is significant but manageable on modern GPUs.
- **Performance:** LPIPS correlates better with human perception than PSNR or SSIM [S3, S4]. It is preferred over MSE for optimization objectives because it accounts for neighboring information and structural context [S6, unofficial].
- **Strengths:** Captures perceptual nuances missed by pixel-wise metrics; robust to small geometric shifts and texture variations [S4][S6, unofficial].
- **Limitations:** Computationally more expensive than PSNR/SSIM; requires a pretrained network; not differentiable with respect to the input images in a way that provides pixel-level gradients for direct optimization (though it can be used as a loss if the backbone is differentiable, which is rare in standard evaluation) [S6, unofficial].
- **When to use:** Evaluating perceptual quality of rendered images, especially in NeRF and Gaussian Splatting where visual fidelity is key [S4][S5, unofficial].
- **When not to use:** When pixel-perfect accuracy is required, or when computational resources are extremely limited [S6, unofficial].

## Background
LPIPS was introduced by Zhang et al. in 2018 [S1, S3][S6, unofficial]. It was designed to address the poor correlation of traditional metrics (MSE, SSIM) with human perceptual judgments. The metric uses features from pretrained networks (AlexNet, VGG, SqueezeNet) and learns weights to minimize the distance between the metric's output and human similarity judgments [S1][S2, unofficial]. It has become a standard metric in NeRF evaluation [S1, S4].
