# Unified Metric Aggregation

Also called: Evaluation & Metric Computation, Evaluation Reporting, Global and Per-view Metric Aggregation

## Overview
Unified Metric Aggregation computes standard photorealistic metrics—Peak Signal-to-Noise Ratio (PSNR), Structural Similarity Index (SSIM), and Learned Perceptual Image Patch Similarity (LPIPS)—and aggregates them into global averages and per-view dictionaries for evaluation reporting [S1, S2, unofficial][S4]. It addresses the problem of quantifying the fidelity of rendered images against ground truth references by balancing pixel-level precision, structural integrity, and perceptual similarity [S1, unofficial][S3]. What sets it apart from raw error metrics is the inclusion of perceptual models (LPIPS) and structural models (SSIM) that correlate better with human judgment, while remaining computationally efficient enough for per-view evaluation during training loops [S2, unofficial]. It builds on [Standard Metric Computation](13741-standard-metric-computation.md) by handling the orchestration of multiple metric types and the serialization of results [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Paired lists of rendered and ground-truth (GT) images, typically in tensor format (CHW: Channel, Height, Width) normalized to $[0, 1]$ [S1, S2, unofficial]. Optional parameters include `compute_extra_metrics` (boolean, default `True` for SSIM/LPIPS) and `N_vis` (integer, controls evaluation interval) [S2, unofficial].
- **Outputs:** Global metrics dictionary (JSON/text) containing arithmetic means of all metrics, and a per-view dictionary mapping image names to their individual metric scores [S1, unofficial].

**Data Structures:**
- `per_view_metrics`: A list or dictionary accumulating per-view results. Structure: `{ "image_name": { "PSNR": float, "SSIM": float, "LPIPS": float } }` [S1, unofficial].
- `global_metrics`: A dictionary for final averages. Structure: `{ "PSNR": float, "SSIM": float, "LPIPS": float }` [S1, unofficial].
- `PSNRs`, `SSIMs`, `LPIPSs`: Lists of floats storing computed values for each view [S2, unofficial].

**Numbered Steps:**
1. Initialize empty lists for per-view metrics (`PSNRs`, `SSIMs`, `LPIPSs`) and a container for per-view detailed results [S1, S2, unofficial].
2. Determine the evaluation interval. If `N_vis < 0`, evaluate all rays/images (`img_eval_interval = 1`). Otherwise, `img_eval_interval = max(total_rays // N_vis, 1)` [S2, unofficial].
3. Iterate over the test dataset rays/images using the determined interval: `for i in range(0, total_rays, img_eval_interval)` [S2, unofficial].
4. For each iteration:
    a. Load the rendered RGB image and the corresponding GT image [S1, unofficial].
    b. Normalize images to $[0, 1]$ and convert to CHW tensor format [S1, unofficial].
    c. Validate that rendered and GT images have matching shapes (H, W, C) [S1, unofficial].
    d. Compute Mean Squared Error (MSE): $\text{MSE} = \frac{1}{N} \sum_{i=1}^{N} (R_i - G_i)^2$, where $R_i$ is rendered pixel, $G_i$ is GT pixel, $N$ is total pixels [S2, unofficial].
    e. Compute PSNR: $\text{PSNR} = -10 \cdot \frac{\log(\text{MSE})}{\log(10)}$ [S2, unofficial].
    f. If `compute_extra_metrics` is enabled:
        i. Compute SSIM using a sliding window approach (typically $3\times3$ or $11\times11$) comparing local structures [S2, unofficial][S4].
        ii. Compute LPIPS by extracting deep features from a pretrained backbone (AlexNet or VGG) and calculating weighted L2 distance between features [S2, unofficial][S4].
    g. Validate that all computed metrics are finite numbers (not NaN or Inf) [S1, unofficial].
    h. Store the per-view results in `per_view_metrics` using the image name as key [S1, unofficial].
    i. Append scalar values to `PSNRs`, `SSIMs`, `LPIPSs` lists [S2, unofficial].
    j. (Optional) Save rendered RGB and depth images to disk for visual inspection [S2, unofficial].
5. After the loop, compute the arithmetic mean for each metric list:
   $$ \text{Global PSNR} = \frac{1}{M} \sum_{j=1}^{M} \text{PSNR}_j $$
   where $M$ is the number of evaluated views [S1, S2, unofficial].
6. Construct the global metrics dictionary and per-view JSON structure [S1, unofficial].
7. Write global metrics and per-view JSON to disk (e.g., `metrics.json` or `results.txt`) [S1, S2, unofficial].
8. (Optional) Generate and save video summaries of the rendered sequence [S2, unofficial].

    psnr_list = []

            print(f"Warning: Non-finite LPIPS for {name}")

        if ssim_val is not None:
            view_metrics["SSIM"] = ssim_val
        if lpips_val is not None:
            view_metrics["LPIPS"] = lpips_val
            
        per_view_results[name] = view_metrics
        
        psnr_list.append(psnr_val)
        if ssim_val is not None:
            ssim_list.append(ssim_val)
        if lpips_val is not None:
            lpips_list.append(lpips_val)

    # 6. Compute global averages [S1, S2, unofficial]
    global_metrics = {}
    if psnr_list:
        global_metrics["PSNR"] = np.mean(psnr_list)
    if ssim_list:
        global_metrics["SSIM"] = np.mean(ssim_list)
    if lpips_list:
        global_metrics["LPIPS"] = np.mean(lpips_list)
        
    return {
        "global": global_metrics,
        "per_view": per_view_results
    }

**Parameters:**
- `compute_extra_metrics`: Boolean. If `True`, computes SSIM and LPIPS in addition to PSNR. Default `True` [S2, unofficial].
- `N_vis`: Integer. Number of views to visualize/evaluate. If `N_vis < 0`, all views are evaluated. Otherwise, a subset is selected based on `max(total_rays // N_vis, 1)` [S2, unofficial].
- `lpips_model`: Pretrained neural network (AlexNet or VGG) for LPIPS computation [S2, unofficial].

**Edge Cases and Pitfalls:**
- **NaN/Inf:** If MSE is 0, PSNR becomes infinity. This should be handled or noted [S2, unofficial].
- **Shape Mismatch:** Rendered and GT images must have identical dimensions (H, W, C). Mismatches cause errors [S1, unofficial].
- **Normalization:** Images must be normalized to $[0, 1]$ before metric computation. Incorrect scaling leads to erroneous PSNR/SSIM values [S1, S2, unofficial].
- **Memory:** LPIPS computation requires loading a deep network and intermediate features, which can be memory-intensive for high-resolution images [S2, unofficial].

## Subtopics

### [LPIPS Evaluation Protocol](4376-lpips-evaluation-protocol.md)
LPIPS is a full-reference perceptual quality metric that measures image similarity by comparing deep feature representations extracted from a pretrained convolutional neural network. Unlike pixel-wise metrics such as PSNR or MSE, which often correlate poorly with human perception, LPIPS aligns closely with human judgments of image similarity by leveraging semantic features. It is primarily used in volume rendering and NeRF optimization to evaluate reconstruction fidelity or as a perceptual loss function to guide training, capturing nuances like texture and structure that standard metrics miss.

### [Metric Computation (PSNR, SSIM, LPIPS)](9928-metric-computation-psnr-ssim-lpips.md)
This method computes standard photorealistic metrics—Peak Signal-to-Noise Ratio (PSNR), Structural Similarity Index (SSIM), and Learned Perceptual Image Patch Similarity (LPIPS)—to quantify the fidelity of rendered images against ground truth references. It addresses the problem of evaluating novel-view synthesis quality by balancing pixel-level precision (PSNR), structural integrity (SSIM), and perceptual similarity (LPIPS). What sets this apart from raw error metrics is the inclusion of perceptual models (LPIPS) and structural models (SSIM) that correlate better with human judgment than simple pixel differences, while remaining computationally efficient enough for per-view evaluation during training loops.

### Evaluation Reporting
This variant focuses on the comprehensive reporting of evaluation results beyond just image quality. It includes reporting the size of the resulting splats in MB, rendering speed on various platforms (standalone PC, PC-VR, mobile VR), and comparing approaches in specific domains like anatomy visualization and thermal scene representation [S3]. It ensures that PSNR, SSIM, and LPIPS are reported alongside these performance and size metrics to provide a holistic view of the method's efficiency and quality [S3].

### Quantitative Evaluation Metrics
This variant extends the standard set with temporal metrics for dynamic scenes. It includes tOF (temporal Optical Flow), which examines errors in motion by comparing optical flow to ground truth, and tLP (temporal Perceptual Loss), which measures perceptual distance as the change in LPIPS between consecutive frames [S4]. For static scenes, PSNR and SSIM are higher-is-better, while LPIPS, tOF, and tLP are lower-is-better [S4]. Example results on KITTI data show PSNR ~26.66, SSIM ~0.806, LPIPS ~0.186, tOF ~0.765×10^6, and tLP ~0.246×100 for high-performing methods [S4].

## Operating characteristics
**Time and Memory Complexity:**
- **PSNR:** $O(N)$ where $N$ is the number of pixels. Very fast.
- **SSIM:** $O(N \cdot K^2)$ where $K$ is the window size (e.g., $11\times11$). Moderate.
- **LPIPS:** $O(N \cdot C \cdot H \cdot W)$ due to feature extraction from deep networks. High memory and compute cost, especially for high-resolution images [S2, unofficial].
- **Aggregation:** $O(M)$ where $M$ is the number of views. Negligible.

**Measured Performance:**
- On KITTI reconstruction, high-performing methods achieve PSNR 26.66, SSIM 0.806, LPIPS 0.186 [S4].
- On KITTI novel composition, PSNR 25.11, SSIM 0.789, LPIPS 0.204 [S4].
- Rendering speed is often reported alongside metrics (e.g., FPS on PC-VR, mobile VR) to contextualize quality [S3].

**Scaling:**
- Evaluation time scales linearly with the number of views and image resolution.
- LPIPS computation is the bottleneck for large-scale evaluation [S2, unofficial].

**Strengths and Limitations:**
- **Strengths:** Provides a multi-faceted view of quality (pixel, structure, perception). Global aggregation simplifies comparison across methods [S1, S2, unofficial].
- **Limitations:** LPIPS is computationally expensive. SSIM and LPIPS may not always correlate perfectly with human judgment in all domains (e.g., medical imaging, thermal scenes) [S3]. Temporal metrics (tOF, tLP) require video sequences and are not applicable to static novel-view synthesis [S4].

**When to Use:**
- Use for standard novel-view synthesis evaluation (PSNR, SSIM, LPIPS) [S1, S2, unofficial].
- Use for dynamic scene reconstruction when temporal consistency is critical (tOF, tLP) [S4].
- Use for VR/AR applications where rendering speed and memory footprint are as important as visual quality [S3].

## Background
Unified Metric Aggregation originated as a standard practice in the NeRF and Gaussian Splatting communities to provide consistent and comparable evaluation results. The specific implementation details of aggregating PSNR, SSIM, and LPIPS into global and per-view JSON structures are documented in unofficial repositories like Advanced3DGS [S1, unofficial] and TensoRF [S2, unofficial]. The inclusion of temporal metrics (tOF, tLP) was introduced in the context of Neural Scene Graphs for Dynamic Scenes [S4]. The reporting of performance metrics (speed, memory) alongside visual quality is highlighted in recent VR-focused Gaussian Splatting works like Shape-Shifting Splats [S3].
