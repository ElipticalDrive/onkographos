# Appearance Matching
## Overview
Appearance matching is a post-training optimization procedure used in multi-block neural radiance field frameworks to ensure visual consistency across block boundaries [S1]. It solves the problem of appearance discontinuities that arise when independent Block-NeRFs are trained with randomly initialized appearance latent codes, which yield different colors for the same semantic code in adjacent blocks [S1]. It sets itself apart from standard training by freezing network weights and optimizing only latent codes or specific appearance parameters, whereas siblings like [HybridNeRF Model Architecture](4842-hybridnerf-model-architecture.md), [MVS Network Query](7517-mvs-network-query.md), [SqueezeNeRF](8704-squeezenerf.md), [VoxNeRF](8865-voxnerf.md), [Deformation Field Integration for Telepresence](10866-deformation-field-integration-for-telepresence.md), [HDR-HexPlane](13548-hdr-hexplane.md), [Multi-scale PointNeRF++ Feature Aggregation](13651-multi-scale-pointnerf-feature-aggregation.md), [FourieRF](15185-fourierf.md), [Hash-grid anti-aliasing and regularization](15594-hash-grid-anti-aliasing-and-regularization.md), [NeRF-W](15666-nerf-w.md), [UniSDF-based Latent NeRF](17022-unisdf-based-latent-nerf.md), [RawNeRF](17244-rawnerf.md), [Neural Duplex Radiance Field](17643-neural-duplex-radiance-field.md), [NeuRay Occlusion-Aware Parameterization](18695-neuray-occlusion-aware-parameterization.md), [SHINE-Mapping](20278-shine-mapping.md), [NeRF-LiDAR](20283-nerf-lidar.md), [DINER (Disorder-Invariant Implicit Neural Representation)](21718-diner-disorder-invariant-implicit-neural-representation.md), [Generative Radiance Fields (GRAF)](21722-generative-radiance-fields-graf.md), and [Instant NGP-based Surface Rendering](22798-instant-ngp-based-surface-rendering.md) integrate appearance handling into the primary forward pass without separate consistency post-processing [S1].

## How it works
The method operates in two distinct contexts: global consistency for Block-NeRFs [S1] and example-based transfer for NeRF Analogies [S2].

### Block-NeRF Appearance Matching
**Inputs:**
*   Two adjacent Block-NeRFs: a *Target* Block-NeRF (with a fixed, desired appearance) and an *Adjacent* Block-NeRF (with inconsistent appearance) [S1].
*   A 3D matching location $p$ in world coordinates [S1].
*   The appearance latent code $c_{target}$ of the Target Block-NeRF [S1].
*   The appearance latent code $c_{adj}$ of the Adjacent Block-NeRF [S1].

**Data Structures:**
*   **Block-NeRF Network:** A neural network $f_\theta$ parameterized by $\theta$ [S1]. Inputs: position $x$, viewing direction $v$, and appearance code $c$ [S1]. Outputs: radiance $r$ and density $\sigma$ [S1].
*   **Visibility Predictor:** A function $V(x)$ estimating the probability that a point $x$ is visible and within the bounds of a specific Block-NeRF [S1].

**Steps:**
1.  **Select Matching Location:** Identify a 3D point $p$ located between the Target and Adjacent blocks [S1]. The selection criterion is that the visibility prediction $V_{target}(p)$ and $V_{adj}(p)$ must both be high for their respective blocks [S1].
2.  **Freeze Weights:** Freeze the network weights $\theta_{target}$ and $\theta_{adj}$ of both Block-NeRFs [S1]. Only the appearance latent code $c_{adj}$ is treated as an optimization variable [S1].
3.  **Render Target Appearance:** Compute the target radiance $r_{target}$ using the fixed code:
    $$ r_{target} = f_{\theta_{target}}(p, v, c_{target}) $$
    where $v$ is the viewing direction at $p$ [S1].
4.  **Render Adjacent Appearance:** Compute the current radiance of the adjacent block:
    $$ r_{adj} = f_{\theta_{adj}}(p, v, c_{adj}) $$
5.  **Optimize:** Minimize the difference between $r_{adj}$ and $r_{target}$ by updating $c_{adj}$ [S1]. The loss function is typically the L1 or L2 norm of the radiance difference:
    $$ \mathcal{L} = \| r_{adj} - r_{target} \|_1 $$
    Gradient descent updates $c_{adj}$ until the appearance in the Adjacent block matches the Target block at location $p$ [S1].

### NeRF Analogy Training Procedure
**Inputs:**
*   Target 3D positions $P_{target}$ [S2].
*   Target surface normals $N_{target}$ [S2].
*   Target viewing directions $V_{target}$ [S2].
*   Source appearance mapping function $\phi$ [S2].
*   Source appearances $A_{source}$ and source viewing directions $V_{source}$ derived from semantic correspondences [S2].

**Data Structures:**
*   **Target NeRF Network:** A network $f_\theta$ taking inputs $(x, n, v)$, where $n$ is the surface normal [S2]. Outputs radiance $r$ [S2].
*   **Mapping Function $\phi$:** Maps source appearance and viewing direction to the target domain [S2].

**Steps:**
1.  **Query Target Network:** Input the target position $p_i$, normal $n_i$, and viewing direction $v_i$ into the target NeRF network to get predicted radiance $r_{pred}$:
    $$ r_{pred} = f_\theta(p_i, n_i, v_i) $$
    Note: The density is assumed to be a Dirac delta distribution (surface), so volume rendering is skipped; the network outputs radiance directly at the surface point [S2].
2.  **Compute Source Appearance:** Apply the mapping function to the source appearance and viewing direction to get the target appearance $r_{source}$:
    $$ r_{source} = \phi(A_{source}, V_{source}) $$
3.  **Calculate Loss:** Compute the L1 loss between the predicted radiance and the mapped source appearance, averaged over all target indices $i$:
    $$ \mathcal{L} = \mathbb{E}_{i} \left[ \| f_\theta(p_i, n_i, v_i) - \phi(A_{source}, V_{source}) \|_1 \right] $$
4.  **Optimize:** Update network parameters $\theta$ to minimize $\mathcal{L}$ [S2].

**Parameters:**
*   **Surface Normals:** Added to the network input for NeRF Analogy to provide a high-frequency signal for recovering high-frequency color changes [S2].

**Edge Cases and Pitfalls:**
*   **Random Initialization:** Without appearance matching, randomly initialized appearance codes lead to different appearances in different blocks, causing visible inconsistencies during compositing [S1].
*   **Visibility:** The matching location must have high visibility in both blocks; otherwise, the optimization may fail or produce artifacts due to occlusion or out-of-bounds queries [S1].
*   **Dirac Delta Assumption:** NeRF Analogy assumes the target density is a Dirac delta distribution [S2]. If the target is a volumetric field rather than a surface, the direct radiance query may not be valid without volume rendering integration [S2].

## Subtopics

### NeRF Analogy Training
A method to train a target NeRF's appearance parameters such that the target's radiance matches the source's appearance under the source viewing direction, using semantic correspondences [S2]. It differs from Block-NeRF matching by using semantic mappings and surface normals rather than latent code optimization between adjacent blocks [S2]. It is chosen when transferring visual attributes (e.g., season, style) from a source image to a target NeRF [S2]. It assumes the target density is a Dirac delta distribution (surface), so no volume rendering is required [S2].

## Operating characteristics
*   **Time Complexity:** Depends on the number of optimization steps and the number of matching points [S1]. For Block-NeRF, it is $O(N_{steps} \cdot N_{points} \cdot D_{network})$, where $D_{network}$ is the cost of a forward pass [S1]. Only the appearance latent code is optimized while the network weights remain frozen [S1].
*   **Memory Complexity:** Low [S1]. Only the appearance latent codes or network parameters are stored in the optimizer's state [S1, S2].
*   **Measured Performance and Scaling:** Not given in the sources [S1, S2].
*   **Strengths:** Ensures seamless compositing of large scenes split into blocks [S1]. Enables style transfer without retraining the entire geometry [S2].
*   **Limitations:** Requires high visibility at matching locations [S1]. NeRF Analogy requires accurate semantic correspondences and surface normals [S2].
*   **When to use:** When compositing multiple Block-NeRFs or when transferring appearance attributes from a source image to a target NeRF [S1, S2].
*   **When not to use:** When real-time rendering is required without pre-computation, or when the scene is a single monolithic Block-NeRF [S1].

## Background
Block-NeRF appearance matching was introduced in "Block-NeRF: Scalable Large Scene Neural View Synthesis" (CVPR 2022) to address scalability issues in large scenes by splitting them into blocks, which inadvertently caused appearance inconsistencies [S1]. NeRF Analogy Training was introduced in "NeRF Analogies: Example-Based Visual Attribute Transfer for NeRFs" (CVPR 2024) to enable example-based visual attribute transfer using semantic correspondences [S2].
