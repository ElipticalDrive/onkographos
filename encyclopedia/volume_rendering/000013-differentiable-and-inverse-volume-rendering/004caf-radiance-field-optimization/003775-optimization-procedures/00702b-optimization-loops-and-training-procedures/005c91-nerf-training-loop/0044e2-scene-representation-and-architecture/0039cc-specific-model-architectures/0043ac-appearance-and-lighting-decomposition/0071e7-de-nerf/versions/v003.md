# DE-NeRF

Also called: Decomposed NeRF, Deformation-based Dynamic NeRF with Event Cameras

## Overview
DE-NeRF models rapidly moving and deforming scenes by combining sparse RGB frames with high-speed asynchronous event camera data [S1, unofficial]. It jointly optimizes camera poses and radiance fields while decomposing the scene into geometric, diffuse, and specular components to enable relighting and appearance editing [S2].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Sparse RGB frames, event stream data (timestamps), and initial camera poses [S1, unofficial][S2].
*   **Outputs:** Optimized camera poses, a Signed Distance Field (SDF) for geometry, and decomposed appearance parameters (diffuse albedo, roughness, specular tint) for relighting [S1, unofficial][S2].

**Data Structures:**
*   **SDF Grid:** A 3D grid representing the signed distance field, reconstructed from 2D RGB images to serve as the geometric prior for the MLP inputs [S2].
*   **MLPs:**
    1.  **Pose Network:** Maps event timestamps to camera poses [S1, unofficial].
    2.  **Geometry Network:** Predicts SDF values and geometric features [S2].
    3.  **Appearance MLPs:** Four separate MLPs predicting diffuse albedo, roughness, and specular tint based on geometric features and distance to the grid [S2].
    4.  **Specular Lighting MLP ($F_s$):** Predicts specular lighting coefficients [S2].

**Numbered Steps:**
1.  **Event-Based Pose Estimation:** Use a neural network to map event timestamps $t$ to camera poses $P(t)$ [S1, unofficial]. This provides continuous pose estimation between sparse RGB frames [G].
2.  **Geometric Reconstruction:** Train a Signed Distance Field (SDF) function using 2D RGB images to reconstruct the scene geometry as a display grid [S2]. The SDF provides geometric features and the distance $h$ from a sampling point to the grid surface [S2].
3.  **Scene Decomposition:** For a given ray and sampling point $\mathbf{x}$:
    *   Extract geometric features from the SDF network [S2].
    *   Input geometric features, appearance features, and the distance $h$ into four corresponding MLPs to predict diffuse albedo $\rho_d$, roughness value $\alpha$, and specular tint (hue) $\mathbf{h}_{\text{spec}}$ [S2].
4.  **Diffuse Color Calculation:** Integrate the diffuse reflectance $\rho_d$ with an environment map $\mathbf{L}_{\text{env}}$ to compute the diffuse color $\mathbf{c}_d$ [S2].
    $$ \mathbf{c}_d = \int_{\Omega} \rho_d \mathbf{L}_{\text{env}}(\omega_i) (\mathbf{n} \cdot \omega_i) d\omega_i $$
    [G] (Standard environment map convolution assumed as exact integration method is not specified in sources.)
5.  **Specular Color Calculation:**
    *   Train a specular lighting MLP $F_s$ to get specular lighting coefficients $\mathbf{c}_l$ [S2].
    *   Multiply the specular lighting $\mathbf{c}_l$ with the specular tint (hue) $\mathbf{h}_{\text{spec}}$ to get the specular color $\mathbf{c}_s$ [S2].
    $$ \mathbf{c}_s = \mathbf{c}_l \odot \mathbf{h}_{\text{spec}} $$
    [S2]
6.  **Final Color Computation:** Calculate the final color $\mathbf{c}$ as the sum of diffuse and specular components [S2].
    $$ \mathbf{c} = \mathbf{c}_s + \mathbf{c}_d $$
    [S2]
7.  **Rendering:** Integrate the color $\mathbf{c}$ along the ray using standard volume rendering, weighted by the SDF-derived density or opacity [S2, G]. The pixel color computation follows the volumetric rendering equation defined in [Specific Model Architectures](8585-specific-model-architectures.md).
8.  **Joint Optimization:** Optimize the camera poses (via the event-based network), the SDF, and the appearance MLPs jointly to minimize the difference between rendered and observed RGB frames [S1, unofficial][S2].

**Parameters:**
*   **Event Threshold:** Not given in the sources. [S1, unofficial][S2]
*   **MLP Hidden Layers:** Not given in the sources. [S1, unofficial][S2]
*   **Environment Map Resolution:** Not given in the sources. [S1, unofficial][S2]

**Edge Cases and Pitfalls:**
*   **Sparse RGB Frames:** The method relies on event cameras for temporal continuity; if event data is missing or noisy, pose estimation may fail [S1, unofficial].
*   **Specular/Diffuse Separation:** Incorrect decomposition can lead to artifacts in relighting [S2].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. [S1, unofficial][S2]
*   **Memory Complexity:** Not given in the sources. [S1, unofficial][S2]
*   **Measured Performance:** On NeRF Synthetic and Shiny Blender datasets, PSNR is 2 points higher than latest papers [S2].
*   **Strengths:** Handles rapidly moving and deforming scenes; enables relighting and appearance editing; leverages event cameras for high-speed dynamics [S1, unofficial][S2].
*   **Limitations:** Requires synchronized RGB and event camera data; complex joint optimization; relies on SDF reconstruction which may be sensitive to initialization [S1, unofficial][S2].
*   **When to use:** Dynamic scenes with fast motion where traditional RGB-based NeRF fails; applications requiring relighting of dynamic objects [S1, unofficial][S2].

## Background
DE-NeRF was proposed to address the limitations of NeRF in dynamic scenes, specifically for rapidly moving and deforming objects [S1, unofficial]. It builds on the principle of decomposing lighting, geometry, and appearance to allow relighting of high-frequency environments and appearance editing [S2]. The method integrates event cameras, which offer high temporal resolution, with sparse RGB frames to model dynamic scenes effectively [S1, unofficial].
