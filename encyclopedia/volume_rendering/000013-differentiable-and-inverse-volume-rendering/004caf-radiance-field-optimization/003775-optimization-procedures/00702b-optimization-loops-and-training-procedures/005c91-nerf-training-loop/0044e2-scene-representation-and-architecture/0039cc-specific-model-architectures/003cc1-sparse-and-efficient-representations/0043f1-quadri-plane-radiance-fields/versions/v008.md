# Quadri-Plane Radiance Fields

Also called: 4-Plane Representation, Quadri-Plane Model

## Overview
Quadri-Plane Radiance Fields represent a 3D scene using four multi-channel 2D feature planes coupled with a decoder MLP, designed to allow computationally efficient volumetric super-resolution by leveraging 2D image super-resolution techniques [S1, unofficial]. It diverges from typical volumetric schemes by using explicit feature vectors arranged in planes rather than a dense 3D grid or hash table, allowing the scene to be viewed as a pair of 3D fields for density and radiance [S1, unofficial]. It sets itself apart from siblings like [Mega-NeRF Spatial Partitioning](8776-mega-nerf-spatial-partitioning.md) and [Sparse Radiance Field (SRF) Representation](8876-sparse-radiance-field-srf-representation.md) by relying on fixed, axis-aligned 2D planes for positional data and a dedicated view-direction plane, rather than spatial hashing or octrees [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A 3D point $p \in \mathbb{R}^3$ and a viewing direction defined by azimuth $\theta_p$ and elevation $\phi_p$.
*   **Output:** Volume density $\sigma$ and RGB radiance $\{r, g, b\}$ for the point.

**Data Structures**
The scene representation $P_s$ consists of four planes:
1.  Three positional planes: $P_{xy}, P_{xz}, P_{yz}$.
2.  One view-direction plane: $P_{dir}$.

**Layout and Dimensions:**
*   Positional planes $P_{xy}, P_{xz}, P_{yz}$: Dimensions $N \times N \times C$.
*   View-direction plane $P_{dir}$: Dimensions $N_{dir} \times N_{dir} \times C$.
*   Typical values: $N=200$, $N_{dir}=32$, $C=48$ [S1, unofficial].

**Decoders**
Two fully-connected MLPs are used:
1.  **Coarse Decoder ($D_c$):** 128 channels, 4 layers.
2.  **Fine Decoder ($D_f$):** 128 channels, 4 layers.
3.  **Radiance Decoder:** Identical characteristics to density MLPs (128 channels, 4 layers) [S1, unofficial].

**Algorithm Steps**
1.  **Positional Feature Retrieval:** For point $p$, retrieve feature vectors from the three positional planes via bilinear interpolation.
    *   $v_{p,xy} = \text{BilinearInterpolate}(P_{xy}, p_x, p_y)$
    *   $v_{p,xz} = \text{BilinearInterpolate}(P_{xz}, p_x, p_z)$
    *   $v_{p,yz} = \text{BilinearInterpolate}(P_{yz}, p_y, p_z)$
2.  **Positional Aggregation:** Compute the average of the positional feature vectors to form $v_p$.
    $$v_p = \frac{1}{3} (v_{p,xy} + v_{p,xz} + v_{p,yz})$$
3.  **View-Direction Feature Retrieval:** Determine the viewing direction $(\theta_p, \phi_p)$ for the ray passing through $p$. Retrieve a complementary feature vector $v_{pdir}$ from $P_{dir}$ via bilinear interpolation at coordinates $(\theta_p, \phi_p)$.
    $$v_{pdir} = \text{BilinearInterpolate}(P_{dir}, \theta_p, \phi_p)$$
4.  **Density Computation:** Compute density $\sigma$ using the coarse decoder $D_c$ and fine decoder $D_f$.
    *   $\sigma_c = D_c(v_p)$
    *   $\sigma_f = D_f(v_p)$
    *   The final density $\sigma$ is derived from these outputs (typically via volume rendering integration, though the specific combination of $\sigma_c$ and $\sigma_f$ for the final $\sigma$ value is not explicitly defined in the source text beyond their use in rendering) [S1, unofficial].
5.  **Radiance Computation:** Compute radiance $\{r, g, b\}$ using the radiance decoder MLP.
    *   Concatenate all four feature vectors: $v_{concat} = [v_{p,xy}, v_{p,xz}, v_{p,yz}, v_{pdir}]$.
    *   $\{r, g, b\} = \text{RadianceDecoder}(v_{concat})$
    *   Note: The view-direction plane $P_{dir}$ affects only radiance, not density, as volume density does not vary with viewing direction in the real world [S1, unofficial].

**Pseudocode**
```python
import numpy as np

def bilinear_interpolate(plane, u, v):
    """
    Performs bilinear interpolation on a 2D plane at coordinates (u, v).
    plane: numpy array of shape (H, W, C)
    u, v: float coordinates in [0, 1] range (normalized to plane dimensions)
    Returns: numpy array of shape (C,)
    """
    H, W, C = plane.shape
    # Normalize coordinates to pixel indices
    u_idx = u * (W - 1)
    v_idx = v * (H - 1)
    
    # Floor and ceil indices
    u0, v0 = int(np.floor(u_idx)), int(np.floor(v_idx))
    u1, v1 = min(u0 + 1, W - 1), min(v0 + 1, H - 1)
    
    # Interpolation weights
    du = u_idx - u0
    dv = v_idx - v0
    
    # Get corner values
    q00 = plane[v0, u0, :]
    q01 = plane[v0, u1, :]
    q10 = plane[v1, u0, :]
    q11 = plane[v1, u1, :]
    
    # Bilinear interpolation
    top = q00 * (1 - du) + q01 * du
    bottom = q10 * (1 - du) + q11 * du
    result = top * (1 - dv) + bottom * dv
    
    return result

def quadri_plane_query(p, theta, phi, P_xy, P_xz, P_yz, P_dir, D_c, D_f, D_rad):
    """
    Queries the Quadri-Plane Radiance Field for density and radiance.
    
    p: numpy array (3,) - 3D point coordinates
    theta: float - viewing azimuth
    phi: float - viewing elevation
    P_xy, P_xz, P_yz: numpy arrays (N, N, C) - positional planes
    P_dir: numpy array (N_dir, N_dir, C) - view-direction plane
    D_c, D_f, D_rad: callable MLPs - decoders
    """
    # 1. Retrieve positional features
    v_pxy = bilinear_interpolate(P_xy, p[0], p[1])
    v_pxz = bilinear_interpolate(P_xz, p[0], p[2])
    v_pyz = bilinear_interpolate(P_yz, p[1], p[2])
    
    # 2. Aggregate positional features
    v_p = (v_pxy + v_pxz + v_pyz) / 3.0
    
    # 3. Retrieve view-direction feature
    # Note: theta and phi must be normalized to [0, 1] for interpolation
    v_pdir = bilinear_interpolate(P_dir, theta, phi)
    
    # 4. Compute density
    sigma_c = D_c(v_p)
    sigma_f = D_f(v_p)
    # The source does not specify the exact formula combining sigma_c and sigma_f
    # into the final sigma used for rendering. [G] Assuming standard NeRF 
    # coarse-to-fine integration or direct usage as per implementation.
    sigma = sigma_c # Placeholder for exact combination logic not in source
    
    # 5. Compute radiance
    v_concat = np.concatenate([v_pxy, v_pxz, v_pyz, v_pdir])
    radiance = D_rad(v_concat)
    
    return sigma, radiance
```

**Parameters**
*   $N$: Plane resolution for positional planes. Determines visual frequency representation. Too small prohibits high frequencies; too large causes artifacts due to insufficient information in LR training images. Typical value for LR: $N=200$ (learned from 100px images) [S1, unofficial].
*   $N_{dir}$: View-direction plane resolution. Set smaller than positional planes ($N_{dir} < N$) because each pixel's information is relevant to only one point on $P_{dir}$ (same viewing direction for all points on a ray), whereas it is relevant to many points on positional planes. Typical value: $N_{dir}=32$ [S1, unofficial].
*   $C$: Number of channels. Typical value: $C=48$ [S1, unofficial].

**Edge Cases and Pitfalls**
*   **View-direction dependency:** Without $P_{dir}$, reconstruction performance drops significantly, especially for shiny/reflective objects with non-uniform lighting. Using $P_{dir}$ improves PSNR (e.g., 29.6 dB vs 23.7 dB in the source context) [S1, unofficial].
*   **Resolution trade-off:** Using planes that are too small prohibits the representation of high visual frequencies. Using too large planes results in some plane regions having too little relevant information in the captured scene images, manifested as visual artifacts when rendering novel scene views [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** On an NVIDIA A100 GPU, training uses Adam optimizers with learning rates of 0.0005 for the decoder and feature planes and 0.00005 for the SR model $F$. 4096 rays are sampled per step [S1, unofficial].
*   **Strengths:** Allows computationally efficient volumetric super-resolution by leveraging 2D image SR techniques. The fixed plane structure simplifies the representation compared to dense 3D grids.
*   **Limitations:** The resolution $N$ must be carefully chosen relative to the training image resolution. Too small $N$ limits frequency, too large $N$ causes artifacts. The method relies on the assumption that density is view-independent, which may not hold for participating media or complex lighting effects not captured by the view-direction plane.
*   **When to use:** When volumetric super-resolution is required and 2D SR techniques can be effectively adapted to 3D plane representations. Suitable for scenes where view-dependent effects are primarily due to lighting and reflectance, captured by the $P_{dir}$ plane.
*   **When not to use:** For scenes with complex view-dependent density (e.g., smoke, fog) or when high-frequency details require resolutions that exceed the memory budget for the planes.

## Background
Quadri-Plane Radiance Fields were proposed in "Neural Volume Super-Resolution" [S1, unofficial]. The work builds on the idea of using feature planes for scene representation, initially proposed by Chan et al. [9] for human faces, and extends it to general scenes. It diverges from typical neural rendering methods [32] by using explicit feature vectors arranged in planes. The introduction of the fourth plane $P_{dir}$ addresses the limitation of positional planes alone in capturing non-uniform lighting and reflective effects. The method is designed to be trained end-to-end, leveraging advances in 2D image super-resolution (e.g., EDSR [25]) for the super-resolution component.
