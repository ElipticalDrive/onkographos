# Neural Light Field (NeLF)

Also called: Implicit Neural Light Field, LFN, Light Field Network with Local Ray Conditioning

## Overview
Neural Light Field (NeLF) is a scene representation method that maps camera rays directly to RGB color values, bypassing the volumetric ray-marching and alpha-composition steps required by Neural Radiance Fields (NeRF) [S1, S3]. Unlike NeRF, which requires multiple forward passes per ray to aggregate radiance, NeLF achieves novel view synthesis with a single forward pass per ray, enabling rendering speeds that are orders of magnitude faster [S2, S3]. While standard NeLF implementations often use shallow networks, efficient variants like R2L employ deep residual MLPs trained via knowledge distillation from a pre-trained NeRF teacher to maintain high visual fidelity [S3].

## How it works
**Inputs and Outputs:**
The method takes a camera ray, parameterized by its origin $\mathbf{o} = (x_o, y_o, z_o)$ and direction $\mathbf{d} = (x_d, y_d, z_d)$, and outputs a 3D RGB color vector $\mathbf{c} = (r, g, b)$ [S3].

**Data Structures and Layout:**
1.  **Ray Representation:** The ray is encoded as a concatenation of spatial coordinates of $K$ sampled points along the ray, forming a $3K$-dimensional input vector [S3]. In the R2L implementation, $K=16$ [S3].
2.  **Network Architecture:** A deep residual Multi-Layer Perceptron (MLP) $G_\phi$ maps the input ray to RGB [S3]. Common configurations include width $W=256$ and depth $D=88$ (W256D88, ~12M FLOPs) or $W=181, D=88$ (W181D88, ~6M FLOPs) [S3]. The network uses extensive residual blocks [S3].
3.  **Positional Encoding:** Inputs are enriched using positional encoding $\gamma(\cdot)$ to mitigate spectral bias [S1, S3].
    $$
    \gamma(\mathbf{x}) = (\sin(2^0 \pi \mathbf{x}), \cos(2^0 \pi \mathbf{x}), \dots, \sin(2^{L-1} \pi \mathbf{x}), \cos(2^{L-1} \pi \mathbf{x}))
    $$
    where $L$ is the number of frequency bands [S1, S3].

**Training Procedure (Distillation):**
NeLF is typically trained by distilling knowledge from a pre-trained NeRF teacher model $F_{\Theta^*}$ [S3].
1.  **Pseudo Data Generation:** Rays are sampled from a uniform distribution $U$ within a viewing bounding box inferred from training camera poses [S3].
    $$
    \begin{aligned}
    x_o &\sim U(x_{o,\min}, x_{o,\max}), & y_o &\sim U(y_{o,\min}, y_{o,\max}), & z_o &\sim U(z_{o,\min}, z_{o,\max}) \\
    x_d &\sim U(x_{d,\min}, x_{d,\max}), & y_d &\sim U(y_{d,\min}, y_{d,\max}), & z_d &\sim U(z_{d,\min}, z_{d,\max})
    \end{aligned}
    $$
    The teacher model queries these rays to obtain target RGB values $(\hat{r}, \hat{g}, \hat{b})$ [S3].
2.  **Loss Function:** The NeLF student network $G_\phi$ is trained using Mean Squared Error (MSE) loss between its output and the teacher's output [S3].
    $$
    L = \text{MSE}(G_\phi(x_o, y_o, z_o, x_d, y_d, z_d), (\hat{r}, \hat{g}, \hat{b}))
    $$
3.  **Hard Example Mining:** To focus on high-frequency details, a pool of hard examples (rays with larger loss) is maintained. In each iteration, the top $r$ fraction of batch losses is added to the pool, and $r$ examples are randomly picked from the pool to augment the training batch [S3]. Default $r=0.2$ [S3].

**Rendering:**
During inference, for each pixel, a ray is defined. $K$ points are evenly spaced along the ray [S3]. The concatenated coordinates are fed into $G_\phi$ to directly predict the pixel color [S3].

import torch.nn as nn
import torch.nn.functional as F

class PositionalEncoding(nn.Module):
    def __init__(self, num_bands):
        super().__init__()
        self.num_bands = num_bands

    def forward(self, x):
        # x shape: (..., 3)
        scales = torch.tensor([2**i for i in range(self.num_bands)], dtype=x.dtype, device=x.device)
        x = x.unsqueeze(-1) * scales.view(1, 1, 1, -1)
        x = torch.cat([torch.sin(x), torch.cos(x)], dim=-1)
        return x.view(x.shape[0], -1)

class ResidualBlock(nn.Module):
    def __init__(self, width):
        super().__init__()
        self.fc1 = nn.Linear(width, width)
        self.fc2 = nn.Linear(width, width)
        self.relu = nn.ReLU()

    def forward(self, x):
        out = self.fc1(x)
        out = self.relu(out)
        out = self.fc2(out)
        return x + out

class NeLF(nn.Module):
    def __init__(self, width=256, depth=88, num_pe_bands=10):
        super().__init__()
        self.pe = PositionalEncoding(num_pe_bands)
        input_dim = 3 * 16 * (2 * num_pe_bands) # K=16 points, 3 coords, 2*bands per coord
        self.input_layer = nn.Linear(input_dim, width)
        
        layers = []
        for _ in range(depth):
            layers.append(ResidualBlock(width))
        self.residual_layers = nn.ModuleList(layers)
        
        self.output_layer = nn.Linear(width, 3) # RGB

    def forward(self, ray_coords):
        """
        ray_coords: (batch_size, 3*K) where K=16
        """
        # Reshape to (batch_size, K, 3) for PE
        b_size = ray_coords.shape[0]
        coords_3d = ray_coords.view(b_size, 16, 3)
        
        # Apply positional encoding
        pe_coords = self.pe(coords_3d) # (b_size, 16, 3 * 2 * bands)
        pe_flat = pe_coords.view(b_size, -1)
        
        x = self.input_layer(pe_flat)
        for layer in self.residual_layers:
            x = layer(x)
        rgb = self.output_layer(x)
        return rgb

    # In practice, one might average teacher outputs or use the first/last point.
    # However, S3 Eq 2 shows teacher queried with origin/direction.
    # Let's assume we extract origin and direction from the first and last point of the batch_coords
    # or simply pass the ray parameters if available. 
    # For this self-contained code, we assume we have ray origins/directions or derive them.
    # Here we assume batch_coords contains the K points. 
    # To match S3, we need origin and direction.

    # Since the prompt asks for self-contained, we will assume the input `ray_coords`

## Subtopics

### [Point-based Neural Light Field](17252-point-based-neural-light-field.md)
A variant that samples points along the ray and predicts density/color for each point, accumulating them via volume rendering. It differs from direct ray-to-color mapping by avoiding the 3D geometry-agnostic nature of direct mapping, though it introduces entanglement between point coordinates.

## Operating characteristics
- **Time Complexity:** Rendering requires a single forward pass per ray, resulting in $O(1)$ queries per pixel compared to $O(N)$ for NeRF ray marching [S3].
- **Memory Complexity:** The model size is determined by the MLP parameters (e.g., 12M FLOPs for W256D88) [S3]. No voxel grids or large feature volumes are stored [S3].
- **Performance:** On synthetic scenes, R2L achieves a 26–35× FLOPs reduction and 28–31× wall-time speedup compared to NeRF [S3]. On the DTU dataset with 3 input views, rendering time is 0.25 seconds compared to 27.01 seconds for PixelNeRF [S1].
- **Quality:** On synthetic scenes, R2L achieves a 1.4–2.8 dB average PSNR improvement over NeRF [S3]. On DTU with 3 views, PSNR is 19.86 and SSIM is 0.657 [S1].
- **Limitations:** May lack high-frequency details compared to NeRF-based counterparts [S1]. Deep networks require residual connections to be trainable [S3].

## Background
Neural Light Fields were introduced as an alternative to Neural Radiance Fields to enable real-time rendering by mapping rays directly to radiance [S2]. The R2L method, a prominent implementation, was proposed by Wang et al. to distill NeRF knowledge into a deep residual NeLF network, achieving significant speedups without customized parallelism [S3].
