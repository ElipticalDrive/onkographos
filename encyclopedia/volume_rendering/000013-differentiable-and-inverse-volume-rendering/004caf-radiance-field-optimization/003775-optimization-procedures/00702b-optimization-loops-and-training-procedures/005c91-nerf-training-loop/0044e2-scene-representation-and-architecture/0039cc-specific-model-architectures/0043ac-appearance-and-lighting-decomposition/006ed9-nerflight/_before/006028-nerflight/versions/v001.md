# NeRFLight


## Overview
NeRFLight is a grid-based neural radiance field architecture designed to achieve real-time view synthesis with a significantly reduced memory footprint compared to standard grid-based methods like Instant-NGP or KiloNeRF [S1, S2]. It solves the trade-off between rendering speed and model size by splitting the 3D scene volume into $N$ distinct spatial regions, each utilizing a separate density decoder but sharing a single, compact feature grid [S1]. Unlike Instant-NGP, which uses hash grids and multiresolution schemes that can suffer from rendering speed losses due to multiple linear interpolations, NeRFLight avoids hash grids entirely and instead uses multiple density decoders to handle feature collisions, ensuring high frame rates [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of training images with known camera poses $(o_j, d_j)$ defining rays $r_j(t) = o_j + d_j t$, and a 3D scene volume bounded by a region of interest.
*   **Output:** A rendered image pixel color $C(\mathbf{r})$ for a given ray, and a compact model representation (shared feature grid + decoder weights) suitable for inference.

**Data Structures:**
1.  **Shared Feature Grid:** A 3D grid of latent features. The grid is symmetrically configured such that features are placed at multiple spatial positions corresponding to the $N$ regions. This symmetry favors feature pruning after training and allows smooth gradient transitions between neighboring voxels [S1].
2.  **Density Decoders:** $N$ separate Multi-Layer Perceptrons (MLPs), denoted as $\theta_i$ for region $i \in [1, N]$. Each decoder takes features from the shared grid and outputs density $\sigma$ and an intermediate latent representation $h$ [S1].
3.  **Color Decoder:** A single MLP that takes the intermediate representation $h$, the viewing direction $\mathbf{d}$, and potentially other lighting parameters to output the final color $\mathbf{c}$ [S1, S2].

**Numbered Steps:**
1.  **Scene Partitioning:** Divide the 3D scene volume into $N$ distinct spatial regions. In the canonical implementation, $N=8$ [S1, S2].
2.  **Feature Grid Initialization:** Create a single shared feature grid. Features are arranged symmetrically across the regions. This configuration forces features to learn a compact representation valid for different parts of the scene, reducing the total number of stored feature values by a factor of $N$ (e.g., 8x reduction) compared to using separate grids per region [S1, S2].
3.  **Ray Sampling:** For a given ray $\mathbf{r}$, sample points $\mathbf{x}_j$ along the ray.
4.  **Region Identification:** Determine which of the $N$ regions a sample point $\mathbf{x}_j$ falls into. Let $i$ be the index of the region containing $\mathbf{x}_j$.
5.  **Feature Lookup:** Retrieve the latent features $\hat{f}(\mathbf{x}_j)$ from the shared feature grid at position $\mathbf{x}_j$.
6.  **Density and Latent Prediction:** Pass the features $\hat{f}(\mathbf{x}_j)$ to the region-specific density decoder $\theta_i$:
    $$
    \sigma_j, h_j = \theta_i(\hat{f}(\mathbf{x}_j))
    $$
    where $\sigma_j$ is the volume density and $h_j$ is the intermediate latent representation [S1].
7.  **Color Prediction:** Pass the intermediate representation $h_j$, the viewing direction $\mathbf{d}$, and the positional encoding of the position $\gamma(\mathbf{x}_j)$ to the color decoder to obtain the color $\mathbf{c}_j$ [S1, S2]. Note: The parent article specifies that the color network takes latent features, $\gamma(\mathbf{x})$, and $\mathbf{d}$ [Parent].
8.  **Volumetric Rendering:** Compute the pixel color $C(\mathbf{r})$ using deterministic volume integration (as opposed to Monte Carlo integration) [S1]:
    $$
    C(\mathbf{r}) = \sum_{j=1}^{M} T_j \alpha_j \mathbf{c}_j
    $$
    where $\alpha_j = 1 - \exp(-\sigma_j \delta_j)$ is the opacity, $T_j = \prod_{k=1}^{j-1} (1 - \alpha_k)$ is the accumulated transmittance, and $\delta_j$ is the distance between samples [Parent, S1].

**Edge Cases and Pitfalls:**
*   **Feature Collisions:** By sharing the feature grid, features must represent multiple regions. This forces compactness but may lead to ambiguity if the scene has distinct features in different regions that are mapped to the same grid location. NeRFLight handles this by using multiple density decoders [S1].
*   **Boundary Artifacts:** The symmetry of the feature configuration is designed to favor smooth gradient transitions between neighboring voxels, reducing artifacts at region boundaries [S1].
*   **Empty Space:** Empty space pruning is applied to accelerate model inference, removing features that do not contribute to the visible scene [S1].

## Operating characteristics
*   **Rendering Speed:** Achieves real-time performance of up to 181 FPS [S1].
*   **Model Size:** The model size is approximately 14MB [S1].
*   **Efficiency:** The FPS/MB ratio is 2x larger than the closest state-of-the-art approach at the time of publication [S1].
*   **Memory Footprint:** The shared feature grid reduces the total number of stored feature values by a factor of $N$ (8x reduction compared to separate grids) [S1, S2].
*   **Strengths:** High rendering speed, small model size, real-time capability, seamless reconstruction due to symmetric feature configuration.
*   **Limitations:** The method relies on a fixed number of regions ($N=8$ in the paper), which may not adapt well to scenes of varying complexity without retraining. It does not use hash grids or multiresolution schemes, which might limit its ability to capture fine details in very large scenes compared to Instant-NGP [S1].
*   **When to use:** When real-time rendering and low memory footprint are critical, and the scene can be effectively partitioned into a small number of regions.
*   **When not to use:** For scenes requiring extremely high detail across a vast volume where a fixed partitioning scheme is insufficient, or when dynamic resolution adaptation is needed.

## Background
NeRFLight was introduced by Rivas-Manzaneque et al. in 2023 [S1]. It extends grid-based NeRF approaches by addressing the memory footprint issues that prevent deployment on bandwidth-constrained applications [S1]. The method builds on the idea of splitting the density field into multiple regions with separate decoders, similar to KiloNeRF, but avoids baking a large number of MLPs by using a shared feature grid [S1]. It also leverages deterministic volume integration from [48] to improve accuracy and speed [S1]. The approach was evaluated on synthetic and real data, demonstrating state-of-the-art FPS/MB ratios [S1].
