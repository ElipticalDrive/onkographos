# Multi-Identity Embedding
## Overview
Multi-Identity Embedding is a method for identifying contributing users in collaborative Neural Radiance Field (NeRF) training by embedding customized hidden information about specific clusters of training views [S1]. It solves the problem of scalable attribution in multi-user scenarios by allowing a single NeRF model to hide distinct identities for different spatial regions without requiring model retraining for each new watermark [S1]. Unlike prior approaches that embed only a single global watermark, this method assigns identity information to specific clusters of anchor views, preventing false positives for unmarked identities [S1]. It builds on [StegaNeRF Training Algorithm](16783-steganerf-training-algorithm.md).

## How it works
**Inputs and Outputs:**
*   **Input:** A collection of user-uploaded training images with camera poses [S1].
*   **Output:** A NeRF model with a modified classifier network capable of recovering specific contributor identities based on the rendering viewpoint [S1].

**Data Structures:**
*   **Classifier Network ($F_{\phi_c}$):** A neural network component that outputs a probability distribution over $M+1$ classes: $M$ classes corresponding to specific contributor clusters, and one additional class for "unmarked" identities [S1].

**Steps:**
1.  **Anchor Selection:** Select $M$ anchor views with distinct viewing positions from the training set [S1].
2.  **Cluster Formation:** For each anchor view, find the $K$ nearest neighbor views based on viewing position to form a cluster [S1]. Each cluster is assumed to share a common contributor identity [S1].
3.  **Network Modification:** Modify the classifier network $F_{\phi_c}$ to output $M$-class cluster predictions plus one class for identities outside the $M$ clusters [S1].
4.  **Loss Computation for Unmarked Views:** For poses outside the $M$ clusters, compute the decoding loss $L^{-dec}$ and the classification loss $L_{dec}$ to ensure no information is recovered for unmarked identities, thereby preventing false positives [S1].

**Parameters:**
*   $M$: Number of anchor views/clusters. Typical value: 3 [S1].
*   $K$: Number of nearest neighbours per anchor. Typical value: 20 [S1].

**Pseudocode:**
```python
def multi_identity_embedding(training_images, M=3, K=20):
    """
    Embeds M distinct contributor identities into a NeRF model.
    Args:
        training_images: List of dicts with 'pose' (3D camera position) and 'image'.
        M: Number of anchor views/clusters.
        K: Number of nearest neighbours per anchor.
    Returns:
        model: Trained NeRF model with embedded identity classifier.
    """
    # Step 1: Select M anchor views with different viewing positions
    anchors = training_images[:M]  # [G] Sources specify random selection; this is a deterministic proxy
    
    # Step 2: Form clusters by finding K nearest neighbours for each anchor
    clusters = []
    for anchor in anchors:
        distances = [sqrt(sum((anchor['pose'][d] - view['pose'][d])**2 for d in range(3))) for view in training_images]
        sorted_indices = sorted(range(len(distances)), key=lambda i: distances[i])
        neighbors = [training_images[i] for i in sorted_indices[:K]]
        clusters.append(neighbors)
        
    # Step 3: Modify classifier network F_phi_c to output M+1 classes
    # M classes for clusters, 1 class for unmarked identities
    classifier = ClassifierNetwork(num_output_classes=M + 1)  # [G] Standard neural network head
    
    # Step 4: Train NeRF with StegaNeRF objectives
    total_loss = 0.0
    for batch in training_images:  # [G] Standard mini-batch iteration
        # Standard StegaNeRF rendering and encoding steps occur here
        # [G] Standard NeRF volume rendering and StegaNeRF encoding logic
        
        # Identify unmarked poses in the batch
        unmarked_poses = []
        for view in batch:
            is_marked = any(view in cluster for cluster in clusters)
            if not is_marked:
                unmarked_poses.append(view)
                
        # Compute losses for unmarked views to prevent false positives
        if unmarked_poses:
            # L_dec ensures the classifier predicts the 'unmarked' class correctly
            loss_dec = cross_entropy(classifier(unmarked_poses), target_class=M)
            # L^-dec ensures no hidden information is recoverable for unmarked views
            loss_minus_dec = reconstruction_loss(classifier(unmarked_poses), target=None)
            
            total_loss = total_loss + loss_dec + loss_minus_dec

    return train_model(training_images, classifier, total_loss)
```

## Subtopics

### [MultiNeRF](17853-multinerf.md)
A 3D watermarking method that embeds multiple uniquely keyed watermarks within images rendered by a single NeRF model, specifically extending the TensoRF architecture. It solves the problem of scalable, robust digital watermarking in 3D scenes by allowing distinct messages to be identified by unique integer IDs at rendering time, without requiring model retraining for each new watermark. Unlike prior approaches that embed only a single watermark, MultiNeRF accommodates multiple distinct messages as an additional model input, maintaining high visual quality by isolating watermark features in a dedicated grid rather than entangling them with scene appearance. Choose it when scalable multi-message watermarking is required without retraining.

## Operating characteristics
*   **Time and Memory Complexity:** Not given in the sources.
*   **Measured Performance:** The method was evaluated on the NeRF-W dataset using a network backbone similar to NeRFW [S1]. Qualitative results show successful recovery of User A, User B, and User C identities within their respective clusters, with low recovery scores for unmarked identities (e.g., 0.2368 for User A's identity in an unmarked region) [S1].
*   **Strengths:** Allows scalable, robust digital watermarking in 3D scenes by accommodating multiple distinct messages as an additional model input [S1].
*   **Limitations:** Requires careful selection of anchor views and nearest neighbours to ensure cluster separation [S1].
*   **When to use:** When identifying contributing users in collaborative NeRF projects is required [S1].
*   **When not to use:** Not given in the sources.

## Background
Multi-Identity Embedding was introduced in the paper "StegaNeRF: Embedding Invisible Information within Neural Radiance Fields" [S1]. It addresses the scenario where a collection of user-uploaded training images is used to generate a NeRF, and it is meaningful to identify the contributing users in the rendered output [S1]. The method extends the StegaNeRF framework to handle multiple identities simultaneously [S1].
