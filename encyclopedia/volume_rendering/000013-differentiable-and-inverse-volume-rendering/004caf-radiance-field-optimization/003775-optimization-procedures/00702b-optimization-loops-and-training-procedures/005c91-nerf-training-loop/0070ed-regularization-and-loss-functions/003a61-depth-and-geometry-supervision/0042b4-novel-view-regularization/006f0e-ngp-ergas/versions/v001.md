# NGP-ERGAS

Also called: Instant Neural Graphics Primitives with ERGAS

## Overview
NGP-ERGAS is a regularization and loss function strategy for Instant Neural Graphics Primitives (Instant-NGP) that improves fine detail reconstruction in novel view synthesis by incorporating nonlocal structural information [S1]. Unlike standard Instant-NGP, which computes loss per-pixel independently, NGP-ERGAS groups GPU threads into custom blocks to compute the Relative Dimensionless Global Error (ERGAS) loss, addressing the inability of previous nonlocal methods like S3IM to run on Instant-NGP's tile-independent parallel architecture [S1]. It sets itself apart by using a thread-based strategy to efficiently collect global structure information with lower computational overhead than patch-based SSIM methods [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** Initial NeRF network parameters $\Theta$, a batch of rays (pixels), ground truth image colors $C$, and hyperparameters $M_1$ (thread block size), $\lambda_1$ (ERGAS weight), $\lambda_2$ (SSIM weight).
*   **Outputs:** Updated network parameters $\Theta$.

**Data Structures**
*   **Custom Thread Block:** A set of $M_1$ threads. Defined by an index range $[m_{min}, m_{max}]$ centered on a dominant thread index $\hat{m}$.
    *   $m_{min} = \lceil \hat{m} - M_1/2 \rceil$
    *   $m_{max} = \lfloor \hat{m} + M_1/2 \rfloor$
    *   The thread with index $\hat{m}$ is the **dominant thread**.
    *   Other threads in the block are **auxiliary threads**.
    *   If an auxiliary thread index is 0 or out of the valid image range, it is skipped [S1].
*   **Color Vectors:** For each thread $m$, $C(m)$ is the ground truth RGB color vector, and $\hat{C}(m)$ is the rendered RGB color vector.

**Parameters**
*   $M_1$: Number of threads in a custom thread block. Adjustable. Typical values are not explicitly stated, but it defines the minibatch size for the ERGAS calculation [S1].
*   $\lambda_1$: Weight parameter for the ERGAS term. Determined experimentally [S1].
*   $\lambda_2$: Weight coefficient for the SSIM loss term. Determined experimentally after fixing $\lambda_1$ [S1].
*   Training steps: 4000 steps (as used in reported experiments) [S1].

**Formulas**
1.  **ERGAS for a Thread Block:**
    For RGB images, the number of bands $K=3$. The spatial resolution ratio $h/l=1$. The ERGAS for a specific thread block is computed as [S1]:
    $$
    \text{ERGAS} = 100 \sqrt{\frac{1}{3} \sum_{k=1}^{3} \left( \frac{\frac{1}{M_1} \sum_{m=1}^{M_1} (C_k^m - \hat{C}_k^m)^2}{\left(\frac{1}{M_1} \sum_{m=1}^{M_1} C_k^m\right)^2} \right)}
    $$
    Where $C_k^m$ is the ground truth color value of the $k$-th band (channel) for the pixel corresponding to the $m$-th thread, and $\hat{C}_k^m$ is the rendered color value [S1].

2.  **Average ERGAS Error ($E$):**
    The average ERGAS value over all threads $\hat{m}$ in the block is [S1]:
    $$
    E(\hat{m}, M_1) = \frac{1}{M_1} \sum_{\hat{m}=1}^{M_1} \text{ERGAS}(\hat{C}(\hat{m}) - C(\hat{m}))
    $$
    Where $\hat{C}(\hat{m})$ and $C(\hat{m})$ denote the sets of rendered and ground truth colors for the threads in the block [S1].

3.  **ERGAS Loss Term ($L_{ERGAS}$):**
    Since ERGAS itself does not directly yield a differentiable gradient suitable for standard backpropagation in this context, it is merged with the original color loss (MSE) of the dominant thread [S1]:
    $$
    L_{ERGAS}(\Theta) = \frac{1}{|\Omega|} \sum_{\hat{m} \in \Omega} \| C(\hat{m}) - \hat{C}(\hat{m}) + \lambda_1 E(\hat{m}, M_1) \|^2
    $$
    Where $\Omega$ is the set of pixels in the batch and $|\Omega|$ is the number of pixels [S1].

4.  **SSIM Loss ($L_{SSIM}$):**
    $$
    L_{SSIM} = 1 - \text{SSIM}
    $$
    Where SSIM is the Structural Similarity Index [S1].

5.  **Total Loss ($L_{all}$):**
    $$
    L_{all} = L_{ERGAS} + \lambda_2 L_{SSIM}
    $$
    [S1]

**Algorithm Steps**
1.  Initialize NeRF network parameters $\Theta$.
2.  While stopping criterion is not met:
    3.  Select a current pixel as the dominant thread $\hat{m}$.
    4.  Randomly select $M_1 - 1$ other pixels to form a data minibatch of rays. The threads corresponding to these $M_1$ pixels form a custom thread block.
    5.  Retrieve the ground truth color $C(\hat{m})$ for the dominant thread.
    6.  Compute the rendered colors $\hat{C}(m)$ for all threads $m$ in the custom thread block using the current network parameters $\Theta$.
    7.  Calculate the ERGAS value for the thread block using the formula above.
    8.  Compute the average error $E(\hat{m}, M_1)$ for the block.
    9.  Calculate $L_{ERGAS}(\Theta)$ by adding $\lambda_1 E(\hat{m}, M_1)$ to the color difference term for the dominant thread and averaging over the batch.
    10. Calculate $L_{SSIM}$ for the batch.
    11. Compute the total loss $L_{all} = L_{ERGAS} + \lambda_2 L_{SSIM}$.
    12. Compute the gradient $\nabla L_{all}(\Theta)$.
    13. Update $\Theta$ using a gradient descent optimizer (e.g., Adam).
    14. End While.
    15. Return updated $\Theta$.

**Pseudocode**
```python
def train_ngp_ergas(network, ground_truth_images, rays, M1, lambda1, lambda2, optimizer, max_steps):
    """
    Trains an Instant-NGP style network using the NGP-ERGAS loss function.
    
    Args:
        network: The NeRF network function taking rays and parameters, returning RGB colors.
        ground_truth_images: Dictionary or array mapping ray indices to ground truth RGB vectors.
        rays: List of ray objects or indices to render.
        M1: Number of threads (pixels) in a custom thread block.
        lambda1: Weight for the ERGAS term.
        lambda2: Weight for the SSIM term.
        optimizer: Gradient descent optimizer with step() method.
        max_steps: Maximum number of training iterations.
        
    Returns:
        network: Trained network parameters.
    """
    # Initialize network parameters
    theta = network.get_parameters()
    
    for step in range(max_steps):
        # 1. Sample a batch of rays
        # In Instant-NGP, rays are typically batched for GPU processing.
        # Here we simulate the "custom thread block" logic.
        batch_rays = sample_rays(rays, batch_size=M1)
        
        # 2. Render the batch
        # network(rays, theta) returns rendered RGB colors for the batch
        rendered_colors = network(batch_rays, theta)
        
        # 3. Get ground truth for the batch
        ground_truth_colors = get_ground_truth(ground_truth_images, batch_rays)
        
        # 4. Compute ERGAS Loss
        # ERGAS is computed over the entire block (M1 threads)
        # Formula: 100 * sqrt( (1/3) * sum_k( RMSE_k / mean_k )^2 )
        # Where RMSE_k and mean_k are computed over the M1 pixels in the block for channel k
        
        ergas_value = 0.0
        for k in range(3): # RGB channels
            gt_channel = ground_truth_colors[:, k]
            pred_channel = rendered_colors[:, k]
            
            # Mean of ground truth for this channel in the block
            mean_gt = torch.mean(gt_channel)
            
            # RMSE for this channel in the block
            rmse = torch.sqrt(torch.mean((gt_channel - pred_channel) ** 2))
            
            # Avoid division by zero
            if mean_gt > 1e-6:
                ergas_value += (rmse / mean_gt) ** 2
        
        ergas_value = 100.0 * torch.sqrt(ergas_value / 3.0)
        
        # Average ERGAS error E(m_hat, M1) is just the ERGAS value itself 
        # as it is a scalar for the block in this implementation context.
        # The loss formulation adds this scalar to the per-pixel error.
        # L_ERGAS = (1/|Omega|) * sum || C - C_hat + lambda1 * E ||^2
        # Note: The source describes adding E to the color difference of the dominant thread.
        # In a batched implementation, we apply this regularization term.
        
        # Calculate per-pixel MSE component
        color_diff = ground_truth_colors - rendered_colors
        
        # Add the ERGAS regularization term to the color difference
        # The source implies E is added to the residual.
        # Since E is a scalar for the block, it acts as a global bias correction for the block's error.
        regularized_diff = color_diff + lambda1 * ergas_value
        
        l_ergas = torch.mean(regularized_diff ** 2)
        
        # 5. Compute SSIM Loss
        # L_SSIM = 1 - SSIM
        # SSIM is typically computed over local windows. 
        # For simplicity in this pseudocode, we assume a standard SSIM function.
        ssim_value = compute_ssim(rendered_colors, ground_truth_colors)
        l_ssim = 1.0 - ssim_value
        
        # 6. Total Loss
        l_all = l_ergas + lambda2 * l_ssim
        
        # 7. Backpropagation
        optimizer.zero_grad()
        l_all.backward()
        optimizer.step()
        
        # Update network parameters (handled by optimizer.step() in most frameworks)
        # network.set_parameters(optimizer.get_parameters())

    return network
```

**Edge Cases and Pitfalls**
*   **Boundary Conditions:** If an auxiliary thread index in the custom thread block is 0 or out of the valid image range, it must be skipped during ERGAS calculation [S1].
*   **Gradient Computation:** ERGAS itself does not directly calculate gradients in the standard sense used by the loss function formulation; it is averaged and merged with the original color loss to enable backpropagation [S1].
*   **Computational Cost:** Unlike S3IM, which requires $M$ times random patch forming and SSIM computing per pixel (heavy cost), NGP-ERGAS uses a thread-based strategy to reduce cost [S1]. However, the mutual influence between pixels in the thread block introduces a slight decrease in rendering and reconstruction efficiency compared to standard Instant-NGP [S1].
*   **Hardware Constraints:** DVGO-S3IM requires an L40 GPU with 48 GB memory, whereas NGP-ERGAS runs on an RTX 4060, making direct time comparisons with DVGO-S3IM potentially misleading due to hardware differences [S1].

## Operating characteristics
*   **Time Complexity:** Slightly higher than standard Instant-NGP due to the centralized consideration of the custom thread block and the mutual influence between pixels [S1].
*   **Memory Complexity:** Approximately 10K network parameters, similar to Instant-NGP, and significantly lower than DVGO-S3IM (~22K parameters) [S1].
*   **Measured Performance:**
    *   **NeRF_synthetic Lego:** PSNR 34.093 (vs 34.203 Standard), SSIM 0.99910 (vs 0.99907 Standard), Time 51s (vs 51s Standard) [S1].
    *   **NeRF_synthetic Drums:** PSNR 25.515 (vs 25.507 Standard), SSIM 0.99240 (vs 0.99211 Standard), Time 51s (vs 49s Standard) [S1].
    *   **NeRF_synthetic Ship:** PSNR 29.175 (vs 28.901 Standard), SSIM 0.99854 (vs 0.99843 Standard), Time 50s (vs 48s Standard) [S1].
    *   **Tanks & Temple Family:** PSNR 29.639 (vs 26.902 Instant-NGP), SSIM 0.91487 (vs 0.91068 Instant-NGP), Time 62s (vs 76s Instant-NGP) [S1].
    *   **Ship with Gaussian Noise:** PSNR 19.545 (vs 19.384 Standard), SSIM 0.98992 (vs 0.98899 Standard), Time 44s (vs 40s Standard) [S1].
*   **Scaling:** Improves PSNR, SSIM, LPIPS, and UQI compared to standard Instant-NGP [S1].
*   **Strengths:** Significantly improves visual effect of fine details and structural integrity with fewer iterations; robust to Gaussian noise; lower parameter count than DVGO-S3IM; runs on consumer hardware (RTX 4060) [S1].
*   **Limitations:** Slightly inferior running times compared to standard Instant-NGP due to pixel mutual influence [S1].
*   **When to Use:** When fine detail reconstruction and structural integrity are prioritized over raw training speed, and when running on hardware with limited memory (e.g., RTX 4060 vs L40) [S1].

## Background
*   **Origin:** Introduced in the paper "NGP-ERGAS: Revisit Instant Neural Graphics Primitives with the Relative Dimensionless Global Error in Synthesis" published in *Comput Mater Contin* in 2025 [S1].
*   **History:** Developed to address the limitation that S3IM (which uses random patch forming and SSIM) could not be applied to Instant-NGP due to its parallel programming technique (one thread per pixel) and inapplicability of tiles-based rendering [S1]. NGP-ERGAS transforms the pixel-based strategy into a thread-based strategy using custom thread blocks and ERGAS loss to incorporate nonlocal structural information efficiently [S1].
*   **Usage:** Evaluated on NeRF_synthetic, Tanks & Temple, and DL3DV datasets [S1].
