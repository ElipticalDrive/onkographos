# Depth Supervision

Also called: Depth Prior Supervision, Monocular Depth Supervision

## Overview
Depth Supervision is a training technique that improves reconstructed geometry by providing depth priors using off-the-shelf depth estimation models, resulting in better geometry and reduced number of floaters [S1, unofficial]. It sets itself apart from standard photometric losses by explicitly leveraging rendered depths and input images to derive a geometry-supervision loss, which constrains the location of the surface [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A dataset containing images and corresponding depth maps stored in `<dataset-root>/depths/<FILENAME>.png`, where `FILENAME` matches the dataset image name [S1, unofficial]. A boolean parameter `use_depth_loss` in `OptimizationParams` enables the feature [S1, unofficial].
*   **Outputs:** Updated neural network parameters (or Gaussian attributes) that minimize the depth discrepancy.

**Data Structures:**
*   Depth maps are stored as PNG files in a subdirectory `depths/` relative to the dataset root [S1, unofficial].
*   The implementation must handle a boolean flag `use_depth_loss` to toggle the loss calculation [S1, unofficial].

**Steps:**
1.  **Refitting:** Since depth estimates from off-the-shelf models may vary in scale between frames, all depth maps are refitted against a prior point cloud to the same scale [S1, unofficial].
2.  **Discarding Invalid Maps:** Depth maps that fail the refitting process against the prior point cloud are discarded and not used for supervision [S1, unofficial].
3.  **Rendering:** Compute the rendered depth $\hat{\mathbf{D}}(\mathbf{r})$ for the current view using the differentiable volume rendering framework [G].
4.  **Loss Calculation:** Enforce that the rendered depth matches the depth predicted by a pre-trained monocular depth network (e.g., MiDaS [37]) for the input image [S2]. The loss is typically the difference between the rendered depth and the monocular prediction.

**Pseudocode:**
```python
def compute_depth_loss(rendered_depth, monocular_depth, prior_point_cloud, use_depth_loss):
    """
    Computes the depth supervision loss.
    
    Args:
        rendered_depth: Tensor of shape (H, W) representing the rendered depth map.
        monocular_depth: Tensor of shape (H, W) representing the depth predicted by a monocular network (e.g., MiDaS).
        prior_point_cloud: Point cloud used for scale refitting.
        use_depth_loss: Boolean flag to enable/disable depth supervision.
        
    Returns:
        loss: Scalar tensor representing the depth loss.
    """
    if not use_depth_loss:
        return 0.0

    # Step 1: Refit monocular depth to the scale of the prior point cloud
    # Note: The exact refitting algorithm (e.g., least squares scaling) is not specified in sources.
    # [G] Assuming a simple scale factor estimation via median or mean ratio between 
    # projected point cloud depths and monocular depths in valid regions.
    try:
        # Estimate scale factor s such that s * monocular_depth aligns with prior_point_cloud
        # This step requires projecting the prior point cloud to the image plane to get reference depths.
        # If the refitting fails (e.g., no overlap, large error), discard the map.
        scale_factor = estimate_scale_factor(monocular_depth, prior_point_cloud)
        refitted_depth = monocular_depth * scale_factor
    except RefittingError:
        # Step 2: Discard invalid maps
        return 0.0

    # Step 3: Compute loss between rendered depth and refitted monocular depth
    # [G] Common loss functions for depth include L1 or L2 loss.
    loss = torch.mean(torch.abs(rendered_depth - refitted_depth))
    
    return loss
```

**Parameters:**
*   `use_depth_loss`: A boolean parameter in `OptimizationParams` that enables depth supervision during training [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Refitting Failure:** Depth maps that fail the refitting process against the prior point cloud are discarded [S1, unofficial].
*   **Harmful Effects:** In some cases, monocular depth supervision was found to be harmful to reconstruction quality [S2].
*   **Noise:** Regularization terms involving depth can be noisy [S2].

## Subtopics

### [Refined Depth for Geometry Supervision](19001-refined-depth-for-geometry-supervision.md)
Refined Depth for Geometry Supervision is a lightweight depth-regularization objective used during per-scene training to refine reconstructed geometry, specifically improving local sharpness and depth consistency without sacrificing efficiency. It sets itself apart from standard photometric losses by explicitly leveraging rendered depths and input images to derive a geometry-supervision loss ($L_{refD}$), which is combined with the original training loss to yield more geometrically faithful surfaces with fast convergence.

## Operating characteristics
*   **Time Complexity:** Adds overhead for monocular depth inference and refitting per iteration. The refitting step requires processing the prior point cloud.
*   **Memory Complexity:** Requires storage for depth maps in the dataset directory [S1, unofficial].
*   **Measured Performance:** Sources report mixed results. One source notes it results in "better geometry and reduced number of floaters" [S1, unofficial]. Another source found that "this additional depth loss in most instances did not noticeably improve reconstruction quality and in some cases was harmful" [S2].
*   **Strengths:** Can reduce floaters and improve geometric fidelity when successful [S1, unofficial].
*   **Limitations:** Can be harmful to reconstruction quality in some cases [S2]. Results are not conclusive [S2].
*   **When to use:** When floaters are a significant issue and other methods (like image-specific prompts) are not available or effective [S2].
*   **When not to use:** When reconstruction quality is already high and depth supervision introduces noise or harm [S2].

## Background
*   **Origin:** The technique is discussed in the context of Gaussian Splatting optimization [S1, unofficial] and RealFusion [S2].
*   **History:** It was explored as a way to improve geometry in single-view or multi-view reconstruction pipelines by leveraging pre-trained monocular depth networks like MiDaS [37] [S2].
*   **Usage:** Used in 3D reconstruction pipelines to constrain the location of surfaces [S1, unofficial].
