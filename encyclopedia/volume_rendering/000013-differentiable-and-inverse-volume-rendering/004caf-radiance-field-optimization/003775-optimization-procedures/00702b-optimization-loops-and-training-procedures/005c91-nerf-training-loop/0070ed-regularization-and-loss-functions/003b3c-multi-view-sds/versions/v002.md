# Multi-view SDS

Also called: BoostDream

## Overview
Multi-view SDS is a plug-and-play regularization method that addresses the Janus problem caused by one-by-one view sampling in standard Score Distillation Sampling (SDS) [S1][S2, unofficial]. Unlike single-view approaches, it stitches rendered images from four sampled views into a single $2 \times 2$ composite image and computes gradients conditioned on a multi-view normal map to enforce geometric consistency across the 3D asset [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A differentiable 3D representation (NeRF, 3DGS, or DMTet) [S1][S2, unofficial], a text prompt, a diffusion model, and a set of $N=4$ camera viewpoints [S1][S2, unofficial].
*   **Outputs:** Optimized 3D representation parameters [S1][S2, unofficial].

**Data Structures:**
*   **Composite Image:** A $2 \times 2$ grid formed by stitching $N$ rendered views [S1][S2, unofficial].
*   **Multi-view Normal Map:** A composite image of normal vectors corresponding to the stitched views, used to condition the gradient calculation [S1][S2, unofficial].

**Steps:**
1.  Sample $N=4$ distinct camera viewpoints for the current optimization step [S1][S2, unofficial].
2.  Render the current 3D representation from each viewpoint to produce individual color images $\mathbf{I}_1, \dots, \mathbf{I}_4$ and normal maps $\mathbf{N}_1, \dots, \mathbf{N}_4$ [S1][S2, unofficial].
3.  Construct a composite image $\mathbf{I}_{\text{multi}}$ by stitching $\mathbf{I}_1, \dots, \mathbf{I}_4$ into a $2 \times 2$ grid [S1][S2, unofficial].
4.  Construct a composite normal map $\mathbf{N}_{\text{multi}}$ from $\mathbf{N}_1, \dots, \mathbf{N}_4$ [S1][S2, unofficial].
5.  Compute the SDS gradients conditioned on $\mathbf{N}_{\text{multi}}$ using the diffusion model [S1][S2, unofficial].
6.  Backpropagate the gradients through the differentiable rendering process to update the 3D representation parameters [S1][S2, unofficial].

**Pseudocode:**
```python
def multi_view_sds_step(nerf_model, diffusion_model, text_prompt, cameras):
    N = len(cameras)
    assert N == 4, "Multi-view SDS uses 4 views [S1][S2, unofficial]."
    color_imgs, normal_imgs = [], []
    for cam in cameras:
        c, n = nerf_model.render(cam)
        color_imgs.append(c)
        normal_imgs.append(n)
    # Stitch 4 views into 2x2 grid [S1][S2, unofficial]
    h, w = color_imgs[0].shape[:2]
    comp_color = np.zeros((2*h, 2*w, 3), dtype=np.float32)
    comp_normal = np.zeros((2*h, 2*w, 3), dtype=np.float32)
    for i in range(4):
        r, c = divmod(i, 2)
        comp_color[r*h:(r+1)*h, c*w:(c+1)*w] = color_imgs[i]
        comp_normal[r*h:(r+1)*h, c*w:(c+1)*w] = normal_imgs[i]
    # Compute SDS gradients conditioned on multi-view normal map [S1][S2, unofficial]
    # Standard SDS gradient: grad = w * (E[epsilon_0] - epsilon_theta)
    # Conditioned on composite normal map; exact diffusion conditioning omitted as not in sources [G]
    grad = diffusion_model.compute_sds_gradient(comp_color, comp_normal, text_prompt)
    return grad
```

**Parameters:**
*   **Number of views ($N$):** Typically 4 [S1][S2, unofficial].
*   **Grid Layout:** $2 \times 2$ [S1][S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Normal Map Alignment:** The multi-view normal map must be correctly aligned with the color images to provide valid geometric conditioning [S1][S2, unofficial].
*   **Precision:** Standard volume rendering precision and boundary handling apply as defined in the parent article [S1].

## Subtopics

### BoostDream
The specific implementation of Multi-view SDS that introduced the 2x2 stitching technique [S1][S2, unofficial]. It sets itself apart by explicit multi-view conditioning via normal maps [S1]. Choose it when geometric consistency across asymmetric objects is critical [S1]. Link: [BoostDream](boostdream.md).

### GaussianDiffusion
A related method that incorporates structured noise from multiple viewpoints to alleviate the Janus problem using variational 3DGS [S1][S2, unofficial]. It sets itself apart by noise injection rather than image stitching [S1]. Choose it when mitigating floaters is prioritized [S1]. Link: [GaussianDiffusion](gaussian-diffusion.md).

## Operating characteristics
*   **Time Complexity:** Increases optimization time compared to single-view SDS due to rendering and processing $N$ views per step [S1].
*   **Memory Complexity:** Higher memory usage due to storing intermediate renders for $N$ views and the composite image [S1][S2, unofficial].
*   **Strengths:** Effectively reduces the Janus problem and improves geometric coherence while remaining plug-and-play with various 3D representations [S1][S2, unofficial].
*   **Limitations:** Increased computational cost relative to single-view baselines [S1].
*   **When to use:** When generating 3D assets with distinct front/back asymmetry where single-view SDS fails to maintain consistency [S1][S2, unofficial].

## Background
Multi-view SDS was proposed by BoostDream [S1][S2, unofficial]. It addresses limitations in standard SDS optimization where views are sampled one by one, leading to inconsistencies [S1][S2, unofficial]. The method leverages the efficiency of 3D Gaussian Splatting in some implementations, replacing MipNeRF as used in DreamGaussian, to render high-resolution images with high FPS and small memory [S1]. It is part of a broader trend of improving 3D generation by incorporating multi-view supervision [S1][S2, unofficial].
