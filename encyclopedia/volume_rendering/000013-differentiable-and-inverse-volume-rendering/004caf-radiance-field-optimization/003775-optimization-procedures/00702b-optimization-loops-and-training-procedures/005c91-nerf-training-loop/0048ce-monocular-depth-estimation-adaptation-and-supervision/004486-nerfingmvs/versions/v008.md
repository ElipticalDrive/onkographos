# NerfingMVS

Also called: Guided NeRF Optimization for MVS, Guided Optimization of Neural Radiance Fields for Indoor Multi-View Stereo, NeRF with Depth Priors

## Overview
NerfingMVS is a multi-view depth estimation method that integrates learning-based monocular depth priors into the optimization of Neural Radiance Fields (NeRF) to resolve the shape-radiance ambiguity inherent in indoor scenes [S2]. Unlike standard NeRF which relies solely on RGB supervision, NerfingMVS explicitly guides volume sampling and rendering using depth maps extracted from a scene-adapted monocular network, allowing for direct optimization over implicit volumes without requiring accurate pixel matching across views [S2]. It distinguishes itself from sibling methods by combining a test-time adaptation of a monocular depth estimator (fine-tuned on sparse SfM+MVS points) with a rendering pipeline that clamps ray bounds based on these priors [S1, S2].

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of multi-view RGB images $I$ [S2].
*   Camera poses (intrinsic and extrinsic) for the input images [S2][S4, unofficial].
*   A pre-trained monocular depth estimation (MDE) network $G_\phi$ (e.g., Mannequin Challenge) [S1][S3].
*   Sparse 3D point cloud or sparse depth maps derived from Structure-from-Motion (SfM) and Multi-View Stereo (MVS) using COLMAP [S1, S2].

**Outputs:**
*   Optimized NeRF model parameters $\Theta$ representing the scene's geometry and appearance [S2].
*   Dense depth maps for each input view [S2][S4, unofficial].
*   Re-rendered RGB images and depth maps [S4, unofficial].

### Data Structures
*   **NeRF Model ($F_\Theta$):** A multi-layer perceptron (MLP) taking 3D position $\mathbf{x}$ and view direction $\mathbf{d}$ as input, outputting volume density $\sigma$ and RGB color $\mathbf{c}$ [S3].
*   **Depth Prior Map ($D^*$):** A 2D tensor of shape $(H, W)$ containing relative depth estimates for a specific view, generated by the adapted MDE network [S2][S3].
*   **Depth Confidence Map ($M$):** A 2D tensor of shape $(H, W)$ indicating the reliability of the depth prior at each pixel [S3].
*   **Ray Bins:** The ray is divided into $N$ equal bins. The near and far bounds of these bins are clamped using the depth priors [S1].
*   **Tensors for Rendering:**
    *   `rays_o`: Ray origins, shape $[-1, 3]$ [S4, unofficial].
    *   `rays_d`: Ray directions, shape $[-1, 3]$ [S4, unofficial].
    *   `depth_priors`: Prior depth values for each ray, shape $[-1]$ [S4, unofficial].
    *   `depth_confidences`: Confidence values for each ray, shape $[-1]$ [S4, unofficial].

### Steps

1.  **Sparse Reconstruction:** Run COLMAP on the input images to obtain camera poses and a sparse 3D point cloud [S1, S2]. Project the fused 3D point clouds to each view to acquire sparse depth maps [S2].
2.  **Depth Prior Adaptation:** Fine-tune the pre-trained monocular depth network $G_\phi$ on the target scene using the sparse depth maps from COLMAP as ground truth [S2]. The network is optimized using a scale-invariant loss to handle the lack of absolute scale in the sparse reconstruction [S2]:
    $$ L(D^i_p, D^i_{Sparse}) = \frac{1}{n} \sum_{j=1}^n \left| \log D^i_p(j) - \log D^i_{Sparse}(j) + \alpha(D^i_p, D^i_{Sparse}) \right| $$
    where $D^i_p$ is the predicted depth, $D^i_{Sparse}$ is the sparse depth, and $\alpha$ is a correction term [S2].
3.  **Ray Preparation:** For each training ray, compute the origin $\mathbf{o}$ and direction $\mathbf{d}$ from the camera pose [S4, unofficial]. If NDC (Normalized Device Coordinates) is used, convert rays to NDC space [S4, unofficial].
4.  **Depth-Guided Sampling Bounds:** Retrieve the depth prior $D^*$ and confidence $M$ for the current view [S4, unofficial]. Use these to clamp the near and far bounds of the ray sampling intervals, effectively focusing computation on plausible depths and skipping empty space [S1].
5.  **Volume Rendering:** Sample points along the ray within the clamped bounds [S1]. Compute density $\sigma$ and color $\mathbf{c}$ for each sample [S3]. Render the RGB color and depth using standard volumetric rendering equations [S4, unofficial].
    *   Compute distances between consecutive samples: $d_i = z_{i+1} - z_i$ [S4, unofficial].
    *   Scale by ray direction norm: $d_i = d_i \cdot \|\mathbf{d}\|$ [S4, unofficial].
    *   Compute alpha: $\alpha_i = 1 - \exp(-\sigma_i \cdot d_i)$ [S4, unofficial].
    *   Compute weights: $w_i = \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j)$ [S4, unofficial].
    *   Rendered RGB: $\mathbf{C} = \sum w_i \mathbf{c}_i$ [S4, unofficial].
    *   Rendered Depth: $\mathbf{D} = \sum w_i z_i$ [S4, unofficial].
6.  **Loss Computation:** Compute the total loss, which includes the RGB reconstruction loss and a depth consistency loss between the rendered depth and the adapted monocular depth prior [S1, S2].
7.  **Optimization:** Update NeRF parameters $\Theta$ using gradient descent [S2].

### Pseudocode

```python
import torch
import torch.nn.functional as F

def nerfingmvs_render(rays_o, rays_d, depth_priors, depth_confidences, model, N_samples, near, far):
    """
    Renders rays using NerfingMVS logic.
    
    Args:
        rays_o: Tensor of shape [num_rays, 3], ray origins.
        rays_d: Tensor of shape [num_rays, 3], ray directions.
        depth_priors: Tensor of shape [num_rays], depth prior for each ray.
        depth_confidences: Tensor of shape [num_rays], confidence for each ray.
        model: The NeRF MLP model.
        N_samples: Number of samples per ray.
        near: Float, absolute near bound (default 0.05).
        far: Float, absolute far bound (default 0.15).
        
    Returns:
        rgb_map: Tensor of shape [num_rays, 3].
        depth_map: Tensor of shape [num_rays].
        acc_map: Tensor of shape [num_rays].
    """
    # 1. Define sampling intervals
    # Divide ray into N equal bins
    t_vals = torch.linspace(0., 1., steps=N_samples).to(rays_o.device)
    z_vals = near * (1. - t_vals) + far * t_vals
    
    # 2. Clamp bounds using depth priors
    # NerfingMVS uses depth priors to guide sampling by clamping ray bounds [S1].
    # Implementation details of exact clamping logic are not fully shown in sources,
    # but priors are passed to modulate sampling ranges [S4, unofficial].
    # We clamp z_vals to the provided near/far bounds as a baseline.
    z_vals = torch.clamp(z_vals, min=near, max=far)
    
    # 3. Sample points and query NeRF
    pts = rays_o.unsqueeze(1) + rays_d.unsqueeze(1) * z_vals.unsqueeze(-1)
    pts = pts.reshape(-1, 3)
    
    # Query NeRF for density and color
    raw_density, raw_color = model(pts)
    
    # 4. Compute weights
    dists = z_vals[..., 1:] - z_vals[..., :-1]
    dists = torch.cat([dists, torch.tensor([1e10]).to(rays_o.device)], dim=-1)
    dists = dists * torch.norm(rays_d.unsqueeze(1), dim=-1)
    
    alpha = 1. - torch.exp(-F.relu(raw_density) * dists)
    
    # Numerical stability: add 1e-10 to (1-alpha) in cumprod to prevent NaNs [S4, unofficial]
    transmittance = torch.cumprod(1. - alpha + 1e-10, dim=-1)
    transmittance = torch.cat([torch.ones_like(transmittance[..., :1]), transmittance[..., :-1]], dim=-1)
    
    weights = alpha * transmittance
    
    # 5. Render RGB and Depth
    rgb_map = torch.sum(weights.unsqueeze(-1) * raw_color, dim=-2)
    depth_map = torch.sum(weights * z_vals, dim=-1)
    acc_map = torch.sum(weights, dim=-1)
    
    # 6. Composite against white background
    rgb_map = rgb_map + (1. - acc_map.unsqueeze(-1))
    
    # 7. NDC transform for depth if applicable
    # depth_map = -1/rays_d_ori[:, 2]*(1 / (1 - depth_map) + rays_o_ori[:, 2]) [S4, unofficial]
    
    return rgb_map, depth_map, acc_map

def nerfingmvs_train_step(rays_o, rays_d, rgb_gt, depth_priors, depth_confidences, model, optimizer):
    """
    Single training step for NerfingMVS.
    """
    optimizer.zero_grad()
    
    # Render
    rgb_pred, depth_pred, acc = nerfingmvs_render(
        rays_o, rays_d, depth_priors, depth_confidences, model, N_samples=64, near=0.05, far=0.15
    )
    
    # Loss 1: RGB Loss (L1 or MSE)
    rgb_loss = F.mse_loss(rgb_pred, rgb_gt)
    
    # Loss 2: Depth Consistency Loss
    # Align rendered depth with depth prior
    # Use confidence to weight the loss
    depth_loss = torch.mean(depth_confidences * torch.abs(depth_pred - depth_priors))
    
    total_loss = rgb_loss + 0.5 * depth_loss
    
    total_loss.backward()
    optimizer.step()
    
    return total_loss.item(), rgb_loss.item(), depth_loss.item()
```

### Parameters
*   `depth_N_rand`: Batch size for depth sampling (default 4) [S4, unofficial].
*   `depth_N_iters`: Number of iterations for depth prior training (default 151) [S4, unofficial].
*   `depth_H`, `depth_W`: Height and width of the depth image (must be multiples of 16, e.g., 288x384) [S4, unofficial].
*   `depth_lrate`: Learning rate for depth network adaptation (default 4e-4) [S4, unofficial].
*   `near`: Absolute near bound for ray clipping (default 0.05) [S4, unofficial].
*   `far`: Absolute far bound for ray clipping (default 0.15) [S4, unofficial].
*   `topk`: Top-k for consistency error filtering (default 4) [S4, unofficial].

### Edge Cases and Pitfalls
*   **Numerical Stability in Cumprod:** When computing transmittance, add $10^{-10}$ to $(1-\alpha)$ to prevent NaNs when $\alpha$ is close to 1 [S4, unofficial].
*   **Division by Zero in Disparity:** If computing disparity maps, use $\max(10^{-10}, \dots)$ to avoid division by zero when depth or accumulated opacity is zero [S4, unofficial].
*   **Scale Ambiguity:** The monocular depth prior is relative [S2]. The scale-invariant loss during adaptation helps, but the final NeRF depth may still lack absolute scale unless constrained by the sparse COLMAP points or explicit scale normalization [S2].
*   **COLMAP Dependency:** The method relies heavily on the quality of COLMAP's sparse reconstruction [S4, unofficial]. Poor pose estimation or sparse points can lead to poor depth priors [S4, unofficial].

## Operating characteristics

*   **Time Complexity:** Training time is significantly higher than standard NeRF due to the additional depth prior adaptation step and the complexity of guided sampling [S3][S4, unofficial]. The source notes approximately 3.5 hours on an NVIDIA GeForce RTX 2080 GPU for a ScanNet scene, including COLMAP, depth training, and NeRF training [S4, unofficial].
*   **Memory Complexity:** Similar to standard NeRF, but requires storing depth priors and confidences for each ray/view [S4, unofficial]. Chunked rendering is used to avoid OOM errors [S4, unofficial].
*   **Strengths:**
    *   Improves geometry in textureless or repetitive indoor scenes where standard NeRF suffers from shape-radiance ambiguity [S2].
    *   Eliminates the need for explicit pixel matching across views during optimization [S2].
    *   Largely improves the quality of the final depth output [S2].
*   **Limitations:**
    *   Requires a good initial sparse reconstruction from COLMAP [S4, unofficial].
    *   Performance is dependent on the quality of the monocular depth estimator and its adaptation to the scene [S2].
    *   Lacks efficiency for real-time system application [S3].
*   **When to Use:** Indoor multi-view stereo tasks where high-quality geometry and depth are required, and sufficient multi-view overlap exists for COLMAP to work [S2].
*   **When Not to Use:** Outdoor scenes with large baselines, dynamic scenes, or scenes where COLMAP cannot produce a reliable sparse reconstruction [S4, unofficial].

## Background

NerfingMVS was introduced by Yi Wei, Shaohui Liu, Yongming Rao, Wang Zhao, Jiwen Lu, and Jie Zhou in September 2021 at ICCV [S2][S3]. The paper, titled "NerfingMVS: Guided Optimization of Neural Radiance Fields for Indoor Multi-View Stereo," addresses the limitations of NeRF in indoor environments, specifically the shape-radiance ambiguity [S2]. It builds upon the NeRF framework [S3] and integrates principles from multi-view stereo (MVS) and monocular depth estimation. The method was evaluated on ScanNet and Matterport3D datasets [S1]. It is based on the PyTorch implementation of NeRF [S4, unofficial].
