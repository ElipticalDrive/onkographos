# NerfingMVS

Also called: Guided NeRF Optimization for MVS, Guided Optimization of Neural Radiance Fields for Indoor Multi-View Stereo, NeRF with Depth Priors

## Overview
NerfingMVS is a multi-view depth estimation method that integrates learning-based monocular depth priors into the optimization of Neural Radiance Fields (NeRF) to resolve the shape-radiance ambiguity inherent in indoor scenes [S2]. Unlike standard NeRF which relies solely on RGB supervision, NerfingMVS explicitly guides volume sampling and rendering using depth maps extracted from a scene-adapted monocular network, allowing for direct optimization over implicit volumes without requiring accurate pixel matching across views [S2]. It distinguishes itself from sibling methods by combining a test-time adaptation of a monocular depth estimator (fine-tuned on sparse SfM+MVS points) with a rendering pipeline that clamps ray bounds and weights samples based on these priors [S1, S2].

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of multi-view RGB images $I$.
*   Camera poses (intrinsic and extrinsic) for the input images.
*   A pre-trained monocular depth estimation (MDE) network $G_\phi$ (e.g., Mannequin Challenge) [S1][S3, unofficial].
*   Sparse 3D point cloud or sparse depth maps derived from Structure-from-Motion (SfM) and Multi-View Stereo (MVS) using COLMAP [S1, S2].

**Outputs:**
*   Optimized NeRF model parameters $\Theta$ representing the scene's geometry and appearance.
*   Dense depth maps for each input view.
*   Re-rendered RGB images and depth maps.

### Data Structures
*   **NeRF Model ($F_\Theta$):** A multi-layer perceptron (MLP) taking 3D position $\mathbf{x}$ and view direction $\mathbf{d}$ as input, outputting volume density $\sigma$ and RGB color $\mathbf{c}$ [S3, unofficial].
*   **Depth Prior Map ($D^*$):** A 2D tensor of shape $(H, W)$ containing relative depth estimates for a specific view, generated by the adapted MDE network [S2][S3, unofficial].
*   **Depth Confidence Map ($M$):** A 2D tensor of shape $(H, W)$ indicating the reliability of the depth prior at each pixel [S3, unofficial].
*   **Ray Bins:** The ray is divided into $N$ equal bins. The near and far bounds of these bins are clamped using the depth priors [S1].
*   **Tensors for Rendering:**
    *   `rays_o`: Ray origins, shape $[-1, 3]$ [S3, unofficial].
    *   `rays_d`: Ray directions, shape $[-1, 3]$ [S3, unofficial].
    *   `depth_priors`: Prior depth values for each ray, shape $[-1]$ [S3, unofficial].
    *   `depth_confidences`: Confidence values for each ray, shape $[-1]$ [S3, unofficial].

### Steps

1.  **Sparse Reconstruction:** Run COLMAP on the input images to obtain camera poses and a sparse 3D point cloud [S1, S2]. Project the fused 3D point clouds to each view to acquire sparse depth maps [S2].
2.  **Depth Prior Adaptation:** Fine-tune the pre-trained monocular depth network $G_\phi$ on the target scene using the sparse depth maps from COLMAP as ground truth. The network is optimized using a scale-invariant loss to handle the lack of absolute scale in the sparse reconstruction [S2]:
    $$ L(D^i_p, D^i_{Sparse}) = \frac{1}{n} \sum_{j=1}^n \left| \log D^i_p(j) - \log D^i_{Sparse}(j) + \alpha(D^i_p, D^i_{Sparse}) \right| $$
    where $D^i_p$ is the predicted depth, $D^i_{Sparse}$ is the sparse depth, and $\alpha$ is a correction term [S2].
3.  **Ray Preparation:** For each training ray, compute the origin $\mathbf{o}$ and direction $\mathbf{d}$ from the camera pose. If NDC (Normalized Device Coordinates) is used, convert rays to NDC space [S3, unofficial].
4.  **Depth-Guided Sampling Bounds:** Retrieve the depth prior $D^*$ and confidence $M$ for the current view. Use these to clamp the near and far bounds of the ray sampling intervals. Specifically, the ray bounds are adjusted to focus sampling on the depth predicted by the prior, effectively skipping empty space or implausible depths [S1][S3, unofficial].
5.  **Volume Rendering:** Sample points along the ray within the clamped bounds. Compute density $\sigma$ and color $\mathbf{c}$ for each sample. Render the RGB color $\mathbf{C}$ and depth $\mathbf{D}$ using standard volumetric rendering equations, but weighted by the confidence of the depth prior if applicable [S1][S3, unofficial].
    *   Compute distances between consecutive samples: $d_i = z_{i+1} - z_i$.
    *   Scale by ray direction norm: $d_i = d_i \cdot \|\mathbf{d}\|$ [S3, unofficial].
    *   Compute alpha: $\alpha_i = 1 - \exp(-\sigma_i \cdot d_i)$ [S3, unofficial].
    *   Compute weights: $w_i = \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j)$ [S3, unofficial].
    *   Rendered RGB: $\mathbf{C} = \sum w_i \mathbf{c}_i$ [S3, unofficial].
    *   Rendered Depth: $\mathbf{D} = \sum w_i z_i$ [S3, unofficial].
6.  **Loss Computation:** Compute the total loss, which includes the RGB reconstruction loss and a depth consistency loss between the rendered depth and the adapted monocular depth prior [S1, S2].
7.  **Optimization:** Update NeRF parameters $\Theta$ using gradient descent [S2].

### Pseudocode

```python
import torch
import torch.nn.functional as F

def nerfingmvs_render(rays_o, rays_d, depth_priors, depth_confidences, model, N_samples, near, far):
    """
    Renders rays using NerfingMVS logic.
    
    Args:
        rays_o: Tensor of shape [num_rays, 3], ray origins.
        rays_d: Tensor of shape [num_rays, 3], ray directions.
        depth_priors: Tensor of shape [num_rays], depth prior for each ray.
        depth_confidences: Tensor of shape [num_rays], confidence for each ray.
        model: The NeRF MLP model.
        N_samples: Number of samples per ray.
        near: Float, absolute near bound (default 0.05).
        far: Float, absolute far bound (default 0.15).
        
    Returns:
        rgb_map: Tensor of shape [num_rays, 3].
        depth_map: Tensor of shape [num_rays].
        acc_map: Tensor of shape [num_rays].
    """
    # 1. Define sampling intervals
    # Divide ray into N equal bins
    t_vals = torch.linspace(0., 1., steps=N_samples).to(rays_o.device)
    z_vals = near * (1. - t_vals) + far * t_vals
    
    # 2. Clamp bounds using depth priors
    # NerfingMVS uses depth priors to guide sampling. 
    # The prior depth is used to adjust the sampling range or weight the samples.
    # Based on [S1], ray bounds are clamped using depth priors.
    # We assume the prior provides a central depth around which to sample.
    # A common implementation (from [S3, unofficial] context) involves 
    # perturbing the z_vals around the prior depth or limiting the range.
    # Here we implement a simple clamping/centering based on prior.
    
    # Ensure depth_priors are within [near, far] for clamping logic
    # If prior is outside, clamp to bounds
    depth_priors_clamped = torch.clamp(depth_priors, min=near, max=far)
    
    # Shift z_vals to be centered around the depth prior? 
    # Or simply use the prior to define the effective near/far?
    # The paper [S1] says "allowing sampling points only at appropriate depths".
    # Implementation [S3, unofficial] passes depth_priors to render_rays.
    # We will assume the sampling is stratified around the prior depth 
    # or the prior is used to filter/weight samples.
    # For this pseudocode, we will use the prior to define the sampling range 
    # if it's more informative than the fixed near/far, or simply perturb.
    
    # Let's use the prior to define the center of sampling, with a fixed spread
    # spread = (far - near) / 2
    spread = (far - near) / 2.0
    z_vals_centered = depth_priors_clamped.unsqueeze(-1) + (z_vals - 0.5) * spread
    
    # Clamp z_vals to [near, far]
    z_vals = torch.clamp(z_vals_centered, min=near, max=far)
    
    # 3. Sample points and query NeRF
    pts = rays_o.unsqueeze(1) + rays_d.unsqueeze(1) * z_vals.unsqueeze(-1)
    pts = pts.reshape(-1, 3)
    
    # Query NeRF for density and color
    # model returns raw density and color
    raw_density, raw_color = model(pts)
    
    # 4. Compute weights
    dists = z_vals[..., 1:] - z_vals[..., :-1]
    dists = torch.cat([dists, torch.tensor([1e10]).to(rays_o.device)], dim=-1)
    dists = dists * torch.norm(rays_d.unsqueeze(1), dim=-1)
    
    alpha = 1. - torch.exp(-F.relu(raw_density) * dists)
    
    # Numerical stability: add 1e-10 to (1-alpha) in cumprod
    transmittance = torch.cumprod(1. - alpha + 1e-10, dim=-1)
    transmittance = torch.cat([torch.ones_like(transmittance[..., :1]), transmittance[..., :-1]], dim=-1)
    
    weights = alpha * transmittance
    
    # 5. Render RGB and Depth
    rgb_map = torch.sum(weights.unsqueeze(-1) * raw_color, dim=-2)
    depth_map = torch.sum(weights * z_vals, dim=-1)
    acc_map = torch.sum(weights, dim=-1)
    
    # 6. Composite against white background
    rgb_map = rgb_map + (1. - acc_map.unsqueeze(-1))
    
    return rgb_map, depth_map, acc_map

def nerfingmvs_train_step(rays_o, rays_d, rgb_gt, depth_priors, depth_confidences, model, optimizer):
    """
    Single training step for NerfingMVS.
    """
    optimizer.zero_grad()
    
    # Render
    rgb_pred, depth_pred, acc = nerfingmvs_render(
        rays_o, rays_d, depth_priors, depth_confidences, model, N_samples=64, near=0.05, far=0.15
    )
    
    # Loss 1: RGB Loss (L1 or MSE)
    rgb_loss = F.mse_loss(rgb_pred, rgb_gt)
    
    # Loss 2: Depth Consistency Loss
    # Align rendered depth with depth prior
    # Use confidence to weight the loss
    # Note: depth_priors and depth_pred are in the same coordinate system if bounds are handled correctly
    depth_loss = torch.mean(depth_confidences * torch.abs(depth_pred - depth_priors))
    
    total_loss = rgb_loss + 0.5 * depth_loss # Weight for depth loss
    
    total_loss.backward()
    optimizer.step()
    
    return total_loss.item(), rgb_loss.item(), depth_loss.item()
```

### Parameters
*   `depth_N_rand`: Batch size for depth sampling (default 4) [S3, unofficial].
*   `depth_N_iters`: Number of iterations for depth prior training (default 151) [S3, unofficial].
*   `depth_H`, `depth_W`: Height and width of the depth image (must be multiples of 16, e.g., 288x384) [S3, unofficial].
*   `depth_lrate`: Learning rate for depth network adaptation (default 4e-4) [S3, unofficial].
*   `near`: Absolute near bound for ray clipping (default 0.05) [S3, unofficial].
*   `far`: Absolute far bound for ray clipping (default 0.15) [S3, unofficial].
*   `topk`: Top-k for consistency error filtering (default 4) [S3, unofficial].

### Edge Cases and Pitfalls
*   **Numerical Stability in Cumprod:** When computing transmittance, add $10^{-10}$ to $(1-\alpha)$ to prevent NaNs when $\alpha$ is close to 1 [S3, unofficial].
*   **Division by Zero in Disparity:** If computing disparity maps, use $\max(10^{-10}, \dots)$ to avoid division by zero when depth or accumulated opacity is zero [S3, unofficial].
*   **Scale Ambiguity:** The monocular depth prior is relative. The scale-invariant loss during adaptation helps, but the final NeRF depth may still lack absolute scale unless constrained by the sparse COLMAP points or explicit scale normalization [S2].
*   **COLMAP Dependency:** The method relies heavily on the quality of COLMAP's sparse reconstruction. Poor pose estimation or sparse points can lead to poor depth priors [S3, unofficial].

## Operating characteristics

*   **Time Complexity:** Training time is significantly higher than standard NeRF due to the additional depth prior adaptation step and the complexity of guided sampling. The source notes approximately 3.5 hours on an NVIDIA GeForce RTX 2080 GPU for a ScanNet scene, including COLMAP, depth training, and NeRF training [S3, unofficial].
*   **Memory Complexity:** Similar to standard NeRF, but requires storing depth priors and confidences for each ray/view. Chunked rendering is used to avoid OOM errors [S3, unofficial].
*   **Strengths:**
    *   Improves geometry in textureless or repetitive indoor scenes where standard NeRF suffers from shape-radiance ambiguity [S2].
    *   Eliminates the need for explicit pixel matching across views during optimization [S2].
    *   Produces more accurate dense depth maps compared to standard NeRF [S2].
*   **Limitations:**
    *   Requires a good initial sparse reconstruction from COLMAP [S3, unofficial].
    *   Performance is dependent on the quality of the monocular depth estimator and its adaptation to the scene [S2].
    *   Not suitable for scenes with significant dynamic content or where COLMAP fails to reconstruct poses [S2].
*   **When to Use:** Indoor multi-view stereo tasks where high-quality geometry and depth are required, and sufficient multi-view overlap exists for COLMAP to work.
*   **When Not to Use:** Outdoor scenes with large baselines, dynamic scenes, or scenes where COLMAP cannot produce a reliable sparse reconstruction.

## Background

NerfingMVS was introduced by Yi Wei, Shaohui Liu, Yongming Rao, Wang Zhao, Jiwen Lu, and Jie Zhou in September 2021 at ICCV [S2][S3, unofficial]. The paper, titled "NerfingMVS: Guided Optimization of Neural Radiance Fields for Indoor Multi-View Stereo," addresses the limitations of NeRF in indoor environments, specifically the shape-radiance ambiguity. It builds upon the NeRF framework [S3, unofficial] and integrates principles from multi-view stereo (MVS) and monocular depth estimation. The method was evaluated on ScanNet and Matterport3D datasets [S1]. It is based on the PyTorch implementation of NeRF [S3, unofficial].
