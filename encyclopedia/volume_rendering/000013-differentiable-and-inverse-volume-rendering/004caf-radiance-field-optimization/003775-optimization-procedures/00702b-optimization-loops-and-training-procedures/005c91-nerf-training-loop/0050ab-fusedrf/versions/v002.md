# FusedRF

Also called: Fusing Multiple Radiance Fields

## Overview
FusedRF is a method to fuse multiple teacher Radiance Fields (RFs) into a single, compact student RF representation using distillation, allowing for composited scene rendering with the memory and time complexity of a single RF [S1, unofficial]. Unlike naive composition which requires parallel tracing into multiple RFs (increasing memory and render time linearly with scene count), FusedRF fuses them into one RF, maintaining constant memory and render time [S1, unofficial]. Unlike retraining from scratch using rendered RGB views, FusedRF uses 3D distillation from existing RFs, reducing training time by 3x [S1, unofficial].

## How it works
**Inputs:**
- $N$ teacher radiance fields $T_1, \dots, T_N$ encoding density $\sigma_I$, color $c_I$, and potentially other attributes [S1, unofficial].
- A set of training rays $\mathcal{R}$ sampled from camera poses associated with the teacher fields [S1, unofficial].
- Identification of a background teacher $T_{bg}$ representing the dominant scene in the composition [S1, unofficial].

**Outputs:**
- A single student radiance field $S$ capable of rendering the composited scene [S1, unofficial].

**Data Structures:**
- The student $S$ and teachers $T_i$ are implemented as neural networks (e.g., MLPs) or structured grids, inheriting the architecture of the source RFs [S1, unofficial].
- The method assumes query functions $T_i(\mathbf{x}, \mathbf{d}) \rightarrow (\sigma, c)$ and $S(\mathbf{x}, \mathbf{d}) \rightarrow (\sigma, c)$, where $\mathbf{x}$ is the 3D position and $\mathbf{d}$ is the viewing direction [S1, unofficial].
- Training points $\mathcal{P}$: A set of 3D coordinates $\mathbf{x}$ sampled along rays, formed by the union of selected high-density points from the teachers [S1, unofficial].

**Parameters:**
- $\delta$: Step size for ray marching [S1, unofficial].
- Density thresholds: Points with lower density are pruned and points with higher density are utilized; exact numerical thresholds are not given in the sources [S1, unofficial].
- Loss weights: Standard L2 losses are applied without explicit weighting factors [S1, unofficial].

**Steps:**

1. **Initialization:** Initialize the student RF $S$ with the weights of the background teacher $T_{bg}$ (the dominant teacher in the composition) to speed up distillation [S1, unofficial].
2. **Ray Marching and Point Selection:** For each training ray $\mathbf{r} \in \mathcal{R}$, sample points along the ray for each teacher $T_i$ [S1, unofficial]. For every sampled point, calculate the activated volumetric density $\alpha_I$ using the formula $\alpha_I = 1 - e^{-\sigma_I \delta}$, where $\sigma_I$ is the density output by $T_i$ at the point and $\delta$ is the step size [S1, unofficial]. Prune points with lower density values and select points with higher density values from the teachers; specifically, for each ray segment, the point with the higher $\alpha$ value is chosen for contribution [S1, unofficial]. The union of these selected points forms the training set $\mathcal{P}$ for the student $S$ [S1, unofficial].
3. **Distillation (Supervised Loss):** For each point $\mathbf{x} \in \mathcal{P}$, query the density $\sigma$, alpha $\alpha$, and color $c$ for the student $S$ and the corresponding teacher $T_i$ at $\mathbf{x}$ [S1, unofficial]. Compute the supervised L2 loss between the student's outputs and the teacher's outputs for both color and density: $\mathcal{L}_{distill} = || c_S(\mathbf{x}) - c_{T}(\mathbf{x}) ||_2^2 + || \sigma_S(\mathbf{x}) - \sigma_{T}(\mathbf{x}) ||_2^2$ [S1, unofficial]. Update $S$ to minimize $\mathcal{L}_{distill}$ [S1, unofficial].
4. **Smoothing (Alpha-Composited Loss):** Render RGB values for rays by accumulating individual color values weighted by activated volumetric density using the Volumetric Rendering Equation: $C(\mathbf{r}) = \sum_{j=1}^{M} T_j c_j$, where $T_j = \left( \prod_{k=1}^{j-1} (1 - \alpha_k) \right) \alpha_j$ [S1, unofficial]. Apply an alpha-composited RGB pixel loss $\mathcal{L}_{render} = || C_S(\mathbf{r}) - C_{target}(\mathbf{r}) ||_2^2$ for a few iterations to smooth results around object boundaries [S1, unofficial].

**Pseudocode:**

```python
import math

def fused_rf_distillation(teachers, background_idx, rays, student, num_samples, delta, lr, num_smoothing_iters):
    # Step 1: Initialization
    student.weights = teachers[background_idx].weights

    # Step 2 & 3: Distillation Loop
    for ray in rays:
        candidate_points = []
        for t_idx, teacher in enumerate(teachers):
            points = sample_points_along_ray(ray, num_samples)
            for p in points:
                sigma, color = teacher.query(p.position, ray.direction)
                alpha = 1.0 - math.exp(-sigma * delta)
                candidate_points.append({
                    'pos': p.position, 
                    't_idx': t_idx, 
                    'sigma': sigma, 
                    'color': color, 
                    'alpha': alpha
                })

        # Select points: union of high-density points. 
        # For each ray segment, pick the point with the highest alpha.
        training_set = []
        for i in range(num_samples):
            segment = [pt for pt in candidate_points if pt['pos'].index_in_ray == i]
            if segment:
                training_set.append(max(segment, key=lambda x: x['alpha']))

        # Compute supervised L2 loss on density and color
        distill_loss = 0.0
        for pt in training_set:
            s_sigma, s_color = student.query(pt['pos'], ray.direction)
            t_sigma = pt['sigma']
            t_color = pt['color']
            distill_loss += (s_sigma - t_sigma)**2 + sum((sc - tc)**2 for sc, tc in zip(s_color, t_color))

        # Update student weights via standard gradient descent
        student.weights -= lr * student.compute_gradients(distill_loss)

    # Step 4: Smoothing Phase
    for _ in range(num_smoothing_iters):
        render_loss = 0.0
        for ray in rays:
            s_rgb = volumetric_render_ray(student, ray, num_samples, delta)
            t_rgb = naive_composite_ray(teachers, ray, num_samples, delta)
            render_loss += sum((sc - tc)**2 for sc, tc in zip(s_rgb, t_rgb))
        student.weights -= lr * student.compute_gradients(render_loss)

    return student

def sample_points_along_ray(ray, num_samples):
    return [{'position': ray.origin + ray.direction * (i * ray.step_size), 'index_in_ray': i} for i in range(num_samples)]

def volumetric_render_ray(rf, ray, num_samples, delta):
    accumulated_color = [0.0, 0.0, 0.0]
    transmittance = 1.0
    for i in range(num_samples):
        p = ray.origin + ray.direction * (i * ray.step_size)
        sigma, color = rf.query(p, ray.direction)
        alpha = 1.0 - math.exp(-sigma * delta)
        weight = transmittance * alpha
        accumulated_color = [c + weight * col for c, col in zip(accumulated_color, color)]
        transmittance *= (1.0 - alpha)
    return accumulated_color

def naive_composite_ray(teachers, ray, num_samples, delta):
    accumulated_color = [0.0, 0.0, 0.0]
    transmittance = 1.0
    for i in range(num_samples):
        p = ray.origin + ray.direction * (i * ray.step_size)
        best_alpha = -1.0
        best_sigma, best_color = 0.0, [0.0, 0.0, 0.0]
        for teacher in teachers:
            sigma, color = teacher.query(p, ray.direction)
            alpha = 1.0 - math.exp(-sigma * delta)
            if alpha > best_alpha:
                best_alpha = alpha
                best_sigma, best_color = sigma, color
        weight = transmittance * best_alpha
        accumulated_color = [c + weight * col for c, col in zip(accumulated_color, best_color)]
        transmittance *= (1.0 - best_alpha)
    return accumulated_color
```

## Operating characteristics
- **Memory Complexity:** Constant with respect to the number of composed scenes [S1, unofficial]. FusedRF maintains the memory footprint of a single RF [S1, unofficial]. On an RTX 3060 Ti (8GB), FusedRF maintains 25MB memory for 8 composed scenes, whereas DVGO goes Out-Of-Memory (OOM) and TensoRF requires 200MB [S1, unofficial].
- **Time Complexity:** Render time is constant with respect to the number of composed scenes [S1, unofficial]. FusedRF takes ~2.04s for 8 scenes, while naive composition scales linearly with the number of components [S1, unofficial]. Training time is reduced by 3x compared to retraining from scratch [S1, unofficial].
- **Performance:**
  - RTX 3060 Ti (8GB):
    - 1 Scene: 25MB / 2.01s
    - 2 Scenes: 25MB / 2.05s
    - 4 Scenes: 25MB / 2.04s
    - 8 Scenes: 25MB / 2.04s
  - Comparison (8 Scenes):
    - DVGO: OOM
    - TensoRF: 200MB / 17.2s
    - FusedRF: 25MB / 2.04s [S1, unofficial]
- **Quality:**
  - PSNR (Figure 1): Ours (w/o RGB) 36.71, Ours (Full) 37.20 [S1, unofficial].
  - PSNR (Figure 3b): Ours (w/o RGB) 35.18, Ours (Full) 39.89 [S1, unofficial].
  - PSNR (Figure 3d): Ours (w/o RGB) 40.32, Ours (Full) 38.78 [S1, unofficial].
- **Strengths:** Low memory footprint, fast rendering, fast convergence (3x faster than retraining), supports addition and deletion of scenes in the fused representation [S1, unofficial].
- **Limitations:** Requires existing trained teacher RFs; assumes rigid transformation without applying additional rigid transformations during composition [S1, unofficial].

## Background
FusedRF was proposed to address the high memory and rendering time requirements of composing multiple Radiance Fields for XR and AR applications [S1, unofficial]. Prior works generated new views by tracing each scene in parallel, which did not scale well [S1, unofficial]. FusedRF distills information from multiple teacher RFs into a single student RF, facilitating further manipulations like addition and deletion [S1, unofficial].
