# NeRF Training Loop

Also called: NeRF Optimization Loop, NeRF Training Procedure, Neural Radiance Fields Training, Training Ray Sampling Strategy for Correspondence Disparity, Ray Sampling Strategy for Correspondence Disparity

## Overview
The NeRF Training Loop is the iterative optimization procedure that minimizes the photometric reconstruction error between rendered images and ground-truth training views by updating the parameters of a continuous radiance field representation [S5, S10, S15, unofficial]. It solves the inverse problem of learning scene geometry and appearance from 2D images by treating the volume rendering equation as a differentiable operator [S5, S10, unofficial]. Unlike [NeRF Evaluation and Metric Calculation](3079-nerf-evaluation-and-metric-calculation.md), which uses deterministic rendering for reproducible metrics, this method employs stochastic sampling with perturbation to facilitate gradient-based optimization [S2, S5, S10, unofficial]. It differs from [Volume Rendering Integration and Forward Pass](15462-volume-rendering-integration-and-forward-pass.md) by encompassing the entire training-specific pipeline—including ray generation, adaptive pruning via occupancy grids, and network querying—rather than focusing solely on the mathematical compositing mechanics [S1][S2, S3, S5, S10, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ training images with known camera poses (extrinsics $C$ and intrinsics $K$), and a neural network model $F_\Theta$ (typically an MLP) parameterized by $\Theta$.
*   **Outputs:** Updated network weights $\Theta$ that minimize the loss between rendered and ground-truth colors.

**Data Structures:**
*   **Rays:** A batch of rays is represented as a tensor of shape $[B, 3, 3]$ or $[B, 6]$, where $B$ is the batch size (number of rays). The first 3 components are the ray origin $(o_x, o_y, o_z)$, the next 3 are the ray direction $(d_x, d_y, d_z)$ [S5, S15, unofficial]. In some implementations, ground truth RGB values are stacked as a third channel, resulting in shape $[B, 3, 3]$ where axis 1 is `[origin, direction, target_rgb]` [S5, S15, unofficial].
*   **Pre-computed Rays:** To accelerate data loading, rays and targets are often pre-computed into a flat array `rays_rgb` of shape $[(N-1) \times H \times W, 3, 3]$ (or similar flattened pixel count) [S5, S15, unofficial]. This array is shuffled at the start of each epoch to ensure random sampling order [S11, unofficial].
*   **Checkpoint:** A dictionary containing the model state dict, optimizer state dict, and current step/epoch [S11, unofficial].

**Numbered Steps:**

1.  **Initialization:**
    *   Load training and validation datasets [S11, unofficial].
    *   Initialize the neural network model $F_\Theta$ [S10, unofficial]. For HashNeRF, initialize alpha linear weights of grown sub-networks to match the parent to avoid instability [S1]. For JaxNGP, initialize the NeRF and background models with zeros for position/direction dimensions [S16, unofficial].
    *   Initialize the optimizer (typically Adam) with a learning rate $lr$ [S5, S10, S11, unofficial].
    *   Initialize a learning rate scheduler (e.g., ExponentialDecay or CosineAnnealingLR) [S5, S11, unofficial].
    *   If using a coarse-to-fine strategy, initialize both coarse and fine MLPs [S11, unofficial].

2.  **Iteration Loop:** For iteration $i$ from 1 to $N_{iters}$:
    *   **Ray Sampling:**
        *   Select a batch of $N_{rand}$ rays from the pre-computed `rays_rgb` array or generate them on-the-fly from random pixel coordinates [S5, S15, unofficial].
        *   If using batching, slice `rays_rgb[i_batch : i_batch + N_{rand}]` [S5, S15, unofficial]. Increment `i_batch`. If `i_batch` exceeds the array length, shuffle the array and reset `i_batch` to 0 [S5, S15, unofficial].
        *   If not using pre-computed batching, randomly select an image index, generate rays for that image, and optionally apply a central crop (precrop) for the first $P_{precrop}$ iterations [S15, unofficial].
        *   Extract ray origins, directions, and target RGB colors into `batch_rays` and `target_s` [S7, S15, unofficial].
    *   **Forward Pass (Rendering):**
        *   For each ray in the batch, sample $N$ points along the ray segment between near and far bounds [S5, unofficial].
        *   Perturb the sampling positions if `perturb > 0` to break symmetry and aid optimization [S5, unofficial].
        *   Query the neural network $F_\Theta$ at each sample point to obtain density $\sigma$ and color $\mathbf{c}$ [S5, unofficial].
        *   Compute the rendered color $\hat{C}(\mathbf{r})$ using the volume rendering equation (see Parent article) [S5, S19, unofficial].
        *   If using coarse-to-fine training, render with the coarse network, sample additional points based on weights, and render with the fine network [S5, unofficial].
    *   **Loss Computation:**
        *   Compute the Mean Squared Error (MSE) between the predicted RGB $\hat{C}(\mathbf{r})$ and the target RGB $\mathbf{C}(\mathbf{r})$ [S5, S15, unofficial]:
            $$ \mathcal{L}_{rgb} = \frac{1}{B} \sum_{j=1}^{B} (\hat{C}_j(\mathbf{r}_j) - \mathbf{C}_j(\mathbf{r}_j))^2 $$
        *   If coarse outputs are available, add the coarse loss: $\mathcal{L}_{coarse} = \text{MSE}(\hat{C}_{coarse}, \mathbf{C})$ [S11, S19, unofficial].
        *   Total Loss $\mathcal{L} = \mathcal{L}_{rgb} + \lambda_{coarse} \mathcal{L}_{coarse} + \mathcal{L}_{reg}$, where $\mathcal{L}_{reg}$ includes regularization terms like sparsity or total variation [S7, S19, unofficial].
    *   **Backpropagation and Update:**
        *   Zero the gradients of the optimizer [S19, unofficial].
        *   Compute gradients via backpropagation: $\mathcal{L}.backward()$ [S19, unofficial].
        *   Step the optimizer: `optimizer.step()` [S19, unofficial].
        *   Update the learning rate according to the scheduler [S19, unofficial].
    *   **Logging and Checkpointing:**
        *   Log loss and PSNR every $I_{print}$ steps [S2, S11, unofficial].
        *   Render validation images every $I_{img}$ steps [S2, S11, unofficial].
        *   Save checkpoints every $I_{weights}$ steps [S2, S11, unofficial].

**Parameters:**
*   $N_{rand}$ (Batch Size): Number of rays sampled per iteration. Typical values: 1024 or 2048 [S5, S11, unofficial].
*   $lr$ (Learning Rate): Adam optimizer learning rate. Typical value: $5 \times 10^{-4}$ [S11, unofficial].
*   $N_{iters}$ (Iterations): Total number of gradient steps. Default: 100,000 [S11, unofficial].
*   $N_{samples}$: Number of samples per ray. Default: 128 [S18, unofficial].
*   $decay\_steps$: Steps after which learning rate decays. Calculated as $args.lrate\_decay \times 1000$ [S5, S19, unofficial].
*   $decay\_rate$: Factor by which LR is multiplied per decay step. Default: 0.1 [S6, S19, unofficial].
*   $chunk$: Maximum number of rays processed per forward pass to limit VRAM [S5, unofficial].

**Edge Cases and Pitfalls:**
*   **VRAM Overflow:** Rendering large batches can exceed GPU memory. Mitigated by splitting rays into chunks via `chunk=args.chunk` [S5, unofficial].
*   **Gradient Graph Freeing:** Higher-order derivatives (e.g., for logging gradients) must be computed *before* `loss.backward()` to avoid freeing the autograd graph [S3, unofficial].
*   **Empty Checkpoints:** If a checkpoint is loaded but the step is 0, it is considered empty and should trigger an error [S16, unofficial].
*   **Resuming Training:** When resuming, the scheduler's last epoch must be set to `start_epoch - 1` to ensure correct scheduling [S9, unofficial].
*   **Instability in Growth:** Directly growing a randomly initialized network can cause density to drop to 0. Initialize grown sub-networks' weights to match the parent [S1].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

def train_nerf_loop(model, optimizer, scheduler, dataloader, num_iters, n_rand, chunk_size=8192):
    """
    Standard NeRF training loop.
    
    Args:
        model: Neural Radiance Field model (MLP).
        optimizer: Optimizer (e.g., Adam).
        scheduler: Learning rate scheduler.
        dataloader: Iterator yielding batches of (rays_o, rays_d, target_rgb).
        num_iters: Total number of training iterations.
        n_rand: Number of rays per batch.
        chunk_size: Max rays per forward pass chunk.
    """
    model.train()
    
    for iteration in range(1, num_iters + 1):
        # 1. Ray Sampling
        # In a real implementation, rays are sampled from pre-computed arrays
        # or generated on-the-fly. Here we assume dataloader yields a batch.
        rays_o, rays_d, target_rgb = next(dataloader)
        
        # 2. Forward Pass (Chunked to save memory)
        all_preds = []
        for i in range(0, rays_o.shape[0], chunk_size):
            chunk_o = rays_o[i:i+chunk_size]
            chunk_d = rays_d[i:i+chunk_size]
            
            # Sample points along rays (simplified)
            # t_vals = torch.linspace(0., 1., steps=n_samples)
            # z_vals = near * (1.-t_vals) + far * (t_vals)
            # pts = chunk_o[..., None, :] + chunk_d[..., None, :] * z_vals[..., :, None]
            
            # Query model
            # raw = model(pts, chunk_d) # raw: [B, N, 4] (sigma, rgb)
            
            # Volume Rendering (simplified)
            # weights = alpha * cumprod(1-alpha)
            # rgb_pred = sum(weights * rgb)
            
            # Placeholder for actual rendering logic
            rgb_pred = model(chunk_o, chunk_d) # Returns [B, 3]
            all_preds.append(rgb_pred)
            
        rgb_pred = torch.cat(all_preds, dim=0)
        
        # 3. Loss Computation
        loss = F.mse_loss(rgb_pred, target_rgb)
        
        # 4. Backpropagation
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 5. Scheduler Update
        scheduler.step()
        
        # 6. Logging
        if iteration % 100 == 0:
            psnr = -10. * torch.log10(loss)
            print(f"Iter {iteration}: Loss {loss.item():.6f}, PSNR {psnr.item():.2f}")
            
        # 7. Checkpointing (omitted for brevity)
```

### Supersampling Baseline
A baseline method for evaluating NeRF on multiscale data by training on full-resolution images and using brute-force supersampling during evaluation, or training on multiscale data with supersampling during both training and evaluation [S23]. For every pixel, multiple jittered rays are cast uniformly at random through the spatial footprint, and the mean of rendered values is used as the predicted color [S23]. This relies on 'oracle' scale information not available for most datasets and performs worse than mip-NeRF while being significantly more expensive [S23].

### Two-stage training for proposers
A training schedule split into two equal-duration phases to stabilize learning of a trainable proposer network in NeRF-ID [S24, unofficial]. Phase 1 trains the proposer to mimic a heuristic proposer by minimizing L2 matching loss between proposal sets. Phase 2 trains all components end-to-end, resetting the optimizer and performing a linear warmup for 1,000 steps to reduce shock from switching regimes [S24, unofficial]. This two-stage approach is consistently effective where training from scratch often fails [S24, unofficial].

### JaxNeRF
A re-implementation of the original NeRF in JAX, used as a benchmark comparison for early works seeking to improve on training and rendering speed [S25]. It is slightly faster and more suited for distributed computing than the original TensorFlow implementation [S25].

### Gradient Detachment in Training
A training strategy where the object field component is detached from the backbone to prevent gradient backpropagation to the rendering part, ensuring independent optimization [S26, unofficial]. With detachment, gradients do not backpropagate to the NeRF backbone, achieving better scene rendering and decomposition quality. Without detachment, gradients cause mutual influence and a significant drop in rendering quality [S26, unofficial]. The optimal hyper-parameter for empty 3D point losses ($\Delta d$) is 0.05 meters [S26, unofficial].

### Ray Generator Network (RGN)
Used in MEIL-NeRF for incremental learning, the RGN learns to map past principal rays and current ground-truth principal rays to generate new rays [S27]. It consists of 3 hidden layers with 16, 64, and 32 units [S27]. During inference, it generates approximate principal rays around which non-principal rays are sampled. Unlike methods reproducing exact past rays, RGN creates approximate rays directed to the scene of interest, allowing accumulated pose errors to reduce learning burden at a small accuracy cost [S27].

### DFF
A method adopting pre-trained feature extraction networks (LSeg, DINO) as teacher networks for knowledge distillation, resulting in a scene-specific 3D feature field that enables extraction and deletion of target objects based on image patches or text [S28].

### ISRF
A method that learns additional feature fields to realize self-supervised 3D segmentation [S28].

### NeRF Volumetric Rendering
Produces final pixel color and depth via volumetric rendering: $\hat{C}(\mathbf{r}) = \sum_{i=1}^{N_p} T_i \alpha_i \mathbf{c}_i$ and $D(\mathbf{r}) = \sum_{i=1}^{N_p} T_i \alpha_i t_i$, where $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_t)$ and $\alpha_i = 1 - \exp(-\sigma_i \delta_t)$ [S29].

## Operating characteristics
*   **Time Complexity:** $O(N_{iters} \cdot N_{rand} \cdot N_{samples} \cdot C)$, where $C$ is the cost of the neural network forward pass. Training typically requires 100,000 iterations [S11, unofficial].
*   **Memory Complexity:** $O(N_{rand} \cdot N_{samples} \cdot D)$ for the forward pass, where $D$ is the model size. VRAM usage is managed by chunking rays [S5, unofficial].
*   **Measured Performance:** On LLFF with 3 views, using 50 target rays per iteration yields PSNR 20.33, SSIM 0.661, LPIPS 0.276. Increasing to 200 rays degrades performance [S21]. Training on 199 images (down-sampled 4x) with batch size 1024 results in ~7,800 iterations per epoch [S18, unofficial].
*   **Strengths:** Stochastic sampling enables efficient optimization on large datasets by avoiding full-image rendering per step [S5, unofficial].
*   **Limitations:** High memory usage for large batches; requires careful tuning of learning rates and sampling strategies [S16, unofficial].
*   **When to Use:** Standard NeRF optimization for multi-view synthesis.
*   **When Not to Use:** When real-time rendering is required (use acceleration methods) or when sparse views require specific priors (use sparse view methods).

## Background
The NeRF Training Loop was introduced in the original NeRF paper by Mildenhall et al. (2020) [S5, S10, unofficial]. It established the standard procedure of optimizing a coordinate MLP via stochastic gradient descent on sampled rays. Subsequent works have adapted this loop for various accelerations (HashNeRF [S7, unofficial], JaxNGP [S16, unofficial]), different representations (NeRV [S10, unofficial], SIREN [S3, unofficial]), and specialized tasks (editing , incremental learning [S27]).
