# NeRF Training Loop

Also called: NeRF Optimization Loop, NeRF Training Procedure, Neural Radiance Fields Training, Training Ray Sampling Strategy for Correspondence Disparity, Ray Sampling Strategy for Correspondence Disparity

## Overview
The NeRF Training Loop is the iterative optimization procedure that learns a continuous 5D radiance field $F_\Theta(\mathbf{x}, \mathbf{d}) = (\sigma, \mathbf{c})$ by minimizing the difference between rendered and observed pixel colors [S5, S10, S15, unofficial]. It solves the inverse rendering problem by repeatedly sampling random rays from training images, synthesizing colors via differentiable volume integration, and updating network weights via gradient descent [S5, S6, unofficial]. Unlike [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md), which defines the forward pass mechanics, the training loop orchestrates the data loading, sampling strategy, loss computation, and optimizer state management required for convergence [S8][S10, unofficial]. It differs from [NeRF Evaluation and Metric Calculation](3079-nerf-evaluation-and-metric-calculation.md) by employing stochastic sampling and perturbation to facilitate gradient-based optimization rather than deterministic rendering for metrics [S2, S5, S10, unofficial].

## How it works
**Inputs:** A set of $N$ training images with known camera poses (extrinsics $C2W$ and intrinsics $K$), and a neural network model $\Theta$ (typically an MLP) initialized with random weights [S5, S10, S15, unofficial].
**Outputs:** Optimized network weights $\Theta^*$ that reconstruct the scene geometry and appearance [S5, S10, unofficial].

**Data Structures:**
*   **Rays Array (`rays_rgb`):** A pre-computed array of shape $[(N-1) \times H \times W, 3, 3]$ storing all possible training rays [S5, S15, unofficial].
    *   Axis 0: Flattened pixel index.
    *   Axis 1: Channel type (0: Ray Origin $\mathbf{o}$, 1: Ray Direction $\mathbf{d}$, 2: Target RGB $\mathbf{c}_{gt}$).
    *   Axis 2: XYZ/RGB components.
    *   Type: `float32` [S5, S15, unofficial].
*   **Checkpoint:** A dictionary containing `'model'` (state dict), `'optimizer'` (state dict), and `'epoch'` or `'step'` (int) [S10, S11, unofficial].

**Parameters:**
*   $N_{rand}$: Number of rays sampled per iteration (batch size). Typical values: 1024 or 2048 [S5, S15, unofficial].
*   $N_{iters}$: Total number of optimization steps. Default: 100,000 [S11, unofficial].
*   $lr$: Learning rate for Adam optimizer. Default: $5 \times 10^{-4}$ [S11, unofficial].
*   $decay\_steps$: Steps after which learning rate decays. Calculated as $args.lrate\_decay \times 1000$ [S5, S19, unofficial].
*   $decay\_rate$: Factor by which learning rate is multiplied per decay step. Default: 0.1 [S5, S19, unofficial].
*   $chunk$: Maximum number of rays processed per forward pass to limit VRAM. Passed to render function [S5, S15, unofficial].
*   $perturb$: Jitter amount for sampling. 0.0 for no jitter, 1.0 for full jitter [S2, S5, unofficial].

**Numbered Steps:**

1.  **Initialization:**
    *   Load training and validation datasets [S10, S11, unofficial].
    *   Precompute the `rays_rgb` array by generating rays for all pixels in all training images [S5, S11, unofficial].
    *   Initialize the NeRF model $\Theta$ (coarse and fine networks if using coarse-to-fine) [S11, unofficial].
    *   Initialize the optimizer (Adam) with learning rate $lr$ [S5, S10, S11, unofficial].
    *   Initialize the learning rate scheduler (Exponential Decay or Cosine Annealing) [S5, S11, unofficial].
    *   If resuming, load checkpoint and set scheduler last epoch to `start_epoch - 1` [S9, unofficial].

2.  **Iteration Loop (for $i = 1$ to $N_{iters}$):**
    *   **Ray Sampling:**
        *   If batching is enabled: Slice `rays_rgb` from index $i_{batch}$ to $i_{batch} + N_{rand}$ [S5, S15, unofficial].
        *   Transpose the batch to shape $[3, N_{rand}, 3]$ (Channels: Origin, Direction, Target) [S15, unofficial].
        *   Increment $i_{batch}$. If $i_{batch} + N_{rand} > \text{total rays}$, shuffle `rays_rgb` and reset $i_{batch} = 0$ [S5, S11, unofficial].
        *   If not batching: Randomly select a training image, generate rays, optionally apply precrop, and sample $N_{rand}$ unique pixel coordinates [S15, unofficial].
    *   **Forward Pass (Rendering):**
        *   Call the rendering function `render_rays` with the batch of rays [S11, S15, unofficial].
        *   Inside `render_rays`:
            *   Sample points along rays using near/far bounds [S5, S15, unofficial].
            *   Apply perturbation if $perturb > 0$ (stratified sampling within intervals) [S5, unofficial].
            *   Query the neural network $\Theta$ at sample points to get raw density $\sigma$ and color $\mathbf{c}$ [S5, unofficial].
            *   Compute transmittance $T_i$ and weights $w_i$ using the emission-absorption model [S5, unofficial].
            *   Composite the final color $\hat{C}(\mathbf{r})$ [S5, unofficial].
            *   Return predicted RGB, depth, accumulation, and extras (e.g., coarse RGB if coarse-to-fine) [S6, S11, unofficial].
    *   **Loss Computation:**
        *   Compute Mean Squared Error (MSE) between predicted RGB $\hat{C}$ and target RGB $\mathbf{c}_{gt}$ [S5, S11, S15, unofficial]:
            $$ \mathcal{L}_{rgb} = \frac{1}{N_{rand}} \sum_{j=1}^{N_{rand}} (\hat{C}_j - \mathbf{c}_{gt,j})^2 $$
        *   If coarse-to-fine training is used, add the coarse network loss $\mathcal{L}_{coarse}$ to the total loss [S11, S19, unofficial]:
            $$ \mathcal{L}_{total} = \mathcal{L}_{rgb} + \mathcal{L}_{coarse} $$
        *   (Optional) Add regularization terms (e.g., Eikonal, TV, Sparsity) if defined in configuration [S7, unofficial][S8].
    *   **Backpropagation and Update:**
        *   Zero gradients: `optimizer.zero_grad()` [S19, unofficial].
        *   Compute gradients: `loss.backward()` [S19, unofficial].
        *   Update weights: `optimizer.step()` [S19, unofficial].
        *   Update learning rate scheduler [S11, S19, unofficial].
    *   **Logging and Checkpointing:**
        *   Log loss and PSNR every `log_every` steps [S11, unofficial].
        *   Render validation images every `render_every` steps [S11, unofficial].
        *   Save checkpoint every `save_every` steps [S11, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.optim as optim
import numpy as np

def train_nerf_loop(model, rays_rgb, optimizer, scheduler, n_iters, n_rand, chunk_size):
    """
    Standard NeRF Training Loop.
    
    Args:
        model: Neural Radiance Field model (MLP).
        rays_rgb: Pre-computed array of shape [Total_Rays, 3, 3] (Origin, Dir, Target).
        optimizer: Adam optimizer.
        scheduler: Learning rate scheduler.
        n_iters: Total number of training iterations.
        n_rand: Number of rays to sample per iteration.
        chunk_size: Max rays per forward pass chunk.
    """
    total_rays = rays_rgb.shape[0]
    i_batch = 0
    
    for i in range(n_iters):
        # 1. Ray Sampling
        # Slice batch
        batch_data = rays_rgb[i_batch : i_batch + n_rand]
        
        # Transpose to [3, Batch, 3] -> [Origin, Dir, Target]
        batch = batch_data.transpose(0, 1) 
        
        # Extract origins, directions, and targets
        rays_o = batch[0] # [Batch, 3]
        rays_d = batch[1] # [Batch, 3]
        target_s = batch[2] # [Batch, 3]
        
        # Increment batch index
        i_batch += n_rand
        
        # Shuffle and reset if exhausted
        if i_batch + n_rand > total_rays:
            # Shuffle rays_rgb in place or copy
            np.random.shuffle(rays_rgb)
            i_batch = 0
            
        # 2. Forward Pass (Rendering)
        # Stack rays for model input
        batch_rays = torch.stack([rays_o, rays_d], dim=0).to(device) # [2, Batch, 3]
        target_s = target_s.to(device) # [Batch, 3]
        
        # Render rays (handles chunking internally or externally)
        # Assuming model.render_rays takes rays_o, rays_d and returns rgb, extras
        with torch.no_grad(): # If using coarse-to-fine, coarse pass might be separate
             pass 
            
        # Forward pass through the model
        # Note: In practice, this calls the volume rendering integration
        rgb, extras = model.render_rays(rays_o, rays_d, chunk=chunk_size)
        
        # 3. Loss Computation
        # MSE Loss
        img_loss = torch.mean((rgb - target_s) ** 2)
        loss = img_loss
        
        # Add coarse loss if available (Coarse-to-Fine)
        if 'rgb0' in extras:
            img_loss0 = torch.mean((extras['rgb0'] - target_s) ** 2)
            loss = loss + img_loss0
            
        # 4. Backpropagation and Update
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 5. Scheduler Update
        scheduler.step()
        
        # 6. Logging (Example)
        if i % 100 == 0:
            psnr = -10.0 * torch.log10(img_loss)
            print(f"Iter {i}: Loss {loss.item():.6f}, PSNR {psnr.item():.2f}")

```

## Subtopics

### [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md)
The differentiable forward pass that synthesizes a 2D image from a continuous 5D radiance field by numerically approximating the volume rendering integral along camera rays. It solves the problem of mapping implicit scene representations to pixel colors by integrating predicted volume density and view-dependent color, using probabilistic density functions to determine sample contributions rather than deterministic surface intersections. Unlike [NeRF Evaluation and Metric Calculation](3079-nerf-evaluation-and-metric-calculation.md), which uses deterministic rendering for reproducible metrics, this method employs stochastic sampling with perturbation to facilitate gradient-based optimization. It differs from [Volume Rendering Integration and Forward Pass](15462-volume-rendering-integration-and-forward-pass.md) by encompassing the entire training-specific pipeline—including ray generation, adaptive pruning via occupancy grids, and network querying—rather than focusing solely on the mathematical compositing mechanics.

### [Training Configuration](2332-training-configuration.md)
Training Configuration defines the hyperparameters, optimization schedules, and architectural constraints required to stabilize convergence and maximize reconstruction quality in neural radiance field (NeRF) optimization. It solves the problem of disparate convergence speeds among geometric, appearance, and latent parameters by specifying learning rates, batch sizes, sampling strategies, and regularization strengths. Unlike [Scene Representation and Architecture](11368-scene-representation-and-architecture.md), which defines the model structure, or [Regularization and Loss Functions](8586-regularization-and-loss-functions.md), which defines the objective, Training Configuration controls the *process* of optimization, including learning rate scheduling, mixed precision, and view sampling strategies.

### [Neural Volume Scene Setup](4168-neural-volume-scene-setup.md)
Constructs a Mitsuba scene containing a volumetric cube and a custom neural radiance field integrator, initializing the density grid and spherical harmonics coefficients. It differs from generic training setups by directly binding the neural network parameters to the scene graph's heterogeneous volume and integrator components.

### [Regularization and Loss Functions](8586-regularization-and-loss-functions.md)
Regularization and Loss Functions define the objective landscape for optimizing differentiable volume rendering fields, ensuring that the learned density $\sigma$ and color $\mathbf{c}$ parameters reconstruct accurate geometry and appearance. This family addresses the ill-posed nature of inverse rendering, where RGB data alone is insufficient to constrain the scene, leading to artifacts like "floaters" or shape-radiance ambiguity. It sets itself apart from sibling methods like [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md) by focusing on the *what* to optimize (the loss landscape) rather than the *how* of sampling, and from [Training Configuration](2332-training-configuration.md) by providing the mathematical gradients rather than the hyperparameter schedules.

### [KNN-NeRF](8672-knn-nerf.md)
KNN-NeRF is a baseline method for training Neural Radiance Fields (NeRFs) using sparse 3D point clouds as supervision instead of multi-view images. It solves the problem of generating ground-truth color labels for rays that do not pass through existing points by assigning the color of the nearest point in the cloud to the ray. Unlike standard NeRF which relies on pixel colors from images, KNN-NeRF constructs a dense training signal from sparse geometry, though it struggles with sharp object borders due to the low-frequency bias of neural networks and the sparsity of the input.

### [Progressive and Dynamic Scene Growth](8869-progressive-and-dynamic-scene-growth.md)
Progressive and Dynamic Scene Growth refers to training procedures that adaptively increase model capacity or expand the training dataset during optimization, rather than using a fixed architecture and static data subset. This family solves the problem of balancing computational resources with reconstruction fidelity in complex, large-scale, or continuously changing scenes. It sets itself apart from static NeRF training by dynamically allocating representational power (via network branches, octree leaves, or block attachments) to regions of high uncertainty or novelty, and by incrementally incorporating new observations to prevent catastrophic forgetting or to handle unbounded data streams.

### [Sparse View and Initialization Methods](9394-sparse-view-and-initialization-methods.md)
This family addresses the instability, artifacts (floaters, blurring), and slow convergence inherent in Neural Radiance Field (NeRF) optimization when trained on sparse input views (typically fewer than 50–100 images). It solves the problem of insufficient geometric constraints by introducing external priors—such as geometry scaffolds, visibility maps, or semantic masks—to regularize the implicit density and color fields. What sets these methods apart from standard NeRF training is the explicit injection of structural or visibility information before or during optimization, rather than relying solely on photometric consistency across views.

### [NeRV Training](10253-nerv-training.md)
NeRV training optimizes a continuous volumetric representation that decouples scene geometry (shape) from material appearance (reflectance) and lighting interactions (visibility) to enable efficient relighting and view synthesis. It differs from standard NeRF training by introducing a separate "visibility MLP" that predicts ray visibility and termination depth, supervised by consistency terms with the primary shape MLP rather than ground-truth labels, allowing the simulation of direct and one-bounce indirect illumination within the training loop.

### [Scene Representation and Architecture](11368-scene-representation-and-architecture.md)
This family defines the neural network topologies, data structures, and optimization strategies used to represent and optimize the radiance field $F_\Theta(\mathbf{x}, \mathbf{d}) = (\sigma, \mathbf{c})$. While the canonical NeRF uses a single deep MLP, this family encompasses methods that modify the network topology (e.g., multi-space decomposition, tensor grids), introduce auxiliary networks for specific tasks (e.g., depth estimation, instance segmentation), or alter the input/output mappings to support dynamic scenes, relighting, or single-view synthesis. These architectures set themselves apart from standard NeRF by addressing specific limitations such as computational cost, geometric ambiguity, lack of semantic understanding, or the inability to handle dynamic content.

### [Acceleration and Sparse Structures](11405-acceleration-and-sparse-structures.md)
This family of methods accelerates NeRF training and rendering by reducing the volume of space queried by the neural network, thereby lowering memory usage and computational cost. It addresses the bottleneck where standard NeRFs sample uniformly across a large bounding box, evaluating the MLP in empty space or on transient objects. It sets itself apart from [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md) by modifying *where* samples are taken (spatial constraints) rather than *how* they are integrated, and from [Adaptive Ray Sampling](8870-adaptive-ray-sampling.md) by using static or pre-computed geometric priors (hulls, blocks) rather than dynamic error metrics during training.

### [Camera Pose and Extrinsic/Intrinsic Optimization](12051-camera-pose-and-extrinsic-intrinsic-optimization.md)
This family of methods addresses the problem of optimizing camera parameters (extrinsics and intrinsics) simultaneously with Neural Radiance Field (NeRF) weights, eliminating the reliance on pre-computed Structure-from-Motion (SfM) pipelines like COLMAP [G]. By treating camera poses as learnable parameters, these methods enable 3D reconstruction from sparse or uncalibrated image sets [G]. What sets this family apart from siblings like [Time-dependent NeRF with Continuous Camera Motion](12399-time-dependent-nerf-with-continuous-camera-motion.md) is the explicit optimization of discrete camera poses per image rather than continuous motion functions, and from [Camera Preconditioning](12545-camera-preconditioning.md) by focusing on the joint gradient-based update of poses and scene geometry rather than preconditioning the optimizer for faster convergence [G].

### [Monocular Depth Estimation Adaptation and Supervision](12353-monocular-depth-estimation-adaptation-and-supervision.md)
This family of methods integrates pre-trained Monocular Depth Estimation (MDE) networks into NeRF training to resolve the shape-radiance ambiguity and geometric inaccuracies inherent in sparse-view or single-view reconstruction. By supervising the NeRF’s rendered depth with MDE priors, these methods enforce geometric consistency where photometric loss is insufficient. They differ from sibling methods like [NerfingMVS](9518-nerfingmvs.md) which primarily use depth for sampling bounds, and [Depth-Guided NeRF Training via Earth Mover’s Distance](11911-depth-guided-nerf-training-via-earth-mover-s-distance.md) which uses distributional losses, by focusing on explicit scale-shift alignment, confidence-weighted supervision, and joint adaptation of the MDE network itself to the target scene.

### [NeRF Editing and Inpainting Procedures](12494-nerf-editing-and-inpainting-procedures.md)
NeRF Editing and Inpainting Procedures modify a pre-trained Neural Radiance Field (NeRF) to remove objects, insert new content, or stylize the scene while maintaining multi-view consistency. Unlike standard training which optimizes for photometric reconstruction of input views, these methods optimize the NeRF parameters $\Theta$ using external priors (e.g., 2D inpainting, diffusion models, or semantic features) and user-defined masks to alter specific regions of interest (ROI). They are distinguished from sibling methods like [Progressive and Dynamic Scene Growth](8869-progressive-and-dynamic-scene-growth.md) by their focus on localized content manipulation rather than global scene expansion, and from [NeRF Training Loop](970-nerf-training-loop.md) by their reliance on generative priors rather than just photometric loss.

### [FlipNeRF Training Pipeline](12501-flipnerf-training-pipeline.md)
FlipNeRF is a training procedure for few-shot novel view synthesis that enhances the standard mip-NeRF representation by introducing flipped reflection rays and consistency-based regularization. It solves the problem of overfitting and unreliable depth estimation in sparse-view settings by enforcing geometric and feature consistency between original viewing rays and their hypothetical flipped counterparts. Unlike standard NeRF training which relies solely on photometric loss from observed views, FlipNeRF distinguishes itself by leveraging reflection symmetry priors and bottleneck feature consistency to regularize the radiance field, achieving higher reliability and lower negative log-likelihood (NLL) than mixture-model baselines like MixNeRF.

### [MLI-NeRF](12709-mli-nerf.md)
MLI-NeRF is a two-stage optimization procedure that learns an intrinsic-aware Neural Radiance Field (NeRF) capable of novel view synthesis, relighting, and intrinsic decomposition (separating reflectance and shading) without relying on statistical priors or ground-truth intrinsic labels. It differs from standard NeRF variants by explicitly modeling multiple light sources to generate physics-based pseudo-labels, and it differs from prior intrinsic NeRF methods (like [IntrinsicNeRF](10253-nerv-training.md)) by leveraging 3D geometric constraints and multi-light visibility rather than chromaticity or semantic statistical constraints. The method solves the ill-posed nature of inverse rendering by decoupling the geometry learning (Stage 1) from the intrinsic component separation (Stage 2), using pseudo-labels derived from the Stage 1 model to guide the decomposition.

### [Diffusion-guided Optimization](13230-diffusion-guided-optimization.md)
Diffusion-guided optimization methods train Neural Radiance Fields (NeRFs) by leveraging pretrained 2D or 3D diffusion models as priors to guide the optimization of 3D geometry and texture. These methods solve the problem of 3D data scarcity and underconstrained reconstruction by distilling generative knowledge from 2D image distributions into 3D scene representations. They set themselves apart from standard NeRF training by backpropagating gradients from a frozen or jointly trained diffusion model through a differentiable renderer, rather than relying solely on photometric reconstruction losses from input images.

### [Application-Specific Methods](13294-application-specific-methods.md)
Application-Specific Methods adapt the general NeRF training loop to solve domain-specific inverse problems by modifying the neural field architecture, loss functions, and optimization strategy. Unlike standard NeRF, which optimizes a single MLP for photometric reconstruction, these pipelines decompose fields to isolate physical properties, enforce domain priors (geometric, semantic, or physical), and employ iterative multi-stage optimization to handle complex constraints.

### [PlanarNeRF](13791-planarnerf.md)
PlanarNeRF is an online learning framework for detecting dense 3D planar primitives from monocular RGB and depth sequences. It combines plane segmentation rendering, an efficient plane fitting module, and a global memory bank to learn plane primitives in an online fashion using neural field representation, appearance, and geometry knowledge. It distinguishes itself from standard NeRF training loops by explicitly modeling planar instances via a dedicated rendering branch and maintaining a global memory bank for consistent plane tracking across views.

### [Progressive Camera Placement for NeRF](13844-progressive-camera-placement-for-nerf.md)
This method is a greedy optimization algorithm that selects camera positions to maximize a reconstruction quality metric $E(C, B_{32})$, which combines observation frequency and angular uniformity, to improve NeRF reconstruction quality with fewer images. Unlike uncertainty-based methods (e.g., ActiveNeRF), this method does not require additional image acquisition to estimate reconstruction quality, making it cheaper to compute. It builds on [NeRF Training Loop](970-nerf-training-loop.md) by dynamically selecting the next best view based on the current state of the occupancy grid and camera set.

### [Neural Refractive Radiance Field (NeRRF)](13882-neural-refractive-radiance-field-nerrf.md)
Neural Refractive Radiance Field (NeRRF) is an inverse rendering method for transparent scenes that reconstructs surface geometry and a radiance field from multi-view images without prior knowledge of the object's Index of Refraction (IOR). It solves the problem of incorrect radiance field learning and visual artifacts (such as holes and color errors) that occur when standard NeRF or SDF-based methods like NeuS attempt to model refraction with a fixed or unknown IOR. NeRRF distinguishes itself by automatically searching for the optimal IOR during training and correcting the calculation of refractive effects, specifically enabling accurate rendering of foreground darkening caused by refraction at object edges.

### [NeRF-Neural ODE](13904-nerf-neural-ode.md)
NeRF-Neural ODE replaces the discrete quadrature summation of standard NeRF with a continuous Neural Ordinary Differential Equation (Neural ODE) solver to integrate radiance and transmittance along rays. It differs from sibling methods like [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md) by treating the ray integration as a continuous dynamical system solved via adaptive ODE solvers rather than fixed-step numerical integration.

### [LOLNeRF](14071-lolnerf.md)
LOLNeRF is a method for single-shot view synthesis of human faces that learns a generative 3D model from single-view images without relying on explicit geometric information like depth or point clouds. It differs from adversarial approaches like $\pi$-GAN by using Generative Latent Optimization (GLO) to learn a per-image table of latent codes, allowing it to reconstruct specific training images with high fidelity while avoiding the resolution limits imposed by GAN discriminators.

### [Robustness and Generalization](14094-robustness-and-generalization.md)
This family encompasses methods that improve the stability of NeRF training against adversarial perturbations, the quality of novel view synthesis through ensemble compression, and the handling of unconstrained "in-the-wild" data with transient occluders or synthetic-to-real domain gaps. Unlike standard NeRF training which assumes a static, consistently lit scene, these methods introduce mechanisms for implicit regularization, multi-model aggregation, or explicit disentanglement of static and transient scene components .

### [FusedRF](14268-fusedrf.md)
FusedRF is a method to fuse multiple teacher Radiance Fields (RFs) into a single, compact student RF representation using distillation, allowing for composited scene rendering with the memory and time complexity of a single RF. Unlike naive composition which requires parallel tracing into multiple RFs (increasing memory and render time linearly with scene count), FusedRF fuses them into one RF, maintaining constant memory and render time. Unlike retraining from scratch using rendered RGB views, FusedRF uses 3D distillation from existing RFs, reducing training time by 3x.

### [MEIL-NeRF](14629-meil-nerf.md)
MEIL-NeRF is a memory-efficient incremental learning algorithm for Neural Radiance Fields (NeRF) that prevents catastrophic forgetting without increasing memory usage by treating the NeRF network itself as a memory storage for pixel RGB values. Unlike replay-based methods that suffer from monotonically increasing memory due to storing past data, MEIL-NeRF maintains constant memory consumption by using a Ray Generator Network (RGN) to retrieve past task information from the NeRF network itself, rather than storing raw data or exemplars. It builds on [NeRF Training Loop](970-nerf-training-loop.md) by introducing a self-distillation mechanism guided by generated rays.

### [NeRF-HuGS](14802-nerf-hugs.md)
NeRF-HuGS is a training procedure for Neural Radiance Fields (NeRF) that mitigates artifacts caused by transient distractors (e.g., moving objects, shadows) in non-static scenes. It solves the problem of distinguishing static geometry from transient elements by combining hand-crafted heuristics with the Segment Anything Model (SAM). Unlike prior segmentation-based methods that require semantic class priors or heuristic-only methods that miss low-frequency static details, HuGS fuses Structure-from-Motion (SfM) features (high-frequency textures) and color residuals from a partially trained NeRF (low-frequency textures) to guide SAM in generating precise static masks.

### [SGCNeRF](14984-sgcnerf.md)
SGCNeRF is a few-shot neural rendering architecture for novel view synthesis that addresses the performance decline of standard frequency regularization in high-frequency regions (rich textures or geometry variations) where methods like FreeNeRF suffer from excessive smoothing. It distinguishes itself by integrating a feature-matching-based sparse geometry regularization module with spatially consistent geometry filtering and frequency-guided geometric regularization, thereby preserving high-frequency details while preventing overfitting.

### [NeRF-Det Training Objectives](14994-nerf-det-training-objectives.md)
NeRF-Det Training Objectives define the loss functions used to jointly optimize a Neural Radiance Field (NeRF) branch and a 3D object detection branch in a single end-to-end framework. The method solves the problem of ambiguous volumetric representations in multi-view 3D object detection by leveraging the NeRF branch to learn a geometry-aware opacity field, which provides superior scene geometry modeling compared to explicit depth estimation or cost volumes. It sets itself apart from sibling methods like [KNN-NeRF](8672-knn-nerf.md) or [Progressive and Dynamic Scene Growth](8869-progressive-and-dynamic-scene-growth.md) by explicitly coupling the photometric/depth supervision of the radiance field with the detection head's classification and localization losses, ensuring that better NeRF optimization directly improves detection results.

### [NeRF Volumetric Rendering](15005-nerf-volumetric-rendering.md)
NeRF Volumetric Rendering is the differentiable integration step that synthesizes a 2D image from a 3D radiance field by accumulating color and opacity along camera rays. It solves the problem of rendering continuous volumetric representations into discrete pixel values by approximating the line integral of the rendering equation. It is distinguished from sibling methods like [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md) by its specific reliance on the alpha-compositing formulation derived from the original NeRF paper, which serves as the primary gradient source for optimizing the underlying neural network parameters.

### [Semantic and Open-Vocabulary Understanding](17023-semantic-and-open-vocabulary-understanding.md)
This family extends NeRF training to predict semantic features or segmentation logits alongside color and density, enabling object-level understanding and editing. It differs from standard NeRF training by incorporating external vision-language models (e.g., CLIP) or foundation models (e.g., SAM) to provide semantic supervision, addressing the challenge of view-inconsistent 2D labels through 3D-consistent refinement strategies like Cross-view Self-enhancement (CSE) and Region Semantic Ranking (RSR).

### Supersampling Baseline
A baseline method for evaluating NeRF on multiscale data by training on full-resolution images and using brute-force supersampling during evaluation, or training on multiscale data with supersampling during both training and evaluation [S23]. For every pixel, it casts multiple jittered rays sampled uniformly at random through the spatial footprint of the pixel, renders each ray with NeRF, and uses the mean of those rendered values as the predicted color in the loss function [S23]. The full-resolution supersampling baseline relies on 'oracle' scale information that does not exist for most datasets [S23]. Performance: The 16x supersampling baseline performs worse than mip-NeRF and is significantly more expensive during both training and evaluation [S23].

### Two-stage training for proposers
A training schedule split into two equal-duration phases to stabilize learning of a trainable proposer network in NeRF-ID [S24, unofficial]. Phase 1 trains the learnt proposer to mimic the heuristic proposer by minimizing the L2 matching loss between their proposal sets [S24, unofficial]. Phase 2 trains all network components end-to-end, resetting the optimizer state and performing a linear warmup for 1,000 SGD steps to reduce shock from switching regimes [S24, unofficial]. Training from scratch sometimes works but often fails; two-stage training is consistently effective [S24, unofficial].

### JaxNeRF
A re-implementation of the original NeRF in JAX, used as a benchmark comparison for early works seeking to improve on training and rendering speed [S25]. It is slightly faster and more suited for distributed computing than the original TensorFlow implementation of NeRF [S25].

### Gradient Detachment in Training
A training strategy where the object field component is detached from the backbone to prevent gradient backpropagation to the rendering part, ensuring independent optimization [S26, unofficial]. With detach, the object field component output is detached so gradients do not backpropagate to the NeRF backbone; without detach, gradients from the object field component backpropagate to the NeRF backbone, causing mutual influence [S26, unofficial]. The hyper-parameter $\Delta d$ for empty 3D point losses ($\ell_{3d \text{ empty}} + \ell_{3d \text{ obj}}$) is tested at 0.025, 0.05, 0.10 meters, with 0.05 meters found optimal [S26, unofficial]. With detach achieves better scene rendering and decomposition quality; without detach causes significant drop in rendering quality [S26, unofficial].

### Ray Generator Network (RGN)
Used in MEIL-NeRF for incremental learning of NeRF [S27]. During training on task $T$, the RGN $f_T^{RGN}$ learns to map past principal rays from $f_{T-1}^{RGN}$ and current GT principal rays [S27]. During inference, it randomly selects a number $x \in [0, 1]$ and generates a principal ray using RGN, then uses camera intrinsic $K$ to randomly generate non-principal rays around the principal rays, forming a cone emitted from the camera center covering the region of the image plane [S27]. The network architecture has 3 hidden layers with 16, 64, and 32 hidden units respectively [S27]. Estimated camera poses accumulate errors over tasks, but the generated approximate rays still effectively direct to the scene of interest near past task cameras, so exact reconstruction of past rays is not required [S27]. Unlike methods that reproduce exact past rays, RGN creates approximate rays directed to the scene of interest, allowing errors under a certain level to reduce the learning burden at a small accuracy cost [S27].

### DFF
A method adopting pre-trained feature extraction networks as teacher networks for knowledge distillation, resulting in a scene-specific 3D feature field, enabling extraction and deletion of target objects based on image patches or text [S28]. It adopts pre-trained feature extraction networks (LSeg [115] and DINO [116]) as teacher networks, performs knowledge distillation, and results in a scene-specific 3D feature field [S28].

## Operating characteristics
*   **Time Complexity:** $O(N_{iters} \cdot N_{rand} \cdot N_{samples})$, where $N_{iters}$ is the number of iterations, $N_{rand}$ is the batch size (rays per iteration), and $N_{samples}$ is the number of samples per ray [S5, S11, unofficial].
*   **Memory Complexity:** $O(N_{rand} \cdot N_{samples})$ for the forward pass, plus $O(N_{rand} \cdot N_{samples})$ for gradients if using reverse-mode AD [S5, S15, unofficial]. Pre-computing `rays_rgb` requires $O(N_{images} \cdot H \cdot W)$ memory [S5, unofficial].
*   **Measured Performance:** In the original NeRF implementation, training typically runs for 100,000 iterations with a batch size of 1024 rays [S11, unofficial]. On a single GPU, this can take several hours depending on scene complexity and network depth [S5, S11, unofficial].
*   **Scaling:** Performance scales with batch size; larger batches improve GPU utilization but increase memory usage [S16, unofficial]. The batch size of $2^{10}$ (1024) is a tradeoff between data loading performance and iterations per second [S16, unofficial].
*   **Strengths:** Simple to implement; leverages standard deep learning frameworks; effective for high-quality novel view synthesis on moderate-sized scenes [S5, S10, unofficial].
*   **Limitations:** High memory usage for large scenes or high-resolution images; slow convergence due to uniform sampling in empty space; prone to artifacts like "floaters" in unobserved regions [S5, S11, S18, unofficial].
*   **When to use:** When high-quality novel view synthesis is required and computational resources are sufficient for iterative optimization [S5, S11, unofficial].
*   **When not to use:** For real-time applications or very large-scale scenes where training time and memory are prohibitive [S16, S18, unofficial].

## Background
The NeRF Training Loop was introduced in the seminal paper "NeRF: Representing Scenes as Neural Radiance Fields for View Synthesis" by Mildenhall et al. in 2020 [S5, S10, S19, unofficial]. It builds on the concept of implicit neural representations for 3D scenes, using a coordinate-based MLP to map 3D coordinates and viewing directions to volume density and color [S5, S19, unofficial]. The training procedure relies on differentiable volume rendering to backpropagate gradients from 2D image losses to the 3D scene representation [S5, S10, unofficial]. Since its introduction, it has become the standard baseline for neural radiance field optimization, with numerous variants and improvements proposed in subsequent works [S1][S2, S5, S10, S11, S15, S19, unofficial].
