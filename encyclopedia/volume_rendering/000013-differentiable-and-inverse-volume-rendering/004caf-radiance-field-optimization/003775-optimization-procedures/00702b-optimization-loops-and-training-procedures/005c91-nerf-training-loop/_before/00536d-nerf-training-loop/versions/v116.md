# NeRF Training Loop

Also called: NeRF Optimization Loop, NeRF Training Procedure, Neural Radiance Fields Training, Training Ray Sampling Strategy for Correspondence Disparity, Ray Sampling Strategy for Correspondence Disparity

## Overview
The NeRF Training Loop is the iterative optimization procedure that learns a continuous volumetric scene representation (Neural Radiance Field) from a set of multi-view images [S5, S11, unofficial]. It solves the inverse problem of reconstructing 3D geometry and appearance by minimizing the photometric difference between rendered and observed pixel colors [S5, S15, unofficial]. It differs from its siblings by defining the core stochastic gradient descent cycle—specifically the random ray sampling, differentiable forward rendering, and weight update mechanism—whereas [Training Ray Marching and Integration](2199-training-ray-marching-and-integration.md) details the forward pass implementation and [Training Configuration](2332-training-configuration.md) specifies the hyperparameters and schedules governing this loop [S1][S2, S3, S11, unofficial].

## How it works
The method optimizes a coordinate MLP (or hash-based network) to map 6D input coordinates (3D position $\mathbf{x}$ and viewing direction $\mathbf{d}$) to density $\sigma$ and color $\mathbf{c}$ [Parent]. The loop iterates over a fixed number of steps or epochs, processing batches of rays to update network parameters via gradient descent [S5, S11, unofficial].

### Inputs and Outputs
*   **Inputs:**
    *   Training dataset: Set of $N$ images with known camera poses (extrinsics $C2W$ and intrinsics $K$) [S11, unofficial].
    *   Ray sampling parameters: Number of samples per ray $N$, near/far bounds ($n, f$), and batch size $B$ (number of rays per step) [S5, S11, unofficial].
    *   Optimization hyperparameters: Learning rate $\eta$, optimizer type (typically Adam), and loss function [S5, S11, unofficial].
*   **Outputs:**
    *   Optimized network weights $\Theta$ [S5, unofficial].
    *   (Optional) Rendered validation images and loss metrics logged periodically [S11, unofficial].

### Data Structures
*   **Rays Bundle:** A tensor of shape $[B, 2, 3]$ or $[B, 5, 3]$ containing ray origins $\mathbf{o}$, directions $\mathbf{d}$, and optionally near/far bounds or view directions [S5, S7, unofficial].
*   **Ground Truth Colors:** A tensor of shape $[B, 3]$ containing the RGB values sampled from the training images at the ray origins' pixel coordinates [S5, S15, unofficial].
*   **Pre-computed Rays (Optional):** For efficiency, rays can be pre-computed and stored in a flat array `rays_rgb` of shape $[(N-1) \cdot H \cdot W, 3, 3]$, where axis 1 is `[origin, direction, target_rgb]` and axis 2 is the XYZ/RGB components [S5, S15, unofficial].

### Numbered Steps
1.  **Initialization:** Initialize the neural network weights (e.g., random or SIREN initialization) and the optimizer (e.g., Adam with learning rate $\eta$) [S5, S13, unofficial]. If using a coarse-to-fine strategy, initialize both coarse and fine networks [S11, unofficial].
2.  **Ray Sampling:** For each iteration $i$:
    *   Select a batch of $B$ random pixels from the training images [S5, S15, unofficial].
    *   Construct ray bundles $(\mathbf{o}, \mathbf{d})$ for these pixels using the camera intrinsics and extrinsics [S4, S15, unofficial].
    *   Sample ground truth colors $\mathbf{c}_{gt}$ from the images at these pixel locations, typically using bilinear interpolation in NDC space [S4, S15, unofficial].
3.  **Forward Pass (Rendering):**
    *   Sample $N$ points along each ray within the near/far bounds [S5, unofficial].
    *   Query the neural network for density $\sigma$ and color $\mathbf{c}$ at these points [S5, unofficial].
    *   Compute the rendered color $\hat{\mathbf{C}}(\mathbf{r})$ using volume rendering (alpha compositing) [Parent, S29]:
        $$ \hat{\mathbf{C}}(\mathbf{r}) = \sum_{j=1}^{N} T_j (1 - \exp(-\sigma_j \delta_j)) \mathbf{c}_j $$
        where $T_j = \exp\left(-\sum_{k=1}^{j-1} \sigma_k \delta_k\right)$ is the transmittance, and $\delta_j$ is the distance between samples [Parent].
    *   (Optional) If coarse-to-fine training is used, compute the coarse loss from the coarse network's output $\hat{\mathbf{C}}_{coarse}$ [S11, unofficial].
4.  **Loss Computation:**
    *   Compute the Mean Squared Error (MSE) between the rendered color $\hat{\mathbf{C}}(\mathbf{r})$ and the ground truth $\mathbf{c}_{gt}$ [S5, S15, unofficial]:
        $$ \mathcal{L}_{rgb} = \frac{1}{B} \sum_{i=1}^{B} \| \hat{\mathbf{C}}(\mathbf{r}_i) - \mathbf{c}_{gt, i} \|^2 $$
    *   (Optional) Add regularization terms (e.g., sparsity, Eikonal, or Total Variation) or coarse losses if applicable [S7, unofficial][S8][S11, unofficial].
    *   Total Loss: $\mathcal{L} = \mathcal{L}_{rgb} + \lambda_{coarse} \mathcal{L}_{coarse} + \dots$ [S11, unofficial].
5.  **Backpropagation and Update:**
    *   Compute gradients $\nabla_\Theta \mathcal{L}$ via automatic differentiation [S5, S19, unofficial].
    *   Update network weights $\Theta$ using the optimizer (e.g., Adam step) [S5, S19, unofficial].
    *   (Optional) Update learning rate according to a schedule (e.g., Exponential Decay or Cosine Annealing) [S5, S11, unofficial].
6.  **Logging and Checkpointing:**
    *   Log loss and metrics (e.g., PSNR) at regular intervals [S11, unofficial].
    *   Render validation images and save model checkpoints at specified intervals [S11, unofficial].

### Pseudocode
```python
def train_nerf(model, optimizer, dataset, num_iters, batch_size, near, far, num_samples):
    """
    Standard NeRF training loop.
    
    Args:
        model: Neural Radiance Field MLP.
        optimizer: Optimizer (e.g., Adam).
        dataset: Object providing images, poses, and intrinsics.
        num_iters: Total number of training iterations.
        batch_size: Number of rays per iteration (N_rand).
        near: Near plane distance.
        far: Far plane distance.
        num_samples: Number of samples per ray.
    """
    # Pre-compute rays if desired for efficiency [S5, S15, unofficial]
    # rays_rgb = precompute_rays(dataset) # Shape: [Total_Pixels, 3, 3]
    
    for i in range(num_iters):
        # 1. Ray Sampling
        # Randomly select batch_size pixels/rays
        if precomputed_rays:
            # Slice from pre-computed array
            batch_indices = slice(i * batch_size, (i + 1) * batch_size)
            batch_rays = rays_rgb[batch_indices] # Shape: [batch_size, 3, 3]
            rays_o = batch_rays[:, 0, :] # Origins
            rays_d = batch_rays[:, 1, :] # Directions
            target_s = batch_rays[:, 2, :] # Ground Truth Colors
        else:
            # Sample random pixels and construct rays
            pixel_coords = sample_random_pixels(dataset, batch_size)
            rays_o, rays_d = construct_rays(pixel_coords, dataset.intrinsics, dataset.poses)
            target_s = sample_gt_colors(pixel_coords, dataset.images)

        # 2. Forward Pass
        # Sample points along rays
        t_vals = linspace(near, far, num_samples)
        z_vals = sample_points(t_vals, perturb=True) # Stratified sampling [S5, unofficial]
        pts = rays_o[:, None, :] + rays_d[:, None, :] * z_vals[:, :, None] # [B, N, 3]
        
        # Query network
        # model returns raw output: [B, N, 4] (RGB + Density)
        raw = model(pts, rays_d) 
        
        # Volume Rendering
        # Convert raw density to alpha
        sigma = raw[..., 3]
        dists = z_vals[:, 1:] - z_vals[:, :-1]
        alpha = 1.0 - torch.exp(-sigma * dists)
        
        # Compute transmittance and weights
        transmittance = torch.cumprod(1.0 - alpha + 1e-10, dim=1, exclusive=True)
        weights = alpha * transmittance
        
        # Rendered color
        rgb = raw[..., :3]
        rendered_rgb = torch.sum(weights[..., None] * rgb, dim=1) # [B, 3]

        # 3. Loss Computation
        # MSE Loss
        loss = torch.mean((rendered_rgb - target_s) ** 2)
        
        # 4. Backpropagation and Update
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 5. Logging (every N steps)
        if i % log_interval == 0:
            psnr = -10.0 * torch.log10(loss)
            print(f"Iter {i}: Loss {loss.item():.6f}, PSNR {psnr.item():.2f}")
            
        # 6. Checkpointing (every M steps)
        if i % save_interval == 0:
            save_checkpoint(model, optimizer, i)
```

### Parameters with Typical Values
*   **Learning Rate ($\eta$):** $5 \times 10^{-4}$ [S11, unofficial] or $10^{-3}$ [S13, unofficial].
*   **Batch Size ($N_{rand}$):** 1024 or 2048 rays per iteration [S5, S11, unofficial].
*   **Samples per Ray ($N$):** 128 (coarse) + 64 (fine) [S5, S11, unofficial].
*   **Iterations:** 100,000 to 1,000,000 [S11, S15, unofficial].
*   **Near/Far Bounds:** Scene-dependent (e.g., 2.0/6.0 for Blender, NDC 0.0/1.0 for LLFF) [S2, S14, unofficial].
*   **Positional Encoding Frequency:** 10 for position, 4 for direction [S11, unofficial].

### Edge Cases and Pitfalls
*   **VRAM Overflow:** Rendering all rays at once can exceed GPU memory. Mitigated by chunking rays during the forward pass [S5, S7, unofficial].
*   **Instability in Dynamic Growth:** Directly growing sub-networks with random initialization can cause density to drop to zero. Initialize grown sub-network weights to match the parent network [S1].
*   **Gradient Computation Order:** Higher-order derivatives (for logging gradients/laplacians) must be computed *before* `loss.backward()` to avoid freeing the autograd graph [S3, unofficial].
*   **Checkpoint Resumption:** When resuming, ensure the learning rate scheduler's last epoch is set to `start_epoch - 1` to maintain correct scheduling [S9, unofficial].
*   **Empty Checkpoints:** If a loaded checkpoint has step 0, it is considered empty and should trigger an error or re-initialization [S16, unofficial].

### Supersampling Baseline
A baseline method for evaluating NeRF on multiscale data by training on full-resolution images and using brute-force supersampling during evaluation, or training on multiscale data with supersampling during both training and evaluation [S23]. For every pixel, multiple jittered rays are sampled uniformly at random through the spatial footprint of the pixel. The mean of these rendered values is used as the predicted color in the loss function [S23]. This method relies on 'oracle' scale information that does not exist for most datasets and performs worse than mip-NeRF while being significantly more expensive [S23].

### Two-stage training for proposers
A training schedule split into two equal-duration phases to stabilize learning of a trainable proposer network in NeRF-ID [S24, unofficial]. Phase 1 trains the learnt proposer to mimic the heuristic proposer by minimizing the L2 matching loss between their proposal sets. Phase 2 trains all network components end-to-end, resetting the optimizer state and performing a linear warmup for 1,000 steps to reduce shock from switching regimes [S24, unofficial]. This two-stage approach is consistently effective where training from scratch often fails [S24, unofficial].

### JaxNeRF
A re-implementation of the original NeRF in JAX, used as a benchmark comparison for early works seeking to improve on training and rendering speed [S25]. It is slightly faster and more suited for distributed computing than the original TensorFlow implementation [S25].

### Gradient Detachment in Training
A training strategy where the object field component is detached from the backbone to prevent gradient backpropagation to the rendering part, ensuring independent optimization [S26, unofficial]. With detachment, gradients do not backpropagate to the NeRF backbone, achieving better scene rendering and decomposition quality. Without detachment, gradients from the object field component backpropagate to the backbone, causing a significant drop in rendering quality [S26, unofficial]. The hyper-parameter $\Delta d$ for empty 3D point losses is typically optimized to 0.05 meters [S26, unofficial].

### Ray Generator Network (RGN)
Used in MEIL-NeRF for incremental learning [S27]. During training on task $T$, the RGN $f_T^{RGN}$ learns to map past principal rays from $f_{T-1}^{RGN}$ and current GT principal rays. During inference, a principal ray is generated using the RGN, and non-principal rays are generated around it using camera intrinsics to form a cone covering the image plane [S27]. The network architecture consists of 3 hidden layers with 16, 64, and 32 hidden units [S27]. Estimated camera poses accumulate errors, but the generated approximate rays still effectively direct to the scene of interest, allowing errors under a certain level to reduce the learning burden [S27].

### DFF
A method adopting pre-trained feature extraction networks (LSeg, DINO) as teacher networks for knowledge distillation, resulting in a scene-specific 3D feature field [S28]. This enables extraction and deletion of target objects based on image patches or text [S28].

### ISRF
A method that learns additional feature fields to realize self-supervised 3D segmentation [S28].

### NeRF Volumetric Rendering
Final pixel color and depth are produced via volumetric rendering: $\hat{C}(\mathbf{r}) = \sum_{i=1}^{N_p} T_i \alpha_i \mathbf{c}_i$, $D(\mathbf{r}) = \sum_{i=1}^{N_p} T_i \alpha_i t_i$. Where $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_t)$, $\alpha_i = 1 - \exp(-\sigma_i \delta_t)$, $t_i$ is the distance of the $i$-th point from the camera, and $\delta_t$ is the distance between sampled points [S29].

## Operating characteristics
*   **Time Complexity:** $O(N_{iters} \cdot B \cdot N \cdot D)$, where $N_{iters}$ is the number of iterations, $B$ is the batch size, $N$ is the number of samples per ray, and $D$ is the MLP dimensionality [S5, S11, unofficial].
*   **Memory Complexity:** $O(B \cdot N \cdot D)$ for storing intermediate activations during the forward pass, plus $O(N_{iters})$ for optimizer states if not using memory-efficient optimizers [S5, unofficial]. Chunking reduces peak memory usage [S5, unofficial].
*   **Measured Performance:** Training on 199 images (down-sampled by factor of 4) with batch size 1024 results in ~7,800 iterations per epoch, totaling ~39,000 iterations for 5 epochs [S18, unofficial].
*   **Scaling:** Larger batch sizes (e.g., $2^{14}$) can hinder data loading performance and prevent full GPU occupancy, while smaller batch sizes (e.g., $2^{10}$) cap iterations per second, reducing throughput [S16, unofficial].
*   **Strengths:** End-to-end differentiable, handles complex geometry and appearance, produces high-quality novel views.
*   **Limitations:** Slow convergence (requires many iterations), high memory usage for large scenes, sensitive to hyperparameters (learning rate, sampling strategy) [S5, S18, unofficial].
*   **When to Use:** When high-quality novel view synthesis is required and computational resources are sufficient.
*   **When Not to Use:** For real-time applications without acceleration structures, or when input data is extremely sparse without additional priors [S1][S18, unofficial].

## Background
The NeRF training loop was introduced by Mildenhall et al. in "NeRF: Representing Scenes as Neural Radiance Fields for View Synthesis" (2020) [S5, S11, unofficial]. It builds on the concept of coordinate-based neural networks for implicit scene representation [S3, unofficial]. The method uses stochastic gradient descent with Adam optimizer to minimize the MSE between rendered and observed colors [S5, S11, unofficial]. It has become the standard baseline for neural radiance field optimization, with numerous variants and accelerations developed subsequently [S25].
