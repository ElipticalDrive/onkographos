# Instant-NSR

Also called: Neural Surface Reconstruction, Neural Surface Reconstruction with Hash

## Overview
Instant-NSR is a neural surface reconstruction method that improves 3D geometry quality by incorporating a Signed Distance Function (SDF) representation into a hash-encoded neural network framework [S1]. It solves the convergence instability inherent in applying SDFs to hash coding by employing a Truncated Signed Distance Function (TSDF) via a sigmoid output activation [S1]. It sets itself apart from its sibling [NeuS](6060-neus.md) by using the spatial hashing acceleration of [Instant-NGP](52-name.md) while retaining NeuS's SDF-based rendering formulation, and from [Surface NeRF](7385-surface-nerf.md) by its specific handling of hash-grid numerical overflow through truncation [S1].

## How it works
**Inputs:** A set of multi-view images with known camera poses.
**Outputs:** A neural network model representing the scene geometry (SDF) and appearance, capable of rendering novel views and extracting mesh surfaces.

**Data Structures:**
1.  **Hash Grid:** A spatial hash encoding structure similar to Instant-NGP [S1]. It maps 3D coordinates to feature vectors via hash collisions and interpolation.
2.  **Neural Network:** A Multi-Layer Perceptron (MLP) that takes the hashed features as input. Unlike Instant-NGP which outputs density, this network outputs the SDF value $f(x)$ [S1].
3.  **TSDF Mapping:** The raw SDF output is passed through a sigmoid function $\pi(\cdot)$ to truncate values to the range $[-1, 1]$ [S1].

**Numbered Steps:**

1.  **Hash Encoding:** For a query point $\mathbf{x}$ in 3D space, compute its hash indices and retrieve the corresponding feature vectors from the hash grid [S1].
2.  **SDF Prediction:** Pass the hashed features through the MLP to predict the raw Signed Distance Function value $f(\mathbf{x})$ [S1].
3.  **TSDF Truncation:** Apply the sigmoid function $\pi(\cdot)$ to the raw SDF output to obtain the truncated SDF value $\pi(f(\mathbf{x}))$ [S1]:
    $$
    \pi(f(\mathbf{x})) = \frac{1 - e^{-bf(\mathbf{x})}}{1 + e^{-bf(\mathbf{x})}}
    $$
    where $b$ is a scaling factor [S1]. This ensures the value remains between -1 and 1, preventing numerical overflow during training [S1].
4.  **Volume Rendering:** Compute the rendered color $\hat{C}(\mathbf{r})$ for a ray $\mathbf{r}$ using the SDF-based volume rendering formulation [S1]. The weight $w(t)$ for a sample at depth $t$ is computed using the cumulative density distribution $\phi_b$ modified for TSDF [S1]:
    $$
    \phi_b(f(\mathbf{x})) = \frac{b e^{-b\pi(f(\mathbf{x}))}}{(1 + e^{-b\pi(f(\mathbf{x}))})^2}
    $$
    This replaces the standard NeuS formulation $\phi_b(f(\mathbf{x})) = \frac{b e^{-bf(\mathbf{x})}}{(1 + e^{-bf(\mathbf{x})})^2}$ to ensure numerical stability [S1].
5.  **Loss Computation:** Calculate the total loss $L_{total}$ as a weighted sum of the rendering loss $L_{render}$ and the eikonal loss $L_{eik}$ [S1]:
    $$
    L_{total} = \alpha L_{render} + \beta L_{eik}
    $$
    where $\alpha$ and $\beta$ are hyperparameters [S1].
6.  **Eikonal Loss:** Enforce the Eikonal equation by ensuring the gradient magnitude of the SDF is 1. For $M$ sampled points $x_j$:
    $$
    L_{eik} = \frac{1}{M} \sum_{j=1}^{M} (\|\nabla f(x_j)\|_2^2 - 1)^2
    $$
    where $\nabla f(x_j)$ is the gradient of the SDF at point $x_j$ [S1].
7.  **Optimization:** Update the network parameters (hash grid features and MLP weights) using gradient descent [S1].

**Parameters:**
*   $\alpha$: Weighting factor for rendering loss. Chosen via cross-validation [S1].
*   $\beta$: Weighting factor for eikonal loss. Chosen via cross-validation [S1].
*   $b$: Scaling factor in the sigmoid/truncation function. Increasing $b$ sharpens the truncation but risks numerical instability if not truncated [S1].

**Edge Cases and Pitfalls:**
*   **Numerical Instability:** In original SDF-based methods, increasing $b$ causes $-bf(\mathbf{x})$ to become a large positive number, making $e^{-bf(\mathbf{x})}$ approach infinity, leading to network divergence [S1]. The TSDF truncation via $\pi(\cdot)$ prevents this overflow [S1].
*   **Hash Grid Convergence:** Applying raw SDF to hash coding frameworks can cause convergence problems; TSDF is required to solve this [S1].

**Pseudocode:**

```python
import torch
import torch.nn as nn

class InstantNSR:
    def __init__(self, hash_grid, mlp, b=10.0):
        """
        Initialize Instant-NSR model.
        
        Args:
            hash_grid: Hash encoding structure (e.g., from Instant-NGP).
            mlp: Neural network taking hashed features and outputting raw SDF.
            b: Scaling factor for sigmoid truncation.
        """
        self.hash_grid = hash_grid
        self.mlp = mlp
        self.b = b

    def forward(self, points):
        """
        Forward pass to get truncated SDF values.
        
        Args:
            points: Tensor of shape (N, 3) containing 3D coordinates.
            
        Returns:
            truncated_sdf: Tensor of shape (N,) with values in [-1, 1].
        """
        # Step 1: Hash encode points
        # [G] Assuming hash_grid returns a feature vector for each point.
        # In practice, this involves hashing coordinates to grid indices and interpolating.
        features = self.hash_grid.encode(points)
        
        # Step 2: Predict raw SDF
        raw_sdf = self.mlp(features)
        
        # Step 3: TSDF Truncation using sigmoid
        # pi(f(x)) = (1 - exp(-b * f(x))) / (1 + exp(-b * f(x)))
        # This is equivalent to tanh(b * f(x) / 2) scaled, but implemented as sigmoid variant per source.
        # Note: The source formula is (1 - e^(-bf)) / (1 + e^(-bf)).
        # This is mathematically equivalent to tanh(bf/2).
        # We implement exactly as described in source [S1].
        exp_term = torch.exp(-self.b * raw_sdf)
        truncated_sdf = (1 - exp_term) / (1 + exp_term)
        
        return truncated_sdf

    def compute_eikonal_loss(self, points):
        """
        Compute the Eikonal loss for a batch of points.
        
        Args:
            points: Tensor of shape (M, 3).
            
        Returns:
            loss: Scalar Eikonal loss.
        """
        points.requires_grad = True
        
        # Get raw SDF for gradient computation
        # Note: We need the raw SDF for the gradient, not the truncated one,
        # as the Eikonal constraint applies to the underlying SDF field f(x).
        features = self.hash_grid.encode(points)
        raw_sdf = self.mlp(features)
        
        # Compute gradient of SDF w.r.t. input points
        grad = torch.autograd.grad(
            raw_sdf, 
            points, 
            grad_outputs=torch.ones_like(raw_sdf), 
            create_graph=True
        )[0]
        
        # L_eik = (1/M) * sum(||grad||^2 - 1)^2
        grad_norm_sq = torch.sum(grad**2, dim=1)
        loss = torch.mean((grad_norm_sq - 1)**2)
        
        return loss

    def render_ray(self, ray_origin, ray_direction, num_samples):
        """
        Render a single ray using SDF-based volume rendering.
        
        Args:
            ray_origin: Tensor (3,)
            ray_direction: Tensor (3,)
            num_samples: Integer, number of samples along the ray.
            
        Returns:
            color: Rendered color.
            loss: Total loss for this ray (if training).
        """
        # [G] Standard ray marching setup: sample points along ray.
        # t = t_min + i * delta_t
        # x_i = ray_origin + t_i * ray_direction
        
        # Sample points
        t_vals = torch.linspace(0.1, 10.0, num_samples) # [G] Typical bounds, not specified in source
        points = ray_origin.unsqueeze(0) + t_vals.unsqueeze(1) * ray_direction.unsqueeze(0)
        
        # Get truncated SDF values
        truncated_sdf = self.forward(points)
        
        # Compute weights using modified phi_b
        # phi_b(f(x)) = b * exp(-b * pi(f(x))) / (1 + exp(-b * pi(f(x))))^2
        exp_term = torch.exp(-self.b * truncated_sdf)
        phi_b = (self.b * exp_term) / ((1 + exp_term)**2)
        
        # [G] Standard volume rendering integration:
        # alpha_i = 1 - exp(-phi_b * delta_t)
        # T_i = product(1 - alpha_j) for j < i
        # Color = sum(T_i * alpha_i * color_i)
        # Since color is not explicitly detailed in the SDF-only context of the source,
        # we assume a standard color prediction branch or fixed color for geometry extraction.
        # The source focuses on the SDF/weight formulation.
        
        # For implementation completeness, we assume a color MLP or fixed color.
        # Here we return the weights for external color integration.
        return phi_b
```

## Subtopics

### NeuS
Uses an SDF-based rendering formulation with a standard MLP (no hash encoding). It serves as the architectural basis for the SDF component in Instant-NSR [S1].

### Instant-NGP
Uses hash encoding for fast training and inference but outputs density rather than SDF. Instant-NSR adopts its hash encoding front-end but replaces the density architecture with NeuS's SDF architecture [S1].

### Surface NeRF
Another SDF-based NeRF method. Instant-NSR differs by specifically addressing the numerical instability of SDFs in hash grids via TSDF truncation [S1].

## Operating characteristics
*   **Time Complexity:** Accelerated by hash encoding, similar to Instant-NGP, allowing for faster training and inference compared to standard MLP-based NeRFs [S1].
*   **Memory Complexity:** Hash grids are memory-efficient compared to dense voxel grids, but the exact memory footprint depends on the hash grid size and resolution [S1].
*   **Strengths:** Improves reconstructed geometry quality over density-based NeRFs (like Instant-NGP) by leveraging SDF constraints [S1]. Solves convergence issues in hash-based SDF training via TSDF [S1].
*   **Limitations:** Requires careful tuning of hyperparameters $\alpha$ and $\beta$ via cross-validation [S1]. Numerical instability can still occur if the truncation is not properly handled (mitigated by TSDF) [S1].
*   **When to use:** When high-quality 3D geometry reconstruction is required alongside novel view synthesis, and training speed is a concern [S1].
*   **When not to use:** If only appearance synthesis is needed without precise geometry, Instant-NGP may be sufficient [S1].

## Background
Instant-NSR was explored in the context of high-fidelity 3D reconstruction of plants using Neural Radiance Fields [S1]. It was introduced to address the limitations of density-based NeRFs in geometry reconstruction by incorporating SDFs, while maintaining the speed of hash encoding [S1]. The method builds on the principles of [NeuS](6060-neus.md) and [Instant-NGP](52-name.md) [S1].
