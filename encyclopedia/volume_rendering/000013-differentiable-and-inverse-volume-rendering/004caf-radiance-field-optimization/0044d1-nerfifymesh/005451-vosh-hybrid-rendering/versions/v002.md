# Vosh Hybrid Rendering

Also called: Vosh, Voxel-Mesh Hybrid Representation

## Overview
Vosh is a hybrid representation method that combines a textured mesh with a sparse voxel grid to achieve real-time view synthesis while preserving comprehensive scene information [S1, unofficial]. It addresses the trade-off between geometric precision and volumetric completeness by using the mesh for surface details and the voxels for thin structures and background volume [S1, unofficial]. Unlike Adaptive Shells, which constrain volume rendering to regions near the surface, Vosh allows pure volume rendering where necessary, making it suitable for outdoor scenes [S1, unofficial]. It differs from VMesh by reconstructing a volumetric density field, enabling the mesh to represent thin structures like fishing nets that are difficult to capture with Signed Distance Fields (SDFs) [S1, unofficial].

## How it works
### Inputs and Outputs
*   **Inputs**: Textured mesh models, camera poses, and multi-view images [S1, unofficial].
*   **Outputs**: A hybrid asset consisting of a textured mesh and a sparse voxel grid, along with associated metadata for real-time rendering [S1, unofficial].

### Data Structures
1.  **Mesh**: Standard triangle mesh with appearance textures storing diffuse color and view-dependent features [S1, unofficial].
2.  **Sparse Voxel Grid**: Based on the multi-resolution hierarchical occupancy grid from SNeRG [S1, unofficial].
    *   **Occupancy Grid**: Binary mask images at multiple resolution levels created via max-pooling to mark occupied voxels [S1, unofficial].
    *   **Voxel Attributes**: Stored in a sparse structure to minimize memory usage [S1, unofficial].
3.  **Mesh-Occupancy Grid**: A grid used to filter spatial overlap between mesh and voxels; resolution $r_{mesh}$ is a hyperparameter [S1, unofficial].

### Algorithm Steps
1.  **Initial Voxel Training**: Train initial voxels using classic MSE loss to measure pixel-level color differences [S1, unofficial]. Use the same optimizer settings as MERF [S1, unofficial].
2.  **Mesh Refinement**: Perform meshing of the density field for 20,000 steps [S1, unofficial]. Set $premove$ to 0.9 (Vosh-Base) or 1.0 (Vosh-Light) [S1, unofficial]. Clean the mesh using operations similar to NeRF2Mesh [S1, unofficial]. Apply L2 regularization terms with rendering weights for background colors to encourage voxels to fill holes in the mesh [S1, unofficial]. Repeat mesh cleaning operations if messy floating faces are produced [S1, unofficial].
3.  **Hybrid Optimization and Rendering**: This stage combines rasterization and ray marching to ensure consistency between GPU training and web inference [S1, unofficial].
    *   **Calculate Mesh-Occupancy Grid**: Compute the occupancy grid of the meshes under training poses [S1, unofficial]. Filter out voxels located in the mesh-occupied grid areas during rendering and baking to prevent spatial overlap [S1, unofficial]. Adjust the ratio of sparse voxels by setting $r_{mesh}$ to suppress voxel density [S1, unofficial].
    *   **Rasterization Pass**: Uniformly shade the meshes [S1, unofficial]. The fragment shader samples appearance textures to incorporate diffuse color and view-dependent features [S1, unofficial]. Output diffuse color, view-dependent features, and a depth map [S1, unofficial].
    *   **Ray Marching Pass**: Use the multi-resolution hierarchical occupancy grid (from SNeRG) to create binary mask images via max-pooling [S1, unofficial]. Perform spatial skips during ray marching using these masks [S1, unofficial]. Reduce sampling distance using the depth map obtained from the rasterization pass [S1, unofficial].
    *   **Hybrid Combination**: For each spatial coordinate after ray marching, compare the transformed depth with the rasterization depth map to determine surface intersection [S1, unofficial]. If the ray reaches the mesh surface, stop marching [S1, unofficial]. Weightily combine the accumulated ray marching result with the appearance result from the rasterization pass [S1, unofficial]. If the ray does not hit the surface, continue marching or accumulate volume contribution as per standard volume rendering [G].
    *   **Loss Function**: Apply voxel pruning loss weighted by $\lambda_{voxel}$ [S1, unofficial]. For Vosh-Base, disable the binary mesh-occupancy grid [S1, unofficial].

### Formulas
*   **MSE Loss**: $\mathcal{L}_{MSE} = \frac{1}{N} \sum_{i=1}^{N} \| \mathbf{C}_{pred}^{(i)} - \mathbf{C}_{gt}^{(i)} \|^2$, where $\mathbf{C}_{pred}$ and $\mathbf{C}_{gt}$ are predicted and ground-truth pixel colors [S1, unofficial].
*   **L2 Regularization**: $\mathcal{L}_{L2} = \| \mathbf{w}_{bg} \|^2$, applied with rendering weights for background colors to encourage voxels to fill mesh holes [S1, unofficial].
*   **Voxel Pruning Loss**: $\mathcal{L}_{voxel} = \lambda_{voxel} \cdot \mathcal{L}_{pruning}$, where $\lambda_{voxel}$ limits volumetric density during ray marching [S1, unofficial].
*   **Weighty Combination**: $\mathbf{C}_{final} = \mathbf{C}_{vol} \cdot \alpha_{vol} + \mathbf{C}_{mesh} \cdot (1 - \alpha_{vol})$, where $\mathbf{C}_{vol}$ and $\mathbf{C}_{mesh}$ are accumulated ray marching and rasterization colors, and $\alpha_{vol}$ is the accumulated volume alpha [G].
*   *Note: Exact mathematical formulations for spatial skip scheduling and max-pooling mask generation are not given in the sources.*

### Parameters
*   $r_{mesh}$: Resolution of the mesh-occupancy grid. Set to 128 for Vosh-Light [S1, unofficial].
*   $\lambda_{voxel}$: Voxel pruning loss weight. Set to 0.001 for Vosh-Base and 0.01 for Vosh-Light [S1, unofficial].
*   $premove$: Parameter for mesh refinement stage. Set to 0.9 for Vosh-Base and 1.0 for Vosh-Light [S1, unofficial].
*   Marching Cubes Resolution: 1024 [S1, unofficial].
*   Optimizer: 25,000 steps, initial learning rate $1e-2$, warmup for 100 steps, decaying to $1e-3$ [S1, unofficial].

### Edge Cases and Pitfalls
*   **Mesh-Voxel Overlap**: Meshes and voxels may overlap at the same spatial location, affecting quality and asset volume; handled by filtering voxels in mesh-occupied grid areas [S1, unofficial].
*   **Floating Faces**: Meshing stage may produce messy floating faces; handled by repeating mesh cleaning operations and using L2 regularization with rendering weights for background colors to encourage voxels to fill mesh holes [S1, unofficial].
*   **Precision/Boundaries**: Depth comparison uses a tolerance threshold to determine surface intersection; standard volume rendering accumulation applies when no intersection is detected [G].

### Pseudocode
```python
import numpy as np

def vosh_render(camera, mesh, voxel_grid, mesh_occupancy_grid, depth_map_raster):
    """
    Renders a frame using Vosh hybrid representation.
    
    Args:
        camera: Object with .resolution (H, W), .max_distance, and .get_rays() method.
        mesh: Textured mesh object with .sample_appearance(u, v) method.
        voxel_grid: Sparse voxel grid with .is_occupied(ray, depth) and .sample(ray, depth) methods.
        mesh_occupancy_grid: Binary grid indicating mesh-occupied voxels.
        depth_map_raster: Depth map from the rasterization pass.
        
    Returns:
        color: Rendered pixel color array of shape (H, W, 3).
    """
    height, width = camera.resolution
    rays = camera.get_rays()
    accumulated_color = np.zeros((height, width, 3))
    epsilon = 1e-3
    step_size = 0.05
    skip_step = 0.2
    
    for v in range(height):
        for u in range(width):
            ray = rays[v, u]
            current_depth = 0.0
            ray_marching_accum = np.zeros(3)
            ray_marching_alpha = 0.0
            
            while current_depth < camera.max_distance:
                # Spatial skip using multi-resolution occupancy grid
                if not voxel_grid.is_occupied(ray, current_depth):
                    current_depth += skip_step
                    continue
                
                # Sample voxel density and color
                density, color = voxel_grid.sample(ray, current_depth)
                
                # Standard volume rendering accumulation
                alpha = 1.0 - np.exp(-density * step_size)
                ray_marching_accum += color * alpha * (1.0 - ray_marching_alpha)
                ray_marching_alpha += alpha * (1.0 - ray_marching_alpha)
                current_depth += step_size
                
                # Surface intersection check
                raster_depth = depth_map_raster[v, u]
                if abs(current_depth - raster_depth) < epsilon:
                    break
            
            # Rasterization appearance result
            mesh_color = mesh.sample_appearance(u, v)
            
            # Weighty combination based on surface hit
            if abs(current_depth - depth_map_raster[v, u]) < epsilon:
                accumulated_color[v, u] = ray_marching_accum * (1.0 - ray_marching_alpha) + mesh_color * ray_marching_alpha
            else:
                accumulated_color[v, u] = ray_marching_accum
                
    return accumulated_color

def vosh_train(mesh, voxel_grid, images, poses):
    """
    Trains the Vosh hybrid representation.
    """
    # Stage 1: Initial Voxel Training
    train_initial_voxels(voxel_grid, images, poses, loss_fn=MSE)
    
    # Stage 2: Mesh Refinement

    clean_mesh(mesh)
    apply_l2_regularization(voxel_grid, mesh, target='background_colors')
    
    # Stage 3: Hybrid Optimization
    for step in range(25000):
        # Calculate mesh-occupancy grid
        mesh_occupancy_grid = calculate_mesh_occupancy(mesh, poses)
        
        # Filter voxels in mesh-occupied areas
        voxel_grid.filter(mesh_occupancy_grid)
        
        # Render and compute loss
        rendered_images = vosh_render_all_views(mesh, voxel_grid, mesh_occupancy_grid, images, poses)
        loss = compute_loss(rendered_images, images)
        
        # Add voxel pruning loss
```

## Operating characteristics
*   **Training Time**: On a single NVIDIA RTX 4090, training takes approximately 66 minutes for initial voxels, 35 minutes for mesh refinement, and 58 minutes for Vosh optimization [S1, unofficial].
*   **Memory Usage**: Peak VRAM usage during training is ~11 GB [S1, unofficial].
*   **Storage**: Vosh-Base uses 506 MB VRAM and 488 MB disk; Vosh-Light uses 490 MB VRAM and 232 MB disk on Mip-NeRF 360 outdoor scenes [S1, unofficial].
*   **Performance**: Vosh achieves real-time rendering on mobile devices [S1, unofficial].
*   **Strengths**: Restores comprehensive scene information compared to SDF-based methods [S1, unofficial]. Can represent thin structures (e.g., fishing nets, ropes) that are difficult for SDFs [S1, unofficial]. Suitable for outdoor scenes where pure volume rendering is necessary [S1, unofficial].
*   **Limitations**: Slightly lower rendering quality in indoor scenes compared to MLP-based methods due to the use of a tiny view-dependent MLP [S1, unofficial]. Disk storage is slightly larger than MERF because it does not use triplane representation [S1, unofficial].
*   **When to Use**: When real-time rendering on mobile devices is required, and the scene contains thin structures or requires pure volume rendering (e.g., outdoor scenes) [S1, unofficial].
*   **When Not to Use**: When maximum indoor rendering quality is prioritized over speed, or when disk space is extremely constrained and MERF's triplane representation is acceptable [S1, unofficial].

## Background
Vosh (Voxel-Mesh Hybrid Representation) was introduced in the paper "Voxel-Mesh Hybrid Representation for Real-Time View Synthesis" [S1, unofficial]. The method builds on previous works such as SNeRG for sparse voxel storage [S1, unofficial], MERF for optimizer settings [S1, unofficial], and NeRF2Mesh for mesh cleaning [S1, unofficial]. It was developed to address the limitations of pure mesh or pure volume representations, particularly in the context of real-time view synthesis on mobile devices [S1, unofficial].
