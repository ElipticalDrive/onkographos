# NeRF-Editing

Also called: Geometry Editing of Neural Radiance Fields

## Overview
NeRF-Editing is a method that allows users to perform user-controlled shape deformation on the implicit representation of a scene (NeRF) and synthesizes novel view images of the edited scene without re-training the network [S1]. It is the first mesh-based shape deformation method, leveraging explicit representations for scene geometry edits and implicit representations for realistic rendering effects [S2]. Unlike EditingNeRF which is limited to color modification or removal of parts, and ObjectNeRF which only supports duplication, movement, or rotation, this method supports substantial shape deformation [S1].

## How it works
**Inputs:**
1. A trained NeRF model (implicit representation) of a scene [S1].
2. Multi-view images used to train the NeRF [S1].
3. User-defined deformation constraints on an extracted explicit mesh [S2].

**Outputs:**
1. Rendered images of the edited scene from novel viewpoints [S1].

**Data Structures:**
1. **Triangular Mesh ($M_{tri}$):** An explicit surface representation extracted from the NeRF [S1].
2. **Tetrahedral Mesh ($M_{tet}$):** A volumetric proxy mesh wrapping around $M_{tri}$, used to propagate deformations into the surrounding space [S1].
3. **Deformation Field ($D(x)$):** A continuous vector field defined over the volume, derived from the discrete deformations of $M_{tet}$ [S1].

**Algorithm Steps:**

1. **Extract Explicit Mesh:**
   Extract a triangular mesh representation ($M_{tri}$) from the trained NeRF [S1].

2. **User-Driven Deformation:**
   Users apply intuitive deformations to $M_{tri}$ using classic mesh deformation methods, such as As-Rigid-As-Possible (ARAP) deformation [S2]. Let the deformed mesh be $M'_{tri}$.

3. **Build Tetrahedral Proxy:**
   Construct a tetrahedral mesh ($M_{tet}$) that wraps around the original triangular mesh $M_{tri}$ [S1]. This mesh serves as a spatial proxy to propagate the surface deformation into the volume.

4. **Propagate Deformation to Tetrahedral Mesh:**
   Drive the deformation of $M_{tet}$ based on the deformation of $M'_{tri}$ [S1]. The vertices of $M_{tet}$ are displaced to reflect the geometric changes of the surface, creating a discrete deformation field [S1]. Let the deformed tetrahedral mesh be $M'_{tet}$.

5. **Interpolate to Continuous Deformation Field:**
   Use tetrahedral vertex interpolation to transform the discrete deformation field from $M'_{tet}$ into a continuous deformation field $D(x)$ defined for any point $x$ in 3D space [S1].
   * For a query point $x$ inside a tetrahedron $T$ with vertices $v_i$ and deformation vectors $d_i$, the deformation $D(x)$ is computed by interpolating $d_i$ using the barycentric coordinates of $x$ within $T$ [G].
   * Points outside $M_{tet}$ are assumed to have zero deformation [G].

6. **Ray Bending:**
   During rendering, camera rays passing through the tetrahedral mesh are bent according to the continuous deformation field $D(x)$ [S1]. Sampling positions along the ray are displaced by $D(x)$ to query the implicit NeRF at the deformed locations [G]. This ensures that the implicit NeRF is queried at locations corresponding to the deformed geometry, effectively "bending" the ray to match the user's edit [S1].

7. **Rendering:**
   Perform standard volume rendering integration along the bent rays. The NeRF decoder predicts density $\sigma$ and color $c$ at the sampled points, and the final color is computed via alpha compositing [G].

**Pseudocode:**

```python
import math

def nerf_editing_render(ray_origin, ray_direction, nerf_model, tet_mesh, deformation_field_func):
    """
    Renders a single ray for the edited scene.
    
    Args:
        ray_origin: 3D vector, origin of the camera ray.
        ray_direction: 3D vector, direction of the camera ray.
        nerf_model: Function that queries NeRF for (sigma, color) at a point.
        tet_mesh: List of tetrahedra, each containing vertices and deformation vectors.
        deformation_field_func: Function that returns deformation vector D(x) for any point x.
        
    Returns:
        color: 3D vector, the final rendered color.
    """
    t_min = 0.1
    t_max = 10.0
    num_samples = 128
    dt = (t_max - t_min) / (num_samples - 1)
    t_vals = [t_min + i * dt for i in range(num_samples)]
    points = [[ray_origin[j] + t * ray_direction[j] for j in range(3)] for t in t_vals]

    deformations = [[0.0, 0.0, 0.0] for _ in points]
    for i, p in enumerate(points):
        if is_inside_tet_mesh(p, tet_mesh):
            deformations[i] = deformation_field_func(p, tet_mesh)

    bent_points = [[points[i][j] + deformations[i][j] for j in range(3)] for i in range(num_samples)]

    sigmas = []
    colors = []
    for p in bent_points:
        sigma, c = nerf_model(p)
        sigmas.append(sigma)
        colors.append(c)

    alphas = [1.0 - math.exp(-s * dt) for s in sigmas]
    transmittances = [1.0]
    for i in range(1, num_samples):
        transmittances.append(transmittances[i-1] * (1.0 - alphas[i-1]))

    color = [0.0, 0.0, 0.0]
    for i in range(num_samples):
        weight = alphas[i] * transmittances[i]
        for j in range(3):
            color[j] += weight * colors[i][j]
    return color

def is_inside_tet_mesh(point, tet_mesh):
    for tet in tet_mesh:
        v0, v1, v2, v3 = tet.vertices
        vol = dot(v1-v0, cross(v2-v0, v3-v0))
        if vol == 0: continue
        w0 = dot(point-v1, cross(v2-v1, v3-v1)) / vol
        w1 = dot(point-v2, cross(v3-v2, v0-v2)) / vol
        w2 = dot(point-v3, cross(v0-v3, v1-v3)) / vol
        w3 = 1.0 - w0 - w1 - w2
        if 0.0 <= w0 <= 1.0 and 0.0 <= w1 <= 1.0 and 0.0 <= w2 <= 1.0 and 0.0 <= w3 <= 1.0:
            return True
    return False

def deformation_field_func(point, tet_mesh):
    for tet in tet_mesh:
        v0, v1, v2, v3 = tet.vertices
        d0, d1, d2, d3 = tet.deformations
        vol = dot(v1-v0, cross(v2-v0, v3-v0))
        if vol == 0: continue
        w0 = dot(point-v1, cross(v2-v1, v3-v1)) / vol
        w1 = dot(point-v2, cross(v3-v2, v0-v2)) / vol
        w2 = dot(point-v3, cross(v0-v3, v1-v3)) / vol
        w3 = 1.0 - w0 - w1 - w2
        return [w0*d0[j] + w1*d1[j] + w2*d2[j] + w3*d3[j] for j in range(3)]
    return [0.0, 0.0, 0.0]

def dot(a, b): return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]
def cross(a, b): return [a[1]*b[2]-a[2]*b[1], a[2]*b[0]-a[0]*b[2], a[0]*b[1]-a[1]*b[0]]
```

**Parameters:**
*   **Deformation Method:** ARAP (As-Rigid-As-Possible) is used for the initial mesh deformation [S2].
*   **Interpolation:** Tetrahedral vertex interpolation (barycentric interpolation) is used to create the continuous field [S1].

**Edge Cases and Pitfalls:**
*   **Artifacts from Direct Interpolation:** Directly transferring deformation from the surface mesh to the implicit volume by simple interpolation (without the tetrahedral proxy) leads to obvious artifacts [S1]. The two-step strategy using a tetrahedral proxy is necessary to avoid these [S1].
*   **Boundary Handling:** Points outside the tetrahedral mesh volume are assumed to have zero deformation [G]. This must be handled explicitly to prevent undefined behavior.
*   **Precision:** The quality of the continuous deformation field depends on the resolution of the tetrahedral mesh. Coarse tetrahedral meshes may result in blocky or inaccurate deformations [G].

## Operating characteristics
*   **Time Complexity:** The method requires no network re-training, making the editing phase fast [S1]. The rendering phase involves an additional interpolation step for the deformation field, adding minor overhead to standard NeRF rendering [G].
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Supports substantial shape deformation (not just color or rigid transforms); works on arbitrary shapes (animals, man-made objects), not limited to humans [S1]. Intuitive user control via mesh editing [S2].
*   **Limitations:** Requires an initial mesh extraction step, which can be noisy or incomplete for complex scenes [G]. The quality of deformation propagation depends on the tetrahedral mesh generation [S1].
*   **When to use:** When substantial geometric changes to a NeRF scene are required without re-training [S1].
*   **When not to use:** When only color or texture edits are needed (EditingNeRF is simpler); when rigid body transforms are sufficient (ObjectNeRF is simpler) [S1].

## Background
NeRF-Editing was proposed in 2022 [S1]. It is cited as the first mesh-based shape deformation method for NeRFs [S2]. It addresses the limitation of prior editing methods that were restricted to color modification, part removal, or rigid transformations (translation, rotation, scaling) [S1]. The method establishes a correspondence between an extracted explicit mesh and the implicit neural representation, allowing users to leverage well-developed mesh-based deformation tools [S1]. It is applicable to arbitrary shapes, including animal models and general man-made objects [S1].
