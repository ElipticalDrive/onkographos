# SVRecon

Also called: SVRaster with Signed Distance Functions

## Overview
SVRecon is a surface reconstruction method that generalizes SVRaster by parametrizing each voxel with Signed Distance Function (SDF) values at its corners, enabling implicit geometry regularization and the extraction of watertight meshes [S1, unofficial]. It addresses the limitation of SVRaster’s density-based representation, which lacks explicit geometric priors and suffers from depth bias, by introducing SDF-based continuity enforcement [S1, unofficial]. Unlike 3D Gaussian Splatting (3DGS) approaches that rely heavily on initial Structure-from-Motion (SfM) points, SVRecon exploits monocular depth cues more effectively without this dependency, producing sharper boundaries and smoother, hole-free surfaces [S1, unofficial].

## How it works
**Inputs:** Sparse voxel grid (initialized via PI³ point-map priors aligned to ground-truth poses), RGB images, and camera poses.
**Outputs:** Watertight mesh extracted from the optimized SDF field.

**Data Structures:**
*   **Voxel:** Identified by index $v = \{i, j, k\}$ at Octree level $l$.
*   **SDF Values:** Each voxel stores SDF values at its eight corners. Let $S_8$ denote the SDF value at a corner.
*   **Hierarchical Indices:** Parent–child and sibling relations are tracked via Morton codes and auxiliary fine-grid indices. Bitmask-based occupancy and neighbor search schemes are used for cross-voxel Laplacian smoothness [S1, unofficial].

**Steps:**

1.  **Initialization:** Initialize the sparse voxel grid using PI³ point-map priors aligned to ground-truth poses. Flip SDF signs to account for visual occlusion [S1, unofficial].
2.  **Trilinear Interpolation:** For a ray passing through voxel $S_7$, compute the SDF $S_8$ at the intersection point using trilinear interpolation of the corner SDF values $S_9$ [S1, unofficial].
3.  **Alpha Blending:** Compute the accumulated color and opacity using the NeuS Cumulative Distribution Function (CDF) [S1, unofficial]. The NeuS CDF is defined as:
    $$
    T(t) = \exp\left(-\sum_{i=1}^{t-1} \sigma_i \delta_i\right)
    $$
    where $\sigma_i$ is the density and $\delta_i$ is the distance between samples [S1, unofficial].
4.  **Regularization:** Apply a combination of losses:
    *   Parent–child continuity loss.
    *   Laplacian loss over fine grid cells.
    *   Local Eikonal terms enforcing $|\nabla SDF| = 1$ [S1, unofficial].

**Pseudocode:**

```python
def svrecon_forward(voxel_grid, ray_origin, ray_direction):
    """
    Renders a ray using SVRecon's SDF-based trilinear interpolation and NeuS alpha blending.
    """
    # 1. Traverse sparse voxel grid to find intersections
    # Returns list of (voxel_index, t_start, t_end) along the ray
    intersections = traverse_sparse_voxel_grid(voxel_grid, ray_origin, ray_direction)
    
    accumulated_color = [0.0, 0.0, 0.0]
    accumulated_alpha = 0.0
    transmittance = 1.0
    
    for voxel_idx, t_start, t_end in intersections:
        # 2. Trilinear Interpolation of SDF
        # Get corner SDF values for the voxel
        sdf_corners = get_voxel_sdf_corners(voxel_grid, voxel_idx)
        
        # Compute SDF at current ray position t
        # Note: In practice, multiple samples are taken within the voxel segment
        # For simplicity, we assume a single sample at the midpoint or use standard ray marching steps
        t_mid = (t_start + t_end) / 2.0
        sdf_val = trilinear_interpolate_sdf(sdf_corners, ray_origin, ray_direction, t_mid)
        
        # Convert SDF to density for NeuS CDF
        # Standard NeuS conversion: sigma = max(0, -grad_SDF * (SDF - threshold))
        # Or simpler: sigma = max(0, -SDF) * scale_factor
        # The source cites NeuS CDF but does not provide the exact sigma conversion formula.
        # We assume a standard softplus or linear conversion for implementation [G].
        sigma = max(0.0, -sdf_val) * 10.0  # [G] Heuristic scale factor
        
        delta = t_end - t_start
        
        # 3. Alpha Blending using NeuS CDF
        alpha = 1.0 - exp(-sigma * delta)
        
        # Get voxel color (from SH coefficients or stored color)
        color = get_voxel_color(voxel_grid, voxel_idx)
        
        # Composite
        weight = transmittance * alpha
        accumulated_color += weight * color
        accumulated_alpha += weight
        transmittance *= (1.0 - alpha)
        
        if transmittance < 1e-5:
            break
            
    return accumulated_color, accumulated_alpha

def trilinear_interpolate_sdf(corners, origin, direction, t):
    """
    Interpolates SDF value at point P = origin + t * direction
    using the 8 corner SDF values of the voxel containing P.
    """
    # Determine local coordinates (u, v, w) in [0, 1] within the voxel
    # This requires knowing the voxel's world-space bounds
    # For brevity, assuming helper function exists
    u, v, w = get_local_coords(corners, origin, direction, t)
    
    c000 = corners[0] # (0,0,0)
    c100 = corners[1] # (1,0,0)
    c010 = corners[2] # (0,1,0)
    c110 = corners[3] # (1,1,0)
    c001 = corners[4] # (0,0,1)
    c101 = corners[5] # (1,0,1)
    c011 = corners[6] # (0,1,1)
    c111 = corners[7] # (1,1,1)
    
    # Trilinear interpolation formula
    # I(u,v,w) = (1-u)(1-v)(1-w)C000 + u(1-v)(1-w)C100 + ...
    term0 = (1-u)*(1-v)*(1-w)*c000
    term1 = u*(1-v)*(1-w)*c100
    term2 = (1-u)*v*(1-w)*c010
    term3 = u*v*(1-w)*c110
    term4 = (1-u)*(1-v)*w*c001
    term5 = u*(1-v)*w*c101
    term6 = (1-u)*v*w*c011
    term7 = u*v*w*c111
    
    return term0 + term1 + term2 + term3 + term4 + term5 + term6 + term7
```

**Parameters:**
*   **Octree Level ($l$):** Determines voxel size $v_s = w_s \times 2^{-l}$ [S2].
*   **Regularization Weights:** Not given in the sources. Typical values for Laplacian and Eikonal losses are not specified [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **SDF Sign Flipping:** SDF signs must be flipped to account for visual occlusion during initialization [S1, unofficial].
*   **Continuity Enforcement:** Due to spatially-disjoint voxels, explicit cross-voxel continuity enforcement is required to avoid artifacts [S1, unofficial].
*   **Depth Quantile Pruning:** Depends on robust view coverage; pathological voids or highly non-uniform depth distributions may impact bin estimation [S1, unofficial].

## Subtopics

### [Sparse Voxel Surface Regularization](15691-sparse-voxel-surface-regularization.md)
SVSR is a set of geometric refinement techniques applied to sparse voxel representations to enforce global geometry consistency and eliminate depth bias during surface reconstruction. It addresses the limitation of extreme voxel locality, which makes plane-based regularization ineffective for enforcing regional constraints, by introducing voxel dropout, surface rectification, and scaling penalties. Unlike 3D Gaussian Splatting (3DGS) approaches such as PGSR, which rely heavily on initial Structure-from-Motion (SfM) points and struggle in challenging areas, SVSR exploits monocular depth cues more effectively without this dependency.

### GeoSVR
GeoSVR is an explicit voxel-based framework for accurate, detailed, and complete surface reconstruction that tames sparse voxels to enable delicate geometry learning, addressing representational bottlenecks of Gaussian Splatting and geometric distortion in vanilla SVRaster [S2]. It starts with fully covered coarse sparse voxels, constantly optimized with RGB images [S2]. Key steps include:
1.  **Voxel-Uncertainty Depth Constraint:** Enforces correct scene convergence while avoiding accuracy degradation by evaluating geometric uncertainty to determine the degree of reliance on monocular depth cues [S2].
2.  **Voxel Dropout:** Enlarges global geometry consistency for tiny voxels during explicit geometry regularization [S2].
3.  **Voxel Regularization:** Aligns the voxel-level density field to the surfaces, facilitating accurate and sharp surface formation [S2].

## Operating characteristics
**Time and Memory Complexity:**
*   SVRaster achieves over 10× speedup compared to uniform-grid ray casting and neural-free voxel methods [S1, unofficial].
*   On MipNeRF-360, SVRaster yields ccc3 FPS (versus ccc4 for instant-NGP-style) and PSNR ≈ 27 dB after 12 minutes of training [S1, unofficial].
*   LiteVoxel matches SVRaster’s perceptual quality at 40–60% of peak VRAM, with less than 1% loss in PSNR, SSIM, or LPIPS [S1, unofficial].

**Measured Performance:**
*   **DTU (15 scenes):** SVRecon achieves a Chamfer distance of ccc5 mm (versus ccc6 mm for SVRaster density) [S1, unofficial].
*   **Tanks-and-Temples:** SVRecon achieves an F1 score of ccc7 in 12 minutes (versus ccc8 for SVRaster) [S1, unofficial].
*   Surfaces are smoother and more hole-free, with robust convergence [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Sharp boundaries, watertight mesh extraction, robust convergence, lower VRAM usage compared to dense grids [S1, unofficial].
*   **Limitations:** Resolution-memory trade-offs become pronounced at deep LoDs. Disjoint voxel design necessitates explicit continuity losses [S1, unofficial].

**When to Use:**
*   When watertight mesh extraction is required.
*   When high geometric accuracy and smooth surfaces are prioritized over raw density-based rendering.
*   When VRAM is constrained (using LiteVoxel variant).

**When Not to Use:**
*   When only density-based rendering is needed (SVRaster may be simpler).
*   In scenes with pathological voids or highly non-uniform depth distributions, where depth-quantile pruning may fail [S1, unofficial].

## Background
SVRecon was introduced as a generalization of SVRaster to surface reconstruction by parametrizing each voxel with SDF values at its corners [S1, unofficial]. It builds on the sparse voxel rasterization framework, which was proposed to efficiently refine scenes via level of details [S2]. The method leverages hierarchical data structures (Morton codes, auxiliary fine-grid indices) to manage parent–child and sibling relations, enabling efficient neighbor searches for regularization [S1, unofficial]. It is compatible with grid-based algorithms such as Volume Fusion, Voxel Pooling, Marching Cubes, and classic sparse-convolution toolchains (fVDB, sparse-convnet) [S1, unofficial].
