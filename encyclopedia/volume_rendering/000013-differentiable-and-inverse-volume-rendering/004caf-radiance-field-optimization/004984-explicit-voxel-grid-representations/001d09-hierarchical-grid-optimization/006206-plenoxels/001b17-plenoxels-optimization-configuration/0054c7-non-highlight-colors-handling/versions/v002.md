# Non-highlight colors handling

Also called: Low-frequency view-dependent function, Per-voxel environment map

## Overview
This method addresses the shape-radiance ambiguity in view-dependent radiance fields by distinguishing surface points from arbitrary volume points using a low-frequency approximation of outgoing radiance [S1, unofficial]. Unlike standard Plenoxels which may struggle with complex view-dependent lighting that lacks clear Lambertian components, this technique assigns a small per-voxel environment map to capture low-frequency view dependence, thereby improving geometry reconstruction [S1, unofficial]. It sets itself apart by integrating a Cauchy loss weighted by the error of this low-frequency approximation into the optimization framework [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A hierarchical voxel grid where each voxel has an associated density $\sigma$. Camera poses and colors are available for ray marching.
*   **Outputs:** A buffer of weights $w$ (one float per voxel) representing the error cost, which is used to modulate the Cauchy loss during optimization.

**Data Structures:**
*   **Per-voxel Environment Map:** Each voxel stores a small environment map of size $8 \times 4$ pixels [S1, unofficial]. This map represents a low-frequency view-dependent function [S1, unofficial].
*   **Weight Buffer:** A buffer storing one float per voxel, containing the pre-computed error cost $w$ [S1, unofficial].

**Parameters:**
*   $\lambda_c$: Controls the overall loss magnitude. Value is $0.05$ for artificial scenes and $0.01$ for real scenes [S1, unofficial].
*   $\lambda_n$: Controls the weight of the cost function in the Cauchy loss. Value is $10$ for both artificial and real scenes [S1, unofficial].

**Steps:**
1.  **Population of View-Dependent Function:** For each voxel, populate its $8 \times 4$ environment map by iterating over all cameras. Project the voxel to the camera, trace visibility, map to spherical coordinates $(\theta, \phi)$, and accumulate the projected color weighted by visibility into the environment map bin. Sum the total visibility [S1, unofficial].
2.  **Normalization:** Normalize the environment map by dividing each bin by the total visibility sum $T_{sum}$ over all spherical coordinates $\theta \in [0, \pi]$ and $\phi \in [-\pi, \pi]$ [S1, unofficial].
3.  **Error Calculation:** Calculate the error $E$ for the voxel by comparing the reference color in each camera with the color predicted by the environment map for the corresponding direction, weighted by visibility [S1, unofficial].
4.  **Weight Storage:** Store the resulting error cost $w$ (derived from $E$) in a buffer. This step is executed once at the beginning of each hierarchical level, except the first [S1, unofficial].
5.  **Loss Evaluation:** In each optimization iteration, evaluate the Cauchy loss using the pre-computed weights $w$ from the buffer [S1, unofficial].

**Formulas:**
The error $E$ for a voxel is calculated as [S1, unofficial]:
$$ E = \sum_{k} \frac{1}{X} \sum_{i} T_k (c_i - p_i)^2 $$
where:
*   $k$ indexes the cameras.
*   $i$ indexes the color channels.
*   $X$ is a normalization factor (implied by the summation structure, likely related to the number of samples or channels, though exact definition of $X$ is not explicitly detailed beyond its presence in the formula [S1, unofficial]).
*   $T_k$ is the visibility to camera $k$.
*   $c_i$ is the reference color in camera $k$ for channel $i$.
*   $p_i$ is the predicted color from the environment map for the corresponding direction and channel $i$.

The weight $w$ is derived from this error $E$ [S1, unofficial].

The Cauchy loss $L_c$ is defined as [S1, unofficial]:
$$ L_c = \lambda_c \sum_{i} \log(1 + \lambda_n w \sigma_i^2) $$
where:
*   $\sigma_i$ is the density for voxel $i$.
*   $w$ is the error cost from the environment map evaluation.
*   $\lambda_c$ and $\lambda_n$ are the parameters defined above.

**Pseudocode:**

```python
def populate_voxel_env_map(voxel, cameras, env_map_size=(8, 4)):
    """
    Populates the 8x4 environment map for a single voxel.
    Returns the normalized environment map and the total visibility sum.
    """
    env_map = zeros(env_map_size)
    T_sum = 0.0
    
    for camera in cameras:
        # Project voxel to camera space
        p = project_voxel_to_camera(voxel, camera)
        
        # Trace visibility from camera to voxel
        T = trace_visibility(voxel, camera)
        
        # Map voxel direction to spherical coordinates (theta, phi)
        theta, phi = map_to_spherical_coordinates(voxel, camera)
        
        # Map spherical coordinates to env map indices
        # Assuming uniform sampling over [0, pi] for theta and [-pi, pi] for phi
        # and env_map_size is (8, 4)
        # Note: Exact mapping logic (e.g., scaling) is not specified, 
        # but typically involves normalizing theta and phi to [0, 1] and scaling to indices.
        # [G] Assuming a standard equirectangular-like projection mapping:
        u = int((phi + pi) / (2 * pi) * env_map_size[1])
        v = int(theta / pi * env_map_size[0])
        
        # Clamp indices to valid range
        u = clamp(u, 0, env_map_size[1] - 1)
        v = clamp(v, 0, env_map_size[0] - 1)
        
        # Accumulate color weighted by visibility
        env_map[v, u] += T * p.color
        
        T_sum += T
        
    # Normalize the environment map
    if T_sum > 0:
        env_map = env_map / T_sum
        
    return env_map, T_sum

def calculate_error(env_map, cameras, voxel):
    """
    Calculates the error E for a voxel based on its environment map.
    """
    error_sum = 0.0
    total_samples = 0
    
    for camera in cameras:
        # Project voxel to camera space to get direction
        p = project_voxel_to_camera(voxel, camera)
        
        # Trace visibility
        T_k = trace_visibility(voxel, camera)
        
        # Get reference color
        c_i = camera.get_color_at_projection(p)
        
        # Get predicted color from environment map
        theta, phi = map_to_spherical_coordinates(voxel, camera)
        u = int((phi + pi) / (2 * pi) * env_map.shape[1])
        v = int(theta / pi * env_map.shape[0])
        u = clamp(u, 0, env_map.shape[1] - 1)
        v = clamp(v, 0, env_map.shape[0] - 1)
        
        p_i = env_map[v, u]
        
        # Calculate squared error weighted by visibility
        # Note: The formula includes 1/X. X is not explicitly defined.
        # [G] Assuming X is the number of color channels or a normalization constant.
        # For implementation, we sum the weighted squared errors.
        error_sum += T_k * sum((c_i - p_i) ** 2)
        total_samples += 1 # Or number of channels, depending on X definition
        
    # Apply 1/X factor if X is known. If X is total samples, this averages.
    # The source formula is E = sum_k (1/X) sum_i T_k (c_i - p_i)^2
    # If X is a constant normalization factor, it should be applied.
    # [G] Without explicit X, we return the sum. If X is needed, it must be provided.
    # Assuming X is a global constant or derived from scene properties.
    # For now, we return the sum as the basis for w.
    return error_sum

def compute_cauchy_loss(voxel_densities, weights, lambda_c, lambda_n):
    """
    Computes the Cauchy loss L_c using pre-computed weights.
    """
    loss = 0.0
    for i, sigma_i in enumerate(voxel_densities):
        w = weights[i]
        loss += log(1 + lambda_n * w * sigma_i ** 2)
    return lambda_c * loss
```

**Edge Cases and Pitfalls:**
*   **Empty Space:** The method is often combined with auxiliary terms to skip empty space using hierarchical formulation to ease computational impact [S1, unofficial].
*   **Visibility Tracing:** Accurate visibility tracing is crucial for populating the environment map correctly. Incorrect visibility can lead to erroneous color accumulation [S1, unofficial].
*   **Spherical Mapping:** The mapping from 3D direction to 2D environment map indices must be consistent between population and evaluation steps [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The population step (Algorithm 1) is executed once per hierarchical level (except the first) for all voxels and cameras. This involves ray marching and spherical mapping for each voxel-camera pair. The loss evaluation is per iteration and per voxel.
*   **Memory Complexity:** Each voxel stores an $8 \times 4$ environment map (32 floats, assuming RGB or similar) plus the weight buffer (1 float per voxel). This adds memory overhead compared to standard Plenoxels.
*   **Performance:** The method was tested on artificial and real scenes (Tanks and Temples) using a Nvidia GTX 1080. Reconstruction times were compared to baseline PERF, showing the computational impact of the additional steps [S1, unofficial].
*   **Strengths:** Improves geometry reconstruction by distinguishing surface points from volume points, especially for view-dependent lighting without clear Lambertian components [S1, unofficial].
*   **Limitations:** Adds computational overhead due to the population step and storage of environment maps per voxel.

## Background
This technique was introduced in the paper "Addressing the Shape-Radiance Ambiguity in View-Dependent Radiance Fields" [S1, unofficial]. It builds upon the Plenoxels framework [3] and SnerG [29] by adding a low-frequency view-dependent function per voxel to handle non-highlight colors. The method aims to improve 3D reconstruction quality by leveraging the fact that a low-resolution function approximating outgoing radiance is more likely to correspond to a surface point than an arbitrary volume point [S1, unofficial].
