# Non-highlight colors handling

Also called: Low-frequency view-dependent function, Per-voxel environment map

## Overview
Non-highlight colors handling is a technique used in radiance-field optimization to distinguish surface points from arbitrary volume points by modeling view-dependent lighting that lacks a clear Lambertian or sharp highlight component [S1, unofficial]. It sets itself apart from sibling methods like [Plenoxels](8054-plenoxel.md) by replacing explicit high-frequency view-dependent storage with a per-voxel low-frequency approximation, thereby reducing memory overhead while improving geometry reconstruction [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A hierarchical voxel grid where each voxel $v$ has an associated density $\sigma$. A set of calibrated cameras $C$ with known poses and intrinsics.
*   **Outputs:** A scalar weight $w$ per voxel, representing the error cost of the low-frequency approximation, used to modulate the Cauchy loss during optimization.

**Data Structures:**
*   **Per-voxel Environment Map:** Each voxel stores a small environment map of size $8 \times 4$ pixels [S1, unofficial]. This map represents a low-frequency view-dependent function.
*   **Weight Buffer:** A buffer storing one float per voxel, holding the pre-computed error cost $w$ [S1, unofficial].

**Algorithm Steps:**
The method is executed once at the beginning of each hierarchical level (except the first) [S1, unofficial].

1.  **Populate Environment Map:** For each voxel $v$:
    *   Initialize the environment map bins to zero and a visibility sum $T_{sum} = 0$.
    *   Iterate over all cameras $c \in C$:
        *   Project the voxel center to the camera image plane to get pixel coordinates $p$ [S1, unofficial].
        *   Trace visibility $T$ from the camera to the voxel through the volume (ray-marching) [S1, unofficial].
        *   Map the viewing direction to spherical coordinates $(\theta, \phi)$, where $\theta \in [0, \pi]$ and $\phi \in [-\pi, \pi]$ [S1, unofficial].
        *   Accumulate the projected color $c_i$ (from camera $c$) weighted by visibility into the corresponding environment map bin: $env\_map(\theta, \phi) \leftarrow env\_map(\theta, \phi) + T \cdot c_i$ [S1, unofficial].
        *   Update total visibility: $T_{sum} \leftarrow T_{sum} + T$ [S1, unofficial].
    *   Normalize the environment map: For each bin $(\theta, \phi)$, divide by $T_{sum}$: $env\_map(\theta, \phi) \leftarrow env\_map(\theta, \phi) / T_{sum}$ [S1, unofficial].

2.  **Compute Error Cost ($w$):**
    *   Calculate the squared error between the reference color $c_i$ in each camera $k$ and the predicted color $p_i$ retrieved from the normalized environment map for the corresponding direction [S1, unofficial].
    *   The error $E$ is computed as:
        $$ E = \sum_{k} \frac{1}{X} \sum_{i} T_k (c_i - p_i)^2 $$
        where $k$ indexes cameras, $i$ indexes color channels, $T_k$ is the visibility to camera $k$, $c_i$ is the reference color, and $p_i$ is the predicted color from the environment map [S1, unofficial].
    *   The resulting scalar $E$ serves as the weight $w$ for the voxel [S1, unofficial].

3.  **Store Weights:** Store $w$ in the weight buffer [S1, unofficial].

4.  **Optimization Loss:** In each optimization iteration, use the stored weights $w$ to compute the Cauchy loss $L_c$ [S1, unofficial]:
    $$ L_c = \lambda_c \sum_{i} \log(1 + \lambda_n w \sigma_i^2) $$
    where $\sigma_i$ is the density of voxel $i$, $\lambda_c$ controls the overall loss, and $\lambda_n$ controls the weight of the cost function [S1, unofficial]. This loss is differentiable and implemented as a residual per density value in the non-linear least squares framework [S1, unofficial].

**Pseudocode:**
```python
def populate_voxel_env_map(voxel, cameras):
    """
    Populates the 8x4 environment map for a single voxel.
    Returns the normalized environment map and the total visibility sum.
    """
    env_map = zeros((8, 4))  # 8x4 pixels
    T_sum = 0.0
    
    for camera in cameras:
        # Project voxel to camera image plane
        p = project(voxel.center, camera)
        
        # Trace visibility from camera to voxel
        T = trace_visibility(camera, voxel)
        
        # Map viewing direction to spherical coordinates
        # theta in [0, pi], phi in [-pi, pi]
        theta, phi = map_to_spherical(voxel.center, camera)
        
        # Map spherical coordinates to env_map indices
        # Assuming linear mapping from [0, pi] x [-pi, pi] to [0, 8) x [0, 4)
        idx_theta = int(theta / pi * 8)
        idx_phi = int((phi + pi) / (2 * pi) * 4)
        
        # Clamp indices to valid range [0, 7] and [0, 3]
        idx_theta = clamp(idx_theta, 0, 7)
        idx_phi = clamp(idx_phi, 0, 3)
        
        # Get reference color from camera at pixel p
        # Note: In practice, this requires ray-casting or sampling the camera image
        c_i = get_camera_color(camera, p)
        
        # Accumulate weighted color
        env_map[idx_theta, idx_phi] += T * c_i
        
        # Accumulate visibility
        T_sum += T
        
    # Normalize
    if T_sum > 0:
        env_map = env_map / T_sum
        
    return env_map, T_sum

        idx_theta = clamp(idx_theta, 0, 7)
        idx_phi = clamp(idx_phi, 0, 3)
        
        p_i = env_map[idx_theta, idx_phi]

def compute_cauchy_loss(voxel_density, weight_buffer, lambda_c, lambda_n):
    """
    Computes the Cauchy loss for a voxel given its density and pre-computed weight.
    """
    sigma = voxel_density
    w = weight_buffer[voxel_id]
    
    # L_c = lambda_c * sum(log(1 + lambda_n * w * sigma^2))
    # For a single voxel, this is just the term for that voxel.
    loss = lambda_c * log(1 + lambda_n * w * sigma ** 2)
    return loss
```

**Parameters:**
*   $\lambda_c = 0.05$ for artificial scenes [S1, unofficial].
*   $\lambda_c = 0.01$ for real scenes [S1, unofficial].
*   $\lambda_n = 10$ for both artificial and real scenes [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Empty Space:** The method is computationally expensive due to ray-marching for every voxel. Auxiliary terms are used to skip empty space using the hierarchical formulation [S1, unofficial].
*   **Visibility Tracing:** Accurate visibility tracing is crucial for correct weighting. Incorrect visibility leads to incorrect environment map normalization.
*   **Spherical Mapping:** The mapping from viewing direction to $8 \times 4$ pixels must be consistent. Degenerate cases (e.g., voxel at camera center) should be handled.

## Background
This technique was introduced in the paper "Addressing the Shape-Radiance Ambiguity in View-Dependent Radiance Fields" to address the ambiguity between shape and radiance in view-dependent radiance fields [S1, unofficial]. It builds on the PERF framework and Plenoxels, aiming to handle view-dependent lighting that does not behave like a sharp highlight [S1, unofficial].
