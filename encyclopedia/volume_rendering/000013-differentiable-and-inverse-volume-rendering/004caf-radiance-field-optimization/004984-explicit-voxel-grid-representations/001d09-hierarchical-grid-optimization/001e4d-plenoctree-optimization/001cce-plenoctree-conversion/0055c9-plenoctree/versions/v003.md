# PlenOctree


## Overview
PlenOctree is a sparse octree-based 3D representation that enables real-time rendering of Neural Radiance Fields (NeRFs) by pre-tabulating view-dependent radiance into a voxel grid [S2, unofficial]. It solves the performance bottleneck of conventional NeRFs, which require dense sampling and neural network inference for every ray step dependent on viewing direction [S2, unofficial]. Unlike naive NeRF rendering, PlenOctrees remove the need for neural network queries at test time by storing precomputed spherical harmonic (SH) coefficients for density and color, achieving inference speeds approximately 3000 times faster than the original NeRF implementation [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A trained NeRF-SH model (an MLP that predicts density $\sigma$ and spherical harmonic coefficients for color) or a standard NeRF model [S1].
*   **Output:** A sparse octree data structure where leaves store density and SH coefficients, enabling real-time volume rendering [S2, unofficial].

**Data Structures:**
The representation is a sparse voxel-based octree [S2, unofficial].
*   **Internal Nodes:** Standard octree pointers indicating the presence of children.
*   **Leaf Nodes:** Store two values:
    1.  Density $\sigma$ (scalar).
    2.  Spherical Harmonic coefficients for color (vector). The number of coefficients depends on the SH degree used during training (e.g., degree 3 yields 16 coefficients per color channel) [S1].

**Method Steps:**

1.  **Train NeRF-SH:** Train a standard NeRF MLP to predict density $\sigma$ and SH coefficients $\mathbf{c}$ instead of direct RGB color values. The color function $c(\mathbf{r})$ for a ray direction $\mathbf{r} = (\theta, \phi)$ is computed as the inner product of the SH basis functions $Y(\mathbf{r})$ and the coefficients $\mathbf{c}$:
    $$ c(\mathbf{r}) = \sum_{l=0}^{L} \sum_{m=-l}^{l} c_{l,m} Y_{l,m}(\theta, \phi) $$
    where $L$ is the SH degree [S2, unofficial].

2.  **Voxelization and Sampling:** Densely sample the NeRF-SH model in the volume around the target object to tabulate density and SH coefficients [S2, unofficial]. This involves evaluating the MLP at grid points to populate the initial octree leaves [S2, unofficial].

3.  **Pruning:** Eliminate voxels with low transmissivity (or low density) to create a sparse representation. This step reduces memory usage and allows the volume renderer to skip empty space during ray marching [S1].

4.  **Fine-tuning (Optional):** Optimize the values stored in the PlenOctree directly using the initial training images. This differentiable optimization improves rendering quality by correcting errors introduced during the tabulation and pruning process [S1][S2, unofficial].

**Pseudocode:**

```python
def build_plenoctree(nerf_sh_model, scene_bounds, resolution, sh_degree, pruning_threshold):
    """
    Constructs a PlenOctree from a trained NeRF-SH model.
    
    Args:
        nerf_sh_model: Trained MLP predicting density and SH coefficients.
        scene_bounds: Bounding box of the scene.
        resolution: Grid resolution for initial sampling.
        sh_degree: Degree of spherical harmonics.
        pruning_threshold: Density threshold for voxel pruning.
        
    Returns:
        octree: Sparse octree structure with leaves containing density and SH coeffs.
    """
    # Step 1: Dense sampling to populate initial grid
    grid = initialize_dense_grid(scene_bounds, resolution)
    
    for voxel in grid:
        # Evaluate NeRF-SH at voxel center
        density, sh_coeffs = nerf_sh_model(voxel.center)
        
        # Store in grid
        voxel.density = density
        voxel.sh_coeffs = sh_coeffs
        
    # Step 2: Convert to sparse octree and prune
    octree = convert_to_octree(grid)
    
    for leaf in octree.leaves():
        if leaf.density < pruning_threshold:
            octree.remove(leaf)
            
    return octree

def render_plenoctree(octree, camera):
    """
    Renders an image using the PlenOctree via volume rendering.
    """
    image = zeros(camera.resolution)
    
    for pixel in camera.rays():
        color = 0.0
        transmittance = 1.0
        
        # Ray march through octree
        for sample in octree.ray_march(pixel):
            if sample is empty:
                continue
                
            # Retrieve precomputed SH coefficients
            sh_coeffs = sample.sh_coeffs
            
            # Compute view-dependent color from SH coefficients
            # Y(theta, phi) are the spherical harmonic basis functions
            color_sample = dot(sh_coeffs, Y(sample.direction))
            
            # Volume rendering accumulation
            alpha = 1.0 - exp(-sample.density * sample.distance)
            weight = transmittance * alpha
            color += weight * color_sample
            transmittance *= (1.0 - alpha)
            
        image[pixel] = color
        
    return image
```

**Edge Cases and Pitfalls:**
*   **SH Degree Selection:** Higher SH degrees capture more complex view-dependent effects (e.g., specularities) but increase memory usage per leaf. The sources do not specify the optimal degree for all scenes, but note that degree 3 is commonly used [S2, unofficial].
*   **Pruning Threshold:** Setting the pruning threshold too high may remove visible details; setting it too low retains unnecessary voxels, reducing performance. The sources mention "low transmissivity" but do not provide a specific numerical value [S1].
*   **Standard NeRF Conversion:** If starting from a standard NeRF (not NeRF-SH), Monte Carlo estimation is required to approximate the SH coefficients from the MLP's color outputs. This adds complexity and potential noise [S1].

## Operating characteristics
*   **Performance:** Renders 800x800 images at 167.68 FPS on an NVIDIA V100 GPU, which is over 3000 times faster than conventional NeRFs (approx. 30 seconds per image) [S2, unofficial].
*   **Memory:** Memory usage is reduced by using a sparse octree structure and pruning empty voxels. The exact memory footprint depends on the scene complexity and SH degree, but it is significantly lower than dense grid-based methods like Instant NGP for high-resolution scenes [S2, unofficial].
*   **Strengths:** Real-time rendering capability; preserves view-dependent effects (specularities) via SH; compatible with web technologies for browser-based interactive rendering [S2, unofficial].
*   **Limitations:** Requires an initial training phase (NeRF-SH) which is slower than training a standard NeRF; quality depends on the SH degree and pruning threshold; not suitable for dynamic scenes without retraining [S1][S2, unofficial].
*   **When to use:** When real-time or interactive rendering of static scenes with complex view-dependent effects is required.
*   **When not to use:** For dynamic scenes, or when training time is a critical constraint and offline rendering is acceptable.

## Background
PlenOctrees were introduced by Alex Yu et al. from UC Berkeley in March 2021 [S2, unofficial]. The method is named after plenoptic functions, referencing the work of Adelson and Bergen [S2, unofficial]. It was developed concurrently with other real-time NeRF acceleration methods such as FastNeRF and KiloNeRF [S1]. The approach has influenced subsequent work, including the adaptation of spherical harmonics in Gaussian Splatting [S1].
