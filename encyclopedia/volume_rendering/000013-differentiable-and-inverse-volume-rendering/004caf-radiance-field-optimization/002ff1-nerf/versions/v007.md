# NeRF++


## Overview
NeRF++ generates novel views for unbounded scenes by separating the scene into a foreground (inside a unit sphere) and a background (outside the sphere) using two separate Neural Radiance Field (NeRF) models [S1]. It solves the parameterization failure of standard NeRF, which assumes the entire scene fits within a bounded volume, leading to missing background elements or loss of detail due to limited sampling resolution in large-scale scenes [S1]. It sets itself apart from its parent [Radiance-field optimization](44-radiance-field-optimization.md) by explicitly handling infinite depth via radial inversion [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ RGB images $\{I_i\}_{i=1}^N$ [S1].
*   **Outputs:** Two NeRF models: $F_{in}$ for the interior volume and $F_{out}$ for the exterior volume, enabling novel view synthesis [S1].

**Data Structures:**
1.  **Scene Partitioning:** The 3D space is divided by a unit sphere centered at the origin [S1].
    *   **Interior:** Points $\mathbf{x}$ where $\|\mathbf{x}\| \le 1$.
    *   **Exterior:** Points $\mathbf{x}$ where $\|\mathbf{x}\| > 1$.
2.  **NeRF Models:**
    *   $F_{in}: \mathbb{R}^3 \times S^2 \to \mathbb{R}^4$: Maps 3D position $\mathbf{x}$ and viewing direction $\mathbf{d}$ to volume density $\sigma_{in}$ and color $\mathbf{c}_{in}$ [S1].
    *   $F_{out}: \mathbb{R}^3 \times S^2 \to \mathbb{R}^4$: Maps 3D position $\mathbf{x}$ and viewing direction $\mathbf{d}$ to volume density $\sigma_{out}$ and color $\mathbf{c}_{out}$ [S1]. Note that $F_{out}$ operates on the *inverted* coordinates of the exterior points [S1].

**Numbered Steps:**
1.  **Ray Definition:** For a pixel $p$ in image $I_i$, define the camera ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$, where $\mathbf{o}$ is the camera center and $\mathbf{d}$ is the unit direction vector [S3].
2.  **Sampling:** Sample $N$ points $\{t_n\}_{n=1}^N$ along the ray within near $t_n$ and far $t_f$ bounds [S6]. Uniform random sampling is used: $t_i \sim U \left[ t_n + \frac{i-1}{N} (t_f - t_n), t_n + \frac{i}{N} (t_f - t_n) \right]$ [S6].
3.  **Point Classification:** For each sample point $\mathbf{x}_n = \mathbf{r}(t_n)$, classify as **Interior** if $\|\mathbf{x}_n\| \le 1$, or **Exterior** if $\|\mathbf{x}_n\| > 1$ [S1].
4.  **Coordinate Transformation (Radial Inversion):** For **Exterior** points, apply radial inversion to map them into the unit sphere [S1]. Let $r = \|\mathbf{x}_n\|$. The inverted coordinate is $\mathbf{x}'_n = \mathbf{x}_n / r^2$ [S1][S8, unofficial]. This allows the exterior MLP to be trained on a bounded domain [S1].
5.  **NeRF Query:** Query $F_{in}(\mathbf{x}_n, \mathbf{d})$ for **Interior** points and $F_{out}(\mathbf{x}'_n, \mathbf{d})$ for **Exterior** points to obtain $(\sigma_n, \mathbf{c}_n)$ [S1].
6.  **Volume Rendering Integration:** Evaluate the ray integral in two parts: the segment inside the sphere and the segment outside the sphere [S1]. Let $t'$ be the intersection distance of the ray with the unit sphere (the smaller positive root of $\|\mathbf{o} + t\mathbf{d}\|^2 = 1$) [G]. The total color $C(\mathbf{r})$ accounts for transmittance accumulation across the boundary:
    $$ C(\mathbf{r}) = \int_{t_n}^{t'} T(t) \sigma_{in}(\mathbf{r}(t)) \mathbf{c}_{in}(\mathbf{r}(t), \mathbf{d}) dt + \int_{t'}^{t_f} T(t) \sigma_{out}(\mathbf{r}(t)) \mathbf{c}_{out}(\mathbf{r}(t), \mathbf{d}) dt $$
    where $T(t) = \exp\left(-\int_{t_n}^t \sigma(\mathbf{r}(s)) ds\right)$ is the accumulated transmittance [S2]. In discrete form:
    $$ \hat{C}(\mathbf{r}) = \sum_{i \in \text{In}} T_i (1 - e^{-\sigma_i \delta_i}) \mathbf{c}_i + T(t') \sum_{j \in \text{Out}} T'_j (1 - e^{-\sigma_j \delta_j}) \mathbf{c}_j $$
    where $T(t')$ is the transmittance at the sphere boundary and $T'_j$ is the transmittance relative to the start of the exterior segment [G].
7.  **Loss Calculation:** Minimize the Mean Squared Error (MSE) between the rendered image $\hat{I}$ and the ground truth image $I$ [S2]:
    $$ \mathcal{L}_{MSE} = \frac{1}{|\mathcal{R}|} \sum_{\mathbf{r} \in \mathcal{R}} \| C(\mathbf{r}) - \hat{C}(\mathbf{r}) \|_2^2 $$

**Pseudocode:**
```python
import torch
import torch.nn as nn

class SimpleMLP(nn.Module):
    def __init__(self, in_dim=6, out_dim=4, hidden_dim=256, num_layers=8):
        super().__init__()
        layers = []
        for _ in range(num_layers):
            layers.append(nn.Linear(in_dim if not layers else hidden_dim, hidden_dim))
            layers.append(nn.ReLU())
        layers.append(nn.Linear(hidden_dim, out_dim))
        self.net = nn.Sequential(*layers)
    def forward(self, x):
        return self.net(x)

class NeRFPlusPlus:
    def __init__(self, num_samples=128, near_plane=0.1, far_plane=100.0):
        self.num_samples = num_samples
        self.near_plane = near_plane
        self.far_plane = far_plane
        self.nerf_in = SimpleMLP(in_dim=6, out_dim=4)
        self.nerf_out = SimpleMLP(in_dim=6, out_dim=4)
        self.optimizer = torch.optim.Adam(
            list(self.nerf_in.parameters()) + list(self.nerf_out.parameters()), lr=5e-4
        )

    def radial_inversion(self, x):
        r = torch.norm(x, dim=-1, keepdim=True)
        r = torch.clamp(r, min=1.0)
        return x / (r ** 2)

    def sample_points(self, ray_o, ray_d, num_samples):
        t_vals = torch.linspace(self.near_plane, self.far_plane, num_samples, device=ray_o.device)
        t_vals = t_vals + torch.rand_like(t_vals) * (self.far_plane - self.near_plane) / num_samples
        points = ray_o.unsqueeze(1) + ray_d.unsqueeze(1) * t_vals.unsqueeze(2)
        return points, t_vals

    def forward(self, ray_o, ray_d):
        points, t_vals = self.sample_points(ray_o, ray_d, self.num_samples)
        # Ray-sphere intersection for t'
        a = torch.sum(ray_d * ray_d, dim=-1)
        b = 2.0 * torch.sum(ray_o * ray_d, dim=-1)
        c = torch.sum(ray_o * ray_o, dim=-1) - 1.0
        disc = b**2 - 4*a*c
        t_sphere = torch.full_like(a, float('inf'))
        valid = disc >= 0
        sqrt_disc = torch.sqrt(torch.clamp(disc, min=0))
        t1 = (-b - sqrt_disc) / (2*a)
        t2 = (-b + sqrt_disc) / (2*a)
        t1 = torch.where(t1 > 0, t1, torch.inf)
        t2 = torch.where(t2 > 0, t2, torch.inf)
        t_sphere = torch.where(valid, torch.minimum(t1, t2), torch.inf)

        point_dists = torch.norm(points, dim=-1)
        is_exterior = point_dists > 1.0

        points_inv = points.clone()
        points_inv[is_exterior] = self.radial_inversion(points_inv[is_exterior])

        sigma_in = torch.zeros_like(points[:, 0])
        color_in = torch.zeros_like(points[:, 0:3])
        sigma_out = torch.zeros_like(points[:, 0])
        color_out = torch.zeros_like(points[:, 0:3])

        ray_d_expanded = ray_d.unsqueeze(1).expand(-1, self.num_samples, -1)

        mask_in = ~is_exterior
        if mask_in.any():
            pos_in = points_inv[mask_in]
            dir_in = ray_d_expanded[mask_in]
            s_in, c_in = self.nerf_in(torch.cat([pos_in, dir_in], dim=-1))
            sigma_in[mask_in] = s_in
            color_in[mask_in] = c_in

        mask_out = is_exterior
        if mask_out.any():
            pos_out = points_inv[mask_out]
            dir_out = ray_d_expanded[mask_out]
            s_out, c_out = self.nerf_out(torch.cat([pos_out, dir_out], dim=-1))
            sigma_out[mask_out] = s_out
            color_out[mask_out] = c_out

        deltas = t_vals[:, 1:] - t_vals[:, :-1]
        deltas = torch.cat([deltas, torch.tensor([1e10], device=points.device).expand_as(deltas[:, :1])], dim=-1)
        sigma_all = torch.where(is_exterior, sigma_out, sigma_in)
        alpha = 1.0 - torch.exp(-sigma_all * deltas)
        T = torch.cumprod(torch.exp(-sigma_all * deltas), dim=1)
        T = torch.cat([torch.ones_like(T[:, :1]), T[:, :-1]], dim=-1)
        weights = alpha * T
        color = torch.sum(weights.unsqueeze(-1) * torch.where(is_exterior, color_out, color_in), dim=1)
        return color

    def train_step(self, ray_o, ray_d, gt_color):
        pred_color = self.forward(ray_o, ray_d)
        loss = torch.mean((pred_color - gt_color) ** 2)
        self.optimizer.zero_grad()
        loss.backward()
        self.optimizer.step()
        return loss.item()
```

**Parameters:**
*   $N$: Number of samples per ray. Not given in the sources.
*   $t_n, t_f$: Near and far bounds. Not given in the sources.
*   Sphere Radius: 1.0 (unit sphere) [S1, S5].

**Edge Cases and Pitfalls:**
*   **Precision at Boundary:** Sampling points exactly on the sphere boundary ($\|\mathbf{x}\|=1$) can cause ambiguity in which MLP to query. It is recommended to use a small epsilon or consistently assign boundary points to one domain (e.g., interior) [G].
*   **Inversion Singularity:** Points at the origin ($\mathbf{x}=0$) cannot be inverted. However, the origin is inside the sphere, so it is handled by $F_{in}$. Exterior points are strictly $>1$ distance, so inversion is safe [G].

## Subtopics

### [Inverted Sphere Parameterization](5573-inverted-sphere-parameterization.md)
Inverted Sphere Parameterization is a spatial parameterization scheme that allows Neural Radiance Fields to model 360° captures of unbounded scenes by separately representing foreground and background content. It solves the parameterization failure of standard NeRF, which assumes the entire scene fits within a bounded volume, leading to missing background elements or loss of detail due to limited sampling resolution in large-scale scenes. It sets itself apart from its parent [NeRF++](6198-nerf.md) by providing the specific mathematical mapping for the outer volume. Choose it when modeling 360° unbounded captures requiring precise outer volume parameterization.

### [DoubleNeRF](7391-doublenerf.md)
DoubleNeRF is a method for synthesizing dynamic scenes by representing them as the superposition of two or more static neural radiance fields, specifically separating a static background from a moving object with a static shape. Unlike [NeRF++](6198-nerf.md), which separates scenes using a spherical boundary, DoubleNeRF separates content semantically (background vs. foreground object) without spherical constraints, and unlike [D-NeRF](5573-d-nerf.md), it does not use time as an input or map canonical space to deformed space, assuming instead that the object's appearance is independent of its position relative to the background. Choose it for dynamic scenes with static-shaped foreground objects.

### [Physically Based Inverse Rendering with Split-Sum Approximation](11361-physically-based-inverse-rendering-with-split-sum-approximat.md)
This method recovers surface materials (albedo, roughness, metallic) and environment lighting from multi-view images by integrating Sur2f with differentiable rendering and a split-sum approximation of the rendering equation. It distinguishes itself from sibling methods by decoupling geometry and appearance, allowing seamless transfer of different appearances to different geometries by exchanging the shading network, whereas other methods often couple them. Choose it when physically based material and lighting recovery is required.

### [Background Inversion for Unit Sphere](11463-background-inversion-for-unit-sphere.md)
This method enables volume rendering of scenes with unbounded or complex backgrounds by mapping points outside a unit sphere into its interior, thereby eliminating the need for foreground masks during optimization. It sets itself apart from sibling methods like [Inverted Sphere Parameterization](5573-inverted-sphere-parameterization.md) by explicitly using a separate density voxel grid and shallow MLP for the inverted background, rather than relying on a single continuous field or point-based representations. Choose it when avoiding foreground masks is necessary for unbounded backgrounds.

### [SNeRF](14885-snerf.md)
SNeRF is a neural radiance field method designed for novel view synthesis in large-scale, unbounded street-view scenes collected by self-driving cars, jointly reconstructing static backgrounds and foreground moving vehicles. Unlike sibling methods such as [Block-NeRF](52-block-nerf.md) or [Urban-NeRF](52-urban-nerf.md) which require heavy camera overlap or dense LiDAR depth, SNeRF operates effectively with sparse, noisy LiDAR points and minimal camera overlap by employing implicit pose refinement and a robust confidence metric. Choose it for large-scale street-view reconstruction with sparse sensor data.

### [NDJIR](15962-ndjir.md)
NDJIR is an inverse rendering method that jointly decomposes geometry (signed distance function), lighting (environment and implicit), and materials (base color, roughness, specular reflectance) by directly addressing the integrals of the rendering equation using a volume rendering framework. It sets itself apart from siblings like [DoubleNeRF](7391-doublenerf.md) or [SNeRF](14885-snerf.md) by avoiding approximations such as Spherical Gaussians, split-sum, or pre-integrated lights, instead computing the physically-based rendering integral directly within the volume rendering pipeline. Choose it when direct physical decomposition without lighting approximations is required.

### Density-Guided Scene Representation
A method to construct an explicit 3D geometric space P from density points, alleviating the pressure on the radiance field to express fine 3D scenes by using rasterization technology to represent the density space in 2D [S9]. Predicted density point $p_r$ is inferred from ray $r$ as: $p_r = \hat{D}_\theta(r)d_r$, where $\hat{D}_\theta(r)$ is the expected depth [S9]. Multiple blocks $P_i$ are fused into a global scene $P$ using Merge operations: $P = \text{Merge}_{i \in \{1..N\}} (P_i, \Phi(P_{i-1}, P_i))$, where $\Phi$ incorporates predicted density points from distant areas with previous scene $P_{i-1}$ to smooth transitions [S9].

### HyperStyle
A pioneering 3D scene stylization method based on NeRF that extends the model with a geometry branch, an appearance branch, and a hypernetwork [S10]. It trains the hypernetwork to predict the parameters of the appearance branch according to the latent vector extracted from the reference image while fixing the geometry branch [S10]. It introduces a patch sub-sampling algorithm to train the hypernetwork with content and stylization losses [S10].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot S)$ per pixel, where $N$ is the number of rays (pixels) and $S$ is the number of samples per ray [G]. The dual-MLP query adds a constant factor overhead compared to single-MLP NeRF [G].
*   **Memory Complexity:** $O(M)$, where $M$ is the number of parameters in the two MLPs [G]. No additional large data structures are required beyond the MLP weights [G].
*   **Measured Performance:** NeRF++ enables high-quality novel view synthesis for unbounded scenes, which standard NeRF fails to do without masking or truncation [S1, S5].
*   **Strengths:** Handles infinite background; no need for manual masking or background removal; maintains view-dependent effects in the background [G].
*   **Limitations:** Requires careful tuning of the sphere radius; performance degrades if the scene geometry does not align well with the spherical partition [G].
*   **When to use:** Unbounded scenes (e.g., outdoor environments, cityscapes) where the background extends to infinity [G].
*   **When not to use:** Bounded indoor scenes where standard NeRF suffices; scenes with strong occlusions that cross the sphere boundary in complex ways [G].

## Background
NeRF++ was introduced by Zhang et al. in October 2020 [S1]. It was developed to address the limitations of the original NeRF [S6], which exhibited large computation requirements, difficulty modeling details of objects within a large scene, and vulnerability to variable illumination and transient occluders [S6]. The method was adapted to generate novel views for unbounded scenes by separating the scene using a sphere, with the inside containing foreground objects and the outside containing the background, which was reparameterized with radial inversion [S1].
