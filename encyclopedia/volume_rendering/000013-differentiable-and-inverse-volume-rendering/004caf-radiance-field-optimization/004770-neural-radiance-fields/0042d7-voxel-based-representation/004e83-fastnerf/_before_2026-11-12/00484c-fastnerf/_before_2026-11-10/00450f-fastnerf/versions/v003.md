# FastNeRF

Also called: Factorized Neural Radiance Fields

## Overview
FastNeRF is a neural rendering method that accelerates the rendering of Neural Radiance Fields (NeRF) by factorizing the view-dependent radiance field into position-dependent and direction-dependent components, enabling efficient caching of intermediate values [S2, unofficial]. Unlike standard NeRF, which requires hundreds of MLP evaluations per pixel, FastNeRF avoids MLP calls at inference time entirely by using pre-computed sparse 3D grids for lookups, achieving interactive frame rates (200Hz+) on consumer hardware [S2, unofficial]. It builds on [Voxel-based Representation](10852-voxel-based-representation.md) by replacing the dense 5D function approximation with a factorized architecture that separates spatial and angular data, allowing the memory complexity of caching to drop from $O(k^3 l^2)$ to $O(k^3 D + l^2 D)$ [S2, unofficial].

## How it works
FastNeRF modifies the standard NeRF architecture to enable caching. The core mechanism is the factorization of the radiance field function $\mathcal{F}_{\text{NeRF}}(\mathbf{p}, \mathbf{d})$ into two independent networks: a position-dependent network $\mathcal{F}_{\text{pos}}$ and a direction-dependent network $\mathcal{F}_{\text{dir}}$ [S2, unofficial].

### Inputs and Outputs
*   **Inputs:**
    *   Training: A set of images with known camera poses (extrinsics and intrinsics).
    *   Inference: A ray $\mathbf{r}$ defined by origin $\mathbf{o}$ and direction $\mathbf{d}$, and a pre-computed cache grid.
*   **Outputs:**
    *   Training: Gradients for network weights.
    *   Inference: Pixel color $\hat{C}(\mathbf{r})$ and density $\sigma$ along rays.

### Data Structures
The method relies on two sparse 3D grids (caches) populated after training:

1.  **Position Cache:**
    *   **Layout:** A 3D grid of size $k \times k \times k$.
    *   **Fields:** For each grid vertex, stores the density $\sigma$ (1 float) and a "deep radiance map" consisting of three $D$-dimensional vectors $\mathbf{u}, \mathbf{v}, \mathbf{w}$ (total $3D+1$ floats).
    *   **Storage:** Dense 16-bit floating point values in the active regions of the grid [S2, unofficial].
2.  **Direction Cache:**
    *   **Layout:** A 2D grid of size $l \times l$ representing the spherical domain of directions.
    *   **Fields:** For each direction sample, stores a $D$-dimensional weight vector $\boldsymbol{\beta}$ [S2, unofficial].
    *   **Storage:** Dense 16-bit floating point values [S2, unofficial].

### Parameters
*   $D$: Number of components in the deep radiance map and direction weights. Typical values: 8 for NeRF Synthetic 360 scenes, 6 for LLFF scenes [S2, unofficial].
*   $k$: Number of uniform samples for each worldspace coordinate ($x, y, z$) in the position cache bounding box $V$. Typical resolutions: $256^3$ to $1024^3$ [S2, unofficial].
*   $l$: Number of uniform samples for each ray direction coordinate ($\theta, \phi$) in the direction cache. $\theta \in [0, \pi]$, $\phi \in [0, 2\pi]$ [S2, unofficial].
*   **MLP Architecture:**
    *   $\mathcal{F}_{\text{pos}}$: 8-layer MLP with 384 hidden units (256 for specific scenes like 'ficus') [S2, unofficial].
    *   $\mathcal{F}_{\text{dir}}$: 4-layer MLP with 128 hidden units [S2, unofficial].
    *   Both use positional encoding on inputs [S2, unofficial].

### Steps

1.  **Training:**
    Train $\mathcal{F}_{\text{pos}}$ and $\mathcal{F}_{\text{dir}}$ jointly using the standard NeRF optimization procedure. The loss is computed by comparing rendered pixel colors against ground truth images using the volume rendering equation [S2, unofficial].

2.  **Cache Population (Post-Training):**
    *   Define a bounding box $V$ covering the scene.
    *   Uniformly sample $k$ values for $x, y, z$ within $V$.
    *   Uniformly sample $l$ values for $\theta, \phi$ for directions.
    *   Compute $\mathcal{F}_{\text{pos}}(\mathbf{p})$ for all position samples to populate the Position Cache with $\{\sigma, \mathbf{u}, \mathbf{v}, \mathbf{w}\}$.
    *   Compute $\mathcal{F}_{\text{dir}}(\mathbf{d})$ for all direction samples to populate the Direction Cache with $\boldsymbol{\beta}$ [S2, unofficial].

3.  **Ray Tracing and Culling:**
    *   For each pixel, generate a ray $\mathbf{r}$.
    *   Construct a collision mesh from the density volume using Marching Cubes [S2, unofficial].
    *   Use hardware-accelerated ray tracing to intersect the mesh. Skip empty space; start integration only after the first hit [S2, unofficial].
    *   For volumes larger than $512^3$, downsample the density volume by a factor of two before meshing to reduce complexity [S2, unofficial].

4.  **Integration:**
    For each sample point $\mathbf{p}_i$ along the ray:
    *   **Lookup Density and Radiance:** Query the Position Cache for $\sigma_i$ and vectors $(\mathbf{u}_i, \mathbf{v}_i, \mathbf{w}_i)$ using nearest-neighbor interpolation [S2, unofficial].
    *   **Lookup Direction Weights:** Determine the ray direction $\mathbf{d}_i$ at $\mathbf{p}_i$. Query the Direction Cache for $\boldsymbol{\beta}_i$ using trilinear sampling [S2, unofficial].
    *   **Compute Color:** Calculate the color $\mathbf{c}_i$ as the dot product:
        $$ \mathbf{c}_i = \boldsymbol{\beta}_i^T \cdot (\mathbf{u}_i, \mathbf{v}_i, \mathbf{w}_i) = \sum_{j=1}^D \beta_{i,j} (u_{i,j}, v_{i,j}, w_{i,j}) $$
        where $\mathbf{c}_i = (r, g, b)$ [S2, unofficial].
    *   **Volume Rendering:** Integrate color and transparency along the ray using the standard NeRF equation:
        $$ \hat{C}(\mathbf{r}) = \sum_{i=1}^N T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i $$
        where $T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right)$ is the transmittance and $\delta_i$ is the distance between samples [S2, unofficial].

### Edge Cases and Pitfalls
*   **Aliasing:** Caching the model to a grid after training introduces aliasing artifacts, which decrease metrics as a function of grid resolution [S1][S2, unofficial].
*   **Memory Explosion:** Discretizing the full 5D space (position and direction) without factorization requires ~176 TB for $512^3$ bins, which is infeasible on consumer hardware [S2, unofficial].
*   **Mesh Complexity:** For density volumes larger than $512^3$, the collision mesh must be downsampled by a factor of two to reduce complexity [S2, unofficial].
*   **Uncached Performance:** Without caching, FastNeRF is slower than standard NeRF due to larger MLPs (384 vs 256 hidden units). It performs identically to NeRF only if the position MLP is reduced to 256 units [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering is memory-bound rather than compute-bound due to cache lookups. It is approximately 3000 times faster than standard NeRF [S2, unofficial].
*   **Memory Complexity:** 
    *   Standard NeRF caching: $O(k^3 l^2)$ [S2, unofficial].
    *   FastNeRF caching: $O(k^3 (1 + 3D) + l^2 D)$ [S2, unofficial].
    *   Example: For $k=l=1024, D=8$, FastNeRF requires ~54 GB, whereas standard NeRF would require ~5600 TB [S2, unofficial].
*   **Performance:** Renders high-fidelity photorealistic images at 200Hz on high-end consumer GPUs [S2, unofficial]. On an Nvidia Tesla V100, it renders 300x300 pixel face images at 30 fps in telepresence scenarios, ~50 times faster than NeRF [S2, unofficial].
*   **Strengths:** Enables interactive rates on consumer hardware; compatible with ray-tracing and loose volume bounds; preserves visual quality comparable to NeRF [S2, unofficial].
*   **Limitations:** Caching reduces model compactness; aliasing artifacts at lower resolutions; slower than NeRF if not cached [S1][S2, unofficial].
*   **When to use:** Scenarios requiring interactive rates on mobile/mixed reality devices, telepresence, and dynamic scenes [S2, unofficial].
*   **When not to use:** When memory is extremely constrained and caching is not feasible; when training speed is the primary bottleneck (FastNeRF does not address training speed) [S2, unofficial].

## Background
FastNeRF was introduced by Garbin et al. in 2021 [S2, unofficial]. It was motivated by the need for real-time neural rendering on mobile and mixed reality devices, where standard NeRF's computational demands are prohibitive [S2, unofficial]. The method draws inspiration from real-time computer graphics techniques for approximating the rendering equation, specifically the use of spherical harmonics and factorization of view-dependent effects [S2, unofficial]. It is used in telepresence applications, dynamic scene reconstruction, and as a drop-in acceleration layer for other NeRF extensions [S2, unofficial].
