# FastNeRF

Also called: FastNeRF

## Overview
FastNeRF is a method that accelerates neural radiance field rendering by caching view-independent radiance values at selected 3D points sorted in a sparse spatial structure, such as voxel grid vertices [S1]. It solves the high memory and computational cost of evaluating the full NeRF MLP for every sample along every ray [S1]. Unlike standard NeRF which evaluates the network on the fly, FastNeRF precomputes and stores these values, allowing for retrieval much faster than on-the-fly evaluation [S1]. It sets itself apart from siblings like V4D and RenderNet by explicitly trading model compactness for rendering speed via explicit spatial caching [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of selected 3D points (typically voxel grid vertices) and their associated view-independent radiance values (density $\sigma$ and view-independent color components).
*   **Output:** A rendered image $\hat{C}(\mathbf{r})$ computed using the cached radiance values and a view-dependent component (e.g., spherical harmonic coefficients or a lightweight MLP) [S1].

**Data Structures:**
The method relies on a sparse spatial structure to store the cached data.
*   **Voxel Grid:** A 3D grid where occupied voxels store the cached view-independent radiance.
*   **Cache Entry:** For each occupied voxel/point, the structure stores:
    *   Density $\sigma$ [S2, unofficial].
    *   View-independent color components (often denoted as weights $\beta$ or similar factors depending on the factorization used) [S2, unofficial].
    *   Coordinates $(u, v, w)$ may be stored explicitly or implied by the grid index [S2, unofficial].

**Numbered Steps:**
1.  **Precomputation:** Evaluate the view-independent component of the radiance (density and base color factors) for a selected set of 3D points (e.g., voxel grid vertices) using the original NeRF MLP or a dedicated network [S1].
2.  **Caching:** Store these precomputed values in a sparse spatial structure (e.g., a voxel grid) [S1].
3.  **Rendering:** For each ray $\mathbf{r}$:
    a. Intersect the ray with the sparse spatial structure to find occupied voxels [S1].
    b. For each sample point along the ray, retrieve the cached view-independent radiance values ($\sigma$, $\beta$) from the structure [S1].
    c. Compute the view-dependent color using the retrieved view-independent values and the viewing direction (e.g., via spherical harmonics or a small MLP) [S1].
    d. Composite the color using the standard volume rendering equation [S1].

**Formulas:**
The memory size for the FastNeRF cache is calculated as [S2, unofficial]:

$$
M_{FastNeRF} = \alpha \left( (D \cdot s_{uvw} + s_{\sigma})k^3 \right) + D \cdot s_{\beta}l^2
$$

Where:
*   $\alpha \in [0, 1)$ is the inverse volume sparsity ($\alpha = 1$ indicates a dense volume) [S2, unofficial].
*   $D$ is the number of components/factors [S2, unofficial].
*   $s_{uvw}$ is the size of the stored $(u_i, v_i, w_i)$ values in bits [S2, unofficial].
*   $s_{\sigma}$ is the size of the stored transparency/density in bits [S2, unofficial].
*   $k$ is the number of bins per dimension in the position-dependent cache [S2, unofficial].
*   $s_{\beta}$ is the size of the weights $\beta_i$ in bits [S2, unofficial].
*   $l$ is the number of bins per dimension in the direction-dependent cache [S2, unofficial].

**Parameters:**
*   Typical values for $k$ and $l$ are 1024 [S2, unofficial].
*   $D$ is often 8 [S2, unofficial].
*   $(r, g, b)$ may be stored as individual bytes [S2, unofficial].
*   Other values may be stored as half-precision floats [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Memory Usage:** Caching radiance values into explicit spatial data structures comes at the expense of model compactness [S1].
*   **Sparsity:** Even for highly sparse volumes with $\alpha = 0.01$, the cache size can be significant (nearly 60TB for standard NeRF parameters, though FastNeRF reduces this drastically) [S2, unofficial].
*   **Precision:** The choice of bit depth for stored values ($s_{uvw}, s_{\sigma}, s_{\beta}$) directly impacts memory and potentially quality [S2, unofficial].

**Pseudocode:**
```python
# Precomputation phase
def precompute_cache(voxel_grid_resolution, original_nerf_mlp):
    """
    Precomputes view-independent radiance values for voxel grid vertices.
    """
    cache = SparseVoxelGrid(voxel_grid_resolution)
    for voxel in voxel_grid:
        if is_occupied(voxel):
            # Evaluate view-independent components using original MLP
            sigma, view_independent_color = original_nerf_mlp(voxel.center)
            # Store in cache
            cache.set(voxel.index, sigma, view_independent_color)
    return cache

# Rendering phase
def render_fastnerf(ray, cache, view_dependent_model):
    """
    Renders a single ray using cached view-independent radiance.
    """
    T = 1.0
    color = [0.0, 0.0, 0.0]
    
    # Intersect ray with sparse voxel grid to get sample points
    sample_points = intersect_ray_with_voxel_grid(ray, cache)
    
    for point in sample_points:
        # Retrieve cached view-independent values
        sigma, view_independent_color = cache.get(point.index)
        
        # Compute view-dependent color
        # Note: The specific factorization (e.g., SH) is handled by view_dependent_model
        # which uses view_independent_color and ray.direction
        rgb = view_dependent_model(view_independent_color, ray.direction)
        
        # Volume rendering step
        alpha = 1.0 - exp(-sigma * point.step_size)
        weight = T * alpha
        color += weight * rgb
        T *= (1.0 - alpha)
        
        # Early termination if transmittance is negligible
        if T < 0.001:
            break
            
    return color
```

## Operating characteristics
*   **Time Complexity:** Rendering is significantly faster than standard NeRF due to cache lookups instead of MLP evaluations. FastNeRF can render high-fidelity photorealistic images at 200fps on a high-end consumer GPU [S1].
*   **Memory Complexity:** Memory usage is determined by the cache size formula $M_{FastNeRF}$ [S2, unofficial]. It is much lower than standard NeRF but still substantial for high resolutions.
*   **Measured Performance:** For $k=l=1024$, $D=8$, with specific bit depths, the NeRF cache size is approximately $\alpha \cdot 5.6$ PB, while FastNeRF reduces this to approximately $\alpha \cdot 54$ GB (specifically $\alpha \cdot 53,687,091,200 + 16,777,216$) [S2, unofficial].
*   **Strengths:** High rendering speed, suitability for real-time applications on consumer hardware [S1].
*   **Limitations:** High memory consumption compared to implicit representations, reduced model compactness [S1].
*   **When to use:** When real-time or near-real-time rendering is required and sufficient GPU memory is available.
*   **When not to use:** When memory is extremely constrained or when the scene is highly dynamic and requires frequent cache updates.

## Background
FastNeRF was introduced by Garbin et al. in 2021 [S1][S2, unofficial]. It was developed to address the high computational cost of standard NeRF by caching view-independent radiance values [S1]. The method builds on the principles of differentiable volume rendering and neural radiance fields [S1]. It is used in applications requiring fast novel view synthesis, such as real-time visualization and interactive applications [S1].
