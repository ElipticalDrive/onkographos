# FastNeRF

Also called: Factorized Neural Radiance Fields

## Overview
FastNeRF is a neural rendering method that accelerates volume rendering by factorizing the view-dependent radiance field into position-dependent and direction-dependent components, enabling efficient caching of intermediate network outputs [S3, unofficial]. It solves the computational bottleneck of standard Neural Radiance Fields (NeRF) by avoiding MLP evaluations at inference time, allowing photorealistic rendering at 200Hz on consumer hardware [S3, unofficial]. Unlike standard NeRF, which evaluates a single 5D function, FastNeRF decouples spatial and angular information, reducing memory complexity from $O(k^3 l^2)$ to $O(k^3 D + l^2 D)$ and enabling hardware-accelerated ray tracing to skip empty space [S3, unofficial].

## How it works
**Inputs and Outputs:**
- **Training Inputs:** A set of $M$ images with known camera poses (extrinsics and intrinsics).
- **Training Outputs:** Weights for two MLPs: $\mathcal{F}_{\text{pos}}$ and $\mathcal{F}_{\text{dir}}$.
- **Inference Inputs:** Camera parameters and a bounding volume $V$ containing the scene.
- **Inference Outputs:** A rendered image $\hat{C}(\mathbf{r})$ for each ray $\mathbf{r}$.

**Data Structures:**
1.  **Position Cache:** A 3D grid of size $k \times k \times k$. Each cell stores density $\sigma$ (1 value) and a deep radiance map $(\mathbf{u}, \mathbf{v}, \mathbf{w})$ where $\mathbf{u}, \mathbf{v}, \mathbf{w}$ are $D$-dimensional vectors. Total storage per cell: $1 + 3D$ values. Stored as 16-bit floating point [S3, unofficial].
2.  **Direction Cache:** A 2D grid of size $l \times l$. Each cell stores a weight vector $\boldsymbol{\beta}$ of dimension $D$. Total storage per cell: $D$ values. Stored as 16-bit floating point [S3, unofficial].
3.  **Collision Mesh:** A triangular mesh derived from the density volume using Marching Cubes, used for hardware-accelerated ray intersection [S3, unofficial].

**Parameters:**
-   $D$: Number of components in the deep radiance map and direction weights. Typical values: 8 for NeRF Synthetic 360 scenes, 6 for LLFF scenes [S3, unofficial].
-   $k$: Number of uniform samples for each worldspace coordinate ($x, y, z$) in the position cache bounding box $V$. Typical values: 256, 384, 512, 768, 1024 [S3, unofficial].
-   $l$: Number of uniform samples for each ray direction coordinate ($\theta, \phi$) in the direction cache. $\theta \in [0, \pi]$, $\phi \in [0, 2\pi]$ [S3, unofficial].
-   MLP Hidden Units: $\mathcal{F}_{\text{pos}}$ uses 384 (or 256 for some scenes); $\mathcal{F}_{\text{dir}}$ uses 128 [S3, unofficial].

**Algorithm Steps:**

1.  **Training:**
    1.  Initialize $\mathcal{F}_{\text{pos}}$ (8-layer MLP, 384 hidden units) and $\mathcal{F}_{\text{dir}}$ (4-layer MLP, 128 hidden units) with positional encoding [S3, unofficial].
    2.  For each training iteration:
        a.  Sample a pixel and generate a ray $\mathbf{r}$ with direction $\mathbf{d}$ and origin.
        b.  Sample $N$ points $\mathbf{p}_i$ along the ray between near and far bounds.
        c.  Compute density $\sigma_i = \mathcal{F}_{\text{pos}}(\mathbf{p}_i).\sigma$ [S3, unofficial].
        d.  Compute deep radiance components $\mathbf{u}_i, \mathbf{v}_i, \mathbf{w}_i = \mathcal{F}_{\text{pos}}(\mathbf{p}_i).(\mathbf{u}, \mathbf{v}, \mathbf{w})$ [S3, unofficial].
        e.  Compute direction weights $\boldsymbol{\beta}_i = \mathcal{F}_{\text{dir}}(\mathbf{d})$ [S3, unofficial].
        f.  Compute color $\mathbf{c}_i = \boldsymbol{\beta}_i^T \cdot (\mathbf{u}_i, \mathbf{v}_i, \mathbf{w}_i)$ [S3, unofficial].
        g.  Render pixel color $\hat{C}(\mathbf{r})$ using the volume rendering equation:
            $$ \hat{C}(\mathbf{r}) = \sum_{i=1}^N T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i $$
            where $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$ and $\delta_i$ is the distance between samples [S3, unofficial].
        h.  Update MLP weights to minimize the difference between $\hat{C}(\mathbf{r})$ and the ground truth image [S3, unofficial].

2.  **Caching (Post-Training):**
    1.  Define a bounding box $V$ covering the scene [S3, unofficial].
    2.  Uniformly sample $k$ values for $x, y, z$ within $V$ and $l$ values for $\theta, \phi$ [S3, unofficial].
    3.  For each position sample $\mathbf{p}$, compute $\{\sigma, (\mathbf{u}, \mathbf{v}, \mathbf{w})\} = \mathcal{F}_{\text{pos}}(\mathbf{p})$ and store in the Position Cache [S3, unofficial].
    4.  For each direction sample $\mathbf{d}$, compute $\boldsymbol{\beta} = \mathcal{F}_{\text{dir}}(\mathbf{d})$ and store in the Direction Cache [S3, unofficial].
    5.  Generate a collision mesh from the density volume $\sigma$ in the Position Cache using Marching Cubes [S3, unofficial]. If volume resolution $> 512^3$, downsample by factor of 2 before meshing [S3, unofficial].

3.  **Inference (Rendering):**
    1.  For each pixel, generate ray $\mathbf{r}$ with direction $\mathbf{d}$ [S3, unofficial].
    2.  Use hardware-accelerated ray tracing to intersect the collision mesh. Skip integration until the first hit [S3, unofficial].
    3.  For each sample point $\mathbf{p}_i$ along the ray (visiting every voxel in the cache grid):
        a.  Lookup $\sigma_i$ and $(\mathbf{u}_i, \mathbf{v}_i, \mathbf{w}_i)$ from the Position Cache using nearest-neighbor interpolation [S3, unofficial].
        b.  Lookup $\boldsymbol{\beta}_i$ from the Direction Cache using trilinear interpolation based on $\mathbf{d}$ [S3, unofficial].
        c.  Compute $\mathbf{c}_i = \boldsymbol{\beta}_i^T \cdot (\mathbf{u}_i, \mathbf{v}_i, \mathbf{w}_i)$ [S3, unofficial].
    4.  Integrate color and transparency along the ray using the standard volume rendering equation [S3, unofficial].
    5.  Terminate ray integration when transmittance saturation is reached [S1].

## Operating characteristics
- **Time Complexity:** Inference is dominated by cache lookups and dot products, avoiding MLP evaluations. Speedup is >3000x compared to standard NeRF [S3, unofficial].
- **Memory Complexity:** Standard NeRF caching requires $O(k^3 l^2)$ memory. FastNeRF reduces this to $O(k^3 (1 + 3D) + l^2 D)$ [S3, unofficial]. For $k=l=1024, D=8$, dense cache size is ~54 GB, compared to ~5600 TB for standard NeRF [S3, unofficial].
- **Performance:** Renders 200Hz on high-end consumer GPUs [S3, unofficial]. On Nvidia Tesla V100, renders 300x300 face images at 30fps in telepresence scenarios [S3, unofficial].
- **Strengths:** Extremely fast inference; compatible with hardware-accelerated ray tracing; maintains high visual quality at high cache resolutions [S3, unofficial].
- **Limitations:** Aliasing artifacts due to grid caching; larger MLPs during training (slower training); memory usage still significant for very high resolutions [S3, unofficial].
- **When to use:** Interactive applications, telepresence, mobile/VR where real-time rendering is required [S3, unofficial].
- **When not to use:** When training speed is critical (FastNeRF training is similar to NeRF but with larger MLPs); when memory is extremely constrained and lower resolution is acceptable without caching [S3, unofficial].

## Background
FastNeRF was introduced by Garbin et al. in March 2021 [S1]. It was motivated by the need for real-time neural rendering on consumer hardware, particularly for mobile and mixed reality applications [S3, unofficial]. The method builds on the principles of Neural Radiance Fields [44-radiance-field-optimization.md] but introduces a factorization inspired by spherical harmonics in computer graphics to enable efficient caching [S3, unofficial].
