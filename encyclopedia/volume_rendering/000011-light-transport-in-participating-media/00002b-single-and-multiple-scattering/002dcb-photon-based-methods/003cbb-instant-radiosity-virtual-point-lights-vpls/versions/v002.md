# Instant Radiosity / Virtual Point Lights (VPLs)
Also called: Instant Radiosity, Virtual Point Lights

## Overview
Instant Radiosity, also known as Virtual Point Lights (VPLs), is a method for computing indirect illumination that approximates the global illumination solution by treating stored photons as discrete light sources rather than using density estimation [S1]. It solves the problem of efficiently calculating diffuse interreflection and caustics on surfaces by replacing the complex integral of incoming radiance with a summation of contributions from a smaller set of virtual point lights [S1][S2, unofficial]. Unlike sibling methods such as [Photon-based Estimation](2521-photon-based-estimation.md), which rely on kernel density estimation to smooth photon contributions, VPLs require explicit visibility computation for each light, resulting in significantly fewer samples but introducing singularity artifacts at close distances [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** Scene geometry, light sources, and a list of photons generated during a prior lighting pass [S1]. Not given in the sources.
*   **Outputs:** Final radiance $L_o(\mathbf{x}, \boldsymbol{\omega}_o)$ for each shading point [S1].

**Data Structures**
*   **VPL List:** A list of Virtual Point Lights derived from the photon list [S1]. Each VPL $j$ stores:
    *   Position $\mathbf{p}_j$: Surface intersection point of the photon [S1].
    *   Direction $\boldsymbol{\omega}_j$: Incoming photon direction at $\mathbf{p}_j$ [S1].
    *   Power $P_j$: Radiant flux carried by the photon, scaled by surface reflectance [S1].

**Steps**
1.  **Lighting Pass:** Shoot photons from light sources into the scene and store their surface intersections [S1].
2.  **VPL Generation:** Treat every stored photon as a virtual point light that emits light into the scene [S1].
3.  **Rendering Pass:** For each shading point $\mathbf{x}$, gather contributions from all VPLs by computing visibility and summing irradiance [S1].

**Pseudocode**
```python
def instant_radiosity(scene, photon_list, shading_points):
    # Step 2: VPL Generation
    vpl_list = []
    for photon in photon_list:
        vpl = {
            'position': photon.position,
            'direction': photon.incoming_direction,
            'power': photon.power * scene.albedo(photon.position) # [G]
        }
        vpl_list.append(vpl)

    # Step 3: Rendering Pass (Gathering)
    final_radiance = 0.0
    for point in shading_points:
        accumulated_radiance = 0.0
        for vpl in vpl_list:
            r = vpl['position'] - point.position
            d = norm(r)
            if d < 0.001: # [G] minimum distance to avoid singularity
                continue
            omega = r / d
            # Visibility test
            if not scene.is_visible(point.position, vpl['position']):
                continue
            # Irradiance approximation [G]
            irradiance = vpl['power'] / (pi * d**2)
            # Cosine terms [G]
            irradiance *= max(0, dot(point.normal, omega))
            irradiance *= max(0, dot(vpl['direction'], -omega))
            # BRDF evaluation [G]
            radiance_contribution = scene.brdf(point.position, -omega, point.outgoing_direction) * irradiance
            accumulated_radiance += radiance_contribution
        final_radiance = accumulated_radiance + scene.emission(point.position, point.outgoing_direction) # [G]
    return final_radiance
```

**Parameters**
*   **Number of VPLs:** Much fewer than the total number of photons because visibility computation is required for each [S1].
*   **Clamping Distance:** A minimum distance threshold used to prevent singularity artifacts when VPLs are extremely close to shading points [S1].

**Edge Cases and Pitfalls**
*   **Singularity Artifacts:** Tiny distances between VPLs and shading points cause $1/d^2$ spikes in irradiance, producing bright artifacts in rendered results [S1].
*   **Mitigation:** Clamping distances or blurring VPL contributions removes spikes but introduces bias or missing energy [S1].
*   **Visibility Cost:** Explicit shadow ray tracing per VPL makes the method computationally expensive; hierarchical pruning (e.g., Lightcuts) is often applied to accelerate it [S1].

## Operating characteristics
*   **Time Complexity:** $O(N_{shading} \cdot N_{VPL})$ in the worst case, dominated by visibility tests per shading point [S1].
*   **Memory Complexity:** $O(N_{VPL})$ to store the virtual point light list [S1].
*   **Strengths:** Produces sharp caustics and accurate indirect illumination without the blurring inherent in density estimation methods [S1]. Requires significantly fewer samples than density estimation for comparable visual quality in many scenarios [S1].
*   **Limitations:** Susceptible to singularity artifacts at close range. Computationally expensive due to per-VPL visibility checks. Not natively suited for participating media without extensions [S1].
*   **When to use:** Surface rendering with diffuse interreflection and caustics where sharp indirect details are desired [S1].
*   **When not to use:** Real-time applications with high VPL counts without acceleration structures; scenes with participating media unless extended with techniques like diffusion dipoles [S1].

## Background
Instant Radiosity was proposed by Christoph Keller [S1]. It has been widely used in surface rendering algorithms for indirect illumination [S1]. The method was later extended to participating media by Arbree et al., who combined lightcuts with diffusion dipoles to approximate subsurface scattering [S1]. Multi-dimensional lightcuts further extended VPLs to handle effects like motion blur in participating media [S1]. Novák et al. proposed a method to approximately compensate for the bias introduced by clamping or blurring [S1].
