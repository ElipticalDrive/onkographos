# Importance Segment Data Structure and Estimation

Also called: Importance Segment Data Structure

## Overview
This method provides a compact, ray-specific data structure for approximating the importance function $\tilde{k}(t)$ during Monte Carlo volume rendering. It solves the problem of efficiently estimating the integral of the importance function required for variance reduction in light transport, specifically within the context of Grid-based Importance Sampling for Boundary Segments. It sets itself apart by storing precomputed integrals of the squared importance function alongside segment parameters, allowing for $O(\log N)$ lookup and interpolation during rendering, rather than recomputing integrals from scratch. This enables progressive refinement of the importance approximation along a single camera ray.

## How it works
The method operates on a per-ray basis, building a step-function approximation of the importance function $\tilde{k}(t)$ and maintaining precomputed integrals to facilitate fast evaluation of the guiding function $h(\mathbf{y})$.

### Inputs and Outputs
*   **Inputs:**
    *   Camera ray origin $\mathbf{x}$ and direction $\omega$.
    *   Number of samples $N$ for the initial approximation.
    *   A mechanism to evaluate the raw importance function $k(t)$ at any point $t$ along the ray.
*   **Outputs:**
    *   A sorted list of segments representing the approximation $\tilde{k}(t)$.
    *   Precomputed cumulative integrals $K_i$ associated with each segment.

### Data Structures
The data structure is a list of segments. Each segment $i$ stores a tuple with the following fields:
1.  $t_i$: The location along the ray (distance from origin) corresponding to the start of the segment.
2.  $l_i$: The length of the segment.
3.  $k_i$: The importance value (constant) for this segment.
4.  $K_i$: The precomputed integral of the squared importance function from the ray start ($0$) to $t_i$. That is, $K_i = \int_0^{t_i} \tilde{k}(s)^2 ds$.

### Algorithm Steps
The rendering process using this data structure follows these steps for each ray:

1.  **Initialize:** Create an empty data structure.
2.  **Sample:** Draw $N$ random samples $t'_i$ along the ray. Evaluate the importance function at these points to get values $k'_i$.
3.  **Insert:** Insert the samples into the data structure. This involves sorting the samples by $t'_i$ and defining segments between them.
    *   For empty regions at the beginning and end of the ray, assume the border has an importance of 0.
    *   Compute and accumulate the integrals for each segment and empty region. The integral for a segment is added to the next segment's $K$ value. Since $\tilde{k}(s)$ is a step function, the integral is a simple sum.
4.  **Track:** Perform Woodcock tracking using the optimized extinction derived from the data structure until a scattering or absorption event occurs.
5.  **Scatter:** If a scattering event occurs, sample light sources and compute the (optionally visibility optimized) transmittance.
6.  **Multiple Scattering (Optional):** Calculate the multiple-scattering contribution.
7.  **Progressive Refinement:** Repeat steps 2–6 for progressive rendering, updating the data structure with new samples.

### Computation of $h(\mathbf{y})$
During rendering, the guiding function $h(\mathbf{y})$ requires evaluating integrals of the importance function. Given the precomputed $K_i$, this is computed as follows for a point $\mathbf{y} = \mathbf{x} + t \cdot \omega$:

1.  **Binary Search:** Find the segment $[t_i, t_{i+1})$ containing $t$.
2.  **Lookup and Add:** Look up the integral to the left of this segment, which is stored as $K_i$. Add the integral inside the current segment up to $t$. This is calculated as:
    $$ \text{Integral}(0 \to t) = K_i + (t - t_i) \cdot k_i^2 $$
3.  **Interpolation (Edge Case):** If $t$ lies between two segments $[t_{i-2}, t_{i-1})$ and $[t_i, t_{i+1})$ such that $t_{i-1} \le t < t_i$ (i.e., $t$ is in a gap or empty region between stored segments), linearly interpolate between:
    *   The stored integral of the segment to the right ($A_i$, value $K_i$).
    *   The integral stored for the left segment ($A_{i-2}$, value $K_{i-2}$) plus the integral of the left segment's contribution.

def compute_importance_integral(t, segments):
    """
    Computes the integral of squared importance from 0 to t.
    segments: List of tuples (t_i, l_i, k_i, K_i)
    """
    # Binary search for the segment index i such that t_i <= t < t_{i+1}
    # If t is beyond the last segment, clamp to last segment end
    # If t is before first segment, return 0
    
    i = binary_search_segments(segments, t)
    
    if i is None or t < segments[0][0]:
        return 0.0
        
    t_i, l_i, k_i, K_i = segments[i]
    
    # Base integral from previous segments
    integral = K_i
    
    # Add integral within the current segment up to t
    # Length inside segment is (t - t_i)
    # Importance is constant k_i
    integral += (t - t_i) * (k_i ** 2)
    
    # Handle case where t lies between segments (gap)
    # Check if t is in a gap after segment i-1 but before segment i
    # Specifically if t_{i-1} <= t < t_i
    if i > 0:
        t_prev, l_prev, k_prev, K_prev = segments[i-1]
        if t_prev <= t < t_i:
            # Linear interpolation between stored integral of segment i (K_i)
            # and integral of segment i-2 plus its contribution?
            # Note: The source describes interpolating between K_i and 
            # (K_{i-2} + integral of left segment). 
            # Assuming standard linear interpolation between the two known integral values
            # at the boundaries of the gap.
            
            # Value at t_{i-1} is effectively K_{i-1} (stored in segment i-1)
            # Value at t_i is K_i (stored in segment i)
            # However, the source mentions K_{i-2}. Let's follow the source strictly:
            # "linearly interpolate between the stored integral of the segment to the right (Ai) 
            # and the integral stored for the left segment (Ai-2) plus the integral of the left segment"
            
            # This implies we have a value at t_{i-1} derived from A_{i-2} and A_{i-1}
            # Let val_left = K_{i-2} + (t_{i-1} - t_{i-2}) * k_{i-2}^2 ? 
            # Or simply K_{i-1} if K_{i-1} is correctly maintained.
            # Given the ambiguity of "Ai-2 plus integral of left segment", 
            # and that K_i is cumulative, K_{i-1} should represent the integral up to t_{i-1}.
            # If the data structure stores K_i correctly, K_{i-1} is the integral up to t_{i-1}.
            
            # Re-reading source: "integral stored for the left segment (Ai-2) plus the integral of the left segment"
            # This phrasing is tricky. Ai-2 stores K_{i-2}. The "left segment" might refer to A_{i-1}.
            # If we assume K_i is strictly cumulative, then K_{i-1} is the integral up to t_{i-1}.
            # Let's assume standard cumulative integral behavior for robustness, 
            # but note the source's specific interpolation instruction.
            
            # If we must follow the source literally:
            # Right value: K_i
            # Left value: K_{i-2} + integral(A_{i-1})
            # Integral(A_{i-1}) = (t_{i-1} - t_{i-2}) * k_{i-2}^2 ? No, k_{i-1}^2.
            
            # Let's use K_{i-1} if available, otherwise fallback to source logic.
            # Since K_i is stored with t_i, K_{i-1} is stored with t_{i-1}.
            
            val_right = K_i
            val_left = K_{i-1} # Assuming K_{i-1} is the integral up to t_{i-1}
            
            # Linear interpolation
            t_gap_start = t_prev
            t_gap_end = t_i
            fraction = (t - t_gap_start) / (t_gap_end - t_gap_start)
            integral = val_left + fraction * (val_right - val_left)
            
    return integral

def build_importance_structure(ray_origin, ray_dir, importance_func, N):
    """
    Builds the importance segment data structure for a ray.
    """
    # 1. Draw N random samples
    samples = []
    for i in range(N):
        t_rand = random.uniform(0, ray_length) # Assuming ray length known or infinite
        k_val = importance_func(ray_origin + t_rand * ray_dir)
        samples.append((t_rand, k_val))
    
    # 2. Sort samples by t
    samples.sort(key=lambda x: x[0])
    
    # 3. Create segments
    segments = []
    current_K = 0.0
    
    # Handle start of ray (empty region with importance 0)
    # If first sample is at t_0, region [0, t_0) has k=0
    if samples:
        t_0, k_0 = samples[0]
        # Segment for empty start
        # Length t_0, importance 0, integral 0
        # But we store segments with non-zero importance usually?
        # Source says: "For empty regions... assume border has importance 0. 
        # Compute and accumulate integrals... store result in next segment"
        
        # Let's create a segment for the first sample
        # The segment starts at t_0
        # We need to account for the integral from 0 to t_0 (which is 0)
        
        # Add first segment
        # We need length. Length is defined by distance to next sample.
        segments.append((t_0, 0, k_0, 0.0)) # Placeholder for length, will update
        
        current_K = 0.0
        
        for i in range(len(samples)):
            t_i, k_i = samples[i]
            
            # Determine length
            if i + 1 < len(samples):
                t_next, k_next = samples[i+1]
                l_i = t_next - t_i
            else:
                # End of ray? Assume infinite or max distance
                l_i = 0 # Or handle end separately
            
            # Update K for this segment
            # K_i is integral up to t_i
            # The integral accumulated so far is stored in K_i
            # The integral of the PREVIOUS segment (i-1) is added to K_i
            
            if i > 0:
                t_prev, l_prev, k_prev, K_prev = segments[i-1]
                # Integral of previous segment
                int_prev = l_prev * (k_prev ** 2)
                current_K += int_prev
            
            segments[i] = (t_i, l_i, k_i, current_K)
            
    return segments

## Operating characteristics
*   **Time Complexity:** Building the structure takes $O(N \log N)$ due to sorting $N$ samples. Lookup for $h(\mathbf{y})$ takes $O(\log N)$ due to binary search.
*   **Memory Complexity:** $O(N)$ to store the $N$ segments.
*   **Strengths:** Enables progressive refinement of importance sampling along a ray. Precomputed integrals allow for fast evaluation of the guiding function without re-integrating.
*   **Limitations:** Requires storing $N$ segments per ray, which can be memory-intensive for high $N$. The approximation is piecewise constant, which may not capture smooth variations in importance perfectly.
*   **When to use:** When rendering participating media with significant variance in importance, and when progressive rendering is desired.

## Background
This method is described in "View‐Dependent Visibility Optimization for Monte Carlo Volume Visualization" [S1]. It is part of a broader approach to optimizing extinction sampling in volume rendering by using importance sampling based on visibility and scattering contributions.
