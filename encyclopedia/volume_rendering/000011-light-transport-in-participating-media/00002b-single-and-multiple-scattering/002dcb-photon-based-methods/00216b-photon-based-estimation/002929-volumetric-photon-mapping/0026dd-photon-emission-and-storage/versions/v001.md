# Photon Emission and Storage

Also called: Photon Mapping with Volume Storage, emitPhotons

## Overview
Photon Emission and Storage is the data generation phase of Volumetric Photon Mapping, responsible for tracing photons from light sources through participating media and surfaces to populate a spatial data structure with scattering events. It solves the problem of approximating indirect illumination and inscattering by storing photon positions, directions, and energies. It differs from its sibling [Beam Radiance Estimate](1283-beam-radiance-estimate.md) by storing discrete point samples rather than beam-like structures, and from [Photon Beam Tracing](5401-photon-beam-tracing.md) by using standard ray-object intersection for storage rather than beam tracing through volumes.

## How it works
**Inputs:**
- Light source position `Light` (Vector3).
- Light source radius `light_bulb_r` (double, typically 0.1).
- Scene objects `objects` (array of `CObj*`), each with type, geometry, color, and optics.
- Room boundaries for validity checks (e.g., $|x| \le 1.5, |y| \le 1.2$).
- Maximum bounces `nrBounces` (integer).
- Reflection limit `reflection_limit` (integer, typically 4).
- Total photon count `nrPhotons` (integer).
- Rendering mode flag `view3D` (boolean).

**Outputs:**
- Volume photon buffer `vol_photons`: Array storing photons interacting with volumes. Each entry contains position, direction, and energy.
- Surface photon map: Spatial data structure storing photons at surface intersections.

**Data Structures:**
- `vol_photons`: A flat array or list. Each element stores:
  - `pos`: Vector3 (position of scattering event).
  - `dir`: Vector3 (direction of photon).
  - `energy`: Vector3 (RGB energy).
- `num_vol`: Integer counter for the number of volume photons stored.
- `numPhotons[t]`: Integer array tracking surface photons per object `t`.

**Parameters:**
- `power`: Scalar energy multiplier (e.g., 500).
- `collect_r`: Radius for gathering photons (e.g., 0.7).
- `exposure`: Exposure factor for weighting (value not specified in source, treated as parameter).
- `NOT_INTERSECTED`: Threshold distance indicating no intersection.

**Steps:**

1. **Initialization:**
   - Reset `num_vol = 0`.
   - Reset `numPhotons[t] = 0` for all objects `t`.
   - Determine total photons to emit: `num_photon = nrPhotons * 3.0` if `view3D` is true, else `nrPhotons`.

2. **Optional Test Emission:**
   - Emit 100 photons from a specific object (e.g., `objects[5]`) with fixed properties for testing purposes. This step is conditional and may be skipped in production.

3. **Main Photon Emission Loop:**
   - Iterate `i` from 0 to `num_photon - 1`.
   - Initialize photon state:
     - `rgb = (1.0, 1.0, 1.0)` (white).
     - `bounces = 1`.
     - `ray = randDir(1.0)` (random unit vector).
     - `from = Light`.

4. **Randomize Start Position:**
   - While `from.y() >= Light.y()`:
     - `from = randDir(1.0) + Light`.
   - This ensures the photon starts below the light source's Y-coordinate.

5. **Validity Checks:**
   - **Room Boundary Check:** If `fabs(from.x()) > 1.5` or `fabs(from.y()) > 1.2`, mark photon invalid by setting `bounces = nrBounces + 1`.
   - **Object Interior Check:** Iterate through all objects `dx`. If object `dx` is a sphere (`TYPE_SPHERE`):
     - Calculate `center` from `ob->coords`.
     - If `distance(from, center) < ob->coords[3]` (radius), mark photon invalid by setting `bounces = nrBounces + 1`.
   - If `bounces > nrBounces`, skip to next photon.

6. **Volume Photon Storage (Initial):**
   - If the photon is valid and volume storage is enabled, call `storePhoton_vol(from, ray, rgb)`.
   - Increment `num_vol`.

7. **Ray Tracing and Bounce Loop:**
   - Perform ray trace: `istat = raytrace(ray, from)`.
   - While `istat.dist < NOT_INTERSECTED` and `bounces <= nrBounces`:
     - Calculate intersection point: `pnt = from + ray * istat.dist`.
     - Handle optics (reflection/refraction) based on `istat.obj->getOptics()`.
     - Limit optical interactions per bounce to `reflection_limit`.
     - Update `ref` counter.
     - Update `from = pnt`.
     - Perform next ray trace: `istat = raytrace(ray, from)`.
     - If no intersection, break loop.
     - Calculate new `pnt`.

8. **Surface Photon Storage and Color Update:**
   - If intersection exists:
     - Calculate object color: `col = mulColor(rgb, istat.obj)`.
     - Attenuate color by bounces: `rgb = col * (1.0 / sqrt(bounces))`.
     - Store photon at surface: `storePhoton(istat.obj, pnt, ray, rgb)`.
     - Increment `numPhotons[istat.obj->getIndex()]`.
     - Trace shadow ray: `shadowPhoton(ray, pnt)`.
     - Reflect ray: `ray = reflect(istat.obj, pnt, ray, from)`.
     - Perform next ray trace: `istat = raytrace(ray, pnt)`.
     - Update `from = pnt`.
     - Increment `bounces`.

9. **Alternative Emission Mode (Light Bulb Extension):**
   - Iterate `i` from 0 to `photon_num - 1` (e.g., 2000).
   - Initialize `rgb = white`, `ray = randDir(1.0)`.
   - Calculate random length: `len = randlen()`.
   - Calculate start position: `from = Light + stepout(ray, light_bulb_r + len)`.
   - Check if `from` is inside the room using `cheak_in_room(from)`. If not, skip.
   - Check if `from` is inside any sphere object. If so, skip.
   - Store volume photon: `storePhoton_vol(from, ray, rgb)`.
   - Increment `num_vol`.

## Subtopics

### Photon Mapping for Participating Media
A method for non-homogeneous materials extending photon mapping to participating media. It uses Monte Carlo simulation of photon transport from light sources, accounting for spatially varying optical properties and general phase functions. It records each scattering event in a spatial data structure called a photon map. In a final gather pass from the viewpoint, it collects scattering events relevant to a viewing ray to account for inscattered photons. The method can be slow because many photons are required for accurate convergence. It is less useful for volume rendering of spatially varying data compared to homogeneous materials. [S2, book]

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of photons emitted and the number of bounces per photon. The final gather step is linear with respect to the number of pixels and the number of photons in the search radius.
- **Memory Complexity:** Linear with respect to the number of photons stored.
- **Performance:** The method is computationally expensive due to the large number of photons required for accurate convergence, especially in participating media. [S2, book]
- **Strengths:** Can handle complex lighting scenarios, including indirect illumination and inscattering in participating media. [S2, book]
- **Limitations:** Slow convergence; requires many photons for accurate results. Less effective for spatially varying optical properties in volumes. [S2, book]

## Background
Photon mapping was introduced as a global illumination technique. The extension to participating media was developed by Jensen and Christiansen, who extended photon mapping to handle non-homogeneous materials and general phase functions. This approach simulates photon transport from light sources and stores scattering events in a photon map, which is then used in a final gather pass to compute inscattered light. [S2, book]
