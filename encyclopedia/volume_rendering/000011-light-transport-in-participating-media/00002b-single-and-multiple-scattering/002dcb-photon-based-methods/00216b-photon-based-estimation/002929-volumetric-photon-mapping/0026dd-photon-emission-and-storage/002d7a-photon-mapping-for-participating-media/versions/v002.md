# Photon Mapping for Participating Media

Also called: Jensen and Christensen, Volume Photon Map

## Overview
Photon Mapping for Participating Media extends surface-based photon mapping to handle light transport within volumetric media [S1][S2, book]. It addresses indirect illumination in participating media by precomputing photon interactions in a volume photon map and estimating radiance via density estimation during a final gather pass [S1][S2, book]. It is distinguished from surface-only photon mapping by its derivation of a distinct radiance estimate formula specifically for volume photons [S1].

## How it works
The method consists of two main phases: a preprocess phase that builds a volume photon map, and a rendering phase that estimates radiance using this map [S1][S2, book].

### Inputs and Outputs
*   **Inputs**: Light source positions and spectra, scene geometry, and participating media definitions including spatially varying optical properties and general phase functions [S2, book].
*   **Outputs**: A rendered image containing inscattered indirect illumination within the volume [S1][S2, book].

### Data Structures
The core data structure is the **Volume Photon Map**, a spatial data structure storing photons that have interacted with the participating media [S1][S2, book]. Each photon record stores the 3D position $\mathbf{x}$ of the scattering event, the direction of incidence $\Omega_i$, and the photon's energy [S1].

### Algorithm Steps

**Phase 1: Preprocess (Photon Tracing)**
1.  **Photon Emission**: Emit photons from light sources into the scene [S2, book].
2.  **Transport Simulation**: Trace photons through the scene using Monte Carlo simulation [S2, book].
    *   If a photon hits a surface, handle reflection or refraction according to surface material properties [S2, book].
    *   If a photon enters a participating medium, simulate transport through the volume [S2, book].
    *   At each step, determine the distance to the next interaction using the extinction coefficient $\sigma_t(\mathbf{x})$ [S2, book].
    *   At an interaction point $\mathbf{x}$, determine if scattering or absorption occurs based on the albedo $\omega_0 = \sigma_s / \sigma_t$ [S2, book].
    *   If scattering occurs, compute the new direction $\Omega_o$ using the phase function $p(\Omega_i \to \Omega_o)$, such as the Schlick phase function [S1].
    *   **Storage Condition**: Store the photon in the Volume Photon Map only if it represents indirect illumination [S1].
    *   **Indirect Illumination Only**: This includes photons that have been reflected or transmitted by surfaces before interacting with the media, and photons that have been scattered at least once in the media [S1].
    *   Record the position $\mathbf{x}$, the direction of incidence $\Omega_i$, and the photon's energy in the spatial data structure [S1].
    *   Continue tracing until the photon is absorbed or leaves the scene [S2, book].

**Phase 2: Rendering (Final Gather)**
1.  **View Ray Tracing**: Trace rays from the camera into the scene for each pixel [S2, book].
2.  **Interaction Point Identification**: Identify points along the view rays that intersect the participating media [S1].
3.  **Radiance Estimation**: For each interaction point $\mathbf{x}$ on the view ray, estimate the inscattered radiance using density estimation from the Volume Photon Map [S1].
    *   Query the spatial data structure for relevant photons near $\mathbf{x}$ [S1].
    *   Compute the estimated radiance $L_{est}(\mathbf{x}, \Omega_o)$ using the derived density estimation formula for the volume photon map [S1]. The formula accounts for the volume density of photons and the phase function to recover the radiance toward the eye direction $\Omega_o$ [S1].
    *   The direction of incidence $\Omega_i$ stored in the photon map is used to correctly evaluate the phase function $p(\Omega_i \to \Omega_o)$ for anisotropic scattering [S1]. This is critical for recovering source radiance toward the eye in anisotropic scattering cases [S1].
4.  **Image Formation**: Combine the estimated inscattered radiance with other lighting components to form the final pixel color [S2, book].

### Parameters and Typical Values
*   **Number of Photons**: A large number of photons is required for accurate convergence [S2, book].
*   **k-nearest neighbors**: The number of photons used in the density estimation kernel. Not given in the sources.
*   **Phase Function**: Schlick phase function is mentioned as an example [S1].

### Edge Cases and Pitfalls
*   **Performance**: The method can be slow because many photons are required for accurate convergence [S2, book].
*   **Anisotropic Scattering**: Failure to store the direction of incidence $\Omega_i$ at hit points will prevent correct recovery of source radiance toward the eye during rendering for anisotropic media [S1].
*   **Indirect Illumination Only**: The volume photon map is strictly for indirect illumination, meaning direct illumination from light sources must be handled separately or via a different mechanism [S1].

## Operating characteristics
*   **Time Complexity**: Slow due to the requirement of many photons for accurate convergence [S2, book]. The preprocessing phase involves tracing a large number of photons through the volume, and the rendering phase involves spatial data structure queries for each interaction point [S1][S2, book].
*   **Memory Complexity**: Proportional to the number of stored photons [G].
*   **Strengths**: Can handle non-homogeneous materials with spatially varying optical properties and general phase functions [S2, book]. Accurately captures complex indirect lighting effects like volume caustics in fog [S1].
*   **Limitations**: Computationally expensive and requires many photons for low noise [S2, book].
*   **When to use**: When accurate rendering of indirect illumination and caustics in participating media is required, and computational resources allow for a large number of photons [S1][S2, book].
*   **When not to use**: When real-time performance is critical or when scenes are simple homogeneous volumes [G].

## Background
Photon Mapping for Participating Media was introduced by Jensen and Christensen [37] (cited as Jensen and Christiansen in [S2, book]) [S1][S2, book]. It extends the original photon mapping technique, which was limited to surfaces, to handle participating media [S1]. The method was developed to address the limitations of previous approaches in rendering complex light transport effects in volumes, such as fog and indirect illumination [S1]. It is based on the Monte Carlo simulation of photon transport and uses density estimation for radiance estimation [S1][S2, book].
