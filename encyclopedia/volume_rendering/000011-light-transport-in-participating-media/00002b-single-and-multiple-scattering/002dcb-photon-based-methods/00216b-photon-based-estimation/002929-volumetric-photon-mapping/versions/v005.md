# Volumetric Photon Mapping

Also called: Photon Mapping in Participating Media, Real-time volume rendering for three-dimensional fetal ultrasound using volumetric photon mapping, Screen-space volumetric photon mapping, Volume Photon Map Creation, Volumetric Photon Mapping (VPM) for Fetal Ultrasound, Volumetric Photon Mapping (VPM) for Real-Time Fetal Ultrasound, Volumetric photon mapping with screen-space destiny estimation

## Overview
Volumetric Photon Mapping (VPM) is a global illumination technique for participating media that simulates light transport by decoupling the simulation of indirect illumination from direct illumination [S1]. It solves the problem of computing realistic in-scattering and absorption in complex volumes (such as medical ultrasound data) by storing photon interactions in a spatial data structure and estimating radiance via density estimation [S2, S5]. Unlike standard ray-marching methods that integrate the Radiative Transfer Equation (RTE) directly, VPM approximates the multiple-scattering component using a photon map, allowing for efficient handling of caustics and indirect lighting effects that are difficult to capture with local illumination models [S1]. It sets itself apart from its sibling [Beam Radiance Estimate](1283-beam-radiance-estimate.md) by using discrete point-to-point density estimation rather than continuous beam-based integration, and from [Photon Beam Storage in BVH](2275-photon-beam-storage-in-bvh.md) by storing discrete photon packets rather than beam segments [S1, S2].

## How it works
Volumetric Photon Mapping operates in two distinct phases: a preprocessing phase (photon emission and storage) and a rendering phase (density estimation and integration) [S1, S2].

### Inputs and Outputs
*   **Inputs:**
    *   Volume dataset (e.g., 3D ultrasound texture) with extinction $\sigma_t$, scattering $\sigma_s$, and absorption $\sigma_a$ coefficients [S1].
    *   Light source positions and intensities [S1].
    *   Camera parameters (origin, direction, samples per pixel) [S1].
    *   Phase function parameters (e.g., anisotropy $g$) [S1].
    *   Photon count $N_{photons}$ [S1].
    *   Exposure parameter $E$ (luminance scaling) [S1].
    *   Search radius $r$ (or squared radius $r^2$) for density estimation [S4, S6, unofficial].
*   **Outputs:**
    *   Rendered image with direct and indirect illumination [S1].
    *   Photon map data structure (volume texture or KD-tree) [S1].

### Data Structures
The method supports two primary storage layouts for the photon map [S1][S4, unofficial]:

1.  **Volume Texture (GPU-Optimized):**
    *   A 3D texture matching the volume resolution.
    *   Stores photon flux/energy at interaction points.
    *   Used to avoid KD-tree overhead and enable real-time performance [S1].
    *   *Note:* Traditional VPM uses KD-trees, but this variant explicitly replaces them with volume textures to minimize storage space and accelerate gathering [S1].

2.  **Standard Photon Map (CPU/General):**
    *   List of photons, each containing:
        *   Position $\mathbf{p}$ (3 floats) [S1].
        *   Incidence direction $\boldsymbol{\omega}_i$ (3 floats) [S1].
        *   Power/Energy $P$ (3 floats, RGB) [S1].

### Numbered Steps

#### Phase 1: Photon Emission and Storage
1.  **Preprocessing:** Apply anisotropic diffusion filtering to the input volume data to reduce speckle noise, which degrades gradient-based normal calculations [S1].
2.  **Emission Loop:**
    *   Initialize a shared counter `Count = 0` [S1].
    *   For each photon $k$ from $1$ to $N_{photons}$:
        *   Emit a photon from a light source with random propagation direction [S1].
        *   Cast a ray from the light source. If it intersects scene geometry, handle surface interactions (reflection/absorption/transmission) using Russian Roulette with a 50% termination probability after 3 bounces [S6, unofficial].
        *   If the ray enters the volume, divide the path into steps of constant size with jitter [S6, unofficial].
        *   For each step, determine interaction using the cumulative distribution function based on extinction [S6, unofficial].
        *   **Interaction:**
            *   If interaction occurs:
                *   Record position $\mathbf{p}$, incidence direction $\boldsymbol{\omega}_i$, and incident energy $P$ [S1].
                *   Store this photon in the photon map (Volume Texture or KD-tree) [S1].
                *   Determine fate: Absorption or Scattering [S6, unofficial].
                *   If Scattering: Sample a new direction $\boldsymbol{\omega}_o$ using the phase function (e.g., Henyey-Greenstein) [S1].
                *   Update photon energy $P$ based on scattering coefficient and Russian Roulette [S1][S6, unofficial].
            *   If no interaction: Continue marching. If surface hit, store surface photon [S6, unofficial].
        *   Increment `Count`. If `Count == N_{photons}`, terminate emission [S1].

#### Phase 2: Rendering (Density Estimation)
1.  **Direct Illumination:**
    *   Calculate single-scattering radiance $L_{ss}$ directly for each sample point along the camera ray [S1].
    *   Formula:
        $$ L_{ss}(x', \omega_0) = \int_{\Omega} s(x', \omega_i, \omega_0) L_i(x', \omega_i) d\omega_i $$
        where $s$ is the shading function and $L_i$ is attenuated incident radiance [S1].
2.  **Indirect Illumination (VPM Gather):**
    *   For each camera sample point $x_s$ along the ray:
        *   Initialize energy accumulator $E_{acc} = 0$ [S4, unofficial].
        *   Set squared search radius $r^2$ (e.g., $0.7^2$) [S4, unofficial].
        *   **Gather Photons:**
            *   Iterate through all volume photons $i$ in the map [S4, unofficial].
            *   Calculate distance $d$ from $x_s$ to photon position $\mathbf{p}_i$:
                $$ d = \| x_s - \mathbf{p}_i \| $$
            *   If $d^2 < r^2$:
                *   Calculate weight $w$. In the specific GPU texture implementation, the normal-based cosine term is often zeroed out or simplified, and weight is primarily determined by distance and exposure [S4, unofficial]:
                    $$ w = \frac{P_i}{N_{vol}} \cdot \frac{1.0 - d}{E} $$
                    where $P_i$ is the photon power, $N_{vol}$ is the total number of volume photons, and $E$ is the exposure parameter [S4, unofficial].
                    *Note:* Standard VPM uses a kernel function $K(d/r)$, but this specific implementation overwrites the weight with a simplified distance/exposure factor [S4, unofficial].
                *   Add contribution to accumulator:
                    $$ E_{acc} += P_i \cdot w $$
3.  **Radiance Integration:**
    *   Compute total scattered radiance $L_s$ as the sum of direct and indirect components:
        $$ L_s(x', \omega_0) = L_{ss}(x', \omega_0) + L_{ms}(x', \omega_0) $$
        where $L_{ms}$ is approximated by the gathered energy $E_{acc}$ [S1].
    *   Integrate along the camera ray using the RTE approximation:
        $$ L(x_s, \omega_0) = L_0(x_0, \omega_0)T(x_0, x_s) + \sum_{j=1}^{n} \left( \prod_{i=j}^{n-1} T(x_i, x_{i+1}) \right) \int_{x_{j-1}}^{x_j} T(x', x_j) \sigma_s(x') L_s(x') dx' $$
        where $T(x_i, x_j) = e^{-\int_{x_i}^{x_j} \sigma_t dt}$ is the transmittance [S1].
    *   Apply High Dynamic Range (HDR) tone mapping to handle intensity ranges exceeding display capabilities [S1].

### Pseudocode

```python
def volumetric_photon_mapping(volume_data, light_sources, camera, num_photons, exposure, search_radius_sq):
    """
    Main entry for Volumetric Photon Mapping.
    volume_data: 3D array of extinction/scattering coefficients.
    light_sources: List of light positions and intensities.
    camera: Camera origin and ray directions.
    num_photons: Total photons to emit.
    exposure: Luminance scaling factor.
    search_radius_sq: Squared radius for photon gathering.
    """
    
    # Phase 1: Photon Emission
    photon_map = [] # List of (position, direction, power)
    count = 0
    
    # Thread co-completion simulation for emission efficiency [S1]
    while count < num_photons:
        photon = emit_photon(light_sources, volume_data)
        photon_map.append(photon)
        count += 1
        
    # Phase 2: Rendering
    image = []
    for ray in camera.rays:
        ray_color = Vector3(0, 0, 0)
        current_pos = ray.origin
        transmittance = 1.0
        
        # Ray marching through volume
        for step in ray.march(volume_data):
            pos = step.position
            dist = step.distance
            
            # 1. Direct Illumination (Single Scattering)
            L_ss = calculate_direct_illumination(pos, ray.direction, light_sources, volume_data)
            
            # 2. Indirect Illumination (VPM Gather)
            L_ms = gather_indirect_radiance(pos, photon_map, search_radius_sq, exposure, len(photon_map))
            
            # 3. Total Scattered Radiance
            L_s = L_ss + L_ms
            
            # 4. Integrate into Ray
            # L(x_s) = L_0 * T + sum( T_prev * sigma_s * L_s * dx )
            sigma_s = volume_data.get_scattering(pos)
            extinction = volume_data.get_extinction(pos)
            
            # Transmittance to next step
            T_step = exp(-extinction * dist)
            
            # Accumulate in-scattering
            # Simplified Riemann sum approximation
            contribution = sigma_s * L_s * dist * transmittance
            ray_color += contribution
            
            transmittance *= T_step
            current_pos += ray.direction * dist
            
        # Add background/transmitted light
        ray_color += camera.background * transmittance
        
        # HDR Tone Mapping
        image.append(tone_map(ray_color))
        
    return image

def emit_photon(light_sources, volume_data):
    """
    Emits a single photon and traces it through the volume.
    Returns (position, direction, power).
    """
    light = random.choice(light_sources)
    direction = random_direction()
    power = light.intensity
    
    pos = light.position
    path = []
    
    # Russian Roulette for termination
    for bounce in range(10):
        if random() < 0.5 and bounce > 3: # 50% termination after 3 bounces [S6, unofficial]
            break
            
        # March through volume
        step = march_volume(pos, direction, volume_data)
        if step.interacted:
            # Store photon at interaction point
            path.append((step.pos, direction, power))
            
            # Determine fate: Absorption or Scattering
            if random() < volume_data.get_absorption_ratio(step.pos):
                break # Absorbed
            else:
                # Scatter
                new_direction = sample_phase_function(direction, volume_data.phase_g)
                power *= volume_data.get_scattering_coefficient(step.pos)
                direction = new_direction
                pos = step.pos
        else:
            pos += direction * step.distance
            
    return path[0] if path else None

def gather_indirect_radiance(query_point, photon_map, radius_sq, exposure, num_photons):
    """
    Estimates in-scattered radiance at query_point using stored photons.
    """
    energy = 0.0
    for photon in photon_map:
        p_pos, p_dir, p_power = photon
        
        dist_sq = distance_sq(query_point, p_pos)
        
        if dist_sq < radius_sq:
            # Weight calculation specific to the GPU texture implementation [S4, unofficial]
            # Note: Normal term is zeroed in the source code provided [S4, unofficial]
            weight = (1.0 - sqrt(dist_sq)) / exposure
            weight = max(0.0, weight)
            
            # Contribution
            energy += p_power * weight / num_photons
            
    return energy
```

### Parameters
*   **$N_{photons}$:** Number of photons. Controls realism and speed. Higher counts improve realism but reduce FPS. Large datasets require higher counts [S1].
*   **$E$ (Exposure):** Luminance value assigned to each photon. Influences brightness. Typical values: 0.3 to 0.4 [S1].
*   **$r$ (Search Radius):** Radius for density estimation. Typical squared radius $r^2 = 0.7$ [S4, unofficial].
*   **$g$ (Anisotropy):** Parameter for Henyey-Greenstein phase function. $g \in [-1, 1]$. Negative: back scattering; 0: isotropic; Positive: forward scattering [S1].
*   **Samples:** Number of samples per pixel during rendering. Fixed at 800 in tested datasets [S1].

### Edge Cases and Pitfalls
*   **Speckle Noise:** Ultrasound speckle noise degrades signal-to-noise ratio and makes gradient-based normal calculation unreliable. VPM is less sensitive to this than local illumination methods [S1].
*   **Storage Overhead:** Traditional KD-tree storage is memory-intensive and slow for gathering. Using a volume texture mitigates this but is limited to surface rendering in some prior works (Czuczor et al.), though this method adapts it for volume [S1].
*   **GPU Thread Scheduling:** Emitting photons one-per-thread causes idle time. Co-completing emission tasks using a shared counter minimizes idle thread time [S1].
*   **Weight Calculation Bug:** In some implementations, the normal-based weighting term `dot(N, photon_direction)` is initialized to zero, rendering it ineffective. The weight relies solely on distance and exposure [S4, unofficial].
*   **Emission Term:** In fetal ultrasound rendering, emission is often ignored, simplifying the RTE by removing the $\lambda_a L_e$ term [S1].

## Subtopics

### [Beam Radiance Estimate](1283-beam-radiance-estimate.md)
The Beam Radiance Estimate (BRE) is a photon-based technique for estimating accumulated in-scattered radiance along an entire camera ray in participating media, serving as the core gathering step for Volumetric Photon Mapping. Unlike conventional volumetric photon mapping, which estimates incident radiance at discrete points along a ray via spherical neighborhood queries, BRE queries all photons intersecting the ray line simultaneously, replacing Dirac delta and Heaviside functions with a 2D smoothing kernel perpendicular to the ray. This approach eliminates redundant photon gathering and noise associated with large step sizes in ray marching, concentrating computational effort only where photons intersect the viewing path.

### [Photon Emission and Storage](3880-photon-emission-and-storage.md)
Photon Emission and Storage is the preprocessing phase of Volumetric Photon Mapping that generates photon paths from light sources and records their positions, directions, and energy densities into spatial data structures for both surface intersections and volumetric scattering events. It solves the problem of efficiently capturing indirect lighting and caustics in participating media by decoupling the complex light transport simulation from the final image synthesis, allowing for density estimation during a subsequent gather pass. Unlike direct integration methods, it pre-computes photon interactions, and it is distinguished from its sibling [Beam Radiance Estimate](1283-beam-radiance-estimate.md) by storing discrete photon packets rather than continuous beam radiance estimates.

### [Photon Beam Tracing](5401-photon-beam-tracing.md)
Photon Beam Tracing is a volumetric radiance estimation method where photon paths are stored as beam segments rather than discrete points, allowing for density estimation via beam intersection. It differs from standard volumetric photon tracing by storing the photon energy up to the point of intersection with solid geometry, rather than discarding the photon upon collision. This approach provides a superset of the information contained in a standard photon map, enabling more efficient handling of boundaries between participating media and opaque surfaces.

### [Progressive Photon Mapping](6672-progressive-photon-mapping.md)
Progressive Photon Mapping is a volumetric light transport method that addresses the memory bottlenecks of traditional photon-based estimation by replacing a single, massive volumetric photon map with a series of small, iterative photon maps. It builds on [Volumetric Photon Mapping](2190-volumetric-photon-mapping.md) by adopting a multipass strategy where photon contributions are updated incrementally, allowing for the efficient handling of participating media without exhausting system memory. It sets itself apart from siblings like [Beam Radiance Estimate](1283-beam-radiance-estimate.md) by using a global, iterative refinement of photon density rather than local beam-based approximations.

## Operating characteristics
*   **Time Complexity:**
    *   Emission: $O(N_{photons} \cdot N_{steps})$, where $N_{steps}$ is the average number of scattering events per photon [S1].
    *   Gathering: $O(N_{samples} \cdot N_{photons})$ for naive search, or $O(N_{samples} \cdot \log N_{photons})$ with KD-tree [S1]. The volume texture approach aims for $O(1)$ access but requires linear scan or texture filtering [S1].
*   **Memory Complexity:** $O(N_{photons})$. Memory costly due to the requirement of a huge volumetric photon map [S2].
*   **Measured Performance:**
    *   Hardware: Intel E5, 8GB RAM, GPU [S1].
    *   Fetus 1 (289x212x266, 800 samples, exposure 0.4, 17 photons): 217 FPS [S1].
    *   Fetus 2 (183x115x126, 800 samples, exposure 0.4, 22 photons): 222 FPS [S1].
    *   Fetus 3 (209x175x209, 800 samples, exposure 0.3, 18 photons): 218 FPS [S1].
    *   Fetus 4 (196x128x122, 800 samples, exposure 0.4, 20 photons): 220 FPS [S1].
    *   Real-time performance maintained even with up to 10 million photons [S1].
*   **Strengths:**
    *   Simulates realistic global illumination effects (scattering) and provides more depth information than local illumination [S1].
    *   Robust against speckle noise in ultrasound images [S1].
    *   Real-time performance achievable with GPU acceleration and volume texture storage [S1].
*   **Limitations:**
    *   Requires GPU acceleration for real-time performance [S1].
    *   Insufficient photons on large volumes produce unrealistic results [S1].
    *   High memory usage for large photon counts [S2].
    *   Not suitable for emission-heavy scenes without modification [S1].

## Background
Volumetric Photon Mapping was developed based on the common photon mapping algorithm introduced by Henrik Wann Jensen [S1, S29]. Jensen generalized photon mapping from surface light travel to volume light transport by storing volumetric interactions as photons and estimating density using a 3D kernel [S2]. The specific real-time application for 3D fetal ultrasound was proposed by Qin Jing et al. to address the challenges of speckle noise and low contrast in ultrasound data, which traditional local-illumination methods fail to handle satisfactorily [S1]. The method separates direct and indirect illumination, using single scattering for direct light and VPM for multiple scattering, to achieve realistic visualization in real-time [S1].
