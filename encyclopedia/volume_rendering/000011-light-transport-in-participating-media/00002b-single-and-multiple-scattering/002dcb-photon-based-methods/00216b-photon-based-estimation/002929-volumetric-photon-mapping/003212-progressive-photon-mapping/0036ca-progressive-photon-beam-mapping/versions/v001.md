# Progressive Photon Beam Mapping


## Overview
Progressive Photon Beam Mapping is a volumetric light transport method that addresses the memory bottlenecks of traditional photon-based estimation by replacing a single, massive volumetric photon map with a series of small, iterative photon maps [S1]. It builds on [Progressive Photon Mapping](6672-progressive-photon-mapping.md) by adopting a multipass strategy where photon contributions are updated incrementally, allowing for the efficient handling of participating media without exhausting system memory [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Scene geometry, participating media properties (scattering coefficient, phase function), light source parameters, and iteration count.
*   **Outputs:** Estimated radiance at shading points.

**Data Structures:**
*   **Small Photon Map:** A temporary data structure storing photon beam data (origin, direction, power) generated in the current iteration. The exact internal layout is not specified in the sources, but it is distinct from the "huge volumetric photon map" used in non-progressive variants [S1].
*   **Shading Points:** Locations in the volume where radiance is estimated.

**Algorithm Steps:**
1.  **Initialize:** Set iteration counter $i = 0$.
2.  **Iterate:** While convergence criteria are not met or maximum iterations reached:
    a.  **Generate:** Emit photons into the scene and store them in a temporary **Small Photon Map** [S1].
    b.  **Update:** For each shading point, query the **Small Photon Map** to estimate its radiance contribution. This involves a beam-to-beam estimator, which is noted to converge faster for certain media like fog compared to point-based estimators [S1].
    c.  **Accumulate:** Add the estimated contribution to the shading point's total radiance estimate.
    d.  **Discard:** Delete the **Small Photon Map** to free memory [S1].
    e.  **Increment:** $i = i + 1$.

**Parameters:**
*   **Iteration Count:** Determines the number of passes. Not given in the sources.
*   **Kernel Bandwidth:** Used in the density estimation step. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Memory Limitations:** The primary advantage is avoiding the memory cost of a huge volumetric photon map [S1].
*   **Convergence:** Convergence speed varies by media type; beams are noted to be suitable for low-order scattering objects, while photons are better for high-order scattering [S1].

## Subtopics
## Operating characteristics
*   **Memory Complexity:** Significantly reduced compared to non-progressive photon mapping, as only small photon maps are stored at any given time [S1].
*   **Time Complexity:** Proportional to the number of iterations. Each iteration requires generating photons and querying the map.
*   **Strengths:** Eliminates memory limitations associated with huge volumetric photon maps; improves practicality for large scenes or complex media [S1].
*   **Limitations:** Requires multiple passes; convergence behavior depends on the media type (beams vs. photons) [S1].
*   **When to Use:** When memory is a constraint and the media exhibits low-order scattering characteristics where beam-based estimation is effective [S1].

## Background
The method was proposed to overcome the memory costs of huge volumetric photon maps used in earlier photon-based methods [S1]. It is part of a broader effort to unify different light transport representations (points, beams, paths) for different media types, as observed by Křivánek et al. [S1]. The specific citation for the progressive photon beam method is reference [11] in the source survey, though the full reference details are not provided in the text [S1].
