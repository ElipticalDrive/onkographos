# Photon Beam Mapping

Also called: Photon Beam Methods

## Overview
Photon Beam Mapping is a photon-based method for rendering participating media that replaces discrete point photons with continuous photon beams during the lighting pass to create a more compact representation of light transport [S1]. This approach solves the problem of high variance and memory consumption associated with traditional point-based photon maps, particularly in media like fog where light is distributed over larger volumes [S1]. It sets itself apart from its sibling [Photon-based Estimation](2521-photon-based-estimation.md) by using a beam-to-beam estimator rather than a point-to-point or point-to-beam estimator, resulting in faster convergence for specific media types [S1].

## How it works
The method operates in two distinct phases: a lighting pass that stores light transport as photon beams, and a rendering pass that gathers contributions using a beam-to-beam estimator [S1].

**Inputs and Outputs**
*   **Input:** Light source positions, directions, and spectral power; scene geometry and participating media properties (extinction, scattering, phase functions); camera parameters.
*   **Output:** Radiance image.

**Data Structures**
The core data structure is a collection of photon beams. Unlike a standard photon map which stores points $(\vec{x}, \vec{\omega}, P)$, a photon beam stores a trajectory segment.
*   **Beam Segment:** Defined by a start point $\vec{x}_0$, an end point $\vec{x}_1$, a direction $\vec{\omega}$, and accumulated power $P$.
*   **Layout:** In a progressive implementation, these are stored in small, temporary photon maps that are generated, used, and discarded iteratively to eliminate memory limitations [S1].

**Numbered Steps**

1.  **Photon Beam Shooting (Lighting Pass):**
    *   Shoot beams from light sources into the participating medium.
    *   Trace the beam through the medium, accounting for extinction and scattering events.
    *   When a scattering event occurs, the beam may split or continue. The power is distributed along the beam trajectory.
    *   Store the resulting beam segments in the photon map. The representation is more compact than point photons because a single beam covers a volume [S1].

2.  **Beam-to-Beam Estimation (Rendering Pass):**
    *   For each pixel, trace a camera ray (view ray) through the scene.
    *   Identify photon beams that intersect or are in close proximity to the camera ray.
    *   Compute the contribution of each intersecting beam to the pixel's radiance using a beam-to-beam estimator.
    *   Sum the contributions from all relevant beams.

**Formulas**
The specific mathematical formulation for the beam-to-beam estimator is not provided in the sources [S1]. However, the method is described as an improvement over the point-to-beam estimator used by Jarosz et al. [9, 10], implying a density estimation kernel adapted for line segments rather than points [S1].

**Parameters**
*   **Beam Length:** Determines the spatial extent of each stored beam segment. Not given in the sources.
*   **Number of Beams:** Controls the density of the photon map. Not given in the sources.
*   **Progressive Iterations:** The number of iterations for generating small photon maps in the progressive variant. Not given in the sources.

**Edge Cases and Pitfalls**
*   **Memory Usage:** Traditional photon maps are memory costly due to the huge number of points required for low variance [S1]. The progressive variant addresses this by discarding small photon maps after use [S1].
*   **Surface Interactions:** The method is unable to handle medium interactions immediately following scattering from a surface, such as volumetric caustics, unless extended [S1].
*   **Bias:** Standard photon mapping is biased. Unbiased variants, such as those by Qin et al. [13], combine the photon path with the camera path to remove bias [S1].

**Pseudocode**
```python
def photon_beam_mapping(scene, camera, num_iterations):
    """
    Progressive Photon Beam Mapping implementation.
    """
    # Initialize output image
    image = zeros(camera.resolution)
    
    for iteration in range(1, num_iterations + 1):
        # Generate a small photon map for this iteration
        photon_map = generate_small_photon_map(scene, iteration)
        
        # Render the scene using the current photon map
        for pixel in camera.rays():
            radiance = 0.0
            # Beam-to-beam estimation
            for beam in photon_map.beams:
                if beam.intersects(pixel.ray):
                    radiance += beam_to_beam_estimator(beam, pixel.ray, scene)
            image[pixel] += radiance / iteration
            
        # Discard the small photon map to save memory
        del photon_map
        
    return image

def generate_small_photon_map(scene, iteration):
    """
    Shoots a subset of photon beams for the current iteration.
    """
    beams = []
    # Number of beams scales with iteration or is fixed per batch
    num_beams = get_beam_count_for_iteration(iteration)
    
    for _ in range(num_beams):
        # Shoot a beam from a light source
        beam = shoot_beam(scene)
        beams.append(beam)
        
    return PhotonMap(beams)

def shoot_beam(scene):

    Traces a single photon beam through the participating medium.

        if hit is None:

        # Record segment

        # Handle scattering

            power *= hit.scattering_albedo
            current_pos = hit.point
            current_dir = new_dir
        else:
            # Absorption
            break
            
    return Beam(beam_segments)
```

## Subtopics

### [Transient Photon Beams](3296-transient-photon-beams.md)
Transient Photon Beams (TPB) is a method for rendering time-resolved light transport in participating media that extends steady-state photon beams by incorporating photon time-of-flight along continuous beam trajectories. It addresses the high variance and sparse temporal sampling inherent in point-based photon methods by leveraging the spatial continuity of photon beams to densely populate the temporal domain. Unlike its sibling [Photon Beam Mapping](7874-photon-beam-mapping.md) which handles steady-state, TPB accounts for propagation and scattering delays, and unlike [Photon Marching](4775-photon-marching.md) which uses marching cubes for isosurfaces, TPB uses kernel density estimation for volumetric radiance. The progressive variant, Progressive Transient Photon Beams (PTPB), further reduces bias and variance by iteratively accumulating independent beam sets with progressively shrinking kernel bandwidths, achieving an optimal asymptotic convergence rate of $O(n^{-2/3})$.

### [Photon Beam Diffusion](3768-photon-beam-diffusion.md)
Photon Beam Diffusion (PBD) is a hybrid numerical method for rendering subsurface scattering in translucent materials that interprets incident light as a continuous beam of photons inside the material and uses Monte Carlo integration to solve the diffusion equation. It solves the problem of efficiently computing accurate multiple-scattering profiles without the quantization errors or computational overhead of sum-of-Gaussians approximations used in Quantized Diffusion (QD). Unlike its sibling [Transient Photon Beams](3296-transient-photon-beams.md) which handles time-dependent effects, or [Photon Marching](4775-photon-marching.md) which marches through media, PBD focuses on steady-state spatial diffusion using an extended source integral, offering faster convergence and numerical stability than standard Photon Diffusion (PD).

### [Photon Marching](4775-photon-marching.md)
Photon Marching is a photon shooting method that deposits energy at uniform intervals along rays originating from light sources, creating a "discrete photon beam". It differs from standard photon tracing (Markov random-walk) by distributing the power of a single photon among multiple photons deposited at fixed steps, analogous to the difference between random-walk volumetric path tracing and ray marching.

### Diffuse Single Scattering Integration
An explicit calculation of the diffuse single-scattering term using the same Monte Carlo integration strategy as multi-scattering, replacing the multi-scattering Green's function with a single-scattering response [S2, unofficial]. It computes the single-scattering profile $R^{(1)}(\vec{x}, \vec{\omega})$ using the same Monte Carlo estimator, but with $f(\vec{x}, \vec{\omega}, t_i) = r^{(1)}(\vec{x}, \vec{x}_r(t_i)) Q(t_i)$ [S2, unofficial]. The single-scattering response is given by:
$$ r^{(1)}(\vec{x}, \vec{x}_r(t)) = \frac{f_s(\vec{\omega} - \vec{x}_r(t)) e^{-t_0 d_r(t)} F_t(\theta_o, \eta) F_t(\theta_i, 1/\rho) \cos \theta_o}{d_r^2(t)} $$
where $\vec{x}_r(t)$ and $d_r(t)$ are the direction and distance from $\vec{x}_r(t)$ to $\vec{x}$, $\theta_o = \arccos(\vec{x}_r(t) - \vec{x} \cdot \vec{n})$, $\theta_i = \arccos(\vec{\omega} \cdot \vec{n})$, and $F_t$ and $f_s$ are transmissive Fresnel and phase function terms [S2, unofficial]. If the surface separates volumes with different indices of refraction, a separate sample sequence for single-scattering starting from the critical angle should be used, as contributions below the critical angle are zero [S2, unofficial].

### Unbiased Photon Gathering
An unbiased photon gathering method by Qin et al. [13] that combines each photon's path with the camera path into one path [S1]. It considers all factors in Monte Carlo methods such as visibility and probability to remove the bias [S1].

### Krueger's Transport Theory Model
A model describing existing volume rendering methods as special cases of an underlying transport theory model of particle transfer in inhomogeneous media [S3, unofficial]. A beam of 'virtual' particles is sent through the volume with user-selected properties and interaction laws [S3, unofficial]. The intensity $I$ at a pixel is a path integral along the view ray:
$$ I = \int_{p_{near}}^{p_{far}} \frac{(a(p) + \rho_{sc}(p) Q(p)) dp}{e^{\tau(p)}} $$
Emission at each point $p$ is scaled by optical depth to eye [S3, unofficial]. The generalized source $Q(p)$ is defined as:
$$ Q(p) = q(p) + \int \frac{\rho_{sc}(p)}{\rho_{sc}} I(S, \vec{u}) d\eta $$
Consists of emission $q(p)$ and incoming intensity along all directions scaled by scattering phase $\rho_{sc}$ [S3, unofficial]. Typically, a low albedo approximation is used to simplify calculations, reducing the integral to a sum over all light sources [S3, unofficial]. If virtual particles have photon properties and interaction laws are governed by optical laws, the model becomes a generalized ray tracer [S3, unofficial].

### Visibility Tracing
A problem of visibility of lighted exit signs in buildings through fire-caused non-uniform smoke, using parallelized Monte Carlo particle tracing method [S4]. It performs a single step: just a particle tracing phase [S4]. Whenever a bundle hits the image plane (receiver), the corresponding pixel is updated [S4]. Using a small number of bundles obtains a coarse solution [S4]. If higher accuracy is required, the energy of already traced bundles is re-scaled and more bundles are shot [S4].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Traditional photon maps are memory costly [S1]. The progressive variant reduces memory usage by generating, using, and discarding small photon maps iteratively [S1].
*   **Measured Performance:** Results in faster convergence for media like fog compared to point-based methods [S1].
*   **Scaling:** Not given in the sources.
*   **Strengths:** More compact representation than point photons; faster convergence for certain media; progressive variant eliminates memory limitations [S1].
*   **Limitations:** Unable to handle medium interactions immediately following scattering from a surface (e.g., volumetric caustics) in its basic form [S1].
*   **When to use:** Rendering participating media like fog where light transport is distributed over larger volumes and point-based methods suffer from high variance or memory constraints [S1].
*   **When not to use:** Scenes with complex surface-to-medium interactions like volumetric caustics, unless extended [S1].

## Background
Photon Beam Mapping was introduced by Jarosz et al. [10] as an improvement over previous photon mapping techniques for participating media [S1]. Jarosz et al. [9] previously improved convergence by gathering photon map contributions along camera rays using a point-to-beam estimator [S1]. Jarosz et al. [10] then replaced photons with photon beams in the lighting pass, creating a more compact representation and a beam-to-beam estimator for further faster convergence [S1]. A progressive method with photon beams was later proposed [11] to address the memory limitations of huge volumetric photon maps [S1]. Křivánek et al. [1] noted that different representations (points, beams, paths) are suitable for different types of participating media or surfaces [S1].
