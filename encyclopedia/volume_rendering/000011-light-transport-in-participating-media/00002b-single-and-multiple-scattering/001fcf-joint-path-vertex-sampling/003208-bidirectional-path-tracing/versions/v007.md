# Bidirectional Path Tracing

Also called: BPT, Bidirectional Path Tracing for Participating Media

## Overview
Bidirectional Path Tracing (BPT) is a stochastic light transport algorithm for participating media that constructs complete paths by connecting independent subpaths traced from light sources and the eye point [S2][S4, book]. It solves the high variance and slow convergence of unidirectional methods (like standard path tracing or light tracing) in scenes with refractive boundaries or complex scattering by ensuring both emitted radiance and sensor importance are included in the sampling density [S1][S3]. Unlike light tracing, which produces partial solutions that are not useful in short times, BPT is view-dependent and allows gradual improvement of image quality starting from a crude approximation [S4, book]. It is the only existing unbiased method for anisotropic media mentioned in the sources [S4, book].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Scene geometry, participating media properties (scattering coefficient $\sigma_s$, extinction coefficient $\sigma_t$, phase function $p$), light source definitions, camera parameters, and a random number generator.
*   **Outputs:** An unbiased estimator for the radiance $L$ reaching the eye.

**Data Structures:**
*   **Light Subpath:** A sequence of vertices $\mathbf{y}_0, \mathbf{y}_1, \dots, \mathbf{y}_{s-1}$, where $\mathbf{y}_0$ is on the light source and subsequent vertices are interaction points in the medium.
*   **Eye Subpath:** A sequence of vertices $\mathbf{z}_0, \mathbf{z}_1, \dots, \mathbf{z}_{t-1}$, where $\mathbf{z}_0$ is the eye/camera position and subsequent vertices are interaction points in the medium.
*   **Connection Segment:** A virtual segment connecting $\mathbf{y}_{s-1}$ and $\mathbf{z}_{t-1}$.

**Steps:**
1.  **Trace Light Subpath:** Trace a random walk from the light source to generate $s$ vertices $\mathbf{y}_0, \dots, \mathbf{y}_{s-1}$. Interaction points are computed within the media as in the Simple Absorption case [S2][S4, book]. The scattering direction at each vertex is computed using the Schlick phase function [S2][S4, book].
2.  **Trace Eye Subpath:** Trace a random walk from the eye point to generate $t$ vertices $\mathbf{z}_0, \dots, \mathbf{z}_{t-1}$, using the same interaction and scattering logic as the light subpath [S2][S4, book].
3.  **Connect Subpaths:** For each pair of endpoints $(\mathbf{y}_{s-1}, \mathbf{z}_{t-1})$, cast a shadow ray (connection segment) between them [S2][S4, book].
4.  **Check Occlusion:** Identify shadow rays that are not occluded by geometry or other media [S2][S4, book]. These constitute complete transport paths from the light source to the eye.
5.  **Compute Contribution:** For each valid connection, compute the illumination contribution using the BPT estimator formula [S5].
6.  **Weighting:** Use the balance heuristic to obtain the weights of the illumination contributions, combining the PDFs of the light and eye subpaths [S2][S4, book].

**Formulas:**
The BPT estimator for a light subpath with $s$ vertices and a camera subpath with $t = k + 1 - s$ vertices is [S5]:

$$
\langle I \rangle_{\text{BPT},s} = L_e(\mathbf{y}_0) \frac{T(\bar{\mathbf{y}})}{p(\bar{\mathbf{y}})} \rho(\mathbf{y}_{s-1}) T_t(\mathbf{y}_{s-1}, \mathbf{z}_{t-1}) G(\mathbf{y}_{s-1}, \mathbf{z}_{t-1}) \rho(\mathbf{z}_{t-1}) \frac{T(\bar{\mathbf{z}})}{p(\bar{\mathbf{z}})} W_e(\mathbf{z}_0)
$$

Where:
*   $s$ is the number of vertices in the light subpath.
*   $t = k + 1 - s$ is the number of vertices in the camera subpath.
*   $L_e(\mathbf{y}_0)$ is the emitted radiance from the light source.
*   $T(\bar{\mathbf{y}})$ is the transmittance along the light subpath.
*   $p(\bar{\mathbf{y}})$ is the probability density of the light subpath.
*   $\rho(\mathbf{y}_{s-1})$ is the scattering function at the light subpath endpoint.
*   $T_t(\mathbf{y}_{s-1}, \mathbf{z}_{t-1})$ is the transmittance of the connecting segment.
*   $G(\mathbf{y}_{s-1}, \mathbf{z}_{t-1})$ is the geometry factor between the endpoints.
*   $\rho(\mathbf{z}_{t-1})$ is the scattering function at the eye subpath endpoint.
*   $T(\bar{\mathbf{z}})$ is the transmittance along the eye subpath.
*   $p(\bar{\mathbf{z}})$ is the probability density of the eye subpath.
*   $W_e(\mathbf{z}_0)$ is the emitted radiance from the camera (often 1 or sensor sensitivity).

The PDF for the BPT configuration is [S5]:
$$
p_{\text{BPT},s} = p(\bar{\mathbf{y}})p(\bar{\mathbf{z}})
$$

**Parameters:**
*   **Subpath Lengths ($s, t$):** A $k$-length path can be constructed in $k+2$ different ways, yielding $k+2$ different sampling techniques [S5]. The specific split $s$ and $t$ determines which estimator variant is used.
*   **Phase Function:** The Schlick phase function is used for scattering direction computation [S2][S4, book].

**Pitfalls:**
*   **Infinite Variance:** Vertex-vertex connections can lead to high variance since none of the terms for the connecting segment are importance sampled, as it is a 0-random-decision subpath connecting the light and eye subpaths. In fact, the variance is infinite [S1].
*   **Anisotropic Media:** While many methods commit errors in anisotropic media, BPT is unbiased [S4, book].

**Pseudocode:**
```python
def bidirectional_path_tracing(scene, camera, rng):
    # Trace light subpath
    light_subpath = trace_light_subpath(scene, rng)
    
    # Trace eye subpath
    eye_subpath = trace_eye_subpath(scene, camera, rng)
    
    total_radiance = 0.0
    
    # Iterate over all possible connection points
    # s is the number of vertices in the light subpath
    # t is the number of vertices in the eye subpath
    # A full path has k+2 vertices, so s+t = k+1
    for s in range(len(light_subpath)):
        t = len(eye_subpath) - 1 - s # Adjust based on total path length k
        
        if t < 0:
            continue
            
        y_end = light_subpath[s]
        z_end = eye_subpath[t]
        
        # Check if connection is valid (not occluded)
        if is_visible(y_end, z_end, scene):
            # Compute transmittance and geometry factor for the connection
            T_conn = compute_transmittance(y_end, z_end, scene)
            G_conn = compute_geometry_factor(y_end, z_end)
            
            # Compute the BPT estimator
            # Note: This is a simplified representation of the complex formula
            # involving full subpath PDFs and transmittances
            radiance = compute_bpt_estimator(
                light_subpath, 
                eye_subpath, 
                s, 
                t, 
                T_conn, 
                G_conn,
                scene
            )
            
            # Apply balance heuristic weight
            weight = compute_balance_heuristic(light_subpath, eye_subpath, s, t)
            total_radiance += radiance * weight
            
    return total_radiance
```

## Subtopics

### [Bidirectional Path-Space Differentiable Rendering](7618-bidirectional-path-space-differentiable-rendering.md)
Bidirectional Path-Space Differentiable Rendering computes gradients of a rendering equation with respect to scene parameters by constructing a differentiable path space using both light and eye subpaths. It sets itself apart from unidirectional differentiable methods by leveraging the bidirectional structure of [Bidirectional Path Tracing](6666-bidirectional-path-tracing.md) to reduce variance in gradient estimation for complex light transport, specifically addressing the discontinuities inherent in path-space derivatives [7618-bidirectional-path-space-differentiable-rendering.md].

### [Primary Sample Space Transformation Layout](9592-primary-sample-space-transformation-layout.md)
A data layout for storing the primary sample vector $\bar{u}$ in Bidirectional Path Tracing (BDPT) to ensure that small changes in the sample space $U$ correspond to small changes in the path space $P$. It solves the problem of sample correlation in heterogeneous participating media by separating random numbers for eye/light subpaths and between scattering/propagation steps, unlike standard BDPT which uses successive dimensions of $U$ directly.

### [Unified Path-based Photon Path (UPBP) Recursive Weight Calculation](10612-unified-path-based-photon-path-upbp-recursive-weight-calcula.md)
UPBP Recursive Weight Calculation is a method for efficiently computing Multiple Importance Sampling (MIS) weights in Bidirectional Path Tracing (BPT) and Photon Density Estimation (PDE) estimators within participating media. It solves the problem of expensive path weight re-evaluation by caching partial sums that remain constant as subpaths are extended, avoiding the storage of full path weights. Unlike methods that store full path weights, UPBP stores only the recursive $d$-quantities, which are updated incrementally as the subpath is traced [10612-unified-path-based-photon-path-upbp-recursive-weight-calcula.md].

### Bidirectional Path Tracing with Approximate Densities
An adaptation of BDPT for participating media where propagation densities $p_i$ are approximated because they are not analytically computable in heterogeneous media [S6]. To preserve the good properties of the heuristics without introducing bias, $\tau$ is approximated by a deterministic quadrature rule, ensuring weights produced by the power heuristic sum up to one [S6]. The multi-sample estimator is:
$$
F = \sum_{i=1}^n \frac{1}{n_i} \sum_{j=1}^{n_i} w_{ij}(x_{i,j}) \frac{f(x)}{p_i(x_{i,j})}
$$
The power heuristic uses an exponent $\beta$, where $\beta=1$ is the balance heuristic and $\beta \to \infty$ is the maximum heuristic [S6]. A pitfall is that using Algorithm 2 to approximate $\tau$ for density estimation in MIS fails condition (17) (weights summing to 1 in expectation) for all but the maximum heuristic [S6].

## Operating characteristics
*   **Time Complexity:** Proportional to the number of subpath vertices and the number of connections attempted. A $k$-length path yields $k+2$ sampling techniques, increasing computational cost compared to unidirectional methods [S5].
*   **Memory Complexity:** Depends on the storage of subpath vertices. Since subpaths are traced independently, memory usage is linear with respect to subpath length.
*   **Measured Performance:** In short times, BPT provides a usable, view-dependent approximation, unlike light tracing which produces partial solutions that are not useful [S4, book]. It improves convergence rate for light transport with refractive boundaries [S3].
*   **Strengths:** Unbiased for anisotropic media [S4, book]. View-dependent, allowing for progressive refinement [S4, book]. Combines light shooting and light gathering [S2].
*   **Limitations:** High variance due to vertex-vertex connections (infinite variance in some cases) [S1]. Computationally expensive due to multiple sampling techniques [S5].
*   **When to use:** Scenes with refractive boundaries, anisotropic media, or where view-dependent progressive rendering is required [S3][S4, book].
*   **When not to use:** Scenes where unidirectional methods are sufficient and computational resources are limited, or where the infinite variance of vertex connections is a critical issue [S1].

## Background
Bidirectional Path Tracing was introduced by Lafortune and Willems to improve convergence rates for light transport with refractive boundaries [S3]. It expands on the ideas of path tracing to a bidirectional approach, combining light shooting (random walks from light sources) and light gathering (random walks from the eye point) [S2]. It is an image-based method [S4, book]. The method uses the balance heuristic to combine illumination contributions from different subpath connections [S2][S4, book]. It is cited as the only existing unbiased method for anisotropic media in the context of the surveyed techniques [S4, book].
