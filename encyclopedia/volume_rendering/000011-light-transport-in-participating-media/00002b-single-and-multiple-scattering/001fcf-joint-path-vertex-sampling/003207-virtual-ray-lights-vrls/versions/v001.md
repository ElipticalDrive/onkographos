# Virtual ray lights (VRLs)

Also called: Novak et al. method, VRL integration

## Overview
Virtual ray lights (VRLs) is a many-light rendering method for participating media that reinterprets the accumulation of light transport as a bidirectional segment-segment connection technique [S1]. It traces rays from light sources, stores the first ray segment after a surface interaction as a "Virtual Ray Light," and organizes these segments into a grid hierarchy to efficiently compute multiple scattering contributions to camera rays using precomputed tables [S2]. Unlike standard path tracing which samples paths stochastically, VRLs use a deterministic lookup based on geometric relationships between light segments and eye segments, trading memory for speed in dense media [S2].

## How it works
### Inputs and Outputs
**Inputs:**
*   $S$: Camera segment ray defined by origin $P$ and direction $\omega_t$ (or endpoint $d$ and direction $\omega_{dc}$ in the connection view) [S1, S2].
*   $G$: Grid hierarchy containing all VRLs [S2].
*   $A$: Accumulated segment table (precomputed radiance data) [S2].
*   $\epsilon$: Solid angle threshold for culling [S2].

**Outputs:**
*   $R$: Multiple scattering radiance contribution [S2].

### Data Structures
**VRL Attributes [S2]:**
Each Virtual Ray Light stores:
1.  Position of ray origin ($v$).
2.  Ray direction ($d$).
3.  Light ray length before the next surface event.
4.  Radiance at the ray origin.

**Grid Hierarchy [S2]:**
*   Structure: Two to five levels of regular grids. Level $i+1$ is computed from level $i$ by merging eight grid cells together.
*   Cell Content:
    *   Index of all VRLs inside the cell.
    *   A representative VRL.
    *   Bounding box.
*   Storage: VRLs are stored in a 1D buffer, reordered for continuous storage per cell.

### Formulas
**Cylindrical Coordinates [S2]:**
To map a camera ray point $P$ relative to a VRL axis defined by origin $v$ and direction $d$:
$$ z = (P - v) \cdot d $$
$$ \rho = \|(P - v) - z d\| $$
where $z$ is the axial distance and $\rho$ is the radial distance from the VRL axis.

**Weight Factor [S2]:**
The weight $W$ accounts for the ratio of the camera segment length to the accumulated segment length (defined as $5 \times$ mean-free path, $\ell$):
$$ W = \frac{\sum_{i=1}^k e^{-i\ell}}{\sum_{i=1}^5 e^{-i\ell}} $$
where $k$ is the length of the camera segment divided by $5 \times \ell$.

**Radiance Reconstruction [S2]:**
The multiple scattering contribution is computed using a precomputed table $\hat{\Phi}$:
$$ \text{mult}(P, \omega_t) = W \hat{\Phi}\left(\frac{\rho}{\ell}, \frac{z}{\ell}, T_{(v,d)}(\omega_t)\right) $$
where $T_{(v,d)}(\omega_t)$ is the direction transformation of $\omega_t$ into the frame defined by $(v, d)$.

### Algorithm
The rendering loop iterates over grid cells and VRLs to accumulate radiance [S2]:

```python
def compute_vrl_radiance(camera_segment, grid_cells, segment_table, epsilon):
    """
    Computes multiple scattering radiance for a camera segment using VRLs.
    
    Args:
        camera_segment: Object containing origin P, direction omega_t, and length.
        grid_cells: List of grid cells in the hierarchy.
        segment_table: Precomputed table A of radiance values.
        epsilon: Solid angle threshold for culling.
        
    Returns:
        R: Accumulated radiance.
    """
    R = 0.0
    
    for cell in grid_cells:
        # Discard grid cells with small contribution
        if solid_angle(cell.bounding_box, camera_segment.origin) <= epsilon:
            continue
            
        vrls = cell.vrls # List of VRLs in this cell
        
        for vrl in vrls:
            # Compute relative coordinate between vrl and camera segment
            # This involves calculating z and rho as defined in formulas
            z = dot(camera_segment.origin - vrl.origin, vrl.direction)
            rho = norm((camera_segment.origin - vrl.origin) - z * vrl.direction)
            
            # Determine index in the accumulated segment table
            # The index depends on normalized rho, z, and transformed direction
            index = get_table_index(rho, z, vrl.direction, camera_segment.direction)
            
            # Weight of segment length
            # Calculate k based on camera segment length and mean-free path
            k = camera_segment.length / (5.0 * vrl.mean_free_path)
            
            # Calculate W
            numerator = sum(exp(-i * vrl.mean_free_path) for i in range(1, int(k) + 1))
            denominator = sum(exp(-i * vrl.mean_free_path) for i in range(1, 6))
            W = numerator / denominator
            
            # Add contribution
            # power(vrl) is the radiance at the ray origin
            # weight(S) is effectively the weight W and table lookup
            R += segment_table[index] * vrl.radiance * W
            
    return R
```

### Parameters
*   **Solid angle threshold $\epsilon$**: Used to discard grid cells with small contribution [S2].
*   **Accumulated segment length**: Defined as $5 \times$ mean-free path ($\ell$) [S2].

### Edge Cases and Pitfalls
*   **Precision**: The exponential terms in $W$ can underflow for large $i$ or small $\ell$. [G] Implementation should use log-sum-exp or careful ordering to maintain numerical stability.
*   **Boundaries**: The grid hierarchy must handle VRLs near cell boundaries correctly. The 1D buffer reordering ensures continuous storage, but index mapping must be precise.
*   **Degenerate Input**: If a VRL direction is parallel to the camera ray, $\rho$ may be zero, requiring careful handling of the table lookup or coordinate system transformation.

## Subtopics

### Bidirectional Path Vertex Sampling
The parent method that VRLs reinterpret. VRLs provide a specific efficient implementation for the segment-segment connection in participating media. [Link](2136-joint-path-vertex-sampling.md)

### Bridge Sampling
A sibling method for connecting subpaths. VRLs differ by using precomputed tables and grid hierarchies rather than direct PDF cancellation for all terms. [Link](3881-bridge-sampling.md)

### Bidirectional Path Tracing
A sibling method. VRLs are more specialized for participating media and use precomputation, whereas BPT is a general-purpose unbiased method. [Link](6666-bidirectional-path-tracing.md)

## Operating characteristics
*   **Time Complexity**: $O(N_{cells} \cdot N_{VRLs})$ per camera segment, where $N_{cells}$ is the number of non-culled grid cells and $N_{VRLs}$ is the number of VRLs per cell. The lookup is $O(1)$ after coordinate transformation.
*   **Memory Complexity**: Dominated by the grid hierarchy and the precomputed segment table. The table size depends on the resolution of $\rho$, $z$, and angular dimensions.
*   **Performance**: Designed for interactive rendering on GPU [S2]. The grid hierarchy and culling reduce the number of VRLs processed.
*   **Strengths**: Efficient for scenes with many light sources and participating media. Precomputation allows fast runtime evaluation.
*   **Limitations**: High memory usage for the precomputed tables. Limited to specific scattering models stored in the table. Not suitable for dynamic media where the scattering properties change rapidly.
*   **When to use**: Interactive rendering of participating media with static lighting and material properties.
*   **When not to use**: Dynamic media, highly complex scattering models not covered by the precomputed table, or scenes with very few lights where direct path tracing is sufficient.

## Background
Virtual ray lights were originally developed by Novak et al. in 2012 [S1]. The method was later adapted and implemented using neural networks for interactive simulation by Kulla and Fajardo (2019) [S2]. It is used in computer graphics for rendering participating media such as fog, smoke, and clouds.
