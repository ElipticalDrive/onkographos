# Real-Time Volumetric Shadows using 1D Min-Max Mipmaps

Also called: 1D Min-Max Mipmap Volumetric Shadows

## Overview
This method computes real-time volumetric shadows in single-scattering participating media on the GPU by evaluating the scattering integral over the intersections of camera rays with a shadow map treated as a 2D height field [S1]. It distinguishes itself from sibling methods by using epipolar rectification to reduce the problem to 1D height fields and employing 1D min-max mipmaps to find lit segments in parallel, allowing all camera rays to be processed simultaneously using only standard pixel shader features without requiring GPGPU APIs or camera rectification [S1].

## How it works
The algorithm evaluates the single-scattering integral for each pixel by identifying the visible segments of the volume along the camera ray that are illuminated by the light source.

### Inputs and Outputs
*   **Inputs:** Camera position and orientation; Light position and intensity; Volume density field $\sigma_t(\mathbf{x})$ (typically stored in a 3D texture or implicit surface); Shadow map from the light's perspective; Depth map from the camera's perspective.
*   **Outputs:** Final color buffer with volumetric shadows.

### Data Structures
1.  **Shadow Map:** A 2D depth texture representing the distance from the light to the volume boundary.
2.  **Rectified Shadow Map:** A 2D texture where rows correspond to epipolar lines.
3.  **1D Min-Max Mipmap:** For each row of the rectified shadow map, a hierarchy of 1D textures where each level stores the minimum and maximum depth values for blocks of texels. This allows for coarse-to-fine traversal to find lit segments.

### Steps

1.  **Render Depth Maps:** Render a standard depth map from the camera and a shadow map from the light [S1].
2.  **Epipolar Rectification:** Transform the shadow map into an epipolar rectified coordinate system. In this system, each camera ray intersects the volume along a single row of the rectified shadow map (an epipolar slice) [S1]. This reduces the 2D intersection problem to a series of 1D problems.
3.  **Low-Rank Approximation:** Compute a low-rank approximation for the terms in the scattering integral excluding the visibility term. This pre-computation accelerates the per-pixel integration [S1].
4.  **Build 1D Min-Max Mipmaps:** For each row of the rectified shadow map, construct a 1D min-max mipmap. Each level $l$ of the mipmap for a row stores the minimum and maximum depth values for contiguous blocks of texels of size $2^l$ [S1].
5.  **Traverse Mipmaps and Accumulate:** For each camera ray (pixel):
    *   Identify the corresponding row in the rectified shadow map.
    *   Traverse the 1D min-max mipmap for that row to find intervals where the volume is lit (i.e., where the shadow map depth is greater than the camera ray depth, accounting for occlusion).
    *   Accumulate the scattering integral over these lit segments. The integral for a segment from $t_1$ to $t_2$ is:
        $$ \int_{t_1}^{t_2} T(\mathbf{o}, \mathbf{x}(t)) \sigma_s(\mathbf{x}(t)) L_{in}(\mathbf{x}(t)) dt $$
        where $T$ is transmittance from the eye, $\sigma_s$ is scattering coefficient, and $L_{in}$ is incident radiance [S1].
6.  **Epipole Handling:** If the epipole (the projection of the light position onto the image plane) is on or near the screen, the rectification becomes singular or inaccurate. In this case, compute the scattering near the epipole using brute-force ray marching [S1].

### Parameters and Edge Cases
*   **Mipmap Levels:** The number of levels depends on the shadow map resolution. Higher resolution requires more levels for efficient traversal.
*   **Epipole Proximity:** The threshold for "near the epipole" determines when to switch to brute-force ray marching. This is a trade-off between performance and accuracy [S1].
*   **Precision:** Floating-point precision in the shadow map and mipmap construction can affect the accuracy of segment finding, especially for thin structures or grazing angles [S1].

## Operating characteristics
*   **Time Complexity:** The method allows parallel processing of all camera rays. The mipmap traversal is logarithmic with respect to the shadow map resolution per row. The overall complexity is dominated by the number of pixels and the cost of mipmap traversal, which is efficient for high-resolution shadow maps [S1].
*   **Memory Complexity:** Requires storage for the shadow map, rectified shadow map, and 1D min-max mipmaps for each row. The memory usage is proportional to the shadow map resolution and the number of rows [S1].
*   **Performance:** Achieves real-time performance on GPUs supporting DirectX 9 pixel shader features. It avoids the overhead of GPGPU APIs and the cost of sending large numbers of vertices, making it suitable for high-resolution shadow maps and complex scenes like forests [S1].
*   **Strengths:** Parallel processing, no GPGPU API dependency, handles high-resolution shadow maps, supports textured lights.
*   **Limitations:** Sacrifices worst-case guarantees compared to incremental integration methods. Accuracy near the epipole relies on brute-force ray marching, which can be costly if the epipole is large or moves frequently [S1].

## Background
The method was introduced in the paper "Real-Time Volumetric Shadows using 1D Min-Max Mipmaps" [S1]. It builds on the observation that epipolar rectification can simplify the 2D shadow map intersection problem to 1D. Min-max mipmaps, previously used for soft shadows and global illumination, are adapted here for volumetric shadow computation [S1]. The method contrasts with Baran et al.'s incremental integration, which requires GPGPU APIs and camera rectification, and Billeter et al.'s method, which processes shadow volume elements rather than pixels [S1].
