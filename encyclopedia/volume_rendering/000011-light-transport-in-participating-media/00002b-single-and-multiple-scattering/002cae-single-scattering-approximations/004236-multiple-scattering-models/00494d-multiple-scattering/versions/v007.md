# Multiple Scattering

Also called: Multiple Scattering Simulation

## Overview
Multiple scattering simulates the effect resulting from more than one scattering bounce, where photons change direction at least twice within a participating medium [S1][S2, unofficial]. It solves the problem of rendering dense media, such as thick clouds or smoke, which appear dark and lifeless under single scattering approximations because they fail to account for light trapped and re-emitted within the volume [S2, unofficial]. Unlike single scattering, which is sufficient for thin media like light haze, multiple scattering is required to capture the high albedo and volumetric glow of dense participating media [S1][S2, unofficial].

## How it works
Multiple scattering is implemented by extending the ray marching process to account for indirect illumination within the volume. While the parent article [Multiple Scattering Models](10687-multiple-scattering-models.md) outlines the general recursive accumulation of radiance, the specific implementation of "Multiple Scattering" as a distinct rendering mode often involves explicitly tracing additional bounces or limiting the simulation depth [S1][S2, unofficial].

**Inputs and Outputs:**
*   **Input:** Volume density field, scattering coefficient $\sigma_s$, absorption coefficient $\sigma_a$, phase function $p(\omega_i, \omega_o)$, and a **Volume Trace Depth** parameter controlling the maximum number of bounces [S2, unofficial].
*   **Output:** Radiance $L$ at the camera pixel, including contributions from direct light and light scattered $n \ge 2$ times [S1].

**Data Structures:**
*   **Volume Trace Depth:** An integer parameter specifying the maximum number of scattering events to simulate per ray [S2, unofficial].
*   **Scattering Strength:** A scalar value in the volume shader that must be sufficiently high to make the intensity of scattered light visible [S2, unofficial].

**Steps:**
1.  **Initialize Ray:** Cast a primary ray from the camera into the scene [S2, unofficial].
2.  **March:** Step through the volume, accumulating optical depth [S2, unofficial].
3.  **Sample Scattering:** At each step, determine if a scattering event occurs based on the scattering coefficient [S2, unofficial].
4.  **Bounce Accumulation:**
    *   If a scattering event occurs, compute the new direction using the phase function [S2, unofficial].
    *   If the current bounce count is less than the **Volume Trace Depth**, continue tracing the ray to account for subsequent bounces [S2, unofficial].
    *   If the bounce count exceeds the depth, terminate the path or approximate the remaining contribution [S2, unofficial].
5.  **Accumulate Radiance:** Sum the emitted and scattered light along the path, weighted by transmittance [S2, unofficial].

**Parameters:**
*   **Volume Trace Depth:** Controls the number of scattering bounces simulated. Typical tested values include 1 (single scattering), 5, and 31 [S2, unofficial].
*   **Scattering Strength:** Must be high enough for scattered light intensity to be visible; otherwise, the multiple scattering effect may be imperceptible [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Noise:** Unbiased rendering of multiple scattering can be noisy due to the high variance in path lengths and scattering events [S1].
*   **Performance:** Every added bounce multiplies the computational work, making dense media with high multiple scattering significantly more expensive to render [S2, unofficial].
*   **Denoising Difficulty:** Volumes are notoriously harder to denoise than surfaces because helper data, such as surface normals, does not exist inside a cloud [S2, unofficial].
*   **Zero Bounces:** In some implementations (e.g., Cycles), the default number of bounces is zero, meaning multiple scattering is disabled by default [S1].

**Pseudocode:**

def render_multiple_scattering(ray, volume, max_bounces):
    """
    Renders a ray through a volume with multiple scattering support.
    
    Args:
        ray: The primary ray from the camera.
        volume: The participating medium properties (sigma_s, sigma_a, phase function).
        max_bounces: The Volume Trace Depth parameter.
        
    Returns:
        L: Total radiance accumulated along the ray.
    """
    L = 0.0
    current_ray = ray
    transmittance = 1.0
    
    for bounce in range(max_bounces + 1):
        # Step through the volume
        hit, distance = volume.march(current_ray)
        
        if not hit:
            break
            
        # Calculate optical depth for the segment
        sigma_t = volume.sigma_s + volume.sigma_a
        optical_depth = sigma_t * distance
        
        # Calculate transmittance
        T = exp(-optical_depth)
        
        # Sample scattering event
        # [G] Standard Russian Roulette or exact sampling logic would go here
        # based on the ratio of sigma_s to sigma_t.
        scattered = sample_scattering(volume, current_ray, distance)
        
        if scattered:
            # Compute in-scattered radiance
            # L_in = sigma_s * integral(p(omega_i, omega_o) * L(omega_i) d omega_i)
            # For simplicity in this basic model, we assume a single dominant 
            # incoming direction or precomputed environment contribution.
            L_scattered = compute_in_scattering(volume, current_ray, distance)
            
            # Add contribution
            L += transmittance * L_scattered
            
            # Prepare for next bounce
            if bounce < max_bounces:
                # Update ray direction based on phase function
                current_ray.direction = scatter_direction(volume.phase_function, current_ray.direction)
                current_ray.origin = hit_point
                transmittance *= T # Update transmittance for the next segment
            else:
                break
        else:
            # Absorption or no scattering event in this segment
            transmittance *= T
            
    return L

## Operating characteristics
*   **Time Complexity:** The computational cost increases multiplicatively with the number of bounces. Simulating dozens or hundreds of bounces is required for realistic dense clouds, making it significantly more expensive than single scattering [S2, unofficial].
*   **Memory Complexity:** Depends on the volume data structure (e.g., OpenVDB) and the recursion depth. No additional large buffers are strictly required for the basic bounce accumulation, but denoising may require auxiliary buffers [S2, unofficial].
*   **Strengths:** Produces realistic lighting for dense media like clouds and smoke, capturing high reflectivity (up to 90% for thick cumulus clouds) [S2, unofficial].
*   **Limitations:** High noise levels in unbiased rendering; difficult to denoise due to lack of surface normals; computationally prohibitive for high bounce counts without approximations [S1][S2, unofficial].
*   **When to use:** For dense participating media where single scattering results in dark, lifeless appearances [S2, unofficial].
*   **When not to use:** For thin media like light haze, where single scattering is sufficient and faster [S2, unofficial]; or for materials with well-defined surfaces like skin, where subsurface scattering is more efficient [S1].

## Background
The concept of multiple scattering is fundamental to radiative transfer in participating media. In computer graphics, it became a distinct rendering mode as engines sought to move beyond the limitations of single scattering approximations. The term "Multiple Scattering" is often used in contrast to "Single Scattering" in software documentation, such as in Blender's Cycles and Eevee renderers, where it is noted that unbiased rendering of multiple scattering can be noisy and is often disabled by default [S1]. The implementation details, such as the "Volume Trace Depth" parameter, have been documented in tutorials and engine-specific guides, highlighting the trade-off between visual fidelity and performance [S2, unofficial].
