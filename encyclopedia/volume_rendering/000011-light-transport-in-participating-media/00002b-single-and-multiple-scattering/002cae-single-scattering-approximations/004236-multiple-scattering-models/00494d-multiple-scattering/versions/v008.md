# Multiple Scattering

Also called: Multiple Scattering Simulation

## Overview
Multiple scattering accounts for light undergoing two or more scattering events within a participating medium before reaching the viewer [S1]. While single scattering approximations suffice for thin media like haze, they fail to capture the brightness and volume of dense media such as clouds or smoke, where photons bounce dozens or hundreds of times [S2, unofficial]. This method solves the problem of dark, lifeless rendering in dense volumes by simulating these higher-order bounces, though it incurs significant computational cost and noise [S1][S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:** Volume density fields (e.g., OpenVDB), scattering coefficient $\sigma_s$, absorption coefficient $\sigma_a$, phase function $p(\omega_i, \omega_o)$, and a `Volume Trace Depth` parameter controlling the maximum number of bounces [S1][S2, unofficial].
*   **Outputs:** Radiance $L$ contributing to the final image pixel, decomposed into direct, single, and multiple scattering components [S1].

**Data Structures**
*   **Volume Grid:** Typically stored in formats like OpenVDB, which holds sparse voxel data for smoke and clouds [S2, unofficial].
*   **Ray State:** Tracks current position, direction, accumulated transmittance, and current scattering order (bounce count) [S2, unofficial].

**Steps**
1.  **Initialize Ray:** Cast a primary ray from the camera into the volume. Initialize accumulated radiance $L_{acc} = 0$ and transmittance $T = 1$. Set bounce counter $n = 0$ [S2, unofficial].
2.  **Marching Loop:** Step through the volume along the ray direction. At each sample point $x$:
    *   Evaluate extinction coefficient $\sigma_t(x) = \sigma_a(x) + \sigma_s(x)$ [S1].
    *   Compute transmittance to the next sample: $T_{step} = \exp(-\sigma_t(x) \cdot \Delta s)$ [S2, unofficial].
    *   Update total transmittance: $T \leftarrow T \cdot T_{step}$ [S2, unofficial].
3.  **Scattering Event:** If a scattering event occurs (determined by $\omega_0 = \sigma_s / \sigma_t$ [S1]):
    *   Increment bounce counter $n$.
    *   If $n > \text{Volume Trace Depth}$, terminate the multiple scattering contribution for this ray [S2, unofficial].
    *   Sample the phase function $p(\omega_i, \omega_o)$ to determine the new direction $\omega_o$ [S1].
    *   Recursively or iteratively trace the new ray segment to compute the in-scattered light contribution [S2, unofficial].
    *   Add the contribution to $L_{acc}$, weighted by $T$ and $\sigma_s$ [S2, unofficial].
4.  **Accumulate:** Sum contributions from all bounces up to `Volume Trace Depth` [S2, unofficial].
5.  **Output:** Return $L_{acc}$ as the multiple scattering component [S1].

**Parameters**
*   **Volume Trace Depth:** Controls the maximum number of scattering bounces simulated. Typical tested values include 1 (single scattering), 5, and 31 [S2, unofficial]. Higher values increase brightness in dense media but also cost [S2, unofficial].
*   **Scattering Strength:** The magnitude of $\sigma_s$ must be sufficiently high for scattered light intensity to be visible [S2, unofficial].

**Pitfalls**
*   **Noise:** Unbiased rendering of multiple scattering is inherently noisy due to the variance in path lengths and scattering events [S1].
*   **Denoising Difficulty:** Volumes are harder to denoise than surfaces because auxiliary data like surface normals are unavailable inside the volume [S2, unofficial].
*   **Performance:** Every added bounce multiplies computational work, making high `Volume Trace Depth` settings expensive [S2, unofficial].

## Operating characteristics
*   **Complexity:** Time complexity grows exponentially with the number of bounces and optical thickness of the medium [S2, unofficial]. Memory complexity depends on the volume grid resolution and storage format (e.g., OpenVDB) [S2, unofficial].
*   **Performance:** Rendering dense clouds with multiple scattering is significantly slower than single scattering [S2, unofficial]. GPU rendering and approximations are often required to manage costs [S2, unofficial].
*   **Strengths:** Produces realistic brightness and volume for dense media like cumulus clouds (which can reflect up to 90% of incident light) [S2, unofficial].
*   **Limitations:** High noise levels; limited by practical render times; not suitable for real-time without approximation [S1][S2, unofficial].
*   **When to use:** For offline rendering of dense clouds, smoke, or subsurface scattering where visual fidelity is critical [S1][S2, unofficial].
*   **When not to use:** For thin media like light haze (single scattering suffices) or real-time applications requiring low latency [S1][S2, unofficial].

## Background
Multiple scattering is a fundamental concept in radiative transfer theory, essential for simulating real-world effects like scattering in clouds and subsurface scattering [S1]. In computer graphics, it has been a challenge for unbiased renderers due to its computational cost and noise. Blender's Cycles renderer, for instance, defaults to zero volume bounces (single scattering) due to noise concerns, while Eevee does not support it [S1]. The industry has adopted OpenVDB for volume data exchange, originally developed at DreamWorks Animation and open-sourced in 2012 [S2, unofficial].
