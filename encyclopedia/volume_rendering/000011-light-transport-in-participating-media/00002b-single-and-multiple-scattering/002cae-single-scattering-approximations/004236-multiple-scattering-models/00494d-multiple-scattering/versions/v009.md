# Multiple Scattering

Also called: Multiple Scattering Simulation

## Overview
Multiple scattering simulates the effect resulting from more than one scattering bounce within a participating medium [S1]. It solves the problem of rendering dense media, such as thick clouds or smoke, where single scattering approximations fail to capture the brightness and volume of light trapped inside the medium [S2, unofficial]. Unlike single scattering, which only accounts for direct light from sources, multiple scattering accounts for light that has been scattered by the medium itself, requiring the simulation of photons bouncing dozens or hundreds of times before escaping [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Volume density field, scattering coefficient ($\sigma_s$), absorption coefficient ($\sigma_a$), phase function $p(\omega', \omega)$, and a maximum bounce count (Volume Trace Depth).
*   **Output:** Radiance $L$ at the camera ray intersection point.

**Data Structures:**
*   **Volume Trace Depth:** An integer parameter controlling the maximum number of scattering bounces simulated per ray [S2, unofficial].

**Steps:**
1.  Initialize the ray at the camera origin with direction $\omega_{cam}$.
2.  March the ray through the volume. At each step, calculate the transmittance $T$ and the contribution of single-scattered light from the direct source.
3.  If the current bounce count is less than `Volume Trace Depth`:
    *   Determine if a scattering event occurs based on the optical depth and the scattering coefficient.
    *   If a scatter occurs, sample a new direction $\omega'$ using the phase function $p(\omega', \omega)$.
    *   Cast a new ray in direction $\omega'$ to find the next scattering event or exit.
    *   Accumulate the radiance returned from this secondary ray, attenuated by the transmittance between the current point and the next interaction point.
    *   Increment the bounce count.
    *   Repeat until `Volume Trace Depth` is reached or the ray exits the volume.
4.  Return the accumulated radiance.

**Parameters:**
*   **Volume Trace Depth:** Controls the number of scattering bounces simulated. Typical values tested include 1, 5, and 31 [S2, unofficial]. A value of 1 corresponds to single scattering. Higher values are required for dense media like clouds [S2, unofficial].
*   **Scattering Strength:** The scattering coefficient must be high enough for the intensity of the scattered light within the volume to be visible [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Noise:** Unbiased rendering of multiple scattering can be noisy due to the high variance in path lengths and bounce counts [S1].
*   **Performance:** Every added bounce multiplies the computational work, making dense media rendering significantly slower [S2, unofficial].
*   **Denoising:** Volumes are notoriously harder to denoise than surfaces because helper data like surface normals does not exist inside a cloud [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The cost increases exponentially with the `Volume Trace Depth` because every added bounce multiplies the work [S2, unofficial].
*   **Memory Complexity:** Depends on the volume data structure (e.g., OpenVDB) and the recursion depth of the ray tracer [S1].
*   **Strengths:** Produces realistic brightness for dense media like clouds and smoke, which appear dark and lifeless under single scattering [S2, unofficial].
*   **Limitations:** Computationally expensive; unbiased rendering is noisy and slow [S1]. For materials with well-defined surfaces like skin or milk, subsurface scattering is more efficient and easier to control [S1].
*   **When to use:** For media without well-defined surfaces, such as clouds or smoke, where many scattering bounces are required for visual fidelity [S1].
*   **When not to use:** For thin media like light haze, where single scattering is sufficient [S2, unofficial].

## Background
Multiple scattering is a fundamental concept in radiative transfer, essential for simulating real-world effects like scattering in clouds or subsurface scattering [S1]. In computer graphics, it has historically been challenging to implement efficiently due to the computational cost of tracing multiple bounces [S2, unofficial]. Modern renderers often limit the number of bounces by default (e.g., zero in Cycles) to maintain performance, requiring explicit enabling for multiple scattering [S1]. The industry has adopted formats like OpenVDB for transporting volume data, originally developed at DreamWorks Animation and open-sourced in 2012, to support these complex simulations [S2, unofficial].
