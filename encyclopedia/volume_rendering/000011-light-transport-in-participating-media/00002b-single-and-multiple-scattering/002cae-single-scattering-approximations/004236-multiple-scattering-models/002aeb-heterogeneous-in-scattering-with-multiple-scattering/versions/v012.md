# Heterogeneous In-scattering with Multiple Scattering

Also called: Cloud Scattering Luminance, Cloud Scattering Luminance Scale

## Overview
This method computes the radiance contribution from light scattering within a heterogeneous participating volume by combining direct lighting from light sources and recursively computing indirect lighting (multiple scattering) up to a fixed maximum depth [S1, unofficial]. It sets itself apart from sibling methods by using a fixed recursion limit and an octave-based transmittance approximation for real-time performance, rather than full path tracing or perturbation series expansions [S1, unofficial][S2].

## How it works
The method traces rays through the volume, computes transmittance via fixed-step integration, and accumulates in-scattered radiance from direct and indirect sources [S1, unofficial]. It builds on the radiative transfer equation principles described in [Parent](10687-multiple-scattering-models.md), specifically evaluating the scattering term $\sigma_s \int_{S^2} p(\omega', \omega) L(x, \omega') d\omega'$ [G].

### Inputs and Outputs
*   **Inputs:** Ray origin $O$ and direction $\omega$; volume coefficients $\mu_a$ (absorption) and $\mu_s$ (scattering); scene geometry for surface intersections; light sources with position and intensity; recursion depth limit [S1, unofficial].
*   **Outputs:** Total radiance $L$ at the ray origin [S1, unofficial].

### Data Structures
*   **Volume Coefficients:** Heterogeneous fields for extinction $\sigma_t(x)$, scattering $\sigma_s(x)$, and absorption $\sigma_a(x)$ [S1, unofficial].
*   **Ray:** Origin $O$, direction $\omega$, current distance $t$ [G].
*   **Hit Record:** Intersection point $P$, surface normal $N$, material properties (albedo, emissive radiance) [G].

### Parameters
*   `mu_a`: Base absorption coefficient. Typical value: $0.05$ [S1, unofficial].
*   `mu_s`: Base scattering coefficient. Typical value: $0.1$ [S1, unofficial].
*   `max_depth`: Maximum recursion depth for multiple scattering. Typical value: $5$ [S1, unofficial].
*   `Cloud Scattering Luminance Scale`: A property on the Atmosphere Light that scales the light contribution to compensate for energy loss when simulating multiple scattering via octave approximation [S2].
*   **Octave Approximation Parameters:** `Number of octaves` (integer $0$ to $2$), `Contribution`, `Occlusion`, and `Eccentricity` in the Volumetric Advanced Material Output expression [S2].

### Steps
1.  **Initial Check:** Calculate local extinction coefficient $\sigma_t$ at the ray origin. If $\sigma_t < 0.0001$, return $0$ (no interaction) [S1, unofficial].
2.  **Single Scattering Albedo:** Compute $\omega_0 = \frac{\sigma_s}{\sigma_t}$ [S1, unofficial].
3.  **Direct In-scattering:** For each light source, sample light position $L_{pos}$ and create a shadow ray. If not occluded, compute transmittance $T_{to\_light}$ using 16-step integration of $\sigma_t$ along the path. Accumulate contribution: $L_{direct} += L_{emitted} \cdot p(\omega_{in}, \omega_{out}) \cdot \text{geometric} \cdot T_{to\_light} \cdot A_{light}$ [S1, unofficial].
4.  **Indirect In-scattering (Recursive):** If `depth` < `max_depth`, sample a hemisphere direction $\omega_{ind}$ using a HemisphericalSampler. Cast a ray from the scatter position. If it hits an object, recursively call `computeInscattering` for the segment up to the surface to get $L_{indirect}$. Add to total in-scattering: $L_{indirect\_contrib} = L_{indirect} \cdot \text{albedo} \cdot T_{to\_scatter} \cdot \frac{1}{4\pi}$ [S1, unofficial].
5.  **Heterogeneous Radiance Computation:** Find the closest intersection with scene geometry along the main ray. If no intersection, return background radiance: $L_{bg} = L_{ambient} + L_{bgColor} \cdot \exp(-(\mu_a + \mu_s) \cdot \bar{\rho} \cdot 10.0)$, clamped to minimum $0.2$ [S1, unofficial]. Compute in-scattering contribution $L_{inscatter}$ for the segment from origin to intersection. Add surface emission: $L_{emission} = L_{emissive} \cdot T_{surface}$. If `depth` < `MaxDepth`, compute reflected radiance (direct + indirect) from the surface and add to $L_{out}$ multiplied by $T_{surface}$ [S1, unofficial].

### Edge Cases and Pitfalls
*   **Isotropic Phase Function:** The implementation uses a hardcoded isotropic phase function ($1/4\pi$) for both direct and indirect scattering contributions, ignoring the material's actual phase function [S1, unofficial]. This is a significant simplification that may reduce accuracy for forward-scattering media [S1, unofficial].
*   **Energy Loss:** Simulating multiple scattering via octave approximation can result in energy loss, requiring compensation via the `Cloud Scattering Luminance Scale` parameter [S2].
*   **Precision:** The transmittance calculation uses 16-step integration, which may introduce errors in highly heterogeneous volumes if the step size is not adaptive [S1, unofficial].
*   **Recursion Depth:** The recursion stops at `depth >= 5` [S1, unofficial].

## Subtopics

### [Perturbation Solution for High Albedo](6659-perturbation-solution-for-high-albedo.md)
Computes radiance in participating media with high single-scattering albedo ($\beta \approx 1$) by expanding the solution into a series of forced conservative scattering equations. It addresses the failure of standard approximations to model deep shadowing and indirect illumination in highly scattering media like clouds. It differs from [Correction Texture for Surface Albedo](9421-correction-texture-for-surface-albedo.md) by handling volumetric multiple scattering rather than surface reflections, and from [Multiple Scattering via Volume Trace Depth](10698-multiple-scattering-via-volume-trace-depth.md) by using an analytical series expansion rather than stochastic depth tracing.

### [Correction Texture for Surface Albedo](9421-correction-texture-for-surface-albedo.md)
Corrects the main scattering texture for light reflected off the ground, which is precomputed assuming a homogeneous mean surface albedo $\bar{a}$. It allows the renderer to remove these homogeneous contributions from the main texture and evaluate surface albedos and reflection characteristics separately at runtime for surfaces with varying properties.

### [Bias Compensation for Instant Radiosity](9586-bias-compensation-for-instant-radiosity.md)
Bias Compensation for Instant Radiosity is an unbiased method to handle weak singularities (infinite variance) in Instant Radiosity when volume points are close to light sources, by bounding the geometric term and recursively compensating for the introduced bias.

### [Multiple Scattering via Volume Trace Depth](10698-multiple-scattering-via-volume-trace-depth.md)
Enables volumetric multiple scattering by controlling the maximum number of scattering bounces computed within participating media, transforming dense volumes from opaque grey masses into luminous, believable objects. It is distinct from single-scattering approximations by explicitly simulating indirect light transport within the volume, but it is computationally more expensive and requires Brute Force Global Illumination, unlike faster heuristic shortcuts.

### Heterogeneous Radiance Computation
Computes the total radiance for a ray by combining volumetric in-scattering, surface emission, and surface reflection, accounting for transmittance through the heterogeneous medium [S1, unofficial]. It finds the closest intersection with scene geometry, computes in-scattering for the segment, adds surface emission, and if depth allows, computes reflected radiance [S1, unofficial].

### Multiple Scattering Approximation via Octaves
An approximation of realistic light scattering in participating media by tracing multiple octaves (steps) of light transmittance within the volume material to simulate the complex scattering effect where light is almost never absorbed (albedo close to 1) [S2].
*   **Parameters:** `Number of octaves` (integer $0$ to $2$; $0$ is single scattering, $1$ is one octave, $2$ is two octaves), `Contribution`, `Occlusion`, and `Eccentricity` [S2].
*   **Comparison:** Single octave ($1$) is recommended for games for performance. Higher octaves ($2$) are more expensive. High Contribution/Low Occlusion can approximate high octaves without performance impact [S2].

## Operating characteristics
*   **Time Complexity:** Exponential with respect to recursion depth due to the branching of indirect scattering rays [S1, unofficial]. The use of 16-step integration for transmittance adds a constant factor per light source per bounce [S1, unofficial].
*   **Memory Complexity:** Linear with respect to the number of light sources and the depth of the recursion stack [S1, unofficial].
*   **Measured Performance:** Not given in the sources [S1, unofficial][S2]. However, higher octaves and deeper recursion increase shader expense [S2].
*   **Scaling:** Performance degrades significantly with increased volume density and number of light sources [S1, unofficial].
*   **Strengths:** Handles heterogeneous volumes; compensates for energy loss with luminance scaling; provides a real-time approximation for multiple scattering [S1, unofficial][S2].
*   **Limitations:** Computationally expensive; uses a hardcoded isotropic phase function by default; requires careful tuning of parameters (depth, octaves, luminance scale) [S1, unofficial][S2].
*   **When to use:** When physically plausible indirect illumination is required and performance allows; for cloud rendering where energy loss compensation is needed [S1, unofficial][S2].
*   **When not to use:** When real-time performance is critical and single scattering approximations are sufficient; when the phase function is highly anisotropic and the isotropic approximation is unacceptable [S1, unofficial].

## Background
The method originates from volumetric path tracing techniques for participating media [S1, unofficial]. The concept of using octave approximation for multiple scattering in real-time rendering is documented in Unreal Engine's Volumetric Cloud Component [S2]. The perturbation solution for high albedo media is based on classical radiative transfer theory [G].
