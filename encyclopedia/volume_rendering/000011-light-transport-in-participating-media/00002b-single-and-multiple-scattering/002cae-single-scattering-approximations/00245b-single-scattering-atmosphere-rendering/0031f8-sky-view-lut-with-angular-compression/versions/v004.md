# Sky View LUT with Angular Compression

Also called: Seb Hillaire’s Sky and Atmosphere Rendering Technique

## Overview
A technique for rendering sky and atmosphere using a precomputed Look-Up Table (LUT) with angular compression, ported from a reference implementation [S1, unofficial]. It builds on [Single-Scattering Atmosphere Rendering](3289-single-scattering-atmosphere-rendering.md) by storing precomputed radiance values in a compressed texture space for efficient runtime lookup [G].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Observer altitude $h$, view zenith angle $\vartheta$, view azimuth, sun zenith angle $\vartheta_s$, sun azimuth $\phi_s$ [S2].
*   **Outputs:** Fragment color $I_F$ for the atmosphere [S2].

**Data Structures:**
*   **Sky View LUT:** A 4D texture array storing precomputed radiance values, with an example resolution of $400 \times 400$ [S1, unofficial].
*   **Extinction Texture:** A 2D lookup texture parameterized by observer altitude $h$ and zenith angle $\vartheta$, containing $t(P P_c)$ where $P$ has altitude $h$ and $P_c$ is the intersection of the ray starting at $P$ under zenith angle $\vartheta$ with the upper atmosphere boundary [S2].

**Steps:**
1.  Precompute the extinction coefficient $t$ into the 2D lookup texture parameterized by $h$ and $\vartheta$ [S2].
2.  Represent the planet and atmospheric shell as finely tessellated spheres with frontface culling for the atmosphere and backface culling for the planet [S2].
3.  For each pixel, map the four-dimensional input space (altitude, view-zenith, sun-zenith, sun-view azimuth) to texture coordinates using angular compression remapping [G].
4.  Fetch two values from the scattering texture array and perform manual linear interpolation for the fourth dimension [S2].
5.  Set the fragment color $I_F = I_S$ for the atmosphere [S2].

**Edge Cases and Pitfalls:**
*   If the observer is outside the atmosphere, compute the intersection point $P_a$ between the view ray and the atmosphere sphere, evaluate the scattering function $f$ for this point, and set scattering/attenuation to zero [S2].
*   Large cell sizes in the LUT can give a blocky look [S1, unofficial].

**Pseudocode:**
```python
# Standard math/vector operations (vec3, sin, cos, dot, lerp, floor, ceil) assumed available.
def render_sky(observer_altitude, view_zenith, view_azimuth, sun_zenith, sun_azimuth, atmosphere_radius, scattering_lut):
    # Step 1: Check if observer is outside the atmosphere
    if observer_altitude > atmosphere_radius:
        origin = vec3(0.0, observer_altitude, 0.0)
        direction = vec3(sin(view_zenith)*cos(view_azimuth), cos(view_zenith), sin(view_zenith)*sin(view_azimuth))
        t = -dot(origin, direction) + sqrt(dot(origin, direction)**2 - dot(origin, origin) + atmosphere_radius**2)
        if t <= 0:
            return vec3(0.0)
        # Evaluate scattering function f for intersection point Pa and set scattering/attenuation to zero
        return vec3(0.0)

    # Step 2: Map 4D input space to texture coordinates using angular compression remapping
    # Standard parameterization mapping to 3D texture coordinates with an emulated fourth dimension [G]
    u, v, w, r = 0.0, 0.0, 0.0, 0.0

    # Step 3: Fetch two values from the scattering texture array
    idx1 = int(floor(r))
    idx2 = int(ceil(r))
    frac = r - floor(r)

    val1 = scattering_lut[u, v, w, idx1]
    val2 = scattering_lut[u, v, w, idx2]

    # Step 4: Manual linear interpolation for the fourth dimension
    color = lerp(val1, val2, frac)
    return color
```

## Subtopics

### [Atmospheric Parameterization](9405-atmospheric-parameterization.md)
A coordinate remapping function that maps the 4D input space to 3D texture coordinates with an emulated fourth dimension via tiling. It uses non-linear mappings for altitude and angles to distribute sampling density according to light scattering behavior [G]. Choose it when efficient runtime lookup of single-scattering data is required.

### Atmosphere Rendering with Lookup Textures
This variant represents the planet and atmospheric shell as finely tessellated spheres with frontface culling (atmosphere) and backface culling (planet) [S2]. It precomputes the extinction coefficient $t$ into a 2D lookup texture parameterized by observer altitude $h$ and zenith angle $\vartheta$ [S2]. For rendering, it fetches two values from the scattering texture and performs manual linear interpolation for the fourth dimension [S2]. If the observer is outside the atmosphere, it computes the intersection point $P_a$ between the view ray and atmosphere sphere, evaluates $f$ for this point, and sets scattering/attenuation to zero [S2]. The fragment color is $I_F = I_S$ for the atmosphere [S2].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per pixel for LUT lookup, assuming constant texture size [G].
*   **Memory Complexity:** $O(N^3)$ for a 3D LUT, where $N$ is the resolution [G]. The example uses a $400 \times 400$ LUT [S1, unofficial].
*   **Strengths:** Efficient real-time rendering of atmospheric scattering [G].
*   **Limitations:** Precomputation cost is high. Blocky artifacts can appear if cell sizes are too large [S1, unofficial].
*   **When to use:** Not given in the sources.
*   **When not to use:** Not given in the sources.

## Background
The technique is based on Seb Hillaire’s "A Scalable and Production Ready Sky and Atmosphere Rendering Technique" [S1, unofficial]. It has been ported to various engines, including vxray [S1, unofficial]. The underlying principles of using lookup textures for atmospheric scattering were explored in earlier works such as [Bruneton and Neyret 2008] and [Schafhitzel et al. 2007] [S2].
