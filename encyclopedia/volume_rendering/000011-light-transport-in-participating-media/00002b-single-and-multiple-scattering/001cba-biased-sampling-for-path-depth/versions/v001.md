# Biased Sampling for Path Depth

Also called: Density and Anisotropy Reduction with Ray Depth, Biasing the Sampling

## Overview
Biased Sampling for Path Depth is a variance reduction technique for volumetric path tracing in dense, highly anisotropic participating media (such as clouds) that exponentially decays the medium's extinction coefficient and anisotropy parameter as the ray depth increases [S1, unofficial]. By reducing the frequency of scattering events and the sharpness of the phase function along the path, the method produces shorter paths with lower variance and significantly faster convergence, accepting a slight bias in the final image [S1, unofficial]. It is distinct from unbiased variance reduction methods like [Multiple Importance Sampling for Volumetric Path Tracing](1167-multiple-importance-sampling-for-volumetric-path-tracing.md) or [Sample Matching for Extinction Gradients](1884-sample-matching-for-extinction-gradients.md) by explicitly altering the physical properties of the medium along the trajectory rather than adjusting the probability density functions or estimator weights [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** The base medium properties: total extinction coefficient $\sigma_t$, anisotropy parameter $g$, and the bias factor $b$.
*   **Output:** Modified coefficients $\sigma_t'$ and $g'$ used for sampling distances and scattering directions at a given ray depth $d$.

**Data Structures:**
No specific complex data structures are required beyond standard scalar storage for $\sigma_t$, $g$, and $b$. The method operates on per-path state variables.

**Parameters:**
*   $b$: Bias factor, a scalar between 0 and 1. Typical value: 0.8 for clouds [S1, unofficial].
*   $d$: Current ray depth (bounce count), starting at 0 or 1 depending on implementation convention. The notes use $d$ as the depth index in the exponent [S1, unofficial].

**Steps:**
1.  Determine the current ray depth $d$ for the current scattering event or path vertex.
2.  Calculate the biased anisotropy parameter $g'$ using the formula:
    $$
    g' = |g|^{1 + d} \cdot \text{sign}(g)
    $$
    This reduces the magnitude of $g$ towards 0 (more isotropic) as $d$ increases, while preserving the sign of $g$ [S1, unofficial].
3.  Calculate the biased total extinction coefficient $\sigma_t'$ using the formula:
    $$
    \sigma_t' = \sigma_t \cdot b^{d}
    $$
    This exponentially decays the extinction coefficient as $d$ increases, leading to larger sampled free-flight distances [S1, unofficial].
4.  Use $\sigma_t'$ for distance sampling (e.g., via [Delta tracking](985-delta-tracking.md) or [Homogeneous Medium Sampling](980-homogeneous-medium-sampling.md)) and $g'$ for phase function evaluation (e.g., [Phase Function](3111-phase-function.md)) [S1, unofficial].

**Pseudocode:**
```python
def get_biased_medium_properties(base_sigma_t, base_g, bias_factor, ray_depth):
    """
    Returns biased extinction and anisotropy for a given ray depth.
    
    Args:
        base_sigma_t (float): The original total extinction coefficient.
        base_g (float): The original anisotropy parameter.
        bias_factor (float): The decay factor b (0 < b < 1).
        ray_depth (int): The current bounce count or path depth d.
        
    Returns:
        tuple: (biased_sigma_t, biased_g)
    """
    # Calculate biased anisotropy: g' = |g|^(1+d) * sign(g)
    abs_g = abs(base_g)
    sign_g = 1.0 if base_g >= 0 else -1.0
    
    # Handle edge case where g is 0 to avoid 0^0 or similar issues if d varies
    if abs_g == 0:
        biased_g = 0.0
    else:
        biased_g = (abs_g ** (1 + ray_depth)) * sign_g
        
    # Calculate biased extinction: sigma_t' = sigma_t * b^d
    biased_sigma_t = base_sigma_t * (bias_factor ** ray_depth)
    
    return biased_sigma_t, biased_g
```

**Edge Cases and Pitfalls:**
*   **Noise vs. Brightness:** Without biasing, low sample counts in dense media exhibit high-frequency noise that can make clouds appear darker than they are. Biased sampling reduces this noise, making the image appear brighter. This brightness is primarily an artifact of reduced noise, not increased radiance [S1, unofficial].
*   **Bias Introduction:** The method introduces a systematic bias. While the visual difference is minimal in practice, it is not a physically correct solution [S1, unofficial].
*   **Reduction Strategy:** The original Hyperion paper suggests linearly reducing density and anisotropy between the 5th and 20th bounce [S1, unofficial]. However, implementing global reduction (throughout the entire path) was found to have minimal visual difference while being faster and resulting in fewer sampled events [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
The method adds negligible computational overhead per step (a few multiplications and exponentiations). Its primary benefit is reducing the average path length, thereby reducing the number of scattering events and light samples per path.

**Measured Performance:**
In a cloud rendering scenario using [Delta tracking](985-delta-tracking.md) and [Region Subdivision](1167-multiple-importance-sampling-for-volumetric-path-tracing.md) (implied by context of Hyperion optimizations):
*   Basic Delta Tracking: ~248 seconds for 10 samples per pixel (spp) [S1, unofficial].
*   With Biased Sampling: ~1.1 seconds for 10 spp, a 225x speedup [S1, unofficial].
*   Clean Image (1000 spp): ~123 seconds [S1, unofficial].
*   High Density (3 clouds, 5000 spp): 996 seconds [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Drastically reduces render times for dense, highly anisotropic media by shortening paths and reducing variance. Simple to implement.
*   **Limitations:** Introduces bias. Not suitable for applications requiring physically accurate radiance. Performance gains diminish if the medium is not dense or anisotropic.

**When to Use:**
Use for offline rendering of dense participating media (clouds, fog) where convergence speed is critical and slight bias is acceptable.

**When Not to Use:**
Avoid for physically based rendering where energy conservation and exact radiance are required, or for sparse media where path lengths are already manageable.

## Background
The technique is derived from Disney’s Hyperion renderer, which proposed reducing medium density and anisotropy along the ray path to handle the high variance caused by dense, big, and highly anisotropic clouds [S1, unofficial]. The implementation described in the source notes follows this approach, noting that most direct lighting contribution comes from the first and last scattering events, justifying the simplification [S1, unofficial].
