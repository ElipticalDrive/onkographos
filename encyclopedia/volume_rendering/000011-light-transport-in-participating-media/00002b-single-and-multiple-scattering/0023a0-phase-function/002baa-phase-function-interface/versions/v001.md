# Phase Function Interface

Also called: pbrt PhaseFunction

## Overview
The Phase Function Interface defines the abstract contract for phase functions in the pbrt rendering system, requiring implementations to evaluate the scattering probability density and sample new scattering directions. It distinguishes itself from sibling implementations by enforcing a specific direction convention where both incident and outgoing vectors point away from the scattering point, differing from standard scattering literature [S1].

## How it works
**Inputs and Outputs:**
The interface operates on unit direction vectors $\omega_o$ (outgoing) and $\omega_i$ (incident) and random variables $u$. It outputs a scalar probability density value or a sampled direction.

**Data Structures:**
The core data structure is the abstract base class `PhaseFunction`. It contains two pure virtual methods:
1.  `p(const Vector3f &wo, const Vector3f &wi)`: Returns the phase function value $p(\omega_o, \omega_i)$.
2.  `Sample_p(const Vector3f &wo, Vector3f *wi, const Point2f &u)`: Samples a new incident direction $\omega_i$ given an outgoing direction $\omega_o$ and 2D uniform random numbers $u$, returning the probability density of the sampled direction.

**Direction Convention:**
pbrt uses the convention that both $\omega_o$ and $\omega_i$ point **away** from the scattering point $x$. This is the same convention used for BSDFs in pbrt but differs from the scattering literature, where the incident direction typically points **toward** the scattering point [S1]. Implementers must account for this sign flip when adapting formulas from standard texts.

**Pseudocode:**
```python
class PhaseFunction:
    """
    Abstract base class for phase functions in pbrt.
    """
    def p(self, wo: Vector3f, wi: Vector3f) -> float:
        """
        Evaluate the phase function value.
        
        Args:
            wo: Outgoing direction (unit vector, pointing away from scattering point).
            wi: Incident direction (unit vector, pointing away from scattering point).
            
        Returns:
            The phase function value p(wo, wi).
        """
        # Pure virtual method. Must be implemented by subclasses.
        raise NotImplementedError

    def Sample_p(self, wo: Vector3f, u: Point2f) -> tuple:
        """
        Sample a new incident direction.
        
        Args:
            wo: Outgoing direction (unit vector, pointing away from scattering point).
            u: 2D uniform random variable [0,1]^2.
            
        Returns:
            A tuple (wi, pdf) where:
                wi: The sampled incident direction (unit vector, pointing away from scattering point).
                pdf: The probability density of the sampled direction with respect to solid angle.
        """
        # Pure virtual method. Must be implemented by subclasses.
        raise NotImplementedError
```

**Edge Cases and Pitfalls:**
*   **Direction Convention:** As noted, the sign of the incident direction differs from standard literature. Using standard formulas directly without flipping the incident vector will result in incorrect scattering angles [S1].
*   **Normalization:** Phase functions are normalized such that $\int_{S^2} p(\omega_o, \omega_i) d\omega_i = 1$. This ensures energy conservation in the scattering model [S1].

## Subtopics

### Ice Phase Function
The Ice Phase Function models light scattering by ice crystals in cirrus clouds, using data from Hess and Wiegner’s Cirrus Optical Properties system [S2]. It is characterized by distinct peaks at 22 and 46 degrees, which create halos when the sun penetrates optically thin cirrus clouds. These peaks exhibit wavelength dependence, resulting in chromatic halos [S2].

## Operating characteristics
**Time and Memory Complexity:**
The interface itself has $O(1)$ time and memory complexity for evaluation and sampling, as it delegates to specific implementations. The complexity depends entirely on the subclass (e.g., Henyey-Greenstein is $O(1)$, while tabulated or complex ice models may involve interpolation or lookup).

**Strengths and Limitations:**
*   **Strengths:** Provides a unified interface for diverse scattering models, enabling modular scene description. The direction convention aligns with pbrt's BSDF framework, simplifying integration.
*   **Limitations:** The abstract nature requires careful implementation of sampling algorithms, which can be non-trivial for complex phase functions. The direction convention may confuse users familiar with standard scattering literature.

**When to Use:**
Use this interface when implementing custom phase functions within the pbrt framework. It is suitable for any participating media simulation requiring angular scattering distribution.

## Background
The Phase Function Interface was introduced in the pbrt rendering system as part of its volume scattering module. It is documented in "Physically Based Rendering: From Theory to Implementation" (3rd edition), specifically in Chapter 11 on Volume Scattering [S1]. The interface design reflects pbrt's consistent use of outgoing-direction conventions for all transport quantities.
