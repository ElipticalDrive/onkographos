# Point Query × Point Data, 3D Blur

Also called: Conventional Radiance Estimation, Standard volumetric radiance estimate, Jensen and Christensen estimate

## Overview
This method estimates the in-scattered radiance at a specific 3D query point $\mathbf{x}$ by aggregating the energy of nearby photon points stored in a photon map [S1, S2]. It solves the problem of reconstructing continuous radiance from discrete photon samples by applying a normalized 3D spherical kernel [S2]. It is distinguished from its siblings by using point-based data and a 3D blur kernel, whereas variants like [Beam Query × Beam Data, 2D Blur](4555-beam-query-beam-data-2d-blur.md) use extended beam data and 2D blurring to reduce bias along the ray direction [S1].

## How it works
**Inputs and Outputs**
*   **Input**: A query point $\mathbf{x}$, a query direction $\vec{\omega}$ (for the scattering function), a spherical kernel radius $r$, and a photon map containing photon points. Each photon point $p$ has position $\mathbf{x}_p$, power $\Phi_p$, and incident direction $\vec{\omega}_p$.
*   **Output**: The estimated in-scattered radiance $L_i(\mathbf{x} \rightarrow \vec{\omega})$ at the query point.

**Data Structures**
The photon map stores discrete photon points. Each entry contains:
*   `position`: 3D vector $\mathbf{x}_p$.
*   `power`: Scalar $\Phi_p$ (radiant flux).
*   `direction`: 3D vector $\vec{\omega}_p$ (incident direction).

**Algorithm**
1.  **Search**: Identify all photon points $p$ within the spherical query region $R$ centered at $\mathbf{x}$ with radius $r$. The region is defined by $\|\mathbf{x}_p - \mathbf{x}\| \le r$.
2.  **Summation**: For each photon $p \in R$, compute the product of the phase function $f(\theta_p)$ and the photon power $\Phi_p$. The phase function is evaluated based on the scattering angle $\theta_p$ between the photon's incident direction $\vec{\omega}_p$ and the query direction $\vec{\omega}$ (or the direction from which radiance is being estimated).
3.  **Normalization**: Sum these products and divide by the volume measure of the query region, $\mu_R(r^3)$. For a spherical kernel, $\mu_R(r^3) = \frac{4}{3}\pi r^3$.

**Formulas**
The in-scattered radiance $L_i$ is estimated as [S2]:

$$
L_i(\mathbf{x} \rightarrow \vec{\omega}) \approx \frac{1}{\sigma_s \mu_R(r^3)} \sum_{p \in R} f(\theta_p) \Phi_p
$$

Where:
*   $\sigma_s$ is the scattering coefficient at the query point $\mathbf{x}$ [S2].
*   $\mu_R(r^3)$ is the volume of the query region. For a sphere of radius $r$, $\mu_R(r^3) = \frac{4}{3}\pi r^3$.
*   $f(\theta_p)$ is the phase function value for the scattering angle $\theta_p$.
*   $\Phi_p$ is the power of photon $p$.
*   The summation is over all photons $p$ found within the 3D query region $R$.

*Note: In some formulations (e.g., [S1]), the scattering coefficient $\sigma_s$ is absorbed into the material shading function $s$ or omitted if the photon power is defined differently. However, [S2] explicitly includes $\sigma_s$ in the denominator for the standard point estimate.*

**Pseudocode**
```python
def estimate_in_scattered_radiance(query_point, query_direction, radius, photon_map):
    """
    Estimates in-scattered radiance at a point using 3D-blurred photon points.
    
    Args:
        query_point (Vec3): The 3D location x where radiance is estimated.
        query_direction (Vec3): The direction omega for which radiance is estimated.
        radius (float): The spherical kernel radius r.
        photon_map (List[Photon]): List of photon points with position, power, direction.
        
    Returns:
        float: Estimated in-scattered radiance L_i.
    """
    # 1. Define the query region R (sphere of radius r centered at query_point)
    # 2. Search for photons within R
    nearby_photons = []
    for photon in photon_map:
        dist_sq = dot(query_point - photon.position, query_point - photon.position)
        if dist_sq <= radius * radius:
            nearby_photons.append(photon)
            
    # 3. Sum contributions
    sum_contribution = 0.0
    for photon in nearby_photons:
        # Calculate scattering angle theta_p between incident direction and query direction
        # Note: Phase function f(theta) depends on the specific medium model (e.g., Henyey-Greenstein)
        # Here we assume a generic phase function evaluation
        cos_theta = dot(normalize(photon.direction), normalize(query_direction))
        phase_value = evaluate_phase_function(cos_theta)
        
        sum_contribution += phase_value * photon.power
        
    # 4. Normalize by volume measure and scattering coefficient
    # Volume of sphere: 4/3 * pi * r^3
    volume_measure = (4.0 / 3.0) * 3.141592653589793 * (radius ** 3)
    
    # Scattering coefficient sigma_s at query_point
    # [G] sigma_s must be retrieved from the medium's property at query_point.
    sigma_s = get_scattering_coefficient(query_point)
    
    if sigma_s == 0:
        return 0.0
        
    radiance = sum_contribution / (sigma_s * volume_measure)
    
    return radiance
```

**Parameters**
*   $r$: Spherical kernel radius. Typical values depend on photon density and scene scale. Not given in the sources.
*   $n$: Number of closest photons. In the standard 3D blur point estimate, all photons within radius $r$ are used, not a fixed $n$ [S1, S2].

**Edge Cases and Pitfalls**
*   **Heterogeneous Media**: The scattering coefficient $\sigma_s$ and extinction coefficient $\sigma_t$ vary with position. The formula assumes $\sigma_s$ is evaluated at the query point [S2].
*   **Boundary Conditions**: If the query point is near a boundary, the spherical kernel may extend outside the medium. The sources note that spatially adaptive blurring kernels are possible to handle such cases, but the standard method uses a constant spherical kernel [S2].
*   **Zero Scattering**: If $\sigma_s = 0$, the estimate is undefined. A guard should return 0 or handle this case appropriately [G].

## Subtopics

## Operating characteristics
*   **Time Complexity**: $O(N)$ for a brute-force search, where $N$ is the number of photons. With a spatial acceleration structure (e.g., k-d tree), the search is $O(\log N + k)$, where $k$ is the number of photons in the kernel.
*   **Memory Complexity**: $O(N)$ to store the photon map.
*   **Strengths**: Simple to implement; provides a direct estimate of point-wise radiance [S2].
*   **Limitations**: Can introduce bias if the kernel radius is too large or too small. The 3D blur can smear energy along the ray direction, potentially causing bias in beam radiance estimates if not integrated carefully [S1].
*   **When to use**: When point-wise radiance is required, or as a component in more complex estimators. It is the baseline for comparison with beam-based methods [S2].

## Background
The method was introduced by Jensen and Christensen in 1998 as the conventional radiance estimation technique for photon mapping in participating media [S1, S2]. It is based on the standard photon mapping approach where photon densities are estimated using kernel density estimation [S1]. The method is reviewed in Section 4.1 of Jarosz et al. [2011a] as the standard volumetric radiance estimate [S2].
