# Point Query × Point Data, 3D Blur

Also called: Conventional Radiance Estimation, Standard volumetric radiance estimate, Jensen and Christensen estimate

## Overview
This method estimates the in-scattered radiance at a specific query point within a participating medium by aggregating the energy of the $n$ closest photons stored within a spherical kernel of radius $r$ [S1, S2]. It solves the problem of reconstructing continuous radiance from discrete photon samples by applying a uniform 3D blurring kernel, effectively averaging photon power over the volume of the query region [S2]. It is distinguished from its siblings by using point-based data (individual photons) rather than beam-based data, and by applying 3D blur to the query, whereas variants like [Beam Query × Beam Data, 2D Blur](4555-beam-query-beam-data-2d-blur.md) blur only in the dimensions perpendicular to the beam direction to reduce bias [S1].

## How it works
**Inputs:**
*   Query point $\mathbf{x}$ in the medium.
*   View direction $\vec{\omega}$ (or outgoing direction $\vec{\omega}_0$).
*   Photon map: A collection of photons, each storing position $\mathbf{x}_p$, power $\Phi_p$, and incident direction (used to determine phase function angle $\theta_p$).
*   Kernel radius $r$.
*   Number of nearest neighbors $n$ (optional, if using fixed radius, $n$ is determined by the search; if using fixed $n$, $r$ is determined by the $n$-th neighbor).

**Outputs:**
*   Estimated in-scattered radiance $L_i(\mathbf{x} \rightarrow \vec{\omega})$.

**Data Structures:**
*   **Photon:** A structure containing:
    *   `pos`: 3D vector $(x, y, z)$ representing the photon's position in the medium.
    *   `power`: Scalar float representing the flux $\Phi_p$ carried by the photon.
    *   `incident_dir`: 3D vector representing the direction from which the photon arrived.
*   **Spatial Index:** A data structure (e.g., k-d tree, grid) allowing efficient retrieval of photons within a spherical region or the $n$ nearest neighbors to $\mathbf{x}$.

**Parameters:**
*   $r$: The radius of the spherical query kernel. Typical values depend on photon density; often chosen to contain a fixed number of photons (e.g., $n=10-20$) to balance bias and variance [S1].
*   $n$: The number of closest photons used for density estimation [S1].

**Formulas:**
The in-scattered radiance $L_i$ at query point $\mathbf{x}$ is estimated by summing the contributions of all photons $p$ found within the 3D query region $R$ (typically a sphere of radius $r$ centered at $\mathbf{x}$) [S2]:

$$ L_i(\mathbf{x} \rightarrow \vec{\omega}) \approx \frac{1}{\sigma_s \mu_R(r^3)} \sum_{p \in R} f(\theta_p) \Phi_p $$

Where:
*   $\sigma_s$ is the scattering coefficient of the medium at $\mathbf{x}$ [S2].
*   $\mu_R(r^3)$ is the volume measure of the query region $R$. For a sphere of radius $r$, $\mu_R(r^3) = \frac{4}{3}\pi r^3$ [S2].
*   $f(\theta_p)$ is the phase function evaluated at the scattering angle $\theta_p$. The angle $\theta_p$ is the angle between the photon's incident direction and the outgoing view direction $\vec{\omega}$ [S2].
*   $\Phi_p$ is the power (flux) of photon $p$ [S2].

Alternatively, using the material shading function $s(\mathbf{x}', \omega_i, \omega_0)$ which encapsulates the phase function and scattering coefficient, the estimate is often written as [S1]:

$$ L_{ms}(\mathbf{x}, \omega_0) \approx \sum_{i=1}^{n} s(\mathbf{x}', \omega_i, \omega_0) \frac{\Delta \Phi(\mathbf{x}', \omega_i)}{\frac{4}{3}\pi r^3} $$

Where $\Delta \Phi$ is the flux of photon $i$ [S1].

**Steps:**
1.  **Search:** Identify the set of photons $P_R$ located within the spherical query region $R$ centered at $\mathbf{x}$ with radius $r$. If using a fixed-$n$ approach, identify the $n$ closest photons and determine the radius $r$ required to enclose them.
2.  **Initialize Accumulator:** Set $L_{sum} = 0$.
3.  **Iterate:** For each photon $p$ in $P_R$:
    a. Calculate the scattering angle $\theta_p$ between the photon's incident direction and the view direction $\vec{\omega}$.
    b. Evaluate the phase function $f(\theta_p)$.
    c. Add the contribution to the accumulator: $L_{sum} \leftarrow L_{sum} + f(\theta_p) \Phi_p$.
4.  **Normalize:** Divide the sum by the volume measure and the scattering coefficient:
    $$ L_i(\mathbf{x} \rightarrow \vec{\omega}) = \frac{L_{sum}}{\sigma_s \cdot \frac{4}{3}\pi r^3} $$
5.  **Return:** The computed radiance $L_i$.

**Pseudocode:**
```python
def estimate_inscattered_radiance(query_point, view_direction, photon_map, radius, scattering_coefficient):
    """
    Estimates in-scattered radiance at a query point using Point Query x Point Data, 3D Blur.
    
    Args:
        query_point: 3D vector (x, y, z)
        view_direction: 3D vector (normalized)
        photon_map: Object with method find_photons_in_sphere(center, radius) returning list of photons
        radius: Float, radius of the spherical kernel
        scattering_coefficient: Float, sigma_s of the medium at query_point
        
    Returns:
        Float, estimated radiance
    """
    # Step 1: Search for photons within the spherical kernel
    photons_in_region = photon_map.find_photons_in_sphere(query_point, radius)
    
    if not photons_in_region:
        return 0.0
        
    sum_contribution = 0.0
    volume_measure = (4.0 / 3.0) * math.pi * (radius ** 3)
    
    # Step 3: Iterate and sum contributions
    for photon in photons_in_region:
        # Calculate scattering angle theta_p
        # theta_p is the angle between photon's incident direction and view_direction
        incident_dir = photon.incident_direction
        cos_theta = dot(incident_dir, view_direction)
        # Clamp to [-1, 1] to handle floating point errors
        cos_theta = max(-1.0, min(1.0, cos_theta))
        theta_p = acos(cos_theta)
        
        # Evaluate phase function f(theta_p)
        phase_value = evaluate_phase_function(theta_p)
        
        # Add contribution: f(theta_p) * Phi_p
        sum_contribution += phase_value * photon.power
        
    # Step 4: Normalize by volume measure and scattering coefficient
    # Note: Some formulations absorb sigma_s into the phase function or shading function.
    # Based on [S2], the formula explicitly divides by sigma_s * volume.
    radiance = sum_contribution / (scattering_coefficient * volume_measure)
    
    return radiance
```

**Edge Cases and Pitfalls:**
*   **Empty Query Region:** If no photons are found within radius $r$, the estimate is zero. This can cause dark spots in sparse regions. [G] A common mitigation is to increase $r$ dynamically or use a fallback estimator, though this introduces bias.
*   **Heterogeneous Media:** The formula assumes a constant scattering coefficient $\sigma_s$ within the kernel. In heterogeneous media, $\sigma_s$ varies with position. The standard estimate uses $\sigma_s$ at the query point $\mathbf{x}$ [S2]. This is an approximation; more accurate estimates might integrate $\sigma_s$ over the kernel volume, but this is not part of the standard definition [S2].
*   **Boundary Conditions:** If the query sphere extends outside the medium, photons outside the medium should not be included. The spatial search must respect the medium boundaries.
*   **Precision:** For very small $r$, the volume measure becomes small, potentially leading to numerical instability if the sum of contributions is also small. [G] Ensure floating-point precision is sufficient for the scale of the scene.

## Subtopics

## Operating characteristics
*   **Time Complexity:** $O(N)$ for a brute-force search, where $N$ is the total number of photons. With a spatial index (e.g., k-d tree), the search for photons within radius $r$ is typically $O(\log N + k)$, where $k$ is the number of photons in the kernel. The summation is $O(k)$.
*   **Memory Complexity:** $O(N)$ to store the photon map.
*   **Performance:** The method is computationally efficient per query point compared to ray marching for incident radiance, as it avoids integrating transmittance along rays for each sample [S2]. However, the quality depends heavily on the choice of $r$. Small $r$ leads to high variance (noisy) images; large $r$ leads to high bias (blurred) images.
*   **Strengths:** Simple to implement; provides a direct estimate of point radiance; widely used as a baseline.
*   **Limitations:** High variance in sparse regions; bias in dense regions if $r$ is too large; requires careful tuning of $r$ or $n$.
*   **When to use:** When a simple, fast estimate of point radiance is sufficient, or as a baseline for comparison.
*   **When not to use:** When high accuracy in sparse regions is required without excessive noise, or when computational resources are extremely limited and a simpler, lower-quality estimate is acceptable (though this method is already quite simple).

## Background
The method was introduced by Henrik Wann Jensen and Hans H. Christensen in 1998 [S2]. It is based on the concept of photon mapping for participating media, where photons are stored in a photon map and radiance is estimated by density estimation using a kernel function. The specific formulation using a spherical kernel and dividing by the volume is the "conventional" or "standard" volumetric radiance estimate. It serves as the foundation for more advanced estimators in the family, such as those using beam data or different blur dimensions [S2].
