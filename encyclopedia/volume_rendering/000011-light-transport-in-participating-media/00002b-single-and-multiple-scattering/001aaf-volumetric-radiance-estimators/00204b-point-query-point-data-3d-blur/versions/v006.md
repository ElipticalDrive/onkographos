# Point Query × Point Data, 3D Blur

Also called: Conventional Radiance Estimation, Standard volumetric radiance estimate, Jensen and Christensen estimate

## Overview
Point Query × Point Data, 3D Blur estimates the in-scattered radiance at a specific 3D point by averaging the energy of nearby discrete photon points within a spherical kernel. It solves the problem of reconstructing continuous radiance fields from discrete photon samples in participating media. It differs from its sibling, the Extended Balance Heuristic, by using a fixed spherical kernel and simple density estimation rather than balancing probabilities, and from its child, Beam Query × Beam Data, 2D Blur, by blurring energy in three dimensions rather than restricting it to a 2D cross-section perpendicular to a beam direction [S1, S2].

## How it works
**Inputs:**
*   A query point $\mathbf{x}$ in the medium.
*   A viewing direction $\vec{\omega}$ (or $\vec{\omega}_0$ in [S1]).
*   A set of stored photons, each defined by position $\mathbf{x}_p$, power $\Phi_p$, and incident direction $\vec{\omega}_p$.
*   A spherical kernel radius $r$.
*   The scattering coefficient $\sigma_s$ and extinction coefficient $\sigma_t$ of the medium at $\mathbf{x}$.
*   The phase function $f(\theta)$, where $\theta$ is the scattering angle between the incident photon direction and the viewing direction.
*   The material shading function $s(\mathbf{x}', \omega_i, \omega_0)$, which typically incorporates the phase function and scattering coefficient [S1, S2].

**Outputs:**
*   The estimated in-scattered radiance $L_i(\mathbf{x} \rightarrow \vec{\omega})$ at the query point.

**Data Structures:**
*   **Photon Map:** A spatial data structure (e.g., k-d tree or grid) storing photon points. Each photon entry contains:
    *   `position`: 3D vector $\mathbf{x}_p$.
    *   `power`: Scalar $\Phi_p$ (energy deposited).
    *   `direction`: 3D vector $\vec{\omega}_p$ (incident direction).
*   **Query Region:** A sphere of radius $r$ centered at $\mathbf{x}$.

**Steps:**
1.  **Search:** Identify all photons $p$ stored in the medium such that their position $\mathbf{x}_p$ lies within the spherical query region $R$ centered at $\mathbf{x}$ with radius $r$. That is, $||\mathbf{x}_p - \mathbf{x}|| \le r$.
2.  **Compute Scattering Angle:** For each photon $p$ in the region, calculate the angle $\theta_p$ between the photon's incident direction $\vec{\omega}_p$ and the query viewing direction $\vec{\omega}$.
    $$ \cos \theta_p = \vec{\omega}_p \cdot \vec{\omega} $$
    (Assuming normalized vectors).
3.  **Evaluate Phase Function:** Compute the phase function value $f(\theta_p)$ for each photon. Common choices include Henyey-Greenstein or Mie phase functions.
4.  **Sum Contributions:** Sum the product of the phase function and the photon power for all photons in the region.
5.  **Normalize:** Divide the sum by the volume measure of the query region, $\mu_R(r^3) = \frac{4}{3}\pi r^3$, and the scattering coefficient $\sigma_s$ [S2]. Note: [S1] incorporates $\sigma_s$ and the phase function into the shading function $s$, effectively normalizing by volume only. The standard form [S2] explicitly divides by $\sigma_s$.

**Formula:**
The in-scattered radiance $L_i$ is estimated as [S2]:

$$ L_i(\mathbf{x} \rightarrow \vec{\omega}) \approx \frac{1}{\sigma_s \mu_R(r^3)} \sum_{p \in R} f(\theta_p) \Phi_p $$

Where:
*   $\mu_R(r^3) = \frac{4}{3}\pi r^3$ is the volume of the spherical kernel.
*   $f(\theta_p)$ is the phase function value.
*   $\Phi_p$ is the power of photon $p$.
*   $\sigma_s$ is the scattering coefficient.

Alternatively, using the shading function $s$ which encapsulates the scattering properties [S1]:

$$ L_{ms}(\mathbf{x}, \omega_0) \approx \sum_{i=1}^{n} s(\mathbf{x}', \omega_i, \omega_0) \frac{\Delta \Phi(\mathbf{x}', \omega_i)}{\frac{4}{3}\pi r^3} $$

Where $n$ is the number of closest photons, and $\Delta \Phi$ is the flux of photon $i$.

**Pseudocode:**
```python
def estimate_inscattered_radiance(query_point, view_direction, photon_map, radius, sigma_s, phase_function):
    """
    Estimates in-scattered radiance at query_point using Point Query x Point Data, 3D Blur.
    
    Args:
        query_point: 3D vector (x, y, z)
        view_direction: 3D vector (normalized)
        photon_map: Object with method search_sphere(center, radius) returning list of photons
        radius: float, kernel radius r
        sigma_s: float, scattering coefficient
        phase_function: function(theta) returning phase value for angle theta
        
    Returns:
        float: Estimated radiance
    """
    # Step 1: Search for photons within the spherical kernel
    photons_in_region = photon_map.search_sphere(query_point, radius)
    
    volume_measure = (4.0 / 3.0) * math.pi * (radius ** 3)
    
    sum_contribution = 0.0
    
    for photon in photons_in_region:
        # Step 2: Compute scattering angle
        # Photon direction is stored in photon.direction
        # Compute cosine of angle between incident photon direction and view direction
        cos_theta = dot(photon.direction, view_direction)
        
        # Clamp to [-1, 1] to handle floating point errors
        cos_theta = max(-1.0, min(1.0, cos_theta))
        
        # Step 3: Evaluate phase function
        # Note: phase_function usually takes theta in radians or cos_theta directly.
        # Assuming it takes cos_theta for efficiency, otherwise use acos(cos_theta)
        f_theta = phase_function(cos_theta)
        
        # Step 4: Sum contributions
        # Photon power is stored in photon.power
        sum_contribution += f_theta * photon.power
        
    # Step 5: Normalize
    # Divide by sigma_s and volume measure
    if volume_measure == 0:
        return 0.0
        
    radiance = sum_contribution / (sigma_s * volume_measure)
    
    return radiance
```

**Parameters:**
*   $r$: The radius of the spherical kernel. Typical values depend on photon density and scene scale. Not given in the sources as a specific number, but it is the primary tuning parameter.
*   $n$: The number of closest photons. In the standard spherical kernel implementation, $n$ is determined by the radius $r$ and photon density. Some variants use a fixed $n$ with a variable radius, but the standard definition [S2] uses a fixed radius $R$.

**Edge Cases and Pitfalls:**
*   **Empty Region:** If no photons fall within the radius $r$, the estimate is zero. This causes noise in sparse regions. [G] A common mitigation is to increase $r$ or use $k$-nearest neighbors instead of a fixed radius, though this changes the estimator to a different variant.
*   **Heterogeneous Media:** The formula assumes $\sigma_s$ and $\sigma_t$ are constant within the kernel or evaluated at the query point. In highly heterogeneous media, this assumption introduces bias. [S2] notes that spatially adaptive blurring kernels are possible but not detailed in the standard definition.
*   **Boundary Effects:** Photons near the boundary of the medium may have their kernels truncated, leading to underestimation. [G] Standard implementations do not correct for this unless boundary handling is explicitly added.

## Subtopics

### [Beam Query × Beam Data, 2D Blur](4555-beam-query-beam-data-2d-blur.md)
Beam Query × Beam Data, 2D Blur is a radiance estimation technique for participating media that computes the accumulated in-scattered radiance along an eye ray by querying photon beams and blurring their energy in two dimensions perpendicular to the beam direction. It solves the problem of estimating light transport in participating media without the bias introduced by blurring along the beam's length, which is inherent in the 3D blur variant. It differs from its parent, Point Query × Point Data, 3D Blur, by using continuous beam data instead of discrete point data and restricting the spatial blur to a 2D cross-section, thereby reducing bias for the same radius. It differs from the Beam × Beam 1D estimate by performing a 2D spatial blur rather than a 1D line blur, making it more general for volumetric scenes where the beam direction varies significantly relative to the view.

## Operating characteristics
*   **Time Complexity:** $O(N)$ for a naive search, where $N$ is the number of photons. With a spatial index (k-d tree), the average case is $O(\log N + k)$, where $k$ is the number of photons in the kernel.
*   **Memory Complexity:** $O(N)$ to store the photon map.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Performance degrades if photon density is low, requiring larger kernels which increase $k$.
*   **Strengths:** Simple to implement; unbiased in the limit of infinite photons and zero radius; widely understood.
*   **Limitations:** Biased for finite samples; sensitive to kernel radius; noisy in sparse regions; 3D blur can introduce bias along the beam direction compared to 2D blur variants [S1].
*   **When to use:** When simplicity is prioritized and photon density is sufficient to fill the kernel.
*   **When not to use:** In highly sparse regions or when bias along the beam direction is critical (use Beam variants).

## Background
The method was introduced by Henrik Wann Jensen and Hans H. Christensen in 1998 [S2]. It is the original volumetric radiance estimate, computing in-scattered radiance at a query point by searching for photon points stored within the medium and blurring values in three dimensions. It is reviewed in Section 4.1 of Jarosz et al. [2011a] as the baseline for comparison with newer estimators.
