# Sample Matching for Extinction Gradients

Also called: Sample Matching for Joint Extinction Gradient Estimation

## Overview
Sample Matching for Extinction Gradients is a technique for differentiating volumetric transport with respect to the extinction coefficient by evaluating the scattering term (positive contribution) and the transmittance term (negative contribution) at shared locations along each path segment, turning their negative correlation into variance reduction [S1, unofficial]. Unlike standard estimators that evaluate these terms at unrelated points, this method aligns the sampling locations to reduce variance in gradient estimation [S1, unofficial]. It is implemented as the `prbvolpath_sm` plugin in Mitsuba 3, supporting both RGB and spectral variants [S1, unofficial].

## How it works
The method splits the computation into two separate megakernels: a primal pass and an adjoint pass. The primal pass runs path tracing identical to [prbvolpath](35-single-and-multiple-scattering.md) but performs no gradient sampling. It writes one small record per segment with a masked scatter, letting values die at the end of the iteration. The adjoint pass reads the segment records back and performs gradient sampling, processing one lane per record [S1, unofficial].

### Inputs and Outputs
**Inputs:**
*   Scene geometry and medium properties (extinction coefficient $\sigma_t$, scattering coefficient $\sigma_s$, phase function $p$).
*   Camera parameters and pixel batch.
*   Integrator parameters: `segment_slots`, `gradient_samples_per_segment`.

**Outputs:**
*   Radiance image (primal pass).
*   Gradient of radiance with respect to extinction coefficients (adjoint pass).

### Data Structures
**Segment Record:**
*   Contains masked scatter values for segment data.
*   Fields are generated from the variant's spectrum size (RGB or spectral).
*   Each record carries the path's wavelengths so the second kernel evaluates the medium at the correct wavelengths [S1, unofficial].

### Parameters
*   `segment_slots`: Selects between estimators.
    *   Default: `max_depth + 1` (one record slot per lane per completed segment). Registered as `prbvolpath_sm_quad`.
    *   Value `1`: One weighted reservoir per lane. The retained segment stands in for the whole path, scaled by the inverse selection probability. Registered as `prbvolpath_sm_linear`.
    *   Value `>1`: Linear mapping where segment $j$ goes to slot $\min(j, \text{segment\_slots} - 1)$. The first `segment_slots - 1` segments are kept exactly; everything from there on shares one reserved row per lane and is resolved by a weighted reservoir [S1, unofficial].
*   `gradient_samples_per_segment`: Number of gradient samples taken per segment. Typical values are 1 or 4. Raising from 1 to 4 costs about 35% in time but reduces variance [S1, unofficial].

### Algorithm Steps

1.  **Primal Pass (Path Tracing):**
    1.  Initialize path state.
    2.  Loop over path segments $j = 0, 1, \dots$:
        a.  Sample distance to next interaction using [Homogeneous Medium Sampling](980-homogeneous-medium-sampling.md) or [Delta tracking](985-delta-tracking.md).
        b.  Compute transmittance $T$ and scattering contribution $S$ for the segment.
        c.  Store a **Segment Record** containing the masked scatter values and the path's wavelengths.
        d.  Update reservoir running weight (only one scalar kept in loop state to avoid continuation spills) [S1, unofficial].
        e.  If Russian Roulette terminates the path, break.
    3.  Accumulate radiance for the pixel.

2.  **Adjoint Pass (Gradient Sampling):**
    1.  Read Segment Records from the primal pass output.
    2.  For each lane/record:
        a.  For $k = 1$ to `gradient_samples_per_segment`:
            i.   Trace a fresh sub-path (or use sample matching logic) to estimate the gradient contribution.
            ii.  Evaluate the medium at the shared locations along the segment using the stored wavelengths.
            iii. Accumulate gradient estimates.
    3.  Output gradients [S1, unofficial].

### Pseudocode

```python
def primal_pass(scene, camera, pixel_batch, segment_slots, max_depth):
    """
    Runs path tracing identical to prbvolpath.
    Writes segment records to a buffer.
    """
    # Buffer for segment records. Size depends on segment_slots and wavefront size.
    segment_records = allocate_buffer(segment_slots * wavefront_size)
    
    for lane in wavefront:
        path_state = initialize_path(camera, lane)
        reservoir_weight = 0.0
        
        for j in range(max_depth):
            # Sample next interaction
            dist, hit_point = sample_interaction(scene, path_state)
            
            # Compute transmittance and scattering
            # T is transmittance over the segment
            # S is the scattered radiance contribution
            T, S = compute_transmittance_and_scatter(scene, path_state, dist)
            
            # Mask scatter if terminated or other conditions
            masked_S = apply_mask(S, path_state)
            
            # Store record
            # Slot index: min(j, segment_slots - 1) for linear mapping
            # Or specific slot for quad mapping (default max_depth + 1)
            slot_idx = min(j, segment_slots - 1)
            segment_records[lane, slot_idx] = {
                'scatter': masked_S,
                'wavelengths': path_state.wavelengths,
                'hit_point': hit_point
            }
            
            # Update reservoir weight
            reservoir_weight += masked_S
            
            # Russian Roulette
            if terminate_path(path_state):
                break
        
        # Final radiance accumulation
        pixel_batch[lane] += reservoir_weight

def adjoint_pass(scene, segment_records, gradient_samples_per_segment):
    """
    Reads segment records and performs gradient sampling.
    """
    gradients = allocate_buffer(wavefront_size)
    
    for lane in wavefront:
        lane_gradient = 0.0
        
        # Iterate over stored segment records for this lane
        for slot_idx in range(segment_records.size(lane)):
            record = segment_records[lane, slot_idx]
            
            # Skip empty records
            if record is None:
                continue
                
            # Sample gradient contributions
            for k in range(gradient_samples_per_segment):
                # Trace fresh sub-path or use sample matching
                # Evaluate medium at shared locations using record's wavelengths
                grad_contribution = estimate_gradient_contribution(
                    scene, 
                    record['hit_point'], 
                    record['wavelengths'],
                    record['scatter']
                )
                lane_gradient += grad_contribution
        
        gradients[lane] = lane_gradient

    return gradients
```

### Edge Cases and Pitfalls
*   **Continuation Spills:** Keeping a segment's record in loop state (named variables or `dr.alloc_local`) causes +2.5 KiB/thread of continuation spills and +45% adjoint time on the bunny scene, with no benefit under analytic intersection. This is avoided by splitting the pass into two kernels [S1, unofficial].
*   **Reconnection:** Reusing the path's own continuation instead of tracing fresh sub-paths was tried but dropped. It resulted in worse variance due to shift mapping weights carrying transmittance ratios ranging from $10^{-9}$ to 356, with only 4.8% of samples reusable [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The primal pass is faster than `prbvolpath` because it consumes null collisions in one fused C++ walk instead of paying `optixTrace` for each. On a Bunny cloud scene (768x576, 64 spp), `prbvolpath` took 104.5 s and `prbvolpath_sm` took 72.1 s [S1, unofficial]. The adjoint pass adds overhead; raising `gradient_samples_per_segment` from 1 to 4 costs about 35% in time [S1, unofficial].
*   **Memory Complexity:** Memory usage scales with `segment_slots`. For a wavefront size resulting in 4.6 GB overhead per slot per segment, `prbvolpath_sm_quad` (default) uses ~8301 MiB (7042 MiB above idle), while `prbvolpath_sm_linear` (1 slot) uses ~3725 MiB (2466 MiB above idle) [S1, unofficial].
*   **Variance Reduction:** On a Bunny cloud scene (768x576, 8 spp, N=516 adjoint renders), sample matching with 4 slots reduced variance from 136.5 (DRT reference) to 46.4 (occupied voxels) and 81.4 (all voxels), a 0.26x factor [S1, unofficial].
*   **Strengths:** Significant variance reduction for extinction gradients. Efficient primal rendering.
*   **Limitations:** Higher memory usage with more segment slots. Adjoint pass is slower than primal pass.
