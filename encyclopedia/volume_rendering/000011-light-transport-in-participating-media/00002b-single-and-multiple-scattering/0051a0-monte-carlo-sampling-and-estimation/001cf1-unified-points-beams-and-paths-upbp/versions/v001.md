# Unified Points, Beams, and Paths (UPBP)

## Overview
Unified Points, Beams, and Paths (UPBP) is a combined rendering algorithm that fuses volumetric radiance estimators (Point-Point, Point-Beam, Beam-Beam) and their short-beam variants with unbiased bidirectional path tracing (BPT) techniques using the extended balance heuristic [S1]. It solves the problem of efficiently simulating light transport in participating media by subsuming previous methods like volumetric photon mapping and bidirectional path tracing into a single framework that leverages the strengths of both biased density estimation and unbiased path connection [S1]. Unlike its siblings, it explicitly unifies surface and medium vertex connections with beam-based segment estimators, fully subsuming the techniques of Georgiev et al. [2012] and Hachisuka et al. [2012] [S1].

## How it works
The algorithm operates in two stages: a light subpath tracing and storage stage, followed by an eye subpath tracing and estimation stage [S1].

**Inputs and Outputs**
*   **Inputs:** Scene geometry, participating media properties (extinction, scattering, phase function), light sources, camera parameters, and iteration count.
*   **Outputs:** Radiance estimate for each pixel.

**Data Structures**
The implementation stores light subpath information in specific acceleration structures [S1]:
1.  **Hashed Grids:** Separate hashed grids for surface vertices and medium vertices. These are used for Point-Point (P-P) estimators.
2.  **Bounding Volume Hierarchy (BVH):** Built over medium vertices specifically for the Point-Beam (P-B) estimator.
3.  **Uniform Grid:** Organizes photon beams. This was found faster than a BVH for beams, though query performance is suboptimal [S1].
4.  **Storage Ratio:** Fewer photon beams are stored than points because the computational and memory cost per beam is much larger [S1].

**Selected Estimators**
To reduce bias and computational cost, the implementation uses only minimum-blur volumetric estimators: P-P3D, P-B2D, and B-B1D [S1]. Specifically, it uses short photon beams and long query beams (P-P3D, P-Bl2D, Bs-Bl1D) for best performance, as long photon beams have high construction and query costs that are rarely compensated by variance reduction [S1]. The implementation uses P-B2D (photon points and query beams) rather than B-P2D for efficiency [S1].

**Stage 1: Light Subpath Tracing and Storage**
1.  Trace a number of light subpaths.
2.  Connect vertices of the light subpaths to the eye (light tracing).
3.  Store vertices as "photon points" and segments as "photon beams" [S1].
4.  Build separate hashed grids over the surface and medium vertices for P-P estimators [S1].
5.  Build a BVH over medium vertices for the P-B estimator [S1].
6.  Organize photon beams in a uniform grid [S1].

**Stage 2: Eye Subpath Tracing and Estimation**
For each iteration, trace one eye subpath per pixel. At each vertex and segment of the eye subpath, construct estimates [S1]:

1.  **Unbiased BPT Connections:** For each vertex (surface or medium), connect to a light source and to vertices of a light subpath to evaluate unbiased BPT estimators [S1].
2.  **Point-Point Estimators:** At each eye subpath vertex, evaluate P-P2D (for surface vertices) or P-P3D (for medium vertices) by looking up photons from the corresponding hashed grid [S1].
3.  **Point-Beam Estimators:** For each eye subpath segment passing through a medium, evaluate P-Bl2D and Bs-Bl1D estimators [S1].

**Pseudocode**

```python
def upbp_render(scene, camera, num_iterations, num_light_subpaths):
    # Data structures
    surface_grid = HashedGrid()
    medium_grid = HashedGrid()
    medium_bvh = BVH()
    beam_grid = UniformGrid()
    
    for iteration in range(num_iterations):
        # Stage 1: Light Subpath Tracing
        light_subpaths = []
        for _ in range(num_light_subpaths):
            subpath = trace_light_subpath(scene)
            light_subpaths.append(subpath)
            
            # Store vertices and beams
            for vertex in subpath.vertices:
                if vertex.is_surface:
                    surface_grid.insert(vertex)
                else:
                    medium_grid.insert(vertex)
                    medium_bvh.insert(vertex)
            
            for segment in subpath.segments:
                if segment.is_in_medium:
                    beam_grid.insert(segment)
        
        # Stage 2: Eye Subpath Tracing
        for pixel in camera.pixels:
            eye_subpath = trace_eye_subpath(scene, camera, pixel)
            radiance = 0.0
            
            for vertex in eye_subpath.vertices:
                # Unbiased BPT connections
                radiance += evaluate_bpt_estimators(vertex, light_subpaths, scene)
                
                # Point-Point estimators
                if vertex.is_surface:
                    radiance += evaluate_pp2d(vertex, surface_grid, scene)
                else:
                    radiance += evaluate_pp3d(vertex, medium_grid, scene)
            
            for segment in eye_subpath.segments:
                if segment.is_in_medium:
                    # Point-Beam estimators (short photon beams, long query beams)
                    radiance += evaluate_pbl2d(segment, medium_grid, beam_grid, scene)
                    radiance += evaluate_bsbl1d(segment, medium_grid, beam_grid, scene)
            
            pixel.radiance += radiance

    return average_iterations(camera.pixels)
```

**Edge Cases and Pitfalls**
*   **Long Beams:** Long photon beams have much higher construction and query costs. Using them is generally not productive as the overhead is rarely compensated by variance reduction [S1].
*   **Query Performance:** The uniform grid for photon beams has suboptimal query performance compared to a BVH, but was found to be faster overall for construction and total time [S1].
*   **Joint Importance Sampling:** The algorithm does not use joint path importance sampling techniques [S1]. Including them would further reduce variance, especially in scenes with highly anisotropically scattering media [S1].

## Operating characteristics
*   **Complexity:** Not given in the sources.
*   **Performance:** The use of short photon beams and long query beams (P-P3D, P-Bl2D, Bs-Bl1D) provides the best performance for a given time budget [S1].
*   **Strengths:** Excels at connecting subpaths over long distances (e.g., direct illumination in media far away from the light) via BPT components [S1]. Subsumes previous methods, providing a unified framework [S1].
*   **Limitations:** The uniform grid for beams has suboptimal query performance [S1]. Does not currently use joint path importance sampling, which could reduce variance in highly anisotropic media [S1].
*   **When to use:** When simulating light transport in participating media requiring a balance of efficiency and accuracy, particularly when subsuming previous volumetric photon mapping and BPT techniques is desired [S1].
*   **When not to use:** When highly anisotropically scattering media are present and joint path importance sampling is required for optimal variance reduction [S1].

## Background
UPBP was introduced by [S1] as a combined rendering algorithm that fuses volumetric estimators with unbiased path sampling techniques. It builds on the VCM algorithm [Georgiev et al. 2012] and extends it to handle participating media [S1]. The implementation builds on top of the publicly available SmallVCM framework [Davidovic and Georgiev 2012] [S1]. The algorithm fully subsumes the methods of Georgiev et al. [2012] and Hachisuka et al. [2012] [S1].
