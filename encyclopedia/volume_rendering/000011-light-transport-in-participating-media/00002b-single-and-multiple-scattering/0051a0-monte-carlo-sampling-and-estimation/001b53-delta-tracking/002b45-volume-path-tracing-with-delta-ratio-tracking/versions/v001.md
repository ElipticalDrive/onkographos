# Volume Path Tracing with Delta/Ratio Tracking

Also called: WebGPU Volume Pathtracer, Woodcock Tracking in WGSL

## Overview
A path tracing method for volumetric rendering implemented in WGSL that uses delta tracking (Woodcock tracking) to sample scattering events and ratio tracking for transmittance estimation [S1, unofficial]. It renders a 3D volume texture using ray-box intersection and Monte Carlo integration [S1, unofficial]. It differs from its siblings by combining rejection-based event sampling (Delta Tracking) with weighted transmittance updates (Ratio Tracking) within a fixed-depth path tracer, whereas siblings like [Null Interactions Shift](1836-null-interactions-shift.md) use shifted null interactions and [Ratio Tracking with Null Scattering](1044-ratio-tracking-with-null-scattering.md) uses null scattering specifically for transmittance without the same rejection-based event loop structure [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   **View Parameters:** A uniform buffer containing projection-view matrix (`proj_view`), eye position (`eye_pos`), volume scale (`volume_scale`), light direction (`light_dir`), frame ID (`frame_id`), and scaling factors (`sigma_t_scale`, `sigma_s_scale`) [S1, unofficial].
*   **Volume Texture:** A 3D texture (`texture_3d<f32>`) representing the density field [S1, unofficial].
*   **Colormap Texture:** A 2D texture (`texture_2d<f32>`) for color mapping density values [S1, unofficial].
*   **Accumulation Buffers:** Two storage textures (`texture_storage_2d`) for ping-pong accumulation [S1, unofficial].

**Outputs:**
*   **Accumulated Color:** Written to the accumulation buffer, which is blit to the swap chain [S1, unofficial].

### Data Structures
*   **ViewParams:**
    *   `proj_view`: `mat4x4<f32>` (16 floats)
    *   `eye_pos`: `vec4<f32>` (4 floats)
    *   `volume_scale`: `vec4<f32>` (4 floats)
    *   `light_dir`: `vec4<f32>` (4 floats)
    *   `frame_id`: `u32` (1 uint, padded to vec4 alignment)
    *   `sigma_t_scale`: `f32` (1 float)
    *   `sigma_s_scale`: `f32` (1 float)
    *   *Note:* WGSL padding is assumed to align to `vec4` boundaries [S1, unofficial].
*   **LCGRand:**
    *   `state`: `u32` [S1, unofficial].
*   **SamplingResult:**
    *   `scattering_event`: `bool`
    *   `color`: `vec3<f32>`
    *   `transmittance`: `f32` [S1, unofficial].

### Parameters
*   `sigma_t_scale`: Scaling factor for extinction coefficient in step size calculation. Default: `100.0` [S1, unofficial].
*   `sigma_s_scale`: Scaling factor for scattering coefficient. Default: `1.0` [S1, unofficial]. *Note: Not explicitly used in the provided tracking function log calculations, only `sigma_t_scale` is used* [S1, unofficial].
*   `volume_emission`: Constant ambient emission strength. Default: `0.5` [S1, unofficial].
*   `ambient_strength`: Constant environment light contribution. Default: `0.0` [S1, unofficial].
*   **Loop Limit:** Hardcoded to 4 iterations [S1, unofficial].
*   **Hash Dimensions:** Fixed at `1280x720` for RNG seeding [S1, unofficial].

    Returns [t0, t1] or None if no intersection.
    """

    t1 = 1e9
    
    for i in range(3):
        if abs(dir[i]) < 1e-8:
            if orig[i] < 0.0 or orig[i] > 1.0:
                return None
        else:
            t_near = (0.0 - orig[i]) / dir[i]

            if t_near > t_far:

            t0 = max(t0, t_near)
            t1 = min(t1, t_far)
            
    if t0 > t1:
        return None
    return [t0, t1]

def delta_tracking_transmittance(orig, dir, interval, sigma_t_scale, volume_texture, rng):
    """
    Delta Tracking for transmittance estimation (absorption only).
    """
    transmittance = 1.0
    current_t = interval[0]
    
    while True:
        r1 = rng.next_float()
        r2 = rng.next_float()
        
        step = -log(1.0 - r1) / sigma_t_scale
        current_t += step
        
        if current_t >= interval[1]:
            return 1.0
            
        p = orig + current_t * dir
        density = volume_texture.sample(p)
        
        if density > r2:
            return 0.0 # Absorption
            
    return 1.0

def ratio_tracking_transmittance(orig, dir, interval, sigma_t_scale, volume_texture, rng):
    """
    Ratio Tracking for transmittance estimation.
    """

        p = orig + current_t * dir
        density = volume_texture.sample(p)
        
        transmittance *= (1.0 - density)
        
    return transmittance

### Edge Cases and Pitfalls
*   **Volume Padding:** WebGPU requires bytes per row to be aligned to 256 bytes. Volumes with width not divisible by 256 must be padded [S1, unofficial].
*   **RNG Determinism:** The RNG state is seeded by a hash of pixel coordinates and frame ID to ensure deterministic results across frames and pixels. The dimensions used in the hash are hardcoded to `1280x720` [S1, unofficial].
*   **Precision:** Using `log(1.0 - r)` can suffer from precision issues if `r` is very close to 1.0. Using `log(r)` is numerically more stable if `r` is uniform [0,1). The source uses `1.0 - r` [S1, unofficial].
*   **Majorant Selection:** The `sigma_t_scale` acts as the majorant. If it is too close to the actual extinction, the rejection rate increases. If too high, steps become large and efficiency drops. Default `100.0` [S1, unofficial].

## Subtopics

### Delta Tracking (Rejection Sampling)
*   **What it is:** A method where scattering events are sampled by comparing the local density to a random threshold against a majorant extinction coefficient.
*   **Difference:** Uses rejection sampling; only records an event if the density exceeds the random value.
*   **When to choose:** When the volume has high contrast or heterogeneous density, and you want to avoid bias from fixed step sizes.
*   **Link:** [Delta Tracking](985-delta-tracking.md)

### Ratio Tracking (Weighted Transmittance)
*   **What it is:** A method where steps are always taken, but the transmittance is weighted by `(1 - density)` at each step.
*   **Difference:** Always samples a step but weights the result; reduces variance in highly absorbing media compared to pure rejection.
*   **When to choose:** When the volume is highly absorbing and rejection sampling would result in too many null interactions.
*   **Link:** [Ratio Tracking with Null Scattering](1044-ratio-tracking-with-null-scattering.md)

## Operating characteristics

*   **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of pixels and $M$ is the number of path iterations (hardcoded to 4) [S1, unofficial]. The number of Woodcock steps per iteration depends on the majorant and density distribution.
*   **Memory Complexity:** $O(V)$ for the volume texture and $O(P)$ for the accumulation buffers, where $V$ is volume resolution and $P$ is pixel resolution [S1, unofficial].
*   **Measured Performance:** Implemented in WGSL on WebGPU. Performance depends on GPU hardware and volume resolution (tested up to 256x256x256) [S1, unofficial].
*   **Strengths:** Simple implementation, handles heterogeneous volumes, deterministic RNG [S1, unofficial].
*   **Limitations:** Fixed path length (4 iterations) limits accuracy for deep volumes. `sigma_t_scale` must be chosen carefully. No explicit light sampling (ambient/emission only) [S1, unofficial].
*   **When to use:** Real-time volumetric rendering on WebGPU where simplicity and determinism are prioritized over physical accuracy.
*   **When not to use:** When high dynamic range or complex lighting interactions are required.
