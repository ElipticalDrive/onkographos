# Metropolis Light Transport for Participating Media

Also called: MLT for Participating Media, Metropolis Light Transport (Pauly et al.), Metropolis Sampling for Light Transport

## Overview
Metropolis Light Transport (MLT) for Participating Media is a stochastic rendering method that samples interaction points from a function of the extinction coefficient $\kappa_t$ to simulate light transport in inhomogeneous media [S1]. It extends the standard Metropolis Light Transport algorithm to incorporate volumetric scattering, producing unbiased results for general geometric models and inhomogeneous media with multiple scattering [S1]. Unlike deterministic ray-marching approaches which often require extensive computational effort and can produce biased estimates if approximations are used, MLT explores the path space locally via mutations, focusing on light paths that contribute most to the rendered image [S1, S4]. It is a view-dependent method that uses little storage but requires careful handling of ergodicity to avoid getting stuck in isolated areas of the scene [S1, S3].

## How it works
**Inputs:** Scene geometry, participating media properties (extinction $\kappa_t$, scattering coefficient $\kappa_s$, absorption coefficient $\kappa_a$, phase function $p$), camera parameters, and an initial set of paths generated by a base path tracer (e.g., Bidirectional Path Tracing).
**Outputs:** A rendered image where pixel values are estimates of the radiance $L(x_0)$.

**Data Structures:**
*   **Path $\bar{x}$:** A sequence of interaction points (vertices) $x_0, x_1, \dots, x_n$. For participating media, vertices represent scattering events within the volume.
*   **Contribution Function $f(\bar{x})$:** The measurement contribution of a path, including geometry terms, phase functions, and transmittance.
*   **Transition Function $T(\bar{x} \rightarrow \bar{y})$:** The probability density of proposing path $\bar{y}$ given current path $\bar{x}$.

**Algorithm Steps:**

1.  **Initialization:**
    Perform a bidirectional path tracing (BDPT) execution to determine the total image brightness and generate an initial set of approximation samples [S1, S3]. The constant $b = \int_{\mathcal{P}} f(\bar{y}) d\mu(\bar{y})$ is estimated using this phase with a low number of samples (typically $10^4$–$10^5$) [S3]. Select one of these approximation samples as the initial state $\bar{x}_0$ for the Metropolis phase with probability proportional to $f(\bar{x})/p(\bar{x})$ [S3]. This sample is expected to be distributed according to the stationary density, avoiding start-up bias without discarding samples [S3].

2.  **Mutation Loop:**
    For each pixel or frame, iterate through the following steps for a fixed number of iterations or until convergence:
    
    a. **Proposal Generation:** Generate a tentative sample $\bar{y}$ from the current sample $\bar{x}$ using a tentative transition function $T(\bar{x} \rightarrow \bar{y})$ [S3]. In the context of participating media, this often involves perturbing the primary sample point or adding/removing vertices in the path [S3]. The mutation should make small changes to the current path to exploit coherence in the scene [S1].
    
    b. **Acceptance Probability:** Calculate the acceptance probability $a(\bar{x} \rightarrow \bar{y})$ [S3]:
    $$
    a(\bar{x} \rightarrow \bar{y}) := \min \left\{ 1, \frac{f(\bar{y})T(\bar{y} \rightarrow \bar{x})}{f(\bar{x})T(\bar{x} \rightarrow \bar{y})} \right\}
    $$
    If the mutation is symmetric ($T(\bar{x} \rightarrow \bar{y}) = T(\bar{y} \rightarrow \bar{x})$), this simplifies to $a(\bar{x} \rightarrow \bar{y}) = \min \{ 1, f(\bar{y}) / f(\bar{x}) \}$ [S3].
    
    c. **Accept/Reject:** Accept the proposal $\bar{y}$ with probability $a(\bar{x} \rightarrow \bar{y})$. If accepted, the new current state becomes $\bar{y}$; otherwise, it remains $\bar{x}$ [S3].
    
    d. **Image Update:** Deposit a certain amount of energy to the pixel(s) the path passes through, updating the image estimate [S1]. The paths are distributed proportionally to their contribution to the final image [S1].

3.  **Ergodicity Maintenance:**
    The mutation alone cannot ensure ergodicity and may get stuck in isolated areas of the scene [S3]. To guarantee that the algorithm explores the entire space, independent paths must be generated at random intervals by the underlying path tracer (e.g., BDPT) by feeding a fresh set of uniform random numbers into the algorithm [S3]. The mutation type is chosen at random before each mutation step [S3].

```python
def metropolis_light_transport_participating_media(scene, camera, num_iterations):
    # 1. Initialization
    # Estimate b and generate initial paths using BDPT
    initial_paths = bidirectional_path_tracing(scene, camera, num_samples=10000)
    b = estimate_integral(initial_paths)
    
    # Select initial state x_bar with probability proportional to f(x_bar)/p(x_bar)
    current_path = select_initial_path(initial_paths, b)
    
    # Initialize image buffer
    image = zeros_like(camera.resolution)
    
    # 2. Mutation Loop
    for i in range(num_iterations):
        # Choose mutation type randomly
        mutation_type = random_choice(['perturb_vertex', 'add_vertex', 'remove_vertex'])
        
        # Generate tentative sample y_bar from x_bar
        tentative_path = propose_mutation(current_path, mutation_type, scene)
        
        # Calculate acceptance probability
        # Note: f(x_bar) includes transmittance, phase functions, and geometry terms
        f_current = compute_contribution(current_path, scene)
        f_tentative = compute_contribution(tentative_path, scene)
        
        # Assuming symmetric mutation for simplicity in this example
        # T(x -> y) = T(y -> x)
        acceptance_prob = min(1.0, f_tentative / f_current)
        
        # Accept or reject
        if random_uniform() < acceptance_prob:
            current_path = tentative_path
        
        # Deposit energy to image
        deposit_energy(current_path, image, scene, camera)
        
        # Ergodicity: Occasionally restart with a new independent path
        if random_uniform() < restart_probability:
            current_path = random_sample_from_path_tracer(scene, camera)
            
    return image

def compute_contribution(path, scene):
    """
    Computes the measurement contribution function f(x_bar) for a path.
    Includes transmittance, phase functions, and geometry terms.
    """
    contribution = 1.0
    for i in range(1, len(path.vertices)):
        prev_vertex = path.vertices[i-1]
        curr_vertex = path.vertices[i]
        
        # Transmittance between vertices
        transmittance = compute_transmittance(prev_vertex, curr_vertex, scene.media)
        contribution *= transmittance
        
        # Phase function
        phase = scene.phase_function.eval(prev_vertex.direction, curr_vertex.direction)
        contribution *= phase
        
        # Geometry term (1/r^2 * cos(theta))
        geometry = compute_geometry_term(prev_vertex, curr_vertex)
        contribution *= geometry
        
    return contribution

def compute_transmittance(p1, p2, media):
    """
    Computes transmittance between two points in participating media.
    For unbiased results, this must be exact or estimated via unbiased methods.
    """
    # Integrate extinction coefficient along the segment
    # T = exp(-int_{p1}^{p2} kappa_t(s) ds)
    integral = integrate_extinction(p1, p2, media)
    return exp(-integral)
```

**Parameters:**
*   **Number of samples for initialization ($10^4$–$10^5$):** Used to estimate $b$ and generate initial paths. This cost is negligible [S3].
*   **Restart Probability:** Determines how often independent paths are generated to maintain ergodicity. Not given in the sources.
*   **Mutation Types:** Perturb vertex, add vertex, remove vertex. Specific probabilities for choosing mutation types are not given in the sources [S3].

**Edge Cases and Pitfalls:**
*   **Biased Transmittance:** Using a biased estimate of transmission (e.g., deterministic ray-marching) in place of the exact quantity causes the Markov chain to not necessarily target the desired density $\pi(\bar{x})$ [S4].
*   **Ergodicity:** The mutation alone cannot ensure ergodicity. Independent paths must be generated at random intervals to avoid getting stuck in isolated areas [S3].
*   **View Dependency:** The method is view-dependent, meaning it requires extra processes (like ray tracing) to get the value of $L(x_0)$ for each pixel [S1].

## Subtopics

### [Primary Sample Space Metropolis Light Transport (PSSMLT)](12269-primary-sample-space-metropolis-light-transport-pssmlt.md)
Primary Sample Space Metropolis Light Transport (PSSMLT) is a Markov Chain Monte Carlo (MCMC) light transport method that applies mutations to random number vectors in primary sample space rather than sampling directly in path space. It solves the problem of exploring complex light transport paths in participating media by leveraging traditional path tracing techniques to generate paths from mutated random seeds. Unlike direct path space mutations, PSSMLT is limited by the expressiveness of the underlying path tracer, restricting the possible exploration of the path space.

### [Pseudo-marginal Metropolis Light Transport (PSSMLT)](12276-pseudo-marginal-metropolis-light-transport-pssmlt.md)
Pseudo-marginal Metropolis Light Transport (PSSMLT) is a Monte Carlo method that enables Metropolis-Hastings sampling in scenes with heterogeneous participating media by replacing the intractable exact light path contribution function with a non-negative, unbiased estimator. Unlike methods that use biased approximations (such as deterministic ray-marching) which fail to target the correct density, PSSMLT constructs an extended target distribution in an auxiliary space to ensure the marginal distribution of sampled paths remains exact. It distinguishes itself from standard PSSMLT implementations that rely on delta tracking by utilizing ratio tracking, which is significantly faster and allows for longer Markov chains and better path space exploration.

### [Metropolis Light Transport](12286-metropolis-light-transport.md)
Metropolis Light Transport (MLT) is a global illumination rendering method that uses Markov Chain Monte Carlo (MCMC) to sample light paths $\bar{x}$ according to a target distribution $\pi(\bar{x})$ proportional to the image contribution of the paths. It differs from standard path tracing by exploring the space of light transport paths via small and large mutations, allowing it to find complex light transport paths (like those involving multiple bounces) that standard path tracing might miss.

### Energy Redistribution Path Tracing
Energy Redistribution Path Tracing (ERPT) is an extension to the original MLT algorithm that samples a large set of paths with standard path tracing methods and then runs many short MCMC chains starting from each initial sample [S4]. The main benefit of ERPT over original MLT is that a well stratified initial sample set can be preserved, e.g., using one path per pixel [S4].

## Operating characteristics
*   **Time Complexity:** The cost of the initialization phase (BDPT) is negligible if $10^4$–$10^5$ samples are used [S3]. The main cost lies in the mutation loop, where each iteration requires computing the contribution function $f(\bar{x})$, which involves integrating transmittance and evaluating phase functions. For heterogeneous media, exact transmittance computation can be expensive [S4].
*   **Memory Complexity:** The method uses little storage as it does not require storing large data structures like photon maps [S1].
*   **Performance:** MLT is effective for scenes with complex light transport, such as those involving multiple scattering in participating media, where standard path tracing might miss important paths [S1, S2]. However, it is view-dependent, which can limit its efficiency in scenes with many cameras or wide-angle views [S1].
*   **Strengths:** Unbiased results, handles general geometric models and inhomogeneous media, accounts for multiple scattering, uses little storage [S1].
*   **Limitations:** View-dependent, requires careful handling of ergodicity, exact transmittance computation can be expensive for heterogeneous media [S1, S4].
*   **When to use:** Scenes with complex light transport in participating media, especially where multiple scattering is significant.
*   **When not to use:** Scenes where view independence is required, or where exact transmittance computation is too expensive.

## Background
Metropolis Light Transport (MLT) was first presented in [VG97] (Veach and Guibas, 1997) and strongly modified in [KSKAC02] (Kelemen et al., 2002) [S3]. The extension to participating media was proposed by Pauly et al. [67] (Pauly et al., 2000) [S1, S2]. The algorithm uses Metropolis sampling [MRR+53] to sample the path space, generating paths according to the measurement contribution function rather than just considering factors of it as in ordinary importance sampling [S3]. It is used in rendering scenes with participating media, such as foggy atmospheres and volumetric effects [S1, S2].
