# Metropolis Light Transport for Participating Media

Also called: MLT, MLT for Participating Media, MLT with volumetric scattering, Metropolis Light Transport (Pauly et al.), Metropolis Sampling for Light Transport, Metropolis sampling

## Overview
Metropolis Light Transport (MLT) for Participating Media is a stochastic rendering method that samples interaction points from a function of the extinction coefficient $\kappa_t$ to simulate light transport in inhomogeneous media [S1]. It extends the standard Metropolis Light Transport algorithm to incorporate volumetric scattering, producing unbiased results for general geometric models and inhomogeneous media with multiple scattering [S1]. Unlike deterministic ray-marching approaches which often require extensive computational effort and can produce biased estimates if approximations are used, MLT explores the path space locally via mutations, focusing on light paths that contribute most to the rendered image [S1, S4]. It is a view-dependent method that uses little storage but requires careful handling of ergodicity to avoid getting stuck in isolated areas of the scene [S1, S3].

## How it works
**Inputs:** Scene geometry, participating media properties (extinction $\kappa_t$, scattering coefficient $\kappa_s$, absorption coefficient $\kappa_a$, phase function $f_p$), camera parameters, and an initial set of paths generated by a base path tracer (e.g., Bidirectional Path Tracing) [S1, S3].
**Outputs:** A rendered image where pixel values are estimates of the radiance $L(x_0)$ [S1, S3].

**Data Structures:**
*   **Path $\bar{x}$:** A sequence of interaction points (vertices) $x_0, x_1, \dots, x_n$ [S3]. For participating media, vertices represent scattering events within the volume [S3].
*   **Contribution Function $f(\bar{x})$:** The measurement contribution of a path, including geometry terms, phase functions, and transmittance [S4].
*   **Transition Function $T(\bar{x} \rightarrow \bar{y})$:** The probability density of proposing path $\bar{y}$ given current path $\bar{x}$ [S4].

**Algorithm Steps:**

1.  **Initialization:** Perform a bidirectional path tracing (BDPT) execution to determine the total image brightness and generate an initial set of approximation samples [S1, S3]. The constant $b = \int_{\mathcal{P}} f(\bar{y}) d\mu(\bar{y})$ is estimated using this phase with a low number of samples (typically $10^4$–$10^5$) [S4]. Select one of these approximation samples as the initial state $\bar{x}_0$ for the Metropolis phase with probability proportional to $f(\bar{x})/p(\bar{x})$ [S4]. This sample is expected to be distributed according to the stationary density, avoiding start-up bias without discarding samples [S4].

2.  **Mutation Loop:** For each pixel or frame, iterate through the following steps for a fixed number of iterations:
    a. **Proposal Generation:** Generate a tentative sample $\bar{y}$ from the current sample $\bar{x}$ using a tentative transition function $T(\bar{x} \rightarrow \bar{y})$ [S4]. In the context of participating media, this involves selecting a mutation strategy (e.g., bidirectional mutations, scattering perturbations, or propagation perturbations) randomly according to a discrete probability density function that assigns a constant weight to each strategy [S3]. The mutation makes small changes to the current path to exploit coherence in the scene [S1].
    b. **Acceptance Probability:** Calculate the acceptance probability $a(\bar{x} \rightarrow \bar{y})$ [S4]:
    $$a(\bar{x} \rightarrow \bar{y}) := \min \left\{ 1, \frac{f(\bar{y})T(\bar{y} \rightarrow \bar{x})}{f(\bar{x})T(\bar{x} \rightarrow \bar{y})} \right\}$$
    If the mutation is symmetric ($T(\bar{x} \rightarrow \bar{y}) = T(\bar{y} \rightarrow \bar{x})$), this simplifies to $a(\bar{x} \rightarrow \bar{y}) = \min \{ 1, f(\bar{y}) / f(\bar{x}) \}$ [S4].
    c. **Accept/Reject:** Accept the proposal $\bar{y}$ with probability $a(\bar{x} \rightarrow \bar{y})$ [S4]. If accepted, the new current state becomes $\bar{y}$; otherwise, it remains $\bar{x}$ [S4].
    d. **Image Update:** Deposit a constant amount of energy to the pixel(s) the path passes through, updating the image estimate [S3]. The paths are distributed proportionally to their contribution to the final image [S3].

3.  **Ergodicity Maintenance:** The mutation alone cannot ensure ergodicity and may get stuck in isolated areas of the scene [S4]. To guarantee that the algorithm explores the entire space, independent paths must be generated at random intervals by the underlying path tracer by feeding a fresh set of uniform random numbers into the algorithm [S4].

**Pseudocode:**

```python
import math
import random

def metropolis_light_transport_participating_media(scene, camera, num_iterations):
    # 1. Initialization
    # Generate initial paths using BDPT and estimate b
    initial_paths = []
    for _ in range(10000):
        initial_paths.append(generate_path(scene, camera))
    b = sum(compute_contribution(p, scene) for p in initial_paths) / len(initial_paths)
    
    # Select initial state with probability proportional to f/p
    current_path = random.choice(initial_paths)
    
    # Initialize image buffer
    image = [0.0] * (camera.width * camera.height)
    
    # 2. Mutation Loop
    for _ in range(num_iterations):
        # Choose mutation strategy randomly with constant weights
        mutation_type = random.choice(['perturb_vertex', 'add_vertex', 'remove_vertex'])
        
        # Generate tentative sample y from x
        tentative_path = apply_mutation(current_path, mutation_type, scene)
        
        # Calculate acceptance probability
        f_current = compute_contribution(current_path, scene)
        f_tentative = compute_contribution(tentative_path, scene)
        
        # Assuming symmetric mutation T(x->y) = T(y->x)
        acceptance_prob = min(1.0, f_tentative / f_current)
        
        # Accept or reject
        if random.random() < acceptance_prob:
            current_path = tentative_path
        
        # Deposit constant energy to pixels the path passes through
        for pixel_idx in current_path.intersected_pixels:
            image[pixel_idx] += 1.0
        
        # Ergodicity: Generate independent paths at random intervals
        # Not given in the sources.
        if random.random() < 0.01:
            current_path = generate_path(scene, camera)
            
    return image

def generate_path(scene, camera):
    # Standard path generation (e.g., BDPT)
    return type('Path', (), {'vertices': [], 'intersected_pixels': []})()

def compute_contribution(path, scene):
    contribution = 1.0
    for i in range(1, len(path.vertices)):
        prev_v = path.vertices[i-1]
        curr_v = path.vertices[i]
        # Transmittance T = exp(-int sigma_e ds)
        integral = sum(scene.media.sigma_e(prev_v + t * (curr_v - prev_v)) for t in [0.0, 0.5, 1.0]) * 0.5
        transmittance = math.exp(-integral)
        phase = scene.phase_function.eval(prev_v.direction, curr_v.direction)
        geometry = 1.0 / (prev_v.distance_to(curr_v) ** 2)
        contribution *= transmittance * phase * geometry
    return contribution

def apply_mutation(path, mutation_type, scene):
    if mutation_type == 'perturb_vertex':
        # Perturb direction or position of a vertex
        return path
    elif mutation_type == 'add_vertex':
        return path
    elif mutation_type == 'remove_vertex':
        return path
    return path
```

**Parameters:**
*   **Number of samples for initialization ($10^4$–$10^5$):** Used to estimate $b$ and generate initial paths. This cost is negligible [S4].
*   **Restart Probability:** Determines how often independent paths are generated to maintain ergodicity. Not given in the sources.
*   **Mutation Strategy Weights:** Constant weights assigned to each mutation strategy in the discrete pdf. Equal weights are the most robust setting; weighting perturbations a hundred times stronger can cause uneven sampling and artifacts in complex scenes [S3].

**Edge Cases and Pitfalls:**
*   **Biased Transmittance:** Using a biased estimate of transmission (e.g., deterministic ray-marching) in place of the exact quantity causes the Markov chain to not necessarily target the desired density $\pi(\bar{x})$ [S4].
*   **Ergodicity:** The mutation alone cannot ensure ergodicity. Independent paths must be generated at random intervals to avoid getting stuck in isolated areas [S4].
*   **View Dependency:** The method is view-dependent, meaning it requires extra processes (like ray tracing) to get the value of $L(x_0)$ for each pixel [S1].
*   **Sharp Shadow Boundaries:** Uneven sampling and sharp shadow boundary artifacts occur if perturbation weights are too high relative to bidirectional mutations in complex scenes, causing single vertices to degenerate to point light sources [S3].
*   **Caustic Constraints:** Caustic perturbations are not effective for caustics seen through a mirror due to pinhole camera constraints [S3].
*   **Small Light/Camera Apertures:** MLT performs poorly when light source and camera aperture are small and paths contain two or more singular scattering interactions separated by a diffuse interaction, because perturbing the direction moves the diffuse point, likely missing the sensor/light source [S3].

## Subtopics

### [Primary Sample Space Metropolis Light Transport (PSSMLT)](12269-primary-sample-space-metropolis-light-transport-pssmlt.md)
Primary Sample Space Metropolis Light Transport (PSSMLT) is a Markov Chain Monte Carlo (MCMC) light transport method that applies mutations to random number vectors in primary sample space rather than sampling directly in path space. It solves the problem of exploring complex light transport paths in participating media by leveraging traditional path tracing techniques to generate paths from mutated random seeds. Unlike direct path space mutations, PSSMLT is limited by the expressiveness of the underlying path tracer, restricting the possible exploration of the path space.

### [Pseudo-marginal Metropolis Light Transport (PSSMLT)](12276-pseudo-marginal-metropolis-light-transport-pssmlt.md)
Pseudo-marginal Metropolis Light Transport (PSSMLT) is a Monte Carlo method that enables Metropolis-Hastings sampling in scenes with heterogeneous participating media by replacing the intractable exact light path contribution function with a non-negative, unbiased estimator. Unlike methods that use biased approximations (such as deterministic ray-marching) which fail to target the correct density, PSSMLT constructs an extended target distribution in an auxiliary space to ensure the marginal distribution of sampled paths remains exact. It distinguishes itself from standard PSSMLT implementations that rely on delta tracking by utilizing ratio tracking, which is significantly faster and allows for longer Markov chains and better path space exploration.

### [Metropolis Light Transport](12286-metropolis-light-transport.md)
Metropolis Light Transport (MLT) is a global illumination rendering method that uses Markov Chain Monte Carlo (MCMC) to sample light paths $\bar{x}$ according to a target distribution $\pi(\bar{x})$ proportional to the image contribution of the paths. It differs from standard path tracing by exploring the space of light transport paths via small and large mutations, allowing it to find complex light transport paths (like those involving multiple bounces) that standard path tracing might miss.

### Energy Redistribution Path Tracing
Energy Redistribution Path Tracing (ERPT) is an extension to the original MLT algorithm that samples a large set of paths with standard path tracing methods and then runs many short MCMC chains starting from each initial sample [S5]. The main benefit of ERPT over original MLT is that a well stratified initial sample set can be preserved, e.g., using one path per pixel [S5].

## Operating characteristics
*   **Time Complexity:** The initialization cost is negligible with $10^4$–$10^5$ samples [S4]. The main cost lies in the mutation loop, where each iteration requires computing the contribution function $f(\bar{x})$, which involves integrating transmittance and evaluating phase functions [S4]. For heterogeneous media, exact transmittance computation via ray marching is expensive [S3].
*   **Memory Complexity:** The method uses little storage as it does not require storing large data structures like photon maps [S1].
*   **Performance:** Rendering performance on a single processor HP C3000 (PA 8500 CPU at 400 MHz) with 640 mutations per pixel: 720x490 pixels in 15 hours, 720x576 pixels in 18 hours, and 380x490 pixels in 8 hours [S3].
*   **Strengths:** Unbiased results, handles general geometric models and inhomogeneous media, accounts for multiple scattering, uses little storage, suitable for complex scenes represented procedurally or implicitly [S1, S3].
*   **Limitations:** View-dependent, requires careful handling of ergodicity, exact transmittance computation can be expensive for heterogeneous media, performs poorly with small light/camera apertures and complex diffuse scattering chains [S1, S3, S4].
*   **When to use:** Scenes with complex light transport in participating media, especially where multiple scattering is significant, or scenes represented procedurally/implicitly [S1, S3].
*   **When not to use:** Scenes where view independence is required, or where exact transmittance computation is too expensive [S1, S4].

## Background
Metropolis Light Transport (MLT) was first presented in [VG97] (Veach and Guibas, 1997) and strongly modified in [KSKAC02] (Kelemen et al., 2002) [S4]. The extension to participating media was proposed by Pauly et al. [67] (Pauly et al., 2000) [S1, S2]. The algorithm uses Metropolis sampling [MRR+53] to sample the path space, generating paths according to the measurement contribution function rather than just considering factors of it as in ordinary importance sampling [S4]. It is used in rendering scenes with participating media, such as foggy atmospheres and volumetric effects [S1, S2].
