# Cloud Radiative Transfer Forward Model Setup

Also called: RTE Solver Configuration, Radiative Transfer Grid and Medium Setup

## Overview
This method configures the geometric grid, optical properties, and numerical solver parameters required to solve the Radiative Transfer Equation (RTE) for cloud-scattering scenarios. It establishes the spatial discretization, generates wavelength-dependent extinction and scattering coefficients from microphysical parameters, and initializes the solver with boundary conditions (surface albedo) and source terms (solar irradiance). It differs from sibling methods by focusing on the *setup* phase—preparing the data structures and solver instances—rather than the iterative solution or propagation steps themselves.

## How it works
The method constructs a 3D radiative transfer grid, generates optical properties based on cloud microphysics, and configures the RTE solver with numerical and physical parameters.

**Inputs:**
*   Cloud scatterer data: 3D arrays for spatial coordinates ($x, y, z$) and optical properties.
*   Microphysical parameters: Effective radius ($r_{eff}$) range, effective variance ($v_{eff}$) range, and size distribution function.
*   Solver configuration: Numerical parameters, surface albedo, solar source definition (wavelength, angles), and Stokes count.
*   Mie tables: Precomputed scattering data for the cloud type.

**Outputs:**
*   `rte_grid`: A structured 3D grid object defining the spatial domain.
*   `medium`: An optical property object containing extinction and scattering coefficients.
*   `solver`: An RTE solver instance configured for the specific scene.

**Data Structures:**
1.  **Radiative Transfer Grid (`rte_grid`)**:
    *   Layout: 3D structured grid.
    *   Fields:
        *   `dx`: X-spacing (derived from `cloud_scatterer.x.diff('x')[0]`).
        *   `nx`: X-dimension (`cloud_scatterer.x.data.size`).
        *   `dy`: Y-spacing (derived from `cloud_scatterer.y.diff('y')[0]`).
        *   `ny`: Y-dimension (`cloud_scatterer.y.data.size`).
        *   `z_coords`: Z-coordinates (`np.append(0, cloud_scatterer.z.data)`).
2.  **Optical Property Generator (`optical_property_generator`)**:
    *   Type: Cloud-specific generator.
    *   Inputs: Cloud type ('cloud'), Mie tables (`mie_mono_tables`), size distribution function, $r_{eff}$ range, $v_{eff}$ range.
3.  **Solver Configuration (`solvers_dict`)**:
    *   Key: Wavelength.
    *   Value: `RTE` solver instance.
    *   Fields:
        *   `numerical_params`: Configuration object for numerical scheme.
        *   `surface`: Lambertian surface with albedo 0.0.
        *   `source`: Solar source defined by wavelength, solar zenith cosine ($\mu_0$), and solar azimuth ($\phi_0$).
        *   `medium`: The generated optical property object.
        *   `num_stokes`: Number of Stokes parameters (1 for unpolarized).

**Steps:**
1.  **Construct the Radiative Transfer Grid**:
    *   Extract X-spacing: $dx = \text{diff}(x)[0]$.
    *   Extract X-dimension: $nx = \text{size}(x)$.
    *   Extract Y-spacing: $dy = \text{diff}(y)[0]$.
    *   Extract Y-dimension: $ny = \text{size}(y)$.
    *   Construct Z-coordinates: $z_{coords} = [0] + z_{data}$.
    *   Initialize `rte_grid` with $(dx, nx, dy, ny, z_{coords})$.
2.  **Generate Optical Properties**:
    *   Define $r_{eff}$ range: Linearly spaced from 5.0 to 30.0 with 30 points.
    *   Define $v_{eff}$ range: Linearly spaced from 0.03 to 0.2 with 9 points.
    *   Initialize `optical_property_generator` with cloud type, Mie tables, size distribution, $r_{eff}$ range, and $v_{eff}$ range.
    *   Generate `medium` object using the generator.
3.  **Configure the RTE Solver**:
    *   Define surface: Lambertian with albedo $\alpha = 0.0$.
    *   Define solar source: Wavelength $\lambda$, solar zenith cosine $\mu_0$, solar azimuth $\phi_0 = 140^\circ$.
    *   Set Stokes count: $N_{stokes} = 1$.
    *   Initialize `solver` with numerical parameters, surface, source, medium, and $N_{stokes}$.
    *   Add `solver` to `solvers_dict` keyed by $\lambda$.

**Pseudocode:**
```python
import numpy as np

def setup_cloud_rte(cloud_scatterer, mie_mono_tables, size_distribution_function, config):
    """
    Sets up the radiative transfer grid, optical properties, and solver for cloud scattering.
    
    Args:
        cloud_scatterer: Object containing x, y, z data arrays.
        mie_mono_tables: Precomputed Mie scattering tables.
        size_distribution_function: Function or data for particle size distribution.
        config: Dictionary containing numerical parameters, solar angles, etc.
        
    Returns:
        rte_grid: The constructed radiative transfer grid.
        medium: The optical property object.
        solver: The configured RTE solver.
    """
    # Step 1: Construct the radiative transfer grid
    # Extract spacing and dimensions from cloud_scatterer
    dx = cloud_scatterer.x.diff('x')[0]
    nx = cloud_scatterer.x.data.size
    dy = cloud_scatterer.y.diff('y')[0]
    ny = cloud_scatterer.y.data.size
    
    # Construct Z coordinates, prepending 0
    z_coords = np.append(0, cloud_scatterer.z.data)
    
    # Initialize the grid
    rte_grid = at3d.grid.make_grid(dx, nx, dy, ny, z_coords)
    
    # Step 2: Generate optical properties
    # Define ranges for effective radius and effective variance
    reff_range = np.linspace(5.0, 30.0, 30)
    veff_range = np.linspace(0.03, 0.2, 9)
    
    # Initialize the optical property generator
    optical_property_generator = at3d.medium.OpticalPropertyGenerator(
        cloud_type='cloud',
        mie_tables=mie_mono_tables,
        size_distribution=size_distribution_function,
        reff=reff_range,
        veff=veff_range
    )
    
    # Generate the medium object
    medium = optical_property_generator.generate()
    
    # Step 3: Configure the RTE solver
    # Define surface: Lambertian with albedo 0.0
    surface = at3d.surface.lambertian(albedo=0.0)
    
    # Define solar source
    wavelength = config['wavelength']
    solar_mu = config['solar_mu'] # Solar zenith cosine
    solar_az = 140.0 # Solar azimuth in degrees
    
    source = at3d.source.solar(
        wavelength=wavelength,
        mu0=solar_mu,
        phi0=solar_az
    )
    
    # Set numerical parameters and Stokes count
    numerical_params = config['numerical_params']
    num_stokes = 1
    
    # Initialize the solver
    solver = at3d.solver.RTE(
        numerical_params=numerical_params,
        surface=surface,
        source=source,
        medium=medium,
        num_stokes=num_stokes
    )
    
    # Add solver to dictionary keyed by wavelength
    solvers_dict = {}
    solvers_dict[wavelength] = solver
    
    return rte_grid, medium, solvers_dict
```

**Parameters:**
*   `surface albedo`: Lambertian surface reflectivity. Default: 0.0 [S1, unofficial].
*   `solar_az`: Solar azimuth angle in degrees. Default: 140 [S1, unofficial].
*   `num_stokes`: Number of Stokes parameters. Default: 1 [S1, unofficial].
*   `reff`: Effective radius range for optical property generation. Default: `np.linspace(5.0, 30.0, 30)` [S1, unofficial].
*   `veff`: Effective variance range for optical property generation. Default: `np.linspace(0.03, 0.2, 9)` [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision**: Ensure `z_coords` includes the base layer (0) to avoid off-by-one errors in vertical discretization [S1, unofficial].
*   **Boundary Conditions**: The Lambertian surface with albedo 0.0 assumes a black surface, which may not be physically accurate for all scenes [S1, unofficial].
*   **Stokes Count**: Using `num_stokes=1` ignores polarization, which is sufficient for many cloud applications but may be insufficient for polarimetric remote sensing [S1, unofficial].

## Subtopics

### Discrete Ordinates Method
Solves the RTE by discretizing the angular domain into a finite set of directions. Choose when high angular accuracy is needed for complex scattering phase functions. [Discrete Ordinates Method](1046-discrete-ordinates-method.md)

### Multiple Scattering Model (Integral Equation)
Formulates the RTE as an integral equation to handle multiple scattering events. Choose when multiple scattering dominates and angular discretization is too expensive. [Multiple Scattering Model (Integral Equation)](1177-multiple-scattering-model-integral-equation.md)

### Principal-Ordinates Propagation
Propagates radiance along principal directions. Choose for efficient forward modeling in homogeneous or layered media. [Principal-Ordinates Propagation](4121-principal-ordinates-propagation.md)

### Jacobi Iterative Method for Diffusion
Solves the diffusion approximation of the RTE. Choose for highly scattering, optically thick media where the diffusion approximation holds. [Jacobi Iterative Method for Diffusion](4382-jacobi-iterative-method-for-diffusion.md)

### Sparse Linear System Solver for Wave Propagation
Solves the wave equation for light transport. Choose for coherent effects or very high-frequency regimes. [Sparse Linear System Solver for Wave Propagation](4718-sparse-linear-system-solver-for-wave-propagation.md)

### Differential Form of RTE
Solves the differential form of the RTE directly. Choose for general-purpose RTE solving without angular discretization. [Differential Form of RTE](4803-differential-form-of-rte.md)

### Spherical Harmonics and Spherical Gaussians for Radiance Transfer
Approximates the angular dependence of radiance using spherical harmonics or Gaussians. Choose for real-time rendering or when angular resolution can be traded for speed. [Spherical Harmonics and Spherical Gaussians for Radiance Transfer](5599-spherical-harmonics-and-spherical-gaussians-for-radiance-tra.md)

### Differential Radiative Transfer
Focuses on the differential form of the RTE for specific geometries. Choose for simple geometries where analytical or semi-analytical solutions are possible. [Differential Radiative Transfer](7879-differential-radiative-transfer.md)

### Ratio Estimator for Volume Scattering
Uses a ratio estimator to reduce variance in Monte Carlo rendering. Choose when variance reduction is critical for noisy volume scattering results. [Ratio Estimator for Volume Scattering](9012-ratio-estimator-for-volume-scattering.md)

## Operating characteristics
*   **Time Complexity**: Not given in the sources. The setup phase is generally $O(1)$ relative to the grid size for grid construction, but $O(N_{reff} \times N_{veff})$ for optical property generation, where $N$ is the number of points in the ranges.
*   **Memory Complexity**: $O(nx \times ny \times nz)$ for the grid and optical properties. The solver memory depends on the numerical scheme and angular discretization.
*   **Measured Performance**: Not given in the sources.
*   **Scaling**: Scales linearly with grid dimensions for grid construction. Optical property generation scales with the number of microphysical parameter combinations.
*   **Strengths**: Modular design allows for easy swapping of cloud types, microphysical parameters, and solver configurations.
*   **Limitations**: Limited to the specific cloud type and microphysical models supported by the `OpticalPropertyGenerator`. Polarization is not supported by default (`num_stokes=1`).
*   **When to Use**: When setting up a forward model for cloud radiative transfer with a focus on unpolarized light and Lambertian surfaces.
*   **When Not to Use**: When polarization effects are critical, or when the surface is not Lambertian.

## Background
The method is derived from the `hybridCT` library, which provides tools for cloud radiative transfer simulations. It integrates cloud microphysics with radiative transfer solvers to model light scattering in clouds. The approach is based on the conservation of energy for light passing through a medium, as described in the parent article.
