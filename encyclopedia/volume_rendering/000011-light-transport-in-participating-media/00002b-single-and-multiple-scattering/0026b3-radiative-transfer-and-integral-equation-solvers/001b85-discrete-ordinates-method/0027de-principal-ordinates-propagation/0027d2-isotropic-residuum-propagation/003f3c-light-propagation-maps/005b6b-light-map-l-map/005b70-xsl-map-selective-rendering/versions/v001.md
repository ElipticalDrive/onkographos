# XSL Map Selective Rendering

Also called: Director map guided rendering, L map, Modulated Saliency Map (S Map), S map, Saliency Map (S Map), Selective Rendering with XSL Map, X map, XSL Map Combination, XSL(wxs, op), extinction map, light map

## Overview
XSL Map Selective Rendering is a perceptual strategy for physically based rendering of participating media that reduces rendering time by using a combination of a saliency map (S map), an extinction map (X map), and a light map (L map) to guide selective rendering, providing more accurate estimates in perceptually important areas [S1]. It builds on [Light Map (L Map)](16885-light-map-l-map.md) by integrating the L map with the XS map to form a unified director map that accounts for both extinction and scattering around light sources, addressing artifacts caused by poor sampling in previous methods [S1]. Unlike standard global illumination which treats all pixels equally, this method modulates the maximum number of rays per pixel based on the XSL map, prioritizing areas with high perceptual saliency, low extinction, and strong scattering [S1].

## How it works
The method generates a director map (XSL map) from three component maps and uses it to weight the sampling density (maximum rays per pixel) for each pixel in the final rendering.

### Inputs and Outputs
*   **Inputs:**
    *   Scene geometry and participating media properties (extinction coefficient $\sigma_t$, scattering coefficient $\sigma_s$, phase function).
    *   Light source positions and intensities.
    *   Camera parameters.
    *   Coefficients $w_{xs}$ and $w_l$ for weighting the XS and L maps.
    *   Combination operator $op$ (typically addition).
    *   Base maximum rays per pixel $R_{max}$ [S1].
*   **Outputs:**
    *   Rendered image with adaptive sampling density.
    *   The XSL director map (intermediate data structure).

### Data Structures
1.  **Extinction Map (X Map):** A 2D image array where each pixel stores the exponential decay of light in the medium along the view ray. Let $X(u,v)$ be the value at pixel $(u,v)$. The value represents the attenuation factor $e^{-\tau}$, where $\tau$ is the optical depth [S1].
2.  **Direct Lighting Snapshot:** A 2D image array representing the scene rendered with ray tracing using only direct lighting (no medium scattering) [S1].
3.  **Saliency Map (S Map):** A 2D image array generated by applying the Itti et al. [1998] saliency algorithm to the modulated snapshot [S1].
4.  **Light Map (L Map):** A 2D image array identifying areas around light sources where multiple scattering is salient. Defined in [Light Map (L Map)](16885-light-map-l-map.md) [S1].
5.  **XS Map:** A 2D image array resulting from the combination of the X Map and S Map.
6.  **XSL Map:** The final director map, a 2D image array resulting from the combination of the XS Map and L Map [S1].

### Steps

1.  **Generate Direct Lighting Snapshot:**
    Render the scene using ray tracing with only direct lighting. No medium scattering is computed for this step [S1]. Let this image be $I_{direct}(u,v)$.

2.  **Compute Extinction Map (X Map):**
    For each pixel $(u,v)$, compute the optical depth $\tau$ along the view ray through the participating media. Calculate the extinction value as:
    $$ X(u,v) = e^{-\tau(u,v)} $$
    This stores the exponential decay of light in the medium [S1].

3.  **Modulate Snapshot for Saliency:**
    To account for the fact that extinction and visibility are inversely proportional for perceptual purposes, invert the X Map and add it to the Direct Lighting Snapshot. Let $I_{modulated}(u,v)$ be the result:
    $$ I_{modulated}(u,v) = I_{direct}(u,v) + (1 - X(u,v)) $$
    Note: The source states "Invert the Extinction Map (X map). Add the inverted X map to the direct-lighting snapshot." It clarifies that while not physically accurate, this empirically suits the needs [S1].

4.  **Generate Saliency Map (S Map):**
    Apply the saliency algorithm from Itti et al. [1998] to $I_{modulated}(u,v)$. This algorithm extracts features based on intensity, color, and orientation at varying spatial scales to produce a conspicuity map, which is then combined into a saliency map [S1]. Let the result be $S(u,v)$.

5.  **Generate XS Map:**
    Combine the X Map and the S Map. The specific combination formula for the XS map is not explicitly detailed beyond being a precursor to the XSL map, but it is implied to be a weighted combination similar to the XSL step. However, the text focuses on the final XSL combination. We assume a standard weighted addition or similar operator for the XS map generation, or that the XS map is an intermediate concept where X and S are combined. The text says "combine the XS map and the L map... where XSL represents the combined XS map and L map". It does not give the explicit formula for XS, only for XSL. We will proceed to the XSL combination using the XS map as an input. *Note: The source does not provide the exact formula for combining X and S into XS, only that it exists. We will treat XS as an intermediate map $XS(u,v)$.*

6.  **Combine into XSL Map:**
    Combine the XS Map and the L Map using the term $XSL(w_{xs}, w_l, op)$. The formula is:
    $$ XSL(u,v) = op(w_{xs} \cdot XS(u,v), w_l \cdot L(u,v)) $$
    Where:
    *   $XS(u,v)$ is the value from the XS map.
    *   $L(u,v)$ is the value from the Light Map.
    *   $w_{xs}$ and $w_l$ are coefficients for the XS and L maps respectively.
    *   $op$ is the combination operator.
    
    For equal weighting, use $w_{xs} = 0.5$ and $w_l = 0.5$ with the addition operator ($+$) [S1]:
    $$ XSL(u,v) = 0.5 \cdot XS(u,v) + 0.5 \cdot L(u,v) $$
    
    To render using only the XS map, use $w_{xs}=1, w_l=0$. To render using only the L map, use $w_{xs}=0, w_l=1$ [S1].

7.  **Selective Rendering:**
    For each pixel $(u,v)$ in the final render:
    *   Retrieve the director map value $D = XSL(u,v)$.
    *   Calculate the number of rays to shoot for this pixel:
        $$ R(u,v) = \text{clamp}(R_{max} \cdot D, 1, R_{max}) $$
        (Assuming $XSL$ values are normalized to $[0,1]$ or scaled appropriately. The source states "Higher values in the director map will result in more rays shot per pixel". It does not specify normalization, but typically director maps are normalized. If $XSL$ is not normalized, $R_{max}$ must be scaled or $D$ normalized. We assume $D$ is a weight factor. If $D > 1$, it might exceed $R_{max}$, so clamping is necessary [G].)
    *   Shoot $R(u,v)$ rays for the pixel to compute the final color, using a global illumination algorithm for participating media (e.g., ray marching or photon mapping) [S1].

### Parameters
*   $w_{xs}$: Coefficient for the XS map. Default: 0.5 [S1].
*   $w_l$: Coefficient for the L map. Default: 0.5 [S1].
*   $op$: Combination operator. Default: Addition ($+$) [S1].
*   $R_{max}$: Maximum number of rays per pixel. User-defined parameter [S1].

### Edge Cases and Pitfalls
*   **Normalization:** The source does not specify if the XSL map values are normalized to $[0,1]$. If not, the ray count calculation must handle values outside the expected range. Clamping $R(u,v)$ to $[1, R_{max}]$ is recommended [G].
*   **Perceptual Degradation:** Although average pixel errors are less than 1%, subjective validation indicates that quality degradation is still noticeable for certain scenes [S1].
*   **Scattering Around Light Sources:** The previous algorithm (XS map only) did not account for scattering around light sources, resulting in noisy artifacts. The L map addresses this, but if $w_l$ is set to 0, these artifacts may reappear [S1].
*   **Extinction Inversion:** The inversion of the X map ($1-X$) is an empirical approximation and not physically accurate, but it works for the saliency generator [S1].

## Subtopics

### Light Map (L Map)
A map identifying areas around light sources where scattering becomes a salient feature, introduced to fix artifacts caused by the XS map. [Link](16885-light-map-l-map.md)

### Saliency Map (S Map)
A modulated saliency map used to guide the perception-based renderer, generated from a direct lighting snapshot and an inverted extinction map. [Link](16885-light-map-l-map.md) (Note: S Map is a component, not a separate article in the provided tree, but referenced in the parent).

### Extinction Map (X Map)
Stores in image-space the exponential decay of light in the medium. [Link](16885-light-map-l-map.md)

## Operating characteristics
*   **Time Complexity:** The preprocessing step (generating the XSL map) involves rendering a direct lighting snapshot, computing extinction, and applying saliency algorithms. The final rendering time is proportional to the sum of rays shot per pixel, which is weighted by the XSL map. Areas with high XSL values require more rays, increasing local computation time, but the overall average ray count is reduced compared to uniform sampling [S1].
*   **Memory Complexity:** Requires storage for the X map, S map, L map, XS map, and XSL map, all of which are 2D image arrays of the same resolution as the output image. The memory overhead is linear with respect to the image resolution [S1].
*   **Measured Performance:** The average pixel errors of objective difference metrics are all less than 1% [S1]. However, subjective validation indicates that degradation in quality is still noticeable for certain scenes [S1].
*   **Strengths:** Significantly reduces rendering times for inhomogeneous media by focusing computational effort on perceptually important areas. Addresses noisy artifacts caused by poor sampling around light sources by incorporating the L map [S1].
*   **Limitations:** The inversion of the X map is an empirical approximation and not physically accurate. Quality degradation is still noticeable in some scenes despite low average pixel errors [S1].
*   **When to Use:** Suitable for applications where rendering time is a constraint and perceptual quality is prioritized over physical accuracy, such as safety, military, or industry applications analyzing visual perception under unfavorable environmental conditions (fog, smoke, dust, flames, silty waters) [S1].
*   **When Not to Use:** When physically accurate global illumination is required without perceptual approximations, or when the artifacts from the empirical X map inversion are unacceptable [S1].

## Background
The XSL Map Selective Rendering method was introduced by Sundstedt, Gutierrez, Anson, Banterle, and Chalmers in 2007 as an extended version of their previous work [Anson et al. 2006] [S1]. The previous algorithm combined a saliency map with a new extinction map (X-map) but did not account for scattering around light sources, leading to noisy artifacts [S1]. The 2007 paper introduced the Light Map (L map) to address this issue and combined it with the XS map to form the XSL map [S1]. The method is used in safety, military, or industry applications for analyzing visual perception under unfavorable environmental conditions [S1].
