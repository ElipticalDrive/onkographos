# XSL Map Selective Rendering

Also called: Selective Rendering with XSL Map

## Overview
XSL Map Selective Rendering is a perceptual strategy for physically based rendering of participating media that reduces rendering time by using a combination of a saliency map (S map), an extinction map (X map), and a light map (L map) to guide selective rendering, providing more accurate estimates in perceptually important areas [S1]. It builds on [Light Map (L Map)](16885-light-map-l-map.md) by integrating the L map with the XS map to form a unified director map that accounts for both extinction and scattering around light sources, addressing artifacts caused by poor sampling in previous methods [S1]. Unlike standard global illumination which treats all pixels equally, this method modulates the maximum number of rays per pixel based on the XSL map, prioritizing areas with high perceptual saliency, low extinction, and strong scattering [S1].

## How it works
The method generates a director map (XSL map) from three component maps and uses it to weight the sampling density (maximum rays per pixel) for each pixel in the final rendering [S1].

### Inputs and Outputs
*   **Inputs:** Scene geometry, participating media properties, light source positions and intensities, camera parameters, coefficients $w_{xs}$ and $w_l$ for weighting the XS and L maps, combination operator $op$ (typically addition), and a base maximum number of rays per pixel (user-defined parameter) [S1].
*   **Outputs:** Rendered image with adaptive sampling density, and the XSL director map as an intermediate data structure [S1].

### Data Structures
1.  **Extinction Map (X Map):** A 2D image array where each pixel stores the exponential decay of light in the medium along the view ray [S1]. Let $X(u,v)$ be the value at pixel $(u,v)$, representing the attenuation factor $e^{-\tau}$, where $\tau$ is the optical depth [S1].
2.  **Direct Lighting Snapshot:** A 2D image array representing the scene rendered with ray tracing using only direct lighting (no medium scattering) [S1].
3.  **Saliency Map (S Map):** A 2D image array generated by applying the Itti et al. [1998] saliency algorithm to the modulated snapshot [S1].
4.  **Light Map (L Map):** A 2D image array identifying areas around light sources where multiple scattering is salient [S1].
5.  **XS Map:** A 2D image array resulting from the combination of the X Map and S Map [S1].
6.  **XSL Map:** The final director map, a 2D image array resulting from the combination of the XS Map and L Map [S1].

### Steps

1.  **Generate Direct Lighting Snapshot:**
    Render the scene using ray tracing with only direct lighting. No medium scattering is computed for this step [S1]. Let this image be $I_{direct}(u,v)$ [S1].

2.  **Compute Extinction Map (X Map):**
    Cast rays from the eye into the scene, ray marching through the medium until the first intersection [S1]. Calculate the extinction value as:
    $$ X(u,v) = e^{-\tau(u,v)} $$
    This stores the exponential decay of light in the medium [S1]. Save the distance to the intersection in a Z buffer to allow instant recomputation if the medium description changes [S1]. For homogeneous media, attenuation is calculated as $e^{-\kappa s}$ using faster ray tracing instead of ray marching [S1]. Apply the MinBound technique: calculate the minimum value $x_{min}$ in the X map and assign it to all zero values to avoid rapid quality changes between ground and sky [S1].

3.  **Modulate Snapshot for Saliency:**
    To account for the fact that extinction and visibility are inversely proportional for perceptual purposes, invert the X Map and add it to the Direct Lighting Snapshot [S1]. Let $I_{modulated}(u,v)$ be the result:
    $$ I_{modulated}(u,v) = I_{direct}(u,v) + (1 - X(u,v)) $$
    While not a physically accurate method, this empirical inversion suits the needs of the saliency generator [S1].

4.  **Generate Saliency Map (S Map):**
    Apply the saliency algorithm from Itti et al. [1998] to $I_{modulated}(u,v)$ [S1]. This algorithm extracts features based on intensity, color, and orientation at varying spatial scales to produce a conspicuity map, which is then combined into a saliency map [S1]. Let the result be $S(u,v)$ [S1].

5.  **Generate XS Map:**
    Combine the X Map and the S Map into the XS map [S1].
    # Source does not specify the exact combination formula for XS [S1]

6.  **Combine into XSL Map:**
    Combine the XS Map and the L Map using the term $XSL(w_{xs}, w_l, op)$ [S1]. The formula is:
    $$ XSL(u,v) = op(w_{xs} \cdot XS(u,v), w_l \cdot L(u,v)) $$
    Where:
    *   $XS(u,v)$ is the value from the XS map [S1].
    *   $L(u,v)$ is the value from the Light Map [S1].
    *   $w_{xs}$ and $w_l$ are coefficients for the XS and L maps respectively [S1].
    *   $op$ is the combination operator [S1].
    
    For equal weighting, use $w_{xs} = 0.5$ and $w_l = 0.5$ with the addition operator ($+$) [S1]:
    $$ XSL(u,v) = 0.5 \cdot XS(u,v) + 0.5 \cdot L(u,v) $$
    
    To render using only the XS map, use $w_{xs}=1, w_l=0$ [S1]. To render using only the L map, use $w_{xs}=0, w_l=1$ [S1].

7.  **Selective Rendering:**
    For each pixel $(u,v)$ in the final render:
    *   Retrieve the director map value $D = XSL(u,v)$ [S1].
    *   Calculate the number of rays to shoot for this pixel:
        $$ R(u,v) = \text{clamp}(R_{base} \cdot D, 1, R_{base}) $$
        (Assuming $XSL$ values are normalized or scaled appropriately [G]. The source states "Higher values in the director map will result in more rays shot per pixel" [S1]. Clamping ensures at least 1 ray and does not exceed the base maximum [G]. If not, the ray count calculation must handle values outside the expected range [G].)
    *   Shoot $R(u,v)$ rays for the pixel to compute the final color, using a global illumination algorithm for participating media [S1]. The system primarily uses ray count weighting, though it could be extended to support other parameters like ray marching step size or volume photon map estimation quality [S1].

### Parameters
*   $w_{xs}$: Coefficient for the XS map. Default: 0.5 [S1].
*   $w_l$: Coefficient for the L map. Default: 0.5 [S1].
*   $op$: Combination operator. Default: Addition ($+$) [S1].
*   $R_{base}$: Base maximum number of rays per pixel. User-defined parameter [S1].

### Edge Cases and Pitfalls
*   **Normalization:** The source does not specify if the XSL map values are normalized to $[0,1]$ [G]. If not, the ray count calculation must handle values outside the expected range [G]. Clamping $R(u,v)$ to $[1, R_{base}]$ is recommended [G].
*   **Perceptual Degradation:** Although average pixel errors of objective difference metrics are all less than 1%, subjective validation indicates that degradation in quality is still noticeable for certain scenes [S1].
*   **Scattering Around Light Sources:** The previous algorithm (XS map only) did not account for scattering around light sources, resulting in noisy artifacts [S1]. The L map addresses this, but if $w_l$ is set to 0, these artifacts may reappear [S1].
*   **Extinction Inversion:** The inversion of the X map ($1-X$) is an empirical approximation and not physically accurate, but it works for the saliency generator [S1].
*   **Infinite Depth (Sky):** In outdoor scenes, large areas with infinite depth (sky) result in an inability to calculate the X map, which defaults to zero [S1]. The MinBound technique prevents poor-quality renders of medium between the camera and sky [S1].

## Subtopics

### Extinction Map (X Map)
A precomputed image-space map storing attenuation values (transmittance) for each pixel, representing the fraction of light (direct and diffuse) that reaches the eye from that pixel through the participating medium [S1]. Rays are cast from the eye into the scene, ray marching through the medium until the first intersection, and saving the result of the exponential decay in the X map for each pixel [S1]. The distance to the intersection is saved in a Z buffer to allow instant recomputation if the medium description changes [S1]. For homogeneous media, attenuation is calculated as $e^{-\kappa s}$ using faster ray tracing instead of ray marching [S1]. The MinBound technique calculates the minimum value $x_{min}$ in the X map and assigns it to all zero values to avoid rapid quality changes between ground and sky [S1]. In outdoor scenes, large areas with infinite depth (sky) result in an inability to calculate the X map, which defaults to zero, potentially causing poor-quality renders of medium between camera and sky [S1].

## Operating characteristics
*   **Time Complexity:** The preprocessing step (generating the XSL map) involves rendering a direct lighting snapshot, computing extinction, and applying saliency algorithms [S1]. The final rendering time is proportional to the sum of rays shot per pixel, which is weighted by the XSL map [S1]. Areas with high XSL values require more rays, increasing local computation time, but the overall average ray count is reduced compared to uniform sampling [S1].
*   **Measured Performance:** The average pixel errors of objective difference metrics are all less than 1% [S1]. However, subjective validation indicates that degradation in quality is still noticeable for certain scenes [S1].
*   **Strengths:** Significantly reduces rendering times for inhomogeneous media by focusing computational effort on perceptually important areas [S1]. Addresses noisy artifacts caused by poor sampling around light sources by incorporating the L map [S1].
*   **Limitations:** The inversion of the X map is an empirical approximation and not physically accurate [S1]. Quality degradation is still noticeable in some scenes despite low average pixel errors [S1].
*   **When to Use:** Suitable for applications where rendering time is a constraint and perceptual quality is prioritized over physical accuracy, such as safety, military, or industry applications analyzing visual perception under unfavorable environmental conditions (fog, smoke, dust, flames, silty waters) [S1].
*   **When Not to Use:** When physically accurate global illumination is required without perceptual approximations, or when the artifacts from the empirical X map inversion are unacceptable [S1].

## Background
The XSL Map Selective Rendering method was introduced by Sundstedt, Gutierrez, Anson, Banterle, and Chalmers in 2007 as an extended version of their previous work [Anson et al. 2006] [S1]. The previous algorithm combined a saliency map with a new extinction map (X-map) but did not account for scattering around light sources, leading to noisy artifacts [S1]. The 2007 paper introduced the Light Map (L map) to address this issue and combined it with the XS map to form the XSL map [S1]. The method is used in safety, military, or industry applications for analyzing visual perception under unfavorable environmental conditions [S1].
