# Reference Path Tracing

Also called: Path Traced Subsurface Scattering, Random Walk SSS, ReferencePathTracer, Volume SSS

## Overview
Reference Path Tracing is an unbiased volumetric path tracer used as a ground-truth reference renderer for subsurface scattering and participating media [S1, S2, unofficial]. It solves the problem of accurate light transport in high-curvature surfaces and complex media by treating the subsurface layer as a volume, performing full random walks from entry to exit points [S2, unofficial]. It sets itself apart from diffusion-based models by explicitly tracking geometric features for accurate shadowing and handling zero- and single-scatter events, while differing from sibling methods like BSDF Sampling for Volumetric Paths by relying on a pure random walk with Next-Event Estimation (NEE) rather than specialized BSDF sampling strategies [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Surface entry point, surface normal, medium extinction coefficient $\sigma_t$ (assumed homogeneous for the basic model), geometry mesh for boundary intersection, maximum bounce count, and Russian roulette start threshold [S2, S1, unofficial].
*   **Outputs:** Radiance contribution from the path, weighted by the path throughput and surface response [S2, S1, unofficial].

**Data Structures:**
The method is encapsulated in a struct `ReferencePathTracer` which inherits from `VolumeIntegrationMethod` [S1, unofficial].
*   `max_bounces::Int`: Maximum number of scattering events per path. Default: 64 [S1, unofficial].
*   `rr_start::Int`: Number of bounces after which Russian roulette activation begins. Default: 3 [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** At the surface entry point, choose the initial direction $\omega_i$ from a Lambertian distribution around the inverse surface normal $-n$ [S2, unofficial].
2.  **Distance Sampling:** Advance along the current direction by a distance $s$ sampled from the transmittance distribution. For a homogeneous medium with extinction coefficient $\sigma_t$, the transmittance $T$ over distance $s$ is governed by Beer's Law:
    $$ T = e^{-\sigma_t s} $$
    To sample the distance, draw a uniform random number $\xi \in [0, 1)$ and invert the cumulative distribution function:
    $$ s = -\frac{\ln(1 - \xi)}{\sigma_t} $$
    [S2, unofficial].
3.  **Direction Update:** For isotropic scattering, update the direction for the next step by drawing a sample from a uniform spherical distribution [S2, unofficial].
4.  **Boundary Intersection:** Trace a ray from the current position along the new direction against the scene geometry to check for intersection with the exterior interface [S2, unofficial].
5.  **Termination Check (Exit):** If the ray intersects the exterior interface at distance $s_{hit} < s_{sampled}$:
    *   Terminate the random walk.
    *   Compute direct illumination at the exit point using Next-Event Estimation (NEE) [S1, unofficial].
    *   Weigh the incoming radiance by a Lambertian response function. Do not apply surface coloring effects (albedo) at this stage [S2, unofficial].
    *   Return the contribution.
6.  **Termination Check (Depth):** If the path continues for a fixed depth limit (default 256 steps) without finding an exit point, deem the photon lost and set the final contribution to zero [S2, unofficial].
7.  **Termination Check (Russian Roulette):** If the path has not exited and has not reached the fixed depth limit:
    *   If the current bounce count $b < rr\_start$, continue to the next step [S1, unofficial].
    *   If $b \ge rr\_start$, apply Russian Roulette to terminate the path stochastically based on the path throughput to maintain unbiasedness [S1, S2, unofficial].
    *   If the path survives, update the throughput and continue to Step 2.

**Pseudocode:**
```python
def reference_path_tracing(entry_point, normal, sigma_t, geometry, max_bounces=64, rr_start=3, fixed_depth=256):
    """
    Performs a reference random walk for subsurface scattering.
    """
    throughput = 1.0
    current_pos = entry_point
    current_dir = sample_lambertian(-normal) # Sample around inverse normal
    bounces = 0
    
    for step in range(fixed_depth):
        # 1. Sample distance using Beer's Law inversion
        xi = random_uniform()
        # Avoid log(0)
        if xi == 0.0: xi = 1e-6
        distance = -log(1.0 - xi) / sigma_t
        
        # 2. Trace ray against geometry to find exit
        hit = geometry.trace_ray(current_pos, current_dir, max_distance=distance)
        
        if hit is not None:
            # Exit found: Compute direct illumination (NEE)
            # Weigh by Lambertian response, no surface coloring
            radiance = compute_direct_illumination(hit.point, hit.normal)
            return throughput * radiance
            
        # 3. Update position
        current_pos = current_pos + current_dir * distance
        
        # 4. Update direction (Isotropic scattering)
        current_dir = sample_spherical()
        
        bounces += 1
        
        # 5. Russian Roulette
        if bounces >= rr_start:
            # Simple RR: probability of survival could be based on throughput or fixed
            # Standard implementation uses throughput or a fixed probability
            # Here we assume a standard RR check
            if random_uniform() > 0.5: # Placeholder for specific RR probability logic
                return 0.0
            throughput /= 0.5 # Adjust throughput for survival
            
        # 6. Max bounces check
        if bounces >= max_bounces:
            return 0.0
            
    # Fixed depth limit reached without exit
    return 0.0
```
[G] The pseudocode assumes standard vector addition and a `trace_ray` function that returns the closest intersection or `None`. The Russian Roulette survival probability is not explicitly defined in the sources; a common practice is to use the maximum component of the throughput or a fixed probability, but the source only states "terminate paths with low weight stochastically" [S2, unofficial]. The Lambertian response weighting at exit is specified, but the exact NEE implementation details are omitted [S2, unofficial].

**Parameters:**
*   `max_bounces`: 64 [S1, unofficial].
*   `rr_start`: 3 [S1, unofficial].
*   `fixed_depth`: 256 [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of scattering events and geometry intersection tests. Each step requires a ray trace against the geometry [S2, unofficial].
*   **Memory Complexity:** Low, as it only stores the current path state and does not require storing large voxel grids or photon maps [S1, S2, unofficial].
*   **Strengths:** Explicitly handles high-curvature geometry and shadowing, which diffusion models fail at. Accurately models zero- and single-scatter events, preserving energy better than diffusion approximations [S2, unofficial]. Unbiased [S1, unofficial].
*   **Limitations:** Can be noisy due to the stochastic nature of random walks, especially for deep or highly absorbing media. The fixed depth limit of 256 may truncate paths in very thick media, though Russian Roulette mitigates this [S2, unofficial]. Chromatic effects require wavelength-specific sampling which is inefficient if not handled carefully [S2, unofficial].
*   **When to use:** When ground-truth accuracy is required for subsurface scattering, particularly for objects with high curvature or thin features where diffusion models are inaccurate [S2, unofficial].
*   **When not to use:** When real-time performance is required, or when the medium is extremely thick and deep, leading to excessive path lengths and noise [S2, unofficial].

## Background
Reference Path Tracing originated as a method to provide a ground-truth reference for subsurface scattering in production renderers [S1, S2, unofficial]. It was developed to address the limitations of diffusion-based subsurface scattering models, which assume a semi-infinite flat slab and fail in areas of high curvature like the nose or ears of a human face [S2, unofficial]. By treating the subsurface as a volume and using a random walk, it allows for the integration of standard volumetric path tracing techniques into subsurface scattering simulations [S2, unofficial]. The specific implementation details, such as the `ReferencePathTracer` struct, are found in the Lyr.jl library [S1, unofficial].
