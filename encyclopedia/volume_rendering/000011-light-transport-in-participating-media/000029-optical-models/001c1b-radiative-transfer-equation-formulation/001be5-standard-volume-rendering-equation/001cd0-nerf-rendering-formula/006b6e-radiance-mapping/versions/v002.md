# Radiance Mapping

Also called: Compact Radiance Mapping, Point Cloud Radiance Mapping, radiance mapping function, spatial mapping function

## Overview

Radiance Mapping is a lightweight rendering method for point clouds that simplifies the NeRF volume rendering formulation by replacing volumetric density prediction with a direct latent feature output [S1]. It models the view-dependent color of the first-time intersection between an estimated surface and a camera ray, augmenting each 3D point with a learnable feature indicating first-hit color, thereby avoiding redundant computation on internal ray samples [S1]. Unlike NeRF, which requires dense spatial sampling and density estimation, Radiance Mapping assumes only the first intersected surface matters, discarding translucent back-surface evaluation and reducing the MLP size significantly [S1].

## How it works

**Inputs and Outputs:**
*   **Input:** A 3D point cloud $P$ (with coordinates and potentially initial attributes), camera parameters (position $o$, direction $d$), and a radius threshold $\tau$ [S1].
*   **Output:** A rendered image of shape $H \times W \times 3$ [S1].

**Data Structures:**
*   **Point Cloud:** A set of 3D points. Raw points contain noise $\epsilon$ such that $x_{pcd} = x_{obj} + \epsilon$ [S1].
*   **Fragments:** Points within radius $\tau$ of a camera ray. For occupied pixels, only the closest point (fragment) is kept [S1].
*   **Feature Map:** An $H \times W \times C$ tensor where $C$ is the feature dimension. Unoccupied pixels are assigned zero features [S1].
*   **Radiance Mapping MLP ($F_\Theta$):** A 5-layer Multi-Layer Perceptron [S1].
    *   Layer dimensions: 256, 256, 256, 128, 8 [S1].
    *   Total parameters: 0.75 million [S1].
    *   Input: Concatenated positional encoding of rectified coordinate $x_{query}$ and view direction $d$.
    *   Output: Latent feature vector $L$ of dimension $C$ (typically 8 in the cited architecture) [S1].
*   **Refinement U-Net:** A 2D convolutional network [S1].
    *   Architecture: Down-samples four times.
    *   Layer dimensions: 16, 32, 64, 128, 256 [S1].
    *   Blocks: Gated convolution, ReLU, Instance Normalization [S1].

**Numbered Steps:**

1.  **Rasterization:**
    *   Transform point clouds from world space to camera space [S1].
    *   For each pixel, search for points within radius $\tau$ of the camera ray [S1].
    *   Keep only the closest point (fragment) for occupied pixels; discard others [S1].
    *   Mark pixels with no points within $\tau$ as unoccupied [S1].
    *   *Note:* $\tau$ values are dataset-dependent: $5 \times 10^{-3}$ for NeRF-Synthetic, $1.5 \times 10^{-2}$ for ScanNet, $3 \times 10^{-3}$ for DTU [S1].

2.  **Coordinate Rectification:**
    *   For each occupied pixel, calculate the rectified query coordinate $x_{query}$ using the z-buffer value $z_{pcd}$ of the closest point [S1]:
        $$ x_{query} = o + \frac{z_{pcd}}{\cos \theta} \times d $$
        where $o$ is the camera position, $d$ is the normalized ray direction, and $\theta$ is the angle between the ray and the z-axis pointing to the scene center [S1].
    *   This rectification ensures the query point lies exactly on the camera ray, correcting for raw point cloud noise and sparsity [S1].

3.  **Radiance Mapping (Spatial Feature Extraction):**
    *   Apply positional encoding to $x_{query}$ and $d$ (using the same scheme as NeRF) [S1].
    *   Feed the encoded inputs into the MLP $F_\Theta$ to obtain the latent feature $L$ [S1]:
        $$ L = F_\Theta(x_{query}, d) $$
    *   The output $L$ has shape $N_{occ} \times C$, where $N_{occ}$ is the number of occupied pixels [S1]. Density $\sigma$ is not predicted [S1].

4.  **Feature Map Assembly:**
    *   Re-organize the latent features $L$ into an $H \times W \times C$ feature map [S1].
    *   Assign zero features to unoccupied pixels [S1].

5.  **Refinement:**
    *   Pass the $H \times W \times C$ feature map through the 2D U-Net [S1].
    *   The U-Net processes the features to compensate for sparsity and noise, leveraging 2D convolutional priors [S1].
    *   The U-Net outputs the final rendered image with shape $H \times W \times 3$ [S1].

**Pseudocode:**

```python
import math
import torch
import torch.nn as nn
import torch.nn.functional as F

def positional_encoding(x, min_deg, max_deg):
    scales = torch.tensor([2**i for i in range(min_deg, max_deg + 1)], dtype=x.dtype, device=x.device)
    xb = torch.reshape((x[..., None, :] * scales[:, None]), list(x.shape[:-1]) + [(max_deg - min_deg + 1) * x.shape[-1]])
    fouriered = torch.cat((torch.sin(xb), torch.cos(xb)), dim=-1)
    return torch.cat((x, fouriered), dim=-1)

class RadianceMappingMLP(nn.Module):
    def __init__(self, input_dim, hidden_dims=[256, 256, 256, 128], output_dim=8):
        super().__init__()
        layers = []
        prev_dim = input_dim
        for h in hidden_dims:
            layers.append(nn.Linear(prev_dim, h))
            layers.append(nn.ReLU())
            prev_dim = h
        layers.append(nn.Linear(prev_dim, output_dim))
        self.net = nn.Sequential(*layers)
    def forward(self, x):
        return self.net(x)

class RefinementUNet(nn.Module):
    def __init__(self, in_channels, out_channels=3):
        super().__init__()
        # Down-samples 4 times. Dimensions: 16, 32, 64, 128, 256.
        # Uses gated blocks (gated conv, ReLU, Instance Norm).
        self.enc1 = nn.Sequential(nn.Conv2d(in_channels, 16, 3, padding=1), nn.InstanceNorm2d(16), nn.ReLU())
        self.enc2 = nn.Sequential(nn.Conv2d(16, 32, 3, padding=1), nn.InstanceNorm2d(32), nn.ReLU())
        self.enc3 = nn.Sequential(nn.Conv2d(32, 64, 3, padding=1), nn.InstanceNorm2d(64), nn.ReLU())
        self.enc4 = nn.Sequential(nn.Conv2d(64, 128, 3, padding=1), nn.InstanceNorm2d(128), nn.ReLU())
        self.enc5 = nn.Sequential(nn.Conv2d(128, 256, 3, padding=1), nn.InstanceNorm2d(256), nn.ReLU())
        self.dec4 = nn.Sequential(nn.Conv2d(256, 128, 3, padding=1), nn.InstanceNorm2d(128), nn.ReLU())
        self.dec3 = nn.Sequential(nn.Conv2d(128, 64, 3, padding=1), nn.InstanceNorm2d(64), nn.ReLU())
        self.dec2 = nn.Sequential(nn.Conv2d(64, 32, 3, padding=1), nn.InstanceNorm2d(32), nn.ReLU())
        self.dec1 = nn.Sequential(nn.Conv2d(32, 16, 3, padding=1), nn.InstanceNorm2d(16), nn.ReLU())
        self.out_conv = nn.Conv2d(16, out_channels, 1)
    def forward(self, x):
        e1 = self.enc1(x)
        e2 = self.enc2(F.avg_pool2d(e1, 2))
        e3 = self.enc3(F.avg_pool2d(e2, 2))
        e4 = self.enc4(F.avg_pool2d(e3, 2))
        e5 = self.enc5(F.avg_pool2d(e4, 2))
        d4 = F.interpolate(e5, scale_factor=2)
        d4 = self.dec4(d4)
        d3 = F.interpolate(d4, scale_factor=2)
        d3 = self.dec3(d3)
        d2 = F.interpolate(d3, scale_factor=2)
        d2 = self.dec2(d2)
        d1 = F.interpolate(d2, scale_factor=2)
        d1 = self.dec1(d1)
        return torch.sigmoid(self.out_conv(d1))

def rasterize_points(points_cam, ray_dirs, height, width, tau):
    """
    Simulates hardware-accelerated rasterization.
    points_cam: (N, 3) in camera space.
    ray_dirs: (H, W, 3) normalized ray directions.
    Returns:
      fragments: (N_occ, 3) 3D coordinates of closest points per occupied pixel.
      pixel_map: (N_occ, 2) integer (x, y) coordinates of occupied pixels.
      z_pcd: (N_occ,) depth values of closest points.
    """
    fragments = []
    pixel_map = []
    z_pcd = []
    for y in range(height):
        for x in range(width):
            d = ray_dirs[y, x]
            min_dist = float('inf')
            closest_idx = -1
            for i, p in enumerate(points_cam):
                op = p
                t = torch.dot(op, d)
                proj = t * d
                dist = torch.norm(op - proj)
                if dist < tau and dist < min_dist:
                    min_dist = dist
                    closest_idx = i
            if closest_idx != -1:
                fragments.append(points_cam[closest_idx])
                pixel_map.append([x, y])
                z_pcd.append(points_cam[closest_idx, 2])
    if not fragments:
        return torch.empty(0, 3), torch.empty(0, 2), torch.empty(0)
    return torch.stack(fragments), torch.tensor(pixel_map), torch.tensor(z_pcd)

def render_radiance_mapping(points_world, camera_o, camera_d, height, width, tau, 
                            min_deg_pe=0, max_deg_pe=10, 
                            mlp_params=None, unet_params=None):
    # 1. Transform to camera space (simplified: assume points_world are already in camera space relative to camera_o)
    points_cam = points_world - camera_o

    # 2. Rasterization
    fragments, pixel_map, z_pcd = rasterize_points(points_cam, camera_d, height, width, tau)

    # 3. Coordinate Rectification
    d_occupied = camera_d[pixel_map[:, 1].long(), pixel_map[:, 0].long()]
    cos_theta = d_occupied[:, 2]
    cos_theta = torch.clamp(cos_theta, min=1e-6)
    scale = z_pcd / cos_theta
    x_query = scale[:, None] * d_occupied

    # 4. Radiance Mapping
    pe_x = positional_encoding(x_query, min_deg_pe, max_deg_pe)
    pe_d = positional_encoding(d_occupied, min_deg_pe, max_deg_pe)
    input_features = torch.cat([pe_x, pe_d], dim=-1)
    mlp = RadianceMappingMLP(input_features.shape[1])
    if mlp_params is not None:
        mlp.load_state_dict(mlp_params)
    L = mlp(input_features)

    # 5. Feature Map Assembly
    feature_map = torch.zeros((height, width, L.shape[1]))
    y_idx = pixel_map[:, 1].long()
    x_idx = pixel_map[:, 0].long()
    feature_map[y_idx, x_idx, :] = L

    # 6. Refinement
    feature_map_tensor = feature_map.permute(2, 0, 1).unsqueeze(0)
    unet = RefinementUNet(in_channels=L.shape[1])
    if unet_params is not None:
        unet.load_state_dict(unet_params)
    rendered_image = unet(feature_map_tensor)
    return rendered_image.squeeze(0).permute(1, 2, 0)
```

**Parameters:**
*   **Radius Threshold ($\tau$):** $5 \times 10^{-3}$ (NeRF-Synthetic), $1.5 \times 10^{-2}$ (ScanNet), $3 \times 10^{-3}$ (DTU) [S1].
*   **MLP Layers:** 5 layers with dimensions 256, 256, 256, 128, 8 [S1].
*   **Positional Encoding:** Same as NeRF (sine/cosine functions at different frequencies) [S1].
*   **Optimizer:** Adam [S1].
*   **Batch Size:** 1 [S1].
*   **Learning Rates:** $5 \times 10^{-4}$ for MLP, $1.5 \times 10^{-4}$ for U-Net [S1].
*   **Learning Rate Decay:** $0.9999$ per step [S1].
*   **Loss Function:** $L2\_loss + 0.01 \times Perceptual\_loss$ [S1].

**Edge Cases and Pitfalls:**
*   **Spatial Frequency Collapse:** When point clouds are sparse, a single neural descriptor is rasterized to multiple pixels and optimized to fit the average of multiple pixels, harming rendering quality [S1]. This is analogous to Nyquist Rate dissatisfaction [S1].
*   **Neighbor Point Disturbance:** When point clouds are dense, points lying close have a larger impact on the feature optimization of each other [S1].
*   **Sparsity/Noise:** Raw point clouds have noise $\epsilon$ such that $x_{pcd} = x_{obj} + \epsilon$ [S1]. Feeding raw coordinates leads to spatial frequency collapse and blurred results because sparse points rasterize to multiple pixels, querying the same latent feature [S1]. Coordinate rectification solves this by providing uniformly distributed query points [S1].
*   **Unoccupied Pixels:** Pixels with no points within radius $\tau$ cause artifacts (bleeding) [S1]. These are handled by the refinement U-Net stage [S1].
*   **Threshold Selection:** If $\tau$ is too large, rasterized points are inaccurate [S1]. If $\tau$ is too small, more pixels become unoccupied, causing bleeding [S1].

## Operating characteristics

**Time and Memory Complexity:**
*   Radiance Mapping requires only single model inference per pixel, significantly reducing computation cost compared to NeRF's dense spatial sampling [S1].
*   The method avoids memory scaling with point cloud density, unlike some prior works [S1].
*   OpenGL-based rasterization is 8-10 times faster than pure software implementations like PyTorch3D [S1].

**Measured Performance:**
*   **NeRF-Synthetic:** PSNR 31.74, SSIM 0.968, LPIPS 0.029 [S1].
*   **ScanNet:** PSNR 25.88, SSIM 0.794, LPIPS 0.414 [S1].
*   **DTU:** PSNR 30.81, SSIM 0.904, LPIPS 0.128 [S1].
*   Outperforms NPBG and NPBG++ on all metrics [S1].

**Strengths and Limitations:**
*   **Strengths:** Lightweight model (0.75M parameters for MLP, ~8M total), fast inference, suitable for mobile devices (AR/VR), state-of-the-art performance on point cloud rendering [S1].
*   **Limitations:** Assumes only the first intersected surface matters (no translucent back-surface evaluation) [S1]. Performance depends on the quality and density of the input point cloud [S1].

**When to Use:**
*   When rendering point clouds with high fidelity and speed is required, especially on resource-constrained devices [S1].
*   When the scene can be approximated as opaque surfaces [S1].

**When Not to Use:**
*   When translucent or volumetric effects are critical [S1].
*   When the input point cloud is extremely noisy or sparse without sufficient refinement capabilities [S1].

## Background

Radiance Mapping was introduced in 2023 by Wang et al. in the paper "Boosting Point Clouds Rendering via Radiance Mapping" [S1]. It is motivated by the volume rendering formulation in NeRF, analyzing its adaptation to point cloud rendering scenarios [S1]. The method simplifies the NeRF representation by removing density prediction and reducing the MLP layers from 13 to 5 [S1]. It aims to boost image quality for point cloud rendering with a compact model design, suitable for mobile computing devices like smartphones or AR/VR headsets [S1]. The code and data are publicly available at https://github.com/seanywang0408/RadianceMapping [S1].
