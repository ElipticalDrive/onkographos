# Kajiya-Von Herren Ray Tracing Algorithm
Also called: Kajiya and Herzen Volume Ray Tracing, Kajiya and Von Herren method, Two-step ray tracing for volume densities

## Overview
The Kajiya-Von Herren algorithm is a two-step method for rendering participating media under the Single Scattering (Blinn Model) approximation [S1, unofficial]. It decouples light transport from image synthesis by precomputing a brightness contribution field for each light source and summing these contributions during ray tracing [S1, unofficial]. This separation allows illumination calculations to be performed once per frame or scene independently of the camera view, distinguishing it from per-pixel Monte Carlo approaches [S1, unofficial].

## How it works
The method consists of two distinct phases: a precomputation step to generate a brightness field, and a ray tracing step to render the final image.

**Inputs and Outputs:**
*   **Precomputation Input:** Light source position, medium density function $\rho(x,y,z)$, and extinction coefficient $\tau$ [S1, unofficial].
*   **Precomputation Output:** A 3D grid or field $I_i(x,y,z)$ representing the precomputed brightness contribution for light source $i$ [S1, unofficial].
*   **Ray Tracing Input:** Camera ray, bounding box of the medium, precomputed fields $I_i$ [S1, unofficial].
*   **Ray Tracing Output:** Pixel color [S1, unofficial].

**Data Structures:**
The precomputed brightness $I_i$ is stored as a 3D volume [S1, unofficial]. The specific grid resolution and bit-depth are not given in the sources.

**Precomputation Step:**
For each light source $i$, the brightness contribution $I_i(x,y,z)$ at any point in space is calculated using Romberg integration [S1, unofficial]. The formula is:

$$ I_i(x, y, z) = \exp\left(-\int_{0}^{r} \tau \rho(\xi) d\xi\right) \int_{0}^{r} \rho(\xi(t), \eta(t), \zeta(t)) dt $$

where $\tau = r \rho$ [S1, unofficial]. The symbol $r$ is the distance from the light source to the point $(x,y,z)$ [S1, unofficial]. The symbol $\rho(\xi)$ is the density at position $\xi$ along the path from the light source [S1, unofficial]. The path from the light source to the point is parameterized by $(\xi(t), \eta(t), \zeta(t))$ [S1, unofficial].

**Ray Tracing Step:**
1.  **Culling:** Each view ray is first culled against a bounding rectangular prism (extent) of the volume [S1, unofficial].
2.  **Path Boundaries:** The integration limits for the ray are determined by the intersection with the bounding extent and the rest of the world database [S1, unofficial]:
    $$ \lambda_1 = \max(0, d_1) $$
    $$ \lambda_2 = \min(d_{global}, d_2) $$
    where $d_1$ is the distance to the nearest intersection with the bounding extent, $d_{global}$ is the distance to the nearest intersection with the rest of the world database, and $d_2$ is the distance to the farthest intersection with the bounding extent [S1, unofficial].
3.  **Summation:** The brightness of the ray is computed by summing the contribution of each volume element along the path segment $[\lambda_1, \lambda_2]$ [S1, unofficial]. The source states the brightness sums the contribution of each volume element but does not provide the explicit discrete summation formula or the specific scattering phase function used in the final sum, only mentioning that for clouds, perfectly diffuse scattering ($p(\cos \theta) = w_0$) and Rayleigh scattering ($p(\cos \theta) = w_0 \frac{4}{3}(1 + \cos^2 \theta)$) are of interest [S1, unofficial].

**Pseudocode:**

```python
import math

def distance(p1, p2):
    return math.sqrt((p1[0]-p2[0])**2 + (p1[1]-p2[1])**2 + (p1[2]-p2[2])**2)

def precompute_brightness(light_source_pos, density_func, extinction_coeff, grid_points):
    brightness_field = {}
    for x, y, z in grid_points:
        target = (x, y, z)
        r = distance(light_source_pos, target)
        # Romberg integration is used for the integrals [S1, unofficial]
        # The exact numerical integration routine is not specified in the sources [G].
        optical_depth_integral = 0.0
        density_integral = 0.0
        
        # Formula: I_i(x,y,z) = exp(-optical_depth_integral) * density_integral
        brightness_field[(x, y, z)] = math.exp(-optical_depth_integral) * density_integral
    return brightness_field

def render_ray(camera_origin, camera_direction, bounding_extent, world_database, brightness_fields):
    # 1. Culling against bounding rectangular prism [S1, unofficial]
    # Standard axis-aligned bounding box intersection test
    t_min, t_max = 1e9, -1e9
    for i in range(3):
        inv_d = 1.0 / camera_direction[i]
        t1 = (bounding_extent.min[i] - camera_origin[i]) * inv_d
        t2 = (bounding_extent.max[i] - camera_origin[i]) * inv_d
        t_min = max(t_min, min(t1, t2))
        t_max = min(t_max, max(t1, t2))
    if t_max < 0 or t_min > t_max:
        return 0.0

    # 2. Determine path boundaries [S1, unofficial]
    d1 = t_min
    d2 = t_max
    d_global = 1e9 # Distance to nearest intersection with rest of world database [S1, unofficial]
    
    lambda_1 = max(0.0, d1)
    lambda_2 = min(d_global, d2)
    
    if lambda_1 >= lambda_2:
        return 0.0

    # 3. Summation along path segment [S1, unofficial]
    # The source states the brightness sums the contribution of each volume element.
    # The exact discrete summation formula and phase function application are not provided [S1, unofficial].
    total_brightness = 0.0
    step = 0.1 # Step size not given in the sources [G]
    t = lambda_1
    while t < lambda_2:
        point = (camera_origin[0] + camera_direction[0]*t,
                 camera_origin[1] + camera_direction[1]*t,
                 camera_origin[2] + camera_direction[2]*t)
        for field in brightness_fields:
            # Sample precomputed field and accumulate
            # Exact weighting formula not specified in sources [G]
            total_brightness += field.get(point, 0.0) * step
        t += step
    return total_brightness
```

**Edge Cases and Pitfalls:**
*   **Boundaries:** The path boundaries $\lambda_1$ and $\lambda_2$ must be correctly calculated to avoid integrating outside the volume or into occluding geometry [S1, unofficial].
*   **Ambiguity:** The exact relationship between the precomputed field $I_i$ and the final ray trace summation is not explicitly defined in the source text, leading to implementation ambiguity [S1, unofficial].

Grid-based Convection-Diffusion Illumination is a real-time volume rendering technique that models light propagation, absorption, and multiple scattering within participating media by solving a unified partial differential equation (PDE) on a regular grid.

## Operating characteristics
*   **Time Complexity:** The precomputation step is performed once per frame or scene, making it independent of the number of pixels [S1, unofficial]. The ray tracing step is linear with respect to the number of volume elements along the ray.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Decouples illumination from rendering, allowing for efficient reuse of lighting calculations [S1, unofficial].
*   **Limitations:** The source does not provide specific performance metrics or hardware details [S1, unofficial]. The ambiguity in the final summation step may lead to incorrect results if not implemented carefully [S1, unofficial].

## Background
The method is based on the work of Kajiya and Von Herren (also cited as Kajiya and Herzen) [S2]. It builds upon Blinn's Low Albedo approximation for volume density scattering [S1, unofficial]. Blinn (1982) introduced the model for participating media with low albedo, considering only one secondary ray traversing the material towards the light source [S1, unofficial]. Kajiya and Von Herren extended this by introducing the two-step precomputation approach and solving the equation differently for high albedo using spherical harmonics [S2].
