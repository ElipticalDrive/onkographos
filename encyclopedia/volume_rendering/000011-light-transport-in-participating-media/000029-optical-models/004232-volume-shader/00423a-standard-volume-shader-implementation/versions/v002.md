# Standard Volume Shader Implementation

Also called: Redshift Volume Shader

## Overview
The Standard Volume Shader is a material definition for participating media that simulates light transport in heterogeneous environments where density varies per voxel, such as smoke, fog, or clouds [S1, unofficial][S2]. It distinguishes itself from subsurface scattering by applying random walk logic to non-polygonal, spatially varying density fields rather than uniform, bounded surfaces [S1, unofficial][S2]. It separates the geometric distribution of particles from their optical properties, using a scalar density grid for occupancy and distinct color channels for scattering albedo and wavelength-dependent absorption [S1, unofficial][S2].

## How it works
**Inputs and Outputs**
*   **Inputs:** A ray traversing the volume; a scalar density grid (voxel data); parameters for Scatter Color, Transparency Color, Anisotropy, and Depth.
*   **Outputs:** Transmittance and scattered radiance accumulated along the ray segment within the volume bounds.

**Data Structures**
*   **Density Grid:** A scalar field where each voxel stores a single floating-point value representing particle count or density relative to empty space. It is independent of color [S1, unofficial][S2].
*   **Scatter Color:** A 3-channel vector (RGB) representing the albedo of suspended particles [S1, unofficial][S2].
*   **Transparency Color:** A 3-channel vector (RGB) encoding the mean free path for each wavelength [S1, unofficial][S2].
*   **Depth Parameter:** A scalar multiplier converting normalized transparency values into physical distances [S1, unofficial][S2].

**Parameters and Typical Values**
*   **Scatter Color:** Default is typically white or neutral, representing the color of light reflected by particles [S1, unofficial][S2].
*   **Transparency Color:** Values range from 0 to 1, representing normalized travel distances [S1, unofficial][S2].
*   **Depth:** Multiplies Transparency Color values into real distances measured in centimeters, scaled to the scene units [S1, unofficial][S2].
*   **Anisotropy:** Controls the phase function directionality. Default is Henyey-Greenstein; Jendersie-d’Eon is used for cloud-like water media [S1, unofficial][S2].
*   **Anisotropy Values:** Can be negative (backward scattering), zero (isotropic), or positive (forward scattering). Example values cited are -0.9, 0, and 0.85 [S2].

**Algorithm Steps**
1.  **Ray Marching:** The renderer marches through the volume, sampling the density grid voxel by voxel as the ray traverses the medium [S1, unofficial][S2].
2.  **Density Sampling:** For each step, retrieve the scalar density value from the grid at the current ray position [S1, unofficial][S2].
3.  **Phase Function Selection:** Determine the scattering direction distribution based on the Anisotropy parameter. Use Henyey-Greenstein for general cases or Jendersie-d’Eon for cloud-like water media [S1, unofficial][S2].
4.  **Absorption Calculation:** Calculate wavelength-dependent extinction using the Transparency Color and Depth. The mean free path for each wavelength is derived from the Transparency Color multiplied by the Depth parameter [S1, unofficial][S2].
5.  **Scattering Contribution:** Apply the Scatter Color (albedo) to the light interacting with the particles at the current voxel [S1, unofficial][S2].
6.  **Accumulation:** Accumulate scattered light and transmittance along the ray. Note that simulating multiple bounces (multiple scattering) is computationally expensive compared to single scattering [S1, unofficial].

**Formulas**
*   **Mean Free Path ($\lambda$):** The average distance a wavelength travels before extinction.
    $$ \lambda_{RGB} = \text{Transparency Color}_{RGB} \times \text{Depth} $$
    Where $\text{Transparency Color}_{RGB}$ is in the range $[0, 1]$ and $\text{Depth}$ is in centimeters [S1, unofficial][S2].
*   **Absorption/Tint Effect:** Light traveling a distance $d$ through the medium is tinted with the opposite of the Transparency Color as other wavelengths are exhausted. This creates effects like the blue color of deep water [S1, unofficial][S2].

**Pseudocode**
```python
def standard_volume_shader(ray, density_grid, scatter_color, transparency_color, depth, anisotropy_mode):
    """
    Simulates light transport in a heterogeneous volume using ray marching.
    
    Args:
        ray: Ray object with origin and direction.
        density_grid: Scalar field providing density at any 3D point.
        scatter_color: RGB vector for particle albedo.
        transparency_color: RGB vector for normalized mean free path (0-1).
        depth: Scalar multiplier for physical distance in cm.
        anisotropy_mode: String, 'henyey_greenstein' or 'jendersie_deon'.
        
    Returns:
        accumulated_radiance: RGB vector of scattered light.
        transmittance: RGB vector of light surviving to the end of the segment.
    """
    accumulated_radiance = vec3(0.0)
    transmittance = vec3(1.0)
    
    # Define step size for ray marching. Not given in sources.
    step_size = 0.1 
    
    # Define traversal bounds. Not given in sources.
    t_min, t_max = ray.volume_bounds()
    
    t = t_min
    while t < t_max:
        # Sample density at current ray position
        pos = ray.origin + ray.direction * t
        density = density_grid.sample(pos)
        
        # Calculate physical extinction coefficient from transparency color and depth
        # Mean free path = transparency_color * depth
        # Extinction coefficient = 1 / mean_free_path
        mean_free_path = transparency_color * depth
        # Guard against division by zero if transparency is 0
        mean_free_path = max(mean_free_path, 1e-6)
        extinction_coeff = 1.0 / mean_free_path
        
        # Optical depth for this step
        # Not given in sources: exact integration method (e.g., midpoint, trapezoidal)
        optical_depth = density * extinction_coeff * step_size
        
        # Update transmittance (Beer-Lambert law)
        # T = exp(-optical_depth)
        transmittance *= exp(-optical_depth)
        
        # Calculate scattering contribution
        # Light available to scatter is the incoming light * transmittance so far
        # Not given in sources: source illumination calculation
        incoming_light = get_scene_radiance(pos, ray.direction)
        
        # Phase function based on anisotropy
        # Not given in sources: specific implementation of Henyey-Greenstein or Jendersie-d'Eon
        phase = compute_phase_function(anisotropy_mode, ray.direction, incoming_light.direction)
        
        # Scattered radiance contribution
        # Not given in sources: exact integration of scattering term
        scatter_contribution = incoming_light * scatter_color * phase * density * step_size
        
        accumulated_radiance += scatter_contribution * transmittance
        
        t += step_size
        
    return accumulated_radiance, transmittance
```

**Edge Cases and Pitfalls**
*   **Wavelength Exhaustion:** Because different wavelengths are absorbed at different rates, light traveling far enough through the medium becomes tinted with the opposite of the Transparency Color once other wavelengths are exhausted [S1, unofficial][S2].
*   **Multiple Scattering Cost:** Simulating multiple bounces (multiple scattering) is significantly more expensive than single scattering, which may suffice for thin media like haze [S1, unofficial].
*   **Scene Scale Awareness:** The Depth parameter must be aware of scene scale to correctly convert normalized 0-1 values into physical centimeters [S1, unofficial][S2].

## Operating characteristics
*   **Complexity:** Time complexity is proportional to the number of ray-march steps and the cost of phase function evaluation. Multiple scattering increases complexity significantly [S1, unofficial].
*   **Memory:** Requires storage for the scalar density grid [S1, unofficial][S2].
*   **Strengths:** Artist-friendly parameterization (Scatter Color, Transparency Color, Depth) allows for intuitive control over volume appearance [S1, unofficial][S2]. Supports heterogeneous media with voxel-based density variations [S1, unofficial][S2].
*   **Limitations:** Computationally expensive due to ray marching and potential multiple scattering [S1, unofficial]. Requires a density grid input [S1, unofficial][S2].
*   **When to Use:** For simulating smoke, fog, clouds, and other non-polygonal participating media where density varies spatially [S1, unofficial][S2].
*   **When Not to Use:** For uniform, bounded subsurface scattering effects like skin or wax, where the standard Subsurface Scattering model is more appropriate [S1, unofficial][S2].

## Background
The Standard Volume Shader is internally related to the Random Walk Subsurface Scattering model used in Redshift’s OpenPBR and Standard Surface materials [S1, unofficial][S2]. While subsurface scattering simulates light in finite, uniform media like skin or wax, the Volume Shader adapts this random walk approach to heterogeneous media with voxel-varying density [S1, unofficial][S2]. The parameter mapping is nearly one-to-one with subsurface scattering: Subsurface Color maps to Scatter Color, Subsurface Radius maps to Transparency Color, and Subsurface Scale maps to Depth [S1, unofficial][S2]. It is used in Redshift renderer for creating effects like flames, fog, smoke, and clouds [S1, unofficial][S2].
