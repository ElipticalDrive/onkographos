# Extinction Falloff

Also called: Extinction Falloff Value

## Overview
Extinction Falloff is a rendering shortcut that approximates the visual contribution of hundreds of additional scattering bounces by gently reducing the extinction coefficient with each real bounce [S1, unofficial][S2]. It allows scenes to achieve brighter, more realistic volumetric lighting (such as internal light spill in fire or smoke) while rendering faster than equivalent scenes without the technique, avoiding the need to increase trace depth [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Input:** The current extinction coefficient of the medium, the current scattering bounce count, and the Extinction Falloff Value parameter [G].
*   **Output:** The modified extinction coefficient used for transmittance calculation at the current segment [G].

**Data Structures:**
The method operates on scalar values associated with the ray's current state and requires no complex data structures [G].

**Parameters:**
*   **Extinction Falloff Value:** A scalar parameter controlling the rate of extinction reduction. The default value is 0.2, described as a deliberate sweet spot [S1, unofficial][S2].

**Method Steps:**
1.  Retrieve the base extinction coefficient for the current medium segment [G].
2.  Determine the current scattering bounce count for the ray [G].
3.  Apply a reduction to the extinction coefficient based on the bounce count and the Extinction Falloff Value parameter [S1, unofficial][S2].
4.  Use the modified extinction coefficient to calculate segment transmittance [G].
5.  Proceed to the next scattering event or ray termination [G].

**Formulas:**
The sources describe the mechanism as a gentle reduction of extinction per bounce but do not provide an explicit mathematical formula [S1, unofficial][S2]. Implementers typically apply a multiplicative decay factor to the base extinction coefficient that scales with the bounce count and the falloff parameter [G].

**Edge Cases and Pitfalls:**
Not given in the sources. Standard ray marching implementations should clamp the modified extinction coefficient to non-negative values to prevent numerical instability [G].

**Pseudocode:**
```python
def calculate_effective_extinction(base_extinction: float, bounce_count: int, falloff_value: float) -> float:
    """
    Calculates the effective extinction coefficient for a given bounce.
    
    Args:
        base_extinction: The medium's original extinction coefficient.
        bounce_count: The current scattering bounce number (1-based).
        falloff_value: The Extinction Falloff Value parameter (default 0.2).
        
    Returns:
        float: The reduced extinction coefficient for this bounce.
    """
    if base_extinction <= 0.0:
        return base_extinction
        
    # The sources describe the mechanism as a gentle reduction of extinction per bounce 
    # but do not provide an explicit mathematical formula [S1, unofficial][S2].
    # A standard geometric decay model consistent with the described behavior is applied below.
    reduction_factor = (1.0 - falloff_value) ** (bounce_count - 1)
    effective_extinction = base_extinction * reduction_factor
    
    return max(effective_extinction, 0.0)
```

## Subtopics

### Anisotropy Falloff
A companion shortcut that lowers the anisotropy parameter with every bounce to mimic van de Hulst’s similarity principle, making deeper rays scatter more isotropically. See [Anisotropy Falloff](4021-anisotropy-falloff.md).

## Operating characteristics
*   **Time Complexity:** Not given in the sources. The technique reduces overall rendering time by allowing the path tracer to terminate earlier while maintaining visual fidelity [S1, unofficial][S2].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** In Redshift's cloud test, using the default value of 0.2 produced a brighter, more realistic result while rendering faster than the same scene without it [S1, unofficial][S2].
*   **Strengths:** Efficiently approximates multiple scattering effects without the computational cost of tracing hundreds of bounces [S1, unofficial][S2].
*   **Limitations:** It is an approximation that mimics the visual result of multiple bounces rather than physically simulating the exact radiative transfer [S1, unofficial][S2].
*   **When to Use:** When rendering participating media with significant multiple scattering (e.g., clouds, smoke, fire) and performance is a concern [S1, unofficial][S2].
*   **When Not to Use:** When strict physical accuracy is required over speed, or when the scene does not benefit from multiple scattering approximation [G].

## Background
Extinction Falloff is a feature introduced in the Redshift Renderer by Maxon [S1, unofficial][S2]. It is part of a suite of shortcuts designed for experienced artists to achieve realistic volumetric results without excessive trace depths [S1, unofficial][S2]. The technique operates alongside Anisotropy Falloff, which draws inspiration from van de Hulst’s similarity principle in radiative transfer [S1, unofficial][S2].
