# Emission-Absorption Ray Marching

Also called: Absorption plus Emission Volume Rendering, Direct Volume Rendering (Emission plus Absorption), Discrete Direct Volume Rendering, EAM Render, EmissionAbsorption, General optical model, Participating medium rendering

## Overview
Emission-Absorption Ray Marching is a deterministic method for rendering participating media where particles both occlude incoming light (absorption) and add their own glow (emission) [S4]. It solves the volume rendering equation by integrating the combined differential equation along a ray, discretizing the solution into a back-to-front compositing loop [S5]. Unlike the [Absorption-only model](839-absorption-only-model.md) which only attenuates background light, or the [Emission-only Model](1016-emission-only-model.md) which lacks attenuation bounds, this model provides a physically bounded intensity result suitable for simulating clouds, flames, and segmented medical data [S4, S5].

## How it works
**Inputs:** Ray origin $O$, ray direction $\vec{d}$, volume bounds, step size $uStepSize$, maximum steps $maxSteps$, extinction coefficient $uExtinction$, and emission source function $g(s)$ [S1, unofficial][S5].
**Outputs:** Final color $C_{out}$ and opacity $\alpha_{out}$ (typically $\alpha_{out}=1$ for opaque compositing) [S1, unofficial].

**Data Structures:**
The method maintains an accumulator state, typically a 4-component vector (RGBA) [S1, unofficial].
- `accumulator`: `vec4` initialized to `(0.0, 0.0, 0.0, 0.0)` [S1, unofficial].
- `rayPosition`: `vec3` tracking current sample location [S1, unofficial].
- `t`: `float` normalized distance along the ray [S1, unofficial].

**Parameters:**
- `uStepSize`: Step length for ray marching. Default 0.5 [S1, S2, unofficial].
- `max_steps`: Maximum iterations per ray. Default 2000 [S2, unofficial].
- `uExtinction`: Extinction coefficient, often scaled by 100.0 in implementation [S1, unofficial].
- `g(s)`: Source term (emission), which can be an arbitrary function of position or derived from a transfer function [S4, S5].

**Formulas:**
The continuous optical model is governed by the differential equation [S5]:
$$ \frac{dI}{ds} = g(s) - \tau(s)I(s) $$
where $g(s)$ is the emission source term and $\tau(s)I(s)$ is the absorption term [S5]. The analytical solution for intensity $I(D)$ at distance $D$ is [S5]:
$$ I(D) = I_0 e^{-\int_0^D \tau(t) dt} + \int_0^D g(s) e^{-\int_s^D \tau(t) dt} ds $$
where $I_0$ is the background intensity at the ray origin [S5].

Discretizing this into $n$ samples along the ray, using the approximation $e^{-\int \tau dt} \approx \prod (1 - \alpha_i)$, yields the discrete implementation [S5]:
$$ I(D) = I_0 \prod_{i=1}^n (1 - \alpha_i) + \sum_{i=1}^n g_i \prod_{j=i+1}^n (1 - \alpha_j) $$
Here, the first term represents background light attenuated by the entire volume, and the second term represents emission from sample $i$ occluded by all subsequent samples $j$ (closer to the viewer) [S5].

**Algorithm Steps:**
1.  **Initialization:** Initialize `accumulator` to zero. Calculate `rayStepLength` based on distance and `uStepSize`. Initialize random offset `t` for jittering to reduce banding [S1, unofficial].
2.  **Loop:** Iterate while `t < 1.0` and `accumulator.a < threshold` (e.g., 0.98 or 0.99) [S1, unofficial].
3.  **Sampling:** Advance `rayPosition` by `rayStepLength`. Sample the volume density/value at `rayPosition` to determine local opacity $\alpha_i$ and emission $g_i$ (color) [S1, unofficial][S5].
4.  **Compositing (Back-to-Front):** Update the accumulator. Since the ray marches from near to far (viewer to volume), but the formula assumes back-to-front accumulation for efficiency, the standard implementation updates the accumulator as if compositing the current sample *over* the accumulated result so far [S1, unofficial][S5].
    -   Update RGB: `accumulator.rgb += (1.0 - accumulator.a) * color.rgb * value` [S1, unofficial].
    -   Update Alpha: `accumulator.a += (1.0 - accumulator.a) * value * uExtinction / 100.0` [S1, unofficial].
    -   *Note:* In this specific implementation style [S1, unofficial], `value` acts as the opacity contribution $\alpha_i$, and `color.rgb` acts as the emission $g_i$ scaled appropriately. The term `(1.0 - accumulator.a)` represents the transmittance of the already accumulated front layers [S1, unofficial].
5.  **Termination:** If `accumulator.a` exceeds the threshold, break early [S1, unofficial].
6.  **Finalization:** If `accumulator.a > 1.0`, normalize RGB by Alpha to premultiply [S1, unofficial]. Output `vec4(accumulator.rgb, 1.0)` [S1, unofficial].

**Pseudocode:**
```python
def emission_absorption_ray_march(ray_origin, ray_direction, volume_sampler, step_size=0.5, max_steps=2000, extinction_coeff=1.0):
    """
    Renders a ray using the emission-absorption optical model.
    volume_sampler: Function that returns (color, opacity) at a given 3D position.
    """
    accumulator_color = vec3(0.0, 0.0, 0.0)
    accumulator_alpha = 0.0
    
    # Calculate step length
    # In a real implementation, distance to volume bounds is calculated here.
    # For this generic pseudocode, we assume a normalized ray parameter t from 0 to 1.
    step_length = step_size 
    
    # Random offset for jittering
    t = random() * step_length * 1.5
    t = clamp(t, 0.0, 1.0)
    
    # Pre-calculate inverse extinction factor if needed, 
    # but here we use the direct alpha update formula from [S1, unofficial]
    # Note: uExtinction / 100.0 in [S1, unofficial] implies the input 'value' might be scaled differently.
    # We assume 'value' returned by sampler is in [0,1] opacity range.
    
    for _ in range(max_steps):
        if t >= 1.0:
            break
            
        # Advance ray
        current_pos = ray_origin + ray_direction * t
        
        # Sample volume
        # Returns: sample_color (emission g_i), sample_alpha (opacity alpha_i)
        sample_color, sample_alpha = volume_sampler(current_pos)
        
        # Back-to-front compositing update
        # Transmittance of the current sample is (1 - sample_alpha)
        # The contribution of the current sample to the final color is:
        # (1 - accumulated_alpha) * sample_color * sample_alpha
        
        # Update Color
        accumulator_color += (1.0 - accumulator_alpha) * sample_color * sample_alpha
        
        # Update Alpha
        accumulator_alpha += (1.0 - accumulator_alpha) * sample_alpha
        
        # Early termination if fully opaque
        if accumulator_alpha >= 0.99:
            break
            
        t += step_length
        
    # Normalize if alpha exceeded 1.0 due to precision or scaling
    if accumulator_alpha > 1.0:
        accumulator_color /= accumulator_alpha
        
    return vec4(accumulator_color, 1.0)
```

## Subtopics

### [Volumetric Liquid Rendering](4017-volumetric-liquid-rendering.md)
Specialized application of emission-absorption for liquids, handling specific refraction and internal reflection properties not covered in the basic model.

### Emission-only Volume Rendering
A variant where absorption is neglected ($\tau(s) \approx 0$). It integrates only the source term $g(s)$. It is computationally simpler but suffers from unbounded intensity accumulation, potentially exceeding display ranges [S4].

### [Absorption-only Model](839-absorption-only-model.md)
Neglects emission ($g(s) = 0$). Only attenuates background light.

### [Emission-only Model](1016-emission-only-model.md)
Neglects absorption.

### Emission-only Volume Rendering
A volume rendering technique where the medium adds light to the ray by emission but neglects absorption, modeling transparent glowing particles [S4]. The differential equation simplifies to $dI/ds = g(s)$ [S4]. It can be computed rapidly using Fourier projection slice theorem and FFTs [S4]. **Pitfall:** Accumulated intensity has no upper bound because there is no attenuation; it can easily exceed the representable range of the output device [S4].

## Operating characteristics
**Time Complexity:** $O(N)$ per pixel, where $N$ is the number of steps along the ray [S5].
**Memory Complexity:** $O(1)$ per ray for the accumulator state, plus storage for the volume data [S1, unofficial].
**Performance:** Back-to-front compositing is preferred over front-to-back because it allows early ray termination when opacity reaches 1.0, improving efficiency [S5]. The method is deterministic [S2, unofficial].
**Strengths:** Physically plausible for media that both glow and block light (e.g., clouds, fire); bounded intensity due to absorption [S4].
**Limitations:** Requires sampling the volume along the ray, which can be expensive for high-resolution volumes; sensitive to step size (aliasing if too large, slow if too small) [S1, S2, unofficial].

## Background
The emission-absorption model is derived from the general volume rendering equation, specifically the case where scattering is neglected [S4]. It was formalized in the context of direct volume rendering by Max [S4], who described the differential equation $dI/ds = g(s) - \tau(s)I(s)$ and its integrating factor solution. The discrete implementation using back-to-front compositing and the product of transparencies is a standard approximation in computer graphics for direct volume rendering [S5]. It is widely used in medical visualization and scientific visualization for segmented data [S4].
