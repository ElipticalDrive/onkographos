# X-ray simulation via ray integration

Also called: CT projection rendering, Digitally Reconstructed Radiograph, Simulated radiography, X-Ray Rendering

## Overview
X-ray simulation via ray integration generates a Digitally Reconstructed Radiograph (DR) by integrating the linear attenuation coefficient along viewing rays from a source to a film plane, producing an X-ray-like projection image [S2, unofficial]. Unlike standard direct volume rendering which maps scalar values to opacity for compositing, this method assumes a single energy level with no scatter, no beam hardening, and no detector response, relying strictly on the Beer-Lambert law to simulate physical attenuation [S2, unofficial]. It is distinguished from its siblings by using actual Hounsfield Unit (HU) values directly in the attenuation calculation rather than arbitrary opacity mappings [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A volume dataset where the scalar field $f$ represents X-ray absorption density reconstructed by Computed Tomography (i.e., Hounsfield Units) [S2, unofficial].
*   **Input:** Camera parameters defining the source position $s=0$ and the film plane orientation [S3, unofficial].
*   **Input:** Exposure control, which acts as a combined multiplier for tube output and detector gain [S2, unofficial].
*   **Output:** A 2D simulated radiograph image [S2, unofficial].

**Data Structures:**
*   **Volume:** A 3D grid of floating-point values representing HU [S2, unofficial].
*   **Ray:** Defined by origin (source) and direction vector [S3, unofficial].
*   **Step Size:** A uniform constant `uMmPerLangkah` representing the integration step size in millimeters [S2, unofficial].

**Formulas:**
1.  **Linear Attenuation Coefficient ($\mu$):**
    Derived from the Hounsfield scale definition:
    $$ \mu = \mu_{water} \times \left(1 + \frac{HU}{1000}\right) $$
    Where $\mu_{water} = 0.0193 \, \text{mm}^{-1}$ at approximately 70 keV [S2, unofficial].

2.  **Attenuation Integral:**
    The optical depth $\tau$ along a ray is the integral of $\mu$ over the path length $l$:
    $$ \tau = \int_{0}^{L} \mu(\mathbf{r}(l)) \, dl \approx \sum_{i} \mu_i \cdot \Delta l $$
    Where $\Delta l$ is the step size in millimeters (`uMmPerLangkah`) [S3, unofficial].

3.  **Image Intensity ($I$):**
    Using the Beer-Lambert law:
    $$ I = I_0 \cdot \text{Exposure} \cdot \exp(-\tau) $$
    Where $I_0$ is the initial intensity (normalized to 1) and Exposure is the scalar control [S2, unofficial].

**Parameters:**
*   **$\mu_{water}$:** $0.0193 \, \text{mm}^{-1}$ [S2, unofficial].
*   **Exposure:** A scalar multiplier. It is NOT a dose in milligrays; no dose is computed [S2, unofficial].
*   **Step Size:** Must be in millimeters. The multiplication by `uMmPerLangkah` is critical; removing it breaks the physics even if the uniform variable exists [S2, unofficial].

**Pitfalls and Edge Cases:**
*   **Step Size Integration:** The integral must explicitly multiply the attenuation coefficient by the millimeter step size. A common implementation error is declaring the step size uniform but failing to use it in the summation, which causes incorrect attenuation values [S2, unofficial].
*   **Irrelevant Controls:** Threshold controls and opacity-per-step sliders are irrelevant and should be hidden. Thresholds do not apply to attenuation-based calculation, and opacity-per-step is a volume-compositing factor not used in this single-pass integration [S2, unofficial].
*   **Physical Assumptions:** The method assumes single energy. It does not account for scatter, beam hardening, or detector response characteristics [S2, unofficial].

**Pseudocode:**
```python
import math

def simulate_xray_projection(volume, camera, exposure, mu_water=0.0193, step_size_mm=0.5):
    """
    Simulates a radiograph by integrating attenuation along rays.
    
    Args:
        volume: 3D array of Hounsfield Units (HU) with .bounds and .sample(point) methods.
        camera: Object with 'ray_for_pixel(u, v)' returning (origin, direction).
        exposure: Scalar multiplier for tube output and detector gain.
        mu_water: Linear attenuation coefficient of water in mm^-1.
        step_size_mm: Integration step size in millimeters.
        
    Returns:
        2D image array.
    """
    height, width = camera.image_size
    image = [[0.0] * width for _ in range(height)]
    vol_min, vol_max = volume.bounds
    
    for y in range(height):
        for x in range(width):
            origin, direction = camera.ray_for_pixel(x, y)
            
            # Normalize direction to ensure step_size_mm applies correctly along the ray
            dir_len = math.sqrt(direction[0]**2 + direction[1]**2 + direction[2]**2)
            if dir_len > 0:
                direction = (direction[0]/dir_len, direction[1]/dir_len, direction[2]/dir_len)
            
            t = 0.0
            integral_mu_dl = 0.0
            
            # Traverse until ray exits volume bounds
            while True:
                point = (origin[0] + direction[0]*t, 
                         origin[1] + direction[1]*t, 
                         origin[2] + direction[2]*t)
                
                if not (vol_min[0] <= point[0] <= vol_max[0] and
                        vol_min[1] <= point[1] <= vol_max[1] and
                        vol_min[2] <= point[2] <= vol_max[2]):
                    break
                
                hu = volume.sample(point)
                mu = mu_water * (1.0 + hu / 1000.0)
                integral_mu_dl += mu * step_size_mm
                t += step_size_mm
            
            intensity = exposure * math.exp(-integral_mu_dl)
            image[y][x] = intensity
            
    return image
```

## Subtopics

### [Hardware-Accelerated Simulated Radiography (Non-Emissive)](10237-hardware-accelerated-simulated-radiography-non-emissive.md)
A GPU-based technique that renders geometric cells (hexahedra or tetrahedra) as separate layers using hardware rasterization to accumulate attenuation in a P-buffer. It handles unsorted, overlapping geometry by iteratively rendering non-overlapping subsets, minimizing expensive synchronization copies compared to sorted front-to-back methods.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Measured on a synthetic 700 HU sphere at 390x844 resolution, the method produces monotonic intensity changes with exposure (e.g., exposure x0.4 yields mean 7.7, x1 yields 14.6, x3 yields 22.2) [S2, unofficial].
*   **Strengths:** Physically accurate projection based on actual HU values; simple implementation; no need for complex transfer function tuning [S2, unofficial].
*   **Limitations:** Assumes single energy; ignores scatter and beam hardening; does not model detector response [S2, unofficial].
*   **When to use:** When generating standard X-ray projections from CT data for comparison with real radiographs or for basic visualization [S2, unofficial].
*   **When not to use:** When high-fidelity spectral effects, scatter, or detector physics are required [S2, unofficial].

## Background
The method originates from the application of optical models for direct volume rendering, specifically the absorption-only model where the transfer function is set to the identity function for X-ray absorption density [S3, unofficial]. It integrates attenuation along viewing rays from arbitrary directions, using the identity transfer function for X-ray absorption density reconstructed by Computed Tomography [S3, unofficial]. The specific implementation details, including the use of `mu_water = 0.0193 /mm` at ~70 keV and the handling of exposure as a combined tube/detector gain factor, are documented in recent software development efforts for DICOM volume rendering [S2, unofficial].
