# ShadedVolumeStyle


## Overview
ShadedVolumeStyle is a rendering style node that calculates and applies lighting effects to the visual output of a volume [S1, unofficial]. It operates within an emission-absorption model using a single scattering approximation [S1, unofficial]. It is distinct from its siblings in that it is implemented as a composable style node (often within a `ComposedVolumeStyle`), allowing it to be easily combined with other styles such as `OpacityMapVolumeStyle` or `BoundaryEnhancementVolumeStyle` in a single rendering pass [S1, unofficial].

## How it works
**Inputs and Outputs:**
The method takes a scalar volume field $V$ and a material definition as input. It outputs a shaded color $\mathbf{c}$ and opacity $\alpha$ for each sample point, which are then used in the front-to-back compositing equation defined in [Direct volume ray casting](19-direct-volume-ray-casting.md).

**Data Structures:**
The style is defined by the following fields [S1, unofficial]:
*   `enabled` (SFBool): Defines whether the style is currently applied.
*   `lighting` (SFBool): Controls whether lighting effects are calculated. When `TRUE`, color and opacity are determined based on the `material` field.
*   `material`: Defines the optical properties (color, opacity) used when lighting is active.
*   `shadows` (SFBool, not implemented): Would control attenuation of light from sources.
*   `phaseFunction` (SFNode, not implemented): Would control angle-dependency of scattering.

**Algorithm:**
1.  **Check Enablement:** If `enabled` is `FALSE`, the style is skipped.
2.  **Check Lighting:** If `lighting` is `FALSE`, the style passes through base color/opacity without modification.
3.  **Normal Estimation:** Estimate the surface normal $\mathbf{n}_i$ at the sample point $\mathbf{p}_i$ by normalizing the gradient of the scalar field $\nabla V(\mathbf{p}_i)$ [G]. The gradient is estimated using finite differences [G]:
    $$ \nabla V(\mathbf{p}_i) \approx \left( \frac{V(\mathbf{p}_i + \Delta x) - V(\mathbf{p}_i - \Delta x)}{2\Delta x}, \frac{V(\mathbf{p}_i + \Delta y) - V(\mathbf{p}_i - \Delta y)}{2\Delta y}, \frac{V(\mathbf{p}_i + \Delta z) - V(\mathbf{p}_i - \Delta z)}{2\Delta z} \right) $$
    The implementation supports different algorithms for this step, specified in `NormalVolumeSettings`:
    *   `precomputedCentralDifferences`: Pre-computed, fastest execution [S1, unofficial].
    *   `onlineCentralDifferences`: Computed on the fly, usually most appropriate [S1, unofficial].
    *   `onlineSobel`: Computed on the fly, produces "nicest" results [S1, unofficial].
4.  **Lighting Calculation:** Compute the lighting term $L(\mathbf{p}_i)$ using a Phong illumination model [G]. This requires the view vector $\mathbf{v}$ and light vector $\mathbf{l}$ [G].
    $$ L(\mathbf{p}_i) = k_a + k_d (\mathbf{n}_i \cdot \mathbf{l}) + k_s (\mathbf{r}_i \cdot \mathbf{v})^n $$
    Where $\mathbf{r}_i = 2(\mathbf{n}_i \cdot \mathbf{l})\mathbf{n}_i - \mathbf{l}$ is the reflection vector [G].
5.  **Color Application:** Apply the lighting to the base color $\mathbf{c}_{base}$ derived from the material [S1, unofficial]:
    $$ \mathbf{c}_{final} = \mathbf{c}_{base} \cdot L(\mathbf{p}_i) $$
    The opacity $\alpha$ is derived solely from the opacity transfer function and is generally not modified by the shading model [G].
6.  **Compositing:** Accumulate $\mathbf{c}_{final}$ and $\alpha$ using the front-to-back alpha compositing equation [G].

**Pitfalls:**
*   **Missing Features:** The fields `shadows` and `phaseFunction` are not yet implemented [S1, unofficial]. Consequently, the method does not account for light attenuation from sources or angle-dependent scattering in participating media.
*   **Gradient Artifacts:** The quality of shading depends heavily on the gradient estimation algorithm. `onlineCentralDifferences` may be noisy compared to `onlineSobel` but faster than pre-computed methods if memory is constrained [S1, unofficial].

## Subtopics

### Cool/Warm Shading
An illumination model where orientation with respect to the light direction is encoded by warm or cool colors, representing orientation using (almost) isoluminant colors [S2]. The advantage over Phong shading is that brightness can still be used to visualize another attribute or property (such as depth via color-based depth cueing/fogging) since orientation is represented by isoluminant colors [S2].

## Operating characteristics
**Time and Memory Complexity:**
The complexity depends on the chosen normal estimation algorithm. `precomputedCentralDifferences` requires $O(N)$ memory for the pre-computed gradient field but $O(1)$ per sample for shading. `onlineCentralDifferences` and `onlineSobel` require $O(1)$ memory but $O(1)$ per sample for gradient calculation, with `onlineSobel` having a higher constant factor due to the larger kernel [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Easily composable with other styles; allows separation of orientation cues (via color) from intensity cues (via brightness) in cool/warm variants [S2].
*   **Limitations:** Lacks shadowing and phase function support, limiting physical accuracy [S1, unofficial].

**When to use:**
Use when visual clarity of surface orientation is required and the rendering environment supports composable style nodes. Avoid when physically accurate shadows or complex scattering are needed.

## Background
ShadedVolumeStyle is part of the InstantReality 1.0 volume rendering framework [S1, unofficial]. The underlying concept of shading volumes to improve perception of structure dates back to early volume rendering research, with Phong shading being a standard technique [G]. Cool/warm shading was introduced as an alternative to intensity-based shading to preserve brightness for other attributes [S2].
