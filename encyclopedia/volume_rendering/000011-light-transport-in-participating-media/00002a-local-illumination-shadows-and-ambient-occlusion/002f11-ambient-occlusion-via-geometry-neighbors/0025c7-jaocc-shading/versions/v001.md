# JAOCC Shading

Also called: Jaocc Occlusion

## Overview
JAOCC Shading is a voxel-based ambient occlusion technique that computes local illumination by analyzing the occupancy of a cubic neighborhood around each voxel [S3, unofficial]. It addresses the visual artifacts inherent in standard axis-aligned bounding box (AABB) voxel rendering, where fixed face normals cause hard, physically implausible lighting transitions (e.g., rays hitting a face perpendicularly appearing dark while grazing rays appear bright) [S1, unofficial]. By dynamically estimating surface orientation from neighbor occupancy and applying a depth-weighted dimming factor, it produces smoother shading results, particularly for higher neighbor counts [S1, S3, unofficial].

## How it works

### Inputs and Outputs
*   **Input:** A 3D voxel grid of size $X \times Y \times Z$. Each voxel contains an occupancy bit (empty/non-empty) and an RGB color value.
*   **Parameters:**
    *   `count`: The radius of the cubic neighborhood to sample (integer). Determines the sampling box size from $-count$ to $+count$ [S3, unofficial].
    *   `depth`: A float parameter controlling occlusion intensity, typically in $[0.01, 1.0]$. Values closer to 1 produce harder, more contrasty shading [S3, unofficial].
*   **Output:** The same voxel grid with updated RGB values, where each voxel's color is multiplied by a computed occlusion factor [S3, unofficial].

### Data Structures
The voxel grid is stored as a 1D array or 3D array indexed by $(x, y, z)$.
*   **Occupancy:** A boolean or integer flag indicating if the voxel is non-empty.
*   **Color:** Three components (R, G, B), typically 8-bit integers $[0, 255]$ or floats $[0, 1]$.

### Algorithm Steps

1.  **Precompute Normalization Factor (`max_dim`):**
    Calculate the maximum possible weighted neighbor count for a given `count`. This is used to normalize the occlusion dimension.
    Iterate $xn$ from $-count$ to $count$, $yn$ from $-count$ to $count$, and $zn$ from $-count$ to $count$.
    For each triplet $(xn, yn, zn)$:
    *   If $yn > 0$, add $1$ to the sum.
    *   If $yn < 0$, subtract $1$ from the sum.
    *   Always add $1$ to the sum.
    *   Sum these values into `max_dim` [S3, unofficial].

2.  **Iterate Over Voxels:**
    Loop through the voxel grid. To avoid boundary checks, iterate $x$ from $count$ to $X - count - 1$, $y$ from $count$ to $Y - count - 1$, and $z$ from $count$ to $Z - count - 1$ [S3, unofficial].
    *   Skip voxels that are empty (occupancy is false) [S3, unofficial].

3.  **Compute Occlusion Dimension (`dim`):**
    Initialize `dim` to $0$.
    Iterate $xn$ from $-count$ to $count$, $yn$ from $-count$ to $count$, and $zn$ from $-count$ to $count$.
    For each neighbor at $(x+xn, y+yn, z+zn)$:
    *   If the neighbor is **not empty**:
        *   Calculate $yk1 = 1$ if $yn > 0$ else $0$.
        *   Calculate $yk2 = 1$ if $yn < 0$ else $0$.
        *   Add $(1 + yk1 - yk2)$ to `dim` [S3, unofficial].

4.  **Calculate Shading Factor (`dim_factor`):**
    Normalize `dim` by `max_dim` and apply the `depth` parameter [S3, unofficial]:
    $$
    \text{dim\_factor} = \text{clamp}\left( \left( \text{clamp}\left(\frac{\text{dim}}{\text{max\_dim}}, 0, 1\right) \right) \times \text{depth} + (1 - \text{depth}), 0, 1 \right)
    $$
    *Note: The source formula implies a linear interpolation between full brightness ($1$) and full occlusion ($0$) based on the normalized density, weighted by `depth` [S3, unofficial].*

5.  **Apply Shading:**
    Multiply the voxel's RGB components by `dim_factor`.
    Clamp the resulting RGB values to the valid range (e.g., $[0, 255]$ for 8-bit) [S3, unofficial].

### Pseudocode

```python
def jaocc_shade(voxel_grid, count, depth):
    """
    voxel_grid: 3D array of shape (X, Y, Z)
    Each element is a tuple (occupied: bool, r: int, g: int, b: int)
    count: int, neighborhood radius
    depth: float, occlusion intensity [0.01, 1.0]
    """
    X, Y, Z = voxel_grid.shape
    
    # Step 1: Precompute max_dim
    max_dim = 0
    for xn in range(-count, count + 1):
        for yn in range(-count, count + 1):
            for zn in range(-count, count + 1):
                term = 1
                if yn > 0:
                    term += 1
                if yn < 0:
                    term -= 1
                max_dim += term
                
    # Handle edge case where max_dim might be 0 if count=0, though count>=1 typically
    if max_dim == 0:
        max_dim = 1 

    # Step 2: Iterate and compute
    for x in range(count, X - count):
        for y in range(count, Y - count):
            for z in range(count, Z - count):
                
                # Skip empty voxels
                if not voxel_grid[x, y, z][0]:
                    continue
                
                # Step 3: Compute dim
                dim = 0
                for xn in range(-count, count + 1):
                    for yn in range(-count, count + 1):
                        for zn in range(-count, count + 1):
                            # Check neighbor occupancy
                            # Note: In a real implementation, bounds checking is needed 
                            # if the loop ranges don't account for boundaries, 
                            # but here we iterate within safe bounds.
                            neighbor_occupied = voxel_grid[x + xn, y + yn, z + zn][0]
                            
                            if neighbor_occupied:
                                yk1 = 1 if yn > 0 else 0
                                yk2 = 1 if yn < 0 else 0
                                dim += (1 + yk1 - yk2)
                
                # Step 4: Calculate dim_factor
                # Clamp dim to [0, max_dim] before division
                dim_clamped = max(0, min(dim, max_dim))
                normalized_dim = dim_clamped / max_dim
                
                # Formula from [S3, unofficial]: clamp((clamp(dim, 0, max_dim) / max_dim) * depth + (1 - depth), 0, 1)
                raw_factor = (normalized_dim * depth) + (1 - depth)
                dim_factor = max(0.0, min(1.0, raw_factor))
                
                # Step 5: Apply shading
                r, g, b = voxel_grid[x, y, z][1], voxel_grid[x, y, z][2], voxel_grid[x, y, z][3]
                
                new_r = int(r * dim_factor)
                new_g = int(g * dim_factor)
                new_b = int(b * dim_factor)
                
                # Clamp to 8-bit range
                new_r = max(0, min(255, new_r))
                new_g = max(0, min(255, new_g))
                new_b = max(0, min(255, new_b))
                
                voxel_grid[x, y, z] = (True, new_r, new_g, new_b)
```

### Edge Cases and Pitfalls
*   **Thin Objects:** The algorithm produces errors with thin objects because the local neighborhood may not accurately represent the surface curvature or thickness, leading to incorrect occlusion estimates [S3, unofficial].
*   **Performance:** The method is computationally expensive due to the nested loops over the neighborhood for every voxel [S3, unofficial].
*   **Boundary Conditions:** The iteration range must exclude voxels within `count` distance of the grid boundaries to ensure all neighbors exist. If the grid is smaller than $2 \times count$, the algorithm cannot process any voxels [S3, unofficial].
*   **AABB Artifacts:** Without this method, fixed AABB normals cause hard lighting transitions where perpendicular rays appear dark and grazing rays appear bright [S1, unofficial]. JAOCC mitigates this by using neighbor-based weighting.

## Operating characteristics

*   **Time Complexity:** $O(N \cdot (2 \cdot count + 1)^3)$, where $N$ is the number of non-empty voxels in the interior of the grid. The cubic neighborhood size grows rapidly with `count`.
*   **Memory Complexity:** $O(1)$ auxiliary space if computed in-place, or $O(N)$ if a separate output grid is used. The input grid is modified in-place in the standard implementation [S3, unofficial].
*   **Measured Performance:** Not given in the sources. However, it is explicitly noted as "slow" [S3, unofficial].
*   **Strengths:** Produces smooth shading results for higher neighbor counts; avoids hard, physically implausible lighting edges associated with fixed AABB normals [S1, S3, unofficial].
*   **Limitations:** Slow performance; inaccurate results on thin geometry; requires a sufficiently large grid to avoid boundary issues [S3, unofficial].
*   **When to use:** When visual smoothness is prioritized over performance and the geometry is not excessively thin.
*   **When not to use:** For real-time applications on large grids with limited hardware, or for scenes with very thin structures where the neighborhood sampling fails to capture geometry accurately.

## Background

JAOCC Shading originates from voxel rendering techniques aimed at improving the visual quality of block-based environments. The specific algorithm is documented in the context of optimizing voxel lighting to overcome the limitations of simple AABB-based shading [S1, S3, unofficial]. It is implemented in open-source voxel engines and demos, such as those found in the `doommy` repository [S3, unofficial] and discussed in academic works on raycasting-based voxel rendering [S1, unofficial]. The technique is part of a broader family of local ambient occlusion methods for voxel data.
