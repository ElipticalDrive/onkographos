# JAOCC Shading

Also called: Jaocc Occlusion

## Overview
JAOCC Shading is a voxel-based ambient occlusion technique that computes a depth-weighted dimming factor by counting non-empty neighbors in a cubic neighborhood [S3, unofficial]. It solves the problem of hard, physically implausible lighting transitions at axis-aligned bounding box (AABB) edges by dynamically estimating surface normals from local voxel geometry rather than using fixed AABB face normals [S1, unofficial]. Unlike sibling methods that may rely on signed distance fields or screen-space heuristics, JAOCC operates directly on the voxel grid's occupancy status to produce smooth shading results, though it is computationally expensive and prone to errors on thin objects [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D voxel grid representing scene occupancy. Each voxel contains an RGB color value and an occupancy flag (empty/non-empty).
*   **Output:** A shaded voxel grid where the RGB color of each non-empty voxel is multiplied by an ambient occlusion factor.

**Data Structures:**
The voxel grid is stored as a 1D array or 3D array. The access pattern described in the source uses a specific indexing scheme for neighbors. Let the grid dimensions be $X_{size}, Y_{size}, Z_{size}$. The source code implies a layout where the fastest varying index is $y$ (or $z$ depending on interpretation, but the neighbor offsets clarify the relative positions). Based on the neighbor definitions in [S2, unofficial], the coordinates are treated as $(x, y, z)$.

**Parameters:**
*   `count`: The radius of the cubic neighborhood to sample (integer). The neighborhood spans from $-count$ to $+count$ in all dimensions. Higher values produce smoother results but increase computational cost [S3, unofficial].
*   `depth`: A float parameter controlling the intensity of the occlusion effect, typically in the range $[0.01, 1.0]$. Values closer to 1.0 produce the "hardest" (most contrasty) shading [S3, unofficial].

**Algorithm Steps:**

1.  **Iterate Voxels:** Loop through all voxels in the grid. To avoid boundary checks, the loop ranges are typically restricted to $x \in [count, X_{size}-count-1]$, $y \in [count, Y_{size}-count-1]$, and $z \in [count, Z_{size}-count-1]$. Skip voxels that are empty [S3, unofficial].

2.  **Compute Max Dimension ($max\_dim$):**
    Calculate the maximum possible neighbor count used for normalization. This represents the occlusion value if all neighbors in the neighborhood were non-empty.
    Iterate $xn$ from $-count$ to $count$, $yn$ from $-count$ to $count$, $zn$ from $-count$ to $count$.
    For each neighbor, calculate a weight $w$:
    $$ w = 1 + y_{k1} - y_{k2} $$
    Where:
    $$ y_{k1} = \begin{cases} 1 & \text{if } yn > 0 \\ 0 & \text{otherwise} \end{cases} $$
    $$ y_{k2} = \begin{cases} 1 & \text{if } yn < 0 \\ 0 & \text{otherwise} \end{cases} $$
    Sum all $w$ values into $max\_dim$ [S3, unofficial].

3.  **Compute Occlusion Dimension ($dim$):**
    Initialize $dim = 0$.
    Iterate $xn$ from $-count$ to $count$, $yn$ from $-count$ to $count$, $zn$ from $-count$ to $count$.
    Check the occupancy status of the neighbor at $(x+xn, y+yn, z+zn)$.
    If the neighbor is **non-empty**:
    $$ dim = dim + (1 + y_{k1} - y_{k2}) $$
    Where $y_{k1}$ and $y_{k2}$ are defined as above based on the relative $yn$ coordinate [S3, unofficial].

    *Note on Neighbor Geometry:* The source [S2, unofficial] defines specific neighbor sets for X, Y, and Z planes to calculate AO tuples, but the core JAOCC algorithm described in [S3, unofficial] uses the cubic neighborhood summation described in steps 2 and 3. The "AO tuple" calculation in [S2, unofficial] appears to be a specific implementation detail for a different shading variant or a simplified 2D slice approximation, whereas the cubic summation is the general 3D method cited for JAOCC. The cubic method effectively weights neighbors based on their position relative to the Y-axis, simulating a normal estimation that favors horizontal surfaces [S1, unofficial][S3, unofficial].

4.  **Normalize and Apply Shading:**
    Calculate the normalized occlusion ratio:
    $$ ratio = \frac{clamp(dim, 0, max\_dim)}{max\_dim} $$
    Calculate the dimming factor ($dim\_factor$):
    $$ dim\_factor = clamp((1.0 - ratio) \times depth + (1 - depth), 0, 1) $$
    Multiply the voxel's RGB components by $dim\_factor$:
    $$ R_{new} = clamp(R_{old} \times dim\_factor, 0, 255) $$
    $$ G_{new} = clamp(G_{old} \times dim\_factor, 0, 255) $$
    $$ B_{new} = clamp(B_{old} \times dim\_factor, 0, 255) $$
    [S3, unofficial]

**Pseudocode:**

```python
def jaocc_shade(voxel_grid, x_size, y_size, z_size, count, depth):
    """
    voxel_grid: 3D array or flattened array with occupancy and color data.
    Assumes voxel_grid[x, y, z] returns a tuple (occupied: bool, r: int, g: int, b: int).
    """
    shaded_grid = empty_grid_of_same_size()
    
    # Pre-calculate max_dim
    max_dim = 0
    for xn in range(-count, count + 1):
        for yn in range(-count, count + 1):
            for zn in range(-count, count + 1):
                yk1 = 1 if yn > 0 else 0
                yk2 = 1 if yn < 0 else 0
                max_dim += (1 + yk1 - yk2)
                
    # Iterate over valid voxel range
    for x in range(count, x_size - count):
        for y in range(count, y_size - count):
            for z in range(count, z_size - count):
                
                # Get current voxel info
                occupied, r, g, b = voxel_grid[x, y, z]
                
                # Skip empty voxels
                if not occupied:
                    shaded_grid[x, y, z] = (False, 0, 0, 0)
                    continue
                
                # Calculate dim
                dim = 0
                for xn in range(-count, count + 1):
                    for yn in range(-count, count + 1):
                        for zn in range(-count, count + 1):
                            # Check bounds for neighbor access if grid is not padded
                            nx, ny, nz = x + xn, y + yn, z + zn
                            if 0 <= nx < x_size and 0 <= ny < y_size and 0 <= nz < z_size:
                                n_occupied, _, _, _ = voxel_grid[nx, ny, nz]
                                if n_occupied:
                                    yk1 = 1 if yn > 0 else 0
                                    yk2 = 1 if yn < 0 else 0
                                    dim += (1 + yk1 - yk2)
                            
                # Normalize and apply factor
                # Clamp dim to [0, max_dim]
                clamped_dim = max(0, min(dim, max_dim))
                ratio = clamped_dim / max_dim
                
                # Calculate dim_factor
                # Formula: clamp((1.0 - ratio) * depth + (1 - depth), 0, 1)
                raw_factor = (1.0 - ratio) * depth + (1.0 - depth)
                dim_factor = max(0.0, min(1.0, raw_factor))
                
                # Apply shading
                new_r = max(0, min(255, int(r * dim_factor)))
                new_g = max(0, min(255, int(g * dim_factor)))
                new_b = max(0, min(255, int(b * dim_factor)))
                
                shaded_grid[x, y, z] = (True, new_r, new_g, new_b)
                
    return shaded_grid
```

**Edge Cases and Pitfalls:**
*   **Thin Objects:** The algorithm produces errors with thin objects. Because it relies on local neighbor counts, thin structures may be incorrectly occluded or under-occluded [S3, unofficial].
*   **Boundary Conditions:** The loop ranges exclude the boundary voxels within `count` distance. These must be handled separately or the grid must be padded [S3, unofficial].
*   **Performance:** The algorithm is slow due to the nested loops over the neighborhood volume ($O(N \cdot (2 \cdot count + 1)^3)$) [S3, unofficial].

## Subtopics

### Compensation Map
A nonlinear rescaling technique applied to the computed AO to mitigate errors from artificial multiple occlusion. It addresses the issue where objects thinner than $\delta$ are in proximity closer than $\delta$, causing overdarkening of adjacent faces (similar to shadow artifacts passing through walls) [S4, unofficial]. The compensation map is encoded as a 1D luminance texture on the GPU and automatically clamps input AO to $[0, 1]$. The curve is fitted using AOV results from multiple viewpoints of reference scenes (Suburb and House) against ray-traced results. The right end of the curve is based on the intuition that a corner with three walls at a right angle has approximately 75% occlusion. Unlike the rest of the algorithm, this map has no physical basis and is an ad hoc solution for scenes violating the $\delta$-thickness assumption. The performance impact of the additional texture fetch is negligible [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(V \cdot (2 \cdot count + 1)^3)$, where $V$ is the number of non-empty voxels. The cubic neighborhood search makes it significantly slower than simple neighbor-counting methods.
*   **Memory Complexity:** $O(V)$ for the input and output grids. The compensation map requires a small 1D texture [S4, unofficial].
*   **Measured Performance:** Not given in the sources. However, [S3, unofficial] notes the algorithm is "slow," and [S4, unofficial] notes the compensation map's performance impact is "below threshold of measurement."
*   **Strengths:** Produces smooth results for higher neighbor counts; robust to tessellation and level of detail changes; avoids hard lighting transitions at AABB edges by using dynamic normals [S1, unofficial][S3, unofficial][S4, unofficial].
*   **Limitations:** Slow performance; errors with thin objects; artificial multiple occlusion in dense, thin structures without compensation [S3, unofficial][S4, unofficial].
*   **When to use:** When smooth, physically plausible shading is required for voxel landscapes and the performance cost is acceptable.
*   **When not to use:** For real-time applications with high voxel counts and limited CPU/GPU budget, or for scenes with many thin, closely spaced objects without the compensation map [S3, unofficial][S4, unofficial].

## Background
JAOCC Shading originates from voxel rendering research aimed at improving the visual quality of voxel-based environments. The core concept of using local neighborhood geometry to estimate normals for shading was identified as a solution to the "hard" and "physically implausible" lighting effects caused by fixed AABB normals in voxel landscapes [S1, unofficial]. The specific algorithmic details involving cubic neighborhood sampling and depth-weighted dimming are documented in community implementations and repositories [S3, unofficial]. The concept of Ambient Occlusion Volumes (AOV) and the compensation map for handling thin-object artifacts were introduced by McGuire in 2010 [S4, unofficial]. The method is used in voxel engine implementations and educational graphics projects [S2, unofficial][S3, unofficial].
