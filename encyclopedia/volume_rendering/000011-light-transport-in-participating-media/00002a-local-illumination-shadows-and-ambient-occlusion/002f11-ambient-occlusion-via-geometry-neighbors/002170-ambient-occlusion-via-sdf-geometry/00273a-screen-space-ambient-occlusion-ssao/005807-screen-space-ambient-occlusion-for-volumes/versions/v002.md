# Screen-Space Ambient Occlusion for Volumes

Also called: SSAO for volumes, Volume SSAO

## Overview
Screen-Space Ambient Occlusion for Volumes extends standard SSAO to volume rendering by extracting position and normal information from the raycasting algorithm to create an opacity isovalue layer [S1, unofficial]. This layer acts as a synthetic surface, allowing the SSAO pass to compute ambient occlusion for internal structures within a volume, thereby increasing depth perception [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Volume data, camera parameters, existing depth buffer, and volume rendering parameters including an opacity threshold and shading flag [S1, unofficial].
*   **Outputs:** Final color buffer with ambient occlusion applied to the volume's internal structures [S1, unofficial].

**Data Structures:**
*   **Position Texture:** Stores the 3D world position of the first sample along the ray that exceeds the opacity threshold [S1, unofficial].
*   **Normal Texture:** Stores the surface normal (computed via local gradient) for the same sample [S1, unofficial].
*   **Depth Texture:** Must be formatted as `Fixed32` to allow the GPU volume mapper to copy the existing depth texture successfully [S1, unofficial].

**Steps:**
1.  **Enable Shading:** Ensure the volume property has shading enabled to compute normals using local gradient values for each sample [S1, unofficial].
2.  **Raycasting with Position/Normal Extraction:** During the volume rendering raycast, compute the fragment position (current sample location) and normal (local gradient value) for each sample [S1, unofficial].
3.  **Threshold Check:** Check if the sample's opacity exceeds the `VolumeOpacityThreshold` [S1, unofficial].
4.  **First-Visible-Write Logic:** The first sample along the ray with opacity greater than the threshold writes its position and normal to the additional GPU textures; subsequent samples along the same ray do not override this information [S1, unofficial].
5.  **Isocontour Generation:** This process generates an opacity layer (isocontour) representing the surface of the volume at the specified opacity threshold [S1, unofficial].
6.  **SSAO Pass Execution:** The SSAO pass reads the position, normal, and depth textures generated in steps 2-4 and applies ambient occlusion as it would for a regular surface [S1, unofficial].
7.  **Compositing:** The calculated occlusion is applied to the rendered volume color, with textures managed at the pass level to ensure compatibility with mixed volume and surface rendering [S1, unofficial].

**Parameters:**
*   `VolumeOpacityThreshold`: Defines the opacity isovalue for the AO layer. Default is 0.9. Recommended value is the opacity of the first visible pixels at volume boundaries [S1, unofficial].
*   `Radius`: Comparison radius for SSAO sampling. Typical value: `0.1 * sceneSize` (where `sceneSize` is the diagonal of the bounding box) [S1, unofficial].
*   `Bias`: Comparison bias to prevent self-occlusion artifacts. Typical value: `0.001 * sceneSize` [S1, unofficial].
*   `KernelSize`: Number of samples used for SSAO. Typical value: 128 [S1, unofficial].
*   `DepthFormat`: Must be `Fixed32` [S1, unofficial].

**Pseudocode:**
```python
import math

def compute_volume_ssao(ray_origin, ray_direction, volume_bounds, volume_opacities, step_size, radius, bias, thresholds):
    """
    Computes SSAO factors for a volume raycast.
    ray_origin: tuple (x, y, z)
    ray_direction: tuple (dx, dy, dz)
    volume_bounds: tuple (min_x, min_y, min_z, max_x, max_y, max_z)
    volume_opacities: callable returning opacity at (x, y, z)
    step_size: float
    radius: float
    bias: float
    thresholds: list of float opacity thresholds
    Returns: list of AO factors in [0.0, 1.0]
    """
    ao_factors = []
    for opacity_threshold in thresholds:
        hit_distance = float('inf')
        t = 0.0
        # Step along the ray until bounds are exceeded or a hit is found
        while t < 1000.0:
            x = ray_origin[0] + ray_direction[0] * t
            y = ray_origin[1] + ray_direction[1] * t
            z = ray_origin[2] + ray_direction[2] * t
            
            # Boundary check
            if volume_bounds[0] <= x <= volume_bounds[3] and \
               volume_bounds[1] <= y <= volume_bounds[4] and \
               volume_bounds[2] <= z <= volume_bounds[5]:
                opacity = volume_opacities(x, y, z)
                if opacity > opacity_threshold:
                    hit_distance = t
                    break
            t += step_size
            
        # Compute AO factor based on first hit distance
        if hit_distance < float('inf'):
            effective_distance = max(0.0, hit_distance - bias)
            ao_factor = max(0.0, 1.0 - (effective_distance / radius))
        else:
            ao_factor = 1.0
        ao_factors.append(ao_factor)
    return ao_factors

# Setup example matching VTK pipeline
scene_size = math.sqrt((bounds[3]-bounds[0])**2 + (bounds[4]-bounds[1])**2 + (bounds[5]-bounds[2])**2)
ssao_pass = SSAOPass()
ssao_pass.SetRadius(0.1 * scene_size)
ssao_pass.SetBias(0.001 * scene_size)
ssao_pass.SetKernelSize(128)
ssao_pass.SetDepthFormat(TextureFormat.Fixed32)
ssao_pass.SetVolumeOpacityThreshold(0.95)
ssao_pass.BlurOn()
volume.GetProperty().ShadeOn()
```

**Edge Cases and Pitfalls:**
*   **Low Opacity Regions:** If the volume opacity is very low, the default SSAO application can make the image appear disturbingly opaque or dark [S2, unofficial].
*   **Depth Precision:** Using a depth format other than `Fixed32` may cause the GPU volume mapper to fail copying the depth texture, breaking the SSAO pass [S1, unofficial].
*   **Normal Computation:** Shading must be explicitly enabled; otherwise, normals are not computed, and SSAO cannot function correctly [S1, unofficial].

## Subtopics

### Fragment Opacity Premultiplied SSAO
A technique where the SSAO contribution is scaled down by the opacity value of the sample that writes to the depth buffer, reducing AO on transparent regions [S2, unofficial]. It is enabled via `vtkSSAOPass::VolumeOpacityPremultipliedOn()` [S2, unofficial]. This approach results in almost no SSAO being applied if the volume opacity is very low, which is considered a good improvement for enabling SSAO by default [S2, unofficial].

### SSAO Intensity Factor
A technique to reduce the amount of ambient occlusion applied to a volume rendering by multiplying the AO result by a constant intensity factor [S2, unofficial]. Typical values include 1.0 (full AO) and 0.5 (reduced AO) [S2, unofficial].

### Offset and Scale SSAO
A modification to the shading equation that subtracts an offset (the `VolumeOpacityThreshold`) from the occlusion value before scaling, allowing control over the 'slope' of shadow intensity and preventing darkening of non-occluded regions [S2, unofficial]. The proposed formula is:
$$
\text{FinalColor} = \text{BaseColor} \times \text{clamp}((\text{Occlusion} - \text{VolumeOpacityThreshold}) \times \text{IntensityScale}, 0.0, 1.0)
$$
This ensures that only regions with occlusion values above the threshold are darkened, preventing the entire image from becoming dark when scaling is increased [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Increases depth perception significantly for volume data; compatible with mixed volume and surface rendering; relatively low overhead compared to full volumetric AO [S1, unofficial].
*   **Limitations:** Relies on a single opacity threshold, which may not capture complex internal structures well; can cause darkening artifacts in semi-transparent regions if not tuned (addressed by variants); requires shading to be enabled [S1, unofficial][S2, unofficial].
*   **When to use:** When depth perception of internal volume structures is critical and performance constraints prevent full volumetric light transport calculations [G].
*   **When not to use:** When high-fidelity transparency effects are required without the "opaque" look of standard SSAO, or when the volume has very low opacity throughout [S2, unofficial].

## Background
Screen-Space Ambient Occlusion (SSAO) was originally developed for surface rendering to estimate ambient occlusion by sampling points in a hemisphere around each pixel's surface position and checking occlusion against the depth buffer [Parent]. The extension to volume rendering was introduced to address the lack of depth cues in volume visualization [S1, unofficial]. It was implemented in the Visualization Toolkit (VTK) and discussed in the context of 3D Slicer, with significant contributions from Kitware and the 3D Slicer community around 2024 [S1, unofficial][S2, unofficial].
