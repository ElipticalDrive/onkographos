# Screen-Space Ambient Occlusion for Volumes

Also called: SSAO for volumes, Volume SSAO

## Overview
Screen-Space Ambient Occlusion for Volumes extends the standard Screen-Space Ambient Occlusion (SSAO) technique to volume rendering by extracting position and normal information from the raycasting algorithm to create an opacity isovalue layer [S1, unofficial]. This layer acts as a synthetic surface, allowing the SSAO pass to compute ambient occlusion for internal structures within a volume, thereby increasing depth perception [S1, unofficial]. It differs from sibling methods like [Combined Volumetric and Geometric Ambient Occlusion](14367-combined-volumetric-and-geometric-ambient-occlusion.md) by relying on screen-space depth comparisons of a generated isocontour rather than explicit volumetric scattering or geometric mesh intersection.

## How it works
**Inputs and Outputs:**
*   **Inputs:** Volume data, existing depth buffer, volume rendering parameters (opacity threshold, shading enabled).
*   **Outputs:** Final color buffer with ambient occlusion applied to the volume's internal structures.

**Data Structures:**
*   **Position Texture:** Stores the 3D world position of the first sample along the ray that exceeds the opacity threshold.
*   **Normal Texture:** Stores the surface normal (computed via local gradient) for the same sample.
*   **Depth Texture:** Must be formatted as `Fixed32` to allow the GPU volume mapper to copy the existing depth texture successfully [S1, unofficial].

**Steps:**
1.  **Enable Shading:** Ensure the volume property has shading enabled to compute normals using local gradient values for each sample [S1, unofficial].
    ```python
    volume.GetProperty().ShadeOn()
    ```
2.  **Raycasting with Position/Normal Extraction:** During the volume rendering raycast, for each sample along the ray:
    *   Compute the fragment position (current sample location).
    *   Compute the normal (local gradient value).
    *   Check if the sample's opacity exceeds the `VolumeOpacityThreshold`.
3.  **First-Visible-Write Logic:** The first sample along the ray with opacity greater than the threshold writes its position and normal to the additional GPU textures. Subsequent samples along the same ray do not override this information [S1, unofficial].
4.  **Isocontour Generation:** This process generates an opacity layer (isocontour) representing the "surface" of the volume at the specified opacity threshold [S1, unofficial].
5.  **SSAO Pass Execution:** The SSAO pass reads the position, normal, and depth textures generated in steps 2-4. It treats this data as if it were a regular opaque surface, performing hemisphere sampling and depth comparison to calculate occlusion factors [S1, unofficial].
6.  **Compositing:** The calculated occlusion is applied to the rendered volume color. Because the textures are written at the pass level, this is compatible with mixed volume and surface rendering [S1, unofficial].

**Parameters:**
*   `VolumeOpacityThreshold`: Defines the opacity isovalue for the AO layer. Default is 0.9. Recommended value is the opacity of the first visible pixels at volume boundaries [S1, unofficial].
*   `Radius`: Comparison radius for SSAO sampling. Typical value: `0.1 * sceneSize` (where `sceneSize` is the diagonal of the bounding box) [S1, unofficial].
*   `Bias`: Comparison bias to prevent self-occlusion artifacts. Typical value: `0.001 * sceneSize` [S1, unofficial].
*   `KernelSize`: Number of samples used for SSAO. Typical value: 128 [S1, unofficial].
*   `DepthFormat`: Must be `Fixed32` [S1, unofficial].

**Pseudocode:**
```python
# Initialization
scene_size = calculate_bounding_box_diagonal(volume)
ssao_pass = SSAOPass()
ssao_pass.SetRadius(0.1 * scene_size)
ssao_pass.SetBias(0.001 * scene_size)
ssao_pass.SetKernelSize(128)
ssao_pass.SetDepthFormat(TextureFormat.Fixed32)
ssao_pass.SetVolumeOpacityThreshold(0.95) # Example value
ssao_pass.BlurOn()

# Volume Setup
volume.GetProperty().ShadeOn()

# Rendering Loop
def render_volume_with_ssao(volume, camera, depth_buffer):
    # 1. Volume Raycast with Position/Normal Extraction
    # Modified GPU Volume Raycast Mapper
    position_texture = allocate_texture()
    normal_texture = allocate_texture()
    
    for each pixel (x, y):
        ray = camera.generate_ray(x, y)
        first_valid_sample = None
        
        for sample in raycast(volume, ray):
            if sample.opacity > ssao_pass.VolumeOpacityThreshold:
                if first_valid_sample is None:
                    first_valid_sample = sample
                    # Write to textures
                    position_texture.write(x, y, sample.position)
                    normal_texture.write(x, y, sample.normal)
                    # Prevent further writes for this pixel
                    break
        
        # If no sample exceeded threshold, no AO is computed for this pixel in this pass
    
    # 2. SSAO Pass
    # Uses position_texture, normal_texture, and depth_buffer
    occlusion_factor = ssao_pass.compute_occlusion(position_texture, normal_texture, depth_buffer)
    
    # 3. Apply AO to Volume Color
    final_color = volume_color * occlusion_factor
    return final_color
```

**Edge Cases and Pitfalls:**
*   **Low Opacity Regions:** If the volume opacity is very low, the default SSAO application can make the image appear disturbingly opaque or dark [S2, unofficial].
*   **Depth Precision:** Using a depth format other than `Fixed32` may cause the GPU volume mapper to fail copying the depth texture, breaking the SSAO pass [S1, unofficial].
*   **Normal Computation:** Shading must be explicitly enabled; otherwise, normals are not computed, and SSAO cannot function correctly [S1, unofficial].

## Subtopics

### Fragment Opacity Premultiplied SSAO
A technique where the SSAO contribution is scaled down by the opacity value of the sample that writes to the depth buffer, reducing AO on transparent regions [S2, unofficial]. It is enabled via `vtkSSAOPass::VolumeOpacityPremultipliedOn()` [S2, unofficial]. This approach results in almost no SSAO being applied if the volume opacity is very low, which is considered a good improvement for enabling SSAO by default [S2, unofficial].

### SSAO Intensity Factor
A technique to reduce the amount of ambient occlusion applied to a volume rendering by multiplying the AO result by a constant intensity factor [S2, unofficial]. Typical values include 1.0 (full AO) and 0.5 (reduced AO) [S2, unofficial].

### Offset and Scale SSAO
A modification to the shading equation that subtracts an offset (the `VolumeOpacityThreshold`) from the occlusion value before scaling, allowing control over the 'slope' of shadow intensity and preventing darkening of non-occluded regions [S2, unofficial]. The proposed formula is:
$$
\text{FinalColor} = \text{BaseColor} \times \text{clamp}((\text{Occlusion} - \text{VolumeOpacityThreshold}) \times \text{IntensityScale}, 0.0, 1.0)
$$
This ensures that only regions with occlusion values above the threshold are darkened, preventing the entire image from becoming dark when scaling is increased [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Dependent on the number of samples in the SSAO kernel (`KernelSize`) and the resolution of the screen-space pass. The volume raycast itself is unchanged in complexity, but adds texture writes for position/normal.
*   **Memory Complexity:** Requires additional GPU textures for position and normal data per pixel, plus the `Fixed32` depth texture compatibility.
*   **Strengths:** Increases depth perception significantly for volume data; compatible with mixed volume and surface rendering; relatively low overhead compared to full volumetric AO.
*   **Limitations:** Relies on a single opacity threshold, which may not capture complex internal structures well; can cause darkening artifacts in semi-transparent regions if not tuned (addressed by variants); requires shading to be enabled.
*   **When to use:** When depth perception of internal volume structures is critical and performance constraints prevent full volumetric light transport calculations.
*   **When not to use:** When high-fidelity transparency effects are required without the "opaque" look of standard SSAO, or when the volume has very low opacity throughout.

## Background
Screen-Space Ambient Occlusion (SSAO) was originally developed for surface rendering to estimate ambient occlusion by sampling points in a hemisphere around each pixel's surface position and checking occlusion against the depth buffer [Parent]. The extension to volume rendering was introduced to address the lack of depth cues in volume visualization. It was implemented in the Visualization Toolkit (VTK) and discussed in the context of 3D Slicer, with significant contributions from Kitware and the 3D Slicer community around 2024 [S1, unofficial][S2, unofficial].
