# Hybrid Ambient Occlusion (HAO) Sampling

Also called: Jittered ray sampling with 3D noise, Monte-Carlo integration over hemisphere, Monte-Carlo integration over hemisphere with noise jitter

## Overview
Hybrid Ambient Occlusion (HAO) is a screen-space technique that computes ambient occlusion by performing Monte-Carlo integration over the hemisphere of each pixel to evaluate the occlusion factor [S1]. It distinguishes itself from standard hemisphere sampling by dynamically jittering ray directions using a space-dependent 3D noise texture to prevent camera-motion flickering, and by using a fixed number of uniform steps for grid occupancy testing to optimize GPU execution [S1].

## How it works

### Inputs and Outputs
*   **Inputs:**
    *   Pixel position $p$ and surface normal $\mathbf{n}$ (from a G-buffer or depth/normal reconstruction) [S1].
    *   A 3D white noise texture $t$ tiling the entire space [S1].
    *   A voxelized 3D proxy of the scene geometry [S1].
    *   Parameters: number of rays $n$, spread angle $\theta_{\text{spread}}$, maximum distance $d_{\max}$, and number of steps per ray $k$ [S1].
*   **Outputs:**
    *   Ambient Occlusion value $A(p, \mathbf{n})$ for each pixel [S1].

### Data Structures
*   **Voxel Grid:** A 3D grid representing the scene proxy where occupancy is binary (filled or empty) [S1].
*   **Noise Texture:** A 3D texture $t(x, y, z)$ containing white noise values, typically stored as floating-point or normalized integer data [S1].

### Algorithm Steps
1.  **Ray Distribution:** Distribute $n$ ray directions $\{\omega_1, \dots, \omega_n\}$ over the hemisphere defined by the surface normal $\mathbf{n}$ using a regular uniform sampling pattern within a cone of open angle $\theta_{\text{spread}}$ [S1].
2.  **Jittering:** For each base ray direction $\omega(p, r)$, sample a jitter offset $\delta$ from the 3D noise texture $t$ using the pixel's world position and normal as coordinates. Shift the ray direction to $\omega(p, r')$ using this offset [S1].
    $$ \omega(p, r') = \text{shift}(\omega(p, r), \delta) $$
3.  **Uniform Step Testing:** For each jittered ray, test grid occupancy at $k$ uniformly spaced points along the ray up to $d_{\max}$, rather than marching the 3D proxy and testing each cell [S1].
4.  **Weighting:** If a filled voxel cell is found at any of the $k$ steps, weight the binary result by a distance function $w(V, d_{\max})$ and the dot product between the ray direction and the surface normal to produce progressive penumbra [S1].
5.  **Integration:** Sum the weighted results and divide by $n$ to obtain the final AO value [S1].

### Formula
The ambient occlusion value $A(p, \mathbf{n})$ is computed as:

$$ A(p, \mathbf{n}) = \frac{1}{n} \sum_{i=1}^{n} w(V(p, \omega_i), d_{\max}) \langle \omega_i, \mathbf{n} \rangle $$

Where:
*   $n$ is the number of rays [S1].
*   $\omega_i$ is the $i$-th jittered ray direction [S1].
*   $\mathbf{n}$ is the surface normal at pixel $p$ [S1].
*   $V(p, \omega_i)$ is the visibility result (binary occupancy) along ray $\omega_i$ starting at $p$ [S1].
*   $w(V, d_{\max})$ is a weighting function based on distance, where $d_{\max}$ is the maximum distance for the weighting function [S1].
*   $\langle \omega_i, \mathbf{n} \rangle$ denotes the dot product (cosine of the angle) between the ray and the normal [S1].

### Parameters
*   **$n$ (Number of rays):** Controls sampling density. Typical values range from 16 to 128 rays per pixel [S1].
*   **$d_{\max}$ (Maximum distance):** The cutoff distance for the weighting function $w$ [S1].
*   **$\theta_{\text{spread}}$ (Spread):** The open angle within which rays are distributed. Influences contrast and smoothness. Typical values are 0.25, 0.5, or 0.75 [S1].
*   **$k$ (Steps per ray):** A fixed, typically small number of steps (e.g., 8) used to test grid occupancy [S1].

### Edge Cases and Pitfalls
*   **Noise from Fixed Steps:** Using a fixed number of steps $k$ instead of marching cell-by-cell can cause rays passing near the corners of non-empty cells to miss them, producing more noise in the AO map [S1]. However, this simplification speeds up sampling and produces visually smooth results after filtering [S1].
*   **Flickering:** Without the 3D noise jitter, hemisphere sampling can cause flickering when the camera moves. The space-dependent noise texture avoids this flickering [S1].
*   **AO Bleeding:** The filtering stage must be designed carefully to avoid AO bleeding between distant objects that are projected closely in image space. Using object-space entities for the range space of the bilateral filter prevents this [S1].

### Pseudocode
```python
import math

def dot(a, b):
    return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]

def normalize(v):
    l = math.sqrt(dot(v, v))
    return (v[0]/l, v[1]/l, v[2]/l)

def cross(a, b):
    return (a[1]*b[2] - a[2]*b[1],
            a[2]*b[0] - a[0]*b[2],
            a[0]*b[1] - a[1]*b[0])

def rotate_to_normal(local_dir, world_normal):
    # [G] Standard basis alignment to rotate a local vector to world space
    if abs(world_normal[2]) < 0.9999:
        basis_x = normalize(cross(world_normal, (0, 0, 1)))
    else:
        basis_x = normalize(cross(world_normal, (1, 0, 0)))
    basis_y = cross(world_normal, basis_x)
    return (basis_x[0]*local_dir[0] + basis_y[0]*local_dir[1] + world_normal[0]*local_dir[2],
            basis_x[1]*local_dir[0] + basis_y[1]*local_dir[1] + world_normal[1]*local_dir[2],
            basis_x[2]*local_dir[0] + basis_y[2]*local_dir[1] + world_normal[2]*local_dir[2])

def generate_uniform_hemisphere_samples(count, normal, spread_angle):
    samples = []
    for _ in range(count):
        u = math.random()
        v = math.random()
        theta = math.sqrt(u) * math.sin(spread_angle)
        phi = 2 * math.pi * v
        local_x = math.cos(phi) * theta
        local_y = math.sin(phi) * theta
        local_z = math.sqrt(max(0.0, 1.0 - theta**2))
        direction = rotate_to_normal((local_x, local_y, local_z), normal)
        samples.append(direction)
    return samples

def jitter_direction(base_direction, noise_val):
    # [G] Simple perturbation: shift the direction vector slightly based on noise
    perturbation = noise_val * 0.1
    jittered = (base_direction[0] + perturbation,
                base_direction[1] + perturbation,
                base_direction[2] + perturbation)
    return normalize(jittered)

def distance_weight_function(dist, d_max):
    # [G] Linear falloff for distance weighting
    if dist > d_max:
        return 0.0
    return 1.0 - (dist / d_max)

def compute_hao(p_world, n_normal, voxel_grid, noise_texture, n_rays, d_max, spread_angle, steps_per_ray):
    total_weight = 0.0
    base_directions = generate_uniform_hemisphere_samples(n_rays, n_normal, spread_angle)
    
    for i in range(n_rays):
        omega_base = base_directions[i]
        noise_val = noise_texture.sample(p_world, n_normal)
        omega_jittered = jitter_direction(omega_base, noise_val)
        
        occluded = False
        min_dist = d_max
        
        for step in range(steps_per_ray):
            t = (step + 1) / steps_per_ray * d_max
            point = (p_world[0] + omega_jittered[0]*t,
                     p_world[1] + omega_jittered[1]*t,
                     p_world[2] + omega_jittered[2]*t)
            
            if voxel_grid.is_filled(point):
                occluded = True
                if t < min_dist:
                    min_dist = t
                break
        
        if occluded:
            dist_weight = distance_weight_function(min_dist, d_max)
            cos_angle = dot(omega_jittered, n_normal)
            if cos_angle > 0:
                total_weight += dist_weight * cos_angle
                
    ao_value = total_weight / n_rays
    return ao_value
```

## Operating characteristics
*   **Time Complexity:** $O(N \cdot K)$ per pixel, where $N$ is the number of rays and $K$ is the number of steps per ray [S1].
*   **Memory Complexity:** $O(V)$ for the voxel grid and $O(T)$ for the noise texture, where $V$ is the voxel grid size and $T$ is the texture size [S1].
*   **Performance:** The method is optimized for GPU execution by using a fixed number of steps, avoiding branching, and ensuring a constant number of intersection tests per ray [S1]. Generating a low-resolution AO map and upsampling it further reduces the computational load [S1].
*   **Strengths:** Fast execution on GPUs, visually smooth results after filtering, no flickering due to 3D noise jitter, and effective penumbra generation [S1].
*   **Limitations:** The fixed-step approach can introduce noise if rays miss small occluders. The sampling bottleneck depends on the resolution of the AO map and the number of rays emitted for each pixel [S1].
*   **When to use:** Real-time applications requiring approximate ambient occlusion with good visual quality and performance [S1].
*   **When not to use:** Applications requiring precise shadowing or where the voxelization proxy cannot accurately represent the geometry [S1].

## Background
Hybrid Ambient Occlusion was introduced by C.K. Reinbothe, T. Boubekeur, and M. Alexa in 2009 [S1]. The method combines Monte-Carlo integration with spatial noise jittering and voxel-based occupancy testing to provide a fast and visually appealing approximation of ambient occlusion for real-time rendering [S1]. It builds on the concept of hemisphere sampling but adds optimizations for GPU execution and visual stability [S1].
