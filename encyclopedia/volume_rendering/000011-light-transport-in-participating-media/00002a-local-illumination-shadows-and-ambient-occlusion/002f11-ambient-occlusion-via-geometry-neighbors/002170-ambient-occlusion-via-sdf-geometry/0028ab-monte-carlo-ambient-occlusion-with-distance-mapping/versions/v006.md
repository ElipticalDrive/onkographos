# Monte Carlo Ambient Occlusion with Distance Mapping

Also called: Random Ray Casting AO

## Overview
Monte Carlo Ambient Occlusion with Distance Mapping is a precomputation technique that estimates the ambient occlusion factor at a surface point by casting rays in random directions and numerically integrating the occlusion contribution using a distance mapping function [S1, unofficial]. It differs from deterministic grid-based or screen-space methods by relying on stochastic sampling of the hemisphere, which allows for flexible handling of complex geometry at the cost of noise and higher sample counts for convergence [S1, unofficial].

## How it works
**Inputs:**
- Surface point position $\mathbf{p}$.
- Surface normal vector $\mathbf{n}$ (normalized).
- Number of random samples $N$.
- Distance mapping function $v(\mathbf{p}, \mathbf{l})$.

**Outputs:**
- Ambient occlusion factor $k_A(\mathbf{p})$, a scalar in $[0, 1]$.

**Data Structures:**
- No persistent data structures are required for the core evaluation; the method is stateless per point.
- Random direction vectors $\mathbf{l}_i$ are generated on the fly.

**Steps:**
1.  Initialize the accumulator $S = 0$.
2.  For each sample $i$ from $1$ to $N$:
    a. Generate a random direction vector $\mathbf{l}_i$ uniformly distributed over the hemisphere defined by $\mathbf{n}$.
    b. Evaluate the distance mapping function $v(\mathbf{p}, \mathbf{l}_i)$. This function returns a floating-point value representing the visibility or occlusion weight for the direction $\mathbf{l}_i$ at position $\mathbf{p}$.
    c. Compute the cosine weight $w = \max(0, \mathbf{n} \cdot \mathbf{l}_i)$.
    d. Add the contribution to the accumulator: $S \leftarrow S + v(\mathbf{p}, \mathbf{l}_i) \cdot w$.
3.  Compute the final occlusion factor: $k_A(\mathbf{p}) = \frac{1}{N} S$.

**Formula:**
The ambient occlusion factor is calculated as [S1, unofficial]:

$$k_A(\mathbf{p}) = \frac{1}{N} \sum_{i=1}^N v(\mathbf{p}, \mathbf{l}_i) (\mathbf{n} \cdot \mathbf{l}_i)^+$$

Where:
- $k_A(\mathbf{p})$ is the ambient occlusion factor for position $\mathbf{p}$.
- $N$ is the integer number of random samples.
- $v(\mathbf{p}, \mathbf{l}_i)$ is the distance mapping function returning a floating-point value.
- $\mathbf{l}_i$ is the $i$-th random direction vector.
- $\mathbf{n}$ is the surface normal vector.
- $(\cdot)^+$ denotes the positive part function $\max(0, \cdot)$.

**Parameters:**
- $N$: The number of random samples. Typical values depend on the desired noise level and performance budget; higher $N$ reduces noise but increases computation time [S1, unofficial].
- $v(\mathbf{p}, \mathbf{l}_i)$: The distance mapping function. Its specific implementation depends on the underlying geometric representation (e.g., SDF, voxel grid, depth buffer) [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Halo Effect:** Because standard Monte Carlo sampling is not inherently cosine-weighted in the distribution of rays (only in the integration weight), it may account for occlusion that should not be accounted for, leading to blackened edges around objects, known as the halo effect [S1, unofficial].
- **Self-Intersection:** As with all ray-casting AO methods, a small bias or offset along the normal $\mathbf{n}$ is required to prevent self-intersection artifacts (acne) due to floating-point precision errors [S1, 2527-ambient-occlusion-via-sdf-geometry.md, unofficial].
- **Noise:** Low sample counts result in noisy outputs. Variance reduction techniques or temporal accumulation are often needed for real-time applications [S1, unofficial].

**Pseudocode:**
```python
def monte_carlo_ao_with_distance_mapping(p, n, N, distance_mapping_func):
    """
    Computes ambient occlusion using Monte Carlo integration with a distance mapping function.
    
    Args:
        p: 3D vector, surface position.
        n: 3D vector, surface normal (must be normalized).
        N: Integer, number of random samples.
        distance_mapping_func: Function taking (p, l) and returning a float.
        
    Returns:
        float, ambient occlusion factor k_A(p).
    """
    accumulator = 0.0
    
    for i in range(N):
        # Generate a random direction l_i uniformly distributed over the hemisphere defined by n
        # Implementation detail: Generate random point on unit sphere, then reflect/shift to hemisphere
        l_i = random_hemisphere_direction(n)
        
        # Evaluate distance mapping function
        v_p_l = distance_mapping_func(p, l_i)
        
        # Compute cosine weight (n . l_i)^+
        cos_weight = max(0.0, dot(n, l_i))
        
        # Accumulate contribution
        accumulator += v_p_l * cos_weight
        
    # Average the sum
    k_A = accumulator / N
    
    return k_A

def random_hemisphere_direction(n):
    """
    Generates a random direction vector uniformly distributed over the hemisphere 
    defined by the normal n.
    """
    # Generate a random point on the unit sphere
    # Using standard rejection sampling or spherical coordinates
    u1 = random_float(0, 1)
    u2 = random_float(0, 1)
    
    # Convert to spherical coordinates
    theta = 2 * pi * u1
    phi = acos(1 - 2 * u2)
    
    # Convert to Cartesian coordinates (local space where n is (0,0,1))
    x = sin(phi) * cos(theta)
    y = sin(phi) * sin(theta)
    z = cos(phi)
    
    local_dir = vec3(x, y, z)
    
    # Rotate local_dir to align with n
    # This requires constructing a basis from n. 
    # For simplicity, assuming a standard rotation implementation exists or is implemented here.
    # [G] Constructing an orthonormal basis from n is a standard graphics operation.
    basis = create_orthonormal_basis(n)
    global_dir = basis.x * local_dir.x + basis.y * local_dir.y + basis.z * local_dir.z
    
    return normalize(global_dir)
```

## Subtopics

### [Hybrid Ambient Occlusion (HAO) Sampling](14818-hybrid-ambient-occlusion-hao-sampling.md)
Hybrid Ambient Occlusion (HAO) is a screen-space technique that computes ambient occlusion by performing Monte-Carlo integration over the hemisphere of each pixel to evaluate the occlusion factor. It distinguishes itself from standard hemisphere sampling by dynamically jittering ray directions using a space-dependent 3D noise texture, which prevents flickering during camera movement, and by using a fixed number of uniform steps for grid occupancy testing to optimize GPU performance.

### Volumetric Obscurance (Loos and Sloan)
Volumetric Obscurance is a Monte Carlo integration formulation of screen-space AO that integrates analytically in the z-dimension to reduce sample count [S1, 14818-hybrid-ambient-occlusion-hao-sampling.md, unofficial]. It computes the integral through random sampling only in the xy-dimension and integrates analytically in the z-dimension [S1, 14818-hybrid-ambient-occlusion-hao-sampling.md, unofficial]. The formula is defined as $v_A(\mathbf{p}) = \int_{x \in X} \rho(d(\mathbf{p}, x)) O(x) dx$, where $X$ is a 3D spherical neighborhood around the point, $\rho(d(\mathbf{p}, x))$ is a distance mapping function, and $O(x)$ is the occupancy function [S1, 14818-hybrid-ambient-occlusion-hao-sampling.md, unofficial]. The distance mapping function can be substituted for a constant function because it has little impact on visual quality [S1, 14818-hybrid-ambient-occlusion-hao-sampling.md, unofficial]. This method requires a lower amount of samples to achieve the same image quality as Crytek's method [S1, 14818-hybrid-ambient-occlusion-hao-sampling.md, unofficial].

### Malley's Method
Malley's Method is an approximation that substitutes the cosine weight factor with importance sampling by imbuing the cosine weight into the ray cast distribution, making rays more likely to be sent in the direction of the surface normal [S1, 14818-hybrid-ambient-occlusion-hao-sampling.md, unofficial]. It differs from standard Monte Carlo AO by casting rays unevenly (biased towards the surface normal) instead of evenly along the hemisphere, reducing the need for a separate cosine weight factor [S1, 14818-hybrid-ambient-occlusion-hao-sampling.md, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ per surface point, where $N$ is the number of samples. The cost is linear with respect to sample count.
- **Memory Complexity:** $O(1)$ auxiliary memory per point during evaluation, assuming the distance mapping function is evaluated on the fly. Storage of precomputed AO data depends on the storage format (texture, volume, vertex data) [S1, unofficial].
- **Performance:** Performance is heavily dependent on the efficiency of the distance mapping function $v(\mathbf{p}, \mathbf{l}_i)$ and the random number generation. On GPU, this method can be parallelized across pixels or points [S1, unofficial].
- **Strengths:** Flexible; works with any geometric representation that supports a distance mapping function. Can handle complex geometry without explicit mesh traversal.
- **Limitations:** Noisy with low sample counts. The "halo effect" can occur if not properly weighted. Requires precomputation or real-time evaluation which can be expensive for high $N$.
- **When to use:** When the geometric representation is already available as a distance field or volume, and deterministic methods are not feasible or too restrictive.
- **When not to use:** When real-time performance with low sample counts is critical and noise is unacceptable without temporal accumulation. When the geometry is simple and deterministic methods (like SSAO) are more efficient.

## Background
Monte Carlo methods are the most common way to precompute ambient occlusion, where either the visibility function approach or the obscurance distance mapping function approach can be used [S1, unofficial]. The method was described in the context of real-time ray traced voxel global illumination [S1, unofficial]. Kontkanen and Laine relied on the reciprocal of a quadratic polynomial to encode how ambient occlusion changes with distance [S1, unofficial]. Loos and Sloan expanded upon Crytek's approach and formulated it as a Monte Carlo integration, giving it the name Volumetric Obscurance [S1, unofficial].
