# Monte Carlo Ambient Occlusion with Distance Mapping

Also called: Random Ray Casting AO

## Overview
Monte Carlo Ambient Occlusion with Distance Mapping is a precomputation method that estimates the ambient occlusion factor at a surface point by numerically integrating visibility over the hemisphere using random ray casting and a distance mapping function [S1, unofficial]. It differs from screen-space approaches like SSAO by relying on explicit geometric queries via a distance field rather than depth buffers, and from pure statistical methods by using a specific distance-based visibility function $v(p, l_i)$ to weight occlusion contributions [S1, unofficial].

## How it works
**Inputs:**
*   Point position $p$ on the surface [S1, unofficial].
*   Surface normal vector $\mathbf{n}$ at $p$ [S1, unofficial].
*   Number of random samples $N$ [S1, unofficial].
*   Distance mapping function $v(p, l_i)$, which returns a floating-point value representing the occlusion contribution for a ray cast in direction $l_i$ from $p$ [S1, unofficial].

**Outputs:**
*   Ambient occlusion factor $k_A(p)$, a floating-point value in $[0, 1]$ [S1, unofficial].

**Data Structures:**
*   The distance mapping function $v$ is typically implemented as a query into a Signed Distance Field (SDF) or a voxel grid [G].
*   The exact layout depends on the underlying geometry representation (e.g., trilinear interpolation on a voxel grid or analytical evaluation of an SDF) [G].
*   Not given in the sources.

**Steps:**
1. **Biasing:** Offset the starting point $p$ slightly along the normal $\mathbf{n}$ to prevent self-intersection artifacts (acne) caused by floating-point precision errors [G]. Let the biased point be $p' = p + \epsilon \mathbf{n}$, where $\epsilon$ is a small bias value [G].
2. **Sampling:** Generate $N$ random direction vectors $l_i$ uniformly distributed over the hemisphere defined by $\mathbf{n}$ [G].
3. **Visibility Query:** For each direction $l_i$, evaluate the distance mapping function $v(p', l_i)$ [S1, unofficial]. This function returns a value based on the distance to the nearest geometry along the ray [G].
4. **Weighting:** Compute the cosine weight $(\mathbf{n} \cdot l_i)^+$ for each sample, where $(\cdot)^+$ denotes the positive part (i.e., $\max(0, \mathbf{n} \cdot l_i)$) [S1, unofficial].
5. **Accumulation:** Sum the products of the distance mapping value and the cosine weight for all samples [S1, unofficial].
6. **Normalization:** Divide the sum by $N$ to obtain the final occlusion factor [S1, unofficial].

**Formula:**
The ambient occlusion factor $k_A(p)$ is calculated as:

$$k_A(p) = \frac{1}{N} \sum_{i=1}^N v(p, l_i) (\mathbf{n} \cdot l_i)^+$$

Where:
*   $k_A(p)$ is the ambient occlusion factor for position $p$ [S1, unofficial].
*   $N$ is the number of random samples [S1, unofficial].
*   $v(p, l_i)$ is the distance mapping function returning a floating-point value [S1, unofficial].
*   $l_i$ is the $i$-th random direction vector [S1, unofficial].
*   $\mathbf{n}$ is the surface normal vector [S1, unofficial].

**Parameters:**
*   $N$: Integer representing the number of random samples. Typical values are not given in the sources [S1, unofficial].
*   $v(p, l_i)$: The distance mapping function. Its specific implementation depends on the geometry representation [G].
*   $l_i$: 3D vector representing the $i$-th random direction [S1, unofficial].
*   $\mathbf{n}$: 3D vector representing the surface normal [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Halo Effect:** Since the standard Monte Carlo method described is not cosine-weighted in the ray distribution itself (only in the final weight), it may account for occlusion that should not be accounted for, leading to blackened edges around objects, known as the halo effect [S1, unofficial].
*   **Self-Intersection:** Without proper biasing, rays cast from $p$ may intersect the surface at $p$ itself due to precision errors, leading to incorrect occlusion values [G].

**Pseudocode:**
```python
import math
import random

def monte_carlo_ao_with_distance_mapping(p, n, N, distance_mapping_function):
    """
    Computes ambient occlusion using Monte Carlo integration with a distance mapping function.
    
    Args:
        p: tuple of 3 floats, the surface point.
        n: tuple of 3 floats, the surface normal at p.
        N: int, number of random samples.
        distance_mapping_function: callable taking (point, direction) and returning a float.
        
    Returns:
        float, the ambient occlusion factor k_A(p).
    """
    # Biasing to prevent self-intersection
    epsilon = 0.001  # Small bias value [G]
    p_biased = (p[0] + epsilon * n[0], p[1] + epsilon * n[1], p[2] + epsilon * n[2])
    
    occlusion_sum = 0.0
    
    for i in range(N):
        # Generate random direction l_i in the hemisphere defined by n
        l_i = sample_hemisphere(n)
        
        # Evaluate distance mapping function
        v = distance_mapping_function(p_biased, l_i)
        
        # Compute cosine weight
        cosine_weight = max(0.0, n[0]*l_i[0] + n[1]*l_i[1] + n[2]*l_i[2])
        
        # Accumulate
        occlusion_sum += v * cosine_weight
        
    # Normalize
    k_A = occlusion_sum / N
    
    return k_A

def sample_hemisphere(n):
    """
    Generates a random direction vector uniformly distributed in the hemisphere
    defined by the normal n [G].
    """
    u = random.random()
    v = random.random()
    
    theta = 2.0 * math.pi * u
    phi = math.acos(1.0 - 2.0 * v)
    
    # Local direction in Z-up hemisphere
    local_dir = (math.sin(phi) * math.cos(theta), math.sin(phi) * math.sin(theta), math.cos(phi))
    
    # Construct orthonormal basis from n [G]
    if abs(n[2]) < 0.999:
        t = (1.0, 0.0, 0.0)
    else:
        t = (0.0, 1.0, 0.0)
    # Gram-Schmidt orthogonalization
    dot_nt = t[0]*n[0] + t[1]*n[1] + t[2]*n[2]
    b = (t[0] - n[0]*dot_nt, t[1] - n[1]*dot_nt, t[2] - n[2]*dot_nt)
    b_len = math.sqrt(b[0]**2 + b[1]**2 + b[2]**2)
    b = (b[0]/b_len, b[1]/b_len, b[2]/b_len)
    # Binormal
    bn = (n[1]*b[2] - n[2]*b[1], n[2]*b[0] - n[0]*b[2], n[0]*b[1] - n[1]*b[0])
    
    # Rotate local_dir to align with n
    return (local_dir[0]*b[0] + local_dir[1]*bn[0] + local_dir[2]*n[0],
            local_dir[0]*b[1] + local_dir[1]*bn[1] + local_dir[2]*n[1],
            local_dir[0]*b[2] + local_dir[1]*bn[2] + local_dir[2]*n[2])
```

## Subtopics

### Volumetric Obscurance (Loos and Sloan)
Volumetric Obscurance is a Monte Carlo integration formulation of screen-space AO that integrates analytically in the z-dimension to reduce sample count [S1, unofficial]. It differs from standard Monte Carlo AO by computing the integral through random sampling only in the xy-dimension and integrating analytically in the z-dimension, which requires a lower amount of samples to achieve the same image quality as Crytek's method [S1, unofficial]. The formula is $v_A(p) = \int_{x \in X} \rho(d(p, x)) O(x) dx$, where $X$ is a 3D spherical neighborhood, $\rho$ is a distance mapping function, and $O(x)$ is the occupancy function [S1, unofficial]. The distance mapping function can be substituted for a constant function because it has little impact on visual quality [S1, unofficial].

### Malley's Method
Malley's Method is an approximation that substitutes the cosine weight factor with importance sampling by imbuing the cosine weight into the ray cast distribution, making rays more likely to be sent in the direction of the surface normal [S1, unofficial]. It differs from standard Monte Carlo AO by casting rays unevenly (biased towards the surface normal) instead of evenly along the hemisphere, reducing the need for a separate cosine weight factor [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ per point, where $N$ is the number of samples [G].
*   **Memory Complexity:** Depends on the storage of the distance mapping function (e.g., SDF or voxel grid) [G]. Not given in the sources.
*   **Performance:** Not given in the sources [S1, unofficial].
*   **Strengths:** Provides accurate occlusion based on explicit geometry; can be precomputed [S1, unofficial].
*   **Limitations:** Susceptible to the halo effect if not properly weighted; requires efficient distance mapping queries; sample count affects noise and accuracy [S1, unofficial].
*   **When to use:** When explicit geometric accuracy is required and precomputation is feasible [S1, unofficial].
*   **When not to use:** When real-time performance with low sample counts is critical and the halo effect is unacceptable without additional techniques [S1, unofficial].

## Background
Monte Carlo methods are the most common way to precompute ambient occlusion, where either the visibility function approach or the obscurance distance mapping function approach can be used [S1, unofficial]. The method described is based on the equation $k_A(p) = \frac{1}{N} \sum_{i=1}^N v(p, l_i) (\mathbf{n} \cdot l_i)^+$ [S1, unofficial]. Kontkanen and Laine relied on the reciprocal of a quadratic polynomial to encode how ambient occlusion changes with distance [S1, unofficial]. Loos and Sloan expanded upon Crytek's approach and formulated it as a Monte Carlo integration, giving it the name Volumetric Obscurance [S1, unofficial].
