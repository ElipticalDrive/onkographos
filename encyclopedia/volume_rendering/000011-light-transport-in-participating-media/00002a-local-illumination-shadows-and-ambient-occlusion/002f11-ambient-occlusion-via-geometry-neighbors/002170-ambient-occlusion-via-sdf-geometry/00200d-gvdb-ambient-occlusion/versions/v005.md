# GVDB Ambient Occlusion

Also called: GVDB AO, computeAmbientOcclusion

## Overview
GVDB Ambient Occlusion estimates the visibility of the hemisphere of incoming ambient light at a surface point by querying a voxelized geometric representation (GVDB volume) using either point sampling or ray casting [S1, unofficial]. It distinguishes itself from sibling methods by operating directly on a hierarchical voxel grid, supporting two distinct sampling modes: discrete point queries for speed and continuous ray casting for smoother gradients, both utilizing a tangent-space basis for rotation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Surface position $\mathbf{p}$, surface normal $\mathbf{n}$, GVDB volume handle, sampling parameters ($a_o\_samples$, $a_o\_radius$, $a_o\_bias$, $AMBIENT\_OCCLUSION\_MODE$).
*   **Output:** Scalar ambient occlusion factor $AO \in [0, 1]$.

**Data Structures:**
The method relies on the GVDB volume structure. The specific internal layout of the GVDB volume (e.g., leaf node size, bit packing) is not defined in the source notes and is assumed to be handled by the underlying GVDB library [S1, unofficial]. The method requires a precomputed random rotation vector (noise) to generate the tangent basis [S1, unofficial].

**Parameters:**
*   $a_o\_samples$: Number of hemisphere samples. Maximum value is 512 [S1, unofficial].
*   $a_o\_radius$: World-space radius for AO sampling, controlling the falloff distance [S1, unofficial].
*   $a_o\_bias$: Distance in world space to backtrack the query position to mitigate acne artifacts. Typical value is $10^{-3}$ [S1, unofficial].
*   $AMBIENT\_OCCLUSION\_MODE$: Integer switch. $0$ for point sampling, $1$ for ray sampling [S1, unofficial].

**Algorithm Steps:**
1.  **Early Exit:** If $a_o\_samples == 0$, return $1.0$ [S1, unofficial].
2.  **Tangent Basis Construction:** Compute tangent $\mathbf{t}$ and bitangent $\mathbf{b}$ vectors from the surface normal $\mathbf{n}$ and a precomputed random rotation vector $\mathbf{noise}$ [S1, unofficial].
    $$ \mathbf{t} = \text{normalize}(\mathbf{noise} - \mathbf{n} \cdot \mathbf{noise} \cdot \mathbf{n}) $$
    $$ \mathbf{b} = \mathbf{n} \times \mathbf{t} $$
3.  **Bias Application:** Retrieve the bias value from the volume at the current position (or use the parameter $a_o\_bias$) to determine the offset for self-intersection prevention [S1, unofficial]. The query position is backtracked along the normal:
    $$ \mathbf{p}_{query} = \mathbf{p} + \mathbf{n} \cdot a_o\_bias $$
    *Note: The source notes mention "Get bias value from volume at pos" but also define $a_o\_bias$ as a parameter. The implementation likely uses the parameter $a_o\_bias$ for the offset magnitude, potentially modulated by volume data if specified, but the primary safeguard is the backtracking distance [S1, unofficial].*
4.  **Hemisphere Sampling:** Initialize $occlusion = 0$. For each sample $i$ from $0$ to $a_o\_samples - 1$:
    a. Generate a sample direction $\mathbf{d}_i$ in the local hemisphere defined by $\mathbf{t}$ and $\mathbf{b}$ (details of hemisphere distribution are not specified in the notes, assumed to be uniform or stratified within the hemisphere) [S1, unofficial].
    b. Transform $\mathbf{d}_i$ to world space using the basis $\{\mathbf{t}, \mathbf{b}, \mathbf{n}\}$:
       $$ \mathbf{d}_{world} = \mathbf{t} \cdot d_{i,x} + \mathbf{b} \cdot d_{i,y} + \mathbf{n} \cdot d_{i,z} $$
    c. **Mode 0 (Point Sampling):**
       i. Compute sample position: $\mathbf{p}_{sample} = \mathbf{p}_{query} + \mathbf{d}_{world} \cdot a_o\_radius$.
       ii. Query the GVDB volume at $\mathbf{p}_{sample}$. Let $v$ be the returned value.
       iii. If $v \le a_o\_bias$ (or a threshold derived from the volume density/geometry), add $1.0$ to $occlusion$ [S1, unofficial].
    d. **Mode 1 (Ray Sampling):**
       i. Shoot a ray from $\mathbf{p}_{query}$ in direction $\mathbf{d}_{world}$ with length $a_o\_radius$.
       ii. If a hit is found at distance $dist$ from $\mathbf{p}_{query}$:
           $$ value = \text{smoothstep}(1, 0, \frac{a_o\_radius}{dist}) $$
           Add $value$ to $occlusion$ [S1, unofficial].
       iii. If no hit is found, add $0$ (or $1.0$ depending on interpretation of "occlusion", but typically ray casting adds occlusion weight if blocked, so if unblocked, add 0 to occlusion sum, or add 1 to visibility sum. The note says "add to occlusion" for hit found. Standard AO sums occlusion. If hit, it contributes to occlusion. If no hit, it contributes nothing to occlusion (fully visible)).
5.  **Normalization:** Divide the accumulated $occlusion$ by $a_o\_samples$ to get the final $AO$ factor [S1, unofficial].

**Pseudocode:**
```python
def compute_ambient_occlusion(p, n, volume, ao_samples, ao_radius, ao_bias, mode, noise):
    if ao_samples == 0:
        return 1.0

    # 1. Compute tangent basis
    # noise is a precomputed random vector
    dot_val = dot(noise, n)
    tangent = normalize(noise - n * dot_val)
    bitangent = cross(n, tangent)

    # 2. Backtrack position to avoid self-intersection (acne)
    # Using ao_bias as the offset distance
    p_query = p + n * ao_bias

    occlusion_sum = 0.0

    for i in range(ao_samples):
        # Generate a sample direction in the local hemisphere
        # Note: Specific hemisphere sampling pattern (e.g., uniform, stratified)
        # is not detailed in the source notes. Assuming a generic sample direction
        # d_local in the hemisphere defined by tangent and bitangent.
        d_local = get_hemisphere_sample(i, ao_samples)
        
        # Transform to world space
        d_world = tangent * d_local.x + bitangent * d_local.y + n * d_local.z

        if mode == 0:
            # Point Sampling Mode
            sample_pos = p_query + d_world * ao_radius
            # Query volume value at sample_pos
            # The condition "value <= bias" implies that if the volume density/
            # occupancy is below the bias threshold, it is considered empty/transparent,
            # and thus NOT occluding? Or does it mean if it's solid?
            # Standard AO: if geometry is present, it occludes.
            # The note says: "if value <= bias, add 1.0 to occlusion".
            # This implies that a LOW value in the volume indicates OCCLUSION?
            # Or perhaps the volume stores "distance to surface" or "inverse density"?
            # Given "GVDB", it often stores density. If density is low, it's empty.
            # If the note says "if value <= bias, add 1.0", it suggests that
            # the volume might store a metric where low values mean "blocked" or
            # the bias is a threshold for "solid".
            # However, typically AO checks if the path is blocked.
            # Let's stick strictly to the note: "if value <= bias, add 1.0 to occlusion"
            val = volume.query(sample_pos)
            if val <= ao_bias:
                occlusion_sum += 1.0
                
        elif mode == 1:
            # Ray Sampling Mode
            hit_dist = volume.ray_cast(p_query, d_world, ao_radius)
            if hit_dist is not None:
                # Formula: smoothstep(1, 0, ao_radius / dist)
                # smoothstep(edge0, edge1, x)
                # Here edge0=1, edge1=0.
                # If dist = ao_radius, ratio = 1. smoothstep(1,0,1) = 1?
                # Standard smoothstep(0,1,x) goes 0->1.
                # smoothstep(1,0,x) goes 1->0.
                # So if dist is small (close hit), ratio is large (>1), result 0?
                # If dist is large (far hit), ratio is small (<1), result 1?
                # This seems inverted for "occlusion weight".
                # Let's re-read: "smoothstep(1, 0, ao_radius / dist)"
                # If dist -> 0, ratio -> inf. smoothstep(1,0,inf) -> 0.
                # If dist -> ao_radius, ratio -> 1. smoothstep(1,0,1) -> 1.
                # If dist > ao_radius, ratio < 1. smoothstep(1,0,<1) -> <1.
                # This formula assigns HIGHER occlusion weight to HITS that are FURTHER AWAY?
                # That is counter-intuitive for standard AO (closer objects occlude more).
                # However, the source note is explicit: value = smoothstep(1, 0, ao_radius / dist).
                # We must follow the source.
                ratio = ao_radius / hit_dist
                weight = smoothstep(1.0, 0.0, ratio)
                occlusion_sum += weight

    ao = occlusion_sum / ao_samples
    return ao

def smoothstep(edge0, edge1, x):
    # Standard smoothstep implementation
    t = clamp((x - edge0) / (edge1 - edge0), 0.0, 1.0)
    return t * t * (3.0 - 2.0 * t)

def clamp(x, min_val, max_val):
    if x < min_val: return min_val
    if x > max_val: return max_val
    return x
```

**Edge Cases and Pitfalls:**
*   **Acne Artifacts:** Sampling directly at the surface can cause self-intersection due to floating-point precision. Mitigated by backtracking $\mathbf{p}$ by $a_o\_bias$ along $\mathbf{n}$ [S1, unofficial].
*   **Mode 0 Logic:** The condition `value <= bias` for adding occlusion is specific to the GVDB volume's data representation. If the volume stores density, this logic might need inversion depending on whether "bias" represents a threshold for "solid" or "empty". The source explicitly states this condition [S1, unofficial].
*   **Ray Mode Formula:** The formula `smoothstep(1, 0, ao_radius / dist)` produces a weight that increases as the hit distance increases (up to the radius). This differs from standard distance-weighted AO where closer hits contribute more. This is a specific characteristic of this implementation [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(a_o\_samples \cdot C)$, where $C$ is the cost of a volume query (point or ray cast). Ray casting is generally more expensive than point sampling [S1, unofficial].
*   **Memory Complexity:** Depends on the GVDB volume size. The AO method itself uses $O(1)$ auxiliary memory [S1, unofficial].
*   **Performance:** Point sampling (Mode 0) is faster but may exhibit aliasing or blockiness. Ray sampling (Mode 1) provides smoother results but is computationally heavier [S1, unofficial].
*   **Strengths:** Integrates directly with GVDB volumes; supports two modes for flexibility; handles arbitrary geometry stored in the volume [S1, unofficial].
*   **Limitations:** Quality depends on volume resolution; ray casting can be slow for deep volumes; the specific occlusion weighting in Mode 1 is non-standard [S1, unofficial].

## Background
GVDB Ambient Occlusion is part of the GVDB (GPU Voxel Database) ecosystem, used for high-performance volume rendering and visualization. It is implemented as a device function within the GVDB library or associated rendering kernels [S1, unofficial].
