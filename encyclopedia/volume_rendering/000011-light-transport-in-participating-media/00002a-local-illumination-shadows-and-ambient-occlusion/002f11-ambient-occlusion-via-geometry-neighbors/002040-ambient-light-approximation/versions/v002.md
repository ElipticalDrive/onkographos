# Ambient Light Approximation

Also called: Ambient Lighting for Volume Clouds, Sky Ambient, Upwards Ray Approximation

## Overview
Ambient Light Approximation provides a computationally efficient estimate of indirect sky illumination for participating media, such as volumetric clouds, by replacing the integration of the sky hemisphere with a single upward-facing ray [S1, unofficial]. Unlike full path tracing or multiple scattering models, it simulates the shadowing effect of cloud density on ambient light without the noise or cost of stochastic sampling [S1, unofficial]. It is distinct from [Lighting Models](2056-lighting-models.md) by focusing specifically on the non-directional sky component, and from [Two-Pass Shadow Casting (Kajiya and Von Herzen)](2196-two-pass-shadow-casting-kajiya-and-von-herzen.md) by using a simplified single-ray occlusion test rather than full shadow maps for the ambient term.

## How it works
**Inputs:**
*   Sample position $\mathbf{p}$ within the volume.
*   Volume density $\sigma_a(\mathbf{p})$ (absorption/scattering coefficient).
*   Cloud profile or distance-to-edge field $E(\mathbf{p})$.
*   Pre-integrated sky light color $L_{sky}$ (constant or sampled from a LUT) [S1, unofficial][S2, unofficial].
*   Upward ambient density $D_{up}(\mathbf{p})$, representing the integrated extinction along the upward ray [S1, unofficial].

**Outputs:**
*   Ambient light contribution $C_{ambient}$ added to the sample's total light.

**Data Structures:**
*   **Sky Light Value:** A single RGB color vector or a pre-integrated value derived from spherical harmonics or random sampling of the sky hemisphere [S1, unofficial].
*   **Upward Density Grid:** A lower-resolution 3D grid or texture storing $D_{up}$. This data is static for static volumes and can be pre-calculated because the upward ray integration is naturally blurry [S1, unofficial].
*   **Cloud LUT (Optional):** In some implementations (e.g., UE4-based), a lookup table containing altitude-based AO factors and ambient color probes [S2, unofficial].

**Steps:**
1.  **Pre-calculate Sky Light:** Integrate the sky hemisphere into a single representative light value $L_{sky}$. This can be done via random sampling, spherical harmonics, or by assigning a fixed color resembling the clear sky [S1, unofficial]. If atmospheric scattering is enabled, sample a `SkyLightLut`; otherwise, sample a baked Ambient Probe encoded with 3rd-order Spherical Harmonics [S2, unofficial].
2.  **Calculate Ambient Occlusion (AO):** Determine the occlusion factor based on the sample's position.
    *   *Method A (Profile-based):* Use the cloud's vertical profile or distance-to-edge field $E(\mathbf{p})$ to weight the ambient light. Edges receive more ambient light than the center [S1, unofficial].
    *   *Method B (Altitude-based):* Interpolate an AO factor based on altitude. It starts at a user-defined minimum value at the cloud bottom and increases to 1.0 as altitude increases. This factor is then multiplied by the B-channel of a Cloud LUT [S2, unofficial].
3.  **Evaluate Upward Transmittance:** Retrieve the pre-calculated upward density $D_{up}(\mathbf{p})$ from the grid. Calculate the transmittance of ambient light as $T_{up} = \exp(-D_{up}(\mathbf{p}))$ [S1, unofficial].
4.  **Compute Ambient Contribution:** Combine the sky light, occlusion, and transmittance. The ambient light added to the current sample is:
    $$ C_{ambient} = L_{sky} \cdot T_{up} \cdot AO_{factor} $$
    Where $AO_{factor}$ is derived from the profile or altitude logic [S1, unofficial][S2, unofficial].
5.  **Integrate into Volume:** Add $C_{ambient}$ to the sample's light accumulation, scaled by the sample's density $\sigma_a$, the step size $\Delta s$, and the transmittance from the light source to the sample [S1, unofficial].

**Pseudocode:**
```python
def compute_ambient_light(sample_position, cloud_profile, upward_density_grid, sky_light_color):
    """
    Computes the ambient light contribution for a volume sample.
    
    Args:
        sample_position: 3D vector, current sample location.
        cloud_profile: float, normalized distance to cloud edge or vertical profile value.
        upward_density_grid: 3D texture/grid, stores pre-calculated upward density D_up.
        sky_light_color: RGB vector, pre-integrated sky hemisphere light.
        
    Returns:
        RGB vector, ambient light contribution.
    """
    # 1. Retrieve upward density from pre-calculated grid
    # The grid stores the integrated extinction along the upward ray
    d_up = upward_density_grid.sample(sample_position)
    
    # 2. Calculate upward transmittance
    # Light from the sky is attenuated by the density above the sample
    t_up = exp(-d_up)
    
    # 3. Calculate Ambient Occlusion factor
    # Method: Weight by cloud profile/edge distance. 
    # Edges (high profile) get more light; center (low profile) gets less.
    # Using a power function to control falloff sharpness.
    # Note: cloud_profile is typically in [0, 1], where 1 is edge.
    ao_factor = pow(clamp(cloud_profile, 0.0, 1.0), 0.5)
    
    # 4. Combine with sky light
    # L_ambient = L_sky * T_up * AO_factor
    ambient_contribution = sky_light_color * t_up * ao_factor
    
    return ambient_contribution

def integrate_ambient_into_sample(sample_light, ambient_contribution, sample_density, step_size, transmittance_from_light):
    """
    Adds the ambient contribution to the total sample light.
    """
    # Scale ambient by local density, step size, and existing transmittance
    # This matches the standard volume rendering integral accumulation
    sample_light += ambient_contribution * sample_density * step_size * transmittance_from_light
    return sample_light
```

**Parameters:**
*   **Sky Light Color:** Typically a blue-ish color representing the clear sky [S1, unofficial].
*   **Profile Power:** The exponent in the profile weighting (e.g., 0.5) controls how quickly ambient light drops off towards the cloud center [S1, unofficial].
*   **Saturation Adjustment:** An artist-controlled parameter to adjust the saturation of the ambient light color. This is necessary because ignoring multiple scattering causes clouds to appear unnaturally blue (too much sky color influence) [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Blue Tint:** The single-ray approximation ignores multiple scattering, leading to clouds appearing too blue. This must be corrected via saturation adjustment or by blending with a darker, less saturated ambient color [S2, unofficial].
*   **Resolution of Upward Grid:** The upward density grid can be stored at a lower resolution than the main volume because the data is naturally blurry. However, if the resolution is too low, shadowing details may be lost [S1, unofficial].
*   **Static vs. Dynamic:** The upward ray approximation assumes static geometry for pre-calculation. For dynamic volumes, the upward density must be re-evaluated or approximated differently [S1, unofficial].

## Subtopics

### Bruneton-style Sky Irradiance
An approach where the sky irradiance is precomputed in a table based on altitude and sun angle, allowing each surface (or volume sample) to sample its own local sky light [S3, unofficial].
*   **Definition:** An atmosphere pass that builds a sky irradiance table to provide sky light from each surface's own sky, ensuring ground seen from orbit keeps its sky fill and terrain past the terminator is not lit by the eye's daylight [S3, unofficial].
*   **Data Structure:** A uniform table `atmosphere_sky_table` covering 16 altitudes by 24 sun cosines, with 6 symmetric L2 harmonics per entry in the local frame [S3, unofficial].
*   **Usage:** Deferred lighting looks up each pixel's own altitude and sun angle from the table to determine ambient illumination [S3, unofficial].
*   **Performance:** Reported cost of 0.60 ms for the deferred lighting pass in the referenced implementation [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample for the ambient term, assuming the upward density grid is pre-calculated and stored in a texture/grid. The cost is dominated by the texture lookup [S1, unofficial].
*   **Memory Complexity:** Requires storage for the pre-calculated upward density grid. The resolution can be significantly lower than the main volume grid due to the blurriness of the data [S1, unofficial].
*   **Strengths:** Extremely fast; avoids the noise and high cost of stochastic ambient occlusion or multiple scattering calculations [S1, unofficial]. Provides realistic shadowing for the underside of clouds [S1, unofficial].
*   **Limitations:** Approximates the sky as a single direction, ignoring lateral ambient light variations. Can result in an unnatural blue tint if multiple scattering is not accounted for [S2, unofficial]. Not suitable for highly dynamic volumes where pre-calculation is not feasible [S1, unofficial].
*   **When to use:** Real-time rendering of volumetric clouds where performance is critical and full multiple scattering is too expensive [S1, unofficial][S2, unofficial].
*   **When not to use:** Offline rendering requiring high physical accuracy, or scenes where lateral ambient light variations are significant [S1, unofficial].

## Background
The method originates from real-time volumetric cloud rendering techniques, specifically those aiming to balance visual quality with performance. It was popularized in the context of game engine cloud rendering, where full path tracing is infeasible. The "upward ray" approximation is a heuristic to simulate the shadowing effect of cloud density on ambient sky light without shooting multiple rays [S1, unofficial]. Variations using SkyLightLuts and Spherical Harmonics are common in engines like Unreal Engine [S2, unofficial]. The Bruneton-style irradiance table approach is used in more complex planetary rendering systems to handle global illumination effects for terrain and atmosphere [S3, unofficial].
