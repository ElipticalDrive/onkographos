# Voxel Culling and Ambient Occlusion

Also called: Moore/Von Neumann Neighbourhood Culling, Sparse Voxel Rendering with AO

## Overview
This method renders only visible voxel faces by culling internal voxels and applying ambient occlusion based on the presence of neighbouring voxels [S1, unofficial]. It distinguishes itself from sibling methods by using a Moore neighbourhood to determine visibility and a Von Neumann neighbourhood mask for occlusion calculations, implemented via instance rendering with precomputed neighbour masks [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A voxel grid organized into chunks of size `CHUNK_SIZE` (128) [S1, unofficial].
- Input: A list of visible voxels, each storing a linear index and a Von Neumann neighbour mask [S1, unofficial].
- Output: Rendered scene with visible voxel faces and ambient occlusion applied [S1, unofficial].

**Data Structures:**
- `VON_NEUMANN_MASK`: A constant `u32` bitmask (4281360) representing the 6 Von Neumann neighbours (indices 4, 10, 12, 14, 16, 22 in the Moore neighbourhood) [S1, unofficial].
- `visible_voxels`: A buffer storing pairs of `(linear_index, neighbours_mask)` for each visible voxel [S1, unofficial].
- `TRI_VERTICES`: Array of vertex offsets for the 6 faces of a voxel [S1, unofficial].
- `TRI_NORMALS`: Array of normal vectors for the 6 faces of a voxel [S1, unofficial].

**Numbered Steps:**
1. **Compute Moore Neighbourhood:** For each voxel position `v`, compute its Moore neighbourhood using `moore_neighbourhood(v)` [S1, unofficial].
2. **Check Visibility:** A voxel is visible if it is `VOXEL_FULL` AND (on the chunk boundary OR has at least one empty Von Neumann neighbour) [S1, unofficial].
3. **Store Visible Voxels:** If visible, atomically increment a counter and store the voxel's linear index and Von Neumann neighbour mask in the `visible_voxels` buffer [S1, unofficial].
4. **Calculate Occlusion Factor:** In the vertex shader, for each instance (voxel), calculate the occlusion factor by counting the number of set bits in the intersection of the current face's Moore mask and the voxel's Von Neumann mask, then dividing by 3.0 [S1, unofficial].
5. **Calculate Lighting Intensity:** Calculate lighting intensity as the diffuse component (`max(dot(norm, light_dir), 0.0)`) minus the ambient occlusion term (`AMBIENT * occlusion`) [S1, unofficial].

**Formulas:**
- Occlusion Factor: $O = \frac{\text{countOneBits}(m \cap n)}{3.0}$, where $m$ is the Moore mask for the specific triangle face and $n$ is the Von Neumann neighbour mask of the voxel [S1, unofficial].
- Lighting Intensity: $I = \max(\mathbf{n} \cdot \mathbf{l}, 0.0) - \text{AMBIENT} \times O$, where $\mathbf{n}$ is the face normal, $\mathbf{l}$ is the normalized light direction, and AMBIENT is 0.25 [S1, unofficial].

**Parameters:**
- `CHUNK_SIZE`: 128 [S1, unofficial].
- `AMBIENT`: 0.25 [S1, unofficial].

**Edge Cases and Pitfalls:**
- The Moore neighbourhood linear index calculation assumes a specific ordering of the 27 neighbours [S1, unofficial].
- The `moore_to_von_neumann` function hardcodes the mapping from Moore indices to Von Neumann indices [S1, unofficial].

AMBIENT = 0.25

# Helper functions
def moore_linear_index(v):
    """Compute linear index in the 3x3x3 Moore neighbourhood."""
    return (v.x + 1) + 3 * (v.y + 1) + 9 * (v.z + 1)

def chunk_vector_index(i):
    """Convert linear chunk index to 3D vector."""

## Operating characteristics
- **Time Complexity:** Visibility check is O(1) per voxel. Occlusion calculation is O(1) per face. Total time is proportional to the number of visible voxels.
- **Memory Complexity:** O(N) for storing visible voxels, where N is the number of visible voxels.
- **Performance:** Efficient for sparse voxel grids as it culls internal voxels. Performance scales with the number of visible voxels rather than total voxels.
- **Strengths:** Simple implementation, efficient culling, real-time capable.
- **Limitations:** Approximate occlusion (only considers immediate neighbours), fixed AMBIENT value may not suit all scenes.
- **When to Use:** Real-time rendering of sparse voxel terrains or environments where performance is critical.
- **When Not to Use:** When high-quality global illumination or accurate shadowing is required.

## Background
This method is derived from the `wgpu-voxel-terrain` project by statusfailed, which implements a voxel terrain renderer using WebGPU [S1, unofficial]. It builds on the concept of voxel ambient occlusion by incorporating neighbour-based culling and occlusion calculations.
