# Voxel Ambient Occlusion

Also called: Voxel AO, computeAO

## Overview
Voxel Ambient Occlusion (Voxel AO) estimates ambient occlusion for a surface point by sampling the solidity of surrounding voxels in a 2D grid relative to the surface normal, simulating light blockage from adjacent geometry [S1, unofficial]. It sets itself apart from its siblings, such as [JAOCC Shading](3634-jaocc-shading.md) which uses precomputed histograms, and [Vertex Ambient Occlusion Approximation](6623-vertex-ambient-occlusion-approximation.md) which operates on vertex data, by performing real-time, position-based shading directly on the voxel grid using a fixed set of neighbor samples [S1, unofficial]. Unlike ray-based approaches such as Local AO, it avoids expensive ray marching by relying on direct grid lookups [S1, unofficial].

## How it works
**Inputs:**
- `hitPos`: The 3D world-space position of the surface hit point.
- `normal`: The 3D surface normal at the hit point.
- `voxelGrid`: A data structure providing `isSolid(pos)` which returns 1 if a voxel at integer coordinate `pos` is occupied, 0 otherwise.
- `axes`: A 2D array of 4 offset vectors representing the corners of a unit square: `(1,1), (-1,1), (-1,-1), (1,-1)`.

**Outputs:**
- `ao`: A float value in `[0.0, 1.0]` representing the ambient occlusion factor, where 1.0 is fully lit and 0.0 is fully occluded.

**Data Structures:**
- `axes`: `vec2[4]` containing `{(1,1), (-1,1), (-1,-1), (1,-1)}`.

**Steps:**
1.  **Base Position Calculation:** Calculate the integer voxel coordinate of the hit surface by rounding the hit position offset by the normal to prevent self-intersection.
    $$ \text{basePos} = \lfloor \text{hitPos} + \text{normal} \times 0.01 \rfloor $$
    [S1, unofficial]

2.  **Neighbor Sampling:** Sample the solidity of the 4 side neighbors and 4 corner neighbors relative to `basePos`.
    -   Side neighbors (using offsets `d1` and `d2` corresponding to the axes):
        ```python
        side.x = isSolid(basePos + d1)
        side.y = isSolid(basePos + d2)
        side.z = isSolid(basePos - d1)
        side.w = isSolid(basePos - d2)
        ```
    -   Corner neighbors:
        ```python
        corner.x = isSolid(basePos + d1 + d2)
        corner.y = isSolid(basePos - d1 + d2)
        corner.z = isSolid(basePos - d1 - d2)
        corner.w = isSolid(basePos + d1 - d2)
        ```
    [S2, unofficial]

3.  **Face AO Calculation:** Compute the AO contribution for each of the 4 faces using a helper function `vertex_ao`.
    ```python
    ao.x = vertex_ao(side.xy, corner.x)
    ao.y = vertex_ao(side.yz, corner.y)
    ao.z = vertex_ao(side.zw, corner.z)
    ao.w = vertex_ao(side.wx, corner.w)
    ```
    [S2, unofficial]

    The `vertex_ao` function is defined as follows [S1, unofficial]:
    1.  Determine dominant axis of `normal`.
    2.  Set `sideA` and `sideB` vectors based on the dominant axis:
        -   If `|normal.x| > 0`: `sideA = (0, offset.x, 0)`, `sideB = (0, 0, offset.y)`
        -   Else if `|normal.y| > 0`: `sideA = (offset.x, 0, 0)`, `sideB = (0, 0, offset.y)`
        -   Else: `sideA = (offset.x, 0, 0)`, `sideB = (0, offset.y, 0)`
    3.  Calculate `cornerOffset = sideA + sideB`.
    4.  Sample solidity for `side1`, `side2`, and `corner` using `isSolid(basePos + sideVector)`.
    5.  Calculate AO contribution:
        -   If `side1 == 1` and `side2 == 1`: `ao = 0.9`
        -   Else: `ao = side1 * 0.4 + side2 * 0.4 + corner * 0.2`
    6.  Return `ao`.

4.  **Accumulation:** Sum the AO contributions from the 4 faces.
    ```python
    aoSum = 0.0
    for i in 0 to 3:
        offset = axes[i]
        # Note: The specific mapping of axes[i] to sideA/sideB in the loop is implicit in the face calculation above.
        # The accumulation simply sums the pre-calculated face AO values.
        aoSum += ao[i]
    ```
    [S1, unofficial]

5.  **Final Result:** Return the inverted and clamped average AO.
    $$ \text{ao} = \text{clamp}(1.0 - (\text{aoSum} / 4.0), 0.0, 1.0) $$
    [S1, unofficial]

**Parameters:**
-   `epsilon`: 0.01 (used in basePos calculation to prevent self-intersection) [S1, unofficial].
-   Weights: 0.9 for full side occlusion, 0.4 for single side, 0.2 for corner [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Self-Intersection:** The offset `normal * 0.01` is critical to prevent the ray/sample from hitting the surface it is shading [S1, unofficial].
-   **Boundary Conditions:** If `basePos` is outside the voxel grid, `isSolid` must return 0 (empty space) or handle bounds checking appropriately [G].
-   **Normal Dominance:** The logic for determining `sideA` and `sideB` relies on the dominant axis of the normal. If the normal is exactly aligned with an axis (e.g., `(1,0,0)`), the `|normal.x| > 0` check handles it, but precision issues near zero should be considered [S1, unofficial].

## Subtopics

### [Histogram-based Voxel Ambient Occlusion](10973-histogram-based-voxel-ambient-occlusion.md)
Histogram-based Voxel Ambient Occlusion is a local illumination technique for volume rendering that approximates ambient occlusion, color bleeding, and basic scattering effects by modulating precomputed intensity distributions (local histograms) with the transfer function during rendering. Unlike ray-based approaches such as Local AO, it uses vector quantization clustering to store these distributions in a 2D texture table, allowing real-time updates via GPU texture blending with only two additional texture lookups compared to standard gradient-based shading.

### [Vicinity Occlusion Mapping (VOM)](10977-vicinity-occlusion-mapping-vom.md)
Vicinity Occlusion Mapping (VOM) is a screen-space technique that incorporates view-dependent ambient occlusion and halo effects into volume rendered images by utilizing two Summed Area Tables (SATs) computed from a depth map. It sets itself apart from its siblings, such as Histogram-based Voxel Ambient Occlusion, by operating in image space rather than volume space, allowing for real-time performance without the high preprocessing costs and memory footprint of 3D density SATs. Unlike Crytek's screen-space ambient occlusion which relies on subsampling patterns that cause noise artifacts and require filtering, VOM computes the average depth of pixel vicinities in constant time using SATs, eliminating the need for filtering.

### [Voxel Culling and Ambient Occlusion](17393-voxel-culling-and-ambient-occlusion.md)
This method renders only visible voxel faces by culling internal voxels and applying ambient occlusion based on the presence of neighbouring voxels. It distinguishes itself from sibling methods by using a Moore neighbourhood to determine visibility and a Von Neumann neighbourhood mask for occlusion calculations, implemented via instance rendering with precomputed neighbour masks.

### Stochastic Hemisphere Sampling for Voxel AO
A stochastic method to estimate ambient occlusion by casting rays into a hemisphere oriented around the surface normal, using cosine-weighted sampling [S1, unofficial].
-   **Steps:**
    1.  Loop `i` from 0 to `maxSamples`.
    2.  Calculate `seed = seedBase + f32(i) * (13.37 * 10.2)`.
    3.  Get two random numbers `u1`, `u2` from `seed`.
    4.  Sample local direction using cosine-weighted hemisphere.
    5.  Transform local direction to world space using tangent (T), bitangent (B), and normal (N) basis.
    6.  For each sample direction, perform a voxel mesh query (ray march) from a slightly offset position (`hitPosition + normal * epsilon`).
    7.  If a hit is found, increment hit counter.
    8.  Calculate `occlusionFactor = 1.0 - (hit / f32(maxSamples))`.
    9.  Multiply AO color by `occlusionFactor`.
-   **Parameters:**
    -   `maxSamples`: `u32 = 8` [S1, unofficial].
    -   `seedBase`: `f32 = fragCoord.x * fragCoord.y + 0.1234 + time` [S1, unofficial].
-   **Pitfall:** Epsilon offset (0.01) is used to prevent self-intersection when casting rays from the surface [S1, unofficial].

### Voxel Ambient Occlusion via Axis-Aligned Corner Sampling
An ambient occlusion technique for voxel scenes that samples the 4 corners of the voxel face adjacent to the hit point, weighted by the surface normal's dominant axis [S1, unofficial].
-   **Steps:**
    1.  Calculate `basePos = floor(hitPos + normal * 0.01)` to get the integer voxel coordinate of the hit surface [S1, unofficial].
    2.  Define 4 corner offsets: `(1,1), (-1,1), (-1,-1), (1,-1)` [S1, unofficial].
    3.  If `abs(normal.x) > 0.0`, set `sideA = (0, offset.x, 0)` and `sideB = (0, 0, offset.y)`. Else if `abs(normal.y) > 0.0`, set `sideA` and `sideB` for Y-dominant normal [S1, unofficial].
    4.  Sum the solidity of the 4 corners.
    5.  Divide by 4.0 to get AO factor (0.0 to 1.0) [S1, unofficial].

### Voxel-Neighborhood Ambient Occlusion
-   **Steps:**
    1.  Convert each vertex's world-space position to voxel grid coordinates by subtracting the grid offset and dividing by the voxel scale, casting to `i32` [S3, unofficial].
    2.  Compute the AO factor by querying the voxel neighborhood at the grid coordinates `(vx, vy, vz)` and the vertex normal [S3, unofficial].
    3.  Modulate the vertex RGB color channels by multiplying each channel by the computed AO factor [S3, unofficial].
-   **Parameters:**
    -   `offset`: world-space origin of the voxel grid [S3, unofficial].

### Color Bleeding via Extinction
An approximation of color bleeding where the color appearance of a surface is affected by colored nearby objects, modeled by including the voxel color $C_{RGB}$ in the attenuation integral [S4, unofficial].
-   **Steps:**
    1.  Reformulate the AO integral (Eq. 4) by multiplying the extinction coefficient $\tau(t)$ by the color $C_{RGB}(t)$ before integration, allowing the estimation of color bleeding using the same aggregate summation structure [S4, unofficial].
-   **Formula:**
    $$ I_{AORGB}(s) \approx I_A \cdot e^{-\int_{t \in \mathbb{N}(s)} \frac{\tau(t) C_{RGB}(t)}{|s-t|^2} dt} $$
    where $I_{AORGB}$ is a vector describing intensity per color, $C_{RGB}(t)$ is the color at position t depending on the Transfer Function (TF), and other terms are as in Eq. 4 [S4, unofficial].

### CUDA-based VOM Construction
A CUDA-based implementation to compute Vicinity Occlusion Maps on the GPU, using a column-then-row summation strategy for Summed Area Tables [S5, unofficial].
-   **Steps:**
    1.  Analyze the source depth map by columns on the GPU [S5, unofficial].
    2.  Sum the resulting values by rows on the GPU [S5, unofficial].
-   **Parameters:**
    -   Hardware: Intel Core 2 Duo CPU at 3.0 GHz, 4GB RAM, NVidia GeForce GTX 280 GPU with 1GB RAM [S5, unofficial].
-   **Pitfall:** The connection between the regular graphics pipeline and the CUDA pipeline requires downloading the depth map to the CPU before uploading it to CUDA memory, limiting performance gains [S5, unofficial].
-   **Performance:**
    -   VOM construction time (ms) on CPU vs GPU (CUDA) for 512x512 viewport: CPU 2.427ms, GPU 1.450ms [S5, unofficial].
    -   Frame rate for Body dataset (512x512x512) at 512x512 viewport: CPU VOM 5.67 fps, CUDA VOM 7.21 fps [S5, unofficial].
-   **Comparison:** CUDA construction times are faster than CPU SAT construction, but overall frame rates are similar to CPU VOM due to data transfer overhead [S5, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
-   Time complexity is $O(1)$ per surface point as it involves a fixed number of voxel lookups (4 sides, 4 corners) and arithmetic operations [S1, unofficial].
-   Memory complexity is $O(1)$ additional memory per sample, relying on the existing voxel grid storage [S1, unofficial].

**Measured Performance:**
-   Specific performance metrics for the core Voxel AO method are not given in the sources [S1, unofficial].
-   Related methods like VOM show that GPU acceleration can reduce construction time (e.g., 2.427ms to 1.450ms for 512x512) but may not improve frame rate significantly due to data transfer overhead [S5, unofficial].

**Scaling:**
-   The method scales well with resolution as the number of samples is constant, but accuracy depends on the voxel grid resolution relative to the scene detail [S1, unofficial].

**Strengths and Limitations:**
-   **Strengths:** Fast, real-time capable, simple implementation, no preprocessing required [S1, unofficial].
-   **Limitations:** Approximate, depends on voxel grid resolution, may suffer from aliasing if grid is coarse [S1, unofficial].

**When to Use:**
-   Use for real-time voxel-based rendering where performance is critical and approximate AO is acceptable [S1, unofficial].
-   Avoid when high-quality, view-dependent AO is required, in which case screen-space methods like VOM or ray-based methods might be better [S1, unofficial][S2, unofficial].

## Background
Voxel Ambient Occlusion is a technique used in voxel-based rendering to approximate the shading effects of ambient occlusion by querying the local neighborhood of voxels [S1, unofficial]. It is part of the broader family of local illumination techniques for volume rendering [S1, unofficial]. The specific implementation details described here are derived from unofficial sources documenting voxel engine implementations [S1, unofficial].
