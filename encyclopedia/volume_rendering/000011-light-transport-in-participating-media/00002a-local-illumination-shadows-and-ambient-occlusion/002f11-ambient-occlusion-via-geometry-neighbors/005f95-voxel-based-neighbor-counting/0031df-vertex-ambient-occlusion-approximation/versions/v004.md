# Vertex Ambient Occlusion Approximation

Also called: Ambient Occlusion (Simple), Voxel Vertex AO, Voxel-based AO approximation

## Overview
Vertex Ambient Occlusion Approximation is a post-processing step that darkens vertices of a polygon mesh generated from voxel data based on the density of solid voxels in their local neighborhood, simulating shadowing in crevices [S2, unofficial]. It solves the problem of harsh, blocky lighting transitions and incorrect zero-light values on blocked faces by sampling neighbors rather than the cell itself [S2, unofficial]. Unlike standard ray-casted ambient occlusion, it achieves a similar darkening effect in concave areas as a side effect of this averaging process, without the computational cost of ray casting [S2, unofficial]. It builds on [Voxel-based Neighbor Counting](17927-voxel-based-neighbor-counting.md) by applying the neighbor count to specific mesh vertices rather than voxel centers.

## How it works
**Inputs and outputs:**
- Input: A vertex position $(x, y, z)$ in voxel coordinates, a surface normal $\mathbf{n}$, and a voxel grid occupancy function $V(x, y, z)$ returning `true` if the voxel is solid, `false` otherwise.
- Output: An ambient occlusion factor $AO \in [0, 1]$ applied to the vertex's color.

**Data structures:**
- The voxel grid is accessed via a closure or function `get(x, y, z)` which returns `false` if coordinates are outside the grid bounds [S2, unofficial].

**Steps:**
1. Initialize counters: `total = 0`, `occluded = 0`.
2. Iterate through all 26 neighbors of the vertex at $(x, y, z)$. For each neighbor offset $(dx, dy, dz) \in \{-1, 0, 1\}^3 \setminus \{(0,0,0)\}$:
   a. Calculate the neighbor direction vector $\mathbf{d} = (dx, dy, dz)$.
   b. Compute the dot product $dot = \mathbf{d} \cdot \mathbf{n}$.
   c. If $dot < 0$, the neighbor is on the 'back' side of the surface relative to the normal; skip this neighbor.
   d. Otherwise, increment `total`.
   e. If `get(x + dx, y + dy, z + dz)` is `true` (solid), increment `occluded`.
3. Compute the AO factor:
   - If `total` is 0, $AO = 1.0$.
   - Otherwise, $AO = 1.0 - \frac{occluded}{total} \times 0.5$.
4. Multiply the vertex's RGB color components by $AO$.

**Formula:**
The primary formula cited is:
$$ AO = 1.0 - \frac{occluded}{total} \times 0.5 $$
where `occluded` is the count of solid neighbors in the visible hemisphere, and `total` is the count of all neighbors in the visible hemisphere [S2, unofficial].

An alternative formula found in sources uses scalar voxel occupancy values `side` and `corner`:
$$ AO = \frac{side.x + side.y + \max(corner, side.x \times side.y)}{10.0} $$
where `side` and `corner` are scalar voxel occupancy values (0.0 or 1.0) [S1, unofficial]. The sources do not specify how `side.x`, `side.y`, and `corner` are derived from the voxel grid or vertex position in this context.

**Parameters:**
- The darkening intensity multiplier is 0.5 [S2, unofficial].

**Edge cases and pitfalls:**
- Boundary checks: The `get` closure returns `false` (non-solid) if coordinates are outside the voxel grid bounds, preventing out-of-bounds access [S2, unofficial].
- Zero neighbors: If `total` is 0 (e.g., isolated vertex or normal pointing into empty space with no neighbors in the hemisphere), the AO factor is 1.0 [S2, unofficial].

**Pseudocode:**
```python
def compute_vertex_ao_approximation(vertex_x, vertex_y, vertex_z, normal, get_voxel):
    """
    Computes ambient occlusion for a vertex based on voxel neighbors.
    
    Args:
        vertex_x, vertex_y, vertex_z: Integer voxel coordinates of the vertex.
        normal: A 3D vector (x, y, z) representing the vertex normal.
        get_voxel: A function/closure that returns True if the voxel at (x,y,z) is solid, False otherwise.
                   Returns False for out-of-bounds coordinates.
    
    Returns:
        float: Ambient occlusion factor between 0.0 and 1.0.
    """
    total = 0
    occluded = 0
    
    # Iterate through 26 neighbors
    for dx in [-1, 0, 1]:
        for dy in [-1, 0, 1]:
            for dz in [-1, 0, 1]:
                # Skip the center voxel
                if dx == 0 and dy == 0 and dz == 0:
                    continue
                
                # Calculate direction vector to neighbor
                # Note: The normal is assumed to be normalized or the dot product is compared against 0
                # The source uses dot product to determine if neighbor is on the 'back' side
                dot = dx * normal.x + dy * normal.y + dz * normal.z
                
                # Skip neighbors on the back side of the surface
                if dot < 0:
                    continue
                
                # Neighbor is in the visible hemisphere
                total += 1
                
                # Check if the neighbor voxel is solid
                if get_voxel(vertex_x + dx, vertex_y + dy, vertex_z + dz):
                    occluded += 1
    
    # Compute AO factor
    if total == 0:
        return 1.0
    
    ao_factor = 1.0 - (occluded / total) * 0.5
    return ao_factor
```

## Subtopics

### [Smooth Vertex Lighting with Ambient Occlusion Effect](10956-smooth-vertex-lighting-with-ambient-occlusion-effect.md)
This method calculates the lighting value for a specific vertex of a polygon mesh generated from voxel data by averaging the light intensities of the four surrounding voxel cells in the direction of the face normal. It solves the problem of harsh, blocky lighting transitions and incorrect zero-light values on blocked faces by sampling neighbors rather than the cell itself. Unlike standard ray-casted ambient occlusion, it achieves a similar darkening effect in concave areas as a side effect of this averaging process, without the computational cost of ray casting. See [Smooth Vertex Lighting with Ambient Occlusion Effect](10956-smooth-vertex-lighting-with-ambient-occlusion-effect.md).

### Least-Square Baking
A method using signal processing to improve interpolated ambient occlusion factors by minimizing the distance between samples and interpolated data in the least-square sense [S3, unofficial]. It samples the occlusion signal uniformly across the mesh and derives vertex values to minimize the error between samples and interpolated data [S3, unofficial]. Developed for vertex data storage but can be applied to texture and volumes [S3, unofficial].

### Blocky Ambient Occlusion Derivation
Computes expected vertex AO purely from local geometry to replace hand-written offset tables, ensuring correctness against occluder positions [S4, unofficial]. For each vertex, it determines the face normal $\mathbf{n}$ and two in-plane steps $\mathbf{e}_1, \mathbf{e}_2$ pointing toward the vertex, then identifies occluder positions at $\mathbf{n}+\mathbf{e}_1$, $\mathbf{n}+\mathbf{e}_2$, and $\mathbf{n}+\mathbf{e}_1+\mathbf{e}_2$ [S4, unofficial]. The formula is $AO = 0.4$ if both sides are occluded; otherwise $AO = 1 - 0.2 \times \text{count\_of\_occluders}$ [S4, unofficial]. It replaces previous hand-written offset triples that required reordering when coordinate fixes were applied [S4, unofficial].

## Operating characteristics
Time complexity is $O(1)$ per vertex, as it always checks a fixed 26-neighbor neighborhood. Memory complexity is $O(1)$ auxiliary space. The method is computationally inexpensive compared to ray casting, making it suitable for real-time applications [S2, unofficial]. However, the approximation may not accurately represent complex shadowing patterns compared to ray-traced methods. The quality depends on the voxel resolution and the accuracy of the vertex normals.

## Background
The method is described in the context of voxel-based lighting in game engines, specifically in the Prometheus Engine [S2, unofficial] and Bevy Voxel Engine [S1, unofficial]. It is a simple approximation used to enhance visual quality in voxel-based rendering by simulating ambient occlusion effects at the vertex level.
