# Blocky Ambient Occlusion Derivation

Also called: 0ao, 0ao AO, 0ao.html technique, AO from geometry, Classic Voxel AO, Vertex Ambient Occlusion (Mikola Lysenko 0ao), Voxel Ambient Occlusion (Lysenko), vertex AO proptest

## Overview
Blocky Ambient Occlusion computes the expected ambient occlusion value for a mesh vertex using only local voxel geometry, eliminating hand-written offset tables and expensive raycasting [S1, unofficial]. It determines vertex darkness by sampling the occupancy of two edge-adjacent and one corner-adjacent neighbor blocks relative to the vertex and face normal [S2, unofficial]. Unlike sibling methods that rely on precomputed lookup tables, this derivation calculates neighbor directions deterministically from the face normal and vertex position, ensuring correctness against actual occluder coordinates [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** Vertex integer coordinates $(x, y, z)$, face normal $\mathbf{n} = (n_x, n_y, n_z)$, and a boolean function `isSolid(pos)` that returns `true` if the voxel at `pos` is occupied [S2, unofficial].
*   **Output:** A normalized ambient occlusion value $AO \in [0.0, 1.0]$, where $0.0$ represents fully occluded (dark) and $1.0$ represents fully lit [S2, unofficial].

**Data Structures**
*   **Vertex Position:** $(x, y, z)$, integer grid coordinates [S2, unofficial].
*   **Face Normal:** $\mathbf{n}$, a unit vector indicating the outward direction of the face [S1, unofficial].
*   **In-Plane Steps:** $\mathbf{e}_1, \mathbf{e}_2$, unit vectors pointing from the face center toward the vertex along the face's plane [S1, unofficial].

**Steps**
1.  **Determine In-Plane Steps:** Identify $\mathbf{e}_1$ and $\mathbf{e}_2$ based on the non-zero component of $\mathbf{n}$ and the vertex coordinates relative to the face center [S2, unofficial].
    *   If $n_x \neq 0$, the in-plane axes are Y and Z. $\mathbf{e}_1$ points along $\pm \hat{y}$ and $\mathbf{e}_2$ along $\pm \hat{z}$, with signs determined by whether $y$ and $z$ are positive or negative relative to the face center [S2, unofficial].
    *   If $n_y \neq 0$, the in-plane axes are X and Z. $\mathbf{e}_1$ points along $\pm \hat{x}$ and $\mathbf{e}_2$ along $\pm \hat{z}$ [S2, unofficial].
    *   If $n_z \neq 0$, the in-plane axes are X and Y. $\mathbf{e}_1$ points along $\pm \hat{x}$ and $\mathbf{e}_2$ along $\pm \hat{y}$ [S2, unofficial].
2.  **Identify Neighbor Positions:** Calculate the coordinates of the three neighbor blocks to sample [S2, unofficial]:
    *   Edge-adjacent neighbor 1: $\mathbf{p}_1 = (x, y, z) + \mathbf{n} + \mathbf{e}_1$
    *   Edge-adjacent neighbor 2: $\mathbf{p}_2 = (x, y, z) + \mathbf{n} + \mathbf{e}_2$
    *   Corner-adjacent neighbor: $\mathbf{p}_c = (x, y, z) + \mathbf{n} + \mathbf{e}_1 + \mathbf{e}_2$ [S2, unofficial].
3.  **Sample Occupancy:** Check the solidity of the identified neighbors using `isSolid` [S2, unofficial]:
    *   $s_1 = \text{isSolid}(\mathbf{p}_1)$
    *   $s_2 = \text{isSolid}(\mathbf{p}_2)$
    *   $s_c = \text{isSolid}(\mathbf{p}_c)$
4.  **Calculate Raw Occlusion Count:** Compute the raw count $C$ based on the number of solid neighbors [S2, unofficial]:
    *   $C = 3 - (s_1 ? 1 : 0) - (s_2 ? 1 : 0) - (s_c ? 1 : 0)$
    *   $C$ ranges from $0$ (all three neighbors solid, fully occluded) to $3$ (no neighbors solid, fully lit) [S2, unofficial].
5.  **Normalize:** Divide the raw count by $3.0$ to map it to the standard brightness range [S2, unofficial]:
    *   $AO = C / 3.0$

**Formulas**
The primary derivation uses a linear count subtracted from three, normalized by three: $AO = \frac{3 - s_1 - s_2 - s_c}{3.0}$ [S2, unofficial]. An alternative rule cited in testing notes states that if both edge neighbors are solid the value is fixed at $0.4$, otherwise it scales as $1 - 0.2 \times \text{count}$ [S1, unofficial]. Both rules map higher occlusion to darker values, but the linear count formula is the canonical geometric derivation [S1, S2, unofficial].

**Parameters**
*   `AO_CURVE`: An array of four floats mapping integer AO levels $0$ through $3$ to brightness multipliers: `[0.55, 0.70, 0.85, 1.00]` [S2, unofficial]. This curve provides softer ambient occlusion than linear interpolation [S2, unofficial].

**Pitfalls and Edge Cases**
*   **Concave Artifacts:** Inconsistent AO values across a quad can cause incorrect winding perception [S2, unofficial]. Fix by flipping triangle indices when `(aoVals[0] + aoVals[2]) < (aoVals[1] + aoVals[3])` [S2, unofficial].
*   **Boundary Checks:** `isSolid` must handle grid boundaries or return `false` for out-of-bounds coordinates to prevent crashes [G].
*   **Normal Consistency:** The face normal must align with the vertex ordering to compute correct in-plane step signs [G].

**Pseudocode**
```python
def compute_blocky_ao(x: int, y: int, z: int, nx: float, ny: float, nz: float, is_solid: callable) -> float:
    # 1. Determine in-plane step directions based on face normal
    if abs(nx) > 0.5:
        # Normal along X; in-plane axes are Y and Z
        e1 = [0, 1 if y > 0 else -1, 0]
        e2 = [0, 0, 1 if z > 0 else -1]
    elif abs(ny) > 0.5:
        # Normal along Y; in-plane axes are X and Z
        e1 = [1 if x > 0 else -1, 0, 0]
        e2 = [0, 0, 1 if z > 0 else -1]
    else:
        # Normal along Z; in-plane axes are X and Y
        e1 = [1 if x > 0 else -1, 0, 0]
        e2 = [0, 1 if y > 0 else -1, 0]

    # 2. Identify neighbor positions
    p1 = [x + nx + e1[0], y + ny + e1[1], z + nz + e1[2]]
    p2 = [x + nx + e2[0], y + ny + e2[1], z + nz + e2[2]]
    pc = [x + nx + e1[0] + e2[0], y + ny + e1[1] + e2[1], z + nz + e1[2] + e2[2]]

    # 3. Sample occupancy
    s1 = 1 if is_solid(p1) else 0
    s2 = 1 if is_solid(p2) else 0
    sc = 1 if is_solid(pc) else 0

    # 4. Calculate raw occlusion count
    c = 3 - s1 - s2 - sc

    # 5. Normalize to [0.0, 1.0]
    return c / 3.0
```

## Operating characteristics
*   **Time Complexity:** $O(1)$ per vertex, requiring exactly three `isSolid` calls and constant arithmetic [S2, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary space, eliminating the need for large offset tables or raycasting buffers [S1, unofficial].
*   **Performance:** Significantly faster than raycasting or marching cubes AO because it avoids traversal and intersection tests [S1, unofficial]. Suitable for real-time mesh generation in voxel engines [S2, unofficial].
*   **Strengths:** Deterministic, replaces error-prone hand-written offset tables, and produces smooth contact shadows [S1, S2, unofficial].
*   **Limitations:** Approximate; does not account for distance-based attenuation or complex multi-bounce occlusion [G]. Requires winding-order fixes to prevent concave artifacts [S2, unofficial].

## Background
Blocky Ambient Occlusion is a vertex-level technique attributed to Mikola Lysenko (2012) as part of the "0ao" method for voxel rendering [S2, unofficial]. It was developed to replace the 24 hand-written offset triples in `compute_ao`, which required strict ordering alignment with `vertices_and_normal` and broke when coordinate system fixes were applied [S1, unofficial]. The derivation ensures correctness against actual occluder positions and passes property tests over random $3 \times 3 \times 3$ neighborhoods [S1, unofficial].
