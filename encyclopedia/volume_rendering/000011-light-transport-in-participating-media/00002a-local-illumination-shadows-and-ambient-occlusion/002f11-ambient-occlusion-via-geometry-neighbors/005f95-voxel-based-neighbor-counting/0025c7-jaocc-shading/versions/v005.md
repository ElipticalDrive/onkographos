# JAOCC Shading

Also called: Jaocc Occlusion

## Overview
JAOCC Shading is a voxel-based ambient occlusion method that computes a depth-weighted dimming factor by counting non-empty neighbors in a cubic neighborhood [S3, unofficial]. It solves the problem of hard, physically implausible lighting transitions at axis-aligned bounding box (AABB) edges by dynamically determining surface normals from local voxel geometry rather than using fixed AABB face normals [S1, unofficial]. It produces smooth results for higher neighbor counts but is computationally slow and prone to errors with thin objects [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D voxel grid representing scene occupancy (empty or non-empty). Each voxel stores an RGB color value.
*   **Parameters:**
    *   `count`: The radius of the cubic neighborhood to sample (integer). Determines the sampling box size from `-count` to `+count`. Higher values produce smoother but slower results [S3, unofficial].
    *   `depth`: A float parameter controlling occlusion intensity, typically in the range $[0.01, 1.0]$. Values closer to 1 produce the hardest (most contrasty) shading [S3, unofficial].
*   **Output:** Shaded RGB values for each voxel, where color components are multiplied by a computed dimming factor and clamped to $[0, 255]$ [S3, unofficial].

**Data Structures:**
*   **Voxel Grid:** A 3D array of size $X \times Y \times Z$.
    *   Occupancy: Boolean or integer flag indicating if a voxel is empty or non-empty.
    *   Color: RGB tuple or integer representation of the voxel's base color.
*   **Neighbor Access:** Direct indexing into the voxel grid using offset coordinates $(x_n, y_n, z_n)$.

**Algorithm Steps:**

1.  **Iterate Voxels:** Loop through all voxels in the volume. The loop bounds exclude the boundary to ensure all neighbors within the `count` radius exist:
    *   $x$ from `count` to $X - \text{count} - 1$
    *   $y$ from `count` to $Y - \text{count} - 1$ (or $Y_{start} + \text{count}$)
    *   $z$ from `count` to $Z - \text{count} - 1$
    *   Skip voxels that are empty [S3, unofficial].

2.  **Calculate Maximum Dimension (`max_dim`):**
    This value normalizes the occlusion count. It represents the maximum possible weighted neighbor count for the given `count` radius.
    *   Initialize `max_dim` = 0.
    *   Iterate $x_n$ from $-\text{count}$ to $\text{count}$.
    *   Iterate $y_n$ from $-\text{count}$ to $\text{count}$.
    *   Iterate $z_n$ from $-\text{count}$ to $\text{count}$.
    *   For each triplet $(x_n, y_n, z_n)$:
        *   Let $y_{k1} = 1$ if $y_n > 0$, else $0$.
        *   Let $y_{k2} = 1$ if $y_n < 0$, else $0$.
        *   Add $(1 + y_{k1} - y_{k2})$ to `max_dim`.
    *   Note: The term $(1 + y_{k1} - y_{k2})$ evaluates to:
        *   $1$ if $y_n = 0$
        *   $2$ if $y_n > 0$
        *   $0$ if $y_n < 0$
    *   This effectively weights neighbors based on their Y-position relative to the center, simulating a projection onto a specific plane or axis alignment [S3, unofficial].

3.  **Compute Occlusion Dimension (`dim`):**
    Calculate the actual weighted occlusion for the current voxel.
    *   Initialize `dim` = 0.
    *   Iterate $x_n$ from $-\text{count}$ to $\text{count}$.
    *   Iterate $y_n$ from $-\text{count}$ to $\text{count}$.
    *   Iterate $z_n$ from $-\text{count}$ to $\text{count}$.
    *   Let $x_{idx} = x + x_n$, $y_{idx} = y + y_n$, $z_{idx} = z + z_n$.
    *   Check if the neighbor at $(x_{idx}, y_{idx}, z_{idx})$ is non-empty.
    *   If non-empty:
        *   Let $y_{k1} = 1$ if $y_n > 0$, else $0$.
        *   Let $y_{k2} = 1$ if $y_n < 0$, else $0$.
        *   Add $(1 + y_{k1} - y_{k2})$ to `dim`.
    *   This step counts non-empty neighbors, weighting them by their Y-offset to approximate the surface orientation [S3, unofficial].

    *Alternative Plane-Specific Neighbor Checks (for finer normal estimation):*
    Some implementations check specific planes to determine the dominant surface normal dynamically:
    *   **Y-Plane Normal:** Check 8 neighbors in the Y-slice: $(x, y-1, z-1), (x-1, y, z-1), (x-1, y, z), (x-1, y, z+1), (x, y, z+1), (x+1, y, z+1), (x+1, y, z), (x+1, y, z-1)$. Calculate AO tuple: $(a+b+c), (g+h+a), (e+f+g), (c+d+e)$ [S2, unofficial].
    *   **X-Plane Normal:** Check 8 neighbors in the X-slice: $(x, y, z-1), (x, y-1, z-1), (x, y-1, z), (x, y-1, z+1), (x, y, z+1), (x, y+1, z+1), (x, y+1, z), (x, y+1, z-1)$ [S2, unofficial].
    *   **Z-Plane Normal:** Check 8 neighbors in the Z-slice: $(x-1, y, z), (x-1, y-1, z), (x, y-1, z), (x+1, y-1, z), (x+1, y, z), (x+1, y+1, z), (x, y+1, z), (x-1, y+1, z)$ [S2, unofficial].
    *   *Note:* The primary JAOCC algorithm described in [S3, unofficial] uses the global `dim` calculation. The plane-specific checks are associated with the broader context of voxel shading normal estimation [S1, unofficial][S2, unofficial].

4.  **Normalize and Apply Shading:**
    *   Calculate `dim_factor`:
        $$ \text{dim\_factor} = \text{clamp}\left( \left( 1.0 - \frac{\text{clamp}(\text{dim}, 0, \text{max\_dim})}{\text{max\_dim}} \right) \times \text{depth} + (1 - \text{depth}), 0, 1 \right) $$
    *   Multiply the voxel's RGB components by `dim_factor`.
    *   Clamp the result to $[0, 255]$ [S3, unofficial].

**Pseudocode:**

```python
def jaocc_shade(voxel_grid, x_size, y_size, z_size, count, depth):
    """
    Applies JAOCC shading to a voxel grid.
    
    Args:
        voxel_grid: 3D array (x, y, z) storing occupancy (bool) and color (RGB tuple).
        x_size, y_size, z_size: Dimensions of the voxel grid.
        count: Radius of the cubic neighborhood.
        depth: Occlusion intensity parameter [0.01, 1.0].
        
    Returns:
        Shaded voxel grid with modified RGB values.
    """
    
    # Pre-calculate max_dim
    max_dim = 0
    for xn in range(-count, count + 1):
        for yn in range(-count, count + 1):
            for zn in range(-count, count + 1):
                yk1 = 1 if yn > 0 else 0
                yk2 = 1 if yn < 0 else 0
                max_dim += (1 + yk1 - yk2)
                
    # Handle edge case where max_dim is 0 (should not happen for count >= 0)
    if max_dim == 0:
        return voxel_grid

    shaded_grid = copy(voxel_grid)

    for x in range(count, x_size - count):
        for y in range(count, y_size - count):
            for z in range(count, z_size - count):
                # Skip empty voxels
                if not voxel_grid[x, y, z].occupied:
                    continue
                
                # Calculate dim
                dim = 0
                for xn in range(-count, count + 1):
                    for yn in range(-count, count + 1):
                        for zn in range(-count, count + 1):
                            # Check bounds for neighbor access (though loop bounds usually prevent this)
                            nx, ny, nz = x + xn, y + yn, z + zn
                            if 0 <= nx < x_size and 0 <= ny < y_size and 0 <= nz < z_size:
                                if voxel_grid[nx, ny, nz].occupied:
                                    yk1 = 1 if yn > 0 else 0
                                    yk2 = 1 if yn < 0 else 0
                                    dim += (1 + yk1 - yk2)
                
                # Clamp dim to [0, max_dim]
                clamped_dim = max(0, min(dim, max_dim))
                
                # Calculate dim_factor
                # Formula: clamp((1.0 - (clamp(dim, 0, max_dim) / max_dim)) * depth + (1 - depth), 0, 1)
                ratio = clamped_dim / max_dim
                factor = (1.0 - ratio) * depth + (1 - depth)
                dim_factor = max(0.0, min(1.0, factor))
                
                # Apply shading
                base_color = voxel_grid[x, y, z].color
                shaded_color = (
                    max(0, min(255, int(base_color.r * dim_factor))),
                    max(0, min(255, int(base_color.g * dim_factor))),
                    max(0, min(255, int(base_color.b * dim_factor)))
                )
                
                shaded_grid[x, y, z].color = shaded_color

    return shaded_grid
```

## Subtopics

### Compensation Map
A nonlinear rescaling technique applied to JAOCC results to mitigate errors from artificial multiple occlusion [S4, unofficial].
*   **Definition:** Rescales computed AO for highly occluded regions using a 1D luminance texture encoded on the GPU. It automatically clamps input AO to $[0, 1]$ [S4, unofficial].
*   **Purpose:** Corrects overdarkening caused by objects thinner than $\delta$ being in proximity closer than $\delta$, where the occlusion volume of one object passes entirely through another [S4, unofficial].
*   **Parameter:** The curve is fitted using AOV results from multiple viewpoints of reference scenes (Suburb, House) against ray-traced results. The right end of the curve is set based on the intuition that a corner with three walls at a right angle has ~75% occlusion [S4, unofficial].
*   **Pitfall:** The compensation map has no physical basis; it is an ad hoc solution for scenes violating the $\delta$-thickness assumption. AO for such scenes is strictly over-estimated, and the correction is roughly parabolic [S4, unofficial].
*   **Performance:** The additional texture fetch impact is below the threshold of measurement [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot (2 \cdot \text{count} + 1)^3)$, where $N$ is the number of non-empty voxels. The cubic neighborhood search makes it expensive for large `count` values [S3, unofficial].
*   **Memory Complexity:** $O(X \cdot Y \cdot Z)$ for the voxel grid. The compensation map adds $O(K)$ memory for a 1D texture of size $K$ [S4, unofficial].
*   **Performance:** The algorithm is noted as slow [S3, unofficial]. The compensation map's performance impact is negligible [S4, unofficial].
*   **Strengths:** Produces smooth results for higher neighbor counts; robust to tessellation and level of detail changes [S3, unofficial][S4, unofficial]. Dynamically determines normals to avoid hard lighting transitions at AABB edges [S1, unofficial].
*   **Limitations:** Errors with thin objects; artificial multiple occlusion artifacts in dense, thin structures; slow computation [S3, unofficial][S4, unofficial].
*   **When to Use:** When smooth ambient occlusion is desired for voxel-based scenes and computational cost is acceptable. Useful for scenes where fixed AABB normals cause visible artifacts [S1, unofficial].
*   **When Not to Use:** For scenes with many thin objects or high-frequency geometry where the $\delta$-thickness assumption is violated, unless the compensation map is applied [S4, unofficial]. For real-time applications requiring high performance, this method may be too slow [S3, unofficial].

## Background
JAOCC Shading originates from voxel-based rendering techniques aimed at improving the visual quality of voxel landscapes. It addresses the specific issue of hard lighting transitions at voxel edges, which are physically implausible due to the fixed normals of axis-aligned bounding boxes [S1, unofficial]. The method was implemented in various voxel engine projects, such as `doommy` and `Minecraft` clones, often as a post-processing or pre-computation step to enhance shading [S2, unofficial][S3, unofficial]. The concept of using neighbor counting for ambient occlusion in voxel grids is also related to Ambient Occlusion Volumes (AOV) by McGuire et al., which introduced the compensation map to handle thin geometry artifacts [S4, unofficial].
