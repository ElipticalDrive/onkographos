# Local Ambient Occlusion (LAO)

Also called: LAO Renderer, Local Ambient Occlusion (LAO) in DVR, Volumetric Ambient Occlusion

## Overview
Local Ambient Occlusion (LAO) is a local shading technique that estimates light contributions from neighboring voxels rather than the entire volume, creating softer shadows and avoiding the complete occlusion of volume parts [S1][S3, unofficial]. It stands between local and global shading, typically by branching rays into random directions within a hemisphere and averaging accumulated translucency [S1][S3, unofficial]. Unlike global lighting, LAO is view-independent and can be precomputed or updated incrementally [S1][S3, unofficial][S4, unofficial].

## How it works
**Inputs:** Volume data (scalar field), Transfer Function (TF), light direction $\mathbf{l}$, kernel radius $R_\Omega$ (number of voxels/distance), kernel size $K$ (number of ray directions), and optional emission parameters [S2, unofficial][S3, unofficial][S4, unofficial][S5].
**Outputs:** An ambient occlusion factor (or contribution) per sample point, stored in an LAO map or integrated into the final color [S3, unofficial][S4, unofficial].

**Data Structures:**
*   **LAO Map:** Stored in a Frame Buffer Object (FBO). The FBO planes correspond to screen coordinates $(x, y)$ and store intensity/light computation results [S4, unofficial].
*   **Volume Representation:** Can be dense or multiresolution (packed coordinates). In multiresolution implementations, volumes are organized into blocks (e.g., $16^3, 8^3, 4^3$) with empty space skipping [S4, unofficial].
*   **Indices:** Mapping between Volume coordinates (V) and Pixel coordinates (P) is required for lookups [S4, unofficial].

**Parameters:**
*   $R_\Omega$ (LAOKernelRadius): Number of voxels traced in each direction [S3, unofficial].
*   $K$ (LAOKernelSize): Number of ray directions [S3, unofficial].
*   $uLAOStepSize$: Step size for ray marching (default 0.05) [S2, unofficial].
*   $uLightRadius$: Radius of the light source for sampling (default 0.19) [S2, unofficial].
*   $uLightCoefficient$: Normalization coefficient (default 1.0) [S2, unofficial].
*   $uLAOWeight$: Weight for mixing LAO into final color (default 0.69) [S2, unofficial].
*   $uNumLAOSamples$: Number of LAO samples per pixel (default 1) [S2, unofficial].

**Algorithm Steps:**

1.  **Direction Generation:** Generate $K$ random directions within a hemisphere oriented around the light vector. Directions can be dynamically configured by subdividing a tetrahedron, icosahedron, or octahedron [S2, unofficial][S4, unofficial]. If $K=1$, LAO is nearly equivalent to volumetric shading with a short ray length [S3, unofficial].
2.  **Ray Marching and Accumulation:** For each sample point, initialize an accumulator. Loop $uNumLAOSamples$ times. Inside, loop $t$ from 0.001 to 1.0 with step $uLAOStepSize$ [S2, unofficial]. Compute a sampling direction or half-vector: $\mathbf{h} = \text{normalize}(\mathbf{l} + \mathbf{d}_i \cdot \text{mix}(0.0, uLightRadius, t) - \mathbf{p})$ [S2, unofficial]. Sample the volume at $\mathbf{p} + \mathbf{h} \cdot t$ [S2, unofficial]. Accumulate the contribution weighted by distance: $A_i \leftarrow A_i + v \cdot (1.0 - t)^2$ [S2, unofficial]. Alternatively, trace voxels and average accumulated translucency [S3, unofficial].
3.  **Normalization:** Divide the accumulated sum by $uLightCoefficient$ and clamp to $[0, 1]$ [S2, unofficial]. Average over all $K$ directions: $\text{LAO}_{\text{factor}} = \frac{1}{K} \sum_{i=1}^{K} A_i$ [S2, unofficial].
4.  **Integration:** Add the LAO contribution to the ambient component of the BRDF model [S3, unofficial]. In the final ray-casting pass, the LAO factor modulates the diffuse/ambient term using $uLAOWeight$ [S2, unofficial].
5.  **Incremental Update:** LAO can be updated incrementally by computing one ray direction per frame [S4, unofficial].

```python
def compute_lao(position, light_dir, kernel_radius, kernel_size, step_size, light_radius, light_coefficient, num_samples):
    total_occlusion = 0.0
    for _ in range(num_samples):
        accumulator = 0.0
        # Generate random direction in hemisphere around light_dir [S2, unofficial]
        rand_vec = (random.uniform(-1, 1), random.uniform(-1, 1), random.uniform(-1, 1))
        rand_scale = random.random()
        length = math.sqrt(rand_vec[0]**2 + rand_vec[1]**2 + rand_vec[2]**2)
        if length > 0:
            random_dir = (rand_vec[0]/length, rand_vec[1]/length, rand_vec[2]/length)
        else:
            random_dir = (0, 0, 1)
        random_dir = (random_dir[0]*rand_scale, random_dir[1]*rand_scale, random_dir[2]*rand_scale)

        t = 0.001
        while t <= 1.0:
            # Compute half-vector/sampling direction [S2, unofficial]
            mix_val = light_radius * t
            half_vec = (light_dir[0] + random_dir[0] * mix_val - position[0],
                        light_dir[1] + random_dir[1] * mix_val - position[1],
                        light_dir[2] + random_dir[2] * mix_val - position[2])
            h_len = math.sqrt(half_vec[0]**2 + half_vec[1]**2 + half_vec[2]**2)
            if h_len > 0:
                sample_dir = (half_vec[0]/h_len, half_vec[1]/h_len, half_vec[2]/h_len)
            else:
                sample_dir = light_dir

            sample_pos = (position[0] + sample_dir[0] * t,
                          position[1] + sample_dir[1] * t,
                          position[2] + sample_dir[2] * t)

            voxel_value = sample_volume(sample_pos)
            weight = (1.0 - t) ** 2
            accumulator += voxel_value * weight
            t += step_size
        accumulator /= light_coefficient
        accumulator = max(0.0, min(1.0, accumulator))
        total_occlusion += accumulator
    lao_factor = total_occlusion / num_samples
    return max(0.0, min(1.0, lao_factor))
```

**Edge Cases and Pitfalls:**
*   When $K=1$, LAO degrades to volumetric shading with a short ray length [S3, unofficial].
*   Multiresolution implementations require increasing the sampling distance for low-resolution blocks to maintain visual consistency [S4, unofficial].
*   Empty space skipping is applied when volume blocks are smaller than $4^3$ to avoid superfluous sampling [S4, unofficial].
*   Performance varies significantly; depending on parameters, LAO could be either slower or faster than standard volumetric shading [S3, unofficial].

**Emissive Tissue Illumination Variant:**
To include colored light emission $c_E(s)$ from sample points along the ray, the integral is modified [S5]:
$$ I_k(x) = \frac{1}{R_\Omega - a} \int_{a}^{R_\Omega} (1 + c_E(s)) \exp\left(-\int_{a}^{s} \tau(u) du\right) ds $$
Here, $c_E(s)$ is the colored light emission parameter at sample point $s$, controlled by the emissive component in the transfer function [S5]. This affects the intensity and color of point $x$ [S5]. The emissive parameter is also included during the final ray-casting step to enhance luminosity [S5].

## Subtopics

### [In-scattering / Emittance Integral](11184-in-scattering-emittance-integral.md)
The In-scattering / Emittance Integral method estimates the light scattered into a volume sample from local light sources by discretizing the emittance integral into a compositing scheme. It sets itself apart from its parent, Local Ambient Occlusion (LAO), by applying similar local sampling principles to compute in-scattered and emissive light contributions rather than just shadowing. It builds on [Local Ambient Occlusion (LAO)](4502-local-ambient-occlusion-lao.md).

### Emissive Tissue Illumination
Modifies the incident light equation to include colored light emission $c_E(s)$ from sample points along the ray [S5]. The integral becomes $I_k(x) = \frac{1}{R_\Omega - a} \int_{a}^{R_\Omega} (1 + c_E(s)) \exp\left(-\int_{a}^{s} \tau(u) du\right) ds$ [S5]. The emissive parameter $c_E(s)$ is controlled by the emissive component in the transfer function and affects the intensity and color of point $x$ [S5]. It is included during the final ray-casting step to enhance luminosity [S5].

## Operating characteristics
*   **Time Complexity:** Depends on $K$ (kernel size) and $R_\Omega$ (kernel radius). Performance varies; depending on parameters, LAO could be either slower or faster than volumetric shading [S3, unofficial].
*   **Memory Complexity:** Requires storage for the LAO map (FBO) if precomputed [S4, unofficial]. Multiresolution implementations reduce memory access by skipping empty blocks ($< 4^3$) [S4, unofficial].
*   **Measured Performance:** On an NVIDIA GF8800 Ultra with 768 MB graphics texture memory, updating one ray in the LAO map took 51 ms/frame, resulting in 27 FPS [S4, unofficial].
*   **Strengths:** Creates soft ambient shadows; avoids fully shadowed regions (undesirable in medical visualization); view-independent; can be updated incrementally [S3, unofficial].
*   **Limitations:** Can be computationally expensive if $K$ and $R_\Omega$ are large; requires careful tuning of kernel parameters [S1][S3, unofficial].
*   **When to use:** Medical visualization where soft shadows and visibility of translucent tissues are desired; interactive applications where global lighting is too slow [S3, unofficial].
*   **When not to use:** When global lighting effects (e.g., deep shadows, caustics) are required; when performance is critical and low-quality local shading is insufficient [S3, unofficial].

## Background
LAO was developed as a local shading technique to address the limitations of global lighting in volume rendering, particularly in medical visualization where complete occlusion of structures is undesirable [S3, unofficial]. It was introduced in preliminary versions around 2010 (Hernell et al.) and further detailed in works by Ljung et al. (2008, 2007) [S1][S4, unofficial][S5]. The technique is implemented in libraries such as VTK.js [S3, unofficial].
