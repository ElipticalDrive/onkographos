# Local Ambient Occlusion (LAO)

Also called: LAO Renderer, Local Ambient Occlusion (LAO) in DVR, Volumetric Ambient Occlusion

## Overview
Local Ambient Occlusion (LAO) is a local shading technique that estimates light contributions from neighboring voxels rather than the entire volume, creating softer shadows and avoiding the complete occlusion of volume parts [S1][S3, unofficial]. It stands between local gradient shading and global lighting, typically by branching rays into random directions within a hemisphere and averaging accumulated translucency [S3, unofficial]. Unlike global lighting, LAO is view-independent and can be precomputed or updated incrementally [S1][S3, unofficial].

## How it works
**Inputs:** Volume data (scalar field), Transfer Function (TF), light direction $\mathbf{l}$, kernel radius $R_\Omega$ (number of voxels/distance), kernel size $K$ (number of ray directions), and optional emission parameters.
**Outputs:** An ambient occlusion factor (or contribution) per sample point, stored in an LAO map or integrated into the final color.

**Data Structures:**
*   **LAO Map:** Stored in a Frame Buffer Object (FBO). The FBO planes correspond to screen coordinates $(x, y)$ and store intensity/light computation results [S4, unofficial].
*   **Volume Representation:** Can be dense or multiresolution (packed coordinates). In multiresolution implementations, volumes are organized into blocks (e.g., $16^3, 8^3, 4^3$) with empty space skipping [S4, unofficial].
*   **Indices:** Mapping between Volume coordinates (V) and Pixel coordinates (P) is required for lookups [S4, unofficial].

**Parameters:**
*   $R_\Omega$ (LAOKernelRadius): Number of voxels traced in each direction [S3, unofficial].
*   $K$ (LAOKernelSize): Number of ray directions [S3, unofficial].
*   $uLAOStepSize$: Step size for ray marching (default 0.05) [S2, unofficial].
*   $uLightRadius$: Radius of the light source for sampling (default 0.19) [S2, unofficial].
*   $uLightCoefficient$: Normalization coefficient (default 1.0) [S2, unofficial].
*   $uLAOWeight$: Weight for mixing LAO into final color (default 0.69) [S2, unofficial].

**Algorithm Steps:**

1.  **Direction Generation:** Generate $K$ random directions within a hemisphere oriented around the light vector or surface normal. Directions can be dynamically configured by subdividing a tetrahedron, icosahedron, or octahedron [S4, unofficial].
    *   *Note:* If $K=1$, LAO is nearly equivalent to volumetric shading with a short ray length [S3, unofficial].

2.  **Ray Marching and Accumulation:** For each direction $i \in \{1, \dots, K\}$:
    *   Initialize accumulator $A_i = 0$.
    *   March along the ray from distance $t = 0.001$ to $t = 1.0$ (normalized) with step $uLAOStepSize$ [S2, unofficial].
    *   At each step $t$, sample the volume at position $\mathbf{p} + \mathbf{d}_i \cdot t$.
    *   Compute the LAO half-vector or sample position based on the light direction and random offset [S2, unofficial]:
        $$ \mathbf{h} = \text{normalize}(\mathbf{l} + \mathbf{d}_i \cdot \text{mix}(0.0, uLightRadius, t) - \mathbf{p}) $$
        *(Note: Source [S2, unofficial] describes a specific implementation using a half-vector; Source [S3, unofficial] describes simpler hemisphere branching. The core concept is sampling neighbors.)*
    *   Sample the volume value $v$ at the current position.
    *   Accumulate the contribution weighted by distance. Source [S2, unofficial] uses a quadratic falloff:
        $$ A_i \leftarrow A_i + v \cdot (1.0 - t)^2 $$
    *   *Alternative (Source [S3, unofficial]):* Accumulate translucency/opacity directly.

3.  **Normalization:**
    *   Divide the accumulated sum by $uLightCoefficient$ and clamp to $[0, 1]$ [S2, unofficial].
    *   Average over all $K$ directions:
        $$ \text{LAO}_{\text{factor}} = \frac{1}{K} \sum_{i=1}^{K} A_i $$

4.  **Integration:**
    *   Add the LAO contribution to the ambient component of the BRDF model [S3, unofficial].
    *   In the final ray-casting pass, the LAO factor modulates the diffuse/ambient term. The final color $C$ might be computed as:
        $$ C = C_{\text{base}} \cdot (1 - \text{LAO}_{\text{factor}} \cdot uLAOWeight) + C_{\text{ambient}} $$
        *(Implementation detail: The exact mixing formula depends on the specific renderer, but LAO typically darkens the ambient/diffuse term.)*

5.  **Incremental Update (Optional):**
    *   LAO can be updated incrementally by computing one ray direction per frame [S4, unofficial]. This allows for interactive performance.

**Pseudocode (GLSL-like fragment shader logic for a single sample):**

```python
# Inputs:
# position: vec3, current sample position in volume
# lightDir: vec3, normalized light direction
# kernelRadius: float, R_Omega
# kernelSize: int, K
# stepSize: float, uLAOStepSize

def compute_lao(position, lightDir, kernelRadius, kernelSize, stepSize):
    total_occlusion = 0.0
    
    # Generate K random directions in a hemisphere around lightDir
    # For simplicity, assume pre-generated random directions d_i
    for i in range(kernelSize):
        direction = get_random_direction_in_hemisphere(lightDir)
        accumulator = 0.0
        
        # March along the ray
        # t represents normalized distance, scaled by kernelRadius if needed
        t = 0.001
        while t <= 1.0:
            # Sample position
            # Note: Actual world position depends on volume bounds and resolution
            sample_pos = position + direction * (t * kernelRadius)
            
            # Sample volume value (opacity/density)
            # In a real implementation, this involves texture lookup and TF application
            voxel_value = sample_volume(sample_pos)
            
            # Weight by distance (quadratic falloff as per [S2, unofficial])
            weight = pow(1.0 - t, 2.0)
            
            accumulator += voxel_value * weight
            
            t += stepSize
            
        # Normalize by light coefficient (assumed 1.0 for simplicity)
        # Accumulate to total
        total_occlusion += accumulator
        
    # Average over K directions
    lao_factor = total_occlusion / kernelSize
    
    # Clamp to [0, 1]
    lao_factor = clamp(lao_factor, 0.0, 1.0)
    
    return lao_factor
```

**Emissive Tissue Illumination Variant:**
To include colored light emission $c_E(s)$ from sample points along the ray, the integral is modified [S5]:
$$ I_k(x) = \frac{1}{R_\Omega - a} \int_{a}^{R_\Omega} (1 + c_E(s)) \exp\left(-\int_{a}^{s} \tau(u) du\right) ds $$
Here, $c_E(s)$ is the colored light emission parameter at sample point $s$, controlled by the emissive component in the transfer function [S5]. This affects the intensity and color of point $x$ [S5].

## Subtopics

### [In-scattering / Emittance Integral](11184-in-scattering-emittance-integral.md)
The In-scattering / Emittance Integral method estimates the light scattered into a volume sample from local light sources by discretizing the emittance integral into a compositing scheme. It sets itself apart from its parent, Local Ambient Occlusion (LAO), by applying similar local sampling principles to compute in-scattered and emissive light contributions rather than just shadowing. It builds on [Local Ambient Occlusion (LAO)](4502-local-ambient-occlusion-lao.md).

## Operating characteristics
*   **Time Complexity:** Depends on $K$ (kernel size) and $R_\Omega$ (kernel radius). Performance varies; depending on parameters, LAO could be either slower or faster than volumetric shading [S3, unofficial].
*   **Memory Complexity:** Requires storage for the LAO map (FBO) if precomputed [S4, unofficial]. Multiresolution implementations reduce memory access by skipping empty blocks ($< 4^3$) [S4, unofficial].
*   **Measured Performance:** On an NVIDIA GF8800 Ultra with 768 MB graphics texture memory, updating one ray in the LAO map took 51 ms/frame, resulting in 27 FPS [S4, unofficial].
*   **Strengths:** Creates soft ambient shadows; avoids fully shadowed regions (undesirable in medical visualization); view-independent; can be updated incrementally [S3, unofficial].
*   **Limitations:** Can be computationally expensive if $K$ and $R_\Omega$ are large; requires careful tuning of kernel parameters [S1][S3, unofficial].
*   **When to use:** Medical visualization where soft shadows and visibility of translucent tissues are desired; interactive applications where global lighting is too slow [S3, unofficial].
*   **When not to use:** When global lighting effects (e.g., deep shadows, caustics) are required; when performance is critical and low-quality local shading is insufficient [S3, unofficial].

## Background
LAO was developed as a local shading technique to address the limitations of global lighting in volume rendering, particularly in medical visualization where complete occlusion of structures is undesirable [S3, unofficial]. It was introduced in preliminary versions around 2010 (Hernell et al.) and further detailed in works by Ljung et al. (2008, 2007) [S1][S4, unofficial][S5]. The technique is implemented in libraries such as VTK.js [S3, unofficial].
