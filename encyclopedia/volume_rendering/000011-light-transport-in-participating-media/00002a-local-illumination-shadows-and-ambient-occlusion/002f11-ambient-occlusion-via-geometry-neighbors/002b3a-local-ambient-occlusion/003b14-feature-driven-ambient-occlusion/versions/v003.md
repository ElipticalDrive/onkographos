# Feature-Driven Ambient Occlusion

Also called: Feature-Driven AO

## Overview
Feature-Driven Ambient Occlusion is a shading technique for direct volume rendering that computes ambient occlusion separately for identified features (layers) to prevent the overdarkening of internal layers caused by inter-occlusions from neighboring features, while preserving auto-occlusions [S1]. Unlike classical ambient occlusion which darkens internal layers in multi-layer volumes due to inter-occlusions, this method neglects inter-occlusions between features to prevent overdarkening while keeping auto-occlusions [S1]. It sets itself apart from siblings like [Local Ambient Occlusion](4300-local-ambient-occlusion-for-volume-rendering.md) by explicitly separating occlusion computation per feature class rather than treating the volume as a single homogeneous medium, and from [Local Ambient Occlusion (LAO)](4502-local-ambient-occlusion-lao.md) by using feature classification to improve shading rather than using occlusion for data classification [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume dataset $V$, a transfer function mapping scalar values to color and opacity, a set of $n_f$ identified features (layers) $k \in [1, n_f]$, and parameters $L$ (number of rays), $M$ (number of samples per ray), and $R_\Omega$ (occlusion sphere radius) [S1].
*   **Output:** A final 3D ambient occlusion volume $AO(v)$ and the ability to render the volume with precomputed occlusion factors [S1].

**Data Structures:**
*   **Bricks:** The 3D dataset is decomposed into equal-sized bricks. Each brick stores a boolean indicating if it contains only empty voxels. Bricks overlap to prevent discontinuities at borders [S1].
*   **Occlusion Textures:** $n_f$ separate 3D textures $T_k$ are computed, one for each feature $k$. Each texture stores the occlusion factor for voxels belonging to feature $k$ [S1].
*   **Final AO Volume:** A single 3D texture storing the recombined ambient occlusion values [S1].

**Algorithm Steps:**

1.  **Preprocessing (Bricking):**
    Decompose the 3D dataset into equal-sized bricks. Scan each brick to determine if it contains only empty voxels. Store this as a boolean flag. Use overlapping bricks to prevent discontinuities at borders [S1].

2.  **Per-Feature Occlusion Computation:**
    For each feature $k$ from $1$ to $n_f$:
    a.  Initialize an empty 3D texture $T_k$.
    b.  For each voxel $v_k$ belonging to feature $k$:
        i.  Cast $L$ rays uniformly scattered in the hemisphere around the voxel normal (or using pseudo-random rays in polar coordinates) [S1].
        ii. For each ray, compute the light contribution $I_l(x_v, k)$ using $M$ samples in a front-to-back compositing scheme.
        iii. During sampling, for any sample point $x_i$ along the ray:
            *   If the sample point belongs to feature $k$, use its actual opacity $\alpha_{i,k}$ obtained via the transfer function.
            *   If the sample point belongs to a different feature $j \neq k$ or is empty, set its opacity $\alpha_{i,j} = 0$ [S1].
        iv. Store the resulting occlusion factor in $T_k(v_k)$ [S1].
    c.  Raycast only non-empty voxels during this phase to optimize performance, skipping large blocks of empty voxels [S1].

3.  **Recombination:**
    Combine the separate occlusion textures $T_k$ into the final ambient occlusion volume $AO(v)$ using the maximum operator:
    $$ AO(v) = \max \{ T_k(v) \mid \forall k \in [1, n_f] \} $$
    This operator is preferred over averaging because it reduces artifacts, improves contrast, and extends the influence of opaque features to neighboring less opaque ones, which is acceptable as less opaque features are less visible [S1].

4.  **Rendering:**
    Perform final rendering using a traditional volume raycasting algorithm (e.g., in GLSL). Fetch one additional texture for the precomputed ambient occlusion factor $AO(v)$ and two additional textures for preintegrated volume rendering [S1].

**Formulas:**

The light contribution $I_l(x_v, k)$ for a single ray for feature $k$ is approximated using $M$ samples:
$$ I_l(x_v, k) = \frac{1}{M} \sum_{m=0}^{M-1} \prod_{i=0}^{m-1} (1 - \alpha_{i,k}) $$
where $\alpha_{i,k}$ is the opacity of sample $i$ for feature $k$. If sample $i$ does not belong to feature $k$, $\alpha_{i,k} = 0$ [S1].

The total light contribution for voxel $v$ is the sum of contributions from all features:
$$ I_l(x_v) = \sum_{k=1}^{n_f} I_l(x_v, k) $$

The ambient occlusion factor $AO(v)$ is computed by averaging the light contributions over $L$ rays:
$$ AO(v) = \frac{1}{L} \sum_{l=1}^{L} I_l(x_v) $$
However, in the final recombination step, the method uses the maximum of the precomputed per-feature occlusion textures $T_k(v)$, which represent the occlusion factor derived from the above integrals [S1].

**Parameters:**
*   $L$: Number of cast rays used to sample the hemisphere for ambient occlusion computation [S1].
*   $M$: Number of samples used to approximate the integral for light contribution along a single ray [S1].
*   $R_\Omega$: Sphere radius used for the occlusion region. If too large, it causes overocclusion; if too small, it results in poor shading [S1].
*   $n_f$: Number of features identified in the dataset [S1].
*   $\alpha_i$: Opacity of sample $i$, obtained via the transfer function [S1].

**Edge Cases and Pitfalls:**
*   **Visual Artifacts at Borders:** Naively setting opacity of neighboring features to 0 during a single pass causes visual artifacts (white dots) at feature borders due to ray sampling and trilinear interpolation when there is a connected area with a different ambient occlusion value [S1].
*   **Inaccurate Averaging:** Averaging all occlusion textures $T_k$ results in inaccurate ambient occlusion values, especially when a low occluding feature borders a high occluding one [S1].
*   **Performance Cost:** Computing separate ambient occlusion textures increases computation cost by a factor equal to the number of features $n_f$ [S1].
*   **Brick Overlap:** Insufficient overlap in bricks can introduce discontinuities at brick borders [S1].

**Pseudocode:**

```python
def compute_feature_driven_ao(volume, features, transfer_function, L, M, R_Omega):
    """
    Computes Feature-Driven Ambient Occlusion for a volume.
    
    Args:
        volume: 3D array of scalar values.
        features: List of 3D boolean masks, one for each feature k.
        transfer_function: Function mapping scalar value to (color, opacity).
        L: Number of rays per voxel.
        M: Number of samples per ray.
        R_Omega: Radius of the occlusion sphere.
        
    Returns:
        ao_volume: 3D array of ambient occlusion factors.
    """
    n_f = len(features)
    shape = volume.shape
    # Initialize per-feature occlusion textures
    # T_k[v] stores the occlusion factor for voxel v if v belongs to feature k
    # If v does not belong to feature k, T_k[v] is undefined/ignored
    T = [np.zeros(shape) for _ in range(n_f)]
    
    # Precompute brick structure for optimization
    # bricks: list of (start_coords, end_coords, is_empty)
    # Note: Implementation details of bricking are omitted as they are 
    # standard volume rendering optimizations. We assume raycasting 
    # skips empty bricks.
    brick_structure = preprocess_bricks(volume)
    
    for k in range(n_f):
        feature_mask = features[k]
        # Iterate over all voxels in the volume
        # Optimization: Only iterate over non-empty bricks and voxels belonging to feature k
        for v in get_voxel_indices(volume, brick_structure):
            if not feature_mask[v]:
                continue
                
            # Compute occlusion for voxel v for feature k
            occlusion_sum = 0.0
            
            # Cast L rays
            for l in range(L):
                ray_direction = get_random_hemisphere_direction(v)
                light_contribution = 0.0
                
                # Sample along the ray
                for m in range(M):
                    # Calculate sample position along the ray
                    # Assuming uniform sampling within R_Omega or similar
                    sample_pos = v + ray_direction * (m + 0.5) * (R_Omega / M)
                    
                    # Get opacity at sample position
                    # If sample_pos is outside volume, opacity is 0
                    if is_outside_volume(sample_pos):
                        alpha = 0.0
                    else:
                        scalar_val = interpolate_volume(volume, sample_pos)
                        _, alpha = transfer_function(scalar_val)
                        
                        # Key step: If sample does not belong to feature k, set opacity to 0
                        # This ignores inter-occlusions from other features
                        if not feature_mask[round(sample_pos)]:
                            alpha = 0.0
                            
                    # Front-to-back compositing for light contribution
                    # Product of (1 - alpha) for previous samples
                    transmittance = 1.0
                    for i in range(m):
                        prev_sample_pos = v + ray_direction * (i + 0.5) * (R_Omega / M)
                        if is_outside_volume(prev_sample_pos):
                            prev_alpha = 0.0
                        else:
                            prev_scalar_val = interpolate_volume(volume, prev_sample_pos)
                            _, prev_alpha = transfer_function(prev_scalar_val)
                            if not feature_mask[round(prev_sample_pos)]:
                                prev_alpha = 0.0
                        transmittance *= (1.0 - prev_alpha)
                        
                    light_contribution += transmittance * alpha
                    
                light_contribution /= M
                occlusion_sum += light_contribution
                
            # Average over L rays
            T[k][v] = occlusion_sum / L
            
    # Recombine using maximum operator
    ao_volume = np.zeros(shape)
    for v in get_voxel_indices(volume, brick_structure):
        max_val = 0.0
        for k in range(n_f):
            # Only consider T_k[v] if v belongs to feature k
            # However, the paper suggests taking max over all k for any voxel v
            # to extend influence of opaque features.
            # The formula is AO(v) = max{T_k(v) | forall k}
            # Note: T_k(v) is only valid/computed if v belongs to feature k.
            # If v does not belong to feature k, T_k(v) is 0 or undefined.
            # The paper states: "AO(v) = max{T_k(v) | forall k in [1, nf]}"
            # This implies we take the max of the computed values.
            # If v is not in feature k, T_k(v) was not computed or is 0.
            # We assume T_k[v] is 0 if v is not in feature k.
            if features[k][v]:
                max_val = max(max_val, T[k][v])
        ao_volume[v] = max_val
        
    return ao_volume
```

## Subtopics

### Local Ambient Occlusion for Volume Rendering
A general method for computing AO in volumes without feature separation. Choose when feature boundaries are not distinct or when computational cost must be minimized. [Link](4300-local-ambient-occlusion-for-volume-rendering.md)

### Local Ambient Occlusion (LAO)
Uses occlusion for data classification. Choose when the goal is to segment or classify data based on local geometry rather than shading enhancement. [Link](4502-local-ambient-occlusion-lao.md)

## Operating characteristics
*   **Time Complexity:** Computing separate ambient occlusion textures increases computation cost by a factor equal to the number of features $n_f$ [S1].
*   **Memory Complexity:** Requires storing $n_f$ separate 3D occlusion textures plus the final recombined texture, plus brick structures [S1].
*   **Measured Performance:**
    *   On AMD Opteron 2431 with Nvidia GTX 295 (1024x768 viewport):
        *   Orange dataset (256x256x64): No shading ~200 fps, Phong shading ~125 fps, Classical AO ~130 fps, Feature-driven AO ~130 fps [S1].
        *   CT Knee dataset (379x229x305): No shading ~60 fps, Phong shading ~50 fps, Classical AO ~45 fps, Feature-driven AO ~45 fps [S1].
*   **Strengths:** Improves visual quality of multi-layer volumes by preventing overdarkening of internal layers. Less parameter-sensitive than classical AO, improving usability for non-experts. Preserves auto-occlusions for shape perception.
*   **Limitations:** Computationally more expensive than classical AO by a factor of $n_f$. Requires prior feature segmentation (though the method itself does not perform segmentation). Artifacts can occur at feature borders if not handled correctly (mitigated by the max recombination operator).
*   **When to Use:** Direct volume rendering of multi-layer datasets (e.g., CT scans) where features are interleaved and distinct, and visual clarity of internal structures is critical.
*   **When Not to Use:** Single-layer volumes, or when computational resources are severely constrained and $n_f$ is large.

## Background
Feature-Driven Ambient Occlusion was introduced by A. Ancel, J.-M. Dischler, and C. Mongenet in 2010 [S1]. It addresses the limitations of straightforward ambient occlusion application in direct volume rendering, where multi-layer volumes result in overdarkening of internal layers due to inter-occlusions [S1]. The method builds on GPU-based approaches with bricking for acceleration [S1]. It is used in direct volume rendering to improve visual quality and usability for non-experts [S1].
