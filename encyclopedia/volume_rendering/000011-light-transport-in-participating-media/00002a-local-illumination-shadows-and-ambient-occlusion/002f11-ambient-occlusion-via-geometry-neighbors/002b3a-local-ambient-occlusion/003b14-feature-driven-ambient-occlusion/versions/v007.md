# Feature-Driven Ambient Occlusion

Also called: Feature-Driven AO

## Overview
Feature-Driven Ambient Occlusion is a shading technique for direct volume rendering that computes ambient occlusion separately for identified features (layers) to prevent the overdarkening of internal layers caused by inter-occlusions from neighboring features, while preserving auto-occlusions [S1]. Unlike classical ambient occlusion which darkens internal layers in multi-layer volumes due to inter-occlusions, this method neglects inter-occlusions between features to prevent overdarkening while keeping auto-occlusions [S1]. It sets itself apart from siblings like [Local Ambient Occlusion](4300-local-ambient-occlusion-for-volume-rendering.md) by explicitly separating occlusion computation per feature class rather than treating the volume as a single homogeneous medium, and from [Local Ambient Occlusion (LAO)](4502-local-ambient-occlusion-lao.md) by using feature classification to improve shading rather than using occlusion for data classification [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume dataset $V$, a transfer function mapping scalar values to color and opacity, a set of $n_f$ identified features (layers) $k \in [1, n_f]$, and parameters $L$ (number of rays), $M$ (number of samples per ray), and $R_\Omega$ (occlusion sphere radius) [S1].
*   **Output:** A final 3D ambient occlusion volume $AO(v)$ and the ability to render the volume with precomputed occlusion factors [S1].

**Data Structures:**
*   **Bricks:** The 3D dataset is decomposed into equal-sized bricks [S1]. Each brick stores a boolean indicating if it contains only empty voxels [S1]. Bricks overlap to prevent discontinuities at borders [S1].
*   **Occlusion Textures:** $n_f$ separate 3D textures $T_k$ are computed, one for each feature $k$ [S1]. Each texture stores the occlusion factor for voxels belonging to feature $k$ [S1].
*   **Final AO Volume:** A single 3D texture storing the recombined ambient occlusion values [S1].

**Algorithm Steps:**

1.  **Preprocessing (Bricking):** Decompose the 3D dataset into equal-sized bricks [S1]. Scan each brick to determine if it contains only empty voxels [S1]. Store this as a boolean flag [S1]. Use overlapping bricks to prevent discontinuities at borders [S1].
2.  **Per-Feature Occlusion Computation:** For each feature $k$ from $1$ to $n_f$:
    a. Initialize an empty 3D texture $T_k$ [S1].
    b. For each voxel $v_k$ belonging to feature $k$:
        i. Cast $L$ rays uniformly scattered in the hemisphere around the voxel normal (or using pseudo-random rays in polar coordinates) [S1].
        ii. For each ray, compute the light contribution $I_l(x_v, k)$ using $M$ samples in a front-to-back compositing scheme [S1].
        iii. During sampling, for any sample point $x_i$ along the ray:
            * If the sample point belongs to feature $k$, use its actual opacity $\alpha_{i,k}$ obtained via the transfer function [S1].
            * If the sample point belongs to a different feature $j \neq k$ or is empty, set its opacity $\alpha_{i,j} = 0$ [S1].
        iv. Store the resulting occlusion factor in $T_k(v_k)$ [S1].
    c. Raycast only non-empty voxels during this phase to optimize performance, skipping large blocks of empty voxels [S1].
3.  **Recombination:** Combine the separate occlusion textures $T_k$ into the final ambient occlusion volume $AO(v)$ using the maximum operator:
    $$ AO(v) = \max \{ T_k(v) \mid \forall k \in [1, n_f] \} $$
    This operator is preferred over averaging because it reduces artifacts, improves contrast, and extends the influence of opaque features to neighboring less opaque ones, which is acceptable as less opaque features are less visible [S1].
4.  **Rendering:** Perform final rendering using a traditional volume raycasting algorithm in GLSL [S1]. Fetch one additional texture for the precomputed ambient occlusion factor $AO(v)$ and two additional textures for preintegrated volume rendering [S1].

**Formulas:**

The light contribution $I_l(x_v, k)$ for a single ray for feature $k$ is approximated using $M$ samples:
$$ I_l(x_v, k) = \frac{1}{M} \sum_{m=0}^{M-1} \prod_{i=0}^{m-1} (1 - \alpha_{i,k}) $$
where $\alpha_{i,k}$ is the opacity of sample $i$ for feature $k$ [S1]. If sample $i$ does not belong to feature $k$, $\alpha_{i,k} = 0$ [S1].

The ambient occlusion texture $T_k(v)$ for feature $k$ at voxel $v$ is the average light contribution over $L$ rays:
$$ T_k(v) = \frac{1}{L} \sum_{l=1}^{L} I_l(x_v, k) $$

The final ambient occlusion volume $AO(v)$ is computed by recombining the per-feature textures with the maximum operator:
$$ AO(v) = \max \{ T_k(v) \mid \forall k \in [1, n_f] \} $$
This replaces the classical feature-summation approach to prevent overdarkening while preserving auto-occlusions [S1].

**Parameters:**
*   $L$: Number of cast rays used to sample the hemisphere for ambient occlusion computation [S1].
*   $M$: Number of samples used to approximate the integral for light contribution along a single ray [S1].
*   $R_\Omega$: Sphere radius used for the occlusion region [S1]. If too large, it causes overocclusion; if too small, it results in poor shading [S1].
*   $n_f$: Number of features identified in the dataset [S1].
*   $\alpha_i$: Opacity of sample $i$, obtained via the transfer function [S1].

**Edge Cases and Pitfalls:**
*   **Visual Artifacts at Borders:** Naively setting opacity of neighboring features to $0$ during a single pass causes visual artifacts (white dots) at feature borders due to ray sampling and trilinear interpolation when there is a connected area with a different ambient occlusion value [S1].
*   **Inaccurate Averaging:** Averaging all occlusion textures $T_k$ results in inaccurate ambient occlusion values, especially when a low occluding feature borders a high occluding one [S1].
*   **Performance Cost:** Computing separate ambient occlusion textures increases computation cost by a factor equal to the number of features $n_f$ [S1].
*   **Brick Overlap:** Insufficient overlap in bricks can introduce discontinuities at brick borders [S1].

**Pseudocode:**

```python
import math

def compute_feature_driven_ao(volume, features, transfer_function, L, M, R_Omega):
    """
    Computes Feature-Driven Ambient Occlusion for a volume.
    
    Args:
        volume: 3D array of scalar values.
        features: List of 3D boolean masks, one for each feature k.
        transfer_function: Function mapping scalar value to (color, opacity).
        L: Number of rays per voxel.
        M: Number of samples per ray.
        R_Omega: Radius of the occlusion sphere.
        
    Returns:
        ao_volume: 3D array of ambient occlusion factors.
    """
    n_f = len(features)
    shape = volume.shape
    # T[k] stores the averaged light contribution over L rays for feature k
    T = [[[0.0 for _ in range(shape[2])] for _ in range(shape[1])] for _ in range(n_f)]
    
    # Brick optimization: skip empty regions. Implementation depends on volume layout; omitted per sources.
    # In practice, bricks are pre-scanned for empty voxels to skip raycasting.

    for k in range(n_f):
        feature_mask = features[k]
        # Iterate over all voxels (optimized by skipping empty bricks)
        for x in range(shape[0]):
            for y in range(shape[1]):
                for z in range(shape[2]):
                    if not feature_mask[x][y][z]:
                        continue
                    
                    occlusion_sum = 0.0
                    
                    # Cast L rays
                    for l in range(L):
                        # Uniform hemisphere sampling (pseudo-random polar coordinates)
                        theta = 2.0 * math.pi * l / L
                        phi = math.pi / 2.0 * (l + 0.5) / L
                        ray_dir = [
                            math.sin(phi) * math.cos(theta),
                            math.sin(phi) * math.sin(theta),
                            math.cos(phi)
                        ]
                        
                        transmittance = 1.0
                        light_contribution = 0.0
                        
                        # Sample along the ray
                        for m in range(M):
                            # Compute sample position
                            dist = (m + 0.5) * R_Omega / M
                            sx = x + ray_dir[0] * dist
                            sy = y + ray_dir[1] * dist
                            sz = z + ray_dir[2] * dist
                            
                            # Get opacity at sample position
                            if 0 <= sx < shape[0] and 0 <= sy < shape[1] and 0 <= sz < shape[2]:
                                scalar_val = interpolate_volume(volume, sx, sy, sz)
                                _, alpha = transfer_function(scalar_val)
                                # Key step: If sample does not belong to feature k, set opacity to 0
                                if not feature_mask[int(round(sx))][int(round(sy))][int(round(sz))]:
                                    alpha = 0.0
                            else:
                                alpha = 0.0
                            
                            # Front-to-back compositing for light contribution
                            light_contribution += transmittance
                            transmittance *= (1.0 - alpha)
                        
                        light_contribution /= M
                        occlusion_sum += light_contribution
                    
                    # Average over L rays to get T_k(v)
                    T[k][x][y][z] = occlusion_sum / L

    # Recombine using maximum operator: AO(v) = max{T_k(v) | ∀k}
    ao_volume = [[[0.0 for _ in range(shape[2])] for _ in range(shape[1])] for _ in range(shape[0])]
    for x in range(shape[0]):
        for y in range(shape[1]):
            for z in range(shape[2]):
                max_val = 0.0
                for k in range(n_f):
                    max_val = max(max_val, T[k][x][y][z])
                ao_volume[x][y][z] = max_val
                
    return ao_volume

def interpolate_volume(volume, x, y, z):
    # Standard trilinear interpolation stub
    ix, iy, iz = int(x), int(y), int(z)
    fx, fy, fz = x - ix, y - iy, z - iz
    v000 = volume[ix][iy][iz]
    v100 = volume[min(ix+1, len(volume)-1)][iy][iz]
    v010 = volume[ix][min(iy+1, len(volume[0])-1)][iz]
    v001 = volume[ix][iy][min(iz+1, len(volume[0][0])-1)]
    v110 = volume[min(ix+1, len(volume)-1)][min(iy+1, len(volume[0])-1)][iz]
    v101 = volume[min(ix+1, len(volume)-1)][iy][min(iz+1, len(volume[0][0])-1)]
    v011 = volume[ix][min(iy+1, len(volume[0][0])-1)][min(iz+1, len(volume[0][0])-1)]
    v111 = volume[min(ix+1, len(volume)-1)][min(iy+1, len(volume[0])-1)][min(iz+1, len(volume[0][0])-1)]
    return (v000*(1-fx)*(1-fy)*(1-fz) + v100*fx*(1-fy)*(1-fz) + v010*(1-fx)*fy*(1-fz) + v001*(1-fx)*(1-fy)*fz +
            v110*fx*fy*(1-fz) + v101*fx*(1-fy)*fz + v011*(1-fx)*fy*fz + v111*fx*fy*fz)
```

## Subtopics

### Local Ambient Occlusion for Volume Rendering
A general method for computing AO in volumes without feature separation [S1]. Choose when feature boundaries are not distinct or when computational cost must be minimized [S1]. [Link](4300-local-ambient-occlusion-for-volume-rendering.md)

### Local Ambient Occlusion (LAO)
Uses occlusion for data classification [S1]. Choose when the goal is to segment or classify data based on local geometry rather than shading enhancement [S1]. [Link](4502-local-ambient-occlusion-lao.md)

## Operating characteristics
*   **Time Complexity:** Computing separate ambient occlusion textures increases computation cost by a factor equal to the number of features $n_f$ [S1].
*   **Memory Complexity:** Requires storing $n_f$ separate 3D occlusion textures plus the final recombined texture, plus brick structures [S1].
*   **Measured Performance:** On AMD Opteron 2431 with Nvidia GTX 295 (1024x768 viewport), Feature-Driven AO achieves ~130 fps on the Orange dataset (256x256x64) and ~45 fps on the CT Knee dataset (379x229x305), matching classical AO performance while providing superior visual quality for multi-layer data [S1].
*   **Strengths:** Improves visual quality of multi-layer volumes by preventing overdarkening of internal layers [S1]. Less parameter-sensitive than classical AO, improving usability for non-experts [S1]. Preserves auto-occlusions for shape perception [S1].
*   **Limitations:** Computationally more expensive than classical AO by a factor of $n_f$ [S1]. Requires prior feature segmentation (though the method itself does not perform segmentation) [S1]. Artifacts can occur at feature borders if not handled correctly (mitigated by the max recombination operator) [S1].
*   **When to Use:** Direct volume rendering of multi-layer datasets (e.g., CT scans) where features are interleaved and distinct, and visual clarity of internal structures is critical [S1].
*   **When Not to Use:** Single-layer volumes, or when computational resources are severely constrained and $n_f$ is large [S1].

## Background
Feature-Driven Ambient Occlusion was introduced by A. Ancel, J.-M. Dischler, and C. Mongenet in 2010 [S1]. It addresses the limitations of straightforward ambient occlusion application in direct volume rendering, where multi-layer volumes result in overdarkening of internal layers due to inter-occlusions [S1]. The method builds on GPU-based approaches with bricking for acceleration [S1]. It is used in direct volume rendering to improve visual quality and usability for non-experts [S1].
