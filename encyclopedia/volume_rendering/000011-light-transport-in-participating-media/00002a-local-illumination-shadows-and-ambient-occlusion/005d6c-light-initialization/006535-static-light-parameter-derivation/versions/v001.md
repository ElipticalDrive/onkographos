# Static Light Parameter Derivation

Also called: Emitter to Light Conversion, Light Parameter Calculation

## Overview
Static Light Parameter Derivation calculates the render parameters (position, color, intensity, range, and suppression) for a static light emitter based on its block definition and a time-varying flicker factor [S1, unofficial]. It transforms raw emitter data into a `PointLight` structure suitable for local illumination in participating media. It differs from dynamic light updates by deriving these values once per frame or per flicker cycle based on a deterministic formula, ensuring consistent shadow casting and intensity falloff for static sources like torches or campfires [S1, unofficial].

## How it works
**Inputs:**
- `emitter`: A block definition containing:
  - `emit`: Peak light level (integer, range 0–15).
  - `emitter_render_pos`: 3D vector position of the emitter.
- `flicker`: A float value representing the current time-varying intensity modifier, typically generated by a flame flicker function.

**Outputs:**
- `PointLight`: A structure with fields:
  - `position`: `emitter_render_pos`
  - `range`: `emit + 2.0`
  - `color`: Normalized RGB vector scaled by intensity.
  - `shadows`: `true`
  - `suppress`: A tuple `(suppress_scale, emit)` used to cancel flood fill artifacts.

**Data Structures:**
The `PointLight` structure is constructed with the following layout:
- `position`: `vec3` (x, y, z)
- `range`: `f32`
- `color`: `vec3` (r, g, b)
- `shadows`: `bool`
- `suppress`: `tuple(f32, i32)`

**Steps:**
1. **Calculate Emit Intensity:** Convert the emitter's `emit` field to a float. Clamp the value to a minimum of 1.0 to prevent division by zero or zero-intensity artifacts.
   $$ e_{emit} = \max(1.0, \text{float}(\text{emit})) $$
2. **Calculate Hue-Normalized Color:** Divide each RGB channel of the emitter's color by $e_{emit}$. This preserves the hue while normalizing brightness.
   $$ c_{norm} = \frac{c_{emitter}}{e_{emit}} $$
3. **Calculate Intensity:** Compute the final intensity using the formula:
   $$ I = 1.8 \times \left( \frac{e_{emit}}{14.0} \right) \times \text{flicker} $$
   Where `flicker` is a value typically in the range $[1-\text{amp}, 1+\text{amp}]$.
4. **Calculate Suppress Scale:** Compute the suppression scale to mitigate rendering artifacts:
   $$ S = \frac{e_{emit}}{15.0 \times \max(0.01, I)} $$
5. **Construct PointLight:** Assemble the final light object:
   - `position`: `emitter_render_pos`
   - `range`: $e_{emit} + 2.0$
   - `color`: $c_{norm} \times I$
   - `shadows`: `true`
   - `suppress`: $(S, e_{emit})$

**Pseudocode:**
```python
def derive_static_light(emitter, flicker):
    # 1. Calculate emit intensity: clamp to at least 1.0
    emit_float = float(emitter.emit)
    e_emit = max(1.0, emit_float)
    
    # 2. Calculate hue-normalized color
    # Assuming emitter.color is a vec3 (r, g, b)
    color_norm = emitter.color / e_emit
    
    # 3. Calculate intensity
    intensity = 1.8 * (e_emit / 14.0) * flicker
    
    # 4. Calculate suppress_scale
    # Use max(0.01, intensity) to avoid division by zero
    suppress_scale = e_emit / (15.0 * max(0.01, intensity))
    
    # 5. Construct PointLight
    light = PointLight()
    light.position = emitter.emitter_render_pos
    light.range = e_emit + 2.0
    light.color = color_norm * intensity
    light.shadows = True
    light.suppress = (suppress_scale, e_emit)
    
    return light
```

**Parameters:**
- `soft_radius`: Returns the soft-shadow source size. Default value is `0.15`. This can be overridden via the environment variable `WILDFORGE_LIGHT_RADIUS` [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Zero Intensity:** If `emit` is 0, clamping to 1.0 ensures the light still contributes to the scene, albeit with minimal intensity. This prevents crashes in the suppression calculation.
- **Division by Zero:** The suppression scale calculation uses $\max(0.01, I)$ to prevent division by zero if `flicker` results in zero intensity.
- **Flicker Range:** The flicker factor should be derived from a stable function (e.g., Flame Flicker Generation) to avoid jittery lighting.

## Subtopics

### Flame Flicker Generation
Generates a slow two-sine flame flicker value in the range $[1-\text{amp}, 1+\text{amp}]$, phased per light key [S1, unofficial]. It is chosen when a natural, non-uniform flicker is desired for static lights. The formula is:
$$ \text{flicker}(t, \text{phase}, \text{amp}) = 1.0 + \text{amp} \times (0.6 \times \sin(t \times 7.3 + \text{phase}) + 0.4 \times \sin(t \times 13.7 + \text{phase} \times 2.0)) $$
Where $t$ is time, `phase` is a per-key offset, and `amp` is amplitude [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per light emitter. The calculation involves a fixed number of arithmetic operations and trigonometric functions.
- **Memory Complexity:** $O(1)$ per light emitter. The output is a single `PointLight` structure.
- **Performance:** The method is computationally inexpensive, suitable for real-time rendering of many static lights. The use of pre-calculated constants (7.3, 13.7) and simple sine functions ensures low CPU/GPU overhead.
- **Strengths:** Deterministic output, easy to implement, handles edge cases (zero intensity), and includes artifact suppression.
- **Limitations:** The flicker function is fixed and may not support arbitrary waveforms. The range is fixed to `emit + 2.0`, which may not be optimal for all scene scales.
- **When to Use:** For static light sources in voxel-based games where performance is critical and visual fidelity requirements are moderate.
- **When Not to Use:** For dynamic lights that require complex, time-varying intensity profiles beyond simple sine waves, or for scenes requiring precise physical light falloff models.

## Background
This method originates from the Wildforge game engine, a Minecraft-alpha-style voxel game written in Rust [S1, unofficial]. It is part of the local illumination system, specifically the light initialization phase, where static emitters are converted into renderable light objects. The suppression mechanism is designed to cancel flood fill artifacts common in voxel-based lighting systems [S1, unofficial].
