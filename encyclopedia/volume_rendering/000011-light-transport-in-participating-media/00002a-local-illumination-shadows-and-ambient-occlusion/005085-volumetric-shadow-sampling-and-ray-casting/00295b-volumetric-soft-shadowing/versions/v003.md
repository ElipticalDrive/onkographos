# Volumetric Soft Shadowing

Also called: Soft Shadows (Volumetric), Volumetric Shadowing

## Overview
Volumetric Soft Shadowing estimates soft shadows in participating media by sampling random directions towards the light source, weighting samples by local density and distance [S1, unofficial]. It differs from hard shadow techniques by approximating the penumbra through stochastic sampling, and from global illumination methods by focusing solely on direct visibility attenuation without simulating indirect bounces [S1, unofficial].

## How it works
**Inputs:**
- Volume density field $V(\mathbf{x})$ [S1, unofficial].
- Light direction vector $\mathbf{l}$ and light radius parameter $R$ (used as `uLightRadious`) [S1, unofficial].
- Current shading position $\mathbf{p}$ [S1, unofficial].
- Number of shadow samples $N$ (parameter `uNumShadowSamples`) [S1, unofficial].

**Outputs:**
- Shadow contribution factor $S \in [0, 1]$ [S1, unofficial].

**Data Structures:**
- Accumulator: A scalar or vector `accumulatedShadowContribution` initialized to 0.0 [S1, unofficial].
- Random number generator state `seed` for stochastic sampling [S1, unofficial].

**Parameters:**
- `uNumShadowSamples`: Number of shadow samples per pixel. Default value: 10 [S1, unofficial].
- `uLightRadious`: Radius parameter for sampling distance [S1, unofficial].
- `uShadowsWeight`: Weight applied when mixing shadow contribution into final color. Default value: 0.54 [S1, unofficial].

**Steps:**
1.  Initialize `accumulatedShadowContribution` to 0.0 [S1, unofficial].
2.  Loop $i$ from 0 to $N-1$:
    a.  Generate a random direction $\mathbf{d}$ towards the light. The source code suggests a specific construction:
        $$ \mathbf{d} = \text{normalize}\left( \begin{bmatrix} -1.0 + l_x \cdot \text{rand}() \\ l_y + \text{rand}() \cdot l_z \\ -1.0 + 2.0 \cdot \text{rand}()_x \end{bmatrix} \right) \cdot \text{rand}() $$
        *Note: The exact random distribution and vector component mapping in the source snippet is ambiguous, but the intent is to sample directions biased towards the light [S1, unofficial].*
    b.  Sample the volume density at $\mathbf{p} + \mathbf{d} \cdot R$. Let this sample be $v_{sample}$ [S1, unofficial].
    c.  Calculate `volumeShadowSample` as $v_{sample} \cdot 0.2$ [S1, unofficial].
    d.  Update accumulator:
        $$ \text{accumulatedShadowContribution} \leftarrow \text{accumulatedShadowContribution} + v_{sample} \cdot \text{volumeShadowSample} \cdot \|\mathbf{d}\|^{1.0} $$
        *Note: The source code multiplies by `pow(length(randomDirection), 1.0)`, which is 1.0 if normalized, suggesting the length term might be redundant or intended for non-normalized directions [S1, unofficial].*
3.  Post-process the accumulator:
    a.  Raise to power 1.0 (identity operation) [S1, unofficial].
    b.  Divide by $N$ [S1, unofficial].
    c.  Multiply by 20.0 [S1, unofficial].
    d.  Clamp result to $[0, 1]$ [S1, unofficial].
4.  Compute final shadow contribution $S_{raw}$:
    $$ S_{raw} = \text{mix}(1.0 - S_{raw}, \text{accumulatedShadowContribution}, 1.2) $$
    *Note: The source code uses `mix(1.0 - uSoftShadowsContribution, accumulatedShadowContribution, 1.2)`. This implies an iterative or feedback loop if `uSoftShadowsContribution` is the output of the previous frame or a persistent state. For a single pass, this formula is ambiguous. Assuming standard mixing:*
    $$ S_{raw} = (1.0 - S_{prev}) \cdot (1.0 - 1.2) + S_{acc} \cdot 1.2 $$
    *However, mixing factors > 1.0 are non-standard. The source likely implies a specific blending logic [S1, unofficial].*
5.  Normalize and clamp:
    $$ S = \frac{S_{raw}}{1.3} $$
    Clamp $S$ to $[0, 1]$ [S1, unofficial].

**Pseudocode:**
```python
def volumetric_soft_shadowing(position, light_dir, light_radius, num_samples, seed):
    accumulated = 0.0
    for i in range(num_samples):
        # Generate random direction biased towards light
        # Note: Exact random generation logic from source is ambiguous
        rand_val_1 = random()
        rand_val_2 = random()
        rand_val_3 = random()
        
        # Construct direction vector
        dx = -1.0 + light_dir.x * rand_val_1
        dy = light_dir.y + rand_val_2 * light_dir.z
        dz = -1.0 + 2.0 * rand_val_3
        
        direction = normalize(vec3(dx, dy, dz))
        
        # Sample volume
        sample_pos = position + direction * light_radius
        volume_sample = sample_volume(volume_field, sample_pos)
        
        # Weight sample
        volume_shadow_sample = volume_sample * 0.2
        
        # Accumulate
        # Source multiplies by length(direction)^1.0, which is 1.0 if normalized
        accumulated += volume_sample * volume_shadow_sample * length(direction)
        
    # Post-processing
    accumulated = pow(accumulated, 1.0)
    accumulated = accumulated / num_samples
    accumulated = accumulated * 20.0
    accumulated = clamp(accumulated, 0.0, 1.0)
    
    # Mixing
    # Note: Source uses mix(1.0 - current, accumulated, 1.2)
    # Assuming 'current' is previous shadow value or 0 for single pass
    shadow_contribution = mix(1.0 - accumulated, accumulated, 1.2)
    
    # Normalize
    shadow_contribution = shadow_contribution / 1.3
    shadow_contribution = clamp(shadow_contribution, 0.0, 1.0)
    
    return shadow_contribution
```

## Subtopics

### [Improved Global Illumination for Volume Rendering](8468-improved-global-illumination-for-volume-rendering.md)
A global illumination technique that simulates light transmission as continuous slices to produce realistic global illumination and real-time interactivity, but modifies the base method to generate soft shadows instead of hard shadows, thereby preserving local details. It differs from [Volumetric Soft Shadowing](4507-volumetric-soft-shadowing.md) by operating in volume space using a light volume generated slice-by-slice, and from [ZM13](https://doi.org/10.1111/cgf.12188) by avoiding back-lighting which fails with high-opacity data and lacks directional depth perception.

## Operating characteristics
- **Time Complexity:** $O(N)$ per pixel, where $N$ is the number of shadow samples. Default $N=10$ [S1, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary memory per pixel, plus the volume data structure [S1, unofficial].
- **Performance:** Depends heavily on the cost of volume sampling. Stochastic sampling can introduce noise if $N$ is low [S1, unofficial].
- **Strengths:** Produces soft shadows suitable for volumetric media; relatively simple to implement [S1, unofficial].
- **Limitations:** Stochastic nature leads to noise; specific mixing parameters (1.2, 1.3) are empirical and may not generalize [S1, unofficial].

## Background
The method is described in the context of the `terier/vpt` project, an unofficial implementation [S1, unofficial]. The specific parameters and mixing logic appear to be tuned for real-time or specific visual effects rather than physically based rendering [S1, unofficial].
