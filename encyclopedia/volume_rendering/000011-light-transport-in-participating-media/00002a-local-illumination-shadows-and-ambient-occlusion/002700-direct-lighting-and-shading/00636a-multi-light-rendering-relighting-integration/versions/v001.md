# Multi-Light Rendering & Relighting Integration

Also called: Light Integration, Relighting Pipeline

## Overview
Multi-Light Rendering & Relighting Integration computes pixel color by integrating the Bidirectional Reflectance Distribution Function (BRDF), light visibility, cosine factor, and light area over all light sources, supporting environment maps, OLAT relighting, and light probe relighting [S1, unofficial]. It differs from its siblings by explicitly handling multiple discrete light sources and probe-based relighting scaling, whereas [Physically-Based Rendering (PBR) Lighting](6815-physically-based-rendering-pbr-lighting.md) focuses on standard PBR terms and [Blinn-Phong Relighting](11122-blinn-phong-relighting.md) uses a simpler specular model [S1, unofficial].

## How it works
**Inputs:**
- `brdf`: Tensor of shape $(H, W, 3)$ representing the BRDF value per pixel.
- `light`: Tensor of shape $(N, 3)$ representing the color/intensity of $N$ lights.
- `l`: Tensor of shape $(H, W, 3)$ representing the normalized light direction vectors per pixel.
- `n`: Tensor of shape $(H, W, 3)$ representing the surface normal vectors per pixel.
- `light_vis`: Tensor of shape $(H, W, N)$ representing the visibility (shadowing) for each light at each pixel.
- `areas`: Tensor of shape $(N,)$ representing the area of each light source.
- `probe`: Optional data for relighting, including `novel_probes` (dictionary of probe images) and `self.light.rgb` (original light color).
- `linear2srgb`: Boolean flag.

**Outputs:**
- `rgb`: Tensor of shape $(H, W, 3)$ representing the final pixel color.

**Data Structures:**
- Lights are stored as a flat tensor of RGB values.
- Visibility is a 3D tensor mapping pixels to lights.

**Steps:**
1. **Compute Cosine Factor:** Calculate the dot product between light directions and surface normals.
   $$ cos = \mathbf{l} \cdot \mathbf{n} $$
   In implementation, this is often done via einsum: `cos = torch.einsum('ijk,ik->ij', l, n)`.

2. **Determine Front-Facing:** Identify pixels where the light is in front of the surface.
   $$ front\_lit = (cos > 0).float() $$

3. **Apply Visibility:** Combine front-facing mask with light visibility.
   $$ lvis = front\_lit \times light\_vis $$

4. **Scale Light Intensity:**
   - If **Relighting** is enabled (using light probes):
     1. Compute the total intensity of the original light:
        $$ I_{orig} = \sum \text{gray}(self.light.rgb) \times 8 $$
     2. Compute the total intensity of the novel probes:
        $$ I_{probe} = \sum_{p \in novel\_probes} \sum \text{gray}(p) $$
     3. Compute the scaling factor:
        $$ light\_scale = \left( \frac{I_{orig}}{I_{probe}} \right)^2 $$
     4. Scale the light contributions:
        $$ light_{scaled} = light \times light\_scale $$
   - If **Not Relighting**:
     $$ light_{scaled} = light $$

5. **Compute Pixel Contribution:**
   Reshape light and visibility to align with pixel dimensions.
   $$ light\_flat = light.reshape(-1, 3) $$
   $$ areas = areas.reshape(1, -1, 1) $$
   $$ light\_contrib = lvis[:, :, None] \times light\_flat[None, :, :] $$
   $$ light\_pix\_contrib = brdf \times light\_contrib \times cos[:, :, None] \times areas $$

6. **Sum Contributions:**
   $$ rgb = \sum_{L} light\_pix\_contrib $$
   Mathematically:
   $$ rgb = \sum_{L} (brdf \cdot light \cdot cos \cdot area) $$

7. **Clip and Convert:**
   $$ rgb = \text{clip}(rgb, 0, 1) $$
   If `linear2srgb` is true, apply linear-to-sRGB transform.

**Pitfalls:**
- NaN or Inf values can occur during relighting; assert against them after concatenation [S1, unofficial].

**Pseudocode:**
```python
import torch
import numpy as np

def multi_light_rendering(brdf, l, n, light_vis, light_rgb, areas, 
                          probe_novel_probes=None, original_light_rgb=None, 
                          linear2srgb=False):
    """
    brdf: (H, W, 3)
    l: (H, W, 3) light directions
    n: (H, W, 3) normals
    light_vis: (H, W, N) visibility
    light_rgb: (N, 3) light colors
    areas: (N,) light areas
    """
    # 1. Cosine factor
    cos = torch.einsum('ijk,ik->ij', l, n) # (H, W)
    
    # 2. Front facing
    front_lit = (cos > 0).float() # (H, W)
    
    # 3. Visibility
    # light_vis is (H, W, N)
    lvis = front_lit.unsqueeze(-1) * light_vis # (H, W, N)
    
    # 4. Light Scaling (Relighting)
    if probe_novel_probes is not None and original_light_rgb is not None:
        # Compute probe intensity
        probe_intensity = 0.0
        for probe_name, probe_img in probe_novel_probes.items():
            # probe_img assumed to be (H, W, 3) or similar, convert to gray sum
            # Using standard gray formula: 0.299R + 0.587G + 0.114B
            gray = 0.299 * probe_img[..., 0] + 0.587 * probe_img[..., 1] + 0.114 * probe_img[..., 2]
            probe_intensity += gray.sum()
            
        # Compute original light intensity
        orig_gray = 0.299 * original_light_rgb[..., 0] + 0.587 * original_light_rgb[..., 1] + 0.114 * original_light_rgb[..., 2]
        orig_intensity = orig_gray.sum() * 8
        
        # Scale factor
        if probe_intensity > 0:
            light_scale = (orig_intensity / probe_intensity) ** 2
        else:
            light_scale = 1.0
            
        light_scaled = light_rgb * light_scale
    else:
        light_scaled = light_rgb
        
    # 5. Reshape for broadcasting
    # light_scaled: (N, 3)
    # lvis: (H, W, N)
    # areas: (N,) -> (1, 1, N)
    # cos: (H, W) -> (H, W, 1)
    
    light_flat = light_scaled # (N, 3)
    areas_exp = areas.reshape(1, 1, -1) # (1, 1, N)
    cos_exp = cos.unsqueeze(-1) # (H, W, 1)
    
    # 6. Contribution
    # lvis[:, :, None] is (H, W, N, 1)
    # light_flat[None, :, :] is (1, N, 3)
    # Broadcasting: (H, W, N, 3)
    light_contrib = lvis.unsqueeze(-1) * light_flat.unsqueeze(0) # (H, W, N, 3)
    
    # brdf: (H, W, 3)
    # light_contrib: (H, W, N, 3)
    # cos_exp: (H, W, 1) -> (H, W, 1, 1)
    # areas_exp: (1, 1, N) -> (1, 1, N, 1)
    
    term = brdf.unsqueeze(2) * light_contrib * cos_exp.unsqueeze(2) * areas_exp.unsqueeze(-1)
    
    # 7. Sum over lights (dim 2)
    rgb = term.sum(dim=2) # (H, W, 3)
    
    # 8. Clip
    rgb = torch.clamp(rgb, min=0.0, max=1.0)
    
    # 9. sRGB conversion (placeholder logic)
    if linear2srgb:
        rgb = linear_to_srgb(rgb)
        
    return rgb

def linear_to_srgb(x):
    # Standard sRGB transfer function
    return torch.where(x <= 0.0031308, 12.92 * x, 1.055 * torch.pow(x, 1.0/2.4) - 0.055)
```

## Subtopics

### Lobe-based Weighting for Extinction
A method to compute the average extinction coefficient $\bar{\sigma}_t(s_k)$ by weighting volume properties with the BRDF lobe shape, prioritizing extinction near the regularly reflected ray over side extinction [S2]. It uses the formula $\bar{\sigma}_t(s_k) \approx \int_A(s) \sigma_t(\omega_i) f_r(x_i; \omega_i, \omega_o) |\omega_i \cdot n(x_i)| d\omega_i$ [S2]. This is chosen when accurate attenuation near the reflection direction is critical, as simple averaging inappropriately attenuates incident light by volume on the side [S2].

### Blender Cycles Integration
A pipeline to make estimated lighting usable in commercial renderers like Blender Cycles by converting hybrid lighting into a standard HDR environment map [S3]. Steps: (1) Convert hybrid lighting to a local environment map via radiance query at the 3D location [S3]. (2) Insert a virtual plane beneath the object [S3]. (3) Render three images: Object-only ($I_{object}$), Plane-only ($I_{plane}$), and Plane with object occlusion ($I_{shadowed}$) [S3]. (4) Compute shadow map $I_{shadow} = I_{shadowed} / I_{plane}$ [S3]. (5) Composite results [S3]. It is chosen for compatibility with commercial renderers but ignores local geometry of the object and virtual plane, failing to render localized shadow effects [S3].

### Rotated Multi-Light Capture
A data acquisition and optimization strategy where the same environment map is rotated along the azimuth for 0, 120, and 240 degrees to create three lighting conditions per view [S4]. Shared environmental lighting is optimized across these rotated multi-light data using known rotation degrees [S4]. It uses the same 100 views as single-light but provides 3 images per view, allowing for more robust lighting estimation compared to single-light settings [S4].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of lights $N$ and pixels $H \times W$, i.e., $O(H \cdot W \cdot N)$ [S1, unofficial].
- **Memory Complexity:** $O(H \cdot W \cdot N)$ to store visibility and intermediate contributions [S1, unofficial].
- **Performance:** Depends heavily on the number of lights and the cost of BRDF evaluation [S1, unofficial].
- **Strengths:** Supports multiple light sources, environment maps, and relighting via probes [S1, unofficial].
- **Limitations:** Cannot render localized shadow effects if using the Blender Cycles integration variant [S3]. Simple averaging of extinction is inaccurate for sharp BRDF lobes [S2].

## Background
Originating from implementations in neural inverse rendering frameworks, this method integrates direct lighting calculations with relighting capabilities [S1, unofficial]. It has been adapted for integration with commercial renderers like Blender Cycles [S3] and for optimizing lighting from rotated multi-light captures [S4]. The lobe-based weighting variant was introduced to improve extinction estimation in participating media [S2].
