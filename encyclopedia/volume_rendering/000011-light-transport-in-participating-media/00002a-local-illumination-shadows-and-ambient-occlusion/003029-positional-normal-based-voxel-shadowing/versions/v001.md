# Positional & Normal-Based Voxel Shadowing

Also called: Block Positional Shadowing, Deterministic Voxel Face Shadowing

## Overview
Positional & Normal-Based Voxel Shadowing is a deterministic, non-ray-tracing method for calculating per-face shadow multipliers in voxel-based rendering. It solves the problem of simulating directional shading and ambient occlusion in blocky environments by evaluating static geometric conditions—specifically block coordinates and face normals—rather than performing expensive visibility tests. Unlike [Shadow Ray Casting](2796-shadow-ray-casting.md), which computes transmittance via ray integration, this method applies a binary or scalar shadow intensity based on predefined spatial rules, offering high performance at the cost of physical accuracy. It is distinct from [Ambient Occlusion via Shadow Rays](878-ambient-occlusion-via-shadow-rays.md) by replacing stochastic or deterministic ray sampling with hardcoded coordinate thresholds.

## How it works
The method calculates a shadow multiplier for a specific block face based on the block's position in the voxel grid, its material type, and the orientation of the face.

**Inputs and Outputs:**
*   **Input:**
    *   `blockPos`: A 3D integer vector $(X, Y, Z)$ representing the block's coordinates in the voxel grid.
    *   `block`: An integer or unsigned short identifier for the block type (e.g., 1 for grass, 6 for stone).
    *   `faceNormal`: A directional enum or vector indicating the outward normal of the face being shaded (Top, Bottom, Left, Right, Front, Back).
*   **Output:**
    *   `shadow`: A float value representing the shadow multiplier, typically $1.0$ (fully lit) or `shadowIntensity` (shadowed).

**Data Structures:**
*   `BlockCulling.transparencyModeByBlock`: An array mapping block IDs to a transparency mode enum. The method checks if the mode is `Opaque`.
*   `shadowIntensity`: A scalar float parameter defining the brightness of shadowed faces.

**Steps:**
1.  Initialize `shadow` to $1.0$.
2.  Determine if the block is transparent. If `BlockCulling.transparencyModeByBlock[block]` is not `Opaque`, the block is considered transparent. [S1, unofficial]
3.  Evaluate shadow conditions in the following order. If a condition is met, set `shadow` to `shadowIntensity` and terminate evaluation (or continue if multiple shadows stack, though the source implies a single assignment):
    *   **Depth Shadow:** If $Y < -2$, apply `shadowIntensity`. [S1, unofficial]
    *   **Z-Offset Pattern:** If $Y \le 0$, $Z \neq 0$, and $|X| \pmod{10} > 5$, apply `shadowIntensity`. [S1, unofficial]
    *   **X-Offset Pattern:** If $Y \le 0$, $X \neq 0$, and $|Z| \pmod{14} > 7$, apply `shadowIntensity`. [S1, unofficial]
    *   **Bottom Face Shadow:** If `faceNormal` is `Bottom` and the block is opaque, apply `shadowIntensity`. [S1, unofficial]
4.  Return `shadow`.

**Pseudocode:**
```python
def get_shadow(block_pos: Vector3i, block_id: int, face_normal: Direction) -> float:
    """
    Calculates the shadow multiplier for a voxel face based on position and normal.
    
    Args:
        block_pos: (X, Y, Z) coordinates of the block.
        block_id: Identifier for the block type.
        face_normal: The direction of the face being shaded.
        
    Returns:
        Shadow multiplier (1.0 or shadowIntensity).
    """
    shadow = 1.0
    
    # Check transparency mode
    # Note: BlockCulling.transparencyModeByBlock is assumed to be a global lookup table
    is_opaque = (BlockCulling.transparencyModeByBlock[block_id] != TransparencyMode.Opaque) is False
    
    # Condition 1: Depth-based shadow
    if block_pos.y < -2:
        shadow = shadowIntensity
        return shadow
        
    # Condition 2: Z-offset pattern shadow
    if block_pos.y <= 0 and block_pos.z != 0:
        if abs(block_pos.x) % 10 > 5:
            shadow = shadowIntensity
            return shadow
            
    # Condition 3: X-offset pattern shadow
    if block_pos.y <= 0 and block_pos.x != 0:
        if abs(block_pos.z) % 14 > 7:
            shadow = shadowIntensity
            return shadow
            
    # Condition 4: Bottom face shadow for opaque blocks
    if face_normal == Direction.Bottom and is_opaque:
        shadow = shadowIntensity
        return shadow
        
    return shadow
```

**Parameters:**
*   `shadowIntensity`: The multiplier applied when a shadow condition is met. Exact value not defined in the source [S1, unofficial].
*   `color1`: Base tint color $(0.8, 0.7, 1.0)$, used in noise-driven tinting variants [S1, unofficial].
*   `color2`: Target tint color $(0.0, 1.0, 1.0)$, used in noise-driven tinting variants [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Grass Blocks:** Blocks with ID 1 (grass) require an additional dirt face (ID 5) to be rendered when side faces are visible. This must be handled before tint calculation to prevent visual artifacts [S1, unofficial].
*   **Modulo Arithmetic:** The use of modulo operations on coordinates creates periodic shadow patterns. Implementers must ensure integer division behavior matches the source (e.g., handling negative numbers if coordinates can be negative, though the source uses `abs()`).
*   **Transparency:** The method explicitly checks for non-opaque blocks. Transparent blocks do not trigger the bottom-face shadow condition, preventing shadows from being cast by or onto see-through surfaces in this specific logic branch [S1, unofficial].

## Subtopics

### Noise-Driven Face Tinting
A variant that combines the positional shadow multiplier with procedural color variation. It applies a 2D noise function to block X/Z coordinates to interpolate between two tint colors, modulated by the result of `GetShadow`. This adds visual variety to flat-shaded voxels.
*   **Definition:** Applies procedural color tint to visible block faces using 2D noise, modulated by the calculated shadow multiplier [S1, unofficial].
*   **Steps:**
    1.  Initialize `tint` to white $(1, 1, 1)$ and `doTint` flag to `false`.
    2.  Determine if tinting is enabled for the specific block/face combination:
        *   If `block == 1` (grass) and `faceNormal != Bottom`, enable tinting.
        *   If `block == 6` (stone) and `faceNormal == Top`, enable tinting.
    3.  If `doTint` is true:
        *   Sample 2D noise at `(blockPos.X, blockPos.Z)`.
        *   Normalize the noise sample to $[0, 1]$.
        *   Interpolate between `color1` and `color2` using the normalized noise value.
    4.  Multiply the resulting `tint` by the `shadow` multiplier.
*   **Parameters:**
    *   `color1`: $(0.8, 0.7, 1.0)$ [S1, unofficial].
    *   `color2`: $(0.0, 1.0, 1.0)$ [S1, unofficial].
    *   `noise`: A `FastNoiseLite` instance or equivalent procedural noise generator [S1, unofficial].
*   **Pseudocode:**
    ```python
    def get_shaded_tint(block_pos: Vector3i, block_id: int, face_normal: Direction) -> Vector3:
        """
        Calculates the final tint color for a voxel face, incorporating shadow and noise.
        """
        shadow = get_shadow(block_pos, block_id, face_normal)
        tint = Vector3(1.0, 1.0, 1.0)
        do_tint = False
        
        # Determine if this face should be tinted
        if block_id == 1 and face_normal != Direction.Bottom:
            do_tint = True
        elif block_id == 6 and face_normal == Direction.Top:
            do_tint = True
            
        if do_tint:
            # Sample 2D noise at X/Z coordinates
            noise_val = noise.get_noise(block_pos.x, block_pos.z)
            # Normalize to [0, 1] assuming noise output is [-1, 1]
            normalized_noise = (noise_val + 1.0) / 2.0
            
            # Interpolate between color1 and color2
            tint = lerp(color1, color2, normalized_noise)
            
        return tint * shadow
    ```

## Operating characteristics
*   **Time Complexity:** $O(1)$ per face. The calculation involves a fixed number of arithmetic comparisons and modulo operations, independent of scene complexity or light distance.
*   **Memory Complexity:** $O(1)$ additional memory per query, assuming the transparency lookup table and noise generator are pre-allocated.
*   **Performance:** Extremely fast, suitable for real-time rendering of large voxel worlds where ray tracing is prohibitive. It avoids the cost of ray traversal and integration [S1, unofficial].
*   **Strengths:** Deterministic results, no jitter, no aliasing artifacts from ray sampling, minimal computational overhead.
*   **Limitations:** Lacks physical accuracy; shadows do not change with light position or angle (static directional shading). The periodic patterns from modulo arithmetic may appear artificial. Does not handle volumetric transmittance or soft shadows natively [S1, unofficial].
*   **When to use:** Stylized voxel games, Minecraft-like engines, or performance-critical applications where approximate shading is acceptable.
*   **When not to use:** Physically based rendering, scenes with dynamic light sources requiring accurate shadow movement, or environments requiring soft shadows and volumetric light scattering.

## Background
This method originates from the `Cubic-Grid_Voxel_Renderer` project by rarefushion, an unofficial, non-peer-reviewed implementation of a voxel renderer [S1, unofficial]. It reflects common techniques in early voxel game development (e.g., Minecraft clones) where performance constraints necessitated simple, hardcoded shading rules rather than full light transport simulation. The use of coordinate-based modulo patterns is a heuristic to simulate depth and surface variation without ray casting.
