# Positional & Normal-Based Voxel Shadowing

Also called: Block Position Shadowing, Deterministic Face Shadowing

## Overview
Positional & Normal-Based Voxel Shadowing is a deterministic, non-physical shading technique used in voxel-based rendering to simulate directional lighting and occlusion without performing ray tracing or volumetric integration. It calculates a per-face shadow multiplier based on the block's absolute world coordinates, its material type, and the orientation of the visible face. Unlike [Shadow Ray Casting](2796-shadow-ray-casting.md), which evaluates transmittance through participating media or geometry, this method applies static, rule-based attenuation to create the visual impression of shadows and ambient occlusion. It is distinct from [Ambient Occlusion via Shadow Rays](878-ambient-occlusion-via-shadow-rays.md) and [Direct Illumination with Shadow Rays](2011-direct-illumination-with-shadow-rays.md) by replacing stochastic or geometric visibility tests with deterministic arithmetic conditions on block indices.

## How it works
The method operates on a per-face basis during the mesh generation or shading phase of a voxel renderer. It determines how much light a specific face receives by evaluating a series of conditional rules against the block's position and properties.

### Inputs and Outputs
*   **Inputs:**
    *   `blockPos`: The integer or float coordinates $(X, Y, Z)$ of the block in world space.
    *   `block`: An identifier (e.g., `ushort`) representing the block type/material.
    *   `faceNormal`: The direction of the face being shaded (e.g., Top, Bottom, Left, Right, Front, Back).
*   **Outputs:**
    *   `shadow`: A float multiplier in the range $[0, 1]$ (or potentially lower if intensity < 1) applied to the face's base color.

### Data Structures
The implementation relies on lookup tables or static arrays defined in the rendering context:
*   `BlockCulling.transparencyModeByBlock`: An array mapping block IDs to a `TransparencyMode` enum (e.g., `Opaque`, `Transparent`).
*   `shadowIntensity`: A scalar float parameter defining the darkness of the shadow when conditions are met.

### Algorithm Steps
1.  **Initialize:** Set `shadow = 1.0`.
2.  **Transparency Check:** Retrieve the transparency mode for `block`. If the mode is not `Opaque`, the block is considered transparent. [S1, unofficial]
3.  **Depth Shadowing:** If `blockPos.Y < -2`, set `shadow = shadowIntensity`. This simulates deep underground darkness. [S1, unofficial]
4.  **Z-Offset Pattern:** If `blockPos.Y <= 0` AND `blockPos.Z != 0` AND `|blockPos.X| \pmod{10} > 5`, set `shadow = shadowIntensity`. This creates a periodic shadow pattern along the X-axis for blocks at or below sea level. [S1, unofficial]
5.  **X-Offset Pattern:** If `blockPos.Y <= 0` AND `blockPos.X != 0` AND `|blockPos.Z| \pmod{14} > 7`, set `shadow = shadowIntensity`. This creates a periodic shadow pattern along the Z-axis for blocks at or below sea level. [S1, unofficial]
6.  **Normal-Based Occlusion:** If `faceNormal == Direction.Bottom` AND the block is `Opaque`, set `shadow = shadowIntensity`. This simulates self-occlusion or lack of sky visibility for bottom faces of solid blocks. [S1, unofficial]
7.  **Return:** Return `shadow`.

### Pseudocode
```python
def get_shadow(block_pos: Vector3i, block_id: ushort, face_normal: Direction, 
               shadow_intensity: float, transparency_mode_by_block: Array[TransparencyMode]) -> float:
    """
    Calculates a deterministic shadow multiplier for a voxel face.
    
    Args:
        block_pos: World coordinates (X, Y, Z) of the block.
        block_id: Identifier for the block type.
        face_normal: The direction of the face being shaded.
        shadow_intensity: The multiplier applied when shadow conditions are met.
        transparency_mode_by_block: Lookup table for block transparency.
        
    Returns:
        A float shadow multiplier.
    """
    shadow = 1.0
    
    # Check transparency
    is_opaque = transparency_mode_by_block[block_id] != TransparencyMode.Transparent
    
    # Condition 1: Deep underground
    if block_pos.y < -2:
        shadow = shadow_intensity
        return shadow
        
    # Condition 2: Periodic shadow based on X, dependent on Z != 0
    if block_pos.y <= 0 and block_pos.z != 0:
        if abs(block_pos.x) % 10 > 5:
            shadow = shadow_intensity
            return shadow
            
    # Condition 3: Periodic shadow based on Z, dependent on X != 0
    if block_pos.y <= 0 and block_pos.x != 0:
        if abs(block_pos.z) % 14 > 7:
            shadow = shadow_intensity
            return shadow
            
    # Condition 4: Bottom face occlusion for opaque blocks
    if face_normal == Direction.Bottom and is_opaque:
        shadow = shadow_intensity
        
    return shadow
```

### Parameters
*   `shadowIntensity`: The value applied when a shadow condition is triggered. The exact value is not defined in the source snippet, but it acts as a multiplicative factor for the face color. [S1, unofficial]
*   Modulo thresholds: `10` for X-axis checks and `14` for Z-axis checks. [S1, unofficial]
*   Offset thresholds: `5` for X-axis and `7` for Z-axis. [S1, unofficial]
*   Depth threshold: `Y < -2`. [S1, unofficial]

### Edge Cases and Pitfalls
*   **Grass Blocks:** Blocks with ID `1` (grass) require special handling. When side faces are visible, an additional dirt face (ID `5`) must be rendered before tint calculation to prevent visual artifacts. [S1, unofficial]
*   **Zero Coordinates:** The conditions explicitly check `blockPos.Z != 0` and `blockPos.X != 0`. If a block lies exactly on the X=0 or Z=0 plane, the corresponding periodic shadow rule is skipped, potentially creating a visible seam or inconsistency in the shadow pattern.
*   **Deterministic Artifacts:** Because the shadows are based on absolute coordinates rather than relative geometry, moving the camera or the world origin will cause shadows to shift independently of the geometry, which may be visually distracting in dynamic scenes.

## Subtopics

### Noise-Driven Face Tinting
A variant that combines the positional shadowing with procedural color variation. It applies a 2D noise function to modulate the tint color of specific block faces, multiplied by the shadow intensity calculated by the base method.
*   **Definition:** Applies a procedural color tint to visible block faces using 2D noise, modulated by the calculated shadow multiplier. [S1, unofficial]
*   **Steps:**
    1.  Initialize `tint` to white `(1, 1, 1)` and `doTint` flag to `false`.
    2.  Determine if tinting is required based on block ID and face normal (e.g., Grass blocks ID `1` on non-bottom faces, or specific blocks ID `6` on top faces). [S1, unofficial]
    3.  If `doTint` is true, sample 2D noise at `(blockPos.X, blockPos.Z)`.
    4.  Normalize the noise sample to $[0, 1]$.
    5.  Interpolate between `color1` `(0.8, 0.7, 1.0)` and `color2` `(0.0, 1.0, 1.0)` using the normalized noise value.
    6.  Return `tint * shadow`. [S1, unofficial]
*   **Parameters:**
    *   `color1`: Base tint color `(0.8, 0.7, 1.0)`. [S1, unofficial]
    *   `color2`: Target tint color `(0.0, 1.0, 1.0)`. [S1, unofficial]
    *   `noise`: A `FastNoiseLite` instance (or equivalent) for procedural sampling. [S1, unofficial]
*   **Pseudocode:**
    ```python
    def get_shaded_tint(block_pos: Vector3i, block_id: ushort, face_normal: Direction, 
                        shadow: float, noise_generator: NoiseGenerator, 
                        color1: Vector3, color2: Vector3) -> Vector3:
        """
        Calculates a noise-modulated tint color, multiplied by the shadow intensity.
        """
        tint = Vector3(1.0, 1.0, 1.0)
        do_tint = False
        
        # Determine if this face should be tinted
        if block_id == 1 and face_normal != Direction.Bottom:
            do_tint = True
        elif block_id == 6 and face_normal == Direction.Top:
            do_tint = True
            
        if do_tint:
            # Sample 2D noise at X, Z coordinates
            noise_val = noise_generator.get_noise(block_pos.x, block_pos.z)
            # Normalize to [0, 1]
            normalized_noise = (noise_val + 1.0) / 2.0
            # Interpolate between color1 and color2
            tint = Vector3.lerp(color1, color2, normalized_noise)
            
        return tint * shadow
    ```

## Operating characteristics
*   **Time Complexity:** $O(1)$ per face. The calculation involves a fixed number of arithmetic operations and array lookups, independent of scene complexity or distance.
*   **Memory Complexity:** $O(1)$ additional memory per face, aside from the static lookup tables for block properties and noise generators.
*   **Performance:** Extremely fast, suitable for real-time rendering of massive voxel worlds on CPU or GPU without the overhead of ray marching or shadow map generation.
*   **Strengths:** Deterministic, easy to implement, no artifacts from ray marching step counts, no memory bandwidth issues associated with shadow maps.
*   **Limitations:** Shadows do not correspond to actual geometry (a block far away can cast a "shadow" on a nearby block if coordinates align). Shadows do not change with light position or time (unless coordinates are time-dependent). No soft shadows or penumbrae.
*   **When to use:** Stylized voxel games, procedural terrain generation where performance is critical, or as a fallback when physical accuracy is not required.
*   **When not to use:** Realistic rendering, scenes with dynamic moving light sources, or when accurate occlusion is required for gameplay mechanics.

## Background
This method originates from the `Cubic-Grid_Voxel_Renderer` project by rarefushion, a GitHub repository documenting a voxel rendering engine. It represents a pragmatic approach to shading in voxel engines, prioritizing visual variety and performance over physical correctness. The technique is common in early voxel games and procedural generation tools where simple, coordinate-based rules are used to break up uniformity and simulate lighting.
