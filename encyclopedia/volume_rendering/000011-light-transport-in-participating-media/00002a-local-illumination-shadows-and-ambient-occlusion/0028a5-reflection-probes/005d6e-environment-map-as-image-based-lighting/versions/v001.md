# Environment Map as Image-Based Lighting

Also called: Environment Lighting, Environment Map Lighting, Image Based Lighting

## Overview
Environment Map as Image-Based Lighting (IBL) simulates illumination from the outer environment, such as sky and sunlight, which are difficult to model as solid objects [S1, unofficial]. It avoids the computational cost of modeling all surrounding objects and accumulating indirect lighting between them by treating the outer environment as an infinitely far sphere [S1, unofficial]. This method is distinct from local illumination techniques by providing global context lighting, and from Reflection Probes by using a single static environment representation rather than spatially varying probes [Parent](4344-reflection-probes.md).

## How it works
**Inputs:**
- A shading point $P$ and its surface normal $\mathbf{n}$.
- An environment map $E$, stored as either a cubemap or a spherical projection map [S1, unofficial].
- A ray direction $\mathbf{d}$ (typically the reflection direction for specular highlights or the view direction for diffuse irradiance).

**Outputs:**
- The incoming radiance $L_e$ at point $P$ from the environment.

**Data Structures:**
- **Environment Map:** A texture array or 3D texture.
  - *Cubemap:* 6 square faces, each of size $N \times N$ texels.
  - *Spherical Projection Map:* A 2D texture mapping spherical coordinates $(\theta, \phi)$ to pixel coordinates. The sources prefer spherical projection maps for easier computation and fewer artifacts [S1, unofficial].

**Steps:**
1. **Ray Generation:** Determine the direction $\mathbf{d}$ for which radiance is needed. For specular reflection, $\mathbf{d} = \text{reflect}(-\mathbf{v}, \mathbf{n})$, where $\mathbf{v}$ is the view vector. For diffuse lighting, integrate over the hemisphere or sample specific directions.
2. **Local Occlusion Check:** Trace a ray from $P$ in direction $\mathbf{d}$ against the local scene geometry.
   - If the ray hits a local object, the contribution from the environment is occluded (or attenuated) by that object.
   - If the ray misses all local objects, the environment is visible.
3. **Environment Sampling:** If the environment is visible, sample the texel from the environment map $E$ at the direction $\mathbf{d}$.
   - Treat the environment as an infinitely far sphere, meaning all rays originate from the center of the sphere [S1, unofficial].
   - Map the direction $\mathbf{d}$ to the appropriate texture coordinates $(u, v)$ based on the map type (cubemap face selection or spherical projection).
4. **Importance Sampling (Optional):** To reduce variance, use importance sampling with a hierarchical sample warping strategy [S2, unofficial]. This requires a probability density function (PDF) derived from the luminance of the environment map texture.
5. **Validation:** Verify sample placement distribution against the PDF using a chi-squared ($\chi^2$) test [S2, unofficial].

**Pseudocode:**
```python
def sample_environment_map(environment_map, shading_point, normal, view_direction):
    """
    Samples the environment map for image-based lighting.
    
    Args:
        environment_map: The environment texture (cubemap or spherical projection).
        shading_point: The 3D position of the shading point.
        normal: The surface normal at the shading point.
        view_direction: The view vector from the camera to the shading point.
        
    Returns:
        radiance: The incoming radiance from the environment.
    """
    # 1. Calculate reflection direction for specular component
    # Note: For diffuse, this step might be replaced by hemisphere sampling
    reflection_direction = reflect(-view_direction, normal)
    
    # 2. Check for local occlusion
    # Trace ray from shading_point in reflection_direction
    hit = trace_ray(shading_point, reflection_direction)
    
    if hit is not None:
        # Environment is occluded by local geometry
        # Return 0 or attenuated value depending on occlusion model
        return vec3(0.0)
    
    # 3. Sample the environment map
    # Treat environment as infinitely far sphere
    if environment_map.type == "CUBEMAP":
        # Map reflection_direction to cubemap face and UV coordinates
        face, u, v = direction_to_cubemap_uv(reflection_direction)
        radiance = environment_map.sample(face, u, v)
    elif environment_map.type == "SPHERICAL_PROJECTION":
        # Map reflection_direction to spherical coordinates (theta, phi)
        # Then to 2D texture coordinates (u, v)
        u, v = direction_to_spherical_uv(reflection_direction)
        radiance = environment_map.sample(u, v)
    else:
        raise ValueError("Unsupported environment map type")
        
    return radiance
```

**Parameters:**
- **Map Type:** Cubemap or Spherical Projection Map. Spherical projection maps are preferred for easier computation and fewer artifacts [S1, unofficial].
- **Sampling Strategy:** Uniform or Importance Sampling. Importance sampling uses hierarchical sample warping [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Cubemap Artifacts:** Cubemaps may have a higher chance of artifacts compared to spherical projection maps [S1, unofficial].
- **Precision:** Ensure accurate mapping from 3D direction to 2D texture coordinates to avoid seams, especially in cubemaps.
- **Occlusion:** If local occlusion is not checked, the environment lighting will incorrectly penetrate through solid objects.

## Subtopics

### Environment Map Setup
This variant uses four layered point-based spheres for the environment map instead of traditional texture-based maps [S3]. It is chosen for its superior performance in neural rendering contexts, specifically for Visual Error Tomography (VET). On the Playground scene (12.5M Points), '4 P.-b. Layered Spheres (init. 2.0M points)' yields 13.3M points, LPIPS 0.124, and PSNR 25.49, outperforming 'No Environment Map' (LPIPS 0.146, PSNR 25.34) and other setups [S3]. This method is less susceptible to overfitting on training views, improving the meaningfulness of error images [S3].

## Operating characteristics
- **Time Complexity:** $O(1)$ per sample for environment map lookup, assuming constant-time texture sampling. Occlusion testing adds complexity proportional to the number of primitives in the local scene.
- **Memory Complexity:** Depends on the environment map resolution. Cubemaps require $6 \times N^2$ texels; spherical projection maps require $N \times M$ texels.
- **Strengths:** Efficiently simulates global illumination from distant sources without modeling complex geometry. Reduces computational load compared to full global illumination algorithms.
- **Limitations:** Assumes the environment is infinitely far, which may not hold for close-up scenes. Cubemaps can introduce artifacts.
- **When to Use:** When the surrounding environment is sufficiently far and static. Ideal for outdoor scenes or indoor scenes with large windows.
- **When Not to Use:** When the environment is dynamic or close to the scene, requiring spatially varying lighting (use Reflection Probes instead).

## Background
Environment maps were introduced as a technique to simulate lighting from the outer environment, such as sky and sunlight, which are hard to model as solid objects [S1, unofficial]. The method avoids the task of modeling all objects from the border of the bounding environment to the shading point and accumulating indirect lighting between any two objects [S1, unofficial]. It is widely used in real-time rendering and offline rendering to achieve realistic illumination with minimal computational cost.
