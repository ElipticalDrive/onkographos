# Motion Blur

Also called: Temporal Blur, Shutter Integration

## Overview
Motion blur simulates the integration of radiance over a finite shutter interval $[t_0, t_1]$ rather than at a single instant [S1, unofficial]. In path tracing, this is achieved by assigning a unique random time sample to each ray, causing moving objects to appear blurred along their trajectories [S1, unofficial]. It differs from post-processing blur by correctly handling occlusion and perspective changes during the exposure [S1, unofficial].

## How it works
**Inputs:** Camera parameters (view/projection matrices), scene geometry with per-object transform data (position, rotation, scale) or velocity vectors, and shutter interval $[t_0, t_1]$.
**Outputs:** A single pixel color value representing the time-integrated radiance.

**Data Structures:**
*   **Transform Data:** Per-object matrices or velocity vectors. For interpolated transforms, the position $\mathbf{p}(t)$ is often linearly interpolated: $\mathbf{p}(t) = \mathbf{p}_0 + (\mathbf{p}_1 - \mathbf{p}_0) \cdot \frac{t - t_0}{t_1 - t_0}$ [S1, unofficial].
*   **Ray Structure:** Contains origin $\mathbf{o}$, direction $\mathbf{d}$, and time $t$.

**Steps:**
1.  **Sample Time:** Generate a uniform random number $u \in [0, 1]$ and compute the shutter time $t$:
    $$ t = t_0 + u \cdot (t_1 - t_0) $$
    [S1, unofficial]
2.  **Evaluate Transforms:** Update the world transform of each object in the scene to its state at time $t$ using the available velocity or interpolated keyframe data [S1, unofficial].
3.  **Trace Ray:** Cast the ray through the scene using the transformed geometry. The intersection logic must account for the object's position at time $t$ [S1, unofficial].
4.  **Accumulate:** Repeat steps 1–3 for multiple samples per pixel and average the results to reduce noise [S1, unofficial].

**Pseudocode:**
```python
def trace_motion_blur_pixel(uv, t0, t1, num_samples, scene):
    color = vec3(0.0)
    for i in range(num_samples):
        # 1. Sample time
        u = random_float()
        t = lerp(t0, t1, u)
        
        # 2. Evaluate transforms at time t
        # This updates the scene's world matrices based on t
        scene.update_transforms(t)
        
        # 3. Construct ray
        # Origin and direction are computed from camera matrices
        # Note: Camera motion can also be sampled if the camera moves
        origin = camera.get_origin(uv, t)
        direction = camera.get_direction(uv, t)
        
        # 4. Trace ray against transformed scene
        hit = trace_ray(origin, direction, scene)
        
        if hit:
            color += hit.radiance
        else:
            color += background_radiance
            
    return color / num_samples
```

**Parameters:**
*   $t_0, t_1$: Shutter start and end times. Typical values depend on the simulation time scale [S1, unofficial].
*   `num_samples`: Number of temporal samples per pixel. Higher values reduce noise but increase cost [S1, unofficial].

**Edge Cases:**
*   **High Velocity:** If objects move significantly between frames, linear interpolation may cause artifacts. Per-object velocity data is preferred [S1, unofficial].
*   **Camera Motion:** If the camera moves, the ray origin and direction must also be sampled at time $t$ [S1, unofficial].

## Subtopics

## Operating characteristics
*   **Time Complexity:** $O(N \cdot S)$, where $N$ is the number of pixels and $S$ is the number of temporal samples per pixel. Each sample requires a full scene transform update and ray trace [S1, unofficial].
*   **Memory Complexity:** $O(V)$, where $V$ is the number of vertices/objects, to store transform history or velocity data [S1, unofficial].
*   **Strengths:** Physically accurate motion blur; handles occlusion and perspective correctly [S1, unofficial].
*   **Limitations:** Requires per-object motion data; noisy with few samples; expensive due to repeated scene traversal [S1, unofficial].

## Background
Motion blur in path tracing is a standard technique for achieving cinematic realism. It relies on the principle that a camera shutter integrates light over a finite time interval [S1, unofficial]. The method described here is a fundamental implementation detail in modern path tracers, often discussed in the context of camera models and anti-aliasing [S1, unofficial].
