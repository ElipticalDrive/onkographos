# Motion Blur

Also called: Temporal Blur, Shutter Blur

## Overview
Motion blur simulates the integration of light over a finite shutter interval $[t_0, t_1]$, resulting in a blurred image when objects or the camera move during exposure [S1, unofficial]. In path tracing, this is achieved by assigning a unique random time sample to each ray, naturally accumulating motion blur across samples [S1, unofficial]. It differs from post-processing blur by preserving correct geometric occlusion and depth-of-field interactions at the sampled time instances [S1, unofficial].

## How it works
**Inputs:**
*   Shutter interval $[t_0, t_1]$ [S1, unofficial].
*   Per-object transform data (position, rotation, scale) or velocity vectors at $t_0$ and $t_1$ [S1, unofficial][S2].
*   Scene geometry and material properties.

**Outputs:**
*   A single pixel color value representing the time-integrated radiance [S1, unofficial].

**Data Structures:**
*   **Transform State:** For each object, a set of transforms $\{T(t_0), T(t_1)\}$ or velocity vectors $\mathbf{v}$ [S1, unofficial][S2].
*   **Random Number:** A uniform random variable $u \in [0, 1)$ [S1, unofficial].

**Steps:**
1.  **Sample Time:** Generate a random time $t$ within the shutter interval:
    $$ t = t_0 + (t_1 - t_0) \cdot u $$
    where $u$ is a uniform random number in $[0, 1)$ [S1, unofficial].
2.  **Interpolate Transforms:** Evaluate the object's transform $T(t)$ at the sampled time $t$. This is typically done via linear interpolation of positions and spherical linear interpolation (SLERP) of rotations, or by applying velocity vectors if available [S1, unofficial][S2].
3.  **Ray Generation:** Construct the ray origin and direction based on the camera state at time $t$ (if camera motion blur is included) or the static camera [S1, unofficial].
4.  **Trace:** Trace the ray through the scene using the interpolated object positions [S1, unofficial].
5.  **Accumulate:** Add the resulting radiance to the pixel buffer. Repeat for multiple samples to reduce noise [S1, unofficial].

**Parameters:**
*   **Shutter Interval $[t_0, t_1]$:** Defines the exposure duration. Typical values depend on the simulation time scale [S1, unofficial].
*   **mbmult:** A multiplier affecting the strength of motion blur. Can be negative [S2].
*   **vol_moblur_method:** Specifies the volumetric motion blur strategy ('Ray-traced' or 'Grid-based') [S2].

**Edge Cases and Pitfalls:**
*   **Precision:** Linear interpolation of transforms may cause artifacts if rotation is not handled correctly (e.g., using SLERP) [S1, unofficial].
*   **Self-Intersection:** In mesh rendering, shifting vertices by velocity can cause penetration. A self-intersection check (mbself) is expensive but prevents artifacts [S2].
*   **Volumetric Limitations:** Grid-based motion blur only applies to Volumetric, Volumetric Geometry, and Volumetric Heat Haze modes, not Mesh or Ocean modes [S2].

**Pseudocode:**
```python
def sample_motion_blur_ray(t0, t1, random_u, object_transforms, camera):
    """
    Generates a ray for a single motion blur sample.
    
    Args:
        t0 (float): Start of shutter interval.
        t1 (float): End of shutter interval.
        random_u (float): Uniform random number in [0, 1).
        object_transforms (dict): Map of object_id to {pos_t0, rot_t0, pos_t1, rot_t1, vel}.
        camera (Camera): Camera object with view/projection matrices.
        
    Returns:
        Ray: Origin and direction at sampled time t.
    """
    # Step 1: Sample time
    t = t0 + (t1 - t0) * random_u
    
    # Step 2: Interpolate transforms for all objects
    # Note: In a real implementation, this would update the scene graph or 
    # provide a transform function for the ray tracer.
    interpolated_transforms = {}
    for obj_id, transforms in object_transforms.items():
        # Linear interpolation for position
        pos = lerp(transforms['pos_t0'], transforms['pos_t1'], random_u)
        # Slerp for rotation (simplified here as lerp for pseudocode clarity)
        rot = lerp_quat(transforms['rot_t0'], transforms['rot_t1'], random_u)
        interpolated_transforms[obj_id] = {'pos': pos, 'rot': rot}
        
    # Step 3: Generate Ray
    # Assuming pinhole camera model for simplicity
    # uv is the pixel coordinate in NDC [-1, 1]
    origin_ndc = vec3(0, 0, 0)
    target_ndc = vec3(uv.x, uv.y, 1)
    
    # Transform to world space
    origin_world = camera.view_inverse * vec4(origin_ndc, 1)
    target_world = camera.view_inverse * vec4(target_ndc, 1)
    
    direction = normalize(target_world.xyz - origin_world.xyz)
    origin = origin_world.xyz
    
    return Ray(origin, direction, t)

def lerp(a, b, t):
    return a + t * (b - a)

def lerp_quat(q0, q1, t):
    # Simplified quaternion interpolation
    # In practice, use slerp or nlerp
    return q0 + t * (q1 - q0)
```

## Subtopics

### [Motion Blur via Sub-frame Optimization](11034-motion-blur-via-sub-frame-optimization.md)
ExBluRF models motion blur in radiance fields by approximating the continuous integral of ray accumulation over the shutter open time as a finite sum of $N$ intermediate sub-frames, jointly optimizing sub-frame camera poses with the radiance field. It differs from prior works that model blur using global camera trajectories or light fields by optimizing each training view’s latent camera trajectory independently, allowing for arbitrary but smooth local motion.

### Ray-traced Volumetric Motion Blur
The default Volumetric Motion Blur method for Phoenix simulations [S2]. It uses per-object velocity data or interpolated transforms to shift geometry during rendering [S2]. The strength is controlled by the `mbmult` parameter, which can be negative [S2].

### Camera motion blur modeling (3DGS)
Simulates exposure-time camera shake by rasterizing multiple sharp images at different temporal instants and averaging them [S3]. It trains 3D Gaussians to model clean representations at various moments light reaches the sensor, rasterizes $M$ clean images from $M$ different moments, and averages them to simulate camera movement during training [S3]. The parameter $M$ (e.g., $M=6$) controls temporal sampling density [S3]. A pitfall is that it assumes images at all instants are sharp without inherent blur; blur only arises from temporal averaging of sharp frames [S3].

### Grid-based Volumetric Motion Blur
A motion blur method for volumetric simulations that produces more visible motion blur streaks, especially with faster moving fluids, by using a pre-pass and requiring more memory than the default Ray-traced method [S2]. It is selected via the `vol_moblur_method` parameter [S2]. A pitfall is that it only affects Volumetric, Volumetric Geometry, and Volumetric Heat Haze Modes, and does not apply to Mesh, Ocean Mesh, Cap Mesh, or Isosurface Modes [S2].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of motion blur samples $N$ and the number of objects in the scene. Each sample requires a full ray trace [S1, unofficial].
*   **Memory Complexity:** Depends on the storage of per-object transform data or velocity vectors. Grid-based volumetric blur requires additional memory for the pre-pass [S2].
*   **Performance:** High-quality motion blur requires many samples to reduce noise, increasing render time [S1, unofficial]. Grid-based volumetric blur is more expensive due to the pre-pass [S2].
*   **Strengths:** Physically accurate integration of motion over time; handles complex occlusions and depth-of-field interactions naturally [S1, unofficial].
*   **Limitations:** Requires per-object velocity or transform data; can be computationally expensive for large scenes or high sample counts [S1, unofficial][S2]. Grid-based method has mode restrictions [S2].

## Background
Motion blur in path tracing was introduced as a natural extension of the Monte Carlo integration of light transport, where the shutter interval is treated as a dimension of the integral [S1, unofficial]. The technique relies on the ability to evaluate scene geometry at arbitrary time instances, which became feasible with the adoption of ray tracing APIs and efficient transform interpolation methods [S1, unofficial]. Variants like ExBluRF extend this to neural radiance fields, optimizing camera poses for blur [S1, unofficial]. Volumetric motion blur methods in simulation software like Phoenix provide specialized techniques for fluid and smoke rendering [S2].
