# Optimization Strategies for Volumetric Lighting

Also called: God Rays Optimization Techniques, Real-time Volumetric Lighting Optimizations

## Overview
Optimization strategies for volumetric lighting reduce the computational cost of rendering soft, low-frequency light shafts (god rays) in real-time [S1, unofficial]. Half-resolution or quarter-resolution rendering provides a 4x or greater performance gain with minimal quality loss [S1, unofficial]. These techniques prioritize rendering efficiency through resolution reduction, temporal accumulation, and noise management [G].

## How it works
The optimization pipeline modifies the standard ray marching loop to reduce per-frame computational load while maintaining visual continuity across frames [G].

**Inputs and Outputs**
- **Input:** Full-resolution scene color buffer, depth buffer, light source position (screen-space or world-space), previous frame's volumetric lighting buffer, current frame index [G].
- **Output:** Optimized volumetric lighting buffer at reduced resolution, composited onto the final scene [G].

**Data Structures**
- **Reduced Resolution Buffer:** A texture with dimensions $W/2 \times H/2$ or $W/4 \times H/4$ relative to the screen [G].
- **Previous Frame Buffer:** A texture storing the volumetric contribution from the prior frame, used for temporal blending [G].
- **Blue Noise Texture:** A 2D texture containing pre-generated blue noise values for dithering [G].

**Numbered Steps**

1.  **Resolution Reduction:**
    Initialize the ray marching loop to compute volumetric lighting at half or quarter screen resolution. The effect is inherently soft and low-frequency, allowing this reduction with minimal quality loss while achieving a 4x or greater performance gain [S1, unofficial].

2.  **Blue Noise Dithering:**
    To mitigate banding artifacts caused by fewer samples, offset the ray march starting positions or sample intervals using blue noise. This converts visible banding artifacts into imperceptible noise [S1, unofficial].
    $$
    \text{start\_offset} = \text{blue\_noise}(uv \times \text{scale}) \times \text{step\_size}
    $$
    Where $uv$ is the texture coordinate, $\text{scale}$ adjusts noise frequency, and $\text{step\_size}$ is the ray march step length [G].

3.  **Temporal Reprojection:**
    For each pixel, retrieve the volumetric contribution from the previous frame's buffer. Reproject this contribution to the current frame's coordinates using motion vectors or depth-based reprojection. Blend the current frame's computed result with the reprojected previous frame result. This effectively multiplies the sample count across frames while computing only a fraction per frame [S1, unofficial].
    $$
    C_{final} = \alpha C_{current} + (1 - \alpha) C_{previous\_reprojected}
    $$
    Where $\alpha$ is the blending factor, typically determined by temporal stability or convergence rate [G].

4.  **Early Termination:**
    During the ray marching loop, calculate the accumulated transmittance $T$. If $T$ drops below a threshold (e.g., 0.01), terminate the march early. Samples beyond this point contribute negligibly to the final color, especially in dense media [S1, unofficial].
    $$
    \text{if } T < 0.01: \text{break}
    $$

5.  **Bilateral Upsampling:**
    When compositing the reduced-resolution result onto the full-resolution scene, apply a depth-aware bilateral filter. This prevents halos and artifacts at depth discontinuities (object edges) by weighting samples based on both spatial proximity and depth similarity [S1, unofficial].

**Pseudocode**

```python
def optimize_volumetric_lighting(scene_color, depth_buffer, light_pos, prev_volumetric_buffer, frame_idx, sigma_s, sigma_t, light_color, step_size, max_steps, alpha_blend):
    res_w = scene_color.width // 2
    res_h = scene_color.height // 2
    reduced_volumetric = [[vec3(0.0)] * res_w for _ in range(res_h)]

    for y in range(res_h):
        for x in range(res_w):
            uv = vec2(x / res_w, y / res_h)
            # Blue noise dithering
            noise_val = blue_noise_sample(uv * 10.0)
            start_offset = noise_val * step_size

            ray_origin = vec3(uv.x, uv.y, 0.0)
            ray_direction = normalize(light_pos - ray_origin)
            ray_origin += ray_direction * start_offset

            transmittance = 1.0
            accumulated_light = vec3(0.0)
            t = 0.0

            for _ in range(max_steps):
                pos = ray_origin + ray_direction * t
                # Standard single scattering contribution [G]
                scatter = light_color * sigma_s * exp(-sigma_t * t)
                accumulated_light += scatter * step_size
                transmittance *= exp(-sigma_t * step_size)
                t += step_size

                if transmittance < 0.01:
                    break

            reduced_volumetric[y][x] = accumulated_light

    # Temporal reprojection
    prev_reprojected = [[vec3(0.0)] * res_w for _ in range(res_h)]
    for y in range(res_h):
        for x in range(res_w):
            uv = vec2(x / res_w, y / res_h)
            motion_uv = motion_vector_sample(uv)
            prev_uv = clamp(uv - motion_uv, 0.0, 1.0)
            prev_reprojected[y][x] = prev_volumetric_buffer.sample(prev_uv)

    blended_volumetric = [[vec3(0.0)] * res_w for _ in range(res_h)]
    for y in range(res_h):
        for x in range(res_w):
            curr = reduced_volumetric[y][x]
            prev = prev_reprojected[y][x]
            blended_volumetric[y][x] = curr * alpha_blend + prev * (1.0 - alpha_blend)

    # Bilateral upsampling
    full_volumetric = [[vec3(0.0)] * scene_color.width for _ in range(scene_color.height)]
    for y in range(scene_color.height):
        for x in range(scene_color.width):
            uv = vec2(x / scene_color.width, y / scene_color.height)
            full_volumetric[y][x] = bilateral_upsample_filter(blended_volumetric, uv, depth_buffer, res_w, res_h)

    return full_volumetric

def blue_noise_sample(uv):
    return texture_sample(blue_noise_tex, uv)

def motion_vector_sample(uv):
    return texture_sample(motion_vec_tex, uv)

def bilateral_upsample_filter(buffer, uv, depth_buffer, buf_w, buf_h):
    src_uv = uv * vec2(buf_w, buf_h)
    center_depth = depth_buffer.sample(uv)
    result = vec3(0.0)
    weight_sum = 0.0
    for dy in range(-1, 2):
        for dx in range(-1, 2):
            neighbor_uv = vec2((src_uv.x + dx) / buf_w, (src_uv.y + dy) / buf_h)
            neighbor_depth = depth_buffer.sample(neighbor_uv)
            spatial_weight = exp(-((dx*dx + dy*dy) / 2.0))
            depth_weight = exp(-((center_depth - neighbor_depth)**2) / 0.01)
            w = spatial_weight * depth_weight
            result += buffer[int(src_uv.y + dy)][int(src_uv.x + dx)] * w
            weight_sum += w
    return result / weight_sum
```

## Subtopics

### [Light Optimization via Light Volumes](14450-light-optimization-via-light-volumes.md)
Light Optimization via Light Volumes is a technique for optimizing light source coefficients in participating media by storing light transport residuals in dedicated volumetric structures rather than directly updating the coefficient vector.

## Operating characteristics
- **Time Complexity:** Reduced by a factor of 4x to 16x due to half/quarter resolution rendering [S1, unofficial]. Temporal reprojection further reduces per-frame cost by allowing fewer spatial samples [G].
- **Memory Complexity:** Requires storage for the reduced-resolution buffer, the previous frame's buffer, and blue noise texture [G]. Bilateral upsampling may require additional temporary buffers for depth-aware filtering [G].
- **Performance:** Significant performance gain on GPU-bound scenarios [G]. The trade-off is potential temporal instability if reprojection fails (e.g., at camera motion boundaries) and slight blurring due to resolution reduction [G].
- **Strengths:** Effective for soft, low-frequency effects like god rays [S1, unofficial]. Minimal quality loss for the performance gain [S1, unofficial].
- **Limitations:** Not suitable for high-frequency volumetric details [G]. Requires stable depth and motion vectors for effective temporal reprojection [G].

## Background
These optimization strategies are standard practices in real-time graphics, particularly in high-end PC games and engines like Unreal Engine 5, which uses froxel grids with temporal reprojection for volumetric fog by default [S1, unofficial]. The techniques address the inherent expense of volumetric lighting as a post-processing effect [S1, unofficial].
