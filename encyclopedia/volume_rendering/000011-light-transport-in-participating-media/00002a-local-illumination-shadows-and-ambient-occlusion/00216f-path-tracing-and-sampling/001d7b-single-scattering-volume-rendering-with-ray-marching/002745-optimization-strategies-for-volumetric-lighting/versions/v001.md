# Optimization Strategies for Volumetric Lighting
Also called: God Rays Optimization Techniques, Real-time Volumetric Lighting Optimizations

## Overview
This method applies performance optimizations to screen-space volumetric lighting (god rays) to make real-time ray marching feasible on consumer hardware. It addresses the high computational cost of sampling participating media by reducing spatial, temporal, and sample complexity. It differs from [Single Scattering Volume Rendering with Ray Marching](1532-single-scattering-volume-rendering-with-ray-marching.md) by prioritizing rendering speed over physical accuracy, and from [Volumetric Lighting with Phase Functions](2358-volumetric-lighting-with-phase-functions.md) by focusing on implementation efficiency rather than scattering physics.

## How it works
The method combines five distinct optimization techniques applied during the generation and compositing of screen-space god rays.

**Inputs:**
- Full-resolution depth buffer.
- Full-resolution albedo/color buffer.
- Light source position (screen-space or world-space).
- Previous frame’s volumetric lighting buffer (for temporal reprojection).

**Outputs:**
- Full-resolution volumetric lighting accumulation buffer.

**Data Structures:**
- `DepthBuffer`: Float texture, resolution $W \times H$.
- `LightBuffer`: Float texture, resolution $W_{res} \times H_{res}$ (where $W_{res} \le W/2$).
- `PrevLightBuffer`: Float texture, same size as `LightBuffer`.

**Steps:**

1. **Downsample Resolution:**
   Render the volumetric lighting pass at half or quarter screen resolution ($W_{res} = W/2, H_{res} = H/2$). This reduces the number of ray march steps by 4x or 16x respectively. The soft, low-frequency nature of the effect minimizes visible quality loss [S1, unofficial].

2. **Blue Noise Dithering:**
   Offset the ray march starting positions using blue noise instead of regular grid spacing. This converts visible banding artifacts into imperceptible noise, allowing for fewer samples per ray while maintaining visual quality [S1, unofficial].

3. **Ray Marching with Early Termination:**
   For each pixel in the low-resolution buffer, perform ray marching from the camera toward the light source.
   - Initialize transmittance $T = 1.0$.
   - Initialize accumulated light $L = 0.0$.
   - For each step $i$ along the ray:
     - Sample depth and compute density $\sigma_t$.
     - Update transmittance: $T \leftarrow T \cdot e^{-\sigma_t \cdot \Delta s}$.
     - If $T < 0.01$, terminate the loop early [S1, unofficial].
     - Accumulate scattered light: $L \leftarrow L + \text{scattering} \cdot T$.
   - Store $L$ in `LightBuffer` [S1, unofficial].

4. **Temporal Reprojection:**
   To further reduce per-frame cost, use different sample offsets each frame and blend the current result with the previous frame’s `LightBuffer`.
   - Let $L_{curr}$ be the result from Step 3.
   - Let $L_{prev}$ be the reprojected previous frame’s buffer.
   - Blend: $L_{final} = \alpha L_{curr} + (1 - \alpha) L_{prev}$, where $\alpha$ is a blending factor (e.g., 0.5) [S1, unofficial].
   - This effectively multiplies the sample count across frames while computing only a fraction per frame [S1, unofficial].

5. **Bilateral Upsampling:**
   Upsample the low-resolution `LightBuffer` to full resolution using a depth-aware bilateral filter. This avoids halos at depth discontinuities (object edges) by weighting samples based on depth similarity [S1, unofficial].

**Pseudocode:**

```python
def optimize_volumetric_lighting(depth_buffer, light_pos, prev_light_buffer, frame_index):
    # Step 1: Downsample resolution
    res_w = depth_buffer.width // 2
    res_h = depth_buffer.height // 2
    light_buffer = Texture(res_w, res_h)
    
    # Step 2: Blue noise dithering offset
    dither_offset = get_blue_noise_offset(frame_index)
    
    # Step 3: Ray marching with early termination
    for y in range(res_h):
        for x in range(res_w):
            # Map screen coords to world space ray
            ray = screen_to_world_ray(x, y, res_w, res_h, depth_buffer)
            ray.origin += dither_offset # Apply blue noise dithering
            
            transmittance = 1.0
            accumulated_light = 0.0
            
            for step in range(MAX_STEPS):
                # Sample density and depth
                depth_sample = sample_depth(ray.position, depth_buffer)
                density = compute_density(depth_sample, ray.position)
                
                # Update transmittance
                transmittance *= exp(-density * STEP_SIZE)
                
                # Early termination
                if transmittance < 0.01:
                    break
                
                # Accumulate light
                scattered_light = compute_scattering(ray.position, light_pos, density)
                accumulated_light += scattered_light * transmittance
                
            light_buffer[x, y] = accumulated_light
            
    # Step 4: Temporal reprojection
    reprojected_prev = reproject(prev_light_buffer, frame_index)
    alpha = 0.5
    blended_light = light_buffer * alpha + reprojected_prev * (1 - alpha)
    
    # Step 5: Bilateral upsampling
    full_res_light = bilateral_upsample(blended_light, depth_buffer)
    
    return full_res_light
```

### [Light Optimization via Light Volumes](14450-light-optimization-via-light-volumes.md)
Optimization of light source coefficients by storing residuals in light-source volumes (voli) rather than directly updating the light vector, avoiding atomic contention during ray traversal.

## Operating characteristics
- **Time Complexity:** Reduced by 4x–16x due to half/quarter resolution rendering. Temporal reprojection further reduces per-frame cost by reusing previous samples.
- **Memory Complexity:** Requires storage for `LightBuffer` (half/quarter resolution) and `PrevLightBuffer`. Bilateral upsampling requires temporary depth-aware weights.
- **Performance:** Enables real-time god rays on mid-range hardware. Mobile/lower-end hardware may prefer screen-space radial blur for even lower cost [S1, unofficial].
- **Strengths:** Minimal quality loss for soft, low-frequency effects; effective at reducing banding and halos.
- **Limitations:** Accuracy trade-off compared to full ray marching; temporal reprojection can cause ghosting if not handled carefully; bilateral upsampling adds complexity.

## Background
Originating from screen-space god ray techniques, these optimizations became standard in high-end PC games. Unreal Engine 5 uses froxel grids with temporal reprojection for high-quality volumetric lighting by default [S1, unofficial]. The techniques are widely adopted in real-time rendering to balance visual fidelity and performance.
