# Light Optimization via Light Volumes

Also called: Light coefficient optimization, Light volume method

## Overview
Light Optimization via Light Volumes optimizes light source coefficients by storing residuals in dedicated light-source volumes (`voli`) rather than directly updating the coefficient vector [S1]. It solves the atomic contention and serialization that occurs when multiple GPU threads write to the same memory locations during ray traversal [S1]. Unlike direct residual accumulation, it uses a gather-based approach via mipmapping to aggregate contributions, trading increased memory consumption for higher performance [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   $V_{ext}$: Extinction volume (voxel grid) [S1].
*   $L_{init}$: Initial light coefficient vector of size $N_{coeffs}$ [S1].
*   $T$: Ray traversal operator representing light transport from light sources to constraint pixels [S1].
*   $I_{target}$: Target images defining constraint pixels [S1].
*   $N_{coeffs}$: Number of light basis functions [S1].
*   $R_{vol}$: Resolution of the light volumes [S1].

**Outputs:**
*   $L_{opt}$: Optimized light coefficient vector [S1].
*   $V_{li}$: Light volumes (one per coefficient) storing the influence of each coefficient [S1].

### Data Structures
1.  **Light Volume ($V_{li}$)**: A 3D voxel grid of resolution $R_{vol} \times R_{vol} \times R_{vol}$ [S1]. For an isotropic phase function, memory consumption is proportional to $N_{coeffs} \times R_{vol}^3$ [S1]. Each voxel stores the accumulated light transport contribution for a specific coefficient [S1].
2.  **Mipmap Pyramid**: A hierarchical structure built over the residual accumulation buffer to facilitate the gather operation [S1]. The highest level contains the aggregated values for the light coefficients [S1].

### Algorithm Steps
1.  **Pre-compute Light Volumes**: Treat each light basis function as an emission source. Shoot rays through $V_{ext}$ for all relevant directions, compute the light transport result for each voxel, and store the result in the corresponding $V_{li}$ [S1]. This is equivalent to lighting the volume with the $i$-th light source and storing the resulting lit volume [S1].
2.  **Forward Pass (Gathering Influence)**: For each constraint pixel, shoot the corresponding ray through $V_{ext}$ [S1]. Multiply with $T$ (ray traversal) to collect information from all $V_{li}$ simultaneously and store the collected information in the constraint pixels [S1].
3.  **Compute Residuals**: Calculate the difference between the target pixel values and the current rendered values [S1].
4.  **Backward Pass (Distributing Residuals)**: Multiply with $T^T$ to distribute the residuals to the light coefficient vector [S1]. Store the residuals with each ray, but target the light coefficient vector [S1].
5.  **Mipmapping Aggregation**: Perform a mipmapping procedure to gather all ray contributions into the highest level of the mipmap pyramid [S1]. The highest level contains the final aggregated values for $L$ [S1].

### Pseudocode
```python
def optimize_light_coefficients(extinction_volume, target_images, num_coeffs, vol_resolution):
    # 1. Pre-compute light volumes (voli)
    voli = []
    for i in range(num_coeffs):
        voli.append(precompute_light_volume(extinction_volume, basis_index=i))

    # 2. Initialize light coefficient vector L
    L = [0.0] * num_coeffs

    # 3. Optimization loop
    for iteration in range(5):
        # Forward pass: Multiply with T (ray traversal) to collect info from all voli
        # Store collected information in constraint pixels
        current_render = []
        for view_idx, target_img in enumerate(target_images):
            view_pixels = []
            for pixel in target_img:
                ray = compute_ray_through_volume(pixel, view_idx)
                accumulated = 0.0
                for i in range(num_coeffs):
                    # Gather values from voli[i] along the ray path
                    value = ray_march(voli[i], ray, extinction_volume)
                    accumulated += L[i] * value
                view_pixels.append(accumulated)
            current_render.append(view_pixels)

        # Compute residuals
        residuals = []
        for target_img, current_pixels in zip(target_images, current_render):
            for t, c in zip(target_img, current_pixels):
                residuals.append(t - c)

        # Backward pass: Multiply with T^T to distribute residuals to L
        # Store residuals with each ray and perform a mipmapping procedure to gather contributions
        mipmap_levels = initialize_mipmap(num_coeffs, vol_resolution)

        # Distribute residuals into mipmap levels via ray traversal
        res_idx = 0
        for view_idx, target_img in enumerate(target_images):
            for pixel in target_img:
                ray = compute_ray_through_volume(pixel, view_idx)
                residual_val = residuals[res_idx]
                res_idx += 1
                scatter_residual_to_mipmap(mipmap_levels, ray, residual_val, num_coeffs)

        # Gather all ray contributions into the highest level of the mipmap pyramid
        aggregated_residuals = get_highest_mipmap_level(mipmap_levels)

        # Update L with aggregated residuals
        for i in range(num_coeffs):
            L[i] += aggregated_residuals[i]

    return L

def precompute_light_volume(ext_vol, basis_index):
    vol = create_zero_volume(ext_vol.resolution)
    for voxel in ext_vol.voxels:
        vol[voxel] = compute_transport_for_basis(ext_vol, voxel, basis_index)
    return vol

def ray_march(voli, ray, ext_vol):
    total = 0.0
    for voxel in ray.intersect(voli):
        total += voxel.value * ray.transmission_to(voxel)
    return total

def initialize_mipmap(num_coeffs, vol_resolution):
    levels = []
    for i in range(4):
        levels.append([0.0] * (num_coeffs * (vol_resolution // (2**i))**3))
    return levels

def scatter_residual_to_mipmap(mipmap, ray, residual_val, num_coeffs):
    for level in mipmap:
        for voxel in ray.intersect(level):
            level[voxel] += residual_val

def get_highest_mipmap_level(mipmap):
    return mipmap[0]
```

### Parameters
*   **Number of Light Coefficients ($N_{coeffs}$)**: Typically low numbers (e.g., 16) are sufficient for acceptable computation times and good results [S1].
*   **Light Volume Resolution ($R_{vol}$)**: Affects memory consumption significantly ($N_{coeffs} \times R_{vol}^3$ for isotropic phase function) but has minor impact on performance compared to ray marching steps [S1].
*   **Light Basis Functions**: In the cited work, 128 uniformly-distributed disc lights restricted to the upper hemisphere covering a constant solid angle with soft falloff were used for environment map stylization [S1].
*   **Ray Marching Steps**: Twice the number of ray marching steps for the length of the diagonal as the number of voxels along an axis is a good choice for accurate integral estimation [S1].

### Edge Cases and Pitfalls
*   **Atomic Contention**: Directly adding residuals to $L$ during ray traversal causes serialization and low performance because multiple threads write to the same memory location, especially with few light coefficients [S1]. The light volume method avoids this by using a gather-based mipmapping approach [S1].
*   **Isotropic Volume Filtering**: An isotropic volume acts as a low-pass filter from the light source to the camera, as well as from the camera to the light sources [S1]. Consequently, high-frequency information (e.g., logos) in target images cannot be perfectly matched [S1]. The resulting environmental lighting is also low-frequency, justifying the low number of light coefficients [S1].
*   **Memory Usage**: Memory consumption is significant ($N_{coeffs} \times R_{vol}^3$) [S1]. If GPU memory is constrained, multiple ray traversals can be performed, keeping only a subset of $V_{li}$ in memory at once, though exchanging the set is costly [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Time Complexity**: Scales linearly with the number of light coefficients ($N_{coeffs}$) [S1]. The pre-computation time for light volumes also scales with $N_{coeffs}$ and resolution [S1].
*   **Memory Complexity**: Proportional to $N_{coeffs} \times R_{vol}^3$ for isotropic phase functions [S1].

### Measured Performance
*   **Hardware**: Intel X5650 CPU, nVidia 560Ti GPU [S1].
*   **Volume Optimization**: For $128^3$ voxels, 256 ray marching steps, 460K constraint pixels (2 views), computation takes less than two seconds [S1]. With 2.3M constraint pixels (10 views), it takes seven seconds [S1].
*   **Light Optimization**: Optimizing for 16 light coefficients on a $128^3$ volume with 2.3M constraint pixels (10 views) takes around three seconds [S1].
*   **Pre-computation**: For 256 coefficients and $128^3$ resolution, pre-computation is ~5.39 seconds [S1].

### Strengths and Limitations
*   **Strengths**: Avoids atomic operations and serialization, leading to high performance on GPUs [S1]. Preferred over direct residual accumulation despite higher memory usage [S1].
*   **Limitations**: High memory consumption [S1]. Cannot reproduce high-frequency details due to the low-pass filtering nature of isotropic volumes [S1].

### When to Use
*   Use when optimizing light source coefficients (e.g., environment maps) for volumetric scenes [S1].
*   Use when atomic contention is a bottleneck in direct coefficient updates [S1].
*   Use for stylizing environmental lighting, such as modifying environment maps for cloud scenes [S1].

### When Not to Use
*   Do not use if high-frequency detail reconstruction is required (e.g., matching logos) [S1].
*   Do not use if GPU memory is extremely constrained and cannot accommodate the light volumes [S1].

## Background

### Origin
The method was introduced in the paper "Property and Lighting Manipulations for Static Volume Stylization Using a Painting Metaphor" [S1].

### History and Development
The technique was developed to address performance issues in volume stylization where artists modify renderings to reflect desired outputs using tools like Adobe Photoshop [S1]. It was preferred over direct residual accumulation because it avoids atomic operations, despite higher memory usage [S1]. The method is particularly useful for modifying environmental illumination, such as in cloud scenes, where low-frequency lighting changes are sufficient [S1].

### Usage
The method is used for stylizing environmental lighting, such as modifying environment maps for cloud scenes [S1]. It allows artists to produce desired target images using image editing tools, and the optimization adjusts the light coefficients to match these targets [S1].
