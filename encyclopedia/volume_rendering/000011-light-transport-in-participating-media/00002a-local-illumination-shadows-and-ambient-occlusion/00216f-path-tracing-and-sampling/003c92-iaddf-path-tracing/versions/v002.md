# IADDF Path Tracing

Also called: Backward Path Tracing with DDF, DDF rendering via backward path tracing, DDF-based path tracing, backward path tracer, PathTracePixelDDF

## Overview
IADDF Path Tracing is a Monte Carlo rendering method that solves the classical rendering equation using Intrinsic Appearance Differentiable Distance Fields (IADDF) [S1]. It traces rays backwards from the eye to light sources, utilizing the DDF to find surface intersections and material/lighting fields to compute radiance [S1]. It builds on [Path Tracing and Sampling](2526-path-tracing-and-sampling.md) and is distinguished from standard path tracing by its reliance on differentiable implicit fields for geometry and appearance, allowing for continuous, analytic surface representation and shading without explicit mesh topology [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Pixel coordinate $u$, Camera $\Pi$ (containing camera position and ray direction).
*   **Models:** DDF $(d, \xi)$, Appearance $(f_B, \Psi)$, Illumination $(ML, EL)$.
*   **Hyper-parameters:** Maximum bounces $n$, Number of Monte Carlo samples $m$.
*   **Output:** Pixel color $c$ at $u$.

**Data Structures:**
The method operates on continuous fields defined over a domain $\mathbb{C} = \mathbb{R}^3$ [S1]. The DDF provides a distance function $d(\mathbf{p}, \mathbf{v})$ returning the distance to the nearest surface intersection in direction $\mathbf{v}$ from point $\mathbf{p}$, and a sign function $\xi(\mathbf{p}, \mathbf{v})$ indicating visibility/intersection status [S1]. The appearance model provides a BRDF field $f_B$ and a bounce sampler $\Psi$ [S1]. The illumination model provides a material emission field $ML$ and an environment light field $EL$ [S1]. All fields output three discrete color values [S1].

**Steps and Formulas:**
1.  **Camera Ray Initialization:** Get the oriented point $(\mathbf{p}, \mathbf{v})$ for pixel $u$ using camera $\Pi$ [S1]. While $\mathbf{p}$ may initially be the camera position, rendering proceeds by projecting $\mathbf{p}$ along the camera ray to the domain boundary $\mathcal{B}$ of the PDDF and using that boundary point as $\mathbf{p}$ [S1].
2.  **Intersection Test:** Check for ray intersection with the scene using $\xi(\mathbf{p}, \mathbf{v})$ [S1]. If $\xi(\mathbf{p}, \mathbf{v}) < 0.5$, the ray misses any local geometry; return $EL(\mathbf{v})$ [S1].
3.  **Surface Point and Normal:** Compute the intersection point $\mathbf{q} = \mathbf{p} + d(\mathbf{p}, \mathbf{v})\mathbf{v}$ [S1]. Compute the surface normal $\mathbf{n} = \text{Unit}(\nabla_{\mathbf{p}} d(\mathbf{p}, \mathbf{v}))$ [S1]. Define the outgoing direction $\omega_o = -\mathbf{v}$ [S1].
4.  **Emission Query:** Query the material emission field $ML$ at $\mathbf{q}$ for direction $\omega_o$ to get emitted color $c_E = ML(\mathbf{q}, \omega_o)$ [S1].
5.  **Monte Carlo Sampling (First Bounce):** Iterate $k$ from $1$ to $m$ [S1]. Sample a light direction $\mathbf{v}_n^{(k)} \sim \Psi(\mathbf{q}, \omega_o \mid \mathbf{n})$ [S1]. Define the incoming direction $\omega_i^{(k)} = -\mathbf{v}_n^{(k)}$ [S1]. Query the BRDF field $B = f_B(\mathbf{q}, \omega_i^{(k)}, \omega_o)$ [S1]. Recursively trace the ray $c_k = B \odot \text{Trace}(\mathbf{q}, \mathbf{v}_n^{(k)}, \ell=1)$ [S1]. Compute the Monte Carlo weight $w_k = \Psi(\mathbf{v}_n^{(k)} \mid \mathbf{q}, \omega_o)^{-1} |\mathbf{n} \cdot \omega_i^{(k)}|$ [S1].
6.  **Final Color Accumulation:** Compute the final pixel color $c = c_E + \frac{1}{m} \sum_{k=1}^{m} w_k c_k$ [S1]. Return $c$.

**Pseudocode:**
```python
def PathTracePixelDDF(u, Π, d, ξ, fB, Ψ, ML, EL, n, m):
    # 1. Camera Ray Initialization
    p, v = GetOrientedPoint(u, Π)  # [S1]
    # Project p to domain boundary B of PDDF if needed [S1]
    
    # 2. Intersection Test
    if ξ(p, v) < 0.5:
        return EL(v)  # [S1]
        
    # 3. Surface Point and Normal
    q = p + d(p, v) * v  # [S1]
    n = Unit(gradient_p(d(p, v)))  # [S1]
    ωo = -v  # [S1]
    
    # 4. Emission Query
    cE = ML(q, ωo)  # [S1]
    
    # 5 & 6. Monte Carlo Sampling & Accumulation
    c = cE
    for k in range(1, m + 1):  # [S1]
        vn = sample(Ψ(q, ωo, n))  # [S1]
        ωi = -vn  # [S1]
        B = fB(q, ωi, ωo)  # [S1]
        ck = B * Trace(q, vn, 1, d, ξ, fB, Ψ, ML, EL, n)  # [S1]
        wk = (1.0 / Ψ(vn, q, ωo)) * abs(dot(n, ωi))  # [S1]
        c += wk * ck  # [S1]
    c /= m  # [S1]
    return c  # [S1]

def Trace(p, v, ℓ, d, ξ, fB, Ψ, ML, EL, n):
    # 1. Intersection Test
    if ξ(p, v) < 0.5:
        return EL(v)  # [S1]
        
    # 2. Bounce Limit
    if ℓ >= n:
        return 0  # [S1]
        
    # 3. Surface Interaction
    q = p + d(p, v) * v  # [S1]
    n = Unit(gradient_p(d(p, v)))  # [S1]
    ωo = -v  # [S1]
    cE = ML(q, ωo)  # [S1]
    
    # 4. Sampling
    vn = sample(Ψ(q, ωo, n))  # [S1]
    ωi = -vn  # [S1]
    B = fB(q, ωi, ωo)  # [S1]
    
    # 5. Recursion
    c_rec = B * Trace(q, vn, ℓ + 1, d, ξ, fB, Ψ, ML, EL, n)  # [S1]
    
    # 6. Return
    return cE + (1.0 / Ψ(vn, q, ωo)) * abs(dot(n, ωi)) * c_rec  # [S1]
```

**Parameters:**
*   **Maximum bounces $n$:** Hyper-parameter limiting the recursion depth in the `Trace` function [S1].
*   **Number of MC Samples $m$:** Hyper-parameter for the number of Monte Carlo samples taken for the first bounce [S1].

**Edge Cases and Pitfalls:**
*   **Efficiency Optimization:** Only multiple Monte Carlo samples are used for the first bounce because contributions from subsequent bounces often fall off quickly [S1].
*   **Camera Ray Initialization:** The initial point $\mathbf{p}$ may be the camera position, but rendering proceeds by projecting $\mathbf{p}$ along the camera ray to the domain boundary $\mathcal{B}$ of the PDDF and using that boundary point as $\mathbf{p}$ [S1].
*   **Precision:** The gradient $\nabla_{\mathbf{p}} d(\mathbf{p}, \mathbf{v})$ must be computed accurately to ensure correct normals, requiring numerical differentiation or analytic gradients of the DDF [S1].

## Background
IADDF Path Tracing originates from the work on Probabilistic Directed Distance Fields (PDDF) for ray-based shape representations [S1]. It was introduced as a method to render scenes represented by differentiable fields, combining geometry (DDF), appearance (BRDF field $f_B$), and illumination (ML, EL) into a unified framework [S1]. The method is described as "backward" because rays start from the camera and bounce to a light source, which is the reverse of physical light propagation [S1].
