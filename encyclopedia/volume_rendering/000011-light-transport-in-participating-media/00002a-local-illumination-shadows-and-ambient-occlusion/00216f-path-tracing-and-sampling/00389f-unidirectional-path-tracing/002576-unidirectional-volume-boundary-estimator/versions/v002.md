# Unidirectional Volume Boundary Estimator

Also called: Main-path side-path sampling, Unidirectional estimator

## Overview
The Unidirectional Volume Boundary Estimator is a Monte Carlo method for estimating radiance contributions from volume boundary paths, where a scattering event occurs exactly on the boundary of a participating medium [S1]. It addresses the problem of efficiently sampling these specific path configurations by building a main path from the detector and constructing side paths to the light source via the boundary [S1]. It sets itself apart from the Bidirectional Volume Boundary Estimator by constructing the path unidirectionally from the detector first, rather than sampling the boundary vertex first, and it is typically combined with the bidirectional estimator using Multiple Importance Sampling (MIS) to reduce variance [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A scene with participating media, light sources, and a detector (camera).
*   **Output:** An estimate of the radiance contribution from volume boundary paths, $\langle \mathbf{I}_{\text{bnd}} \rangle$ [S1].

**Data Structures:**
*   **Main Path:** A sequence of vertices $\vec{\mathbf{p}}^D = (p^D_0, p^D_1, \dots)$ starting from the detector $p^D_0$ [S1].
*   **Side Path:** A sequence of vertices $\vec{\mathbf{p}}^S_n = (p^S_{n,0}, \dots, p^S_{n,m_n})$ connecting the boundary vertex to the light source [S1].
*   **Boundary Vertex:** A point $p^B_n$ located on the null interface $\partial BV$ of a translucent object [S1].

**Parameters:**
*   **Russian Roulette Threshold:** Used to stochastically decide whether to generate a side path based on the throughput of the main path vertex [S1]. The specific threshold value is not given in the sources.

**Steps:**
1.  **Build Main Path:** Construct a main path $(p^D_0, p^D_1, \dots)$ using unidirectional volume path tracing starting from the detector $p^D_0$ [S1].
2.  **Iterate Vertices:** For each vertex $p^D_n$ in the main path:
    a.  **Russian Roulette:** Stochastically decide whether to generate a side path using Russian roulette based on the throughput at $p^D_n$ [S1]. If the decision is to skip, continue to the next vertex.
    b.  **Sample Direction:** If generating a side path, draw a direction $\omega_n$ based on the BSDF or phase function at $p^D_n$ [S1].
    c.  **Find Boundary:** Trace a ray from $p^D_n$ in direction $\omega_n$ and find the intersection $p^B_n$ with all "null" interfaces $\partial BV$ [S1].
    d.  **Build Side Path:** Connect $p^B_n$ to a light source via a subpath $(p^S_{n,0}, \dots, p^S_{n,m_n})$ where $m_n \ge 0$ [S1].
    e.  **Form Volume Boundary Path:** Construct the full volume boundary path as $(p^S_{n,m_n}, \dots, p^S_{n,0}, p^B_n, p^D_n, \dots, p^D_0)$ [S1]. Here, $p^B_n$ corresponds to a volume scattering event happening exactly on the boundary [S1].
3.  **Estimate Contribution:** Calculate the contribution of the formed path using the estimator formula [S1].

**Formula:**
The single-sample Monte Carlo estimator for the radiance contribution is [S1]:

$$
\langle \mathbf{I}_{\text{bnd}} \rangle = \frac{f(\vec{\mathbf{p}}) \nu_{\perp}(\mathbf{p}_K)}{\text{pdf}(\vec{\mathbf{p}})}
$$

Where:
*   $f(\vec{\mathbf{p}})$ is the path contribution [S1].
*   $\nu_{\perp}(\mathbf{p}_K)$ is the perpendicular velocity at the boundary vertex $\mathbf{p}_K$ (which corresponds to $p^B_n$) [S1].
*   $\text{pdf}(\vec{\mathbf{p}})$ is the probability density of sampling the entire path $\vec{\mathbf{p}}$ [S1].

**Pseudocode:**
```python
def unidirectional_volume_boundary_estimator(scene, camera):
    # 1. Build main path from detector
    main_path = unidirectional_volume_path_tracing(scene, camera)
    
    total_estimate = 0.0
    
    for n, p_D_n in enumerate(main_path):
        # 2. Russian roulette to decide if side path is generated
        # [G] Typical implementation uses throughput to determine survival probability
        if not russian_roulette_survives(p_D_n.throughput):
            continue
            
        # 3. Draw direction based on BSDF or phase function at p_D_n
        omega_n = sample_direction_from_bsdf_or_phase_function(p_D_n)
        
        # 4. Trace ray to find boundary intersection p_B_n
        # [G] Assumes a ray-tracing primitive is available to find intersection with null interfaces
        p_B_n = trace_ray_and_find_boundary_intersection(scene, p_D_n.position, omega_n)
        
        if p_B_n is None:
            continue
            
        # 5. Connect p_B_n to a light source via a subpath
        # [G] m_n >= 0 implies the subpath can be just the light connection or include intermediate bounces
        side_path = connect_to_light_subpath(scene, p_B_n)
        
        # 6. Form the volume boundary path
        # Path order: side_path_reversed + [p_B_n] + main_path_prefix
        full_path = side_path.reverse() + [p_B_n] + main_path[:n+1]
        
        # Calculate contribution
        # [G] pdf calculation must account for all sampling steps: main path, direction, boundary intersection, side path
        path_pdf = calculate_path_probability(full_path)
        path_contribution = calculate_path_radiance(full_path)
        
        # Perpendicular velocity at boundary vertex
        # [G] Depends on the geometry of the boundary and the direction of arrival
        nu_perp = calculate_perpendicular_velocity(p_B_n)
        
        estimate = (path_contribution * nu_perp) / path_pdf
        total_estimate += estimate
        
    return total_estimate
```

## Subtopics

### [Bidirectional Volume Boundary Estimator](4773-bidirectional-volume-boundary-estimator.md)
Samples the boundary vertex first, then constructs two subpaths to the light and detector. Chosen when the unidirectional approach suffers from high variance due to difficult boundary intersections or when combined with the unidirectional estimator via MIS.

## Operating characteristics
*   **Complexity:** The complexity depends on the length of the main path and the side path. The use of Russian roulette helps control the computational overhead when the main path is long [S1].
*   **Strengths:** Supports the full radiative transfer model including multiple scattering, anisotropic phase functions, and heterogeneity [S1].
*   **Limitations:** Can suffer from high computational overhead if side paths are generated for every vertex of a long main path, hence the need for Russian roulette [S1].
*   **When to use:** When using unidirectional path tracing and needing to account for volume boundary scattering events, particularly in combination with the bidirectional estimator for variance reduction [S1].

## Background
The Unidirectional Volume Boundary Estimator was introduced in the paper "Efficient Path-Space Differentiable Volume Rendering With Respect To Shapes" by Shuang et al. (EGSR 2023) [S1]. It is part of a framework that includes both unidirectional and bidirectional estimators, combined using Multiple Importance Sampling (MIS) to handle volume boundary paths efficiently [S1].
