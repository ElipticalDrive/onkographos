# Volumetric-Primitives Path Tracer

Also called: Volumetric-Primitives Radiance Field (VPRF)

## Overview
Volumetric-Primitives Path Tracer (VPPT) is a forward rendering method for scattering and emissive media that models the scene as a collection of 3D kernel-based volumetric primitives and uses ray tracing to compute light transport, supporting multiple scattering via Next-Event Estimation [S1, unofficial]. Unlike 3D Gaussian Splatting (3DGS) which approximates density as a sum of delta functions leading to view-dependent ordering artifacts, VPPT maintains 3D volumetric density and integrates physically, preserving reciprocity and avoiding popping artifacts [S1, unofficial]. It builds on [Single and multiple scattering](35-single-and-multiple-scattering.md) by providing closed-form solutions for transmittance and free-flight distance sampling, enabling noise-free path tracing without relying on probabilistic grid-based approximations [S1, unofficial].

## How it works
**Inputs:**
*   A set of $N$ volumetric primitives $\{P_i\}_{i=1}^N$.
*   Each primitive $P_i$ is defined by:
    *   A spatial density distribution (kernel function $K_i(\mathbf{x})$).
    *   An optical cross-section $\sigma_i$ (or $\tau_i$ in some notations, representing the peak extinction magnitude).
    *   An emission term $Q_i(\boldsymbol{\omega})$.
    *   A phase function $f_{p,i}(\boldsymbol{\omega}' \to \boldsymbol{\omega})$.
*   A camera ray $\mathbf{r}(t) = \mathbf{o} + t\boldsymbol{\omega}$.
*   Acceleration structure (e.g., BVH) containing bounding boxes or shells for the primitives.

**Outputs:**
*   Radiance $L(\mathbf{x}_0, \boldsymbol{\omega})$ for the camera ray.

**Data Structures:**
*   **Primitive:** Stores kernel parameters (e.g., mean, covariance for Gaussian; center, bandwidth for Epanechnikov), $\sigma_i$, $Q_i$, and $f_{p,i}$.
*   **Segment:** An ordered interval $S_k = [b_{t_{k,0}}, b_{t_{k,1}}]$ along the ray, representing the intersection interval with a set of overlapping primitives.

**Algorithm Steps:**

1.  **Compute Extinction Field:**
    The total extinction coefficient at any point $\mathbf{x}$ is the superposition of contributions from all primitives:
    $$ \mu_t(\mathbf{x}) = \sum_{i=1}^{N} \sigma_i K_i(\mathbf{x}) $$
    [S1, unofficial]

2.  **Ray-Primitive Intersection and Segmentation:**
    Use hardware-accelerated ray tracing (e.g., BVH on OptiX) to find all intersecting volumetric primitive bounding boxes/shells for the camera ray. Sort the entry and exit points of these intersections to segment the ray into an ordered sequence of segments $S_k = [b_{t_{k,0}}, b_{t_{k,1}}]$. Each segment $S_k$ contains a specific set of overlapping primitives.
    [S1, unofficial]

3.  **Calculate Transmittance per Segment:**
    For each segment $S_k$, calculate the transmittance from the start of the segment $b_{t_{k,0}}$ to a point $t$ within the segment. This is done analytically by accumulating the optical depths $\tau_i$ of all primitives $i$ overlapping with the segment:
    $$ T(\mathbf{x}_{b_{t_{k,0}}}, \mathbf{x}_t) = \exp \left( -\sum_{i \in S_k} \tau_i(\mathbf{x}_{b_{t_{k,0}}}, \mathbf{x}_{\min(t, b_{t_{k,1}})}) \right) $$
    [S1, unofficial]
    The optical depth $\tau_i(\mathbf{x}_a, \mathbf{x}_b)$ for a single primitive $i$ along a ray segment from $a$ to $b$ is the integral of the kernel along the ray:
    $$ \tau_i(\mathbf{x}_a, \mathbf{x}_b) = \sigma_i \int_{\max(a, t_{i,0})}^{\min(b, t_{i,1})} K_i(\mathbf{x}_{t'}) dt' $$
    where $t_{i,0}$ and $t_{i,1}$ are the entry and exit parameters of the ray with respect to primitive $i$'s support.
    [S1, unofficial]

4.  **Sample Free-Flight Distance:**
    Sample a free-flight distance $t$ along the ray proportional to the probability density function (PDF) $p(t) = \mu_t(\mathbf{x}_t)T(\mathbf{x}_0, \mathbf{x}_t)$.
    *   For a single primitive, use analytical inversion of the transmittance function.
    *   For multiple overlapping primitives within a segment, use numerical root-finding (e.g., Newton-Raphson or bisection) on the cumulative optical depth, or approximate with uniform sampling if precision requirements allow.
    [S1, unofficial]

5.  **Radiance Integration (Next-Event Estimation):**
    Integrate radiance $L(\mathbf{x}_0, \boldsymbol{\omega})$ front-to-back over the segments. For each segment $S_k$, compute the radiance contribution $L_k$ from emission and in-scattering (using Next-Event Estimation to sample scattering events for multiple scattering). The total radiance is:
    $$ L(\mathbf{x}_0, \boldsymbol{\omega}) = \sum_{k=1}^{M} T^{k-1}(\mathbf{x}_0, \mathbf{x}_{b_{t_{k,0}}}) L_k(\mathbf{x}_{b_{t_{k,0}}}, \boldsymbol{\omega}) $$
    where $T^{k-1}$ is the transmittance from the camera origin to the start of segment $k$, and $L_k$ is the radiance emitted/scattered from segment $k$.
    [S1, unofficial]

**Parameters:**
*   **Kernel Types:**
    *   **Gaussian Kernel:** Uses the error function (erf) for closed-form transmittance. Has infinite support, requiring clipping to avoid evaluating all primitives [S1, unofficial].
    *   **Epanechnikov Kernel:** Has finite support, enabling more efficient acceleration structures and faster rendering. Better for sharp edges and high-frequency details [S1, unofficial].
*   **Optical Cross-section ($\sigma_i$):** Controls the density/extinction magnitude of each primitive.
*   **Phase Function ($f_{p,i}$):** Defines scattering directionality. Can use Henyey-Greenstein or Schlick's approximation [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Infinite Support:** Gaussian kernels have infinite support. In practice, they must be clipped to a certain radius to limit the number of primitives evaluated per ray. Failure to clip leads to $O(N)$ complexity per ray instead of $O(1)$ or $O(\log N)$ with BVH [S1, unofficial].
*   **Degenerate Input:** If primitives have zero cross-section or zero kernel magnitude, they should be skipped to avoid division by zero or numerical instability in root-finding.
*   **Precision:** Numerical root-finding for transmittance inversion in overlapping primitives can suffer from precision issues if the optical depth changes very rapidly. Bisection is more robust than Newton-Raphson in these cases [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering time is significantly faster than traditional grid-based methods due to the compact representation and closed-form solutions. Complexity depends on the number of primitives intersected by the ray, which is managed by the BVH. With Epanechnikov kernels, the finite support further reduces the number of primitives to check [S1, unofficial].
*   **Memory Complexity:** Memory usage is proportional to the number of primitives $N$, which is much smaller than the number of voxels in a grid for equivalent visual fidelity. This allows for high-resolution scenes with low memory footprint [S1, unofficial].
*   **Measured Performance:** The method achieves significant speedups compared to voxel-based approaches and avoids the noise associated with Monte Carlo sampling in grids. It supports Level-of-Detail (LoD) by adjusting the number of primitives [S1, unofficial].
*   **Strengths:** Noise-free rendering (due to closed-form integration), physically based, supports multiple scattering via NEE, compact memory usage, sharp details with Epanechnikov kernels.
*   **Limitations:** Requires efficient BVH construction and traversal. Gaussian kernels require clipping. Not inherently suited for inverse rendering without additional gradient computation machinery (though the paper mentions it is possible).
*   **When to use:** When high-quality, physically accurate volumetric rendering is needed with limited memory, or when sharp volumetric details are required. Suitable for both forward and inverse rendering applications.
*   **When not to use:** If the scene is extremely dense with many small primitives that cannot be efficiently accelerated by BVH, or if real-time performance on very low-end hardware is critical without hardware ray tracing support.

## Background
The method was proposed in 2025 by researchers at Meta, titled "Don’t Splat your Gaussians: Volumetric Ray-Traced Primitives for Modeling and Rendering Scattering and Emissive Media" [S1, unofficial]. It addresses the limitations of 3D Gaussian Splatting (3DGS) in physically based rendering, where 3DGS treats volumes as splats (delta functions) that lack true volumetric density and reciprocity. VPPT introduces 3D kernel-based primitives that can be ray-traced, enabling accurate light transport simulation. The work builds on the principles of radiative transfer and extends them with efficient closed-form integration techniques [S1, unofficial].
