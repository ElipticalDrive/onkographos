# Unidirectional Path Tracing

Also called: PathTracing, Standard Path Tracing Lighting

## Overview
Unidirectional Path Tracing is a Monte Carlo method for solving the rendering equation by tracing paths from the camera into the scene, accumulating radiance through surface reflections and volumetric scattering [S1, S2, unofficial]. It differs from bidirectional methods by constructing a single path tree rooted at the sensor, making it suitable for real-time or interactive applications where memory bandwidth for multiple path trees is prohibitive [S2, unofficial]. Unlike explicit path tracing with Russian Roulette which separates the termination logic into a distinct post-loop phase, this method integrates survival probability checks directly into the main traversal loop to handle path termination dynamically [S2, unofficial].

## How it works
**Inputs:**
- Camera position, orientation, and lens parameters.
- Scene geometry (primitives) and material definitions (BSDFs).
- Volume definitions (extinction coefficient $\sigma_t$, scattering coefficient $\sigma_s$, phase function $p$).
- Light sources (emitted radiance $L_e$).
- Random number generator (Sampler).
- `maxDepth`: Maximum path length (default 100) [S2, unofficial].
- `rayBounces`: Parameter controlling bounce limits in scene data [S1, unofficial].

**Outputs:**
- Radiance $L$ for each pixel.

**Data Structures:**
- **Ray:** Struct containing `origin` (Vec3f), `direction` (Vec3f), `tmax` (float, implied by intersection), and `throughput` (Vec3f) [S2, unofficial].
- **Medium Stack:** A stack of pointers to medium objects, managed via `pushMedium` and `popMedium`, used to track the current participating media during traversal [S2, unofficial].
- **Materials:** Defined in a constant array `MATERIALS` of size 5. Each material has `specular` (f32) and `emissive` (bool) fields.
    - Index 0: specular 0.0, not emissive.
    - Index 1: specular 0.0, not emissive.
    - Index 2: specular 0.0, emissive.
    - Index 3: specular 0.9, not emissive.
    - Index 4: specular 1.0, not emissive [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Set radiance $L = 0$, ray throughput $T = (1, 1, 1)$, and path depth $d = 0$. Initialize the medium stack with the background medium [S2, unofficial].
2.  **Traversal Loop:** While $d < \text{maxDepth}$:
    a.  **Russian Roulette:** If $d > 0$, calculate survival probability $p = \min\left(\frac{T_r + T_g + T_b}{3}, 1.0\right)$. If `sampler.getNext1D()` $\ge p$, break the loop. Otherwise, update $T \leftarrow T / p$ [S2, unofficial].
    b.  **Intersection:** Cast ray against scene geometry. If no hit, break loop.
    c.  **Area Light Check:** If the hit primitive is an area light, add $T \cdot L_e$ to $L$ and break loop [S2, unofficial].
    d.  **Surface Interaction:** If the hit primitive has a surface:
        i.  **Shading Normal Check:** Let $\mathbf{n}_g$ be the geometric normal and $\mathbf{n}_s$ be the shading normal. Let $\omega_i$ be the incoming direction (from surface to camera, i.e., $-\text{ray.direction}$) and $\omega_o$ be the outgoing direction (sampled BSDF direction). If $\omega_i \cdot \mathbf{n}_g \cdot \omega_i \cdot \mathbf{n}_s \le 0$ or $\omega_o \cdot \mathbf{n}_g \cdot \omega_o \cdot \mathbf{n}_s \le 0$, return 0 (prevent light leaks) [S2, unofficial].
        ii. **BSDF Sampling:** Sample the BSDF to get outgoing direction $\omega_o$ and PDF $p(\omega_o)$. Calculate BSDF value $f(\omega_i, \omega_o)$ [S2, unofficial].
        iii. **Throughput Update:** Update throughput:
        $$ T_{new} = T_{old} \cdot \frac{f(\omega_i, \omega_o) \cdot |\cos \theta|}{p(\omega_o)} $$
        where $\theta$ is the angle between $\mathbf{n}_s$ and $\omega_o$ [S2, unofficial].
        iv. **Medium Update:** Update the medium stack based on surface crossing using `updateMedium(ray, dir, info)` [S2, unofficial].
        v.  **Ray Update:** Set ray origin to surface position and direction to $\omega_o$. Set flag `is_reflected_or_refracted = true` [S2, unofficial].
    e.  **Volume Interaction:** If the ray is in a participating medium (or if `is_scattered` is true from a previous step, though typically volume sampling happens during ray marching):
        i.  Sample free flight distance $t$ using the cumulative distribution function derived from $\sigma_t$.
        ii. If the sampled distance hits a surface before leaving the medium, handle surface interaction (steps d).
        iii. If the ray exits the medium or no surface is hit, accumulate scattered light from the volume segment.
        iv. Set flag `is_scattered = true` [S2, unofficial].
    f.  **Depth Increment:** If `is_scattered` or `is_reflected_or_refracted` is true, increment $d$ [S2, unofficial].
    g.  **Reset Flags:** Reset `is_scattered` and `is_reflected_or_refracted` to false for the next iteration [S2, unofficial].

**Pseudocode:**
```python
def unidirectional_path_tracing(camera, scene, sampler, max_depth=100):
    radiance = Vec3f(0, 0, 0)
    throughput = Vec3f(1, 1, 1)
    depth = 0
    ray = camera.sample_ray(sampler)
    medium_stack = [scene.background_medium]
    
    while depth < max_depth:
        # Russian Roulette
        if depth > 0:
            survival_prob = min((throughput.r + throughput.g + throughput.b) / 3.0, 1.0)
            if sampler.get_next_1d() >= survival_prob:
                break
            throughput = throughput / survival_prob
        
        # Intersection
        hit = scene.intersect(ray)
        if not hit:
            break
        
        # Area Light
        if hit.is_area_light:
            radiance += throughput * hit.emitted_radiance
            break
        
        # Surface Interaction
        if hit.has_surface:
            # Shading Normal Check
            wi = -ray.direction
            wo = hit.sample_bsdf(wi, sampler)
            pdf = hit.bsdf_pdf(wi, wo)
            
            if dot(wi, hit.geometric_normal) * dot(wi, hit.shading_normal) <= 0 or \
               dot(wo, hit.geometric_normal) * dot(wo, hit.shading_normal) <= 0:
                break # Light leak prevention
            
            f = hit.bsdf(wi, wo)
            cos_theta = abs(dot(wo, hit.shading_normal))
            throughput = throughput * (f * cos_theta) / pdf
            
            # Medium Update
            medium_stack = update_medium_stack(ray, wo, hit)
            
            # Ray Update
            ray.origin = hit.position
            ray.direction = wo
            ray.tmax = scene.world_size # Reset tmax for new ray
            
            is_reflected_or_refracted = True
        else:
            is_reflected_or_refracted = False
            
        # Volume Interaction (Simplified for single step)
        # Note: Full volume path tracing requires marching through the medium
        # This step assumes volume scattering is handled within the ray march
        # or via a separate volume intersection routine.
        # For the purpose of this algorithm structure from [S2, unofficial], volume
        # scattering events update throughput similarly to surfaces.
        
        if is_reflected_or_refracted or is_scattered:
            depth += 1
            
        is_scattered = False
        is_reflected_or_refracted = False
        
    return radiance
```

**Parameters:**
- `maxDepth`: Maximum path length. Default value is 100 [S2, unofficial].
- `rayBounces`: Controls the number of ray bounces in `SceneData` [S1, unofficial].
- Sun direction: Defined by `sunDirX`, `sunDirY`, `sunDirZ` (vec3f) [S1, unofficial].
- Sun intensity: Defined by `sunIntensity` (f32) [S1, unofficial].
- Sun enabled: Defined by `sunEnabled` (u32) [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Light Leaks:** Prevented by checking the asymmetry of the BSDF using shading normals ($\mathbf{n}_s$) and geometric normals ($\mathbf{n}_g$). If $\omega_i \cdot \mathbf{n}_g \cdot \omega_i \cdot \mathbf{n}_s \le 0$ or $\omega_o \cdot \mathbf{n}_g \cdot \omega_o \cdot \mathbf{n}_s \le 0$, the contribution is zeroed out [S2, unofficial].
- **Precision:** Throughput division by survival probability can lead to variance explosion if probability is very low. Clamping probability to a minimum value is recommended [G].
- **Boundary Conditions:** When crossing surface boundaries, the medium stack must be updated correctly to ensure the correct extinction coefficient is used for subsequent volume interactions [S2, unofficial].

## Subtopics

### [Unidirectional Volume Boundary Estimator](3538-unidirectional-volume-boundary-estimator.md)
A Monte Carlo method for estimating radiance from volume scattering events occurring exactly on the boundary of participating media. It constructs a "main" path from the detector and generates "side" paths from main path vertices to the volume boundary and then to the light source. Choose this when boundary interactions dominate the scattering contribution.

## Operating characteristics
- **Time Complexity:** $O(N \cdot D)$, where $N$ is the number of pixels and $D$ is the average path depth. Each bounce involves a scene intersection and a BSDF/volume sampling [S1, S2, unofficial].
- **Memory Complexity:** $O(D)$ for the path stack and medium stack. No need to store multiple paths as in bidirectional methods [S2, unofficial].
- **Measured Performance:** On an RTX 3090, a related voxel raymarching implementation achieves around 120fps at 4K, dipping to 60fps or lower depending on scene complexity [S1, unofficial].
- **Strengths:** Low memory footprint, simple implementation, suitable for real-time rendering [S1, unofficial].
- **Limitations:** High variance in scenes with complex lighting or deep shadows due to the unidirectional nature. Requires many samples for convergence [S2, unofficial].
- **When to Use:** Real-time applications, interactive rendering, or scenes with simple lighting.
- **When Not to Use:** Scenes with complex indirect lighting, caustics, or deep shadows where bidirectional methods or path space exploration would be more efficient.

## Background
Unidirectional path tracing was introduced by James T. Kajiya in 1986 as a generalization of Monte Carlo ray tracing to solve the full rendering equation [S2, S1, unofficial]. It has become a standard technique in offline rendering and is increasingly used in real-time graphics with hardware acceleration. The method is foundational for modern path tracers and serves as the basis for more advanced techniques like bidirectional path tracing and Metropolis light transport [S2, unofficial].
