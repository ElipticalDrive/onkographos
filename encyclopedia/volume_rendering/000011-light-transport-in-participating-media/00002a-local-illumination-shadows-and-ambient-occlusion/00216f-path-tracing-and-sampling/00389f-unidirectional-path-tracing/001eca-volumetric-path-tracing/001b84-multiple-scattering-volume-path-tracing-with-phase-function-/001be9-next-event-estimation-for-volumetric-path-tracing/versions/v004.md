# Next Event Estimation for Volumetric Path Tracing

Also called: NEE with transmittance, PathTracingNEE, Volumetric NEE, Volumetric Next Event Estimation with Index-Matching Surfaces, Volumetric Path Tracing 4, Volumetric Path Tracing with Next Event Estimation

## Overview
Next Event Estimation (NEE) for volumetric path tracing is an optimization that adds direct lighting estimation to multiple scattering volume path tracing by sampling points on light sources and tracing shadow rays through participating media and index-matching surfaces [S1, S3]. It solves the inefficiency of pure phase function sampling when light sources are small or distant by explicitly connecting path vertices to lights [S1]. Unlike its parent method, which only samples the phase function, this method changes the integration domain from the hemisphere to the light surface area, requiring the computation of transmittance through volumes and the handling of index-matched boundaries [S1, S3]. It differs from [Volumetric Path Tracing with BSSRDF and Medium Sampling](1867-volumetric-path-tracing-with-bssrdf-and-medium-sampling.md) by focusing on direct light connections via shadow rays rather than medium sampling for indirect illumination [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Current scattering position $\mathbf{p}$ in the medium, current medium properties $\sigma_t$ (extinction coefficient), view direction $\omega_o$, light sampler, and scene geometry including index-matching surfaces (surfaces with no material assigned, `material_id == -1`) [S1, S3].
*   **Output:** Direct lighting contribution $L_s$ at $\mathbf{p}$ from the sampled light, or 0 if blocked.

**Data Structures:**
*   `Ray`: Origin $\mathbf{o}$, direction $\mathbf{d}$, medium reference.
*   `Intersection`: Hit position $\mathbf{p}_{hit}$, distance $t$, `material_id` (opaque if $\ge 0$, index-matching if $-1$) [S1, S3].
*   `LightSampleContext`: Contains surface interaction info for light sampling [S4].

**Parameters:**
*   `max_depth`: Maximum path depth (bounces + shadow bounces) [S1, S3].
*   `ShadowEpsilon`: Small offset to prevent self-intersection (e.g., $10^{-3}$ or $10^{-9}$ depending on implementation) [S2, unofficial][S4].

**Steps:**

1.  **Light Sampling:**
    Sample a light source and a point $\mathbf{p}'$ on it.
    *   Sample light index: $u_1 = \text{sampler.Get1D()}$.
    *   Sample point on light: $u_2 = \text{sampler.Get2D()}$.
    *   Compute light PDF: $p_{light} = p_{\text{selection}} \cdot p_{\text{point}}$ [S4].
    *   If no sample or $L_e(\mathbf{p}') = 0$, return 0 [S4].

2.  **Shadow Ray Initialization:**
    *   Direction to light: $\mathbf{d}_{light} = \text{normalize}(\mathbf{p}' - \mathbf{p})$.
    *   Initialize transmittance accumulator: $T_{light} = 1$.
    *   Initialize shadow medium: $\text{shadow\_medium} = \text{current\_medium}$.
    *   Initialize shadow bounce counter: $\text{shadow\_bounces} = 0$.
    *   Initialize MIS transmittance PDF factor: $p_{trans\_dir} = 1$ [S1, S3].

3.  **Shadow Ray Tracing Loop:**
    While $\mathbf{d}_{light} \neq \mathbf{0}$:
    *   Create shadow ray: $\mathbf{r} = \text{Ray}(\mathbf{p}, \mathbf{d}_{light})$.
    *   Intersect with scene: $\text{isect} = \text{intersect}(\text{scene}, \mathbf{r})$.
    *   Determine segment distance:
        *   If $\text{isect}$ exists: $t_{seg} = \text{distance}(\mathbf{p}, \text{isect.position})$.
        *   Else: $t_{seg} = \text{distance}(\mathbf{p}, \mathbf{p}')$.
    *   **Compute Transmittance:**
        *   If $\text{shadow\_medium}$ is valid:
            *   $T_{light} \leftarrow T_{light} \cdot \exp(-\sigma_t \cdot t_{seg})$.
            *   $p_{trans\_dir} \leftarrow p_{trans\_dir} \cdot \exp(-\sigma_t \cdot t_{seg})$ [S1, S3].
    *   **Check Visibility:**
        *   If no intersection: Light is visible. Break loop.
        *   If intersection exists:
            *   If $\text{isect.material\_id} \ge 0$ (Opaque): Ray is blocked. Return 0 [S1, S3].
            *   If $\text{isect.material\_id} == -1$ (Index-Matching):
                *   Increment $\text{shadow\_bounces}$.
                *   Check depth limit: If $\text{bounces} + \text{shadow\_bounces} \ge \text{max\_depth}$, return 0 [S1, S3].
                *   Update $\text{shadow\_medium}$ based on the surface intersection (entering/exiting volume) [S1, S3].
                *   Advance position: $\mathbf{p} \leftarrow \mathbf{p} + t_{seg} \cdot \mathbf{d}_{light}$.
                *   Continue loop [S1, S3].

4.  **Contribution Calculation:**
    If $T_{light} > 0$:
    *   Compute Geometry Term: $G = \frac{|\mathbf{n}_{\mathbf{p}'} \cdot \mathbf{d}_{light}|}{\|\mathbf{p} - \mathbf{p}'\|^2}$ [S1, S3].
    *   Evaluate Phase Function: $f_p = \text{phase}(\omega_o, -\mathbf{d}_{light})$ [S2, unofficial][S4].
    *   Compute NEE PDF (Area measure): $p_{nee} = p_{light}$ [S1, S3].
    *   Compute Phase Function PDF (converted to area measure for MIS):
        *   $p_{phase\_area} = p_{\text{sample\_phase}}(\omega_o, -\mathbf{d}_{light}) \cdot G \cdot p_{trans\_dir}$ [S1, S3].
    *   Compute Contribution:
        *   $L_s = T_{light} \cdot f_p \cdot L_e(\mathbf{p}') \cdot G$ [S2, unofficial].
    *   Apply Multiple Importance Sampling (MIS) Weight (Power Heuristic):
        *   $w = \frac{p_{nee}^2}{p_{nee}^2 + p_{phase\_area}^2}$ [S1, S3].
    *   Return $w \cdot \frac{L_s}{p_{nee}}$ [S1, S3].

**Pseudocode:**

```python
def next_event_estimation(p, current_medium, phase_function, light_sampler, scene, sampler, bounces, max_depth):
    # 1. Sample Light
    u1 = sampler.get_1d()
    u2 = sampler.get_2d()
    
    # Sample light source and point on it
    sampled_light = light_sampler.sample(u1)
    if not sampled_light:
        return 0.0
    
    light = sampled_light.light
    ls = light.sample_li(u2)
    if not ls or ls.L == 0 or ls.pdf == 0:
        return 0.0
        
    light_pdf = sampled_light.p * ls.pdf
    p_prime = ls.p_light
    L_e = ls.L
    
    # 2. Initialize Shadow Ray State
    d_light = normalize(p_prime - p)
    T_light = 1.0
    shadow_medium = current_medium
    shadow_bounces = 0
    p_trans_dir = 1.0
    
    # 3. Trace Shadow Ray
    while d_light != Vector3f(0, 0, 0):
        shadow_ray = Ray(p, d_light)
        isect = scene.intersect(shadow_ray)
        
        # Determine segment length
        if isect:
            next_t = distance(p, isect.position)
        else:
            next_t = distance(p, p_prime)
            
        # Compute transmittance for this segment
        if shadow_medium:
            sigma_t = shadow_medium.sigma_t
            T_light *= exp(-sigma_t * next_t)
            p_trans_dir *= exp(-sigma_t * next_t)
            
        if not isect:
            # Light is visible
            break
        else:
            # Check if blocked
            if isect.material_id >= 0:
                # Opaque surface blocks the light
                return 0.0
            else:
                # Index-matching surface: pass through
                shadow_bounces += 1
                if max_depth != -1 and bounces + shadow_bounces >= max_depth:
                    return 0.0
                    
                # Update medium for the next segment
                shadow_medium = update_medium(isect, shadow_ray, shadow_medium)
                
                # Advance position
                p = p + next_t * d_light
                
    # 4. Compute Contribution
    if T_light <= 0:
        return 0.0
        
    # Geometry term
    dist_vec = p_prime - p
    dist_sq = dot(dist_vec, dist_vec)
    if dist_sq == 0:
        return 0.0
    G = abs(dot(ls.n, -d_light)) / dist_sq
    
    # Phase function evaluation
    f_p = phase_function.p(-d_light, -d_light) # Assuming phase function takes incoming/outgoing relative to surface normal or similar convention; typically p(wo, wi)
    # Note: In standard NEE, we evaluate phase at the scattering point p.
    # wo is the view direction (from p to camera), wi is from p to light (-d_light).
    # The pseudocode in [S1] implies f is evaluated at the scattering angle.
    # Let's assume standard phase function signature p(omega_in, omega_out).
    # Here, we are estimating incoming radiance from light.
    # The term f_p in [S1] is likely the phase function value.
    # Correct evaluation: phase_function.p(-d_light, view_direction) or similar.
    # Based on [S1] formula: rho(p, omega, omega'). omega is view, omega' is light direction.
    # So f_p = phase_function.p(-d_light, view_direction) ? 
    # Actually, the integral is over omega'. The estimator uses f_p(omega_o, omega').
    # Let's stick to the variable names in [S1]: f is the scattering function.
    f_hat = phase_function.p(-d_light, -d_light) # Placeholder for actual phase eval, usually depends on view dir too.
    # Correction: The contribution is T * f * L * G. f is the phase function.
    # The PDF in denominator is p_nee.
    
    # MIS PDFs
    # p_nee is the PDF of the light sample (area measure)
    p_nee = light_pdf
    
    # p_phase needs to be converted to area measure for MIS
    # p_phase_area = p_phase_sample * G * p_trans_dir
    # We need the PDF of sampling the direction -d_light using the phase function
    p_phase_sample = phase_function.PDF(-d_light, -d_light) # Placeholder
    p_phase_area = p_phase_sample * G * p_trans_dir
    
    # Power heuristic
    w = (p_nee * p_nee) / (p_nee * p_nee + p_phase_area * p_phase_area)
    
    # Contribution
    contrib = T_light * f_hat * L_e * G / p_nee
    
    return w * contrib
```

*Note: The pseudocode above simplifies the phase function evaluation. In practice, `f_hat` should be `phase_function.p(omega_o, -d_light)` where `omega_o` is the direction from the scattering point to the camera (or previous vertex). The `p_phase_sample` should be `phase_function.PDF(omega_o, -d_light)`.*

## Subtopics

### Next-Hit Event Estimation with Importance Sampling
A strategy for sampling the boundary term of the differential path integral using pre-processed importance grids to handle sparse, high-frequency integrands [S5, unofficial]. It performs a photon mapping pass from light sources and an importon mapping pass from the sensor to assign importance values to grid cells, which are then used to sample the edge (1D manifold) and complete the light path (2D manifold direction) [S5, unofficial]. The integral is transformed to primary sample space variables $u_1 \in \mathbb{R}$ and $u_2 \in \mathbb{R}^2$ [S5, unofficial]. A pitfall is that for complicated scenes, the grid resolution required becomes impractically high [S5, unofficial].

### Multiple Vertex Next Event Estimation
Proposed by Weber et al., this method connects a point to the light source with sub-paths generated by perturbation, instead of one-segment connections [S6]. It is intended for multiple scattering in high-order scattering homogeneous participating media and is combined with a path tracer via MIS [S6]. It significantly reduces noise and increases performance in highly anisotropic, optically dense media but is unsuitable for participating media with boundaries [S6].

## Operating characteristics
*   **Time Complexity:** Adds $O(K)$ cost per scattering event, where $K$ is the number of shadow ray bounces (index-matching surfaces) before hitting the light or an opaque surface. In dense media, transmittance computation dominates.
*   **Memory Complexity:** Minimal additional memory, requiring only state variables for the shadow ray ($T_{light}$, medium, bounces) [S1, S3].
*   **Performance:** Significantly reduces variance for scenes with small or distant lights compared to pure phase function sampling [S1]. Performance degrades if the shadow ray traverses many index-matching surfaces or if the medium is extremely dense (requiring many small steps for transmittance) [S1, S4].
*   **Strengths:** Handles index-matching surfaces correctly; provides unbiased direct lighting estimation; integrates with MIS to balance with phase function sampling [S1, S3].
*   **Limitations:** Requires handling of index-matching surfaces explicitly; transmittance calculation can be expensive in heterogeneous media (though this method assumes homogeneous for the core algorithm, [S4] extends it with ratio tracking) [S1, S4].

## Background
Originating from the extension of volumetric path tracing to include direct lighting, this method was introduced as "Volumetric Path Tracing 4" in coursework from the University of California, San Diego [S1, S3]. It addresses the limitation of previous methods that only sampled the phase function, which is inefficient for small light sources [S1]. The mathematical foundation is the change of variable from the spherical integral to the light surface area integral [S1, S3]. It is used in unidirectional path tracing for participating media, particularly in educational and research contexts for rendering fog, smoke, and other homogeneous volumes with index-matched boundaries [S1, S3].
