# Recursive Trace Function

Also called: DDF-based recursive path tracing

## Overview
The Recursive Trace Function is the core recursive routine used in backward path tracing with Directed Distance Fields (DDF) to compute light transport for subsequent bounces [S1]. It handles intersection, shading, and recursion logic for a single light path segment [S1].

## How it works
**Inputs and Outputs:**
- **Inputs:** $p$: Origin point in $\mathbb{R}^3$ [S1]. $v$: Incoming direction vector (pointing towards the eye, i.e., $-v$ is the ray direction) [S1]. $\ell$: Current bounce level (integer) [S1].
- **Outputs:** $c$: Radiance color vector (RGB) at $p$ from direction $v$ [S1].

**Data Structures:**
- **DDF ($d, \xi$):** A scalar field $d(p, v)$ representing the distance to the surface along direction $v$ from $p$, and a binary field $\xi(p, v)$ indicating intersection ($\xi < 0.5$) [S1].
- **Material Emission Field ($M_L$):** Queries emitted color $c_E$ at point $q$ for direction $\omega_o$ [S1].
- **BRDF Field ($f_B$):** Queries reflectance $B$ for incoming $\omega_i$ and outgoing $\omega_o$ [S1].
- **BRDF Sampling Distribution ($\Psi$):** Samples outgoing direction $v_n$ given point $q$, outgoing direction $\omega_o$, and normal $n$ [S1].

**Parameters:**
- $n_{\text{max}}$: Maximum number of bounces (hyper-parameter) [S1]. (Renamed from the source's $n$ to avoid collision with the surface normal $n$)

**Steps:**
1. **Intersection Check:** Evaluate $\xi(p, v)$ [S1]. If $\xi(p, v) < 0.5$, the ray does not intersect the scene geometry [S1]. Return the environment light $EL(v)$ [S1].
2. **Bounce Limit Check:** If $\ell \ge n_{\text{max}}$, the maximum bounce depth is reached [S1]. Return the zero vector $\vec{0}$ [S1].
3. **Forward Pass (Position):** Compute the next scene point $q$ along the ray direction $-v$:
   $$ q = p + d(p, v)v $$ [S1]
4. **Backward Pass (Normal):** Compute the surface normal $n$ at $q$ by taking the gradient of the distance field with respect to position:
   $$ n = \text{Unit}(\nabla_p d(p, v)) $$ [S1]
5. **Direction Definitions:** Outgoing direction (towards eye): $\omega_o = -v$ [S1]. Sample a light direction $v_n$ from the BRDF sampling distribution: $v_n \sim \Psi(q, \omega_o \mid n)$ [S1]. Incoming direction (into surface): $\omega_i = -v_n$ [S1].
6. **Emission Query:** Query the material emission field at $q$ for direction $\omega_o$:
   $$ c_E = M_L(q, \omega_o) $$ [S1]
7. **BRDF Query:** Query the BRDF field at $q$ for directions $\omega_i$ and $\omega_o$:
   $$ B = f_B(q, \omega_i, \omega_o) $$ [S1]
8. **Recursive Call:** Recursively call `Trace` with the new origin $q$, direction $v_n$, and incremented bounce level $\ell + 1$:
   $$ c_{\text{rec}} = \text{Trace}(q, v_n, \ell + 1) $$ [S1]
9. **Weight Calculation:** Compute the Monte Carlo weight $w_k$ for the sampled direction:
   $$ w_k = \Psi(v_n \mid q, \omega_o)^{-1} |n \cdot \omega_i| $$ [S1]
10. **Return:** Return the sum of emitted color and the weighted recursive color:
    $$ c = c_E + w_k (B \odot c_{\text{rec}}) $$ [S1] The source pseudocode [S1] shows $B \odot \text{Trace}(\dots)$ inside the recursive call in Fig 25, but Fig 26 shows $B \odot \text{Trace}(\dots)$ as part of the return calculation. Fig 26 is the specific definition of the recursive function. The return statement is $c_E + \Psi(v_n \mid q, \omega_o)^{-1} |n \cdot \omega_i| c$, where $c$ is the result of $B \odot \text{Trace}(\dots)$. Thus, the final formula is $c_E + w_k (B \odot c_{\text{rec}})$ [S1].

**Pseudocode:**
```python
def Trace(p, v, l, n_max, d, xi, grad_d, M_L, f_B, Psi, EL):
    # 1. Intersection Check
    if xi(p, v) < 0.5:
        return EL(v)
    
    # 2. Bounce Limit Check
    if l >= n_max:
        return [0.0, 0.0, 0.0]
    
    # 3. Forward Pass: Compute scene point q
    q = p + d(p, v) * v
    
    # 4. Backward Pass: Compute surface normal n
    # grad_d returns the gradient vector at p for direction v
    normal = normalize(grad_d(p, v))
    
    # 5. Direction Definitions
    omega_o = -v
    # Sample outgoing direction from BRDF distribution
    v_n = sample(Psi, q, omega_o, normal)
    omega_i = -v_n
    
    # 6. Emission Query
    c_E = M_L(q, omega_o)
    
    # 7. BRDF Query
    B = f_B(q, omega_i, omega_o)
    
    # 8. Recursive Call
    c_rec = Trace(q, v_n, l + 1, n_max, d, xi, grad_d, M_L, f_B, Psi, EL)
    
    # 9. Weight Calculation
    # Psi returns the PDF value for the sampled direction v_n
    pdf = Psi(q, omega_o, normal, v_n)
    weight = (1.0 / pdf) * abs(dot(normal, omega_i))
    
    # 10. Return
    # B is multiplied element-wise with c_rec
    return c_E + weight * (B * c_rec)
```

**Edge Cases and Pitfalls:**
- **Gradient Precision:** Computing $\nabla_p d(p, v)$ requires numerical or analytical gradients of the DDF [S1]. Small errors in the normal can cause shading artifacts [G].
- **Zero PDF:** If $\Psi$ returns 0 for the sampled direction, division by zero occurs [G]. The sampling distribution must be non-zero where the BRDF is non-zero [G].
- **Recursion Depth:** The function relies on the parent to manage the maximum bounce count $n_{\text{max}}$ [S1]. If $n_{\text{max}}$ is too small, paths terminate prematurely; if too large, performance degrades [G].

## Operating characteristics
- **Time Complexity:** $O(n_{\text{max}})$ per path, where $n_{\text{max}}$ is the maximum bounce depth [S1]. Each recursive call performs one forward pass ($d(p, v)$) and one backward pass ($\nabla_p d(p, v)$) on the DDF [S1].
- **Memory Complexity:** $O(n_{\text{max}})$ stack space for recursion depth [G].
- **Strengths:** Integrates seamlessly with DDF-based rendering, avoiding explicit mesh intersection tests [S1]. Simple to implement as a recursive routine [G].
- **Limitations:** Recursion depth is limited by stack size [G]. Performance depends heavily on the efficiency of the DDF queries [S1].

## Background
The Recursive Trace Function is defined in the context of "Probabilistic Directed Distance Fields for Ray-Based Shape Representations" [S1]. It is part of a backward path tracing algorithm that uses DDFs to represent scene geometry and material properties [S1]. The method was introduced to enable efficient rendering of complex shapes represented by DDFs without explicit geometry [S1].
