# Recursive Trace Function

Also called: DDF-based recursive path tracing, Trace

## Overview
The Recursive Trace Function is the core recursive routine used in backward path tracing with Directed Distance Fields (DDF) to compute light transport for subsequent bounces. It handles the intersection, shading, and recursion logic for a single light path segment. It is distinguished from non-recursive or iterative path tracers by its explicit handling of DDF queries (forward and backward passes) and its direct integration of Russian Roulette termination logic via the parent algorithm's bounce limit.

## How it works
**Inputs and Outputs:**
- **Inputs:**
  - $p$: Origin point in $\mathbb{R}^3$.
  - $v$: Incoming direction vector (pointing towards the eye, i.e., $-v$ is the ray direction).
  - $\ell$: Current bounce level (integer).
- **Outputs:**
  - $c$: Radiance color vector (RGB) at $p$ from direction $v$.

**Data Structures:**
- **DDF ($d, \xi$):** A scalar field $d(p, v)$ representing the distance to the surface along direction $v$ from $p$, and a binary field $\xi(p, v)$ indicating intersection ($\xi < 0.5$).
- **Material Emission Field ($M_L$):** Queries emitted color $c_E$ at point $q$ for direction $\omega_o$.
- **BRDF Field ($f_B$):** Queries reflectance $B$ for incoming $\omega_i$ and outgoing $\omega_o$.
- **BRDF Sampling Distribution ($\Psi$):** Samples outgoing direction $v_n$ given point $q$, outgoing direction $\omega_o$, and normal $n$.

**Parameters:**
- $n$: Maximum number of bounces (hyper-parameter).
- $m$: Number of Monte Carlo samples per pixel (used in the caller, not the recursive function itself, but the recursive function assumes a single sample path).

**Steps:**
1. **Intersection Check:** Evaluate $\xi(p, v)$. If $\xi(p, v) < 0.5$, the ray does not intersect the scene geometry. Return the environment light $EL(v)$.
2. **Bounce Limit Check:** If $\ell \ge n$, the maximum bounce depth is reached. Return the zero vector $\vec{0}$.
3. **Forward Pass (Position):** Compute the next scene point $q$ along the ray direction $-v$:
   $$ q = p + d(p, v)v $$
4. **Backward Pass (Normal):** Compute the surface normal $n$ at $q$ by taking the gradient of the distance field with respect to position:
   $$ n = \text{Unit}(\nabla_p d(p, v)) $$
5. **Direction Definitions:**
   - Outgoing direction (towards eye): $\omega_o = -v$.
   - Sample a light direction $v_n$ from the BRDF sampling distribution: $v_n \sim \Psi(q, \omega_o \mid n)$.
   - Incoming direction (into surface): $\omega_i = -v_n$.
6. **Emission Query:** Query the material emission field at $q$ for direction $\omega_o$:
   $$ c_E = M_L(q, \omega_o) $$
7. **BRDF Query:** Query the BRDF field at $q$ for directions $\omega_i$ and $\omega_o$:
   $$ B = f_B(q, \omega_i, \omega_o) $$
8. **Recursive Call:** Recursively call `Trace` with the new origin $q$, direction $v_n$, and incremented bounce level $\ell + 1$:
   $$ c_{rec} = \text{Trace}(q, v_n, \ell + 1) $$
9. **Weight Calculation:** Compute the Monte Carlo weight $w_k$ for the sampled direction:
   $$ w_k = \Psi(v_n \mid q, \omega_o)^{-1} |n \cdot \omega_i| $$
10. **Return:** Return the sum of emitted color and the weighted recursive color:
    $$ c = c_E + w_k (B \odot c_{rec}) $$
    *Note: The source pseudocode [S1] shows $B \odot \text{Trace}(\dots)$ inside the recursive call in Fig 25, but Fig 26 shows $B \odot \text{Trace}(\dots)$ as part of the return calculation. Fig 26 is the specific definition of the recursive function. The return statement is $c_E + \Psi(v_n \mid q, \omega_o)^{-1} |n \cdot \omega_i| c$, where $c$ is the result of $B \odot \text{Trace}(\dots)$. Thus, the final formula is $c_E + w_k (B \odot c_{rec})$.*

**Pseudocode:**
```python
def Trace(p, v, l, n, d, xi, grad_d, M_L, f_B, Psi, EL):
    # 1. Intersection Check
    if xi(p, v) < 0.5:
        return EL(v)
    
    # 2. Bounce Limit Check
    if l >= n:
        return [0.0, 0.0, 0.0]
    
    # 3. Forward Pass: Compute scene point q
    q = p + d(p, v) * v
    
    # 4. Backward Pass: Compute surface normal n
    # grad_d returns the gradient vector at p for direction v
    grad = grad_d(p, v)
    n = normalize(grad)
    
    # 5. Direction Definitions
    omega_o = -v
    # Sample outgoing direction from BRDF distribution
    v_n = sample(Psi, q, omega_o, n)
    omega_i = -v_n
    
    # 6. Emission Query
    c_E = M_L(q, omega_o)
    
    # 7. BRDF Query
    B = f_B(q, omega_i, omega_o)
    
    # 8. Recursive Call
    c_rec = Trace(q, v_n, l + 1, n, d, xi, grad_d, M_L, f_B, Psi, EL)
    
    # 9. Weight Calculation
    # Psi returns the PDF value for the sampled direction v_n
    pdf = Psi(q, omega_o, n, v_n)
    weight = (1.0 / pdf) * abs(dot(n, omega_i))
    
    # 10. Return
    # B is multiplied element-wise with c_rec
    return c_E + weight * (B * c_rec)
```

**Edge Cases and Pitfalls:**
- **Gradient Precision:** Computing $\nabla_p d(p, v)$ requires numerical or analytical gradients of the DDF. Small errors in the normal can cause shading artifacts.
- **Zero PDF:** If $\Psi$ returns 0 for the sampled direction, division by zero occurs. The sampling distribution must be non-zero where the BRDF is non-zero.
- **Recursion Depth:** The function relies on the parent to manage the maximum bounce count $n$. If $n$ is too small, paths terminate prematurely; if too large, performance degrades.

## Operating characteristics
- **Time Complexity:** $O(n)$ per path, where $n$ is the maximum bounce depth. Each recursive call performs one forward pass ($d(p, v)$) and one backward pass ($\nabla_p d(p, v)$) on the DDF.
- **Memory Complexity:** $O(n)$ stack space for recursion depth.
- **Strengths:** Integrates seamlessly with DDF-based rendering, avoiding explicit mesh intersection tests. Simple to implement as a recursive routine.
- **Limitations:** Recursion depth is limited by stack size. Performance depends heavily on the efficiency of the DDF queries.

## Background
The Recursive Trace Function is defined in the context of "Probabilistic Directed Distance Fields for Ray-Based Shape Representations" [S1]. It is part of a backward path tracing algorithm that uses DDFs to represent scene geometry and material properties. The method was introduced to enable efficient rendering of complex shapes represented by DDFs without explicit geometry.
