# Importance Sampling for Discrete Media

Also called: Concentric Spheres / Shells Precomputed Scattering, Moon et al. method, Precomputed Shell Importance Sampling, Shell Function Importance Sampling, Shell Tracing, Shell-based importance sampling for discrete media

## Overview
This method accelerates path tracing in discrete participating media (e.g., sand) by replacing small-step integration with large-step sampling guided by precomputed probability densities [S1, S2]. It differs from standard discrete event sampling by using spatial precomputation to determine scattering locations at larger distances, thereby reducing the number of sampling steps and improving convergence speed [S1]. Unlike methods for continuous media, it relies on the statistical independence of particle positions characteristic of discrete media [S2].

## How it works
The method consists of two phases: precomputation of scattering probabilities on concentric shells, and rendering via shell-guided sampling.

### Inputs and Outputs
*   **Inputs:**
    *   Medium properties: extinction coefficient $\sigma_t$, albedo $\omega_0$ (or phase function $p(\Omega_i \to \Omega_o)$).
    *   Scene geometry: a set of opaque surfaces defining the boundary of the medium.
    *   Precomputation resolution: number of concentric shells $N_s$ and angular resolution per shell.
*   **Outputs:**
    *   Precomputed probability density functions (PDFs) stored on concentric spheres/shells.
    *   Rendered image with reduced noise due to larger step sizes.

### Data Structures
The core data structure is a set of concentric shells centered at the current scattering position.
*   **Shell Structure:** A shell is defined by its radius $r$ and a 2D texture or array representing the PDF over the solid angle.
*   **PDF Storage:** For each shell $i$ with radius $r_i$, the PDF $p_i(\Omega)$ is stored. The sources indicate this is stored on a sphere, implying a discretization of the angular domain [S1, S2].
*   **Geometry Intersection:** A spatial data structure (e.g., BVH or grid) is required to test if a sphere of radius $r$ centered at a point intersects any scene geometry [S2].

### Precomputation Stage
1.  **Center Selection:** For a given scattering event at position $\mathbf{x}$, consider a set of concentric spheres centered at $\mathbf{x}$ with radii $r_1, r_2, \dots, r_{N_s}$.
2.  **PDF Calculation:** For each radius $r_i$, compute the probability density of the next scattering event occurring on the sphere of radius $r_i$. This involves integrating the scattering probability over the sphere, accounting for attenuation through the medium and the phase function.
    *   The probability of scattering at distance $s$ is proportional to $\sigma_t e^{-\sigma_t s}$.
    *   The PDF on the shell is derived from this distribution, normalized over the sphere's surface area and angular distribution [S1, S2].
3.  **Storage:** Store the computed PDFs for each shell. The sources note that materials with high albedo require longer computation times because particles are less likely to be absorbed, requiring more samples for accurate PDF estimation [S2].

### Rendering Stage
1.  **Ray Marching:** When a ray hits a scattering event in the medium at position $\mathbf{x}$, the algorithm must determine the next scattering position.
2.  **Shell Selection:** Find the sphere with the maximum radius $r_{max}$ centered at $\mathbf{x}$ such that the sphere does not intersect any scene geometry. This ensures the scattering event occurs within the medium volume [S2].
3.  **Sampling:** Sample the precomputed PDF associated with the selected shell $r_{max}$ to determine the direction $\Omega_o$ and distance $r_{max}$ to the next scattering event.
    *   The next position is $\mathbf{x}' = \mathbf{x} + r_{max} \Omega_o$.
    *   The direction $\Omega_o$ is sampled from the stored angular PDF [S2].
4.  **Weighting:** Apply the appropriate Russian Roulette or weight adjustment based on the albedo and the ratio of the sampled PDF to the true PDF if importance sampling is not perfectly matched. The sources imply the precomputed PDF guides the sampling to reduce variance [S1].
5.  **Iteration:** Repeat from step 1 for the new position $\mathbf{x}'$ until the path terminates or escapes the medium.

### Pseudocode
```python
def precompute_shells(center_point, geometry, sigma_t, albedo, num_shells, angular_resolution):
    """
    Precompute PDFs for concentric shells around a center point.
    Returns a list of shell objects, each containing radius and PDF data.
    """
    shells = []
    # Radii are typically spaced to cover the relevant mean free paths
    # Exact spacing not specified in sources; assume uniform or logarithmic spacing [G]
    for i in range(num_shells):
        r = compute_radius(i, num_shells) # Placeholder for radius generation strategy [G]
        
        # Check if sphere intersects geometry
        if geometry.intersects_sphere(center_point, r):
            # If it intersects, this shell is invalid for free-space sampling
            # The method selects the MAXIMUM radius with NO intersection.
            # We store None or mark as invalid.
            shells.append(Shell(radius=r, pdf=None))
            continue
            
        # Compute PDF for this shell
        # PDF represents the probability density of the next scatter occurring
        # on the sphere of radius r, considering attenuation and phase function.
        # Formula: p(omega) proportional to sigma_t * exp(-sigma_t * r) * p_phase(omega)
        # Normalized over the sphere surface.
        pdf_data = compute_shell_pdf(r, sigma_t, albedo, angular_resolution)
        shells.append(Shell(radius=r, pdf=pdf_data))
        
    return shells

def sample_next_scatter(center_point, geometry, precomputed_shells):
    """
    Determine the next scattering position and direction using precomputed shells.
    """
    # Find the largest valid shell (no geometry intersection)
    valid_shell = None
    for shell in reversed(precomputed_shells):
        if shell.pdf is not None:
            valid_shell = shell
            break
            
    if valid_shell is None:
        # No valid shell found; fallback to standard small-step sampling or escape
        return None, None
        
    # Sample direction from the stored PDF
    direction = valid_shell.pdf.sample()
    
    # Distance is fixed to the shell radius
    distance = valid_shell.radius
    
    next_position = center_point + direction * distance
    return next_position, direction

def compute_shell_pdf(r, sigma_t, albedo, angular_resolution):
    """
    Compute the angular PDF for a shell of radius r.
    Simplified model: The probability of scattering at distance r is
    determined by the transmittance T(r) = exp(-sigma_t * r).
    The angular distribution is governed by the phase function.
    """
    # Probability of scattering at distance r (unnormalized)
    # P(scatter at r) ~ sigma_t * exp(-sigma_t * r)
    # This is integrated into the PDF normalization.
    
    # For discrete media, the phase function p(omega) defines the angular distribution.
    # The PDF on the sphere is p(omega) / integral(p(omega) domega)
    # Since the sources do not specify the exact phase function integration,
    # we assume a standard phase function (e.g., Henyey-Greenstein) is used.
    
    # The stored PDF is a 2D texture/array over the sphere.
    # Implementation detail: Discretize the sphere into angular bins.
    pdf_array = zeros(angular_resolution)
    
    # Fill PDF array based on phase function p(omega)
    for each angular_bin omega:
        pdf_array[bin] = phase_function(omega)
        
    # Normalize so that integral over sphere is 1
    pdf_array = normalize(pdf_array)
    
    return pdf_array
```

### Parameters and Typical Values
*   **Number of Shells:** Not given in the sources. Depends on the spatial variation of the medium and geometry.
*   **Angular Resolution:** Not given in the sources. Higher resolution reduces angular aliasing but increases memory.
*   **Albedo:** High albedo materials require longer precomputation times [S2].

### Edge Cases and Pitfalls
*   **Geometry Intersection:** If a sphere intersects geometry, it cannot be used for free-space sampling. The algorithm must select the largest non-intersecting sphere [S2].
*   **Spatial Resolution:** Concentric shells have lower spatial resolution, leading to poor representation on the axis and Mach banding effects if the number of samples is insufficient [S2].
*   **Continuous Media:** The method is designed for discrete media. When applied to continuous media, efficiency depends on the ratio of the mean-free-path to object size; it works better for smaller mean-free-paths (more opaque materials) [S2].

## Subtopics

### Multi-scale rendering for discrete media
A variant that combines accurate small-scale rendering with large-scale approximation [S1].
*   **Meng et al. [68] variant:** Uses path tracing with the shell-based method [69] for accurate rendering at small scales, and uses diffusion theory to approximate at large scales [S1].
*   **Müller et al. [70] variant 1:** Treats mixed media in multiple discrete participating media as equivalent continuous participating media to support mixed media rendering [S1].
*   **Müller et al. [70] variant 2:** Uses a particle scattering distribution function for small scale rendering and the method of Moon et al. [69] for large scale rendering [S1].

## Operating characteristics
*   **Time Complexity:** Precomputation time depends on the number of shells, angular resolution, and albedo. High albedo materials require longer computation times [S2]. Rendering time is reduced compared to small-step tracing because fewer scattering events are sampled per path [S1].
*   **Memory Complexity:** Memory cost is determined by the number of shells and angular resolution. The sources note that memory costs are almost the same for different materials in their tests, but compression techniques (e.g., quadtree-based) can be used for adaptive representation [S2].
*   **Performance:** Reduces the number of sampling steps and improves convergence speed [S1]. However, it may suffer from Mach banding effects due to lower spatial resolution of concentric shells [S2].
*   **Strengths:** Efficient for discrete media like sand; reduces noise by taking larger steps [S1, S2].
*   **Limitations:** Not suitable for continuous media without modification; suffers from aliasing/Mach banding; precomputation cost can be high for high-albedo materials [S2].

## Background
The method was proposed by Moon et al. [69] (also cited as [20] in some contexts) as an importance sampling approach for path tracing in discrete media via precomputation [S1]. It was designed to address the inefficiency of small-step integration in discrete media such as sand [S2]. The method has been further improved by Meng et al. [68] and Müller et al. [70] to support multi-scale rendering and mixed media scenarios [S1].
