# Shadow Volume Rendering

Also called: Volumetric Shadow Maps

## Overview
Shadow Volume Rendering is a specialized ray marching routine that computes only the accumulated alpha (transmittance) along a ray to generate shadow maps or occlusion values for volume scenes [S1, unofficial]. It precomputes a shadow volume to store the amount of light arriving at each sample after attenuation by intervening material, allowing the renderer to multiply interpolated values from this map by colors from the transfer function during the main pass [S2]. Unlike [Ray Marching with Shadow Mapping](1415-ray-marching-with-shadow-mapping.md), which uses an opacity shadow map for occlusion, this method explicitly constructs a volumetric shadow buffer [S2]. It differs from [Volume Shadow Calculation via Light Strength Buffer](1914-volume-shadow-calculation-via-light-strength-buffer.md) and [Light Injection Pass](2759-light-injection-pass.md) by focusing on precomputing the shadow volume itself rather than accumulating light strength or injecting light [S2].

## How it works
**Inputs:** Ray origin and direction in world space, world-to-object transformation matrix, sampling scale multiplier, and a threshold for alpha termination.
**Outputs:** Accumulated alpha (transmittance) value for the ray.

**Data Structures:**
*   `ShadowPayload`: A structure containing:
    *   `rng`: Pointer to a random number generator (e.g., `RandomTEA`).
    *   `alpha`: Float representing the accumulated alpha.
*   The payload is packaged using `packPointer(&payload, u0, u1)` [S1, unofficial].

**Steps:**
1.  **Transform Ray:** Convert the ray origin and direction from world space to object space.
    $$ \text{org} = \text{xfmPoint}(\text{wto}, \text{world\_org}) $$
    $$ \text{dir} = \text{xfmVector}(\text{wto}, \text{world\_dir}) $$
    Where `xfmPoint` applies the transformation to the origin and `xfmVector` applies it to the direction [S1, unofficial].

2.  **Initialize Payload:** Create a `ShadowPayload` with `alpha = 0.0` and initialize the random number generator `rng` [S1, unofficial].

3.  **Ray Marching Loop:** Iterate along the ray from `tMin` to `tMax` using a `raymarching_iterator`. The step size is adjusted by a `samplingScale` multiplier:
    $$ \text{step} = \text{samplingScale} \times \text{self.step} $$
    The iterator calls a lambda function for each sample [S1, unofficial].

4.  **Sample Position:** Compute the sample position $p$ within the current step interval $[t.x, t.y]$ using jittered interpolation:
    $$ p = \text{org} + \text{lerp}(\text{jitter}, t.x, t.y) \times \text{dir} $$
    Where `jitter` is derived from the random number generator `rng` [S1, unofficial].

5.  **Accumulate Alpha:** Sample the volume density/alpha at $p$ (denoted as `sampleAlpha`). Update the payload's accumulated alpha using front-to-back blending:
    $$ \text{payload.alpha} \leftarrow \text{payload.alpha} + (1.0 - \text{payload.alpha}) \times \text{sampleAlpha} $$
    [S1, unofficial].

6.  **Termination Check:** Continue marching as long as the accumulated alpha is below a nearly-one threshold (e.g., `nearly_one`):
    $$ \text{if } \text{payload.alpha} < \text{nearly\_one}, \text{ continue; else break.} $$
    [S1, unofficial].

7.  **Final Computation:** After the loop, the `payload.alpha` represents the total attenuation. During the main rendering pass, this value is interpolated from the volumetric shadow map and multiplied by the colors from the transfer function [S2].

**Parameters:**
*   `samplingScale`: Multiplier applied to `self.step` to adjust shadow ray sampling density [S1, unofficial]. Typical values are not specified in the sources.

**Edge Cases and Pitfalls:**
*   **Blurry Shadows:** The method can result in blurry shadows due to the nature of shadow mapping and interpolation [S2].
*   **Dark Images:** Incorrectly applied shadow volumes can lead to overly dark images [S2].
*   **Memory Usage:** The precomputed shadow volume requires extra memory [S2].
*   **Precision:** The sources do not specify precision issues, but the use of `float` for alpha accumulation suggests potential precision limits in high-opacity regions [S1, unofficial].

## Subtopics

### Transmittance Function Mapping
*   **Definition:** An approximation method that uses orthogonal basis functions (e.g., Fourier series) to calculate self-shadowing more efficiently than ray marching [S3, unofficial].
*   **How it works:**
    1.  Generate a volume shadow map from the sun direction using orthographic projection [S3, unofficial].
    2.  Store the first 9 Fourier coefficients in a shadow map with format 512x512x3 R11G11B10 [S3, unofficial].
    3.  During rendering, read the Fourier coefficients and combine them linearly with basis functions to reconstruct optical depth and transmittance [S3, unofficial].
*   **Comparison:** TFM efficiency is roughly equivalent to Ray Marching with 1-2 steps, but provides more accurate results than 2-step RM. It may produce banding artifacts [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** The basic shadow volume rendering involves a ray marching loop. The number of steps depends on the `samplingScale` and volume density. TFM is roughly equivalent to 1-2 steps of ray marching in efficiency [S3, unofficial].
*   **Memory Complexity:** Requires storage for the volumetric shadow map. The TFM variant uses a 512x512x3 R11G11B10 texture [S3, unofficial].
*   **Performance:** Not given in the sources for the basic method. TFM is noted as efficient [S3, unofficial].
*   **Strengths:** Precomputes shadow information, allowing for faster rendering during the main pass compared to per-pixel ray marching for shadows [S2]. TFM offers a good balance of efficiency and accuracy [S3, unofficial].
*   **Limitations:** Can produce blurry shadows and dark images [S2]. TFM may produce banding artifacts [S3, unofficial]. Requires extra memory for the shadow volume [S2].
*   **When to use:** When self-shadowing is required for volumetric scenes and performance is a concern, but high accuracy is still desired (TFM).
*   **When not to use:** When memory is extremely constrained or when the highest possible shadow detail is required without artifacts (basic shadow volume may be too blurry) [S2][S3, unofficial].

## Background
The concept of precomputing a shadow volume for volumetric materials was introduced to address the unrealistic assumption that light arrives at a sample without interacting with the rest of the volume [S2]. This approach was proposed as an alternative to surface-based lighting models [S2]. The Transmittance Function Mapping variant has been used in games like Final Fantasy, utilizing Fourier series for approximation [S3, unofficial].
