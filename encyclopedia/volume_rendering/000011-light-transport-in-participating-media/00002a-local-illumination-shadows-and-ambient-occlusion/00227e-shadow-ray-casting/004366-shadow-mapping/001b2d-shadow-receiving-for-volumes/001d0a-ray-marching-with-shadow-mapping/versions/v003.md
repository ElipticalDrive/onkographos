# Ray Marching with Shadow Mapping

Also called: Deep Opacity Maps, OSM, Opacity Shadow Map Volume Rendering

## Overview
Ray Marching with Shadow Mapping is a technique for efficient self-shadowing in volume rendering that uses an opacity shadow map to determine occlusion by the volume itself [S1, unofficial]. It solves the problem of expensive per-view-ray light sampling by precomputing transmittance values from the light's perspective, avoiding the need to trace rays toward the light for each view-ray sample [S2, unofficial]. Unlike [Shadow Volume Rendering](1556-shadow-volume-rendering.md), which explicitly constructs a volumetric shadow buffer, this method uses a 2D depth map combined with a 3D array of opacity images sampled from the light source's perspective [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Volume density function $density(\mathbf{p})$, absorption coefficient $k_a$, scattering coefficient $k_s$, light direction (azimuth $\alpha$, elevation $\beta$), shadow volume range $[z_{min}, z_{max}]$, step size $\Delta z$, number of layers/slices $N$ [S1, unofficial].
*   **Outputs:** A 3D texture (opacity shadow map) storing transmittance values, and a final rendered image with self-shadowed illumination [S1, unofficial].

**Data Structures:**
The opacity shadow map consists of:
1.  A depth (offset) image storing the distance to the cloud start from the light source [S2, unofficial].
2.  A 3D texture array storing transmittance values. The dimensions are $W \times H \times N$, where $W, H$ are the shadow map resolution and $N$ is the number of depth slices [S2, unofficial].
    *   *Constraint:* All layers must be stored in a single channel (e.g., Red) to allow correct bilinear/trilinear interpolation. Storing different layers in different color channels (e.g., Layer 1 in Red, Layer 2 in Green) prevents correct interpolation [S1, unofficial].
    *   *MRT Limit:* If using Multiple Render Targets (MRT) to write layers, the minimum count is 8. If more than 8 layers are needed, multiple passes are used [S1, unofficial].

**Parameters:**
*   $z_{min}, z_{max}$: Define the volume range for slicing the shadow map. If $z_{min}$ is too large, the shadow map slice starts inside the volume, making the side facing the light incorrectly too dark [S1, unofficial].
*   $k = k_{Schlick}$: Anisotropy parameter for Schlick's approximation phase function [S1, unofficial].
*   $\alpha$: Azimuth angle controlling directional light direction around the y-axis ($0^\circ$ is center-right, $90^\circ$ is behind) [S1, unofficial].
*   $\beta$: Elevation angle controlling directional light direction around -z ($0^\circ$ is center-right, $90^\circ$ is top) [S1, unofficial].
*   Step jitter: A small random offset added to the step size to hide visible banding caused by low layer counts, at the cost of adding noise [S1, unofficial].

**Steps:**

1.  **Render Opacity Shadow Map (Light Pass):**
    1.  Render the scene from the light source's perspective. Use an orthographic camera for directional lights and a perspective camera for point lights [S1, unofficial].
    2.  Ray march with even steps of $\Delta z$ through an encapsulating volume from $z_{min}$ to $z_{max}$ [S1, unofficial].
    3.  For each sample position, compute the density and update the accumulated transmittance using Beer's Law:
        $$ T_{new} = T_{old} \cdot \exp(-\rho \cdot (k_a + k_s) \cdot \Delta z) $$
        where $\rho$ is the current density, and $k_a, k_s$ are absorption and scattering coefficients [S1, unofficial].
    4.  Store the transmittance values for each depth layer into the 3D texture. If $N \le 8$, use MRT to write all layers in one pass. Otherwise, use multiple passes [S1, unofficial].

2.  **Main Rendering Pass (View Pass):**
    1.  Initialize transmittance $T = 1.0$ and illumination $I = \vec{0}$ [S1, unofficial].
    2.  Loop for $i$ from $0$ to $stepCount$:
        a.  Advance sample position: $\mathbf{p} \leftarrow \mathbf{p} + \mathbf{d} \cdot \Delta z$, where $\mathbf{d}$ is the march direction [S1, unofficial].
        b.  Sample current density $\rho = density(\mathbf{p})$ [S1, unofficial].
        c.  Update volume transmittance:
            $$ T \leftarrow T \cdot \exp(-\rho \cdot (k_a + k_s) \cdot \Delta z) $$
        d.  Compute in-scattering. First, determine the shadow factor from the opacity shadow map:
            i.  Transform $\mathbf{p}$ to shadow map space: $\mathbf{p}_{light} = M_{light} \cdot \mathbf{p}$ [S1, unofficial].
            ii. Normalize depth $z$ within the shadow volume range:
                $$ z = \frac{-\mathbf{p}_{light}.z - z_{min}}{z_{max} - z_{min}} $$
            iii. Compute UV coordinates:
                $$ uv = \frac{\mathbf{p}_{light}.xy}{lightCamSize} / 2.0 + \vec{0.5} $$
            iv. Sample the 3D texture:
                $$ shadowFactor = texture(opacityShadowMap, vec3(uv, z)).r $$
        e.  Compute in-scattering:
            $$ I_{in} = L_{ambient} + L_{direct} \cdot phase(\mathbf{v}, -\mathbf{l}) \cdot shadowFactor $$
            where $phase(\mathbf{v}, -\mathbf{l})$ is the Schlick phase function [S1, unofficial].
        f.  Compute out-scattering:
            $$ I_{out} = k_s \cdot \rho $$
        g.  Accumulate illumination:
            $$ I \leftarrow I + T \cdot I_{in} \cdot I_{out} \cdot \Delta z $$
    3.  Return $\vec{4}(I, T)$ [S1, unofficial].

**Pseudocode:**

```python
import math

def schlick_phase(mu, k):
    """Schlick's approximation phase function [S2, unofficial]."""
    g = k
    num = 3.0 * (1.0 - g * g) * (1.0 + mu * mu)
    den = 8.0 * math.pi * (2.0 + g * g) * math.pow(1.0 + g * g - 2.0 * g * mu, 1.5)
    return num / den

def transform_point(m, p):
    """Transforms a 3D point by a 4x4 matrix, returning xyz [G]."""
    w = m[3][0]*p[0] + m[3][1]*p[1] + m[3][2]*p[2] + m[3][3]
    return (
        (m[0][0]*p[0] + m[0][1]*p[1] + m[0][2]*p[2] + m[0][3]) / w,
        (m[1][0]*p[0] + m[1][1]*p[1] + m[1][2]*p[2] + m[1][3]) / w,
        (m[2][0]*p[0] + m[2][1]*p[1] + m[2][2]*p[2] + m[2][3]) / w
    )

def sample_3d_texture(tex, uv, z):
    """Trilinear interpolation sample from a 3D texture array [G]."""
    return tex[uv[0], uv[1], z]

def render_opacity_shadow_map(light_cam_matrix, shadow_volume_range, slice_count, density_func, absorption_coef, scattering_coef):
    """Generates the opacity shadow map layers using MRT [S1, unofficial]."""
    extinction_coef = absorption_coef + scattering_coef
    step_size = (shadow_volume_range[1] - shadow_volume_range[0]) / slice_count
    layers = [0.0] * 8
    local_position = (0.0, 0.0, 0.0) # Input: position in light camera space
    total_density = 0.0
    for i in range(slice_count):
        sample_pos = (local_position[0], local_position[1], local_position[2] - i * step_size)
        current_density = density_func(sample_pos)
        total_density += current_density
        transmittance = math.exp(-total_density * step_size * extinction_coef)
        if i < 8:
            layers[i] = transmittance
    return layers

def raymarch(sample_position, march_direction, step_count, step_size, light_cam_matrix, shadow_volume_range,
             opacity_shadow_map, ambient_light, direct_light, scattering_coef, absorption_coef, light_cam_size,
             light_direction, k):
    """Main rendering pass with shadow lookup [S1, unofficial]."""
    extinction_coef = absorption_coef + scattering_coef
    transmittance = 1.0
    illumination = [0.0, 0.0, 0.0]
    for i in range(step_count):
        sample_position = (sample_position[0] + march_direction[0] * step_size,
                           sample_position[1] + march_direction[1] * step_size,
                           sample_position[2] + march_direction[2] * step_size)
        current_density = density_func(sample_position)
        transmittance *= math.exp(-current_density * extinction_coef * step_size)

        shadow_map_position = transform_point(light_cam_matrix, sample_position)
        z = (-shadow_map_position[2] - shadow_volume_range[0]) / (shadow_volume_range[1] - shadow_volume_range[0])
        uv = (shadow_map_position[0] / light_cam_size[0] / 2.0 + 0.5,
              shadow_map_position[1] / light_cam_size[1] / 2.0 + 0.5)
        shadow_factor = sample_3d_texture(opacity_shadow_map, uv, z)

        v_dot_l = -(march_direction[0]*light_direction[0] + march_direction[1]*light_direction[1] + march_direction[2]*light_direction[2])
        phase_val = schlick_phase(v_dot_l, k)
        in_scattering = [ambient_light[0] + direct_light[0] * phase_val * shadow_factor,
                         ambient_light[1] + direct_light[1] * phase_val * shadow_factor,
                         ambient_light[2] + direct_light[2] * phase_val * shadow_factor]
        out_scattering = scattering_coef * current_density
        current_light = [in_scattering[0] * out_scattering, in_scattering[1] * out_scattering, in_scattering[2] * out_scattering]

        illumination[0] += transmittance * current_light[0] * step_size
        illumination[1] += transmittance * current_light[1] * step_size
        illumination[2] += transmittance * current_light[2] * step_size
    return (illumination[0], illumination[1], illumination[2], transmittance)
```

## Subtopics

### [Shadow Volume Rendering](1556-shadow-volume-rendering.md)
Shadow Volume Rendering is a specialized ray marching routine that computes only the accumulated alpha (transmittance) along a ray to generate shadow maps or occlusion values for volume scenes. It precomputes a shadow volume to store the amount of light arriving at each sample after attenuation by intervening material, allowing the renderer to multiply interpolated values from this map by colors from the transfer function during the main pass. Unlike [Ray Marching with Shadow Mapping](1415-ray-marching-with-shadow-mapping.md), which uses an opacity shadow map for occlusion, this method explicitly constructs a volumetric shadow buffer.

### [Volume Shadow Calculation via Light Strength Buffer](1914-volume-shadow-calculation-via-light-strength-buffer.md)
This method adds shadows to mixtures of geometric and volumetric data by storing shadow information in a 3D light strength buffer instead of a 2D shadow depth buffer. It sets itself apart from its sibling [Ray Marching with Shadow Mapping](1415-ray-marching-with-shadow-mapping.md) by computing a fractional light strength at every point in space, which allows it to correctly render penumbras and semi-transparent shadows without the aliasing artifacts associated with Williams' 2D shadow depth buffer.

### [Light Injection Pass](2759-light-injection-pass.md)
The Light Injection Pass is a post-processing technique that adds volumetric light scattering (such as sun shafts and lamp glow) to a rendered scene by marching rays from the camera through the volume to sample light sources and their occlusion. It solves the problem of visualizing light interacting with participating media (air/fog) in real-time without full path tracing, relying on pre-existing shadow maps for occlusion. Unlike [Shadow Volume Rendering](1556-shadow-volume-rendering.md) which uses geometric volumes, or [Volume Shadow Calculation via Light Strength Buffer](1914-volume-shadow-calculation-via-light-strength-buffer.md) which may use different accumulation buffers, this method specifically targets direct illumination scattering using a ray-marching approach over a depth buffer, executed as a distinct post-process step.

### Deep Shadow Maps
Deep Shadow Maps are a shadow mapping technique where each pixel stores a curve representing volume density as a function of distance, rather than just the depth to the nearest object [S3, unofficial]. The algorithm computes a shadow map per light in the scene, storing a curve in each pixel that represents how transmission through the volume changes as one moves through it [S3, unofficial]. Unlike standard shadow maps which store depth to the nearest object, deep shadow maps store volume density information [S3, unofficial]. It is mentioned for completeness and historical reasons, with similarities to baking lighting into voxels [S3, unofficial]. Developed in 2000 by Tom Lokovic and Eric Veach from Pixar [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1, unofficial].
*   **Memory Complexity:** Not given in the sources [S1, unofficial].
*   **Measured Performance:** In an example using 28.5 FPS on an AMD Ryzen 7 4700U at 640x480 resolution, 3 deep opacity maps with a 7x512x512 transmittance array were rendered per frame [S2, unofficial].
*   **Strengths:** More efficient than sampling light rays towards the light source for each sample of the view ray [S2, unofficial]. Avoids the need for per-view-ray light sampling [S2, unofficial].
*   **Limitations:** Visible banding can occur due to the low number of layers [S1, unofficial]. Storing layers in different color channels prevents correct interpolation [S1, unofficial]. If $z_{min}$ is too large, shadows are incorrect [S1, unofficial].
*   **When to use:** When self-shadowing is required for volumes and performance is a concern compared to full light sampling [G].
*   **When not to use:** When high-quality penumbras are required (consider [Volume Shadow Calculation via Light Strength Buffer](1914-volume-shadow-calculation-via-light-strength-buffer.md)) or when the volume geometry is highly irregular and non-uniform sampling is needed (consider [Deep Opacity Maps](1415-ray-marching-with-shadow-mapping.md) variant) [G].

## Background
The technique was developed as an alternative to per-view-ray light sampling for volume self-shadowing [S2, unofficial]. It builds on the concept of shadow mapping, extending it to record transparency (transmittance) along different depths from the light's perspective [S1, unofficial]. The term "Opacity Shadow Maps" is used to describe this specific implementation using a 3D texture of transmittance values [S1, unofficial]. Related historical techniques include Deep Shadow Maps by Tom Lokovic and Eric Veach (2000) [S3, unofficial].
