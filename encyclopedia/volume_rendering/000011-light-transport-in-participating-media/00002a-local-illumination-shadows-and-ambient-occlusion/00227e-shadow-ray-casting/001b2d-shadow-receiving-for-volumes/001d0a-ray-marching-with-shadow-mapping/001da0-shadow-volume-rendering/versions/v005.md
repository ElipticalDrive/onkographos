# Shadow Volume Rendering

Also called: Volumetric Shadow Maps

## Overview
Shadow Volume Rendering is a specialized ray marching routine that computes only the accumulated alpha (transmittance) along a ray to generate shadow maps or occlusion values for volume scenes [S1, unofficial]. It precomputes a shadow volume to store the amount of light arriving at each sample after attenuation by intervening material [S2]. It differs from [Ray Marching with Shadow Mapping](1415-ray-marching-with-shadow-mapping.md) by explicitly precomputing a shadow volume structure rather than relying solely on runtime opacity shadow maps, and from [Volume Shadow Calculation via Light Strength Buffer](1914-volume-shadow-calculation-via-light-strength-buffer.md) by focusing on alpha accumulation for shadow generation rather than light strength buffering [S2].

## How it works
**Inputs:**
- Ray origin `org_world` and direction `dir_world` in world space [S1, unofficial].
- World-to-object transformation matrix `M` [S1, unofficial].
- Ray bounds `t_min` and `t_max` [S1, unofficial].
- Base step size `step` [S1, unofficial].
- Sampling scale multiplier `sampling_scale` [S1, unofficial].
- Random number generator state `rng` (e.g., `RandomTEA`) [S1, unofficial].

**Outputs:**
- Accumulated alpha (transmittance) value [S1, unofficial].

**Data Structures:**
- `ShadowPayload`:
  - `rng`: Pointer to `RandomTEA` instance [S1, unofficial].
  - `alpha`: Float, accumulated alpha [S1, unofficial].
  - Layout: Packaged via `packPointer(&payload, u0, u1)` [S1, unofficial].

**Steps:**
1. **Transform Ray:** Convert ray origin and direction from world space to object space [S1, unofficial].
2. **Initialize Payload:** Create `ShadowPayload` with random state and initial alpha of 0 [S1, unofficial].
3. **March Ray:** Iterate along the ray using parameters `org`, `dir`, `t_min`, `t_max`, `sampling_scale * step`, and a lambda function [S1, unofficial].
4. **Sample Position:** Compute sample position with jitter [S1, unofficial].
5. **Accumulate Alpha:** Perform front-to-back blending [S1, unofficial].
6. **Termination:** Continue marching while `payload.alpha < nearly_one` [S1, unofficial].

**Formulas:**
- Sample position: $p = \text{org} + \text{lerp}(\text{jitter}, t_x, t_y) \times \text{dir}$ [S1, unofficial].
- Alpha accumulation: $\alpha_{\text{new}} = \alpha_{\text{old}} + (1.0 - \alpha_{\text{old}}) \times \alpha_{\text{sample}}$ [S1, unofficial].

**Parameters:**
- `sampling_scale`: Multiplier applied to `step` to adjust shadow ray sampling density. Typical value: Not given in the sources.

**Edge Cases and Pitfalls:**
- **Blurry Shadows:** Results in visual artifacts such as blurry shadows [S2].
- **Dark Images:** Can result in dark images due to the use of volumetric shadow maps [S2].
- **Memory Usage:** Uses extra memory for storing the shadow volume [S2].

**Pseudocode:**
```python
def shadow_volume_rendering(org_world, dir_world, M, t_min, t_max, sampling_scale, step, rng):
    # 1. Transform ray to object space
    org = M.transform_point(org_world)
    dir = M.transform_vector(dir_world)

    # 2. Initialize payload
    payload_alpha = 0.0
    nearly_one = 0.9999

    # 3. March along the ray
    t = t_min
    while t < t_max and payload_alpha < nearly_one:
        # 4. Compute sample position with jitter
        jitter = next_jitter(rng) # [G] Advance PRNG state
        # Evidence uses lerp(jitter, t.x, t.y); adapted to scalar t for Python
        p = org + lerp(jitter, t, t + step) * dir

        # Sample volume alpha at position p
        sample_alpha = sample_volume_alpha(p) # [G] Standard volume texture lookup

        # 5. Accumulate alpha using front-to-back blending
        payload_alpha += (1.0 - payload_alpha) * sample_alpha

        # Advance step
        t += sampling_scale * step

    return payload_alpha

def lerp(a, b, t):
    return a + t * (b - a)
```

## Subtopics

### [Shadow Volume Representation (SVR)](4603-shadow-volume-representation-svr.md)
Shadow Volume Representation (SVR) is a sparse data structure that stores global opacity ($\alpha_g$) along rays from volume points to a light source, enabling efficient estimation of direct light contribution in participating media. It distinguishes itself from full-resolution ray integration by decoupling the storage resolution from the integration resolution, allowing interactive adjustment of the shadow map density while maintaining high-quality visibility estimates. Link: [Shadow Volume Representation (SVR)](4603-shadow-volume-representation-svr.md).

### Transmittance Function Mapping
Transmittance Function Mapping (TFM) approximates the transmittance function using orthogonal basis functions (e.g., Fourier series) to calculate self-shadowing more efficiently than ray marching [S3, unofficial]. It generates a volume shadow map from the sun direction using orthographic projection, storing Fourier coefficients in a 512x512x3 R11G11B10 format (first 9 coefficients) [S3, unofficial]. During rendering, it reads Fourier coefficients and combines them linearly with basis functions to reconstruct optical depth and transmittance [S3, unofficial]. TFM efficiency is roughly equivalent to Ray Marching with 1-2 steps but provides more accurate results than 2-step RM, though it may produce banding artifacts [S3, unofficial].

### Cloud Shadow Map Directional Consistency Fix
Cloud Shadow Map Directional Consistency Fix addresses incorrect cloud shadows for non-parallel lights by ensuring the cloud shadow map is traced along the view's first directional light, but consumers look it up in that light's own basis [S4, unofficial]. Previously, every consumer looked it up for each light in that light's own basis, causing a second, nonparallel sun to read the first one's optical depths as a displaced, wrongly oriented shadow [S4, unofficial]. For non-parallel lights, it marches the cloud layer toward the light using `cloud_far_transmittance` in the atmosphere passes, leaving meshes unshadowed by clouds for those lights [S4, unofficial]. Parallel lights continue to share the shadow map [S4, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Uses extra memory for storing the shadow volume [S2].
- **Measured Performance:** TFM efficiency is roughly equivalent to Ray Marching with 1-2 steps [S3, unofficial].
- **Scaling:** Not given in the sources.
- **Strengths:** Decouples storage resolution from integration resolution [S1, unofficial]; allows interactive adjustment of shadow map density [S1, unofficial]; TFM provides more accurate results than low-step RM [S3, unofficial].
- **Limitations:** Results in blurry shadows and dark images [S2]; TFM may produce banding artifacts [S3, unofficial]; uses extra memory [S2].
- **When to Use:** When self-shadowing in participating media is required and performance allows for precomputation or sparse storage.
- **When Not to Use:** When memory is constrained or when blurry shadows are unacceptable.

## Background
Shadow Volume Rendering was introduced as a method to incorporate complex lighting effects, such as volumetric shadows, into volume rendering [S2]. It was developed as an alternative to simple lighting models that assume light arrives at a sample without interacting with the rest of the volume [S2]. The technique is used in various volume rendering applications, including cloud rendering [S3, unofficial] and atmospheric scattering [S4, unofficial].
