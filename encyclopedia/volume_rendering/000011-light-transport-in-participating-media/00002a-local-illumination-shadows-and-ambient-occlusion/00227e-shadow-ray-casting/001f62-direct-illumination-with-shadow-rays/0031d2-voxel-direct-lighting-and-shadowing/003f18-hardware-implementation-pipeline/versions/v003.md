# Hardware Implementation Pipeline

Also called: Single Scattering Rendering Pipeline, Volumetric Shadow Volume Method

## Overview
The Hardware Implementation Pipeline is a five-step method for rendering single scattering and volumetric shadows in real-time using GPU shaders and the stencil buffer, designed for minimal texture memory cost [S1, unofficial]. It differs from ray-marching approaches by leveraging conventional polygonal rendering and shadow volume logic, making it straightforward to integrate into traditional graphics engines [S1, unofficial].

## How it works
The pipeline consists of five steps that must be repeated for each light source [S1, unofficial]. An initialization stage is required beforehand to obtain ambient lighting and the first depth map [S1, unofficial].

**Inputs:** Scene geometry containing moving shadow casters, light source position (static or moving), and view ray direction [S1, unofficial].
**Outputs:** Radiance $L$ with direct single scattering ($L_{dss}$) and volumetric shadows [S1, unofficial].

**Data Structures:**
*   **Stencil Buffer:** Integer buffer tracking occlusion status for shadow volume logic [S1, unofficial].
*   **Shadow Planes:** Geometry derived from object silhouettes relative to the light source [S1, unofficial].

**Pseudocode:**
```python
def hardware_pipeline(scene, lights):
    # Initialization stage: obtain ambient lighting and first depth map [S1, unofficial]
    init_ambient_and_depth_map()
    for light in lights:
        # Step 1 (CPU)
        silhouettes = compute_silhouettes(scene.shadow_casters, light.position)
        if light.is_moving:
            silhouettes = compute_silhouettes(scene.shadow_casters, light.position)
        # Step 2 (GPU)
        render_scene_conventional()
        apply_shadow_planes_for_surface_shadows()
        add_ambient_fog_for_absorption_and_multiple_scattering()
        # Step 3 (GPU)
        set_depth_test(EQUAL)
        render_scene_again()
        compute_direct_single_scattering_per_vertex()
        # Step 4 (CPU)
        shadow_planes = generate_planes_from_silhouettes(silhouettes)
        shadow_planes.sort(back_to_front)
        # Step 5 (GPU)
        set_depth_test(LESS)
        set_stencil_test(front: stencil==1, back: stencil==0)
        for plane in shadow_planes:
            if plane.is_front_facing:
                add_contribution()
                stencil_decrement()
            else:
                subtract_contribution()
                stencil_increment()
```
*Note: Helper functions for conventional rendering, fog application, and silhouette generation are standard graphics operations [G].*

**Radiance Model:**
The observed radiance $L$ along a view ray $\vec{u}$ from point $P$ is given by [S1, unofficial]:
$$L_{\vec{u}\vec{P}} = L_{dss}(\vec{u}\vec{P}) + e^{-k_t OP} L(P) + L_a e^{-k_t OP} + L_{oiss}(\vec{u}\vec{P})$$
Where:
*   $L_{dss}(\vec{u}\vec{P})$: Direct single scattering term [S1, unofficial].
*   $L(P)$: Radiance at point $P$ computed in steps 2 and 3 [S1, unofficial].
*   $k_t$: Extinction coefficient [S1, unofficial].
*   $OP$: Distance from observer to $P$ [S1, unofficial].
*   $L_a$: Ambient radiance [S1, unofficial].
*   $L_{oiss}(\vec{u}\vec{P})$: Other indirect single scattering terms [S1, unofficial].

**Parameters:**
*   The entire pipeline (steps 1-5) must be repeated for each light source [S1, unofficial].

**Pitfalls:**
*   Moving lights or objects require silhouette recomputation in Step 1 [S1, unofficial].
*   An initialization stage is mandatory before the main pipeline to obtain ambient lighting and the first depth map [S1, unofficial].

## Operating characteristics
*   **Complexity:** Real-time performance for classical graphics scenes [S1, unofficial].
*   **Memory:** Minimal texture memory cost [S1, unofficial].
*   **Strengths:** Easy to integrate into traditional engines; supports moving objects and lights [S1, unofficial].
*   **Limitations:** Limited to single scattering and volumetric shadows; relies on stencil buffer operations which may have performance implications on some hardware [S1, unofficial].
*   **Measured Performance:** Tested on scenes with up to 14,785 triangles, achieving approximately 30 frames per second with direct single scattering and shadows enabled [S1, unofficial].

## Background
The method was proposed in "Single Scattering Effects for Computer Games" [S1, unofficial]. It follows the same strategy as the shadow volume algorithm, using only shaders and textures [S1, unofficial].
