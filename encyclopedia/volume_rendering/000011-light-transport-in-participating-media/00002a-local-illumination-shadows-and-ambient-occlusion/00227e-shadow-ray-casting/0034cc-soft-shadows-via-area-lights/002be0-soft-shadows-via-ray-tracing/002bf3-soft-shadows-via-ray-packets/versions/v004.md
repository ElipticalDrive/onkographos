# Soft Shadows via Ray Packets

Also called: Area Light Shadows, Ray Packet Soft Shadows, Soft Shadows via Coherent Shadow Rays, Soft Shadows with Ray Packets

## Overview
Soft Shadows via Ray Packets generates soft shadows from area light sources by creating packets of coherent shadow rays [S1, S2]. This method leverages the ray tracing basis of the underlying system to support global illumination effects that are difficult to implement in rasterization-based pipelines [S1, S2]. It differs from hard shadow casting by tracing secondary ray packets from primary ray hit points to multiple samples on an area light source, producing smooth transitions between shadowed and unshadowed regions that provide visual cues about relative object positioning [S1, S2].

## How it works
**Inputs and Outputs:**
- **Input:** Primary ray hit point on a surface or particle; area light source definition; scene geometry (particle dataset); grid structure for traversal [S1, S2].
- **Output:** Shadow visibility factor for the primary ray, used to modulate local illumination [S1].

**Data Structures:**
- **Shadow Ray Packet:** A collection of $N \times N$ shadow rays sharing a common origin at the primary ray hit point [S1, S2]. Each ray is defined by its origin $\mathbf{o}$ and direction $\mathbf{d}$ [G].
- **Area Light Samples:** $N \times N$ points distributed over the area light source [S1, S2]. The light source area is specified as 5% of the solid angle subtended by the bounding box of the scene [S2]. One source notes the area as 5% of the bounding box area instead [S1].

**Numbered Steps:**
1. **Shadow Ray Generation:** For each primary ray that intersects a surface or particle, generate a packet of coherent shadow rays by connecting the hit point to $N \times N$ samples on the area light source [S1, S2]. The direction $\mathbf{d}_i$ for each shadow ray $i$ is calculated as:
   $$ \mathbf{d}_i = \frac{\mathbf{l}_i - \mathbf{o}}{\|\mathbf{l}_i - \mathbf{o}\|} $$
   where $\mathbf{o}$ is the hit point and $\mathbf{l}_i$ is the $i$-th sample point on the area light [G].
2. **Packet Traversal:** Trace the secondary ray packet through the scene using the modified Coherent Grid Traversal (CGT) algorithm [S1, S2]. Because all rays in the packet share a common origin, they exhibit high spatial coherence, allowing them to traverse the grid identically to primary ray packets [S1, S2].
3. **Shadow Determination:** For each ray in the packet, traverse the grid to determine if it intersects any occluding geometry before reaching the light source [S1, S2].
4. **Shading:** Modulate the local illumination (e.g., simple Lambertian shading) by the computed shadow visibility [S1].

**Parameters:**
- **Packet Size ($N \times N$):** Tested sizes are 2x2 (4 rays), 4x4 (16 rays), and 8x8 (64 rays) [S1, S2]. The number of shadow ray samples is interactively controlled by the user to permit performance-for-quality trade-offs [S1, S2].
- **Light Source Area:** 5% of the solid angle subtended by the bounding box of the scene [S2].

**Edge Cases and Pitfalls:**
- **Coherence Dependency:** Interactive performance with soft shadows depends heavily on the coherence exhibited by secondary ray packets [S2].
- **Performance Scaling:** The performance impact is sublinear in the number of shadow rays traced, but large packets can still cause significant frame rate degradation [S2].
- **Light Size:** The tested configurations use a large light source area, which affects the angular spread of shadow rays [S2].

    """
    Compute soft shadow factor for a primary ray hit point using ray packets.
    
    Args:
        hit_point (Vector3): Origin of the shadow ray packet.
        light_samples (List[Vector3]): N*N sample points on the area light.
        grid (Grid): The coherent grid structure for traversal.
        particles (List[Particle]): The particle dataset.
        
    Returns:
        float: Shadow factor (0.0 to 1.0).
    """
    num_rays = len(light_samples)
    occluded_count = 0
    
    for light_sample in light_samples:
        # Calculate shadow ray direction
        direction = light_sample - hit_point
        direction = direction / length(direction)
        
        # Trace shadow ray using modified CGT
        # Returns True if the ray is occluded before reaching the light
        is_occluded = trace_shadow_ray(hit_point, direction, grid, particles)
        
        if is_occluded:
            occluded_count += 1
            
    # Shadow factor is the ratio of unoccluded rays
    shadow_factor = 1.0 - (occluded_count / num_rays)
    return shadow_factor

## Operating characteristics
**Time and Memory Complexity:**
- **Time Complexity:** The performance impact is sublinear in the number of shadow rays traced due to packet coherence [S2].
- **Memory Complexity:** Memory usage depends on the grid structure and particle storage, similar to primary ray casting [S1]. No additional significant memory is required for the shadow rays themselves beyond the packet storage [S2].

**Measured Performance:**
Performance was measured on a test machine with 16 threads, rendering 1024x1024 images [S1]. Frame rates for various datasets and shadow settings are as follows [S1, S2]:

| Dataset     | No shadows | 2x2 (4 rays) | 4x4 (16 rays) | 8x8 (64 rays) |
|-------------|------------|--------------|---------------|---------------|
| Cylinder    | 100.20 fps | 14.91 fps    | 10.47 fps     | 5.34 fps      |
| JP8         | 99.88 fps  | 16.31 fps    | 12.21 fps     | 6.65 fps      |
| Bullet      | 126.93 fps | 19.55 fps    | 13.69 fps     | 6.56 fps      |
| Thunder     | 40.86 fps  | 14.07 fps    | 10.74 fps     | 6.45 fps      |
| Foam        | 14.34 fps  | 4.38 fps     | 2.51 fps      | 1.17 fps      |
| BulletTorso | 18.30 fps  | 7.39 fps     | 6.09 fps      | 3.82 fps      |

The performance degradation ranges from a factor of 2.42 (for 2x2 packets) to 19.35 (for 8x8 packets) [S2].

**Strengths and Limitations:**
- **Strengths:** Integrates easily into ray tracing-based visualization systems; provides smooth, realistic shadows; performance impact is sublinear in the number of shadow rays; user-controllable quality/performance trade-off [S1, S2].
- **Limitations:** Performance is highly dependent on ray coherence; large packets can significantly reduce frame rates; not suitable for real-time applications requiring high frame rates with large shadow packets [S2].

**When to Use:**
- Use when soft shadows are needed for visual clarity in particle-based simulations and interactive performance is acceptable with moderate packet sizes (e.g., 2x2 or 4x4) [S1, S2].
- Avoid when high frame rates are critical and large shadow packets are required, or when ray coherence is low [S2].

## Background
**Origin:**
The method was introduced in the referenced papers on coherent grid traversal for particle visualization [S1, S2]. The work extends the modified Coherent Grid Traversal (CGT) algorithm to support soft shadows via ray packets [S1, S2].

**History and Development:**
The technique builds on previous research in coherent ray tracing and grid traversal for particle visualization [S1]. The specific approach of using ray packets for soft shadows leverages the coherence of shadow rays sharing a common origin to maintain traversal efficiency [S1, S2].

**Applications:**
The method is used in interactive visualization systems for particle-based simulation data, such as fluid dynamics and molecular dynamics simulations, where soft shadows provide important visual cues about object positioning and depth [S1, S2].
