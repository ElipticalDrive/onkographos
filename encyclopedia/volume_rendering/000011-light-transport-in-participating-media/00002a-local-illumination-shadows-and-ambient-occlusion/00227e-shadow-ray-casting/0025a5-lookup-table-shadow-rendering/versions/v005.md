# Lookup Table Shadow Rendering

Also called: One-pass Shadow with Lookup Tables, Shadow Rendering, VolPack Shadow Algorithm

## Overview
Lookup Table Shadow Rendering is a fast, one-pass shadowing technique implemented within the VolPack volume rendering library [S1]. It accelerates shadow determination by mapping density or depth values to pre-calculated shadow factors via a lookup table, rather than evaluating transmittance along rays during rendering [S1].

## How it works
The method relies on the VolPack library's internal data structures and configuration functions [S1]. The core mechanism involves configuring a shadow lookup shader that uses precomputed tables to determine the shadow factor for voxels based on their density and depth [S1].

**Inputs and Outputs:**
*   **Input:** A volume dataset managed by VolPack, specifically the density field and the viewing volume parameters (front/back planes) [S1].
*   **Output:** A rendered image [S1].

**Data Structures:**
*   **VolPack Context (`vpContext`):** Manages the state of the volume rendering, including the lookup tables for shadows [S1].
*   **Lookup Table:** A precomputed array mapping input parameters to shadow factors [S1]. The exact layout and size of this table are not specified in the sources [S1].

**Steps:**
1.  Configure the shadow lookup shader using `vpSetShadowLookupShader` [S1].
2.  Declare the output image array using `vpSetImage`, which also implicitly determines the viewport transformation [S1].
3.  Render the volume; during rendering, the shadow factor is retrieved from the lookup table based on voxel properties (density, depth) [S1].
4.  Calculate fog transparency as $T = front\_factor \cdot \exp(-density \cdot depth)$, where $depth$ is $0$ at the front plane and $1$ at the back plane [S1].
5.  Modulate the voxel's color or transparency with the retrieved shadow factor [S1].

**Parameters:**
*   **Density:** Controls fog density and recession into darkness [S1].
*   **Front Factor:** Multiplies transparency, where larger numbers brighten the foreground [S1].
*   **Depth:** The normalized distance from the front plane [S1].
*   **Typical Values:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   The exact implementation details of `vpSetShadowLookupShader` and the lookup table size/content are not provided in the sources [S1].

## Subtopics

### Voxel Shadow Raycasting
A shadowing algorithm that casts rays from a light source to each voxel to determine occlusion and darken the voxel index accordingly [S2, unofficial]. It iterates through all voxels, casts a ray to the light, and if an occluding voxel is found, it subtracts a depth value from the voxel's palette index [S2, unofficial]. This method is CPU-based and uses a palette index system for color and shading [S2, unofficial]. It is suitable for simple voxel engines where GPU acceleration is not available [S2, unofficial]. The shadowing is applied by modifying the voxel index directly, which affects both color and shading [S2, unofficial]. A key pitfall is ensuring the voxel index does not drop below the lower bound of its tone group, requiring clamping [S2, unofficial].

**Steps:**
1.  Iterate $x$ from $0$ to $xsize-1$, $y$ from $0$ to $ysize-1$, and $z$ from $0$ to $zsize-1$ [S2, unofficial].
2.  Retrieve the current voxel's palette index: `voxel = get_voxel_pal(x, y, z)` [S2, unofficial].
3.  If the voxel is not empty (`voxel != 0`), cast a ray from the light position $(lx, ly, lz)$ to the voxel position $(x, y, z)$ using `throw_ray_to_pos` [S2, unofficial]. Let the result be $(hx, hy, hz, i)$, where $i$ is the index of the first non-empty voxel hit along the ray [S2, unofficial].
4.  If the ray hit a voxel ($i \neq 0$), darken the current voxel by subtracting depth: `voxel = voxel - depth` [S2, unofficial].
5.  Write the modified voxel index back: `set_voxel_pal(x, y, z, voxel)` [S2, unofficial].

**Parameters:**
*   $(lx, ly, lz)$ are the world coordinates of the light source [S2, unofficial].
*   `depth` is the amount to darken the voxel index if in shadow, typically between $1$ and $32$ [S2, unofficial].
*   $(xsize, ysize, zsize)$ are the dimensions of the current level in voxels [S2, unofficial].

**Pitfalls:**
*   The voxel index must not drop below the lower bound of its tone group [S2, unofficial].
*   Calculate `color_margin = math.floor((voxel-1)/32)*32 + 1` [S2, unofficial].
*   If `voxel < color_margin`, clamp it to `color_margin` [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** The lookup table requires additional memory, the size of which is not specified [S1].
*   **Performance:** VolPack's lookup table method is described as "fast" [S1]. The Voxel Shadow Raycasting method is CPU-based [S2, unofficial].
*   **Strengths:** Fast shadow computation for VolPack [S1]. Simple implementation for CPU-based voxel engines [S2, unofficial].
*   **Limitations:** Limited flexibility in shadow appearance due to precomputed tables [S1]. CPU-bound performance for Voxel Shadow Raycasting [S2, unofficial].
*   **When to use:** Use VolPack's method when using the VolPack library and needing fast shadows [S1]. Use Voxel Shadow Raycasting for CPU-based voxel engines [S2, unofficial].

## Background
The Lookup Table Shadow Rendering method is part of the VolPack volume rendering library developed by Stanford University [S1]. The Voxel Shadow Raycasting method is part of the "Doommy" voxel engine, an unofficial project by jabberx [S2, unofficial].
