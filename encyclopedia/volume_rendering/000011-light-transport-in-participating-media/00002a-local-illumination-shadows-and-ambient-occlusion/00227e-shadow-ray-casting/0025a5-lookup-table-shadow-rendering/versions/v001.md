# Lookup Table Shadow Rendering

Also called: One-pass Shadow with Lookup Tables, Shadow Rendering, VolPack Shadow Algorithm

## Overview
Lookup Table Shadow Rendering is a fast, one-pass shadowing technique implemented within the VolPack volume rendering system. It solves the problem of computing shadows for participating media by precomputing shadow contributions into lookup tables, avoiding the per-ray integration overhead of standard shadow ray casting. It is distinguished from its siblings by its reliance on precomputed tables for immediate shading, whereas methods like [Shadow Ray Casting](2796-shadow-ray-casting.md) compute visibility dynamically per fragment.

## How it works
The method relies on the VolPack API to configure and execute a shadowing pass that utilizes lookup tables to accelerate the calculation of light attenuation through the volume.

**Inputs and Outputs:**
*   **Input:** A VolPack context (`vpContext`), shadow parameters (light position, density, falloff), and the volume data structure.
*   **Output:** A rendered image with shadows applied, where voxel colors are modulated by the shadow factor.

**Data Structures:**
The implementation uses the VolPack internal structures. The specific layout of the lookup tables is not exposed in the public API documentation; they are managed internally by the library [S1].

**Steps:**
1.  **Initialize VolPack Context:** Create and configure the VolPack context using standard initialization routines.
2.  **Configure Shadow Lookup Shader:** Call `vpSetShadowLookupShader` to enable and configure the one-pass shadow algorithm. This function sets up the internal lookup tables based on current shadow parameters [S1].
    *   *Note:* The exact parameters accepted by `vpSetShadowLookupShader` are detailed in the VolPack man page, which is not fully reproduced in the provided source text [S1].
3.  **Set Image Buffer:** Declare the output image array using `vpSetImage` to specify the destination buffer, width, height, and pixel format [S1].
4.  **Render:** Execute the rendering pass. VolPack internally uses the precomputed lookup tables to determine shadow contributions for each voxel or fragment during the ray marching process [S1].

**Formulas:**
While the specific lookup table generation formula is not explicitly detailed in the provided text, VolPack's general transparency model for fog/shadowing is given by:
$$ T = \text{front\_factor} \times \exp(-\text{density} \times \text{depth}) $$
where:
*   $T$ is the transparency factor.
*   $\text{front\_factor}$ is a scaling factor (typically 1.0, but can be larger to brighten foreground) [S1].
*   $\text{density}$ controls the rate at which objects recede into darkness [S1].
*   $\text{depth}$ is the normalized distance from the front plane (0) to the back plane (1) of the viewing volume [S1].

Each voxel color component is multiplied by this transparency factor $T$ during rendering [S1].

**Parameters:**
*   **Density:** Controls the "density" of the fog/shadowing effect [S1].
*   **Front Factor:** Scaling factor for foreground brightness [S1].
*   **Light Position/Direction:** Implicitly handled by the shadow shader configuration [S1].

**Edge Cases and Pitfalls:**
*   **API Dependency:** The method is tightly coupled to the VolPack library's internal implementation. Customizing the lookup table generation requires understanding VolPack's internal man page documentation [S1].
*   **Precision:** Not given in the sources.
*   **Boundaries:** The `depth` parameter is normalized between 0 and 1 relative to the viewing volume [S1].

## Subtopics

### Voxel Shadow Raycasting
A shadowing algorithm that casts rays from a light source to each voxel to determine if it is in shadow, darkening the voxel index accordingly [S2, unofficial]. It differs from Lookup Table Shadow Rendering by operating directly on voxel indices in a CPU-based engine rather than using precomputed tables in a GPU/library context [S2, unofficial]. Choose this when implementing a custom CPU-based voxel engine without external rendering libraries [S2, unofficial].

**Steps:**
1.  Iterate $x$ from $0$ to $xsize-1$, $y$ from $0$ to $ysize-1$, and $z$ from $0$ to $zsize-1$ [S2, unofficial].
2.  Retrieve the current voxel's palette index: `voxel = get_voxel_pal(x, y, z)` [S2, unofficial].
3.  If the voxel is not empty (`voxel != 0`), cast a ray from the light position $(lx, ly, lz)$ to the voxel position $(x, y, z)$ using `throw_ray_to_pos` [S2, unofficial].
4.  Let the result be $(hx, hy, hz, i)$, where $i$ is the index of the first non-empty voxel hit along the ray [S2, unofficial].
5.  If the ray hit a voxel ($i \neq 0$), darken the current voxel by subtracting depth: `voxel = voxel - depth` [S2, unofficial].
6.  Write the modified voxel index back: `set_voxel_pal(x, y, z, voxel)` [S2, unofficial].

**Parameters:**
*   $lx, ly, lz$: World coordinates of the light source [S2, unofficial].
*   $depth$: Amount to darken the voxel index if in shadow, typically between 1 and 32 [S2, unofficial].
*   $xsize, ysize, zsize$: Dimensions of the current level in voxels [S2, unofficial].

**Pitfalls:**
*   The voxel index must not drop below the lower bound of its tone group. Calculate `color_margin = math.floor((voxel-1)/32)*32 + 1`. If `voxel < color_margin`, clamp it to `color_margin` [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. The "one-pass" description suggests $O(1)$ lookup cost per fragment after table construction, but table construction cost is unspecified [S1].
*   **Memory Complexity:** Not given in the sources. Depends on the size of the internal lookup tables [S1].
*   **Measured Performance:** Described as "fast" [S1].
*   **Strengths:** Fast one-pass execution; integrates directly with VolPack's rendering pipeline [S1].
*   **Limitations:** Tied to the VolPack library; lack of detailed control over the lookup table generation process [S1].
*   **When to use:** When using VolPack and requiring efficient shadows for participating media [S1].
*   **When not to use:** When custom shadow algorithms or non-VolPack pipelines are required [S1].

## Background
The method originates from the VolPack volume rendering system, which supports a fast one-pass shadow algorithm implemented with lookup tables [S1]. It is documented in the VolPack User's Guide [S1].
