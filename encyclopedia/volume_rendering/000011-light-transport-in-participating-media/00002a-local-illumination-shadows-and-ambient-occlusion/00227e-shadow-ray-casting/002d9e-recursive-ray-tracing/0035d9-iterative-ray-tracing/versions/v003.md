# Iterative Ray Tracing

Also called: Bounce-Level Ray Looping, Iterative Ray Color Calculation, Non-recursive Ray Tracing

## Overview
Iterative Ray Tracing is a GPU-friendly implementation of recursive ray tracing that replaces function calls with an explicit loop to compute ray color [S1, unofficial]. It solves the problem of limited or absent recursion support in GPU shading languages like GLSL, while reducing register pressure and shader inlining overhead by consolidating ray tracer calls into a single loop per bounce level [S1, unofficial][S2, unofficial]. It builds on [Recursive Ray Tracing](5600-recursive-ray-tracing.md) [S1, unofficial].

## How it works
**Inputs:**
*   $r$: Current ray (origin, direction) [S1, unofficial].
*   $O$: Set of objects in the scene [S1, unofficial].
*   $b$: Remaining bounce count (integer) [S1, unofficial].

**Outputs:**
*   `color`: The computed radiance/color for the ray [S1, unofficial].

**Data Structures:**
*   `sphereRays`: An array storing 1 or 2 rays per bounce level [S2, unofficial].
*   `c`: Accumulator for material color, initialized to 1 (identity for Hadamard product) [S1, unofficial].

**Formulas:**
*   **Hadamard Product ($\circ$):** Element-wise multiplication of vectors/matrices of same dimensions. $(a, c, e) \circ (b, d, f) = (ab, cd, ef)$ [S1, unofficial].
*   **Ray Point:** $p = \text{origin}(r) + t \cdot \text{direction}(r)$, where $t$ is the intersection distance [S1, unofficial].

**Steps:**
1.  Initialize accumulator $c \leftarrow 1$ [S1, unofficial].
2.  Enter an infinite loop [S1, unofficial].
3.  Check if $b < 0$. If true, return 0 [S1, unofficial].
4.  Find object $o \in O$ with minimum intersection distance $t > 0$ from current ray $r$ [S1, unofficial].
    *   $o \leftarrow \arg \min_{o \in O} \{ t \mid t = \text{intersection test}(r, o) \land t > 0 \}$ [S1, unofficial].
5.  If no object is hit ($o = \emptyset$), return $\text{bg}(r) \circ c$, where $\text{bg}(r)$ is the background color [S1, unofficial].
6.  Compute intersection point $p$ using $r$ and $t$ [S1, unofficial].
7.  Compute valid bounce direction $d$ at point $p$ on object $o$ given incoming ray $r$ [S1, unofficial].
8.  Update ray $r \leftarrow \text{ray}(p, d)$ [S1, unofficial].
9.  Update accumulator $c \leftarrow c \circ \text{color material}(p, o)$ [S1, unofficial].
10. Repeat from step 2 [S1, unofficial].

**Pseudocode:**
```python
def iterative_ray_color(r, O, b):
    c = [1.0, 1.0, 1.0]  # Accumulator initialized to identity for Hadamard product [S1, unofficial]
    while True:
        if b < 0:
            return [0.0, 0.0, 0.0]  # No more bounces allowed [S1, unofficial]
        
        # Find object o with minimum intersection distance t > 0 from current ray r among all objects O [S1, unofficial]
        o = None
        min_t = float('inf')
        for obj in O:
            # Standard ray-object intersection test returning t > 0, or infinity [G]
            t = float('inf')
            if t > 0 and t < min_t:
                min_t = t
                o = obj
        
        if o is None:
            # No object hit: return background color modulated by accumulated material color [S1, unofficial]
            return hadamard(background_color(r), c)
        
        # Compute intersection point p using ray origin, direction, and distance t [S1, unofficial]
        t = min_t
        p = r.origin + t * r.direction
        
        # Compute valid bounce direction d at point p on object o given incoming ray r [S1, unofficial]
        # Standard reflection or shading normal calculation [G]
        d = r.direction
        
        # Update ray r to start at p with direction d [S1, unofficial]
        r = Ray(p, d)
        
        # Update accumulator c by Hadamard multiplying it with the material color at p on object o [S1, unofficial]
        c = hadamard(c, material_color(p, o))  # Returns material color vector at point [G]

def hadamard(a, b):
    return [a[i] * b[i] for i in range(len(a))]

def background_color(ray):
    # Returns scene background color vector [G]
    return [0.0, 0.0, 0.0]

def material_color(point, obj):
    # Returns material color vector at point [G]
    return [1.0, 1.0, 1.0]

class Ray:
    def __init__(self, origin, direction):
        self.origin = origin
        self.direction = direction
```

**Parameters:**
*   `b`: Maximum bounce depth [S1, unofficial].
*   `sphereRays`: Array of 1 or 2 rays per bounce level [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Recursion Limit:** GPUs like GLSL do not support recursion, necessitating this iterative approach [S1, unofficial].
*   **Register Pressure:** By inlining only 2 walks per level and looping over `sphereRays`, register usage is reduced compared to recursive inlining of 6 grid walks [S2, unofficial].
*   **Background Color:** If no object is hit, the background color is returned, modulated by the accumulated material color [S1, unofficial].

## Background
Iterative Ray Tracing was developed as a practical solution for implementing global illumination on GPUs, specifically in GLSL, which lacks recursion support [S1, unofficial]. It was adopted as the most common method to avoid the maintenance burden of defining separate functions for each bounce level [S1, unofficial]. It is used in real-time ray tracing applications and educational implementations of global illumination [S1, unofficial][S2, unofficial].
