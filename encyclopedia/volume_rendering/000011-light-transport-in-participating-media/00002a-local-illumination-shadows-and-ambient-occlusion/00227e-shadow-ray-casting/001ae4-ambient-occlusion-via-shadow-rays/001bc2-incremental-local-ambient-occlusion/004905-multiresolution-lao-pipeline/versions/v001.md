# Multiresolution LAO Pipeline

Also called: Incremental LAO update, Per-fragment LAO computation

## Overview
The Multiresolution LAO Pipeline is a per-fragment GPU-based method for computing Local Ambient Occlusion (LAO) illumination in multiresolution volume rendering. It accelerates LAO computation by leveraging the same data reduction achieved by the volume's Level-of-Detail (LOD) selection, adapting sampling rates to voxel block resolution. Unlike the parent Incremental LAO method which updates one ray direction per frame, this pipeline processes all incident light directions incrementally over multiple frames using a fragment shader pipeline, allowing for dynamic configuration of ray counts and efficient hardware-accelerated blending.

## How it works
**Inputs and Outputs:**
- **Input:** A multiresolution packed volume texture, a reverse index texture mapping packed coordinates to volume coordinates ($P \to V$), and a set of incident light directions in the local neighborhood $\Omega$.
- **Output:** A 3D texture storing the accumulated emissive color and ambient occlusion factor for each voxel.

**Data Structures:**
1.  **Packed Volume Texture:** Stores voxel data (opacity $\alpha$, color) organized in blocks of varying resolutions.
2.  **Reverse Index Texture ($P \to V$):** Maps a packed coordinate $P$ to its corresponding volume coordinate $V$. This is necessary because the volume is packed to save space, and lower-resolution blocks contain fewer voxels.
3.  **LAO Accumulation Texture:** A 3D texture (or 2D texture array if slice-by-slice rendering is used) that stores the running sum of light contributions for each voxel.
4.  **Ray Direction Texture:** Stores the $K$ ray directions and their associated weights $w_k$.

**Parameters:**
-   $K$: Number of light directions to sample. Dynamically configurable.
-   $a$: User-defined initial offset for sampling along a ray. Prevents self-occlusion for boundary voxels.
-   $d$: Base sampling density.
-   $R_\Omega$: Radius of the local occlusion neighborhood.
-   $\gamma$: User-controlled parameter to modify opacity for LAO intensity control.
-   $\lambda_h$: Highest resolution level (base level) of the volume blocks.
-   $\lambda$: Current block resolution level of the voxel being processed.

**Algorithm Steps:**

1.  **Initialization:** Create the LAO accumulation 3D texture initialized to zero. Store the $K$ ray directions and weights in a texture.
2.  **Slice Mapping:** Iterate through each slice of the packed volume texture. Map the current slice as the rendering target of a Framebuffer Object (FBO).
    *   *Constraint:* Requires GPU hardware support for attaching a 3D texture slice to an FBO (e.g., Nvidia GF8800 Ultra or later) [S1].
3.  **Fragment Pipeline Initiation:** Render a large quad covering the entire framebuffer. Each pixel in the quad corresponds to one voxel in the current mapped slice.
4.  **Voxel Location Lookup:** For each fragment, use the fragment's 2D location and the per-slice constant $z$-position to determine the packed coordinate $P$. Use the reverse index texture ($P \to V$) to retrieve the corresponding volume coordinate $V$ and the block level $\lambda$ of that voxel.
5.  **Ray Iteration (Incremental Update):** The pipeline iterates over the $K$ incident light directions. This iteration happens over multiple frames (one direction per frame, or a batch of directions per frame) to incrementally build the LAO result.
    *   For each ray direction $\omega_k$ with weight $w_k$:
        a.  **Determine Step Length:** Calculate the step length $s$ based on the block level $\lambda$. The step length is increased to maintain sampling density relative to the underlying volume data:
            $$ s = \frac{2^{\lambda_h} + 2^\lambda}{2} $$
            *Note:* If the difference in step length between adjacent blocks is too large, block artifacts may occur [S1].
        b.  **Sample Volume:** Starting at offset $a$ along the ray direction $\omega_k$, sample the volume at intervals of $s$. Use the reverse index texture to map sample positions from volume space back to packed texture coordinates for lookup.
        c.  **Opacity Correction:** When sampling, the opacity $\alpha$ must be corrected on the fly to account for the changed step length and density. The modified opacity $\alpha_{modified}$ is calculated as:
            $$ \alpha_{modified} = 1.0 - (1.0 - \alpha_{original})^{\frac{\gamma \cdot d \cdot 2}{2^{\lambda_h} + 2^\lambda}} $$
            Where $\alpha_{original}$ is the stored opacity, $\gamma$ is the control parameter, and $d$ is the base sampling density.
        d.  **Accumulate Contribution:** Compute the light contribution of the ray (transmittance and emission along the path). Blend this contribution with the previously stored value in the LAO accumulation texture using OpenGL blend operations (e.g., additive blending).
6.  **Final Intensity:** After all $K$ rays have been processed (over $K$ frames), the final LAO factor for a voxel is the average of the accumulated ray intensities.
7.  **Rendering:** Perform the final volume rendering using the accumulated LAO texture. Interblock interpolation is optional in the final rendering but is not performed during LAO computation to avoid excessive texture lookups [S1].

**Pseudocode:**

```python
# Constants
K = 8  # Number of rays
a = 0.1  # Initial offset
d = 1.0  # Base sampling density
gamma = 1.0  # Opacity control parameter
lambda_h = 0  # Highest resolution level (base)

# Pre-computed ray directions and weights stored in a texture
ray_directions = load_ray_directions(K)
ray_weights = load_ray_weights(K)

# Main loop: Process each slice of the volume
for slice_z in range(num_slices):
    # Bind the slice of the 3D LAO accumulation texture to the FBO
    bind_fbo_texture_slice(lao_texture, slice_z)
    
    # Render a quad covering the framebuffer
    render_quad()

# Fragment Shader Code (executed per voxel in the slice)
def fragment_shader():
    # 1. Get fragment coordinates
    frag_coord = get_fragment_position()
    z_pos = slice_z  # Constant for this slice
    
    # 2. Map fragment to packed coordinate P
    P = (frag_coord.x, frag_coord.y, z_pos)
    
    # 3. Look up volume coordinate V and block level lambda
    V, lambda_val = reverse_index_texture.lookup(P)
    
    # 4. Get original voxel data
    alpha_original, color_original = volume_texture.lookup(V)
    
    # 5. Initialize accumulated LAO value for this voxel
    # This value persists across frames for the K rays
    accumulated_lao = lao_accumulation_texture.lookup(V)
    
    # 6. Incremental update: Process one ray per frame (or batch)
    # The frame counter determines which ray index to process
    ray_index = get_current_frame_ray_index()
    direction = ray_directions[ray_index]
    weight = ray_weights[ray_index]
    
    # Calculate step length based on block level
    step_length = (2**lambda_h + 2**lambda_val) / 2.0
    
    # Sample along the ray
    ray_intensity = 0.0
    t = a  # Start at offset a
    while t < R_Omega:  # R_Omega is the neighborhood radius
        # Sample position in volume space
        sample_pos = V + direction * t
        
        # Map sample position to packed coordinates
        sample_P = reverse_index_texture.map_volume_to_packed(sample_pos)
        
        # Lookup opacity in packed volume
        alpha_sample = volume_texture.lookup_alpha(sample_P)
        
        # Apply opacity correction
        exponent = (gamma * d * 2.0) / (2**lambda_h + 2**lambda_val)
        alpha_modified = 1.0 - (1.0 - alpha_sample)**exponent
        
        # Accumulate transmittance/emission (simplified)
        # In practice, this involves integrating emission and transmittance
        ray_intensity += sample_emission(sample_P) * transmittance
        
        t += step_length
    
    # Average the ray intensity by the weight (simplified averaging)
    # The blending operation in the GPU handles the accumulation
    contribution = ray_intensity * weight
    
    # Blend contribution into the LAO accumulation texture
    # This is done via OpenGL blend function, e.g., GL_ADD
    lao_accumulation_texture.write(V, accumulated_lao + contribution)

# After K frames, the LAO texture contains the final accumulated values.
# Final rendering uses these values.
```

**Edge Cases and Pitfalls:**
-   **Hardware Dependency:** The method requires GPU support for attaching a 3D texture slice to an FBO. Without this, the slice-by-slice rendering target approach fails [S1].
-   **Block Artifacts:** A large difference in step length between adjacent blocks (due to different $\lambda$ values) can lead to visible block artifacts in the LAO effect. Careful tuning of $\lambda_h$ and $\lambda$ is required [S1].
-   **Interblock Interpolation:** Interblock interpolation is not performed during LAO computation to save texture lookups. While optional in final rendering, its absence in LAO computation has not been observed to cause significant artifacts [S1].

## Operating characteristics
-   **Time Complexity:** The computation is performed incrementally over $K$ frames. Each frame processes one ray direction for all voxels. The cost per voxel per frame depends on the number of samples along the ray, which is proportional to $R_\Omega / s$. Since $s$ increases with $\lambda$, lower-resolution blocks are processed faster.
-   **Memory Complexity:** Requires storage for the packed volume, the reverse index texture, and the LAO accumulation texture. The LAO texture size is proportional to the number of voxels in the volume.
-   **Performance:** The method achieves speed-up by combining multiresolution data reduction with adaptive sampling rates. The use of GPU fragment shaders and hardware blending allows for efficient parallel processing. Reported frame rates for LAO computation with 8 directions were comparable to diffuse illumination rendering (e.g., 27.2 FPS vs 26.4 FPS in the source results) [S1].
-   **Strengths:** Efficient incremental update, hardware-accelerated, adapts to multiresolution structure.
-   **Limitations:** Requires specific GPU hardware features, potential block artifacts if step length differences are not managed, limited to local occlusion.

## Background
The Multiresolution LAO Pipeline was introduced by Hernell et al. in 2007 as part of the paper "Efficient Ambient and Emissive Tissue Illumination using Local Occlusion in Multiresolution Volume Rendering" [S1]. It builds upon the Incremental LAO method and integrates with multiresolution volume management techniques to provide efficient local illumination effects for volumetric data, particularly in medical imaging contexts.
