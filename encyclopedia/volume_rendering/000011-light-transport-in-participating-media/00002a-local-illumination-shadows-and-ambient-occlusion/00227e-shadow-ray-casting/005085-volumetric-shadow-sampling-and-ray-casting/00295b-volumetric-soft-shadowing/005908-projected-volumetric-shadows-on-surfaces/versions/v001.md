# Projected Volumetric Shadows on Surfaces

Also called: Projected Volumetric Shadows, Surface Lighting (Cast Direct Light), Volumetric shadows on opaque objects

## Overview
Projected Volumetric Shadows on Surfaces is a technique to cast shadows from a participating medium onto opaque geometry using a pre-computed volumetric shadow map [S2, unofficial]. It allows the volumetric beam to light the surfaces it reaches, creating bright patches with soft shadows that align with the medium's occlusion [S1, unofficial]. Unlike standard shadow mapping which casts shadows from opaque objects, this method projects the medium's own density onto the scene, building on the occlusion data generated by [Volumetric Soft Shadowing](4507-volumetric-soft-shadowing.md).

## How it works
**Inputs:**
- World-space position of the surface pixel being shaded.
- Volumetric shadow map containing optical thickness $\tau$.
- Light intensity multiplier.
- Shadow filtering parameters (samples, radius).

**Outputs:**
- Transmittance factor $T$ applied to the surface lighting calculation.

**Data Structures:**
- **Volumetric Shadow Map:** A texture storing optical thickness $\tau$. The layout is identical to the shadow map used for the volume itself, typically a depth-like texture where each texel stores the integrated extinction coefficient along the light ray [S2, unofficial].

**Steps:**
1. **Coordinate Conversion:** In the pixel shader, convert the world-space coordinates of the pixel being shaded into the shadow map's texture space (shadow space) [S2, unofficial].
2. **Sampling:** Sample the optical thickness $\tau$ from the volumetric shadow map at the projected coordinates [S2, unofficial].
3. **Transmittance Calculation:** Compute the transmittance $T$ using the Beer-Lambert law:
   $$ T = e^{-\tau} $$
   where $\tau$ is the optical thickness sampled from the map [S2, unofficial].
4. **Lighting Application:** Use $T$ as the shadow factor when computing the direct lighting contribution for the surface [S2, unofficial].

**Parameters:**
- **Intensity:** A multiplier for the light contribution on surfaces [S1, unofficial].
- **Softness Samples:** Number of samples used for filtering shadow edges, ranging from 1 to 32. Higher values produce softer penumbras [S1, unofficial].
- **Softness Radius:** Radius for filtering shadow edges, ranging from 0 to 8. A wider radius yields softer penumbras [S1, unofficial].
- **Blend Mode:** Determines how the projected light interacts with the surface material.
    - **Additive:** Adds light shaded by scene normals [S1, unofficial].
    - **Blend:** Reads albedo and specular from the G-Buffer, allowing material-specific coloring. This mode is slower and requires the Deferred rendering path [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Rendering Path Dependency:** The "Blend" mode requires the Deferred rendering path. In Forward+ or Deferred+ paths, translucent shadow maps may not be available, requiring DirectX 11 or specific rendering path configurations [S1, unofficial].
- **Feature Requirements:** When using Render Graph, the "Volumetric Lights Render Feature" must be enabled on the URP Renderer, or the system will warn of missing dependencies [S1, unofficial].
- **Light Component Independence:** Because the volume lights the surfaces directly, the standard scene Light component can be disabled to avoid double illumination, though it must remain enabled if other lighting calculations depend on it [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Dominated by the shadow map sampling and filtering in the pixel shader. Filtering cost scales linearly with the number of Softness Samples [S1, unofficial].
- **Memory Complexity:** Requires storing the volumetric shadow map, which is shared with the volume rendering pass [S2, unofficial].
- **Strengths:** Provides visually consistent shadows that match the volumetric beam's shape and color, including colored patches from translucent media (e.g., stained glass effects) [S1, unofficial].
- **Limitations:** The "Blend" mode is computationally expensive due to G-Buffer reads [S1, unofficial]. Requires specific rendering infrastructure (URP Render Graph, Deferred path) for full feature support [S1, unofficial].

## Background
The technique is described in the context of volumetric rendering of particles and light transport in participating media [S2, unofficial]. It is also implemented as a feature in Unity's Universal Render Pipeline (URP) under the name "Cast Direct Light," where it is designed to work with the Deferred rendering path and Render Graph [S1, unofficial].
