# Shadow Caching

Also called: Shadow Caching with 3D Textures

## Overview
Shadow Caching exploits the inherent coherence of shadow rays for a point light source that are occluded by the same object to avoid redundant ray traversal [S1, unofficial]. It stores occlusion results in a spatial data structure, replacing expensive shadow ray casts during rendering [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Scene subdivision, light source position, and transfer function [S1, unofficial][S2, unofficial].
*   **Output:** A cached shadow lookup structure and the final rendered image [S2, unofficial].

**Data Structures:**
1.  **Shadow Cache (3D Texture):** A volumetric texture storing the shadow status for each spatial region relative to the light source [S2, unofficial].
2.  **Shadow Feelers:** Precomputed rays used to populate the cache [S2, unofficial].

**Steps:**
1.  Subdivide the scene into cells or spatial regions [S1, unofficial].
2.  For each cell, generate shadow feelers by casting rays from representative points toward the light source [S2, unofficial].
3.  Traverse the feelers to determine if the cell is fully occluded, fully visible, or partially visible to the light [S1, unofficial].
4.  Store the occlusion status in the spatial cache, such as a 3D texture [S2, unofficial].
5.  During rendering, query the cache for the cell containing the shading point [G].
6.  If the cache indicates fully occluded or fully visible, return the cached result immediately [S1, unofficial].
7.  If partially visible or a cache miss occurs, perform a full shadow ray traversal [S1, unofficial].

**Parameters:**
*   **Light Source Position:** Must be known during preprocessing [S2, unofficial].
*   **Cache Resolution:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   Shadow feelers must be recomputed if the light source position changes or if the transfer function changes [S2, unofficial].

**Pseudocode:**
```python
def build_shadow_cache(scene_cells, light_position):
    cache = {}
    for cell in scene_cells:
        feelers = [(cell.center, light_position)]
        status = "FULLY_VISIBLE"
        for start, end in feelers:
            if is_occluded(start, end, scene):
                status = "FULLY_OCCLUDED"
                break
        cache[cell.id] = status
    return cache

def render_shadow_caching(voxels, cache, light_position):
    for voxel in voxels:
        cell_id = get_cell_id(voxel.position)
        status = cache.get(cell_id, "PARTIALLY_VISIBLE")
        if status == "FULLY_OCCLUDED":
            voxel.light = 0.0
        elif status == "FULLY_VISIBLE":
            voxel.light = 1.0
        else:
            voxel.light = 0.0 if is_occluded(voxel.position, light_position, scene) else 1.0

def is_occluded(start, end, scene):
    # Standard ray-scene intersection check
    return any(intersects(ray, obj) for obj in scene.objects)

def get_cell_id(position):
    # Standard spatial hashing or grid lookup
    return hash(position)
```

## Subtopics

### Shadow Caching with 3D Textures
This variant uses 3D textures to store shadow results, gaining performance through fast texture lookups instead of ray traversal [S2, unofficial]. It requires preprocessing of shadow feelers [S2, unofficial]. A key pitfall is that shadow feelers need to be recomputed if the light source position changes or if the transfer function changes [S2, unofficial].

## Operating characteristics
Time and memory complexity are Not given in the sources. Strengths include exploiting shadow ray coherence to reduce redundant computations [S1, unofficial]. Limitations include preprocessing overhead and costly cache invalidation when the light source or transfer function changes [S2, unofficial]. Usage guidelines are Not given in the sources.

## Background
Fernandez et al. [104] subdivided the scene and maintained lists of light sources per region as fully occluded, fully visible, or partially visible using shadow ray approximations [S1, unofficial]. Pharr et al. [94] introduced ray queues for scene cells [S1, unofficial]. The 3D texture variant was explored by Ropinski for GPU-based volume raycasting [S2, unofficial].
