# Variance Shadow Mapping for NeRFs

Also called: NeRF shadow mapping, VSM for NeRFs

## Overview
Variance Shadow Mapping for NeRFs is a technique for rendering cast shadows in neural radiance fields that avoids the computational cost of ray-marching transmittance along shadow rays. Inspired by traditional variance shadow mapping, it computes shadow visibility by comparing the depth of a surface point (from the camera view) against a statistical distribution of depths rendered from a virtual light source. It produces soft, continuous shadows in the range $[0, 1]$, distinguishing it from naive shadow mapping which yields hard edges, and from direct shadow ray casting which requires expensive cumulative transmittance calculations.

## How it works
The method relies on two depth maps: one from the camera view and one from a virtual light source. It uses the Chebyshev inequality to estimate the probability that a point is occluded based on the mean and variance of the depth distribution in the light's view.

### Inputs and Outputs
*   **Inputs**:
    *   Camera parameters (intrinsics, extrinsics).
    *   Light source position and orientation (defining the virtual light camera).
    *   A trained NeRF model (implicitly accessed via the generation of depth maps).
    *   A surface point $\mathbf{r}$ in 3D space (or the ray $\mathbf{r}$ being rendered).
*   **Outputs**:
    *   Visibility factor $V(\mathbf{r}) \in [0, 1]$.
    *   Final pixel color $I(\mathbf{r})$ (when combined with other lighting terms).

### Data Structures
1.  **Depth Map ($X$)**: A 2D array of size $H \times W$ (matching the light camera resolution). Each element stores the depth $z$ of the first surface hit from the light's perspective.
2.  **Squared Depth Map ($X^2$)**: A 2D array of size $H \times W$. Each element stores the square of the depth value at that pixel ($z^2$).
3.  **Filtered Maps**:
    *   $\mu(X)$: Box-filtered version of $X$.
    *   $\mu(X^2)$: Box-filtered version of $X^2$.

### Numbered Steps

1.  **Reconstruct 3D Coordinates from Camera View**:
    Using the depth map from the primary camera view and the camera parameters, reconstruct the 3D coordinates of the surface point $\mathbf{r}$ corresponding to the pixel being rendered. Let $z(\mathbf{r})$ be the depth of this point along the light ray direction (or the depth value associated with the point in the light's coordinate system).

2.  **Render Light View Depth Maps**:
    Set up a virtual camera at the light source position. Render two depth maps from this view:
    *   The standard depth map $X$, where each pixel stores the distance to the nearest surface.
    *   The squared depth map $X^2$, where each pixel stores the square of that distance.

3.  **Box Filtering**:
    Apply a box filter (uniform averaging) over a neighborhood of size $k \times k$ to both $X$ and $X^2$. This produces the filtered mean depth $\mu(X)$ and filtered mean squared depth $\mu(X^2)$.
    *   *Note*: The filter size determines the softness of the shadow.

4.  **Calculate Variance**:
    For the pixel $\mathbf{r}_l$ in the light view corresponding to the 3D point $\mathbf{r}$, calculate the variance $\sigma^2(\mathbf{r}_l)$ using the formula:
    $$ \sigma^2(\mathbf{r}_l) = \mu(\mathbf{X}^2)(\mathbf{r}_l) - \mu^2(\mathbf{X})(\mathbf{r}_l) $$

5.  **Calculate Visibility**:
    Determine the visibility $V(\mathbf{r})$ by comparing the point's depth $z(\mathbf{r})$ with the mean depth $\mu(\mathbf{X})(\mathbf{r}_l)$ from the light view:
    $$ V(\mathbf{r}) = \begin{cases} 1, & z(\mathbf{r}) \leq \mu(\mathbf{X})(\mathbf{r}_l) \\ \frac{\sigma^2(\mathbf{r}_l)}{\sigma^2(\mathbf{r}_l) + (z(\mathbf{r}) - \mu(\mathbf{X})(\mathbf{r}_l))^2}, & z(\mathbf{r}) > \mu(\mathbf{X})(\mathbf{r}_l) \end{cases} $$
    *   If the point is closer to the light than the mean depth of the light's view, it is fully visible ($V=1$).
    *   If it is further, the visibility is estimated using the Chebyshev inequality bound, resulting in a value between 0 and 1.

6.  **Composite Final Color**:
    Combine the visibility with the direct illumination and other lighting components. The final rendering for ray $\mathbf{r}$ is:
    $$ I(\mathbf{r}) = I_d(\mathbf{r}) + I_s(\mathbf{r}) + V(\mathbf{r})\mathcal{R}(\mathbf{r})S_{SG}(\mathbf{r}) $$
    Where $I_d$ is diffuse, $I_s$ is specular, $\mathcal{R}$ is reflectance, and $S_{SG}$ is the shadow term from the neural scene graph or similar component [S1].

### Pseudocode

```python
def variance_shadow_mapping_neRF(camera_depth_map, camera_intrinsics, light_camera_intrinsics, 
                                 light_camera_extrinsics, point_3d, filter_size):
    """
    Computes shadow visibility for a 3D point using Variance Shadow Mapping for NeRFs.
    
    Args:
        camera_depth_map: 2D array, depth from primary camera view.
        camera_intrinsics: Camera matrix for primary view.
        light_camera_intrinsics: Camera matrix for light view.
        light_camera_extrinsics: Extrinsics for light view.
        point_3d: 3D coordinates (x, y, z) of the surface point to shadow test.
        filter_size: Integer, size of the box filter kernel (e.g., 5).
        
    Returns:
        V: Float, visibility factor in [0, 1].
    """
    
    # Step 1: Get depth of the point from the light's perspective
    # Transform point_3d to light camera coordinates
    point_light_coords = transform_to_light_view(point_3d, light_camera_extrinsics)
    z_point = point_light_coords[2] # Depth along light ray
    
    # Step 2: Render/Retrieve Light View Depth Maps
    # In practice, these are pre-rendered or cached.
    # X: Depth map from light view
    # X2: Squared depth map from light view
    X = get_light_depth_map() 
    X2 = get_light_squared_depth_map()
    
    # Step 3: Box Filtering
    # Calculate mean of X and X2 over the filter neighborhood
    # Let r_l be the pixel coordinate in light view corresponding to point_3d
    r_l = project_to_light_view(point_3d, light_camera_intrinsics, light_camera_extrinsics)
    
    mu_X = box_filter(X, r_l, filter_size)
    mu_X2 = box_filter(X2, r_l, filter_size)
    
    # Step 4: Calculate Variance
    sigma_sq = mu_X2 - (mu_X ** 2)
    
    # Step 5: Calculate Visibility
    if z_point <= mu_X:
        V = 1.0
    else:
        # Chebyshev inequality bound
        # Avoid division by zero if sigma_sq is very small
        if sigma_sq < 1e-6:
            V = 0.0 # Or handle as fully occluded if depth is significantly larger
        else:
            V = sigma_sq / (sigma_sq + (z_point - mu_X)**2)
            
    return V

def box_filter(image, center_pixel, kernel_size):
    """
    Applies a uniform box filter to an image at center_pixel.
    """
    h, w = image.shape
    ky, kx = kernel_size // 2, kernel_size // 2
    cy, cx = center_pixel
    
    y_min = max(0, cy - ky)
    y_max = min(h, cy + ky + 1)
    x_min = max(0, cx - kx)
    x_max = min(w, cx + kx + 1)
    
    region = image[y_min:y_max, x_min:x_max]
    return np.mean(region)
```

### Parameters and Edge Cases
*   **Filter Size**: Controls shadow softness. Larger kernels produce softer shadows but may introduce "bleeding" artifacts where shadows leak into unoccluded areas. Not given in the sources.
*   **Precision**: The variance calculation $\mu(X^2) - \mu(X)^2$ is prone to numerical instability if the depth values are large and the variance is small. [G] Clamp $\sigma^2$ to be non-negative ($\max(0, \sigma^2)$) to prevent NaNs or invalid visibility values.
*   **Depth Boundaries**: If the point is outside the light camera's frustum, visibility is undefined or should be handled as fully lit/occluded based on scene context. Not given in the sources.
*   **Degenerate Input**: If the light view depth map is empty or invalid, the method fails. [G] Check for valid depth values before filtering.

## Operating characteristics
*   **Time Complexity**: Dominated by the rendering of two depth maps (light view) and the box filtering. The visibility lookup is $O(1)$ per pixel after preprocessing. This is significantly faster than ray-marching shadow rays, which is $O(N)$ per pixel where $N$ is the number of samples.
*   **Memory Complexity**: Requires storing two additional depth maps ($X$ and $X^2$) at the resolution of the light camera. Memory usage is $2 \times H \times W \times \text{bytes\_per\_pixel}$.
*   **Strengths**: Produces soft shadows efficiently without iterative ray marching. Integrates well with NeRF rendering pipelines that already generate depth maps.
*   **Limitations**: Shadows are an approximation based on depth statistics. Can suffer from shadow acne or bleeding if the filter size is not tuned correctly. Relies on the accuracy of the NeRF's depth estimation.
*   **When to Use**: When soft shadows are desired and computational efficiency is critical, and the scene geometry is well-represented by the NeRF's depth maps.
*   **When Not to Use**: When precise hard shadows are required, or when the NeRF's depth map is noisy/inaccurate, leading to poor variance estimates.

## Background
This method was proposed in the context of relighting scenes with object insertions in Neural Radiance Fields. It adapts the variance shadow mapping technique from traditional computer graphics [14] (referenced in [S1]) to the implicit representation of NeRFs. The key insight is that NeRFs can provide depth information, allowing the use of depth-based shadowing techniques without explicit mesh extraction. The method avoids the cumulative transmittance calculation typical of volumetric shadowing, offering a more efficient alternative for local illumination.
