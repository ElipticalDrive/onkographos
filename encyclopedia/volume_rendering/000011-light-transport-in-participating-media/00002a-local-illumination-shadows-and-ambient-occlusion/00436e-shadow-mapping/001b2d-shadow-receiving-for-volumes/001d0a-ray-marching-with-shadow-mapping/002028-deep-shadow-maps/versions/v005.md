# Deep Shadow Maps

Also called: DOM, Deep Opacity Maps, Deep Shadow Mapping, Deep shadow maps with ray casting, Opacity shadow maps, Ropinski et al

## Overview
Deep Shadow Maps is a shadow mapping technique for volume rendering that stores a curve of volume density (or accumulated alpha) as a function of distance in each pixel, rather than just the depth to the nearest opaque object [S1, unofficial][S2]. This allows for the correct computation of shadows cast by complex, semi-transparent structures, which standard shadow maps cannot handle [S2]. It differs from its sibling [Ray Marching with Shadow Mapping](1415-ray-marching-with-shadow-mapping.md) by using a pre-computed, hierarchical texture stack to approximate the shadow function, offering a more compact representation than storing full alpha values per layer as in [Shadow Volume Rendering](1556-shadow-volume-rendering.md) [S2].

## How it works
**Inputs:**
*   Volume dataset (density/opacity field) [G].
*   Light source position and type (directional or point, located outside the volume) [S2].
*   Error threshold parameter $\epsilon$ controlling approximation precision [S2].

**Outputs:**
*   A deep shadow map: a stack of $L$ textures (where $L \le L_{max}$), where each pixel $(u, v)$ contains a sequence of segments describing the accumulated alpha (absorption) along the ray from the light source through the volume [S2].
*   Shadowed illumination contribution for the volume rendering pass [S2].

**Data Structures:**
The deep shadow map is stored as a stack of 2D textures [S2]. Each texture layer $l$ stores two values per pixel:
1.  $d_l$: The distance from the light source to the start of the linear segment.
2.  $\alpha_l$: The accumulated alpha (absorption) value at distance $d_l$.

The segments are stored sequentially. If a pixel requires $k$ segments, the first $k$ layers of the texture stack contain the data. The structure effectively stores a piecewise linear approximation of the alpha function $\alpha(d)$, where $d$ is the distance from the light [S2].

**Algorithm Steps:**

1.  Compute a shadow map per light source [S1, unofficial][S2].
2.  For each pixel in the light's view, compute the first hit point for the shadow ray, similar to standard shadow mapping [S2].
3.  Store the distance to the light source and the alpha value (initially zero) for the first hit position in the first layer of the deep shadow map [S2].
4.  Traverse the volume along the shadow ray, sampling at discrete intervals [S2].
5.  At each sample, check if the accumulated alpha function can be approximated by a linear segment from the last stored breakpoint within the error threshold $\epsilon$ [S2]. The error constraint is enforced by adding or subtracting $\epsilon$ at each sample's position to bound the variance of the linear approximation [S2].
6.  If the alpha function exceeds the range defined by the error threshold, store the distance of the previous sample to the light source and the accumulated alpha value at the previous sample in the next layer of the deep shadow map [S2].
7.  Start a new linear segment approximation from the previous sample to the current sample [S2].
8.  Repeat steps 4–7 until the ray exits the volume or all layers of the deep shadow map have been created [S2].
9.  Use the resulting shadowing information to diminish diffuse reflectance $L_{diff}$ in gradient-based shading or directly modulate emissive contribution $L_e$ at position $\tilde{x}$ [S2].

**Pseudocode:**

```python
def generate_deep_shadow_map(width, height, step_size, epsilon, max_layers):
    # Initialize stack of textures. Each layer is a 2D grid of (distance, alpha) tuples.
    layers = [[[(0.0, 0.0) for _ in range(height)] for _ in range(width)] for _ in range(max_layers)]
    
    for u in range(width):
        for v in range(height):
            current_dist = 0.0
            accumulated_alpha = 0.0
            layer_idx = 0
            
            # Step 2 & 3: Compute first hit point and store in first layer
            layers[layer_idx][u][v] = (current_dist, accumulated_alpha)
            seg_start_dist = current_dist
            seg_start_alpha = accumulated_alpha
            
            while current_dist < 100.0: # Ray traversal limit
                current_dist += step_size
                density = volume.sample(u, v, current_dist)
                accumulated_alpha += density * step_size
                
                # Step 5: Check approximation error
                # Linear interpolation between segment start and current point
                if current_dist != seg_start_dist:
                    alpha_linear = seg_start_alpha + (accumulated_alpha - seg_start_alpha) * (current_dist - seg_start_dist) / (current_dist - seg_start_dist)
                    # Evidence: error threshold constrains variance by adding/subtracting error at each sample
                    if abs(accumulated_alpha - alpha_linear) > epsilon:
                        # Step 6: Store previous sample in next layer
                        layer_idx += 1
                        if layer_idx >= max_layers:
                            break
                        layers[layer_idx][u][v] = (seg_start_dist, seg_start_alpha)
                        # Step 7: Start new segment
                        seg_start_dist = seg_start_dist
                        seg_start_alpha = seg_start_alpha
                        continue
                # Step 4: Continue traversal
                pass
            if layer_idx < max_layers:
                layers[layer_idx][u][v] = (current_dist, accumulated_alpha)
    return layers
```

**Rendering Usage:**
During the volume rendering pass, for each sample point $\tilde{x}$ along the view ray, the corresponding shadow ray is cast to the light [S2]. The deep shadow map is sampled to retrieve the relevant segment [S2]. The accumulated alpha $\alpha(d)$ is computed by linear interpolation between the breakpoints stored in the deep shadow map [S2]. This alpha value is used to modulate the light contribution:
*   Diminish diffuse reflectance $L_{diff}$ in gradient-based shading [S2].
*   Directly modulate emissive contribution $L_e$ at position $\tilde{x}$ [S2].

**Edge Cases and Pitfalls:**
*   **Thin Opaque Occluders:** Thin structures may appear transparent in shadows because the alpha function approximation diminishes over too long depth intervals [S2].
*   **Error Threshold:** A too small error threshold results in a too close approximation, requiring more layers to represent the shadow function, increasing memory usage and rendering complexity [S2].
*   **Single Light Source:** Due to unidirectional shadow propagation, only a single light source is supported [S2].
*   **Light Position:** Light sources should be located outside the volume [S2].

## Subtopics

### Cascaded Deep Opacity Maps
A variant of deep opacity maps using a series of cuboids covering different splits of the view frustum, similar to cascaded shadow maps, to handle varying distances [S3, unofficial]. This helps manage the trade-off between resolution and coverage for large volumes or clouds [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** The generation of the deep shadow map is interactive, proportional to the number of samples along shadow rays and the number of layers [S2]. Rendering time is also interactive [S2].
*   **Memory Complexity:** The memory footprint is directly proportional to the number of used layers $L$ and the resolution of the shadow map [S2].
*   **Strengths:** Supports semi-transparent occluders, which standard shadow maps do not [S2]. More compact than storing full alpha values per layer (opacity shadow maps) [S2].
*   **Limitations:** Introduces artifacts with thin structures due to approximation [S2]. Supports only a single light source [S2]. Requires re-computation when lighting or transfer function changes [S2].
*   **When to Use:** When semi-transparent shadows are needed and the scene has a single dominant light source. Suitable for interactive volume rendering where performance is critical [S2].
*   **When Not to Use:** When multiple light sources are required, or when high fidelity for thin structures is necessary [S2].

## Background
Deep Shadow Maps were developed in 2000 by Tom Lokovic and Eric Veach from Pixar [S1, unofficial][S2]. The technique was first applied to volume rendering by Hadwiger et al. [HKSB06] and Ropinski et al. [RKH08] [S2]. It is historically significant as an early method for handling semi-transparent shadows in volume rendering, though it has been largely superseded by more modern techniques [S1, unofficial].
