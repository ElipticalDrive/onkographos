# Shadow Mapping for Volumes

Also called: Image-based shadow algorithms

## Overview
Shadow Mapping for Volumes adapts standard image-based shadow mapping to participate in light transport within volumetric data [G]. It solves the problem of determining whether a sample point along a view ray is occluded by the volume itself when viewed from a light source [G]. Unlike methods that compute exact volumetric occlusion integrals, this approach provides a binary shadow decision based on depth comparisons, prioritizing rendering speed over physically accurate attenuation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric dataset, light source position and direction (for directional lights) or position (for point lights), and transfer function [G].
*   **Output:** A shadow map texture and the final rendered volume with shadowed regions [G].

**Data Structures:**
1.  **Standard Shadow Map:** A 2D texture storing depth values [S1, unofficial]. Each texel stores the distance from the light source to the first hit point along the light ray [G].
2.  **Alpha Shadow Map:** A 2D texture storing multiple layers [S1, unofficial]. Each layer is a pair of depth and transparency [S1, unofficial]. Control points for piecewise linear functions are saved per pixel to reconstruct the attenuation profile [S1, unofficial].

**Steps:**
1.  **Shadow Map Construction (Preprocessing):**
    *   Render the volume from the light source's perspective [G].
    *   For each pixel in the light-space image, trace a ray through the volume [G].
    *   Identify the first hit point (entry point) of the ray into the volume [G].
    *   **Standard:** Store the depth value $d$ of this first hit point in the shadow map [S1, unofficial].
    *   **Alpha Shadow Maps:** Save the first key value (depth and transparency) at the first hit point [S1, unofficial]. Evaluate an error function to determine if further sampling is needed [S1, unofficial]. If the error exceeds a threshold, save further key values to approximate the piecewise linear function of the volume's opacity profile [S1, unofficial].
2.  **Rendering (Shadow Lookup):**
    *   For each sample point $P$ along the view ray during volume raycasting:
    *   Project $P$ into light space to obtain coordinates $(u, v)$ [G].
    *   Retrieve the depth value $d_{\text{shadow}}$ from the shadow map at $(u, v)$ [G].
    *   Compute the distance $d_{\text{sample}}$ from the light source to $P$ [G].
    *   **Binary Decision:** Compare $d_{\text{sample}}$ with $d_{\text{shadow}}$ [S1, unofficial].
    *   Apply a **shadow threshold** to mark the intensity limit [S1, unofficial].
    *   **Filtering:** Apply filtering to the shadow map to reduce artifacts [S1, unofficial].

**Formulas:**
*   Depth comparison: $d_{\text{sample}} > d_{\text{shadow}}$ indicates the sample point is occluded (in shadow); $d_{\text{sample}} \le d_{\text{shadow}}$ indicates it is lit [S1, unofficial].

**Parameters:**
*   Error thresholds for Alpha Shadow Map construction: $0.01$ and $0.00005$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   Standard shadow maps only support opaque occluders [S1, unofficial].
*   The shadow map needs to be recomputed on light source or transfer function change [S1, unofficial].
*   Not given in the sources.

## Subtopics

### Alpha Shadow Maps
A variant of shadow mapping that supports semi-transparent occluders [S1, unofficial]. It differs from standard shadow mapping by incorporating multiple layers of depth and transparency for each pixel [S1, unofficial]. Instead of a single depth value, it saves control points of piecewise linear functions that approximate the volume's attenuation profile along the light ray [S1, unofficial]. This allows for more accurate shadowing in translucent volumes [G]. Choose this when visual fidelity of shadows in semi-transparent media is required, accepting higher memory and preprocessing costs [G]. Error values of $0.01$ and $0.00005$ are cited as typical thresholds for determining the granularity of these control points [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Not given in the sources.
*   **Strengths:** Fast, simple to implement, decouples shadow calculation from the main raycasting loop [G].
*   **Limitations:** Binary shadowing in standard form does not account for volumetric attenuation; requires recomputation on light source or transfer function change [S1, unofficial].

## Background
The technique was developed by Timo Ropinski (University of Münster) and others (Markus Hadwiger, Patric Ljung, Christof Rezk Salama) as part of advanced illumination techniques for GPU-based volume raycasting [S1, unofficial]. It was presented in the thesis "Advanced Illumination Techniques for GPU-Based Volume Raycasting" in 2008 [S1, unofficial].
