# Half-Angle Slicing for Incremental Lighting

Also called: Two-Pass Volumetric Shadow Setup, Image Space Shadow Attenuation, Pixel Buffer Shadowing, Render to Texture Shadowing

## Overview
Half-Angle Slicing for Incremental Lighting is a multipass technique that computes volumetric shadows by accumulating light attenuation in an off-screen pixel buffer, thereby avoiding the memory overhead and leakage artifacts associated with volumetric shadow maps [S1, S2]. It differs from its parent method, [Volume Shadow Calculation via Light Strength Buffer](1914-volume-shadow-calculation-via-light-strength-buffer.md), by decoupling the light transport sampling from the data volume resolution and using a single 2D buffer instead of a 3D volume [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Volume dataset, transfer function (color $C$, opacity $A$), light color $C_L$, observer view direction, light view direction, frame buffer resolution [S1, S2].
*   **Output:** Final image with volumetric shadows in the eye buffer [S1, S2].

**Data Structures:**
1.  **Eye Buffer:** Standard frame buffer storing the final composited color [S2].
2.  **Light Buffer:** Off-screen render buffer (pixel buffer) or texture storing accumulated light intensity [S1, S2].
    *   **Layout:** 2D texture/buffer [S1].
    *   **Initialization:** Cleared to light color $C_L$ or an arbitrary image for spotlights [S1, S2].
    *   **Resolution:** 30–50% higher than frame buffer resolution to mitigate shadow boundary artifacts [S1].

**Parameters:**
*   $d_v$: Desired sampling distance along observer view direction [S2].
*   $\theta$: Angle between observer and light view directions [S2].
*   $d_s$: Slice spacing to maintain constant sampling rate [S2].

**Formulas:**
The slice spacing $d_s$ is determined by the angle $\theta$ between the view and light directions [S1, S2]:
$$ d_s = d_v \cos\left(\frac{\theta}{2}\right) $$

**Algorithm Steps:**
1.  **Initialize Buffers:** Clear the eye buffer and initialize the light buffer to $C_L$ [S2].
2.  **Determine Slice Axis:** Compute dot product of light direction $L$ and view direction $V$ [S2]. If $L \cdot V > 0$, set slice axis halfway between $L$ and $V$, render eye front-to-back with Under operator [S2]. If $L \cdot V \le 0$, set slice axis halfway between $L$ and $-V$, render eye back-to-front with Over operator [S2]. In both cases, render light front-to-back with Over operator [S2].
3.  **Iterate Slices:** For each slice along axis with spacing $d_s$:
    *   **Pass 1 (Eye Rendering):** Render slice to eye buffer [S2]. Bind light buffer as texture [S2]. In fragment shader, evaluate TF for $C$ and $A$ [S2]. Sample light buffer for $C_L$ [S2]. Compute $C_{final} = C \times C_L$ [S2]. Blend $C_{final}$ and $A$ into eye buffer using operator from step 2 [S2].
    *   **Pass 2 (Light Buffer Update):** Render slice to light buffer [S2]. In fragment shader, evaluate TF for $A$ [S2]. Set fragment color to 0 [S2]. Blend into light buffer using Over operator to accumulate opacity [S1, S2].

**Pseudocode:**
```python
import math

def dot(a, b):
    return sum(x * y for x, y in zip(a, b))

def normalize(v):
    mag = math.sqrt(sum(x * x for x in v))
    return [x / mag for x in v] if mag > 0 else v

def over_blend(src_c, src_a, dst_c, dst_a):
    out_a = src_a + dst_a * (1.0 - src_a)
    out_c = (src_c * src_a + dst_c * dst_a * (1.0 - src_a)) / out_a if out_a > 0 else dst_c
    return out_c, out_a

def under_blend(src_c, src_a, dst_c, dst_a):
    out_a = src_a + dst_a * (1.0 - src_a)
    out_c = (src_c * src_a * (1.0 - dst_a) + dst_c * dst_a) / out_a if out_a > 0 else dst_c
    return out_c, out_a

def half_angle_slicing(volume_data, transfer_fn, light_color, view_dir, light_dir, dv):
    # 1. Initialize buffers
    eye_buffer = {'color': [0.0, 0.0, 0.0], 'alpha': 0.0}
    light_buffer = {'color': list(light_color), 'alpha': 0.0}

    # 2. Determine slice axis and blending operator
    dot_product = dot(light_dir, view_dir)
    if dot_product > 0:
        slice_axis = normalize([light_dir[i] + view_dir[i] for i in range(3)])
        eye_blend = under_blend
    else:
        slice_axis = normalize([light_dir[i] - view_dir[i] for i in range(3)])
        eye_blend = over_blend

    theta = math.acos(dot(normalize(view_dir), normalize(light_dir)))
    ds = dv * math.cos(theta / 2.0)

    # 3. Render slices
    num_slices = compute_num_slices(volume_data, slice_axis, ds)
    for i in range(num_slices):
        slice_vertices = get_slice_geometry(volume_data, slice_axis, i * ds)
        light_tex_coords = project_to_light_buffer(slice_vertices)

        # Pass 1: Eye Buffer
        for frag in slice_vertices:
            vol_val = sample_volume(volume_data, frag.pos)
            C, A = transfer_fn(vol_val)
            C_L = light_buffer['color']
            final_color = [C[j] * C_L[j] for j in range(3)]
            eye_buffer['color'], eye_buffer['alpha'] = eye_blend(final_color, A, eye_buffer['color'], eye_buffer['alpha'])

        # Pass 2: Light Buffer
        for frag in slice_vertices:
            vol_val = sample_volume(volume_data, frag.pos)
            A = transfer_fn(vol_val).alpha
            light_buffer['color'], light_buffer['alpha'] = over_blend([0.0, 0.0, 0.0], A, light_buffer['color'], light_buffer['alpha'])

    return eye_buffer
```

**Edge Cases and Pitfalls:**
*   **Attenuation Leakage:** When view and light directions are perpendicular, naive 2D shadow buffers suffer from attenuation leakage where light intensity is stored at coarse resolution and interpolated, causing blurry shadows and overly dark surfaces [S1]. Using a light buffer with 30–50% higher resolution than the frame buffer mitigates this [S1].
*   **Sharp Opacity Jumps:** Artifacts may appear at shadow boundaries if opacity jumps sharply from low to high due to image-space sampling [S1].
*   **Angle Dependency:** As the angle between observer and light changes, $d_s$ must be adjusted to maintain the constant sampling rate $d_v$ [S2].

## Subtopics

### Volumetric Shadow Maps
Pre-computed 3D textures storing shadow information [S1]. They are memory-intensive and suffer from interpolation artifacts compared to the image-space approach of Half-Angle Slicing [S1, S2].

### Shear Warp Rendering
A technique that slices along major volume axes [S1]. It is limited in the maximum angle between view and light directions it can handle effectively without reslicing artifacts [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of slices and the resolution of the buffers [S1, S2]. Each slice requires two rendering passes (eye and light buffer) [S1, S2].
*   **Memory Complexity:** $O(W \times H)$ for the light buffer, where $W, H$ are the buffer dimensions [S1]. This is significantly less memory than the volumetric shadow maps [S1].
*   **Performance:** Efficient for interactive rendering as it decouples light transport sampling from the data volume resolution [S1].
*   **Strengths:** Avoids volumetric shadow map artifacts; efficient memory usage; supports arbitrary view and light directions via the half-angle slice axis [S1, S2].
*   **Limitations:** Does not account for light scattering within the volume (translucency), resulting in dark/unrealistic images if scattering is significant [S2]. Sensitive to resolution mismatches between light buffer and frame buffer [S1].

## Background
The technique was introduced by Kniss et al. in 2003 as an improvement over volumetric shadow maps for interactive volume rendering [S2]. It utilizes an off-screen render buffer (pixel buffer) to accumulate light attenuation from the light's point of view, allowing the same slice to be rendered from both the eye and light points of view by modifying the slice axis to be halfway between the view and light directions [S1, S2].
