# Inject Direct Lighting Pass

## Overview
The Inject Direct Lighting Pass populates a voxelized scene's octree data structure with direct illumination data to enable subsequent global illumination calculations like voxel cone tracing [S1, unofficial]. It transfers light transport information from a rasterized shadow map into a 3D volumetric representation by reconstructing world positions from shadow map texels and traversing the octree [S1, unofficial]. It differs from its sibling, the [Light Injection Pass](2759-light-injection-pass.md), which operates in the GPU fragment stage using camera-space ray traversal and A-Buffer visibility; this pass operates in world space by traversing an octree from shadow map texels [S1, unofficial][Parent].

## How it works
**Inputs:**
- A voxelized scene represented as an octree data structure, stored in 3D texture bricks [S1, unofficial].
- A shadow map rendered from the light's point of view [S1, unofficial].
- Light direction and position [S1, unofficial].

**Outputs:**
- Updated 3D texture bricks containing reflected radiance values at leaf nodes [S1, unofficial].

**Data Structures:**
- **Octree:** Hierarchical structure where leaf nodes correspond to voxels. Each leaf stores radiance data [S1, unofficial].
- **Shadow Map:** 2D texture storing depth information from the light's perspective [S1, unofficial].

**Steps:**
1. **Render Shadow Map:** Render the scene from the light's point of view to generate a shadow map [S1, unofficial].
2. **Iterate Shadow Map Texels:** For each pixel (texel) in the shadow map:
   a. **Reconstruct World Position:** Convert the shadow map texel coordinates and depth value back into world-space coordinates [S1, unofficial].
   b. **Traverse Octree:** Traverse the octree data structure to locate the voxel(s) corresponding to the reconstructed world position [S1, unofficial].
   c. **Calculate Reflected Radiance:** Compute the direct lighting contribution. The method assumes the surface reflects diffusely [S1, unofficial].
   d. **Write to Bricks:** Write the calculated radiance value into the 3D texture bricks associated with the leaf nodes of the octree [S1, unofficial].

**Parameters:**
- **Cascade Shadow Map:** Uses a cascade shadow map with 4 cascades. The last cascade is specifically used for the light injection pass [S1, unofficial].
- **Slope Scale Depth Bias:** Disabled. This ensures that the reconstructed world position is exactly inside the voxel, preventing misalignment artifacts [S1, unofficial].

**Pitfalls and Edge Cases:**
- **Shadow Map Instability:** If the shadow map moves relative to the scene (e.g., due to camera movement), it causes flickering during the subsequent cone tracing step. Stabilization is required, such as computing the directional light position from the view camera [S1, unofficial].
- **Unfilled Voxels:** Stabilizing the shadow map may result in some voxels remaining unfilled with lighting data if the shadow map resolution is low or not fully utilized [S1, unofficial].
- **Resolution Artifacts:** Low shadow map resolution leads to incomplete light injection. Launching one thread per shadow map texel means only voxels aligned with texel centers receive light. For example, in a vertical column of 5 voxels, a low-resolution shadow map might only inject light into 3 of them, leaving gaps [S1, unofficial].

**Pseudocode:**
```python
def inject_direct_lighting(octree, shadow_map, light_direction, light_view_matrix, light_proj_matrix):
    # Step 1: Shadow map is assumed to be already rendered from the light's point of view [S1, unofficial]
    
    # Step 2: Iterate over shadow map texels
    for y in range(shadow_map.height):
        for x in range(shadow_map.width):
            depth = shadow_map.sample(x, y)
            
            # Reconstruct world position from shadow map texel coordinates and depth
            clip_ndc = vec4(x / shadow_map.width * 2.0 - 1.0, y / shadow_map.height * 2.0 - 1.0, depth * 2.0 - 1.0, 1.0)
            view_ray = inverse(light_proj_matrix) @ clip_ndc
            view_ray = view_ray / view_ray.w
            world_pos = inverse(light_view_matrix) @ view_ray
            
            # Traverse octree to find leaf node at world_pos
            leaf = octree.traverse(world_pos)
            
            if leaf is not None:
                # Calculate reflected radiance assuming diffuse reflection [S1, unofficial]
                # [G] Standard diffuse direct lighting calculation
                radiance = max(0.0, dot(light_direction, leaf.normal)) * leaf.albedo
                
                # Write radiance to 3D texture brick [S1, unofficial]
                leaf.write_radiance(radiance)
```

## Subtopics

### DVR Volume Lighting Pass
A pass that updates volumetric light maps for Volume raycasters with Direct Volume Rendering (DVR) enabled, participating in the VOLUMETRIC_SHADOW_MAPPING render pass [S2]. It calls `MActor::render()` for all actors using the VOLUMETRIC_SHADOW_MAPPING render pass [S2]. Raycasters update their volumetric light maps only when required and when volumetric lighting is enabled [S2]. Because updating DVR light maps is expensive, updates are performed only when necessary to optimize performance [S2].

## Operating characteristics
- **Time Complexity:** Proportional to the number of shadow map texels, as one thread is launched per texel to determine voxel injection [S1, unofficial].
- **Memory Complexity:** Requires storage for the shadow map and the 3D texture bricks [S1, unofficial].
- **Strengths:** Directly injects lighting into the voxel structure for subsequent global illumination passes like cone tracing [S1, unofficial].
- **Limitations:** Highly sensitive to shadow map resolution; low resolution causes visible gaps in lighting (unfilled voxels) [S1, unofficial]. Requires careful stabilization to avoid flickering during camera movement [S1, unofficial].
- **When to use:** When a voxelized scene is already available and direct lighting needs to be baked into the voxel structure for subsequent global illumination passes [S1, unofficial].
- **When not to use:** Not given in the sources.

## Background
This method is part of the Voxel Cone Tracing pipeline, specifically the step that injects direct lighting into the voxel data structure to calculate global illumination [S1, unofficial]. It was described in the context of implementing voxel cone tracing in a custom engine, utilizing cascade shadow maps and octree traversal [S1, unofficial].
