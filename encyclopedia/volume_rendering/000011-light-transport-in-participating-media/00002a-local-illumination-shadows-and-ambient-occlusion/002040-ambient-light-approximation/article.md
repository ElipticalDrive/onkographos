# Ambient Light Approximation

Also called: Ambient Lighting for Volume Clouds, Sky Ambient, Upwards Ray Approximation

## Overview
Ambient Light Approximation provides a computationally efficient method for simulating indirect sky illumination in participating media, specifically volumetric clouds, by integrating the sky hemisphere into a single upward-propagating light value [S1, unofficial]. Unlike full multiple-scattering solvers or complex spherical harmonic integrations, this method approximates the diffuse sky contribution using a single ray cast upwards from the sample point, weighted by local density and transmittance [S1, unofficial]. It distinguishes itself from siblings like [Lighting Models](2056-lighting-models.md) by explicitly handling the shadowing of ambient light through density integration, ensuring that deep or covered parts of a cloud receive less ambient fill than exposed edges [S1, unofficial].

## How it works
The method approximates the integral of incoming radiance from the sky hemisphere by assuming the majority of ambient light originates from directly above. It combines a pre-integrated sky color with a density-weighted attenuation factor derived from an upward ray.

**Inputs and Outputs**
*   **Inputs:**
    *   $\mathbf{p}$: Current sample position in the volume.
    *   $\rho(\mathbf{p})$: Volume density at $\mathbf{p}$.
    *   $\sigma_t$: Total extinction coefficient.
    *   $L_{sky}$: Pre-integrated ambient sky color (constant or sampled from a LUT).
    *   $Profile(\mathbf{p})$: A scalar representing the sample's position relative to the cloud boundary (e.g., distance to edge or normalized depth).
*   **Outputs:**
    *   $L_{ambient}$: The computed ambient radiance contribution for the current sample.

**Data Structures**
*   **Sky Light Value ($L_{sky}$):** A single RGB color vector. Sources indicate this can be a fixed color, a result of random sampling of the sky hemisphere, or spherical harmonics coefficients [S1, unofficial]. In engine implementations, it may be sampled from a `SkyLightLut` generated by atmospheric scattering routines [S2, unofficial]. If atmospheric scattering is disabled, it may be sampled from a baked Ambient Probe encoded with 3rd-order Spherical Harmonics [S2, unofficial].
*   **Ambient Density Map (Optional):** For static grids, the summed density of the upward ray can be precalculated and stored in a lower-resolution 3D texture or grid, leveraging the natural blurriness of ambient data [S1, unofficial].

**Numbered Steps**
1.  **Integrate Sky Hemisphere:** Compute or retrieve the single representative ambient sky color $L_{sky}$. This can be done via random sampling, spherical harmonics, or a fixed artistic color choice [S1, unofficial].
2.  **Cast Upward Ray:** From the current sample position $\mathbf{p}$, cast a ray in the upward direction (typically the world up vector $\mathbf{y}$).
3.  **Compute Upward Transmittance:** Calculate the optical depth $\tau_{up}$ along this upward ray by integrating the extinction coefficient $\sigma_t$ from $\mathbf{p}$ to the top of the atmosphere or cloud boundary. The transmittance is $T_{up} = e^{-\tau_{up}}$.
    *   *Implementation Note:* If a precalculated Ambient Density Map is used, this step is a texture lookup of the stored summed density [S1, unofficial].
4.  **Apply Edge Weighting:** Determine a weighting factor based on the sample's position within the cloud, often using a "profile" function. This ensures edges receive more ambient light than the center. A common form is $\sqrt{Profile(\mathbf{p})}$ or a remapped distance field to the cloud edge [S1, unofficial].
5.  **Calculate Ambient Contribution:** Combine the sky color, upward transmittance, and edge weighting.
    $$ L_{ambient} = L_{sky} \cdot T_{up} \cdot \sqrt{Profile(\mathbf{p})} $$
    *   *Variants:* Some implementations multiply by density $\sigma_s$ and step size $dt$ during the final accumulation loop rather than at this stage [S1, unofficial].
6.  **Accumulate:** Add $L_{ambient}$ to the total scattered light, scaled by the current sample's transmittance, density, and step size, consistent with the standard volumetric integration loop [S1, unofficial].

```python
def compute_ambient_light(sample_position, profile_value, sky_light_color, ambient_density_map=None):
    """
    Computes ambient light contribution for a volume sample.
    
    Args:
        sample_position: 3D vector, current position in volume.
        profile_value: float, normalized distance to cloud edge or depth profile (0 to 1).
        sky_light_color: vec3, pre-integrated sky ambient color.
        ambient_density_map: 3D texture, optional precalculated upward density.
        
    Returns:
        vec3, ambient radiance contribution.
    """
    # Step 1 & 2: Retrieve sky light and determine upward direction
    # sky_light_color is assumed pre-computed [S1, unofficial]
    # upward direction is typically world up (0, 1, 0)
    
    # Step 3: Compute upward transmittance
    if ambient_density_map is not None:
        # Use precalculated density from lower-res grid [S1, unofficial]
        summed_density = ambient_density_map.sample(sample_position)
    else:
        # Perform upward ray march if not precalculated
        # Integrate sigma_t from sample_position upwards
        summed_density = ray_march_upwards(sample_position)
        
    upward_transmittance = exp(-summed_density)
    
    # Step 4: Apply edge weighting
    # Using square root of profile to soften falloff at edges [S1, unofficial]
    edge_weight = sqrt(saturate(profile_value))
    
    # Step 5: Calculate final ambient contribution
    ambient_light = sky_light_color * upward_transmittance * edge_weight
    
    return ambient_light

def accumulate_ambient_in_loop(sample_position, sample_density, step_size, transmittance_to_sample, profile_value, sky_light_color, ambient_density_map):
    """
    Called within the main ray-marching loop to add ambient contribution.
    """
    # Compute ambient light for current sample
    L_ambient = compute_ambient_light(sample_position, profile_value, sky_light_color, ambient_density_map)
    
    # Weight by current sample properties and add to total
    # Formula: L_ambient * transmittance * density * step_size [S1, unofficial]
    contribution = L_ambient * transmittance_to_sample * sample_density * step_size
    
    return contribution
```

**Parameters and Typical Values**
*   **Profile Exponent:** The power applied to the profile value (e.g., 0.5 for square root) controls how quickly ambient light falls off towards the cloud center [S1, unofficial].
*   **Saturation Correction:** An artist parameter to adjust the saturation of $L_{sky}$ to counteract the overly blue tint caused by ignoring multiple scattering [S2, unofficial].

**Edge Cases and Pitfalls**
*   **Blue Tint:** Ignoring multiple scattering in the ambient approximation causes clouds to appear unnaturally blue, as the light is dominated by the direct sky color [S2, unofficial]. This is mitigated by saturation adjustment or more complex scattering models.
*   **Resolution:** Precalculating the upward ray density allows for lower-resolution storage due to the low-frequency nature of ambient light, but insufficient resolution may cause banding in smooth clouds [S1, unofficial].
*   **Dynamic Volumes:** Precalculated density maps are only valid for static grids. Dynamic volumes require real-time upward ray marching or updated probes [S1, unofficial].

## Subtopics

### Bruneton-style Sky Irradiance
An approach where the sky irradiance is precomputed in a table based on altitude and sun angle, providing sky light specific to each surface's local sky [S3, unofficial]. It ensures that ground seen from orbit retains its sky fill and terrain past the terminator is not incorrectly lit by the eye's daylight [S3, unofficial].
*   **Data Structure:** A sky irradiance table covering 16 altitudes by 24 sun cosines, storing 6 symmetric L2 harmonics per entry in the local frame [S3, unofficial]. Published as a uniform `atmosphere_sky_table` [S3, unofficial].
*   **Usage:** Deferred lighting looks up each pixel's altitude and sun angle from this table to determine ambient illumination [S3, unofficial].
*   **Performance:** Reported cost of 0.60 ms for the `DeferredLight` pass [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample if using a precalculated density map or LUT; $O(N)$ per sample if performing a real-time upward ray march, where $N$ is the number of steps in the upward direction.
*   **Memory Complexity:** $O(1)$ for the sky color parameter. $O(V)$ for a precalculated ambient density map, where $V$ is the volume of the grid (typically lower resolution than the main volume).
*   **Strengths:** Extremely fast; adds significant visual realism by preventing shadowed undersides from becoming pitch black; easy to integrate into existing ray-marching loops [S1, unofficial].
*   **Limitations:** Does not account for multiple scattering, leading to color inaccuracies (blue tint) [S2, unofficial]; assumes sky light comes primarily from above, which may fail for ground-based scenes with strong ground reflection [S1, unofficial].
*   **When to Use:** Real-time rendering of volumetric clouds where performance is critical and full multiple-scattering solvers are too expensive [S1, unofficial].
*   **When Not to Use:** Offline rendering requiring physical accuracy, or scenes where ground-reflected light is a dominant ambient source.

## Background
The method originates from practical real-time rendering techniques for volumetric clouds, popularized by blogs and engine implementations (e.g., UE4 atmospheric scattering) [S1, S2, unofficial]. It addresses the visual artifact of "black undersides" in clouds when only direct sunlight is considered. The Bruneton-style irradiance table variant is derived from Eric Bruneton's work on precomputed atmospheric scattering, adapted for voxel-based planet rendering [S3, unofficial].
