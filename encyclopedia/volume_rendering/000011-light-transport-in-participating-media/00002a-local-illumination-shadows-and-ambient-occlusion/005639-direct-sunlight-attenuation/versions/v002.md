# Direct Sunlight Attenuation

Also called: Light Attenuation Simulation, Sun Attenuation via Framebuffer Readback

## Overview
Direct Sunlight Attenuation simulates the reduction of solar intensity as light passes through a participating medium, typically using precomputed ray templates or eye-buffer transparency to determine voxel brightness [S1, unofficial][S2]. It builds on [Local illumination, shadows and ambient occlusion](34-local-illumination-shadows-and-ambient-occlusion.md) by decoupling the direct light contribution into a separate pass that attenuates a distant light source based on integrated density, rather than computing scattering events along the view ray [S2].

## How it works
**Inputs:**
- A 3D volume grid of density values $\rho$ [S1, unofficial].
- A light direction vector $\mathbf{l}$ (typically the sun) [S2].
- A view direction vector $\mathbf{v}$ [S2].
- Parameters: `DECAY` (absorption coefficient), `AMBIENT` (minimum light floor), `n` (grid dimension) [S1, unofficial][S3, unofficial].

**Outputs:**
- Attenuated light intensity $l$ for each voxel or pixel [S1, unofficial][S2].
- A final shaded color incorporating the direct sunlight term [S3, unofficial].

**Data Structures:**
- **Density Grid:** A 3D array of floats, indexed linearly as `offset = ((xx * n) + yy) * n + zz` [S1, unofficial]. Implementation may require index reversal depending on texture generation versus simulation coordinate systems [S1, unofficial].
- **Intensity Buffer:** An 8-bit unsigned char array (`unsigned char* intensity`) storing accumulated light levels [S1, unofficial].
- **Ray Template:** A precomputed array of 3D offsets (`_rayTemplate[i][0..2]`) defining the path from a source point into the volume [S1, unofficial].

**Steps:**
1. Determine start indices $sx, sy, sz$ based on the light direction [S1, unofficial].
2. Compute decay factor: $\text{decay} = \frac{1.0}{n \times \text{DECAY}}$ [S1, unofficial].
3. Loop over the 2D grid; for each non-zero light direction component, call `LightRay` [S1, unofficial].
4. `LightRay` iterates along the ray template, updating intensity and reducing light level $l$ by $\rho \times \text{decay}$ until $l$ reaches `AMBIENT` or volume bounds are exceeded [S1, unofficial].
5. In the distant light pass, store total volume transparency in the alpha channel of the eye buffer [S2].
6. Calculate the dot product of the view and light vectors; if the view vector is within the 0.5 degree disk of the sun, add the attenuated sunlight term [S2].
7. Alternatively, render each cell to the framebuffer and read the color to determine the amount of sunlight passed through clouds to the cell center, then use this transmitted light data to determine the cell color [S3, unofficial]. This approach properly handles two light sources (Sun and Sky) [S3, unofficial].

**Formulas:**
- Light level update: $l_{\text{new}} = \max(\text{AMBIENT}, l_{\text{old}} - \rho \times \text{decay})$ [S1, unofficial].
- Intensity accumulation: $\text{intensity}[\text{offset}] = \lfloor (\text{intensity}[\text{offset}] + l_{\text{new}}) / 2 \rfloor$ when non-zero, else $l_{\text{new}}$ [S1, unofficial].

**Parameters:**
- `DECAY`: 0.06f (light absorption coefficient) [S1, unofficial].
- `AMBIENT`: 100 (minimum light level floor) [S1, unofficial].
- Sun disk threshold: 0.5 degrees [S2].

**Edge Cases and Pitfalls:**
- Intensity accumulation uses averaging, which halves the contribution of previous rays [S1, unofficial].
- Density lookup offset calculation must align with texture generation coordinate systems, as index reversal may occur [S1, unofficial].
- Using 8-bit integers for intensity limits dynamic range; floating-point buffers are recommended for high-dynamic-range scenes [G].

**Pseudocode:**
```python
def LightRay(x, y, z, n, decay, dens, intensity, ray_template, ambient):
    xx, yy, zz = x, y, z
    i = 0
    l = 200  # Initial light level [S1, unofficial]
    while 0 <= xx < n and 0 <= yy < n and 0 <= zz < n:
        offset = (xx * n + yy) * n + zz
        d = dens[offset] * 255.0
        if l > ambient:
            l = max(ambient, l - d * decay)
        if intensity[offset] > 0:
            intensity[offset] = int((intensity[offset] + l) * 0.5)
        else:
            intensity[offset] = int(l)
        i += 1
        xx = x + ray_template[i][0]
        yy = y + ray_template[i][1]
        zz = z + ray_template[i][2]
```

## Subtopics

### Shadow-View Slice Rendering
Divides volume data into shadow-view slices (SVS) to capture attenuation in both sunlight and viewing directions [S4]. Atmospheric density and attenuation ratio are stored as a single texture mapped to the SVS [S4]. Final intensity is obtained by blending the SVSs along the path of the viewpoint [S4].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Performance:** Implemented on early programmable hardware (e.g., GeForce FX) using fragment programs [S2]. Relies on framebuffer readback and alpha blending, which may introduce latency on modern graphics APIs [G]. Properly handles two light sources (Sun and Sky) [S3, unofficial].

## Background
The method originates from efficient rendering techniques for atmospheric phenomena, where direct sunlight is treated as a distant light source attenuated by the volume's total transparency [S2]. It was implemented on early programmable graphics hardware using fragment programs [S2]. The ray-template approach for voxel-based attenuation is documented in unofficial smoke simulation repositories [S1, unofficial]. Framebuffer readback techniques for cloud illumination were explored in academic coursework [S3, unofficial].
