# Colored Stochastic Shadow Mapping for Volume Rendering

Also called: CSSM for DVR, Colored Stochastic Shadow Mapping (CSSM), Colored Stochastic Shadow Mapping (CSSM) for Direct Volume Rendering, Stochastic Shadow Mapping for Volume Rendering

## Overview
Colored Stochastic Shadow Mapping (CSSM) is a two-step rendering technique for Direct Volume Rendering (DVR) that generates physically plausible, colored shadows for translucent volumes using stochastic shadow maps [S1]. Unlike traditional shadow mapping which applies binary occlusion or thresholding, CSSM adapts probabilistic photon traversal events to volumetric data, allowing translucent objects to cast partial, color-specific shadows [S1]. It distinguishes itself from sibling methods like [Deep Shadow Mapping](9816-colored-stochastic-shadow-mapping-for-volume-rendering.md) by storing only one stochastic depth value per color channel rather than piecewise linear control points, thereby achieving higher color fidelity with significantly less texture memory [S1].

## How it works
CSSM operates in two distinct phases: CSSM Generation (preprocessing) and DVR Rendering (compositing). The method relies on the emission-absorption model [Max95] and adapts stochastic surface shadow mapping to volumes by discretizing the light ray into segments [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Volume dataset $V$ with associated transfer functions for opacity $\alpha$ and transmission $t$.
    *   Light source position (assumed point light).
    *   Camera parameters for the DVR view.
    *   CSSM resolution (e.g., $1024^2$, $2048^2$).
    *   Number of offset queries $m$ for denoising.
*   **Outputs:**
    *   CSSM Texture: An RGB texture where each fragment stores three depth values $(c_R, c_G, c_B)$.
    *   Final DVR Image: Volume samples modulated by computed shadow factors.

### Data Structures
**CSSM Texture:**
*   Format: RGB floating-point or fixed-point texture.
*   Layout: Each texel stores three values: $c_R, c_G, c_B$.
*   Value Range: $[0, 1]$, representing the normalized distance from the light source to the point of first absorption for that specific wavelength.
*   Initialization: All accumulators initialized to $1.0$ (representing "no shadow" or full transmission).

### Pseudocode: CSSM Generation
The following algorithm generates the CSSM texture. It iterates over every fragment of the shadow map, casting a ray from the light source through the volume.

```python
def generate_cssm(volume, light_pos, cssm_texture, resolution):
    # Iterate over all fragments in the CSSM texture
    for x in range(resolution):
        for y in range(resolution):
            # Step 1: Initialize depth accumulators for RGB channels
            cR = 1.0
            cG = 1.0
            cB = 1.0
            
            # Step 2: Cast and discretize a ray from light source through fragment (x,y)
            # Determine the ray direction and step size based on volume bounds
            ray = cast_ray_from_light(light_pos, x, y, resolution)
            
            # Step 3: Iterate through each segment i of the discretized ray
            for i in range(1, num_segments):
                # Step 4: Compute depth zi of segment i, normalized to [0, 1]
                zi = ray.get_normalized_depth(i)
                
                # Step 5: Generate a random number ri uniformly distributed in [0, 1]
                ri = random_uniform(0.0, 1.0)
                
                # Step 6 & 7: Process each wavelength {R, G, B}
                for lambda_channel in ['R', 'G', 'B']:
                    # Get opacity alpha_i for segment i
                    alpha_i = volume.get_opacity(ray.get_position(i))
                    
                    # Get conditional transmission probability t_i,lambda
                    # This depends on the color properties/transfer function of the volume
                    t_i_lambda = volume.get_transmission_probability(i, lambda_channel)
                    
                    # Compute probability rho_i,lambda that photon is NOT transmitted
                    # Formula: p_i,lambda = alpha_i * (1 - t_i,lambda)
                    rho_i_lambda = alpha_i * (1.0 - t_i_lambda)
                    
                    # If probability exceeds random threshold, photon is absorbed
                    if rho_i_lambda > ri:
                        # Update accumulator with the minimum depth (closest shadow)
                        if lambda_channel == 'R':
                            cR = min(cR, zi)
                        elif lambda_channel == 'G':
                            cG = min(cG, zi)
                        elif lambda_channel == 'B':
                            cB = min(cB, zi)
                
                # Step 8: Terminate early if all channels are shadowed
                if cR < 1.0 and cG < 1.0 and cB < 1.0:
                    break
            
            # Step 9: Store final accumulated depths in CSSM fragment
            cssm_texture.set_fragment(x, y, cR, cG, cB)
```

### Pseudocode: DVR Rendering with CSSM
During the standard DVR ray casting loop, each sample's illumination is modulated by querying the CSSM.

```python
def render_dvr_with_cssm(volume, camera, cssm_texture, offsets, m):
    # Step 10: Initialize shadow factors for RGB channels
    lR = 0.0
    lG = 0.0
    lB = 0.0
    
    # Standard DVR Ray Casting Loop
    for each ray from camera:
        for each sample s along the ray:
            # Step 11: Compute sample position (sx, sy, sz) in light coordinate system
            # Project sample s onto the CSSM texture space
            sx, sy = project_to_light_space(s.position)
            sz = s.depth_in_light_space
            
            # Step 12: Iterate through m offset queries
            for j in range(1, m + 1):
                offset = offsets[j-1] # e.g., (0,0), (3,3), etc.
                
                # Step 13: Read CSSM entries at (sx, sy) + offset
                cR_j, cG_j, cB_j = cssm_texture.get_fragment(sx + offset.x, sy + offset.y)
                
                # Step 14: Binary test per wavelength
                # If stored depth > sample depth, sample is in shadow
                if cR_j > sz:
                    lR += 1.0 / m
                if cG_j > sz:
                    lG += 1.0 / m
                if cB_j > sz:
                    lB += 1.0 / m
            
            # Use shadow factors (lR, lG, lB) to modulate the sample's color/intensity
            # Final color contribution = BaseColor * (lR, lG, lB)
            pass
```

### Formulas
**Probability of Non-Transmission:**
The probability $\rho_{i,\lambda}$ that a photon of wavelength $\lambda$ is not transmitted through the $i$-th volume segment is derived from the opacity $\alpha_i$ and the conditional transmission probability $t_{i,\lambda}$:

$$
\rho_{i,\lambda} = \alpha_i \cdot (1 - t_{i,\lambda})
$$

Where:
*   $\alpha_i$: Opacity of the volume in segment $i$.
*   $t_{i,\lambda}$: Conditional probability that the photon is transmitted given it interacts with the volume in segment $i$.

**Shadow Factor:**
The shadow factor $l_\lambda$ for a color channel is the average of $m$ binary tests:

$$
l_\lambda = \frac{1}{m} \sum_{j=1}^{m} \mathbb{I}(c_{\lambda,j} > s_z)
$$

Where:
*   $c_{\lambda,j}$: The CSSM depth value for channel $\lambda$ at the $j$-th offset.
*   $s_z$: The depth of the current DVR sample in light space.
*   $\mathbb{I}(\cdot)$: Indicator function, returning 1 if true, 0 otherwise.

### Parameters
*   **$\alpha_i$**: Opacity derived from the volume's transfer function.
*   **$t_{i,\lambda}$**: Conditional transmission probability, dependent on the color properties of the volume segment.
*   **$m$**: Number of offset queries. Typical value: 13 [S1].
    *   7 offsets: Plausible results with no noticeable noise [S1].
    *   13 offsets: Standard experimental value [S1].
    *   21 offsets: Softer shadows, higher computation time [S1].
*   **$\Delta_j$**: Spatial offsets for CSSM lookup. Example set for $m=13$: $\{(0,0), (\pm3,\pm3), (\pm4,0), (0,\pm4), (\pm7,0), (0,\pm7)\}$ [S1].
*   **CSSM Resolution**: Tested resolutions include $1024^2$, $2048^2$, and $4096^2$ [S1]. Higher resolution improves detail but increases memory.

### Edge Cases and Pitfalls
*   **Noise:** Stochastic generation introduces noise. Mitigated by averaging over multiple CSSM lookups with offsets. Complex scenes may require more offsets than the standard 13 to achieve noise-free results [S1].
*   **Blurring:** Increasing $m$ softens shadows but increases computation time and causes blurring [S1].
*   **Single Light Source:** The method is limited to a single point light source. Additional lights require additional shadow maps, a general limitation of shadow mapping [S1].
*   **Precision:** Depth values are normalized to $[0,1]$. Precision issues may arise if the volume bounds are not tightly aligned with the light frustum or if depth values are very close, though the stochastic nature provides some robustness [S1].

## Operating characteristics
*   **Time Complexity:**
    *   **CSSM Generation:** Proportional to the number of fragments in the shadow map times the number of volume segments per ray.
    *   **DVR Rendering:** Proportional to the number of samples times the number of offsets $m$.
    *   **Measured Performance:** At $1024^2$ resolution, CSSM rendering time is 4.9 ms, compared to 3.2 ms for Traditional Shadow Mapping (TSM) and 3.3 ms for Deep Shadow Mapping (DSM) [S1]. The overhead is due to increased texture fetches (13 per query for CSSM vs 1 for TSM and 3 for DSM) [S1].
*   **Memory Complexity:**
    *   CSSM stores 3 values (RGB depths) per fragment.
    *   DSM with 3 nodes per channel stores 12 values per fragment (4x storage) [S1].
    *   CSSM memory usage is constant regardless of the number of offsets $m$ used during rendering [S1].
*   **Strengths:**
    *   Produces higher-quality colored shadows than TSM or DSM [S1].
    *   Handles translucent objects correctly, creating partial shadows [S1].
    *   Uses significantly less texture memory than DSM [S1].
    *   Compatible with mixed scenes (volume and surface) [S1].
*   **Limitations:**
    *   Limited to single point light source [S1].
    *   Stochastic noise requires averaging, which can blur sharp shadow edges if $m$ is too large [S1].
    *   Slightly higher rendering time than TSM due to multiple texture fetches [S1].
*   **When to Use:**
    *   When colored shadows for translucent volumes are required.
    *   When memory is constrained compared to DSM.
    *   When interactive rates are needed (all methods produce interactive frame rates) [S1].
*   **When Not to Use:**
    *   When multiple dynamic light sources are required (requires multiple CSSMs).
    *   When sharp, hard shadows are strictly required without any blurring (DSM may be preferred if color fidelity is less critical).

## Background
CSSM was proposed as an alternative to Deep Shadow Maps for Direct Volume Rendering, aiming to produce higher-quality colored shadows with less texture memory [S1]. It adapts the CSSM concept, originally developed for surface rendering [ME11], to volumetric data by modifying probabilistic events to represent photon traversal through a volume with changing opacities [S1]. The method was implemented in the Voreen framework using a GPU-based ray casting approach and tested on synthetic datasets and a Walnut CT dataset [S1]. It builds on the emission-absorption model [Max95] and addresses the limitations of traditional shadow mapping, which fails to handle translucency correctly [S1].
