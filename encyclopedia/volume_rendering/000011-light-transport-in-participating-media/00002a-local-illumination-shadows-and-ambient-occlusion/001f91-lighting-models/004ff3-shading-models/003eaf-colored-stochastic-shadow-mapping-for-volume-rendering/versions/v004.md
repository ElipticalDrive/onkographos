# Colored Stochastic Shadow Mapping for Volume Rendering

Also called: CSSM for DVR, Colored Stochastic Shadow Mapping (CSSM), Colored Stochastic Shadow Mapping (CSSM) for Direct Volume Rendering, Stochastic Shadow Mapping for Volume Rendering

## Overview
Colored Stochastic Shadow Mapping (CSSM) is a two-step rendering technique for Direct Volume Rendering (DVR) that computes colored shadows by adapting stochastic shadow mapping concepts to volumetric data [S1]. Unlike traditional shadow maps that produce binary occlusion or deep shadow maps that require significant memory for piecewise approximations, CSSM uses probabilistic events to store the closest depth at which a photon of a specific wavelength is absorbed or scattered, enabling translucent objects to cast partial, color-accurate shadows [S1]. It sets itself apart by storing only one depth value per color channel per fragment, offering a memory-efficient alternative to Deep Shadow Maps (DSM) while providing superior color fidelity compared to Traditional Shadow Maps (TSM) [S1].

## How it works
CSSM operates in two distinct phases: CSSM Generation (building the shadow map) and DVR Rendering (compositing the volume with shadow factors) [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Volume dataset $V$ with opacity $\alpha$ and transmission properties $t_\lambda$.
    *   Light source position and direction (assumed to be a single point light for the basic formulation) [S1].
    *   CSSM texture resolution (e.g., $1024^2$, $2048^2$, $4096^2$) [S1].
    *   Number of offset queries $m$ for denoising (typical values: 7, 13, 21) [S1].
    *   Offset set $\Delta_j$ for $j=1 \dots m$ [S1].
*   **Outputs:**
    *   CSSM Texture: An RGB texture where each fragment stores three depth values $(c_R, c_G, c_B)$ representing the closest absorption depth for each wavelength [S1].
    *   Final Image: Volume-rendered image with shadowed illumination [S1].

### Data Structures
*   **CSSM Texture:** A 2D texture with RGB channels. Each fragment stores three floating-point depth values $(c_R, c_G, c_B)$, normalized to $[0, 1]$. Initial values are $(1, 1, 1)$, representing "no shadow" (depth 1 is the far plane) [S1].
*   **Volume Data:** Sampled via ray casting. Opacity $\alpha_i$ and conditional transmission probability $t_{i,\lambda}$ are derived from the volume's transfer function for segment $i$ and wavelength $\lambda$ [S1].

### Pseudocode

#### Phase 1: CSSM Generation
This phase builds the shadow map by simulating photon traversal through the volume from the light source's perspective.

```python
def generate_cssm(volume, light_position, cssm_texture, resolution):
    """
    Generates the Colored Stochastic Shadow Map.
    volume: Function to sample opacity alpha and transmission t_lambda at 3D coordinates.
    light_position: 3D vector defining the light source.
    cssm_texture: 2D texture of size resolution x resolution with RGB channels.
    resolution: Width/Height of the CSSM texture.
    """
    # Iterate over all fragments of the CSSM texture
    for y in range(resolution):
        for x in range(resolution):
            # Step 1: Initialize depth accumulators for RGB channels
            cR = 1.0
            cG = 1.0
            cB = 1.0
            
            # Step 2: Cast and discretize a ray from the light source through the current fragment
            # The ray direction is determined by the fragment's screen position (x, y)
            # and the light position. The ray is discretized into n segments.
            ray = cast_ray_from_light_through_fragment(light_position, x, y, resolution)
            
            # Step 3: Iterate through each segment i of the discretized ray
            for i in range(1, n + 1):
                # Step 4: Compute the depth zi of segment i, normalized to [0, 1]
                zi = ray.get_segment_depth(i)
                
                # Step 5: Generate a random number ri uniformly distributed in [0, 1]
                ri = random_uniform(0, 1)
                
                # Step 6 & 7: For each wavelength lambda in {R, G, B}
                for lambda in ['R', 'G', 'B']:
                    # Get volume properties for segment i
                    alpha_i = volume.sample_opacity(ray.get_segment_center(i))
                    t_i_lambda = volume.sample_transmission(ray.get_segment_center(i), lambda)
                    
                    # Compute probability rho_i,lambda that the photon is NOT transmitted
                    # Formula: p_i,lambda = alpha_i * (1 - t_i,lambda)
                    rho_i_lambda = alpha_i * (1.0 - t_i_lambda)
                    
                    # If probability exceeds random threshold, photon is absorbed/scattered
                    if rho_i_lambda > ri:
                        # Update depth accumulator: store the closest depth where absorption occurred
                        if lambda == 'R':
                            cR = min(cR, zi)
                        elif lambda == 'G':
                            cG = min(cG, zi)
                        elif lambda == 'B':
                            cB = min(cB, zi)
                
                # Step 8: Terminate early if all color accumulators are < 1
                # This indicates the photon was fully absorbed or blocked in previous segments
                if cR < 1.0 and cG < 1.0 and cB < 1.0:
                    break
            
            # Step 9: Store the final accumulated depths in the CSSM fragment
            cssm_texture.set_pixel(x, y, (cR, cG, cB))
```

#### Phase 2: DVR Rendering
This phase composites the volume, adjusting illumination based on the CSSM.

```python
def render_dvr_with_cssm(volume, camera, light_position, cssm_texture, resolution, m, offsets):
    """
    Renders the volume using the pre-generated CSSM for shadowing.
    volume: Function to sample color and opacity for DVR compositing.
    camera: Camera parameters for ray generation.
    light_position: 3D vector of the light source.
    cssm_texture: The generated CSSM texture.
    resolution: Resolution of the output frame buffer.
    m: Number of offset queries for denoising.
    offsets: List of m 2D offset vectors (dx, dy).
    """
    # Initialize output image
    image = empty_image(resolution, resolution, RGB)
    
    # Step 10: For all samples of the DVR approach (pixels in the frame buffer)
    for y in range(resolution):
        for x in range(resolution):
            # Generate ray from camera through pixel (x, y)
            ray = cast_ray_from_camera_through_pixel(camera, x, y)
            
            # Perform standard DVR compositing (emission-absorption model)
            # This yields a base color and accumulated opacity for the pixel
            # However, we need to compute shadow factors for the light contribution
            
            # Initialize shadow factors for RGB channels
            lR = 0.0
            lG = 0.0
            lB = 0.0
            
            # Cast ray from light source to determine light coordinate system for this pixel
            # Or more commonly, for each volumetric sample along the camera ray,
            # we project its position into light space to query the CSSM.
            
            # Let's assume we are iterating through volumetric samples along the camera ray
            # for the DVR compositing loop.
            for sample in ray.cast_through_volume(volume):
                sample_pos = sample.position
                sample_color = sample.color
                sample_opacity = sample.opacity
                
                # Step 11: Compute the sample position (sx, sy, sz) in the light coordinate system
                # sz is the depth from the light source to the sample
                # sx, sy are the screen coordinates in the light's view
                light_ray = cast_ray_from_light_through_point(light_position, sample_pos)
                sz = light_ray.get_depth(sample_pos)
                
                # Normalize sz to [0, 1] if necessary, assuming CSSM depths are normalized
                sz_normalized = normalize_depth(sz)
                
                # Step 12: Iterate through m offset queries
                for j in range(1, m + 1):
                    # Step 13: Read CSSM entries from fragment at (sx, sy) + delta_j
                    offset = offsets[j-1]
                    query_x = sx + offset.dx
                    query_y = sy + offset.dy
                    
                    # Clamp coordinates if necessary
                    query_x = clamp(query_x, 0, cssm_texture.width - 1)
                    query_y = clamp(query_y, 0, cssm_texture.height - 1)
                    
                    cR_j, cG_j, cB_j = cssm_texture.get_pixel(query_x, query_y)
                    
                    # Step 14: For each lambda, check if sample is in shadow
                    # If CSSM depth > sample depth, the sample is behind the shadow caster
                    if cR_j > sz_normalized:
                        lR += 1.0 / m
                    if cG_j > sz_normalized:
                        lG += 1.0 / m
                    if cB_j > sz_normalized:
                        lB += 1.0 / m
                
                # Use shadow factors (lR, lG, lB) to modulate the light contribution
                # The final color for this sample is adjusted by the shadow factors
                shadowed_color = sample_color * (lR, lG, lB)
                
                # Composite shadowed_color into the pixel's final color using DVR alpha blending
                image[x, y] = composite(image[x, y], shadowed_color, sample_opacity)
    
    return image
```

### Formulas
*   **Probability of Non-Transmission ($\rho_{i,\lambda}$):** The probability that a photon of wavelength $\lambda$ is not transmitted through the $i$-th volume segment is calculated as [S1]:
    $$ p_{i,\lambda} = \alpha_i \cdot (1 - t_{i,\lambda}) $$
    Where:
    *   $\alpha_i$ is the opacity of the volume in segment $i$.
    *   $t_{i,\lambda}$ is the conditional probability that the photon is transmitted given it interacts with the volume in segment $i$.
    *   This is derived from $P(V_i) = \alpha_i$ (probability of interaction) and $P(T_{i,\lambda}|V_i) = t_{i,\lambda}$ (conditional transmission probability) [S1].

*   **Shadow Factor ($l_\lambda$):** The shadow factor for a color channel is the average of $m$ binary tests [S1]:
    $$ l_\lambda = \frac{1}{m} \sum_{j=1}^{m} \mathbb{I}(c_{\lambda,j} > s_z) $$
    Where:
    *   $c_{\lambda,j}$ is the CSSM depth value for channel $\lambda$ at offset $j$.
    *   $s_z$ is the sample's depth in the light coordinate system.
    *   $\mathbb{I}(\cdot)$ is the indicator function, returning 1 if the condition is true (sample is in shadow) and 0 otherwise.

### Parameters
*   **$\alpha_i$ (Opacity):** Derived from the volume's transfer function or data values for segment $i$ [S1].
*   **$t_{i,\lambda}$ (Conditional Transmission):** Depends on the color properties of the volume in segment $i$. Not given in the sources how this is specifically derived from data, but it is part of the transfer function [S1].
*   **$m$ (Number of Offsets):** The number of offset queries used for denoising/averaging. Typical value used in experiments: 13 [S1]. Other tested values include 7 (pleasing results, no noticeable noise) and 21 (softer shadows) [S1].
*   **$\Delta_j$ (Offsets):** Spatial offsets applied to the CSSM lookup coordinates. Example set for $m=13$: $\{(0,0), (\pm3,\pm3), (\pm4,0), (0,\pm4), (\pm7,0), (0,\pm7)\}$ [S1].
*   **CSSM Resolution:** The resolution of the shadow map texture. Tested resolutions include $1024^2$, $2048^2$, and $4096^2$. Higher resolution improves shadow detail but increases memory usage [S1].

### Edge Cases and Pitfalls
*   **Noise:** Stochastic generation introduces noise in the shadows. This is mitigated by averaging over multiple CSSM lookups with offsets. Complex scenes may require more offsets to achieve pleasing results without noise [S1].
*   **Blurring:** Increasing the number of offsets ($m$) softens shadows but increases computation time and causes blurring [S1].
*   **Single Light Source:** The method is limited to a single point light source. Additional light sources require additional shadow maps, which is a general limitation of shadow mapping approaches [S1].
*   **Precision:** Depth values are normalized to $[0, 1]$. Precision issues may arise if the volume depth range is not well-mapped to this interval [S1].
*   **Boundary Conditions:** Offsets $\Delta_j$ may query outside the CSSM texture bounds. Clamping or wrapping must be applied [S1].

## Operating characteristics
*   **Time Complexity:** CSSM generation is $O(R^2 \cdot n \cdot 3)$, where $R$ is the CSSM resolution and $n$ is the number of segments per ray. DVR rendering is $O(P \cdot S \cdot m)$, where $P$ is the number of pixels, $S$ is the number of samples per pixel, and $m$ is the number of offsets [S1].
*   **Memory Complexity:** CSSM texture requires $3 \cdot R^2$ floating-point values (one per color channel per fragment). This is significantly less than Deep Shadow Maps (DSM), which require $4 \cdot N \cdot R^2$ values for $N$ nodes per channel [S1].
*   **Measured Performance:** At $1024^2$ resolution, CSSM rendering time is 4.9 ms, compared to 3.2 ms for Traditional Shadow Maps (TSM) and 3.3 ms for Deep Shadow Maps (DSM) [S1]. The higher time is due to increased texture fetches (13 per query for CSSM vs 1 for TSM and 3 for DSM) [S1].
*   **Strengths:** Produces high-quality colored shadows, handles translucent objects correctly, uses less memory than DSM, and is compatible with mixed volume/surface scenes [S1].
*   **Limitations:** Limited to single point light source, stochastic noise requires averaging, and blurring increases with more offsets [S1].
*   **When to Use:** When colored shadows for translucent volumes are required, and memory is a constraint compared to DSM. Suitable for interactive applications where slightly higher rendering time is acceptable for better visual quality [S1].
*   **When Not to Use:** When multiple light sources are needed (requires multiple CSSMs), or when hard, binary shadows are sufficient (use TSM) [S1].

## Background
CSSM was proposed as an alternative to Deep Shadow Maps (DSM) for Direct Volume Rendering (DVR) [S1]. It adapts the concept of Stochastic Shadow Mapping, originally developed for surface rendering, to volumetric data [S1]. The method was implemented in the Voreen framework and tested on synthetic datasets (Spheres) and real-world medical data (Walnut CT scan) [S1]. It addresses the limitations of TSM (incorrect shadows for translucent objects) and DSM (high memory usage and greyish shadows) [S1].
