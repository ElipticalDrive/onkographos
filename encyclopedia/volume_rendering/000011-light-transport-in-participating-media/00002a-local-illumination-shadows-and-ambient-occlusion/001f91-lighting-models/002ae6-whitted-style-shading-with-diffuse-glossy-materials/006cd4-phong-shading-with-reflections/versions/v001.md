# Phong Shading with Reflections

Also called: Phong Shading with Environment Reflections

## Overview
Computes the color of a hit point by combining ambient lighting, diffuse lighting, specular highlights, and environment reflections [S1, unofficial]. It extends basic Phong shading by blending the surface color with a reflection of the environment, allowing for glossy or mirror-like surfaces [S1, unofficial]. It differs from [Color Ramp Modulation](14791-color-ramp-modulation.md) by using physically-based vector math for lighting rather than texture lookup modulation, and from [Inter-reflection Modeling](15367-inter-reflection-modeling.md) by only computing a single bounce of reflection rather than recursive global illumination.

## How it works
**Inputs:**
- `hit.position`: The 3D coordinates of the intersection point.
- `hit.normal`: The surface normal at the intersection point.
- `hit.mat`: A material structure containing:
  - `albedo`: Base surface color (vec3).
  - `diffuse`: Diffuse reflectivity coefficient (float).
  - `specular`: Specular exponent (float).
  - `reflectance`: Reflection blending factor (float, typically 0.0 to 1.0).
- `r.direction`: The direction vector of the incoming ray (vec3).
- `CUBE_MAP`: Boolean flag indicating whether to use an environment map (1) or a simple background function (0).

**Outputs:**
- `col`: The final computed color (vec3).

**Data Structures:**
- `vec3`: A 3-component floating-point vector (x, y, z).
- `material`: A struct holding `albedo`, `diffuse`, `specular`, and `reflectance`.

**Parameters:**
- `light_dir`: Direction of the light source. Value: `normalize(vec3(0, 3., 2))` [S1, unofficial].
- `light_color`: Color of the light. Value: `vec3(0.85, 0.94, 1.0)` [S1, unofficial].
- `surface_ambient`: Ambient color component. Value: `hit.mat.albedo / 40.0` [S1, unofficial].

**Steps:**
1.  **Compute Normal:** Ensure `normal` is normalized. If not provided, compute it from the SDF or geometry at `hit.position` [S1, unofficial].
2.  **Define Light:** Set `light_dir` and `light_color` as defined in parameters [S1, unofficial].
3.  **Compute Shadow:**
    -   Create a shadow ray origin: `shadow_origin = hit.position + light_dir * 0.5` [S1, unofficial].
    -   Ray march from `shadow_origin` in direction `light_dir`.
    -   If the ray hits an object, `shadow = 0.0`.
    -   If the ray misses all objects, `shadow = 1.0` [S1, unofficial].
4.  **Compute Specular Highlight:**
    -   Calculate the half-vector: `halfDir = normalize(light_dir + normalize(-r.direction))` [S1, unofficial]. Note: `r.direction` points towards the camera, so the view direction is `-r.direction`.
    -   Calculate the specular angle: `specAngle = max(dot(halfDir, normal), 0.0)` [S1, unofficial].
    -   Calculate specular intensity: `specular = pow(specAngle, hit.mat.specular)` [S1, unofficial].
5.  **Compute Reflection:**
    -   Calculate the reflection direction: `ref = reflect(normalize(-r.direction), normal)` [S1, unofficial].
    -   If `CUBE_MAP` is 1, sample the environment map at `ref` to get `ref_text` [S1, unofficial].
    -   If `CUBE_MAP` is 0, compute a background color at `ref` (e.g., sky color or gradient) to get `ref_text` [S1, unofficial].
6.  **Compute Base Color:**
    -   Calculate the diffuse term: `diffuse_term = shadow * light_intensity * light_color * max(dot(normal, light_dir), 0.0) * hit.mat.diffuse` [S1, unofficial]. Note: `light_intensity` is assumed to be 1.0 if not specified, or absorbed into `light_color` [S1, unofficial].
    -   Calculate the specular term: `specular_term = shadow * light_intensity * light_color * specular * clamp(hit.mat.specular, 0.0, 1.0)` [S1, unofficial]. Note: The source uses `clamp(hit.mat.specular, 0.0, 1.0)` as a multiplier, which is unusual for a specular exponent but must be implemented as stated [S1, unofficial].
    -   Combine with ambient: `col = surface_ambient + (diffuse_term + specular_term) * hit.mat.albedo` [S1, unofficial].
7.  **Blend Reflection:**
    -   Final color: `col = hit.mat.reflectance * ref_text + (1.0 - hit.mat.reflectance) * col` [S1, unofficial].

**Pseudocode:**
```python
def phong_shading_with_reflections(hit, r, cube_map, env_map):
    # 1. Compute Normal
    normal = normalize(hit.normal)
    
    # 2. Define Light
    light_dir = normalize(vec3(0, 3, 2))
    light_color = vec3(0.85, 0.94, 1.0)
    light_intensity = 1.0 # Assumed if not provided
    
    # 3. Compute Shadow
    shadow_origin = hit.position + light_dir * 0.5
    shadow_ray = Ray(shadow_origin, light_dir)
    shadow_hit = trace(shadow_ray)
    shadow = 1.0 if shadow_hit is None else 0.0
    
    # 4. Compute Specular
    view_dir = normalize(-r.direction)
    half_dir = normalize(light_dir + view_dir)
    spec_angle = max(dot(half_dir, normal), 0.0)
    specular = pow(spec_angle, hit.mat.specular)
    
    # 5. Compute Reflection
    ref_dir = reflect(view_dir, normal)
    if cube_map:
        ref_text = sample_env_map(env_map, ref_dir)
    else:
        ref_text = compute_background_color(ref_dir)
        
    # 6. Compute Base Color
    surface_ambient = hit.mat.albedo / 40.0
    diffuse_term = shadow * light_intensity * light_color * max(dot(normal, light_dir), 0.0) * hit.mat.diffuse
    specular_term = shadow * light_intensity * light_color * specular * clamp(hit.mat.specular, 0.0, 1.0)
    col = surface_ambient + (diffuse_term + specular_term) * hit.mat.albedo
    
    # 7. Blend Reflection
    col = hit.mat.reflectance * ref_text + (1.0 - hit.mat.reflectance) * col
    
    return col
```

## Subtopics

### Metal Scattering
A variant where the reflection direction is perturbed by randomness to simulate rough metallic surfaces [S2, unofficial].
- **Parameter:** `fuzz` (double): Amount of randomness added to the reflection direction. Clamped to a maximum of 1 [S2, unofficial].
- **Pitfall:** Rays reflecting inward (into the object) are discarded to prevent self-intersection artifacts [S2, unofficial].

### Deferred Phong Shading
A shading technique that defers the final lighting calculation until all primitives for a region are processed, storing intermediate surface normal values per pixel to achieve significant speedup over per-primitive shading [S3, unofficial].
- **Steps:**
  1. During primitive processing, for each visible pixel, store the x, y, and z components of the surface normal. For polygons, compute these components by simple linear interpolation of each component [S3, unofficial].
  2. After all primitives for a region are processed, perform end-of-frame operations: normalize the stored normal vector by dividing by the square root of its length, computed using a Newton iteration [S3, unofficial].
  3. Compute the final color for each pixel using the standard Phong lighting model [S3, unofficial].
- **Parameters:** Renderer cycle count for end-of-frame Phong lighting with a single light source: approximately 23,000 cycles or 0.57 milliseconds [S3, unofficial].
- **Performance:** Total end-of-frame time for full screen resolution (1024x1280) with 16 renderers: 2.85 milliseconds per frame, calculated as 0.57msec * (80/16) [S3, unofficial]. Rendering time overhead: 6.8 percent of total rendering time at 24 frames per second [S3, unofficial].

### Logarithmic Phong Shading
A hardware implementation of the Phong illumination model that uses logarithmic number systems to replace multiplications and divisions with additions and subtractions, optimizing for VLSI chip space and speed [S4].
- **Steps:**
  1. Transform operands into logarithm domain at various places in the computing pipeline [S4].
  2. Perform arithmetic operations (multiplications/divisions) as additions/subtractions in the log domain [S4].
  3. Back-transform results into the number domain [S4].
  4. Compute the exponentiation of the specular term using multiplication instead of a table look-up [S4].
- **Parameters:** Illumination Model: Unrestricted Phong illumination model supporting non-parallel light, perspective projection, and depth-cueing based on light-to-eye distance [S4].
- **Pitfall:** Requires compact and fast logarithm converters to achieve significant gains in chip space [S4].

## Operating characteristics
- **Time Complexity:** O(1) per pixel for the standard Phong shading calculation [S1, unofficial]. Deferred Phong shading reduces the number of lighting calculations from O(P) (primitives) to O(Pixels) [S3, unofficial].
- **Memory Complexity:** O(1) for standard Phong shading [S1, unofficial]. Deferred Phong shading requires O(Pixels) memory to store intermediate normal components [S3, unofficial].
- **Measured Performance:** In a 16-renderer system with 1024x1280 resolution, deferred Phong shading takes 2.85 milliseconds per frame, which is 6.8% of the total rendering time at 24 fps [S3, unofficial].
- **Strengths:** Provides realistic specular highlights and reflections [S1, unofficial]. Deferred shading offers significant speedups for complex scenes [S3, unofficial]. Logarithmic implementation optimizes for hardware efficiency [S4].
- **Limitations:** Standard Phong shading does not account for inter-reflections beyond the first bounce [S1, unofficial]. Metal scattering can introduce artifacts if inward rays are not handled [S2, unofficial]. Logarithmic implementation requires specialized hardware [S4].
- **When to use:** Use for real-time rendering where performance is critical and high-quality reflections are needed [S1, unofficial]. Use deferred shading for scenes with many primitives [S3, unofficial]. Use logarithmic shading for hardware-constrained environments [S4].

## Background
Phong shading was introduced by Bui Tuong Phong in 1973 [S3, unofficial]. It is a widely used local illumination model in computer graphics for rendering smooth surfaces with specular highlights [S3, unofficial]. The addition of environment reflections extends the model to include glossy and mirror-like surfaces [S1, unofficial]. Deferred Phong shading was developed to optimize rendering performance in parallel graphics systems [S3, unofficial]. Logarithmic Phong shading was developed for VLSI implementations to reduce chip space and increase speed [S4].
