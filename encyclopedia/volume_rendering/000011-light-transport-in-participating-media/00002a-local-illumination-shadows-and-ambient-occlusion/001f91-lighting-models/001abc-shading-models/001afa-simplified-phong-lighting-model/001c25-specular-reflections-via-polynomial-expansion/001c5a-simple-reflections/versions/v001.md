# Simple Reflections

Also called: Raymarched Reflections, Surface Reflection Blending

## Overview
Simple Reflections is a local illumination technique that approximates specular reflections in raymarched scenes by casting a secondary ray from the surface point and blending its result with the primary surface color [S1, unofficial]. It solves the problem of adding visual depth and realism to smooth surfaces without the computational cost of full recursive path tracing [S1, unofficial]. Unlike its parent method, Specular Reflections via Polynomial Expansion, which analytically expands the Phong specular term into a polynomial for Fourier evaluation, Simple Reflections uses a geometric raymarching approach to sample the environment directly [S1, unofficial].

## How it works
**Inputs:**
*   Surface position $\mathbf{p}$
*   Surface normal $\mathbf{n}$ (normalized)
*   View direction $\mathbf{v}$ (normalized, pointing from surface to camera)
*   Distance field function $SDF(\mathbf{x})$
*   Reflection blend factor $\alpha \in [0, 1]$

**Outputs:**
*   Reflected color $C_{refl}$

**Data Structures:**
*   Ray structure: $\{ \mathbf{origin}: \mathbb{R}^3, \mathbf{direction}: \mathbb{R}^3, \mathbf{color}: \mathbb{R}^3, \mathbf{t}: \mathbb{R} \}$

**Steps:**
1.  **Calculate Reflected Direction:** Compute the direction of the reflected ray $\mathbf{r}$ using the surface normal $\mathbf{n}$ and the view direction $\mathbf{v}$. The standard reflection formula is:
    $$ \mathbf{r} = 2(\mathbf{n} \cdot \mathbf{v})\mathbf{n} - \mathbf{v} $$
    [S1, unofficial]

2.  **Raymarch:** Cast a ray starting at $\mathbf{p}$ with direction $\mathbf{r}$ into the scene.
    *   Initialize ray origin $\mathbf{o} = \mathbf{p} + \epsilon \mathbf{r}$ (where $\epsilon$ is a small offset to prevent self-intersection) [G].
    *   Iterate to find the closest surface intersection distance $d = SDF(\mathbf{o})$.
    *   Advance the ray: $\mathbf{o} \leftarrow \mathbf{o} + d \mathbf{r}$.
    *   Repeat until $d$ is below a threshold (hit) or a maximum distance is exceeded (miss).
    *   If a hit occurs, sample the color $C_{env}$ at the hit point (potentially recursively or via a simplified shading model). If no hit, use a background color $C_{bg}$ [S1, unofficial].

3.  **Blend:** Combine the reflected color $C_{env}$ with the original surface color $C_{surf}$ (computed from the primary ray's shading) using the blend factor $\alpha$:
    $$ C_{refl} = \alpha C_{env} + (1 - \alpha) C_{surf} $$
    [S1, unofficial]

**Parameters:**
*   $\alpha$: Reflection strength. Typical values range from 0.0 (no reflection) to 1.0 (mirror). [S1, unofficial]
*   $\epsilon$: Offset for self-intersection prevention. Typical value: $10^{-4}$ to $10^{-3}$ times the scene scale [G].

**Edge Cases and Pitfalls:**
*   **Self-Intersection:** Without the offset $\epsilon$, the reflected ray may immediately intersect the surface it originated from, causing artifacts.
*   **Infinite Recursion:** If the reflection ray hits a reflective surface, naive implementation leads to infinite recursion. This method assumes a single bounce [S1, unofficial].
*   **Precision:** Floating-point precision errors in raymarching can cause jittering in reflections, especially at grazing angles.

**Pseudocode:**
```python
def simple_reflections(p, n, v, sdf, alpha, max_steps=10, max_dist=100.0, epsilon=1e-4):
    """
    Calculates simple reflection color.
    
    Args:
        p: Surface position (vec3)
        n: Surface normal (vec3, normalized)
        v: View direction (vec3, normalized, from surface to camera)
        sdf: Distance field function
        alpha: Blend factor [0, 1]
        max_steps: Maximum raymarch steps
        max_dist: Maximum raymarch distance
        epsilon: Self-intersection offset
        
    Returns:
        Reflected color (vec3)
    """
    # 1. Calculate reflected direction
    # r = 2 * dot(n, v) * n - v
    dot_nv = dot(n, v)
    r = 2.0 * dot_nv * n - v
    r = normalize(r)
    
    # 2. Raymarch
    ray_origin = p + epsilon * r
    ray_color = vec3(0.0)
    hit = False
    
    for i in range(max_steps):
        dist = sdf(ray_origin)
        if dist < 1e-4: # Hit surface
            hit = True
            # Sample environment color at hit point
            # For simplicity, assume a solid color or basic shading
            # In a full renderer, this might involve normal sampling or recursive calls
            ray_color = vec3(1.0, 1.0, 1.0) # Placeholder for environment color
            break
        if dist > max_dist: # Miss
            ray_color = vec3(0.0, 0.0, 0.0) # Background color
            break
        ray_origin += dist * r
        
    if not hit:
        ray_color = vec3(0.0, 0.0, 0.0) # Background if loop finishes without hit
        
    # 3. Blend
    # C_surf is assumed to be passed in or computed externally
    # For this function, we return the blended result assuming C_surf is known
    # Note: The source [S1, unofficial] implies blending with "surface color", 
    # so this function should ideally take C_surf as input or return C_env
    # to be blended by the caller. Here we assume C_surf is provided.
    return alpha * ray_color + (1.0 - alpha) * C_surf
```
*Note: The pseudocode above assumes `C_surf` is available in the scope or passed as an argument. The core logic from [S1, unofficial] is the raymarching and blending.*

## Subtopics

### Cube Map Mapping
A variant that replaces raymarching with a cube map lookup for reflections [S2, unofficial]. It maps the reflected direction to cube map texture coordinates following OpenGL specifications [S2, unofficial].
**Steps:**
1.  Compute reflected directions: `reflected_directions = 2 * surface_normals * torch.sum(view_directions * surface_normals, dim=-1, keepdim=True) - view_directions` [S2, unofficial].
2.  Find the max absolute component index and value: `max_indices = torch.argmax(torch.abs(reflected_directions), dim=-1, keepdim=True)`; `max_values = torch.gather(reflected_directions, -1, max_indices)` [S2, unofficial].
3.  Compute texture coordinates: `texcoords_x, texcoords_y, texcoords_z = torch.unbind(reflected_directions / torch.abs(max_values), dim=-1)` [S2, unofficial].
4.  Map coordinates to cube faces using linear mapping for the third coordinate: `linear_mapping(inputs, in_min, in_max, out_min, out_max) = (inputs - in_min) / (in_max - in_min) * (out_max - out_min) + out_min` [S2, unofficial].
5.  Construct grid coordinates for each face based on `max_indices` and `max_values` sign, stacking `(u, v, face_index)` where `face_index` is mapped from 0-5 to -1 to 1 [S2, unofficial].
6.  Sample cube map: `images = nn.functional.grid_sample(images, grids.unsqueeze(-4)).squeeze(-3)` [S2, unofficial].
7.  Permute output: `images = images.permute(0, 2, 3, 1)` [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of raymarch steps per reflection. Significantly slower than analytical specular highlights but faster than full path tracing.
*   **Memory Complexity:** $O(1)$ additional memory per pixel for the reflection ray state.
*   **Strengths:** Simple to implement; provides realistic mirror-like effects; works with any distance field.
*   **Limitations:** Single-bounce only; noisy if raymarching is sparse; expensive for high-resolution reflections; self-intersection artifacts if not handled.
*   **When to use:** When mirror-like reflections are needed and full path tracing is too slow.
*   **When not to use:** For diffuse-only scenes, or when multiple bounces are required.

## Background
Simple Reflections is a common technique in real-time raymarching and signed distance field (SDF) rendering. It was popularized in the context of procedural geometry and raymarched scenes, as described in early online tutorials on raymarching distance fields [S1, unofficial]. It serves as a practical alternative to analytical specular models when environmental context is important.
