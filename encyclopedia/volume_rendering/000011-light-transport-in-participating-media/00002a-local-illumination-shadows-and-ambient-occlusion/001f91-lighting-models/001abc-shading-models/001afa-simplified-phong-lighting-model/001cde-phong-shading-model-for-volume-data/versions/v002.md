# Phong Shading Model for Volume Data

Also called: Direct Volume Rendering using Textures, Engel, Kraus & Ertl technique, Gradient-based Phong Shading, Texture Mapping Based Volume Rendering with Phong Illumination

## Overview
This method renders 3D volume data by mapping it to 2D or 3D textures and projecting polygonal planes (oriented to the object or view) onto the screen, where a fragment shader computes Phong illumination (ambient, diffuse, specular) and alpha blending [S3]. It differs from ray-marching approaches by leveraging hardware-accelerated texture lookups and fixed-function or early programmable pipeline blending, trading physical light transport accuracy for interactive performance on older hardware [S3]. It builds on [Simplified Phong Lighting Model](885-simplified-phong-lighting-model.md) by applying the Phong reflection model directly to volume samples accessed via texture coordinates [S3].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset stored in a `sampler3D` texture unit [S3].
*   **Input:** Texture coordinates (`texPos0`) for the polygon vertices [S3].
*   **Input:** Lighting parameters: light position, eye position, light color, and reflection coefficients [S3].
*   **Output:** A 4D color value (`OUT`) representing the final fragment color and alpha [S3].

**Data Structures:**
*   `sampler3D samplerTex0`: Bound to `TEXUNIT0`, holding the volume data. The data layout is not specified beyond being a 3D texture [S3].
*   `float4 texPos0`: Input texture coordinate from `TEXCOORD0` [S3].
*   `float4 OUT`: Output color, initialized to white with alpha 1.0 [S3].

**Parameters:**
*   `globalAmbient`: Uniform `float3` for global ambient light color [S3].
*   `lightColor`: Uniform `float3` for the light source color [S3].
*   `lightPosition`: Uniform `float3` for the light source position [S3].
*   `eyePosition`: Uniform `float3` for the camera/eye position [S3].
*   `Ka`: Uniform `float3` for the ambient reflection coefficient [S3].
*   `Kd`: Uniform `float3` for the diffuse reflection coefficient [S3].
*   `Ks`: Uniform `float3` for the specular reflection coefficient [S3].
*   `shininess`: Uniform `float` for the specular exponent [S3].

**Steps:**
1.  **Initialize Output:** Set `OUT` to `(1.0, 1.0, 1.0, 1.0)` [S3].
2.  **Sample Volume:** Sample the 3D texture at `texPos0` using `samplerTex0` to obtain `texvalue` [S3].
3.  **Extract Alpha:** Set `OUT.a` to the alpha component of `texvalue` [S3].
4.  **Compute Normal:** Compute the surface normal by expanding the RGB components of `texvalue` using the function `expand(v) = (v - 0.5) * 2`, which maps the `[0, 1]` range to `[-1, 1]` [S3]. This assumes the volume data's RGB channels store pre-computed surface normals or a representation that can be linearly mapped to normal space [S3].
5.  **Lighting Calculation (Conditional):** If `OUT.a > 0`:
    a.  **Ambient:** Compute ambient lighting: `ambient = lightColor * Ka` [S3].
    b.  **Halfway Vector:** Compute the normalized halfway vector between the light and the eye: `H = normalize(lightPosition - eyePosition)` [S3].
    c.  **Diffuse:** Compute diffuse lighting. The source implementation uses `dot(lightPosition, normal)` directly, which deviates from the standard Phong model where the normalized light direction vector $\mathbf{L}$ should be used [S3]. Formula: `diffuse = max(dot(lightPosition, normal), 0) * Kd * lightColor` [S3].
    d.  **Specular:** Compute specular lighting using the Blinn-Phong approximation (halfway vector): `specular = pow(dot(H, normal), shininess) * Ks` [S3].
    e.  **Combine:** Set `OUT.rgb` to the sum of ambient, diffuse, and specular components [S3].
6.  **Return:** Return `OUT` [S3].

**Pseudocode:**
```python
# Fragment Shader Implementation for Texture-Mapped Plane Volume Rendering
# Inputs: texPos0 (Vector4), globalAmbient (Vector3), lightColor (Vector3),
#         lightPosition (Vector3), eyePosition (Vector3), Ka (Vector3),
#         Kd (Vector3), Ks (Vector3), shininess (float), samplerTex0 (3D Texture)

def expand(v: Vector3) -> Vector3:
    """Maps [0,1] range to [-1,1] range for normal extraction."""
    return (v - 0.5) * 2.0

def sample_3d_texture(tex: Texture3D, coord: Vector3) -> Vector4:
    """Standard 3D texture lookup with trilinear interpolation."""
    return tex.fetch(coord)

def main(texPos0: Vector4, globalAmbient: Vector3, lightColor: Vector3,
         lightPosition: Vector3, eyePosition: Vector3, Ka: Vector3,
         Kd: Vector3, Ks: Vector3, shininess: float,
         samplerTex0: Texture3D) -> Vector4:
    
    # 1. Initialize output
    OUT = Vector4(1.0, 1.0, 1.0, 1.0)
    
    # 2. Sample volume data
    texvalue = sample_3d_texture(samplerTex0, texPos0.xyz)
    
    # 3. Extract alpha
    OUT.a = texvalue.a
    
    # 4. Compute normal from RGB components
    normal = expand(texvalue.rgb)
    
    # 5. Lighting calculation if alpha is non-zero
    if OUT.a > 0:
        # Ambient component
        ambient = lightColor * Ka
        
        # Halfway vector
        halfway = normalize(lightPosition - eyePosition)
        
        # Diffuse component
        # Note: Source code uses lightPosition directly in dot product,
        # which is non-standard. Standard Phong uses normalized light direction vector.
        diffuse = max(dot(lightPosition, normal), 0.0) * Kd * lightColor
        
        # Specular component (Blinn-Phong)
        specular = pow(dot(halfway, normal), shininess) * Ks
        
        # Combine
        OUT.rgb = ambient + diffuse + specular
        
    return OUT
```

**Edge Cases and Pitfalls:**
*   **Zero Alpha:** If `OUT.a` is 0, the lighting calculation is skipped, and `OUT` remains white `(1.0, 1.0, 1.0, 1.0)` with alpha 0. If alpha blending is used without proper alpha testing or if the background is not black, this results in white fragments being blended into the image [S3].
*   **Normal Interpretation:** The method assumes the RGB components of the volume data represent surface normals. If the volume data represents scalar density, this approach will produce incorrect lighting unless the RGB channels are explicitly pre-computed as normals [S3].
*   **Light Position Usage:** The diffuse term uses `lightPosition` directly in the dot product instead of the normalized light direction vector $\mathbf{L}$. This is a specific implementation detail of the cited source and deviates from the standard Phong model definition [S3].
*   **Ray Marching Incompatibility:** This method projects polygonal planes and computes lighting per-fragment via texture sampling; it does not traverse rays through volume cells. Test cases expecting ray-marching behavior (e.g., step-based traversal, front-to-back compositing) will fail because the algorithm operates on a fundamentally different rendering primitive [S3].

## Subtopics

### [Volume Shading Modes](1550-volume-shading-modes.md)
Volume Shading Modes are a set of three shading strategies applied during volume ray marching to compute lighting and shadows for each sample along a ray. They extend the Phong Shading Model for Volume Data by providing specific heuristics for handling illumination in participating media, distinguishing themselves through their approach to gradient estimation and shadow accumulation.

## Operating characteristics
*   **Performance:** The technique using fragment shaders (Cg) results in lower performance compared to using the fixed-function pipeline of OpenGL [S3].
*   **Texture Orientation:** 3D textures oriented to the view plane have substantially lower performance than those oriented to the object plane [S3].
*   **Texture Access:** 3D texture accesses are slower than 2D texture accesses due to irregular memory access patterns [S3].
*   **Alpha Testing:** Enabling alpha test generates more frames per second compared to disabling it [S3].
*   **Zoom Effect:** The performance of polygons oriented to the projection plane improves when the zoom increases [S3].
*   **Measured Performance:** For a "Fat" volume at zoom 1.0 in motion:
    *   OpenGL 2D Object Textures: 32-34 FPS (Alpha Test On), 23-24 FPS (Alpha Test Off) [S3].
    *   OpenGL 3D Object Textures: 15 FPS (Alpha Test On), 12-13 FPS (Alpha Test Off) [S3].
    *   OpenGL+Cg 3D View Textures: 4 FPS (Alpha Test On), 3 FPS (Alpha Test Off) [S3].
*   **Strengths:** Leverages hardware texture interpolation and blending; suitable for real-time visualization on older hardware [S3].
*   **Limitations:** Does not account for light transport within the volume (scattering/absorption); performance degrades with 3D textures and view-oriented planes; requires pre-computed normals in RGB channels or specific data layout [S3].

## Background
The technique is used in the implementation described by Engel, Kraus & Ertl [S3]. It applies the Phong reflection model to volume data rendered via texture mapping, aiming to provide visual cues for shape and depth in volume rendering [S1, S3]. The Phong model components (ambient, diffuse, specular) are adapted from polygon shading to volume samples [S1].
