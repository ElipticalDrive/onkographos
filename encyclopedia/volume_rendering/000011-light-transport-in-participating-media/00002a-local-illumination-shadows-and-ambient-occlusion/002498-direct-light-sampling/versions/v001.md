# Direct Light Sampling

Also called: Direct Illumination Sampling, Iluminación directa

## Overview
Direct Light Sampling is a technique for computing direct illumination in participating media and scenes by explicitly shooting a ray from a surface or volume intersection point toward a light source to determine visibility and contribution [S1, unofficial][S2, unofficial]. It solves the problem of accurately rendering shadows and light falloff by testing occlusion between the shading point and the light, distinguishing it from ambient approximations or global illumination methods that rely on precomputed buffers or stochastic path tracing without explicit light targeting [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** The current intersection point $\mathbf{p}$, the scene geometry $\mathcal{O}$ (set of objects), the set of light sources $\mathcal{L}$, and the material properties at $\mathbf{p}$.
- **Output:** The direct illumination color contribution $C_{direct}$ at $\mathbf{p}$.

**Data Structures:**
- **Ray:** Defined by origin $\mathbf{o}$ and direction $\mathbf{d}$.
- **Intersection Result:** Contains distance $t$, hit object $o$, and hit point $\mathbf{p}$.
- **Light Hit:** Contains color $C_{light}$, direction $\mathbf{l}$, distance $d$, and probability density function (PDF) $p$.

**Steps:**
1.  **Select Light:** Choose a light source $l \in \mathcal{L}$ to sample. If using uniform sampling over $N$ lights, select one randomly [S2, unofficial]. If only one light exists and it is the current hit light, return zero contribution [S2, unofficial].
2.  **Compute Direction:** Calculate the direction vector from the intersection point $\mathbf{p}$ to the light source position $\mathbf{pos}(l)$:
    $$ \mathbf{d}_l = \text{normalize}(\mathbf{pos}(l) - \mathbf{p}) $$
    [S1, unofficial]
3.  **Cast Shadow Ray:** Create a shadow ray $\mathbf{r}_s$ originating at $\mathbf{p}$ with direction $\mathbf{d}_l$:
    $$ \mathbf{r}_s = \text{ray}(\mathbf{p}, \mathbf{d}_l) $$
    [S1, unofficial]
4.  **Test Light Visibility:** Perform an intersection test between $\mathbf{r}_s$ and the light source $l$ to find distance $t_l$ [S1, unofficial].
5.  **Test Occlusion:** Perform intersection tests between $\mathbf{r}_s$ and all scene objects $\mathcal{O}$ to find the minimum positive distance $t_{min}$:
    $$ t_{min} = \min \{ t \mid o \in \mathcal{O} \land t = \text{intersection\_test}(\mathbf{r}_s, o) \land t > 0 \} $$
    [S1, unofficial]
6.  **Determine Visibility:** The light is visible if it is hit ($t_l$ exists) and is closer than any occluding object ($t_l \le t_{min}$) [S1, unofficial]. Let $V$ be the visibility flag (true if visible, false otherwise).
7.  **Calculate Contribution:** If $V$ is true, compute the direct light contribution.
    -   **Illumination:** Get the light's color $C_{light}$, direction $\mathbf{l}$, and PDF $p_{light}$ from the light's `illuminate` function [S2, unofficial].
    -   **Material Evaluation:** Evaluate the material's bidirectional reflectance/transmittance distribution function (BRDF/BTDF) or shading model at $\mathbf{p}$ for the incoming direction $\mathbf{l}$ [S2, unofficial].
    -   **Power Heuristic:** Apply the power heuristic to balance the sampling densities if combining with other methods, though for pure direct sampling, the weight is often simplified. The general form cited is:
        $$ \text{weight} = \frac{p_{light}^2}{p_{light}^2 + p_{path}^2} $$
        Where $p_{path}$ is the PDF of the path direction. In simple direct sampling implementations where only the light is sampled, this may default to 1 or be handled via uniform scaling [S2, unofficial].
    -   **Final Term:**
        $$ C_{direct} = \text{material\_evaluate}(\mathbf{p}, \mathbf{l}) \cdot C_{light} \cdot \frac{\text{weight}}{p_{light}} $$
        [S2, unofficial]
8.  **Scale:** If uniform sampling over $N$ lights was used, scale the result by $N$ to account for the selection probability [S2, unofficial].

**Pseudocode:**
```python
def direct_light_sampling(p, normal, geometry, lights, material):
    """
    Computes direct illumination at point p.
    """
    if not lights:
        return 0.0

    # Select a random light (uniform sampling)
    light_index = random_integer(0, len(lights) - 1)
    light = lights[light_index]
    
    # Get light properties
    # Note: In a full path tracer, interaction includes the incoming direction.
    # Here we assume 'p' is the shading point and we are evaluating the light contribution.
    light_hit = light.illuminate(p, normal) # Returns color, direction, pdf
    
    # Calculate direction to light
    direction_to_light = normalize(light_hit.position - p)
    
    # Cast shadow ray
    shadow_ray = Ray(origin=p, direction=direction_to_light)
    
    # Test intersection with light source
    t_light = shadow_ray.intersect(light)
    
    # Test intersection with all geometry
    min_t = infinity
    for obj in geometry:
        t_obj = shadow_ray.intersect(obj)
        if t_obj > 0 and t_obj < min_t:
            min_t = t_obj
            
    # Check visibility: light must be hit and closer than any object
    is_visible = (t_light is not None) and (t_light <= min_t)
    
    if is_visible:
        # Evaluate material response
        # This typically involves dot product with normal and phase function if volume
        material_response = material.evaluate(p, normal, direction_to_light)
        
        # Calculate contribution
        # PDF is from the light sampling distribution
        pdf = light_hit.pdf
        
        # Power heuristic (simplified for single light sampling context)
        # If this is part of a larger integrator, p_path would be the path direction PDF
        # For pure direct light sampling step, we often just divide by pdf
        weight = 1.0 
        
        contribution = material_response * light_hit.color * weight / pdf
        
        # Scale by number of lights if uniform sampling was used
        contribution *= len(lights)
        
        return contribution
    else:
        return 0.0
```

**Parameters:**
- **Light Selection Strategy:** Uniform random sampling is standard [S2, unofficial].
- **Shadow Ray Epsilon:** A small offset is typically added to the shadow ray origin to prevent self-intersection artifacts [G].

**Edge Cases:**
- **No Lights:** Return zero [S2, unofficial].
- **Self-Intersection:** The shadow ray origin $\mathbf{p}$ may intersect the object it just hit. A small epsilon offset along the normal or ray direction is required [G].
- **Degenerate Light:** If the light is at the same position as $\mathbf{p}$, the direction is undefined. Handle by returning zero or a default value [G].

## Operating characteristics
- **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of lights sampled (typically 1) and $M$ is the number of objects in the scene for the shadow ray intersection test. With spatial acceleration structures (BVH, Octree), this reduces to $O(N \cdot \log M)$ [S1, unofficial].
- **Memory Complexity:** $O(M)$ to store scene geometry.
- **Performance:** Provides accurate shadows and light falloff but can be noisy if few samples are used per pixel due to the binary nature of visibility (hit/miss) [S1, unofficial].
- **Strengths:** Simple to implement; produces sharp, correct shadows; efficient for scenes with few lights.
- **Limitations:** Does not account for indirect illumination; noisy in complex lighting scenarios without multiple samples; performance degrades with large numbers of objects if acceleration structures are not used.
- **When to Use:** Scenes with direct lighting requirements, real-time rendering where global illumination is approximated, or as a component in a larger path tracer.
- **When Not to Use:** Scenes requiring soft shadows from area lights without additional sampling techniques, or scenes dominated by indirect illumination.

## Background
The method originates from basic ray tracing techniques for direct illumination, where shadow rays are cast from intersection points to light sources to determine visibility [S1, unofficial]. It is a fundamental component of many rendering algorithms, including Whitted-style ray tracing and path tracing. The specific implementation details cited here are drawn from educational resources on volume rendering and path tracing implementations [S1, unofficial][S2, unofficial].
