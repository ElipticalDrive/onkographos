# Direct Light Sampling

Also called: Direct Illumination Estimation, Direct Illumination Sampling, Iluminación directa, Runtime direct lighting for NIV

## Overview
Direct Light Sampling computes direct illumination at a surface or volume intersection point by explicitly shooting a ray toward a light source to determine visibility and light contribution [S1, S3, unofficial]. It solves the problem of accurately modeling first-order scattering and shadows by testing occlusion along the path to the light, distinguishing itself from methods that rely on random walk termination or global opacity interpolation [S1, unofficial][S2]. Unlike [Light Ray Sampling](4885-light-ray-sampling.md), which integrates density along a fixed direction, Direct Light Sampling explicitly selects light sources and verifies geometric visibility, often using a power heuristic for unbiased estimation when multiple lights are present [S2][S3, unofficial].

## How it works
**Inputs:**
- Ray $r$ with origin and direction.
- Set of scene objects $O$.
- Light source $l$ (or a list of lights) [S1, S3, unofficial].
- Bounce counter $b$ [S1, unofficial].
- Current accumulated color $c$ (initially $1$ or $0$ depending on implementation) [S1, unofficial].

**Outputs:**
- Final color contribution from the light path [S1, unofficial].

**Data Structures:**
- `LightHit`: A structure containing:
  - `colour`: Radiance/Color of the light ($Vec3f$) [S3, unofficial].
  - `pdf`: Probability density function of the sampling ($float$) [S3, unofficial].
  - `direction`: Unit vector from surface to light ($Vec3f$) [S3, unofficial].
  - `distance`: Distance to light source ($float$) [S3, unofficial].
- `ScatterEvent`: Interaction point data including position, normal, and output direction [S3, unofficial].

**Steps:**
1. **Initialize:** Set hit flag $hl = \text{false}$ and accumulated color $c = 1$ [S1, unofficial].
2. **Ray Intersection:** Find the closest object $o \in O$ intersected by ray $r$ at distance $t > 0$ [S1, unofficial]. If no intersection, return background color modulated by $c$ [S1, unofficial].
3. **Light Direction:** Calculate direction to light: $\mathbf{dl} = \text{normalize}(\text{position}(l) - \mathbf{p})$, where $\mathbf{p}$ is the intersection point [S1, S3, unofficial].
4. **Shadow Ray:** Create shadow ray $r_l$ from $\mathbf{p}$ in direction $\mathbf{dl}$ [S1, S3, unofficial].
5. **Light Intersection:** Test intersection between $r_l$ and light $l$ to get distance $t_l$ [S1, S3, unofficial].
6. **Occlusion Test:** Find minimum distance $t_{min}$ to any object $o \in O$ along $r_l$ (excluding the light itself) [S1, unofficial].
7. **Visibility Check:** Update hit flag: $hl \leftarrow hl \lor (t_l \le t_{min})$ [S1, unofficial]. If the light is hit and closer than any occluding object, the point is directly illuminated [S1, S3, unofficial].
8. **Illumination Calculation:**
   - If using a sampler to select lights (for multiple lights), select a random light $l_i$ not equal to the current hit light [S3, unofficial].
   - Illuminate the interaction point to get direction, color, and PDF [S3, unofficial].
   - Calculate the direct light contribution using the power heuristic: $\text{weight} = \frac{1 \cdot \text{lightHit.pdf}}{1 \cdot \text{lightHit.pdf} + 1 \cdot \text{pdf}}$ [S3, unofficial].
   - Add to direct light: $\text{directLight} += \text{material} \rightarrow \text{evaluate}(\text{interaction}) \times \text{lightHit.colour} \times \text{weight} / \text{lightHit.pdf}$ [S3, unofficial].
   - Scale the direct light by the total number of lights in the scene to account for uniform sampling [S3, unofficial].
9. **Specular Guard:** If the material supports specular lobes, return zero contribution as mirror reflection cannot be lit this way [S3, unofficial].
10. **Recursive Bounce:** If bounce counter $b > 0$, compute valid bounce direction $\mathbf{d}$, create new ray $r' = \text{ray}(\mathbf{p}, \mathbf{d})$, update $c \leftarrow c \circ \text{color material}(\mathbf{p}, o)$, and recurse [S1, unofficial].

**Pseudocode:**
```python
def direct_light_sampling(r, objects, lights, bounce_count, accumulated_color):
    """
    Computes direct light contribution by shooting a shadow ray to a light source.
    """
    if bounce_count < 0:
        return accumulated_color * get_background_color(r.direction)

    closest_obj = None
    closest_t = float('inf')
    for obj in objects:
        t = obj.intersection_test(r)
        if t > 0 and t < closest_t:
            closest_t = t
            closest_obj = obj

    if closest_obj is None:
        return accumulated_color * get_background_color(r.direction)

    p = r.origin + closest_t * r.direction
    normal = closest_obj.normal_at(p)

    # Select light (simplified: uniform sampling over lights list)
    light = lights[0]
    dl = normalize(light.position - p)
    shadow_ray = Ray(p, dl)

    t_light = light.intersection_test(shadow_ray)
    t_occlusion = float('inf')
    for obj in objects:
        t = obj.intersection_test(shadow_ray)
        if t > 0 and t < t_occlusion:
            t_occlusion = t

    is_visible = (t_light < t_occlusion)
    if is_visible:
        light_hit = light.illuminate(p, normal, r.direction)
        # Simplified power heuristic weight matching source notation
        weight = (1.0 * light_hit.pdf) / (1.0 * light_hit.pdf + 1.0 * 1.0) if (1.0 * light_hit.pdf + 1.0 * 1.0) > 0 else 0.0
        material_eval = closest_obj.material.evaluate(p, normal, r.direction)
        contribution = material_eval * light_hit.colour * weight / light_hit.pdf
        accumulated_color += contribution * len(lights)

    if bounce_count > 0:
        d = get_valid_bounce_direction(p, normal, r.direction)
        new_ray = Ray(p, d)
        new_accumulated = accumulated_color * closest_obj.material.color_at(p)
        return direct_light_sampling(new_ray, objects, lights, bounce_count - 1, new_accumulated)

    return accumulated_color

def normalize(v):
    length = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
    return (v[0]/length, v[1]/length, v[2]/length)

def get_background_color(direction):
    return (0.0, 0.0, 0.0)

def get_valid_bounce_direction(p, normal, incident_dir):
    return normalize(normal)

class Ray:
    def __init__(self, origin, direction):
        self.origin = origin
        self.direction = direction
```

**Parameters:**
- `bounce_count`: Controls recursion depth; typically $1$ for direct illumination only [S1, unofficial].
- `sigma` (Gaussian filter): Used in post-processing to reduce noise, e.g., $\sigma = 4$ [S1, unofficial].

**Edge Cases:**
- **No Lights:** Return zero or background [S2].
- **Self-Intersection:** Shadow ray origin should be offset slightly along normal to avoid self-intersection [G].
- **Precision:** Floating point errors in $t_l \le t_{min}$ comparison can cause flickering; use a small epsilon [G].
- **Specular Materials:** Return zero contribution to prevent incorrect mirror lighting [S3, unofficial].

## Subtopics

### [Light Sampling for NEE](2616-light-sampling-for-nee.md)
Computes direct illumination by explicitly sampling a light source and a point on its surface from a path vertex, returning direction, probability density, and emitted radiance. It differs from [Direct Illumination Sampling with Mesh Intersection](4450-direct-illumination-sampling-with-mesh-intersection.md) by sampling emitter geometry directly rather than intersecting scene meshes [G]. It differs from [Light Ray Sampling](4885-light-ray-sampling.md) by casting rays from the light towards the vertex rather than from the vertex towards the light [G].

### [Direct Illumination Sampling with Mesh Intersection](4450-direct-illumination-sampling-with-mesh-intersection.md)
Computes direct illumination for a surface point by sampling a light source and verifying visibility against explicit triangle meshes. It serves as the standard direct illumination integrator for polygonal scenes, distinguishing itself from SDF-based approaches by relying on geometric primitives rather than implicit distance fields. It builds on [Direct Light Sampling](3337-direct-light-sampling.md) by handling the specific geometry intersection requirements of mesh-based renderers.

### [Light Ray Sampling](4885-light-ray-sampling.md)
Computes direct illumination at a surface or volume sample point by stepping along the direction to a light source (typically a distant sun) to the light's boundary, accumulating optical density, and applying the phase function. It differs from standard shadow ray tracing by explicitly integrating the participating medium's extinction and scattering properties along the light path, rather than performing a single binary occlusion test.

### [Direct Light Contribution Estimation](5411-direct-light-contribution-estimation.md)
Computes direct illumination intensity at a specific point in a participating medium by combining local high-resolution occlusion data with global attenuation data. It solves the problem of balancing computational efficiency with visual fidelity in volume rendering, where calculating exact transmittance for every voxel is prohibitively expensive. It differs from standard global light propagation methods by explicitly separating the near-field occlusion (handled via local piecewise integration) from the far-field attenuation (handled via a Sparse Voxel Representation), ensuring that local shadows remain sharp while global lighting remains consistent.

## Operating characteristics
- **Time Complexity:** $O(N \cdot L)$ per pixel, where $N$ is the number of bounces and $L$ is the number of lights (if testing all) or $O(N)$ if using a sampler to select one light [S1, S3, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary space per ray, excluding scene data structures [S1, unofficial].
- **Performance:** Limited by hardware constraints; launching infinite rays uniformly is not feasible for real-time FPS ($>15$ FPS) [S1, unofficial]. Post-processing filters (Gaussian, bilinear) are often applied to reduce noise [S1, unofficial].
- **Strengths:** Accurate shadowing and direct illumination; simple to implement [S1, unofficial].
- **Limitations:** High variance (noise) in complex scenes; requires many samples for convergence [S1, unofficial]. The noise-free assumption only holds for simple lighting and low light counts; complex scenes require additional render passes like shadow maps [S2].

## Background
Originated in studies on Sparse Voxel Octree compression and efficiency for global illumination, where direct illumination is added by shooting rays from intersection points to light sources [S1, unofficial]. The method is implemented in educational path tracers to handle different light types and ensure visibility [S3, unofficial]. It is also discussed in the context of Neural Irradiance Volumes (NIV) for runtime direct illumination estimation without sampling noise, though efficient noise-free shading remains impossible for many lights [S2].
