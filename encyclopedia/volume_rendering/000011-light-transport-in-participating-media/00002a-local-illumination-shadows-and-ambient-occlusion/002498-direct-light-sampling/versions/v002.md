# Direct Light Sampling

Also called: Direct Illumination Sampling, Iluminación directa

## Overview
Direct Light Sampling is a technique for computing direct illumination in participating media and scenes by explicitly shooting a ray from a surface or volume intersection point toward a light source to determine visibility and contribution [S1, unofficial][S2, unofficial]. It differs from unidirectional shadow casting by actively selecting light sources (often via sampling) to reduce noise and handle multiple lights, whereas sibling methods like [Two-Pass Shadow Casting](2196-two-pass-shadow-casting-kajiya-and-von-herzen.md) rely on precomputed buffers or fixed directions. It builds on [Local illumination, shadows and ambient occlusion](34-local-illumination-shadows-and-ambient-occlusion.md) by providing the specific mechanism for evaluating the direct light term in the rendering equation.

## How it works
**Inputs:**
- Intersection point $\mathbf{p}$ and normal $\mathbf{n}$ (or volume position).
- List of scene lights $\mathcal{L}$.
- Scene geometry $\mathcal{O}$ for occlusion testing.
- Material properties at $\mathbf{p}$.
- Sampler for random light selection (if multiple lights).

**Outputs:**
- Direct illumination color contribution $C_{direct}$ at $\mathbf{p}$.

**Data Structures:**
- `Light`: Contains position, direction, color, intensity, and type.
- `LightHit`: Structure holding `colour` (RGB), `pdf` (probability density function), `direction` (unit vector), and `distance` (scalar).
- `Ray`: Defined by origin $\mathbf{o}$ and direction $\mathbf{d}$.

**Steps:**
1. **Light Selection:**
   - If $\mathcal{L}$ is empty, return 0.
   - If $\mathcal{L}$ contains a single light, select it.
   - If $\mathcal{L}$ contains multiple lights, select a random light $l \in \mathcal{L}$ using the sampler [S2, unofficial].

2. **Direction Calculation:**
   - Compute the direction to the selected light $l$:
     $$ \mathbf{d}_l = \text{normalize}(\text{position}(l) - \mathbf{p}) $$
     For directional lights, $\mathbf{d}_l$ is the light's predefined direction [S2, unofficial].

3. **Shadow Ray Creation:**
   - Create a shadow ray $\mathbf{r}_s$ originating from $\mathbf{p}$ in direction $\mathbf{d}_l$.
   - Offset the origin slightly along $\mathbf{d}_l$ to avoid self-intersection (shadow acne) [G].

4. **Occlusion Test:**
   - Find the minimum intersection distance $t_{min}$ among all objects $o \in \mathcal{O}$ for ray $\mathbf{r}_s$:
     $$ t_{min} = \min \{ t \mid t = \text{intersection\_test}(\mathbf{r}_s, o) \land t > \epsilon \} $$
     If no intersection is found, $t_{min} = \infty$ [S1, unofficial].

5. **Light Visibility Test:**
   - Determine if the light is visible. For point/disk lights, compute the distance $t_l$ to the light source.
   - The light is visible if $t_l \le t_{min}$ (or if $t_{min} = \infty$) [S1, unofficial].

6. **Illumination Calculation:**
   - If the light is visible, compute the `LightHit` structure:
     - `direction`: $\mathbf{d}_l$.
     - `distance`: $\|\text{position}(l) - \mathbf{p}\|$ (for point lights).
     - `colour`: $\text{color}(l) \times \text{intensity}(l)$.
     - `pdf`: Probability density of the sampling strategy. For uniform point light sampling over the sphere, $pdf = 4\pi d^2$ [S2, unofficial]. For directional lights, PDF handling depends on the specific implementation (often treated as 1 or handled via power heuristic) [S2, unofficial].

7. **Contribution Accumulation:**
   - Evaluate the material's bidirectional reflectance/transmittance distribution function (BRDF/BTDF) $f_r$ at $\mathbf{p}$ for the incoming direction $\mathbf{d}_l$ and outgoing direction (typically view direction $\mathbf{v}$, but in direct sampling context, often simplified to the shading normal dot product for diffuse) [S2, unofficial].
   - Calculate the raw contribution:
     $$ C_{raw} = f_r(\mathbf{p}, \mathbf{d}_l, \mathbf{v}) \cdot \text{lightHit.colour} $$
   - Apply the Power Heuristic to balance path tracing and light sampling if used in a mixed strategy [S2, unofficial]:
     $$ \text{weight} = \frac{w^2}{w^2 + 1} \quad \text{where } w = \frac{1}{\text{lightHit.pdf}} $$
     (Note: The source [S2, unofficial] uses `powerHeuristic(1, lightHit.pdf, 1, pdf)` where `pdf` is the path sampling PDF. If only direct light sampling is considered, the weight simplifies to $1/\text{lightHit.pdf}$ or is handled by the renderer's integrator).
   - Scale by the number of lights $N$ if uniform sampling was used:
     $$ C_{direct} = \frac{C_{raw} \cdot \text{weight}}{\text{lightHit.pdf}} \cdot N $$
   - If specular lobes are present and the light direction does not align with the specular lobe, the contribution may be zero or negligible depending on the material model [S2, unofficial].

**Pseudocode:**
```python
def direct_light_sampling(p, n, lights, geometry, material, sampler):
    if not lights:
        return 0.0
    
    # Select light
    if len(lights) == 1:
        light = lights[0]
    else:
        light = sampler.sample_light(lights)
        
    # Calculate direction to light
    if light.type == DIRECTIONAL:
        d_l = light.direction
        distance = float('inf')
    else:
        d_l = normalize(light.position - p)
        distance = length(light.position - p)
        
    # Create shadow ray
    ray_s = Ray(p + d_l * EPSILON, d_l)
    
    # Test occlusion
    t_min = float('inf')
    for obj in geometry:
        t = ray_s.intersect(obj)
        if t is not None and t > EPSILON:
            t_min = min(t_min, t)
            
    # Test light visibility
    is_visible = False
    if light.type == DIRECTIONAL:
        is_visible = True # Directional lights are assumed unoccluded or handled by sky
    else:
        # For point lights, check if light is closer than any occluder
        # Note: In a rigorous implementation, one checks if the light's geometric extent
        # is intersected. Here we assume a point light approximation or that t_min
        # represents the closest object.
        if t_min == float('inf') or distance <= t_min:
            is_visible = True
            
    if not is_visible:
        return 0.0
        
    # Calculate LightHit
    light_hit = LightHit()
    light_hit.direction = d_l
    light_hit.distance = distance
    light_hit.colour = light.colour * light.intensity
    
    # PDF calculation
    if light.type == POINT:
        light_hit.pdf = 4.0 * PI * distance * distance
    else:
        light_hit.pdf = 1.0 # Simplified for directional/abstract
        
    # Material evaluation
    # Assuming diffuse shading for simplicity as per S2's max(0, dot(n, d))
    # In a full BRDF, this would be f_r * cos(theta)
    f_r = material.evaluate(n, d_l) # Returns color * cos(theta) if diffuse
    
    # Power Heuristic (assuming path sampling PDF is 1 for simplicity in this snippet)
    # S2 uses: weight = powerHeuristic(1, lightHit.pdf, 1, pdf)
    # If pdf (path) is 1, weight = lightHit.pdf^2 / (lightHit.pdf^2 + 1)
    # However, S2 code snippet shows: add material * lightHit.colour * weight / lightHit.pdf
    # This implies the final term is roughly material * colour * weight / pdf
    
    weight = (light_hit.pdf * light_hit.pdf) / (light_hit.pdf * light_hit.pdf + 1.0)
    
    contribution = f_r * light_hit.colour * weight / light_hit.pdf
    
    # Scale by number of lights if uniform sampling
    if len(lights) > 1:
        contribution *= len(lights)
        
    return contribution
```

## Subtopics

### [Direct Illumination Sampling with Mesh Intersection](4450-direct-illumination-sampling-with-mesh-intersection.md)
Computes direct illumination for surface points by sampling lights and intersecting explicit triangle meshes. Chosen for polygonal scenes where precise geometric occlusion is required.

### [Light Ray Sampling](4885-light-ray-sampling.md)
Steps along the light direction in a volume, integrating density and phase functions. Chosen for participating media to capture soft, volumetric shadows and subsurface scattering effects.

## Operating characteristics
- **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of intersection points and $M$ is the number of lights (if all are tested) or $O(N)$ if one light is sampled per point. Occlusion testing is $O(K)$ where $K$ is the number of objects in the scene.
- **Memory Complexity:** $O(1)$ per point, excluding scene storage.
- **Performance:** Efficient for scenes with few lights. Noise increases with multiple lights if not sampled properly. Requires robust intersection testing [S1, unofficial].
- **Strengths:** Reduces noise compared to brute-force shadow rays for all lights. Handles multiple light sources naturally.
- **Limitations:** High variance if lights are small or distant. Does not account for indirect illumination (requires [Path Tracing and Sampling](2526-path-tracing-and-sampling.md) or [Light Sampling for NEE](2616-light-sampling-for-nee.md)).

## Background
Originated in the context of global illumination algorithms, specifically as an optimization to visualize shadows and light contributions by explicitly shooting rays to light sources [S1, unofficial]. It is a core component of Monte Carlo path tracing and bidirectional path tracing implementations [S2, unofficial].
