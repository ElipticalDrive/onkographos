# Shadow Mapping

Also called: Depth Map Shadowing, Light Space Depth Testing

## Overview
Shadow Mapping is a technique to efficiently render shadows by rendering the scene from the light's point of view to generate a depth map (shadow map) [S1, unofficial]. It determines if a point is occluded by another object from the light's perspective [S1, unofficial]. It differs from [Shadow Ray Casting](2796-shadow-ray-casting.md) by using pre-rendered depth buffers instead of per-pixel ray traversal, and from [Two-Pass Shadow Casting (Kajiya and Von Herzen)](2196-two-pass-shadow-casting-kajiya-and-von-herzen.md) by relying on a single depth buffer comparison rather than geometric silhouette processing.

## How it works
**Inputs:** Scene geometry, light position, light direction, light aperture angle, shadow map resolution.
**Outputs:** A binary shadow value (1.0 for lit, 0.0 for shadow) per fragment.

**Data Structures:**
*   **Shadow Map:** A 2D texture (typically `GL_DEPTH_COMPONENT` or `GL_R32F`) storing depth values in light space.
*   **Light Space Coordinates:** Homogeneous coordinates $(x_l, y_l, z_l, w_l)$ resulting from transforming world positions by the light's view-projection matrix.

**Parameters:**
*   **Bias:** A small positive value added to the depth comparison to prevent shadow acne [S1, unofficial]. Typical values depend on scene scale and depth precision; not given in the sources as a specific number [S1, unofficial].
*   **Spotlight Angle:** The aperture angle for the perspective projection [S1, unofficial].
*   **Near/Far Planes:** Depth bounds for the light's frustum [S1, unofficial].

**Steps:**

1.  **Generate Light View-Projection Matrix:**
    For a spotlight, construct the view matrix using the light's position and direction. To avoid gimbal lock when the light direction is parallel to the world up vector, select an appropriate up vector [S1, unofficial]:
    $$
    \text{up} = \begin{cases} 
    \text{normalize}(\text{cross}(\text{vec3}(0,0,1), \text{dir})) & \text{if } |\text{dot}(\text{dir}, \text{vec3}(0,0,1))| < 0.99 \\
    \text{normalize}(\text{cross}(\text{vec3}(1,0,0), \text{dir})) & \text{otherwise}
    \end{cases}
    $$
    Create the view matrix $V = \text{lookAt}(\text{pos}, \text{pos} + \text{dir}, \text{up})$ and the projection matrix $P = \text{perspective}(\text{angle}, 1.0, \text{near}, \text{far})$ [S1, unofficial]. The final matrix is $M = P \times V$.

2.  **Render Shadow Map:**
    Render the scene geometry using matrix $M$ into a depth buffer. This stores the minimum depth $z_l$ of visible surfaces from the light's perspective [S1, unofficial].

3.  **Sample Shadow Map (Fragment Shader):**
    For each fragment in the main pass:
    a. Transform the fragment's world position $P_{world}$ to light space: $P_{light} = M \times P_{world}$.
    b. Perform perspective division to get normalized device coordinates (NDC) in light space:
    $$
    P_{ndc} = \left( \frac{x_l}{w_l}, \frac{y_l}{w_l}, \frac{z_l}{w_l} \right)
    $$
    c. Convert NDC to texture coordinates (assuming OpenGL-style depth range $[0, 1]$):
    $$
    \text{coords} = P_{ndc} \times 0.5 + 0.5
    $$
    d. Sample the depth value from the shadow map:
    $$
    \text{shadowDepth} = \text{texture}(u_{\text{shadowMap}}, \text{coords}.xy).r
    $$
    e. Compare the fragment's depth against the stored depth, applying a bias to mitigate self-shadowing artifacts (shadow acne) [S1, unofficial]:
    $$
    \text{shadowVal} = \begin{cases} 
    1.0 & \text{if } \frac{z_l}{w_l} \ge \text{shadowDepth} + \text{bias} \\
    0.0 & \text{otherwise}
    \end{cases}
    $$

**Edge Cases and Pitfalls:**
*   **Shadow Acne:** Caused by quantization errors in the depth buffer where a surface incorrectly shadows itself. Mitigated by the bias parameter [S1, unofficial].
*   **Perspective Distortion:** Standard shadow maps suffer from uneven sampling density. Not addressed in the basic method described [S1, unofficial].
*   **Light Space Calculation:** Incorrect up vector selection when the light direction aligns with the world up vector causes singular view matrices [S1, unofficial].

## Subtopics

### Variance Shadow Mapping
A shadow mapping technique that smoothens depth to calculate the probability of shadows using Chebyshev's inequality, producing soft shadow edges instead of the abrupt 0/1 values of naive shadow mapping [S2]. It requires storing two depth maps and filtering them, resulting in only slightly increased computational overhead compared to standard shadow mapping [S2]. It is chosen when soft shadows are desired with minimal performance cost [S2].

## Operating characteristics
*   **Time Complexity:** $O(N)$ for rendering the shadow map (where $N$ is the number of triangles) and $O(1)$ per fragment for sampling.
*   **Memory Complexity:** $O(W \times H)$ for the shadow map texture, where $W$ and $H$ are the resolution.
*   **Strengths:** Efficient for static scenes; no per-pixel ray tracing overhead; simple to implement [S1, unofficial].
*   **Limitations:** Produces hard shadows in the basic form; suffers from aliasing and precision issues (Peter Panning, Shadow Acne) without bias or variance techniques [S1, unofficial][S2].
*   **When to use:** Real-time rendering where performance is critical and hard shadows are acceptable, or when extended to Variance Shadow Mapping for soft shadows [S1, unofficial][S2].
*   **When not to use:** When physically accurate soft shadows with complex penumbras are required without approximation [S2].

## Background
Shadow mapping was introduced by Lance Williams in 1978 [S1, unofficial]. It is widely used in real-time graphics pipelines for efficient shadow generation [S1, unofficial]. The method described here focuses on spotlights for indoor scenes, as directional lights are less suitable at close distances due to perspective effects, and point lights require more complex cube map handling [S1, unofficial].
