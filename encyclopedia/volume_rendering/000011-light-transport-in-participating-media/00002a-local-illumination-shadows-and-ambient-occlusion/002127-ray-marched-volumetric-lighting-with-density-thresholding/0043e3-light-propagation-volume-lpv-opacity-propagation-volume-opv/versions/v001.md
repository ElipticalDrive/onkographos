# Light Propagation Volume (LPV) / Opacity Propagation Volume (OPV)

Also called: Cell-to-cell optical depth propagation, Crytek's algorithm, Opacity Propagation, Opacity Propagation Volume (OPV) Propagation, Opacity Propagation Volume (OPV) method, Propagation - Pixel shader

## Overview
Light Propagation Volume (LPV), specifically the Opacity Propagation Volume (OPV) variant, is a real-time method for precomputing the optical depth $T(S,X)$ from each light source $S$ to each cell $X$ in a 3D grid [S1]. It solves the problem of efficiently calculating light attenuation (extinction) through heterogeneous participating media by propagating density information radially from light sources through a 3D volume on the GPU [S1]. Unlike standard radiance propagation which suffers from rapid scattering errors in dense media, OPV focuses on accurate optical depth integration, enabling correct shadowing and attenuation for subsequent ray-marched rendering [S1]. It builds on [Ray-marched Volumetric Lighting with Density Thresholding](2456-ray-marched-volumetric-lighting-with-density-thresholding.md) by providing the precomputed attenuation data required for that rendering step.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of light sources $S$, each with a local extinction coefficient. A medium density model defined as a sum of Radial Basis Functions (RBFs).
*   **Output:** An Opacity Propagation Volume (OPV) storing the optical depth integral $T(X,S)$ for each cell $X$ and light source $S$.

**Data Structures:**
1.  **Extinction Volume (EV):** A 3D texture storing the sampled density of the medium.
    *   **Format:** 3D 16-bit floating point texture.
    *   **Dimensions:** Same as the OPV.
    *   **Content:** Extinction coefficient values sampled from the RBF density model.
2.  **Opacity Propagation Volume (OPV):** A 3D texture storing optical depth.
    *   **Format:** 3D 16-bit floating point texture.
    *   **Dimensions:** Same as the EV.
    *   **Content:** One optical depth integral per light source. One texture is needed per group of four lights [S1].
3.  **Visited Texture:** An additional texture (format not specified, typically boolean or integer) used to mark texels that have already been computed or reached during propagation [S1].

**Parameters:**
*   **Grid Resolution:** The dimensions of the 3D textures (e.g., $20^3$ as used in the source experiments) [S1].
*   **Light Grouping:** Lights are processed in groups of four to fit into a single OPV texture [S1].

**Algorithm Steps:**

1.  **Density Injection (EV Construction):**
    *   Model the medium's extinction function as a sum of Radial Basis Functions (RBFs) [S1].
    *   Sample this density into the Extinction Volume (EV) [S1].
    *   *Note:* The source provides a fragment shader snippet for sampling RBFs into a pixel, but the EV construction is described as a sampling process [S1].

2.  **OPV Initialization:**
    *   Clear the two OPV textures (ping-pong buffers) so that each texel starts with zero [S1].
    *   For cells containing a light source $S$, initialize the corresponding texel in the OPV with the light source's local extinction coefficient [S1].

3.  **Propagation Loop (Cell-to-Cell Optical Depth Propagation):**
    *   The propagation originates from a single cell containing the light and advances radially like a wavefront [S1].
    *   Use a ping-pong buffer approach with at least two copies of the OPV texture because reading and writing to the same texture in a shader is not available [S1].
    *   Each single propagation step involves a plane sweep along the texture slices [S1].
    *   Use the **Visited Texture** to discard cells which have already been computed or have not been reached yet, speeding up the process [S1].
    *   The gathering algorithm is implemented in a fragment shader called on a fullscreen quad [S1].

**Edge Cases and Pitfalls:**
*   **Texture Read/Write Conflict:** Reading and writing to the same texture in a shader is not available, requiring ping-pong buffering with at least two copies of each OPV texture [S1].
*   **Visited State:** Correctly marking visited texels is crucial for performance and correctness, as it discards cells that have already been computed or have not been reached yet [S1].
*   **Light Grouping:** Lights must be grouped in sets of four to fit into a single OPV texture [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. The propagation is GPU-based and uses a wavefront approach with visited texel culling to speed up the process [S1].
*   **Memory Complexity:** Requires at least two copies of the OPV texture (ping-pong buffers) plus one EV texture and one Visited texture [S1]. Each OPV texture is a 3D 16-bit float texture with dimensions matching the EV [S1]. One OPV texture handles four light sources [S1].
*   **Measured Performance:** The method achieves real-time performance on conventional hardware. In the source's Cornell box experiments with a $20^3$ resolution, it rendered mediums with different complexities at varying FPS (e.g., 27000 FPS for 9 lights, 142 FPS for 9 lights in a different configuration, though the table context is unclear) [S1].
*   **Strengths:** Real-time performance, easy to implement and integrate, handles heterogeneous isotropic scattering media, renders scattering effects such as halos around light sources [S1].
*   **Limitations:** The source does not explicitly list limitations, but the method relies on a 3D grid which may have resolution constraints. The specific propagation formula is a "modified version of Crytek's algorithm," implying potential complexity in implementation details not fully covered [S1].

## Background
*   **Origin:** The method was presented in the paper "Illuminating and Rendering Heterogeneous Participating Media in Real Time using Opacity Propagation" by authors from LIGM, Marne-la-Vallée, France [S1].
*   **History:** It is described as a new approach for real-time illumination of participating media, using a modified version of Crytek's algorithm for opacity propagation [S1].
*   **Usage:** Used for real-time rendering of single scattering effects in heterogeneous participating media, integrating with ray-marching for final image synthesis [S1].
