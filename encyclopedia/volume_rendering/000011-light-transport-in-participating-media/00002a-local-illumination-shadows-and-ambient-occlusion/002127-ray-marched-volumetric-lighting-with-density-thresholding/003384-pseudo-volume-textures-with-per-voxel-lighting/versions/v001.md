# Pseudo Volume Textures with Per-Voxel Lighting

Also called: Custom Implementation (Pseudo Volume Textures with Per-Voxel Lighting), Direct Volume Rendering with Pseudo Volume Textures, Pseudo Volume Textures, YouTube tutorial series based on ShaderBits Blog

## Overview
This method implements direct volume rendering using 2D textures containing tiles that represent low-resolution 2D slices of the volume, referred to as 'pseudo volume textures' [S1, S2, unofficial]. It solves the problem of rendering dynamic volumetric data by allowing the volume to be "painted" at runtime [S1, S2, unofficial]. It differs from true 3D volume textures by restricting effective maximum volume resolution further, but distinguishes itself from its parent [Ray-marched Volumetric Lighting with Density Thresholding](2456-ray-marched-volumetric-lighting-with-density-thresholding.md) by recomputing lighting for each frame via secondary ray marches for every voxel sample [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 2D texture atlas (pseudo volume texture) containing tiled 2D slices of the volume data.
- Input: Primary ray direction and origin for the viewer.
- Input: Light source position and direction.
- Output: Final color buffer with per-voxel lighting.

**Data Structures:**
- **Pseudo Volume Texture:** A 2D texture where each tile represents a 2D slice of the volume. The resolution is lower than a true 3D volume texture [S1, S2, unofficial].
- **Voxel Sample:** A point along the primary ray intersecting the volume.

**Steps:**
1. For each pixel in the screen space, cast a primary ray into the volume.
2. Sample the pseudo volume texture along the primary ray to obtain voxel density and color data [S1, S2, unofficial].
3. For each voxel sample taken along the primary ray, perform a secondary ray march towards the light source [S1, S2, unofficial].
4. Accumulate lighting along the secondary ray to determine the illumination for the current voxel sample [S1, S2, unofficial].
5. Composite the lit voxel color into the final pixel color.

## Subtopics

### Precomputed Lighting Cache
An optimization where lighting is precomputed and updated only on voxel content or light source changes. It requires an additional render pass and custom C++ and shader code [S1, S2, unofficial].

### TBRayMarcher Plugin
An existing plugin for Unreal Engine based on an implementation by Sundén and Ropinski [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Prohibitive for larger volumes due to the per-voxel secondary ray march for lighting [S1, S2, unofficial].
- **Memory Complexity:** Restricted by the 2D texture atlas structure, limiting effective maximum volume resolution compared to true volume textures [S1, S2, unofficial].
- **Strengths:** Allows runtime "painting" of the volume, making it fully dynamic [S1, S2, unofficial].
- **Limitations:** Performance impact is prohibitive for larger volumes; effective maximum volume resolution is restricted [S1, S2, unofficial].
- **When to use:** When dynamic volume painting is required and volume size is small enough to tolerate the performance cost of per-frame lighting recomputation [S1, S2, unofficial].
- **When not to use:** For large volumes where performance is critical [S1, S2, unofficial].

## Background
This approach was used in the ARENA2 visualization dome [S1, S2, unofficial]. It is based on an implementation by Sundén and Ropinski [S1, unofficial]. The technique is part of a survey on rendering large volume datasets in Unreal Engine 5 [S1, S2, unofficial].
