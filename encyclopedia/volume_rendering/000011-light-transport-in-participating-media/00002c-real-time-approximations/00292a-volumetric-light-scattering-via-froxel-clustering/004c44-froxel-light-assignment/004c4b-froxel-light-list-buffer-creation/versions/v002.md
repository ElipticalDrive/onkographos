# Froxel Light List Buffer Creation

Also called: Froxel Light List Buffer Allocation

## Overview
This method prepares the GPU buffers required to store the variable-length light lists for each froxel after they have been assigned. It allocates the necessary memory structures and executes compute shaders to populate the light indices, ensuring that subsequent rendering passes can efficiently access the lights relevant to each volume voxel. It differs from its parent [Froxel Light Assignment](13184-froxel-light-assignment.md) by focusing on the buffer allocation, offset calculation, and index population rather than the spatial assignment logic itself.

## How it works
The method consists of buffer allocation, a reduction pass to determine total light count, an atomic assignment pass to populate indices, and a prefix-sum scan to compute offsets.

### Inputs and Outputs
**Inputs:**
- `Grid`: 3D grid dimensions $(G_X, G_Y, G_Z)$ defining the froxel structure.
- `NumLights_RT`: Number of real-time lights in the scene.
- `MaxLightsPerFroxel`: Maximum number of lights assigned to any single froxel.

**Outputs:**
- `FroxelLists`: A structure containing four buffers (see Layout).

### Data Structures and Layout
The `FFroxelLists` structure contains the following buffers, all created as `RWStructuredBuffer` with `BUF_ShaderResource | BUF_UnorderedAccess` flags:

1.  **Counts**: `RWStructuredBuffer<uint32>`, size $G_X \times G_Y \times G_Z$. Stores the number of lights assigned to each froxel.
2.  **Offsets**: `RWStructuredBuffer<uint32>`, size $G_X \times G_Y \times G_Z$. Stores the starting index in `LightIndices` for each froxel.
3.  **TotalIndices**: `RWStructuredBuffer<uint32>`, size 1. Stores the total number of light indices across all froxels.
4.  **LightIndices**: `RWStructuredBuffer<uint32>`, size $(G_X \times G_Y \times G_Z) \times MaxLightsPerFroxel$. Stores the actual light indices for all froxels, packed sequentially.

### Steps

1.  **Calculate Froxel Count**:
    $$N_{froxel} = G_X \times G_Y \times G_Z$$

2.  **Allocate Buffers**:
    Allocate the four buffers defined in the Layout section with sizes derived from $N_{froxel}$ and `MaxLightsPerFroxel`.

3.  **Compute Total Indices (Reduction)**:
    -   Clear `TotalIndices` UAV to 0.
    -   Execute the `FFroxelTotalIndicesCS` compute shader.
    -   Group count: $(1, 1, 1)$.
    -   This pass sums the `Counts` buffer to determine the total number of light entries.

4.  **Assign Light Indices**:
    -   Clear `LightIndices` UAV to 0.
    -   Reuse the `Counts` buffer as `FroxelHeads` (atomic head pointer) and clear it to 0.
    -   Execute the `FFroxelAssignLightsCS` compute shader.
    -   Group count: $\lceil NumLights_{RT} / 64 \rceil$.
    -   Each light thread atomically increments the head for its assigned froxel and writes the light index to `LightIndices` at the returned position.

5.  **Compute Offsets (Prefix Sum)**:
    The offsets are computed using a 3-pass Blelloch scan to handle the 3D grid efficiently:
    -   **Pass A (Intra-Slice Scan)**: Perform a prefix sum on `Counts` within each Z-slice (size $G_X \times G_Y$). Store intermediate results in `ZSliceTotals` and final offsets in `Offsets`.
    -   **Pass B (Inter-Slice Scan)**: Perform a prefix sum on the `ZSliceTotals` buffer (size $G_Z$) to get cumulative sums for each Z-slice. Store in `ZSliceOffsets`.
    -   **Pass C (Add Z-Slice Offsets)**: Add the corresponding `ZSliceOffsets` value to each froxel's offset in the `Offsets` buffer.

### Pseudocode

```python
def create_froxel_light_list_buffers(grid: tuple, num_lights: int, max_lights_per_froxel: int):
    """
    Allocates and populates buffers for froxel light lists.
    grid: (Gx, Gy, Gz)
    """
    Gx, Gy, Gz = grid
    N_froxel = Gx * Gy * Gz
    Z_slice_size = Gx * Gy

    # 1. Allocate Buffers
    # All buffers are RWStructuredBuffer with ShaderResource | UnorderedAccess
    counts = allocate_buffer(N_froxel, dtype=uint32)
    offsets = allocate_buffer(N_froxel, dtype=uint32)
    total_indices = allocate_buffer(1, dtype=uint32)
    light_indices = allocate_buffer(N_froxel * max_lights_per_froxel, dtype=uint32)
    
    # Temporary buffers for prefix sum
    z_slice_totals = allocate_buffer(Gz, dtype=uint32)
    z_slice_offsets = allocate_buffer(Gz, dtype=uint32)

    # 2. Compute Total Indices
    clear(total_indices, 0)
    execute_compute_shader(
        shader=FFroxelTotalIndicesCS,
        params={
            'FroxelSharedUB': shared_ub,
            'View': view_uniform_buffer,
            'Lights': lights_srv,
            'FroxelLightCounts': counts
        },
        group_count=(1, 1, 1)
    )

    # 3. Assign Light Indices
    clear(light_indices, 0)
    clear(counts, 0) # Reuse counts as atomic heads
    
    execute_compute_shader(
        shader=FFroxelAssignLightsCS,
        params={
            'FroxelSharedUB': shared_ub,
            'View': view_uniform_buffer,
            'Lights': lights_srv,
            'FroxelLightCounts': counts, # Acts as heads
            'FroxelLightIndices': light_indices
        },
        group_count=ceil(num_lights / 64)
    )

    # 4. Compute Offsets (3-Pass Blelloch Scan)
    
    # Pass A: Prefix sum within each Z-slice
    clear(z_slice_totals, 0)
    clear(offsets, 0)
    execute_compute_shader(
        shader=FFroxelOffsetPassACS,
        params={
            'FroxelSharedUB': shared_ub,
            'FroxelLightCounts': counts,
            'FroxelLightOffsets': offsets,
            'ZSliceTotals': z_slice_totals
        },
        group_count=get_group_count(N_froxel, 64) # Or appropriate tile size
    )

    # Pass B: Prefix sum of Z-slice totals
    clear(z_slice_offsets, 0)
    execute_compute_shader(
        shader=FFroxelOffsetPassBCS,
        params={
            'ZSliceTotals': z_slice_totals,
            'ZSliceOffsets': z_slice_offsets
        },
        group_count=get_group_count(Gz, 64)
    )

    # Pass C: Add Z-slice offsets to individual froxel offsets
    execute_compute_shader(
        shader=FFroxelOffsetPassCCS,
        params={
            'FroxelLightOffsets': offsets,
            'ZSliceOffsets': z_slice_offsets,
            'GridSize': grid
        },
        group_count=get_group_count(N_froxel, 64)
    )

    return {
        'Counts': counts,
        'Offsets': offsets,
        'TotalIndices': total_indices,
        'LightIndices': light_indices
    }
```

### Parameters and Edge Cases
-   **MaxLightsPerFroxel**: Must be large enough to avoid overflow. If exceeded, light indices are dropped. [S1, unofficial]
-   **Atomic Contention**: The `FFroxelAssignLightsCS` uses atomic operations on `Counts` (as heads). High light density per froxel may cause contention. [S1, unofficial]
-   **Grid Dimensions**: The prefix sum assumes a Z-slice major order. $G_X \times G_Y$ defines the slice size. [S1, unofficial]

## Subtopics

### Froxel Light Index Assignment
Computes the list of light indices for each froxel, storing results in `FroxelLists.LightIndices`. It first computes the total number of indices using a reduction pass, then assigns indices using an atomic counter. It differs from the parent by focusing on the actual index population rather than buffer allocation. [S1, unofficial]

## Operating characteristics
-   **Time Complexity**: $O(N_{froxel} + N_{lights})$ for assignment and $O(N_{froxel})$ for prefix sum. The prefix sum is implemented in 3 passes, so constant factors are higher.
-   **Memory Complexity**: $O(N_{froxel} \times MaxLightsPerFroxel)$ for `LightIndices`, plus $O(N_{froxel})$ for `Counts` and `Offsets`.
-   **Performance**: The atomic assignment pass can be a bottleneck if many lights map to the same froxel. The 3-pass prefix sum is efficient for large grids but requires temporary buffers. [S1, unofficial]
-   **Strengths**: Efficiently handles variable-length light lists. GPU-native.
-   **Limitations**: Requires significant temporary memory for prefix sum. Atomic contention may reduce throughput. [S1, unofficial]

## Background
This method is part of the Unreal Engine 5 Froxel Lighting system, an unofficial implementation of volumetric light scattering using froxel clustering. It was developed by Armin Tajik. [S1, unofficial]
