# Noise Kernel Generation

Also called: GetNoiseKernel

## Overview
Noise Kernel Generation constructs a rotation matrix aligned with the light direction to transform a fixed set of 6 offset vectors into a local coordinate system [S1, unofficial]. It serves as the foundation for Random Cone Rotation by providing the directional basis for sampling indirect diffuse lighting in Voxel Cone Tracing [S1, unofficial]. Unlike TraceDiffuse, which uses a tangent-space grid based on the surface normal, Noise Kernel Generation relies on the light vector to define the cone distribution [S1, unofficial][S2, unofficial].

## How it works
**Inputs:**
- `lightDirection`: A normalized 3D vector representing the direction of the light source.

**Outputs:**
- `sunRotMatrix`: A $3 \times 3$ rotation matrix.
- `noise_kernel`: An array of 6 transformed 3D vectors.

**Data Structures:**
The kernel consists of 6 fixed base offsets defined in a local space. These are transformed by the rotation matrix to align with the light direction.

Base offsets (`base_offsets[6]`):
1. $(0.1, 0.25, -0.15)$
2. $(0.2, 0.50, 0.20)$
3. $(-0.2, 0.10, -0.10)$
4. $(-0.05, 0.75, 0.05)$
5. $(-0.1, 1.00, 0.00)$
6. $(0.0, 3.00, 0.00)$

**Steps:**
1. **Determine Reference Vector:** Identify the component of `lightDirection` with the largest absolute value. Let this be $c_{max}$. Create a unit vector `maxCompUnitVector` aligned with this axis. For example, if $|x|$ is the maximum, `maxCompUnitVector` is $(1, 0, 0)$ or $(-1, 0, 0)$ depending on the sign of $x$ to ensure alignment, though the source specifies using the absolute magnitude component to define the axis [S1, unofficial]. Specifically, if $|x|$ is max, the vector is $(|x|, 0, 0)$ normalized, effectively $(1, 0, 0)$ or $(-1, 0, 0)$. The source text says "if |x| is max, vector is (|x|, 0, 0)", which implies a non-normalized intermediate or a specific construction. Standard practice for constructing a basis from a vector is to pick an arbitrary orthogonal vector. The source describes: `maxCompUnitVector` is created based on the max component. Let's assume standard basis alignment: if $|x| \ge |y|$ and $|x| \ge |z|$, `maxCompUnitVector` = $(1, 0, 0)$. If $|y|$ is max, $(0, 1, 0)$. If $|z|$ is max, $(0, 0, 1)$. The source note "vector is (|x|, 0, 0)" suggests using the magnitude to select the axis, but for cross products, a unit vector is required. We normalize the selected axis vector.
2. **Compute Z-axis:** Calculate the cross product of `lightDirection` and `maxCompUnitVector` to get the local Z-axis vector `zcom`.
   $$ zcom = \text{cross}(\text{lightDirection}, \text{maxCompUnitVector}) $$
   If `lightDirection` is parallel to `maxCompUnitVector`, the cross product is zero. A guard is needed [G].
3. **Compute X-axis:** Calculate the cross product of `zcom` and `lightDirection` to get the local X-axis vector `xcom`.
   $$ xcom = \text{cross}(zcom, \text{lightDirection}) $$
4. **Construct Rotation Matrix:** Form the $3 \times 3$ matrix `sunRotMatrix` using `xcom`, `lightDirection`, and `zcom` as columns.
   $$ \text{sunRotMatrix} = \begin{bmatrix} | & | & | \\ xcom & \text{lightDirection} & zcom \\ | & | & | \end{bmatrix} $$
   Note: The source specifies columns as `xcom`, `lightDirection`, `zcom` [S1, unofficial].
5. **Transform Kernel Offsets:** For each base offset $b_i$ in `base_offsets`, compute the final kernel vector $k_i$:
   $$ k_i = \text{sunRotMatrix} \times b_i $$
   Store $k_i$ in `noise_kernel[i]`.

**Pseudocode:**
```python
def generate_noise_kernel(light_direction):
    # Normalize input
    L = normalize(light_direction)
    
    # Step 1: Determine reference vector
    abs_x = abs(L.x)
    abs_y = abs(L.y)
    abs_z = abs(L.z)
    
    if abs_x >= abs_y and abs_x >= abs_z:
        ref_vec = vec3(1.0, 0.0, 0.0)
    elif abs_y >= abs_x and abs_y >= abs_z:
        ref_vec = vec3(0.0, 1.0, 0.0)
    else:
        ref_vec = vec3(0.0, 0.0, 1.0)
        
    # Step 2: Compute Z-axis
    zcom = cross(L, ref_vec)
    
    # Guard against parallel vectors (degenerate case)
    # If L is parallel to ref_vec, cross product is zero.
    # Use a different reference vector or handle specifically.
    # Standard fallback: if length(zcom) < epsilon, use a different axis for ref_vec.
    if length(zcom) < 1e-6:
        if abs_x < 0.9:
            ref_vec = vec3(1.0, 0.0, 0.0)
        else:
            ref_vec = vec3(0.0, 1.0, 0.0)
        zcom = cross(L, ref_vec)
        
    zcom = normalize(zcom)
    
    # Step 3: Compute X-axis
    xcom = cross(zcom, L)
    xcom = normalize(xcom)
    
    # Step 4: Construct Rotation Matrix
    # Columns are xcom, L, zcom
    rot_matrix = mat3(xcom, L, zcom)
    
    # Step 5: Transform Kernel Offsets
    base_offsets = [
        vec3(0.1, 0.25, -0.15),
        vec3(0.2, 0.50, 0.20),
        vec3(-0.2, 0.10, -0.10),
        vec3(-0.05, 0.75, 0.05),
        vec3(-0.1, 1.00, 0.00),
        vec3(0.0, 3.00, 0.00)
    ]
    
    noise_kernel = []
    for offset in base_offsets:
        transformed = rot_matrix * offset
        noise_kernel.append(transformed)
        
    return rot_matrix, noise_kernel
```

**Parameters:**
- No adjustable parameters for the kernel generation itself. The base offsets are hardcoded [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Degenerate Input:** If `lightDirection` is parallel to the chosen reference axis, the cross product for `zcom` becomes zero. The pseudocode includes a guard to select an alternative reference vector [G].
- **Precision:** The large Y-component in the last base offset $(0.0, 3.00, 0.00)$ may require careful handling of floating-point precision during transformation if the scene scale is very large or very small [S1, unofficial].

## Subtopics

### TraceDiffuse
Approximates indirect diffuse lighting by casting multiple cones in a tangent space around the surface normal rather than the light direction [S2, unofficial]. It defines 9 fixed cone directions in a $3 \times 3$ grid on the upper hemisphere ($z=1$) [S2, unofficial]. It calculates an aperture based on an `apertureAngle` parameter (default 30 degrees, must be $< 45$ degrees) [S2, unofficial]. It generates random tangent vectors `xtan` and `ytan` based on position and time to jitter the sampling, constructing a tangent space matrix `tanSpace = mat3(xtan, ytan, normal)` [S2, unofficial]. It loops `CONES` times (default 5) to transform cone directions via `tanSpace` and calls `ConeTracing` [S2, unofficial]. Choose TraceDiffuse when surface-normal-based indirect lighting is required, as opposed to light-direction-based sampling [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ for kernel generation, as it involves a fixed number of vector operations and matrix multiplications.
- **Memory Complexity:** $O(1)$, storing a fixed $3 \times 3$ matrix and 6 vectors.
- **Performance:** Extremely fast, suitable for real-time execution per pixel or per voxel [S1, unofficial].
- **Strengths:** Provides a consistent, deterministic rotation basis for cone tracing aligned with the light source [S1, unofficial].
- **Limitations:** The fixed kernel offsets may not adapt to varying scene geometries or lighting conditions beyond the direction [S1, unofficial].

## Background
Noise Kernel Generation is part of the Voxel Cone Tracing pipeline, specifically within the Real-time approximations for Light Transport in Participating Media [S1, unofficial]. It was implemented in the `realtime-volumetric-cloudscapes` project by erickTornero [S1, unofficial]. The method is used to sample indirect lighting in volumetric scenes, such as clouds, by rotating a predefined set of cone directions to align with the sun [S1, unofficial].
