# Random Cone Rotation
Also called: Randomized Cone Orientation, Cone Jittering
## Overview
Random Cone Rotation is a technique used in Voxel Cone Tracing to mitigate the blocky artifacts inherent in sparse cone sampling for diffuse indirect lighting [S1, unofficial]. By randomly rotating a fixed set of cones around the surface normal, it breaks up the rigid geometric structure of the sampling pattern [S1, unofficial]. This method is a specific implementation of the broader Diffuse Cone Distribution strategy [5677-diffuse-cone-distribution.md].
## How it works
**Inputs and Outputs:**
- Input: A set of $N$ cone directions $\{\mathbf{d}_i\}$ defined in a local coordinate system aligned with the surface normal $\mathbf{n}$, and a random seed or value $\rho \in [0, 1)$.
- Output: A rotated set of cone directions $\{\mathbf{d}'_i\}$ in world or view space.

**Data Structures:**
The standard distribution consists of 5 cones: one aligned with the normal $\mathbf{n}$, and four perpendicular to it [S1, unofficial].
- Cone 0: Direction $\mathbf{d}_0 = \mathbf{n}$.
- Cones 1-4: Directions $\mathbf{d}_1, \dots, \mathbf{d}_4$ lie in the tangent plane perpendicular to $\mathbf{n}$, typically spaced at 90° intervals.
- All cones share a fixed aperture angle $\alpha = 30^\circ$ [S1, unofficial].

**Steps:**
1. Generate a random rotation angle $\theta$ uniformly distributed in $[0, 2\pi)$ using the input random value $\rho$.
2. Construct a rotation matrix $R$ that rotates vectors around the axis $\mathbf{n}$ by angle $\theta$.
3. Apply $R$ to each cone direction $\mathbf{d}_i$ to obtain the rotated direction $\mathbf{d}'_i = R \mathbf{d}_i$.
4. Use $\{\mathbf{d}'_i\}$ for cone tracing.

**Pseudocode:**
```python
import math
import numpy as np

def random_cone_rotation(normal: np.ndarray, random_value: float) -> list:
    """
    Rotates a fixed set of 5 diffuse cones around the surface normal.
    
    Args:
        normal: Surface normal vector (3,), assumed normalized.
        random_value: Random float in [0, 1) to determine rotation angle.
        
    Returns:
        List of 5 rotated cone direction vectors (3,).
    """
    # 1. Define the base cone directions in local space
    # Cone 0 is along the normal
    base_cones = [
        np.array([0.0, 0.0, 1.0]),  # Along Z (normal)
        np.array([1.0, 0.0, 0.0]),  # Perpendicular X
        np.array([0.0, 1.0, 0.0]),  # Perpendicular Y
        np.array([-1.0, 0.0, 0.0]), # Perpendicular -X
        np.array([0.0, -1.0, 0.0])  # Perpendicular -Y
    ]
    
    # 2. Generate rotation angle
    theta = random_value * 2.0 * math.pi
    
    # 3. Construct rotation matrix around the normal axis
    # Using Rodrigues' rotation formula or axis-angle representation
    # Axis is 'normal', angle is 'theta'
    # For a unit axis k=(kx, ky, kz), the rotation matrix R is:
    # R = I + sin(theta)*K + (1-cos(theta))*K^2
    # where K is the cross-product matrix of k
    
    kx, ky, kz = normal
    s = math.sin(theta)
    c = math.cos(theta)
    one_minus_c = 1.0 - c
    
    # Cross-product matrix K
    K = np.array([
        [0.0, -kz, ky],
        [kz, 0.0, -kx],
        [-ky, kx, 0.0]
    ])
    
    # Identity matrix
    I = np.eye(3)
    
    # Rotation matrix R
    R = I + s * K + one_minus_c * (K @ K)
    
    # 4. Rotate each base cone direction
    rotated_cones = []
    for base_dir in base_cones:
        rotated_dir = R @ base_dir
        rotated_cones.append(rotated_dir)
        
    return rotated_cones
```

**Parameters:**
- Aperture angle: $30^\circ$ [S1, unofficial].
- Number of cones: 5 (1 normal, 4 perpendicular) [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Noise:** The randomization introduces temporal and spatial noise into the lighting result [S1, unofficial]. This requires temporal filtering or accumulation to converge.
- **Precision:** Ensure the normal vector is normalized before constructing the rotation matrix to avoid scaling artifacts.
- **Degenerate Input:** If the normal is zero, the rotation is undefined. Guard against this in implementation.

## Subtopics
## Operating characteristics
- **Time Complexity:** $O(1)$ per cone, as the number of cones is fixed (5). The rotation calculation is constant time.
- **Memory Complexity:** $O(1)$, storing only the base cone directions and the rotation matrix.
- **Strengths:** Effectively reduces blocky artifacts caused by sparse sampling without increasing the number of cones [S1, unofficial].
- **Limitations:** Introduces noise, which may require additional filtering or temporal accumulation [S1, unofficial].
- **When to Use:** When using a small number of cones for diffuse indirect lighting in real-time Voxel Cone Tracing and blocky artifacts are visible.
- **When Not to Use:** When noise is unacceptable without post-processing, or when higher fidelity is required (consider more cones or different sampling strategies).

## Background
Random Cone Rotation was introduced in the context of Voxel Cone Tracing for real-time global illumination [S1, unofficial]. It addresses the visual quality issues arising from the use of very few cones (5) to approximate the diffuse hemisphere integral. The method is part of a broader effort to make voxel-based global illumination feasible in real-time applications by balancing performance and visual quality.
