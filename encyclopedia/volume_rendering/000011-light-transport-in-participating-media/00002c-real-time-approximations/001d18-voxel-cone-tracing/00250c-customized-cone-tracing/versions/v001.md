# Customized Cone Tracing

Also called: Voxel Cone Tracing with modifications

## Overview
Customized Cone Tracing is a variant of Voxel Cone Tracing that modifies the standard occlusion, specular, and diffuse cone behaviors to improve aesthetic quality, specifically addressing artifacts like overly dark corners, unrealistic specular highlights on curved surfaces, and dim indirect lighting [S1, unofficial]. It builds on [Voxel Cone Tracing](1454-voxel-cone-tracing.md) by introducing specialized BRDFs, distance-weighted occlusion accumulation, and early-termination heuristics [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Voxel data structure (containing color and alpha/occlusion), light source direction $\vec{l}$, surface normal, view direction, and material parameters (shininess $\alpha$, shininess_falloff $q$).
*   **Output:** Final pixel color combining direct lighting and customized indirect lighting (diffuse and specular).

**Data Structures:**
*   **Voxel:** Contains color ($C$) and occlusion/alpha ($a$).
*   **VoxSettings:** Contains parameters like `shadow_str` (occlusion strength), `shininess_falloff` ($q$), and angular grace factor constant.

**Algorithm Steps:**

1.  **Direct Lighting:** Compute Phong-based direct lighting for the surface point [S1, unofficial].
2.  **Shadow Cone:** Trace a shadow-cone towards the light source to yield an occlusion factor. Multiply the direct lighting by this factor [S1, unofficial].
3.  **Diffuse Cone Tracing:**
    *   Cast a cone in the hemisphere defined by the surface normal.
    *   March along the cone. At each step, sample the voxel's occlusion value $voxel.a$.
    *   **Early Termination:** If the sampled volume occlusion $voxel.a > 1/100$, immediately stop the cone trace. Return the color sampled at that specific point as the diffuse contribution [S1, unofficial].
    *   If not terminated, accumulate diffuse color from the sample.
4.  **Specular Cone Tracing:**
    *   Cast a cone in the direction of the reflected view vector $\vec{r}$ (or specular reflection direction).
    *   Calculate the angle $\gamma$ between the cone travel direction $\vec{\omega}$ and the light source direction $\vec{l}$:
        $$ \gamma = \arccos(\vec{\omega} \cdot \vec{l}) $$
    *   Calculate the normalized angle $\gamma_n$ using an angular grace value $p$:
        $$ \gamma_n = \max(0, \gamma - p) $$
    *   Compute the specular BRDF contribution using the shininess_falloff $q$:
        $$ f_{spec} = \left(1 - \frac{\gamma_n}{\pi}\right)^q = \left(1 - \frac{\max(0, \arccos(\vec{\omega} \cdot \vec{l}) - p)}{\pi}\right)^q $$
    *   Accumulate the specular color weighted by $f_{spec}$ [S1, unofficial].
5.  **Occlusion Cone Tracing (for Ambient Occlusion/Shadowing):**
    *   Trace a cone (typically with a larger aperture for ambient occlusion effects).
    *   At each step, calculate the distance traveled $current\_dist$ and the maximum trace distance $max\_dist$.
    *   Calculate the intermediate occlusion value $occ_r$:
        $$ occ_r = voxel.a \times \text{smoothstep}(0.0, max\_dist, \sqrt{current\_dist} \times shadow\_str) $$
        Here, `smoothstep` acts as a Hermite interpolation function [S1, unofficial].
    *   Update the total occlusion $occ$ using front-to-back alpha blending:
        $$ occ = occ + (1 - occ) \times occ_r $$
    *   This weighting mitigates short-distance occlusion intensity by decreasing sampled values proportional to the square root of the distance traveled [S1, unofficial].

**Pseudocode:**

```python
def customized_cone_trace(surface_point, normal, view_dir, light_dir, voxel_data, vox_settings):
    # 1. Direct Lighting
    direct_light = compute_phong_direct_lighting(surface_point, normal, view_dir, light_dir)
    
    # 2. Shadow Cone (for direct lighting occlusion)
    shadow_occ = trace_shadow_cone(surface_point, light_dir, voxel_data, vox_settings)
    lit_direct = direct_light * (1.0 - shadow_occ)
    
    # 3. Diffuse Cone
    diffuse_color = vec3(0.0)
    diffuse_cone_dir = sample_hemisphere(normal) # Simplified: single cone or multi-cone average
    current_pos = surface_point
    for step in trace_cone(current_pos, diffuse_cone_dir, voxel_data):
        voxel = sample_voxel(step.pos, voxel_data)
        if voxel.a > 0.01: # 1/100 threshold
            diffuse_color += voxel.color
            break # Early termination
        else:
            diffuse_color += voxel.color * step.weight
    
    # 4. Specular Cone
    specular_color = vec3(0.0)
    reflected_dir = reflect(-view_dir, normal)
    current_pos = surface_point
    for step in trace_cone(current_pos, reflected_dir, voxel_data):
        voxel = sample_voxel(step.pos, voxel_data)
        
        # Calculate angle between cone travel direction and light
        # Note: step.dir is the direction of the cone at this step
        cos_gamma = dot(normalize(step.dir), normalize(light_dir))
        gamma = acos(clamp(cos_gamma, -1.0, 1.0))
        
        # Angular grace
        p = vox_settings.angular_grace_constant * vox_settings.shininess_alpha
        gamma_n = max(0.0, gamma - p)
        
        # Specular BRDF
        q = vox_settings.shininess_falloff
        f_spec = pow(1.0 - (gamma_n / PI), q)
        
        specular_color += voxel.color * f_spec * step.weight
        
    return lit_direct + diffuse_color + specular_color

def trace_shadow_cone(origin, light_dir, voxel_data, vox_settings):
    occ = 0.0
    max_dist = vox_settings.max_trace_distance
    shadow_str = vox_settings.shadow_str
    
    current_pos = origin
    for step in trace_cone(current_pos, light_dir, voxel_data):
        voxel = sample_voxel(step.pos, voxel_data)
        
        # Distance weighting
        current_dist = length(step.pos - origin)
        
        # Hermite interpolation / smoothstep
        # smoothstep(0.0, max_dist, sqrt(current_dist) * shadow_str)
        t = sqrt(current_dist) * shadow_str
        weight = smoothstep(0.0, max_dist, t)
        
        occ_r = voxel.a * weight
        occ = occ + (1.0 - occ) * occ_r
        
        if occ >= 1.0:
            break
            
    return occ
```

**Parameters:**
*   $p$ (angular grace value): Defined as $p = \text{const.} \times \alpha$, where $\alpha$ is the Phong shininess (range 0-256). The constant is $0.008 \times \pi$ [S1, unofficial].
*   $q$ (shininess_falloff): Included in `VoxSettings`. Sensible results for $p$ values between 0 and 20 [S1, unofficial].
*   $shadow\_str$: Occlusion strength factor.
*   $max\_dist$: Maximum trace distance.

**Edge Cases and Pitfalls:**
*   **Self-Intersection:** Standard specular cones on highly curved surfaces can collide with the opposite side of the surface, causing unrealistic highlights. The customized BRDF mitigates this by penalizing large angles between the cone direction and light [S1, unofficial].
*   **Dark Corners:** Standard occlusion cones with large apertures cause immediate collision with neighboring walls in narrow angles, leading to overly dark corners. The square-root distance weighting mitigates this [S1, unofficial].
*   **Dim Indirect Light:** Standard diffuse cones can result in very dim indirect light. The early termination at $voxel.a > 1/100$ provides a cruder but aesthetically pleasing result [S1, unofficial].

## Subtopics

### [Two-Bounce Indirect Illumination](4558-two-bounce-indirect-illumination.md)
Indirect illumination computation uses a two-step approach: capturing incoming radiance from light sources in octree leaves, filtering/distributing it over octree levels, and performing approximate cone tracing for light transport [4558-two-bounce-indirect-illumination.md]. This variant extends the single-bounce model to approximate multiple bounces.

### [Multi-Cone Shading](5176-multi-cone-shading.md)
Approximates diffuse interreflection by casting 5 cones in different directions from a surface point and averaging the results [5176-multi-cone-shading.md]. This reduces the blocky appearance of single-cone tracing.

### [Diffuse Cone Distribution](5677-diffuse-cone-distribution.md)
Details the specific distribution or sampling strategy for diffuse cones [5677-diffuse-cone-distribution.md].

### Separate Diffuse/Reflection Bias
A parameter separation technique where the single cone tracing bias value is split into two independent parameters: `bias` for diffuse cones and `reflection_bias` for the single specular/reflection cone [S2, unofficial]. This allows independent tuning because reflections benefit from a smaller bias for sharp contact reflections, while diffuse GI benefits from a larger bias to reduce self-occlusion noise [S2, unofficial].
*   **Implementation:** Modify `VoxelGIData` to have `bias` affect only the diffuse cones and `reflection_bias` control the single specular/reflection cone independently [S2, unofficial].
*   **Layout:** The `VoxelGIData` uniform struct byte layout is duplicated in 4 places (`gi.h`, `gi.glsl`, `scene_forward_clustered_inc.glsl`, `volumetric_fog_process.glsl`). All 4 must be updated in lockstep to keep the `std140` layout identical, as a mismatch would silently corrupt every existing field [S2, unofficial].
*   **Usage:** Implemented in the RD (Forward+/Mobile) backend, which is the only backend that actually implements VoxelGI cone tracing. GLES3/Compatibility and dummy backends have matching empty overrides for the new virtuals [S2, unofficial]. The forward-clustered inline GI path (used for transparent/forward-shaded materials) picks up `reflection_bias`. Anisotropic sampling in this path is left as follow-up work [S2, unofficial].

### Specular Cone Tracing
Casts a cone in the direction of the reflected view vector [S3, unofficial]. The cone aperture depends on surface roughness: high roughness results in a high aperture, while smooth surfaces result in a small aperture [S3, unofficial]. Smooth surfaces are more expensive to calculate because smaller apertures require more marching steps [S3, unofficial].

### Ambient Occlusion via Cone Tracing
Ambient occlusion is approximated using the same cones used for diffuse reflection for efficiency. Only the occlusion value $\alpha_2$ is accumulated [S4, unofficial].
*   **Formula:** The weighting function is $f(r) = \frac{1}{1+\lambda r}$, where $r$ is the current radius of the cone and $\lambda$ is a user-defined value controlling how fast $f(r)$ decays along the traced distance [S4, unofficial].
*   **Accumulation:** At each cone step, the ambient occlusion term $\delta$ is updated as: $\delta = \delta + (1-\delta)\alpha_2f(r)$ [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of cone steps. Specular cones on smooth surfaces are more expensive due to smaller apertures requiring more steps [S3, unofficial].
*   **Memory Complexity:** Requires voxel data structures. The separate bias implementation requires duplicating uniform struct layouts in multiple shader files [S2, unofficial].
*   **Strengths:** Mitigates specific aesthetic artifacts (dark corners, unrealistic specular highlights) common in standard Voxel Cone Tracing [S1, unofficial]. Provides a balance between performance and visual quality through heuristic modifications [S1, unofficial].
*   **Limitations:** The early termination for diffuse cones is a "blunt method" that may not accurately represent complex indirect lighting paths [S1, unofficial]. The specialized BRDF does not depend on the viewing direction, which is unusual but acceptable for specular reflection cones [S1, unofficial].
*   **When to use:** When standard Voxel Cone Tracing produces visually unsatisfactory results regarding corner darkening or specular artifacts, and real-time performance is required [S1, unofficial].

## Background
Customized Cone Tracing was developed as part of a thesis on real-time global illumination using OpenGL and Voxel Cone Tracing [S1, unofficial]. It emerged from a long process of experimentation to achieve aesthetically pleasing results by modifying the standard cone tracing algorithms established in previous models (specifically referencing section 4.3.2 of the source) [S1, unofficial]. The method addresses specific visual flaws identified in standard implementations, such as the "unrealistic grey highlight" on curved surfaces and overly dark corners [S1, unofficial].
