# Two-Bounce Indirect Illumination

Also called: Glossy Reflections via Cone Tracing, Indirect Illumination, Real-time Indirect Illumination Algorithm, Voxel Cone Tracing Pipeline

## Overview
A three-step GPU-based algorithm for computing two light bounces of indirect illumination for Lambertian and glossy materials at interactive framerates [S1]. It differs from its parent [Customized Cone Tracing](3447-customized-cone-tracing.md) by explicitly separating the capture of incoming radiance from dynamic lights into a sparse voxel octree and using a view-dependent Gaussian-Lobes filtering scheme to store direction distributions, enabling efficient approximation of glossy reflections and color bleeding [S1]. It addresses the limitations of static caching in dynamic scenes by recomputing the radiance distribution per frame [S1].

## How it works
The method computes indirect illumination using a two-step approach (capture and filter) followed by final gathering [S1].

**Inputs:**
*   Scene geometry and material properties (specifically Phong specular exponent $k_s$) [S1].
*   Dynamic light source positions and intensities [S1].
*   Sparse voxel octree hierarchy (pre-existing or built) [S1].

**Outputs:**
*   Final color buffer with direct and indirect illumination combined [S1].

**Data Structures:**
*   **Sparse Voxel Octree:** Stores incoming radiance. Each node/leaf contains a "compact Gaussian-Lobes representation" of the filtered distribution of incoming light directions and energy [S1]. The structure supports mipmap-like levels [S1].
*   **Light-View Map:** A rasterization output map where each pixel represents a photon (world position, energy, direction) from a light source [S1].

**Steps:**

1.  **Capture Incoming Radiance (Photon Splatting):**
    *   Rasterize the scene from the perspective of each dynamic light source to generate a light-view map [S1].
    *   For each visible surface fragment in the light-view map, splat a photon into the leaves of the sparse voxel octree [S1].
    *   The photon stores incoming energy and direction [S1].
    *   *Note:* This step assumes the octree structure exists; the exact construction of the octree from geometry is not detailed in the core algorithm description but is implied as a prerequisite [S1].

2.  **Filter and Distribute Radiance (Octree Filtering):**
    *   Filter the incoming radiance values from the leaves up to higher levels of the octree (mipmap levels) [S1].
    *   Use a compact Gaussian-Lobes representation to store the filtered distribution of incoming light directions [S1].
    *   Perform this filtering efficiently in parallel using a screen-space quad-tree analysis [S1].
    *   The filtering scheme treats the Normal Distribution Function (NDF) and the Bidirectional Reflectance Distribution Function (BRDF) in a view-dependent way [S1].
    *   *Formula/Logic:* The Gaussian-Lobes representation approximates the directional distribution of light. The specific mathematical formulation of the Gaussian-Lobes is not provided in the sources [S1].

3.  **Final Gathering (Cone Tracing):**
    *   Render the scene from the camera using deferred shading to identify surface points requiring indirect illumination [S1].
    *   For each such surface point, combine direct and indirect illumination [S1].
    *   Perform approximate cone tracing to query the illumination distributed in the octree [S1].
    *   Send out a few cones over the hemisphere to collect illumination [S1].
    *   **Diffuse Component:** Use typically five large cones to estimate the diffuse energy coming from the scene [S1].
    *   **Specular Component:** Use a tight cone in the reflected direction with respect to the viewpoint to capture the specular component [S1].
    *   **Specular Cone Aperture:** The aperture of the specular cone is derived from the specular exponent $k_s$ of the material [S1]. The exact formula for deriving the aperture from $k_s$ is not given in the sources [S1].

**Pseudocode:**

```python
def compute_two_bounce_indirect_illumination(scene, lights, octree, camera):
    # Step 1: Capture Incoming Radiance
    # Render scene from each light's perspective to generate light-view map
    light_view_maps = []
    for light in lights:
        light_view_map = rasterize_scene_from_light(scene, light)
        light_view_maps.append(light_view_map)
    
    # Splat photons from light-view maps into octree leaves
    for light_view_map in light_view_maps:
        for fragment in light_view_map.fragments:
            splat_photon_into_octree_leaves(octree, fragment.position, fragment.energy, fragment.direction)

    # Step 2: Filter and Distribute Radiance
    # Filter incoming radiance up the octree hierarchy using Gaussian-Lobes
    # This is done in parallel via screen-space quad-tree analysis
    filter_octree_leaves_to_levels(octree)

    # Step 3: Final Gathering
    # Determine surface points needing indirect illumination via deferred shading
    surface_points = deferred_shading_pass(scene, camera)
    
    final_colors = []
    for point in surface_points:
        # Combine direct and indirect illumination
        direct_light = compute_direct_illumination(point, lights)
        
        # Approximate cone tracing for indirect illumination
        indirect_light = Vector3(0, 0, 0)
        
        # Estimate diffuse energy with ~5 large cones
        diffuse_cones = generate_large_cones(point.normal, point.position, count=5)
        for cone in diffuse_cones:
            radiance = query_octree_cone_trace(octree, cone.origin, cone.direction, cone.aperture)
            indirect_light += radiance * point.brdf.diffuse
        
        # Capture specular component with tight cone in reflected direction
        view_direction = normalize(camera.position - point.position)
        reflected_direction = reflect(-view_direction, point.normal)
        specular_cone = generate_tight_cone(reflected_direction, point.position)
        # Aperture derived from specular exponent k_s (formula not given)
        specular_cone.aperture = derive_aperture_from_specular_exponent(point.material.specular_exponent)
        specular_radiance = query_octree_cone_trace(octree, specular_cone.origin, specular_cone.direction, specular_cone.aperture)
        indirect_light += specular_radiance * point.brdf.specular
        
        final_color = direct_light + indirect_light
        final_colors.append(final_color)
        
    return final_colors
```

**Parameters:**
*   Number of diffuse cones: Typically 5 [S1].
*   Specular cone aperture: Derived from the material's specular exponent [S1]. Exact derivation formula not given [S1].

**Edge Cases and Pitfalls:**
*   The algorithm assumes the octree structure is already present and populated with incoming radiance before the final gathering step [S1].
*   The method focuses on low-energy/low-frequency and high-energy/high-frequency components of arbitrary material BRDFs, but the description specifically details Phong BRDFs [S1].
*   Precision issues may arise if the Gaussian-Lobes representation is insufficient for complex directional distributions, though the sources claim it is compact and efficient [S1].

## Subtopics

## Operating characteristics
*   **Time Complexity:** Interactive framerates are claimed [S1]. The filtering step is performed efficiently in parallel [S1].
*   **Memory Complexity:** Uses a sparse voxel octree hierarchy, which allows for sparse storage of incoming radiance and scene occlusion information [S1].
*   **Strengths:** Enables glossy reflections and color bleeding in dynamic scenes; uses sparse storage to maintain high precision; efficient parallel filtering [S1].
*   **Limitations:** The exact mathematical formulation of the Gaussian-Lobes representation and the aperture derivation are not provided, making implementation difficult without inference [S1]. The method is described primarily for Phong-like BRDFs [S1].
*   **When to use:** Real-time rendering of dynamic scenes requiring indirect illumination with glossy reflections [S1].
*   **When not to use:** Static scenes where precomputed radiance transfer might be more efficient; scenes with complex BRDFs not approximated by Phong models [S1].

## Background
The method was introduced in the paper "Interactive Indirect Illumination Using Voxel Cone Tracing" [S1]. It builds upon previous work on voxel cone tracing for ambient occlusion and extends it to handle indirect illumination and glossy reflections [S1]. The approach is inspired by photon mapping concepts, specifically the idea of storing incoming radiance rather than outgoing radiance to simulate glossy surfaces [S1].
