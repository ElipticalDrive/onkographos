# Two-Bounce Indirect Illumination

Also called: Glossy Reflections via Cone Tracing, Indirect Illumination, Real-time Indirect Illumination Algorithm, Voxel Cone Tracing Pipeline

## Overview
A three-step GPU-based algorithm for computing two light bounces of indirect illumination for Lambertian and glossy materials at interactive framerates [S1]. It differs from standard Ambient Occlusion by capturing and storing incoming radiance direction and energy in a sparse voxel octree, enabling view-dependent specular reflections and color bleeding rather than just visibility [S1]. It builds on [Customized Cone Tracing](3447-customized-cone-tracing.md) by explicitly separating the capture of direct illumination from the final gathering phase.

## How it works
The method computes indirect illumination using a two-step approach: capturing incoming radiance from light sources into a sparse voxel octree, filtering it across octree levels, and performing approximate cone tracing for final gathering [S1].

### Inputs and Outputs
*   **Inputs**: Scene geometry, material properties (specifically Phong specular exponent), dynamic light source positions and intensities, sparse voxel octree structure.
*   **Outputs**: Final pixel color with direct and indirect illumination (diffuse and specular components).

### Data Structures
*   **Sparse Voxel Octree**: Stores filtered incoming radiance. Each node contains a compact Gaussian-Lobes representation of the distribution of incoming light directions and energy [S1].
*   **Light-View Map**: A render target storing world positions of surface fragments visible from each light source, used to inject photons into the octree leaves [S1].

### Steps

1.  **Capture Direct Illumination (Injection)**
    *   Rasterize the scene from the perspective of each dynamic light source to generate the light-view map [S1].
    *   For each visible surface fragment (pixel in the light-view map), splat a "photon" into the leaves of the sparse voxel octree [S1].
    *   The photon stores incoming radiance energy and direction [S1].
    *   *Note*: The sources assume the incoming radiance is already present in the octree for the subsequent steps, detailing the capture separately [S1].

2.  **Filter and Distribute Radiance**
    *   Filter the incoming radiance values from the octree leaves into higher levels (mipmap levels) [S1].
    *   Use a compact Gaussian-Lobes representation to store the filtered distribution of incoming light directions [S1].
    *   Perform this filtering efficiently in parallel using a screen-space quad-tree analysis [S1].
    *   The voxel filtering scheme treats the Normal Distribution Function (NDF) and the Bidirectional Reflectance Distribution Function (BRDF) in a view-dependent way [S1].

3.  **Final Gathering (Cone Tracing)**
    *   Render the scene from the camera using deferred shading to identify surface points requiring indirect illumination [S1].
    *   For each such point, combine direct and indirect illumination [S1].
    *   Perform final gathering by sending out several cones over the hemisphere to collect illumination distributed in the octree [S1].
    *   **Diffuse Component**: Use typically five large cones to estimate diffuse energy coming from the scene [S1].
    *   **Specular Component**: Use a tight cone in the reflected direction with respect to the viewpoint to capture the specular component [S1].
    *   **Specular Cone Aperture**: The aperture of the specular cone is derived from the specular exponent of the material [S1].

### Pseudocode

```python
def compute_two_bounce_indirect_illumination(scene, lights, octree, camera):
    # Step 1: Capture incoming radiance from lights
    for light in lights:
        # Render scene from light's perspective to get visible fragments
        light_view_map = rasterize_scene_from_light(scene, light)
        
        # Splat photons into octree leaves for each visible fragment
        for fragment in light_view_map:
            photon = create_photon(
                energy=light.intensity,
                direction=fragment.normal, # Approximation of incoming direction
                position=fragment.world_pos
            )
            octree.inject_into_leaves(photon)

    # Step 2: Filter radiance up the octree hierarchy
    # Uses screen-space quad-tree analysis for parallel efficiency
    octree.filter_gaussian_lobes()

    # Step 3: Final gathering from camera
    for surface_point in deferred_shading_pass(scene, camera):
        if surface_point.requires_indirect_illumination:
            indirect_diffuse = 0.0
            indirect_specular = 0.0
            
            # Estimate diffuse energy with ~5 large cones
            for i in range(5):
                cone = create_large_cone(surface_point, direction=hemisphere_sample(i))
                radiance = octree.query_cone(cone)
                indirect_diffuse += radiance
            
            # Estimate specular with tight cone in reflected direction
            # Aperture derived from material's specular exponent
            specular_exponent = surface_point.material.specular_exponent
            cone_aperture = derive_aperture_from_exponent(specular_exponent)
            specular_cone = create_tight_cone(
                surface_point, 
                direction=reflect(camera.view_direction, surface_point.normal),
                aperture=cone_aperture
            )
            indirect_specular = octree.query_cone(specular_cone)
            
            surface_point.color += indirect_diffuse + indirect_specular
```

### Parameters
*   **Number of diffuse cones**: Typically 5 [S1].
*   **Specular cone aperture**: Derived from the material's specular exponent [S1]. Exact formula not given in sources.
*   **Material Model**: Phong BRDF is the primary focus [S1].

### Edge Cases and Pitfalls
*   **Complexity of Capture**: Writing incoming radiance into the octree structure is complex; the algorithm description often assumes it is already present [S1].
*   **View-Dependence**: The filtering scheme is view-dependent, which may require careful handling of camera position changes during the filtering step [S1].
*   **Low-Energy/High-Frequency**: The solution works for low-energy/low-frequency and high-energy/high-frequency components, but performance may vary [S1].

## Operating characteristics
*   **Time Complexity**: Interactive framerates are claimed [S1]. The parallel filtering via screen-space quad-tree analysis suggests efficient GPU utilization [S1].
*   **Memory Complexity**: Uses sparse voxel octree, allowing high precision with sparse storage of incoming radiance and occlusion information [S1].
*   **Strengths**: Enables glossy reflections and color bleeding; handles dynamic lights; view-dependent NDF/BRDF filtering [S1].
*   **Limitations**: Complex implementation for the capture step; relies on rasterization for capture which may have aliasing issues; limited to two bounces [S1].
*   **When to use**: Real-time rendering requiring glossy indirect illumination and color bleeding with dynamic lights [S1].
*   **When not to use**: Offline rendering requiring full global illumination; scenes with extremely high-frequency indirect lighting where cone approximation fails [S1].

## Background
Originated in the paper "Interactive Indirect Illumination Using Voxel Cone Tracing" [S1]. The approach is inspired by photon mapping concepts [DS05] but adapted for real-time GPU execution using voxel cone tracing [S1]. It is part of the Voxel Cone Tracing pipeline, specifically customized for aesthetic results regarding occlusion, specular, and diffuse behaviors [S1].
