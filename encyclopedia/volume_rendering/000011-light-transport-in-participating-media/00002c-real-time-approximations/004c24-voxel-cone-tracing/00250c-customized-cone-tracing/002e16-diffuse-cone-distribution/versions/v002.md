# Diffuse Cone Distribution


## Overview
Diffuse Cone Distribution is a sampling strategy for approximating indirect diffuse lighting in Voxel Cone Tracing [S1, unofficial]. It uses a fixed, deterministic arrangement of five cones—one aligned with the surface normal and four at perpendicular angles—distinguishing it from stochastic rotation or multi-bounce variants [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Surface normal vector $\mathbf{n}$, surface position $\mathbf{p}$ [G].
- Output: Accumulated diffuse radiance $L_{\text{diffuse}}$ [G].

**Data Structures:**
- Cone: Defined by origin $\mathbf{o}$, direction $\mathbf{d}$, and aperture angle $\alpha$ [G].

**Parameters:**
- Number of cones: 5 [S1, unofficial].
- Cone aperture: $30^\circ$ for all cones [S1, unofficial].
- Offset distance: Small scalar $\epsilon$ to prevent self-intersection [S1, unofficial].

**Steps:**
1. **Generate Cone Directions:** Create five direction vectors relative to $\mathbf{n}$: $\mathbf{d}_0 = \mathbf{n}$, and $\mathbf{d}_1, \mathbf{d}_2, \mathbf{d}_3, \mathbf{d}_4$ lying in the plane perpendicular to $\mathbf{n}$ [S1, unofficial].
2. **Set Origins:** For each cone $i$, compute $\mathbf{o}_i = \mathbf{p} + \epsilon \mathbf{d}_i$ [S1, unofficial]. The offset prevents sampling the surface voxel itself, which causes self-shadowing and self-lighting artifacts [S1, unofficial].
3. **Trace Cones:** Cast each cone using direction $\mathbf{d}_i$, aperture $30^\circ$, and origin $\mathbf{o}_i$ [S1, unofficial].
4. **Accumulate:** Sum the radiance contributions from all five traces:
   $$ L_{\text{diffuse}} = \sum_{i=0}^{4} L_i $$
   where $L_i$ is the result of the $i$-th cone trace [G].

**Pseudocode:**
```python
def diffuse_cone_distribution(surface_normal, surface_position, epsilon=0.001):
    directions = [surface_normal]
    # Compute orthonormal basis for perpendicular directions [G]
    up = vec3(0.0, 0.0, 1.0) if abs(dot(surface_normal, vec3(0.0, 0.0, 1.0))) < 0.9 else vec3(1.0, 0.0, 0.0)
    tangent = normalize(cross(surface_normal, up))
    bitangent = cross(surface_normal, tangent)
    directions.extend([tangent, bitangent, -tangent, -bitangent])
    
    accumulated_light = vec3(0.0)
    aperture = 30.0 # degrees [S1, unofficial]
    
    for direction in directions:
        origin = surface_position + direction * epsilon # Offset avoids sampling the surface voxel [S1, unofficial]
        accumulated_light += trace_cone(origin, direction, aperture)
    return accumulated_light

def trace_cone(origin, direction, aperture_deg):
    # Standard voxel cone traversal accumulating radiance until occlusion [G]
    # Implementation details (step size, max distance, attenuation) are not given in the sources.
    color = vec3(0.0)
    t = 0.0
    step = 0.1 # Not given in the sources.
    max_dist = 10.0 # Not given in the sources.
    while t < max_dist:
        voxel = get_voxel_at(origin + direction * t)
        if voxel.is_empty:
            t += step
        else:
            color += voxel.color * attenuation
            break
    return color
```

**Edge Cases:**
- **Self-Shadowing:** If $\epsilon$ is too small, the cone origin samples the surface voxel itself, causing self-shadowing and self-lighting artifacts [S1, unofficial].
- **Blocky Artifacts:** Using only five cones produces coarse sampling, resulting in visible blockiness in smooth gradients [S1, unofficial].

## Subtopics

### [Random Cone Rotation](5911-random-cone-rotation.md)
Mitigates blocky artifacts by rotating the cone orientations randomly around the surface normal. It trades visual coherence for stochastic noise, unlike the deterministic 5-cone set.

### [Two-Bounce Indirect Illumination](4558-two-bounce-indirect-illumination.md)
Extends the approximation to include secondary bounces, offering higher accuracy at greater cost [G].

### [Multi-Cone Shading](5176-multi-cone-shading.md)
Uses a larger number of cones for smoother results, increasing computational load [G].

## Background
This distribution was proposed in an unofficial report on Voxel Cone Tracing implementation details [S1, unofficial]. The specific choice of 5 cones and $30^\circ$ aperture was empirically determined to provide "good quality" for the computational cost in that context [S1, unofficial].
