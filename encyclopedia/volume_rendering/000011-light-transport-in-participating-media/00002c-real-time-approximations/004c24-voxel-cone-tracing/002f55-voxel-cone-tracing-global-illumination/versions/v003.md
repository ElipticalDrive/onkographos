# Voxel Cone Tracing Global Illumination

Also called: Crassin's voxel cone tracing, Voxel Cone Traced Global Illumination, VCTGI

## Overview
Voxel Cone Tracing Global Illumination (VCTGI) is a real-time global illumination technique that approximates indirect lighting by storing scene radiance in a voxel grid and sampling it via cone tracing [S3, unofficial]. It differs from diffuse-only voxel GI by supporting specular and glossy reflections with significantly lower performance costs, requiring only a single cone trace per glossy material [S1, unofficial]. Unlike sparse voxel octrees, this implementation typically uses a plain 3D texture to support moving cameras without expensive reconstruction [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Scene geometry (triangles), surface properties (color, normal, emission), light sources, and camera position [S3, unofficial].
*   **Output:** A final rendered image with indirect diffuse and specular lighting [S3, unofficial].

**Data Structures:**
1.  **Voxel Grid:** A plain 3D texture (not a sparse octree) storing view-independent radiance [S3, unofficial].
2.  **Mipmap Chain:** Generated from the radiance texture using trilinear interpolation [S3, unofficial]. Anisotropic mipmaps may be used to reduce light bleeding [S3, unofficial].

**Steps:**

1.  **Voxelization:**
    *   Project triangles into the voxel grid [S3, unofficial]. To maximize covered area and minimize holes, project triangles in the geometry shader based on the greatest component of the surface normal [S3, unofficial].
        *   If the Z component is greatest, project onto the XY plane [S3, unofficial].
        *   If the X component is greatest, project onto the YZ plane [S3, unofficial].
        *   If the Y component is greatest, project onto the XZ plane [S3, unofficial].
    *   Use **Conservative Rasterization** to ensure triangles cover the center of pixels, preventing holes in the voxelized mesh [S3, unofficial].

2.  **Radiance Volume Construction:**
    *   Combine surface color, normal, emission, and direct lighting (including shadows) into the voxel grid [S3, unofficial].
    *   **Concurrency Handling:** Since shaders execute concurrently in warps, unsynchronized writes to the voxel texture can cause race conditions [S3, unofficial]. Mitigation strategies include:
        *   Using a Compare-And-Swap (CAS) loop with a moving average, converting RGBA8 to R32UI before accumulation [S3, unofficial].
        *   Using `NV_shader_atomic_float` extensions to perform `imageAtomicAdd` on floats [S3, unofficial].

3.  **Mipmap Generation:**
    *   Generate mipmaps of the radiance texture [S3, unofficial]. Anisotropic mipmaps are preferred to reduce light bleeding artifacts [S3, unofficial].

4.  **Lighting (Cone Tracing):**
    *   For each fragment, shoot cones around the hemisphere oriented along the surface normal [S3, unofficial].
    *   **Cone Types:**
        *   **Diffuse:** Large aperture, samples the mipmap chain to capture broad indirect lighting [S3, unofficial].
        *   **Specular:** Smaller aperture, samples the mipmap chain to capture glossy reflections. Only one cone is typically needed for glossy materials [S1, unofficial].
        *   **Ambient Occlusion:** Used for occlusion calculations [S3, unofficial].
    *   **Aperture:** The cone aperture determines the rate at which the diameter increases with distance from the surface [S3, unofficial]. The diameter selects the appropriate mipmap level [S3, unofficial].
    *   **Accumulation:** Traverse the voxel structure using front-to-back accumulation [S3, unofficial]. For each step, update color and opacity using the following formulas [S3, unofficial]:
        $$
        \text{color} = \text{opacity} \cdot \text{color} + (1 - \text{opacity}) \cdot \text{read\_opacity} \cdot \text{read\_color}
        $$
        $$
        \text{opacity} = \text{opacity} + (1 - \text{opacity}) \cdot \text{read\_opacity}
        $$
    *   **Weighting:** Average the results from multiple cones (Monte Carlo style), weighting each partial result by the cosine similarity between the cone direction and the surface normal [S3, unofficial].

**Pseudocode:**

```python
import math
import random

# Standard vector operations [G]
def vec3(x, y, z): return (x, y, z)
def dot(a, b): return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]
def normalize(v):
    l = math.sqrt(dot(v, v))
    return (v[0]/l, v[1]/l, v[2]/l)
def reflect(I, N):
    return (I[0] - 2*dot(I, N)*N[0], I[1] - 2*dot(I, N)*N[1], I[2] - 2*dot(I, N)*N[2])

def sample_hemisphere(normal):
    # Uniform hemisphere sampling [G]
    u = random.uniform(0, 1)
    v = random.uniform(0, 1)
    theta = 2.0 * math.pi * u
    phi = math.acos(1.0 - 2.0 * v)
    local_dir = (math.cos(theta)*math.sin(phi), math.sin(theta)*math.sin(phi), math.cos(phi))
    # Rotate to align with surface normal (simplified rotation matrix omitted for brevity)
    return normalize(local_dir)

def trace_cone(origin, direction, aperture, max_distance, voxel_grid):
    opacity = 0.0
    accumulated_color = vec3(0.0, 0.0, 0.0)
    distance = 0.0
    step_size = aperture * 0.5  # Step size scales with aperture [G]

    while distance < max_distance:
        current_pos = (origin[0] + direction[0]*distance, 
                       origin[1] + direction[1]*distance, 
                       origin[2] + direction[2]*distance)
        current_diameter = aperture * distance  # Diameter grows linearly with distance [G]
        mip_level = max(0, int(math.log2(current_diameter + 1e-6)))  # Select mipmap based on diameter [G]

        read_color, read_opacity = voxel_grid.sample(current_pos, mip_level)

        # Front-to-back accumulation
        accumulated_color = (opacity * accumulated_color[0] + (1.0 - opacity) * read_opacity * read_color[0],
                             opacity * accumulated_color[1] + (1.0 - opacity) * read_opacity * read_color[1],
                             opacity * accumulated_color[2] + (1.0 - opacity) * read_opacity * read_color[2])
        opacity = opacity + (1.0 - opacity) * read_opacity

        if opacity >= 1.0:
            break
        distance += step_size

    return accumulated_color, opacity

def compute_global_illumination(fragment, voxel_grid, max_distance=10.0):
    normal = fragment.normal
    diffuse_color = vec3(0.0, 0.0, 0.0)
    specular_color = vec3(0.0, 0.0, 0.0)

    # Diffuse GI: Multiple cones
    num_diffuse_cones = 16
    for i in range(num_diffuse_cones):
        direction = sample_hemisphere(normal)
        aperture = 1.0  # Large aperture for diffuse [S3, unofficial]
        color, _ = trace_cone(fragment.position, direction, aperture, max_distance, voxel_grid)
        weight = max(0.0, dot(direction, normal))  # Cosine weighting [S3, unofficial]
        diffuse_color = (diffuse_color[0] + color[0] * weight,
                         diffuse_color[1] + color[1] * weight,
                         diffuse_color[2] + color[2] * weight)

    diffuse_color = (diffuse_color[0] / num_diffuse_cones,
                     diffuse_color[1] / num_diffuse_cones,
                     diffuse_color[2] / num_diffuse_cones)

    # Specular GI: Single cone for glossy
    specular_aperture = 0.2  # Smaller aperture for specular [S3, unofficial]
    specular_direction = reflect((-fragment.view_direction[0], -fragment.view_direction[1], -fragment.view_direction[2]), normal)
    specular_color, _ = trace_cone(fragment.position, specular_direction, specular_aperture, max_distance, voxel_grid)

    return diffuse_color, specular_color
```

## Operating characteristics
*   **Performance:** In a test with 1024x768 resolution and ~70,000 triangles, frame times were: Voxelization 0.97ms, Radiance volume 4.96ms, Isotropic mipmaps 0.09ms, Lighting 5.1ms [S3, unofficial].
*   **Complexity:** Lighting complexity is proportional to the number of cones traced per fragment. Diffuse GI requires many cones (e.g., 16), while specular GI requires only one [S1, unofficial][S3, unofficial].
*   **Strengths:** Real-time performance; supports specular reflections; simple implementation with plain 3D textures; no complex octree reconstruction for moving cameras [S3, unofficial].
*   **Limitations:** Voxel artifacts may appear on highly polished reflectors [S1, unofficial]; light bleeding can occur if anisotropic mipmaps are not used [S3, unofficial]; requires conservative rasterization to avoid holes [S3, unofficial].
*   **When to use:** Real-time applications requiring both diffuse and specular global illumination, especially with moving cameras [S3, unofficial].
*   **When not to use:** Scenes with extremely high-frequency indirect lighting details that require higher resolution than the voxel grid can provide, or where voxel artifacts are unacceptable [S1, unofficial].

## Background
The Voxel Cone Tracing global illumination technique was proposed by Cyril Crassin et al. in 2011 [S2, unofficial][S3, unofficial]. It was introduced to bring global illumination into the realm of real-time rendering by leveraging the efficiency of voxel grids and cone tracing [S3, unofficial]. The technique has been used in commercial video games, such as *The Tomorrow Children* [S3, unofficial].
