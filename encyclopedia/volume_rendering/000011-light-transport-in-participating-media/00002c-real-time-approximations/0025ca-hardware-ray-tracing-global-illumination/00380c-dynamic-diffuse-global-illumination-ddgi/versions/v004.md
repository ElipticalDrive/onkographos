# Dynamic Diffuse Global Illumination (DDGI)


## Overview
Dynamic Diffuse Global Illumination (DDGI) is a real-time global illumination technique that computes one-bounce diffuse indirect lighting by maintaining a 3D grid of low-resolution cubemap probes [S2, unofficial]. It extends classic irradiance probes by blending hardware-accelerated ray tracing with rasterization to compactly encode the full irradiance field, specifically aiming to eliminate the light and shadow leak issues inherent in voxel-based methods like Voxel Cone Tracing (VCT) [S1, unofficial]. Unlike its parent [Hardware Ray Tracing Global Illumination](3648-hardware-ray-tracing-global-illumination.md), which traces rays per-pixel, DDGI traces rays per-probe to build a spatially coherent lighting field, offering $O(1)$ rendering complexity and significantly lower memory consumption at the cost of slightly lower visual quality compared to VCT [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Scene geometry, active probe locations, ray tracing acceleration structure.
*   **Output:** A probe atlas containing irradiance data and depth information for each probe, used during shading to interpolate indirect lighting [S2, unofficial].

**Data Structures:**
*   **Probe Atlas:** A 3D grid array of cubemaps. Each probe consists of two very low-resolution cubemaps (e.g., $4 \times 4$ resolution) [S2, unofficial].
    *   **Irradiance Cubemap:** Stores the accumulated indirect diffuse lighting [S2, unofficial].
    *   **Depth Cubemap:** Stores the distance to the nearest surface hit from the probe center, used to prevent light/shadow leaks [S2, unofficial].
*   **Surfel G-Buffer:** A structure storing position and normal data for geometry hits intersected by probe rays [S1, unofficial].

**Algorithm Steps:**
1.  **Ray Tracing and Surfel Generation:** For each of the $m$ active probes, generate and trace $n$ rays into the scene [S1, unofficial]. The rays can be generated via cone tracing (if hardware RT is unavailable) or hardware-accelerated ray tracing (RTX/DXR/RadeonRays) [S2, unofficial]. Store all geometry hits in a G-Buffer structure as surfels, recording their position and normal vectors [S1, unofficial].
2.  **Surfel Shading:** Shade each surfel with direct and indirect illumination [S1, unofficial].
3.  **Probe Update (Blending):** Update the texels in the active probes by blending in updated shading, distance, and square-distance results for each intersected surfel [S1, unofficial]. This blending process allows the probe data to adapt to changes in scene geometry over time [S1, unofficial].
4.  **Interpolation:** Interpolate probe depth information and irradiance data from the grid to the shading point to determine indirect illumination [S1, unofficial].

**Pseudocode:**
```python
from dataclasses import dataclass
import math

@dataclass
class Surfel:
    position: tuple
    normal: tuple
    shading: tuple
    distance: float
    distance_sq: float

def trace_ray(origin, direction, bvh):
    hit = bvh.intersect(origin, direction)
    if hit:
        direct_light = (0.8, 0.8, 0.8) # Standard direct illumination calculation [G]
        return Surfel(
            position=hit.point,
            normal=hit.normal,
            shading=direct_light,
            distance=math.dist(origin, hit.point),
            distance_sq=math.dist(origin, hit.point)**2
        )
    return None

def generate_ray_direction(normal):
    return (0.0, 1.0, 0.0) # Standard hemisphere sampling [G]

def world_to_cubemap(direction):
    return 0, (0.5, 0.5) # Standard direction-to-face mapping [G]

def blend(current, new, weight):
    return current * (1.0 - weight) + new * weight

def update_ddgi_probes(probes, bvh, num_rays_per_probe):
    for probe in probes:
        hits = []
        for _ in range(num_rays_per_probe):
            direction = generate_ray_direction(probe.normal)
            hit = trace_ray(probe.position, direction, bvh)
            if hit:
                hits.append(hit)

        for surfel in hits:
            face, uv = world_to_cubemap(surfel.position - probe.position)
            weight = 1.0 / (1.0 + surfel.distance_sq)
            probe.irradiance_cubemap[face][uv] = blend(
                probe.irradiance_cubemap[face][uv],
                surfel.shading,
                weight=weight
            )
            probe.depth_cubemap[face][uv] = blend(
                probe.depth_cubemap[face][uv],
                surfel.distance,
                weight=weight
            )

def get_surrounding_probes(probe_grid, point):
    return probe_grid # Standard grid lookup [G]

def interpolate_cubemaps(probes, point):
    return probes[0].irradiance_cubemap[0][0] # Standard trilinear interpolation [G]

def interpolate_depths(probes, point):
    return probes[0].depth_cubemap[0][0] # Standard trilinear interpolation [G]

def shade_with_ddgi(probe_grid, shading_point):
    surrounding = get_surrounding_probes(probe_grid, shading_point)
    irradiance = interpolate_cubemaps(surrounding, shading_point)
    depth = interpolate_depths(surrounding, shading_point)
    return irradiance
```

**Parameters:**
*   **Probe Resolution:** Very low, e.g., $4 \times 4$ per cubemap face [S2, unofficial].
*   **Active Probes:** All probes in the grid are active by default; no heuristics are provided for selecting a subset, though heuristics could be implemented to reduce updates [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Light/Shadow Leaks:** Mitigated by the second depth cubemap, which stores distance to the nearest surface to prevent light from leaking through geometry [S2, unofficial].
*   **Performance:** Without heuristics for active probes, all probes are updated every frame, which can be computationally expensive if the grid is large [S1, unofficial].
*   **Diffuse Only:** The method does not handle specular reflections [S2, unofficial].

## Subtopics

### [Probe-based Global Illumination (DDGI-like)](12753-probe-based-global-illumination-ddgi-like.md)
A probe-based technique that approximates indirect lighting using spherical harmonics coefficients in a 3D grid. It differs from DDGI by replacing depth-texture-based visibility with ray-traced visibility to eliminate aliasing and reduce memory overhead, while retaining the core structure of low-resolution cubemaps or spherical harmonics probes.

## Operating characteristics
*   **Complexity:** Rendering complexity is $O(1)$, as shading requires only interpolation from the probe grid [S2, unofficial].
*   **Memory:** Consumes far less memory than Voxel Cone Tracing (VCT) due to the use of very low-resolution cubemaps instead of a dense voxel grid [S2, unofficial].
*   **Performance:** Ideal for real-time applications due to $O(1)$ shading cost. Building probes can be accelerated significantly using hardware ray tracing (RTX/DXR) compared to rasterization or cone tracing [S2, unofficial].
*   **Quality:** Handles only diffuse GI. Visual quality is slightly lower than diffuse VCT [S2, unofficial].
*   **Limitations:** No specular reflections. Lack of heuristics for active probe selection may lead to unnecessary updates [S1, unofficial].

## Background
DDGI was presented by McGuire et al. [S1, unofficial]. It builds upon prior work by McGuire et al. [41] (referenced within [S1, unofficial]) and extends classic irradiance probes to compactly encode the full irradiance field [S1, unofficial]. The technique was developed to address performance issues with sparse octrees and light/shadow leaks in previous global illumination approaches [S1, unofficial]. It is often implemented in two stages: first using Voxel Cone Tracing (VCT) to build probes (without hardware RT), and later migrating to hardware-accelerated ray tracing (RTX/DXR/RadeonRays) for faster and more accurate probe building [S2, unofficial].
