# Volumetric Cloud Rendering with Pre-computed Light Transmittance

Also called: Pre-computed Light Transmittance for Clouds

## Overview
This method generates volumetric clouds by ray marching through a voxel density grid, accelerating the rendering equation by pre-computing light transmittance from every voxel to the light source [S1, unofficial]. It distinguishes itself from standard volumetric integration by decoupling the expensive light transport calculation (transmittance) from the per-pixel ray march, storing it in the voxel grid to allow for fast accumulation during rendering [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
- Voxel grid containing density and color data.
- Light source position (`lpos`).
- Camera parameters: eye position (`eyep`), viewing direction (`vdir`), up vector (`uvec`), field of view (`fovy`), and resolution (`reso_x`, `reso_y`) [S1, unofficial].
- Rendering quality mode (integer 0–4) [S1, unofficial].
- Absorption coefficient (`kapa`) [S1, unofficial].
- Background color (`bcol`) [S1, unofficial].

**Outputs:**
- Rendered image pixels with color values clamped to [0, 1] [S1, unofficial].

### Data Structures

**VoxelGrid**
The grid is stored in a flat `vector<Voxel*>` ordered by Z, then Y, then X indices [S1, unofficial].
- `voxelSize`: `double`, size of a single voxel.
- `xCount`, `yCount`, `zCount`: `int`, dimensions of the grid.
- `defaultDensity`: `double`, density value for empty space.
- `voxels`: `vector<Voxel*>`, pointers to voxel data.

**Voxel**
- `density`: `double`, the density value at this voxel [S1, unofficial].
- `transmissivity`: `double`, the pre-computed light transmittance from this voxel to the light source [S1, unofficial].
- `color`: `vec3`, the base color of the cloud material at this voxel [S1, unofficial].

### Pre-computation Phase
Before rendering, light transmittance is computed for every voxel in the grid [S1, unofficial].

1.  For each voxel `v` in the grid:
2.  Cast a ray from the voxel center to the light source position `lpos`.
3.  March along this ray using the selected quality mode (0–4) to collect sample points [S1, unofficial].
4.  For each sample point `p` along the ray:
    -   Retrieve density `rho` at `p`. If quality < 3, use nearest neighbor; if quality >= 3, use trilinear interpolation [S1, unofficial].
    -   If `rho > 0`:
        -   Calculate transmittance contribution: `deltaT = exp(-kapa * step_size * rho)`.
        -   Accumulate total transmittance: `T = T * deltaT`.
5.  Store the final accumulated transmittance `T` in `v.transmissivity` [S1, unofficial].

### Rendering Phase

#### 1. Camera Setup
Compute screen vectors to map pixel coordinates to world space [S1, unofficial].
-   `midpoint = eyep + vdir`
-   `h_px = (reso_x / reso_y) * vdir.length() * tan(fovy * 0.5 * D2R) * normalize(vdir cross uvec)`
-   `v_px = vdir.length() * tan(fovy * 0.5 * D2R) * normalize(vdir cross (vdir cross uvec))`
    -   Where `D2R` is the conversion factor from degrees to radians ($\pi/180$) [S1, unofficial].

#### 2. Ray Generation
For each pixel $(x, y)$:
-   `orig = midpoint + (2.0 * (x / (reso_x - 1)) - 1) * h_px + (2.0 * (y / (reso_y - 1)) - 1) * v_px`
-   `dir = normalize(orig - eyep)` [S1, unofficial].

#### 3. Ray Marching and Integration
March from `orig` along `dir` through the voxel grid. The marching algorithm (step size and interpolation) varies by quality mode [S1, unofficial].

**Pseudocode:**

```python
def render_pixel(x, y, eyep, vdir, uvec, reso_x, reso_y, fovy, kapa, bcol, grid, quality_mode):
    # 1. Camera Setup
    midpoint = eyep + vdir
    h_px = (reso_x / reso_y) * vdir.length() * tan(fovy * 0.5 * 3.14159265358979323846 / 180.0) * normalize(cross(vdir, uvec))
    v_px = vdir.length() * tan(fovy * 0.5 * 3.14159265358979323846 / 180.0) * normalize(cross(vdir, cross(vdir, uvec)))
    
    # 2. Ray Generation
    orig = midpoint + (2.0 * (x / (reso_x - 1)) - 1) * h_px + (2.0 * (y / (reso_y - 1)) - 1) * v_px
    dir = normalize(orig - eyep)
    
    # 3. Ray Marching and Integration
    color = vec3(0.0, 0.0, 0.0)
    transmittance = 1.0
    
    # Initialize marching state based on quality mode
    # Note: Specific marching logic (fixed step vs voxel-boundary) depends on quality_mode
    # Modes 0,1,3 use fixed step; Modes 2,4 use voxel-boundary [S1, unofficial]
    current_pos = orig
    step_size = get_step_size(quality_mode) # Implementation detail not fully specified in source
    
    while current_pos is inside grid:
        # Get density and color at current_pos
        # Interpolation depends on quality_mode: <3 is nearest, >=3 is trilinear [S1, unofficial]
        rho = get_density(current_pos, grid, quality_mode)
        rgb = get_color(current_pos, grid, quality_mode)
        
        if rho > 0:
            # Compute transmittance for this step
            deltaT = exp(-kapa * step_size * rho)
            
            # Update ray transmittance
            transmittance *= deltaT
            
            # Early termination pitfall: if transmittance is negligible, break [S1, unofficial]
            if transmittance < 1e-6:
                break
            
            # Get pre-computed light transmittance from the voxel
            # Interpolation depends on quality_mode [S1, unofficial]
            q = get_transmissivity(current_pos, grid, quality_mode)
            
            # Accumulate color
            # Formula: color += (1 - deltaT)/kapa * rgb * transmittance * q
            color += ((1.0 - deltaT) / kapa) * rgb * transmittance * q
        
        # Advance ray
        current_pos += dir * step_size
        
    # Add background
    color += bcol * transmittance
    
    # Clamp output to [0, 1] [S1, unofficial]
    return clamp(color, 0.0, 1.0)
```

### Parameters
-   `reso_x`: Output image resolution width. Default: 640.0 [S1, unofficial].
-   `reso_y`: Output image resolution height. Default: 480.0 [S1, unofficial].
-   `kapa`: Absorption coefficient. Value not given in the sources.
-   `quality_mode`: Integer 0–4. Determines interpolation and marching strategy [S1, unofficial].

### Edge Cases and Pitfalls
-   **Early Termination:** If `transmittance` drops below $10^{-6}$, the ray march loop breaks immediately to save computation, as further contributions are negligible [S1, unofficial].
-   **Clamping:** Output color components must be clamped to the range [0, 1] before conversion to 8-bit integers to prevent overflow [S1, unofficial].
-   **Interpolation Consistency:** Quality modes 0–2 use nearest-neighbor sampling for density, color, and transmissivity, while modes 3–4 use trilinear interpolation. Modes 0, 1, and 3 use fixed-step marching, while modes 2 and 4 use voxel-boundary marching [S1, unofficial].

## Operating characteristics

### Time and Memory Complexity
-   **Pre-computation:** $O(N \cdot M)$, where $N$ is the number of voxels and $M$ is the number of samples along the light ray for each voxel. This is a one-time cost per frame or per light position change.
-   **Rendering:** $O(P \cdot L)$, where $P$ is the number of pixels and $L$ is the number of steps per ray. The per-step cost is $O(1)$ due to pre-computed transmissivity.

### Measured Performance
Not given in the sources.

### Strengths and Limitations
-   **Strengths:** Significantly accelerates the rendering equation evaluation by pre-computing light transmittance, allowing for real-time or near-real-time rendering of complex volumetric clouds [S1, unofficial]. Supports multiple quality modes for balancing performance and visual fidelity [S1, unofficial].
-   **Limitations:** Requires significant memory to store transmissivity for every voxel. The pre-computation step is expensive if the light source moves frequently. Fixed-step marching (modes 0, 1, 3) may suffer from aliasing or inefficiency compared to voxel-boundary marching (modes 2, 4) [S1, unofficial].

### When to Use
Use when rendering static or slowly moving volumetric clouds where light source position is relatively stable, and real-time performance is required. Choose higher quality modes (3-4) for cinematic quality and lower modes (0-2) for performance-critical applications [S1, unofficial].

## Background
This technique was originally created in 2009 and updated in 2010 by the developer of the open-source project `VolumetricClouds` [S1, unofficial]. The 2010 update involved a complete code rewrite to improve efficiency, implementing new voxel grid traversal algorithms and Perlin noise for cloud generation [S1, unofficial]. It is an unofficial implementation found in a GitHub repository [S1, unofficial].
