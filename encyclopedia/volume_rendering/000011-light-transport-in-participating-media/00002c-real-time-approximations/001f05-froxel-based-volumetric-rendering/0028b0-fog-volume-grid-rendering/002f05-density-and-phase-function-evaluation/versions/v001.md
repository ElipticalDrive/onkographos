# Density and Phase Function Evaluation

Also called: Fog Density and Material Properties Evaluation, Froxel Property Update

## Overview
This method computes the optical properties (density, scattering, absorption) and angular scattering behavior (phase function) for each cell in a froxel-based volumetric grid. It serves as the initialization step for light transport, determining how much light is attenuated and how it is redistributed within the medium before the light injection pass. It differs from sibling methods by focusing solely on material property assignment rather than optimization or entity management.

## How it works
**Inputs:**
- 3D grid dimensions $(W, H, D)$ representing the froxel volume.
- Fog type: Uniform or Dynamic.
- Material parameters: Scattering coefficient $\sigma_s$, Absorption coefficient $\sigma_a$, Asymmetry parameter $g$.
- Auxiliary 3D noise texture (for dynamic fog).
- View-projection matrix and camera parameters (for world-space reconstruction).

**Outputs:**
- 3D texture storing per-froxel data: Extinction coefficient $\sigma_t$, Phase function parameters, and potentially albedo/emission.

**Data Structures:**
- Each froxel cell stores a struct or packed float values containing:
  - $\sigma_t$: Extinction coefficient.
  - $g$: Asymmetry parameter (if spatially varying).
  - Other material properties (albedo, emission) as defined by the parent [Fog Volume Grid Rendering](4350-fog-volume-grid-rendering.md).

**Steps:**
1. **Dispatch Compute Shader:** Execute a compute shader pass using `glDispatchCompute` (or equivalent) with thread groups covering the 3D grid dimensions. Each thread processes one froxel cell.
2. **Reconstruct World Position:** For the current froxel at grid index $(x, y, z)$:
   - Map grid coordinates to normalized device coordinates (NDC).
   - Apply the inverse view-projection matrix to clip-space coordinates.
   - Perform perspective division by $w$ to obtain the world-space center position $\mathbf{P}_{world}$ of the froxel.
   - *Note:* The mapping from view-space depth $z$ to normalized texture coordinate $w$ typically follows:
     $$w = \frac{\ln(z / z_{near})}{\ln(z_{far} / z_{near})}$$
     [S1, unofficial]
3. **Evaluate Density:**
   - **Uniform Fog:** Set density parameters to constant values defined by the material.
   - **Dynamic Fog:** Sample the auxiliary 3D noise texture (e.g., Perlin-Worley noise) using $\mathbf{P}_{world}$ as the coordinate. The noise value modulates the base density.
4. **Compute Extinction Coefficient:** Calculate the total extinction coefficient:
   $$\sigma_t = \sigma_s + \sigma_a$$
   where $\sigma_s$ is the scattering coefficient and $\sigma_a$ is the absorption coefficient. [S1, unofficial]
5. **Evaluate Phase Function:** Compute the Henyey-Greenstein phase function value for the current froxel. This defines the angular distribution of scattered light. The formula is:
   $$p(\theta) = \frac{1}{4\pi} \frac{1 - g^2}{(1 + g^2 - 2g \cos\theta)^{3/2}}$$
   where $g \in (-1, 1)$ is the asymmetry parameter controlling forward ($g > 0$) or backward ($g < 0$) scattering relative to the view vector and light direction. [S1, unofficial]
   - *Note:* The angle $\theta$ is typically computed during the light injection pass based on the specific light direction and view vector. This step may store $g$ for later use or precompute a lookup table if $\theta$ is discretized.

**Pseudocode:**
```python
# Compute Shader Main Function
void main() {
    // 1. Identify froxel index
    ivec3 gridPos = ivec3(gl_GlobalInvocationID);
    
    // 2. Reconstruct world-space position
    // Map gridPos to clip space, apply inverse VP, divide by w
    vec3 worldPos = reconstructWorldPosition(gridPos);
    
    // 3. Evaluate Density
    float density;
    if (fogType == FOG_DYNAMIC) {
        // Sample auxiliary 3D noise texture (e.g., Perlin-Worley)
        density = sampleNoiseTexture(worldPos);
    } else {
        density = FOG_UNIFORM_DENSITY;
    }
    
    // 4. Compute Extinction Coefficient
    // sigma_s and sigma_a are material properties
    float sigma_t = sigma_s + sigma_a;
    
    // 5. Store Properties
    // Store sigma_t and g (asymmetry parameter) in the froxel texture
    froxelTexture[gridPos] = vec4(sigma_t, g, 0.0, 0.0);
}

// Helper: Reconstruct world position from grid index
vec3 reconstructWorldPosition(ivec3 gridPos) {
    // Map grid coordinates to NDC
    vec3 ndc = vec3(
        (gridPos.x + 0.5) / W * 2.0 - 1.0,
        (gridPos.y + 0.5) / H * 2.0 - 1.0,
        (gridPos.z + 0.5) / D * 2.0 - 1.0
    );
    
    // Map NDC depth to view-space depth using logarithmic mapping
    // w is the normalized depth coordinate
    float w = log(ndc.z / z_near) / log(z_far / z_near);
    
    // Convert to clip space
    vec4 clipPos = vec4(ndc.xy, w, 1.0);
    
    // Apply inverse view-projection matrix
    vec4 worldPos = inverseViewProjectionMatrix * clipPos;
    
    // Perspective division
    return worldPos.xyz / worldPos.w;
}
```

**Parameters:**
- $\sigma_s$: Scattering coefficient. Typical values depend on fog density.
- $\sigma_a$: Absorption coefficient.
- $g$: Asymmetry parameter. Range $(-1, 1)$. $g=0$ is isotropic, $g \to 1$ is forward scattering, $g \to -1$ is backward scattering.
- Noise Texture: 3D texture containing Perlin-Worley or similar noise.

**Edge Cases:**
- **Boundary Conditions:** Ensure world-space reconstruction handles froxels outside the camera frustum if the grid extends beyond it.
- **Noise Sampling:** Handle wrap modes for the noise texture to avoid artifacts at grid boundaries.
- **Precision:** Use sufficient precision for $\sigma_t$ and $g$ to avoid banding in the final render.

## Subtopics

### [Froxel-diagonal inverse-square bias](21230-froxel-diagonal-inverse-square-bias.md)
This method bounds the near-field singularity of a point or spot light's inverse-square attenuation in volumetric fog by adding a bias term to the denominator, preventing extreme aliasing and jitter artifacts when samples land very close to the light source. Unlike Godot's fixed floor or Unity's normalized range clamping, this technique uses a bias scaled to the froxel's physical size, ensuring the bound adapts to the resolution and depth of the volume cell.

## Operating characteristics
- **Time Complexity:** $O(W \times H \times D)$, where $W, H, D$ are the grid dimensions. Each froxel is processed once in parallel.
- **Memory Complexity:** $O(W \times H \times D)$ for storing the froxel properties.
- **Performance:** The compute shader pass is highly parallelizable and efficient on modern GPUs. The cost is dominated by memory bandwidth for reading/writing the froxel texture and sampling the noise texture.
- **Strengths:** Simple to implement, flexible for uniform and dynamic fog, provides accurate optical properties for subsequent light transport.
- **Limitations:** Requires a 3D texture for the froxels and an auxiliary noise texture. Dynamic fog requires noise sampling, which can be costly if not optimized.
- **When to Use:** When accurate volumetric fog rendering is required, especially with dynamic or patchy fog.
- **When Not to Use:** For simple uniform fog where constant values suffice, or when memory bandwidth is a critical bottleneck.

## Background
This method is part of the froxel-based volumetric rendering pipeline, specifically the step that initializes the medium properties. It builds on [Fog Volume Grid Rendering](4350-fog-volume-grid-rendering.md). The use of Henyey-Greenstein phase function is standard in computer graphics for simulating light scattering in participating media [S1, unofficial]. The reconstruction of world-space positions from grid indices is a common technique in volumetric rendering to ensure correct spatial sampling of noise and light sources.
