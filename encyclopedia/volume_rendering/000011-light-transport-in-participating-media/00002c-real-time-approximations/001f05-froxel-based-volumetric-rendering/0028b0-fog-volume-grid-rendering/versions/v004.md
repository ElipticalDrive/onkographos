# Fog Volume Grid Rendering

Also called: FogMaterial volumetric fog integration, FogVolume Volumetric Rendering

## Overview
Fog Volume Grid Rendering is a technique for integrating local volumetric fog sources (defined by `FogVolume` and `FogMaterial` nodes) into a froxel-based volumetric rendering pipeline. It solves the problem of missing local fog contributions by adding density, albedo, and emission from scene volumes to the froxels (volumetric grid cells) that the volume's shape geometrically covers, matching the behavior of Godot 4.6.3 [S1, unofficial][S2]. It differs from brute-force volume testing by using precomputed bounds to cull irrelevant volume-froxel pairs, and differs from per-volume dispatch methods by using a single GPU kernel with a culled list of ranges [S1, unofficial][S2]. It builds on [Froxel-based Volumetric Rendering](1919-froxel-based-volumetric-rendering.md).

## How it works
**Inputs and Outputs:**
*   **Inputs:** A list of visible, unculled `FogVolume` entities, each with a `FogMaterial` defining density, albedo, emission, and shape parameters; a froxel grid representing the scene; noise textures (e.g., `NoiseTexture3D`) or image textures (`ImageTexture3D`) for density variation.
*   **Outputs:** Updated froxel grid cells containing accumulated density, albedo, and emission values from all covering volumes.

**Data Structures:**
1.  **Fog Volume Row Texture:** A texture where each row represents a visible, unculled volume. It packs volume parameters (position, size, type, material properties) into a fixed layout. The exact field sizes and bit packing are not given in the sources, but the texture is used to pass volume data to the GPU kernel [S1, unofficial].
2.  **Fog Density Atlas:** A single 3D texture formed by stacking individual density textures (from `NoiseTexture3D` or `ImageTexture3D`) in depth. This is necessary because WebGL2 shaders cannot index a sampler array in a loop. The stack holds floats once a density texture does [S1, unofficial].
3.  **Froxel Grid:** The standard froxel structure, extended to store accumulated fog contributions.

**Numbered Steps:**

1.  **Froxel Range Calculation:** For each visible `FogVolume`, determine which froxels it covers. This involves porting the froxel range calculation logic from Godot's `fog.cpp` (lines 551-718) to compute the axis-aligned bounding box of the volume in froxel space and identifying all froxels intersecting this box [S1, unofficial].
2.  **Volume Packing:** Pack each visible, unculled volume into a row in the Fog Volume Row Texture. This includes its shape parameters (box, ellipsoid, cone, cylinder, world), material properties (density, albedo, emission), and noise texture indices [S1, unofficial].
3.  **Density Texture Generation:**
    *   For `NoiseTexture3D`: Build the density texture as a worker job. Ensure texels and seamless blend match Godot byte-for-byte. The noise is generated using algorithms like simplex or reduced simplex progressive [S1, unofficial].
    *   For `ImageTexture3D`: Decode the image sub-resources in every uncompressed format (8-bit, 16-bit, half, float, RGBA4444, RGB565, RGBE9995) as `Image::_get_color_at_ofs` does. Unpack the pixels accordingly [S1, unofficial].
    *   For imported 3D textures: Cut them into slices matching Godot's layered importer (`resource_importer_layered_texture.cpp:370-386`) [S1, unofficial].
    *   Stack all generated density textures into the Fog Density Atlas [S1, unofficial].
4.  **GPU Kernel Execution (Light Pass):** Execute a compute shader pass (e.g., `glDispatchCompute`) that iterates over the froxels. For each froxel, it reads the list of covering volumes from the Fog Volume Row Texture.
5.  **Fixed-Point Summation:** For each covering volume, calculate its contribution to the froxel's density, albedo, and emission. This involves:
    *   Evaluating the volume's shape function (box, ellipsoid, etc.) at the froxel's center to determine if it is inside the volume.
    *   Applying density modifiers: `GlobalDensity`, `DensityOffset`, `DensityNoiseOffset`, `DensityNoiseScale`, `DensityNoiseFrequency`, `DensityNoiseTimeFrequency`, `FallOffDirLati`, `FallOffDirLong`, `FallOffScale`, `FallOffShift`, `SoftEdges`, `RampStart`, `RampEnd`, `RampInfluence`, `WindInfluence` [S2].
    *   Sampling the Fog Density Atlas using the froxel's position and the volume's noise texture index to get a noise-based density multiplier [S1, unofficial].
    *   Handling Godot's packed-colour overflow for albedo and emission [S1, unofficial].
    *   Accumulating these values into the froxel's storage using fixed-point arithmetic to prevent precision loss [S1, unofficial].
6.  **Edge Cases and Pitfalls:**
    *   **Float Texel Upload:** Float texels upload raw as half float because Godot gives a float format no sRGB view and WebGL2 always filters a half float. An atlas crop of a half-float sheet stays half float; a canvas read converts it to bytes [S1, unofficial].
    *   **ShaderMaterial Limitation:** A fog `ShaderMaterial` runs no fog shader. This requires a shading-language runtime [S1, unofficial].
    *   **Compressed/Integer Formats:** An Image in a block-compressed format draws nothing. An Image in an integer format draws nothing because a float sampler cannot read it [S1, unofficial].
    *   **NoiseTexture3D Build Delay:** A `NoiseTexture3D` shows even density until its build lands [S1, unofficial].
    *   **Stack Limit:** Past 2048 stacked density slices, further textures leave the density even [S1, unofficial].
    *   **sRGB Decoding:** A 3D colour slot still decodes every texture as sRGB. Godot reads a format without an sRGB view raw, so a Lum8 or grey-noise albedo draws too dark [S1, unofficial].

## Subtopics

### [Fog Volume Injection Optimization](15036-fog-volume-injection-optimization.md)
Fog Volume Injection Optimization reduces the computational cost of injecting scene fog volumes into a froxel grid by ensuring each volume is processed only by the froxels it geometrically covers, rather than having every froxel test every scene fog volume. It differs from the brute-force approach (where every froxel iterates all volumes) by using precomputed CPU-side bounds to cull irrelevant volume-froxel pairs, and differs from Godot’s per-volume dispatch by using a single GPU kernel with a culled list of ranges, avoiding the overhead of many small kernel launches.

### Density and Phase Function Evaluation
Execute a compute shader pass (`glDispatchCompute`) to evaluate fog density and material properties for every cell in the 3D texture [S3, unofficial]. For dynamic fog, sample an auxiliary 3D noise texture (e.g., Perlin-Worley noise) using the reconstructed world-space position of the froxel [S3, unofficial]. The extinction coefficient is calculated as $\sigma_t = \sigma_s + \sigma_a$, where $\sigma_s$ is scattering and $\sigma_a$ is absorption [S3, unofficial]. The angular distribution of scattered light is modeled using the Henyey-Greenstein phase function: $p(\theta) = \frac{1}{4\pi} \frac{1 - g^2}{(1 + g^2 - 2g \cos\theta)^{3/2}}$, where $g \in (-1, 1)$ is the asymmetry parameter [S3, unofficial].

### Fog Volume Entity
An entity used to control local fog density and color by adding fog density and color into an area [S2]. It supports parameters such as `Active`, `AffectsThisAreaOnly`, `Color`, `GlobalDensity`, `DensityNoiseOffset`, `DensityNoiseScale`, `DensityNoiseTimeFrequency`, `DensityOffset`, `FallOffDirLati`, `FallOffDirLong`, `FallOffScale`, `FallOffShift`, `NearCutOff`, `RampStart`, `RampEnd`, `RampInfluence`, `SoftEdges`, `UseGlobalFogColor`, `VolumeType`, `WindInfluence`, `DensityNoiseFrequency XYZ`, and `Size XYZ` [S2].

## Operating characteristics
*   **Time Complexity:** Depends on the number of visible volumes and the number of froxels they cover. The optimization reduces this from $O(N_{froxels} \times N_{volumes})$ to $O(\sum_{volumes} N_{covering\_froxels})$ [S1, unofficial][S2].
*   **Memory Complexity:** Requires storage for the Fog Volume Row Texture (proportional to the number of visible volumes) and the Fog Density Atlas (proportional to the number of density textures, up to 2048 slices) [S1, unofficial].
*   **Measured Performance:** Golden test 'fog-volume' (3x3x3 box at 0, 1, -5): Mean error against Godot 4.6.3 drops from 3.476/255 (no volume) to 0.205/255 [S1, unofficial]. Value check mean error over pixels the volume changes in Godot: box 13.05→0.40, ellipsoid 10.66→0.22, cone 8.90→0.40, cylinder 15.67→0.41, world shape 14.07→0.25, negative density 3.65→0.26, height falloff 2 9.58→0.24, edge fade 0 14.21→0.40, edge fade 4 2.55→0.08, no material 13.21→0.35, albedo/emission 32.91→1.13, density 8 23.92→0.45, rotated/scaled 13.73→0.30, spot/sun lights 24.70→0.60 [S1, unofficial]. Value check mean error over whole frame: imported 3D texture 3.554→0.209, ImageTexture3D .tres Lum8 4.459→0.206, NoiseTexture3D .tres 5.418→0.196, ImageTexture3D .tres RHalf 2.227→0.215, RFloat 2.229→0.216, R16 1.153→0.184, RGBE9995 2.229→0.215, NoiseTexture3D warp simplex 0.714→0.194, reduced simplex progressive 0.683→0.199, basic grid independent 0.496→0.196 [S1, unofficial].
*   **Strengths:** Accurately matches Godot 4.6.3 behavior; supports various volume shapes and density modifiers; optimized to avoid brute-force testing.
*   **Limitations:** WebGL2 limitations (no sampler array indexing in loops); float texel upload issues; compressed/integer format drawing issues; noise texture build delay; stack limit of 2048 slices; sRGB decoding issues for 3D color slots; ShaderMaterial limitation [S1, unofficial].
*   **When to use:** When local volumetric fog effects are needed in a froxel-based rendering pipeline, especially in WebGL2 environments.
*   **When not to use:** When high-performance real-time rendering with many dynamic volumes is required and the overhead of texture generation and atlas management is prohibitive; when using compressed or integer formats for density textures.

## Background
Fog Volume Grid Rendering was introduced to address the missing local fog contributions in the volumetric fog system. It was implemented to match the behavior of Godot 4.6.3's volume pass [S1, unofficial]. The implementation involved porting froxel range calculation logic from Godot's `fog.cpp`, creating new resources for `FogVolume` and `FogMaterial`, and building density textures as worker jobs [S1, unofficial]. It closes issue #665 [S1, unofficial].
