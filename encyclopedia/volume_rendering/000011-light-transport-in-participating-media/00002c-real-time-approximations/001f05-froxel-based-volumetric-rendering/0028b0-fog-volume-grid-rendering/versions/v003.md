# Fog Volume Grid Rendering

Also called: FogMaterial volumetric fog integration, FogVolume Volumetric Rendering

## Overview
Fog Volume Grid Rendering is a technique for integrating static and dynamic volumetric fog sources (defined by `FogVolume` and `FogMaterial` nodes) into a froxel-based volumetric rendering pipeline. It solves the problem of missing local fog contributions by adding the density, albedo, and emission of each volume to the froxels (volumetric grid cells) that the volume's shape geometrically covers, matching the behavior of Godot 4.6.3 [S1, unofficial]. It differs from its siblings by focusing on the **injection** of discrete volume definitions into the global froxel grid, whereas [Froxel TAA Reprojection](1920-froxel-taa-reprojection.md) handles temporal stability, [Froxel Depth Distribution](1922-froxel-depth-distribution.md) handles depth precision, and [Volumetric Accumulation Rendering Pipeline](1932-volumetric-accumulation-rendering-pipeline.md) handles the final accumulation pass.

## How it works
**Inputs:**
- A list of visible, unculled `FogVolume` nodes, each with a `FogMaterial` defining density, albedo, emission, and shape parameters.
- A froxel grid (3D texture) representing the volumetric space.
- Density textures: `NoiseTexture3D`, `ImageTexture3D` (inline or `.tres`), or imported 3D textures.

**Outputs:**
- Updated froxel grid with accumulated density, albedo, and emission values from all active volumes.

**Data Structures:**
1.  **Fog Volume Row Texture:** A 1D texture where each row represents a visible volume. It packs volume parameters (position, scale, rotation, shape type, material properties) for efficient shader access.
2.  **Fog Density Atlas:** A single 3D texture formed by stacking individual density textures in depth. This is necessary because WebGL2 shaders cannot index a sampler array in a loop [S1, unofficial]. The atlas holds floats once a density texture is processed.
3.  **Image Sub-resource Decoding:** Supports 8-bit, 16-bit, half, float, RGBA4444, RGB565, and RGBE9995 formats, unpacked as `Image::_get_color_at_ofs` does [S1, unofficial].

**Steps:**

1.  **Froxel Range Calculation:**
    For each visible `FogVolume`, calculate the bounding box of froxels it covers. This involves porting the froxel range calculation logic from Godot's `fog.cpp` (lines 551-718) to determine which grid cells intersect the volume's shape (box, ellipsoid, cone, cylinder, or world) [S1, unofficial].

2.  **Volume Packing:**
    Pack each visible, unculled volume into a row in the `fogVolumeRows` texture using `fogVolumeRows.ts`. This prepares the volume data for the compute shader [S1, unofficial].

3.  **Density Texture Preparation:**
    -   Build `NoiseTexture3D` density textures as a worker job, ensuring texels and seamless blend match Godot byte-for-byte [S1, unofficial].
    -   For imported 3D textures, cut them into slices matching Godot's layered importer (`resource_importer_layered_texture.cpp:370-386`) [S1, unofficial].
    -   Decode `Image` sub-resources in every uncompressed format (8-bit, 16-bit, half, float, RGBA4444, RGB565, RGBE9995) [S1, unofficial].
    -   Stack every density texture in depth into one 3D texture (`fogDensityAtlas.ts`) [S1, unofficial].

4.  **Compute Shader Execution (Density and Phase Function Evaluation):**
    Execute a compute shader pass (`glDispatchCompute`) to evaluate fog density and material properties for every cell in the 3D texture [S2, unofficial].
    -   **World Position Reconstruction:** Map the 3D grid index $(x, y, z)$ to clip space, apply the inverse view-projection matrix, and divide by $w$ to determine the world-space center of the cell [S2, unofficial].
    -   **Density Sampling:** For dynamic fog, sample an auxiliary 3D noise texture (e.g., Perlin-Worley noise) using the reconstructed world-space position of the froxel [S2, unofficial].
    -   **Material Properties:** Calculate extinction coefficient $\sigma_t = \sigma_s + \sigma_a$, where $\sigma_s$ is scattering and $\sigma_a$ is absorption [S2, unofficial].
    -   **Phase Function:** Evaluate the Henyey-Greenstein phase function:
        $$p(\theta) = \frac{1}{4\pi} \frac{1 - g^2}{(1 + g^2 - 2g \cos\theta)^{3/2}}$$
        where $g \in (-1, 1)$ is the asymmetry parameter [S2, unofficial].

5.  **Light Pass Integration:**
    In the light pass, use `fogVolumeShader.ts` to add the volumes' fixed-point sums to the froxels. This step handles Godot's packed-colour overflow [S1, unofficial]. It supports height falloff, edge fade, negative density, and the default fog shader for volumes without a material [S1, unofficial].

6.  **Resource Slot Handling:**
    Use `useTextResourceSlot` to read a slot naming a `.tres` file as that file's `[resource]` in the file's own tables. This allows `AtlasTexture` to use the inline route [S1, unofficial].

**Parameters:**
-   `density_texture`: A `FogMaterial` property that shapes density. It can be a `NoiseTexture3D`, an `ImageTexture3D` (inline or saved as `.tres`), or an imported 3D texture [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Float Texel Upload:** Float texels upload raw as half float because Godot gives a float format no sRGB view and WebGL2 always filters a half float. An atlas crop of a half-float sheet stays half float; a canvas read converts it to bytes [S1, unofficial].
-   **ShaderMaterial Limitation:** A fog `ShaderMaterial` runs no fog shader. This requires a shading-language runtime (Issue #734) [S1, unofficial].
-   **Compressed/Integer Formats:** An Image in a block-compressed format draws nothing. An Image in an integer format draws nothing because a float sampler cannot read it (Issue #736) [S1, unofficial].
-   **NoiseTexture3D Build Delay:** A `NoiseTexture3D` shows even density until its build lands [S1, unofficial].
-   **Slice Limit:** Past 2048 stacked density slices, further textures leave the density even [S1, unofficial].
-   **sRGB Decoding:** A 3D colour slot still decodes every texture as sRGB. Godot reads a format without an sRGB view raw, so a Lum8 or grey-noise albedo draws too dark (Issue #737) [S1, unofficial].

## Subtopics

### [Fog Volume Injection Optimization](15036-fog-volume-injection-optimization.md)
Fog Volume Injection Optimization is a performance enhancement for froxel-based volumetric rendering that restricts the injection of scene fog volumes to only those froxels they geometrically cover, eliminating the naive $O(N_{froxels} \times N_{volumes})$ test where every froxel evaluates every volume. It differs from the baseline SGL3D implementation by replacing the global volume loop with a targeted dispatch mechanism, matching the approach used in Godot's renderer which computes per-volume AABBs and dispatches kernels only for covered regions.

## Operating characteristics
-   **Time Complexity:** The baseline approach without optimization is $O(N_{froxels} \times N_{volumes})$. With injection optimization, it becomes proportional to the number of froxels actually covered by volumes.
-   **Memory Complexity:** Requires storage for the froxel grid, the fog volume row texture, and the fog density atlas. The atlas size depends on the number of stacked density textures.
-   **Measured Performance:** Golden test 'fog-volume' (3x3x3 box at 0, 1, -5): Mean error against Godot 4.6.3 drops from 3.476/255 (no volume) to 0.205/255 [S1, unofficial]. Value check mean error over pixels the volume changes in Godot: box 13.05→0.40, ellipsoid 10.66→0.22, cone 8.90→0.40, cylinder 15.67→0.41, world shape 14.07→0.25, negative density 3.65→0.26, height falloff 2 9.58→0.24, edge fade 0 14.21→0.40, edge fade 4 2.55→0.08, no material 13.21→0.35, albedo/emission 32.91→1.13, density 8 23.92→0.45, rotated/scaled 13.73→0.30, spot/sun lights 24.70→0.60 [S1, unofficial]. Value check mean error over whole frame: imported 3D texture 3.554→0.209, ImageTexture3D .tres Lum8 4.459→0.206, NoiseTexture3D .tres 5.418→0.196, ImageTexture3D .tres RHalf 2.227→0.215, RFloat 2.229→0.216, R16 1.153→0.184, RGBE9995 2.229→0.215, NoiseTexture3D warp simplex 0.714→0.194, reduced simplex progressive 0.683→0.199, basic grid independent 0.496→0.196 [S1, unofficial].
-   **Strengths:** High accuracy compared to Godot 4.6.3, supports various volume shapes and material properties.
-   **Limitations:** WebGL2 limitations on sampler arrays, sRGB decoding issues, block-compressed format support gaps, and noise texture build delays.
-   **When to use:** When accurate local volumetric fog integration is required and the target platform supports WebGL2 compute shaders.
-   **When not to use:** When performance is critical and the number of volumes is very high without optimization, or when block-compressed textures are necessary.

## Background
Fog Volume Grid Rendering is based on the volumetric fog implementation in Godot 4.6.3, specifically the behavior of `FogVolume` and `FogMaterial` nodes [S1, unofficial]. The technique was ported to a WebGL2-based renderer (textscene-inspector) to provide similar volumetric fog capabilities in a web environment. The implementation addresses specific challenges of WebGL2, such as the inability to index sampler arrays in loops and the handling of various texture formats.
