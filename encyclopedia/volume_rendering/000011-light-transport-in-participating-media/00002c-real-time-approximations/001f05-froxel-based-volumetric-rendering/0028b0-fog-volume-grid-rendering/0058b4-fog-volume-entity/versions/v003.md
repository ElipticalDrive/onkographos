# Fog Volume Entity

Also called: Fog Volume Entity Setup, FogVolume
## Overview
The Fog Volume Entity defines local volumetric fog density, color, and noise-based structure within a 3D level [S1]. It solves the problem of creating non-uniform, patchy fog effects that global fog settings cannot produce [S1]. It differs from [Fog Volume Grid Rendering](4350-fog-volume-grid-rendering.md) by providing a high-level entity interface for shaping fog via noise parameters rather than directly manipulating froxel data [S1].
## How it works
### Inputs and Outputs
The entity accepts spatial placement and parameter values [S1]. It outputs an `Enabled` boolean state via Flow Graph [S1].

### Data Structures
The entity exposes scalar and boolean parameters with the following ranges [S1].

**Parameter Layout:**
*   `Density`: Float. Range: $[0, 100]$. Controls base fog density [S1].
*   `DensityNoiseOffset`: Float. Range: $[-2, +2]$. Offsets the noise value for density [S1].
*   `DensityNoiseScale`: Float. Range: $[0, 10]$. Scales the noise value for density [S1].
*   `DensityNoiseFrequency`: Vector3 $(X, Y, Z)$. Defines the frequency of noise patches [S1].
*   `DensityNoiseTimeFrequency`: Float. Controls the speed of temporal morphing [S1].
*   `WindInfluence`: Float. Range: $[0, 20]$. Controls the influence of global wind [S1].
*   `UseGlobalFogColor`: Boolean. Overrides local color with global fog color [S1].
*   `Enabled`: Boolean. Controls entity state [S1].

### Steps and Formulas
The entity generates a local fog field by combining a base density with a noise function [S1]. The exact noise function implementation is not provided in the sources [G]. The following procedural steps describe the configuration and runtime behavior:

1.  **Initialization**: Place the entity in the level and define its spatial bounds (e.g., $50\text{m} \times 50\text{m} \times 50\text{m}$) [S1].
2.  **Base Density Setup**: Set `Density` to a high value (e.g., $100$) for visibility during setup, or to a production value (typically $1$–$3$) for subtle effects [S1].
3.  **Noise Offset Application**: Apply `DensityNoiseOffset` [S1]. A negative value (e.g., $-1.2$) breaks the solid volume into patches [S1].
4.  **Noise Scaling**: Apply `DensityNoiseScale` [S1]. This defines the thickness of individual fog patches (clouds) or the spacing between them [S1]. A value of $0.5$ thins density and increases spacing [S1].
5.  **Frequency Definition**: Set `DensityNoiseFrequency` $(X, Y, Z)$ [S1]. Increasing $Z$ (e.g., from $10$ to $100$) creates a layered effect [S1]. Higher $X$ and $Y$ values create more individual patches [S1]. Varying $X, Y, Z$ values randomly breaks up patches into different sizes [S1].
6.  **Temporal Morphing**: Apply `DensityNoiseTimeFrequency` [S1]. A low value (e.g., $0.2$) ensures natural morphing; higher values cause unnatural quick morphing [S1].
7.  **Color Blending**: If `UseGlobalFogColor` is enabled, the entity's local color is overridden by the global fog color, ensuring natural blending [S1].
8.  **Wind Interaction**: Apply `WindInfluence` to allow global wind to affect the fog volume's shape or movement [S1].

### Edge Cases and Pitfalls
*   **High Density Values**: Setting `Density` to $100$ is intended for setup visibility only [S1]. Using this in production results in unnatural, opaque fog [S1].
*   **Fast Morphing**: High `DensityNoiseTimeFrequency` values cause unnatural, rapid morphing of fog patches [S1].
*   **Parameter Coupling**: `DensityNoiseOffset` and `DensityNoiseScale` work closely together; adjusting one often requires tweaking the other to maintain the desired patch structure [S1].

## Operating characteristics
*   **Performance**: Performance impact depends on the number of active Fog Volume entities [S1]. The entity is controlled via Flow Graph, allowing runtime modification of parameters [S1].
*   **Memory**: Memory usage is associated with the entity's transform and parameter storage [S1].
*   **Strengths**: Allows for complex, non-uniform fog structures (banks, layers) without manual texture painting or complex shader graphs [S1].
*   **Limitations**: Limited to the parameters exposed by the entity [S1].
*   **When to use**: For creating localized fog effects like mist, fog banks, or layered clouds in specific areas of a level [S1].
*   **When not to use**: For uniform, global fog effects, which are better handled by global fog settings [S1].

## Background
The Fog Volume Entity is part of the CRYENGINE 5 Volumetric Fog system [S1]. It was introduced to provide artists with control over density noise, enabling the creation of interesting shapes within fog volumes [S1]. It is used in conjunction with the Flow Graph system for runtime control [S1].
