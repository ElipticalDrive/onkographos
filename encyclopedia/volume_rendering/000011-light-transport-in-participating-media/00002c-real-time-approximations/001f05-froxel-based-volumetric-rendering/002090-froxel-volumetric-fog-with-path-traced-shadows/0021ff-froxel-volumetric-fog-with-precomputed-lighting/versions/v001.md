# Froxel Volumetric Fog with Precomputed Lighting

Also called: Froxel Fog, Froxel Volumetric Fog Renderer, Frustum Voxel Fog, Volumetric Fog System

## Overview
Froxel Volumetric Fog with Precomputed Lighting is a real-time rendering technique that simulates light scattering in participating media (mist, smoke, atmospheric fog) by dividing the camera view frustum into a 3D grid of voxels called "froxels" [S1, S2, unofficial]. Unlike traditional distance fog, which applies a uniform screen-space blur, this method allows for dynamic light beams, shadowed fog, and density variations within the volume [S2, unofficial]. It distinguishes itself from its sibling method, [Froxel Volumetric Fog with Path-Traced Shadows](2314-froxel-volumetric-fog-with-path-traced-shadows.md), by using precomputed lighting passes (specifically Next Event Estimation approximations via compute shaders) rather than runtime path tracing for shadow calculation, offering a balance between visual fidelity and performance [S1, S2, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   Camera view frustum parameters (near/far planes, projection matrix).
*   Scene lighting data (directional light direction/color, point/spot lights, sky ambient).
*   Fog parameters (base density, height falloff, ground height, wind vector, noise scale).
*   Prebaked 3D noise texture (128x128x128 tileable) [S1, unofficial].
*   Previous frame's froxel history (for temporal reprojection) [S1, unofficial].

**Outputs:**
*   Integrated froxel volume (RGB: accumulated in-scattered radiance; Alpha: remaining transmittance) [S1, unofficial].
*   Composite result: Fogged scene color, optionally written back to `_CameraOpaqueTexture` for refractive materials [S1, unofficial].

### Data Structures

**Froxel Grid (Material Volume):**
*   **Type:** 3D Render Texture (`Tex3D`) [S2, unofficial].
*   **Format:** `R16G16B16A16_SFloat` [S2, unofficial].
*   **Dimensions:** Vary by quality preset [S1, unofficial]:
    *   Low: 80 x 45 x 64
    *   Medium: 160 x 90 x 64
    *   High: 160 x 90 x 128
    *   Ultra: 240 x 135 x 128
*   **Layout:**
    *   `RGB`: Scattering radiance [S1, unofficial].
    *   `A`: Extinction coefficient (density) [S1, unofficial].
*   **Flags:** `enableRandomWrite = true` [S2, unofficial].

**Integrated Volume:**
*   **Layout:**
    *   `RGB`: Accumulated in-scattered radiance [S1, unofficial].
    *   `A`: Remaining transmittance [S1, unofficial].

**History Storage:**
*   Ping-ponged between two 3D render textures per camera [S1, unofficial].
*   Separate history buffers for Game View and Scene View to prevent garbage during editor camera movement [S1, unofficial].

### Numbered Steps

1.  **Noise Bake:** Sample the prebaked 128x128x128 tileable 3D noise texture. The lookup is animated by wind: $uvw = \frac{worldPos}{noiseScale} - wind \times \frac{time}{noiseScale}$ [S1, unofficial].
2.  **Inject Density:** Compute density for each froxel based on height falloff. Calculate $h = worldPos.y - groundHeight$. Compute density: $density = baseDensity \times \exp\left(-\frac{\max(h, 0.0)}{\max(heightFalloff, 0.01)}\right)$ [S1, unofficial]. Write `float4(density, density, density, 1)` to the material volume [S2, unofficial].
3.  **Scatter Lighting:** Reconstruct jittered world positions for each froxel. Compute lighting contributions from:
    *   Main directional light and shadows.
    *   Point/Spot lights and their shadows.
    *   Sky ambient and atmospheric sun tint [S1, unofficial].
    *   Apply Henyey-Greenstein phase function with anisotropy $g$. Add low-frequency anisotropy noise to prevent banding near forward directions [S1, unofficial].
    *   Clamp light contributions to prevent temporal instability spikes from lights near their source [S1, unofficial].
    *   Write `float4(lighting, density)` to the material volume [S2, unofficial].
4.  **Multiple Scattering Approximation:** Apply octave approximation. First octave is direct single scattering. Later octaves broaden the phase lobe, soften shadows, and reduce intensity to fill shadows and prevent dullness [S1, unofficial].
5.  **Temporal Reprojection:**
    *   Jitter the current froxel center using spatio-temporal blue noise (or Interleaved Gradient Noise if unavailable) [S1, unofficial].
    *   Reproject the current froxel center into the previous frame using the previous view-projection matrix.
    *   If the point lands inside the old volume, manually trilinear sample history.
    *   Blend: $blended = \text{lerp}(history.rgb, current.rgb, temporalBlend)$ where `temporalBlend` is typically 0.9 [S1, S2, unofficial].
6.  **Spatial Filtering:** Apply a 3x3x3 Gaussian-style filter over the scattering volume. Filter RGB only; let extinction (Alpha) pass through unchanged to preserve depth and absorption profiles [S1, unofficial]. Store history *before* filtering to prevent blur stacking [S1, unofficial].
7.  **Integrate:** March through Z for every screen-space XY cell using exponential depth slices. For each slice:
    *   Calculate depth: $depth = nearDistance \times \exp\left(\frac{slice}{sliceCount} \times \log\left(\frac{farDistance}{nearDistance}\right)\right)$ [S1, unofficial].
    *   Compute optical depth: $opticalDepth = extinction \times sliceThickness$.
    *   Compute slice transmittance: $sliceTransmittance = \exp(-opticalDepth)$.
    *   Compute slice scatter: $sliceScatter = scatter \times (1 - sliceTransmittance) / extinction$ [S1, unofficial].
    *   Accumulate scatter into RGB and transmittance into Alpha [S1, unofficial].
8.  **Composite:** Sample camera depth, convert to froxel Z, read integrated volume. Apply: $finalColor = sceneColor \times transmittance + accumulatedScatter$ [S1, unofficial].
    *   Near pixels pass through unchanged.
    *   Pixels beyond the froxel far distance use analytical extension: terrain pixels estimate extinction rate from integrated transmittance; sky pixels integrate exponential height fog toward the horizon [S1, unofficial].
9.  **Update Opaque Texture:** Copy the fogged color back into `_CameraOpaqueTexture` so refractive shaders (glass, windshields) sample the fogged world [S1, unofficial].

### Pseudocode

```python
# Compute Shader: FogDensity.compute
# Inputs: FogVolume (RWTexture3D<float4>), fogHeight, density
# Output: FogVolume

kernel void CSMain(uint3 id : SV_DispatchThreadID) {
    // Height-based density injection
    float heightFactor = saturate(1.0 - id.y / fogHeight);
    float fog = density * heightFactor;
    
    // Write density to RGB, 1.0 to Alpha (extinction placeholder)
    FogVolume[id] = float4(fog, fog, fog, 1.0);
}

# Compute Shader: FogLighting.compute
# Inputs: FogVolume (RWTexture3D<float4>), lightDirection, lightColor
# Output: FogVolume

kernel void CSMain(uint3 id : SV_DispatchThreadID) {
    // Read current density
    float density = FogVolume[id].r;
    
    // Approximate phase function (dot product with light direction)
    // Note: In production, use Henyey-Greenstein with anisotropy g
    float scatter = saturate(dot(normalize(float3(0, 1, 0)), -lightDirection));
    
    // Compute lighting contribution
    float3 lighting = lightColor * density * scatter;
    
    // Write lighting to RGB, density to Alpha
    FogVolume[id] = float4(lighting, density);
}

# Fragment Shader: RayMarchFog
# Inputs: rayOrigin, rayDir, _FogVolume (Texture3D), sampler_FogVolume
# Output: float4

float4 RayMarchFog(float3 rayOrigin, float3 rayDir) {
    float stepSize = 0.5;
    float3 pos = rayOrigin;
    float3 color = 0.0;
    float transmittance = 1.0;
    
    // Fixed iteration count for simplicity; production may use depth-based termination
    for (int i = 0; i < 64; i++) {
        // Sample 3D texture
        float4 fog = SAMPLE_TEXTURE3D(_FogVolume, sampler_FogVolume, pos);
        
        // Accumulate color
        color += fog.rgb * transmittance;
        
        // Update transmittance
        transmittance *= exp(-fog.a * stepSize);
        
        // Advance position
        pos += rayDir * stepSize;
    }
    
    return float4(color, 1.0);
}

# Composite Shader: VolumetricComposite
# Inputs: sceneColor, cameraDepth, integratedVolume, sampler_IntegratedVolume
# Output: finalColor

float4 VolumetricComposite(float2 uv, float depth) {
    // Convert camera depth to froxel Z coordinate
    float froxelZ = DepthToFroxelZ(depth);
    
    // Sample integrated volume
    float4 integrated = SAMPLE_TEXTURE3D(integratedVolume, sampler_IntegratedVolume, float3(uv, froxelZ));
    
    float transmittance = integrated.a;
    float3 accumulatedScatter = integrated.rgb;
    
    // Composite equation
    float3 finalColor = sceneColor * transmittance + accumulatedScatter;
    
    return float4(finalColor, 1.0);
}
```

### Parameters and Typical Values
*   **Grid Resolution:** 160x90x64 (Medium) is common for AAA games, often running at 1/4 screen resolution [S2, unofficial].
*   **Temporal Blend Factor:** 0.9 [S2, unofficial].
*   **Step Size:** 0.5 (in ray marching example) [S2, unofficial].
*   **Noise Texture:** 128x128x128 tileable 3D texture [S1, unofficial].
*   **Anisotropy ($g$):** Positive values push energy forward (sun halos/headlight beams); $g \approx 0$ scatters softly [S1, unofficial].

### Edge Cases and Pitfalls
*   **Banding:** High anisotropy noise causes banding near forward directions. Keep anisotropy noise amount small [S1, unofficial].
*   **Temporal Instability:** Point/spot lights near their source can cause spikes. Clamp light contributions before entering the volume [S1, unofficial].
*   **Blur Stacking:** Spatial filtering must run after reprojection, but history must be stored *before* filtering to prevent blur accumulation [S1, unofficial].
*   **Volume Termination:** Pixels beyond the froxel far distance require analytical extension to prevent the fog from ending at a camera-locked plane [S1, unofficial].

## Operating characteristics

### Time and Memory Complexity
*   **Memory:** Proportional to grid dimensions ($W \times H \times D$) and format size (16 bytes per voxel for R16G16B16A16_SFloat) [S2, unofficial]. History requires double the volume memory [S1, unofficial].
*   **Time:** Dominated by the lighting compute pass (proportional to voxel count) and the integration/composite pass (proportional to screen resolution) [S1, S2, unofficial].

### Measured Performance
*   Most AAA games run fog at 1/4 resolution to maintain performance [S2, unofficial].
*   Specific hardware-dependent metrics are not provided in the sources.

### Strengths and Limitations
*   **Strengths:** Reacts to sky, local lights, headlights, weather, and transparent materials without full-screen blur; allows light beams and shadowed fog; efficient via precomputed lighting [S1, S2, unofficial].
*   **Limitations:** Precomputed lighting approximates shadows (less accurate than path-traced shadows in the sibling method); requires careful tuning of temporal stability and anisotropy to avoid artifacts [S1, S2, unofficial].

### When to Use
*   Use for atmospheric fog, mist, and smoke where dynamic lighting interaction is required but full path-traced shadows are too expensive.
*   Avoid when high-fidelity, physically accurate shadowing within the volume is critical and hardware supports real-time path tracing.

## Background

### Origin
The term "froxel" (frustum voxel) is attributed to Alex Evans and Sony ATG, described in the "Learning from Failure" SIGGRAPH 2015 talk and noted in the Real-Time Rendering blog and *Call of Duty: Advanced Warfare* post-processing [S1, unofficial]. The Henyey-Greenstein phase function source is L. G. Henyey and J. L. Greenstein, *The Astrophysical Journal*, 1941 [S1, unofficial].

### History
The technique evolved from production needs for fog that reacts to dynamic lighting without the cost of full volumetric ray marching. It was popularized in URP (Universal Render Pipeline) implementations as a ScriptableRendererFeature [S1, unofficial].
