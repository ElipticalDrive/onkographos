# Karis-Inspired Anti-Flicker

Also called: Anti-Flicker, Anti-Flicker Heuristic, Clipping-aware Temporal Blending

## Overview
Karis-Inspired Anti-Flicker is a heuristic temporal anti-aliasing technique for froxel-based volumetric rendering that reduces visual flicker introduced by variance clipping [S1, unofficial]. It biases the temporal signal towards the frame where clipping occurs, effectively dampening the impact of quick impulses caused by discontinuities in the history buffer [S1, unofficial]. Unlike fixed alpha blending, it dynamically adjusts the blend factor based on the distance between the reprojected history and its clipped counterpart, offering superior stability in static scenes with high-contrast noise or spot lights without globally degrading accuracy [S1, unofficial].

## How it works
The method operates in the RGB color space [S1, unofficial]. It modifies the blend factor $\alpha$ used in the temporal accumulation step of the Froxel TAA Reprojection pipeline [S1, unofficial].

**Inputs and Outputs:**
*   **Input:** The reprojected history value $h_{reprojected}$ and the clipped history value $h_{clipped}$ for a specific froxel $i$ at frame $t$ [S1, unofficial].
*   **Output:** The adaptive blend factor $\alpha_{i,t}$ and the final accumulated color [S1, unofficial].

**Data Structures:**
*   **Color Vector:** $h_{reprojected}$ and $h_{clipped}$ are 3-component vectors (RGB) [S1, unofficial].
*   **Parameters:**
    *   $\alpha_{\min}$: Minimum blend factor. Typical value: $0.02$ [S1, unofficial].
    *   $\alpha_{\max}$: Maximum blend factor. Typical value: $0.05$ [S1, unofficial].
    *   $d_{\min}$: Lower bound for distance scaling. Typical value: $0$ [S1, unofficial].
    *   $d_{\max}$: Upper bound for distance scaling. Typical value: $0.1$ [S1, unofficial].

**Steps:**
1.  **Compute Distance:** Calculate the Euclidean distance $d_{i,t}$ in color space between the reprojected history and the clipped history [S1, unofficial]:
    $$d_{i,t} = \| h_{reprojected} - h_{clipped} \|$$
2.  **Compute Interpolation Factor:** Calculate the normalized interpolation factor $k$ using linear scaling clamped to $[0, 1]$ [S1, unofficial]:
    $$k = \text{clamp} \left( \frac{d_{i,t} - d_{\min}}{d_{\max} - d_{\min}}, 0, 1 \right)$$
3.  **Compute Blend Factor:** Interpolate between $\alpha_{\min}$ and $\alpha_{\max}$ based on $k$ [S1, unofficial]:
    $$\alpha_{i,t} = (1 - k)\alpha_{\min} + k\alpha_{\max}$$
4.  **Accumulate:** Use $\alpha_{i,t}$ as the blend weight in the standard temporal accumulation formula:
    $$C_{current} = \alpha_{i,t} \cdot C_{clipped} + (1 - \alpha_{i,t}) \cdot C_{history}$$
    *(Note: The specific accumulation formula is inherited from the parent method [Froxel TAA Reprojection](1920-froxel-taa-reprojection.md) [G].)*

**Pseudocode:**
```python
def compute_karis_blend_factor(h_reprojected, h_clipped, alpha_min=0.02, alpha_max=0.05, d_min=0.0, d_max=0.1):
    """
    Computes the adaptive blend factor for Karis-Inspired Anti-Flicker.
    
    Args:
        h_reprojected: List[float, float, float] - RGB vector of reprojected history.
        h_clipped: List[float, float, float] - RGB vector of clipped history.
        alpha_min: float - Minimum blend factor.
        alpha_max: float - Maximum blend factor.
        d_min: float - Lower bound for distance scaling.
        d_max: float - Upper bound for distance scaling.
        
    Returns:
        float - The adaptive blend factor alpha_i,t.
    """
    # Step 1: Compute Euclidean distance in RGB space
    diff_r = h_reprojected[0] - h_clipped[0]
    diff_g = h_reprojected[1] - h_clipped[1]
    diff_b = h_reprojected[2] - h_clipped[2]
    distance = (diff_r**2 + diff_g**2 + diff_b**2)**0.5
    
    # Step 2: Compute interpolation factor k
    if d_max == d_min:
        k = 0.0
    else:
        k = (distance - d_min) / (d_max - d_min)
        # Clamp k to [0, 1]
        if k < 0.0:
            k = 0.0
        elif k > 1.0:
            k = 1.0
            
    # Step 3: Compute blend factor alpha
    alpha = (1.0 - k) * alpha_min + k * alpha_max
    
    return alpha
```

**Edge Cases and Pitfalls:**
*   **Color Space:** The method must be applied in RGB color space [S1, unofficial]. Implementations in YCoCg or YCrCb color spaces produced excessive flickering and were deemed infeasible [S1, unofficial].
*   **Spot Light Variance:** Near the origin of spot lights, sub-froxel jittering causes sampled values to jump from zero to high intensity, creating high variance [S1, unofficial]. This is mitigated by introducing a minimum distance threshold of $0.5$ meters for spot light intensity calculations; samples closer than this use the minimum distance [S1, unofficial]. This reduces fireflies but makes the spot light attenuation shape less visually distinct [S1, unofficial].

## Subtopics

### [Malan-Inspired Adaptive Blending](1928-malan-inspired-adaptive-blending.md)
An adaptive blending method that does not modify the history buffer but changes the blend factor adaptively based on the color extent of the local neighborhood. It uses a linear mapping of the neighborhood extent to the blend factor. Unlike Karis-Inspired Anti-Flicker, which reacts to clipping discontinuities, Malan-Inspired Adaptive Blending reacts to local color variation. See [Malan-Inspired Adaptive Blending](1928-malan-inspired-adaptive-blending.md).

### Frostbite Volumetric TAA
The final proposed volumetric TAA algorithm implemented in the Frostbite engine, combining variance clipping and anti-flicker with specific parameter settings [S1, unofficial]. Anti-flicker uses $\alpha_{\min} = 0.02$, $\alpha_{\max} = 0.05$, and $d_{\max} = 0.1$ [S1, unofficial]. The bounds for variance clipping are constructed using a 6-tap neighborhood [S1, unofficial]. Initially, YCoCg was implemented but produced too much flickering to be feasible, so RGB is used instead [S1, unofficial]. Spot light intensity calculations enforce a minimum distance threshold of $0.5$ meters to mitigate high-intensity fireflies caused by sub-froxel jittering near the light origin, at the cost of a less visually distinct attenuation shape [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per froxel, as it involves a constant number of arithmetic operations (distance calculation, clamp, linear interpolation) [S1, unofficial].
*   **Performance:** In a static noise cube scenario, anti-flicker decreased Temporal Instability by $56.21\%$ compared to fixed alpha blending, while RMSE remained slightly lower ($0.251354$ vs $0.251850$) [S1, unofficial]. In a dynamic noise cube scenario, it increased Temporal Instability by only $1.41\%$ compared to fixed alpha blending, with negligible visual difference [S1, unofficial].
*   **Strengths:** Significantly reduces flicker in static scenes with high-contrast elements (e.g., spot lights, noise textures) compared to fixed alpha blending [S1, unofficial]. It is more effective than simply lowering the global blend factor, which results in worse accuracy and higher Temporal Instability [S1, unofficial].
*   **Limitations:** In dynamic scenarios, the performance gain over fixed alpha blending is negligible [S1, unofficial]. The spot light mitigation (minimum distance threshold) reduces visual fidelity of the light's attenuation shape [S1, unofficial].
*   **When to Use:** Recommended for scenes with static or slowly moving volumetric noise and spot lights where variance clipping causes visible flickering [S1, unofficial].
*   **When Not to Use:** Not recommended if YCoCg or YCrCb color spaces are required for other pipeline stages, as they cause flickering [S1, unofficial].

## Background
The method is based on the work by Karis [16] and was implemented and tested in the context of real-time froxel-based volumetric rendering [S1, unofficial]. It was specifically designed to address the Temporal Instability (flicker) introduced by variance clipping, which creates sharp discontinuities in the history buffer [S1, unofficial]. The technique was first tested in Godot using scenes with static noise density textures and spot lights, and later implemented in the Frostbite engine as part of the final proposed volumetric TAA algorithm [S1, unofficial].
