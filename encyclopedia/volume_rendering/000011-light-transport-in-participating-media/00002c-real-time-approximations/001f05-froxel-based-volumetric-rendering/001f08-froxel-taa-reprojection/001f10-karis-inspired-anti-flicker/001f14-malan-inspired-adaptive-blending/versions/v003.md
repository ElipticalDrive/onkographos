# Malan-Inspired Adaptive Blending

Also called: Linear Blend Factor Mapping, Malan's Neighborhood Color Range Adaptation

## Overview
Malan-Inspired Adaptive Blending is a temporal anti-aliasing technique for froxel-based volumetric rendering that computes the blend factor $\alpha$ based on the spatial extent of the color neighborhood in the current frame [S1, unofficial]. Unlike history rectification methods that modify the stored history value, this method leaves the history unchanged and instead adaptively adjusts the weight given to the previous frame [S1, unofficial]. It sets itself apart from its parent [Karis-Inspired Anti-Flicker](1924-karis-inspired-anti-flicker.md) by using the local color variance to determine stability rather than relying on clipping heuristics, thereby balancing ghosting reduction in flat areas with temporal stability in high-frequency regions [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** The current frame's froxel color $c_{i,t}$, the previous frame's history froxel color $h_{i,t-1}$, and the spatial neighborhood of current-frame samples surrounding pixel $i$ [S1, unofficial].
*   **Output:** The temporally blended froxel color $f_{i,t}$ and the updated blend factor $\alpha_{i,t}$ [S1, unofficial].

**Data Structures:**
*   **Froxel:** Stores color values and history [S1, unofficial].
*   **Neighborhood:** A set of current-frame samples surrounding the target pixel $i$ [S1, unofficial].

**Steps:**
1.  **Color Space Transformation:** Retrieve the current-frame samples for the neighborhood and transform them into a chosen color space (e.g., CoCg, YCrCb) [S1, unofficial].
2.  **Compute Extent ($r_{i,t}$):** Determine the component-wise minimum ($c_{min}$) and maximum ($c_{max}$) color values within the transformed neighborhood [S1, unofficial]. Calculate the extent $r_{i,t}$ as the Euclidean length of the difference vector between these bounds:
    $$r_{i,t} = |c_{max} - c_{min}|$$
    where $c_{min}$ and $c_{max}$ are vectors in the chosen color space [S1, unofficial].
3.  **Compute Scaling Factor ($k$):** Map the extent $r_{i,t}$ to a scaling factor $k$ using a linear mapping bounded by $r_{min}$ and $r_{max}$:
    $$k = 1 - \text{clamp}\left(\frac{r_{i,t} - r_{\min}}{r_{\max} - r_{\min}}, 0, 1\right)$$
    where $\text{clamp}(x, 0, 1)$ restricts $x$ to the range $[0, 1]$ [S1, unofficial].
4.  **Compute Blend Factor ($\alpha_{i,t}$):** Calculate the final blend factor using the minimum and maximum user-defined blend factors:
    $$\alpha_{i,t} = (1 - k)\alpha_{\min} + k\alpha_{\max}$$
    This formula ensures that a small extent (flat color) results in a high $k$ and thus a high $\alpha$ (more current frame contribution, faster convergence), while a large extent (edges/noise) results in a low $k$ and low $\alpha$ (less current frame contribution, more temporal blurring) [S1, unofficial].
5.  **Blending:** Blend the history and current frame using the computed $\alpha_{i,t}$ in the transformed color space, then transform the result back to RGB space before storage [S1, unofficial].

**Parameters:**
*   $\alpha_{\min} = 0.05$: Minimum blend factor [S1, unofficial].
*   $\alpha_{\max} = 0.50$: Maximum blend factor [S1, unofficial].
*   $r_{\min} = 0.01$: Lower bound for the neighborhood extent range [S1, unofficial].
*   $r_{\max} = 0.40$: Upper bound for the neighborhood extent range [S1, unofficial].

```python
def malan_adaptive_blending(current_froxel, history_froxel, neighborhood_samples,
                            alpha_min=0.05, alpha_max=0.50, r_min=0.01, r_max=0.40,
                            color_space="RGB"):
    # Step 1: Transform neighborhood samples to the chosen color space
    transformed_samples = [transform_to_space(sample, color_space) for sample in neighborhood_samples]

    # Step 2: Compute extent r_i,t
    # Find component-wise min and max in the transformed space
    c_min = list(transformed_samples[0])
    c_max = list(transformed_samples[0])

    for sample in transformed_samples[1:]:
        for j in range(3):
            if sample[j] < c_min[j]:
                c_min[j] = sample[j]
            if sample[j] > c_max[j]:
                c_max[j] = sample[j]

    # Calculate Euclidean length of the difference vector
    diff = [c_max[j] - c_min[j] for j in range(3)]
    r_i_t = math.sqrt(sum(d * d for d in diff))

    # Step 3: Compute scaling factor k
    if r_max == r_min:
        k = 0.5  # Fallback when range is zero [G]
    else:
        ratio = (r_i_t - r_min) / (r_max - r_min)
        ratio = clamp(ratio, 0.0, 1.0)
        k = 1.0 - ratio

    # Step 4: Compute blend factor alpha_i,t
    alpha_i_t = (1.0 - k) * alpha_min + k * alpha_max

    # Step 5: Blend in the transformed color space
    c_transformed = transform_to_space(current_froxel, color_space)
    h_transformed = transform_to_space(history_froxel, color_space)

    blended_transformed = [
        (1.0 - alpha_i_t) * h_transformed[j] + alpha_i_t * c_transformed[j]
        for j in range(3)
    ]

    # Transform result back to RGB space before storage
    blended_color = transform_from_space(blended_transformed, color_space)

    return blended_color, alpha_i_t
```

**Edge Cases and Pitfalls:**
*   **Division by Zero:** If $r_{max} = r_{min}$, the denominator becomes zero [S1, unofficial]. The source does not specify a fallback, but $r_{max}$ should be strictly greater than $r_{min}$ [S1, unofficial].
*   **Color Space Choice:** The source notes that CoCg and YCrCb were implemented and evaluated, and the choice affects the calculation [S1, unofficial].

## Subtopics

### [Adaptive Blending](1983-adaptive-blending.md)
A temporal anti-aliasing technique that reduces ghosting artifacts in volumetric rendering by constraining the maximum amount the historical buffer can be updated per frame. Unlike methods that modify history validity or reject stale data, this approach limits the blend factor itself, ensuring gradual convergence rather than instant replacement. It is distinct from variance clipping, which reduces ghosting more effectively while exhibiting similar temporal instability. Choose this variant when you need to balance ghosting with temporal stability on a per-scene basis without altering the stored history values.
