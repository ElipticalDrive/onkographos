# Malan-Inspired Adaptive Blending

Also called: Linear Blend Factor Mapping, Malan's Neighborhood Color Range Adaptation

## Overview
Malan-Inspired Adaptive Blending is a temporal anti-aliasing technique for froxel-based volumetric rendering that computes the blend factor $\alpha$ based on the spatial extent of the color neighborhood in the current frame [S1, unofficial]. Unlike history rectification methods that modify the stored history value, this method leaves the history unchanged and instead adaptively adjusts the weight given to the previous frame [S1, unofficial]. It sets itself apart from its parent [Karis-Inspired Anti-Flicker](1924-karis-inspired-anti-flicker.md) by using the local color variance to determine stability rather than relying on clipping heuristics, thereby balancing ghosting reduction in flat areas with temporal stability in high-frequency regions [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** The current frame's froxel color $c_{i,t}$, the previous frame's history froxel color $h_{i,t-1}$, and the spatial neighborhood of current-frame samples surrounding pixel $i$.
*   **Output:** The temporally blended froxel color $f_{i,t}$ and the updated blend factor $\alpha_{i,t}$.

**Data Structures:**
*   **Froxel:** Stores color values (typically RGB or a transformed color space) and history.
*   **Neighborhood:** A set of current-frame samples surrounding the target pixel $i$. The specific radius or kernel shape is not defined in the source, but implies a local spatial window [S1, unofficial].

**Steps:**
1.  **Color Space Transformation:** Retrieve the current-frame samples for the neighborhood. Transform these samples from RGB into a chosen color space (e.g., CoCg, YCrCb) to better align with human perception or reduce chromatic artifacts [S1, unofficial].
2.  **Compute Extent ($r_{i,t}$):** Determine the minimum ($c_{min}$) and maximum ($c_{max}$) color values within the transformed neighborhood. Calculate the extent $r_{i,t}$ as the Euclidean length of the difference vector between these bounds:
    $$r_{i,t} = |c_{max} - c_{min}|$$
    where $c_{min}$ and $c_{max}$ are vectors in the transformed color space [S1, unofficial].
3.  **Compute Scaling Factor ($k$):** Map the extent $r_{i,t}$ to a scaling factor $k$ using a linear mapping bounded by $r_{min}$ and $r_{max}$:
    $$k = 1 - \text{clamp}\left(\frac{r_{i,t} - r_{\min}}{r_{\max} - r_{\min}}, 0, 1\right)$$
    Here, $\text{clamp}(x, 0, 1)$ restricts $x$ to the range $[0, 1]$ [S1, unofficial].
4.  **Compute Blend Factor ($\alpha_{i,t}$):** Calculate the final blend factor using the minimum and maximum user-defined blend factors:
    $$\alpha_{i,t} = (1 - k)\alpha_{\min} + k\alpha_{\max}$$
    This formula ensures that a small extent (flat color) results in a high $k$ and thus a high $\alpha$ (more history contribution, faster convergence), while a large extent (edges/noise) results in a low $k$ and low $\alpha$ (less history contribution, more temporal blurring) [S1, unofficial].
5.  **Blending:** Blend the history and current frame using the computed $\alpha_{i,t}$:
    $$f_{i,t} = (1 - \alpha_{i,t}) h_{i,t-1} + \alpha_{i,t} c_{i,t}$$
    Transform the result back to RGB space if a different color space was used for the neighborhood analysis [S1, unofficial].
6.  **Update History:** Store $f_{i,t}$ as the new history $h_{i,t}$ for the next frame [S1, unofficial].

**Parameters:**
*   $\alpha_{\min} = 0.05$: Minimum blend factor. [S1, unofficial]
*   $\alpha_{\max} = 0.50$: Maximum blend factor. [S1, unofficial]
*   $r_{\min} = 0.01$: Lower bound for the neighborhood extent range. [S1, unofficial]
*   $r_{\max} = 0.40$: Upper bound for the neighborhood extent range. [S1, unofficial]

**Pseudocode:**
```python
def malan_adaptive_blending(current_froxel, history_froxel, neighborhood_samples, 
                            alpha_min=0.05, alpha_max=0.50, r_min=0.01, r_max=0.40):
    """
    Computes the blended froxel color using Malan-Inspired Adaptive Blending.
    
    Args:
        current_froxel: Color vector of the current frame pixel (RGB).
        history_froxel: Color vector from the previous frame (RGB).
        neighborhood_samples: List of color vectors from the spatial neighborhood (RGB).
        alpha_min: Minimum blend factor.
        alpha_max: Maximum blend factor.
        r_min: Lower bound for extent scaling.
        r_max: Upper bound for extent scaling.
        
    Returns:
        blended_color: The temporally anti-aliased color (RGB).
    """
    
    # Step 1: Transform neighborhood samples to a perceptual color space.
    # Note: The source mentions CoCg and YCrCb were evaluated. 
    # We assume a generic transform function for demonstration.
    transformed_samples = [rgb_to_transformed(sample) for sample in neighborhood_samples]
    
    # Step 2: Compute extent r_i,t
    # Find min and max components in the transformed space.
    # c_min and c_max are vectors.
    c_min = transformed_samples[0].copy()
    c_max = transformed_samples[0].copy()
    
    for sample in transformed_samples[1:]:
        for j in range(3):
            if sample[j] < c_min[j]:
                c_min[j] = sample[j]
            if sample[j] > c_max[j]:
                c_max[j] = sample[j]
                
    # Calculate Euclidean length of the difference vector
    diff = [c_max[j] - c_min[j] for j in range(3)]
    r_i_t = math.sqrt(sum(d*d for d in diff))
    
    # Step 3: Compute scaling factor k
    # clamp((r_i_t - r_min) / (r_max - r_min), 0, 1)
    if r_max == r_min:
        # Avoid division by zero; if range is zero, k is undefined by formula.
        # Default to 0.5 or handle as edge case. Source does not specify.
        # Assuming standard clamp behavior if denominator is 0 is not defined.
        # We will assume r_max > r_min in practice.
        k = 0.5 
    else:
        ratio = (r_i_t - r_min) / (r_max - r_min)
        ratio = max(0.0, min(1.0, ratio)) # clamp
        k = 1.0 - ratio
        
    # Step 4: Compute blend factor alpha_i,t
    alpha_i_t = (1.0 - k) * alpha_min + k * alpha_max
    
    # Step 5: Blend
    # Transform current froxel to the same space for consistent blending?
    # Source says: "The final blended result is transformed back into RGB space 
    # before being stored". It implies blending might happen in RGB or the 
    # transformed space. Equation 3.6 uses alpha on c_i,t and h. 
    # Usually, if color space transform is used for extent, blending is done 
    # in that space or RGB. The source states: "After retrieving any sample, 
    # it is transformed... The final blended result is transformed back".
    # This implies: Transform current and history, blend in transformed space, 
    # then transform back.
    
    c_transformed = rgb_to_transformed(current_froxel)
    h_transformed = rgb_to_transformed(history_froxel)
    
    blended_transformed = [
        (1.0 - alpha_i_t) * h_transformed[j] + alpha_i_t * c_transformed[j]
        for j in range(3)
    ]
    
    blended_color = transformed_to_rgb(blended_transformed)
    
    return blended_color
```

**Edge Cases and Pitfalls:**
*   **Division by Zero:** If $r_{max} = r_{min}$, the denominator in the $k$ calculation becomes zero. The source does not specify a fallback, but logically $r_{max}$ should be strictly greater than $r_{min}$ [S1, unofficial].
*   **Color Space Choice:** The source notes that CoCg and YCrCb were implemented and evaluated. The choice of color space affects the calculation of $r_{i,t}$ and thus the blend factor. RGB is not explicitly recommended for the extent calculation due to potential perceptual inaccuracies [S1, unofficial].
*   **Neighborhood Definition:** The exact size or shape of the "local neighborhood" is not specified. Implementers must define this (e.g., 3x3, 5x5 kernel) [S1, unofficial].

## Subtopics

### [Adaptive Blending](1983-adaptive-blending.md)
A method that reduces ghosting by allowing the history to be modified by a maximum blend factor per frame. A maximum blend factor of 50% was tested. This variant modifies the history value itself, whereas Malan-Inspired Adaptive Blending only modifies the blend factor.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of samples in the neighborhood, as it requires iterating through the neighborhood to find min/max values.
*   **Memory Complexity:** $O(1)$ additional memory per froxel for storing the blend factor and temporary min/max values.
*   **Performance:** The method adds computational overhead due to the neighborhood analysis and color space transformations. However, it avoids the more complex history rectification logic.
*   **Strengths:** Effectively reduces ghosting in flat, static areas by allowing the history to contribute more (high $\alpha$). Provides temporal stability in noisy or high-frequency areas by reducing the history contribution (low $\alpha$). Allows artists to tune the balance between ghosting and stability via $\alpha_{min}$, $\alpha_{max}$, $r_{min}$, and $r_{max}$ [S1, unofficial].
*   **Limitations:** Does not correct stale history values directly; it only weights them less. If the history is significantly wrong, it may still cause artifacts, albeit reduced. The quality depends heavily on the choice of color space and neighborhood size [S1, unofficial].
*   **When to use:** When ghosting in flat regions is a primary concern and a simple, parameter-tunable solution is preferred over history modification.
*   **When not to use:** When severe history staleness occurs that cannot be mitigated by simply reducing the blend weight, or when computational budget is extremely tight and neighborhood analysis is too expensive.
