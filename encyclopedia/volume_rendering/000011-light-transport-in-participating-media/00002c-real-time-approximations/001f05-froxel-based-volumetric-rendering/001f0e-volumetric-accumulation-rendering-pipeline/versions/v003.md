# Volumetric Accumulation Rendering Pipeline

Also called: Froxel-based Volumetric Accumulation, Temporal Froxel Rendering

## Overview
The Volumetric Accumulation Rendering Pipeline is a real-time approximation for rendering participating media using a low-resolution 3D grid of "froxels" (volume pixels) within the camera frustum [S1, unofficial]. It solves the computational intractability of full volumetric light transport by decoupling the expensive in-scattering calculation from the final integration, using temporal accumulation to stabilize the noisy samples across frames [S1, unofficial]. It differs from [Froxel TAA Reprojection](1920-froxel-taa-reprojection.md) by explicitly defining the full pipeline stages including the 3D integration and final compositing, and from [Froxel Depth Distribution](1922-froxel-depth-distribution.md) by relying on temporal history rather than spatial depth distributions for anti-aliasing and stability [S1, unofficial].

## How it works
**Inputs:** Camera view/projection matrices, world-to-camera transform, froxel grid resolution, volumetric effect range, per-frame jitter offset, and previous frame's history buffer.
**Outputs:** Final composited image with volumetric lighting contribution.

**Data Structures:**
1.  **Froxel Grid:** A 3D texture of size $W \times H \times D$.
    *   $W, H$: Screen-space width and height (e.g., 160x90, 240x135). Aspect ratio $\approx 16:9$.
    *   $D$: Depth slices covering the volumetric effect range (e.g., 64 or 128).
    *   Each cell stores in-scattered radiance and participating media density.
2.  **History Buffer:** Same dimensions as the Froxel Grid. Stores the temporally accumulated radiance values $f_t(p)$ for each froxel $p$ [S1, unofficial].
3.  **Integrated 3D Texture:** Output of the integration pass. Same size as the Froxel Grid. Each slice contains the accumulated volumetric transmittance up to that depth [S1, unofficial].

**Parameters:**
*   **Froxel Resolution:** Varies by platform. Common values: $160 \times 90 \times 64$, $160 \times 90 \times 128$, $160 \times 88 \times 64$, or $240 \times 135 \times 64$ [S1, unofficial].
*   **Volumetric Effect Range:** Depth extent of the grid. Typical values: 50–128 meters (Wronski), ~160 meters (RDR2) [S1, unofficial].
*   **Blending Factor ($\alpha$):** Exponential moving average weight, $\alpha \in [0, 1]$ [S1, unofficial].
*   **Jitter Offset:** Per-frame sub-froxel offset, often from a Halton sequence [S1, unofficial].

**Steps:**

1.  **Grid Creation:** Create a low-resolution froxel grid aligned with the camera frustum for the current frame [S1, unofficial].
2.  **In-Scattering Compute:** In a GPU compute shader, compute local in-scattered radiance and participating media density for each froxel in parallel [S1, unofficial].
3.  **Jittering:** Acquire the per-frame sub-froxel jitter offset. Apply this offset to the sampling point within the froxel [S1, unofficial].
4.  **Reprojection:** Reproject the history buffer from the previous frame into the current frame's froxel grid using a reprojection vector derived from camera movement [S1, unofficial].
    *   If reprojection fails (e.g., vector points outside the history buffer), discard history and use the current frame sample [S1, unofficial].
5.  **Temporal Blending:** Blend the current frame sample $s_t(p)$ with the reprojected history $f_{t-1}(\pi(p))$ using an exponential moving average:
    $$ f_t(p) = \alpha s_t(p) + (1 - \alpha) f_{t-1}(\pi(p)) $$
    where $f_t(p)$ is the blended radiance for froxel $p$ at frame $t$ [S1, unofficial].
6.  **Smoothing (Optional):** Apply a low-pass filter (e.g., Gaussian blur with radius 3) to smooth sharp changes between nearby froxels [S1, unofficial]. Note: This may remove sharp features [S1, unofficial].
7.  **Integration:** Integrate volumetric radiance and transmittance through the froxel grid depth-wise from the camera outward.
    *   Performed in a low-resolution 2D shader corresponding to the $x$ and $y$ dimensions of the grid.
    *   Accumulate transmitted radiance into an output 3D texture, where each slice contains the accumulated transmittance up to that depth [S1, unofficial].
8.  **Rendering:** Render participating media onto the scene.
    *   Transform world-space fragment positions into froxel space.
    *   Sample the integrated 3D texture at the transformed position to acquire the volumetric contribution [S1, unofficial].
    *   Filter the sampled texture (e.g., quadrilinear filtering) to prevent a jagged/pixelated appearance [S1, unofficial].
9.  **Compositing:** Blend the resulting volumetric contribution with previously rendered geometry using pre-multiplied color/alpha blending [S1, unofficial].

**Pseudocode:**

```python
# Step 1-3: Compute In-Scattering
def compute_froxel_radiance(froxel_grid, jitter_offset):
    for each froxel p in froxel_grid:
        # Apply jitter to sampling point
        sample_point = p.center + jitter_offset
        # Compute local in-scattered radiance and density
        radiance = compute_in_scattered_radiance(sample_point)
        density = compute_media_density(sample_point)
        froxel_grid[p].radiance = radiance
        froxel_grid[p].density = density

# Step 4-5: Temporal Accumulation
def accumulate_history(current_radiance, history_buffer, reprojection_vector, alpha):
    new_history = empty_buffer_like(history_buffer)
    for each froxel p in history_buffer:
        # Reproject previous history position to current frame
        reprojected_pos = reproject(p.position, reprojection_vector)
        
        # Check if reprojection is valid (within bounds)
        if is_valid(reprojected_pos):
            old_radiance = history_buffer[reprojected_pos].radiance
        else:
            old_radiance = 0.0 # Reset history on failure
            
        # Exponential Moving Average
        current_sample = current_radiance[p].radiance
        new_radiance = alpha * current_sample + (1 - alpha) * old_radiance
        new_history[p].radiance = new_radiance
        
    return new_history

# Step 6: Optional Smoothing
def smooth_froxels(froxel_grid, blur_radius=3):
    # Apply Gaussian blur to froxel_grid.radiance
    froxel_grid.radiance = gaussian_blur(froxel_grid.radiance, blur_radius)

# Step 7: Integration
def integrate_transmittance(froxel_grid):
    # Output 3D texture same size as froxel_grid
    integrated_texture = empty_3d_texture_like(froxel_grid)
    
    # Iterate over x, y (screen space dimensions)
    for x in range(froxel_grid.width):
        for y in range(froxel_grid.height):
            accumulated_transmittance = 1.0
            accumulated_radiance = 0.0
            
            # Step through depth slices from camera outward
            for z in range(froxel_grid.depth):
                froxel = froxel_grid[x, y, z]
                # Simple volume rendering integration step
                # T(z) = T(z-1) * exp(-density * step_size)
                # L(z) += T(z) * radiance * (1 - exp(-density * step_size))
                
                transmittance_factor = exp(-froxel.density * step_size)
                accumulated_transmittance *= transmittance_factor
                
                contribution = accumulated_transmittance * froxel.radiance * (1 - transmittance_factor)
                accumulated_radiance += contribution
                
                # Store accumulated transmittance up to this depth
                integrated_texture[x, y, z].transmittance = accumulated_transmittance
                
    return integrated_texture

# Step 8-9: Final Rendering
def render_volumetrics(integrated_texture, camera_transform, geometry_buffer):
    for each fragment in geometry_buffer:
        # Transform world position to froxel space
        froxel_pos = transform_to_froxel_space(fragment.world_position, camera_transform)
        
        # Sample integrated texture
        volumetric_contribution = sample_3d_texture(integrated_texture, froxel_pos)
        
        # Filter to smooth result
        volumetric_contribution = quadrilinear_filter(integrated_texture, froxel_pos)
        
        # Blend with geometry
        final_color = pre_multiply_blend(geometry_buffer.color, volumetric_contribution)
        return final_color
```

## Subtopics

### [Accumulation Buffer Composite](2368-accumulation-buffer-composite.md)
The Accumulation Buffer Composite is a post-processing step that averages accumulated color samples from a stochastic volume renderer and blends the result with the background using a reveal factor.

### [Empirical Volume Shading with Indirect Light Approximation](4092-empirical-volume-shading-with-indirect-light-approximation.md)
Empirical Volume Shading with Indirect Light Approximation is a real-time shading model for participating media that approximates global illumination by blurring direct light within a local neighborhood cone and applying a separate indirect attenuation term. It solves the computational intractability of full light transport in participating media by decoupling indirect lighting from high-resolution volume data, allowing for interactive frame rates without pre-computed global illumination caches. It differs from traditional volume rendering by adding indirect attenuation and local light diffusion, and from full global illumination by restricting scattering to a local blur rather than computing transport from all directions.

### SNeRG Deferred Shading Model
SNeRG decomposes the radiance field into a 3D field of densities, diffuse RGB colors, and feature vectors to reduce MLP evaluations to one per ray [S2]. It volumetrically accumulates diffuse colors and features, then computes view-dependent color using a small MLP [S2].
*   **Accumulation:** $C_d = \sum_i w_i c_{d,i}$ and $F = \sum_i w_i f_i$.
*   **Final Color:** $C = C_d + h(C_d, F, d)$, where $h$ is a small MLP [S2].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of froxels ($W \times H \times D$) for the compute and integration passes. Independent of screen resolution, making performance stable across different display settings [S1, unofficial].
*   **Memory Complexity:** Cubic with respect to the froxel grid dimensions ($W \times H \times D$) for storing the grid and history buffers [S1, unofficial].
*   **Performance:** Low-resolution grids (e.g., 160x90x64) allow for real-time frame rates on modern GPUs [S1, unofficial].
*   **Strengths:** Real-time performance; temporal accumulation reduces noise; decoupled integration allows for efficient depth-wise accumulation [S1, unofficial].
*   **Limitations:** Ghosting artifacts if reprojection fails or motion is too fast; blurring from low-pass filters may reduce detail; memory usage scales cubically with grid resolution [S1, unofficial].
*   **When to use:** Real-time applications requiring volumetric effects (fog, smoke) with temporal stability.
*   **When not to use:** Scenes with high-speed camera motion where reprojection is unreliable, or where high-frequency volumetric detail is critical without blurring.

## Background
The Volumetric Accumulation Rendering Pipeline is based on froxel-based volumetric rendering techniques introduced for real-time graphics. Key implementations include Wronski's work (160x90x64/128 resolution, 50-128m range) [S1, unofficial], Red Dead Redemption 2 (160x88x64, ~160m range) [S1, unofficial], and Unity HDRP (240x135x64) [S1, unofficial]. The use of temporal accumulation with exponential moving averages and reprojection is a standard technique in real-time rendering to stabilize noisy volumetric samples [S1, unofficial].
