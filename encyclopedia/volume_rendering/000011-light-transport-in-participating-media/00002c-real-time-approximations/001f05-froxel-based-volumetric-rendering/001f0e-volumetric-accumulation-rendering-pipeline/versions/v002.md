# Volumetric Accumulation Rendering Pipeline


## Overview
The Volumetric Accumulation Rendering Pipeline is a real-time approximation method for light transport in participating media that uses a low-resolution froxel grid to compute in-scattered radiance and applies temporal anti-aliasing to stabilize the result [S1, unofficial]. It solves the high computational cost and cubic memory scaling of full volumetric ray-marching by decoupling the scattering calculation from the final high-resolution rendering pass, relying on history reprojection and exponential smoothing to reduce noise [S1, unofficial].

## How it works
**Inputs:** Camera view/projection matrices, previous frame's history buffer, current frame's geometry depth/position data, volumetric effect range, and froxel grid resolution [S1, unofficial].
**Outputs:** Final composited image with volumetric fog [S1, unofficial].

**Data Structures:**
1.  **Froxel Grid:** A 3D texture of size $W \times H \times D$ [S1, unofficial].
    *   $W, H$: Screen-space width/height (e.g., 160×90) with an aspect ratio of $\sim 16:9$ [S1, unofficial].
    *   $D$: Depth slices covering the volumetric effect range (e.g., 64 or 128) [S1, unofficial].
    *   Layout: Linear memory or 3D texture format; each cell stores computed in-scattered radiance and participating media density [S1, unofficial].
2.  **History Buffer:** Same dimensions as the Froxel Grid [S1, unofficial]. Stores the accumulated radiance value $f_t(p)$ for each froxel $p$ at frame $t$ [S1, unofficial].
3.  **Integrated 3D Texture:** Same dimensions as the Froxel Grid [S1, unofficial]. Each slice contains accumulated volumetric transmittance up to that depth [S1, unofficial].

**Parameters:**
*   **Froxel Resolution:** Varies by platform. Typical: $160 \times 90 \times 64$ or $160 \times 90 \times 128$ [S1, unofficial]. Unity HDRP default: $240 \times 135 \times 64$ [S1, unofficial]. RDR2: $160 \times 88 \times 64$ [S1, unofficial].
*   **Volumetric Effect Range:** Depth extent of the grid. Typical: 50–128 meters (Wronski), $\sim 160$ meters (RDR2) [S1, unofficial].
*   **Blending Factor ($\alpha$):** Exponential moving average weight, $\alpha \in [0, 1]$ [S1, unofficial].
*   **Jitter Offset:** Per-frame sub-froxel offset, typically from a Halton sequence [S1, unofficial].

**Steps:**
1.  **Grid Creation:** Create a low-resolution froxel grid aligned with the camera frustum for the current frame, covering the defined volumetric effect range [S1, unofficial].
2.  **Compute In-Scattered Radiance:** In a GPU compute shader, compute the local in-scattered radiance and participating media density for each froxel in parallel [S1, unofficial].
3.  **Jitter Sampling:** Acquire the per-frame sub-froxel jitter offset and apply it to the sampling point within the froxel [S1, unofficial]. The offset is pre-calculated and passed as a shader parameter [S1, unofficial].
4.  **Reprojection:** Reproject the history buffer from the previous frame into the current frame's froxel grid using a reprojection vector derived from the camera's movement and rotation between frames [S1, unofficial]. For each froxel $p$, calculate the reprojected coordinate $\pi(p)$ using the vector and the froxel's position [S1, unofficial]. If $\pi(p)$ falls outside the history buffer bounds, discard the history and use the current sample only [S1, unofficial].
5.  **Temporal Blending:** Blend the current frame's sample $s_t(p)$ with the reprojected history $f_{t-1}(\pi(p))$ using an exponential moving average:
    $$ f_t(p) = \alpha s_t(p) + (1 - \alpha) f_{t-1}(\pi(p)) $$
    where $f_t(p)$ is the blended radiance for froxel $p$ at frame $t$ [S1, unofficial]. Store $f_t(p)$ in the history buffer for the next frame [S1, unofficial].
6.  **Low-Pass Filtering (Optional):** Apply a low-pass filter (e.g., Gaussian blur with radius 3) to the froxel grid to smooth sharp changes between nearby froxels [S1, unofficial]. This may remove sharp features depending on the use-case [S1, unofficial].
7.  **Depth-Wise Integration:** Integrate volumetric radiance and transmittance through the froxel grid depth-wise from the camera outward [S1, unofficial]. Perform this in a low-resolution 2D shader corresponding to the $x$ and $y$ dimensions of the grid [S1, unofficial]. Accumulate transmitted radiance into an output 3D texture, where each slice contains the accumulated volumetric transmittance up to that depth [S1, unofficial].
8.  **Final Rendering:** Render participating media onto the scene [S1, unofficial]. Transform world-space fragment positions into froxel space [S1, unofficial]. Sample the integrated 3D texture at the transformed position to acquire the volumetric contribution [S1, unofficial]. Apply filtering (e.g., quadrilinear filtering) to the sampled texture to prevent a jagged or pixelated appearance [S1, unofficial]. Blend the result with previously rendered geometry using pre-multiplied color/alpha blending [S1, unofficial].

**Pseudocode:**

def compute_froxel_radiance(froxel_grid, history_buffer, camera_matrix, prev_camera_matrix, jitter_offset, alpha):
    # Step 1: Grid is implicitly created based on camera frustum and effect range [S1, unofficial]
    # Step 2: Compute local in-scattered radiance and density for each froxel in parallel [S1, unofficial]
    for froxel in froxel_grid:
        # Step 3: Acquire and apply per-frame sub-froxel jitter offset [S1, unofficial]
        sample_pos = froxel.position + jitter_offset
        current_sample = compute_in_scattered_radiance(sample_pos, froxel.density)
        
        # Step 4: Reproject history buffer [S1, unofficial]
        reprojection_vector = get_camera_movement_vector(camera_matrix, prev_camera_matrix)
        prev_pos = froxel.position + reprojection_vector
        if is_within_bounds(prev_pos, history_buffer):
            history_value = history_buffer.sample(prev_pos)
        else:
            history_value = 0.0  # Reset history if out of bounds [S1, unofficial]
            
        # Step 5: Temporal blending (Exponential Moving Average) [S1, unofficial]
        blended_radiance = alpha * current_sample + (1 - alpha) * history_value
        history_buffer.set(froxel.position, blended_radiance)

def integrate_volumetric_data(froxel_grid, effect_range, depth_slices):
    # Step 7: Integrate volumetric radiance and transmittance depth-wise [S1, unofficial]
    integrated_texture = create_3d_texture(froxel_grid.dimensions)
    step_size = effect_range / depth_slices
    for x in range(froxel_grid.width):
        for y in range(froxel_grid.height):
            accumulated_transmittance = 1.0
            accumulated_radiance = 0.0
            for z in range(depth_slices):
                froxel = froxel_grid[x, y, z]
                # Compute transmittance over one froxel step [G]
                transmittance = exp(-froxel.density * step_size)
                accumulated_radiance += froxel.radiance * accumulated_transmittance
                accumulated_transmittance *= transmittance
                integrated_texture[x, y, z] = (accumulated_radiance, accumulated_transmittance)
    return integrated_texture

def render_volumetric_fog(scene_geometry, integrated_texture, froxel_grid):
    # Step 8: Final rendering pass [S1, unofficial]
    for fragment in scene_geometry:
        froxel_pos = transform_to_froxel_space(fragment.world_position)
        # Sample integrated 3D texture with quadrilinear filtering [S1, unofficial]
        volumetric_contribution = integrated_texture.quadrilinear_sample(froxel_pos)
        # Blend with previously rendered geometry using pre-multiplied color/alpha blending [S1, unofficial]
        final_color = blend_pre_multiplied(fragment.color, volumetric_contribution)
        return final_color

# Helper definitions
def compute_in_scattered_radiance(position, density):
    # Computes local in-scattered radiance based on position and density [G]
    return density * 0.5  # Placeholder for scene-specific lighting model [G]

def get_camera_movement_vector(curr_mat, prev_mat):
    # Returns translation/rotation delta between frames [G]
    return curr_mat.translation - prev_mat.translation

def is_within_bounds(pos, buffer):
    # Checks if coordinates fall inside buffer dimensions [G]
    return 0 <= pos.x < buffer.width and 0 <= pos.y < buffer.height and 0 <= pos.z < buffer.depth

def transform_to_froxel_space(world_pos):
    # Transforms world coordinates into froxel grid space [G]
    return froxel_grid.world_to_local_matrix * world_pos

def blend_pre_multiplied(geom_color, vol_contrib):
    # Applies pre-multiplied alpha blending [G]
    return geom_color + vol_contrib * (1.0 - geom_color.a)

def create_3d_texture(dimensions):
    # Allocates and returns a 3D texture array [G]
    return Texture3D(dimensions)

## Operating characteristics
**Time Complexity:** The core computation scales with the number of froxels ($W \times H \times D$), which is fixed and independent of screen resolution, making performance predictable [S1, unofficial]. The integration pass scales with $W \times H \times D$ [S1, unofficial]. The final rendering pass scales with screen resolution but is lightweight (texture sampling and blending) [S1, unofficial].
**Memory Complexity:** Scales cubically with froxel resolution [S1, unofficial]. For $160 \times 90 \times 64$, this is manageable in modern GPUs, but higher resolutions (e.g., $160 \times 90 \times 128$) double the memory cost [S1, unofficial].
**Performance:** Real-time frame rates are achievable on modern hardware [S1, unofficial]. RDR2 uses $160 \times 88 \times 64$ for $\sim 160$m range [S1, unofficial]. Unity HDRP uses $240 \times 135 \times 64$ [S1, unofficial].
**Strengths:** Performance is decoupled from screen resolution; temporal accumulation reduces noise without requiring high sample counts per frame; reprojection handles camera movement efficiently [S1, unofficial].
**Limitations:** Ghosting artifacts if reprojection fails or history validation is insufficient; blurring from low-pass filters or temporal smoothing can reduce sharpness; fixed froxel resolution may lead to aliasing at extreme distances or angles if not managed [S1, unofficial].
**When to Use:** Real-time applications requiring volumetric fog/lighting with dynamic cameras and limited computational resources [S1, unofficial].
**When Not to Use:** Offline rendering requiring high fidelity without temporal artifacts; scenes with very large, static volumetric effects where pre-computation might be better [S1, unofficial].

## Background
The method originates from real-time froxel-based volumetric rendering techniques developed for modern video games [S1, unofficial]. Key implementations include Wronski's work (resolutions 160×90×64/128, range 50–128m) [S1, unofficial], Red Dead Redemption 2 (resolution 160×88×64, range $\sim 160$m) [S1, unofficial], and Unity's High Definition Render Pipeline (HDRP) (resolution 240×135×64) [S1, unofficial]. The approach leverages temporal anti-aliasing (TAA) principles, specifically exponential moving average blending and reprojection, to stabilize stochastic volumetric samples [S1, unofficial].
