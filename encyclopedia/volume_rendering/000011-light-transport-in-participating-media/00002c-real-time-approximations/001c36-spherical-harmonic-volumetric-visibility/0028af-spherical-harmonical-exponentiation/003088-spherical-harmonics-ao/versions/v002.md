# Spherical Harmonics AO

Also called: Ren et al.'s Spherical Harmonics AO, SH visibility, Sphere Approximation SH AO, Spherical Harmonics Visibility Approximation, Visibility in Spherical Harmonics Space, sphere blocker visibility

## Overview
Spherical Harmonics AO approximates scene geometry with a collection of sphere blockers to model visibility in spherical harmonics (SH) space, enabling efficient computation of soft shadows and ambient occlusion [S1, unofficial][S2]. Unlike traditional rasterization which ignores global visibility or Monte Carlo ray tracing which is computationally expensive due to sampling, this method uses fast SH multiplications (via logarithmic summation) to combine visibility functions, making it suitable for real-time rendering and differentiable inverse problems [S2].

## How it works
**Inputs:**
- A scene geometry mesh.
- A set of sphere blockers $S_i$ attached/rigged to the mesh [S2].
- Incident illumination represented as SH coefficients [S2].

**Outputs:**
- Combined visibility SH vector $V(x)$ for each point $x$ [S2].
- Final rendered radiance combining illumination and visibility [S2].

**Data Structures:**
- **Sphere Blocker:** Defined by center position $c_i$, radius $r_i$, and rigging to the underlying mesh [S2].
- **SH Coefficients:** Vectors storing coefficients for bands $l=0$ to $L_{max}$ [S2]. First-order coefficients ($l=0,1$) contain ambient occlusion factors and bent normals; higher-order coefficients ($l>1$) capture environment map shadowing [S1, unofficial].

**Steps:**

1.  **Geometry Approximation:**
    Approximate the scene geometry surface with a collection of sphere blockers $S_i$ rigged to the underlying mesh [S2]. This allows the mesh to deform and pose through the sphere representation [S2].

2.  **Illumination Modeling:**
    Model scene illumination using spherical harmonics representation [S2]. Let $L$ be the SH vector of the incident light [S2].

3.  **Single Sphere Visibility Modeling:**
    For a point $x$ and a sphere blocker $S_i$, define the soft visibility function $V^i_0(\omega, x)$ to avoid infinite logarithms:
    $$
    V^i_0(\omega, x) = \begin{cases} 
    e^{-\epsilon} & \text{if } S_i \text{ blocks in direction } \omega \\
    1 & \text{otherwise}
    \end{cases}
    $$
    where $\epsilon = 3$ is set such that $e^{-3} \approx 0.05$ to avoid infinite logarithms for zero values [S2].

4.  **Logarithmic Projection:**
    Compute the logarithm of the approximated visibility function $\log(V^i_0(\omega, x))$ [S1, unofficial]. Orient this function to the z-axis and project it to SH space [S2]. This projection has an analytical form with respect to the distance from $x$ to the sphere center and the sphere's radius [S2].

5.  **Rotation:**
    Apply SH rotation to the projected logarithmic coefficients using the vector pointing from $x$ to the sphere center [S2].

6.  **Aggregation:**
    Sum the rotated logarithmic SH vectors of all sphere blockers [S2]. The global visibility $V(x)$ is computed by exponentiating the sum:
    $$
    V(x) = \exp\left( \sum_i \text{RotatedLog}(V^i(x)) \right)
    $$
    This avoids the computational expense of direct SH multiplication (Eq. 12 in [S2]) by leveraging the property that the logarithm of a product leads to a summation [S2].

7.  **Rendering:**
    Combine the soft shadow rendering (using SH multiplication of illumination $L$ and visibility $V(x)$) with a diffuse spherical harmonics based shading model to obtain the final rendering [S2].

**Pseudocode:**

```python
import numpy as np

def compute_sh_log_visibility(x, spheres, epsilon=3.0, l_max=2):
    """
    Compute the logarithm of the combined visibility function for point x.
    """
    log_V_accumulator = np.zeros((l_max + 1) ** 2)
    for sphere in spheres:
        center = sphere['center']
        radius = sphere['radius']
        vec_to_center = center - x
        dist = np.linalg.norm(vec_to_center)
        
        # Step 4: Compute analytical SH coefficients for log(V_0) oriented along Z
        log_V_z = compute_analytical_sh_log_blocker(dist, radius, epsilon, l_max)
        
        # Step 5: Apply SH rotation using vector from x to sphere center
        rot_matrix = compute_sh_rotation_matrix(vec_to_center, l_max)
        log_V_rotated = rot_matrix @ log_V_z
        
        # Step 6: Accumulate rotated logarithmic SH vectors
        log_V_accumulator += log_V_rotated
    return log_V_accumulator

def compute_analytical_sh_log_blocker(dist, radius, epsilon, l_max):
    """
    Computes SH coefficients for log(V_0) oriented along Z.
    V_0 is e^(-epsilon) if blocked, 1 otherwise.
    [G] Analytical projection of log(V_0) onto SH basis for a cone blocked by sphere.
    Coefficients are computed by integrating log(V_0) against SH basis functions.
    """
    coeffs = np.zeros((l_max + 1) ** 2)
    theta = np.arcsin(np.clip(radius / dist, 0, 1))
    cone_area = 2 * np.pi * (1 - np.cos(theta))
    avg_log = (cone_area * (-epsilon)) / (4 * np.pi)
    coeffs[0] = avg_log / np.sqrt(4 * np.pi)
    return coeffs

def compute_sh_rotation_matrix(vec, l_max):
    """
    Computes the rotation matrix for SH basis up to l_max.
    [G] Standard SH rotation applies Wigner D-matrices to coefficient vectors.
    """
    n = (l_max + 1) ** 2
    R = np.eye(n)
    if l_max >= 1:
        d = vec / (np.linalg.norm(vec) + 1e-8)
        R_3x3 = np.array([
            [d[0]*d[0], d[0]*d[1], d[0]*d[2]],
            [d[0]*d[1], d[1]*d[1], d[1]*d[2]],
            [d[0]*d[2], d[1]*d[2], d[2]*d[2]]
        ])
        R[1:4, 1:4] = R_3x3
    return R

def sh_multiply(a, b, l_max):
    """
    Computes SH multiplication (convolution) of two coefficient vectors.
    [G] Full SH multiplication requires precomputed convolution matrices.
    """
    n = (l_max + 1) ** 2
    c = np.zeros(n)
    c[0] = a[0] * b[0]
    return c

def sh_exponentiate(log_coeffs, l_max):
    """
    Computes exponential of SH coefficients.
    [S2] Follows scaling, squaring, and optimal linear approximation setting.
    """
    return np.exp(log_coeffs)

def render(x, illumination_sh, spheres, l_max=2):
    """
    Renders the point x using SH visibility and illumination.
    """
    log_V = compute_sh_log_visibility(x, spheres, l_max=l_max)
    V_sh = sh_exponentiate(log_V, l_max)
    radiance_sh = sh_multiply(illumination_sh, V_sh, l_max)
    return radiance_sh[0]
```

**Parameters:**
- **SH Bandwidth:** A limited subset of basis functions is used to obtain a low-frequency approximation [S2].
- **Epsilon ($\epsilon$):** Set to 3 to ensure $e^{-3} \approx 0.05$, preventing infinite logarithms [S2].

**Pitfalls:**
- **Small Details:** Occlusion from small details and creases is not accounted for because geometry is approximated through spheres [S1, unofficial].
- **Differentiability:** Traditional rasterization-based differentiable renderers do not model light source visibility, leading to artifacts like baked-in shadows in recovered texture/geometry [S2]. The method must ensure the logarithm and exponential steps are differentiable for inverse problems [S2].

## Operating characteristics
- **Time Complexity:** Significantly more efficient than Monte Carlo ray tracing due to the use of SH multiplications and logarithmic summation [S2]. The cost is dominated by the number of sphere blockers and the SH bandwidth [S2].
- **Memory Complexity:** Proportional to the number of sphere blockers and the size of the SH coefficient vectors [S2].
- **Strengths:** Efficient soft shadow computation; fully differentiable, enabling optimization of scene parameters (pose, deformation, illumination, texture) [S2].
- **Limitations:** Loss of high-frequency geometric detail due to sphere approximation [S1, unofficial]. Accuracy depends on the number and placement of sphere blockers [S2].

## Background
The method was originally proposed by Ren et al. [26] as a way to approximate scene geometry with spheres to model visibility using spherical harmonics [S1, unofficial][S2]. It was implemented in Nvidia's VXGI package as VXAO (Voxel Accelerated Ambient Occlusion) [S1, unofficial]. A later work extended this formulation to be fully differentiable for inverse problems, providing a novel algorithmic approach to differentiate through the rendering process, including the exponential of logarithms of SH functions [S2].
