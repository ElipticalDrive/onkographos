# Precomputed Lighting (Baking)

Also called: Baking Lighting, Baking the lighting, Direct Lighting Caching, Precomputed Light Transmissivity

## Overview
Precomputed Lighting (Baking) accelerates volume rendering by pre-computing the incident radiance term ($L_i$) for each voxel in a grid and storing it, thereby skipping $L_i$ evaluation during the per-pixel raymarching pass [S1, S2, S3, unofficial]. It solves the performance bottleneck of evaluating volumetric shadows or direct illumination for every sample point by trading offline computation and memory for runtime speed [S1, S2, S3, unofficial]. Unlike [Modular Transfer](1249-modular-transfer.md), which decomposes transfer functions for flexible runtime lighting, this method is static and view-independent, requiring a full re-bake whenever the scene geometry, lighting, or density simulation changes [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D voxel grid representing the volume density/opacity, and a static lighting configuration (light positions, intensities, colors) and scene geometry [S1, S3, unofficial].
*   **Output:** A 3D texture or data structure where each voxel stores the pre-computed incident radiance ($L_i$) or light transmissivity [S1, S2, unofficial].

**Data Structures:**
The lighting data is stored in a 3D texture or voxel grid. To optimize cache performance during the baking pass, the data should be iterated and stored in memory order (e.g., x-fastest, z-slowest) to avoid cache misses [S1, unofficial]. The resolution of this cache can be lower than the actual simulation voxel resolution because light attenuation and illumination are inherently smooth and blurry [S3, unofficial].

**Steps:**
1.  **Baking Pass (Pre-computation):** Iterate through every voxel in the grid. For each voxel center, calculate the incident radiance ($L_i$) from all light sources. This typically involves casting rays from the voxel center to each light source to determine visibility and accumulating direct illumination [S1, S2, S3, unofficial].
2.  **Storage:** Store the calculated $L_i$ value in the corresponding voxel of the precomputed lighting grid [S1, S2, unofficial].
3.  **Rendering Pass:** During real-time volume rendering, when a raymarching step reaches a sample point, retrieve the pre-computed $L_i$ value by trilinearly interpolating the values from the surrounding voxels in the precomputed grid [S2, S3, unofficial].
4.  **Hybrid Sampling:** In some implementations, a few real light samples are taken before sampling the cached value to handle sharp transitions [S3, unofficial].

**Formulas:**
Not given in the sources for the exact precomputation formula. At render time, the incident radiance is approximated via trilinear interpolation:
$$ L_i(\mathbf{p}) \approx \text{TrilinearInterpolate}(\text{BakedGrid}, \mathbf{p}) $$
Where $\mathbf{p}$ is the current sample position on the camera ray [S2, unofficial].

**Parameters:**
*   **Cache Resolution:** The resolution of the precomputed lighting grid. It can be lower than the density grid resolution because light is blurry [S3, unofficial]. Not given in the sources for exact ratios.
*   **Light Samples:** In some hybrid approaches, a few real light samples are taken before sampling the cache, but the core method relies on full precomputation [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Dynamic Scenes:** The technique requires re-baking whenever the lighting configuration or the density simulation changes [S1, unofficial].
*   **Historical Context:** The technique is primarily mentioned for reference and historical reasons rather than current practical utility [S1, unofficial].

**Pseudocode:**
```python
def bake_lighting(volume_grid, lights, resolution):
    """
    Pre-computes incident radiance for each voxel.
    volume_grid: 3D array of density values indexed [z][y][x].
    lights: List of dicts with 'position' (vec3), 'color' (vec3), 'intensity' (float).
    resolution: Tuple (res_x, res_y, res_z).
    Returns: 3D array of precomputed radiance values indexed [z][y][x].
    """
    res_x, res_y, res_z = resolution
    baked_lighting = [[[0.0, 0.0, 0.0] for _ in range(res_x)] for _ in range(res_y)]
    for z in range(res_z):
        baked_lighting[z] = [[[0.0, 0.0, 0.0] for _ in range(res_x)] for _ in range(res_y)]

    # Iterate x-fastest, z-slowest for cache performance [S1, unofficial]
    for z in range(res_z):
        for y in range(res_y):
            for x in range(res_x):
                # Voxel center in normalized coordinates [0, 1]
                voxel_center = [(x + 0.5) / res_x, (y + 0.5) / res_y, (z + 0.5) / res_z]
                total_radiance = [0.0, 0.0, 0.0]

                for light in lights:
                    # Compute transmissivity by raymarching from voxel to light
                    transmissivity = 1.0
                    ray_pos = list(voxel_center)
                    ray_dir = [light['position'][i] - ray_pos[i] for i in range(3)]
                    ray_len = (ray_dir[0]**2 + ray_dir[1]**2 + ray_dir[2]**2)**0.5
                    ray_dir = [d / ray_len for d in ray_dir]

                    # Standard ray march to light [G]
                    steps = 10
                    for _ in range(steps):
                        ix, iy, iz = int(ray_pos[0] * res_x), int(ray_pos[1] * res_y), int(ray_pos[2] * res_z)
                        ix, iy, iz = max(0, min(ix, res_x-1)), max(0, min(iy, res_y-1)), max(0, min(iz, res_z-1))
                        density = volume_grid[iz][iy][ix]
                        transmissivity *= max(0.0, 1.0 - density * 0.1)
                        ray_pos = [ray_pos[i] + ray_dir[i] * 0.1 for i in range(3)]

                    # Accumulate direct lighting
                    contribution = [light['color'][c] * light['intensity'] * transmissivity for c in range(3)]
                    total_radiance = [total_radiance[c] + contribution[c] for c in range(3)]

                baked_lighting[z][y][x] = total_radiance
    return baked_lighting

def render_with_baked_lighting(camera_origin, camera_direction, volume_grid, baked_lighting, resolution, step_size=0.01):
    """
    Renders volume using precomputed lighting.
    """
    accumulated_color = [0.0, 0.0, 0.0]
    accumulated_alpha = 0.0
    t = 0.0

    while t < 1.0 and accumulated_alpha < 1.0:
        sample_pos = [camera_origin[i] + camera_direction[i] * t for i in range(3)]
        x, y, z = int(sample_pos[0] * resolution[0]), int(sample_pos[1] * resolution[1]), int(sample_pos[2] * resolution[2])
        x, y, z = max(0, min(x, resolution[0]-1)), max(0, min(y, resolution[1]-1)), max(0, min(z, resolution[2]-1))
        density = volume_grid[z][y][x]

        if density > 0:
            # Retrieve precomputed lighting via trilinear interpolation [S2, S3, unofficial]
            li = trilinear_interpolate(baked_lighting, sample_pos, resolution)

            # Standard volume rendering integration (front-to-back) [G]
            scattering = [density * li[c] for c in range(3)]
            alpha = 1.0 - 2.71828**(-density * step_size)
            weight = alpha * (1.0 - accumulated_alpha)
            accumulated_color = [accumulated_color[c] + scattering[c] * weight for c in range(3)]
            accumulated_alpha += weight

        t += step_size

    return accumulated_color

def trilinear_interpolate(grid, point, resolution):
    """Standard 3D trilinear interpolation [G]."""
    res_x, res_y, res_z = resolution
    fx = point[0] * res_x
    fy = point[1] * res_y
    fz = point[2] * res_z
    ix, iy, iz = int(fx), int(fy), int(fz)
    dx, dy, dz = fx - ix, fy - iy, fz - iz

    def get_val(x, y, z):
        x = max(0, min(x, res_x - 1))
        y = max(0, min(y, res_y - 1))
        z = max(0, min(z, res_z - 1))
        return grid[z][y][x]

    result = [0.0, 0.0, 0.0]
    for c in range(3):
        v000 = get_val(ix, iy, iz)[c]
        v100 = get_val(ix+1, iy, iz)[c]
        v010 = get_val(ix, iy+1, iz)[c]
        v110 = get_val(ix+1, iy+1, iz)[c]
        v001 = get_val(ix, iy, iz+1)[c]
        v101 = get_val(ix+1, iy, iz+1)[c]
        v011 = get_val(ix, iy+1, iz+1)[c]
        v111 = get_val(ix+1, iy+1, iz+1)[c]

        v00 = v000 * (1-dx) + v100 * dx
        v01 = v010 * (1-dx) + v110 * dx
        v10 = v001 * (1-dx) + v101 * dx
        v11 = v011 * (1-dx) + v111 * dx

        v0 = v00 * (1-dy) + v01 * dy
        v1 = v10 * (1-dy) + v11 * dy
        result[c] = v0 * (1-dz) + v1 * dz
    return result
```

## Operating characteristics
*   **Time Complexity:** Baking is $O(V \cdot L \cdot S)$, where $V$ is the number of voxels, $L$ is the number of lights, and $S$ is the number of samples per light ray for visibility [S1, S2, unofficial]. Rendering is $O(R \cdot S)$, where $R$ is the number of rays and $S$ is samples per ray, but with a significantly smaller constant factor because $L_i$ evaluation is replaced by a texture lookup [S1, S3, unofficial].
*   **Memory Complexity:** $O(V)$, where $V$ is the number of voxels, storing additional radiance values per voxel [S1, unofficial].
*   **Performance:** Significantly speeds up rendering by skipping $L_i$ evaluation at each raymarching step [S1, S3, unofficial]. The initial baking pass takes time [S1, unofficial].
*   **Strengths:** Fast runtime rendering; view-independent [S2, unofficial].
*   **Limitations:** Requires re-baking whenever the lighting configuration or the density simulation changes [S1, unofficial].
*   **When to use:** Not given in the sources.
*   **When not to use:** Not given in the sources.

## Background
Precomputed Lighting (Baking) is a historical technique mentioned for reference and educational purposes in modern volume rendering contexts [S1, unofficial]. It is based on the principle of precalculating illumination for each voxel center to allow trilinear interpolation at render time [S2, unofficial]. The method is view-independent but scene and light source dependent [S2, unofficial]. While shadow maps and deep shadow maps are related concepts, baking lighting directly into the voxel grid is a distinct approach for volumetric data [S1, unofficial].
