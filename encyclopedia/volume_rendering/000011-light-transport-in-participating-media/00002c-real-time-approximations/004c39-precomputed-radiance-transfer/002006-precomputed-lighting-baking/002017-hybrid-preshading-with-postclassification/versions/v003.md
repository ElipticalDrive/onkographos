# Hybrid Preshading with Postclassification

Also called: Hybrid Classification and Shading

## Overview
Hybrid Preshading with Postclassification is a real-time volume rendering optimization that decouples the classification and shading stages to balance visual fidelity and performance [S1]. It solves the trade-off between the speed of preclassification/preshading and the visual quality of postclassification/postshading by performing classification after interpolation (postclassification) but shading before interpolation (preshading) [S1]. Unlike pure preclassification methods that require opacity-weighted color interpolation to avoid artifacts, or pure postclassification methods that are computationally expensive, this hybrid approach avoids visible artifacts while maintaining high rendering speeds [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset, a set of quantized space directions, and a lighting model.
*   **Output:** A rendered image with volume data classified and shaded.

**Data Structures:**
1.  **Volume Grid:** Standard 3D voxel grid storing scalar density values.
2.  **Gradient Map:** A 3D grid storing precomputed volume gradients for each voxel.
3.  **Direction Index Map:** A 3D grid storing an integer index associated with every voxel, representing the closest quantized space direction to the precomputed gradient at that location [S1].
4.  **Preshaded Reflectance Map:** A lookup table (or texture) indexed by the quantized space directions. Each entry stores the precomputed shading result (color and opacity contribution) for that specific direction [S1].

**Parameters:**
*   **Number of quantized space directions:** 8192 [S1].
*   **Sampling rate ($\Delta s$):** Typically initialized to 0.5, allowing between two and four samplings along a ray within a cell [S1].

**Steps:**
1.  **Precompute Gradients:** Calculate the volume gradient for every voxel in the dataset [S1].
2.  **Quantize Directions:** Define a fixed set of 8192 quantized space directions [S1].
3.  **Build Direction Index Map:** For each voxel, determine which of the 8192 quantized directions is closest to the precomputed gradient vector. Store this index in the Direction Index Map [S1].
4.  **Generate Preshaded Reflectance Map:**
    *   For each of the 8192 quantized directions:
        *   Apply the shading model (lighting calculation) to this direction [S1].
        *   Store the resulting reflectance (color/opacity) in the Preshaded Reflectance Map at the corresponding index [S1].
5.  **Rendering (Ray Marching):**
    *   For each pixel, cast a ray through the volume.
    *   Sample the volume along the ray.
    *   **Interpolation:** Perform trilinear interpolation of the volume data (density, gradient direction index) at the sampling location using the 8 surrounding vertices [S1].
    *   **Classification:** Use the interpolated density value to determine the material properties (e.g., opacity, color) via the transfer function. This is the "postclassification" step, as it happens after interpolation [S1].
    *   **Shading:** Retrieve the interpolated gradient direction index from the 8 vertices. Use this index to look up the pre-shaded color from the Preshaded Reflectance Map. This is the "preshading" step, as the shading is applied to the vertices/interpolated data before the final color accumulation [S1].
    *   **Accumulation:** Composite the classified and shaded values along the ray.

**Pseudocode:**

```python
# Preprocessing Phase
def preprocess_volume(volume_data, num_directions=8192):
    # 1. Precompute gradients for all voxels
    gradients = compute_gradients(volume_data)
    
    # 2. Define quantized space directions (e.g., uniform distribution on sphere)
    directions = get_quantized_directions(num_directions)
    
    # 3. Build Direction Index Map: map each voxel to the closest direction index
    direction_index_map = zeros_like(volume_data, dtype=int)
    for each voxel v in volume_data:
        grad = gradients[v]
        # Find index of direction in 'directions' closest to grad
        idx = argmin([dot(grad, d) for d in directions])
        direction_index_map[v] = idx
        
    # 4. Generate Preshaded Reflectance Map
    # Map from direction_index -> precomputed_shading_result
    preshaded_reflectance_map = {}
    for i, direction in enumerate(directions):
        # Apply shading model for this specific direction
        shading_result = apply_shading_model(direction)
        preshaded_reflectance_map[i] = shading_result
        
    return direction_index_map, preshaded_reflectance_map

# Rendering Phase
def render_ray(ray_origin, ray_direction, volume_data, direction_index_map, preshaded_reflectance_map, delta_s=0.5):
    accumulated_color = (0, 0, 0, 0)
    accumulated_opacity = 0
    t = 0.0
    
    while t < ray_length:
        # Sample position
        pos = ray_origin + ray_direction * t
        
        # Get 8 surrounding voxel indices for trilinear interpolation
        voxel_indices = get_surrounding_voxels(pos)
        
        # Interpolate density and direction index from 8 vertices
        density = trilinear_interpolate(volume_data, voxel_indices, pos)
        dir_idx = trilinear_interpolate(direction_index_map, voxel_indices, pos)
        
        # Postclassification: Determine material properties from density
        opacity, base_color = classify(density)
        
        # Preshading: Look up precomputed shading based on interpolated direction index
        # Note: dir_idx might be fractional if interpolated, so round or use nearest
        nearest_idx = round(dir_idx)
        pre_shaded_color = preshaded_reflectance_map[nearest_idx]
        
        # Combine base color with pre-shaded result (implementation detail)
        final_color = combine(base_color, pre_shaded_color)
        
        # Accumulate
        accumulated_color, accumulated_opacity = composite(
            accumulated_color, accumulated_opacity,
            final_color, opacity
        )
        
        t += delta_s
        
    return accumulated_color
```

**Edge Cases and Pitfalls:**
*   **Artifacts:** Mueller et al. reported bad artifacts with preshading and postclassification [S1]. However, this implementation shows no visible artifacts, suggesting that the specific combination of 8192 directions and the interpolation method avoids the issues identified in other works [S1].
*   **Precision:** Color and opacity are computed on 16-bit unsigned integers, which may introduce minor quantization errors [S1].
*   **Hardware Limitations:** Code running on MMX-only processors may not support line equation tests, leading to minor artifacts on the image [S1].

## Operating characteristics
*   **Time Complexity:** The preprocessing step is $O(V \cdot D)$ where $V$ is the number of voxels and $D$ is the number of quantized directions (8192). The rendering step is $O(R \cdot S)$ where $R$ is the number of rays and $S$ is the number of samples per ray. The shading lookup is $O(1)$ per sample.
*   **Memory Complexity:** Requires storing the volume data, gradient map, direction index map, and the preshaded reflectance map (size proportional to 8192 directions) [S1].
*   **Performance:** Benchmarks were performed on platforms using MMX, SSE, or 3DNow! SIMD extensions [S1]. The method allows for high-quality rendering on $512^2$ pixel images with up to 4x zoom without visible noise [S1].
*   **Strengths:** Avoids artifacts associated with pure preclassification/preshading (which requires opacity-weighted interpolation) and pure postclassification (which is slow) [S1].
*   **Limitations:** Requires significant preprocessing time to build the reflectance map. The quality depends on the number of quantized directions (8192 used in the source) [S1].

## Background
This technique is described in "A new object-order ray-casting algorithm" [S1]. It was developed to address the limitations of existing volume rendering methods that either prioritized speed (preclassification/preshading) or visual quality (postclassification/postshading) [S1]. The authors argue against the interpretation by Mueller et al. [24] that preshading and postclassification inherently cause bad artifacts, demonstrating that their implementation avoids these issues [S1].
