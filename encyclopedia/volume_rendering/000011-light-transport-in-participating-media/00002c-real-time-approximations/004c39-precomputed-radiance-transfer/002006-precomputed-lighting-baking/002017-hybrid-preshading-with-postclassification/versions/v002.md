# Hybrid Preshading with Postclassification

Also called: Hybrid Classification and Shading

## Overview
Hybrid Preshading with Postclassification is a real-time volume rendering optimization that decouples classification from shading to balance visual fidelity and performance [S1]. Unlike pure preclassification/preshading which risks artifacts without opacity-weighted interpolation, or pure postclassification/postshading which is computationally expensive, this method performs classification after interpolation (postclassification) but shading before interpolation (preshading) [S1]. It builds on [Precomputed Lighting (Baking)](2169-precomputed-lighting-baking.md) by precomputing lighting contributions for a discrete set of quantized space directions, applying shading to the 8 vertices of each cell before color interpolation at the sampling location [S1].

## How it works
**Inputs:**
- Volume dataset (scalar field) [S1].
- Transfer function mapping scalar values to color and opacity [S1].
- Lighting model with light positions and material properties [S1].
- Number of quantized space directions ($N_{dir}$), typically 8192 [S1].

**Outputs:**
- Rendered image with shaded volume data [S1].

**Data Structures:**
1. **Volume Grid:** Standard 3D array of scalar values [S1].
2. **Gradient Grid:** 3D array of 3D vectors ($\nabla V$), precomputed from the volume grid [S1].
3. **Preshaded Reflectance Map (PRM):** Lookup table indexed by quantized direction index and scalar value, storing the precomputed color contribution for that direction and value [S1].
4. **Direction Index Grid:** 3D array storing an integer index ($0 \dots N_{dir}-1$) for each voxel, corresponding to the quantized space direction of the precomputed gradient at that location [S1].

**Steps:**
1. **Precompute Gradients:** Calculate the volume gradient $\nabla V$ for every voxel in the volume grid [S1].
2. **Quantize Directions:** Define a set of $N_{dir}$ unit vectors representing space directions [S1]. Map each precomputed gradient vector to the nearest index in this set and store the index in the Direction Index Grid for each voxel [S1].
3. **Generate Preshaded Reflectance Map:** Apply shading to every quantized direction before rendering to generate the preshaded reflectance map [S1].
4. **Raymarching with Hybrid Shading:** For each pixel, cast a ray through the volume [S1]. For each cell crossed by the ray:
   a. **Shade Vertices:** For each of the 8 vertices of the cell, use its precomputed direction index to look up the precomputed shading color from the PRM [S1].
   b. **Interpolate:** Trilinearly interpolate the scalar values and the shaded vertex colors from the 8 vertices to the sampling location [S1].
   c. **Classify:** Apply the transfer function to the interpolated scalar value to determine opacity and base color (postclassification) [S1].
   d. **Composite:** Accumulate the sample color and opacity using front-to-back compositing [S1].

**Formulas:**
- Gradient: $\nabla V = \left[ \frac{\partial V}{\partial x}, \frac{\partial V}{\partial y}, \frac{\partial V}{\partial z} \right]$ [S1].
- Direction Index: $idx = \arg \min_{j} \| \frac{\nabla V}{\|\nabla V\|} - \vec{d}_j \|$ where $\vec{d}_j$ is the $j$-th quantized direction [S1].
- Shading Lookup: $C_{shade} = \text{PRM}[idx, v]$ [S1].

**Parameters:**
- $N_{dir} = 8192$ [S1].
- Sampling rate $\Delta s = 0.5$ (distance between consecutive interpolations), allowing between two and four samplings along a ray within a cell [S1].
- Image resolution: $512 \times 512$ pixels [S1].
- Pixel subdivisions and precomputed rays: $16 \times 16$ [S1].
- Color and opacity are computed on 16-bit unsigned integers [S1].

**Edge Cases and Pitfalls:**
- **Gradient Zero:** If $\nabla V = 0$, the direction index is undefined [G]. Assign a default direction (e.g., $(0,0,1)$) or handle as a special case in the quantization step.
- **Quantization Artifacts:** Discrete directions may cause directional aliasing [S1]. The large number of directions (8192) mitigates this [S1].
- **Artifact Claim:** Contrary to Mueller et al. [24] who reported bad artifacts with preshading and postclassification, this implementation shows no visible artifacts [S1].

## Subtopics

### [Fast Two-Pass Shading](2311-fast-two-pass-shading.md)
Decouples classification and illumination from geometric filtering via a P-buffer, improving performance by 5%–10%. Choose when maximizing throughput on typical hardware is prioritized over per-fragment shading accuracy.

### [Congradient Shading](2341-congradient-shading.md)
Integrates shading directly into the projection pipeline using local gradients, combining geometric accuracy with contextual robustness. Choose when surface orientation accuracy is critical and post-processing stages are undesirable.

### [Fake Phong Illumination via Normal Quantization](5846-fake-phong-illumination-via-normal-quantization.md)
Replaces per-voxel Phong calculations with a pre-computed color lookup table indexed by quantized normals. Choose when interactive speed is required and directional aliasing artifacts are acceptable.

## Operating characteristics
- **Time Complexity:** Precomputation scales with the number of voxels and quantized directions [S1]. Rendering scales with pixel count and ray steps, using constant-time shading lookup [S1].
- **Memory Complexity:** Requires storage for the Volume Grid, Gradient Grid, Direction Index Grid, and PRM [S1].
- **Performance:** High efficiency for interactive rendering, with SIMD optimizations (MMX, SSE, 3DNow!) used for memory copying and trilinear interpolation [S1].
- **Strengths:** Avoids artifacts associated with pure preclassification/preshading (without opacity-weighted interpolation) and is faster than pure postclassification/postshading [S1].
- **Limitations:** Requires precomputation of gradients and PRM [S1]. Directional aliasing is possible if $N_{dir}$ is too small [S1].

## Background
This method is described in "A new object-order ray-casting algorithm" [S1]. It addresses the trade-off between the speed of preclassification/preshading and the visual quality of postclassification/postshading [S1]. The authors argue against the artifact claims of Mueller et al. [24] for this specific implementation [S1].
