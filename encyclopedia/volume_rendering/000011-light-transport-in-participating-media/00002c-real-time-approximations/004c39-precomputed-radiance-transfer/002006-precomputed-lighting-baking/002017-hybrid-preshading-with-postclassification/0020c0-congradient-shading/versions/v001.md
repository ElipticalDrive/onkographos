# Congradient Shading

Also called: Gradient-based Table-driven Shading

## Overview
Congradient shading is a real-time volume rendering technique that defines the surface orientation of a voxel using a finite set of local gradients, enabling a fast, table-driven shading mechanism [S1, book]. It distinguishes itself by integrating shading directly into the projection pipeline as an integral part of the rendering process, rather than performing it in a separate post-processing stage [S1, book]. This approach combines the geometric accuracy of gradient shading with the contextual robustness of contextual shading [S1, book].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset (voxel grid), light source parameters (position, intensity), and a finite set of predefined local gradient directions.
*   **Output:** A shaded 2D image (frame buffer).

**Data Structures:**
*   **Congradient Value:** A data structure holding concatenated values of the voxel's color and its local gradient index. The exact bit-packing is not specified, but it serves as a composite index [S1, book].
*   **Look-Up Table (LUT):** A 2D array mapping congradient values to shaded colors based on light source parameters [S1, book].

**Steps:**
1.  **Projection and Congradient Generation:** For each pixel in the projection plane, a ray is cast through the volume. The system identifies the first opaque voxel along the ray (or the relevant voxel for shading) [S1, book].
2.  **Gradient Computation:** The local gradient for the selected voxel is computed. Two implementations are described:
    *   **Unidirectional Shading:** The gradient is computed using only the depth values of horizontal neighbors [S1, book].
    *   **Bidirectional Shading:** The gradient is computed using both horizontal and vertical neighbors [S1, book].
3.  **Congradient Formation:** The color of the voxel and the computed local gradient index are concatenated to form a single congradient value [S1, book].
4.  **Pipelining:** The production of the congradient value for one pixel is interleaved with the projection time of the next pixel [S1, book].
5.  **Shading via LUT:** The congradient value is used as an index into a look-up table [S1, book].
6.  **Color Retrieval:** The LUT translates the congradient value into a final shaded color based on the current light source parameters [S1, book].

## Subtopics

### Unidirectional Shading
Computes gradients using only horizontal neighbors. Simpler hardware implementation, suitable for basic shading needs. [Link](2171-hybrid-preshading-with-postclassification.md)

### Bidirectional Shading
Computes gradients using both horizontal and vertical neighbors. Slightly more complex but potentially more accurate surface orientation estimation. [Link](2171-hybrid-preshading-with-postclassification.md)

## Operating characteristics
*   **Time Complexity:** The total time for an arbitrary projection is $O(n^2 \log n)$, where $n$ is the resolution dimension, allowing real-time arbitrary projection [S1, book]. The shading itself adds no additional time because the congradient calculation time for each pixel is much less than its projection time [S1, book].
*   **Memory Complexity:** Uses a single 2D array (e.g., a frame buffer) for the projection stage [S1, book]. The LUT size depends on the number of unique colors and gradient directions.
*   **Performance:** Faster than alternative techniques that use separate post-processors [S1, book].
*   **Strengths:** Real-time performance, hardware-friendly, supports dynamic light sources for motion parallax [S1, book].
*   **Limitations:** Quality depends on the finite set of gradients; may lack smooth shading compared to continuous gradient methods [S1, book].

## Background
Congradient shading was developed for the Cube architecture, emphasizing real-time performance [S1, book]. It capitalizes on the advantages of both gradient shading and contextual shading [S1, book]. The technique was implemented and tested on various workstations including Sun-S, Sun-4, Silicon Graphics IRIS, and HP Turbo SRX, using resolutions such as $128^3$, $256^3$, and $512^3$ [S1, book].
