# Piecewise Integration

Also called: Piecewise Light Propagation, Segmented Light Transport

## Overview
Piecewise Integration is a precomputation technique for real-time volume rendering that approximates global light transport by dividing light paths into discrete segments [S1]. It solves the problem of expensive volumetric illumination by storing transmittance data in a multiresolution 3D texture, allowing incoming radiance to be computed via a single texture lookup per sample [S1]. It is distinguished from full path-tracing methods by its reliance on precomputed segment data and from simple direct illumination by its inclusion of first-order inscattering approximations [S1].

## How it works
**Inputs:**
*   Volumetric dataset [S1].
*   Light source definition (position, radiance $L_0$, type: directional or point) [S1].
*   Transfer function [S1].
*   Number of segments $k$ [S1].

**Outputs:**
*   Final radiance 3D texture [S1].

**Data Structures:**
1.  **Piecewise Segment Texture:** An intermediate 3D texture storing transmittance values between segment endpoints [S1]. It uses a multiresolution structure and a lower-resolution grid to reduce memory usage [S1].
2.  **Final Radiance Texture:** A 3D texture accumulating the progressive refinement results [S1].
3.  **Auxiliary Textures:** Three additional 3D textures are required for intermediate computations [S1].

**Steps:**
1.  **Segmentation:** For each voxel in the volume, cast short rays towards the light source to determine piecewise segments [S1].
2.  **Precomputation:** Store the transmittance $T(\tilde{x}_n, \tilde{x}_{n+1})$ for each segment endpoint pair into the Piecewise Segment Texture [S1].
3.  **Radiance Evaluation:** For each voxel, send global rays towards the light source taking steps equal to the short ray size, sampling from the Piecewise Segment Texture [S1].
4.  **Inscattering Approximation:** Approximate first-order inscattering by treating scattering in the vicinity of the sample point as emission [S1].
5.  **Progressive Refinement:** To maintain interactivity, refine the final radiance by sending one ray at a time and blending the result into the Final Radiance Texture [S1].

**Formula:**
The incoming radiance $L_i$ at a position $\tilde{x}$ from direction $\tilde{\omega}_i$ is computed as [S1]:

$$L_i(\tilde{x}, \tilde{\omega}_i) = L_0 \cdot \prod_{n=0}^{k} T(\tilde{x}_n, \tilde{x}_{n+1})$$

Where:
*   $L_0$ is the source radiance [S1].
*   $k$ is the number of segments [S1].
*   $T(\tilde{x}_n, \tilde{x}_{n+1})$ is the transmittance between segment endpoints $\tilde{x}_n$ and $\tilde{x}_{n+1}$ [S1].
*   $\tilde{x}_n$ and $\tilde{x}_{n+1}$ are the endpoints of the $n$-th segment [S1].

**Parameters:**
*   $k$: The number of segments into which rays are divided [S1]. Value not given in the sources.

**Pitfalls:**
*   **Recomputation:** If the light source position, type, or the transfer function changes, the radiance must be fully recomputed [S1].
*   **Memory:** Requires sufficient graphics memory for three additional 3D textures, though mitigated by multiresolution structures [S1].
*   **Light Source Limitation:** Supports only a single directional or point light source [S1].

**Pseudocode:**
```python
import math

def normalize(v):
    mag = math.sqrt(sum(c*c for c in v))
    return tuple(c/mag for c in v)

def is_inside(pos, dims):
    return 0 <= pos[0] < dims[0] and 0 <= pos[1] < dims[1] and 0 <= pos[2] < dims[2]

def piecewise_integration(volume_dims, light_pos, L0, k, step_size, transfer_function):
    """
    Computes volumetric illumination using piecewise integration.
    
    Args:
        volume_dims: Tuple (Dx, Dy, Dz) of grid dimensions.
        light_pos: Tuple (x, y, z) of light source position.
        L0: Source radiance scalar.
        k: Number of segments.
        step_size: Fixed step length for short and global rays [G].
        transfer_function: Callable mapping volume scalar to optical density.
        
    Returns:
        final_radiance_texture: Dict mapping (x,y,z) to radiance value.
    """
    # 1. Precompute piecewise segments
    piecewise_segment_texture = {}
    
    for x in range(volume_dims[0]):
        for y in range(volume_dims[1]):
            for z in range(volume_dims[2]):
                voxel_pos = (x, y, z)
                direction = normalize(tuple(light_pos[i] - voxel_pos[i] for i in range(3)))
                current_pos = voxel_pos
                accumulated_T = 1.0
                
                for n in range(k + 1):
                    density = transfer_function(volume_dims, current_pos)
                    segment_T = math.exp(-density * step_size)
                    accumulated_T *= segment_T
                    piecewise_segment_texture[current_pos] = accumulated_T
                    
                    current_pos = tuple(current_pos[i] + direction[i] * step_size for i in range(3))
                    if not is_inside(current_pos, volume_dims):
                        break
                        
    # 2. Progressive refinement
    final_radiance_texture = {}
    
    for x in range(volume_dims[0]):
        for y in range(volume_dims[1]):
            for z in range(volume_dims[2]):
                voxel_pos = (x, y, z)
                direction = normalize(tuple(light_pos[i] - voxel_pos[i] for i in range(3)))
                current_pos = voxel_pos
                incoming_radiance = 0.0
                accumulated_transmittance = 1.0
                
                while is_inside(current_pos, volume_dims):
                    segment_T = piecewise_segment_texture.get(current_pos, 1.0)
                    accumulated_transmittance *= segment_T
                    
                    density = transfer_function(volume_dims, current_pos)
                    emitted_radiance = density * L0
                    incoming_radiance += emitted_radiance * accumulated_transmittance
                    
                    current_pos = tuple(current_pos[i] + direction[i] * step_size for i in range(3))
                    
                final_radiance_texture[voxel_pos] = incoming_radiance
                
    return final_radiance_texture
```

## Operating characteristics
*   **Time Complexity:** Low rendering times due to the single extra lookup required to compute incoming radiance at the sample position [S1].
*   **Memory Complexity:** Requires three additional 3D textures for computations [S1]. Memory requirements are alleviated by using a multiresolution structure and a lower-resolution grid [S1].
*   **Performance:** Supports interactive frame rates, provided sufficient graphics memory is available [S1].
*   **Strengths:** Enables interactive progressive refinement; supports dynamic movement of a single light source [S1].
*   **Limitations:** Radiance must be recomputed if the light source or transfer function changes, which can be costly but is performed interactively and progressively [S1]. Limited to single directional or point light sources [S1].

## Background
Piecewise Integration was introduced by Habel et al. in 2008 [S1]. It was developed for volume ray-casting but can be combined with other rendering paradigms [S1]. The technique is part of the broader effort to achieve interactive volume rendering with volumetric illumination, building on concepts like Summed Area Tables which were exploited by Diaz et al. for illumination effects [S1].
