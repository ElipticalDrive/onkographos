# Multiple Scattering Approximation via Light Volume Lookup


## Overview
This method approximates multiple scattering in participating media by precomputing light attenuation into a volumetric data structure (the "light volume") and treating the multiple scattering contribution as a lookup operation based on accumulated optical thickness and a derived blurring width [S1]. It solves the problem of expensive numerical integration of the radiative transfer equation for multiple scattering orders by replacing it with a spatially varying blur lookup, allowing for near-real-time rendering of complex volumetric effects like smoke and clouds [S1].

## How it works
**Inputs:**
- Density volume grid $\rho(x)$ storing medium density at voxel centers [S1].
- Optical properties: Absorption cross-section $C_{abs}$ and Scattering cross-section $C_{sca}$ [S1].
- Light source positions and intensities [S1].
- Camera ray parameters (origin, direction) [G].

**Outputs:**
- Final radiance $L_{total}$ for each pixel [G].

**Data Structures:**
1. **Density Volume:** A 3D grid of size $N^3$ (e.g., $128^3$) storing $\rho(x)$ [S1].
2. **Light Volume Pyramid:** A mip-map structure storing precomputed attenuated radiance at different blur levels [S1].
3. **Optical Thickness Squared Volume:** An auxiliary volume storing $\tau^2$ for the light path, used to handle inhomogeneous media without runtime integration [S1].

**Formulas:**
- Scattering coefficient: $a(x) = C_{abs} \cdot \rho(x)$ [S1].
- Scattering coefficient: $b(x) = C_{sca} \cdot \rho(x)$ [S1].
- Optical thickness (light path): $\tau = \int_{0}^{s_0} b(x_{start} + s \cdot \hat{\omega}) ds$ [S1].
- Blurring width $w$: Derived from path integral analysis, approximating the spatial spread of the light beam. It is a function of optical thickness and scattering properties [S1].
- Multiple scattering phase function: $P_{MS}(\theta, \tau)$ [S1].
- Path curvature: $C = \alpha \cdot \theta^2 / \tau$ [S1].
- Weight for multiple scattering contribution: $weight = \exp(-(c/b)\tau) \cdot \exp(-C) \cdot P_{MS}(\theta, \tau)$ [S1]. (Note: $c$ is not defined in the sources; implementation typically omits this term or sets $c=0$ [G].)

**Parameters:**
- $w$: Blurring level, used as an index or parameter for the light volume lookup [S1].
- $C_{abs}$: Absorption cross-section [S1].
- $C_{sca}$: Scattering cross-section [S1].
- $\rho(x)$: Density of the medium at point $x$ [S1].
- $\alpha$: Constant for path curvature calculation [G].

**Steps:**

1. **Preprocessing (Light Volume Construction):**
   1. For each light source, compute the optical thickness $\tau$ from the light to every voxel in the density volume [S1].
   2. For inhomogeneous media, compute and store $\tau^2$ in the auxiliary volume to avoid expensive runtime integration [S1].
   3. Propagate light through the medium, applying attenuation based on $a(x)$ and $b(x)$ [S1].
   4. Apply spatial blurring to the propagated light using the derived blurring width $w$ to simulate multiple scattering spread [S1].
   5. Store the attenuated and blurred radiance in the Light Volume Pyramid at appropriate mip-map levels corresponding to different blur widths [S1].

2. **Rendering (Ray Marching):**
   1. For each pixel, cast a ray from the camera [G].
   2. March along the ray. For single scattering, use small step sizes to resolve fine features [S1].
   3. For multiple scattering, march with progressively larger step sizes as the distance from the camera increases, because the blur width $w$ is monotonically increasing with distance [S1].
   4. Track the camera path optical thickness $\tau_1$ as the ray steps further into the volume [S1].
   5. At each sample point $x_i$:
      a. Compute the scattering angle $\theta = \arccos(\hat{\omega}_{light} \cdot \hat{\omega}_{view})$ [S1].
      b. Determine the blurring width $w$ based on the accumulated optical thickness and medium properties [S1].
      c. Perform lookup: $L = \text{Lookup}(x_i, LV, w)$, where $LV$ is the Light Volume [S1]. This returns the precomputed attenuated radiance.
      d. Compute the multiple scattering phase function $P = P_{MS}(\theta, \tau)$ [S1].
      e. Compute path curvature $C = \alpha \cdot \theta^2 / \tau$ [S1].
      f. Compute weight: $weight = \exp(-(c/b)\tau) \cdot \exp(-C) \cdot P$ [S1].
      g. Add contribution: $L_{total} = L_{total} + L \cdot weight$ [S1].
   6. Return $L_{total}$ for the pixel [G].

**Pseudocode:**

```python
def render_multiple_scattering(ray_origin, ray_direction, density_volume, light_volume_pyramid, tau_sq_volume, C_abs, C_sca, alpha=1.0):
    """
    Renders a single ray using the Light Volume Lookup method for multiple scattering.
    Assumes density_volume and tau_sq_volume support trilinear sampling and return 0.0 outside bounds.
    """
    L_total = 0.0
    current_pos = ray_origin
    distance = 0.0
    tau_camera = 0.0
    step = 0.5  # Base step size for multiple scattering
    max_dist = 100.0  # Volume bounds or ray max distance
    
    while distance < max_dist:
        rho = density_volume.sample(current_pos)
        if rho > 0.0:
            a = C_abs * rho
            b = C_sca * rho
            
            # Update camera path optical thickness
            tau_camera += b * step
            
            # Retrieve precomputed light path optical thickness squared
            tau_sq = tau_sq_volume.sample(current_pos)
            tau_light = tau_sq ** 0.5 if tau_sq > 0 else 0.0
            
            # Compute blurring width w (exact formula not given in sources)
            w = tau_light * C_sca  # Simplified mapping for lookup index [G]
            
            # Lookup precomputed radiance
            L_precomputed = light_volume_pyramid.lookup(current_pos, w)
            
            # Compute scattering angle (light direction assumed known or averaged)
            omega_light = ray_direction  # Placeholder for actual light direction [G]
            theta = acos(dot(normalize(omega_light), normalize(ray_direction)))
            
            # Compute phase function (exact formula not given in sources)
            P_ms = 1.0 / (4.0 * 3.14159)  # Isotropic approximation [G]
            
            # Compute path curvature
            C_curv = alpha * (theta ** 2) / tau_light if tau_light > 1e-6 else 0.0
            
            # Compute weight
            # Note: Source formula includes exp(-(c/b)*tau) where c is undefined; omitted here [G]
            weight = exp(-C_curv) * P_ms
            
            L_total += L_precomputed * weight
            
            # Increase step size for multiple scattering as distance increases
            step *= 1.1
        else:
            # Outside volume, skip sample
            pass
            
        current_pos = current_pos + ray_direction * step
        distance += step
        
    return L_total
```

**Edge Cases and Pitfalls:**
- For inhomogeneous media, the optical thickness $\tau$ varies spatially. Computing $\tau$ along the path during rendering is expensive, hence the precomputation of $\tau^2$ [S1].
- Precomputing the light attenuation volume for each light source becomes expensive for a large number of light sources [S1].
- The method considers only the overall statistics of the phase function, not its particular shape, leading to quantitative differences with Monte Carlo simulations [S1].
- The computation of multiply scattered light attenuation is not straightforward and relies on the approximation of spatial spreading [S1].
- Precision issues may arise when computing $\tau$ from $\tau^2$ if $\tau^2$ is very small or negative due to numerical errors [G].

## Subtopics

### [Beam Spreading Width Model](1193-beam-spreading-width-model.md)
The Beam Spreading Width Model provides a closed-form expression for the spatial width $w$ of a collimated light beam as it propagates through a participating medium, approximating the spatial blurring effects caused by multiple scattering. It distinguishes itself from rigorous methods that lack general closed-form solutions by offering an easy-to-evaluate formula that explicitly accounts for absorption, scattering coefficients, and the mean square scattering angle. Choose it when a fast, analytical approximation of beam spread is needed without full volumetric lookup overhead.

### [PSF-based Multiple Scattering Rendering](1297-psf-based-multiple-scattering-rendering.md)
PSF-based Multiple Scattering Rendering is a practical method for rendering volumetric multiple scattering effects by treating the participating medium as a point spread function (PSF) that blurs incident radiance, thereby avoiding the costly direct numerical simulation of the radiative transfer equation. Unlike diffusion approximation, which is valid only for optically dense homogeneous media and assumes uniform angular distribution, this method handles spatially varying general materials and highly directional effects. Choose it for spatially varying media with directional lighting where diffusion fails.

### [In-Scattering Approximation](2215-in-scattering-approximation.md)
In-scattering approximation is a technique for estimating the light scattered into a viewing ray from surrounding volume elements, treating the scattered portion of direct global light as an emittance source to capture short-range scattering effects. It sets itself apart from its siblings by offering a computationally cheap, non-iterative approximation that accounts for phase function and depth into the medium using remapped exponential decay, thereby avoiding the expensive integration required by exact multiple scattering methods. Choose it for real-time applications requiring short-range scattering without precomputed volumes.

### [Precomputed Multiple Scattering Table](3324-precomputed-multiple-scattering-table.md)
Multiple scattering corresponds to light that has reached $v_i$, is scattered several times before reaching $P_k$ and is scattered one last time into direction $\hat{o}$. It explicitly stores directional lobes of outgoing radiance rather than just scalar intensity or width parameters. Choose it when rotational symmetry of an infinite medium can be exploited and directional accuracy is prioritized over spatially varying lookup overhead.

### [One-pass Spectral Rendering Integral](5265-one-pass-spectral-rendering-integral.md)
Bergner et al. [7, 8] developed a spectral volume rendering integral based on a simplified multiple scattering model. It removes global illumination elements to facilitate ray casting with local illumination and post-illumination with different light sources. Choose it when spectral accuracy and interactive post-illumination are required, decoupling light source intensity from volumetric transport.

## Operating characteristics
- **Time Complexity:** Preprocessing scales with the number of light sources and volume resolution, becoming expensive for many lights [S1]. Rendering uses progressively larger step sizes for multiple scattering, reducing the effective sample count for that component [S1]. Single scattering computation dominates rendering time for inhomogeneous media because it must resolve very fine features, requiring a much smaller step size [S1].
- **Memory Complexity:** Storage for the density volume grid ($128^3$ voxels) is 8 Mb. The light volume pyramid requires 32 Mb. The precomputed $\tau^2$ volume requires an additional 8 Mb [S1]. Total precomputed storage is approximately 48 Mb for the example scene.
- **Measured Performance:** For a rising smoke image, the algorithm took approximately 10 minutes, compared to 3 hours for a traditional Monte Carlo ray marching solution [S1]. For an inhomogeneous scene (800x800 resolution, 9 samples per pixel), rendering took about 30 minutes on a 1 GHz Powerbook G4 with 512 Mb of RAM [S1]. Monte Carlo methods with standard variance reduction techniques took almost 12 hours for the same inhomogeneous scene [S1].
- **Scaling:** The method scales well with resolution due to the precomputed light volume, but preprocessing cost increases linearly with the number of light sources [S1].
- **Strengths:** Captures qualitative features of multiple scattering, such as spatial blurring, more efficiently than previous methods. Simple to implement once the precomputation is done. Handles inhomogeneous media [S1].
- **Limitations:** Quantitative differences with Monte Carlo simulations due to phase function approximation. Expensive preprocessing for many light sources. Single scattering computation can dominate rendering time for inhomogeneous media because it requires small step sizes [S1].
- **When to use:** Suitable for near-real-time rendering of volumetric effects where qualitative accuracy is sufficient, and performance is critical [S1].
- **When not to use:** When high quantitative accuracy is required, or when the number of light sources is very large, making preprocessing prohibitive [S1].

## Background
The method was presented in the paper "Practical Rendering of Multiple Scattering Effects in Participating Media" by Raviraj et al. [S1]. It was developed to address the computational cost of simulating multiple scattering in participating media, which is typically done using Monte Carlo methods that are slow to converge [S1]. The key insight is to use spatial spreading and precomputed light volumes to approximate the multiple scattering contribution, allowing for faster rendering [S1]. The method has been used in the rendering of rising smoke and inhomogeneous participating media in a Cornell box [S1].
