# Precomputed Multiple Scattering Table

Also called: Multiple Scattering by Precomputation, Multiple scattering precomputation, Particle tracing in infinite medium

## Overview
This method approximates multiple scattering in participating media by precomputing the material's radiance response to a directional point light source in an infinite medium using Monte Carlo simulation [S1]. It solves the problem of efficiently rendering complex multiple scattering effects in real-time or near real-time by replacing expensive runtime integration with a lookup from a compressed, symmetry-exploited data structure [S1]. It differs from [Beam Spreading Width Model](1193-beam-spreading-width-model.md) and [PSF-based Multiple Scattering Rendering](1297-psf-based-multiple-scattering-rendering.md) by explicitly storing the angular distribution of scattered light (lobes) in a 4D or 5D table indexed by spatial and angular coordinates, rather than using analytic width models or fixed-point-spread functions [S1].

## How it works
**Inputs:**
*   Material properties: albedo $\alpha$, phase function parameter $g$ (e.g., Henyey-Greenstein), and mean-free-path $\ell$ [S1].
*   Scene geometry: positions of light sources and scattering points $v_i$ [S1].
*   View direction $\hat{\mathbf{o}}$ [S1].

**Outputs:**
*   Multiple scattering contribution at each point $P_k$ [S1].

**Data Structures:**
The core data structure is a precomputed table representing the outgoing radiance $L_o$.
1.  **Cylindrical Spatial Index:** The table is indexed by normalized cylindrical coordinates $(\rho/\ell, z/\ell)$ [S1].
    *   $\rho/\ell$: Normalized radial distance from the propagation axis.
    *   $z/\ell$: Normalized depth along the propagation axis.
    *   The base grid resolution is $1024 \times 512$ cells [S1].
2.  **Angular Storage:** At each spatial cell, outgoing radiance is stored in spherical coordinates $(\theta, \phi)$ relative to the local frame defined by the source direction [S1].
    *   $\theta$: Polar angle, sampled with 18 directions.
    *   $\phi$: Azimuthal angle, sampled with 36 directions [S1].
3.  **Compression:** The spatial grid is compressed using a quadtree based on particle density. Nodes with no scattering events are discarded [S1]. This reduces memory from 8.4 GB to approximately 60 MB for standard materials [S1].

**Steps:**

1.  **Precomputation (Monte Carlo Simulation):**
    *   Initialize a point light source at the origin, emitting photons in a single direction (z-axis) into an infinite medium [S1].
    *   Propagate photons using a standard Monte Carlo procedure:
        *   Move photons in straight lines.
        *   Scatter and absorb photons based on the material's scattering and absorption coefficients [S1].
    *   Normalize all spatial coordinates by the mean-free-path $\ell$ to allow reuse across different material properties [S1].
    *   Accumulate photon contributions into the $1024 \times 512$ grid, storing angular distribution in spherical coordinates $(\theta, \phi)$ [S1].
    *   Compress the resulting grid using a quadtree, removing empty nodes [S1].
    *   Repeat for various combinations of albedo $\alpha$ and phase function parameter $g$ [S1].

2.  **Runtime Lookup:**
    *   For a scattering point $v_i$ with incoming direction $\hat{\mathbf{d}}_i$ and a target point $P_k$:
    *   Calculate the vector $\mathbf{r}_i$ from $v_i$ to $P_k$ [S1].
    *   Compute cylindrical coordinates of $P_k$ relative to the axis defined by $(v_i, \hat{\mathbf{d}}_i)$:
        $$ z_k = |\mathbf{r}_i \cdot \hat{\mathbf{d}}_i| $$
        $$ \rho_k = \|\mathbf{r}_i - z_k \hat{\mathbf{d}}_i\| $$
    *   Normalize coordinates: $z_{norm} = z_k / \ell$, $\rho_{norm} = \rho_k / \ell$ [S1].
    *   Determine the outgoing direction $\hat{\mathbf{o}}$ in the local frame. Transform $\hat{\mathbf{o}}$ into the frame defined by $(v_i, \hat{\mathbf{d}}_i)$ using rotation matrix $T_{(v_i, \hat{\mathbf{d}}_i)}$ to get local angles $(\theta, \phi)$ [S1].
    *   Interpolate in the precomputed table at $(\rho_{norm}, z_{norm}, \theta, \phi)$ to retrieve $L_o$ [S1].
    *   Sum contributions from all relevant incoming paths $i_1$:
        $$ \text{mult.}(P_k) = \sum_{i_1} L_0 \left( \frac{\rho_k}{\ell}, \frac{z_k}{\ell}, T_{(i_1, \hat{d}_1)}(\hat{\mathbf{o}}) \right) $$
        where $L_0$ is the precomputed radiance value [S1].

**Parameters:**
*   $\ell$: Mean-free-path, used for normalization and indexing [S1].
*   $\alpha$: Albedo, affects the table values [S1].
*   $g$: Phase function parameter, affects the table values [S1].
*   Grid Resolution: $1024 \times 512$ spatial cells, 18 $\theta$ samples, 36 $\phi$ samples [S1].

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** The precomputed table assumes an infinite medium. It does not account for light bouncing off internal surfaces [S1]. This requires correction (see [Bounced Multiple Scattering](3532-bounced-multiple-scattering.md)) [S1].
*   **Precision:** Coordinate normalization by $\ell$ is critical for reusability; errors in $\ell$ estimation lead to lookup mismatches [S1].
*   **Compression Artifacts:** Aggressive quadtree pruning may remove valid scattering events in low-density regions, causing artifacts [S1].

## Subtopics

### [Bounced Multiple Scattering](3532-bounced-multiple-scattering.md)
Corrects for light that has bounced on the internal surface of the material, which is missing from the infinite medium precomputed table. It adds diffuse indirect illumination to compensate for the lack of boundary interactions in the precomputed data.

### GPU Implementation of Precomputed Multiple Scattering
Optimizes the method for GPU execution by reducing memory footprint and enabling interpolation [S1].
*   **Approximation:** Approximates each lobe by a lobe with symmetry of revolution around the axis joining the source point $O$ and the current point $P$ [S1].
*   **3D Table:** Stores material response in a 3D table indexed by $(\rho/\ell, z/\ell, \theta)$, where $\theta$ is the angle between the outgoing direction and the lobe axis [S1].
*   **5D Material Table:** Repeats computations for multiple values of albedo $\alpha$ and phase function parameter $g$, storing responses in a 5D table [S1].
*   **Interpolation:** At run-time, interpolates over $\alpha$ and $g$ to extract the table corresponding to the current material [S1].
*   **Memory Cost:** The overall cost of the 5D table is 600 MB [S1].

## Operating characteristics
*   **Time Complexity:** Lookup is $O(1)$ per sample after precomputation, dominated by interpolation in the 4D/5D table [S1].
*   **Memory Complexity:**
    *   CPU/General: ~60 MB for compressed quadtree representation (down from 8.4 GB) [S1].
    *   GPU: ~600 MB for the 5D material table [S1].
*   **Performance:** Enables real-time or near real-time rendering of multiple scattering by avoiding runtime Monte Carlo integration for multiple bounces [S1].
*   **Strengths:** High accuracy for multiple scattering in homogeneous media; efficient storage via symmetry and compression; reusable across materials via interpolation [S1].
*   **Limitations:** Assumes infinite medium (no boundary bounces); limited to homogeneous media; precomputation cost is high; accuracy depends on table resolution and interpolation [S1].
*   **When to Use:** Real-time rendering of homogeneous participating media where multiple scattering is significant and boundary effects are secondary or corrected separately [S1].
*   **When Not to Use:** Heterogeneous media; scenes with significant boundary reflections; resources constrained to <600 MB for GPU storage [S1].

## Background
The method originates from the work on point-based rendering for homogeneous participating media with refractive boundaries, specifically the section on multiple scattering by precomputation [S1]. It was implemented in the Mitsuba Renderer and compared against photon mapping with Beam-Radiance Estimate (BRE) and Bi-Directional Path Tracing (BDPT) [S1]. The approach leverages the rotational symmetry of scattering in infinite media to compress the data structure significantly [S1].
