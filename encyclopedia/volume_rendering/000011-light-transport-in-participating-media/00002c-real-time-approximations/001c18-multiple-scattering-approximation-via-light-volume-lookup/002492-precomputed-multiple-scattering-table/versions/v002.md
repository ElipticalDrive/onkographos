# Precomputed Multiple Scattering Table

Also called: Multiple Scattering by Precomputation, Multiple scattering precomputation, Particle tracing in infinite medium

## Overview
This method approximates the contribution of light that has undergone multiple scattering events within a homogeneous participating medium by storing the material's radiance response in a precomputed lookup table [S1]. It solves the computational cost of simulating high-order scattering in real-time or near-real-time rendering by exploiting the rotational symmetry of an infinite medium and normalizing distances by the mean free path [S1]. It is distinct from [Beam Spreading Width Model](1193-beam-spreading-width-model.md) and [PSF-based Multiple Scattering Rendering](1297-psf-based-multiple-scattering-rendering.md) by explicitly storing directional lobes of outgoing radiance rather than just scalar intensity or width parameters, and it serves as the primary multiple scattering term in [Multiple Scattering Approximation via Light Volume Lookup](1188-multiple-scattering-approximation-via-light-volume-lookup.md) before optional corrections like [Bounced Multiple Scattering](3532-bounced-multiple-scattering.md) are applied [S1].

## How it works
**Inputs:**
*   Material properties: albedo $\alpha$, phase function parameter $g$ (e.g., Henyey-Greenstein), and mean free path $\ell$.
*   Scene geometry: positions of light sources $v_i$ and their emission directions $\hat{d}_i$.
*   Camera ray intersection points $P_k$ and outgoing view directions $\hat{o}$.

**Outputs:**
*   Multiple scattering radiance contribution $\text{mult.}(P_k)$ for each sample point.

**Data Structures:**
The core data structure is a precomputed table storing outgoing radiance $L_o$.
1.  **Spatial Indexing (Cylindrical):** The table is indexed by normalized cylindrical coordinates $(\rho/\ell, z/\ell)$ relative to the light source axis.
    *   $\rho/\ell$: Normalized radial distance from the axis of propagation.
    *   $z/\ell$: Normalized depth along the axis of propagation.
    *   The base grid resolution is $1024 \times 512$ cells [S1].
2.  **Directional Indexing (Spherical):** At each spatial cell, outgoing radiance is stored in spherical coordinates $(\theta, \phi)$ relative to the local frame defined by the light source direction.
    *   $\theta$: Polar angle, sampled with 18 directions [S1].
    *   $\phi$: Azimuthal angle, sampled with 36 directions [S1].
3.  **Compression (Quadtree):** The 2D spatial grid is compressed using a quadtree based on particle density. Nodes with no scattering events are discarded [S1]. This reduces memory from 8.4 GB to ~60 MB for standard materials [S1].
4.  **GPU Variant (3D/5D Table):** For GPU implementation, lobes are approximated with symmetry of revolution around the axis joining the source $O$ and point $P$. The table becomes 3D indexed by $(\rho/\ell, z/\ell, \theta)$, where $\theta$ is the angle between the outgoing direction and the lobe axis [S1]. To support multiple materials, a 5D table is stored indexed by $(\rho/\ell, z/\ell, \theta, \alpha, g)$, with a total cost of 600 MB [S1].

**Numbered Steps:**

1.  **Precomputation (Monte Carlo Simulation):**
    *   Initialize a point light source emitting photons in a single direction (z-axis) within an infinite homogeneous medium [S1].
    *   Propagate particles in straight lines, applying standard Monte Carlo scattering and absorption procedures [S1].
    *   Normalize all coordinates by the mean free path $\ell$ to allow reuse across different material properties [S1].
    *   Accumulate scattered photon contributions into the spatial grid [S1].
    *   Store the accumulated radiance in the directional bins $(\theta, \phi)$ [S1].
    *   Repeat for various combinations of $\alpha$ and $g$ if building the multi-material 5D table [S1].
    *   Compress the spatial grid using the quadtree structure [S1].

2.  **Runtime Evaluation:**
    *   For a given light source $v_i$ with direction $\hat{d}_i$ and a point $P_k$ in the medium:
    *   Calculate the vector $\mathbf{r}_i$ from the light source to the point $P_k$.
    *   Compute the cylindrical coordinates of $P_k$ relative to the axis $(v_i, \hat{d}_i)$:
        $$ z_k = |\mathbf{r}_i \cdot \hat{\mathbf{d}}_i| $$
        $$ \rho_k = \|\mathbf{r}_i - z_k \hat{\mathbf{d}}_i\| $$
    *   Normalize these coordinates: $z_{norm} = z_k / \ell$, $\rho_{norm} = \rho_k / \ell$.
    *   Determine the outgoing direction $\hat{o}$ in the local frame of the light source. Let $T_{(v_i, \hat{d}_i)}(\hat{o})$ be the transformation of $\hat{o}$ into the frame defined by $(v_i, \hat{d}_i)$, yielding angles $(\theta, \phi)$ [S1].
    *   In the GPU variant, compute $\theta_{lobe}$ as the angle between $\hat{o}$ and the axis $(v_i, \hat{d}_i)$ [S1].
    *   Look up the radiance $L_o$ from the precomputed table using indices $(\rho_{norm}, z_{norm}, \theta, \phi)$ [S1] or $(\rho_{norm}, z_{norm}, \theta_{lobe})$ for the GPU symmetric approximation [S1].
    *   If using the 5D material table, interpolate over $\alpha$ and $g$ to find the specific response for the current material [S1].
    *   Sum contributions from all relevant light sources $i_1$:
        $$ \text{mult.}(P_k) = \sum_{i_1} L_0 \left( \frac{\rho_k}{\ell}, \frac{z_k}{\ell}, T_{(i_1, \hat{d}_1)}(\hat{\mathbf{o}}) \right) $$
        where $L_0$ is the stored radiance value [S1].

**Parameters:**
*   $\ell$: Mean free path, used for normalization and indexing [S1].
*   $\alpha$: Albedo, affects the table values [S1].
*   $g$: Phase function parameter, affects the table values [S1].
*   Grid Resolution: $1024 \times 512$ for the base 2D spatial grid [S1].
*   Angular Resolution: 18 $\theta$ directions, 36 $\phi$ directions for the full 4D table [S1].

**Edge Cases and Pitfalls:**
*   **Infinite Medium Assumption:** The table assumes an infinite medium. It does not account for light bouncing off internal surfaces. This requires a separate correction term, such as [Bounced Multiple Scattering](3532-bounced-multiple-scattering.md) [S1].
*   **Homogeneity:** The method assumes the medium is homogeneous. Variations in density or properties require different tables or interpolation [S1].
*   **Precision:** Normalization by $\ell$ is critical for reusability; errors in $\ell$ estimation lead to incorrect indexing [S1].
*   **Memory:** The uncompressed table is prohibitively large (8.4 GB); compression is mandatory [S1]. The GPU variant increases memory to 600 MB for multi-material support [S1].

## Subtopics

### [Bounced Multiple Scattering](3532-bounced-multiple-scattering.md)
Bounced Multiple Scattering corrects for light that has bounced off the internal surface of a material, which is missing from the infinite medium precomputed multiple scattering table. It adds diffuse indirect illumination from inside the material to surface samples, allowing the renderer to account for light that enters the volume, scatters, hits the boundary, reflects back into the volume, and scatters again toward the camera. It is a correction term applied after the primary multiple scattering lookup, distinct from single and double scattering approximations.

### GPU Implementation of Precomputed Multiple Scattering
This variant adapts the method for GPU execution by approximating each lobe with symmetry of revolution around the axis joining the source point $O$ and the current point $P$ [S1]. This reduces the directional storage from spherical $(\theta, \phi)$ to a single angle $\theta$ (angle between outgoing direction and lobe axis), resulting in a 3D table indexed by $(\rho/\ell, z/\ell, \theta)$ [S1]. To support multiple materials, responses for various $\alpha$ and $g$ are stored in a 5D table with an overall cost of 600 MB [S1]. At runtime, interpolation over $\alpha$ and $g$ extracts the table for the current material [S1].

## Operating characteristics
*   **Time Complexity:** Precomputation is expensive (Monte Carlo simulation), but runtime lookup is $O(1)$ per light source per sample, dominated by table access and interpolation [S1].
*   **Memory Complexity:** The hierarchical representation reduces memory from 8.4 GB to approximately 60 MB for single-material precomputation [S1]. The GPU 5D table for multiple materials costs 600 MB [S1].
*   **Measured Performance:** The method enables real-time or near-real-time rendering of multiple scattering effects that would otherwise require prohibitive photon counts [S1].
*   **Strengths:** High accuracy for multiple scattering in homogeneous media; efficient runtime performance; reusability across different lighting conditions via normalization [S1].
*   **Limitations:** Assumes infinite medium (no boundary bounces); assumes homogeneity; high precomputation cost; large memory footprint for multi-material support [S1].
*   **When to use:** Real-time rendering of homogeneous participating media where multiple scattering is significant and boundaries are not the primary concern or are handled separately.
*   **When not to use:** Inhomogeneous media, media with strong boundary interactions (without correction), or when memory is extremely constrained.

## Background
The method originates from the work on point-based rendering for homogeneous participating media with refractive boundaries, specifically detailed in "Point-Based Rendering for Homogeneous Participating Media with Refractive Boundaries" [S1]. It was implemented within the Mitsuba Renderer and compared against photon mapping with Beam-Radiance Estimate (BRE) and Bi-Directional Path Tracing (BDPT) [S1]. The approach builds on the observation that multiple scattering in an infinite medium exhibits rotational symmetry, allowing for efficient precomputation [S1].
