# MIP map filtering for multiple scattering

Also called: Elek et al. MIP map filtering, Filtering-based real-time multiple scattering, MIP map Gaussian blurring, Real-time GPU filtering method

## Overview
This method efficiently approximates multiple-scattering light transport in non-homogeneous, analytically integrable participating media by applying Gaussian blurring via MIP maps [S1, unofficial]. It solves the high computational cost of neighborhood filtering in screen-space rendering, enabling real-time performance on GPUs by reducing time complexity from $O(n^4)$ to $O(n^2 \log_2 n)$ [S1, unofficial]. Unlike naive gathering which iterates over a fixed neighborhood for every pixel, this approach leverages hierarchical image representations to accumulate contributions across scales [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A screen-space image representing single-scattering or vacuum-rendered lighting, where each pixel is treated as an independent light source [S1, unofficial].
*   **Input:** A density function $\varrho(x)$ that is analytically integrable, allowing for non-homogeneous media (e.g., exponential density variations) [S1, unofficial].
*   **Output:** The filtered image after applying MIP map convolution [S1, unofficial].

**Data Structures:**
*   **MIP Map Pyramid:** A set of images $L_k$ where $L_0$ has resolution $n \times n$ [S1, unofficial]. Higher levels $L_k$ have resolutions decreasing exponentially until $1 \times 1$, yielding a total of $O(\log_2 n)$ levels [S1, unofficial].
*   **Kernel:** A constant-sized Gaussian kernel $G$ used for convolution at each level [S1, unofficial].

**Parameters:**
*   **$n$:** Image resolution (width or height) [S1, unofficial].
*   **$m$:** Neighborhood radius. In HDR images where a pixel blurs into the whole image, $m = n$ [S1, unofficial].
*   **Target Performance:** Higher than 25 FPS at 1280x720 resolution (HD) [S1, unofficial].

**Steps:**
1.  **Generate MIP Map Pyramid:** Construct the MIP map levels $L_0$ to $L_{max}$ from the input image [S1, unofficial]. The total number of levels is $O(\log_2 n)$ [S1, unofficial].
2.  **Iterate Levels:** For each MIP map level $k > 0$:
    a.  Perform convolution of the current level's image with the constant-sized Gaussian kernel $G$ [S1, unofficial].
    b.  For each pixel in the level, iterate through the constant-sized neighborhood defined by the kernel [S1, unofficial].
    c.  Accumulate weighted contributions from the neighborhood pixels [S1, unofficial].
3.  **Handle Non-Homogeneous Media:** Use analytically integrable density functions (e.g., derived from the barometric formula) to calculate transmittance efficiently between points [S1, unofficial].

**Formulas:**
*   **Barometric Formula for Pressure:** Used to derive density functions for non-homogeneous media [S1, unofficial]:
    $$p(z) = p(0) \cdot \exp\left(-\frac{mgz}{kT}\right)$$
    Where:
    *   $p(z)$ is pressure at altitude $z$.
    *   $p(0)$ is pressure at $z=0$.
    *   $m$ is molecular mass.
    *   $g$ is gravitational constant.
    *   $k$ is Boltzmann constant.
    *   $T$ is temperature.
    *   Density $\varrho(z)$ is derived similarly, as it is directly related to pressure [S1, unofficial].

**Pseudocode:**
```python
import math

def mip_map_filtering(input_image, kernel_radius):
    """
    Applies MIP map filtering for multiple scattering.
    Args:
        input_image: 2D list of floats, resolution n x n.
        kernel_radius: Half-width of the constant-sized Gaussian kernel G.
    Returns:
        filtered_image: Resulting multiple-scattering approximation.
    """
    n = len(input_image)
    # Step 1: Generate MIP Map Pyramid
    mip_levels = [input_image]
    current = input_image
    while len(current) > 1:
        h, w = len(current), len(current[0])
        next_h, next_w = (h + 1) // 2, (w + 1) // 2
        next_level = [[0.0] * next_w for _ in range(next_h)]
        for i in range(0, h, 2):
            for j in range(0, w, 2):
                val = 0.0
                count = 0
                for di in range(2):
                    for dj in range(2):
                        if i + di < h and j + dj < w:
                            val += current[i + di][j + dj]
                            count += 1
                if count > 0:
                    next_level[i // 2][j // 2] = val / count
        mip_levels.append(next_level)
        current = next_level

    # Step 2: Iterate Levels and Convolve
    # The source describes convolving each level k > 0 with a constant kernel G
    # and accumulating weighted contributions.
    filtered_image = [[0.0] * n for _ in range(n)]
    half_k = kernel_radius

    for k in range(1, len(mip_levels)):
        level = mip_levels[k]
        h, w = len(level), len(level[0])
        blurred_level = [[0.0] * w for _ in range(h)]
        for i in range(h):
            for j in range(w):
                contribution = 0.0
                for di in range(-half_k, half_k + 1):
                    for dj in range(-half_k, half_k + 1):
                        ni, nj = i + di, j + dj
                        # Clamp boundaries
                        ni = max(0, min(ni, h - 1))
                        nj = max(0, min(nj, w - 1))
                        weight = gaussian_weight(di, dj, kernel_radius)
                        contribution += level[ni][nj] * weight
                blurred_level[i][j] = contribution

        # Upsample blurred level back to original resolution for accumulation
        upscaled = upscale_to_original(blurred_level, n)
        for i in range(n):
            for j in range(n):
                filtered_image[i][j] += upscaled[i][j]

    return filtered_image

def gaussian_weight(dx, dy, radius):
    """Computes Gaussian weight for a given offset."""
    sigma = radius / 2.0
    exponent = -((dx ** 2 + dy ** 2) / (2 * sigma ** 2))
    return math.exp(exponent)

def upscale_to_original(blurred_level, target_n):
    """Bilinear upsampling to match original resolution n x n."""
    h, w = len(blurred_level), len(blurred_level[0])
    scale_h = target_n / h
    scale_w = target_n / w
    upscaled = [[0.0] * target_n for _ in range(target_n)]
    for i in range(target_n):
        for j in range(target_n):
            src_i = i / scale_h
            src_j = j / scale_w
            i0, i1 = int(math.floor(src_i)), int(math.ceil(src_i))
            j0, j1 = int(math.floor(src_j)), int(math.ceil(src_j))
            i0, i1 = max(0, min(i0, h - 1)), max(0, min(i1, h - 1))
            j0, j1 = max(0, min(j0, w - 1)), max(0, min(j1, w - 1))
            fi, fj = src_i - i0, src_j - j0
            val = ((1 - fi) * (1 - fj) * blurred_level[i0][j0] +
                   fi * (1 - fj) * blurred_level[i1][j0] +
                   (1 - fi) * fj * blurred_level[i0][j1] +
                   fi * fj * blurred_level[i1][j1])
            upscaled[i][j] = val
    return upscaled
```

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** The pseudocode assumes clamping for neighborhood iteration; the source does not specify [G].
*   **Non-Analytic Densities:** The method requires analytically integrable density functions; arbitrary density functions cannot be handled efficiently [S1, unofficial].
*   **Artifacts:** While MIP map filtering reduces artifacts compared to naive gathering, some visual artifacts may still be present, though significantly reduced [S1, unofficial].
*   **Screen-Space Approximation:** The method treats every pixel as an independent light source, disregarding attenuation or scattering before surface reflection for simplicity [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(n^2 \log_2 n)$, where $n$ is the image resolution [S1, unofficial]. This is a significant improvement over naive gathering's $O(n^4)$ to $O(n^6)$ for HDR images where $m=n$ [S1, unofficial].
*   **Memory Complexity:** $O(n^2)$ for storing the MIP map pyramid, as the sum of geometric series $n^2 + (n/2)^2 + \dots$ converges to $O(n^2)$ [S1, unofficial].
*   **Measured Performance:** On a GeForce GTX 760M, the method achieved 2 milliseconds per frame for a sample image, compared to 30 seconds for the gathering algorithm and 15 hours for path-tracing reference [S1, unofficial].
*   **Target Performance:** Higher than 25 FPS at 1280x720 resolution (HD) [S1, unofficial].
*   **Strengths:** Real-time performance on GPUs; handles non-homogeneous media; significantly faster than naive gathering [S1, unofficial].
*   **Limitations:** Requires analytically integrable density functions; screen-space approach disregards attenuation/scattering before surface reflection; potential for residual visual artifacts compared to more accurate but slower methods [S1, unofficial].
*   **When to Use:** Real-time rendering of multiple scattering in non-homogeneous media where performance is critical and approximate results are acceptable [S1, unofficial].
*   **When Not to Use:** When high accuracy is required (e.g., offline rendering), or when density functions are not analytically integrable [S1, unofficial].

## Background
*   **Origin:** Proposed by Elek et al. [2013] as a solution to reduce visual artifacts and computational cost in multiple-scattering light transport [S1, unofficial].
*   **History:** The method is part of a broader effort to enable real-time rendering of complex light transport effects in participating media [S1, unofficial]. It builds on the concept of treating screen-space pixels as light sources and applying filtering to approximate multiple scattering [S1, unofficial].
*   **Usage:** Implemented in fragment shaders for GPU execution, tested on hardware like the GeForce GTX 760M [S1, unofficial]. It is used in contexts requiring real-time performance, such as video games or interactive applications, where traditional path-tracing is too slow [S1, unofficial].
