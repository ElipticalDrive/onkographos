# Alpha Accumulation for Voxel Cone Tracing

Also called: Correct alpha blending for voxel cone tracing, Front-to-back blending for cone tracing

## Overview
Alpha accumulation is a front-to-back blending method used during the cone tracing pass of voxel cone tracing to correctly handle transparency and prevent black staircase artifacts at voxel edges [S1, unofficial]. Unlike standard alpha blending, which can cause unfilled (black) regions with zero alpha to bleed aggressively into the result, this method accumulates color and alpha multiplicatively, ensuring that opaque or semi-transparent surfaces are rendered without darkening artifacts caused by empty space [S1, unofficial]. It builds on [Voxel Cone Tracing](4558-voxel-cone-tracing.md) by modifying the light accumulation step to support volumetric or surface transparency.

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D voxel texture containing RGBA values, where `A` represents opacity. The cone tracing parameters (origin, direction, half-angle) and the current accumulated color and alpha.
*   **Output:** The final accumulated color and alpha for the fragment being shaded.

**Data Structures:**
*   **Voxel:** A 4-component floating-point vector (`float4`) storing Red, Green, Blue, and Alpha channels.
*   **Accumulators:** Two `float4` variables, `color` and `alpha`, initialized to zero.

**Algorithm:**
The method replaces the standard alpha blending equation with a front-to-back accumulation loop during cone tracing.

1.  Initialize accumulators:
    $$ \text{color} = 0 $$
    $$ \text{alpha} = 0 $$
2.  For each step along the cone (ray-marching in world space):
    a.  Calculate the cone diameter at the current distance from the cone origin:
        $$ d_{\text{cone}} = 2 \cdot \tan(\theta_{\text{half}}) \cdot d_{\text{origin}} $$
        where $\theta_{\text{half}}$ is the cone half-angle and $d_{\text{origin}}$ is the distance from the cone origin to the current sampling position [S1, unofficial].
    b.  Determine the mip level for the 3D texture based on the cone diameter and the base voxel size $s_{\text{voxel}}$:
        $$ m = \log_2 \left( \frac{d_{\text{cone}}}{s_{\text{voxel}}} \right) $$
        [S1, unofficial]
    c.  Sample the voxel at the current position and mip level:
        $$ v = \text{SampleVoxels}(pos, m) $$
        where $v.rgba$ contains the voxel's color and alpha [S1, unofficial].
    d.  Calculate the remaining alpha (transmittance of the empty space behind the current voxel):
        $$ a_{\text{rem}} = 1 - \alpha $$
        [S1, unofficial]
    e.  Update the accumulated color and alpha using front-to-back blending:
        $$ \text{color} \leftarrow \text{color} + a_{\text{rem}} \cdot v.rgb $$
        $$ \alpha \leftarrow \alpha + a_{\text{rem}} \cdot v.a $$
        [S1, unofficial]
    f.  **Termination Condition:** If $\alpha$ reaches 1.0 (or a threshold close to it), the cone is fully opaque, and tracing can stop [S2, unofficial].

**Pitfalls:**
*   **Black Staircase Artifacts:** Using regular alpha blending (e.g., `color += (1-alpha) * voxel.rgb; alpha += (1-alpha) * voxel.a;` is incorrect if not ordered front-to-back correctly or if the formula is misapplied) causes black regions with zero alpha to bleed into the result aggressively at voxel edges [S1, unofficial]. The specific formula `color += (1-alpha) * voxel.rgb` combined with `alpha += (1-alpha) * voxel.a` is the correct front-to-back accumulation [S1, unofficial].
*   **Thin Geometry:** Thin walls or geometry require higher resolution to avoid bleeding. Additionally, thin walls cause a stepping problem where secondary rays emit with equal strength on each side, potentially leading to incorrect lighting contributions [S2, unofficial].

**Pseudocode:**
```python
def accumulate_alpha_cone_trace(cone_origin, cone_direction, cone_half_angle, voxel_texture, voxel_size):
    """
    Performs alpha accumulation for voxel cone tracing.
    
    Args:
        cone_origin: vec3, origin of the cone.
        cone_direction: vec3, direction of the cone.
        cone_half_angle: float, half-angle of the cone in radians.
        voxel_texture: 3D texture object with sample function.
        voxel_size: float, size of the base voxel.
        
    Returns:
        float4: Accumulated color and alpha.
    """
    color = vec4(0.0)
    alpha = 0.0
    
    # Parameters for stepping
    step_size = voxel_size # Ray-march in voxel-size increments [S1, unofficial]
    max_steps = 100 # Implementation detail [G]
    
    current_pos = cone_origin
    current_dist = 0.0
    
    for i in range(max_steps):
        # Calculate cone diameter at current position
        # d_cone = 2 * tan(cone_half_angle) * distance_from_origin
        cone_diameter = 2.0 * tan(cone_half_angle) * current_dist
        
        # Calculate mip level
        # mip = log2(cone_diameter / voxel_size)
        mip = log2(cone_diameter / voxel_size)
        
        # Sample voxel
        # Note: In practice, mip coordinates need to be clamped to valid range
        voxel = voxel_texture.sample(current_pos, mip)
        
        # Front-to-back blending
        # a_rem = 1 - alpha
        a_rem = 1.0 - alpha
        
        # color += a_rem * voxel.rgb
        color += a_rem * voxel.rgb
        
        # alpha += a_rem * voxel.a
        alpha += a_rem * voxel.a
        
        # Stop if fully opaque
        if alpha >= 1.0:
            break
            
        # Advance along the cone direction
        current_pos += cone_direction * step_size
        current_dist += step_size
        
    return color, alpha
```

## Subtopics

### Voxel Cone Tracing with Transparency
This variant extends the basic alpha accumulation to support full transparency and refraction. It requires storing alpha values in voxels and using multiplicative `(1-alpha)` accumulation during filtering and light accumulation [S2, unofficial]. The cone tracing steps along the cone, accumulating light while multiplying the result by alpha, and stops if alpha is zero [S2, unofficial]. For refraction, the cone direction is refracted, replacing the Bidirectional Reflectance Distribution Function (BRDF) with a Bidirectional Transmittance Distribution Function (BTDF) [S2, unofficial]. This approach is more complex and requires higher resolution to handle thin geometry, which otherwise suffers from bleeding and stepping artifacts where thin walls emit secondary rays of equal strength on each side [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of steps in the cone trace. The number of steps depends on the scene depth and the cone half-angle.
*   **Memory Complexity:** Depends on the voxel texture size and mip levels. Storing alpha adds no extra memory overhead if the voxel format is already RGBA [S1, unofficial].
*   **Strengths:** Prevents black artifacts at voxel edges, allowing for correct rendering of semi-transparent surfaces and volumetric effects within the voxel cone tracing framework [S1, unofficial].
*   **Limitations:** Thin geometry requires higher resolution, increasing memory and computational cost [S2, unofficial]. Refraction adds significant complexity by requiring cone direction changes and BTDF evaluation [S2, unofficial].
*   **When to use:** When the scene contains transparent or semi-transparent objects that need to interact with indirect lighting computed via voxel cone tracing.
*   **When not to use:** For scenes with very thin geometry where resolution constraints prevent accurate alpha representation, or when performance is critical and transparency is not required.

## Background
Alpha accumulation for voxel cone tracing was discussed in the context of real-time global illumination implementations. The method addresses the limitations of standard alpha blending in the specific context of voxel-based light transport, where empty space (zero alpha) can negatively impact the visual result [S1, S2, unofficial]. The approach was popularized in community discussions and tutorials regarding voxel-based GI, such as those found on Stack Overflow and personal blogs detailing the implementation of voxel cone tracing [S1, S2, unofficial].
