# Radiance Cascades

Also called: Radiance Intervals, Suslik's Radiance Cascades

## Overview
Radiance Cascades is a global illumination technique developed for *Path of Exile 2* that approximates indirect lighting by sampling radiance along concentric shells (cascades) around probes [S1, unofficial]. It stores light information hierarchically to balance compute and storage costs for interactive applications [S2, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   Scene geometry and direct lighting information [S1, unofficial].
*   Probe placement configuration: screen-space or world-space [S1, unofficial].
*   Cascade parameters: Level 0 ray count ($N_0$), branching factor ($N_{level}$), Level 0 interval radius ($R_0$), and total levels ($L$) [S1, unofficial].

**Outputs:**
*   Indirect radiance values stored in cascade shells for each probe [S1, unofficial].
*   Merged and unmerged cascade data to retain information for computing reflections on surfaces defined by GGX or similar roughness models [S1, unofficial].

### Data Structures
**World Space Probes Layout:**
The storage cost is calculated based on the probe diameter ($D$), ray count per probe ($N_{ray}$), and bytes per ray ($B_{ray}$) [S1, unofficial].
*   `rayCount`: 6 (fixed in source examples) [S1, unofficial].
*   `bytesPerRay`: 16 bytes [S1, unofficial].
*   `Total Bytes`: $D^3 \times \text{rayCount} \times \text{bytesPerRay} \times 2$ [S1, unofficial].
*   Fields: `diameter`, `megabytes`, `MB per slice` [S1, unofficial].

**Cascade Parameters:**
*   `2i spacing (level 0)`: Initial interval spacing [S1, unofficial].
*   `2r raycount (level 0)`: Initial ray count $N_0$ [S1, unofficial].
*   `branching factor`: Scaling factor for ray count per level $N_{level}$ [S1, unofficial].
*   `interval radius (level 0)`: $R_0$ [S1, unofficial].
*   `levels`: Total number of cascade levels $L$ [S1, unofficial].

### Algorithm Steps
1.  **Initialize Cascade Levels:**
    For each cascade level $i$ from $0$ to $L-1$:
    *   Calculate inner radius $r_{in}(i)$ and width $w(i)$. In 2D, each level doubles the inner radius and width relative to the previous level [S1, unofficial].
    *   Calculate ray count $N(i)$. The number of rays doubles (or scales by $N_{level}$) per level [S1, unofficial].
    *   Manage total rays per probe to balance compute cost [S1, unofficial].

2.  **Ray Distribution:**
    For each probe at level $i$, generate $N(i)$ rays distributed within the cascade shell [S1, unofficial].
    *   Offset rays to avoid overlaps using the formula:
        $$ \theta_k = \tau \times \frac{k + 0.5}{N(i)} $$
        where $\tau = 2\pi$, $k$ is the ray index ($0 \le k < N(i)$), and $N(i)$ is the ray count for level $i$ [S1, unofficial].

3.  **Ray Marching / Sampling:**
    *   Trace rays from the probe center through the cascade shell [S1, unofficial].
    *   For screen-space probes with world-space intervals, place probes on min and max depth to handle high depth complexity and thin objects [S1, unofficial].
    *   For world-space probes, use a ping-pong buffer at various spatial resolutions to compute storage costs and store data [S1, unofficial].
    *   Accumulate radiance along the rays using parameters such as `accumulate non-linearly` and `accumulation decay` [S1, unofficial].

4.  **Merge and Store:**
    *   Keep both merged and unmerged cascades to retain data for computing reflections on surfaces defined by GGX or similar roughness models [S1, unofficial].
    *   Store results in the World Space Probes structure or screen-space buffer [S1, unofficial].

### Pseudocode
```python
import math

def compute_radiance_cascades(probe_center, cascade_params):
    """
    Computes radiance cascades for a single probe.
    
    Args:
        probe_center: 3D vector, position of the probe.
        cascade_params: Object containing:
            - N0: ray count at level 0
            - branching_factor: scaling factor for ray count per level
            - R0: interval radius at level 0
            - L: total number of levels
        scene: Object providing raymarch functionality.
        
    Returns:
        List of cascade levels, each containing radiance values.
    """
    cascades = []
    current_R = cascade_params.R0
    current_N = cascade_params.N0
    
    for level in range(cascade_params.L):
        rays = []
        for k in range(current_N):
            # Angle offset formula: angle = TAU * (rayIndex + 0.5) / rayCount
            angle = 2 * math.pi * (k + 0.5) / current_N
            # In 2D, direction is purely angular; in 3D, spherical coordinates are used.
            rays.append(angle)
        
        radiance_accumulation = 0.0
        for angle in rays:
            # Raymarch step: trace ray from probe_center through cascade shell.
            # Parameters include raymarch mipmap N on cascade level N, DDA, fixed step multiplier, non-linear accumulation, and accumulation decay.
            # Not given in the sources.
            sample_radiance = 0.0
            radiance_accumulation += sample_radiance
            
        # Guard against division by zero [G]
        radiance_avg = radiance_accumulation / current_N if current_N > 0 else 0.0
        
        cascades.append({
            'level': level,
            'radius': current_R,
            'ray_count': current_N,
            'radiance': radiance_avg
        })
        
        # Each level doubles the inner radius and width (2D case)
        current_R *= 2
        current_N *= cascade_params.branching_factor
        
    return cascades
```

### Edge Cases and Pitfalls
*   **High Depth Complexity:** Thin objects may be missed if probes are not placed on min and max depth in screen-space probes [S1, unofficial].
*   **Roughness Models:** Merged cascades alone are insufficient for GGX or similar roughness models; unmerged data must be retained [S1, unofficial].
*   **Precision:** Accumulation decay and non-linear accumulation parameters affect precision in deep cascades [S1, unofficial].
*   **Visual Artifacts:** The technique suffers from light leaking at thin objects and depth discontinuities, displays visible individual rays around small light sources, and exhibits flickering during object or camera movement [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of probes, cascade levels, and rays per level. Average render times scale with sampling resolution: 5 ms, 20 ms, and 30 ms for scenes of increasing size when sampling every fourth screen pixel; 19 ms, 67 ms, and 101 ms when sampling every other pixel [S2, unofficial]. Sampling every pixel yields render times too high to be feasible for real-time applications [S2, unofficial]. Render times have significant large peaks despite being relatively stable [S2, unofficial].
*   **Memory Complexity:** Proportional to the number of probes and the storage cost per probe ($D^3 \times 6 \times 16 \times 2$ bytes) [S1, unofficial].
*   **Strengths:** Efficiently calculates and stores light information in a hierarchical manner for interactive applications [S2, unofficial]. Supports rough reflections via unmerged cascades [S1, unofficial].
*   **Limitations:** Approximate; suffers from light leaking at thin objects and depth discontinuities, visible individual rays around small light sources, and flickering during movement [S2, unofficial].
*   **When to Use:** Interactive applications requiring efficient indirect illumination storage and computation [S2, unofficial].
*   **When Not to Use:** Not given in the sources.

## Background
Radiance Cascades was developed by Alexander Sannikov (Suslik) for *Path of Exile 2* [S1, unofficial]. It evolved from earlier 2D Radiance Intervals, extending the concept to 3D with screen-space and world-space probes [S1, unofficial]. The technique has been discussed in Exilecon talks and implemented in various community demos and shaders [S1, unofficial].
