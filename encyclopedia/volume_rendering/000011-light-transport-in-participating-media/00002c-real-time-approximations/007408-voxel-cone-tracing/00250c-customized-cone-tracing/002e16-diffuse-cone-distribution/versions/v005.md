# Diffuse Cone Distribution


## Overview
Diffuse Cone Distribution is a sampling pattern used in Voxel Cone Tracing to approximate indirect diffuse lighting for surface-based global illumination [S1, unofficial]. It uses a fixed set of five cones: one aligned with the surface normal and four distributed at perpendicular angles, all sharing a $30^\circ$ aperture [S1, unofficial]. It is distinguished from its siblings by its rigid geometric symmetry, contrasting with the random rotations of [Random Cone Rotation](5911-random-cone-rotation.md) and the multi-bounce logic of [Two-Bounce Indirect Illumination](4558-two-bounce-indirect-illumination.md) [S1, unofficial].

## How it works
**Inputs:** Surface position $P$, surface normal $n$, voxel grid data [S1, unofficial].
**Outputs:** Accumulated diffuse indirect lighting color $L_{\text{diffuse}}$ [S1, unofficial].
**Parameters:**
- Number of cones $N = 5$ [S1, unofficial].
- Cone aperture $\theta = 30^\circ$ [S1, unofficial].

**Data Structures:**
A list of $N$ cone direction vectors $d_i$ and a fixed aperture $\theta$ [S1, unofficial].

**Steps:**
1. **Construct Basis Vectors:** Let $n$ be the normalized surface normal. Construct two orthogonal vectors $u$ and $v$ such that $\{u, v, n\}$ form an orthonormal basis [G].
2. **Define Cone Directions:** Generate the 5 direction vectors $d_i$ for $i \in \{0, \dots, 4\}$: $d_0 = n$; $d_1 = u$, $d_2 = -u$, $d_3 = v$, $d_4 = -v$ [S1, unofficial]. The four vectors $d_1$ to $d_4$ lie in the plane perpendicular to $n$ [S1, unofficial].
3. **Trace Cones:** For each cone direction $d_i$:
   a. **Offset Origin:** Offset the ray origin $P$ slightly along the normal to prevent self-intersection artifacts: $P' = P + \epsilon n$, where $\epsilon$ is a small positive value [S1, unofficial].
   b. **Cone Trace:** Perform a voxel cone trace starting at $P'$ along direction $d_i$ with aperture $\theta$, accumulating transmittance and in-scattered color within the cone volume. Let the result be $C_i$ [S1, unofficial].
4. **Accumulate:** Sum the results:
   $$ L_{\text{diffuse}} = \sum_{i=0}^{4} C_i $$
   The sources do not specify weighting factors for the perpendicular cones versus the normal cone, implying a direct sum [S1, unofficial].

**Pseudocode:**
```python
def diffuse_cone_distribution(P, n, voxel_grid, epsilon=1e-4):
    # Construct orthonormal basis [G]
    if abs(n.x) < 0.9:
        u = normalize(cross(n, vec3(1, 0, 0)))
    else:
        u = normalize(cross(n, vec3(0, 1, 0)))
    v = cross(n, u)
    
    # Define 5 cone directions [S1, unofficial]
    directions = [n, u, -u, v, -v]
    theta = 30.0  # degrees [S1, unofficial]
    accumulated_light = vec3(0.0)
    
    for d in directions:
        P_prime = P + n * epsilon  # Offset to prevent self-intersection [S1, unofficial]
        C_i = cone_trace(P_prime, d, theta, voxel_grid)  # Standard cone trace primitive [G]
        accumulated_light += C_i
        
    return accumulated_light
```

**Edge Cases and Pitfalls:**
- **Self-Shadowing:** Failing to offset the ray origin causes the cone to immediately intersect the surface voxel, resulting in incorrect darkening or brightening [S1, unofficial].
- **Blocky Artifacts:** The sparse, rigid 5-cone sampling pattern produces visible blockiness in indirect lighting [S1, unofficial]. This limitation motivates the sibling method [Random Cone Rotation](5911-random-cone-rotation.md) [S1, unofficial].

## Subtopics

### [Random Cone Rotation](5911-random-cone-rotation.md)
Mitigates the blocky artifacts of this fixed distribution by randomly rotating the cone set around the normal. Choose this when visual quality is prioritized over deterministic performance, accepting the introduction of noise.

### SH Light Probe Update via Cone Tracing
A method to update dynamic object lighting by calculating spherical harmonic (SH) coefficients using voxel cone tracing, allowing real-time updates without pre-baking [S2, unofficial]. NetLight calculates SH weights by performing a spherical cone trace at each probe position $x_p$ to estimate directional irradiance $f(s)$, projecting the result onto SH basis functions: $f_{lm} = \sum_{i=0}^{C} g(x_p, d_i) y_{lm}(d_i)$, where $C$ is the number of cones and $d_i$ is the direction of cone $i$ [S2, unofficial]. The system calculates $f_{lm}$ for each probe in parallel using a single compute shader [S2, unofficial]. Unity shades objects using weights interpolated from the four nearest probes in a tetrahedral grid [S2, unofficial]. Compared to cubemap integration, this method has minimal runtime cost regardless of scene complexity or probe count [S2, unofficial]. Cone trace time is $\sim 0.01\text{ms}$ for 32 to 2048 probes, with application time scaling from $0.025\text{ms}$ to $0.78\text{ms}$ [S2, unofficial].

### Fixed Cone Distribution
A fixed-direction cone tracing configuration that uses six cones to approximate indirect illumination, with each cone spanning a $60^\circ$ aperture [S3, unofficial]. The cone directions are defined as $\text{coneDirections}[6] = \text{vec3}[](\text{vec3}(0, 1, 0), \text{vec3}(0, 0.5, 0.866025), \text{vec3}(0.823639, 0.5, 0.267617), \text{vec3}(0.509037, 0.5, -0.700629), \text{vec3}(-0.509037, 0.5, -0.700629), \text{vec3}(-0.823639, 0.5, 0.267617))$ [S3, unofficial]. Corresponding weights are $\text{coneWeights}[6] = \text{float}[](0.25, 0.15, 0.15, 0.15, 0.15, 0.15)$ [S3, unofficial].

## Operating characteristics
- **Complexity:** $O(1)$ cone traces per surface point (fixed at 5) [S1, unofficial].
- **Performance:** Very fast due to the low cone count [S1, unofficial].
- **Limitations:** The rigid 5-cone structure produces noticeable aliasing/blocking artifacts in indirect lighting [S1, unofficial]. It does not adapt to surface roughness for diffuse components, unlike the specular cones described in the same source [S1, unofficial].

## Background
This distribution originates from practical implementations of Voxel Cone Tracing for real-time rendering, specifically detailed in a GitHub report by righier [S1, unofficial]. The author found that 5 cones are sufficient to achieve good quality for indirect diffuse lighting approximation [S1, unofficial].
