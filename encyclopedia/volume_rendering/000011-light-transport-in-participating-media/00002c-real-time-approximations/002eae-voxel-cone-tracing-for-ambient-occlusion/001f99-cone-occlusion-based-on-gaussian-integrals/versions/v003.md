# Cone Occlusion based on Gaussian Integrals

Also called: Cone Occlusion, Cone Shadow, RC1PConeTracingDirOcclusionShading

## Overview
Cone Occlusion based on Gaussian Integrals is a volume rendering shading technique that approximates light occlusion and shadowing by tracing cones through a voxel volume and integrating extinction coefficients using Gaussian distributions [S1, unofficial]. It supports two distinct modes: Cone Occlusion for self-shadowing and Cone Shadow for external light source shadows [S1, unofficial].

## How it works
### Inputs and Outputs
Inputs include the extinction coefficient volume texture, camera matrices (Eye, View, Projection), FOV tangent, aspect ratio, occlusion/shadow flags, integration step size, Phong shading flags, Blinn-Phong coefficients ($K_{ambient}, K_{diffuse}, K_{specular}, N_{shininess}$), light source positions, and cone tracing parameters [S1, unofficial]. The output is a screen-space image texture containing the final shading result [S1, unofficial].

### Data Structures
The implementation relies on a `ConeGaussianSampler` configuration to manage cone parameters [S1, unofficial]. Key fields include `cone_half_angle` (aperture half-angle in degrees), `initial_step` (initial gap step for cone sampling), `d_sigma` (cone sample separation multiplier), `r_sigma` (minimum circular cone section radius), `covered_distance` (maximum distance the cone covers), and `max_gaussian_packing` (enum specifying the number of Gaussian sections packed into the cone, e.g., `_1` or `_3`) [S1, unofficial].

### Algorithm Steps
1. Initialize the renderer by creating the rendering pass, generating the extinction coefficient volume, generating cone samples, and estimating the initial integration step size based on the volume diagonal [S1, unofficial].
2. Set shader uniforms by binding camera matrices, FOV tangent, aspect ratio, occlusion/shadow flags, step size, Phong shading flags, Blinn-Phong coefficients, and light source positions [S1, unofficial].
3. Dispatch the compute shader by clearing the output texture, binding the rendering shader and output image texture, and dispatching compute shader groups based on screen resolution or multi-scaling mode [S1, unofficial].

### Parameters and Formulas
The integration step size $m\_u\_step\_size$ is initialized from the volume scale $sv = (sv.x, sv.y, sv.z)$ as $m\_u\_step\_size = \frac{0.5}{\sqrt{3.0}} \sqrt{sv.x^2 + sv.y^2 + sv.z^2}$ [S1, unofficial]. For Cone Occlusion mode, `cone_half_angle` defaults to 20.0 degrees, `initial_step` defaults to $3.0 \times \sigma_0$ (where $\sigma_0$ is the base level Gaussian sigma from volume generation), `covered_distance` is set to $0.50 \times \text{volume diagonal}$, and `max_gaussian_packing` is `_3` [S1, unofficial]. For Cone Shadow mode, `cone_half_angle` defaults to 0.5 degrees, `covered_distance` is set to $0.75 \times \text{volume diagonal}$, and `max_gaussian_packing` is `_1` [S1, unofficial]. A pre-computed light cache texture with resolution $32 \times 32 \times 32$ stores shading coefficients [S1, unofficial].

### Edge Cases and Pitfalls
If the current volume texture is null, the initialization process fails and returns false [S1, unofficial].

## Background
The method is implemented in the `cppvolrend` project, a volume rendering application developed using C++ and GLSL [S1, unofficial]. It implements techniques from "Directional Ambient Occlusion and Shadows with Cone Tracing" (Schott et al., 2009) and "Parallel distributed, GPU-accelerated, advanced lighting calculations for large-scale volume visualization" (Shih et al., 2016) [S1, unofficial]. The implementation aims to replicate results from various volume rendering papers, including those on extinction-based shading and directional occlusion [S1, unofficial].
