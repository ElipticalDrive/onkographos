# Point Light Shading with Shadow Offset

Also called: Point Light Shading with Geometric Bias, Shadow Ray Offset Shading

## Overview
This method computes direct illumination from a point light at a surface intersection point, incorporating shadow testing with a geometric offset to prevent self-shadowing artifacts such as shadow acne [S1, unofficial]. It extends basic Lambert shading by introducing a bias term to the shadow ray origin, ensuring robust occlusion detection in ray-traced scenes [S1, unofficial].

## How it works
**Inputs:**
- Intersection point $P$ on the surface.
- Surface normal $N$ (normalized).
- Incoming camera ray direction $V$ (normalized, pointing towards the surface).
- Light position $L_{pos}$ (world space).
- Light radiance $L_{light}$.
- Material reflectance $f_r$.
- Shadow offset bias $\epsilon$.

**Outputs:**
- Reflected radiance $L_r$ at point $P$.

**Data Structures:**
- `Ray`: Struct containing origin $O$ and direction $D$.
- `Intersection`: Struct containing point $P$, normal $N$, and distance $t$.

**Parameters:**
- $\epsilon$: Geometric bias for shadow ray origin. Typical value: $10^{-9}$ [S1, unofficial].
- $f_r$: Diffuse material reflectance. Typical value: $1/\pi$ for ideal diffuse [S1, unofficial].

**Steps:**
1. **Compute Light Direction:** Calculate the vector from the intersection point to the light source: $\vec{L}_{dir} = L_{pos} - P$.
2. **Compute Distance:** Calculate the squared distance to the light: $d^2 = \|\vec{L}_{dir}\|^2$. If $d^2 \approx 0$, return zero radiance [G].
3. **Determine Shadow Ray Origin:** To prevent self-intersection, shift the shadow ray origin $O_{shadow}$ along the normal $N$. The direction of the shift depends on the dot product between the incoming ray direction $V$ and the normal $N$:
   $$ \text{sign} = \text{sign}(V \cdot N) $$
   $$ O_{shadow} = P + \epsilon \cdot \text{sign} \cdot N $$
   This ensures the ray starts slightly outside the surface, avoiding intersection with the surface it just hit [S1, unofficial].
4. **Trace Shadow Ray:** Create a shadow ray with origin $O_{shadow}$ and direction $\vec{L}_{dir} / \|\vec{L}_{dir}\|$. Trace this ray against the scene geometry.
5. **Determine Occlusion:** If the shadow ray intersects an object at a distance $t_{hit}$ such that $0 < t_{hit} < \|\vec{L}_{dir}\|$, the point is in shadow ($inShadow = true$). Otherwise, $inShadow = false$ [S1, unofficial].
6. **Compute Cosine Term:** Calculate the cosine of the angle between the normal and the light direction: $\cos\theta = \max(0, N \cdot (\vec{L}_{dir} / \|\vec{L}_{dir}\|))$ [S1, unofficial].
7. **Calculate Radiance:** Compute the final reflected radiance using the point light formula:
   $$ L_r = \text{clamp}\left( \frac{L_{light} \cdot f_r \cdot \cos\theta \cdot (1 - inShadow)}{d^2 \cdot 4\pi} \right) $$
   where $d = \|\vec{L}_{dir}\|$ [S1, unofficial].

**Pseudocode:**
```python
def point_light_shading_with_shadow_offset(P, N, V, L_pos, L_light, fr, epsilon):
    # 1. Compute light direction and distance
    L_dir = L_pos - P
    d_sq = dot(L_dir, L_dir)
    
    # Guard against zero distance
    if d_sq < 1e-12:
        return 0.0
    
    d = sqrt(d_sq)
    L_dir_norm = L_dir / d
    
    # 2. Determine shadow ray origin with offset
    # Sign of dot product between incoming ray (V) and normal (N)
    # Note: V is typically the direction from camera to surface, 
    # so V . N indicates if the surface is facing the camera.
    # The offset is applied along N.
    sign = 1.0 if dot(V, N) > 0.0 else -1.0
    O_shadow = P + epsilon * sign * N
    
    # 3. Trace shadow ray
    shadow_ray = Ray(origin=O_shadow, direction=L_dir_norm)
    hit = trace_scene(shadow_ray, min_t=epsilon, max_t=d)
    
    # 4. Determine occlusion
    in_shadow = hit is not None
    
    # 5. Compute cosine term
    cos_theta = max(0.0, dot(N, L_dir_norm))
    
    # 6. Calculate radiance
    # Formula: L_r = clamp(L * fr * cosθ * (1 - inShadow) / (d² * 4π))
    numerator = L_light * fr * cos_theta * (1.0 if not in_shadow else 0.0)
    denominator = d_sq * 4.0 * 3.14159265358979323846
    
    if denominator == 0.0:
        return 0.0
        
    L_r = numerator / denominator
    
    # Clamp to valid range
    return max(0.0, min(1.0, L_r))
```

## Operating characteristics
- **Time Complexity:** $O(1)$ shading calculation plus the cost of one shadow ray trace per point light. The shadow ray trace complexity depends on the scene acceleration structure (e.g., $O(\log N)$ for BVH).
- **Memory Complexity:** $O(1)$ additional memory for local variables.
- **Strengths:** Simple to implement; effectively reduces shadow acne artifacts common in basic shadow ray implementations.
- **Limitations:** The fixed offset $\epsilon$ may cause "Peter Panning" (shadow detachment) if too large, or fail to prevent acne if too small. It does not account for soft shadows or penumbrae.
- **When to use:** Real-time rendering or offline rendering where point lights are used and shadow acne is a visible artifact.
- **When not to use:** When soft shadows are required, or when the offset causes noticeable visual artifacts due to large surface curvature or small feature sizes.

## Background
This method is a practical extension of basic shadow ray shading, commonly found in ray tracing implementations to handle the numerical precision issues of floating-point arithmetic when testing for self-intersection. The specific implementation details, including the formula and offset logic, are documented in the `VolumeSingleScattering` repository by WangYue [S1, unofficial].
