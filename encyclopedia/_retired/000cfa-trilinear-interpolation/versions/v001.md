# Stochastic Jittering

Also called: Jittering Sample Positions, Stochastic Noise, Stochastic Sampling

## Overview
Stochastic Jittering is a sampling technique in direct volume ray casting that replaces regularly spaced sample positions with random offsets within each segment to eliminate banding and "wood-grain" artifacts [S1, S2]. Unlike [Uniform Ray Sampling](1261-uniform-ray-sampling.md), which produces visible structural artifacts due to aliasing, Stochastic Jittering transforms these artifacts into high-frequency noise that is visually less noticeable [S1, S2]. It differs from [Monte Carlo Volume Rendering](2060-monte-carlo-volume-rendering.md) in that it typically applies jitter only to the sample positions along the ray (often uniformly distributed) rather than using complex importance sampling or stratification for the entire integral, though it is fundamentally a Monte Carlo approach [S2].

## How it works
**Inputs and Outputs:**
- Input: Ray origin ($ray\_orig$), ray direction ($ray\_dir$), entry point $t_0$ ($isect.t0$), step size ($step\_size$), sample index ($n$).
- Output: Sample position ($sample\_pos$).

**Data Structures:**
- `Noise`: A boolean flag to enable/disable the technique [S1].
- `MaxNoiseFactor`: A scalar controlling the maximum magnitude of the jitter [S1].
- `NoiseTexture`: A 2D texture of size `NoiseTextureSize` x `NoiseTextureSize` used to generate spatially coherent or screen-space jitter values [S1].

**Steps:**
1. Generate a random value $r$ uniformly distributed in $[0, 1]$ [S2]. In GPU implementations, this is often sampled from a noise texture using screen coordinates [S1, S3].
2. Calculate the sample position $t$ along the ray:
   $$ t = isect.t0 + step\_size \times (n + r) $$
   where $n$ is the integer sample index (0, 1, 2...) [S2].
3. Compute the 3D sample position:
   $$ sample\_pos = ray\_orig + t \times ray\_dir $$
   [S2].

**Parameters:**
- `MaxNoiseFactor`: Typical value 0.75 [S1]. This scales the random offset $r$. If applied as $r \times MaxNoiseFactor$, the offset is bounded. Note that standard stochastic sampling uses $r \in [0,1]$ directly [S2], while VTK implementations scale the noise factor [S1].
- `NoiseTextureSize`: Typical value 64 [S1]. Determines the resolution of the pre-generated noise texture [S1].

**Edge Cases and Pitfalls:**
- Without refinement, isosurface rendering errors are inevitable if the sample distance is not reduced; jittering only makes these artifacts less visible [S1].
- Replaces banding artifacts with noise. The noise can be reduced using quasi-Monte Carlo methods, but this is not implemented in the basic version [S2].
- Precision issues may arise if `step_size` is very small and `isect_t0` is large, potentially causing loss of precision in the addition `isect_t0 + step_size * (n + r)` [G].

## Subtopics

### Slice Artifact Reduction
A variant that combines jittering with a solidity check to reduce "wood grain" artifacts caused by visible slice boundaries [S3]. It jitters the ray start position along the view direction by adding `stepVector * texture(Noise, gl_FragCoord.xy / 256).r` [S3]. Inside the raycasting loop, if the voxel value $V$ exceeds a threshold, it performs a solidity check: it moves back by half-step ($s = -stepVector \times 0.5$), samples $V$. If $V > Threshold$, it moves forward by quarter-step ($s *= 0.5$), else backward ($s *= -0.5$), and samples again. Lighting proceeds only if the re-sampled $V$ is still $> Threshold$ [S3]. This method is chosen when high-frequency slice boundaries are visible despite adequate sample density [S3].

### Temporal Filtering and Jittering
A technique that smooths out noise and improves perceived volume resolution without extra raymarching steps [S4]. It applies depth jittering each frame using a sub-voxel offset derived from a pseudo-random sequence (such as blue noise or Halton sequence) to offset ray positions [S4]. A temporal reprojection compute pass then blends the current frame’s 3D texture with the previous frame's 3D texture using camera motion vectors [S4]. This is chosen for real-time applications where spatial resolution is limited but temporal coherence can be exploited [S4].

## Operating characteristics
- **Time Complexity:** $O(1)$ per sample for the jitter calculation, same as uniform sampling [S2].
- **Memory Complexity:** $O(N^2)$ for the noise texture if pre-generated, where $N$ is `NoiseTextureSize` [S1].
- **Measured Performance:** No specific hardware benchmarks provided in sources [S1, S2].
- **Scaling:** Performance is independent of resolution, but visual quality improves with higher `NoiseTextureSize` or better random sequences [S1, S2].
- **Strengths:** Eliminates banding artifacts; simple to implement; visually superior to uniform sampling for coarse steps [S1, S2].
- **Limitations:** Introduces high-frequency noise; does not reduce isosurface errors without refinement; noise may be distracting in some contexts [S1, S2].
- **When to use:** When banding artifacts are visible due to coarse sampling or regular grid alignment [S2].
- **When not to use:** When strict quantitative accuracy is required, or when temporal stability is critical without temporal filtering [S2, S4].

## Background
Stochastic jittering was introduced as a technique to mitigate banding artifacts in volume rendering by adding controlled noise to ray starting points [S1]. It is implemented in the VTK library (`vtkGPUVolumeRayCastMapper2`) under the nomenclature "Noise" to maintain compatibility with the original class [S1]. The method is described as a Monte Carlo technique that samples at non-uniformly spaced locations [S2]. It is often used in conjunction with isosurface rendering refinement to hide errors when sample distances are large [S1].
