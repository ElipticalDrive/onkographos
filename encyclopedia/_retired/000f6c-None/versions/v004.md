# Sky Gradient

Also called: Aurora Rendering, Aurora curtains, Horizon-Zenith Gradient, Neon Sky, Sky gradient texture, Synthwave Sky Gradient, getSky

## Overview
Sky Gradient generates a background color for rays that do not intersect the primary volume, interpolating between a horizon color and a zenith color based on the ray's vertical direction component [S1, S3, S4, unofficial]. It differs from [Sky Radiance Model](3256-sky-radiance-model.md) by using simple linear or power-based interpolation rather than physical atmospheric scattering equations, and from [SkyboxRendering](2619-skyboxrendering.md) by lacking time-dependent sun/moon arcs or procedural starfields in its core definition [S1, S2, S3, unofficial].

## How it works
**Inputs and Outputs**
- Input: Ray direction vector $\mathbf{d}$ (typically normalized).
- Input: Horizon color $\mathbf{C}_{horizon}$ (RGB).
- Input: Zenith color $\mathbf{C}_{zenith}$ (RGB).
- Input: Optional transition parameters (bounds, power, glow intensity).
- Output: Background color $\mathbf{C}_{sky}$ (RGB).

**Data Structures**
No persistent data structures are required. The method is a pure function of the ray direction and uniform color parameters.

**Steps**
1.  **Normalize Direction**: Ensure the ray direction $\mathbf{d}$ is normalized. If the input is a point $\mathbf{p}$ relative to the camera, compute $\mathbf{d} = \text{normalize}(\mathbf{p})$ [S3, unofficial].
2.  **Compute Vertical Component**: Extract the vertical component $y = \mathbf{d}_y$ (the y-component of the normalized direction vector) [S1, S3, S4, unofficial].
3.  **Compute Interpolation Factor**: Calculate a factor $t$ that maps the vertical range to $[0, 1]$. Two common variations exist:
    -   *Linear Mapping*: $t = 0.5 \times (y + 1.0)$ [S3, unofficial]. This maps $y=-1$ (nadir) to $t=0$ and $y=1$ (zenith) to $t=1$.
    -   *Smoothstep Mapping*: $t = \text{smoothstep}(0.0, 0.7, y)$ [S1, unofficial]. This creates a smooth transition starting at $y=0$ and completing at $y=0.7$.
    -   *Clamped Linear*: $h = \text{clamp}(0.5 \times y + 0.5, 0.0, 1.0)$ [S4, unofficial].
4.  **Apply Power (Optional)**: Some implementations apply a power function to the factor to adjust the gradient curve. For example, use $h^{0.55}$ instead of $h$ [S4, unofficial].
5.  **Interpolate Colors**: Compute the base sky color using linear interpolation (mix):
    $$ \mathbf{C}_{base} = (1 - t) \mathbf{C}_{horizon} + t \mathbf{C}_{zenith} $$
    Or using the power-adjusted factor $h$:
    $$ \mathbf{C}_{base} = (1 - h^p) \mathbf{C}_{horizon} + h^p \mathbf{C}_{zenith} $$
    where $p$ is the mix power (e.g., 0.55) [S4, unofficial].
6.  **Add Ground Glow (Optional)**: Enhance the horizon with a glow effect. Compute the glow intensity based on the distance from the horizon:
    $$ \mathbf{C}_{glow} = \mathbf{C}_{horizon} \times I \times (1.0 - |y|)^g $$
    where $I$ is intensity (e.g., 0.4) and $g$ is the glow power (e.g., 6.0) [S4, unofficial].
7.  **Combine**: Add the glow to the base color:
    $$ \mathbf{C}_{sky} = \mathbf{C}_{base} + \mathbf{C}_{glow} $$
    [S4, unofficial].

**Pseudocode**
```python
def sky_gradient(direction: Vector3, horizon: Vector3, zenith: Vector3, 
                 use_smoothstep: bool = False, smoothstep_max: float = 0.7,
                 mix_power: float = 1.0, glow_intensity: float = 0.0, glow_power: float = 6.0) -> Vector3:
    """
    Computes sky gradient color based on ray direction.
    
    Args:
        direction: Normalized ray direction vector.
        horizon: RGB color at the horizon (y ~ 0 or -1 depending on mapping).
        zenith: RGB color at the zenith (y ~ 1).
        use_smoothstep: If True, use smoothstep transition; else linear.
        smoothstep_max: Upper bound for smoothstep if use_smoothstep is True.
        mix_power: Power applied to interpolation factor for curve adjustment.
        glow_intensity: Intensity of ground glow effect.
        glow_power: Power of ground glow falloff.
        
    Returns:
        RGB color vector.
    """
    # 1. Normalize direction (ensure input is normalized)
    d = normalize(direction)
    y = d.y
    
    # 2. Compute interpolation factor
    if use_smoothstep:
        # smoothstep(0.0, smoothstep_max, y)
        t = smoothstep(0.0, smoothstep_max, y)
    else:
        # Linear mapping: y in [-1, 1] -> t in [0, 1]
        t = 0.5 * (y + 1.0)
        # Clamp to [0, 1] to handle potential precision issues or non-normalized input
        t = clamp(t, 0.0, 1.0)
        
    # 3. Apply power for curve adjustment
    t_pow = pow(t, mix_power)
    
    # 4. Interpolate base color
    base_color = mix(horizon, zenith, t_pow)
    
    # 5. Add ground glow if intensity > 0
    if glow_intensity > 0.0:
        # Glow is strongest at horizon (y=0) and fades towards zenith/nadir
        # Using abs(y) to symmetrically fade from horizon
        glow_factor = pow(1.0 - abs(y), glow_power)
        glow_color = horizon * glow_intensity * glow_factor
        base_color = base_color + glow_color
        
    return base_color

def smoothstep(edge0: float, edge1: float, x: float) -> float:
    """Standard smoothstep function."""
    t = clamp((x - edge0) / (edge1 - edge0), 0.0, 1.0)
    return t * t * (3.0 - 2.0 * t)

def mix(a: Vector3, b: Vector3, t: float) -> Vector3:
    """Linear interpolation between vectors a and b."""
    return a * (1.0 - t) + b * t

def clamp(x: float, min_val: float, max_val: float) -> float:
    """Clamp value x between min_val and max_val."""
    if x < min_val: return min_val
    if x > max_val: return max_val
    return x
```

**Parameters**
-   **Horizon Color**: RGB vector. Example: `(0.80, 0.90, 1.0)` [S1, unofficial], `(0.55, 0.06, 0.32)` [S4, unofficial], `(255, 100, 80)` [S3, unofficial].
-   **Zenith Color**: RGB vector. Example: `(0.35, 0.60, 0.95)` [S1, unofficial], `(0.02, 0.01, 0.05)` [S4, unofficial], `(10, 20, 60)` [S3, unofficial].
-   **Smoothstep Bounds**: Transition range for $d.y$. Example: `(0.0, 0.7)` [S1, unofficial].
-   **Mix Power**: Exponent for interpolation factor. Example: `0.55` [S4, unofficial]. Default: `1.0`.
-   **Glow Intensity**: Multiplier for ground glow. Example: `0.4` [S4, unofficial]. Default: `0.0`.
-   **Glow Power**: Exponent for glow falloff. Example: `6.0` [S4, unofficial]. Default: `1.0`.

**Edge Cases and Pitfalls**
-   **Non-normalized Input**: If the direction vector is not normalized, the $y$-component will not accurately represent the vertical angle, leading to incorrect gradient placement. Always normalize [S1, S3, unofficial].
-   **Precision**: When $y$ is close to 0 or 1, floating-point precision errors might cause slight color shifts. Clamping $t$ to $[0, 1]$ mitigates this [S4, unofficial].
-   **Degenerate Input**: If horizon and zenith colors are identical, the result is constant regardless of direction.

## Operating characteristics
-   **Time Complexity**: $O(1)$ per ray. The computation involves a few arithmetic operations and trigonometric functions (if normalization is required).
-   **Memory Complexity**: $O(1)$. No additional memory is required beyond the input parameters.
-   **Performance**: Extremely fast. Suitable for real-time rendering on any hardware.
-   **Strengths**: Simple to implement, computationally inexpensive, easy to tune visually.
-   **Limitations**: Lacks physical accuracy (no scattering, no sun position), no temporal variation (static unless manually animated), no starfields or complex atmospheric effects.
-   **When to Use**: Simple backgrounds, stylized rendering, performance-critical applications, or as a base for more complex sky models.
-   **When Not to Use**: When physical accuracy is required, when dynamic sun/moon positions are needed, or when volumetric background effects are desired.

## Background
The Sky Gradient method is a common technique in computer graphics for generating simple sky backgrounds. It is often used in ray marching demos and voxel engines due to its simplicity and visual appeal. Variations include "Aurora Rendering" which adds sine-wave based aurora effects [S2, unofficial], and "Neon Sky" which uses specific color palettes and ground glow effects [S4, unofficial]. The technique is widely used in indie games and real-time rendering applications where performance is critical and physical accuracy is not the primary goal.
