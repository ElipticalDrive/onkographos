# Sparse Volume Rendering with Block Walking and Culling

Also called: Hardware Ray Tracing Sparse Volume Rendering

## Overview
A method to render sparse volumetric data using hardware ray tracing that accelerates traversal by storing adjacency information in BVH nodes to skip ray-tracing queries for adjacent blocks (Block Walking) and using density-based culling masks to skip irrelevant blocks (Block Culling) [S1, unofficial]. It builds on [Sparse Brickmap Volume Rendering](2978-sparse-brickmap-volume-rendering.md) by replacing the brick-based hierarchy with a two-level block/subblock structure optimized for hardware ray query acceleration [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** RGBA volume data (8 bits per channel, last component is density), user-specified density range for culling, rendering mode (first-hit, alpha=1 termination, or full traversal).
- **Output:** Rendered image or scalar traversal count.

**Data Structures:**
1.  **Subblock:** A dense 3D grid of voxels. Default size is $8 \times 8 \times 8$ voxels, but parametric [G]. Voxel data is RGBA 8-bit; no transfer function applied during preprocessing [S1, unofficial].
2.  **Block:** Contains indices of active Subblocks.
    -   **Index Storage:** Subblock addresses are stored as unsigned 8-bit integers. This limits the maximum number of subblocks per block to $6^3 = 216$ (since $6^3 \le 256$) [S1, unofficial].
    -   **Adjacency:** Stores information about adjacent nodes (blocks) to enable block walking [S1, unofficial].
    -   **Culling Mask:** A bitfield representing the density range of the block.
3.  **Acceleration Structure:** Built from Block AABBs. Blocks act as top-level instances [S1, unofficial].

**Parameters:**
-   **Quantization Divider ($q$):** Used to bin density ranges into culling mask bits. Calculated as $q = \frac{\text{max density}}{\text{max bits allowed}}$. For Vulkan (8-bit mask) and 8-bit density data (max 256), $q = 256 / 32 = 8$ [S1, unofficial]. Note: The source states "divide... by 32" implying 32 bits are used for annotation or a specific mapping, resulting in $q=8$ [S1, unofficial].

**Steps:**
1.  **Build Blocks and Subblocks:** Group voxels into uniform-sized subblocks. Group subblocks into blocks. Store indices of active subblocks in each block [S1, unofficial].
2.  **Compute Adjacency Information:** For each block, compute and store indices of neighboring blocks in the BVH node's corresponding field [S1, unofficial].
3.  **Compute Culling Masks:**
    -   For each block, compute min and max density of its voxels.
    -   Calculate quantized indices: $idx_{min} = \lfloor \min(\text{density}) / q \rfloor$, $idx_{max} = \lfloor \max(\text{density}) / q \rfloor$ [S1, unofficial].
    -   Create a bitfield mask with bits set between $idx_{min}$ and $idx_{max}$ [S1, unofficial].
    -   Pass this mask to the RT API [S1, unofficial].
4.  **Build Acceleration Structure:** Request an acceleration structure compatible with ray tracing from the API. Pass AABBs of blocks [S1, unofficial].
5.  **Ray Generation:** Launch a compute kernel. Pass runtime configuration (including culling mask) via push-constants [S1, unofficial].
6.  **Ray Traversal Loop:**
    1.  **First Hit:** Use hardware ray tracing query to find the first intersection of the ray against the blocks (closest hit AABB) [S1, unofficial].
    2.  **Block Processing:** Process the hit block immediately. Use two-level DDA to traverse the voxel data within the subblocks of the block [S1, unofficial].
    3.  **Block Walking (Subsequent Hits):** After finishing a block, calculate the parametric $t$ after Half-Disk Distance Approximation (HDDA).
        -   If $t$ is inside a neighboring block (checked via stored adjacency), start HDDA directly into the adjacent block without launching a new ray-tracing query [S1, unofficial].
        -   If no adjacent block exists or $t$ is not in a neighbor, launch a ray query to find the next closest block [S1, unofficial].
    4.  **Termination:** Repeat until exiting the volume, reaching alpha=1 (opaque), or first hit, depending on rendering mode [S1, unofficial].

**Pseudocode:**

    min_d = min(block.voxels)
    max_d = max(block.voxels)

    idx_max = floor(max_d / Q)
    mask = 0
    for i in range(idx_min, idx_max + 1):

## Operating characteristics
-   **Time Complexity:** Reduces overhead of repeated hardware ray-tracing queries by using block walking [S1, unofficial]. Performance scales better with data size compared to pure ray tracing [S1, unofficial].
-   **Memory Complexity:** Low memory overhead due to sparse block/subblock structure [S1, unofficial].
-   **Strengths:** Efficient traversal of sparse data; effective culling when users remove large parts of data [S1, unofficial].
-   **Limitations:** Unpredictable data shape and user-controlled filtering can reduce efficiency without acceleration [S1, unofficial]. API overhead from repeated spatial acceleration structure access is a pitfall [S1, unofficial].
-   **When to Use:** Interactive rendering of sparse volumetric data where hardware ray tracing is available [S1, unofficial].
-   **When Not to Use:** Dense volumes where block walking overhead may not justify benefits; scenes with highly unpredictable sparse regions without adjacency optimization [S1, unofficial].
