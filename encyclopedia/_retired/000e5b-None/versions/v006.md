# Boolean Voxel Meshing

Also called: Blocky Mesh, VoxelGrid to Mesh, VoxelGrid To Mesh Hull, VoxelGrid Mesh Hull Generation

## Overview
Boolean Voxel Meshing converts a 3D boolean voxel occupancy grid into an explicit triangular mesh representation [S2, S3, unofficial]. It solves the problem of visualizing discrete voxel data by generating geometry that preserves the exact blocky shape of the input grid, contrasting with interpolation-based methods like Marching Cubes which produce smooth surfaces [S4, unofficial]. Unlike [Voxel Face Mesh Generation](4212-voxel-face-mesh-generation.md), which may treat voxels as independent objects resulting in non-manifold geometry, Boolean Voxel Meshing detects shared faces at voxel boundaries to produce a watertight manifold where vertices are shared between adjacent voxels [S7, G, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D boolean occupancy grid (voxel field) representing occupied (`true`) and empty (`false`) space [S1, S3, unofficial].
*   **Output:** A triangular mesh consisting of vertex positions and triangle indices [S1, S2, unofficial].

**Data Structures:**
The voxel grid is typically stored as a 3D array of booleans. For implementation, this can be a flattened 1D array accessed via coordinate mapping [S1, unofficial].
*   **Voxel Field:** `bool data[Dx * Dy * Dz]` accessed via `at(x, y, z)` [S1, unofficial].
*   **Vertex Buffer:** A list of 3D coordinates (e.g., `std::vector<std::array<float, 3>>`) [S1, unofficial].
*   **Index Buffer:** A list of integer indices defining triangles (e.g., `std::vector<std::array<unsigned int, 3>>`) [S1, unofficial].

**Algorithm Steps:**
1.  **Padding:** Pad the input occupancy grid with a constant empty boundary (1 voxel thick) on all sides to simplify boundary checks [S2, S5, unofficial]. Let the padded grid dimensions be $(N_x+2, N_y+2, N_z+2)$ [S2, unofficial].
2.  **Boundary Detection:** Identify exposed faces by comparing each voxel with its neighbors. A face is exposed if the current voxel is occupied and the neighbor is empty or out of bounds [S1, unofficial].
    *   For each axis direction (X, Y, Z), compute two boolean masks: one for the "positive" face (current occupied, neighbor empty) and one for the "negative" face (current empty, neighbor occupied) [S2, unofficial].
    *   Example for X-axis: $F_{x+} = (occ[x, y, z] \land \neg occ[x+1, y, z])$ [S2, unofficial].
3.  **Vertex Generation:**
    *   **Method A (Naive/Per-Voxel):** For every occupied voxel, generate 8 unique vertices representing the cube corners. This results in duplicate vertices at shared corners [S1, unofficial].
    *   **Method B (Shared/Manifold):** Generate a vertex grid of size $(N_x+1, N_y+1, N_z+1)$. A vertex exists at grid point $(i, j, k)$ if it is part of any exposed face [S2, unofficial]. Map these boolean flags to unique vertex indices [S2, unofficial].
    *   **Coordinate Calculation:** Convert grid indices to world space. If $s$ is the voxel size (grid step) and $(x_c, y_c, z_c)$ is the voxel center or corner base:
        $$v_x = x_{coord} + \frac{s}{2} \cdot ((v \ \& \ 4) ? 1 : -1)$$
        $$v_y = y_{coord} + \frac{s}{2} \cdot ((v \ \& \ 2) ? 1 : -1)$$
        $$v_z = z_{coord} + \frac{s}{2} \cdot ((v \ \& \ 1) ? 1 : -1)$$
        where $v \in [0,7]$ is a bit mask for the corner offset relative to the voxel center [S3, unofficial].
4.  **Face/Index Generation:**
    *   For each exposed face identified in Step 2, generate two triangles (a quad).
    *   If using Method A (Naive), use hardcoded local indices 0-7 for the 8 corners of the current voxel [S1, unofficial]. Note: This produces 12 triangles per voxel if no culling is applied [S1, unofficial].
    *   If using Method B (Shared), use the global vertex indices mapped in Step 3. For example, a left-facing face in the X-dimension uses vertices $[v_{idx}(x,y,z), v_{idx}(x,y,z+1), v_{idx}(x,y+1,z+1), v_{idx}(x,y+1,z)]$ [S2, unofficial].
    *   Ensure consistent winding order (e.g., counter-clockwise) for correct back-face culling [S2, S7, unofficial].
5.  **Post-Processing (Optional):**
    *   **T-Junction Removal:** Consolidate vertices of unconnected lips to remove T-junctions, which can cause visible discontinuities and prevent smoothing algorithms like Catmull-Clark [S7, unofficial].
    *   **Directional Decomposition:** Optionally split the mesh into six directional planes based on face normals (+X, -X, +Y, -Y, +Z, -Z) [S6, unofficial].

**Pseudocode (Shared Vertex Approach):**

```python
def boolean_voxel_meshing(occ: np.ndarray, voxel_size: float, origin: np.ndarray) -> tuple:
    """
    occ: 3D numpy array of booleans (occupied voxels).
    voxel_size: size of one voxel edge.
    origin: world position of the first voxel corner (0,0,0).
    Returns: (vertices, faces)
    """
    # 1. Pad the occupancy grid with 1 layer of False
    padded_occ = np.pad(occ, 1, mode='constant', constant_values=False)
    nx, ny, nz = padded_occ.shape
    
    # 2. Identify exposed faces
    # Faces perpendicular to X axis
    f_x_pos = padded_occ[:-1, 1:-1, 1:-1] & ~padded_occ[1:, 1:-1, 1:-1]
    f_x_neg = ~padded_occ[:-1, 1:-1, 1:-1] & padded_occ[1:, 1:-1, 1:-1]
    
    # Faces perpendicular to Y axis
    f_y_pos = padded_occ[1:-1, :-1, 1:-1] & ~padded_occ[1:-1, 1:, 1:-1]
    f_y_neg = ~padded_occ[1:-1, :-1, 1:-1] & padded_occ[1:-1, 1:, 1:-1]
    
    # Faces perpendicular to Z axis
    f_z_pos = padded_occ[1:-1, 1:-1, :-1] & ~padded_occ[1:-1, 1:-1, 1:]
    f_z_neg = ~padded_occ[1:-1, 1:-1, :-1] & padded_occ[1:-1, 1:-1, 1:]
    
    # 3. Generate Vertex Grid
    # A vertex exists at grid point (i,j,k) if it belongs to any exposed face
    # Grid dimensions are (nx, ny, nz) for vertices corresponding to padded_occ corners
    # Note: padded_occ has shape (nx, ny, nz). Vertices are at corners, so shape is (nx, ny, nz)
    # Actually, if occ is NxNyNz, padded is (Nx+2)(Ny+2)(Nz+2).
    # Vertices are at integer coordinates 0..Nx+1, 0..Ny+1, 0..Nz+1.
    
    v_exists = np.zeros((nx, ny, nz), dtype=bool)
    
    # Assign face contributions to vertex grid
    # f_x_pos is shape (nx-1, ny-2, nz-2) -> maps to vertices x:0..nx-2, y:1..ny-2, z:1..nz-2
    # This mapping is complex; simpler approach: iterate faces and mark vertices
    
    # Simplified: Create a boolean grid for vertices
    # Dimensions of vertex grid match the corners of the padded occupancy grid
    # padded_occ shape: (H, W, D). Vertices shape: (H, W, D) ? No.
    # If voxel at (i,j,k) has corners (i,j,k) to (i+1,j+1,k+1).
    # Padded occ indices 0..H-1. Vertices indices 0..H.
    
    # Let's use the explicit assignment from [S2, unofficial]
    # v shape: (nx, ny, nz) where nx=occ.shape[0]+2, etc.
    v = np.zeros((nx, ny, nz), dtype=bool)
    
    # f1 (X faces) shape: (nx-1, ny-2, nz-2)
    # Assign to v[:, :-1, :-1], v[:, :-1, 1:], v[:, 1:, :-1], v[:, 1:, 1:]
    v[:, :-1, :-1] |= f_x_pos
    v[:, :-1, 1:] |= f_x_pos
    v[:, 1:, :-1] |= f_x_pos
    v[:, 1:, 1:] |= f_x_pos
    
    v[:, :-1, :-1] |= f_x_neg
    v[:, :-1, 1:] |= f_x_neg
    v[:, 1:, :-1] |= f_x_neg
    v[:, 1:, 1:] |= f_x_neg
    
    # f2 (Y faces) shape: (nx-2, ny-1, nz-2)
    v[:-1, :, :-1] |= f_y_pos
    v[:-1, :, 1:] |= f_y_pos
    v[1:, :, :-1] |= f_y_pos
    v[1:, :, 1:] |= f_y_pos
    
    v[:-1, :, :-1] |= f_y_neg
    v[:-1, :, 1:] |= f_y_neg
    v[1:, :, :-1] |= f_y_neg
    v[1:, :, 1:] |= f_y_neg
    
    # f3 (Z faces) shape: (nx-2, ny-2, nz-1)
    v[:-1, :-1, :] |= f_z_pos
    v[:-1, 1:, :] |= f_z_pos
    v[1:, :-1, :] |= f_z_pos
    v[1:, 1:, :] |= f_z_pos
    
    v[:-1, :-1, :] |= f_z_neg
    v[:-1, 1:, :] |= f_z_neg
    v[1:, :-1, :] |= f_z_neg
    v[1:, 1:, :] |= f_z_neg
    
    # 4. Map vertices to indices and coordinates
    v_indices = np.full((nx, ny, nz), -1, dtype=int)
    v_coords = np.argwhere(v)
    
    # Normalize to [-0.5, 0.5] relative to voxel size, then scale and offset
    # v_coords are integer grid indices
    # World pos = origin + (coord - 0.5 * count) * size ? 
    # [S2, unofficial] says: v_x = v_x/nx - 0.5. This normalizes to [-0.5, 0.5] range of the grid.
    
    vertices = []
    for idx, (x, y, z) in enumerate(v_coords):
        # Normalize to [-0.5, 0.5]
        nx_v = x / (nx - 1) - 0.5
        ny_v = y / (ny - 1) - 0.5
        nz_v = z / (nz - 1) - 0.5
        
        # Scale and translate
        wx = origin[0] + nx_v * voxel_size * (nx - 1) # Approximation based on [S2, unofficial]
        wy = origin[1] + ny_v * voxel_size * (ny - 1)
        wz = origin[2] + nz_v * voxel_size * (nz - 1)
        
        v_indices[x, y, z] = idx
        vertices.append([wx, wy, wz])
        
    vertices = np.array(vertices)
    
    # 5. Generate Faces
    faces = []
    
    # Helper to get face indices
    def get_face_indices(face_mask, v_grid_indices, axis, direction):
        # face_mask is boolean array of exposed faces
        coords = np.argwhere(face_mask)
        local_faces = []
        for x, y, z in coords:
            # Determine the 4 corner vertex indices in the global v_indices grid
            # This depends on axis and direction (positive/negative)
            # Example for X-positive face at (x,y,z) in padded_occ:
            # Corners in vertex grid: (x,y,z), (x,y,z+1), (x,y+1,z+1), (x,y+1,z)
            # Note: face_mask indices correspond to the voxel, vertex indices correspond to corners
            
            # Mapping from face coordinate (x,y,z) to vertex grid coordinates:
            # X-face at x: vertices x and x+1? 
            # In [S2, unofficial], f1_r (X+) uses v_idx[x,y,z] etc.
            
            vx, vy, vz = x, y, z
            
            if axis == 0: # X
                if direction == 'pos':
                    # Face at x (right side of voxel x)
                    # Vertices: (x, y, z), (x, y, z+1), (x, y+1, z+1), (x, y+1, z)
                    # Wait, [S2, unofficial] says: f1_r uses v_idx[x,y,z]...
                    # Let's stick to the explicit quad definitions in [S2, unofficial]
                    quad = [
                        v_grid_indices[x, y, z],
                        v_grid_indices[x, y, z+1],
                        v_grid_indices[x, y+1, z+1],
                        v_grid_indices[x, y+1, z]
                    ]
                else: # neg
                    quad = [
                        v_grid_indices[x+1, y, z],
                        v_grid_indices[x+1, y+1, z],
                        v_grid_indices[x+1, y+1, z+1],
                        v_grid_indices[x+1, y, z+1]
                    ]
            elif axis == 1: # Y
                if direction == 'pos':
                    quad = [
                        v_grid_indices[x, y, z],
                        v_grid_indices[x+1, y, z],
                        v_grid_indices[x+1, y, z+1],
                        v_grid_indices[x, y, z+1]
                    ]
                else:
                    quad = [
                        v_grid_indices[x, y+1, z],
                        v_grid_indices[x, y+1, z+1],
                        v_grid_indices[x+1, y+1, z+1],
                        v_grid_indices[x+1, y+1, z]
                    ]
            else: # Z
                if direction == 'pos':
                    quad = [
                        v_grid_indices[x, y, z],
                        v_grid_indices[x+1, y, z],
                        v_grid_indices[x+1, y+1, z],
                        v_grid_indices[x, y+1, z]
                    ]
                else:
                    quad = [
                        v_grid_indices[x, y, z+1],
                        v_grid_indices[x, y+1, z+1],
                        v_grid_indices[x+1, y+1, z+1],
                        v_grid_indices[x+1, y, z+1]
                    ]
            
            # Filter out invalid vertices (should not happen if logic is correct)
            if all(v != -1 for v in quad):
                # Two triangles per quad
                local_faces.append([quad[0], quad[1], quad[2]])
                local_faces.append([quad[0], quad[2], quad[3]])
        return local_faces

    # Note: The indices in [S2, unofficial] for face masks correspond to the voxel coordinates.
    # The vertex grid indices correspond to the corners.
    # The mapping in [S2, unofficial] is:
    # f1_l (X-): v_idx[x,y,z], v_idx[x,y+1,z], v_idx[x,y+1,z+1], v_idx[x,y,z+1]
    # This implies the face at voxel x (left side) uses vertex column x.
    
    # Re-implementing strictly from [S2, unofficial] assignments:
    
    # f1_l
    faces_1_l = get_face_indices(f_x_neg, v_indices, 0, 'neg') # Adjusted logic for neg
    # f1_r
    faces_1_r = get_face_indices(f_x_pos, v_indices, 0, 'pos')
    
    # f2_l
    faces_2_l = get_face_indices(f_y_neg, v_indices, 1, 'neg')
    # f2_r
    faces_2_r = get_face_indices(f_y_pos, v_indices, 1, 'pos')
    
    # f3_l
    faces_3_l = get_face_indices(f_z_neg, v_indices, 2, 'neg')
    # f3_r
    faces_3_r = get_face_indices(f_z_pos, v_indices, 2, 'pos')
    
    all_faces = np.concatenate([faces_1_l, faces_1_r, faces_2_l, faces_2_r, faces_3_l, faces_3_r], axis=0)
    
    return vertices, all_faces
```

**Parameters:**
*   `dWidth` / `voxel_size`: Scaling factor to convert grid coordinates to world space [S1, S3, unofficial]. Typical value: 1.0 or 0.2 [S3, unofficial].
*   `Fake Shadow`: Boolean flag to add a fake shadow visualization [S6, unofficial]. Default: false.
*   `Light Direction`: Fixed vector for fake shadow, e.g., `(-0.495633, 0.142501, 0.856762)` [S6, unofficial].
*   `color`: RGBA array for mesh coloring [S7, unofficial].

**Edge Cases and Pitfalls:**
*   **Redundant Geometry:** The naive approach of drawing 12 triangles per voxel without culling results in significant redundancy for internal faces [S1, unofficial].
*   **T-Junctions:** Shared faces must be culled and vertices merged; otherwise, T-junctions cause visible discontinuities and prevent smoothing [S7, unofficial].
*   **Non-Watertight:** If culling is incomplete, the mesh may not be watertight, breaking volume-preserving algorithms [S1, unofficial].
*   **Hardcoded Indices:** Cube faces are often hardcoded, requiring manual indexing for all 12 triangles if culling is not implemented [S3, unofficial].

## Subtopics

### [Voxel Occupancy Boundary Detection](1011-voxel-occupancy-boundary-detection.md)
Identifies voxels within a 3D occupancy grid that lie on the interface between occupied and unoccupied space. It serves as the geometric definition step in Boolean Voxel Meshing, converting a binary volume into a set of boundary markers that subsequent geometry generation stages use to construct triangular meshes [Parent]. It differs from [Octree Traversal for Surface Extraction](2113-octree-traversal-for-surface-extraction.md) by operating on a fixed-resolution grid rather than a hierarchical structure, and from [Greedy Triangle Meshing](15263-greedy-triangle-meshing.md) by producing explicit voxel-level boundary flags rather than directly assembling triangles.

### [Octree Traversal for Surface Extraction](2113-octree-traversal-for-surface-extraction.md)
Extracts a triangular mesh from a boolean voxel occupancy grid by recursively traversing an octree structure and generating geometry for leaf nodes. It differs from interpolation-based methods like Marching Cubes by outputting axis-aligned cube meshes directly from octree leaves, resulting in simpler but blocky geometry unless voxel resolution is high. It builds on [Boolean Voxel Meshing](971-boolean-voxel-meshing.md) by handling hierarchical data structures rather than flat grids.

### [VoxelGrid Mesh Generation](2714-voxelgrid-mesh-generation.md)
Constructs a combined triangle mesh from a sparse set of voxels within a `VoxelGrid` by instantiating a base cell geometry for each selected voxel and transforming it into world space. It solves the problem of converting a boolean voxel occupancy grid or a filtered subset of voxels into an explicit triangular mesh representation. Unlike [Boolean Voxel Meshing](971-boolean-voxel-meshing.md), which detects shared faces at voxel boundaries to produce a watertight manifold, this method treats each voxel as an independent object, resulting in a non-manifold mesh where vertices are not shared between adjacent voxels [G]. This approach is distinct from [Voxel Grid to Triangle Mesh Conversion](6291-voxel-grid-to-triangle-mesh-conversion.md) and [Blocky Surface Extraction](6418-blocky-surface-extraction.md) in its explicit duplication of geometry per voxel rather than merging boundary surfaces [G].

### [Voxel Grid to Triangle Mesh Conversion](6291-voxel-grid-to-triangle-mesh-conversion.md)
Extracts a watertight triangular mesh that represents the exact volume of a boolean voxel occupancy grid. It solves the problem of preserving the discrete geometry of the voxel grid without the interpolation artifacts of marching cubes, ensuring that every edge in the resulting mesh connects to exactly two faces. Unlike [Blocky Surface Extraction](6418-blocky-surface-extraction.md) which may produce non-watertight or simplified outputs, this method explicitly generates triangles for every exposed face of surface voxels, guaranteeing volume preservation at the cost of higher triangle counts.

### [Blocky Surface Extraction](6418-blocky-surface-extraction.md)
Generates a voxel-aligned triangle mesh by iterating over voxels inside the isosurface and adding faces to the exterior boundary where adjacent voxels are outside the shape.

### [VoxelBodyMeshing](6947-voxelbodymeshing.md)
Is a blocky surface extraction method that converts a boolean voxel occupancy grid into a triangular mesh by processing sub-chunks of a `VoxelBody`. It builds on [Boolean Voxel Meshing](971-boolean-voxel-meshing.md) by handling the meshing of individual chunks in a multi-threaded worker loop, supporting both hard-edged (face-merging) and smooth (Marching Cubes) modes. It is distinct from sibling methods by its specific integration with the `VoxelEngine` architecture, using a thread-local `MeshGrid` and `MeshBuilder` to output `ChunkMeshData` parts that are transformed into body-local coordinates to allow shared model matrices.

### [Greedy Triangle Meshing](15263-greedy-triangle-meshing.md)
A voxel mesher that generates optimized triangle meshes from voxel data, specifically designed for BabylonJS integration.

### Voxels Grid to Compressed Mesh Conversion
Converts a voxel grid into a compressed mesh representation using a Marching Cubes-like approach, sharing vertices and faces across adjacent voxels to reduce redundancy [S8, unofficial]. It iterates through all voxels, skipping empty ones, and calls specific face generation functions (`AddFacesVertexXY`, etc.) for occupied voxels. It uses `std::unordered_map` for vertex marking and `std::array<std::vector<bool>, 3>` for face marking to track added geometry [S8, unofficial].

### Surface Nets Mesh Generation
Generates a smooth triangle mesh from a binary density field using the Surface Nets algorithm, producing fewer vertices than voxel-based methods [S4, unofficial]. It calls `SurfaceNets::GenerateMesh` with an iso-value of 0.5 and translates vertices to world space [S4, unofficial]. It produces smoother meshes with fewer vertices compared to the blocky voxel-based mesh generation [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is visited once to check neighbors and generate faces [S1, S2, unofficial].
*   **Memory Complexity:** $O(N)$ for the voxel grid and $O(F)$ for the output mesh, where $F$ is the number of exposed faces. In the worst case (checkerboard pattern), $F \propto N$.
*   **Performance:** The naive approach (no culling) generates 12 triangles per voxel, leading to high triangle counts and redundant geometry [S1, unofficial]. With culling, the triangle count is proportional to the surface area of the shape.
*   **Strengths:** Exact preservation of voxel geometry; simple implementation; fast execution for dense grids; produces watertight meshes if culling is correct [S1, S7, unofficial].
*   **Limitations:** Blocky appearance; high triangle count for smooth approximations; T-junctions if not handled; not suitable for smooth surfaces [S4, S7, unofficial].
*   **When to Use:** When the blocky aesthetic is desired (e.g., Minecraft-style) or when exact volume preservation is required without interpolation artifacts [S4, S1, unofficial].
*   **When Not to Use:** When smooth surfaces are needed (use Marching Cubes or Surface Nets) [S4, unofficial].

## Background
Boolean Voxel Meshing is a fundamental technique in voxel-based graphics, often associated with games like Minecraft [S1, S4, unofficial]. It is used in various engines and tools for exporting voxelized geometry (e.g., OBJ export) [S3, unofficial], procedural generation of voxel worlds [S5, unofficial], and WebGL visualization [S7, unofficial]. The method has evolved from naive per-voxel rendering to optimized manifold generation with shared vertices and face culling [S1, S7, unofficial].
