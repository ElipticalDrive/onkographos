# Boolean Voxel Meshing

Also called: Blocky Mesh, Minecraft-like Mesh, VoxMeshHull, Voxel-Based Mesh Generation, VoxelGrid Mesh Hull Generation, VoxelGrid To Mesh Hull, VoxelGrid to Mesh, voxel-to-mesh

## Overview
Boolean Voxel Meshing converts a 3D boolean voxel occupancy grid into a triangular mesh by detecting faces and vertices at voxel boundaries [S1, S2, S3, unofficial]. It solves the problem of generating a watertight, manifold representation of a discrete binary volume, producing a "blocky" or Minecraft-like aesthetic [S3, unofficial]. It differs from [Voxel Face Mesh Generation](4212-voxel-face-mesh-generation.md) by explicitly computing shared vertex indices across adjacent voxels to merge coplanar faces into a single manifold, rather than emitting independent quads for every visible face [S1, unofficial]. It differs from [VoxelGrid Mesh Generation](2714-voxelgrid-mesh-generation.md) by sharing vertices between adjacent voxels to produce a manifold mesh, whereas the latter treats each voxel as an independent object resulting in a non-manifold mesh with duplicated geometry [S2714, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D boolean occupancy grid `occ` of dimensions $(N_x, N_y, N_z)$, where `occ[x][y][z]` is true if the voxel is occupied.
*   **Output:** A triangular mesh defined by a list of 3D vertex coordinates and a list of face indices (triplets of vertex indices).

**Data Structures:**
1.  **Occupancy Grid:** A 3D array of booleans. To simplify boundary checks, the grid is conceptually padded with a constant false boundary (empty space) on all sides.
2.  **Vertex Grid (`v`):** A 3D boolean array of shape $(N_x+1, N_y+1, N_z+1)$. Each entry `v[i][j][k]` indicates whether the grid vertex at integer coordinate $(i, j, k)$ is part of the mesh surface.
3.  **Face Masks:** Six boolean arrays representing the detected faces on the boundaries between voxels:
    *   $f1$ (X-axis faces): Shape $(N_x+1, N_y, N_z)$.
    *   $f2$ (Y-axis faces): Shape $(N_x, N_y+1, N_z)$.
    *   $f3$ (Z-axis faces): Shape $(N_x, N_y, N_z+1)$.
4.  **Vertex Index Map (`v_idx`):** A 3D integer array of shape $(N_x+1, N_y+1, N_z+1)$, initialized to -1. It maps valid vertex grid coordinates to unique indices in the output vertex list.

**Steps:**

1.  **Pad the Occupancy Grid:**
    Create a padded occupancy grid `occ_padded` of shape $(N_x+2, N_y+2, N_z+2)$ by padding the original `occ` with a constant boundary of `false` (empty) on all sides. This ensures that voxels on the outer edge of the original grid correctly detect boundaries against empty space [S1, unofficial].

2.  **Detect Boundary Faces:**
    Iterate through the interior of the padded grid to identify faces where an occupied voxel meets an empty neighbor. For each axis, compute the "right" (positive direction) and "left" (negative direction) facing faces using bitwise operations.
    
    *   **X-axis faces ($f1$):**
        $$f1\_r = occ\_padded[:-1, 1:-1, 1:-1] \ \& \ \sim occ\_padded[1:, 1:-1, 1:-1]$$
        $$f1\_l = \sim occ\_padded[:-1, 1:-1, 1:-1] \ \& \ occ\_padded[1:, 1:-1, 1:-1]$$
        $$f1 = f1\_r \ | \ f1\_l$$
        Shape of $f1$: $(N_x+1, N_y, N_z)$ [S1, unofficial].
        
    *   **Y-axis faces ($f2$):**
        $$f2\_r = occ\_padded[1:-1, :-1, 1:-1] \ \& \ \sim occ\_padded[1:-1, 1:, 1:-1]$$
        $$f2\_l = \sim occ\_padded[1:-1, :-1, 1:-1] \ \& \ occ\_padded[1:-1, 1:, 1:-1]$$
        $$f2 = f2\_r \ | \ f2\_l$$
        Shape of $f2$: $(N_x, N_y+1, N_z)$ [S1, unofficial].
        
    *   **Z-axis faces ($f3$):**
        $$f3\_r = occ\_padded[1:-1, 1:-1, :-1] \ \& \ \sim occ\_padded[1:-1, 1:-1, 1:]$$
        $$f3\_l = \sim occ\_padded[1:-1, 1:-1, :-1] \ \& \ occ\_padded[1:-1, 1:-1, 1:]$$
        $$f3 = f3\_r \ | \ f3\_l$$
        Shape of $f3$: $(N_x, N_y, N_z+1)$ [S1, unofficial].

3.  **Mark Surface Vertices:**
    Initialize a vertex grid `v` of shape $(N_x+1, N_y+1, N_z+1)$ with all `False`. Assign the detected faces to the corresponding corners of the vertex grid.
    
    *   For $f1$ (X-boundaries):
        $$v[:, :-1, :-1] \ |= \ f1$$
        $$v[:, :-1, 1:] \ |= \ f1$$
        $$v[:, 1:, :-1] \ |= \ f1$$
        $$v[:, 1:, 1:] \ |= \ f1$$
        
    *   For $f2$ (Y-boundaries):
        $$v[:-1, :, :-1] \ |= \ f2$$
        $$v[:-1, :, 1:] \ |= \ f2$$
        $$v[1:, :, :-1] \ |= \ f2$$
        $$v[1:, :, 1:] \ |= \ f2$$
        
    *   For $f3$ (Z-boundaries):
        $$v[:-1, :-1, :] \ |= \ f3$$
        $$v[:-1, 1:, :] \ |= \ f3$$
        $$v[1:, :-1, :] \ |= \ f3$$
        $$v[1:, 1:, :] \ |= \ f3$$
        
    This step ensures that any vertex touching a detected surface face is marked as part of the mesh [S1, unofficial].

4.  **Map Vertex Indices:**
    Create an index map `v_idx` of shape $(N_x+1, N_y+1, N_z+1)$, initialized to -1. Assign a unique sequential index to each `True` entry in `v`.
    $$v\_idx[v] = \text{np.arange}(n\_vertices)$$
    where $n\_vertices$ is the count of `True` values in `v` [S1, unofficial].

5.  **Extract Vertex Coordinates:**
    Find the coordinates $(x, y, z)$ of all `True` entries in `v`. Normalize these integer coordinates to a unit cube range $[-0.5, 0.5]$ to facilitate scaling and translation later.
    $$v\_x = \frac{x}{N_x} - 0.5$$
    $$v\_y = \frac{y}{N_y} - 0.5$$
    $$v\_z = \frac{z}{N_z} - 0.5$$
    Stack these into a vertex array `vertices` of shape $(n\_vertices, 3)$ [S1, unofficial].

6.  **Construct Face Indices:**
    For each detected face mask ($f1\_l, f1\_r, f2\_l, f2\_r, f3\_l, f3\_r$), extract the coordinates of the face centers using `np.where`. Construct quadrilateral face indices by looking up the corresponding vertex indices in `v_idx`. The winding order must be consistent (e.g., counter-clockwise) to ensure correct culling.
    
    *   **f1_l (Left X-face):** $[v\_idx[x,y,z], v\_idx[x,y,z+1], v\_idx[x,y+1,z+1], v\_idx[x,y+1,z]]$
    *   **f1_r (Right X-face):** $[v\_idx[x,y,z], v\_idx[x,y+1,z], v\_idx[x,y+1,z+1], v\_idx[x,y,z+1]]$
    *   **f2_l (Left Y-face):** $[v\_idx[x,y,z], v\_idx[x+1,y,z], v\_idx[x+1,y,z+1], v\_idx[x,y,z+1]]$
    *   **f2_r (Right Y-face):** $[v\_idx[x,y,z], v\_idx[x,y,z+1], v\_idx[x+1,y,z+1], v\_idx[x+1,y,z]]$
    *   **f3_l (Left Z-face):** $[v\_idx[x,y,z], v\_idx[x,y+1,z], v\_idx[x+1,y+1,z], v\_idx[x+1,y,z]]$
    *   **f3_r (Right Z-face):** $[v\_idx[x,y,z], v\_idx[x+1,y,z], v\_idx[x+1,y+1,z], v\_idx[x,y+1,z]]$
    
    Concatenate all face index arrays into a single `faces` array [S1, unofficial].

7.  **Transform to World Space:**
    Apply the final transformation to the vertices. If `loc` is the world origin offset and `scale` is the voxel size (grid step $s$):
    $$vertices_{world} = loc + scale \times vertices$$
    Construct the final mesh object using the transformed vertices and the face indices [S1, unofficial].

**Pseudocode:**

```python
import numpy as np

def boolean_voxel_meshing(occ, loc=np.array([0.0, 0.0, 0.0]), scale=1.0):
    """
    Convert a boolean occupancy grid to a triangular mesh.
    
    Args:
        occ: numpy array of shape (Nx, Ny, Nz) of booleans.
        loc: 3D vector for world space translation.
        scale: float, voxel edge length.
        
    Returns:
        vertices: numpy array of shape (V, 3)
        faces: numpy array of shape (F, 3) (triangulated quads)
    """

    occ_padded = np.pad(occ, 1, constant_values=False)
    Nx, Ny, Nz = occ.shape
    
    # 2. Detect boundary faces
    # X-axis faces (f1)
    f1_r = occ_padded[:-1, 1:-1, 1:-1] & ~occ_padded[1:, 1:-1, 1:-1]
    f1_l = ~occ_padded[:-1, 1:-1, 1:-1] & occ_padded[1:, 1:-1, 1:-1]
    f1 = f1_r | f1_l
    
    # Y-axis faces (f2)
    f2_r = occ_padded[1:-1, :-1, 1:-1] & ~occ_padded[1:-1, 1:, 1:-1]
    f2_l = ~occ_padded[1:-1, :-1, 1:-1] & occ_padded[1:-1, 1:, 1:-1]
    f2 = f2_r | f2_l
    
    # Z-axis faces (f3)
    f3_r = occ_padded[1:-1, 1:-1, :-1] & ~occ_padded[1:-1, 1:-1, 1:]
    f3_l = ~occ_padded[1:-1, 1:-1, :-1] & occ_padded[1:-1, 1:-1, 1:]
    f3 = f3_r | f3_l
    
    # 3. Mark surface vertices
    v = np.zeros((Nx + 1, Ny + 1, Nz + 1), dtype=bool)
    
    # Assign f1 to v corners
    v[:, :-1, :-1] |= f1
    v[:, :-1, 1:] |= f1
    v[:, 1:, :-1] |= f1
    v[:, 1:, 1:] |= f1
    
    # Assign f2 to v corners
    v[:-1, :, :-1] |= f2
    v[:-1, :, 1:] |= f2
    v[1:, :, :-1] |= f2
    v[1:, :, 1:] |= f2
    
    # Assign f3 to v corners
    v[:-1, :-1, :] |= f3
    v[:-1, 1:, :] |= f3
    v[1:, :-1, :] |= f3
    v[1:, 1:, :] |= f3

    v_indices = np.where(v)
    n_vertices = len(v_indices[0])
    v_idx[v] = np.arange(n_vertices)

    vx, vy, vz = v_indices
    # Normalize to [-0.5, 0.5]
    vx_norm = vx / Nx - 0.5
    vy_norm = vy / Ny - 0.5
    vz_norm = vz / Nz - 0.5
    
    vertices = np.stack([vx_norm, vy_norm, vz_norm], axis=1)
    
    # 6. Construct face indices
    faces_list = []

    def get_face_indices(mask, axis_offset):
        # axis_offset: 0 for X, 1 for Y, 2 for Z
        # Returns list of quad indices [v0, v1, v2, v3]
        coords = np.where(mask)

        # This depends on whether it's the 'left' or 'right' face of the axis

        # Note: The exact indexing depends on the specific face orientation (l/r)
        # Below implements the logic from [S1, unofficial]

    # X-axis faces
    # f1_l: Left face of voxel at x. Face is at x+1 in vertex grid? 
    # According to [S1, unofficial]: f1_l corresponds to ~occ[:-1] & occ[1:]. 
    # The face is between x and x+1. The vertices are at x+1.
    # Let's use the explicit formulas from [S1, unofficial]
    
    # f1_l indices
    x_l, y_l, z_l = np.where(f1_l)
    # Vertices: [v_idx[x,y,z], v_idx[x,y,z+1], v_idx[x,y+1,z+1], v_idx[x,y+1,z]]

    ])
    faces_list.append(idx_f2_r)

    x, y, z = np.where(f3_l)
    # [v_idx[x,y,z], v_idx[x,y+1,z], v_idx[x+1,y+1,z], v_idx[x+1,y,z]]
    idx_f3_l = np.column_stack([
        v_idx[x, y, z],
        v_idx[x, y+1, z],
        v_idx[x+1, y+1, z],
        v_idx[x+1, y, z]
    ])
    faces_list.append(idx_f3_l)
    
    # f3_r
    x, y, z = np.where(f3_r)
    # [v_idx[x,y,z], v_idx[x+1,y,z], v_idx[x+1,y+1,z], v_idx[x,y+1,z]]

        v_idx[x, y, z],
        v_idx[x+1, y, z],
        v_idx[x+1, y+1, z],
        v_idx[x, y+1, z]
    ])
    faces_list.append(idx_f3_r)
    
    faces_quads = np.concatenate(faces_list, axis=0)
    
    # Triangulate quads (2 triangles per quad)
    # Triangle 1: 0, 1, 2
    # Triangle 2: 0, 2, 3
    faces = np.zeros((faces_quads.shape[0] * 2, 3), dtype=int)
    faces[0::2, 0] = faces_quads[:, 0]
    faces[0::2, 1] = faces_quads[:, 1]
    faces[0::2, 2] = faces_quads[:, 2]
    faces[1::2, 0] = faces_quads[:, 0]
    faces[1::2, 1] = faces_quads[:, 2]
    faces[1::2, 2] = faces_quads[:, 3]
    
    # 7. Transform to world space
    vertices = loc + scale * vertices
    
    return vertices, faces
```

**Parameters:**
*   `desiredStep` (float): Target voxel edge length. Used to compute optimal grid dimensions if generating from a continuous field. Typical UI value: 0.2f [S2, unofficial].
*   `Fake Shadow` (bool): If true, applies a fake shadow to the mesh for visualization. Default: false [S5, unofficial].
*   `Light Direction` (Vector3d): Fixed vector for fake shadow calculation: $(-0.495633, 0.142501, 0.856762)$ [S5, unofficial].
*   `Shadow Colors`: Highlight is `Color.White`, shadow is `Color.Black` [S5, unofficial].
*   `color` (RGBA array): Mesh color. Default: null [S6, unofficial].
*   `convertToTriangles` (bool): Convert output quads to triangles. Default: true [S6, unofficial].
*   `flatten` (bool): Flatten mesh structure. Default: true [S6, unofficial].

**Edge Cases and Pitfalls:**
*   **T-junctions:** If shared faces are not properly culled or vertices not consolidated, T-junctions can cause visible discontinuities in the mesh [S6, unofficial].
*   **Closed Mesh Requirement:** Many mesh transformation algorithms (e.g., Catmull-Clark smoothing) require a closed, watertight mesh. Boolean Voxel Meshing produces a manifold mesh, but holes in the input occupancy grid will result in non-closed meshes [S6, unofficial].
*   **Hardcoded Indices:** Cube faces are hardcoded, requiring manual indexing for all 12 triangles per cube if generating independent cubes rather than merged faces [S2, unofficial].
*   **Exception Handling:** If directional mesh generation fails (e.g., `VoxelGridToMeshByPlanes` throws), the component may throw a new exception with the message "Creating multiple meshes failed: [original exception]" [S5, unofficial].

## Subtopics

### [Voxel Occupancy Boundary Detection](1011-voxel-occupancy-boundary-detection.md)
Voxel Occupancy Boundary Detection identifies voxels in a 3D occupancy grid that lie on the interface between occupied and unoccupied space. It solves the problem of converting a discrete boolean volume into a set of boundary indicators required for surface extraction algorithms, such as Boolean Voxel Meshing [G]. It differs from [Octree Traversal for Surface Extraction](2113-octree-traversal-for-surface-extraction.md) by operating on a fixed-resolution grid rather than a hierarchical tree, and from [VoxelGrid Mesh Generation](2714-voxelgrid-mesh-generation.md) by outputting a boolean mask of boundary voxels rather than a mesh directly [G].

### [Octree Traversal for Surface Extraction](2113-octree-traversal-for-surface-extraction.md)
This method extracts a triangular mesh from a boolean voxel occupancy grid by recursively traversing an octree structure and generating geometry for leaf nodes. It differs from interpolation-based methods like Marching Cubes by outputting axis-aligned cube meshes directly from octree leaves, resulting in simpler but blocky geometry unless voxel resolution is high. It builds on [Boolean Voxel Meshing](971-boolean-voxel-meshing.md) by handling hierarchical data structures rather than flat grids.

### [VoxelGrid Mesh Generation](2714-voxelgrid-mesh-generation.md)
VoxelGrid Mesh Generation constructs a combined triangle mesh from a sparse set of voxels within a `VoxelGrid` by instantiating a base cell geometry for each selected voxel and transforming it into world space. It solves the problem of converting a boolean voxel occupancy grid or a filtered subset of voxels into an explicit triangular mesh representation. Unlike [Boolean Voxel Meshing](971-boolean-voxel-meshing.md), which detects shared faces at voxel boundaries to produce a watertight manifold, this method treats each voxel as an independent object, resulting in a non-manifold mesh where vertices are not shared between adjacent voxels. This approach is distinct from [Voxel Grid to Triangle Mesh Conversion](6291-voxel-grid-to-triangle-mesh-conversion.md) and [Blocky Surface Extraction](6418-blocky-surface-extraction.md) in its explicit duplication of geometry per voxel rather than merging boundary surfaces.

### [Voxel Grid to Triangle Mesh Conversion](6291-voxel-grid-to-triangle-mesh-conversion.md)
This method converts a discrete boolean voxel occupancy grid into a triangular mesh by instantiating a box primitive for every occupied voxel. Unlike smooth surface extraction techniques (e.g., [Marching Cubes](52-marching-cubes.md)) or boundary-aware methods (e.g., [Voxel Occupancy Boundary Detection](1011-voxel-occupancy-boundary-detection.md)), this approach preserves the exact blocky geometry of the input grid without attempting to smooth or merge adjacent faces. It is primarily used when the voxel structure itself is the desired output, such as for animation or when the input data is already voxelized and no underlying scalar field exists.

### [Blocky Surface Extraction](6418-blocky-surface-extraction.md)
Blocky Surface Extraction generates a voxel-aligned triangle mesh by iterating over voxels inside an isosurface and adding faces to the exterior boundary where adjacent voxels are outside the shape. It differs from [Boolean Voxel Meshing](971-boolean-voxel-meshing.md) by explicitly constructing quad faces from voxel corners rather than detecting boundary edges, resulting in a "blocky" aesthetic where faces are strictly axis-aligned.

### [VoxelBodyMeshing](6947-voxelbodymeshing.md)
VoxelBodyMeshing is a blocky surface extraction method that converts a boolean voxel occupancy grid into a triangular mesh by processing sub-chunks of a `VoxelBody`. It builds on [Boolean Voxel Meshing](971-boolean-voxel-meshing.md) by handling the meshing of individual chunks in a multi-threaded worker loop, supporting both hard-edged (face-merging) and smooth (Marching Cubes) modes. It is distinct from sibling methods by its specific integration with the `VoxelEngine` architecture, using a thread-local `MeshGrid` and `MeshBuilder` to output `ChunkMeshData` parts that are transformed into body-local coordinates to allow shared model matrices.

### Voxels Grid to Compressed Mesh Conversion
Converts a voxel grid into a compressed mesh representation using a Marching Cubes-like approach, sharing vertices and faces across adjacent voxels to reduce redundancy [S7, unofficial]. It clears the mesh and calculates maximum possible vertices and faces: $max\_vertices\_num = (VoxelsPerSide + 1)^3$, $max\_faces\_num = VoxelsPerSide^2 \times (VoxelsPerSide + 1)$ [S7, unofficial]. It initializes six predefined normals: $(0,0,1), (0,1,0), (1,0,0), (0,0,-1), (0,-1,0), (-1,0,0)$ [S7, unofficial]. It iterates through all voxels; if empty, skip. Otherwise, it calls `AddFacesVertexXY`, `AddFacesVertexXZ`, and `AddFacesVertexYZ` for both false and true orientations to generate faces and vertices [S7, unofficial]. It reserves and assigns white color $(1.0, 1.0, 1.0, 1.0)$ to all vertices [S7, unofficial]. Data structures include `vertices_marked`: a map from unique vertex ID to `(face index, Position)`, and `faces_marked`: an array of three vectors of booleans tracking added faces for each axis [S7, unofficial].

### Surface Nets Mesh Generation
Generates a smooth triangle mesh from a binary density field using the Surface Nets algorithm, producing fewer vertices than voxel-based methods [S3, unofficial]. It calls `SurfaceNets::GenerateMesh(d, 0.5)` passing the density field `d` and an iso-value of 0.5 [S3, unofficial]. It translates all mesh vertices to world space by adding the bounding box lower corner `bounding_box.lo` to each vertex [S3, unofficial]. Surface Nets produces smoother meshes with fewer vertices compared to the blocky voxel-based mesh generation [S3, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
The algorithm iterates over the voxel grid dimensions, performing constant-time bitwise operations per voxel to detect faces. Face detection is $O(N_x N_y N_z)$. Vertex marking and index mapping are also linear in the number of voxels. Constructing the face indices involves iterating over the detected faces, which is proportional to the surface area. Thus, time complexity is $O(V + F)$, where $V$ is the number of voxels and $F$ is the number of surface faces. Memory complexity is dominated by the vertex grid and index map, $O(V)$, and the output mesh, $O(F)$.

**Measured Performance:**
Specific performance metrics are not given in the sources. However, the method is noted to produce smaller meshes that render faster due to culling of shared faces [S6, unofficial].

**Scaling:**
The method scales linearly with the number of voxels. For very large grids, memory usage for the vertex grid $(N_x+1)(N_y+1)(N_z+1)$ can become significant.

**Strengths and Limitations:**
*   **Strengths:** Produces a watertight, manifold mesh. Efficiently merges coplanar faces. Simple to implement using bitwise operations.
*   **Limitations:** Results in a blocky, non-smooth aesthetic. Not suitable for smooth surfaces. Requires a closed mesh for certain transformations [S6, unofficial].

**When to use it and when not:**
Use when a blocky, voxel-aligned mesh is desired, such as for Minecraft-like aesthetics or when the input data is inherently discrete [S3, unofficial]. Do not use when smooth surfaces are required; use [Marching Cubes](52-marching-cubes.md) or [Surface Nets](6418-blocky-surface-extraction.md) instead.

## Background
Boolean Voxel Meshing originates from the need to convert discrete voxel data into polygonal meshes for rendering and physics. It is used in various contexts, including exporting voxelized geometry as OBJ files [S2, unofficial], generating Minecraft-like worlds [S3, unofficial], and WebGL mesh generation [S6, unofficial]. The technique is foundational for blocky surface extraction methods and is often implemented in voxel engines and geometry builders [S4, unofficial].
