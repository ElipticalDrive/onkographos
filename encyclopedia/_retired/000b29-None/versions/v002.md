# Sparsity and Beta Loss Regularization

Also called: Additional Regularization for Real Scenes, Beta Loss, Plenoxel Cauchy Loss, Plenoxel Sparsity and Beta Regularization

## Overview
This method applies auxiliary regularization losses to sparse voxel radiance fields to enforce sparsity and improve foreground-background separation during optimization [S1][S2, unofficial]. It complements the Total Variation (TV) regularization by adding a sparsity prior for forward-facing and 360° scenes, and a beta distribution regularizer for 360° scenes [S1][S2, unofficial]. Unlike TV regularization which enforces smoothness, these terms specifically target empty space reduction and transmittance boundary clarity [S1][S2, unofficial].

## How it works
### Inputs and Outputs
*   **Inputs**:
    *   $\mathcal{R}$: Set of training rays [S1][S2, unofficial].
    *   $\sigma(\mathbf{r}_i(t_k))$: Density (or opacity) of sample $k$ along ray $i$ [S1][S2, unofficial].
    *   $T_{FG}(\mathbf{r})$: Accumulated foreground transmittance for ray $\mathbf{r}$ [S1][S2, unofficial].
    *   $\lambda_s$: Sparsity loss weight [S2, unofficial].
    *   $\lambda_\beta$: Beta loss weight [S2, unofficial].
*   **Outputs**:
    *   Scalar loss values $\mathcal{L}_s$ and $\mathcal{L}_\beta$ to be added to the optimization objective [S1][S2, unofficial].

### Data Structures
*   **Voxel Grid**: Sparse representation of density $\sigma$ [S1][S2, unofficial].
*   **Ray Samples**: List of $(\mathbf{r}_i, t_k)$ pairs for active rays in the current minibatch [G].

### Steps
1.  **Identify Scene Type**: Determine if the current scene is forward-facing or 360° [S1][S2, unofficial].
2.  **Evaluate Sparsity Loss**: If the scene is forward-facing or 360°, iterate over all active rays $i$ and all samples $k$ along those rays in the minibatch [S1][S2, unofficial]. Retrieve $\sigma(\mathbf{r}_i(t_k))$ for each sample [S1][S2, unofficial]. Compute $\log(1 + 2\sigma(\mathbf{r}_i(t_k))^2)$ [S1][S2, unofficial]. Sum these values and multiply by $\lambda_s$ to obtain $\mathcal{L}_s$ [S1][S2, unofficial].
3.  **Evaluate Beta Loss**: If the scene is 360°, iterate over all training rays $\mathbf{r}$ in the minibatch [S1][S2, unofficial]. Compute the accumulated foreground transmittance $T_{FG}(\mathbf{r})$ using standard volume rendering accumulation over foreground components [G]. Compute $\log(T_{FG}(\mathbf{r})) + \log(1 - T_{FG}(\mathbf{r}))$ [S1][S2, unofficial]. Sum these values over all rays and multiply by $\lambda_\beta$ to obtain $\mathcal{L}_\beta$ [S1][S2, unofficial].
4.  **Combine Losses**: Add $\mathcal{L}_s$ and $\mathcal{L}_\beta$ to the reconstruction loss $\mathcal{L}_{recon}$ and TV loss $\mathcal{L}_{TV}$ as defined in the parent article [S1][S2, unofficial].

### Formulas
1.  **Sparsity Loss ($\mathcal{L}_s$)**:
    Applied to forward-facing and 360° scenes to encourage voxels to be empty [S1][S2, unofficial].
    $$
    \mathcal{L}_s = \lambda_s \sum_{i,k} \log \left( 1 + 2\sigma(\mathbf{r}_i(t_k))^2 \right)
    $$
    Where $\sigma(\mathbf{r}_i(t_k))$ denotes the density (or opacity) of sample $k$ along training ray $i$ [S1][S2, unofficial].
2.  **Beta Loss ($\mathcal{L}_\beta$)**:
    Applied to 360° scenes to promote clear foreground-background decomposition [S1][S2, unofficial].
    $$
    \mathcal{L}_\beta = \lambda_\beta \sum_{\mathbf{r}} \left( \log(T_{FG}(\mathbf{r})) + \log(1 - T_{FG}(\mathbf{r})) \right)
    $$
    Where $T_{FG}(\mathbf{r}) \in [0, 1]$ is the accumulated foreground transmittance of ray $\mathbf{r}$ [S1][S2, unofficial].

### Parameters
*   $\lambda_s$: Weight for sparsity loss [S2, unofficial].
*   $\lambda_\beta$: Weight for beta loss [S2, unofficial].
*   Typical values: Not given in the sources.

### Edge Cases and Pitfalls
*   **Log of Zero**: If $T_{FG}(\mathbf{r})$ is exactly 0 or 1, $\log(T_{FG})$ or $\log(1-T_{FG})$ becomes undefined [G]. A small epsilon ($\epsilon$) should be added to clamp the transmittance values, e.g., $\max(\epsilon, \min(1-\epsilon, T_{FG}(\mathbf{r})))$ [G].
*   **Scene Type Specificity**: These losses are only applied to real forward-facing and 360° scenes, not synthetic ones [S1][S2, unofficial].

## Operating characteristics
*   **Time Complexity**: $\mathcal{L}_s$ scales linearly with the number of samples per minibatch [G]. $\mathcal{L}_\beta$ scales linearly with the number of rays per minibatch [G].
*   **Memory Complexity**: No additional memory structures required beyond storing ray samples and transmittance values [G].
*   **Strengths**: Reduces memory usage by encouraging empty voxels [S1][S2, unofficial]. Improves visual quality in 360° scenes by separating foreground and background [S1][S2, unofficial].
*   **Limitations**: Only applicable to specific scene types [S1][S2, unofficial]. Requires careful tuning of $\lambda_s$ and $\lambda_\beta$ [G].
*   **When to use**: Use for real-world forward-facing and 360° scenes to save memory and improve decomposition [S1][S2, unofficial]. Do not use for synthetic scenes or static-dynamic factorization scenarios where different regularization is preferred [G].

## Background
Introduced in the Plenoxels paper (Fridovich-Keil et al., CVPR 2022) [S1][S2, unofficial]. The sparsity loss is based on the Cauchy loss from SNeRG [S1][S2, unofficial]. The beta loss follows Neural Volumes [S1][S2, unofficial]. The method was introduced to handle the challenges of sparse voxel optimization in real-world scenarios [S1][S2, unofficial].
