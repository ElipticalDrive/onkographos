# LevelSetHDDA

Also called: Hierarchical DDA for Level Sets, Hierarchical Digital Differential Analyzer for Level Set trees, LevelSet Hierarchical DDA

## Overview
LevelSetHDDA is a specialized Hierarchical Digital Differential Analyzer (HDDA) designed for static intersection testing of rays against level set trees, such as those used in OpenVDB [S1, S2, unofficial]. It recursively traverses the VDB tree hierarchy from a specified node level down to the leaf level (-1) to determine if a ray intersects the implicit surface defined by the level set [S1, S2, unofficial]. It sets itself apart from general volume HDDA methods by terminating at the voxel level (-1) rather than the leaf node level, ensuring precise intersection checks against the underlying scalar field values [S1, S2, unofficial]. It builds on [Implicit Surface and SDF Intersection](2795-implicit-surface-and-sdf-intersection.md).

## How it works
**Inputs and Outputs:**
*   **Input:** A ray $\mathbf{r}$, a Tester object `TesterT` that provides access to the ray, the tree structure, and intersection logic, and a template parameter `NodeLevel` indicating the current depth in the tree hierarchy.
*   **Output:** A boolean indicating whether an intersection was found.

**Data Structures:**
The method relies on the VDB tree structure defined by `TreeT`.
*   `ChainT`: Defined as `typename TreeT::RootNodeType::NodeChainType` [S1, S2, unofficial].
*   `NodeT`: Defined as `typename ChainT::template Get<NodeLevel>` [S1, S2, unofficial]. This represents the node type at the current recursion depth.
*   `math::DDA`: A Digital Differential Analyzer instance used to step through the grid. It is parameterized by the ray type and the total number of dimensions (typically 3) [S1, S2, unofficial].

**Algorithm Steps:**
The algorithm is implemented as a template struct `LevelSetHDDA<TreeT, int NodeLevel>` with two specializations: the general recursive case and the base case for voxels [S1, S2, unofficial].

1.  **General Case (`NodeLevel > -1`):**
    *   Initialize a `math::DDA` instance for the current `NodeT` using the ray from the tester [S1, S2, unofficial].
    *   Enter a loop that continues as long as `dda.step()` returns true [S1, S2, unofficial].
    *   Inside the loop, check if the current voxel coordinate `dda.voxel()` corresponds to an active node of type `NodeT` using `tester.template hasNode<NodeT>(dda.voxel())` [S1, S2, unofficial].
    *   If a node exists:
        *   Update the tester's search range to the current DDA time interval `[dda.time(), dda.next())` using `tester.setRange()` [S1, S2, unofficial].
        *   Recursively call `LevelSetHDDA<TreeT, NodeLevel-1>::test(tester)` [S1, S2, unofficial].
        *   If the recursive call returns true, propagate true immediately [S1, S2, unofficial].
    *   If no node exists or the recursive call returns false, continue to the next voxel by calling `dda.step()` [S1, S2, unofficial].
    *   If the loop completes without finding an intersection, return false [S1, S2, unofficial].

2.  **Base Case (`NodeLevel = -1`):**
    *   Initialize a `math::DDA` instance for voxels (dimension 0 in the DDA template, representing individual voxels) using the ray from the tester [S1, S2, unofficial].
    *   Initialize the tester with the starting time of the ray using `tester.init(dda.time())` [S1, S2, unofficial].
    *   Enter a loop that continues as long as `dda.step()` returns true [S1, S2, unofficial].
    *   Inside the loop, evaluate the intersection at the current voxel and time interval using `tester(dda.voxel(), dda.next())` [S1, S2, unofficial].
    *   If the tester returns true, return true immediately [S1, S2, unofficial].
    *   If the loop completes without finding an intersection, return false [S1, S2, unofficial].

**Pseudocode:**
```python
# Pseudocode representing the C++ template specialization logic
# Note: This is a conceptual translation of the recursive template structure.

def LevelSetHDDA_Test(TesterT, TreeT, NodeLevel):
    """
    Recursive HDDA test for Level Sets.
    TesterT: Object providing ray, hasNode, setRange, init, and call operators.
    TreeT: The VDB tree type.
    NodeLevel: Current node level in the hierarchy.
    """
    
    # Determine NodeT based on NodeLevel
    # In C++, this is resolved at compile time via template metaprogramming.
    # NodeT = ChainT.Get<NodeLevel>
    
    if NodeLevel == -1:
        # Base Case: Voxel Level
        # Initialize DDA for voxels (dimension 0)
        dda = MathDDA(TesterT.Ray(), Dimensions=0)
        
        # Initialize tester with start time
        TesterT.init(dda.time())
        
        while dda.step():
            # Test intersection at current voxel and time interval
            if TesterT(dda.voxel(), dda.next()):
                return True
                
        return False
        
    else:
        # Recursive Case: Internal Node Level
        # Initialize DDA for current NodeT
        # NodeT::TOTAL is typically 3 for 3D space
        dda = MathDDA(TesterT.Ray(), Dimensions=NodeT.TOTAL)
        
        while dda.step():
            # Check if there is a node of type NodeT at this voxel
            if TesterT.hasNode[NodeT](dda.voxel()):
                # Set the search range for the tester
                TesterT.setRange(dda.time(), dda.next())
                
                # Recurse to the next lower level
                if LevelSetHDDA_Test(TesterT, TreeT, NodeLevel - 1):
                    return True
                    
        return False
```

**Parameters:**
*   `TreeT`: The VDB tree type [S1, S2, unofficial].
*   `NodeLevel`: The current node level in the hierarchy being tested [S1, S2, unofficial].
*   `TesterT`: A template parameter defining the interface for testing nodes and voxels [S1, S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** The DDA stepping relies on floating-point arithmetic. Degenerate rays or very small features may require careful handling of epsilon values in the tester implementation [G].
*   **Empty Space:** The `hasNode` check efficiently skips empty space, but if the tree is sparse, the overhead of DDA stepping through empty regions should be considered [S1, S2, unofficial].
*   **Termination:** The recursion terminates strictly at `NodeLevel = -1`. Attempting to recurse below this level is undefined behavior in the provided implementation [S1, S2, unofficial].

## Subtopics

### VolumeHDDA
A similar hierarchical DDA method but for generic volumes. It differs by terminating at the leaf node level rather than the voxel level, making it suitable for volume rendering where leaf node values are sufficient. See [VolumeHDDA](3892-volumehdda.md).

### Kalra & Barr Implicit Surface Intersection
An earlier method for implicit surface intersection using hierarchical grids. It differs by using a different traversal strategy and refinement technique. See [Kalra & Barr Implicit Surface Intersection](1278-kalra-barr-implicit-surface-intersection.md).

## Operating characteristics
*   **Time Complexity:** Proportional to the number of nodes and voxels intersected by the ray. The hierarchical structure allows skipping large empty regions, providing significant speedup over linear voxel traversal [S1, S2, unofficial].
*   **Memory Complexity:** Minimal additional memory beyond the tree structure and the recursion stack. The depth of recursion is equal to the depth of the tree [S1, S2, unofficial].
*   **Strengths:** Efficient for sparse level set trees; precise intersection at the voxel level; integrates seamlessly with OpenVDB's tree structure [S1, S2, unofficial].
*   **Limitations:** Requires a compatible Tester interface; recursion depth is limited by tree depth; not suitable for dynamic trees without rebuilding the DDA state [S1, S2, unofficial].
*   **When to use:** When precise ray-level set intersection is required for level set volumes in OpenVDB [S1, S2, unofficial].
*   **When not to use:** When approximate intersection is sufficient, or when using a different tree structure not compatible with OpenVDB's node chain [S1, S2, unofficial].

## Background
LevelSetHDDA is part of the OpenVDB library, developed by DreamWorks Animation and later maintained by the Academy Software Foundation [S1, S2, unofficial]. It was introduced to provide efficient ray intersection capabilities for level set volumes, which are commonly used in visual effects for fluid simulation and surface reconstruction [S1, S2, unofficial]. The method leverages the hierarchical nature of VDB trees to accelerate the search process [S1, S2, unofficial].
