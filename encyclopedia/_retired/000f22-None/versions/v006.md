# Deferred Surface Splatting

Also called: EWA surface splatting with deferred shading, Finalization Shader, Lighting Pass, Point Cloud Splatting, Point cloud splatting to G-buffer, Surface Splatting Finalization Pass

## Overview
Deferred Surface Splatting is a rendering technique that converts unstructured point clouds into continuous, shaded surfaces by projecting points as splats into a deferred rendering pipeline [S2, unofficial]. It solves the problem of sparse dot cloud aliasing and transparency artifacts inherent in raw point rendering by assigning each point sample an extent drawn as a small oriented primitive (a splat) carrying a radially decreasing reconstruction kernel [S2, unofficial]. Unlike forward splatting methods that apply lighting during rasterization, this method decouples geometric projection and attribute accumulation from lighting calculation, allowing multiple light sources to be applied efficiently in screen space without re-projecting geometry [S1, S2, unofficial].

## How it works
The method operates in three distinct passes: a Depth Visibility Pass, an Attribute Blending Pass, and a Finalization (Lighting) Pass. It requires a G-buffer to store intermediate surface properties.

### Inputs and Outputs
*   **Input:** A set of point cloud samples, each defined by position $\mathbf{p}$, color $\mathbf{c}$, and optionally normal $\mathbf{n}$.
*   **Output:** A final image with continuous surface shading.
*   **G-Buffer Textures:**
    1.  **Depth:** `GL_DEPTH_COMPONENT32F` storing front-surface depth [S2, unofficial].
    2.  **Normal:** `GL_RGBA32F` storing view-space normals. The Alpha channel is allocated but unused [S2, unofficial].
    3.  **Color/Weight:** `GL_RGBA32F` storing $(\mathbf{c}_r, \mathbf{c}_g, \mathbf{c}_b, w)$, where $w$ is the accumulated weight [S2, unofficial].

### Data Structures and Uniforms
The implementation uses `std140` uniform blocks [S1, unofficial]:
*   **Camera:** `mat4 modelview_matrix`, `mat4 modelview_matrix_it`, `mat4 projection_matrix` [S1, unofficial].
*   **Raycast:** `mat4 projection_matrix_inv`, `vec4 viewport` [S1, unofficial].
*   **Parameter:** `vec3 material_color`, `float material_shininess`, `float radius_scale`, `float ewa_radius`, `float epsilon` [S1, unofficial].

Key parameters:
*   $\varepsilon$: Depth slab thickness, calculated as `_renderingParams->_epsilonMultiplier * _renderingParams->_pointSize` [S2, unofficial].
*   $r$: Particle radius (splat size) [S2, unofficial].

### Steps

1.  **Initialization:**
    *   Load and compile shaders with defines `SMOOTH` (1 if smooth shading, 0 if flat) and `MULTISAMPLING` (1 if enabled) [S1, unofficial].
    *   Initialize OpenGL state: Enable `GL_DEPTH_TEST` with `GL_LESS`. Enable vertex program point size. Set point sprite coordinate origin to `GL_LOWER_LEFT` [S2, unofficial].

2.  **Depth Visibility Pass:**
    *   Bind G-Buffer. Set color mask to false for RGB channels (write only depth) [S2, unofficial].
    *   Draw the scene using the depth shader (`splat.vert`, `splat_depth.frag`) [S2, unofficial].
    *   The vertex shader projects points to screen space. The fragment shader computes the analytic front-surface depth of a sphere impostor:
        $$z_{surface} = z_{center} - \sqrt{r^2 - x^2 - y^2}$$
        where $(x,y)$ are the fragment's local coordinates within the splat [S2, unofficial].
    *   The depth value written to the texture is $z_{write} = z_{surface} - \varepsilon$. This creates a thin depth slab around the visible surface [S2, unofficial].

3.  **Attribute Blending Pass:**
    *   Bind G-Buffer. Bind `_gDepthTex` to `GL_TEXTURE0` [S2, unofficial].
    *   Set color mask to true for all channels. Disable depth mask. Disable depth test. Enable blending with `GL_ONE, GL_ONE` (pure additive) [S2, unofficial].
    *   Draw the scene using the attribute shader (`splat.vert`, `splat_attributes.frag`) [S2, unofficial].
    *   For each fragment, fetch the depth $z_{depth}$ from `_gDepthTex` [S2, unofficial].
    *   Discard the fragment if $z_{frag} > z_{depth}$ (i.e., if the fragment is behind the $\varepsilon$ slab) [S2, unofficial].
    *   Calculate weights:
        $$w_{radial} = 1 - \frac{d}{r}$$
        $$w_{depth} = \frac{z_{surface} - z_{frag}}{\varepsilon}$$
        where $d$ is the distance from the fragment center to the splat center [S2, unofficial].
    *   Total weight $w = w_{radial} \cdot w_{depth}$ [S2, unofficial].
    *   Accumulate color and weight additively into the Color/Weight attachment:
        $$\mathbf{C}_{acc} += \mathbf{c} \cdot w$$
        $$W_{acc} += w$$
    *   Where neighboring splats overlap, their contributions are blended and normalized by the total accumulated weight to reconstruct a smooth, hole-free surface signal [S2, unofficial].

4.  **Finalization (Lighting) Pass:**
    *   Bind default framebuffer. Clear color buffer [S2, unofficial].
    *   Draw a full-screen quad using the finalization shader [S2, unofficial].
    *   The shader reads from `_gDepthTex`, `_gNormalTex`, and `_gColorTex` [S2, unofficial].
    *   Initialize accumulator `res` to `vec4(0.0)` [S1, unofficial].
    *   If `MULTISAMPLING` is defined, loop $i$ from 0 to 3, converting UVs to integer coordinates and fetching texels; otherwise, process the single texel at `texture_uv` [S1, unofficial].
    *   Inside the loop (or single pass):
        *   Fetch pixel $\mathbf{p}_{pix}$ from `_gColorTex` and normal $\mathbf{n}_{pix}$ from `_gNormalTex` [S1, unofficial].
        *   If $\mathbf{p}_{pix}.a > 0.0$:
            *   Reconstruct NDC position $\mathbf{p}_{ndc}$: $x,y$ from viewport and `gl_FragCoord`, $z$ from depth and `gl_DepthRange`, $w=1.0$ [S1, unofficial].
            *   Transform $\mathbf{p}_{ndc}$ to eye space $\mathbf{v}_{eye}$ using `projection_matrix_inv` and divide by $w$ [S1, unofficial].
            *   If `SMOOTH` is defined:
                *   Compute lighting result: $\mathbf{L} = \text{lighting}(\mathbf{n}_{pix}, \mathbf{v}_{eye}.xyz, \mathbf{p}_{pix}.rgb / \mathbf{p}_{pix}.a, \text{material\_shininess})$ [S1, unofficial].
                *   Add to res: `res += vec4(L, 1.0)` [S1, unofficial].
            *   If not `SMOOTH`:
                *   Add premultiplied color: `res += vec4(p_pix.rgb / p_pix.a, 1.0)` [S1, unofficial].
        *   If $\mathbf{p}_{pix}.a \le 0.0$:
            *   Add white: `res += vec4(1.0)` [S1, unofficial].
    *   After processing, if `MULTISAMPLING`, output `frag_color = sqrt(res / 4.0)`; otherwise `frag_color = sqrt(res)` [S1, unofficial].

### Pseudocode

```python
# Finalization Pass Fragment Shader Logic
# Inputs: texture_uv (vec2), g_depth_tex (sampler2D), g_normal_tex (sampler2D), g_color_tex (sampler2D)
# Uniforms: projection_matrix_inv (mat4), viewport (vec4), material_shininess (float), lighting_params

def finalization_pass(texture_uv):
    res = vec4(0.0)
    
    # Handle multisampling if defined
    if MULTISAMPLING:
        itexture_uv = textureSize(g_color_tex) * texture_uv
        for i in range(4):
            pixel = texelFetch(g_color_tex, ivec2(itexture_uv) + vec2(i % 2, i // 2))
            normal = texelFetch(g_normal_tex, ivec2(itexture_uv) + vec2(i % 2, i // 2))
            depth = texelFetch(g_depth_tex, ivec2(itexture_uv) + vec2(i % 2, i // 2))
            res += process_pixel(pixel, normal, depth)
        return sqrt(res / 4.0)
    else:
        pixel = texture(g_color_tex, texture_uv)
        normal = texture(g_normal_tex, texture_uv)
        depth = texture(g_depth_tex, texture_uv)
        return sqrt(process_pixel(pixel, normal, depth))

def process_pixel(pixel, normal, depth):
    if pixel.a > 0.0:
        # Reconstruct NDC position
        # Assuming viewport.x, viewport.y are origin, viewport.z, viewport.w are size
        ndc_x = (gl_FragCoord.x - viewport.x) / viewport.z * 2.0 - 1.0
        ndc_y = (gl_FragCoord.y - viewport.y) / viewport.w * 2.0 - 1.0
        ndc_z = 2.0 * depth.r - 1.0 # Assuming depth is normalized 0-1, adjust for gl_DepthRange if needed
        p_ndc = vec4(ndc_x, ndc_y, ndc_z, 1.0)
        
        # Transform to eye space
        v_eye = projection_matrix_inv * p_ndc
        v_eye.xyz /= v_eye.w
        
        if SMOOTH:
            # Normal is already in view space from G-buffer
            n_view = normalize(normal.rgb)
            # Lighting function depends on specific implementation (e.g., Phong)
            # lighting(n, v, albedo, shininess) -> vec3
            albedo = pixel.rgb / pixel.a
            light_result = lighting(n_view, v_eye.xyz, albedo, material_shininess)
            return vec4(light_result, 1.0)
        else:
            # Flat shading: just color
            albedo = pixel.rgb / pixel.a
            return vec4(albedo, 1.0)
    else:
        # Background
        return vec4(1.0)
```

### Edge Cases and Pitfalls
*   **Normal Buffer Format:** The implementation uses `GL_RGBA32F` for the normal buffer instead of `GL_RGB32F` due to hardware compatibility issues ("RGB doesn't work on my laptop"). The Alpha channel is allocated but not used for data [S2, unofficial].
*   **Raw Points Mode:** If `_renderingParams->_rawPoints` is true, the splatting pipeline is skipped. The scene is drawn directly to the screen using `GL_POINTS` with additive blending disabled and depth test enabled, using the same vertex shader to maintain consistent screen-space point sizing [S2, unofficial].
*   **Precision:** The depth slab offset $\varepsilon$ must be carefully chosen to avoid z-fighting or gaps between splats. Too small $\varepsilon$ causes holes; too large causes depth conflicts [S2, unofficial].

## Subtopics

### [Deferred Lighting Resolve](1401-deferred-lighting-resolve.md)
Deferred Lighting Resolve is the final shading pass in a deferred surface splatting pipeline. It reconstructs the final pixel color by applying a lighting model (ambient, diffuse, specular) to the weighted color and surface normals accumulated in the G-buffers during the splatting phase. It differs from forward rendering by decoupling the geometric projection (splatting) from the lighting calculation, allowing multiple light sources to be applied efficiently in screen space without re-projecting geometry [G].

### [Point-Based Rendering](2827-point-based-rendering.md)
Point-based rendering approximates an implicit or dense discrete surface using a set of nonpolygonal proxy geometry, typically points or billboards, rather than triangles. It solves the problem of rendering large, unstructured point clouds or dense meshes by rasterizing these proxies directly, avoiding the overhead of mesh generation and complex topology management. Unlike its sibling Deferred Surface Splatting, which focuses on deferred shading of splatted points, point-based rendering is a broader category that includes early procedural particle systems and modern GPU-accelerated splatting, often relying on distance adaptation to maintain frame rates.

### [Hardware EWA Splatting Pipeline](13219-hardware-ewa-splatting-pipeline.md)
The Hardware EWA Splatting Pipeline is a specialized GPU architecture designed to render Elliptical Weighted Average (EWA) splats in a single pass, addressing the inefficiencies of multi-pass software implementations on standard graphics hardware. It solves the problem of accurate attribute accumulation and normalization for point-based surfaces by introducing a frame buffer-sized surface reconstruction buffer and a ternary depth test, allowing splats to be processed with maximum reuse of existing GPU units. Unlike standard triangle rasterization, which processes discrete primitives, this pipeline defers shading until after splat contributions are accumulated, enabling any fragment shading program to be used on the reconstructed surface.

### Weighted Splatting with Depth Proximity
Weighted Splatting with Depth Proximity is a rendering technique where point clouds are rendered as spheres (splats) in a multi-pass pipeline. It accumulates weighted attributes (color, normal) into a G-buffer to handle heavy overlap and reconstruct surface properties, deferring lighting to a final resolve pass [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N + P)$, where $N$ is the number of splats and $P$ is the number of pixels. The splatting passes are $O(N)$, and the finalization pass is $O(P)$.
*   **Memory Complexity:** $O(P)$ for the G-buffer textures (Depth, Normal, Color/Weight).
*   **Performance:** The multi-pass approach allows for efficient handling of large point clouds by leveraging GPU rasterization hardware. The deferred shading pass is highly efficient for scenes with many lights, as lighting is computed per-pixel rather than per-splat.
*   **Strengths:** Handles heavy overlap gracefully; produces smooth, continuous surfaces; supports complex lighting models in the final pass; avoids z-fighting issues associated with raw point rendering.
*   **Limitations:** Requires multiple render passes; G-buffer memory usage scales with screen resolution; may suffer from aliasing if splat size is not adaptive to distance.
*   **When to use:** Ideal for real-time visualization of large, unstructured point clouds where surface continuity and lighting quality are important.
*   **When not to use:** Not suitable for scenes requiring precise geometric intersection testing or when memory bandwidth is severely constrained.

## Background
Deferred Surface Splatting builds on the principles of Surface Splatting [S2, unofficial]. The technique was popularized by Zwicker, Pfister, van Baar, and Gross in "Surface Splatting" (SIGGRAPH 2001) and further optimized for GPU implementation by Botsch, Hornung, Zwicker, and Kobbelt in "High-Quality Surface Splatting on Today's GPUs" (PBG 2005) [S2, unofficial]. The specific implementation details described here are derived from open-source repositories [S1, S2, unofficial].
