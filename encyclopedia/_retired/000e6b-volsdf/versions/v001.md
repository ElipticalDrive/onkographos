# Metaball Field Evaluation

Also called: Dynamic Metaball Volume Update Pipeline, GPU Field Generation, GPU volume generation, Implicit Metaball Field, Metaball Density Function, Metaball Field Computation, Metaball density field update

## Overview
Metaball Field Evaluation is a procedural method for generating and updating a 3D scalar density volume representing dynamic metaballs (spheres) using compute or fragment shaders. It solves the problem of efficiently computing the scalar field values for a large number of moving volumetric primitives on the GPU, often serving as input for subsequent raycasting or marching cubes algorithms. It distinguishes itself from static implicit surface definitions by supporting real-time animation of blob positions and strengths, and from simple sphere blending by using an inverse-square distance falloff with a threshold offset rather than a smooth Gaussian blend.

## How it works
The method evaluates a scalar field $D(x,y,z)$ at every voxel in a 3D grid by summing contributions from a set of moving "blobs" (metaballs) and optionally a static floor plane. The evaluation is typically performed in parallel on the GPU, where each thread or fragment computes the field value for a specific voxel coordinate.

### Inputs and Outputs
**Inputs:**
- **Grid Dimensions:** Width, height, and depth of the 3D volume in voxels ($N_x, N_y, N_z$).
- **Voxel Size:** Physical size of a single voxel ($\Delta$).
- **Blob Parameters:** For each blob $i$, position $(p_{ix}, p_{iy}, p_{iz})$, strength $s_i$, and optionally color.
- **Time:** Current simulation time $t$ used to update blob positions.
- **Threshold:** A scalar value used to determine the isosurface or active region.

**Outputs:**
- **Density Volume:** A 3D texture where each voxel stores the computed density value. In some implementations, this is a 4-component texture (RGBA) where RGB stores color and A stores density [S1, unofficial].
- **Flag Volume (Optional):** A lower-resolution 3D texture indicating active (non-empty) regions to skip evaluation during raycasting [S1, unofficial].

### Data Structures
**Blob Constant Buffer (CPU -> GPU):**
A structured buffer containing blob data. A typical layout supports up to 150 balls [S1, unofficial]:
```cpp
struct CB_Balls {
    XMFLOAT4 fBalls[150]; // xyz: position, w: power/strength
    XMFLOAT4 fBallsCol[150]; // xyz: color, w: unused
    int iNumBalls;
    int dummy0;
    int dummy1;
    int dummy2;
};
```
Alternatively, uniforms may be used in fragment shaders: `u_blobParams` as an array of `vec4` (xyz=pos, w=strength) of size 100 [S3, unofficial].

**Volume Textures:**
- **Data Volume:** `ID3D11Texture3D` with format `DXGI_FORMAT_R32G32B32A32_FLOAT`. Dimensions are typically $(2 \cdot \text{halfReso}_x, 2 \cdot \text{halfReso}_y, 2 \cdot \text{halfReso}_z)$ [S1, unofficial]. Bind as Shader Resource View (SRV) and Unordered Access View (UAV).
- **Flag Volume:** `ID3D11Texture3D` with format `DXGI_FORMAT_R8_SINT`. Dimensions are downsampled by `VOXEL_BRICK_RATIO` [S1, unofficial]. Used for empty space skipping.

### Numbered Steps

1.  **Initialize Volume:**
    - Create the 3D density texture and optional flag texture.
    - Set half resolutions and voxel size parameters [S1, unofficial].
    - Initialize the density volume with zeros [S3, unofficial].

2.  **Update Blob Positions (CPU or GPU):**
    - For each blob $i$, update its position based on time $t$.
    - Common motion model: Circular orbits in the XY plane with a Z oscillation [S1, unofficial]:
      $$
      \begin{aligned}
      p_{ix}(t) &= r_i \cos(\omega_i t + \phi_i) \\
      p_{iy}(t) &= r_i \sin(\omega_i t + \phi_i) \\
      p_{iz}(t) &= 0.3 r_i \sin(2\omega_i t + \phi_i)
      \end{aligned}
      $$
      Where $r_i$ is the orbit radius, $\omega_i$ is the angular speed, and $\phi_i$ is the phase [S1, unofficial].
    - Update the constant buffer or uniform array with new positions and strengths [S1, unofficial].

3.  **Dispatch Field Evaluation:**
    - Launch a compute shader or fragment shader for each voxel in the grid.
    - If using a tiled fragment shader approach, determine the 3D voxel coordinates $(x,y,z)$ from the 2D screen coordinates and tile indices [S3, unofficial]:
      $$
      \begin{aligned}
      \text{tileX} &= \lfloor \text{fragXY}_x / \text{tileW} \rfloor \\
      \text{tileY} &= \lfloor \text{fragXY}_y / \text{tileH} \rfloor \\
      z &= \text{tileY} \cdot \text{u\_tilesX} + \text{tileX} \\
      x &= \text{fragXY}_x \pmod{\text{tileW}} \\
      y &= \text{fragXY}_y \pmod{\text{tileH}}
      \end{aligned}
      $$
    - Discard fragments outside the valid grid bounds ($x \ge N_x$ or $y \ge N_y$ or $z \ge N_z$) [S3, unofficial].

4.  **Evaluate Scalar Field:**
    - Normalize voxel coordinates to $[0, 1]$ range:
      $$
      \begin{aligned}
      f_x &= x / (N_x - 1) \\
      f_y &= y / (N_y - 1) \\
      f_z &= z / (N_z - 1)
      \end{aligned}
      $$
    - Initialize field value $D = 0.0$ [S3, unofficial].
    - For each blob $i$ (from $0$ to $N_{\text{blobs}}-1$):
      - Calculate squared distance in normalized space:
        $$
        d_i^2 = (f_x - p_{ix})^2 + (f_y - p_{iy})^2 + (f_z - p_{iz})^2
        $$
      - Calculate contribution using inverse square falloff with epsilon for stability:
        $$
        v_i = \frac{s_i}{\epsilon + d_i^2} - T
        $$
        Where $\epsilon$ is a small constant (e.g., $0.000001$ or $0.001$) and $T$ is a threshold (e.g., $12.0$) [S2, S3, unofficial].
      - If $v_i > 0$, add to total: $D \leftarrow D + v_i$.
    - Add floor contribution (if applicable):
      $$
      v_{\text{floor}} = \frac{2.0}{\epsilon_{\text{floor}} + f_y^2} - T
      $$
      If $v_{\text{floor}} > 0$, add to total: $D \leftarrow D + v_{\text{floor}}$ [S3, unofficial].

5.  **Store Result:**
    - Write the computed density $D$ to the density volume at $(x,y,z)$.
    - If using a 4-component texture, store color information in RGB and density in A [S1, unofficial].
    - Update the flag volume if the density exceeds a certain threshold, marking the voxel as active [S1, unofficial].

### Formulas
The core density function for a point $(x,y,z)$ is:
$$
D(x,y,z) = \sum_{i=1}^{N} \frac{s_i}{d_i^2 + \epsilon} - T \cdot N_{\text{active}}
$$
Where:
- $s_i$: Strength of blob $i$.
- $d_i^2$: Squared Euclidean distance from the point to the center of blob $i$.
- $\epsilon$: Epsilon constant to prevent division by zero (typically $10^{-6}$ to $10^{-3}$) [S2, S3, unofficial].
- $T$: Threshold value (typically $12.0$) [S3, unofficial].
- $N_{\text{active}}$: Number of blobs contributing a positive value [S3, unofficial].

### Parameters
- **$\epsilon$**: Stability constant. Values range from $0.000001$ to $0.001$ [S2, S3, unofficial].
- **$T$**: Threshold for blob contribution. Typically $12.0$ [S3, unofficial].
- **MAX_BALLS**: Maximum number of supported blobs. Typically 150 [S1, unofficial].
- **VOXEL_BRICK_RATIO**: Downsampling factor for the flag volume. Not given in the sources.
- **THREAD_X, THREAD_Y, THREAD_Z**: Compute shader thread group dimensions. Not given in the sources.

### Edge Cases and Pitfalls
- **Precision:** UINT to float conversion latency in shaders can be avoided by storing volume resolutions as floats in constant buffers [S1, unofficial].
- **Division by Zero:** The epsilon term $\epsilon$ is critical to prevent NaNs when a voxel center coincides with a blob center [S2, S3, unofficial].
- **Boundary Conditions:** Fragments/threads outside the grid bounds must be discarded to prevent out-of-bounds memory access [S3, unofficial].
- **Performance:** Evaluating all blobs for all voxels is $O(N \cdot M)$ where $N$ is number of blobs and $M$ is number of voxels. Using a flag volume to skip empty regions can significantly reduce this cost [S1, unofficial].

### Pseudocode
```python
# Compute Shader or Fragment Shader Entry Point
def evaluate_metaball_field(voxel_coords: vec3, blob_params: array, time: float, grid_size: int, epsilon: float, threshold: float) -> float:
    """
    Evaluates the metaball field for a given voxel.
    
    Args:
        voxel_coords: (x, y, z) integer voxel indices
        blob_params: Array of structs with {pos: vec3, strength: float}
        time: Current simulation time
        grid_size: Size of the grid (assumed cubic for simplicity)
        epsilon: Stability constant
        threshold: Threshold value for contribution
        
    Returns:
        Density value at the voxel
    """
    # Normalize voxel coordinates to [0, 1]
    fx = voxel_coords.x / (grid_size - 1)
    fy = voxel_coords.y / (grid_size - 1)
    fz = voxel_coords.z / (grid_size - 1)
    
    density = 0.0
    
    # Evaluate blob contributions
    for blob in blob_params:
        # Calculate squared distance in normalized space
        dx = fx - blob.pos.x
        dy = fy - blob.pos.y
        dz = fz - blob.pos.z
        dist_sq = dx*dx + dy*dy + dz*dz
        
        # Calculate contribution
        val = blob.strength / (epsilon + dist_sq) - threshold
        
        # Add if positive
        if val > 0.0:
            density += val
            
    # Evaluate floor contribution (if applicable)
    floor_val = 2.0 / (0.0001 + fy*fy) - threshold
    if floor_val > 0.0:
        density += floor_val
        
    return density

# CPU-side update loop (simplified)
def update_blob_positions(blobs: array, time: float):
    for blob in blobs:
        # Example circular orbit with Z oscillation
        radius = blob.orbit_radius
        speed = blob.orbit_speed
        phase = blob.phase
        
        blob.pos.x = radius * cos(time * speed + phase)
        blob.pos.y = radius * sin(time * speed + phase)
        blob.pos.z = 0.3 * radius * sin(2 * time * speed + phase)
        
        # Update strength/power if needed
        blob.strength = blob.power
```

## Subtopics

### [Radial Gaussian Density Field Generation](2081-radial-gaussian-density-field-generation.md)
Generates a 3D scalar field for volume rendering by summing normalized radial Gaussian functions centered at predefined atomic positions, then scaling and clamping the result to a [0,1] range. Unlike the inverse-square falloff of standard metaballs, this variant uses Gaussian decay, which provides smoother transitions and is often used for particle-based fluid or smoke simulation. It is chosen when smooth, continuous density fields are preferred over the sharper, threshold-based isosurfaces of inverse-square metaballs. See [Radial Gaussian Density Field Generation](2081-radial-gaussian-density-field-generation.md).

## Operating characteristics
- **Time Complexity:** $O(N \cdot V)$, where $N$ is the number of blobs and $V$ is the number of voxels. Each voxel requires $N$ distance calculations and additions.
- **Memory Complexity:** $O(V)$ for the density volume, plus $O(N)$ for blob parameters. The flag volume adds $O(V / \text{brick\_ratio})$ [S1, unofficial].
- **Performance:** Performance is heavily dependent on the number of blobs and grid resolution. Using a flag volume to skip empty regions can significantly improve performance for sparse scenes [S1, unofficial].
- **Strengths:** Real-time animation support, GPU-friendly parallel evaluation, simple mathematical formulation.
- **Limitations:** Inverse-square falloff can lead to sharp peaks and requires careful tuning of epsilon and threshold. Not suitable for very large numbers of blobs without spatial acceleration structures (e.g., BVH, grid-based culling).
- **When to use:** Dynamic volumetric effects like smoke, fire, or fluid blobs where real-time updates are required.
- **When not to use:** Static scenes or scenes with a very large number of blobs where spatial acceleration is needed.

## Background
The method originates from real-time volume rendering techniques for dynamic volumetric data. It is commonly used in conjunction with raycasting or marching cubes algorithms to visualize implicit surfaces defined by metaballs. The specific implementation details, such as the use of a flag volume for empty space skipping and the inverse-square falloff with a threshold, are derived from practical implementations in graphics programming communities [S1, S3, unofficial]. The technique is widely used in educational graphics projects and real-time visualization applications.
