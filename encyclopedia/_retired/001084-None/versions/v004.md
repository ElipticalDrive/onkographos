# Tight Voxelization (Point-in-Mesh Test)

Also called: Interior Voxel Verification, Point-in-Mesh Test, Tetrahedron Point-Inclusion Test

## Overview
Tight Voxelization is an optional post-processing step applied to solid voxelization results to verify the interior status of each voxel. It determines whether the center point of a voxel lies inside or outside the input mesh, removing voxels classified as outside to produce a tighter, more accurate volume representation [S1, unofficial]. It differs from its siblings by relying on explicit geometric containment tests (typically point-in-tetrahedron) rather than ray-casting or winding numbers, offering deterministic results at the cost of higher computational overhead [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of candidate voxels (typically generated by a preceding step like [Interior Voxelize](995-interior-voxelize.md)) and the source mesh (triangle or tetrahedron).
*   **Output:** A filtered set of voxels where only those with centers inside the mesh are retained.

**Data Structures:**
*   **Voxel Center:** A 3D point $P = (x, y, z)$ representing the geometric center of the voxel.
*   **Mesh Element:**
    *   For triangle meshes: The method typically relies on the parent voxelization step to identify candidate tetrahedra or uses a spatial acceleration structure to find intersecting tetrahedra.
    *   For tetrahedral meshes: A tetrahedron defined by four vertices $A, B, C, D$.

**Algorithm Steps:**
The core operation is the Point-in-Tetrahedron test, used when the input mesh is volumetric (tetrahedral) or when a tetrahedral approximation is used [S2].

1.  **Identify Candidate Tetrahedron:** For a voxel center $P$, identify the tetrahedron $T$ (vertices $A, B, C, D$) that potentially contains $P$. If the mesh is triangular, $P$ must first be associated with a tetrahedral element, often via spatial hashing or bounding volume hierarchies [S2].
2.  **Compute Face Normals:** For each of the four faces of the tetrahedron, calculate the outward-pointing normal vector.
    *   For face $ABC$, the normal $\vec{n}_{ABC}$ is calculated as:
        $$ \vec{n}_{ABC} = \frac{(B - A) \times (C - A)}{\|(B - A) \times (C - A)\|} $$
    *   Ensure the normal points *away* from the tetrahedron's interior. This is verified by checking the dot product with a vector to the fourth vertex (e.g., $D - A$). If $\vec{n}_{ABC} \cdot (D - A) > 0$, the normal is inward and must be negated [S2].
3.  **Plane Side Test:** For each face, determine if $P$ lies on the opposite side of the plane defined by that face relative to the tetrahedron's interior.
    *   Calculate the vector from a vertex on the face (e.g., $A$) to $P$: $\vec{v}_P = P - A$.
    *   Compute the dot product: $d = \vec{n}_{face} \cdot \vec{v}_P$.
    *   If the normal points outward, $P$ is inside the half-space of the face if $d \le 0$ (assuming the normal points away from the interior, the interior is on the negative side). *Note: Source [S2] states "check if point P is on the opposite side of the plane". If the normal points away from the center, the interior is on the side where the dot product is negative (or zero).*
4.  **Classification:**
    *   If $P$ is on the "inside" side of all four planes (i.e., $d \le 0$ for all four faces), classify $P$ as inside the tetrahedron [S2].
    *   If $P$ fails this test for any face, it is outside.
5.  **Filtering:** Remove the voxel from the output if its center $P$ is determined to be outside the mesh [S1, unofficial].

**Parameters:**
*   `--tight`: Boolean flag to enable this step. Default: `false` [S1, unofficial].
*   `voxel_size`: Determines the resolution and thus the position of $P$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Performance:** This step is computationally expensive ("time consuming") because it requires a geometric test for every candidate voxel [S1, unofficial].
*   **Boundary Precision:** Points lying exactly on the mesh surface may yield $d=0$. Implementation should handle floating-point epsilon errors to avoid flickering or incorrect classification at boundaries [G].
*   **Non-Tetrahedral Meshes:** If the input is a triangle mesh, the "Point-in-Tetrahedron" test is not directly applicable without first converting the mesh to a tetrahedral volume or using a different point-in-mesh algorithm (like ray casting). The source [S2] specifically links this method to volume meshes (tetrahedrons). For triangle meshes, this step might be skipped or replaced by a different containment check not detailed in the provided notes [S2].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot K)$, where $N$ is the number of candidate voxels and $K$ is the cost of finding the containing tetrahedron (ideally $O(1)$ with spatial hashing, but worst-case higher). The geometric test itself is $O(1)$ per tetrahedron.
*   **Memory Complexity:** $O(1)$ auxiliary memory per voxel test.
*   **Performance:** Significantly slower than basic solid voxelization due to the per-voxel geometric verification [S1, unofficial].
*   **Strengths:** Produces a tighter, more accurate volume by removing false positives from the initial voxelization step. Deterministic for tetrahedral meshes.
*   **Limitations:** High computational cost; not suitable for real-time applications or very high-resolution grids without optimization. Limited to tetrahedral meshes or requires conversion for triangle meshes.
*   **When to use:** When memory efficiency and geometric accuracy are prioritized over speed, and the input mesh is tetrahedral or can be efficiently converted.

## Background
Tight Voxelization as a post-processing verification step is documented in the `voxelizer` tool by topskychen [S1, unofficial] and in the `CudaVox` component of `cad2vox` [S2]. The point-in-tetrahedron algorithm is a standard computational geometry technique, with implementations discussed in community resources like Stack Overflow [S2]. The specific integration into voxelization pipelines appears in open-source tools targeting CAD-to-voxel conversion.
