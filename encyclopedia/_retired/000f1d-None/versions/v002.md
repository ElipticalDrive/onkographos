# VoxelGrid Down Sample
## Overview
VoxelGrid Down Sample reduces the resolution of a volumetric voxel grid by a specified integer factor using max pooling [S1, unofficial]. It serves as a foundational block for generating lower-resolution levels in a multiresolution hierarchy, enabling efficient rendering or compression by discarding fine-grained detail in favor of coarser, representative values [S1, unofficial]. Unlike frequency-domain methods or adaptive culling, this approach operates directly in the spatial domain via fixed-size block reduction [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A `VoxelGrid` object containing a 3D data array `data` of shape $(N_x, N_y, N_z)$, a location origin `loc`, and a voxel scale `scale`.
- Output: A new `VoxelGrid` object with reduced dimensions $(N_x/s, N_y/s, N_z/s)$, preserving the original `loc` and `scale`.

**Data Structures:**
- `VoxelGrid`:
  - `data`: NumPy array or tensor of shape $(N_x, N_y, N_z)$.
  - `loc`: 3D vector representing the grid's origin.
  - `scale`: Scalar or 3D vector representing voxel size.

**Steps:**
1. **Validate Divisibility:** Check if the input dimensions are divisible by the down-sampling factor $s$. If $N_x \pmod s \neq 0$ or $N_y \pmod s \neq 0$ or $N_z \pmod s \neq 0$, raise an error [S1, unofficial].
2. **Block Reduction:** Partition the input volume into non-overlapping blocks of size $s \times s \times s$. Compute the maximum value within each block to form the new voxel value [S1, unofficial].
3. **Construct Output:** Create a new `VoxelGrid` instance. Assign the reduced data array to it. Copy the `loc` and `scale` from the input grid to maintain spatial consistency [S1, unofficial].

**Pseudocode:**
```python
import numpy as np

def voxelgrid_down_sample(voxel_grid, factor):
    """
    Down samples a VoxelGrid by a given integer factor using max pooling.
    
    Args:
        voxel_grid: Object with attributes .data (3D array), .loc, .scale.
        factor: Integer down-sampling factor (e.g., 2).
        
    Returns:
        A new VoxelGrid with reduced resolution.
    """
    data = voxel_grid.data
    s = factor
    
    # Step 1: Validate divisibility
    if data.shape[0] % s != 0 or data.shape[1] % s != 0 or data.shape[2] % s != 0:
        raise ValueError(f"Resolution {data.shape} is not divisible by factor {s}")
    
    # Step 2: Downsample using max pooling
    # Reshape to group voxels into blocks of size s
    # Shape: (N_x/s, s, N_y/s, s, N_z/s, s)
    reshaped = data.reshape(
        data.shape[0] // s, s,
        data.shape[1] // s, s,
        data.shape[2] // s, s
    )
    
    # Take max over the block dimensions (axes 1, 3, 5)
    new_data = np.max(reshaped, axis=(1, 3, 5))
    
    # Step 3: Return new VoxelGrid
    new_grid = VoxelGrid()
    new_grid.data = new_data
    new_grid.loc = voxel_grid.loc
    new_grid.scale = voxel_grid.scale
    
    return new_grid
```

**Parameters:**
- `factor`: Integer scaling factor $s$. Typical values are powers of 2 (e.g., 2, 4) to align with hardware texture sampling [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Non-divisible Dimensions:** The method strictly requires dimensions to be divisible by the factor. Rounding or truncation is not performed by the core method [S1, unofficial].
- **Max Pooling Bias:** Max pooling preserves high-intensity features but may introduce artifacts if the volume contains significant transparency or low-density regions, as it ignores lower values within the block [S1, unofficial].

## Subtopics

### [Volume Resampling and Overflow Guard](1772-volume-resampling-and-overflow-guard.md)
This method prevents downstream memory overflow by enforcing a strict maximum voxel count on a candidate volume grid. It calculates a scaling factor to reduce dimensions if the candidate count exceeds the limit, applies trilinear interpolation to resample the data, and includes a fallback mechanism to ensure the final voxel count is strictly reduced even if rounding prevents it. It builds on [VoxelGrid Down Sample](1014-voxelgrid-down-sample.md) by adding a safety cap and precise resampling logic.

### [Grid Deformation](5372-grid-deformation.md)
Grid Deformation is a preprocessing technique applied prior to data reduction in volume rendering compression. It transforms the input data grid according to user-defined regions to better preserve salient features during subsequent downsampling. It is an orthogonal approach to hierarchical models like wavelets, reporting improved visual results compared to pure downsampling and wavelet-based methods.

### [Optimization-based Downsampling](5825-optimization-based-downsampling.md)
Optimization-based downsampling is a method for generating low-resolution microflake volume representations that preserve the visual appearance of the reference high-resolution volume, specifically accounting for microscopic self-shadowing effects. It distinguishes itself from simple max-pooling or linear resampling by iteratively optimizing scattering parameters via large-scale training rendering to match the target appearance.

### [Pre-processing for Half Resolution](6436-pre-processing-for-half-resolution.md)
This method constructs a half-resolution volumetric representation from a full-resolution input to reduce data size while preserving visual quality and avoiding the information loss associated with direct subsampling. It differs from its sibling [VoxelGrid Down Sample](1014-voxelgrid-down-sample.md), which uses max pooling, by explicitly filling "holes" (transparent voxels in the downsampled grid) with median values from adjacent full-resolution neighbors to prevent occlusion artifacts. Unlike [Frequency-Domain Downsampling](6578-frequency-domain-downsampling.md), which relies on low-pass filtering in the frequency domain, this approach operates directly in the spatial domain using a specific subsampling pattern and local median replacement.

### Max-Pooling Layer
A layer that applies a max filter to non-overlapping sub-regions of the input to downsample the input and reduce parameters in subsequent encoder layers. It contains no trainable parameters. Typical parameters include a filter size of $2 \times 2$ and a stride of 2, often applied in layers with input channels 64, 32, and 8 [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of voxels in the input grid, as each voxel is visited once to compute the block maximum.
- **Memory Complexity:** $O(N/s^3)$ for the output grid, plus $O(N)$ temporary memory for reshaping if not done in-place.
- **Strengths:** Simple to implement, computationally efficient, and preserves high-intensity features (e.g., bright surfaces or dense regions) [S1, unofficial][S2, unofficial].
- **Limitations:** Loses low-intensity information within blocks, which can cause artifacts in transparent or volumetrically sparse regions. Requires divisible dimensions [S1, unofficial].
- **When to Use:** When generating MIP maps or coarse levels for rendering where high-frequency detail is less critical, or as a preprocessing step for deep learning encoders [S2, unofficial].
- **When Not to Use:** When preserving average density or transparency is critical, or when input dimensions are not multiples of the desired scale factor [S1, unofficial].

## Background
The method originates from the need to efficiently manage volumetric data in differentiable rendering and deep learning pipelines. It is implemented in the `autonomousvision/differentiable_volumetric_rendering` repository as a core utility for managing grid resolutions [S1, unofficial]. The underlying max-pooling operation is a standard component in convolutional neural networks for spatial downsampling, as described in architectures for compressed volume rendering using deep learning [S2, unofficial].
