# Signed Box Distance Function

Also called: Box SDF, SDF Box, implicit box, Rectangular (Axis-Aligned Box) SDF

## Overview
The Signed Box Distance Function computes the exact Euclidean distance from a query point to the surface of an axis-aligned box, returning a negative value if the point is inside and a positive value if it is outside [S3, S5, S7, unofficial]. It distinguishes itself from sibling primitives like the Sphere SDF by handling the distinct geometric regions of a box (faces, edges, and corners) using component-wise absolute values and max/min operations, ensuring the distance estimate is never an underestimation [S1, S7, unofficial]. This property is critical for sphere tracing, as underestimating the distance can cause the ray to overshoot the surface or produce incorrect ambient occlusion [S1, S7, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A query point $p \in \mathbb{R}^3$ and box parameters: center $c \in \mathbb{R}^3$ and side lengths $s \in \mathbb{R}^3$ (where $s_i > 0$) [S4, S5, S6, unofficial]. Alternatively, the box can be defined by half-extents $e = s/2$ [S2, S4, unofficial].
*   **Output:** A scalar signed distance $d \in \mathbb{R}$. $d < 0$ indicates the point is inside the box; $d > 0$ indicates the point is outside; $d = 0$ indicates the point is on the surface [S1, S5, unofficial].

**Data Structures:**
*   The box is defined by two vectors: `center` (3 floats) and `side_lengths` (3 floats). In some implementations, these are learnable parameters [S4, S5, S6, unofficial].

**Algorithm:**
The standard robust implementation (Algorithm 3.6 in [S7, S8, unofficial]) proceeds as follows:

1.  **Translate and Scale:** Compute the vector from the box center to the point, then subtract the half-extents.
    $$ diff = |p - c| - \frac{s}{2} $$
    Here, $| \cdot |$ is the component-wise absolute value. Let $diff = (diff_x, diff_y, diff_z)$ [S4, S5, S7, S8, unofficial].

2.  **Determine Inside/Outside:** Calculate the maximum component of $diff$.
    $$ res = \max(diff_x, \max(diff_y, diff_z)) $$
    This value represents the distance to the closest face if the point is inside [S7, S8, unofficial].

3.  **Compute Distance:**
    *   If $res > 0$, the point is outside the box. The distance is the Euclidean norm of the positive components of $diff$ (clamping negative components to zero):
        $$ res = \| \max(diff, 0) \|_2 = \sqrt{\max(diff_x, 0)^2 + \max(diff_y, 0)^2 + \max(diff_z, 0)^2} $$
    *   If $res \le 0$, the point is inside the box. The distance is simply $res$ (which is negative or zero) [S7, S8, unofficial].

4.  **Return:** Return $res$ [S7, S8, unofficial].

**Pseudocode:**
```python
def signed_box_distance(p, center, side_lengths):
    """
    Computes the signed distance from point p to an axis-aligned box.
    
    Args:
        p: vec3, query point coordinates.
        center: vec3, center of the box.
        side_lengths: vec3, lengths of the box sides (x, y, z).
        
    Returns:
        float: Signed distance. Negative if inside, positive if outside.
    """
    # Step 1: Translate point to box-local space and subtract half-extents
    # diff = |p - center| - side_lengths / 2
    diff_x = abs(p.x - center.x) - side_lengths.x / 2.0
    diff_y = abs(p.y - center.y) - side_lengths.y / 2.0
    diff_z = abs(p.z - center.z) - side_lengths.z / 2.0
    
    # Step 2: Determine if inside or outside by checking the max component
    # res = max(diff_x, max(diff_y, diff_z))
    res = diff_x
    if diff_y > res:
        res = diff_y
    if diff_z > res:
        res = diff_z
        
    # Step 3: Compute final distance
    if res > 0:
        # Point is outside. Distance is L2 norm of positive components.
        # max(diff, 0) clamps negative components to 0.
        pos_x = diff_x if diff_x > 0 else 0.0
        pos_y = diff_y if diff_y > 0 else 0.0
        pos_z = diff_z if diff_z > 0 else 0.0
        
        res = sqrt(pos_x * pos_x + pos_y * pos_y + pos_z * pos_z)
        
    # If res <= 0, it is the distance to the closest face (inside the box)
    return res
```

**Parameters:**
*   `center`: The 3D coordinates of the box center. Default: $(0, 0, 0)$ [S1, S7, unofficial].
*   `side_lengths`: The width, height, and depth of the box. Must be positive. Example: $(1, 1, 1)$ for a unit box [S7, unofficial].

**Edge Cases and Pitfalls:**
*   **Underestimation:** An incorrect implementation (e.g., Algorithm 3.5 in [S7, S8, unofficial]) may underestimate the distance in corner regions. This leads to smaller ray steps, slower convergence, and incorrect ambient occlusion (artifacts like black dots or banding) [S7, S8, unofficial].
*   **Overestimation:** Overestimating the distance can cause the ray to pass through the surface or inaccurately estimate the surface position, also negatively impacting ambient occlusion [S7, unofficial].
*   **Precision:** The use of absolute values and max/min operations is numerically stable. However, floating-point precision issues near the surface ($d \approx 0$) are common to all SDFs and may require epsilon clamping in downstream shading logic [G].

## Subtopics

### [Sphere Signed Distance Function](1237-sphere-signed-distance-function.md)
Computes distance to a sphere. Simpler than the box, as it relies solely on radial distance. Choose when rotational symmetry is sufficient.

### [Ellipsoid Signed Distance Function](2397-ellipsoid-signed-distance-function.md)
Generalizes the sphere to non-uniform scaling. More complex than the box, requiring iterative or approximate methods for exact distance. Choose when anisotropic scaling is needed.

### [Capsule Signed Distance Function](2439-capsule-signed-distance-function.md)
Computes distance to a line segment with rounded caps. More complex than the box, involving projection onto a line. Choose for organic or limb-like shapes.

### [Plane Signed Distance Function](1102-plane-signed-distance-function.md)
Computes distance to an infinite plane. The simplest primitive. Choose for ground planes or infinite boundaries.

## Operating characteristics
*   **Time Complexity:** $O(1)$. The computation involves a fixed number of arithmetic operations (subtractions, absolute values, max/min, and one square root).
*   **Memory Complexity:** $O(1)$. No auxiliary data structures are required.
*   **Strengths:** Exact distance calculation; robust for sphere tracing; efficient; handles all octants uniformly via symmetry [S1, S7, unofficial].
*   **Limitations:** Only applies to axis-aligned boxes. For rotated boxes, the point must be transformed into the box's local coordinate system first [G].
*   **When to use:** When rendering axis-aligned rectangular volumes or bounding boxes in ray marching.
*   **When not to use:** For rotated boxes (use transformation) or when approximate distance is acceptable and simpler primitives suffice (though box SDF is already very simple).

## Background
The Signed Box Distance Function is a fundamental primitive in Signed Distance Field (SDF) rendering, popularized by Inigo Quilez in his online resources on distance functions [S1, unofficial]. It is widely used in ray marching for rendering implicit surfaces, particularly in real-time graphics and neural rendering pipelines where it serves as a learnable primitive [S4, S5, S6, unofficial]. The correct formulation (Algorithm 3.6) was highlighted in academic work on GPU ray marching to avoid artifacts in ambient occlusion computation [S7, S8, unofficial].
