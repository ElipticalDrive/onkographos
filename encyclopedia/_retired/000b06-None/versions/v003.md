# Interior Voxelize

Also called: point-in-mesh voxelization, grid containment sampling

## Overview
Interior Voxelize determines the occupancy status of a voxel grid by sampling discrete points within the grid volume and testing whether each point lies inside the input mesh [S1, S2, unofficial]. It differs from its siblings [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxel-filling.md) and [Front/Back Face Flagging](1506-front-back-face-flagging.md) by relying on direct point containment queries rather than deterministic ray intersections or surface normal orientation flags [S1, unofficial]. This method is distinct from [Stochastic Ray-Casting Voxelization](1067-stochastic-ray-casting-voxelization.md) because it uses a fixed grid of sample points rather than randomized ray directions, making it deterministic for a given grid resolution [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A triangle mesh (typically manifold or closed) and a target voxel resolution $N$.
- Output: A 3D boolean occupancy grid (or bitmap) where each voxel is marked as interior (1) or exterior (0).

**Data Structures:**
1.  **Mesh**: Represented as a collection of triangles. For efficient queries, a spatial acceleration structure (e.g., AABB tree) is built [S2, unofficial].
2.  **Spatial Index**: `DMeshAABBTree3` or equivalent, built from the mesh with auto-build enabled [S2, unofficial].
3.  **Grid Indexer**: `ShiftGridIndexer3` (or equivalent) mapping integer grid coordinates $(i, j, k)$ to 3D world coordinates [S2, unofficial].
4.  **Occupancy Bitmap**: `Bitmap3` of dimensions $(N, N, N)$ storing boolean values [S2, unofficial].

**Steps:**
1.  **Compute Bounding Box**: Calculate the axis-aligned bounding box (AABB) of the input mesh, denoted as $B_{min}$ and $B_{max}$ [S2, unofficial].
2.  **Determine Grid Parameters**:
    -   Let $N$ be the resolution (number of cells along the maximum dimension of the bounding box) [S2, unofficial].
    -   Calculate the cell size $s$:
        $$ s = \frac{\max(B_{max} - B_{min})}{N} $$
        where $\max(B_{max} - B_{min})$ is the length of the longest side of the bounding box [S2, unofficial].
3.  **Initialize Indexer**: Create a grid indexer that maps grid indices to world space using $B_{min}$ and $s$ [S2, unofficial].
4.  **Generate Sample Points**:
    -   Define the grid shape as $(N, N, N)$ [S1, unofficial].
    -   Generate a 3D grid of points covering the bounding box. The points are typically centered within the cells. For a grid from $0$ to $N-1$, the center coordinates in grid units are $0.5, 1.5, \dots, N-0.5$ [S1, unofficial].
    -   Transform these grid coordinates to world coordinates using the indexer [S2, unofficial].
    -   *Optional Noise*: To break symmetry or handle degenerate cases where points lie exactly on edges/faces, small random noise may be added to the sample points [S1, unofficial].
5.  **Containment Test**:
    -   For each sample point $p$, use the spatial index to determine if $p$ is inside the mesh: $occ = \text{IsInside}(p)$ [S2, unofficial].
    -   The `IsInside` function typically uses ray casting or winding number logic internally, but is abstracted as a single query [S2, unofficial].
6.  **Store Results**: Assign the result of the containment test to the corresponding voxel in the `Bitmap3` [S2, unofficial].

**Pseudocode:**
```python
def interior_voxelize(mesh, resolution=32):
    """
    Voxelize a mesh by checking point containment in a grid.
    
    Args:
        mesh: A triangle mesh object with a method to build a spatial index.
        resolution: Integer, number of cells along the longest axis.
        
    Returns:
        occ: A 3D numpy array of shape (resolution, resolution, resolution) with boolean values.
    """
    # 1. Build spatial index
    spatial = build_aabb_tree(mesh, auto_build=True)
    
    # 2. Get bounding box
    bounds = mesh.get_bounding_box()
    bb_min = bounds.min
    bb_max = bounds.max
    
    # 3. Calculate cell size based on max dimension
    max_dim = max(bb_max.x - bb_min.x, bb_max.y - bb_min.y, bb_max.z - bb_min.z)
    cell_size = max_dim / resolution
    
    # 4. Create grid indexer
    # Maps grid index (i,j,k) to world coordinate
    indexer = ShiftGridIndexer3(bb_min, cell_size)
    
    # 5. Generate grid points
    # Create indices 0 to resolution-1
    indices = np.arange(resolution)
    # Create meshgrid for i, j, k
    i_grid, j_grid, k_grid = np.meshgrid(indices, indices, indices, indexing='ij')
    
    # Convert to world coordinates using indexer
    # Note: The indexer expects integer grid coordinates. 
    # Depending on implementation, points might be cell centers or corners.
    # Here we assume cell centers are derived from integer indices via the indexer's FromGrid method.
    # If the indexer maps integer indices to cell centers, we pass (i, j, k).
    # If it maps to corners, we might need to adjust. 
    # Based on S2, FromGrid(idx) is used directly on integer indices.
    
    # Flatten indices for batch processing
    flat_indices = np.column_stack([i_grid.ravel(), j_grid.ravel(), k_grid.ravel()])
    
    # Map to world space
    # This step depends on the specific indexer implementation. 
    # Assuming indexer.FromGrid takes a single Vector3i and returns Vector3d.
    # We iterate or vectorize this call.
    points = []
    for idx in flat_indices:
        v = indexer.from_grid(idx)
        points.append(v)
    points = np.array(points)
    
    # Optional: Add noise to break symmetry (S1)
    # noise = 0.1 * (np.random.rand(*points.shape) - 0.5)
    # points += noise
    
    # 6. Check containment
    # spatial.IsInside(v) returns boolean
    occ_flat = np.array([spatial.is_inside(p) for p in points])
    
    # 7. Reshape to grid
    occ = occ_flat.reshape(resolution, resolution, resolution)
    
    return occ
```

**Parameters:**
-   `resolution` ($N$): The number of voxels along the longest axis of the bounding box. Typical value: 32 [S2, unofficial]. Higher values increase accuracy but also memory and compute cost.

**Edge Cases and Pitfalls:**
-   **Degenerate Geometry**: If the mesh is not closed or has holes, point containment tests may yield inconsistent results depending on the winding number or ray-casting logic used internally by `IsInside` [S2, unofficial].
-   **Precision**: Points lying exactly on mesh faces may lead to ambiguous results. Adding small noise (as suggested in [S1, unofficial]) can mitigate this.
-   **Performance**: Testing every voxel center can be slow for high resolutions. Spatial indexing is critical for performance [S2, unofficial].

## Subtopics

### [Stochastic Ray-Casting Voxelization](1067-stochastic-ray-casting-voxelization.md)
Uses random rays from voxel centers to determine interior status via majority voting. Choose when dealing with non-manifold geometry where deterministic point tests might fail due to ambiguity.

### [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxel-filling.md)
Scans along principal axes to fill intervals between front/back faces. Choose for faster, deterministic filling on manifold meshes.

### [Front/Back Face Flagging](1506-front-back-face-flagging.md)
Assigns orientation flags to surface voxels. Choose when surface orientation is critical for attribute assignment.

### [Tight Voxelization (Point-in-Mesh Test)](1709-tight-voxelization-point-in-mesh-test.md)
Post-processing step to verify voxel centers. Choose as a refinement step to remove false positives.

### [Mesh Winding Number Voxelization](2328-mesh-winding-number-voxelization.md)
Computes winding number for smooth density fields. Choose for handling open boundaries or non-manifold geometry with smooth transitions.

### [Polyhedron Moment Integration and Voxelization](3722-polyhedron-moment-integration-and-voxelization.md)
Analytic integration of density moments. Choose for exact density representation rather than binary occupancy.

### [Point-Containment Voxelization](3882-point-containment-voxelization.md)
Uses exact geometric containment queries for grid vertices. Choose when vertex-based accuracy is prioritized over cell-center accuracy.

### [CPU Solid Voxelization](6756-cpu-solid-voxelization.md)
Deterministic sweep-line algorithm on CPU. Choose for CPU-only implementations requiring exact geometric projection.

### [Sub-Voxel Volume Clipping](6989-sub-voxel-volume-clipping.md)
Smooths clipped voxel boundaries. Choose when post-processing clipped volumes to avoid stair-stepping artifacts.

## Operating characteristics
-   **Time Complexity**: $O(N^3 \cdot \log T)$, where $N$ is the resolution and $T$ is the number of triangles in the mesh. Each of the $N^3$ voxels requires a spatial query, which is typically $O(\log T)$ with an AABB tree [S2, unofficial].
-   **Memory Complexity**: $O(N^3)$ for the occupancy grid, plus $O(T)$ for the mesh and spatial index [S2, unofficial].
-   **Measured Performance**: For $N=32$, the method is fast enough for real-time or near-real-time applications on modern hardware [S2, unofficial]. Performance degrades linearly with $N^3$.
-   **Strengths**: Simple to implement; robust to complex mesh topology if the underlying `IsInside` function is robust; deterministic [S1, S2, unofficial].
-   **Limitations**: Computationally expensive for high resolutions ($N > 128$); sensitive to mesh quality (non-manifold, holes) if `IsInside` is not robust; requires building a spatial index [S2, unofficial].
-   **When to Use**: When a simple, deterministic occupancy grid is needed and the mesh is reasonably well-formed. Suitable for pre-processing steps in volume rendering pipelines [S1, S2, unofficial].
-   **When Not to Use**: For very high-resolution grids where performance is critical; for meshes with significant non-manifold geometry if the `IsInside` implementation is not robust to such cases.

## Background
Interior Voxelize is a fundamental technique in volumetric rendering and 3D computer graphics for converting surface representations (meshes) into volume representations (voxel grids). The method of sampling grid points and testing containment is a standard approach in computational geometry [S1, S2, unofficial]. The specific implementation using `DMeshAABBTree3` and `ShiftGridIndexer3` is documented in tutorials on 3D bitmaps and mesh winding numbers [S2, unofficial]. The use of noise to break symmetry is noted in the context of differentiable volumetric rendering [S1, unofficial].
