# Interior Voxelize

Also called: point-in-mesh test, solid voxelization via containment

## Overview
Interior Voxelize determines which voxels in a discrete grid lie strictly inside a closed 3D mesh by sampling points within the voxel volume and testing for geometric containment [S1, S2, unofficial]. Unlike sibling methods that rely on ray-casting parity [1067-stochastic-ray-casting-voxelization.md], winding numbers [2328-mesh-winding-number-voxelization.md], or rasterization coverage [908-rasterization-based-voxelization.md], this approach directly evaluates the boolean "inside" status of specific sample points, making it robust against non-manifold geometry and self-intersections where deterministic ray paths might fail [S1, unofficial]. It serves as the core occupancy determination step in producing volume data from mesh inputs [12-voxelization.md].

## How it works
**Inputs and Outputs:**
- Input: A closed 3D mesh (triangle soup or BRep) and a target grid resolution $N$.
- Output: A 3D boolean grid (Bitmap) where `True` indicates the voxel is interior to the mesh.

**Data Structures:**
1.  **Mesh**: A collection of triangles.
2.  **Spatial Index**: An Acceleration Structure (e.g., AABB Tree) built over the mesh triangles to accelerate point-in-mesh queries [S2, unofficial].
3.  **Grid Indexer**: A mapping structure (e.g., `ShiftGridIndexer3`) that converts integer grid indices $(i, j, k)$ to world-space coordinates $(x, y, z)$ based on the mesh bounding box [S2, unofficial].
4.  **Bitmap**: A 3D array of booleans with dimensions $(N, N, N)$ [S2, unofficial].

**Steps:**

1.  **Construct Spatial Index**: Build a spatial acceleration structure (e.g., `DMeshAABBTree3`) from the input mesh with automatic building enabled [S2, unofficial].
2.  **Calculate Bounds**: Determine the axis-aligned bounding box (AABB) of the mesh, denoted as $B_{min}$ and $B_{max}$ [S2, unofficial].
3.  **Define Grid Parameters**:
    -   Set the resolution $N$ (typical value: 32) [S2, unofficial].
    -   Calculate the cell size:
        $$ cell\_size = \frac{\max(B_{max} - B_{min})}{N} $$
        where $\max(\cdot)$ takes the maximum dimension of the bounding box vector [S2, unofficial].
    -   Create a grid indexer mapping grid coordinates to 3D space using $B_{min}$ and $cell\_size$ [S2, unofficial].
4.  **Generate Sample Points**:
    -   Create a set of 3D points representing the sample locations within the grid. Common strategies include:
        -   **Center Sampling**: Points at the center of each voxel cell [S3, unofficial].
        -   **Uniform Grid**: Points distributed across the bounding box volume [S1, unofficial].
    -   *Optional*: Add small random noise to points to break symmetry and avoid degenerate cases on mesh boundaries [S1, unofficial].
    -   *Optional*: Normalize points to a canonical range (e.g., $[-0.5, 0.5]$) if required by the containment function [S1, unofficial].
5.  **Test Containment**:
    -   Iterate over all grid indices $(i, j, k)$.
    -   Map the grid index to a world coordinate $v$ using the indexer: $v = \text{Indexer.FromGrid}(i, j, k)$ [S2, unofficial].
    -   Query the spatial index to determine if $v$ is inside the mesh: $inside = \text{Spatial.IsInside}(v)$ [S2, unofficial].
    -   Alternatively, use a direct point-in-mesh containment function if available [S1, unofficial].
6.  **Assign Occupancy**: Set the voxel at $(i, j, k)$ in the Bitmap to the result of the containment test [S2, unofficial].
7.  **Post-Processing (Optional)**:
    -   If "Tight Voxelization" is enabled, verify if the center point of each voxel is inside the mesh. If outside, remove the voxel (set to false) [S3, unofficial]. Note: This step is computationally expensive [S3, unofficial].

**Pseudocode:**

```python
def interior_voxelize(mesh, resolution=32):
    """
    Voxelize a mesh by testing point containment.
    
    Args:
        mesh: A 3D mesh object with triangles.
        resolution: Integer grid resolution along the maximum dimension.
        
    Returns:
        A 3D boolean numpy array of shape (resolution, resolution, resolution).
    """
    # Step 1: Construct Spatial Index
    # Build an AABB tree for fast ray/point queries
    spatial_index = build_aabb_tree(mesh)
    
    # Step 2: Calculate Bounds
    bounds = mesh.get_bounding_box()
    bb_min = bounds.min
    bb_max = bounds.max
    
    # Step 3: Define Grid Parameters
    numcells = resolution
    # Calculate cell size based on the largest dimension of the bounding box
    max_dim = max(bb_max.x - bb_min.x, bb_max.y - bb_min.y, bb_max.z - bb_min.z)
    cell_size = max_dim / numcells
    
    # Create a grid indexer to map grid indices to world coordinates
    # This maps integer (i,j,k) to world (x,y,z)
    indexer = create_shift_grid_indexer(bb_min, cell_size)
    
    # Initialize Bitmap
    bitmap = create_bitmap3(numcells, numcells, numcells)
    
    # Step 4 & 5: Generate Points and Test Containment
    for i in range(numcells):
        for j in range(numcells):
            for k in range(numcells):
                # Map grid index to world coordinate
                v = indexer.from_grid(i, j, k)
                
                # Test if point is inside the mesh
                # Uses the spatial index to determine interior status
                is_inside = spatial_index.is_inside(v)
                
                # Step 6: Assign Occupancy
                bitmap.set(i, j, k, is_inside)
                
    # Step 7: Optional Tight Voxelization
    # If enabled, re-verify center points and remove false positives
    # This is time-consuming [S3, unofficial]
    # for i, j, k in bitmap.indices():
    #     center = indexer.from_grid(i, j, k)
    #     if not spatial_index.is_inside(center):
    #         bitmap.set(i, j, k, False)
            
    return bitmap.to_numpy_array()
```

**Parameters:**
-   `resolution` ($N$): The number of cells along the maximum dimension of the bounding box. Typical value: 32 [S2, unofficial].
-   `tight` (Boolean): If true, performs an additional check to remove voxels whose centers are outside the mesh. Default: false [S3, unofficial].

**Edge Cases and Pitfalls:**
-   **Performance**: Point-in-mesh tests are computationally expensive, especially for high resolutions or complex meshes [S3, unofficial]. The use of a spatial index (AABB tree) is critical for performance [S2, unofficial].
-   **Non-Watertight Meshes**: If the mesh is not closed, the definition of "inside" may be ambiguous. Methods like Mesh Winding Number [2328-mesh-winding-number-voxelization.md] may handle this better, but standard point-in-mesh tests may produce inconsistent results [S1, unofficial].
-   **Boundary Precision**: Points exactly on the mesh surface may yield undefined results. Adding small noise to sample points can help break symmetry and avoid degenerate cases [S1, unofficial].
-   **Memory**: Storing a dense 3D bitmap for high resolutions (e.g., 256^3) requires significant memory. Sparse structures may be needed for large grids [4391-sparse-and-hierarchical-structures.md].

## Subtopics

### [Stochastic Ray-Casting Voxelization](1067-stochastic-ray-casting-voxelization.md)
Determines interior status by casting multiple random rays from each voxel center and counting intersections with mesh triangles. It differs from Ray-Cast Style Voxel Filling [1502-ray-cast-style-voxel-filling.md] and Front/Back Face Flagging [1506-front-back-face-flagging.md] by relying on statistical majority voting over randomized directions rather than deterministic axis-aligned rays or face orientation flags, making it robust against non-manifold geometry, broken meshes, and self-intersections where a single deterministic ray might fail [1067-stochastic-ray-casting-voxelization.md].

### [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxel-filling.md)
Determines interior voxels by scanning along a principal axis (typically Z) and filling intervals between front-facing and back-facing surface voxels [1502-ray-cast-style-voxel-filling.md]. It differs from Stochastic Ray-Casting Voxelization [1067-stochastic-ray-casting-voxelization.md] by using deterministic scanline logic rather than probabilistic sampling, and from Mesh Winding Number Voxelization [2328-mesh-winding-number-voxelization.md] by relying on explicit face orientation flags rather than topological winding counts [1502-ray-cast-style-voxel-filling.md].

### [Front/Back Face Flagging](1506-front-back-face-flagging.md)
Determines the interior of a mesh by assigning a boolean orientation flag to voxels intersected by triangle surfaces. It solves the problem of distinguishing interior from exterior voxels in non-watertight or open meshes by tracking the direction of surface traversal relative to a specified filling direction. Unlike sibling methods that rely on ray-casting parity [1067-stochastic-ray-casting-voxelization.md], winding numbers [2328-mesh-winding-number-voxelization.md], or stencil buffer accumulation [3722-polyhedron-moment-integration-and-voxelization.md], this approach explicitly records whether a voxel's boundary triangle is front-facing or back-facing relative to a global vector, allowing subsequent filling algorithms to resolve ambiguity by prioritizing back-facing surfaces [1506-front-back-face-flagging.md].

### [Mesh Winding Number Voxelization](2328-mesh-winding-number-voxelization.md)
Determines the interior of a mesh by evaluating the Mesh Winding Number (MWN) at sample points within a voxel grid. Unlike Ray-Cast Style Voxel Filling [1502-ray-cast-style-voxel-filling.md] or Front/Back Face Flagging [1506-front-back-face-flagging.md], which rely on ray intersection parity or face orientation, MWN provides a robust signed distance-like field that handles meshes with holes and non-manifold geometry gracefully. It sets itself apart by yielding an integer value for closed meshes and a smoothly diffusing value around open boundaries, allowing for a consistent threshold-based classification [2328-mesh-winding-number-voxelization.md].

### [Polyhedron Moment Integration and Voxelization](3722-polyhedron-moment-integration-and-voxelization.md)
Computes the polynomial density moments of a convex polyhedron within a voxel grid by recursively splitting the polyhedron along its longest axis until it occupies single voxels, then integrating the polynomial density field over the resulting polyhedron volume for each voxel [3722-polyhedron-moment-integration-and-voxelization.md]. It differs from Stochastic Ray-Casting Voxelization [1067-stochastic-ray-casting-voxelization.md] and Ray-Cast Style Voxel Filling [1502-ray-cast-style-voxel-filling.md] by providing exact analytic integration of density moments rather than stochastic or rasterization-based approximations, and from Mesh Winding Number Voxelization [2328-mesh-winding-number-voxelization.md] by supporting arbitrary polynomial density orders (not just binary occupancy) [3722-polyhedron-moment-integration-and-voxelization.md].

### [Point-Containment Voxelization](3882-point-containment-voxelization.md)
Converts a 3D solid model into a 3D grid of voxels by determining which voxels intersect the solid's volume. It achieves this by sampling the grid vertices and checking their containment against the solid's Boundary Representation (BRep). It is distinguished from sibling methods by its reliance on exact geometric containment queries for grid vertices rather than ray casting, winding numbers, or stochastic sampling [3882-point-containment-voxelization.md].

### [CPU Solid Voxelization](6756-cpu-solid-voxelization.md)
A deterministic, CPU-based algorithm that fills the interior of a triangle mesh into a voxel grid by projecting triangles onto the Y-Z plane and sweeping along the X-axis [6756-cpu-solid-voxelization.md]. It determines which voxels are inside the mesh by testing voxel centers against the projected 2D triangle and calculating the maximum X-intersection, then filling all voxels from the origin up to that intersection [6756-cpu-solid-voxelization.md]. Unlike Stochastic Ray-Casting Voxelization [1067-stochastic-ray-casting-voxelization.md] which uses probabilistic sampling, or Ray-Cast Style Voxel Filling [1502-ray-cast-style-voxel-filling.md] which casts rays per voxel, this method uses exact geometric projection and edge traversal logic derived from the Schwarz-Seidel approach [6756-cpu-solid-voxelization.md]. It differs from Front/Back Face Flagging [1506-front-back-face-flagging.md] by explicitly computing the X-extent of the surface intersection rather than relying on normal orientation flags alone [6756-cpu-solid-voxelization.md].

## Operating characteristics
-   **Time Complexity**: $O(N^3 \cdot \log T)$, where $N$ is the grid resolution and $T$ is the number of triangles in the mesh. The $\log T$ factor comes from the spatial index query [S2, unofficial]. Without a spatial index, it is $O(N^3 \cdot T)$, which is prohibitive for large meshes.
-   **Memory Complexity**: $O(N^3)$ for the dense bitmap. For high resolutions, this can be significant. Sparse representations can reduce this to $O(V)$, where $V$ is the number of interior voxels [4391-sparse-and-hierarchical-structures.md].
-   **Measured Performance**: At resolution 32, the method is relatively fast for simple meshes but becomes slow for complex meshes due to the large number of containment queries [S2, unofficial]. The "Tight" post-processing step adds significant overhead [S3, unofficial].
-   **Strengths**: Robust to non-manifold geometry and self-intersections when using stochastic or winding-based containment tests. Simple to implement if a robust point-in-mesh function is available.
-   **Limitations**: Computationally expensive for high resolutions. Requires a watertight mesh for consistent results with simple containment tests.
-   **When to Use**: When robustness to mesh quality is more important than speed, or when the mesh is known to be watertight and simple.
-   **When Not to Use**: For real-time applications or very high-resolution grids where performance is critical. Consider sparse voxelization or hierarchical structures [4391-sparse-and-hierarchical-structures.md] in such cases.

## Background
Interior Voxelize is a fundamental technique in volume rendering and 3D computer graphics for converting polygonal meshes into voxel grids. The specific implementation using point containment tests with spatial acceleration structures is popularized by tutorials and libraries such as those by gradientspace [S2, unofficial] and the differentiable volumetric rendering framework [S1, unofficial]. The "Tight Voxelization" variant is documented in open-source voxelizers like topskychen/voxelizer [S3, unofficial]. The method builds on the general principles of voxelization [12-voxelization.md], specifically the occupancy determination step.
