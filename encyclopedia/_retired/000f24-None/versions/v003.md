# Perspective-Correct Point Splatting Vertex Shader

Also called: Point Splatting with Perspective Correction

## Overview
This method renders point clouds as splats (quads or points) in a vertex shader, applying size attenuation based on perspective projection to ensure the visual size of points corresponds to their world-space radius [S1, unofficial]. It differs from its siblings by explicitly calculating the point size in the vertex shader using the projection matrix and depth, rather than relying on hardware extensions or post-hoc footprint evaluation [S1, unofficial][S2, unofficial]. It builds on [Splat Kernels and Footprints](8724-splat-kernels-and-footprints.md) [S1, unofficial].

## How it works
**Inputs:**
- `in_position`: The world-space position of the point.
- `particle_radius`: The world-space radius of the point splat.
- `in_color`: The color of the point.
- `view_proj_matrix`: The combined view-projection matrix.
- `fov_y`: The vertical field of view in radians.
- `viewport_size`: The dimensions of the viewport (specifically height).

**Outputs:**
- `gl_Position`: Clip-space position.
- `gl_PointSize`: The size of the point in screen space.
- `VertOut`: A struct passing `particle_radius` and `in_color` to the fragment shader.

**Data Structures:**
- `VertOut`:
  - `float particle_radius`
  - `vec3 in_color`

**Steps:**
1. Transform the input position `in_position` to clip space using the `view_proj_matrix` and assign the result to `gl_Position` [S1, unofficial].
2. Calculate `gl_PointSize` using the perspective-correct formula:
   $$ \text{gl\_PointSize} = \text{viewport\_height} \times \frac{1}{\tan(\text{fov\_y} / 2)} \times \frac{\text{particle\_radius}}{\text{gl\_Position.w}} $$
   This scales the point size inversely with depth (`gl_Position.w`) [S1, unofficial].
3. Pass the `particle_radius` and `in_color` to the fragment shader via the output struct `VertOut` [S1, unofficial].

**Parameters:**
- `fov_y`: The vertical field of view in radians, used to calculate perspective scaling [S1, unofficial].
- `viewport_size`: The dimensions of the viewport, specifically `viewport_size[1]` (height) is used for scaling [S1, unofficial].
- `particle_radius`: The world-space radius of the point splat [S1, unofficial].

**Pseudocode:**
```python
import math

def vertex_shader(in_position, particle_radius, in_color, view_proj_matrix, fov_y, viewport_height):
    # Step 1: Transform to clip space
    clip_pos = view_proj_matrix @ [in_position[0], in_position[1], in_position[2], 1.0]
    gl_Position = clip_pos

    # Step 2: Calculate perspective-correct point size
    tan_half_fov = math.tan(fov_y / 2.0)
    gl_PointSize = viewport_height * (1.0 / tan_half_fov) * (particle_radius / gl_Position[3])

    # Step 3: Pass data to fragment shader
    out = {"particle_radius": particle_radius, "in_color": in_color}
    return out
```

## Subtopics

### Point Scaling via OpenGL Point Parameter
A technique to scale points automatically according to distance from the eye point using the OpenGL point parameter extension, overcoming the limitation of standard `glPointSize` which does not support perspective scaling [S2, unofficial]. It provides a conservative lower bound for point sizing to prevent holes [S2, unofficial]. The lower bound formula is $z^2 \ge d^2 \cdot k$, where $d$ is the distance to the eye and $k = (1 + 2\tan^2(\theta/2))^{-1}$ [S2, unofficial]. The conservative point diameter is $D = \frac{H}{2\sqrt{2} \cdot d \cdot k \cdot \tan(\theta/2)}$ [S2, unofficial]. To match this derived diameter $D$, set $D_0 = 1$, $a = 0$, $b = 0$, and $c = \frac{2 k \tan^2(\theta/2)}{H^2}$ in the OpenGL point size formula $D = D_0 \sqrt{\frac{1}{a + b d + c d^2}}$ [S2, unofficial]. A pitfall is that the point parameter extension scales according to distance $d$, not the $z$-coordinate; using a lower bound for $z$ ensures the point size is never smaller than the true size, preventing holes [S2, unofficial].
