# SparseGrid

Also called: SparseGrid Data Structure

## Overview
SparseGrid is a sparse adaptive grid that allocates memory only for cells explicitly added to the structure, making it suitable for large domains containing small active regions [S1, unofficial]. It differs from dense grids by storing only active cell indices and their associated values on the device, and differs from tree-based structures by using a flat, index-based layout rather than hierarchical pointers [S1, unofficial].

## How it works
**Inputs and Outputs:**
The structure is initialized with a global `shape` (uint3, number of sample points per dimension), an axis-aligned bounding box (`aabb_min`, `float3`, default $[-1, -1, -1]$), `aabb_max` (float3, default $[1, 1, 1]$), and a `default_value` (float, default `FLT_MAX`) for unset points [S1, unofficial]. The primary inputs are 1D `int32` tensors of linear cell indices for adding or removing cells, and the outputs are tensors of corner coordinates, scalar values, and connectivity information [S1, unofficial].

**Data Structures:**
The core data structure resides on the GPU and consists of the following private members [S1, unofficial]:
*   `thrust::device_vector<float> values`: Stores scalar values at cell corners.
*   `thrust::device_vector<uint> cell_indices`: Stores the linear indices of all active cells.
*   `uint3 shape`: The dimensions of the implied lattice $(N_x, N_y, N_z)$.
*   `float3 aabb_min`: Minimum corner of the bounding box.
*   `float3 aabb_max`: Maximum corner of the bounding box.
*   `float default_value`: Value for unset points.

**Linear Indexing:**
Cells are identified by linear indices within the implied lattice defined by `shape` [S1, unofficial]. A cell at integer coordinates $(x, y, z)$ maps to a linear index $i$ calculated as:
$$ i = x + y \cdot N_x + z \cdot N_x \cdot N_y $$
where $0 \le x < N_x$, $0 \le y < N_y$, and $0 \le z < N_z$ [G].

**Operations:**
1. **Add Cells:** `add_cells` accepts a 1D `int32` tensor of linear indices [S1, unofficial]. These indices are added to the `cell_indices` vector [S1, unofficial].
2. **Remove Cells:** `remove_cells` accepts a 1D `int32` tensor of linear indices [S1, unofficial]. These are removed from the `cell_indices` vector [S1, unofficial].
3. **Get Points:** `get_points_by_cell_indices` takes a 1D `int32` tensor of cell indices and returns an $(N, 8, 3)$ `float32` tensor containing the 3D coordinates of the 8 corners for each of the $N$ active cells [S1, unofficial]. The coordinates are derived by mapping the integer cell indices to the continuous space defined by `aabb_min` and `aabb_max` [G].
4. **Get Values:** `get_values` returns an $(N, 8)$ `float32` tensor of scalar values at the corners of the active cells [S1, unofficial]. If a corner value is not explicitly set, it defaults to `default_value` [S1, unofficial].
5. **Filter Cell Indices:** `filter_cell_indices` takes `cell_indices`, `values` (shape $N, 8$), and a `level` (default 0.0) [S1, unofficial]. It returns a 1D `int32` tensor containing only the indices of cells where the iso-surface (defined by `level`) intersects the cell volume [S1, unofficial].
6. **Get Cell Count:** Returns `cell_indices.size()` [S1, unofficial].
7. **Get Point Count:** Returns `cell_indices.size() * 8` [S1, unofficial].
8. **Get Grid View:** Returns a `GridView` struct containing `shape`, `aabb_min`, `aabb_max`, pointers to `values.data().get()` and `cell_indices.data().get()`, and a boolean flag set to `true` [S1, unofficial].
9. **Get Dual Quads:** Returns a tuple of `thrust::device_vector<int4>`, `thrust::device_vector<bool>`, and `thrust::device_vector<uint2>` [S1, unofficial]. It takes `NDArray<uint2> edges` and `NDArray<bool> is_out` as input to construct dual mesh geometry [S1, unofficial].

**Pseudocode:**
The following Python-like pseudocode illustrates the data access and basic operations.

```python
class SparseGrid:
    def __init__(self, shape: tuple, aabb_min: tuple, aabb_max: tuple, default_value: float = float('inf')):
        self.shape = shape
        self.aabb_min = aabb_min
        self.aabb_max = aabb_max
        self.default_value = default_value
        self.cell_indices = []
        self.values = {}

    def add_cells(self, indices: list):
        for idx in indices:
            if idx not in self.cell_indices:
                self.cell_indices.append(idx)
                if idx not in self.values:
                    self.values[idx] = [self.default_value] * 8

    def remove_cells(self, indices: list):
        for idx in indices:
            if idx in self.cell_indices:
                self.cell_indices.remove(idx)
            if idx in self.values:
                del self.values[idx]

    def get_points_by_cell_indices(self, indices: list):
        points = []
        dx = (self.aabb_max[0] - self.aabb_min[0]) / (self.shape[0] - 1)
        dy = (self.aabb_max[1] - self.aabb_min[1]) / (self.shape[1] - 1)
        dz = (self.aabb_max[2] - self.aabb_min[2]) / (self.shape[2] - 1)
        for idx in indices:
            x = idx % self.shape[0]
            y = (idx // self.shape[0]) % self.shape[1]
            z = idx // (self.shape[0] * self.shape[1])
            cell_points = []
            for i in range(8):
                cx = (i >> 0) & 1
                cy = (i >> 1) & 1
                cz = (i >> 2) & 1
                px = self.aabb_min[0] + (x + cx) * dx
                py = self.aabb_min[1] + (y + cy) * dy
                pz = self.aabb_min[2] + (z + cz) * dz
                cell_points.append((px, py, pz))
            points.append(cell_points)
        return points

    def get_values(self, indices: list):
        vals = []
        for idx in indices:
            if idx in self.values:
                vals.append(self.values[idx])
            else:
                vals.append([self.default_value] * 8)
        return vals

    def filter_cell_indices(self, indices: list, values: list, level: float = 0.0):
        crossing_indices = []
        for i, idx in enumerate(indices):
            cell_vals = values[i]
            if min(cell_vals) < level < max(cell_vals):
                crossing_indices.append(idx)
        return crossing_indices

    def get_cell_count(self):
        return len(self.cell_indices)

    def get_point_count(self):
        return len(self.cell_indices) * 8

    def get_grid_view(self):
        return {
            "shape": self.shape,
            "aabb_min": self.aabb_min,
            "aabb_max": self.aabb_max,
            "values_ptr": self.values,
            "cell_indices_ptr": self.cell_indices,
            "valid": True
        }

    def get_dual_quads(self, edges, is_out):
```

**Edge Cases and Pitfalls:**
*   **Precision:** Linear indexing assumes integer coordinates fit within the `uint` range [G]. For very large `shape` values, overflow may occur [G].
*   **Boundaries:** The `shape` defines the number of sample points, meaning there are `shape[0]-1` cells in the x-dimension [G]. Indices must be strictly within $[0, N_x \cdot N_y \cdot N_z - 1]$ [G].
*   **Default Value:** Unset points default to `FLT_MAX` (or `default_value`) [S1, unofficial]. This can affect iso-surface filtering if the level is high [G].

## Operating characteristics
*   **Time Complexity:** Adding or removing cells is $O(1)$ amortized per cell if using hash-based lookup, or $O(N)$ if using linear scan [G]. `get_points` and `get_values` are $O(N)$ where $N$ is the number of active cells [S1, unofficial].
*   **Memory Complexity:** $O(N)$ where $N$ is the number of active cells [S1, unofficial]. Memory usage is proportional to the number of active cells, not the total domain size [S1, unofficial].
*   **Performance:** Suitable for large domains with sparse active regions [S1, unofficial]. Not given in the sources for specific hardware benchmarks.
*   **Scaling:** Scales linearly with the number of active cells [G].
*   **Strengths:** Low memory overhead for sparse data; simple flat layout allows for efficient GPU parallel processing [S1, unofficial].
*   **Limitations:** No hierarchical traversal acceleration; requires explicit management of active cells [S1, unofficial].
*   **When to use:** Ideal for large domains where only small iso-surface regions are active [S1, unofficial].
*   **When not:** Unsuitable for dense volumes or when hierarchical traversal acceleration is required [G].

## Background
SparseGrid is a sparse adaptive grid implementation that inherits from a base `Grid` class and stores values and cell indices on the device [S1, unofficial]. It is designed to support efficient iso-surface extraction on GPU by providing a flexible sparse data structure [S1, unofficial]. The implementation leverages Thrust for device-side memory management and parallel operations [S1, unofficial].
