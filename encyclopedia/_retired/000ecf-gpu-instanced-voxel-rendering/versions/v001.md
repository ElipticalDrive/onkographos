# GPU-Accelerated Image-Aligned Splatting Framework

Also called: Early Z-Culling Splatting, Post-shaded Splatting

## Overview
An object-order rendering approach for scattered data points (ellipsoidal or spherical kernels) using front-to-back compositing, spatial decomposition, and GPU-based early z-culling for occlusion culling and splat elimination [S1]. It differs from its parent [Ellipsoidal Kernel Splatting with Warped Slicing](1290-ellipsoidal-kernel-splatting-with-warped-slicing.md) by replacing the warped slicing planes with a direct screen-aligned slicing pass that outputs vertex attributes for GPU rasterization, enabling efficient occlusion culling via early Z-tests [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ scattered data points, each defined by an ellipsoid (13 floating-point parameters) and a scalar density value $d \in [0, 1]$.
*   **Output:** A final composited frame-buffer image with normalized density values.

**Data Structures:**
1.  **Spatial Decomposition (CPU-side):** A low-resolution 3D cubic block grid. Each grid cell maintains a list of indices of points that intersect it. This structure is traversed in front-to-back order relative to the camera.
2.  **Input Textures (GPU-side):** Three 2D textures storing the 13 ellipsoid parameters packed into floating-point channels. The Z and Y elements of the translation matrix $T$ are packed together to fit the data.
3.  **Intermediate Textures (GPU-side):** Three destination textures (Multiple Render Targets - MRT) storing the 12 output values per ellipsoid:
    *   Starting position of the first intersecting slice in screen space: $(p_x, p_y, p_z)$.
    *   2D axis-aligned slicing polygon vectors: $(u_x, u_y)$ and $(v_x, v_y)$.
    *   Difference vector to the next slicing polygon.
    *   Starting position in unit texture space: $(0, 0, \text{StartZ}_{us})$.
    *   Scalar density (modified to encode vertex identity).
4.  **Slicing Buffer (GPU-side):** A buffer storing reconstructed density slices and accumulated splatted weights for normalization.

**Numbered Steps:**

1.  **Preprocessing (CPU):** Decompose the volume into the low-resolution cubic block data structure. For each grid point, maintain a list of intersecting points. Flatten this 3D structure onto a set of four 2D textures by copying cell contents [S1].
2.  **Ellipsoid Slicing (Fragment Program):** Process all data points as textures. For each point, calculate the intersection with the current image-aligned slicing plane. Output the 12 values described above into the 3 destination textures using MRT [S1].
3.  **Vertex Array Generation:** Convert the sliced data into vertex attribute arrays in GPU memory. The cells are processed in front-to-back order [S1].
4.  **Splatting Vertex Program:**
    *   Receive a uniform variable `currentSlicingZ` representing the z-value of the current image-aligned slicing plane.
    *   For each vertex (representing a corner of a slicing polygon), check if the point intersects the current slice.
    *   If intersecting: Compute corner positions and texture coordinates.
    *   If not intersecting: Cull the point by setting coordinates outside the view frustum [S1].
    *   **Vertex Identity Encoding:** The density value is modified to encode which of the 4 polygon corners the vertex represents:
        $$ d_{encoded} = \frac{\text{vertexCount} \pmod 4}{1000} + d_{input} $$
        where $\text{vertexCount}$ is the index of the vertex within the quad [S1].
5.  **Rasterization:** Render polygons using `GL_QUAD` primitives. Replicate point data for each destination vertex (4 corners) [S1].
6.  **Kernel Slicing and Accumulation:**
    *   Slice the 3D spherical kernel using texture mapping of a 2D Gaussian kernel.
    *   Modulate the 2D kernel by a 1D Gaussian along the z-direction.
    *   Compute the 1D Gaussian value in the vertex shader [S1].
    *   Accumulate kernel contributions into the slicing buffer. Maintain splatted weights in a separate channel of the slicing buffer [S1].
7.  **Normalization and Compositing (Fragment Program):**
    *   Retrieve the reconstructed density $D$ and accumulated weight $W$ for each pixel.
    *   Normalize the density to handle sparse coverage at boundaries:
        $$ D_{normalized} = \frac{D}{\max(W, 1)} $$
    *   Perform classification, shading, and front-to-back compositing to the final frame-buffer [S1].

**Pitfalls and Edge Cases:**
*   **Boundary Artifacts:** At volume boundaries, coverage is sparse, and accumulated weights $W$ are smaller than one. Dividing by small $W$ causes unnaturally high density values. The solution is to threshold the weight at 1 before division [S1].
*   **Ghost Points Alternative:** An alternative solution is to add "ghost points" with zero density and normal weight values around boundaries, mimicking regular volumes with infinite coverage. However, this requires additional data management, whereas the thresholding method is self-contained [S1].

```python
# 1. Preprocessing (CPU)
def preprocess_volume(points, grid_resolution):
    """
    Decompose volume into a low-resolution cubic block data structure.
    Returns a list of cells, where each cell contains a list of point indices.
    """
    grid = create_3d_grid(grid_resolution)
    for point in points:
        cell = get_intersecting_cell(point, grid)
        cell.point_list.append(point)
    return flatten_to_2d_textures(grid)

# 2. Ellipsoid Slicing (Fragment Program)
def slice_ellipsoids(input_textures, current_view_matrix):
    """
    Process all data points as textures.
    Returns 3 destination textures with 12 values per ellipsoid.
    """
    dest_textures = create_mrt_textures(3)
    for point in input_textures:
        # Extract 13 ellipsoid parameters
        params = unpack_ellipsoid_params(point)
        
        # Calculate screen-aligned slicing intersection
        # Returns: px, py, pz, ux, uy, vx, vy, diff_vector, start_z_us
        slice_data = compute_screen_aligned_slice(params, current_view_matrix)
        
        # Encode vertex identity into density for later use in vertex shader
        # Note: This is a placeholder for the actual MRT assignment logic
        # The density value is modified as: density = (vertexCount % 4) / 1000 + inputScalarDensity
        # Since this is per-point, we store the base density and vertex count separately
        # or encode it during the vertex replication step.
        
        write_to_mrt(dest_textures, slice_data)
    return dest_textures

# 3. Splatting Vertex Program
def splat_vertex_program(vertex_index, current_slicing_z, vertex_data):
    """
    Determines if a vertex intersects the current slice and computes its position.
    """
    # vertex_data contains: px, py, pz, ux, uy, vx, vy, density_encoded
    px, py, pz = vertex_data.position
    ux, uy = vertex_data.u_vector
    vx, vy = vertex_data.v_vector
    density_encoded = vertex_data.density
    
    # Check intersection with current slicing plane
    if intersects_slice(pz, current_slicing_z):
        # Compute corner positions based on vertex identity (encoded in density)
        corner_id = int(density_encoded * 1000) % 4
        
        # Calculate corner position in screen space
        if corner_id == 0:
            pos = (px, py, pz)
        elif corner_id == 1:
            pos = (px + ux, py + uy, pz)
        elif corner_id == 2:
            pos = (px + vx, py + vy, pz)
        elif corner_id == 3:
            pos = (px + ux + vx, py + uy + vy, pz)
            
        # Compute texture coordinates for kernel lookup
        tex_coords = compute_texture_coords(corner_id, ux, uy, vx, vy, current_slicing_z)
        
        return VertexOutput(position=pos, tex_coords=tex_coords, density=density_encoded)
    else:
        # Cull by setting coordinates outside view frustum
        return VertexOutput(position=NEGATIVE_INFINITY, tex_coords=None, density=0)

# 4. Kernel Slicing and Accumulation (Vertex/Fragment Program)
def accumulate_kernel_contributions(vertex_output, kernel_texture):
    """
    Accumulate kernel contributions into the slicing buffer.
    """
    # Compute 1D Gaussian value in vertex shader
    z_gaussian = compute_1d_gaussian(vertex_output.position.z)
    
    # Sample 2D Gaussian kernel from texture
    kernel_value = sample_2d_gaussian(kernel_texture, vertex_output.tex_coords)
    
    # Modulate by 1D Gaussian
    total_kernel = kernel_value * z_gaussian
    
    # Accumulate into slicing buffer
    slicing_buffer.density += total_kernel * vertex_output.density
    slicing_buffer.weight += total_kernel

# 5. Normalization and Compositing (Fragment Program)
def normalize_and_composite(slicing_buffer, final_framebuffer):
    """
    Normalize densities and composite to final frame-buffer.
    """
    density = slicing_buffer.density
    weight = slicing_buffer.weight
    
    # Threshold weight at 1 to prevent high density values at boundaries
    normalized_weight = max(weight, 1.0)
    
    normalized_density = density / normalized_weight
    
    # Perform classification, shading, and compositing
    color = classify_and_shade(normalized_density)
    composite_to_framebuffer(final_framebuffer, color, normalized_density)
```

## Operating characteristics
*   **Time Complexity:** The slicing step is performed once per viewpoint change. Measured timings for this step are 30-90 msec for datasets of 35K-500K points [S1].
*   **Memory Complexity:** Requires GPU memory for input textures (13 floats per point packed into 3 textures), intermediate MRT textures (12 values per point), and the slicing buffer. The spatial decomposition structure is stored on the CPU and transferred to GPU textures [S1].
*   **Strengths:** Achieves very high quality images even for sparse datasets at high magnifications and interactive frame-rates. Early Z-culling allows for efficient occlusion culling and splat elimination [S1].
*   **Limitations:** Requires MRT extension support (available on NVidia and ATI boards at the time of publication). The need to re-slice and regenerate vertex arrays on every viewpoint change can be costly for dynamic scenes [S1].
*   **When to use:** Suitable for static or slowly changing scattered data volumes where high-quality rendering of ellipsoidal kernels is required and GPU hardware supports MRT and vertex programs [S1].
*   **When not to use:** Not suitable for highly dynamic scenes where viewpoint changes frequently, due to the cost of re-slicing and vertex array generation. Also not suitable if MRT support is unavailable [S1].

## Background
This method was introduced in the paper "GPU-Accelerated Volume Splatting With Elliptical RBFs" by the authors of [S1]. It extends existing GPU-accelerated image-aligned splatter algorithms to handle unstructured data sets consisting of arbitrarily oriented general ellipsoids of various sizes. The work addresses the challenges of implementing object-order rendering with front-to-back compositing on the GPU without expensive sorting or bucketing operations, by using a spatial decomposition data structure and early Z-culling [S1].
