# Chunk Border Neighbor Access

Also called: Read-only neighborhood view, VoxelNeighborhood trait

## Overview
Chunk Border Neighbor Access is a strategy for handling neighbor lookups at chunk boundaries in chunk-based voxel data structures by treating chunk borders as semantically identical to internal voxels [S1, unofficial]. It solves the problem of cross-chunk geometry culling (such as face removal) by providing a unified interface for accessing adjacent voxels, regardless of whether they reside in the same chunk or a different one [S1, unofficial]. Unlike methods that embed chunk-transition logic into the meshing algorithm, this approach separates neighbor retrieval from geometry generation, allowing the mesher to remain agnostic of the underlying storage layout [S1, unofficial].

## How it works
The method relies on a trait or interface that abstracts the retrieval of voxel states. The core input is a 3D integer coordinate (position) relative to the world or chunk origin, and the output is the state of the voxel at that position, or a null/empty state if the voxel is outside the world or the required chunk is unavailable [S1, unofficial].

### Data Structures
The primary data structure is the `VoxelNeighborhood` trait, which defines a single method for accessing voxel data [S1, unofficial]:

```rust
trait VoxelNeighborhood {
    fn get(&self, position: IVec3) -> Option<BlockState>;
}
```

Here, `IVec3` represents a 3D integer coordinate, and `BlockState` represents the voxel type or material [S1, unofficial]. The return type `Option<BlockState>` allows for handling cases where the queried position is invalid or the data is missing [S1, unofficial].

### Algorithm Steps
1.  **Query Interface**: The meshing algorithm calls `neighborhood.get(position)` for any voxel it needs to inspect, including those on the boundary of the current chunk [S1, unofficial].
2.  **Internal Lookup**: If the `position` falls within the bounds of the current chunk, the method returns the voxel state from the local flat array [S1, unofficial].
3.  **Cross-Chunk Lookup**: If the `position` falls outside the current chunk (i.e., it is a neighbor chunk), the method resolves the target chunk index and retrieves the voxel state from that chunk's data [S1, unofficial].
4.  **Missing Data Handling**: If the target chunk is not currently loaded or available in memory, the method must apply a predefined policy [S1, unofficial]. Common policies include:
    *   Treating missing data as air (empty) and remeshing later when the chunk is loaded [S1, unofficial].
    *   Delaying meshing until all required neighbor chunks are present [S1, unofficial].
    *   Returning an explicit "unknown" state to indicate incomplete data [S1, unofficial].
5.  **Semantic Consistency**: The method ensures that a face on the edge of a chunk is treated as having a normal voxel neighbor, with the only difference being the source of the data retrieval [S1, unofficial].

### Parameters and Edge Cases
*   **Chunk Availability**: The correctness of the neighbor access depends on the world-streaming model. If a neighbor chunk is not loaded, the behavior is undefined unless a policy is explicitly defined [S1, unofficial].
*   **Transparency**: The method does not inherently handle material semantics. For example, two adjacent glass blocks may geometrically cover each other, but whether their shared face should be removed depends on material/rendering rules, which are applied after the neighbor state is retrieved [S1, unofficial].
*   **Precision**: The method assumes integer coordinates. Floating-point precision issues are not addressed by this method but may affect the `lies_on_boundary` checks in the meshing algorithm [S1, unofficial].

### Pseudocode
The following pseudocode illustrates the implementation of the `VoxelNeighborhood` trait for a chunk-based system. It assumes a `ChunkManager` is available to resolve chunk indices and load chunks if necessary.

```python
class VoxelNeighborhood:
    def __init__(self, chunk_manager):
        self.chunk_manager = chunk_manager

    def get(self, position: IVec3) -> Option[BlockState]:
        """
        Retrieves the voxel state at the given global position.
        Returns None if the position is out of bounds or the chunk is unavailable.
        """
        # 1. Determine the chunk index and local offset
        chunk_pos = self.chunk_manager.get_chunk_index(position)
        local_pos = self.chunk_manager.get_local_offset(position, chunk_pos)

        # 2. Check if the chunk is available
        chunk = self.chunk_manager.get_chunk(chunk_pos)
        if chunk is None:
            # Policy: Treat missing data as air
            return BlockState.AIR

        # 3. Retrieve the voxel from the chunk
        # Note: This assumes the chunk has a method to access its internal array
        voxel = chunk.get_voxel(local_pos)
        return voxel
```

## Subtopics

### Chunk Neighbor Referencing for Boundary Meshing
Precomputes pointers to adjacent chunks to handle meshing at chunk boundaries without global lookups [S2, unofficial]. It calculates chunk access indices using `GetAccessLocal(chunkPosX, chunkPosY, chunkPosZ)` and determines neighbor pointers for X, Y, Z axes using precomputed strides (`CHUNK_STEP_X`, `CHUNK_STEP_Y`, `CHUNK_STEP_Z`) [S2, unofficial]. If a neighbor is out of bounds, it assigns a sentinel chunk (`Map.EMPTY_CHUNK` or `Map.FULL_CHUNK`) based on the `ShouldMeshExterior` flag [S2, unofficial]. The strides are defined as: `CHUNK_STEP_Y = 1`, `CHUNK_STEP_X = MaxChunkAmount`, and `CHUNK_STEP_Z = MaxChunkAmountSquared` [S2, unofficial]. This method is chosen when static chunk layouts are used and boundary meshing performance is critical [S2, unofficial].

### Padded Chunk Data Structure
A 3D array of voxels with 1-voxel boundary padding on all sides to allow neighbor lookups without bounds checks [S3, unofficial]. The linearization index for a 3D coordinate `[x, y, z]` in a padded chunk with X innermost is `index = x + PADDED_CHUNK_SIZE * (y + PADDED_CHUNK_SIZE * z)` [S3, unofficial]. The data structure is a flat array of type `[VoxelBlock; PADDED_CHUNK_VOLUME]` where `PADDED_CHUNK_SIZE = CHUNK_SIZE_U32 + 2` and `PADDED_CHUNK_VOLUME = PADDED_CHUNK_SIZE^3` [S3, unofficial]. This method is chosen when avoiding conditional checks during neighbor access is more important than memory overhead [S3, unofficial].

## Operating characteristics
*   **Time Complexity**: Neighbor lookup is $O(1)$ if the chunk is loaded and the offset is calculated directly [S1, S2, unofficial]. If chunk loading is required, it depends on the chunk manager's efficiency [S1, unofficial].
*   **Memory Complexity**: The trait itself adds negligible memory overhead [S1, unofficial]. The padded variant adds $O(CHUNK\_SIZE^2)$ memory per chunk for the boundary padding [S3, unofficial].
*   **Strengths**: Simplifies meshing code by removing chunk-boundary logic [S1, unofficial]. Consistent interface for all voxel accesses [S1, unofficial].
*   **Limitations**: Requires a robust chunk management system to handle cross-chunk lookups and missing data [S1, unofficial]. Padding increases memory usage [S3, unofficial].
*   **When to Use**: When the meshing algorithm needs to access neighbors across chunk boundaries frequently and consistently [S1, unofficial].
*   **When Not to Use**: When memory is extremely constrained and padding is prohibitive [S3, unofficial]. When chunk boundaries are not aligned with geometry culling needs.

## Background
The concept of treating chunk borders as semantically identical to internal voxels was introduced in the context of face culling for voxel cubes and partial shapes [S1, unofficial]. The `VoxelNeighborhood` trait was proposed as a way to abstract neighbor access, allowing meshers to remain independent of the storage layout [S1, unofficial]. The padded chunk data structure is a common optimization in voxel engines to simplify neighbor access [S3, unofficial]. The chunk neighbor referencing method with precomputed strides is used in specific meshing implementations for performance [S2, unofficial].
