# Trilinear Interpolation

Also called: Trilinear Interpolant, 3D Linear Interpolation, Trilinear Interpolation for Rectilinear Grids

## Overview
Trilinear interpolation estimates the scalar field value at an arbitrary point within a voxel grid by computing a weighted average of the eight surrounding voxel corner values [S1, S6, S9, unofficial]. It solves the problem of sampling continuous volume data at non-integer coordinates, which occurs because ray casting sample points rarely align exactly with voxel centers [S4, unofficial]. Compared to nearest-neighbor interpolation, trilinear interpolation produces significantly smoother images with fewer aliasing artifacts, though it requires approximately five times more computation time [S1, S4, unofficial]. It serves as the foundational reconstruction scheme for direct volume ray casting on regular grids [S1, unofficial].

## How it works
**Inputs:**
*   A 3D scalar field defined on a regular grid with dimensions $D_x \times D_y \times D_z$.
*   A query point $P = (x, y, z)$ in voxel space.

**Outputs:**
*   A single scalar value $V$ representing the interpolated density or intensity at $P$.

**Data Structures:**
*   The volume data is stored in a 3D array (or flattened 1D array with row-major indexing).
*   Voxel values are accessed via integer indices $(i, j, k)$ where $0 \le i < D_x$, $0 \le j < D_y$, $0 \le k < D_z$.

**Algorithm Steps:**

1.  **Coordinate Normalization and Offset:**
    If the input coordinates are in world space, convert them to voxel space. Let $P_{voxel}$ be the position in voxel coordinates. To ensure that a sample point located exactly at the center of a voxel returns that voxel's value (and not an average of neighbors), shift the coordinate by $-0.5$ along each axis [S1, S6, unofficial].
    $$ P_{lattice} = P_{voxel} - 0.5 $$
    [G] If the grid uses a rectilinear structure with non-uniform spacing, the offset and interpolation weights must be computed using the specific coordinate arrays $X, Y, Z$ rather than simple integer arithmetic [S10, unofficial]. For this article, we assume a regular grid with unit cell sizes as is standard for the basic definition [S2, unofficial].

2.  **Determine Containing Voxel:**
    Compute the integer indices of the lower-left-front corner of the voxel containing $P_{lattice}$ using the floor function:
    $$ i_0 = \lfloor P_{lattice}.x \rfloor $$
    $$ j_0 = \lfloor P_{lattice}.y \rfloor $$
    $$ k_0 = \lfloor P_{lattice}.z \rfloor $$
    [G] Clamp these indices to valid bounds. Specifically, if $i_0 \ge D_x - 1$, set $i_0 = D_x - 2$ (and similarly for $j, k$) to ensure the upper neighbor index $i_0+1$ does not exceed the grid boundary [S9, S7, unofficial].

3.  **Compute Fractional Weights:**
    Calculate the fractional distance from the lower-left corner to the query point within the voxel. These fractions serve as interpolation weights.
    $$ w_x = P_{lattice}.x - i_0 $$
    $$ w_y = P_{lattice}.y - j_0 $$
    $$ w_z = P_{lattice}.z - k_0 $$
    Note that $w_x, w_y, w_z \in [0, 1)$.

4.  **Retrieve Corner Values:**
    Fetch the scalar values from the eight corners of the containing voxel. Let $V_{ijk}$ denote the value at grid index $(i, j, k)$. The eight values are:
    *   $V_{000} = V_{i_0, j_0, k_0}$
    *   $V_{100} = V_{i_0+1, j_0, k_0}$
    *   $V_{010} = V_{i_0, j_0+1, k_0}$
    *   $V_{110} = V_{i_0+1, j_0+1, k_0}$
    *   $V_{001} = V_{i_0, j_0, k_0+1}$
    *   $V_{101} = V_{i_0+1, j_0, k_0+1}$
    *   $V_{011} = V_{i_0, j_0+1, k_0+1}$
    *   $V_{111} = V_{i_0+1, j_0+1, k_0+1}$

5.  **Perform Trilinear Interpolation:**
    The final value is the sum of the corner values weighted by the product of their respective distances to the query point. The weight for a corner is the product of the "closeness" factors $(1-w)$ or $w$ for each dimension.
    
    Using the expanded form [S1, S9, unofficial]:
    $$
    \begin{aligned}
    V = \;& V_{000}(1-w_x)(1-w_y)(1-w_z) + V_{100}w_x(1-w_y)(1-w_z) \\
    + \;& V_{010}(1-w_x)w_y(1-w_z) + V_{110}w_x w_y (1-w_z) \\
    + \;& V_{001}(1-w_x)(1-w_y)w_z + V_{101}w_x(1-w_y)w_z \\
    + \;& V_{011}(1-w_x)w_y w_z + V_{111}w_x w_y w_z
    \end{aligned}
    $$
    
    Alternatively, this can be computed sequentially using three linear interpolations (lerp) [S2, S7, unofficial]:
    1.  Interpolate along X for the bottom face ($k=k_0$) and top face ($k=k_0+1$):
        $$ C_{00} = \text{lerp}(V_{000}, V_{100}, w_x) $$
        $$ C_{10} = \text{lerp}(V_{010}, V_{110}, w_x) $$
        $$ C_{01} = \text{lerp}(V_{001}, V_{101}, w_x) $$
        $$ C_{11} = \text{lerp}(V_{011}, V_{111}, w_x) $$
    2.  Interpolate along Y for the resulting pairs:
        $$ C_0 = \text{lerp}(C_{00}, C_{10}, w_y) $$
        $$ C_1 = \text{lerp}(C_{01}, C_{11}, w_y) $$
    3.  Interpolate along Z:
        $$ V = \text{lerp}(C_0, C_1, w_z) $$
    
    Where $\text{lerp}(a, b, t) = a(1-t) + bt$.

**Pseudocode:**

```python
def trilinear_interpolation(volume, dims, p_voxel):
    """
    volume: 3D array of scalar values, shape (Dx, Dy, Dz)
    dims: tuple (Dx, Dy, Dz)
    p_voxel: tuple (x, y, z) in voxel space (center-aligned)
    """
    # 1. Shift by -0.5 to align voxel centers with integer grid
    p_lattice = (p_voxel[0] - 0.5, p_voxel[1] - 0.5, p_voxel[2] - 0.5)
    
    # 2. Compute lower-left indices
    i0 = int(p_lattice[0])
    j0 = int(p_lattice[1])
    k0 = int(p_lattice[2])
    
    # 3. Clamp indices to ensure upper neighbors are within bounds
    # If p_lattice is exactly at the boundary, floor might give index == dim-1
    # We need i0 < Dx-1, so clamp i0 to Dx-2 max
    i0 = max(0, min(i0, dims[0] - 2))
    j0 = max(0, min(j0, dims[1] - 2))
    k0 = max(0, min(k0, dims[2] - 2))
    
    # 4. Compute fractional weights
    wx = p_lattice[0] - i0
    wy = p_lattice[1] - j0
    wz = p_lattice[2] - k0
    
    # 5. Fetch 8 corner values
    # Indices: (i0+i, j0+j, k0+k) for i,j,k in {0,1}
    v000 = volume[i0][j0][k0]
    v100 = volume[i0+1][j0][k0]
    v010 = volume[i0][j0+1][k0]
    v110 = volume[i0+1][j0+1][k0]
    v001 = volume[i0][j0][k0+1]
    v101 = volume[i0+1][j0][k0+1]
    v011 = volume[i0][j0+1][k0+1]
    v111 = volume[i0+1][j0+1][k0+1]
    
    # 6. Interpolate along X
    c00 = v000 * (1 - wx) + v100 * wx
    c10 = v010 * (1 - wx) + v110 * wx
    c01 = v001 * (1 - wx) + v101 * wx
    c11 = v011 * (1 - wx) + v111 * wx
    
    # 7. Interpolate along Y
    c0 = c00 * (1 - wy) + c10 * wy
    c1 = c01 * (1 - wy) + c11 * wy
    
    # 8. Interpolate along Z
    result = c0 * (1 - wz) + c1 * wz
    
    return result
```

**Parameters:**
*   **Grid Assumption:** Regular grid with unit lengths in all three cell dimensions [S2, unofficial]. If the grid is rectilinear (non-uniform spacing), the weights $w_x, w_y, w_z$ must be calculated as normalized distances between the coordinate arrays $X, Y, Z$ [S10, unofficial].
*   **Precision:** Standard single-precision floating point is typically sufficient, but care must be taken with boundary conditions to avoid out-of-bounds memory access [S9, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** If the query point lies outside the volume bounds, the algorithm must handle out-of-bounds access. Common strategies include clamping the indices to the nearest valid voxel or returning a default value (e.g., 0) [S10, S9, unofficial].
*   **Center Alignment:** Without the $-0.5$ offset, a sample point at the exact center of a voxel would incorrectly average all 8 neighbors instead of returning the voxel's own value [S1, S6, unofficial].
*   **Cache Coherence:** Naive access patterns to voxel buffers can lead to poor cache coherence, significantly impacting performance [S6, unofficial]. Tiled storage schemes are recommended for production [S6, unofficial].
*   **Artifacts:** Trilinear interpolation introduces $C^1$ discontinuities (false edges or "star patterns") because the triangular pulse reconstruction kernel has infinite extent in the frequency domain [S5, unofficial]. This manifests as apparent sharpness not present in the data [S5, unofficial].

## Subtopics

### [Plenoxels Interpolation Methods](935-plenoxels-interpolation-methods.md)
Samples voxel values using nearest neighbor, trilinear, or tricubic interpolation to reconstruct the continuous radiance field from discrete voxel grids.

### [Multi-Texture Trilinear Estimation](1164-multi-texture-trilinear-estimation.md)
An algorithm that substitutes trilinear interpolation with two bilinear interpolations and one linear interpolation to improve image quality over basic 2D texture rendering.

### [Semi-Analytical Volume Rendering with Trilinear Interpolation](1312-semi-analytical-volume-rendering-with-trilinear-interpolatio.md)
Semi-analytical volume rendering with trilinear interpolation is a direct volume ray casting technique for hexahedral cells that eliminates topological artifacts (discontinuities, holes) in isosurfaces by analytically determining optimal sampling points along the ray. It sets itself apart from standard trilinear interpolation [1531-trilinear-interpolation.md] by replacing uniform sampling with a piecewise-linear approximation over monotonic intervals defined by the analytical extrema of the reconstructed signal, ensuring no isovalue is missed.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample, requiring exactly 8 memory fetches and 7 linear interpolations (or equivalent arithmetic operations) [S2, S5, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary space. The data structure is the volume grid itself, $O(N_x N_y N_z)$.
*   **Performance:** Trilinear interpolation takes approximately 5 times longer to compute than nearest-neighbor lookup [S1, unofficial]. It is significantly faster than higher-order methods like tri-cubic interpolation but provides lower image quality [S6, unofficial].
*   **Strengths:** Simple to implement, computationally efficient, produces smoother results than nearest-neighbor, widely supported by hardware texture units (often via bilinear + linear approximation) [S1027-hardware-interpolation-approximation.md].
*   **Limitations:** Introduces blurring and $C^1$ discontinuities (false edges) [S5, unofficial]. Not suitable for high-fidelity reconstruction where sharp features must be preserved without aliasing.
*   **When to use:** General-purpose volume rendering where performance is critical and high-frequency artifacts are acceptable or mitigated by other means (e.g., supersampling).
*   **When not to use:** When high-frequency accuracy is required (use [Fast tri-cubic interpolation](848-fast-tri-cubic-interpolation.md) or [Frequency Domain Volume Rendering with Sinc Resampling](826-frequency-domain-volume-rendering-with-sinc-resampling.md)), or when rendering rectilinear grids with significant non-uniformity without proper weight calculation [S10, unofficial].

## Background
Trilinear interpolation is a standard technique in computer graphics and scientific visualization for sampling 3D scalar fields. It is derived from the tensor product of 1D linear interpolation kernels [S2, unofficial]. The method is fundamental to direct volume ray casting on regular grids [S1, unofficial]. It is implemented in various libraries, including OpenVDB, which uses a nested interpolation structure for sparse voxel grids [S1, unofficial]. The mathematical properties of the trilinear interpolant, including the existence of saddle points, have been analyzed in the context of Marching Cubes and isosurface extraction [S3, unofficial].
