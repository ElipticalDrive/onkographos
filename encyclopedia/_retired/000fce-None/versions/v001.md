# Task Shader Block-wise Stream Compaction

Also called: Task Shader Cell Classification and Task Generation

## Overview
Task Shader Block-wise Stream Compaction is a GPU-driven occlusion culling technique that identifies volume blocks containing isosurface geometry and generates proxy geometry to determine the potentially visible set (PVS) of blocks [S1, S2]. It solves the problem of high draw times in volumes with high depth complexity by avoiding the extraction and rendering of geometry for blocks that are occluded [S2][S3, unofficial]. Unlike methods that process the depth texture of a previously established occluder representation, such as hierarchical occlusion maps [ZMHH97] or iterative depth warping [LKE18], this approach rasterizes proxy geometry directly [S1, S2]. It is a hybrid between basic raster occlusion culling [KT14] and hierarchical approaches [LL20], resolving potential visibility only for fixed-size blocks using a custom task and mesh shader pipeline [S3, unofficial].

## How it works
The method operates in two shader stages: a task shader for block-wise stream compaction and a mesh shader for proxy geometry creation. It processes volume data organized into fixed-size blocks.

**Inputs:**
- Volume data (implicit or explicit).
- Min-max texture storing the minimum and maximum scalar values for each volume block.
- Isovalue threshold for isosurface extraction.

**Outputs:**
- A list of potentially visible blocks (implicitly defined by the mesh shader workgroups launched).
- Rasterized proxy geometry for visibility testing.

**Data Structures:**
- `min_max_texture`: A 3D texture where each texel corresponds to a volume block, storing the minimum and maximum scalar values within that block.
- `block_occupancy_index`: A dense array of indices pointing to occupied blocks. This array is built by the task shader.
- `num_occupied_blocks`: A scalar value indicating the total number of occupied blocks found in the current task shader workgroup.

**Parameters:**
- Block size: Fixed size (e.g., $8 \times 8 \times 8$ cells, though the exact cell count per block is not specified, the block grouping is fixed) [S1, S2].
- Task shader workgroup size: Processes a localized group of 256 blocks [S1].
- Mesh shader workgroup size: Processes sets of 32 occupied blocks [S1].

**Steps:**

1.  **Task Shader: Block-wise Stream Compaction**
    The task shader analyzes a localized group of 256 blocks [S1].
    1.  For each block in the group, sample the min-max texture at the block's location.
    2.  Determine occupancy: A block is occupied if the isovalue lies between the sampled minimum and maximum values ($min \le isovalue \le max$) [S1].
    3.  Generate a dense list of occupied blocks. This is done using a local prefix sum algorithm for stream compaction, avoiding atomic variables to improve performance [S1, S2].
    4.  Store the indices of occupied blocks in the `block_occupancy_index` array.
    5.  Count the total number of occupied blocks (`num_occupied_blocks`).
    6.  Emit mesh shader workgroups. Each workgroup processes 32 occupied blocks, except the final workgroup which may process between 1 and 32 blocks [S1]. No list offset or length buffers are required because workgroups operate on fixed-length lists [S1].

2.  **Mesh Shader: Proxy Geometry Creation**
    Each mesh shader workgroup processes a set of 32 occupied blocks [S1].
    1.  Each thread in the mesh shader workgroup computes an offset into the `block_occupancy_index` array based on its thread and workgroup indices [S1].
    2.  Ensure the computed index is less than `num_occupied_blocks` [S1].
    3.  Each active thread creates proxy geometry for one occupied block [S1].
    4.  Proxy geometry consists of a single quad containing the bounding box of the block projected into screen space with the minimal z-coordinate of the block's corners [S1]. This reduces triangles from 6 to 2 per block, primitives per workgroup from 224 to 64, and vertices from 224 to 128 [S1].
    5.  Write the vertex and index buffers for the blocks' quad proxies [S1].

3.  **Rasterization**
    1.  Rasterize the proxy geometry [S1, S2].
    2.  Fragments that pass the early depth test and the representative fragment test [KTB*18] write to a buffer to indicate visibility [S1].
    3.  Rasterizing fewer primitives increases the likelihood of early termination of rasterization via the representative fragment test, leading to fewer buffer writes in the subsequent fragment shader stage [S1].

**Pseudocode:**

```python
# Task Shader Stage
# Input: min_max_texture, isovalue
# Output: block_occupancy_index, num_occupied_blocks

def task_shader_block_wise_stream_compaction():
    # Process a localized group of 256 blocks
    occupied_count = 0
    for block_idx in range(256):
        # Sample min-max texture for the current block
        min_val, max_val = sample_min_max_texture(block_idx)
        
        # Determine occupancy
        if min_val <= isovalue <= max_val:
            # Add to dense list using local prefix sum (avoiding atomics)
            # This step implicitly handles the compaction
            block_occupancy_index[occupied_count] = block_idx
            occupied_count += 1
            
    num_occupied_blocks = occupied_count
    
    # Emit mesh shader workgroups
    # Each workgroup processes 32 blocks, except the last one
    num_workgroups = (num_occupied_blocks + 31) // 32
    for wg_idx in range(num_workgroups):
        launch_mesh_shader_workgroup(wg_idx, num_occupied_blocks)

# Mesh Shader Stage
# Input: block_occupancy_index, num_occupied_blocks
# Output: Vertex and Index buffers for proxy geometry

def mesh_shader_proxy_geometry_creation(thread_idx, workgroup_idx, num_occupied_blocks):
    # Compute offset into block_occupancy_index array
    base_offset = workgroup_idx * 32
    index = base_offset + thread_idx
    
    # Ensure index is within bounds
    if index < num_occupied_blocks:
        occupied_block_idx = block_occupancy_index[index]
        
        # Create proxy geometry for the occupied block
        # Proxy geometry is a single quad with minimal z-coordinate
        vertices = create_quad_proxy(occupied_block_idx)
        indices = create_quad_indices()
        
        # Write to vertex and index buffers
        write_vertex_buffer(vertices)
        write_index_buffer(indices)
```

**Edge Cases and Pitfalls:**
- **Precision:** Sampling the min-max texture must be precise enough to correctly determine occupancy.
- **Boundaries:** The final mesh shader workgroup may process fewer than 32 blocks, requiring bounds checking [S1].
- **Multi-view Rendering:** When using multi-view rendering features to rasterize proxy geometry per-eye in a joint pass, generating one quad per eye facilitates implementation. Rendering more than 3 sides of a cube would require accounting for blocks located between the viewer's eyes on cardinal axes [S1].

## Subtopics

### [Raster Occlusion Culling](1562-raster-occlusion-culling.md)
Raster Occlusion Culling determines the visibility of voxel blocks by replacing expensive individual hardware occlusion queries with a single efficient proxy geometry rasterization pass, followed by GPU-driven stream compaction to create a dense list of occupied subvolumes. It solves the problem of high draw times in volumes with high depth complexity by avoiding the extraction and rendering of geometry for blocks that are occluded. Unlike methods that process the depth texture of a previously established occluder representation, such as hierarchical occlusion maps [ZMHH97] or iterative depth warping [LKE18], this approach rasterizes proxy geometry directly. It is a hybrid between basic raster occlusion culling [KT14] and hierarchical approaches [LL20], resolving potential visibility only for fixed-size blocks using a custom task and mesh shader pipeline.

### [PVS Compactification and Temporal Coherence Pass](1563-pvs-compactification-and-temporal-coherence-pass.md)
This compute shader pass compactifies the raw visibility indices generated by the preceding raster occlusion culling stage and constructs two distinct Potentially Visible Set (PVS) datasets: $PVS_{curr}$ and $PVS_{curr-prev}$. It solves the problem of efficiently preparing visibility data for temporal coherence by identifying blocks visible in the current frame and those newly visible since the last frame, enabling the selection of optimal occluders for subsequent rendering passes. It differs from sibling methods like [Raster Occlusion Culling](1562-raster-occlusion-culling.md) by focusing on data structure construction and temporal history management rather than the initial geometric visibility test.

### GPU-driven Visibility Culling
A culling technique that uses per-subchunk metadata (AABB, terrain/water draw ranges) to test visibility on the GPU and emit indirect draw commands only for visible subchunks [S3, unofficial]. It tests the AABB of each subchunk against the view frustum or camera position and emits indirect draw commands only for subchunks that pass the visibility test [S3, unofficial]. It utilizes the `MULTI_DRAW_INDIRECT_COUNT` GPU feature, which allows the GPU to control how many indirect draw commands are executed, enabling dynamic draw counts [S3, unofficial].

## Operating characteristics
- **Time Complexity:** The task shader processes 256 blocks per workgroup, and the mesh shader processes 32 occupied blocks per workgroup. The complexity is linear with respect to the number of blocks processed.
- **Memory Complexity:** Requires storage for the `block_occupancy_index` array and the min-max texture. No list offset or length buffers are required [S1].
- **Performance:** Rasterizing fewer primitives (2 triangles per block instead of 6) reduces the number of primitives per workgroup from 224 to 64 and vertices from 224 to 128 [S1]. This increases the likelihood of early termination of rasterization via the representative fragment test [KTB*18], leading to fewer buffer writes [S1].
- **Strengths:** Reduces the number of task shader workgroups launched by avoiding extraction of geometry for occluded blocks [S1]. Exploits view-dependent visibility information via GPU-driven occlusion culling [S1, S2]. Conservative visibility determination [S1, S2].
- **Limitations:** Resolves potential visibility only for fixed-size blocks [S1, S2]. Requires a custom task and mesh shader pipeline [S1, S2].
- **When to use:** Volumes with high depth complexity where occlusion culling can significantly reduce the number of primitives to be rendered [S1, S2].
- **When not to use:** Volumes with low depth complexity where the overhead of the culling pass may not be justified.

## Background
The technique was introduced in "Efficient Direct Isosurface Rasterization of Scalar Volumes" [S1, S2]. It builds on prior work in raster occlusion culling [KT14, LL20] and probabilistic culling [IRR*22]. The method is influenced by the PMB algorithm, determining occupancy on a block level [S1, S2]. It addresses the limitations of ray-marching-based approaches, which have a linear dependence on display resolution, by leveraging the highly optimized rasterization units in modern GPUs [S1, S2].
