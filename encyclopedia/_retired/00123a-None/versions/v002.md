# Wilhelms and Van Gelder Octree

## Overview
A hierarchical spatial subdivision method using an octree to accelerate cell extraction by pruning branches that cannot contain the isosurface [S1, unofficial].

## How it works
**Inputs:** Volume data $V$, isovalue $t$, octree structure [S1, unofficial].
**Outputs:** Set of cells intersecting the isosurface $t$ [S1, unofficial].

**Data Structures:**
Each node $n$ in the octree corresponds to a rectilinear block $B$ of cells $C_{i,j,k}$ [S1, unofficial]. Each node is attributed an interval $[n_{min}, n_{max})$, defined as the union of all intervals $[v_{min}, v_{max}]$ of the cells belonging to the block [S1, unofficial].
$$ [n_{min}, n_{max}) = \bigcup_{C_{i,j,k} \in B} [v_{min}, v_{max}] $$
where for each cell $C_{i,j,k}$:
$$ v_{min} = \min V_{i,j,k}, \quad v_{max} = \max V_{i,j,k} $$
This interval represents the range of values the interpolation function $\hat{f}$ attains in the portion of the volume corresponding to node $n$ [S1, unofficial].

**Algorithm Steps:**
1. **Build Octree:** Construct the octree from the volume data [G]. For each node, compute $n_{min}$ and $n_{max}$ by aggregating the min/max values of its child cells or children nodes [S1, unofficial].
2. **Recursive Traversal:** Start at the root node [G].
3. **Pruning:** For a current node $n$, check if the isovalue $t$ lies within the node's bounding interval $[n_{min}, n_{max})$ [S1, unofficial].
    * If $t \notin [n_{min}, n_{max})$, ignore this branch entirely [S1, unofficial].
    * If $t \in [n_{min}, n_{max})$, proceed to children (if internal) or process cells (if leaf) [S1, unofficial].
4. **Leaf Processing:** For leaf nodes $n$ where $t \in [n_{min}, n_{max})$, investigate cells cell-by-cell using the standard enumeration algorithm to extract the isosurface geometry [S1, unofficial].

**Pseudocode:**
```python
def extract_isosurface_octree(node, t):
    """
    Recursively traverse the octree to find cells intersecting isovalue t.
    node: OctreeNode with fields .min_val, .max_val, .is_leaf, .children, .cells
    t: float, the isovalue
    Returns: List of cells intersecting the isosurface
    """
    # Pruning step: if t is outside the range of values in this node's block,
    # no cell in this block can contain the isosurface.
    if not (node.min_val <= t < node.max_val):
        return []

    if node.is_leaf:
        # Leaf node: process cells individually
        intersecting_cells = []
        for cell in node.cells:
            # Check if cell contains isovalue t
            if cell.min_val <= t < cell.max_val:
                intersecting_cells.append(cell)
        # The sources state to investigate leaf cells cell-by-cell using the enumeration algorithm [S1, unofficial].
        # The specific enumeration step (e.g., Marching Cubes lookup) is a standard method [G].
        return intersecting_cells
    else:
        # Internal node: recurse into children
        all_cells = []
        for child in node.children:
            all_cells.extend(extract_isosurface_octree(child, t))
        return all_cells
```

**Parameters:**
* $t$: Isovalue. Typical values depend on the dataset [G].
* Octree depth: Determined by the desired resolution or data characteristics. Not given in the sources.

**Edge Cases:**
* **Precision:** Floating-point comparisons for $t \in [n_{min}, n_{max})$ must handle boundary conditions carefully. The interval is half-open $[n_{min}, n_{max})$ [S1, unofficial].
* **Degenerate Input:** If $n_{min} = n_{max}$, the interval is a single point. If $t = n_{min}$, it is included; if $t = n_{max}$, it is excluded [S1, unofficial].

## Subtopics

### [View-Dependent Isosurface Extraction](2309-view-dependent-isosurface-extraction.md)
A method that extracts and renders only the visible portions of an isosurface to reduce polygon count and rendering time, exploiting depth complexity and occlusion in large datasets. It differs from non-view-dependent isocontouring by skipping internal sections that are occluded by the external isosurface, and from Greene's method by marking triangles as visible in software and forwarding them to graphics hardware for final visibility determination rather than rendering the visible portion in software.

## Operating characteristics
* **Time Complexity:** Linear time complexity $O(n)$ with respect to the size of the volume data in the worst case, but considerable acceleration is achieved in practice by ignoring irrelevant branches [S1, unofficial].
* **Memory Complexity:** Moderate additional CPU storage space is required to store the octree structure and the bounding intervals for each node [S1, unofficial].
* **Strengths:** Accelerates cell extraction by avoiding unnecessary processing of cells that do not contain the isosurface [S1, unofficial].
* **Limitations:** Requires additional memory for the octree. Performance gain depends on the sparsity of the isosurface relative to the volume [S1, unofficial].

## Background
Proposed by Wilhelms and Van Gelder as a method to accelerate cell extraction using hierarchical spatial subdivision [S1, unofficial].
