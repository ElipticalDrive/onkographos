# Instancing with Procedural/Shader Generation

Also called: Instanced Voxel Rendering with Palette Textures, Palette-based Voxel Rendering, Voxel Instancing

## Overview
Instancing with Procedural/Shader Generation renders a voxel model by submitting a single unit cube mesh as an instanced primitive, where each instance represents a single voxel [S1, unofficial]. It solves the problem of high CPU overhead and memory bandwidth consumption associated with generating unique geometry for every voxel by decoupling the geometric shape (the cube) from the per-voxel attributes (position and color) [S1, unofficial]. Unlike [Naive Voxel Rendering](1103-naive-voxel-rendering.md), which may generate explicit vertex buffers for all faces, or [Sparse Voxel Rasterization](3032-sparse-voxel-rasterization.md), which uses complex acceleration structures, this method relies on hardware instancing to transform a minimal base mesh into a volumetric representation using per-instance data buffers and palette textures [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A voxel grid defined by occupied indices $(i, j, k)$, a 2D palette texture mapping UV coordinates to base colors, and camera/lighting parameters.
*   **Output:** A rasterized image of the voxel model with Phong shading.

**Data Structures:**
1.  **Instance Buffer (VBO):** A contiguous array of floating-point values bound to `GL_ARRAY_BUFFER` with `GL_STATIC_DRAW` usage hint [S1, unofficial].
    *   **Layout:** Each instance consists of exactly 5 floats:
        1.  `offsetX` (float): X-coordinate of the voxel center.
        2.  `offsetY` (float): Y-coordinate of the voxel center.
        3.  `offsetZ` (float): Z-coordinate of the voxel center.
        4.  `u` (float): S-coordinate for palette texture sampling.
        5.  `v` (float): T-coordinate for palette texture sampling.
    *   **Size:** $N_{instances} \times 5 \times 4$ bytes [S1, unofficial].
2.  **Palette Texture:** A 2D texture (e.g., `GL_RGBA8`) storing the base colors for the voxel materials [S1, unofficial].
3.  **Base Geometry:** A single unit cube mesh (typically 24 vertices for flat shading or 8 for shared shading) representing the voxel shape [S1, unofficial].

**Parameters:**
*   **Lighting:** Ambient intensity ($0.35$), Specular intensity ($0.5$), Shininess ($32$), Light position $(10, 15, 10)$ [S1, unofficial].
*   **Texture Sampling:** Wrap modes set to `GL_CLAMP_TO_EDGE` for both S and T axes to prevent boundary artifacts [S1, unofficial].

**Numbered Steps:**
1.  **Instance Data Generation:** For each occupied voxel at grid index $(i, j, k)$, calculate the world-space offset. If the source format uses Z-up (e.g., `.vly`), swap Y and Z coordinates to align with OpenGL's Y-up convention: `localY = gridZ`, `localZ = gridY` [S1, unofficial]. Assign a UV coordinate $(u, v)$ to the voxel based on its material or index. Pack these into the 5-float structure.
2.  **Buffer Upload:** Upload the packed instance data to the GPU via `glBufferData` or `glBufferSubData` [S1, unofficial].
3.  **Vertex Shader Execution:** For each vertex of the base cube, the vertex shader receives the local vertex position $P_{local}$ and the instance offset $O_{instance}$ [S1, unofficial].
    *   Compute the combined world position: $P_{combined} = P_{local} + O_{instance}$ [S1, unofficial].
    *   Transform to clip space: $P_{clip} = M_{MVP} \times [P_{combined}, 1.0]^T$ [S1, unofficial].
    *   Pass the instance UVs $(u, v)$ to the fragment shader via a varying/interpolator [S1, unofficial].
4.  **Fragment Shader Execution:** For each rasterized fragment:
    *   Sample the base color from the palette texture: $C_{base} = \text{texture}(u_{PaletteTexture}, v_{UV})$ [S1, unofficial].
    *   Compute lighting using a Phong model:
        *   Ambient: $C_{ambient} = C_{base} \times I_{ambient}$
        *   Diffuse: $C_{diffuse} = C_{base} \times \max(\mathbf{N} \cdot \mathbf{L}, 0.0)$
        *   Specular: $C_{specular} = \mathbf{1.0} \times \rho \times I_{specular}$ (where $\rho$ is the specular factor derived from shininess) [S1, unofficial].
    *   Combine: $C_{final} = C_{ambient} + C_{diffuse} + C_{specular}$ [S1, unofficial].
5.  **Rasterization and Culling:** The GPU rasterizes the instanced cubes. Back-face culling is enabled to discard faces oriented away from the camera [S1, unofficial].

**Pseudocode:**

```python
# Vertex Shader Logic (GLSL-like pseudocode)
# Inputs:
#   aLocalPosition: vec3, vertex position of the unit cube
#   aInstanceOffset: vec3, offset from instance buffer
#   aInstanceUV: vec2, UV from instance buffer
#   uMVPMatrix: mat4, Model-View-Projection matrix

void main() {
    // Combine local geometry with instance position
    vec3 combinedPos = aLocalPosition + aInstanceOffset;
    
    // Transform to clip space
    gl_Position = uMVPMatrix * vec4(combinedPos, 1.0);
    
    // Pass UV to fragment shader
    vUV = aInstanceUV;
}

# Fragment Shader Logic (GLSL-like pseudocode)
# Inputs:
#   vUV: vec2, interpolated UV coordinates
#   uPaletteTexture: sampler2D, the color palette
#   uLightPosWorld: vec3, light position in world space
#   uCameraPosWorld: vec3, camera position in world space
#   uAmbientIntensity: float, ambient light strength
#   uSpecularIntensity: float, specular light strength
#   uShininess: float, specular shininess exponent

void main() {
    // Sample base color from palette
    vec3 baseColor = texture(uPaletteTexture, vUV).rgb;
    
    // Calculate lighting vectors (assuming normal N is available from geometry)
    vec3 N = normalize(gl_FrontFacing ? normal : -normal); // Simplified normal handling
    vec3 L = normalize(uLightPosWorld - gl_FragCoord.xyz); // Approximation for demo
    vec3 V = normalize(uCameraPosWorld - gl_FragCoord.xyz);
    vec3 H = normalize(L + V);
    
    // Phong Lighting Model
    float diff = max(dot(N, L), 0.0);
    float spec = pow(max(dot(N, H), 0.0), uShininess);
    
    vec3 ambient = baseColor * uAmbientIntensity;
    vec3 diffuse = baseColor * diff;
    vec3 specular = vec3(1.0) * spec * uSpecularIntensity;
    
    gl_FragColor = vec4(ambient + diffuse + specular, 1.0);
}
```

**Edge Cases and Pitfalls:**
*   **Coordinate System Mismatch:** Source formats may use different up-axes (e.g., Z-up in `.vly` vs Y-up in OpenGL). This must be handled during offset calculation by swapping axes [S1, unofficial].
*   **Texture Artifacts:** Sampling at the edges of the palette texture can cause bleeding if wrap modes are not set to `GL_CLAMP_TO_EDGE` [S1, unofficial].

## Subtopics

### [Surface-based Instancing with Noise Modulation](1582-surface-based-instancing-with-noise-modulation.md)
Generates high-density point clouds from parametric surface primitives to approximate volumetric effects like smoke or fire [1582-surface-based-instancing-with-noise-modulation.md]. It differs from standard surface rendering by treating the surface as a distribution of discrete particles rather than a continuous triangle mesh, and from pure particle systems by deriving point positions from a structured surface parameterization ($s,t$) [1582-surface-based-instancing-with-noise-modulation.md].

### [3D Gaussian Splatting via Instancing](1586-3d-gaussian-splatting-via-instancing.md)
Renders volumetric data or 2D Gaussian projections by submitting a single instanced draw call per Gaussian primitive [1586-3d-gaussian-splatting-via-instancing.md]. It solves the problem of efficiently rendering millions of semi-transparent primitives by dynamically sizing quads based on opacity and computing the Gaussian decay in the fragment shader, setting itself apart by explicitly handling the spatial extent and opacity cutoff of Gaussian kernels [1586-3d-gaussian-splatting-via-instancing.md].

### [GPU Instancing with Indirect Draw Calls](2205-gpu-instancing-with-indirect-draw-calls.md)
Efficiently draws millions of identical meshes by issuing a single draw command that reads instance counts and parameters from a GPU-accessible buffer [2205-gpu-instancing-with-indirect-draw-calls.md]. Unlike standard GPU instancing which requires CPU-side iteration, this method batches rendering into one or few calls, significantly reducing CPU-GPU synchronization overhead [2205-gpu-instancing-with-indirect-draw-calls.md].

### [Indirect Draw Argument Setting](2418-indirect-draw-argument-setting.md)
A compute shader kernel that sets up indirect draw arguments by multiplying vertex and instance counts and setting start indices [2418-indirect-draw-argument-setting.md].

### [Procedural Particle Rendering](2926-procedural-particle-rendering.md)
Generates particle attributes (position, velocity, color, size) on-the-fly using a seeded random number generator (RNG) rather than storing explicit particle data in memory buffers [2926-procedural-particle-rendering.md]. This method solves the memory overhead and synchronization issues of traditional particle systems by computing each particle's state deterministically from its ID and time [2926-procedural-particle-rendering.md].

### [WebGL 2 Hardware Instancing](3152-webgl-2-hardware-instancing.md)
Sends a single base primitive (typically a 2x2x2 cube) to the GPU and executes `gl.drawElementsInstanced` to render hundreds of thousands of copies simultaneously [3152-webgl-2-hardware-instancing.md]. It solves the CPU bottleneck associated with issuing individual draw calls by packing translation, scaling, and color data into flat typed arrays [3152-webgl-2-hardware-instancing.md].

### [Geometry Shader Advanced Instancing for Cubes](4576-geometry-shader-advanced-instancing-for-cubes.md)
Uses a geometry shader to generate cube meshes from instanced points, optimizing for visibility by emitting at most 12 vertices (3 quads) per cube [4576-geometry-shader-advanced-instancing-for-cubes.md]. It leverages backface culling and frustum culling in projection space to reduce the number of primitives submitted to the rasterizer [4576-geometry-shader-advanced-instancing-for-cubes.md].

### [Procedural Point Rendering with Billboard Transformation](6422-procedural-point-rendering-with-billboard-transformation.md)
Renders a sparse set of surface points as billboards using GPU procedural instancing, transforming grid-based point cloud data into world space and orienting each primitive to face the camera [6422-procedural-point-rendering-with-billboard-transformation.md]. It differs from standard voxel rasterization by decoupling the geometric representation from the dense grid structure [6422-procedural-point-rendering-with-billboard-transformation.md].

### [Buffer-Based Instancing (SSBO/Instance Buffers)](6501-buffer-based-instancing-ssbo-instance-buffers.md)
Decouples geometric data from the CPU by storing voxel attributes in GPU-accessible Shader Storage Buffer Objects (SSBOs) or structured buffers [6501-buffer-based-instancing-ssbo-instance-buffers.md]. It differs from the parent method by explicitly leveraging large, mutable GPU buffers for instance data rather than relying solely on uniform arrays or texture lookups [6501-buffer-based-instancing-ssbo-instance-buffers.md].

## Operating characteristics
*   **Time Complexity:** Setup time is $O(V)$ to compute offsets and pack data, where $V$ is the number of voxels [S1, unofficial]. Draw time is $O(1)$ draw call, with fragment shader cost proportional to the number of visible voxels [S1, unofficial].
*   **Memory Complexity:** $O(V)$ for the instance buffer (5 floats per voxel) and $O(P)$ for the palette texture, where $P$ is the number of palette entries [S1, unofficial].
*   **Performance:** Implemented in the VoxelRenderer Android application for rendering `.vly` models using OpenGL ES 3.0 [S1, unofficial]. The method is efficient for dense grids but requires careful management of instance buffer size for very large volumes.
*   **Strengths:** Minimal CPU overhead per frame after initial setup; leverages hardware instancing for high throughput; simple implementation.
*   **Limitations:** Limited to uniform voxel shapes (cubes); requires palette texture management; visibility culling is basic (frustum/back-face) unless extended with more complex acceleration structures.

## Background
This method is implemented in the VoxelRenderer Android application for rendering `.vly` voxel models using OpenGL ES 3.0 [S1, unofficial]. It builds upon the principles of instancing in graphics APIs to optimize the rendering of repetitive geometric primitives.
