# Instancing with Procedural/Shader Generation

Also called: Procedural Instancing, Shader-Generated Voxel Geometry, GPU-Driven Voxel Rendering

## Overview
Instancing with Procedural/Shader Generation renders volumetric data by submitting a minimal set of base geometry primitives (typically cubes or points) and using GPU instancing to replicate them across a scene, with per-instance attributes (position, scale, color, orientation) stored in buffers and processed in the vertex or geometry shader. It solves the problem of rendering millions of voxels without the memory and CPU overhead of storing explicit mesh data for each voxel, shifting the burden of geometry assembly to the GPU pipeline. It differs from [Binary Volume Rendering (Opacity Thresholding)](1015-binary-volume-rendering-opacity-thresholding.md) by using explicit geometric primitives rather than ray-marching a volume texture, and from [Naive Voxel Rendering](1103-naive-voxel-rendering.md) by leveraging hardware instancing to reduce draw call overhead.

## Shared principles
The core mechanism relies on three components: a shared base geometry buffer, an instance data buffer, and an instanced draw call.

1.  **Base Geometry**: A static vertex buffer containing the vertices of a single primitive, typically a unit cube centered at the origin or $(0,0,0)$ to $(1,1,1)$. To support flat shading (unique normals per face), the cube is often defined with 24 vertices (4 vertices per face $\times$ 6 faces) rather than 8. An index buffer may define the triangles for the visible faces (e.g., 3 faces $\times$ 2 triangles $\times$ 3 vertices = 18 indices) or all 6 faces (36 indices).
2.  **Instance Data Buffer**: A GPU-accessible buffer (e.g., `StructuredBuffer` in HLSL, `std430` buffer in GLSL, or `ComputeBuffer` in Unity) stores per-instance attributes. Common attributes include:
    *   **Position**: 3D coordinates $(x, y, z)$.
    *   **Occupancy/Visibility**: A scalar flag (e.g., $w$-component of a `float4`) indicating if the voxel is solid or empty.
    *   **Material/Color**: Albedo, tint, or texture atlas index.
    *   **Orientation/Shape**: Rotation matrices or indices into a precomputed rotation table.
    *   **Scale**: Uniform or non-uniform scaling factors.
3.  **Instanced Draw Call**: A single draw command (e.g., `glDrawArraysInstanced`, `DrawInstanced`, or `DrawMeshInstancedIndirect`) is issued. The number of instances corresponds to the number of elements in the instance data buffer.
4.  **Shader Processing**:
    *   **Vertex Shader**: Retrieves per-instance data using `gl_InstanceID` (or equivalent). It transforms the base geometry vertices into world space using the instance's position, rotation, and scale. It may also perform early culling (e.g., discarding empty voxels) or face culling (determining visible faces based on camera position).
    *   **Fragment Shader**: Samples textures or computes colors based on the interpolated attributes passed from the vertex shader.

## Subtopics

### [Surface-based Instancing with Noise Modulation](1582-surface-based-instancing-with-noise-modulation.md)
Generates high-density point clouds from surface primitives to achieve smooth volumetric appearance at high resolutions. It differs from sibling methods by explicitly instantiating a massive number of points (e.g., ~400 million) per primitive and modulating their density or position using procedural noise functions before rasterization or voxelization.

### [3D Gaussian Splatting via Instancing](1586-3d-gaussian-splatting-via-instancing.md)
Renders volumetric data or 2D Gaussian projections by submitting a single instanced draw call per Gaussian primitive, utilizing the standard hardware vertex/fragment pipeline to avoid the memory traffic and sorting overhead of tile-based rasterizers. It solves the problem of efficiently rendering millions of semi-transparent, oriented primitives by dynamically sizing quads based on opacity and computing the Gaussian decay in the fragment shader, setting itself apart from its parent [Instancing with Procedural/Shader Generation](2794-instancing-with-procedural-shader-generation.md) by explicitly handling the spatial extent and opacity cutoff of Gaussian kernels.

### [Procedural Instancing for Voxel Blocks](1637-procedural-instancing-for-voxel-blocks.md)
Replaces baked mesh geometry with a compact instance record per voxel, resolving position, color, and occlusion in the vertex shader using a shared cube template. It differs from surface-based instancing by operating on the full cubic grid occupancy rather than extracted surfaces, and from 3D Gaussian splatting by using hard-edged geometric primitives rather than soft volumetric blobs.

### [GPU Instancing with Indirect Draw Calls](2205-gpu-instancing-with-indirect-draw-calls.md)
Is a rendering technique that efficiently draws millions of identical meshes (voxels) by issuing a single draw command that reads instance counts and parameters from a GPU-accessible buffer, allowing the GPU to generate draw commands itself. Unlike standard GPU instancing which requires CPU-side iteration to set up per-instance data or multiple draw calls, this method batches the rendering of all instances into one or few calls, significantly reducing CPU-GPU synchronization overhead. It sets itself apart from [Surface-based Instancing with Noise Modulation](1582-surface-based-instancing-with-noise-modulation.md) by rasterizing explicit geometry rather than evaluating implicit surfaces, and from [3D Gaussian Splatting via Instancing](1586-3d-gaussian-splatting-via-instancing.md) by using discrete cube primitives rather than splatted ellipsoids.

### [Cube Rasterization via SSBO](2267-cube-rasterization-via-ssbo.md)
Is a voxel rendering technique that explicitly rasterizes the visible faces of each voxel as triangle geometry rather than using point sprites or ray-marching. It solves the problem of rendering large voxel fields with exact geometric boundaries and explicit face culling by packing voxel data into a Shader Storage Buffer Object (SSBO) and using a single large index buffer to draw 3 faces per voxel instance. It differs from [Surface-based Instancing with Noise Modulation](1582-surface-based-instancing-with-noise-modulation.md) by using explicit triangle primitives instead of implicit surface definitions, and from [Instancing with Procedural/Shader Generation](2794-instancing-with-procedural-shader-generation.md) by relying on a pre-computed index buffer for face selection rather than procedural generation in the vertex shader.

### [Procedural Particle Rendering](2926-procedural-particle-rendering.md)
Rendering particles by seeding a random number generator with particle ID, rather than storing particle data in memory.

### [Instanced Voxel Renderer](4102-instanced-voxel-renderer.md)
A GPU-driven voxel rendering technique that packs shape instances into large Shader Storage Buffer Objects (SSBOs), groups them into spatial chunks, and renders them via instanced drawing with per-chunk frustum culling.

### [Geometry Shader Advanced Instancing for Cubes](4576-geometry-shader-advanced-instancing-for-cubes.md)
A technique using geometry shaders to generate cube meshes from instanced points. It optimizes for visibility by emitting at most 12 vertices (3 quads) per cube, leveraging backface culling and frustum culling in projection space.

### Indirect Draw Argument Setting
- **Definition**: A compute shader kernel that sets up indirect draw arguments by multiplying vertex and instance counts and setting start indices [S1, unofficial].
- **Steps**:
    1.  Multiply the first element of `indirectArgsBuffer` by `vertexCountMultiplier`: `indirectArgsBuffer[0] *= vertexCountMultiplier;` [S1, unofficial].
    2.  Multiply the second element of `indirectArgsBuffer` by `instanceCountMultiplier`: `indirectArgsBuffer[1] *= instanceCountMultiplier;` [S1, unofficial].
    3.  Set the third element to `startVertex`: `indirectArgsBuffer[2] = startVertex;` [S1, unofficial].
    4.  Set the fourth element to `startInstance`: `indirectArgsBuffer[3] = startInstance;` [S1, unofficial].
    5.  Set the fifth element to 0: `indirectArgsBuffer[4] = 0;` [S1, unofficial].
- **Layout**: Buffers and Constants: `indirectArgsBuffer` (`RWStructuredBuffer<uint>`), `vertexCountMultiplier` (`uint`), `instanceCountMultiplier` (`uint`), `startVertex` (`uint`), `startInstance` (`uint`) [S1, unofficial].

### WebGL 2 Hardware Instancing
- **Definition**: A rendering technique that sends a single primitive (2x2x2 cube) to the GPU and executes `gl.drawElementsInstanced` to render hundreds of thousands of copies simultaneously, bypassing CPU bottlenecks by packing translation, scaling, and color data into flat `Float32Arrays` [S2, unofficial].
- **Steps**:
    1.  Create a base geometry buffer for positions, normals, and indices [S2, unofficial].
    2.  Create flat typed arrays for instance data: `instancePositions` (`numInstances * 3`), `instanceScales` (`numInstances`), and `instanceColors` (`numInstances * 3`) [S2, unofficial].
    3.  For each instance attribute (position, scale, color), create a buffer, bind it, upload data with `gl.bufferData`, enable the vertex attribute array, set the pointer with `gl.vertexAttribPointer`, and set the divisor to 1 using `gl.vertexAttribDivisor` [S2, unofficial].
    4.  In the vertex shader, define instancing attributes: `in vec3 aInstancePosition`, `in float aInstanceScaleY`, `in vec3 aInstanceColor` [S2, unofficial].
    5.  In the vertex shader, apply instance data to the base vertex position: `pos.y *= aInstanceScaleY; pos.xyz += aInstancePosition;` [S2, unofficial].
- **Parameters**: `gridSize`: The dimension of the square world grid, set to 500, resulting in 250,000 cubes (500x500) [S2, unofficial]. `spacing`: The distance between voxel centers, set to 2 [S2, unofficial].

### Instanced Voxelization
- **Definition**: A technique to draw all voxelization slices in a single draw call using instancing [S3, unofficial].
- **Steps**: Use instancing to draw all slices in a single draw call. Use the instance ID to specify the target slice [S3, unofficial].

### Sphere Impostors for DEM Pebbles
- **Definition**: Rendering of Discrete Element Method (DEM) pebble beds using instanced sphere impostors. Each pebble is drawn as a quad with an exact orthographic ray-sphere hit test in the fragment shader, providing sphere shading and depth [S4, unofficial].
- **Steps**:
    1.  Draw instanced quads: For each pebble, submit an instance of a quad geometry. The shader performs an exact orthographic ray-sphere intersection test per fragment [S4, unofficial].
    2.  Render to offscreen target: Draw the impostors into an offscreen target, which egui then displays. This allows interaction (orbit, zoom) while positions stream [S4, unofficial].
- **Parameters**: `Scale`: 27,000 pebbles are rendered at interactive rates [S4, unofficial]. `CPU Overhead`: Submitting a frame takes 1.2-1.3 ms of CPU time [S4, unofficial].
- **Comparison**: Fallback: If no wgpu device is available, egui discs are used as the fallback rendering method [S4, unofficial].

## Background
Instancing with procedural generation has evolved as a standard technique for rendering large-scale voxel scenes, particularly in games and simulations where memory bandwidth and draw call overhead are critical constraints. Early implementations relied on CPU-side mesh generation, which did not scale well beyond thousands of voxels. The advent of GPU instancing (e.g., `glDrawArraysInstanced` in OpenGL 3.1) allowed for the efficient rendering of millions of instances by moving the per-instance transformation logic to the vertex shader.

Key developments include:
*   **Procedural Instancing**: Techniques like those described in [Procedural Instancing for Voxel Blocks](1637-procedural-instancing-for-voxel-blocks.md) optimize memory by packing instance data into compact buffers and using shared geometry templates.
*   **Indirect Draw Calls**: Methods such as [GPU Instancing with Indirect Draw Calls](2205-gpu-instancing-with-indirect-draw-calls.md) further reduce CPU overhead by allowing the GPU to determine instance counts and parameters dynamically, often via compute shaders.
*   **Advanced Shading**: Techniques like [3D Gaussian Splatting via Instancing](1586-3d-gaussian-splatting-via-instancing.md) and [Surface-based Instancing with Noise Modulation](1582-surface-based-instancing-with-noise-modulation.md) extend the concept to soft, volumetric appearances, bridging the gap between discrete voxel rendering and continuous surface rendering.

The technique is widely used in real-time voxel engines, terrain rendering, and scientific visualization, where it provides a balance between visual fidelity and performance.
