# PSNR Metric Calculation

Also called: PSNR Calculation, PSNR Metric, Peak Signal-to-Noise Ratio

## Overview
Peak Signal-to-Noise Ratio (PSNR) is a standard benchmark metric used to evaluate the quality of reconstructed images in novel view synthesis and volume rendering by comparing rendered output against ground-truth reference images [S2, unofficial][S3, unofficial]. It quantifies the logarithmic ratio between the maximum possible pixel intensity and the Mean Squared Error (MSE) between the two images, providing a single scalar value where higher indicates better fidelity [S1, unofficial][S4]. Unlike structural metrics such as SSIM, PSNR measures pixel-level photometric error averaged over the entire frame, making it sensitive to large smooth regions but less responsive to small, high-frequency details like specular highlights [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** Two images (or volumes) of identical dimensions: the ground-truth image $I_{gt}$ and the reconstructed/predicted image $I_{pred}$. Both must have the same width $W$ and height $H$ (or voxel grid dimensions for 3D volumes).
- **Output:** A single floating-point value representing the PSNR in decibels (dB).

**Data Structures:**
- Images are treated as arrays of pixel values. For RGB images, each pixel has 3 channels (R, G, B). For grayscale or volumetric data, the channel count may vary, but the MSE calculation sums squared differences across all channels per spatial location.
- Values are typically normalized to the range $[0, 1]$ or scaled to an integer range (e.g., $[0, 255]$). The parameter $\text{MAX}$ depends on this normalization.

**Steps:**
1. **Validation:** Verify that $I_{gt}$ and $I_{pred}$ have identical spatial dimensions ($W \times H$). If dimensions mismatch, the metric is undefined or returns an error/infinity [S5, unofficial].
2. **MSE Calculation:** Compute the Mean Squared Error between the two images.
   - For each pixel $i$ from $0$ to $N-1$ (where $N = W \times H$), compute the squared difference for each channel $c$.
   - Sum these squared differences.
   - Divide by the total number of elements (pixels $\times$ channels) or pixels depending on convention. The standard definition in [S1, unofficial] and [S4] uses the mean over all pixels, summing channel differences within the pixel.
   - Formula for MSE:
     $$ \text{MSE} = \frac{1}{N} \sum_{i=0}^{N-1} \sum_{c \in \{R,G,B\}} (I_{gt,i,c} - I_{pred,i,c})^2 $$
     Note: Some implementations (like [S5, unofficial]) compute RMSE first, but PSNR requires MSE.
3. **PSNR Calculation:** Apply the logarithmic formula.
   - To prevent division by zero or $\log(0)$ when MSE is zero (perfect prediction), a small epsilon $\epsilon$ is added to the denominator or MSE [S3, unofficial].
   - Formula:
     $$ \text{PSNR} = 10 \log_{10} \left( \frac{\text{MAX}^2}{\text{MSE} + \epsilon} \right) $$
     Alternatively, using the property $\log(a/b) = \log(a) - \log(b)$:
     $$ \text{PSNR} = 20 \log_{10}(\text{MAX}) - 10 \log_{10}(\text{MSE} + \epsilon) $$
   - If $\text{MSE} = 0$, PSNR is theoretically infinite. In practice, it is capped or logged as a special value [S2, unofficial].

**Parameters:**
- **MAX:** The maximum possible pixel value. For images normalized to $[0, 1]$, $\text{MAX} = 1.0$ [S2, unofficial][S6, unofficial]. For 8-bit images, $\text{MAX} = 255$ [S4].
- **eps:** A small constant to prevent numerical instability. Commonly $10^{-10}$ [S3, unofficial].

**Pseudocode:**
```python
import math

def calculate_psnr(image_gt, image_pred, max_val=1.0, eps=1e-10):
    """
    Calculate Peak Signal-to-Noise Ratio between two images.
    
    Args:
        image_gt: Array-like of ground truth pixel values. Shape (H, W, C) or (H, W).
        image_pred: Array-like of predicted pixel values. Same shape as image_gt.
        max_val: Maximum possible pixel value (e.g., 1.0 for [0,1] normalized).
        eps: Small constant to prevent log(0).
        
    Returns:
        float: PSNR in dB.
    """
    # 1. Validate dimensions
    if image_gt.shape != image_pred.shape:
        raise ValueError("Images must have identical dimensions.")
    
    # 2. Compute MSE
    # Calculate squared differences for all pixels and channels
    squared_diffs = (image_gt - image_pred) ** 2
    
    # Mean Squared Error: average over all elements (pixels * channels)
    # Note: Some definitions average only over pixels, summing channels. 
    # Standard image processing usually averages over all elements for consistency 
    # with the MAX^2 term if MAX is per-channel or global. 
    # However, [S1, unofficial] and [S4] imply MSE is over all pixels. 
    # If MAX is the max value of a single channel (e.g. 1.0), and we sum 3 channels,
    # the numerator should technically be MAX^2 * num_channels if MSE sums channels.
    # But standard convention [S1, unofficial][S4] uses MAX^2 / MSE where MSE is mean per pixel 
    # summing channels. Let's follow the explicit formula in [S1, unofficial][S4]:
    # MSE(x,y) is mean squared error between original and reconstructed.
    # Usually, MSE = mean( (x-y)^2 ). If x,y are RGB, (x-y)^2 sums the channels.
    
    mse = numpy.mean(squared_diffs)
    
    # 3. Compute PSNR
    if mse == 0:
        return float('inf') # Or a large number like 100.0
        
    psnr = 10 * math.log10((max_val ** 2) / (mse + eps))
    
    return psnr
```

**Edge Cases and Pitfalls:**
- **Zero MSE:** If the prediction is identical to the ground truth, MSE is 0, leading to infinite PSNR. Handle with a cap or epsilon [S2, unofficial].
- **Dimension Mismatch:** If input images have different sizes, the metric is invalid [S5, unofficial].
- **Weighting Bias:** PSNR averages over all pixels. Large smooth regions dominate the error score, while small bright features (specular highlights, thin structures) have negligible impact on the final score [S1, unofficial].
- **Interpretation:** A difference of 3 dB corresponds to a halving of the squared error; 6 dB corresponds to a quartering [S1, unofficial].

## Subtopics

### [3D Evaluation Metrics](2903-3d-evaluation-metrics.md)
3D Evaluation Metrics assess the fidelity of reconstructed volumetric or radiance-field representations against ground-truth data [G]. The method computes statistical similarity metrics on voxel grids and surface geometries to evaluate both visual appearance and spatial accuracy. Unlike PSNR which measures pixel-level photometric error in 2D projections, this method aggregates errors across 3D volume dimensions (axial, coronal, sagittal) and surface normals. It complements Mesh Reconstruction Evaluation, which focuses strictly on triangular mesh topology and spatial accuracy rather than volumetric or photometric appearance.

### Noise Floor Estimation via MAD
Noise Floor Estimation via MAD uses Median Absolute Deviation (MAD) estimators to determine the noise standard deviation $\sigma$ in a volume, allowing for the calculation of a "noise floor" PSNR. This is used to determine if a model is noise-limited or signal-limited [S6, unofficial].
- **Laplacian MAD:** Compute the D-dimensional discrete Laplacian response. Scale the MAD of the response by $1/(0.6745 \cdot \sqrt{2D(2D+1)})$ to estimate $\sigma$ [S6, unofficial].
- **Haar Finite-Difference MAD:** Compute diagonal second differences $d = I(y,x) - I(y,x+1) - I(y+1,x) + I(y+1,x+1)$. Estimate $\sigma = \text{median}(|d|) / (0.6745 \cdot \sqrt{2})$ [S6, unofficial].
- **Noise Floor PSNR:** Calculated as $10 \log_{10}(1/\sigma^2)$ [S6, unofficial].
- **Pitfall:** MAD estimators may return exactly zero for some volumes (e.g., Mouse heart nuclei), indicating the model is signal-limited, not noise-limited, and thus the noise floor is not estimable [S6, unofficial].

### Benchmark Performance Numbers
Benchmark numbers provide context for typical PSNR values in modern radiance-field optimization methods on standard datasets like Mip-NeRF 360 (room scale) [S7, unofficial].
- **Vanilla 3DGS:** ~27.4 PSNR [S7, unofficial].
- **Mip-Splatting:** ~27.7 PSNR [S7, unofficial].
- **Scaffold-GS:** ~27.9 PSNR [S7, unofficial].
- **2DGS:** ~27.0 PSNR (with better geometry) [S7, unofficial].
- **GES:** Comparable PSNR to baselines with ~30% fewer primitives [S7, unofficial].
- **Hierarchical 3DGS:** Comparable performance with Level of Detail (LoD) streaming [S7, unofficial].
- **Target:** For NeRF paper Blender scenes, target PSNR is 31–33 dB [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the total number of pixels (or voxels) in the image/volume. The calculation involves a single pass to compute squared differences and a logarithmic operation.
- **Memory Complexity:** $O(N)$ if images are not in-place, or $O(1)$ auxiliary space if computing MSE incrementally.
- **Strengths:** Simple to compute, widely understood, and provides a single scalar for easy comparison. It is the standard baseline for image quality in many papers [S2, unofficial][S3, unofficial].
- **Limitations:** It does not correlate well with human perception for all types of errors, particularly structural similarities or perceptual quality (LPIPS is often preferred for this) [S1, unofficial]. It is heavily biased towards large, smooth areas [S1, unofficial].
- **When to Use:** When a quick, standard photometric error metric is required for logging during training or for comparing against historical baselines [S3, unofficial].
- **When Not to Use:** When perceptual quality is more important than pixel-wise accuracy, or when evaluating structural fidelity [S1, unofficial].

## Background
PSNR originated in signal processing and telecommunications as a measure of signal quality [S4]. It has been adopted as a standard benchmark in computer graphics, particularly for novel view synthesis and volume rendering, to evaluate the reconstruction quality of radiance fields and neural radiance fields (NeRFs) [S2, unofficial][S3, unofficial]. The metric is frequently reported alongside SSIM and LPIPS to provide a more comprehensive evaluation [S1, unofficial].
