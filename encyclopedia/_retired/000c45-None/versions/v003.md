# Froxel TAA Reprojection

Also called: EMA Blending, History Reprojection, TAA Resolve Pass, Temporal Accumulation, Temporal Accumulation with Exponential Moving Average, Temporal anti-aliasing for froxels

## Overview
Froxel TAA Reprojection is a temporal anti-aliasing technique for froxel-based volumetric rendering that achieves temporal supersampling by reusing in-scattered radiance data from the previous frame and blending it with new stochastic samples [S1, unofficial]. It solves the heavy aliasing inherent in single-sample-per-froxel rendering by estimating the light transport integral over time using an Exponential Moving Average (EMA) [S1, unofficial]. Unlike traditional pixel-based TAA which relies on geometry and depth buffers to detect disocclusions, this method operates on world-space volumetric data, requiring only camera motion reprojection and handling history validity through frustum bounds and neighborhood color extents [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Current frame froxel grid (radiance and density), history buffer 3D texture (previous frame's accumulated radiance), reprojection vector (camera motion from $t-1$ to $t$), sub-froxel jitter offset [S1, unofficial].
*   **Outputs:** Accumulated froxel grid (blended radiance and density) for the current frame [S1, unofficial].

**Data Structures:**
*   **Froxel Grid:** A 3D texture storing volumetric data [S1, unofficial]. Each texel contains radiance (RGB) and density (Alpha) [S1, unofficial]. The source notes specify using integer 3D texture lookups for the current frame values [S1, unofficial].
*   **History Buffer:** A 3D texture storing the accumulated radiance from the previous frame [S1, unofficial]. It is sampled using trilinear interpolation due to floating-point precision limitations in reprojection [S1, unofficial].
*   **Reprojection Vector:** A transformation matrix or vector describing the camera's movement and rotation from the previous frame to the current frame [S1, unofficial]. It is applied to the froxel's world-space position to map history buffer coordinates [S1, unofficial].

**Numbered Steps:**
1.  **Read Current Frame Data:** Retrieve the current frame's in-scattered radiance $s_t(p)$ and density from the froxel grid using an integer 3D texture lookup at position $p$ [S1, unofficial].
2.  **Reproject History:** Calculate the reprojected position $\pi(p)$ by applying the reprojection vector to the froxel's position $p$ [S1, unofficial]. Sample the history buffer at $\pi(p)$ using a trilinear sampler to obtain the historical radiance $f_{t-1}(\pi(p))$ [S1, unofficial].
    *   *Edge Case:* If $\pi(p)$ falls outside the bounds of the history 3D texture (e.g., outside the camera's frustum in the new frame), return the current frame values $s_t(p)$ immediately, resetting temporal accumulation for this froxel [S1, unofficial].
3.  **Color Space Transformation:** Transform both the current frame radiance $s_t(p)$ and the reprojected historical radiance $f_{t-1}(\pi(p))$ into a selected color space (e.g., YCoCg or YCbCr) to decouple luminance and chrominance [S1, unofficial]. The density (alpha channel) remains unchanged during this transformation [S1, unofficial].
4.  **History Validation (Rectification):** Apply history validation to estimate the color extent of the froxel using a neighborhood of current frame samples [S1, unofficial]. Map the historical value onto this color extent to mitigate artifacts from noisy inputs or undersampling [S1, unofficial]. The specific algorithm depends on the chosen validation method [S1, unofficial].
5.  **Blend (EMA):** Blend the rectified history with the current-frame sample using the Exponential Moving Average formula [S1, unofficial].
6.  **Inverse Transform and Store:** Transform the blended result $f_t(p)$ back into RGB space [S1, unofficial]. Store the result in the output froxel texture to be used as $f_{t-1}$ in the next frame [S1, unofficial].

**Formula:**
$$f_t(p) = \alpha \cdot s_t(p) + (1 - \alpha) \cdot f_{t-1}(\pi(p))$$
where $f_t(p)$ is the blended radiance for froxel $p$ at frame $t$, $\alpha \in [0, 1]$ is the blending factor, $s_t(p)$ is a single current-frame sample of in-scattered radiance, and $f_{t-1}(\pi(p))$ is the froxel's historical radiance value, reprojected using $\pi(p)$ [S1, unofficial].

**Parameters:**
*   **Blending Factor ($\alpha$):** Controls the weight of the new sample versus history [S1, unofficial]. Typical values are 10%, 5%, or 2% [S1, unofficial].
*   **Jitter Sequence:** A low-discrepancy sequence, commonly Halton(2,3) of length 8 or 16, used to generate sub-froxel offsets [S1, unofficial]. Sub-Froxel Temporal Jittering restricts this offset to the z-axis (depth) to reduce spatial variance [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Ghosting Artifacts:** Moving lights, animated density textures, and color changes cause blurring and smearing because the EMA reacts slowly to changes [S1, unofficial]. With $\alpha=10\%$ at 60 FPS, it takes ~1 second (60 frames) for artifacts to fade; with $\alpha=2\%$, it takes ~4 seconds (240 frames) [S1, unofficial].
*   **Flickering and Shimmering:** In regions with sharp signal changes (e.g., light sources, high-frequency noise), consecutive samples produce drastically different values, causing flickering even in static scenes [S1, unofficial].
*   **Reprojection Failure:** If the reprojection vector points outside the history buffer bounds, the current-frame sample is returned immediately, resetting temporal accumulation for that froxel [S1, unofficial].
*   **Disocclusion Handling:** Surface-related TAA techniques like using geometry and depth buffers to detect disocclusions are not viable for froxel data [S1, unofficial].
*   **View-Dependence:** Highly view-dependent phase functions can become problematic for reprojected history data [S1, unofficial].

**Pseudocode:**
```python
def froxel_taa_reprojection(froxel_pos, current_radiance, current_density, 
                            history_buffer, reprojection_vector, alpha, jitter_offset):
    # Step 1: Calculate reprojected position
    jittered_pos = froxel_pos + jitter_offset
    # Apply camera motion transformation to map history buffer coordinates [S1, unofficial]
    reprojected_pos = apply_reprojection(jittered_pos, reprojection_vector)
    
    # Step 2: Sample history buffer
    # Use trilinear sampling due to floating-point precision limitations [S1, unofficial]
    history_radiance = history_buffer.sample_trilinear(reprojected_pos)
    
    # Edge Case: Reprojection failure
    if not history_buffer.is_inside_bounds(reprojected_pos):
        # Reset temporal accumulation: return current frame values [S1, unofficial]
        return current_radiance, current_density
    
    # Step 3: Color Space Transformation
    # Transform radiance to decouple luminance/chrominance (e.g., YCoCg) [S1, unofficial]
    # Density remains unchanged
    current_radiance_cs = to_color_space(current_radiance)
    history_radiance_cs = to_color_space(history_radiance)
    
    # Step 4: History Validation (Rectification)
    # Estimate color extent from neighborhood and map history to it [S1, unofficial]
    # The sources do not specify the exact validation algorithm [G]
    rectified_history_cs = history_radiance_cs
    
    # Step 5: Blend using Exponential Moving Average
    # f_t(p) = alpha * s_t(p) + (1 - alpha) * f_{t-1}(pi(p)) [S1, unofficial]
    blended_radiance_cs = alpha * current_radiance_cs + (1 - alpha) * rectified_history_cs
    
    # Step 6: Inverse Transform and Store
    # Transform back to RGB space [S1, unofficial]
    blended_radiance = from_color_space(blended_radiance_cs)
    
    return blended_radiance, current_density
```

## Subtopics

### [Karis-Inspired Anti-Flicker](1924-karis-inspired-anti-flicker.md)
Karis-Inspired Anti-Flicker is a heuristic temporal anti-aliasing technique for froxel-based volumetric rendering that reduces visual flicker introduced by variance clipping. It biases the temporal signal towards the frame where clipping occurs, dynamically adjusting the blend factor based on the distance between the reprojected history and its clipped counterpart, offering superior stability in static scenes with high-contrast noise or spot lights without globally degrading accuracy.

### [Sub-Froxel Temporal Jittering](2092-sub-froxel-temporal-jittering.md)
Sub-Froxel Temporal Jittering is a technique for real-time volumetric rendering that offsets the sampling position within a froxel along the camera's depth axis to enable temporal supersampling and anti-aliasing. It distinguishes itself from full 3D jittering by restricting movement to the z-axis, thereby reducing spatial variance in the x and y directions to improve temporal stability when accumulating history.

## Operating characteristics
*   **Time Complexity:** O(1) per froxel per frame, assuming constant-time texture lookups and reprojection [S1, unofficial]. The cost is dominated by the compute shader pass for the froxel grid [S1, unofficial].
*   **Memory Complexity:** O(N) where N is the number of froxels, requiring storage for the current frame grid and the history buffer [S1, unofficial].
*   **Measured Performance:** The method enables real-time rendering of high-quality volumetric lighting by reducing the need for multiple samples per froxel, achieving an effectively supersampled volume at very little extra performance cost [S1, unofficial].
*   **Strengths:**
    *   Reuses previous results directly in a world-aligned grid, which is not possible in traditional per-pixel ray marching [S1, unofficial].
    *   Reprojection is straightforward as it only requires camera motion, not geometric disocclusion handling [S1, unofficial].
*   **Limitations:**
    *   **Ghosting:** Moving lights, animated density, or color changes cause blurring and smearing [S1, unofficial].
    *   **Flickering:** Sharp signal changes (e.g., light sources, high-frequency noise) cause flickering even in static scenes [S1, unofficial].
    *   **Reprojection Failure:** If the camera moves significantly, the history buffer may become unusable, resetting accumulation [S1, unofficial].
    *   **View-Dependence:** Highly view-dependent phase functions can become problematic for reprojected history data [S1, unofficial].
    *   **Disocclusion:** Surface-related TAA techniques (geometry/depth buffers) are not viable for froxel data [S1, unofficial].
*   **When to Use:** Static or slowly moving scenes with stable lighting [S1, unofficial]. Ideal for real-time volumetric fog and lighting where performance is critical and single-sample rendering is too aliased [S1, unofficial].
*   **When Not to Use:** Scenes with rapidly moving light sources or dynamic density textures, as ghosting artifacts are severe [S1, unofficial]. Not suitable if high-fidelity, artifact-free temporal stability is required without additional anti-flicker heuristics [S1, unofficial].

## Background
Froxel TAA Reprojection originated from the need to render high-quality volumetric lighting in real-time engines like Frostbite [S1, unofficial]. The method is based on the principle of temporal accumulation, a form of Monte Carlo integration that estimates light transport integrals over time using stochastic sampling [S1, unofficial]. The specific adaptation for froxels, which store world-space volumetric data rather than surface pixels, was detailed in research on temporal anti-aliasing for real-time froxel-based rendering [S1, unofficial].
