# Orthogonal BSP Tree Construction

Also called: BSP tree conversion, Orthogonal BSP

## Overview
Orthogonal BSP Tree Construction converts a set of arbitrarily sized and positioned grown boxes into an orthogonal Binary Space Partitioning (BSP) tree where every splitting plane is object-aligned [S1]. This structure enables trivial visibility sorting for 3D texture rendering, solving the problem that arbitrary box positions prevent simple sorting based on viewpoint [S1]. It sets itself apart from its parent method, Growing Boxes Partitioning, by imposing a strict hierarchical tree structure on the adaptive boxes, ensuring that boxes are never split across multiple nodes without explicit handling, unlike uniform partitioning which allows trivial sorting by default [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of "grown boxes" produced by the parent method. Each box has a defined bounding box and a type (uniform, gradient, or other).
*   **Output:** An orthogonal BSP tree where leaf nodes contain exactly one box (either an original grown box or a child box generated from splitting). Non-leaf nodes contain lists of boxes and a "room" (the bounding box of their union).

**Data Structures:**
*   **Box:** A 3D axis-aligned bounding box. It may have a `parent` pointer.
*   **BSP Node:**
    *   `room`: A 3D axis-aligned bounding box representing the union of all boxes in this node's list.
    *   `box_list`: A list of boxes associated with this node.
    *   `front_child`: Pointer to the front child node.
    *   `back_child`: Pointer to the back child node.
    *   `type`: The type of the box(es) contained (uniform, gradient, other).

**Algorithm Steps:**

1.  **Initialization:** Create a root BSP node. Set its `room` to the bounding box of the union of all input grown boxes. Add all input grown boxes to the root's `box_list`.

2.  **Node Splitting:** Recursively split nodes until each leaf node contains exactly one box.
    *   **2.1 Create Children:** Create two child nodes, `front` and `back`.
    *   **2.2 Choose Partitioning Plane:** Select a splitting plane that coincides with the faces of at least two boxes in the current node's `box_list` [S1]. The criterion is to minimize the number of boxes that are cut by the plane (i.e., minimize splits) [S1].
    *   **2.3 Define Child Rooms:** Split the current node's `room` into two boxes using the chosen plane. Set these two boxes as the `room` for `front` and `back` respectively.
    *   **2.4 Distribute Boxes:** Iterate through each box in the current node's `box_list`:
        *   If the box is completely enclosed in the `front` room, move it to `front.box_list`.
        *   If the box is completely enclosed in the `back` room, move it to `back.box_list`.
        *   If the box is cut by the plane:
            *   Create two new boxes by splitting the original box along the plane.
            *   Place one new box in `front.box_list` and the other in `back.box_list`.
            *   **Parent Hierarchy:**
                *   If the original box has no parent (it is an original grown box), set the original box as the `parent` of the two new boxes.
                *   If the original box has a parent, set the original box's `parent` as the `parent` of the two new boxes.
                *   Delete the original box from the current node's list.
    *   **2.5 Recurse:** Recursively apply splitting to `front` and `back` if they contain more than one box or if their boxes are not yet finalized as leaf nodes.

3.  **Bottom-Up Merging:** Reduce the BSP tree size by merging child nodes where possible to keep the total number of boxes comparable to the original set [S1].
    *   **3.1 Merge Conditions:** Merge `front` and `back` children into a single node if *any* of the following conditions are true:
        1.  Both children contain uniform boxes, and the merged box (union of their rooms) is also uniform.
        2.  Both children contain "other" boxes or both contain "gradient" boxes.
        3.  One of the boxes is tiny or very thin (size along one axis is smaller than a threshold) [S1].
    *   **3.2 Merge Execution:**
        *   Create a new parent node.
        *   Set its `room` to the union of the `front` and `back` rooms.
        *   Combine the `box_list` from both children.
        *   If the children had different parent boxes, delete those parent boxes and set all their children (now in the new list) as parentless.
        *   Redetermine the type of the merged box based on the enclosed voxel properties.
    *   **3.3 Recurse:** Apply merging bottom-up from the leaves to the root.

**Pseudocode:**

```python
def split_node(node):
    if len(node.box_list) <= 1:
        return node

    # 1. Create children
    front = BSPNode()
    back = BSPNode()
    
    # 2. Choose partitioning plane
    # Plane coincides with faces of at least two boxes to minimize splits
    plane = choose_optimal_plane(node.box_list, node.room)
    
    # 3. Split room
    front.room, back.room = split_box(node.room, plane)
    
    # 4. Distribute boxes
    for box in node.box_list:
        if box.is_enclosed_in(front.room):
            front.box_list.append(box)
        elif box.is_enclosed_in(back.room):
            back.box_list.append(box)
        elif box.is_cut_by(plane):
            # Split box
            box_front, box_back = split_box(box, plane)
            front.box_list.append(box_front)
            back.box_list.append(box_back)
            
            # Handle parent hierarchy
            if box.parent is None:
                box_front.parent = box
                box_back.parent = box
            else:
                box_front.parent = box.parent
                box_back.parent = box.parent
            # Delete original box from current list (handled by iteration logic)
            
    # 5. Recurse
    front = split_node(front)
    back = split_node(back)
    
    node.front_child = front
    node.back_child = back
    return node

def merge_nodes(front, back):
    # Check merge conditions
    if (front.type == 'uniform' and back.type == 'uniform' and is_uniform(union(front.room, back.room))) or \
       (front.type in ['other', 'gradient'] and back.type in ['other', 'gradient']) or \
       is_tiny_or_thin(front.box_list[0]) or is_tiny_or_thin(back.box_list[0]):
        
        merged = BSPNode()
        merged.room = union(front.room, back.room)
        merged.box_list = front.box_list + back.box_list
        
        # Handle parent deletion if parents differ
        if front.box_list[0].parent != back.box_list[0].parent:
            if front.box_list[0].parent is not None:
                delete_parent(front.box_list[0].parent)
                for b in front.box_list:
                    b.parent = None
            if back.box_list[0].parent is not None:
                delete_parent(back.box_list[0].parent)
                for b in back.box_list:
                    b.parent = None
                    
        merged.type = determine_type(merged.box_list)
        return merged
    else:
        return None

def build_orthogonal_bsp(grown_boxes):
    root = BSPNode()
    root.room = union_all(grown_boxes)
    root.box_list = grown_boxes
    
    # Split phase
    root = split_node(root)
    
    # Merge phase (bottom-up)
    root = merge_bottom_up(root)
```

**Parameters:**
*   **Threshold for tiny/thin box:** Not given in the sources.
*   **Partitioning Plane Selection Criterion:** Minimize the number of boxes cut by the plane [S1].

**Edge Cases and Pitfalls:**
*   **Hierarchy Constraint:** No box can be a child and a parent at the same time. There is only one level of parent-child hierarchy. Parent boxes reside on non-leaf nodes; rendering uses only leaf nodes [S1].
*   **Texture Sharing:** Child boxes share the texture of their parent with siblings to avoid replicating texels along boundaries, which would increase memory requirements [S1].
*   **Box Count:** The total number of boxes at leaf nodes after splitting can be significantly greater than the original grown boxes, necessitating the bottom-up merging step [S1].

## Subtopics

### [K-D Tree Hierarchy Construction](2300-k-d-tree-hierarchy-construction.md)
K-D Tree Hierarchy Construction is a spatial partitioning method that organizes polygons into a binary tree structure to enable efficient ray traversal and early termination in volume rendering. It solves the problem of explicitly clipping polygons against view frustums or traversal planes by associating each polygon with the smallest node region that completely contains it. Unlike its parent method, Orthogonal BSP Tree Construction, which uses object-aligned splitting planes, the K-D tree splits regions along axis-aligned hyperplanes, typically bisecting the space. This approach avoids subdividing polygons, ensuring they are stored only in leaf or internal nodes where they fit entirely, thereby simplifying the active polygon list during rendering.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Enables trivial visibility sorting for 3D texture rendering by converting arbitrary grown boxes into an orthogonal BSP tree [S1]. Keeps the total number of boxes comparable to the original set through merging [S1].
*   **Limitations:** The splitting process can significantly increase the number of leaf boxes before merging [S1]. Requires careful handling of parent-child relationships and texture sharing to avoid memory bloat [S1].
*   **When to use:** When using grown boxes for volume rendering and trivial visibility sorting is required [S1].
*   **When not to use:** When the overhead of maintaining the BSP tree structure and handling texture sharing is prohibitive compared to other acceleration structures.

## Background
Orthogonal BSP Tree Construction is part of the "Empty Space Skipping and Occlusion Clipping for Texture-based Volume Rendering" methodology [S1]. It addresses the issue that adaptive partitioning results in arbitrary box sizes and positions, which prevents trivial visibility sorting as seen in uniform partitioning [S1]. The method was introduced in the paper "Empty Space Skipping and Occlusion Clipping for Texture-based Volume Rendering" [S1].
