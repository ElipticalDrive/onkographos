# DeepBrick

Also called: Deep Volume Raytracing

## Overview
DeepBrick is a ray-marching kernel for deep volume raytracing that samples volumetric data stored in hierarchical "brick" structures, handling empty space skipping and alpha accumulation [S1, unofficial]. It differs from standard sparse voxel traversal by operating on pre-integrated brick textures and adjusting sampling density based on a "sample ratio" relative to the brick's internal resolution, allowing for efficient rendering of deep volumes with variable step sizes [S1, unofficial]. It builds on [Sparse Voxel Traversal](1525-sparse-voxel-traversal.md).

## How it works
**Inputs and Outputs:**
*   **Input:** Ray origin, direction, and t-range; VDB leaf node reference; voxel delta (`gvdb->vdel[0]`); world position increment (`wpt`).
*   **Output:** `outBuf` with a layout of 10 floats per pixel: indices 0-2 for color, 3 for mask, 4-6 for normal, 7 for depth, 8-9 for flow [S1, unofficial].

**Data Structures:**
*   **Voxel Value (`val`):** A vector containing color components (`val.x`, etc.) and density/alpha (`val.w`).
*   **Accumulated Color (`clr`):** A vector containing accumulated color components (`clr.x`, etc.) and current transmittance (`clr.w`).
*   **Hit Point (`hit`):** A vector where `hit.x` stores the front hit point (initialized to 0 if not set) and `hit.y` stores the weighted mean depth [S1, unofficial].
*   **Fetched Color (`hclr`):** Temporary color value fetched from the brick texture [S1, unofficial].

**Parameters:**
*   `SCN_MINVAL`: Threshold for skipping empty voxels during initial traversal [S1, unofficial].
*   `SCN_ALPHACUT`: Threshold for stopping color accumulation based on current transtransmittance [S1, unofficial].
*   `MAX_ITER`: Maximum number of iterations allowed per ray [S1, unofficial].
*   `SCN_EXTINCT`: Extinction coefficient [S1, unofficial].
*   `SCN_ALBEDO`: Albedo multiplier [S1, unofficial].
*   `SCN_PSTEP`: Step size [S1, unofficial].

**Steps:**
1.  **Initialization:**
    *   Get the VDB leaf node using `getNode`.
    *   Compute the sample point in index coordinates `p` from world position `wp` and voxel delta `gvdb->vdel[0]`.
    *   Compute world increment `wpt`.
    *   Initialize `val` and `hclr` to zero.
    *   Initialize `clr` (accumulated color/transmittance) to zero.
    *   Record the front hit point `hit.x` if it is zero.

2.  **Empty Space Skipping:**
    *   Loop while `val.w < SCN_MINVAL`, `iter < MAX_ITER`, and `p` is within bounds:
        *   Transfer voxel value to `val`.
        *   Advance `p`, `wp`, and `t.x`.
        *   Increment `iter`.

3.  **Color Accumulation:**
    *   Loop while `clr.w > SCN_ALPHACUT`, `iter < MAX_ITER`, and `p` is within bounds:
        *   **Depth Buffer Test:** Perform an optional depth buffer test [S1, unofficial].
        *   **Transfer Voxel Value:** Fetch voxel value into `val`.
        *   **Compute Transmittance:** Calculate transmittance for the current step:
            $$val.w = \exp(SCN\_EXTINCT \cdot val.w \cdot SCN\_PSTEP)$$
            where $val.w$ is the voxel density, $SCN\_EXTINCT$ is the extinction coefficient, and $SCN\_PSTEP$ is the step size [S1, unofficial].
        *   **Update Weighted Mean Depth:** Update `hit.y` using the transmittance and step size [S1, unofficial].
        *   **Fetch Color:** Fetch color into `hclr` [S1, unofficial].
        *   **Accumulate Color:** Update accumulated color:
            $$clr.x += val.x \cdot clr.w \cdot (1 - val.w) \cdot SCN\_ALBEDO \cdot hclr.x$$
            where $val.x$ is the voxel color component, $clr.w$ is current transmittance, and $hclr.x$ is the fetched color [S1, unofficial].
        *   **Update Transmittance:** Update `clr.w` by multiplying with `val.w` (implicit in standard volume rendering, though not explicitly stated as a separate formula, it is required for the next iteration's `clr.w` check).
        *   **Advance:** Advance `p`, `wp`, and `t.x`.
        *   Increment `iter`.

4.  **Finalization:**
    *   Clamp final color and alpha [S1, unofficial].
    *   Write results to `outBuf` [S1, unofficial].

**Pseudocode:**
```python
def deep_brick_raycast(ray_origin, ray_direction, ray_t_min, ray_t_max, vdb_leaf, voxel_delta, scn_minval, scn_alphacut, max_iter, scn_extinct, scn_albedo, scn_pstep):
    # Initialization
    wp = ray_origin
    p = compute_index_coords(wp, voxel_delta)
    wpt = compute_world_increment(ray_direction, voxel_delta)
    val = vec4(0.0)
    hclr = vec4(0.0)
    clr = vec4(0.0) # clr.w is transmittance
    hit = vec2(0.0) # hit.x is front hit point, hit.y is weighted mean depth
    iter = 0
    
    # Empty Space Skipping
    while val.w < scn_minval and iter < max_iter and is_within_bounds(p):
        val = transfer_voxel_value(p, vdb_leaf)
        p += wpt
        wp += wpt
        iter += 1
        
    # Color Accumulation
    while clr.w > scn_alphacut and iter < max_iter and is_within_bounds(p):
        # Optional depth buffer test
        if perform_depth_buffer_test(wp, hit.x):
            break
            
        val = transfer_voxel_value(p, vdb_leaf)
        
        # Compute Transmittance
        val_w_transmittance = exp(scn_extinct * val.w * scn_pstep)
        
        # Update Weighted Mean Depth
        hit.y = update_weighted_mean_depth(hit.y, val_w_transmittance, scn_pstep)
        
        # Fetch Color
        hclr = fetch_color(p, vdb_leaf)
        
        # Accumulate Color
        clr.x += val.x * clr.w * (1.0 - val_w_transmittance) * scn_albedo * hclr.x
        clr.y += val.y * clr.w * (1.0 - val_w_transmittance) * scn_albedo * hclr.y
        clr.z += val.z * clr.w * (1.0 - val_w_transmittance) * scn_albedo * hclr.z
        
        # Update Transmittance
        clr.w *= val_w_transmittance
        
        # Advance
        p += wpt
        wp += wpt
        iter += 1
        
    # Finalization
    clr = clamp(clr, 0.0, 1.0)
    
    # Write to output buffer (10 floats per pixel)
    # Indices 0-2: Color, 3: Mask, 4-6: Normal, 7: Depth, 8-9: Flow
    out_buf[0:3] = clr[0:3]
    out_buf[3] = 1.0 # Mask
    out_buf[4:7] = compute_normal(wp, vdb_leaf) # Placeholder for normal computation
    out_buf[7] = hit.y # Depth
    out_buf[8:10] = compute_flow(wp, vdb_leaf) # Placeholder for flow computation
    
    return out_buf
```

## Subtopics

### [Brick Traversal](4170-brick-traversal.md)
Brick Traversal is a ray-marching kernel that samples a volumetric brick texture, adjusts alpha and RGB values for variable step sizes, and composites the result into a destination color using front-to-back alpha blending. It accounts for a "sample ratio" ($r$) between the ray step and the brick's internal resolution to adjust sampling density across hierarchical levels. It is chosen when hierarchical brick structures are used to store volumetric data, allowing for efficient traversal and sampling at different resolutions. See [Brick Traversal](4170-brick-traversal.md).

### Node Processing Rules
Node Processing Rules define how different types of nodes in the hierarchical structure are handled during traversal [S2, unofficial]:
*   **Loaded Brick:** If the node is a brick with available data, perform regular ray-marching inside its data [S2, unofficial].
*   **Unloaded Brick:** If the brick is not loaded (e.g., dynamic loading failure), use the average color stored in the node and accumulate it based on the distance the ray travels through the brick (using pre-integration) [S2, unofficial].
*   **Empty Node:** If the node is empty, ignore it (skip processing) [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of voxels traversed along the ray, but reduced by empty space skipping and hierarchical traversal. The complexity is $O(N)$ where $N$ is the number of non-empty voxels intersected by the ray.
*   **Memory Complexity:** Depends on the storage of the VDB leaf nodes and brick textures. Hierarchical structures allow for sparse storage, reducing memory usage compared to dense voxel grids.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales well with hierarchical data structures, as empty regions are skipped. Performance is dependent on the density of the volume and the efficiency of the empty space skipping.
*   **Strengths:** Efficient handling of large, sparse volumes; supports variable step sizes and hierarchical data structures; handles unloaded bricks gracefully.
*   **Limitations:** Requires pre-integrated brick textures; performance may degrade in highly dense volumes where empty space skipping is less effective.
*   **When to use:** Suitable for rendering large, sparse volumetric datasets where hierarchical storage and empty space skipping are beneficial.
*   **When not to use:** Not ideal for dense volumes where the overhead of hierarchical traversal outweighs the benefits of empty space skipping.

## Background
DeepBrick is associated with deep volume raytracing techniques, often implemented in conjunction with VDB (OpenVDB) data structures for sparse volumetric data [S1, unofficial]. The method is described in the context of adaptive sampling and reconstruction for volume visualization [S1, unofficial] and interactive exploration of procedural volumes [S2, unofficial].
