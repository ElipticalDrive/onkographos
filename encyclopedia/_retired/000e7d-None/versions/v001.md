# Gradient Computation via Finite Differences

Also called: Central Difference Gradient, Compute Gradient Map, Discrete Gradient, FD Gradient, Finite Difference Gradient, Finite Difference Gradient Computation, Gradient Computation with Edge Clamping, Gradient Map Compute, Gradient Volume Generation, On-the-fly Gradient Computation, Tetrahedron Gradient Technique, Voxel Gradient Encoding, Voxel Gradient Estimation

## Overview
Gradient Computation via Finite Differences calculates the 3D gradient vector for each voxel in a scalar volume by approximating spatial derivatives using neighboring voxel values [S2, unofficial][S4]. This method provides the surface normal information required for lighting models (such as [Gradient-based Diffuse Lighting with Alpha Blending](1257-gradient-based-diffuse-lighting-with-alpha-blending.md)) and isosurfacing algorithms when analytical gradients are unavailable [S4]. It is distinguished from analytical gradient computation by its reliance on discrete sampling and from tetrahedron-based methods by its direct use of axis-aligned neighbor differences [S1, S3, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   A scalar volume texture or array $V$ of resolution $R = (R_x, R_y, R_z)$ [S2, S3, unofficial].
*   Optional: A magnitude modifier scalar $M$ [S1, unofficial].
*   Optional: Grid spacing $h$ for physical units [S4].

**Outputs:**
*   A gradient array $G$ containing the 3D gradient vector $\nabla V$ for each voxel [S2, unofficial].
*   Alternatively, an encoded texture storing normalized direction and magnitude [S1, S3, unofficial].

### Data Structures
1.  **Gradient Array (CPU/General):** A 1D float array of size $N \times 3$, where $N = R_x \times R_y \times R_z$. The layout is interleaved RGB: indices $3k, 3k+1, 3k+2$ store $g_x, g_y, g_z$ for voxel $k$ [S2, unofficial].
2.  **Gradient Texture (GPU):**
    *   **RGBA8_SNORM:** Stores normalized direction $(n_x, n_y, n_z)$ in RGB and magnitude in A [S1, unofficial].
    *   **RGBA8:** Stores direction in RGB and clamped density/magnitude in A [S3, unofficial].
    *   **RG8:** Stores clamped density in R and clamped magnitude in G [S3, unofficial].

### Algorithm Steps

#### 1. Boundary Handling
To prevent out-of-bounds reads, sampling coordinates are clamped to the valid voxel range $[0, R_i-1]$ for each axis $i \in \{x, y, z\}$ [S3, unofficial]. Alternatively, boundary neighbors are determined explicitly:
*   If index $i=0$: $x_0=0, x_1=1, dx=1.0$ [S2, unofficial].
*   If index $i=R_x-1$: $x_0=R_x-2, x_1=R_x-1, dx=1.0$ [S2, unofficial].
*   Otherwise: $x_0=i-1, x_1=i+1, dx=2.0$ [S2, unofficial].

#### 2. Gradient Calculation
The gradient components are computed using central differences.

**Standard Central Difference (Unit Spacing):**
$$ g_x = \frac{V(x+1, y, z) - V(x-1, y, z)}{2} $$
$$ g_y = \frac{V(x, y+1, z) - V(x, y-1, z)}{2} $$
$$ g_z = \frac{V(x, y, z+1) - V(x, y, z-1)}{2} $$
[S3, unofficial]

**Physical Spacing:**
If grid spacing $h$ is known, the step size $s$ is computed as $s = 0.01 \sqrt{\text{spacing}^2}$ [S4]. The components are divided by the respective distances $dx, dy, dz$ [S2, unofficial].

**Tetrahedron-Based Method:**
An alternative approach sums contributions from 4 tetrahedron neighbors defined by offset vectors $k$ [S1, unofficial]:
1.  Offset $(-1, -1, 1)$ with weight $(-1, -1, 1)$.
2.  Offset $(1, -1, 1)$ with weight $(1, -1, 1)$.
3.  Offset $(1, 1, -1)$ with weight $(1, 1, -1)$.
4.  Offset $(1, 1, 1)$ with weight $(1, 1, 1)$.
The sum is multiplied by $0.25$ to yield the final vector [S1, unofficial].

#### 3. Normalization and Encoding
1.  Compute magnitude: $L = \sqrt{g_x^2 + g_y^2 + g_z^2}$ [S3, unofficial].
2.  If $L > \epsilon$ (e.g., $10^{-6}$), normalize: $\mathbf{n} = \mathbf{g} / L$ [S3, unofficial]. Else, $\mathbf{n} = (0,0,0)$ [S3, unofficial].
3.  **Direction Encoding:** Map $\mathbf{n} \in [-1, 1]$ to $[0, 1]$ via $\mathbf{e} = \mathbf{n} \cdot 0.5 + 0.5$ [S3, unofficial]. Quantize to 8-bit integers: $out = \text{round}(\mathbf{e} \cdot 255)$ [S3, unofficial].
4.  **Magnitude Encoding:** Multiply magnitude by $M$ (default 1.0 or specific modifier) and clamp to $[0, 1]$ [S1, unofficial]. For RG8 layout, scale typical max magnitude ($\sqrt{3}/2$) by $2.0$ to fit range [S3, unofficial].

### Pseudocode
```python
def compute_gradients(volume, resolution, magnitude_modifier=1.0):
    """
    Computes voxel gradients using central differences with edge clamping.
    volume: 3D array or texture sampler of shape (Rx, Ry, Rz)
    resolution: tuple (Rx, Ry, Rz)
    returns: gradient_array of shape (Rx, Ry, Rz, 3) and magnitude_array of shape (Rx, Ry, Rz)
    """
    Rx, Ry, Rz = resolution
    gradients = np.zeros((Rx, Ry, Rz, 3))
    magnitudes = np.zeros((Rx, Ry, Rz))
    
    # Helper to clamp index
    def clamp(val, max_val):
        return max(0, min(val, max_val - 1))

    for z in range(Rz):
        for y in range(Ry):
            for x in range(Rx):
                # Boundary handling for X
                if x == 0:
                    x0, x1, dx = 0, 1, 1.0
                elif x == Rx - 1:
                    x0, x1, dx = Rx - 2, Rx - 1, 1.0
                else:
                    x0, x1, dx = x - 1, x + 1, 2.0
                
                # Boundary handling for Y
                if y == 0:
                    y0, y1, dy = 0, 1, 1.0
                elif y == Ry - 1:
                    y0, y1, dy = Ry - 2, Ry - 1, 1.0
                else:
                    y0, y1, dy = y - 1, y + 1, 2.0

                # Boundary handling for Z
                if z == 0:
                    z0, z1, dz = 0, 1, 1.0
                elif z == Rz - 1:
                    z0, z1, dz = Rz - 2, Rz - 1, 1.0
                else:
                    z0, z1, dz = z - 1, z + 1, 2.0

                # Fetch values
                v_x0 = volume[x0, y, z]
                v_x1 = volume[x1, y, z]
                v_y0 = volume[x, y0, z]
                v_y1 = volume[x, y1, z]
                v_z0 = volume[x, y, z0]
                v_z1 = volume[x, y, z1]

                # Compute components
                gx = (v_x1 - v_x0) / dx
                gy = (v_y1 - v_y0) / dy
                gz = (v_z1 - v_z0) / dz

                # Normalize
                length = math.sqrt(gx*gx + gy*gy + gz*gz)
                if length > 1e-6:
                    nx, ny, nz = gx/length, gy/length, gz/length
                else:
                    nx, ny, nz = 0.0, 0.0, 0.0

                gradients[x, y, z] = [nx, ny, nz]
                magnitudes[x, y, z] = min(length * magnitude_modifier, 1.0)

    return gradients, magnitudes
```

### Parameters
*   **grad_magnitude_modifier:** Scalar multiplier applied to gradient magnitude before clamping [S1, unofficial].
*   **scale:** Factor (e.g., 2.0) used to map gradient magnitudes to the $[0,1]$ range for specific texture formats [S3, unofficial].
*   **step:** Finite difference step size, computed as $0.01 \times \sqrt{\text{grid\_spacing}^2}$ in CGAL implementations [S4].

### Edge Cases and Pitfalls
*   **Zero Distance:** If the distance $d$ between points is 0, the gradient direction is undefined; assign a null vector [S4].
*   **Precision:** Using `float` for gradient storage may lose precision for very small volumes or high-resolution data; `float16` or `float32` should be chosen based on dynamic range requirements [S2, unofficial].
*   **Boundary Artifacts:** Clamping creates discontinuities at the volume edges. Repeating edge voxels is a common mitigation [S3, unofficial].

## Subtopics

### Gradient Map Generation
A specific GPU compute shader implementation that calculates gradients for all voxels and stores them in a 3D image buffer [S1, unofficial]. It uses the global invocation ID to map threads to voxels, computes the gradient vector, normalizes it, and stores the direction in RGB and the clamped magnitude (multiplied by `grad_magnitude_modifier`) in the Alpha channel of an `rgba8_snorm` texture [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of voxels, as each voxel requires a constant number of reads and arithmetic operations [S2, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the gradient array (3 floats per voxel) or texture [S2, unofficial].
*   **Performance:** On GPU, dispatching compute shaders with workgroups of size 8x8x8 allows efficient parallelization [S1, unofficial].
*   **Strengths:** Simple to implement; works on any discrete scalar field; provides necessary normal data for lighting and marching cubes/dual contouring [S4].
*   **Limitations:** Sensitive to noise in the volume data; central differences amplify high-frequency noise; boundary conditions require careful handling to avoid artifacts [S3, unofficial].

## Background
The method originates from standard numerical analysis techniques for approximating derivatives [S4]. In computer graphics, it is widely used in volume rendering for illumination [S3, unofficial] and in isosurfacing algorithms like Dual Contouring, where CGAL's `Finite_difference_gradient_3` class provides a robust implementation for computing gradients from discrete values [S4]. The tetrahedron-based variant is attributed to Iñaki Ñiguez [S1, unofficial].
