# NeRF Training Loop

Also called: Coordinate regression training, Full-batch Neural Field Training Loop, NeRF Training Procedure, Neural Radiance Field (NeRF) Training Loop, Volume Rendering Optimization

## Overview
The NeRF training loop optimizes a coordinate-based neural field (typically an MLP) to reconstruct a scene by minimizing the mean squared error (MSE) between rendered RGB values and ground truth images [S2, S3]. It differs from explicit radiance field methods by learning a continuous volumetric representation via differentiable volume rendering, allowing gradient-based optimization of scene geometry and appearance simultaneously [S3].

## How it works
**Inputs:**
- Training dataset: Images, camera poses ($c2w$), and intrinsics ($K$).
- Model: A neural network (MLP or SIREN) mapping 3D coordinates (and optionally viewing directions) to color and density [S1, S2].
- Hyperparameters: Learning rate, batch size, number of epochs, sampling parameters (near/far bounds, number of samples per ray) [S1, S3].

**Outputs:**
- Trained model weights (checkpoint).
- Rendered images/videos for evaluation [S3].

**Data Structures:**
- `rays_rgb`: Array of shape $[N_{rays}, 3]$ containing ray origins ($r_o$), ray directions ($r_d$), and target RGB values. In full-batch implementations, this may cover the entire image grid; in mini-batch, it is a subset [S1, S3].
- `camera`: Dictionary or object containing $c2w$ matrix, intrinsics $K$, and image dimensions [S3].
- `optimizer_state`: State for Adam optimizer (momentum buffers) [S3].

**Numbered Steps:**

1. **Initialization**:
   - Parse command-line arguments and configuration [S1, S3].
   - Initialize summary writers for logging training and validation metrics [S1].
   - Instantiate the neural network model. If using SIREN, apply specific weight initialization (Uniform distribution scaled by $\omega_0$) [S2].
   - Initialize the Adam optimizer with learning rate `lr` [S1, S3].
   - Initialize a learning rate scheduler (e.g., `LambdaLR` with decay factor $\gamma$ and step size $s$) [S3].
   - Load training and validation datasets. Compute near/far bounds based on dataset type (e.g., LLFF uses bounding depths or NDC; Blender uses fixed $[2, 6]$) [S1, S3].
   - Create a DataLoader with batch size 1 (or specified batch size) [S3].

2. **Training Loop** (for `epoch` from `start_epoch` to `num_epochs`):
   - **Data Loading**: Extract `image`, `camera`, and `camera_idx` from the batch. Move tensors to GPU [S3].
   - **Ray Sampling**:
     - If using full-batch or specific coordinate regression: Sample random pixel coordinates $(x, y)$ from the image grid [S2, S3].
     - Generate ray origins ($r_o$) and directions ($r_d$) using camera intrinsics and poses [S1, S3].
     - Construct ray batch tensor containing $r_o$, $r_d$, near, far, and optionally viewing directions if `use_viewdirs` is enabled [S1].
   - **Forward Pass**:
     - Sample points along each ray within $[near, far]$ bounds. Perturb sampling times if `perturb > 0` [S1, S3].
     - Pass sampled 3D coordinates (and viewing directions) through the neural network to predict volume density ($\sigma$) and color ($c$) [S1, S3].
     - Perform differentiable volume rendering to compute predicted RGB for each ray [S1, S3].
   - **Loss Calculation**:
     - Compute MSE loss between predicted RGB and ground truth RGB at sampled pixels [S1, S2, S3].
     - If coarse network output is available and `--rvs` is not enabled, add its MSE loss to the total loss [S1].
     - If using volume SDF rendering, add Eikonal loss term: $L_{eikonal} = \lambda_{eikonal} \|\nabla \phi(x) - 1\|^2$ [S3].
     - **Logging**: Compute gradients and Laplacian for visualization *before* the backward pass [S2].
   - **Backpropagation**:
     - Zero gradients: `optimizer.zero_grad()` [S3].
     - Compute gradients: `loss.backward()` [S3].
     - Update weights: `optimizer.step()` [S3].
   - **Scheduler Step**: Update learning rate: $lr_{new} = lr_{old} \times \gamma^{(epoch / s)}$ [S3].
   - **Checkpointing**: If `epoch % checkpoint_interval == 0`, save model state, optimizer state, and epoch number [S3].
   - **Evaluation**: If `epoch % render_interval == 0`, render images using test poses and save to disk [S3].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

def train_nerf_loop(model, optimizer, scheduler, train_loader, val_loader, cfg):
    """
    Main training loop for NeRF.
    """
    start_epoch = 0
    # Load checkpoint if resuming
    if cfg.resume_path:
        checkpoint = torch.load(cfg.resume_path)
        model.load_state_dict(checkpoint['model_state_dict'])
        optimizer.load_state_dict(checkpoint['optimizer_state_dict'])
        start_epoch = checkpoint['epoch'] + 1

    for epoch in range(start_epoch, cfg.training.num_epochs):
        model.train()
        total_loss = 0.0
        
        for batch in train_loader:
            # 1. Data Preparation
            image = batch['image'].cuda().unsqueeze(0) # [1, H, W, 3]
            camera = batch['camera'].cuda()
            
            # 2. Ray Sampling
            # Get random pixel coordinates
            xy_grid = get_random_pixels_from_image(
                cfg.training.batch_size, 
                cfg.data.image_size, 
                camera
            )
            
            # Generate rays from pixels
            rays_o, rays_d = get_rays_from_pixels(
                xy_grid, 
                cfg.data.image_size, 
                camera
            )
            
            # Create ray bundle
            ray_bundle = {
                'origins': rays_o,
                'directions': rays_d,
                'near': cfg.training.near,
                'far': cfg.training.far,
                'use_viewdirs': cfg.model.use_viewdirs
            }
            
            # 3. Forward Pass
            out = model(ray_bundle)
            pred_rgb = out['rgb'] # [batch_size, 3]
            
            # 4. Loss Calculation
            # Sample ground truth RGB at pixel grid
            gt_rgb = sample_images_at_xy(image, xy_grid) # [batch_size, 3]
            
            # MSE Loss
            loss = F.mse_loss(pred_rgb, gt_rgb)
            
            # Eikonal Loss (if using SDF)
            if cfg.renderer.type == 'volume_sdf':
                eikonal_loss = get_eikonal_loss(
                    model.implicit_fn, 
                    cfg.training.batch_size, 
                    cfg.training.bounds, 
                    gt_rgb.device
                )
                loss += cfg.training.eikonal_weight * eikonal_loss
            
            # Logging (must be before backward)
            if epoch % cfg.training.steps_til_summary == 0:
                grad = gradient(pred_rgb, ray_bundle['origins'])
                laplacian = laplace(pred_rgb, ray_bundle['origins'])
                # Save plots if needed
            
            # 5. Backpropagation
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
            
            total_loss += loss.item()
        
        # 6. Scheduler Step
        scheduler.step()
        
        # 7. Checkpointing
        if epoch % cfg.training.checkpoint_interval == 0 and epoch > 0:
            save_checkpoint(
                model.state_dict(),
                optimizer.state_dict(),
                epoch,
                cfg.training.checkpoint_path
            )
            
        # 8. Evaluation
        if epoch % cfg.training.render_interval == 0 and epoch > 0:
            render_evaluation(model, val_loader, cfg)

def get_random_pixels_from_image(batch_size, image_size, camera):
    H, W = image_size
    # Return random (x, y) coordinates
    x = torch.randint(0, W, (batch_size,))
    y = torch.randint(0, H, (batch_size,))
    return torch.stack([x, y], dim=1)

def get_rays_from_pixels(xy_grid, image_size, camera):
    H, W = image_size
    # Convert pixel coordinates to ray origins and directions using camera intrinsics
    # K is 3x3 matrix
    K = camera['K']
    c2w = camera['c2w']
    
    # Inverse intrinsics
    K_inv = torch.inverse(K)
    
    # Homogeneous pixel coordinates
    ones = torch.ones_like(xy_grid[..., :1])
    pixel_coords = torch.cat([xy_grid.float(), ones], dim=-1) # [B, 3]
    
    # Ray directions in camera space
    dirs_cam = torch.matmul(K_inv, pixel_coords.t()).t() # [B, 3]
    dirs_cam = F.normalize(dirs_cam, dim=-1)
    
    # Transform to world space
    dirs_world = torch.matmul(c2w[:3, :3], dirs_cam.t()).t()
    
    # Ray origins are camera center
    origins_world = c2w[:3, 3].unsqueeze(0).expand(batch_size, -1)
    
    return origins_world, dirs_world

def sample_images_at_xy(image, xy_grid):
    # Bilinear sampling of image at given coordinates
    # Normalize coordinates to [-1, 1]
    H, W = image.shape[1:3]
    x_norm = (xy_grid[:, 0].float() / (W - 1)) * 2 - 1
    y_norm = (xy_grid[:, 1].float() / (H - 1)) * 2 - 1
    grid = torch.stack([x_norm, y_norm], dim=-1).unsqueeze(0).unsqueeze(0) # [1, 1, B, 2]
    
    # grid_sample expects [N, C, H, W] input and [N, H_out, W_out, 2] grid
    # We need to transpose image to [1, 3, H, W]
    img_4d = image.permute(0, 3, 1, 2) # [1, 3, H, W]
    
    # Sample
    sampled = F.grid_sample(img_4d, grid, align_corners=True) # [1, 3, 1, B]
    return sampled.squeeze(-1).squeeze(0).permute(1, 0) # [B, 3]
```

**Parameters:**
- `lr` (float): Learning rate for Adam optimizer. Typical value: $5 \times 10^{-4}$ [S1, S3].
- `total_steps` (int): Total number of optimization steps [S2].
- `lr_scheduler_gamma` (float): Base for learning rate decay exponent [S3].
- `lr_scheduler_step_size` (int): Denominator for learning rate decay exponent [S3].
- `perturb` (float): Jitter amount for sampling. $0.0$ for no jitter, $1.0$ for max jitter [S1].
- `raw_noise_std` (float): Standard deviation of noise added to density output. Default $0.0$, recommended $1e0$ [S1].
- `multires` (int): Log2 of max frequency for positional encoding of 3D location. Default $10$ [S1].
- `multires_views` (int): Log2 of max frequency for positional encoding of viewing direction. Default $4$ [S1].
- `eikonal_weight` (float): Weight for Eikonal loss in volume SDF rendering [S3].
- `checkpoint_interval` (int): Frequency of checkpoint saving in epochs [S3].
- `render_interval` (int): Frequency of rendering evaluation in epochs [S3].
- `num_epochs` (int): Total number of training epochs [S3].
- `render_factor` (int): Downsampling factor for fast preview. Default $0$ (no downsampling) [S1].
- `dataset_type` (str): Dataset type (llff, blender, deepvoxels). Default `llff` [S1].
- `use_viewdirs` (bool): Use 5D input (3D pos + 2D dir). Default `True` [S1].
- `samples_union` (bool): Flag for samples union variant [S1].
- `rvs` (bool): Use reparameterized volume sampling [S1].

**Edge Cases and Pitfalls:**
- **Gradient Computation Order**: Higher-order derivatives (gradient, Laplacian) for logging must be computed *before* `loss.backward()` because the backward pass frees the autograd graph [S2].
- **Precision**: Use float32 for standard training; float64 may be needed for precise gradient checks but increases memory usage [G].
- **Boundary Conditions**: Ensure ray sampling respects near/far bounds to avoid NaNs in density computation [S1].
- **Degenerate Input**: Handle cases where camera intrinsics are missing by initializing with default values based on image dimensions [S1].

## Operating characteristics
- **Time Complexity**: $O(N \cdot S \cdot D)$ per step, where $N$ is the number of rays sampled, $S$ is the number of samples per ray, and $D$ is the MLP depth/width [S1, S3].
- **Memory Complexity**: $O(N \cdot S)$ for storing intermediate ray samples and gradients [S3].
- **Performance**: Training can take several hours to days depending on scene complexity and resolution. GPU memory usage can exceed 15GB for high-resolution scenes [S3].
- **Strengths**: High-quality novel view synthesis; continuous representation allows arbitrary resolution rendering [S3].
- **Limitations**: Slow training and inference compared to explicit methods; prone to overfitting on small datasets without regularization [S1, S3].
- **When to Use**: When high-quality novel views are required and training time is not a constraint [S3].
- **When Not to Use**: For real-time applications or large-scale scenes where explicit methods (e.g., 3DGS) are more efficient [S3].

## Background
The NeRF training loop was introduced in "Neural Radiance Fields" by Mildenhall et al. (2020) [S1, S3]. It builds on earlier work on coordinate-based neural representations and differentiable volume rendering [S2]. The method has become a standard baseline for view synthesis and 3D reconstruction [S3].
