# Network Ray Marching Iterator

Also called: Distributed Ray Marching with Macrocell DDA, Networked Ray Marching

## Overview
The Network Ray Marching Iterator is a ray marching algorithm designed for distributed or networked rendering environments, typically leveraging GPU ray tracing APIs such as NVIDIA OptiX [S1, unofficial]. It extends the parent [Adaptive Ray Marching with Macrocell DDA](1500-adaptive-ray-marching-with-macrocell-dda.md) by introducing block-level divergence control via `block_any` to manage thread synchronization across macrocell boundaries [S1, unofficial]. This method is distinct from its siblings because it explicitly handles the "alive" status of rays in a distributed context, ensuring that inactive threads do not waste computation while maintaining adaptive sampling rates based on opacity upper bounds [S1, unofficial].

## How it works
The algorithm traverses a volume using a 3D Digital Differential Analyzer (DDA) over macrocells. It adapts the step size within each macrocell based on an estimated opacity upper bound and uses a device function `block_any` to synchronize thread divergence across the block [S1, unofficial].

### Inputs and Outputs
- **Inputs**: Ray origin `org`, ray direction `dir`, ray segment `[tMin, tMax]`, volume dimensions `dims`, macrocell spacing inverse `macrocell_spacings_rcp`, and a lambda function defining the per-sample body logic.
- **Outputs**: The final "alive" status of the ray after traversal, and accumulated color/opacity if the body function modifies state.

### Data Structures
- **Macrocell Coordinates**: `m_org` and `m_dir` are floating-point vectors representing the ray origin and direction scaled by the inverse macrocell spacing.
- **DDA State**: The `network_dda3` function yields a tuple `(cell, t0, t1, alive)` for each macrocell intersection, where `cell` is the macrocell index, `t0` and `t1` are the entry and exit distances, and `alive` is the boolean status of the ray.

### Parameters
- **`block_any`**: A device function that returns `true` if any thread in the current warp/block satisfies a given condition. Used for divergence control [S1, unofficial].
- **`float_epsilon`**: A small constant used to determine if the opacity upper bound is effectively zero. Value not given in the sources [G].
- **`step`**: The base sampling step size. Value not given in the sources [G].

### Steps
1. **Calculate Macrocell Coordinates**:
   Compute the ray origin and direction in macrocell space:
   $$ m\_org = org \times macrocell\_spacings\_rcp $$
   $$ m\_dir = dir \times macrocell\_spacings\_rcp $$

2. **Invoke DDA**:
   Call `dda::network_dda3(m_org, m_dir, tMin, tMax, dims, debug, lambda)` to iterate over macrocells. The lambda function receives `(cell, t0, t1, alive)` for each cell.

3. **Initialize Loop Variables**:
   Inside the lambda, initialize `ss = 100.f` (adaptive step size) and `non_empty = true`.

4. **Check Opacity Upper Bound**:
   If `alive` is true:
   - Calculate `r = opacityUpperBound(self, cell)`.
   - If `fabsf(r) <= float_epsilon`, set `non_empty = false`.

5. **Calculate Adaptive Step**:
   If `alive` is true, set `ss = adaptiveSamplingRate(step, r)`.

6. **Divergence Control**:
   Evaluate `block_any(non_empty && alive)`. If this returns `false`, return `alive` (terminate the ray for this block).

7. **Initialize Sample Interval**:
   Set `t = vec2f(t0, min(t1, t0 + ss))`.

8. **Sample Loop**:
   Loop while `block_any(alive && (t.y > t.x))`:
   - Update `alive = body(t, alive)`.
   - Update `t.x = t.y`.
   - Update `t.y = min(t.x + ss, t1)`.

9. **Return Status**:
   Return the final `alive` status.

### Non-Adaptive Fallback
If adaptive sampling is not used, initialize `t = vec2f(tMin, min(tMax, tMin + step))` and `alive = (t.y > t.x)`. Loop while `block_any(alive && (t.y > t.x))`:
- Update `alive = body(t, alive)`.
- Update `t.x = t.y`.
- Update `t.y = min(t.x + step, tMax)`.

### Pseudocode
```python
def network_ray_marching_iterator(org, dir, tMin, tMax, dims, macrocell_spacings_rcp, step, float_epsilon, opacityUpperBound, adaptiveSamplingRate, block_any, body):
    # 1. Calculate macrocell coordinates
    m_org = org * macrocell_spacings_rcp
    m_dir = dir * macrocell_spacings_rcp

    # 2. Call DDA
    def lambda_func(cell, t0, t1, alive):
        # 3. Initialize variables
        ss = 100.0
        non_empty = True

        # 4. Check opacity upper bound
        if alive:
            r = opacityUpperBound(cell)
            if abs(r) <= float_epsilon:
                non_empty = False

        # 5. Calculate adaptive step
        if alive:
            ss = adaptiveSamplingRate(step, r)

        # 6. Divergence control
        if not block_any(non_empty and alive):
            return alive

        # 7. Initialize sample interval
        t_x = t0
        t_y = min(t1, t0 + ss)

        # 8. Sample loop
        while block_any(alive and (t_y > t_x)):
            alive = body(t_x, t_y, alive)
            t_x = t_y
            t_y = min(t_x + ss, t1)

        # 9. Return status
        return alive

    # Execute DDA with lambda
    dda_result = network_dda3(m_org, m_dir, tMin, tMax, dims, lambda_func)
    return dda_result
```

### Edge Cases and Pitfalls
- **Precision**: The use of `float_epsilon` for opacity checks requires careful selection to avoid premature termination of rays in low-opacity regions [S1, unofficial].
- **Boundaries**: The `min(t1, t0 + ss)` logic ensures that the last sample does not exceed the macrocell exit distance `t1` [S1, unofficial].
- **Divergence**: If `block_any` is not implemented efficiently, thread divergence can lead to performance degradation [S1, unofficial].

## Subtopics

### [Resumable Ray Marching Iterator](1505-resumable-ray-marching-iterator.md)
A variant that allows ray traversal to be paused and resumed, useful for progressive rendering. Choose when memory bandwidth is limited or when integrating with progressive refinement techniques.

### [Macrocell Grid Traversal with Majorant Densities](1528-macrocell-grid-traversal-with-majorant-densities.md)
Uses majorant densities for more accurate opacity bounds. Choose when higher accuracy in empty-space skipping is required, at the cost of increased computation per macrocell.

## Operating characteristics
- **Time Complexity**: Linear with respect to the number of macrocells intersected by the ray, with adaptive sampling reducing the number of samples per macrocell based on opacity [S1, unofficial].
- **Memory Complexity**: Constant per ray, as it only stores current macrocell state and sample intervals [S1, unofficial].
- **Performance**: Optimized for distributed rendering on GPUs using ray tracing APIs like OptiX [S1, unofficial].
- **Strengths**: Efficient handling of thread divergence in distributed contexts; adaptive sampling reduces unnecessary computations [S1, unofficial].
- **Limitations**: Requires support for `block_any` and custom DDA implementations; may not be suitable for non-GPU or non-ray-tracing environments [S1, unofficial].

## Background
The Network Ray Marching Iterator was introduced as part of the instantvnr project, a neural volume rendering framework [S1, unofficial]. It builds on the principles of adaptive ray marching and macrocell traversal, extending them to support distributed rendering scenarios [S1, unofficial]. The method is designed to leverage the parallelism of modern GPUs and the synchronization primitives provided by ray tracing APIs [S1, unofficial].
