# Triangulated Active Brick Boundary Mesh for Space Skipping

Also called: Active Brick Boundary Mesh, Active Region Boundary Geometry, Boundary Mesh Space Skipping, RTX-Accelerated Empty Space Skipping using Triangulated Active Region Boundary Geometry

## Overview
A GPU-accelerated space-skipping technique for structured volumes that replaces clustered proxy boxes with a triangle mesh bounding the surface between active and inactive macrocells. It solves the host-GPU transfer bottleneck and high depth complexity of prior proxy-box methods by generating the boundary geometry entirely on the GPU and using native RTX hardware for ray-triangle intersection. Unlike [Adaptive Ray Marching with Macrocell DDA](1500-adaptive-ray-marching-with-macrocell-dda.md), which uses software traversal, this method leverages hardware BVH traversal for all space-skipping decisions.

## How it works
**Inputs:**
- Input volume dimensions $V_x \times V_y \times V_z$.
- Brick size $K$ (default 16), defining macrocell resolution.
- Transfer function (TF) defining active scalar ranges.
- Ray origin $\mathbf{o}$ and direction $\mathbf{d}$.

**Outputs:**
- Volume integration intervals $[t_0, t_1]$ for active regions.
- Final pixel color.

**Data Structures:**
1.  **Macrocell Grid:** Size $M_x \times M_y \times M_z$, where $M_x = \lfloor V_x/K \rfloor$, etc. Each cell stores min/max scalar values of input voxels.
2.  **Active Bricks Mask:** Boolean grid $M_x \times M_y \times M_z$ on GPU. `true` if macrocell has non-zero alpha for current TF.
3.  **Vertex Array:** Pre-allocated `float3` array of size $N_{vtxMax} = (M_x+1)(M_y+1)(M_z+1)$. Contains all possible macrocell grid vertices.
4.  **Triangle Index Array:** Pre-allocated `int3` array of size $N_{triMax}$. Stores indices referencing the Vertex Array.
5.  **numTriangles:** Device-side integer counter, initialized to 0.
6.  **OptiX BVH:** Built over the generated triangle mesh.

**Steps:**

1.  **Initial Setup:**
    - Build Macrocell Grid on host, upload to GPU.
    - Allocate GPU memory for Active Bricks Mask, Vertex Array, and Triangle Index Array.
    - Initialize `numTriangles = 0`.

2.  **Active Cell Classification (Per TF Change):**
    - Launch CUDA kernel. Each thread maps to one macrocell $(i,j,k)$.
    - Check if macrocell's scalar range maps to non-zero alpha in TF.
    - Write result to `ActiveBricksMask[i][j][k]`.

3.  **Boundary Triangle Generation (Per TF Change):**
    - Clear `numTriangles = 0`.
    - Run three templated CUDA kernels for X, Y, Z orientations.
    - For orientation $D \in \{0,1,2\}$ (X,Y,Z):
        - Thread maps to face perpendicular to axis $D$.
        - Let `curr` be macrocell index on positive side of face, `prev` on negative side.
        - If `prev` is out-of-bounds, treat as inactive.
        - If `ActiveBricksMask[prev] == ActiveBricksMask[curr]`, return.
        - Get 4 vertex indices $\{v_0, v_1, v_2, v_3\}$ spanning the face.
        - `triID = atomicAdd(&numTriangles, 2)`.
        - If `ActiveBricksMask[prev]` is true (prev active, curr inactive):
            - `Triangles[triID] = {v_0, v_1, v_2}`
            - `Triangles[triID+1] = {v_0, v_2, v_3}`
        - Else (`curr` active, `prev` inactive):
            - `Triangles[triID] = {v_1, v_0, v_2}`
            - `Triangles[triID+1] = {v_2, v_0, v_3}`
        - Winding order points away from active towards inactive.
    - Download `numTriangles` to host.

4.  **BVH Rebuild:**
    - Update OptiX geometry to reference generated mesh.
    - Rebuild BVH with "optimize for traversal" flag.
    - Compact BVH.

5.  **Ray Tracing & Integration:**
    - Initialize ray with $t_{min}=0, t_{max}=\infty$.
    - Trace ray against BVH.
    - **No Hit:** Terminate ray.
    - **Hit:** Get hit distance $t_{hit}$ and hit kind (front/back).
    - **Back-Facing Hit:** Ray is inside volume. Integration interval $[t_0, t_1] = [0, t_{hit}]$.
    - **Front-Facing Hit:** Ray enters volume at $t_0 = t_{hit}$. Trace same ray with $t_{min}=t_0$ to find exit $t_1$.
    - **Volume Integration:** Sample volume texture at fixed rate $dt=0.5$ (interleaved) over $[t_0, t_1]$. Apply gradient shading and early ray termination.
    - If ray terminated early, return.
    - Else, trace new ray from $t_1 + \epsilon$ to find next segment. Repeat.

# CUDA Kernel for Boundary Generation
template <int DIM>
__global__ void generateBoundaryMeshKernel(int &numTriangles, int3 *triangles, bool activeCells[...][...][...]) {
    int3 curr = getGlobalThreadIndex();
    int3 prev;
    if constexpr(DIM == 0) prev = curr - int3(1, 0, 0);
    else if constexpr(DIM == 1) prev = curr - int3(0, 1, 0);
    else if constexpr(DIM == 2) prev = curr - int3(0, 0, 1);

    // Handle boundary faces: treat out-of-bounds as inactive
    bool prevActive = false;
    bool currActive = activeCells[curr];
    
    if (isInsideGrid(prev)) {
        prevActive = activeCells[prev];
    } else {
        prevActive = false;
    }

    if (prevActive == currActive) return;

    int vi[4] = getBoundaryQuadVertices(curr, DIM);
    int triID = atomicAdd(&numTriangles, 2);

    if (prevActive) {
        // prev is active, curr is inactive
        triangles[triID + 0] = int3(vi[0], vi[1], vi[2]);
        triangles[triID + 1] = int3(vi[0], vi[2], vi[3]);
    } else {
        // curr is active, prev is inactive
        triangles[triID + 0] = int3(vi[1], vi[0], vi[2]);
        triangles[triID + 1] = int3(vi[2], vi[0], vi[3]);
    }
}

## Operating characteristics
- **Time Complexity:** Mesh generation is $O(M_x M_y M_z)$ per TF change. BVH rebuild is $O(N \log N)$ where $N$ is triangle count. Ray tracing is hardware-accelerated.
- **Memory Complexity:** Vertex array is fixed size $(M_x+1)(M_y+1)(M_z+1)$. Triangle array is pre-allocated to upper bound.
- **Performance:** On Exajet dataset, BVH rebuild takes ~300ms on Titan RTX/RTX 8000 [S2]. Significantly faster than Ganter and Manzke [GM19] due to no host-GPU transfer and no CPU clustering.
- **Strengths:** No host-GPU bottleneck. Lower depth complexity than proxy boxes. Hardware-accelerated intersection.
- **Limitations:** BVH must be rebuilt on TF change. Pre-allocated vertex array wastes memory.
- **When to use:** Interactive TF editing on GPU. Structured volumes.
- **When not to use:** Unstructured data (use [Adaptive Ray Marching with Macrocell DDA](1500-adaptive-ray-marching-with-macrocell-dda.md) or other methods).

## Background
- **Origin:** Ganter and Manzke [GM19] introduced RTX-accelerated space skipping using proxy boxes. This method extends it by replacing boxes with a boundary mesh [S1, unofficial].
- **History:** Inspired by unstructured volume rendering techniques using boundary tetrahedra [BKS97]. Implemented using OptiX 7.2 and OWL library [S1, unofficial].
- **Usage:** Used in interactive volume rendering systems supporting TF editing.
