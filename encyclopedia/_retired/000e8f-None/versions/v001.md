# Linear Depth Cueing via Fourier Projection-Slice Theorem

Also called: Fourier Projection-Slice Depth Cueing, Linear Attenuation via Fourier Projection-Slice, Linear Depth Cueing

## Overview
A shading model that enhances depth perception in X-ray projections by weighting volume points based on their distance from the viewer, without introducing occlusion [S1, unofficial]. It replaces per-voxel shading followed by projection with projection followed by per-pixel shading, allowing depth cueing (linear attenuation) to be computed efficiently by factoring the viewing direction out of the integral [S1, unofficial]. Unlike opaque volume renderings, this method produces X-ray-like projections with no occlusion, but the linear shading provides sufficient shape cues for spatial understanding, especially in motion [S1, unofficial].

## How it works
**Inputs:**
- Volume density $\rho(x,y,z)$ and emission coefficient $C(x,y,z)$, combined as $f(x,y,z) = \rho(x,y,z)C(x,y,z)$.
- Normalized viewing direction vector $\mathbf{V} = (V_x, V_y, V_z)$, pointing away from the eye [S1, S2, unofficial].
- Constant linear attenuation coefficient $\tau$ [S1, S2, unofficial].
- Linear depth function $\mathbf{D}(P) = mP + b$, where $P$ is position along the ray [S1, S2, unofficial].

**Outputs:**
- 2D projection image $I$ [S1, S2, unofficial].

**Data Structures:**
- Four 3D spectra (frequency domain representations) of the volume, each of size $N_x \times N_y \times N_z$ (complex values).
- Two-dimensional slices extracted from these spectra for inverse transformation.

**Steps:**
1. **Precomputation:**
   - Create four copies of the volume data $f(x,y,z)$.
   - Multiply the first copy by $1$.
   - Multiply the second copy by $D_x(x,y,z)$, the x-component of the depth function.
   - Multiply the third copy by $D_y(x,y,z)$, the y-component of the depth function.
   - Multiply the fourth copy by $D_z(x,y,z)$, the z-component of the depth function.
   - Compute the 3D Fourier Transform of each of the four modified volumes to yield four 3D spectra: $\mathcal{F}\{f\}$, $\mathcal{F}\{D_x f\}$, $\mathcal{F}\{D_y f\}$, and $\mathcal{F}\{D_z f\}$ [S1, unofficial].

2. **Per-view Rendering:**
   - For the current viewing direction $\mathbf{V}$, extract 2D slices from each of the four 3D spectra corresponding to the projection plane defined by $\mathbf{V}$ [S1, unofficial].
   - Compute the 2D Inverse Fourier Transform of each extracted slice to obtain spatial domain images [S1, unofficial].
   - Weight the inverse-transformed images by the components of $\mathbf{V}$ and the constant terms derived from the attenuation model:
     - Multiply the image from $\mathcal{F}\{D_x f\}$ by $V_x$.
     - Multiply the image from $\mathcal{F}\{D_y f\}$ by $V_y$.
     - Multiply the image from $\mathcal{F}\{D_z f\}$ by $V_z$.
     - Multiply the image from $\mathcal{F}\{f\}$ by the constant $c_1 = \tau/2 - \tau/2 (V_x + V_y + V_z)$ [S2, unofficial].
   - Sum the four weighted images to produce the final output image $I$ [S1, S2, unofficial].

**Formula:**
The intensity $I$ at a pixel is given by [S2, unofficial]:
$$ I = V_x \Pi_{\mathbf{V}} \left[ \left(\frac{\tau}{2} + \frac{\tau}{2} D_x \right) \rho C \right] + V_y \Pi_{\mathbf{V}} \left[ \left(\frac{\tau}{2} + \frac{\tau}{2} D_y \right) \rho C \right] + V_z \Pi_{\mathbf{V}} \left[ \left(\frac{\tau}{2} + \frac{\tau}{2} D_z \right) \rho C \right] + c_1 \Pi_{\mathbf{V}} [\rho C] $$
where $\Pi_{\mathbf{V}}$ is the projection operator, $D_x, D_y, D_z$ are components of $\mathbf{D}$, and $c_1 = \tau/2 - \tau/2 (V_x + V_y + V_z)$ [S2, unofficial].

The underlying integral being approximated is [S2, unofficial]:
$$ I_P = \int_a^b \rho(P(t)) C(P(t)) \left[ \frac{\tau}{2} + \frac{\tau}{2} (\mathbf{D}(P(t)) \cdot \mathbf{V}) \right] dt $$
where $\mathbf{D} = mP + b$ is a linear function of position [S2, unofficial].

**Parameters:**
- $\tau$: Constant linear attenuation coefficient [S1, S2, unofficial].
- $\mathbf{V}$: Normalized viewing direction vector [S1, S2, unofficial].
- $m, b$: Constants defining the linear depth function $\mathbf{D}$ [S1, S2, unofficial].

**Edge Cases and Pitfalls:**
- **Ghosting:** To avoid ghosting artifacts caused by spectral leakage, the input volume must be surrounded by a margin of zeros [S2, unofficial]. The margin width is $N(k_2-1)/2$ on each side, where $k_2$ is the factor by which the volume width is increased [S2, unofficial].
- **Viewing Direction Convention:** $\mathbf{V}$ must point away from the eye, not towards it [S1, S2, unofficial].

**Pseudocode:**
```python
def precompute_spectra(volume_rho, volume_C, depth_func_D):
    """
    Precomputes the four 3D spectra required for linear depth cueing.
    
    Args:
        volume_rho: 3D array of density values.
        volume_C: 3D array of emission coefficients.
        depth_func_D: Function or 3D array representing D(x,y,z) = (Dx, Dy, Dz).
        
    Returns:
        four_spectra: List of four 3D complex arrays [S_f, S_Dx, S_Dy, S_Dz].
    """
    # Combine density and emission
    volume_f = volume_rho * volume_C
    
    # Extract components of the depth function
    # Note: D is linear, D = mP + b. 
    # If depth_func_D is a function, evaluate it on the grid.
    # If it is an array, assume it contains the vector field.
    if callable(depth_func_D):
        # Assuming grid coordinates are available or implied
        # For simplicity, assume depth_func_D returns a tuple (Dx, Dy, Dz) for each voxel
        Dx, Dy, Dz = depth_func_D(volume_rho.shape) 
    else:
        # Assume depth_func_D is a 4D array (Nx, Ny, Nz, 3) or similar structure
        # This part depends on specific implementation details not fully specified in sources
        # [G] Assuming standard layout for vector field storage
        Dx = depth_func_D[..., 0]
        Dy = depth_func_D[..., 1]
        Dz = depth_func_D[..., 2]

    # Create four copies and multiply by depth components
    vol_1 = volume_f.copy()
    vol_Dx = volume_f * Dx
    vol_Dy = volume_f * Dy
    vol_Dz = volume_f * Dz

    # Compute 3D Fourier Transforms
    # Using standard FFT library
    S_f = fftn(vol_1)
    S_Dx = fftn(vol_Dx)
    S_Dy = fftn(vol_Dy)
    S_Dz = fftn(vol_Dz)

    return [S_f, S_Dx, S_Dy, S_Dz]

def render_linear_depth_cueing(spectra, viewing_direction_V, tau, projection_params):
    """
    Renders a single view using linear depth cueing via Fourier Projection-Slice Theorem.
    
    Args:
        spectra: List of four 3D complex arrays [S_f, S_Dx, S_Dy, S_Dz] from precompute_spectra.
        viewing_direction_V: Tuple (Vx, Vy, Vz) normalized vector pointing away from eye.
        tau: Constant linear attenuation coefficient.
        projection_params: Parameters needed to extract slices (e.g., rotation matrix, slice indices).
        
    Returns:
        image: 2D array representing the rendered projection.
    """
    S_f, S_Dx, S_Dy, S_Dz = spectra
    Vx, Vy, Vz = viewing_direction_V

    # Extract 2D slices from each 3D spectrum
    # The extraction method depends on the specific projection geometry
    # [G] Assuming a helper function extract_slice that handles the Fourier Slice Theorem mapping
    slice_f = extract_slice(S_f, projection_params)
    slice_Dx = extract_slice(S_Dx, projection_params)
    slice_Dy = extract_slice(S_Dy, projection_params)
    slice_Dz = extract_slice(S_Dz, projection_params)

    # Inverse Fourier Transform the slices
    img_f = ifftn(slice_f) # Result is 2D
    img_Dx = ifftn(slice_Dx)
    img_Dy = ifftn(slice_Dy)
    img_Dz = ifftn(slice_Dz)

    # Calculate constant c1
    c1 = tau / 2.0 - (tau / 2.0) * (Vx + Vy + Vz)

    # Weight and sum the images
    # Note: The formula in [S2, unofficial] groups the tau/2 terms with the D components.
    # However, the precomputation in [S1, unofficial] multiplies by D directly.
    # The formula I = Vx * Pi[(tau/2 + tau/2 Dx) f] ... implies that the spectra
    # should be of (tau/2 + tau/2 Dx) * f.
    # Let's re-read [S1, unofficial] carefully: "Four copies of rho C are created. Each is multiplied by 
    # the appropriate depth cueing function... The first three spectra represent volumes 
    # that are depth cued along one of object space coordinate axes."
    # And [S2, unofficial] formula: I = Vx Pi[(tau/2 + tau/2 Dx) rho C] ...
    # This implies the precomputation should include the tau/2 factor.
    # [G] Adjusting precomputation logic to match [S2, unofficial] formula exactly.
    # The precomputed spectra should be:
    # S_1 = FFT( (tau/2) * f )
    # S_Dx = FFT( (tau/2) * Dx * f )
    # etc.
    # But [S1, unofficial] says "multiplied by the appropriate depth cueing function component (1, Dx, Dy, Dz)".
    # And then "Weight the results by the appropriate component of the current viewing direction V".
    # Let's look at the summation in [S1, unofficial]: "summed to produce an image that is depth cued".
    # The formula in [S2, unofficial] is the definitive mathematical result.
    # I = Vx * Pi[ (tau/2 + tau/2 Dx) f ] + ...
    # This can be rewritten as:
    # I = (tau/2) * [ Vx * Pi[Dx f] + Vy * Pi[Dy f] + Vz * Pi[Dz f] + (1 - Vx - Vy - Vz) * Pi[f] ]
    # Wait, c1 = tau/2 - tau/2(Vx+Vy+Vz).
    # So the term for Pi[f] is c1 * Pi[f].
    # The terms for Pi[Dx f] are Vx * (tau/2) * Pi[Dx f].
    # So the precomputed spectra should be:
    # S_base = FFT( f )
    # S_Dx = FFT( Dx * f )
    # S_Dy = FFT( Dy * f )
    # S_Dz = FFT( Dz * f )
    # And the rendering weights are:
    # Weight for S_Dx slice: Vx * (tau/2)
    # Weight for S_Dy slice: Vy * (tau/2)
    # Weight for S_Dz slice: Vz * (tau/2)
    # Weight for S_base slice: c1 = tau/2 - tau/2(Vx+Vy+Vz)
    
    # Re-evaluating based on [S1, unofficial] text: "Weight the results by the appropriate component of the current viewing direction V (Vx, Vy, Vz, or 1) and sum them"
    # This suggests the tau/2 factor might be handled differently or absorbed.
    # However, [S2, unofficial] is explicit about the formula.
    # Let's stick to the formula in [S2, unofficial] for correctness.
    
    # Apply weights
    # Note: ifftn returns complex numbers, take real part if necessary
    term_Dx = Vx * (tau / 2.0) * img_Dx
    term_Dy = Vy * (tau / 2.0) * img_Dy
    term_Dz = Vz * (tau / 2.0) * img_Dz
    term_base = c1 * img_f

    # Sum them
    image = term_Dx + term_Dy + term_Dz + term_base
    
    return image.real
```

## Subtopics

### [Composite Depth Cueing and Directional Shading](1143-composite-depth-cueing-and-directional-shading.md)
Composite Depth Cueing and Directional Shading is a frequency-domain rendering technique that simultaneously applies linear depth cueing (attenuation) and hemispherical directional shading to volume data. It solves the problem of efficiently computing both effects within the Fourier Projection-Slice framework, where naive spatial-domain computation would be prohibitively expensive. It sets itself apart from its parent method, [Linear Depth Cueing via Fourier Projection-Slice Theorem](1129-linear-depth-cueing-via-fourier-projection-slice-theorem.md), by combining the attenuation model with a hemispherical illumination model that avoids the nonlinear absolute value operator, allowing the lighting direction to be factored out of the integral. This requires 16 precomputed spectra and is slower than individual models due to a high constant factor, though asymptotically less expensive than conventional rendering.

## Operating characteristics
- **Memory:** 48 megabytes for the 128^3 voxel cube implementation described [S1, unofficial].
- **Performance:** Rendering time was approximately 6 seconds per view on a 36 MHz Silicon Graphics 4D/320 VGX for the linear depth cueing equation (approx. 1.5 seconds per extracted slice) [S1, unofficial].
- **Scaling:** Per-view processing time increases by a factor of $k_2^2$ if the volume width is increased by a factor of $k_2$ due to zero padding [S2, unofficial]. Memory requirements increase by a factor of $k_2^3$ [S2, unofficial].
- **Strengths:** Efficient computation of depth cueing in the frequency domain; produces X-ray-like projections with shape cues [S1, unofficial].
- **Limitations:** No occlusion; requires zero-padding to avoid ghosting artifacts [S2, unofficial].

## Background
Originated in the work of Marc Levoy, described in "Volume Rendering using the Fourier Projection-Slice Theorem" [S1, S2, unofficial]. The method is part of a family of algorithms for generating realistically shaded renderings of volume data using the Fourier projection-slice theorem [S1, unofficial].
