# SSVDAG Node Layout and Tagged Pointer Encoding

Also called: Compact representation, Tagged pointer encoding

## Overview
This method defines the binary layout of inner nodes in a Symmetry-aware Sparse Voxel DAG (SSVDAG) to minimize memory footprint while supporting GPU-friendly traversal [S1]. It replaces fixed-size child pointers with variable-length tagged pointers (2 or 4 bytes) that embed transformation codes, solving the memory overhead problem of standard SVDAGs where all pointers are fixed at 4 bytes [S1]. It differs from its parent [Symmetry-aware Sparse Voxel DAG (SSVDAG)](1285-symmetry-aware-sparse-voxel-dag-ssvdag.md) by explicitly detailing the bit-packing scheme for these pointers and the associated traversal state management [S1].

## How it works

### Inputs and Outputs
*   **Input:** A voxelized scene represented as a Sparse Voxel DAG with symmetry-aware compression [S1].
*   **Output:** A memory layout for inner nodes where child pointers are encoded as variable-length tagged pointers, and a traversal algorithm that maintains a cumulative transformation status [S1].

### Data Structures

#### Inner Node Header
Each inner node begins with a 16-bit header [S1]. This header contains 8 entries, each 2 bits wide, corresponding to the 8 potential children in octant order [S1].
*   **Tag 00:** Null pointer. No child data follows [S1].
*   **Tag 01:** 16-bit child pointer [S1].
*   **Tag 10:** 32-bit child pointer [S1].
*   **Tag 11:** 32-bit child pointer [S1].

#### Child Pointer Encoding
Child pointers are stored immediately after the header [S1]. The size and format depend on the header tag [S1].

**1. 16-bit Pointer (Tag 01)**
*   **Size:** 2 bytes (16 bits) [S1].
*   **Layout:**
    *   Bits [15:13]: Transformation code (3 bits) [S1].
    *   Bits [12:0]: Offset in number of level-words (13 bits) [S1].
*   **Addressing:**
    *   For inner levels: Level-word size is 2 bytes [S1]. Max addressable offset is $2^{13} \times 2 = 2^{14}$ bytes (16 KB) [S1].
    *   For leaf levels: Level-word size is 8 bytes [S1]. Max addressable offset is $2^{13} \times 8 = 2^{16}$ bytes (64 KB) [S1].

**2. 32-bit Pointers (Tags 10 and 11)**
*   **Size:** 4 bytes (32 bits) [S1].
*   **Layout:**
    *   Bits [31:29]: Transformation code (3 bits) [S1].
    *   Bits [28:0]: Lowest 29 bits of the offset [S1].
    *   The highest bit of the full offset (bit 29) is not stored in the pointer; it is reconstructed from the least significant bit of the 2-bit header tag for that child [S1].
        *   If Tag is 10 (binary `10`), the header's LSB is 0, so the offset high bit is 0 [S1].
        *   If Tag is 11 (binary `11`), the header's LSB is 1, so the offset high bit is 1 [S1].
*   **Addressing:**
    *   For inner levels: Max addressable offset > 2 GB [S1].
    *   For leaf levels: Max addressable offset > 8 GB [S1].

### Traversal State
During ray traversal, a 3-bit **Transformation Status** variable is maintained [S1].
*   **Initialization:** 0 [S1].
*   **Update:** When descending to a child, XOR the current status with the 3-bit transformation code extracted from the child's pointer [S1].
*   **Restoration:** The status must be pushed to a stack along with the current node index to allow restoration upon backtracking [S1].
*   **Application:** This status indicates which reflections must be applied to indices when accessing child pointers in inner nodes or voxel contents in leaf nodes [S1].

### Algorithm: Accessing the i-th Child Pointer
Accessing the $i$-th child requires computing the byte offset within the node's data stream [S1]. Unlike SVDAG, where pointers are either 0 or 4 bytes, SSVDAG pointers are 0, 2, or 4 bytes [S1].
1. Read the 16-bit header.
2. Extract the 2-bit tag for child $i$.
3. Compute the byte offset from the start of the child pointer array:
   $$ \text{Offset} = \sum_{j=0}^{i-1} \text{Size}(\text{Tag}_j) $$
   Where $\text{Size}(\text{Tag}_j)$ is 0 if $\text{Tag}_j = 00$, 2 if $\text{Tag}_j = 01$, and 4 if $\text{Tag}_j \in \{10, 11\}$ [S1].
4. Read the pointer data at this offset.
5. Extract the transformation code from the top 3 bits [S1].
6. Decode the offset based on the pointer size (see formulas below) [S1].

### Formulas

**16-bit Pointer Offset Decoding:**
Let $P_{16}$ be the 16-bit integer value of the pointer [S1].
$$ \text{Transform} = P_{16} \gg 13 $$
$$ \text{WordOffset} = P_{16} \ \& \ 0x1FFF $$
$$ \text{ByteOffset} = \text{WordOffset} \times \text{LevelWordSize} $$
Where $\text{LevelWordSize} = 2$ for inner levels, $8$ for leaf levels [S1].

**32-bit Pointer Offset Decoding:**
Let $P_{32}$ be the 32-bit integer value of the pointer [S1].
$$ \text{Transform} = P_{32} \gg 29 $$
$$ \text{LowOffset} = P_{32} \ \& \ 0x1FFFFFFF $$
$$ \text{HighBit} = (\text{HeaderTag} \ \& \ 1) $$
$$ \text{FullOffset} = (\text{HighBit} \ll 29) \ | \ \text{LowOffset} $$
$$ \text{ByteOffset} = \text{FullOffset} \times \text{LevelWordSize} $$

### Pseudocode
```python
def decode_child_pointer(header_16bit, child_index, level_word_size, buffer):
    """
    Decodes the child pointer for a specific child index in an SSVDAG inner node.
    buffer: list of bytes containing the node data starting immediately after the header.
    """
    # Extract the 2-bit tag for the specific child
    tag = (header_16bit >> (child_index * 2)) & 0x3
    
    if tag == 0x0:
        # Null pointer
        return (0, None)
    
    # Calculate byte offset within the child pointer array
    # Sum sizes of all previous children [S1]
    byte_offset_in_array = 0
    for j in range(child_index):
        prev_tag = (header_16bit >> (j * 2)) & 0x3
        if prev_tag == 0x0:
            byte_offset_in_array += 0
        elif prev_tag == 0x1:
            byte_offset_in_array += 2
        else: # 0x2 or 0x3
            byte_offset_in_array += 4
            
    # Read pointer data based on size
    if tag == 0x1:
        # 16-bit pointer
        ptr_val = (buffer[byte_offset_in_array] << 8) | buffer[byte_offset_in_array + 1]
        transform_code = ptr_val >> 13
        word_offset = ptr_val & 0x1FFF
        byte_offset = word_offset * level_word_size
        return (transform_code, byte_offset)
        
    else:
        # 32-bit pointer (tags 0x2 or 0x3)
        ptr_val = (buffer[byte_offset_in_array] << 24) | (buffer[byte_offset_in_array + 1] << 16) | (buffer[byte_offset_in_array + 2] << 8) | buffer[byte_offset_in_array + 3]
        transform_code = ptr_val >> 29
        low_offset = ptr_val & 0x1FFFFFFF
        
        # Determine high bit from header tag
        header_tag_low_bit = tag & 0x1
        high_bit = header_tag_low_bit << 29
        full_offset = high_bit | low_offset
        byte_offset = full_offset * level_word_size
        
        return (transform_code, byte_offset)

def traverse_ssvdag_ray(ray_origin, ray_direction, node_buffer, level_word_size, level_offsets):
    """
    Demonstrates traversal logic with transformation status management.
    """
    # Stack for backtracking
    stack = []
    
    # Current transformation status
    current_transform = 0
    
    # Start at root (index 0)
    current_node_idx = 0
    current_level = 0 # [G] Track current tree level for offset lookup
    
    while True:
        # Read node header
        header = (node_buffer[current_node_idx] << 8) | node_buffer[current_node_idx + 1]
        
        # [G] Compute child_idx from ray-node intersection logic
        child_idx = None 
        
        if child_idx is None:
            # No intersection with this node's children, backtrack
            if not stack:
                break # Ray escaped
            
            # Restore state
            prev_node_idx, prev_transform = stack.pop()
            current_node_idx = prev_node_idx
            current_transform = prev_transform
            continue
            
        # Decode child pointer
        # [G] Buffer for child pointers starts after the header bytes.
        child_buffer = node_buffer[current_node_idx + 2:]
        transform_code, child_byte_offset = decode_child_pointer(header, child_idx, level_word_size, child_buffer)
        
        # Update transformation status
        # XOR with the pointer's reflection tag
        new_transform = current_transform ^ transform_code
        
        # Push current state to stack for backtracking
        stack.append((current_node_idx, current_transform))
        
        # Move to child
        # [G] Absolute child address requires adding the level start offset from level_offsets.
        current_node_idx = level_offsets[current_level] + child_byte_offset
        current_transform = new_transform
```

### Edge Cases and Pitfalls
*   **Variable Size Access:** Accessing the $i$-th child requires summing the sizes of all preceding pointers $[0, i-1]$ [S1]. This differs from SVDAG, which only had sizes 0 and 4 [S1]. This computation must be performed in the shader, typically via a manually unrolled loop [S1].
*   **Precision:** The 13-bit offset in 16-bit pointers limits addressing to the first 16 KB of inner levels and 64 KB of leaf levels [S1]. If a node is located beyond this range, it must use a 32-bit pointer (Tag 10 or 11) [S1].
*   **Transformation Accumulation:** The transformation status is cumulative [S1]. It must be XOR-ed with each pointer's transformation code as the traversal descends [S1]. It must be saved to the stack to be restored upon backtracking [S1].

## Operating characteristics
*   **Memory Footprint:** Significantly reduced compared to fixed-pointer SVDAGs [S1]. Null children consume 0 bytes, common children consume 2 bytes, and rare/distant children consume 4 bytes [S1].
*   **Complexity:**
    *   **Time:** Traversal requires computing variable offsets via a loop for each child access [S1].
    *   **Space:** Inner node headers are fixed at 16 bits [S1]. Child data is variable [S1].
*   **Performance:** Designed for GPU efficiency [S1]. The variable-length encoding allows compact storage, improving cache utilization [S1]. The transformation status is a simple 3-bit integer, minimizing register pressure [S1].
*   **Limitations:** The 16-bit pointer is limited to small offsets [S1]. Large scenes may require more 32-bit pointers, reducing the compression benefit [S1].

## Background
The SSVDAG node layout was introduced by Kämpe et al. in 2016 as an extension of the Sparse Voxel DAG (SVDAG) [S1]. The original SVDAG used fixed 4-byte pointers [S1]. The SSVDAG method was developed to further reduce memory consumption by exploiting the fact that many child pointers are null or point to nearby nodes, allowing for variable-length encoding [S1]. It also integrates symmetry-aware compression, storing transformation codes directly in the pointers [S1].
