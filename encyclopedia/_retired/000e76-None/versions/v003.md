# Wavelet-based Volume Rendering

Also called: Wavelet reconstruction, Wavelet compression rendering, Hierarchical wavelet rendering, Multiresolution wavelet rendering, Inverse wavelet transform rendering, Discrete Wavelet Transform (DWT) Volume Rendering

## Overview
Wavelet-based Volume Rendering is a technique that compresses volumetric data using wavelet transforms to enable efficient storage and rendering, particularly for large-scale or time-varying datasets [S1, unofficial]. It solves the problem of high memory bandwidth and storage requirements by representing the volume in a frequency domain where coefficients can be pruned or encoded [S1, unofficial]. It is distinguished from its sibling [Laplacian Pyramid Volume Rendering](2261-laplacian-pyramid-volume-rendering.md) by its use of orthogonal or biorthogonal wavelet bases (such as Haar or Daubechies) which provide multi-resolution analysis with better frequency localization, whereas Laplacian pyramids use fixed Gaussian filters [S3].

## How it works
**Inputs:** Original volumetric data $V$ of size $N \times N \times N$ [G].
**Outputs:** Rendered image $I$ and/or compressed bitstream [G].

**Data Structures:**
1. **Wavelet Coefficients:** A hierarchical set of coefficients organized by scale (level) and subband [G]. For a 3D transform, each level $j$ produces 8 subbands [G]. The dataset is filtered along every data direction with a given function/basis/filter to separate data into low-pass and high-pass components [S3]. The low-pass filtered data results in approximation coefficients, while the high-pass filtered data results in detail coefficients [S3].
2. **Compressed Bitstream:** Entropy-encoded wavelet coefficients [G].

**Parameters:**
* **Wavelet Basis:** e.g., Haar ($m=2$), Daubechies W6 ($m=6$) [S5, unofficial].
* **Quantization:** Optional. If used, the method is lossy; if not, it is lossless [S1, unofficial].
* **Error Tolerance:** User-specified threshold for adaptive resolution selection [S4, unofficial].

**Steps:**

1. **Encoding (Compression):**
    1. Apply 3D Wavelet Transform to $V$ to obtain coefficients $C$ [S1, unofficial].
    2. (Optional) Apply quantization to $C$ for lossy compression [S1, unofficial].
    3. Apply entropy reduction (run-length, arithmetic, or Huffman encoding) to $C$ to produce the bitstream [S1, unofficial].

2. **Decoding (Reconstruction):**
    1. Decode the compressed data [S1, unofficial].
    2. Perform Inverse Wavelet Transform on the decoded coefficients to reconstruct voxel values [S1, unofficial]. Reconstruction can be done point-wise, block-wise, or on-the-fly [S5, unofficial].
    3. Perform conditional reconstruction to select the data representation sufficiently accurate for rendering [S1, unofficial]. This may involve traversing the wavelet tree based on an error tolerance to decompress only necessary blocks [S4, unofficial].

3. **Rendering:**
    1. Render the reconstructed volume using standard volume rendering techniques (e.g., raycasting) [G].

**Pseudocode:**

```python
def wavelet_volume_rendering(volume_data, wavelet_type='haar', quantize=False, error_tolerance=None):
    """
    Main pipeline for wavelet-based volume rendering.
    """
    # Step 1: Encoding
    coefficients = wavelet_transform_3d(volume_data, wavelet_type)
    
    # Optional Quantization
    if quantize:
        coefficients = quantize_coefficients(coefficients)
        
    # Entropy Encoding (Compression)
    bitstream = entropy_encode(coefficients)
    
    # Step 2: Decoding
    # Decode bitstream
    decoded_coeffs = entropy_decode(bitstream)
    
    # Conditional Reconstruction / Adaptive Resolution
    if error_tolerance is not None:
        # Traverse tree and select blocks based on error tolerance
        selected_blocks = select_blocks_by_error(decoded_coeffs, error_tolerance)
        # Decompress only selected blocks
        reconstructed_volume = reconstruct_blocks(selected_blocks, wavelet_type)
    else:
        # Full reconstruction
        reconstructed_volume = inverse_wavelet_transform_3d(decoded_coeffs, wavelet_type)
        
    # Step 3: Rendering
    image = render_volume(reconstructed_volume)
    return image

def wavelet_transform_3d(data, wavelet_type):
    """
    Performs 3D wavelet transform using separable 1D transforms.
    """
    # Apply 1D transform along x
    temp_x = apply_1d_wavelet(data, axis=0, wavelet_type=wavelet_type)
    # Apply 1D transform along y
    temp_y = apply_1d_wavelet(temp_x, axis=1, wavelet_type=wavelet_type)
    # Apply 1D transform along z
    coefficients = apply_1d_wavelet(temp_y, axis=2, wavelet_type=wavelet_type)
    return coefficients

def apply_1d_wavelet(data, axis, wavelet_type):
    """
    Applies 1D wavelet transform along a specific axis.
    Performs convolution with wavelet kernel followed by downsampling.
    """
    # Transpose to process along axis
    data = transpose_3d(data, axis, 0)
    low, high = [], []
    for row in data:
        for i in range(0, len(row) - 1, 2):
            low.append((row[i] + row[i+1]) / 2.0)
            high.append((row[i] - row[i+1]) / 2.0)
        if len(row) % 2 == 1:
            low.append(row[-1])
            
    # Pack low and high bands
    result = []
    for l, h in zip(low, high):
        result.append([l, h])
    if len(low) > len(high):
        result.append([low[-1], 0.0])
        
    # Restore original axis order
    return transpose_3d(result, 0, axis)

def apply_1d_inverse_wavelet(data, axis, wavelet_type):
    """
    Applies 1D inverse wavelet transform along a specific axis.
    Upsamples and convolves with inverse kernel.
    """
    data = transpose_3d(data, axis, 0)
    reconstructed = []
    for pair in data:
        reconstructed.append(pair[0] + pair[1])
    return transpose_3d(reconstructed, 0, axis)

def inverse_wavelet_transform_3d(coefficients, wavelet_type):
    """
    Performs inverse 3D wavelet transform.
    """
    temp_z = apply_1d_inverse_wavelet(coefficients, axis=2, wavelet_type=wavelet_type)
    temp_y = apply_1d_inverse_wavelet(temp_z, axis=1, wavelet_type=wavelet_type)
    reconstructed = apply_1d_inverse_wavelet(temp_y, axis=0, wavelet_type=wavelet_type)
    return reconstructed

def transpose_3d(data, src_axis, dst_axis):
    """
    Pure Python 3D array transpose.
    """
    shape = [len(data), len(data[0]), len(data[0][0])]
    new_shape = list(shape)
    new_shape[src_axis], new_shape[dst_axis] = new_shape[dst_axis], new_shape[src_axis]
    result = [[[0 for _ in range(new_shape[2])] for _ in range(new_shape[1])] for _ in range(new_shape[0])]
    for i in range(shape[0]):
        for j in range(shape[1]):
            for k in range(shape[2]):
                indices = [i, j, k]
                new_indices = [indices[0], indices[1], indices[2]]
                new_indices[src_axis], new_indices[dst_axis] = new_indices[dst_axis], new_indices[src_axis]
                result[new_indices[0]][new_indices[1]][new_indices[2]] = data[i][j][k]
    return result

def quantize_coefficients(coefficients):
    """
    Quantizes wavelet coefficients for lossy compression.
    """
    return [[c / 4.0 for c in row] for row in coefficients]

def entropy_encode(coefficients):
    """
    Applies run-length encoding as per [S1, unofficial][S3].
    """
    encoded = []
    if not coefficients: return encoded
    current = coefficients[0]
    count = 1
    for val in coefficients[1:]:
        if val == current:
            count += 1
        else:
            encoded.append((current, count))
            current = val
            count = 1
    encoded.append((current, count))
    return encoded

def entropy_decode(bitstream):
    """
    Decodes the bitstream.
    """
    decoded = []
    for val, count in bitstream:
        decoded.extend([val] * count)
    return decoded

def select_blocks_by_error(coefficients, error_tolerance):
    """
    Traverses the wavelet tree to select blocks that satisfy the error tolerance.
    """
    selected = []
    for coeff in coefficients:
        if abs(coeff) > error_tolerance:
            selected.append(coeff)
    return selected

def reconstruct_blocks(selected_blocks, wavelet_type):
    """
    Reconstructs volume from selected wavelet blocks.
    """
    return inverse_wavelet_transform_3d(selected_blocks, wavelet_type)

def render_volume(volume):
    """
    Renders the volume using raycasting or similar method.
    """
    return [sum(row) for row in volume]
```

**Edge Cases and Pitfalls:**
* **Serial Decoding:** Lossless compression decoding is serial because it requires previous information to make the next decoding decision, making it difficult to implement efficiently on GPU [S1, unofficial].
* **Memory Access:** Without specific optimizations, the whole volumetric data must be decompressed in main memory to allow access for parts of the data [S1, unofficial].
* **Redundant Computation:** In block-wise reconstruction, adjacent blocks have redundant computation because the wavelet kernel extends outside the target block boundary [S5, unofficial].

## Subtopics

### [Wavelet-based Multiresolution Rendering](1588-wavelet-based-multiresolution-rendering.md)
An interactive rendering method for isosurfaces in a voxel grid where the underlying trivariate function is represented as a spline wavelet hierarchy. It allows adaptive, view-dependent selection of level-of-detail by superimposing appropriately weighted basis functions, decreasing resolution for distant parts to improve performance with minimal visual impact. It is distinguished from its sibling [Hierarchical Wavelet Transform on Omnitrees](2216-hierarchical-wavelet-transform-on-omnitrees.md) by its specific use of polynomial spline wavelets with B-spline basis functions to guarantee continuous surfaces and its implementation of a gathering-based CUDA kernel for reconstruction rather than scattering.

### [Hierarchical Wavelet Transform on Omnitrees](2216-hierarchical-wavelet-transform-on-omnitrees.md)
This method transforms nodal omnitree data into wavelet coefficients to enable lossless or lossy compression via pruning and tree restructuring (downsplit). It operates directly on the omnitree's anisotropic structure, allowing coarsening in specific dimensions while preserving the hierarchical spatial layout.

### [L2-optimal wavelet splatting](2816-l2-optimal-wavelet-splatting.md)
L2-optimal wavelet splatting is a volume rendering technique that decomposes volume data into a wavelet pyramid representation in the spline domain and computes splats via an orthogonal projection operator using least-squares approximation on an adaptive multiresolution grid. It sets itself apart from standard interpolation-based wavelet splatting (such as [Wavelet-based Multiresolution Rendering](1588-wavelet-based-multiresolution-rendering.md)) by ensuring the smallest possible approximation error for a given sampling step size and by adapting the grid resolution to the basis function size, which yields significant performance gains at coarse scales.

### [Point-wise Inverse Discrete Wavelet Transform (PW-IDWT) via Generalized Projection](3394-point-wise-inverse-discrete-wavelet-transform-pw-idwt-via-ge.md)
The Point-wise Inverse Discrete Wavelet Transform (PW-IDWT) via Generalized Projection (GP) reconstructs a single signal sample (or a set of samples) from a wavelet decomposition by determining the minimal set of subband coefficients required. It solves the problem of identifying which coefficients at a coarser level contribute to a specific sample at a finer level during synthesis, exploiting the recursive nature of the lifting scheme. Unlike methods that decode entire subbands, this approach calculates the exact "Generalized Projection" of a sample into the transformed domain, minimizing the number of subband images to decode. It builds on [Wavelet-based Volume Rendering](1052-wavelet-based-volume-rendering.md) by providing an efficient, sample-specific inverse transform mechanism [G].

### Wavelet-based Adaptive Resolution Volume Rendering
A rendering technique that stores reconstructed data at pre-selected wavelet tree nodes based on available storage to reduce reconstruction cost, then traverses the tree per error tolerance to decompress and render blocks in parallel [S4, unofficial].
* **Steps:** 1. Traverse the wavelet tree according to a user-specified error tolerance [S4, unofficial]. 2. Identify data blocks of different resolutions that satisfy the error tolerance [S4, unofficial]. 3. Decompress the selected blocks [S4, unofficial]. 4. Render the decompressed blocks in parallel to compose the final image [S4, unofficial].
* **Parameters:** Error tolerance: User-specified threshold that controls wavelet tree traversal depth and determines which resolution blocks are decompressed and rendered [S4, unofficial].
* **Characteristics:** Reduces run-time communication cost to a minimum and ensures a well-balanced workload among processors when visualizing gigabytes of data with arbitrary error tolerances [S4, unofficial].

### Block-wise Wavelet Reconstruction
A reconstruction method that processes wavelet coefficients in blocks rather than point-wise to reduce redundant computation during volume rendering [S5, unofficial].
* **Steps:** Reconstruct a block of voxels along the z dimension by convolving the input with a wavelet kernel of size $m$ row by row [S5, unofficial]. Perform three passes (one for each dimension) to complete the reconstruction [S5, unofficial].
* **Formula:** The computational cost for one pass is $mn^3$, where $m$ is the kernel size and $n$ is the dimension size. Total cost for three passes is $3mn^3$. Point-wise cost is $m^3n^3$. The efficiency factor is $k = m^2/3$ [S5, unofficial].
* **Parameters:** Kernel size $m$: For Haar wavelet, $m=2$; for Daubechies W6, $m=6$ [S5, unofficial].
* **Pitfall:** Adjacent blocks have redundant computation because the wavelet kernel extends outside the target block boundary [S5, unofficial].

### On-the-fly Voxel Reconstruction
A method to reconstruct voxel values on-the-fly from wavelet coefficients during rendering, avoiding pre-computation of the entire volume [S5, unofficial]. It involves finding the appropriate wavelet coefficient at level $k$ and applying inverse wavelet transforms iteratively down to level 0 [S5, unofficial].
* **Steps:**
    1. Given a wavelet coefficient with $k$ levels and a target voxel $(x_0, y_0, z_0)$, find the voxel (cube of size $1 \times 1 \times 1$) from the level $k$, $w_k$, whose reconstruction contains the target voxel [S5, unofficial]. Map indices $x_0, y_0, z_0$ to $x_k, y_k, z_k$ in $w_k$ by dividing $x_0, y_0, z_0$ by $2^k$ [S5, unofficial]. The resultant voxel is in the LLL region of $w_k$ [S5, unofficial].
    2. Find the corresponding voxel in the other seven regions of the decomposed data (fHHH, fLLH, fHHL, fHLL, fLHH, fLHL, fLLH, fLLL) [S5, unofficial]. To do this, add half of the size of $x_k, y_k$, and $z_k$ (dimensions of $w_k$) to $x_k, y_k$, and $z_k$ respectively [S5, unofficial].
    3. Apply the inverse wavelet transformation to the above eight sub-cubes to reconstruct a new sub-cube with size doubled in each axis ($x_{k-1}, y_{k-1}, z_{k-1}$) [S5, unofficial]. The new reconstructed sub-cube will be in the LLL of $w_{k-1}$ [S5, unofficial].
    4. Repeat steps 2 and 3 until level 0 ($w_0$) is reached [S5, unofficial]. The resultant sub-volume is of size $2^k \times 2^k \times 2^k$ containing the desired voxel $(x_0, y_0, z_0)$ [S5, unofficial].

### Wavelet Splatting Method 1
A wavelet-based volume rendering method with slower complexity decay compared to Method 2 [S6].
* **Complexity:** Time complexity $Op_1$ decays with a factor of $2^j$ per scale $j$ [S6].
* **Comparison:** Method 1 is slower than Method 2, with $Op_2$ decaying with up to $2^{3j}$ per scale $j$ whereas $Op_1$ decays with only $2^j$ [S6].

### EZW-3-D
A 3-D wavelet-based coding algorithm used for comparison, including a context-modeling variant (3-D CB-EZW) [S7].
* **Performance:** On MR-MRI data, 3-D CB-EZW achieved 2.285 bit/voxel (integer 5-3 filter) and 2.195 bit/voxel (two-level integer transform with (1,1) filter) [S7].

## Operating characteristics
* **Time Complexity:** Depends on the reconstruction method. Point-wise reconstruction has complexity $O(m^3 n^3)$, while block-wise reconstruction reduces this to $O(3mn^3)$, offering an efficiency factor of $k = m^2/3$ [S5, unofficial]. Wavelet splatting Method 1 has complexity decaying with $2^j$ per scale, while Method 2 decays with $2^{3j}$ [S6].
* **Memory Complexity:** Lossless compression decoding is serial and may require decompressing the whole volume in main memory unless optimized [S1, unofficial]. Adaptive methods reduce memory usage by only decompressing necessary blocks [S4, unofficial].
* **Measured Performance:** On MR-MRI data, 3-D CB-EZW achieved lossless rates of 2.285 and 2.195 bit/voxel [S7].
* **Strengths:** High compression ratios, support for multi-resolution rendering, and efficient storage of large datasets [S1, unofficial].
* **Limitations:** Serial nature of lossless decoding makes GPU implementation difficult [S1, unofficial]. Redundant computation in block-wise reconstruction [S5, unofficial].
* **When to use:** Large-scale time-varying data visualization on PC clusters or workstations [S1, unofficial].
* **When not to use:** When real-time interactive rendering on GPU is required with lossless compression and no specific optimizations are used [S1, unofficial].

## Background
Wavelet-based volume rendering originated from the application of wavelet transforms to volumetric data compression and rendering [S3]. It has been thoroughly studied by researchers in recent years, with overviews provided by Stollnitz et al. [S1, unofficial]. The method is used in frameworks like WTSP (Wavelet-based Time-Space Partitioning) tree for large-scale time-varying data visualization on PC clusters [S1, unofficial]. The technique leverages the multi-resolution properties of wavelets to enable adaptive rendering and efficient data storage [S1, unofficial].
