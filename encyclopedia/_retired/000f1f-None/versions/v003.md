# Inter-Ray Coherency

Also called: Reference Ray Caster

## Overview
Inter-Ray Coherency accelerates volume rendering by exploiting the spatial correlation between adjacent rays, assuming that neighboring rays traverse similar voxel sequences and encounter similar surface structures. It sets itself apart from sibling methods like [Temporal Differential Rendering](5499-temporal-differential-rendering.md) by leveraging spatial proximity within a single frame rather than temporal consistency across frames, and from [Intra-ray Parallelism](3135-intra-ray-parallelism.md) by focusing on data reuse between distinct rays rather than parallelizing the computation along a single ray path.

## How it works
**Inputs:** A 3D volume dataset, a set of eye rays (one per pixel), and a buffer storing the traversal state of the previously processed ray.
**Outputs:** A rendered image with reduced computational overhead.

**Data Structures:**
1.  **Reference Buffer:** Stores the sequence of cells (voxels) encountered by the last processed ray.
2.  **Intersection Flag:** A boolean or bitmask associated with the buffer, indicating whether a portion of the iso-surface (or relevant feature) is contained within the stored cells.

**Algorithm Steps:**
1.  **Ray Traversal:** For each ray, perform fast voxel traversal from the eye point towards the volume.
2.  **Coherency Check:** Compare the current ray's path against the data stored in the Reference Buffer.
3.  **Early Termination/Skip:** If the current ray visits the same cells as the reference ray and the Intersection Flag indicates no iso-surface intersection in those cells, skip the expensive ray-surface intersection tests for those segments.
4.  **Intersection Test:** If the coherency check fails or the flag indicates a potential intersection, perform fast ray-surface intersection tests as described in standard cell-based first-hit ray casting [S1, unofficial].
5.  **Buffer Update:** After processing the ray, update the Reference Buffer with the cells encountered by the current ray and update the Intersection Flag based on the result.

**Pseudocode:**
```python
# Global state
reference_cells = [] # List of cell coordinates from the last ray
reference_has_intersection = False # Flag indicating iso-surface presence in reference_cells

def render_ray(ray_origin, ray_direction, volume):
    global reference_cells, reference_has_intersection
    
    # 1. Traverse the volume
    current_cells = []
    has_intersection = False
    
    # Fast voxel traversal to find candidate cells
    for cell in traverse_voxels(ray_origin, ray_direction, volume.bounds):
        current_cells.append(cell)
        
        # 2. Check coherency with reference
        if cell in reference_cells:
            # If we are in a known cell from the previous ray
            if not reference_has_intersection:
                # 3. Skip intersection test if flag says no surface
                continue
            else:
                # If flag says surface might be here, we must check
                pass
        
        # 4. Perform intersection test if needed
        # This is the expensive operation being optimized
        if check_ray_surface_intersection(ray_origin, ray_direction, cell, volume):
            has_intersection = True
            # Handle hit (e.g., return color, break if first-hit)
            return compute_color(ray_origin, ray_direction, cell, volume)
            
    # 5. Update reference buffer for next ray
    # In a real implementation, this might be done in a separate pass or with synchronization
    reference_cells = current_cells
    reference_has_intersection = has_intersection
    
    return background_color
```

**Parameters:**
*   **Reference Buffer Size:** Not explicitly defined, but effectively limited by the ray length through the volume.
*   **Iso-value Threshold:** Used to determine surface presence. Note: Distance coding was not used in the reference implementation because it would require recomputation for each new iso-value [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Iso-value Changes:** If the iso-value changes between rays, the reference buffer becomes invalid unless distance coding is employed, which adds computational cost [S1, unofficial].
*   **Discontinuous Geometry:** In regions with high-frequency detail or discontinuities, the assumption of inter-ray coherency breaks down, leading to missed optimizations or incorrect skips.
*   **Synchronization:** In parallel implementations, updating the reference buffer must be handled carefully to avoid race conditions if multiple rays update it simultaneously.

## Subtopics

### Marching Caches
An explicit data caching strategy that exploits inter-ray coherence by maintaining a shared cache around a bundle of rays, which is incrementally updated as the ray front advances through the volume [S2]. It differs from the basic Reference Ray Caster by explicitly managing a shared memory cache for a bundle of rays rather than a single reference ray, allowing for higher-order filters and significant bandwidth reduction [S2]. Choose this method when memory bandwidth is the bottleneck and higher-order reconstruction filters are required [S2].

**Steps:**
1.  **Align Bundle:** Align a bundle of rays such that the ray front accesses the same data simultaneously [S2].
2.  **Create Cache:** Create a cache containing the required data around the bundle of rays [S2].
3.  **Incremental Update:** Incrementally update the cache in the direction of the rays as they traverse the volume, where neighboring rays share fast memory to fill missing values [S2].
4.  **Synchronize:** Synchronize the ray front and incrementally update the cache as the ray front advances [S2].

**Parameters:**
*   **Filters:** Supports Catmul-Rom, B-spline, ambient occlusion projection, trilinear, bilateral, gradient, and filtered gradient [S2].

**Performance:**
*   Achieved a speedup of four times compared to using implicit hardware caching [S2].
*   Reduced memory bandwidth to global memory by orders of magnitude [S2].

## Operating characteristics
**Time Complexity:** The method reduces the number of expensive ray-surface intersection tests. The reference implementation accelerated rendering by about 60 percent [S1, unofficial]. Marching Caches achieved a four-fold speedup [S2].
**Memory Complexity:** Requires additional memory for the reference buffer or marching cache. Marching Caches reduce global memory bandwidth, which is critical for performance on GPUs [S2].
**Strengths:** Significant performance gains in coherent scenes; reduces memory bandwidth pressure.
**Limitations:** Performance degrades in scenes with high-frequency details or when iso-values change frequently. The reference implementation did not use distance coding, limiting flexibility with iso-values [S1, unofficial].

## Background
The concept of Inter-Ray Coherency was introduced in the context of cell-based first-hit ray casting by Neubauer, Mroz, Hauser, and Wegenkittl [S1, unofficial]. The Marching Caches variant was later proposed to address memory bandwidth limitations on parallel processors by explicitly managing shared memory caches [S2].
