# CSG Model Voxelization
Also called: Boolean CSG voxelization

## Overview
CSG Model Voxelization is a GPU-accelerated method for converting Constructive Solid Geometry (CSG) models into voxel grids by rendering individual CSG nodes into 2D textures (worksheets or slicemaps) and performing boolean operations in image space using GPU blending [S1, S2, S3, unofficial]. It solves the problem of efficiently computing the volumetric representation of complex boolean combinations of meshes, which is particularly useful for collision detection, haptic feedback, and transparent illustration [S3, unofficial]. It sets itself apart from sibling methods like [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by explicitly leveraging the GPU's fixed-function blending hardware to execute boolean logic (AND, OR, NOT) directly on the voxel data during the rendering pass, rather than post-processing or using complex CPU-side data structures [S1, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A CSG tree representing the model, where leaf nodes are polygon meshes (or parametric surfaces) and internal nodes are boolean operators (Union, Intersection, Difference) [S1, S3, unofficial].
*   **Output:** A 3D voxel grid (or a stack of 2D slicemaps) representing the final boolean result [S1, S3, unofficial].

**Data Structures:**
*   **Worksheet / Slicemap:** A 2D texture (or render target) representing a single slice of the voxel grid. It stores binary occupancy or multivalued data (e.g., normals, material IDs) for the voxels in that slice [S1, S2, S3, unofficial].
*   **CSG Tree:** A hierarchical structure of nodes. Each node has a type (leaf or boolean) and children [S1, S3, unofficial].

**Steps:**
1.  **Voxelize Leaf Nodes:** For each leaf node (mesh) in the CSG tree, render the mesh into its dedicated 2D worksheet/slicemap. This is typically done using a vertex shader that transforms vertices to 3D space and projects them onto the 2D slice, writing occupancy bits to the texture [S1, S2, unofficial].
2.  **Evaluate Boolean Operations:** Process the CSG tree from the bottom up (leaves to root). For each internal boolean node:
    *   Retrieve the 2D textures (worksheets) corresponding to its children.
    *   Perform the boolean operation (Union, Intersection, Difference) on these 2D textures using GPU blending operations. For example, Union might use `glBlendFunc(GL_ONE, GL_ONE)`, Intersection might use `glBlendFunc(GL_DST_COLOR, GL_ZERO)` or similar blending modes depending on the specific implementation of the boolean logic in the fragment shader or fixed-function pipeline [S1, S3, unofficial].
    *   Store the result in a new 2D texture (worksheet) for this node.
3.  **Handle CSG Trees:** For complex CSG trees with height $n$, intermediate results are stored. The storage requirement is noted as $O(\log^* n)$ where $n$ is the height of the tree, though rearranging the tree can optimize this [S3, unofficial].
4.  **Final Output:** The root node's worksheet represents the final voxelized CSG model. If a full 3D volume is needed, this process is repeated for all slices along the desired axis [S1, S3, unofficial].

**Pseudocode:**
```python
def voxelize_csg(csg_tree, slice_resolution):
    """
    Voxelizes a CSG tree into a 3D volume by processing each slice.
    """
    # Assume csg_tree is a node with type 'leaf' or 'boolean'
    # and children if boolean.
    # slice_resolution is (width, height) for the 2D slicemap.
    
    # Dictionary to store the 2D texture (slicemap) for each node
    node_slicemaps = {}
    
    # Helper function to evaluate a node's slicemap
    def evaluate_node(node):
        if node.type == 'leaf':
            # Voxelize the leaf mesh into a new 2D texture
            slicemap = create_empty_texture(slice_resolution)
            render_mesh_to_texture(node.mesh, slicemap)
            node_slicemaps[node.id] = slicemap
            return slicemap
        elif node.type == 'boolean':
            # Evaluate children first
            left_slicemap = evaluate_node(node.left_child)
            right_slicemap = evaluate_node(node.right_child)
            
            # Create result texture
            result_slicemap = create_empty_texture(slice_resolution)
            
            # Perform boolean operation using GPU blending
            # The exact blending function depends on the boolean operator
            if node.operator == 'UNION':
                blend_func = GL_ONE, GL_ONE # Example blending
            elif node.operator == 'INTERSECTION':
                blend_func = GL_DST_COLOR, GL_ZERO # Example blending
            elif node.operator == 'DIFFERENCE':
                blend_func = GL_ONE, GL_ONE_MINUS_SRC_ALPHA # Example blending
            
            render_two_textures(left_slicemap, right_slicemap, result_slicemap, blend_func)
            node_slicemaps[node.id] = result_slicemap
            return result_slicemap
        else:
            raise ValueError("Unknown node type")

    # Process all slices (e.g., along Z-axis)
    volume = []
    for z in range(slice_resolution[1]): # Assuming height is Z
        # Update camera/viewport for current slice
        set_slice_viewport(z)
        
        # Evaluate the entire CSG tree for this slice
        root_slicemap = evaluate_node(csg_tree.root)
        
        # Add the 2D slice to the 3D volume
        volume.append(read_texture_to_array(root_slicemap))
        
    return volume
```

**Parameters:**
*   **Slice Resolution:** The resolution of each 2D slicemap. High resolutions (e.g., $1024^3$) are supported [S3, unofficial].
*   **Blending Function:** The specific GPU blending mode used to implement each boolean operator [S1, S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** The method works at a precision of several billion ($10^9$) voxels in real-time [S3, unofficial].
*   **Artifacts:** Previous solutions for CSG or inter-object intersection were more complex and could contain artifacts; this method aims to reduce such artifacts by using solid voxelization [S3, unofficial].
*   **Memory:** Storing intermediate results for deep CSG trees can be memory-intensive, though the storage is noted as $O(\log^* n)$ [S3, unofficial].

## Subtopics

### CSG and Inter-object Intersection
This variant focuses on using CSG voxelization for testing object penetration and collision detection. It voxelizes each object into a separate slicemap and renders them over each other with blending to compute the boolean intersection. The density computation allows for rapid recovery of the intersection's volume, which is useful for collision detection or haptic feedback. It works at a precision of several billion ($10^9$) voxels in real-time with low dependence on input geometry complexity [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Real-time performance is claimed, with low dependence on input geometry complexity [S3, unofficial]. The cost is directly linked to the voxelization process itself [S3, unofficial].
*   **Memory Complexity:** Storage for intermediate results in CSG trees is noted as $O(\log^* n)$ where $n$ is the height of the tree, though this can be optimized by rearranging the tree [S3, unofficial].
*   **Performance:** Works at a precision of several billion ($10^9$) voxels in real-time [S3, unofficial].
*   **Strengths:** Simple implementation leveraging GPU hardware; efficient for complex boolean combinations; suitable for real-time applications like collision detection and haptic feedback [S3, unofficial].
*   **Limitations:** Requires GPU support for blending operations; memory usage for deep CSG trees can be a concern [S3, unofficial].
*   **When to Use:** When real-time voxelization of complex CSG models is needed, especially for collision detection, haptic feedback, or transparent illustration [S1, S3, unofficial].
*   **When Not to Use:** When CPU-side processing is preferred, or when the CSG tree is extremely deep and memory is constrained [S3, unofficial].

## Background
CSG Model Voxelization was introduced in the context of real-time voxelization for complex models. It leverages the GPU's ability to perform boolean operations on 2D textures via blending operations, making it straightforward to voxelize CSG models [S1, S2, unofficial]. It has been applied to problems such as transparent illustration and inter-object intersection testing [S1, S3, unofficial].
