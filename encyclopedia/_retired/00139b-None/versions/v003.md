# CSG Model Voxelization

Also called: Boolean CSG voxelization

## Overview
CSG Model Voxelization is a method for converting Constructive Solid Geometry (CSG) models into voxel grids by voxelizing individual CSG nodes into 2D texture worksheets and performing boolean operations in image space using GPU blending [S1, S2, unofficial]. It differs from its siblings, [Out-of-Core Point-Based Rendering](6825-out-of-core-point-based-rendering.md) and [Point Feature Generation](6972-point-feature-generation.md), by operating on volumetric occupancy data derived from rasterization rather than point clouds, enabling efficient boolean logic on complex meshes [S1, S2, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A CSG tree composed of primitive nodes (e.g., spheres, boxes) or mesh nodes, and a target voxel resolution (grid dimensions).
*   **Output:** A 3D voxel grid (or a set of 2D slices/slicemaps) representing the boolean combination of the input geometry.

**Data Structures:**
*   **Worksheet/Slicemap:** A 2D texture (or buffer) representing a single slice or the entire voxel volume projected onto the GPU. For single-object voxelization, this stores occupancy bits. For CSG trees, intermediate results are stored in these textures [S1, S2, S3, unofficial].
*   **CSG Tree:** A hierarchical structure where leaves are primitives/meshes and internal nodes are boolean operators (Union, Intersection, Difference) [S1, S2, unofficial].

**Steps:**
1.  **Voxelize Nodes:** Each leaf node of the CSG tree is voxelized individually into its respective 2D texture worksheet (or slicemap) [S1, S2, unofficial].
    *   For parametric surfaces, vertices are processed in a vertex shader. Texture coordinates in the parametric domain are used to calculate 3D positions, which are then transcoded to the worksheet [S1, S2, unofficial].
    *   For meshes, standard rasterization techniques are used to fill the worksheet with occupancy data [S3, unofficial].
2.  **Perform Boolean Operations:** The CSG constructions are performed from the bottom of the tree to the top automatically in image space [S1, S2, unofficial].
    *   This is achieved by rendering the 2D textures defined by the child nodes onto a target texture, using GPU blending operations that correspond to the boolean operator (e.g., additive blending for Union, multiplicative for Intersection) [S1, S2, unofficial].
    *   For inter-object CSG, each object is voxelized into a separate slicemap. The first object's slicemap is rendered over the second, blending with the desired boolean operation [S3, unofficial].
3.  **Finalize:** The top node of the CSG tree yields the final voxelized result [S1, S2, unofficial].

**Parameters:**
*   **Voxel Resolution:** Determines the precision. The method works at a precision of several billion ($10^9$) voxels in real-time [S3, unofficial].
*   **Blending Mode:** Defined by the boolean operator (Union, Intersection, Difference) [S1, S2, S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** The method relies on the rasterization precision and the resolution of the worksheets. Artifacts may occur if the resolution is too low for the geometry complexity [S3, unofficial].
*   **CSG Tree Height:** Extending to CSG trees requires storing intermediate results. The storage requirement is intuitively $\log^* n$ where $n$ is the height of the tree, though rearranging the tree can optimize this [S3, unofficial].
*   **Transparent Illustration:** For multivalued voxelization (e.g., storing normals, texture coordinates, material IDs), the worksheet must store combinations of these values, and lighting must be enabled in the rendering stage to show appearance [S1, S2, unofficial].

## Subtopics

### [SDF-based Voxelization](6595-sdf-based-voxelization.md)
SDF-based Voxelization is a method to visualize any Constructive Solid Geometry (CSG) mesh or analytic primitive as a Minecraft-style voxel chunk pile by determining world-space bounding boxes, sampling a 3D grid, and querying Signed Distance Fields (SDF) to determine occupancy. It differs from GPU-based rasterization voxelization by relying on CPU-side SDF queries and storing results in a packed bitmap for later rendering as analytic box primitives, enabling A/B comparison with the original mesh without shader changes.

### CSG and Inter-object Intersection
CSG and Inter-object Intersection is a specific application of CSG Model Voxelization for testing object penetration and computing intersection volumes [S3, unofficial]. It performs general CSG by voxelizing each object in a separate slicemap and rendering one over the other with blending for the desired boolean operation [S3, unofficial]. It allows for rapid recovery of the intersection's volume for collision detection or haptic feedback [S3, unofficial]. It extends to CSG trees by storing intermediate results, requiring $\log^* n$ storage where $n$ is the height of the tree [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Real-time performance is achieved, with low dependence on input geometry complexity [S3, unofficial]. The cost is directly linked to the voxelization resolution [S3, unofficial].
*   **Memory Complexity:** For CSG trees, storage is intuitively $\log^* n$ where $n$ is the height of the tree, though this can be optimized by rearranging the tree [S3, unofficial].
*   **Strengths:** Simple implementation for complex CSG operations; works at high precision ($10^9$ voxels); enables rapid volume computation for collision/haptics; simplifies transparent illustration [S1, S2, S3, unofficial].
*   **Limitations:** Precision is limited by voxel resolution; artifacts may occur with complex geometry if resolution is insufficient [S3, unofficial].
*   **When to use:** When real-time CSG operations on complex meshes are needed, or when rapid volume computation for collision detection is required [S3, unofficial].
*   **When not to use:** When exact boundary representation is required without discretization errors [S3, unofficial].

## Background
CSG Model Voxelization was introduced in the context of real-time voxelization for complex models [S1, S2, unofficial]. It leverages the GPU's ability to perform boolean operations on 2D textures via blending operations [S1, S2, unofficial]. The method was further applied to inter-object intersection and collision detection, demonstrating its utility in haptic feedback and real-time visualization [S3, unofficial].
