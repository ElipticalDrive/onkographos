# Adaptive Contouring via Octree Vertex Clustering

Also called: Adaptive Simplification, Octree-based Vertex Clustering

## Overview
Adaptive Contouring via Octree Vertex Clustering is a surface extraction method that constructs multi-resolution iso-surfaces by clustering vertices of child cells in an octree into a single vertex in a topologically safe manner [S1, unofficial]. It allows an arbitrary number of vertices per cell, significantly reducing polygon count in flat regions compared to methods restricted to one vertex per cell [S1, unofficial]. It sets itself apart from [Dual Contouring with Octree](1271-dual-contouring-with-octree.md) by permitting multiple vertices per cell through a clustering phase, and from [Manifold Dual Contouring](2138-manifold-dual-contouring.md) by its specific vertex-tree-based clustering mechanism which requires additional constraints to guarantee manifold topology [S1, unofficial].

## How it works
**Inputs:** An octree representation of the volume data; an error threshold $\epsilon$.
**Outputs:** A polygonal mesh representing the iso-surface.

**Data Structures:**
*   **Vertex:** Contains a parent pointer `p`, a Quadratic Error Function (QEF) matrix/vector pair $(A, b)$, and the scalar error value $E = \|A\mathbf{v} - \mathbf{b}\|^2$ evaluated at the vertex position $\mathbf{v}$ [S1, unofficial].
*   **Vertex Tree:** A hierarchical structure where leaves are finest-level octree vertices and internal nodes represent clustered vertices. Each vertex maintains a pointer to its parent in this tree [S1, unofficial].
*   **Cell Status:** Each octree cell has a boolean flag `collapsed` [S1, unofficial].

**Parameters:**
*   `error_threshold` ($\epsilon$): The maximum allowed QEF error for a vertex to be considered collapsible. If $E < \epsilon$, the vertex is marked collapsible [S1, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    *   Create a vertex tree starting with all vertices at the finest level of the octree [S1, unofficial].
    *   For each vertex, initialize its parent pointer to `NULL` [S1, unofficial].
    *   Flag all vertices as `collapsible` [S1, unofficial].

2.  **Bottom-Up Traversal and Clustering:**
    *   Traverse octree cells from bottom to top [S1, unofficial].
    *   For each non-leaf cell, consider its eight children [S1, unofficial].
    *   Identify the twelve internal faces shared by these children (4 for each Euclidean axis) [S1, unofficial].
    *   Find edges dual to these twelve internal faces using a recursive octree traversal algorithm (e.g., Ju et al. [3]) [S1, unofficial].
    *   Group vertices at the root of the vertex tree that are topologically connected by these dual edges [S1, unofficial].
    *   For each group:
        *   Combine the QEFs of all vertices in the group: $A_{new} = \sum A_i$, $\mathbf{b}_{new} = \sum \mathbf{b}_i$ [S1, unofficial].
        *   Minimize the combined error function to find the new vertex location $\mathbf{v}_{new}$ and its error $E_{new}$ [S1, unofficial].
        *   If $E_{new} < \epsilon$, mark the new vertex as `collapsible` [S1, unofficial].
        *   Set the parent pointers of the grouped vertices to point to this new vertex [S1, unofficial].

3.  **Cell Collapse Optimization:**
    *   Mark a cell as `collapsed` if all clustered vertices created within it satisfy the collapsible criterion ($E < \epsilon$) AND all children of that cell are either leaf cells or marked as `collapsed` [S1, unofficial].

4.  **Polygon Generation:**
    *   Traverse the octree to generate polygons [S1, unofficial].
    *   For each edge exhibiting a sign change in the volume data, create a polygon connecting the associated vertices [S1, unofficial].
    *   For each such vertex, follow its parent pointers up the vertex tree to find the last vertex marked as `collapsible` [S1, unofficial].
    *   Include a vertex in the output mesh if it is marked `collapsible` and has no `collapsible` ancestors in the vertex tree [S1, unofficial].
    *   **Optimization:**
        *   If a cell is `collapsed`, truncate the `cellProc` traversal; no children polygons are generated [S1, unofficial].
        *   If both cells sharing a face are `collapsed`, truncate the `faceProc` traversal for that face [S1, unofficial].

            new_vertex.is_collapsible = (new_error < error_threshold)

                # The source implies the new vertex becomes the representative.

            # For simplicity, we assume the new vertex is the new root for this cluster.
            # In a real implementation, we'd manage the tree structure explicitly.
            # Here, we just ensure the new vertex is available for parent pointers.
            # The source says "vertices at the root of the vertex tree". 
            # This implies we process roots of subtrees.

        clustered_vertices = get_clustered_vertices_in_cell(cell)
        all_collapsible = all(v.is_collapsible for v in clustered_vertices)

            cell.is_collapsed = True

## Operating characteristics
*   **Time Complexity:** Depends on the octree traversal and QEF minimization. The bottom-up traversal is linear in the number of cells. QEF minimization is constant time per cluster (solving a small linear system).
*   **Memory Complexity:** Proportional to the number of vertices in the vertex tree.
*   **Strengths:** Reduces polygon count in flat regions by allowing arbitrary vertices per cell. Optimizations (collapsed cells/faces) prune the traversal [S1, unofficial].
*   **Limitations:** May produce non-manifold topology (e.g., threads collapsing to single polygons) if no additional constraints are applied [S1, unofficial]. Requires careful handling of topological connectivity [S1, unofficial].
*   **When to use:** When a simplified, multi-resolution mesh is desired and non-manifold artifacts are acceptable or can be filtered.
*   **When not to use:** When strict manifold topology is required without post-processing.

## Background
Originated in the context of dual contouring simplification, specifically addressing the restriction of one vertex per cell in standard DC [S1, unofficial]. It builds on vertex clustering techniques similar to Zhang et al. [7] but uses a vertex tree for topological connectivity [S1, unofficial]. The method was developed to allow arbitrary numbers of vertices per cell, enabling more aggressive simplification [S1, unofficial].
