# Varying Refinement Levels of Coarse Elements

Also called: Coarse mesh refinement level variation, Inserting refinement levels into coarse mesh

## Overview
This method optimizes hierarchical volume rendering by controlling the granularity of the coarse mesh used for bounding volume hierarchy (BVH) construction and macrocell-based optimizations. It solves the trade-off between BVH traversal efficiency and the overhead of traversing the underlying refinement tree (e.g., TET-AMR) by selecting which level of the refinement hierarchy is promoted to the coarse mesh [S1, unofficial]. Unlike sibling methods that may use fixed coarse structures or different traversal primitives, this approach explicitly varies the refinement level inserted into the coarse mesh to balance macrocell tightness against BVH node count [S1, unofficial].

## How it works
**Inputs:**
*   A hierarchical dataset with a refinement tree (e.g., TET-AMR) where elements exist at multiple refinement levels (0 to $L_{max}$).
*   A target refinement level $k$ for the coarse mesh.
*   A renderer configuration (e.g., Ray Marcher, Woodcock tracking) with optional macrocell optimizations.

**Outputs:**
*   A coarse mesh containing elements from refinement level $k$ (or leaves if they are finer than $k$).
*   A BVH built over this coarse mesh.
*   Rendering performance metrics.

**Data Structures:**
*   **Coarse Mesh:** A collection of geometric primitives (tetrahedra or faces) representing the bounding volumes for BVH nodes. The size of this mesh is determined by the number of elements at level $k$ in the refinement tree.
*   **BVH:** A bounding volume hierarchy built over the coarse mesh elements. The source specifies using 4 faces per element in the BVH construction [S1, unofficial].

**Algorithm:**
1.  **Traverse Refinement Tree:** For each root or relevant parent in the refinement tree, traverse its children.
2.  **Select Element:** Continue traversing down the tree until an element is reached that is either:
    *   At the desired refinement level $k$.
    *   A leaf element (if the leaf is finer than level $k$, it is included; if the tree structure dictates stopping at $k$ regardless of leaf status, the source implies "until an element from the desired refinement level or a leaf element is reached" [S1, unofficial]).
3.  **Add to Coarse Mesh:** Insert the selected element into the coarse mesh structure.
4.  **Build BVH:** Construct the BVH using the elements in the coarse mesh. The source notes the use of 4 faces per element for BVH construction [S1, unofficial].
5.  **Render:** Perform volume rendering using the selected renderer (Ray Marcher or Woodcock) with or without macrocell optimizations.

**Parameters:**
*   **Refinement Level ($k$):** The level of the refinement tree to insert into the coarse mesh. Typical values tested are integers $0$ to $5$ [S1, unofficial].
*   **Macrocell Optimization:** A boolean flag enabling or disabling macrocell-based culling/optimizations [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **BVH Efficiency:** Increasing the number of elements in the coarse mesh (higher $k$) decreases BVH efficiency and reduces the maximum traversal depth in the TET-AMR traversal process [S1, unofficial]. This can negatively impact performance if the BVH overhead outweighs the benefits of reduced refinement tree traversal [S1, unofficial].
*   **Leaf Handling:** The algorithm must correctly handle leaf nodes. If a leaf is at a level finer than $k$, it is still added to the coarse mesh, potentially increasing the coarse mesh size more than expected [S1, unofficial].

**Pseudocode:**
```python
def build_coarse_mesh(refinement_tree, target_level):
    """
    Builds a coarse mesh by traversing the refinement tree and selecting
    elements at the target refinement level or leaf nodes.
    
    Args:
        refinement_tree: The root of the refinement tree structure.
        target_level: The integer refinement level to target.
        
    Returns:
        coarse_mesh: A list of geometric elements (faces/tetrahedra)
                     suitable for BVH construction.
    """
    coarse_mesh = []
    
    # Helper function to traverse the tree
    def traverse(node, current_level):
        # If the node is a leaf, add it to the coarse mesh
        if node.is_leaf():
            coarse_mesh.append(node.element)
            return
        
        # If the current level matches the target level, add this element
        if current_level == target_level:
            coarse_mesh.append(node.element)
            return
        
        # If the current level is finer than target, we should have stopped earlier
        # or this branch is handled by the leaf check above.
        # However, the source says "until an element from the desired refinement 
        # level or a leaf element is reached". This implies we stop at target_level
        # even if children exist, or we stop at leaf if leaf is encountered.
        # If current_level < target_level, we continue to children.
        if current_level < target_level:
            for child in node.children:
                traverse(child, current_level + 1)
        else:
            # current_level > target_level should not happen if we stop at target_level
            # But if we are at a node deeper than target, we treat it as a leaf 
            # for the purpose of coarse mesh insertion? 
            # The source says "until an element from the desired refinement level 
            # or a leaf element is reached". 
            # This implies if we pass target_level without hitting it, we might 
            # hit a leaf. But typically refinement trees are uniform in depth 
            # or structured such that level k is a specific depth.
            # We assume standard traversal where we stop at target_level.
            pass

    # Start traversal from root
    traverse(refinement_tree, 0)
    
    return coarse_mesh

def render_with_coarse_mesh(coarse_mesh, renderer_config):
    """
    Renders the volume using the coarse mesh and specified renderer.
    
    Args:
        coarse_mesh: The list of elements from build_coarse_mesh.
        renderer_config: Configuration including 'use_macrocell' flag.
    """
    # Build BVH from coarse mesh
    # Source specifies 4 faces per element in BVH
    bvh = build_bvh_from_faces(coarse_mesh, faces_per_element=4)
    
    # Perform rendering
    if renderer_config.use_macrocell:
        return ray_marcher_with_macrocells(bvh, coarse_mesh)
    else:
        return ray_marcher_without_macrocells(bvh, coarse_mesh)
```

## Operating characteristics
**Time and Memory Complexity:**
*   The number of elements in the coarse mesh (and thus the BVH) grows exponentially with the refinement level $k$. For the Uniform Engine dataset, the number of elements increases from 6 at level 0 to 196,608 at level 5 [S1, unofficial]. For the Engine dataset, it increases from 5,177 at level 0 to 14,402,140 at level 5 [S1, unofficial].
*   BVH construction and traversal time increase with the number of elements, but the efficiency of the BVH decreases as the number of elements increases [S1, unofficial].

**Measured Performance:**
*   **Engine Dataset:**
    *   Ray Marcher with macrocell: Level 0 (41.47 ms), Level 1 (45.72 ms), Level 2 (50 ms), Level 3 (53.31 ms), Level 4 (62.45 ms), Level 5 (87.77 ms) [S1, unofficial].
    *   Ray Marcher without macrocell: Level 0 (41.12 ms), Level 1 (45.53 ms), Level 2 (50.43 ms), Level 3 (54.69 ms), Level 4 (54.69 ms), Level 5 (84.02 ms) [S1, unofficial].
    *   Woodcock with macrocell: Level 0 (7.14 ms), Level 1 (11.07 ms), Level 2 (18.46 ms), Level 3 (33.18 ms), Level 4 (56.65 ms), Level 5 (94.97 ms) [S1, unofficial].
    *   Woodcock without macrocell: Level 0 (14.70 ms), Level 1 (16.11 ms), Level 2 (16.11 ms), Level 3 (18.52 ms), Level 4 (21.00 ms), Level 5 (21.00 ms) [S1, unofficial].
*   **Uniform Engine Dataset:**
    *   Ray Marcher with macrocell: Level 0 (78.58 ms), Level 1 (75.8 ms), Level 2 (80.7 ms), Level 3 (93.18 ms), Level 4 (101.84 ms), Level 5 (99.81 ms) [S1, unofficial].
    *   Ray Marcher without macrocell: Level 0 (77.61 ms), Level 1 (75 ms), Level 2 (79.69 ms), Level 3 (91.93 ms), Level 4 (101.16 ms), Level 5 (100.96 ms) [S1, unofficial].
    *   Woodcock with macrocell: Level 0 (10.72 ms), Level 1 (9.57 ms), Level 2 (9.56 ms), Level 3 (12.80 ms), Level 4 (22.04 ms), Level 5 (43.80 ms) [S1, unofficial].
    *   Woodcock without macrocell: Level 0 (24.99 ms), Level 1 (26.66 ms), Level 2 (30.91 ms), Level 3 (33.09 ms), Level 4 (32.13 ms), Level 5 (29.30 ms) [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Can improve performance for specific datasets (e.g., Uniform Engine at level 1) by reducing refinement tree traversal depth, even if BVH overhead increases [S1, unofficial]. Macrocell optimizations can significantly improve Woodcock tracker performance at levels 1 and 2 for Uniform Engine due to tighter majorants [S1, unofficial].
*   **Limitations:** Increasing coarse mesh elements generally decreases BVH efficiency and can hurt performance (e.g., Engine dataset) [S1, unofficial]. The optimal level depends heavily on the dataset structure and renderer type [S1, unofficial].

**When to Use:**
*   Use when the refinement tree has a large depth and reducing traversal depth is beneficial (e.g., Uniform Engine at level 1) [S1, unofficial].
*   Use with Woodcock tracking and macrocell optimizations when smaller macrocells can provide tighter majorants (e.g., Uniform Engine at levels 1 and 2) [S1, unofficial].

**When Not to Use:**
*   Avoid for datasets where BVH efficiency is critical and increasing coarse mesh elements leads to significant performance degradation (e.g., Engine dataset) [S1, unofficial].

## Background
This method was proposed in the context of direct volume rendering of tree-based tetrahedral adaptive mesh refinement (TET-AMR) data [S1, unofficial]. The research explores how different levels of the refinement hierarchy can be used to construct a coarse mesh for BVH-based acceleration, balancing the costs of BVH traversal against refinement tree traversal [S1, unofficial]. The work is part of a broader effort to optimize volume rendering for complex, multi-resolution scientific data [S1, unofficial].
