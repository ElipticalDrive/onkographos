# Isomorphic Node Recycling (DAOG)

Also called: Reciclaje de nodos isomorfos

## Overview
Isomorphic Node Recycling is a compression method that converts a Sparse Voxel Octree into a Directed Acyclic Octal Graph (DAOG) by reusing structurally identical (isomorphic) nodes [S1, unofficial]. It differs from bottom-up reduction [Bottom-up SVO to DAG Reduction](898-bottom-up-svo-to-dag-reduction.md) by employing a top-down traversal with a hash table to detect and merge identical subtrees during insertion, rather than sorting and compacting nodes after the tree is fully built.

## How it works
**Inputs:** A voxel $v$, a current node $n$, a bitstream $b$ encoding the path, a depth counter $d$, and a hash table $ht$ mapping node identities to unique instances.
**Outputs:** The resulting node (or reference to an existing isomorphic node) and the updated hash table.

**Data Structures:**
*   **Node:** Contains pointers to 8 children and a 64-bit integer for leaf data.
    ```cpp
    struct Node {
        Node* children[8];
        int64_t leafs;
    };
    ```
*   **Hash Table:** Maps a computed hash value (based on structure and content) to a unique node instance.

**Algorithm Steps:**
1.  **Traversal:** Recursively traverse the octree. The bitstream $b$ is processed in groups of 3 bits to determine the child index (0-7) at each level [S1, unofficial].
2.  **Internal Node Processing ($d > 0$):**
    *   Determine the child index $g$ from the bitstream group at depth $d$.
    *   Retrieve the existing child $c$ from node $n$ at index $g$.
    *   If $c$ exists:
        *   Check if $c$ is already in the hash table.
        *   If yes, replace $c$ with the unique instance found in the hash table.
        *   If no, recursively process $c$ with depth $d+1$ (note: source text specifies $d+1$, though logically depth usually decreases; this is implemented as stated) [S1, unofficial].
    *   If $c$ does not exist:
        *   Create a new empty node $c$.
        *   Recursively process $c$ with depth $d+1$ [S1, unofficial].
    *   Update node $n$'s child at index $g$ to the returned node.
3.  **Leaf Node Processing ($d = 0$):**
    *   Create a new node $n'$ containing the voxel $v$.
    *   Check if $n'$ is in the hash table.
    *   If yes, replace $n'$ with the found instance.
    *   If no, insert $n'$ into the hash table.
    *   Return $n'$ and the updated hash table.

**Hash Function (Structure-Dependent):**
To ensure isomorphic nodes map to the same bucket, a recursive hash function is used [S1, unofficial].
*   **Input:** Node $n$.
*   **Logic:**
    *   If $n$ is not a voxel (internal node):
        *   Initialize hash $h = 0$.
        *   For each child $c$ in $n$'s children:
            *   $h \leftarrow h \oplus \text{recursive\_hash}(c)$
        *   Return $h$.
    *   If $n$ is a voxel:
        *   Return the voxel's information (e.g., color, density) as the hash value.

**Pseudocode:**
```python
def insert_voxel(v, n, b, d, ht):
    """
    Insert voxel v into node n using bitstream b at depth d.
    Reuses isomorphic nodes via hash table ht.
    """
    if d > 0:
        # Get child index from bitstream group (3 bits)
        g = get_bitstream_group(b, d, 3)
        
        # Get existing child or create new
        c = n.children[g]
        if c is not None:
            # Check hash table for existing isomorphic node
            if c in ht:
                c = ht[c]
            else:
                # Recursively process existing child
                # Note: Source specifies d+1, though typically depth decreases
                c, ht = insert_voxel(v, c, b, d + 1, ht)
        else:
            c = Node()
            c, ht = insert_voxel(v, c, b, d + 1, ht)
        
        n.children[g] = c
        return n, ht
    else:
        # Leaf level
        n_prime = Node()
        n_prime.leafs = v.data
        n_prime.children = [None] * 8
        
        if n_prime in ht:
            n_prime = ht[n_prime]
        else:
            ht[n_prime] = n_prime
            
        return n_prime, ht

def recursive_hash(n):
    """
    Compute hash based on node structure and content.
    """
    if not n.is_voxel:
        h = 0
        for c in n.children:
            if c is not None:
                h = h ^ recursive_hash(c)
        return h
    else:
        return n.leafs
```

**Parameters:**
*   **Hash Table:** Stores references to unique node structures. Optimizations include memoization to avoid recursive searches and uniform distribution of nodes in buckets [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Depth Counter:** The source algorithm specifies incrementing depth ($d+1$) during recursion for internal nodes, which is atypical for standard octree traversal where depth usually decrements. This must be implemented exactly as stated in the source [S1, unofficial].
*   **Hash Collisions:** The structure-dependent hash uses XOR. While efficient, it may produce collisions for different structures (e.g., $A \oplus B = B \oplus A$). The source does not specify collision resolution beyond the hash table lookup, implying the hash is used as a primary key for identity [S1, unofficial].

## Subtopics

### Octree Serialization for GPU
A method to convert the sparse Octree/DAOG into a contiguous memory buffer for GPU transmission [S1, unofficial].
*   **Definition:** Reaggregates nodes into a contiguous vector, replacing memory pointers with indices to allow relocation and efficient GPU access.
*   **Steps:**
    1.  Reaggregate nodes into a contiguous vector to eliminate gaps.
    2.  The first entry is always the root node.
    3.  Replace memory pointers with `int32_t` indices into the vector.
    4.  Serialize using a Depth-First traversal [S1, unofficial].
*   **Layout:**
    ```cpp
    struct Node {
        int32_t children[8]; // Indices into the vector
        int64_t leafs;       // Packed leaf data
    };
    ```
*   **When to choose:** When the DAOG needs to be transferred from CPU to GPU or stored in a flat buffer.

### Structure-Dependent Hash Function
A specific hash function implementation for identifying isomorphic nodes [S1, unofficial].
*   **Definition:** Computes a hash value based on the recursive structure of the node's children.
*   **Logic:**
    *   Internal Node: $h = 0$; for each child $c$, $h \leftarrow h \oplus \text{recursive\_hash}(c)$.
    *   Voxel Node: Returns the voxel's info (e.g., `info(n)`).
*   **Optimization:** The source mentions a second optimization involving a linear congruential generator-like step: $k \leftarrow (a \cdot k + b) \pmod p$ applied after the XOR accumulation to distribute nodes uniformly in buckets [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the hash table operations. Insertion and lookup are $O(1)$ on average, but hash computation is recursive, proportional to the subtree size.
*   **Memory Complexity:** Reduces memory usage by sharing identical subtrees. The hash table adds overhead.
*   **Strengths:** Effective for scenes with repetitive structures. Simple to implement with a hash table.
*   **Limitations:** The hash function using XOR may have collisions. The source notes that the hash table reduces algorithm efficiency, requiring optimizations like memoization [S1, unofficial].
*   **When to use:** When memory bandwidth is a bottleneck and the scene has high redundancy.
*   **When not to use:** When the scene has low redundancy, as the hash table overhead may outweigh compression benefits.

## Background
Originated in a thesis by an unspecified author (unofficial source) focusing on compression and efficiency of Sparse Voxel Octrees for global illumination [S1, unofficial]. The method was developed to leverage the implicit position deduction of octrees and the similarity between nodes to compress the structure by reusing isomorphic nodes.
