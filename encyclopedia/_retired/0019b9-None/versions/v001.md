# White Background Compositing
Also called: Alpha Blending over White
## Overview
White Background Compositing is a specific case of alpha compositing used in volume rendering and image synthesis to convert an RGBA image into an RGB image by assuming a solid white background. It solves the problem of displaying semi-transparent renderings on standard displays or when saving to formats that do not support an alpha channel. It differs from [Back-to-Front Compositing](2078-back-to-front-compositing.md) by assuming a fixed, uniform background color (white) rather than accumulating contributions from a complex background scene, and from [Hardware Alpha Blending Compositing](5697-hardware-alpha-blending-compositing.md) by being a software-side mathematical operation rather than a GPU pipeline state.
## How it works
**Inputs and Outputs:**
*   Input: An RGBA image $I_{in}$ with dimensions $W \times H$, where each pixel has components $(R_{in}, G_{in}, B_{in}, \alpha_{in})$.
*   Output: An RGB image $I_{out}$ with dimensions $W \times H$, where each pixel has components $(R_{out}, G_{out}, B_{out})$.

**Data Structures:**
*   The input image is typically stored as a 3D array or tensor of shape $(H, W, 4)$ with floating-point values in the range $[0, 1]$.
*   The output image is a 3D array of shape $(H, W, 3)$ with floating-point values in the range $[0, 1]$.

**Formula:**
The compositing equation assumes the background color $C_{bg}$ is white $(1.0, 1.0, 1.0)$. For each pixel, the output color is calculated as:

$$
C_{out} = C_{in} \cdot \alpha_{in} + (1 - \alpha_{in}) \cdot C_{bg}
$$

Where:
*   $C_{in}$ is the input RGB color vector $(R_{in}, G_{in}, B_{in})$.
*   $\alpha_{in}$ is the input alpha value.
*   $C_{bg}$ is the background color vector $(1.0, 1.0, 1.0)$.
*   $C_{out}$ is the output RGB color vector $(R_{out}, G_{out}, B_{out})$.

Expanding for each channel $c \in \{R, G, B\}$:

$$
C_{out,c} = C_{in,c} \cdot \alpha_{in} + (1 - \alpha_{in})
$$

**Pseudocode:**
The following Python-like pseudocode implements the operation for a batch of images or a single image stored as a NumPy array.

```python
import numpy as np

def white_background_compositing(images_rgba):
    """
    Composites RGBA images over a white background.
    
    Args:
        images_rgba: np.ndarray of shape (..., 4) or (H, W, 4) with values in [0, 1].
        
    Returns:
        np.ndarray of shape (..., 3) or (H, W, 3) with values in [0, 1].
    """
    # Extract RGB and Alpha channels
    # Assuming the last dimension is channels, with 4 channels (RGBA)
    rgb_in = images_rgba[..., :3]
    alpha = images_rgba[..., 3:4]
    
    # Background color is white (1.0, 1.0, 1.0)
    # The formula is: out = rgb_in * alpha + (1 - alpha) * 1.0
    # Since 1.0 is constant, we can simplify:
    rgb_out = rgb_in * alpha + (1.0 - alpha)
    
    return rgb_out
```

**Parameters:**
*   Background Color: Fixed at $(1.0, 1.0, 1.0)$. Not configurable in this specific method.

**Edge Cases and Pitfalls:**
*   **Alpha Range:** The method assumes $\alpha \in [0, 1]$. If $\alpha$ is outside this range, the result may be clamped or exhibit unexpected brightness.
*   **Precision:** When $\alpha$ is very close to 0, the result approaches white. When $\alpha$ is very close to 1, the result approaches the input color. Floating-point precision errors are minimal but should be considered in high-dynamic-range contexts.
*   **Non-Linear Color Spaces:** The formula assumes linear color space. If the input is in sRGB or another non-linear space, it should be linearized before compositing and re-encoded afterward to avoid incorrect blending results.

## Subtopics
## Operating characteristics
**Time and Memory Complexity:**
*   Time Complexity: $O(N)$, where $N$ is the number of pixels. The operation is a simple element-wise arithmetic operation.
*   Memory Complexity: $O(N)$ for the output image. The input can be processed in-place or with a single temporary buffer for the alpha channel.

**Measured Performance:**
*   Performance is extremely high, often limited only by memory bandwidth. On modern CPUs, vectorized instructions (SIMD) can process multiple pixels per cycle. On GPUs, this is a trivial kernel.

**Strengths and Limitations:**
*   **Strengths:** Simple to implement, computationally inexpensive, produces visually correct results for transparent objects against white backgrounds (e.g., medical imaging, 3D models on white slides).
*   **Limitations:** Only suitable for white backgrounds. Not suitable for complex background scenes or non-white backdrops.

**When to Use:**
*   When saving transparent renderings to formats like JPEG or PNG (without alpha).
*   When displaying volume renderings in web browsers or applications that do not support alpha channels.

**When Not to Use:**
*   When the background is not white.
*   When the background is a complex image or video.
*   When the alpha channel does not represent opacity against a white backdrop.

## Background
White Background Compositing is a standard technique in computer graphics and image processing. It is widely used in volume rendering pipelines, particularly in medical imaging and 3D visualization, where transparent structures are rendered over a neutral background. The method is derived from the general Porter-Duff alpha compositing equation [S1, unofficial].
