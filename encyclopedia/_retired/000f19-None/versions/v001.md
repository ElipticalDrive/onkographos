# Topological Sort for Cell Projection

Also called: Back-to-front sort using directed graph, Directed graph sort, Exact Meshed Polyhedra Visibility Ordering, Exact Visibility Ordering for Cell Projection, MPVO (Maximal Polyhedra Visibility Ordering), MPVO algorithm, Visibility Sorting (Topological Sort for Convex Grids)

## Overview
Topological Sort for Cell Projection (MPVO) is an $O(n)$ algorithm for computing a back-to-front visibility ordering of convex polyhedral cells in a convex grid [S1, S2, S3]. It solves the occlusion ordering problem required for correct alpha-blending in object-order volume rendering by constructing a directed graph of pairwise occlusion relations between adjacent cells and performing a topological sort [S1, S3]. Unlike [Projected Tetrahedra](877-projected-tetrahedra.md) which may use simpler centroid sorts, MPVO guarantees a correct visibility order for convex meshes by respecting the transitive occlusion chain along viewing rays [S1, S3]. It fails on non-convex meshes because it ignores occlusion across empty space between non-adjacent cells [S1, S3].

## How it works
**Inputs:** A convex grid of convex polyhedral cells; a viewpoint $V$ (for perspective) or a projection direction vector $\vec{d}$ (for orthogonal).
**Outputs:** A list of cells sorted in back-to-front order.

**Data Structures:**
1.  **Cell Node:** Contains `incount` (integer, number of incoming edges), `visited` (boolean), `cycle_detection` (boolean), and a list of outgoing edges (indices of cells it occludes).
2.  **Directed Graph:** Implicitly defined by adjacency. Nodes are cells. An edge exists from cell $B$ to cell $A$ if $B <_{vp} A$.
3.  **Queue:** A FIFO queue for cells with `incount` == 0.

**Definitions:**
*   Relation $B <_{vp} A$: Cell $B$ must be rendered before cell $A$. This holds if the viewpoint $V$ is on the same side of the shared face $F$ between $A$ and $B$ as cell $A$ is [S1]. This implies $A$ occludes $B$, but $B$ cannot occlude $A$ [S1].
*   Plane Equation: For a face $F$ with normal $\vec{n}$ and point $P$ on the face, the signed distance of a point $X$ is $D(X) = \vec{n} \cdot (X - P)$ [S3].

**Algorithm Steps:**

1.  **Phase I: Construct Partial Ordering (Graph Construction)**
    *   Initialize all cells $C$: $C.incount = 0$, $C.visited = false$, $C.cycle\_detection = false$ [S1, S3].
    *   For each interior face $f$ shared by cells $c_1$ and $c_2$:
        *   Determine the direction of occlusion.
        *   **Perspective View:** Calculate the vector from the viewpoint $V$ to a point on the face. If $V$ and $c_1$ are on the same side of the plane of $f$ (i.e., $D(V)$ and $D(c_1)$ have the same sign relative to the face normal pointing out of $c_1$), then $c_1$ occludes $c_2$. Add a directed edge from $c_2$ to $c_1$ [S1, S3].
        *   **Orthogonal View:** Use the projection direction $\vec{d}$. If $\vec{d} \cdot \vec{n}_{c_1} > 0$ (where $\vec{n}_{c_1}$ points out of $c_1$), $c_1$ is "in front" of $c_2$. Add edge from $c_2$ to $c_1$ [S3].
        *   Increment $c_1.incount$ for each incoming edge [S1].
    *   Identify **sink cells**: Cells with no outgoing arrows across interior faces (i.e., they do not occlude any other cell across a shared face). Add these to a `sink_cell_list` [S3].
    *   Identify **source cells**: Cells with $incount == 0$. Add these to the `queue` [S1].

2.  **Phase II: Topological Sort (DFS-based)**
    *   While `sink_cell_list` is not empty:
        *   Pop a cell $currentCell$ from `sink_cell_list` [S3].
        *   Call `RECURSIVE-DFS(currentCell)` [S3].
    *   **Function `RECURSIVE-DFS(currentCell)`:**
        1.  Set $currentCell.visited = true$ and $currentCell.cycle\_detection = true$ [S3].
        2.  For each eligible neighbor $neighbor$ of $currentCell$ (a cell $c$ such that there is an edge from $c$ to $currentCell$, i.e., $c$ occludes $currentCell$):
            *   If $neighbor.visited$ is false:
                *   Call `RECURSIVE-DFS(neighbor)` [S3].
            *   Else if $neighbor.cycle\_detection$ is true:
                *   **Pitfall:** A visibility cycle is detected. Output warning and exit [S3].
        3.  If no remaining eligible neighbors are unvisited:
            *   Add $currentCell$ to the sorted output list [S3].
            *   Set $currentCell.cycle\_detection = false$ [S3].

**Pseudocode:**

```python
def mpvo_sort(cells, viewpoint, is_orthogonal=False, projection_dir=None):
    # Phase I: Graph Construction
    for cell in cells:
        cell.incount = 0
        cell.visited = False
        cell.cycle_detection = False
        cell.outgoing_edges = [] # List of cells that this cell occludes (edges FROM this cell)
        cell.incoming_edges = [] # List of cells that occlude this cell (edges TO this cell)

    sink_cell_list = []
    
    # Process interior faces
    for face in interior_faces:
        c1, c2 = face.cells # c1 and c2 share this face
        # Determine direction: who occludes whom?
        # Edge goes FROM occluded TO occluder.
        # If c1 occludes c2, edge is c2 -> c1.
        
        occludes, occluded = determine_occlusion(c1, c2, face, viewpoint, is_orthogonal, projection_dir)
        
        # Add edge: occluded -> occludes
        occluded.outgoing_edges.append(occludes)
        occludes.incoming_edges.append(occluded)
        occludes.incount += 1
        
        # Check if c1 or c2 is a sink (no outgoing edges)
        # Note: incount tracks incoming. Outgoing count is len(outgoing_edges).
        # We need to track outgoing count separately or check len()
        if len(occludes.outgoing_edges) == 0:
            sink_cell_list.append(occludes)
        if len(occluded.outgoing_edges) == 0:
            sink_cell_list.append(occluded)

    # Initialize Queue with sources (incount == 0)
    queue = [c for c in cells if c.incount == 0]
    
    # Phase II: Topological Sort using DFS
    sorted_output = []
    
    # We use a stack for iterative DFS to avoid recursion limits, 
    # but the logic follows the recursive definition in [S3].
    # To strictly follow [S3], we process sink cells first.
    
    for start_cell in sink_cell_list:
        if not start_cell.visited:
            dfs_visit(start_cell, sorted_output)

    # Handle any remaining unvisited cells (should be covered by sink list if acyclic, 
    # but queue method in [S1] is an alternative for acyclic graphs)
    # The [S3] DFS method is preferred for cycle detection.
    
    return sorted_output

def determine_occlusion(c1, c2, face, viewpoint, is_orthogonal, projection_dir):
    # Returns (occluder, occluded)
    # Edge direction: occluded -> occluder
    if is_orthogonal:
        # Use projection direction
        # If normal points out of c1, and dot(projection_dir, normal) > 0, c1 is in front
        n = face.normal # Points out of c1
        if dot(projection_dir, n) > 0:
            return c1, c2 # c1 occludes c2
        else:
            return c2, c1
    else:
        # Perspective: Viewpoint V
        # If V and c1 are on the same side of face plane, c1 occludes c2
        # Plane defined by face points and normal n (out of c1)
        # Distance of V: D(V) = dot(n, V - P_face)
        # Distance of c1 center: D(c1) = dot(n, c1.center - P_face)
        # If signs are same, V and c1 are on same side
        n = face.normal
        P = face.center
        d_v = dot(n, viewpoint - P)
        d_c1 = dot(n, c1.center - P)
        
        if (d_v > 0 and d_c1 > 0) or (d_v < 0 and d_c1 < 0):
            return c1, c2 # c1 occludes c2
        else:
            return c2, c1

def dfs_visit(current_cell, sorted_output):
    current_cell.visited = True
    current_cell.cycle_detection = True
    
    # Eligible neighbors are those that occlude current_cell (incoming edges)
    for neighbor in current_cell.incoming_edges:
        if not neighbor.visited:
            dfs_visit(neighbor, sorted_output)
        elif neighbor.cycle_detection:
            raise CycleError("Visibility cycle detected")
            
    # No remaining eligible neighbors
    sorted_output.append(current_cell)
    current_cell.cycle_detection = False
```

**Edge Cases and Pitfalls:**
*   **Visibility Cycles:** If the graph contains a cycle, the topological sort fails. In DFS, this is detected if a neighbor is currently in the recursion stack (`cycle_detection` is true) [S3]. In the Kahn's algorithm variant (queue-based), this is detected if the queue empties before all cells are output [S1]. Cycles imply no global visibility order exists; cells must be subdivided or per-pixel sorting used [S1, S3].
*   **Non-Convex Meshes:** The algorithm assumes convexity. If the mesh is non-convex, viewing rays may exit and re-enter the volume, creating occlusion relations not captured by shared faces [S1, S3]. MPVO fails here [S3].
*   **Non-Planar Faces:** If a face is non-planar (e.g., in curvilinear grids), a ray may leave and re-enter the same cell across the same face, making visibility sorting impossible for that cell [S1].

## Subtopics

### Approximate MPVONC Sort
An approximate, faster sorting algorithm for real-time rendering on non-convex or large datasets [S2, S3]. It starts with an $O(n \log n)$ sort of cells with exterior faces, keyed by the distance of their centroids to the viewpoint [S2, S3]. A depth-first search is then conducted from these sorted exterior cells [S3]. It is used when correct sorts (like MPVO) are too slow for real-time interaction with large datasets [S2].

### A-buffer visibility sort for non-convex grids
An algorithm for general non-convex grids that avoids true global visibility sort complexities by using an A-buffer [S1]. It sorts exterior faces by centroid depth, scan-converts them, and uses the A-buffer to extract extra occlusion relations across ray gaps (empty space between cells) [S1]. These extra relations are processed during the topological sort [S1]. It does not produce a true global visibility sort but ensures image correctness by matching the A-buffer rays to pixel sample rays [S1]. Time complexity is $O(b \log b + wh + a + n)$, where $b$ is exterior faces, $w,h$ image dimensions, $a$ projected area of external faces, and $n$ relations across shared faces [S1].

### Power Distance Sort
A sorting method based on power distance [S3]. It is fast with small constant computations but not guaranteed to produce accurate visibility ordering unless the mesh is a Delaunay triangulation [S3]. Simple schemes like this may fail from certain viewpoints or viewing directions [S3].

### Per-Pixel Sorting (General Variant)
Variants that sort all faces projecting onto a pixel at render time, just prior to compositing [S3]. They handle visibility cycles gracefully since a visibility sort always exists for each pixel center even if no global sort exists [S3]. Methods include scan-line visible surface algorithms with y-buckets, active lists, x-buckets, and z-sorted lists [S3]. They usually spend greater effort on per-pixel sorting since exterior faces are a small fraction of total faces [S3].

## Operating characteristics
*   **Time Complexity:** $O(n)$ for convex grids, where $n$ is the number of cells [S1, S3]. Each cell is treated twice during initialization and once in the loop; each edge is treated once in initialization and once in the loop. Max 6 faces per cell [S1].
*   **Memory Complexity:** Linear space $O(n)$ for data structures (graph nodes, edges, queues/lists) [S3].
*   **Strengths:** Very fast, accurate for convex meshes, low computational overhead, detects visibility cycles [S3].
*   **Limitations:** Fails for non-convex meshes (requires extra gap relations or approximate methods) [S1, S3]. Fails for non-planar faces [S1]. Requires convexity of cells and grid [S1, S3].
*   **When to use:** Convex grids of convex polyhedral cells where exact visibility ordering is required and performance is critical [S1, S3].
*   **When not to use:** Non-convex meshes, non-planar faces, or when real-time interaction with very large non-convex datasets is needed (use Approximate MPVONC or Per-Pixel Sorting) [S2, S3].

## Background
The MPVO algorithm was described by Williams [27] and similarly by Max et al. [15] [S3]. It is based on the observation that for convex meshes, local occlusion relations across shared faces define a partial order that can be topologically sorted to yield a correct global visibility order [S3]. It is a foundational method for cell projection volume rendering [S3].
