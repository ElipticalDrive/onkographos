# Topological Sort for Cell Projection

Also called: MPVO, MPVO algorithm, Meshed Polyhedra Visibility Ordering, Maximal Polyhedra Visibility Ordering, Exact Meshed Polyhedra Visibility Ordering, Exact Visibility Ordering for Cell Projection

## Overview
Topological Sort for Cell Projection (MPVO) is an $O(n)$ algorithm for computing a back-to-front visibility ordering of convex polyhedral cells in a convex grid [S1, S2, unofficial, S3]. It solves the occlusion ordering problem required for correct alpha-blending in object-order volume rendering by constructing a directed graph of pairwise occlusion relations between adjacent cells and performing a topological sort [S1, S3]. Unlike [Tetrahedral Volume Rendering](820-tetrahedral-volume-rendering.md) or [Projected Tetrahedra](877-projected-tetrahedra.md) which may rely on simpler centroid or distance-based heuristics, MPVO guarantees a correct visibility order for convex meshes by respecting the transitive occlusion chain along viewing rays [S1, S3]. It fails on non-convex meshes because it ignores occlusion across empty space between non-adjacent cells [S1, S3].

## How it works
**Inputs:** A convex grid of convex polyhedral cells; a viewpoint $V$ (for perspective) or a projection direction vector $\vec{d}$ (for orthogonal) [S1, S3].
**Outputs:** A list of cells sorted in back-to-front order, where an occluded cell precedes an occluder [S1, S3].

**Data Structures:**
1.  **Cell Node:** Contains `incount` (integer, number of incoming edges), `visited` (boolean), `cycle_detection` (boolean), `outgoing` (list of cell references it occludes), and `incoming` (list of cell references that occlude it) [S1, S3].
2.  **Directed Graph:** Implicitly defined by adjacency, where nodes are cells and edges represent occlusion relations [S1, S3].
3.  **Queue / Sink List:** A FIFO queue for cells with `incount == 0` (Kahn's variant) or a list of sink cells with no outgoing edges (DFS variant) [S1, S3].

**Definitions:**
*   Relation $B <_{vp} A$: Cell $B$ must be rendered before cell $A$ [S1]. This holds if the viewpoint $V$ is on the same side of the shared face $F$ between $A$ and $B$ as cell $A$ is [S1]. This implies $A$ occludes $B$, but $B$ cannot occlude $A$ [S1].
*   Arrow Direction: The direction is calculated using the plane equation for the face and the coordinates of the viewpoint (for perspective views) or a vector along the direction of projection (for orthogonal views) [S4, unofficial].

**Algorithm Steps:**
1.  **Phase I: Construct Partial Ordering (Graph Construction)**
    *   Initialize all cells $C$: set $C.incount = 0$, $C.visited = false$, $C.cycle\_detection = false$ [S1, S3].
    *   For each interior face $f$ shared by cells $c_1$ and $c_2$:
        *   Determine the direction of occlusion using the face plane equation and viewpoint/projection vector [S4, unofficial].
        *   **Perspective View:** If $V$ and $c_1$ are on the same side of the plane of $f$, then $c_1$ occludes $c_2$ [S1, S3].
        *   **Orthogonal View:** If the projection direction $\vec{d}$ aligns with the outward normal of $c_1$ relative to $f$, $c_1$ is in front of $c_2$ [S4, unofficial].
        *   Add a directed edge from the occluded cell to the occluder [S1].
        *   Increment the occluder's `incount` [S1].
    *   Identify **sink cells**: Cells with no outgoing arrows across interior faces [S3]. Add these to a `sink_cell_list` [S3].
    *   Identify **source cells**: Cells with $incount == 0$ [S1]. Add these to the `queue` [S1].

2.  **Phase II: Topological Sort (DFS-based)**
    *   While `sink_cell_list` is not empty:
        *   Pop a cell $currentCell$ from `sink_cell_list` [S3].
        *   Call `RECURSIVE-DFS(currentCell)` [S3].
    *   **Function `RECURSIVE-DFS(currentCell)`:**
        1.  Set $currentCell.visited = true$ and $currentCell.cycle\_detection = true$ [S3].
        2.  For each eligible neighbor $neighbor$ of $currentCell$ (a cell $c$ such that there is an edge from $c$ to $currentCell$):
            *   If $neighbor.visited$ is false:
                *   Call `RECURSIVE-DFS(neighbor)` [S3].
            *   Else if $neighbor.cycle\_detection$ is true:
                *   **Pitfall:** A visibility cycle is detected. Output warning and exit [S3].
        3.  If no remaining eligible neighbors are unvisited:
            *   Add $currentCell$ to the sorted output list [S3].
            *   Set $currentCell.cycle\_detection = false$ [S3].

**Pseudocode:**
```python
def mpvo_sort(cells, interior_faces, viewpoint, is_orthogonal=False, projection_dir=None):
    # Phase I: Initialize and build graph
    for cell in cells:
        cell.incount = 0
        cell.visited = False
        cell.cycle_detection = False
        cell.outgoing = []
        cell.incoming = []
        
    for c1, c2, face in interior_faces:
        # Determine occlusion direction
        if is_orthogonal:
            n = face.normal
            if dot(projection_dir, n) > 0:
                occluder, occluded = c1, c2
            else:
                occluder, occluded = c2, c1
        else:
            # Perspective: V and c1 on same side of face plane -> c1 occludes c2
            n = face.normal
            P = face.center
            d_v = dot(n, viewpoint - P)
            d_c1 = dot(n, c1.center - P)
            if (d_v > 0 and d_c1 > 0) or (d_v < 0 and d_c1 < 0):
                occluder, occluded = c1, c2
            else:
                occluder, occluded = c2, c1
                
        # Add edge: occluded -> occluder
        occluded.outgoing.append(occluder)
        occluder.incoming.append(occluded)
        occluder.incount += 1
        
    # Identify sink cells (no outgoing edges)
    sink_cell_list = [c for c in cells if len(c.outgoing) == 0]
    
    # Phase II: Topological Sort using DFS
    sorted_output = []
    
    for start_cell in sink_cell_list:
        if not start_cell.visited:
            dfs_visit(start_cell, sorted_output)
            
    return sorted_output

def dfs_visit(current_cell, sorted_output):
    current_cell.visited = True
    current_cell.cycle_detection = True
    
    # Eligible neighbors are those that occlude current_cell (incoming edges)
    for neighbor in current_cell.incoming:
        if not neighbor.visited:
            dfs_visit(neighbor, sorted_output)
        elif neighbor.cycle_detection:
            raise ValueError("Visibility cycle detected")
            
    # No remaining eligible neighbors
    sorted_output.append(current_cell)
    current_cell.cycle_detection = False
```

**Edge Cases and Pitfalls:**
*   **Visibility Cycles:** If the graph contains a cycle, the topological sort fails [S3]. In DFS, this is detected if a neighbor is currently in the recursion stack (`cycle_detection` is true) [S3]. In the Kahn's algorithm variant (queue-based), this is detected if the queue empties before all cells are output [S1]. Cycles imply no global visibility order exists; cells must be subdivided or per-pixel sorting used [S1, S3].
*   **Non-Convex Grids:** If the grid is non-convex, viewing rays may leave the volume through an external face, cross empty space, and re-enter another cell [S1]. MPVO only considers shared faces, so it misses these cross-gap occlusions [S1, S3].
*   **Complexity Accounting:** Each cell is treated twice during initialization and once in the loop; each edge is treated once in initialization and once in the loop [S1].

## Subtopics

### [A-buffer visibility sort for non-convex grids](1057-a-buffer-visibility-sort-for-non-convex-grids.md)
An algorithm to sort exterior faces for volume rendering on general non-convex grids using an A-buffer to manage pixel-level intersection lists, avoiding true visibility sort complexities while ensuring correct hardware rendering. It sorts exterior faces by centroid depth, scan-converts them, and uses the A-buffer to extract extra occlusion relations across ray gaps (empty space between cells). These extra relations are processed during the topological sort. Time complexity is $O(n + b^2)$ for pairwise boundary tests, or $O(n + bp)$ when combined with balanced BSP trees.

### [Power Distance Sort](1060-power-distance-sort.md)
A sorting method based on power distance described by Cignoni et al. and Wittenbrim. It is fast with small constant computations but not guaranteed to produce accurate visibility ordering unless the mesh is a Delaunay triangulation. Simple schemes like this may fail from certain viewpoints or viewing directions.

### [Per-Pixel Sorting (General Variant)](1061-per-pixel-sorting-general-variant.md)
Variants that sort all cells projecting onto a pixel at render time, just prior to compositing. They handle visibility cycles gracefully since a visibility sort always exists for each pixel center even if no global sort exists. They usually spend greater effort on per-pixel sorting since exterior faces are a small fraction of total faces.

### XMPVO
An algorithm that augments MPVO by discovering exterior face relations using ray shooting queries at edge intersections and vertices of the projection complex, then performing a topological sort [S4, unofficial]. It handles non-convex meshes by capturing cross-gap occlusions that MPVO misses [S4, unofficial].

### MPVONC
A heuristic extension of MPVO to nonconvex meshes that sorts exterior cells with exterior front-facing faces by decreasing distance of centroid to viewpoint, then conducts DFS from each sorted cell [S4, unofficial]. It is used for fast rendering instead of slower correct sorts because correct sorts do not allow real-time interaction for large data sets [S3].

## Operating characteristics
*   **Time Complexity:** $O(n)$ for convex grids, where $n$ is the number of cells [S1, S3]. Each cell is treated twice during initialization and once in the loop; each edge is treated once in initialization and once in the loop [S1].
*   **Memory Complexity:** Linear space $O(n)$ for data structures (graph nodes, edges, queues/lists) [S3].
*   **Strengths:** Very fast, accurate for convex meshes, low computational overhead, detects visibility cycles [S3].
*   **Limitations:** Fails for non-convex meshes (requires extra gap relations or approximate methods) [S1, S3]. Requires convexity of cells and grid [S1, S3].
*   **When to use:** Convex grids of convex polyhedral cells where exact visibility ordering is required and performance is critical [S1, S3].
*   **When not to use:** Non-convex meshes, non-planar faces, or when real-time interaction with very large non-convex datasets is needed (use Approximate MPVONC or Per-Pixel Sorting) [S2, unofficial, S3].

## Background
The MPVO algorithm was described by Williams [27] and similarly by Max et al. [15] [S3]. It is based on the observation that for convex meshes, local occlusion relations across shared faces define a partial order that can be topologically sorted to yield a correct global visibility order [S3]. It is a foundational method for cell projection volume rendering [S3].
