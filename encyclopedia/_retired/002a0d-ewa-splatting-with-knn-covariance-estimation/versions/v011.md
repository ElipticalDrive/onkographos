# EWA Splatting with kNN Covariance Estimation

Also called: Elliptical Weighted Average splatting

## Overview
A rendering method that uses per-point 3D covariance estimated from k-nearest neighbours to project an elliptical weighted average (EWA) shape onto the 2D image plane for denser coverage than simple disk splatting [S1, unofficial]. It distinguishes itself from standard [EWA Splatting](1069-ewa-splatting.md) by deriving the local surface geometry and anisotropy directly from the point cloud's neighbourhood structure rather than assuming isotropic Gaussians or fixed kernel shapes, allowing it to handle raw, unstructured point clouds without mesh reconstruction [S1, unofficial].

## How it works
**Inputs:**
- Point cloud: positions `xyz` $[N, 3]$, colors `rgb` $[N, 3]$ (normalized to $[0,1]$), labels `label` $[N]$.
- Camera batch: intrinsics `intr` $[M, 4]$ (format: $f_x, f_y, c_x, c_y$), extrinsics `extr` $[M, 4, 4]$ (world-to-camera), viewport width $W$, height $H$.
- Parameters: $k$ (number of neighbours, default 16), `splat_radius` (pixel radius, default 1), `extent` (frustum culling margin, default 1.3).

**Outputs:**
- `color_img`: $[H, W, 3]$ uint8.
- `label_img`: $[H, W]$ uint8.
- `index_map`: $[H, W]$ int32 (stores point index, -1 if empty).

**Data Structures:**
- KDTree built on `xyz` for $O(\log N)$ nearest neighbour queries.
- 3D Covariance Matrix `cov3d` $[N, 3, 3]$.
- 2D Conic Matrix derived from `cov3d` and camera projection.
- Depth canvas for Z-buffer occlusion.

**Steps:**

1.  **Neighbourhood Covariance Estimation:**
    For each point $i$, query the $k$-nearest neighbours using the KDTree. Let $P_i$ be the set of $k$ neighbour positions. Compute the 3D covariance matrix $\Sigma_{3D}^{(i)}$:
    $$ \Sigma_{3D}^{(i)} = \frac{1}{k-1} \sum_{j \in P_i} (\mathbf{p}_j - \bar{\mathbf{p}})(\mathbf{p}_j - \bar{\mathbf{p}})^T $$
    where $\bar{\mathbf{p}}$ is the mean position of the neighbours [S1, unofficial]. This captures the local surface orientation and spread.

2.  **EWA Projection:**
    For each camera view, project the 3D covariance to the 2D image plane. Given camera intrinsics $K$ and extrinsics $R, t$, the 3D point $\mathbf{X}$ is transformed to camera space $\mathbf{X}_c = R\mathbf{X} + t$. The 2D covariance $\Sigma_{2D}$ is computed via the Jacobian $J$ of the projection function:
    $$ \Sigma_{2D} = J \Sigma_{3D} J^T $$
    From $\Sigma_{2D}$, derive the elliptical footprint parameters: center $(u, v)$, radius $r$, and the conic matrix defining the ellipse shape [S1, unofficial]. The radius $r$ is typically scaled by a factor (e.g., 3 standard deviations) to ensure coverage.

3.  **Visibility and Occlusion Filtering:**
    Filter points that are not visible. A point is visible if its projected pixel coordinates $(u, v)$ are within the image bounds $[0, W-1] \times [0, H-1]$ and its depth $z > 0$ [S1, unofficial]. Apply strict Z-buffer occlusion: a point is rendered only if its depth is less than the current depth value at the corresponding pixel location in the depth canvas [S1, unofficial].

4.  **Y-Axis Correction:**
    World camera Y points up, but image v coordinates point down. Flip the Y coordinate:
    $$ v_{img} = H - 1 - \text{round}(v) $$
    [S1, unofficial].

5.  **Splatting and Z-Buffer Update:**
    Sort visible points by depth ascending (front-to-back). For each point $i$ with radius $r_i$:
    - Iterate over pixel offsets $dy \in [-r_i, r_i]$ and $dx \in [-r_i, r_i]$.
    - Calculate pixel coordinates $(x, y)$.
    - If $(x, y)$ is within bounds and the point's depth $z_i$ is less than the existing `depth_canvas[x, y]`:
        - Update `color_img[x, y]` with the point's color.
        - Update `label_img[x, y]` with the point's label.
        - Update `index_map[x, y]` with the point's index.
        - Update `depth_canvas[x, y]` with $z_i$.
    [S1, unofficial].

**Pitfalls:**
- **Y-Axis Orientation:** Failure to flip the Y-axis results in vertically flipped images [S1, unofficial].
- **Empty Visible Set:** If no points are visible (e.g., camera outside frustum), return zero-filled canvases with `index_map` filled with -1 [S1, unofficial].
- **Precision:** Use float32 for covariance and projection calculations to avoid numerical instability in small ellipses [G].
- **Boundary Conditions:** Clamp the integer radius $r_{int}$ between 0 and 32 to prevent excessive memory access or empty splats [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \log N)$ for KDTree construction and neighbour queries; $O(M \cdot N)$ for projection and occlusion; $O(N \cdot r^2)$ for splatting, where $r$ is the average radius.
- **Memory Complexity:** $O(N \cdot k)$ for storing neighbour indices and covariance matrices; $O(H \cdot W)$ for output canvases.
- **Performance:** Efficient for large point clouds due to batched GPU operations and early Z-buffer culling. Performance scales linearly with the number of points and cameras.
- **Strengths:** Handles raw point clouds without meshing; adaptive kernel shapes improve rendering quality at edges and sparse regions; differentiable variants enable optimization.
- **Limitations:** Sensitive to noise in point cloud positions; requires careful tuning of $k$ and radius; occlusion handling is approximate compared to ray tracing.

## Background
Originated from the CamPoint project and popularized in the context of point-based rendering pipelines for multi-view synthesis [S1, unofficial]. It builds on the foundational EWA splatting technique by incorporating local geometric information from the point cloud itself, enabling robust rendering of unstructured data.
