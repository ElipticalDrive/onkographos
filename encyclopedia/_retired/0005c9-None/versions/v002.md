# Fast Convex Polygon Wrapper (FCPW) Accelerator

Also called: Mesh Query Handler

## Overview
The Fast Convex Polygon Wrapper (FCPW) Accelerator is a geometric query structure designed to efficiently compute ray-tetrahedron edge intersections and closest-point projections on polygonal meshes. It solves the problem of robustly determining intersection parameters and surface normals for tetrahedral cells defined by polygonal boundaries, serving as the core geometric engine for the [MeshQueryHandler](1664-fast-convex-polygon-wrapper-fcpw-accelerator.md). It sets itself apart from sibling methods by wrapping convex polygonal geometry into an accelerated structure that supports both single-edge intersection finding and closest-point queries, enabling efficient rasterization of ambient occlusion volumes via the [Convex Polygon Falloff Function](10023-convex-polygon-falloff-function.md).

## How it works
The FCPW accelerator is constructed from a set of polygons and their vertex positions. It provides two primary query operations: finding the single intersection of a ray with tetrahedron edges, and finding the closest point on the mesh surface to a query point.

**Inputs and Outputs:**
- **Construction Input:** `polygons` (list of vertex indices defining faces), `positions` (3D coordinates of vertices).
- **Intersection Query Input:** `tet_positions` (vertices of the tetrahedron), `accel` (the FCPW structure), `useRobust` (boolean flag for robust computation), `recordNormals` (boolean flag).
- **Intersection Query Output:** Arrays for intersection times (`t`) and normals (`n`), and a boolean flag indicating if an intersection was found.
- **Closest Point Query Input:** `q` (query point in 3D space), `accel` (the FCPW structure).
- **Closest Point Query Output:** `closest_point` (3D coordinate), `normal` (surface normal at closest point).

**Data Structures:**
The internal layout of the `accel` structure is not explicitly detailed in the sources, but it is implied to store polygonal topology and spatial indexing to facilitate fast queries [S1, unofficial].

**Steps:**

1. **Acceleration Structure Construction:**
   Initialize the accelerator using the polygon soup.
   $$ \text{accel} = \text{get\_fcpw\_accel}(\text{polygons}, \text{positions}) $$
   This step organizes the geometric data for efficient retrieval [S1, unofficial].

2. **Ray-Tetrahedron Edge Intersection:**
   To find intersections between a ray and the edges of a tetrahedron defined by `tet_positions`:
   $$ (\text{found}, t, n) = \text{find\_single\_tet\_edge\_intersections\_fcpw}(\text{tet\_positions}, \text{accel}, \text{useRobust}, \text{recordNormals}) $$
   The function returns whether an intersection exists, the intersection parameter $t$, and optionally the normal vector $n$ [S1, unofficial].

3. **Closest Point Projection:**
   To find the closest point on the mesh to a query point $q$:
   $$ (\text{closest\_point}, \text{normal}) = \text{closest\_point\_fcpw}(q, \text{accel}) $$
   This computes the projection of $q$ onto the mesh surface and the associated surface normal [S1, unofficial].

**Pseudocode:**

```python
# Construction
accel = get_fcpw_accel(polygons, positions)

# Intersection Query
# ray_origin and ray_direction are assumed to be defined in the calling context
# tet_positions is a list of 4 vertices defining the tetrahedron
use_robust = True
record_normals = True
found, t, normal = find_single_tet_edge_intersections_fcpw(tet_positions, accel, use_robust, record_normals)

if found:
    # Process intersection at t with normal
    pass

# Closest Point Query
q = Vector3(0.0, 0.0, 0.0) # Example query point
closest_point, normal = closest_point_fcpw(q, accel)
```

**Edge Cases and Pitfalls:**
- The `useRobust` flag suggests that numerical stability is a concern, particularly for degenerate tetrahedra or nearly parallel rays [S1, unofficial].
- Boundary conditions for rays originating inside or outside the mesh are handled by the intersection logic, but specific behavior for grazing intersections is not detailed [S1, unofficial].

## Subtopics

### [Convex Polygon Falloff Function](10023-convex-polygon-falloff-function.md)
Computes a scalar occlusion weight based on distance from a convex polygon. It uses the FCPW accelerator to efficiently rasterize ambient occlusion volumes by leveraging the closest-point and intersection capabilities of the wrapper. Choose this when smooth, monotonic falloff for arbitrary convex polygons is required.

## Operating characteristics
The performance characteristics of the FCPW accelerator are not explicitly quantified in the sources. However, its use in a "subgrid pipeline" suggests it is optimized for high-frequency queries within a larger volume rendering or mesh processing context [S1, unofficial]. The availability of a `useRobust` flag indicates a trade-off between speed and numerical stability, where robust mode may incur higher computational cost [S1, unofficial].

## Background
The FCPW Accelerator is part of the `subgrid-marching` project, developed by H. Baktash. It is implemented as part of the `MeshQueryHandler` class, which serves as an alternative to CGAL-based query handlers for geometric operations on polygonal meshes [S1, unofficial]. The method is used in the context of generating subgrid meshes and computing geometric properties for visualization and further processing.
