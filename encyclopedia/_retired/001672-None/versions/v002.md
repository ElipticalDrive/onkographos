# Tetrahedral Splatting

Also called: TetSplat

## Overview
Tetrahedral Splatting is a point-based technique for the real-time rendering of large, unstructured tetrahedral meshes by approximating each tetrahedron with a spherical or ellipsoidal splat [S1, unofficial]. It distinguishes itself from sibling methods like [Voxel Splat Rendering](3730-voxel-splat-rendering.md) by operating directly on explicit geometric primitives rather than sampled grids, and from [Triangle Mesh Splatting](8109-triangle-mesh-splatting.md) by using volume-approximating kernels instead of surface projections. The method relies on hierarchical culling for performance but requires static meshes and pre-processing to handle degenerate geometry [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A static, unstructured tetrahedral mesh $T = \{t_1, \dots, t_N\}$, where each tetrahedron $t_i$ is defined by four vertices. A camera configuration (Model-View-Projection matrix).
*   **Output:** A 2D image with accumulated color and opacity.

**Data Structures:**
*   **Tetrahedron Representation:** Each tetrahedron is mapped to a single splat primitive. The primitive is defined by a center point $c_i$ and a shape parameter (radius $r$ for spheres, or a covariance matrix $\Sigma_i$ for ellipsoids) [S1, unofficial].
*   **Hierarchical Structure:** A spatial hierarchy (e.g., BVH or octree) is built over the splat centers to enable efficient back-face and occlusion culling [S1, unofficial].

**Steps:**
1.  **Pre-processing (Partitioning and Cleaning):**
    *   Eliminate degenerated tetrahedra (needles, spindles, slivers, caps) using edge collapse [S1, unofficial].
    *   Partition the volume into a **Shell** (boundary) and **Solid** (interior) components [S1, unofficial].
    *   *Note:* This step assumes a static mesh and is performed once before rendering [S1, unofficial].

2.  **Splat Parameterization:**
    *   For each tetrahedron $t_i$, compute the center $c_i$ (e.g., centroid of vertices).
    *   Determine the splat shape:
        *   **Spherical:** Radius $r_i$ is derived from the tetrahedron's volume or bounding sphere.
        *   **Ellipsoidal:** Covariance matrix $\Sigma_i$ is derived from the tetrahedron's geometry to better fit elongated shapes [S1, unofficial].
    *   *Pitfall:* Using a single splat per tetrahedron often results in visible gaps, even with ellipsoidal adaptation [S1, unofficial].

3.  **Screen-Space Projection:**
    *   Transform the splat center $c_i$ from volume space to screen space using the MVP matrix [S1, unofficial].
    *   Project the splat footprint onto the screen. For ellipsoids, this involves transforming the covariance matrix $\Sigma_i$ by the view and projection matrices [S1, unofficial].

4.  **Culling:**
    *   Use the hierarchical structure to cull splats that are outside the view frustum, back-facing, or occluded by closer geometry [S1, unofficial].

5.  **Rasterization and Blending:**
    *   Rasterize the projected splats as triangles or points.
    *   In the fragment shader, evaluate the kernel intensity $h(d)$ based on the distance $d$ from the fragment to the splat center (or axis for ellipsoids) [S1, unofficial].
    *   Accumulate contributions using alpha blending [S1, unofficial].

**Pseudocode:**
```python
def render_tetrahedral_splat(tetrahedra, camera):
    # Pre-processing: Clean and partition (assumed static, done once)
    clean_tetrahedra = remove_degenerate_tetrahedra(tetrahedra)
    shell, solid = partition_volume(clean_tetrahedra)
    
    # Build hierarchy for culling
    hierarchy = build_bvh(shell + solid)
    
    # Render
    for primitive in hierarchy.cull(camera):
        # Project center
        center_screen = camera.mvp * primitive.center
        
        # Determine footprint
        if primitive.shape == 'sphere':
            radius = primitive.radius
            footprint = circle(center_screen, radius)
        else: # ellipsoid
            cov_matrix = transform_covariance(primitive.cov, camera)
            footprint = ellipse(center_screen, cov_matrix)
            
        # Rasterize and blend
        rasterize(footprint, primitive.color, primitive.opacity)
```

## Operating characteristics
*   **Time Complexity:** Dominated by the rasterization of splats and hierarchical culling. Culling reduces the number of splats processed per frame [S1, unofficial].
*   **Memory Complexity:** Linear in the number of tetrahedra, plus overhead for the hierarchical structure [S1, unofficial].
*   **Performance:** Enables real-time rendering of large meshes due to efficient culling [S1, unofficial].
*   **Strengths:** Handles unstructured meshes directly; real-time capability; hierarchical culling [S1, unofficial].
*   **Limitations:** Requires static meshes; pre-processing eliminates topology (incompatible with dynamic smoke); single-splat-per-tetrahedron causes visible gaps; degenerate tetrahedra must be removed [S1, unofficial].
*   **When to use:** Static unstructured volume visualization where real-time performance is critical and topological fidelity of degenerate elements is not required [S1, unofficial].
*   **When not to use:** Dynamic volumes (e.g., smoke integration) where topology must be maintained or degenerate elements are common [S1, unofficial].

## Background
Tetrahedral Splatting (TetSplat) was introduced as a point-based technique for real-time rendering of large tetrahedral meshes [S1, unofficial]. It addresses the limitations of voxel-based methods by operating on explicit geometry, using hierarchical data structures for culling [S1, unofficial]. The method is described in the context of real-time smoke volume rendering, highlighting its suitability for static scenes [S1, unofficial].
