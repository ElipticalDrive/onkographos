# Tetrahedral Splatting

Also called: TetSplat

## Overview
Tetrahedral Splatting is a point-based technique for the real-time rendering of large, unstructured tetrahedral meshes [S1, unofficial]. It approximates each tetrahedron with a single spherical or ellipsoidal splat and leverages hierarchical data structures for efficient back-face and occlusion culling [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A static tetrahedral mesh defining the volume [S1, unofficial].
*   **Output:** A rendered 2D image of the volume [S1, unofficial].

**Data Structures:**
*   **Tetrahedron Representation:** Each tetrahedron $T_i$ is represented by a single splat primitive [S1, unofficial].
*   **Splat Geometry:** The splat is defined as a sphere or an ellipsoid [S1, unofficial]. The position is typically the centroid or a representative point of the tetrahedron [G].
*   **Hierarchical Structure:** A hierarchical data structure (e.g., a bounding volume hierarchy) is built over the splats to enable efficient culling of back faces and occluded primitives [S1, unofficial].

**Preprocessing (Static Mesh Only):**
1.  **Degeneracy Removal:** The mesh is analyzed to identify degenerated tetrahedra (needles, spindles, slivers, and caps) [S1, unofficial].
2.  **Edge Collapse:** Degenerated tetrahedra are removed from the dataset using edge collapse operations [S1, unofficial]. This step is necessary because degenerated shapes are difficult to represent accurately with standard splat kernels [S1, unofficial].
3.  **Splat Generation:** For each remaining tetrahedron, a corresponding spherical or ellipsoidal splat is generated [S1, unofficial].
4.  **Hierarchy Construction:** A hierarchical culling structure is built over the generated splats [S1, unofficial].

**Rendering Steps:**
1.  **Culling:** Using the hierarchical structure, splats that are back-facing or occluded by closer geometry are culled [S1, unofficial].
2.  **Transformation:** The remaining splats are transformed from object space to screen space using the Model-View-Projection (MVP) matrix [G].
3.  **Rasterization:** The transformed splats are rasterized onto the screen, contributing to pixels within their footprint [G].
4.  **Compositing:** The contributions from all visible splats are accumulated to form the final image [G].

**Parameters:**
*   **Splat Shape:** Spherical or Ellipsoidal. Ellipsoids may be adapted to better fit the aspect ratio of the tetrahedron, but this increases computational complexity [S1, unofficial].
*   **Mesh Type:** Static. The method assumes the mesh does not change during rendering [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Degenerate Tetrahedra:** The removal of degenerate tetrahedra is incompatible with applications requiring strict topological preservation, such as smoke volume rendering, where tetrahedra may naturally become near-degenerate during integration [S1, unofficial].
*   **Visible Gaps:** Representing a tetrahedron with a single splat can lead to visible gaps between splats, especially in small meshes, even when using ellipsoidal shapes [S1, unofficial].
*   **Dynamic Meshes:** The preprocessing step assumes a static mesh; dynamic objects are not supported in the current implementation [S1, unofficial].

Partitions the mesh into a Shell (boundary) and Solid (interior) to handle shading discontinuities. It distinguishes itself from sibling methods by explicitly separating boundary rendering from interior volume rendering logic to resolve shading discontinuities at the CSG probe interface. Choose it when rendering unstructured tetrahedral meshes with distinct boundary and interior shading requirements.

## Operating characteristics
*   **Time Complexity:** Rendering time is dominated by the rasterization of splats and hierarchical culling [S1, unofficial].
*   **Memory Complexity:** Linear in the number of tetrahedra, plus overhead for the hierarchical structure [G].
*   **Performance:** Enables real-time rendering of large tetrahedral meshes [S1, unofficial].
*   **Strengths:** Efficient culling via hierarchical structures [S1, unofficial].
*   **Limitations:** Requires static meshes; preprocessing removes topological details (degenerate tetrahedra); single-splat-per-tetrahedron representation can cause visible artifacts (gaps) [S1, unofficial].
*   **When to Use:** Real-time visualization of static unstructured tetrahedral volumes where topological fidelity of degenerate elements is not critical [S1, unofficial].
*   **When Not to Use:** Dynamic meshes; smoke volume rendering requiring topological preservation; scenes where high-fidelity representation of individual tetrahedra is required without interpolation artifacts [S1, unofficial].

## Background
Tetrahedral Splatting (TetSplat) was introduced as a point-based technique for the real-time rendering of large tetrahedral meshes [S1, unofficial]. It utilizes spherical or ellipsoidal splat representations and hierarchical data structures for efficient culling [S1, unofficial]. The method was presented in the context of smoke volume rendering, though its preprocessing requirements limit its applicability to dynamic or topologically sensitive volumes [S1, unofficial].
