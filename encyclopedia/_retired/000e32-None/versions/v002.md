# Adaptive Subdivision in DiffTetVR

Also called: Adaptive Mesh Refinement, Adaptive tetrahedral subdivision, Gradient-based mesh refinement, Prism Splitting, Tetrahedral Subdivision

## Overview
Adaptive Subdivision in DiffTetVR is a training strategy that refines a tetrahedral mesh by subdividing vertices with high color gradients to increase resolution where needed, aiming to solve the issue of wasted resolution in empty regions [S1, unofficial]. It distinguishes itself from uniform refinement by using accumulated absolute color gradients to select specific vertices for local subdivision, and from static mesh generation by integrating refinement directly into the differentiable optimization loop [S1, unofficial].

## How it works
**Inputs:**
*   Initial tetrahedral mesh (generated via regular grid conversion or Delaunay triangulation of SfM points) [S1, unofficial].
*   Camera poses and target images for training [S1, unofficial].
*   Target number of tetrahedra or subdivision iterations [S1, unofficial].

**Outputs:**
*   Refined tetrahedral mesh with updated vertex positions and colors [S1, unofficial].

**Data Structures:**
*   **Mesh:** Stores vertices and tetrahedra. Connectivity is managed via adjacency lists. The implementation uses `OpenVolumeMesh` for data structure management [S1, unofficial].
*   **Gradient Accumulator:** An array storing the accumulated absolute color gradient magnitude for each vertex [S1, unofficial].
*   **CSP Solver:** A solver (implemented in `FlipSolver.cpp`) to resolve splitting constraints for adjacent prisms [S1, unofficial].

**Parameters:**
*   $N̂$: The number of vertices with the largest gradient magnitudes selected for subdivision. In the reference implementation, this is set to 5% of the total vertices [S1, unofficial].
*   Learning rates: Vertex color learning rate ($lr_c$) and vertex position learning rate ($lr_p$). Position optimization is found to be unstable; stable results with position optimization require $lr_p \in \{1e-6, 5e-6\}$, but yield lower PSNR than color-only optimization [S1, unofficial].
*   Regularization strength ($\lambda$) and softplus parameter ($\beta$): Used in vertex position optimization. Typical values cited are $\lambda=10, \beta=100$ [S1, unofficial].

**Steps:**
1.  **Initialization:** Generate an initial coarse tetrahedral mesh. This can be done by:
    *   Creating a regular grid aligned with the scene bounding box and converting hexahedral cells to tetrahedra (using libraries like fTetWild or TetGen) [S1, unofficial].
    *   Performing Delaunay triangulation on a sparse point cloud from Structure-from-Motion (SfM) algorithms like COLMAP [S1, unofficial].
2.  **Training Loop (Epochs):**
    *   **Epoch Type A (Color Opt):** Optimize only vertex colors for 800 renderings (1 epoch definition) [S1, unofficial].
    *   **Epoch Type B (Joint Opt):** Jointly optimize vertex colors and positions for 800 renderings [S1, unofficial].
    *   **Epoch Type C (Gradient Accum):** Accumulate absolute color gradients at every vertex without performing optimization steps for 800 renderings [S1, unofficial].
    *   **Refinement Step:**
        1.  Identify the $N̂$ vertices with the highest absolute color gradients [S1, unofficial].
        2.  For each selected vertex, split all incident edges by inserting a new vertex at the midpoint [S1, unofficial].
        3.  Split the incident tetrahedra using the newly inserted vertices. This operation creates:
            *   One new tetrahedron incident with the splitting vertex.
            *   A truncated pyramid in the form of a triangular prism formed by the original non-splitting vertices and the new midpoints on the incident edges [S1, unofficial].
        4.  Split each triangular prism into exactly three tetrahedra. The split direction of the quad faces of the prism is determined by a Constraint Satisfaction Problem (CSP) to ensure compatibility with adjacent prisms [S1, unofficial].
            *   **CSP Constraints:**
                1.  The splits for one prism may not be FFF or RRR [S1, unofficial].
                2.  Two adjacent prisms must split a shared quad face using exactly one F and one R split [S1, unofficial].
            *   **Split Direction:** Edges are categorized as 'Rising' (R) or 'Falling' (F) based on the direction of the tessellation edge relative to the extruded prism face in a counter-clockwise manner [S1, unofficial].
        5.  Repeat the process until a target amount of tetrahedra is reached [S1, unofficial].
    *   **Final Step:** In the final iteration, optimize only vertex colors to produce the final result [S1, unofficial].

**Pseudocode:**

```python
def adaptive_subdivision_diff_tetvr(mesh, images, cameras, target_tet_count, n_percent=0.05):
    """
    Performs adaptive subdivision on a tetrahedral mesh using DiffTetVR strategy.
    
    Args:
        mesh: Initial tetrahedral mesh object.
        images: List of target images.
        cameras: List of camera poses.
        target_tet_count: Target number of tetrahedra to reach.
        n_percent: Percentage of vertices to subdivide (default 5%).
        
    Returns:
        Refined mesh.
    """
    # Initialize gradient accumulator
    vertex_gradients = zeros(mesh.num_vertices)
    
    # Define epoch size
    epoch_size = 800
    
    # Training loop
    while mesh.num_tetrahedra < target_tet_count:
        
        # Epoch 1: Optimize only vertex colors
        optimize_colors(mesh, images[:epoch_size], cameras[:epoch_size])
        
        # Epoch 2: Jointly optimize vertex colors and positions
        # Note: Position optimization is unstable; use low learning rates (1e-6 to 5e-6)
        optimize_colors_and_positions(mesh, images[:epoch_size], cameras[:epoch_size], 
                                    lr_color=1e-3, lr_position=1e-6, 
                                    lambda_reg=10, beta=100)
        
        # Epoch 3: Accumulate absolute color gradients without optimization
        reset_gradients(vertex_gradients)
        for i in range(epoch_size):
            render = render_tet_mesh(mesh, cameras[i])
            loss = mse_loss(render, images[i])
            gradients = compute_gradient(loss, mesh)
            vertex_gradients += abs(gradients)
            
        # Refinement Step
        # Select top N vertices with highest gradients
        n_select = int(n_percent * mesh.num_vertices)
        top_vertices = argsort(vertex_gradients, descending=True)[:n_select]
        
        # Subdivide incident tetrahedra for selected vertices
        for v in top_vertices:
            split_vertex_at_midpoint(mesh, v)
            
        # Resolve CSP for all prisms created by subdivision
        # The CSP ensures compatible splits on shared quad faces
        resolve_prism_splits_csp(mesh)
        
        # Update mesh data structures
        mesh.update_connectivity()
        
    # Final optimization of vertex colors only
    optimize_colors(mesh, images, cameras)
    
    return mesh

def split_vertex_at_midpoint(mesh, vertex_index):
    """
    Splits all incident edges of a vertex by inserting a new vertex at the midpoint.
    Then splits the incident tetrahedra.
    """
    incident_tets = mesh.get_incident_tetrahedra(vertex_index)
    incident_edges = mesh.get_incident_edges(vertex_index)
    
    new_vertices = []
    for edge in incident_edges:
        # Insert new vertex at midpoint
        mid_vertex = mesh.insert_vertex_at_midpoint(edge)
        new_vertices.append(mid_vertex)
        
    # Split incident tetrahedra
    # Each incident tetrahedron creates one new tetrahedron incident to the splitting vertex
    # and a triangular prism from the other vertices
    for tet in incident_tets:
        # Identify the splitting vertex 'a' and other vertices 'b', 'c', 'd'
        # Create new midpoints on edges ab, ac, ad
        # Form the new tetrahedron {a, mid_ab, mid_ac, mid_ad}
        # Form the prism {b, c, d, mid_ab, mid_ac, mid_ad}
        # The prism is split into 3 tetrahedra via CSP
        split_tetrahedron(mesh, tet, vertex_index, new_vertices)

def resolve_prism_splits_csp(mesh):
    """
    Solves the Constraint Satisfaction Problem for all prisms in the mesh.
    Constraints:
    1. One prism may not be FFF or RRR.
    2. Adjacent prisms sharing a quad face must use one F and one R split.
```

**Edge Cases and Pitfalls:**
*   **Vertex Position Instability:** Optimization of vertex positions is unstable, especially as the mesh becomes more subdivided and tetrahedra get smaller, increasing the chance of inversion [S1, unofficial].
*   **Recursive Subdivision:** Subdivision does not sufficiently lower local error, causing recursive subdivision of the same regions. This eventually halts optimization progress as CSP solving and data structure updates dominate computation time [S1, unofficial].
*   **Incompatible Splits:** Incompatible splits on shared quad faces lead to infinitesimally thin holes in the tet mesh. This occurs if adjacent prisms choose the same split direction (e.g., both R or both F) on a shared face [S1, unofficial].
*   **Performance:** After too many optimization epochs, solving the CSPs and updating the OpenVolumeMesh data structure dominates computation time [S1, unofficial].

## Subtopics

### [Differentiable Mesh Refinement](984-differentiable-mesh-refinement.md)
Differentiable Mesh Refinement is a post-processing optimization step that improves the geometric fidelity of a triangular mesh by adjusting vertex positions to better fit an underlying implicit occupancy field. It distinguishes itself from topological refinement methods (such as [Recursive Subdivision](1304-recursive-subdivision.md)) by operating directly on the existing mesh topology, using face subsampling to maintain computational efficiency during the optimization loop. This method builds on [Adaptive Subdivision in DiffTetVR](807-adaptive-subdivision-in-difftetvr.md) by providing a final polishing step that decouples geometry adjustment from topological changes.

### [Recursive Subdivision](1304-recursive-subdivision.md)
Recursive Subdivision is a deterministic tetrahedral mesh generation and refinement technique for regular volume data. It recursively bisects tetrahedra by adding edge midpoints, following a fixed sequence of geometric cases (Step 1, Step 2, Step 3) to produce a hierarchical framework. Unlike octree decompositions that require complex stitching to handle resolution boundaries, this method guarantees conforming faces and well-shaped tetrahedra without element quality degradation during subdivision.

## Operating characteristics
*   **Time Complexity:** The refinement step involves gradient accumulation, vertex selection, edge splitting, tetrahedron splitting, and CSP solving. As the mesh subdivides, the cost of CSP solving and data structure updates dominates computation time [S1, unofficial].
*   **Memory Complexity:** Depends on the number of tetrahedra and vertices. The use of `OpenVolumeMesh` implies overhead for adjacency management [S1, unofficial].
*   **Measured Performance:** Color-only optimization achieves a peak PSNR of 33.5 on the Tooth dataset. Vertex position optimization with fixed $\beta=100$ and $\lambda=10$ is only stable at learning rates $1e-6$ and $5e-6$, achieving a significantly lower PSNR of approx. 26.9 [S1, unofficial].
*   **Strengths:** Reduces wasted resolution in empty regions by focusing refinement on high-gradient areas [S1, unofficial]. Uses absolute gradients, which was found to result in better outcomes compared to other gradient metrics [S1, unofficial].
*   **Limitations:** Vertex position optimization is unstable and prone to inversion [S1, unofficial]. Subdivision may not sufficiently lower local error, leading to redundant subdivisions and halted optimization progress [S1, unofficial]. Does not model directional lighting or volume scattering [S1, unofficial].
*   **When to Use:** When the scene has sparse high-frequency details and uniform resolution is inefficient.
*   **When Not to Use:** When vertex position stability is critical, or when lighting/scattering effects are important.

## Background
DiffTetVR was introduced by Chris Mile et al. in the paper "DiffTetVR: Differentiable Tetrahedral Volume Rendering" (arXiv:2601.00114, 2026) [S1, unofficial]. The method builds on the principles of differentiable volume rendering and tetrahedral mesh representation. The adaptive subdivision strategy was proposed to address the issue of wasted resolution in empty regions, which is a common problem in uniform tetrahedral volume rendering. The prism splitting algorithm is based on the work of Erleben et al. [44], and the initial mesh generation can utilize libraries like fTetWild, TetGen, or COLMAP [S1, unofficial].
