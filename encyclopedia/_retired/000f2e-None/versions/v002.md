# Hierarchical Splatting

Also called: Progressive refinement splatting, Pyramidal volume splatting

## Overview
Hierarchical splatting is a progressive refinement algorithm for volume rendering that uses a pyramidal volume representation to achieve real-time interactive rendering [S1, unofficial]. It solves the problem of rendering large datasets efficiently by allowing the user to start with a low-resolution approximation and progressively refine the image as needed [S2, unofficial]. It sets itself apart from standard splatting by using a multi-resolution pyramid structure to adapt the rendering resolution to the desired image quality, and from [Multi-Resolution Points](4784-multi-resolution-points.md) by explicitly constructing a hierarchical pyramid of averaged volume cells rather than just selecting points based on density or distance [S2, unofficial].

## How it works
**Inputs:** A 3D volume dataset of size $N^3$ samples, a viewing direction, and a user-supplied precision threshold (or desired image quality level) [S1, S2, unofficial].
**Outputs:** A rendered 2D image [S1, S2, unofficial].

**Data Structures:**
1. **Pyramid Data Structure:** A sequence of $\log_2(N)$ volumes for an original dataset of $N^3$ samples [S2, unofficial]. Level 0 is the original dataset [S2, unofficial]. Level $k$ is a volume of size $(N/2^k)^3$ created by averaging each $2 \times 2 \times 2$ group of samples from level $k-1$ [S2, unofficial]. Each cell in the pyramid stores the average value of the underlying samples and an estimated error [S1, unofficial].
2. **Octtree:** Constructed by fitting an octtree to the pyramid based on the user-supplied precision threshold [S1, unofficial].

**Algorithm Steps:**
1. **Build Pyramid:** Construct the pyramidal volume representation. For an original dataset of $N^3$ samples, create $\log_2(N)$ volumes. Level 0 is the original data. For each subsequent level $k$, compute the value of each cell by averaging the $2 \times 2 \times 2$ group of samples from level $k-1$ that it represents [S2, unofficial].
2. **Fit Octtree:** Fit an octtree to the pyramid using the user-supplied precision threshold [S1, unofficial].
3. **Determine Resolution Level:** Select the appropriate level of the pyramid to scan based on the desired image quality [S2, unofficial].
4. **Back-to-Front Scan:** Scan the selected level(s) of the pyramid in back-to-front order relative to the viewing direction [S2, unofficial].
5. **Splatting:** For each element (cell) in the scanned level: project the volume cell onto the image plane, determine the size of the splat footprint to match the projection of the corresponding volume cell, approximate the splat with an RGBA Gouraud-shaded polygon, and render the polygon using conventional graphics hardware [S1, S2, unofficial].

**Pseudocode:**
```python
def hierarchical_splatting(volume_data, view_direction, precision_threshold):
    N = len(volume_data)
    levels = [volume_data]
    # Step 1: Build Pyramid
    while len(levels[-1]) > 1:
        prev = levels[-1]
        new_size = len(prev) // 2
        new_level = [[[0.0 for _ in range(new_size)] for _ in range(new_size)] for _ in range(new_size)]
        for x in range(0, len(prev), 2):
            for y in range(0, len(prev[0]), 2):
                for z in range(0, len(prev[0][0]), 2):
                    avg = sum(prev[x+dx][y+dy][z+dz] for dx in range(2) for dy in range(2) for dz in range(2))
                    new_level[x//2][y//2][z//2] = avg / 8.0
        levels.append(new_level)

    # Step 2 & 3: Determine Level
    # Fit octtree based on precision_threshold to select level L.
    L = len(levels) - 1

    # Step 4 & 5: Scan and Splat
    img_w, img_h = 512, 512
    image = [[None for _ in range(img_h)] for _ in range(img_w)]

    cells = []
    for x in range(len(levels[L])):
        for y in range(len(levels[L][0])):
            for z in range(len(levels[L][0][0])):
                cells.append({'x': x, 'y': y, 'z': z, 'val': levels[L][x][y][z]})

    # Sort back-to-front relative to view direction
    cells.sort(key=lambda c: c['x'] * view_direction[0] + c['y'] * view_direction[1] + c['z'] * view_direction[2], reverse=True)

    for cell in cells:
        # Project volume cell corners to image plane
        scale = img_w / N
        corners = [
            (cell['x'] * scale, cell['y'] * scale),
            ((cell['x'] + 1) * scale, cell['y'] * scale),
            ((cell['x'] + 1) * scale, (cell['y'] + 1) * scale),
            (cell['x'] * scale, (cell['y'] + 1) * scale)
        ]
        # Approximate splat with polygon and rasterize (Gouraud shading applied per vertex)
        for sx in range(int(corners[0][0]), int(corners[2][0])):
            for sy in range(int(corners[0][1]), int(corners[2][1])):
                if 0 <= sx < img_w and 0 <= sy < img_h:
                    image[sx][sy] = cell['val']
    return image
```

**Edge Cases and Pitfalls:**
*   **Binary Data:** For binary data, bits can be packed into bytes where each byte represents a $2 \times 2 \times 2$ portion [S2, unofficial]. A byte represents an object element if it contains more than four non-zero bits, otherwise it represents background [S2, unofficial]. This allows faster generation of lower resolution images, producing an image with half the linear resolution in approximately one-eighth the time [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Building the pyramid takes $O(N^3)$ time [S2, unofficial]. Rendering time depends on the selected level and the number of cells [S2, unofficial]. For binary data, rendering lower resolution images can be up to 8 times faster than full resolution [S2, unofficial].
*   **Memory Complexity:** The pyramid requires $O(N^3)$ memory [S2, unofficial].
*   **Strengths:** Real-time interactive rendering; progressive refinement allows users to see a rough image quickly and refine it [S1, S2, unofficial].
*   **Limitations:** Quality depends on the pyramid level and precision threshold [S1, S2, unofficial].
*   **When to use:** Interactive applications requiring real-time feedback on large volume datasets [S1, unofficial].

## Background
Hierarchical splatting was introduced by David Laur and Pat Hanrahan in 1991 [S1, unofficial]. It was designed to enable real-time volume rendering on modern graphics workstations by leveraging hardware-accelerated polygon rasterization [S1, unofficial]. The method builds on the concept of splatting but introduces a hierarchical data structure to manage resolution adaptively [S1, S2, unofficial].
