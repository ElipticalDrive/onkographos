# Grid Density Data Structure

Also called: 1D Array Density Layout, 3D Grid, 3D Voxel Grid Density Field, Dense Voxel Grid Storage, Dense structure, Linearized 3D Grid, Volume Grid Data Structure

## Overview
The Grid Density Data Structure is a dense, axis-aligned 3D grid used to store scalar density values for volume rendering [S1, unofficial]. It solves the problem of representing continuous volumetric media (such as smoke, clouds, or fluids) in a format that allows for fast, direct memory access during ray marching [S1, unofficial][S4, unofficial]. Unlike sparse structures like [Morton Code Encoding/Decoding](1700-morton-code-encoding-decoding.md) or [Voxel Grid Indexing](1719-voxel-grid-indexing.md) which use indirection to save memory, the dense grid stores every voxel in a contiguous 1D array, prioritizing sampling speed over memory efficiency [S4, unofficial]. It serves as the foundational storage for higher-level operations such as [Interpolated Discrete Values & Gradients](1268-interpolated-discrete-values-gradients.md) and [Euclidean Distance Field (EDF) Data Structure](3220-euclidean-distance-field-edf-data-structure.md).

## How it works
### Inputs and Outputs
*   **Input:** Grid resolution $N$ (assumed cubic, e.g., $N \times N \times N$), world-space bounding box defined by minimum point $\mathbf{p}_{min}$ and maximum point $\mathbf{p}_{max}$, and a source of density data (e.g., simulation cache, procedural function, or sparse voxel loader) [S1, unofficial][S3, unofficial].
*   **Output:** A `Grid` data structure containing a contiguous 1D array of density values, resolution metadata, and world-space bounds [S1, unofficial].

### Data Structures
The core structure is a `Grid` object. While implementations vary, the essential fields are:

1.  **`density`**: A contiguous 1D array of floating-point values (typically `float`). The size is $N^3$.
2.  **`dimension`**: An integer representing the resolution $N$ in one dimension. The total number of voxels is $N \times N \times N$ [S1, unofficial].
3.  **`bounds`**: An array or pair of 3D points defining the Axis-Aligned Bounding Box (AABB) in world space. $\mathbf{p}_{min}$ and $\mathbf{p}_{max}$ [S1, unofficial].

*Note: Some implementations may also store optional auxiliary data such as temperature or majorant values in separate handles, but the density field is the primary component [S2, unofficial].*

### Linearization and Indexing
The 3D grid coordinates $(x, y, z)$ are mapped to a 1D index $I$ using row-major ordering. For a grid with dimensions $n_x, n_y, n_z$:

$$ I = (z \cdot n_y + y) \cdot n_x + x $$

where $0 \le x < n_x$, $0 \le y < n_y$, and $0 \le z < n_z$ [S3, unofficial].

To sample the grid at a world-space position $\mathbf{p}_{world}$, the position must first be transformed into local grid coordinates. This is achieved using a transformation matrix $\mathbf{D}$ that maps world coordinates to the grid's local coordinate system (where the grid spans $[0, 1]^3$ or $[0, N]^3$ depending on implementation convention). Given a world-to-local transformation matrix $\mathbf{D}$:

1.  Compute local coordinates: $\mathbf{p}_{local} = \mathbf{D} \cdot \mathbf{p}_{world}$ (using homogeneous coordinates).
2.  Convert local coordinates to integer grid indices:
    $$ x = \lfloor p_{local, x} \cdot n_x \rfloor $$
    $$ y = \lfloor p_{local, y} \cdot n_y \rfloor $$
    $$ z = \lfloor p_{local, z} \cdot n_z \rfloor $$
3.  Compute the 1D index $I$ using the formula above [S3, unofficial].

*Note: The transformation matrix $\mathbf{D}$ is typically derived from the grid's world-space bounds. If the grid spans from $\mathbf{p}_{min}$ to $\mathbf{p}_{max}$, the scaling factor is $S = \frac{N}{\mathbf{p}_{max} - \mathbf{p}_{min}}$ and the translation accounts for the offset [S3, unofficial].*

### Construction Algorithm
The grid can be constructed by initializing the density array and populating it with values from a source. A common procedural example is a smoke sphere [S3, unofficial]:

1.  Initialize `density` array of size $n_x \cdot n_y \cdot n_z$ with zeros [S3, unofficial].
2.  Iterate through all voxel indices $(x, y, z)$ where $1 \le x < n_x-1$, $1 \le y < n_y-1$, $1 \le z < n_z-1$ [S3, unofficial].
3.  Calculate the Euclidean distance from the center of the grid:
    $$ dist = \sqrt{ \left(x - \frac{n_x-1}{2}\right)^2 + \left(y - \frac{n_y-1}{2}\right)^2 + \left(z - \frac{n_z-1}{2}\right)^2 } $$
4.  Assign density value:
    $$ density[index] = \frac{1}{2^{dist+2}} $$
5.  Set boundary voxels (where $x=0, x=n_x-1$, etc.) to 0 to avoid harsh edges [S3, unofficial].

### Pseudocode
```python
import math

class Grid:
    def __init__(self, resolution, bounds_min, bounds_max):
        """
        Initialize a dense 3D grid.
        
        Args:
            resolution (int): N, the number of voxels per dimension.
            bounds_min (tuple): (x_min, y_min, z_min) in world space.
            bounds_max (tuple): (x_max, y_max, z_max) in world space.
        """
        self.dimension = resolution
        self.bounds_min = bounds_min
        self.bounds_max = bounds_max
        
        # Contiguous 1D array for density
        self.density = [0.0] * (resolution ** 3)
        
        # Precompute transformation matrix components for fast lookup
        # Map world space [bounds_min, bounds_max] to local space [0, resolution]
        self.scale_x = resolution / (bounds_max[0] - bounds_min[0])
        self.scale_y = resolution / (bounds_max[1] - bounds_min[1])
        self.scale_z = resolution / (bounds_max[2] - bounds_min[2])
        
        self.offset_x = -bounds_min[0] * self.scale_x
        self.offset_y = -bounds_min[1] * self.scale_y
        self.offset_z = -bounds_min[2] * self.scale_z

    def world_to_local_index(self, x, y, z):
        """
        Convert world-space coordinates to a 1D grid index.
        Returns -1 if the point is outside the grid bounds.
        """
        # Transform to local grid coordinates
        lx = x * self.scale_x + self.offset_x
        ly = y * self.scale_y + self.offset_y
        lz = z * self.scale_z + self.offset_z
        
        # Convert to integer indices
        ix = int(lx)
        iy = int(ly)
        iz = int(lz)
        
        # Boundary check
        if not (0 <= ix < self.dimension and 
                0 <= iy < self.dimension and 
                0 <= iz < self.dimension):
            return -1
            
        # Row-major linearization
        return (iz * self.dimension + iy) * self.dimension + ix

    def populate_smoke_sphere(self):
        """
        Populate the grid with a procedural smoke sphere density field.
        """
        n = self.dimension
        center = (n - 1) / 2.0
        
        for z in range(1, n - 1):
            for y in range(1, n - 1):
                for x in range(1, n - 1):
                    dist = math.sqrt(
                        (x - center)**2 + 
                        (y - center)**2 + 
                        (z - center)**2
                    )
                    index = (z * n + y) * n + x
                    self.density[index] = 1.0 / (2.0 ** (dist + 2))
```

### Edge Cases and Pitfalls
*   **Memory Usage:** The memory cost is $O(N^3)$. For high resolutions (e.g., $1024^3$), this becomes prohibitive [S4, unofficial].
*   **Boundary Conditions:** Voxels on the boundary of the grid must be handled carefully. Setting them to zero prevents artifacts during ray marching but requires explicit iteration or masking [S3, unofficial].
*   **Coordinate Transformation:** Incorrect transformation matrices lead to sampling outside the grid bounds. The grid is assumed to be axis-aligned; non-axis-aligned grids require transforming the ray into the grid's object space first [S1, unofficial].
*   **Precision:** Using integer arithmetic for index calculation is preferred over floating-point division for performance, but boundary checks are critical to avoid out-of-bounds memory access [S1, unofficial].

## Subtopics

### [Gradient Computation via Finite Differences](1077-gradient-computation-via-finite-differences.md)
Estimates the spatial gradient (normal vector) of the scalar density field at each voxel using discrete neighbor sampling. It differs from [Analytic Gradient Computation](2167-analytic-gradient-computation.md) by not requiring closed-form derivatives and from [Gradient Estimation from Samples](2180-gradient-estimation-from-samples.md) by operating directly on the indexed grid structure. It is used for Phong shading and multidimensional transfer functions.

### [EdgeMap Data Layout](1109-edgemap-data-layout.md)
A memory structure within the grid that stores geometric intersection data for isosurface extraction. It organizes intersection points, surface normals, and indexing offsets into contiguous arrays. It differs from gradient methods by storing pre-computed geometric primitives rather than derivative values.

### [Interpolated Discrete Values & Gradients](1268-interpolated-discrete-values-gradients.md)
Computes a continuous scalar field and its spatial gradient at arbitrary 3D query points by interpolating discrete values stored at grid vertices using tri-linear or tri-cubic interpolation. It provides $C^0$ or $C^1$ continuity, unlike nearest-neighbor lookup which yields discontinuous results. It builds on the Grid Density Data Structure by providing the sampling primitive.

### [Euclidean Distance Field (EDF) Data Structure](3220-euclidean-distance-field-edf-data-structure.md)
A spatial indexing structure that stores scalar distance magnitudes for each voxel to accelerate ray traversal. It allows rays to jump over empty space (space-skipping), reducing intersection tests. It differs from EdgeMap by storing distance magnitudes rather than boundary flags.

### [Grid Resolution Heuristic](4871-grid-resolution-heuristic.md)
A method for determining the optimal spatial resolution ($N$) for leaf-level uniform grids to minimize expected traversal cost [4871-grid-resolution-heuristic.md]. It uses the Surface Area Metric to balance traversal and intersection costs, adapting the grid density to scene geometry. Unlike static resolution choices, it directly informs the structural parameters of the grid.

## Operating characteristics
*   **Time Complexity:** Sampling is $O(1)$ per voxel access, as it involves simple arithmetic and array indexing [S4, unofficial]. Ray marching complexity depends on the number of steps, which is proportional to the grid resolution $N$ along the ray path.
*   **Memory Complexity:** $O(N^3)$, where $N$ is the resolution per dimension. This is the primary limitation [S4, unofficial].
*   **Performance:** Dense grids are significantly faster to sample than sparse grids because they avoid the indirection overhead of tree traversal or hash lookups [S4, unofficial].
*   **Strengths:** Fast sampling, simple implementation, compatibility with hardware 3D textures, ability to store auxiliary data (lighting, temperature) [S4, unofficial].
*   **Limitations:** High memory consumption limits resolution; inefficient for sparse scenes where most voxels are empty [S4, unofficial].
*   **When to Use:** Suitable for dense media, small to medium resolutions, or when sampling speed is critical and memory is abundant [S4, unofficial].
*   **When Not to Use:** Unsuitable for large, sparse scenes or very high-resolution requirements where sparse structures (like [Morton Code Encoding/Decoding](1700-morton-code-encoding-decoding.md)) are preferred [S4, unofficial].

## Background
The Grid Density Data Structure originates from early volume rendering techniques that quantized continuous density fields into discrete 3D arrays [S1, unofficial]. It is analogous to 2D bitmaps for images [S1, unofficial]. The approach was popularized in foundational graphics literature and educational resources, such as the "scratchapixel" tutorials and the "Physically Based Rendering" (pbrt) book examples, which demonstrate its use in fluid simulation visualization and volumetric path tracing [S1, unofficial][S3, unofficial]. It remains a standard baseline for volume rendering implementations due to its simplicity and hardware support via 3D textures [S4, unofficial].
