# 16-bit Floating Point Format for Spectra

Also called: 16-bit Floating Point Spectrum Representation, 1G-bit floating point format

## Overview
This method defines a custom 16-bit floating point format to represent the frequency domain spectrum of volumetric data, reducing memory cost compared to 64-bit double precision while maintaining acceptable precision for volume rendering. It is specifically designed for frequency domain volume rendering, where the wide dynamic range of spectral coefficients necessitates floating point representation over integer formats. It differs from spatial domain compression methods by operating in the frequency domain and is distinct from sibling hardware-specific compressions by being a custom format tailored for spectral data rather than general spatial voxels.

## How it works
**Inputs and Outputs:**
- Input: Volumetric data (typically real-valued, e.g., CT scans) transformed into the frequency domain (via Hartley or Fourier transform).
- Output: A compressed spectral representation using 16-bit floating point values, ready for inverse transformation or direct frequency domain rendering.

**Data Structures:**
- The format is a custom 16-bit floating point representation. The exact bit layout (sign, exponent, mantissa) is not specified in the sources [S1, S2, unofficial].
- Each spectral coefficient is stored as one 16-bit value.
- The full spectrum is stored, including both positive and negative frequency components, despite Hermitian symmetry allowing storage of only positive coefficients [S1, unofficial].

**Steps:**
1. **Transform:** Apply a Hartley transform (or Fourier transform) to the spatial volume data. The Hartley transform is preferred in the cited work as it handles real-valued data without complex number overhead, though the memory cost is still higher than the original spatial data [S1, S2, unofficial].
2. **Quantize:** Convert each spectral coefficient from 64-bit double precision to the custom 16-bit floating point format. This step reduces the memory footprint significantly.
3. **Store:** Store the 16-bit values. The full spectrum is stored to simplify slice extraction and rendering processes, avoiding the complexity of handling Hermitian symmetry explicitly [S1, unofficial].

**Formulas and Parameters:**
- **Memory Cost Reduction:**
  - Original spatial volume: 1 byte per voxel.
  - 64-bit double precision spectrum: 8 times the memory of the original spatial volume (assuming 1 byte per voxel in spatial domain) [S1, S2, unofficial].
  - 16-bit floating point spectrum: 2 times the memory of the original spatial volume [S1, S2, unofficial].
  - Formula: $Memory_{16bit} = 2 \times Memory_{spatial}$ [S1, S2, unofficial].
- **Precision:**
  - The relative difference between images rendered using the 16-bit format and those using 64-bit double precision is below 50 dB [S1, S2, unofficial].

**Edge Cases and Pitfalls:**
- **Dynamic Range:** The wide dynamic range of spectra makes 8-bit or integer formats insufficient; floating point is necessary [S1, S2, unofficial].
- **Hermitian Symmetry:** While storing only positive coefficients (due to Hermitian symmetry of real signals) could save memory, it complicates slice extraction, so the full spectrum is stored [S1, unofficial].
- **Precision Loss:** Although the format reduces memory, the relative difference from double precision is small (<50 dB), indicating acceptable precision loss for rendering purposes [S1, S2, unofficial].

## Operating characteristics
- **Time Complexity:** The frequency domain method grows at $O(n^2 \log n)$, much slower than the spatial domain method's $O(n^3)$ [S1, S2, unofficial].
- **Memory Complexity:** The 16-bit format occupies 2 times the memory of the original spatial volume (assuming 1 byte per voxel), compared to 8 times for double precision [S1, S2, unofficial].
- **Measured Performance:**
  - Head dataset (128^3): Rendering time 0.54 sec (freq) vs 3.15 sec (spatial) [S2, unofficial].
  - Teapot dataset (256^3): Rendering time 1.77 sec (freq) vs 24.29 sec (spatial) [S2, unofficial].
  - Turbine dataset (256^3): Rendering time 2.03 sec (freq) vs 24.38 sec (spatial) [S2, unofficial] [S2, unofficial].
- **Strengths:** Significant memory reduction compared to double precision; acceptable precision loss (<50 dB relative difference); faster rendering times for large volumes.
- **Limitations:** Custom format requires specific implementation; full spectrum storage increases memory compared to theoretical minimum (half spectrum); precision loss, though small, is present.
- **When to Use:** Frequency domain volume rendering where memory is a constraint and slight precision loss is acceptable.
- **When Not to Use:** Spatial domain rendering; applications requiring exact double precision; scenarios where custom format implementation is not feasible.

## Background
The 16-bit floating point format for spectra was introduced by Takashi Totsuka and Marc Levoy in their work on frequency domain volume rendering [S1, S2, unofficial]. The work was published in 1993 as a technical report from Stanford University [S1, S2, unofficial]. It was developed to address the high memory cost of representing frequency domain spectra using 64-bit double precision, which was considered a safe choice due to the wide dynamic range of spectra. The format was used in rendering images of a human skull, a teapot, and a turbine blade, demonstrating its practical applicability in volume rendering [S1, S2, unofficial].
